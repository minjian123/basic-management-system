## 1. 文档目的 <a id="purpose"></a>

本文档是 BMS（基础管理系统）数据库设计的**总纲**：说明数据库设计体系的定位、设计依据、数据分布、
通用规范与文档组织方式，并作为入口引用全部数据库设计节点文件。数据库设计在[《项目规划说明》](../../规划/项目规划说明.md)
「核心数据表清单」「多数据源策略」「数据库兼容」「数据规范」章节与[《架构设计·数据架构》](../架构设计/05_架构设计_数据架构.md)
之上，将每一张表落到**字段级表结构**（字段、类型、约束、索引、分片与归档策略），供开发人员按模块直接实现。

> 数据库设计是详细设计的数据库侧落地：概要设计定义"每个模块有哪些数据与流程"，数据库设计定义"这些数据以什么表结构存储"。
> 数据库设计不推翻规划与架构已定案的数据决策；与《架构设计·数据架构》冲突时以架构设计为准并先修订架构节点。

## 4. 数据分布总览 <a id="distribution"></a>

| 库 | 名称 | 内容 | 归属 |
| --- | --- | --- | --- |
| 平台库 | `bms_platform` | 租户注册、平台超管、SSO 全局身份映射、平台统一维护的菜单/表单/按钮/字段与业务/动作权限码、AI 模型端点配置 | 平台运营（跨租户） |
| 租户库 | `bms_tenant_{code}` | 一租户一库：该租户全部业务数据（未标注【平台库】的表均在此） | 租户（物理隔离） |
| 归档库 | `bms_archive` | 统一收存各租户归档数据（带 tenant_id 与原库表标识，只读查询） | 治理（只读） |

- 跨库引用一律用逻辑外键（code），不建物理外键
- 开发环境用多个 SQLite 文件模拟平台库、租户库与归档库；环境库命名 `bms_dev` / `bms_test` / `bms_prod`
- 多数据源、读写分离、分片与归档流转机制见[架构 09-数据访问与分片](../架构设计/09_架构设计_子系统_数据访问与分片.md)

## 5. 通用数据规范 <a id="rules"></a>

全部业务表统一遵守（详见02-数据规范节点）：

- **主键**：业务表雪花 ID（yitter/IdGenerator），关联表用唯一联合主键
- **软删除**：业务数据软删除（deleted_at 时间戳），审计类数据物理保留；唯一约束统一建为 `(唯一字段, deleted_at)` 复合唯一索引
- **审计字段**：created_at / created_by / updated_at / updated_by，ORM 事件自动填充
- **乐观锁**：version 字段，更新时比对
- **时间**：统一 UTC 存储，前端按本地时区展示
- **字符集**：MySQL utf8mb4、PostgreSQL UTF8、达梦 DM8 UTF8
- **多语言**：展示文案不入主表，由 `{主表}_i18n` 附表存储（主表 ID + locale 联合主键），缺省回退主表默认文案
- **分片**：按月分片表名带 yyyyMM 后缀（如 `sys_operation_log_202608`），逻辑表名不带后缀
- **索引**：排序字段、外键、数据权限过滤字段必须建索引；唯一性约束用唯一索引
- **三库兼容**：ORM 层禁用方言特有功能，Alembic 维护 MySQL / PostgreSQL / 达梦 DM8 三套方言迁移

## 6. 核心表清单总表 <a id="tables"></a>

表前缀：平台域固定——系统 `sys_`、工作流 `wf_`、报表 `rpt_`、AI 域 `ai_`；业务模块表用各模块独立前缀（注册制，如采购 `pur_`、收付款 `pay_`、供应商 `sup_`）。标注【平台库】的表位于平台库，其余位于租户库。

## 8. 阅读指南 <a id="reading"></a>

1. **先读总纲**（本文档）：了解数据分布、通用规范与文档地图
2. **再读数据规范**（02 节点）：所有表的通用约定（主键/软删除/审计/分片/索引/三库兼容），后续节点不再逐表重复
3. **按模块读对应节点**：开发某模块前，对照《概要设计》同模块节点读数据库设计节点，先读表清单总表定位
4. **交叉对照**：分片/归档/哈希链机制以[架构 09-数据访问与分片](../架构设计/09_架构设计_子系统_数据访问与分片.md)、[架构 15-审计哈希链](../架构设计/15_架构设计_子系统_审计哈希链.md)为机制依据；表结构以本体系节点为落地依据

## 9. 与上下游文档的关系 <a id="coordination"></a>

- **上游**：规划（表清单/数据规范）与架构（数据架构/数据访问/审计链）为唯一来源，本体系只做字段级落地展开，每篇节点开头标注其对应的规划章节与架构节点
- **下游**：Alembic 迁移脚本按本体系节点表结构生成；开发按本体系节点实现建表与 ORM 模型
- **变更传导**：表结构变更须先更新本体系对应节点，再改迁移脚本；与架构设计冲突时先修订架构节点
- **配套规范**：表设计、索引、三库兼容 SQL 写法遵循《[数据库开发规范](../../规范/数据库开发规范.md)》
