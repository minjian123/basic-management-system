## 1. 概述 <a id="overview"></a>

本节点定义测试策略与质量门禁：测试金字塔、用例管理（Kiwi TCMS）、新功能覆盖、压测、安全专项、兼容性基线、CI 流水线、测试流程管理与代码规范。对应[《项目规划说明》](../../规划/项目规划说明.md)的「测试策略与测试流程」「工程化与质量」章节。

## 2. 测试金字塔 <a id="pyramid"></a>

| 层级 | 工具 | 内容 |
| --- | --- | --- |
| 单元/接口测试 | pytest + httpx（ASGITransport 免启服务器） | SQLite 库，CI 每次 MR 执行 |
| 集成测试 | GitLab CI 服务容器（MySQL/PostgreSQL）+ mjbk 常驻达梦 DM8 | 多数据源、读写分离路由、真实分片规则、三库方言迁移 |
| 前端组件/单元 | Vitest | 组件与单元测试（零配置，Vite 同构） |
| E2E | Playwright | 登录、主体链 RBAC 权限（含按钮显隐与字段权限）、核心 CRUD 主流程；服务容器起 backend（SQLite）与前端产物 |
| 压测 | locust | 登录、列表查询、审批提交场景，阶段十验收前执行（500 并发 / P99 ≤ 1s） |
| 验收测试（UAT） | E2E 全量先行 + 人工抽检 | MVP 验收前先跑 E2E 全量回归作自动化预走查，再按验收清单抽检关键链路与界面体验（Kiwi TCMS 登记结果） |

> **个人开发 + AI 辅助总则**：单人开发人力有限，测试资产以自动化为主——手工用例仅覆盖自动化不可覆盖的场景（UI 视觉、真机体验等）；用例初稿由 AI 依据概要设计与验收标准批量生成、人工审核后登记 Kiwi TCMS；E2E 用例以 Playwright 录制器 + AI 补全断言辅助编写，不逐条手写。

## 3. 用例管理（Kiwi TCMS） <a id="cases"></a>

- 平台：mjbk Docker Compose 常驻（宿主 8060，复用 MySQL），唯一用例库——手工与自动化用例统一登记（含用例编号），测试代码以用例 ID 标注关联（`@pytest.mark.kiwi_id(1234)`）；pytest/Playwright 执行结果经官方插件导入平台归档，平台统计执行情况与历史。
- 内容与组织：用例名称/描述/分类使用中文；按模块分类（Category）+ 标签（Tag）组织，前端页面 E2E 用例按页面模块分类承载；平台缺陷链接指向 GitLab Issue。
- 用例设计方法：等价类划分 / 边界值 / 场景法 / 错误推测；关键业务链路（审批、权限、收付款、归档）用场景法覆盖主路径与异常路径。
- 优先级与风险：用例按 High / Medium / Low 三级优先级；核心模块（认证、RBAC、工作流、审计、收付款）高风险用例优先设计与执行。
- 可追溯性：用例与模块/功能点及验收项双向追溯（用例 ID 标注所属模块与对应验收项），保证需求全覆盖、无孤儿用例。

## 4. 新功能覆盖 <a id="coverage"></a>

以下场景均纳入测试（随阶段推进）：Socket.IO 广播与断线重连、分片上传断点续传、图形验证码逻辑、OAuth2 开放接口与 Webhook 推送、消息队列事件流转、真实分片规则（双日志表按月分片）、任务调度入库与手动触发、邮件模板在线编辑渲染、短信发送记录、公告发布与已读回执、通知批量已读、缓存清理与热数据刷新、账号锁定与解锁审计、租户配额超限拦截、备份任务执行与恢复演练登记、回收站恢复（审计留痕）、附件在线预览、会话踢出即时生效、多租户隔离（跨租户访问拒绝）、SSO 登录与 JIT 建号、报表 SQL 安全执行、移动端审批链路（含附件预览与个人中心）、字段级审计与哈希链校验（含跨归档链校验）、密码策略与数据脱敏、字段权限（读时过滤/写时校验）、首页工作台（卡片注册/平台与角色模板/个人布局定制与一键重置/数据集图表卡渲染）、表单定制（三级布局解析、字段属性动态校验、租户自建字段动态 DDL 加列与跨方言类型映射、停用不删列、查询区与明细区配置、导入导出联动）、多语言动态扩展与 RTL、归档流转（热表→归档库→对象存储→物理清理）、全文检索（事件同步与索引重建、检索权限租户隔离、文件内容解析）、AI 能力（NL2SQL 安全执行、RAG 检索与问答租户隔离、AI 交互审计落库、OCR 解析）、链路追踪（Jaeger 链路可见）、收付款管理（收款/付款/退款审批链路、退款金额 ≤ 原单余额校验、流水台账一致性、渠道抽象预留可扩展）。

## 5. 压测 <a id="load"></a>

- locust 脚本（loadtest/scenario_登录.py 等）：登录、列表查询、审批提交场景
- 字典并发专项（loadtest/scenario_字典并发.py）：① 500 并发首次全缓存未命中（验证 DB 互斥锁回源收敛，DB 查询次数应 ≈ 字典类型数 × worker 数）② 500 并发全命中（批量接口与版本比对稳定吞吐）③ 500 并发后端批量翻译（导出含 30 字典字段列表，验证 dogpile.cache 内存缓存零往返、Redis 往返次数收敛）④ 1000 行明细 × 30 字典字段批量翻译（以超大字典为主：首次每字段 1 次 IN 查询共 30 次、二次起零查询）
- 阶段十验收：达到 500 并发 / P99 ≤ 1s；压测报告归档

## 6. 安全专项 <a id="security-test"></a>

- 集中用例集：越权、注入、XSS、上传绕过、限流爆破、脱敏泄露、会话劫持
- CI 定期执行；依赖漏洞扫描与安全更新（Renovate / GitLab Dependency Scanning 模板）；容器镜像扫描（main 流水线 GitLab Container Scanning / Trivy，CVSS ≥ 9 高危阻断发版）
- 专项验证：跨租户访问拒绝、字段权限读写双向、哈希链校验

## 7. 兼容性基线（单人可执行口径） <a id="compat"></a>

- PC 端：Playwright 跨浏览器自动化覆盖 Chrome / Edge / Firefox / Safari 最新版
- 移动端：缩减矩阵——1~2 台安卓主流真机 + 微信/钉钉内嵌 WebView 抽测；无常备 iOS 设备，以标准 H5 兼容写法规避（Vant 官方兼容基线），交付需要时借用设备发布前专项抽测
- 数据库：SQLite（开发/测试）+ MySQL / PostgreSQL / 达梦 DM8 三库 CI 通过

## 8. CI 流水线 <a id="ci"></a>

CI 全量运行在自托管 GitLab CE（gitlab-runner 容器化，挂载 docker.sock，Docker executor）；代码仓库、Merge Request、CI 与容器 Registry 一体，MR/push 事件原生触发流水线，无跨平台桥接。GitHub 仓库保留为只读归档，GitLab push mirror 单向同步 main 变更（GitHub 侧改动不回传、不承载协作）。流水线以 .gitlab-ci.yml 定义。

- MR 流水线：后端 ruff + pytest（pytest-cov 覆盖率门禁）；前端 ESLint + Vitest（coverage 门禁）+ 双端构建（frontend / frontend-mobile）
- main 流水线：在 MR 流水线基础上另含 Playwright E2E 独立 job（服务容器起 backend（SQLite）与前端产物，覆盖登录/RBAC/核心 CRUD 主流程）与 MySQL/PostgreSQL/达梦 DM8 三库方言集成测试（复用 mjbk 常驻三库，job 内建 bms_test 前缀独立测试库，建库 → 迁移 → 测试 → 清理）
- main 分支：构建镜像推送 GitLab Registry + 镜像安全扫描（GitLab Container Scanning / Trivy，CVSS ≥ 9 高危阻断发版）+ 导出 swagger.json 契约快照 + Allure 报告生成归档 + 测试结果导入 Kiwi TCMS
- 测试失败自动上报：任一测试 job 失败即调用 `deploy/tools/defect/defect_capture.py` 生成 REPRO 复现包（现场 dump + 失败堆栈/日志 + repro.json + REPRO.md，归档 mjbk `/mnt/data/backup/defects/`）并自动创建/复用 GitLab 缺陷 Issue（「用例 ID + 失败摘要」指纹去重、defect-auto 标签），修复闭环见第 9 节
- Renovate 依赖升级（自动提 MR）；main 保护分支，MR 合入需 CI 通过。单人开发口径：不设强制人工批准——核心模块（认证/RBAC/工作流/审计/收付款）改动提交前经 AI 交叉评审（本地模型优先）、MR 描述附评审结论；多人协作时再启用"≥1 名 reviewer 批准 + 核心模块作者外确认"

## 9. 测试流程管理 <a id="flow"></a>

- **缺陷管理**：GitLab Issue + Milestone（按阶段/版本关联）；分级 P0（阻断主流程/数据安全）、P1（严重功能缺失/可用性降级）、P2（一般缺陷）、P3（轻微/建议）；流程：上报 → 指派修复 → CI 回归验证 → 关闭；P0/P1 阻断 MR 合入。
  - **自动上报**：MR 与 main 流水线任一自动化测试失败即自动执行——defect_capture.py 归档 REPRO 复现包并自动创建/复用 Issue（描述含 commit、用例 ID、dump 路径、环境标记、流水线地址；同指纹未关闭 Issue 追加评论附新路径）
  - **AI 修复代理（指派修复环节）**：ai_fix.py 扫描 defect-auto 未关闭 Issue，按复现包定位根因生成补丁——**双轨**：本地模型（LM Studio，内网零费用）优先，定位不了/置信度低（< 0.6）且 AI_CLOUD_ALLOWED=1 时升级云端（先敏感信息过滤，dump 内容严禁外发）；bot 推送 fix/defect-* 分支提 MR（引用指纹与诊断），**人工 review 合入、CI 回归通过后人工关闭**；无法定位时评论标注需人工。一键复现：reproduce.py（检出 commit + 导入 dump + 跑用例）
  - **现场数据（缺陷重现）**：P0/P1 缺陷附问题现场 dump（mysqldump / pg_dump / 达梦 dexp），与 commit、用例 ID、环境标记归档 /mnt/data/backup/defects/<缺陷号>/（不入 Git，随每日备份保留 30 天）
- **回归策略**：冒烟回归（每次 MR 与发版前——登录含验证码、主体链 RBAC 按钮/字段权限、核心 CRUD 主链路）+ 全量回归（每阶段末与 MVP 验收前全部自动化用例，结果导入 Kiwi TCMS 归档）+ 探索性测试（MVP 验收前，发现项入缺陷库）。
- **进入准则**：进入全量回归与 UAT 前需冒烟通过、CI 流水线绿色、Kiwi TCMS 用例登记完成且用例 ID 与代码关联一致。
- **准出标准**：P0/P1 清零；功能用例通过率 ≥ 98%；安全专项全通过；压测 500 并发 / P99 ≤ 1s；三库 CI 通过；覆盖率达标（核心 ≥ 80%、整体 ≥ 70%）。
- **稳定性/可靠性**：MVP 验收前对核心链路（审批、Socket.IO 推送、任务调度）执行 7×24 长稳运行与故障恢复演练，结果入测试报告。
- **测试报告**：Allure 自动化报告（CI 产物）+ 每阶段末汇总报告（执行统计/缺陷统计/覆盖率/风险与遗留项；CI 数据脚本汇总 + AI 生成初稿、人工补充结论）+ 测试复盘（阶段末经验教训、MVP 后整体复盘）。
- **执行方式**：重负载执行以 CI（mjbk GitLab Runner）为主，不占本地开发资源；本地仅在明确需要时小范围执行（执行前与开发确认）。

## 10. 代码质量门禁 <a id="quality"></a>

- 后端：ruff（lint + format 一体化）+ pyright 严格模式类型检查（CI 强制）
- 前端：ESLint + Prettier；TS 严格
- 覆盖率：核心模块（auth、rbac、wf、audit、收付款）行覆盖 ≥ 80%、整体 ≥ 70%，CI 门禁（pytest-cov / Vitest coverage），低于门槛流水线失败
- 测试数据：独立种子脚本（tests/seeds），不与初始化数据混用
- 测试命名：test_模块.py / TestXxx / test_行为_期望；组件.spec.ts；自动化用例标注 Kiwi 用例 ID（先登记平台用例再写代码）
