4. 数据规范

  • 主键：业务表雪花 ID（yitter/IdGenerator）；关联表用唯一联合主键，不设 id
  • 软删除：业务数据 deleted_at；唯一约束统一建为 (唯一字段, deleted_at) 复合唯一索引——未删行 deleted_at 为 NULL，SQLite/MySQL/PostgreSQL/达梦 DM8 四库均允许多个 NULL 不冲突（达梦按 Oracle 兼容口径，阶段一验证）；PostgreSQL 可另加部分唯一索引优化
  • 审计字段：created_at / created_by / updated_at / updated_by，由 ORM 事件自动填充
  • 乐观锁：version 字段，更新时比对，防止多实例并发覆盖
  • 时间：统一 UTC 存储，前端按本地时区展示
  • 字符集：MySQL utf8mb4、PostgreSQL UTF8、达梦 DM8 UTF8
  • 索引：排序字段、外键、数据权限过滤字段必须建索引；唯一性约束用唯一索引（idx_/uq_ 前缀）
  • SQL 规范：禁止 SELECT *；批量写入用 bulk；事务尽量短；定期走查慢查询日志

4.1 字典与系统参数管理

  • 字典（sys_dict_type / sys_dict_item）与系统参数（sys_config）：平台库存默认，租户库可覆盖/自建（租户开通种子自动下发默认项）
  • 字典多语言 label 存各自 _i18n 附表，按 locale 关联查询
  • 缓存：只读热数据 Redis 缓存（bms:{tenant}:dict:{locale}:{type}），短 TTL + 随机偏移；字典/参数变更后删除缓存 key（先写库后删缓存协议）
  • 字典/参数是权限体系与业务模块的通用依赖（状态、类型等基础字典），页面管理权限码 dict:manage / config:manage

4.2 回收站机制

  • 无独立表：回收站复用软删除字段（deleted_at），软删除数据查看与恢复（权限码 recycle:restore）
  • 恢复动作落操作日志与字段级审计（sys_data_audit_log）——审计留痕；恢复即清除 deleted_at
  • 过期软删除残留由 Celery 定时物理清理，与归档清理任务衔接（清理顺序：先归档可归档数据，再物理清理过期残留）
  • 唯一约束 (唯一字段, deleted_at) 复合唯一索引保证删除后释放唯一键、恢复不冲突

5. 缓存架构

统一 Redis 缓存（弃用本地内存缓存——多实例内存独立会造成数据不一致）。key 格式 bms:{租户|global}:{域}:{业务键}，全小写冒号分隔，所有 key 必须携带 TTL。

5.1 key 空间规划

域key 示例TTL 策略
缓存类bms:{tenant}:dict:{locale}:{type}、bms:global:menu:{locale}、bms:{tenant}:perm:{user_id}:{version}短 TTL + 随机偏移（防雪崩）
会话与认证bms:{tenant}:sess:{session_id}、bms:global:token:blacklist:{jti}与业务有效期对齐（14 天 / 黑名单短窗）
验证码与限流bms:global:captcha:{uuid}（5 分钟）、bms:global:rate:{维度}:{目标}短 TTL，与策略窗口对齐
锁与幂等bms:global:lock:{资源}、bms:{tenant}:idem:{key}SETNX 带过期，防死锁
空值缓存查询不存在的 key 值 = EMPTY 标记短 TTL（防穿透）

5.2 三防与一致性协议

  • 防穿透：不存在数据缓存空值（短 TTL）
  • 防击穿：热点 key 过期用互斥锁（SETNX）单实例重建
  • 防雪崩：TTL 加随机偏移，避免大量 key 同时失效
  • 一致性：先写库后删缓存；写操作后同一会话内读主库，避免读到从库旧数据
  • 权限缓存失效：权限相关变更 → 权限版本号 +1，用户缓存按版本校验，保证变更即时生效

6. 迁移策略

  • Alembic 按数据源分别维护迁移脚本，只管理各库 schema；MySQL / PostgreSQL / 达梦 DM8 三套方言迁移脚本
  • 租户库批量迁移：遍历 sys_tenant 逐库执行（批量迁移脚本）；新租户开通自动执行
  • SQLite 开发库自动建表（不依赖迁移脚本）
  • 测试环境与开发环境一致使用 SQLite；三库方言差异以 CI 集成测试覆盖
