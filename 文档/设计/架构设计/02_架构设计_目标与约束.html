3. 技术约束

3.1 语言与生态

  • Python 3.14+，uv 管理依赖与虚拟环境；版本兼容口径：阶段一逐依赖验证（FastAPI/SQLAlchemy/Pydantic/psycopg/Celery/SpiffWorkflow 等），任一核心依赖不兼容则整体回退 Python 3.13
  • 前端 Node 版本由 .nvmrc 固定（≥ 20.19），volta/fnm 管理；包管理 npm，frontend 与 frontend-mobile 双工程彻底独立（各自 lock 与 ESLint/Prettier/TS 配置，不共享、不生成额外配置文件）
  • 测试环境与开发环境一致使用 SQLite（aiosqlite）

3.2 数据库兼容

  • 开发/测试 SQLite；生产同时支持 MySQL 8.x、PostgreSQL 16+ 与达梦 DM8（信创选配）三库并行
  • ORM 层禁用方言特有功能：JSON 等类型使用跨方言通用类型（达梦 JSON 支持有限，用通用类型兜底），分页统一 limit/offset
  • Alembic 维护 MySQL / PostgreSQL / 达梦 DM8 三套方言迁移；SQLite 开发库自动建表；CI 三库方言集成测试

3.3 系统形态

  • 多租户 SaaS（租户独立库）为既定形态，见多租户路由子系统
  • 单体模块化 + 独立 worker 进程（celery-worker / celery-beat / event-worker），跨域调用走事件总线
  • 配置：config.toml 按环境分层（BMS_ENV）+ 环境变量覆盖；密钥只走环境变量 / Secret 管理
  • 部署：Docker Compose 编排，数据量或规模增长后演进 Kubernetes

4. 明确不采用

技术不采用理由重新评估条件
KubernetesMVP 用 Docker Compose 部署即可满足数据量或部署规模增长后
Kafka消息量级未到，RocketMQ 已覆盖事件总线，Redis 已覆盖任务队列消息量级显著增长
MFA / 2FA账号密码 + 图形验证码 + 找回密码双通道 + 限流已满足 MVP 安全基线安全基线升级需求
原生 WebSocket统一采用 Socket.IO（自动重连、Redis 跨实例广播）性能瓶颈且协议约束无法满足
APNs / FCM 移动端系统推送MVP 站内信 + 企业微信/钉钉内免登即达移动端独立 App 场景
微服务拆分保持单体模块化 + 独立 worker 进程团队规模/部署边界需要时
前端 SSR / Nuxt管理端与 H5 均为 SPASEO 需求出现
