1. 概述

多租户路由子系统承载 BMS 的 SaaS 多租户形态：请求级确定目标租户与数据库引擎，管理引擎 生命周期与连接预算，执行租户开通/停用与配额治理。对应《项目规划说明》的「多数据源策略」 「租户管理」「认证与安全（租户识别）」章节，覆盖租户管理模块与平台超管运营视图。

2. 租户解析链

来源场景优先级
子域名 {tenant}.bms.example.com生产环境（泛域名 DNS + 泛 TLS 证书）1

3. 引擎注册表与生命周期

机制设计
EngineRegistry注册表 {db_key → AsyncEngine}；平台引擎常驻（bms_platform）；租户引擎懒加载（首次访问创建，连接参数来自 config.toml 数据源声明）
闲置回收LRU + 最后使用时间：超时未访问的租户引擎 dispose 回收；停用租户强制回收；控制活跃租户引擎数上限
连接预算总连接 = worker 数 × (pool_size + max_overflow) ≤ 数据库 max_connections 的 70%（预留其他客户端）；多租户按活跃租户数规划，避免全量租户连接常驻
并发保护引擎创建加锁（进程内锁 + Redis 锁），防多实例同时为同一租户建引擎；创建失败快速失败并告警

4. 租户开通/停用

  • 开通流程（平台超管 tenant:manage）：校验 code 唯一 → 建库 bms_tenant_{code} → 三套 Alembic 迁移（按目标库方言，MySQL/PostgreSQL/达梦 DM8）→ 批量种子（三类内置管理员角色 + 初始系统管理员账号（首次登录强制改密）+ 默认 IdP 占位 + 归档策略 + 平台统一菜单/表单/按钮/字段挂接与权限码）→ 注册 sys_tenant → 预热引擎（可选）→ 落 tenant.created 事件
  • 停用：租户引擎全部回收、会话标记失效（按租户前缀批量清理 Redis）、登录拦截；启用：恢复正常 + 落 tenant.activated 事件
  • 租户库批量迁移：Alembic 遍历 sys_tenant 逐库执行（运维脚本 scripts/）

5. 配额管理

  • 配额维度（sys_tenant_quota.quota_key）：user_count / storage_bytes / open_calls
  • 超限拦截：创建用户/上传文件/开放接口调用前校验配额，超限拒绝并告警；used_value 计数落库
  • 配额变更由平台超管运营视图配置（tenant:quota）

6. 隔离边界

  • 第一层：引擎物理隔离（一租户一独立库，库级隔离）
  • 第二层：查询强制 tenant 过滤（repository 统一注入 tenant_id 条件）
  • 第三层：跨库引用走 code 逻辑外键（不建物理外键）；业务/动作权限码跨库引用同理
  • 验证：跨租户访问拒绝测试纳入 CI（安全专项用例集）

7. 与其他子系统的协调

  • 认证与会话：token 携带 tenant_id，会话 key 带租户前缀；踢出/锁定按租户维度生效
  • 数据访问与分片：TenantContext 决定数据源路由；分片键支持按租户（预留）
  • 事件总线：事件信封携带 tenant_id，审计链分区键 = 租户（保证租户内有序）
  • 缓存架构：租户数据 key 必含租户前缀，平台数据用 global
  • 权限计算引擎：权限码租户侧可见、可分配、不可增删（平台统一维护）
