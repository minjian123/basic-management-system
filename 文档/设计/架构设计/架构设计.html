1. 概述

本文档描述 BMS（基础管理系统）的总体架构设计，是《项目规划说明》（文档/规划/项目规划说明.md） 的架构层面展开，供开发、测试、运维人员理解系统结构，也是后续实施与演进的设计依据。

BMS 定位为多租户 SaaS 形态的后端管理系统：支持分布式、集群部署，租户独立库隔离，内置 RBAC 权限体系、工作流、报表 BI、全文检索与 AI 能力；前端含 PC 管理端与移动端 H5 两个独立工程。

本文档与《项目规划说明》《文档生成规范》《命名规范》配套阅读；文档中涉及的代码、数据库、API 命名均遵循《命名规范》。

2. 设计目标与原则

原则落地方式
多租户隔离一租户一独立库（bms_tenant_{code}），平台数据独立平台库（bms_platform）；跨租户访问一律拒绝
无状态可扩展JWT 认证 + Redis 会话标记；文件存 MinIO；任一实例可随时停机、随时横向扩容
单体模块化 + 独立进程后端保持单体应用，任务与事件消费拆为 celery-worker、celery-beat、event-worker 独立进程，跨域调用走事件总线
数据库兼容开发/测试用 SQLite，生产支持 MySQL 8.x 与 PostgreSQL 16+ 双库并行，ORM 层禁用方言特有功能
安全合规三权分立、审计日志哈希链防篡改、数据脱敏、等保管理要求对齐
性能目标≥ 500 并发用户，P99 响应 ≤ 1s（登录、列表查询、审批提交主链路）

4. 多租户架构

4.1 库划分

  • 平台库 bms_platform：租户注册（sys_tenant）、平台超管（sys_admin）、SSO 全局身份映射（sys_user_identity）、平台统一维护的菜单/表单/按钮/字段与业务/动作权限码
  • 租户库 bms_tenant_{code}：一租户一库，承载该租户全部业务数据（未标注【平台库】的表均在此）
  • 归档库 bms_archive：统一收存各租户归档数据（带 tenant_id 与原库表标识，只读查询）
  • 跨库引用一律用逻辑外键（code），不建物理外键

4.2 租户路由

  • 生产环境按子域名解析租户（{tenant}.bms.example.com），泛域名 DNS + 泛 TLS 证书
  • 开发环境以 access token 内 tenant_id 兜底；一人多租户经 X-Tenant-ID 请求头切换
  • 租户库按 tenant 动态路由异步 engine：懒加载创建、闲置回收、池上限控制，避免全量租户连接常驻
  • 租户隔离三层校验：数据库物理隔离 → 查询强制 tenant 过滤 → 跨租户访问拒绝测试

4.3 租户开通与配额

  • 租户开通自动执行：建库 → 双套 Alembic 迁移 → 种子数据（三类内置管理员角色、初始系统管理员账号、默认 IdP 占位、归档策略、菜单/表单/按钮/字段挂接）
  • 租户库批量迁移：Alembic 遍历 sys_tenant 逐库执行
  • 配额管理（sys_tenant_quota）：用户数 / 存储 / 开放接口调用量，超限拦截与告警

5. 后端应用架构

5.1 分层职责

层目录职责与约束
接口层app/api参数校验与路由分发、依赖注入（require_permission 等），禁止在此直接操作模型
业务层app/services业务逻辑与事务边界
数据访问层app/repositories数据访问与数据源路由、分片路由，禁止在 api 层直接操作模型
基础设施层app/db、app/core异步引擎、AsyncSession 工厂、读写分离路由、配置、安全、异常处理
任务与事件app/tasks、app/ws、app/i18nCelery 任务定义、Socket.IO 事件、国际化管理

5.2 异步数据访问

  • 全链路异步栈：FastAPI + SQLAlchemy 2.0 异步 + aiomysql / psycopg 3（异步方言）+ redis.asyncio
  • 异步会话不可跨请求共享；避免循环内多次查询（N+1），大事务显式声明边界
  • 多数据源用多个异步 engine 管理；AsyncSession 工厂按读写标记选择主/从引擎
  • 写操作与事务强制走主库；写后同一会话内读主库，避免读到从库旧数据

5.3 模块组织

  • monorepo 布局：backend/、frontend/、frontend-mobile/、deploy/、scripts/、.github/、文档/
  • 后端按模块分组（app/api/user/、app/models/user.py），模块目录用单数名词
  • 配置：config.toml 分层（dev/test/prod 由 BMS_ENV 指定）+ 环境变量覆盖（密钥类只走环境变量）
  • ID 生成：yitter/IdGenerator 雪花算法，配置时钟回拨处理

6. 数据架构

6.1 数据规范

  • 主键：业务表雪花 ID（id），关联表唯一联合主键；表前缀 sys_/wf_/biz_/rpt_/ai_，表名单数 snake_case
  • 软删除：业务数据 deleted_at；唯一约束统一建为 (唯一字段, deleted_at) 复合唯一索引，三库均允许多 NULL；回收站复用 deleted_at，过期残留由 Celery 物理清理
  • 审计字段 created_at/created_by/updated_at/updated_by（ORM 事件自动填充）+ 乐观锁 version；时间统一 UTC
  • 多语言：固定文案存 sys_i18n_message（页面维护、运行时下发）；业务展示文案走 {主表}_i18n 附表（主表 ID + locale 联合主键），缺省回退主表默认文案

6.2 多数据源与读写分离

  • config.toml 声明多个数据源，每库可配主从连接；repositories 层按模块指定数据源
  • 主从读写分离：写与事务强制走主库，查询走从库（可配）；主库故障时降级只读模式
  • 迁移：Alembic 按数据源分别维护 MySQL / PostgreSQL 两套方言迁移脚本；SQLite 开发库自动建表

6.3 分片策略

  • Python 生态无成熟分片中间件，采用应用层自研 ShardingRouter（分片键 → 物理库/表解析）
  • MVP 真实分片规则：sys_operation_log、sys_open_log 按月分表（物理表名带 yyyyMM 后缀），新月份分片表由 Celery 提前创建
  • 分片键支持按租户 / 按时间，由接入模块声明

6.4 缓存策略

  • 统一 Redis 缓存，弃用本地内存缓存（多实例内存独立会造成数据不一致）
  • 只读热数据（字典、系统参数、菜单树、权限码）短 TTL 缓存；key 携带租户前缀（bms:{租户|global}:{域}:{键}），全部 key 必须带 TTL
  • 三防：穿透（空值缓存）、击穿（SETNX 互斥锁重建）、雪崩（TTL 随机偏移）
  • 一致性：先写库后删缓存

6.5 审计与归档

  • 审计日志（操作/登录/开放接口/数据变更）逐条哈希串联（prev_hash + record_hash）防篡改，分片表内成链、跨月表首尾衔接
  • 归档两段式：热表超阈值迁归档库（可在线查询）→ 按保留期转对象存储冷化；归档前执行链完整性校验
  • 合规留存：审计数据 90 天热表 + 归档冷存储，哈希链随归档导出供事后校验；合规销毁记录销毁日志

7. 消息与异步架构

7.1 事件总线

  • RocketMQ 5.x 作事件总线：操作日志异步化、Webhook 推送、审计链串行消费、模块解耦；分区有序消息保证审计链顺序，事务消息兜底
  • 事件命名 {域}.{对象}.{动作}（如 user.created、wf.task.completed、purchase.order.created），Webhook 订阅按事件名匹配
  • topic 命名 bms.{事件域}.{事件}；数据同步（如 ES 索引）走事件驱动异步消费，独立 event-worker 进程，索引重建时重放事件
  • 消息量级远未到 Kafka 场景，RocketMQ 已覆盖事件总线；任务队列独立走 Redis broker（Celery 官方不支持 RocketMQ）

7.2 任务调度

  • Celery 分布式任务队列，broker 用 Redis；任务定义入库 sys_task，自研数据库调度器（beat 启动时加载、任务变更事件触发重载），页面可动态增删改与启停
  • 执行历史落 sys_task_log；失败自动重试、ack 确认
  • 内置任务：孤儿分片清理、日志归档、分片表预创建、每日全量备份
  • worker 为同步进程，任务内执行异步业务须用 asyncio.run 或独立引擎，禁止跨事件循环复用连接/会话；beat 单副本运行避免重复调度

7.3 审计链有序性

审计日志哈希链对写入顺序敏感：写入经 RocketMQ 按租户分区有序消费（分区有序消息）保证链序， 避免多 worker 并发写乱序破坏 prev_hash 衔接；链校验工具定期巡检，归档前校验链完整性。

8. 权限与安全架构

8.1 权限模型

  • 主体链 RBAC：用户与角色间可插入任意中间实体（岗位、部门等），链条任意长度；最终权限计算统一收敛为 用户 → 角色，多链取并集去重；主体角色绑定用通用表 sys_role_assign（subject_type + subject_id + role_id）
  • 权限分层：菜单 → 表单 → 业务、按钮 → 动作、字段（visible/editable）；授权业务权限隐含对应表单与菜单权限；按钮权限默认全无，字段权限默认全可见可编辑、授予后收窄
  • 数据权限：动作级配置（sys_data_scope），默认无数据权限；四种范围（全部 / 本部门及以下 / 本部门 / 仅本人），读载入时与写保存时双向校验
  • 权限码：业务:动作（如 user:create、wf:approve）；业务/动作码平台统一维护，租户可见、可分配、不可增删
  • 双重控制：前端按权限码显隐菜单/按钮/字段，后端接口用 require_permission 依赖强制校验
  • 三权分立：租户侧系统管理员 / 安全管理员 / 审计管理员权限互斥；平台超管（sys_admin）独立于租户体系

8.2 认证与会话

  • 双 token：access token（30 分钟，仅存前端内存）+ refresh token（14 天滚动轮换，httpOnly + Secure + SameSite cookie）
  • 鉴权时随 access token 一并校验 Redis 会话有效标记（每请求一次 Redis 读，毫秒级），强制踢出即时生效
  • SSO：OIDC 为主 + CAS 兼容；外部 IdP 认证回跳后经 sys_user_identity 全局映射定位租户并 JIT 自动建号；BMS 兼作 IdP 供第三方系统登录；本地账号密码并存（超管应急通道）
  • 密码：PBKDF2 哈希（标准库）+ 登录失败限流（slowapi，Redis 后端，如 5 次锁 15 分钟）+ 连续失败 3 次强制图形验证码 + 密码策略（复杂度/90 天有效期/近 5 次历史/180 天未登录锁定）
  • 多端会话：并发登录上限（默认 5，最旧失效）；会话管理可强制踢出并广播"会话失效"

8.3 安全基线

  • 数据脱敏：敏感字段注册标记，序列化层默认掩码（138****5678），持 data:plain 权限码方可查看明文
  • 上传安全：类型白名单 + 大小上限 + 分片 SHA256 校验；存储于 MinIO 私有桶，下载用限时预签名 URL，后端不代理文件流
  • 限流：slowapi（limits 库，Redis 后端，IP / 用户 / client 维度），登录限流优先；Redis 故障降级 memory 后端
  • 防护：ORM 参数化防 SQL 注入、前端框架默认转义防 XSS、接口级限流、JWT secret 轮换、密钥走 Secret 管理
  • AI 安全（阶段十四）：交互全量审计、提示词与数据不出租户边界、prompt 注入防护、AI 结果默认仅辅助展示、自动写操作/自动审批独立开关默认关闭

9. 前端架构

9.1 双工程结构

  • PC 管理端 frontend/（Vue 3 + Vite + TypeScript + Element Plus）与移动端 frontend-mobile/（Vue 3 + Vant）为两个彻底独立的工程：各自维护 package.json / lock 文件与 ESLint/Prettier/TS 配置，不共享基础配置与公共类型
  • 包管理用 npm（Node 官方自带，不生成额外配置文件）；CI 用 npm ci 锁定安装
  • 前后端契约：后端 OpenAPI schema 经 openapi-typescript 自动生成 TS 类型，保持契约一致
  • 移动端复用后端 API 与会话体系，企业微信 / 钉钉内嵌免登

9.2 动态菜单与权限渲染

  • 菜单树由后端按用户业务权限动态返回（sys_menu + sys_form 挂接业务权限过滤，按当前 locale 关联 i18n 附表返回翻译文案）
  • 表单元数据（按钮/字段定义与当前用户可见/可编辑状态）随菜单接口一并下发；前端根据菜单树动态注册路由与生成侧边栏，不硬编码路由表，新增菜单/表单/按钮/字段无需发版
  • 按钮按动作权限显隐（默认无）、字段按字段权限控制显隐与可编辑；权限指令 v-perm="'业务:动作'"

9.3 实时推送与国际化

  • Socket.IO（socket.io-client）接收待办/通知实时到达、会话失效广播；集群经 Redis 适配器跨实例广播
  • vue-i18n：语言包运行时从后端拉取（Redis 缓存 + localStorage 二次缓存），文案不硬编码；RTL 由 sys_i18n_locale.rtl 标记驱动布局切换；用户时区偏好按 Intl 本地化

10. 可观测性

  • 日志：structlog 结构化 JSON（携带 request_id），Loki 聚合跨实例检索
  • 指标：Prometheus 采集 /metrics（请求量、延迟、依赖状态）
  • 链路：OpenTelemetry，应用经 otel-collector 上报 trace 至 Jaeger 存储展示；trace_id 与 request_id 关联，Grafana 以 Jaeger 数据源统一可视化
  • 告警：Alertmanager 推送邮件 / 企业微信 / 钉钉 / 短信（经 BMS 内部接口转换格式）
  • 健康检查：/healthz（存活）、/readyz（就绪，检查 DB/Redis 连通性），供编排系统滚动发布

11. 部署架构

11.1 部署拓扑

nginx（TLS 终止 / 静态资源 / /api 反代 / 租户子域名 / WebSocket 亲和）
  ├── backend × N（无状态）
  ├── celery-worker × N ── celery-beat × 1
  ├── event-worker × N（RocketMQ 消费）
  ├── MySQL / PostgreSQL 主从（1 平台库 + N 租户库 + 1 归档库）
  ├── Redis（Sentinel/Cluster 高可用）
  ├── RocketMQ（nameserver + broker）
  ├── MinIO（按租户 bucket 前缀隔离，归档文件亦存于此）
  ├── ElasticSearch（MVP 单节点，生产集群）
  └── 监控：Prometheus / Loki / Grafana / Alertmanager / Jaeger / otel-collector

11.2 集群设计要点

  • 无状态：会话标记、token 黑名单、限流计数存 Redis；文件存 MinIO；定时任务分布式执行
  • 实时推送：Socket.IO 经 Redis 适配器广播，任一实例可推送至任意用户；nginx 对 /socket.io 放行 Upgrade/Connection 头，并用 ip_hash / Cookie 亲和保证连接升级后固定在同一实例
  • 分布式锁：Redis SETNX，用于防并发与幂等拦截（幂等键前置去重 + 唯一约束兜底）
  • 连接池：pool_size / max_overflow 按 worker 数规划，总连接数 ≤ 数据库 max_connections 的 70%；多租户引擎懒加载 + 闲置回收
  • 消息队列高可用：RocketMQ 多副本（主从、同步刷盘、持久化）；Celery beat 单副本
  • 检索高可用：ES 多节点集群（多副本）；检索故障降级为数据库模糊查询兜底，数据可经事件重放全量重建
  • 数据库高可用：主从 + 故障切换；主库故障预案（从库提升、只读模式）
  • 安全响应头：nginx 统一配置 CSP、HSTS、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy

11.3 备份与恢复

  • 数据库：每日全量备份 + Binlog/WAL（PITR），保留 30 天异机存储；备份任务与记录由页面管理（sys_backup_task/sys_backup_log，Celery 调度，支持手动备份与恢复演练登记）
  • MinIO：定期增量备份 + 生命周期策略；元数据随数据库备份
  • 目标：RTO ≤ 4 小时、RPO ≤ 1 小时，定期演练
