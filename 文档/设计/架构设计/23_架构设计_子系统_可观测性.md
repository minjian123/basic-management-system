## 1. 概述 <a id="overview"></a>

可观测性子系统统一承载日志、指标、链路、告警与健康检查，支撑跨实例运维。对应[《项目规划说明》](../../规划/项目规划说明.md)的「日志」「链路追踪」「系统监控」「监控」章节。技术栈：structlog + Prometheus + Loki + Grafana + Alertmanager + OpenTelemetry（Jaeger）。

## 2. 结构化日志 <a id="log"></a>

- structlog 结构化 JSON 日志，携带 request_id 贯穿请求链路，配合 Loki 跨实例聚合检索
- 与标准 logging 集成，不影响第三方库输出
- 敏感字段（密码、token、密钥）脱敏后记录，不落原始值

## 3. 指标采集 <a id="metrics"></a>

- Prometheus 采集 /metrics：请求量、延迟、依赖状态（DB/Redis/MinIO）、Socket.IO 连接数、RocketMQ 消费积压、AI 成本（阶段十五）
- Grafana 统一展示（指标 + 日志 + 告警面板 + Jaeger 数据源）

## 4. 链路追踪 <a id="trace"></a>

- OpenTelemetry：应用经 otel-collector 上报 trace 至 Jaeger 存储展示（MVP 即接入）
- trace_id 与 structlog 的 request_id 关联；Grafana 以 Jaeger 数据源统一可视化
- 追踪数据随 Prometheus/Loki 采集展示（指标/日志/链路三合一）

## 5. 告警 <a id="alert"></a>

- Alertmanager 推送：邮件走原生 SMTP receiver；企业微信/钉钉群机器人经 webhook receiver 转 BMS 内部接口转换格式后推送；短信经 BMS 内部接口（sys_sms_template 渠道）
- 告警面板同步可见（Grafana）

## 6. 健康检查与优雅停机 <a id="health"></a>

- /healthz（存活探针）：进程存活即返回
- /readyz（就绪探针）：检查依赖（DB/Redis）连通性，供编排系统滚动发布
- 优雅停机：SIGTERM 后停止接收新请求、等待在途请求完成（配合 K8s preStop / terminationGracePeriod）

## 7. 系统监控模块 <a id="monitor-module"></a>

- 依赖状态：DB/Redis/MinIO 健康检查展示
- 缓存管理：Redis key 分布/内存占用、按前缀清理、热数据一键刷新（monitor:cache）
- Grafana 独立部署，BMS 内页面跳转/嵌入（X-Frame-Options SAMEORIGIN 兼容）
- 权限码：monitor:view、monitor:cache

## 8. 与其他子系统的协调 <a id="coordination"></a>

- **[全部子系统](03_架构设计_总体架构.md)**：日志/链路贯穿所有请求与任务；trace_id 随请求传递
- **[任务调度](13_架构设计_子系统_任务调度.md)**：任务执行耗时/失败指标
- **[事件总线](12_架构设计_子系统_事件总线.md)**：消费积压与死信监控
- **[认证与会话](10_架构设计_子系统_认证与会话.md)**：登录失败率、会话数指标；踢出等关键操作日志
- **[部署与运维](28_架构设计_部署与运维.md)**：告警路由配置、运维手册配套
