## 1. 文档目的 <a id="purpose"></a>

本文档是 BMS（基础管理系统）架构设计的**总纲**：说明项目背景、设计依据与文档组织方式，
并作为入口引用全部架构设计节点文件。架构设计完整覆盖[《项目规划说明》](../../规划/项目规划说明.md)
的每一个决策点，阐述各组件、模块、数据、接口在架构中如何协调运作。

> 架构设计是详细设计（数据库表结构、接口 Schema、页面交互）与后续[《概要设计》](../概要设计/01_概要设计_总览.md)的源头依据：概要设计将严格依照本文档各节点展开。

## 2. 项目概述 <a id="overview"></a>

BMS 为多租户 SaaS 形态的基础管理系统，主要用作后端管理：支持分布式、集群部署；多租户 SaaS
架构（租户独立库）；支持 SSO 单点登录；内置报表 BI 与移动端 H5；集成全文检索与 AI 能力。

- 后端：Python 3.14+ / FastAPI / SQLAlchemy 2.0 异步 / Alembic / Redis / RocketMQ / Celery / MinIO / ES / Milvus（阶段十五）
- 前端：Vue 3 + Vite + TypeScript（PC 端 Element Plus + 移动端 Vant 双工程，npm 各自独立）
- 部署：Docker Compose + nginx；监控 Prometheus/Loki/Grafana/Alertmanager + Jaeger（OpenTelemetry）
- 研发辅助：知识图谱（graphify）辅助代码理解与架构分析

## 5. 阅读指南 <a id="reading"></a>

1. **先读总纲**（本文档），了解项目全貌与文档地图
2. **按序读基础节点**：目标与约束 → 总体架构 → 核心交互时序 → 数据架构 → 接口与集成
3. **按需读子系统节点**：20 个子系统节点彼此独立，按当前任务选择（如做审批功能读工作流 + 通知公告 + 实时推送）
4. **横切节点**：涉及性能/安全/部署时对照阅读；决策与风险记录历史取舍，改架构前必读

## 6. 与后续文档的关系 <a id="coordination"></a>

- **概要设计**：严格依照架构设计各节点展开——模块划分对应功能模块清单，流程对应核心时序，机制对应子系统节点，不做架构级新决策
- **详细设计**：在概要设计基础上落到表结构、接口 Schema、页面交互
- **实施落地**：各阶段开发按《项目规划说明》开发计划推进，架构约束以本文档为准
- 架构变更（技术选型、结构、机制）须先更新本架构设计相应节点，再传导到下游文档
