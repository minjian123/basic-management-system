1. 概述

本节点描述 BMS 的关键交互时序，体现各子系统如何协调运作。每个时序标注参与的子系统， 对应《项目规划说明》的「认证与安全」「多数据源策略」「审计合规」等章节。 概要设计将照此展开为更细的步骤级流程与接口调用。

2. 请求生命周期

请求 → nginx（租户子域名解析 {tenant}.bms.example.com）
  → backend 中间件：验签 access token → Redis 会话标记校验 → 构造 TenantContext/UserContext
  → 权限引擎加载权限码集合（缓存命中或计算）→ require_permission(业务:动作) 校验
  → slowapi 接口限流检查（IP/用户维度）
  → services 执行业务（显式事务边界）→ repositories 按数据源/分片路由访问
  → 响应序列化：字段权限过滤（不可见字段不返回）+ 数据脱敏（掩码）
  → 写操作后删缓存；关键操作发事件（RocketMQ 事务消息）；ORM 事件捕获审计变更
  → 响应头携带 trace_id / request_id

参与子系统：多租户路由、认证与会话、权限计算引擎、数据访问与分片、事件总线、审计哈希链、可观测性。

3. 登录与双 token

用户 → 登录页（连续失败 3 次后强制图形验证码）
  → POST /api/v1/auth/login（slowapi 限流：5 次失败锁 15 分钟）
  → 校验图形验证码（Redis bms:global:captcha:{uuid}，TTL 5 分钟，单次有效）
  → PBKDF2 校验密码（标准库）→ 检查账号状态（停用/锁定/强制改密标记）
  → 签发双 token：
       access token（30 分钟，载荷 sub/tenant_id/jti/type=access）
       refresh token（14 天滚动轮换，httpOnly + Secure + SameSite cookie）
  → 建会话：写 sys_session + Redis 标记 bms:{tenant}:sess:{session_id}（TTL 14 天）
  → 写 sys_login_log（成功/失败，异步经 RocketMQ）→ 返回用户概要 + 菜单与权限概要
登出：refresh 入黑名单（bms:global:token:blacklist:{jti}）即时失效
找回密码：邮箱/企微钉钉双通道 → 短时效 token（Redis TTL 15 分钟单次有效）→ 重置后强制失效全部会话

参与子系统：认证与会话、权限计算引擎、事件总线、任务调度（未登录锁定扫描）、可观测性。

4. SSO 登录

用户 → 登录页选择 IdP 入口（sys_identity_provider，OIDC/CAS/企微/钉钉）
  → 跳转外部 IdP 认证 → 回跳携带授权码/身份凭证
  → authlib 校验凭证 → 按 idp_key + external_id 查 sys_user_identity 全局映射
  → 命中 → 定位租户与用户；未命中 → JIT 自动建号（唯一约束防并发重复建号）
  → 落 sso.user.jit_created 事件 → 签发 BMS 双 token → 进入系统
本地账号密码登录并存（超管应急通道，防 IdP 故障锁死）
BMS 兼作 IdP：第三方系统经 OIDC 授权码流程以 BMS 用户体系登录（客户端注册 sys_client）

5. 会话踢出

管理端 → POST /api/v1/sessions/{id}/kick（require_permission("session:kick")）
  → 删 Redis 会话标记 bms:{tenant}:sess:{session_id}
  → 吊销 refresh（入黑名单）→ sys_session.revoked_at 落库
  → Socket.IO 广播 session.revoked → 该会话全部实时连接关闭（Redis 适配器跨实例）
  → HTTP 侧：下一请求因会话标记缺失被拦截（即时生效）
并发会话上限（默认 5）：超出自动作废最旧会话

6. 租户开通

平台超管 → 创建租户（code/名称/域名/配额，require_permission("tenant:manage")）
  → 校验 code 唯一 → 建库 bms_tenant_{code}
  → 三套 Alembic 迁移（按目标库方言执行，MySQL/PostgreSQL/达梦 DM8）→ 批量种子：
      三类内置管理员角色 + 初始系统管理员（首次登录强制改密）+ 默认 IdP 占位
      + 归档策略种子 + 平台统一菜单/表单/按钮/字段挂接与业务/动作权限码
  → 注册 sys_tenant（db_key）→ 预热租户引擎（可选）
  → 落 tenant.created 事件（Webhook 可订阅）
停用：租户引擎全部回收、会话标记失效、登录拦截；启用恢复正常

7. 审批流程执行

申请人 → 提交采购申请（Idempotency-Key 幂等去重）→ 落 biz_purchase_apply（待审批）
  → 启动流程实例（三级审批模板：部门经理 → 财务 → 分管领导；SpiffWorkflow 线程池执行）
  → 生成 wf_task 待办 → 事件总线 → 通知中心站内信 + Socket.IO 推送（approval.todo）
  → 审批人同意/驳回/评论（会签/或签按流程定义；写接口幂等键防重复）
  → wf_record 记录审批轨迹 → 全部通过 → 生成采购订单（biz_purchase_order）
  → 落 purchase.order.created 事件 → Webhook 订阅方收到推送
  → 驳回：流程退回指定节点，申请人可修改后重新提交

参与子系统：工作流、通知公告、事件总线、实时推送、审计哈希链。

8. 审计链写入

业务写操作 → ORM 事件捕获字段级变更（sys_data_audit_log，关键表清单见数据架构节点）
  → 审计事件发 RocketMQ（分区键 = 租户）
  → event-worker 串行消费 → record_hash = SHA256(prev_hash + 规范化记录内容)
  → 按月分片落库（sys_operation_log_yyyyMM 等；跨月首条 prev_hash = 上月末条哈希）
  → 定期巡检校验；归档前链完整性校验；合规销毁记录销毁日志

9. 缓存一致性协议

写路径：事务提交 → 删除缓存 key（DEL）→ 后续读重建（短 TTL + 随机偏移）
  → 删除失败由短 TTL 兜底收敛（最终一致）
  → 写后同一会话内读主库（避免从库延迟）
  → 权限类变更：权限版本号 +1 → 用户权限缓存按版本校验即时失效
  → 三防：穿透（空值缓存）/ 击穿（SETNX 互斥锁重建）/ 雪崩（TTL 随机偏移）

10. 文件分片上传

≤20MB：整包上传（类型白名单 + SHA256 校验）→ MinIO 私有桶 → 写 sys_file（状态=完成）
  >20MB：初始化上传（sys_file 状态=上传中，upload_id）→ 逐分片上传
    （分片临时对象 .part 标识 + 逐片 SHA256 校验 + 断点续传：按 part_no 重传缺失片）
  → 全部上传 → 合并为最终对象并清理分片 → 状态=完成 → 落 file.uploaded 事件
  → 下载走预签名 URL（限时有效），后端不代理文件流
  → 中断遗留孤儿分片（超时 .part / 超期上传中）由 Celery 定时回收

11. 归档流转

归档策略（sys_archive_policy）→ Celery 调度执行：
  ① 热表超阈值（如 90 天）→ 链完整性校验 → 迁归档库（bms_archive，可在线查询）
  ② 归档库数据按保留期 → 转对象存储冷化（MinIO）
  ③ 过期归档文件与软删除残留 → Celery 物理清理
  → 归档执行记录 sys_archive_log；哈希链随归档导出供事后校验
  → 回收站：软删除数据查看/恢复（恢复动作落操作日志与字段级审计），过期物理清理
