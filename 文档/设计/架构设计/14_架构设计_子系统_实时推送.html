1. 概述

实时推送子系统基于 python-socketio（Socket.IO 协议）：待办/通知实时到达、会话失效广播、 移动端审批提醒。对应《项目规划说明》的「实时推送」章节，覆盖通知中心（PC + 移动端）的实时能力。 原生 WebSocket 明确不采用（统一 Socket.IO：自动重连、事件机制、心跳保活、Redis 跨实例广播）。

2. 握手与鉴权

  • Socket.IO 握手阶段校验 access token（auth 参数），失败拒绝连接；建立后绑定用户身份
  • 握手完成后向客户端下发连接确认（含 session 绑定关系）

3. 连接注册

  • 连接元数据存 Redis：user_id → [{session_id, sid}]，会话级映射（一个用户多端可并行连接）
  • 断线清理：连接断开时从注册表移除（避免向失效连接推送）

4. 跨实例广播

  • python-socketio RedisManager 适配器：发送目标（用户/会话）→ 广播到目标连接所在实例 → 该实例向 sid 推送；任一实例可推送任意用户
  • nginx 亲和：/socket.io 放行 Upgrade/Connection 头；ip_hash / Cookie 亲和保证连接升级后固定同一后端实例（Redis 适配器兜底跨实例）

5. 事件路由

事件触发场景目标
approval.todo生成审批待办审批人
notification.new新站内信收件用户
session.revoked会话被踢出/登出目标会话全部连接

服务端事件按域命名（领域.动作），按事件类型选目标用户/会话；事件生产经事件总线消费组触发（见事件总线子系统）。

6. 断线恢复

  • socket.io 自动重连（心跳保活）；重连成功后前端拉取未读数/待办数补偿，不依赖推送补齐
  • 移动端 H5 与企业微信/钉钉内嵌同样走 Socket.IO（WebView 环境）

7. 与其他子系统的协调

  • 认证与会话：握手校验 token；踢出广播 session.revoked 关闭该会话全部实时连接（HTTP 侧由 Redis 会话标记校验同步拦截）
  • 通知公告：站内信/待办落库后触发本子系统推送；批量已读后同步角标状态
  • 工作流：审批待办生成事件 → 通知组消费 → 本子系统推送（approval.todo）
  • 可观测性：Socket.IO 连接数监控（Prometheus 指标）
