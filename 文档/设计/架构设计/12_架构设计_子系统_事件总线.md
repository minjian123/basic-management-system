# 架构设计 · 子系统 · 事件总线

> BMS · RocketMQ 事件模型、消费与推送

## 1. 概述 <a id="overview"></a>

事件总线基于 RocketMQ 5.x：作事件总线承载操作日志异步化、Webhook 推送、审计链分区有序消费、
模块解耦与跨域数据同步。对应[《项目规划说明》](../../规划/项目规划说明.md)的「消息队列」「事件总线事件模型」「Webhook 管理」章节。

## 2. 事件模型 <a id="model"></a>

- 事件信封 EventEnvelope：event_id（幂等键）、type（`{域}.{对象}.{动作}`）、tenant_id、occurred_at、payload
- topic 命名：`bms.{事件域}.{事件}`（如 bms.log.operation、bms.wf.task、bms.event.purchase、bms.event.payment）
- 事件命名：`user.updated`、`wf.task.completed`、`purchase.order.created`、`payment.payment.executed` 等（完整清单见 [06-接口与集成节点](06_架构设计_接口与集成.md)）
- 默认清单开发期可扩展；Webhook 订阅按事件名匹配

## 3. 生产一致性 <a id="produce"></a>

- RocketMQ 事务消息：半消息 → 本地业务事务提交回调 → 确认发送 / 回滚——本地事务与消息发送原子一致，避免丢事件
- 生产者封装统一事件发布组件，业务代码不直接操作 MQ 客户端

## 4. 消费组架构 <a id="consume"></a>

| 消费组 | 职责 | 有序性 |
| --- | --- | --- |
| 审计链组 | 审计日志（操作/登录/开放接口/数据变更）串行追加 + 哈希链计算 | 分区有序（分区键=租户） |
| 日志落库组 | 操作日志/登录日志异步落库（降低主库写压力） | 并行 |
| Webhook 推送组 | 事件按订阅匹配推送（HMAC 签名、退避重试） | 并行 |
| 通知组 | 站内信落库 + 触发 Socket.IO 推送 | 并行 |
| ES 同步组（阶段十四） | 主数据/审计日志/文件内容索引同步 | 并行 |
| embedding 组（阶段十五） | 文件分段向量化入 Milvus | 并行 |

## 5. 幂等与重试 <a id="reliability"></a>

- 幂等：event_id 去重——Redis SETNX 短窗口 + 业务唯一约束兜底（如日志表事件 id 唯一），重试不产生重复副作用
- 重试：消费失败指数退避重试（有限次）→ 转死信 topic 落库标记，监控告警人工介入
- 审计链消费分区键 = 租户：保证同租户日志串行追加，哈希链不乱序（见审计哈希链子系统）

## 6. Webhook 推送 <a id="webhook"></a>

- 订阅管理：sys_webhook（name、url、events、secret、status、fail_count），Webhook 管理页面注册（open 业务）
- 推送：HMAC 签名校验（sha256(secret, body)）；指数退避重试；失败记录 sys_webhook_log（webhook_id、event、payload、status、retry_count、next_retry_at、error_msg）
- 出站调用统一 httpx 封装（超时/重试/熔断）

## 7. 与其他子系统的协调 <a id="coordination"></a>

- **[审计哈希链](15_架构设计_子系统_审计哈希链.md)**：审计事件经本总线分区有序消费，保证链序
- **[通知公告](18_架构设计_子系统_通知公告.md)**：通知类事件（notification.sent）触发站内信与推送
- **[工作流](17_架构设计_子系统_工作流.md)**：wf.* 事件（deployed/started/task.completed/rejected/finished）驱动待办提醒与外部订阅
- **[全文检索](21_架构设计_子系统_全文检索.md)**：事件驱动 ES 索引同步与重建（重放事件流）
- **[任务调度](13_架构设计_子系统_任务调度.md)**：任务执行完成落 task.completed 事件（与 Celery 任务队列解耦，互不干扰）
- **[故障降级](25_架构设计_性能与安全.md)**：RocketMQ 故障时审计/日志降级为同步直写（标记降级时段，恢复后补发）
