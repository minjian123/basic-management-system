1. 模块概述与职责

国际化管理模块统一承载前后端固定文案与业务数据文案的多语言能力：语言清单动态扩展（含 RTL 标记）、 语言包页面在线维护、i18n 附表、用户时区偏好与运行时渲染。目标为新增语言免发版—— 语言与文案全部入库维护，运行时下发。

  • 语言清单维护：sys_i18n_locale（code、name、rtl、status）动态扩展，rtl 标记驱动前端布局切换
  • 语言包页面维护：sys_i18n_message（msg_key + locale 联合主键），前后端固定文案统一存储，页面在线维护，新增语言免发版
  • 开发期提取：后端 Babel 仅开发期提取消息 key 入库（gettext 机制），Accept-Language 驱动请求语言
  • 业务文案 i18n 附表：需多语言的展示文案不入主表，由 {主表}_i18n 附表存储，查询按当前 locale 关联、缺省回退主表默认文案
  • 用户时区偏好：sys_user.timezone，时间统一 UTC 存储、前端按用户偏好时区展示，数字/日期格式经 Intl API 本地化
  • 运行时渲染：运行时通知内容由 gettext 按收件人语言翻译；前端 vue-i18n 语言包运行时拉取与 RTL 适配

职责边界：本模块只管理语言能力（清单、语言包、时区、渲染规则），不负责具体业务文案内容的录入（由各业务模块经 i18n 附表提供）；邮件/短信模板多语言内容由邮件通知模块走 sys_mail_template_i18n。

相邻模块协作：与权限计算引擎协作返回菜单/权限码多语言名称；与通知公告协作按收件人 locale 渲染内容；与认证与会话协作在登录返回用户语言/时区偏好；与前端架构协作实现运行时拉取 + RTL 布局 + 时区格式化。

2.2 业务规则

  • 固定文案（错误消息、按钮、提示）统一存 sys_i18n_message，页面在线维护、运行时下发（Redis 缓存），新增语言免发版
  • i18n key 命名：模块.页面.字段（如 user.form.username、common.confirm）；错误码文案按 error.{code} 映射
  • Babel 仅开发期提取消息 key 入库，运行时翻译走 gettext 机制，Accept-Language 驱动请求语言
  • 业务展示文案不入主表，由 {主表}_i18n 附表存储（主表 ID + locale + 翻译字段，联合主键）；查询按当前 locale 关联，缺省回退主表默认文案；覆盖 sys_menu_i18n（name）、sys_business_i18n、sys_action_i18n、sys_field_i18n、sys_dict_type_i18n、sys_dict_item_i18n、sys_mail_template_i18n（subject、content）
  • 语言清单 sys_i18n_locale 动态扩展；rtl 标记驱动前端布局切换；语言偏好 localStorage 持久化；用户级语言偏好 sys_user.locale
  • 时间统一 UTC 存储，按用户时区（sys_user.timezone）展示；数字/日期格式经 Intl API 本地化
  • 运行时生成的通知内容不走附表，由 gettext 按收件人语言翻译（如审批提醒邮件、告警短信）；邮件模板多语言内容走 sys_mail_template_i18n
  • 菜单树按当前 locale 关联 i18n 附表返回翻译文案（动态菜单接口）
  • 前端不硬编码文案；多语言数据（字典、菜单树）缓存键含 locale 维度；租户数据缓存键含 tenant 前缀

2.3 流程步骤

新增语言主流程（含异常分支）：

  1. 系统管理员在「语言管理」页面新增语言（code、name、rtl、status）
  2. 语言包维护页面出现新语言列，可为各 msg_key 补充该语言 value；批量维护亦可经导入导出
  3. 保存后失效 Redis 语言包缓存，前端下次拉取 GET /api/v1/i18n/messages 即得新语言
    • 异常分支：缓存未及时失效 → 语言包短 TTL + 主动失效兜底
    • 异常分支：某 msg_key 缺该语言翻译 → 前端回退默认语言（缺省回退主表/默认 locale 文案），不阻塞渲染
  4. 用户切换语言（顶栏/个人中心）→ 偏好写 sys_user.locale + localStorage 持久化 → 按 RTL 标记切换布局方向
  5. 业务查询（菜单树/字典）按当前 locale 关联 i18n 附表返回翻译文案，缺省回退主表默认文案
  6. 通知/邮件发送时按收件人 locale 经 gettext 渲染内容

4. 数据模型与表设计

核心表：sys_i18n_locale（语言清单）、sys_i18n_message（固定文案语言包），均位于租户库；i18n 附表与主表同库（联合主键）。

表关键字段说明
sys_i18n_localecode、name、rtl、status语言清单，动态扩展；rtl 标记驱动前端布局切换
sys_i18n_messagemsg_key、locale、value前后端固定文案语言包，联合主键（msg_key + locale），页面维护、运行时下发
{主表}_i18n 附表主表 ID、locale、翻译字段sys_menu_i18n（name）、sys_business_i18n（name）、sys_action_i18n（name）、sys_field_i18n（name）、sys_dict_type_i18n（label）、sys_dict_item_i18n（label）、sys_mail_template_i18n（subject、content）；联合主键（主表 ID + locale）
sys_user（偏好字段）locale、timezone用户级语言/时区偏好，登录返回，个人中心可修改
  • 索引：sys_i18n_message 联合主键即查询键（msg_key + locale）；sys_i18n_locale code 唯一
  • 缓存：语言包 Redis 缓存（键含 locale 维度 + 租户前缀，短 TTL）+ 前端 localStorage 二次缓存；多语言数据（字典、菜单树）缓存键含 locale 维度
  • 归档/分片：语言包数据量小、变更低频，不分片不归档；仅语言包变更本身经 ORM 事件落入数据变更审计（sys_data_audit_log）
  • 数据流转：开发期 Babel 提取 key 入库 → 页面在线维护 value → 运行时 Redis/localStorage 下发 → 渲染时按 locale 关联（附表缺省回退主表默认文案）
语言清单动态扩展（新增语言免发版）为既定能力：前端语言包全部运行时拉取，代码内不硬编码文案；RTL 语言经 sys_i18n_locale.rtl 标记驱动布局切换，无需前端发版。

7. 错误码与异常处理

按《项目规划说明》5 位错误码分段表，国际化语言包属系统配置段 4xxxx（40001-49999，覆盖菜单/字典/系统参数/国际化语言包），段内序号一经发布稳定不变。建议段内分配（44001 起为国际化模块保留）：

错误码含义处理要求
44001语言 code 已存在新增语言唯一性校验失败，提示更换 code
44002语言存在关联语言包数据，不可删除仅允许停用（status），防止语言包孤儿数据
44003msg_key 格式非法校验 模块.页面.字段 命名规范
44004至少保留一种启用的语言停用语言时校验，防止无可用语言
44005默认语言不可停用默认语言（zh-CN）保护
  • 文案由前端按 i18n 映射（error.44001），后端不承担文案拼装——错误码文案本身即走语言包
  • 异常处理：语言包缓存失效失败降级短 TTL 兜底；翻译缺失不回退为空白而是缺省回退默认语言文案
  • 「错误码文案按 error.{code} 映射」与本模块互相印证：错误码体系即国际化语言包的消费方之一
