1. 模块概述与职责

本节对应《项目规划说明》「功能模块」之登录日志模块，与「核心数据表清单」「审计合规」 「认证与安全（账号锁定）」「性能与高并发设计」「多数据源策略（分库分表）」等章节；架构设计依据《架构设计》 14-审计哈希链、09-认证与会话、11-事件总线、 08-数据访问与分片等节点。

登录日志记录登录成功/失败（username、ip、user_agent、status、fail_reason）， 与操作日志同属审计域：经 RocketMQ 异步写入、按月分表、哈希链防篡改、保留 90 天归档。 登录失败信息同时作为账号锁定（fail_limit 锁定类型）的判定依据，配合认证与会话域执行。

维度说明
模块定位登录成功/失败记录的捕获、异步落库、哈希链防篡改、查询与归档
职责边界只做登录审计记录与失败判定数据支撑；锁定动作本身由认证域（sys_account_lock）执行
架构依据14-审计哈希链（prev_hash/record_hash、链序）、09-认证与会话（登录流程与锁定联动）、11-事件总线（RocketMQ 异步写入）、08-数据访问与分片（按月分片）
相邻协作认证与会话（产生登录事件、fail_limit 锁定判定）、操作日志（同审计域同机制）、归档管理（90 天归档）、全文检索（阶段十三按月索引）

2.2 业务规则

  • 记录内容：username、ip、user_agent、status（成功/失败）、fail_reason（失败原因：密码错误/账号锁定/验证码错误等）；成功登录记录时间戳（last_login_at 联动）
  • 哈希链：record_hash = SHA256(prev_hash + 规范化记录内容)；prev_hash 取当前分片表末条 record_hash；分片表内成链、跨月表首尾衔接（首月链头为约定初始值）
  • 链序保证：经 RocketMQ 分区有序消息按租户分区串行消费，保证链序
  • 物理保留：审计数据物理保留，不支持删除；登录失败日志不做脱敏以外的清洗（用户名明文记录，密码本身不落日志）
  • 保留周期：90 天热表，超期归档；归档前链完整性校验，链完整方可归档
  • 锁定依据：登录失败记录与限流/验证码策略共同支撑账号锁定（fail_limit 锁定类型，配合认证域，锁定列表/手动解锁归用户管理模块）

2.3 流程步骤与异常分支

  1. 登录请求：认证域执行登录（含 slowapi 限流、连续失败 3 次后强制图形验证码）
  2. 结果判定：成功 → 签发双 token + 会话记录；失败 → 记录 fail_reason（密码错误/验证码错误/账号锁定/IdP 异常等）
  3. 发布：登录结果组装审计记录 → 发布至 RocketMQ（按租户分区）→ 登录响应不受日志写库阻塞
  4. 消费落库：event-worker 分区有序消费 → prev_hash 取末条 → 计算 record_hash → 写入 sys_login_log_yyyyMM；异常：消费失败重试（ack 确认），持续失败告警
  5. 锁定联动：连续失败达到阈值（限流规则如 5 次锁 15 分钟）→ 认证域执行账号锁定（fail_limit）→ 锁定记录落 sys_account_lock；手动解锁审计
  6. 跨月与归档：次月分片表由 Celery 预创建，跨月首条 prev_hash 衔接上月；超 90 天按策略归档（归档前链校验）

3. 关键时序与协作

用户登录
  └─ 认证域校验（限流/图形验证码/密码/锁定状态）
       ├─ 成功 → 双 token + 会话记录（sys_session）
       └─ 失败 → 判定 fail_reason；连续失败达阈值 → 账号锁定（fail_limit，sys_account_lock）
  └─ 发布登录审计事件 → RocketMQ（分区键 = 租户，分区有序）
       └─ event-worker 分区有序消费
            ├─ 定位分片表 sys_login_log_{yyyyMM}（Celery 已预创建）
            ├─ prev_hash = 末条 record_hash
            ├─ record_hash = SHA256(prev_hash + 规范化记录内容)
            └─ 写入分片表（分片表内成链；跨月首尾衔接）

审计管理员（三权分立）
  └─ GET /api/v1/login-logs → 按月分片路由查询
  └─ 链校验工具：定期巡检 + 归档前强制校验

归档任务（Celery）
  └─ 90 天保留期超期 → 链完整性校验通过 → 两段式归档（热表→归档库→对象存储）
登录失败信息与账号锁定（fail_limit）联动：日志提供失败事实，锁定策略与解锁由认证域与用户管理模块执行，本模块不越权处置。

4. 数据模型与表设计

4.1 核心表

表关键字段说明

4.2 分片与索引

  • 分片：分片键 = 时间（yyyyMM），物理表名带后缀；新月份分片表由 Celery 定时任务提前创建；ShardingRouter 按时间路由
  • 索引：created_at（排序键）、username、status、ip；排序字段与筛选字段必须建索引
  • 查询优化：常规列表 limit/offset 限深 100 页；大数据量列表游标分页兜底（last_id + 排序键索引）
  • 归档：sys_archive_policy 配置（初始归档策略种子：四类审计日志 90 天归档），两段式归档，归档数据只读查询
  • 哈希链：prev_hash/record_hash 成链，跨月表首尾衔接；链校验结果与异常告警接入系统监控

4.3 数据流转（哈希链与归档）

认证域登录结果 → RocketMQ 登录审计事件 → 分区有序消费 → 按月分片落库（链内成链）→ 90 天热表 → 归档（归档前链完整性校验，链完整方可归档；哈希链随归档导出）→ 归档库只读查询（审计管理员）。 阶段十三全文检索经事件同步至 ES 按月索引。

5. 接口设计

5.1 接口清单

全部接口前缀 /api/v1，统一响应 {code, message, data}，鉴权 Bearer access token：

方法路径说明权限码

日志为只读审计数据：不提供新增/修改/删除接口；导出复用通用列表导出能力（export 业务，含脱敏）。

5.2 分页/幂等/限流

  • 分页：查询参数 page（从 1 起）、size；响应 {list, total, page, size}；大数据量列表游标分页兜底
  • 幂等：本模块无写接口，不涉及幂等键
  • 限流：查询接口走接口级限流（slowapi，Redis 后端，IP/用户维度）

5.3 事件

本模块无独立权限码新设、无独立事件：登录审计事件由认证域产生，经事件总线消费落库； 事件总线事件模型中无 login 域独立事件。

  • 链校验异常：定位被篡改记录并告警，接入系统监控

8. 页面清单与验收要点

8.1 页面清单

端页面说明

8.2 验收标准

  • 登录成功/失败审计落库完整：username/ip/user_agent/status/fail_reason 齐全；成功登录 last_login_at 联动
  • 哈希链校验通过：逐条重算比对无篡改；跨月衔接正确（新分片表首条 prev_hash = 上月末条 record_hash）
  • 异步写入生效：登录响应不等待日志落库；分片表按月正确路由；次月分片表预创建
  • 失败联动生效：连续失败达阈值触发账号锁定（fail_limit），锁定记录落 sys_account_lock 且解锁操作审计
  • 归档：超 90 天数据按策略归档，归档前链校验，归档后只读可查
  • 权限：非审计管理员不可访问（三权分立互斥）
