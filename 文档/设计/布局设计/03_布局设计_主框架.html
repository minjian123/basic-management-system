1. 主框架

主框架用来展示主要内容，分左右两部分：左侧导航栏 + 右侧内容栏（可多 Tab）。

  1. 左侧导航栏：导航项按树状结构展示；单击叶子结点，在右侧内容栏展示对应界面。
  2. 右侧内容栏：展示具体界面内容，可分多个 Tab 页显示不同界面。
  3. 内容栏上下两部分：上为 Tab 栏（工具栏见《表单栏布局设计》），下为表单栏（展示具体表单界面字段内容与数据）。
适用范围：PC 管理端（frontend 工程）；移动端 H5（frontend-mobile）为独立工程，见《移动端布局设计》。

2. 左侧导航栏

  • 数据源：动态菜单接口（后端按用户权限过滤返回，按当前 locale 关联 i18n 附表返回翻译文案），前端不硬编码菜单；无权限菜单不渲染。
  • 树状结构：分组 → 菜单项（菜单项可含子菜单），仅叶子结点可点击进入界面。
  • 分组与子菜单支持展开/收起，状态写入 localStorage（key：bms_menu_expanded），刷新后恢复。
  • 单击叶子结点行为：
    • 对应 Tab 未打开 → 新建 Tab 并激活
    • 对应 Tab 已打开 → 直接激活该 Tab（不重复新建）
  • 叶子结点为 router-link，点击走路由联动开 Tab（见 3.3）。

2.1 导航搜索框

  • 位于品牌下方、导航上方，输入关键字过滤导航项。
  • 匹配规则：菜单名包含关键字（忽略大小写），命中叶子后其父级菜单与分组自动展开，未命中的分组整体隐藏。
  • 无匹配时显示「未找到匹配菜单」提示；清空输入恢复默认展开状态。

3. 右侧内容栏（Tab 页）

3.1 Tab 组成

  • 固定首页 Tab（工作台）：默认打开、不可关闭，关闭其它 Tab 后回退到首页。
  • 业务 Tab：由导航叶子结点打开，可单独关闭。

3.2 打开与切换

  • 同一路由只允许一个 Tab：重复点击导航叶子不新建，只切换激活。
  • 每个 Tab 与 URL 一一对应：激活 Tab 时同步路由跳转（如 /users），支持浏览器前进/后退。
  • 通过收藏夹/地址栏直接访问某路由：若该路由 Tab 未打开，先新建再激活。
  • Tab 路径白名单 ALLOWED_PATHS：仅业务页面可成为 Tab，登录页等自动排除。
  • 无权限访问：路由守卫校验当前用户权限码，无权限跳转 403 页（或首页）；地址栏直接访问无权限路由同样拦截，不新建 Tab。

3.3 路由联动

  • 激活 Tab 时路由 push 同步 URL（如 /users），Tab 与 URL 一一对应。
  • 浏览器前进/后退：路由变化驱动 Tab 激活切换（不新建重复 Tab）。
  • 直接访问 URL（收藏夹/地址栏/分享）：白名单校验 → 有权限且 Tab 未打开则先新建再激活；无权限拦截（见上）。

3.4 关闭行为

  • 每个 Tab 提供关闭按钮（X）；鼠标中键也可关闭。
  • 关闭激活中的 Tab 后，激活其左侧相邻的 Tab（与 VS Code 一致）。
  • 关闭非激活 Tab：直接关闭，激活状态不变。
  • 未保存保护：Tab 内表单存在未保存修改（dirty 检测）时，关闭前弹确认提示。
  • 工具栏（新增/修改/删除/刷新/关闭）详见《表单栏布局设计》。

3.5 状态保持（keep-alive）

  • 切换 Tab 时组件实例缓存（keep-alive），保留表单输入、列表数据与滚动位置。
  • 缓存白名单 cachedNames 为 ["Workbench", "FormFrame"]：实体页面路由组件均为 FormFrame，列表页/表单页作为其子组件随树整体缓存。
  • :max="20" 限制缓存数量（LRU），避免旧缓存键无限增长。
  • 渲染 key 为 route.path（按路由路径缓存，切换 Tab 复用实例）。
  • 数据刷新策略：激活 Tab 时若缓存超过时效（默认 5 分钟，可配置）自动刷新列表数据；手动刷新按钮即时刷新。

3.6 持久化恢复

  • 已打开的 Tab 列表（含激活项）写入 localStorage（key：bms_open_tabs）。
  • 刷新（F5）后恢复 Tab 列表，并回到最后激活的 Tab。
  • 恢复时按白名单过滤历史脏数据（如旧的 /、/login 条目），再结合当前用户权限过滤（无权限菜单对应的 Tab 丢弃），首页恒在首位。

3.7 溢出处理（更多按钮）

  • .tab 设置 flex-shrink: 0，Tab 不压缩时才会溢出。
  • 监听容器宽度（scrollWidth > clientWidth，含 resize 与 tabs 变化），溢出时显示「更多」（▾）按钮。
  • 点击弹出下拉列表：相对「更多」按钮定位（右缘对齐、位于按钮正下方），展示全部 Tab 含未显示的，当前激活项高亮。
  • 下拉浮层置于 .tab-bar 之外层（tab-more-wrap 相对定位），避免被 tab-list 的 overflow: hidden 裁剪。

3.8 Tab 标题

  • 取菜单名（动态菜单接口返回的当前 locale 翻译），回退路由 meta.title；不直接使用路由 name（PascalCase 仅作代码标识）。
  • 路由 name 与 Tab 标题解耦：菜单 i18n 变更后无需发版。

3.9 Tab 数量上限

  • 打开 Tab 数上限默认 20（可配置），超出后提示并自动关闭最久未激活的 Tab。

4. 内容栏内部结构

表单栏

  • 展示具体界面内容（列表表格、表单等）。
  • 页面自带的「新增/编辑/删除」等操作入口保留在页面内部。
  • 工具栏（新增/修改/删除/刷新/关闭）见《表单栏布局设计》。
  • .main-content 无 max-width 上限，宽度随浏览器缩放自适应（窗口宽 − 侧栏 220px − 内边距）。
  • 面包屑：不采用——Tab 栏已承担页面定位与导航职责，内容栏不再展示面包屑。

5. 工作台首页

  • 路由 /home（name "Workbench"），/ 重定向到 /home，登录成功后默认进入。
  • 内容：欢迎横幅（用户名 + 当前日期，每小时刷新）、快捷入口卡片（跳转各管理页面）、系统信息表。
  • 作为固定首页 Tab，永远存在且不可关闭。

6. 技术要点

  • Tab 状态管理为模块级单例组合式函数 useTabs：维护 Tab 列表、激活项、打开/关闭/激活逻辑与 localStorage 同步（watch 深度监听自动持久化）。
  • keep-alive 按组件 name 匹配缓存：路由组件 Workbench/FormFrame 显式声明 name（defineOptions），实体列表页/表单页作为子组件随树缓存。
  • 路由组件根节点需支持缓存（避免缓存后组件卸载副作用），激活切换用路由 push。
  • 更多按钮：监听 Tab 栏容器宽度（resize + tabs 变化），溢出时显示下拉。
