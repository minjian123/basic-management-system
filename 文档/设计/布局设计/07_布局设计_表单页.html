1. 目的与适用范围

规范 BMS 管理端表单页（FormDetailPanel）的统一布局：作为《表单框架布局》FormFrame 的 「表单 Tab」内容，展示单条记录的查看与编辑。用户、部门、角色、采购申请等实体模块的表单页均复用本布局。

表单页承载「记录 Tab」形态（见《表单框架布局》1.2）；列表页（列表 Tab）见《列表页布局》。

2. 页面结构

表单页结构（FormDetailPanel）
工具栏：修改 / 删除 / 刷新 / 关闭（只读态）· 保存（编辑态）
信息栏：详细信息 │ 系统信息
详细信息（主表字段区 + 明细区）
主表字段区：label 右对齐，栅格两列为主
明细 Tab 页区：明细A │ 明细B（行内编辑，仅编辑态可用）
系统信息：ID / 创建时间 / 修改时间（只读）

2.1 信息栏（详细信息/系统信息）

  • 信息栏分两个子 Tab：「详细信息」与「系统信息」。
  • 详细信息 = 主表字段区 + 明细区（主从模块）；无明细的模块只显示主表字段区。
  • 系统信息 = ID / 创建时间 / 修改时间等系统字段，用纯文本展示、不套输入框（只读，无编辑态）。

2.2 主表字段区

  • 布局：label 右对齐，栅格两列为主（el-col :span="12"）；窄容器（移动端/窄抽屉）单列。
  • 分组：> 8 字段用分区标题（el-divider）分组（基本信息/扩展信息）。
  • 主表业务字段：只读态为 disabled 输入框（见 §3），编辑态可编辑；仅系统信息字段（ID/创建/修改时间）用纯文本，不套输入框。

2.3 明细区

  • 多个明细时每个明细一个 Tab 页（明细A/明细B），各自展示其列表。
  • 明细与主表通过明细中的「主表数据 id」列关联（对应当前主表 ID）。
  • 明细工具栏：新增行、删除行（仅编辑态可用）。
  • 明细行行内编辑：字段直接编辑（仅编辑态），保存随主表整体提交。

3. 只读/编辑分态

状态进入方式行为
只读（默认）双击列表行打开 / 保存后停留字段禁用，仅查看；点工具栏「修改」进入编辑态
编辑点「修改」 / 工具栏「新增」打开新 Tab字段可编辑，工具栏「修改」切换为「保存」
  • 新增 Tab 打开即编辑态（无需先点「修改」），保存后回填 id。
  • 修改未保存时切换/关闭 Tab → 弹确认框（脏数据保护，dirty 检测）。

4. 字段权限与脱敏

  • 字段权限联动：字段按表单元数据接口下发的字段权限渲染——visible=false 的字段不渲染（读时过滤），editable=false 的字段即使在编辑态也保持禁用（写时校验由后端兜底）。
  • 敏感字段脱敏：只读/编辑态均按脱敏规则掩码展示（如手机号 138****5678），持 data:plain 权限码方可查看明文。
  • 字段 i18n：字段标签与表单标题取自表单元数据接口返回的当前 locale 翻译（sys_field_i18n 附表），前端不硬编码文案。

5. 表单组织

  • 布局：label 右对齐，栅格两列为主（el-col :span="12"），窄抽屉单列。
  • 分组：> 8 字段用分区标题（el-divider）分组（基本信息/扩展信息）。
  • 校验：必填项 required + 规则与后端一致（《API接口规范》）；错误信息走 i18n。
  • 提交：保存按钮 loading 防重复提交；成功后关闭并刷新列表（或局部更新）。
  • 系统字段（创建时间、编号）用纯文本展示，不套输入框；主表业务字段按 §3 只读/编辑分态。

6. 校验与提交

  • 必填/格式校验规则与后端一致（《API接口规范》），错误提示走 i18n。
  • 整体保存（主从模块）：工具栏「保存」一次性提交主表 + 全部明细（单事务），保证主表与明细一致性。
  • 新增主表时，明细的「主表数据 id」在保存事务内用新主表 ID 回填。
  • 乐观锁冲突：保存请求携带记录 version，后端比对失败（已被他人修改）返回冲突错误，前端提示「记录已被修改」并重新加载最新数据。
  • 保存成功后自动刷新列表 Tab（列表数据与表单一致）。

7. 文件类字段

  • 字段类型含文件（图片/PDF 等）时使用通用上传组件：上传走文件接口（分片上传/断点续传）、预览用预签名 URL 直开、下载走预签名 URL（限时有效）。
  • 文件字段同样受字段权限与脱敏规则约束。

8. 与 FormFrame 的交互

交互方向约定
记录标识FormFrame → 表单页prop main-id（Number，null 表示新增）
保存/删除/标题表单页 → FormFrameemit("saved", id) / emit("deleted") / emit("title-change", 名称)
脏数据状态FormFrame ← 表单页表单页 expose dirty（切换/关闭 Tab 时拦截确认）
  • 路由：实体页面路由组件为 FormFrame，通过路由 props 注入 title / listComponent / detailComponent（详见《表单框架布局》第 2 节）。
  • 表单页被 keep-alive 整体缓存（顶层缓存的是 FormFrame 实例，表单页作为子组件随树缓存），切换顶层 Tab 不丢数据。

9. 检查清单

  • □ 信息栏（详细信息/系统信息）结构正确，主表 + 明细分区
  • □ 只读/编辑分态切换正确，新增 Tab 直接可编辑
  • □ 字段权限（visible/editable）与脱敏规则生效
  • □ 表单栅格/分组/校验规范，错误信息走 i18n
  • □ 主从整体保存单事务，乐观锁冲突提示，保存后刷新列表
  • □ 文件字段走通用上传组件，受权限与脱敏约束
