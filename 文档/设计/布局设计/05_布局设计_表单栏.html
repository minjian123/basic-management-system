1. 表单框架（FormFrame）

用来在「内容栏」中展示表单具体界面内容的布局，分为上下两部分：表单 Tab 页栏 + 表单内容栏。表单内容栏按激活的 Tab 分两种形态：列表页形态（列表 Tab）与表单页形态（记录 Tab）。

1.1 列表 Tab 形态

FormFrame · 列表 Tab 形态
表单 Tab 页栏：列表（固定） │ 记录A × │ 记录B ×
工具栏：新增 / 刷新 / 关闭（左）· 导出 / 更多（右）
关键字 + 常用条件 + 查询/重置（可折叠）筛选区
表格：多选列 + 数据列（无操作列，双击行打开表单 Tab）空状态 / 加载遮罩 / 骨架屏
总数 + 页码 + 每页条数分页区
  • 列表 Tab 为第一个 Tab，不可在表单栏内关闭，始终保持打开，可随整个表单管理页面关闭而关闭。
  • 双击列表数据行 → 新增打开一个 Tab 展示对应表单；已打开则切换到对应 Tab。

1.2 表单 Tab 形态

FormFrame · 表单 Tab 形态（记录A）
表单 Tab 页栏：列表（固定） │ 记录A ×（激活） │ 记录B ×
工具栏：修改 / 删除 / 刷新 / 关闭（只读态）· 保存（编辑态）
信息栏：详细信息 │ 系统信息
详细信息（主表字段区 + 明细区）
主表字段区（label 右对齐，栅格两列为主）
明细 Tab 页区：明细A │ 明细B（行内编辑，仅编辑态可用）
系统信息：ID / 创建时间 / 修改时间（只读）
  • 表单页默认只读查看，点工具栏「修改」进入编辑态；新增 Tab 打开即编辑态（保存后回填 id）。
  • 详情 Tab 标题取记录标识字段（如名称），新增未保存前显示「新建xxx」。
  • 每个详情 Tab 渲染一个独立的表单页组件实例（可同时打开多条记录）。

2. 职责分离（列表页与表单页各自独立）

列表页与表单页为独立组件文件，各自承载业务逻辑，将来可各自添加权限控制，互不渗透。二者仅通过约定事件与暴露的方法与表单框架交互：

交互方向约定
打开详情 Tab列表页 → FormFrameemit("open-detail", item)（null 表示新增）
刷新列表FormFrame → 列表页保存/删除成功后调用列表页暴露的 fetchList()
记录标识FormFrame → 表单页prop main-id（Number，null 表示新增）
保存/删除/标题表单页 → FormFrameemit("saved", id) / emit("deleted") / emit("title-change", 名称)
脏数据状态FormFrame ← 表单页表单页 expose dirty（切换/关闭 Tab 时拦截确认）
  • 路由：实体页面路由组件为 FormFrame，通过路由 props 注入 title / listComponent / detailComponent。
  • 动态组件解析：listComponent / detailComponent 为动态菜单接口下发的组件名，前端维护「组件名 → 组件」映射表（import.meta.glob 批量注册）；遇到未注册的组件名时拦截并提示（防菜单配置错误导致白屏），不渲染空页面。

3. 表单页内部结构（FormDetailPanel）

表单页（属性/效果/状态）复用共享组件 FormDetailPanel：

  • 只读/编辑分态：表单默认只读查看（字段禁用），点工具栏「修改」进入编辑态后字段可编辑。
  • 字段权限联动：字段按表单元数据接口下发的字段权限渲染——visible=false 的字段不渲染（读时过滤），editable=false 的字段即使在编辑态也保持禁用（写时校验由后端兜底）。
  • 字段 i18n：字段标签与表单标题取自表单元数据接口返回的当前 locale 翻译（sys_field_i18n 附表），前端不硬编码文案。
  • 敏感字段脱敏：只读/编辑态均按脱敏规则掩码展示（如手机号 138****5678），持 data:plain 权限码方可查看明文。
  • 信息栏：分「详细信息」与「系统信息」两个子 Tab：
    • 详细信息：主表 + 明细上下两部分——主表为除系统信息外的字段；明细用 Tab 页展示（多个明细一个 Tab 一个列表），明细与主表通过明细中的「主表数据 id」列关联（对应当前主表 ID），明细行内编辑与增删行仅编辑态可用。
    • 系统信息：ID、创建时间、修改时间等系统字段（只读）。
  • 用户无明细结构，表单页自行实现简单表单（用户含密码特殊逻辑：编辑留空不修改）。

列表页无操作列（数据行仅展示，双击行打开表单）；遵循统一分页规范：page/size 分页（响应 {list, total, page, size}），筛选条件走查询参数；大数据量场景游标分页兜底。

3.1 文件类字段

  • 字段类型含文件（图片/PDF 等）时使用通用上传组件：上传走文件接口（分片上传/断点续传）、预览用预签名 URL 直开、下载走预签名 URL（限时有效）。
  • 文件字段同样受字段权限与脱敏规则约束。

4. 交互细节

4.1 详情 Tab 生命周期

场景行为
双击列表行打开该记录的表单 Tab（默认只读态）；已打开则直接切换
列表工具栏「新增」打开空表单 Tab（新增态，直接可编辑），保存后回填 id 并刷新列表
点「修改」从只读态进入编辑态，字段启用
关闭表单 Tab回到列表 Tab（列表 Tab 不可关，始终存在）
修改未保存时切换/关闭表单 Tab弹出确认框（脏数据保护），确认后丢弃

4.2 保存与事务

  • 整体保存（主从模块）：工具栏「保存」一次性提交主表 + 全部明细（单事务），保证主表与明细一致性。
  • 新增主表时，明细的「主表数据 id」在保存事务内用新主表 ID 回填。
  • 乐观锁冲突：保存请求携带记录 version，后端比对失败（已被他人修改）返回冲突错误，前端提示「记录已被修改」并重新加载最新数据。
  • 保存成功后自动刷新列表 Tab（列表数据与表单一致）。

5. 工具栏

工具栏为一行，统一提供：新增、修改、保存、删除、刷新、关闭等按钮（不区分层级）。

按钮出现状态说明
新增列表 Tab打开空表单 Tab（新增态，直接可编辑），保存后写入并刷新列表
修改表单 Tab（只读态）从只读态进入编辑态，字段启用
保存表单 Tab（编辑态）保存当前表单修改（主从模块整体提交主表 + 全部明细，单事务）
删除表单 Tab删除当前记录（含明细，需确认）
刷新列表/表单 Tab重新加载当前数据（丢弃未保存修改，触发脏数据确认）
关闭表单 Tab关闭当前表单 Tab，回到列表 Tab
  • 按钮按激活状态与编辑态启用：列表 Tab 提供「新增/刷新」；表单 Tab 只读态提供「修改/删除/刷新/关闭」，编辑态将「修改」切换为「保存」；按钮归属对应页面各自实现。
  • 按钮权限联动：工具栏按钮按动作权限码显隐（v-perm="'业务:动作'"），默认无任何按钮权限——如「新增」需 {业务}:create、「删除」需 {业务}:delete、进入编辑需 {业务}:update；后端接口同步强制校验。

5.1 明细区交互

  • 明细工具栏：新增行、删除行（作用于当前明细 Tab 的列表，仅编辑态可用）。
  • 明细行行内编辑：字段直接编辑（仅编辑态），保存随主表整体提交。
  • 多个明细时，每个明细独立 Tab 页展示其列表。

6. 技术要点

  • 表单内 Tab 为页面内部状态（FormFrame 组件内维护），独立于顶层 useTabs，不参与 URL 与 localStorage 持久化；刷新页面后恢复为仅列表 Tab（详情 Tab 丢失可接受）。
  • 表单页被 keep-alive 整体缓存（顶层缓存的是 FormFrame 实例，表单/列表页作为子组件随树缓存），切换顶层 Tab 不丢数据。
  • 脏数据检测：各表单页维护 dirty 标记（watch 表单变化），FormFrame 切换/关闭 Tab 时读取并拦截确认。
  • 主表-明细保存：单事务提交，明细「主表数据 id」由保存事务内生成的主表 ID 回填。
  • 行内编辑：明细行字段直接 v-model 绑定，未保存修改随整体保存一并提交。
