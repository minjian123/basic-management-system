1. 表单框架（FormFrame）

用来在「内容栏」中展示表单具体界面内容的布局，分为上下两部分：表单 Tab 页栏 + 表单内容栏。表单内容栏按激活的 Tab 显示两种并排（互斥切换）的形态：激活「列表」Tab 显示列表页，激活「记录A」Tab 显示表单页——两者为同一 Tab 栏下的切换关系，不是嵌套关系。详细布局分别见《列表页布局》与《表单页布局》。

1.1 形态一：列表 Tab（激活「列表」）

FormFrame · 列表 Tab（激活）
表单 Tab 页栏：列表（激活） │ 记录A × │ 记录B ×
→ 列表页布局：工具栏（新增/刷新/关闭）
筛选区 → 表格（无操作列，双击行打开表单 Tab）→ 分页区

1.2 形态二：表单 Tab（激活「记录A」）

FormFrame · 表单 Tab（激活）
表单 Tab 页栏：列表 │ 记录A ×（激活） │ 记录B ×
→ 表单页布局：工具栏（修改/删除/刷新/关闭，编辑态变保存）
信息栏：详细信息（主表字段区 + 明细区）│ 系统信息
  1. 表单 Tab 页栏：可分多个 Tab 页显示不同表单内容。
    • 第一个 Tab 为列表内容（列表页），不可在表单框架内关闭，始终保持打开，可随整个表单管理页面关闭而关闭。
    • 双击列表数据行，新增打开一个 Tab 展示对应表单；已打开则切换到对应 Tab。
    • 详情 Tab 标题取记录标识字段（如名称），新增未保存前显示「新建xxx」。
  2. 表单内容栏：同一时刻只显示一个 Tab 的内容——列表 Tab 渲染列表页组件；每个详情 Tab 渲染一个独立的表单页组件实例（可同时打开多条记录，切换显示）。

2. 职责分离（列表页与表单页各自独立）

列表页与表单页为独立组件文件（见《列表页布局》《表单页布局》），各自承载业务逻辑，将来可各自添加权限控制，互不渗透。二者仅通过约定事件与暴露的方法与表单框架交互：

交互方向约定
打开详情 Tab列表页 → FormFrameemit("open-detail", item)（null 表示新增）
刷新列表FormFrame → 列表页保存/删除成功后调用列表页暴露的 fetchList()
记录标识FormFrame → 表单页prop main-id（Number，null 表示新增）
保存/删除/标题表单页 → FormFrameemit("saved", id) / emit("deleted") / emit("title-change", 名称)
脏数据状态FormFrame ← 表单页表单页 expose dirty（切换/关闭 Tab 时拦截确认）
  • 路由：实体页面路由组件为 FormFrame，通过路由 props 注入 title / listComponent / detailComponent。
  • 动态组件解析：listComponent / detailComponent 为动态菜单接口下发的组件名，前端维护「组件名 → 组件」映射表（import.meta.glob 批量注册）；遇到未注册的组件名时拦截并提示（防菜单配置错误导致白屏），不渲染空页面。

3. 交互细节（框架层）

表单页自身的只读/编辑分态、字段权限、保存与事务见《表单页布局》；本节只约定 FormFrame 框架层的 Tab 行为。

3.1 详情 Tab 生命周期

场景行为
双击列表行打开该记录的表单 Tab（默认只读态）；已打开则直接切换
列表工具栏「新增」打开空表单 Tab（新增态，直接可编辑），保存后回填 id 并刷新列表
点「修改」从只读态进入编辑态，字段启用
关闭表单 Tab回到列表 Tab（列表 Tab 不可关，始终存在）
修改未保存时切换/关闭表单 Tab弹出确认框（脏数据保护），确认后丢弃

4. 工具栏

工具栏为一行，统一提供：新增、修改、保存、删除、刷新、关闭等按钮（不区分层级）；位于筛选区上方（见《列表页布局》第 2 节）。

按钮出现状态说明
新增列表 Tab打开空表单 Tab（新增态，直接可编辑），保存后写入并刷新列表
修改表单 Tab（只读态）从只读态进入编辑态，字段启用
保存表单 Tab（编辑态）保存当前表单修改（主从模块整体提交主表 + 全部明细，单事务）
删除表单 Tab删除当前记录（含明细，需确认）
刷新列表/表单 Tab重新加载当前数据（丢弃未保存修改，触发脏数据确认）
关闭表单 Tab关闭当前表单 Tab，回到列表 Tab
  • 按钮按激活状态与编辑态启用：列表 Tab 提供「新增/刷新」；表单 Tab 只读态提供「修改/删除/刷新/关闭」，编辑态将「修改」切换为「保存」；按钮归属对应页面各自实现。
  • 按钮权限联动：工具栏按钮按动作权限码显隐（v-perm="'业务:动作'"），默认无任何按钮权限——如「新增」需 {业务}:create、「删除」需 {业务}:delete、进入编辑需 {业务}:update；后端接口同步强制校验。

5. 技术要点

  • 表单内 Tab 为页面内部状态（FormFrame 组件内维护），独立于顶层 useTabs，不参与 URL 与 localStorage 持久化；刷新页面后恢复为仅列表 Tab（详情 Tab 丢失可接受）。
  • 表单页被 keep-alive 整体缓存（顶层缓存的是 FormFrame 实例，表单/列表页作为子组件随树缓存），切换顶层 Tab 不丢数据。
  • 脏数据检测：各表单页维护 dirty 标记（watch 表单变化），FormFrame 切换/关闭 Tab 时读取并拦截确认。
  • 主表-明细保存：单事务提交，明细「主表数据 id」由保存事务内生成的主表 ID 回填（详见《表单页布局》第 6 节）。
  • 行内编辑：明细行字段直接 v-model 绑定，未保存修改随整体保存一并提交。
