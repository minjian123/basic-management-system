1. 目的与适用范围

规范 BMS 的亮/暗色主题与多租户品牌化（logo、主色、名称）机制， 支撑 SaaS 多租户的视觉隔离（见《租户管理》）。 基于《全局设计令牌》实现。

2. 主题体系（亮/暗色）

模式触发要点
亮色（默认）默认 / 跟随系统令牌默认值（见《全局设计令牌》）
暗色用户偏好（记忆）或跟随系统仅反转语义色与背景令牌，保持对比度 ≥ 4.5:1
  • 主题切换不刷新页面：[data-theme="dark"] 覆盖令牌，组件库同步（Element Plus dark CSS 变量）。
  • 图标/插画需双主题适配（使用语义色填充，不硬编码浅色）。
  • 暗色模式为阶段二后的体验优化，首个 MVP 版本可不做（登记需求）。

3. 租户品牌化

项来源说明
主色租户配置（sys_tenant 主题字段）覆盖 --color-primary 及其衍生色（hover/active/浅色背景）
Logo租户上传（MinIO）侧边栏/登录页/移动端三处统一替换
系统名称租户配置登录页、标题、浏览器 title
登录页背景租户可选默认使用平台默认背景
主色覆盖必须基于令牌推导：定义 primary 后由 SCSS 函数生成 primary-light-3、primary-dark-2 等衍生色，禁止手写多组色值； 并保证状态色（成功/警告/危险）语义不变（《全局设计令牌》第 2 节）。

4. 品牌资源管理

  • 平台默认资源：src/assets/brand/（logo-bms.svg、login-bg.svg 等，kebab-case）。
  • 租户资源存 MinIO bms-{租户} bucket（《命名规范》），前端按租户上下文拉取并缓存。
  • 资源变更后前端局部刷新（登录页/侧栏 logo 不整页重载）。

  • 登录后由后端下发租户主题配置（/api/v1/tenant/profile），前端写入 data-tenant 与 CSS 变量。
  • 用户主题偏好存本地（localStorage，key bms:theme）或用户喜好表（《用户喜好》）。

6. 检查清单

  • □ 主题基于令牌覆盖，无硬编码色值
  • □ 租户主色衍生色自动生成，状态色语义不变
  • □ Logo/名称/登录页按租户替换，资源走 MinIO
  • □ 切换不刷新、无闪烁，偏好可记忆
  • □ 暗色模式对比度达标（若启用）
