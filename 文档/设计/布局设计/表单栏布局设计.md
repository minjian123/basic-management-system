# 表单栏布局设计

用来在前端布局设计的"内容栏"中展示表单具体界面内容的布局。


## 表单框架（FormFrame）

用来展示具体界面内容，分为上下两部分：

1. **表单 Tab 页栏**：可以分多个 Tab 页显示不同的表单界面具体内容。
   1.1 第一个 Tab 页默认是表单的列表内容（列表页），不可在表单栏内关闭，始终保持打开，但可以随着整个表单管理页面关闭而关闭。
   1.2 双击列表内容的数据行，在表单 Tab 页栏新增打开一个 Tab 页，展示对应表单界面。
   1.3 如果已有打开对应表单界面的 Tab 页，切换到对应 Tab 页。
   1.4 详情 Tab 的标题取记录标识字段（如名称），新增未保存前显示"新建xxx"。
2. **表单内容栏**：Tab 内容区。
   - 列表 Tab 渲染列表页组件；每个详情 Tab 渲染一个独立的表单页组件实例（可同时打开多条记录）。

```
┌───────────────────────────────────────────────┐
│ 表单Tab页栏: [列表(固定)][记录A ×][记录B ×]       │
├───────────────────────────────────────────────┤
│ 列表Tab: 列表页（自带工具栏：新增/刷新 + 表格，    │
│          无操作列，双击行打开表单）               │
│ 详情Tab: 表单页（默认只读查看，点"修改"进入编辑态）│
│          └ 信息栏: [详细信息] [系统信息]          │
│             ├ 详细信息: 主表字段区                │
│             │           明细Tab页区(明细A/明细B)  │
│             └ 系统信息: ID/创建时间/修改时间(只读) │
└───────────────────────────────────────────────┘
```

## 职责分离（列表页与表单页各自独立）

列表页与表单页为**独立组件文件**，各自承载业务逻辑，将来可各自添加权限控制，互不渗透。二者仅通过约定事件与暴露的方法与表单框架交互：

| 交互 | 方向 | 约定 |
|------|------|------|
| 打开详情 Tab | 列表页 → FormFrame | `emit("open-detail", item)`（null 表示新增） |
| 刷新列表 | FormFrame → 列表页 | 保存/删除成功后调用列表页暴露的 `fetchList()` |
| 记录标识 | FormFrame → 表单页 | prop `main-id`（Number，null 表示新增） |
| 保存/删除/标题 | 表单页 → FormFrame | `emit("saved", id)` / `emit("deleted")` / `emit("title-change", 名称)` |
| 脏数据状态 | FormFrame ← 表单页 | 表单页 `expose dirty`（切换/关闭 Tab 时拦截确认） |

路由：实体页面路由组件为 `FormFrame`，通过路由 `props` 注入 `title` / `listComponent` / `detailComponent`。

## 表单页内部结构（FormDetailPanel）

表单页（属性/效果/状态）复用共享组件 `FormDetailPanel`：

- **只读 / 编辑分态**：表单默认只读查看（字段禁用），点工具栏"修改"进入编辑态后字段可编辑
- **字段权限联动**：字段按表单元数据接口下发的字段权限渲染——`visible=false` 的字段不渲染（读时过滤），`editable=false` 的字段即使在编辑态也保持禁用（写时校验由后端兜底）
- **字段 i18n**：字段标签与表单标题取自表单元数据接口返回的当前 locale 翻译（sys_field_i18n 附表），前端不硬编码文案
- **敏感字段脱敏**：只读/编辑态均按脱敏规则掩码展示（如手机号 `138****5678`），持 `data:plain` 权限码方可查看明文
- **信息栏**：分为"详细信息"和"系统信息"两个子 Tab
  - 详细信息：分为主表和明细上下两部分展示
    - 主表：除了系统信息字段之外的其他字段
    - 明细：使用 Tab 页展示，可能会有多个明细，一个明细一个 Tab 页展示明细列表内容
      - 明细与主表的关联：使用明细中的"主表数据 id"列进行具体关联，对应当前主表的 ID 字段
      - 明细行行内编辑与增删行仅在编辑态可用
  - 系统信息：显示 ID、创建时间、修改时间等系统字段信息（只读展示）
- 用户/故事无明细结构，表单页自行实现简单表单（用户含密码特殊逻辑：编辑留空不修改）

列表页无操作列：数据行仅展示，双击行打开表单。
列表页遵循统一分页规范：`page`/`size` 分页（响应 `{list, total, page, size}`），筛选条件走查询参数；大数据量场景游标分页兜底。

### 文件类字段

- 字段类型含文件（图片/PDF 等）时使用通用上传组件：上传走文件接口（分片上传/断点续传）、预览用预签名 URL 直开、下载走预签名 URL（限时有效）
- 文件字段同样受字段权限与脱敏规则约束

## 交互细节

### 详情 Tab 生命周期

| 场景 | 行为 |
|------|------|
| 双击列表行 | 打开该记录的表单 Tab（**默认只读态**）；已打开则直接切换 |
| 列表工具栏"新增" | 打开空表单 Tab（新增态，直接可编辑），保存后回填 id 并刷新列表 |
| 点"修改" | 从只读态进入编辑态，字段启用 |
| 关闭表单 Tab | 回到列表 Tab（列表 Tab 不可关，始终存在） |
| 修改未保存时切换 / 关闭表单 Tab | 弹出确认框（脏数据保护），确认后丢弃 |

### 保存与事务

- **整体保存**（主从模块）：工具栏"保存"一次性提交主表 + 全部明细（单事务），保证主表与明细一致性
- 新增主表时，明细的"主表数据 id"在保存事务内用新主表 ID 回填
- **乐观锁冲突**：保存请求携带记录 `version`，后端比对失败（已被他人修改）返回冲突错误，前端提示"记录已被修改"并重新加载最新数据
- 保存成功后自动刷新列表 Tab（列表数据与表单一致）

## 工具栏

工具栏为**一行**，统一提供：新增、修改、保存、删除、刷新、关闭等按钮（不区分层级）。

| 按钮 | 出现状态 | 说明 |
|------|----------|------|
| 新增 | 列表 Tab | 打开空表单 Tab（新增态，直接可编辑），保存后写入并刷新列表 |
| 修改 | 表单 Tab（只读态） | 从只读态进入编辑态，字段启用 |
| 保存 | 表单 Tab（编辑态） | 保存当前表单的修改（主从模块整体提交主表 + 全部明细，单事务） |
| 删除 | 表单 Tab | 删除当前记录（含明细，需确认） |
| 刷新 | 列表 / 表单 Tab | 重新加载当前数据（丢弃未保存修改，触发脏数据确认） |
| 关闭 | 表单 Tab | 关闭当前表单 Tab，回到列表 Tab |

工具栏按钮按激活状态与编辑态启用：列表 Tab 提供"新增 / 刷新"；表单 Tab 只读态提供"修改 / 删除 / 刷新 / 关闭"，编辑态将"修改"切换为"保存"；按钮归属对应页面（列表页、表单页）各自实现。

**按钮权限联动**：工具栏按钮按动作权限码显隐（`v-perm="'业务:动作'"`），默认无任何按钮权限——如"新增"需 `{业务}:create`、"删除"需 `{业务}:delete`、进入编辑需 `{业务}:update`；后端接口同步强制校验。

### 明细区交互

- 明细工具栏：新增行、删除行（作用于当前明细 Tab 的列表，仅编辑态可用）
- 明细行**行内编辑**：字段直接编辑（仅编辑态），保存随主表整体提交
- 多个明细时，每个明细独立 Tab 页展示其列表

## 技术要点

- 表单内 Tab 为**页面内部状态**（FormFrame 组件内维护），独立于顶层 `useTabs`，不参与 URL 与 localStorage 持久化；刷新页面后恢复为仅列表 Tab（详情 Tab 丢失可接受）
- 表单页被 keep-alive 整体缓存（顶层缓存的是 FormFrame 实例，表单/列表页作为子组件随树缓存），切换顶层 Tab 不丢数据
- 脏数据检测：各表单页维护 dirty 标记（watch 表单变化），FormFrame 切换/关闭 Tab 时读取并拦截确认
- 主表-明细保存：单事务提交，明细"主表数据 id"由保存事务内生成的主表 ID 回填
- 行内编辑：明细行字段直接 `v-model` 绑定，未保存修改随整体保存一并提交
