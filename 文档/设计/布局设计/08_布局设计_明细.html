1. 目的与适用范围

规范 BMS 管理端明细（主从模块的子表数据）的统一展示与编辑布局。 明细组件嵌入《列表页》与《表单页》中使用， 用于主从模块（如采购申请 + 明细行、审批单 + 流转明细）的数据记录明细展示。

主从模块：主表一条记录对应明细多行（1:N）。明细复用统一组件（明细列表），列表页与表单页通过 props 注入数据源与编辑态。

2. 明细列表结构

明细区结构
明细工具栏：新增行 / 删除行（仅编辑态）
明细表格：数据列 + 主表数据 id 列（隐藏，用于关联）行内编辑（仅编辑态可用）· 空状态 / 加载态

2.1 多明细（Tab 页）

  • 主表存在多个明细（明细A/明细B）时，每个明细一个 Tab 页，各自展示其列表。
  • 明细 Tab 与主表字段区同处「详细信息」信息栏（见《表单页布局》2.1）。

2.2 单明细

  • 仅一个明细时直接展示明细列表，不套 Tab 壳。
  • 无明细结构的主从模块（如用户）不显示明细区，表单页自行实现简单表单。

3. 嵌入位置

3.1 列表页中的明细

  • 列表页（主表列表）中，明细以展开行（el-table expand）或行内子表形式展示：点击展开图标查看该主表记录关联的明细行。
  • 展开行明细为只读列表（数量有限制，如最多展示最近 N 条），完整明细在表单页查看/编辑。
  • 明细列宽自适应，超出横向滚动；不承载新增/删除操作。

3.2 表单页中的明细

  • 表单页（记录 Tab）中，明细位于「详细信息」信息栏的主表字段区下方（或明细 Tab 页区），完整展示与编辑。
  • 只读态：明细行仅展示（字段禁用），随主表整体只读。
  • 编辑态：明细工具栏与行内编辑可用（见第 4、5 节）。

4. 明细工具栏

  • 提供：新增行、删除行（作用于当前明细列表，仅编辑态可用）。
  • 删除行需二次确认（ElMessageBox.confirm）。
  • 批量操作（如明细行勾选批量删除）按需提供，受权限码控制。

5. 行内编辑

  • 明细行行内编辑：字段直接 v-model 绑定（仅编辑态），未保存修改随整体保存一并提交。
  • 文件类字段同表单页规则（通用上传组件、预签名 URL，见《表单页布局》第 7 节）。
  • 字段校验与主表一致（必填/格式，错误提示走 i18n）。

6. 与主表关联

  • 明细与主表通过明细中的「主表数据 id」列关联（对应当前主表 ID）。
  • 新增主表时，明细的「主表数据 id」在保存事务内用新主表 ID 回填。
  • 关联遵循逻辑外键约定（不建物理外键，见《数据库开发规范》）。

7. 保存与事务

  • 整体保存：工具栏「保存」一次性提交主表 + 全部明细（单事务），保证主表与明细一致性。
  • 乐观锁：保存携带主表 version，冲突时提示「记录已被修改」并重新加载。
  • 保存成功后自动刷新列表页（含展开行明细）与表单页（详见《表单框架布局》第 2 节交互协议）。

8. 检查清单

  • □ 明细组件嵌入列表页（展开行只读）与表单页（信息栏完整编辑）
  • □ 多明细 Tab 化、单明细直接展示
  • □ 明细工具栏/行内编辑仅编辑态可用，删除二次确认
  • □ 「主表数据 id」关联正确，新增主表事务内回填
  • □ 整体保存单事务 + 乐观锁，保存后刷新主表列表
  • □ 字段校验与文件字段规则同表单页
