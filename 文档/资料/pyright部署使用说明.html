1. 简介与选型理由

pyright 是微软出品的 Python 静态类型检查器（TypeScript 实现），以严格模式（strict）闻名：对任何「类型未知」的情况都要报告，逼着把类型写明白。VS Code 的 Pylance 就是基于它。

BMS 规划选型 pyright 的理由：严格类型检查，与 Pydantic v2 模型配合，可在 IDE 中即时发现类型错误，不必等运行时报错。

本机版本：pyproject.toml 声明 pyright>=1.1.411（2026-08-05 核实，pyright 版本持续以 1.1.x 递增发布，实际安装版本以 uv.lock 为准）。

2. 安装

BMS 后端已声明开发依赖 pyright>=1.1.411（dev 组），backend 目录执行 uv sync 即装好。

新项目手动添加（PowerShell）：

uv add --dev pyright

验证安装：

uv run pyright --version

3. 常用命令

3.1 全量检查

uv run pyright

按 pyproject 的 [tool.pyright] 配置扫描全部纳入范围的文件。有错误时逐条输出文件:行:列 - error: 说明，退出码非 0。

3.2 单文件检查

uv run pyright app/core/config.py

只查指定文件，改代码时快速看某处类型对不对用得上。

3.3 IDE 集成

VS Code 装 Pylance 扩展即可：它读同一份 [tool.pyright] 配置，编辑时实时报类型错误，与命令行结果一致。

当前遗留问题（2026-08-05 本机核实）：app/core/config.py 有 2 个类型错误，位于 104-105 行——target 与 next() 实参被判定为 dict[Unknown, Unknown]（reportUnknownVariableType / reportUnknownArgumentType）。root cause：tomllib.load() 返回的嵌套 dict 在遍历合并过程中类型信息丢失。此问题须在阶段一任务 9 之前清零。

  d:\Develop\bms\backend\app\core\config.py:105:17 - error: Argument type is partially unknown
    Argument corresponds to parameter "i" in function "next"

2 errors, 0 warnings, 0 informations

修复方向（建议）：给 _TomlSource.__call__() 里的中间字典补显式类型注解（如 dict[str, Any]），消除遍历中的类型推断丢失。修复后 uv run pyright 应为 0 errors。

5. 常见问题

现象处理
strict 一开，全是 reportUnknown* 报错Unknown 表示「pyright 无法确定类型」，逐层补显式注解（dict[str, Any] 等）即可消掉，这是严格模式的常态工作
第三方库报「no type stub」类错误库未带类型标注；可用 # type: ignore[reportXxx] 局部豁免并写明原因，或给库补类型 stub
IDE 里不报、命令行报（或反过来）确认两边读的是同一个 pyproject.toml；VS Code 若开了别的 Python 解释器需切换为项目 .venv
config.py 的两个错误现在能不能放着不管不能：规划要求阶段一任务 9 前清零，测试骨架（任务 9）和 CI 都会把它当门禁
改了配置没生效pyright 每次运行独立读取配置，无缓存概念；改完 pyproject.toml 重跑即可
