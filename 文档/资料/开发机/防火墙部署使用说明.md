## 1. 目的与适用范围 <a id="purpose"></a>

记录开发机 **mjpc**（Ubuntu 26.04.1 LTS，主机名 `mjpc`）的 ufw 防火墙现状、规则口径、启用过程与验证结果，作为后续增删规则的唯一参照。

与开发服务器 mjbk 的口径差异：mjbk 承载全部服务、按《[开发部署规划](../../规划/开发部署规划.md)》第 9 节逐端口放行；mjpc 为纯开发机、不对外提供服务，因此只做「入站默认拒绝 + 仅放行 SSH」的最小口径。

`<mjpc-IP>` 等取值见《[本地资源](../../用户文档/本地资源.md)》（已 gitignore），不在本文档记录。

## 2. 现状与规则口径 <a id="status"></a>

### 2.1 启用前状态 <a id="fw-status"></a>

2026-08-28 检查确认，启用前 mjpc 没有任何防火墙生效：

| 检查项 | 结果 |
| --- | --- |
| `sudo ufw status` | 状态：不活动 |
| `sudo iptables -S` | 默认策略全放行（INPUT/FORWARD/OUTPUT 均 ACCEPT，无自定义规则） |
| `sudo nft list ruleset` | 空规则集 |
| `systemctl is-active firewalld` | inactive（未安装使用） |

### 2.2 放行规则总表 <a id="rules"></a>

| 规则 | 来源 | 端口 | 用途 |
| --- | --- | --- | --- |
| ALLOW IN | Anywhere | 22/tcp（v4 + v6） | 系统 SSH（预留，见 6.1） |
| 默认策略 | — | incoming: deny；outgoing: allow；routed: 未设置 | 入站默认拒绝、出站默认允许 |

经确认的口径（2026-08-28）：

- 防火墙工具：**ufw**（Ubuntu 自带，版本 0.36.2）
- 入站：默认拒绝 + 白名单放行
- 放行端口：**仅 OpenSSH (22)**
- 出站：默认允许（不影响 apt、上网、302 反代回源）

### 2.3 监听端口说明 <a id="ports-check"></a>

启用时 `ss -ltnp` 实查的监听清单：

| 监听 | 进程 | 暴露面 | 防火墙影响 |
| --- | --- | --- | --- |
| 127.0.0.53 / 127.0.0.54:53 | systemd-resolved | 仅回环 | 无（回环流量不过 INPUT 链） |
| 127.0.0.1:631 | cups 打印 | 仅回环 | 无 |
| 127.0.0.1:80 / 443 | Steamcommunity_302 反代 | 仅回环 | 无（见 6.2） |
| 127.0.0.1:1234 | llama-server（本地模型） | 仅回环 | 无 |
| 127.0.0.1:40289 / 43903 | Steamcommunity_302 控制面 | 仅回环 | 无 |
| `*`:14870 / `*`:31131 | Steamcommunity_302 后端（caddy） | 全接口 | 入站被默认拒绝挡住；本机功能不依赖外部访问，无需放行 |
| 127.0.0.1 临时端口（VSCode / opencode 等） | 编辑器与工具链 | 仅回环 | 无 |

## 3. 启用步骤 <a id="enable"></a>

本次启用的完整操作（复现或重做时照此执行，均需 sudo，按序执行）：

```bash
# 1. 默认策略：入站拒绝、出站允许
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 2. 放行 SSH（注意：本机无 OpenSSH 应用配置文件，
#    `ufw allow OpenSSH` 会报「无法找到相匹配的配置」，须用端口规则）
sudo ufw allow 22/tcp comment 'OpenSSH'

# 3. 启用（SSH 规则已先就位，不会断连）
sudo ufw enable

# 4. 核对
sudo ufw status verbose
```

启用后 `ufw.conf` 为 `ENABLED=yes`、`LOGLEVEL=low`，systemd 单元 `ufw` 处于 enabled（开机自启）。

## 4. 验证 <a id="verify"></a>

```bash
$ sudo ufw status verbose
状态：激活
日志： on (low)
默认：deny (incoming), allow (outgoing), disabled (routed)

至                          动作          来自
-                          --          --
22/tcp                     ALLOW IN    Anywhere                   # OpenSSH
22/tcp (v6)                ALLOW IN    Anywhere (v6)              # OpenSSH
```

功能回归：302 反代走回环地址，不受防火墙影响，启用后实测 `curl https://steamcommunity.com` 仍返回 200，Steam 社区访问正常。

## 5. 日常运维 <a id="ops"></a>

| 操作 | 命令 |
| --- | --- |
| 查看状态与规则 | `sudo ufw status numbered` / `verbose` |
| 新增放行（限内网来源） | `sudo ufw allow from <内网网段> to any port <端口> proto tcp comment '<用途>'` |
| 删除规则 | `sudo ufw delete <编号>`（编号取 `status numbered`） |
| 重载规则 | `sudo ufw reload` |
| 临时停用 | `sudo ufw disable`（恢复用 `sudo ufw enable`） |
| 开机自启确认 | `systemctl is-enabled ufw` |

新增需要对外（内网）可达的服务时：先加 `ufw allow` 规则，再从 mjbk 或同网段机器做 TCP 连通性验证，最后回本文档 2.2 总表登记。

## 6. 已知边界与注意事项 <a id="limits"></a>

### 6.1 SSH 22 为预留放行 <a id="ssh"></a>

启用当日 mjpc 未运行 sshd（`ss -ltn` 无 22 监听），22 放行属预留规则，供日后开启远程登录直接使用；若长期不需要，可用 `sudo ufw delete allow 22/tcp` 移除。

### 6.2 Steamcommunity_302 不受影响 <a id="s302"></a>

302 反代监听 127.0.0.1:80/443（hosts 模式），流量全部走回环，不经过 ufw INPUT 链，防火墙启用前后行为一致。注意其后端 caddy 另有两个全接口监听（14870 / 31131），当前被默认拒绝挡住，本机使用无需放行；若日后需要其他机器直连 302，再按 5. 节流程加规则。

### 6.3 后续启用 Docker 的口径 <a id="docker"></a>

本机当前未安装 Docker。若日后在 mjpc 装 Docker：容器发布端口走 FORWARD 链绕过 ufw INPUT 规则，须先 `sudo ufw default allow routed` 再启用防火墙，否则容器端口全部不通（mjbk 上的同款坑见《[防火墙部署使用说明（mjbk）](../开发服务器/防火墙部署使用说明.md)》6.2 节）。

### 6.4 302 DNS 重定向模式 <a id="s302-dns"></a>

302 当前仅用 hosts 模式（`dns.enabled=false`），不依赖 netfilter。若日后在 302 设置中开启 DNS 重定向（iptables 模式），它会直接写 iptables/nft 规则，与 ufw 共管同一规则集——开启前确认 ufw 处于稳定状态，改动后用 `sudo ufw status` 与 `sudo iptables -S` 双查，异常时先关 302 DNS 模式再 `sudo ufw reload`。
