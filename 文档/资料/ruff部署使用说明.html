1. 简介与选型理由

ruff 是 Astral 出品的 Python lint + 格式化一体化工具（Rust 实现），一套替代 flake8 / black / isort 三件套。检查与格式化都很快，规则默认对标主流工具，不需要额外维护多份配置。

BMS 规划选型 ruff 的理由：lint + format 一体化，性能极高，工程化配置集中在 pyproject.toml 一处，CI 里一条命令跑完。

本机实测版本：ruff 0.16.1（2026-08-05）。

2. 安装

BMS 后端已声明开发依赖 ruff>=0.16.1（dev 组），backend 目录执行 uv sync 即装好。

新项目手动添加（PowerShell）：

uv add --dev ruff

验证安装：

uv run ruff --version

3. 常用命令

3.1 检查

uv run ruff check .

对当前目录全部 Python 文件做 lint。有违规时逐条列出文件:行:列 规则代码 说明，退出码非 0。BMS 的 CI 后端 job 就是跑这条。

3.2 自动修复

uv run ruff check . --fix

能安全自动修的直接改掉（如 import 排序、未用变量删除等），剩下的需要手工处理。--show-fixes 可列出这次实际修了哪些。

3.3 格式化

uv run ruff format .          # 直接格式化
uv run ruff format --check .  # 只检查格式是否符合，不改文件（CI 用）

3.4 指定文件检查

uv run ruff check app/core/config.py
uv run ruff format app/core/config.py

4. 与 BMS 的集成

配置全部写在 backend/pyproject.toml 的 [tool.ruff] 段：

配置项值含义
[tool.ruff] line-length120行长上限 120 字符
[tool.ruff] target-versionpy314按 Python 3.14 语法特性做检查
[tool.ruff.lint] selectE F I UP B ASYNC S N启用的规则集：E pycodestyle 风格、F pyflakes 错误、I import 排序、UP pyupgrade 新语法、B bugbear 常见坑、ASYNC 异步写法、S bandit 安全、N 命名规范
[tool.ruff.lint] ignoreS101豁免 assert 使用（测试里常用）
[tool.ruff.lint.per-file-ignores]"app/core/snowflake/*.py"豁免 E501/UP/B/S/N/ASYNC——vendor 的雪花算法源码（yitter/IdGenerator，MIT），保持算法原样，不强制格式

实施状态：当前 uv run ruff check . 全绿（2026-08-05 本机核实）；CI（阶段一任务 10）在 backend job 中以 uv run ruff check . 作为 PR 门禁。

5. 常见问题

现象处理
check 和 format 分工不清楚format 只重排代码格式、不改语义；import 排序归 I 规则，要靠 check . --fix 修
报错很多，看着吓人先 ruff check . --fix 自动修掉能修的，剩下的逐条看；大部分是 E 系列的空白/行长问题
snowflake 目录的代码被强制改动该目录在 per-file-ignores 已豁免大部分规则，vendor 代码保持原样，不要手动改格式
改完代码 CI 仍报错CI 用 ruff check .，本地务必先跑一遍同一条命令，不要只看编辑器提示
IDE 里想实时提示安装 Ruff 官方 VS Code 扩展，可配置保存时自动 format，与 pyproject 配置同源
