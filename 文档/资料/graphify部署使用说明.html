1. 什么是 graphify

graphify 是一个开源命令行工具（Python 包名 graphifyy），能把任意目录下的 代码、文档、论文、图片、视频自动转换为持久化的知识图谱，并附带社区检测、审计追踪， 产出三种结果：交互式 HTML 可视化、GraphRAG 就绪的 JSON、以及人话版的 GRAPH_REPORT.md。

核心特性：

  • 纯 AST 结构化抽取：代码文件用 Python AST 分析，确定性、免费、无需 API Key。
  • 语义抽取：文档/论文/图片可选用 Gemini API，未配置时由 AI 助手自身完成。
  • 诚实审计：每条关系标注 EXTRACTED（事实）／INFERRED（推断）／AMBIGUOUS（模糊）。
  • 持久化：图谱跨会话保留在 graphify-out/，之后直接用 query 查询，不必重建。
  • 增量更新：--update / graphify update 只重新抽取新增或变更的文件。

2. 环境要求

本机（Windows + PowerShell 7）已验证的环境：

组件要求本机版本
Python≥ 3.103.14.4
uv推荐（工具安装/隔离环境）0.11.7
git克隆 GitHub 仓库时使用2.54.0
graphifypip 或 uv 安装0.9.32
graphify 本身不需要任何 API Key。只有对文档/论文/图片做语义抽取时才可选配 Gemini Key；纯代码目录（最常见的场景）完全免费离线运行。

3. 安装与部署

3.1 安装 graphify（推荐用 uv）

# 方式一：uv 安装（推荐，本机采用此方式）
uv tool install graphifyy

# 方式二：pip 安装
python -m pip install graphifyy

# 验证安装
graphify --version

uv 方式安装后，graphify 被隔离在 C:\Users\minji\AppData\Roaming\uv\tools\graphifyy\，全局可调用 graphify 命令。

3.2 （可选）配置 Gemini 语义抽取

# 先安装 gemini 扩展，再设置环境变量
uv tool install graphifyy --extra gemini
setx GEMINI_API_KEY "你的Key"   # 或 GOOGLE_API_KEY

设置后重启终端生效。未配置时语义抽取自动降级为由 AI 助手自身完成，不影响代码图谱。

3.3 集成到 AI 编程助手

graphify 内置了对主流编程助手的安装命令，可把 skill 与钩子写入对应平台配置：

graphify install opencode   # 写入 AGENTS.md 说明 + tool.execute.before 插件
graphify install claude     # 写入 CLAUDE.md + PreToolUse 钩子
graphify install cursor     # 写入 .cursor/rules/graphify.mdc
graphify uninstall opencode # 卸载（--purge 可同时删除 graphify-out/）
本项目已通过 opencode 集成（graphify install opencode），skill 位于 C:\Users\minji\.config\opencode\skills\graphify\，项目内由 .opencode/ 插件支撑。

4. 首次构建图谱

在项目根目录执行完整构建（推荐在 AI 助手中用 /graphify 触发，或命令行直跑）：

# 在 AI 助手中
/graphify .                          # 对当前目录全流程构建

# 命令行直跑（无 LLM，纯代码目录）
graphify extract . --code-only

# 指定路径 / 深度模式 / 只建报告不建可视化
graphify extract 文档/ --mode deep
graphify extract . --no-cluster

构建流程分四步：

  1. 检测：扫描目录，分类统计代码/文档/论文/图片/视频文件。
  2. 抽取：代码走 AST（免费快速），文档/图片走语义抽取（可选 Gemini）。
  3. 聚类与分析：社区检测、凝聚度评分、枢纽节点（god nodes）识别。
  4. 输出：生成 graph.html、graph.json、GRAPH_REPORT.md 及分析侧车文件。
注意：目录超过 500 个文件或 200 万词时，graphify 会提示收敛范围；建议按子目录分别构建。超过 5000 节点时 HTML 可视化会自动聚合到社区视图，不要用 --no-viz 之外的方式强行渲染。

5. 输出产物说明

所有产物都在 graphify-out/ 目录下：

文件说明
graph.html交互式图谱，浏览器直接打开，可缩放、点节点看详情。
graph.json原始图数据（GraphRAG 就绪），供 query/path/explain 等命令查询。
GRAPH_REPORT.md人话版审计报告：God Nodes、意外关联、建议问题、token 成本。
manifest.json文件清单与语义哈希，update 增量更新依赖它。
cost.json累计 token 成本跟踪。
.graphify_python记录本次使用的 Python 解释器路径（skill 内部使用）。
.graphify_root记录的扫描根目录，供无参 update 使用。
cache/语义抽取缓存，未变更文件不重复抽取。

6. 日常使用

6.1 自然语言查询

graphify query "认证流程如何处理token刷新？"   # BFS 广度遍历
graphify query "数据如何流入审计模块？" --dfs   # DFS 深度追踪
graphify query "……" --budget 1500              # 限制回答 token 数

6.2 路径与概念

graphify path "AuthModule" "Database"   # 两概念间最短路径
graphify explain "JWT"                  # 用大白话解释某节点及其邻居

6.3 影响面与枢纽

graphify affected "UserService" --depth 2   # 反向遍历：谁会被它影响
graphify god-nodes --top 10                 # 架构枢纽节点排行

6.4 增量构建常用参数

graphify update .                  # 只抽取新增/变更代码，免费无 LLM
graphify update . --force          # 重建后节点数变少时覆盖（大重构后使用）
graphify watch 文档/               # 监视目录，代码变更自动重建
graphify cluster-only .            # 只重跑聚类和报告

7. 维护与更新

  • 代码改动后：运行 graphify update . 保持图谱最新（纯 AST，无 API 开销）。本项目 AGENTS.md 已约定：修改代码后运行 graphify update .。
  • 大重构删除了代码：graphify update . --force（防止旧图谱残留导致误判）。
  • 提交钩子：graphify hook install 安装 post-commit 自动重建钩子。
  • 全局图谱：多个项目可合并到全局图 graphify global add 项目路径，跨仓库查询。

8. 与 AI 编程助手的集成

项目根目录 AGENTS.md 中已写入 graphify 使用规则，AI 助手会遵循：

  • 代码库问题优先 graphify query "<问题>"，关系用 graphify path，概念用 graphify explain——返回的子图比全文 grep 小得多。
  • 有 graphify-out/wiki/index.md 时用其做广域导航。
  • 钩子或增量更新后 graphify-out/ 变脏属正常现象，不跳过 graphify。

9. 常见问题

问题处理
提示需要 API Key？ 纯代码目录不需要。文档/图片语义抽取可选配 GEMINI_API_KEY，否则由 AI 助手自身完成，绝不要配置 ANTHROPIC/OPENAI Key——graphify 不读取它们。
构建时报 “Graph is empty”？ 抽取未产出节点。检查目录是否全为不支持的类型（如纯二进制），或抽取步骤失败。
update 后节点变少、拒绝覆盖？ graphify 有防缩保护（#479）。确实删了代码请加 --force。
报告提示 Graph Health Warning？ 存在悬空/折叠边，图可能不完整但可用；用 graphify diagnose multigraph 排查。
目录太大跑不动？ 按子目录分次构建，或加 --no-cluster 跳过昂贵的聚类步骤。
如何彻底卸载？ uv tool uninstall graphifyy；连同图谱一并删除用 graphify uninstall --purge。
