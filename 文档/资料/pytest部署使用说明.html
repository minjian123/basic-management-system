1. 简介与选型理由

pytest 是 Python 事实标准的测试框架；pytest-asyncio 让它能直接运行 async def 测试函数；httpx 提供 ASGITransport——把 FastAPI 应用当 HTTP 服务直接调用，测接口不用真的起服务器。

BMS 规划选型理由：FastAPI 测试用 ASGITransport 免启服务器；测试库统一 SQLite 保证可移植；CI 每次 PR 跑后端测试。

本机版本（pyproject.toml dev 组声明）：pytest>=9.1.1、pytest-asyncio>=1.4.0、httpx>=0.28.1；Python 3.14.4（2026-08-05 核实）。

2. 安装

BMS 后端已声明开发依赖（dev 组），backend 目录执行 uv sync 即装好三个包。

新项目手动添加（PowerShell）：

uv add --dev pytest pytest-asyncio httpx

验证安装：

uv run pytest --version

3. 常用命令

3.1 全量运行

uv run pytest

按 testpaths 配置（BMS 为 tests）收集全部测试并运行。结束输出汇总：N passed / M failed / K skipped，有失败时列出失败项与 -ra 汇总摘要。

3.2 指定目录与筛选

uv run pytest tests/unit                  # 只跑单测
uv run pytest tests/integration            # 只跑集成测试
uv run pytest tests/unit -k "config"       # 按名称筛选
uv run pytest --maxfail=1                  # 首个失败即停（排错时省时间）

3.3 详细输出

uv run pytest -v    # 每个用例一行
uv run pytest -s    # 显示测试里的 print 输出（调试时用）

4. 与 BMS 的集成

当前实施状态：测试骨架属阶段一任务 9，尚未开始（backend/tests/ 目录尚不存在，2026-08-05 核实），以下为设计约定（依据《阶段一_项目骨架说明》第 11 节与《项目规划说明》测试策略节）。

配置写在 backend/pyproject.toml 的 [tool.pytest.ini_options] 段：

配置项值含义
asyncio_modeautopytest-asyncio 自动运行 async def 测试，不用逐个加装饰器
testpaths["tests"]默认收集目录
addopts-ra结束时汇总显示失败/跳过/错误的原因

目录与测试设计：

  • tests/unit/：单测——配置加载（BMS_ENV 切换、环境变量覆盖）、日志格式、上下文（request_id/tenant）、错误码；SQLite + Redis 本地
  • tests/integration/：集成测试——健康检查（/readyz 依赖故障返回 503）、双库拓扑路由（平台库/租户库读写）、租户解析（X-Tenant-ID）、模型基类（雪花 ID 唯一、审计字段、软删过滤、乐观锁冲突）；SQLite 模拟多库，CI 中另起 MySQL/PostgreSQL 容器验证真实双库
  • conftest.py：app fixture（依赖覆盖：测试库与测试 Redis）、client fixture（httpx.AsyncClient + ASGITransport，免起服务器）
  • 测试数据：独立种子，不与初始化数据混用

接口测试写法示例（设计约定，测试骨架落地后可用）：

import httpx
from httpx import ASGITransport
from app.main import app


async def test_health(client: httpx.AsyncClient):
    r = await client.get("/healthz")
    assert r.status_code == 200

5. 常见问题

现象处理
async 测试函数没执行/报 coroutine 相关错误确认已装 pytest-asyncio 且 asyncio_mode = "auto" 生效；asyncio_mode 缺省是 strict，需显式配置
ASGITransport 请求 404transport 挂的是 ASGI 应用而非真实地址，确认传的是 app 对象而非 URL；路径要含完整前缀（BMS 为 /api/v1）
SQLite 内存库（:memory:）数据对不上每个连接的内存库相互独立，多连接场景要用文件型测试库（BMS 用 backend/data/ 下文件 SQLite），避免 in-memory 陷阱
用例间数据污染BMS 约定测试数据独立种子、不混用初始化数据；跨用例共享状态应放 conftest fixture 并在用例间清理
-ra 没看到摘要摘要只在存在失败/跳过/错误时显示；全部通过时只有 N passed
本地全绿但 CI 挂CI（阶段一任务 10）还跑真实 MySQL/PostgreSQL 集成 job，方言相关失败本地 SQLite 复现不了，看 CI 日志对应 job
