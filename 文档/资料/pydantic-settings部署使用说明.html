1. 简介与选型理由

pydantic-settings 是 Pydantic 官方的配置管理库：配置模型还是普通 Pydantic 模型（自动类型校验），额外引入"数据源"机制——环境变量、文件、初始化参数按优先级合并，省掉手写 os.getenv 和手工解析的活。BMS 用它实现「config.toml 按环境分层 + 环境变量覆盖」（见《项目规划说明》：单配置文件易读，部署时用环境变量覆盖敏感项，遵循 12-factor）。

本机实测版本：pydantic-settings 2.14.2，底层 pydantic 2.13.4（2026-08-05）。

2. 安装

依赖已写进 backend/pyproject.toml（pydantic-settings>=2.14.2），在 backend 目录执行 uv sync 即可。验证：

cd backend
uv sync
uv run python -c "import pydantic_settings; print(pydantic_settings.__version__)"

3. 使用方法

3.1 基本用法

from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    app_name: str = "bms"      # 字段默认值；无默认值且没配来源则启动报错
    debug: bool = True         # 环境变量字符串自动转布尔

s = Settings()                 # 默认自动读环境变量（大小写不敏感、前缀可配）

BMS 没有走默认的 env 前缀机制，而是用自定义数据源接管（见下节），因为配置主体来自 config.toml 而不是默认的 .env 文件。

3.2 自定义数据源

通过类方法 settings_customise_sources 声明数据源列表，每个数据源是 PydanticBaseSettingsSource 的子类，实现 __call__ 返回一个 dict。优先级规则：tuple 里靠后的覆盖靠前的。BMS 的 app/core/config.py 就是这么写的（源码摘录）：

@classmethod
def settings_customise_sources(cls, settings_cls, init_settings, env_settings,
                               dotenv_settings, file_secret_settings):
    # 优先级（tuple 靠后者覆盖前者）：config.toml < 环境变量 < init 参数
    return _TomlSource(settings_cls), _EnvVarSource(settings_cls), init_settings

3.3 获取配置

应用内统一走 get_settings() 入口，禁止散落 os.getenv（config.py 文档字符串与《后端开发规范》约定），保证所有配置项都经过 Settings 模型声明与校验。

4. 与 BMS 的集成

4.1 三个数据源与加载顺序

BMS 配置加载顺序（后者覆盖前者，已实现于 app/core/config.py）：

  1. _TomlSource：读 config.toml——公共段（[app]、[log]、[database]、[redis]、[snowflake]）+ 环境段（[env.dev] / [env.test] / [env.prod]）按 BMS_ENV 合并；扁平键（如 [env.prod] 下的 debug）覆盖同名小节里的值，找不到目标节则并入 [app]
  2. _EnvVarSource：BMS_ 前缀环境变量，映射成嵌套字典
  3. init_settings：实例化时传入的参数（测试覆盖配置用）
config.toml 开头有同款加载顺序说明注释；测试里也依赖这个优先级做依赖覆盖（conftest 的 app fixture）。

4.2 BMS_ENV 特例

  • _TomlSource：先看环境变量 BMS_ENV，没有则回退 config.toml 里 [app].env（默认 dev），决定合并哪个环境段
  • _EnvVarSource：BMS_ENV 不按"节_键"拆分，而是特例映射到 app.env
  • 取值必须是 dev / test / prod 三选一（Settings 里 env 字段是 Literal 类型，写错启动即报错）

4.3 环境变量命名约定

约定 BMS_<节>_<键>，全大写（UPPER_SNAKE），节限 app / log / database / redis / snowflake 五个，其他前缀一律忽略不报错。环境变量值都是字符串，由 Pydantic 自动转成字段类型。示例：

环境变量映射
BMS_ENVapp.env（特例）
BMS_DATABASE_PLATFORM_URLdatabase.platform_url（生产必填）
BMS_DATABASE_POOL_SIZEdatabase.pool_size
BMS_REDIS_URLredis.url
BMS_LOG_LEVELlog.level

PowerShell 设置示例：$env:BMS_ENV = "prod"（仅当前会话生效；长期配置写入系统环境变量）。

4.4 密钥只走环境变量

密钥类配置（数据库密码、Redis 密码，后续的 JWT secret、MinIO 凭据）一律只走环境变量，config.toml 不存放任何真实密钥；.env.example 只给变量名与占位值。生产环境必须用 BMS_DATABASE_PLATFORM_URL、BMS_REDIS_URL 覆盖连接串（config.toml 里默认是本地 SQLite / localhost）。

5. 常见问题

现象处理
改了 config.toml 不生效配置在进程启动时加载；uvicorn --reload 模式改动后会自动重启生效
写了 .env 文件不生效BMS 没接入 dotenv 数据源（settings_customise_sources 只有 toml / env / init 三个），必须设真实环境变量：PowerShell $env:BMS_ENV = "prod"
环境变量设了但没覆盖检查前缀 BMS_、全大写、节名在 app/log/database/redis/snowflake 内；拼错不会报错，只是被忽略
启动报 env 字段校验错误BMS_ENV 必须 dev / test / prod 三选一，Literal 校验不过会直接抛错
布尔值怎么传Pydantic 自动转换，建议统一用 true / false 字符串
列表类型（如 dev_tenants）怎么传按 JSON 数组格式传值，如 $env:BMS_DATABASE_DEV_TENANTS = '["demo","t1"]'，由 Pydantic 解析
密钥误写入 config.toml立即删除并轮换该密钥；仓库内已提交则检查 git 历史并清理（config.toml 已入库）
