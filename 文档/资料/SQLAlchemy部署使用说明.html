1. 简介与选型理由

SQLAlchemy 是 Python 生态里用得最多的 ORM 库，2.0 开始把异步支持做成了一等公民：AsyncEngine、AsyncSession 和同步写法基本同构，学一套会两套。BMS 后端是 FastAPI 异步栈，选它主要看中几点：

  • 原生异步：aiosqlite、aiomysql、psycopg（async）这些驱动都能直接挂到 AsyncEngine 上，请求全程不阻塞事件循环
  • ORM + Core 两层：业务代码用 ORM 模型，批量写入、复杂统计可以退回 Core 表达式，不用换库
  • 方言体系：同一套模型能在 SQLite / MySQL / PostgreSQL 三库间切换，正是 BMS「开发用 SQLite、生产用 MySQL/PostgreSQL」策略的支撑
  • 官方配套 Alembic：schema 演进有同源迁移工具（见《Alembic部署使用说明》）

本机核实版本：SQLAlchemy 2.0.51，运行于 Python 3.14.4；aiosqlite 在 pyproject.toml 中的约束为 ≥0.22.1。

2. 安装

依赖已经写进 backend/pyproject.toml（sqlalchemy[asyncio]>=2.0.51 与 aiosqlite>=0.22.1），Windows PowerShell 里进 backend 目录执行一次同步即可：

cd backend
uv sync

验证安装：

uv run python -c "import sqlalchemy, aiosqlite; print(sqlalchemy.__version__)"

生产方言驱动说明：config.toml 注释里给了 MySQL（mysql+aiomysql）和 PostgreSQL（postgresql+psycopg）的连接串写法，但这两个驱动（aiomysql、psycopg）目前还没有加进 pyproject.toml，等生产接入时用 uv add 补上。

3. 常用用法

3.1 连接串与引擎

连接串格式按库不同，都是 dialect+driver:// 开头：

目标库连接串用途
SQLitesqlite+aiosqlite:///./data/platform.db开发/测试；aiosqlite 是异步驱动
MySQL 8.xmysql+aiomysql://bms:密码@主机:3306/bms_platform生产；aiomysql 异步驱动
PostgreSQL 16+postgresql+psycopg://bms:密码@主机:5432/bms_platform生产；psycopg3 原生支持 async

写独立脚本时建引擎与会话：

from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker

engine = create_async_engine("sqlite+aiosqlite:///./data/platform.db")
Session = async_sessionmaker(engine, expire_on_commit=False)

async def demo():
    async with Session() as session:
        # 用 session 做事
        pass

注意：create_async_engine 的 URL 必须带异步方言（写 sqlite+aiosqlite 而不是 sqlite://），否则实际走的是同步驱动，在事件循环里会阻塞。

3.2 会话与增删改查

async def crud(session):
    user = User(name="张三")              # 新增
    session.add(user)
    await session.commit()

    u = await session.get(User, user.id)  # 查询
    u.name = "李四"                        # 修改
    await session.commit()

    await session.delete(u)               # 删除
    await session.commit()

写操作要显式 commit()，事务边界自己控制；一个请求尽量只开一个会话，别在循环里反复开。

3.3 查询写法

from sqlalchemy import select, func

result = await session.execute(select(User).where(User.dept_id == 1))
users = result.scalars().all()

count = await session.scalar(select(func.count()).select_from(User))

有关联关系的查询用 selectinload() 或 joinedload() 提前加载，避免 N+1 查询；BMS 规范里禁 SELECT *，列一律显式写。

3.4 调试开关

想看到每一条执行的 SQL，建引擎时加 echo=True，或者把日志级别调到 DEBUG：

engine = create_async_engine(url, echo=True)      # 打印所有 SQL
import logging
logging.getLogger("sqlalchemy.engine").setLevel(logging.DEBUG)

config.toml 里的 echo 配置项就是干这个的，仅调试用，生产保持 false。

库拓扑（platform_url / tenant_url_template）：开发环境用多个 SQLite 文件模拟三库，生产切 MySQL/PostgreSQL 只改连接串，代码不动。

库开发（SQLite 模拟）生产
平台库backend/data/platform.dbbms_platform（MySQL 8.x / PostgreSQL 16+）
租户库backend/data/tenant_{code}.db，一租户一库bms_tenant_{code}，{code} 运行时替换为租户编码
归档库仅预留配置位阶段四启用
  • EngineRegistry 懒加载：按数据源 key 缓存 AsyncEngine，首次访问才创建，避免全量租户连接常驻；入口两个——get_platform_engine() 与 get_tenant_engine(tenant_code)；engine 空闲超阈值自动 dispose 释放连接
  • 连接池：pool_size=5、max_overflow=10（config.toml）；多 worker 部署按 总连接数 = worker × (pool_size + max_overflow) ≤ 数据库 max_connections 的 70% 核算
  • AsyncSession 工厂：每次请求创建独立会话、请求结束关闭，异步会话禁止跨请求共享；get_db() 依赖按当前租户上下文返回对应库的会话；事务为请求依赖粒度，显式 commit/rollback
  • 模型基类（db/base.py 四类混入）：
混入字段说明
SnowflakeIdMixinid雪花 ID 主键（yitter/IdGenerator），Python 侧生成，时钟回拨按配置处理
AuditMixincreated_at / created_by / updated_at / updated_byORM 事件自动填充；时间统一 UTC 存储
SoftDeleteMixindeleted_at软删除，查询默认过滤；业务唯一约束建为 (唯一字段, deleted_at) 复合唯一索引
OptimisticLockMixinversion乐观锁，更新时比对 version，防止多实例并发覆盖

软删除复合唯一索引的原理：未删行 deleted_at 为 NULL，SQLite / MySQL / PostgreSQL 三库都允许多个 NULL 不冲突；删除时写入时间戳即释放唯一键，恢复时清掉 deleted_at。PostgreSQL 可另加部分唯一索引优化。

  • 数据库兼容：ORM 层禁用方言特有功能——JSON 等类型用跨方言通用类型，分页统一 limit/offset，字符集 MySQL utf8mb4 / PostgreSQL UTF8，禁用 SELECT *，参数化查询防 SQL 注入；这样同一套代码三库都能跑

5. 常见问题

现象处理
URL 写 sqlite:// 挂在异步代码里，事件循环被卡住改用 sqlite+aiosqlite://；MySQL/PG 同理必须带异步驱动名
会话没关，连接池被占满，请求超时会话只在请求内创建、结束时关闭；不要跨请求共享，也别在循环里开会话不关
日志里出现 "greenlet" / 跨事件循环报错多半是同步 Session 混进了异步代码，统一走 AsyncSession
想看的 SQL 没打印echo=true 或 sqlalchemy.engine 日志调 DEBUG，用完关掉
时间字段对不上时区BMS 规范统一 UTC 存储，前端按本地时区展示，入库前先转 UTC
Windows 下 SQLite 文件找不到相对路径统一从 backend 目录解析（config.toml 里 ./data/platform.db），启动命令的工作目录放在 backend
