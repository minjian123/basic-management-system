1. 简介与选型理由

Vue 3 + Vite + TypeScript 是 BMS 前端的基础技术栈。选它的原因：

  • 组合式 API：中后台页面逻辑按功能聚合，比选项式 API 好维护，也方便把共用逻辑抽成可复用的组合函数
  • Vite 冷启动快：开发服务器按需编译，大型项目也不用等；原生 ESM 与 HMR 配合，改代码即时生效
  • TypeScript：前后端契约可以靠 openapi-typescript 从后端 OpenAPI schema 自动生成 TS 类型，接口改了类型马上对不上，编译期就能发现

BMS 是 monorepo，前端分两个工程：frontend（PC 管理端）和 frontend-mobile（移动端 H5，用 Vant）。两个工程同一套技术栈，共享基础配置，源码各自独立。

2. 安装与工程初始化

前置要求：Node.js ≥ 20.19（本机实测 v24.15.0，2026-08-05），包管理器 pnpm 11.20.0。版本由工程根 .nvmrc 固定，用 fnm / volta 等工具自动切换。

# 检查版本（两者都要达标）
node -v
pnpm -v

# 用官方脚手架创建新工程（Vue 3 + TS 模板）
pnpm create vue@latest
# 交互选择：TypeScript + Router + Pinia + Vitest 均选 Yes

创建后安装依赖并启动：

pnpm install
pnpm dev

生产构建与本地预览：

pnpm build
pnpm preview

3. 常用命令

3.1 本地开发

pnpm dev          # 启动开发服务器，默认 http://localhost:5173
pnpm dev --host   # 局域网可访问（调试手机端时用）

Vite 开发服务器默认代理配置见 vite.config.ts 的 server.proxy，BMS 中把 /api 代理到本地后端（开发环境跨域问题靠这个解决，生产则由 nginx 同源反代）。

3.2 构建与预览

pnpm build          # 产物输出到 dist/，可配 base 路径
pnpm preview        # 本地起静态服务验证 dist/ 产物
pnpm build --mode prod   # 指定模式加载对应 .env.production

环境变量：Vite 只暴露 import.meta.env 中 VITE_ 前缀的变量，如 VITE_API_BASE（后端接口地址）。

3.3 检查与测试

pnpm lint          # ESLint 检查
pnpm test          # Vitest 单测/组件测试（BMS 前端 job 中用 vitest run）
pnpm type-check    # vue-tsc 全量类型检查（CI 可加此步骤）

4. 与 BMS 的集成

前端工程阶段一尚未初始化，以下为设计约定，来自《阶段一·项目骨架说明》第 9 节与《项目规划说明》。

4.1 双工程结构

monorepo 下两个前端工程，通过 pnpm workspace 纳入 pnpm-workspace.yaml：

frontend/                # PC 管理端：Vite + Vue 3 + TS + Element Plus
frontend-mobile/         # 移动端 H5：Vite + Vue 3 + TS + Vant
pnpm-workspace.yaml      # 两工程共享 ESLint/Prettier/TS 基础配置包

两工程各自维护 package.json 与 .nvmrc（固定 Node ≥ 20.19），运行方式都是 pnpm --filter frontend dev 一类。

4.2 src 目录分层

frontend/
├── .nvmrc                    # 固定 Node ≥ 20.19
├── vite.config.ts            # 插件、代理、构建配置
├── package.json
└── src/
    ├── main.ts               # 入口：注册 pinia / router / i18n / Element Plus
    ├── App.vue
    ├── api/                  # 接口封装：axios 实例 + 各模块 API 函数 + 类型
    ├── router/               # 路由表与守卫（路由懒加载、权限守卫）
    ├── stores/               # Pinia 状态（用户、权限、全局 UI 状态）
    ├── views/                # 页面组件
    ├── layouts/              # 主布局（侧边栏、顶栏、标签页等）
    ├── components/           # 通用业务组件
    ├── i18n/                 # 语言包加载与初始化
    └── utils/                # 工具函数（请求封装、格式化等）

分层职责：api/ 只管请求与类型，stores/ 管状态，页面组件在 views/ 下按菜单结构组织。菜单树由后端动态下发，前端据此动态注册路由与生成侧边栏，不硬编码路由表（阶段十实现）。

4.3 类型契约

后端提供 OpenAPI schema，前端用 openapi-typescript 生成 TS 类型，保持前后端契约一致。阶段一后端 schema 尚未稳定，不引入；阶段二接入：

# 从本地后端导出 schema 并生成类型（阶段二起执行）
pnpm dlx openapi-typescript http://localhost:8000/openapi.json -o src/api/schema.d.ts

4.4 编码约定

  • 统一使用组合式 API（<script setup>），状态管理用 Pinia
  • 路由懒加载：component: () => import('@/views/user/index.vue')，配合静态资源 gzip/brotli 压缩，控制首屏体积
  • 文案不硬编码：页面文案走 vue-i18n，语言包运行时从后端 GET /api/v1/i18n/messages 拉取（Redis + localStorage 缓存）
  • Element Plus 按需引入，主题用 SCSS 变量定制（见《Element Plus 部署与使用说明》）
  • 移动端复用后端 API 与会话体系，企业微信/钉钉内免登（规划约定）

5. 常见问题

现象处理
pnpm dev 提示 Node 版本不满足要求先看 .nvmrc 要求的版本（≥ 20.19），用 fnm/volta 切换到对应版本再跑；不要强行用低版本运行
5173 端口被占用Vite 会自动换端口并在终端提示；或手动 pnpm dev --port 5174
接口请求报跨域开发环境在 vite.config.ts 配 server.proxy 把 /api 代理到后端；生产由 nginx 同源反代，不存在跨域
构建产物在子路径部署打不开在 vite.config.ts 设 base 为部署子路径，否则资源路径会 404
改了 .env 不生效环境变量在 dev server 启动时读取，改动后需重启 pnpm dev
依赖装得慢换 npm 镜像源：pnpm config set registry https://registry.npmmirror.com（pnpm 自身也走该镜像）
