1. 目的与定位

local-helper 是本项目的本地子代理：把本机 LM Studio 上的多模态模型（qwen3.8-27b）注册为 opencode 的子代理（subagent）， 让主会话把简单重复的劳动派给它干，主会话与云端子代理集中精力处理较难与核心工作。 它是《本地多模态接入方案》双轨架构的"子代理"一轨（另一轨是 MCP server 工具 multimodal_chat / screenshot）。

为什么要有它：识图评审、文本整理等重复劳动占用云端上下文与费用。本地模型零费用、可反复调用，适合承接这些琐碎任务；但它能力一般（27B 量化），复杂任务交给它会返回有问题的结果，因此必须有任务分级（见第 2 节）。

3. 环境要求

  • 本机 LM Studio 服务常开（OpenAI 兼容，http://127.0.0.1:1234），模型 qwen/qwen3.8-27b 已加载；模型列表、凭据见 文档/用户文档/本地资源.md（已 gitignore，不入库）。
  • 模型设为常驻内存（Keep model loaded），避免每次首次调用冷加载等待。
  • opencode 已重启（provider / agent 配置改动后须重启生效）。

4. 部署配置

4.1 provider（lmstudio）

在 .opencode/opencode.json 的 provider 段登记本地模型（@ai-sdk/openai-compatible 适配 OpenAI 兼容接口）：

"provider": {
  "lmstudio": {
    "npm": "@ai-sdk/openai-compatible",
    "name": "本地多模态（LM Studio）",
    "options": {
      "baseURL": "http://127.0.0.1:1234/v1",
      "apiKey": "local"
    },
    "models": {
      "qwen3.8-27b": {
        "id": "qwen/qwen3.8-27b",
        "name": "qwen3.8-27b 本地多模态",
        "tool_call": true,
        "reasoning": true,
        "attachment": true,
        "temperature": true
      }
    }
  }
}
  • 模型引用格式：lmstudio/qwen3.8-27b（子代理 frontmatter 的 model 字段即此）。
  • 本地 LM Studio 无鉴权时 apiKey 填占位值 local。

4.2 子代理定义

子代理定义在 .opencode/agent/local-helper.md（frontmatter + 正文职责说明）：

---
description: 本地多模态子代理（LM Studio qwen3.8-27b）。识图分析、界面截图评审、文本整理、交叉检查。
mode: subagent
model: lmstudio/qwen3.8-27b
permission:
  read: allow
  glob: allow
  grep: allow
  list: allow
  edit: deny
  bash: allow
  task: deny
  webfetch: deny
  websearch: deny
  question: deny
---
  • 正文（body）为职责说明：识图分析、界面走查、文本整理、交叉检查的干法；以及"能力边界"——遇到复杂任务明确拒活并建议转派（见第 6 节）。
  • 命名规范：子代理名 local-helper 全小写连字符，符合《命名规范》。

4.3 权限说明

权限值说明
read / glob / grep / listallow可读文件、搜索定位，干活所需
bashallow可跑命令：截图脚本、识图脚本（deploy/tools/multimodal/ 下 CLI）
editdeny只读：禁止修改任何文件，防止本地模型乱改
taskdeny禁派生子任务（防递归）
webfetch / websearchdeny禁联网，本地模型不外联
questiondeny不打断用户提问

5. 使用方法

5.1 派活方式

主会话用 task 工具选择 local-helper 子代理，在任务描述中写清三件事：输入（文件路径）、步骤（怎么做）、输出格式（要什么）。任务描述是唯一指令，越具体越好。

task(description="原型页面走查", subagent_type="local-helper",
  prompt="对 D:/Develop/bms/文档/设计/原型设计/03_通用骨架/03_主框架.html 做走查：
1. 用 deploy/tools/multimodal/screenshot.py 按 1440x900 截图到 temp/vision/ 下；
2. 对截图逐区域识图（可用 deploy/tools/multimodal/vision_analyze.py --prompt prototype-review）；
3. 输出：问题清单（位置/描述/严重程度）。只输出清单，不要修改文件。")

5.2 任务描述模板

场景任务描述要点
识图描述给出图片路径 + 想知道的点（元素/关系/文案），要求输出结构化（列表或 JSON）
截图走查给出 HTML 路径 + 分辨率 + 走查重点（遮挡/破版/对齐），要求输出问题清单
文本整理给出文件路径 + 整理目标（摘要/清单/翻译），要求输出结构化文本
交叉检查给出要核对的材料（A 与 B），要求列出不一致点，附行号/位置证据

6. 能力边界

local-helper 只接受简单重复、容错要求低的任务。遇到以下情况，它会明确回复"此任务超出我的能力，建议交给云端子代理或主代理处理"，不做硬编：

  • 方案设计、代码编写/重构、多步推理
  • 需要领域判断、一致性要求高的产出（评审结论定稿、问题定级、报告终稿）
  • 任务描述含糊、目标不确定、需要反复权衡取舍的工作

子代理输出仅供参考，主会话须复核关键结论（评审问题、定级、结论性文字）。

7. 常见问题

现象原因与处理
派活后子代理长时间无响应LM Studio 未启动或模型冷加载；确认服务在线（http://127.0.0.1:1234/v1/models），模型设常驻内存
输出带大量"思考过程"、迟迟不结束推理模型思考未关闭；opencode 对本地模型请求默认 reasoning_effort 处理见《本地多模态接入方案》第 3.3 节
找不到子代理 / 派活时报错配置改动后未重启 opencode；检查 .opencode/agent/local-helper.md 的 frontmatter（mode: subagent）
子代理结果明显错误任务难度超出其能力；按第 2 节改派云端子代理或主会话自己做
