1. 目的与适用范围

为 BMS 项目（《项目规划说明》）建设一项通用识图辅助能力： 通过调用外部识图模型 API，让 AI 助手能够「看图」，覆盖原型视觉评审、截图分析、文档图片理解等场景。 能力以 opencode 插件 + Python 客户端 + Edge 无头截图三部分组成，与具体场景解耦， 新场景只需新增提示词模板即可复用。

背景：当前会话模型（deepseek-v4-flash）不支持图片输入，原型设计工作流缺少视觉校验环节。本方案补齐「截图 → 识图 → 问题清单 → 修正」闭环。

3. 识图 API 接入

3.1 接口契约

采用 OpenAI 兼容格式（chat/completions + 图片 data URI），国内主流视觉模型（通义千问 VL、GLM-4V、智谱、豆包等）均支持此格式，无需额外适配层。

POST {endpoint}/v1/chat/completions
Authorization: Bearer {API_KEY}
Content-Type: application/json

{
  "model": "{model}",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "{提示词}" },
        { "type": "image_url",
          "image_url": { "url": "data:image/png;base64,{base64}" } }
      ]
    }
  ],
  "temperature": 0.2
}

3.2 配置项

配置来源说明
endpoint环境变量 VISION_API_ENDPOINTAPI 基地址（不含 /v1 后缀），如 https://dashscope.aliyuncs.com/compatible-mode
api_key环境变量 VISION_API_KEY密钥不落配置文件、不入库（见第 8 节）
model环境变量 VISION_API_MODEL识图模型名，如 qwen-vl-max
timeout环境变量 VISION_API_TIMEOUT请求超时秒数，默认 60

3.3 固化配置（opencode.json）

本地模型（如 LM Studio，endpoint 为 http://127.0.0.1:1234）可把配置固化到 opencode.json 插件 options，随项目走、一处维护，避免每次会话设置环境变量：

{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    ".opencode/plugins/graphify.js",
    [
      "./deploy/tools/vision/vision.js",
      {
        "endpoint": "http://127.0.0.1:1234",
        "apiKey": "local",
        "model": "qwen/qwen3.6-35b-a3b",
        "timeout": 300000
      }
    ]
  ]
}
  • 优先级：环境变量 VISION_API_* ＞ 插件 options；两者都未配置时工具返回 {ok:false,error} 提示，不影响 opencode 启动。
  • timeout：本地模型推理较慢（尤其冷加载），建议 300000ms（5 分钟）；云端 API 可缩短。
  • 本地 LM Studio 无鉴权时 apiKey 填占位值（如 local）；真实密钥仅走环境变量（见第 8 节）。
  • 修改 opencode.json 后需重启 opencode 生效。

4. Python 识图客户端

脚本 deploy/tools/vision/vision_analyze.py（deploy/tools/vision/），仅依赖标准库（urllib）与可选 requests，避免引入第三方依赖。

4.1 用法

# 单图分析（指定提示词模板）
python vision_analyze.py --image page.png --prompt prompts/prototype-review.md

# 批量分析（目录下全部图片，逐个调用）
python vision_analyze.py --dir screenshots/ --prompt prompts/prototype-review.md --out report.json

# 直接传提示词文本
python vision_analyze.py --image page.png --text "检查页面是否存在遮挡"

# 输出 JSON 文件
python vision_analyze.py --image page.png --prompt x.md --out result.json

4.2 输出

标准输出为 JSON（供插件/模型消费），格式固定：

{
  "image": "page.png",
  "ok": true,
  "summary": "总体结论一句话",
  "issues": [
    { "severity": "high|medium|low",
      "area": "区域/元素描述",
      "problem": "问题描述",
      "rule": "违反的规范条目（可选）",
      "suggestion": "修改建议" }
  ]
}

模型温度固定 0.2（评审要求确定性输出）；失败时 ok=false 并给出 error 字段。

5. 截图服务（Edge 无头）

本机 Windows 环境使用系统自带 Edge 无头模式渲染 HTML/URL 为 PNG，无需安装额外浏览器：

& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --headless --disable-gpu --screenshot="out.png" `
  --window-size=1440,900 --virtual-time-budget=3000 `
  "file:///D:/Develop/bms/文档/设计/原型设计/02_通用骨架/03_主框架.html"
  • --window-size：分辨率参数，评审默认三档 1440×900 / 1366×768 / 1024×768（覆盖《布局设计-响应式适配》断点）。
  • --virtual-time-budget：等待渲染完成（动画/角标模拟），默认 3000ms。
  • 截图输出目录：项目下临时目录 temp/vision/（已 gitignore，不入库不提交），同一 HTML 的同名截图会覆盖旧文件。若需留档，再由评审流程把报告产物复制到项目内（见第 7.1 节）。
  • Edge 可执行路径探测顺序：C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe → C:\Program Files\...\msedge.exe → Chrome 兜底。

插件文件 deploy/tools/vision/vision.js（在 opencode.json 的 plugin 数组登记，tuple 形式携带固化配置，见第 3.3 节：["./deploy/tools/vision/vision.js", {"endpoint": "...", "apiKey": "...", "model": "..."}]）。

7. 场景适配

能力本身与场景解耦：vision_analyze 可分析任意本地图片（界面截图、文档图、流程图、图表、对比图），提示词用 --text 直传或 prompts/ 下的模板文件；新场景 = 新增一个模板文件，无需改代码。

7.1 原型视觉评审（首批场景）

  • 提示词模板 prompts/prototype-review.md 注入评审规则：设计令牌色值/间距/栅格、列表页三段式（工具栏/筛选/表格/分页）、表单页分态工具栏、弹窗规格、设计说明文字不得出现在界面等检查项。
  • 触发方式：AI 助手在原型改动后调用 vision_review_proto，或用户要求「评审原型 XX」。当前模型无识图能力时，由插件完成识图并把结果注入对话。
  • 报告落位：文档/资料/评审报告/（HTML，含截图缩略图 + 问题清单），遵循《文档生成规范》。
  • 修正闭环：AI 按问题清单修正 → 重新截图复评，直到无高危问题。

8. 安全与隐私

  • API 密钥只从环境变量读取（VISION_API_KEY），不写入任何配置文件、文档或代码；已被 gitignore 的 文档/用户文档/本地资源.md 也不登记密钥。
  • 图片仅本地临时处理，识别请求为一次性提交；评审报告落库时不含敏感截图（仅缩略图 + 文字清单，可配置）。
  • 截图与分析日志留存项目下临时目录（temp/vision/，已 gitignore），定期清理；批量评审注意 API 调用量与费用。
  • 识图模型只见图片与提示词，不接触代码库其他内容；提示词模板内不写敏感信息。
