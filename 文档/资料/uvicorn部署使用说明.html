1. 简介与选型理由

uvicorn 是跑 ASGI 应用的服务器（类似 WSGI 时代的 gunicorn），FastAPI 这类 ASGI 框架都靠它对外提供 HTTP 服务。BMS 规划选它作为 ASGI 服务器，并明确「多 worker 部署」承载并发（见《项目规划说明》技术栈表）。uvicorn[standard] 是带扩展的安装方式，额外附带 uvloop / httptools / watchfiles：Linux 上 uvloop 明显提速，watchfiles 供开发热重载用。

本机实测版本：uvicorn 0.52.1（2026-08-05）。

2. 安装

依赖已写进 backend/pyproject.toml（uvicorn[standard]>=0.52.1），在 backend 目录执行 uv sync 即可。验证：

cd backend
uv sync
uv run uvicorn --version

3. 常用命令

3.1 开发模式

uv run uvicorn app.main:app --reload --port 8000
  • app.main:app：导入路径——模块 app/main.py 里的应用对象 app
  • --reload：改代码自动重启，只用于开发
  • --port 8000：BMS 本地开发默认端口
app/main.py（应用工厂）由阶段一任务 7 产出，当前仓库尚未实现——本命令待任务 7 实现后生效。开发期间可先确认安装：uv run uvicorn --version。

3.2 生产部署

uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
  • --host 0.0.0.0：容器/服务器里必须绑全部网卡，否则外部访问不到；本地开发可省略
  • --workers 4：多进程承载并发（规划示例规模即 4 worker）
  • --reload 与 --workers 不能同用：reload 模式固定单进程
  • 生产环境不挂 --reload
平台差异：多 worker 面向 Linux（Docker 容器、服务器）生产环境；Windows 本地开发多进程受 spawn 机制限制，请用单进程 --reload 模式。

4. 与 BMS 的集成

4.1 启动命令

BMS 后端统一启动命令（backend 目录下）：

uv run uvicorn app.main:app --reload --port 8000

日常命令一律带 uv run 前缀，无需手动激活虚拟环境。命令生效前提是 app/main.py 存在（阶段一任务 7「租户解析与应用组装」的产出物，当前未实现，待其实现后生效）。

4.2 worker 与连接池核算

每个 worker 是独立进程、各自维护独立连接池。多 worker 部署时按规划公式核算总量（见《项目规划说明》"部署规模与连接规划"节）：

总连接数 = worker 数 × (pool_size + max_overflow) ≤ 数据库 max_connections × 70%
  • 当前 config.toml：pool_size = 5、max_overflow = 10
  • 4 worker 时每个数据源：4 × (5 + 10) = 60 条连接，上限留 70% 给数据库并预留其他客户端
  • 例如数据库 max_connections = 150：70% ≈ 105，60 在限内；worker 数或 pool 调大前先按公式核算
  • 多租户场景按活跃租户数规划连接（engine 懒加载 + 闲置回收），避免全量租户连接常驻
  • 写事务尽量短，避免长事务占用连接

4.3 健康检查与编排

BMS 提供两个探针端点（阶段一任务 5，当前未实现）：GET /healthz 存活探针（进程活着即 200）；GET /readyz 就绪探针（平台库 SELECT 1 + Redis PING，全部通过 200，任一失败 503）。多 worker / 容器多副本部署时，编排系统按这两个端点做重启判断与滚动发布流量摘除。

4.4 日志接入

  • uvicorn 属第三方库，日志经标准 logging 汇入 structlog 统一管线，与其他库同格式（阶段一第 5 节设计）
  • 请求访问日志（method / path / status / cost_ms / request_id）由 BMS 中间件记录，不以 uvicorn 默认访问日志为准
  • uvicorn 自身日志级别可用 --log-level info 调整（默认 info）

5. 常见问题

现象处理
Windows 端口被占用，报 [Errno 10048]换端口 --port 8001；或 netstat -ano | findstr 8000 找 PID 结束进程
--workers 4 在 Windows 上不生效/报错生产多进程面向 Linux；Windows 本地用单进程 --reload
改代码不自动重启确认命令带 --reload 且装有 watchfiles（uvicorn[standard] 自带）；Windows 偶发监听失灵就手动重启
DB 连接数超限（Too many connections）按公式核算：worker × (pool_size + max_overflow) 是否超数据库 70%；调小 worker 数或 pool 参数
改了 config.toml 不生效配置在进程启动时加载；--reload 模式下改动会自动重启进程
容器里访问不到服务确认 --host 0.0.0.0，只绑 localhost 外部不可达
