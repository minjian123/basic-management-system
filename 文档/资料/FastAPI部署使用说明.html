1. 简介与选型理由

FastAPI 是 Python 的 Web 框架，三个核心点：原生异步、靠类型注解自动生成 OpenAPI 文档、参数校验交给 Pydantic。BMS 规划选它的理由（见《项目规划说明》）：原生异步与异步 SQLAlchemy 天然契合；接口文档（Swagger UI / ReDoc）随代码自动生成，调试接口零成本。

本机实测版本：FastAPI 0.141.1，配套校验引擎 pydantic 2.13.4（2026-08-05）。

2. 安装

FastAPI 依赖已写进 backend/pyproject.toml（fastapi>=0.141.1），不用单独装，在 backend 目录执行一次 uv sync 就全部装齐。单独升级或调整版本用：

cd backend
uv sync                # 按 pyproject.toml + uv.lock 安装全部依赖
uv add fastapi         # 升级/固定 FastAPI 版本（会同步更新锁文件）
uv run python -c "import fastapi; print(fastapi.__version__)"   # 验证版本
表单与文件上传功能需要 python-multipart（规划已列入选型），目前尚未加入 pyproject.toml，阶段用到上传功能时再 uv add python-multipart。本机命令均为 PowerShell 语法。

3. 使用方法

3.1 路由与依赖注入

FastAPI 本身没有独立的命令行，应用靠 uvicorn 等 ASGI 服务器跑起来。入口文件 backend/app/main.py（应用工厂）由阶段一任务 7 产出，当前仓库尚未实现，下面的路由示例仅作通用写法参考：

# 路由模块：APIRouter 组织，FastAPI 自动校验与生成文档
from fastapi import APIRouter, Depends

router = APIRouter(prefix="/api/v1", tags=["示例"])

@router.get("/items/{item_id}")
async def get_item(item_id: int, db=Depends(get_db)):
    # item_id 非 int 时直接返回 422，不用手写校验
    return {"code": 0, "message": "ok", "data": {"id": item_id}}
  • 依赖注入 Depends(...)：BMS 的 get_db() 依赖按当前租户上下文返回对应库的会话（阶段一 7.3 节设计，当前未实现）
  • 路由函数推荐写 async def；含同步阻塞操作（慢 SQL、第三方调用）的函数用普通 def 声明，FastAPI 会丢线程池执行，不卡事件循环

4. 与 BMS 的集成

4.1 api 分层与路由前缀

后端接口统一挂在 /api/v1 前缀下（规划约定"全部接口 /api/v1"），路由注册在 app/api/router.py，各模块路由放 app/api/v1/（阶段一为 health.py 与 system.py）。分层职责（规划 + 阶段一约定）：

层职责位置
api只做参数校验与路由分发，禁止直接操作模型app/api/
services业务逻辑app/services/（阶段一为空骨架）
repositories数据访问与数据源路由app/repositories/（阶段一为空骨架）

启动方式（详见《uvicorn 部署使用说明》）：uv run uvicorn app.main:app --reload --port 8000——app/main.py 阶段一尚未实现，该命令待任务 7（应用组装）实现后生效。

4.2 统一响应与错误码

BMS 全部接口统一响应结构 {code, message, data}（app/core/errors.py 统一包装，阶段一任务 4 产出）：

  • code = 0 成功；非 0 为业务错误码
  • HTTP 状态码与业务错误码分离：HTTP 只表达传输层面的结果，业务成败看 body 里的 code
  • 错误码为 5 位数字，万位为模块段、后 4 位为段内序号，一经发布稳定不变；文案由前端按 i18n 映射，后端不承担文案拼装
  • 错误码分段示例：8xxxx（80001-89999）为开放接口/Webhook/租户/SSO 段
  • 异常响应携带 request_id，便于日志链路排查

4.3 权限校验（阶段二）

阶段二实现，当前未实现。规划约定：

  • 后端接口用依赖注入 require_permission(...) 强制校验，前端按权限码控制菜单/按钮/字段显隐只是第一层，后端兜底强制
