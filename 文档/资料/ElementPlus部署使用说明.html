1. 简介与选型理由

Element Plus 是 Vue 3 生态里中文社区用得最多的后台组件库。BMS 选它的原因：

  • 后台管理常用组件齐全：表格、表单、树、弹窗、分页、日期选择等开箱即用，不用自己造轮子
  • 主题可定制：样式基于 SCSS 变量，改几个变量就能换整套颜色，配合 BMS 的品牌色很容易
  • 与 Vue 3 同源维护，升级节奏跟得上；文档和社区资料都是中文，遇到问题好查
  • 默认转义输出，能挡住常见的 XSS 注入（规划"基础防护"节明确列了这一点）

BMS 里只有 PC 管理端（frontend）用 Element Plus；移动端 H5 用的是 Vant，两边组件库不混用。

2. 安装与按需引入

# 安装组件库本体
pnpm add element-plus

# 安装按需引入插件（开发依赖）
pnpm add -D unplugin-vue-components unplugin-auto-import

在 vite.config.ts 里配置插件：

import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    AutoImport({ resolvers: [ElementPlusResolver()] }),
    Components({ resolvers: [ElementPlusResolver()] }),
  ],
})

配好之后，模板里直接用组件名（如 <el-button>）即可，组件与对应样式会自动按需引入，不用手动 import。图标建议显式引入，方便打包工具做 tree-shaking：

pnpm add @element-plus/icons-vue
按需引入后，Element Plus 的样式只打包用到的那部分，首屏体积明显小。这是规划「前端性能」节的要求，不要改成全量引入。

3. 使用方法

3.1 组件与图标

<template>
  <el-button type="primary" @click="submit">保存</el-button>
  <el-table :data="rows">
    <el-table-column prop="name" label="名称" />
    <el-table-column prop="status" label="状态" />
  </el-table>
</template>

表单场景建议用 el-form 的校验规则：

const formRef = ref<FormInstance>()
const rules: FormRules = {
  name: [{ required: true, message: '请输入名称', trigger: 'blur' }],
}
await formRef.value.validate()

3.2 主题定制

BMS 用 SCSS 变量覆盖的方式定制主题（规划「样式：SCSS（Element Plus 主题定制）」）。做法是建一个 src/styles/element/index.scss：

// 覆盖 Element Plus 的 SCSS 变量，再引入完整主题样式
@forward 'element-plus/theme-chalk/src/common/var.scss' with (
  $colors: (
    'primary': ('base': #0969da),   // 主色改成 BMS 品牌色
  ),
  $border-radius: (
    'base': 6px,
  ),
);

然后在 vite.config.ts 里用 scss 的 additionalData 引入这个文件：

css: {
  preprocessorOptions: {
    scss: {
      additionalData: `@use "@/styles/element/index.scss" as *;`,
    },
  },
}

注意：一旦用 SCSS 变量覆盖主题，该文件就必须用 @forward ... with 方式引入完整主题样式，跟按需引入配合时按 Element Plus 官方「按需引入 + 主题定制」章节的写法来，两个插件配置里加上对应处理，否则变量覆盖不生效。

3.3 国际化配合

Element Plus 自带内置语言包，与 vue-i18n 切换：

import zhCn from 'element-plus/es/locale/lang/zh-cn'
import en from 'element-plus/es/locale/lang/en'

// 组件内置文案（分页、日期选择器里的"确定/取消"等）随语言切换
app.use(ElementPlus, { locale: zhCn })

业务文案不走这里，统一由 vue-i18n 管理，运行时从后端语言包下发（见下节）。

4. 与 BMS 的集成

前端工程阶段一尚未初始化，以下为设计约定，来自《项目规划说明》前端选型与前端页面清单节。
事项约定
引入方式按需引入（unplugin-vue-components + unplugin-auto-import），只用到的组件进打包产物
主题定制SCSS 变量覆盖主色与圆角等；品牌色统一在主题文件里维护，页面里不散写颜色值
vue-i18n 配合组件内置文案用 Element Plus 语言包随 locale 切换；业务文案走 vue-i18n，从后端 GET /api/v1/i18n/messages 拉取（Redis + localStorage 缓存），前端不硬编码文案
表单与权限表单元数据（按钮/字段定义）随菜单接口下发，按钮显隐走动作权限；默认无按钮权限，需后端授权后显示
安全Element Plus 默认转义输出，作为 XSS 基础防护之一；渲染后端返回的富文本（如公告内容）时按后端脱敏规则处理，不直接 v-html 未经清洗的内容
业务组件高频场景（分片上传、审批流相关）在 components/ 下封装为通用组件，页面复用，不各写各的

5. 常见问题

现象处理
组件有功能但样式全裸按需引入没生效：检查 vite.config.ts 两个 unplugin 插件是否配置、resolver 是否用 ElementPlusResolver
改了 SCSS 变量不生效主题覆盖必须用 @forward ... with 并保证该文件被引入；另外重启 dev server（scss 预处理器配置改动需要重启）
图标显示不出来确认已装 @element-plus/icons-vue；按需场景下图标推荐显式 import 使用
中文组件文案变成英文Element Plus 默认 locale 是英文，需要在入口显式传入 zh-cn 语言包
表单校验不触发el-form-item 的 prop 必须与 el-form 的 model 字段名一致；rules 放在 el-form 的 :rules 或 rules 对象里
生产环境体积大确认是按需引入而非全量 app.use(ElementPlus)；构建时开启 gzip/brotli 压缩（规划要求）
