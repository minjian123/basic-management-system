## 1. 技术概述 <a id="overview"></a>

**Pillow**（PIL Fork）是 Python 生态里事实标准的图像处理库，
是对早已停止维护的 **PIL（Python Imaging Library）**的延续与重写，
至今由社区活跃维护，覆盖图像读写、裁剪、缩放、绘图、滤镜、格式转换等绝大多数常见需求。
在 BMS 中它只承担一个很具体的职责——**生成图形验证码图片**。

- **定位**：BMS 登录链路中图形验证码图片的服务端生成器。
- **版本**：12.x 系列（持续迭代，按季度发布，建议锁定依赖版本）。
- **许可**：HPND（PIL 许可），OSI 认证开源。
- **语言**：Python（本项目 3.14+），核心含 C 扩展以获得性能。

## 2. 核心概念与原理 <a id="principles"></a>

| 概念 | 说明 |
| --- | --- |
| Image 对象 | 内存中的一张位图，是所有操作的起点：可绘图、裁剪、缩放、加滤镜、存为文件 |
| ImageDraw | 在 Image 上画东西的工具：文字、直线、矩形、弧线、椭圆——验证码字符与干扰线都靠它 |
| ImageFont | 加载字体文件（TTF/OTF）并指定字号，决定验证码文字的外观与可读性 |
| 像素与模式（Mode） | 图像由像素组成；`RGB` 为彩色、`L` 为灰度、`RGBA` 带透明通道，验证码一般用 RGB |
| 干扰元素 | 在字符上叠加随机折线、噪点，增加 OCR 识别难度，是验证码安全性的关键 |
| 随机字符集 | 验证码内容从字母/数字集合中随机抽取，应使用密码学安全随机源（`secrets`）而非普通 `random` |
| 序列化为字节 | Image 本身是内存对象，需 `save` 到 `BytesIO` 得到 PNG 字节流，才能经 HTTP 返回或入 Redis |
| 格式（Format） | 支持 PNG/JPEG/GIF/BMP 等；验证码用 PNG（无损、体积小、支持透明） |
| 线程安全 | Image 对象实例方法非线程安全，但「每次请求新建 Image 再绘制」的用法天然隔离，可安全用于并发接口 |

## 3. 在 BMS 项目中的用途 <a id="usage"></a>

- 登录接口生成 4~6 位随机字符的图形验证码图片，以 PNG 字节流返回前端。
- 验证码明文（或摘要）写入 Redis，key 为 `bms:global:captcha:{uuid}`，短 TTL 5 分钟，到期自动失效。
- 登录连续失败 3 次后强制要求输入验证码，与 [slowapi](slowapi技术介绍.md) 限流叠加，共同防爆破（见《[项目规划说明](../../../规划/项目规划说明.html#security)》12 节「认证与安全」）。
- 验证码校验为一次性：比对成功后立即删除 Redis key，防止重放。
- 生成逻辑为 CPU 密集 + 同步阻塞，接口内应放入线程池执行，避免卡住事件循环（见《[FastAPI 技术介绍](FastAPI技术介绍.md)》注意事项）。
- 与《[项目规划说明](../../../规划/项目规划说明.html#perf)》14 节「限流与降级」、《[安全开发规范](../../../规范/安全开发规范.html)》的登录防护要求对齐。

## 4. 选型对比 <a id="compare"></a>

| 候选技术 | 优缺点 | 结论 |
| --- | --- | --- |
| **Pillow（选中）** | 纯 Python 生态、API 简单、功能覆盖验证码全部需求、社区最活跃 | 生成图形验证码的默认选择，无外部依赖 |
| PIL（原版） | 历史经典，但早已停止维护，存在已知安全漏洞 | 不采用，Pillow 即其官方延续 |
| Wand（ImageMagick 绑定） | 功能极强，但需额外安装 ImageMagick 原生库，部署变重 | 杀鸡用牛刀，验证码场景不需要 |
| OpenCV | 面向计算机视觉/图像处理重型任务，库体积大、学习成本高 | 与「画几个字符」的需求不匹配 |

## 5. 常见问题与注意事项 <a id="pitfalls"></a>

- **阻塞事件循环**：图像生成是同步 CPU 操作，在 `async def` 接口里直接调用会卡住整个进程，需放入线程池（`run_in_executor`）或交给 Celery。
- **字体依赖**：`ImageFont.truetype` 需要真实字体文件，部署镜像里要带上字体并写对路径，跨平台（Linux/Windows）字体名不同，缺失时会回退默认位图字体导致样式异常。
- **随机源安全**：验证码字符务必用 `secrets` 模块生成，普通 `random` 可被预测，等于没设防。
- **防 OCR**：纯字符无干扰的验证码可被 OCR 批量识别，应叠加干扰线/噪点，并控制字符集（避免 0/O、1/l 等易混字符）。
- **内存与尺寸**：验证码图片保持小尺寸（如 120×40），不要生成大图；高并发下大量临时 Image 对象注意及时释放。
- **版本锁定**：Pillow 12.x 与旧版本存在 API/行为差异，依赖锁定（uv.lock）后升级需回归验证码渲染与格式测试。
