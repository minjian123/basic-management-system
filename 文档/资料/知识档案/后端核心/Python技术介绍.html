1. 技术概述

Python 是一种解释型、通用型的高级编程语言，以语法简洁、生态庞大著称， 是数据分析、AI 与后端开发的主流语言之一。BMS 后端技术栈（FastAPI、SQLAlchemy、Celery 等） 全部构建在 Python 之上，它是整个项目的语言地基。

  • 定位：BMS 后端唯一开发语言，全栈生态的粘合剂。
  • 版本：Python 3.14+（2025 年 10 月发布），项目锁定 3.14，`.python-version` 统一管理。
  • 许可：PSF-2.0（Python 软件基金会许可），宽松、无传染性。
  • 运行方式：CPython 官方解释器，配合 uv 管理依赖与虚拟环境。

2. 核心概念与原理

概念说明
解释器（CPython）官方 Python 解释器：读取源代码逐条编译为字节码再执行，无需显式编译步骤
GIL全局解释器锁：同一时刻只允许一个线程执行字节码，多线程跑 CPU 密集任务受其限制，I/O 密集场景影响小
虚拟环境（venv）隔离项目依赖的运行环境，避免不同项目包版本互相污染；本项目用 uv 的 venv 能力管理
包管理（uv/pip）安装第三方库并解析依赖树；uv 比 pip 快一个数量级，且支持锁文件（uv.lock）锁定全量版本（见《uv 技术介绍》）
类型注解def foo(x: int) -> str: 形式标注参数与返回类型，配合 pyright 实现静态检查（见《pyright 技术介绍》）
异步（async/await）协程式并发模型：单线程内交替执行多个 I/O 任务，是 FastAPI + 异步 ORM 高并发的基础
PEPPython 增强提案：语言新特性的官方设计文档（如 PEP 744 JIT、PEP 703 free-threaded）
JIT 编译器3.14 起默认启用的实验性即时编译（PEP 744），部分热点代码执行更快
free-threaded 构建无 GIL 的实验性构建选项（PEP 703），多线程并行度更高，但三方库兼容性待观察，本项目不启用
标准库随解释器内置的模块（json、sqlite3、hashlib 等），PBKDF2 密码哈希即用标准库实现
pip / requirements.txt传统依赖管理方式，本项目由 uv + pyproject.toml 替代

3. 在 BMS 项目中的用途

  • 作为项目语言基础：后端全部代码（backend/）以 Python 3.14+ 编写，前端与运维脚本（如 deploy/tools/）亦大量使用。
  • 配合 uv 管理依赖与虚拟环境：uv sync 一键还原环境，uv.lock 锁定全量依赖版本，见《uv 技术介绍》。
  • 语法新特性提升开发效率：类型注解、模式匹配、异常组等让代码更简洁、可读，配合 pyright 在 IDE 中即时发现类型错误（见《pyright 技术介绍》）。
  • 兼容性口径（重要）：Python 3.14 相对较新，阶段一骨架阶段需逐依赖验证（FastAPI/SQLAlchemy/Pydantic/psycopg/Celery/SpiffWorkflow 等，含达梦 dmPython），任一核心依赖不兼容则整体回退 Python 3.13（`.python-version` 同步调整）——口径见《项目规划说明》3.1 节。
  • 标准库承担密码哈希（PBKDF2）、uuid 等基础能力，减少第三方依赖（见《项目规划说明》2.1 节）。

4. 选型对比

候选技术优缺点结论
Python 3.14+（选中）生态覆盖 FastAPI/SQLAlchemy/SpiffWorkflow 等全部选型；开发效率高、团队上手快；3.14 较新存在少量依赖兼容风险（已有回退口径）与既定技术栈天然契合，无需额外成本
Java（Spring Boot）性能与并发强、企业生态成熟；但开发节奏重、样板代码多，与轻量异步栈目标不符重，不适合当前团队与项目体量
Go编译型、部署为单二进制、并发强；但 BPMN 工作流、AI 生态远不如 Python生态缺口大，排除
Node.js（TypeScript）前后端同语言；但后端业务生态（ORM/工作流/信创驱动）不如 Python仅适合前端侧，后端仍用 Python

5. 常见问题与注意事项

  • GIL 与并发：CPU 密集逻辑用多线程无法提速，应走多进程（uvicorn 多 worker）或线程池；BMS 的 I/O 密集场景（数据库、HTTP）受影响小。
  • 依赖兼容性：3.14 是较新版本，第三方库偶有滞后；发现核心依赖不兼容时按规划口径回退 3.13，不要自行"局部妥协"。
  • 环境隔离：不在系统 Python 里直接装依赖，一律走 uv 管理的虚拟环境，避免污染全局。
  • 版本管理：.python-version 是团队统一版本的口径文件，修改需经确认并同步 CI；勿随手改本机默认版本。
  • 类型检查：写接口签名务必带类型注解，否则 pyright 严格模式与 FastAPI 自动校验都会失效。
  • 锁文件：依赖升级后必须更新 uv.lock 并提交，保证 CI 与本地环境一致（见《uv 技术介绍》）。
  • 编码规范：代码风格遵循《后端开发规范》，以 ruff 为唯一格式化与 lint 工具。
