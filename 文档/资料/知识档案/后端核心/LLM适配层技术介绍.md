## 1. 技术概述 <a id="overview"></a>

**LLM 适配层**是 BMS 自建的**大模型统一接入层**（不是某个第三方产品）：
把「调哪家大模型」这件事收敛到一个接口后面——业务代码只调适配层，不直接碰具体厂商的 SDK。
默认接外部大模型 API（DeepSeek/Qwen 等），敏感场景可配置私有化端点（Ollama/vLLM 自托管），
切换模型只改配置，不改业务代码。它是阶段十五全部 AI 能力的底座。

- **定位**：BMS 唯一的 LLM 出入口，承载八项 AI 能力（智能报表助手、智能审批辅助、AI 内容生成、语义搜索与文件问答、OCR 与自动分类、审计异常检测、知识库问答机器人、帮助文档智能维护）。
- **版本**：项目内部组件，无独立版本号；底层模型版本由厂商各自管理，配置中显式指定模型名。
- **许可**：适配层代码随仓库；外部模型 API 按量计费（商业 API 条款，见《[项目规划说明](../../../规划/项目规划说明.html#stack-license)》2.5 节）；私有化模型（DeepSeek/Qwen/Ollama/vLLM）各自开源。
- **接口基础**：DeepSeek、Qwen、Ollama、vLLM 均提供 OpenAI 兼容的 `/chat/completions` 接口，这是「一套代码调多家模型」的关键。

## 2. 核心概念与原理 <a id="principles"></a>

| 概念 | 说明 |
| --- | --- |
| LLM（大语言模型） | 按提示词生成文本的模型，如 DeepSeek、Qwen；本项目不训练模型，只调用 |
| Prompt（提示词） | 给模型的输入指令，分系统提示词（定角色与规则）与用户提示词（本次问题）；BMS 的提示词模板集中管理、按能力区分 |
| Token | 模型处理文本与计费的基本单位，1 个中文字约 1~2 个 token；上下文越长费用越高 |
| 上下文窗口 | 模型一次能处理的最大文本长度，决定能塞进多少检索内容/文档片段 |
| API key | 模型服务的访问凭据；BMS 走 Secret 管理（环境变量 `BMS_AI_API_KEY`），不入库、不写代码 |
| OpenAI 兼容接口 | 事实上的 REST API 标准（`POST /chat/completions`）：DeepSeek/Qwen 外部 API 与 Ollama/vLLM 私有化端点都支持，适配层据此统一调用 |
| 私有化端点 | 把开源模型部署在自己机器上（Ollama 单机运行、vLLM 高性能推理），数据不出内网，用于敏感场景 |
| RAG（检索增强生成） | 先从 ES/Milvus 检索相关片段，把片段连同问题一起喂给 LLM 生成答案；知识库问答、文件问答的主要做法，可溯源、少幻觉 |
| NL2SQL | 自然语言转 SQL：智能报表助手的底层做法；生成的 SQL 必须过权限与白名单校验后执行 |
| Embedding | 把文本转成向量的模型/过程，语义检索的前提（向量存 Milvus，见《[Milvus 技术介绍](Milvus技术介绍.md)》） |
| ai_chat_log | BMS 的 AI 交互审计表：全量记录模型、token 消耗、提示词摘要、结果与耗时，用于合规与成本分析 |
| 独立限流 | AI 接口单独限流（slowapi），与业务接口隔离，防刷防成本失控 |

## 3. 在 BMS 项目中的用途 <a id="usage"></a>

- **八项 AI 能力的统一底座**（见《[项目规划说明](../../../规划/项目规划说明.html#modules)》5 节「AI 能力」行）：智能报表助手（NL2SQL 问数）、智能审批辅助（参考意见/风险提示）、AI 内容生成（邮件/通知模板、审批意见、申请理由草稿）、语义搜索与文件问答（Milvus）、OCR 与文件自动分类、审计异常检测、知识库问答机器人、帮助文档智能维护。
- **模型可切换、不侵入业务**：默认外部 API（DeepSeek/Qwen），敏感场景切私有化端点（Ollama/vLLM）；模型名、端点、key 都是配置项（`config.toml` 的 `[ai]` 小节），业务代码只认适配层统一接口。
- **凭据安全**：API key 走 Secret 管理（`BMS_AI_API_KEY`），严禁硬编码或提交仓库。
- **AI 结果默认仅辅助展示**：意见、草稿、检索、告警建议都供人参考；「AI 自动执行写操作」与「AI 自动审批」是两个独立可选开关，**默认关闭**，且审批开关依赖写操作开关开启（见《[项目规划说明](../../../规划/项目规划说明.html#security)》12 节）。
- **数据不出租户边界**：向量库按租户隔离（Milvus collection 按租户建）、提示词注入防护、AI 交互全量落 `ai_chat_log` 审计。
- **帮助文档智能维护**：输入源为功能代码（graphify 知识图谱）、设计文档与表单元数据；支持手动触发、变更事件自动触发（`form.updated` 事件驱动）、定时质量评估；生成结果一律为草稿，人工审核后发布，不自动覆盖已发布文章。
- **独立限流**：AI 接口单独限流，避免大模型调用拖垮业务接口或刷爆费用。

```python
# 业务代码只调适配层统一接口，不关心背后是哪家模型
from app.services import llm

result = llm.chat(
    tenant_id=1,
    system="你是 BMS 智能报表助手，用中文回答，只基于查询结果作答。",
    user="上个月采购申请总金额是多少？",
)
print(result["text"])  # 结果默认仅辅助展示，落 ai_chat_log 审计
```

## 4. 选型对比 <a id="compare"></a>

| 候选方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **自建薄适配层（选中）** | 基于 OpenAI 兼容接口，轻量可控；审计、限流、租户边界、模型切换全部自持，无额外重依赖 | 超时重试、token 统计、流式输出需自行实现（工作量可控） | 与「可切换 + 可审计 + 边界可控」的项目要求最贴合 |
| LangChain | 生态丰富，RAG/Agent 组件现成 | 依赖重、抽象层厚，审计与数据边界难完全自持，版本迭代快 | 不作主链路，其 RAG 做法可作参考 |
| LlamaIndex | 专注数据索引与 RAG | 同样依赖重，与项目「薄封装」取向不符 | 不采用 |
| 各厂商 SDK 直连 | 上手快、功能全 | 业务代码与具体厂商耦合，换模型要改代码，审计散落各处 | 不采用 |

## 5. 常见问题与注意事项 <a id="pitfalls"></a>

- **API key 安全**：只走 Secret 管理（`BMS_AI_API_KEY`），不硬编码、不进日志明文、不进 git；定期轮换，泄漏立即作废重发。
- **提示词注入**：用户输入可能夹带「忽略之前指令」类攻击；系统提示词要设防，且 AI 结果默认仅辅助展示、不自动执行，是最后一道闸。
- **成本失控**：外部 API 按 token 计费，长上下文很贵；独立限流 + 每日用量统计，超预算要能告警/熔断。
- **超时与重试**：LLM 响应可能 10~60 秒以上，接口要设合理超时、幂等重试；长回答建议流式输出，别让用户干等。
- **换模型要回归**：不同模型能力差异大，切换后必须重跑验收用例（尤其 NL2SQL 的安全执行验证），不能只改配置就上线。
- **数据边界**：敏感场景必须走私有化端点（Ollama/vLLM）；用外部 API 前确认数据出边界符合客户合规要求与厂商条款。
- **审计完整性**：成功与失败调用都要落 `ai_chat_log`（模型、token、耗时、结果摘要），否则出了问题查无实据。
- **两个开关的依赖关系**：AI 自动审批依赖「AI 自动执行写操作」开关开启，两者默认都关闭；开启后须配白名单 + 二次确认 + 可撤销（规划 12 节）。
