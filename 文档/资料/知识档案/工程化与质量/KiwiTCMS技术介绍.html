1. 技术概述

Kiwi TCMS 是一个开源测试用例管理系统（Django 编写的 Web 应用）， 管理用例（TestCase）、测试计划（TestPlan）、测试运行（TestRun）三类核心对象， 提供完整的 API 与 pytest 官方插件，把手工测试与自动化测试的执行结果统一收进一个平台归档。

  • 定位：BMS 的测试用例唯一管理平台（唯一用例库），手工与自动化用例统一登记。
  • 版本：16.x 系列（镜像 kiwitcms/kiwi，随镜像持续更新）。
  • 许可：GPL-3.0。作为独立测试基础设施部署于 mjbk、不随产品交付、不修改其源码，对本系统无传染影响（见《项目规划说明》2.5 节）。
  • 语言：Python（Django），部署形态为 Docker Compose 容器。

2. 核心概念与原理

概念说明
用例（TestCase）最小测试单元：标题、步骤、预期结果、优先级；BMS 约定名称与描述使用中文
测试计划（TestPlan）把一批用例组织成计划（如"阶段一回归计划"），计划内用例可排序、分组
测试运行（TestRun）计划的一次实际执行记录：每个用例的执行结果（通过/失败/阻塞/跳过）逐条落库，形成历史
Category / Tag分类方式：Category 按模块组织用例，Tag 打业务标签（如 E2E、冒烟），交叉检索
Build（构建）测试运行挂在具体构建版本上，结果与版本对应，方便回归比对
官方 API 与插件REST API + tcms-api 插件：pytest / Playwright 执行结果一键导入平台归档
用例 ID每个用例有平台内唯一编号，BMS 测试代码以用例 ID 标注关联，实现"代码 ↔ 用例 ↔ 验收项"双向追溯
缺陷链接用例/运行条目可与缺陷关联，BMS 约定缺陷实体在 GitLab Issue，链接指向 GitLab
统计与历史平台按计划/运行/时间维度统计通过率与执行历史，支撑《项目规划说明》16.5 节测试报告

3. 在 BMS 项目中的用途

  • 作为《项目规划说明》2.3 节指定的测试用例管理平台（选型依据见《项目规划说明》3.3 节），承担"唯一用例库"职责。
  • 手工与自动化用例统一登记：前端大量页面产生的 E2E 用例、后端接口用例、手工用例全部收进平台，用例编号唯一；测试代码以用例 ID 标注关联。
  • 执行结果导入归档：pytest / Playwright 结果经官方插件导入平台，CI 每次跑完自动归档（见《项目规划说明》3.4 节），历史统计随《项目规划说明》16 节测试流程汇总。
  • 用例内容中文：名称/描述/分类中文，按模块建 Category + Tag 组织；界面以官方简体中文翻译为主、浏览器自动翻译兜底。
  • 可追溯性：用例标注所属模块与对应验收项（见《项目规划说明》16.1 节），保证需求全覆盖、无孤儿用例。
  • 缺陷闭环：平台内缺陷链接指向 GitLab Issue，上报 → 修复 → CI 回归验证 → 关闭的流程以用例为锚点（见《项目规划说明》16.2 节）。
  • 部署与日常维护见《KiwiTCMS部署使用说明》：mjbk Docker Compose 常驻、复用 mjbk MySQL（库 kiwi）、宿主端口 8060（HTTPS、自签名证书、仅内网），业务数据随 MySQL 每日备份。

5. 常见问题与注意事项

  • GPL-3.0 边界：Kiwi TCMS 仅作独立测试基础设施部署，不随产品交付、不改其源码、不走代码链接，遵守《项目规划说明》2.5 节的独立部署边界即可，不要把它打包进产品镜像。
  • HTTPS 自签名证书：访问 https://<mjbk-IP>:8060 首次需接受浏览器证书警告（仅内网使用）；自动化导入脚本注意跳过证书校验或配置信任。
  • 用例 ID 关联维护：用例在平台登记与代码标注要同步，重命名/删除用例后同步更新代码标注，否则追溯链断裂（CI 可不强制、人工评审把关）。
  • 导入归档的账号权限：自动化导入用专用服务账号（只读 + 更新执行结果），避免用个人账号，防止离职/改密导致 CI 中断。
  • 数据备份：业务数据全在 mjbk MySQL 的 kiwi 库，随《MySQL部署使用说明》每日 dump；上传附件在命名卷 compose_kiwi-uploads，备份脚本需单独覆盖（见部署说明第 5 节）。
  • 中文界面：官方简体中文翻译已开启为主，个别页面用浏览器自动翻译兜底；用例内容本身是中文，不受界面语言影响。
  • 与 GitLab 账号体系独立：Kiwi TCMS 用户体系与 GitLab 不打通，新同事入职需在平台单独开号并授最小权限。
