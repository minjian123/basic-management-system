## 1. 技术概述 <a id="overview"></a>

**禅道（ZenTao）** 是国产开源项目管理软件（青岛易软天创网络科技有限公司开发），把产品（需求）、项目（迭代/任务）、测试（用例/缺陷）、文档等研发管理对象放在同一个平台管理，对标 Jira + 缺陷管理的国产一体化方案，原生全中文界面。

- **定位**：BMS 的**项目管理平台**——需求/任务/迭代/甘特图/看板/文档的登记与进度管理载体（选型见《[项目规划说明](../../../规划/项目规划说明.md#sel-eng)》3.3 节）。
- **版本**：禅道开源版（随官方镜像 `easysoft/zentao` 持续更新，部署时取最新稳定版）。
- **许可**：ZPL 1.2（ZenTao Public License，禅道自有开源许可，**非 OSI 认证**）。内部自用免费；仅作独立项目管理服务部署于 mjbk、不随产品交付，无传染影响；商业再分发或对外提供 SaaS 服务需采购商业授权（见《[项目规划说明](../../../规划/项目规划说明.md#stack-license)》2.5 节）。
- **语言**：PHP（Apache），部署形态为 Docker Compose 容器（mjbk 常驻，宿主端口 8070）。**数据库复用 mjbk 外部 MySQL**（bms-mysql 容器的 `zentao` 库）；官方镜像亦支持内置 MySQL（`MYSQL_INTERNAL=true` 启用，默认使用外部库），本项目采用外部库形态（2026-08-21 部署定案）。

## 2. 核心概念与原理 <a id="principles"></a>

| 概念 | 说明 |
| --- | --- |
| 产品（Product） | 顶层业务域，需求按产品组织；BMS 规划为「BMS 基础管理系统」一个产品 |
| 需求（Story） | 功能需求条目（用户故事式），可挂计划；BMS 对应《项目规划说明》功能模块与 MVP 验收项 |
| 项目（Project）/ 迭代（Sprint） | 交付单元，迭代内拆任务；BMS 里程碑 M0~M15 对应各阶段迭代 |
| 任务（Task） | 最小执行单元，可指派、估时、记录工时；BMS 按阶段 WBS 拆解登记 |
| 甘特图 | 项目/迭代内任务的时间条视图，BMS 进度跟踪以禅道甘特图为准 |
| 看板（Kanban） | 任务按状态（待办/进行中/已完成等）列展示，拖拽流转 |
| 燃尽图 | 迭代内剩余工作量趋势，反映迭代进度健康度 |
| 文档（Doc） | 平台内文档库，可挂接项目；BMS 阶段报告、复盘记录等可归档于此 |
| 缺陷（Bug） | 禅道内置缺陷管理，**BMS 约定不使用**——缺陷实体在 GitLab Issue，避免双轨 |
| 测试模块（用例/测试单） | 禅道自带测试用例管理，**BMS 约定不使用**——唯一用例库为 Kiwi TCMS（见《[KiwiTCMS 技术介绍](KiwiTCMS技术介绍.md)》） |
| REST API | 禅道提供 API（token 认证），供脚本集成（如任务批量导入） |

## 3. 在 BMS 项目中的用途 <a id="usage"></a>

- 作为《[项目规划说明](../../../规划/项目规划说明.md#stack-eng)》2.3 节指定的项目管理平台（选型依据见 3.3 节），承担「需求/任务/迭代/进度」管理职责。
- 需求与任务登记：按《[总体项目规划](../../../规划/总体项目规划.md#wbs)》第 6 节 WBS 将 15 个阶段的工作包拆解为禅道任务，挂接各阶段迭代；里程碑 M0~M15 以迭代与完成标准验收（见《[总体项目规划](../../../规划/总体项目规划.md#milestones)》7.1 节）。
- 进度管理：迭代看板日常流转任务状态，甘特图跟踪阶段工期基线（《[总体项目规划](../../../规划/总体项目规划.md#baseline)》第 15 节），偏差触发里程碑门禁评审与工期基线滚动调整。
- 与 GitLab 分工：**禅道管需求/任务/迭代，GitLab Issue 只承载代码缺陷与 MR 关联**；任务与缺陷在两侧以链接互指，代码提交仍走 GitLab MR 流程（见《[总体项目规划](../../../规划/总体项目规划.md#comm)》第 11 节）。
- 与 Kiwi TCMS 边界：**测试用例继续以 Kiwi TCMS 为唯一用例库**，禅道测试模块不使用（pytest/Playwright 结果经 Kiwi 官方插件回流 CI 的既定链路不变）。
- 部署与日常维护见《[禅道部署使用说明](../../开发服务器/禅道部署使用说明.md)》与《开发部署规划》第 4.3/9/10 节：mjbk Docker Compose 常驻（镜像 `easysoft/zentao`）、宿主端口 8070（容器内 80）、**数据库复用 bms-mysql 的 `zentao` 库**（镜像环境变量 `MYSQL_HOST/MYSQL_PORT/MYSQL_DB/MYSQL_USER/MYSQL_PASSWORD` 注入，账号见 `deploy/.env` 的 `ZENTAO_*`）、程序数据在命名卷 `zentao-data`。

## 4. 选型对比 <a id="compare"></a>

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **禅道开源版（选中）** | 全中文界面、需求/任务/迭代/甘特图/看板/文档一体、官方 Docker 镜像一键部署、国产维护活跃、资源占用可控（预算 1.5 GB） | 许可 ZPL 非 OSI（内部自用免费，商业再分发需授权）；与 Kiwi TCMS 测试模块有功能重叠（约定不使用） | 与单人兼职、中文、内网自托管场景完全契合 |
| OpenProject（社区版） | GPL-3.0（OSI）、项目管理最标准全面（甘特图/WBS/时间跟踪/报告）、官方 Docker Compose | 资源占用重（内存 2-4 GB+），mjbk 预算紧张；界面英文为主 | 资源与语言成本偏高，不采用 |
| Plane | AGPL-3.0（OSI）、现代界面、迭代 Cycles/模块/甘特图视图齐全、Docker 一键 | 界面英文为主、无内置测试与文档体系、社区版功能边界需持续关注 | 中文场景适配成本高，不采用 |
| Redmine | GPL-2.0（OSI）、轻量成熟、中文翻译良好、插件生态丰富 | UI 老旧、原生看板/迭代弱（需插件组合） | 能力分散，不采用 |
| GitLab CE 自带（Issues/Milestones/Boards） | 零部署成本、与 MR/CI 天然一体 | 无甘特图，Epics/路线图是付费功能，项目管理视图弱 | 保留管代码缺陷，不承担项目管理 |

## 5. 常见问题与注意事项 <a id="pitfalls"></a>

- **ZPL 许可边界**：禅道开源版自用免费，但**不可打包进产品交付物、不可对外提供基于禅道的 SaaS 服务**（需采购商业授权）；BMS 内部开发管理使用不受影响，遵守《[项目规划说明](../../../规划/项目规划说明.md#stack-license)》2.5 节独立部署边界。
- **与 Kiwi TCMS / GitLab 的边界要守住**：禅道不用测试模块、不用缺陷模块，否则与唯一用例库（Kiwi）和缺陷载体（GitLab Issue）形成双轨，破坏既定流程与追溯链。
- **自动化结果导入**：禅道无 pytest 官方插件，自动化结果回流传给 Kiwi TCMS 官方插件承担，不要在禅道上自建测试结果导入。
- **内存占用**：官方镜像为 Apache + PHP（内置 MySQL 可选，本项目未启用），预算 1.5 GB 封顶，部署后以 `docker stats` 监控实际占用。
- **数据备份**：业务数据在 bms-mysql 的 `zentao` 库，随《[MySQL部署使用说明](../../开发服务器/MySQL部署使用说明.md)》每日 dump（`/mnt/data/backup/mysql/`）；程序配置与附件在命名卷 `zentao-data`（NVMe SSD），随命名卷整机级镜像；另禅道页面备份功能可每日导出至 `/mnt/data/backup/zentao/`（见《开发部署规划》第 8 节）。
- **首次安装**：部署完成后访问 `http://<mjbk-IP>:8070/install.php` 走 Web 安装向导（全新安装 → 数据库配置填 bms-mysql 的 `zentao` 库与账号 → 创建管理员账号），向导完成后自动建表并生成 `my.php`。
- **访问方式**：内网 `http://<mjbk-IP>:8070`；端口被占用时改映射并同步《开发部署规划》端口清单与防火墙放行。
- **与 GitLab/Kiwi 账号体系独立**：禅道用户体系与 GitLab、Kiwi TCMS 均不打通，各自建号并授最小权限。
