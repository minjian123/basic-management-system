## 1. 目的与适用范围 <a id="purpose"></a>

mjbk 上的禅道（容器 `bms-zentao`）是 BMS 项目的**项目管理平台**（《[项目规划说明](../../规划/项目规划说明.md)》2.3/3.3）：需求/任务/迭代/甘特图/看板/文档的登记与进度管理载体；
**数据库复用 mjbk MySQL（bms-mysql 的 `zentao` 库）**，宿主端口 8070。

占位符取值：`<mjbk-IP>`、`<内网网段>` 见《[本地资源](../../用户文档/本地资源.md)》与 mjbk 本机 `deploy/.env`（`MJBK_IP`）。

职责分工（已逐项确认）：禅道管需求/任务/迭代/进度；GitLab Issue 只承载代码缺陷与 MR 关联；测试用例仍归 Kiwi TCMS（禅道测试/缺陷模块不使用）。

## 2. Compose 配置 <a id="compose"></a>

定义于仓库 `deploy/compose/base.yml`（已同步至 mjbk `~/deploy/compose/base.yml`）：

```yaml
  zentao:
    image: easysoft/zentao:latest
    container_name: bms-zentao
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
      MYSQL_HOST: ${ZENTAO_MYSQL_HOST}
      MYSQL_PORT: ${ZENTAO_MYSQL_PORT}
      MYSQL_DB: ${ZENTAO_MYSQL_DB}
      MYSQL_USER: ${ZENTAO_MYSQL_USER}
      MYSQL_PASSWORD: ${ZENTAO_MYSQL_PASSWORD}
    ports:
      - "8070:80"
    volumes:
      - zentao-data:/opt/zbox
      - zentao-userdata:/data
    mem_limit: 1536m
```

> **镜像说明**：`easysoft/zentao:latest` 为禅道官方镜像（滚动发布，2026-08-21 实测容器版本 **22.5**，`/apps/zentao/VERSION`）。镜像**默认使用外部 MySQL**（内置库需 `MYSQL_INTERNAL=true` 才启用）——本项目按确认结果采用**外部库形态**（复用 bms-mysql）。容器内 Apache 监听 80，故映射 `8070:80`，访问地址是 `http://`。

> **卷布局（两卷，2026-08-21 `docker inspect` 实测）**：
> - **应用卷**（具名 `compose_zentao-data`，挂容器 `/opt/zbox`）：禅道应用本体（`bin`/`etc`/`lib`），首次挂载时由镜像拷入；宿主路径 `/mnt/ssd2t/docker/volumes/compose_zentao-data/`（卷名带 compose 项目名前缀）。**可随镜像重建，不必单独备份。**
> - **数据卷**（具名 `compose_zentao-userdata`，挂容器 `/data`）：**真正需备份的用户数据**——`/data/zentao/config/my.php`（配置）、`config/license/`（授权）、`www/data/`（上传附件）、`tmp/backup/`（内部备份包）、`extension/`（扩展）；宿主路径 `/mnt/ssd2t/docker/volumes/compose_zentao-userdata/`。
>
> **备份以数据卷（`/data`）为准**（见第 7 节与 `deploy/tools/backup/backup_zentao.sh`）。

## 3. 部署步骤 <a id="deploy"></a>

1. mjbk `~/deploy/.env` 配置禅道键（键位见仓库 `deploy/.env.example`）：`ZENTAO_MYSQL_HOST/PORT/DB/USER/PASSWORD`（指向 bms-mysql 与 `zentao` 库）。

2. 在 mjbk MySQL（bms-mysql）创建独立库与账号（库 `zentao`，utf8mb4；账号 `zentao`，仅授 `zentao` 库权限）：

    ```sql
    mysql -h<mjbk-IP> -uroot -p \
      -e "CREATE DATABASE IF NOT EXISTS zentao DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
          CREATE USER IF NOT EXISTS 'zentao' IDENTIFIED BY '<密码>';
          GRANT ALL PRIVILEGES ON zentao.* TO 'zentao';
          FLUSH PRIVILEGES;"
    ```

3. 启动容器（首次自动拉取官方镜像，较大，耐心等待）：

    ```bash
    cd ~/deploy
    docker compose -f compose/base.yml --env-file ~/deploy/.env up -d zentao
    ```

4. **Web 安装向导**（关键步骤，无法跳过）：浏览器打开 `http://<mjbk-IP>:8070/install.php`，选「全新安装」→ 环境检查 → 数据库配置填：
   数据库服务器 `192.168.0.107`、端口 `3306`、用户名 `zentao`、密码（`.env` 的 `ZENTAO_MYSQL_PASSWORD`）、数据库名 `zentao`（字符集选 `utf8mb4`）；
   完成后创建管理员账号（记录到《[本地资源](../../用户文档/本地资源.md)》与 mjbk 密码管理器）。

> 排障提示：容器内 `localhost` 不是数据库地址，向导必须填宿主 IP `192.168.0.107`；向导完成前首页 302 跳转 `install.php` 属正常，完成后跳转登录页（`index.php?m=user&f=login`）。

## 4. 验证 <a id="verify"></a>

```bash
docker ps --filter name=bms-zentao              # Up ...，端口 0.0.0.0:8070->80/tcp
curl -sI http://127.0.0.1:8070/ | grep -i location   # 302 → /index.php?m=user&f=login
docker exec bms-mysql mysql -uzentao -p<密码> -e "SHOW TABLES;" zentao   # ops_ 前缀表（禅道 21 表前缀）
docker stats --no-stream bms-zentao             # 内存预算 1.5 GB 封顶
```

本次部署结果：容器 Up、登录页 302 正常、`zentao` 库已建表、管理员 `minjian` 登录验证通过（API token 获取成功）。

## 5. 使用说明 <a id="use"></a>

| 项目 | 值 |
| --- | --- |
| 访问地址 | `http://<mjbk-IP>:8070`（HTTP，仅内网） |
| 管理员账号 | `minjian`（密码见《[本地资源](../../用户文档/本地资源.md)》） |
| 界面语言 | 原生简体中文 |
| 数据存储 | 业务数据在 MySQL `zentao` 库；配置/授权/上传附件在**数据卷**（具名 `compose_zentao-userdata`，容器 `/data`，宿主 `/mnt/ssd2t/docker/volumes/compose_zentao-userdata/`）；应用本体在应用卷 `compose_zentao-data`（容器 `/opt/zbox`） |

BMS 项目中的用法（与《[总体项目规划](../../规划/总体项目规划.md)》一致）：

- 产品「BMS 基础管理系统」+ 项目「BMS 开发」（scrum）+ 迭代 M0~M15（对应里程碑，T+0 相对工期，日期为示意，实际以里程碑门禁调整）。
- 任务按阶段 WBS 登记、指派 `minjian`，迭代内看板流转；甘特图为进度跟踪依据，偏差触发里程碑评审与工期基线滚动调整。
- 缺陷登记在 GitLab Issue（禅道缺陷模块不使用），任务与 Issue 以链接互指；测试用例登记在 Kiwi TCMS（禅道测试模块不使用）。

## 6. 日常运维 <a id="ops"></a>

| 操作 | 命令 |
| --- | --- |
| 查看状态 | `docker ps --filter name=bms-zentao` |
| 查看日志 | `docker logs -f bms-zentao` |
| 重启 | `docker restart bms-zentao` |
| 更新镜像 | `docker compose -f compose/base.yml pull zentao && docker compose -f compose/base.yml up -d zentao` |
| 数据库备份 | 随《[MySQL部署使用说明](MySQL部署使用说明.md)》每日 dump（`zentao` 库在 `/mnt/data/backup/mysql/`） |
| 禅道页面备份 | 后台 → 数据备份 → 备份到服务器（导出目录见容器 `/opt/zbox/data/zentao/tmp/backup`） |

> 防火墙：mjbk ufw 当前处于**不活动**状态；若日后启用 ufw，需放行内网 8070（`allow from <内网网段> to any port 8070 proto tcp`），并注意 Docker 发布端口需 `ufw default allow routed`（见 GitLab 部署说明排障记录）。

## 7. 备份与恢复 <a id="backup"></a>

- **业务数据**：全部在 MySQL `zentao` 库，随《[MySQL部署使用说明](MySQL部署使用说明.md)》每日 dump；恢复时重建库账号后导入 dump 即可，无需改动容器配置。
- **程序配置/授权/上传附件**（**数据卷**，具名 `compose_zentao-userdata` 挂容器 `/data`）：由 `deploy/tools/backup/backup_zentao.sh` 每日 02:00 备份（`--volumes-from bms-zentao` 取 `/data` 卷 tar，落 `/mnt/data/backup/zentao/` 保留 7 天）；手动备份：`docker run --rm --volumes-from bms-zentao -v /mnt/data/backup/zentao-data:/backup alpine tar czf /backup/zentao-data.tar.gz -C /data .`。
- **应用本体**（应用卷 `compose_zentao-data`，挂容器 `/opt/zbox`）：可随镜像重建，不单独备份；如需：`docker run --rm -v compose_zentao-data:/src alpine tar czf - -C /src . > /mnt/data/backup/zentao-app.tar.gz`。
- **禅道页面备份**：后台「数据备份」可定时/手动生成禅道内部备份包（含数据库 dump 与附件），导出至 `/mnt/data/backup/zentao/` 保留 7 天。

## 8. 排障记录 <a id="trouble"></a>

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 内置 MySQL 未启动导致服务不可用 | 首次启动容器 Up 但 `curl` 返回 000；日志 `Apache Unable to connect to MySQL: 127.0.0.1:3306`，重试耗尽 | 官方镜像**默认使用外部 MySQL**（`MYSQL_INTERNAL` 默认 false），仅设 `MYSQL_ROOT_PASSWORD` 不会启用内置库；改配 `MYSQL_HOST/MYSQL_PORT/MYSQL_DB/MYSQL_USER/MYSQL_PASSWORD` 复用 bms-mysql 的 `zentao` 库后重建容器 |
| 安装向导跳转 install.php 且无法完成 | 服务就绪后首页 302 到 `install.php`，数据库表未建 | 属正常：禅道需 Web 安装向导完成建表与管理员创建；数据库配置必须填宿主 IP `192.168.0.107`（容器内 localhost 无数据库），字符集选 utf8mb4 |
| API 创建迭代报「所属项目不能为空」 | POST `/api.php/v1/executions` body 带 `project` 仍失败 | 迭代创建走复数入口 `POST /api.php/v1/executions?project={id}`，`project` 从 **URL 参数**取（body 中的值会被覆盖） |
| API 创建任务返回 200 空响应 | 单数与带 ID 的 URL 均无响应体、任务未创建 | 任务创建须走**批量入口** `POST /api.php/v1/executions/{id}/tasks/batchCreate`（body `{"tasks":[{name,type,estimate,estStarted,deadline,...}]}`）；`/tasks/{id}` 路由到单数 entry 无 post 方法，`estStarted`/`deadline` 必填 |
| API 指派任务报「《预计剩余》不能为空」 | 任务已建但 `assignto` 失败 | 指派须同时传 `left`（预计剩余，取任务 estimate） |

## 9. API 操作 <a id="api"></a>

禅道 REST API（`/api.php/v1`，token 认证）的端点总表、全部实测踩坑与 Python 工具包（`deploy/tools/zentao/`，CLI + 库两种用法）见《[禅道API使用说明](../AI/禅道API使用说明.md)》。本文档只列本次初始化用到的核心端点：

| 操作 | 方法/路径 | 要点 |
| --- | --- | --- |
| 获取 token | POST `/tokens` | body `{account,password}`，请求头 `Token: <token>` |
| 创建产品 | POST `/products` | body `{name}`（21.x 下 code 会被清空） |
| 创建项目 | POST `/projects` | body `{name,type:scrum,begin,end,products:[id]}`，`products` 必填 |
| 创建迭代 | POST `/executions?project={id}` | `project` 走 URL 参数 |
| 批量创建任务 | POST `/executions/{id}/tasks/batchCreate` | 唯一创建入口；`estStarted`/`deadline` 必填 |
| 指派任务 | POST `/tasks/{id}/assignto` | body `{assignedTo,left}`，`left` 必填 |
| 查看任务 | GET `/executions/{id}/tasks` | 列表分页 `page/limit`，limit 最大 100 |
