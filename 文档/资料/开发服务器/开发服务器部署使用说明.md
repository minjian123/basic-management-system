## 1. 目的与适用范围 <a id="purpose"></a>

本文档是开发服务器 **mjbk**（内网 IP 记为 `<mjbk-IP>`，Ubuntu 24.04.4 LTS 桌面版）全部开发服务的**总览**：
部署顺序、服务清单、端口与目录约定、日常运维入口。
每项服务的详细部署步骤、调试记录与排障经验单独成文（见[第 8 节](#docs)），本文档只做汇总与导航。
**取值说明**：本文档中 `<mjbk-IP>` / `<mjpc-IP>` / `<SSH账号>` / `<内网网段>` 等占位符的具体值见《[本地资源](../../用户文档/本地资源.md)》与 mjbk 本机 `deploy/.env`（键 `MJBK_IP` / `MJBK_SSH_USER`），不在仓库文档中记录。

部署依据《[开发部署规划](../../规划/开发部署规划.md)》；系统安装与基础配置见《[Ubuntu安装部署使用说明](../工具/Ubuntu安装部署使用说明.md)》。

## 2. 环境概览 <a id="env"></a>

| 机器 | IP | 系统 | 角色 |
| --- | --- | --- | --- |
| mjbk | `<mjbk-IP>` | Ubuntu 24.04.4 LTS（桌面版） | 开发服务器（有线接入，常开） |
| mjpc | `<mjpc-IP>` | Windows 11 专业版 | 开发机（本地编码与联调） |

### 2.1 已就绪项 <a id="env-ready"></a>

- 系统：Ubuntu 24.04.4 LTS，静态 IP `<mjbk-IP>/24`，时区 Asia/Shanghai，主机名 `mjbk`
- 远程通道：SSH（22），mjpc 公钥免密登录
- apt 镜像源：清华 TUNA（已验证）
- 数据盘：1TB HDD 挂载 `/mnt/data`（ext4，fstab 自动挂载）；2T NVMe SSD 挂载 `/mnt/ssd2t`（ext4，fstab 自动挂载，Fanxiang S770）
- Docker 运行数据：data-root 已迁移至 `/mnt/ssd2t/docker`（镜像/容器/命名卷全部上 NVMe），GitLab 数据迁至 `/mnt/ssd2t/gitlab`
- 系统快照：Timeshift 每日自动备份（保留 5 份，存 `/mnt/data/timeshift`）
- 笔记本特性：合盖不休眠（logind + GNOME 两层配置）

### 2.2 磁盘与目录 <a id="env-disk"></a>

| 盘 | 容量 | 存放内容 |
| --- | --- | --- |
| 系统盘 SSD（`/`） | 512 GB | 系统 + Docker Engine 本体；Docker 运行数据已迁出，当前仅用约 40 GB |
| NVMe SSD（`/mnt/ssd2t`） | 2 TB | Docker data-root（`/mnt/ssd2t/docker`：镜像/容器/全部命名卷，数据库等 IO 敏感数据）、GitLab 数据（`/mnt/ssd2t/gitlab`） |
| HDD（`/mnt/data`） | 1 TB | 备份（`/mnt/data/backup`）、Timeshift 快照（`/mnt/data/timeshift`）——数据与备份异盘，单盘故障可恢复 |

## 5. 配置与凭据管理 <a id="config"></a>

- 真实凭据只写 `deploy/.env`（mjbk 本机，`.env.example` 入仓库）；密钥类配置只走环境变量，不入文档。
- 机器登录凭据见《[本地资源](../../用户文档/本地资源.md)》；各服务账号密码在部署时生成，记录于 mjbk 本机密码管理器，不写入本文档与仓库。
- 服务名、环境变量、数据库命名遵循《[命名规范](../../规范/命名规范.md)》。

## 6. 日常运维速查 <a id="ops"></a>

| 操作 | 命令 |
| --- | --- |
| SSH 登录 | `ssh <SSH账号>@<mjbk-IP>` |
| 服务状态 | `docker compose -f deploy/compose/xxx.yml ps` / `docker ps` |
| 服务日志 | `docker logs -f <容器名>` |
| 防火墙状态 | `sudo ufw status` |
| 系统快照 | `sudo timeshift --list`（恢复见《[Ubuntu安装部署使用说明](../工具/Ubuntu安装部署使用说明.md)》第 7 节） |

## 7. 备份与恢复 <a id="backup"></a>

- **系统层**：Timeshift 每日快照（保留 5 份），装坏环境用安装 U 盘 `sudo timeshift --restore` 还原。
- **数据层**：数据库每日 dump 至 `/mnt/data/backup/`（cron 2 点执行），GitLab 每日 `gitlab-backup`，详见《开发部署规划》第 8 节与各服务文档。
