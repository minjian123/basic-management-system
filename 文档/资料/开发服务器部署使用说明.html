1. 目的与适用范围

本文档记录 BMS 开发服务器 mjbk（192.168.0.107）远程管理通道的开通过程、部署命令与排障经验， 供后续在开发机 mjpc 上远程操作 mjbk 时参照。硬件与账号信息见《本地资源》， 开发环境的整体部署方案见《开发部署规划》。

当前已打通两条远程通道：

  • WinRM（PowerShell 远程，HTTP 5985）：批量脚本与自动化操作
  • OpenSSH Server（端口 22）：跨平台命令行登录（v10.0.0.0p2，手动安装）

3. WinRM 远程通道开通

3.1 mjbk 侧启用

通过 RDP 登录 mjbk，管理员 PowerShell 执行（首次只需一次）：

Enable-PSRemoting -Force

输出应包含「WinRM 已更新为接收请求」「WinRM 防火墙异常已启用」。若防火墙规则显示未启用，补充执行：

Get-NetConnectionProfile | Select-Object Name, InterfaceAlias, NetworkCategory
Set-NetFirewallRule -Name "WINRM-HTTP-In-TCP" -Enabled True

3.2 mjpc 侧配置

mjpc 管理员 PowerShell 执行（首次只需一次）：

Set-Service WinRM -StartupType Automatic
Start-Service WinRM
Set-Item WSMan:\localhost\Client\TrustedHosts -Value "192.168.0.107" -Force
坑点 1：mjpc 本机 WinRM 服务默认是 Stopped，不先启动则 TrustedHosts 路径不存在、写入报错； 且以上命令需要管理员权限（非管理员报 Access denied）。

3.3 连通性验证

Test-NetConnection -ComputerName 192.168.0.107 -Port 5985

$pw = ConvertTo-SecureString "密码" -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential("minjian", $pw)
Invoke-Command -ComputerName 192.168.0.107 -Credential $cred -ScriptBlock { hostname }

返回 MJBK 即打通。日常远程操作模板：

$pw = ConvertTo-SecureString "密码" -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential("minjian", $pw)
Invoke-Command -ComputerName 192.168.0.107 -Credential $cred -ScriptBlock { 任意 PowerShell 命令 }

4. OpenSSH Server 安装

4.1 系统组件方式失败原因

最初尝试 Windows 可选功能方式安装，两个环节失败：

  • 远程会话权限不足：WinRM 会话内执行 Add-WindowsCapability -Online -Name OpenSSH.Server 报「拒绝访问」；改为计划任务以 SYSTEM 身份运行（schtasks /create /ru SYSTEM /rl HIGHEST）可解决权限，但：
  • 微软源下载极慢：组件安装卡在 Windows Update 下载超过 10 分钟无进展（DismHost/TiWorker 活跃但无网络吞吐），遂终止，改用国内镜像手动安装（见 4.2）。
依据《AGENTS.md》网络与镜像规则：默认源（微软 CDN）不畅时立即切换国内镜像，不长时间等待。实测 update.microsoft.com 可连通但下载速度极慢，镜像源 gh-proxy.com 约 1.4–4 MB/s。

4.2 镜像下载与手动安装

步骤 1：用国内镜像代理下载 Win32-OpenSSH 官方二进制（mjbk 上执行）：

curl.exe -sL --max-time 180 -o C:\bms-tmp\OpenSSH-Win64.zip `
  "https://gh-proxy.com/https://github.com/PowerShell/Win32-OpenSSH/releases/download/10.0.0.0p2-Preview/OpenSSH-Win64.zip"

可用镜像代理（2026-08 实测）：gh-proxy.com（最快）、ghfast.top；ghproxy.net 慢、ghproxy.cc 不可用。GitHub 直连仅约 8 KB/s。

步骤 2：解压安装并注册服务（mjbk，管理员 PowerShell）：

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
Expand-Archive C:\bms-tmp\OpenSSH-Win64.zip -DestinationPath "$env:TEMP\oss-x" -Force
Copy-Item "$env:TEMP\oss-x\OpenSSH-Win64" "C:\Program Files\OpenSSH" -Recurse -Force
sc.exe stop sshd 2>$null; sc.exe delete sshd 2>$null
& "C:\Program Files\OpenSSH\install-sshd.ps1"
Set-Service sshd -StartupType Automatic
Start-Service sshd
& "C:\Program Files\OpenSSH\ssh.exe" -V
坑点 2：install-sshd.ps1 需在允许脚本执行的环境中运行（Set-ExecutionPolicy -Scope Process Bypass）， 否则报「禁止运行脚本」。

4.3 防火墙放行

New-NetFirewallRule -Name "OpenSSH-Server-In-TCP" -DisplayName "OpenSSH SSH Server (sshd)" `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 `
  -RemoteAddress 192.168.0.0/24 -Profile Any

验证：Get-NetTCPConnection -LocalPort 22 -State Listen 应显示 0.0.0.0:22 与 [::]:22 监听。

5. SSH 密钥认证配置

5.1 客户端密钥生成

mjpc 上生成（已生成，可跳过）：

ssh-keygen -t ed25519 -N "" -f "$env:USERPROFILE\.ssh\id_ed25519" -C "minjian@mjpc"
坑点 3（重要）：不要写成 -N '""'。PowerShell 中 '""' 会把两个 字面双引号字符作为密码传给 ssh-keygen，私钥因此意外带密码；批处理模式（BatchMode）下无法输密码， 导致签名失败、认证被拒（见 6.3）。生成后务必验证： 
ssh-keygen -y -P "" -f "$env:USERPROFILE\.ssh\id_ed25519"
能输出公钥才说明私钥无密码。

5.2 公钥部署与权限

将公钥写入 mjbk 的用户 authorized_keys（本次绕过了默认的 Match Group administrators 专用文件，直接使用普通用户路径，配置更简洁）：

# mjbk 上执行：注释掉 sshd_config 中的 Match 块，改用普通文件
$c = [IO.File]::ReadAllText("C:\ProgramData\ssh\sshd_config")
$c = $c.Replace("Match Group administrators", "#Match Group administrators")
[IO.File]::WriteAllText("C:\ProgramData\ssh\sshd_config", $c, [Text.Encoding]::ASCII)

# 写入公钥（多个密钥逐行追加）
[IO.File]::WriteAllText("C:\Users\minjian\.ssh\authorized_keys",
  "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIMlSnUNRBgq3+MBwLTILhdig5MOeEAc9RrYKwDT0ZM2Q minjian@mjpc`n",
  [Text.Encoding]::ASCII)

# 权限：仅用户本人与 SYSTEM 可访问
icacls "C:\Users\minjian\.ssh\authorized_keys" /inheritance:r /grant:r "minjian:(R,W)" "NT AUTHORITY\SYSTEM:(F)"
Restart-Service sshd

5.3 验证

ssh -i "$env:USERPROFILE\.ssh\id_ed25519" minjian@192.168.0.107 "hostname"

返回 mjbk 即成功。免密登录（本机默认密钥名时可直接 ssh minjian@192.168.0.107）。

6. 排障记录

6.1 防火墙规则不生效

现象：sshd 监听正常、规则显示 Enabled/Allow/Profile=Any/端口 22，但外部连接 TCP 超时； 临时禁用防火墙后即通。

处理：删除并重建规则后恢复正常：

Remove-NetFirewallRule -Name "OpenSSH-Server-In-TCP"
New-NetFirewallRule -Name "OpenSSH-Server-In-TCP" -DisplayName "OpenSSH SSH Server (sshd)" `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 `
  -RemoteAddress 192.168.0.0/24 -Profile Any
该规则疑似在组件安装残留的异常半激活状态，Get-NetFirewallRule -All 可见 Inactive 状态为空；重建规则即生效。

6.2 公钥认证 preauth 失败

现象：公钥认证返回 Permission denied；服务端日志出现 Accepted key ... found at ... → Postponed publickey → ssh_dispatch_run_fatal: Unknown error [preauth]。

排查路径（逐层排除）：

  1. 客户端 ssh -vvv：确认「Server accepts key」后出现 we did not send a packet, disable method——客户端签名失败、未发送签名请求，随即 RST（服务端表现为 10054 连接重置）。
  2. 服务端回环测试（本机 127.0.0.1 公钥认证）成功——排除服务端与系统问题。
  3. mjpc 换 v10 客户端仍失败、换端口仍失败、停 Defender 仍失败——排除客户端版本/端口/杀软。
  4. pktmon 抓包（管理员）：确认 RST 由 mjpc 本机发出（Flags [R.]，源 MAC 为 mjpc 网卡）。
  5. 最终定位：私钥意外带密码（见 6.3），BatchMode 签名失败。

6.3 私钥意外带密码

根因：ssh-keygen -N '""' 的 PowerShell 传参问题——单引号内的 "" 是两个字面字符， 被当作密码写入私钥。验证方法： 

ssh-keygen -y -P ""  -f id_ed25519   # 报 incorrect passphrase = 私钥有密码
ssh-keygen -y -P '""' -f id_ed25519   # 能输出公钥 = 密码是 "" 两个字面引号

修复（将密码移除）：

ssh-keygen -p -f "$env:USERPROFILE\.ssh\id_ed25519" -P '""' -N ""

6.4 其他坑点

坑点现象处理
ssh_host 事件日志无文本 手动安装 v10 后 OpenSSH 事件日志「无法检索事件消息文本」 消息 DLL 未注册，不影响功能；排查用 sshd -ddd 前台抓日志
sshd 只监听 2222 配置追加 Port 2222 后 22 端口丢失 sshd 配置中存在 Port 指令时只监听指定端口，移除多余 Port 行
WinRM 会话被杀 远程 Start-Process 启动的 sshd -ddd 随会话结束被终止 长驻前台进程用计划任务（/ru SYSTEM）运行
安装脚本禁跑 install-sshd.ps1 报「禁止运行脚本」 Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

8. 已知问题与安全提示

  • id_rsa 私钥（排查过程中生成）仍带密码未修复，未使用；如需删除请执行 Remove-Item "$env:USERPROFILE\.ssh\id_rsa*"。
  • SSH 同时启用密码认证（默认），远程凭据按《本地资源》管理；建议后续在 mjbk 上为 minjian 设置强密码。
  • 防火墙仅放行 192.168.0.0/24 内网访问 22/5985；密钥文件仅 SYSTEM 与用户本人可读。
  • OpenSSH 为手动安装的 10.0.0.0p2（官方 Preview 通道），如需随 Windows 更新管理可改回系统组件方式（需先卸载当前版本，且解决微软源下载慢问题）。
  • mjbk 通过 WiFi 接入，若后续排查网络相关问题注意 AP 侧因素（本次排障已排除 WiFi 影响）。
