1. 简介与协作模型

Git 是分布式版本控制系统，仓库在每个人本地有一份完整历史，可以离线提交，再通过远端（GitHub）交换。BMS 用 Git 管理整个 monorepo（backend、frontend、frontend-mobile、deploy、文档全在一个仓库里）。

协作模型：main 是唯一的保护分支，日常改动在 feature 分支上进行，经 Pull Request 合入 main，CI 通过才能合并（详见第 4 节）。

2. 安装与初始配置

# Windows（winget）/ macOS（brew）
winget install Git.Git
brew install git

# 首次配置（用户名与邮箱会写进每次提交）
git config --global user.name "你的名字"
git config --global user.email "you@example.com"

# 克隆 BMS 仓库
git clone <仓库地址>

Windows 上装完 Git 自带 Git Bash，PowerShell 里也能直接用 git 命令。

3. 常用命令

3.1 日常提交

git status         # 看改了哪些文件
git diff           # 看未暂存的具体改动
git add 文件名      # 暂存（只提交想提交的，别 git add . 一把梭）
git commit -m "feat: 描述"
git push           # 推送到远端

3.2 分支与合并

git switch main            # 切到 main
git switch -c feature/xxx  # 从当前分支开新分支
git pull                   # 拉取远端更新（提交前先 pull 保持同步）
git push -u origin feature/xxx   # 推送新分支并建立跟踪
# 合入 main 一律走 PR，不用本地 merge（见 4.1）

3.3 回退与修复

git restore 文件名         # 丢弃工作区改动（未暂存）
git restore --staged 文件名 # 取消暂存
git commit --amend         # 修正最近一次提交信息（未推送时用）
git log --oneline          # 看提交历史

4. 与 BMS 的集成

4.1 分支模型

  • main：保护分支，禁止直接推送，只能通过 PR 合入
  • feature 分支：命名如 feature/阶段任务或模块名，从 main 拉出，改完提 PR
  • 合并条件：CI 通过方可合并（GitHub Actions 状态会直接显示在 PR 上）；PR 含评审与讨论记录

4.2 提交规范

本仓库提交信息格式为「类型: 中文说明」，类型前缀取自 docs / feat / fix 等，说明用中文描述改了什么。仓库实际历史示例：

docs: 阶段一实施文档产出——实施记录/启动指南/验收报告，骨架说明移入阶段一目录
feat: 后端骨架初始化——pyproject/uv 依赖、config.toml 分层配置与核心配置加载

习惯：一次提交只做一件事，说明写清楚「做了什么」，别堆一堆无关改动。提交规范细节见《前端开发规范》（阶段一已产出）中的提交规范部分。

4.3 .gitignore

仓库根 .gitignore 已核实包含：.venv/、.env、__pycache__/、*.log、.pytest_cache/、.ruff_cache/、.coverage、dist/、.reasonix/、graphify-out/（图谱产物含本机绝对路径，不入库）等。

当前 .gitignore 是 Python 侧模板，还没有前端条目；前端工程初始化时应补上 node_modules/、pnpm-lock.yaml 除外（锁文件必须入库）等规则，注意别把 .nvmrc、.python-version 这类固定版本的文件忽略掉。

5. 常见问题

现象处理
把不该提交的文件 add 了git restore --staged 文件名 取消暂存；若已提交但未推送，git commit --amend 修正
提交到 main 了保护分支默认禁止直接推送；万一进了，用 PR 评审流程回退（git revert 保留历史）
终端中文乱码Windows PowerShell 设 [Console]::OutputEncoding = [Text.Encoding]::UTF8；或装新版 Git for Windows 默认 UTF-8
推送要输密码/凭证失效Windows 用 Git Credential Manager（装 Git 时自带）或 SSH key 认证：ssh-keygen 后把公钥加到 GitHub
合并冲突按文件手动取舍后 git add 并继续合并；拿不准的先问涉及该模块的人
换行符警告（CRLF/LF）Windows 上配 git config --global core.autocrlf true，团队统一，避免整个文件被当成改动
误删了文件还没提交的话 git restore 文件名；已提交的从历史里找：git log --oneline -- 文件名
