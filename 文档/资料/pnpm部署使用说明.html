1. 简介与选型理由

pnpm 是 npm 之外常用的 Node 包管理器。它跟 npm/yarn 最大的区别在存储方式：所有包内容存在一个全局 store 里，项目通过硬链接引用，磁盘占用小、装得快。BMS 选它的原因：

  • 省磁盘：两个前端工程（frontend、frontend-mobile）很多依赖是重复的，硬链接后只占一份空间
  • 依赖隔离严格：不会出现「本机装得上、CI 装不上」的幽灵依赖问题，装什么就声明什么
  • workspace 原生支持：一个仓库管多个工程，共享配置包不需要单独发布

本机实测版本：pnpm 11.20.0（2026-08-05），运行于 Node v24.15.0。

2. 安装

Windows / macOS / Linux 都可用 corepack（Node 自带）或 npm 全局安装：

# 方式一：npm 全局安装（最直接）
npm install -g pnpm

# 方式二：corepack 启用（Node 自带，版本由 package.json 的 packageManager 字段固定）
corepack enable pnpm

安装后验证：

pnpm --version

3. 常用命令

3.1 依赖安装

pnpm install          # 按 pnpm-lock.yaml 安装全部 workspace 依赖
pnpm add element-plus      # 给当前工程加依赖
pnpm add -D vitest         # 开发依赖
pnpm remove axios          # 移除依赖
pnpm up                   # 升级依赖

pnpm install 会读取 workspace 根部的 pnpm-lock.yaml，锁文件必须提交到 git，保证每个人和 CI 装出来的依赖一致。

3.2 workspace 与 filter

BMS 仓库根部有 pnpm-workspace.yaml，声明了两个前端工程属于同一个 workspace。之后用 --filter（简写 -F）指定对哪个工程操作：

pnpm -F frontend dev              # 启动 PC 端开发服务器
pnpm -F frontend-mobile dev       # 启动移动端开发服务器
pnpm -F frontend add axios        # 只给 PC 端装依赖
pnpm -F frontend build            # 只构建 PC 端
pnpm --filter frontend --filter frontend-mobile build   # 双端都构建

3.3 日常维护

pnpm store path        # 查看全局 store 位置
pnpm store prune       # 清理不再被引用的缓存内容
pnpm ls                # 查看当前工程依赖树
pnpm why element-plus  # 谁依赖了它、为什么装进来了
pnpm config set registry https://registry.npmmirror.com   # 换国内镜像源

4. 与 BMS 的集成

前端工程阶段一尚未初始化，以下为设计约定，来自《阶段一·项目骨架说明》第 9 节与《项目规划说明》。
事项约定
workspace 纳入双前端根部 pnpm-workspace.yaml 声明 packages: [frontend, frontend-mobile]，一次 pnpm install 装完两个工程
共享基础配置ESLint / Prettier / TS 基础配置做成 workspace 内共享包，两个工程引用同一份规则，不各写各的（源码目录各自独立）
日常开发pnpm --filter frontend dev 起 PC 端；pnpm --filter frontend-mobile dev 起移动端
Node 版本两工程各自有 .nvmrc（≥ 20.19），pnpm 运行在 Node v24.15.0（本机已核）
CI 用法frontend job 步骤为：setup-node（读 .nvmrc）→ pnpm install → eslint → vitest run → 双端 build；pnpm store 缓存以缩短流水线（见《GitHub Actions 部署与使用说明》）
锁文件pnpm-lock.yaml 提交入库；CI 里 pnpm install --frozen-lockfile 检查 lock 与 package.json 是否一致

5. 常见问题

现象处理
装完后项目里找得到文件，但磁盘占用没省硬链接在 Windows 上对跨盘符目录不生效；确认 store 与工程在同一个盘（如都放 D 盘），或看 pnpm store path
某个包「本机能用、CI 报找不到」多半是幽灵依赖：代码用了没声明的包。把该包加进对应工程的 package.json 再 pnpm install
pnpm install 报 lock 文件与 package.json 不一致有人改了依赖没更新锁文件。拉最新代码后 pnpm install 重新生成，或加 --frozen-lockfile 先查差异
store 目录越来越大pnpm store prune 清理；目录位置 Windows 上通常在 %LOCALAPPDATA%\pnpm\store
装包慢pnpm config set registry https://registry.npmmirror.com，或用环境变量 PNPM_REGISTRY；CI 里同理配置
忘了在哪个工程执行命令先看当前目录：命令默认作用于「最近的 package.json 所在工程」；跨工程操作务必带 -F 工程名
