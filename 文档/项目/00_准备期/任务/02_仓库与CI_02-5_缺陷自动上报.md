## 2. 任务内容 <a id="content"></a>

1. 任一自动化测试 job 失败时：先导出测试库场景 dump，再调 `deploy/tools/defect/defect_capture.py` 生成 REPRO 复现包（dump + 日志 + repro.json + REPRO.md）
2. 自动创建/复用 GitLab Issue（`defect-auto` tag）；人工补充复现步骤与定级后指派修复
3. 指派修复走 `ai_fix.py`（本地模型优先、云端兜底，bot 提 MR、人工合并）；`reproduce.py` 一键复现验证

## 3. 完成标准 <a id="accept"></a>

CI 测试失败时自动产出 REPRO 包并建 GitLab Issue，无需人工补建。

## 5. 实施记录（2026-08-22 端到端验证完成）<a id="impl"></a>

接线内容：

| 项 | 结果 |
| --- | --- |
| 失败钩子 | `.gitlab-ci.yml` 的 `defect-capture` job（stage `.post`、`when: on_failure`）：apt 换阿里源装 mariadb-client → 调 `defect_capture.py`（dump 参数经 CI Variables 注入） |
| 归档卷 | runner `config.toml` volumes 增加 `/mnt/data/backup/defects:/mnt/data/backup/defects:rw`，REPRO 包直落宿主备份盘（《测试规范》9 节路径） |
| CI Variables | `GITLAB_API_URL` / `GITLAB_API_TOKEN`(masked) / `MYSQL_ROOT_PASSWORD`(masked)；`CI_PROJECT_ID` 为 CI 自带 |
| 本地干跑 | `ai_fix.py --dry-run` 正常空转；capture/reproduce 依赖 mysqldump 在 PATH，运行环境为 runner 容器 |

受控失败实验（experiment-fail job → 验后 revert）端到端结果：

```text
job 失败 → defect-capture 触发 → mysqldump 导出现场
  → REPRO 包落 /mnt/data/backup/defects/7ef8a3454b8a/
  → 同指纹查询 → 自动创建 Issue #1（defect-auto 标签）✅
```

实测修掉的三个坑（均已入代码）：

1. job 内 apt 走 Debian 官方源出网缓慢——换阿里云镜像源
2. `defect_capture.py` 无 `--pipeline-url` 参数（误传导致 argparse 报错）——并入 summary
3. mariadb 客户端默认 TLS 撞 MySQL 自签证书——`dump_mysql()` 加 `--ssl=0`
