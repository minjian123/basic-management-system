## 2. 任务内容 <a id="content"></a>

1. 后端：ruff check + pytest（SQLite，pytest-cov 覆盖率门禁：核心模块 ≥ 80%、整体 ≥ 70%）
2. 前端：ESLint + Vitest + `frontend` / `frontend-mobile` 双构建
3. MR 合并须流水线通过（main 保护分支强制）

> 口径更新（2026-08-22）：单人开发不设强制人工批准——核心模块（认证/RBAC/工作流/审计/收付款）改动提交前经 AI 交叉评审、MR 描述附评审结论；多人协作时再启用"≥1 名 reviewer 批准"（《开发部署规划》第 7 节）。

## 3. 完成标准 <a id="accept"></a>

含代码改动的 MR 在流水线未通过时被阻止合并。

## 5. 实施记录（2026-08-22 完成）<a id="impl"></a>

| 项 | 结果 |
| --- | --- |
| 门禁设置 | 项目「Pipelines must succeed」开启（API `only_allow_merge_if_pipeline_succeeds=true`） |
| 通过场景实测 | MR !1（.gitlab-ci.yml 落地）流水线 success → 正常合入 |
| 阻断场景实测 | MR !2 故意失败分支 pipeline failed → `ci_must_pass` 合并被阻止 ✅ |

实施要点与后续演进：

- runner 实际注册 tag 为 `bms`（非规划写的 `bms,docker`，新版认证 token 注册不能带 tag 参数）；CI tags 统一对齐为 `[bms]`
- registry.gitlab.com 的 helper 镜像首拉缓慢曾致 job 卡死：预缓存 python:3.14-slim / node:22-slim / gitlab-runner-helper 三镜像，runner `pull_policy = ["if-not-present"]`（详见《GitLab部署使用说明》排障表）
- CI 演进（同日）：doc-smoke/ci-smoke 因 `changes`「任一命中」语义陷阱合并为 **gate-smoke 无条件必跑**；流水线改**指令驱动**——push/MR 不再自动触发，「合并」时经 API 显式发起，main 直推保留自动验证
- 覆盖率门禁（核心 ≥80%/整体 ≥70%）已写入 backend-test job，随阶段一代码与用例自动激活
