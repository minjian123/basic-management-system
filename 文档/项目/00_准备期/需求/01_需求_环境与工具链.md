## 1. 域说明 <a id="intro"></a>

本域对应准备期需求域一「开发服务器环境与工具链就绪」（6 条需求，WBS 01-1 ~ 01-6），覆盖三块：

- **mjbk**（开发服务器，常开）：Ubuntu 基础、Docker 与防火墙、三库 + Redis + MinIO 常驻、备份体系
- **mjpc**（开发机）：uv / Node / VSCode / Git 工具链
- **运维工具链**：仓库内 `scripts/`（WOL 电源控制、bg 后台执行、graphify 知识图谱）

**依据**：《开发部署规划》第 4 节（mjbk 部署）、第 5 节（mjpc 环境）、第 8 节（备份与恢复）。
**目标**：mjpc 上环境可达、工具可用，可进入阶段一骨架开发。

## 2. 需求 01-1：mjbk Ubuntu 基础 <a id="r01-1"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-15

**内容**（《开发部署规划》4.1/4.2）：

1. Ubuntu 24.04.4 LTS 桌面版，静态 IP（内网段 /24），apt 换清华源
2. SSH 免密：mjpc 公钥录入 mjbk
3. 磁盘挂载：机械盘 `/mnt/data`、2T NVMe SSD `/mnt/ssd2t`（ext4 + fstab 自动挂载）
4. Docker data-root 迁至 `/mnt/ssd2t/docker`（镜像/容器/命名卷全落 NVMe）；GitLab 数据落 `/mnt/ssd2t/gitlab`；机械盘只放备份与 Timeshift 快照（数据与备份分盘）
5. Timeshift 系统快照：每日自动，保留 5 份，落 `/mnt/data/timeshift`

**完成标准**：mjpc SSH 免密连通；重启后两块盘自动挂载且 `daemon.json` data-root 生效；Timeshift 可建快照并可回滚。

**参考文档**：《Ubuntu安装部署使用说明》第 7 节、《开发部署规划》4.1/4.2

## 3. 需求 01-2：Docker Engine 与 ufw 防火墙 <a id="r01-2"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-15

**内容**（《开发部署规划》4.1/4.6/9）：

1. Docker Engine 走清华 docker-ce 源安装（docker-ce + buildx + compose 插件），systemd 自启
2. 镜像加速：`/etc/docker/daemon.json` 配置国内 registry-mirrors
3. ufw 防火墙：仅放行内网段服务端口（GitLab 8080/5050/2222、三库 3306/5432/5236、Redis 6379、MinIO 9000/9001、Kiwi 8060 等，完整清单见《开发部署规划》第 9 节），`ufw enable`

**完成标准**：`docker info` / `docker compose version` 通过；mjpc 可连通已放行的内网端口。

**参考文档**：《DockerEngine部署使用说明》、《开发部署规划》4.1/4.6/9

## 4. 需求 01-3：常驻服务（三库 / Redis / MinIO） <a id="r01-3"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-15

**内容**（《开发部署规划》4.3/4.4）：

1. `deploy/compose/base.yml` 拉起第一批容器：redis:8（6379）、mysql:8.4（3306）、postgres:16（5432）、minio（9000/9001 控制台）；达梦 DM8 原生安装（`/opt/dmdbms`，systemd，5236，非容器）
2. 数据落 NVMe 命名卷（`/mnt/ssd2t/docker`）
3. 建 `bms_dev` 库与账号：凭据仅存 `deploy/.env`，不进仓库；慢查询日志开启；字符集 MySQL utf8mb4、PostgreSQL/达梦 UTF8
4. dmPython 驱动与 Python 3.14 兼容性验证（不兼容则整体降 3.13，按规划口径）

**完成标准**：五服务全部 healthy；mjpc 可连通三库、Redis、MinIO。

**参考文档**：《开发部署规划》4.3/4.4、《MySQL部署使用说明》《PostgreSQL部署使用说明》《达梦DM8部署使用说明》《Redis部署使用说明》《MinIO部署使用说明》

> 注：第 4 项驱动兼容性验证按阶段一口径执行（《总体项目规划》第 10 节风险表），本条完成判定以「服务部署与可达」为准。

## 5. 需求 01-4：运维工具链 <a id="r01-4"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-21

**内容**（仓库内 `scripts/` 工具链）：

1. WOL 远程唤醒/关机：`scripts/tools/wol/`（`wake_mjbk.py` 发魔术包并等待 SSH 就绪；`shutdown_mjbk.py` 为破坏性操作，执行前必须确认）；凭据从 `deploy/.env` 读取，不硬编码
2. bg 后台执行器：`scripts/tools/bg/`（bg-run/bg-status/bg-stop），长命令后台化 + 秒级轮询状态，替代同步阻塞
3. graphify 知识图谱：`graphify update/query/path/explain`；更新后跑 `scripts/tools/graphify/localize-graph.py` 收尾汉化

**完成标准**：唤醒/关机实测可用；bg_run/bg_status 往返通过；`graphify query` 返回子图。

**参考文档**：《开发服务器电源控制使用说明》《通用后台执行器部署使用说明》《graphify部署使用说明》

## 6. 需求 01-5：备份体系 <a id="r01-5"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-22T02:37:00Z

**内容**（《开发部署规划》第 8 节）：

1. 三库：cron 每日 02:00 dump 至 `/mnt/data/backup/{mysql,postgres,dameng}/`（达梦用 dmrman），保留 7 天
2. GitLab：容器内 `gitlab-backup` 每日执行，备份落 `/mnt/data/backup/gitlab/`，保留 7 天
3. 平台数据：Kiwi 库随 MySQL 全量 dump；uploads 卷 tar 导出（见需求 03-5）
4. 备份落机械盘 `/mnt/data/backup`，与数据（NVMe）分盘；恢复演练每季度登记一次

**完成标准**：各备份文件按期生成；至少完成一次从备份恢复的验证。

**参考文档**：《开发部署规划》第 8 节
