## 2. 准备期目标与范围 <a id="goal"></a>

**M0 目标**（《总体项目规划》7.1 M0 行）：环境 / 仓库 / CI 就绪，可进入阶段一骨架开发。周期口径 2 周（兼职，T+0 启动）。

**范围内**（共 17 条需求，见第 3 节总清单）：

| 需求域 | 内容 | 禅道任务 |
| --- | --- | --- |
| 一 环境与工具链 | mjbk Ubuntu 基础、Docker 与 ufw、三库 + Redis + MinIO 常驻、运维工具链、备份体系、mjpc 开发机 | 1（子任务 85~90） |
| 二 仓库与 CI | GitLab CE + runner、仓库迁移与分支模型、MR/main 流水线、缺陷自动上报、Renovate 与 GitHub 归档 | 2 |
| 三 测试与项目管理平台 | Kiwi TCMS、禅道、初始化与 WBS 登记、三方平台分工、备份联动 | 3 |

**范围外**：

- 阶段一及以后交付物（monorepo 骨架代码、三库驱动兼容性验证等，见《总体项目规划》第 10 节风险表）
- 预留业务模块（销售 `sale_`、仓储 `wh_`，预留不排期，见《总体项目规划》第 8 节）
- 对外集成、第三方系统对接

> 边界说明：仓库迁移与分支模型属准备期（已完成）；`backend/frontend/frontend-mobile` 工程骨架属阶段一，`.gitlab-ci.yml` 流水线实现随阶段一第一批落地（《开发部署规划》第 10 节口径），需求 02-3/02-4 在 M0 基线中登记为「未开始」。

## 4. M0 验收门禁 <a id="accept"></a>

门禁定义（《总体项目规划》7.1 M0 行）：**环境 / 仓库 / CI 就绪，可进入骨架开发**。逐项核对：

| 验收点 | 核对方式 | 对应需求 | 结论 |
| --- | --- | --- | --- |
| 环境可达 | mjpc SSH 免密到 mjbk；三库 / Redis / MinIO 可连通 | 01-1 ~ 01-3、01-6 | 达标 |
| 工具链可用 | WOL 唤醒/关机实测；bg 往返；graphify query；zentao CLI 往返 | 01-4 | 达标 |
| 平台可用 | 禅道看板 / 甘特可用，M0 任务清单已建；Kiwi TCMS 可用 | 03-1 ~ 03-4 | 达标 |
| 仓库就绪 | bms 仓库在 GitLab；main 保护分支 + MR 流转 | 02-1、02-2 | 达标 |
| CI 就绪 | MR 门禁流水线、main 流水线通过 | 02-3、02-4 | **未达标** |
| 备份就绪 | 三库 / GitLab / 禅道定时备份 + 恢复演练 | 01-5（已完成）、03-5（Kiwi uploads 待补） | 部分达标 |

**结论**：M0 门禁未全部达成。剩余工作 01-5、02-3、02-4、02-5（流水线接线）、03-5；02-6 按风险口径搁置（mjbk 外网不可达，见《开发部署规划》第 11 节）。其中 02-3/02-4 随阶段一第一批（骨架）落地，01-5/03-5 可独立补做。
