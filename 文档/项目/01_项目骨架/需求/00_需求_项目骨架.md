## 2. 项目骨架目标与范围 <a id="goal"></a>

**M1 目标**（《总体项目规划》7.1 M1 行）：本地起服务、CI 通过、/healthz /readyz 正常、三库拓扑可路由、模块注册校验生效。周期口径 3 周（兼职，T+0 = 2026-08-24；M1 基线 2026-09-28，累计 5 周）。

**范围内**（共 15 条需求，见第 3 节总清单）：

| 需求域 | 内容 |
| --- | --- |
| 一 工程骨架 | monorepo 仓库骨架、backend 分层骨架、frontend/frontend-mobile 工程骨架、依赖锁定与 Python 3.14 兼容验证 |
| 二 后端基础能力 | 配置管理、日志体系、健康检查、SQLAlchemy 接入 |
| 三 多租户数据拓扑 | 平台库/租户库拓扑、租户解析与路由、批量迁移工具 |
| 四 模块注册表 | sys_module 注册表种子、注册唯一性校验（启动 + CI） |
| 五 CI 与阶段验收 | CI 流水线激活（含准备期 02-4 收口）、M1 验收与测试报告 |

**范围外**：

- 阶段二及以后交付物（认证与安全、RBAC 权限体系、通用能力等，见《总体项目规划》第 6 节 WBS）
- 业务模块（采购 `pur_`、收付款 `pay_`、供应商 `sup_` 等，随对应阶段排期）
- 前端页面与组件开发（阶段十一）；ElasticSearch 等阶段十四依赖（《开发部署规划》第 4 节两节奏口径）
- 租户开通/停用/配额等租户管理业务功能（阶段三），阶段一仅交付拓扑与迁移基础工具

> 边界说明：`.gitlab-ci.yml` 流水线**框架**（六类 job）已于准备期 02-3/02-4 落地、main 空载通过；阶段一代码落地后流水线随 job 的 exists 条件自动激活（05-1），准备期遗留的 02-4 端到端验证随 05-1 收口。Python 3.14 与核心依赖/dmPython 兼容性由 01-4 首周验证，结论决定后续全部阶段的 Python 版本口径。

## 4. M1 验收门禁 <a id="accept"></a>

门禁定义（《总体项目规划》7.1 M1 行）：**本地起服务、CI 通过、/healthz /readyz 正常、三库拓扑可路由、模块注册校验生效**。逐项核对：

| 验收点 | 核对方式 | 对应需求 | 结论 |
| --- | --- | --- | --- |
| 本地起服务 | backend 可启动（uvicorn，/docs 可访问）；frontend/frontend-mobile `npm run dev` 可访问默认页 | 01-1 ~ 01-4、02-1、02-4 | 待阶段完成核对 |
| CI 通过 | MR 门禁 + main 流水线以阶段一真实代码执行全绿 | 05-1 | 待阶段完成核对 |
| 健康检查正常 | /healthz 存活 200；/readyz 依赖（DB/Redis）正常时 200、依赖停时变不健康 | 02-3 | 待阶段完成核对 |
| 三库拓扑可路由 | MySQL/PostgreSQL/达梦 DM8 驱动连通与迁移通过；租户请求路由到对应租户库 | 01-4、02-4、03-1 ~ 03-3 | 待阶段完成核对 |
| 模块注册校验生效 | 表前缀/错误码段/事件域冲突种子被启动与 CI 拒绝 | 04-1、04-2 | 待阶段完成核对 |

**结论**：阶段一尚未启动（排期自 2026-08-24），门禁待阶段完成时核对。五项验收点均在本阶段 15 条需求内闭环，无跨阶段依赖。
