## 2. 需求 04-1：sys_module 表与种子 <a id="r04-1"></a>

优先级：2（高）　|　禅道 story：59　|　禅道任务：151（父任务 132）　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 模块注册》第 2/3 节、《项目规划说明》23.3/23.4/23.5）：

1. `sys_module` 表（平台库），字段明细：
   | 字段 | 类型 | 约束 | 说明 |
   | --- | --- | --- | --- |
   | id | BIGINT | 主键（雪花 ID） | — |
   | module_key | VARCHAR(32) | uq（(module_key, deleted_at) 复合唯一） | 模块简称，2-6 位全小写英文，与英文名一致（如 `purchase`） |
   | name | VARCHAR(64) | — | 模块中文名（如「采购管理」） |
   | table_prefix | VARCHAR(16) | uq（(table_prefix, deleted_at) 复合唯一） | 形如 `{简称}_`（如 `pur_`）；平台域为 `sys_`/`wf_`/`rpt_`/`ai_` |
   | errcode_segment | SMALLINT | uq（(errcode_segment, deleted_at) 复合唯一） | 两位段号，10 起（10=采购段 10xxxx）；平台域 0 占位（1xxxx~9xxxx 既有段） |
   | event_domain | VARCHAR(32) | uq（(event_domain, deleted_at) 复合唯一） | 事件域，小写，默认与 module_key 一致，多事件域模块预留扩展 |
   | status | SMALLINT | 默认 1 | 1 启用 / 0 规划中（未交付模块登记态，种子状态标记，非运行时开关） |
   | created_at/created_by/updated_at/updated_by/deleted_at/version | 按基类 | — | 审计/软删除/乐观锁 |
   - 多语言模块名附表 `sys_module_i18n`（module_id + locale 联合主键 + name），中文名存主表、英文名入附表（en-US）
2. 初始种子（Alembic 数据迁移或幂等种子脚本，随版本演进）：
   - 平台域固定：`sys`（系统，prefix `sys_`）、`wf`（工作流，`wf_`）、`rpt`（报表，`rpt_`）、`ai`（AI 域，`ai_`）
   - 业务模块规划态（status=0，表未建）：`purchase`（`pur_`，段 10）、`payment`（`pay_`，段 11）、`supplier`（`sup_`，段 12）、`sale`（`sale_`，段 13）、`warehouse`（`wh_`，段 14）——与《项目规划说明》23.4/23.5 登记表逐行一致
3. 注册方式约束：运行时**无写接口**（不提供增删改）；新增模块 = Alembic 迁移 revision（建表 schema 迁移 + 注册种子数据迁移）原子落地，平台库单库执行一次；status 为种子状态标记，租户级模块开关另表 sys_tenant_module（阶段三）
4. 业务码口径：业务码与模块简称一致（sys_business 注册，阶段三）；错误码段与事件命名以 sys_module 登记值为权威

**完成标准**：sys_tenant 同库、同迁移流水线落表（三库迁移通过）；种子查询返回 4 平台域 + 5 业务规划态共 9 行，prefix/段号/事件域与《项目规划说明》23.4/23.5 逐行一致；sys_module_i18n 英文名可查；无任何写接口暴露。

**参考文档**：《架构设计 · 模块注册》第 2/3 节、《项目规划说明》23.3~23.5、《命名规范》第 7 节

## 3. 需求 04-2：注册唯一性校验 <a id="r04-2"></a>

优先级：2（高）　|　禅道 story：60　|　禅道任务：152（父任务 132）　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 模块注册》第 4 节、《项目规划说明》23.3）：

1. 校验规则（对 sys_module 全表）：`table_prefix` / `errcode_segment` / `event_domain` 三要素唯一；格式校验——table_prefix 形如 `{简称}_`、errcode_segment 两位段号（平台域 0、业务模块 10 起）、event_domain 全小写；校验覆盖平台域种子与业务模块（防止业务前缀与平台域冲突）
2. 启动校验：应用启动（lifespan 内，连接平台库后）读取 sys_module 执行校验；冲突或格式非法 → **启动失败**（进程退出非 0）+ CRITICAL 日志报出冲突明细（冲突双方模块与冲突字段）+ 控制台可读错误
3. CI 校验：校验逻辑复用为独立脚本/函数（`scripts/check_module_registry.py` 或等价 pytest 用例），流水线在测试库迁移后执行 SQL 查重（《架构设计 · 模块注册》3.2 口径）；冲突 → job 失败、不允许合并；校验 job 与 05-1 流水线衔接
4. 数据库级兜底：三要素的 (字段, deleted_at) 复合唯一索引为物理兜底（04-1 已建），即使校验被绕过插入也被拒

**完成标准**：构造冲突种子（新模块 table_prefix 与 sys_ 相同）后启动被拒、CRITICAL 日志含冲突双方与字段名；CI 校验 job 对冲突种子失败、对合法种子通过；数据库直接 INSERT 冲突行被唯一索引拒绝。

**参考文档**：《架构设计 · 模块注册》第 4 节、《项目规划说明》23.3、《总体项目规划》7.1、《测试规范》

## 4. 需求 04-3：模块查询接口 <a id="r04-3"></a>

优先级：2（高）　|　禅道 story：61　|　禅道任务：153（父任务 132）　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 模块注册》3.3、《API接口规范》第 2/3 节）：

1. 接口契约：`GET /api/v1/modules`——平台库 sys_module 只读查询，返回注册清单：
   - 响应：`{code: 0, message: "ok", data: {list: [{module_key, name, table_prefix, errcode_segment, event_domain, status}], total}}`；不分页（清单量小），按 module_key 排序
   - 查询参数：`status`（可选，筛选启用/规划中）；软删除过滤（deleted_at IS NULL）
   - 归属平台接口（豁免租户解析，见 03-4 豁免清单）
2. 鉴权口径：阶段一权限体系未落地，接口暂不鉴权（OpenAPI 标注 TODO：阶段三接入 `platform:manage` 权限码）；**无任何写接口**（POST/PUT/DELETE 不存在，404）
3. 实现约束：repository 层查询（走 02-5/03 域底座），响应模型显式声明（不直接返回 ORM 对象）；接口 docstring 完整（进入 OpenAPI 契约）

**完成标准**：`GET /api/v1/modules` 返回 9 条注册记录、字段与响应契约一致；`?status=0` 返回 5 条规划态；POST 该路径返回 404；接口在 /docs 可见且 docstring 完整。

**参考文档**：《架构设计 · 模块注册》3.3、《API接口规范》第 2/3 节、《后端开发规范》第 4/6 节
