## 1. 域说明 <a id="intro"></a>

本域对应项目骨架阶段一域「后端基础能力」（WBS 02），覆盖五块：

- **配置管理**：config.toml 分区与键清单、BMS_ 环境变量覆盖、启动校验
- **日志体系**：structlog JSON、上下文字段、脱敏、请求日志中间件
- **异常与错误码骨架**：BizError 体系、全局异常处理器、基础错误码登记
- **健康检查**：/healthz /readyz 接口契约、依赖检查项、鉴权豁免
- **SQLAlchemy 数据访问底座**：引擎工厂、会话工厂、四库方言、达梦同步驱动接入、读写分离占位

**依据**：《[项目规划说明](../../规划/项目规划说明.md)》3.1/17/19.3、《总体项目规划》第 12 节（配置基线）、《[日志规范](../../规范/日志规范.md)》、《[后端开发规范](../../规范/后端开发规范.md)》第 5/7/8 节、《[API接口规范](../../规范/API接口规范.md)》第 3/4 节、《[架构设计 · 数据访问与分片](../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》。
**目标**：backend 具备可配置、可观测、可探活、可连库的基础能力，支撑 03 域数据拓扑与后续全部模块。

## 2. 需求 02-1：配置管理 <a id="r02-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《项目规划说明》3.1/17、《总体项目规划》第 12 节、《命名规范》第 10 节）：

1. `backend/config.toml` 分区与键清单（小节名按《命名规范》第 10 节，键逐项中文注释）：
   - `[app]`：`name`（BMS 基础管理系统）、`env`（占位，实际由 BMS_ENV 环境变量决定）、`debug`
   - `[server]`：`host`（0.0.0.0）、`port`（8000）、`workers`
   - `[log]`：`level`（dev=DEBUG / prod=INFO）、`format`（json）
   - `[database]`：数据源声明 `platform`（平台库，含 `url`、`pool_size`、`max_overflow`、`pool_recycle`、`pool_pre_ping`）、`tenants`（租户库模板，连接参数同 platform）、`archive`（归档库占位）；每库预留主从结构（`primary`/`replicas`，阶段一主从同源填同一 url）
   - `[redis]`：`url`、`db`
   - `[minio]`：`endpoint`、`bucket`、`access_key`、`secret_key`（阶段一仅占位，文件服务随阶段四）
   - `[security]`：`jwt_secret`、`access_token_ttl`（阶段二启用，占位）
   - `[cors]`：`allowed_origins`（dev 放行前端开发服务器跨域，生产由 nginx 同源反代不开放跨域）
2. 环境分层与环境变量覆盖：`BMS_ENV` 指定 `dev`/`test`/`prod` 环境层（config.toml 按层组织：`[app]` 基础节 + `[env.dev]`/`[env.test]`/`[env.prod]` 覆盖节）；`BMS_` 前缀环境变量（UPPER_SNAKE）映射覆盖配置键（`BMS_DB_URL` → database.platform.url，映射规则：`BMS_` + 路径上划线拼接）；**密钥类配置（DB URL 密码、Redis 密码、JWT secret、MinIO 凭据）只走环境变量，不入配置文件、不入库**
3. 配置加载与校验：`app/core/config.py` 用 pydantic-settings 建模（`Settings` 类），启动时（lifespan 内）加载并校验——必填键缺失、端口/池参数类型错误即启动失败并报出字段名；加载结果以 `app.state.settings` 暴露，业务代码禁止重复读文件
4. 敏感值保护：日志/异常/接口响应任何位置不回显配置值中的密码（脱敏清单见 02-2）

**完成标准**：`BMS_ENV=dev|test|prod` 三环境可切换加载；`BMS_DB_URL` 环境变量注入后覆盖生效（读取值等于注入值）；删除必填键后启动报错并指出字段名；三环境配置差异处（日志级别、CORS）加载结果正确。

**参考文档**：《项目规划说明》3.1/17、《总体项目规划》第 12 节、《命名规范》第 10 节

## 3. 需求 02-2：日志体系 <a id="r02-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《日志规范》全文、《后端开发规范》第 11 节）：

1. structlog 配置（`app/core/logging.py`）：processors 链（时间戳、级别、logger 名、上下文合并、堆栈单行化、JSON 渲染）；输出目标 stdout（容器统一收集，应用不落文件）；级别默认值 dev=DEBUG、prod=INFO（读 02-1 配置）；禁止 print
2. 上下文字段由中间件注入（《日志规范》第 4 节）：`request_id`（进程内请求序号，兜底）、`trace_id`（入站读 `X-Trace-Id` 头、缺失则生成 UUID4，透传到下游调用与日志上下文）、`tenant`（租户上下文，03-4 接入后启用）、`user_id`/`user`（阶段二认证接入后启用）、`client_ip`、`duration_ms`
3. 请求日志中间件：每请求 1-2 条（进入记 INFO 一条、结束记 INFO 一条带 status/duration_ms）；4xx 记 WARNING、5xx 记 ERROR；与全局异常处理器集成——未捕获异常记 ERROR 且堆栈合并单行（换行转义），生产环境响应不回显堆栈
4. 脱敏清单（《日志规范》第 5 节）：密码、access/refresh token、验证码、私钥、完整手机号/身份证等 PII（掩码或省略）；数据库连接串日志隐藏密码；ORM 异常日志禁用 bind params；第三方密钥（MinIO/GitLab/API Key）不回显
5. 慢查询与依赖调用：DB/Redis 调用异常记 error 级（阶段九前以 warning 兜底不告警）；慢查询走三库慢查询日志（开发环境已开启，应用侧不重复实现）

**完成标准**：任意请求后日志输出单行 JSON 且含 request_id/trace_id/client_ip/duration_ms 字段；携带 `X-Trace-Id: abc` 的请求日志 trace_id 为 `abc`；构造未捕获异常后日志 ERROR 行堆栈为单行、HTTP 响应无堆栈；密码/token 在全部日志中不出现明文。

**参考文档**：《日志规范》、《后端开发规范》第 11 节

## 4. 需求 02-3：异常与错误码骨架 <a id="r02-3"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《后端开发规范》第 5 节、《API接口规范》第 3/4 节）：

1. 统一响应模型（`app/schemas/common.py`）：`ApiResponse`（`code`、`message`、`data`，code=0 成功）、`PageResponse`（`list`、`total`、`page`、`size`）；分页参数 `page`（1 起）/`size`（默认 20、上限 200）公共 Schema
2. 异常体系（`app/core/exceptions.py`）：
   - `BizError(code, detail)` 基类（携带错误码与参数）；`services` 层抛业务异常，api 层不 catch 业务异常
   - 全局异常处理器（exception handlers 统一注册于 create_app）：`BizError` → HTTP 200 + `{code, message, data: null}`；`RequestValidationError`（Pydantic 校验失败）→ 422 + 业务码 `10001`；未捕获异常 → HTTP 500 + 业务码 `10002`（系统内部错误，不暴露堆栈）；HTTPException 透传语义（401/403/404 等）
   - HTTP 状态码表示传输层语义，业务失败统一 200 + 业务码
3. 基础错误码登记（1xxxx 通用段，登记于「错误码总表」）：`10001` 参数校验失败、`10002` 系统内部错误、`10003` 资源不存在、`10004` 操作不允许；错误码一经发布不可更改含义，段内序号递增不复用
4. 错误码文案：后端不承担文案拼装，前端按 `error.{code}` i18n 映射；message 字段返回 i18n key 或通用文案

**完成标准**：`raise BizError(10003)` 经任意接口返回 `HTTP 200 + {"code": 10003, "data": null}`；非法请求体返回 422 + code 10001；未捕获异常返回 500 + code 10002 且响应体无堆栈；四个基础错误码在「错误码总表」登记。

**参考文档**：《后端开发规范》第 5 节、《API接口规范》第 3/4 节、《命名规范》第 8 节

## 5. 需求 02-4：健康检查 <a id="r02-4"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《项目规划说明》2.4/3.4/8/19.3、《API接口规范》第 2 节）：

1. `/healthz` 存活探针：`GET /healthz`，进程存活即 `HTTP 200`，响应体 `{"status": "ok"}`；不做任何依赖检查、不触碰 DB/Redis
2. `/readyz` 就绪探针：`GET /readyz`，检查依赖连通性，响应契约：
   - 全部依赖就绪 → `HTTP 200`；任一依赖不可达 → `HTTP 503`
   - 响应体：`{"status": "ok"|"degraded", "checks": {"database": {"ok": true, "latency_ms": 3}, "redis": {"ok": false, "error": "connection refused"}}}`
   - 检查项与方式：`database`（平台库执行 `SELECT 1`）、`redis`（`PING`）、`minio`（阶段一未接入则整体省略该键）；每项超时 2 秒，超时视为不可达
   - 状态明细不暴露连接串、密码与内部错误堆栈（error 字段仅写异常类别）
3. 鉴权豁免：`/healthz`、`/readyz` 不在 Bearer 校验范围（阶段二认证接入时保持豁免，豁免清单与登录/刷新同列）
4. 路由注册：`app/api/health.py` 独立 APIRouter，`create_app` 统一 include；两探针不计限流（阶段二限流排除清单预留）

**完成标准**：本地起服务后 `/healthz`、`/readyz` 均 200 且响应体结构正确；停 Redis 后 `/readyz` 变 503 且 checks.redis.ok=false、`/healthz` 保持 200；停平台库后 `/readyz` 503 且 checks.database.ok=false；响应体无密码/连接串信息。

**参考文档**：《项目规划说明》2.4/3.4/8/19.3、《API接口规范》第 2 节

## 6. 需求 02-5：SQLAlchemy 数据访问底座 <a id="r02-5"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《项目规划说明》3.1/10/11、《后端开发规范》第 7/8 节、《架构设计 · 数据访问与分片》）：

1. 引擎工厂（`app/db/engine.py`）：按数据源配置创建 SQLAlchemy 2.0 引擎；四方言 URL 模板与连接参数：
   - SQLite（开发/测试）：`sqlite+aiosqlite:///…/bms_dev.db`，check_same_thread=false
   - MySQL：`mysql+aiomysql://用户:密码@主机:3306/库?charset=utf8mb4`
   - PostgreSQL：`postgresql+psycopg://…:5432/库`
   - 达梦 DM8：`dm+dmPython://用户:密码@主机:5236/库`
   - 统一连接池参数（pool_size / max_overflow / pool_recycle / pool_pre_ping 来自 config.toml）；字符集 MySQL utf8mb4、PostgreSQL/达梦 UTF8
2. **达梦同步驱动接入（先修订口径再实现）**：dmPython 为官方同步驱动，不满足 SQLAlchemy 2.0 异步 engine 要求，与《后端开发规范》第 8 节「禁止在请求路径用同步 DB 驱动」及架构 09「多异步 bind」存在口径缺口——实现前**先修订《架构设计 09》节点与《后端开发规范》第 8 节**，明确达梦数据源采用「同步 engine + `asyncio.to_thread` 执行器封装」的例外口径（session 生命周期与其他异步会话一致、不在事件循环内同步阻塞）；修订确认后按该口径实现
3. 会话工厂（`app/db/session.py`）：`async_sessionmaker`（expire_on_commit=False）；`get_db` FastAPI 依赖（请求级会话，请求结束归还）；异步会话**禁止跨请求共享**；事务边界在 services 层 `with session.begin()` 显式声明
4. Base 与元数据：`app/models/base.py` 定义 `Base`（DeclarativeBase）与 `BaseModel` 基类（字段细节在 03-2）；元数据命名约定：表名单数 snake_case、`idx_`/`uq_` 索引前缀、每表必备 COMMENT
5. 读写分离占位：`app/db/` 提供读写路由接口（按请求上下文读写标记选引擎），阶段一主从同源（primary 与 replicas 同一 url），路由逻辑与接口签名按架构 09 预留
6. 查询基线约束（《后端开发规范》第 7 节）：禁止 SELECT *；批量写入 bulk；禁止循环内逐条写；ORM 层禁用方言特有功能（JSON 等类型用跨方言通用类型，分页统一 limit/offset）

**完成标准**：SQLite 平台库建库 + 基类模型自动建表 + CRUD 冒烟通过；MySQL/PostgreSQL 异步引擎各连通一次（SELECT 1）；达梦按修订后口径连通（dmPython SELECT 1）；读写路由占位接口在主从同源下读写可用；达梦口径修订已落入《架构设计 09》与《后端开发规范》第 8 节。

**参考文档**：《项目规划说明》3.1/10/11、《后端开发规范》第 7/8 节、《架构设计 · 数据访问与分片》、《数据库开发规范》第 6 节
