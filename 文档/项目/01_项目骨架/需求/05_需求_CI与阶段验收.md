## 2. 需求 05-1：CI 流水线激活 <a id="r05-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《总体项目规划》13 节（2026-08-23 分层口径）、《开发部署规划》第 10 节、准备期需求 02-3/02-4）：

1. 激活口径（单人开发期，直推 main 不走 MR）：`.gitlab-ci.yml` 既有 job 以 `exists` 守卫，阶段一代码目录落地后自动激活——`backend/` 存在即跑 Python 系 job、`frontend/` 存在即跑前端系 job；纯文档推送继续免 CI
2. main 冒烟层（含代码改动 main 直推自动执行）：`gate-smoke` + `ruff check` + `pyright` + `pytest`（SQLite）+ `ESLint` + `Vitest` + `frontend/frontend-mobile` 双构建；任一步失败 pipeline 红
3. 重验证层（仅 main 运行）：Playwright E2E（服务容器起 backend（SQLite）与前端产物，骨架期覆盖：三工程可达、健康检查探针、模块查询接口）、三库方言集成测试（详情 05-2）、镜像构建推 Registry（`bms-backend`/`bms-frontend`）、Trivy 镜像扫描（CVSS ≥ 9 阻断；mjbk 外网不可达暂缓，不阻塞其余 job）、swagger.json 契约快照导出归档、Allure 报告归档并导入 Kiwi TCMS
4. 覆盖率门禁：`pytest-cov` 报告接入（核心模块 ≥ 80% / 整体 ≥ 70% 为后续阶段达标线）；骨架阶段先落地门禁机制（阈值与模块清单写入 `.gitlab-ci.yml` 或 pytest 配置，骨架期整体阈值暂按 70% 起步并注明随阶段递增口径）
5. 02-4 收口衔接（执行详情在 05-2）：重验证层以真实数据跑通后，回写准备期文档

**完成标准**：含代码改动的 main 推送自动跑冒烟层且全绿；重验证层六类 job 全绿（Trivy 因外网暂缓项除外，按暂缓口径标注）；覆盖率报告产出且低于阈值时 pipeline 红；纯文档推送不触发 CI。

**参考文档**：《总体项目规划》13 节、《开发部署规划》第 10 节、《测试规范》第 8 节、《架构设计 · 测试与质量》、[准备期需求 02-3/02-4](../../00_准备期/需求/02_需求_仓库与CI.md#r02-4)

## 3. 需求 05-2：三库集成测试与 02-4 收口 <a id="r05-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 测试与质量》第 2 节、准备期需求 02-4、《数据库开发规范》第 5 节）：

1. 三库集成测试 job 流程：job 连接 mjbk 常驻 MySQL/PostgreSQL/达梦 DM8，各建 `bms_test` 前缀独立测试库 → Alembic 三套方言迁移 → 集成测试执行 → 删库清理（失败也清理，留 REPRO 走准备期 02-5 缺陷链路）
2. 集成测试用例清单（pytest 标记 `integration`，本阶段至少覆盖）：
   - 三库迁移建表（sys_tenant + sys_module 表就位、字段/索引与需求一致）
   - 基类行为：审计字段自动填充、软删除复合唯一索引、乐观锁冲突（03-2 验收项的三库版）
   - 拓扑路由：demo 租户请求读写落在对应租户库、平台请求落平台库、跨租户数据不可见
   - 模块注册：种子 9 行一致、冲突种子被启动校验拒绝
   - 健康检查：readyz 依赖状态明细（以测试库为 database 依赖）
3. 02-4 端到端验证收口（准备期遗留）：E2E、三库集成、镜像构建推 Registry、契约快照、Allure 导入 Kiwi TCMS 以阶段一真实数据全部跑通后——回写准备期文档：`02-4` 状态改「已完成」、完成日期补记、准备期计划「剩余任务排期」清空该行
4. 测试库命名与清理：`bms_test` 前缀（如 `bms_test_platform`/`bms_test_tenant_demo`），清理删库不留残留；达梦复用 mjbk 常驻实例（schema `bms_test` 口径）

**完成标准**：三库集成 job 全绿（三库各自通过）；02-4 在准备期文档完成状态与日期回写；测试库无残留；任一库失败时 REPRO 复现包自动生成（02-5 缺陷链路实测一次）。

**参考文档**：《架构设计 · 测试与质量》第 2 节、《数据库开发规范》第 5 节、《测试规范》第 9 节、[准备期需求 02-4](../../00_准备期/需求/02_需求_仓库与CI.md#r02-4)
