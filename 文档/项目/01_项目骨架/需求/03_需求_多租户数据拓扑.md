## 1. 域说明 <a id="intro"></a>

本域对应禅道 M1 迭代父任务「03 多租户数据拓扑」（待建），覆盖六块：

- **三库拓扑与建库**：bms_platform / bms_tenant_{code} / bms_archive 库模型与建库标准
- **模型基类与表规范**：雪花 ID / 软删除 / 审计字段 / 乐观锁 / 四库类型映射
- **平台库基础表**：sys_tenant 字段与索引、demo 租户种子
- **租户解析中间件**：解析链、TenantContext、豁免路径、未知租户拒绝
- **引擎注册表与池管理**：懒加载、LRU 回收、连接预算、创建加锁
- **批量迁移与租户库初始化**：Alembic 三套方言、批量脚本、建库→迁移→种子

**依据**：《[项目规划说明](../../规划/项目规划说明.md)》第 6/10/11 节、《[架构设计 · 数据架构](../../设计/架构设计/05_架构设计_数据架构.md)》、《[架构设计 · 多租户路由](../../设计/架构设计/08_架构设计_子系统_多租户路由.md)》、《[架构设计 · 数据访问与分片](../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》、《[命名规范](../../规范/命名规范.md)》第 7 节、《[数据库开发规范](../../规范/数据库开发规范.md)》第 2/5/7 节。
**目标**：多租户独立库拓扑落地、租户请求可路由、三库方言迁移可用——M1 验收点「三库拓扑可路由」的直接承载。

## 2. 需求 03-1：三库拓扑与建库 <a id="r03-1"></a>

优先级：2（高）　|　禅道 story：—　|　禅道任务：—　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 数据架构》第 2 节、《命名规范》第 7 节）：

1. 三库模型与职责：平台库 `bms_platform`（租户注册、平台超管、平台统一菜单/权限码，阶段一仅 sys_tenant 与 sys_module）；租户库 `bms_tenant_{code}`（一租户一库，该租户全部业务数据，code 为租户编码全小写）；归档库 `bms_archive`（各租户归档数据统一收存，带 tenant_id 与原库表标识，只读，阶段四起用——阶段一仅登记命名与连接配置占位，不建业务表）
2. 开发环境库模拟：本地开发/测试用**多个 SQLite 文件**模拟（`bms_platform.db`、`bms_tenant_demo.db`、`bms_archive.db` 放 `backend/tests/` 或 dev 数据目录），一文件一库；环境库命名 `bms_dev`/`bms_test`/`bms_prod`（多环境实例名，与三库模型区分）
3. 建库标准：字符集 MySQL utf8mb4、PostgreSQL UTF8、达梦 UTF8；达梦注意 schema 前缀（开发实例 `bms_dev`，查询/迁移引用时统一小写标识符口径）；SQLite 开发库自动建表（`Base.metadata.create_all`，不依赖迁移脚本）
4. 跨库引用原则：一律逻辑外键（code），不建物理外键；跨库查询禁止 JOIN（服务层聚合或事件同步）

**完成标准**：三库在 SQLite 模拟下建库成功、互不串库；MySQL/PostgreSQL/达梦三实例上 `bms_platform` 与示例 `bms_tenant_demo` 建库成功且字符集符合标准；跨库引用无物理外键。

**参考文档**：《架构设计 · 数据架构》第 2 节、《命名规范》第 7 节、《数据库开发规范》第 7 节

## 3. 需求 03-2：模型基类与表规范 <a id="r03-2"></a>

优先级：2（高）　|　禅道 story：—　|　禅道任务：—　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 数据架构》第 4 节、《数据库开发规范》第 2/3 节）：

1. `app/models/base.py` 的 `BaseModel` 字段（每表必备，ORM 层定义一次）：
   - 主键 `id`：雪花 ID（yitter/IdGenerator，BIGINT 跨库类型），生成器封装于 `app/core/id.py`（`generate_id()`）
   - 审计：`created_at`（DATETIME/TIMESTAMP）、`created_by`、`updated_at`、`updated_by`——由 ORM 事件自动填充（insert/update 监听），业务代码禁止手动赋值
   - 软删除：`deleted_at`（DATETIME，NULL=未删）；乐观锁：`version`（INT，更新时比对，冲突返回明确错误码）
2. 四库类型映射表（基类字段跨方言实现，写入模型定义注释）：
   | 字段 | SQLite | MySQL | PostgreSQL | 达梦 DM8 |
   | --- | --- | --- | --- | --- |
   | id | INTEGER | BIGINT | BIGINT | BIGINT（自增列口径，雪花值写入） |
   | created_at 等 | DATETIME | DATETIME | TIMESTAMP | TIMESTAMP |
   | version | INTEGER | INT | INTEGER | INT |
   | 布尔（通用约定） | INTEGER 0/1 | TINYINT(1) | SMALLINT | SMALLINT（达梦无 BOOLEAN 时口径） |
   - 时间统一 UTC 存储（应用侧 UTC 写入），前端本地时区展示；金额 NUMERIC(20,4)、字符串 VARCHAR（长度显式）、禁用方言专用类型（JSON/ENUM/SERIAL）
3. 软删除机制：查询默认过滤 `deleted_at IS NULL`（repository 基类统一注入，禁止业务层手写过滤）；唯一约束统一建为 `(唯一字段, deleted_at)` 复合唯一索引——未删行 deleted_at 为 NULL，四库均允许多个 NULL 不冲突（**达梦按 Oracle 兼容口径，阶段一实测验证**）；删除时写入时间戳即释放唯一键、恢复即清 NULL；PostgreSQL 另加部分唯一索引优化（可选）
4. 索引规范：排序字段、外键（逻辑外键列）、数据权限过滤字段必须建索引；命名 `idx_字段`/`uq_字段`；每表索引不超过 5 个
5. 表级规范：表名单数 snake_case；表前缀平台域 sys_/wf_/rpt_/ai_ 与业务模块 {简称}_（注册制）；每表与字段 COMMENT（中文）必填

**完成标准**：基于 BaseModel 的示例模型（sys_tenant 复用验证）在四库均能建表（SQLite 自动建表 + 三库迁移）；审计字段插入/更新自动填充实测通过；同表同值两行未删记录插入被 (唯一字段, deleted_at) 索引拒绝、软删除后再插入同值成功（达梦实测）；乐观锁版本冲突返回明确错误码。

**参考文档**：《架构设计 · 数据架构》第 4 节、《数据库开发规范》第 2/3/4 节、《命名规范》第 7 节、《项目规划说明》第 6/11 节

**完成标准**：sys_tenant 三库迁移通过；demo 种子落库后可查询；(code, deleted_at) 复合唯一索引生效（重复 code 插入被拒）；其余平台表未建（范围外不交付）。

## 5. 需求 03-4：租户解析中间件 <a id="r03-4"></a>

优先级：2（高）　|　禅道 story：—　|　禅道任务：—　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 多租户路由》第 2 节、《项目规划说明》17 节）：

1. 解析链（按优先级取第一个命中）：
   - 生产：子域名 `{tenant}.bms.example.com` → 查平台库 `sys_tenant.domain`（命中 Redis 短 TTL 缓存），解析出 tenant_code
   - 一人多租户切换：请求头 `X-Tenant-ID`（租户 code，切换后重发 token，阶段二接入）
   - 开发兜底：access token 内 tenant_id（阶段二接入；阶段一无认证，dev 环境以 `X-Tenant-ID` 头 + 默认 demo 租户兜底）
2. `TenantContext`（`app/core/tenant.py`）：解析结果构造（tenant_code、db_key、引擎引用），经 FastAPI 依赖注入传入 services/repositories；**禁止全局单例持有租户引擎/上下文**（并发隔离）
3. 中间件行为：识别失败或未知租户（sys_tenant 无记录/停用）→ 直接拒绝，返回 `HTTP 404 + 业务码 80001`（AppId 无效段，8xxxx 租户段，登记「错误码总表」）；租户上下文注入日志 `tenant` 字段（02-2 联动）
4. 豁免路径清单（不解析租户、直接放行）：`/`、`/docs`、`/openapi.json`、`/healthz`、`/readyz`；平台级接口（后续 `/api/v1/platform/*` 形态）预留豁免位
5. dev/test 环境口径：无认证阶段，`X-Tenant-ID` 头指定租户、缺省取 demo；prod 环境 token 缺席即 401（阶段二前 prod 未启用，行为占位不生效）

**完成标准**：`X-Tenant-ID: demo` 请求日志 tenant 字段为 `demo`，数据读写落在 `bms_tenant_demo` 库（SQLite 模拟实测）；未知租户 `X-Tenant-ID: ghost` 返回 404 + 80001；豁免路径（/docs、/healthz）不受租户校验影响；并发请求下 TenantContext 互不串扰（pytest 并发用例）。

**参考文档**：《架构设计 · 多租户路由》第 2 节、《项目规划说明》17 节、《API接口规范》第 4 节

## 6. 需求 03-5：引擎注册表与池管理 <a id="r03-5"></a>

优先级：2（高）　|　禅道 story：—　|　禅道任务：—　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 多租户路由》第 3 节、《架构设计 · 数据访问与分片》第 2 节）：

1. `EngineRegistry`（`app/db/registry.py`）：注册表 `{db_key → engine}`；**平台引擎常驻**（bms_platform 启动即建）；**租户引擎懒加载**（首次访问创建，连接参数来自 config.toml 数据源声明）；`get_engine(db_key)` 同步接口（进程内锁保护创建段）
2. 闲置回收：LRU + 最后使用时间——超过闲置阈值（默认 30 分钟，config.toml 可配）的租户引擎 `dispose()` 回收；停用租户强制回收；活跃租户引擎数上限（默认 32，config.toml 可配）超出时按 LRU 淘汰
3. 连接预算：总连接 = worker 数 × (pool_size + max_overflow) ≤ 数据库 max_connections 的 70%（预留其他客户端）；参数在 config.toml 数据源声明中显式可配，启动校验预算不超限（超限启动告警日志）
4. 并发保护：引擎创建加锁（进程内锁 + Redis SETNX 分布式锁，防多实例同时为同一租户建引擎）；创建失败快速失败并记 ERROR 告警（阶段九前 warning 兜底）
5. 与 02-5 衔接：EngineRegistry 管理 02-5 工厂产出的引擎（含达梦同步引擎）；TenantContext 持引擎引用而非全局查找

**完成标准**：demo 租户引擎首次请求才创建（懒加载实测：启动后仅平台引擎存在）；闲置阈值调短（如 5s）后租户引擎自动回收；活跃上限调小后超出按 LRU 淘汰；并发 20 请求仅创建 1 个租户引擎（加锁防重）；连接预算超限时启动输出告警日志。

**参考文档**：《架构设计 · 多租户路由》第 3 节、《架构设计 · 数据访问与分片》第 2 节、《项目规划说明》第 10 节

## 7. 需求 03-6：批量迁移与租户库初始化 <a id="r03-6"></a>

优先级：2（高）　|　禅道 story：—　|　禅道任务：—　|　状态：未开始　|　完成日期：—

**内容**（《架构设计 · 数据架构》第 6 节、《数据库开发规范》第 5 节、《架构设计 · 多租户路由》第 4 节）：

1. Alembic 结构（`backend/alembic/`）：`env.py` 按数据源读 URL（config.toml）、区分平台库/租户库迁移上下文；`versions/` 三套方言迁移脚本（MySQL / PostgreSQL / 达梦 DM8，不写方言 SQL、达梦注意 schema 前缀）；SQLite 开发库自动建表不依赖迁移脚本
2. 批量迁移脚本 `scripts/migrate_tenants.py`（运维工具，仓库内 scripts/）：
   - 参数：`--target all|tenant_code|platform`、`--db mysql|postgres|dameng`、`--dry-run`（只打印将执行的库清单）
   - 行为：遍历 `sys_tenant`（按 db_key 匹配数据源）逐库执行迁移；逐库记录执行结果；**失败不中断后续库**，输出汇总清单（成功/失败/跳过），失败库重跑幂等（Alembic 版本表天然幂等）
3. 新租户初始化脚本 `scripts/init_tenant.py`：`建库 bms_tenant_{code}（不存在时）→ 三套迁移（按目标库方言）→ 幂等种子`；种子机制 `backend/alembic/seeds/` 或 `scripts/seeds/`（幂等、可重复执行，与结构迁移分离）；阶段一种子仅空租户基线（demo 验证用），租户开通完整种子（三类内置管理员角色等）属阶段三
4. 迁移验证矩阵：MySQL/PostgreSQL/达梦三库各跑一遍「迁移 → 建表检查 → 回滚/再迁移」；CI 三库测试流程（bms_test 前缀建库 → 迁移 → 测试 → 清理）与 05-2 衔接

**完成标准**：迁移脚本在三库各执行通过（sys_tenant + sys_module 表就位）；`migrate_tenants.py --dry-run` 输出正确库清单、实际执行后 demo 租户库 schema 与平台库一致；`init_tenant.py` 新租户（如 `t1`）建库→迁移→种子一次跑通且重跑幂等无报错。

**参考文档**：《架构设计 · 数据架构》第 6 节、《数据库开发规范》第 5 节、《架构设计 · 多租户路由》第 4 节、《项目规划说明》3.1
