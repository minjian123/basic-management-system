## 4. 需求 01-3：backend 分层目录与职责 <a id="r01-3"></a>

优先级：2（高）　|　禅道 story：44　|　禅道任务：136（父任务 129）　|　状态：未开始　|　完成日期：—

**内容**（《项目规划说明》第 4 节、《后端开发规范》第 2/4 节）：

1. `backend/app/` 分层目录与首版文件（`__init__.py` 均带中文模块 docstring）：
   - `core/`：`config.py`（配置加载，02-1）、`security.py`（安全占位）、`exceptions.py`（异常体系，02-3）
   - `api/`：`deps.py`（公共依赖 `get_db` 等）、`router.py`（聚合注册）、`health.py`（健康检查，02-4）；模块目录 `api/{模块}/` 随模块按单数名词建
   - `models/`：`base.py`（BaseModel 基类，03-2）、模块文件 `{模块}.py`
   - `schemas/`：`common.py`（统一响应模型 ApiResponse/PageResponse，02-3）
   - `services/`：模块服务 `{模块}_service.py`（XxxService 类）
   - `repositories/`：模块仓库 `{模块}_repository.py`（XxxRepository 类，数据源路由，03 域）
   - `db/`：`engine.py`（引擎工厂）、`session.py`（会话工厂与 get_db，02-5）
   - `tasks/`（Celery 任务占位）、`ws/`（Socket.IO 占位）、`i18n/`（语言包占位）——目录与占位文件就位，实现随对应阶段
   - `alembic/`（03-6）、`tests/`（与 app 同构：tests/api/、tests/services/ 等）
2. 分层调用规则（在每层 `__init__.py` docstring 中写明）：
   - api 层只做参数校验与路由分发，依赖注入（`db: AsyncSession`、`redis: Redis`），**禁止直接操作模型、禁止写业务逻辑**
   - services 层承载业务逻辑与事务边界（`with session.begin()`），**禁止直接拼 SQL、禁止绕过 repositories**
   - repositories 层承载数据访问与数据源/分片路由，**禁止承载业务规则**
   - models/schemas 只放 ORM/Pydantic 模型，**禁止写业务逻辑**
3. 路由注册约定：模块内 `APIRouter(prefix="/{资源}", tags=["{模块}"])`，`app/api/router.py` 统一 include；模块四件套 models + schemas + services + repositories（+ api 路由）缺一不可

**完成标准**：目录树与上述清单逐项一致；各层 `__init__.py` docstring 写明职责与禁止项；新建一个示例模块 `sys`（占位 CRUD 空壳）按四件套 + 路由注册走通，证明分层与注册机制可用。

**参考文档**：《项目规划说明》第 4 节、《后端开发规范》第 2/4 节、《命名规范》第 3/6 节
