1. 目标与范围

阶段一落地一个可运行、可测试、可交付的工程骨架，为后续 13 个阶段提供稳定基座。 本文档是阶段一的实施依据，与《项目规划说明》配套：规划定方向，本文档定本阶段细节。

本阶段范围：

  • monorepo 初始化：backend / frontend / frontend-mobile / deploy / scripts / .github
  • 配置体系：config.toml 按环境分层 + 环境变量覆盖（pydantic-settings 实现）
  • 日志体系：structlog 结构化日志 + request_id 链路贯穿
  • 健康检查：/healthz（存活）、/readyz（依赖就绪）
  • SQLAlchemy 2.0 异步接入：多数据源引擎工厂、AsyncSession、平台库/租户库拓扑与租户解析、模型基类（雪花 ID/审计/软删/乐观锁）
  • Redis 接入（redis.asyncio），/readyz 纳入连通性检查
  • Alembic 双套迁移环境 + 批量迁移工具框架 + SQLite 开发库自动建表
  • 前端双工程完整初始化（pnpm workspace），不写业务页面
  • CI 流水线（GitHub Actions）：后端 ruff + pytest + 双库集成测试，前端 lint + Vitest + 双端构建

不在本阶段：认证与权限（阶段二/三）、任何业务模块（阶段四起）。

2. 完成标准与验收

#完成标准（来自规划）验证方式
1本地起服务uv run uvicorn app.main:app 启动；两个前端 pnpm dev 可访问
2/healthz /readyz 正常curl 返回 200；/readyz 在 Redis 停止时返回 503，恢复后自动转 200
3双库拓扑可路由平台库与租户库各建一张验证表，按租户上下文写入/读取成功（集成测试覆盖）
4CI 通过PR 触发：ruff、pytest（SQLite 单测）、MySQL/PostgreSQL 服务容器集成测试、前端 lint + Vitest + 双端构建全部绿
5配置/日志可用BMS_ENV 切换环境生效；环境变量覆盖生效；请求日志含 request_id 且为 JSON 格式
6迁移工具可用Alembic 可对平台库/租户库分别升级；批量迁移脚本遍历已注册租户
本阶段验收通过后，阶段二（认证与安全）方可启动。

4. 配置设计

采用 pydantic-settings 实现「config.toml 按环境分层 + 环境变量覆盖」，加载顺序（后者覆盖前者）：

  1. config.toml 公共段（[app]、[database]、[redis] 等）
  2. config.toml 环境段（[env.dev] / [env.test] / [env.prod]），由 BMS_ENV 指定选哪个
  3. 环境变量 BMS_*（最高优先级，敏感项必须走环境变量，不落配置文件）

config.toml 结构示例（TOML 支持 # 注释，配置必须带注释说明，见下）：

# ==================== BMS 配置文件 ====================
# 加载顺序（后者覆盖前者）：
#   1. 本文件公共段（[app] [log] [database] [redis] 等）
#   2. 环境段（[env.dev] / [env.test] / [env.prod]），由 BMS_ENV 指定选哪个
#   3. 环境变量 BMS_*（最高优先级；密钥类只走环境变量，不写入本文件）

[app]
env = "dev"                # 运行环境：dev / test / prod（BMS_ENV 可覆盖）
debug = true               # 调试模式：开启后输出详细错误、开启 Swagger 文档；生产必须 false

[log]
level = "INFO"             # 日志级别：DEBUG / INFO / WARNING / ERROR

[database]
# 平台库连接串（生产必填环境变量 BMS_DATABASE_PLATFORM_URL 覆盖）
# SQLite（开发/测试）：sqlite+aiosqlite:///./data/platform.db
# MySQL 8.x（生产）：  mysql+aiomysql://bms:密码@主机:3306/bms_platform
# PostgreSQL 16+（生产）：postgresql+psycopg://bms:密码@主机:5432/bms_platform
platform_url = "sqlite+aiosqlite:///./data/platform.db"

# 租户库连接串模板：{code} 占位符在运行时替换为租户编码，一租户一库
# 例：sqlite+aiosqlite:///./data/tenant_{code}.db（开发）
#    mysql+aiomysql://bms:密码@主机:3306/bms_tenant_{code}（生产）
tenant_url_template = "sqlite+aiosqlite:///./data/tenant_{code}.db"

pool_size = 5              # 每个数据源连接池大小（多 worker 部署时按规划公式核算总量）
max_overflow = 10          # 连接池上限之外的额外连接数
echo = false               # 是否打印 SQL 日志（仅调试用，生产保持 false）

[redis]
url = "redis://localhost:6379/0"   # Redis 连接串（生产用 BMS_REDIS_URL 覆盖）
timeout = 0.5              # 单次操作超时（秒），Redis 故障快速失败，避免拖垮请求

[env.test]
debug = false              # 测试环境覆盖项

[env.prod]
debug = false              # 生产环境覆盖项（密钥一律走环境变量）

环境变量约定（全部 BMS_ 前缀，UPPER_SNAKE）：

变量说明示例
BMS_ENV环境（dev/test/prod）dev
BMS_DATABASE_PLATFORM_URL平台库连接串（生产必填）mysql+aiomysql://bms:xxx@host:3306/bms_platform
BMS_REDIS_URLRedis 连接串redis://host:6379/0
BMS_LOG_LEVEL日志级别INFO
密钥类（DB 密码、Redis 密码、后续的 JWT secret/MinIO 凭据）一律只走环境变量，config.toml 不存；.env.example 只给变量名与占位值。

5. 日志设计

  • structlog 结构化日志：生产输出 JSON（一行一条，Loki 可直接聚合），dev 环境输出可读控制台格式
  • request_id：请求进入时生成（或沿用客户端 X-Request-ID），存入 contextvars，贯穿请求全链路；异常响应同样携带
  • 与标准 logging 集成：第三方库（uvicorn、SQLAlchemy 等）日志汇入同一管线，统一字段注入
  • 公共字段：timestamp、level、logger、request_id、env；请求日志含 method、path、status、cost_ms
  • 敏感字段（密码、token、密钥）一律脱敏，不落原始值（与认证与安全节一致）

日志 JSON 示例：

{"timestamp":"2026-08-05T10:00:00Z","level":"info","logger":"bms.api","request_id":"9f8e2c1a","method":"GET","path":"/healthz","status":200,"cost_ms":3,"env":"dev"}

6. 健康检查

端点语义行为
GET /healthz存活探针进程活着即 200，不检查依赖（供容器重启判断）
GET /readyz就绪探针检查平台库 DB 连通（SELECT 1）与 Redis PING；全部通过 200，任一失败 503（供滚动发布与流量摘除）
/readyz 每次实时探测（DB/Redis 操作短超时快速失败，Redis 500ms），不做缓存，保证编排系统判断准确。

7. 数据库接入

7.1 库拓扑

库命名阶段一实现
平台库bms_platformSQLite 文件 backend/data/platform.db（生产 MySQL/PostgreSQL）
租户库bms_tenant_{code}SQLite 文件 backend/data/tenant_{code}.db，URL 由模板生成
归档库bms_archive仅预留配置位，阶段四启用

租户库连接串由 tenant_url_template 模板生成；阶段三引入 sys_tenant.db_key 后改为按注册表路由（本阶段用模板，机制预留）。

7.2 异步引擎工厂

  • EngineRegistry：按数据源 key 懒加载 AsyncEngine（首次访问创建，字典缓存），避免全量租户连接常驻
  • 连接池：pool_size / max_overflow 从配置读取；多 worker 部署时按 总连接数 = worker × (pool_size + max_overflow) ≤ DB max_connections 70% 规划（见规划"部署规模与连接规划"）
  • 闲置回收：engine 空闲超过阈值自动 dispose，释放连接
  • 阶段一实现 get_platform_engine() 与 get_tenant_engine(tenant_code) 两个入口，读写分离留待阶段八

7.3 会话与请求上下文

  • AsyncSessionFactory：每次请求创建独立会话，请求结束关闭；异步会话禁止跨请求共享
  • 请求上下文（contextvars）：request_id、tenant_code、tenant_id（user_id 阶段二加入）；中间件写入，repositories 路由读取
  • 依赖注入：get_db() 依赖按当前租户上下文返回对应库的会话
  • 事务边界：FastAPI 依赖粒度事务（请求内显式 commit/rollback），大事务显式声明边界

7.4 租户解析

解析顺序（优先级从高到低，阶段一实现前两级，token 兜底阶段二加入）：

  1. X-Tenant-ID 请求头：一人多租户切换时前端携带（最终与 token 内 tenant_id 校验一致）
  2. 子域名：{tenant}.bms.example.com（生产），dev 环境不启用
  3. access token 内 tenant_id（阶段二认证接入后启用）

解析失败或租户未注册时返回明确错误码（租户相关错误归 8xxxx 段）；平台级请求（如租户开通）不经过租户解析。

7.5 模型基类

db/base.py 提供四类混入与统一基类，后续所有模型继承：

混入字段说明
SnowflakeIdMixinid雪花 ID 主键（yitter/IdGenerator），Python 侧生成，时钟回拨按配置处理
AuditMixincreated_at / created_by / updated_at / updated_byORM 事件自动填充；UTC 存储
SoftDeleteMixindeleted_at软删除；查询默认过滤；唯一约束按 (唯一字段, deleted_at) 复合索引（三库兼容）
OptimisticLockMixinversion乐观锁，更新时比对

阶段一以验证表（平台库 sys_migration_probe 一类）验证基类与路由链路，业务表阶段二起按模块建立。

8. 迁移工具

  • 双套 Alembic 环境：alembic_platform.ini（平台库）+ alembic_tenant.ini（租户库），迁移脚本分目录存放（app/migrations/platform/ 与 app/migrations/tenant/），互不干扰
  • SQLite 开发库自动建表：开发/测试环境启动时经 Base.metadata.create_all 建表，不维护 SQLite 迁移脚本（规划约定）；MySQL/PostgreSQL 必须走 Alembic 迁移
  • 批量迁移工具 scripts/migrate_tenants.py：读取平台库 sys_tenant 注册表，逐个租户库执行升级（阶段三有 sys_tenant 表后完整启用；阶段一实现框架与单租户演练路径）
  • MySQL / PostgreSQL 方言差异：迁移脚本分方言验证（CI 集成测试覆盖双库）

9. 前端工程骨架

  • pnpm workspace：pnpm-workspace.yaml 纳入 frontend 与 frontend-mobile，共享 ESLint/Prettier/TS 基础配置包，源码各自独立
  • frontend（PC）：Vite + Vue 3 + TypeScript + Element Plus（按需引入）+ vue-router + pinia + axios（封装骨架）+ vue-i18n 占位；src 按 api/router/stores/views/layouts/components/i18n/utils 分层；阶段一只提供「健康检查」演示页与主布局占位，不写业务页面
  • frontend-mobile（H5）：Vite + Vue 3 + TypeScript + Vant，目录分层同 PC
  • .nvmrc 固定 Node ≥ 20.19；vitest 空跑通过；ESLint + Prettier 配置完成
  • 前端依赖后端契约：OpenAPI 类型生成（openapi-typescript）在阶段二后端 schema 稳定后接入，阶段一不引入

13. 风险与注意事项

风险应对
Python 3.14 生态兼容（FastAPI/SQLAlchemy/pydantic/psycopg 等 C 扩展与新版适配期）任务 1 即逐依赖验证；任一核心依赖不兼容则按规划回退机制整体退回 3.13（.python-version 与 CI 同步调整）
