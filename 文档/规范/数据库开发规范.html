1. 目的与适用范围

规范 BMS 数据库的表设计、索引、迁移与 SQL 编写，保证 MySQL 8 / PostgreSQL 16 / 达梦 DM8 三库 方言兼容（CI 三库测试要求）。命名约定见《命名规范》第 7 节，本文档在其基础上 约束结构与写法。

2. 表结构设计

  • 表前缀：平台域固定 sys_（系统/权限）、wf_（工作流）、rpt_（报表）、ai_（AI 域）；业务模块表用各模块独立前缀（注册制：先登记于平台库 sys_module 再建表，唯一性由启动与 CI 校验；pur_ 采购、pay_ 收付款、sup_ 供应商、sale_ 销售、wh_ 仓储，登记表见《项目规划说明》「附加业务模块规划」节）；表名单数 snake_case。
  • 主键统一 id；关联表（sys_user_post 等）联合主键、不设 id。
  • 每表必备审计字段：created_at、created_by、updated_at、updated_by；软删除表加 deleted_at、并发控制加 version。
  • 金额用 DECIMAL/NUMERIC，禁止 FLOAT/DOUBLE；状态、类型用 status、type 短整型或枚举，配合字典管理（不写死魔法值）。
  • 大字段（BLOB/TEXT/JSON）独立成表或明确评估：主表行宽保持可控，避免索引失效。
  • 表与字段必须带 COMMENT（中文），与《项目规划说明》「数据规范」一致。

4. 索引规范

  • 普通索引 idx_字段（多列 idx_a_b）、唯一索引 uq_字段。
  • 外键列、高频查询过滤列、排序列（sort、created_at）建索引；复合索引遵循最左前缀。
  • 禁止冗余索引（已有 idx_a_b 不再建 idx_a）；索引数量每表不超过 5 个（联调阶段从严）。
  • 软删除查询注意 deleted_at 参与条件；大表按分片键设计索引（见第 7 节）。

5. 迁移规范（Alembic）

  • 所有结构变更走 Alembic 迁移脚本，禁止手工 DDL（开发库可临时，但必须随后补迁移）。
  • 迁移文件命名：修订号_描述.py（如 0003_add_wf_approval.sql 风格由 Alembic 自动生成），提交信息 feat(db): ...。
  • 迁移脚本必须三库可执行：不写方言 SQL；达梦注意 schema 前缀（bms_dev）。
  • CI 三库测试流程：job 内建 bms_test 前缀库 → 迁移 → 集成测试 → 删库（复用 mjbk 常驻三库，见《开发部署规划》4.4）。
  • 数据变更（种子、修复数据）单独脚本，与结构迁移分离，可重复执行（幂等）。

6. SQL 编写（三库兼容）

事项要求反例

日期参数化传入时间戳/ISO 字符串，避免 NOW() 差异DATE_FORMAT/to_char 混用

  • ORM 为主（SQLAlchemy），原生 SQL 仅限复杂统计且必须写方言兼容版本并在三库测试。

7. 多租户与分片

  • 库拓扑：平台库 bms_platform + 租户库 bms_tenant_{code} + 归档库 bms_archive；开发环境 bms_dev（见《命名规范》第 7 节）。
  • 租户隔离优先库级（一租户一库）；同库场景所有表必须含 tenant_id 且查询强制过滤。
  • 分片键：语义名 tenant / date；分片表预创建由定时任务维护（孤儿分片清理见规划）。
  • 跨库查询禁止 JOIN，改服务层聚合或事件同步（见《多租户路由》）。

8. 性能要求

  • 新增/修改查询需 EXPLAIN 确认走索引；禁止全表扫描的列表查询。
  • 列表查询禁止 N+1（ORM 关系预加载 selectin/joinedload）。
  • 批量写（导入、归档）分批提交（每批 ≤ 500 行），禁止单事务超大集合。
  • 慢查询（> 1s）登记并优化；三库均开启慢查询日志（开发环境已配置）。

9. 检查清单

  • □ 表前缀/字段命名符合《命名规范》，含审计字段与 COMMENT
  • □ 字段类型三库通用，无方言专用类型
  • □ 索引命名与数量合规，无冗余索引
  • □ 结构变更已生成 Alembic 迁移并在三库通过
  • □ SQL 参数化、方言兼容、分页统一
  • □ 租户隔离与分片键处理正确，无跨库 JOIN
  • □ 列表查询无 N+1，EXPLAIN 走索引
