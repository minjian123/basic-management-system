## 1. 目的与适用范围 <a id="purpose"></a>

规范 BMS 的测试组织与执行：分层清晰、命名统一、用例统一入库（Kiwi TCMS）、CI 自动执行并带覆盖率门禁，
保障三库兼容与安全基线，按标准测试流程闭环（计划 → 设计 → 执行 → 缺陷 → 回归 → 准出 → 报告）。
总体策略见《[项目规划说明](../规划/项目规划说明.md)》「测试策略与测试流程」节，
CI 流水线见《[开发部署规划](../规划/开发部署规划.md)》第 7 节，命名约定见《[命名规范](命名规范.md)》第 11 节。

## 2. 测试分层 <a id="level"></a>

| 层 | 范围 | 工具 | 执行时机 |
| --- | --- | --- | --- |
| 单元测试 | 纯逻辑：校验器、权限计算、工具函数、服务层单测 | pytest + SQLite | MR 流水线 |
| 集成测试 | API + DB + Redis：接口全链路、三库方言 | pytest + httpx（ASGITransport） | MR / main 流水线 |
| E2E 测试 | 浏览器主流程：登录、RBAC、采购审批 | Playwright | main 流水线 |
| 压测 | 500 并发 / P99 ≤ 1s（阶段十验收） | locust（`loadtest/`） | 阶段验收 |
| 验收测试（UAT） | 用户按验收清单逐项人工走查（MVP 验收前） | 人工（Kiwi TCMS 登记结果） | MVP 验收前 |

稳定性/可靠性：MVP 验收前对核心链路（审批、Socket.IO 推送、任务调度）执行 7×24 长稳运行与故障恢复演练，结果入测试报告。

## 3. 命名规范 <a id="naming"></a>

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 后端测试文件 | `test_模块.py` | `test_user_api.py` |
| 测试类 | `TestXxx` | `TestUserApi` |
| 测试函数 | `test_行为_期望` | `test_create_user_returns_201` |
| 前端测试 | `组件名.spec.ts` | `UserForm.spec.ts` |
| E2E | 功能描述 `login.spec.ts` | — |
| 压测脚本 | `scenario_场景.py` | `scenario_登录.py` |
| 用例 ID 关联 | 自动化用例标注 Kiwi TCMS 用例编号（pytest mark / Playwright 注解），与平台用例一一对应；先登记平台用例再写代码 | `@pytest.mark.kiwi_id(1234)` |

## 4. 测试数据 <a id="data"></a>

- 固定夹具 `tests/fixtures/`、种子 `tests/seeds/`（`seed_xxx.py`），与初始化数据分离（《[项目规划说明](../规划/项目规划说明.md)》「测试策略与测试流程」）。
- 每个测试独立数据隔离：事务回滚或唯一键后缀，禁止用例间共享可变状态。
- 密码等敏感测试数据用固定测试值（如 `Test@123456`），不入真实凭据。
- CI 三库测试库：`bms_test` 前缀（建库 → 迁移 → 测试 → 删库），与开发数据隔离（见《[开发部署规划](../规划/开发部署规划.md)》4.4）。
- 本地测试用独立 SQLite 库文件与独立端口，不占用开发库与开发服务端口。

## 5. 用例管理（Kiwi TCMS） <a id="cases"></a>

- **平台**：mjbk Docker Compose 常驻（宿主 8060，复用 MySQL，数据随 MySQL 备份），为唯一用例库——手工用例与自动化用例统一登记（含用例编号），测试代码以用例 ID 标注关联；pytest/Playwright 执行结果经官方插件导入平台归档，平台统计执行情况与历史。
- **内容与组织**：用例名称/描述/分类使用中文；按模块分类（Category）+ 标签（Tag）组织，前端页面 E2E 用例按页面模块分类承载；界面以官方简体中文翻译为主、浏览器自动翻译兜底；平台缺陷链接指向 GitLab Issue。
- **用例设计方法**：等价类划分 / 边界值 / 场景法 / 错误推测；关键业务链路（审批、权限、收付款、归档）用场景法覆盖主路径与异常路径。
- **优先级与风险**：用例按 High / Medium / Low 三级优先级；核心模块（认证、RBAC、工作流、审计、收付款）高风险用例优先设计与执行。
- **可追溯性**：用例与模块/功能点及验收项双向追溯（用例 ID 标注所属模块与对应验收项），保证需求全覆盖、无孤儿用例。
- **执行方式**：重负载执行（全量回归、三库集成、压测）以 CI（mjbk GitLab Runner）为主，不占本地开发资源；本地仅在明确需要时小范围执行（执行前与开发确认）。

## 6. 覆盖率要求 <a id="coverage"></a>

- 后端：核心模块（auth、rbac、wf、audit、收付款）行覆盖率 ≥ 80%；整体 ≥ 70%（pytest-cov 统计）。
- 前端：核心组件与 store 逻辑覆盖（Vitest coverage 统计），计入整体门槛 ≥ 70%。
- 覆盖率作 CI 门禁，低于门槛流水线失败、阻断 MR 合入。

## 7. 三库方言测试 <a id="three-db"></a>

- 集成测试默认 SQLite 快速执行；**main 流水线**跑 MySQL / PostgreSQL / 达梦 DM8 三库迁移 + 核心用例（复用 mjbk 常驻三库）。
- 方言差异重点用例：分页、日期、字符串、布尔、自增主键、大小写（详见《[数据库开发规范](数据库开发规范.md)》第 6 节）。
- 三库任一失败即阻断；方言兼容问题在开发期暴露，不在交付期。

## 8. 安全测试用例 <a id="security"></a>

CI 定期执行的集中安全用例集（《[项目规划说明](../规划/项目规划说明.md)》「测试策略与测试流程」），至少覆盖：

- 越权：跨用户/跨租户资源访问（A 的 id 被 B 访问）
- 注入：SQL/命令/XXE 注入样本
- XSS：富文本与 `v-html` 场景
- 上传绕过：类型伪造、超大文件、路径穿越
- 限流爆破：登录/验证码失败锁定
- 脱敏泄露：响应与日志无敏感字段明文
- 会话安全：会话劫持、会话踢出即时生效

## 9. 缺陷管理 <a id="defect"></a>

- **载体**：GitLab Issue + Milestone（按阶段/版本关联）；Kiwi TCMS 平台缺陷链接指向对应 Issue。
- **分级**：P0（阻断主流程/数据安全）、P1（严重功能缺失/可用性降级）、P2（一般缺陷）、P3（轻微/建议）。
- **流程**：上报（含复现步骤与关联用例 ID）→ 指派修复 → CI 回归验证 → 关闭；P0/P1 缺陷阻断 MR 合入，修复后回归通过方可合入。
- **自动上报（自动化测试失败时）**：MR 与 main 流水线任一自动化测试失败即全自动执行——`scripts/defect/defect_capture.py` 生成 REPRO 复现包归档到 mjbk `/mnt/data/backup/defects/<缺陷号>/`（现场 dump + stacktrace.txt + repro.json + REPRO.md，含测试文件与复现命令），按「用例 ID + 失败摘要」指纹查 GitLab 未关闭同源 Issue：不存在则自动创建（标题/描述含 commit、用例 ID、dump 路径、环境标记、流水线地址），已存在则追加评论附新 dump 路径；自动 Issue 打 `defect-auto` 标签，人工补充复现步骤与定级（P0-P3）后进入指派修复；令牌用 CI/CD 变量 `GITLAB_API_TOKEN`（bot 账号，勿入库）。
- **AI 辅助修复（指派修复环节）**：`scripts/defect/ai_fix.py` 扫描 defect-auto 未关闭 Issue，按复现包定位根因并生成补丁——**双轨**：本地模型（LM Studio，内网零费用）优先，定位不了或置信度低（< 0.6）且 `AI_CLOUD_ALLOWED=1` 时升级云端模型（先经敏感信息过滤，dump 内容严禁外发）；成功则 bot 推送 `fix/defect-*` 分支并提 MR（描述引用指纹与诊断），评论 Issue；**人工 review 合入、CI 回归通过后人工关闭**，AI 不自动合入/关闭；无法定位时评论标注需人工处理。复现验证：`scripts/defect/reproduce.py --issue-repro <复现包目录> --dump-target <库>`（检出 commit + 导入 dump + 跑复现命令）。
- **人工上报（UAT / 探索性测试）**：按上述脚本 `--summary` 手动执行生成 Issue 模板，或直接建 Issue 并按下列现场数据约定归档。
- **现场数据（缺陷重现）**：P0/P1 缺陷必须附**问题现场数据库 dump**（P2/P3 视可复现性可选）——在问题库上以 mysqldump / pg_dump / 达梦 dexp 导出（命令见对应数据库部署说明「日常运维」节），与代码 commit、用例 ID、运行环境标记一并归档到 mjbk `/mnt/data/backup/defects/<缺陷号>/`（dump 含业务数据，不入 Git 仓库，随每日备份保留 30 天）；修复验证按「代码 commit + 用例 + dump 导入」重建问题现场，确认缺陷消失且无回归。

## 10. 回归策略 <a id="regression"></a>

- **冒烟回归**：每次 MR 与发版前执行——登录（含图形验证码）、主体链 RBAC 权限（按钮显隐与字段权限）、核心 CRUD 主链路。
- **全量回归**：每阶段末与 MVP 验收前执行全部自动化用例（单元/接口/前端组件/E2E），结果导入 Kiwi TCMS 归档。
- **探索性测试**：MVP 验收前由开发/用户对新功能区开展探索性测试，发现项入缺陷库。

## 11. 进入与准出标准 <a id="exit"></a>

**进入准则**（进入全量回归与 UAT 的前置条件，同时满足）：

- 冒烟回归通过（登录、主体链 RBAC、核心 CRUD 主链路）；
- CI 流水线绿色（单元/接口/前端组件测试通过）；
- 用例就绪：Kiwi TCMS 用例登记完成，用例 ID 与代码关联一致。

**准出标准**（阶段交付与 MVP 验收，同时满足）：

- P0/P1 缺陷清零；
- 功能用例通过率 ≥ 98%；
- 安全专项用例集全部通过；
- 压测达到 500 并发 / P99 ≤ 1s；
- MySQL / PostgreSQL / 达梦 DM8 三库 CI 通过；
- 覆盖率达标（核心 ≥ 80%、整体 ≥ 70%）。

## 12. 测试报告 <a id="report"></a>

- **自动化报告**：后端 pytest + Allure、前端 Vitest/Playwright 生成自动化测试报告（CI 产物归档）。
- **阶段汇总报告**：每阶段末输出（用例执行统计、缺陷统计、覆盖率、风险与遗留项），纳入《[项目规划说明](../规划/项目规划说明.md)》「文档计划」交付项；MVP 验收前输出总测试报告。
- **测试复盘**：阶段末报告含经验教训小节（测试过程问题与改进项），MVP 验收后整体复盘一次。

## 13. CI 执行策略 <a id="ci"></a>

| 流水线 | 内容 |
| --- | --- |
| MR 流水线 | ruff + pytest（SQLite，pytest-cov 覆盖率门禁）+ ESLint + Vitest（coverage 门禁）+ 双端构建 |
| main 流水线 | Playwright E2E + 三库方言集成测试 + 镜像构建（`bms-backend`/`bms-frontend` → Registry）+ swagger 契约存档 + Allure 报告归档 + 测试结果导入 Kiwi TCMS |
| 定时/安全 | 安全用例集、依赖漏洞扫描（Renovate / Dependency Scanning） |

> runner 并发上限 2（mjbk 6 核），大任务错峰执行。

## 14. 检查清单 <a id="checklist"></a>

- □ 新功能/修复带对应测试（单测或集成）
- □ 用例已登记 Kiwi TCMS（用例 ID 与代码关联一致）
- □ 命名符合规范，测试数据隔离
- □ 覆盖率达标，CI 全绿
- □ 涉及 SQL 的变更已跑三库用例
- □ 涉及权限/文件/上传的变更补充安全用例
- □ 缺陷按 P0-P3 分级走 GitLab Issue 流程
- □ P0/P1 缺陷已附现场 dump 与 commit / 用例 ID（归档 `/mnt/data/backup/defects/<缺陷号>/`）
- □ 阶段末测试报告与复盘完成
