1. 目的与适用范围

约束 BMS 开发过程中的安全实践（参考 OWASP Top 10），覆盖密钥管理、认证授权、输入输出、审计合规， 支撑项目的审计合规与信创交付要求。涉及架构的安全机制见《性能与安全》与《项目规划说明》「认证与安全」节。

2. 密钥与配置安全

  • 密钥（DB/Redis 密码、JWT secret、MinIO 凭据、第三方 API Key）只走环境变量（BMS_ 前缀），不入代码、不入配置仓库、不入镜像。
  • 仓库只提交 .env.example（键名模板）；真实 .env 加入 .gitignore（参考《开发部署规划》第 6 节）。
  • 密码强度：数据库等 ≥ 12 位混合字符；生产密钥用 Secret 管理（K8s Secret / Docker secrets）。
  • 令牌轮换：GitLab/GitHub PAT、开放接口 AppSecret 定期轮换；泄露立即撤销。

3. 认证与会话安全

  • 密码存储：bcrypt/argon2 哈希，禁止明文与 MD5/SHA1；登录防爆破（失败计数 + 锁定，见《会话管理》）。
  • 双 token：access 短时（分钟级）+ refresh 长时（可吊销）；token 黑名单（登出/强踢）落 Redis。
  • 会话：强制踢出广播「会话失效」事件；会话列表可管理（见《会话管理》）。
  • SSO：OIDC/CAS 对接遵循《身份认证SSO》设计；JIT 建号校验域名/租户白名单。
  • 接口鉴权用权限码（业务:动作），禁止仅靠路由隐藏（详见《API接口规范》）。

5. Web 常见漏洞

  • 越权：接口必须做归属校验（资源属于当前租户/用户），CRUD 禁止仅凭 id 访问他人数据；越权用例入 CI（见《测试规范》）。
  • XSS：前端框架默认转义，禁止 v-html 渲染不可信内容；富文本走白名单清洗。
  • CSRF：前后端分离 + Bearer 令牌已天然免疫；Cookie 场景启用 SameSite/CSRF Token。
  • 上传安全：文件服务限类型/大小/数量，下载走鉴权 URL，禁目录穿越。
  • 安全响应头：nginx 统一 CSP、HSTS（dev 关）、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy（见《开发部署规划》「基础设施编排」）。

6. 敏感数据与脱敏

  • 敏感字段（手机号、邮箱、身份证、银行卡、密码、token）出接口必须脱敏（掩码 138****1234）；脱敏规则配置化（见《系统参数》）。
  • 日志、审计、导出文件同样脱敏；导出大文件记录审计。
  • 密码/密钥类字段永不出现在响应与日志中（Pydantic 序列化排除）。
  • 静态资源与 MinIO 对象按租户隔离（bucket 前缀，见《命名规范》）。

7. 审计与合规

  • 操作日志/登录日志/开放接口日志/数据变更日志四类审计（见《审计合规》），90 天归档策略。
  • 审计日志防篡改：哈希链（见《审计哈希链》）。
  • 管理员操作（授权、导出、删除、改密）必须留痕；解锁/锁定账号记录审计。
  • 合规：信创交付注意达梦等组件许可合规（见《项目规划说明》许可章节）。

8. 依赖与供应链

  • 依赖锁定版本（uv.lock / package-lock.json），Renovate 自动升级并提 MR（见《开发部署规划》第 7 节）。
  • CI 集成依赖漏洞扫描（GitLab Dependency Scanning），高危漏洞阻断合入。
  • 禁止引入来源不明的第三方包；内网环境拉取依赖走国内镜像。

9. 检查清单

  • □ 无密钥/凭据入代码、入库、入镜像；环境变量 BMS_ 前缀
  • □ 密码 bcrypt/argon2，接口鉴权权限码完备
  • □ SQL/命令/文件/URL 均参数化或白名单
  • □ 接口归属校验（越权防护），敏感字段脱敏
  • □ 上传与下载安全，安全响应头就位
  • □ 审计日志覆盖敏感操作且防篡改
  • □ 依赖版本锁定 + 漏洞扫描无高危
