## 1. 目的与适用范围 <a id="purpose"></a>

本规范定义**需求文档**（需求总览 + 需求域文档）的固定格式，是 `deploy/tools/zentao/zentao_sync_push.py`（文档→禅道）解析需求、创建/更新禅道 story 的**强制契约**，也是 `zentao_sync_pull.py`（禅道→文档）回写状态的落点格式。

- 适用于 `文档/项目/{阶段}/需求/` 下全部需求文档（阶段0 准备期已按本规范编写）。
- 本规范只约束**文档怎么写**（可被工具解析的格式）；禅道侧字段口径（主题命名、优先级、描述三段式、录入方式、状态与工时）以《[项目管理规范](项目管理规范.md)》为准，两者配套。
- **强制契约**：同步工具只解析符合本规范的文档；字段缺失、行格式不符即报错停住，不静默跳过——保证不漏同步。
- 与《[文档生成规范](文档生成规范.md)》的关系：文档生成规范管「文档通用怎么写」（载体/目录/措辞/图形），本规范只管「需求文档的结构与字段格式」，两者同时适用。

## 2. 文件组织 <a id="files"></a>

一个阶段的需求文档分两层：

```text
需求/
├── 00_需求_{阶段}.md        # 需求总览：目标/范围/需求总清单/M0 验收门禁（00 固定为总览）
├── {NN}_需求_{域名}.md       # 需求域文档：本域全部需求，一条需求一个章节
│   └── 例：01_需求_环境与工具链.md、02_需求_仓库与CI.md
└── {NN}_需求_{域名}.md       # 域名即禅道父任务主题，编号两位、按阅读顺序
```

- 总览文档 `00_` 固定编号，不承载单条需求，只承载总清单与门禁。
- 域文档一个需求域一份，域编号两位（`01`/`02`/`03`…），与需求编号前缀一致（域 `01` 的需求编号为 `01-1`…）。
- 新增需求域时顺延编号，不与既有编号冲突。

## 3. 需求总览文档格式 <a id="overview"></a>

总览文档固定章节与需求总清单表（同步工具据此核对域文档完整性）：

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 说明 | `## N. 文档说明` | `purpose` | 文档集定位、与禅道关系、依据 |
| 目标范围 | `## N. 准备期目标与范围`（阶段名替换） | `goal` | 范围内/外清单 |
| **总清单** | `## N. 需求总清单` | `list` | 全部需求汇总表（下表） |
| 验收门禁 | `## N. {阶段}验收门禁` | `accept` | 验收点逐项核对 |

**需求总清单表**列固定为（顺序不可变，同步工具按表头定位列）：

```markdown
| 编号 | 需求 | 域文档 | 禅道 story | 禅道任务 | 优先级 | 状态 | 完成日期 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 01-1 | mjbk Ubuntu 基础（静态 IP / 清华源 / SSH 免密 / 磁盘挂载 / data-root 迁移 / Timeshift） | [01](01_需求_环境与工具链.md#r01-1) | 101 | 85（父任务 1） | 2 高 | 已完成 | 2026-08-15 |
| 01-5 | 备份体系（三库 / GitLab / 禅道每日备份） | [01](01_需求_环境与工具链.md#r01-5) | — | 89（父任务 1） | 2 高 | 未开始 | — |
```

- **编号**：`{域两位}-{序号一位}`，全阶段唯一，是需求的主键。
- **禅道 story**：禅道 story id（数字）；未创建填 `—`（全角破折号）。创建后由 `zentao_sync_push.py` 回填。
- **禅道任务**：对应禅道任务 id（可附「（父任务 {id}）」）；与元信息行「禅道任务」一致，用于需求↔任务互链。
- **优先级**：`{1–4} {含义}`（1 紧急 / 2 高 / 3 中 / 4 低，口径见《项目管理规范》2.3）。
- **状态**：取值见第 6 节状态口径。
- **完成日期**：`YYYY-MM-DD`；未完成填 `—`。

## 4. 需求域文档格式 <a id="domain"></a>

### 4.1 单条需求章节（核心解析单元） <a id="requirement"></a>

每条需求一个 `##` 章节，章节标题、锚点、元信息行格式固定：

```markdown
## 2. 需求 01-1：mjbk Ubuntu 基础 <a id="r01-1"></a>

优先级：2（高）　|　禅道 story：101　|　禅道任务：85（父任务 1）　|　状态：已完成　|　完成日期：2026-08-15

**内容**（《开发部署规划》4.1/4.2）：

1. Ubuntu 24.04.4 LTS 桌面版，静态 IP（内网段 /24），apt 换清华源
2. SSH 免密：mjpc 公钥录入 mjbk
3. 磁盘挂载：机械盘 `/mnt/data`、2T NVMe SSD `/mnt/ssd2t`（ext4 + fstab 自动挂载）

**完成标准**：mjpc SSH 免密连通；重启后两块盘自动挂载且 `daemon.json` data-root 生效；Timeshift 可建快照并可回滚。

**参考文档**：《Ubuntu安装部署使用说明》第 7 节、《开发部署规划》4.1/4.2
```

**逐行格式契约**（同步工具按下表解析，字段名与分隔符不可变）：

| 元素 | 固定格式 | 说明 |
| --- | --- | --- |
| 章节标题 | `## {序号}. 需求 {编号}：{标题} <a id="r{编号小写}"></a>` | 序号按域内顺序；`编号` 如 `01-1`；锚点 `id` = `r` + 编号小写去连字符（`r01-1` 保留连字符亦可，以实际为准） |
| 元信息行 | `优先级：{pri}（{含义}）　|　禅道 story：{id\|—}　|　禅道任务：{id}（父任务 {id}）　|　状态：{状态}　|　完成日期：{date\|—}` | 紧跟标题下一行（中间空一行）；字段以 `　\|　`（全角竖线）分隔；缺省值一律 `—` |
| 内容 | `**内容**（{依据}）：` + 编号清单 | 一条一事，带具体值（版本/端口/路径/账号），映射禅道 story 描述「内容」段 |
| 完成标准 | `**完成标准**：{文本}` | 可验证验收点，映射描述「完成标准」段 |
| 参考文档 | `**参考文档**：{清单}` | 出处与章节号，映射描述「参考文档」段 |

> 元信息行是**唯一**承载「禅道 story id / 状态 / 完成日期」的位置；同步工具只认这一行，正文其它位置的状态描述不作数。

### 4.2 章节内顺序 <a id="order"></a>

单条需求章节内元素顺序固定：`章节标题 → 空行 → 元信息行 → 空行 → **内容** → **完成标准** → **参考文档**`。可加 `> 注：` 补充说明块（置于参考文档之后），工具忽略引用块。

### 4.3 域文档固定章节 <a id="domain-sections"></a>

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 域说明 | `## 1. 域说明` | `intro` | 对应禅道父任务、覆盖范围、依据、目标 |
| 需求 N | `## {2…}. 需求 {编号}：{标题}` | `r{编号}` | 见 4.1，一条需求一个章节，按编号顺序 |

## 5. 与禅道的映射 <a id="mapping"></a>

同步工具按下表把需求文档字段映射到禅道 story（字段口径见《项目管理规范》第 2 节）：

| 需求文档字段 | 禅道 story 字段 | 说明 |
| --- | --- | --- |
| 编号 + 标题 | `title` | 主题「对象 + 动作（要点）」；编号用于幂等匹配，不入 title |
| 内容/完成标准/参考文档 | `spec` | 按《项目管理规范》4 节拼成三段式描述 |
| 优先级 | `pri` | 1–4 |
| 域 | `category` + 所属父任务 | 域 → 分类；域对应禅道父任务（WBS） |
| 所属阶段 | 关联里程碑 | 在描述中写明 M0–M15 |
| 禅道 story id | （回填字段） | 创建后写回「禅道 story：{id}」，重跑按 id 更新不重复建 |

**幂等匹配规则**：优先按「禅道 story id」（已回填）匹配；未回填时按「编号 + 标题」在禅道 story 列表检索；命中则更新，未命中则创建并回填 id。

## 6. 状态与日期口径 <a id="status"></a>

需求文档「状态」取值固定为下表左列，`zentao_sync_push.py` 按右列映射到禅道 story 状态（状态流转动作见《项目管理规范》7.1）：

| 文档状态 | 含义 | 映射禅道 |
| --- | --- | --- |
| 未开始 | 登记未动工 | `wait` |
| 进行中 | 已动工未完 | `doing` |
| 部分完成 | 一部分就绪、余量未完 | `doing`（描述注明余量） |
| 已完成 | 全部达标 | `finished`（再 `closed`） |
| 搁置 | 主动挂起（如外网不可达） | `wait`（描述注明搁置原因） |

- 「完成日期」仅在状态为「已完成」时有值，`YYYY-MM-DD`；其余状态填 `—`。
- 状态与日期是 `zentao_sync_pull.py` 回写的目标字段；回写只改元信息行的「状态 / 完成日期」与总清单表对应两列，不动其它字段。

## 7. 同步工具接口 <a id="tool"></a>

| 工具 | 方向 | 对需求文档的动作 |
| --- | --- | --- |
| `zentao_sync_push.py` | 文档 → 禅道 | 解析总清单 + 各域单条需求，创建/更新 story，回填「禅道 story id」 |
| `zentao_sync_pull.py` | 禅道 → 文档 | 读禅道 story 状态/日期，按第 6 节口径回写元信息行与总清单表 |

两工具共用 `ZentaoClient`（`deploy/tools/zentao/`），凭据读 `deploy/.env`；均支持 `--dry-run`（只打印将执行的建/改，不落库）。调用示例：

```bash
python deploy/tools/zentao/zentao_sync_push.py --stage 00_准备期 --dry-run
python deploy/tools/zentao/zentao_sync_pull.py --stage 00_准备期
```

## 8. 检查清单 <a id="checklist"></a>

- □ 总览 `00_` + 域文档 `{NN}_` 编号无冲突、域前缀与需求编号一致
- □ 需求总清单表七列表头与顺序正确，每行编号唯一
- □ 每条需求：章节标题格式、元信息行五字段齐全（缺省 `—`）、内容/完成标准/参考文档三段齐备
- □ 元信息行是状态/日期/story id 唯一落点
- □ 状态取值在第 6 节集合内；已完成才有完成日期
- □ `zentao_sync_push.py --dry-run` 全量解析通过、无字段报错
