1. 目的与适用范围

统一 BMS 项目内全部标识符与资源的命名方式，保证代码、数据库、API、基础设施与文档风格一致， 降低理解成本。适用于本仓库全部代码、配置、部署文件与文档；与《文档生成规范》《项目规划说明》配套使用。

2. 通用原则

2.2 命名规则

  • 语义优先：名称表达用途，不表达实现（用 get_user_by_id 而非 query_user_1）
  • 完整单词：禁止随意缩写；仅使用公认缩写（id、url、config、auth、msg）
  • 语言分工：代码标识符一律英文；注释、文档、提交信息、数据库 comment 用中文
  • 风格一致性：同一实体在代码/数据库/API/前端各层保持同名映射（如 dept_id / deptId / /departments/{id}）
  • 禁止：拼音命名、无意义命名（a/b/c）、与保留字冲突、中文变量名

3. 项目与目录命名

  • 仓库与根目录：bms
  • 顶层目录：backend/、frontend/、deploy/、文档/（全小写英文，文档目录用中文）
  • 后端：app/core、app/api、app/models、app/schemas、app/services、app/repositories、app/db、app/tasks（Celery）、app/ws（Socket.IO）、app/i18n（国际化）、alembic/、tests/，均小写
  • 前端：src/api、src/router、src/stores、src/views、src/layouts、src/components、src/i18n、src/utils
  • 按模块分组：模块目录用单数名词（views/user/、app/api/user/、app/models/user.py）

4. 文档命名

  • 文件：中文、主题一致（项目规划说明.html、graphify部署使用说明.html），不叠加多余后缀
  • 格式分工：用户手写 .md；AI 生成 .html
  • 资源：HTML 的图片等资源放同级 资源/文档名/ 同名子目录
  • 章节编号：1. / 1.1 阿拉伯数字逐级编号，目录与正文一致
  • 编号与主题之间的分隔符用下划线 _（snake_case），不用连字符 -：01_架构设计_总览.html、02_概要设计_用户管理.html、02_布局设计_设计令牌.html（序号与文件名、文件名各段之间均以 _ 连接）。理由：
    • 文档文件须被代码环境解析：Python/Java/Go 的 import 与模块系统要求目录和文件名是合法标识符，连字符（减号）不能作为标识符；正则 \w 识别 _ 而不识别 -，脚本（grep、graphify 等）按词处理时下划线更稳妥
    • 连字符在英文文法中是有意义的复合词连接符（如 upper-case、non-English），用于文件名会破坏其语义，下划线无此歧义
    • URL 中 Google 建议用连字符是出于 SEO 词分隔考虑，但本仓库文档以本地传递与代码环境处理为主，不依赖搜索引擎收录；文件名中的中文本身也需百分号编码，分隔符选择不影响 URL 可用性（- 与 _ 均无需转义）
    • 与 Python 命名（snake_case）同源风格，全仓库命名风格统一
  • 参考：文件命名，下划线还是中划线？（adoyle · 今天我学了什么）——按使用环境取舍：本仓库文档以代码环境解析为主，选 _；Coding Horror · Of Spaces, Underscores and Dashes

7. 数据库命名

  • 库：平台库 bms_platform、租户库 bms_tenant_{code}（一租户一库）、归档库 bms_archive；环境库 bms_dev / bms_test / bms_prod
  • 表前缀：平台域固定前缀 sys_ 系统（含权限体系：用户/岗位/角色/菜单/表单/字段/按钮/业务/动作/数据范围）、wf_ 工作流、rpt_ 报表、ai_ AI 域；业务模块表用各模块独立前缀（{模块简称}_，注册制，登记表见《项目规划说明》「附加业务模块规划」节）：pur_ 采购、pay_ 收付款、sup_ 供应商、sale_ 销售（规划中）、wh_ 仓储（规划中）；表名单数 snake_case：sys_user、sys_post、pur_purchase_apply、pay_receipt、sup_supplier、wf_task、rpt_report、ai_chat_log
  • 字段：snake_case；主键统一 id；外键 目标表名_id（dept_id、role_id）；布尔 is_ 前缀；时间 xxx_at（created_at）；审计 created_by / updated_by；通用 deleted_at、version、status、sort、remark
  • 索引：普通 idx_字段（idx_dept_id）、唯一 uq_字段（uq_username）
  • 关联表：两表名单词连接（sys_user_post、sys_role_permission），联合主键，不设 id；通用主体角色绑定 sys_role_assign（subject_type + subject_id + role_id）
  • 枚举值：小写 snake_case 或 UPPER_SNAKE（subject_type = 'user' | 'post' | 'dept'、button.type = 'toolbar' | 'interface'、lock_type = 'fail_limit' | 'inactive' | 'manual'、sms.channel = 'aliyun' | 'tencent'、quota_key = 'user_count' | 'storage_bytes' | 'open_calls'），统一用字典管理；数据范围非枚举，规则表达式存 sys_data_scope.config（字段 + 运算符 + 预置变量，形态见权限设计文档）

8. API 命名

  • 前缀：内部 /api/v1，开放 /api/open
  • 资源：复数名词（/users、/departments），子资源嵌套（/users/{id}/roles）
  • 动词交给 HTTP 方法：GET 查、POST 建、PUT 全量改、PATCH 部分改、DELETE 删；动作类接口动词短语（/auth/login、/users/{id}/reset-password）
  • 参数：分页 page、size；排序 order_by；筛选 模块字段名（status、keyword）；游标分页 cursor、limit
  • 权限码：业务:动作——业务对应业务权限（sys_business，如 user、wf、open），动作对应动作权限（sys_action，如 create、approve、manage）；组合示例 user:create、wf:approve、open:call
  • 错误码：5 位数字按模块分段（1xxxx 通用、2xxxx 认证、3xxxx 用户与组织、4xxxx 系统配置、5xxxx 文件、6xxxx 工作流、7xxxx 通知/邮件/任务、8xxxx 开放接口/租户/SSO、9xxxx 报表/审计/归档/监控），稳定不变；业务模块错误码段自 10xxxx 起扩展（10xxxx 采购、11xxxx 收付款、12xxxx 销售、13xxxx 仓储，注册即定，见《项目规划说明》「附加业务模块规划」节）
  • 统一响应 {code, message, data}，分页响应 {list, total, page, size}
  • 幂等键请求头 Idempotency-Key

12. 国际化命名

  • 前端 locale：zh-CN.ts、en-US.ts；i18n key 用点分：模块.页面.字段（user.form.username、common.confirm）
  • 后端 po 文件：zh_CN/LC_MESSAGES/messages.po、en_US/...；msgid 用英文原文，msgstr 本地化
  • 错误码文案：前端按错误码映射 i18n key（error.20001），不硬编码

13. 检查清单

  • □ 无拼音、无缩写不明、无中英混排标识符
  • □ 风格与第 2.1 节对照一致（各语言各自的风格）
  • □ 数据库字段名与后端模型、前端参数同名映射
  • □ 表前缀使用正确：平台域 sys_/wf_/rpt_/ai_，业务模块 {简称}_（登记表见《项目规划说明》「附加业务模块规划」节）；外键 表_id、索引 idx_/uq_ 前缀
  • □ API 资源复数、权限码 业务:动作（业务/动作两级）、错误码分段正确
  • □ Redis key 符合 bms:{租户|global}:{域}:{键}；RocketMQ topic / 事件 / ES 索引 / Milvus collection 符合点分或连字符约定
  • □ 环境变量带 BMS_ 前缀；密钥仅环境变量
  • □ 提交信息 type(scope): 中文描述；分支 类型/描述
