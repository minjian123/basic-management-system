4. 测试数据

  • 固定夹具 tests/fixtures/、种子 tests/seeds/（seed_xxx.py），与初始化数据分离（《项目规划说明》「测试策略」）。
  • 每个测试独立数据隔离：事务回滚或唯一键后缀，禁止用例间共享可变状态。
  • 密码等敏感测试数据用固定测试值（如 Test@123456），不入真实凭据。
  • CI 三库测试库：bms_test 前缀（建库 → 迁移 → 测试 → 删库），与开发数据隔离（见《开发部署规划》4.4）。

5. 覆盖率要求

  • 后端：核心模块（auth、rbac、wf、biz 主流程）行覆盖率 ≥ 85%；全局 ≥ 70%（阶段一基线后逐步收紧）。
  • 前端：核心组件与 store 逻辑覆盖；表单组件 ≥ 60%。
  • 覆盖率统计入 CI 报告，不达标阻断 MR 合入。

6. 三库方言测试

  • 集成测试默认 SQLite 快速执行；main 流水线跑 MySQL / PostgreSQL / 达梦 DM8 三库迁移 + 核心用例（复用 mjbk 常驻三库）。
  • 方言差异重点用例：分页、日期、字符串、布尔、自增主键、大小写（详见《数据库开发规范》第 6 节）。
  • 三库任一失败即阻断；方言兼容问题在开发期暴露，不在交付期。

7. 安全测试用例

CI 定期执行的集中安全用例集（《项目规划说明》「测试策略」），至少覆盖：

  • 越权：跨用户/跨租户资源访问（A 的 id 被 B 访问）
  • 注入：SQL/命令/XXE 注入样本
  • XSS：富文本与 v-html 场景
  • 上传绕过：类型伪造、超大文件、路径穿越
  • 限流爆破：登录/验证码失败锁定
  • 脱敏泄露：响应与日志无敏感字段明文
