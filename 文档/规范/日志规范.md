# 日志规范

## 1. 目的与适用范围 <a id="purpose"></a>

规范 BMS 后端日志的记录方式：级别清晰、格式统一（JSON 便于 Loki 聚合）、敏感信息脱敏、可跨服务追踪。
与《[可观测性](../设计/架构设计/23_架构设计_子系统_可观测性.md)》与《[开发部署规划](../规划/开发部署规划.md)》监控组（阶段八）配套。

## 2. 日志级别 <a id="level"></a>

| 级别 | 使用场景 | 示例 |
| --- | --- | --- |
| DEBUG | 调试细节，默认关闭（dev 可开） | 参数快照、中间计算结果 |
| INFO | 关键业务流程节点（每请求 1-2 条） | 登录成功、订单创建、任务执行完成 |
| WARNING | 可恢复的异常情况 | 重试成功、限流触发、慢查询告警 |
| ERROR | 单次操作失败（含异常堆栈） | 接口 500、第三方调用失败 |
| CRITICAL | 系统级故障，需立即介入 | 数据库不可用、密钥轮换失败 |

> 禁止用 print 输出日志；统一走 structlog 日志器，业务代码不直接操作日志文件。

## 3. 日志格式 <a id="format"></a>

结构化 JSON（structlog），每行一条，示例：

```json
{"ts": "2026-08-11T09:00:00.123+08:00", "level": "info", "logger": "app.api.user",
  "event": "user_created", "trace_id": "a1b2c3d4...", "tenant": "demo",
  "user_id": 42, "user": "zhangsan", "duration_ms": 35}
```

- 字段名统一 snake_case；`event` 为动作描述（`user_created`、`login_failed`），便于检索聚合。
- 上下文（租户、用户、trace_id）由中间件注入，业务代码只记业务字段。
- 多行堆栈合并为单行（替换换行为 `\n` 转义），保证日志可被 Loki 逐行解析。

## 4. 上下文字段 <a id="context"></a>

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 请求链路 ID（入站生成/透传），跨服务一致 |
| `tenant` | 租户标识（多租户必记） |
| `user_id` / `user` | 操作者 |
| `duration_ms` | 请求/任务耗时 |
| `client_ip` | 来源 IP（审计需要） |
| `request_id` | 进程内请求序号（未接入 trace 时兜底） |

## 5. 脱敏要求 <a id="mask"></a>

- 禁止记录：密码、令牌（access/refresh）、验证码、私钥、完整手机号/身份证等 PII（记录掩码或省略）。
- 请求/响应级 DEBUG 日志若打印 body，须经脱敏过滤器（Pydantic 字段排除 + 正则掩码）。
- 第三方密钥（MinIO/GitLab/API Key）不回显；数据库连接串日志脱敏（隐藏密码）。
- 错误信息不输出 SQL 参数明文（ORM 异常日志禁用 bind params）。

## 6. 链路追踪 <a id="trace"></a>

- 入站请求生成 `trace_id` 并透传：HTTP 头（`X-Trace-Id`）→ 日志上下文 → 下游调用（DB/Redis/消息/Socket.IO 事件）。
- 阶段八接入 OpenTelemetry（otel-collector + Jaeger）：`trace_id`/`span_id` 与日志关联，跨服务链路可查。
- 异步任务（Celery）与消息消费者（event-worker）在消费入口沿用或生成 trace_id。

## 7. 保留与归档 <a id="retention"></a>

- 容器日志（stdout）由 Docker 限制大小（logging rotate）；生产经 Loki 聚合。
- 日志保留策略与审计要求一致：普通日志 30 天、审计类日志 90 天归档（见《[安全开发规范](安全开发规范.md)》第 7 节）。
- 归档日志入 MinIO（`bms-log-*`），可检索期内在 Loki/ES 保留。

## 8. 检查清单 <a id="checklist"></a>

- □ 使用 structlog，JSON 单行格式，级别使用正确
- □ 请求级日志含 trace_id / tenant / user 上下文
- □ 无密码/令牌/PII 明文日志
- □ 异步任务入口 trace_id 贯通
- □ 日志保留与归档策略符合审计要求
