1. 目的与适用范围

统一 BMS 后端 API 的设计与实现约定，保证前后端联调顺畅、外部开放接口稳定。 命名规则见《命名规范》第 8 节，本文档为其落地约束；与《项目规划说明》「API 设计规范」一致。

2. URL 与资源设计

类别前缀说明
内部接口/api/v1管理端/租户端全部接口
开放接口/api/open外部系统接入（AppId/Secret 鉴权）
  • 资源用复数名词：/users、/departments；子资源嵌套：/users/{id}/roles。
  • 动词交给 HTTP 方法：GET 查、POST 建、PUT 全量改、PATCH 部分改、DELETE 删。
  • 动作类接口用动词短语：/auth/login、/users/{id}/reset-password、/purchase/{id}/approve。
  • 路径参数用 {id} 占位（FastAPI 路径参数）；禁止在 URL 中暴露敏感信息（密码、token）。

3. 统一响应

{
  "code": 0,          // 业务码：0 成功，非 0 失败（见第 4 节）
  "message": "ok",    // 提示信息（i18n key 或已翻译文案）
  "data": { ... }     // 业务数据；失败时为 null
}

分页响应：

{ "code": 0, "message": "ok", "data": { "list": [...], "total": 100, "page": 1, "size": 20 } }
  • HTTP 状态码表示传输层语义（200 成功、401 未认证、403 无权限、404 不存在、429 限流、500 服务异常）；业务失败统一 200 + 业务码。
  • 删除类接口返回 data: null；创建返回资源 id（{"id": 123}）。

4. 错误码

5 位数字，按模块分段（稳定不变，见《命名规范》第 8 节）：

段模块示例
1xxxx通用10001 参数校验失败、10002 资源不存在
2xxxx认证20001 登录失败、20002 令牌过期
3xxxx用户与组织30001 用户名已存在
4xxxx系统配置40001 字典编码重复
5xxxx文件50001 文件过大
6xxxx工作流60001 流程已终止
7xxxx通知/邮件/任务—

9xxxx报表/审计/归档/监控—
  • 错误码一经发布不可更改含义；前端按码映射 i18n 文案（error.20001，见《国际化规范》）。
  • 新增错误码在「错误码总表」登记，随代码评审同步。

5. 参数与分页

参数约定
分页page（从 1 起）、size（默认 20，上限 200）
排序order_by=字段（白名单校验，禁止用户输入直接拼接）
筛选字段名直传：status、keyword、dept_id
游标分页cursor、limit（日志/审计类大数据量场景）
日期范围start_at / end_at（ISO 8601）
  • 参数校验用 Pydantic Schema（字段类型、长度、枚举），不信任前端。
  • 写接口参数结构稳定后不随意改名；兼容性变更走版本化（见第 8 节）。

6. 认证与权限

  • 认证：双 token（access + refresh），Bearer 方式；会话管理、锁定策略见《认证与会话》。
  • 授权：RBAC 权限码 业务:动作（user:create、wf:approve），接口级注解校验（依赖注入），前端 v-perm 同步（见《命名规范》第 8/9 节）。
  • 开放接口：AppId/Secret 签名鉴权，IP 白名单可选；令牌/密钥不落前端。
  • 未认证 401、无权限 403，与业务码区分。

7. 幂等 / 限流 / 审计

  • 幂等：写接口（POST/PUT）支持 Idempotency-Key 请求头，Redis 前置去重 + 唯一约束兜底（见《项目规划说明》「限流与降级」）。
  • 限流：登录防爆破（失败次数锁定）、开放接口按 AppId 限流、通用接口按用户限流（slowapi/limits，Redis 后端，见规划）。
  • 审计：操作日志（sys_operation_log）记录用户、IP、请求、结果、耗时；敏感操作（删除、导出、授权变更）必记；正文脱敏（见《安全开发规范》）。

8. 接口文档与版本

  • FastAPI 自动生成 OpenAPI（Swagger UI /docs）；契约快照（swagger.json）随 main 流水线导出存档（见《开发部署规划》第 7 节）。
  • 前端类型契约：OpenAPI 经 openapi-typescript 生成 TS 类型，接口变更后同步重新生成，禁止手写类型漂移。
  • 兼容性变更：新增字段向后兼容；破坏性变更（删参数、改语义）提版本（路径 /api/v2 或参数版本协商），并登记迁移说明。

9. 检查清单

  • □ URL 符合前缀/复数/方法语义，无动作裸 URL
  • □ 响应统一 {code, message, data}，分页结构正确
  • □ 错误码使用正确且已登记
  • □ 参数经 Schema 校验、排序白名单、分页上限
  • □ 接口鉴权与权限码配置正确（含前端 v-perm 同步）
  • □ 写接口支持幂等键；敏感操作有审计与限流
  • □ OpenAPI 契约已生成、前端类型已同步
