1. 目的与适用范围

本规范统一 BMS 项目中文档的组织、格式与生成方式，保证 AI 助手生成的文档风格一致、 易于阅读维护。适用于「文档」目录下 AI 生成的全部文档，也约束 AI 修改用户编写的 Markdown 文档时的行为。

2. 文档格式约定

文档类型格式说明
用户手写文档 Markdown（.md） 由用户亲自编写或审定的文档，AI 只可修改，不得擅自改写格式。
AI 生成文档 HTML（.html） AI 独立撰写的新文档一律输出 HTML，避免与用户手写 md 混淆。
AI 对 md 的补充 遵循原格式 在用户 md 中补充内容时沿用原有结构、标题层级与风格。
设计体系文档 HTML（.html） 架构/概要/布局/原型四套设计体系：总纲 + 节点文件；原型界面的可交互 HTML 规则见第 8 节。
判断依据：文档内容来源。AI 全新撰写 → html；在既有 md 上修改 → 保持 md。

3. 目录结构

graph TD
    A["文档/"] --> B["规划/ 项目规划、技术选型说明（用户 md）"]
    A --> C["规范/ 各类规范文档（文档生成规范、命名规范等）"]
    A --> D["资料/ 参考资料、工具说明、AI 生成的各类文档"]
    D --> D1["资源/ 图片、音频、视频等资源文件（见第 4 节）"]
    A --> E["其他主题目录 按需新增，语义清晰即可"]

新增主题目录时遵循「功能即名字」原则，目录名用中文、简短、无歧义。

4. 资源文件管理

  • HTML 文档引用的图片、音频、视频等资源，统一放入同级目录「资源」文件夹下的同名子目录中。
  • 例：文档/资料/graphify部署使用说明.html 的图片放在 文档/资料/资源/graphify部署使用说明/。
  • 子目录名与文档主文件名保持一致（不含扩展名），便于关联与清理。
  • 引用时使用相对路径（资源/文档名/xxx.png），保证目录整体迁移后仍可显示。
  • 公共资源（全站共享，非单文档专属）：直接放 文档/资源/ 根下，如公共样式 资源/文档样式.css（见第 7.2 节），各文档按相对深度引用。
  • 无资源依赖时不要创建空的资源目录；优先使用纯 CSS 方案（图标、分隔线等），减少外部文件。

5. 命名规范

  • 文档文件名：中文、与内容主题一致、不加「说明」「规范」以外的后缀堆叠。例：graphify部署使用说明.html。
  • 标题（h1 / title）：与文件名对应，格式「主题 + 文档类型」，如「graphify 部署与使用说明」「文档生成规范」。
  • 章节标题统一阿拉伯数字编号：1. 2. 3.；子节用 x.y。
  • 目录条目与正文标题文字一致，数字编号对应。
  • 项目内其他命名（代码、数据库、API、基础设施等）遵循《命名规范》，本文档只约束文档本身。
规范文档间的关系：本文档约束「文档怎么写」，《命名规范》约束「项目所有标识符怎么叫」；生成文档涉及代码/接口示例时两者同时适用。

6. 语言与措辞

  • 全部使用简体中文；命令、代码、专有名词（graphify、JWT 等）保留原文。
  • 解释性内容用「人话」：面向同事阅读，不堆砌术语，必要时在括号内给出英文原名。
  • 代码示例必须给出可复制的完整命令，注明平台差异（Windows / PowerShell 与 Linux 不同处）。
  • 避免 AI 味：不用「总而言之」「首先其次最后」等空洞衔接，不用过度夸张的形容词。

7. HTML 文档布局规范

7.1 左右布局

  • 页面采用左侧固定目录 + 右侧滚动正文布局：左侧窄栏放品牌标题与完整目录，右侧区域独立上下滚动。
  • 左侧栏宽约 280px，overflow-y: auto；右侧 flex: 1; overflow-y: auto，外层 .layout { display: flex; height: 100vh; overflow: hidden; }。
  • 目录含两级结构（章节 + 子节），点击锚点跳转，当前阅读位置无需翻回顶部即可切换章节。

7.2 公共样式共享

  • 全部文档不再内联 CSS，统一引用公共样式文件 资源/文档样式.css（位于 文档/资源/），仅保留一行 <link>，避免每份文档重复携带样式。
  • 引用写法（相对路径，按文档所在层级）：
<!-- 文档/ 根级（如文档首页） -->
<link rel="stylesheet" href="资源/文档样式.css">
<!-- 文档/一级子目录/（规范、规划、资料） -->
<link rel="stylesheet" href="../资源/文档样式.css">
<!-- 文档/二级子目录/（资料/开发服务器、设计/架构设计 等） -->
<link rel="stylesheet" href="../../资源/文档样式.css">
  • 公共样式覆盖全部通用组件（布局、导航、表格、代码块、note/warn 等）；布局示意图（diagram 系列，布局设计文档用）与窄图变体（diagram-mobile）已内置。
  • 新增通用样式（多个文档复用）时：先加入 文档样式.css，再在各文档使用；仅单个文档使用的私有样式才允许内联 <style>。
  • 图形统一用 Mermaid.js 渲染（<pre class="mermaid">，见第 7.7 节）；锚点跳转靠原生 id 实现。
  • 中文字体栈："Microsoft YaHei", "PingFang SC", "Segoe UI", sans-serif；代码字体：Consolas, "Cascadia Mono", monospace（已含于公共样式）。
  • 配色使用统一的 CSS 变量（--accent、--border 等），全站风格一致（已含于公共样式）。

7.3 锚点导航

  • 每个 <h2> 设置 id，子节 <h3> 同样设置；目录链接指向对应 id。
  • 正文内首次出现的专有名词如需链接，使用相对路径或项目内文件，不引用外部站点（工具官网链接除外）。

7.4 移动端适配

  • 媒体查询 @media (max-width: 768px)：左右布局退化为上下布局，侧栏变顶栏并限制最大高度 40vh。
  • 代码块 pre 设置 overflow-x: auto，防止长命令溢出。

7.5 顶部导航栏

  • 所有生成文档在页面最顶部添加导航栏（全宽横条，位于左右布局之上），便于多级文件结构的跳转导航。
  • 内容：
    • 面包屑路径：从文档根入口（如「文档首页/总纲」）到当前文档的逐级链接，用 › 分隔。
    • 同级导航（多文件体系，如架构设计分节点文档）：当前节点的上级文档链接 + 上一页 / 下一页链接，跨文件跳转无需返回目录。
  • 实现：纯 HTML + CSS（无 JavaScript），样式沿用统一 CSS 变量（--bg、--border、--accent 等）；链接一律相对路径。
  • 首页 / 总纲文档无面包屑上级时省略上级链接，但保留同级导航入口。

结构示例（面包屑 + 同级导航，示例为「架构设计」多文件体系）：

<div class="topnav">
  <a href="../文档首页.html">文档首页</a> ›
  <a href="../设计/架构设计/01_架构设计_总览.html">架构设计</a> ›
  <span>05_架构设计_数据架构</span>
  <span class="topnav-side">
    <a href="../设计/架构设计/04_架构设计_核心交互时序.html">← 上一页</a>
    <a href="../设计/架构设计/06_架构设计_接口与集成.html">下一页 →</a>
  </span>
</div>

7.6 关联文档链接

  • 正文中首次提及项目内关联文档（《项目规划说明》、架构设计节点、其他规范、设计文档、README 等）时，必须提供可点击链接，读者点击可直接跳转查看；同一文档后续再次提及时可不重复链接。
  • 链接一律使用相对路径（相对当前文档所在目录，如 ../../规划/项目规划说明.html、../架构设计/01_架构设计_总览.html），保证目录整体迁移后仍可跳转；不得使用绝对路径，不得引用外部站点（工具官网链接除外）。
  • 链接文字用文档名（如《项目规划说明》），与正文表述一致；跨文档体系提及（如概要设计节点引用架构设计节点）时，链接指向目标文件并保持与目标文件命名一致。
  • 检查标准：正文中出现「《xxx》」或「xxx 文档」字样的首次位置应能点击跳转；生成后逐个点击验证。
本规范自身即遵循此条：正文首次提及《命名规范》处（第 5 节）即提供相对路径链接。

7.7 图形与示意图

  • 图形统一用 Mermaid.js 渲染：所有图形（时序图、流程图、状态图、甘特图、类图等）写成 <pre class="mermaid"> 文本块，浏览器加载 mermaid.min.js 后自动渲染为矢量图。
  • 禁止用 Markdown / ASCII 方式画图：不得在 <pre><code> 代码块内嵌框线字符（┌┐└┘├┤│─═）绘制图形；<pre><code> 仅用于命令、配置、代码等可复制文本。
  • 脚本引用：每份含图形的文档在 </body> 前添加（相对路径按文档层级）： 
    <script src="../../资源/mermaid.min.js"></script>
<script src="../../资源/mermaid-init.js"></script>
    mermaid.min.js（UMD 版，约 2.5MB）与 mermaid-init.js（全局初始化配置：字号/线色/字体，保证全站图样式统一）放 文档/资源/ 共享，本地 file:// 打开亦可渲染；不得引用外部 CDN（离线不可用）。
  • 时序图语法：sequenceDiagram，participant 声明参与者（中文名直接写，含特殊字符用 as 起别名），实线 ->>、返回虚线 -->>、注释 Note over；消息文本内避免 < >（需写为 &lt; &gt;）。
  • flowchart 注意：节点文本用 ["..."] 引号包裹（含 /、:、括号等字符时必需）；边标签 |...| 内出现花括号 {}（如 bms:{tenant}:i18n:{locale}）必须用双引号包裹整个标签
  • 时序图的语义必须完整保留：消息名、方向（发送/返回）、条件分支、数据流；纯命令/配置代码块保持 <pre><code> 不动。
  • 布局设计类文档的线框示意图（主框架、移动端）继续使用 diagram / diagram-mobile CSS 系列，不适用 mermaid。

8. 设计文档体系规范

BMS 的设计文档按「体系 + 总纲 + 节点」组织，位于 文档/设计/ 下。本节约束设计文档的生成与维护。

8.1 适用范围与体系定位

体系目录回答的问题稳定性
架构设计文档/设计/架构设计/技术选型与机制如何运作（分层、子系统、数据、接口、性能安全）稳定，改则牵动下游
概要设计文档/设计/概要设计/每个 MVP 模块的职责、流程、数据表、接口、权限、错误码定稿后慎改
布局设计文档/设计/布局设计/界面栅格、组件形态、交互的统一规范稳定（改则全站变）
原型设计文档/设计/原型设计/每个模块页面长什么样、点哪里去哪（可交互演示）迭代频繁（需求确认工具）
  • 生成顺序与追溯：规划 → 架构 → 概要；布局/原型服务于界面呈现；原型暴露的功能/流程问题须先修订概要设计，再同步原型
  • 概要设计不做架构级新决策；与架构设计冲突时以架构设计为准并先修订架构节点
  • 原型页面必须符合布局设计规范；与规范冲突时以布局设计为准

8.2 组织方式

  • 架构/概要/布局三体系：总纲（01）+ 节点文件，每个节点独立成文、自包含可单独阅读；总纲统一引用并维护文档地图
  • 原型设计：模块子文件夹结构——每个模块一个子文件夹，内含 01_设计说明.html（模块设计说明）与按序编号的可交互界面文件；总览维护模块地图
  • 设计文档变更（模块职责、接口、权限、机制）须先更新对应体系节点，再传导到下游文档

8.3 命名与编号规则

  • 节点文件：{两位编号}_{体系名}_{主题}.html，如 31_架构设计_子系统_表单定制.html、38_概要设计_表单定制.html；编号即阅读顺序，新增节点顺延，不与既有编号冲突
  • 原型体系：模块文件夹 {两位编号}_{模块名}（如 05_用户管理/，总览为 01 不建文件夹）；模块内文件 {两位编号}_{名称}.html，设计说明固定 01_设计说明.html，界面按阅读顺序 02 起编号
  • 文档标题与文件名对应；界面名用界面业务名称（如「用户列表页」），不堆叠「原型」等后缀

8.4 引用与追溯

  • 每个节点正文开头标注其对应的规划说明章节与上游设计节点，保证 规划 → 架构 → 概要 可追溯（如概要节点开头注明「架构设计依据 31-表单定制子系统节点」）
  • 首次提及的关联文档必须提供可点击链接（相对路径，见第 7.6 节）；节点间的「上一页/下一页」同级导航须与实际编号一致
  • 原型设计说明列出该模块全部界面并逐条链接到可交互界面文件

8.5 原型设计专项规则

  • 可交互要求：界面原型为可点击操作的 HTML（按钮反馈、Tab 切换、弹窗开关、表单录入、视图跳转），双击 file:// 打开即用，不依赖构建与联网；仅静态示意不满足「可交互原型」定义
  • 公共资源：公共原型样式与脚本放 原型设计/共享资源/（原型样式.css / 原型脚本.js），各界面统一引用，禁止各界面复制样式代码；单界面私有样式可内联 <style>
  • 原型条：每个界面顶部带原型条（返回设计说明 + 界面名），便于评审跳转
  • 模拟数据：内置假数据，交互仅前端模拟不做持久化；交互与视觉对齐实际组件（Element Plus/Vant）行为，原型即验收基准
  • 迭代记录：设计说明维护「迭代记录」表（日期/变更/状态），定稿后标注「已确认」

8.6 设计文档检查清单

  • □ 节点开头标注上游依据（规划章节/架构节点）可追溯
  • □ 节点编号与总览文档地图一致，新增节点不冲突且总览已收录
  • □ 首次提及的关联文档链接可跳转（相对路径正确）
  • □ 原型界面：可点击交互、引用 共享资源、带原型条、设计说明逐条链接界面
  • □ 原型模块文件夹与文件编号符合 8.3 规则

9. 生成流程与检查清单

  1. 收集事实：涉及工具、版本、路径时先在本机核实（如 graphify --version），禁止编造。
  2. 组织结构：按「概述 → 环境 → 部署 → 使用 → 维护 → 常见问题」常见顺序组织，编号章节。
  3. 撰写正文：中文、简洁、示例可复制，遵守第 6 节措辞规范；涉及代码/接口示例时按《命名规范》命名。
  4. 自检清单：
    • □ 左侧目录与正文标题、编号完全一致
    • □ 所有锚点链接可跳转（点击验证）
    • □ 代码块可完整复制，Windows 路径正确
    • □ 已引用公共样式 资源/文档样式.css（相对路径正确，无失效路径），无内联大段样式（仅单文档私有样式可内联）
    • □ 若引用了图片等资源，已放入「资源/同名子目录」
    • □ 文件与标题命名符合本文档第 5 节及《命名规范》
    • □ 中文通顺，无 AI 味措辞
    • □ 顶部导航栏存在，面包屑与同级链接均有效
    • □ 图形使用 HTML 结构图（seq/tree/layer/diagram），无 ASCII 框线图（7.7 节）
    • □ 提及的关联文档均提供可点击链接（相对路径），首次提及处可跳转
    • □ 设计文档遵守第 8 节（体系/编号/引用/原型规则）与 8.6 检查清单

10. 与知识图谱的关系

  • 「文档」目录是 graphify 的索引范围之一，文档变更后运行 graphify update . 保持图谱最新。
  • 新增文档后可用 graphify query 验证文档已被纳入图谱；HTML 文档会被当作内容文件索引。
  • 本文档自身同样遵循第 7 节布局规范，是布局与样式的参照样板。
