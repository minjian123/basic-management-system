1. 目的与适用范围

本规范统一 BMS 项目中文档的组织、格式与生成方式，保证 AI 助手生成的文档风格一致、 易于阅读维护。适用于「文档」目录下 AI 生成的全部文档，也约束 AI 修改用户编写的 Markdown 文档时的行为。

2. 文档格式约定

文档类型格式说明
用户手写文档 Markdown（.md） 由用户亲自编写或审定的文档，AI 只可修改，不得擅自改写格式。
AI 生成文档 HTML（.html） AI 独立撰写的新文档一律输出 HTML，避免与用户手写 md 混淆。
AI 对 md 的补充 遵循原格式 在用户 md 中补充内容时沿用原有结构、标题层级与风格。
判断依据：文档内容来源。AI 全新撰写 → html；在既有 md 上修改 → 保持 md。

3. 目录结构

文档/
├── 规划/       # 项目规划、技术选型说明（用户 md）
├── 规范/       # 各类规范文档（文档生成规范、命名规范等）
├── 资料/       # 参考资料、工具说明、AI 生成的各类文档
│   └── 资源/   # 图片、音频、视频等资源文件（见第 4 节）
└── 其他主题目录 # 按需新增，语义清晰即可

新增主题目录时遵循「功能即名字」原则，目录名用中文、简短、无歧义。

4. 资源文件管理

  • HTML 文档引用的图片、音频、视频等资源，统一放入同级目录「资源」文件夹下的同名子目录中。
  • 例：文档/资料/graphify部署使用说明.html 的图片放在 文档/资料/资源/graphify部署使用说明/。
  • 子目录名与文档主文件名保持一致（不含扩展名），便于关联与清理。
  • 引用时使用相对路径（资源/文档名/xxx.png），保证目录整体迁移后仍可显示。
  • 无资源依赖时不要创建空的资源目录；优先使用纯 CSS 方案（图标、分隔线等），减少外部文件。

5. 命名规范

  • 文档文件名：中文、与内容主题一致、不加「说明」「规范」以外的后缀堆叠。例：graphify部署使用说明.html。
  • 标题（h1 / title）：与文件名对应，格式「主题 + 文档类型」，如「graphify 部署与使用说明」「文档生成规范」。
  • 章节标题统一阿拉伯数字编号：1. 2. 3.；子节用 x.y。
  • 目录条目与正文标题文字一致，数字编号对应。
  • 项目内其他命名（代码、数据库、API、基础设施等）遵循《命名规范》，本文档只约束文档本身。
规范文档间的关系：本文档约束「文档怎么写」，《命名规范》约束「项目所有标识符怎么叫」；生成文档涉及代码/接口示例时两者同时适用。

6. 语言与措辞

  • 全部使用简体中文；命令、代码、专有名词（graphify、JWT 等）保留原文。
  • 解释性内容用「人话」：面向同事阅读，不堆砌术语，必要时在括号内给出英文原名。
  • 代码示例必须给出可复制的完整命令，注明平台差异（Windows / PowerShell 与 Linux 不同处）。
  • 避免 AI 味：不用「总而言之」「首先其次最后」等空洞衔接，不用过度夸张的形容词。

7. HTML 文档布局规范

7.1 左右布局

  • 页面采用左侧固定目录 + 右侧滚动正文布局：左侧窄栏放品牌标题与完整目录，右侧区域独立上下滚动。
  • 左侧栏宽约 280px，overflow-y: auto；右侧 flex: 1; overflow-y: auto，外层 .layout { display: flex; height: 100vh; overflow: hidden; }。
  • 目录含两级结构（章节 + 子节），点击锚点跳转，当前阅读位置无需翻回顶部即可切换章节。

7.2 自包含性

  • CSS 全部内联在 <style> 中，不依赖外链样式表、CDN 或字体。
  • 不使用 JavaScript（除非交互必需）；锚点跳转靠原生 id 实现。
  • 中文字体栈："Microsoft YaHei", "PingFang SC", "Segoe UI", sans-serif；代码字体：Consolas, "Cascadia Mono", monospace。
  • 配色使用统一的 CSS 变量（--accent、--border 等），全站风格一致。

7.3 锚点导航

  • 每个 <h2> 设置 id，子节 <h3> 同样设置；目录链接指向对应 id。
  • 正文内首次出现的专有名词如需链接，使用相对路径或项目内文件，不引用外部站点（工具官网链接除外）。

7.4 移动端适配

  • 媒体查询 @media (max-width: 768px)：左右布局退化为上下布局，侧栏变顶栏并限制最大高度 40vh。
  • 代码块 pre 设置 overflow-x: auto，防止长命令溢出。

7.5 顶部导航栏

  • 所有生成文档在页面最顶部添加导航栏（全宽横条，位于左右布局之上），便于多级文件结构的跳转导航。
  • 内容：
    • 面包屑路径：从文档根入口（如「文档首页/总纲」）到当前文档的逐级链接，用 › 分隔。
    • 同级导航（多文件体系，如架构设计分节点文档）：当前节点的上级文档链接 + 上一页 / 下一页链接，跨文件跳转无需返回目录。
  • 实现：纯 HTML + CSS（无 JavaScript），样式沿用统一 CSS 变量（--bg、--border、--accent 等）；链接一律相对路径。
  • 首页 / 总纲文档无面包屑上级时省略上级链接，但保留同级导航入口。

结构示例（面包屑 + 同级导航）：

<div class="topnav">
  <a href="../../架构设计.html">文档首页</a> ›
  <a href="01-架构设计.html">架构设计</a> ›
  <span>05-数据架构</span>
  <span class="topnav-side">
    <a href="04-架构设计-核心交互时序.html">← 上一页</a>
    <a href="06-架构设计-接口与集成.html">下一页 →</a>
  </span>
</div>

7.6 关联文档链接

  • 正文中首次提及项目内关联文档（《项目规划说明》、架构设计节点、其他规范、设计文档、README 等）时，必须提供可点击链接，读者点击可直接跳转查看；同一文档后续再次提及时可不重复链接。
  • 链接一律使用相对路径（相对当前文档所在目录，如 ../../规划/项目规划说明.md、../架构设计/01-架构设计.html），保证目录整体迁移后仍可跳转；不得使用绝对路径，不得引用外部站点（工具官网链接除外）。
  • 链接文字用文档名（如《项目规划说明》），与正文表述一致；跨文档体系提及（如概要设计节点引用架构设计节点）时，链接指向目标文件并保持与目标文件命名一致。
  • 检查标准：正文中出现「《xxx》」或「xxx 文档」字样的首次位置应能点击跳转；生成后逐个点击验证。
本规范自身即遵循此条：正文首次提及《命名规范》处（第 5 节）即提供相对路径链接。

8. 生成流程与检查清单

  1. 收集事实：涉及工具、版本、路径时先在本机核实（如 graphify --version），禁止编造。
  2. 组织结构：按「概述 → 环境 → 部署 → 使用 → 维护 → 常见问题」常见顺序组织，编号章节。
  3. 撰写正文：中文、简洁、示例可复制，遵守第 6 节措辞规范；涉及代码/接口示例时按《命名规范》命名。
  4. 自检清单：
    • □ 左侧目录与正文标题、编号完全一致
    • □ 所有锚点链接可跳转（点击验证）
    • □ 代码块可完整复制，Windows 路径正确
    • □ 无外链 CSS / JS / 字体，无失效相对路径
    • □ 若引用了图片等资源，已放入「资源/同名子目录」
    • □ 文件与标题命名符合本文档第 5 节及《命名规范》
    • □ 中文通顺，无 AI 味措辞
    • □ 顶部导航栏存在，面包屑与同级链接均有效
    • □ 提及的关联文档均提供可点击链接（相对路径），首次提及处可跳转

9. 与知识图谱的关系

  • 「文档」目录是 graphify 的索引范围之一，文档变更后运行 graphify update . 保持图谱最新。
  • 新增文档后可用 graphify query 验证文档已被纳入图谱；HTML 文档会被当作内容文件索引。
  • 本文档自身同样遵循第 7 节布局规范，是布局与样式的参照样板。
