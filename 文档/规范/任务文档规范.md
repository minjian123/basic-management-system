# 任务文档规范

> 任务文档格式契约 · 同步工具解析依据

## 1. 目的与适用范围 <a id="purpose"></a>

本规范定义**任务文档**（父任务/域总览 + 子任务文档）的固定格式，是 `scripts/tools/zentao/zentao_sync_push.py`（文档→禅道）解析任务、创建/更新禅道任务与回填排期的**强制契约**，也是 `zentao_sync_pull.py`（禅道→文档）回写状态/工时的落点格式。

- 适用于 `文档/项目/{阶段}/任务/` 下全部任务文档（阶段0 准备期已按本规范编写）。
- 本规范只约束**文档怎么写**（可被工具解析的格式）；禅道侧字段口径（主题命名、描述三段式、父任务、指派、状态与工时、录入方式）以《[项目管理规范](项目管理规范.md)》为准，两者配套。
- **强制契约**：同步工具只解析符合本规范的文档；字段缺失、行格式不符即报错停住，不静默跳过。
- 与《[文档生成规范](文档生成规范.md)》、《[需求文档规范](需求文档规范.md)》同时适用。

## 2. 文件组织 <a id="files"></a>

一个阶段的任务文档分两层（与需求域一一对应）：

```text
任务/
├── {NN}_{域名}.md                       # 父任务/域总览：父任务信息 + 子任务清单
│   └── 例：01_环境与工具链.md、02_仓库与CI.md
└── {NN}_{域名}_{编号}_{任务名}.md        # 子任务文档：一条任务一份
    └── 例：01_环境与工具链_01-5_备份体系.md、02_仓库与CI_02-3_MR流水线门禁.md
```

- 域编号两位（`01`/`02`/`03`…），与需求编号前缀、禅道父任务对应。
- 子任务文件名含**编号**（`01-5`）与**任务名**，文件名即任务主键的一部分。
- 父任务（域总览）不建对应禅道子任务，它映射禅道父任务（WBS 顶层）；子任务文档映射禅道子任务。

## 3. 父任务/域总览文档格式 <a id="parent"></a>

父任务文档固定章节：

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 域说明 | `## 1. 域说明` | `intro` | 对应禅道父任务（id）、覆盖范围、依据 |
| 子任务清单 | `## 2. 子任务清单` | `list` | 本域全部子任务汇总表（下表） |
| 工时合计 | `## 3. 工时与依赖` | `effort` | 子任务工时合计、关键依赖、风险 |

**子任务清单表**列固定为（顺序不可变，同步工具按表头定位列）：

```markdown
| 编号 | 任务 | 工时（重估） | 状态 | 完成日期 | 任务文件 |
| --- | --- | --- | --- | --- | --- |
| 01-1 | mjbk Ubuntu 基础 | 4h | 已完成 | 2026-08-15 | [01-1](01_环境与工具链_01-1_mjbk_Ubuntu基础.md) |
| 01-5 | 备份体系 | 4h | 未开始 | — | [01-5](01_环境与工具链_01-5_备份体系.md) |
```

- **编号**：`{域两位}-{序号一位}`，与需求编号、文件名编号三处一致（主键）。
- **工时（重估）**：`{数字}h`；未定填 `—`。
- **状态 / 完成日期**：口径见第 6 节。
- **任务文件**：相对链接，指向子任务文档。

## 4. 子任务文档格式（核心解析单元） <a id="task"></a>

### 4.1 任务信息表 <a id="meta"></a>

子任务文档以「任务信息」表承载全部可解析字段，表结构固定：

```markdown
# 01-5 备份体系

## 1. 任务信息 <a id="meta"></a>

| 项 | 值 |
| --- | --- |
| 编号 | 01-5 |
| 父任务 | [01 环境与工具链](01_环境与工具链.md) |
| 对应需求 | [01-5](../需求/01_需求_环境与工具链.md#r01-5) |
| 禅道任务 | 89（父任务 1） |
| 工时（重估） | 4h（禅道基线 2h，重估上调：含恢复演练） |
| 依赖 | 01-1（机械盘）、01-3（三库）、02-1（GitLab）、03-2（禅道） |
| 负责人 | minjian |
| 状态 | 未开始 |
| 完成日期 | — |
```

**字段契约**（同步工具按「项」列定位行，「值」列取值）：

| 项（固定） | 值格式 | 说明 |
| --- | --- | --- |
| 编号 | `{域两位}-{序号一位}` | 任务主键，与文件名、清单表一致 |
| 父任务 | `[父任务名](父任务文件)` | 映射禅道父任务；子任务必填 |
| 对应需求 | `[需求编号](需求文件#r{编号})` | 关联需求（story），用于互链 |
| 禅道任务 | `{id}` 或 `{id}（父任务 {id}）` 或 `—` | 禅道任务 id；未创建填 `—`，创建后由 `zentao_sync_push.py` 回填 |
| 工时（重估） | `{数字}h`（可附括号说明） | 映射禅道 `estimate`/`left`；取首个 `{数字}h` |
| 依赖 | `{编号}（{说明}）、…` | 前置任务编号，映射描述/甘特依赖 |
| 负责人 | `{账号}` | 映射禅道 `assignedTo`（当前一律 `minjian`） |
| 状态 | 见第 6 节 | 映射禅道任务状态 |
| 完成日期 | `YYYY-MM-DD` 或 `—` | 仅「已完成」有值 |

> 「禅道任务」是**唯一**承载禅道任务 id 的位置；状态/日期/工时的唯一落点也是本表。同步工具只认「任务信息」表，正文其它位置不作数。

### 4.2 任务正文 <a id="content"></a>

「任务信息」表之后固定三节，映射禅道任务描述三段式（《项目管理规范》4 节）：

| 章节 | 标题（固定） | 锚点 | 映射禅道 |
| --- | --- | --- | --- |
| 任务内容 | `## 2. 任务内容` | `content` | 描述「内容」段（编号清单） |
| 完成标准 | `## 3. 完成标准` | `accept` | 描述「完成标准」段 |
| 参考文档 | `## 4. 参考文档` | `ref` | 描述「参考文档」段 |

```markdown
## 2. 任务内容 <a id="content"></a>

1. 三库：cron 每日 02:00 dump 至 `/mnt/data/backup/{mysql,postgres,dameng}/`，保留 7 天
2. GitLab：容器内 `gitlab-backup` 每日执行，落 `/mnt/data/backup/gitlab/`

## 3. 完成标准 <a id="accept"></a>

各备份文件按期生成；至少完成一次从备份恢复的验证。

## 4. 参考文档 <a id="ref"></a>

- 《开发部署规划》第 8 节
```

### 4.3 章节顺序 <a id="order"></a>

子任务文档元素顺序固定：`# 标题 → ## 1. 任务信息（表）→ ## 2. 任务内容 → ## 3. 完成标准 → ## 4. 参考文档`。

## 5. 与禅道的映射 <a id="mapping"></a>

| 任务文档字段 | 禅道任务字段 | 说明 |
| --- | --- | --- |
| 编号 + 标题 | `name` | 主题「对象 + 动作（要点）」；编号用于幂等匹配，不入 name |
| 父任务 | `parent`（走 URL `?task={id}`） | WBS 拆解；父任务对应域总览 |
| 任务内容/完成标准/参考文档 | `desc` | 按《项目管理规范》4 节拼三段式 |
| 工时（重估） | `estimate` / `left` | 单位小时；未开始时 `left = estimate` |
| 负责人 | `assignedTo` | 创建后补指派（`left` 必填） |
| 状态 | `status`（走 start/finish/close） | 见第 6 节 |
| 完成日期 | `finishedDate` | 完成时必填 |
| 排期窗口（来自计划文档） | `estStarted` / `deadline` | 由 `zentao_sync_push.py` 从计划文档读入，见《计划文档规范》 |

**幂等匹配规则**：优先按「禅道任务 id」（已回填）匹配；未回填时按「编号 + 标题」在迭代任务列表检索；命中则更新，未命中则 `batchCreate` 创建并回填 id。子任务创建走批量入口、父级走 URL 参数（《项目管理规范》3.2、踩坑 #3/#11/#12）。

## 6. 状态与工时口径 <a id="status"></a>

任务文档「状态」取值固定为下表左列，`zentao_sync_push.py` 按右列映射到禅道任务状态（流转动作见《项目管理规范》7.1）：

| 文档状态 | 含义 | 映射禅道动作 |
| --- | --- | --- |
| 未开始 | 登记未动工 | `wait` |
| 进行中 | 已动工未完 | `doing`（`start`） |
| 部分完成 | 一部分就绪、余量未完 | `doing`（描述注明余量） |
| 已完成 | 全部达标 | `finished`（`finish` 填 `currentConsumed`/`realStarted`/`finishedDate`）再 `closed` |
| 搁置 | 主动挂起 | `wait`（描述注明搁置原因） |

- 「完成日期」仅「已完成」有值；`zentao_sync_pull.py` 回写目标为「任务信息」表的状态/完成日期两行 + 父任务清单表对应列。
- 工时规则：`estimate` 录入必填；未开始 `left = estimate`；完成必填 `currentConsumed`/`realStarted`/`finishedDate`（《项目管理规范》7.2）。

## 7. 同步工具接口 <a id="tool"></a>

| 工具 | 方向 | 对任务文档的动作 |
| --- | --- | --- |
| `zentao_sync_push.py` | 文档 → 禅道 | 解析父任务清单 + 各子任务文档，创建/更新任务、落排期，回填「禅道任务 id」 |
| `zentao_sync_pull.py` | 禅道 → 文档 | 读禅道任务状态/日期/工时，按第 6 节口径回写「任务信息」表与父任务清单表 |

两工具共用 `ZentaoClient`（`scripts/tools/zentao/`），凭据读 `deploy/.env`；均支持 `--dry-run`。调用示例：

```bash
python scripts/tools/zentao/zentao_sync_push.py --stage 00_准备期 --dry-run
python scripts/tools/zentao/zentao_sync_pull.py --stage 00_准备期
```

## 8. 检查清单 <a id="checklist"></a>

- □ 父任务域总览 `{NN}_{域名}.md` + 子任务 `{NN}_{域名}_{编号}_{任务名}.md` 命名一致
- □ 子任务清单表六列表头与顺序正确，编号唯一且与文件名一致
- □ 子任务「任务信息」表九项齐全（编号/父任务/对应需求/禅道任务/工时/依赖/负责人/状态/完成日期），缺省 `—`
- □ 任务内容/完成标准/参考文档三节齐备，映射禅道描述三段式
- □ 状态取值在第 6 节集合内；已完成才有完成日期
- □ 工时 `{数字}h` 可被提取；子任务工时合计与父任务一致
- □ `zentao_sync_push.py --dry-run` 全量解析通过、无字段报错
