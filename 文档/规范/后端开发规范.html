1. 目的与适用范围

统一 BMS 后端（backend/，FastAPI + SQLAlchemy）的开发方式，保证代码质量与协作效率。 与《命名规范》《项目规划说明》《阶段一项目骨架说明》配套；本文档只约束后端，前端见《前端开发规范》。

2. 分层职责

层目录职责禁止
接口层app/api/路由定义、参数校验（Pydantic）、鉴权与权限依赖、响应组装业务逻辑、直接操作模型
业务层app/services/业务规则、事务编排、跨仓储调用操作 Request/Response 对象、拼 SQL
数据层app/repositories/数据访问、多数据源与分片路由、查询组装业务规则、权限校验
模型层app/models/SQLAlchemy 模型声明（继承 db/base.py 基类）业务逻辑、对外暴露模型对象（用 schema 转换）
契约层app/schemas/Pydantic 请求/响应模型数据库字段直接透传（敏感字段必须显式声明）
基础设施app/core/、app/db/配置、日志、上下文、引擎、会话、模型基类业务代码

依赖方向：api → services → repositories → db；模型与 schema 是横切契约。禁止跨层调用（api 不得直接调 repositories）。

3. 代码风格

  • 格式与检查：ruff（lint + format 一体化），行宽 120；类型检查 pyright 严格模式，CI 与本地均需通过
  • 类型注解：所有函数与公开成员必须标注类型（含返回值）；禁止 Any 滥用（确需时注释原因）
  • 命名：遵循《命名规范》（snake_case 函数/变量、PascalCase 类、UPPER_SNAKE 常量）
  • 文档注释：公共函数/类写 docstring（中文，简述作用与参数）；模块头注明模块职责
  • 注释：代码内注释用中文；注释说明「为什么」，不重复「是什么」；配置类文件必须写注释说明（见第 4 节）
  • 禁止：print 调试（用 logger）、eval、全局可变状态、隐式异常吞掉

4. 配置规范

  • config.toml 必须带注释说明：每个键注释「含义 + 可选值/示例」，新加配置必须同步注释（见阶段一文档第 4 节示例）
  • 加载顺序：config.toml 公共段 → 环境段（BMS_ENV）→ 环境变量 BMS_*（最高）
  • 密钥类（DB/Redis 密码、JWT secret、MinIO 凭据、短信 AK/SK、AI API key）只走环境变量，不落 config.toml、不落库、不入镜像
  • 新增配置必须过 core/config.py 的 Settings 模型声明，禁止散落 os.getenv
  • .env.example 同步更新（只给变量名与占位值）

5. 日志规范

  • 统一 structlog：生产 JSON（Loki 聚合），dev 可读格式；禁止 print
  • request_id 贯穿请求链路；异步任务（Celery/event-worker）日志带任务 ID 或关联 request_id
  • 敏感数据脱敏：密码、token、密钥、身份证、手机号等不落日志；错误对象脱敏后记录
  • 日志级别使用规范：DEBUG 调试细节；INFO 业务关键事件（登录、审批、配置变更）；WARNING 可恢复异常；ERROR 需要处理的异常
  • 异常日志必须含上下文：操作对象 ID、租户、错误码，便于定位

6. 异常与错误码

  • 统一响应 {code, message, data}；code=0 成功，非 0 业务错误码；HTTP 状态码与业务错误码分离（4xx/5xx 表示传输层，业务错误用 200 + 业务码或 4xx + 业务码）
  • 业务异常抛 BizError(code, message)，由全局异常处理器统一转换；未知异常转 500 并记 ERROR 日志
  • 错误码：5 位，万位为模块段（分段表见规划「API 设计规范」节），段内递增；新增错误码必须先登记进错误码表（随接口契约维护），禁止复用旧码
  • 错误文案由前端按 i18n 映射，后端不拼装用户文案（message 给开发与联调用）
  • 参数校验错误用 Pydantic 默认校验 + 统一格式化，错误码归 1xxxx 段

7. API 规范

  • 内部接口一律 /api/v1 前缀；对外开放 /api/open（见规划「系统集成」节）
  • RESTful 资源式：GET/POST/PUT/DELETE；列表筛选用查询参数；分页 page/size，响应 {list, total, page, size}
  • 鉴权：除登录/刷新/健康检查外一律 Bearer token；权限校验用 require_permission("业务:动作") 依赖（两级校验：业务权限 + 动作权限，见规划「权限模型」节）
  • 写接口（审批提交、导入等）支持幂等键 Idempotency-Key 请求头
  • Schema 用 *Request/*Response 后缀（Pydantic）；响应字段显式声明，禁止直接返回 ORM 对象

8. 数据库规范

  • 模型必须继承 db/base.py 基类（雪花 ID / 审计字段 / 软删除 / 乐观锁），禁止自建 id 与审计字段
  • 表/字段命名遵循《命名规范》：表前缀 sys_/wf_/biz_/rpt_/ai_，snake_case，外键 目标表_id，布尔 is_，时间 xxx_at
  • 软删除表唯一约束建 (唯一字段, deleted_at) 复合索引；查询默认过滤 deleted_at（仓储层统一实现）
  • 多语言展示字段不入主表，按 {主表}_i18n 附表规范（见规划「核心数据表清单」）
  • 分片表：逻辑表名不带后缀，物理表带 yyyyMM；访问经 ShardingRouter，禁止直接拼物理表名
  • 索引：排序字段、外键、数据权限过滤字段必须建索引；唯一约束用唯一索引；索引命名 idx_/uq_ 前缀
  • 时间统一 UTC 存储；MySQL utf8mb4 / PostgreSQL UTF8；字符集差异由 ORM 层屏蔽，禁止方言特有类型

9. SQL 与查询规范

  • 优先 ORM/Core 查询；动态查询用查询构造器，禁止字符串拼接 SQL
  • 禁止 SELECT *（指定列）；批量写入用 bulk；事务尽量短，禁止长事务
  • 防止 N+1：循环内查询必须走 selectinload/join 或批量取数；代码走查重点项
  • 大列表游标分页（last_id + 排序键索引），常规列表 limit/offset 限深 100 页
  • 慢查询日志开启，定期走查；SQL 变更影响大表时先评估索引

10. 异步规范

  • 会话生命周期：每次请求经 get_db() 依赖创建与关闭；禁止跨请求共享 AsyncSession
  • 禁止在异步代码中直接调用阻塞 IO（requests、同步驱动、文件读写），确需时用线程池（asyncio.to_thread）
  • Celery worker 为同步进程：任务内异步业务用 asyncio.run 或独立事件循环，禁止复用请求事件循环的连接/会话
  • 并发控制：乐观锁 version 比对；需要强互斥的场景用 Redis SETNX 分布式锁（key 遵循 bms:{租户|global}:{域}:{键}）
  • 跨服务调用设置超时（httpx 短超时 + 重试），失败走降级路径，禁止无限等待

11. 测试规范

  • 分层：tests/unit（纯逻辑）、tests/integration（DB/Redis/路由）；命名 test_模块.py、函数 test_行为_期望
  • 单元测试禁止依赖真实 DB/Redis（用依赖覆盖或 mock）；集成测试用 SQLite 模拟多库，CI 中 MySQL/PostgreSQL 验证方言
  • 测试数据放 tests/fixtures 与 tests/seeds，独立种子脚本，不与初始化数据混用
  • 覆盖要求：service 层业务分支全覆盖；api 层覆盖成功 + 失败（越权、参数错、错误码）路径
  • 涉及权限的测试必须覆盖：无权限拒绝、字段权限（读过滤/写拒绝）、数据范围边界

12. 迁移规范

  • 平台库与租户库各自维护 Alembic 迁移脚本（双套环境），互不干扰
  • 脚本命名：{序号}_{说明}.py，说明用英文短句；一个变更一个迁移，禁止合并无关变更
  • 迁移脚本必须双库（MySQL/PostgreSQL）验证通过方可合入；禁止手改生产库 schema
  • SQLite 开发库自动建表（create_all），不维护 SQLite 迁移；方言敏感操作（如部分索引）在迁移内显式区分
  • 破坏性变更（删表/删列）走「新列共存 → 数据迁移 → 下线」流程，与 API 版本演进节奏一致
