## 1. 项目概述 <a id="overview"></a>

基础管理系统，主要用作后端管理，简称 BMS。支持分布式、集群部署；多租户 SaaS 架构（租户独立库），支持 SSO 单点登录，内置报表 BI 与移动端 H5。

后端基于 FastAPI + SQLAlchemy，前端基于 Vue 3 + Vite（PC 管理端 + 移动端 H5 双工程），通过知识图谱（graphify）辅助代码理解与架构分析。

## 3. 选型说明 <a id="selection"></a>

### 3.1 后端核心 <a id="sel-backend"></a>

- **Python 3.14+**：配合 uv 管理依赖与虚拟环境；语法新特性提升开发效率。版本兼容口径：阶段一骨架阶段逐依赖验证（FastAPI/SQLAlchemy/Pydantic/psycopg/Celery/SpiffWorkflow 等），任一核心依赖不兼容则整体回退 Python 3.13。
- **FastAPI**：原生异步、基于 Pydantic 自动生成 OpenAPI 文档，与异步 SQLAlchemy 天然契合；自带 Swagger UI / ReDoc，调试接口零成本。
- **Pydantic v2**：Rust 内核，校验与序列化性能数倍于 v1；作为请求/响应模型与 ORM 解耦。
- **SQLAlchemy 2.0 异步**：统一 ORM/Core 两套 API；多数据源用多个异步 engine 管理，租户独立库按 tenant 动态路由 engine（懒加载创建 + 闲置回收 + 池上限控制）。注意：异步会话不可跨请求共享，避免循环内多次查询（N+1），大事务显式声明边界。
- **Alembic**：schema 版本管理；URL 从 config.toml 读取。注意 MySQL / PostgreSQL / 达梦 DM8 方言差异需分环境验证迁移脚本。
- **SQLite / MySQL 8.x / PostgreSQL 16+ / 达梦 DM8**：开发与测试用 SQLite 零部署成本；生产三库并行支持（达梦为信创场景选配），ORM 层禁用方言特有功能（见"数据库兼容"节）。
- **aiomysql**：MySQL 异步驱动，与整体异步栈一致；同步 fallback 可换 PyMySQL（aiomysql 底层即其移植）。备选 asyncmy，性能更好但维护活跃度一般。
- **psycopg 3**：PostgreSQL 官方维护驱动，原生异步支持（dialect `postgresql+psycopg`），替代已冻结的 psycopg2。
- **dmPython**：达梦官方 Python 驱动（同步），dialect `dm+dmPython`；达梦 DM8 与 Oracle 语法兼容，方言差异大，迁移脚本与集成测试单独维护；对 Python 3.14 兼容性未知，纳入阶段一逐依赖验证，任一核心依赖不兼容则按既定口径整体回退 Python 3.13。
- **Redis（redis-py）**：官方客户端，RESP2 兼容旧版服务器；用异步客户端（redis.asyncio）配合缓存、限流、token 黑名单场景。集群环境统一走 Redis 作为共享缓存源；字典为只读热配置，另加进程内内存字典缓存（整类型 dict，版本号比对保证多实例一致，见「性能与高并发设计·缓存策略」）。
- **JWT + Redis 会话状态校验 + PBKDF2**：JWT 便于横向扩展；鉴权时随 access token 一并校验 Redis 会话有效标记（每请求一次 Redis 读，毫秒级开销），强制踢出即时生效；PBKDF2 用标准库实现。注意 access token 有效期不可过长，见"认证与安全"节。
- **authlib（SSO）**：OIDC 为主 + CAS 兼容——作为客户端接入各租户外部 IdP（Keycloak/AD/Authing 等）；同时提供 OIDC Provider 能力，其他系统以 BMS 租户用户体系为统一认证源；企业微信/钉钉免登复用同一外部身份框架。SSO 首次登录 JIT 自动建号，本地账号密码登录并存（超管应急通道）。
- **slowapi**：基于 limits 库的 FastAPI 限流方案，装饰器声明限流规则（IP / 用户 / client 维度），Redis 后端集群共享计数，Redis 故障降级 memory 后端；登录防爆破优先。
- **图形验证码**：Pillow 生成验证码图片，Redis 存储（bms:global:captcha:{uuid}，短 TTL 5 分钟），登录连续失败 3 次后强制要求，与 slowapi 限流叠加防爆破。
- **python-multipart**：FastAPI 处理表单与文件上传的必备依赖。
- **openpyxl**：Excel 读写，支撑用户批量导入与列表导出。
- **MinIO**：S3 兼容对象存储，多实例共享文件；本地开发可用文件系统模拟，生产独立部署或对接现有 S3 服务。大文件分片上传：分片临时对象存 MinIO（object key 加 .part 标识），全部上传后合并为最终对象并清理分片；集群实例无本地磁盘依赖，遵循无状态原则。孤儿分片（上传中断遗留的 .part 对象）由 Celery 定时任务回收。
- **消息文案入库 + Babel**：前后端固定文案（错误消息、按钮、提示）统一存 sys_i18n_message，页面在线维护、运行时下发（Redis 缓存），新增语言免发版；Babel 仅开发期提取消息 key 入库。业务展示文案（菜单名、字典 label、邮件模板等）走 i18n 附表；运行时通知内容按收件人 locale 渲染。用户级时区：sys_user.timezone，时间按用户偏好时区展示；数字/日期格式经 Intl API 本地化；RTL 语言由 sys_i18n_locale.rtl 标记驱动前端布局切换。
- **TOML（config.toml + 环境变量覆盖）**：单配置文件易读；部署时用环境变量覆盖敏感项（DB URL、密钥），遵循 12-factor。
- **yitter/IdGenerator**：雪花算法，分布式环境下无需中心协调即可生成全局唯一 ID；注意时钟回拨处理配置。
- **structlog**：结构化 JSON 日志，携带 request_id 贯穿请求链路，配合 Loki 跨实例聚合检索；与标准 logging 集成，不影响第三方库输出。
- **SpiffWorkflow**：Python 生态最成熟的 BPMN 2.0 引擎，解析执行标准 BPMN XML（用户任务、网关、结束事件）；同步执行，在 FastAPI 异步栈中放线程池运行；引擎本身不持久化，流程实例/任务/审批记录由 BMS 自建表维护。注意 Python 3.14 兼容性风险：若引擎暂未适配，可退回 Python 3.13。
- **Jinja2**：服务端模板渲染（邮件/通知模板、简单 HTML 页面输出，如导出预览）；邮件模板入库（sys_mail_template）支持页面在线编辑，保存前做语法校验与沙箱渲染测试，多语言内容走 i18n 附表；页面主体仍为前后端分离。
- **python-socketio**：Socket.IO 协议服务端，内置自动重连、事件机制、心跳保活；集群多实例用 Redis 适配器（socketio.RedisManager）跨实例广播消息；握手阶段校验 token 鉴权。
- **RocketMQ 5.x**：Apache 顶级项目，作事件总线（操作日志异步化、Webhook 推送、审计链按租户分区有序消费、模块解耦）；分区有序消息保证审计链顺序，事务消息兜底；消息量级远未到 Kafka 场景但保留生态与扩展空间。注意：Celery 官方不支持 RocketMQ broker，故定时任务 Celery 的 broker 用 Redis（官方支持，复用现有 Redis），事件总线与任务队列解耦。
- **Celery**：分布式任务队列，任务在 worker 间分配执行，多实例无需额外锁；broker 用 Redis，事件总线独立走 RocketMQ；定时任务用 celery beat，任务定义入库（sys_task），自研数据库调度器（beat 启动时加载、任务变更事件触发重载），页面可动态增删改与启停，执行历史落 sys_task_log；失败自动重试、ack 确认；承担孤儿分片清理、日志归档、分片表预创建等周期性任务。注意：worker 为同步进程，任务内执行异步业务须用 asyncio.run 或独立引擎，禁止跨事件循环复用连接/会话；beat 单副本运行避免重复调度。
- **aiosmtplib**：异步 SMTP 客户端，配合 Jinja2 模板发送邮件通知（审批提醒、告警）。
- **ElasticSearch 8.x**：全文检索，覆盖三类场景——主数据全局搜索（用户/部门/角色/字典/采购单据/文件元数据/帮助文章）、审计日志检索（操作/登录/开放接口/数据变更，按月索引与分片表对齐）、文件内容检索（PDF/Word/Excel/TXT，经 Celery 任务解析文本后入库索引；扫描件 OCR 由阶段十五 AI 支持）。数据同步走 RocketMQ 事件驱动异步消费（独立 event-worker 进程，复用现有事件模型；索引重建时重放事件）；ES 只承担检索匹配，返回业务 ID + 高亮，详情回查数据库取最新数据，避免双写一致性难题。索引按用途分（主数据/日志/文件），均含 tenant_id 字段，查询强制租户隔离与数据权限过滤；生产开启安全认证，MVP 单节点部署。
- **AI 能力（阶段十五）**：统一 LLM 适配层——默认接入外部大模型 API（DeepSeek/Qwen 等），敏感场景可配置私有化端点（Ollama/vLLM），API key 走 Secret 管理，模型可切换不侵入业务代码。八项能力（智能报表助手、智能审批辅助、AI 内容生成、语义搜索与文件问答、OCR 与自动分类、审计异常检测、知识库问答机器人、帮助文档智能维护）与模块的结合见"功能模块"节；向量检索用 Milvus（独立部署，依赖 etcd 与 MinIO，MinIO 已复用），embedding 管线经 RocketMQ 事件驱动（复用 event-worker）；OCR 默认本地 PaddleOCR，可切换多模态模型 API。帮助文档智能维护：输入源为功能代码（graphify 知识图谱）、设计文档与表单元数据（sys_form/sys_field/业务权限码清单），支持手动触发（维护人点击生成/更新草稿）、变更事件自动触发（菜单/表单/字段变更经 form.updated 事件驱动，自动生成更新草稿并通知维护人）、定时质量评估扫描（评估陈旧度/完整性/准确性并生成改进建议）；生成结果一律为草稿（draft），人工审核后发布，不自动覆盖已发布文章，全量落 ai_chat_log 审计。设计约束：AI 交互全量落 ai_chat_log 审计、提示词与数据不出租户边界（向量库按租户隔离、prompt 注入防护）、AI 结果默认仅辅助展示（意见、草稿、检索、告警建议）、AI 接口独立限流。AI 自动执行写操作与 AI 自动审批为两个独立可选功能，各自由 sys_config 开关控制且默认关闭，AI 自动审批依赖 AI 自动执行写操作开启（见"认证与安全"节）。
- **OpenTelemetry**：链路追踪，MVP 即接入；应用经 otel-collector 上报 trace 至 Jaeger 存储展示，trace_id 与 structlog 的 request_id 关联，随 Grafana 统一可视化（Jaeger 数据源）。

### 3.2 前端 <a id="sel-frontend"></a>

- **Vue 3 + Vite + TypeScript**：组合式 API 适合中后台业务；Vite 冷启动快；TS 提供类型安全，与后端 Pydantic schema 经 openapi-typescript 由 OpenAPI schema 自动生成 TS 类型，保持前后端契约一致。
- **Element Plus**：中文社区生态最大，后台管理组件齐全（表格、表单、树、弹窗），主题可定制；与 Vue 3 同源维护。
- **Vue Router 4 / Pinia**：官方路由与状态管理，路由守卫配合业务权限做菜单级控制；Pinia 取代 Vuex，TS 支持好。
- **Axios**：统一封装请求拦截器（注入 access token、处理 401 刷新）；响应拦截器统一错误提示。
- **vue-i18n**：中英文切换，语言偏好 localStorage 持久化；语言包运行时从后端拉取（GET /api/v1/i18n/messages，Redis 缓存 + localStorage 二次缓存），文案统一存 sys_i18n_message，页面在线维护、新增语言免发版；前端不硬编码文案。
- **SCSS**：配合 Element Plus 主题变量定制样式；避免引入重型 UI 框架外的 CSS 方案。
- **npm**：Node 官方自带包管理器，零额外依赖、不生成任何额外配置文件；frontend 与 frontend-mobile 双工程依赖与配置各自独立（各自 package-lock.json、ESLint/Prettier/TS 配置，互不共享）；CI 用 npm ci 锁定安装保证可复现。
- **ESLint + Prettier**：规范代码风格；与 Vue 官方插件链配合。
- **Vitest**：与 Vite 同构，组件/单元测试零配置，内置 coverage 统计前端覆盖率；E2E 用 Playwright——自动等待、录制器、跨浏览器，替代 Selenium。
- **bpmn-js**：BPMN 流程图建模组件，管理端拖拽绘制流程定义，导出 BPMN XML 交由 SpiffWorkflow 执行。
- **ECharts**：报表与大屏渲染，中文生态最全，图表类型覆盖管理端全场景。
- **gridstack.js**：工作台卡片与报表设计器统一使用——框架无关、活跃维护，支持网格拖拽、卡片尺寸调整与响应式断点；工作台个人布局（sys_user_preference）与角色模板（sys_dashboard_template）的 layout_config 均序列化为 gridstack 布局结构。
- **vue-flow（@vue-flow/core）**：大屏自由画布——节点自由拖拽（绝对定位）、缩放平移，配合 ECharts 渲染图表节点；与 gridstack 网格布局分工明确，互不混用。
- **vuedraggable（SortableJS 封装）**：表单设计器专用——字段排序、分组与跨分区拖拽、查询区/明细列顺序调整；与 gridstack（网格布局）、vue-flow（自由画布）三者分工：列表排序 / 网格布局 / 自由画布。
- **Vue 3 + Vant（移动端）**：frontend-mobile 独立工程，Vant 移动端组件库；复用后端 API 与会话体系，企业微信/钉钉内免登。

### 3.3 工程化与质量 <a id="sel-eng"></a>

- **uv**：Python 依赖管理 + 虚拟环境一体化，速度远超 pip；`pyproject.toml` 集中声明依赖与工具配置。
- **ruff**：lint + format 一体化，性能极高，替换 flake8/black/isort。
- **pyright**：严格类型检查，VS Code 原生支持；与 Pydantic v2 模型配合可在 IDE 中即时发现类型错误。
- **pytest + httpx**：FastAPI 测试用 ASGITransport 免启服务器；测试库统一 SQLite 保证可移植；pytest-cov 统计覆盖率并作 CI 门禁。
- **Kiwi TCMS**：测试用例唯一管理平台（mjbk 以 Docker Compose 常驻部署，复用 mjbk MySQL），手工与自动化用例统一登记（代码以用例 ID 关联）、执行结果导入归档、历史统计；用例内容中文。
- **Allure**：自动化测试报告（pytest/Playwright 结果生成，CI 产物归档）。
- **Swagger UI / ReDoc**：FastAPI 自动生成，接口联调与验收依据。
- **graphify**：知识图谱辅助代码理解与架构分析，详见《graphify 部署使用说明》。
- **禅道（ZenTao 开源版）**：全中文一体化项目管理平台（需求/任务/迭代/甘特图/看板/文档/燃尽图），官方 Docker 镜像一键部署（mjbk 常驻，宿主端口 8070）。与 GitLab CE、Kiwi TCMS 职责分工：**禅道管需求/任务/迭代/进度**（对应「开发计划与验收标准」各阶段与里程碑），**GitLab Issue 只承载代码缺陷与 MR 关联**，测试用例继续以 Kiwi TCMS 为唯一用例库（禅道测试模块不使用，自动化结果回流既定链路不变）。开源版许可 ZPL 1.2（非 OSI 认证），内部自用免费、不随产品交付无传染；引入阶段：准备期/阶段一随 GitLab 同步落地。

### 3.4 部署与运维 <a id="sel-ops"></a>

- **Docker + Docker Compose**：backend / frontend / redis / rocketmq（nameserver + broker）/ minio / 数据库 一键编排，本地与生产环境一致；开发与生产统一使用 Docker Engine + Compose（mjbk 已换装 Ubuntu 24.04.4，apt 清华 docker-ce 源直装），共用同一套 Compose 编排文件。
- **nginx**：托管前端静态资源（PC + 移动端）并反代 /api 到后端；负载均衡与 TLS 终止层；子域名租户路由。
- **MinIO**：对象存储服务，backend 多副本共享同一存储端点。
- **Prometheus + Loki + Grafana + Alertmanager**：Prometheus 采集 /metrics 指标；Loki 聚合 structlog 日志跨实例检索；Grafana 统一展示；Alertmanager 推送告警——邮件走原生 SMTP receiver，企业微信/钉钉群机器人经 webhook receiver 转 BMS 内部接口转换格式后推送；链路追踪 OpenTelemetry（otel-collector + Jaeger）随监控一并落地。
- **/healthz、/readyz**：存活探针与就绪探针分离，就绪检查依赖（DB/Redis）连通性，供编排系统滚动发布。
- **GitLab CE**：自托管 GitLab CE + gitlab-runner（Docker Compose 部署，仅作开发与 CI 基础设施，不随产品交付）；gitlab-runner 以容器方式运行（gitlab/gitlab-runner 镜像挂载 docker.sock，executor=docker，开发环境并发上限 2）；代码仓库、Merge Request、CI 流水线与容器 Registry 一体。GitHub 仓库保留为只读归档：GitLab 配置 push mirror 单向同步 main 变更至 GitHub（GitHub 侧改动不回传、不承载协作）。**外网访问边界说明**：mjbk 访问 GitHub 仅限 push mirror 同步这一处；Renovate 对自托管 GitLab 全本地运行（平台操作走本地 API），查新走各语言官方 registry（PyPI/npm/Docker Hub，均国内可达），零 GitHub 依赖——勿误以为 Renovate 需要访问 GitHub；GitHub release 类文件下载一律走 ghfast.top 镜像代理。流水线以 .gitlab-ci.yml 定义——MR 流水线：后端 ruff + pytest（含 pytest-cov 覆盖率门禁，低于门槛失败）、前端 ESLint + Vitest（含 coverage 门禁）+ 双端构建；main 流水线：另含 Playwright E2E 独立 job、MySQL/PostgreSQL/达梦 DM8 三库方言集成测试（复用开发服务器常驻三库，job 内建 bms_test 前缀独立测试库，建库 → 迁移 → 测试 → 清理）、构建镜像推送 GitLab Registry、导出 swagger.json 契约快照；测试结果生成 Allure 报告（CI 产物归档）并经官方插件导入 Kiwi TCMS 归档；main 保护分支，MR 合入需 CI 通过。依赖升级用 Renovate（原生支持自托管 GitLab，自动提 MR 升级依赖）。

## 4. 项目目录结构 <a id="structure"></a>

采用 monorepo 布局（职责见行尾注释）：

```text
bms/
├── backend/          # FastAPI 后端
│   ├── app/
│   │   ├── core/         # 配置、安全、异常处理
│   │   ├── api/          # 路由层（按模块），依赖注入
│   │   ├── models/       # SQLAlchemy 模型
│   │   ├── schemas/      # Pydantic 请求/响应模型
│   │   ├── services/     # 业务逻辑
│   │   ├── repositories/ # 数据访问，多数据源/分片路由
│   │   ├── db/           # 异步引擎、AsyncSession、读写分离路由
│   │   ├── tasks/        # Celery 任务定义
│   │   ├── ws/           # Socket.IO 连接与会话事件
│   │   └── i18n/         # 国际化管理（语言包接口、运行时翻译）
│   ├── alembic/          # 迁移脚本
│   ├── tests/            # pytest
│   ├── config.toml
│   └── pyproject.toml
├── frontend/         # Vue 3 + Vite
│   ├── src/
│   │   ├── api/          # Axios 封装与接口定义
│   │   ├── router/       # 动态路由生成
│   │   ├── stores/       # Pinia
│   │   ├── views/        # 页面（按模块）
│   │   ├── layouts/      # 主布局
│   │   ├── components/   # 通用组件
│   │   ├── i18n/         # 中英文文案
│   │   └── utils/
│   ├── package.json
│   └── .nvmrc
├── frontend-mobile/  # Vue 3 + Vant（移动端 H5：审批、通知、数据查询）
├── deploy/           # Docker Compose、nginx 配置（含 GitLab CE、gitlab-runner、Renovate 编排）
├── scripts/          # 开发期工具链（WOL / bg / graphify / 禅道 / defect / multimodal / backup / gitlab / reorder-design）
├── ops/              # 产品运维脚本（种子数据 / 备份恢复 / 租户库迁移）
├── .gitlab-ci.yml    # CI 流水线定义（GitLab CE）
├── 文档/             # 项目文档
└── graphify-out/     # 知识图谱产物
```

分层职责：api 层只做参数校验与路由分发；services 层承载业务逻辑；repositories 层承载数据访问与数据源路由，禁止在 api 层直接操作模型。

## 6. 核心数据表清单 <a id="tables"></a>

所有业务表统一规范：雪花 ID 主键、软删除（deleted_at）、审计字段（created_at/created_by/updated_at/updated_by）、乐观锁（version）、时间 UTC 存储；关联表用唯一联合主键。表名前缀：平台域固定前缀——系统表 sys_、工作流 wf_、报表 rpt_、AI 域 ai_；业务模块表采用各模块独立前缀（{模块简称}_，注册制，如采购 pur_、收付款 pay_、供应商 sup_，登记表与新增规则见"附加业务模块规划"节）。多租户库划分：平台库（bms_platform）存平台级数据（标注【平台库】），租户库（bms_tenant_{code}）一租户一库存该租户全部业务数据，未标注的表均位于租户库；另有归档库（bms_archive）统一收存各租户归档数据（带 tenant_id 与原库表标识，只读查询）；跨库引用用逻辑外键（code），不建物理外键。多语言数据规范：需多语言的展示文案不入主表，由对应 i18n 附表存储（{主表}_i18n：主表 ID + locale + 翻译字段，联合主键），查询按当前 locale 关联，缺省回退主表默认文案；运行时生成的通知内容不走附表，由 gettext 按收件人语言翻译。分片表规范：按月分片的表名带 yyyyMM 后缀（如 sys_operation_log_202608），逻辑表名不带后缀。

## 7. 权限模型 <a id="perm"></a>

采用 RBAC + 主体链 + 权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）+ 动作级数据权限：

- **主体链**：用户与角色之间可插入任意中间实体（岗位、部门等），链条任意长度（用户→岗位→角色、用户→部门→角色、用户→岗位→部门→角色…），最终权限计算统一收敛为**用户 → 角色**，多链取并集合并去重；主体角色绑定用通用表 sys_role_assign（subject_type + subject_id + role_id），新增实体类型仅扩展枚举，权限计算逻辑不变。
- **权限分层**（菜单→表单→业务、按钮→动作、字段可见可编辑）：
  - **菜单权限**：用户可看到哪些菜单入口；一个菜单必然对应一个表单（sys_menu → sys_form），授予菜单权限即隐含对应表单权限；菜单下发叠加租户模块开关过滤（停用模块的菜单在租户侧不可见）。
  - **表单权限**：具体业务表单界面和对应数据表的权限；一个表单必然对应一个业务权限（sys_form → sys_business），授予表单权限即隐含对应业务权限。
  - **业务权限**：抽象解耦层，界面不可见、不直接授予——通过"表单→业务"对照关系，由已授予的菜单/表单权限推导确定业务权限。
  - **按钮权限**：表单上所有动作按钮的权限；一个按钮必然对应一个动作（sys_button → sys_action），**默认没有任何按钮权限**。
  - **动作权限**：抽象管理概念，将具体权限设置与具体表单按钮解耦，通过"按钮→动作"对应关系关联。
  - **字段权限**：控制表单字段是否可见、可编辑；字段权限授予存 sys_role_field（role_id + form_id + field_id + visible + editable）——**默认（未授予）全部字段可见可编辑**，授予后按配置收窄：不可见字段读取载入时过滤，不可编辑字段写入保存时校验拒绝；与数据脱敏（data:plain）机制互补。
  - **数据权限**：**默认没有任何数据权限**；在动作上配置可访问数据范围（sys_data_scope：动作→范围规则），写入保存时与读取载入时均检查；匹配规则为可配置规则表达式（字段 + 运算符 + 预置变量）。
- **权限码**：命名 `业务:动作`（如 `user:create`）；业务对应业务权限（sys_business），动作对应动作权限（sys_action），动作归属业务。
- 双重控制：前端按权限码控制菜单/按钮/字段显隐，后端接口用依赖注入 `require_permission(...)` 强制校验（两级：业务权限校验表单入口与数据表访问，动作权限校验按钮对应接口）。
- 超级管理员：分两级——平台超管（sys_admin，跨租户运营：租户开通/停用/域名配置，不进入租户业务数据）与租户侧管理角色；租户侧实行完整三权分立——系统管理员（用户/岗位/部门等系统配置）、安全管理员（角色/业务/动作/数据范围/密码策略/IdP 配置）、审计管理员（只读全部日志与审计数据），三类内置角色权限互斥、同一用户不得兼任；租户开通首建系统管理员账号，由其创建另两类管理员。
- 租户边界：数据权限规则解析结果强制叠加租户过滤，任何规则不得跨租户；业务/动作权限码跨库引用用 code 逻辑外键。

## 8. API 设计规范 <a id="api"></a>

- 前缀：全部接口 `/api/v1`。
- 统一响应：`{code, message, data}`；code=0 成功，非 0 为业务错误码；HTTP 状态码与业务错误码分离。
- 错误码：平台段 1xxxx~9xxxx 为 5 位数字，万位为模块段、后 4 位为段内序号；附加业务模块扩展段 10xxxx 起升为 6 位（两位段号 + 段内 4 位序号，分配见"附加业务模块规划"节），结构统一为"模块段 + 段内序号"，一经发布稳定不变；文案由前端按 i18n 映射，后端不承担文案拼装。平台分段表：

| 段 | 区间 | 覆盖模块 |
| --- | --- | --- |
| 1xxxx | 10001-19999 | 通用（参数校验、限流、系统内部） |
| 2xxxx | 20001-29999 | 认证（登录/刷新/登出/验证码/找回密码/会话） |
| 3xxxx | 30001-39999 | 用户与组织（用户/部门/角色/权限/三权分立） |
| 4xxxx | 40001-49999 | 系统配置（菜单/字典/系统参数/国际化语言包） |
| 5xxxx | 50001-59999 | 文件（上传/下载/分片/导入导出） |
| 6xxxx | 60001-69999 | 工作流（流程定义/实例/待办/审批/会签） |
| 7xxxx | 70001-79999 | 通知/邮件/任务调度 |
| 8xxxx | 80001-89999 | 开放接口/Webhook/租户/SSO |
| 9xxxx | 90001-99999 | 报表/审计/归档/监控 |

- 分页：查询参数 `page`（从 1 起）、`size`；响应 `{list, total, page, size}`。
- 命名：RESTful 资源式（GET /users、POST /users、PUT /users/{id}、DELETE /users/{id}），列表筛选用查询参数。
- 鉴权：除登录/刷新/健康检查外一律 Bearer access token；权限校验用 `require_permission` 依赖。
- 租户识别：生产环境按子域名解析租户（{tenant}.bms.example.com），开发环境以 access token 内 tenant_id 兜底；一人多租户经 X-Tenant-ID 请求头切换并重发 token。
- 幂等：审批提交、Excel 导入等写接口支持幂等键（请求头 Idempotency-Key）；实现为 Redis SETNX 前置拦截 + 幂等键字段唯一约束兜底。
- 对外开放：外部系统走独立前缀 /api/open，与内部接口隔离，见"系统集成"节。
- 版本演进：破坏性变更升级大版本（/api/v2），新旧版本并行至少一个发布周期后下线旧版；非破坏性变更在版本内演进。
- 生产环境关闭 Swagger/ReDoc；OpenAPI 契约由 CI 导出快照分发。

## 9. 系统集成 <a id="integration"></a>

与其他系统的接口连接方案：

### 9.1 对外 API（外部系统调 BMS） <a id="integ-out"></a>

- 鉴权：OAuth2 Client Credentials——client_id/secret 换取 access token（自签 JWT，短 TTL），支持 scope（接口权限范围）、独立撤销、调用审计。
- 防重放：/api/open 请求强制携带 X-Timestamp（服务器时间 ±5 分钟窗口，超窗拒绝）与 X-Nonce（随机唯一串，Redis SETNX 去重、TTL 与窗口对齐，重复拒绝）；与 Client Credentials + IP 白名单叠加构成三重防护。
- 路由：独立前缀 /api/open，与内部接口隔离；按 client 维度独立限流。
- 开放范围：全量 CRUD 按 scope 控制；安全默认——scope 最小化分配，写接口（POST/PUT/DELETE）需显式授予，未授予一律拒绝。
- 契约：OpenAPI 文档（swagger.json）作为集成契约；CI 构建时导出快照存档，随版本分发给外部系统；生产环境关闭在线文档端点。
- BMS 兼作 IdP：对外提供 OIDC Provider（授权码流程），第三方系统以 BMS 租户用户体系实现单点登录；客户端注册复用 sys_client。

### 9.2 出站集成（BMS 调外部） <a id="integ-in"></a>

- 同步调用：httpx 统一封装（超时/重试/熔断，复用降级机制）。
- 事件推送：Webhook 订阅——事件发生后经 RocketMQ 事件总线异步推送至注册 URL，HMAC 签名校验、指数退避重试、失败记录。

### 9.3 事件总线事件模型 <a id="integ-event"></a>

事件命名 `{域}.{动作}`，经 RocketMQ 事件总线发布，Webhook 订阅按事件名匹配。默认清单（开发期可扩展）：

| 事件 | 触发时机 | 主要载荷 | Webhook 订阅 |
| --- | --- | --- | --- |
| user.created / user.updated / user.deleted | 用户创建/修改/删除后 | 用户 ID、username、dept_id、status | 是 |

## 10. 多数据源策略 <a id="datasource"></a>

支持三层数据架构（分层设计，逐层可选）：

1. **多业务库并存**：config.toml 声明多个数据源（每库含主从连接）；SQLAlchemy 2.0 多异步 bind；repositories 层按模块指定数据源。**多租户落地于本层**：一租户一独立库，平台库 sys_tenant.db_key 指向数据源配置，请求按租户路由到对应异步 engine（懒加载创建、闲置回收、池上限控制）；新租户开通自动建库+迁移+种子；Alembic 批量迁移遍历全部租户库。
2. **主从读写分离**：每个业务库可配一主多从；AsyncSession 工厂按读写标记选择异步引擎，写操作与事务强制走主库。
3. **分库分表**：抽象 ShardingRouter 层（分片键 → 物理库/表解析），真实分片规则 MVP 落地——sys_operation_log 与 sys_open_log 按月分表（分片键=时间，物理表名带 yyyyMM 后缀），新月份分片表由 Celery 定时任务提前创建；分片键支持按租户/按时间，由接入模块声明；Python 生态无成熟分片中间件，采用应用层自研路由。

迁移策略：Alembic 按数据源分别维护迁移脚本，只管理各库 schema；租户库批量迁移遍历 sys_tenant。开发环境用多个 SQLite 文件模拟平台库、租户库与归档库；主从路由、分片路由与归档流转以集成测试覆盖。

## 11. 数据库兼容 <a id="dbcompat"></a>

- 开发环境默认 SQLite，生产同时支持 MySQL 8.x、PostgreSQL 16+ 与达梦 DM8（信创选配）。
- ORM 层禁用方言特有功能：JSON 等类型使用跨方言通用类型（达梦 JSON 支持有限，用通用类型兜底），分页统一 limit/offset。
- Alembic 维护 MySQL / PostgreSQL / 达梦 DM8 三套方言迁移；SQLite 开发库自动建表。
- 测试环境与开发环境一致使用 SQLite。

### 11.1 数据规范 <a id="dbrule"></a>

- 主键：业务表统一雪花 ID（yitter/IdGenerator），关联表用联合主键。
- 软删除：业务数据软删除（deleted_at 时间戳），审计类数据物理保留；查询默认过滤已删除；业务唯一约束统一建为 (唯一字段, deleted_at) 复合唯一索引——未删行 deleted_at 为 NULL，SQLite/MySQL/PostgreSQL/达梦 DM8 四库均允许多个 NULL 不冲突（达梦按 Oracle 兼容口径，阶段一验证），删除时写入时间戳即释放唯一键；PostgreSQL 可另加部分唯一索引优化。软删除数据进回收站（recycle 业务：查看/恢复），恢复即清除 deleted_at，恢复动作落操作日志与字段级审计；过期软删除残留由 Celery 定时物理清理。
- 审计字段：created_at / created_by / updated_at / updated_by，由 ORM 事件自动填充。
- 乐观锁：version 字段，更新时比对，防止多实例并发覆盖。
- 时间：统一 UTC 存储，前端按本地时区展示。
- 多语言：固定文案存 sys_i18n_message（页面维护）；业务展示文案由 {主表}_i18n 附表按 locale 存储，查询关联当前 locale，缺省回退主表默认文案；语言清单 sys_i18n_locale 动态扩展，rtl 标记驱动布局。
- 字符集：MySQL utf8mb4、PostgreSQL UTF8、达梦 DM8 UTF8。
- 索引：排序字段、外键、数据权限过滤字段必须建索引；唯一性约束用唯一索引。
- SQL 规范：禁止 SELECT *；批量写入用 bulk；事务尽量短；定期走查慢查询日志。

## 12. 认证与安全 <a id="security"></a>

- 双 token：access token（30 分钟）+ refresh token（14 天，滚动轮换）。
- SSO 单点登录：OIDC 为主 + CAS 兼容——登录页展示租户配置的 IdP 入口（sys_identity_provider），外部 IdP 认证回跳后经 sys_user_identity 全局映射定位租户并 JIT 自动建号，签发 BMS 双 token；本地账号密码登录并存（超管应急通道，防 IdP 故障锁死）。
- 移动端免登：企业微信/钉钉内嵌 H5 走各自 OAuth 免登，复用外部身份框架；手机浏览器走账号密码/SSO。
- 存储：access token 仅存前端内存（刷新页面后静默续期）；refresh token 存 httpOnly + Secure + SameSite cookie，防 XSS 窃取；CSRF 采用双重提交校验（SameSite=Lax + 自定义请求头校验）。
- 密码：PBKDF2 哈希（标准库）；登录失败限流（slowapi，Redis 后端，如 5 次锁 15 分钟），连续失败 3 次后登录页强制图形验证码。
- 密码与账号策略（sys_config 可配）：复杂度校验（长度/字符组合）、90 天有效期强制改密（pwd_changed_at 驱动）、近 5 次历史密码不可重复（pwd_history）、180 天未登录自动锁定（定时任务扫描 last_login_at）。
- 找回密码：登录页自助找回，邮箱与企业微信/钉钉双通道——输入已登记邮箱发送含短时效 token 的重置链接，或经企业微信/钉钉内身份验证；token 存 Redis（TTL 15 分钟、单次有效）；重置链接/验证码申请叠加 Redis 限流防滥用；重置成功后强制失效该账号全部会话。
- 数据脱敏：敏感字段（手机号/邮箱/身份证等）注册标记，序列化层默认掩码展示（如 138****5678）与导出脱敏；持 data:plain 权限码方可查看明文。
- 登出：refresh token 加入 Redis 黑名单即时失效。
- 多端会话：允许同一账号并发登录，但活跃会话数设上限（默认 5 个，sys_config 可配），超出后最旧会话自动失效；登录产生独立会话记录（sys_session）；会话有效标记存 Redis，鉴权时随 access token 一并校验；管理端可查看在线会话并强制踢出——作废该会话 refresh token 并失效 Redis 会话标记，踢出即时生效，同时经 Socket.IO 广播"会话失效"关闭该会话全部实时连接。
- 密钥管理：JWT secret 支持轮换（新旧并行验证期），DB/Redis/MinIO 凭据走 Secret 管理，不落库不入镜像。
- 上传安全：文件类型白名单 + 大小上限（默认 20MB，超限走分片上传，单文件上限可配置如 2GB）+ 分片 SHA256 校验 + 整文件校验，存储于 MinIO 私有桶；下载用预签名 URL（限时有效），后端不代理文件流。
- 基础防护：ORM 参数化防 SQL 注入、Element Plus 默认转义防 XSS、接口级限流（slowapi，Redis 后端）。
- 日志：登录日志、操作日志落库；操作日志的 action 记录权限码（业务:动作，与权限体系对齐）；敏感字段（密码、token、密钥）脱敏后记录，不落原始值。
- AI 安全（阶段十五）：AI 交互全量落审计（ai_chat_log），提示词与响应不出租户边界；RAG 检索上下文遵守动作级数据权限范围；prompt 注入防护（角色隔离、指令约束、输出校验）；AI 结果默认仅辅助展示。AI 自动执行写操作（ai.auto_execute）与 AI 自动审批（ai.auto_approve）为两个独立功能，各自由 sys_config 开关控制、默认关闭——ai.auto_approve 依赖 ai.auto_execute 开启（未开启时配置拒绝保存并强制关闭）；开启时仅限配置白名单（写接口、审批节点），执行前强制二次确认，自动执行全量落 ai_chat_log 与操作日志、结果可人工撤销；AI 接口独立限流与预算控制。

## 13. 审计合规 <a id="audit"></a>

- 字段级变更审计：关键表（sys_user、sys_role、sys_role_assign、sys_role_permission、sys_role_field、sys_post、sys_dept、sys_notice、sys_tenant_quota、sup_supplier、wf_process、pur_purchase_*、pay_payment_*、pay_receipt、pay_refund 等）经 ORM 事件自动记录字段级旧值/新值至 sys_data_audit_log，按月分表。
- 哈希链防篡改：审计类日志（操作/登录/开放接口/数据变更）逐条哈希串联（prev_hash + record_hash），分片表内成链、跨月表首尾衔接；写入经 RocketMQ 按租户分区有序消费保证链序；提供链校验工具定期巡检。
- 三权分立：系统管理员/安全管理员/审计管理员权限互斥（见"权限模型"节），满足等保管理要求。
- 合规留存：审计数据 90 天热表 + 归档冷存储，哈希链随归档一并导出供事后校验；归档前执行链完整性校验，链完整方可归档；合规销毁（含审计数据销毁）记录销毁日志备查。

### 13.1 法律合规 <a id="legal"></a>

- **等级保护**：目标定级**等保三级**（与三权分立、审计哈希链设计匹配），安全建设贯穿各阶段（12 节认证与安全、本节审计合规为对应技术措施）；定级备案与正式测评**按需启动**——商业交付合同明确要求时执行（测评费用与周期列入交付成本与排期），自用 / 内部部署不强制、不作为 GA 前置；测评结果存档备查。
- **个人信息保护（PIPL）**：系统收集手机号 / 邮箱 / 身份证号等个人信息，其中身份证号属敏感个人信息——遵循最小必要采集（表单元数据不强制收集非必要字段）、处理告知同意由租户侧完成、界面默认脱敏展示与导出脱敏（data:plain 明文权限已有）、明文查看全量落操作日志；租户作为个人信息处理者，BMS 提供技术支撑能力（字段级审计、脱敏、销毁留痕）。
- **数据安全（数安法）**：数据分类分级——客户与供应商信息、收付款流水列为重要数据，从严管控（访问审计 + 导出审批 + 归档加密存储）；销毁动作留销毁日志备查（合规留存已有）。
- **涉外场景预留**：i18n 支持 RTL 语言暗示潜在海外交付，若服务涉及境外用户或数据出境，另行评估 GDPR 合规与数据出境安全评估要求，不在 MVP 范围。


## 14. 性能与高并发设计 <a id="perf"></a>

### 性能目标

- 目标：≥ 500 并发用户，P99 响应 ≤ 1s（登录、列表查询、审批提交主链路）；验收前压测验证。

### 可用性目标与 SLO <a id="slo"></a>

- **可用性目标**：99.9%（月累计不可用 ≤ 约 43 分钟），为生产多副本部署后的稳态目标；MVP 单机 Compose 部署受单机房约束，实际可用性以该值为改进方向、不作为验收门禁。
- **核心链路 SLO**（Alertmanager 告警阈值锚点）：登录成功率 ≥ 99.9%；列表查询 P99 ≤ 1s；审批提交成功率 ≥ 99.95%；Socket.IO 待办推送延迟 P95 ≤ 2s；备份任务每日成功。
- **告警分级**：警告（SLO 逼近阈值，如 P99 连续 5 分钟超 800ms）→ 工作时间处理；严重（错误率突增 / 依赖宕机 / 备份失败 / 审计链校验失败）→ 立即通知（企业微信 + 钉钉 + 邮件三通道并发）；阈值与分级配置随运维手册（阶段九）交付。

### 部署规模与连接规划

- uvicorn 多 worker 部署（如 4 worker）；连接池 pool_size / max_overflow 按 worker 数规划，确保 总连接数 = worker × (pool_size + max_overflow) ≤ 数据库 max_connections 的 70%；多租户场景按活跃租户数规划连接（engine 懒加载 + 闲置回收），避免全量租户连接常驻。
- 每个 worker 独立连接池；写事务尽量短，避免长事务占用连接。

### 缓存策略

- 只读热数据（字典、系统参数、菜单树、业务/动作权限码）Redis 缓存，短 TTL；多语言数据缓存键含 locale 维度；租户数据缓存键含 tenant 前缀。
- 字典内存缓存：字典为只读热配置，后端另设进程内内存字典缓存（dogpile.cache 统一管理，双 Region：小字典整类型 + 超大字典已查条目局部子集）；一致性靠全局版本号 `bms:{tenant}:dict:version` 惰性比对（字典变更 INCR 版本，各实例下次请求发现版本变化自动重载）；后端业务翻译（导出/通知/报表/审批/明细行批量）与字典查询接口共用该内存缓存，零网络往返；超大字典批量翻译走「局部缓存 + 一次性 IN 查询」防 N+1（1000 行明细 × 30 字段 = 30 次而非 30000 次查询）。
- Redis key 命名规范：统一格式 `bms:{租户标识|global}:{域}:{业务键}`，如 bms:global:captcha:{uuid}、bms:global:token:blacklist:{jti}、bms:{tenant}:sess:{session_id}、bms:{tenant}:dict:{locale}:{type}、bms:global:rate:{维度}:{目标}；所有 key 必须携带 TTL——缓存类短 TTL + 随机偏移，持久状态类（token 黑名单、会话标记、分布式锁、幂等键）TTL 与业务有效期对齐；租户数据 key 必含租户前缀，平台数据用 global。
- 三防：穿透（查询不存在的数据缓存空值）、击穿（热点 key 过期用互斥锁 SETNX 单实例重建）、雪崩（过期时间加随机偏移）。
- 一致性：先写库后删缓存；写操作后同一会话内读主库，避免读到从库旧数据。

### 分页与查询

- 常规列表 limit/offset（限深 100 页）；大数据量列表（如操作日志）游标分页兜底（last_id + 排序键索引）。
- 排序字段、外键、数据权限过滤字段必须建索引；禁止 SELECT *；批量写入用 bulk；N+1 走查。

### 限流与降级

- 接口级限流：slowapi（limits 库，Redis 后端，IP / 用户维度），登录限流优先。
- 降级：Redis 故障→缓存失效直连 DB + 日志告警，限流降级为 memory 后端；主库故障→只读模式（从库响应查询，写接口返回明确错误）；接口熔断→对耗时异常的依赖调用快速失败（短超时、重试幂等）。

### 超时与资源

- DB 连接/执行超时、Redis 操作短超时快速失败（如 500ms）。
- 操作日志/登录日志：经 RocketMQ 异步写入降低主库写压力。
- 慢查询日志开启，定期走查。

## 15. 前端页面清单与菜单机制 <a id="pages"></a>

### 16.1 测试计划与阶段 <a id="test-plan"></a>

- **阶段安排**：不设独立测试阶段，测试活动并入各阶段完成标准（模块接口测试、关键链路 E2E 抽样、CI 三库方言集成测试随模块交付，详见"开发计划与验收标准"节）；MVP 验收前集中执行全量回归、安全专项、压测、UAT 与探索性测试。
- **个人开发 + AI 辅助总则**：单人开发人力有限，测试资产以自动化为主——手工用例仅覆盖自动化不可覆盖的场景（UI 视觉、真机体验等）；用例初稿由 AI 依据概要设计与验收标准批量生成、人工审核后登记 Kiwi TCMS；E2E 用例以 Playwright 录制器 + AI 补全断言辅助编写，不逐条手写。
- **执行方式**：全量回归、三库集成测试、压测等重负载执行以 CI（mjbk 服务器 GitLab Runner）为主，不占本地开发资源；本地仅在明确需要时小范围执行（执行前与开发确认，不影响开发）。
- **测试环境**：test 环境部署于 mjbk，用于联调、回归与验收，与 dev 隔离；Kiwi TCMS 平台同机部署（见"环境与配置"节三套环境）。
- **用例管理（Kiwi TCMS）**：mjbk 以 Docker Compose 常驻部署 Kiwi TCMS（复用 mjbk MySQL，数据持久化并纳入备份），作为唯一用例库——手工用例与自动化用例统一登记（含用例编号），测试代码以用例 ID 标注关联；pytest/Playwright 执行结果经官方插件导入平台归档，平台统计执行情况与历史；用例名称/描述/分类使用中文，按模块分类（Category）+ 标签（Tag）组织，承载前端大量页面产生的 E2E 用例；界面以官方简体中文翻译为主、浏览器自动翻译兜底；平台缺陷链接指向 GitLab Issue。
- **用例设计方法**：等价类划分/边界值/场景法/错误推测；关键业务链路（审批、权限、收付款、归档）用场景法覆盖主路径与异常路径。
- **优先级与风险分析**：用例按 High/Medium/Low 三级优先级，核心模块（认证/RBAC/工作流/审计/收付款）高风险用例优先设计与执行。
- **可追溯性**：用例与模块/功能点及"开发计划与验收标准"节验收项双向追溯（用例 ID 标注所属模块与对应验收项），保证需求全覆盖、无孤儿用例。
- **稳定性/可靠性测试**：MVP 验收前对核心链路（审批、Socket.IO 推送、任务调度）执行 7×24 长稳运行与故障恢复演练（含备份恢复演练，见"部署与运维"节），结果入测试报告。
- **用户验收（UAT）**：MVP 验收前先执行 E2E 全量回归作自动化预走查，再由开发者按"开发计划与验收标准"节验收清单抽检关键链路与界面体验；发现缺陷走缺陷管理流程，验收通过后验收记录存档。
- **探索性测试**：MVP 验收前由开发/用户对新功能区开展探索性测试（发现脚本化用例覆盖不到的缺陷），发现项入缺陷库。

### 16.2 缺陷管理 <a id="test-defect"></a>

- **载体**：GitLab Issue + Milestone（按阶段/版本关联），测试平台缺陷链接指向对应 Issue。
- **分级**：P0（阻断主流程/数据安全）、P1（严重功能缺失/可用性降级）、P2（一般缺陷）、P3（轻微/建议）。
- **流程**：上报（含复现步骤与关联用例 ID）→ 指派修复 → CI 回归验证 → 关闭；P0/P1 缺陷阻断 MR 合入，修复后回归通过方可合入。
- **自动上报**：MR 与 main 流水线任一自动化测试失败即由 `scripts/tools/defect/defect_capture.py` 自动归档 REPRO 复现包（现场 dump + 失败堆栈/日志 + repro.json + REPRO.md）并自动创建/复用 GitLab Issue（fingerprint 去重、defect-auto 标签），细节见《[测试规范](../规范/测试规范.md)》9 节。
- **AI 辅助修复（双轨）**：指派修复环节由 AI 修复代理（`scripts/tools/defect/ai_fix.py`）处理——按复现包定位根因并生成补丁：本地模型（LM Studio，内网、零费用）优先；定位不了或置信度低时经敏感信息过滤（dump 内容严禁外发）升级云端模型；bot 推送 `fix/defect-*` 分支并提 MR（描述引用 Issue 指纹），**人工 review 后合入、CI 回归通过后人工关闭**，AI 不自动合入/关闭；复现验证用 `scripts/tools/defect/reproduce.py`（检出 commit + 导入 dump + 跑用例）。

### 16.3 回归策略 <a id="test-regression"></a>

- **冒烟回归**：每次 MR 与发版前执行——登录（含图形验证码）、主体链 RBAC 权限（按钮显隐与字段权限）、核心 CRUD 主链路。
- **全量回归**：每阶段末与 MVP 验收前执行全部自动化用例（单元/接口/前端组件/E2E），结果导入 Kiwi TCMS 归档。

### 16.4 进入与准出标准 <a id="test-exit"></a>

**进入准则**（进入全量回归与 UAT 的前置条件，同时满足）：

- 冒烟回归通过（登录、主体链 RBAC、核心 CRUD 主链路）；
- CI 流水线绿色（单元/接口/前端组件测试通过）；
- 用例就绪：Kiwi TCMS 用例登记完成，用例 ID 与代码关联一致。

**准出标准**（阶段交付与 MVP 验收，同时满足）：

- P0/P1 缺陷清零；
- 功能用例通过率 ≥ 98%；
- 安全专项用例集全部通过；
- 压测达到 500 并发 / P99 ≤ 1s；
- MySQL/PostgreSQL/达梦 DM8 三库 CI 通过；
- 代码覆盖率达标：核心模块（认证/RBAC/工作流/审计/收付款）行覆盖 ≥ 80%、整体 ≥ 70%，CI 门禁（后端 pytest-cov、前端 Vitest coverage），低于门槛流水线失败。

### 16.5 测试报告 <a id="test-report"></a>

- **自动化报告**：后端 pytest + Allure、前端 Vitest/Playwright 生成自动化测试报告（CI 产物归档）。
- **阶段汇总报告**：每阶段末输出测试汇总报告（用例执行统计、缺陷统计、覆盖率、风险与遗留项），纳入"文档计划"节交付项；**由 CI 数据（pytest/Allure/Kiwi TCMS 结果、覆盖率、GitLab 缺陷统计）脚本汇总并经 AI 生成初稿，人工补充风险与遗留项结论**；MVP 验收前输出总测试报告。
- **测试复盘**：阶段末报告含经验教训小节（测试过程问题与改进项），MVP 验收后整体复盘一次。

## 17. 环境与配置 <a id="env"></a>

- 三套环境：dev / test / prod，config.toml 按环境分层（BMS_ENV 指定）+ 环境变量覆盖。
- 开发环境依赖（Redis/RocketMQ/ElasticSearch/MinIO）由 Docker Compose 统一提供，本地不安装原生服务；Milvus（含 etcd）随阶段十五 AI 一并加入 Compose。
- 项目管理平台禅道（ZenTao 开源版）随阶段一部署于开发服务器 mjbk（Docker Compose 常驻，宿主端口 8070，见《开发部署规划》第 4.3 节）。
- 后端 Python 版本：`.python-version` 固定 3.14，uv 自动管理解释器。
- 前端 Node 版本：`.nvmrc` 固定（≥ 20.19），volta/fnm 管理。
- 密钥类配置只走环境变量，不入配置文件、不入库。
- CORS：dev 环境放行前端开发服务器跨域；生产由 nginx 同源反代，不开放跨域。
- 租户域名：生产泛域名 DNS（*.bms.example.com）+ 泛 TLS 证书；dev 环境以 token 租户标识替代子域名。
- git 分支：**单人开发期（2026-08-23 起）直推 main，不走 MR**——尚无基本产品且单人开发，MR 门禁收益为零、流程开销显著；含代码改动由 main 流水线自动冒烟验证。**MR 全流程暂缓**至产品成型或多人协作期恢复，恢复时口径：main 保护分支，feature 分支经 PR 合入（CI 通过方可合并），不设强制人工批准——核心模块（认证/RBAC/工作流/审计/收付款）改动提交前经 **AI 交叉评审**（本地模型优先），MR 描述附评审结论；多人协作期再启用"≥1 名 reviewer 批准 + 核心模块作者外确认"；AI 修复代理提交的 fix/defect-* 分支仍人工 review 后合入（16.2 节）。暂缓说明见《[Git协作规范](../规范/Git协作规范.md)》。

## 19. 部署与运维 <a id="deploy"></a>

### 19.1 部署拓扑 <a id="deploy-topo"></a>

- 入口：nginx（TLS 终止、/api 反向代理、前端静态资源托管）→ backend 多副本（无状态，可横向扩展）。
- 数据层：MySQL / PostgreSQL 主从（读写分离 + 故障切换，1 平台库 + N 租户库 + 1 归档库）/ 达梦 DM8（信创环境选配，DM 数据守护做主从）+ Redis（Sentinel/Cluster 高可用，key 含租户前缀）+ RocketMQ + ElasticSearch + Milvus（阶段十五）+ MinIO（按租户 bucket 前缀隔离，归档文件亦存于此）。
- 监控：Prometheus + Loki + Grafana + Alertmanager + Jaeger（trace 存储展示，otel-collector 统一采集）。

### 19.2 集群设计要点 <a id="deploy-cluster"></a>

- **无状态**：JWT 无状态（会话有效标记存 Redis，鉴权顺带校验，毫秒级开销）；token 黑名单、限流计数存 Redis；文件存 MinIO；定时任务由 Celery 分布式执行——任一实例可随时停机、随时扩容。
- **缓存一致性**：统一走 Redis 作为共享缓存源；一般业务数据不引入本地内存缓存（多实例内存独立会造成数据不一致）；字典为只读热配置例外——进程内内存字典缓存（整类型 dict + 全局版本号 `bms:{tenant}:dict:version` 惰性比对，多实例天然同步）。
- **分布式锁**：Redis SETNX 实现，用于防并发与幂等拦截（幂等键前置去重，唯一约束兜底）。
- **实时推送**：Socket.IO 连接分散于各实例，经 Redis 适配器广播；强制踢出时广播"会话失效"事件（HTTP 接口侧由 Redis 会话标记校验同步拦截）。
- **分布式限流**：slowapi（limits 库）Redis 后端（登录防爆破已采用），Redis 故障降级 memory 后端。
- **连接池**：各数据源配置 pool_size / max_overflow，避免实例增多时连接耗尽。
- **数据库高可用**：主从 + 故障切换策略；读写分离期间定义主库故障预案（从库提升）。
- **消息队列高可用**：RocketMQ 多副本（broker 主从、同步刷盘 + 消息持久化），节点故障消息不丢（生产部署 RocketMQ 集群，MVP 单机）；Celery（Redis broker）beat 单副本运行（避免重复调度），worker 多副本横向扩展。
- **检索高可用**：ElasticSearch 生产多节点集群（索引多副本、故障自动分片迁移），MVP 单节点；检索数据可经事件重放全量重建索引，检索服务故障时可降级为数据库模糊查询兜底。
- **配置与密钥**：config.toml + 环境变量覆盖；密钥（DB/Redis 密码、JWT secret、MinIO 凭据）走 Secret 管理（K8s Secret / Docker secrets），不落库、不入镜像。

### 19.3 基础设施编排 <a id="deploy-compose"></a>

- 初版 Docker Compose：backend（多副本）+ celery-worker（多副本）+ celery-beat（单副本）+ event-worker（RocketMQ 事件消费者，多副本）+ frontend（nginx，托管 PC + 移动端静态资源）+ redis + rocketmq（nameserver + broker）+ elasticsearch + milvus（含 etcd，MinIO 复用）+ minio + 数据库（按环境选择 MySQL、PostgreSQL 或达梦 DM8）+ 监控（Prometheus/Loki/Grafana/Alertmanager）+ jaeger（trace）+ otel-collector。
- nginx 需支持 WebSocket：/socket.io 路径放行 Upgrade/Connection 头；负载均衡用 ip_hash / Cookie 亲和（sticky session）——Socket.IO 连接升级后必须固定在同一后端实例。
- 健康检查：/healthz（存活）、/readyz（依赖就绪），供编排系统滚动发布。
- TLS 与 HTTPS：nginx 层配置，cookie Secure 标志随环境启用。
- 安全响应头：nginx 统一配置 CSP、HSTS（dev 环境关闭）、X-Frame-Options（SAMEORIGIN，兼容同源 Grafana 嵌入）、X-Content-Type-Options、Referrer-Policy、Permissions-Policy。
- 演进：数据量或部署规模增长后迁移 Kubernetes。
- 优雅停机：SIGTERM 后停止接收新请求、等待在途请求完成，配合 K8s preStop / terminationGracePeriod 配置。

### 19.4 备份与恢复 <a id="deploy-backup"></a>

- 数据库：每日全量备份 + 开启 Binlog/WAL（时间点恢复 PITR），达梦 DM8 用 dmrman 备份/归档；保留 30 天，异机存储；归档库纳入备份范围；备份任务与记录由页面管理（sys_backup_task/sys_backup_log，Celery 调度，支持手动备份与恢复演练登记）。
- MinIO：对象数据定期增量备份 + 生命周期策略；元数据随数据库备份。
- 恢复：定期演练恢复流程，恢复时效目标 RTO ≤ 4 小时、数据丢失目标 RPO ≤ 1 小时。
- 数据归档：全表可配归档策略（sys_archive_policy），两段式流转——热表超阈值迁归档库（可在线查询），按保留期转对象存储冷化；过期归档文件与软删除残留由 Celery 物理清理。

### 19.5 版本与发布管理 <a id="deploy-release"></a>

- **版本号策略**：产品版本遵循语义化版本（主.次.修订）——主版本含破坏性变更（含 API 大版本 /api/v2 升级），次版本为向后兼容的新功能，修订号为缺陷修复；Git 打 tag 与 CI 构建镜像一一对应。
- **发布检查单**（每次发版逐项确认）：CI 流水线绿色；Alembic 迁移在 MySQL/PostgreSQL/达梦 DM8 三库演练通过；当日备份成功且可恢复；swagger.json 契约快照已导出归档（有 API 变更时）；发布说明（变更清单、迁移步骤、回滚预案）已编写。各项状态由 CI job 自动采集输出（迁移演练结果 / 备份状态 / 契约快照产物），人工仅做最终放行确认。
- **Schema 向后兼容规则**：滚动发布期间新旧版本并存，迁移脚本必须向后兼容——只加列不删列不改列；新列必须可空或带默认值；删列 / 改类型延后两个版本分步执行（先停用代码引用，下版再物理删除）；不兼容变更随主版本一次性升级并停机窗口执行。
- **应用回滚**：镜像按版本留存于 GitLab Registry，回滚即 Compose 切换上一 tag 镜像重启；数据库迁移原则上向前修复（forward-fix）优先，仅兼容性迁移（加列类）允许 Alembic downgrade 回退，破坏性迁移不可回滚、必须在发布检查单中标注。
- **发布流程**：main 打 tag → CI 构建 tag 镜像 → 发布检查单确认 → 生产滚动发布 → 冒烟回归（16.3 节用例）通过即发布完成；失败触发回滚预案。
- **灰度发布**（MVP Compose 口径）：test 环境先行验证 → 生产低峰期滚动发布 → 内部/试点租户子域名走查核心链路、SLO 无异常后再全量放量；按租户金丝雀路由列入 K8s 演进后的能力（22 节演进路线）。

### 19.6 容量规划 <a id="deploy-capacity"></a>

- **基线容量模型**（首年，超出后按监控实测修订）：50 租户 × 每租户 200 用户；单租户库首年数据量 ≤ 10GB；审计日志按月分表单表 ≤ 500 万行（超阈值由归档策略流转）。
- **ElasticSearch**：索引按用途三类（主数据/日志/文件），日志索引按月滚动、热保留 90 天后随归档清理；MVP 单节点 JVM 堆 ≤ 31GB（压缩指针上限）；磁盘水位 70% 告警。
- **RocketMQ**：commitlog 消息保留 72 小时（默认口径）；消费滞后超阈值告警（审计链消费优先）。
- **Redis**：maxmemory 设上限并配 volatile-lru 逐出策略（持久状态类 key 均带 TTL、缓存类短 TTL + 随机偏移）；内存水位 70% 告警。
- **可观测性栈保留期**：Prometheus 指标 15 天、Loki 日志热保留 30 天（MVP 单机口径，K8s 化后再评估冷存分层）。
- **复核节奏**：阶段九部署落地与阶段十压测后各修订一次基线，此后随运维复盘年度修订。

## 20. 开发计划与验收标准 <a id="plan"></a>

### 里程碑分层（Alpha / Beta / GA）

15 个阶段体量接近完整产品而非传统意义的"最小可行产品"，为控制交付风险、避免范围失控，引入行业通行的三级发布分层对阶段分组（仅标注交付节奏，不改变各阶段内容与完成标准）：

| 层级 | 覆盖阶段 | 达成标志 |
| --- | --- | --- |

## 23. 附加业务模块规划 <a id="addon"></a>

BMS 作为基础管理系统，在采购（模拟业务）、收付款等 MVP 模块之外，后续可按本章方式便捷附加销售管理、仓储管理等业务模块。附加方式分两轨：**内置模块**（主推，平台统一开发随主版本发布）与**独立服务**（独立部署，经认证/开放接口/事件总线集成）。

### 23.1 接入方式（双轨） <a id="addon-ways"></a>

| 方式 | 说明 | 适用场景 |
| --- | --- | --- |
| 内置模块（主推） | 在 monorepo 内按既有分层（api/models/schemas/services/repositories）新增模块，经种子数据注册业务/动作权限码、菜单/表单/按钮/字段（含 i18n 附表），随主版本发版；数据落租户库，复用工作流、报表、导入导出、全文检索、审计、回收站等全部平台能力 | 采购、销售、仓储等与权限体系/工作流/报表深度绑定的核心业务 |
| 独立服务 | 单独部署的业务系统（可异构技术栈），以 BMS 为统一认证源（OIDC IdP）、经 /api/open 开放接口（OAuth2 Client Credentials + scope）交互、Webhook 订阅事件；数据独立存储，不进租户库；菜单以外部链接形式挂入 sys_menu | 大型独立业务系统、外部团队开发、强隔离或异构技术栈需求 |

### 23.2 内置模块标准接入流程 <a id="addon-flow"></a>

1. **模块注册**：确定模块简称、表前缀、业务码、错误码段、事件域，在 sys_module 平台注册（阶段一已实现的基础能力，含唯一性校验），并登记业务/动作码（见 23.3/23.4/23.5），避免冲突。
2. **数据模型**：新表用 {前缀}_ 命名（表名单数 snake_case），遵循"数据规范"节（雪花 ID、软删除、审计字段、乐观锁、UTC 时间、i18n 附表、跨库逻辑外键）；Alembic 迁移脚本三库可执行；表位于租户库。
3. **后端分层**：按模块新增 app/api/{简称}/、models/、schemas/、services/、repositories/ 目录，遵守分层职责（api 只做参数校验与路由分发，禁止直接操作模型）；模块间引用走服务层或事件，禁止跨模块直接操作模型。
4. **权限接入**：业务码注册 sys_business、动作码注册 sys_action（平台库种子，动作按业务分配）；动作码若为通用语义（query/create/update/delete/manage 等）复用既有清单，模块私有动作再新增。
5. **菜单/页面接入**：菜单/表单/按钮/字段种子（sys_menu/sys_form/sys_button/sys_field + 各自 i18n 附表），前端动态路由自动生效、按钮/字段权限自动挂接，无需前端发版。
6. **工作流接入**：审批类单据定义流程模板（wf_process，bpmn-js 建模），wf_instance.business_type 指向模块业务码，待办/通知/移动端审批自动复用。
7. **事件接入**：事件命名 {域}.{动作}（如 sale.order.created），Webhook 订阅按事件名注册；检索索引同步、审计异步化等平台机制经事件总线自动复用。
8. **报表与导入导出**：rpt_dataset 挂接新表 SQL（只读从库执行）；Excel 导入导出按平台通用能力接入。
9. **国际化**：模块固定文案入 sys_i18n_message（页面在线维护），业务展示文案（菜单名、字典 label 等）用对应 i18n 附表。
10. **测试与 CI**：模块接口测试（pytest + httpx）、关键链路 E2E 抽样、CI 三库方言集成测试纳入流水线；随模块交付对应概要设计文档与验收标准。

### 23.3 模块注册要素 <a id="addon-register"></a>

新增模块在平台库 sys_module 统一登记以下要素（一处登记、全局生效；该机制为阶段一实现的平台基础能力，启动与 CI 校验表前缀/错误码段/事件域唯一），简称全小写、与英文名一致：

| 要素 | 规则 | 示例（销售） |
| --- | --- | --- |
| 模块简称 | 英文名词，2-6 位全小写 | sale |
| 表前缀 | {简称}_，表名 {前缀}{表名单数} | sale_order |
| 业务码 | 与模块简称一致（sys_business 注册） | sale |
| 错误码段 | 10xxxx 起逐模块分配，注册即定、稳定不变 | 12xxxx |
| 事件域 | {简称}.{动作} 事件命名 | sale.order.created |
| 后端目录 | app/api/{简称}/ 等分层目录 | app/api/sale/ |
| 前端目录 | frontend/src/views/{简称}/ | views/sale/ |

### 23.6 示例模块简要设计 <a id="addon-example"></a>

#### 销售管理（sale_）

- **注册要素**：简称 sale、前缀 sale_、业务码 sale、错误码段 12xxxx、事件域 sale.*。
- **核心表**：sale_customer 客户档案、sale_contract 销售合同、sale_order 销售订单、sale_order_item 销售订单明细、sale_delivery 发货单、sale_return 退货单。
- **菜单挂接**：销售管理菜单组（客户管理 / 合同管理 / 订单管理 / 发货管理 / 退货管理），表单/按钮/字段按标准流程注册。
- **主流程**：销售订单登记 → 审批（复用工作流）→ 审批通过生成发货单（触发仓储 wh_ 出库）→ 收款关联 pay_receipt；退货单审批 → 退款关联 pay_refund（金额 ≤ 原单余额校验复用）。

#### 仓储管理（wh_）

- **注册要素**：简称 wh、前缀 wh_、业务码 wh、错误码段 13xxxx、事件域 wh.*。
- **核心表**：wh_warehouse 仓库、wh_location 库位、wh_stock 库存余额、wh_stock_log 库存流水、wh_inbound 入库单、wh_outbound 出库单、wh_transfer 调拨单、wh_check 盘点单。
- **菜单挂接**：仓储管理菜单组（仓库库位 / 入库管理 / 出库管理 / 调拨盘点 / 库存查询）。
- **主流程**：采购收货（pur_purchase_order 到货）→ 入库单入库 → 库存余额更新 + 流水落库 + wh.inbound.completed 事件；销售发货（sale_delivery）→ 出库单出库 → 库存扣减；调拨与盘点经 wh_transfer/wh_check 走差异调整，库存数据供报表数据集查询。

### 23.7 独立服务集成 <a id="addon-service"></a>

- **认证**：BMS 作 OIDC Provider，独立服务以 BMS 租户用户体系单点登录（客户端注册复用 sys_client，scope 最小化分配）。
- **数据交互**：经 /api/open 开放接口（OAuth2 Client Credentials + 调用审计），不直连租户库。
- **事件联动**：Webhook 订阅 BMS 事件（如 sale.order.created）；独立服务自有事件回传经其自身 Webhook 或独立通道，不占用 BMS 事件域。
- **数据边界**：独立服务自建库，不进租户库；与租户数据交互一律走开放接口，遵守租户隔离与调用审计。
- **页面入口**：以外部链接菜单挂入 sys_menu（sys_form 挂外链类型），权限分配走既有菜单权限机制。

### 23.8 开发计划与演进 <a id="addon-plan"></a>

- 开发计划"附加业务模块（预留）"阶段：销售管理、仓储管理按 23.2 标准流程推进，启动时间另行确定、不纳入 MVP 排期；每个模块交付时配套概要设计文档（遵循《文档生成规范》设计体系）与验收标准。

## 24. 明确不采用 <a id="exclude"></a>

MVP 明确不采用的技术与方案（防止后续反复讨论，按需再评估）：

- Kubernetes：MVP 用 Docker Compose 部署，数据量或部署规模增长后按"演进路线"迁移。
- Kafka：消息量级未到，RocketMQ 已覆盖事件总线，Redis 已覆盖任务队列。
- MFA / 2FA：账号密码 + 图形验证码 + 找回密码双通道 + 限流已满足 MVP 安全基线。
- 原生 WebSocket：统一采用 Socket.IO（自动重连、Redis 跨实例广播）。
- APNs / FCM 等移动端系统推送：MVP 站内信 + 企业微信/钉钉内免登即达。
- 微服务拆分：保持单体模块化 + 独立 worker 进程，跨域调用走事件总线。评估结论——微服务虽带来独立部署、故障隔离、独立扩缩容等收益，但对本项目代价过大：分布式事务（审计哈希链、软删除复合唯一约束、乐观锁等强一致场景）、跨服务延迟（威胁 P99 ≤ 1s 目标）、权限体系与多租户路由横切全局难以拆分、基础设施已 8+ 组件再拆分运维翻倍、小团队维护成本高；单体 + worker 已通过事件总线获得模块解耦与独立伸缩的大部分收益。
- 前端 SSR / Nuxt：管理端与 H5 均为 SPA。
- WCAG / 信息无障碍专项适配：不纳入 MVP 范围（内部管理后台场景，Element Plus 组件自带基础可访问性兜底）；交付客户合同有明确要求时以 WCAG 2.1 AA 为基线专项立项。

## 25. 风险管理 <a id="risk"></a>

风险登记册随阶段复审（每阶段末测试复盘时一并走查），新识别风险登记入禅道并跟踪闭环；概率 / 影响按高、中、低三级定性评估：

| 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- |

## 26. 术语表 <a id="glossary"></a>

本文档自定义概念较多，集中收录高频术语（按文中出现顺序归类）：

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| 平台库 / 租户库 / 归档库 | 平台级数据存平台库（bms_platform）；一租户一独立库存全量业务数据（bms_tenant_{code}）；归档数据统一收存归档库（bms_archive，只读） | 多数据源策略 |
| 主体链 | 用户与角色之间可插入任意中间实体（岗位/部门等）的绑定链条，权限计算统一收敛为用户 → 角色，多链取并集 | 权限模型 |
| 业务码 / 动作码 / 权限码 | 业务码抽象资源（sys_business）、动作码抽象操作（sys_action）、权限码 = `业务:动作`（如 user:create） | 权限模型 |
| 三权分立 | 租户侧系统管理员/安全管理员/审计管理员三类内置角色权限互斥、不得兼任 | 权限模型 |
| 三级布局 | 表单布局三级回退：平台默认 → 租户覆盖 → 角色视图，空布局回退字段 sort 默认栅格 | 功能模块·表单定制 |
| 三态共用 | 同一表单布局结构同时服务新增/编辑/详情三个界面形态 | 功能模块·表单定制 |
| 租户自建字段 | 租户在表单定制中动态加的物理列（ext_ 前缀，运行时 DDL），停用不删列、跨四库类型映射 | 功能模块·表单定制 |
| 逻辑外键 | 跨库引用用 code 等逻辑字段关联，不建物理外键约束（多库拓扑下物理外键不可行） | 核心数据表清单 |
| 分片表 | 按月拆分的物理表（表名带 yyyyMM 后缀），逻辑表名不带后缀；分片键=时间 | 多数据源策略 |
| i18n 附表 | {主表}_i18n 结构的多语言附表（主表 ID + locale + 翻译字段，联合主键），查询按当前 locale 关联、缺省回退主表默认文案 | 数据规范 |
| 哈希链 | 审计日志逐条 prev_hash + record_hash 串联防篡改，分片表内成链、跨月衔接，提供链校验巡检 | 审计合规 |

| 卡片双轨制 | 工作台卡片两类来源：功能卡（卡片注册表内置渲染器）/ 图表卡（挂接报表数据集动态渲染） | 功能模块·首页工作台 |
