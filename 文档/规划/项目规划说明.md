# 项目规划说明

基础管理系统，主要用作后端管理，简称BMS。

## 项目概述

基础管理系统，支持分布式、集群部署。

后端基于 FastAPI + SQLAlchemy，前端基于 Vue 3 + Vite，通过知识图谱（graphify）辅助代码理解与架构分析。

## 选型说明

### 后端核心

- **Python 3.14+**：配合 uv 管理依赖与虚拟环境；语法新特性（如类型参数语法）提升开发效率。
- **FastAPI**：原生异步、基于 Pydantic 自动生成 OpenAPI 文档，与异步 SQLAlchemy 天然契合；自带 Swagger UI / ReDoc，调试接口零成本。
- **Pydantic v2**：Rust 内核，校验与序列化性能数倍于 v1；作为请求/响应模型与 ORM 解耦。
- **SQLAlchemy 2.0 异步**：统一 ORM/Core 两套 API；多数据源用多个异步 engine 管理。注意：异步会话不可跨请求共享，避免循环内多次查询（N+1），大事务显式声明边界。
- **Alembic**：schema 版本管理；URL 从 config.toml 读取。注意 MySQL / PostgreSQL 方言差异需分环境验证迁移脚本。
- **SQLite（aiosqlite）/ MySQL 8.x / PostgreSQL 16+**：开发与测试用 SQLite 零部署成本；生产双库并行支持，ORM 层禁用方言特有功能（见"数据库兼容"节）。
- **aiomysql**：MySQL 异步驱动，与整体异步栈一致；同步 fallback 可换 PyMySQL（aiomysql 底层即其移植）。备选 asyncmy，性能更好但维护活跃度一般。
- **psycopg 3**：PostgreSQL 官方维护驱动，原生异步支持（SQLAlchemy dialect `postgresql+psycopg`），替代已冻结的 psycopg2。
- **Redis（redis-py）**：官方客户端，RESP2 兼容旧版服务器；用异步客户端（redis.asyncio）配合缓存、限流、token 黑名单场景。集群环境统一走 Redis，**弃用本地内存缓存**——多实例内存相互独立会造成数据不一致。
- **JWT（PyJWT）+ PBKDF2**：JWT 无状态便于横向扩展；PBKDF2 用标准库实现，不引入额外密码库。注意 access token 有效期不可过长，见"认证与安全"节。
- **python-multipart**：FastAPI 处理表单与文件上传的必备依赖。
- **MinIO**：S3 兼容对象存储，多实例共享文件；本地开发可用文件系统模拟，生产独立部署或对接现有 S3 服务。
- **Babel + gettext**：后端错误消息按 Accept-Language 翻译，`msgfmt` 编译 po 文件；注意新文案需同步提取。
- **TOML（config.toml + 环境变量覆盖）**：单配置文件易读；部署时用环境变量覆盖敏感项（DB URL、密钥），遵循 12-factor。
- **yitter/IdGenerator**：雪花算法，分布式环境下无需中心协调即可生成全局唯一 ID；注意时钟回拨处理配置。
- **structlog**：结构化 JSON 日志，Docker 环境下便于日志收集与检索；与标准 logging 集成，不影响第三方库输出。
- **RabbitMQ（二期）**：Celery 官方推荐 broker；兼作通用消息队列（操作日志异步化、模块解耦）；消息量级远未到 Kafka 场景。
- **Celery（二期）**：分布式任务队列，任务在 worker 间分配执行，多实例无需额外锁；定时任务用 celery beat，失败自动重试、ack 确认。

### 前端

- **Vue 3 + Vite + TypeScript**：组合式 API 适合中后台业务；Vite 冷启动快；TS 提供类型安全，与后端 Pydantic schema 可做类型对齐。
- **Element Plus**：中文社区生态最大，后台管理组件齐全（表格、表单、树、弹窗），主题可定制；与 Vue 3 同源维护。
- **Vue Router 4 / Pinia**：官方路由与状态管理，路由守卫配合权限码做菜单级控制；Pinia 取代 Vuex，TS 支持好。
- **Axios**：统一封装请求拦截器（注入 access token、处理 401 刷新）；响应拦截器统一错误提示。
- **vue-i18n**：中英文切换，语言偏好 localStorage 持久化；文案统一走 locale 文件，避免硬编码。
- **SCSS**：配合 Element Plus 主题变量定制样式；避免引入重型 UI 框架外的 CSS 方案。
- **pnpm**：硬链接节省磁盘、依赖隔离严格，安装速度快。
- **ESLint + Prettier**：规范代码风格；与 Vue 官方插件链配合。
- **Vitest**：与 Vite 同构，组件/单元测试零配置；E2E 用 Playwright——自动等待、录制器、跨浏览器，替代 Selenium。

### 工程化与质量

- **uv**：Python 依赖管理 + 虚拟环境一体化，速度远超 pip；`pyproject.toml` 集中声明依赖与工具配置。
- **ruff**：lint + format 一体化，性能极高，替换 flake8/black/isort。
- **pyright**：严格类型检查，VS Code 原生支持；与 Pydantic v2 模型配合可在 IDE 中即时发现类型错误。
- **pytest + httpx**：FastAPI 测试用 ASGITransport 免启服务器；测试库统一 SQLite 保证可移植。
- **Swagger UI / ReDoc**：FastAPI 自动生成，接口联调与验收依据。
- **graphify**：知识图谱辅助代码理解与架构分析，详见《graphify 部署使用说明》。

### 部署与运维

- **Docker + Docker Compose**：backend / frontend / redis / rabbitmq / minio / 数据库 一键编排；本地与生产环境一致。
- **nginx**：托管前端静态资源并反代 /api 到后端；负载均衡与 TLS 终止层。
- **MinIO**：对象存储服务，backend 多副本共享同一存储端点。
- **Prometheus + Loki + Grafana**：Prometheus 采集 /metrics 指标（请求量、延迟、依赖状态）；Loki 聚合 structlog 日志跨实例检索；Grafana 统一展示；链路追踪二期（OpenTelemetry）。
- **/healthz、/readyz**：存活探针与就绪探针分离，就绪检查依赖（DB/Redis）连通性，供编排系统滚动发布。
- **GitHub Actions**：PR 触发 ruff + pytest 检查，main 分支构建镜像推送仓库。

## 权限模型

采用 RBAC + 数据权限：

- 模型：用户 → 角色 → 权限码；权限码命名 `模块:动作`（如 `user:create`、`role:update`）
- 双重控制：前端按权限码控制菜单/按钮显隐，后端接口用依赖注入 `require_permission(...)` 强制校验
- 数据权限：挂在角色上，支持四种范围——全部数据 / 本部门及以下 / 本部门 / 仅本人；查询时由通用过滤器按当前用户注入数据范围条件
- 超级管理员：内置角色，绕过权限校验，不可删除

## 多数据源策略

支持三层数据架构（分层设计，逐层可选）：

1. **多业务库并存**：config.toml 声明多个数据源（每库含主从连接）；SQLAlchemy 2.0 多异步 bind；repositories 层按模块指定数据源
2. **主从读写分离**：每个业务库可配一主多从；AsyncSession 工厂按读写标记选择异步引擎，写操作与事务强制走主库
3. **分库分表**：抽象 ShardingRouter 层（分片键 → 物理库/表解析）；MVP 交付抽象层与路由骨架，真实分片规则（按租户/按时间）二期落地；Python 生态无成熟分片中间件，采用应用层自研路由

迁移策略：Alembic 按数据源分别维护迁移脚本，只管理各库 schema。

## 数据库兼容

- 开发环境默认 SQLite，生产同时支持 MySQL 8.x 与 PostgreSQL 16+
- ORM 层禁用方言特有功能：JSON 等类型使用跨方言通用类型，分页统一 limit/offset
- Alembic 维护 MySQL / PostgreSQL 两套方言迁移；SQLite 开发库自动建表
- 测试环境与开发环境一致使用 SQLite

## 认证与安全

- 双 token：access token（15–30 分钟）+ refresh token（7–30 天，滚动轮换）
- 存储：access token 仅存前端内存（刷新页面后静默续期）；refresh token 存 httpOnly + Secure cookie，防 XSS 窃取，同时做好 CSRF 防护
- 密码：PBKDF2 哈希（标准库）；登录失败 Redis 限流（如 5 次锁 15 分钟）
- 登出：refresh token 加入 Redis 黑名单即时失效
- 日志：登录日志、操作日志落库

## 部署与运维

### 部署拓扑

- 入口：nginx（TLS 终止、/api 反向代理、前端静态资源托管）→ backend 多副本（无状态，可横向扩展）
- 数据层：MySQL / PostgreSQL 主从（读写分离 + 故障切换）+ Redis（Sentinel/Cluster 高可用）+ RabbitMQ + MinIO
- 监控：Prometheus（指标）+ Loki（日志聚合）+ Grafana（展示）

### 集群设计要点

- **无状态**：JWT 无状态；token 黑名单、限流计数存 Redis；文件存 MinIO；定时任务由 Celery 分布式执行——任一实例可随时停机、随时扩容
- **缓存一致性**：统一走 Redis，不引入本地内存缓存（多实例内存独立会造成数据不一致）
- **分布式锁**：Redis SETNX 实现，用于幂等操作与防并发
- **分布式限流**：Redis 计数/令牌桶（登录防爆破已采用）
- **连接池**：各数据源配置 pool_size / max_overflow，避免实例增多时连接耗尽
- **数据库高可用**：主从 + 故障切换策略；读写分离期间定义主库故障预案（从库提升）
- **配置与密钥**：config.toml + 环境变量覆盖；密钥（DB/Redis 密码、JWT secret、MinIO 凭据）走 Secret 管理（K8s Secret / Docker secrets），不落库、不入镜像

### 基础设施编排

- 初版 Docker Compose：backend（多副本）+ frontend（nginx）+ redis + rabbitmq + minio + 数据库（按环境选择 MySQL 或 PostgreSQL）
- 健康检查：/healthz（存活）、/readyz（依赖就绪），供编排系统滚动发布
- TLS 与 HTTPS：nginx 层配置，cookie Secure 标志随环境启用
- 演进：数据量或部署规模增长后迁移 Kubernetes

## 演进路线

- 二期：真实分片规则落地、系统监控（Prometheus/Loki 指标与日志聚合）、任务调度与消息队列落地（Celery + RabbitMQ）、链路追踪（OpenTelemetry）
- 后续：Kubernetes 化部署、工作流审批（概念预留，视需求启动）
