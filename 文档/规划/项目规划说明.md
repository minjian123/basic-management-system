# 项目规划说明

基础管理系统，主要用作后端管理，简称BMS。

## 项目概述

基础管理系统，支持分布式、集群部署；多租户 SaaS 架构（租户独立库），支持 SSO 单点登录，内置报表 BI 与移动端 H5。

后端基于 FastAPI + SQLAlchemy，前端基于 Vue 3 + Vite（PC 管理端 + 移动端 H5 双工程），通过知识图谱（graphify）辅助代码理解与架构分析。

## 选型说明

### 后端核心

- **Python 3.14+**：配合 uv 管理依赖与虚拟环境；语法新特性（如类型参数语法）提升开发效率。版本兼容口径：阶段一骨架阶段逐依赖验证（FastAPI/SQLAlchemy/Pydantic/psycopg/Celery/SpiffWorkflow 等），任一核心依赖不兼容则整体回退 Python 3.13。
- **FastAPI**：原生异步、基于 Pydantic 自动生成 OpenAPI 文档，与异步 SQLAlchemy 天然契合；自带 Swagger UI / ReDoc，调试接口零成本。
- **Pydantic v2**：Rust 内核，校验与序列化性能数倍于 v1；作为请求/响应模型与 ORM 解耦。
- **SQLAlchemy 2.0 异步**：统一 ORM/Core 两套 API；多数据源用多个异步 engine 管理，租户独立库按 tenant 动态路由 engine（懒加载创建 + 闲置回收 + 池上限控制）。注意：异步会话不可跨请求共享，避免循环内多次查询（N+1），大事务显式声明边界。
- **Alembic**：schema 版本管理；URL 从 config.toml 读取。注意 MySQL / PostgreSQL 方言差异需分环境验证迁移脚本。
- **SQLite（aiosqlite）/ MySQL 8.x / PostgreSQL 16+**：开发与测试用 SQLite 零部署成本；生产双库并行支持，ORM 层禁用方言特有功能（见"数据库兼容"节）。
- **aiomysql**：MySQL 异步驱动，与整体异步栈一致；同步 fallback 可换 PyMySQL（aiomysql 底层即其移植）。备选 asyncmy，性能更好但维护活跃度一般。
- **psycopg 3**：PostgreSQL 官方维护驱动，原生异步支持（SQLAlchemy dialect `postgresql+psycopg`），替代已冻结的 psycopg2。
- **Redis（redis-py）**：官方客户端，RESP2 兼容旧版服务器；用异步客户端（redis.asyncio）配合缓存、限流、token 黑名单场景。集群环境统一走 Redis，**弃用本地内存缓存**——多实例内存相互独立会造成数据不一致。
- **JWT（PyJWT）+ Redis 会话状态校验 + PBKDF2**：JWT 便于横向扩展；鉴权时随 access token 一并校验 Redis 会话有效标记（每请求一次 Redis 读，毫秒级开销），强制踢出即时生效；PBKDF2 用标准库实现，不引入额外密码库。注意 access token 有效期不可过长，见"认证与安全"节。
- **authlib（SSO）**：OIDC 为主 + CAS 兼容——作为客户端接入各租户外部 IdP（Keycloak/AD/Authing 等）；同时提供 OIDC Provider 能力，其他系统以 BMS 租户用户体系为统一认证源；企业微信/钉钉免登复用同一外部身份框架。SSO 首次登录 JIT 自动建号，本地账号密码登录并存（超管应急通道）。
- **slowapi**：基于 limits 库的 FastAPI 限流方案，装饰器声明限流规则（IP / 用户 / client 维度），Redis 后端集群共享计数，Redis 故障降级 memory 后端；登录防爆破优先。
- **图形验证码**：Pillow 生成验证码图片，Redis 存储（bms:global:captcha:{uuid}，短 TTL 5 分钟），登录连续失败 3 次后强制要求，与 slowapi 限流叠加防爆破。
- **python-multipart**：FastAPI 处理表单与文件上传的必备依赖。
- **openpyxl**：Excel 读写，支撑用户批量导入与列表导出。
- **MinIO**：S3 兼容对象存储，多实例共享文件；本地开发可用文件系统模拟，生产独立部署或对接现有 S3 服务。大文件分片上传：分片临时对象存 MinIO（object key 加 .part 标识），全部上传后合并为最终对象并清理分片；集群实例无本地磁盘依赖，遵循无状态原则。孤儿分片（上传中断遗留的 .part 对象）由 Celery 定时任务回收。
- **消息文案入库 + Babel**：前后端固定文案（错误消息、按钮、提示）统一存 sys_i18n_message，页面在线维护、运行时下发（Redis 缓存），新增语言免发版；Babel 仅开发期提取消息 key 入库。业务展示文案（菜单名、字典 label、邮件模板等）走 i18n 附表，见"核心数据表清单"节；运行时通知内容按收件人 locale 渲染。用户级时区：sys_user.timezone，时间按用户偏好时区展示；数字/日期格式经 Intl API 本地化；RTL 语言由 sys_i18n_locale.rtl 标记驱动前端布局切换。
- **TOML（config.toml + 环境变量覆盖）**：单配置文件易读；部署时用环境变量覆盖敏感项（DB URL、密钥），遵循 12-factor。
- **yitter/IdGenerator**：雪花算法，分布式环境下无需中心协调即可生成全局唯一 ID；注意时钟回拨处理配置。
- **structlog**：结构化 JSON 日志，携带 request_id 贯穿请求链路，配合 Loki 跨实例聚合检索；与标准 logging 集成，不影响第三方库输出。
- **SpiffWorkflow**：Python 生态最成熟的 BPMN 2.0 引擎，解析执行标准 BPMN XML（用户任务、网关、结束事件）；同步执行，在 FastAPI 异步栈中放线程池运行；引擎本身不持久化，流程实例/任务/审批记录由 BMS 自建表维护。注意 Python 3.14 兼容性风险：若引擎暂未适配，可退回 Python 3.13。
- **Jinja2**：服务端模板渲染（邮件/通知模板、简单 HTML 页面输出，如导出预览）；邮件模板入库（sys_mail_template）支持页面在线编辑，保存前做语法校验与沙箱渲染测试，多语言内容走 i18n 附表；页面主体仍为前后端分离，模板渲染仅作辅助场景。
- **python-socketio**：Socket.IO 协议服务端，内置自动重连、事件机制、心跳保活；集群多实例用 Redis 适配器（socketio.RedisManager）跨实例广播消息；握手阶段校验 token 鉴权。
- **RocketMQ 5.x**：Apache 顶级项目，作事件总线（操作日志异步化、Webhook 推送、审计链按租户分区有序消费、模块解耦）；分区有序消息保证审计链顺序，事务消息兜底；消息量级远未到 Kafka 场景但保留生态与扩展空间。注意：Celery 官方不支持 RocketMQ broker，故定时任务 Celery 的 broker 用 Redis（官方支持，复用现有 Redis），事件总线与任务队列解耦。
- **Celery**：分布式任务队列，任务在 worker 间分配执行，多实例无需额外锁；broker 用 Redis（官方支持），事件总线独立走 RocketMQ（Celery 不支持 RocketMQ broker）；定时任务用 celery beat，任务定义入库（sys_task），自研数据库调度器（beat 启动时加载、任务变更事件触发重载），页面可动态增删改与启停，执行历史落 sys_task_log；失败自动重试、ack 确认；承担孤儿分片清理、日志归档、分片表预创建等周期性任务。注意：worker 为同步进程，任务内执行异步业务须用 asyncio.run 或独立引擎，禁止跨事件循环复用连接/会话；beat 单副本运行避免重复调度。
- **aiosmtplib**：异步 SMTP 客户端，配合 Jinja2 模板发送邮件通知（审批提醒、告警）。
- **ElasticSearch 8.x**：全文检索，覆盖三类场景——主数据全局搜索（用户/部门/角色/字典/采购单据/文件元数据）、审计日志检索（操作/登录/开放接口/数据变更，按月索引与分片表对齐）、文件内容检索（PDF/Word/Excel/TXT，经 Celery 任务解析文本后入库索引；扫描件 OCR 由阶段十四 AI 支持）。数据同步走 RocketMQ 事件驱动异步消费（独立 event-worker 进程，复用现有事件模型；索引重建时重放事件）；ES 只承担检索匹配，返回业务 ID + 高亮，详情回查数据库取最新数据，避免双写一致性难题。索引按用途分（主数据/日志/文件），均含 tenant_id 字段，查询强制租户隔离与数据权限过滤；生产开启安全认证，MVP 单节点部署。
- **AI 能力（阶段十四）**：统一 LLM 适配层——默认接入外部大模型 API（DeepSeek/Qwen 等），敏感场景可配置私有化端点（Ollama/vLLM），API key 走 Secret 管理，模型可切换不侵入业务代码。七项能力（智能报表助手、智能审批辅助、AI 内容生成、语义搜索与文件问答、OCR 与自动分类、审计异常检测、知识库问答机器人）与模块的结合见"功能模块"节；向量检索用 Milvus（独立部署，依赖 etcd 与 MinIO，MinIO 已复用），embedding 管线经 RocketMQ 事件驱动（复用 event-worker）；OCR 默认本地 PaddleOCR，可切换多模态模型 API。设计约束：AI 交互全量落 ai_chat_log 审计、提示词与数据不出租户边界（向量库按租户隔离、prompt 注入防护）、AI 结果默认仅辅助展示（意见、草稿、检索、告警建议）、AI 接口独立限流。AI 自动执行写操作与 AI 自动审批为两个独立可选功能，各自由 sys_config 开关控制且默认关闭，AI 自动审批依赖 AI 自动执行写操作开启（见"认证与安全"节）。
- **OpenTelemetry**：链路追踪，MVP 即接入；应用经 otel-collector 上报 trace 至 Jaeger 存储展示，trace_id 与 structlog 的 request_id 关联，随 Grafana 统一可视化（Jaeger 数据源）。

### 前端

- **Vue 3 + Vite + TypeScript**：组合式 API 适合中后台业务；Vite 冷启动快；TS 提供类型安全，与后端 Pydantic schema 经 openapi-typescript 由 OpenAPI schema 自动生成 TS 类型，保持前后端契约一致。
- **Element Plus**：中文社区生态最大，后台管理组件齐全（表格、表单、树、弹窗），主题可定制；与 Vue 3 同源维护。
- **Vue Router 4 / Pinia**：官方路由与状态管理，路由守卫配合业务权限做菜单级控制；Pinia 取代 Vuex，TS 支持好。
- **Axios**：统一封装请求拦截器（注入 access token、处理 401 刷新）；响应拦截器统一错误提示。
- **vue-i18n**：中英文切换，语言偏好 localStorage 持久化；语言包运行时从后端拉取（GET /api/v1/i18n/messages，Redis 缓存 + localStorage 二次缓存），文案统一存 sys_i18n_message，页面在线维护、新增语言免发版；前端不硬编码文案。
- **SCSS**：配合 Element Plus 主题变量定制样式；避免引入重型 UI 框架外的 CSS 方案。
- **npm**：Node 官方自带包管理器，零额外依赖、不生成任何额外配置文件；frontend 与 frontend-mobile 双工程依赖与配置各自独立（各自 package-lock.json、ESLint/Prettier/TS 配置，互不共享）；CI 用 npm ci 锁定安装保证可复现。
- **ESLint + Prettier**：规范代码风格；与 Vue 官方插件链配合。
- **Vitest**：与 Vite 同构，组件/单元测试零配置；E2E 用 Playwright——自动等待、录制器、跨浏览器，替代 Selenium。
- **bpmn-js**：BPMN 流程图建模组件，管理端拖拽绘制流程定义，导出 BPMN XML 交由 SpiffWorkflow 执行。
- **ECharts**：报表与大屏渲染，中文生态最全，图表类型覆盖管理端全场景。
- **Vue 3 + Vant（移动端）**：frontend-mobile 独立工程，Vant 移动端组件库；复用后端 API 与会话体系，企业微信/钉钉内免登。

### 工程化与质量

- **uv**：Python 依赖管理 + 虚拟环境一体化，速度远超 pip；`pyproject.toml` 集中声明依赖与工具配置。
- **ruff**：lint + format 一体化，性能极高，替换 flake8/black/isort。
- **pyright**：严格类型检查，VS Code 原生支持；与 Pydantic v2 模型配合可在 IDE 中即时发现类型错误。
- **pytest + httpx**：FastAPI 测试用 ASGITransport 免启服务器；测试库统一 SQLite 保证可移植。
- **Swagger UI / ReDoc**：FastAPI 自动生成，接口联调与验收依据。
- **graphify**：知识图谱辅助代码理解与架构分析，详见《graphify 部署使用说明》。

### 部署与运维

- **Docker + Docker Compose**：backend / frontend / redis / rocketmq（nameserver + broker）/ minio / 数据库 一键编排；本地与生产环境一致。
- **nginx**：托管前端静态资源（PC + 移动端）并反代 /api 到后端；负载均衡与 TLS 终止层；子域名租户路由。
- **MinIO**：对象存储服务，backend 多副本共享同一存储端点。
- **Prometheus + Loki + Grafana + Alertmanager**：Prometheus 采集 /metrics 指标（请求量、延迟、依赖状态）；Loki 聚合 structlog 日志跨实例检索；Grafana 统一展示（告警面板同步可见）；Alertmanager 推送告警——邮件走原生 SMTP receiver，企业微信/钉钉群机器人经 webhook receiver 转 BMS 内部接口转换格式后推送；链路追踪 OpenTelemetry（otel-collector + Jaeger）随监控一并落地。
- **/healthz、/readyz**：存活探针与就绪探针分离，就绪检查依赖（DB/Redis）连通性，供编排系统滚动发布。
- **GitHub Actions**：PR 触发后端 ruff + pytest、前端 ESLint + Vitest + 双端构建（frontend / frontend-mobile）；Playwright E2E 独立 job，用服务容器起 backend（SQLite）与前端产物，覆盖登录/RBAC/核心 CRUD 主流程；main 分支构建镜像推送仓库，并导出 swagger.json 契约快照。

## 核心数据表清单

所有业务表统一规范：雪花 ID 主键、软删除（deleted_at）、审计字段（created_at/created_by/updated_at/updated_by）、乐观锁（version）、时间 UTC 存储；关联表用唯一联合主键。表名前缀：系统表 sys_、工作流 wf_、业务表 biz_、报表 rpt_、AI 域 ai_。多租户库划分：平台库（bms_platform）存平台级数据（标注【平台库】），租户库（bms_tenant_{code}）一租户一库存该租户全部业务数据，未标注的表均位于租户库；另有归档库（bms_archive）统一收存各租户归档数据（带 tenant_id 与原库表标识，只读查询）；跨库引用用逻辑外键（code），不建物理外键。多语言数据规范：需多语言的展示文案不入主表，由对应 i18n 附表存储（{主表}_i18n：主表 ID + locale + 翻译字段，联合主键），查询按当前 locale 关联，缺省回退主表默认文案；运行时生成的通知内容不走附表，由 gettext 按收件人语言翻译。分片表规范：按月分片的表名带 yyyyMM 后缀（如 sys_operation_log_202608），逻辑表名不带后缀。

## 权限模型

采用 RBAC + 主体链 + 权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）+ 动作级数据权限：

- **主体链**：用户与角色之间可插入任意中间实体（岗位、部门等），链条任意长度（用户→岗位→角色、用户→部门→角色、用户→岗位→部门→角色…），最终权限计算统一收敛为**用户 → 角色**，多链（用户直接绑定 + 岗位继承 + 部门继承等）取并集合并去重；主体角色绑定用通用表 sys_role_assign（subject_type + subject_id + role_id），新增实体类型仅扩展枚举，权限计算逻辑不变
- **权限分层**（菜单→表单→业务、按钮→动作、字段可见可编辑）：
  - **菜单权限**：用户可看到哪些菜单入口（用户视角只接触菜单与表单）；一个菜单必然对应一个表单（sys_menu → sys_form），授予菜单权限即隐含对应表单权限
  - **表单权限**：具体业务表单界面和对应数据表的权限；一个表单必然对应一个业务权限（sys_form → sys_business），授予表单权限即隐含对应业务权限
  - **业务权限**：抽象解耦层，界面不可见、不直接授予——将具体权限设置与具体菜单/表单解耦，通过"表单→业务"对照关系，由已授予的菜单/表单权限推导确定业务权限
  - **按钮权限**：表单上所有动作按钮（工具栏按钮 + 表单界面按钮）的权限；一个按钮必然对应一个动作（sys_button → sys_action），**默认没有任何按钮权限**
  - **动作权限**：抽象管理概念，将具体权限设置与具体表单按钮解耦，通过"按钮→动作"对应关系关联
  - **字段权限**：控制表单上所有界面字段是否可见、可编辑；字段实体 sys_field 挂表单（form_id + field_key），字段权限授予存 sys_role_field（role_id + form_id + field_id + visible + editable）——**默认（未授予）全部字段可见可编辑**，授予后按配置收窄：不可见字段读取载入时过滤（不返回不渲染），不可编辑字段写入保存时校验拒绝；与数据脱敏（data:plain）机制互补
  - **数据权限**：**默认没有任何数据权限**；权限管理人员在动作上配置可访问数据范围（sys_data_scope：动作→范围规则），写入保存时与读取载入时均检查是否在数据范围内；支持四种范围——全部数据 / 本部门及以下 / 本部门 / 仅本人
- **权限码**：命名 `业务:动作`（如 `user:create`）；业务对应业务权限（sys_business），动作对应动作权限（sys_action），动作归属业务
- 双重控制：前端按权限码控制菜单/按钮/字段显隐，后端接口用依赖注入 `require_permission(...)` 强制校验（两级：业务权限校验表单入口与数据表访问——业务权限经已授予的菜单/表单权限按对照关系推导，动作权限校验按钮对应接口）
- 超级管理员：分两级——平台超管（sys_admin，跨租户运营：租户开通/停用/域名配置，不进入租户业务数据）与租户侧管理角色；租户侧实行完整三权分立——系统管理员（用户/岗位/部门等系统配置）、安全管理员（角色/业务/动作/数据范围/密码策略/IdP 配置）、审计管理员（只读全部日志与审计数据），三类内置角色权限互斥、同一用户不得兼任；租户开通首建系统管理员账号，由其创建另两类管理员
- 租户边界：数据权限四种范围中的"全部数据"收敛为本租户全部；业务/动作权限码跨库引用用 code 逻辑外键

## API 设计规范

- 前缀：全部接口 `/api/v1`
- 统一响应：`{code, message, data}`；code=0 成功，非 0 为业务错误码；HTTP 状态码与业务错误码分离
- 错误码：5 位数字，万位为模块段、后 4 位为段内序号，一经发布稳定不变；文案由前端按 i18n 映射，后端不承担文案拼装。分段表：

  | 段 | 区间 | 覆盖模块 |
  | --- | ----- | --------- |
  | 1xxxx | 10001-19999 | 通用（参数校验、限流、系统内部） |
  | 2xxxx | 20001-29999 | 认证（登录/刷新/登出/验证码/找回密码/会话） |
  | 3xxxx | 30001-39999 | 用户与组织（用户/部门/角色/权限/三权分立） |
  | 4xxxx | 40001-49999 | 系统配置（菜单/字典/系统参数/国际化语言包） |
  | 5xxxx | 50001-59999 | 文件（上传/下载/分片/导入导出） |
  | 6xxxx | 60001-69999 | 工作流（流程定义/实例/待办/审批/会签） |
  | 7xxxx | 70001-79999 | 通知/邮件/任务调度 |
  | 8xxxx | 80001-89999 | 开放接口/Webhook/租户/SSO |
  | 9xxxx | 90001-99999 | 报表/审计/归档/监控 |

- 分页：查询参数 `page`（从 1 起）、`size`；响应 `{list, total, page, size}`
- 命名：RESTful 资源式（GET /users、POST /users、PUT /users/{id}、DELETE /users/{id}），列表筛选用查询参数
- 鉴权：除登录/刷新/健康检查外一律 Bearer access token；权限校验用 `require_permission` 依赖
- 租户识别：生产环境按子域名解析租户（{tenant}.bms.example.com），开发环境以 access token 内 tenant_id 兜底；一人多租户经 X-Tenant-ID 请求头切换并重发 token
- 幂等：审批提交、Excel 导入等写接口支持幂等键（请求头 Idempotency-Key）；实现为 Redis SETNX 前置拦截（重复键直接返回首次结果）+ 幂等键字段唯一约束兜底（并发穿透时拒绝重复提交）
- 对外开放：外部系统走独立前缀 /api/open，与内部接口隔离，见"系统集成"节
- 版本演进：破坏性变更升级大版本（/api/v2），新旧版本并行至少一个发布周期后下线旧版；非破坏性变更（新增字段/接口）在版本内演进
- 生产环境关闭 Swagger/ReDoc；OpenAPI 契约由 CI 导出快照分发，见"系统集成"节

## 系统集成

与其他系统的接口连接方案：

### 对外 API（外部系统调 BMS）

- 鉴权：OAuth2 Client Credentials——client_id/secret 换取 access token（自签 JWT，短 TTL），支持 scope（接口权限范围）、独立撤销、调用审计
- 路由：独立前缀 /api/open，与内部接口隔离；按 client 维度独立限流
- 开放范围：全量 CRUD 按 scope 控制；安全默认——scope 最小化分配，写接口（POST/PUT/DELETE）需显式授予，未授予一律拒绝
- 契约：OpenAPI 文档（swagger.json）作为集成契约；CI 构建时导出 swagger.json 快照存档，随版本分发给外部系统；生产环境关闭在线文档端点
- BMS 兼作 IdP：对外提供 OIDC Provider（授权码流程），第三方系统以 BMS 租户用户体系实现单点登录；客户端注册复用 sys_client（redirect_uris/grant_types 扩展字段）

### 出站集成（BMS 调外部）

- 同步调用：httpx 统一封装（超时/重试/熔断，复用降级机制）
- 事件推送：Webhook 订阅——事件发生后经 RocketMQ 事件总线异步推送至注册 URL，HMAC 签名校验、指数退避重试、失败记录

## 多数据源策略

支持三层数据架构（分层设计，逐层可选）：

1. **多业务库并存**：config.toml 声明多个数据源（每库含主从连接）；SQLAlchemy 2.0 多异步 bind；repositories 层按模块指定数据源。**多租户落地于本层**：一租户一独立库，平台库 sys_tenant.db_key 指向数据源配置，请求按租户路由到对应异步 engine（懒加载创建、闲置回收、池上限控制）；新租户开通自动建库+迁移+种子；Alembic 批量迁移遍历全部租户库
2. **主从读写分离**：每个业务库可配一主多从；AsyncSession 工厂按读写标记选择异步引擎，写操作与事务强制走主库
3. **分库分表**：抽象 ShardingRouter 层（分片键 → 物理库/表解析），真实分片规则 MVP 落地——sys_operation_log 与 sys_open_log 按月分表（分片键=时间，物理表名带 yyyyMM 后缀），新月份分片表由 Celery 定时任务提前创建；分片键支持按租户/按时间，由接入模块声明；Python 生态无成熟分片中间件，采用应用层自研路由

迁移策略：Alembic 按数据源分别维护迁移脚本，只管理各库 schema；租户库批量迁移遍历 sys_tenant。开发环境用多个 SQLite 文件模拟平台库、租户库与归档库；主从路由、分片路由与归档流转以集成测试覆盖。

## 数据库兼容

- 开发环境默认 SQLite，生产同时支持 MySQL 8.x 与 PostgreSQL 16+
- ORM 层禁用方言特有功能：JSON 等类型使用跨方言通用类型，分页统一 limit/offset
- Alembic 维护 MySQL / PostgreSQL 两套方言迁移；SQLite 开发库自动建表
- 测试环境与开发环境一致使用 SQLite

### 数据规范

- 主键：业务表统一雪花 ID（yitter/IdGenerator），关联表用联合主键
- 软删除：业务数据软删除（deleted_at 时间戳），审计类数据物理保留；查询默认过滤已删除；业务唯一约束统一建为 (唯一字段, deleted_at) 复合唯一索引——未删行 deleted_at 为 NULL，SQLite/MySQL/PostgreSQL 三库均允许多个 NULL 不冲突，删除时写入时间戳即释放唯一键；PostgreSQL 可另加部分唯一索引优化。软删除数据进回收站（recycle 业务：查看/恢复），恢复即清除 deleted_at，恢复动作落操作日志与字段级审计；过期软删除残留由 Celery 定时物理清理
- 审计字段：created_at / created_by / updated_at / updated_by，由 ORM 事件自动填充
- 乐观锁：version 字段，更新时比对，防止多实例并发覆盖
- 时间：统一 UTC 存储，前端按本地时区展示
- 多语言：固定文案存 sys_i18n_message（页面维护）；业务展示文案由 {主表}_i18n 附表按 locale 存储，查询关联当前 locale，缺省回退主表默认文案；语言清单 sys_i18n_locale 动态扩展，rtl 标记驱动布局
- 字符集：MySQL utf8mb4、PostgreSQL UTF8
- 索引：排序字段、外键、数据权限过滤字段必须建索引；唯一性约束用唯一索引
- SQL 规范：禁止 SELECT *；批量写入用 bulk；事务尽量短；定期走查慢查询日志

## 认证与安全

- 双 token：access token（30 分钟）+ refresh token（14 天，滚动轮换）
- SSO 单点登录：OIDC 为主 + CAS 兼容——登录页展示租户配置的 IdP 入口（sys_identity_provider），外部 IdP 认证回跳后经 sys_user_identity 全局映射定位租户并 JIT 自动建号，签发 BMS 双 token；本地账号密码登录并存（超管应急通道，防 IdP 故障锁死）
- 移动端免登：企业微信/钉钉内嵌 H5 走各自 OAuth 免登，复用外部身份框架；手机浏览器走账号密码/SSO
- 存储：access token 仅存前端内存（刷新页面后静默续期）；refresh token 存 httpOnly + Secure + SameSite cookie，防 XSS 窃取；CSRF 采用双重提交校验（SameSite=Lax + 自定义请求头校验）
- 密码：PBKDF2 哈希（标准库）；登录失败限流（slowapi，Redis 后端，如 5 次锁 15 分钟），连续失败 3 次后登录页强制图形验证码
- 密码与账号策略（sys_config 可配）：复杂度校验（长度/字符组合）、90 天有效期强制改密（pwd_changed_at 驱动）、近 5 次历史密码不可重复（pwd_history）、180 天未登录自动锁定（定时任务扫描 last_login_at）
- 找回密码：登录页自助找回，邮箱与企业微信/钉钉双通道——输入已登记邮箱发送含短时效 token 的重置链接（复用邮件模板入库体系与 aiosmtplib），或经企业微信/钉钉内身份验证（复用 sys_user_identity 绑定）；token 存 Redis（TTL 15 分钟、单次有效）；重置链接/验证码申请叠加 Redis 限流防滥用（如每账号 1 次/5 分钟、每 IP 5 次/小时）；重置成功后强制失效该账号全部会话
- 数据脱敏：敏感字段（手机号/邮箱/身份证等）注册标记，序列化层默认掩码展示（如 138****5678）与导出脱敏；持 data:plain 权限码方可查看明文
- 登出：refresh token 加入 Redis 黑名单即时失效
- 多端会话：允许同一账号并发登录，但活跃会话数设上限（默认 5 个，sys_config 可配），超出后最旧会话自动失效；登录产生独立会话记录（sys_session）；会话有效标记存 Redis，鉴权时随 access token 一并校验（每请求一次 Redis 读）；管理端可查看在线会话并强制踢出——作废该会话 refresh token 并失效 Redis 会话标记，踢出即时生效，同时经 Socket.IO 广播"会话失效"关闭该会话全部实时连接
- 密钥管理：JWT secret 支持轮换（新旧并行验证期），DB/Redis/MinIO 凭据走 Secret 管理，不落库不入镜像
- 上传安全：文件类型白名单 + 大小上限（默认 20MB，超限走分片上传，单文件上限可配置如 2GB）+ 分片 SHA256 校验 + 整文件校验，存储于 MinIO 私有桶；下载用预签名 URL（限时有效），后端不代理文件流
- 基础防护：ORM 参数化防 SQL 注入、Element Plus 默认转义防 XSS、接口级限流（slowapi，Redis 后端）
- 日志：登录日志、操作日志落库；操作日志的 action 记录权限码（业务:动作，与权限体系对齐）；敏感字段（密码、token、密钥）脱敏后记录，不落原始值
- AI 安全（阶段十四）：AI 交互全量落审计（ai_chat_log），提示词与响应不出租户边界；RAG 检索上下文（历史审批、文档分段等）遵守动作级数据权限范围；prompt 注入防护（角色隔离、指令约束、输出校验）；AI 结果默认仅辅助展示（意见、草稿、检索、告警建议）。AI 自动执行写操作（ai.auto_execute）与 AI 自动审批（ai.auto_approve）为两个独立功能，各自由 sys_config 开关控制、默认关闭——ai.auto_approve 依赖 ai.auto_execute 开启（未开启时配置拒绝保存并强制关闭）；开启时仅限配置白名单（写接口、审批节点），执行前强制二次确认，自动执行全量落 ai_chat_log 与操作日志、结果可人工撤销；AI 接口独立限流与预算控制

## 性能与高并发设计

### 性能目标

- 目标：≥ 500 并发用户，P99 响应 ≤ 1s（登录、列表查询、审批提交主链路）；验收前压测验证

### 部署规模与连接规划

- uvicorn 多 worker 部署（如 4 worker）；连接池 pool_size / max_overflow 按 worker 数规划，确保 总连接数 = worker × (pool_size + max_overflow) ≤ 数据库 max_connections 的 70%，预留其他客户端；多租户场景按活跃租户数规划连接（engine 懒加载 + 闲置回收），避免全量租户连接常驻
- 每个 worker 独立连接池；写事务尽量短，避免长事务占用连接

### 缓存策略

- 只读热数据（字典、系统参数、菜单树、业务/动作权限码）Redis 缓存，短 TTL；多语言数据（字典、菜单树）缓存键含 locale 维度；租户数据缓存键含 tenant 前缀
- Redis key 命名规范：统一格式 `bms:{租户标识|global}:{域}:{业务键}`，如 bms:global:captcha:{uuid}、bms:global:token:blacklist:{jti}、bms:{tenant}:sess:{session_id}、bms:{tenant}:dict:{locale}:{type}、bms:global:rate:{维度}:{目标}；所有 key 必须携带 TTL——缓存类短 TTL + 随机偏移，持久状态类（token 黑名单、会话标记、分布式锁、幂等键）TTL 与业务有效期对齐；租户数据 key 必含租户前缀，平台数据用 global
- 三防：
  - 穿透：查询不存在的数据缓存空值（短 TTL）
  - 击穿：热点 key 过期用互斥锁（Redis SETNX）单实例重建
  - 雪崩：过期时间加随机偏移，避免大量 key 同时失效
- 一致性：先写库后删缓存；写操作后同一会话内读主库，避免读到从库旧数据

### 分页与查询

- 常规列表 limit/offset（限深 100 页）；大数据量列表（如操作日志）游标分页兜底（last_id + 排序键索引）
- 排序字段、外键、数据权限过滤字段必须建索引；禁止 SELECT *；批量写入用 bulk；N+1 走查

### 限流与降级

- 接口级限流：slowapi（limits 库，Redis 后端，IP / 用户维度），登录限流优先
- 降级：
  - Redis 故障：缓存失效直连 DB + 日志告警，限流降级为 memory 后端（本地计数）
  - 主库故障：只读模式（从库响应查询，写接口返回明确错误）
  - 接口熔断：对耗时异常的依赖调用快速失败（短超时、重试幂等）

### 超时与资源

- DB 连接/执行超时、Redis 操作短超时快速失败（如 500ms）
- 操作日志/登录日志：经 RocketMQ 异步写入降低主库写压力
- 慢查询日志开启，定期走查

## 部署与运维

### 部署拓扑

- 入口：nginx（TLS 终止、/api 反向代理、前端静态资源托管）→ backend 多副本（无状态，可横向扩展）
- 数据层：MySQL / PostgreSQL 主从（读写分离 + 故障切换，1 平台库 + N 租户库 + 1 归档库）+ Redis（Sentinel/Cluster 高可用，key 含租户前缀）+ RocketMQ + ElasticSearch + Milvus（阶段十四）+ MinIO（按租户 bucket 前缀隔离，归档文件亦存于此）
- 监控：Prometheus + Loki + Grafana + Alertmanager + Jaeger（trace 存储展示，otel-collector 统一采集）

### 集群设计要点

- **无状态**：JWT 无状态（会话有效标记存 Redis，鉴权顺带校验，毫秒级开销）；token 黑名单、限流计数存 Redis；文件存 MinIO；定时任务由 Celery 分布式执行——任一实例可随时停机、随时扩容
- **缓存一致性**：统一走 Redis，不引入本地内存缓存（多实例内存独立会造成数据不一致）
- **分布式锁**：Redis SETNX 实现，用于防并发与幂等拦截（幂等键前置去重，唯一约束兜底，见"API 设计规范"节）
- **实时推送**：Socket.IO 连接分散于各实例，经 Redis 适配器广播，任一实例可推送至任意用户；强制踢出时广播"会话失效"事件，关闭该会话全部实时连接（HTTP 接口侧由 Redis 会话标记校验同步拦截）
- **分布式限流**：slowapi（limits 库）Redis 后端（登录防爆破已采用），Redis 故障降级 memory 后端
- **连接池**：各数据源配置 pool_size / max_overflow，避免实例增多时连接耗尽
- **数据库高可用**：主从 + 故障切换策略；读写分离期间定义主库故障预案（从库提升）
- **消息队列高可用**：RocketMQ 多副本（broker 主从、同步刷盘 + 消息持久化），节点故障消息不丢（生产部署 RocketMQ 集群，MVP 单机）；Celery（Redis broker）beat 单副本运行（避免重复调度），worker 多副本横向扩展
- **检索高可用**：ElasticSearch 生产多节点集群（索引多副本、故障自动分片迁移），MVP 单节点；检索数据可经事件重放全量重建索引，检索服务故障时可降级为数据库模糊查询兜底
- **配置与密钥**：config.toml + 环境变量覆盖；密钥（DB/Redis 密码、JWT secret、MinIO 凭据）走 Secret 管理（K8s Secret / Docker secrets），不落库、不入镜像

### 基础设施编排

- 初版 Docker Compose：backend（多副本）+ celery-worker（多副本）+ celery-beat（单副本）+ event-worker（RocketMQ 事件消费者，多副本）+ frontend（nginx，托管 PC + 移动端静态资源）+ redis + rocketmq（nameserver + broker）+ elasticsearch + milvus（含 etcd，MinIO 复用）+ minio + 数据库（按环境选择 MySQL 或 PostgreSQL）+ 监控（Prometheus/Loki/Grafana/Alertmanager）+ jaeger（trace）+ otel-collector
- nginx 需支持 WebSocket：/socket.io 路径放行 Upgrade/Connection 头；负载均衡用 ip_hash / Cookie 亲和（sticky session）——Socket.IO 连接升级后必须固定在同一后端实例，否则多实例下连接抖动断线
- 健康检查：/healthz（存活）、/readyz（依赖就绪），供编排系统滚动发布
- TLS 与 HTTPS：nginx 层配置，cookie Secure 标志随环境启用
- 安全响应头：nginx 统一配置 CSP、HSTS（dev 环境关闭）、X-Frame-Options（SAMEORIGIN，兼容同源 Grafana 嵌入）、X-Content-Type-Options、Referrer-Policy、Permissions-Policy
- 演进：数据量或部署规模增长后迁移 Kubernetes
- 优雅停机：SIGTERM 后停止接收新请求、等待在途请求完成，配合 K8s preStop / terminationGracePeriod 配置

### 备份与恢复

- 数据库：每日全量备份 + 开启 Binlog/WAL（时间点恢复 PITR）；保留 30 天，异机存储；归档库纳入备份范围；备份任务与记录由页面管理（sys_backup_task/sys_backup_log，Celery 调度，支持手动备份与恢复演练登记）
- MinIO：对象数据定期增量备份 + 生命周期策略；元数据随数据库备份
- 恢复：定期演练恢复流程，恢复时效目标 RTO ≤ 4 小时、数据丢失目标 RPO ≤ 1 小时
- 数据归档：全表可配归档策略（sys_archive_policy），两段式流转——热表超阈值迁归档库（可在线查询），按保留期转对象存储冷化；过期归档文件与软删除残留由 Celery 物理清理

## 明确不采用

MVP 明确不采用的技术与方案（防止后续反复讨论，按需再评估）：

- Kubernetes：MVP 用 Docker Compose 部署，数据量或部署规模增长后按"演进路线"迁移
- Kafka：消息量级未到，RocketMQ 已覆盖事件总线，Redis 已覆盖任务队列
- MFA / 2FA：账号密码 + 图形验证码 + 找回密码双通道 + 限流已满足 MVP 安全基线
- 原生 WebSocket：统一采用 Socket.IO（自动重连、Redis 跨实例广播）
- APNs / FCM 等移动端系统推送：MVP 站内信 + 企业微信/钉钉内免登即达
- 微服务拆分：保持单体模块化 + 独立 worker 进程，跨域调用走事件总线。评估结论——微服务虽带来独立部署、故障隔离、独立扩缩容等收益，但对本项目代价过大：分布式事务（审计哈希链、软删除复合唯一约束、乐观锁等强一致场景）、跨服务延迟（威胁 P99 ≤ 1s 目标）、权限体系与多租户路由横切全局难以拆分、基础设施已 8+ 组件再拆分运维翻倍、小团队维护成本高；单体 + worker 已通过事件总线获得模块解耦与独立伸缩的大部分收益
- 前端 SSR / Nuxt：管理端与 H5 均为 SPA
