# 基座文档清单

> 通用基座权威清单：bms 仓库为权威源维护，产品仓库按本清单订阅同步（见《平台可扩展性规划》4.3）

[文档首页](文档首页.md) › 基座文档清单　|　[配套：平台可扩展性规划 →](规划/平台可扩展性规划.md)

## 1. 基座定义 <a id="def"></a>

三层分层（见《[平台可扩展性规划](规划/平台可扩展性规划.md)》第 3 节）：**通用基座** / **平台专属** / **产品专属**。
- **通用基座**：跨项目共享的规范与基础设施，判据——内容对任意基于平台的产品都适用（规范方法论、共享基础设施、平台通用能力）。
- 平台专属（规划/项目/设计/平台部署记录）与产品专属内容**不登记**本清单。

## 3. 平台默认标识说明 <a id="platform-prefix"></a>

基座文档中 `bms`、`bms_`、`BMS_`、`bms:` 等为**本平台默认标识**（仓库名、库名、环境变量前缀、镜像名、Redis key 前缀等，定义见《[命名规范](规范/命名规范.md)》第 3 节与《[英文简称规范](规范/英文简称规范.md)》）。
- 复用本平台的产品：沿用默认标识（作为平台扩展运行时即平台标识）；
- 独立部署的产品：可整体替换为自身标识。

## 4. 同步与变更提示 <a id="sync"></a>

- 权威源：通用基座只在 bms 仓库演进，产品订阅同步，不 fork 二次维护。
- 同步脚本：`scripts/tools/base-sync/base-sync.py`（见 `scripts/tools/base-sync/README.md`）按本清单比较 bms 与产品仓库差异 → 输出变更明细 → 人工确认后覆盖（不引入 git submodule）。

```bash
# 输出 bms 与产品仓库差异（dry-run 不写盘）
python3 scripts/tools/base-sync/base-sync.py sync --target <产品仓库>

# 只更新规则文件，或只同步某子目录
python3 scripts/tools/base-sync/base-sync.py sync --target <产品仓库> --scope update
python3 scripts/tools/base-sync/base-sync.py sync --target <产品仓库> --dir 规范

# 确认后实际写入
python3 scripts/tools/base-sync/base-sync.py sync --target <产品仓库> --apply
```

- 差异分类：**更新**（产品侧已有但不同，覆盖前审阅行数）、**新增**（产品侧缺失，按需补入）、**产品独有**（产品业务专属文件，不删不覆盖）。
- 排除项：`文档/用户文档/`（本地资源凭据模板，各仓库自带副本、内容各异）。
- 变更提示：bms 提交涉及基座路径时，提交信息与 AGENTS 注明「基座变更，产品仓库需同步」；产品侧运行同步脚本刷新。
- 首次同步：cw 早期规范为人工改编版（BMS→CW 前缀替换），按权威源切源覆盖为中性权威版；cw 特有增补迁到产品专属文档。

## 5. 维护约定 <a id="maintain"></a>

- 新增/删除基座目录或文件：同步更新第 2 节清单。
- 平台专属（`文档/规划`、`文档/项目`、`文档/设计`）与产品专属内容：不登记本清单。
- 基座文档中性化口径：项目称谓用「本项目/本平台」，平台前缀按第 3 节保留标注。
