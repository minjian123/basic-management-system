## 1. 技术概述 <a id="overview"></a>

**接口契约**是插件化架构的地基：主程序用一份稳定的约定，规定「实现必须提供哪些方法、参数是什么、返回什么、抛什么异常、是同步还是异步、何时被调用」。约定越清晰，实现越可替换，主程序越不必为每种实现写特例。

- **定位**：连接「端口定义」（[02 端口适配器](02_插件化架构_端口适配器.md)）与「发现/注册」（[04 插件发现机制](04_插件化架构_插件发现机制.md)、[08 自建注册表](08_插件化架构_自建注册表.md)）的中间层。
- **载体**：Python 中常用抽象基类（`abc.ABC`）或结构化子类型（`typing.Protocol`），也可用函数签名、数据类描述。
- **目标**：换实现时业务代码零改动；契约测试可覆盖全部实现；不兼容变更可被识别与拒绝。

## 2. 核心概念与原理 <a id="principles"></a>

| 概念 | 说明 |
| --- | --- |
| 契约（Contract） | 端口的调用约定，包含方法签名、语义、异常、异步性、生命周期与线程/并发假设 |
| 抽象基类（ABC） | `abc.ABC` + `@abstractmethod`，**名义子类型**：实现类须显式继承，未实现抽象方法则实例化报错 |
| Protocol | `typing.Protocol`，**结构化子类型**：不要求继承，只要方法形状匹配即视为实现，支持静态检查 |
| 运行时校验 | 用 `isinstance(obj, ABC)` 或 `hasattr` 检查实现是否满足契约；`Protocol` 需 `@runtime_checkable` |
| 契约测试（Contract Test） | 一组针对接口的测试，任何实现都必须通过；保证换实现不改变行为 |
| 兼容性 | 契约视为对外承诺：新增方法优先给默认实现，删除/改签名属破坏性变更，需文档与迁移 |
| 回退链 | 主实现不可用时的降级实现（如同步回退、内存回退），也须满足同一契约 |

**两种载体的差异**：

```python
# 名义子类型：实现必须继承，运行时校验直接可用
from abc import ABC, abstractmethod

class IdGenerator(ABC):
    @abstractmethod
    async def next_id(self) -> int: ...

# 结构化子类型：不强制继承，静态检查友好，运行时校验需标记
from typing import Protocol, runtime_checkable

@runtime_checkable
class IdGenerator(Protocol):
    async def next_id(self) -> int: ...
```

| 维度 | ABC | Protocol |
| --- | --- | --- |
| 是否需继承 | 需要 | 不需要 |
| 静态检查 | 一般 | 好（pyright/mypy） |
| 运行时 `isinstance` | 直接支持 | 需 `@runtime_checkable`，且只检查方法存在性 |
| 防止漏实现 | 实例化时报错 | 静态检查期发现 |
| 适合场景 | 平台定义、实现方明确继承 | 结构性兼容、第三方实现不便继承时 |

> 本项目同时使用 pyright 做静态检查、pytest 做运行期测试，**ABC 与 Protocol 可组合**：平台以 ABC 给出明确基类，另以 Protocol 描述可选能力（如 `SupportsHealthCheck`）。

## 3. 在本项目中的用途 <a id="usage"></a>

- **平台能力端口的统一写法**：ID 生成、文件存储、通知发送、缓存、认证后端、LLM 适配层等，均以「一个 ABC/Protocol + 一份契约测试 + 多个适配器」的形式提供。
- **异步契约**：后端是 FastAPI 异步栈，涉及 I/O 的端口方法一律 `async def`；纯计算的实现（如雪花算法）内部可同步，但对外方法保持异步一致，避免业务层分叉。
- **标识与错误码**：契约中的异常应映射到平台统一错误码体系，实现不得抛出未登记的框架内部异常。
- **与 SQLAlchemy 模型解耦**：契约只使用领域类型/Pydantic 模型/标准库类型，不暴露 `Session`、`Engine` 等实现细节，保证适配器可换、核心层可独立测试。
- **契约测试入库**：为每个端口提供可复用的契约测试基类，新增实现只要继承测试基类即可验证（见 [11 生命周期与热插拔](11_插件化架构_生命周期与热插拔.md) 的验收口径）。

## 4. 契约要素设计 <a id="elements"></a>

| 要素 | 设计要点 | 反例 |
| --- | --- | --- |
| 方法签名 | 参数与返回值用抽象类型；避免可选参数堆叠 | 返回具体数据库 ORM 对象 |
| 异步性 | 涉及 I/O 的显式 `async`；同步实现放线程池 | 异步栈里放同步阻塞方法 |
| 异常约定 | 定义领域异常，映射统一错误码；文档化可能抛出的异常 | 直接抛厂商 SDK 异常 |
| 生命周期 | 明确 `init/start/stop` 是否需要、由谁调用 | 实现方在 `__init__` 里连外部服务 |
| 并发与线程安全 | 声明是否可并发调用、是否有共享状态 | 隐式假设单线程 |
| 幂等与事务 | 明确是否幂等、是否参与调用方事务 | 在生成 ID 时偷偷写库 |
| 依赖声明 | 实现外部依赖（Redis/ZK）在插件元数据声明 | 运行时才发现缺依赖 |

**契约粒度**：按能力聚合，一个端口 3~7 个方法；从不同时使用的方法组拆成独立端口（如把 `Storage` 与 `Presigner` 分开）。

## 5. 兼容性与演进 <a id="compat"></a>

- **加法优先**：新增方法给默认实现（ABC 提供默认实现，或 Protocol 设可选）；不改既有语义。
- **破坏性变更**：改签名、删方法、改异常语义视为破坏性，须提前公告、提供迁移步骤与过渡期，过渡期内新旧并存。
- **版本声明**：插件声明其适配的框架/契约版本范围，装配阶段校验，不匹配则跳过并告警，而非运行时报错。
- **契约测试为准**：兼容性以契约测试为客观判据；全部实现通过即认为兼容，避免口头约定。
- **文档锚点即契约**：平台文档中被产品/插件引用的章节锚点，同样按对外契约管理。

## 6. 常见问题与注意事项 <a id="pitfalls"></a>

- **契约里塞实现细节**：接口方法带 `session`、`redis` 参数，等于把实现泄漏给调用方。
- **只用 `hasattr` 做校验**：方法存在不代表行为正确，仍需契约测试。
- **契约过宽**：一个接口十几个方法，任何实现都要实现全部，导致空实现遍地。
- **忽略异步语义**：同步实现被异步调用直接阻塞事件循环，高并发下拖垮服务。
- **异常不收敛**：实现各自抛不同异常，上层无法统一处理与降级。
- **不写契约测试**：换实现靠手工点，遗漏分支在线上暴露。
- **把 Protocol 当运行时校验银弹**：`runtime_checkable` 只检查方法名，不检查签名与语义。
