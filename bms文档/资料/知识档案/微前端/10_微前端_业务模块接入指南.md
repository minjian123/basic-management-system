## 1. 目的与适用 <a id="purpose"></a>

本文是**操作范式**：任何业务页面（平台内示例、产品仓库模块）按模块形态接入时，照本文步骤即可完成「注册声明 → 独立构建 → 运行时加载 → 独立发布 / 回滚」。

- **适用**：新业务页面按运行时模块形态（清单 `mode: remote`）独立构建与发布；平台自身页面仍在主应用内（构建期合并 `mode: local`）。
- **权威口径**：语义与契约见平台《架构设计 · 前端模块契约》《架构设计 · 前端架构》§9；强制口径见《[前端开发规范](../../../规范/前端开发规范.md)》「依赖共享 / 运行时模块隔离 / 模块清单与发布治理 / 模块可观测」节；发布流程见《[部署发布规范](../../../规范/部署发布规范.md)》「模块发布与回滚」节。本文只写**怎么照抄**，不重复规范正文。
- **参照实现**：首个模块样例 `frontend/modules/sample/`（示例数据管理：查询筛选 + 列表 + 详情 + 独立表单）——本文所有样例均取自它。

## 2. 前置与总原则 <a id="principles"></a>

| 原则 | 说明 |
| --- | --- |
| 模块自包含 | 模块只经 `setup(context)` **只读快照**消费宿主能力；不直连宿主 store / router、不建宿主级实例、不持久化、不改全局（隔离约定，机器护栏拦截） |
| 复用优先 | 页面复用阶段四组件库（`@bms/ui-ep`）、契约类型（`@bms/core`）与设计令牌；**不重复造件、不硬编码色值** |
| 清单唯一来源 | 模块的入口 / 版本 / 加载形态 / 可见性只在宿主清单登记；加载、发布与回滚只改清单 |
| 版本单一来源 | 模块版本取自模块工程 `package.json`，构建期注入模块定义；产物元数据为「产物版本」权威 |
| 契约版本 | 模块自报平台常量 `MODULE_CONTRACT_VERSION`；加载器与发布 / 回滚**双端校验**，不一致即拒绝 |
| 独立计量 | 模块产物单独计量、单独归档，不并入宿主首屏阈值 |

## 3. 模块工程目录结构 <a id="layout"></a>

```text
frontend/modules/<模块名>/
├── package.json                  # @bms/module-<模块名>（版本单一来源；scripts: dev/build/build:standalone/preview/budget/guard:isolation/lint/test/typecheck）
├── pnpm-lock.yaml                # 单一锁文件（必须提交；packages / apps / modules 收敛于根 workspace）
├── .npmrc                        # 国内源（pnpm 读取）
├── .prettierrc.json
├── vite.config.ts                # MF remote 配置（name/filename/exposes/shared + 版本注入 + 产物元数据 + sourcemap + 第三方分包）
├── vitest.config.ts              # 版本注入与构建同源；jsdom + element-plus 内联
├── tsconfig.json / tsconfig.app.json / tsconfig.node.json
├── eslint.config.js
├── budget.json                   # 模块产物体积阈值（入口闭包 + 最大块 + 入口块数 + 页面异步块数 + 页面块命名特征）
├── index.html                    # 独立预览壳（最小 --bms-* 令牌兜底；不进远端产物）
├── scripts/
│   └── check-bundle-budget.mjs   # 复用平台 module-metrics 单一计量
├── src/
│   ├── index.ts                  # 默认导出模块定义（八类注册声明；版本构建期注入）
│   ├── standalone.ts             # 独立预览入口（自带本地框架副本；隔离扫描豁免）
│   ├── env.d.ts                  # __BMS_MODULE_VERSION__ 与 ui-ep 间接依赖的类型补充
│   ├── domain.ts                 # 领域类型与选项常量
│   ├── runtime.ts                # 宿主上下文只读消费的派生状态
│   ├── i18n/messages.ts          # 模块文案真源（兼作 i18nPacks 注册载荷）
│   ├── composables/              # 模块内组合式（如 useXxxI18n）
│   ├── services/                 # 数据通路（占位实现，后续替换为真实接口）
│   ├── components/               # 模块内组件（字段渲染器 / 工作台卡片 / 区域件）
│   └── views/                    # 页面（列表 / 详情 / 表单；一律异步分包）
└── tests/
    ├── module-contract.spec.ts   # 经契约工厂 describeModuleContract 跑同一套断言（必需；护栏断言齐备）
    ├── module-definition.spec.ts # 模块专属断言（清单身份 / 声明键 / 路由 meta）
    ├── module-context.spec.ts    # 注入上下文只读消费与降级
    ├── <service>.spec.ts         # 数据服务
    └── views.spec.ts             # 页面渲染与表单校验
```

## 4. 模块定义与注册声明样例 <a id="registration"></a>

### 4.1 模块定义骨架 <a id="define"></a>

```ts
import { MODULE_CONTRACT_VERSION, WorkbenchCardProvider, defineModule } from '@bms/core'

export const sampleModule = defineModule({
  manifest: { name: 'sample', version: __BMS_MODULE_VERSION__, contractVersion: MODULE_CONTRACT_VERSION },
  setup: (context) => {
    applyHostContext(context) // 只读消费注入上下文（缺失降级）
    return { routes, components, fieldRenderers, icons, cards, regions, themeTokens, i18nPacks }
  },
})
export default sampleModule // 入口**默认导出**模块定义（MF 暴露 ./module 的约定）
```

### 4.2 八类注册声明 <a id="channels"></a>

| 通道 | 键规则 | 样例 |
| --- | --- | --- |
| `routes` | 键 = 路由名；`path` 以 `/` 开头；`component` 为 `() => import(...)` | `/sample`、`/sample/detail/:id`、`/sample/form/:id?` |
| `regions` | `<模块名>:<区域项>`；`area` 为点分区域标识 | `sample:header-badge`（`area: 'layout.header'`，`order: 20`） |
| `components` | `<模块名>:<键>` | `sample:priority-tag` |
| `fieldRenderers` | `<模块名>:<键>`；可选 `fieldType` | `sample:priority`（`fieldType: 'priority'`） |
| `icons` | `<模块名>:<键>` | `sample:record` |
| `cards` | `<模块名>:<键>` | `new WorkbenchCardProvider('sample:summary', () => import('...'), '示例数据概览')` |
| `themeTokens` | `<模块名>:<主题标识>`；键须 `--bms-*` | `sample:accent`（`{ '--bms-sample-accent': '#0f766e' }`） |
| `i18nPacks` | `<模块名>:<语言标识小写>` | `sample:zh-cn` / `sample:en` |

> 模块注册键须以 `<模块名>:` 开头（防覆盖平台项）；**只声明自有令牌**，不覆盖宿主核心令牌（会全局污染宿主配色）。

### 4.3 路由菜单 meta 约定 <a id="route-meta"></a>

路由 `meta` 承载菜单语义（宿主据此从注册表快照装配菜单，无需宿主硬编码）：

| `meta` 键 | 语义 | 缺省 |
| --- | --- | --- |
| `title` | 页面 / 页签 / 菜单标题 | 缺失 → **不登记菜单项**（仍注册路由） |
| `icon` | 菜单图标名 | 无 |
| `menu` | `false` → **不进菜单**（详情 / 表单页） | `true` |
| `group` | 菜单分组标题（同模块菜单项归入该组） | 无 → 顶级项 |
| `groupIcon` | 分组图标名 | 取组内首项 `icon` |
| `devOnly` | `true` → **生产态不展示**（开发态可见） | `false` |
| `keepAlive` | 页签缓存 | `false` |

```ts
routes: [
  { path: '/sample', name: 'SampleList', component: () => import('./views/SampleList.vue'),
    meta: { title: '示例数据管理', icon: 'document', group: '示例模块', groupIcon: 'document', keepAlive: true } },
  { path: '/sample/detail/:id', name: 'SampleDetail', component: () => import('./views/SampleDetail.vue'),
    meta: { title: '记录详情', menu: false } },
  { path: '/sample/form/:id?', name: 'SampleForm', component: () => import('./views/SampleForm.vue'),
    meta: { title: '记录表单', menu: false } },
]
```

## 5. 页面与数据 <a id="pages"></a>

- **页面组合**：`PageContainer` + `QueryFilter`（查询筛选）+ `DataTable`（列表 / 排序 / 分页 / 行双击）+ `DescriptionList`（详情）+ 输入件（表单）；状态标签复用 `StatusTag`。
- **数据通路（占位）**：模块内自包含服务（`services/`），签名字符对齐后端统一分页 `{ list, total, page, size }`；真实接口联调时仅替换服务实现，页面与路由不变。
- **文案**：模块文案真源（`i18n/messages.ts`）兼作 `i18nPacks` 注册载荷；页面经模块内组合式取文案，不硬编码中文、不直连宿主 i18n 实例。
- **样式**：一律 `<style scoped>`；只消费 `--bms-*` 令牌（含模块自有令牌）；类名以模块名前缀（如 `.sample-`）。

## 6. 构建与依赖声明 <a id="build"></a>

| 项 | 口径 |
| --- | --- |
| MF 角色 | remote：`name` = 清单 `name`；`filename: 'remoteEntry.js'`；`exposes: { './module': './src/index.ts' }` |
| 共享依赖 | **与宿主同源**（`frontend/shared-dependencies.json`，单一来源）；模块侧 `import: false` + `strictVersion: true`（不打包本地副本，版本不满足即拒绝） |
| 平台基座包 | `@bms/core` / `@bms/ui-ep` 以 `file:` 依赖链接（保留裸标识符）；登记为**受控非共享项**（体积受阈值约束） |
| 两个构建目标 | 缺省 `dist/`（**远端产物**：只含容器 + 暴露模块 + 异步分包，不带 HTML 壳）；`build:standalone` → `dist-standalone/`（**独立预览产物**：带 HTML 壳与本地框架副本） |
| sourcemap | 开**外部 `.map`**（不内联）；发布按版本归档，发布前强校验要求存在 |
| 产物元数据 | 构建期产出 `dist/module.meta.json`（名称 / 版本 / 契约版本） |
| 版本注入 | `moduleVersionDefine` 注入 `__BMS_MODULE_VERSION__`（vitest 与构建同源，缺一即版本口径不一致） |
| 第三方分包 | `output.codeSplitting.groups` 将 `element-plus` 独立为 vendor 块（Vite 8/Rolldown 口径；`manualChunks` 被 MF 插件忽略）——避免 EP 的全局副作用被产物面隔离扫描误判为「模块自有块污染」 |
| 体积预算 | `budget.json` + `scripts/check-bundle-budget.mjs`：入口闭包 gzip / 最大块 / 入口块数 / 页面异步块数 / 页面块命名特征（页面一律异步分包、不得并入容器入口） |
| 隔离护栏 | 源码面随宿主护栏用例（`desktop-check`）；产物面 `pnpm run guard:isolation`（`module-build`） |

## 7. 发布与回滚 <a id="release"></a>

```text
cd frontend/modules/<模块名> && pnpm run build            # 1. 独立构建（产出 dist/ 与 module.meta.json）
node frontend/scripts/release-module.mjs publish --module <模块名>   # 2. 发布（四关校验 → 归档 → 清单 → 留痕）
node frontend/scripts/serve-module-releases.mjs          # 3. 起本机发布存储（默认 5002）
cd frontend/apps/desktop && pnpm run dev                  # 4. 起宿主（默认 5173），经菜单进入模块页面
```

| 动作 | 命令 | 说明 |
| --- | --- | --- |
| 发布 | `publish --module <名> [--origin <基址>] [--by <操作者>] [--force] [--dry-run]` | **四关强校验**（版本 / 隔离 / 共享 / sourcemap）→ 归档 `releases/<名>/<版本>/` → 清单指向 `…/<名>/<版本>/remoteEntry.js` → 留痕 |
| 回滚 | `rollback --module <名> [--to <版本>]` | 清单版本回退（缺省上一版本）；**产物按版本保留是回滚前提**；回滚后同步处理源码版本 |
| 停用 / 启用 | `disable` / `enable --module <名>` | 改清单 `enabled`（不加载、不挂载、不进菜单；保留入口与版本） |
| 状态 | `status [--module <名>]` | 打印清单条目 / 已归档版本 / 最近记录 |

- **版本不可变**：已归档版本不得覆盖（回滚依赖旧产物完整）；本地重发用 `--force`（记 `republish`，生产禁用）。
- **契约变更协同升级**：平台契约版本升级时，模块适配并升版本、重新构建发布；契约不匹配的产物不得入清单 / 不得回滚生效。
- **留痕**：`frontend/releases/release-log.json`（真源）+ `release-log.md`（摘要），随仓库提交。

## 8. 宿主侧接入 <a id="host"></a>

- **清单条目**：`apps/desktop/public/modules.json` 增一条 `{ "name": "<名>", "entry": "http://localhost:5002/<名>/<版本>/remoteEntry.js", "version": "<版本>", "mode": "remote" }`（发布脚本自动写入）。
- **菜单**：模块经路由 `meta` 声明菜单，宿主按 `group` 分组、`devOnly` 过滤**自动装配**——无需改宿主菜单代码。
- **消费接线**：区域渲染 / 令牌注入 / 文案并入随模块**挂载生效、卸载还原**（宿主已接线，模块只需声明）。
- **可观测与兜底**：加载失败 / 超时（10s）/ 初始化异常由宿主模块边界降级（带模块名与版本）、支持单模块重试；错误经总基类通道上报并带模块名与版本（模块侧无需额外接线，按规范命名即可）。

## 9. 自检清单 <a id="checklist"></a>

- □ 入口**默认导出**模块定义；清单 `name` / `version` 与自报严格一致；`contractVersion` = 平台常量
- □ 八类注册声明齐备且键带 `<模块名>:` 前缀；路由 `path` 以 `/` 开头、`component` 为函数
- □ 菜单 `meta` 正确（列表进菜单 / 详情表单 `menu:false` / 分组与生产可见性）
- □ 页面复用 `@bms/ui-ep` 组件与 `--bms-*` 令牌，无硬编码色值；样式全 `scoped`
- □ 无全局污染（原型 / 事件 / 样式 / 全局变量 / 根节点）与运行时违规（自建宿主实例 / 持久化）
- □ 模块文案走文案真源，不硬编码中文；只读消费注入上下文、缺失降级
- □ 共享依赖取自单一来源、`import:false` + `strictVersion`；第三方（`element-plus`）独立分包
- □ 开外部 sourcemap；`module.meta.json` 就位；`budget` 通过（页面异步分包）
- □ `pnpm run lint` / `typecheck` / `test` / `build` / `budget` / `guard:isolation` 全绿；`tests/module-contract.spec.ts` 经契约工厂跑同一套断言
- □ 发布经四关校验、留痕完整；回滚可执行（产物按版本保留）
