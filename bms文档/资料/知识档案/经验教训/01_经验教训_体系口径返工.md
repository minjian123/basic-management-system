## 1. 目的与用法

记录本体系「**主体继承 / 二开组合**」两轨口径的返工历史与教训，供后续设计与实现避坑。**教训是经验记录（可含时间线与具体成因），不是强制口径**；当同类经验积累成熟后，再提炼为条文回写《[AI开发规范](../../../规范/AI开发规范.md)》《[前端开发规范](../../../规范/前端开发规范.md)》《[后端开发规范](../../../规范/后端开发规范.md)》「架构铁律」节。

## 2. 当前口径（定案）

**主体开发（平台内建主线）用继承保统一，二次开发 / 定制用组合保灵活**——两轨不互斥，汇入同一登记与契约体系。继承链**固定前三段**（总基类 → 能力域基类 → 插件基类，前后端同名同序），其下按功能与抽象需要逐级细化（组件侧：组件根 → 能力基类 → 组件基类 → 具体件）；**横切功能即继承链上的基类**。权威口径见《[AI开发规范](../../../规范/AI开发规范.md)》「架构铁律」节与《[前端基类清单](../../../前端基类清单.md)》《[后端基类清单](../../../后端基类清单.md)》。

## 3. 三次返工（时间线）

### 3.1 一次返工：从「组合轨默认」到「能力入继承链」

- **原写法**：「组合轨默认、能力不在继承链上、域基类只是可选语义归类」。
- **后果**：能力平铺、无层次、无统一管理、散落系统各处。
- **处置**：修正为「**能力入继承链**」。

### 3.2 二次返工：固定前三段

- **原写法**：链层不固定、「固定分层 + 能力片段」框架。
- **处置**：按基类体系彻底对齐——固定前三段（总基类 → 能力域基类 → 插件基类），其下能力基类 → 组件基类 → 具体件逐级细化（各链长短不一）。

### 3.3 三次返工（2026-09-17 · 推翻重来级）

- **原写法**：「固定分层 + 能力片段」框架下层级固定、能力以「片段」形式挂接。
- **处置**：**不是修补，而是推翻重来**——层级不固定、**横切功能一律落为继承链上的基类**、**「能力类」实体不再存在**（能力声明机制由能力域基类承载）；设计口径与双端已交付件全部重做。
- **成因与处置详录**：见《[前端基类清单](../../../前端基类清单.md)》§1.1 与 §11.1。

## 4. 教训（写给后续）

1. **口径冲突先报冲突**：发现文档口径与铁律冲突时，**先报冲突、按铁律执行并回写冲突文档**，不得沿旧口径继续实施。
2. **继承链单一来源**：继承链全系统只有《前端基类清单》/《后端基类清单》一份，其他文档一律引用，不得各写一套。
3. **动手前必核铁律**：新增实现 / 设计 / 文档前必须核「架构铁律」；**不允许再次返工**。
4. **设计口径与已交付件一致性**：口径变更时，设计与已交付件须同步重做，避免文档与实现分叉。
