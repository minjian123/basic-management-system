# 钉钉登录技术介绍

## 1. 技术概述 <a id="overview"></a>

钉钉开放平台提供「网页方式登录第三方网站」（PC 扫码 / 账号密码登录）与「钉钉内免登」（移动端 H5、企业内部微应用）两类能力。当前官方**主推新版 OAuth 2.0** 方案，旧版 `oapi.dingtalk.com/connect/*` 与 `sns/*` 接口已归档为历史文档（功能未下线，作为存量兼容）。

- **新版入口**：授权域 `login.dingtalk.com`，接口域 `api.dingtalk.com`；用 `clientId` / `clientSecret`（企业内部应用即 AppKey / AppSecret）走标准 OAuth2 授权码换用户令牌。
- **旧版入口**：授权域与接口域都在 `oapi.dingtalk.com`；扫码 `scope=snsapi_login`、移动端免登 `scope=snsapi_auth`，换用户信息用 AppKey + AppSecret 的 HmacSHA256 签名，无独立用户令牌。
- **身份主键**：`unionId`（同一开发者主体下统一）/ `openId`（应用内唯一）；企业自建应用另有 `userid`（企业内唯一）。
- **协议形态**：新版接近标准 OAuth2 / OIDC 简化形态（有 `scope=openid`），但用户信息走独立通讯录接口，非标准 OIDC 验签。
- **本档案定位**：理解与联调用参考资料，协议细节以钉钉官方文档为准。

## 2. 核心概念与术语 <a id="concepts"></a>

| 术语 | 说明 |
| --- | --- |
| Client ID / AppKey | 应用标识；新版授权 URL 用 `client_id`，旧版与接口用 `appid` / `appKey` |
| Client Secret / AppSecret | 应用密钥，换取令牌用；只存服务端 |
| authCode / code | 授权回跳带来的临时授权码；新版回跳**同时返回 `code` 与 `authCode`，二者值相同**，取任一 |
| 用户级 accessToken | 新版 `userAccessToken` 换取，代表「某登录用户」的令牌，7200 秒；鉴权头 `x-acs-dingtalk-access-token` |
| 应用级 accessToken | 新版 `accessToken`（appKey + appSecret 换）或旧版 `gettoken`，代表应用自身，7200 秒 |
| unionId | 用户在同一开发者主体下的统一标识，跨应用稳定（推荐作外部身份主键） |
| openId | 用户在某应用下的标识，应用内唯一 |
| userid | 企业内部成员在通讯录内的标识（企业内唯一） |
| snsapi_login | 旧版扫码登录第三方网站的 scope |
| snsapi_auth | 旧版钉钉内免登第三方网站（移动端）的 scope |
| 签名（旧版） | `HmacSHA256(timestamp + "\n" + AppSecret)`，用于 `sns/getuserinfo_bycode`；时间偏差 > 1 分钟报 853002 |
| 免登码 | 钉钉容器内 JSAPI `requestAuthCode` 取到的一次性码（5 分钟、一次性），换 userid 用 |

## 3. 新版 OAuth2 扫码登录（主推） <a id="oauth2"></a>

### 3.1 授权跳转 <a id="oauth2-authorize"></a>

```text
https://login.dingtalk.com/oauth2/auth
  ?redirect_uri=URLENCODE(REDIRECT_URI)
  &response_type=code
  &client_id=CLIENT_ID
  &scope=openid|openid%20corpid
  &state=STATE
  &prompt=consent
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| redirect_uri | 是 | 回调地址，须与后台「钉钉登录与分享」登记一致，URLEncode |
| response_type | 是 | 固定 `code` |
| client_id | 是 | 企业内部应用填 Client ID（AppKey）；第三方填 SuiteKey |
| scope | 是 | `openid` 或 `openid corpid`（空格分隔、需编码） |
| prompt | 是 | `consent` 时进入授权确认页 |
| state | 否 | 原样回传 |
| org_type / corpId | 否 | 仅 scope 含 corpid 时有意义 |

- 回跳：成功 `redirect_uri?code=xxx&authCode=xxx&state=…`（`code` 与 `authCode` 值相同）；失败 `?error=…&state=…`。
- 内嵌二维码：引入 `https://g.alicdn.com/dingding/h5-dingtalk-login/0.21.0/ddlogin.js`，用 `window.DTFrameLogin(...)`；回调可直接拿 `authCode` 换令牌，页面须与 `redirect_uri` 同源。

### 3.2 换取用户令牌与用户信息 <a id="oauth2-exchange"></a>

```text
# 1) 以授权码换用户级 accessToken
POST https://api.dingtalk.com/v1.0/oauth2/userAccessToken
  body: { "clientId": "…", "clientSecret": "…", "code": "…", "grantType": "authorization_code" }
→ { "accessToken":"…", "refreshToken":"…", "expireIn":7200, "corpId":"…" }

# 2) 以用户级 accessToken 取用户信息（unionId 传 me 表示当前授权人）
GET https://api.dingtalk.com/v1.0/contact/users/me
  header: x-acs-dingtalk-access-token: ACCESS_TOKEN
→ { "nick":"…", "avatarUrl":"…", "mobile":"…", "openId":"…", "unionId":"…", "email":"…", "stateCode":"…" }

# 应用级令牌（服务端调通讯录等接口时用）
POST https://api.dingtalk.com/v1.0/oauth2/accessToken
  body: { "appKey":"…", "appSecret":"…" }
→ { "accessToken":"…", "expireIn":7200 }
```

要点：

- 第三方企业应用手机号会脱敏（如 `155****3240`）；真实值需应用具备相应权限。
- 用户级令牌 7200 秒、刷新令牌 30 天；过期用 `grantType=refresh_token` + `refreshToken` 续期。
- `unionId` 跨应用稳定，建议作外部身份映射主键；企业自建场景也可用 `userid` 关联通讯录。

## 4. 旧版扫码登录与免登（存量兼容） <a id="legacy"></a>

| 场景 | 授权入口 | scope | 回跳 / 返回 |
| --- | --- | --- | --- |
| 扫码登录第三方网站（跳转） | `https://oapi.dingtalk.com/connect/qrconnect?appid=&response_type=code&scope=snsapi_login&state=&redirect_uri=` | `snsapi_login` | 追加 `code` 与 `state` |
| 扫码登录（内嵌二维码） | JS `DDLogin({id,goto,...})`，`goto` 指向 `https://oapi.dingtalk.com/connect/oauth2/sns_authorize?…` | `snsapi_login` | JS 回传 `loginTmpCode`，再跳 `sns_authorize` |
| 账号密码登录第三方网站 | `https://oapi.dingtalk.com/connect/oauth2/sns_authorize?appid=&response_type=code&scope=snsapi_login&state=&redirect_uri=` | `snsapi_login` | 追加 `code` / `state` |
| 钉钉内免登第三方网站（仅移动端） | `https://oapi.dingtalk.com/connect/oauth2/sns_authorize?appid=&response_type=code&scope=snsapi_auth&state=&redirect_uri=` | `snsapi_auth` | 追加 `code` / `state` |

旧版换取身份：

```text
# 临时授权码换用户信息（AppKey + AppSecret 签名，无用户令牌）
POST https://oapi.dingtalk.com/sns/getuserinfo_bycode?accessKey=&timestamp=&signature=
  body: { "tmp_auth_code": "…" }
→ { "user_info": { "nick":"…", "unionid":"…", "openid":"…", "main_org_auth_high_level":true } }

# 企业内部微应用免登码换 userid（需应用 access_token）
POST https://oapi.dingtalk.com/topapi/v2/user/getuserinfo?access_token=
  body: { "code": "…" }
→ { "userid":"…", "unionid":"…", "name":"…" }

# unionid → userid（需应用 access_token）
POST https://oapi.dingtalk.com/topapi/user/getbyunionid
# userid → 用户详情（需应用 access_token）
POST https://oapi.dingtalk.com/topapi/v2/user/get
```

- **签名算法**：`signature = URLENCODE(HmacSHA256(timestamp + "\n" + AppSecret))`，`timestamp` 为毫秒；与服务器时间差 > 1 分钟报 `853002`，签名不符报 `853004`。
- **旧版应用令牌**：`GET https://oapi.dingtalk.com/gettoken?appkey=&appsecret=` → `access_token`、`expires_in`（7200 秒）。
- **新版与旧版令牌不通用**：新版用 `clientId/clientSecret` 换 `api.dingtalk.com` 的 token，鉴权头 `x-acs-dingtalk-access-token`；旧版用 `access_token` 查询参数。

## 5. 移动端 H5 免登 <a id="mobile"></a>

- **第三方网站免登（历史方案）**：钉钉容器内访问 `https://oapi.dingtalk.com/connect/oauth2/sns_authorize?appid=&response_type=code&scope=snsapi_auth&state=&redirect_uri=`，拿 `code` 后走 `sns/getuserinfo_bycode`。
- **企业内部 H5 微应用免登**：不用 URL，改用 JSAPI `dd.runtime.permission.requestAuthCode({ corpId })` 取免登码（5 分钟、一次性），再 `POST /topapi/v2/user/getuserinfo` 换 `userid`。
- 本项目移动端内嵌 H5 免登归阶段十七，与「真实企业凭据联调」同口径。

## 7. 本项目中的用途 <a id="usage"></a>

- **钉钉免登**：作为阶段六需求 02-4 的适配对象之一，按统一身份源契约实现授权跳转、换取用户身份、用户信息解析，复用同一 SSO 链路与 JIT 建号。
- **PC 扫码形态**：登录页经授权跳转入口渲染二维码，用户确认后回跳本项目回调完成会话签发；外部身份主体取 `unionId`（缺失回落 `openId`）。
- **配置载体**：企业应用凭据（`client_id` / `client_secret` 等）经 `sys_identity_provider` 配置，凭据缺失时入口不可用并明确提示；真实凭据联调归阶段十七。
- **统一外部身份框架**：钉钉与微信生态、OIDC、CAS 同属「外部身份 → `sys_user_identity` 映射 → 会话签发」一条链路，协议差异由各适配器承载，见《[authlib 技术介绍](../后端核心/authlib技术介绍.md)》。

## 8. 常见问题与注意事项 <a id="pitfalls"></a>

- **新版 / 旧版不要混用**：授权域、接口域、令牌体系、鉴权方式都不同；新接入一律走新版 OAuth2，旧版仅作存量兼容。
- **`code` 与 `authCode` 取其一**：新版回跳两者值相同，解析任一即可，不要当作两个不同的码二次换取。
- **`redirect_uri` 必须登记一致**：与后台「钉钉登录与分享」登记的回调地址完全一致，否则报错；内嵌二维码页面须与 `redirect_uri` 同源。
- **scope 取值**：新版仅支持 `openid` 或 `openid corpid`；旧版扫码用 `snsapi_login`、移动端免登用 `snsapi_auth`。
- **旧版签名细节**：`timestamp` 毫秒、签名串 `timestamp + "\n" + AppSecret`、`signature` 需 URLEncode；时间偏差过大或签名错误会被拒（853002 / 853004）。
- **手机号脱敏**：第三方企业应用拿到的 `mobile` 可能脱敏，需权限与资质方可取真实值。
- **令牌有效期与刷新**：正令牌 7200 秒；用户级 refreshToken 30 天，过期需重新授权；应用级令牌须缓存、避免频繁换取。
- **身份主键选择**：多应用统一用户优先 `unionId`；企业自建通讯录场景可辅以 `userid`，但不要用 `openId` 跨应用关联。
- **state 防 CSRF**：发起授权生成随机 `state` 并落存储，回跳比对、一次性消费；不得用请求参数拼 `redirect_uri`（开放重定向风险）。
