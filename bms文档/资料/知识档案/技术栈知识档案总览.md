## 1. 用途与阅读建议 <a id="purpose"></a>

本档案是本项目技术栈的**知识补给站**：针对平台《项目规划说明》「技术栈」节技术栈中提到的每一项技术，
单独成文介绍「是什么、核心原理、在本项目中的用途、选型对比、常见坑、参考资料」。
每份文档相互独立，可以按需单独阅读，不必从头读到尾。

- 阅读顺序：按需查阅即可；新手建议先按第 11 节学习路径走一遍。
- 每份文档末尾都带「学习与参考资料」节（官网、中文教程、书籍、视频）与「项目内关联文档」节（内部相对路径链接）。
- 涉及部署的组件（Redis/MySQL/PostgreSQL/达梦/MinIO/KiwiTCMS 等）同时链接到《开发服务器部署使用说明总览》等内部文档。
- 本档案定位为理解用参考资料，不替代《项目规划说明》（技术选型决策依据）与设计文档（实现细节依据）。

## 11. 学习路径建议 <a id="path"></a>

技术栈庞大，不必一次学完。按角色与阶段给出建议路线：

| 角色 / 目标 | 建议顺序 | 说明 |
| --- | --- | --- |
| 后端入门（新手） | Python → FastAPI → Pydantic → SQLAlchemy → Alembic → Redis → JWT 与 PBKDF2 → structlog | 先掌握一条「请求进、响应出」的主链路：框架 → 校验 → 数据库 → 缓存 → 认证 → 日志 |
| 后端进阶 | RocketMQ → Celery → python-socketio → SpiffWorkflow → ElasticSearch → OpenTelemetry | 异步化与消息驱动：事件总线、定时任务、实时推送、工作流、检索、链路追踪 |
| 前端入门（新手） | TypeScript → Vue 3 → Vite → Element Plus → Vue Router → Pinia → Axios | 先跑通「页面 → 路由 → 状态 → 请求后端」闭环，再学样式与测试 |
| 前端进阶 | ECharts → gridstack → vuedraggable → vue-flow → bpmn-js → vue-i18n → SCSS → Vitest → Playwright | 可视化与交互：图表、拖拽布局、流程建模、国际化、测试 |
| 工程效率 | uv → ruff → pyright → pytest → Allure | 工具链学习成本低，边用边查即可；Kiwi TCMS 为测试平台需了解工作流 |
| 部署运维 | Docker 与 Compose → nginx → GitLab → Prometheus → Grafana → Loki → Renovate | 先掌握容器化与 CI/CD 主线，再补监控告警体系；etcd 了解即可（Milvus 依赖） |
| 架构与扩展 | 端口适配器 → 接口契约设计 → 自建注册表 → 配置驱动选择 → 生命周期与热插拔 | 理清平台「能力可替换与进程内扩展」主线，再按需深入发现机制与第三方生态 |
| 架构决策（单体 / 微服务） | 微服务 01 总览 → 02 取舍 → 10 项目评估 → 11 常见误区 | 参与「要不要拆微服务」讨论前的必修四篇；想深入再按子篇地图展开 |

## 12. 术语速查表 <a id="terms"></a>

档案中反复出现的高频术语，一表速查：

| 术语 | 一句话解释 |
| --- | --- |
| ORM | 对象关系映射：用类与对象操作数据库表（SQLAlchemy 即 Python 的 ORM） |
| ASGI | Python 异步 Web 服务器网关接口，FastAPI 的部署协议标准（对比 WSGI 为同步旧标准） |
| Pydantic Schema | 用 Pydantic 定义的数据模型：负责请求参数校验与响应序列化 |
| JWT | JSON Web Token：无状态令牌，服务端签名、客户端携带，用于认证 |
| OIDC / OAuth 2.0 | 开放认证协议族：OAuth 2.0 管授权，OIDC 在其上增加身份层，SSO 单点登录的基础 |
| CAS | 中央认证服务：另一种单点登录协议（清华等高校常用） |
| PBKDF2 | 密码哈希算法：加盐多次迭代，抗暴力破解，用于存储密码 |
| Redis | 内存键值数据库：缓存、会话、计数、限流等场景的高速存储 |
| 消息队列 / MQ | 异步传递消息的中间件：生产者发、消费者收，实现模块解耦与削峰 |
| 事件总线 | 以消息队列为底座的事件分发中枢：系统内各处事件统一发布、订阅消费 |
| Broker | 消息队列中承接生产者与消费者的中转组件（RocketMQ 的 broker、Celery 的 Redis） |
| Beat | Celery 的定时调度进程：到点把任务投递给 worker 执行 |
| Worker | Celery 的工作进程：从队列取任务并执行 |
| BPMN 2.0 | 业务流程建模与执行标准：用图形化流程图描述审批等业务流程 |
| Socket.IO | 基于 WebSocket 的实时通信协议，带自动重连与降级机制 |
| S3 协议 | Amazon S3 的对象存储访问协议（HTTP + 签名），MinIO 兼容实现 |
| 预签名 URL | 带时效签名的下载链接，无需登录即可在有效期内直接访问对象 |
| 全文检索 | 对文档内容分词建索引，按关键词快速搜索（ElasticSearch 即此类引擎） |
| 向量库 | 存向量（文本/图片的数学表示）并按相似度检索的数据库（Milvus） |
| Embedding | 把文本/图片转换为向量表示的过程，向量检索的前提 |
| LLM | 大语言模型：如 DeepSeek、Qwen，接受提示词生成文本 |
| OCR | 光学字符识别：从图片/扫描件中识别文字（PaddleOCR） |
| 雪花算法 | 分布式 ID 生成算法：时间戳 + 机器号 + 序列号拼成全局唯一 ID |
| TTL | 存活时间：键（Redis）或记录的有效期限，到期自动删除 |
| 限流（Rate Limit） | 限制单位时间内请求次数，防刷防爆 |
| 链路追踪 | 为每个请求分配 trace_id，串联各服务日志，定位耗时与故障 |
| 可观测性 | 指标（Metrics）+ 日志（Logs）+ 链路（Traces）三件套，监控系统核心 |
| CI / CD | 持续集成（提交即自动测试构建）/ 持续部署（测试通过自动发布） |
| Runner | GitLab CI 中实际执行流水线任务的机器（agent） |
| 镜像 / 容器 | 镜像为打包好的运行环境模板，容器是镜像的运行实例（Docker） |
| 反向代理 | 站在服务端前的代理：转发请求、负载均衡、TLS 终止（nginx） |
| TLS 终止 | 在代理层解密 HTTPS 流量，内部再走明文，减轻后端负担 |
| Prometheus | 时序指标采集与存储系统，配合 exporter 收集各服务指标 |
| Loki | 类 Prometheus 的日志系统：只索引元数据，日志原文压缩存储 |
| 多租户 | 一套系统服务多个租户（客户），数据与配置相互隔离 |
| SaaS | 软件即服务：订阅式云服务交付模式 |
| 信创 | 信息技术应用创新：国产软硬件替代（本项目的达梦 DM8 属信创场景） |
| 单点登录（SSO） | 一次登录，多系统免登：企业微信/钉钉免登即其应用 |
| JIT 建号 | 即时建号：SSO 首次登录时按身份信息自动创建本地账号 |
| 对象存储 | 以「桶 + 对象」存任意文件的存储（MinIO/S3），适合大文件与静态资源 |
| 事件驱动 | 以事件（消息）驱动业务联动：如「表单变更 → 触发索引更新」 |
| 幂等 | 同一操作执行多次结果一致，消息/接口防重的重要性质 |
| 微服务 | 把应用拆成一组可独立部署的小服务、经网络协作的架构风格；用分布式复杂度换独立性 |
| 模块化单体 | 单部署单元 + 强制模块边界（契约 / 数据所有权 / 架构测试），微服务收益的进程内版本 |
| 分布式单体 | 形式是服务、行为仍耦合的反模式：共享库表、同步调用链、必须协调发布 |
| 限界上下文 | 领域模型的适用边界，是业务拆分（而不是技术分层）的语义依据（DDD） |
| Saga | 跨服务业务事务的实现：一串本地事务 + 失败时的补偿动作，替代分布式事务 |
| Outbox | 事务性发件箱：业务写入与事件写入同库同事务，投递器可靠转发，避免双写不一致 |
| 绞杀者（Strangler Fig） | 渐进式现代化模式：外立面按功能逐步把流量从旧系统切到新系统 |
| 康威定律 | 系统架构会长成组织的沟通结构；可逆用（逆康威机动）以组织设计反推架构 |
| 微服务溢价 | 微服务引入的额外成本与风险；只有足够复杂的系统能摊平它 |
| 微前端 | 可独立交付的前端模块组合成更大整体的架构风格；隔离与治理是成败关键 |
| 宿主 / 外壳 | 负责加载、路由与组合微应用的容器，应保持极薄 |
| Module Federation | 打包器层面的运行时模块共享机制（remoteEntry + shared 依赖） |
| 版本偏斜 | 宿主与模块依赖版本不一致导致的运行时异常；需 singleton + 双端声明治理 |
| 分布式单体前端 | 多构建产物但需同步发布、共享可变状态的微前端反模式 |
| 微前端无政府状态 | 各团队任意技术栈与依赖、无共享规范导致体验与治理崩坏的反模式 |
| BFF | 为特定前端定制的后端聚合层，由该前端团队拥有 |
| ESI / SSI | 服务端（边缘）模块拼装机制，服务端组合路线的代表 |
