# 多租户与安全

> **定位**：bms 是多租户平台，消息平台一旦接入产品，就必然承载跨租户流量。本篇讲清「隔离做到哪一层、配额加在哪、身份怎么验、越权怎么防」，是 8B_07 的设计输入。

## 1. 为什么消息平台必须做多租户 <a id="why"></a>

| 风险 | 不做多租户的后果 |
| --- | --- |
| 数据越权 | A 租户的消费者读到 B 租户的消息（最严重） |
| 资源抢占 | 一个大租户打满磁盘 / 带宽，全体不可用 |
| 故障扩散 | 单租户的毒消息拖慢整组消费 |
| 计费 / 计量 | 无法统计各租户用量 |
| 合规 | 无法证明数据隔离 |

## 2. 隔离模型 <a id="isolation"></a>

| 模型 | 做法 | 隔离强度 | 成本 |
| --- | --- | --- | --- |
| **逻辑隔离（共享集群）** | 命名空间 + 标签 + 配额 | 中 | 低 |
| **物理隔离（独享集群 / 独享目录）** | 每租户独立 broker 或独立数据目录 | 高 | 高 |
| **混合** | 普通租户共享，大客户独享 | 可调 | 中 |

**命名空间的三种做法**：

| 做法 | 示例 | 优点 | 缺点 |
| --- | --- | --- | --- |
| topic 前缀 | `t_001.order.created` | 改动小 | 易漏判、易拼错 |
| 独立 namespace 字段 | `(tenant_id, topic)` | 语义清晰、可做权限 | 元数据要支持复合键 |
| 物理目录隔离 | `data/{tenant}/{topic}/` | 故障与配额隔离好 | 文件句柄与运维成本上升 |

**建议**：**逻辑隔离 + 目录按租户分（`data/{tenant}/{topic}`）**。既保留共享集群的低成本，又让「删租户 / 算用量 / 限制磁盘」按目录做。

## 3. 配额模型 <a id="quota"></a>

| 配额 | 粒度 | 超限动作 |
| --- | --- | --- |
| topic 数 | 租户 | 拒绝建 topic |
| 消费组数 | 租户 | 拒绝建组 |
| 生产速率（msg/s 或 B/s） | 租户 / topic | 限流（返回 35005） |
| 存储量 | 租户 | 缩短保留期 / 拒绝写 |
| 未确认消息数 | 消费组 | 暂停投递 |
| 连接数 | 租户 | 拒绝新连接 |

**配额执行点必须前置**：在「接收请求时」判断，而不是「写入后统计」。后者要么已经占用了资源，要么要回滚。

**配额的三个设计要点**：

1. **默认值 + 显式覆盖**：新租户有合理默认，大客户单独配置。
2. **软硬两档**：软限告警、硬限拒绝。
3. **可观测**：每个租户的用量要能看到，否则配额就是黑盒。

## 4. 认证 <a id="authn"></a>

| 方式 | 说明 | 适用 |
| --- | --- | --- |
| **JWT（服务令牌）** | bms 基座签发的服务身份 JWT | 内部服务间 |
| mTLS | 双向证书 | 生产、跨网、强隔离 |
| SASL（PLAIN / SCRAM） | 用户名密码 / 挑战响应 | 兼容开源客户端生态 |
| API Key | 简单共享密钥 | 外部集成（弱） |

**bms 现状**：服务间用 JWT（`[service_token]`），用户令牌用统一校验器。**消息平台应复用这套**，不另造身份体系。

**必须校验的三件事**：

1. **身份真实性**：签名、签发者、有效期。
2. **身份归属**：这个服务属于哪个租户 / 产品。
3. **身份权限**：能对哪些 topic 做哪些操作。

## 5. 授权 <a id="authz"></a>

| 模型 | 粒度 | 说明 |
| --- | --- | --- |
| ACL（主题级） | `(principal, operation, resource)` | 简单、直观 |
| RBAC（角色级） | 角色 → 权限集 → 资源 | 与 bms 权限体系一致 |
| ABAC（属性级） | 按标签 / 租户 / 环境 | 灵活但复杂 |

**建议**：**RBAC 为主 + 资源级 ACL 兜底**。bms 已有权限码体系（`业务码:动作`），消息平台沿用 `msg:query` / `msg:manage`，再按 topic 做细粒度 ACL。

**操作类型**：`publish` / `subscribe` / `describe` / `manage`（建删 topic、改配额、重放）。

**最容易漏的越权点**：

1. 消费者订阅了别的租户的 topic（命名空间校验缺失）。
2. 管理接口只校验「登录」，不校验「租户归属」。
3. 重放接口能操作任意 topic。

## 6. 加密 <a id="crypto"></a>

| 层 | 手段 | 说明 |
| --- | --- | --- |
| 传输 | TLS（h2 over TLS） | 生产必须；内网可先 h2c |
| 静态 | 磁盘加密 / 应用层加密 | 磁盘加密防物理窃取；应用层加密防运维越权 |
| 字段级 | payload 加密 | 敏感字段由业务加密，broker 只存密文 |

**取舍**：

- **TLS 会增加 CPU 与握手开销**，但生产环境没有理由不做。
- **应用层加密会让 broker 无法做内容审计**，也与零拷贝转发冲突（如果只是「原样存密文」，仍可零拷贝）。
- **字段级加密的责任在业务**，平台只保证「密文原样传输与存储」。

## 7. 密钥轮换 <a id="rotation"></a>

| 对象 | 轮换方式 | 注意 |
| --- | --- | --- |
| TLS 证书 | 双证书过渡（新旧并存） | 客户端要能接受新旧 |
| 服务 JWT 密钥 | `active_kid` + 多密钥并存 | 旧密钥保留到所有令牌过期 |
| API Key | 双 Key 过渡 | 给调用方迁移窗口 |

**轮换的铁律**：**先加新、再切用、后删旧**，任何一步都不能跳。直接替换密钥会让所有在途连接与未过期令牌失效。

## 8. 审计 <a id="audit"></a>

必须留痕的操作：

| 类别 | 示例 |
| --- | --- |
| 配置变更 | 建 / 删 topic、改分区数、改保留期、改配额 |
| 数据操作 | 重放、删除消息、清空消费组位点 |
| 权限变更 | 授权 / 回收 ACL |
| 访问异常 | 越权尝试、认证失败 |

审计记录应包含：谁（principal）、何时、对什么（topic / group）、做了什么、结果、来源 IP / trace_id。

**与 bms 审计域的关系**：消息平台的管理操作审计，应写入 bms 的审计链（`audit-chain`），而不是自建一套。这样「谁在消息平台做了什么」与其他平台操作在同一处可查。

## 9. 业界对照 <a id="compare"></a>

| 实现 | 多租户 | 认证 | 授权 |
| --- | --- | --- | --- |
| **Kafka** | 逻辑（topic 前缀 + 配额） | SASL / mTLS | ACL（topic / group 级） |
| **RocketMQ** | 逻辑（namespace） | ACL（AccessKey / SecretKey） | 主题级 |
| **Pulsar** | **原生多租户**（tenant / namespace / topic 三级） | TLS / JWT / Athenz | 租户 / 命名空间 / 主题三级 |
| **NATS** | 逻辑（account 隔离） | NKey / JWT / TLS | account 级 + subject 权限 |

**Pulsar 的三级模型最完整**：`tenant → namespace → topic`，配额与权限都挂在 namespace 上。自研时可以借鉴「租户 + 命名空间 + 主题」三级，而不是只有「租户 + 主题」两级——后者在租户内业务线多时会不够用。

## 10. 对 msg 的设计约束 <a id="msg"></a>

| 决策点 | 建议 | 理由 |
| --- | --- | --- |
| 隔离 | 逻辑隔离 + 目录按租户分 | 成本与隔离的平衡 |
| 命名空间 | `(tenant, namespace, topic)` 三级 | 预留租户内业务线划分 |
| 配额 | 租户级默认 + topic 级覆盖 | 兼顾公平与灵活 |
| 认证 | 复用 bms 服务 JWT；生产加 TLS | 不另造身份体系 |
| 授权 | `msg:query` / `msg:manage` + topic ACL | 与 bms RBAC 对齐 |
| 加密 | 生产 TLS；静态加密按部署环境 | 首期 h2c 仅限内网 |
| 审计 | 管理操作写 bms 审计链 | 统一可查 |
| 租户识别 | 从令牌解析，不接受客户端自报 | 防伪造 |

**最关键的一条**：**租户 ID 必须从令牌解析，不能从请求头自报**。否则任何客户端都能冒充其他租户。

## 11. 失败模式与自检 <a id="failure"></a>

| 失败模式 | 现象 | 防法 |
| --- | --- | --- |
| 租户 ID 由客户端自报 | 可冒充任意租户 | 从令牌解析 |
| 只校验登录不校验归属 | 跨租户越权 | 资源级 ACL |
| 配额事后统计 | 资源已被占用 | 前置判断 |
| 无默认配额 | 新租户无限使用 | 默认值 + 硬限 |
| 密钥直接替换 | 在途连接与令牌全失效 | 双密钥过渡 |
| 重放无权限校验 | 任意 topic 可重放 | manage 权限 + 审计 |
| 管理台无审计 | 无法追责 | 全量留痕 |
