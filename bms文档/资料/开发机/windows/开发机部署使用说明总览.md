## 1. 目的与适用范围 <a id="purpose"></a>

开发机 **mjpc** 为 **Windows 11 与 Ubuntu 双系统同机**（引导机制见《[双系统引导部署使用说明](../双系统引导部署使用说明.md)》）。本文档汇总 **Windows 11 侧**的开发环境部署：每一项设施的详细部署、验证与排障单独成文（见[第 6 节](#docs)），本文只做汇总与导航；**Linux 侧**对照见《[开发机部署使用说明总览（Linux）](../linux/开发机部署使用说明总览.md)》，两台角色划分与协作见[第 5 节](#collab)。

**取值说明**：`<mjpc-IP>` / `<开发服务器-IP>` / `<Git某账户>` 等占位符与真实凭据的具体值见《[本地资源](../../../用户文档/本地资源.md)》与 mjbk 本机 `deploy/.env`，不在仓库文档中记录。开发机是单人开发环境，账号与密码以本机密码管理器为准。

部署依据平台《开发部署规划》；Windows 11 系统安装与双系统布局见《[双系统引导部署使用说明](../双系统引导部署使用说明.md)》。

## 2. 环境概览 <a id="env"></a>

### 2.1 机器与角色 <a id="env-role"></a>

| 机器 | IP | 系统 | 角色 |
| --- | --- | --- | --- |
| mjpc（Windows 侧） | `<mjpc-IP>` | Windows 11 专业版 26H2（Build 26300.9711）；同机另装 Ubuntu 26.04.1 LTS，双系统 | 开发机（本地编码、AI 助手、文档、真机浏览器验证） |
| mjbk | `<开发服务器-IP>` | Ubuntu 24.04.4 LTS（桌面版） | 开发服务器（GitLab、三库、CI 等，常开） |

- Windows 侧与 Linux 侧**各是一套独立开发环境**（各自的仓库克隆、工具链与依赖外置仓），通过 GitLab 远端同步代码；日常在双系统间切换使用，具体以当次工作场景为准。
- 远端服务（GitLab、三库、Redis 等）在开发服务器 mjbk 上，Windows 侧经 HTTP / SSH 访问，不本机部署。

### 2.3 开发目录与依赖外置 <a id="env-dirs"></a>

| 项 | 取值 |
| --- | --- |
| 工作区根 | `D:\Develop\bizs`（以工作区文件 `bizs.code-workspace` 多根打开：工作区配置 / BMS 基座 / 产品） |
| 依赖外置仓 | `D:\dev-deps\bms`——前端 `node_modules` 与后端 `backend\.venv` 均**外置**（原位为 junction），检索零污染；mdm 等其他仓库各自独立解析 |
| 外置维护入口 | `bms/scripts/tools/deps/`（`外置依赖` / `还原依赖` / `重装依赖`；Python 单一实现，Windows `.bat` / Linux `.sh` 为薄包装） |

> 安装依赖（`pnpm install` / `uv sync`）前必须先「还原依赖」，装完再「外置依赖」——安装器见符号链接会误判跳过；一条龙用「重装依赖」。口径详见《[pnpm 部署使用说明](pnpm部署使用说明.md)》与《[uv 部署使用说明](uv部署使用说明.md)》。

## 4. Windows 侧与 Linux 侧的差异 <a id="diff"></a>

| 事项 | Windows 侧 | Linux 侧 |
| --- | --- | --- |
| 终端 / Shell | PowerShell 7 为主；Git Bash 可跑 `.sh` | bash（GNOME 终端） |
| 脚本包装 | `.bat`（双击 / cmd 可用） | `.sh` |
| 依赖外置原位 | junction（`mklink /J`） | 符号链接 |
| IDE 调试配置 | `.vscode/launch.json` 的 `windows` 平台覆盖（Chrome 绝对路径、`.venv\Scripts\python.exe`、`pnpm.cmd`） | 平台默认值（`/usr/bin/google-chrome`、`.venv/bin/python`） |
| 浏览器真机验证 | Chrome for Testing 不装内核，走系统 Chrome（`--browser chrome`） | 同口径 |
| Linux 侧专属设施（Windows 侧未部署、也不需要） | — | 中文输入法、防火墙、Steamcommunity_302、goat-gauge、WorkBuddy 等 |
| 本地跑测性能（杀软 / 文件系统） | 已加 **Defender 实时防护排除项**：BMS 仓 `D:\Develop\bizs\bms`、依赖外置仓 `D:\dev-deps`、Python 安装目录 `%LOCALAPPDATA%\Programs\Python\Python314`（其他克隆 / 产品仓如遇慢可同法加）；即便如此，`check_preflight.py` **完整预检**仍明显慢于 Linux（单线程 pytest + 11 次启动 + 文件元数据开销） | pytest / 依赖安装无杀软扫描开销，预检快 |

> **本地预检口径（Windows 侧）**：日常自检只跑 `python3 scripts/tools/preflight/check_preflight.py --fast`（秒级：CI 配置 / 静态 / 基座与边界）；**完整预检**（含覆盖率硬门禁）按需执行或交 CI 兜底。预检的可选依赖（pyyaml，缺失时「CI 配置自检」段降级跳过）见 `scripts/tools/preflight/requirements.txt`。Windows 侧本机性能差异与提速待立项事项见平台《项目骨架计划》§3.1 后续阶段待办（工具治理待立项）。

## 5. 日常入口与协作 <a id="collab"></a>

- **打开工作区**：VS Code / CodeBuddy 打开 `D:\Develop\bizs\bizs.code-workspace`（多根）；BMS 基座的任务面板（`.vscode/tasks.json`）与调试（`.vscode/launch.json`）已做双平台口径，直接可用。
- **本机裸跑后端全套**：`python3 scripts/tools/dev/本地全套.py up`（tenant / platform / identity 三服务，统一 8000 + loopback 别名）；详见《[CodeBuddy 部署使用说明](CodeBuddy部署使用说明.md)》IDE 任务表与《[开发服务器部署使用说明总览](../../开发服务器/linux/开发服务器部署使用说明总览.md)》对「本地裸跑 vs 容器」的口径。
- **访问远端服务**：GitLab（HTTP，首次拉取弹凭据管理器登录）、三库与 Redis 在 mjbk；Windows 侧不需要 Docker。
- **与 Linux 侧同步**：代码经 GitLab 远端在两侧工作区对齐（`git pull` 即可）；工具链与依赖仓两边各自独立维护。
