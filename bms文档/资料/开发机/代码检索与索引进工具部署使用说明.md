## 1. 目的与适用范围 <a id="purpose"></a>

本文说明 `bms/scripts/tools/search/` 三支脚本的**部署前提、生成流程、日常用法与排障**，对应 AGENTS.md「代码与文档检索（强制口径）」节与 bms 文档根两份索引（《[文档域路由索引](../../文档域路由索引.md)》《[代码落点索引](../../代码落点索引.md)》）。

适用场景：文档或代码目录结构变化后**重新生成索引**；新工作区**从零生成索引**；生成结果异常时**定位排障**。

不适用范围：Zoekt / Sourcegraph 一类外置检索引擎的选型与测评（见《[代码检索与知识库方案评估](../知识档案/工程化与质量/代码检索与知识库方案评估.md)》）——本文只覆盖已落地的脚本工具链。

## 2. 工具链组成 <a id="components"></a>

| 组件 | 路径 | 职责 |
| --- | --- | --- |
| 结构生成器 | `scripts/tools/search/gen-doc-index.py` | 扫文档根，按「阶段 / 子目录」聚合成语义单元，产出骨架 JSON |
| 语义补全 | 同一脚本 `--enrich` | 调本地 LLM 为每个单元生成「主题归类 / 典型问题 / 首查文件」 |
| 渲染器 | `scripts/tools/search/render-doc-index.py` | 骨架 JSON → 《文档域路由索引》Markdown，含一致性校验 |
| 代码索引 | `scripts/tools/search/gen-code-index.py` | 扫前后端源码，从**头部注释**提取职责，产出《代码落点索引》 |

产物落点：

| 产物 | 路径 | 是否入 git |
| --- | --- | --- |
| 文档域路由索引 | `bms文档/文档域路由索引.md` | **入**（语义靠 LLM 补，丢了要重跑模型） |
| 代码落点索引 | `bms文档/代码落点索引.md` | 不入（纯静态扫注释，秒级可重建） |

## 3. 部署前提 <a id="prereq"></a>

**必选**（三支脚本都能不依赖它运行，但两项护栏校验需要）：

- Python 3.11+（脚本用 `X | Y` 联合类型注解与 `re.DOTALL`）；
- `bms_core` 源码根可达：脚本内部自动把 `backend/libs/bms_core/src` 插入 `sys.path`，**无需手动配环境变量**；这是集合声明护栏要求的 `ConcurrentStable*` 导入来源。

**仅语义补全需要**（只产结构骨架可整段跳过）：

- 本地 LLM 服务（OpenAI 兼容接口）监听 `127.0.0.1:8080`，启动方式见桌面项「本地LLM 启动标准版」或《[llamacpp部署使用说明](../AI/llamacpp部署使用说明.md)》；
- 可用环境变量覆盖：`BMS_LLM_URL`（默认 `http://127.0.0.1:8080/v1/chat/completions`）、`BMS_LLM_MODEL`（默认 `qwen`）、`BMS_LLM_TIMEOUT`（默认 180 秒）。

> **注意**：本地模型按 deepseek 推理格式启动时会先输出推理内容，容易挤占 `max_tokens` 导致 JSON 被截断。脚本已在请求里带 `chat_template_kwargs: {"enable_thinking": False}` 关闭思考——若换模型后仍见「输出不完整」，优先查这一项。

## 4. 生成流程 <a id="pipeline"></a>

三步，前两步可合并，第三步必跑：

```bash
cd bms    # bms 仓库根

# ① 扫结构（--no-llm 不调模型；去掉即边扫边补语义）
python3 scripts/tools/search/gen-doc-index.py --workspace .. \
    --no-llm --out /tmp/skeleton.json

# ② 语义补全（本地 LLM 必须已在 8080 监听）
python3 scripts/tools/search/gen-doc-index.py \
    --enrich /tmp/skeleton.json --out /tmp/enriched.json

# ③ 渲染 + 一致性校验（校验不过会以退出码 1 中止，不写文件）
python3 scripts/tools/search/render-doc-index.py /tmp/enriched.json \
    -o bms文档/文档域路由索引.md
```

代码索引一条命令即可（无 LLM 依赖）：

```bash
python3 scripts/tools/search/gen-code-index.py --bms-root . \
    -o bms文档/代码落点索引.md
```

**增量重跑**：`--enrich` 只补「有 `needs_llm` 且无 `semantic`」的单元，已有语义的自动跳过，可安全重复执行；目录结构变化后从第 ① 步重扫。

## 5. 用法与验收口径 <a id="usage"></a>

### 5.1 单元聚合规则

- **项目域**（`项目/`）按**阶段**聚合：`项目/<NN_阶段名>` 是一个单元。单任务的设计 / 实施 / 测试三件套只 1~3 份，逐任务调模型只会浪费；
- 其余域按**一级子目录**聚合（如 `设计/架构设计`、`规范`）；
- 单文件单元（如某份规范自身）不调模型——它自己就是入口。

### 5.2 前端职责提取的三种注释形态

`gen-code-index.py` 认三种，缺一即漏（实测教训）：

| 形态 | 示例 | 说明 |
| --- | --- | --- |
| JSDoc `/** … */` | `frontend/packages/core/src/base/BaseObject.ts` | TS 主流写法 |
| 连续行注释 `// …` | `ui-ep/src/components/ai/AiAssistant.vue` | Vue `<script setup>` 内常用 |
| HTML 注释 `<!-- … -->` | `ui-ep/src/components/display/SsoQrLoginPanel.vue` | 写在 `<template>` 区、`<script>` 之前 |

后端取 Python docstring 首行。当前覆盖率：后端 536 / 536、前端 1211 / 1217（余下 6 个是 vitest 配置与测试文件，无需职责）。

### 5.3 生成后必须跑的三项校验

```bash
python3 scripts/tools/base-check/check-base.py            # 基座完整性
python3 scripts/tools/base-check/check-links.py           # 相对链接自洽
python3 scripts/tools/base-check/check-bare-collections.py .   # 集合声明护栏
```

第三项对 `scripts/tools/` 全境生效：**集合声明必须落 `ConcurrentStableList` / `ConcurrentStableDict`**，且泛型参数里也不能出现裸 `list` / `dict`（护栏递归检查注解）。注意这两个类**不支持** `[]` 赋值、`.append()`、`.setdefault()`、`.extend()`，对应改用 `.set()` / `.add()` / `get()` + 循环。

## 6. 常见问题 <a id="trouble"></a>

### 6.1 在工作区根检索只看到十几个文件 <a id="blind"></a>

**症状**：`rg` / IDE 全局搜索在 `bizs/` 根搜不到 `bms/`、`mdm/`、`biz/`、`test/` 的任何内容。

**成因**：工作区根 `.gitignore` 首行 `/*` 是白名单式忽略，只放行配置文件那几项，四个内容主体全被排除。

**修复**：`rg` 的 `.ignore` 优先级高于 `.gitignore`，用 `!` 反消除即可。该文件已随工作区配置仓提交（`.gitignore` 里须有 `!/.ignore` 白名单，否则它自己被 `/*` 忽略、不会入库）；`scripts/tools/workspace/setup_workspace.py` 的 `ensure_ignore()` 会在搭建工作区时自动落盘，兼容旧工作区与手工删除。

**取证口径**：判定检索范围一律用**不带 `-g`** 的 `rg --files`。`-g` 白名单不经过忽略层，`rg -g 'mdm/frontend/node_modules/**'` 会列出三万多个依赖文件，据此判断「会不会扫到依赖」是错的。

### 6.2 本地模型启动即崩（`clip_model_loader::load_tensors`） <a id="llm-crash"></a>

`qwen-start.sh` 带 `-mm` 挂多模态投影。偶发在显存未释放完时加载失败。**重试一次通常即可**；失败时确认无其他占显存应用（JoyFox / ComfyUI 与 24G 显存互斥，启动脚本会自动停它们，但驱动释放是异步的）。**不需要多模态时可去掉 `-mm` 启动**，纯文本对话不受影响。

### 6.3 语义补全返回「失败，回退为文件名兜底」 <a id="llm-fallback"></a>

脚本对调不通 / 输出不可解析的单元自动降级，不中断整批。逐条查：

1. 模型是否在 `127.0.0.1:8080` 监听（`curl -s 127.0.0.1:8080/v1/models`）；
2. 输出是否被截断（`max_tokens` 不足或未关思考，见第 3 节注意事项）；
3. JSON 外是否裹了 ``` 代码块或杂文本——`extract_json()` 已能剥离，仍失败则看原始响应。

### 6.4 索引里出现断链 <a id="broken-link"></a>

渲染器会先校验再写文件，但那只查**语义一致性**（topic / questions / entry_files 非空）。**链接有效性要靠 `check-links.py`**，重新生成后必跑。跨仓条目按项目分治口径写纯文本路径（`mdm/mdm文档/…`），bms 本仓才写相对链接——写错会让 CI 只 clone bms 时判断链失败。
