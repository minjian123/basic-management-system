## 1. 目的与适用范围 <a id="purpose"></a>

本文档是开发机 **mjpc** 的**总览**：它与开发服务器 mjbk 的职责划分、系统与硬件、已装开发设施（工具链 / AI / 项目）与日常运维入口。每项设施的详细部署与排障单独成文（见[第 6 节](#docs)），本文档只做汇总与导航。它对应《[开发服务器部署使用说明总览](../开发服务器/linux/开发服务器部署使用说明总览.md)》的「机器侧」文档——那份汇总 mjbk 上的**服务部署**，本文汇总 mjpc 上的**开发环境**。

**取值说明**：`<mjpc-IP>` / `<开发服务器-IP>` / `<Git某账户>` 等占位符与真实凭据的具体值见《[本地资源](../../用户文档/本地资源.md)》与 mjbk 本机 `deploy/.env`，不在仓库文档中记录。开发机是单人开发环境，账号与密码以本机密码管理器为准。

部署依据平台《开发部署规划》；系统安装与基础配置见《[Ubuntu安装部署使用说明](../工具/Ubuntu安装部署使用说明.md)》。

> **口径说明**：开发服务器文档的环境概览中曾将 mjpc 记为 Windows 11，实际 mjpc 为 **Ubuntu 26.04.1 LTS**（本机核实 2026-08-29）。以本机为准。

### 2.4 CUDA 工具链 <a id="env-cuda"></a>

开发机上的 CUDA 分三层，**版本各自独立、互不替代**：

| 层面 | 版本 | 位置与来源 |
| --- | --- | --- |
| 编译工具链（`nvcc`，默认） | CUDA 13.4.1（`nvcc` V13.4.59） | `/usr/local/cuda-13.4`，经 `/usr/local/cuda` 访问；NVIDIA 官方源 |
| 编译工具链（备用） | CUDA 12.4.131 | `/usr/bin/nvcc`；Ubuntu 仓库 `nvidia-cuda-toolkit` |
| 跑图运行时 | CUDA 13.0（torch 2.13.0+cu130 自带） | ComfyUI venv 内的 pip 轮子，不依赖系统工具链 |

- **默认 `nvcc` 取 13.4**：`/etc/profile.d/cuda.sh` 把 `/usr/local/cuda/bin` 置于 `PATH` 最前（登录 shell 生效）；要用 12.4 走绝对路径 `/usr/bin/nvcc`。
- **只改 `PATH`，不设 `LD_LIBRARY_PATH`**：避免遮蔽 ComfyUI venv 内 pip 的 CUDA 运行时。
- **`/usr/local/cuda` 由 `update-alternatives` 管理**，指向当前版本目录（现为 `cuda-13.4`）；不要手工 `ln -sf` 覆盖，切换版本用 `sudo update-alternatives --config cuda`。
- **库搜索路径**：包自带 `/etc/ld.so.conf.d/000_cuda.conf`（与 `987_cuda-13.conf`、`gds-13-4.conf`，均归 13.4 的 config-common 包所有），自编译的 CUDA 程序据此加载 `libcudart.so.13`——llama.cpp 已用 13.4 重编，见《[llamacpp部署使用说明](../AI/llamacpp部署使用说明.md)》。
- **已知坑（2026-09-10 实测）**：Ubuntu 仓库的 `cuda-toolkit-13-1`（13.1.115）与 glibc 2.43 冲突，`nvcc` 报 `rsqrt`/`rsqrtf` 异常规格不兼容、任何 `.cu` 都编不过（[Ubuntu LP #2155233](https://bugs.launchpad.net/ubuntu/stonking/+source/cuda-crt-13-1/+bug/2155233)；上游 CUDA 13.2 起已修，Resolute 的修复上传被退回）。**不要装仓库里的 `cuda-toolkit-13-1`**，需要 13.x 就用官方源装 13.4。

官方源安装（`cuda-keyring` 自动登记仓库，国内解析到 `developer.download.nvidia.cn`，实测约 22 MB/s）：

```bash
curl -fsSL -o /tmp/cuda-keyring.deb \
  https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2604/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i /tmp/cuda-keyring.deb && sudo apt-get update
sudo apt-get install -y cuda-toolkit-13-4
```

### 3.1 桌面快捷方式设置（通用） <a id="desktop-shortcuts"></a>

桌面快捷方式（`.desktop` 文件）有两个去向，**效果不同**：

| 目录 | 作用 | 放置要求 |
| --- | --- | --- |
| `~/桌面`（本机 `xdg-user-dir DESKTOP` 的解析值，中文环境为 `/home/minjian/桌面`） | **GNOME 桌面上的图标** | 可执行位 + `trusted` 元数据（见下），否则双击被拦「不受信任」 |
| `~/.local/share/applications/` | GNOME **应用菜单 / Activities** 列表 | 无特殊要求；`desktop-file-validate` 可校验语法 |

> **只放应用菜单目录、桌面上不会出现图标**（2026-09-09 实测踩坑：「更新 dsh与插件」先只放 `~/.local/share/applications/`，桌面无图标，补放 `~/桌面` 后出现）。日常桌面操作项建议**双份都放**（桌面可见 + 菜单可搜）；仅菜单级工具可只放应用菜单目录。

桌面图标正确设置流程：

```bash
# 1) 编写 .desktop：Exec 必须绝对路径；需要终端跑脚本用 Terminal=true，
#    或 Exec=ptyxis -x "bash <脚本>"（Terminal=false，窗口由 ptyxis 显式开）
# 2) 放入桌面文件夹并授权（两步缺一不可）：
cp 某.desktop ~/桌面/
chmod +x ~/桌面/某.desktop
gio set ~/桌面/某.desktop metadata::trusted true
# 3) （可选）应用菜单注册：另存一份到 ~/.local/share/applications/
# 4) 图标统一放 ~/.local/share/icons/（png / svg 均可），Icon= 写绝对路径
```

本机现有桌面项（均 `~/桌面`，部分双份），Exec 形态分两类：

| 桌面项 | Exec 形态 | 双份 |
| --- | --- | --- |
| `ComfyUI 启动/停止` | `Terminal=true` → `~/.local/bin/comfyui-control.sh start/stop` | 有 |
| `JoyFox 启动/停止` | `Terminal=true` → `~/develop/llama.cpp/joyfox-*.sh` | 有 |
| `本地LLM 启动UD/标准版/Uncensored、停止` | `Terminal=true` → `~/.local/bin/qwen-control.sh start [ud\|std\|unc]/stop` | 有 |
| `启动 dsh web` / `停止 dsh web` | `ptyxis -x "bash ~/.local/bin/dsh-web-start.sh"`（Terminal=false） | 仅桌面 |
| `更新 dsh与插件` | `Terminal=true` → `~/develop/bms/scripts/tools/dsh/dsh-update.sh`（2026-09-09 新增） | 有 |
| `唤醒/睡眠/关机 mjbk` | `Terminal=true` → `~/develop/bms/scripts/tools/wol/唤醒mjbk.sh` 等（2026-09-10 新增） | 有 |
| `唤醒/睡眠/关机 mjw` | `Terminal=true` → `~/develop/bms/scripts/tools/winrm/唤醒mjw.sh` 等（2026-09-10 新增；睡眠/关机需 pywinrm venv，缺失时脚本给出安装指引） | 有 |

排错要点：

- 放桌面后不出现：确认文件在 `~/桌面`（不是 `applications`），`ls ~/桌面` 可见即 GNOME 会自动显示；不显示可重新登录一次会话。
- 双击提示「不受信任」：补 `gio set ~/桌面/某.desktop metadata::trusted true`。
- 双击无反应：先在终端手动跑 `Exec` 里的命令，看脚本本身报错（常见：脚本缺执行位、路径写错、依赖 nvm 的脚本在桌面环境需自行加载 `~/.nvm`）。
- 双击无反应但脚本手动执行正常：检查**默认终端注册**——`Terminal=true` 图标由系统默认终端（`x-scheme-handler/terminal`）拉起，未注册则无反应。修复：`xdg-mime default org.gnome.Ptyxis.desktop x-scheme-handler/terminal`（2026-09-10 实测：电源控制 6 图标（唤醒/睡眠/关机 × mjbk/mjw）双击无反应即此因 + trusted 缺失，两项修复后正常）。

## 5. 部署与运维联动 <a id="collab"></a>

开发机与开发服务器 mjbk 的联动入口：

- **凭据**：真实值只写 mjbk 本机 `deploy/.env`（键位见 `deploy/.env.example`），开发机侧通过 SSH 免密登录 mjbk 操作，不复制凭据到文档。
- **服务器电源控制**：远程唤醒/睡眠/关机 mjbk、mjw 的工具链（`wol/` 走 SSH、`winrm/` 走 WinRM）与命令见《[开发服务器电源控制使用说明](../开发服务器/linux/开发服务器电源控制使用说明.md)》与《[开发服务器Windows电源控制使用说明](../开发服务器/windows/开发服务器Windows电源控制使用说明.md)》；mjpc 桌面图标入口「唤醒/睡眠/关机 × mjbk/mjw」见[第 3.1 节](#desktop-shortcuts)（2026-09-10）。
- **后台任务**：长命令用 `scripts/tools/bg/`（bg-run/bg-status/bg-stop）与 `.opencode/plugins/bg.js` 后台化，避免同步阻塞。详见《[通用后台执行器部署使用说明](../工具/通用后台执行器部署使用说明.md)》。
- **远程操作**：SSH 到 mjbk 的方式与模板见《开发服务器部署使用说明总览》相关章节；Windows 服务器 mjw 走 WinRM，见《[开发服务器Windows部署使用说明总览](../开发服务器/windows/开发服务器Windows部署使用说明总览.md)》。
