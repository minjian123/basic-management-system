## 1. 目的与范围 <a id="purpose"></a>

覆盖后端 9 个已启用服务的**公开契约兼容性门禁**——独立契约基线、oasdiff 破坏性变更拦截（「只加不删」）、Schemathesis 接口正确性冒烟（打真实服务、零 Broker）、CI 门禁挂载与契约破坏数推送。语义见平台《架构设计 · 测试与质量》「CI 流水线」节、平台《架构设计 · 接口与集成》「服务间通信与契约」节与《[部署发布规范](../../../规范/部署发布规范.md)》「契约门禁」节；实现侧详细设计见平台任务目录 `项目/02_后端基座与服务化地基/任务/09_多服务CI-CD与契约门禁/09_多服务CI-CD与契约门禁_03_契约门禁/`。

- 契约快照（当前值）由 05_01 交付：`deploy/contracts/<服务>.json` + `backend/ops/contract_snapshot.py`（`export` / `check`）。
- 本门禁新增**独立基线**与比对 / 冒烟 CLI：`backend/ops/contract_gate.py`、`backend/ops/contract_smoke.py`（均仅依赖 Python 标准库 + 共享基座库）。
- 工具走固定 tag 镜像：`tufin/oasdiff:v1.32.1`、`schemathesis/schemathesis:4.28.0`。

## 2. 工具与版本 <a id="tools"></a>

| 工具 | 镜像（固定 tag） | 用途 |
| --- | --- | --- |
| oasdiff | `tufin/oasdiff:v1.32.1` | `breaking` 比对基线 ↔ 当前公开契约，破坏性变更拦截 |
| Schemathesis | `schemathesis/schemathesis:4.28.0` | 依据 OpenAPI 生成用例，打真实服务做接口正确性冒烟 |

- 工具镜像登记 `scripts/tools/docker/镜像清单.txt`，用 `scripts/tools/docker/拉取镜像.sh --host <user@mjbk>` 预拉（断点续传 + 自动重试）。
- CI 门禁 job 运行在 `ci-backend:py314` 基础镜像（已加装 docker CLI 静态二进制），同 job 内既以 uv 起真实服务、又以 `docker run` 调两工具镜像。

## 3. 契约基线与目录 <a id="layout"></a>

```text
deploy/contracts/
├── <service>.json            # 当前公开契约快照（随代码变更重新导出并提交；快照 job 零漂移校验 + 归档）
└── baseline/
    └── <service>.json        # 独立契约基线（入 Git；表示已放行的兼容契约，仅经评审更新）

backend/ops/
├── contract_gate.py          # 基线管理 / oasdiff 门禁 / 破坏数推送
└── contract_smoke.py         # Schemathesis 冒烟（源码起真实服务 + 容器打）

deploy/ci/verify/contract-gate # 契约门禁档开关（删档即关）
```

- 基线集合须与服务目录 `enabled_service_keys()` 一致（guardrail 用例断言：无缺件 / 无多余）。
- 当前值与基线**不混同**：前者每次契约变更都更新，后者只在预期破坏性变更经评审合入时更新。

## 4. oasdiff 破坏性变更门禁 <a id="gate"></a>

```bash
cd backend
# 比对基线 ↔ 实时公开契约（逐启用服务）；破坏性变更即非零退出并输出中文清单
uv run python -m ops.contract_gate check
# 同时写出破坏数指标文本（CI after_script 推送用）
uv run python -m ops.contract_gate check --metrics-out /tmp/contract-metrics.txt
# 预期破坏性变更时刷新基线（人工；之后提交并走评审合入）
uv run python -m ops.contract_gate baseline-update --service platform
uv run python -m ops.contract_gate baseline-update --all
```

- 比对对象为**实时公开契约**（`contract_snapshot.build_openapi` 内存构建后确定性渲染），不依赖已提交快照，故任意提交都可复现。
- oasdiff 调用（**不用 bind mount**）：`docker create tufin/oasdiff:v1.32.1 breaking /base.json /cur.json --fail-on ERR --format json` → `docker cp <基线> <容器>:/base.json`、`docker cp <当前> <容器>:/cur.json` → `docker start -a <容器>`（回传退出码）→ `docker rm -f <容器>`。原因：门禁 job 运行在容器内，其路径（`$CI_PROJECT_DIR` / `/tmp`）在宿主 daemon 上不可见，`docker run -v <job 路径>` 会挂到空目录（实测 oasdiff 返回码 102 `no such file or directory`；2026-09-24 首推流水线发现并修复）。
- 输出为英文 JSON；CLI 包一层中文提示：`服务 X：检测到 N 项破坏性变更（基线 → 当前公开契约）` + 明细 + 更新指引。
- **只加不删**：删字段 / 删端点 / 改类型 / 收紧必填等判破坏性并阻断；新增可选字段 / 端点放行。确需破坏时按「版本演进」升大版本（`/api/v2` 并行一个发布周期）并更新基线。
- **基线更新走评审**：`baseline-update` 仅本地人工执行，门禁 job 只读比对、不写基线（无自动覆盖路径）。

## 5. Schemathesis 契约冒烟 <a id="smoke"></a>

```bash
cd backend
# 单服务：用已构建镜像起容器 → 就绪 → Schemathesis 容器打 → 停容器
uv run python -m ops.contract_smoke run --service platform --image "$REGISTRY_IMAGE_PREFIX/bms-platform:$CI_COMMIT_SHORT_SHA"
uv run python -m ops.contract_smoke run --service platform --image bms-platform:local --max-examples 1
```

- **被测服务来源**：**已构建服务镜像**（子流水线 `service-build` 产物 `bms-{service}:$CI_COMMIT_SHORT_SHA`，固定 tag ⇒ 可固定重现）——`docker run -d -e BMS_ENV=dev <镜像>` 起容器；不由 CLI 源码起进程、不重复构建。
- **调度范围**：**按服务、仅本次变更的服务**——父流水线 9 个 `contract-smoke-<服务>` job 各以 `rules:changes: backend/services/<服务>/**/*` 放行，未变更服务不跑。
- **网络与 schema**：Schemathesis 容器以 `--network container:<服务容器>` 与服务容器共享网络命名空间，经 `127.0.0.1:8000` 打真实服务；就绪轮询 `docker inspect -f '{{.State.Health.Status}}'`（镜像 `HEALTHCHECK` `/healthz`）至 `healthy`；schema 经 `docker cp` 复制进容器 `/tmp/<服务>.json`（**不用 `-v` 挂 job 路径**——宿主不可见）。
- **口径**：只读方法（`--include-method GET` / `HEAD`）+ 每操作 1 例（`--max-examples 1`）+ 仅 `not_a_server_error`（无 5xx 即通过）+ `--suppress-health-check all` + 排除基础设施端点（`--exclude-path /healthz` `/readyz` `/metrics`；无依赖时 503 属预期）；非 2xx（4xx / 401 / 403 / 404）视为可达通过；零 Broker（无需 Pact 平台）。**阻断**（2026-09-24 06_04 起，原 `allow_failure: true` 已移除）——dev 环境请求侧 5xx 根因（租户解析把 IP 字面量主机名当子域名、兜底把请求值当租户编码 → 派生非法库名 `bms_platform_127.0.0.1`）已修复，platform 零 5xx 由真实流水线实证（修复前 7 处 5xx → 修复后 exit 0）。

## 6. CI 门禁 <a id="ci"></a>

- 档位 `deploy/ci/verify/contract-gate`（删档即关）；父流水线 verify 阶段：

| job | 作用 | 关键 | 
| --- | --- | --- |
| `contract-gate` | oasdiff 破坏性变更门禁 + 破坏数推送（**阻断**） | `needs: swagger-snapshot`；`check --metrics-out`；`after_script` 推 `bms_contract_breaking_total{service}`；规则 `changes: backend/**` / `deploy/**` |
| `contract-smoke-<服务>`（9 个） | Schemathesis 用已构建镜像打真实服务（**阻断**） | `needs: trigger-<服务>`；规则 `changes: backend/services/<服务>/**/*`（**仅变更服务**）；命令 `contract_smoke run --service <服务> --image bms-<服务>:$CI_COMMIT_SHORT_SHA` |

- 触发：main 直推（+ MR 预留）；tag 流水线不进契约门禁。
- 破坏数推送：`POST $PUSHGATEWAY_URL/metrics/job/bms-ci`（文本格式、末尾换行；未配置地址则跳过、失败不阻断门禁结论）。

## 8. 验证 <a id="verify"></a>

```bash
# oasdiff：基线 ↔ 当前（兼容应 exit 0；人为删端点应 exit 1 并列出变更）
# 容器内（CI / job）用 create + cp + start（不依赖宿主路径挂载；适用门禁 job 在容器内运行）
docker create --name bms-cg tufin/oasdiff:v1.32.1 breaking --fail-on ERR --format json /base.json /cur.json
docker cp "$PWD/deploy/contracts/baseline/platform.json" bms-cg:/base.json
docker cp "$PWD/deploy/contracts/platform.json" bms-cg:/cur.json
docker start -a bms-cg; echo "exit=$?"; docker rm -f bms-cg
# 宿主直接执行（非 job 容器）时可用 bind mount：
# docker run --rm -v "$PWD/deploy/contracts/baseline:/base:ro" -v "$PWD/deploy/contracts:/cur:ro" \
#   tufin/oasdiff:v1.32.1 breaking --fail-on ERR --format json /base/platform.json /cur/platform.json

# Schemathesis 打真实服务（推荐直接用 CLI；下方为等价手工步骤）
# 1) 起已构建服务镜像容器并等 healthy
docker run -d --name bms-smoke-platform -e BMS_ENV=dev "$REGISTRY_IMAGE_PREFIX/bms-platform:local"
# 2) Schemathesis 容器 --network container:服务容器 + schema 经 docker cp
docker create --name bms-sch --network container:bms-smoke-platform schemathesis/schemathesis:4.28.0 \
  run /tmp/platform.json --url http://127.0.0.1:8000 --max-examples 1 --checks not_a_server_error \
  --suppress-health-check all --include-method GET --include-method HEAD \
  --exclude-path /healthz --exclude-path /readyz --exclude-path /metrics
docker cp "$PWD/deploy/contracts/platform.json" bms-sch:/tmp/platform.json
docker start -a bms-sch; echo "exit=$?"; docker rm -f bms-sch bms-smoke-platform

# 破坏数通道（样例推送后可查 Prometheus）
curl -s 'localhost:9090/api/v1/query?query=bms_contract_breaking_total' | python3 -m json.tool
```

## 9. 排障 <a id="troubleshooting"></a>

| 现象 | 排查 |
| --- | --- |
| oasdiff 报镜像缺失 | 未预拉：`scripts/tools/docker/拉取镜像.sh`（见 §7）；CLI 会提示镜像名与清单路径 |
| oasdiff 返回码 102（`no such file or directory`） | 门禁 job 在容器内、用 `docker run -v <job 路径>` 时挂载源在宿主不可见（挂到空目录）；CLI 已改用 `create + cp + start`（见 §4 / §8），若手工复现请勿用 bind mount job 路径 |
| 破坏性变更误报（确为预期） | 更新基线并走评审：`contract_gate baseline-update --service <服务>` 后提交；确需破坏应升大版本 |
| `contract_gate check` 报基线缺件 / 多余件 | 基线集合与服务目录不一致：补齐 / 删除 `deploy/contracts/baseline/<服务>.json` 后重跑 |
| Schemathesis `Unmatched filters: --include-method HEAD` | 该服务无 HEAD 操作（警告非错误，不影响结论）；可忽略 |
| Schemathesis 大量 404 / 401 | 只读占位端点未实现认证 / 无对应资源；非 2xx 视为可达通过，不影响门禁 |
| 服务容器起不来 / 不就绪（`docker run` 失败或 `inspect` 非 healthy） | 该服务 job 失败并清理容器；确认本服务镜像已构建（`bms-<服务>:$CI_COMMIT_SHORT_SHA`）与 `BMS_ENV=dev` 可起 |
| 冒烟报 5xx 且响应为 `库名形态非法：bms_<服务>_<主机名>` | 租户解析把请求 Host 当租户来源（06_04 修复前行为）：IP 字面量 / `localhost` 与形态非法的来源值现均按「未命中」处理，不再派生库名；若复现，检查是否绕过了 `db/tenant.py` 的形态校验 |
| Schemathesis `The specified file does not exist` | schema 经 `-v` 挂 job 路径在宿主不可见；CLI 已改 `docker cp` 复制 schema 进容器 `/tmp`（见 §5 / §8），手工复现请勿用 bind mount job 路径 |
| 破坏数面板空 | 破坏数由 main 契约门禁 job 推送；查 `up{job="pushgateway"}` 与推送日志（推送失败不阻断门禁） |

## 10. 实测结论（mjbk，2026-09-24） <a id="measured"></a>

| 项 | 结果 |
| --- | --- |
| 镜像预拉 | `tufin/oasdiff:v1.32.1`、`schemathesis/schemathesis:4.28.0` 拉取成功 |
| oasdiff 兼容比对 | 基线 ↔ 当前 platform 契约：`[]`，exit 0 |
| oasdiff 拦截 | 人为删除 `GET /api/v1/modules/snapshot`：输出 `api-path-removed-without-deprecation`（`level:3`），exit 1 |
| Schemathesis 打真实服务 | 对**已构建平台镜像起容器**（`docker run -d -e BMS_ENV=dev`）+ Schemathesis 容器 `--network container:<服务容器>` 打：通过，exit 0（按服务、仅变更服务运行；固定 tag 可重现） |
| Schemathesis 命令口径 | `--max-examples` / `--checks not_a_server_error` / `--include-method GET,HEAD` / `--suppress-health-check all` 实测有效（v4.28.0 `--help` 核对） |
| dev 环境 5xx 根因与修复（06_04） | 按 CI 同口径在开发机复现（`BMS_ENV=dev` + 本机 SQLite + `uvx schemathesis==4.28.0` 打真实服务）：修复前 **7 failures**（19 个 GET 操作选中，全部为 `库名形态非法：bms_platform_127.0.0.1`）；定位到租户解析把 IP 主机名当子域名 + 兜底把请求值当租户编码；修复后 **462 passed / exit 0**（同命令、同契约） |
