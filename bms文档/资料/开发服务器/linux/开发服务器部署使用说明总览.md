### 2.1 已就绪项 <a id="env-ready"></a>

- 系统：Ubuntu 24.04.4 LTS，静态 IP `<mjbk-IP>/24`，时区 Asia/Shanghai，主机名 `mjbk`
- 远程通道：SSH（22），mjpc 公钥免密登录
- apt 镜像源：清华 TUNA（已验证）
- 数据盘：1TB HDD 挂载 `/mnt/data`（ext4，fstab 自动挂载）；2T NVMe SSD 挂载 `/mnt/ssd2t`（ext4，fstab 自动挂载，Fanxiang S770）
- Docker 运行数据：data-root 在 `/mnt/ssd2t/docker`（容器 / 命名卷 / 构建缓存），**镜像层在 containerd 存储 `/mnt/ssd2t/containerd`**（本机 Docker 用 containerd 镜像存储，2026-10-17 由系统盘 `/var/lib/containerd` 迁出）；GitLab 数据在 `/mnt/ssd2t/gitlab`；容器日志按 100 MB × 3 轮转（详见《[Docker部署使用说明](Docker部署使用说明.md)》「大镜像拉取与断点续传」「日志轮转、镜像存储位置与空间清理」节）

- 笔记本特性：合盖不休眠（logind + GNOME 两层配置）
- 显卡：Intel UHD Graphics 630（核显）+ NVIDIA GeForce GTX 1060 Mobile（独显），PRIME `on-demand`；驱动与独显功耗见《[显卡驱动部署使用说明](显卡驱动部署使用说明.md)》

### 2.3 磁盘与健康巡检 <a id="env-disk-health"></a>

健康巡检工具随系统包安装（apt 源为清华 TUNA）：

| 工具                     | 版本            | 覆盖范围                                          |
| ------------------------ | --------------- | ------------------------------------------------- |
| `nvme-cli`（`nvme` 命令） | 2.8-1ubuntu0.1  | NVMe 盘枚举、SMART 健康日志（`smart-log`）、错误日志 |
| `smartmontools`（`smartctl`） | 7.4-2build1 | 机械盘 SMART 属性与自评；也可读 NVMe（与 `nvme-cli` 互为佐证） |

常用巡检命令：

```bash
df -hT -x tmpfs -x devtmpfs -x squashfs -x overlay   # 容量与使用率（排除 snap 回环与虚拟文件系统）
lsblk -o NAME,SIZE,FSTYPE,TYPE,MOUNTPOINT,MODEL      # 设备与挂载拓扑
sudo nvme list                                        # NVMe 盘与命名空间占用
sudo nvme smart-log /dev/nvme0                        # SSD 健康日志：温度 / 备用块 / 磨损 / 介质错误
sudo smartctl -H -A /dev/sda                          # 机械盘自评结果与属性表
```

巡检基线（2026-10-17 实测；同日完成存储整理，容量为整理后）：

| 盘          | 设备节点       | 型号                       | 挂载                | 容量 / 已用               | 健康结论                                                        |
| ----------- | -------------- | -------------------------- | ------------------- | ------------------------- | --------------------------------------------------------------- |
| 系统盘      | `/dev/nvme1n1` | SAMSUNG MZVKW512HMJP-00000 | `/`、`/boot/efi`    | 468 GB / 36 GB（8%）      | 通过；介质错误 0，磨损 1%，37 °C                                |
| 数据盘 SSD  | `/dev/nvme0n1` | Fanxiang S770 2TB          | `/mnt/ssd2t`        | 1.8 TB / 53 GB（4%）      | 通过；介质错误 0，磨损 1%，38 °C                                |
| 数据盘 HDD  | `/dev/sda`     | TOSHIBA MQ04ABF100         | `/mnt/data`         | 916 GB / 315 GB（37%）    | 通过；重映射 / 待定扇区 0，通电 21767 h，35 °C                  |

- 三盘均无告警、无坏道，容量充裕，无扩容或换盘需求。
- **2026-10-17 存储整理**（清前系统盘 143 GB / 33%）：GitLab 容器日志 32 GB → 0（未轮转，已 truncate 并加 daemon 日志轮转）；containerd 镜像存储 105 GB 由系统盘迁至 `/mnt/ssd2t/containerd`；Docker 镜像 60.9 GB → 30.5 GB、构建缓存 38.4 GB → 11.8 GB、未挂载卷 26.2 GB → 4.0 GB。清理口径与命令见《[Docker部署使用说明](Docker部署使用说明.md)》「日志轮转、镜像存储位置与空间清理」节（**勿用 `docker system prune -a`**，会丢断点续传缓存）。
- 系统盘 `nvme error-log` 历史条目偏多（链路 / 超时类记录），介质错误为 0、备用块 100%，不属盘体劣化；机械盘已通电约 2.5 年，纳入定期巡检关注。
- `smartd.service` 随 `smartmontools` 安装启用（默认 `DEVICESCAN`，待机盘跳过），后台会持续采集并尝试邮件告警；本机未配 MTA，告警邮件实际到不了人，**结论仍以人工巡检为准**。

## 5. 配置与凭据管理 <a id="config"></a>

- 真实凭据只写 `deploy/.env`（mjbk 本机，`.env.example` 入仓库）；密钥类配置只走环境变量，不入文档。
- **部署机为仓库完整检出**（`/home/minjian/bms`，`/home/minjian/deploy` 为指向其 `deploy/` 的软链，2026-10-17 起）：配置同步走 `git -C /home/minjian/bms pull`，不在服务器手工改配置（详见《[服务编排与发布部署使用说明](服务编排与发布部署使用说明.md)》「目录与配置」节）。
- 机器登录凭据见《[本地资源](../../../用户文档/本地资源.md)》；各服务账号密码在部署时生成，记录于 mjbk 本机密码管理器，不写入本文档与仓库。
- 服务名、环境变量、数据库命名遵循《[命名规范](../../../规范/命名规范.md)》。

## 7. 备份与恢复 <a id="backup"></a>

- **系统层**：Timeshift 每日快照（保留 5 份），装坏环境用安装 U 盘 `sudo timeshift --restore` 还原。
- **数据层**：脚本 `~/deploy/backup/backup_daily.sh` 由 **systemd 用户级 timer（每日 12:00，`Persistent=true`，错过则开机补跑）**触发，统一产出 MySQL / PostgreSQL / 达梦 / GitLab / Kiwi 附件备份并本地保留 7 天，
  详见《[数据备份与恢复部署使用说明](数据备份与恢复部署使用说明.md)》（含恢复演练与已定位的待办）。
- **异地层**：数据层当日产物经 gpg 加密上传百度网盘 `/apps/bms-backup/`，详见《[百度网盘云备份部署使用说明](百度网盘云备份部署使用说明.md)》。
