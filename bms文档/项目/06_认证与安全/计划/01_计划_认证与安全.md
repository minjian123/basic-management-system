## 5. M6 验收门禁 <a id="accept"></a>

门禁定义见《[总体项目规划](../../../规划/总体项目规划.md)》「阶段内容与完成标准」节（阶段六行）与「里程碑」节；**逐项结论与证据索引见下表（10 行）**，阶段汇总见《[阶段测试报告](../01_测试报告_认证与安全.md)》。判定口径：本阶段门禁判「**机制与产物就位 + 真实链路实证**」，真实业务链路 / 部署形态留后续阶段的项在结论后以「（限定：… → 计划 §7 第 N 项）」注明归口；**10 行全部达标，无未达标项**（2026-10-03 收口）。 **收口后补遗（2026-10-04）**：补充需求 11-1 追加 `11_01`（40h）、补充需求 05-6 追加 `05_06`（20h），均属 M6 基线**外**增量，上表 10 行结论不受影响；两项的门禁结论随任务完成单独核对并回写本节。

**补遗门禁结论 —— `11_01`（2026-10-04 完成）**：多租户用户的 `my_tenants` 能列出其可访问租户且 `multi_tenant=true`；`switch` 仅对可访问租户生效、越权目标被拒（`80003` / 403）；六条写入路径以「统一建号入口 + `source`」承接（本期接线 SSO JIT，其余登记接入点）；登录前链路无任何账号反查（关系数据源不入免认证面）；契约快照与 `@bms/api-types` 零漂移；新增 / 变更模块行覆盖率 100%；后端定向 `pytest`、`ruff`、`pyright` 与 `preflight --fast` 全通过。**（限定：对账巡检定时化 → 阶段八；未实现写入路径功能本体 → 各功能立项时按统一建号入口接入；Kiwi 用例编号待平台登记回填；三库真库迁移随部署窗口）**

**补遗门禁结论 —— `05_06`（2026-10-04 完成，补遗收尾）**：单租户 / 子域名部署下登录页**不渲染**租户标识、留空提交即可直接登录（唯一启用租户解析）；多租户同域留空提交返回认证段 **`20007`**（HTTP 200、`data=null`）且**不消费验证码、不计失败**，前端展开租户标识输入框并聚焦、填写后提交成功；本机已记住租户编码时**静默随请求携带且不显示该项**；登录前链路**无任何**按账号查询租户 / 账号存在性的请求（安全规范 §3）；`20007` 响应体不含租户清单；免登录公开面经 `[tenant].deferred_paths` 延迟解析（生产无来源不硬拒、`20007` 可达）；SSO 入口按唯一启用租户回落；契约四道门禁全绿（identity 端点说明含 `20007`、tenant 含内部 `active-single` 且生成类型零漂移）；新增 / 变更代码路径覆盖率 100%；前端 `vue-tsc` / ESLint / Vitest 与后端定向 `pytest` / `ruff` / `pyright` / `preflight --fast` 全通过。**（限定：验证码场景策略在租户未解析时的租户级读取细化 → 后续评估；`deferred_paths` 长期治理为口径提醒；Kiwi 用例 2239 / 2240 已登记）**
