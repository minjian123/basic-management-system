## 1. 设计目标与范围 <a id="goal"></a>

把《[测试规范](../../../../../../规范/测试规范.md)》要求的**七类安全专项**与**核心模块（认证）行覆盖率 ≥80%** 从「文档已写、部分能力已交付」落为**可执行的门禁与证据**：新增集中安全专项套件覆盖七类（越权 / 注入 / XSS / 上传绕过 / 限流爆破 / 脱敏泄露 / 会话安全），新增**路径级覆盖率门禁脚本**把「认证模块 ≥80%」表达为按路径子阈值，并将覆盖率快照与执行结果归档供域七阶段测试报告引用。

- **本任务范围**：
  1. **安全专项套件**：新增后端集中套件（基座横切 + 认证链路两处）+ 前端 `v-html` 护栏，覆盖七类；以「补缺口 + 专项断言」为主，复用既有替身与夹具，不重复既有用例。
  2. **路径级覆盖率门禁**：新增 `scripts/tools/base-check/check-coverage-threshold.py`（读 `coverage.json`，按声明的路径集合逐项校验子阈值；含 `--self-test`）。
  3. **CI 挂接**：`backend-test` job 追加 `--cov-report=json:coverage.json`、门禁脚本步骤与 `coverage.json` artifact；失败沿用既有 `defect-capture` 自动缺陷单机制（不改）。
  4. **本地接线**：`preflight` 的 `--self-test` 恒跑、真实阈值校验在非 `--fast`（有覆盖率数据）执行。
  5. **证据归档**：覆盖率快照（`coverage.json` artifact）与专项执行结果登记实施 / 测试记录，供域七引用。
- **不在本任务**：
  - **后端 HTML 净化基座**（`BaseRichText` 类能力）与**上传安全控制**（魔数 / 类型白名单 / 大小上限 / 随机存储名）——当前无实现且属未立项能力，**归后续安全强化**（见 §7）。
  - **跨用户越权归属校验**（会话 `list/get/kick` 的 actor 归属判定）——属域一 `01_04` 行为面，RBAC 就绪前为平台超管口径，**归阶段七 RBAC**（见 §3.5）。
  - `data:plain` 真实权限判定（域七）、导出大文件审计（阶段八）等既有遗留（业已在计划 §7 归口）。
- **不改动**：`backend-test` / 服务子流水线的既有 `--cov-fail-under=70` 语义（整体门槛保持 70%，新增的是**路径子阈值**）；七类既有用例的编码与编号；`require_permission` 当前 Null 实现。
- **安全影响（SDL）**：本任务决定「七类专项是否真有用例、认证模块覆盖率是否存在可执行门槛、覆盖数据是否可复查」。专项验收点：七类均有用例且执行通过；认证模块（identity 整包 + `bms_core` 认证横切）行覆盖率 ≥80% 且门禁在 CI 生效；门槛接入的流水线证据可查。

| # | 缺口 | 事实 | 后果 |
| --- | --- | --- | --- |
| 1 | 七类无**集中入口** | 六类后端断言散落于 `ratelimit` / `session` / `security` / `api` / `masking` / `transfer` / `identity/tests/auth` 各处；`v-html` 无专项护栏 | 无法「按专项集」定点执行与取证，域七引用成本高 |

| 4 | 会话**过期 / 伪造**缺端到端 | JWT 层有伪造 / 过期单测；会话记录 `expires_at<=now` 分支缺路由级用例 | 会话安全覆盖不完整 |

| 6 | **注入边界**缺用例 | 登录契约层空 / 超长入参无专门用例；SQL 注入样本仅 2 处基座骨架 | 认证注入覆盖不完整 |
| 7 | **认证覆盖率门禁缺失** | 全仓只有整体 / 服务级 70%；`.gitlab-ci.yml` 注释占位「认证 ≥80% 随阶段接入」 | 需求「认证 ≥80% 并在 CI 生效」无落地 |
| 8 | **覆盖率快照无归档** | 仓库内无 `coverage.json` / 报告归档（仅本地 `.coverage`，被 gitignore） | 域七无证据可引用 |

**消费方**：CI 流水线（`backend-test`）、本地预检（`preflight`）、域七阶段验收（覆盖率与专项证据）、后续模块（RBAC / 工作流）复用同一路径级门禁脚本。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 安全专项套件的组织与落点 <a id="suite"></a>

七类专项按**被测物归属**分三处承载，统一命名与覆盖矩阵，构成「可独立运行的安全专项集」：

| 位置 | 类别 | 理由 |
| --- | --- | --- |
| `libs/bms_core/tests/security/test_security_controls.py` | 脱敏泄露（响应 / 日志 / 导出）、注入（契约层边界）、上传绕过（存储路径穿越）、限流（窗口与键作用域） | 被测基座均在 `bms_core`，跨服务不可互相导入，横切能力就近集中 |
| `services/identity/tests/auth/test_auth_security_special.py` | 限流爆破（IP 与账号双维度 + 强制验证码）、会话劫持（伪造 / 过期记录 / 踢出后重放）、越权（跨租户请求 / 跨用户口径）、注入（登录契约边界 + 注入样本） | 被测物为认证链路编排（`LoginService` / `SessionService` / 会话路由），须服务侧应用夹具 |
| `frontend/packages/ui-ep/tests/guard-vhtml-sanitize.spec.ts` | XSS | 前端 `sanitizeHtml` 为唯一净化落点，护栏属前端组件库 |

> **落点校准（2026-10-03 实施）**：认证链路套件落 `tests/auth/` 而非另起 `tests/security/`——用例需复用本包 `helpers` / `session_helpers` 的替身与夹具，而 `tests/` 无 `__init__.py`（避免十个服务的 `tests` 包同名冲突），跨包相对导入不可用。套件仍为独立文件、与既有用例并列，覆盖矩阵与编号口径不变。

**口径**：
- 套件以**补缺口 + 专项断言**为主，**复用既有替身与夹具**（`FakeUserTokenIssuer` / `FakeOrgClient` / `FakeCaptcha` / `MemorySessionStore` / `MemoryRateLimiter` / `wire_auth` / `seed_session` 等），不复制既有用例、不新增被测能力。
- 套件文件 basename **全库唯一**（`test_security_controls.py` / `test_auth_security_special.py`），符合「测试目录 basename 唯一」既有口径。
- 用例统一以 `@pytest.mark.kiwi_id(<编号>)` 标注（单一编号，见 §5）；前端护栏以 `// kiwi_id: <编号>` 标注。

### 3.2 路径级覆盖率门禁脚本 <a id="gate-script"></a>

**脚本**：`scripts/tools/base-check/check-coverage-threshold.py`（口径同 `check-env-example.py`：纯函数 + CLI + `--self-test`；退出码 0 通过 / 1 不达标 / 2 数据缺失）。

**数据源**：coverage.py JSON 报告（`pytest --cov-report=json:<path>`），结构 `{"files": {"<相对路径>": {"summary": {"covered_lines", "num_statements"}}}}`；文件键按 `backend/` 工作目录为基准（如 `services/identity/src/bms_identity/api/auth.py`），脚本以**后缀匹配**归一，兼容相对 / 绝对路径。

**路径组与阈值**（脚本模块级常量，配置化，后续模块可追加）：

| 组名 | 路径集合（后缀匹配） | 阈值 |
| --- | --- | --- |
| 认证（identity 服务） | `services/identity/src/bms_identity/` | ≥80% |
| 认证（bms_core 横切） | `libs/bms_core/src/bms_core/api/base.py`、`session/`、`security/`、`captcha/`、`ratelimit/`、`permission/`、`masking/`、`idp/`、`oauth/` | ≥80% |

- **组覆盖率口径**：`sum(covered_lines) / sum(num_statements) × 100`（行覆盖率，与《[测试规范](../../../../../../规范/测试规范.md)》§6「行覆盖率」一致）。
- **文件键约定**：以 `backend/` 为基准的相对路径（`--cov` 在 `backend/` 目录执行时 coverage 记录该形态）；脚本对键做归一（去 `./` 前缀、统一 `/`），再按后缀匹配。

**CLI**：
```text
python3 scripts/tools/base-check/check-coverage-threshold.py [bms 仓库根] [--coverage-json <path>]
python3 scripts/tools/base-check/check-coverage-threshold.py --self-test
```
- 默认 `--coverage-json = <root>/backend/coverage.json`。
- **纯函数** `check_coverage_thresholds(files, groups) -> tuple[str, ...]`（入参为解析后的文件摘要与组声明，返回问题清单），供 `--self-test` 与主流程共用。

**输出**：逐组打印 `组名：实际 xx.x%（阈值 80%）通过 / 未达标`；末尾给总结论。

**`--self-test`（表驱动，覆盖正常 + 反例）**：
| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 两组均达标 | 0 问题 |
| 2 | 认证组低于阈值 | 命中未达标 |
| 3 | 某组**无匹配文件**（键口径漂移 / 报告缺文件） | 命中「无匹配文件」（防静默通过） |
| 4 | `num_statements = 0` 的组 | 命中（防除零静默通过） |
| 5 | 仅 identity 达标、`bms_core` 横切缺失 | 命中 |

### 3.3 CI 接线（`backend-test`） <a id="ci"></a>

在既有 `backend-test` job 内**复用同一次全量 pytest**，零额外测试耗时：

```yaml
  script:
    - cd backend
    - uv sync --frozen
    - uv run pytest --cov=bms_core ... --cov-branch --cov-report=term \
        --cov-report=json:coverage.json --cov-fail-under=70
    # 路径级子阈值：认证模块（identity 整包 + bms_core 认证横切）行覆盖率 ≥80%（04_04）
    - uv run python ../scripts/tools/base-check/check-coverage-threshold.py ..
  artifacts:
    when: always
    paths: [backend/coverage.json]
    expire_in: 30 days
```

- 保留既有 `--cov-fail-under=70`（整体门槛不变）；新增的是**路径子阈值**（脚本）。
- `artifacts` 以 `when: always` 归档覆盖率快照，供域七阶段测试报告引用（证据留痕）。
- 失败自动缺陷单：沿用既有 `defect-capture`（`.post` stage，`on_failure`）机制，**不新增**逻辑。

### 3.4 本地预检接线（`preflight`） <a id="preflight"></a>

- `--self-test` **恒跑**（`--fast` 与非 `--fast` 均执行），验证门禁脚本自身正确。
- 真实阈值校验：非 `--fast` 时，在聚合全量 pytest 之后（该步追加 `--cov-report=json:coverage.json`）执行脚本；`--fast` 时若磁盘已存在 `backend/coverage.json`（上一次全量遗留）则同样执行，否则跳过并提示。
- **不改变** `--fast` 的「跳过 pytest」语义（避免拖慢日常推送前预检）。

### 3.5 七类专项覆盖矩阵 <a id="matrix"></a>

| # | 类别 | 既有覆盖（复用） | 本任务新增（补缺口） |
| --- | --- | --- | --- |
| 1 | 限流爆破 | 账号维度限流（2194/2218）、连续失败锁定、强制验证码与清零（2208）、基座契约（Kiwi 43） | 登录 **IP 维度**限流（键租户位 = 雪花 id）、IP + 账号双维度与强制验证码的**组合断言**、限流**窗口过期**边界（基座） |
| 2 | 脱敏泄露 | 序列化掩码（嵌套 / 列表 / fail-closed，2225）、日志脱敏（2225 / 63）、掩码策略（2212）、`mask_rows` 函数级 | **导出链路**（`mask_rows` 消费断言：声明列掩码 / 未声明列不掩 / 空集短路）、响应序列化与日志在**同一用例内**的「无敏感明文」综合断言；**日志内置敏感键名补 PII**（`phone` / `mobile` / `email` / `id_card` / `idcard` / `bank_card`，不含 `name`）并断言 |
| 3 | 会话劫持 | 伪造 / 篡改 / 过期（JWT 层）、踢出后 refresh 401（2194 / 2195）、会话标记缺失 20012（2196）、黑名单 / TTL（2194） | 会话记录 `expires_at<=now` **路由级** 401、伪造 refresh 串拒绝、**踢出后旧 refresh 重放** 端到端 |
| 4 | 越权 | 跨租户中间件 / 依赖 / 契约（1019 / 2196）、OIDC userinfo 跨租户、SSO 租户不匹配 | 跨租户**显式请求头与令牌不一致**（认证链路端到端）、**跨用户口径固化**（RBAC 前平台超管：同租户凭会话 id 可查看 / 踢出他人会话 → 断言现状；归属校验登记阶段七遗留） |
| 5 | 注入 | `str_strip_whitespace`（Kiwi 13）、租户过滤条件与配置口令注入样本、验证码 `kind` 非法 10001 | 契约层**边界**（空 / 超长入参 → 10001，非 5xx；基座 + 登录契约）、注入样本按字面透传（参数化在数据访问层）→ 20002 |
| 6 | XSS | `sanitizeHtml` 白名单清洗（970）、Markdown 渲染清洗、单一落点护栏（禁组件直引 DOMPurify） | **`v-html` 净化护栏**：组件内出现 `v-html` 必须局部 `eslint-disable vue/no-v-html` 留痕、`eslint` 未全局关闭该规则、fixture 反例被拦 |
| 7 | 上传绕过 | 存储 `_resolve` 路径穿越（661）、分片契约校验（845）、前端类型 / 大小校验（965 / 770） | 基座**非法 key**（空 / 绝对路径 / `..`）集中断言 + 合法键原子读写（原子写闭环）；契约层类型 / 大小 / 摘要格式边界复用既有 845 |

**须登记遗留（未立项能力，归后续安全强化）**：
- 后端 HTML 净化基座（后端无富文本净化实现，XSS 后端面缺被测物）。
- 上传安全控制真实实现（魔数 / 类型白名单 / 大小上限 / 随机存储名；当前仅在契约与存储层做路径穿越与格式校验）。
- 跨用户越权归属校验（阶段七 RBAC）。

### 3.6 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| `coverage.json` 缺失 / 非 JSON | 门禁脚本退出码 2（`--no-cov` / 未跑测试时为预期，提示后由调用方处置） |
| 某路径组**无匹配文件** | 判失败（退出码 1）——防「键口径漂移导致静默通过」 |
| 某路径组 `num_statements = 0` | 判失败（防除零静默通过） |
| 某路径组实际覆盖率低于阈值 | 退出码 1，输出未达标组与实测值 |
| 全部组达标 | 退出码 0 |
| 登录 IP 维度限流命中 | 429 / 10005（与账号维度同码） |
| 会话过期 / 伪造 / 踢出后重放 | 401 / 20001（认证链路统一处理面） |
| 契约层入参非法（空 / 纯空白 / 超长） | 10001（HTTP 200 统一响应体，框架校验归一），**不得** 5xx |
| 注入样本作为 account | 20002（认证失败，参数化不穿透），**不得** 500 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **既有测试**：本任务**只新增**用例文件，不改既有用例断言（既有编号不加注）；既有七类用例经「复用」引用并在测试记录登记覆盖矩阵。
- **CI**：`backend-test` 增一个 `--cov-report` 选项（不影响覆盖率统计口径）、一个门禁步骤与一个 artifact；`--cov-fail-under=70` 与各 job 语义不变。服务子流水线（`backend-service.yml`）**不改**。
- **preflight**：新增两个步骤（`--self-test` 恒跑 + 非 fast 真实校验）；`--fast` 的耗时语义基本不变（`--self-test` 为毫秒级）。
- **门禁脚本**：新增独立脚本，不接入 `base-integrity` job（避免在无覆盖率数据的 job 中失败）；仅接入 `backend-test` 与 preflight。
- **前端**：仅新增一条 spec（护栏），不改 `sanitizeHtml` 实现与组件；`ui-ep` 既有用例不受影响。
- **后续复用**：RBAC / 工作流等模块落地时，只需在门禁脚本的路径组常量追加条目即可接入子阈值（长期成本低）。

## 7. 边界与开放项 <a id="boundary"></a>

- **后端 HTML 净化基座**（`BaseRichText` 类）→ **后续安全强化**（后端无富文本净化实现，XSS 后端面当前无被测物；前端 `sanitizeHtml` 为唯一净化落点，已覆盖）。
- **上传安全控制真实实现**（魔数 / 类型白名单 / 大小上限 / 随机存储名）→ **后续安全强化**（当前 `bms_file` 路由与存储基座只做路径穿越与格式校验；文件管理上层未立项）。
- **跨用户越权归属校验**（会话 `list/get/kick` 的 actor 归属判定）→ **阶段七 RBAC**（当前 `require_permission` 为 Null 恒定通过，平台超管口径）。
- **服务子流水线的身份服务 80% 门槛**：本任务不改服务模板（服务级统一 70%）；认证 ≥80% 由父流水线路径级门禁统一承接（避免模板按服务分支）。如需服务级 80%，后续单独评估。
- **覆盖率门禁的路径组维护**：新增模块（RBAC / 工作流）接入时，在脚本路径组常量追加条目；`--self-test` 需同步补用例。
- **`--fast` 下的真实阈值校验**：仅当磁盘已有 `coverage.json` 时执行（见 §3.4）；日常快速预检以 `--self-test` 为兜底。
- **Kiwi 用例编号** → 实施时登记回填。
