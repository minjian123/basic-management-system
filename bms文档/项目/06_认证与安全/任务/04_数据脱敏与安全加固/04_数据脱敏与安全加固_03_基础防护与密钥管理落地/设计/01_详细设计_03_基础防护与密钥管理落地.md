## 1. 设计目标与范围 <a id="goal"></a>

把《[安全开发规范](../../../../../../规范/安全开发规范.md)》要求的**基础防护与密钥基线**从「文档已写 / 部署件部分就位」落为**可复查的证据与门禁**：安全响应头补齐 CSP 与按环境差异的 HSTS、生产关闭 Swagger / ReDoc / OpenAPI、密钥键位同步与无硬编码核验、依赖漏洞高危阻断与 SBOM 挂点确认。

- **本任务范围**：
  1. **安全响应头**：`deploy/gateway/nginx.conf` 模板化，补 `Content-Security-Policy`，新增按环境注入的 `Strict-Transport-Security`（dev 不发送）；compose 变量与挂载同步；资料部署说明回写。
  2. **文档端点**：`[app]` 增 `docs_enabled` 环境分层键（基线 `true`、生产 `false`），应用工厂据此关闭 `/docs`、`/redoc`、`/openapi.json`。
  3. **密钥管理**：核验 JWT / 服务令牌密钥只走环境变量与 Secret（不入库 / 不入镜像 / 不落日志）；修复 `backend/.env.example` 陈旧 `[security]` 段；新增轻量静态门禁（两份 `.env.example` 键位一致性）挂 preflight 与 CI `base-integrity`。
  4. **CI 安全扫描**：新增依赖漏洞高危阻断 job（Trivy `fs`，覆盖 `uv.lock` / `pnpm-lock.yaml`）；确认官方 Dependency-Scanning 报告口径；在服务镜像发布 job 增 SBOM 挂点（Trivy CycloneDX artifact）。
  5. **证据留痕**：核验命令与结果登记实施记录（可复查）。
- **不在本任务**：
  - **`secret:` 密钥加密存取**（`sys_identity_provider.config` 密钥类加密值入库 + 解密供出站）与**加密字段 `reveal` 解密路径**——原挂本任务，经 2026-10-02 拍板**改归后续安全强化 / 另立子任务**（本任务不做；口径见 §7 与阶段计划「后续阶段待办」）。理由：需求 04-3 范围为「核验 + 补齐基线」，且当前无可加密的存储字段，单独实现会引入未定义的数据契约与密钥管理方案。
  - 前端静态产物接入 CSP 的按需放宽（归部署阶段，随前端构建产物接入一并核验）。
  - SBOM 的上报 / 签名 / 随交付分发策略（挂点本期就位，完整落地归部署阶段）。
  - Nginx TLS 终止 / 证书（生产随部署阶段）。
- **不改动**：`[security]` / `[service_token]` 的密钥结构与 01_01 定稿口径；`BaseMasker` 契约（04_01 / 04_02 已定稿）；网关 APISIX 声明式配置（安全响应头统一在 nginx 边缘层）。
- **安全影响（SDL）**：本任务决定「边缘响应头是否完整、生产是否暴露接口文档、密钥是否可能落库 / 落盘、依赖高危是否阻断」。专项验收点：响应头按环境差异正确（dev 关 HSTS）；生产三文档端点关闭；密钥来源检查通过（无硬编码 / 无入库）；`.env.example` 键位与实现一致；核验证据归档。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 安全响应头（nginx 模板化 + 环境差异） <a id="headers"></a>

**配置落点**：`deploy/gateway/nginx.conf` 改名为 `deploy/gateway/nginx.conf.template`，挂载为容器内 `/etc/nginx/templates/default.conf.template`（nginx 官方镜像入口脚本 `20-envsubst-on-templates.sh` 渲染输出到 `/etc/nginx/conf.d/default.conf`，覆盖镜像自带默认站点）。

**响应头口径**（`server` 级，均带 `always`）：

| 头 | 取值 | 环境差异 |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | 恒发 |
| `X-Frame-Options` | `SAMEORIGIN`（兼容同源 Grafana 嵌入） | 恒发 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 恒发 |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=()` | 恒发 |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'self'; base-uri 'self'; object-src 'none'` | 恒发（基线严格档；前端产物接入时按需放宽，归部署阶段） |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | **仅生产**（模板由环境变量注入指令行；dev 不发送） |

**环境差异机制**（envsubst）：

```nginx
    add_header Content-Security-Policy "default-src 'self'; ...; object-src 'none'" always;
    ${GATEWAY_HSTS_HEADER}
```

- `GATEWAY_HSTS_HEADER`：整行 `add_header Strict-Transport-Security "..." always;` 或空串；**dev 留空**（不注入），**prod 注入完整指令**。
  - 决策确认时表述为「由 `GATEWAY_ENV` 控制是否注入 HSTS」；实施取**更稳妥的整行变量**口径——envsubst 无法做条件分支，而「空值 `add_header` 是否被 nginx 省略」在版本间语义不稳，故以「整行指令是否存在」表达环境差异，语义等价、无版本依赖。
- 用 `NGINX_ENVSUBST_FILTER=^GATEWAY_` 限定仅替换 `GATEWAY_*` 变量，避免误触模板内的 nginx 变量（`$host` / `$http_upgrade` 等）。
- `GATEWAY_HSTS_HEADER` 必须**始终有定义**（compose 以 `${GATEWAY_HSTS_HEADER:-}` 提供空默认），否则 envsubst 不替换、nginx 配置报错。

**编排契约**（`deploy/compose/gateway.yml` 的 `gateway-nginx`）：

```yaml
    environment:
      TZ: Asia/Shanghai
      NGINX_ENVSUBST_FILTER: "^GATEWAY_"
      GATEWAY_HSTS_HEADER: ${GATEWAY_HSTS_HEADER:-}
    volumes:
      - ../gateway/nginx.conf.template:/etc/nginx/templates/default.conf.template:ro
      - ../gateway/static:/usr/share/nginx/html:ro
```

`.env.example` 增键位：

```bash
# 安全响应头 HSTS（dev 留空不发送；生产 TLS 就绪后填入整行指令）：
# GATEWAY_HSTS_HEADER=add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
GATEWAY_HSTS_HEADER=
```

### 3.2 文档端点环境开关 <a id="docs"></a>

**配置契约**（`AppSettings` 新增，纳入既有 `[app]` 分区与 `BMS_APP__` 覆盖）：

| 配置键（`config.toml`） | 环境变量 | 口径 |
| --- | --- | --- |
| `[app].docs_enabled` | `BMS_APP__DOCS_ENABLED` | 布尔；基线 `true`（dev / test 开），`config.prod.toml` 置 `false` |

**应用工厂**（`application.py`）：

```python
docs_enabled = settings.app.docs_enabled
app = FastAPI(
    title=self.service_title,
    version=self.contract_version,
    lifespan=service_lifespan,
    dependencies=[Depends(get_masker)],
    docs_url="/docs" if docs_enabled else None,
    redoc_url="/redoc" if docs_enabled else None,
    openapi_url="/openapi.json" if docs_enabled else None,
)
```

- 关闭范围：`/docs`（Swagger）、`/redoc`（ReDoc）、`/openapi.json`（OpenAPI）**三端点全关**；契约唯一来源为 CI 快照 `deploy/contracts/`（`swagger-snapshot` job 产出）。
- `app.openapi()` **方法不受影响**：`openapi_url=None` 仅不注册路由，`ops.contract_snapshot` 直接调用 `app.openapi()` 仍可取契约（CI 以 test / dev 环境运行，不依赖端点）。
- 豁免路径清单（`[edge].exempt_paths` / `[tenant].exempt_paths` / 日志排除路径）中的 `/docs` / `/redoc` / `/openapi.json` 保留不动：这些是**路径豁免登记**（无需鉴权 / 不记日志），端点关闭后路径自然 404，豁免无副作用。

### 3.4 CI 依赖漏洞高危阻断 <a id="depscan"></a>

**保留**：官方 `Security/Dependency-Scanning.gitlab-ci.yml` 模板（`pnpm-lock` 等生态报告 + 安全面板展示）。

**新增**（`.gitlab-ci.yml`，stage `test`）：

```yaml
# 依赖漏洞高危阻断（04_03；《安全开发规范》「高危漏洞阻断合入」）
dependency-scan:
  stage: test
  image: docker:27-cli
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
      changes:
        paths: [backend/uv.lock, backend/pyproject.toml, pnpm-lock.yaml, frontend/**/package.json, deploy/**/*, .gitlab-ci.yml]
    - if: $CI_COMMIT_BRANCH
      changes:
        compare_to: 'refs/heads/main'
        paths: [ ...同上... ]
  script:
    - docker run --rm -v "$CI_PROJECT_DIR:/src:ro" -v trivy-cache:/root/.cache/trivy -e TRIVY_DB_REPOSITORY=ghcr.nju.edu.cn/aquasecurity/trivy-db:2 aquasec/trivy:0.74.0 fs --scanners vuln --severity CRITICAL,HIGH --exit-code 1 --skip-dirs .git --skip-dirs node_modules /src
```

- 固定 tag `aquasec/trivy:0.74.0`（与镜像扫描同源、已预拉）；漏洞库走国内镜像 + `trivy-cache` 持久卷（口径同 service-release）。
- 覆盖 `backend/uv.lock`（补官方 gemnasium 的 Python 缺口）与 `pnpm-lock.yaml`；`CRITICAL` / `HIGH` 即 job 失败（阻断）。
- 与《[测试规范](../../../../../../规范/测试规范.md)》《安全开发规范》「依赖与供应链」节一致；阈值 / 忽略策略后续按误报情况调整。

```yaml
    - docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v "$CI_PROJECT_DIR:/out" -v trivy-cache-$SERVICE:/root/.cache/trivy -e TRIVY_DB_REPOSITORY=ghcr.nju.edu.cn/aquasecurity/trivy-db:2 aquasec/trivy:0.74.0 image --format cyclonedx --output "/out/sbom-$SERVICE.cyclonedx.json" "$IMAGE"
```

- artifact 追加 `sbom-*.cyclonedx.json`（`release-manifest.json` 的 `checklist` 保持「人工确认」占位口径不变）。
- 与镜像扫描共用**按服务隔离**的 `trivy-cache-$SERVICE` 卷与同一镜像（2026-10-03 起按服务隔离，避免跨服务缓存 / 漏洞库锁竞争）；`--exit-code` 不设（SBOM 生成不阻断，阻断由前一步扫描承担）。

### 3.6 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| `GATEWAY_HSTS_HEADER` 未定义（非 compose 直挂静态 conf） | 模板渲染残留 `${...}` → nginx 启动报错（fail-fast，不静默降级）；compose 默认空串规避 |
| `GATEWAY_HSTS_HEADER` 为空（dev） | 模板对应行空行；不发送 HSTS，其余响应头正常 |
| `[app].docs_enabled = false` | 三文档端点不注册 → 请求返回 404；`app.openapi()` 仍可用 |
| `[app].docs_enabled` 非布尔 | 配置模型校验拒启（不静默降级） |
| `.env.example` 残留废弃键 / 缺键 / 真实 PEM | 门禁脚本退出码 1（preflight 与 `base-integrity` 均失败） |
| Trivy fs 发现高危 | `dependency-scan` job 失败（阻断）；无高危则通过 |
| Trivy 镜像 / 漏洞库不可达 | job 失败（重验证层口径，需人工处置；与 service-release 一致） |
| SBOM 生成失败 | 发布 job 失败（与镜像扫描同 job，不合规不发布）；完整策略归部署阶段 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **文档端点**：基线 `docs_enabled = true` → dev / test / 单测行为零变化；仅 `config.prod.toml` 关闭。既有依赖 `/openapi.json` 的**端点调用**不存在（CI 契约经 `app.openapi()` 生成，非 HTTP）。

## 7. 边界与开放项 <a id="boundary"></a>

- **`secret:` 密钥加密存取**（`sys_identity_provider.config` 密钥类加密值入库 + 解密供出站）→ **改归后续安全强化 / 另立子任务**（原挂本任务；2026-10-02 拍板调整）。落地前 IdP 配置仅支持 `env:变量名` 引用，`secret:` 写入即拒。
- **加密字段 `reveal` 解密路径与密钥来源** → **改归后续安全强化 / 另立子任务**（当前无可加密的存储字段，单独实现会引入未定义数据契约）。04_01 / 04_02 设计中「→ 04_03」的边界指向随本条调整。
- **CSP 按前端产物放宽**（`script-src` / `connect-src` / 第三方域）→ 部署阶段随前端构建产物接入一并核验。
- **生产 TLS / 证书 / HSTS 真机验证** → 部署阶段（当前 dev 无 TLS，HSTS 按 dev 关闭核验）。
- **SBOM 上报 / 签名 / 随交付分发** → 部署阶段（本期仅挂点与 artifact）。
- **依赖扫描阈值与忽略策略**（高危误报处置、例外登记）→ 后续按实际告警调整。
- **`config.toml` 的 `[app].docs_enabled` 默认值** → 基线 `true`；如后续需 test 环境也关，按需在 `config.test.toml` 覆盖。
- **Kiwi 用例编号** → 实施时登记回填。
