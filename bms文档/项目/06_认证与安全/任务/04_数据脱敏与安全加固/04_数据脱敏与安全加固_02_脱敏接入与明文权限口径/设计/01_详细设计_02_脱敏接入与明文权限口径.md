## 1. 设计目标与范围 <a id="goal"></a>

把已交付的脱敏基座（[04_01](../../04_数据脱敏与安全加固_01_脱敏基座真实实现/04_数据脱敏与安全加固_01_脱敏基座真实实现.md) 的 `DefaultMasker`）真正接到**响应序列化、日志、导出**三条出路上，并把 `data:plain` 明文口径的过渡期行为固定为「**无权限码一律掩码**」：调用方不需要逐个接口手工掩码，敏感字段声明一次即自动生效。

- **本任务范围**：`BaseSchema` 敏感字段声明的「映射 + 集合兼容」与递归掩码；掩码器 `mask` / `reveal` 的策略入参扩展；掩码器全局注入；日志脱敏配置化（追加型键名与后缀名单）；文本掩码辅助 `mask_text`；导出脱敏公共工具；`mask_phone` 回接共享纯函数；`ai_chat_log` 与 identity 侧的消费方口径登记。
- **不在本任务**：`data:plain` 真实权限判定（阶段七 RBAC，本任务只保证占位检查器下 **fail-closed**）；加密字段的真实解密与密钥（[04_03](../../04_数据脱敏与安全加固_03_基础防护与密钥管理落地/04_数据脱敏与安全加固_03_基础防护与密钥管理落地.md)）；`ai_chat_log` 真实落库与导出审计真实实现（阶段八）。
- **不改动**：`BaseMasker` 的掩码规则口径（04_01 已定稿：7 策略 / 固定星数 / 长度退化 / 未知策略兜底 `custom`）；`BaseExporter` 契约（导出脱敏仍在传入 `rows` 前完成）；`CaptchaChallenge.target` 契约与调用面。
- **安全影响（SDL）**：本任务决定「敏感数据出接口是否真被掩码」的成败。专项验收点：带标记字段的响应**全部掩码**（含嵌套 / 列表）；日志与导出**无敏感明文**；**无权限码时 `data:plain` 静默不生效**（占位检查器下恒掩码）；掩码为纯函数（无 IO、不落日志、不缓存原值）；日志配置**只可追加**（防误关内置名单）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 敏感字段声明与序列化掩码 <a id="schema"></a>

**声明形态**（`BaseSchema` 类属性，默认保留空集——既有声明与既有断言零改动）：

```python
MaskedFields = Mapping[str, str] | Set[str]   # 字段 → 策略 ｜ 字段名集合（兼容写法）

class BaseSchema(BaseModel, BaseDataContract):
    masked_fields: ClassVar[MaskedFields] = ConcurrentStableSet()
```

**归一化**（模块级纯函数，测试可直接调用）：把两种写法统一为「字段 → 策略」映射。

| 声明写法 | 归一化规则 | 示例 |
| --- | --- | --- |
| `{"mobile": "phone", "mail": "email"}`（映射） | 原样使用（键 = 字段名，值 = 策略名） | `mobile` 按 `phone` 策略 |
| `{"phone", "email"}` / 任意 `Set[str]`（集合） | 逐字段取**字段名同名内置策略**；不在 `MASK_STRATEGIES` 内则 `custom` 全掩码 | `phone` → `phone` 策略；`email` → `email` 策略 |

**递归掩码**（`_apply_masking(masked, data, masker)`，在 `model_serializer(mode="wrap")` 内调用）：

| 数据形态 | 处理 |
| --- | --- |
| `Mapping` | 遍历键：值若为 `Mapping` / 非字符串序列则**递归**（内部键各自按声明表匹配）；否则若是声明字段 → `masker.mask(key, value, strategy=声明策略)`，未声明 → 原样 |
| 非字符串序列（`list` / 元组 / 基座集合类） | 逐元素按**同一字段上下文**继续递归（声明为敏感字段的列表逐元素掩码） |
| 字符串 / 其他标量 | 声明字段 → 掩码；未声明 → 原样 |
| 深度达上限（`_MAX_MASK_DEPTH = 5`，与日志脱敏同口径） | 原样返回（防深层 / 循环结构） |

- **容器类型保持**：重建时保持原容器类型（基座集合类仍是集合类实例），不降级为内置容器。
- **与子模型 serializer 的关系**：嵌套的 `BaseSchema` 子模型在自己的 `model_serializer` 内已按自身声明掩码；父层递归对「已掩码的字符串」再次掩码**幂等**（各策略对掩码串再掩码结果不变，见 §5 用例），故重复处理无副作用，且能兜住「声明的字段值是裸 `dict` / `list`」的情形。
- **未注入掩码器**（`current_masker is None`）/ 无声明 / 序列化结果非字典——原样返回，既有行为完全一致。

### 3.2 掩码器契约扩展 <a id="masker"></a>

`BaseMasker`（与 `NullMasker`、`DefaultMasker` 同步签名）：

| 方法 | 签名（本任务） | 语义 |
| --- | --- | --- |
| `mask` | `mask(field: str, value: object, strategy: str \| None = None) -> object` | 未声明且未注册字段 / `None` → 原样；持 `data:plain` → 原值；否则按解析出的策略返回掩码串 |
| `reveal` | `reveal(field: str, value: object, strategy: str \| None = None) -> object` | 与 `mask` 对称（本期无加密字段，[04_03](../../04_数据脱敏与安全加固_03_基础防护与密钥管理落地/04_数据脱敏与安全加固_03_基础防护与密钥管理落地.md) 扩展解密） |

**策略解析链**（`DefaultMasker._resolve_strategy(field, declared)`，`declared` 即 Schema 传参）：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | `[masking].options.rules` / 显式 `register` | 运维应急覆盖与业务显式注册（`self._rules` 命中即用其策略） |
| 2 | Schema 声明（`strategy` 传参） | `BaseSchema.masked_fields` 归一化后的策略名 |
| 3 | 字段名同名内置策略 | 字段名 ∈ `MASK_STRATEGIES` 时按其自身策略（含 `email` 特例） |
| 4 | 未命中 | **原样返回**（未声明即非敏感，保持 04_01 既有语义，`mask("unregistered", v)` 仍原样） |

- **行为变化（登记）**：`mask("phone", v)` 在「未注册、未声明」时由「原样」变为「按 `phone` 内置策略掩码」。全库该形态的调用面仅 `BaseSchema` 序列化层（届时必传声明）与单测；`unregistered` 类字段名仍原样。
- **未知策略名**：仍兜底 `custom` 全掩码（不抛错，序列化期抛错会中断响应）。
- **`data:plain`**：判定单点仍在 `DefaultMasker.check_plain()`（注入占位检查器一律 `False`）；阶段七换真实 RBAC 检查器后自动按权限码放行，脱敏侧零改动。

### 3.3 掩码器全域注入 <a id="inject"></a>

- 落点：`BaseServiceApplicationFactory.create()` 创建 `FastAPI` 时传 `dependencies=[Depends(get_masker)]`——**一处生效、全部服务全部路由统一**，请求期 `current_masker` 就位、请求结束复位（沿用 `get_masker` 异步生成器依赖的既有语义）。
- `services/org/api/org.py` 路由级已挂同一依赖 → FastAPI 依赖缓存去重，不重复解析、无副作用；既有路由声明保持不动（留有显式可读性）。
- 未匹配到路由的请求（404）不解析全局依赖，不影响任何响应体（无序列化）。
- 每请求多一次插件解析（`resolve_plugin("masking", …)`），开销为注册表查表级；仅对**声明了敏感字段**的响应产生实质掩码行为，其余响应逐字节不变。

### 3.4 日志脱敏配置化 <a id="log"></a>

配置契约（`[log]` 新增两键，扁平风格与现有 `level` / `format` 一致）：

```toml
[log]
level = "INFO"
format = "json"
slow_request_ms = 1000
# 追加型敏感键名 / 后缀名单（内置名单恒生效，配置只可追加不可移除）
redact_keys = []
redact_suffixes = []
```

| 项 | 口径 |
| --- | --- |
| 生效名单 | **内置名单 ∪ 配置追加**（`_SENSITIVE_KEYS` / `_SENSITIVE_SUFFIXES` 恒生效；配置只能加） |
| 键名匹配 | 忽略大小写，全等于键名或命中后缀（既有规则不变） |
| 值形态 | 敏感键值**整体替换 `***`**（决策 3，不暴露片段）；连接串密码替换规则不变 |
| 嵌套 | 限深递归（`_MAX_REDACT_DEPTH` 不变）；起效点仍是处理器链内的 `_redact_sensitive` |
| 装配 | `configure_logging` 构建处理器链时按 `settings.log` 组装「内置 ∪ 配置」名单并闭包进处理器（不引入全局可变状态） |
| 配置形态 | `LogSettings.redact_keys` / `redact_suffixes` 用基座契约集合（`Annotated[ConcurrentStableList[str], CONTRACT_COLLECTION]`，缺省空） |

- 非法配置（非字符串列表）由配置模型既有校验拒启，不静默降级。
- `config.dev.toml` / `config.test.toml` / `config.prod.toml` 按需追加，基线 `config.toml` 给出空数组占位。

### 3.5 文本掩码辅助 <a id="text"></a>

落点 `masking/text.py`（新增，纯函数模块，无 IO、可并发）：

```python
def apply_builtin_strategy(strategy: str, text: str, mask_char: str = DEFAULT_MASK_CHAR) -> str
def mask_text(text: str, strategy: str = "custom", *, mask_char: str = DEFAULT_MASK_CHAR) -> str
```

- `apply_builtin_strategy`：`email` 特例 → `mask_email`；否则查 `BUILTIN_MASK_SPECS`，未知策略兜底 `custom`（与 `DefaultMasker` 一致）；`DefaultMasker._apply` 改为「先查自定义策略表、未命中再委托本函数」，**内置口径单一来源**。
- `mask_text`：面向「一段文本值」的掩码入口（`mask_text(text, "phone")`），供 `ai_chat_log` 等消费方在落库前对敏感文本掩码；**不做值探测 / 正则识别**（显式给出策略），与 04_01「显式注册驱动」口径一致。
- **不使用**：需要自定义策略或 `data:plain` 判定时仍走 `BaseMasker.mask`（纯函数不含权限与自定义策略表）。

### 3.6 导出脱敏公共工具 <a id="export"></a>

落点 `transfer/masking.py`（新增）：

```python
def mask_rows(
    rows: ConcurrentStableList[ConcurrentStableDict[str, object]],
    fields: Mapping[str, str],
    masker: BaseMasker,
) -> ConcurrentStableList[ConcurrentStableDict[str, object]]
```

- 逐行逐列：列名命中 `fields` → `masker.mask(列名, 值, strategy=fields[列名])`；未命中 → 原样。
- `BaseExporter` 契约不变（导出脱敏在传入 `rows` 前完成）；工具由调用方（导出接口 / 业务导出件）在调用 `export` 前消费。
- 掩码器经**参数传入**（不静态依赖插件解析），便于测试与调用方复用当前请求的实例。
- **导出大文件审计占位**：真实审计基座归阶段八，本任务只登记消费方口径（阶段计划「后续阶段待办」）。

### 3.7 既有场景回接 <a id="rewire"></a>

| 场景 | 口径 |
| --- | --- |
| 短信手机号回显（03_03） | `captcha/base.py::mask_phone` 签名与调用面不变，内部改为委托 `mask_edges(text, BUILTIN_MASK_SPECS["phone"])`——前 3 后 4 与长度退化口径**逐字节一致**（含 `""` / 短号边界） |
| 组织用户回显（`OrgUser`） | **保留集合写法** `{"phone", "email"}`（验证兼容路径）；经「字段名同名内置策略」自动取 `phone` / `email` 策略；配合 §3.3 全局注入后输出掩码 |
| SSO / 会话接口用户标识 | identity 对外 Schema 当前**无** phone / email 输出字段；本任务只登记「一旦输出即声明 `masked_fields`」口径（真实取数与输出随对应阶段） |

### 3.8 `data:plain` 明文口径（过渡期） <a id="plain"></a>

- **判定**：经 `BasePermissionChecker` 的 `data:plain` 权限码，单点在 `DefaultMasker.check_plain()`（`PLAIN_PERMISSION = "data:plain"` 已常量化）。
- **过渡期行为**：注入的检查器是占位实现（`NullPermissionChecker`，恒定允许）→ 一律视为不持权限码 → **掩码**（fail-closed）；阶段七换真实 RBAC 检查器后自动按权限码放行。
- **消费方登记**：阶段七 RBAC（阶段计划「后续阶段待办」已登记该依赖）；前端既有 `data:plain` 权限码常量与后端同名，无需改动。

### 3.9 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 未声明且未注册字段 / `value is None` | 原样返回（不把 `None` 变掩码串） |
| 声明字段为 `None` | 原样返回（`None` 不参与掩码） |
| 声明字段值为空串 | 按策略掩码为掩码串（`phone` → `****`，与 `mask_phone("")` 一致） |
| 声明字段值是 `dict` / `list` | 递归处理内部键 / 元素，不把容器 `str()` 成掩码串 |
| 嵌套深度超上限 | 该层原样返回（不抛错） |
| 策略名未知（Schema 写了未注册策略名） | 兜底 `custom` 全掩码（序列化期不抛错） |
| 占位权限检查器 | `check_plain()` → `False`（恒掩码，无权限码静默不生效） |
| 未注入掩码器（非请求态，如脚本 / 单测直调 `model_dump()`） | 原样返回（既有行为不变） |
| 日志配置项非法 | 配置模型校验拒启（不静默降级） |
| 日志配置试图移除内置名单 | 并集语义，移除无效（只可追加） |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **向后兼容**：`mask` / `reveal` 新增**可选**参数——既有调用（`mask(field, value)`）零改动；`masked_fields` 默认仍是空集——既有模型与断言（`BaseSchema.masked_fields == frozenset()`、`OrgUser.masked_fields == frozenset({...})`）不变；`NullMasker` 行为不变（仍原样返回）。
- **测试隔离**：`conftest.py` 的 `BMS_MASKING__PROVIDER=""`（单测回落 `NullMasker`）继续生效 → 新增全局依赖不会让既有单测产出掩码，既有用例零改动。
- **响应面**：全局依赖使所有服务请求期持有掩码器，但**只有声明了敏感字段的模型**会掩码（当前仅 `OrgUser`）→ 其余响应逐字节不变。
- **`OrgUser` 输出变化（预期修复）**：`phone` / `email` 由明文变为掩码值（`138****5678` / `z***@example.com`）；org 侧既有用例只断言字段清单与声明集合，不断言明文值（实施前复核确认）。
- **`captcha` 回显**：`CaptchaChallengeResponse.target` 已由 `mask_phone` 生成掩码值，其 `masked_fields` 为空 → 不会被二次掩码；回接后取值口径不变。
- **日志**：内置名单恒生效 → 现网日志脱敏行为不变；新增键位默认空，仅追加配置时扩大覆盖面。
- **导出**：`BaseExporter` / `ImpExp` 契约零改动；新工具为纯增量。
- **阶段七接续零改动**：换真实权限检查器后 `check_plain()` 自动按 `data:plain` 放行；`get_masker` 提供者与插件键均不变。

## 7. 边界与开放项 <a id="boundary"></a>

- **`data:plain` 真实判定**（RBAC 权限码）→ 阶段七；本任务只保证 fail-closed 与消费方登记。
- **加密字段真实解密**（`reveal` 解密路径与密钥来源）→ 04_03。
- **`ai_chat_log` 真实落库**：本任务只提供 `mask_text` 与登记落库前掩码口径，写入实现归 AI 阶段。
- **导出审计真实实现**：真实审计基座归阶段八；本任务只登记「导出大文件记录审计」的消费方口径。
- **值探测自动识别**（按值正则猜类型）：**不做**（与 04_01 一致，显式声明 / 显式策略驱动）。
- **自定义策略经 Schema 声明**：纯函数 `mask_text` 只解析内置策略；Schema 声明引用自定义策略名时，需该策略已注册到掩码器（否则兜底 `custom` 全掩码）——口径登记于基类清单。
- **日志自由文本**：仅按**键名**脱敏（值整体 `***`），不扫描值内手机号 / 邮箱（避免误掩与性能损耗）；需要时由消费方经 `mask_text` 显式处理。
- **导出列的多形态值**：`mask_rows` 面向扁平列值（标量）；列值为嵌套结构时由调用方先经序列化掩码口径处理（不在本工具重复实现）。
- **Kiwi 用例编号** → 实施时登记回填。
