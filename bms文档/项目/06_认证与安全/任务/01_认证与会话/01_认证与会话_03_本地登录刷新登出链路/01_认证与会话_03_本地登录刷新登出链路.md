## 2. 任务内容 <a id="content"></a>

1. **`sys_user` 最小模型（org 服务）**：表文件先设计后落库（账号 / 密码哈希 / 状态 / 锁定字段 / `pwd_changed_at` / `pwd_history` / `last_login_at` / 语言时区偏好），ORM 模型 + Alembic 迁移 + 表归属登记（《[数据库开发规范](../../../../../规范/数据库开发规范.md)》流程）。
2. **org 内部凭据接口**：凭据校验 / 密码更新 / 锁定状态读写的最小内部接口（服务 JWT 鉴权、不经网关、SIT 直连拒绝），供 identity 登录与域二 JIT 建号、域三密码策略调用；契约快照与版本登记。
3. **登录端点**：`POST /auth/login`——验证码校验接线（经 `BaseCaptcha`，真实强制分支随 `03_04`）、登录限流与失败计数（经限流基座，Redis 后端）、org 凭据校验、签发双 token、创建会话载体（记录 + Redis 标记，管理能力归 01_04）、更新 `last_login_at` / 密码策略字段。
4. **刷新端点**：`POST /auth/refresh`（httpOnly cookie）——校验签名 / 黑名单 / 会话标记，轮换签发新双 token（旧 refresh 失效）；refresh 重放被拒。
5. **登出端点**：`POST /auth/logout`——refresh 入黑名单、会话置 `revoked`、删 Redis 标记；幂等。
6. **错误语义**：`20001` ~ `20006` 认证错误码段实现（账号 / 密码 / 锁定 / 验证码 / 限流语义），错误信息不泄露账号是否存在；登录不落 `sys_login_log`（归阶段八），结构化日志不落密码 / 令牌原始值。

## 3. 完成标准 <a id="accept"></a>

本地登录 → 访问受保护接口 → 静默刷新 → 登出链路端到端通过；错误分支（错密 / 锁定 / 验证码 / 限流）返回码与契约一致；refresh 轮换后旧票据重放被拒；org 内部接口仅接受有效服务 JWT；`sys_user` 表文件 ↔ 总览登记 ↔ 迁移零漂移且三库校验通过；Kiwi 用例登记并全绿。
