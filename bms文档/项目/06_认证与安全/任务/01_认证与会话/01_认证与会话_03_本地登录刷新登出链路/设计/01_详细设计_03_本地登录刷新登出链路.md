## 1. 设计目标与范围 <a id="goal"></a>

在 01_01（安全原语）与 01_02（用户双 token 自签）之上，落**本地账号密码登录 / 刷新 / 登出**完整链路：

1. **`sys_user` 最小模型（org 服务）**——表文件 + ORM 模型 + 迁移 + 表归属登记，承载账号 / 密码哈希 / 状态 / 最小锁定字段 / `pwd_changed_at` / `pwd_history` / `last_login_at` / 语言时区偏好；
2. **org 内部凭据接口**——`verify`（凭据校验 + 按需重哈希）、`update-password`（密码更新）、`login-state`（登录态与锁定写回）三个最小内部端点，**服务 JWT 鉴权、不经网关、直连伪造拒绝**，随公开契约快照登记；
3. **登录端点** `POST /auth/login`——验证码接线（`BaseCaptcha`，按场景策略）、登录限流与失败计数（`BaseRateLimiter` Redis 后端 + memory 降级）、经 org 凭据校验、签发双 token、创建会话载体（`sys_session` 记录 + Redis 标记）、更新 `last_login_at`；
4. **刷新端点** `POST /auth/refresh`（httpOnly cookie）——校验签名 / 黑名单 / 会话标记 / `refresh_token_hash`，轮换签发新双 token（同会话 id，旧 refresh 失效）；
5. **登出端点** `POST /auth/logout`——refresh 入黑名单、会话置 `revoked`、删 Redis 标记；幂等；
6. **错误语义**——认证段新增 `20002`（账号或密码错误，防枚举）、`20003`（账号已锁定）、`20004`（账号已停用），验证码沿用 `20101~20103`、限流沿用 `10005`；错误信息不泄露账号是否存在；登录不落 `sys_login_log`（归阶段八）；结构化日志不落密码 / 令牌原始值。

**不在本期**：`require_auth` 真实登录态与租户解析接线（`01_05`）、会话列表 / 详情 / 强制踢出 / 多端上限（`01_04`）、验证码真实出题与连续失败强制分支（`03_04`）、密码复杂度 / 有效期 / 历史策略判定（`03_05`）、账号三型锁定明细与解锁审计（`03_07`）、SSO 授权码链路（域 02）、`sys_login_log` 落库（阶段八）。

**安全影响（SDL）**：涉及用户凭据（密码明文入参 → PBKDF2 校验）、长时 refresh 载体、跨服务凭据接口。专项验收点：密码 / 令牌原始值不落日志与响应、`needs_rehash` 平滑升级、refresh 类型强校验（不得当 access 用）、内部接口仅接受 `sub∈{identity}` 的有效服务 JWT（网关 `sub=gateway` 与用户票据一律拒）、失败信息不泄露账号存在性、登录失败计数与锁定防爆破。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 数据库表与归属 <a id="tables"></a>

两张新表，表文件为字段唯一事实源（本节只列要点，字段清单不复制）：

| 表 | 归属库 | 模块 | ORM 模型 | 迁移链 | 状态 |
| --- | --- | --- | --- | --- | --- |
| `sys_user` | org 服务租户库 `bms_org_{code}` | 03-用户管理 | `bms_org/models/user.py::SysUser` | `org:tenant` | 已落库 |
| `sys_session` | identity 服务租户库 `bms_identity_{code}` | 15-会话管理 | `bms_identity/models/session.py::SysSession` | `identity:tenant` | 已落库 |

- `sys_user` 关键字段：`username`（`uq_sys_user_username_deleted_at`）、`password_hash`、`name`、`status`（`enabled`/`disabled`）、`failed_count`、`locked_until`、`pwd_changed_at`、`pwd_history`（`TEXT` 存 JSON 数组，仅应用侧读写，理由入表文件）、`last_login_at`、`locale`、`timezone`；公共字段继承 `BaseModel`。
- `sys_session` 关键字段：`id`（雪花主键）、`session_id`（= jti，`uq_sys_session_session_id_deleted_at`）、`user_id`、`refresh_token_hash`（SHA-256 hex）、`device`、`ip`、`login_at`、`expires_at`、`revoked_at`；索引 `idx_sys_session_user_id`（在线会话主路径 `user_id + revoked_at IS NULL`）。
- 表归属登记（`bms_core/services/table_registry.py::TABLE_OWNERSHIP`）：新增 `sys_user`（owner `org`、datasource `TENANT`、status `enabled`）；`sys_session`（现有 owner `identity`、datasource `TENANT`）由 `planned` 转 `enabled`。
- 变更顺序（《数据库开发规范》强制）：**先表文件（含变更记录）→ 总览登记 → ORM 模型 → Alembic 迁移 → 回写状态两处**。

### 3.2 org 内部凭据接口 <a id="org-internal"></a>

路径统一 `/api/v1/org/internal/credentials/*`（服务间调用基座要求落在 `/api/v1` 公开面），模块级依赖 `Depends(require_service("identity"))`：

| 方法 | 路径 | 请求 | 响应 data | 语义 |
| --- | --- | --- | --- | --- |
| POST | `/internal/credentials/verify` | `{account, password}` | `{found, valid, locked, status, rehashed, user?}` | 校验哈希（常量时间）；命中且 `needs_rehash` 时**同请求内重算回写** `password_hash`（`pwd_changed_at` 不变）；`user` 为最小概要（`id` / `username` / `name` / `locale` / `timezone` / `pwd_changed_at`） |
| POST | `/internal/credentials/update-password` | `{account, new_password, keep_history}` | `{updated}` | 计算新哈希、`pwd_changed_at=now`、`pwd_history` 追加旧哈希并保留近 N 条；供域三改密 / 找回复用 |
| POST | `/internal/credentials/login-state` | `{account, success, failed_count?, lock_seconds?}` | `{failed_count, locked_until, last_login_at}` | 成功：`last_login_at=now`、`failed_count=0`、`locked_until=NULL`；失败：写 `failed_count`，`lock_seconds>0` 时 `locked_until=now+lock_seconds` |

- **租户定位**：经服务 JWT 的 `tenant` claim（`ServiceJwtEdgeTrust` 回写租户头），由全局租户中间件按租户库解析；端点不离租户豁免清单（需真实租户上下文选库）。
- **鉴权**：`require_service("identity")` = 从 `Authorization: Bearer` 取 token → `UnifiedTokenVerifier.verify(token, audience="service")` → 校验 `verified.service == "identity"`；无 token / 用户票据 / 网关服务票据（`sub=gateway`）一律 `AuthError`（20001/401）。
- **契约登记**：本组端点**计入 org 公开契约**（`deploy/contracts/org.json` 重生成，零漂移）；`CONTRACT_VERSION` 不变（纯新增，非破坏性）。
- **失败语义**：账号不存在与密码错误**在内部接口可区分**（`found` / `valid`），但登录侧统一映射为 `20002`（防枚举）；停用 / 锁定以 `status` / `locked` 表达。

### 3.3 登录 / 刷新 / 登出端点契约 <a id="endpoints"></a>

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/v1/auth/login` | 公开（网关 `public_paths` 已登记） | 账号密码登录 |
| POST | `/api/v1/auth/refresh` | 公开（读 httpOnly cookie） | 静默刷新轮换 |
| POST | `/api/v1/auth/logout` | 读 cookie（幂等，无需 access） | 登出 |

**登录请求 / 响应**：

```json
// POST /api/v1/auth/login
{ "account": "admin", "password": "***", "tenant": "demo",
  "captcha": { "captcha_id": "...", "kind": "image", "code": "1234", "trace": [] } }
// 200
{ "code": 0, "message": "ok", "data": {
    "access_token": "<BMS 自签 access>", "token_type": "Bearer", "expires_in": 1800,
    "user": { "id": "1800...", "username": "admin", "name": "管理员",
              "tenant": "demo", "locale": "zh-cn", "timezone": "Asia/Shanghai",
              "must_change_password": false } } }
// 响应头：Set-Cookie: bms_refresh_token=<refresh>; HttpOnly; Secure; SameSite=Lax; Path=/api/v1/auth; Max-Age=1209600
```

**刷新**：无请求体；读 `bms_refresh_token` cookie；**租户经请求上下文（子域名 / `X-Tenant-ID`）确定**并与 refresh claims 的 `tenant_id` 交叉校验。响应 `{access_token, token_type, expires_in}` + 重设 cookie（轮换）。`refresh_token_hash` 比对 + 会话标记存在性校验；旧票据重放（哈希不符）→ `AuthError`（20001/401）。

**登出**：读 cookie；命中则 refresh `jti` 入黑名单（TTL 至 refresh 过期）、`sys_session.revoked_at=now`、删 Redis 会话标记；无论 cookie 是否存在均返回 `200`（幂等），并清 cookie。

### 3.4 会话载体与轮换机制 <a id="session"></a>

- **会话 id 稳定**：登录 `new_session_id()`（雪花）生成 `session_id`，access 与 refresh 的 `jti` 同值（沿用 01_02）；轮换**不换** `session_id`，只更新 `refresh_token_hash`。
- **Redis 标记**：`bms:{tenant}:sess:{session_id}`（新增 `build_session_key`），值 = 会话负载 JSON（`user_id` / `tenant` / `login_at`），TTL 与 refresh 对齐（14 天）；登录写、刷新续期、登出删。每请求校验链由 01_05 消费（本任务只保证写入正确）。
- **轮换**：`refresh` 校验通过后签发新 access + 新 refresh（同 `session_id`），更新 `sys_session.refresh_token_hash` 与 Redis TTL，重设 cookie；旧 refresh 因哈希不符在下一次使用被拒。
- **登出 / 失效**：refresh 入黑名单（`BaseSessionSecurity.blacklist_key`，`bms:global:token:blacklist:{jti}`）+ `revoked_at` 落库 + 删标记；三处一致。
- **存储实现**：新增 `RedisSessionStore`（真实现，JSON + TTL，Redis 异常降级为「不命中」）与 `MemorySessionStore`（测试 / 降级）；`[session_store].provider` 选择（基线 `redis`，测试套置空回落 Null）。

### 3.5 服务间调用与租户传递 <a id="servicecall"></a>

- **启用范围（全局）**：基线 `config.toml` 置 `[service_client].provider="http"`、`options.attach_service_token=true`，并置 `[session_store].provider="redis"`、`[rate_limiter].provider="redis"`；各服务测试套 `conftest.py` 显式置 `BMS_SERVICE_CLIENT__PROVIDER=""`（与既有 `BMS_METRICS__PROVIDER=""` / `BMS_TRACER__PROVIDER=""` 同模式），保单测确定性。
- **租户透传**：`ServiceRequest` 增 `tenant` 字段；`HttpServiceClient` 签发服务 JWT 时带 `ServiceTokenSpec(service=..., scopes=..., tenant=...)`；org 侧 `ServiceJwtEdgeTrust` 由 claim 回写 `X-Tenant-ID`，全局租户中间件据此解析租户库。
- **调用方**：identity 新增 `OrgCredentialClient`（基于 `get_service_client`，`ServiceRequest(service="org", path="/api/v1/org/internal/credentials/...", tenant=code, policy=ServiceCallPolicy(scopes=("credential",)))`）；捕获 `ServiceUnavailableError`（10007）→ 登录返回 `ServiceUnavailableError`（503）不降级为「密码错误」（fail-closed）。
- **服务寻址**：`org` 已在服务目录登记启用，地址走模板 `http://{service}:8000`（Compose DNS；测试注入 `MockTransport` / `ASGITransport`）。

### 3.6 限流 / 失败计数 / 账号锁定 <a id="lock"></a>

- **限流（防爆破）**：`BaseRateLimiter` 新增 Redis 后端（固定窗口 `INCR`+`EXPIRE`，异常降级 memory）+ memory 实现；登录按维度 `ip` 与 `account` 各 `require` 一次（键 `build_rate_limit_key`，阈值 / 窗口取 `[login]`）。
- **失败计数**：Redis 计数键 `bms:{tenant}:login:fail:{account}`（成功清零、失败自增）；达到上限 → 调 org `login-state(success=false, failed_count, lock_seconds)` 写回 `sys_user.locked_until` 并返回 `20003`。
- **账号锁定（最小）**：`sys_user.locked_until` + `failed_count` + `status` 供登录即时判定；三型锁定明细、解锁与审计归域三 `03_07`。
- **验证码**：按 `captcha.policy("login")` 决定是否强制；`required` 或请求携带凭证时调 `require_credential`；连续失败强制分支归 `03_04`（本期常量 + `[login]` 预留）。

### 3.7 错误码口径与冲突处置 <a id="errors"></a>

**冲突**：架构 09 已登记 `20001` 认证失效、`20101~20103` 验证码、`10005` 限流；概要 14 §7 却把 `20001~20006` 记为会话错误；需求 01-3 文本又要求 `20001~20006` 表示登录类错误。**处置（本次拍板）**：

| 码位 | 含义 | 落点 |
| --- | --- | --- |
| `20001` | 认证失效（401；token / 会话无效） | 既有（不变） |
| `20002` | 账号或密码错误（同码防枚举） | **新增** |
| `20003` | 账号已锁定 | **新增** |
| `20004` | 账号已停用 | **新增** |
| `20101~20103` | 验证码（校验失败 / 不存在或过期 / 过于频繁） | 既有（沿用） |
| `10005` | 限流 | 既有（沿用） |
| `20011~20016` | 会话错误（原概要 14 的 `20001~20006`，避让登录段） | 概要 14 §7 **回写** |

- 新增异常：`LoginFailedError` / `AccountLockedError` / `AccountDisabledError`（继承 `AuthError`，HTTP 401，业务码 `20002/~20003/~20004`，文案交前端 i18n `error.{code}`）。
- 回写：概要 14 §7 会话错误码表整体后移 `20011~20016`；架构 09「平台已发布码位」补 `20002~20004`；需求 01-3 文本保持不变（详细设计为准），冲突记录入 §8。

### 3.8 配置契约 <a id="config"></a>

```toml
[service_client]
provider = "http"                                  # 真实跨服务调用（全局启用）
options = { attach_service_token = true }          # 出站附自签服务 JWT（带 tenant）

[session_store]
provider = "redis"                                 # 会话标记 Redis 实现（连接串取 [redis].url）

[rate_limiter]
provider = "redis"                                 # 限流 Redis 实现（异常降级 memory）

[login]
max_failures = 5                                   # 连续失败锁定阈值
lock_seconds = 900                                 # 锁定时长（15 分钟）
ip_rate_limit = 60                                 # 每 IP 每分钟登录请求上限
account_rate_limit = 20                            # 每账号每分钟登录请求上限
captcha_lock_threshold = 3                         # 连续失败强制验证码阈值（预留 03_04）
```

| 配置键 | 环境变量 | 口径 |
| --- | --- | --- |
| `[service_client].provider` | `BMS_SERVICE_CLIENT__PROVIDER` | 基线 `http`；测试置空回落 Null |
| `[service_client].options.attach_service_token` | `BMS_SERVICE_CLIENT__OPTIONS__ATTACH_SERVICE_TOKEN` | `true`；出站剥离入站 `Authorization` 并附服务 JWT |
| `[session_store].provider` | `BMS_SESSION_STORE__PROVIDER` | 基线 `redis`；测试置空 |

### 3.9 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 登录：账号不存在 / 密码错误 | `LoginFailedError`（20002/401，不区分，防枚举）；Redis 失败计数 +1 |
| 登录：账号锁定（`locked_until > now`） | `AccountLockedError`（20003/401） |
| 登录：账号停用（`status != enabled`） | `AccountDisabledError`（20004/401） |
| 登录：验证码强制未过 / 失效 / 频繁 | `20101` / `20102` / `20103`（沿用） |
| 登录：请求限流命中 | `RateLimitError`（10005/429） |
| 登录：org 不可达 / 返回 5xx | `ServiceUnavailableError`（10007/503），不降级为登录失败 |
| 登录：连续失败达阈值 | 写 `locked_until` + 返回 `20003` |
| 刷新：cookie 缺失 / 非 refresh / 过期 / 签名不符 / 未知 kid | `AuthError`（20001/401） |
| 刷新：jti 命中黑名单 / 会话标记不存在 / `refresh_token_hash` 不符 | `AuthError`（20001/401） |
| 刷新：租户上下文缺失或与 claims `tenant_id` 不符 | `AuthError`（20001/401） |
| 登出：cookie 缺失 / 无效 / 已登出 | `200`（幂等，清 cookie） |
| 登出：黑名单 / 落库 / Redis 删除任一步失败 | 尽力而为 + 日志告警；`revoked_at` 已写即视为成功，不回滚 |
| org 内部端点：无 / 用户 / 网关服务票据 | `AuthError`（20001/401） |
| org 内部端点：有效 identity 服务 JWT | 放行；租户由 claim 解析 |
| 达梦 / 三库方言 | 结构走迁移，零漂移校验；`pwd_history` 用 `TEXT` 存 JSON 规避方言 JSON 差异 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **新增**：`require_service`、`OrgCredentialClient`、`Redis/MemorySessionStore`、`Redis/MemoryRateLimiter`、`build_session_key`、`SysUser` / `SysSession`、org 内部端点、登录 / 刷新 / 登出端点、`[login]` 配置。
- **扩展**：`ServiceRequest` 增可选 `tenant`（默认 None，向后兼容）；`HttpServiceClient` 仅在 `attach_service_token` 且 `tenant` 非空时写入 `ServiceTokenSpec.tenant`。
- **默认值变更（需回归）**：`[service_client].provider=""` → `"http"`、新增 `[session_store]` / `[rate_limiter]` 的 `redis` 默认；受影响的既有测试（如 `test_servicecall` 断言 NullServiceClient）随测试套 `conftest` 置空后保持原语义。
- **不改**：`introspect` 端点契约与网关生成件、`oauth` 服务令牌链路、`[security]` 密钥 / TTL、契约快照 identity/org 的既有端点、既有 Kiwi 用例号。
- **迁移链影响**：`identity:tenant` 与 `org:tenant` 由「未登记」转「已登记」，`test_alembic_chains` 的反例改用仍未登记的服务链（如 `file:tenant`），并更新 `chain_metadata` 断言。
- **数据所有权**：`sys_user`（org）与 `sys_session`（identity）跨服务逻辑外键用值传递（`user_id`），不直连他库、不建物理外键；identity 不 import org 模型。

## 7. 边界与开放项 <a id="boundary"></a>

- **归 01_04**：会话列表 / 详情 / 强制踢出 / 多端上限（`sys_session` 管理）、`session.revoked` 广播占位；本任务只交登录态会话载体与会话存取原语。
- **归 01_05**：`require_auth` 真实登录态与每请求会话标记校验、租户解析接线。
- **归 03_04 / 03_05 / 03_07**：验证码真实出题与连续失败强制、密码复杂度 / 有效期 / 历史策略判定、三型锁定与解锁审计。
- **归阶段八**：`sys_login_log` 落库（异步 + 哈希链）、`session.revoked` 实时广播。
- **归阶段七**：登录响应的权限码 / 菜单概要（本期只返用户概要）。
- **开放项（登录租户覆盖）**：body `tenant` 与请求上下文不一致时以 body 为准，经 `tenant_source` 校验后用统一会话入口 `session_scope`（显式库键，库键由基座 `build_tenant_db_key` 派生）落 identity 会话；认证前置端点属租户上下文特例，记入本设计（后续是否统一为「登录页强制带 `X-Tenant-ID`」由域五前端联调时评估）。
- **开放项（`attach_service_token` 与密钥）**：dev 真实外呼需 `[service_token].keys` / `[security].keys` 就绪（`deploy/.env` 注入）；测试套经 `conftest` 置空 provider，登录用例以依赖覆盖注入 fake 客户端。
- **开放项（限流降级）**：Redis 故障时降级 memory（进程内，单副本口径）；跨副本一致性与告警细化归性能 / K8s 阶段。
