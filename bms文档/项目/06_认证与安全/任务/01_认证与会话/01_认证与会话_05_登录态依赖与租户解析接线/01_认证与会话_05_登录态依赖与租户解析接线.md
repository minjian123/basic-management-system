## 2. 任务内容 <a id="content"></a>

1. **`require_auth` 真实实现**：解析网关注入的可信身份头（`X-User-Subject` / `X-Tenant-Id`，边缘信任已交付）或本地校验 Bearer 用户令牌；失败抛 `AuthError`（20001 / 401）；成功写请求上下文（用户标识 / 租户 / 会话）。
2. **受保护路由统一切换**：全部「登录即可」路由（服务目录、插件聚合、检索、图标、打印、AI 等）切换真实登录态依赖；冒烟确认无遗漏。
3. **租户解析接线**：请求上下文租户优先取网关身份头，其次取 token `tenant_id` 兜底；全局租户中间件豁免路径（探针 / 公开认证端点）与判决口径一致；会话 / 缓存键按租户前缀隔离核验。
4. **错误码落地**：认证错误码段（`20001` 等）实现与用例；错误响应不泄露内部细节。
5. **口径回写**：《[后端基类清单](../../../../../后端基类清单.md)》「鉴权依赖占位」条目与《[架构设计 · 认证与会话](../../../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》协调节更新。
6. **回归**：既有服务端用例（含受保护路由）在真实鉴权下回归全绿（需要登录态的用例经测试夹具取得令牌）。

## 3. 完成标准 <a id="accept"></a>

未携带 / 携带无效 token 访问受保护接口返回 401；有效登录态下请求上下文用户与租户正确（跨租户被拒）；租户解析三来源（身份头 / token / 显式入参）用例覆盖；全量后端回归与基座 / 边界校验全绿。
