## 4. refresh cookie 路径修复设计 <a id="cookie"></a>

**根因**：cookie 的 `Path` 由**服务**下发，但浏览器按**浏览器地址**做前缀匹配；服务内 `/api/v1/auth` 与浏览器外部路径 `/api/identity/v1/auth/*` 不是前缀关系 ⇒ 永不回传。

**口径**：`REFRESH_COOKIE_PATH = "/"`。

- **为什么 `/`**：① 只依赖「同源」，不依赖网关 shape / 服务键 / 部署形态（换网关、加服务、改前缀都无需再动）；② dev（Vite 代理）与生产（nginx → APISIX）**同形**，避免「本地能续期、线上不能」类问题；③ 副作用可控——cookie 仍为 `HttpOnly` + `Secure`（生产）+ `SameSite=Lax`，跨站 `POST` 仍被 Lax 拦截，作用域放宽只影响**同源**请求的携带面。
- **不改网关的理由**：nginx `proxy_cookie_path` 与 Vite `cookiePathRewrite` 需**两处**各自维护且易漏（新增服务键 / 换边缘即失效）；后端常量是**单一来源**。
- **迁移兼容**：历史 cookie（`Path=/api/v1/auth`）在浏览器中惰性残留（永不回传），登出时按**两个 Path** 各下发一次删除；不做其它清理（无法枚举浏览器中全部历史 Path）。
- **不做**：不引入 `[login].cookie_path` 配置项（当前无多环境差异）；不改 `REFRESH_COOKIE_NAME`；不改 `Max-Age` / `remember_me` 语义（[05-5](../../../../需求/05_需求_登录前端.md#r05-5) 口径不变）。

**回归面**：SSO 回调（`api/sso.py:453`）复用同一下发函数 → 自动覆盖；`test_callback.py` 的 `Path` 断言同步校正；identity 其余 cookie 行为（`Max-Age` / `SameSite` / `HttpOnly`）保持不变（既有断言继续把关）。

## 5. 模块错误态作用域设计 <a id="boundary"></a>

**现状问题**：`ModuleBoundary` 的 `error !== null` 判定**不分路由**，且错误态为全局单例 ⇒ 任一模块加载失败（含 `modules.json` 清单失败）顶掉**所有**路由内容（含 `/login`）。

**设计（两级判定）**：

| 错误来源 | 判定 | 结果 |
| --- | --- | --- |
| **当前路由自身渲染失败**（`onErrorCaptured`，含平台页面） | 组件内 `renderFailed` 置真 | 渲染错误页（**保持既有行为**，含重试） |
| **模块加载 / 清单失败**（`module/host.ts` 写入的全局错误态） | 仅当「当前路由**归属该失败模块**」且「非免登录 / 基础路由」 | 渲染错误页；否则渲染 `<slot />`（正常路由内容） |

- **免登录 / 基础路由白名单**：`isPublicPath(route.path, resolvePublicPaths())`（`/login`、`/403`、`/404`、`/500` + DEV 专属）——**永不受模块错误态影响**。
- **模块归属**：`resolveRouteModule(route.name)?.name === error.module`（`module/host.ts` 既有能力）；平台自身路由（无归属模块）与「清单失败」（`module: 'modules.json'`）**不阻断宿主页面**——避免 `modules.json` 读取失败导致整站不可用。
- **重试**：保持既有 `retry()`（模块级重挂 → 失败退整页刷新）；`clearModuleError` 语义不变。
- **不做**：不新增错误边界层级、不改模块加载重试策略（归 06_02 边界）。

## 6. 守卫未装配时的会话就绪兜底（§7 第 29 项） <a id="guard-off"></a>

**现状**：`installAuthGuard` 关闭时直接 `return false`，无人调用 `session.ensureReady()`；`App.vue` 以 `!session.ready` 渲染骨架屏 ⇒ 应用**停在骨架屏**。

**设计**：`installAuthGuard` 在守卫关闭分支**仍触发一次** `deps.ensureSession()`（`void`，不阻塞、不注册任何钩子、返回值仍为 `false`），使 `ready` 落定；失败静默（与 `05_03` 既有口径一致：不提示、不跳转）。守卫开启路径**零改动**。

## 7. `ops/seed_user.py` 设计 <a id="seed"></a>

**定位**：**运维建号 / 联调入口**（不在业务链路、不被应用代码引用），与 `ops/seed_tenant.py` / `ops/seed_menu.py` 同范式。

| 项 | 设计 |
| --- | --- |
| 用法 | `uv run python -m ops.seed_user --tenant demo --username admin [--name 管理员] [--password <明文>] [--reset-password] [--url <org 租户库连接串>] [--service org] [--dry-run]` |
| 库定位 | `--url` 优先；否则读平台库对照表 `sys_tenant_database` 取 `db_basis`（缺行回落 `--tenant`）→ `build_tenant_db_key(db_basis, service=--service)` → `EngineFactory(settings, allow_cross_service=True).resolved_url(key)`（与 `ops/init_tenant.py` 同源口径） |
| 建表 | `Base.metadata.create_all(conn, tables=[SysUser.__table__])`（`checkfirst=True`；SQLite 开发库 / 首次建库容错） |
| 幂等判定 | `username` + `deleted_at IS NULL` 判存：存在且未传 `--reset-password` → **跳过**；存在且传 → **重置**；不存在 → **新建** |
| 写入字段 | `username` / `password_hash`（`Pbkdf2PasswordHasher` 自描述串）/ `name` / `status="enabled"` / `pwd_changed_at=now` / `pwd_reset_required=False`；重置分支额外清 `failed_count=0` / `locked_until=None` |
| 口令 | `--password` 给定则用之（须满足最小长度校验，脚本侧仅做长度与空值防护）；缺省**随机生成**（`secrets`）并**仅标准输出一次性打印**；不落库（只落哈希）、不落日志文件 |
| 输出 | `新增 1 行 / 重置 1 行 / 跳过 1 行`；`--dry-run` 打印目标库（脱敏）与将执行的动作，不建连 |
| 边界 | 不写 `sys_user_identity`（SSO 映射）、不改 `sys_session`；用户↔租户归属关系若已由域 11 提供则**尽力写入**（失败仅告警，不阻断建号） |

**安全口径**：脚本只建 / 重置并按需打印一次明文口令；生产环境首建账号的口令强度由操作者按《[安全开发规范](../../../../../../规范/安全开发规范.md)》把关；脚本不引入任何免登录 / 旁路鉴权能力。

## 9. 风险与开放项 <a id="risk"></a>

| 风险 / 开放项 | 处置 |
| --- | --- |
| 作用域放宽至 `/` 后 refresh cookie 随同源请求携带面变大 | `HttpOnly` + `Secure`（生产）+ `SameSite=Lax` 不变；跨站 `POST` 仍被拦截；如后续要收紧，可改为「外部前缀」口径（本设计 §4 已登记替代方案） |
| 浏览器残留历史 Path cookie | 登出双 Path 清理；残留 cookie 本身惰性不可用（不回传） |
| 远端开发环境为共享环境，建号会写入真实租户库 | 只建 / 重置**联调账号**（用户名显式指定、口令随机一次打印）；不动既有账号（除显式 `--reset-password`） |
| SSO / 扫码分支真机回归需 IdP 环境 | 接口层用例 + 调用点核对覆盖（同常量同函数，风险等价）；真机 IdP 回归凭据就绪时补 |
| `modules.json` 读取失败时模块路由不再报错页 | 由「模块清单失败」不阻断宿主换取「登录 / 错误页可用」；模块路由表现为 404，重试入口经模块观测面板（06_02 边界不变） |
