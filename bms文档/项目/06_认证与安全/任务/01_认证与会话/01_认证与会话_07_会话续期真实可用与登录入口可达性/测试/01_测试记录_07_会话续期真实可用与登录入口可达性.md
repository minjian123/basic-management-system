## 4. 真实浏览器验证与未覆盖项 <a id="browser"></a>

**已完成（真实浏览器 · **本机全套**：`scripts/tools/dev/本地全套.sh up` 起四服务 + 本地 SQLite + 前端 5173）**：

1. **真机整链（需求 01-7 核心准出）**：清空 cookie 访问 `http://localhost:5173/` → 落 `/login?redirect=/`；填 `admin` / `***REDACTED***`（`ops/seed_user.py` 建号）→ 进入 `/`；会话 cookie 为 **`bms_refresh_token`（`path=/`、`HttpOnly`）**；**硬刷新（真实导航重载）后仍停留 `/`**——静默续期成功（修复前硬刷新必回登录页）；调用登出接口后浏览器 cookie **清空**（当前 + 历史双 `Path` 删除）。
2. **模块加载失败不顶登录页**：停掉模块产物服务（5002）后访问 `/login`——**登录表单正常渲染**、页面无「模块加载失败」错误页（修复前即为错误页）；恢复 5002 后一切照旧。
3. **cookie 作用域机制**：浏览器内设 `path=/` 的 `bms_refresh_token` → `POST /api/identity/v1/auth/refresh` 返回「票据验签失败」（**cookie 已回传**，进入票据校验分支）；设 `path=/api/v1/auth` → 返回「缺少刷新令牌」（未回传，修复前行为）——即修复后**浏览器侧续期链路打通**。
4. **后端断点入口（`ops/dev_run.py`，真实进程验证）**：`本地全套.sh stop identity`（该服务 healthz 000、其余三个不受影响）→ `python -m ops.dev_run --service identity` → `healthz/readyz 200`，经前端代理 `POST /api/identity/v1/auth/login` **200** 且该请求**确由调试进程处理**（其日志含 `path=/api/v1/auth/login`）；停止进程后端口释放，`up` 补回四服务全健康。**未新增 Kiwi 用例**——开发调试入口不属交付链路，以真实进程验证代替（断点能力由 IDE 项「后端：单服务（debugpy · 本机四服务）」提供）。

**未覆盖（已登记）**：

1. **远端开发环境（mjbk）同链路复核**：本机全套已覆盖同一代码路径与同一浏览器行为；远端 `bms-identity` 仍是 **2026-09-27 构建的旧代际**（`19a620b9`），待**发布窗口**重新部署后复核（开发态一律本机裸跑，部署只在发布时进行）。
2. SSO / 扫码分支真机续期：同一常量同一函数，接口层用例已覆盖（`test_callback.py`）；真机 IdP 回归凭据就绪时补。
3. 开发 / 生产两形态的网关层 cookie 行为差异：本任务口径不依赖网关改写（Vite 代理与 APISIX / 边缘 nginx 均不改 Set-Cookie），无需额外验证。
