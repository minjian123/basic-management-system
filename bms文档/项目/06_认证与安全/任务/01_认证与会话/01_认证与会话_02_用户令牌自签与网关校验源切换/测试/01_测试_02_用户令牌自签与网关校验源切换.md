## 4. mjbk 真实冒烟记录 <a id="smoke"></a>

**环境**：mjbk Docker（APISIX 3.18.0-debian 容器 `bms-apisix`、Keycloak 26.7.4）；identity 服务以**开发机承载新代码**（临时 `~/deploy/.env` 设 `GATEWAY_AUTH_HOST=<开发机IP>`，临时 `ufw allow from <mjbk> to any port 8000`）；上游以临时 whoami（别名 `platform`，冒烟期临时停 `bms-platform`）。

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| JWKS 合并发布 | `GET /.well-known/jwks.json`（identity 直连） | 200；`svc-k1` + `usr-k1` 公钥（只含公钥、按 kid 排序） |
| 本地签发 | 开发机以 `[security]` 密钥 `issue_pair`（`sub=1001` / `tenant_id=demo` / `session_id=smoke-sess-1` / `scope=user:read`） | access / refresh 双票据 |
| 受保护路径无凭证（经网关） | `GET /api/platform/v1/ping` | **401** |
| 本地 access 经网关 | 带 `Authorization: Bearer <本地 access>` | **200**；上游 echo 收到 `X-User-Subject=1001` / `X-Tenant-Id=demo` / `X-User-Scopes=user:read` / `X-Gateway-Identity=bms-edge`；`Authorization` 为网关服务 JWT（`iss=bms` / `sub=gateway` / `aud=service` / `typ=service` / `kid=svc-k1`） |
| 伪造分支（经网关） | refresh 当 access / 过期 access / `aud=service` / `iss=evil` / 错签名 五种 | 全部 **401**（`WWW-Authenticate: Bearer error="invalid_token"`） |
| 公开路径免认证 | `GET /api/identity/v1/auth/login` 无凭证 | 免认证放行（上游旧镜像无该端点故 404，非 401） |
| 外部 IdP 解耦 | `docker stop bms-keycloak` 后重放本地 access | **200**（本地校验不依赖 IdP）；`docker start bms-keycloak` 恢复 |
| 清理 | 删除临时 whoami、恢复 `bms-platform`、还原 `GATEWAY_AUTH_HOST=identity`、删除 ufw 规则、停止开发机 identity 服务 | 无残留（网关无凭证请求复归 401） |

## 6. 缺陷与偏差 <a id="defects"></a>

| # | 类型 | 说明 | 处置 |

| 1 | 实现问题（自检发现） | JWKS 端点改 `Response` 返回导致公开契约 200 响应结构消失（契约漂移） | 改回 `dict` + `HTTPException(503)`；契约结构不变，仅 description 更新并重生成快照 / 前端类型（见实施记录 §4 问题 1） |

| 3 | 测试自纠 | 负向用例初期取新密钥签名 / `iat` 取未来时间，未命中目标分支 | 改为签发者密钥 + 相对时间构造伪造票据，覆盖率 100% |
