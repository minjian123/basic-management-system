## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段六需求域 01 的 5 条需求——[01-1 安全原语真实实现与认证配置定稿](../../需求/01_需求_认证与会话.md#r01-1)、[01-2 用户令牌自签与网关校验源切换](../../需求/01_需求_认证与会话.md#r01-2)、[01-3 本地登录 / 刷新 / 登出链路](../../需求/01_需求_认证与会话.md#r01-3)、[01-4 会话管理与强制踢出](../../需求/01_需求_认证与会话.md#r01-4)、[01-5 登录态依赖真实化与租户解析接线](../../需求/01_需求_认证与会话.md#r01-5)，按「1 需求 = 1 子任务」拆 5 个子任务（`01_01` ~ `01_05`）。
- **端范围**：**后端为主**（identity 服务 + org 服务最小模型 + bms_core 安全原语 + 网关校验源配置）；前端登录接线归域 05。
- **承接口径**：阶段二已交付 identity 服务工程与网关 forward-auth 接线（`/api/v1/auth/introspect`）、服务 JWT 自签与统一校验、边缘信任（`ServiceJwtEdgeTrust` / `EdgeGuardMiddleware`）、OIDC 客户端；本域在其上**替换用户令牌签发方、补真实登录会话能力**，不重复建设基座。
- **公共前置**：`bms_core/core/security.py` 安全基座占位（本域 01_01 真实化）、`BaseTokenVerifier` / `BaseServiceTokenIssuer`（阶段二已交付）、Redis 与平台 / 租户库（阶段二已交付）、org 服务工程（阶段二已交付骨架）。
- **依据**：《[架构设计 · 认证与会话](../../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §3 / §7、《[概要设计 · 会话管理](../../../../设计/概要设计/14_概要设计_会话管理.md)》、《[后端基类清单](../../../../后端基类清单.md)》。
- **执行序**：`01_01 安全原语` → `01_02 令牌自签与校验源切换` → `01_03 登录 / 刷新 / 登出链路` → `01_04 会话管理与强制踢出` → `01_05 登录态依赖与租户解析`（见[计划](../../计划/01_计划_认证与安全.md)）。

## 3. 工时与依赖 <a id="effort"></a>

- **工时合计**：80h（01 12h + 02 16h + 03 24h + 04 16h + 05 12h）。
- **关键依赖**：`01_02` 依赖 `01_01`；`01_03` 依赖 `01_02`（登录签发与刷新校验）；`01_04` 依赖 `01_03`（会话载体）；`01_05` 依赖 `01_03`（真实登录态）；`01_03` 的强制验证码分支依赖域 03（本域先接基座接口，真实强制分支随 `03_04` 验收）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_认证与安全.md)（本节不写排期）。
- **风险**：令牌签发方切换涉及网关 / 边缘与既有 forward-auth 用例（须回归全绿）；`sys_user` 落 org 服务引入跨服务调用（须经服务 JWT 且失败语义明确）；会话 Redis 标记为每请求路径（性能与降级口径须实测）。
