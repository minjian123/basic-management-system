# 06 详细设计 · 当前用户概要端点（`GET /auth/me`）

> 认证与安全 · 01 认证与会话 · 子任务 06（需求 01-6）· 详细设计

[文档首页](../../../../../../文档首页.md) › [01 认证与会话](../../01_认证与会话.md) › [06 当前用户概要端点](../01_认证与会话_06_当前用户概要端点.md) › 详细设计　|　[需求 01-6](../../../../需求/01_需求_认证与会话.md#r01-6)

## 1. 设计目标与范围 <a id="goal"></a>

补建**当前用户概要端点**，使「刷新页面后首屏静默续期」能够**完整恢复登录态**（访问令牌 + 用户概要），并让 org 内部用户概要接口具备强制改密标记：

- **identity 端点（需求 01-6 第 1 / 3 / 4 条）**：新增 `GET /api/v1/auth/me`（`require_auth`），返回 `ApiResponse[UserSummary]`，字段与登录响应**同字段、同语义**。
- **org 契约补字段（需求 01-6 第 2 条）**：org 内部 `users/profile` 响应增 `pwd_reset_required`（取用户行既有列 `sys_user.pwd_reset_required`），identity 直接映射为 `must_change_password`。
- **契约与类型（需求 01-6 第 5 条）**：identity / org 公开契约快照与 oasdiff 基线按评审节点更新；`@bms/api-types` 重生成零漂移。

**不在本任务**：前端首屏恢复接线（归域五 [05_02](../../../05_登录前端/05_登录前端_02_token与401静默刷新接线/05_登录前端_02_token与401静默刷新接线.md)）；强制改密页面与个人中心（归阶段十五）；用户资料编辑与权限码装载（归阶段七 RBAC）；`/auth/me` 的访问审计与缓存（归阶段八 / 后续）。

**安全影响（SDL）**：本端点回显**当前登录主体自身的**概要（不含口令哈希、历史密码、联系方式等敏感字段），鉴权由 `require_auth` 承担；用户不存在或账号非启用一律按**登录态失效**（401）返回，不泄露「账号是否存在」之外的内部细节。

### 1.1 现状实测与缺口 <a id="gap"></a>

| # | 实测项 | 结论 |
| --- | --- | --- |
| 1 | `RefreshResult` 字段 | 仅 `access_token` / `token_type` / `expires_in`——**不含用户概要** |
| 2 | identity 公开契约路径 | **无「当前用户」端点**（`/auth/*` 下仅 login / refresh / logout / introspect / forgot-password / reset-password / sso/*） |
| 3 | org 内部用户概要接口 | `POST /api/v1/org/internal/users/profile` 已交付（`require_service("identity")`），响应 `UserProfileResult{found, user: UserProfileUser}` |
| 4 | `UserProfileUser` 字段 | `id` / `username` / `name` / `status` / `locale` / `timezone`——**不含强制改密标记** |
| 5 | 强制改密标记来源 | 登录经凭据校验取 `OrgVerifyResult.pwd_reset_required`；org 模型 `sys_user.pwd_reset_required` **已是持久列**（登录超期置真、改密成功清假） |
| 6 | identity 侧调用通路 | `OrgCredentialClient.user_profile(tenant, user_id)` 已可用（自签服务 JWT `sub=identity` + 租户位，失败 10007/503 fail-closed） |
| 7 | `AuthContext` | 已含 `subject` / `user_id` / `tenant_id` / `tenant_code` / `session_id`——**当前用户主体与租户位可直接取用** |

| # | 缺口 | 后果 |
| --- | --- | --- |
| 1 | 首屏续期只能恢复令牌 | 刷新页面后用户概要与强制改密标记丢失（顶栏用户信息为空），登录态不完整 |
| 2 | org 概要无强制改密标记 | 即便补端点也无法与登录响应口径一致（要么丢字段、要么语义失真） |

## 3. 设计与边界 <a id="design"></a>

### 3.1 org 侧：概要补强制改密标记（需求 01-6 第 2 条） <a id="org"></a>

- `UserProfileUser` 增 `pwd_reset_required: bool = False`（描述「是否需强制改密（密码超有效期）」）——与 `UserCreateResult` / 凭据校验 DTO 同名字段语义一致。
- `_summary(row: SysUser) -> UserProfileUser` 增映射 `pwd_reset_required=row.pwd_reset_required`（**读既有持久列**，不重算策略，与登录经凭据校验所得同源）。
- **兼容性**：新增字段属**非破坏性变更**（响应体加字段）；`users/profile` 现有消费方（identity SSO 回调 / JIT）不受影响。

### 3.2 identity 侧：`GET /api/v1/auth/me`（需求 01-6 第 1 / 3 / 4 条） <a id="identity"></a>

```text
api/auth.py
└── @router.get("/me")  →  ApiResponse[UserSummary]
    ├── 鉴权：AuthDep = Annotated[AuthContext, Depends(require_auth)]
    ├── 依赖：OrgCredentialClient（经 get_service_client 构造，与登录同源）
    └── 服务：LoginService.current_user(...) / 独立方法
        ├── auth.user_id 为空 → AuthError（20001 / 401）
        ├── org 概要 found=false → AuthError（用户不存在）
        ├── user.status != "enabled" → AuthError（账号已停用）
        └── 映射 OrgProfileUser → UserSummary(
                id, username, name,
                tenant=AuthContext.tenant_code,
                locale, timezone,
                must_change_password=profile.pwd_reset_required)
```

- **字段与语义**：与 `POST /auth/login` 的 `UserSummary` **同字段、同语义**（同一模型，零漂移）。
- **租户位**：取 `AuthContext.tenant_code`（对外编码）；org 调用按 `AuthContext.tenant_id` / 编码随服务 JWT 传租户位（复用既有 `OrgCredentialClient.user_profile` 签名）。
- **失败分支**：

| 场景 | 处理 |
| --- | --- |
| 未登录 / 令牌无效 / 会话已失效 | `require_auth` 抛 `AuthError`（`20001` / `20012`，401）——本端点不额外处理 |
| 会话有效但 `user_id` 缺失（网关身份头不完整） | `AuthError("缺少用户标识")`（20001 / 401） |
| org 概要 `found=false`（用户已删除） | `AuthError("用户不存在")`（20001 / 401）——前端走统一 401 清会话路径 |
| 账号 `status != "enabled"` | `AuthError("账号已停用")`（20001 / 401） |
| org 不可达 / 响应契约非法 | `ServiceUnavailableError`（10007 / 503，fail-closed，不降级为 401） |

- **口径选择说明**：「用户不存在 / 账号停用」按 **401** 而非 404 —— 二者都意味着当前会话不应继续，401 使前端统一走「会话失效 → 清会话 + 跳登录」路径，避免在首屏恢复处引入按码分流（与域一 `01_05` 的 `20012` / `20001` 同属 401 处理面口径一致）。
- **不返回**：口令哈希、历史密码、邮箱 / 手机等敏感字段（`UserSummary` 本身不含）；org 概要亦不含（`UserProfileUser` 仅含展示字段 + 状态 + 改密标记）。
- **审计**：本端点不写操作日志（读端点；操作日志归阶段八）。

### 3.3 契约与类型（需求 01-6 第 5 条） <a id="contract"></a>

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 1 快照重生成 | `uv run python -m ops.contract_snapshot export` | `deploy/contracts/identity.json`（新增 `/api/v1/auth/me`）与 `org.json`（`UserProfileUser` 加字段）更新 |
| 2 基线更新 | `uv run python -m ops.contract_gate baseline-update --service identity` / `--service org` | 两服务基线按评审节点更新（**仅新增**，非破坏） |
| 3 前端类型重生成 | `pnpm --filter @bms/api-types run gen` | `identity.ts` 含 `/api/v1/auth/me` 与 `ApiResponse_UserSummary_` |
| 4 零漂移与门禁 | `contract_snapshot check` / `check_contracts`（四道）/ `api-types:gen:check` | 全绿 |

- **路由覆盖护栏注意**：`/auth/me` 为**受保护**端点（`include_in_schema=True`），会进入公开契约 `paths`，护栏 A 自动覆盖；**不得**加入任何白名单。
- **契约版本**：保持 `0.1.0`（兼容新增）。

### 3.4 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| org 侧 `pwd_reset_required` 列缺省值 | 模型列 `default=False`；DTO 缺省 `False`——存量行无值时为「不需强制改密」 |
| identity 内部 DTO（`OrgProfileUser`）未同步加字段 | 由契约快照与用例双向核对（字段缺失即用例失败） |
| 前端 `@bms/api-types` 未随契约重生成 | `api-types:gen:check` 阻断 |
| 端点被误加入公开路径白名单 | 契约门禁断言 B / D 与路由覆盖护栏拦截 |
| 未来新增「用户概要」字段 | 只需改 `UserProfileUser` + `_summary` + `UserSummary`（三处同源，契约自动同步） |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **新增端点**：`GET /api/v1/auth/me` 属**兼容新增**；网关 `public_paths` **不**放行该路径（受保护端点，由 `require_auth` 校验）。
- **org 响应加字段**：`UserProfileUser` 新增字段，既有消费方（identity SSO 回调 / JIT 建号）按模型解析不受影响。
- **前端**：`@bms/api-types` 新增 `/auth/me` 类型；域五 `05_02` 按其消费。
- **契约门禁**：四道断言全绿；oasdiff 基线仅新增。

## 7. 边界与开放项 <a id="boundary"></a>

- **用户上下文装载范围**：本端点只返回 `UserSummary`（展示与状态），**不含权限码 / 菜单**（RBAC 归阶段七）；首屏恢复后权限判定仍按空集处理（`01_05` / 域六口径）。
- **强制改密动作**：本端点只回显标记；改密页面与个人中心归阶段十五。
- **缓存**：`/auth/me` 不缓存（每次读 org + 库）；如出现首屏热点再评估（归性能阶段）。
- **访问审计**：读端点不落操作日志（归阶段八）。
- **SSO 会话**：SSO 登录用户的 `sub` 经映射后为本地用户 id，本端点同样适用（映射口径归域二）。
