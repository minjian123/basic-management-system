## 2. 实施过程 <a id="process"></a>

1. **立项与设计**：新增需求 01-6（域 01 计数 5 → 6）、新建子任务 `01_06`（与 `01_01`~`01_05` 平级）、父任务与需求总览与阶段计划表同步回写；落详细设计。定稿提交 `c5361cff`。
2. **Kiwi 登记**：经容器内 Django shell 登记 1 条策展用例，回读用例号 **2229**（标签「自动化」、`CONFIRMED`）；脚本临时文件用后即删。
3. **org 侧**：`UserProfileUser` 增 `pwd_reset_required: bool = False`；`_summary(row)` 增映射 `row.pwd_reset_required`（读既有持久列 `sys_user.pwd_reset_required`，**不重算策略**，与登录经凭据校验所得同源）。
4. **identity 内部 DTO**：`OrgProfileUser` 增 `pwd_reset_required: bool = False`（与 org 响应字段对齐）。
5. **identity 端点与服务**：新增 `CurrentUserService`（只依赖 org 客户端，**不占租户库会话**）与 `GET /api/v1/auth/me` 路由（`AuthDep` = `require_auth` + `AuthContext`，路由级声明 401 响应）；失败语义：缺 `user_id` / 用户不存在 → `AuthError`（20001/401），账号非 `enabled` → `AccountDisabledError`（20004/401），org 不可达 → `ServiceUnavailableError`（10007/503，由既有客户端 fail-closed）。
6. **契约与类型**：`contract_snapshot export`（identity +58 行 / org +6 行，**纯新增**）→ `baseline-update --service identity / org` → `@bms/api-types gen`（新增 `/api/v1/auth/me` 与 `ApiResponse_UserSummary_`）。
7. **消费方标注**：域五 `05_02` 任务文档补「前置契约（已交付 · 01_06）· 首屏用户概要」与依赖项；同步补「前置契约（已交付 · 06_03）· 响应契约完整」。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 | 归口 |
| --- | --- | --- | --- |
| 1 | `UserProfileUser` 不含强制改密标记，`/auth/me` 无法与登录响应口径一致 | 按拍板在 org 概要补 `pwd_reset_required`（读既有持久列，无需重算策略） | 本任务内闭环 |
| 2 | 测试替身 `FakeOrgClient` 未实现 org 概要动作（`profile` 路径返回空 `data`） | 补 `profile` 分派与 `_profile(user_id)` 构造（含 `pwd_reset_required`），与 org 真实响应形态对齐 | 本任务内闭环 |
| 3 | 「用户不存在 / 账号停用」返回码选择 | 取 **401**（`20001` / `20004`）而非 404——二者都意味着当前会话不应继续，401 使前端统一走会话失效路径，避免首屏恢复处按码分流（与域一 401 处理面口径一致）；已回写设计 §3.2 | 本任务内闭环 |
| 4 | `ruff format --check` 报 3 个文件需格式化 | 以 `ruff format` 修正（均为本任务改动文件） | 本任务内闭环 |
| 5 | 本机无 docker → oasdiff 无法本地复现 | 以快照差异核验替代（identity / org **纯新增**，零移除）；CI `contract-gate` 为权威门禁 | 推送后按需手动触发一次 |
