## 2. 任务内容 <a id="content"></a>

1. **端点**：identity 新增 `GET /api/v1/auth/me`（`require_auth`），返回 `ApiResponse[UserSummary]`；字段与登录响应**同字段、同语义**（`id` / `username` / `name` / `tenant` / `locale` / `timezone` / `must_change_password`）。
2. **改密标记同源**：org 内部 `users/profile` 响应补 `pwd_reset_required`（取用户行既有强制改密标记列，与凭据校验所得同源）；identity 直接映射为 `must_change_password`。
3. **数据通路**：经 `OrgCredentialClient.user_profile`（服务间契约面 + 自签服务 JWT + 租户位）取概要；下游不可达 / 响应非法按 `10007` / 503 fail-closed。
4. **失败语义**：用户不存在（`found=false`）或账号非 `enabled` → `20001` / 401（按登录态失效处理，前端走统一 401 路径清会话）；错误响应不泄露内部细节。
5. **契约与类型**：新端点进入 identity 公开契约快照；org 契约新增字段；oasdiff 基线按评审节点更新；前端 `@bms/api-types` 重生成并零漂移；契约四道门禁全绿。
6. **用例**：成功返回与登录响应一致；未登录 / 用户不存在 / 账号停用三类失败分支；org 概要含 `pwd_reset_required`。

## 3. 完成标准 <a id="accept"></a>

有效登录态下 `/auth/me` 返回与登录响应一致的用户概要（含强制改密标记）；未登录 / 用户不存在 / 账号停用均返回 401；org 内部 `users/profile` 响应含 `pwd_reset_required`；契约四道门禁与 `@bms/api-types` 零漂移全绿；`ruff`、`pyright`、定向 `pytest`、基座校验与 `preflight --fast` 全绿。
