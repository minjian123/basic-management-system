## 2. 任务内容 <a id="content"></a>

1. **口令哈希（PBKDF2）**：真实实现哈希 / 校验 / 「需重哈希」判定（算法与迭代参数升级自动重算），不引入新依赖。
2. **令牌编解码**：基于 joserfc 封装签发与验签（算法白名单 RS256 / ES256），多密钥并行轮换（`kid` 选择 + 新旧并行验证期）。
3. **会话黑名单**：refresh 一次性轮换（旧 `jti` 入 Redis 黑名单，短 TTL）、登出 / 踢出即时失效；键命名遵循《[命名规范](../../../../../规范/命名规范.md)》。
4. **配置定稿**：`[security]` 节定稿（access 30 分钟、refresh 14 天、算法与密钥来源走环境变量 / Secret），`config.{env}.toml` 与 `deploy/.env.example` 键位同步。
5. **口径回写**：《[安全开发规范](../../../../../规范/安全开发规范.md)》密码哈希表述由 bcrypt / argon2 改为 PBKDF2；《[后端基类清单](../../../../../后端基类清单.md)》安全基座条目状态更新；补《[概要设计 · 系统参数](../../../../../设计/概要设计/10_概要设计_系统参数.md)》「前端配置」节。
6. **用例与护栏**：哈希 / 编解码 / 轮换 / 黑名单单元用例；密钥不入库不入日志的静态检查沿用既有护栏。

## 3. 完成标准 <a id="accept"></a>

三类原语经依赖注入装配可用（哈希可校验、令牌可签可验、黑名单可命中）；密钥轮换期内新旧并行验签通过；`[security]` 与文档口径一致；含升级重哈希 / 轮换 / 失效分支的用例全绿；`pytest`、`pyright`、`ruff` 与基座校验通过。
