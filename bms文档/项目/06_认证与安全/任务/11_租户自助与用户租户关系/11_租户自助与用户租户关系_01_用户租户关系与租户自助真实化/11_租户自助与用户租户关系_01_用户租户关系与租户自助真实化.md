> **背景（2026-10-04 立项）**：架构 12 已交付「租户自助」契约与占位（`BaseTenantSelfService` 的 `my_tenants` / `switch` / `brand`；REST `GET /api/v1/tenants/mine`、`POST /api/v1/tenants/switch`），但实现是 **Null 占位**（固定单租户、不落库），且数据模型**没有**任何表承载「用户在哪些租户中」——`sys_user` 每租户一份、`username` 仅租户内唯一。跨租户功能（我加入的租户、切换、邀请加入、跨租户协作）因此**全部缺公共前置**，经拍板在本阶段补遗期内**提前**立项（架构 12 原计划归 RBAC 阶段）。

## 2. 任务内容 <a id="content"></a>

1. **关系模型（平台库 `bms_tenant`）**：新增用户↔租户关系表，记录「某租户内的某用户（组合键 `(租户 code, 用户 code)`）可访问的租户集合」；租户位存**雪花 `tenant_id`**；唯一约束覆盖 `(所属租户, 用户 code, 目标租户, deleted_at)`；带 `source`（来源）、`status`、审计字段与软删除。按《数据库开发规范》先改表文件 → 模型 → 迁移 → 状态两处回写。
2. **跨租户标识口径**：组合键 `(租户 code, 用户 code)`；**不引入**平台级账号 ID，**不假设**跨租户同名同人。
3. **写入路径全量覆盖**：租户开通建超管 / 管理员建号 / 批量导入 / SSO JIT 建号 / 自助注册 / 用户停用删除（回收）——**六条**写入全部同步维护关系；写入方与一致性口径（本地事务提交后同步服务调用 + 幂等 upsert + 读路径自愈 + 对账巡检）已在详细设计定稿，并落一致性巡检用例防漂移。
4. **读路径真实化**：`my_tenants` 返回可访问租户列表 + `current_code` + `multi_tenant`；`switch` 校验「目标租户 ∈ 当前用户可访问租户」并按既有语义返回生效方式（是否需重发令牌）；**解析链优先级不变**。
5. **数据边界**：关系表只承载「用户 ↔ 租户」可达性，不含角色 / 权限（RBAC 不在本条），不落 PII。
6. **不服务登录前判定**：关系表不得用于免认证链路账号反查；登录页 `20007` 语义见[需求 05-6](../../../需求/05_需求_登录前端.md#r05-6)。
7. **契约与门禁**：`/tenants/mine`、`/tenants/switch` 响应字段与新表进公开契约快照与 `@bms/api-types` 生成类型；契约四道门禁 + 数据库一致性校验全绿。
8. **用例与核对**：覆盖「单 / 多租户 `my_tenants`」「`switch` 命中与越权拒绝」「五条写入路径建立关系」「停用删除回收关系」「免认证链路无账号反查」；新增模块覆盖率达标。

## 3. 完成标准 <a id="accept"></a>

多租户用户的 `my_tenants` 能列出其可访问租户且 `multi_tenant=true`；`switch` 仅对可访问租户生效、越权目标被拒；**六条**写入路径均能建立 / 回收关系且无长期漂移；登录前链路无任何账号反查请求；契约四道门禁与数据库一致性校验全绿；后端 `pytest`、覆盖率门禁与 `preflight --fast` 全通过。
