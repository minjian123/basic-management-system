1. **建立上下文**：按《[AI开发规范](../../../../../../规范/AI开发规范.md)》「阅读顺序（动手前必读）」节顺序读本地资源 → 规划 → 规范 → 设计 → 项目 → 需求 → 任务 → 计划，并读相关架构节点：《[多租户路由](../../../../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》《[认证与会话](../../../../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》《[事件总线](../../../../../../设计/架构设计/16_架构设计_子系统_事件总线.md)》、数据库设计总览与表文件（`sys_outbox` / `sys_event_dead_letter` / `sys_user_identity` / `sys_tenant`）、《[后端开发规范](../../../../../../规范/后端开发规范.md)》命名节、《[后端基类清单](../../../../../../后端基类清单.md)》§10、[09_04 详细设计](../../../09_类体系根治理/09_类体系根治理_04_术语统一/设计/01_详细设计_04_术语统一.md)。
2. **现状检索（定向）**：并行调研三块——① 租户解析链与请求上下文（`TenantContext` / `TenantSnapshot` / `TenantLookup` / `TenantMiddleware` / `require_auth` / `current_tenant`）；② 令牌 claim 与事件 / 发件箱 / 缓存与限流键；③ 库键 / 库名派生与运维脚本。命中并核读 `db/keys.py`、`db/tenant.py`、`db/tenant_registry.py`、`oauth/user_jwt.py`、`oauth/jwt.py`、`oauth/token.py`、`events/base.py`、`events/platform_events.py`、`models/outbox.py`、`api/deps.py`、`core/context.py`、`session/base.py`、`cache/base.py`、`ratelimit/base.py` 等。
3. **决策确认**：用 `question` 工具逐项确认——首轮 10 项（库键 / 库名落点、令牌 claim 范围、claim 值形态、旧令牌兼容、DB 列迁移、会话键、事件负载键、网关注入头、`tenant_id` 缺失兜底、迁移窗口），跟进 3 项（对照表设计、库键解析与改名策略、`idp_key` 前缀）。
4. **落详细设计**：按《[文档生成规范](../../../../../../规范/文档生成规范.md)》落 `设计/01_详细设计_01_详细设计与口径定稿.md`——目标与口径依据、改造基线、库键 / 对照表、边界解析、令牌、命名对齐清单、迁移与兼容、测试设计与验收映射、登记落点、相邻任务边界、开放项、对齐记录。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 处置 |
| --- | --- | --- |
| 1 | 现状「令牌 claim 名为 `tenant_id`、值实为 code」「请求态 `state["tenant_id"]` 无生产写入」 | 设计明确 claim 值改雪花 id、`state["tenant_id"]` 语义修正并在认证后写入（§5、§6.1） |
| 2 | 库键 / 库名是否改 id：改则运维不可读 + 全量改名，不改则 code 复用有物理串号风险 | 确认「保持 code 派生 + 新增对照表 `sys_tenant_database`」，库键定位为运维命名、身份仍以 `tenant_id` 为准（§3） |
| 3 | 09_04 曾定「事件负载键 `tenant_code` 保持不变并有断言」 | 本域口径 9 覆盖之（负载键改 `tenant_id`）；10_03 须回写 09_04 相关用例断言（§10） |
| 4 | 网关 / 边缘 `X-Tenant-Id` 与客户端同名头冲突 | 确认保持 code（外部 / 边界语义一致），introspect 由令牌 id 解析为 code 后注入（§5） |
| 5 | 旧令牌 / 旧会话兼容成本 | 确认现阶段（新建库新建数据）不设兼容窗口，接受一次强制重登（§1.1、§7） |
