## 1. 域说明 <a id="intro"></a>

把**内部租户标识**由 `code` 改为雪花 `id`：对外接口仍以 `code` 表达，边界做一次可缓存的 `code → id` 解析，内部链路（请求上下文 / 令牌 claim / 事件信封 / 发件箱 / 身份映射表 / 请求态 / 缓存与限流键）统一携带 `tenant_id`。

- **覆盖范围**：需求 [10-1](../../需求/10_需求_租户标识内部化.md#r10-1)（租户标识内部化）——边界解析、内部标识改造、库键 / 库名评估、DB 列迁移与兼容窗口、命名对齐。
- **端范围**：**后端为主**（`bms_core` 解析链 / 令牌 / 事件与发件箱 / 数据访问 / 缓存与限流；identity / tenant 服务与运维脚本）+ **数据库**（迁移与表文件）+ **运维脚本**（建库 / 迁移 / 初始化）。
- **承接口径**：租户解析链（子域名 → 请求头 → token）、`TenantContext`（已同时携带 `code` 与 `tenant_id`）、`TenantSnapshot`、租户源与缓存已交付；本域只**换内部标识**，不重写解析 / 取数语义。
- **已定口径**（2026-09-28 拍板，见[需求域说明](../../需求/10_需求_租户标识内部化.md#intro)）：对外仍用 `code`；内部以雪花 `tenant_id` 为准；边界一次 `code → id` 解析；命名按值（`tenant_id`=雪花主键、`tenant_code`=租户业务编码）；迁移与兼容窗口；库键 / 库名落点由详细设计定。
- **依据**：《[架构设计 · 多租户路由](../../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》、《[架构设计 · 事件总线](../../../../设计/架构设计/16_架构设计_子系统_事件总线.md)》、《[后端开发规范](../../../../规范/后端开发规范.md)》命名节。
- **执行序**：`10_01 详细设计与口径定稿` → `10_02 令牌与请求态（含边界解析）` → `10_03 事件 / 发件箱 / 缓存与限流键` → `10_04 DB 列迁移与模型` → `10_05 收口回归与记录`。

## 3. 工时与依赖 <a id="effort"></a>

- **工时合计**：64h（估算，待详细设计确认）。
