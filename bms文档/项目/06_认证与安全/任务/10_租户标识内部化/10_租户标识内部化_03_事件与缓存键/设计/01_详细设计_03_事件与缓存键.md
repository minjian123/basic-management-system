**不涉及**：令牌与请求态键（10_02 已交付）；DB 列迁移与模型（10_04）；`sys_tenant_database` 对照表落表（10_04）；无租户位的既有键（短信验证码限流 / 服务间调用限流 / 文件上传幂等 / 引擎创建全局锁）**不扩租户位**（维持现状）。

## 3. 接口与字段边界 <a id="contract"></a>

### 3.1 事件契约（负载与版本） <a id="event-contract"></a>

| 项 | 口径 |
| --- | --- |
| 负载键常量 | `TENANT_CODE_PAYLOAD_KEY = "tenant_code"` **退场**；新增 `TENANT_ID_PAYLOAD_KEY = "tenant_id"`（事件侧单一来源） |
| 租户事件负载 | `tenant.created` / `tenant.suspended` / `tenant.activated`：`tenant_code`（string 必填）→ **`tenant_id`（string 必填，雪花 id 十进制字符串）**；`db_key` / `status` 保留（`db_key` 值语义为 `tenant_{db_basis}`，取数落点随租户发布方实现） |
| 契约版本 | 三条租户事件 **`1.0.0` → `2.0.0`**（破坏性变更升主版本）；其余 20 条保持 `1.0.0` |
| 信封保留键 | `RESERVED_PAYLOAD_KEYS` **移除 `tenant_id`**（信封与负载租户位同名同值属统一表达）；其余 6 键（`event_id` / `event_type` / `event_version` / `occurred_at` / `trace_id` / `aggregate_key`）保留 |
| 事件信封 | `EventEnvelope.tenant_id`：值 = 雪花 id 十进制字符串（类型 `str \| None` 不变；平台链 / 审计等无租户事件可空） |
| 发件箱记录 | `OutboxRecord.tenant_id` / `DeadLetterRecord.tenant_id`：值语义同为雪花 id 字符串（类型不变；`sys_outbox` / `sys_event_dead_letter` 列类型归 10_04） |
| Saga 事件 | `build_saga_event(tenant_id=…)`：入参语义为雪花 id 字符串（签名不变，文档对齐） |

### 3.2 契约兼容规则（`check_event_compatibility`） <a id="compat"></a>

**置信规则：主版本严格升级（`current.major > previous.major`）时，破坏性字段变更合法**；主版本内（次 / 补丁升级）维持现行全部限制：

| 变更 | 主版本内（现行） | 主版本严格升级（新增出口） |
| --- | --- | --- |
| 删除字段 | 违规「字段只增不删，禁止删除」 | 允许（不再报违规） |
| 字段类型变更 | 违规「字段类型变更属破坏性」 | 允许 |
| 字段必填性变更 | 违规「字段必填性变更属破坏性」 | 允许 |
| 新增字段必填 | 违规「新增字段必须可选」 | 允许 |
| 新增字段可选 | 允许（至少升次版本） | 允许（无需强制升次版本的判定自然满足） |
| 弃用标记回退 | 违规 | 违规（不豁免） |
| 版本回退 / 版本格式非法 / 事件类型不一致 | 违规 | 违规（不豁免） |

- 实现：破坏性违规判定受 `major_upgraded` 控制（主版本内照旧 append 违规；主版本升级时跳过 append、仅保留 `breaking` 标记供既有「必须升主版本」分支判定——该分支在已升主版本时自然不触发）。
- 订阅覆盖校验（`check_subscription_coverage`）不变：主版本升级时登记的消费方订阅须覆盖新主版本；本仓库订阅清单当前为空，产品仓库消费方按「前置契约」协调（见 §7）。
- **失败分支**：主版本内删除 / 改类型 / 增必填仍由校验拦截；事件类型删除仍拒（须置 `deprecated=True`）；快照与注册表漂移由 `ops.event_contracts check` 拦截。

### 3.3 缓存 / 限流 / 幂等 / 锁键 <a id="keys"></a>

**内部键租户位取值**：雪花 id 十进制字符串；无 id（演示兜底 / 无上下文）→ `None` → 键落 `global`（口径 10_01 §4.1「演示租户不参与内部 id 键」）。

| 载体 | 形态（改后） | 调用点与落点 |
| --- | --- | --- |
| 缓存键 | `bms:{tenant_id}:{域}:{键}` | dict：`bms_core/dict/sql.py`（按类型 / 批量 / 翻译 3 处）、`dict/service.py`（失效）；config：`bms_core/config/sql.py`、`config/service.py` |
| 限流键 | `bms:{tenant_id}:rate:{维度}:{目标}` | 登录（IP / 账号 / 失败计数）、SSO authorize（IP / client）、找回密码（IP / 标识 / 用户）、IdP 连通性测试、SQL 试算（平台 codecheck） |
| 幂等键 | `bms:{tenant_id}:idem:{键}` | 平台 icon（增 / 改 / 删）、租户 switch、报表导出 / 批量打印 |
| 锁键 | `bms:{tenant_id}:lock:{资源}` | JIT 建号锁已用 id（10_02）；`db/registry.py` 引擎创建锁为全局；**本任务无 code → id 的锁调用点** |
| 会话 / IdP state 键 | 10_02 已改 id | 不重复 |

**服务层助手**：`bms_core/db/tenant.py` 新增 `current_tenant_id_str()` —— 完整租户上下文（含解析链产出的雪花主键）优先，回落请求上下文变量；无主键返回 `None`（供 dict / config 等不走路由层级函数注入的服务层复用，避免 `api/deps` 反向依赖）。

**IdP 连通性测试 target**：`f"{tenant_id}:{actor}"`（target 与键租户位均改 id，管理接口经认证上下文必有 id，缺失按 `AuthError` 拒绝）。

**路由层调用点**：`current_code_of(tenant)` → `current_tenant_id_of(tenant)`（键租户位）；`my_tenants(current_code=…)` 等**对外展示 / 业务参数保持 code**。

**失败分支**：调用点漏改（仍以 code 构造内部键）由定向用例的键形态断言拦截；`tenant_id` 缺失（演示兜底）按 `global` 处理（既有语义）。

## 8. 边界与开放项 <a id="open"></a>

- **产品仓库消费方兼容**：契约快照与登记就位；产品侧订阅声明（`supported_majors` 含 2）随其消费方实现落地，本任务不做跨仓库改动。
- **事件发布方（tenant 服务）**：三条租户事件尚无生产发布代码；契约已按 `2.0.0` 声明，发布实现落地时按新负载键构造（`tenant_id` = 雪花 id）。
- **无租户位键**：短信验证码 / 服务间调用限流、文件上传幂等、引擎创建全局锁维持现状（不在本任务「code → id」范围）。
- **`sys_event_consumed` 无租户列**：维持（每库隔离；10_01 §11 已登记）。
- **契约快照兼容窗口**：窗口期内已投递旧事件（`event_version=1.0.0`、负载 `tenant_code`）与新事件（`2.0.0`）并存；消费方按主版本订阅兼容（真实消费随 集成消息）。
