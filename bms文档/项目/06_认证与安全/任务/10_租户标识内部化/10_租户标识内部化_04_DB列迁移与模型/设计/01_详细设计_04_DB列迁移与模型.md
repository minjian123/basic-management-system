## 3. 表结构变更（先改表文件） <a id="tables"></a>

### 3.1 新增表 `sys_tenant_database` <a id="new-table"></a>

| 字段 | 类型 | 可空 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 否 | 主键，雪花 ID | 主键 |
| `tenant_id` | BIGINT | 否 | —（同库逻辑外键 → `sys_tenant.id`） | 租户主键（雪花 ID） |
| `db_basis` | VARCHAR(64) | 否 | — | 库名基（创建时冻结的租户编码，稳定不可变） |
| 公共字段 | — | — | 继承 `BaseModel` | `created_at` / `created_by` / `updated_at` / `updated_by` / `deleted_at` / `version` |

- 唯一约束：`(tenant_id, deleted_at)` 复合唯一（软删除后可重挂），名 `uq_sys_tenant_database_tenant_deleted_at`；
- 无业务普通索引（仅公共软删除索引 `idx_sys_tenant_database_deleted_at`）；无物理外键；
- 归属库：平台服务库 `bms_tenant`（归属服务 `tenant`，与 `sys_tenant` 同库）；一租户一行、各服务共享同一基。

### 3.2 三表列类型变更 <a id="alter"></a>

| 表 | 字段 | 改造前 | 改造后 | 可空 |
| --- | --- | --- | --- | --- |
| `sys_outbox` | `tenant_id` | VARCHAR(64) | **BIGINT** | 是（平台链不可解析保持 NULL） |
| `sys_event_dead_letter` | `tenant_id` | VARCHAR(64) | **BIGINT** | 是（同上） |
| `sys_user_identity` | `tenant_id` | VARCHAR(64) | **BIGINT** | 否 |
| `sys_user_identity` | `idp_key` | `{tenant_code}:{provider_key}` | `{tenant_id}:{provider_key}`（仅值前缀变更，列类型 / 长度不变，VARCHAR(160) 足够） | 否 |

### 3.3 既有缺口补齐（发件箱三表） <a id="gap-fill"></a>

`identity:platform` / `identity:tenant` / `org:tenant` 三链迁移脚本从未建发件箱三表，与《数据库设计总览》表归属登记（`sys_outbox` / `sys_event_consumed` / `sys_event_dead_letter` 为 `OWNER_EVERY_SERVICE` + `BOTH`）不一致。本次在三链各自链尾补建三表（结构按现模型，`tenant_id` 直接为 `BIGINT`），使有脚本链全部零漂移。

### 3.4 变更记录 <a id="revlog"></a>

- 四张表文件「变更记录」各追加一行（v2：`tenant_id` 改 `BIGINT` / 新增对照表），与 Alembic 迁移一一对应；
- 总览「已设计数据表登记」新增 `sys_tenant_database`（状态 `已落库`），并核对三表状态仍为 `已落库`。

## 4. ORM 模型 <a id="models"></a>

- **新增** `bms_tenant/models/tenant_database.py::SysTenantDatabase(BaseModel)`：`__tablename__ = "sys_tenant_database"`；`tenant_id: Mapped[int] = mapped_column(BigInteger, comment=…)`；`db_basis: Mapped[str] = mapped_column(String(64), comment=…)`；`UniqueConstraint("tenant_id", "deleted_at", name="uq_sys_tenant_database_tenant_deleted_at")`；追加进 `bms_tenant/models/__init__.py::MODEL_MODULES`（否则链不导入、自动建表不带）。
- **改类型**：

| --- | --- | --- | --- | --- |

| 2 | `platform:tenant` | `alembic/versions/platform/tenant/` | `0005_sys_outbox_tenant_id_bigint`（`0004_sys_config`） | 同上 |

| 5 | `tenant:tenant` | `alembic/versions/tenant/tenant/` | `0003_sys_outbox_tenant_id_bigint`（`0002_sys_outbox_event_version`） | 同上 |

**实现要点**：

- 迁移脚本内**不写方言 SQL**（一套脚本三库执行）；`sys_tenant_database` 回填用参数化绑定（时间取 Python 侧 `datetime.now(UTC)`，雪花 `id` 取 `bms_core.core.id.id_generator.next_id`，禁止数据库端时间函数）；
- `sys_tenant_database` 回填：`SELECT id, code FROM sys_tenant WHERE deleted_at IS NULL` → 逐行 `INSERT`（`tenant_id=id`、`db_basis=code`）；重复执行由 `uq` 兜底（幂等重建库场景）；
- 改类型的迁移在**存量已回填为数字串**后执行（执行序见第 6 节），空库 / 新建库为空操作；
- 降级：`batch.alter_column(type_=String(64), existing_type=BigInteger)`；`sys_tenant_database` `drop_table`。

## 6. 存量回填（独立幂等 ops 脚本） <a id="backfill"></a>

**形态**：结构与数据分离——迁移脚本只改类型；`code → id` 回填与 `idp_key` 前缀重写由新增 `ops/backfill_tenant_id_columns.py` 承载（幂等、可重复；符合《数据库开发规范》「数据变更单独脚本」）。

**停机窗口执行序**：**① 全库备份 → ② 回填脚本（`code → id` 归一为数字串）→ ③ `ops.migrate_tenants`（列类型变更）→ ④ 代码上线 → ⑤ 冒烟**。空库 / 新建库场景②为空操作。

**脚本行为**：

1. 读租户注册库 `sys_tenant`（键 `platform_tenant`）构建 `code → id` 映射（未软删）；
2. **`sys_user_identity`（identity 平台库）**：`tenant_id`（code）→ id；`idp_key` 前缀 `{code}` → `{id}`；**不可解析即报错中止并列出 `(表, 主键, 原值)` 明细**（列非空、不可置 NULL）；
3. **`sys_outbox` / `sys_event_dead_letter`（各服务平台库 + 各租户库）**：`tenant_id`（code）→ id；平台链不可解析的租户位按 10_01 §7.2 **置 NULL**（不阻断），租户链不可解析即报错中止；
4. 目标库枚举复用 `ops.migrate_tenants` 的服务 × 数据源 × 租户编排内核；`--dry-run` 只打印计划；`--url` / `--db-key` 支持单库演练；
5. 幂等：已是数字串（id）的行跳过；重复执行输出 0 变更。

**失败分支**：注册库不可读 / 无法构造映射 → 退出码 1；不可解析行按上述分表处置。

## 8. 方言差异实测 <a id="dialect"></a>

在 MySQL 8 / PostgreSQL 16 / 达梦 DM8 真库执行「VARCHAR(64) → BIGINT 列类型变更 + 新表 `sys_tenant_database` + `idp_key` 前缀重写」迁移实测，结论标「**实测**」并回写三份方言特性文档：

- `ALTER` 语句形态（MySQL `MODIFY` / PostgreSQL `ALTER … TYPE … USING`（需显式 `USING tenant_id::bigint`）/ 达梦 `MODIFY`）；
- 存量数字串转换可行性；非数字串（code）在改类型前的必须归一；
- 新表 / 唯一约束在各方言的 DDL 落点；
- 未实测项标「待验」。

## 12. 边界与开放项 <a id="open"></a>

- **存量回填与迁移的跨库性**：`sys_tenant`（`bms_tenant`）与目标三表分属不同库，回填不能内嵌单个 Alembic 脚本；已按「结构 / 数据分离」落为独立幂等脚本（本任务定案）。
- **`sys_event_consumed` 无租户列**：维持（10_01 §11）；其后端列与回填无涉。
- **库键 code 段为 `db_basis`**：`sys_tenant` 无 `db_basis` 列，库名基存于 `sys_tenant_database`；`sys_tenant.db_key` 废弃列物理删列另立任务。
- **`identity:platform` 等三链缺口**：本次补齐发件箱三表；若后续有服务首建链，其脚本须包含基础设施表（由 `chain_tables` / 零漂移门禁断言）。
- **回填脚本一次性**：停机窗口执行后保留为运维工具（幂等），不随常规迁移链运行。
