## 3. 实施过程 <a id="process"></a>

1. **表文件先行**：新建 `sys_tenant_database.md`（`tenant_id` BIGINT + `db_basis` VARCHAR(64) + `(tenant_id, deleted_at)` 复合唯一）；`sys_outbox` / `sys_event_dead_letter` / `sys_user_identity` 三表 `tenant_id` 由 `VARCHAR(64)` 改 `BIGINT`（`idp_key` 值前缀改 `{tenant_id}`），各追加「变更记录」；《数据库设计总览》「已设计数据表登记」新增对照表行。
2. **ORM 模型**：新增 `bms_tenant/models/tenant_database.py::SysTenantDatabase` 并注册进 `MODEL_MODULES`；`bms_core/models/outbox.py` 两表 `tenant_id` 改 `BigInteger`（可空保持）；`bms_identity/models/user_identity.py` `tenant_id` 改 `BigInteger`（非空保持）；`TABLE_OWNERSHIP` 登记 `sys_tenant_database`（`tenant` / `platform`）。
3. **Alembic 迁移（9 个 revision，分链）**：三表列类型变更落 `platform:platform 0006` / `platform:tenant 0005` / `tenant:platform 0005` / `tenant:tenant 0003` / `identity:platform 0003`；对照表落 `tenant:platform 0004`（含存量租户回填 `db_basis=当前 code`）；缺口补齐落 `identity:platform 0002` / `identity:tenant 0004` / `org:tenant 0005`（建发件箱三表）。
4. **存量回填（结构与数据分离）**：新增 `ops/backfill_tenant_id_columns.py`——读注册库构建 `code → id` 映射，`sys_user_identity` 改 `tenant_id` 并重写 `idp_key` 前缀（不可解析中止并列明细），发件箱 / 死信按库类别严格 / 置 NULL；幂等、`--dry-run`、缺库跳过。停机窗口执行序「先回填、后迁移」。
5. **`db_basis` 真实取数**：租户源 `_load` 左联对照表取 `db_basis`（缺行回落 code 记 WARNING）；只读契约 `db_basis` 经仓储取数；仓储 `create` 同事务写 `sys_tenant` + `sys_tenant_database`；`seed_tenant` 补写对照行；`migrate_tenants` / `provision_tenant` / `init_tenant` 库键改按 `db_basis` 派生（显式 `--code` 模式经对照表补基、注册库不可读回落 code）。
6. **同口径收口**：发件箱存储 `_to_record` / `_to_dead_record` 将 BIGINT 列值转回信封口径字符串、`enqueue` 将信封字符串转列值（`_tenant_id_str` / `_tenant_id_col`）；SSO 回调映射行租户比较改 `str(mapping.tenant_id)`；`sso:bind` 契约载荷 `str(row.tenant_id)`（契约字段仍为字符串，不变更公开契约）；`build_tenant_db_key` / `tenant_database_name` 入参语义收紧为库名基。
7. **测试与门禁**：链头断言与 `test_migration_ops` revision 断言更新；`test_alembic_drift` 改为**全链参数化**（全部有脚本链）；新增回填用例（Kiwi 2219）；租户源新增 `db_basis` 稳定解析用例；受影响测试批量更新。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 处置 |
| --- | --- | --- |
| 1 | PostgreSQL 改类型报 `DatatypeMismatch: column "tenant_id" cannot be cast automatically to type bigint`（真库实测） | 迁移 `alter_column` 加 `postgresql_using="tenant_id::bigint"`（Alembic 方言参数，非脚本内方言 SQL）；回写 PG 方言文档 |
| 2 | revision 标识超 32 字符：MySQL 报 `Data too long for column 'version_num'`、PostgreSQL 报 `value too long for type character varying(32)`（真库实测） | 标识统一缩短为 `…_outbox_tenant_bigint` / `…_user_identity_bigint`（≤32 字符），文件名 / 引用 / 测试断言同步 |
| 3 | 达梦改类型报语法错：Alembic 默认生成 PostgreSQL 式 `ALTER COLUMN … TYPE`，达梦不支持（真库实测） | `alembic/env.py` 注册 `@compiles(ColumnType, "dm")` 生成 `ALTER TABLE … MODIFY <列> <类型>`（达梦实测 `MODIFY` 可用）；回写 DM 方言文档 |
| 4 | 达梦增量迁移报「对象 `ALEMBIC_VERSION` 已存在」：达梦方言 `has_table` 不认会话 `SET SCHEMA` 后的当前模式（真库实测：不带 `schema=` 返回 False） | `alembic/env.py` 的 `context.configure` 加 `version_table_schema=<模式>` 显式限定版本表；经用户拍板本次一并修复 |
| 5 | 达梦对可空性 / 注释变更无编译处理器（`ALTER COLUMN … DROP NOT NULL` 语法错、`ColumnComment` 无 `dm` 处理器）（真库实测） | 迁移只改列类型（不传可空性 / 注释参数；原可空性不变）；库内注释保持原值；回写 DM 方言文档「可空性与注释变更」条 |
| 6 | 全链零漂移门禁暴露既有缺口：`identity:platform` / `identity:tenant` / `org:tenant` 三链未建发件箱三表（与归属登记不一致，`identity:platform` 差异 9 项） | 经用户拍板一并补齐（三链各加迁移建三表），全部有脚本链纳入零漂移 |
| 7 | `sys_outbox` / 死信 ORM `tenant_id` 改 BIGINT 后，记录对象（信封口径字符串）与列值类型不一致 | `outbox/store.py` 增 `_tenant_id_str`（列 → 记录）与 `_tenant_id_col`（记录 → 列）双向转换；相关测试租户位由 `"t1"` 改数字串 |
| 8 | SSO 回调映射命中判定 `mapping.tenant_id == flow.tenant_id` 因列值改 int 失效（403） | 改 `str(mapping.tenant_id) == flow.tenant_id`；`sso:bind` 载荷 `str(row.tenant_id)`（契约不变） |
| 9 | `seed_tenant` 增写对照行后，既有测试「新增 2 行」与总数断言变化 | 断言更新为「租户 + 对照行」合计；补对照行计数断言 |
| 10 | 租户源左联对照表后，`test_tenant_source` 夹具缺表致查询失败 | 夹具同建 `sys_tenant_database` 并写入对照行；新增「改名租户库键稳定」用例 |
| 11 | 新代码触发裸无序集合护栏（新签名 `list` / `dict`、dataclass 字段 `list`） | 新签名改 `Sequence` / `Mapping`、统计字段改 `tuple`；`--update-baseline` 递减 6 条基线并保持通过 |
| 12 | `ops.test_db.drop` 无 `password` 参数（演练脚本调用错误） | 仅在 `create` 传测试密码；`drop` 依赖管理员连接串（临时演练脚本修正，不入库） |

## 6. 偏差与遗留 <a id="deviations"></a>

- **偏差**：
  - **范围扩展（经拍板）**：原设计只列三表列迁移 + 对照表；因全链零漂移门禁暴露 `identity:platform` / `identity:tenant` / `org:tenant` 三链发件箱三表缺口，一并补齐；因达梦增量迁移基座缺陷（版本表模式 / `MODIFY` 编译）阻断 DM 实测，一并修复 `alembic/env.py`（用户 2026-09-29 拍板）。
  - **迁移只改列类型**：不改可空性与注释（达梦无对应编译处理器；原可空性不变、库内注释保持原值），与设计「附注释更新」的预期有落差，已回写设计 §5 实现要点。
  - **回填脚本未随迁移链执行**：按「结构与数据分离」为独立一次性 ops 工具（设计已定），不随 `migrate_tenants` 常规运行。
  - **`prettier`/`frontend` 未涉及**：本任务为后端 + 数据库侧，前端 `api-types` 无变更（`sso:bind` 载荷仍为字符串）。
- **遗留**：
  - 收口回归与覆盖率门槛 → **10_05**；
  - 产品仓库跨服务事件消费方「前置契约（已交付）」标注（事件负载键 `tenant_id` 主版本升级）→ **消费方实现时按其任务文档补**（计划 §3.1 已登记，10_03 起承接，本任务无新增）；
  - 达梦列注释变更（`ColumnComment` 无 `dm` 编译处理器）→ **后续如需变更注释时评估**（方言文档已标「待验」）；
  - `sys_tenant.db_key` 废弃列物理删列、`sys_event_consumed` 是否加租户列 → 维持 10_01 开放项口径（另立任务 / 后续评估）。
