## 3. 三库真库方言实测（增量迁移） <a id="dialect"></a>

**方法**（每方言 3 项 drill，均为「先迁到前置 revision → 插入存量数字串行 → 增量迁到 head → 校验列类型与值」，覆盖「既有库上改类型」的真实场景；复用 `ops/test_db.py` 建 / 删测试对象）：

| drill | 链 | 覆盖 |
| --- | --- | --- |
| A | `platform:tenant` | 发件箱 / 死信 `tenant_id` `VARCHAR(64) → BIGINT`（带存量行） |
| B | `tenant:platform` | 新表 `sys_tenant_database` + 存量租户回填 `db_basis=当前 code` + 发件箱改类型 |
| C | `identity:platform` | 缺口补齐（建发件箱三表）+ `sys_user_identity.tenant_id` 改 BIGINT（带存量行） |

**结果（2026-09-29，MySQL 8 / PostgreSQL 16 / DM8 各 3 项全通过）**：

| 方言 | 列类型变更 DDL 落点 | 结果 |
| --- | --- | --- |
| MySQL 8 | `ALTER TABLE … MODIFY`（`batch_alter_table` 生成）；`alembic_version` revision ≤ 32 字符 | A / B / C 通过（存量值保真） |
| PostgreSQL 16 | 须 `postgresql_using="tenant_id::bigint"`；否则 `DatatypeMismatch` | A / B / C 通过（存量值保真） |
| 达梦 DM8 | 需 `ALTER TABLE … MODIFY`（`alembic/env.py` 注册 `ColumnType` 的 `dm` 编译补丁）；版本表以 `version_table_schema` 限定（`has_table` 不认 `SET SCHEMA`） | A / B / C 通过（存量值保真；增量迁移修复后可用） |

**实测发现并已修复的方言问题**（详见实施记录 §4，结论已回写三份方言特性文档）：PostgreSQL `USING`、revision 标识长度上限、达梦 `MODIFY` 编译补丁、达梦版本表模式、达梦可空性 / 注释变更限制。
