## 2. 任务内容 <a id="content"></a>

1. **租户标识默认隐藏**：登录页默认**不渲染**租户标识输入框；提交时按「本机已记住的租户编码（有则静默带上，不显示该项）→ 域名 / 请求头 → 唯一启用租户」解析；**不做任何前端预判**，也不新增免登录部署信息接口。
2. **未提供租户时的解析语义**：`POST /auth/login` 未解析到租户（子域名 / `X-Tenant-ID` / 请求体均无）时——恰好 **1 个启用租户** → 采用该租户继续登录；**≥ 2 个启用租户** → 返回认证段错误码 **`20007`（需要选择租户）**；**0 个启用租户** → 沿用既有失败语义。
3. **`20007` 不带租户列表**：仅作「请填写租户标识」提示，`data` 为空——不返回租户清单（不暴露租户目录、也无法按账号反查）。
4. **错误码登记**：`20007` 进 `bms_core/core/error_codes.py`、公开契约与核心前端文案表 `AUTH_ERROR_TEXTS`，文案「请填写租户标识（当前部署存在多个租户）」。
5. **验证码口径**：`20007` 在**解析租户阶段**返回（早于验证码与凭据校验）——**不消费**挑战、不计失败；前端保留验证码块状态与输入，仅提示补充租户标识后重提。
6. **前端接入（`20007` 触发展开）**：收到 `20007` → **展开**租户标识输入框并聚焦，表单级提示「请填写租户标识」；填写后再次提交即完成登录。单租户 / 子域名部署下该项**永不出现**。
7. **契约与门禁**：`20007` 进 identity 公开契约快照、契约快照基线与 `@bms/api-types` 生成类型（零漂移由既有门禁保证）；前端按生成类型消费，不手写重复类型。
8. **用例与核对**：后端覆盖「单启用租户留空直登 / 多启用租户返回 `20007` / `20007` 不消费验证码 / 凭据错误仍 `20002`」；前端覆盖「**默认隐藏** / 本机记忆静默携带 / 留空提交 / 收到 `20007` 触发展开与聚焦 / 与验证码块联动」；宿主核对页补自检项。

## 3. 完成标准 <a id="accept"></a>

单租户部署或子域名部署下**不出现**租户标识输入框、留空提交即可直接登录；多租户同域部署下留空提交返回 `20007` 且**不消费验证码**，前端展开输入框、填写后提交成功；本机已记住租户编码时静默带上且不显示该项；登录前**无任何**按账号查询租户 / 账号存在性的请求；`20007` 响应体不含租户清单；契约四道门禁全绿且生成类型含 `20007`；`vue-tsc`、ESLint、Vitest 与后端 `pytest` 全通过。
