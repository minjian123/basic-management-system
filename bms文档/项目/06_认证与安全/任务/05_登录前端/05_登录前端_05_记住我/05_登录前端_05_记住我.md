> **背景（2026-10-02 立项）**：需求 [05-1](../../../需求/05_需求_登录前端.md#r05-1) 原列「记住我」，但后端 `LoginRequest` 无该字段、refresh 有效期由 `[security]` 统一控制——`05_01` 实施期发现该缺口，经拍板**另立本条**：先补后端登录契约与保留时长策略，再接入前端开关；`05_01` 本轮不渲染该开关。

## 2. 任务内容 <a id="content"></a>

1. **登录契约扩展**：`LoginRequest` 增可选 `remember_me`（布尔，缺省 `false`，只增不删）；未携带时行为与本任务落地前完全一致。
2. **保留时长策略**：`remember_me=false` → refresh **会话级**（浏览器会话结束即失效）；`remember_me=true` → refresh **14 天滚动轮换**（现行口径）。
3. **会话侧对齐**：`sys_session.expires_at` 与 Redis 会话标记 TTL 随选项取值对齐；refresh 轮换保持会话 id 稳定；登出 / 踢出清理口径不变。
4. **前端接入**：登录页表单恢复「记住我」勾选项（缺省不勾选），随登录请求提交；口径成文（不落 access、不变更 access 有效期）。
5. **契约与门禁**：新字段进入 identity 公开契约快照、oasdiff 基线与 `@bms/api-types` 生成类型（零漂移由既有门禁保证）。
6. **安全口径**：勾选仅延长 refresh 有效期，不改变 Cookie 的 `HttpOnly` / `Secure` / `SameSite` 与 `Path` 收敛口径。
7. **用例与核对**：后端用例覆盖会话级与 14 天两分支；前端组件用例 + 核对页覆盖勾选项提交；`vue-tsc`、ESLint、Vitest 门禁。

## 3. 完成标准 <a id="accept"></a>

勾选与不勾选两种登录在刷新后表现为不同的 refresh 有效期（用例覆盖会话级与 14 天两分支）；契约四道门禁全绿且生成类型含 `remember_me`；登录页勾选项随请求提交且文案与口径一致；`vue-tsc`、ESLint、Vitest 全通过。
