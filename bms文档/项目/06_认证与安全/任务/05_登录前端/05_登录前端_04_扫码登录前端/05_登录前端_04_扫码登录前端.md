## 2. 任务内容 <a id="content"></a>

1. **二维码与轮询**：经二维码件渲染授权二维码（企微 / 钉钉），按间隔轮询授权状态（待扫 / 已扫待确认 / 已确认 / 过期）；过期自动刷新、轮询错误退避。
2. **换取会话**：授权确认后调用后端免登回调 / 换取接口（域 `02_04` 提供），成功后装载用户上下文（复用 `05_02` / `05_03` 链路）。
3. **状态机与体验**：二维码状态可视反馈（遮罩 / 刷新按钮 / 提示文案）；页面隐藏时经可见性 API 暂停轮询。
4. **联调口径**：企业真实凭据就绪时完成一次 PC 扫码登录 E2E；未就绪以测试夹具覆盖状态机并登记遗留（同域 `02_04` 口径）。
5. **用例**：四态状态机、过期刷新、退避、换取成功与失败。

## 3. 完成标准 <a id="accept"></a>

扫码状态机四态均可用（含过期刷新与退避）；授权确认后成功换取会话进入系统；真实凭据未就绪时状态机用例全绿且遗留登记；`vue-tsc`、ESLint、Vitest 全通过。

> **前置契约（已交付 · 02_04，2026-09-27）**：后端已冻结三段契约——`GET /auth/sso/providers` 按 `type`（`wecom` / `dingtalk`）区分入口；`GET /auth/sso/{idp_key}/authorize-url` 返回 `authorize_url` / `state` / `expires_in`（供渲染二维码 / 初始化平台内嵌登录组件，授权 URL 内已含平台参数）；用户确认后回跳 `GET /auth/sso/{idp_key}/callback` 由后端完成换身份、JIT 与会话签发。**轮询状态机（待扫 / 已扫待确认 / 已确认 / 过期）与换取会话由本任务前端按平台页面细化**——后端不做轮询状态机与会话旁路存储；真实企业凭据联调归阶段十七。

> **前置契约（已交付 · 06_01）· 契约类型**：认证端点已全部进入 identity 公开契约快照（需求 06-1），扫码链路的 SSO 端点（`/auth/sso/providers`、`/auth/sso/{idp_key}/authorize-url`）按 `@bms/api-types` 的 `identity` 命名空间生成类型消费（`import type { identity } from "@bms/api-types"`），**不手写重复类型定义**（零漂移由 `api-types-check` 门禁保证）。

> **协同契约（已交付 · 05_02 / 05_03，2026-10-02）· 换取会话**：扫码确认后换取会话统一经 `stores/session.ts::signIn({ token, user, tenant, codes? })` 写入（令牌 / 用户概要 / 租户编码内存态），随后由路由守卫的会话就绪链路**幂等装载菜单动态路由**并放行目标页——扫码页不自行注册路由、不自行处理回跳；轮询期间的会话等待用 `stores/session.ensureReady()`（单例）。
