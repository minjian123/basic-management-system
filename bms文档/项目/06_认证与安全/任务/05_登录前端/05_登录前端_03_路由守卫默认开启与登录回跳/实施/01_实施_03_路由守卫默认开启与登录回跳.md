## 2. 实施过程 <a id="process"></a>

1. **设计定稿**：12 项待拍板口径逐项确认（开关语义 / 判定落点 / `meta.public` / DEV 白名单 / 等待态 / 回跳交付度 / 403 占位 / 动态路由 / 观测落点 / 核对页 / Kiwi 登记 / 回跳默认页），详细设计提交 `eea1fc65`。
2. **Kiwi 登记**：经容器内 Django shell 登记 1 条策展用例，回读编号 **2231**；临时脚本用后即删。
3. **核心纯函数**：`domain/route-guard.ts` 由「单一登录跳转判定」扩为决策 / 公开页 / 跳登录构造 / 站内回跳校验四组，新增 `DEFAULT_HOME_PATH` / `DEFAULT_FORBIDDEN_PATH` / `REDIRECT_QUERY_KEY` 常量与 `AuthGuardDecision` / `LoginLocation` 类型；`resolveAuthRedirect` 保留为兼容包装（阶段二 2191 断言继续通过）。
4. **核心遥测**：`module/telemetry.ts` 新增 `ModuleGuardRecord`（`kind: 'guard'`），平台聚合组新增 `guards`；`capabilities/module-telemetry.ts` 快照按种类分派（守卫记录归平台组）；`src/index.ts` 导出新 API 与类型。
5. **会话就绪**：`stores/session.ts` 新增 `ready` 状态与 `ensureReady()`（`WeakMap` 按 store 实例缓存单例 Promise；结束时以**当次令牌**判定，避免会话已被并发清理时误判为已登录）。
6. **动态路由**：`router/dynamic.ts` 新增 `ensureMenuRoutes`（幂等装载，模块级登记）与 `uninstallMenuRoutesAll`（会话清理卸载）。
7. **守卫接线**：`router/guard.ts` 重写——默认开启（`VITE_AUTH_GUARD !== 'off'`）、`resolvePublicPaths(dev)`（核心常量 + DEV 专属路由）、`installAuthGuard(router, deps)` 依赖注入（会话就绪 / 动态路由 / 权限 / 观测）；公开错误页直接放行；受保护路径与登录页 `await` 会话就绪；已登录进登录页回跳；装载动态路由后按新路由表重解析当前地址；`meta.perm` 判不通过跳 `/403`。
8. **宿主装配**：`router/index.ts` 移除模块加载期守卫接线；`main.ts` 在 pinia 就绪后装配守卫与请求适配器、`session.$subscribe` 联动菜单路由装载 / 卸载、会话失效处理增加「本次失效前无会话则不提示不跳转」判据并改用核心 `buildLoginLocation`。
9. **等待态与观测**：`App.vue` 在 `!session.ready` 时渲染骨架屏（纯令牌样式）；`ModuleObservabilityView.vue` 新增「守卫决策（平台）」区块。
10. **核对页**：新增 `auth-guard-check.html` + `src/dev/authGuardCheck.ts` + `src/dev/AuthGuardCheck.vue`（五组自检逐项上屏，`vite build` 只构建 `index.html`，核对页不进产物）。
11. **登记回写**：《[前端基类清单](../../../../../../前端基类清单.md)》「宿主横切底座」节与「可观测」节、《[前端开发规范](../../../../../../规范/前端开发规范.md)》§7 实现口径、[05_02 详细设计](../../05_登录前端_02_token与401静默刷新接线/设计/01_详细设计_02_token与401静默刷新接线.md) §3.6、05_01 / 05_04 任务文档协同契约、阶段计划表。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 | 归口 |
| --- | --- | --- | --- |
| 1 | 冷启动（无 refresh cookie）静默续期失败时，`05_02` 的失效处理会**误提示「会话已失效」并 `router.push('/login')`**，与守卫导航竞争 | 失效处理增加判据：**本次失效前无会话**（`session.token === null`）直接返回，提示与跳转交由守卫按未登录处理 | 设计 §4 第 1 项；已回写 05_02 详细设计 §3.6 |
| 2 | `ensureReady()` 首次用「缓存 Promise 结果」作返回值——会话失效清空后内存令牌为 `null`，但缓存的 `true` 会让守卫误放行受保护页 | 结束时以**当次 `this.token !== null`** 判定（缓存 Promise 只保证单例，不承载结果） | 设计 §3.3；用例 `session-readiness` 覆盖 |
| 3 | 路由元信息增强若写在 `src/env.d.ts`（全局脚本文件）会**遮蔽 `vue-router` 真实类型**（`useRouter` / `createRouter` 等全部报 TS2305） | 增强落**独立模块文件** `src/router/route-meta.d.ts`（含 `export {}`），`env.d.ts` 只保留环境变量与 `bpmn-moddle` 声明 | 计划表偏差列；设计 §2 交付物清单已同步 |
| 4 | 菜单动态路由原为「启动期无条件装载」，与「登录后按用户上下文装载」冲突且登出后路由残留 | 装载改「会话就绪幂等」，卸载挂 `session.$subscribe`（登录 / 登出 / 失效共用一条路径）；启动期装载退役 | 设计 §3.6；用例 `dynamic-routes` 覆盖 |
| 5 | 刷新进入菜单路由时该路径尚未注册，`to` 已命中兜底 404，仅装载路由不会自动重解析 | 守卫在装载后判断「装载前不可解析、装载后可解析」则返回当前地址（`replace`）重解析 | 设计 §3.6；用例 `auth-guard` 覆盖 |
| 6 | 守卫需注入会话依赖，但原接线在 `router/index.ts` 模块加载期（早于 pinia 创建） | 守卫改由 `main.ts` 在 pinia 就绪后装配（`installAuthGuard(router, deps)`），`router/index.ts` 只导出路由实例 | 设计 §3.8 |
