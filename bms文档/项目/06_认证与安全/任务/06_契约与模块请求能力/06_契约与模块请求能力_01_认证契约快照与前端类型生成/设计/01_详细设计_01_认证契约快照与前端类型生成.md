## 1. 设计目标与范围 <a id="goal"></a>

把阶段六新增认证端点**收口**到阶段二既有的契约机制（契约导出 → 快照零漂移 → oasdiff 破坏性门禁 → `@bms/api-types` 前端类型生成）之上，并补一层**长效护栏**：

- **核验（需求 06-1）**：identity 公开契约快照覆盖全部认证端点与错误响应 schema；`@bms/api-types` 生成物与快照零漂移；oasdiff 破坏性变更 0 项；公开契约版本（`info.version` / 服务包自报 / 服务目录登记）三处一致；`deploy/contracts/baseline/identity.json` 更新为当前认证契约，使 oasdiff 门禁对认证端点真实生效。
- **护栏（需求 06-3，2026-10-02 补充立项）**：新增**服务契约路由覆盖护栏**——对全部启用服务断言「实现路由集合 ⊆ 公开契约 `paths`」（防漏登）与「被排除出契约者仅限框架内置文档端点与可观测端点」（防人为隐藏），接入 CI 与本地预检，**CI 与本地同口径**。
- **消费方标注（需求 06-1 第 5 条）**：域五 4 个任务文档 + 域五父任务标注「前端按 `@bms/api-types` 生成类型消费，不手写重复类型」。

**不在本任务**：模块请求能力 `api` 与模块契约版本升 2（需求 06-2，归子任务 [06_02](../../06_契约与模块请求能力_02_模块请求能力api与契约版本升2/06_契约与模块请求能力_02_模块请求能力api与契约版本升2.md)）；前端请求层与登录页的真实接线（归[域五](../../../05_登录前端/05_登录前端.md)）；契约导出 / 生成 / 零漂移机制的既有实现与 openapi-typescript 生成链路（阶段二 `03_01` / `04-1-1` 已交付，**不重复建设**）。

**安全影响（SDL）**：契约是接口的**事实源**——实现端点在契约中缺失会使前端类型与消费方口径失真，被人为隐藏则等同「接口存在但对外不可见」，两类问题都可能在联调期才暴露。本任务以机器护栏把该风险前移到构建期（接口治理面，非数据安全面）。

## 3. 设计与边界 <a id="design"></a>

### 3.1 契约覆盖核对（需求 06-1） <a id="coverage"></a>

**identity 公开契约路径清单**（36 条，按分组，作为需求 06-1「认证端点全部进入契约」的核对基线）：

| 分组 | 路径 | 来源任务 |
| --- | --- | --- |
| 登录 / 令牌 | `/api/v1/auth/login`、`/auth/refresh`、`/auth/logout`、`/auth/introspect` | 01_03 / 01_02 |
| 找回密码 | `/api/v1/auth/forgot-password`、`/auth/reset-password` | 03_06 |
| SSO | `/api/v1/auth/sso/providers`、`/auth/sso/{idp_key}/authorize`、`/authorize-url`、`/callback` | 02_01 / 02_04 |
| 验证码 | `/api/v1/captcha/challenges`、`/captcha/verify`、`/captcha/sms`、`/captcha/scenes/{scene}/policy` | 03_01~03_04 |
| 会话管理 | `/api/v1/sessions`、`/sessions/{session_id}`、`/sessions/{session_id}/kick` | 01_04 |
| IdP 配置 | `/api/v1/idp/providers`、`/idp/providers/test`、`/idp/providers/{provider_id}`、`/{provider_id}/status`、`/{provider_id}/test` | 02_06 |
| BMS 作 IdP | `/api/v1/oidc/.well-known/openid-configuration`、`/oidc/authorize`、`/oidc/token`、`/oidc/jwks`、`/oidc/userinfo` | 02_05 |
| 客户端注册 | `/api/v1/open/clients`、`/clients/{client_id}`、`/{client_id}/status`、`/{client_id}/reset-secret` | 02_05 |
| 身份映射 | `/api/v1/users/{user_id}/identities` | 02_02 |
| 平台通用 | `/`、`/.well-known/jwks.json`、`/healthz`、`/readyz` | 阶段二基座 |

- **错误响应 schema**：登录 / 找回 / 会话等端点已声明 401 / 403 / 404 / 422 → `ApiResponse`（统一响应模型），构成「错误响应 schema」覆盖。
- **契约版本**：保持 `0.1.0`（新增端点为**兼容变更**，按阶段二口径「非破坏性变更在版本内演进」）；`info.version` / 服务包 `CONTRACT_VERSION` / 服务目录 `contract_version` 三处一致（`validate_contract` 与 `ops.check_modules` 双向校验）。
- **快照纪律**：契约「只加不删」——破坏性变更须先登记消费方、同步前端类型与版本，并升大版本（`/api/v2`）。

### 3.2 路由覆盖护栏（需求 06-3） <a id="guard"></a>

**判定口径**（对每个启用服务）：

| 断言 | 规则 | 违反即失败 |
| --- | --- | --- |
| A. 覆盖 | 「计入契约的实现路由集合」⊆ 公开契约 `paths` | 列明细（服务 + 缺失路径） |
| B. 不可见白名单 | 「被排除出契约的实现路由集合」⊆ 白名单 | 列明细（服务 + 越界路径） |

**白名单**（`INVISIBLE_ROUTE_WHITELIST`）：`/docs`、`/redoc`、`/openapi.json`、`/docs/oauth2-redirect`（框架内置文档端点）、`/metrics`（可观测端点）。**新增白名单项须在设计 / 规范侧说明理由**（白名单只允许框架强制或平台基础设施端点，业务端点**一律不得**入白名单）。

**纯判定函数**（`bms_core/services/service_contract.py`，与 `validate_contract` 同处、纯函数可单测）：

```text
service_contract.py（新增）
├── INVISIBLE_ROUTE_WHITELIST: ConcurrentStableSet[str]      # 不可见路由白名单
├── service_route_sets(app: object) -> tuple[ConcurrentStableSet[str], ConcurrentStableSet[str]]
│     # (计入契约的实现路由, 被排除出契约的实现路由)；去重、稳定
├── route_coverage_gaps(implemented, paths) -> ConcurrentStableList[str]      # 断言 A 差异
└── hidden_route_violations(hidden, *, whitelist=None) -> ConcurrentStableList[str]   # 断言 B 差异
```

- **提取方式（框架惰性路由兼容）**：以**鸭子类型**遍历应用路由树——对具备 `effective_candidates()` 可调用者（FastAPI 0.141 的 `_IncludedRouter` 惰性挂载）递归其返回值；对具备 `routes` 属性者（`Mount` / 路由器）递归；对同时具备 `path: str` 与 `include_in_schema: bool` 者按布尔值归入 A / B 集合。**不硬依赖框架私有类名**，规避版本升级脆裂。
- **集合形态**：一律用插入序基座集合（`ConcurrentStableSet` / `ConcurrentStableList`），符合《后端开发规范》「集合与排序」强制口径与 `check-bare-collections` 护栏。

**护栏命令**（`backend/ops/check_contracts.py`，与 `ops/check_modules.py` 同款 CLI 体例）：

```text
ops/check_contracts.py
├── check_service(service_key)            # 单服务：A + B 断言（含「提取为空判失败」防漏检）
├── check_all(services)                   # 遍历目标服务（缺省 enabled_service_keys()）
└── main(argv)                            # 支持 --service / --all；打印分组明细；通过 0 / 失败 1
```

- `ops/contract_snapshot.build_openapi` 改为调用新增的 `build_app(service_key)`（**行为不变**，仅为复用应用对象），避免两处重复 import 服务包；护栏经 `from ops.contract_snapshot import build_app` 复用同一构建入口。
- 输出形如 `[契约路由] 服务 identity：实现路由 36 条全部进入契约；不可见 5 条均在白名单`，失败逐条列出。

### 3.3 identity 契约基线更新（需求 06-1） <a id="baseline"></a>

- **动作**：`uv run python -m ops.contract_gate baseline-update --service identity`，把当前 `deploy/contracts/identity.json`（36 路径）写入 `deploy/contracts/baseline/identity.json`。
- **语义**：基线是「**已放行的兼容契约**」，本次更新即**评审节点**——把阶段六新增认证端点纳入已放行集合，此后对它们的破坏性变更（删端点 / 删字段 / 改必填 / 改类型）将被 `contract-gate` 门禁拦截。基线更新**仅经评审**，无自动覆盖路径。
- **验证**：更新后本地以 oasdiff 二进制复现 `baseline ↔ 当前契约`，9 服务 breaking 仍为 0；CI `contract-gate` job 口径不变。
- **不改**：其余 8 个服务基线（本次无认证端点增量）。

### 3.5 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| 实现路由未出现在契约 `paths`（含被 `include_in_schema=False` 排除） | 断言 A 失败，列出「服务 + 路径」，退出码 1 |
| 业务端点被排除出契约（不在白名单） | 断言 B 失败，列出「服务 + 越界路径」，退出码 1 |
| 服务应用构建失败 / 服务包缺失 | 该服务判失败（复用 `build_openapi` 的 `RuntimeError` 语义），退出码 1 |
| 框架路由结构升级（私有惰性容器形态变化） | 提取以鸭子类型实现：能力缺失时**不静默放过**——路由集合为空即判失败（宁可报错不可漏检） |
| 白名单需新增项 | 须在设计 / 规范侧说明理由；业务端点不得入白名单 |
| 基线更新引入破坏性变更 | `baseline-update` 后本地 oasdiff 复现必须为 0；否则回退并走 breaking 登记 / 升大版本 |
| 前端类型与快照漂移 | `api-types:gen:check`（本地 / CI `api-types-check`）阻断 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **运行时零影响**：护栏只在构建 / CI 期读取应用对象，不改任何服务行为、路由、响应体与契约内容（`build_openapi` 抽 `build_app` 后行为逐字节不变）。
- **契约内容零变更**：identity 契约快照文件本身**不改**（已零漂移）；本次只更新**基线**（门禁放行集合）。
- **契约版本不变**：保持 `0.1.0`，`sys_module` 登记值不动。
- **前端零改动**：`@bms/api-types` 生成物不改；域五只补文档标注。
- **CI 影响**：`swagger-snapshot` job 增一步（秒级，纯内存构建）；预检契约段增一步（`--fast` 覆盖）。
- **既有护栏不受影响**：`check-bare-collections` 基线归零（08_02），本任务新增集合声明一律落插入序基类，不新增基线条目。

## 7. 边界与开放项 <a id="boundary"></a>

- **单向断言**：「实现 → 契约」由本护栏保证；「契约 → 实现」（契约有而实现无）由 `contract_snapshot check`（快照由实现生成）与 `contract_gate` 隐含保证，不重复断言。
- **框架惰性路由内部结构**：提取以鸭子类型兼容 FastAPI 0.141 的 `_IncludedRouter` / `_EffectiveRouteContext`；框架大版本升级后若形态变化，护栏**宁可报错不可漏检**（提取为空即失败），升级时复核（登记为开放项）。
- **契约版本自动回写**（CI 取 OpenAPI 版本写入服务目录）仍归契约门禁需求开放项（阶段二 `09_03` 边界），本任务不实施。
- **基线定期评审**：`deploy/contracts/baseline/*.json` 仅在明确评审节点更新；本任务只更新 identity。
- **其他服务基线**：本次无增量，保持不动；后续如有端点增量，按同口径在对应任务评审更新。
- **产品模块 / 移动端**：不涉及（模块请求能力归需求 06-2 / 移动端归阶段十七）。

## 9. 实施步骤与关键命令 <a id="steps"></a>

```mermaid
flowchart LR
    A["Kiwi 用例登记（先登记后编码）"] --> B["service_contract 纯函数 + 用例"]
    B --> C["contract_snapshot 抽 build_app"]
    C --> D["ops/check_contracts.py 命令 + 真跑"]
    D --> E["CI swagger-snapshot + preflight 接入"]
    E --> F["identity 基线更新 + oasdiff 复现"]
    F --> G["域五消费方标注 + 规范/清单登记"]
    G --> H["门禁全绿 + 计划与记录回写"]
    H --> I["提交（feat / docs 分开）+ 偏差遗留闭环"]
```

1. 读《[KiwiTCMS部署使用说明](../../../../../../资料/开发服务器/linux/KiwiTCMS部署使用说明.md)》「用例约定」节，登记本任务用例并**回读编号**（先登记后编码）。
2. `service_contract.py` 新增白名单常量、`service_route_sets`、`route_coverage_gaps`、`hidden_route_violations`；用例。
3. `ops/contract_snapshot.py` 抽 `build_app`（`build_openapi` 改调用之，行为不变）。
4. 新增 `ops/check_contracts.py`；真跑 9 服务。
5. `.gitlab-ci.yml` `swagger-snapshot` 增一步；`check-preflight.py` 契约段增一步。
6. `uv run python -m ops.contract_gate baseline-update --service identity`；本地 oasdiff 复现 9 服务 breaking = 0。
7. 域五 4 任务 + 父任务补「契约类型」标注；《后端开发规范》《后端基类清单》登记。
8. 门禁：定向 `pytest` / `ruff` / `ruff format --check` / `pyright`（CI 兜底）/ 基座校验 / `check-preflight --fast`；覆盖率核对。
9. 计划 / 任务 / 父任务状态回写 + 实施 / 测试记录 + 代码与文档分开提交（`feat` / `docs`）；偏差与遗留闭环另提。

关键命令：

```bash
# 后端（bms/backend）
uv run python -m ops.check_contracts                      # 路由覆盖护栏（新增）
uv run python -m ops.contract_snapshot check              # 快照零漂移
uv run python -m ops.contract_gate baseline-update --service identity   # identity 基线更新
uv run pytest -q libs/bms_core/tests/services/            # 定向用例
uv run ruff check . && uv run ruff format --check .
# 前端（bms 根）
pnpm run api-types:gen:check                              # 类型零漂移
# 仓库根
python3 scripts/tools/base-check/check-base.py
python3 scripts/tools/base-check/check-links.py
python3 scripts/tools/check-docs/check-status.py --stage 06_认证与安全
python3 scripts/tools/preflight/check-preflight.py --fast
```

> 本机无 docker 时，`ops.contract_gate check` 无法本地复现（依赖 `tufin/oasdiff` 镜像）；本地以 oasdiff 官方二进制（v1.32.1）复现同口径比对，CI `contract-gate` job 为权威门禁。
