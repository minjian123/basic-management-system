## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段六需求域 06 的 2 条需求——[06-1 认证契约快照与前端类型生成](../../需求/06_需求_契约与模块请求能力.md#r06-1)、[06-2 模块请求能力 `api` 与契约版本升 2](../../需求/06_需求_契约与模块请求能力.md#r06-2)，按「1 需求 = 1 子任务」拆 2 个子任务（`06_01` ~ `06_02`）。
- **端范围**：**前后端契约交叉**（identity 契约快照 + `@bms/api-types` 生成 + 前端模块契约与宿主请求层）。
- **承接口径**：契约导出 / 生成 / 零漂移机制（阶段二 `03_01` / `04-1-1`）、模块契约与注册表基座（阶段四 `10_01` / `10_02`）、模块清单与契约版本校验（阶段五 `03_02`）均为已交付产物；本域只做**认证端点增量与模块请求能力增量**。
- **依据**：《[微服务演进规划](../../../../规划/微服务演进规划.md)》、《[架构设计 · 前端模块契约](../../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[架构设计 · 接口与集成](../../../../设计/架构设计/09_架构设计_接口与集成.md)》。
- **执行序**：`06_01 认证契约与类型生成`（先行，供前端登录页消费）→ `06_02 模块请求能力 api`（前端请求层接线就绪后，见[计划](../../计划/01_计划_认证与安全.md)）。

## 3. 工时与依赖 <a id="effort"></a>

- **工时合计**：18h（01 6h + 02 12h）。
- **关键依赖**：`06_01` 依赖域一 / 域二端点实现（契约导出）；`06_02` 依赖域五 `05_02`（宿主请求层 token / 刷新接线）与阶段五 `03_02`（契约版本校验机制）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_认证与安全.md)（本节不写排期）。
- **风险**：契约「只加不删」纪律若破坏会连带前端类型与消费方（须走 breaking 登记）；模块契约版本升 2 若不做旧版本拒绝会造成运行时行为不一致（须版本门禁 + 双模块回归）。
