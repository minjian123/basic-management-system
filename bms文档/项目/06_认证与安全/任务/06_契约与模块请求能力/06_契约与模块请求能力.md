## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段六需求域 06 的 4 条需求——[06-1 认证契约快照与前端类型生成](../../需求/06_需求_契约与模块请求能力.md#r06-1)、[06-2 模块请求能力 `api` 与契约版本升 2](../../需求/06_需求_契约与模块请求能力.md#r06-2)、[06-3 服务契约路由覆盖护栏](../../需求/06_需求_契约与模块请求能力.md#r06-3)（补充需求，2026-10-02 立项）、[06-4 响应契约 schema 完整性与门禁](../../需求/06_需求_契约与模块请求能力.md#r06-4)（补充需求，2026-10-02 立项）。子任务按「1 需求 = 1 子任务」拆 3 个（`06_01` ~ `06_03`）；**需求 06-3 与 `06_01` 完成标准「认证端点全部进入契约快照」同源，归 `06_01` 内扩范围，不新增子任务**；**需求 06-4 是独立的基座缺陷修复与长效门禁能力（全 9 服务受益），与其前置任务 `06_01` 平级单列 `06_03`**。
- **端范围**：**前后端契约交叉**（identity 契约快照 + `@bms/api-types` 生成 + 前端模块契约与宿主请求层）。
- **承接口径**：契约导出 / 生成 / 零漂移机制（阶段二 `03_01` / `04-1-1`）、模块契约与注册表基座（阶段四 `10_01` / `10_02`）、模块清单与契约版本校验（阶段五 `03_02`）均为已交付产物；本域只做**认证端点增量与模块请求能力增量**，以及 `06_03` 的**契约 schema 完整性修复与门禁增量**。
- **依据**：《[微服务演进规划](../../../../规划/微服务演进规划.md)》、《[架构设计 · 前端模块契约](../../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[架构设计 · 接口与集成](../../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[后端开发规范](../../../../规范/后端开发规范.md)》「契约与门禁」节。
- **执行序**：`06_01 认证契约与类型生成`（先行，供前端登录页消费）→ `06_03 契约响应 schema 完整性与门禁`（`06_01` 之后、域五 `05_02` 之前）→ `06_02 模块请求能力 api`（前端请求层接线就绪后，见[计划](../../计划/01_计划_认证与安全.md)）。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：`06_01` 依赖域一 / 域二端点实现（契约导出）；`06_03` 依赖 `06_01`（契约快照、oasdiff 基线与路由覆盖护栏）；`06_02` 依赖域五 `05_02`（宿主请求层 token / 刷新接线）与阶段五 `03_02`（契约版本校验机制）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_认证与安全.md)。
- **风险**：契约「只加不删」纪律若破坏会连带前端类型与消费方（须走 breaking 登记）；实现端点漏登或被显式隐藏出公开契约时既有门禁「一致地」放行（须路由覆盖护栏兜底，需求 06-3）；**响应体 schema 为空对象时快照零漂移与 oasdiff 基线同样「一致地」放行，前端生成类型退化为 `unknown`**（须 `06_03` 的基座修复 + 空 schema 门禁兜底）；基座序列化器改动面覆盖全部服务的响应契约，须保证运行时序列化与脱敏行为零变化（既有用例回归把关）；模块契约版本升 2 若不做旧版本拒绝会造成运行时行为不一致（须版本门禁 + 双模块回归）。
