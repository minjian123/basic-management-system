## 2. 任务内容 <a id="content"></a>

1. **服务端合成出图**：生成带缺口背景图与滑块块图（合成后返回，**不含 `gap_x` / `gap_y`**），缺口位置存 Redis（TTL 与场景策略一致）；`payload` 字段承载出图数据（`background` / `slider` / `width` / `height`），坐标字段移除（2026-09-26 拍板口径）。
2. **轨迹判定**：接收轨迹凭证 `[[x, y, 相对起点毫秒], …]`（沿用冻结形态），按终点落点容差（`SLIDER_TOLERANCE`）与轨迹合理性（时间分布 / 采样点）判定；判定后单次失效。
3. **失败与计数**：轨迹不合格返回 `20101` 子段（校验不通过）并计数、按剩余 TTL 回写可重试；挑战不存在 / 过期走 `20102`；前端自动刷新出题（联调由 `03_04` 承载）。
4. **契约变更登记**：`payload` 新形态（`background` / `slider` / `width` / `height`，不含缺口坐标）登记消费方——前端 `06_04` 滑块件按新 `payload` 调整渲染与端到端联调**归 03_04**（与父任务端范围口径一致）；本任务只做后端真实实现与消费方标注。
5. **用例**：正确轨迹通过、错位 / 机器轨迹被拒、单次失效、坐标不下发、Redis fail-closed。

## 3. 完成标准 <a id="accept"></a>

滑块出图正常（背景含缺口 + 滑块块图）、坐标不出现在任何响应；轨迹正确通过、错位 / 机器轨迹被拒；判定后单次失效；前端 `06_04` 新 `payload` 渲染与端到端联调归 `03_04`（本任务完成契约变更登记与消费方标注）；`pytest`、`pyright`、`ruff` 通过。
