## 1. 设计目标与范围 <a id="goal"></a>

把 `DefaultCaptcha`（03_01 已交付图形码真实实现）在同一实现类内补 **滑块挑战真实实现**：服务端 Pillow **合成出图**（带缺口背景 + 滑块块图，经线程池避免阻塞事件循环）、缺口位置**只存 Redis 不下发**、前端提交**轨迹凭证**后按**落点容差 + 轨迹合理性**判定、判定后单次失效、失败计数复用图形码口径、Redis 不可用 fail-closed。

- **本任务范围**：滑块形态（`CaptchaKind.SLIDER`）的服务端合成出图、Redis 挑战记录、轨迹判定、配置项、测试与登记；同一 `DefaultCaptcha` 类内扩展，**不新增插件键 / 能力域 / 装配**。
- **不在本任务**：短信（03_03）、场景策略按租户读取与失败计数强制（03_04）、密码策略（03_05）；**前端 `06_04` 滑块件按新 `payload` 渲染与端到端联调归 03_04**（本任务只做后端真实实现与**契约变更登记 / 消费方标注**，见 §4、§8 对齐记录 #1）。
- **接口兼容**：`/api/v1/captcha/challenges` / `sms` / `verify` / `scenes/{scene}/policy` 四端点字段与业务错误码子段保持 `02-3-14` 冻结形态（只增不删）；本期不改路由契约、不改插件键 `captcha`、不改 `app.state.captcha` 落点。
- **安全影响（SDL）**：滑块属防爆破挑战形态之一——专项验收点：**缺口坐标绝不出现在任何响应**（只入 Redis）、轨迹判定双因子（落点 + 时间分布 / 采样点）、挑战取用即删（并发只有一个能取到）、Redis 不可用 fail-closed（不放行）、滑块参数不出现在日志。

### 3.2 实现类与方法面 <a id="bases"></a>

```python
class DefaultCaptcha(BaseCaptcha):
    plugin_name: str = "default"

    def __init__(self, *, url: str | None, client: AsyncRedis | None = None,
                 image: CaptchaImageOptions | None = None,
                 slider: CaptchaSliderOptions | None = None) -> None: ...
```

| 方法 | 语义（本任务） |
| --- | --- |
| `generate(scene, *, kind=IMAGE)` | `kind=IMAGE` → 沿用 03_01 图形码；`kind=SLIDER` → **本任务**合成出图（线程池）+ 写 Redis（含 `gap_x` / `gap_y`）；`kind=SMS` → `ServiceUnavailableError`（未启用） |
| `send_sms(phone, scene)` | `ServiceUnavailableError`（短信归 03_03，不变） |
| `verify_credential(credential) -> bool` | 一次性取出后按**记录内 `kind` 分派**：`slider` 走轨迹判定、其余走校验码比对；成功 True、失败 / 不存在 / Redis 异常均 False（**不抛错**，保持契约） |
| `require_credential(credential)` | 覆写（03_01 已有）：不存在 / 过期 → `CaptchaExpiredError`（20102）；判定不通过 / Redis 异常 → `CaptchaVerifyError`（20101） |
| `policy(scene)` | 平台默认策略（不变；按租户读取归 03_04） |

**方法分发**：`_matches(record, credential)` 改为按 `record["kind"]` 分派——`"slider"` → 新增 `_matches_slider`，其余 → 既有校验码比对（`_matches_code`）。`_take` / `_register_failure` 复用 03_01 口径（`PTTL` + `GETDEL` 原子取出、失败按剩余 TTL `SET ... PX` 回写并 `fails+1`）。

### 3.3 滑块出图与轨迹判定口径 <a id="impl"></a>

**合成出图（同步函数 `_render_slider`，`await asyncio.to_thread(...)` 执行）**：

1. 生成 `(slider_width, slider_height)` 随机**渐变噪声底**：对角线性渐变（逐行插值两随机色）+ 数十个随机半透明矩形 / 椭圆 / 短线纹理（抗简单识别）。
2. 随机取缺口左上角 `gap_x ∈ [piece, width - piece)`、`gap_y ∈ [piece, height - piece)`；块图 `slider` = 背景在 `(gap_x, gap_y, gap_x+piece, gap_y+piece)` 的裁剪（视觉与背景一致）。
3. 在背景对应区域绘制**缺口标记**（深色半透明填充 + 描边），使缺口可见。
4. 输出两张 PNG 字节（`BytesIO` + `Image.save(format="PNG")`）；经 base64 填入 `payload`。

**出图数据契约（`CaptchaChallenge.payload`，JSON 字符串）**：

```json
{"background": "<base64 PNG>", "slider": "<base64 PNG>", "width": 300, "height": 150}
```

- 顶层 `image` 为空字节（`b""`）——出图数据**全部经 `payload`** 承载（对齐记录 #2）。
- **不含** `gap_x` / `gap_y`（坐标不下发，对齐记录 #8）。
- `payload` 内图片为**原始 base64**（无 `data:` 前缀，与顶层 `image` 同口径；前端 `captchaImageUrl` 统一补前缀，对齐记录 #3）。

**Redis 挑战记录（`bms:global:captcha:{uuid}`，键拼接沿用 `build_captcha_key`）**：

- 记录 JSON：`{"kind": "slider", "scene": "<场景>", "gap_x": <int>, "gap_y": <int>, "fails": 0}`；`SET key value EX CAPTCHA_TTL`（300 秒）。
- 校验：先 `PTTL` 再 `GETDEL` 原子取出（取用即删 = 单次有效，并发只有一个能取到），按记录内 `kind` 分派判定。

**轨迹判定（双因子，阈值经 `[captcha].options` 可配、宽松起步，对齐记录 #6）**：

| 因子 | 规则 |
| --- | --- |
| 形态匹配 | 记录 `kind == "slider"`，且 `gap_x` 为合法整数；否则判不通过 |
| 采样点 | `len(trace) >= slider_min_points`（缺省 2） |
| 时间分布 | 各点 `t` **非递减**；**时长不再单独否决**——`trace[-1].t - trace[0].t < slider_min_duration_ms`（缺省 300ms，0 表示不校验）**且**落点像素级对准（偏差 ≤ `slider_exact_tolerance`，缺省 4px）才判不通过（**瞬移 + 精准 = 脚本**；人类无法「瞬间又对准」） |
| 落点容差 | `abs(trace[-1].x - gap_x) <= slider_tolerance`（缺省 `SLIDER_TOLERANCE` = 10px） |
| 纵向 | **不校验 `y`**（前端为横向拖动、`y` 恒 0；`gap_y` 仅入记录备后续演进，对齐记录 #12） |

- 满足全部通过；任一不满足 → 判不通过，走 `_register_failure`（`fails+1`、保留剩余 TTL、**可重试**）。
- **人类形态必须放行（2026-10-04 用户口径修订）**：「快速但略偏」「慢速略偏」「慢速对准」都属人类（慢速略偏恰恰更像人），只要在落点容差内即通过；**仅**「瞬移且像素级对准」判为脚本。修订原因：缺省口径曾把时长作**单独**否决项（300ms），实测人类快速甩动（~150ms、落点准确）被误判 ⇒ 拖到位也恒失败，而**该拦的「瞬间对准」反而与人类慢速略偏混在一起**。
- 坐标空间：轨迹 `x` 与 `gap_x` **同为背景图横向像素坐标**（前端负责把轨道拖动位移换算到图片像素，归 03_04）。

**滑块选项（`[captcha].options`，`slider_` 前缀扁平键，与图形码键无冲突，对齐记录 #7）**：

| 键 | 缺省 | 约束 | 说明 |
| --- | --- | --- | --- |
| `slider_width` | 300 | 160 ~ 600 | 背景画布宽（像素） |
| `slider_height` | 150 | 80 ~ 300 | 背景画布高（像素） |
| `slider_piece_size` | 48 | 16 ~ `min(width, height) // 2` | 块图边长（像素） |
| `slider_tolerance` | `SLIDER_TOLERANCE`（10） | 0 ~ 50 | 落点容差（像素） |
| `slider_min_duration_ms` | 300 | 0 ~ 10000 | 轨迹总时长下限（毫秒；0 = 不校验）；仅与下一项**组合**生效 |
| `slider_exact_tolerance` | 4 | 0 ~ 50（超过 `slider_tolerance` 按后者收敛） | 「像素级对准」上限（像素）；时长过短时判定为机器人所需的落点精度 |
| `slider_min_points` | 2 | 1 ~ 100 | 轨迹最少点数 |

解析复用 03_01 的 `_int_option`（缺省取默认、类型非整数 / 越界 → `PluginError` 装配拒启）。选项仅承载非敏感值。

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 轨迹正确（落点 + 合理性均满足） | 挑战已被 `GETDEL` 删除（单次有效）；二次使用 → 20102 |
| 轨迹不合格（错位 / 点数不足 / 时长过短 / 时间回退） | `_register_failure`（`fails+1`、保留剩余 TTL）；`require_credential` → `CaptchaVerifyError`（**20101** / 200，可重试）；`verify_credential` → False（对齐记录 #5） |
| 挑战不存在 / 已过期（`GETDEL` 未命中） | `require_credential` → `CaptchaExpiredError`（20102 / 404）；`verify_credential` → False |
| Redis 不可用（出题） | `generate` → `ServiceUnavailableError`（10007 / 503，明确稍后重试） |
| Redis 不可用（校验） | `verify_credential` → False（不放行）；`require_credential` → `CaptchaVerifyError`（20101） |
| 记录 `kind=slider` 但 `gap_x` 缺失 / 非法（脏值） | 判不通过（`require_credential` → 20101） |
| 未启用形态（`kind=sms`） | `ServiceUnavailableError`（10007 / 503，明确未启用，不放行） |
| `[captcha].options` 非法 | 工厂 `PluginError`（装配拒启） |
| 路由未知场景 / 非法形态 | 沿用路由层 `ParamError`（10001），不改 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **同域扩展而非替换**：`BaseCaptcha` 契约与数据契约零改动（`CaptchaChallenge.payload` 语义由「背景与缺口参数」细化为「背景与滑块块图参数」，字段与类型不变）；图形码行为零变化（分派后仍走校验码路径）。
- **`NullCaptcha` 不变**：占位三形态恒定通过；identity 既有契约用例（Kiwi 41 / 879）不受影响。
- **既有图形码用例适配**：`libs/bms_core/tests/captcha/test_captcha_default.py` 中「未启用形态不放行」用例原断言滑块与短信均抛 `ServiceUnavailableError`——滑块启用后该断言失效，需改为**仅短信**（该用例仍归 Kiwi 2204；属能力演进的必要适配，实施记录登记）。
- **前端 `06_04`（消费方，归 03_04）**：`payload` 新形态——新增 `slider`（块图）、移除 `gap_x` / `gap_y`（不再自绘缺口）；`parseCaptchaSliderParams` 需补 `slider` 字段，`SliderCaptcha.vue` 以 `background` 为画布、按拖动位移渲染 `slider` 块并把轨道位移换算为图片像素坐标。**本任务只做契约变更登记与消费方标注**（对齐记录 #1）。
- **登录链路**：`_enforce_captcha` 不改，仍调 `require_credential`；滑块判定失败语义为 20101。
- **后续扩展点**：03_03 在同一类内补 `send_sms`；03_04 把 `policy` 改读 `sys_config`、把记录内 `fails` 与登录侧强制计数对齐、并完成前端联调。**不新增插件键、不改装配骨架**。
- **平台契约套件**：`DefaultCaptcha` 构造参数新增 `slider`（带缺省、非必填），仍不自动登记（`test_plugin_registration` 键集不变）。

## 7. 边界与开放项 <a id="boundary"></a>

- **前端 `06_04` 滑块件渲染与联调**：归 **03_04**（父任务端范围口径）；本任务只登记契约变更与消费方。
- **短信（03_03）**：本任务 `send_sms` 仍明确失败不放行。
- **场景策略按租户读取**（`sys_config`）与**失败计数驱动「连续失败 N 次强制」**（登录侧）→ 03_04；本任务 `policy` 返回平台默认、记录内 `fails` 仅记录。
- **轨迹判定阈值调参**：本任务按「宽松起步 + 可配置」交付，不得在生产前凭真机取样收紧；阈值常量集中维护。
- **拼图凸凹形状 / 真实图片底**：本任务采用渐变噪声底 + 矩形缺口，后续需要时按「只增字段 / 只加选项」演进（不改 `payload` 已下发字段语义）。
- **坐标换算**：轨迹 `x` 与 `gap_x` 同为背景图横向像素，前端换算归 03_04；若后续改用归一化坐标，按契约扩展处理。
- **Kiwi 用例编号** → 测试实施时登记回填。
- **真 Redis 集成用例**依赖 `BMS_TEST_REDIS_URL`（未配置 skip）；本地以开发机 Redis 实跑并记入测试记录。
