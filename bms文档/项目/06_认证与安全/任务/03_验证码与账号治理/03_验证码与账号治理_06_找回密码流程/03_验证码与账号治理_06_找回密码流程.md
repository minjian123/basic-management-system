## 2. 任务内容 <a id="content"></a>

1. **流程接口**：发起找回（账号 / 手机 / 邮箱取通道）→ 验证码校验（场景策略）→ 生成重置 token 存 Redis（15 分钟、单次有效）→ 重置密码（强制过策略）→ 该账号全部会话失效。
2. **限流防滥用**：每账号 1 次 / 5 分钟、每 IP 5 次 / 小时（经限流基座）；命中明确提示。
3. **发送通道**：经 `BaseNotifier` 占位发送（邮件 / 企微 / 钉钉真实渠道归阶段八，接口契约对齐）；不回显 token 与验证码。
4. **安全口径**：token 单次有效、重置后 refresh 黑名单 + Redis 会话标记清理即时生效；响应不泄露账号是否存在。
5. **用例**：全链路成功、token 单次 / 过期、限流阈值、重置后原会话即 401。

## 3. 完成标准 <a id="accept"></a>

找回 → 校验 → 重置 → 会话全失效全链路可用（真实渠道到位前以占位通道验证）；token 单次 / 过期 / 限流用例齐全；重置后原会话下一请求即 401；`pytest`、`pyright`、`ruff` 通过。
