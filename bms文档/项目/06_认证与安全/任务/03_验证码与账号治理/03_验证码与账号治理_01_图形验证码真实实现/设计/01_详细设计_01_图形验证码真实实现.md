## 1. 设计目标与范围 <a id="goal"></a>

把 `BaseCaptcha` 从**结构占位**（`NullCaptcha` 恒定通过、出图为空串）落为**图形码插件化真实实现**：Pillow 出图（干扰线 / 噪点 / 字符变形）、经线程池避免阻塞事件循环、挑战存 Redis 一次性校验、Redis 不可用 fail-closed；四端点契约与错误码 `20101` ~ `20103` 不变，`BaseCaptcha` 真实实现部分交付状态回写《[后端基类清单](../../../../../../后端基类清单.md)》。

- **本任务范围**：图形码（`CaptchaKind.IMAGE`）的真实出题与真实校验；真实实现类、Redis 存取、配置项、插件装配、测试与登记。
- **不在本任务**：滑块（03_02）、短信（03_03）、场景策略按租户读取与失败计数强制（03_04）、密码策略（03_05）——本任务对滑块 / 短信只落**明确失败不放行**（不留安全缺口），能力由后续子任务在同一实现类内补齐。
- **接口兼容**：`/api/v1/captcha/challenges` / `sms` / `verify` / `scenes/{scene}/policy` 四端点字段与业务错误码子段保持 `02-3-14` 冻结形态（只增不删）；本期不改路由契约、不改插件键 `captcha`、不改 `app.state.captcha` 落点。
- **安全影响（SDL）**：涉及验证码防爆破第一道闸——专项验收点：出图非空且可人工识别、挑战单次有效（成功后二次使用被拒）、比对大小写不敏感且常量时间（`hmac.compare_digest`）、Redis 不可用 fail-closed（不放行）、验证码明文不落日志（沿用 `[logging]` 敏感键）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 能力域与插件键 <a id="domain"></a>

| 能力域（插件键） | 插件基类 | 真实实现（`plugin_name`） | Null 实现 | 契约版本 |
| --- | --- | --- | --- | --- |
| `captcha` | `BaseCaptcha` | `DefaultCaptcha`（`default`） | `NullCaptcha` | `0.1.0` |

继承链（固定前三段 + 域中间层）：`BaseObject` → `BaseCapability` → `BasePluggable`（+ `BaseAsyncResource`）→ `BaseCaptcha`（能力域，`key = plugin_key = "captcha"`）→ `DefaultCaptcha`；`NullCaptcha` 走 `BaseNullObject` 缺省轨。**不新增插件键、不新增能力域、`_EXPECTED_PLUGIN_KEYS` 不变**。

### 3.2 实现类与方法面 <a id="bases"></a>

```python
class DefaultCaptcha(BaseCaptcha, BaseAsyncResource):
    plugin_name: str = "default"

    def __init__(self, *, url: str | None, client: AsyncRedis | None = None,
                 image: CaptchaImageOptions | None = None) -> None: ...
    # url 无默认值 → 非零参可实例化 → 不进插件注册表自动收集，交装配工厂显式登记
```

| 方法 | 语义（本任务） |
| --- | --- |
| `generate(scene, *, kind=IMAGE)` | `kind=IMAGE` → Pillow 出图（线程池）+ 写 Redis；`kind=SLIDER` / `SMS` → `ServiceUnavailableError`（未启用，fail-closed） |
| `send_sms(phone, scene)` | `ServiceUnavailableError`（短信归 03_03） |
| `verify_credential(credential) -> bool` | 一次性取出比对（大小写不敏感），成功 True、失败 / 不存在 / Redis 异常均 False（**不抛错**，保持契约） |
| `require_credential(credential)` | **覆写**：成功返回；不存在 / 过期 → `CaptchaExpiredError`（20102）；码不符 / Redis 异常 → `CaptchaVerifyError`（20101） |
| `policy(scene)` | 平台默认策略（`default_scene_policy`；按租户读取归 03_04） |

### 3.3 真实实现口径 <a id="impl"></a>

**出图（同步函数，`await asyncio.to_thread(...)` 执行）**：

- 画布 `(width, height)`、浅色随机底色；逐字符以 `ImageFont.load_default(size=font_size)` 绘制，字符随机垂直抖动与 ±`rotate_degrees` 内旋转（字符变形）；叠加 `noise_lines` 条随机干扰线与 `noise_dots` 个噪点。
- 字符集固定常量 `CAPTCHA_CHARS = "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"`（去 `I` / `O` / `0` / `1` 等易混字符），长度取 `length`。
- 输出 PNG 字节（`BytesIO` + `Image.save(format="PNG")`）；路由面沿用 base64（`api/captcha.py` 已实现，不改）。
- 字体取 Pillow 内置可缩放默认字体（`load_default(size=...)`，Pillow ≥ 10.1），**不依赖系统字体文件**。

**Redis 存取（`bms:global:captcha:{uuid}`，键拼接沿用 `build_captcha_key`）**：

- 记录 JSON：`{"code": "<大写码>", "scene": "<场景>", "kind": "image", "fails": 0}`；写入 `SET key value EX CAPTCHA_TTL`（300 秒）。
- 校验：`GETDEL key` **原子取出**（成功即删除 = 单次有效，并发只有一个能取到）；码经 `hmac.compare_digest` 常量时间比对（大小写不敏感：比对前统一 `strip().upper()`）。
- 失败重试：码不符时 `SET key value KEEPTTL` 回写（保留剩余 TTL）且 `fails + 1`（**失败计数**落记录内，随 TTL 过期，仅记录不驱动强制）。
- 懒建连（`AsyncRedis.from_url(url, decode_responses=True)`，构造不建连）；实例实现 `aclose()` 随 `ResourceManager` 回收。

**配置选项（`[captcha].options`，键与缺省）**：

| 键 | 缺省 | 约束 | 说明 |
| --- | --- | --- | --- |
| `width` | 160 | 80 ~ 400 | 画布宽（像素） |
| `height` | 60 | 30 ~ 200 | 画布高（像素） |
| `length` | 4 | 1 ~ 8 | 字符数 |
| `font_size` | 36 | 12 ~ `height` | 字号 |
| `noise_lines` | 4 | 0 ~ 10 | 干扰线条数 |
| `noise_dots` | 60 | 0 ~ 500 | 噪点数 |
| `rotate_degrees` | 25 | 0 ~ 45 | 单字符最大旋转角度 |

解析在工厂构造期完成：键缺失取缺省；类型非整数 / 超界 → `PluginError`（装配拒启，不静默）。选项仅承载非敏感值（无密钥）。

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 挑战不存在 / 已过期（`GETDEL` 未命中） | `require_credential` → `CaptchaExpiredError`（20102 / 404）；`verify_credential` → False |
| 校验码不符（大小写不敏感后仍不等） | 回写记录 `fails+1`；`require_credential` → `CaptchaVerifyError`（20101 / 200）；`verify_credential` → False |
| 校验成功 | 记录已被 `GETDEL` 删除（单次有效）；二次使用 → 20102 |
| Redis 不可用（出题） | `generate` / `send_sms` → `ServiceUnavailableError`（10007 / 503，明确稍后重试） |
| Redis 不可用（校验） | `verify_credential` → False（不放行，保持「不抛错」契约）；`require_credential` → `CaptchaVerifyError`（20101） |
| 出题 / 校验遇到未启用形态（slider / sms） | `ServiceUnavailableError`（10007 / 503，明确未启用，不放行） |
| `[captcha].options` 非法 | 工厂 `PluginError`（装配拒启） |
| 路由未知场景 / 非法形态 | 沿用路由层 `ParamError`（10001），不改 |
| 挑战编号为空 | 沿用路由契约 `min_length=1` 与 `verify_credential` 未命中路径（→ 20102），不改 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **新增而非替换**：`NullCaptcha` 保留（provider 空 / 测试回落），`BaseCaptcha` 契约与数据契约零改动。
- **默认 provider 切换**：`config.toml` 由「空 → null」改为 `"default"`；各服务单测在 `conftest.py` 增 `BMS_CAPTCHA__PROVIDER=""` 回落 `NullCaptcha`（与 `session_store` / `rate_limiter` 真实实现关闭同口径）——既有用例离线、行为不变。
- **既有契约用例**（identity `tests/captcha/`，Kiwi 41 / 879）**保留不动**：直接以 `NullCaptcha` 断言占位语义，不受默认 provider 影响。
- **登录链路**：`_enforce_captcha` 不改，仍调 `require_credential`；真实实现下失败语义由 20101 细化为 20101 / 20102。
- **后续扩展点**：同一 `DefaultCaptcha` 内 03_02 补 `SLIDER` 出图与轨迹判定、03_03 补 `send_sms`（经 `BaseNotifier` / `BaseRateLimiter`）；03_04 把 `policy` 改读 `sys_config`、把记录内 `fails` 与登录侧强制计数对齐。**不新增插件键、不改装配**。
- **平台契约套件**：新增实现类有必填构造参数 → 不自动登记（`test_plugin_registration` 键集不变）；工厂在 `assembly.py` 显式登记。
