## 1. 设计目标与范围 <a id="goal"></a>

把阶段二 `02-3-07` 交付的 `NullPasswordPolicy`（恒定通过）落为**真实密码策略**，并补齐账号治理的三处接线：**复杂度校验**（长度 / 大小写 / 数字 / 符号 / 不得含用户名，规则按租户读 `sys_config`）、**有效期与历史**（`pwd_changed_at` 驱动 90 天强制改密并置 `pwd_reset_required`；`pwd_history` 近 5 次 PBKDF2 比对不可重复）、**180 天不活跃扫描**（按 `last_login_at` 扫描的服务方法 + 手动触发入口，命中落 `sys_account_lock`（`inactive` 型））。改密 / 重置路径（org 内部 `update-password`，供 `03_06` 找回密码消费）强制过策略；登录成功后按判定置 `pwd_reset_required`。

- **本任务范围**：`bms_core/password` 真实实现（`DefaultPasswordPolicy` + 工厂装配 + `[password_policy]` 配置）与契约小幅扩展（新增非抽象 `history_count`）；`sys_config` 密码 / 账号策略键位与平台默认种子；`sys_user` 新增 `pwd_reset_required` 字段；`sys_account_lock` 表 / 模型 / 仓储 / 迁移；org 改密强制过策略、登录置标志；org 180 天扫描服务方法与内部触发端点；identity 内部契约映射（`must_change_password`）；测试与登记回写。
- **不在本任务**：找回密码流程（`03_06` 消费本任务 org 改密接口）；账号锁定的 `fail_limit` / `manual` 两型、解锁接口、锁定列表 / 详情与页面（`03_07` 复用本任务 `sys_account_lock` 表扩展）；Celery 定时调度（归阶段八，本任务只交服务方法与手动触发）；`sys_config` 管理面（阶段八）；密码策略 / 强度提示前端页面（阶段十五，`05_01` 登录页仅消费 `must_change_password`）。
- **接口兼容**：`BasePasswordPolicy` 三个抽象方法签名不变，**只新增非抽象** `history_count()`（默认 5，向后兼容，参照 `03_04` 给 `BaseRateLimiter` 增 `peek` 的先例）；org / identity 内部契约**只增字段**；公开登录响应 `UserSummary.must_change_password` 已存在（阶段二占位），本任务仅真正填充，公开契约零变更。
- **安全影响（SDL）**：密码策略是等保 / PIPL 合规闸门——专项验收点：复杂度不通过拒绝写库（30005）、新密码命中近 N 次历史拒绝（30006）、策略按租户隔离且变更即时生效、历史密码仅存哈希（PBKDF2 自描述串，不落明文）、扫描锁定不泄露账号存在性、日志不落密码明文。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 密码策略能力域与真实实现 <a id="policy"></a>

**契约小幅扩展**（`password/base.py`，向后兼容）：新增**非抽象**方法，缺省返回平台默认次数——

```python
PASSWORD_HISTORY_COUNT = 5
"""历史密码不可重复比对条数（平台默认；真实实现按租户读 `password.history_count` 覆盖）。"""

class BasePasswordPolicy(BasePluggable, ABC):
    ...  # 三个抽象方法签名不变

    async def history_count(self) -> int:
        """历史密码不可重复比对条数（非抽象，缺省平台默认；真实实现按租户读 `sys_config`）。"""
        return PASSWORD_HISTORY_COUNT
```

**真实实现**（`password/default.py`，插件名 `default`）：

```python
class DefaultPasswordPolicy(BasePasswordPolicy):
    plugin_name = "default"

    def __init__(self, *, config: BaseConfigSource | None = None, hasher: BasePasswordHasher | None = None) -> None: ...

    async def validate(self, password, *, username=None) -> tuple[str, ...]:
        # 读 password.min_length / require_upper|lower|digit|symbol / forbid_username（缺省回落代码默认）
        # 依 PASSWORD_VIOLATIONS 固定顺序产出：too_short / too_long / need_upper / need_lower /
        #   need_digit / need_symbol / username_included
    async def expired(self, pwd_changed_at, *, now=None) -> bool:
        # 读 password.max_age_days（缺省 90）；pwd_changed_at 为 None → 不判过期（False）
    async def reused(self, password, *, history) -> bool:
        # 对 history 逐条 hasher.verify，命中即 True（常量时间；空历史 False）
    async def history_count(self) -> int:
        # 读 password.history_count（缺省 5）
```

- **容错解析**：新增私有 `_parse_bool` / `_parse_int`（同 `captcha/default.py` 口径：`true/false/1/0/yes/no/on/off`、整数串；非法 / 缺失回落代码默认，不抛错）。
- **返回缺失项清单**：`validate` 结果即 `PASSWORD_VIOLATIONS` 子集，供上层映射文案（前端只展示等级与缺失项，不回显密码）。
- **默认值**（代码默认 = 平台种子，保持一致）：`min_length=8` / `max_length=128` / `require_upper|lower|digit|symbol=true` / `forbid_username=true` / `max_age_days=90` / `history_count=5`。
- `expired` 的 `pwd_changed_at=None` 按「未过期」处理（新账号 / 首登未改密不误锁）；`too_long` 取 `password.max_length`（缺省 128，与登录请求体 `max_length=512` 不冲突，策略侧更严）。
- **Null 轨**：`NullPasswordPolicy` 不变（恒定通过，不读 `sys_config`）；`config.toml` 置 `provider="default"` 即真实实现默认启用，单测以空 provider 回落 Null 保持离线。

### 3.4 改密 / 重置路径强制过策略（org 内部） <a id="update-password"></a>

`CredentialService.update_password` 在写库前执行策略闸门（`policy` 经构造注入，缺省 `NullPasswordPolicy` 向后兼容）：

```python
async def update_password(self, account, new_password, *, keep_history=None) -> UpdatePasswordResult:
    async with self._uow.begin():
        user = await self._repo().get_by_username(account)
        if user is None:
            return UpdatePasswordResult(updated=False, reason="not_found")
        violations = await self._policy.validate(new_password, username=user.username)
        if violations:
            return UpdatePasswordResult(updated=False, reason="policy_violation", violations=violations)
        history = parse_password_history(user.pwd_history)
        if await self._policy.reused(new_password, history=[user.password_hash, *history]):
            return UpdatePasswordResult(updated=False, reason="history_reused")
        keep = keep_history if keep_history is not None else await self._policy.history_count()
        history.append(user.password_hash)
        history = history[-keep:] if keep > 0 else []
        await self._repo().update(
            user.id,
            password_hash=self._hasher.hash(new_password),
            pwd_changed_at=_utc_now(),
            pwd_history=json.dumps(history, ensure_ascii=False),
            pwd_reset_required=False,   # 改密成功即清除强制改密标志
        )
        return UpdatePasswordResult(updated=True)
```

- **比对范围**：`[当前哈希, *历史]` —— 新密码不得与**当前 / 近 N 次历史**重复。
- **判定顺序**：复杂度（30005）→ 历史（30006）→ 写库；账号不存在返回 `updated=False, reason="not_found"`（不抛错，由调用侧定语义）。
- **接口层**：org `api/internal.py` 的 `_service(uow, hasher)` 增策略参数（`Depends(get_password_policy)`）；端点只做透传，不改路径与既有字段。

### 3.6 180 天不活跃扫描（org 内部服务 + 手动触发） <a id="scan"></a>

**服务方法**（`services/account_lock.py::AccountLockService`）：

```python
INACTIVE_LOCK_SENTINEL = datetime(9999, 12, 31, 0, 0, 0)   # UTC naive，长期哨兵
"""inactive 型锁定复用 `sys_user.locked_until` 的远期哨兵（登录即被既有锁定链拒绝，手动解锁清空）。"""

async def scan_inactive(self, *, now: datetime | None = None) -> InactiveScanReport:
    # 1) 读 account.inactive_lock_days（缺省 180）→ 阈值 threshold = now - days
    # 2) 候选：deleted_at IS NULL ∧ status='enabled' ∧ (locked_until IS NULL OR <= now)
    #          ∧ ( (last_login_at IS NOT NULL AND last_login_at < threshold)
    #              OR (last_login_at IS NULL AND created_at < threshold) )
    # 3) 逐候选：sys_user.locked_until = INACTIVE_LOCK_SENTINEL；
    #            写 sys_account_lock(user_id, lock_type='inactive', reason, locked_at=now)
    # 4) 单事务提交；返回 {scanned, locked}
```

- **含从未登录账号**：`last_login_at` 为 NULL 的账号按 `created_at` 判定（避免建号后长期未首登的合规盲区）。
- **幂等**：命中后 `locked_until` 为远期哨兵（> now），重复扫描该账号即被排除；不重复写锁记录。
- **排除**：已停用（`status != enabled`）、已锁定（`locked_until > now`）不重复处理。

**手动触发端点**：

| 方法 | 路径 | 鉴权 | 请求 | 响应 data |
| --- | --- | --- | --- | --- |
| POST | `/api/v1/org/internal/account-locks/scan-inactive` | `require_service("identity", "platform")` | 空体 | `{scanned, locked}` |

- 路由基类 `BaseRouter(key="org_internal_account_locks", prefix="/org/internal/account-locks")`；租户由服务 JWT `tenant` claim 经全局租户中间件解析（操作当前租户库）。
- 计入 org 公开契约（`deploy/contracts/org.json` 重生成，零漂移）；管理触发页面 / Celery 定时归阶段七 / 八。

### 3.7 内部数据契约 <a id="dto"></a>

**org 侧**（`schemas/credentials.py` / `schemas/account_lock.py`）：

| 契约 | 变更 | 说明 |
| --- | --- | --- |
| `CredentialVerifyResult` | 增 `pwd_reset_required: bool = False` | 登录后是否需强制改密 |
| `UpdatePasswordResult` | 增 `reason: str = ""` / `violations: list[str] = []` | `""`=成功（`updated=true`）；`not_found` / `policy_violation` / `history_reused` |
| `InactiveScanReport`（新） | `scanned: int` / `locked: int` | 扫描概要 |

**identity 侧**（`schemas/auth.py`）：

| 契约 | 变更 | 说明 |
| --- | --- | --- |
| `OrgVerifyResult` | 增 `pwd_reset_required: bool = False` | 映射公开 `must_change_password` |
| `OrgUpdatePasswordResult`（新） | `updated: bool` / `reason: str` / `violations: list[str]` | 改密结果消费 |

- `OrgCredentialClient.update_password` 解析 org 结果：`updated=true` → 返回 `True`；`policy_violation` → 抛 `PasswordPolicyViolationError`（30005，data 带 `violations`）；`history_reused` → 抛 `PasswordReusedError`（30006）；`not_found` → 返回 `False`（保持既有布尔语义）。`03_06` 找回密码直接消费该语义。

### 3.8 错误码 <a id="errors"></a>

`error_codes.py` 顺延新增（3xxxx 用户与组织段；现有 `PERMISSION=30001` 不复用）：

| 错误码 | 名称 | HTTP | 说明 |
| --- | --- | --- | --- |
| 30005 | `PASSWORD_POLICY_VIOLATION` | 400 | 密码不符合复杂度策略（data 带 `violations` 清单） |
| 30006 | `PASSWORD_REUSED` | 400 | 新密码与近 N 次历史密码重复 |

- 对应异常 `PasswordPolicyViolationError` / `PasswordReusedError`（继承 `UserOrgError`）。
- 文案由前端按 i18n 映射；后端不承担文案拼装（与概要 03 §7 口径一致）。

### 3.9 配置契约 <a id="config"></a>

`config.toml` 新增一节：

```toml
[password_policy]
# 密码策略实现选择（插件化配置；default = 读 sys_config 的复杂度 / 有效期 / 历史策略、空串 = null 占位恒定通过）
provider = "default"
options = {}
```

- `Settings.password_policy` 字段已存在，无需新增；`deploy/.env.example` 不新增键（嵌套规则自动可用）。
- 单测沿用空 provider 回落 `NullPasswordPolicy`（离线）；`config.dev.toml` 无需改动（`config.toml` 基线即 default）。

### 3.10 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 复杂度不通过（改密 / 重置） | `UpdatePasswordResult(updated=false, reason=policy_violation, violations=[…])`；identity 侧 `30005` |
| 新密码命中当前 / 近 N 次历史 | `UpdatePasswordResult(updated=false, reason=history_reused)`；identity 侧 `30006` |
| 账号不存在（改密） | `updated=false, reason=not_found`（不抛错）；identity 客户端返回 `False` |
| `sys_config` 键缺失 / 非法 / 源不可达 | 回落代码默认，策略生效不报错（读取降级） |
| `pwd_changed_at` 为 NULL | `expired=False`（不误锁新账号） |
| 扫描无命中 | `{scanned:0, locked:0}`（幂等） |
| 扫描端点鉴权：无 / 用户 / 网关票据 | `AuthError`（20001 / 401） |
| 扫描端点：identity / platform 服务 JWT | 放行；租户由服务 JWT `tenant` 解析 |
| `[password_policy]` 选项非法 | 工厂 `PluginError`（装配拒启） |

## 4. 兼容性与消费方影响 <a id="compat"></a>

## 7. 边界与开放项 <a id="boundary"></a>

- **账号锁定其余两型与解锁**：`fail_limit` / `manual` 写锁、解锁接口、锁定列表 / 详情、`user:unlock` 权限、页面 → **`03_07`**（复用本任务 `sys_account_lock` 表）。
- **Celery 定时调度**：180 天扫描的定时触发（每日）→ **阶段八**；本任务只交服务方法与手动触发端点。
- **`sys_config` 管理面**：密码策略键的 CRUD / 页面 / 审计 / 平台默认下发流程 → **阶段八**（`03_08` 边界）。
- **密码强度提示前端**：等级 / 缺失项展示、改密与找回密码页面 → **阶段十五**（`05_01` 登录页仅消费 `must_change_password`）。
- **`password.max_length`**：策略默认 128（较登录体 512 更严）；如需放宽按租户经 `sys_config` 覆盖。
- **`expired` 的 NULL 口径**：`pwd_changed_at` 为 NULL 视为未过期（不误锁首登账号）；如后续要求「建号即计时」再评估。
- **历史条数存储**：`update_password` 落库保留条数取策略 `history_count`；改小不追溯清理既有更长历史（比对按现值）。
- Kiwi 用例编号 → 测试实施时登记回填。
