## 1. 设计目标与范围 <a id="goal"></a>

把 `DefaultCaptcha`（03_01 图形码 / 03_02 滑块已交付）在同一实现类内补 **短信验证码真实实现**：生成 **6 位纯数字** 验证码存 Redis（TTL 300s）、经 `BaseNotifier` 通知基座下发（本期占位不真发、接口契约不变）、目标手机号**脱敏回显**、**重发冷却 60s + 账号 / IP 双维限次**（经 `BaseRateLimiter`）、校验一次性且失败计数复用既有口径、Redis 不可用与通知渠道不可用均**明确失败不放行**；错误子段 `20103` 生效。

- **本任务范围**：短信形态（`CaptchaKind.SMS`）的生成、存储、通知下发、冷却限次、脱敏回显、配置项、测试与登记；同一 `DefaultCaptcha` 类内扩展，**不新增插件键 / 能力域 / 装配落点**。
- **不在本任务**：场景策略按租户读取与失败计数强制（03_04）、密码策略（03_05）、找回密码（03_06）；短信模板与真实渠道实现（阿里云 / 腾讯云）归**阶段八（通知公告）**；前端 `06_04` 短信件渲染与端到端联调归 **03_04**；脱敏改经 `BaseMasker` 归 **04_02**（见 §4 与对齐记录 #1）。
- **接口兼容**：`/api/v1/captcha/challenges` / `sms` / `verify` / `scenes/{scene}/policy` 四端点字段与业务错误码子段保持 `02-3-14` 冻结形态（只增不删）；`BaseCaptcha.send_sms(phone, scene)` 签名**不变**（IP 经 `current_client_ip` 上下文取，不改契约）；不改路由契约、不改插件键 `captcha`、不改 `app.state.captcha` 落点。
- **安全影响（SDL）**：短信属防爆破与身份校验渠道——专项验收点：**验证码明文绝不出现在响应 / 日志**（只入 Redis 记录与通知内容）、目标手机号**恒脱敏回显**（任何输入不原样回显）、**冷却期内不重置倒计时**（限流命中返回 `20103`）、Redis 不可用 fail-closed（不放行）、通知渠道不可用明确报错（不静默放行）、发送失败即删除已写入挑战（避免「无码可过」）。

### 1.1 现状与缺口 <a id="gap"></a>

```text
backend/libs/bms_core/src/bms_core/
├── captcha/
│   ├── base.py            # BaseCaptcha.send_sms 契约（签名不变）；常量 SMS_CAPTCHA_TTL / SMS_COOLDOWN；mask_phone（脱敏唯一入口）
```

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 能力域与插件键 <a id="domain"></a>

| 能力域（插件键） | 插件基类 | 真实实现（`plugin_name`） | Null 实现 | 契约版本 |
| --- | --- | --- | --- | --- |
| `captcha` | `BaseCaptcha` | `DefaultCaptcha`（`default`） | `NullCaptcha` | `0.1.0` |

**不新增插件键、不新增能力域、`_EXPECTED_PLUGIN_KEYS` 不变**；三形态同为 `DefaultCaptcha` 同一实例按 `kind` / 端点分派。继承链不变：`BaseObject` → `BaseCapability` → `BasePluggable` → `BaseCaptcha` → `DefaultCaptcha`。**本任务消费（不新建）** `BaseNotifier`（`notifier`）与 `BaseRateLimiter`（`rate_limiter`）能力域实例。

### 3.2 实现类与方法面 <a id="bases"></a>

```python
class DefaultCaptcha(BaseCaptcha):
    plugin_name: str = "default"

    def __init__(self, *, url: str | None, client: AsyncRedis | None = None,
                 image: CaptchaImageOptions | None = None,
                 slider: CaptchaSliderOptions | None = None,
                 sms: CaptchaSmsOptions | None = None,
                 notifier: BaseNotifier | None = None,
                 rate_limiter: BaseRateLimiter | None = None) -> None: ...
```

| 方法 | 语义（本任务） |
| --- | --- |
| `generate(scene, *, kind=IMAGE)` | `kind=IMAGE` → 沿用 03_01；`kind=SLIDER` → 沿用 03_02；`kind=SMS` → **`ParamError`（10001，短信请经 `/captcha/sms` 端点）** |
| `send_sms(phone, scene) -> CaptchaChallenge` | **本任务**：冷却 / 账号 / IP 限次（经限流基座）→ 生成 6 位数字码写 Redis（TTL 300s）→ 经通知基座下发 → 返回脱敏目标挑战；失败即删除挑战 |
| `verify_credential(credential) -> bool` | 一次性取出后按记录内 `kind` 分派（`slider` 走轨迹、其余走校验码）；短信复用校验码路径（**零改动**） |
| `require_credential(credential)` | 覆写（03_01 已有）：不存在 / 过期 → `CaptchaExpiredError`（20102）；码不符 / Redis 异常 → `CaptchaVerifyError`（20101） |
| `policy(scene)` | 平台默认策略（不变；`send_sms` 取其 `cooldown` / `ttl`；按租户读取归 03_04） |

**依赖注入**：`notifier` / `rate_limiter` 经装配工厂解析注入（沿用 `HttpServiceClientFactory` 解析熔断 / 降级 / 限流同口径）；构造参数均带缺省（`None` → `NullNotifier` / `NullRateLimiter`），既有单测与既有构造调用零改动。

### 3.3 短信发送口径 <a id="impl"></a>

**生成与存储**：

1. 生成 **6 位纯数字** 验证码（字符集 `0123456789`，长度取 `CaptchaSmsOptions.code_length`，缺省 6）。
2. 挑战存 `bms:global:captcha:{uuid}`（键拼接沿用 `build_captcha_key`），记录 JSON：`{"kind": "sms", "scene": "<场景>", "code": "<6 位数字>", "fails": 0}`；`SET key value EX policy.ttl`（缺省 300 秒）。
3. 返回 `CaptchaChallenge(captcha_id, image=b"", expires_in=policy.ttl, scene, kind=SMS, payload="", target=mask_phone(phone), cooldown=policy.cooldown)`；**`code` 绝不出现在响应**。

**通知下发（`NotificationMessage`）**：

```python
NotificationMessage(
    channel=NotifyChannel.SMS,
    recipient=phone,                       # 通知基座收件目标为真实手机号（渠道需要）
    content=SMS_CAPTCHA_TEMPLATE.format(code=code, minutes=max(1, policy.ttl // 60)),
    title="",
    biz_type="captcha",
    biz_id=captcha_id,
)
```

- `SMS_CAPTCHA_TEMPLATE = "您的验证码是 {code}，{minutes} 分钟内有效，请勿泄露。"`（基座内置中文模板；**占位不真发**，真实模板 / i18n 渲染归阶段八，登记遗留）。
- `send` 返回 `delivered=False` 或抛异常 → **删除已写入挑战**（`client.delete`，删除失败仅日志）→ 抛 `ServiceUnavailableError`（10007 / 503，不静默放行）；限流计数不回收（防借失败重试刷量）。

**冷却与限次（经 `BaseRateLimiter`，固定窗口；超限统一 `CaptchaTooFrequentError` `20103` / 429）**：

| 维度 | key（`build_rate_limit_key`，全局作用域 `tenant=None`） | 规则 |
| --- | --- | --- |
| 重发冷却 | `dimension="sms-cooldown"`，`target="{phone}:{scene}"` | `limit=1, window=policy.cooldown`（缺省 60s） |
| 账号频次 | `dimension="sms-account"`，`target=phone` | `limit=sms.account_limit, window=sms.window`（缺省 5 / 3600s） |
| IP 频次 | `dimension="ip"`，`target=current_client_ip` | `limit=sms.ip_limit, window=sms.window`（缺省 20 / 3600s；IP 缺失时跳过该维） |

- 判定用 `check`（返回决策）而非 `require`（其抛 `RateLimitError` `10005`），命中即抛 `CaptchaTooFrequentError` 并在 `data` 携带 `{"reset_after": decision.reset_after}`（提示剩余秒数）。
- **冷却不重置**：固定窗口 `INCR` + 首次 `EXPIRE`，窗口内重复请求计数递增但**不重置过期时间**，`reset_after` 保持；前端以其为倒计时依据（命中即保留原倒计时）。
- 检查顺序：冷却 → 账号 → IP；任一不过即拒（不继续后续维度）。

**脱敏回显**：目标一律 `mask_phone(phone)`（基座唯一入口，保留前 3 后 4，长度不足不原样回显）；**脱敏改经 `BaseMasker` 归 04_02**（对齐记录 #1）。

**短信选项（`[captcha].options`，`sms_` 前缀扁平键，与图形 / 滑块键无冲突）**：

| 键 | 缺省 | 约束 | 说明 |
| --- | --- | --- | --- |
| `sms_code_length` | 6 | 4 ~ 8 | 验证码位数（与前端「短信 6 位」一致） |
| `sms_account_limit` | 5 | 1 ~ 100 | 账号（手机号）窗口内上限 |
| `sms_ip_limit` | 20 | 1 ~ 1000 | IP 窗口内上限 |
| `sms_window` | 3600 | 60 ~ 86400 | 频次窗口（秒） |

解析复用 03_01 的 `_int_option`（缺省取默认、类型非整数 / 越界 → `PluginError` 装配拒启）；选项仅承载非敏感值。

### 3.4 配置契约 <a id="config"></a>

`config.toml` 的 `[captcha]` 节**结构不变**（仍 `provider` + `options`），`options` 值仍为 `{}`、仅补短信键缺省注释：

```toml

# 短信选项（非敏感；sms_ 前缀，缺省 sms_code_length=6 / sms_account_limit=5 / sms_ip_limit=20 / sms_window=3600；冷却与有效期取场景策略）
```

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 发送成功 | 挑战已写 Redis（单次有效）；返回脱敏目标 + 冷却；通知基座占位固定成功 |
| 冷却期内 / 账号或 IP 超频 | `CaptchaTooFrequentError`（**20103** / 429，`data.reset_after` 剩余秒数）；**不重置倒计时** |
| 通知渠道不可用（`delivered=False` / 抛异常） | 删除已写入挑战 → `ServiceUnavailableError`（10007 / 503，明确报错不放行） |
| Redis 不可用（写入挑战） | `ServiceUnavailableError`（10007 / 503，明确稍后重试） |
| Redis 不可用（校验） | `verify_credential` → False（不放行）；`require_credential` → `CaptchaVerifyError`（20101） |
| `generate(kind=sms)` | `ParamError`（10001，短信请经 `/captcha/sms` 端点） |
| 校验码不符 / 挑战不存在 | 复用 03_01：码不符 → 20101（可重试，`fails+1`）；不存在 / 过期 → 20102 |
| `[captcha].options` 非法 | 工厂 `PluginError`（装配拒启） |
| 路由未知场景 / 非法形态 | 沿用路由层 `ParamError`（10001），不改 |
| IP 维度值缺失 | 跳过 IP 维（不因取不到 IP 而拒绝，其余维度照常） |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **同域扩展而非替换**：`BaseCaptcha` 契约与数据契约零改动（`send_sms` 签名不变）；图形码 / 滑块行为零变化（分派后仍走各自路径），短信与图形码共用校验码比对路径。
- **`NullCaptcha` 不变**：占位三形态恒定通过；identity 既有契约用例（Kiwi 41 / 879）不受影响。
- **既有用例适配**：`test_captcha_default.py` 的 `test_unsupported_kinds_fail_closed` 与 `test_captcha_slider.py` 的 `test_sms_still_unsupported` 原断言「短信 fail-closed」随短信启用失效，改为断言 `generate(kind=sms)` → `ParamError`（**属能力演进必要适配**，仍归 Kiwi 2204 / 2205，实施记录登记）。
- **前端 `06_04`（消费方，归 03_04）**：四端点契约与响应字段（`target` 脱敏 / `cooldown` 60 / `expires_in` 300）**零改动**；仅由占位改为真实数据源，联调归 03_04。
- **登录 / 找回密码链路**：`send_sms` 的后续调用方（03_06 找回密码）零改动；登录链路 `_enforce_captcha` 不变（`policy` + `require_credential`，短信校验走 `code`）。
- **脱敏基座**：本任务沿用 `mask_phone`；**短信回显改经 `BaseMasker` 归 04_02**（需求 04-2 §5「既有场景回接：短信手机号回显（域 03-3）」已明确归口），本任务不引入 `NullMasker` 空操作漏脱敏风险。
- **后续扩展点**：03_04 把 `policy` 改读 `sys_config`（`send_sms` 自动取到按租户冷却 / 有效期）；阶段八接真实短信渠道与模板（`BaseNotifier` 调用面不变）。**不新增插件键、不改装配骨架**。
- **平台契约套件**：`DefaultCaptcha` 构造参数新增 `sms` / `notifier` / `rate_limiter`（带缺省、非必填），仍不自动登记（`test_plugin_registration` 键集不变）。

## 7. 边界与开放项 <a id="boundary"></a>

- **场景策略按租户读取**（`sys_config` 的冷却 / 有效期 / 是否强制）与**失败计数驱动「连续失败 N 次强制」**（登录侧）→ 03_04；本任务 `send_sms` 取平台默认策略、`fails` 仅记录。
- **短信模板与真实渠道**（阿里云 / 腾讯云、`sys_sms_template` / `sys_sms_log`、i18n 渲染）→ **阶段八（通知公告）**；本任务基座内置中文模板内容，`BaseNotifier` 调用面不变。
- **脱敏改经 `BaseMasker`** → **04_02**（域 04-2「既有场景回接」已明确归口）。
- **前端短信件真实数据通路与端到端联调** → **03_04**。
- **手机号格式严格校验**（运营商号段 / 国际区号）：本任务沿用路由契约 `min_length=1` + 前端校验；如需后端严格校验另立需求（避免与前端 / 渠道口径分叉）。
- **发送成功 / 失败的发送记录落库**（`sys_sms_log`）→ 阶段八；本任务不落表。
- **Kiwi 用例编号** → 测试实施时登记回填。
- **真 Redis 集成用例**依赖 `BMS_TEST_REDIS_URL`（未配置 skip）；本地以开发机 Redis 实跑并记入测试记录。
