## 1. 设计目标与范围 <a id="goal"></a>

在 `03_01` / `03_02` / `03_03`（三形态真实实现）与 `03_08`（`sys_config` 读取基座）之上，把验证码**从「可选装饰」落为「按租户策略生效的强制关卡」**：五场景策略从 `sys_config` 按租户读取、缺省回落平台默认表、变更即时生效；登录连续失败达阈值后强制验证码（窗口与成功清零）、与账号锁定阈值联动避免双重惩罚；策略端点按租户返回**可用渠道与降级顺序**；阶段四 `06_04` 验证码字段对接真实四端点（滑块新 `payload` 渲染、错误码文案核对）。

- **本任务范围**：`DefaultCaptcha.policy` 按租户读 `sys_config` + 渠道可用性；`BaseRateLimiter.peek` 只读计数；登录链路连续失败强制；`CaptchaScenePolicy` / 策略端点响应新增 `channels`；渠道降级顺序成文；前端 `core` 领域 / 能力基类、`ui-ep` 滑块件与验证码字段、开发核对页联调；测试与登记回写。
- **不在本任务**：三形态真实实现（已交付）；密码策略（`03_05`）、找回密码（`03_06`）、账号锁定管理与解锁（`03_07`）；`sys_config` 基座本身（`03_08`）；宿主业务登录页接线（归 `05_01`，其依赖本任务）。
- **接口兼容**：四端点路径与既有字段不变，**策略端点响应只增 `channels`**（只增不删）；`CaptchaScenePolicy` 数据契约尾部追加带默认值字段（向后兼容）；登录请求 / 响应不变。
- **安全影响（SDL）**：连续失败强制是防爆破闸门——专项验收点：达阈值未携带验证码拒绝（20101）、验证码校验失败**不计入**登录失败计数（不诱发误锁 / 双重惩罚）、策略按租户隔离、跨服务读失败回落平台默认（不放宽强制口径）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 场景策略按租户读取 <a id="policy"></a>

`DefaultCaptcha.policy(scene)` 改为：**读 `sys_config` 按租户键 → 缺省回落平台默认表 → 计算可用渠道**。

```python
# bms_core/captcha/base.py
CAPTCHA_SCENE_CHANNELS: Mapping[str, tuple[CaptchaKind, ...]] = {
    "login":           (CaptchaKind.SLIDER, CaptchaKind.IMAGE),
    "reset_password":  (CaptchaKind.SMS, CaptchaKind.SLIDER, CaptchaKind.IMAGE),
    "bind":            (CaptchaKind.SMS, CaptchaKind.SLIDER, CaptchaKind.IMAGE),
    "unbind":          (CaptchaKind.SMS, CaptchaKind.SLIDER, CaptchaKind.IMAGE),
    "register":        (CaptchaKind.SMS, CaptchaKind.SLIDER, CaptchaKind.IMAGE),
}
"""场景渠道降级顺序（平台默认；按渠道可用性过滤，图形码恒为兜底渠道）。"""

@dataclass(frozen=True)
class CaptchaScenePolicy(BaseObject):
    ...  # 既有字段不变
    channels: tuple[CaptchaKind, ...] = (CaptchaKind.SLIDER, CaptchaKind.IMAGE)
    """该场景可用渠道（按降级顺序；末位恒为图形码兜底）。"""

async def policy(self, scene: str) -> CaptchaScenePolicy:
    defaults = default_scene_policy(scene)
    values = await self._config.get_many((
        f"captcha.scene.{scene}.required",
        f"captcha.scene.{scene}.fail_threshold",
        f"captcha.scene.{scene}.ttl",
        f"captcha.scene.{scene}.cooldown",
        "captcha.channel.image", "captcha.channel.slider", "captcha.channel.sms",
    ))
    return CaptchaScenePolicy(
        scene=scene,
        required=_parse_bool(values.get(f"captcha.scene.{scene}.required"), defaults.required),
        fail_threshold=_parse_int(values.get(f"captcha.scene.{scene}.fail_threshold"), defaults.fail_threshold),
        ttl=_parse_int(values.get(f"captcha.scene.{scene}.ttl"), defaults.ttl),
        cooldown=_parse_int(values.get(f"captcha.scene.{scene}.cooldown"), defaults.cooldown),
        channels=_resolve_channels(scene, values),
    )
```

- `_parse_bool` / `_parse_int`：容错解析（`true/false/1/0`、整数串）；非法 / 缺失回落默认，不抛错。
- `_resolve_channels`：取 `CAPTCHA_SCENE_CHANNELS.get(scene, 默认)`，按 `captcha.channel.{kind}` 开关过滤（**IMAGE 恒保留**；短信未配默认关闭 → 图形码兜底）；未知场景回落 `(SLIDER, IMAGE)`。
- `DefaultCaptcha.__init__` 增 `config: BaseConfigSource | None = None`（缺省 `NullConfigSource`，`get_many` 返回空 → 全回落默认）；`DefaultCaptchaFactory` 经 `resolve_plugin("config_source", settings.config_source.provider)` 注入。
- `send_sms` 自动消费按租户 `policy.ttl` / `policy.cooldown`（既有调用面零改动）。
- `NullCaptcha.policy` 仍返回平台默认（其 `channels` 取默认值），契约不变。

### 3.2 失败计数只读与连续失败强制 <a id="failcount"></a>

**限流基座只读计数**（`BaseRateLimiter`）：

```python
async def peek(self, key: str) -> int:
    """读当前窗口计数（不自增、不改窗口；缺省 0）。"""
    return 0
```

- `MemoryRateLimiter.peek`：返回该 key 当前计数；`RedisRateLimiter.peek`：`GET key` → int（无 / 非数值 → 0）；异常降级 0（与降级 memory 口径一致）。
- 仅新增派生方法（非抽象），既有实现不强制覆写，向后兼容。

**登录强制**（`LoginService`）：

```python
async def _enforce_captcha(self, captcha, *, tenant: str, account: str) -> None:
    policy = await self._captcha.policy(_LOGIN_SCENE)
    fails = await self._limiter.peek(self._fail_key(tenant, account))
    required = policy.required or (policy.fail_threshold > 0 and fails >= policy.fail_threshold)
    if captcha is None:
        if required:
            raise CaptchaVerifyError("需要验证码")
        return
    ...  # 形态归一 + require_credential（不变）
```

- 调用处由 `await self._enforce_captcha(req.captcha)` 改为 `await self._enforce_captcha(req.captcha, tenant=tenant, account=req.account)`。
- **失败计数口径**：仅账号 / 密码失败经 `_record_failure` 自增（既有不变）；**验证码校验失败不计入**登录失败计数（挑战记录内 `fails` 仍自记，不驱动锁定）。
- **成功清零**：登录成功既有 `self._limiter.reset(self._fail_key(...))`（不变）。
- **与锁定联动**：验证码阈值（默认 3）< 锁定阈值 `[login].max_failures`（默认 5）；达 3 强制验证码、达 5 锁定（15 分钟窗口）——先加验证码、后锁定，避免「一失败即锁」的双重惩罚。
- **阈值口径收敛**：场景策略 `fail_threshold` 为唯一来源（`sys_config` 覆盖、缺省平台默认 3）；移除 `[login].captcha_lock_threshold`（原预留字段，从未驱动判定）与其 `config.toml` 行。

### 3.3 策略端点契约扩展 <a id="endpoint"></a>

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `channels` | `list[str]`（`image` / `slider` / `sms`） | **新增**：该场景可用渠道（按降级顺序；末位恒 `image` 兜底） |

- `CaptchaPolicyResponse` 增 `channels`；路由映射 `channels=list(policy.channels)`。
- 既有字段（`scene` / `required` / `fail_threshold` / `ttl` / `cooldown`）不变；契约「只增不删」，`identity.json` 重生成零漂移。
- **渠道降级顺序成文**：前端按 `channels` 顺序取首个「已就绪」渠道渲染；图形码恒为兜底渠道；短信渠道未配（`captcha.channel.sms=false`）时不出现——即「短信未配 → 滑块 / 图形码兜底」。默认顺序见 §3.1。

### 3.4 配置契约 <a id="config"></a>

- 删除 `[login].captcha_lock_threshold`（`LoginSettings.captcha_lock_threshold` 字段与 `config.toml` 行）：阈值改由场景策略 `captcha.scene.login.fail_threshold` 承载（`03_08` 种子默认 3，可按租户覆盖）。
- 其余无新增配置键。

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 连续失败达阈值、请求未带验证码 | `CaptchaVerifyError`（20101，提示需要验证码） |
| 连续失败达阈值、请求带验证码 | 正常 `require_credential`（通过放行 / 不通过 20101） |
| 未达阈值且未带验证码 | 按 `policy.required`（登录默认 false，放行） |
| 验证码校验失败 | 记录内 `fails+1` 可重试；**不**自增登录失败计数、不触发锁定 |
| 登录成功 | 失败计数清零（既有） |
| `sys_config` 键缺失 / 非法 / 源不可达 | 回落平台默认场景策略（读取降级不报错） |
| 渠道全部不可用（理论不出现，IMAGE 恒可用） | `channels` 至少含 `image` |

## 4. 前端联调设计 <a id="frontend"></a>
