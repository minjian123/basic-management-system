## 1. 设计目标与范围 <a id="goal"></a>

**建立「泛指 / 专指」编码命名规则，并把「租户编码」在全仓统一为可判定的命名**：

- **规则（写入《[后端开发规范](../../../../../../规范/后端开发规范.md)》命名节）**：**泛指**——实体（基础数据）**自身**的业务编码字段（每张基础数据表都有的那个）统一叫 `code`；**专指**——其他数据里**引用**某业务编码的字段，用限定名 `<业务>_code`（引用租户 → `tenant_code`）。
- **落地**：租户视图对象（`TenantContext` / `TenantSnapshot` / `TenantSummary`）承载的是租户**自身**编码 → `code`；其余一切**引用**租户编码的字段（`tenant_id` / `tenant` / 引用型 `code`）一律 → `tenant_code`；层 `CODE_FIELD` 映射退场。
- **契约键隔离**：字段是 Python 属性，契约键（事件负载键、缓存载荷键、DB 列、JWT claim、API 协议）与外层逐处显式映射/改名，不因属性改名而隐式漂移。

**范围（2026-09-28 拍板扩为「全域」口径三）**：覆盖 `backend/libs` / `backend/services` / `backend/ops` 全部 Python 标识符（字段 / 参数 / 局部变量 / 辅助函数名）、JWT claim、事件信封与发件箱键、缓存与会话载荷键、请求态键、API 协议与 query 参数、DB 列（含迁移）。**硬切不兼容**（不设新旧并存窗口）。

**不在本任务**：非租户业务编码的一般化改名（本任务只落规则，其他域按规则在各自任务处理）；`X-Tenant-ID` 请求头名（边缘身份头，单一来源 `edge/headers.py`，非本命名域）。

## 2. 命名规则（规则条文） <a id="rule"></a>

| 类别 | 判据 | 命名 | 例 |
| --- | --- | --- | --- |
| 泛指 | 实体**自身**的业务编码字段 | `code` | `sys_tenant.code`、`sys_dict_item.code`、`sys_post.code`、`sys_icon.code`、`ApiResponse.code`、验证码输入 `code` |
| 专指 | 其他数据里**引用**某业务编码的字段 | `<业务>_code` | 引用租户 → `tenant_code` |

- 一句话判据：**字段值是“本实体自己的编码” → `code`；是“指向别的实体的编码” → `<业务>_code`**。
- 真 ID（数据库主键 / 逻辑外键）不属本规则，仍用 `<实体>_id`（如 `TenantContext.tenant_id` 为租户主键）。
- 规则写入《后端开发规范》命名节（`§4 Python 编码规范` 的命名条），作为强制性约定。

### 3.3 契约 / 存储 / 运行时键 <a id="keys"></a>

| 面 | 键 | 处置 |
| --- | --- | --- |
| JWT claim | `claims["tenant"]`（服务 JWT）、`claims["tenant_id"]`（用户 / OIDC JWT） | → `claims["tenant_code"]`（签发与校验同改，硬切） |
| 事件信封 | `EventEnvelope` 序列化键 `"tenant_id"`（`events/contracts.py`、`outbox/store.py`） | → `"tenant_code"` |
| 事件负载键 | `_TENANT_PAYLOAD["tenant_code"]` | 保持（本已是精确名） |
| 缓存载荷 | `TenantSnapshot.to_payload()` 键 `"code"`（实体自身编码）/ `"tenant_id"`（主键） | 保持 |
| 请求态键 | `state["tenant_id"]`（token 租户编码） | → `state["tenant_code"]`；`state["tenant"]`（`TenantContext` 对象）保持 |
| Redis 会话载荷 | 键 `"tenant"`（`session/redis.py`） | → `"tenant_code"` |
| identity 会话 / 重置载荷 | `{"tenant": ...}`（`session_issuer` / `auth` / `password_reset`） | → `{"tenant_code": ...}` |
| 日志上下文 | `("tenant", <code>)`（`core/logging.py`） | → `("tenant_code", <code>)` |
| DB 列 | `sys_outbox.tenant_id` / `sys_event_dead_letter.tenant_id` / `sys_user_identity.tenant_id` | → `tenant_code`（Alembic 迁移，三库） |

### 3.4 局部变量与辅助函数名 <a id="locals"></a>

**改**（直接承载租户编码值）：

- 局部 / 参数：`tenant` / `token_tenant` / `flow.tenant` / `req.tenant` / `result.tenant` 等承载编码者 → `tenant_code` / `token_tenant_code`（按语义限定）。
- 辅助：`current_tenant`（contextvar）→ `current_tenant_code`；`get_current_tenant` / `set_current_tenant` → `get_current_tenant_code` / `set_current_tenant_code`；`_claim_tenant` → `_claim_tenant_code`；`_require_tenant`（返回编码）→ `_require_tenant_code`。

**不改**（命名指“租户一般概念”而非编码值）：

- `get_tenant` / `get_tenant_context` / `current_tenant_context`（返回 `TenantContext` 对象）、`resolve_request_tenant`（返回对象）、`TenantSource` / `TenantLookup`（对象）、`build_tenant_db_key` / `parse_tenant_db_key` / `tenant_database_name`（库键）、`tenant_hostname` / `is_tenant_domain` / `is_local_hostname` / `is_exempt_path`（域名与路径）、`is_tenant_code`（已是精确名）、`EdgeIdentity` / `TenantContext` 等类名。
- `state["tenant"]`（`TenantContext` 对象键）、`X-Tenant-ID` 头、`sys_tenant` 表与 `sys_tenant.code` 列、`tenant_self_service` 能力键 / 插件键、`tenant_` 库键前缀 / 事件域 `tenant` / 表前缀 `tenant_`（基础设施标识，非字段）。

## 4. 分批计划与兼容 <a id="batches"></a>

**硬切不兼容**（用户拍板）：不设新旧并存窗口；破坏面（JWT / 事件 / API / Redis / 请求态 / DB）由同一次发版同步切换，旧令牌 / 旧载荷 / 旧前端在切换后失效（dev / 单机，可接受）。

| 批次 | 内容 | 破坏面 | 验证 |
| --- | --- | --- | --- |
| ① | 规则入规范 + §3.1 / §3.2 属性面 + §3.4 局部/函数 + `CODE_FIELD` 退场 + 事件负载键映射常量 | 无 | 定向 pytest / ruff / pyright / 基座护栏 |
| ② | §3.3 JWT claim 与请求态 / Redis / 日志键 | 令牌与运行时会话 | identity 定向 pytest |
| ③ | §3.3 事件信封 / 发件箱键 | 跨服务事件 | events / outbox 定向 pytest |
| ④ | §3.3 API 协议（schemas 与 query） + 前端 api-types / 契约快照重生成 | API 契约 | 契约快照 export/check / 前端类型 |
| ⑤ | §3.2 DB 列 + 模型 + Alembic 迁移（三库）+ 数据库设计回写 | 存储 | 迁移链护栏 / 迁移实跑 |
| ⑥ | 收口回归与记录 | — | 全量定向 pytest + 门禁 |

> 批次顺序按「进程内 → 运行时键 → 事件 → 对外协议 → 存储」推进，每批独立提交、独立验证，保证任一时刻仓库可运行。

## 5. 影响与迁移 <a id="impact"></a>

- **运行时不变量**：改名不改运行语义；值对象 / 数据契约的字段与默认值仅换名，`frozen` / dataclass 语义不变。
- **契约快照**：API 协议改名会使 `deploy/contracts/*.json` 漂移 → 随批次 ④ 用 `ops/contract_snapshot.py export` 重生成；前端 `api-types` 同步重生成。
- **数据库**：批次 ⑤ 生成 Alembic `op.alter_column(..., new_column_name="tenant_code")`（三套方言链），同步改模型 `mapped_column` 与《数据库设计》表文件（含「变更记录」）；**表文件 → 模型 → 迁移 → 总览状态**顺序不可倒置。
- **令牌**：批次 ② 改 claim 名，签发与校验同批切换；切换前签发的令牌失效（重登）。网关（APISIX）经 `X-Tenant-ID` 头传租户、不解析该 claim，不受影响。
- **事件**：批次 ③ 改信封键，生产者 / 消费者同批切换；发件箱存量记录的键随重启后新写生效（存量兼容由硬切口径接受）。
- **测试**：受影响用例随批随更；新增术语护栏用例（见 §6）。
- **零新增能力域 / 插件键**：不新增插件键（`_EXPECTED_PLUGIN_KEYS` 不变）。

## 8. 边界与开放项 <a id="boundary"></a>

- **非租户域的一般化改名不在本任务**：规则本任务写入规范，其他域（如 `DictItem.parent_id` 实际存 value 等）按规则在各自任务处理，避免本任务边界失控。
- **硬切风险**：JWT / 事件 / API / Redis / DB 硬切，切换瞬间旧令牌 / 旧载荷 / 旧前端失效；dev 单机接受，生产切换须择停机窗口（运维阶段）。
- **`{tenant_code}:{provider_key}`（`sys_user_identity.idp_key` 格式串）保留**：属已落库数据格式，改名会使存量映射键失效；本任务是字段名统一，不改数据格式。
- **`X-Tenant-ID` 头与 `sys_tenant` 表名 / 列名 `code`**：基础设施标识，不在本命名域。
- **`tenant` 局部变量改名的边界**：以「值是否为租户编码」判定；无法确定处按最小改动原则保留并在实施记录登记。
