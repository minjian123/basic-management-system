## 1. 设计目标与口径依据 <a id="goal"></a>

**确立「按值命名」的编码字段命名规则，并把租户视图对象的自身编码统一为 `code`**：

- **命名规则（写入《[后端开发规范](../../../../../../规范/后端开发规范.md)》命名节）**：① 实体（基础数据）**自身**业务编码 → `code`；② **租户主键（雪花 id，全系统唯一且不可变）** → `tenant_id`；③ **租户业务编码**（人为编码，可变 / 软删后可复用，仅作外部 / 边界标识） → `tenant_code`；④ 真 ID → `<实体>_id`。**判据是字段实际承载的值，不得名实不符。**
- **落地**：`TenantContext.tenant_code` → `code`（租户视图对象承载的是租户**自身**编码，与 `TenantSnapshot.code` / `sys_tenant.code` 一致），租户链层 `BaseTenantViewContract` 公共段纳入 `code`、`CODE_FIELD` 映射**退场**。
- **契约键隔离**：事件负载键 `tenant_code`（`_TENANT_PAYLOAD`）保持不变，以事件侧常量 `TENANT_CODE_PAYLOAD_KEY` 单一来源承接。

**范围边界（2026-09-28 拍板）**：本任务**只做无争议部分**——命名规则 + 租户视图对象自身编码 + `CODE_FIELD` 退场 + 契约键显式映射。**不改**内部链路的租户标识（JWT claim / 事件信封 / 发件箱 / 请求态键 / API 协议 / DB 列）——租户编码**可变更、可复用**，不应作内部稳定键；「内部标识改以雪花 `tenant_id` 为准」的**架构改造另立[需求域 10](../../../../需求/10_需求_租户标识内部化.md)**。

> **背景（一轮过度改名的教训）**：曾把「内部链路里装租户编码 `code`、却名为 `tenant_id`」的字段一律改名为 `tenant_code`（批次 ②~⑥，含 JWT / 事件 / 请求态 / API / DB 列）。经复核，这些字段是**内部租户标识**、其正确归属应是雪花 id（需求域 10 处理），**改名是治标**；且该改名牵连 JWT / 事件契约 / DB 迁移 / 前端类型等破坏面，故**整体回退**，仅保留本任务无争议部分。

## 3. 改名与契约 <a id="contract"></a>

| 项 | 口径 |
| --- | --- |
| `TenantContext.tenant_code` | → `code`（租户**自身**编码，进 `BaseTenantViewContract.COMMON_FIELDS`） |
| `TenantSnapshot.code` / `TenantSummary.code` / `SysTenant.code` | 保持（本就为实体自身编码） |
| `BaseTenantViewContract.CODE_FIELD` | **删除**（层不提供同名读取属性，避免与 `TenantSnapshot.code` 冲突） |
| 事件负载键 `_TENANT_PAYLOAD` | 保持 `tenant_code`；以 `TENANT_CODE_PAYLOAD_KEY` 常量承接（对象字段 `code` ↔ 负载键 `tenant_code` 显式映射） |
| `UserInfoResult.sub` → `subject` | 09_03 已交付，本任务不重复 |

**失败分支**：漏改（仍 `tenant_code` 属性引用）由 `pyright` 严格模式拦截；事件负载键被误改由用例拦截（断言键仍为 `tenant_code`）。

## 6. 边界与开放项 <a id="boundary"></a>

- **内部租户标识（JWT / 事件 / 请求态 / API / DB）不改**：归[需求域 10](../../../../需求/10_需求_租户标识内部化.md)（内部以雪花 id 为准）——本任务只做命名与视图对象自身编码。
- **`X-Tenant-ID` 头 / 子域名 / 登录请求体 `tenant`**：外部标识，保持 code；其命名与内部标识改造随需求域 10 统一评估。
- **`{tenant_code}:{provider_key}`（`sys_user_identity.idp_key` 格式串）**：已落库数据格式，不动。
