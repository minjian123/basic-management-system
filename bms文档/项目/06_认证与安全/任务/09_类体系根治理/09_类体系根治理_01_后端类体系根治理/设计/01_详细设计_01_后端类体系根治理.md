## 1. 设计目标与范围 <a id="goal"></a>

**消灭上帝基类**：把 `BaseObject` 从「什么类都挂的万能父类」收敛回**唯一根系**——只承载所有类共有的最小语义；新增三个**体系基类**（不可变值对象 / 可变数据契约 / 框架对象）承接各自体系的公共语义，既有框架类基类统一改挂框架对象体系，继承链固定为**四段**；并以**继承链护栏 + 基线递减**把「除体系根外禁止直继承」变成可执行口径，**目标零直继承**。

- **本任务范围**：`core/objects.py` 三个体系基类；既有框架类基类与数据契约类基类的**改挂**（`BasePlaceholder` / `BaseCapability` / `BaseAsyncResource` / `BaseLogger` / `BaseRouter` / `BaseSchema` / `BaseModel`）；**体系根收敛为 7 个**；`check-backend-base` 新增「直继承合法性」检查（白名单＝清单 §10 新增的「体系根清单」小节）与基线快照；`backend/ops` 纳入清单对账范围并补登未登记类；160 处直继承存量盘点与分批建议；架构 04 / 后端开发规范 / 后端基类清单口径回写。
- **不在本任务**：**160 处存量归位**（按体系与模块分批另立任务，见[计划 §7](../../../../计划/01_计划_认证与安全.md#followup)）；前端框架对象层（[09_02 前端框架层对称](../../09_类体系根治理_02_前端框架层对称/09_类体系根治理_02_前端框架层对称.md)）。
- **接口兼容**：不新增 / 不修改任何能力域契约与运行时行为；改挂仅**上移公共语义的承载层**（`object_kind` / `aclose` 钩子位等），既有子类方法签名与语义不变；不新增插件键（`_EXPECTED_PLUGIN_KEYS` 不变）。
- **安全影响（SDL）**：本任务为**架构治理**，不直接处理敏感数据；价值在于恢复「公共语义单点维护」能力——避免各体系在根系上堆叠差异语义造成的隐性耦合（含脱敏 / 日志 / 鉴权等横切语义的落点漂移）。

### 1.1 现状与缺口 <a id="gap"></a>

**继承链现状（改造前）**：

```text
BaseObject（根系）
├── BasePlaceholder → BaseNullObject / BaseStub
├── BaseCapability(ABC) → BaseProvider / BasePluggable
├── BaseAsyncResource(ABC)
├── BaseLogger(ABC)
├── BaseRouter(APIRouter)
├── BaseSchema(pydantic.BaseModel)
├── BaseModel(sqlalchemy DeclarativeBase)
├── BaseSorted(ABC) → BaseConcurrentSorted → ConcurrentSorted*
├── RedisSortedSet / RedisSortedDict / RedisSnapshot
├── BaseRepository(ABC) → BaseScopedRepository → …
├── BaseService → BaseTransactionalService
└── UnitOfWork(ABC)
+ 其余 160 个「乱挂在根系上」的业务 / 数据 / 框架类
```

| # | 缺口 | 影响 |
| --- | --- | --- |
| 1 | **`BaseObject` 被当上帝基类**：171 个类直继承（值对象 110 / 可变数据类 3 / 框架类 58） | 各体系差异语义无处承载，公共配置（frozen / 生命周期 / 标识）逐类重复，「公共字段与方法只在链上基类维护」落空 |
| 2 | **框架类无体系层**：`BaseCapability` / `BaseAsyncResource` / `BasePlaceholder` / `BaseLogger` / `BaseRouter` 各自直挂根系 | 框架对象（非数据对象）的公共语义（不参与值语义 / 序列化、标识、生命周期钩子）无落点 |
| 3 | **数据类无体系层**：Pydantic 契约（`BaseSchema`）、ORM 模型（`BaseModel`）与普通 dataclass 三方各自直挂 | 「数据契约体系」裂成三处，值语义与可变语义无从区分 |
| 4 | **护栏缺口**：`check-backend-base` 只检查「直继承类**是否登记**清单」，**不检查直继承本身是否合法** | 新类继续直挂根系不会被拦；「体系根」概念不存在于校验口径 |
| 5 | **`backend/ops` 不在对账范围**：`SOURCE_DIRS` 仅 `backend/libs` + `backend/services` | `ops/` 4 个直继承类长期未登记、无归属 |
| 6 | **存量无台账**：160 处直继承类无归位建议 | 无法分批收敛 |

**实测（2026-09-28，AST 只读测绘）**：直继承 `BaseObject` 共 **171** 个——`bms_core` 138 / `services` 29 / `ops` 4；形态：`frozen dataclass` 110 / 非 frozen `dataclass` 3 / 普通类 58。其中够格当体系根的 **7 个**，其余 **164 个**（含框架类基类 5 个与数据契约基类 2 个在本任务改挂）必须归位。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 三个体系基类（`core/objects.py`） <a id="objects"></a>

```python
@dataclass(frozen=True)
class BaseValueObject(BaseObject):
    """不可变值对象体系基类：frozen 语义 + dataclass 相等 / 哈希。"""

@dataclass
class BaseDataContract(BaseObject):
    """可变数据契约体系基类（Pydantic 契约 / ORM 模型 / 普通数据类共用归口）。"""

class BaseFrameworkObject(BaseObject):
    """框架对象体系基类：非数据对象（不参与值语义与序列化输出）。"""

    object_kind: ClassVar[str] = "framework"
    """框架对象统一标识（子层覆写，如 `capability` / `middleware` / `registry`）。"""

    async def aclose(self) -> None:
        """可选生命周期钩子位（默认空操作；`BaseAsyncResource` 覆写为抽象）。"""
```

| 契约点 | 口径 |
| --- | --- |
| `BaseValueObject` | `@dataclass(frozen=True)` 基类——子类继续以 `@dataclass(frozen=True)` 声明字段，继承 frozen / 相等 / 哈希语义基线；序列化沿用 `BaseObject.to_dict`（实测：frozen 链 `eq` / `hash` 正常） |
| `BaseDataContract` | `@dataclass`（可变）基类；**实测**：作为混入父类与 `pydantic.BaseModel` / `sqlalchemy.DeclarativeBase` 组合**无冲突**（`BaseSchema(BaseModel, BaseDataContract)`、`BaseModel(Base, BaseDataContract)` 均可用） |
| `BaseFrameworkObject` | 非数据对象语义（**约定**：框架对象不参与值语义与序列化输出，不作 data 传输）；`object_kind` 统一标识；`aclose` **非抽象**默认空操作钩子位（`BaseAsyncResource` 覆写为抽象，避免层级重复定义） |
| 三者共同 | 均**直接继承 `BaseObject`**（它们是体系根）；除体系根外**禁止直接继承 `BaseObject`** |

### 3.2 继承链四段落地（本任务改挂清单） <a id="migration"></a>

| 类 | 现状 | 改造后 | 体系 |
| --- | --- | --- | --- |
| `BasePlaceholder` | `(BaseObject)` | `(BaseFrameworkObject)` | 框架对象 |
| `BaseCapability` | `(BaseObject, ABC)` | `(BaseFrameworkObject, ABC)` | 框架对象 |
| `BaseAsyncResource` | `(BaseObject, ABC)` | `(BaseFrameworkObject, ABC)` | 框架对象 |
| `BaseLogger` | `(BaseObject, ABC)` | `(BaseFrameworkObject, ABC)` | 框架对象 |
| `BaseRouter` | `(APIRouter, BaseObject)` | `(APIRouter, BaseFrameworkObject)` | 框架对象 |
| `BaseSchema` | `(pydantic.BaseModel, BaseObject)` | `(pydantic.BaseModel, BaseDataContract)` | 数据契约 |
| `BaseModel` | `(DeclarativeBase, BaseObject)` | `(DeclarativeBase, BaseDataContract)` | 数据契约 |
| `BaseSorted` / `BaseRepository` / `BaseService` / `UnitOfWork` | 直继承 `BaseObject` | **不变**（各自体系根） | 集合 / 仓储 / 服务 / 事务 |

**改造后继承链**：

```text
BaseObject（根系 · 唯一）
├── BaseValueObject（值对象体系根）
├── BaseDataContract（数据契约体系根）→ BaseSchema(pydantic) / BaseModel(ORM)
├── BaseFrameworkObject（框架对象体系根）
│   ├── BasePlaceholder → BaseNullObject / BaseStub
│   ├── BaseCapability → BasePluggable → BaseProviderRegistry
│   ├── BaseAsyncResource
│   ├── BaseLogger
│   └── BaseRouter(APIRouter)
├── BaseSorted（集合体系根）→ BaseConcurrentSorted → ConcurrentSorted*
├── BaseRepository（仓储体系根）
├── BaseService（服务体系根）
└── UnitOfWork（事务体系根）
```

**四段口径**：`BaseObject`（总基类 / 根系）→ `BaseFrameworkObject`（框架对象层）→ **能力域基类** → **插件基类**（`BaseCapability → BasePluggable`），即「固定四段」；各体系其余链（仓储 / 服务 / 集合 / 数据契约）在体系根之后按需延伸。

### 3.3 体系根清单与白名单解析 <a id="roots"></a>

**权威来源**：《后端基类清单》§10 内新增小节「**体系根清单（允许直接继承 `BaseObject`）**」，每行一个体系根：

```markdown
- `BaseValueObject`：值对象体系
- `BaseDataContract`：数据契约体系
- `BaseFrameworkObject`：框架对象体系
- `BaseSorted`：集合体系
- `BaseRepository`：仓储体系
- `BaseService`：服务体系
- `UnitOfWork`：事务体系
```

**护栏解析**：`parse_root_bases()` 取该小节内的 `- \`ClassName\`：` 行提取类名集合（若小节缺失或少于 1 项 → 报错退出，避免白名单静默为空导致全线失败）。**共 7 个体系根**。

### 3.4 护栏扩展（`check-backend-base.py`） <a id="guard"></a>

| 新增检查 | 语义 |
| --- | --- |
| `check_direct_inheritance` | 扫描目标内**直接继承 `BaseObject`** 的类：∈ 体系根清单 → 放行；∈ 基线快照 → 放行并计数；否则 → 违规（`[直继承]` 前缀，报文件 + 类名 + 建议归位体系） |
| 清单对账范围 | `SOURCE_DIRS` 增 `backend/ops`（`ops/` 4 个直继承类纳入登记对账） |
| 私有类口径 | `_` 前缀私有类**不要求登记清单**（沿用既有跳过规则），但**仍受直继承护栏约束**（须归位或入基线） |
| 自测矩阵 | `--self-test` 增：体系根放行 / 非体系根直继承拦截 / 基线内放行 / 基线缺失时全量拦截 / 白名单小节缺失即报错 |

**基线快照**（`deploy/boundaries/direct_base_object_baseline.json`）：

```json
{
  "version": 1,
  "generated_at": "2026-10-08",
  "entries": [
    { "file": "backend/libs/bms_core/src/bms_core/captcha/base.py", "class": "CaptchaChallenge", "target_system": "value_object", "count": 1 }
  ]
}
```

| 字段 | 语义 |
| --- | --- |
| `file` / `class` | 定位存量直继承类（比对键，`count` 聚合同名重复） |
| `target_system` | 拟归位体系（`value_object` / `data_contract` / `framework_object` / `collection` / `repository` / `service` / `unit_of_work`） |
| `count` | 同 `(file, class)` 出现次数 |

判定：**新增直继承即失败**；基线残留（已归位）仅**提示递减**，由维护者按盘点报告逐批重写（与 08_01 同名机制）。

### 3.7 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 白名单小节缺失 / 空 | `check-backend-base` 报错并退出 `1`（**不静默放行**） |
| 基线条目字段缺失 / 版本非 1 | 报错退出 `1`（fail-fast） |
| 基线文件缺失 | 视为空基线：全部直继承（除体系根）即违规（提示先按盘点建立基线） |

| 基线残留（已归位未更新） | 输出提示行，不影响退出码 |
| 改挂后既有断言失败 | 视为缺陷，修正实现（不得放宽断言） |

## 4. 兼容性与影响 <a id="compat"></a>

- **运行时零行为变更**：改挂仅改变父类链，既有子类方法与签名不变；`BaseFrameworkObject.aclose` 默认空操作不影响既有 `BaseAsyncResource` 抽象语义；`@dataclass` 混入已**实测**与 Pydantic / SQLAlchemy 兼容。
- **契约用例影响**：既有继承链断言（Kiwi 用例中 `issubclass(X, BaseObject)` 等）仍成立（四段仍是 `BaseObject` 的传递子类）；仅「父类直挂」类断言需按新链同步（如断言 `BaseCapability` 直继承 `BaseObject` 的写法）。
- **清单/架构回写**：《后端基类清单》§2 分层总览（新增「体系基类」行、中间层改挂）、§10 继承链与代码位置（四段 + 体系根清单）；架构 04 §3/§4（四段与体系根）；《后端开发规范》§3.1（严禁上帝基类 + 四段）。
- **后续扩展点**：160 处存量按体系分批归位；新增类必须经所属体系基类落地（护栏拦截）。
- **CI/预检**：`check-backend-base` 已在 preflight `--fast` 与 CI `base-integrity` 中，扩展后自动生效。

## 7. 边界与开放项 <a id="boundary"></a>

- **160 处存量归位** → 分批另立任务（计划 §7 第 26 项）；本任务只交付基类 / 护栏 / 基线 / 盘点。
- **前端框架对象层** → [09_02](../../09_类体系根治理_02_前端框架层对称/09_类体系根治理_02_前端框架层对称.md)。
- **`BaseFrameworkObject` 的「不参与序列化输出」为约定而非强制**（不覆写 `to_dict`，避免破坏既有行为）；如需硬约束（如覆写抛错），另立评估。
- **集合体系内部仍有直挂**（`RedisSortedSet` / `RedisSortedDict` / `RedisSnapshot` 直挂根系）：归位（挂 `BaseSorted` 或集合体系内新层）属**存量归位**范围，本任务入基线并登记拟归位体系。
- **`backend/ops` 纳入清单对账**后，`ops/` 内新增直继承类同样受护栏约束。
- **Kiwi 用例编号** → 测试实施时登记回填。
