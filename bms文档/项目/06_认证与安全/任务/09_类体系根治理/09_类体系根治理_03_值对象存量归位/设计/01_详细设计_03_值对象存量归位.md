## 1. 设计目标与范围 <a id="goal"></a>

**让「值对象体系」一次收口**：把直继承 `BaseObject` 的 **110 个不可变值对象**改挂 [09_01](../../09_类体系根治理_01_后端类体系根治理/09_类体系根治理_01_后端类体系根治理.md) 交付的值对象体系根 `BaseValueObject`，使这批类不再直挂根系；直继承存量基线由 **160 条递减到 50 条**（余量＝数据契约 3 + 框架对象 47），向「除体系根外零直继承」的验收目标推进第一步。

- **本任务范围**：110 处改挂（66 个源文件）+ 《后端基类清单》§10 同步链改写 + 基线递减 + [存量归位盘点报告](../../09_类体系根治理_01_后端类体系根治理/实施/02_存量归位盘点报告_01_后端类体系根治理.md)台账回写 + 测试（Kiwi 先登记）。
- **不在本任务**：08 裸集合存量「批次 1」（7 处类字段裸集合，另立任务）；09 批次 2 数据契约（3 处）/ 批次 3 框架对象（47 处）；体系基类与护栏本身（09_01 已交付）。
- **接口兼容**：**零运行时行为变更**——只替换父基类与同步 import，不改字段、方法、`frozen` 声明与任何调用点；不新增 / 不修改能力域契约；不新增插件键（`_EXPECTED_PLUGIN_KEYS` 不变）。
- **安全影响（SDL）**：本任务为**架构治理**，不处理敏感数据；价值在于让「值对象公共语义（不可变 / 相等 / 哈希 / 序列化口径）」有唯一维护落点——后续如需统一调整值对象语义（如新增不可变校验、序列化脱敏约定），改一处即可全链生效。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 改挂规则（仅改声明） <a id="rules"></a>

| 项 | 口径 |
| --- | --- |
| 类声明 | `class X(BaseObject)` → `class X(BaseValueObject)`（**只换父名**；不改基类列表其余项、不改类名、不改装饰器） |

### 3.2 语义等价（frozen 链） <a id="semantics"></a>

`BaseValueObject` 是**无字段**的 `@dataclass(frozen=True)` 体系根。子类 `@dataclass(frozen=True) class X(BaseValueObject)` 的 dataclass 处理结果与 `class X(BaseObject)`（`BaseObject` 非 dataclass）**完全一致**：

| 语义点 | 说明 |
| --- | --- |
| 字段集 / `__init__` | 由子类自身声明生成；父类无字段 → 签名与默认值完全相同 |
| `__eq__` / `__hash__` | `@dataclass(frozen=True)` 由子类生成（按字段元组 + 同类型判定），不因父类是 dataclass 而改变 |
| `__repr__` / `__str__` / `to_dict` / `to_json` | 沿用 `BaseObject` 实现（经继承链传递，未覆写） |
| `isinstance(x, BaseObject)` / `issubclass(X, BaseObject)` | 仍然成立（`BaseValueObject` 继承 `BaseObject`） |

**实测前提**（2026-09-28 全量扫描）：110 处全部满足「`@dataclass(frozen=True)` + 单继承 + 无子类」——不存在「非 frozen 子类继承 frozen 父类」的跨层报错，也不存在「子类 MRO 依赖直挂根系」的情形。

### 3.3 清单 §10 链改写 <a id="manifest"></a>

《[后端基类清单](../../../../../../后端基类清单.md)》§10 的链式为**子 → 父**（`check-backend-base` 按 `A → B` 校验「`A` 的父类含 `B`」），因此归位后必须逐处把涉及类的 `→ BaseObject` 改为 `→ BaseValueObject`：

| 项 | 口径 |
| --- | --- |
| 改写范围 | §10 中承载本批 110 个类名的历史链条目（含一行登记多类、以 `、` 分组的写法） |
| 改写方式 | 按「每类名独立反引号 + 短横线箭头」形态整体替换，**逐条核对**，避免误伤同行的框架对象 / 数据契约类（同文件中两类不同体系） |
| 「存量链路口径」注 | 处数由「164」更正为「50」＝当前基线条目数（随批次递减，与本批基线一致） |
| 校验 | `check-backend-base.py .`（继承链对账 + 直继承合法性）全通过 |

### 3.4 基线递减 <a id="baseline"></a>

cd bms && python3 scripts/tools/base-check/check-backend-base.py . --update-baseline   # 160 → 50

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 漏改（仍直继承 `BaseObject`） | 护栏「直继承合法性」报 `[直继承]` 并退出 1；继承链对账报「应为 `BaseValueObject` 子类」 |
| 误改（把框架对象 / 数据契约类也改挂） | 护栏对账 / 继承链对账报错；定向回归失败（`BaseObjectStorage` 等链上类少一层框架对象语义） |
| import 缺失或多余 | `ruff check`（F401 / F821）+ `pyright` 报错；`pytest` 导入即失败 |
| 混合文件漏留 `BaseObject` import | `ruff` F821 / 导入报错（同文件其余直继承类解析失败） |
| 基线未同步 | 护栏不报错但基线残留提示；验收要求 `--update-baseline` 后条目数 50 且零漂移 |

## 4. 兼容性与影响 <a id="compat"></a>

- **运行时零行为变更**：仅父类链变更；值对象的构造、比较、哈希、序列化与异常行为不变（§3.2）。
- **既有断言仍成立**：用例中 `issubclass(X, BaseObject)`、`isinstance(x, BaseObject)`、`BaseObject.to_dict` 输出等断言不受影响；仅「`X.__bases__ == (BaseObject,)`」型断言（若有）需按新链修正——本轮实测未见此类断言，若回归暴露则按缺陷修正实现而非放宽断言。
- **护栏与对账**：`check-backend-base` 第 2 项「清单登记对账」对本批类**不再要求**（其父类已非 `BaseObject`），但 §10 链登记与 §2 分层总览登记照旧保留（清单是类归属的唯一台账）。
- **裸集合护栏**：本任务不触碰任何注解与签名 → `check-bare-collections` 命中数不变（554 处）。
- **前端 / 契约快照**：不涉及接口契约与前端生成件，无回归面。
- **CI / 预检**：`check-backend-base` 已在 `preflight --fast` 与 CI `base-integrity` 中，基线递减后自动生效，无配置改动。

## 7. 边界与开放项 <a id="boundary"></a>

- **08 裸集合批次 1（7 处）不并入**（本任务口径「只改父基类不改行为」）：`MigrationChain.tables` / `MaskerOptions.rules` / `OutboxRecord.payload` / `DeadLetterRecord.payload` / `ServiceRequest.json_body` / `EventEnvelope.payload` / `BaseRepository.sortable_fields` → 08 域另立批次任务。
- **余 50 处（数据契约 3 + 框架对象 47）** → 09 后续批次（批次 2 数据契约 / 批次 3 框架对象）；其中框架对象多为插件基类链成员，需逐类判定「非数据对象」语义，故不与值对象同批。
- **归位体系判定仍为启发式**（`target_system` 由 dataclass 形态推导）：本批 110 处逐类复核后**全部为 frozen dataclass**，判定与形态一致，无 `target_system` 修正。
- **`BaseValueObject` 仍无字段**：如后续需为值对象体系增加公共字段（如统一版本位），属体系根语义变更，另立评估。
