## 1. 目标与范围 <a id="goal"></a>

把基线快照 `deploy/boundaries/direct_base_object_baseline.json` 中**剩余的 50 处直继承 `BaseObject`** 全部归位，使基线递减至 **0**（需求 09-1 验收目标「除体系根外零直继承」）：

| 体系 | 处数 | 区域分布 |
| --- | --- | --- |
| 可变数据契约 → `BaseDataContract` | **3** | `bc/audit/base.py`（`FieldChange`）/ `bc/events/base.py`（`EventEnvelope`）/ `bc/sharding/base.py`（`ShardBinding`） |
| 框架对象 → `BaseFrameworkObject` 及其下能力域基类 | **47** | `bms_core` 30 / `identity` 12 / `org` 3 / `tenant` 2 |

**取证结论（实测，2026-09-28）**：数据契约 3 处**全部是** `@dataclass`（未 frozen）单继承 → 改挂 `BaseDataContract` 语义成立且机械；框架对象 47 处**全部是**普通类（无 `@dataclass`、无字段注解）→ 符合「非数据对象」约定，但**落点需逐类判定**（是否适配既有能力域基类）。

## 2. 落点判定规则 <a id="rule"></a>

按**优先级**判定，逐类给出依据并登记《后端基类清单》§10：

1. **既有能力域基类**（语义**完全**匹配才用；实测可用的候选）：
   - `BaseProviderRegistry[ItemT]`（`core/provider.py`，挂 `BasePluggable`）：提供者登记 + 唯一性 + 未命中语义；要求实现抽象 `_provider_key`；
   - `BaseCollection`（`core/collections.py`，集合体系唯根；随 08 域唯一链收口）与 `BaseSorted`（有序公共段：`to_list` / `__iter__`）：有序集合契约；
   - `CacheRegion`（`cache/base.py`，挂 `BasePluggable`）：缓存区域；
   - `BaseRepository` / `BaseScopedRepository`（白名单体系根）：仓储；
   - `BaseAsyncResource`（挂 `BaseFrameworkObject`）：异步资源与生命周期。
2. **`BaseFrameworkObject`（默认落点）**：语义为「非数据对象」（不参与值语义与序列化输出）+ `object_kind` 统一标识 + 可选 `aclose` 生命周期钩子位。
3. **新增能力域基类（`BaseFrameworkObject` 之下）**：仅当**同族 ≥3 类**共享公共段且既有基类均不匹配时新增；新增须在《后端基类清单》登记并给出公共段与断言（本批次预判 1 个：**`BaseMiddleware`**，5 个中间件共享 ASGI/`dispatch` 公共段）。

**明确不适配（实测）**：`BaseService[ModelT]` 的 `__init__(repository)` 绑定仓储 CRUD 语义，本批 14 个 `*Service` 多为**编排服务**（登录 / SSO / OIDC / 会话 / 锁定），构造不接仓储 → **不挂 `BaseService`**，按规则 2 挂 `BaseFrameworkObject`（若实施中发现同族共享公共段，再按规则 3 加层）。

## 5. 特殊项与风险 <a id="risk"></a>

| 项 | 说明与处置 |
| --- | --- |
| `BizError`（错误体系根） | 改父类会顺延**全部**错误类的 MRO（`BizError` / 段位基 / 具体错误码）→ 单独提交 + 错误段位与 `isinstance` 回归（`check-backend-base` 错误码段位项 + 错误域用例） |
| 服务类不挂 `BaseService` | 实测 `BaseService[ModelT].__init__(repository)` 绑定仓储 CRUD；编排服务挂它会引入无关语义 → 一律 `BaseFrameworkObject`（不臆造能力域基类） |
| 新增 `BaseMiddleware` | 5 个中间件公共段 = 「ASGI 调用约定（`__call__` / `dispatch`）+ 可读 `key`」；新增后须登记《后端基类清单》+ 用例断言公共段在 5 个成员上成立；若实施确认公共段不成立 → 退回 `BaseFrameworkObject` 并回写设计 |
| 待确认项（21 处标「待确认」） | 实施期逐类读实现后定论：**适配既有能力域基类**（`BaseProviderRegistry` / `BaseCollection` / `BaseHttpClient` / `BaseScopedRepository` / `CacheRegion`）或回落 `BaseFrameworkObject`；结论逐条回写本表（集合体系成员的最终归属随 08 域唯一链收口：`RedisSorted*` → `BaseAsyncSorted`、`RedisSnapshot` → `BaseCacheSnapshot`） |
| 行为零变更 | 除按框架对象语义补 `object_kind`（及必要的 `aclose`）外**不改任何逻辑**；`object_kind` 取值按模块域命名并与清单登记一致 |
| 多父类类 | 仅 `BizError`（`BaseObject, Exception`）一处；改挂后保持 `Exception` 在继承列表 |

## 6. 测试口径 <a id="test"></a>

1. **Kiwi 用例（先登记取号、后写自动化）**：断言 50 处均已改挂对应体系根 / 能力域基类、均不再直继承 `BaseObject`、**基线递减至 0**；`BizError` 仍为 `Exception` 子类且错误段位判定不变。
2. **台账用例**：沿用 09_03 `tests/core/test_value_object_roots.py` 的台账范式（本批为框架对象 / 数据契约侧：断言父基类名 ∈ 白名单体系根 + 能力域基类集合）。
3. **新增基类用例**：`BaseMiddleware`（若落地）公共段在全部成员上成立。
4. **定向回归**：错误域 / 中间件与请求链路 / 插件装配 / 字典与配置 / 事件与发件箱 / identity 登录与 SSO / org 用户 / tenant 注册等受影响子域；**全量** `uv run pytest -q`；`ruff` / `format` / `pyright` / 基座 6 项 / `check-links` / `check-status` / `preflight`。

## 7. 清单与护栏收口 <a id="manifest"></a>

1. 《后端基类清单》§10 逐处改写历史链（`→ BaseObject` → 落点基类）并拆链；同步 §1「体系根白名单」（新增 `BaseMiddleware` 时）与「存量链路口径」处数（50 → 0）。
2. 基线用 `check-backend-base.py . --update-baseline` 递减（**不得手工删除条目**），每批次递减后立即跑护栏确认。
3. 09_01《存量归位盘点报告》§3 批次 2/3 状态与「当前余量」随实施更新（基线即台账）。
