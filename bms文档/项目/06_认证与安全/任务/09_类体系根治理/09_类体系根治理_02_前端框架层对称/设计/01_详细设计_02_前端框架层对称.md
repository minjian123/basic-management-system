## 1. 设计目标与范围 <a id="goal"></a>

前端基类体系当前为「**总基类 → 能力域基类 → 插件基类**」三段 + 组件根，而后端已随 [09_01](../../09_类体系根治理_01_后端类体系根治理/09_类体系根治理_01_后端类体系根治理.md) 落地**四段**（`BaseObject → BaseFrameworkObject → BaseCapability → BasePluggable`）。本任务在前端**插入同名的框架对象层**，使前后端**逐段对称**（[09_01 设计](../../09_类体系根治理_01_后端类体系根治理/设计/01_详细设计_01_后端类体系根治理.md) §3.2 的对称口径由「固定前三段」修订为「固定四段」）。

- **本任务范围**：新增 `BaseFrameworkObject`（前端框架对象层基类，落 `base/framework-object.ts`）；框架类基类改挂（`BaseCapability` / `BaseAsyncResource` / `BasePlaceholder`）；`src/index.ts` 具名导出；《前端基类清单》口径与全量登记表回写；《架构设计 · 后端基础类体系》前后端对称句补全；守卫用例与契约用例同步（vitest）。
- **不在本任务**：前端**数据/契约体系层**（`BaseApi` / `BaseDataObject` / `BaseEntity` / `BasePageQuery` 仍直挂 `BaseObject`——前端无「数据契约」体系根，属**已知差异**，登记遗留）；组件侧链（组件根 → 能力基类 → 组件基类）层序不变；「禁止直接继承 `BaseObject`」的**前端护栏**（后端已由 `check-backend-base` 硬校验；前端如需同口径护栏，另立任务）。
- **接口兼容**：不新增 / 不修改任何运行时能力（能力键、插件键、注册表语义不变）；仅**上移公共语义的承载层**（新增 `objectKind` 统一标识），既有子类方法与签名不变。
- **与 09_01 的关系**：`09_01` 为前置（后端框架对象层语义与四段口径先行）✓ 已完成。

### 1.1 现状与缺口 <a id="gap"></a>

```text
frontend/packages/core/src/
├── base/
│   ├── BaseObject.ts        # 总基类：namespace/version、log、reportError、getConfig、dispose/onDispose
│   ├── BaseComponent.ts     # 组件根：extends BasePluggable
│   └── mixin.ts             # withBaseObject（Error 等宿主类注入公共面）
├── mechanisms/
│   ├── capability.ts        # BaseCapability extends BaseObject        ← 缺框架对象层
│   ├── pluggable.ts         # BasePluggable extends BaseCapability
│   ├── resource.ts          # BaseAsyncResource extends BaseObject      ← 缺框架对象层
│   ├── placeholder.ts       # BasePlaceholder extends BaseObject        ← 缺框架对象层
│   ├── error.ts             # BaseError 经 withBaseObject(Error)（PARENT_EXEMPT）
│   └── registry.ts / factory.ts / provider.ts
└── contracts/               # BaseApi / BaseDataObject / BaseEntity / BasePageQuery extends BaseObject（本任务不改）
```

| # | 缺口 | 影响 |
| --- | --- | --- |
| 1 | **无框架对象层**：`BaseCapability` 直挂 `BaseObject` | 与后端 09_01 后**不对称**（后端为 `BaseObject → BaseFrameworkObject → BaseCapability`），清单/架构「前后端对称」表述失真 |
| 2 | **框架对象无统一标识**：无 `objectKind` 等价物 | 框架对象（能力域 / 插件 / 注册表 / 工厂 / 资源 / 占位）无法在运行期统一辨识，日志与诊断缺统一锚点 |
| 3 | 清单 §1.1 / §3 / §5 三处「固定前三段」表述 | 需同步为四段，否则清单是「唯一继承来源」的权威性受损 |
| 4 | 守卫用例（`guard-base-registry.spec.ts`）三重校验（清单↔源码零差集 / `extends` 一致 / 入口具名导出） | 新增基类若不同步清单与导出，用例即红——**护栏会替我们拦住漏改** |

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 基类契约（`base/framework-object.ts`） <a id="interface"></a>

```ts
/**
 * 框架对象体系基类（对齐后端 `BaseFrameworkObject`；《前端基类清单》§3.2）。
 *
 * **框架对象**＝非渲染、非数据对象（能力域 / 插件 / 注册表 / 工厂 / 资源 / 占位 / 中间件等）；
 * 本层承载其公共语义：统一标识 `objectKind`。生命周期沿用总基类 `dispose()` / `onDispose()`，
 * 不在本层重复定义（与后端 `BaseFrameworkObject` 提供可选 `aclose` 钩子位的差异见 §7）。
 */
export class BaseFrameworkObject extends BaseObject {
  /** 框架对象统一标识（子层覆写，如 `capability` / `component` / `registry` / `resource`）。 */
  readonly objectKind: string = 'framework'
}
```

| 契约点 | 口径 |
| --- | --- |
| 继承 | 直接继承 `BaseObject`（框架对象层是**体系根**，与后端 7 体系根口径一致：除体系根外禁止直挂根系——前端该强制护栏归 §7 遗留） |
| `objectKind` | 前端 camelCase（对齐后端 `object_kind` 语义；命名风格按前端 TS 惯例） |
| 生命周期 | 沿用 `BaseObject.dispose()` / `onDispose()`；**不重复定义**（后端 `aclose` 为其异步风格对应物，见 §7） |
| 抽象性 | 普通类（与后端一致；可被 `BaseCapability` 等直接继承） |

## 4. 兼容性与影响 <a id="compat"></a>

- **运行时零行为变更**：仅新增一层父类并新增 `objectKind` 只读字段；`key` / `pluginKey` / `pluginName` / `contractVersion` / `describe()` / `dispose()` 语义不变。
- **插件与宿主**：`ui-ep` / `vue` / `apps/desktop` 侧导入的基类均已登记（守卫 ⑤），改挂不改变其可用面。
- **清单权威性**：清单为「继承链唯一来源」，本任务同步 §1.1 / §2.1 / §3 / §5 / §9 五处，避免口径漂移。
- **后续扩展点**：前端「数据契约体系层」（`BaseApi` / `BaseDataObject` 等）与「禁止直挂根系」前端护栏 → §7 遗留。

## 7. 边界与开放项 <a id="boundary"></a>

1. **前端数据契约体系层**（`BaseApi` / `BaseDataObject` / `BaseEntity` / `BasePageQuery` 仍直挂 `BaseObject`）→ 登记遗留（如需与后端 `BaseDataContract` 对称，另立任务）。
2. **前端「禁止直挂根系」护栏**（对应后端「直继承合法性」检查）→ 登记遗留（当前仅清单守卫，无「体系根白名单」硬校验）。
3. **`objectKind` 与后端 `object_kind` 的主干差异**：后端 `BaseFrameworkObject` 提供可选 `aclose` 异步钩子位，前端对应物为既有 `dispose()` / `onDispose()`（同步），**不新增 `aclose`**（前端无异步资源释放口径）。
4. **`BaseError`** 经 mixin 实现（`PARENT_EXEMPT`），不进入框架对象层——其在清单 §6.3 口径不变。
5. **Kiwi 用例编号** → 测试实施时登记回填。
