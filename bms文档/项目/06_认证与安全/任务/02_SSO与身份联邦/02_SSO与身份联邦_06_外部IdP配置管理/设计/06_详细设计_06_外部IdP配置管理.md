## 1. 设计目标与范围 <a id="goal"></a>

在 02_01（SSO 链路 + `sys_identity_provider` 落表与读路径）、02_02（JIT 键）、02_03（CAS 键）、02_04（企微 / 钉钉键）、02_05（管理面鉴权 / 审计 / 契约生成范式）之上，交付**租户级外部 IdP 配置管理面**：

1. **管理接口（IDP 域）**——新增 identity 服务 `/api/v1/idp/providers` 管理端点：列表（分页筛选）/ 详情 / 新建 / 修改 / **独立启停** / 软删除，权限码 `idp:manage`（RBAC 前 = 超管口径）；写操作落 `AuditCapturer` 占位。
2. **配置写入校验**——按协议**声明式 schema**（必填 / 类型 / 枚举）校验 `sys_identity_provider.config`：覆盖 OIDC（含 02_02 的 `jit_enabled` / `allowed_email_domains`）、CAS（含 02_03 的平铺键与 `attribute_map` 对象）、企微（含 02_04 的 `mode` 枚举）、钉钉；**未知键拒绝**；密钥引用只接受 `env:变量名`（`secret:` 继续预留、写入即拒）。
3. **凭据零明文**——响应层**确定性脱敏**：`config` 内敏感键只返「是否已配置 + 引用前缀」（如 `env:***`），其余键原样返回；DB、响应、日志零明文；写入拒绝疑似明文密钥。
4. **SSRF 校验**——出站 URL（OIDC `issuer`、CAS `cas_server_url`、企微 / 钉钉 `api_base_url`）协议白名单（http/https）+ 主机静态校验（禁字面内网 / 回环 / 链路本地 / 元数据 / `localhost`）；企业内网 IdP 合法场景经 `[idp_manage].allow_private_hosts` 开关放行。
5. **连通性测试**——分协议探测（OIDC Discovery / CAS `serviceValidate` / 企微 `gettoken` / 钉钉 `userAccessToken` 探活），提供**已保存行** `GET /{id}/test` 与**草稿** `POST /test`（不落库）两形态；测试限流防滥用；只返可达性与**摘要诊断**（状态码 / 错误类别），不泄原始报文与密钥。
6. **登录页入口数据**——沿用 02_01 已交付的 `GET /api/v1/auth/sso/providers`（按 `enabled` + `sort` 取数、永不返回 `config`），本任务补回归用例锁定「凭据不泄露」，不重复建设。

**不在本期**：`secret:标识` 加密存取（归域 04_03 密钥管理，本任务登记遗留）；前端 IdP 配置管理页面（归阶段七 / 十五）；RBAC 真实权限判定与页面菜单（阶段七）；`sys_login_log` / 操作日志真实落库（阶段八）；IdP 配置变更的事件广播（阶段八）；批量拖拽排序接口（后续按需）。

**安全影响（SDL）**：涉及租户外部 IdP 凭据引用与出站探测（SSRF 面）。专项验收点：密钥类只存引用（`env:`）、DB / 响应 / 日志零明文；响应敏感键确定性脱敏（不依赖域 04 占位掩码基座）；写入拒绝明文密钥；出站 URL 协议 + 主机静态校验（内网放行经显式开关，生产默认关闭）；连通性测试限流防滥用；管理面鉴权 `require_auth` + `idp:manage`；写操作审计占位；探测失败只返摘要诊断（不泄原始报文 / 密钥 / 环境变量名）；软删除保留轨迹。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 数据库表与归属 <a id="tables"></a>

**不改表结构、零迁移**——`sys_identity_provider` 现有字段（`name` / `idp_key` / `type` / `icon` / `config` / `status` / `sort` + 公共字段）已满足 CRUD / 启停 / 连通性；表文件（[`sys_identity_provider.md`](../../../../../../设计/数据库设计/数据表设计/sys_identity_provider.md)）无需变更，归属登记（`identity:tenant` 0002）不变。本任务在「变更记录」中仅追加一条「管理面落地，表结构不变」的口径注记（若实施无需改动字段则省略，避免噪声）。

- 复用既有唯一约束 `uq_sys_identity_provider_idp_key_deleted_at`（软删后标识可复用）与索引 `idx_sys_identity_provider_status_sort`（入口清单）。
- 排序经 `PUT /{id}` 改 `sort` 字段实现，无批量排序接口。

### 3.2 配置 schema 与写入校验 <a id="schema"></a>

新增 `bms_core/idp/schema.py`：以**声明式键规格**描述各协议 `config`，统一驱动写入校验与键白名单。

键规格元素：`required`（必填键）+ `optional`（可选键）；每键声明 `kind`（`str` / `bool` / `int` / `number` / `str_list` / `str_map` / `secret_ref` / `outbound_url` / `client_url`）与 `enum`（枚举）。

| 协议 | 必填键 | 可选键 |
| --- | --- | --- |
| `oidc` | `issuer`(`outbound_url`) / `client_id`(`str`) / `client_secret_ref`(`secret_ref`) | `scopes`(`str_list`) / `redirect_uri`(`client_url`) / `discovery_cache_ttl`(`number`) / `jwks_cache_ttl`(`number`) |
| `cas` | `cas_server_url`(`outbound_url`) | `cas_login_path`(`str`) / `cas_service_validate_path`(`str`) / `attribute_map`(`str_map`) / `redirect_uri`(`client_url`) |
| `wecom` | `corp_id`(`str`) / `agent_id`(`str`) / `secret_ref`(`secret_ref`) | `mode`(`enum qr\|oauth`) / `login_url`(`client_url`) / `oauth_url`(`client_url`) / `api_base_url`(`outbound_url`) / `scope`(`str`) / `login_type`(`str`) / `redirect_uri`(`client_url`) |
| `dingtalk` | `client_id`(`str`) / `client_secret_ref`(`secret_ref`) | `login_url`(`client_url`) / `api_base_url`(`outbound_url`) / `scope`(`str`) / `prompt`(`str`) / `redirect_uri`(`client_url`) |

- **通用键**（四协议皆可）：`jit_enabled`(`bool`，02_02)、`allowed_email_domains`(`str_list`，02_02)。
- `str_map` 键（`attribute_map`）要求「字符串 → 字符串数组」对象；`str_list` 要求字符串数组（元素非空、自动去重去空白）。
- **未知键拒绝**：出现键规格之外的键即 `IDP_CONFIG_INVALID`（20064）。
- `secret_ref`：值须匹配 `env:[A-Za-z_][A-Za-z0-9_]*`；`secret:` 前缀写入即拒（未实现，提示改用 `env:`）；其余形态视为疑似明文密钥拒绝。
- `client_url`（`redirect_uri` / `login_url` / `oauth_url`）：仅校验协议为 http/https（浏览器跳转地址，非服务端出站，不做主机内网校验）。
- 校验函数：`validate_provider_config(type: str, config: Mapping[str, object]) -> dict[str, object]`（返回归一化后的新字典，非法抛 `IdpConfigInvalidError`）；`type` 不在 `IDP_PROTOCOLS` 同样拒绝。

### 3.3 SSRF 校验 <a id="ssrf"></a>

新增 `bms_core/idp/ssrf.py`：`validate_outbound_url(url: str, *, allow_private_hosts: bool) -> None`（非法抛 `IdpConfigInvalidError`）。

- **协议白名单**：仅 `http` / `https`；其余（`ftp` / `file` / `gopher` / 无协议等）拒绝。
- **主机静态校验**（`allow_private_hosts=False` 时）：
  - `localhost` / `*.localhost` / 空主机 拒绝；
  - 字面 IPv4 私网段（`10/8`、`172.16/12`、`192.168/16`）、回环（`127/8`）、链路本地（`169.254/16`，含元数据 `169.254.169.254`）、`0.0.0.0/8` 拒绝；
  - 字面 IPv6 回环（`::1`）、唯一本地（`fc00::/7`）、链路本地（`fe80::/10`）拒绝。
- **不做 DNS 解析后私网校验**（避免 TOCTOU 与部署复杂度；「域名解析到内网」为已知残留，登记开放项）。
- **内网放行**：`[idp_manage].allow_private_hosts = true` 时跳过主机静态校验（仍校验协议）——企业自建内网 Keycloak / AD 合法场景；dev 与测试默认开启，生产默认关闭。
- 应用点：写入校验（`outbound_url` 键）与连通性测试前置（对已存行 / 草稿 config 的出站 URL 复校，覆盖历史种子行）。

### 3.4 凭据脱敏 <a id="mask"></a>

`bms_core/idp/schema.py::mask_provider_config(type: str, config: Mapping[str, object]) -> dict[str, object]`：返回新字典，敏感键（`kind == "secret_ref"`：`client_secret_ref` / `secret_ref`）值替换为「引用前缀 + `***`」：

- `env:VAR` → `env:***`；`secret:ID` → `secret:***`；非法 / 缺失 → `***`。
- 非敏感键原样返回；未知键（历史脏配置）原样返回（读取侧不因历史数据报错）。

管理面响应 DTO 另带 `secret_configured: bool`（是否存在任一敏感键且引用非空），供前端展示「凭据已配置」而无需解析掩码值。**当前域 04 `BaseMasker` 为占位（Null 恒原样返回、受 `data:plain` 门控），不可用于凭据脱敏**——故采用响应层确定性脱敏，不依赖掩码基座（开放项登记域 04 落地后可评估统一）。

### 3.5 各协议连通性探测 <a id="probe"></a>

在身份源契约上新增**探测能力**（横切能力落基类，符合架构铁律）：

- `bms_core/idp/base.py` 新增数据契约 `IdpProbeResult(reachable: bool, protocol: str, status: int | None = None, detail: str = "")`（frozen dataclass），并新增 `BaseIdentityProvider.probe() -> IdpProbeResult` **默认实现**（返回不可达，`detail` 为「该协议不支持连通性探测」）——保持既有实现与第三方后端兼容（非抽象方法，和 `verify_token` 同范式）。
- 各实现覆盖：

| 协议 | 探测动作 | 可达判定 | `detail` 摘要 |
| --- | --- | --- | --- |
| `oidc` | GET `{issuer}/.well-known/openid-configuration` | 2xx 且响应为 JSON 对象且含 `issuer` / `authorization_endpoint` / `token_endpoint` | 「Discovery 正常」/ 状态码 |
| `cas` | GET `{cas_server_url}{cas_service_validate_path}?service={派生回调}`（无票据） | 任意结构化 HTTP 响应（CAS XML / 官方错误体）即视为可达 | 「CAS 端点可达」/ 状态码 |
| `wecom` | GET `{api_base_url}/cgi-bin/gettoken?corpid=&corpsecret=` | 2xx 且 `errcode == 0` 为「凭据有效且可达」；`errcode != 0` 仍算可达但 `detail` 记「凭据 / 配置异常（errcode）」 | 不透传原始报文 |
| `dingtalk` | POST `{api_base_url}/v1.0/oauth2/userAccessToken`（占位 code） | 4xx 结构化响应 = 端点可达（`detail` 记「端点可达（未带有效 code，仅探活）」）；网络 / 5xx = 不可达 | 不透传原始报文 |
| `null` | 无出站 | 恒不可达（fail-closed） | 「占位身份源不可探测」 |

- 网络 / 超时 / 非 JSON 等异常统一转 `reachable=False` + `detail`（不抛异常出服务层）；`detail` 只放**摘要**（状态码 / 错误类别 / errcode 数值），不含原始报文、密钥、环境变量名。
- 探测复用各实现既有 `httpx.AsyncClient`（`transport` 测试注入 `MockTransport`、`timeout` 沿用各协议缺省）。

### 3.6 ProviderRegistry 扩展 <a id="registry"></a>

`bms_identity/services/provider_registry.py` 增两个方法（既有 `spec_for` / `instance_for` 语义不变）：

- `spec_for_config(*, idp_key: str, type: str, config: Mapping[str, object]) -> IdentityProviderSpec`：草稿 config → spec，套用与 `spec_for` 相同的 `redirect_uri` 派生（缺省按 `[sso].callback_base_url` 补 `{base}/api/v1/auth/sso/{idp_key}/callback`），`id=0` / `updated_at=""`（草稿不缓存）。
- `instance_for_spec(spec: IdentityProviderSpec) -> BaseIdentityProvider`：`self._registry.get(spec)`；`instance_for(row)` 改为 `instance_for_spec(spec_for(row))`（行为不变）。

### 3.7 管理端点契约 <a id="endpoints"></a>

挂 identity 服务 `/api/v1/idp/providers`（外部经网关 `/api/identity/v1/idp/providers`）；模块级 `Depends(require_auth)` + `Depends(require_permission("idp:manage"))`；统一响应体 `ApiResponse`。

| 方法 | 路径 | 请求 | 响应 | 说明 |
| --- | --- | --- | --- | --- |
| GET | `/idp/providers` | 分页 `page`/`size` + `status`/`type`/`name` 筛选 | 分页 `IdpProviderItem` | 列表（config 敏感键脱敏） |
| POST | `/idp/providers` | `IdpProviderCreateRequest` | `IdpProviderItem` | 新建（校验 + SSRF + 唯一） |
| GET | `/idp/providers/{id}` | — | `IdpProviderItem` | 详情 |
| PUT | `/idp/providers/{id}` | `IdpProviderUpdateRequest` | `IdpProviderItem` | 修改（`name`/`icon`/`config`/`sort`；`type`/`idp_key` 不可改） |
| POST | `/idp/providers/{id}/status` | `IdpProviderStatusRequest` | `IdpProviderItem` | 独立启停（`enabled`/`disabled`） |

### 3.9 错误码口径 <a id="errors"></a>

认证段（`2xxxx`）SSO 子段新增管理面码位（`core/error_codes.py` 单一登记；架构 09「平台已发布码位」同步）：

| 码 | 常量 | 异常类 | HTTP | 场景 |
| --- | --- | --- | --- | --- |
| `20063` | `IDP_NOT_FOUND` | `IdpNotFoundError` | 404 | 配置不存在（详情 / 修改 / 启停 / 删除 / 已存测试按 id 未命中） |
| `20064` | `IDP_CONFIG_INVALID` | `IdpConfigInvalidError` | 400 | 写入校验失败（必填缺失 / 类型或枚举非法 / 未知键 / 密钥引用非法或疑似明文 / 出站 URL SSRF 拒绝 / `type` 非法） |

| `20066` | `IDP_TEST_FAILED` | `IdpTestFailedError` | 502 | 连通性测试不可达 / 不可探测（`data` 携 `IdpProviderTestResult`） |

- `idp_key` 唯一冲突在服务层先 `get_by_key` 预检，并以 DB 唯一约束 + `IntegrityError` 兜底转 `20065`（并发）。

## 7. 边界与开放项 <a id="boundary"></a>

- **归域 04_03（密钥管理）**：`secret:标识` 加密存取；落地后接入本管理面（写入校验放开 `secret:`、脱敏保持）并评估是否统一到 `BaseMasker`。
- **归阶段七（RBAC / 用户管理）**：`idp:manage` 真实权限判定、IdP 配置页面与菜单、按钮动作。
- **归阶段八**：IdP 配置变更事件广播、操作日志真实落库（本任务仅 `AuditCapturer` 占位）。
- **开放项（SSRF 域名解析绕过）**：仅主机静态校验，不做 DNS 解析后私网校验；如需强化，后续接出站白名单 / egress 代理（另立任务）。
- **开放项（内网放行开关粒度）**：`allow_private_hosts` 为全局（分区级）布尔，非按行 / 按租户白名单；如需细粒度，后续按行配置或租户配置扩展。
- **开放项（启停不校验连通性）**：启用不强制先过连通性测试（避免内网探测阻塞运维）；如需强约束，前端流程或后续新增「启用前预检」。
- **开放项（钉钉探测深度）**：无有效 `code` 时仅探活端点可达性，不校验凭据真伪；真实凭据验证归阶段十七真实联调。
- **开放项（排序接口粒度）**：仅单行 `sort` 更新，无批量拖拽排序；如前端需要，后续在 `/idp/providers` 增批量排序端点（非破坏新增）。
- **开放项（列表缓存）**：管理面列表不做缓存；登录页入口仍每次查库（数据量为个位数行，不引入缓存复杂度）。
