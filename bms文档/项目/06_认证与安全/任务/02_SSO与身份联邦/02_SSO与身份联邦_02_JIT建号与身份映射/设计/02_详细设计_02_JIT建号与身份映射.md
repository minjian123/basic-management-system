## 1. 设计目标与范围 <a id="goal"></a>

在 02_01（SSO 登录完整链路）之上补齐 **JIT 自动建号与身份映射的写路径**：

1. **JIT 建号**——首次 SSO 登录映射未命中且 JIT 启用时，经 **org 建号内部接口**创建 `sys_user` 最小模型记录（口令哈希存**不可登录占位**），随后在平台库写入 `sys_user_identity` 映射；同租户同外部身份二次登录命中映射直接登录（02_01 已交付读路径）。
2. **建号规则**——按 IdP 行配置的租户归属建号；用户名来源 `preferred_username → email 本地部分 → sub` 并统一清洗；撞名自动加后缀 `_2.._5`（超出拒绝）；**域名白名单**（per-IdP `config.allowed_email_domains`）与**租户白名单**（全局 `[sso].jit_allowed_tenants`）校验。
3. **JIT 开关**——IdP 行 `config.jit_enabled` 优先，行缺配回落全局 `[sso].jit_enabled`；两者皆缺省 `false`（需显式开启）。
4. **并发防护**——新增**分布式锁能力域**（memory / redis 真实实现），JIT 临界区按映射键串行化；`sys_user_identity` 唯一约束作跨进程兜底（冲突回读复用）。
5. **事件登记**——`identity.user.jit_created` 经 **Outbox** 在平台库与映射插入**同事务**写入（仅首次建号发；事件契约 02_01 已登记，本任务落签发路径）。
6. **绑定查看**——`sso:bind` 只读端点 `GET /api/v1/users/{id}/identities`（identity 服务），闭环 02_01 遗留（权限码占位、RBAC 前超管口径）。
7. **口径回写**——《后端基类清单》「身份源」条目与《架构设计 · 认证与会话》§4 更新。

**不在本期**：IdP 配置 CRUD / 启停 / 连通性 / 凭据加密（`02_06`）；CAS（`02_03`）、企微 / 钉钉（`02_04`）、BMS 兼作 IdP（`02_05`）；绑定**管理**（解绑 / 重绑，`sso:bind` 写动作随用户管理 + RBAC）；`sys_login_log`（阶段八）。

**安全影响（SDL）**：涉及外部身份断言驱动的**自动建号**与**跨服务写**。专项验收点：JIT 默认关闭、需显式开启；白名单双层校验（域名 + 租户）防越权建号；建号口令哈希为**不可登录占位**（本地登录必然失败，SSO 通道与本地通道隔离）；JIT 事件载荷不含手机号 / 邮箱 / 令牌；映射键 `{tenant}:{provider_key}` 防跨租户串号；并发经分布式锁 + 唯一约束双保险；建号失败 fail-closed（不静默放行）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 数据库表与归属 <a id="tables"></a>

**无表结构变更**——现有表已满足 JIT 写路径：

| 表 | 归属库 | 本任务用途 | 变更 |
| --- | --- | --- | --- |
| `sys_user_identity` | 平台库 `bms_platform` | 写入映射行（`idp_key` / `external_id` / `tenant_id` / `user_id`）；`(idp_key, external_id, deleted_at)` 唯一约束作并发兜底 | 无（02_01 已落库；字段清单以[表文件](../../../../../../设计/数据库设计/数据表设计/sys_user_identity.md)为唯一事实源） |
| `sys_user` | org 服务租户库 `bms_org_{code}` | JIT 建号写最小模型记录；`password_hash` 存不可登录占位（非 PBKDF2 串） | 无（仅表文件补占位语义注记） |

- 写路径顺序：**org 建号（租户库，独立事务）→ 平台库映射插入 + Outbox 事件（同事务）**；跨库无 2PC（分属两服务库），以「JIT 锁串行化 + 唯一约束回读」保证幂等。
- `sys_user.password_hash` 占位常量由 org 侧定义（`!sso`，非 PBKDF2 自描述串 → `Pbkdf2PasswordHasher.verify` 恒 `False`）；「是否 SSO 账号」以 `sys_user_identity` 绑定为事实源，不新增列、不建迁移。

### 3.2 分布式锁能力域真实实现 <a id="lock"></a>

现 `bms_core/lock/` 仅 `base.py` + `null.py`；本任务补 `memory.py` / `redis.py`：

- `MemoryDistributedLock(BaseDistributedLock)`（`plugin_name = "memory"`）：进程内 `dict[key] = (token, expire_at)`；`acquire` 惰性过期 + `wait > 0` 时按 `asyncio.sleep` 轮询至超时；`release` 按令牌删除；`extend` 按令牌重置 TTL。单副本口径。
- `RedisDistributedLock(BaseDistributedLock, BaseAsyncResource)`（`plugin_name = "redis"`，懒建连）：`acquire` 用 `SET key token NX EX ttl`（`wait > 0` 轮询）；`release` / `extend` 用 Lua 脚本**校验令牌**后 `DEL` / `EXPIRE`；Redis 异常时**降级 memory** 并记日志（与 `RedisRateLimiter` 同口径，保可用性）。
- 装配：`assembly.py` 增 `register_plugin("distributed_lock", "memory" | "redis", …)`；`_NULL_MODULES` 已含 `bms_core.lock.null`（占位不变）。`build_lock_key(tenant, resource)` 复用（键 `bms:{租户}:lock:{资源}`）。
- 语义：锁仅**缩小**并发行窗口（正常路径无重复建号）；最终一致性由映射唯一约束回读兜底（见 §3.5）。

### 3.3 org 建号内部接口 <a id="org-create"></a>

路径 `POST /api/v1/org/internal/users/create`（模块级 `Depends(require_service("identity"))`，与既有 internal 端点同前缀同级）：

| 方法 | 路径 | 请求 | 响应 data | 语义 |
| --- | --- | --- | --- | --- |
| POST | `/internal/users/create` | `{username, name, locale?, timezone?}` | `{created, reason?, user?}`；`user = {id, username, name, status, locale, timezone}` | 单次「用户名空闲即建号」；`created=false` + `reason="username_conflict"` 表示撞名（由调用侧换后缀重试） |

- **建号口径**：`status="enabled"`；`password_hash = SSO_PASSWORD_PLACEHOLDER`（不可登录占位）；`failed_count=0`、`locked_until=None`、`locale` / `timezone` 取请求（可空）。
- **冲突语义**：先按 `username` 查询，命中即 `created=false`；查询后插入若触发 `uq_sys_user_username_deleted_at`（并发），回滚返回 `created=false`（不抛 409，便于调用侧换后缀）。
- **契约登记**：计入 org 公开契约（`deploy/contracts/org.json` 重生成，非破坏新增）；identity 侧 `OrgCredentialClient.create_user` 以 `ServiceCallPolicy(scopes=("user_profile",))` 调用（org 侧只校验服务身份，不校验 scope）。
- **失败语义**：下游不可达 / 契约非法 → `ServiceUnavailableError`（10007）；identity 边界翻译为 `20053`（§3.6）。

### 3.4 identity JIT 编排 <a id="jit"></a>

新增 `bms_identity/services/jit.py`：

```text
JitService（BaseObject）
├── ExternalIdentity(subject, username?, name?, email?, locale?, timezone?)   # 冻结数据契约
├── JitResult(user_id, created)                                               # provision 结果
├── jit_enabled(row) -> bool                                                  # 行 config.jit_enabled 优先，缺配回落 [sso].jit_enabled
├── provision(*, tenant, idp_key, row, identity, platform_session) -> JitResult
│     ├── 开关校验（未启用 → SsoIdentityUnmatchedError 20054）
│     ├── 白名单校验（域名 per-IdP + 租户全局；空 = 不限；拒绝 → 20054）
│     ├── lock.hold(build_lock_key(tenant, "jit:{provider}:{subject}"), ttl, wait)
│     │     └── 未取到 → SsoIdentityConflictError（20055/409）
│     ├── 锁内二次查映射命中 → 直接复用（created=False）
│     ├── 用户名派生 + 后缀尝试（最多 5 次）→ org create_user
│     ├── 平台库：映射 create + Outbox enqueue（identity.user.jit_created）同事务 commit
│     └── IntegrityError → 回滚 → 回读命中则复用，否则 SsoIdentityConflictError（20055）
└── 派生 / 清洗 / 白名单为模块级 helper（可独立单测）
```

- **用户名派生**：`identity.username`（`preferred_username` 或 userinfo `username`）→ `email` 本地部分 → `subject`；清洗：小写、仅保留 `[a-z0-9._-]`、去首尾分隔符、截断 64；仍为空回落 `"user"`。
- **后缀**：候选 `base`、`base_2` … `base_5`（最多 5 次）；全部撞名 → `20054`。
- **白名单**：`row.config.allowed_email_domains`（非空时要求 `identity.email` 域名命中，邮箱缺失即拒）；`[sso].jit_allowed_tenants`（非空时要求 `tenant` 命中）。
- **锁参数**：`ttl = [sso].jit_lock_ttl_seconds`、`wait = [sso].jit_lock_wait_seconds`。
- **二次登录**：命中映射走 02_01 原路径（org 概要 → 会话签发），不经过 JIT、不发事件。

### 3.5 身份映射写路径与 Outbox 事件 <a id="mapping-event"></a>

- `UserIdentityRepository` 增 `create(**values) -> SysUserIdentity`（继承基类 CRUD，flush 不提交）与 `list_by_user(user_id) -> list[SysUserIdentity]`。
- **映射 + 事件同事务**：`platform_session` 依次 `create` 映射、`outbox.enqueue(session, EventEnvelope(...))`、`commit`；任一失败整体回滚。
- **事件口径**：`event_type="identity.user.jit_created"`；`payload={"user_id": str(user_id), "idp_key": "{tenant}:{provider_key}"}`（契约字段 `user_id` / `idp_key` 均为 string）；`tenant_id=tenant`、`aggregate_key=映射键`；仅首次建号发。
- **契约校验**：事件契约已登记（`platform_events.py` / `deploy/events/contracts.json`）；`[event].contract_mode="enforce"` 下未登记即拒发（10010），本任务补签发路径与用例。

### 3.6 回调编排改动与失败语义 <a id="callback"></a>

`SsoService.callback` 调整：`_resolve_subject` 升级为 `_resolve_identity`（返回 `ExternalIdentity`）→ 映射查询 `platform_session` → **未命中且 JIT 启用委派 `JitService.provision`**，否则 `20054`；命中则校验 `tenant_id` 一致后取 `user_id`。`api/sso.py` 的 `platform_session` 由只读改可写（JIT 需写），并注入 `get_distributed_lock` / `get_outbox_store`。

| 场景 | 行为 |
| --- | --- |
| 映射未命中 + JIT 未启用 | `SsoIdentityUnmatchedError`（20054/403，与 02_01 一致） |
| 白名单外租户 / 域名，或 `allowed_email_domains` 非空但邮箱缺失 | `20054/403` |
| 用户名 5 连撞 | `20054/403` |
| JIT 锁未取到 | `SsoIdentityConflictError`（20055/409） |
| 映射唯一约束冲突且回读未命中 | `20055/409` |
| org 建号接口不可达 / 契约非法 | 翻译为 `SsoProviderUnavailableError`（20053/503，fail-closed） |
| 首次建号成功 | 写映射 + `identity.user.jit_created`（同事务）→ 继续 org 概要 → 会话签发（02_01） |
| 二次登录命中映射 | 复用 02_01 路径，不建号、不发事件 |
| 绑定查看 | `GET /api/v1/users/{id}/identities` 返回该用户全部绑定（只读） |

### 3.7 配置契约 <a id="config"></a>

```toml
[sso]
```

### 3.8 绑定查看端点 <a id="bind"></a>

`GET /api/v1/users/{user_id}/identities`（identity 服务，`prefix="/users"`；外部经网关为 `/api/identity/v1/users/{id}/identities`）：

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/users/{user_id}/identities` | `require_auth` + `require_permission("sso:bind")` 占位 | 按本地用户反查绑定（平台库 `sys_user_identity`）；返回 `{items:[{idp_key, external_id, tenant_id}]}` |

- `user_id` 越权校验（仅本人 / 超管）随 RBAC（阶段七）；本期按超管口径（permission 基座 null 恒定通过）。
- `idp_key` 返回**映射键**（含租户前缀），不返回 `user_id` / 审计字段；不泄漏凭据。

## 7. 边界与开放项 <a id="boundary"></a>

- **归 02_06**：`sys_identity_provider` CRUD / 启停 / 连通性；行配置新增键（`jit_enabled` / `allowed_email_domains`）的管理面校验；凭据加密与 `secret:` 解析。
- **归 02_03 / 02_04**：CAS 与企微 / 钉钉适配器复用同一 JIT 与映射写路径（无需为本任务改动）。
- **归阶段七**：`sso:bind` 真实权限码与「本人 / 超管」越权判定；绑定解绑 / 重绑写动作。
- **归阶段八**：JIT 建号与绑定的操作日志、`sys_login_log`。
- **归阶段十**：`sys_client` 与开放接口（`02_05`）不受影响。
- **开放项（Redis 降级）**：分布式锁 Redis 异常降级 memory——极端「Redis 故障 + 多副本 + 同一外部身份并发首登」下可能出现一个未绑定孤儿用户；由映射唯一约束保证不产生重复映射，孤儿登记为运维可清理项（不阻断登录）。
- **开放项（孤儿清理）**：上述孤儿用户与「org 建号成功、映射写失败」的极端窗口由后续运维任务提供对账 / 清理（本任务不实现删除内部接口）。
- **开放项（事件消费方）**：`identity.user.jit_created` 本期无内建订阅方（消费随需求落地）；Webhook 推送归事件总线 / 开放接口阶段。
- **开放项（JIT 邮箱必填）**：`allowed_email_domains` 非空即要求邮箱；无邮箱 IdP 仅能使用「不配域名白名单」口径。
