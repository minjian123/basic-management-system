## 2. 任务内容 <a id="content"></a>

1. **入口数据**：`GET /auth/sso/providers`（免登录）按租户返回可用 IdP 列表（标识 / 名称 / 图标 / 类型），数据取自 `sys_identity_provider`（域 02_06 载体）。
2. **授权跳转**：`GET /auth/sso/{type}/authorize`——生成 `state` / `nonce` / PKCE `code_verifier` 存 Redis（短 TTL、一次性），重定向外部 IdP 授权端点。
3. **回调闭环**：`GET /auth/sso/{type}/callback`——校验 `state`（一次性）/ `nonce` / PKCE，换码 + ID Token 校验，解析用户信息；经 JIT（`02_02`）定位用户后签发 BMS 双 token、创建会话（复用域一链路）。
4. **异常分支**：IdP 不可达 / 配置缺失 / `state` 不匹配 / 用户被禁用返回明确错误码与登录页提示；**外部 IdP 故障降级本地登录**（并存口径）。
5. **绑定查看**：SSO 用户与本地账号绑定关系可查（`sso:bind` 权限码占位）。
6. **联调**：以 Keycloak（开发环境已就位）完成一次完整 SSO 登录 E2E；协议差异经统一 `BaseIdentityProvider` 框架承载，不另建链路。

## 3. 完成标准 <a id="accept"></a>

经 Keycloak 完成完整 SSO 登录（入口 → 跳转 → 回调 → BMS 会话 → 访问受保护接口）E2E 通过；`state` / `nonce` / PKCE 校验失败与 IdP 故障降级分支均有用例（Kiwi 登记）；本地登录与 SSO 登录并存互不影响。
