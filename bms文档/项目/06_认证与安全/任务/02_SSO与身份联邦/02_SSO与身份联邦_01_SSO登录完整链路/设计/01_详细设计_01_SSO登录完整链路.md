## 1. 设计目标与范围 <a id="goal"></a>

在 01_03（本地登录 / 会话签发）与阶段二 `07_01`（OIDC 客户端）之上，落 **SSO 登录完整链路（OIDC 先行，协议差异经统一 `BaseIdentityProvider` 承载）**：

1. **IdP 配置载体（读路径）**——`sys_identity_provider` 表文件 + ORM + `identity:tenant` 迁移 + 按租户查询；CRUD / 启停 / 连通性 / 凭据加密 / SSRF 校验归 `02_06`；
2. **身份映射载体（读路径）**——`sys_user_identity` 表文件 + ORM + `identity:platform` 迁移 + `(idp_key, external_id)` 命中查询；JIT 建号写路径 / 白名单 / 事件归 `02_02`；
3. **入口清单** `GET /auth/sso/providers`（免登录）——按租户返回可用 IdP（`idp_key` / 名称 / 图标 / 类型 / 排序），只返 `enabled`、永不返回 `config`；
4. **授权跳转** `GET /auth/sso/{idp_key}/authorize`（免登录）——生成 `state` / `nonce` / PKCE `code_verifier` 存 `idp_state_store`（短 TTL、一次性原子消费），经 `ProviderRegistry` 构造租户内 IdP 实例，302 到外部授权端点；
5. **回调闭环** `GET /auth/sso/{idp_key}/callback`（免登录）——一次性消费 `state`（租户以 state 记录为权威）→ 校验 `nonce` / PKCE / ID Token 签名（失败一律 `20052`）→ 映射命中 → org 用户概要（停用 → `20004`）→ 复用公共会话签发作构件创建 BMS 会话（双 token + `sys_session` + Redis 标记）→ `Set-Cookie` refresh → 302 前端；未匹配 → `20054`（JIT 开关预留，逻辑归 `02_02`）；
6. **契约扩展**——`BaseIdentityProvider.authorize / exchange_token / verify_token` 以**可选默认参数**承接 `nonce` / PKCE / nonce 校验（向后兼容）；新增 `idp_state_store` 能力域（memory / redis）与 `IdentityProviderRegistry`（行配置 → 实例，进程内缓存）；
7. **错误与安全**——认证段新增子段 `20051~20056`（IdP 配置缺失 / 回调校验失败 / IdP 不可达 / 未匹配 / 映射冲突 / 本地登录保护预留）；复用 `BaseRateLimiter` 对 authorize / callback 限流；结构化失败日志（不落 code / token / secret）；外部 IdP 故障时**本地登录通道不受影响**（并存，前端引导本地登录）。

**不在本期**：JIT 自动建号 / 域名租户白名单 / `identity.user.jit_created` 事件 / `sso:bind` 只读端点（`02_02`）；IdP 配置 CRUD / 启停 / 连通性测试 / 凭据加密 / SSRF（`02_06`）；CAS（`02_03`）、企微 / 钉钉（`02_04`）、BMS 兼作 IdP（`02_05`）；前端登录页 SSO 按钮与失败提示（域五）；`sys_login_log` 落库（阶段八）。

**安全影响（SDL）**：涉及外部身份断言（授权码 + ID Token）、流程状态载体（`state` / `nonce` / PKCE）、外部 IdP 凭据引用。专项验收点：`state` 一次性**原子**消费（Redis `GETDEL`）且短 TTL；`nonce` / PKCE 全链路启用（默认 `pkce=true`）；ID Token 必验签名 / `issuer` / `audience` / 过期 / `nonce`（校验失败一律 `20052`，不泄露细节）；密钥只存引用（`env:` 本期 / `secret:` 预留），DB、响应、日志零明文；回调成功 / 失败跳转地址**只取配置**（防开放重定向）；`state` 随日志脱敏；authorize / callback 限流防状态洪泛；本地登录与 SSO 互不影响。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 数据库表与归属 <a id="tables"></a>

两张新表，表文件为字段唯一事实源（本节只列要点，字段清单不复制）：

| 表 | 归属库 | 模块 | ORM 模型 | 迁移链 | 本期范围 |
| --- | --- | --- | --- | --- | --- |
| `sys_identity_provider` | identity 服务租户库 `bms_identity_{code}` | 27-身份认证SSO | `bms_identity/models/identity_provider.py::SysIdentityProvider` | `identity:tenant`（0002） | 落表 + 读路径（`02_06` 补管理） |
| `sys_user_identity` | 平台库 `bms_platform` | 27-身份认证SSO | `bms_identity/models/user_identity.py::SysUserIdentity` | `identity:platform`（0001，新建链） | 落表 + 读路径（`02_02` 补 JIT 写） |

- `sys_identity_provider` 关键字段：`name`（显示名）、`idp_key`（租户内稳定标识 slug，`uq_sys_identity_provider_idp_key_deleted_at`）、`type`（`oidc` / `cas` / `wecom` / `dingtalk`，取 `IDP_PROTOCOLS`）、`icon`（图标，可空）、`config`（`TEXT` 存 JSON，**密钥仅存引用**）、`status`（`enabled` / `disabled`，默认 `enabled`）、`sort`；索引 `idx_sys_identity_provider_status_sort`（列表主路径 `status + sort`）；公共字段继承 `BaseModel`。
- `config` JSON 口径（OIDC，`02_06` 管理面沿用）：`{ issuer, client_id, client_secret_ref, scopes?, redirect_uri?, discovery_cache_ttl?, jwks_cache_ttl?, jit_enabled? }`；`client_secret_ref` 只允许 `env:变量名`（本期）或 `secret:标识`（`02_06` 加密存取，预留）；`redirect_uri` 为空时按 `[sso].callback_base_url` 派生；`jit_enabled` 预留（`02_02` 消费，本期不读）。
- `sys_user_identity` 关键字段：`idp_key`（映射键 = `{tenant_code}:{provider_key}`，`uq_sys_user_identity_idp_external_deleted_at` 联 `external_id`）、`external_id`（IdP 主体，OIDC 为 `sub`）、`tenant_id`（租户编码，按需求字段名落列）、`user_id`（org 库 `sys_user.id`，值传递、无物理外键）；索引 `idx_sys_user_identity_user_id`。
- 表归属登记（`bms_core/services/table_registry.py::TABLE_OWNERSHIP`）：`sys_identity_provider`（owner `identity`、`TENANT`）与 `sys_user_identity`（owner `identity`、`PLATFORM`）由 `PLANNED` 转 `ENABLED`（删 `status` 行）；`sys_client` 保持 `PLANNED`（归 `02_05`）。
- 变更顺序（《数据库开发规范》强制）：**先表文件（含变更记录）→ 总览登记 → ORM 模型 → Alembic 迁移（含新链配置段）→ 回写状态两处**。

### 3.2 `BaseIdentityProvider` 契约扩展与流程状态存储 <a id="idp-contract"></a>

**方法扩展（可选默认参数，向后兼容）**：

| 方法 | 现状（07_01） | 扩展后 | 语义 |
| --- | --- | --- | --- |
| `authorize(state)` | 仅 `state` | `authorize(state, *, nonce=None, code_challenge=None, code_challenge_method=None)` | `nonce` / PKCE 挑战入授权 URL；不支持方忽略参数 |
| `exchange_token(code)` | 仅 `code` | `exchange_token(code, *, code_verifier=None)` | 换码带 PKCE 校验码 |
| `verify_token(token, *, audience=None)` | 仅 `audience` | `verify_token(token, *, audience=None, nonce=None)` | 提供 `nonce` 时校验 ID Token `nonce` claim，不符抛 `AuthError` |

- `BaseIdentityProvider` 默认实现忽略新增参数；`OidcIdentityProvider` 实现 PKCE（`code_challenge = BASE64URL(SHA256(verifier))`、`code_challenge_method=S256`）、`nonce` 入 URL 与校验；`NullIdentityProvider` 逻辑不变。
- `OidcIdentityProvider.exchange_token` 同时透出 `id_token`（`IdentityToken.id_token`），供 SSO 服务执行 `verify_token`。

**流程状态能力域（`bms_core/idp/state/`，形态照 `session/`）**：

- `DEFAULT_IDP_STATE_TTL = 300`；`IDP_STATE_KEY_PREFIX = "bms"`；`build_idp_state_key(state, *, tenant=None) -> f"bms:{tenant or 'global'}:idpstate:{state}"`。
- `BaseIdpStateStore(BasePluggable, ABC)`：`key = plugin_key = "idp_state_store"`、`plugin_name = NULL_PLUGIN_NAME`、`contract_version = DEFAULT_CONTRACT_VERSION`；抽象 `async save(state, payload: Mapping[str, object], *, tenant=None, ttl=DEFAULT_IDP_STATE_TTL)`、`async consume(state, *, tenant=None) -> Mapping[str, object] | None`（**一次性原子消费**：Redis `GETDEL`；memory `pop` + 惰性过期）、`async delete(state, *, tenant=None)`。
- 实现：`RedisIdpStateStore` / `MemoryIdpStateStore` / `NullIdpStateStore`；`get_idp_state_store(request)` 经 `resolve_plugin`，`[idp_state_store].provider` 选择（基线 `redis`，测试置空回落 Null）。
- 流程记录（保存 payload）：`IdpFlowState(tenant, idp_key, nonce, code_verifier, redirect_uri, created_at)`（服务层序列化为 JSON）。

**行配置实例化（`bms_core/idp/registry.py`）**：

- `IdentityProviderSpec(id, idp_key, type, config: Mapping, updated_at)`；`resolve_secret_ref(ref)`：`env:NAME` → 环境变量值（缺失抛 `ConfigError`）、`secret:标识` → `ConfigError`（`02_06` 预留）、未知前缀抛 `ConfigError`。
- `IdentityProviderRegistry(secret_resolver, transport=None)`：`build(spec) -> BaseIdentityProvider` 按 `type` 分派（本期仅 `oidc`，`cas` / `wecom` / `dingtalk` 在对应任务注册）；`get(spec)` 按 `(id, updated_at, type)` 进程内缓存（配置变更自动失效），供 authorize / callback 逐请求取实例且保留 discovery / JWKS 缓存。

### 3.3 identity SSO 端点契约 <a id="endpoints"></a>

| 方法 | 路径 | 鉴权 / 租户 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/auth/sso/providers` | 公开；租户=上下文优先 + `tenant` 参数回落 | 可用 IdP 清单（只 `enabled`，按 `sort` / `id`） |
| GET | `/api/v1/auth/sso/{idp_key}/authorize` | 公开；租户同左 | 生成流程状态并 302 到外部授权端点 |
| GET | `/api/v1/auth/sso/{idp_key}/callback` | 公开；**租户以 state 记录为权威** | 回调闭环，302 前端 + refresh cookie |

**入口清单**：

```json
// GET /api/v1/auth/sso/providers?tenant=demo
// 200
{ "code": 0, "message": "ok", "data": { "items": [
    { "idp_key": "keycloak", "name": "Keycloak", "icon": "", "type": "oidc", "sort": 0 } ] } }
```

**授权跳转**：生成 `state = token_urlsafe(32)`、`nonce = token_urlsafe(16)`、`code_verifier = token_urlsafe(64)`，落 `idp_state_store`（`ttl = [sso].state_ttl_seconds`）；取租户内 `enabled` 行构造实例（`pkce=true` 时带 `code_challenge`），`302 Location=<authorization_endpoint?response_type=code&client_id=…&redirect_uri=…&scope=…&state=…&nonce=…&code_challenge=…&code_challenge_method=S256>`。

**回调闭环**（`state` / `code` 由 IdP 回传；IdP 带 `error` 时同样走失败分支）：

```text
GET /api/v1/auth/sso/keycloak/callback?code=…&state=…
  ├─ consume(state) 命中 → tenant = 记录租户（请求上下文有租户且不一致 → 20052）
  ├─ 换码（code_verifier）→ 取 id_token → 验签 / issuer / audience / nonce（失败 → 20052）
  │    └─ 无 id_token 时回退 userinfo（nonce 校验不可用，记入开放项）
  ├─ 映射命中 sys_user_identity（idp_key = {tenant}:{idp_key}）；未命中 → 20054（JIT 归 02_02）
  ├─ org 用户概要：不存在 → 20054；status≠enabled → 20004（403）；取 locale / timezone
  ├─ SessionIssuer.issue（双 token + sys_session + Redis 标记）+ org login-state(success=True)
  └─ 302 {success_redirect}?tenant={code} + Set-Cookie refresh（HttpOnly / Secure / SameSite=Lax / Path=/api/v1/auth）
```

- 失败时（任一错误码）：配置了 `failure_redirect` → `302 {failure_redirect}?error={code}&message={urlencoded}`；未配置 → 统一 JSON 错误体（HTTP 状态随错误码）。
- 成功跳转地址与失败跳转地址**只取配置**（不允许来自请求参数），防开放重定向；`success_redirect` 未配置时回退 JSON `{code:0, data:{tenant}}`（联调便利）。
- **限流**（`BaseRateLimiter`，键经 `build_rate_limit_key`）：authorize 按 `ip` 维度 + `client` 维度（target=`idp_key`，承载「外部 IdP」键）；callback 按 `ip` 维度；阈值取 `[sso].ip_rate_limit` / `[sso].provider_rate_limit`（默认各 60/min）；命中 → `10005`（失败跳转带 `error=10005`）。
- **失败日志**：结构化 `warning`（`idp_key` / `tenant` / `code` / `error`；`state` 脱敏、不落 token / code / secret）；`sys_login_log` 落库归阶段八。

### 3.4 org 内部用户概要接口 <a id="org-internal"></a>

路径 `/api/v1/org/internal/users/profile`（服务间调用基座要求落在 `/api/v1` 公开面），模块级 `Depends(require_service("identity"))`：

| 方法 | 路径 | 请求 | 响应 data | 语义 |
| --- | --- | --- | --- | --- |
| POST | `/internal/users/profile` | `{user_id}` | `{found, user?}`；`user = {id, username, name, status, locale, timezone}` | 按 id 取用户概要；不存在 `found=false`；停用 / 语言时区由调用侧判定使用 |

- **租户定位 / 鉴权**：同 01_03（服务 JWT `tenant` claim + `require_service("identity")`；直连伪造拒绝）。
- **契约登记**：计入 org 公开契约（`deploy/contracts/org.json` 重生成，非破坏新增）；identity 侧 `OrgCredentialClient.user_profile` 以 `ServiceCallPolicy(scopes=("user_profile",))` 调用。
- **identity 侧映射**：`found=false` → `20054`；`status≠enabled` → 复用 `AccountDisabledError`（`20004`）；org 不可达 / 契约非法 → `ServiceUnavailableError`（`10007/503`，fail-closed）。

### 3.5 会话签发作构件（共用） <a id="session-issuer"></a>

- 自 `LoginService` 抽取 `SessionIssuer`（`services/session_issuer.py`）：`issue(*, user_id, tenant, ip, user_agent) -> IssuedSession(access_token, refresh_token, access_expires_in, refresh_expires_in, session_id)`，内部顺序与 01_03 一致——`new_session_id` → `issue_pair`（access / refresh 同 `session_id`）→ `enforce_max_active` → `uow.begin` 内 `create_session`（含 `refresh_token_hash`）→ `session_store.save`。
- `LoginService` 改用该构件，对外结果（`LoginOutcome` / cookie / 错误语义）不变；SSO 回调复用同一构件签发**同构**会话（access / refresh 同 `session_id`、Redis 标记同键），保证后续 `/auth/refresh` 与 `require_auth`（01_05）无缝消费。
- SSO 登录不写 `failed_count` / `locked_until`（走 org `login-state(success=True)` 仅更新 `last_login_at` 并清零历史失败计数）。

### 3.6 配置契约 <a id="config"></a>

```toml
[sso]
state_ttl_seconds = 300                     # state / nonce / PKCE 流程状态 TTL（一次性）
success_redirect = ""                       # 回调成功前端地址（空=回退 JSON，联调便利）
failure_redirect = ""                       # 回调失败前端地址（空=回退 JSON 错误体）
ip_rate_limit = 60                          # 每 IP 每分钟 authorize / callback 上限
provider_rate_limit = 60                    # 每 IdP 每分钟 authorize 上限
pkce = true                                 # 强制 PKCE（S256）
callback_base_url = "http://localhost:8000" # 回调地址基址（派生 redirect_uri）

[idp_state_store]
provider = "redis"                          # redis / memory / 空（Null）；连接串取 [redis].url
```

| 配置键 | 环境变量 | 口径 |
| --- | --- | --- |
| `[sso].state_ttl_seconds` | `BMS_SSO__STATE_TTL_SECONDS` | 流程状态短 TTL；过期即 `20052` |
| `[sso].success_redirect` / `failure_redirect` | `BMS_SSO__SUCCESS_REDIRECT` / `BMS_SSO__FAILURE_REDIRECT` | 只允许配置来源；域五联调确定值 |
| `[sso].ip_rate_limit` / `provider_rate_limit` | `BMS_SSO__IP_RATE_LIMIT` / `BMS_SSO__PROVIDER_RATE_LIMIT` | 固定窗口 60s；后续按租户 `sys_config` 覆盖留待 |
| `[sso].pkce` | `BMS_SSO__PKCE` | 默认 `true`；不支持的 IdP 以协议适配层处理，不做全局关闭 |
| `[sso].callback_base_url` | `BMS_SSO__CALLBACK_BASE_URL` | 默认直连形态 `http://localhost:8000`；网关形态（`http://localhost:8088`）经行 `config.redirect_uri` 覆盖 |
| `[idp_state_store].provider` | `BMS_IDP_STATE_STORE__PROVIDER` | 基线 `redis`；测试置空回落 Null |
| `[gateway].public_paths`（新增项） | — | 增 `/api/identity/v1/auth/sso`（前缀匹配，覆盖 providers / authorize / callback） |

### 3.7 错误码口径与冲突处置 <a id="errors"></a>

**新增认证子段 `20051~20056`**（架构 09 行 50、`core/error_codes.py` 同步登记；概要 26 §7.1 含义已录）：

| 码位 | 含义 | HTTP | 异常类（`SsoError(AuthError)` 子类） |
| --- | --- | --- | --- |
| `20051` | IdP 配置不存在或已停用 | 404 | `SsoProviderNotFoundError` |
| `20052` | 回调校验失败（`state` 缺失/过期/租户不符 / `nonce` / PKCE / ID Token 校验 / IdP 回传错误） | 400 | `SsoCallbackError` |
| `20053` | 外部 IdP 不可达或超时（发现 / 换码 / 用户信息 / JWKS） | 503 | `SsoProviderUnavailableError` |
| `20054` | 未匹配本地用户且 JIT 未启用 / 被拒 | 403 | `SsoIdentityUnmatchedError` |
| `20055` | 身份映射冲突 | 409 | `SsoIdentityConflictError` |
| `20056` | 本地登录保护（预留，本期不触发） | 429 | `LocalLoginGuardError` |

- **翻译层**：`bms_core` 能力域对 IdP 出站失败抛 `ServiceUnavailableError`（`10007`）；SSO 服务在端点边界翻译为 `SsoProviderUnavailableError`（`20053`），不反向修改已发布的 07_01 错误口径。
- **账号停用**：复用既有 `20004/401`（`AccountDisabledError`），与本地登录口径一致。
- 回写：架构 09「平台已发布码位」补 `20051~20056`；概要 26 §5.2 限流口径由 slowapi 改为 `BaseRateLimiter`；需求 02-1 文本不变（详细设计为准），对齐结论入 §8。

### 3.8 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| providers：租户无启用 IdP | `200` + 空列表（前端只用本地登录） |
| providers / authorize：未知或停用 `idp_key` | `SsoProviderNotFoundError`（20051/404） |
| providers / authorize：无租户上下文且无 `tenant` 参数 | `TenantNotFoundError`（既有，与 refresh 同口径） |
| providers / authorize：上下文租户与 `tenant` 参数不一致 | `20051` |
| authorize：IdP 发现失败 / 超时 | 翻译为 `20053`（failure_redirect 场景经前端提示「IdP 不可用，请用本地登录」） |
| authorize / callback：限流命中 | `RateLimitError`（10005/429） |
| callback：`state` 缺失 / 已消费 / 过期（重放） | `SsoCallbackError`（20052），日志记 `state` 前缀脱敏 |
| callback：请求上下文租户与 state 记录不符 | `20052` |
| callback：`nonce` 不符 / PKCE 校验失败 / ID Token 签名 / `issuer` / `audience` / 过期失败 | `20052` |
| callback：IdP 回传 `error=access_denied`（用户取消） | `20052`（message 区分，前端提示可重试） |
| callback：换码 / userinfo / JWKS 不可达 | `20053` |
| callback：映射未命中（JIT 未启用） | `20054` |
| callback：映射多行 / 唯一约束冲突 | `20055`（读路径防御；写路径归 02_02） |
| callback：org 用户不存在 | `20054` |
| callback：org 用户 `status≠enabled` | `AccountDisabledError`（20004/401） |
| callback：org 不可达 / 契约非法 | `ServiceUnavailableError`（10007/503，fail-closed） |
| callback：`login-state` 写回失败 | `10007/503`（与 01_03 一致；会话已落库，前端重试登录） |
| callback 成功 | `302 {success_redirect}?tenant=…` + `Set-Cookie` refresh；无配置回退 `200 JSON` |
| callback 失败且有 `failure_redirect` | `302 {failure_redirect}?error={code}&message=…` |
| 本地登录 / 刷新 / 登出 | 完全不受影响（SSO 为增量链路，本地通道并存） |
| 达梦 / 三库方言 | 结构走迁移零漂移；`config` 用 `TEXT` 存 JSON 规避方言差异 |

## 7. 边界与开放项 <a id="boundary"></a>

- **归 02_02**：JIT 自动建号（org 内部接口）、域名 / 租户白名单、用户名冲突规则、`identity.user.jit_created`（Outbox）、映射写路径与并发唯一约束处置、`sso:bind` 只读端点；本期未匹配一律 `20054`，`config.jit_enabled` 字段已预留。

- **开放项（回调地址形态）**：回调 `redirect_uri` 默认走直连形态 `{callback_base_url}/api/v1/auth/sso/{idp_key}/callback`；经边缘 / 网关访问时以行 `config.redirect_uri` 覆盖（`http://localhost:8088/api/identity/v1/auth/sso/{idp_key}/callback`）。realm 注册两种形态，生产以部署域名为准（域五联调时定稿）。
- **开放项（无 id_token 的 IdP）**：部分 IdP 不发 `id_token` 时回退 `userinfo`，`nonce` 无法校验（PKCE + 短 TTL + 一次性 state 仍生效）；如需强制，行配置可要求 `id_token`（`02_06` 连通性测试补充）。
- **开放项（Keycloak 测试用户）**：集成用例经 Keycloak Admin API 按需创建测试用户（凭据读 `deploy/.env`，密码随机生成不入仓）；`deploy/keycloak/bms-realm.json` 仅增回调 URI，不预置用户。
- **开放项（真机冒烟）**：mjbk 需重建 identity / org 镜像并应用迁移（`identity:tenant` 0002 + `identity:platform` 0001）、执行 `ops/seed_sso.py` 种子；Keycloak 开发实例已在线（本设计期间验证 HTTP 200），真机链路随本任务收尾窗口执行并留痕。
- **开放项（登录租户来源）**：SSO 端点沿用 01_03 口径（上下文优先 / `tenant` 参数回落到统一租户入口），是否强制「登录页必带 `X-Tenant-ID`」随域五前端联调评估。
