## 5. 端到端证据 <a id="e2e"></a>

- **Keycloak 真实 E2E（integration，2026-09-27 实测通过）**：`test_keycloak_end_to_end_login` —— 种子 IdP 行（`issuer = {KEYCLOAK_PUBLIC_URL}/realms/bms`，`client_secret_ref = env:KEYCLOAK_CLIENT_SECRET`）→ `authorize` 302 至 Keycloak 授权端点 → 真实登录页表单 POST → 302 回本服务回调（授权码）→ `callback` 换码 + ID Token 验签 + 映射命中 → 200 + refresh cookie（`bms_refresh_token`）。Keycloak Admin API 幂等创建测试用户并自愈登记回调 URI（凭据读 `deploy/.env`，不入仓）。
- **回调闭环（ASGI + Mock IdP）**：`test_callback.py` 覆盖成功链路（双 token 同 `session_id`、`sys_session` 落库、Redis 标记、cookie 属性、`login-state` 写回）与全失败分支（`state` / `nonce` / PKCE / 签名 / 未匹配 / 冲突 / 停用 / org 不可达 / 无 `id_token` 回退）。
- **授权跳转与入口清单**：`test_authorize.py` / `test_providers.py` 覆盖 URL 参数、状态落库与 TTL、限流、排序与租户口径。
- **并存**：本地登录 / 刷新 / 登出复用既有 `auth` 用例全量回归（`SessionIssuer` 抽取对外行为不变）。
- **真机部署态冒烟**：mjbk 重建 identity / org 镜像 + 迁移 + `ops/seed_sso.py` 种子 + 真实浏览器链路（入口 → Keycloak → 回调 → 前端回跳 → refresh；IdP 停机时本地登录可用）——随本任务收尾窗口执行并留痕（见 §6）。
