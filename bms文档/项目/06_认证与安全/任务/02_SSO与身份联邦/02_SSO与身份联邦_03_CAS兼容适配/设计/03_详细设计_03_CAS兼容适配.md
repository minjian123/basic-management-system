## 1. 设计目标与范围 <a id="goal"></a>

在 02_01（SSO 登录完整链路，OIDC 先行）与 02_02（JIT 建号与身份映射）之上，按 `BaseIdentityProvider` 契约补齐 **CAS 兼容适配**——协议差异经同一 SSO 链路承载，不为 CAS 另建链路：

1. **CAS 客户端**——`bms_core/idp/cas.py` 新增 `CasIdentityProvider`（`plugin_name = "cas"`）：授权跳转（`service` 拼装）、`serviceValidate` 票据校验（CAS 3.0 `p3/serviceValidate`，含 attributes）、用户属性解析（账号 / 姓名 / 邮箱）；`IdentityProviderRegistry.build` 增 `type="cas"` 分派。
2. **契约扩展（可选参数 / 字段，向后兼容）**——`BaseIdentityProvider.authorize` / `exchange_token` 增可选 `service`；`IdentityToken` 增可选 `identity`；`IdentityUser` 增可选 `name`。CAS 经 `exchange_token`（serviceValidate）直接回填 `identity`，SSO `_resolve_identity` 优先消费；`service`（含 `state`）由 SSO 统一生成，保证登录跳转与校验两处完全一致。
3. **回调票据接入**——`callback` 端点增 `ticket` 查询参数，`code or ticket` 归一后传入 provider（OIDC 用 `code`、CAS 用 `ticket`，链路不分裂）。
4. **属性映射**——内置默认映射（`username` / `name` / `email` 各候选属性名）+ 行配置 `attribute_map` 覆盖；CAS principal 取 `subject`。
5. **失败语义**——票据无效 / 服务未注册 / IdP 回传 `authenticationFailure` → `20052`；IdP 不可达 / 超时 / 响应非法 → `20053`；映射未命中且 JIT 未启用 → `20054`；复用 02_01 既有错误码，不新增码位。
6. **插件族登记**——`type="cas"` 行配置分派 + `CasIdentityProviderFactory` 经 assembly 登记进 `identity_provider` 插件族（`plugin_name` 与 `IDP_PROTOCOLS` 对齐）。
7. **mock CAS 联调**——pytest 夹具 `CasMock`（`httpx.MockTransport`，模拟 `p3/serviceValidate` 成功 / 失败 XML），完成端到端 SSO 登录（含 JIT 建号）与失败分支验证。

**不在本期**：CAS 单点登出（SLO）/ proxy 代理票 / SAML（归后续，见 §7）；IdP 配置 CRUD / 启停 / 连通性 / 凭据加密（`02_06`）；企微 / 钉钉（`02_04`）；BMS 兼作 IdP（`02_05`）；真实 CAS IdP 联调（凭据就绪时，与域 02_04 同口径）；前端登录页与失败提示（域五）；`sys_login_log`（阶段八）。

**安全影响（SDL）**：涉及外部身份断言（CAS 票据）与外部 XML 响应解析。专项验收点：`state` 一次性消费（02_01 既有）+ `service` 与登录时完全一致（防票据挪用于其他服务）；`service` 只由 SSO 依配置 `redirect_uri` + `state` 生成、不取请求参数（防开放重定向）；XML 解析拒绝 `<!DOCTYPE` / `<!ENTITY`（防 XXE / 实体膨胀）并限制响应体积；`authenticationFailure` 不泄露原始 XML，只映射为 `20052`；日志不落票据 / `state`（`state` 前 8 位脱敏，既有口径）；CAS 不要求客户端密钥，无密钥明文落库风险。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 CAS 协议口径 <a id="cas-protocol"></a>

CAS 无令牌交换：授权后 IdP 直接以 `ticket`（服务票据）回跳，客户端凭 `ticket` 调 `serviceValidate` 换回主体与属性。

| 阶段 | 请求 | 响应 |
| --- | --- | --- |
| 授权跳转 | `GET {server_url}{login_path}?service={urlencode(service)}` | `302`（或 CAS 登录页）；`service` = `{redirect_uri}?state={state}` |
| 票据回跳 | CAS 回跳 `service`，追加 `ticket` | 请求携带 `state`（service 原查询串保留）+ `ticket=ST-…` |
| 票据校验 | `GET {server_url}{service_validate_path}?service={urlencode(service)}&ticket={urlencode(ticket)}` | `200` + `serviceResponse` XML |

**成功 XML**（CAS 3.0）：

```xml
<cas:serviceResponse xmlns:cas="http://www.yale.edu/tp/cas">
  <cas:authenticationSuccess>
    <cas:user>alice</cas:user>
    <cas:attributes>
      <cas:displayName>Alice</cas:displayName>
      <cas:email>alice@example.com</cas:email>
    </cas:attributes>
  </cas:authenticationSuccess>
</cas:serviceResponse>
```

**失败 XML**（票据无效 / 服务未注册）：

```xml
<cas:serviceResponse xmlns:cas="http://www.yale.edu/tp/cas">
  <cas:authenticationFailure code="INVALID_TICKET">Ticket ST-… not recognized</cas:authenticationFailure>
</cas:serviceResponse>
```

### 3.2 `BaseIdentityProvider` 契约扩展（可选参数 / 字段，向后兼容） <a id="idp-contract"></a>

| 项 | 现状（02_01） | 扩展后 | 语义 |
| --- | --- | --- | --- |
| `authorize(state, *, nonce, code_challenge, code_challenge_method)` | 无 `service` | 增 `service: str | None = None` | 授权入口附加服务地址（CAS 用作 `service`；OIDC / 占位忽略） |
| `exchange_token(code, *, code_verifier)` | 无 `service` | 增 `service: str | None = None` | 换码 / 校验附加服务地址（CAS 用于 `serviceValidate` 的 `service`；OIDC / 占位忽略） |
| `IdentityToken` | `access_token` / `token_type` / `expires_in` / `id_token` / `refresh_token` | 增 `identity: IdentityUser | None = None` | 协议可直接回填身份（CAS 无令牌、无独立 userinfo 时序）；SSO 优先消费 |
| `IdentityUser` | `subject` / `username` / `email` / `tenant` / `idp_key` | 增 `name: str | None = None` | 显示名（CAS attributes；OIDC userinfo 仍只填 username，可选补 name） |

- `BaseIdentityProvider.authorize` / `exchange_token` 默认实现（抽象）声明新参数；`OidcIdentityProvider` / `NullIdentityProvider` / 测试 `_PlainProvider` 同步签名（忽略 `service`），既有行为不变。
- `_resolve_identity` 解析顺序：`token.identity`（CAS）→ `token.id_token`（OIDC 验签）→ `userinfo(token.access_token)`（OIDC 回退）；三条路径互斥、对既有 OIDC 零影响。

### 3.3 CAS 客户端（`bms_core/idp/cas.py`） <a id="cas-client"></a>

```text
CasIdentityProvider(BaseIdentityProvider)   # plugin_name = "cas"
├── __init__(server_url, redirect_uri, *, login_path="/login",
│            service_validate_path="/p3/serviceValidate",
│            attribute_map=None, timeout=10.0, transport=None)
├── authorize(state, *, nonce=None, code_challenge=None, code_challenge_method=None, service=None) -> str
│     └── {server_url}{login_path}?service={urlencode(service or redirect_uri)}（nonce / PKCE 忽略）
├── exchange_token(code, *, code_verifier=None, service=None) -> IdentityToken
│     └── GET {server_url}{service_validate_path}?service=…&ticket={code}
│           ├─ 成功 → IdentityToken(access_token="", identity=IdentityUser(subject, username, name, email, idp_key=server_url))
│           ├─ authenticationFailure → AuthError（票据无效 / 服务未注册）
│           └─ 网络 / 非 2xx / 响应非合法 XML / 结构非法 → ServiceUnavailableError
└── userinfo(access_token) -> IdentityUser
      └── 不支持（CAS 主体随票据校验一次取回）：抛 ConfigError（40001）

CasIdentityProviderFactory(BasePluginFactory[CasIdentityProvider])   # plugin_name = "cas"
└── create() 读 [identity_provider]：cas_server_url 缺失 → PluginError（40002）
```

- **属性映射**：principal（`cas:user`）→ `subject`；`username` / `name` / `email` 按 `attribute_map` 候选序取首个命中；缺省映射如下（行配置同名键覆盖默认候选）：

  | 字段 | 默认候选属性 |
  | --- | --- |
  | `username` | `username` / `uid` / `userName` / `account` |
  | `name` | `displayName` / `cn` / `name` |
  | `email` | `email` / `mail` |

- **XML 安全**：解析前拒绝含 `<!DOCTYPE` / `<!ENTITY` 的响应；响应体超限（默认 256 KiB）即拒；用 `xml.etree.ElementTree` 解析并按**本地名**匹配节点（跨命名空间 / 2.0 / 3.0 兼容），不联网取 DTD / 实体。
- **多值属性**：同名字段以空格拼接的 CAS 多值形态取**首个**值。
- **超时**：复用 `_HTTP_TIMEOUT = 10.0`（与 OIDC 一致）。

### 3.4 行配置实例化（`IdentityProviderRegistry.build` 增 `cas` 分支） <a id="registry"></a>

`build(spec)` 按 `spec.type` 分派：`oidc` → 既有；`cas` → `_build_cas(spec)`；其余抛 `ConfigError`（40001）。

CAS 行 `config` 口径（平铺键，**不要求客户端密钥**）：

| 键 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `cas_server_url` | 是 | — | CAS 服务基址（如 `https://cas.example.com/cas`；尾斜杠自动去除） |
| `redirect_uri` | 是 | — | 回调地址（`ProviderRegistry` 通用派生：行配置优先，缺省按 `[sso].callback_base_url` 派生） |
| `cas_login_path` | 否 | `/login` | 登录端点路径 |
| `cas_service_validate_path` | 否 | `/p3/serviceValidate` | 校验端点路径（CAS 3.0 含属性；2.0 为 `/serviceValidate`） |
| `attribute_map` | 否 | `{}` | 属性映射覆盖（对象：`{字段: [候选属性名…]}`；非法类型抛 `ConfigError`） |

### 3.5 SSO 链路改造（`bms_identity/services/sso.py` + `api/sso.py`） <a id="sso"></a>

**`service` 生成（单一事实源）**：SSO 统一构造 `service = {redirect_uri}?state={quote(state)}`（`redirect_uri` 已含查询串时以 `&` 追加），授权跳转与回调校验两处使用同一函数，保证 CAS 两处 `service` 完全一致；OIDC / 占位 provider 忽略该参数，行为不变。

**授权跳转**：`SsoService.authorize` 生成 `state / nonce / code_verifier` 后，取 `instance.authorize(state, nonce=…, code_challenge=…, code_challenge_method=…, service=service)`。

**回调闭环**：`callback` 增 `state` 参数（回调端点回传），`_exchange(instance, code, flow, idp_key, service)`：

```text
callback(flow, *, idp_key, code, error, ip, user_agent, session, platform_session, session_issuer, state="")
  ├─ error → SsoCallbackError（20052）
  ├─ code 为空 → SsoCallbackError（缺少授权码）
  ├─ 取 IdP 行 → instance（同 02_01）
  ├─ _exchange：instance.exchange_token(code, code_verifier=…, service=…)
  │     ├─ ServiceUnavailableError → SsoProviderUnavailableError（20053）
  │     ├─ AuthError（CAS 票据无效 / 服务未注册）→ SsoCallbackError（20052）
  │     └─ ConfigError → SsoProviderUnavailableError（20053）
  ├─ _resolve_identity：token.identity（CAS）→ id_token 验签（OIDC）→ userinfo（OIDC 回退）
  ├─ _resolve_user_id：映射命中复用；未命中且 JIT 启用 → JitService.provision（02_02）
  ├─ org 概要（停用 → 20004）→ SessionIssuer 签发 → org login-state
  └─ 302 {success_redirect}?tenant=… + Set-Cookie refresh（同 02_01）
```

**CAS 身份归一化**：`token.identity` 存在时构造 `ExternalIdentity(subject, username, name or username, email)` 交 JIT / 映射路径（复用 02_02 全部规则：映射键 `{tenant}:{provider_key}`、白名单、并发锁、`identity.user.jit_created`）。

**回调端点**（`GET /api/v1/auth/sso/{idp_key}/callback`）：新增 `ticket` 查询参数；`code or ticket` 归一为凭证、`state` 传入服务层；`error` 沿用。OIDC 仍走 `code`。

### 3.6 配置契约 <a id="config"></a>

`[identity_provider]` 增 CAS 字段（缺省不启用；`provider` 仍缺省空）：

```toml
[identity_provider]
# 既有 OIDC 字段略（issuer / client_id / client_secret / redirect_uri / scopes / 缓存 TTL）
# CAS 服务基址（如 https://<cas-host>/cas；仅 provider="cas" 时必填）
cas_server_url = ""
# CAS 登录端点路径
cas_login_path = "/login"
# CAS 校验端点路径（CAS 3.0 p3/serviceValidate 含属性；2.0 用 /serviceValidate）
cas_service_validate_path = "/p3/serviceValidate"
# CAS 属性映射覆盖（对象：{username|name|email: [候选属性名…]}；空对象用内置默认映射）
attribute_map = {}
```

| 配置键 | 环境变量 | 口径 |
| --- | --- | --- |
| `[identity_provider].cas_server_url` | `BMS_IDENTITY_PROVIDER__CAS_SERVER_URL` | CAS 服务基址；单例插件形态（`provider="cas"`）必填 |
| `[identity_provider].cas_login_path` | `BMS_IDENTITY_PROVIDER__CAS_LOGIN_PATH` | 登录端点路径（缺省 `/login`） |
| `[identity_provider].cas_service_validate_path` | `BMS_IDENTITY_PROVIDER__CAS_SERVICE_VALIDATE_PATH` | 校验端点路径（缺省 `/p3/serviceValidate`） |
| `[identity_provider].attribute_map` | `BMS_IDENTITY_PROVIDER__ATTRIBUTE_MAP` | 属性映射覆盖（JSON 对象） |

- 行配置（`sys_identity_provider.config`）与单例配置字段同名同义；生产多租户以行配置为准（`02_06` 管理面）。
- `provider = "cas"` 时选中 `CasIdentityProviderFactory`；SSO 链路本走行配置实例化，单例工厂仅作插件族完整登记与直连兜底。

### 3.7 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| authorize：`idp_key` 未知 / 停用 | `SsoProviderNotFoundError`（20051/404，既有） |
| authorize：`cas_server_url` 缺失 / 行配置非法 | `SsoProviderUnavailableError`（20053/503，既有翻译） |
| callback：缺 `ticket`（且无 `code`） | `SsoCallbackError`（20052/400） |
| callback：`state` 缺失 / 过期 / 重放 / 租户不符 | `SsoCallbackError`（20052/400，既有） |
| callback：CAS 回传 `authenticationFailure`（`INVALID_TICKET`） | `AuthError` → 翻译 `SsoCallbackError`（20052/400） |
| callback：CAS 回传 `authenticationFailure`（`INVALID_SERVICE`） | `AuthError` → 翻译 `SsoCallbackError`（20052/400） |
| callback：CAS 服务不可达 / 超时 / 非 2xx | `ServiceUnavailableError` → `SsoProviderUnavailableError`（20053/503） |
| callback：响应非合法 XML / 含 `DOCTYPE` / 超限 / 缺 `authenticationSuccess` | `ServiceUnavailableError` → `SsoProviderUnavailableError`（20053/503） |
| callback：`service` 与登录时不一致（CAS 侧拒绝） | IdP 返回 `authenticationFailure` → `20052` |
| callback：映射未命中且 JIT 未启用 | `SsoIdentityUnmatchedError`（20054/403，既有） |
| callback：org 用户不存在 | `SsoIdentityUnmatchedError`（20054/403，既有） |
| callback：org 用户 `status≠enabled` | `AccountDisabledError`（20004/401，既有） |
| callback：JIT 锁 / 映射冲突 | `SsoIdentityConflictError`（20055/409，既有） |
| OIDC / 本地登录 | 完全不受影响（CAS 为增量协议适配，签名扩展向后兼容） |
| 达梦 / 三库方言 | 无表结构变更，结构走既有迁移零漂移 |

## 4. 兼容性与消费方影响 <a id="compat"></a>

- **新增**：`bms_core/idp/cas.py`（`CasIdentityProvider` / `CasIdentityProviderFactory` / 属性映射 helper）、`[identity_provider]` CAS 字段、`ticket` 回调参数、assembly CAS 工厂登记、mock `CasMock` 与用例。
- **扩展（可选参数 / 字段，向后兼容）**：`BaseIdentityProvider.authorize` / `exchange_token` 增 `service`；`IdentityToken` 增 `identity`；`IdentityUser` 增 `name`；`IdentityProviderRegistry.build` 增 `cas` 分派；`SsoService._exchange` 增 `AuthError → 20052` 翻译；`_resolve_identity` 增 `token.identity` 优先分支。
- **行为变更（需回归）**：`SsoService.authorize` 现向 provider 传 `service`（OIDC / 占位忽略，URL 不变）；`callback` 增 `state` 形参（默认 `""`，既有 OIDC 直调用例不受影响）；callback 端点契约增 `ticket`（非破坏新增，需重生成契约与 api-types）。
- **不改**：本地登录 / 刷新 / 登出链路；02_01 三端点路径与错误码 `20051`~`20056`（复用，不新增）；`sys_identity_provider` / `sys_user_identity` 表结构与迁移链；JIT 规则与映射键；`org_client`；OIDC 客户端行为（未传 `service` 时 URL 与旧行为一致）。
- **无迁移**：无表结构变更，不改 `identity:tenant` / `identity:platform` / `org:tenant` 链。
- **消费方前置契约标注**：`02_04`（企微 / 钉钉可复用 `service` / `identity` 契约扩展与 ticket 归一形态，按各自协议落地）、`02_06`（CAS 行配置键 `cas_server_url` / `cas_login_path` / `cas_service_validate_path` / `attribute_map` 的管理面校验与连通性测试复用 `IdentityProviderRegistry`）、域五（登录页按 `providers` 渲染 CAS 入口、跳转与失败提示）、阶段八（CAS 登录失败结构化日志 / `sys_login_log`）。

## 7. 边界与开放项 <a id="boundary"></a>

- **归 02_04**：企业微信 / 钉钉免登适配（可复用本期 `service` / `identity` 契约扩展与 `ticket` 归一形态，各自协议另定）。
- **归 02_06**：`sys_identity_provider` CRUD / 启停 / 连通性；CAS 行配置键的管理面校验；凭据响应急忙（CAS 无需密钥）。
- **归后续**：CAS 单点登出（SLO）/ proxy 代理票 / SAML；CAS 2.0（无属性）如需强姓名 / 邮箱须改端点路径为 `/serviceValidate`（本期已可配，但无属性，姓名 / 邮箱由映射缺省 + JIT 兜底）。
- **开放项（真实 CAS 联调）**：本期以 mock CAS 夹具联调；真实 CAS IdP 联调归凭据就绪时（与域 02_04 同口径），登记遗留。
- **开放项（CAS 变体）**：个别 CAS 变体需客户端密钥 / 特殊握手——本期不加；如需，经行配置扩展（`02_06` 管理面）或后续任务。
- **开放项（属性多值 / 编码）**：多值属性取首个；非 UTF-8 响应按 `httpx` 文本解码兜底，异常解码按 `20053` 处理。
- **开放项（前端消费）**：登录页按 `providers` 渲染 CAS 入口与「IdP 不可用 → 用本地登录」引导归域五。
