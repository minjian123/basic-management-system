## 5. 端到端证据 <a id="e2e"></a>

- **CAS 端点 E2E（ASGI + Mock CAS）**：`test_cas.py::test_cas_end_to_end_jit_creates_user_and_session` —— 授权跳转登录 URL 的 `service` 含 `state`；回调 `?state=&ticket=ST-ok` 经 `serviceValidate` 取回 principal + 属性 → JIT 自动建号（org 替身）→ 平台库写入 `sys_user_identity`（`idp_key=demo:cas`、`external_id=cas-alice`）→ `identity.user.jit_created` 入发件箱（一次）→ 签发会话并回执租户。
- **service 一致性**：`CasMock` 记录校验请求的 `service`，断言其等于登录时的 `service`（同一 `state`），验证设计「SSO 统一生成 service 传两处」。
- **失败分支**：`test_cas_invalid_ticket_and_service_rejected`（票据无效 / 服务未注册 → 20052）、`test_cas_unavailable_and_unmatched`（IdP 5xx → 20053；未匹配且 JIT 关闭 → 20054）。
- **契约扩展**：`test_idp.py::test_verify_token_default_and_null`（`_PlainProvider` 随 `service` 契约对齐）、`test_units.py::test_build_service_url_edge`。

## 6. 偏差与遗留 <a id="deviations"></a>

- **偏差**：
  1. 测试侧新增 CAS 专用流程启动 helper（`_start_cas_flow`）——CAS 的 `state` 嵌于 `service` 查询串，通用 `start_flow` 不适用；已回写设计 §9。
- **遗留**：
  1. 真实 CAS IdP 联调（**归口：凭据就绪时，与域 02_04 同口径**）。
  2. CAS 单点登出 / proxy / SAML（**归口：后续阶段**）。
  3. CAS 行配置管理面校验与连通性（**归口：02_06**）。
  4. 登录页 CAS 入口与失败提示（**归口：域五**）。
  5. CAS 登录失败日志 / `sys_login_log`（**归口：阶段八**）。
