## 1. 设计目标与范围 <a id="goal"></a>

在 02_01（SSO 登录完整链路）、02_02（JIT 建号与身份映射）、02_03（CAS 适配与契约扩展）之上，按 `BaseIdentityProvider` 契约补齐 **企业微信 / 钉钉免登适配**——两平台协议差异经同一 SSO 链路承载，不另建链路、不新增签名骨架：

1. **企业微信适配**——`bms_core/idp/wecom.py` 新增 `WecomIdentityProvider`（`plugin_name = "wecom"`）：`authorize` 支持 `mode=qr`（PC 扫码，官方新版登录链接 `login.work.weixin.qq.com/wwlogin/sso/login`）与 `mode=oauth`（企微内置 Webview / 移动端 H5 网页授权 `open.weixin.qq.com/connect/oauth2/authorize`）；`exchange_token` 以 `gettoken`（应用 `access_token`，进程内缓存）+ `cgi-bin/auth/getuserinfo` 取成员身份（`userid`，非成员回落 `openid`），经 `IdentityToken.identity` 回填。
2. **钉钉适配**——`bms_core/idp/dingtalk.py` 新增 `DingtalkIdentityProvider`（`plugin_name = "dingtalk"`）：`authorize` 走新版 OAuth2（`login.dingtalk.com/oauth2/auth`）；`exchange_token` 以 `v1.0/oauth2/userAccessToken` 换用户级令牌；`userinfo` 以 `x-acs-dingtalk-access-token` 调 `v1.0/contact/users/me` 取身份（`unionId`，回落 `openId`）。
3. **行配置分派**——`IdentityProviderRegistry.build` 增 `type="wecom"` / `type="dingtalk"` 分支；单例工厂 `WecomIdentityProviderFactory` / `DingtalkIdentityProviderFactory` 登记进 `identity_provider` 插件族（`plugin_name` 与 `IDP_PROTOCOLS` 对齐）。
4. **扫码接口契约（供域 05_04 对接）**——复用既有 `authorize` / `callback` 链路，新增 `GET /api/v1/auth/sso/{idp_key}/authorize-url` JSON 端点（返回 `authorize_url` / `state` / `expires_in`），供前端渲染二维码或初始化平台内嵌登录组件；**不做后端轮询状态机与会话旁路存储**。
5. **错误语义**——新增企微 / 钉钉专用码段 `20057`~`20062`（配置类 / 授权类 / 不可达类，每平台三码）；映射未命中 / 冲突 / 停用等仍复用既有 `20054` / `20055` / `20004`。
6. **配置与校验**——凭据经 `sys_identity_provider.config` 平铺键配置（密钥只存引用 `env:`）；凭据缺失 / 非法时实例化即抛配置类错误（入口不可用、提示明确）；**连通性测试归域 02_06**（复用 `IdentityProviderRegistry`，本任务不实现端点）。
7. **联调口径**——交付适配与单元 / 集成测试（`httpx.MockTransport` 模拟两平台响应）；**企业真实凭据联调与移动端内嵌 H5 免登留阶段十七**（凭据就绪可提前真跑）。

**不在本期**：钉钉旧版 `oapi.dingtalk.com/connect/*` 与 `sns/getuserinfo_bycode` 签名链路；企业微信旧版 `wwopen/sso/qrConnect`；微信开放平台 / 公众号 C 端登录；后端扫码轮询状态机与「会话待领取」旁路存储；连通性测试端点与配置 CRUD（`02_06`）；`sys_login_log`（阶段八）；移动端 H5 免登（阶段十七）；前端二维码件与状态机（域五 `05_04`）。

**安全影响（SDL）**：涉及外部身份断言（外部 `code`）与两平台身份接口。专项验收点：`state` 一次性消费（02_01 既有，前端二维码场景由 `authorize-url` 生成的 `state` 承载）+ 回调按路径 `idp_key` 与流程记录交叉校验；`redirect_uri` 只由行配置 / 派生生成、不取请求参数（防开放重定向）；应用 `access_token` 仅进程内缓存、不落库不落日志；`secret` 只存引用（`env:`）运行期解析为内存明文，日志不落 `code` / `token` / `secret`（`state` 前 8 位脱敏，既有口径）；两平台错误响应只映射为业务码，不外泄原始报文。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 企业微信协议口径 <a id="wecom-protocol"></a>

企业微信提供两种拿 `code` 的入口，回跳均为 `redirect_uri?code=CODE&state=STATE`，且都走同一换身份接口。

| 形态 | 授权入口 | 说明 |
| --- | --- | --- |
| `mode=qr`（PC 扫码） | `GET {login_url}?login_type=CorpApp&appid={corp_id}&agentid={agent_id}&redirect_uri={enc}&state={state}` | 默认 `login_url = https://login.work.weixin.qq.com/wwlogin/sso/login`；新版扫码 + 桌面端快速登录 |
| `mode=oauth`（内嵌 H5） | `GET {oauth_url}?appid={corp_id}&redirect_uri={enc}&response_type=code&scope={scope}&state={state}&agentid={agent_id}#wechat_redirect` | 默认 `oauth_url = https://open.weixin.qq.com/connect/oauth2/authorize`；`scope` 缺省 `snsapi_base` |

换取身份（`exchange_token`）：

```text
1) GET {api_base_url}/cgi-bin/gettoken?corpid={corp_id}&corpsecret={secret}
   → { errcode:0, access_token, expires_in }        # 应用级令牌，进程内缓存
2) GET {api_base_url}/cgi-bin/auth/getuserinfo?access_token={token}&code={code}
   → 企业成员 { userid }   /   非成员 { openid, external_userid }
```

- `api_base_url` 缺省 `https://qyapi.weixin.qq.com`。
- 身份主键：`subject = userid or openid`（`userid` 优先，非企业成员回落 `openid`）；`username = subject`。
- **扫码 `code` 不返回 `user_ticket`**，本期不取敏感信息（手机 / 邮箱）；成员详情如需另经通讯录接口（本期不做，见 §7）。
- 令牌缓存：进程内按实例缓存 `access_token` 与到期时刻，命中且未过期即复用（防 `gettoken` 频率拦截）。

### 3.2 钉钉协议口径 <a id="dingtalk-protocol"></a>

仅新版 OAuth 2.0：

| 阶段 | 请求 | 响应 |
| --- | --- | --- |
| 授权跳转 | `GET {login_url}?redirect_uri={enc}&response_type=code&client_id={client_id}&scope={scope}&state={state}&prompt={prompt}` | 用户确认后 `redirect_uri?code=…&authCode=…&state=…`（两码同值） |
| 换用户令牌 | `POST {api_base_url}/v1.0/oauth2/userAccessToken`，body `{clientId, clientSecret, code, grantType:"authorization_code"}` | `{ accessToken, refreshToken, expireIn, corpId }` |
| 取用户信息 | `GET {api_base_url}/v1.0/contact/users/me`，头 `x-acs-dingtalk-access-token: {accessToken}` | `{ unionId, openId, nick, avatarUrl, email, mobile, stateCode }` |

- `login_url` 缺省 `https://login.dingtalk.com/oauth2/auth`；`api_base_url` 缺省 `https://api.dingtalk.com`；`scope` 缺省 `openid`；`prompt` 缺省 `consent`。
- 身份主键：`subject = unionId or openId`（`unionId` 优先，回落 `openId`）；`username = nick or subject`；`name = nick or subject`；`email` 可空。
- 回跳 `code` 与 `authCode` 同值，回调端点按既有 `code` 参数接收即可，无需新增参数。

### 3.3 适配器实现 <a id="adapters"></a>

```text
WecomIdentityProvider(BaseIdentityProvider)          # plugin_name = "wecom"
├── __init__(corp_id, agent_id, secret, redirect_uri, *, mode="qr",
│            login_url=…wwlogin…, oauth_url=…oauth2/authorize…, api_base_url=…qyapi…,
│            scope="snsapi_base", login_type="CorpApp", timeout=10.0, transport=None)
├── authorize(state, *, nonce=None, code_challenge=None, code_challenge_method=None, service=None) -> str
│     ├─ mode == "oauth" → {oauth_url}?appid&redirect_uri&response_type=code&scope&state&agentid#wechat_redirect
│     └─ 否则（qr）         → {login_url}?login_type&appid&agentid&redirect_uri&state
├── exchange_token(code, *, code_verifier=None, service=None) -> IdentityToken
│     ├─ gettoken（缓存）→ 失败（网络 / 非 2xx / 非 JSON 对象）→ WecomUnavailableError；errcode≠0 → WecomConfigError
│     ├─ getuserinfo → 失败（网络 / 非 2xx / 非 JSON 对象）→ WecomUnavailableError；errcode≠0 → WecomAuthError
│     └─ 成功 → IdentityToken(access_token="", identity=IdentityUser(subject, username, idp_key=corp_id))
└── userinfo(access_token) -> IdentityUser
      └── 企微无独立 userinfo 时序：抛 ConfigError（40001）

DingtalkIdentityProvider(BaseIdentityProvider)       # plugin_name = "dingtalk"
├── __init__(client_id, client_secret, redirect_uri, *, login_url=…, api_base_url=…,
│            scope="openid", prompt="consent", timeout=10.0, transport=None)
├── authorize(state, *, nonce=None, code_challenge=None, code_challenge_method=None, service=None) -> str
│     └── {login_url}?redirect_uri&response_type=code&client_id&scope&state&prompt
├── exchange_token(code, *, code_verifier=None, service=None) -> IdentityToken
│     ├─ POST userAccessToken → 网络 / 非 JSON 对象 / 5xx → DingtalkUnavailableError；4xx → DingtalkAuthError
│     └─ 成功 → IdentityToken(access_token=accessToken, expires_in=expireIn, refresh_token=refreshToken)
└── userinfo(access_token) -> IdentityUser
      ├─ GET contact/users/me（头 x-acs-dingtalk-access-token）→ 网络 / 非 JSON 对象 / 5xx → DingtalkUnavailableError；4xx → DingtalkAuthError
      └─ 成功 → IdentityUser(subject=unionId or openId, username/name=nick, email, idp_key=client_id)
```

- 两适配器 `authorize` 忽略 `nonce` / PKCE / `service`（按各自协议仅使用 `state`；OIDC / CAS 既有行为不变）。
- `exchange_token` 出站统一走 `httpx.AsyncClient`（`transport` 供测试注入 `MockTransport`），超时缺省 `10.0`（与 OIDC / CAS 一致）。
- **企业微信身份经 `token.identity` 回填**（复用 02_03 契约，SSO `_resolve_identity` 优先消费）；**钉钉经 `access_token` → `userinfo` 回填**（复用 OIDC 回退路径）；均不改 `BaseIdentityProvider` 契约。
- 工厂：`WecomIdentityProviderFactory` / `DingtalkIdentityProviderFactory`（`BasePluginFactory`，读 `[identity_provider]`，必填缺失启动期 `PluginError` 40002）。

### 3.4 行配置实例化（`IdentityProviderRegistry.build` 增两分支） <a id="registry"></a>

`build(spec)` 按 `spec.type` 分派：`oidc` / `cas` → 既有；`wecom` / `dingtalk` → `_build_wecom` / `_build_dingtalk`；其余抛 `ConfigError`。

企业微信行 `config`（平铺键）：

| 键 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `corp_id` | 是 | — | 企业 CorpID（授权 `appid`；兼作 `idp_key` 来源） |
| `agent_id` | 是 | — | 应用 AgentID（扫码与 H5 授权携带） |
| `secret_ref` | 是 | — | 应用密钥引用（`env:变量名`，运行期解析明文） |
| `redirect_uri` | 是 | — | 回调地址（`ProviderRegistry` 通用派生：行配置优先，缺省按 `[sso].callback_base_url`） |
| `mode` | 否 | `qr` | `qr`（PC 扫码）/ `oauth`（内嵌 H5 网页授权） |
| `login_url` | 否 | `https://login.work.weixin.qq.com/wwlogin/sso/login` | 扫码入口（`mode=qr`） |
| `oauth_url` | 否 | `https://open.weixin.qq.com/connect/oauth2/authorize` | 网页授权入口（`mode=oauth`） |
| `api_base_url` | 否 | `https://qyapi.weixin.qq.com` | 服务端接口基址 |
| `scope` | 否 | `snsapi_base` | `mode=oauth` 的 scope |
| `login_type` | 否 | `CorpApp` | `mode=qr` 的登录类型 |

钉钉行 `config`（平铺键）：

| 键 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `client_id` | 是 | — | Client ID / AppKey（授权 `client_id`；兼作 `idp_key` 来源） |
| `client_secret_ref` | 是 | — | 应用密钥引用（`env:变量名`） |
| `redirect_uri` | 是 | — | 回调地址（同上派生口径） |
| `login_url` | 否 | `https://login.dingtalk.com/oauth2/auth` | 授权入口 |
| `api_base_url` | 否 | `https://api.dingtalk.com` | 服务端接口基址 |
| `scope` | 否 | `openid` | 授权 scope |
| `prompt` | 否 | `consent` | 授权确认方式 |

- 必填缺失 / 密钥引用解析失败 → `WecomConfigError`（20057）/ `DingtalkConfigError`（20060），**不改** 既有 `_require_config_str` 抛 `ConfigError` 的通用口径（两 `_build_*` 内捕获并转抛平台专用异常）。
- `mode` 仅接受 `qr` / `oauth`，非法 → `WecomConfigError`。
- 复用 02_02 的 `jit_enabled` / `allowed_email_domains` 键（JIT 路径不变）。

### 3.5 SSO 链路改造（`authorize-url` 端点） <a id="sso"></a>

**服务层**（`bms_identity/services/sso.py`）：抽取 `authorize_info(...) -> SsoAuthorizeResult`（现有 `authorize` 主体：限流 → 取行 → 取实例 → 生成 `state / nonce / verifier` 落流程状态 → 构造授权 URL），返回 `authorize_url / state / expires_in`（`expires_in = [sso].state_ttl_seconds`）；`authorize(...)` 保留为薄封装（`return (await self.authorize_info(...)).authorize_url`），既有 302 行为不变。

**端点**（`bms_identity/api/sso.py`）：

```text
GET /api/v1/auth/sso/{idp_key}/authorize-url      # 公开；租户解析与限流同 authorize
  → 200 ApiResponse[SsoAuthorizeInfo] = { authorize_url, state, expires_in }
  失败分支同 authorize（20051 / 20053 / 20057 / 20060 / 10005 限流）
```

- 前端（域 05_04）据此渲染二维码 / 初始化平台内嵌登录组件；用户确认后回跳 `redirect_uri`，由既有 `callback` 完成会话签发（refresh cookie + `302 success_redirect`）。
- 授权 URL 内已含平台参数（企微 `appid` / `agentid` / `redirect_uri` / `state`；钉钉 `client_id` / `scope` / `prompt` / `state`），前端如需内嵌组件可从返回的 `authorize_url` 查询串解析，无需后端另出字段。
- `SsoAuthorizeInfo`（`schemas/sso.py`）：`authorize_url: str`、`state: str`、`expires_in: int`。

### 3.6 错误码与异常 <a id="errors"></a>

认证段（`2xxxx`）SSO 子段内新增企微 / 钉钉专用码位（`error_codes.py` 单一登记）：

| 码 | 常量 | 异常类 | HTTP | 场景 |
| --- | --- | --- | --- | --- |
| `20057` | `WECOM_CONFIG` | `WecomConfigError` | 503 | 企微行配置缺失 / 非法（`corp_id` / `agent_id` / 密钥引用 / `mode`）、`gettoken` 返回凭据类 `errcode` |
| `20058` | `WECOM_AUTH` | `WecomAuthError` | 400 | 企微 `getuserinfo` 返回 `errcode`（`code` 无效 / 用户未授权 / 不在可见范围） |
| `20059` | `WECOM_UNAVAILABLE` | `WecomUnavailableError` | 503 | 企微接口网络 / 超时 / 非 2xx / 响应非法 |
| `20060` | `DINGTALK_CONFIG` | `DingtalkConfigError` | 503 | 钉钉行配置缺失 / 非法（`client_id` / 密钥引用） |
| `20061` | `DINGTALK_AUTH` | `DingtalkAuthError` | 400 | 钉钉授权码换取 4xx（`code` 无效 / 用户未授权）、用户信息接口 4xx |
| `20062` | `DINGTALK_UNAVAILABLE` | `DingtalkUnavailableError` | 503 | 钉钉接口网络 / 超时 / 5xx / 响应非法 |

- 异常层次：新增 `EnterpriseIdpError(SsoError)` 子段基，六个子类预置码位与 HTTP 状态（`exceptions.py`）。
- `SsoService._exchange` / `authorize` / `callback` 中，`EnterpriseIdpError` **优先捕获并原样抛出**（在 `ServiceUnavailableError` / `AuthError` / `ConfigError` 之前），保证专用码不被既有翻译逻辑覆盖；映射未命中 / 冲突 / 停用等仍走 `SsoIdentityUnmatchedError`（20054）/ `SsoIdentityConflictError`（20055）/ `AccountDisabledError`（20004）。
- 失败日志沿用 02_01 结构化 `warning`（`idp_key` / `tenant` / `code` / `error`；`state` 前 8 位脱敏，不落 `code` / `token` / `secret`）。

| 行配置键 | 单例字段 | 环境变量（密钥） | 口径 |
| --- | --- | --- | --- |
| `corp_id` | `wecom_corp_id` | — | 企业 CorpID |
| `agent_id` | `wecom_agent_id` | — | 应用 AgentID |

### 3.8 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |

## 7. 边界与开放项 <a id="boundary"></a>

- **归 02_06**：`sys_identity_provider` CRUD / 启停 / 连通性测试（企微 `gettoken`、钉钉 `userAccessToken` 探活）；企微 / 钉钉行配置键写入校验与凭据掩码。
- **归域五 `05_04`**：二维码件渲染、轮询状态机与用户体验；前端消费 `authorize-url` 后回跳 `callback`。
- **归阶段十七**：企业真实凭据联调；移动端内嵌 H5 免登（企微 `mode=oauth` 已就绪，待真实环境验证）；钉钉移动端 JSAPI 免登。
- **开放项（企微敏感信息）**：本期不取手机 / 邮箱（扫码 `code` 无 `user_ticket`）；如后续需要，经 `mode=oauth` + `snsapi_privateinfo` + `getuserdetail` 扩展（另立行配置 scope 与字段映射）。
- **开放项（钉钉旧版）**：旧版 `oapi.dingtalk.com/connect/*` 与 `sns/getuserinfo_bycode` 签名链路不实现；存量旧版接入如需，后续任务或行配置扩展。
- **开放项（令牌失效重取）**：企微应用 `access_token` 进程内缓存；多实例部署与过期瞬间的并发重取由各实例独立处理（不做跨实例共享缓存），如需可经 Redis 缓存后续优化。
- **开放项（失败细分）**：企微 / 钉钉各平台错误码统一收敛为「配置 / 授权 / 不可达」三类，不逐条透传平台 `errcode`；排障依赖结构化日志。
