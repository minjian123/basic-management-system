## 2. 门禁核对对象与判定口径 <a id="criteria"></a>

**核对对象**：计划 §5「验收门禁」现有 **10 行**，与《[总体项目规划](../../../../../../规划/总体项目规划.md)》「阶段内容与完成标准」节（阶段六行）逐条对位——**不新增、不合并、不删减**验收点（决策项 1）。10 行分别为：本地登录链路 / SSO 登录链路 / JIT 建号 / 前端登录与按服务寻址 / 策略强制生效 / 会话强制踢出 / 账号锁定与手动解锁 / BMS 作 IdP / 数据脱敏 / 安全与覆盖率门槛。

**判定口径**（决策项 3）：

- 结论取值只取 **「达标」**；凡「机制与产物已交付、真实业务链路或部署形态留后续阶段」的项，结论仍记「达标」，并在其后以「（限定：… → 计划 §7 第 N 项）」注明归口与去向。
- **不出现「未达标」**：若核对中发现确凿不达标项，先停下报用户确认，不得自行按「达标」写下（与《[AI开发规范](../../../../../../规范/AI开发规范.md)》「随时可停」一致）。
- 证据形态固定三类：**任务测试记录**（命令与原始输出）、**GitLab 流水线号**（项目 `bms/bms`）、**Kiwi TCMS 用例编号**；计数字面值（用例数 / 覆盖率）只作**收口当日快照**记录，不在文档中断言「永久值」。
