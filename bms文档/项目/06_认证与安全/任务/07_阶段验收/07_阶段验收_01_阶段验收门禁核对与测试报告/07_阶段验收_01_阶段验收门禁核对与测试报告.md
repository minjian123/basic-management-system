## 2. 任务内容 <a id="content"></a>

1. ** 门禁逐条核对**：按阶段六完成标准（本地 + SSO 登录链路 E2E、JIT 建号落库、前端登录与按服务寻址联通、策略强制生效）与《[总体项目规划](../../../../../规划/总体项目规划.md)》阶段六行逐条给出结论与证据索引（Kiwi 用例 / 门禁输出 / 报告章节）。
2. **阶段测试报告**：归档 `01_测试报告_认证与安全.md`（用例执行、缺陷、覆盖率（认证模块 ≥80% 与整体口径）、安全专项、风险与遗留）。
3. **状态一致性**：任务 / 计划两处状态与完成日期一致；父任务工作量 = 自有 + 直属子任务合计。
4. **遗留归口**：确需延后的项逐条给归口（企业真实凭据联调 → 阶段十七、Socket.IO 广播 → 阶段八、登录日志 → 阶段八、`data:plain` 真实权限 → 阶段七、会话管理页面 → 阶段十五 等），登记计划「后续阶段待办」台账。
5. **收口提交**：门禁结论表 + 测试报告归档 + 状态回写。

> **前置契约（已交付）**：安全专项用例与认证模块覆盖率门槛已随 [04_04](../../../任务/04_数据脱敏与安全加固/04_数据脱敏与安全加固_04_安全专项用例与覆盖率门槛/04_数据脱敏与安全加固_04_安全专项用例与覆盖率门槛.md) 交付（2026-10-03）——七类安全专项集中套件（Kiwi 2235）全绿；路径级覆盖率门禁脚本 `scripts/tools/base-check/check-coverage-threshold.py` 挂 CI `backend-test`（认证 identity 服务 99.3% / `bms_core` 认证横切 99.5%，均 ≥80%），覆盖率快照 `backend/coverage.json` 以 artifact 归档（保留 30 天）。本任务的覆盖率与安全专项章节可直接引用其门禁输出与快照；门槛口径与路径组见 04_04 详细设计 §3.2。

## 3. 完成标准 <a id="accept"></a>

 门禁逐条有结论与证据且无未达标项（或未达标项已归口并获确认）；阶段测试报告归档；三类文档就位（进度以阶段计划为准）；遗留台账逐条有归口、无「无归口」条目。
