## 3. 实施过程 <a id="process"></a>

### 3.1 公共段：输出可读性与冻结机制（`core/collections.py`）

1. 新增常量 `REPR_ITEM_LIMIT = 10` 与函数 `render_payload(payload)`：`list` 渲染为 `[..]`、`dict` 渲染为 `{..}`，超限截断并追加「… 共 N 项」；非容器原样 `repr`。内部以 `cast` 收窄为 `list[Any]` / `dict[Any, Any]`（strict 模式需要）。
2. `BaseCollection` 新增 `_frozen` 标记、抽象 `_freeze_clone()`、`freeze()` 与 `_ensure_mutable()`；`__str__` 兜底为 `类名(<形态标记[ 冻结]>)`。
3. `BaseSorted.__str__` 改为 `类名(render_payload(self._json_data())[ 冻结])`——映射因而输出 `{..}` 而非键值对列表；`_freeze_clone` 按 `_json_data()` 的形态（映射走 `.items()`、序列走元素）重建同类副本。

### 3.2 插入序形态（`core/concurrent.py`）

1. `ConcurrentStableList`：新增 `append` / `extend` / `__iadd__` / `__add__` / `copy` / `pop(index)` / `__setitem__` / `__delitem__` / `sorted` / `merge`；新增 `_spawn(items)`（同类 + 同策略 + 同段数）供拼接 / 排序 / 切片共用，顺带修正切片丢失策略的问题；`_delete_seq` / `_replace_seq` 两个按序号操作助手（`pop` / `__setitem__` / `__delitem__` 用）。
2. `ConcurrentStableSet`：新增 `remove`（缺失抛 `KeyError`）/ `pop()`（取首个插入元素）/ `copy` / `union` / `intersection` / `difference` / `symmetric_difference` / `update` / 四个 `*_update` / `_spawn`。
3. `ConcurrentStableDict`：新增 `__setitem__` / `__delitem__` / `clear` / `pop`（`MISSING` 哨兵区分缺失与 `None` 值）/ `popitem`（LIFO）/ `setdefault`（段锁内查-写，不用 `put_if_absent` 组合）/ `fromkeys` / `copy` / `__or__` / `__ior__` / `sorted_items` / `sorted_keys` / `_spawn`；`update` 改为接受「映射 | 键值对 | kwargs」，映射分支走 `.items()`（**修掉原 `ValueError`**）。
4. 模块级新增 `MISSING: Any = object()` 哨兵（公开名，供 `sorted_collections` 复用）。
5. 写方法统一前置 `self._ensure_mutable()`。

### 3.3 升序形态（`core/sorted_collections.py`）

同一套写法逐一落到 `ConcurrentSortedList` / `ConcurrentSortedSet` / `ConcurrentSortedDict`；`_shard_count` 保存使 `_spawn` 能保段数。两处形态差异如实实现：

- `ConcurrentSortedList.sorted()` 返回**升序同类副本**——底层 `SortedList` 插入即归位，`reverse=True` 对升序形态无效（已写入 docstring 与设计 §3.2）；
- `ConcurrentSortedDict.popitem()` 取**最大键**（升序末位），与内置 `dict` 的「最后」语义对齐。

### 3.4 跨副本 `repr`（`core/redis_collections.py`）

`BaseAsyncSorted.__str__` / `__repr__` 改为描述式 `类名(key='…')`（不读远端、**恒不抛错**）；`BaseAsyncSorted` 与 `BaseCacheSnapshot` 的 `_freeze_clone` 显式抛 `NotImplementedError`（无同步读入口，无法构造内容快照）。

### 3.5 插件只读快照（`core/plugin.py`）

`PluginRegistry.build()` 返回**冻结副本**（内层与外层均 `freeze()`），使「运行期只读」从「碰巧没有 `__setitem__`」变成**真实机制**。

### 3.6 测试与用例

- Kiwi 平台登记用例 **2322**（分类「平台骨架」/ `P2` / `CONFIRMED` / 标签「自动化」），先登记后写码；
- 新增 `tests/core/test_collections_general.py`（74 用例覆盖单元 + 参数化），改造 `tests/core/test_concurrent_stable.py` 的两条旧口径用例（见 §4-1）。

## 6. 偏差与遗留 <a id="deviations"></a>

**偏差（已回写设计 / 规范 / 清单）**：

1. **口径推翻**：`08_02` 详细设计 §3.3 与《后端开发规范》原写「写入仍走显式原子方法，不提供 `append` / `__setitem__`」，本次按确认口径改为「**写糖一律等价于对应原子方法、不新增写路径**」；已回写规范「集合与排序」、《后端基类清单》「集合体系」节、治理台账，并在 `08_02` 设计 §3.3 加注「口径已由 08-4 修订」。
2. **新增 `freeze()` 机制**（原 12 项确认范围外的新待决项，已单独确认）：集合类公共段新增冻结标记 / `freeze()` / `_ensure_mutable()`；`PluginRegistry.snapshot()` 改返回冻结副本。
3. **`merge` 语义修正**：插入序形态由 `heapq.merge`（要求可比较、结果按大小交织）改为**顺序拼接**——插入序不比较元素，归并对该形态无意义。
4. **`sorted` 在升序形态的语义限制**：`reverse=True` 无效（底层维持升序），已在 docstring 与设计 §3.2 写明，用例断言实际行为。
5. **`_Missing` 哨兵**：设计原写「哨兵类」，实施改为裸 `object()`（自建类会触发「所有类须继承基类」护栏，且哨兵不需行为）。

**遗留（不阻塞本次收口）**：

1. **`len()` 在 `SHARDED` 下为 O(段数)**（16），非严格 O(1)；改为维护计数需在每个写路径加计数，收益不抵风险，已在复杂度表如实标注。
2. **切片赋值 / 切片删除**仍不支持（须全表重编号）；若将来确有高频需求，另立「重建集合」助手，而非开放原地切片写。
3. **`sorted_by` 语义含糊**（映射侧只返回键列表）：新场景用 `sorted_items` / `sorted_keys`；是否废弃 `sorted_by` 待后续评估，存量调用方本次零影响。
4. **`__add__` 的策略保真依赖 `_spawn`**：若将来新增锁策略，`_spawn` 是唯一扩展点（设计 §7 已登记）。
