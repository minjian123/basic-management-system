> 认证与安全 · 08 裸无序集合治理 · 子任务 04（需求 08-4，补充需求）· 详细设计

[文档首页](../../../../../../文档首页.md) › [08 裸无序集合治理](../../08_裸无序集合治理.md) › [04 集合类通用功能补齐](../08_裸无序集合治理_04_集合类通用功能补齐.md) › 详细设计

## 1. 设计目标与范围 <a id="goal"></a>

让集合体系在**不新增写路径、不牺牲并发语义**的前提下，能用内置 `list` / `set` / `dict` 的日常写法（`append` / `extend` / `+=` / `d[k]=v` / `del d[k]` / `clear` / `pop` / `setdefault` / `update(映射)` / 命名集合运算）直接操作，并让 `repr` / `str` 可读且**任何形态打印都不抛错**。

### 1.1 现状与缺口（2026-10-20 实测） <a id="gap"></a>

以 `dir(类)` 与 `dir(内置容器)` 求差集实测：

| 类 | 相比内置容器缺失 | 备注 |
| --- | --- | --- |
| `ConcurrentStableList` | `append` `extend` `insert` `pop` `reverse` `sort` `copy` | 另有 `+=` / `+` / 索引赋值 / 索引删除缺失 |
| `ConcurrentStableSet` | `remove` `pop` `copy` `union` `intersection` `difference` `symmetric_difference` 及四个 `*_update` | 运算符已有 |
| `ConcurrentStableDict` | `clear` `pop` `popitem` `setdefault` `fromkeys` `copy` | 另有 `d[k]=v` / `del d[k]` / `update(映射)` / `\|` 缺失 |

同时实测到三处**既有缺陷**：

1. `repr(ConcurrentStableDict({"a": 1}))` → `ConcurrentStableDict([('a', 1)])`（`BaseSorted.__str__` 用 `to_list()`，映射被显示成键值对列表）；
2. `repr(RedisSortedSet(...))` → **抛 `NotImplementedError`**（`__str__` 链到 `to_list()`，跨副本形态无同步读入口），日志 / 调试器 / 异常栈一打印就崩；
3. `ConcurrentStableDict.update({"b": 2})` → **抛 `ValueError: not enough values to unpack (expected 2, got 1)`**（`update` 只按键值对解包）。

另有一处**语义缺陷**（顺带修正）：`BaseSorted.merge` 用 `heapq.merge` 归并，对**插入序**形态无意义（插入序不比较元素，归并结果顺序错乱）——`ConcurrentStableList.merge` 应改为顺序拼接。

### 1.2 范围内 / 范围外 <a id="scope"></a>

- **范围内**：`core/collections.py`（公共段 `__str__` / `__repr__` 与截断助手、`BaseCollection` 兜底 `repr`）、`core/concurrent.py`（`ConcurrentStable*`）、`core/sorted_collections.py`（`ConcurrentSorted*`）、`core/redis_collections.py`（`BaseAsyncSorted.__str__` / `__repr__`）。
- **范围外（不动）**：`Sorted*` 三个非并发类（基于 `sortedcontainers`，内置方法已齐，实测 `copy` 等可用）；插入序与升序形态的**内部数据结构与锁策略**；`RedisSnapshot` 归属与行为；护栏脚本与基线快照；调用方代码（本次只扩 API，不改调用点）。

## 2. 决策确认结果（2026-10-20，12 项） <a id="decisions"></a>

| 项 | 结论 |
| --- | --- |
| 立项落点 | 需求 08-4 + 新任务 `08_04`（归域 08，不重开已收口的阶段二需求编号） |
| 输出可读性 | 「类名 + 内置字面量 + 超长截断」（默认 10 项，超出提示「共 N 项」） |
| 跨副本 `repr` | 描述式（含键名、不读远端），**永不抛错** |
| 列表写糖 | 全补 `append` / `extend` / `+=` / `+` |
| 列表按索引写删 | 补 `pop(index)` / `l[i]=v` / `del l[i]`；**不补 `insert`** |
| 列表排序 | **不提供原地 `sort` / `reverse`**；新增 `sorted(key=, reverse=)` 返回同类新实例 |
| 字典通用功能 | 全补 `d[k]=v` / `del d[k]` / `clear` / `pop` / `popitem` / `setdefault` / `fromkeys` / `update(映射 \| kwargs)` / `\|` |
| 集合通用功能 | 全补 `remove` / `pop` / `copy` / 四个命名运算及 `*_update` |
| 字典排序辅助 | 补 `sorted_items(key=, reverse=)` / `sorted_keys(reverse=)` |
| 形态覆盖 | 同一套写法**同步落** `ConcurrentSorted*` |
| 旧口径回写 | 改为「写糖一律等价于对应原子方法、不新增写路径」 |
| 性能护栏 | 复杂度标注 + 并发用例 + 「禁用 / 慎用场景」表 |

**不提供 `insert` / 原地 `sort` / 原地 `reverse` 的依据**：插入序形态的序号是**全局单调分配**的，任意位置插入或原地重排都要求「全表重编号」——须持**全局写锁**遍历全部段重排序号，等于阻塞所有写，与「分段写 ≈ 段数写并发」的定位直接冲突。替代写法：重建集合（`ConcurrentStableList(新顺序)`）或先 `to_list()` 在快照上操作。

## 3. 接口设计 <a id="api"></a>

### 3.1 公共段：输出可读性（`core/collections.py`） <a id="repr"></a>

```python
REPR_ITEM_LIMIT = 10
"""`__str__` / `__repr__` 的默认条目上限（超出截断并提示总项数）。"""

class BaseCollection[ItemT](BaseObject, ABC):
    def __str__(self) -> str:
        """兜底展示：类名 + 形态标记（子层覆写为内容式）。"""
        return f"{type(self).__name__}(<{self.collection_kind}>)"

    def __repr__(self) -> str:
        return self.__str__()

class BaseSorted[ItemT](BaseCollection[ItemT], ABC):
    def __str__(self) -> str:
        """内容式展示：类名 + 内置字面量（超长截断）。"""
        return f"{type(self).__name__}({_render_payload(self._json_data())})"
```

`_render_payload(payload)` 规则（`_json_data()` 已返回**内置容器**，故直接 `repr` 即得字面量）：

| 载荷 | 未超限 | 超限 |
| --- | --- | --- |
| `list` | `[1, 2, 3]` | `[1, 2, …, 共 25 项]` |
| `dict` | `{'a': 1}` | `{'a': 1, …, 共 25 项}` |

- 截断**只在展示层**，不改变任何数据；
- 非 `list` / `dict` 载荷（防御分支）直接 `repr`；
- `_json_data()` 本身要取快照，故 `repr` 的成本 = 一次快照（O(n)）；**不得**在热路径日志里对大集合打 `repr`（见 §7 禁用 / 慎用场景）。

**跨副本形态**（`core/redis_collections.py`）：`BaseAsyncSorted` 覆写为描述式，不读远端、不调 `to_list`：

```python
def __str__(self) -> str:
    return f"{type(self).__name__}(key={getattr(self, '_key', '<unbound>')!r})"
```

`RedisSnapshot`（`BaseCacheSnapshot`）落到 `BaseCollection` 兜底形态 `RedisSnapshot(<cache_snapshot>)`，同样不抛错。

### 3.2 列表：`ConcurrentStableList` / `ConcurrentSortedList` <a id="list"></a>

| 成员 | 语义 | 复杂度 | 等价原子方法 / 实现 |
| --- | --- | --- | --- |
| `append(item)` | 追加（= `add`） | O(1)（SHARDED）/ O(log n)（升序） | `add` |
| `extend(items)` | 批量追加（= `update`） | O(k) | `update` |
| `__iadd__(items)` | `l += items`，原地并返回自身 | 同 `extend` | `update` |
| `__add__(items)` | `l + items`，返回**同类新实例**（保策略） | O(n + k) | `_spawn([*to_list(), *items])` |
| `pop(index=-1)` | 取走并删除指定位置元素 | **O(n)**（需先取快照定位序号） | 见下 |
| `__setitem__(index, value)` | 替换指定位置元素（**仅整型索引**） | **O(n)** | 见下 |
| `__delitem__(index)` | 删除指定位置元素（**仅整型索引**） | **O(n)** | 见下 |
| `sorted(key=None, reverse=False)` | 排序结果返回**同类新实例** | O(n log n) | `sorted(to_list(), …)` 后 `_spawn` |
| `merge(*others)` | **改为顺序拼接**（插入序不比较元素） | O(n + Σk) | `_spawn([*to_list(), *chain(others)])` |

`pop` / `__setitem__` / `__delitem__` 的实现（`SHARDED` 与其余策略共用同一语义）：

1. 取 `_view()` 快照（已按序号归并），按索引取目标 `(seq, item)`；索引越界自然抛 `IndexError`；
2. 按 `seq` 定位所在段并只锁该段删除 / 替换（`SHARDED` 下须持**全局读锁**保证定位期间无清空；非 `SHARDED` 走 `_write_data()`）；
3. 替换**保留原 `seq`**（插入位置不变）。

- **切片赋值 / 切片删除不支持**：`l[1:3] = [...]` 会触发 `TypeError`（须全表重编号）；切片**读取**保持返回同类快照（现状不变）。
- **策略保真**：新增 `_spawn(items) -> Self` 受保护助手，按「同类 + 同策略 + 同段数」构造，供 `__add__` / `sorted` / `merge` / 切片读取共用（顺带修掉现有切片丢失策略的问题）。

### 3.3 字典：`ConcurrentStableDict` / `ConcurrentSortedDict` <a id="dict"></a>

| 成员 | 语义 | 复杂度 | 等价原子方法 / 实现 |
| --- | --- | --- | --- |
| `__setitem__(k, v)` | = `set` | O(1) | `set` |
| `__delitem__(k)` | = `delete`（缺失抛 `KeyError`） | O(1) | `delete` |
| `clear()` | 清空 | O(n) | 全段清空（持全局写锁） |
| `pop(k[, default])` | 取走并删除；缺失且无默认抛 `KeyError` | O(1) | 段内 `pop`（区分「缺失」与「值为 `None`」用哨兵） |
| `popitem()` | 取走**最后插入**的键值对（LIFO，与内置 `dict` 一致）；空则抛 `KeyError` | **O(n)**（取快照定位末条序号） | `_view()` 末条 + 按序号删除 |
| `setdefault(k, default=None)` | 存在返回既有值；不存在原子写入并返回 `default` | O(1) | 段锁内「查 → 写」，**不用 `put_if_absent` 组合**（既有值为 `None` 时无法区分） |
| `fromkeys(keys, value=None)` | 类方法，构造同类 | O(k) | `cls((k, value) for k in keys)` |
| `update(items=(), **kwargs)` | 接受**映射 / 键值对可迭代 / 关键字参数**（三者可叠加） | O(k) | 逐项 `set` |
| `__or__(other)` / `__ior__(other)` | `d \| other` 返回同类新实例；`\|=` 原地 | O(n + k) | `_spawn(to_list() + 新增项)` / `update` |
| `sorted_items(key=None, reverse=False)` | 按键值对排序输出**内置 `list`** | O(n log n) | `sorted(items(), …)` |
| `sorted_keys(reverse=False)` | 按键排序输出**内置 `list`** | O(n log n) | `sorted(keys(), reverse=…)` |

- `update` 签名：`def update(self, items: Mapping[KeyT, ValueT] | Iterable[tuple[KeyT, ValueT]] = (), /, **kwargs: ValueT) -> None`；**映射分支显式走 `.items()`**（修掉现抛 `ValueError` 的缺陷），关键字参数并入（同键后写覆盖，插入位置不变）。
- `popitem` 取「最后插入」而非「任意」：`_view()` 已按插入序归并，末条即最后插入；语义与内置 `dict` 一致、可预测。
- `sorted_items` / `sorted_keys` 返回**内置 `list`**（不是集合类）：它们是「排序输出」而非新集合形态，避免与「列表排序走排序契约」的口径冲突；且 `sorted_by` 对映射只返回键列表（语义含糊），本任务以 `sorted_items` / `sorted_keys` 取代其使用场景，**`sorted_by` 保留不动**（存量调用方零影响）。

### 3.4 集合：`ConcurrentStableSet` / `ConcurrentSortedSet` <a id="set"></a>

| 成员 | 语义 | 复杂度 | 等价原子方法 / 实现 |
| --- | --- | --- | --- |
| `remove(item)` | 删除（缺失抛 `KeyError`） | O(1) | `discard` + 存在性判定（段锁内一次完成） |
| `pop()` | 取走并返回**首个插入**元素；空则抛 `KeyError` | O(1)（首条按序号取最小） | `_view()` 首条 + `discard` |
| `copy()` | 同类同策略副本 | O(n) | `_spawn(to_list())` |
| `union(*others)` | 并集 | O(n + Σk) | `__or__` 链式 |
| `intersection(*others)` | 交集 | O(n + Σk) | `__and__` 链式 |
| `difference(*others)` | 差集 | O(n + Σk) | `__sub__` 链式 |
| `symmetric_difference(other)` | 对称差 | O(n + k) | `__xor__` |
| `update(*others)` / `intersection_update(*others)` / `difference_update(*others)` / `symmetric_difference_update(other)` | 原地版本 | 同上 | 逐元素 `add` / `discard` |

- 命名运算一律**返回同类新实例**并保插入序（沿用现有运算符口径）；`*_update` 返回 `None`。
- `ConcurrentStableSet` 现无 `update`（`Set` 抽象不提供），本任务一并补上（与 `union` 等价但原地）。

### 3.5 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 列表 `pop` / `l[i]` / `del l[i]` 索引越界 | `IndexError`（与内置一致） |
| 列表切片赋值 / 切片删除 | `TypeError`（明确不支持，消息指向「重建集合」） |
| 列表 `pop` 空表 | `IndexError`（与内置 `list.pop` 一致） |
| 字典 `pop` 缺失且无默认 / `del d[k]` / `popitem` 空表 | `KeyError`（与内置一致） |
| 集合 `remove` 缺失 / `pop` 空集 | `KeyError`（与内置一致） |
| 字典 `update` 传入既非映射也非键值对可迭代 | 透传 Python 解包错误（`ValueError` / `TypeError`），不额外包装 |
| 任何形态 `repr` / `str` | **恒不抛错**（跨副本走描述式；其余走兜底或内容式） |

- 全部新方法**不在锁内做 IO、不回调外部函数**（沿用既有并发约定）；`sorted` / `sorted_items` / `sorted_keys` 在**锁外**排序（先取快照）。
- 写糖与原子方法**语义完全等价**：`append` ≡ `add`、`extend` ≡ `update`、`__setitem__` ≡ `set`、`__delitem__` ≡ `delete`、`clear` 与「逐键 `delete`」等价（结果等价）。

## 4. 性能口径与「禁用 / 慎用场景」 <a id="perf"></a>

**红线**：写糖一律等价于对应原子方法，**不新增锁、不新增全表重编号、不额外快照拷贝**（`__add__` / `sorted` / `merge` / `copy` 的一次快照属返回新实例的必要成本，已在复杂度列标出）。

| 方法 | 复杂度 | 使用建议 |
| --- | --- | --- |
| `append` / `extend` / `+=` / `d[k]=v` / `del d[k]` / `pop(k)` / `setdefault` / `add` / `discard` | O(1) | 随便用 |
| `remove(x)`（集合）/ `add_if_absent` / `put_if_absent` / `update_atomic` / `get_and_remove` | O(1) | 随便用 |
| `__contains__` / `get` / `len` | O(1)（`len` 为 O(段数)） | 随便用 |
| `pop(index)` / `l[i]=v` / `del l[i]` | **O(n)** | 循环里按索引改列表 → 改「先 `to_list()` 在快照上改，再重建集合」 |
| `popitem()` | **O(n)** | 仅用于低频收尾；批量消费用 `to_list()` + `clear()` |
| `sorted` / `sorted_items` / `sorted_keys` / `sorted_by` | O(n log n) | 排序结果若只要一次，用内置 `sorted(...)`；列表排序优先走**排序契约**（仓储层） |
| `__add__` / `union` / `intersection` / `difference` / `symmetric_difference` / `copy` / `merge` | O(n + k) | 返回新实例；高频拼接改用原地 `extend` / `update` |
| `repr` / `str` | O(n)（一次快照） | **禁止**在大集合热路径日志里直接打 `repr`；用 `len()` + 摘要 |
| `insert` / 原地 `sort` / 原地 `reverse` | — | **不提供**：须全表重编号并持全局写锁，改为重建集合 |

## 5. 测试设计 <a id="test"></a>

| 用例组 | 覆盖点 | 断言要点 |
| --- | --- | --- |
| 输出可读性 | 三类形态 + 截断 + 跨副本 + 兜底 | `repr` 含内置字面量；超 10 项含「共 N 项」；`repr(RedisSortedSet)` 不抛错且含键名；`repr(RedisSnapshot)` 不抛错 |

| 字典通用功能 | 全部 12 项 | `update(映射)` / `update(kwargs)` / `update(键值对)` 三者等价；`pop` 哨兵区分 `None` 值；`popitem` LIFO；`setdefault` 既有值为 `None` 时返回 `None`；`\|` 与 `\|=`；`fromkeys` |
| 集合通用功能 | 全部 12 项 | `remove` 缺失抛 `KeyError`；`pop` 首个插入、空集 `KeyError`；四个命名运算与 `*_update` 结果正确且保插入序 |
| 升序形态同步 | `ConcurrentSorted*` 同一套写法 | 与稳定形态同名同义（升序语义下结果按序） |
| 并发安全 | 多线程写糖混写 | 元素不丢不重、每线程子序列保插入序；`pop` / `setdefault` / `remove` 并发下不崩 |
| 复杂度护栏 | 禁用方法不存在 | 断言 `insert` / `sort` / `reverse` **不存在**（防止误加回全表重编号路径） |

- 用例覆盖**四种锁策略**（`SHARDED` / `RW` / `RLCK` / `SNAPSHOT`）分支；
- 覆盖率门禁：**100%（行 + 分支）**，以 `bms_core/core/collections.py`、`concurrent.py`、`sorted_collections.py`、`redis_collections.py` 为目标文件。

## 7. 边界与开放项 <a id="boundary"></a>

1. **切片赋值 / 切片删除**：不做（全表重编号）。开放项：若将来确有高频需求，另立「重建集合」助手，而非开放原地切片写。
2. **`insert` / 原地 `sort` / 原地 `reverse`**：不做（同上），用例断言其不存在以防回潜。
3. **`sorted_by` 语义**：映射侧仍返回键列表（存量调用方零影响），新场景用 `sorted_items` / `sorted_keys`；是否废弃 `sorted_by` 待后续评估。
4. **`len()` 的复杂度**：`SHARDED` 形态为 O(段数)（16），非严格 O(1)；本次不改（改为维护计数需在每个写路径加计数，收益不抵风险），仅在清单复杂度列如实标注。
5. **`__add__` 的策略保真**：新增 `_spawn` 后切片读取也保真；若将来新增策略，`_spawn` 为唯一扩展点。
