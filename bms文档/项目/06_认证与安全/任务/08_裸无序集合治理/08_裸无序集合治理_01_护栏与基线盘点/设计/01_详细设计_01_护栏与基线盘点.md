## 1. 设计目标与范围 <a id="goal"></a>

把《[后端开发规范](../../../../../../规范/后端开发规范.md)》「集合与排序」既有禁令——**有序集合对外输出稳定序、禁止裸无序集合**——从「只有文字」落为**可执行、可递减的静态护栏**：新增 AST 检查脚本 `check-bare-collections.py`（检出类字段注解与函数签名注解中的裸无序集合）、以**基线快照**豁免存量（新增即失败）、挂接 `preflight --fast` 与 CI `base-integrity`，产出**存量盘点报告**并补强规范口径。

- **本任务范围**：护栏脚本（含 `--self-test` / `--json` / `--report` / `--update-baseline`）、基线快照（`deploy/boundaries/bare_collections_baseline.json`）、preflight 与 CI 挂接、存量盘点报告、《后端开发规范》「集合与排序」口径补强、《后端基类清单》「集合体系」节登记护栏与基线落点。
- **不在本任务**：**存量整改**（约 556 处，按模块分批另立任务，已登记[计划 §7 后续阶段待办](../../../../计划/01_计划_认证与安全.md#followup)）；集合基座形态新增（有序 / 并发 / 跨副本已交付）；前端 TS 侧集合形态（另有前端规范，不在本轮范围）。
- **接口兼容**：不新增 / 不修改任何运行时代码与能力域；不改插件键、不改基座契约；新增均为**构建期校验资产与文档**，对运行时零影响。
- **安全影响（SDL）**：本任务不直接处理敏感数据；价值在于**阻止「绕过基座集合（顺序不可控 → 分页 / 游标 / 导出结果不稳定）」的实现继续扩散**，并为后续整改提供台账（属「架构机制 + CI 门禁」类落点，不写人工检查表）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 检查器 CLI 与退出码 <a id="cli"></a>

```text
用法：python3 scripts/tools/base-check/check-bare-collections.py [仓库根]
       python3 scripts/tools/base-check/check-bare-collections.py . --json
       python3 scripts/tools/base-check/check-bare-collections.py . --report
       python3 scripts/tools/base-check/check-bare-collections.py . --update-baseline
       python3 scripts/tools/base-check/check-bare-collections.py . --self-test
```

| 参数 | 语义 |
| --- | --- |
| `[仓库根]`（位置参数，缺省 `.`） | 扫描与基线定位根（默认取脚本位置推导的仓库根，与既有脚本同范式） |
| `--report` | **报告模式**：仅统计与清单输出，**恒退出 0**（供盘点使用） |
| `--json` | 机器可读输出（`{"passed", "counts", "problems", "baseline"}`） |
| `--update-baseline` | 以本次扫描结果重写基线快照（**递减**：已修复条目随之移除） |
| `--self-test` | 自测矩阵（临时仓库 fixture，见 §3.5） |

| 退出码 | 条件 |
| --- | --- |
| `0` | 无**新增**违规（基线内命中允许）；或 `--report` |
| `1` | 存在**新增**违规（不在基线内）或**基线漂移**（基线条目与实际不匹配）或脚本自身异常 |

输出风格与既有护栏一致：违规按类目前缀（`[类字段]` / `[签名参数]` / `[签名返回]`），汇总行 `[check-bare-collections] 通过：...` / `[check-bare-collections] 不通过：N 项`。

### 3.2 检测规则 <a id="rules"></a>

| 维度 | 口径（2026-09-28 拍板） |
| --- | --- |
| 扫描范围 | `backend/libs/bms_core/src`、`backend/services/*/src`、`backend/ops`、`scripts/tools` |
| 排除 | 路径含 `/tests/`、文件名以 `test_` 开头、`__pycache__` |
| 检测位置 | 类体 `AnnAssign`（类字段注解）＋ 函数 / 异步函数签名的**参数注解**与**返回注解**；**函数体内局部注解不查** |
| 命中容器 | `dict` / `list` / `set` / `frozenset` 与 `typing` 别名 `Dict` / `List` / `Set` / `FrozenSet` / `DefaultDict` |
| 不命中 | `Sequence` / `Iterable` / `Mapping` / `MutableMapping`（只读 / 有序抽象）；自定义集合类（`SortedList` 等）与基座形态 |
| 注解递归 | `Name` / `Attribute`（`typing.Dict`）/ `Subscript`（`dict[str, int]`）/ `BinOp`（`X \| None`）/ `Tuple` / `List`；**字符串前向引用**按词边界正则识别 |
| 位置分类 | `class_field`（含继承 `BaseObject` 的类，标注 `base_object` 以便优先整改） / `signature_param` / `signature_return` |

### 3.3 基线快照格式 <a id="baseline"></a>

`deploy/boundaries/bare_collections_baseline.json`：

```json
{
  "version": 1,
  "generated_at": "2026-10-08",
  "entries": [
    {
      "file": "backend/libs/bms_core/src/bms_core/events/base.py",
      "line": "    payload: dict[str, object] = field(default_factory=dict)",
      "container": "dict",
      "position": "class_field",
      "count": 1
    }
  ]
}
```

| 字段 | 语义 |
| --- | --- |
| `version` | 快照格式版本（非 1 即拒，fail-fast） |
| `generated_at` | 生成日期（`YYYY-MM-DD`） |
| `entries[].file` | 相对仓库根的 POSIX 路径 |
| `entries[].line` | **规范化行内容**（`strip()` 后原样；**不含行号**，容行漂移） |
| `entries[].container` | 命中容器名 |
| `entries[].position` | `class_field` / `signature_param` / `signature_return` |
| `entries[].count` | 同「文件 + 行内容 + 容器」命中的**允许条数**（同内容重复时聚合，压缩文件体积） |

**比对算法**（多重集差）：

- 实际命中 → `Counter((file, line, container))`；基线 → 同键展开 `count`；
- `新增 = 实际 - 基线`（非空 → **不通过**，逐条报出文件与行内容）；
- `残留 = 基线 - 实际`（非空 → **提示**「基线可递减」，建议跑 `--update-baseline`；**不单独致失败**，避免行内微调即红）；
- `--update-baseline` 以实际命中重写快照（自然完成递减）。

### 3.5 存量盘点报告与自测矩阵 <a id="report"></a>

**盘点报告**（`实施/02_存量盘点报告_01_护栏与基线盘点.md`）内容：① 总量与分布（区域 × 位置 × 容器，含 `base_object` 类字段单列）；② 高频文件 TOP N；③ **分批整改建议**（契约层 `base_object` 类字段优先 → `bms_core` 其余 → `services` → `ops` / `scripts`）；④ 基线快照规模与递减口径说明。

**`--self-test` 矩阵**（临时目录 fixture，代码内标注 Kiwi 用例编号）：

| # | 断言 |
| --- | --- |
| 1 | **命中**：类字段 `x: dict[str, int]`、签名 `def f(a: list[str]) -> set[int]`、`Dict` / `DefaultDict` 别名、`X \| None` 联合、字符串前向引用均被检出 |
| 2 | **不命中**：`Sequence` / `Iterable` / `Mapping` / `SortedList` / 自定义基类集合形态不报 |
| 3 | **位置口径**：函数体内局部注解（`def f(): x: dict = {}`）不报 |
| 4 | **排除口径**：`tests/` 目录与 `test_*.py` 不扫描 |
| 5 | **基线语义**：存量入基线 → 通过；新增一行违规 → 不通过；修复一行 → 提示递减、不失败；`--update-baseline` 后再次通过 |
| 6 | **模式语义**：`--report` 恒退出 0 且输出统计；`--json` 结构合法（`passed` / `counts` / `problems`） |

### 3.6 失败分支与错误语义 <a id="failures"></a>

| 场景 | 行为 |
| --- | --- |
| 仓库根不存在 / 无扫描目标 | 退出 `1`，明确报错（不静默通过） |
| 基线文件缺失 | 视为**空基线**：全部实际命中即「新增」→ 不通过（提示先 `--update-baseline` 建立基线） |
| 基线版本非 `1` / JSON 非法 / 条目字段缺失 | 退出 `1`（fail-fast，不静默忽略） |
| `.py` 语法错误（不可解析） | 记为扫描异常并**退出 1**（与既有基座脚本口径一致） |
| 新增违规 | 逐条报出「文件 + 行内容 + 容器 + 位置」，退出 `1` |
| 基线残留（已修复） | 输出提示行（数量），**不影响退出码** |
| `--update-baseline` 与 `--report` 同时给出 | `--update-baseline` 优先（报告后再写）；语义在 `--help` 与文档中写明 |

## 4. 兼容性与影响 <a id="compat"></a>

- **运行时零影响**：不修改任何后端运行时代码、能力域与契约；不新增插件键（`_EXPECTED_PLUGIN_KEYS` 不变）。
- **CI 影响**：`base-integrity` 增加一次 AST 扫描（秒级），不改变 job 依赖与产物；**本次 CI 配置改动不在同条流水线自验**（等下次命中路径），交付前以本地 `preflight --fast` 与直跑脚本为准。
- **既有护栏不变**：`check-base` / `check-backend-base` / `check-service-boundaries` 逻辑与白名单机制不动；新护栏为**独立第五个基座检查**。
- **开发者体验**：本地新增违规时 `preflight --fast` 立即报出；存量已入基线故不阻塞现有开发；整改存量后需跑 `--update-baseline` 完成递减。
- **后续扩展点**：存量分批整改任务按盘点报告推进；如后续要纳入前端 TS（另一套规范），另立检查器。

## 7. 边界与开放项 <a id="boundary"></a>

- **存量整改**（本任务不含）→ 按模块分批另立任务（计划 §7 第 25 项）。
- **前端 TS 集合形态** → 前端另有《前端开发规范》，不属本检查器（如后续需要，另立检查器）。
- **字符串前向引用识别**为**词边界正则**近似（AST 无法解析字符串注解语义）；如出现误报，先改口径并同步自测用例。
- **函数体内局部注解不查**（口径已定）；如需扩展，先评估噪声。
- **行内容指纹**对「行内微调」会同时产生新增与残留（需跑 `--update-baseline`）；这是「显式递减」的代价，不引入行号绑定（行号更脆）。
- **`scripts/tools/` 不在 CI lint 覆盖范围**：本脚本以 `--self-test` + preflight 保障；如后续要把 `scripts/` 纳入 ruff/pyright，另立任务。
- **Kiwi 用例编号** → 测试实施时登记回填。
