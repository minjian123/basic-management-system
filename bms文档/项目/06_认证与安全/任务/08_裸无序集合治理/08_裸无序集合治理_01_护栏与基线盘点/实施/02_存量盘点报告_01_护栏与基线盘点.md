## 4. 分批整改建议 <a id="batching"></a>

按「契约影响面优先、随模块任务顺带整改（不独立大改）」原则分四批（各批数量为**基线快照条目近似值**，实际以整改时脚本报告为准）：

| 批次 | 范围 | 约数量 | 建议 |
| --- | --- | --- | --- |
| 1 | 直接继承 `BaseObject` 的类字段（对外数据契约 / 值对象） | 8 | **优先**：影响对外契约与序列化，且集中在 `events` / `outbox` / `idp` / `masking` 等基座契约类 |
| 2 | `bms_core` 其余类字段与签名 | ~297 | 随对应基座 / 能力域任务顺带整改（如契约类字段改基座只读抽象） |
| 3 | `services`（identity / org / ai 等） | ~80 | 随各服务后续任务顺带整改；Schema 字段优先 |
| 4 | `backend/ops` 与 `scripts/tools` | ~169 | **最后评估**：`scripts/tools` 多为构建期内部工具（结构不外流），整改收益低于基座；可评估「内部工具豁免」或在低峰期统一处理 |

> **注（2026-09-29 批次口径调整）**：批次 1 的判定口径「直接继承 `BaseObject` 的类字段」经 09 域归位后**实测仅剩 1 处**，已失去独立批次意义；存量整改改按**区域**分三批、**批内先类字段后签名**（承接「契约影响面优先」）。**同日二次拍板**把口径扩为「全覆盖 + 业务只落插入序集合类 + 参数位也落」，并纳入**既有只读 / 可变抽象落点**——批次 1 `bms_core`（`backend/libs`）**596 处**（裸 287 + 抽象 309）、批次 2 `services` **104 处**（裸 79 + 抽象 25）、批次 3 `backend/ops` **75 处**（裸 30 + 抽象 45）与 `scripts/tools` **145 处**（裸 134 + 抽象 11），合计 **920 处**（**2026-09-29 实施修正**：初稿测绘 616/940 未扣除实现文件豁免，见详细设计 §1.1 数字修正）。已立项为子任务 [`08_02`](../../08_裸无序集合治理_02_bms_core存量整改/08_裸无序集合治理_02_bms_core存量整改.md) / [`08_03`](../../08_裸无序集合治理_03_services存量整改/08_裸无序集合治理_03_services存量整改.md) / [`08_04`](../../08_裸无序集合治理_04_ops与脚本存量整改/08_裸无序集合治理_04_ops与脚本存量整改.md)（需求 08-2，2026-09-29）。下表批次划分保留 2026-09-28 建议原貌。

**整改注意事项**：
1. **落点收口（2026-09-29 二次拍板）**：**业务与契约的集合一律落继承 `BaseConcurrentSorted` 的插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`，类字段 / 参数 / 返回位置全覆盖）；**升序形态 `ConcurrentSorted*` 与 `SortedList` / `SortedDict` / `SortedSet` 同为基座内部实现**，业务与契约不得直接声明 / 继承（排序需求走排序契约）；只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）不再作落点（见[需求域 08](../../../../需求/08_需求_裸无序集合治理.md) 已定口径）。
2. **口径收紧的存量纳入**：白名单收紧会把既有抽象落点判为「新增」——批次 1 先 `--update-baseline` 如实吸收现状（**548 → 920**：裸 530 + 抽象 390；已扣除实现文件豁免 20 处），再按批递减（`08_02` → 324、`08_03` → 220、`08_04` → 0）；**不得手工增删基线条目**。
3. **同步基线**：每批完成后跑 `--update-baseline` 递减基线，使护栏持续反映现状（**不得**直接删基线条目绕过）。
4. **与 04_02 的解耦**：04_02（脱敏接入）仅需按本域落定的口径实现（声明与公共纯函数使用基座集合 / 读取面），**不依赖存量整改完成**。

## 5. 基线与递减口径 <a id="baseline"></a>

- 快照路径：`deploy/boundaries/bare_collections_baseline.json`（`version` / `generated_at` / `entries`）。
- 条目形态：`{file, line（规范化行内容指纹，不含行号）, container, position, count}`。
- 判定：**新增即失败**；基线残留（已修复）仅提示「可递减」，由 `--update-baseline` 重写完成递减；基线条目**不得**手工删除绕过。
- **口径收紧的基线吸收（2026-09-29 二次拍板；同日实施）**：护栏白名单收紧（裸容器 + 只读 / 可变抽象 + 升序形态一律违规）后，既有 **390 处抽象落点**对护栏而言属「新增」——按既有机制**先如实吸收**（`--update-baseline`，**548 → 920**；已扣除实现文件豁免，台账不手工增删），再按批次递减（`08_02` → 324、`08_03` → 220、`08_04` → 0）。
