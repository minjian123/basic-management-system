## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段六补充需求域 08 的 5 条需求——[08-1 裸无序集合护栏与存量盘点](../../需求/08_需求_裸无序集合治理.md#r08-1)（1 子任务：`08_01`）、[08-2 裸无序集合存量整改](../../需求/08_需求_裸无序集合治理.md#r08-2)（1 子任务：`08_02`，内含批次 1~4）、[08-3 集合体系收链](../../需求/08_需求_裸无序集合治理.md#r08-3)（1 子任务：`08_03`）、[08-4 集合类通用功能补齐](../../需求/08_需求_裸无序集合治理.md#r08-4)（1 子任务：`08_04`）与 [08-5 元组注解分形态治理与不可变集合形态](../../需求/08_需求_裸无序集合治理.md#r08-5)（1 子任务：`08_05`）。
- **端范围**：**后端**（`bms_core` / `services` / `ops` / `scripts/tools` 的 Python 静态检查、盘点、存量整改与集合体系继承链收口）；不涉及前端。
- **承接口径**：集合基座与《[后端基类清单](../../../../后端基类清单.md)》「集合体系」节已交付；本域以**护栏、盘点、规范口径收口、存量整改与体系收链**为主。
- **集合体系唯一链（2026-09-29 拍板 · 本域口径总纲）**：**所有集合类一律（间接）继承基础集合基类 `BaseCollection`、无任何例外**——根只承载集合通用语义（有序语义 + 稳定序约定 + `collection_kind` 标记），其下按形态分支：`BaseSorted`（非并发有序 · 无锁高效，`Sorted*` 落点）、`BaseConcurrent`（基础并发：锁守卫 + 原子复合操作 + 快照遍历）、`BaseAsyncSorted`（跨副本异步有序：并发由 Lua 原子脚本 + 版本号承载、无同步锁层）、`BaseCacheSnapshot`（通用缓存层，`RedisSnapshot` 归此）；`BaseSorted` / `BaseSyncSorted` / `BaseConcurrentSorted` 等旧名退场。**业务与契约的集合一律落插入序形态 `ConcurrentStable*`**；升序形态 `ConcurrentSorted*` 与 `Sorted*` 为体系内部基础实现，业务与契约不得直接声明 / 继承（排序走排序契约）。
- **已定口径（2026-09-28 拍板 · 护栏与盘点）**：检测形态＝`dict` / `list` / `set` / `frozenset` 及 typing 别名；检测位置＝类字段注解 + 函数签名注解；存量以**基线快照**豁免并递减；首轮不含存量整改（按模块分批另立任务）。
- **已定口径（2026-09-29 拍板 · 存量整改与收链）**：
  1. **存量整改立项**为需求 08-2，按**区域**分四批（批次 1~4，均在 `08_02` 内实施）、批内先类字段后签名、逐批递减基线至归零。
  2. **集合落地形态**：`SortedList` / `SortedDict` / `SortedSet` 与 `ConcurrentSorted*` 为**体系内部基础实现**（业务与契约不得直接声明 / 继承）；业务与契约一律落**插入序形态** `ConcurrentStable*`；列表排序一律走排序契约；无合适形态时先新增继承 `BaseCollection` 的形态并回写规范与清单，不得链外自造。
  3. **护栏口径**（2026-09-29 二次拍板收紧，本域按「无例外」落定）：白名单**只含插入序形态**——裸容器、只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）、升序形态（`Sorted*` / `ConcurrentSorted*`）一律判违规；**取消全部豁免**——`ClassVar` 类级常量、`BaseSettings` 配置字段、测试目录（扩扫描目标至 `*/tests`）与函数体带注解局部变量**一律纳入**；仅保留「迭代 / 调用协议（`Iterable` / `Iterator` / `Callable`）不查」（非集合声明）；集合体系**实现文件**（`core/collections.py` / `core/concurrent.py` / `core/redis_collections.py`）为**不属约束对象**（护栏只约束业务侧集合声明，实现文件是体系自身、其内置容器为内部底座与序列化出口）。
  4. **基线递减**：`--update-baseline` 重写快照，**不得手工增删基线条目**；口径扩面后先如实吸收（918 → **1711**，2026-09-30 实测），再按批递减。
  5. **`scripts/tools` 长期口径专项**（随批次 3）＝评估构建期内部工具是否纳入长期强制口径，结论回写规范与清单。
  6. **集合体系收链立项**为需求 08-3：跨副本形态 `RedisSortedSet` / `RedisSortedDict` 回归集合链（挂 `BaseAsyncSorted`）；`RedisSnapshot` 由框架对象体系**改挂通用缓存层 `BaseCacheSnapshot`**（不再有链外例外）。
- **已定口径（2026-10-20 拍板 · 元组分形态与不可变形态）**：
  1. **tuple 分形态**：**同构** `tuple[X, ...]` 视为集合声明、纳入白名单治理（落 `ConcurrentStableList`）；**固定元数** `tuple[A, B]` 视为「多返回值 / 元组值」**显式豁免**（Pydantic 契约形态为 `prefixItems` + `minItems` / `maxItems`，改 `list` 会漂移）。
  2. **护栏改真白名单**：`WHITELIST_FORMS` 参与判定（现为死常量），**未命中白名单即违规**——堵住 `tuple` / `deque` / `Counter` / `OrderedDict` 等同类漏网。
  3. **新增不可变层 `BaseImmutable`**（承 `BaseConcurrent`）与三形态 `ConcurrentStableFrozenList` / `FrozenSet` / `FrozenDict`；**不可变形态仍需并发基座**——构造期即写路径（`__init__` 末行 `self.update(items)` 持分段写锁与序号锁）；**构造期直接写、构造后恒冻结**，不复用 `freeze()`（其实质是完整重构造）。
  4. **哈希分工**：可变形态 `ConcurrentStable*` 改 `__hash__ = None`（与内置 `list` / `dict` / `set` 对齐）；**内容哈希只给不可变形态**（与 `eq` 语义对齐：列表按序、集合与映射用 `frozenset`，哈希值缓存）。**可变形态做内容哈希会破坏 dict / set 语义**（内容变化后 hash 改变，元素「凭空消失」）。
  5. **值对象字段归位**：**16 处** `BaseValueObject` 字段改落不可变形态（frozen dataclass 生成的 `__hash__` 依赖字段可哈希；现用可变集合类导致 `eq` 相等而 `len({a, b}) == 2`）。
  6. **派生运算**：不可变形态的 `|` / `union` / `difference` / `symmetric_difference` 改为「先算可变临时实例、最后一次冻结」（现实现 `copy()` 后 `update()` 会撞冻结，实测三处失败）。
  7. **存量整改**：**524 处同构元组**按区域分四批递减（`libs` 源侧 294 → `services` 51 + `ops` 31 → `scripts/tools` 83 → `libs` 测试 65）。
- **依据**：《[后端开发规范](../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[后端基类清单](../../../../后端基类清单.md)》「集合体系」节、《[测试规范](../../../../规范/测试规范.md)》。
- **执行序**：`08_01 护栏与基线盘点`（已交付）→ `08_02 存量整改`（批次 1 `bms_core` **1036 处** + 集合体系唯一链收口 + 护栏口径收紧与基线吸收；批次 2 `services` **348 处**；批次 3 `ops` 与 `scripts/tools` **327 处**，收口至基线归零）→ `08_03 集合体系收链`（跨副本形态回链，已交付）→ `08_04 集合类通用功能补齐`（已交付）→ `08_05 元组注解分形态治理与不可变集合形态`（护栏改真白名单 + `BaseImmutable` 与三形态 + 哈希不变量修正 + 524 处同构元组整改）；`08_01` 成果为 [04_02 脱敏接入与明文权限口径](../04_数据脱敏与安全加固/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径.md) 的**前置**（见[计划](../../计划/01_计划_认证与安全.md)）。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：本域**无前置**；`08_01` 成果作为 [04_02 脱敏接入与明文权限口径](../04_数据脱敏与安全加固/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径.md) 的**前置**（本域口径先行落定，04_02 的实现与测试据此对齐）；存量整改 `08_02` 依赖 `08_01`（护栏与基线，已交付；批次 1~4 逐批递减基线）；`08_03` 已交付（跨副本形态回链优先于存量整改收口，避免同一批文件二次回归）；`08_04` 依赖 `08_02` / `08_03`（在插入序形态与唯一链落定后补通用功能面，避免同一批文件二次回归）；`08_05` 依赖 `08_02` / `08_03` / `08_04`（白名单判定与不可变形态建立在插入序形态与通用功能面之上）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_认证与安全.md)。
- **风险**：
  - 护栏为**插入序白名单 + 无例外**判定（裸容器 / 只读可变抽象 / 升序形态 / 类级常量 / 配置字段 / 测试目录 / 函数体局部变量均纳入；集合体系实现文件为不属约束对象；迭代 / 调用协议不查）；新增集合形态后须同步脚本白名单与《后端基类清单》（清单零漂移核对把关）。
  - 基线快照与现状漂移 → 口径收紧先如实吸收（918 → **1711**），每批复跑「新增 0 / 残留 0」并 `--update-baseline` 递减（**不得手工增删条目**）。
  - 存量整改改动面 **1711 处**（`libs` 1036 / `services` 348 / `scripts/tools` 224 / `ops` 103，2026-09-30 实测），落点为插入序集合类（参数位也落，运行期加锁与插入序为预期行为），契约字段另需 Pydantic 契约元数据与 `model_dump()` 形态适配，易引入行为偏差 → 基座能力先行落地并过用例、批内先类字段后签名、逐批定向回归。
  - **收链触及集合体系公共段**（`BaseCollection` 为 7 个体系根之一）→ 已由 `08_02` 交付（唯一链收口）；`check-backend-base.py` 体系根白名单、`direct_base_object_baseline.json`、继承链对账与后续任务文档均随之回写。
  - **`08_05` 哈希语义变更面**（可变形态改不可哈希）→ 已实测全扫描面无集合类实例作 set 元素 / dict 键 / `frozenset` 成员的用法、无值对象 `hash()` 依赖（1244 文件 AST 扫描，命中 0）；回归面为「既有用例中依赖集合类可哈希的断言」，逐批定向回归把关。
  - **`08_05` 契约漂移面**：同构元组改 `ConcurrentStableList` 时 Pydantic schema 与 `list[X]` 逐字节一致（均为 `array`），契约零漂移；**固定元数豁免**正是为避免 `prefixItems` + `minItems` / `maxItems` 形态漂移。
