## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段六补充需求域 08 的 3 条需求——[08-1 裸无序集合护栏与存量盘点](../../需求/08_需求_裸无序集合治理.md#r08-1)（1 子任务：`08_01`）、[08-2 裸无序集合存量整改](../../需求/08_需求_裸无序集合治理.md#r08-2)（按区域分 3 子任务：`08_02`~`08_04`）与 [08-3 集合体系收链](../../需求/08_需求_裸无序集合治理.md#r08-3)（1 子任务：`08_05`）。
- **端范围**：**后端**（`bms_core` / `services` / `ops` / `scripts/tools` 的 Python 静态检查、盘点、存量整改与集合体系继承链收链）；不涉及前端。
- **承接口径**：集合基座（有序 / 进程内并发 / 跨副本三类形态）与《[后端基类清单](../../../../后端基类清单.md)》「集合体系」节已交付；本域以**护栏、盘点、规范口径收口、存量整改与体系收链**为主；**存量整改口径扩为「全覆盖继承并发有序基类（`BaseConcurrentSorted`）的集合类」后，基座缺口（并发集合只读 API / 插入序形态 `ConcurrentStable*` / Pydantic 契约元数据 `CONTRACT_COLLECTION`）随 `08_02` 一并补齐**（2026-09-29 二次拍板），`08_01` 只交付护栏与台账，`08_05` 只调整继承链与公共段分层。
- **已定口径**（2026-09-28 拍板）：检测形态＝`dict` / `list` / `set` / `frozenset` 及 typing 别名（**不查** `Mapping` / `Iterable` / `Sequence`）；检测位置＝类字段注解 + 函数签名注解（函数体内局部变量不查）；存量以**基线快照**豁免并递减；首轮不含存量整改（按模块分批另立任务）。
- **已定口径（2026-09-29 拍板）**：**存量整改立项**为需求 08-2，按**区域**分三批（`bms_core` 305 / `services` 79 / `ops` 与 `scripts/tools` 164，合计 **548** 处，2026-09-29 实测）**一批一子任务**、批内**先类字段后签名**、逐批递减基线至归零；盘点报告原「批次 1＝直继承 `BaseObject` 的类字段」经 09 域归位后实测仅剩 1 处，已失去独立批次意义，改按区域划分；随批次 3 评估 `scripts/tools` 是否纳入长期强制口径。
- **已定口径（2026-09-29 拍板 · 收链）**：**集合体系收链**立项为需求 [08-3](../../需求/08_需求_裸无序集合治理.md
- **已定口径（2026-09-29 拍板 · 集合落地形态；同日二次拍板收敛到插入序）**：`SortedList` / `SortedDict` / `SortedSet` 与 `ConcurrentSorted*` 为**基座内部基础实现**，**业务与契约不得直接声明 / 继承**；**业务与契约的集合一律落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`；无合适形态先新增继承 `BaseConcurrentSorted` 的形态并回写规范与清单，不得链外自造）；**列表排序一律走排序契约**，不用集合结构排序；只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）不再作落点；`Sorted*` 的子类一律改继承对应 `ConcurrentSorted*`（当前无此类子类，规则面向新增）；跨副本 `RedisSortedSet` / `RedisSortedDict` 保持异步链。**二次拍板**：批次 1 起**全覆盖**（含既有抽象落点与 Pydantic 契约 / 配置字段、参数位）；基座新增（只读 API / `ConcurrentStable*`（**分段写 + 插入序号归并**）/ `CONTRACT_COLLECTION`）**并入 `08_02`**；护栏收紧为**插入序白名单**（裸容器 / 抽象 / 升序形态均违规，实现文件豁免）；验收基准为「**形态一致 + 逐处登记**」；基线先由 548 吸收至 918 再逐批递减；域 08 工作量 ****、顺延至 **2026-12-04**（见计划）。
- **依据**：《[后端开发规范](../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[后端基类清单](../../../../后端基类清单.md)》「集合体系」节。
- **执行序**：`08_01 护栏与基线盘点`（已交付）→ `08_02 bms_core 存量整改` → `08_03 services 存量整改` → `08_04 ops 与 scripts/tools 存量整改`（收口至基线归零）→ `08_05 集合体系收链`（跨副本形态回链）；`08_01` 成果为 [04_02 脱敏接入与明文权限口径](../04_数据脱敏与安全加固/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径.md) 的**前置**（见[计划](../../计划/01_计划_认证与安全.md)）。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：本域**无前置**；`08_01` 成果作为 [04_02 脱敏接入与明文权限口径](../04_数据脱敏与安全加固/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径/04_数据脱敏与安全加固_02_脱敏接入与明文权限口径.md) 的**前置**（本域口径先行落定，04_02 的实现与测试据此对齐）；存量整改 `08_02` 依赖 `08_01`（护栏与基线，已交付），`08_03` 依赖 `08_02`，`08_04` 依赖 `08_03`（批次逐批递减基线）；`08_05` 依赖 `08_04`（存量整改收口后再动继承链，避免同一批文件二次回归）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_认证与安全.md)。
- **风险**：护栏为**插入序白名单**判定（裸容器 / 只读可变抽象 / 升序形态均违规，集合体系实现文件豁免，迭代 / 调用协议不查），新增集合形态后须同步脚本白名单与《后端基类清单》（清单零漂移核对把关）；基线快照与现状漂移 → 白名单收紧先如实吸收现状（548 → 918），每批复跑「新增 0 / 残留 0」并 `--update-baseline` 递减（**不得手工增删条目**）；存量整改改动面 **918 处**（裸 528 + 抽象 390）、落点由「只读抽象」整体改为**插入序集合类**且**参数位也落**（运行期加锁与插入序为预期变化），契约字段另需 Pydantic 契约元数据与 `model_dump()` 形态适配，易引入行为偏差 → 基座能力新增先行落地并过用例、批内先类字段后签名、逐批定向回归；**收链触及集合体系公共段**（`BaseSorted` 为 7 个体系根之一且承载同步抽象）→ 已由 `08_05` 交付，本域后续只复用。
