## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 首次全量回归暴露 `core/concurrent.py` 覆盖率 99.23%（缺 6 行 / 3 分支） | 缺口全部来自新增不可变形态的 `_spawn` / `_mutable_spawn` 两策略分支与 `freeze()` 返回自身；补 5 个用例后行 + 分支均 100% |
| 2 | `Boundary` 用例一度因新文件引入裸 `tuple` 注解而失败（护栏自检互相约束） | 用例内部把 `args: tuple[str, ...]` 改为 `ConcurrentStableList[str]`，护栏恢复通过 |
| 3 | 守卫用例首次运行把 pytest 进程自身杀掉（`os._exit` 被测试直接触发） | 钩子拆为 `check()`（抛 `SystemExit`，供单测）+ `boot()`（硬退出），用例改测 `check()` |
| 4 | 守卫误拦窄目录 pyright（原判定「非 `.py` 路径即重命令」） | 判定改为「无参数」或「指向仓库级目录（`libs` / `services` / `scripts` / `deploy` / `frontend` / `.`）」才拦；pytest 侧改为按目录下测试文件数是否超 20 判定 |

## 6. 偏差与遗留 <a id="deviations"></a>

| # | 偏差 / 遗留 | 说明 |
| --- | --- | --- |
| 1 | 用例数量以实测为准 | 设计阶段预估的用例数未逐条锁定，实施后按覆盖缺口补齐至行 + 分支 100% |
| 2 | 守卫负向用例以「实测 + 单测」双口径留痕 | 端到端拦截行为无法在 pytest 内自证（会杀进程），故拆为 `check()` 单测 + §3.5 手工实测记录 |
| 3 | `ruff` 全仓调用无法被守卫拦截 | 原生二进制无 Python 注入点；已在规范与实施记录明写，靠纪律 + 预检兜底 |
| 4 | 基座模块改动时选测退化工程级全量 | `picked=430/430 degraded=true`；属正确行为（影响面超阈值），非缺陷 |
| 5 | **既有测试隔离缺陷（非本任务引入，未修复）**：`services/platform/tests/api/test_my_menu.py` 末 3 个用例在 xdist 全量并发下偶发失败——首步 `GET /api/v1/businesses` / `POST /api/v1/menus` 返回 `data=None`（错误响应），**单独跑该文件必过** | 出现频次：5 次全量 / 预检中 **1 次**。已排除项：①单跑该文件通过；②`bms_core + platform` 两测试根同 worker 并行通过（2743 passed）；③无 `perms` 缓存串味（`bms_isolate_settings` 已 autouse 重置）；④`service_app` / `client` 为函数级、`platform_db` 与 `permission_db_url` 为会话级，作用域未见错配。**已落地确定性改进**：把 `response.json()["data"]["id"]` 改为 `_data_or_fail(response, 标���)`，失败时断言信息带**完整响应体与状态码**（原写法只报 `TypeError: NoneType`，把真实错误码吞掉），下次复现即可直接定位成因。**遗留处置建议**：登记到 [13 测试执行粒度与工程效能](../../../../../02_后端基座与服务化地基/任务/13_测试执行粒度与工程效能/13_测试执行粒度与工程效能.md) 域，以「同选测连跑 N 次 + `--dist` 显式档」取证后修隔离，不在本任务范围内盲改 |
