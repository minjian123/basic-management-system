## 1. 域说明 <a id="intro"></a>

本域收口《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」既有禁令——**有序集合对外输出稳定序、禁止裸无序集合**——的**护栏缺位**：该禁令成文已久，但仅有文字约束、无强制校验，后端 Python 侧存量裸 `dict` / `list` / `set` / `frozenset`（类字段注解与函数签名注解）审计时为 554 处、**2026-09-29 实测 548 处**，新代码持续新增、存量无法收敛。

- **本域范围**：裸无序集合**静态护栏**（AST 检查脚本 + 基线快照 + preflight / CI 挂接）、**存量盘点报告**、**规范口径补强**、**存量分批整改**（逐批递减基线至归零）、**集合体系收链**（集合体系收敛为唯一继承链）、**集合类通用功能补齐**（写糖 / 通用方法 / 输出可读性）、**元组注解分形态治理与不可变集合形态**（补充需求 08-5）。
- **不重复建设**：集合基座（**唯一链**：基础集合基类 `BaseCollection` → 非并发有序 `BaseSorted` / 基础并发 `BaseConcurrent` / 跨副本异步有序 `BaseAsyncSorted` / 通用缓存层 `BaseCacheSnapshot`）与《[后端基类清单](../../../后端基类清单.md)》「集合体系」节均已交付；本域只做**护栏、盘点、口径收口、存量整改与体系收链**（收链只调整继承链与公共段归属，不新增集合形态本身）。
- **已定口径**（2026-09-28 拍板）：
  1. **检测形态**＝内建可变 / 无序容器（`dict` / `list` / `set` / `frozenset` 及 `typing` 别名 `Dict` / `List` / `Set` / `FrozenSet` / `DefaultDict`）。**（2026-09-29 二次拍板收紧：改为「插入序白名单」——裸容器、只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）与升序形态（`Sorted*` / `ConcurrentSorted*`）一并判违规，见口径 8）**
  2. **检测位置**＝类字段注解（含 dataclass / Pydantic / 基座派生）＋ 函数签名注解（参数与返回）。**（2026-09-29 二次拍板扩展：函数体带注解局部变量与测试目录一并纳入，见口径 8）**
  3. **存量豁免**＝**基线快照**（文件 + 规范化行内容指纹，落 `deploy/boundaries/`）；新增即失败、修复后同步更新（可审计递减），与既有 `data_ownership_exceptions.json` 同源机制。
  4. **本轮交付**＝护栏 + 基线 + 盘点报告 + 规范口径补强；**存量整改按区域分批另立任务**（不宜一把梭）。
- **已定口径（2026-09-29 拍板）**：
  1. **存量整改立项**＝补充需求 [08-2 裸无序集合存量整改](#r08-2)（本域第二个需求），在 `08_02` 内按**区域**分四批（批次 1~4）逐批推进，**目标基线归零**。
  2. **整改口径**＝**全覆盖落继承集合体系唯根 `BaseCollection` 的集合类，业务与契约只落插入序形态**（`ConcurrentStable*`）；**升序形态（`ConcurrentSorted*`）与 `SortedList` / `SortedDict` / `SortedSet` 同为体系内部基础实现**，业务与契约不得直接声明 / 继承（见口径 7）。**（2026-09-29 二次拍板取代「改声明不改行为 + 只读抽象」口径，并收敛「业务只落插入序」，见口径 8）**

  7. **集合落地形态**（2026-09-29 拍板；**同日二次拍板收敛**）：`SortedList` / `SortedDict` / `SortedSet` 与 `ConcurrentSorted*` 定位为**体系内部基础实现**（仅由体系内部组合使用），**业务代码与对外数据契约不得直接声明、不得继承**；**业务与契约的集合一律落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`；**无合适形态时先新增继承 `BaseCollection` 的形态并回写规范与清单，不得链外自造**）；**列表排序一律走排序契约**（请求侧统一排序参数 + 仓储可排序字段白名单），**不用集合结构排序**；**只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）不再作落点**；**凡以 `Sorted*` 为基的子类一律改为继承对应 `ConcurrentSorted*`**（全仓当前无此类子类，本条为面向新增的强制规则）；跨副本异步形态 `RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`——其并发语义由 Lua 原子脚本 + `WATCH` / `MULTI` 乐观重试 + 版本号承载，且异步接口无法继承同步并发类。**落点**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、本需求 08-2 整改落点与 `08_02` 任务文档。
  8. **集合体系唯一链与护栏口径无例外**（2026-09-29 二次拍板）：**所有集合类一律（间接）继承基础集合基类 `BaseCollection`、无任何例外**——根只承载集合通用语义（有序语义 + 稳定序约定 + `collection_kind` 标记），其下按形态分支：非并发有序 `BaseSorted`（无锁高效，`Sorted*` 落点）、基础并发 `BaseConcurrent`（锁守卫 + 原子复合操作 + 快照遍历）、跨副本异步有序 `BaseAsyncSorted`（Lua + 版本号，无同步锁层、无同步读入口）、通用缓存层 `BaseCacheSnapshot`（`RedisSnapshot` 归此）；`BaseSorted`（旧语义根）/ `BaseSyncSorted` / `BaseConcurrentSorted` 等旧名退场。**护栏取消全部豁免**——白名单只含插入序形态；裸容器、只读 / 可变抽象、升序形态、`ClassVar` 类级常量、`BaseSettings` 配置字段、**测试目录**（扩扫描目标至 `*/tests`）与**函数体带注解局部变量**一律纳入；仅保留「迭代 / 调用协议（`Iterable` / `Iterator` / `Callable`）不查」；集合体系**实现文件为不属约束对象**（护栏只约束业务侧集合声明——对外数据契约、值对象与模块类；实现文件是体系自身、其内置容器为内部底座与序列化出口）。**位置全覆盖**（类字段 / 签名参数 / 签名返回 / 局部变量）；新增基座能力并入 `08_02`——① 并发集合**只读 API**（`Sequence` / `Mapping` / `Set` 只读面，含与内置容器内容相等；写入仍走显式原子方法）；② **插入序形态** `ConcurrentStable*`（`collection_kind="stable"`；**分段写 + 插入序号归并**支持高并发写）；③ **Pydantic 契约元数据** `CONTRACT_COLLECTION` + 插入序空集合工厂常量（落 `schemas/base.py`，`core` 不引入 Pydantic；契约 JSON Schema 与前端类型零漂移为门禁）；④ **护栏收紧 + 豁免取消**并如实吸收基线。**验收基准**为「**形态一致 + 逐处登记**」——加锁与插入序为预期行为；契约字段 `model_dump()` 输出集合类实例、`model_dump_json()` 输出 `array` / `object`。**基线口径**：收紧后先如实吸收现状（918 → **1711**，2026-09-30 实测），按批递减至归零。
  9. **整改范围与推进**（2026-09-29 二次拍板）：`08_02` 起全覆盖（批次 1~4，域 08 一体推进）；进度见[本阶段计划](../计划/01_计划_认证与安全.md)。
  10. **集合类通用功能补齐**（2026-10-20 逐项拍板，12 项）：立项为需求 [08-4](#r08-4)、任务 `08_04`——① 输出可读性：`__str__` / `__repr__` 统一为「类名 + 内置字面量 + 超长截断」；② 跨副本形态 `repr` 改描述式、**永不抛错**（现打印即抛 `NotImplementedError`）；③ 列表补写糖 `append` / `extend` / `+=` / `+`、按索引写删 `pop(index)` / `l[i]=v` / `del l[i]`，**不提供 `insert`**（全表重编号持全局写锁，阻塞所有写）；④ 列表排序**不提供原地 `sort` / `reverse`**，新增 `sorted(key=, reverse=)` 返回同类新实例；⑤ 字典补 `d[k]=v` / `del d[k]` / `clear` / `pop` / `popitem` / `setdefault` / `fromkeys` / `update(映射 | kwargs)` / `|`；⑥ 集补 `remove` / `pop` / `copy` / 四个命名集合运算及 `*_update`；⑦ 字典补 `sorted_items` / `sorted_keys`；⑧ 同一套写法**同步落升序形态** `ConcurrentSorted*`；⑨ 口径回写为「**写糖一律等价于对应原子方法、不新增写路径**」；⑩ 每个新增方法标注复杂度并落「禁用 / 慎用场景」表。**性能红线**：不得为对齐内置容器写法而引入新的锁、全表重编号或额外快照拷贝。
  11. **元组注解分形态治理与不可变集合形态**（2026-10-20 逐项拍板）：立项为需求 [08-5](#r08-5)、任务 `08_05`——① **tuple 分形态处置**：同构 `tuple[X, ...]` 视为集合、纳入白名单治理（落 `ConcurrentStableList`）；固定元数 `tuple[A, B]` 视为「多返回值 / 元组值」**显式豁免**（Pydantic 的 `prefixItems` + `minItems` / `maxItems` 契约形态不可替代）；② **护栏改真白名单**：`WHITELIST_FORMS` 参与判定（现为死常量），未命中白名单即违规，堵住 tuple / `deque` / `Counter` / `OrderedDict` 等同类漏网；③ **新增不可变集合形态** `ConcurrentStableFrozenList` / `FrozenSet` / `FrozenDict`，挂**新增独立层 `BaseImmutable`**（位于 `BaseConcurrent` 之下——**构造期即写路径**，实测 `__init__` 末行 `self.update(items)` 持分段写锁与全局序号锁，故不可变形态仍需并发基座）；构造期直接写、构造后恒冻结（**不复用 `freeze()`**，其实质是完整重构造）；④ **哈希不变量修正**：可变形态 `ConcurrentStable*` 改 `__hash__ = None`（与内置 `list` / `dict` / `set` 对齐），**内容哈希只给不可变形态**（可变形态做内容哈希会破坏 dict / set 语义：放入容器后内容变化则 hash 改变、元素「凭空消失」）；⑤ **16 处值对象字段改落不可变形态**（`BaseValueObject` 为 frozen dataclass，其生成 `__hash__` 依赖字段可哈希；现用可变集合类导致 `eq` 相等而 `len({a, b}) == 2`）；⑥ 存量 **524 处同构元组**按区域分四批递减基线。
- **依据**：《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[后端基类清单](../../../后端基类清单.md)》「集合体系」与「扩展与演进」节、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「红线与纪律」节。

## 2. 需求 08-1：裸无序集合护栏与存量盘点 <a id="r08-1"></a>

优先级：3（中）

**背景与动机**：「禁止裸无序集合」是《后端开发规范》的**强制禁令**，但当前只有文字约束——`check-base.py`（目录 / 基座清单）、`check-backend-base.py`（继承链 / 错误码段位）、`check-service-boundaries.py`（数据所有权）等基座护栏均不覆盖该口径，导致：① 存量裸无序集合无台账、无法收敛；② 新代码继续新增，评审靠人眼；③ 集合基座形同「可选建议」。**能自动化的不靠人工**——本需求把该禁令变成可执行、可递减的护栏。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[AI开发规范](../../../规范/AI开发规范.md)》「执行护栏」）：

1. **静态护栏**：新增基座校验脚本 `check-bare-collections.py`（`scripts/tools/base-check/`），以 AST 解析后端 Python（`bms_core` / `services` / `ops` / `scripts/tools`，含 `tests`），按「类字段注解 + 函数签名注解 + 函数体带注解局部变量」检出裸无序集合；支持**文本清单**与**机器可读（JSON）**两种输出、**基线比对**与**报告模式**（仅统计不改退出码）。
2. **基线快照**：现存违规以「文件 + 规范化行内容指纹」入基线快照（落 `deploy/boundaries/`），**新增违规即失败**；修复后同步更新快照，基线条目可审计递减（防回潜）。
3. **挂接**：纳入 `scripts/tools/preflight/check-preflight.py --fast`（基座与边界段）与 CI（静态 / 基座校验域），与既有基座护栏同机制、可单独运行。
4. **存量盘点报告**：按「区域（`bms_core` / `services` / `ops` / `scripts/tools`）× 位置（类字段 / 签名参数 / 签名返回 / 局部变量）× 容器形态」统计存量，给出**分批整改建议**（按区域归属与契约层优先度）。
5. **规范口径补强**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」明确「对外数据契约、值对象与模块类的集合字段与签名**一律使用继承基础集合基类 `BaseCollection` 的集合类，业务面只落插入序形态**（`ConcurrentStable*`）；升序形态与 `Sorted*` 同为体系内部基础实现；**禁止裸无序集合与只读 / 可变抽象落点**；**集合体系为唯一链、所有集合类一律继承 `BaseCollection`、无任何例外**」，并指向护栏脚本与基线快照（白名单与豁免口径随 `08_02` 收紧 / 取消，2026-09-29）。
6. **存量整改分批**：按区域分批，在 `08_02` 内实施（本轮只登记待办，不在本条需求内整改）。

**完成标准**：护栏脚本可用（基线比对 + 报告模式 + JSON 输出）；**新增违规能被拦截**（自测用例证明）；基线快照与现状一致（生成后复校零漂移）；盘点报告落文档（含分批建议）；规范口径补强完成；preflight 与 CI 挂接生效；`pytest`、`pyright`、`ruff` 通过。

**参考文档**：《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「红线与纪律」节

## 3. 需求 08-2：裸无序集合存量整改（分批递减至基线归零） <a id="r08-2"></a>

优先级：3（中）

**背景与动机**：08-1 已把「禁止裸无序集合」落为**可执行护栏 + 基线快照**（生成时 554 处入基线豁免；截至 2026-09-29 实测 548 处），但基线只**防新增**、不**收敛存量**——存量裸 `dict` / `list` 仍在对外数据契约、值对象与模块类的字段与签名上承担序列化输出，顺序不确定与后续脱敏接入面持续存在；集合基座与只读抽象因而仍形同「可选建议」。若不做存量整改，护栏只是把问题冻结在当下水位，规范口径落不到既有代码。

**内容**（盘点报告 §4「分批整改建议」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」）：

## 4. 需求 08-3：集合体系收链（跨副本形态回链） <a id="r08-3"></a>

优先级：3（中）

**背景与动机**：《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」按共享范围自小到大**逐层演进**（有序 → 进程内并发 → 跨副本），§4「扩展与演进」示例一也把三层画成**一条加层链**；架构铁律要求「能力即继承链上的层」「禁止在链外自由挂接功能」。但实测第三层 `RedisSortedSet` / `RedisSortedDict` / `RedisSnapshot`（`bms_core/core/redis_collections.py`）曾挂 `BaseFrameworkObject`（**集合链外**）。根因：集合体系根曾承载**同步**公共段（抽象 `to_list()` / `__iter__`），而跨副本形态的公共方法全为 `async`，无法满足同步契约。结果是「集合体系三层」名存实亡——第三层既不在链上、也不受集合体系语义约束。

**内容**（《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」与「扩展与演进」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节）：

1. **唯一链收口**：集合体系收敛为**唯一继承链**——基础集合基类 `BaseCollection` 为**集合体系唯根**，其下按形态分支 `BaseSorted`（非并发有序）/ `BaseConcurrent`（基础并发）/ `BaseAsyncSorted`（跨副本）/ `BaseCacheSnapshot`（通用缓存）；**所有集合类一律（间接）继承 `BaseCollection`、无任何例外**。
2. **跨副本形态回链**：`RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`（承 `BaseSorted`，**无同步读入口**——并发由 Lua + 版本号承载）；`RedisSnapshot` 为非有序集合，经**通用缓存层 `BaseCacheSnapshot`** 入链（不再有链外例外）。
3. **登记与口径回写**：修正《[后端基类清单](../../../后端基类清单.md)》§1 层级图与表、§4 表与「扩展与演进」示例、§10 体系根清单（`BaseCollection`）与继承链登记。
4. **护栏**：`check-backend-base.py` 的继承链对账与体系根白名单覆盖新根与新层（`BaseCollection`）；`check-bare-collections.py` 白名单与「不属约束对象」口径同步。
5. **测试**：先登记 Kiwi TCMS 用例取号、后写自动化——断言所有集合类（含 `Sorted*` / `Concurrent*` / `Redis*` / `RedisSnapshot`）均（间接）继承 `BaseCollection`、跨副本形态无同步读入口、清单 §1/§4/§10 与代码零漂移；受影响定向回归（集合类 + Redis 集合用例）与门禁全绿。

**完成标准**：集合体系为**一条继承链**（所有集合类均继承 `BaseCollection`；`RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`；`RedisSnapshot` 挂 `BaseCacheSnapshot`）；《[后端基类清单](../../../后端基类清单.md)》§1 / §4 / §10 与代码**零漂移**；`check-backend-base.py` 继承链对账与体系语义检查通过（含 `--self-test`）；同步侧**行为零变更**（既有集合用例全绿）；定向 `pytest`、`ruff`、`pyright`、基座校验与 `preflight --fast` 全绿。

**参考文档**：《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」/「扩展与演进」、§10；《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节；《[架构设计 · 后端基础类体系](../../../设计/架构设计/04_架构设计_后端基础类体系.md)》；[08-1 裸无序集合护栏与存量盘点](#r08-1)

## 5. 需求 08-4：集合类通用功能补齐（写糖 / 通用方法 / 输出可读性） <a id="r08-4"></a>

优先级：3（中）

**背景与动机**：集合体系落定后，业务与契约的集合一律改用 `ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`，但三者只提供**显式原子方法**（`add` / `set` / `discard` / `delete` 等），与内置 `list` / `set` / `dict` 的日常写法差一截——`append` / `extend` / `d[k]=v` / `del d[k]` / `clear` / `pop` / `setdefault` 全都没有。结果是每处改动都要改写调用写法，`08_02` 实施记录里「`append` → `add`、`extend` → `update`、`x[k] = v` → `set`、`pop(k, None)` → `get_and_remove`」的适配条目反复出现，人工改法成本高且易漏；同时输出可读性有实际缺陷：`repr(ConcurrentStableDict({"a": 1}))` 输出 `ConcurrentStableDict([('a', 1)])`（dict 显示成键值对列表），`repr(RedisSortedSet)` **直接抛 `NotImplementedError`**（日志、调试器、异常栈一打印就崩）；`ConcurrentStableDict.update({"b": 2})` 传映射会抛 `ValueError: not enough values to unpack`。不做的话，集合类始终是「能落型但不能顺手用」的形态，业务侧会持续以适配改写的方式绕行，且线上排障时打印集合仍有崩溃面。

**内容**（《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」；12 项口径 2026-10-20 逐项拍板，详见 §1 已定口径 10）：

1. **输出可读性**：`__str__` / `__repr__` 统一为「类名 + 内置字面量」（列表 `[..]`、集合 `[..]`、字典 `{..}`），**超长截断**（默认 10 项，超出以「共 N 项」提示）；跨副本形态（`RedisSortedSet` / `RedisSortedDict`）改**描述式 `repr`**（含键名，不读远端），**永不抛错**。
2. **列表写糖与按索引写删**：`append`（= `add`）、`extend`（= `update`）、`+=`、`+`（返回同类新实例）、`pop(index)`、`l[i] = v`、`del l[i]`；**不提供 `insert`**（须全表重编号并持全局写锁，会阻塞所有写，改用重建集合）。
3. **列表排序**：**不提供原地 `sort` / `reverse`**（同样需全表重编号并破坏插入序语义），新增 `sorted(key=, reverse=)` 返回**同类新实例**。
4. **字典通用功能**：`d[k] = v`（= `set`）、`del d[k]`（= `delete`）、`clear`、`pop(key[, default])`、`popitem()`、`setdefault(key, default)`、`fromkeys`、`update(映射 | 键值对 | kwargs)`、`|` / `|=`；`update` 传映射**不得再抛 `ValueError`**。
5. **集合通用功能**：`remove(x)`（缺失抛 `KeyError`）、`pop()`、`copy()`、`union` / `intersection` / `difference` / `symmetric_difference` 及四个 `*_update`。
6. **字典排序辅助**：`sorted_items(key=, reverse=)`、`sorted_keys(reverse=)`。
7. **形态一致**：同一套写法**同步落升序形态** `ConcurrentSorted*`，两形态 API 不分叉。
8. **性能红线**：所有写糖**一律等价于对应原子方法**（不新增写路径、不额外加锁、不额外快照）；每个新增方法在代码中标注**复杂度**，并在《[后端基类清单](../../../后端基类清单.md)》「集合体系」节落「**禁用 / 慎用场景**」表——性能有实质代价的写法（如 `pop(index)` 为 O(n)）明确标出并给出替代写法。

**完成标准**：`ConcurrentStable*` 与 `ConcurrentSorted*` 的通用方法面覆盖上列 1~7 项，内置容器日常写法（`append` / `extend` / `+=` / `d[k]=v` / `del d[k]` / `clear` / `pop` / `setdefault` / `update(映射)` / 命名集合运算）可直接使用；`repr` / `str` 可读且**任何形态打印都不抛错**；每个新增方法标注复杂度且「禁用 / 慎用场景」表成文；**写糖与对应原子方法行为等价**（用例逐对断言）；并发用例证明写糖不破坏插入序与线程安全；定向 `pytest`（含覆盖率门禁）、`ruff`、`pyright`、基座护栏与 `preflight` 全绿。

**参考文档**：[08-1 裸无序集合护栏与存量盘点](#r08-1)、[08-3 集合体系收链](#r08-3)；《[后端基类清单](../../../后端基类清单.md)》「集合体系」节；《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」；`08_02` 实施记录「问题与处置」（集合类功能缺口的历史踩坑记录）

## 6. 需求 08-5：元组注解分形态治理与不可变集合形态 <a id="r08-5"></a>

优先级：3（中）

**背景与动机**：08 域治理「裸无序集合」时，护栏实现是**黑名单**（`BANNED_FORMS` = 裸容器 + 只读 / 可变抽象 + 升序形态），`tuple` 从未列入——而规范《后端开发规范》「集合与排序」写的是**白名单**语义（「集合字段与函数签名一律使用继承 `BaseCollection` 的集合类」）。两处口径分叉导致 `tuple` 落在夹缝里：**护栏 `WHITELIST_FORMS` 常量定义了却从未参与判定（死常量）**，任何未列入黑名单的形态自动放行。结果是全仓 **769 处 `tuple` 注解**（其中同构 `tuple[X, ...]` 524 处、固定元数 370 处）长期不在治理范围内，基线归零只说明「黑名单里的形态没了」，不代表集合声明已经收敛。同类漏网形态还有 `deque` / `Counter` / `OrderedDict`——今天补 `tuple`、明天还会有下一个。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节；口径逐项拍板 2026-10-20，详见 §1 已定口径 11）：

1. **tuple 分形态处置**：**同构** `tuple[X, ...]` 视为集合声明，纳入白名单治理、落 `ConcurrentStableList`；**固定元数** `tuple[A, B]` 视为「多返回值 / 元组值」（如 `(新增行数, 更新行数)`、`(行号, 违规类型, 命中片段)`），**显式豁免并写入规范**——其 Pydantic JSON Schema 为 `prefixItems` + `minItems` / `maxItems`（与 `array` 语义不同），改 `list` 会造成契约快照与前端类型漂移。
2. **护栏改真白名单**：`WHITELIST_FORMS` 参与判定，**未命中白名单即违规**；同步补 `--self-test` 矩阵（同构 tuple 报 / 固定元数不报 / 新形态报 / 未登记形态报）。框架边界豁免（`# bare-collections:allow`）与迭代 / 调用协议不查的口径保持不变。
3. **新增不可变集合形态**：`ConcurrentStableFrozenList` / `ConcurrentStableFrozenSet` / `ConcurrentStableFrozenDict`，挂**新增独立层 `BaseImmutable`**（位于 `BaseConcurrent` 之下）。**不可变形态仍需并发基座**——构造期即写路径（实测 `__init__` 末行 `self.update(items)`，`update` 持分段写锁 + 全局序号锁），且构造完成前若被共享仍需锁保护；**构造期直接写、构造后恒冻结**，不复用 `freeze()`（其实质是 `_freeze_clone` 完整重构造，2 万项实测 35.2ms）。
4. **哈希不变量修正**：**可变形态** `ConcurrentStable*` 改 `__hash__ = None`（与内置 `list` / `dict` / `set` 一致——可变对象做内容哈希会在内容变化后破坏 dict / set 的桶定位，元素「凭空消失」）；**内容哈希只给不可变形态**（列表按序、集合与映射用 `frozenset` 与 `eq` 语义对齐，并缓存哈希值）。**现有 16 处值对象字段**（`_Granted.permission_codes`、`QueryResult.rows`、`ImportResult.rows`、`ServiceRequest.headers`、`SpanContext.attributes` 等）改落不可变形态——`BaseValueObject` 是 frozen dataclass，其生成 `__hash__` 依赖字段可哈希，现用可变集合类导致 `eq` 相等而 `len({a, b}) == 2`。
5. **派生运算口径**：不可变形态的派生运算（`|` / `union` / `difference` / `symmetric_difference` 等）改为「**先算可变临时实例、最后一次冻结**」（现实现是 `copy()` 后 `update()`，而 `copy()` 保类型 ⇒ 新实例构造完即冻结 ⇒ `update()` 抛 `TypeError`，实测 `set |` / `union` / `dict |` 三处均失败）。
6. **存量整改**：**524 处同构元组**按区域分四批递减（批次 1 `libs` 源侧 294 → 批次 2 `services` 51 + `ops` 31 → 批次 3 `scripts/tools` 83 → 批次 4 `libs` 测试 65），与 08-2 区域口径一致、逐批 `--update-baseline` 递减。

**完成标准**：护栏为**真白名单判定**且 `--self-test` 覆盖新规则（同构 tuple 报 / 固定元数不报 / 未登记形态报）；不可变形态三件落唯一链（`BaseImmutable` 承 `BaseConcurrent`、`check-backend-base.py` 继承链对账与清单零漂移），构造期写、构造后冻结，**内容哈希与 `eq` 语义对齐**（同内容可作 dict 键 / set 元素去重生效）；可变形态改不可哈希且与内置容器行为一致；16 处值对象字段改落不可变形态后 `len({同内容两实例}) == 1`；派生运算不撞冻结；524 处同构元组整改完成、基线归零、复跑「新增 0 / 残留 0」；规范「集合与排序」与《后端基类清单》「集合体系」回写并与代码零漂移；定向 `pytest`（覆盖率 100% 行 + 分支）、`ruff`、`pyright`、基座护栏与 `preflight` 全绿。
