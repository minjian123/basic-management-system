## 1. 域说明 <a id="intro"></a>

本域收口《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」既有禁令——**有序集合对外输出稳定序、禁止裸无序集合**——的**护栏缺位**：该禁令成文已久，但仅有文字约束、无强制校验，后端 Python 侧存量裸 `dict` / `list` / `set` / `frozenset`（类字段注解与函数签名注解）审计时为 554 处、**2026-09-29 实测 548 处**，新代码持续新增、存量无法收敛。

- **本域范围**：裸无序集合**静态护栏**（AST 检查脚本 + 基线快照 + preflight / CI 挂接）、**存量盘点报告**、**规范口径补强**、**存量分批整改**（逐批递减基线至归零）、**集合体系收链**（跨副本形态回归集合继承链）。
- **不重复建设**：集合基座（有序 / 进程内并发 / 跨副本三类形态、`BaseSorted` → `SortedList` / `SortedDict` / `SortedSet` 等）与《[后端基类清单](../../../后端基类清单.md)》「集合体系」节均已交付；本域只做**护栏、盘点、口径收口、存量整改与体系收链**，不新增集合形态本身（收链只调整继承链与公共段分层）。
- **已定口径**（2026-09-28 拍板）：
  1. **检测形态**＝内建可变 / 无序容器（`dict` / `list` / `set` / `frozenset` 及 `typing` 别名 `Dict` / `List` / `Set` / `FrozenSet` / `DefaultDict`）；**不查**只读抽象（`Mapping` / `Iterable`）与有序抽象（`Sequence`——本身即有序契约）。**（2026-09-29 二次拍板收紧：改为「插入序白名单」——裸容器、只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）与升序形态（`ConcurrentSorted*` / `Sorted*`）一并判违规，集合体系实现文件豁免，迭代 / 调用协议不查，见 §2 口径 8）**
  2. **检测位置**＝类字段注解（含 dataclass / Pydantic / 基座派生）＋ 函数签名注解（参数与返回）；**函数体内局部变量不查**（内部变量不外流、无顺序与脱敏风险）。
  3. **存量豁免**＝**基线快照**（文件 + 规范化行内容指纹，落 `deploy/boundaries/`）；新增即失败、修复后同步更新（可审计递减），与既有 `data_ownership_exceptions.json` 同源机制。
  4. **本轮交付**＝护栏 + 基线 + 盘点报告 + 规范口径补强；**存量整改按模块分批另立任务**（共约 556 处，不宜一把梭）。
- **已定口径（2026-09-29 拍板）**：
  1. **存量整改立项**＝补充需求 [08-2 裸无序集合存量整改](#r08-2)（本域第二个需求），按**区域**分三批、**一批一子任务**（`08_02`~`08_04`）逐批推进，**目标基线归零**。
  2. **整改口径**＝**全覆盖落继承并发有序基类（`BaseConcurrentSorted`）的集合类，业务面只落插入序形态**（`ConcurrentStable*`）；**升序形态（`ConcurrentSorted*`）与 `SortedList` / `SortedDict` / `SortedSet` 同为基座内部实现**，业务与契约不得直接声明 / 继承（见口径 7）。**（2026-09-29 二次拍板取代「改声明不改行为 + 只读抽象」口径，并收敛「业务只落插入序」，见口径 8）**
  3. **批次划分调整**（2026-09-29 拍板）：盘点报告原「批次 1＝直接继承 `BaseObject` 的类字段」经 09 域归位后**实测仅剩 1 处**（报告快照时为 8 处），已失去独立批次意义；改按**区域**分三批（`bms_core` 305 / `services` 79 / `ops` 与 `scripts/tools` 164，合计 **548** 处），**批内先类字段后签名**承接「契约影响面优先」；同一文件只被一批触碰。
  4. **基线递减**＝每批完成后 `--update-baseline` 重写快照，**不得手工删除基线条目**（基线即台账）。
  5. **`scripts/tools` 长期口径专项**（随批次 3 评估）＝评估 `scripts/tools`（构建期内部工具、不在 CI `ruff` / `pyright` 覆盖范围）是否纳入长期强制口径（内部工具豁免 vs 统一整改），结论回写规范并同步护栏扫描范围。
  6. **集合体系收链立项**为需求 [08-3](#r08-3)（2026-09-29 拍板）：第三层跨副本形态（`RedisSortedSet` / `RedisSortedDict`）**回归集合继承链**（集合体系公共段对同步 / 异步中立，具体落法随该任务详细设计逐项确认）；`RedisSnapshot` 为通用缓存快照、非有序集合，保持框架对象侧并在清单注明；顺带修正《后端基类清单》§1 表第三层父类登记（现记 `BaseObject`，实际已是 `BaseFrameworkObject`）。
  7. **集合落地形态**（2026-09-29 拍板；**同日二次拍板收敛**）：`SortedList` / `SortedDict` / `SortedSet` 与 `ConcurrentSorted*` 定位为**基座内部基础实现**（仅由基座内部组合使用），**业务代码与对外数据契约不得直接声明、不得继承**；**业务与契约的集合一律落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`；**无合适形态时先新增继承 `BaseConcurrentSorted` 的形态并回写规范与清单，不得链外自造**）；**列表排序一律走排序契约**（请求侧统一排序参数 + 仓储可排序字段白名单），**不用集合结构排序**；**只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）不再作落点**；**凡以 `Sorted*` 为基的子类一律改为继承对应 `ConcurrentSorted*`**（全仓当前无此类子类，本条为面向新增的强制规则）；跨副本异步形态 `RedisSortedSet` / `RedisSortedDict` 保持 `BaseAsyncSorted`——其并发语义由 Lua 原子脚本 + `WATCH` / `MULTI` 乐观重试 + 版本号承载，且异步接口无法继承同步并发类。**落点**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、本需求 08-2 整改落点与 `08_02`~`08_04` 任务文档。
  8. **整改口径扩面**（2026-09-29 二次拍板）：批次 1 起**全覆盖**——除裸容器（`bms_core` 285 处）外，**既有只读 / 可变抽象落点（`Sequence` / `Mapping` / `Collection` 等，`bms_core` 309 处）一并纳入**，并按**位置全覆盖**（类字段 / 签名参数 / 签名返回，参数位也落集合类）；**业务面只落插入序形态**；新增基座能力**并入 `08_02`**——① 并发集合**只读 API**（`Sequence` / `Mapping` / `Set` 只读面，含与内置容器内容相等；写入仍走显式原子方法）；② **插入序形态** `ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`（`collection_kind="stable"`；体系根语义扩展为「有序＝**升序或插入序**两形态」，升序退为基座内部实现；**分段写 + 插入序号归并**支持高并发写）；③ **Pydantic 契约元数据** `CONTRACT_COLLECTION` + 插入序空集合工厂常量（落 `schemas/base.py`，`core` 不引入 Pydantic；契约 JSON Schema 与前端类型零漂移为门禁）；④ **护栏收紧**为插入序白名单（裸容器 / 抽象 / 升序形态均判违规，实现文件豁免，迭代协议不查）。**验收基准**为「**形态一致 + 逐处登记**」——加锁与插入序为预期行为；契约字段 `model_dump()` 输出集合类实例、`model_dump_json()` 输出 `array` / `object`。**基线口径**：收紧后先如实吸收现状（548 → **918**），按批递减至 `08_02` 324 / `08_03` 220 / `08_04` 0。
 9. **整改范围与推进**（2026-09-29 二次拍板）：`08_02` 起全覆盖，连带 `08_03`、`08_04`（域 08 一体推进）；进度见[本阶段计划](../计划/01_计划_认证与安全.md)。

## 2. 需求 08-1：裸无序集合护栏与存量盘点 <a id="r08-1"></a>

优先级：3（中）

**背景与动机**：「禁止裸无序集合」是《后端开发规范》的**强制禁令**，但当前只有文字约束——`check-base.py`（目录 / 基座清单）、`check-backend-base.py`（继承链 / 错误码段位）、`check-service-boundaries.py`（数据所有权）等基座护栏均不覆盖该口径，导致：① 存量裸无序集合（约 556 处）无台账、无法收敛；② 新代码继续新增，评审靠人眼；③ 集合基座（`SortedList` / `SortedDict` / `SortedSet`）形同「可选建议」。**能自动化的不靠人工**——本需求把该禁令变成可执行、可递减的护栏。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[AI开发规范](../../../规范/AI开发规范.md)》「执行护栏」）：

1. **静态护栏**：新增基座校验脚本 `check-bare-collections.py`（`scripts/tools/base-check/`），以 AST 解析后端 Python（`bms_core` / `services` / `ops` / `scripts/tools`，排除测试），按「类字段注解 + 函数签名注解」检出裸无序集合；支持**文本清单**与**机器可读（JSON）**两种输出、**基线比对**与**报告模式**（仅统计不改退出码）。
2. **基线快照**：现存违规以「文件 + 规范化行内容指纹」入基线快照（落 `deploy/boundaries/`），**新增违规即失败**；修复后同步更新快照，基线条目可审计递减（防回潜）。
3. **挂接**：纳入 `scripts/tools/preflight/check-preflight.py --fast`（基座与边界段）与 CI（静态 / 基座校验域），与既有基座护栏同机制、可单独运行。
4. **存量盘点报告**：按「区域（`bms_core` / `services` / `ops` / `scripts/tools`）× 位置（类字段 / 签名参数 / 签名返回）× 容器形态」统计存量，给出**分批整改建议**（按模块归属与契约层优先度）。
5. **规范口径补强**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」明确「对外数据契约、值对象与模块类的集合字段与签名**一律使用继承并发有序基类（`BaseConcurrentSorted`）的集合类，业务面只落插入序形态**（`ConcurrentStable*`）；升序形态与 `Sorted*` 同为基座内部实现；**禁止裸无序集合与只读 / 可变抽象落点**」，并指向护栏脚本与基线快照（白名单口径随 `08_02` 收紧，2026-09-29）。
6. **存量整改分批**：按模块分批另立任务（本轮登记后续阶段待办，不在本域内整改）。

**完成标准**：护栏脚本可用（基线比对 + 报告模式 + JSON 输出）；**新增违规能被拦截**（自测用例证明）；基线快照与现状一致（生成后复校零漂移）；盘点报告落文档（含分批建议）；规范口径补强完成；preflight 与 CI 挂接生效；`pytest`、`pyright`、`ruff` 通过。

**参考文档**：《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「红线与纪律」节

## 3. 需求 08-2：裸无序集合存量整改（分批递减至基线归零） <a id="r08-2"></a>

优先级：3（中）

**背景与动机**：08-1 已把「禁止裸无序集合」落为**可执行护栏 + 基线快照**（生成时 554 处入基线豁免；截至 2026-09-29 实测 **548** 处），但基线只**防新增**、不**收敛存量**——存量裸 `dict` / `list` 仍在对外数据契约、值对象与模块类的字段与签名上承担序列化输出，顺序不确定与后续脱敏接入面持续存在；集合基座（`SortedList` / `SortedDict` / `SortedSet`）与只读抽象因而仍形同「可选建议」。若不做存量整改，护栏只是把问题冻结在当下水位，规范口径落不到既有代码。

**内容**（盘点报告 §4「分批整改建议」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」）：

1. **分批推进**（按**区域**分三批、一批一子任务，**批内先类字段后签名**，逐批递减基线；数量为 2026-09-29 实测，**含口径收紧纳入的抽象落点**）：批次 1 `backend/libs`（`bms_core`）**594 处**（裸容器 285＝类字段 109 / 参数 32 / 返回 144；抽象落点 309＝类字段 19 / 参数 216 / 返回 74）→ 批次 2 `backend/services`（identity / org / tenant 等）**104 处**（裸 79 + 抽象 25）→ 批次 3 `backend/ops` **75 处**（裸 30 + 抽象 45）与 `scripts/tools` **145 处**（裸 134 + 抽象 11）。
2. **整改口径**（2026-09-29 二次拍板）：**全套落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`，类字段 / 参数 / 返回位置全覆盖）；**升序形态（`ConcurrentSorted*`）与 `SortedList` / `SortedDict` / `SortedSet` 同为基座内部实现、不作为整改落点**（不得直接声明或继承，排序走排序契约，见 §2 已定口径 7）；只读 / 可变抽象不再作落点；批次 1 一并交付基座能力新增（只读 API / `ConcurrentStable*`（含分段写）/ `CONTRACT_COLLECTION` / 护栏收紧，见 §2 口径 8）；**基线先由 548 吸收至 918 再递减**（`08_02` → 324）。
3. **基线递减**：每批完成后跑 `python3 scripts/tools/base-check/check-bare-collections.py . --update-baseline` 重写 `deploy/boundaries/bare_collections_baseline.json`，**不得手工删除基线条目**（基线即台账，进度以条目数递减为准）。
4. **`scripts/tools` 长期口径专项**（随批次 3）：评估 `scripts/tools`（构建期内部工具、结构不外流、不在 CI `ruff` / `pyright` 覆盖范围）是否纳入长期强制口径（内部工具豁免 vs 统一整改）；结论回写《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」与《[后端基类清单](../../../后端基类清单.md)》「集合体系」，并同步护栏扫描范围（若豁免，需同步护栏实现与基线）。
5. **登记回写**：《[后端基类清单](../../../后端基类清单.md)》「集合体系」节「裸无序集合护栏与基线」小段登记批次进度与基线归零状态；盘点报告批次表状态随实施更新。

**完成标准**：三批全部完成、`bare_collections_baseline.json` **条目归零**且 `check-bare-collections.py` 复跑「新增 0 / 残留 0」；对外数据契约 / 值对象 / 模块类的集合字段与签名（类字段 / 参数 / 返回）一律为**插入序集合类**（`ConcurrentStable*`；`Sorted*` 与 `ConcurrentSorted*` 不作为整改落点，且不得新增直接声明 / 继承）；**形态一致 + 逐处登记**（加锁与插入序为预期行为；契约 JSON Schema 与前端类型零漂移；受影响定向回归全绿，`pytest` 定向 + `ruff` + `pyright`）；护栏收紧为**插入序白名单**且 `--self-test` 覆盖新规则；`scripts/tools` 长期口径结论回写规范与清单；`preflight --fast` 全绿。

## 4. 需求 08-3：集合体系收链（跨副本形态回链） <a id="r08-3"></a>

优先级：3（中）

**背景与动机**：《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」按共享范围自小到大**逐层演进**（有序 → 进程内并发 → 跨副本），§4「扩展与演进」示例一也把三层画成**一条加层链**；架构铁律要求「能力即继承链上的层」「禁止在链外自由挂接功能」。但实测第三层 `RedisSortedSet` / `RedisSortedDict` / `RedisSnapshot`（`bms_core/core/redis_collections.py`）实际挂的是 `BaseFrameworkObject`（**集合链外**），且清单 §1 表还把父类登记为 `BaseObject`（未同步）。根因：集合体系根 `BaseSorted` 承载的是**同步**公共段（抽象 `to_list()` / `__iter__`），而跨副本形态的公共方法全为 `async`（`add` / `set` / `get` / `items` / `get_locked`…），无法满足同步契约，09_05 归位时遂判给 `BaseFrameworkObject`。结果是「集合体系三层」名存实亡——第三层既不在链上、也不受集合体系语义约束，后续新增集合形态还会继续各挂各的。

**内容**（《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」与「扩展与演进」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节）：

1. **公共段对同步 / 异步中立**：把集合体系公共段调整为「有序语义 + 稳定序 / 序列化契约」，同步抽象（`to_list` / `__iter__`）与异步抽象（异步读写 + 快照）各自下沉为**角色链上的层**；具体落法（体系根只留语义 + 同步方法下沉 / 拆同步-异步两条角色链 / 新增集合体系根）在该任务详细设计逐项确认，不在需求层定死。
2. **跨副本形态回链**：`RedisSortedSet` / `RedisSortedDict` 改挂集合体系（异步角色链上的层）；`RedisSnapshot` 是**通用缓存快照、非有序集合**，保持框架对象体系，并在《[后端基类清单](../../../后端基类清单.md)》注明其归属与理由。
3. **登记与口径回写**：修正《[后端基类清单](../../../后端基类清单.md)》§1 表第三层父类登记、§4 表与「扩展与演进」示例一（三层为一条链）、§10 链登记与体系根白名单（如新增层或体系根）。
4. **护栏**：`check-backend-base.py` 的继承链对账与体系根白名单须覆盖新层；如集合体系新增语义约束（例如异步角色链成员不得为 dataclass），补对应检查与 `--self-test` 用例。
5. **测试**：先登记 Kiwi TCMS 用例取号、后写自动化——断言 `RedisSortedSet` / `RedisSortedDict` 落在集合体系链上（`issubclass` 断言）、`RedisSnapshot` 仍在框架对象侧、清单 §1/§4/§10 与代码一致；受影响定向回归（集合类 + Redis 集合用例）与门禁全绿。

**完成标准**：集合体系三层为**一条继承链**（`RedisSortedSet` / `RedisSortedDict` 在链上，`RedisSnapshot` 按非有序集合在框架对象侧且有清单注明）；《[后端基类清单](../../../后端基类清单.md)》§1 / §4 / §10 与代码**零漂移**；`check-backend-base.py` 继承链对账与体系语义检查通过（含 `--self-test`）；**行为零变更**（既有 Redis 集合用例全绿）；定向 `pytest`、`ruff`、`pyright`、基座校验与 `preflight --fast` 全绿。
