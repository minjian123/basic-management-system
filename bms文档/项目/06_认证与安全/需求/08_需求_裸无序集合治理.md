## 1. 域说明 <a id="intro"></a>

本域收口《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」既有禁令——**有序集合对外输出稳定序、禁止裸无序集合**——的**护栏缺位**：该禁令成文已久，但仅有文字约束、无强制校验，后端 Python 侧现存约 556 处裸 `dict` / `list` / `set` / `frozenset`（类字段注解与函数签名注解），新代码持续新增、存量无法收敛。

- **本域范围**：裸无序集合**静态护栏**（AST 检查脚本 + 基线快照 + preflight / CI 挂接）、**存量盘点报告**、**规范口径补强**。
- **不重复建设**：集合基座（有序 / 进程内并发 / 跨副本三类形态、`BaseSorted` → `SortedList` / `SortedDict` / `SortedSet` 等）与《[后端基类清单](../../../后端基类清单.md)》「集合体系」节均已交付；本域只做**护栏、盘点与口径收口**，不新增集合形态。
- **已定口径**（2026-09-28 拍板）：
  1. **检测形态**＝内建可变 / 无序容器（`dict` / `list` / `set` / `frozenset` 及 `typing` 别名 `Dict` / `List` / `Set` / `FrozenSet` / `DefaultDict`）；**不查**只读抽象（`Mapping` / `Iterable`）与有序抽象（`Sequence`——本身即有序契约）。
  2. **检测位置**＝类字段注解（含 dataclass / Pydantic / 基座派生）＋ 函数签名注解（参数与返回）；**函数体内局部变量不查**（内部变量不外流、无顺序与脱敏风险）。
  3. **存量豁免**＝**基线快照**（文件 + 规范化行内容指纹，落 `deploy/boundaries/`）；新增即失败、修复后同步更新（可审计递减），与既有 `data_ownership_exceptions.json` 同源机制。
  4. **本轮交付**＝护栏 + 基线 + 盘点报告 + 规范口径补强；**存量整改按模块分批另立任务**（共约 556 处，不宜一把梭）。
- **依据**：《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[后端基类清单](../../../后端基类清单.md)》「集合体系」与「扩展与演进」节、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「红线与纪律」节。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 08-1：裸无序集合护栏与存量盘点 <a id="r08-1"></a>

优先级：3（中）

**背景与动机**：「禁止裸无序集合」是《后端开发规范》的**强制禁令**，但当前只有文字约束——`check-base.py`（目录 / 基座清单）、`check-backend-base.py`（继承链 / 错误码段位）、`check-service-boundaries.py`（数据所有权）等基座护栏均不覆盖该口径，导致：① 存量裸无序集合（约 556 处）无台账、无法收敛；② 新代码继续新增，评审靠人眼；③ 集合基座（`SortedList` / `SortedDict` / `SortedSet`）形同「可选建议」。**能自动化的不靠人工**——本需求把该禁令变成可执行、可递减的护栏。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[AI开发规范](../../../规范/AI开发规范.md)》「执行护栏」）：

1. **静态护栏**：新增基座校验脚本 `check-bare-collections.py`（`scripts/tools/base-check/`），以 AST 解析后端 Python（`bms_core` / `services` / `ops` / `scripts/tools`，排除测试），按「类字段注解 + 函数签名注解」检出裸无序集合；支持**文本清单**与**机器可读（JSON）**两种输出、**基线比对**与**报告模式**（仅统计不改退出码）。
2. **基线快照**：现存违规以「文件 + 规范化行内容指纹」入基线快照（落 `deploy/boundaries/`），**新增违规即失败**；修复后同步更新快照，基线条目可审计递减（防回潜）。
3. **挂接**：纳入 `scripts/tools/preflight/check-preflight.py --fast`（基座与边界段）与 CI（静态 / 基座校验域），与既有基座护栏同机制、可单独运行。
4. **存量盘点报告**：按「区域（`bms_core` / `services` / `ops` / `scripts/tools`）× 位置（类字段 / 签名参数 / 签名返回）× 容器形态」统计存量，给出**分批整改建议**（按模块归属与契约层优先度）。
5. **规范口径补强**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」明确「对外数据契约、值对象与模块类的集合字段与签名**一律使用继承基座的集合类或只读抽象**（`Sequence` / `Mapping` / `Iterable`），禁止裸无序集合」，并指向护栏脚本与基线快照。
6. **存量整改分批**：按模块分批另立任务（本轮登记后续阶段待办，不在本域内整改）。

**完成标准**：护栏脚本可用（基线比对 + 报告模式 + JSON 输出）；**新增违规能被拦截**（自测用例证明）；基线快照与现状一致（生成后复校零漂移）；盘点报告落文档（含分批建议）；规范口径补强完成；preflight 与 CI 挂接生效；`pytest`、`pyright`、`ruff` 通过。
