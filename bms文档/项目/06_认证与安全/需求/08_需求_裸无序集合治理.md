## 1. 域说明 <a id="intro"></a>

本域收口《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」既有禁令——**有序集合对外输出稳定序、禁止裸无序集合**——的**护栏缺位**：该禁令成文已久，但仅有文字约束、无强制校验，后端 Python 侧存量裸 `dict` / `list` / `set` / `frozenset`（类字段注解与函数签名注解）审计时为 554 处、**2026-09-29 实测 548 处**，新代码持续新增、存量无法收敛。

- **本域范围**：裸无序集合**静态护栏**（AST 检查脚本 + 基线快照 + preflight / CI 挂接）、**存量盘点报告**、**规范口径补强**、**存量分批整改**（逐批递减基线至归零）、**集合体系收链**（集合体系收敛为唯一继承链）。
- **不重复建设**：集合基座（**唯一链**：基础集合基类 `BaseCollection` → 非并发有序 `BaseSorted` / 基础并发 `BaseConcurrent` / 跨副本异步有序 `BaseAsyncSorted` / 通用缓存层 `BaseCacheSnapshot`）与《[后端基类清单](../../../后端基类清单.md)》「集合体系」节均已交付；本域只做**护栏、盘点、口径收口、存量整改与体系收链**（收链只调整继承链与公共段归属，不新增集合形态本身）。
- **已定口径**（2026-09-28 拍板）：
  1. **检测形态**＝内建可变 / 无序容器（`dict` / `list` / `set` / `frozenset` 及 `typing` 别名 `Dict` / `List` / `Set` / `FrozenSet` / `DefaultDict`）。**（2026-09-29 二次拍板收紧：改为「插入序白名单」——裸容器、只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）与升序形态（`Sorted*` / `ConcurrentSorted*`）一并判违规，见口径 8）**
  2. **检测位置**＝类字段注解（含 dataclass / Pydantic / 基座派生）＋ 函数签名注解（参数与返回）。**（2026-09-29 二次拍板扩展：函数体带注解局部变量与测试目录一并纳入，见口径 8）**
  3. **存量豁免**＝**基线快照**（文件 + 规范化行内容指纹，落 `deploy/boundaries/`）；新增即失败、修复后同步更新（可审计递减），与既有 `data_ownership_exceptions.json` 同源机制。
  4. **本轮交付**＝护栏 + 基线 + 盘点报告 + 规范口径补强；**存量整改按区域分批另立任务**（不宜一把梭）。
- **已定口径（2026-09-29 拍板）**：
  1. **存量整改立项**＝补充需求 [08-2 裸无序集合存量整改](#r08-2)（本域第二个需求），按**区域**分三批、**一批一子任务**（`08_02`~`08_04`）逐批推进，**目标基线归零**。
  2. **整改口径**＝**全覆盖落继承集合体系唯根 `BaseCollection` 的集合类，业务与契约只落插入序形态**（`ConcurrentStable*`）；**升序形态（`ConcurrentSorted*`）与 `SortedList` / `SortedDict` / `SortedSet` 同为体系内部基础实现**，业务与契约不得直接声明 / 继承（见口径 7）。**（2026-09-29 二次拍板取代「改声明不改行为 + 只读抽象」口径，并收敛「业务只落插入序」，见口径 8）**
  3. **批次划分调整**（2026-09-29 拍板）：盘点报告原「批次 1＝直接继承 `BaseObject` 的类字段」经 09 域归位后**实测仅剩 1 处**（报告快照时为 8 处），已失去独立批次意义；改按**区域**分三批（`bms_core` / `services` / `ops` 与 `scripts/tools`），**批内先类字段后签名**承接「契约影响面优先」；同一文件只被一批触碰。
  4. **基线递减**＝每批完成后 `--update-baseline` 重写快照，**不得手工删除基线条目**（基线即台账）。
  5. **`scripts/tools` 长期口径专项**（随批次 3 评估）＝评估 `scripts/tools`（构建期内部工具、不在 CI `ruff` / `pyright` 覆盖范围）是否纳入长期强制口径（内部工具豁免 vs 统一整改），结论回写规范并同步护栏扫描范围。
  6. **集合体系收链立项**为需求 [08-3](#r08-3)（2026-09-29 拍板）：第三层跨副本形态（`RedisSortedSet` / `RedisSortedDict`）**回归集合继承链**（挂 `BaseAsyncSorted`）；`RedisSnapshot` 由框架对象体系**改挂通用缓存层 `BaseCacheSnapshot`**（不再有链外例外），顺带修正《后端基类清单》§1 表第三层父类登记。
  7. **集合落地形态**（2026-09-29 拍板；**同日二次拍板收敛**）：`SortedList` / `SortedDict` / `SortedSet` 与 `ConcurrentSorted*` 定位为**体系内部基础实现**（仅由体系内部组合使用），**业务代码与对外数据契约不得直接声明、不得继承**；**业务与契约的集合一律落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`；**无合适形态时先新增继承 `BaseCollection` 的形态并回写规范与清单，不得链外自造**）；**列表排序一律走排序契约**（请求侧统一排序参数 + 仓储可排序字段白名单），**不用集合结构排序**；**只读 / 可变抽象（`Sequence` / `Mapping` / `AbstractSet` / `Collection` / `Mutable*`）不再作落点**；**凡以 `Sorted*` 为基的子类一律改为继承对应 `ConcurrentSorted*`**（全仓当前无此类子类，本条为面向新增的强制规则）；跨副本异步形态 `RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`——其并发语义由 Lua 原子脚本 + `WATCH` / `MULTI` 乐观重试 + 版本号承载，且异步接口无法继承同步并发类。**落点**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、本需求 08-2 整改落点与 `08_02`~`08_04` 任务文档。
  8. **集合体系唯一链与护栏口径无例外**（2026-09-29 二次拍板）：**所有集合类一律（间接）继承基础集合基类 `BaseCollection`、无任何例外**——根只承载集合通用语义（有序语义 + 稳定序约定 + `collection_kind` 标记），其下按形态分支：非并发有序 `BaseSorted`（无锁高效，`Sorted*` 落点）、基础并发 `BaseConcurrent`（锁守卫 + 原子复合操作 + 快照遍历）、跨副本异步有序 `BaseAsyncSorted`（Lua + 版本号，无同步锁层、无同步读入口）、通用缓存层 `BaseCacheSnapshot`（`RedisSnapshot` 归此）；`BaseSorted`（旧语义根）/ `BaseSyncSorted` / `BaseConcurrentSorted` 等旧名退场。**护栏取消全部豁免**——白名单只含插入序形态；裸容器、只读 / 可变抽象、升序形态、`ClassVar` 类级常量、`BaseSettings` 配置字段、**测试目录**（扩扫描目标至 `*/tests`）与**函数体带注解局部变量**一律纳入；仅保留「迭代 / 调用协议（`Iterable` / `Iterator` / `Callable`）不查」；集合体系**实现文件为不属约束对象**（护栏只约束业务侧集合声明——对外数据契约、值对象与模块类；实现文件是体系自身、其内置容器为内部底座与序列化出口）。**位置全覆盖**（类字段 / 签名参数 / 签名返回 / 局部变量）；新增基座能力并入 `08_02`——① 并发集合**只读 API**（`Sequence` / `Mapping` / `Set` 只读面，含与内置容器内容相等；写入仍走显式原子方法）；② **插入序形态** `ConcurrentStable*`（`collection_kind="stable"`；**分段写 + 插入序号归并**支持高并发写）；③ **Pydantic 契约元数据** `CONTRACT_COLLECTION` + 插入序空集合工厂常量（落 `schemas/base.py`，`core` 不引入 Pydantic；契约 JSON Schema 与前端类型零漂移为门禁）；④ **护栏收紧 + 豁免取消**并如实吸收基线。**验收基准**为「**形态一致 + 逐处登记**」——加锁与插入序为预期行为；契约字段 `model_dump()` 输出集合类实例、`model_dump_json()` 输出 `array` / `object`。**基线口径**：收紧后先如实吸收现状（918 → **1711**，2026-09-30 实测），按批递减至归零。
  9. **整改范围与推进**（2026-09-29 二次拍板）：`08_02` 起全覆盖，连带 `08_03`、`08_04`（域 08 一体推进）；进度见[本阶段计划](../计划/01_计划_认证与安全.md)。

## 2. 需求 08-1：裸无序集合护栏与存量盘点 <a id="r08-1"></a>

优先级：3（中）

**背景与动机**：「禁止裸无序集合」是《后端开发规范》的**强制禁令**，但当前只有文字约束——`check-base.py`（目录 / 基座清单）、`check-backend-base.py`（继承链 / 错误码段位）、`check-service-boundaries.py`（数据所有权）等基座护栏均不覆盖该口径，导致：① 存量裸无序集合无台账、无法收敛；② 新代码继续新增，评审靠人眼；③ 集合基座形同「可选建议」。**能自动化的不靠人工**——本需求把该禁令变成可执行、可递减的护栏。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」、《[AI开发规范](../../../规范/AI开发规范.md)》「执行护栏」）：

1. **静态护栏**：新增基座校验脚本 `check-bare-collections.py`（`scripts/tools/base-check/`），以 AST 解析后端 Python（`bms_core` / `services` / `ops` / `scripts/tools`，含 `tests`），按「类字段注解 + 函数签名注解 + 函数体带注解局部变量」检出裸无序集合；支持**文本清单**与**机器可读（JSON）**两种输出、**基线比对**与**报告模式**（仅统计不改退出码）。
2. **基线快照**：现存违规以「文件 + 规范化行内容指纹」入基线快照（落 `deploy/boundaries/`），**新增违规即失败**；修复后同步更新快照，基线条目可审计递减（防回潜）。
3. **挂接**：纳入 `scripts/tools/preflight/check-preflight.py --fast`（基座与边界段）与 CI（静态 / 基座校验域），与既有基座护栏同机制、可单独运行。
4. **存量盘点报告**：按「区域（`bms_core` / `services` / `ops` / `scripts/tools`）× 位置（类字段 / 签名参数 / 签名返回 / 局部变量）× 容器形态」统计存量，给出**分批整改建议**（按区域归属与契约层优先度）。
5. **规范口径补强**：《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」明确「对外数据契约、值对象与模块类的集合字段与签名**一律使用继承基础集合基类 `BaseCollection` 的集合类，业务面只落插入序形态**（`ConcurrentStable*`）；升序形态与 `Sorted*` 同为体系内部基础实现；**禁止裸无序集合与只读 / 可变抽象落点**；**集合体系为唯一链、所有集合类一律继承 `BaseCollection`、无任何例外**」，并指向护栏脚本与基线快照（白名单与豁免口径随 `08_02` 收紧 / 取消，2026-09-29）。
6. **存量整改分批**：按区域分三批另立任务（本轮登记后续阶段待办，不在本条需求内整改）。

**完成标准**：护栏脚本可用（基线比对 + 报告模式 + JSON 输出）；**新增违规能被拦截**（自测用例证明）；基线快照与现状一致（生成后复校零漂移）；盘点报告落文档（含分批建议）；规范口径补强完成；preflight 与 CI 挂接生效；`pytest`、`pyright`、`ruff` 通过。

**参考文档**：《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[后端基类清单](../../../后端基类清单.md)》「集合体系」节、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「红线与纪律」节

## 3. 需求 08-2：裸无序集合存量整改（分批递减至基线归零） <a id="r08-2"></a>

优先级：3（中）

**背景与动机**：08-1 已把「禁止裸无序集合」落为**可执行护栏 + 基线快照**（生成时 554 处入基线豁免；截至 2026-09-29 实测 548 处），但基线只**防新增**、不**收敛存量**——存量裸 `dict` / `list` 仍在对外数据契约、值对象与模块类的字段与签名上承担序列化输出，顺序不确定与后续脱敏接入面持续存在；集合基座与只读抽象因而仍形同「可选建议」。若不做存量整改，护栏只是把问题冻结在当下水位，规范口径落不到既有代码。

**内容**（盘点报告 §4「分批整改建议」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节「集合与排序」）：

1. **分批推进**（按**区域**分三批、一批一子任务，**批内先类字段后签名**，逐批递减基线；数量为 2026-09-30 实测，**含口径收紧与豁免取消纳入的测试目录与函数体局部变量**）：批次 1 `backend/libs`（`bms_core`，含 `tests`）**1036 处** → 批次 2 `backend/services`（含 `tests`）**348 处** → 批次 3 `scripts/tools` **224 处** 与 `backend/ops` **103 处**（合计 327 处）。
2. **整改口径**（2026-09-29 二次拍板；2026-09-30 结构落定）：**全套落插入序形态**（`ConcurrentStableList` / `ConcurrentStableSet` / `ConcurrentStableDict`，类字段 / 参数 / 返回 / 局部变量位置全覆盖）；**升序形态（`ConcurrentSorted*`）与 `SortedList` / `SortedDict` / `SortedSet` 同为体系内部基础实现、不作为整改落点**（不得直接声明或继承，排序走排序契约，见 §2 已定口径 7）；只读 / 可变抽象不再作落点；批次 1 一并交付**集合体系唯一链收口**（`BaseCollection` 唯根 + `BaseSorted` / `BaseConcurrent` / `BaseAsyncSorted` / `BaseCacheSnapshot`）与基座能力新增（只读 API / `ConcurrentStable*`（含分段写）/ `CONTRACT_COLLECTION` / 护栏收紧 + 豁免取消，见 §2 口径 8）；**基线先由 918 吸收至 1711 再递减**。
3. **基线递减**：每批完成后跑 `python3 scripts/tools/base-check/check-bare-collections.py . --update-baseline` 重写 `deploy/boundaries/bare_collections_baseline.json`，**不得手工删除基线条目**（基线即台账，进度以条目数递减为准）。
4. **`scripts/tools` 长期口径专项**（随批次 3）：评估 `scripts/tools`（构建期内部工具、结构不外流、不在 CI `ruff` / `pyright` 覆盖范围）是否纳入长期强制口径（内部工具豁免 vs 统一整改）；结论回写《[后端开发规范](../../../规范/后端开发规范.md)》「集合与排序」与《[后端基类清单](../../../后端基类清单.md)》「集合体系」，并同步护栏扫描范围（若豁免，需同步护栏实现与基线）。
5. **登记回写**：《[后端基类清单](../../../后端基类清单.md)》「集合体系」节「裸无序集合护栏与基线」小段登记批次进度与基线归零状态；盘点报告批次表状态随实施更新。

**完成标准**：三批全部完成、`bare_collections_baseline.json` **条目归零**且 `check-bare-collections.py` 复跑「新增 0 / 残留 0」；对外数据契约 / 值对象 / 模块类的集合字段、签名与局部变量一律为**插入序集合类**（`ConcurrentStable*`；`Sorted*` 与 `ConcurrentSorted*` 不作为整改落点，且不得新增直接声明 / 继承）；**集合体系唯一链**（`BaseCollection` 唯根，`RedisSnapshot` 归通用缓存层）与代码、清单零漂移；**形态一致 + 逐处登记**（加锁与插入序为预期行为；契约 JSON Schema 与前端类型零漂移；受影响定向回归全绿，`pytest` 定向 + `ruff` + `pyright`）；护栏为**插入序白名单 + 无例外**且 `--self-test` 覆盖新规则；`scripts/tools` 长期口径结论回写规范与清单；`preflight --fast` 全绿。

## 4. 需求 08-3：集合体系收链（跨副本形态回链） <a id="r08-3"></a>

优先级：3（中）

**背景与动机**：《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」按共享范围自小到大**逐层演进**（有序 → 进程内并发 → 跨副本），§4「扩展与演进」示例一也把三层画成**一条加层链**；架构铁律要求「能力即继承链上的层」「禁止在链外自由挂接功能」。但实测第三层 `RedisSortedSet` / `RedisSortedDict` / `RedisSnapshot`（`bms_core/core/redis_collections.py`）曾挂 `BaseFrameworkObject`（**集合链外**）。根因：集合体系根曾承载**同步**公共段（抽象 `to_list()` / `__iter__`），而跨副本形态的公共方法全为 `async`，无法满足同步契约。结果是「集合体系三层」名存实亡——第三层既不在链上、也不受集合体系语义约束。

**内容**（《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」与「扩展与演进」、《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节）：

1. **唯一链收口**：集合体系收敛为**唯一继承链**——基础集合基类 `BaseCollection` 为**集合体系唯根**，其下按形态分支 `BaseSorted`（非并发有序）/ `BaseConcurrent`（基础并发）/ `BaseAsyncSorted`（跨副本）/ `BaseCacheSnapshot`（通用缓存）；**所有集合类一律（间接）继承 `BaseCollection`、无任何例外**。
2. **跨副本形态回链**：`RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`（承 `BaseSorted`，**无同步读入口**——并发由 Lua + 版本号承载）；`RedisSnapshot` 为非有序集合，经**通用缓存层 `BaseCacheSnapshot`** 入链（不再有链外例外）。
3. **登记与口径回写**：修正《[后端基类清单](../../../后端基类清单.md)》§1 层级图与表、§4 表与「扩展与演进」示例、§10 体系根清单（`BaseCollection`）与继承链登记。
4. **护栏**：`check-backend-base.py` 的继承链对账与体系根白名单覆盖新根与新层（`BaseCollection`）；`check-bare-collections.py` 白名单与「不属约束对象」口径同步。
5. **测试**：先登记 Kiwi TCMS 用例取号、后写自动化——断言所有集合类（含 `Sorted*` / `Concurrent*` / `Redis*` / `RedisSnapshot`）均（间接）继承 `BaseCollection`、跨副本形态无同步读入口、清单 §1/§4/§10 与代码零漂移；受影响定向回归（集合类 + Redis 集合用例）与门禁全绿。

**完成标准**：集合体系为**一条继承链**（所有集合类均继承 `BaseCollection`；`RedisSortedSet` / `RedisSortedDict` 挂 `BaseAsyncSorted`；`RedisSnapshot` 挂 `BaseCacheSnapshot`）；《[后端基类清单](../../../后端基类清单.md)》§1 / §4 / §10 与代码**零漂移**；`check-backend-base.py` 继承链对账与体系语义检查通过（含 `--self-test`）；同步侧**行为零变更**（既有集合用例全绿）；定向 `pytest`、`ruff`、`pyright`、基座校验与 `preflight --fast` 全绿。

**参考文档**：《[后端基类清单](../../../后端基类清单.md)》§4「集合体系」/「扩展与演进」、§10；《[后端开发规范](../../../规范/后端开发规范.md)》「后端基座体系（强制）」节；《[架构设计 · 后端基础类体系](../../../设计/架构设计/04_架构设计_后端基础类体系.md)》；[08-1 裸无序集合护栏与存量盘点](#r08-1)
