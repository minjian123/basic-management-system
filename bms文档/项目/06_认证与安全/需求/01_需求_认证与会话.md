## 1. 域说明 <a id="intro"></a>

本域是阶段六的主链：把阶段二已交付的「网关 forward-auth + 双类 JWT + 边缘信任」从**占位与外部 IdP 签发**切换为 **BMS 自签用户令牌 + 真实登录会话治理**，是 SSO（域 02）、账号治理（域 03）与前端登录（域 05）共同的地基。

- **本域范围**：安全原语（PBKDF2 哈希 / 令牌编解码 / 会话黑名单）真实实现；用户双 token 自签与网关校验源切换；本地登录 / 刷新 / 登出链路（验证码与限流接线）；会话记录与强制踢出；登录态依赖真实化与租户解析接线；当前用户概要端点（`GET /auth/me`，补充需求 01-6，2026-10-02 立项）。
- **不重复建设**：identity 服务工程、网关 forward-auth 接线、服务 JWT 自签与统一校验、边缘信任与请求净化、Redis / 出站 / 幂等横切基座均为阶段二已交付产物，本域只做**用户令牌与登录会话**部分的真实化与接线。
- **依赖口径**：登录凭据（账号 / 密码哈希 / 状态）与锁定字段落 **org 服务**（`sys_user` 最小模型，用户主数据归属），identity 经服务间契约调用其内部凭据校验 / 锁定写入接口；会话与身份映射表归 identity 服务（平台库 / 租户库按表归属登记）。
- **依据**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §3 / §7、《[架构设计 · 核心交互时序](../../../设计/架构设计/06_架构设计_核心交互时序.md)》、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[后端基类清单](../../../后端基类清单.md)》、《[安全开发规范](../../../规范/安全开发规范.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 01-1：安全原语真实实现与认证配置定稿 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：`bms_core/core/security.py` 的 `PasswordHasher` / `TokenCodec` / `SessionSecurity` 目前抛 `NotImplementedError`（占位），而登录链路、SSO 联邦与服务间身份都建立在「口令哈希、令牌编解码、会话黑名单」三件原语之上；`[security]` 配置现为占位（`access_token_expire_minutes=60`、算法口径不一），若不定稿，后续每个任务都要各自猜口径，返工面覆盖全部认证功能。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §5、《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「认证与存储安全」节、《[后端基类清单](../../../后端基类清单.md)》安全基座条目）：

1. **口令哈希**：PBKDF2 标准库实现（迭代次数与盐长按《安全开发规范》口径），支持校验与「需要重哈希」判定（算法 / 迭代参数升级时自动重算）；不引入 bcrypt / argon2 新依赖。
2. **令牌编解码**：统一 JOSE 引擎（joserfc，复用阶段二已进锁依赖）封装签发与验签，算法白名单 RS256 / ES256，密钥集支持多密钥并行轮换（`kid` 选择 + 新旧并行验证期）。
3. **会话黑名单**：refresh 使用一次即轮换（旧 `jti` 入黑名单，短 TTL），登出 / 踢出即时失效；Redis 键命名与租户前缀遵循《命名规范》。
4. **配置定稿**：`[security]` 节定稿 access 有效期 **30 分钟**、refresh **14 天**、签名算法与密钥来源（环境变量 / Secret 注入），并补《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》「前端配置」节（前端可读项与构建期变量边界）。
5. **口径回写**：PBKDF2 结论回写《[安全开发规范](../../../规范/安全开发规范.md)》（替换 bcrypt / argon2 表述）；占位 docstring 与配置样例同步更新。

**完成标准**：三类原语真实实现且经依赖注入装配可用（哈希可校验、令牌可签可验、黑名单可命中）；密钥轮换期内新旧密钥并行验签通过；`[security]` 配置与文档口径一致；单元用例（含升级重哈希 / 轮换 / 失效分支）全绿；`pytest`、`pyright`、`ruff` 门禁通过。

**参考文档**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2、《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「认证与存储安全」节、《[安全开发规范](../../../规范/安全开发规范.md)》「认证与会话安全」节、《[后端基类清单](../../../后端基类清单.md)》安全基座条目

## 3. 需求 01-2：用户令牌自签与网关校验源切换 <a id="r01-2"></a>

优先级：2（高）

**背景与动机**：阶段二的用户 JWT（`aud=api`）由外部 IdP（Keycloak）签发、BMS 只验签；但规划要求「本地账号密码登录并存（超管应急通道，防 IdP 故障锁死）」与「BMS 兼作 IdP」，且 SSO 各来源必须统一收敛为 BMS 自有令牌。若继续由外部 IdP 签发，本地登录与超管应急通道将依赖外部 IdP 可用性，BMS 兼作 IdP 也无从落地（2026-09-26 拍板：BMS 自签）。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §7、《[架构设计 · API 网关与边缘](../../../设计/架构设计/36_架构设计_子系统_API网关与边缘.md)》「边缘认证」节）：

1. **用户令牌自签**：identity 服务用本服务密钥签发 access（30 分钟，载荷含 `sub` / `tenant_id` / `jti` / `type=access`）与 refresh（14 天滚动轮换），`aud=api`、`iss` 为 BMS；刷新页面后静默续期（access 仅前端内存）。
2. **JWKS 发布**：identity 服务 `/.well-known/jwks.json` 同时发布服务令牌与用户令牌公钥（`kid` 区分用途），供网关 / 内部服务本地验签。
3. **校验源切换**：统一校验器（`BaseTokenVerifier`）用户票据来源由外部 IdP JWKS 切到 **identity 自签 JWKS**；网关 forward-auth（`/api/v1/auth/introspect`）按 `aud=api` 全校验（签名 / `exp` / `iss` / `aud`）后换发网关服务 JWT 的既有链路**保持不变**。
4. **Keycloak 角色调整**：Keycloak 保留为**外部 IdP 之一**（SSO 演示 / 测试环境），不再承担本地用户令牌签发；`[identity_provider]` 配置指向不变。
5. **口径回写**：架构 14 §2（签发方）与架构 36 认证链路、阶段二网关配置说明按新口径回写；服务间身份（`aud=service`）与服务 JWT 链路不受影响。

**完成标准**：本地签发的用户 access / refresh 经网关与 identity 校验通过、外部 IdP 失效不影响本地登录与超管应急通道；JWKS 端点同时可验服务令牌与用户令牌；伪造 `aud` / 过期 / 签名不符均被拒（用例覆盖）；既有网关 forward-auth 与边缘信任用例回归全绿。

**参考文档**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §7、《[架构设计 · API 网关与边缘](../../../设计/架构设计/36_架构设计_子系统_API网关与边缘.md)》、《[后端基类清单](../../../后端基类清单.md)》「统一校验」「服务 JWT」条目、阶段二 [07_03 网关认证接线与服务身份](../../02_后端基座与服务化地基/任务/07_认证与服务身份/07_认证与服务身份_03_网关认证接线与服务身份/07_认证与服务身份_03_网关认证接线与服务身份.md)（**前置契约已交付**）

## 4. 需求 01-3：本地登录 / 刷新 / 登出链路 <a id="r01-3"></a>

优先级：2（高）

**背景与动机**：网关已放行 `/api/identity/v1/auth/login`、`/auth/refresh` 路径，但端点本身尚不存在；前端登录页仍是占位页。没有真实登录链路，的「本地 + SSO 登录链路 E2E 通过」与后端受保护接口的真实鉴权都无从验证。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2、《[架构设计 · 核心交互时序](../../../设计/架构设计/06_架构设计_核心交互时序.md)》「登录与双 token」节、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》）：

1. **登录端点**：`POST /auth/login`（账号 + 密码 + 租户标识 + 可选验证码凭证）——校验验证码（域 03）、登录限流（失败计数与锁定联动）、经 org 内部凭据校验接口比对 PBKDF2 哈希，成功后签发双 token、创建会话（域 01-4）、更新 `last_login_at` 与密码策略字段（域 03-5）。
2. **刷新端点**：`POST /auth/refresh`（httpOnly cookie）——校验 refresh 签名 / 黑名单 / 会话标记，轮换签发新双 token（旧 refresh 失效）；refresh 重放按旧票据已失效拦截。
3. **登出端点**：`POST /auth/logout`——refresh 入黑名单、会话置 `revoked`、删除 Redis 会话标记；幂等（重复登出不报错）。
4. **org 凭据校验内部接口**：org 服务提供最小模型（账号 / 密码哈希 / 状态 / 锁定字段）与内部校验 / 写入接口（服务 JWT 鉴权、不经网关），供 identity 登录、JIT 建号（域 02-2）与密码更新调用。
5. **异常语义**：账号不存在 / 密码错误 / 账号锁定 / 验证码失败 / 限流命中分别返回认证错误码段（`20001` ~ `20006`，见《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》与概要 14 错误码表），错误信息不泄露账号是否存在。
6. **登录留痕口径**：本期不落 `sys_login_log` 表（归阶段八），失败计数走 Redis、锁定记录落 `sys_account_lock`；结构化日志不落密码 / 令牌原始值。

**完成标准**：本地登录 → 访问受保护接口 → 静默刷新 → 登出全链路 E2E 通过；错误分支（错密 / 锁定 / 验证码失败 / 限流）返回码与文案符合契约；refresh 轮换后旧票据重放被拒；org 内部接口仅接受有效服务 JWT（直连伪造被拒）。

**参考文档**：《[架构设计 · 核心交互时序](../../../设计/架构设计/06_架构设计_核心交互时序.md)》、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》「接口清单」「错误码」节、《[API接口规范](../../../规范/API接口规范.md)》、阶段二 04-1-1 前端网关接入改造（**前端寻址与 401 钩子已交付**）

## 5. 需求 01-4：会话管理与强制踢出 <a id="r01-4"></a>

优先级：2（高）

**背景与动机**：会话管理是「踢出即时生效」与多端登录治理的载体：只有 Redis 会话标记才能让已签发的 access 在下一请求即被拦截（JWT 无状态本身无法即时吊销）。MVP 验收明确要求「会话强制踢出即时生效、账号锁定与手动解锁可用」，本期必须先落地后端会话能力。

**内容**（《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§3）：

1. **会话记录**：`sys_session` 落库（`refresh_token_hash` / 设备 / IP / `login_at` / `expires_at` / `revoked_at`），表文件先设计后落库（《[数据库开发规范](../../../规范/数据库开发规范.md)》口径）。
2. **Redis 会话标记**：`bms:{tenant}:sess:{session_id}`（TTL 与 refresh 对齐）；每请求校验链 = 验签 → 类型校验 → 会话标记存在性 →（可选）设备 / IP 一致性；每请求一次 Redis 读。
3. **强制踢出**：删 Redis 标记 + 吊销 refresh + `revoked_at` 落库，HTTP 侧下一请求即拦截（即时生效）；「谁踢的 / 何时」入操作日志占位与结构化日志；Socket.IO 广播经 `BaseRealtimePublisher` 占位（阶段八接真实实现）。
4. **多端会话**：允许并发登录，活跃会话数上限默认 5（`sys_config` 可配，超限自动作废最旧会话）。
5. **会话接口**：在线会话列表 / 详情 / 强制踢出（`session:query` / `session:kick` 权限码占位，RBAC 就绪前按平台超管口径）；会话管理页面归阶段十五（本期只交付接口与证据）。
6. **黑名单协同**：踢出 / 登出的 refresh 黑名单与 JWKS 校验源切换（01-2）协同生效。

**完成标准**：踢出后目标会话下一请求即 401（不等 access 自然过期）、refresh 不可用；多端上限生效（第 6 次登录作废最旧会话）；会话记录与 Redis 标记一致（登出 / 过期 / 踢出三路径清理正确）；`revoked` 状态落库；用例覆盖踢出即时性 / 上限 / 幂等分支。

**参考文档**：《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§3、《[架构设计 · 实时推送](../../../设计/架构设计/18_架构设计_子系统_实时推送.md)》（广播占位口径）

## 6. 需求 01-5：登录态依赖真实化与租户解析接线 <a id="r01-5"></a>

优先级：2（高）

**背景与动机**：后端 `require_auth` 目前恒定放行（占位），服务目录、插件、图标、打印、AI 等大量「登录即可」路由实际上处于敞开状态；租户解析也未接 token 兜底，网关注入的租户身份与全局租户中间件尚未闭环。这既是安全缺口，也阻塞阶段七 RBAC 的权限校验挂接。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§7、《[架构设计 · 多租户路由](../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》、《[后端基类清单](../../../后端基类清单.md)》「鉴权依赖占位」条目）：

1. **`require_auth` 真实实现**：解析网关注入的可信身份（`X-User-Subject` / `X-Tenant-Id`，边缘信任已交付）或本地校验 Bearer token；失败抛认证错误 `20001` / 401；成功写请求上下文（用户标识 / 租户 / 会话）。
2. **受保护路由统一切换**：全部「登录即可」路由（服务目录、插件、检索、图标、打印、AI 等）切换为真实登录态依赖，冒烟回归确认无遗漏。
3. **租户解析接线**：请求上下文租户优先取网关身份头，其次校验 token 内 `tenant_id` 兜底；全局租户中间件豁免路径（健康检查 / 公开认证端点）与判决口径保持一致；会话 / 缓存键按租户前缀隔离。
4. **错误码落地**：认证错误码段实现与用例（`AuthError` 20001 等），错误响应不泄露内部细节。
5. **口径回写**：《[后端基类清单](../../../后端基类清单.md)》「鉴权依赖占位」状态与《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》协调节回写。

**完成标准**：未携带 / 携带无效 token 访问受保护接口返回 401；有效登录态下请求上下文用户与租户正确（跨租户访问被拒）；既有服务端用例（含受保护路由）在真实鉴权下回归全绿；租户解析链三来源（身份头 / token / 显式入参）用例覆盖。

**参考文档**：《[后端基类清单](../../../后端基类清单.md)》「鉴权依赖占位」条目、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§8、《[架构设计 · 多租户路由](../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》

## 6. 需求 01-6：当前用户概要端点（`GET /auth/me`） <a id="r01-6"></a>

优先级：2（高）｜**补充需求**（2026-10-02 立项）

**背景与动机**：需求 [05-2](05_需求_登录前端.md#r05-2) 要求「刷新页面后首屏静默续期（先 refresh 再放行受保护请求）」，但 `POST /auth/refresh` 的响应（`RefreshResult`）只含新 access 与有效期，**不含用户概要**；identity 公开契约中亦**没有「当前用户」端点**。结果是刷新页面后只能恢复访问令牌与租户标识，**用户概要与强制改密标记丢失**（顶栏用户信息为空），登录态无法真正恢复。本需求补建当前用户概要端点，供首屏恢复复用，并作为个人中心、权限装载与后续 RBAC 前的主体信息来源。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §3、《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节）：

1. **端点**：identity 新增 `GET /api/v1/auth/me`（受登录态保护，`require_auth`），返回统一响应包装的 `UserSummary`（`id` / `username` / `name` / `tenant` / `locale` / `timezone` / `must_change_password`）——**与登录响应同字段、同语义**。
2. **改密标记同源**：`must_change_password` 取用户行的强制改密标记（与登录经凭据校验所得 `pwd_reset_required` 同源）；org 内部 `users/profile` 响应补该字段（新增字段，非破坏）。
3. **数据通路**：经现有服务间客户端（org 内部用户接口）按用户主键取概要，出站附自签服务 JWT 与租户位；下游不可达按 `10007` / 503 fail-closed，不降级为「未登录」。
4. **失败语义**：用户不存在或账号非启用 → 按**登录态失效**处理（`20001` / 401），前端据统一 401 路径清会话并跳登录；错误响应不泄露内部细节。
5. **契约与类型**：新端点进入 identity 公开契约快照与 oasdiff 基线；前端 `@bms/api-types` 重生成，首屏恢复按生成类型消费（不手写重复类型）。

**完成标准**：有效登录态下 `/auth/me` 返回与登录响应一致的用户概要（含强制改密标记）；未登录 / 用户不存在 / 账号停用均返回 401；org 内部 `users/profile` 响应含 `pwd_reset_required`；新端点进入公开契约且契约四道门禁全绿；前端生成类型含 `/auth/me` 且零漂移；用例覆盖成功与三类失败分支。

**参考文档**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §3 / §7、[需求 01-3](01_需求_认证与会话.md#r01-3)、[需求 05-2](05_需求_登录前端.md#r05-2)、《[后端开发规范](../../../规范/后端开发规范.md)》「契约与门禁」节。

## 7. 需求 01-7：会话续期真实可用与登录入口可达性（refresh cookie 作用域 / 账号种子 / 宿主边界） <a id="r01-7"></a>

优先级：1（高）｜**补充需求**（2026-10-04 立项）

**背景与动机**：阶段七 `03_01` 排查「启动全套看不到登录界面」时，实测发现三处**阻断登录可用性**的缺口（前两处已登记[计划 §7 第 50 / 29 项](../计划/01_计划_认证与安全.md#followup)）：

1. **refresh cookie 作用域与浏览器可见路径不一致**：常量 `REFRESH_COOKIE_PATH = "/api/v1/auth"`（`services/identity/src/bms_identity/schemas/auth.py`）写的是**服务内**路径，而浏览器地址是网关**外部**路径 `/api/{service_key}/v1/...`（如 `/api/identity/v1/auth/refresh`）。浏览器按 cookie `Path` 前缀匹配回传 ⇒ 该 cookie **从不回传**，硬刷新 / 重开页面时 `/auth/refresh` 恒 401「缺少刷新令牌」，[需求 05-5](05_需求_登录前端.md#r05-5)「记住我」的续期价值在真实浏览器中**从未生效**；Vite dev proxy（`apps/desktop/vite.config.ts` 纯透传）与 APISIX 网关（`deploy/gateway/apisix.yaml` 仅 `proxy-rewrite` 改请求路径、边缘 nginx 亦无 `proxy_cookie_path`）**都不改写** Set-Cookie。
2. **任一模块加载 / 渲染失败顶掉所有路由内容**：`ModuleBoundary` 包在 `App.vue` 的 `router-view` 外层、模块错误态为**全局单例** ⇒ 模块产物服务（5002）未起时 `remoteEntry.js` 拉取失败，**连免登录的 `/login` 也被错误页顶掉**（实测：裸起前端 dev 时 `/login` 无登录表单，只有「模块加载失败 + 重试」）。
3. **没有任何可用账号**：`ops/` 只有租户 / 字典 / 参数 / 菜单 / 模块 / OIDC / SSO 种子，**从未建过用户**；唯一建号入口是 org 内部接口（`/org/internal/users/create`，供 SSO JIT 与未交付的用户管理用），且 JIT 建号落**占位口令**（`!sso`，本地登录恒不通过）⇒ 任何环境都建不出本地可登录账号，真实浏览器端到端回归**无载体**（[计划 §7 第 34 项](../计划/01_计划_认证与安全.md#followup) 亦因此改归口）。另 [计划 §7 第 29 项](../计划/01_计划_认证与安全.md#followup)（`VITE_AUTH_GUARD=off` 时会话就绪无人触发 → 停在骨架屏）同属登录入口可达性。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2 / §3、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[安全开发规范](../../../规范/安全开发规范.md)》、《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节）：

1. **refresh cookie 路径与浏览器可见路径对齐**：`REFRESH_COOKIE_PATH` 由服务内路径改为 **`"/"`**——浏览器只做 Path 前缀匹配，`/` 与「外部路径形态」（网关 shape / 部署形态）**彻底解耦**、dev 与生产同形；`HttpOnly` / `Secure`（`[login].cookie_secure`）/ `SameSite=Lax` 口径**全部不变**（仅作用域放宽，跨站 POST 仍由 `SameSite=Lax` 拦截）。
2. **登出双 Path 清理（迁移兼容）**：`clear_refresh_cookie` 同时按新路径（`/`）与历史路径（`/api/v1/auth`）下发删除，避免浏览器残留旧作用域 cookie（历史 cookie 虽已惰性不可用，但清理面须干净）。
3. **首个可用账号种子**：新增 `ops/seed_user.py`（照 `ops/seed_tenant.py` / `ops/seed_menu.py` 范式：`--url` / `--tenant` / `--username` / `--dry-run` / 幂等 / 打印新增跳过的行数），在**目标租户的 org 租户库**建或重置账号——口令经 `Pbkdf2PasswordHasher`（`[password_hasher]` 插件口径，自描述串）生成，并置 `status=enabled` / `pwd_changed_at` / `pwd_reset_required=False`；`--reset-password` 重置既有账号口令（同步清零 `failed_count` / `locked_until`）。该脚本仅作**运维建号 / 联调**入口，不进任何业务链路；生产首建账号须满足《安全开发规范》口令强度要求，脚本不落明文口令入库、只在标准输出一次性打印。
4. **模块加载失败不得阻断免登录 / 基础路由**：模块错误态（`ModuleBoundary`）只影响**归属该失败模块**的路由；`/login`、`/403`、`/404`、`/500` 等免登录与基础路由**永不受影响**（模块产物服务不可用时仍能正常登录、正常看错误页）；**当前路由自身渲染失败**仍按既有口径渲染错误页。
5. **守卫未装配时的会话就绪兜底（§7 第 29 项）**：`VITE_AUTH_GUARD=off`（或任何未装配守卫的宿主）仍须触发一次会话就绪判定，应用**不停在骨架屏**。
6. **真机浏览器端到端回归**：真实浏览器在**远端开发环境**跑「建号 → 登录 → 硬刷新静默续期（不回登录页）→ 记住我两分支 → 登出（cookie 双 Path 清空）」并留证（截图 / 网络证据）。
7. **契约与文档口径**：cookie 属**响应头**、不进 OpenAPI 契约（契约版本**不升**、oasdiff 基线不动、`api-types` 无需重生成）；设计口径回写 [需求 01-3](01_需求_认证与会话.md#r01-3) 相关的 `01_03` / `02_01`（SSO 回调同源常量）/ `02_03` 设计与 [需求 05-5](05_需求_登录前端.md#r05-5)「`Path` 收敛不变」表述，以及部署说明中的 cookie 口径。
8. **用例与门禁**：后端断言 Set-Cookie 的 `Path` 值与登出双清；前端覆盖「模块加载失败不顶免登录页」与「守卫关闭不卡骨架屏」；`ops/seed_user.py` 幂等（重复执行新增为 0）；契约 / 静态 / 类型 / 覆盖率门禁全绿。

**完成标准**：真实浏览器「登录 → 硬刷新 → **不跳登录页**（静默续期成功）」；`remember_me` 两分支的 `Max-Age` 与续期行为符合[需求 05-5](05_需求_登录前端.md#r05-5) 口径；登出后浏览器**两个 Path 的 cookie 均被清除**；模块产物服务未起时 `/login` 仍渲染登录表单；`VITE_AUTH_GUARD=off` 时不卡骨架屏；用 `ops/seed_user.py` 建出的账号在远端开发环境可正常登录；定向用例与门禁全绿。

**参考文档**：[需求 01-3](01_需求_认证与会话.md#r01-3)（登录 / 刷新 / 登出链路）、[需求 05-5](05_需求_登录前端.md#r05-5)（记住我）、[需求 06-2](06_需求_契约与模块请求能力.md#r06-2)（模块请求能力）、[计划 §7 第 50 / 34 / 29 项](../计划/01_计划_认证与安全.md#followup)、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》、《[安全开发规范](../../../规范/安全开发规范.md)》
