## 1. 域说明 <a id="intro"></a>

本域把阶段二交付的**脱敏基座占位**落为真实能力（规则分派 / 序列化自动掩码 / 日志与导出脱敏），并收口认证相关的**基础防护与安全基线**（响应头、生产关闭 Swagger、密钥管理复核、安全专项用例与覆盖率门槛），使阶段六交付物整体满足《[安全开发规范](../../../规范/安全开发规范.md)》与《[测试规范](../../../规范/测试规范.md)》的安全侧要求。

- **本域范围**：脱敏基座真实实现；脱敏接入（序列化 / 日志 / 导出）与明文权限口径；基础防护与密钥管理落地；安全专项用例与认证模块覆盖率门槛。
- **不重复建设**：`BaseMasker` 契约（阶段二 `02-3-05`）、`BaseSchema.masked_fields` 字段约定、nginx 安全响应头与限流基座（阶段一 / 二部署与基座交付）均为已交付产物；本域只做**真实实现、接线与核验**。
- **已定口径**（2026-09-26 拍板）：脱敏本期落**规则 + 序列化 / 日志 / 导出接入**；RBAC（阶段七）就绪前 `data:plain` 按「无权限码一律掩码」执行，明文判定接口预留、阶段七接真实权限校验。
- **依据**：《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》§3「安全架构」、《[安全开发规范](../../../规范/安全开发规范.md)》、《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》、《[后端基类清单](../../../后端基类清单.md)》「数据脱敏」条目。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 04-1：脱敏基座真实实现 <a id="r04-1"></a>

优先级：2（高）

**背景与动机**：`NullMasker` 原样返回，敏感字段（手机号 / 身份证 / 邮箱 / 银行卡 / 姓名）在接口、日志、导出中全部明文；这既违反《安全开发规范》「敏感数据出接口必须脱敏」，也让安全专项用例「脱敏泄露」无从落地。真实实现是域 03-3 短信手机号回显、域 04-2 序列化接入的共同前置。

**内容**（《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「数据安全」节、《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》）：

1. **规则分派**：按字段类型（手机号 / 身份证 / 邮箱 / 银行卡 / 姓名 / 地址等）内置掩码规则（如 `138****5678`、保留首尾），规则可配置化。
2. **自定义规则**：支持注册自定义掩码规则（字段名或标记驱动），规则冲突与优先级口径成文。
3. **明文揭示**：`reveal` 能力实现（受权限约束的明文读取路径），判定接口预留（`data:plain` 权限码，RBAC 就绪后接真实权限校验；本期无权限码一律不解掩码）。
4. **口径回写**：《[后端基类清单](../../../后端基类清单.md)》「数据脱敏」占位状态更新；规则清单与示例在实现侧文档登记（架构节点不写实现细节）。

**完成标准**：各类型掩码结果符合规范示例；`reveal` 在无权限时拒绝、有权限（测试注入）时返回明文；自定义规则注册 / 优先级用例通过；掩码纯函数单元用例全绿。

**参考文档**：《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「数据安全」节、《[安全开发规范](../../../规范/安全开发规范.md)》「敏感数据与脱敏」节、《[后端基类清单](../../../后端基类清单.md)》「数据脱敏」条目

## 3. 需求 04-2：脱敏接入与明文权限口径 <a id="r04-2"></a>

优先级：2（高）

**背景与动机**：只有把脱敏接到**响应序列化、日志、导出**三条出路上，敏感数据才真正不泄露；若只在工具层实现而响应仍走原值，等于没做。同时 `data:plain` 依赖阶段七 RBAC，需明确过渡期口径避免「等权限就绪再脱敏」的空窗。

**内容**（《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「数据安全」节、《[后端基类清单](../../../后端基类清单.md)》`BaseSchema.masked_fields` 约定）：

1. **序列化自动掩码**：`BaseSchema.masked_fields` 标记字段在序列化层默认掩码，支持嵌套模型与列表；标记与数据库字段（或业务标记）单一来源，不重复声明。
2. **日志脱敏**：结构化日志过滤器对敏感键（密码 / token / 密钥 / 手机号等）掩码，`ai_chat_log` 落库前消费同口径（占位接线，真实入库归对应阶段）。
3. **导出脱敏**：导入导出框架的导出路径走脱敏（阶段四前端导入导出件的后端契约对齐）；导出大文件记录审计占位。
4. **明文口径**：`data:plain` 判定经 `BasePermissionChecker` 预留点；**RBAC 就绪前该权限码不存在 → 一律掩码**；阶段七接入后按权限码放行（口径登记消费方）。
5. **既有场景回接**：短信手机号回显（域 03-3）、SSO / 会话接口中的用户标识按本域规则输出。

**完成标准**：带标记字段的响应全部掩码（含嵌套 / 列表用例）；日志与导出无敏感明文（安全专项用例如实断言）；无权限码时 `data:plain` 静默不生效；口径与阶段七依赖登记在案。

**参考文档**：《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》「数据安全」节、《[安全开发规范](../../../规范/安全开发规范.md)》「敏感数据与脱敏」节、《[后端基类清单](../../../后端基类清单.md)》

## 4. 需求 04-3：基础防护与密钥管理落地 <a id="r04-3"></a>

优先级：3（中）

**背景与动机**：安全响应头、生产关闭 Swagger、密钥只走环境变量是《安全开发规范》的硬性基线；阶段一 / 二的部署件与 nginx 配置已部分就位，但从未按认证阶段口径核验（JWT 密钥来源、轮换、生产文档端点关闭）。本项做**核验 + 补齐**，把基线变成可复查的证据。

**内容**（《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》§3「基础防护」「密钥管理」节、《[安全开发规范](../../../规范/安全开发规范.md)》）：

1. **安全响应头**：核验 nginx 统一配置（CSP / HSTS（dev 关）/ `X-Frame-Options` / `X-Content-Type-Options` / `Referrer-Policy` / `Permissions-Policy`），缺口补齐。
2. **文档端点**：生产环境关闭 Swagger / ReDoc，契约走 CI 导出快照（`deploy/contracts/`）口径核验。
3. **密钥管理**：JWT / 服务令牌密钥只走环境变量与 Secret（不入库 / 不入镜像 / 不落日志）；密钥轮换流程（新旧并行验证期）与 `[security]` 配置定稿（域 01-1）配合核验；`deploy/.env.example` 键位同步。
4. **CI 安全扫描**：依赖漏洞扫描既有 job 口径核验（高危阻断），镜像扫描（Trivy）与 SBOM 归部署阶段但在 CI 配置中确认挂点存在。

**完成标准**：响应头按环境差异正确（dev 关 HSTS）；生产文档端点关闭；密钥来源检查（grep 无硬编码 / 无入库）通过；`.env.example` 键位与实现一致；核验结论登记（证据可复查）。

**参考文档**：《[架构设计 · 性能与安全](../../../设计/架构设计/31_架构设计_性能与安全.md)》§3、《[安全开发规范](../../../规范/安全开发规范.md)》「密钥与配置安全」节、《[开发部署规划](../../../规划/开发部署规划.md)》

## 5. 需求 04-4：安全专项用例与覆盖率门槛 <a id="r04-4"></a>

优先级：2（高）

**背景与动机**：《测试规范》要求安全专项覆盖「越权 / 注入 / XSS / 上传绕过 / 限流爆破 / 脱敏泄露 / 会话劫持」，且核心模块（含认证）覆盖率 ≥80%；阶段一遗留「认证 / 权限 / 越权类用例待阶段六」与「核心模块覆盖率门槛待接入」。不落专项用例与门槛，M6 与准出标准都缺证据。

**内容**（《[测试规范](../../../规范/测试规范.md)》「安全专项」「覆盖率」节、《[架构设计 · 测试与质量](../../../设计/架构设计/32_架构设计_测试与质量.md)》）：

1. **安全专项用例**：围绕本阶段能力补齐——登录限流爆破（含验证码强制）、脱敏泄露（响应 / 日志 / 导出）、会话劫持（伪造 / 过期 / 踢出后重放）、越权（跨租户 / 跨用户访问受保护接口）、认证注入（参数化与输入校验核验）；用例先登记 Kiwi 再落代码。
2. **覆盖率门槛**：认证模块（identity 服务与认证相关路径）行覆盖率 ≥80%，接入 CI 覆盖率门禁（按路径子阈值）；基线快照与门槛口径成文。
3. **CI 挂接**：安全专项与认证覆盖率随 CI 流水线执行（全绿为准出证据）；失败自动缺陷单沿用既有机制。
4. **证据归档**：用例执行结果与覆盖率快照入阶段测试报告（域 07-1）。

**完成标准**：七类安全专项均有用例且执行通过（Kiwi 编号登记）；认证模块覆盖率 ≥80% 并在 CI 生效；门槛接入的流水线证据（job 输出）归档。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》「安全专项」「覆盖率门禁」节、《[架构设计 · 测试与质量](../../../设计/架构设计/32_架构设计_测试与质量.md)》、《[安全开发规范](../../../规范/安全开发规范.md)》「检查清单」节
