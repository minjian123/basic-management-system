## 1. 域说明 <a id="intro"></a>

本域把阶段二交付的验证码 / 密码策略**占位契约**落为真实能力（图形 / 滑块 / 短信三形态出题与判定），并补齐**账号治理**（密码策略强制、找回密码、账号锁定与解锁），是登录链路（域 01-3）的安全前置与 MVP 验收「策略强制生效」的直接承载。

- **本域范围**：图形验证码真实出题与校验；滑块挑战（服务端合成出图 + 轨迹判定）；短信验证码（脱敏回显 / 冷却频次 / 通道占位）；场景策略与失败计数（按租户 `sys_config`、连续失败强制）；密码策略（复杂度 / 90 天 / 近 5 次历史 / 180 天不活跃）；找回密码；账号锁定与解锁管理。
- **不重复建设**：`BaseCaptcha` / `BasePasswordPolicy` 契约与渠道扩展（三形态枚举 / 场景五项 / 策略契约 / 一次性凭证 / 占位路由）为阶段二 `02-3-07` / `02-3-14` 已交付产物；本域只做**真实实现与接线**，不新建契约、不另起编号空间。
- **已定口径**（2026-09-26 拍板）：滑块**服务端合成出图、不下发缺口坐标**（前端只提交轨迹，前端 `06_04` 契约同步微调）；Redis 不可用时验证码 **fail-closed 拒绝**；登录日志本期不落表（失败计数 Redis + `sys_account_lock`）；账号锁定后端全做、管理页面归阶段七；找回密码做 token 流程、发送通道占位；180 天扫描落服务方法 + 手动触发，Celery 定时归阶段八。
- **依据**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[后端基类清单](../../../后端基类清单.md)》「验证码渠道」「密码策略」条目、需求 `02-31` / `02-42` 实现期要点。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 03-1：图形验证码真实实现 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：登录失败 3 次强制图形验证码是防爆破的第一道闸；现状 `NullCaptcha` 恒定通过、出图为空串，前端验证码字段只能显示占位（阶段四 `06_04` 已冻结四端点契约与 HTTP 数据源）。不落真实出题与一次性校验，M6 的「策略强制生效」与安全专项用例（限流爆破 / 验证码绕过）都无从验收。

**内容**（需求 `02-31` / `02-42` 实现期要点、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5）：

1. **真实出题**：Pillow 生成图形码（干扰线 / 噪点 / 字符变形等基础抗识别处理），经线程池执行避免阻塞事件循环；图片以 base64 返回（沿用四端点契约，形态定稿不扩字段）。
2. **一次性校验**：挑战存 Redis `bms:global:captcha:{uuid}`（TTL 5 分钟），`verify` 比对**大小写不敏感**、成功后立即删除（单次有效）、失败可重试但计入失败计数。
3. **接口兼容**：`/api/v1/captcha/challenges`、`/verify` 四端点契约与响应字段保持阶段二冻结形态（只增不删）；错误语义落 `20101` ~ `20103` 子段。
4. **降级口径**：Redis 不可用时出题 / 校验 **fail-closed**（明确报错并提示稍后重试），不放行不降级。
5. **口径回写**：`BaseCaptcha` 占位状态在《[后端基类清单](../../../后端基类清单.md)》更新（真实实现部分交付）。

**完成标准**：出图非空且可人工识别；正确码校验通过且挑战单次失效（二次使用被拒）；错误码返回 `20101` 子段并计数；Redis 不可用 fail-closed 用例通过；Pillow 出图与 Redis 存取集成用例（真 Redis）全绿。

**参考文档**：需求 `02-31` / `02-42` 实现期要点（[阶段一后端基座需求](../../01_项目骨架/需求/02_需求_后端基座.md)）、《[后端基类清单](../../../后端基类清单.md)》「验证码渠道」条目

## 3. 需求 03-2：滑块挑战真实实现 <a id="r03-2"></a>

优先级：3（中）

**背景与动机**：滑块是图形码之外的挑战形态（移动端与体验场景主用），现状同为占位；且前端已按 `{background, gap_x, gap_y, width, height}` 冻结待定稿。为避免「缺口坐标直接下发被机器人利用」，2026-09-26 拍板**服务端合成出图、不下发坐标**，前端只提交轨迹——需要真实实现与契约微调同步落地。

**内容**（需求 `02-42` 实现期要点、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5）：

1. **服务端合成出图**：服务端生成带缺口背景图与滑块块图（合成后返回，**不含 `gap_x` / `gap_y` 坐标**），挑战（缺口位置）存 Redis；`payload` 字段承载出图数据（`background` / `slider` / `width` / `height`），坐标字段移除。
2. **轨迹判定**：接收前端轨迹凭证（`[[x, y, 相对起点毫秒], …]`，沿用冻结形态），按终点落点容差（`SLIDER_TOLERANCE`）与轨迹合理性（时间分布 / 采样点）判定；判定后单次失效。
3. **失败与复位**：失败返回 `20102` 子段并计数（计入场景失败计数），前端自动刷新出题（域 03-4 联调）。
4. **契约微调协同**：前端 `06_04` 滑块件按新 `payload` 形态调整渲染（不再自绘缺口坐标）；契约变更登记消费方（前端验证码字段）。

**完成标准**：滑块出图正常（背景含缺口 + 滑块块图）、坐标不出现在任何响应；轨迹正确通过、错位 / 机器轨迹被拒；判定后单次失效；前端件按新 payload 渲染并完成一次联调（Kiwi 登记）。

**参考文档**：需求 `02-42` 实现期要点、阶段四 [06_04 验证码字段](../../04_前端组件库/任务/06_字段类/06_字段类_04_验证码字段/06_字段类_04_验证码字段.md)（**前端契约调整消费方**）

## 4. 需求 03-3：短信验证码真实实现 <a id="r03-3"></a>

优先级：3（中）

**背景与动机**：短信验证码用于登录 / 找回密码 / 绑定手机等场景；现状为「不真发、恒定通过」。短信模板与渠道实现属阶段八通知能力，本期需先落**出题 / 校验 / 脱敏回显 / 冷却频次**逻辑，发送经通知基座占位（阶段八接入真实渠道后自动生效）。

**内容**（需求 `02-42` 实现期要点、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5）：

1. **下发与校验**：生成短验证码存 Redis（TTL 300s），经 `BaseNotifier` 通知基座发送（本期占位实现不真发，接口契约不变）；校验一次性、失败计数。
2. **脱敏回显**：响应目标手机号一律脱敏（`138****5678`，改经域 04 脱敏基座）；不回显验证码本身。
3. **冷却与频次**：重发冷却 60s、按账号 / IP 维度限次（经限流基座，Redis 计数）；冷却期内重复请求返回明确提示且不重置倒计时。
4. **降级口径**：Redis 不可用 fail-closed；通知渠道不可用时明确报错（不静默放行）。

**完成标准**：短信出题落 Redis、校验一次性；目标脱敏、冷却与限次生效（用例覆盖「限流命中不重置倒计时」）；通知基座占位下流程可跑通、接口契约与阶段八真实渠道对齐；错误子段 `20103` 生效。

**参考文档**：需求 `02-42` 实现期要点、《[后端基类清单](../../../后端基类清单.md)》「通知渠道基座」「验证码渠道」条目、阶段四 06_04（前端短信件契约）

## 5. 需求 03-4：验证码场景策略与失败计数 <a id="r03-4"></a>

优先级：2（高）

**背景与动机**：三类验证码共用「场景 → 是否强制、失败阈值、有效期、重发冷却」的策略口径，策略需按租户下发、缺省回落平台默认；同时「连续失败 N 次强制」必须由认证流程落地，否则验证码只是可选装饰，防爆破形同虚设。

**内容**（需求 `02-42` 实现期要点、《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》）：

1. **场景策略**：五场景（登录 / 找回密码 / 绑定手机 / 解绑手机 / 注册）策略从 `sys_config` 按租户读取，缺省回落平台默认表；策略变更即时生效（读取带缓存失效）。
2. **失败计数与强制**：登录失败计数落 Redis（窗口 TTL），连续失败达阈值（默认 3）后强制要求验证码；成功登录清零；计数与账号锁定（域 03-7）联动。
3. **策略端点**：`/captcha/scenes/{scene}/policy` 按当前租户返回策略（前端按策略渲染）；渠道不可用（如短信通道未配）时的降级顺序成文（图形码兜底）。
4. **前端联调**：阶段四 `06_04` 验证码字段对接真实四端点（替换占位数据源），滑块 `payload` 新形态（域 03-2）同步落地；核对页与错误码文案更新。

**完成标准**：策略按租户读取、缺省回落、变更即时生效；连续失败 3 次后登录强制验证码（用例覆盖失败计数窗口与清零）；前端四端点真实联通（图形 / 滑块 / 短信各一次端到端），滑块新 payload 渲染正确；错误码 `201xx` 文案与前端契约一致。

**参考文档**：《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》、需求 `02-31` / `02-42` 实现期要点、阶段四 [06_04 验证码字段](../../04_前端组件库/任务/06_字段类/06_字段类_04_验证码字段/06_字段类_04_验证码字段.md)

## 6. 需求 03-5：密码策略真实实现 <a id="r03-5"></a>

优先级：2（高）

**背景与动机**：`NullPasswordPolicy` 恒定通过，密码合规检查名存实亡；M6 验收明确「密码策略强制生效」（复杂度、90 天有效期、近 5 次历史、180 天未登录锁定），这是审计合规（等保 / PIPL）的直接要求。

**内容**（需求 `02-31` 实现期要点、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》「密码策略」节）：

1. **复杂度校验**：长度 / 大小写 / 数字 / 符号 / 不得含用户名，规则从 `sys_config` 读取，返回缺失项清单（`PASSWORD_VIOLATIONS`），供前端强度提示（只展示等级与缺失项，不回显密码）。
2. **有效期与历史**：`pwd_changed_at` 驱动 90 天强制改密判定（`pwd_reset_required`）；`pwd_history` 近 5 次历史密码 PBKDF2 比对不可重复。
3. **180 天不活跃**：按 `last_login_at` 扫描的服务方法 + 手动触发入口（Celery 定时任务归阶段八），命中写 `sys_account_lock`（`inactive` 型）。
4. **接线**：改密 / 重置路径（找回密码域 03-6 与 org 内部接口）强制过策略；登录成功后按判定置 `pwd_reset_required`。
5. **口径回写**：《[后端基类清单](../../../后端基类清单.md)》「密码策略」占位状态更新。

**完成标准**：复杂度 / 90 天 / 近 5 次历史 / 180 天扫描四规则均有正反用例；改密与重置路径强制过策略；`sys_config` 变更即时生效；`pwd_history` 追加与比对正确。

**参考文档**：需求 `02-31` 实现期要点、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》、《[后端基类清单](../../../后端基类清单.md)》「密码策略」条目、《[安全开发规范](../../../规范/安全开发规范.md)》

## 7. 需求 03-6：找回密码流程 <a id="r03-6"></a>

优先级：3（中）

**背景与动机**：找回密码是登录可用性的兜底路径；架构要求「token 存 Redis（TTL 15 分钟、单次有效）+ 限流防滥用 + 重置后强制失效全部会话」。邮件与企微 / 钉钉发送通道属阶段八通知能力，本期先落流程与校验，通道经基座占位。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》）：

1. **流程接口**：发起找回（账号 / 手机 / 邮箱取通道）→ 验证码校验（域 03-4 策略）→ 生成重置 token 存 Redis（15 分钟、单次有效）→ 重置密码（强制过密码策略域 03-5）→ 全部会话失效。
2. **限流防滥用**：每账号 1 次 / 5 分钟、每 IP 5 次 / 小时（经限流基座）；命中返回明确提示。
3. **发送通道**：经 `BaseNotifier` 占位发送（邮件 / 企微 / 钉钉通道真实实现归阶段八，接口契约对齐）；不回显 token 与验证码。
4. **安全口径**：重置 token 单次有效、重置后 refresh 黑名单 + 会话标记清理即时生效；响应不泄露账号是否存在。

**完成标准**：找回 → 校验 → 重置 → 会话全失效全链路可用（真实渠道到位前以占位通道验证）；token 单次有效、过期失效、限流阈值各有用例；重置后原会话下一请求即 401。

**参考文档**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》、《[后端基类清单](../../../后端基类清单.md)》「通知渠道基座」条目

## 8. 需求 03-7：账号锁定与解锁管理 <a id="r03-7"></a>

优先级：2（高）

**背景与动机**：MVP 验收要求「账号锁定与手动解锁可用」；锁定既是防爆破的处置手段（`fail_limit`），也承载合规扫描（`inactive`）与管理员处置（`manual`）。管理页面属阶段七用户管理，本期交后端能力与审计，供域 01-3 登录链路与阶段七页面复用。

**内容**（《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§5）：

1. **锁定记录**：`sys_account_lock` 落库（`lock_type`：`fail_limit` / `inactive` / `manual`；锁定原因 / 时间 / 操作人 / 解锁时间），用户状态字段与锁定记录一致（org 服务库）。
2. **自动锁定**：登录失败达阈值触发 `fail_limit`（15 分钟窗口口径与限流协同）；180 天未登录扫描触发 `inactive`（域 03-5）。
3. **手动解锁**：解锁接口（`user:unlock` 权限码占位，RBAC 前平台超管口径）+ 锁定列表 / 详情接口；解锁恢复账号状态并留痕（操作日志占位 + 结构化日志）。
4. **登录联动**：被锁账号登录被拒（`20004` / `20005` 语义），锁定期满自动解锁或保持直到手动解锁的口径成文并与概要一致。
5. **页面归口**：锁定列表 / 解锁页面随阶段七用户管理（本期只交接口与 E2E 证据）。

**完成标准**：三型锁定均可产生且落库；手动解锁恢复登录且留痕；被锁账号登录被拒；锁定 / 解锁并发与幂等分支用例通过。
