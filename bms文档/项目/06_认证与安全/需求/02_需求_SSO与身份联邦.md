## 1. 域说明 <a id="intro"></a>

本域把阶段二已交付的「OIDC 客户端（授权码 + JWKS 验签）」补齐为**完整 SSO 登录闭环**（授权码回调 / state / nonce / PKCE / JIT 建号 / 身份绑定），并扩展 CAS 兼容与企业微信 / 钉钉免登；同时交付 **BMS 兼作 IdP**（OIDC Provider）与租户级 IdP 配置管理，使 BMS 既是外部身份的消费者、也是其他系统的统一认证源。

- **本域范围**：SSO 登录链路（OIDC 完整链路 + 登录页 IdP 入口 + 异常分支 + 本地并存）；JIT 建号与 `sys_user_identity` 全局映射；CAS 兼容适配；企业微信 / 钉钉免登适配；BMS 兼作 IdP（OIDC Provider 内核 + `sys_client` 最小注册接口）；外部 IdP 配置管理（`sys_identity_provider` CRUD / 连通性测试）。
- **不重复建设**：OIDC 客户端内核（Discovery / 授权 URL / 换码 / userinfo / JWKS 验签，阶段二 `07_01`）、统一校验与服务 JWT（`07_02` / `07_03`）、`BaseIdentityProvider` 契约与 `IDP_PROTOCOLS` 常量均为已交付产物；本域只做**链路闭环、协议扩展与联邦治理**。
- **本期联调口径**（2026-09-26 拍板）：OIDC 以 Keycloak（开发环境已就位）真联调；CAS 以本地 mock CAS 服务联调；企业微信 / 钉钉交付适配与单元测试，**企业真实凭据联调与移动端内嵌 H5 免登留阶段十七**（凭据就绪可提前真跑）。
- **表归属**：`sys_user_identity` 平台库（全局身份映射，避免租户定位前无法查表）；`sys_identity_provider`、`sys_client` 租户库；`sys_user` 最小模型落 org 服务库（用户主数据归属）。
- **依据**：《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[后端基类清单](../../../后端基类清单.md)》「身份源」条目。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 02-1：SSO 登录链路（OIDC 授权码完整链路） <a id="r02-1"></a>

优先级：2（高）

**背景与动机**：阶段二交付了 OIDC 客户端的单个动作（授权 URL / 换码 / userinfo），但没有「登录页展示租户 IdP 入口 → 跳转 → 回调 → 建立 BMS 会话」的完整链路；M6 验收要求「本地 + SSO 登录链路 E2E 通过」，不闭环就无法验收，也无法验证本地应急通道与 IdP 故障降级并存。

**内容**（《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》「功能点 / 流程 / 接口清单」节、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4）：

1. **登录页入口数据**：`GET /auth/sso/providers`（免登录）按租户返回可用 IdP 列表（标识 / 名称 / 图标 / 类型），供登录页渲染入口。
2. **授权跳转**：`GET /auth/sso/{type}/authorize`——生成 `state` / `nonce` / PKCE `code_verifier` 并存 Redis（短 TTL 单次有效），重定向至外部 IdP 授权端点。
3. **回调闭环**：`GET /auth/sso/{type}/callback`——校验 `state`（一次性）、`nonce` 与 PKCE，换码 + 校验 ID Token，解析用户信息；经 JIT（域 02-2）定位 / 建立 BMS 用户后签发 BMS 双 token 并创建会话（复用域 01 链路）。
4. **异常分支**：IdP 不可达 / 配置缺失 / `state` 不匹配 / 用户被禁用时返回明确错误码与登录页提示；**外部 IdP 故障降级本地账号密码登录**（超管应急通道并存）。
5. **绑定与查看**：SSO 用户与本地账号的绑定关系可查（`sso:bind` 权限码占位）；本期内置 OIDC（Keycloak）真联调，其余协议由域 02-3 / 02-4 适配。

**完成标准**：经 Keycloak 完成一次完整 SSO 登录（入口 → 跳转 → 回调 → BMS 会话 → 访问受保护接口）E2E 通过；`state` / `nonce` / PKCE 校验失败与 IdP 故障降级分支各有用例（Kiwi 登记）；本地登录与 SSO 登录并存互不影响。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[架构设计 · 核心交互时序](../../../设计/架构设计/06_架构设计_核心交互时序.md)》「SSO 登录」节、阶段二 [07_01 OIDC IdP 接入](../../02_后端基座与服务化地基/任务/07_认证与服务身份/07_认证与服务身份_01_OIDC IdP 接入/07_认证与服务身份_01_OIDC IdP 接入.md)（**前置契约已交付**）

## 3. 需求 02-2：JIT 建号与身份映射 <a id="r02-2"></a>

优先级：2（高）

**背景与动机**：SSO 首次登录的用户在 BMS 中尚不存在，必须按外部身份自动建号（JIT）并建立「外部身份 → 租户 / 用户」的全局映射；若映射表与唯一约束不落地，并发首次登录会重复建号，M6 的「JIT 建号落库正确」也无从验收。

**内容**（《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4）：

1. **身份映射表**：`sys_user_identity` 落库（`idp_key` / `external_id` / `tenant_id` / `user_id`），`(idp_key, external_id)` 唯一约束防并发重复建号（表文件先设计后落库，平台库）。
2. **JIT 建号**：首次 SSO 登录经 **org 服务内部接口**创建 `sys_user` 最小模型记录（账号 / 状态 / 语言时区偏好；无本地密码或标记为 SSO 账号），随后写身份映射；同租户同外部身份二次登录命中映射直接登录。
3. **建号规则**：按 IdP 配置的租户归属与标识规则建号；用户名冲突处置（加后缀 / 拒绝）成文；JDIT 建号受「域名 / 租户白名单」校验（《安全开发规范》口径）。
4. **事件登记**：`identity.user.jit_created` 事件经 Outbox 登记（事件契约「只加不删」），供后续模块订阅。
5. **口径回写**：《[后端基类清单](../../../后端基类清单.md)》「身份源」条目与架构 14 §4 回写。

**完成标准**：首次 SSO 登录自动建号 + 写映射（落库可查）；并发 / 重复首次登录不产生重复用户（唯一约束 + 用例）；白名单外租户 / 域被拒；`identity.user.jit_created` 事件登记并经契约校验。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[后端基类清单](../../../后端基类清单.md)》「身份源」条目、《[数据库开发规范](../../../规范/数据库开发规范.md)》

## 4. 需求 02-3：CAS 兼容适配 <a id="r02-3"></a>

优先级：3（中）

**背景与动机**：存量政企 / 高校客户大量使用 CAS 协议 IdP，规划把「CAS 兼容」列为阶段六内容；阶段二仅交付 `BaseIdentityProvider` 契约（`IDP_PROTOCOLS` 含 CAS），真实适配待补。本项以「同一外部身份框架 + mock CAS 服务」联调，保证协议扩展不破坏 OIDC 主链。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》）：

1. **CAS 适配实现**：按 `BaseIdentityProvider` 契约实现 CAS 客户端（授权跳转 / 服务票据校验 / 用户属性解析），复用同一 SSO 登录链路（域 02-1）与 JIT 建号（域 02-2），不为 CAS 另建链路。
2. **票据校验**：CAS `serviceValidate` 响应解析、属性映射（账号 / 姓名 / 邮箱）、失败语义（票据无效 / 服务未注册 / IdP 不可达）。
3. **mock CAS 联调**：以本地 mock CAS 服务（测试夹具）完成端到端联调；真实 CAS IdP 联调归凭据就绪时（与域 02-4 同口径）。
4. **契约与用例**：协议实现登记进身份源插件族（`plugin_name` 命名与 `IDP_PROTOCOLS` 对齐），单元 / 集成用例覆盖成功与失败分支。

**完成标准**：mock CAS 服务下端到端 SSO 登录（含 JIT 建号）通过；票据无效 / 服务未注册 / IdP 不可达分支有明确错误语义与用例；OIDC 主链回归不受影响；`pytest`、`pyright`、`ruff` 通过。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[后端基类清单](../../../后端基类清单.md)》「身份源」条目、阶段二 07_01（CAS 占位与扩展口径）

## 5. 需求 02-4：企业微信 / 钉钉免登适配 <a id="r02-4"></a>

优先级：3（中）

**背景与动机**：规划把「企业微信 / 钉钉免登」列为阶段六内容（PC 扫码登录与移动端内嵌共用同一外部身份框架）；阶段二仅交付占位。若不实现适配，登录页扫码入口与后端免登回调没有落点，域 05-4 的扫码登录前端也无处对接。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》）：

1. **两适配实现**：企业微信 / 钉钉各按 `BaseIdentityProvider` 契约实现（授权跳转 / 换取用户身份 / 用户信息解析），复用 SSO 登录链路（域 02-1）与 JIT 建号（域 02-2）。
2. **PC 扫码形态**：支持 `snsapi_login`（企微）/ `snsapi_login`（钉钉）扫码登录；前端轮询与换取会话由域 05-4 对接。
3. **配置与校验**：企业应用凭据（`corp_id` / `agent_id` / `app_secret` 等）经 `sys_identity_provider` 配置与连通性测试（域 02-6）；凭据缺失时入口不可用并明确提示。
4. **联调口径**：交付适配与单元测试；**企业真实凭据联调与移动端内嵌 H5 免登留阶段十七**（凭据就绪可提前真跑）。

**完成标准**：两类免登适配可用（配置齐备时完成一次 PC 扫码登录 E2E，凭据未就绪以测试夹具 / 单测覆盖并登记遗留）；凭据缺失 / 用户未授权 / 状态失效分支有明确错误语义与用例；适配登记进身份源插件族。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§4、《[后端基类清单](../../../后端基类清单.md)》「身份源」条目

## 6. 需求 02-5：BMS 兼作 IdP（OIDC Provider + `sys_client` 最小注册） <a id="r02-5"></a>

优先级：2（高）

**背景与动机**：规划与 MVP 验收均要求「BMS 兼作 IdP、其他系统以 BMS 用户体系为统一认证源」；本项也是 BMS 自签用户令牌（域 01-2）的自然延伸——同一套密钥与用户体系对外发布 OIDC 能力。客户端注册管理页面属阶段十开放接口范围，本期先交内核与最小注册接口，避免与阶段十重复建设。

**内容**（《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》《[概要设计 · 开放接口管理](../../../设计/概要设计/20_概要设计_开放接口管理.md)》）：

1. **Provider 内核**：OIDC Discovery（`/.well-known/openid-configuration`）、JWKS、授权码流程（`/authorize` / `/token` / `/userinfo`）、ID Token 签发（复用用户令牌密钥体系，`kid` 与 `aud` 口径区分）；支持 PKCE。
2. **客户端注册**：`sys_client` 表落库（`client_id` / `client_secret` 哈希 / `redirect_uris` / `grant_types` / scope），提供**内部最小注册与管理接口**（创建 / 查询 / 启用停用 / 重置凭据；服务 JWT 鉴权或平台超管口径），管理页面归阶段十。
3. **令牌与撤销**：授权码单次有效短 TTL；客户端凭据独立撤销；签发审计经操作日志占位（`sys_open_log` 与开放接口鉴权归阶段十）。
4. **与外部 IdP 并存**：BMS 兼作 IdP 与「BMS 作为外部 IdP 客户端」两向能力互不冲突（同一 `BaseIdentityProvider` 契约族与自有 Provider 内核分列）。
5. **联调演示**：以测试客户端完成一次授权码流程 E2E（授权 → 换码 → userinfo），作为 M6「BMS 作 IdP 通过」证据。

**完成标准**：Discovery / JWKS 可访问且字段合规；测试客户端授权码流程 E2E 通过（PKCE 校验、授权码单次、scope 校验）；`sys_client` 注册 / 停用 / 重置经最小接口可用且落库；错误分支（非法 redirect_uri / 未知 client / 授权码重放）有用例。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[概要设计 · 开放接口管理](../../../设计/概要设计/20_概要设计_开放接口管理.md)》、《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[后端基类清单](../../../后端基类清单.md)》「开放接口服务端」条目（阶段十真实实现）

## 7. 需求 02-6：外部 IdP 配置管理 <a id="r02-6"></a>

优先级：3（中）

**背景与动机**：租户需要自助配置外部 IdP（Keycloak / AD / Authing / CAS / 企微 / 钉钉）；没有配置载体与连通性校验，SSO 只靠配置文件，无法多租户落地，登录页 IdP 入口也无数据来源。

**内容**（《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》「数据表 / 接口清单」节）：

1. **配置载体**：`sys_identity_provider` 落库（租户库）——协议类型（OIDC / CAS / 企微 / 钉钉）、`idp_key`、端点与客户端凭据（**密钥类字段只存引用 / 加密值，不明文入库**）、状态、排序。
2. **管理接口**：CRUD + 启用停用 + **连通性测试**（Discovery / 元数据探测或试授权），权限码 `idp:manage`（RBAC 就绪前平台超管口径）；配置变更写操作审计占位。
3. **登录页数据**：为域 02-1 的 `GET /auth/sso/providers` 提供按租户、按状态的入口清单（脱敏字段不出）。
4. **安全口径**：凭据字段响应永久掩码；连通性测试限流防滥用；配置校验（URL 协议 / 白名单）符合《安全开发规范》SSRF 要求。

**完成标准**：租户级 IdP 配置 CRUD / 启停 / 连通性测试可用；凭据字段任何响应不返明文；登录页入口清单按配置正确渲染；错误配置（端点不可达 / 缺字段）给出明确提示；用例覆盖密钥掩码与连通性分支。

**参考文档**：《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、《[安全开发规范](../../../规范/安全开发规范.md)》、《[数据库开发规范](../../../规范/数据库开发规范.md)》
