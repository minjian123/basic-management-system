## 1. 域说明 <a id="intro"></a>

本域收口四条工作：一是认证服务新增端点的**契约快照与前端类型生成**（保证前后端字段零漂移，「前端登录与按服务寻址联通」的类型基础）；二是**模块请求能力 `api` 注入与模块契约版本升 2**（《[微服务演进规划](../../../规划/微服务演进规划.md)》明确「随阶段六交付」，使前端模块经宿主请求层安全消费服务接口）；三是**服务契约路由覆盖护栏**（补充需求，2026-10-02 立项，防实现端点漏登或被人为隐藏出公开契约，适用全部启用服务）；四是**响应契约 schema 完整性修复与门禁**（补充需求 06-4，2026-10-02 立项，修复基座序列化模式 JSON Schema 塌陷致全部响应体 schema 为空、前端生成类型为 `unknown` 的缺陷，并补长效门禁，适用全部启用服务）。

- **本域范围**：认证契约快照与 `@bms/api-types` 重新生成（零漂移校验）；模块请求能力 `api` 注入 `ModuleHostContext`、契约版本升 2、demo / sample 双模块回归；服务契约路由覆盖护栏（实现路由 ⊆ 公开契约 `paths` + 不可见路由白名单断言，入 CI 与本地预检）；响应契约 schema 完整性修复（基座序列化模式 JSON Schema 以字段口径输出）+ 空 schema 门禁（`components.schemas` 无空对象、成功响应 schema 可解析且非空，入 CI 与本地预检）。
- **不重复建设**：服务段寻址与 9 份契约类型生成（阶段二 `04-1-1` 已交付）、模块契约与注册表基座（阶段四 `10_01` / `10_02`）、模块清单与发布治理（阶段五 `03_02`）均为已交付产物；本域只做**认证端点增量与模块请求能力增量**。
- **依据**：《[微服务演进规划](../../../规划/微服务演进规划.md)》（「模块契约新增请求能力 `api`，契约版本升 2，随阶段六交付」）、《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[前端基类清单](../../../前端基类清单.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 06-1：认证契约快照与前端类型生成 <a id="r06-1"></a>

优先级：2（高）

**背景与动机**：登录 / 刷新 / 登出 / SSO / 会话等端点（域 01、02）是阶段六新增的对外契约；若契约快照与前端类型不随实现同步，前端只能手写类型，字段漂移在联调期才暴露。阶段二已建立「契约导出 + `@bms/api-types` 生成 + 零漂移 CI」机制，本期把它用在新认证端点上。

**内容**（《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[微服务演进规划](../../../规划/微服务演进规划.md)》、阶段二 `03_01` 服务目录与契约登记）：

1. **契约快照更新**：identity 服务契约（`deploy/contracts/identity.json`）随实现导出更新，覆盖新增认证端点（登录 / 刷新 / 登出 / SSO 入口与回调 / 会话管理 / IdP 配置）与错误响应 schema。
2. **前端类型生成**：重新生成 `@bms/api-types` 对应服务类型，前端请求层与登录页按生成类型消费（不手写重复类型）；`oasdiff` / 契约门禁确认无破坏性变更（breaking 检查）。
3. **零漂移校验**：CI `api-types-check` 等既有校验保持全绿；契约版本登记（服务包自报契约版本）与阶段二口径一致。
4. **快照纪律**：契约「只加不删」（兼容承诺）；确需破坏性变更先登记消费方并同步前端类型与版本。

**完成标准**：认证端点全部进入契约快照且 CI 契约门禁通过；`@bms/api-types` 重新生成零漂移；登录页 / 请求层使用生成类型（无手写重复定义）；breaking 检查无未登记破坏项。

**参考文档**：《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[微服务演进规划](../../../规划/微服务演进规划.md)》、阶段二 [03_01 服务目录与注册要素登记](../../02_后端基座与服务化地基/任务/03_服务目录与契约登记/03_服务目录与契约登记_01_服务目录与注册要素登记/03_服务目录与契约登记_01_服务目录与注册要素登记.md)（**契约机制已交付**）

## 3. 需求 06-2：模块请求能力 `api` 与契约版本升 2 <a id="r06-2"></a>

优先级：2（高）

**背景与动机**：微服务化后前端模块必须经宿主请求层按服务段寻址访问后端，模块不得自建 HTTP / 裸 `fetch`，也不应接触 token（安全与治理要求）；阶段二已交付宿主请求层，阶段四 / 五已有模块契约与发布治理，但 `ModuleHostContext` 尚无 `api` 能力。微服务演进规划明确「随阶段六交付」——登录链路就绪后，模块才能带鉴权消费真实接口。

**内容**（《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》「请求能力」节、《[微服务演进规划](../../../规划/微服务演进规划.md)》）：

1. **`api` 能力注入**：`ModuleHostContext` 新增请求能力 `api`（按服务键 + 路径调用，宿主统一注入 token、错误解包与 401 处理）；模块经上下文消费，**token 不注入模块**。
2. **模块禁自建 HTTP**：模块内禁止自建 axios / 裸 `fetch`（隔离扫描护栏扩展该规则），既有 demo / sample 模块改造为经 `api` 消费。
3. **契约版本升 2**：模块契约版本自增（`MODULE_CONTRACT_VERSION`），版本不匹配的模块拒绝加载 / 明确提示；契约文档（架构 35）同步新增请求能力语义。
4. **双模块回归**：demo 与 sample 双模块经 `api` 完成一次真实请求（登录态下）与 401 分支；模块契约测试（契约用例工厂）覆盖新能力；发布清单与契约版本校验（阶段五 `03_02` 机制）同步。
5. **基类清单回写**：《[前端基类清单](../../../前端基类清单.md)》模块上下文相关条目与宿主请求层条目更新。

**完成标准**：模块可经 `api` 完成真实接口请求（鉴权由宿主处理）、401 自动刷新对模块透明；模块自建 HTTP 被护栏拦截（fixture 用例）；契约版本升 2 后旧模块加载被明确拒绝 / 提示，demo / sample 回归通过；`vue-tsc`、ESLint、Vitest 与契约用例全绿。

**参考文档**：《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[微服务演进规划](../../../规划/微服务演进规划.md)》、阶段五 [03_02 模块清单与发布治理](../../05_前端插件化/任务/03_隔离与治理/03_隔离与治理_02_模块清单与发布治理/03_隔离与治理_02_模块清单与发布治理.md)（**契约版本与校验机制已交付**）

## 4. 需求 06-3：服务契约路由覆盖护栏 <a id="r06-3"></a>

优先级：3（中）｜**补充需求**（2026-10-02 立项）

**背景与动机**：需求 [06-1](#r06-1) 的完成标准是「认证端点全部进入契约快照且 CI 契约门禁通过」，但既有两道契约门禁各有边界——`contract_snapshot check` 只保证「已提交快照与当前公开契约零漂移」，`contract_gate` 只保证「基线 ↔ 公开契约无破坏性变更」；**两者都不校验「服务的实现路由是否全部进入公开契约」**。若某端点被显式排除在契约之外（框架的「不入契约」开关），快照与基线会「一致地」缺失该端点，两道门禁全绿而对外契约已悄悄少了接口。本需求补上这一层长效护栏，防漏登、防人为隐藏，且不只针对 identity——**适用全部启用服务**（任何服务新端点自动受保护）。

**内容**（《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》「服务间通信与契约」节、《[微服务演进规划](../../../规划/微服务演进规划.md)》「服务边界与契约」门禁口径）：

1. **路由覆盖断言**：对每个启用服务，断言「实现路由集合（计入契约者）⊆ 公开契约 `paths`」——凡已实现且应公开的端点必须出现在公开契约中，缺登即失败并列出明细。
2. **不可见路由白名单断言**：被显式排除出契约的实现路由，仅允许框架内置文档端点与可观测端点（`/metrics`）；业务端点被人为隐藏即失败。
3. **校验命令化与门禁接入**：校验以基座命令形式提供（纯判定函数落共享库、可单测），接入 CI 与本地预检，**CI 与本地同口径**。
4. **全服务覆盖**：断言对全部启用服务生效（identity 只是其一），新增服务 / 新增端点自动纳入。

**完成标准**：9 个启用服务的路由覆盖断言与不可见白名单断言全绿；当出现「实现端点漏登契约」或「业务端点被隐藏出契约」时护栏失败（fixture 用例锁定）；CI 与本地预检同口径并全绿。

**参考文档**：《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[微服务演进规划](../../../规划/微服务演进规划.md)》、需求 [06-1](#r06-1)。

## 5. 需求 06-4：响应契约 schema 完整性与门禁 <a id="r06-4"></a>

优先级：2（高）｜**补充需求**（2026-10-02 立项）

**背景与动机**：需求 [06-1](#r06-1) 的完成标准是「认证端点全部进入契约快照、前端按生成类型消费（不手写重复类型定义）」，需求 [06-3](#r06-3) 补齐了「实现路由 ⊆ 公开契约 `paths`」的路由覆盖护栏；但**既有三道契约门禁（快照零漂移 / oasdiff 基线破坏 / 路由覆盖）都不校验契约 `components.schemas` 的内容完整性**。实测（2026-10-02）发现：公开契约快照中**全部响应体 schema 均为空对象**（`ApiResponse`、各 `ApiResponse_*` 包装、`LoginResult` / `RefreshResult` / `UserSummary`、`ConfigResolveResponse`、`LoginStateResult` 等，**9 个启用服务一致**）。根因是本基座 `BaseSchema._serialize_ids`（`@model_serializer(mode="wrap")` 返回 `Any`）使 **FastAPI 序列化模式**的 JSON Schema 塌陷为空对象，而请求体走校验模式不受影响（故 `LoginRequest` 等请求模型字段完整）。后果是 `@bms/api-types` 生成的**全部响应类型为 `unknown`**——前端「按生成类型消费、字段零漂移」在**响应侧实际落空**，且缺失是「一致地」缺失：快照零漂移与 oasdiff 基线两道门禁全绿也发现不了。本需求修复该基座缺陷并补长效门禁，使 06-1 的零漂移承诺在响应侧真实成立，并回接需求域 05 的 `05_02`（token 与 401 静默刷新接线）按生成类型消费。

**内容**（《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[后端开发规范](../../../规范/后端开发规范.md)》契约与门禁节）：

1. **基座序列化 schema 修复**：`BaseSchema` 在**序列化模式**生成 JSON Schema 时剥离模型序列化器、以字段口径输出；**校验模式 schema 与运行时序列化行为保持不变**（ID 字符串化与敏感字段掩码照旧）；`id` / `*_id` 字段按实际输出口径标为字符串，与 ID 字符串化规则**同源**（单点判定，不重复实现）。
2. **契约快照与基线重生成**：9 个启用服务的公开契约快照与 oasdiff 基线按新口径重生成（仅新增字段信息，无破坏性变更）。
3. **前端类型重生成**：`@bms/api-types` 重新生成并通过零漂移校验，响应类型不再为 `unknown`。
4. **响应契约门禁**：在既有契约校验命令内新增断言——公开契约 `components.schemas` **不得存在空对象条目**；每个操作的**成功响应**（2xx，含 `application/json`）的**引用型**（`$ref`）schema 必须可解析且引用目标非空；门禁对**全部启用服务**生效，CI 与本地预检同口径，fixture 用例锁定（空 schema 条目 / 悬空 `$ref` 即失败）。**边界**：直接返回 `Response` / `JSONResponse` / `RedirectResponse` 的原始响应端点（探针 / OIDC / SSO 回调）其内联空 schema 属另一缺陷类，不在本需求范围（登记归口后续任务）。
5. **回归**：认证链路端点（登录 / 刷新 / 登出 / SSO / 会话 / IdP 配置）响应字段完整可断言；既有序列化 / 脱敏 / 契约集合用例全绿。

**完成标准**：9 个启用服务响应契约 schema 完整（无空 schema 条目，引用型成功响应 schema 可解析且目标非空）；`@bms/api-types` 响应类型具字段可用且零漂移校验通过；契约门禁在「`components.schemas` 出现空对象」或「响应 `$ref` 悬空 / 目标为空」时失败（fixture 用例锁定）；CI 与本地预检同口径并全绿；序列化与脱敏运行时行为零变化（既有用例回归全绿）。

**参考文档**：《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》、《[后端开发规范](../../../规范/后端开发规范.md)》「契约与门禁」节、需求 [06-1](#r06-1) / [06-3](#r06-3)。
