## 1. 域说明 <a id="intro"></a>

本域把阶段二 `04-1-1` 已交付的前端接入骨架（服务段寻址 / 能力源分流 / 请求层 token 注入与 401 钩子 / 路由守卫骨架默认关闭 / 登录占位页）接上真实认证链路：**登录页、token 生命周期、守卫与回跳、扫码登录**，实现 的「前端登录与按服务寻址联通」。

- **本域范围**：登录页真实实现（含验证码与 SSO 入口）；token 与 401 静默刷新接线；路由守卫默认开启与登录回跳；扫码登录轮询与换取会话；记住我（登录保留时长选项，补充需求 05-5，2026-10-02 立项）。
- **不重复建设**：服务寻址单一来源（`service-endpoint.ts`）、能力源分流（`endpoints.ts`）、请求层 `apiUrl` / `request` / `token`（内存态）/ `http`（401 钩子位）、路由守卫判定纯函数（`resolveAuthRedirect`）与白名单均为阶段二已交付产物；本域只做**真实业务接线与登录页交付**。
- **端范围**：**仅 PC**（`frontend/apps/desktop` + `frontend/packages/*`）；移动端 `frontend/apps/mobile` 尚未建立（阶段十七）。
- **已定口径**（2026-09-26 拍板）：access 仅存内存（刷新页面静默续期）、refresh 走 httpOnly cookie；守卫默认开启；滑块验证码新 `payload` 形态（域 03-2）同步调整验证码件渲染。
- **依据**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2、《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节、《[安全开发规范](../../../规范/安全开发规范.md)》「前端密码口径」。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 05-1：登录页真实实现 <a id="r05-1"></a>

优先级：2（高）

**背景与动机**：`LoginView.vue` 目前是占位页（无表单），登录链路没有用户入口；登录页还要承载租户识别、三类验证码（按策略强制）、SSO / 扫码入口与锁定提示，是 前端侧的直接验收对象。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》「页面」节、《[安全开发规范](../../../规范/安全开发规范.md)》「前端密码口径」）：

1. **登录表单**：账号 / 密码 / 租户标识（或域名识别）；提交调用 `/auth/login`（经服务段寻址 `api/identity`），成功后装载用户上下文与动态路由。
2. **验证码接入**：按场景策略渲染图形 / 滑块 / 短信件（阶段四 `06_04` 件族复用），连续失败达阈值后强制；验证码失败自动刷新与错误提示。
3. **SSO 与扫码入口**：按 `/auth/sso/providers` 渲染 IdP 入口（跳转授权）与扫码登录入口（域 05-4）；入口不可用（未配置 / 凭据缺失）时隐藏或提示。
4. **错误与状态**：错误码文案映射（账号锁定 / 密码错误 / 验证码失败 / 限流命中 / IdP 故障）；「记住我」不落 access、仅影响 refresh 有效期选项（口径成文）；登录中态防重复提交。
5. **安全口径**：密码框不回填、明文切换仅内存态、不写控制台 / `localStorage` / `sessionStorage`、`autocomplete="new-password"`；强度提示只展示等级与缺失项。

**完成标准**：本地账号登录（含三类验证码强制分支）与 SSO 跳转入口均可用；错误码文案与后端契约一致；密码安全口径经用例 / 核对页验证；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节、阶段四 [06_04 验证码字段](../../04_前端组件库/任务/06_字段类/06_字段类_04_验证码字段/06_字段类_04_验证码字段.md)

> 注：本条原第 4 条列「记住我」，但后端登录契约（`LoginRequest`）无该字段、refresh 有效期由 `[security]` 统一控制，前端渲染开关无语义支撑——经 2026-10-02 拍板**改由补充需求 [05-5](05_需求_登录前端.md#r05-5) 立项**（先补后端契约再接入），登录页本轮不渲染该开关；第 5 条「密码强度提示」在登录场景无强度语义（用户输入为既有密码），**登录页不显示**，强度归改密 / 注册场景。

## 3. 需求 05-2：token 与 401 静默刷新接线 <a id="r05-2"></a>

优先级：2（高）

**背景与动机**：请求层已预留 token 注入位与 401 钩子，但「access 仅内存 + refresh httpOnly 静默续期 + 并发 401 只刷一次 + 登出清理」的完整生命周期尚未实现；若处理不当会出现刷新风暴、丢请求或刷新循环，直接影响登录可用性。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》§2）：

1. **token 注入**：access 仅存内存（Pinia），请求拦截器统一注入 `Authorization`；刷新页面后首屏静默续期（先 refresh 再放行受保护请求）。
2. **401 静默刷新**：单例刷新（并发 401 共享同一次 `/auth/refresh`），成功后重放原请求；刷新失败清会话并跳登录（带 `redirect` 回跳参数）；**不产生刷新循环**（刷新请求本身 401 不回递归）。
3. **登出**：调用 `/auth/logout` 清 refresh cookie 与会话、清内存 token 与用户上下文、跳登录；多标签页口径成文（本期以单标签为准并登记）。
4. **失效提示**：会话被踢出 / 过期时统一提示并跳登录（结合域 01-4 的即时拦截）。
5. **契约对齐**：refresh 请求经 `api/identity` 寻址、携带 httpOnly cookie（`withCredentials` 口径），响应字段与后端契约一致。

**完成标准**：受保护请求在 access 过期后自动刷新并重放（用户无感）；并发 401 仅一次刷新（用例覆盖）；刷新失败跳登录且无循环；登出后受保护请求不再携带旧 token；Vitest 用例全绿。

**参考文档**：阶段二 [04-1-1 前端网关接入改造](../../02_后端基座与服务化地基/任务/04_API网关与边缘/04_API网关与边缘_01_网关接入与声明式配置/04_API网关与边缘_01_网关接入与声明式配置_01_前端网关接入改造/04_API网关与边缘_01_网关接入与声明式配置_01_前端网关接入改造.md)（**骨架契约已交付**）、《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节

## 4. 需求 05-3：路由守卫默认开启与登录回跳 <a id="r05-3"></a>

优先级：2（高）

**背景与动机**：路由守卫骨架（`resolveAuthRedirect` + 默认白名单）已交付但默认关闭（`VITE_AUTH_GUARD` 未启用），登录链路就绪后必须默认开启，否则未登录用户可直达内部页面、登录后也不回跳目标页。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「路由守卫」节、《[前端基类清单](../../../前端基类清单.md)》）：

1. **默认开启**：`VITE_AUTH_GUARD` 默认 `on`（登录链路就绪后移除「默认关闭」口径）；白名单（登录页 / 错误页 / 公开页）与后端公开路径口径一致。
2. **回跳**：未登录访问受保护路由 → 跳登录并携带 `redirect`；登录成功后回跳原目标（无目标回默认首页）。
3. **与动态路由协同**：登录后按用户上下文装载动态路由（阶段七动态菜单就绪前的占位口径成文）；无权限路由跳 403。
4. **首屏体验**：已登录刷新时静默续期期间不闪登录页（骨架屏 / 等待态）；守卫判定失败的可观测提示（域 03-03 观测面板沿用）。

**完成标准**：未登录直达受保护路由被拦截并回跳；登录后回跳正确；白名单路由不受拦；刷新不闪登录页；Vitest 与宿主核对页验证通过。

**参考文档**：《[前端基类清单](../../../前端基类清单.md)》「宿主横切底座」节、阶段二 04-1-1（**守卫骨架已交付**）

## 5. 需求 05-4：扫码登录前端（二维码轮询与换取会话） <a id="r05-4"></a>

优先级：3（中）

**背景与动机**：阶段四交付的二维码件明确「扫码登录轮询与换取会话随认证阶段」；企微 / 钉钉免登（域 02-4）需要前端轮询授权状态并换取 BMS 会话，否则 PC 扫码入口只有图没有后续。

**内容**（《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》、阶段四 `07_02` 遗留口径）：

1. **二维码与轮询**：经二维码件渲染授权二维码（企微 / 钉钉），按间隔轮询授权状态（待扫 / 已扫待确认 / 已确认 / 过期）；过期自动刷新、轮询错误退避。
2. **换取会话**：授权确认后调用后端免登回调 / 换取接口（域 02-4 提供），成功后装载用户上下文（复用域 05-2 / 05-3 链路）。
3. **状态机与体验**：二维码状态可视反馈（遮罩 / 刷新按钮 / 提示文案）；轮询在页面隐藏时暂停（可见性 API）。
4. **联调口径**：企业真实凭据就绪时完成一次 PC 扫码登录 E2E；未就绪以测试夹具覆盖状态机并登记遗留（同域 02-4 口径）。

**完成标准**：扫码状态机四态均可用（含过期刷新与退避）；授权确认后成功换取会话进入系统；真实凭据未就绪时状态机用例全绿且遗留登记；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：阶段四 [07_02 轻量展示件](../../04_前端组件库/任务/07_展示类/07_展示类_02_轻量展示件/07_展示类_02_轻量展示件.md)（**二维码件与遗留口径**）、《[概要设计 · 身份认证SSO](../../../设计/概要设计/26_概要设计_身份认证SSO.md)》

## 6. 需求 05-5：记住我（登录保留时长选项） <a id="r05-5"></a>

优先级：3（中）｜**补充需求**（2026-10-02 立项）

**背景与动机**：需求 [05-1](05_需求_登录前端.md#r05-1) 原列「记住我」需「不落 access、仅影响 refresh 选项」，但后端 `POST /auth/login` 的 `LoginRequest` 只有 `account` / `password` / `tenant` / `captcha`，**无「记住我」字段**，refresh 有效期由 `[security]` 统一控制（14 天滚动）。前端若渲染该开关而提交无载体，属**误导性装饰**；要让「记住我」真正生效，必须**先扩展后端登录契约并明确 refresh 有效期策略**，再接入前端。该缺口由登录页任务（`05_01`）实施期发现，经拍板另立本条。

**内容**（《[架构设计 · 认证与会话](../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》「双 token 模型」节、《[概要设计 · 会话管理](../../../设计/概要设计/14_概要设计_会话管理.md)》、[需求 01-3](01_需求_认证与会话.md#r01-3)）：

1. **登录契约扩展**：`LoginRequest` 增**可选** `remember_me`（布尔，缺省 `false`，只增不删）；未携带时行为与本补充需求落地前完全一致（向后兼容）。
2. **保留时长策略**：`remember_me=false` → refresh 有效期为**会话级**（浏览器会话结束即失效，Cookie 不带持久 `Max-Age`）；`remember_me=true` → refresh 为**14 天滚动轮换**（现行口径）。取值与 Cookie 属性随详细设计定稿并回写契约。
3. **会话侧对齐**：`sys_session.expires_at` 与 Redis 会话标记 TTL 随选项取值对齐；refresh 轮换保持会话 id 稳定；登出 / 踢出清理口径不变。
4. **前端接入**：登录页表单恢复「记住我」勾选项（缺省不勾选），随登录请求提交；口径成文——**不落 access**、不变更 access 有效期（仍 30 分钟且仅存内存）。
5. **契约与门禁**：新字段进入 identity 公开契约快照、oasdiff 基线与 `@bms/api-types` 生成类型（零漂移由既有门禁保证）。
6. **安全口径**：勾选仅延长 refresh 有效期，不改变 Cookie 的 `HttpOnly` / `Secure` / `SameSite` 口径，不改 `Path` 收敛；禁用「记住我」不落任何明文口令。

**完成标准**：勾选与不勾选两种登录在刷新后表现为不同的 refresh 有效期（用例覆盖会话级与 14 天两分支）；契约四道门禁全绿且生成类型含 `remember_me`；登录页勾选项随请求提交且文案与口径一致；`vue-tsc`、ESLint、Vitest 全通过。
