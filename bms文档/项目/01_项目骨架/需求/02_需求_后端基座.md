## 1. 域说明 <a id="intro"></a>

本域对应阶段一「后端基座」，是**后端全部模块的前置地基**——基类与基座先立，认证 / RBAC / 通用能力等模块才有统一写法（不做则各模块各自实现异常、会话、路由与注册，口径必然发散）。覆盖六块，共 16 条需求：

- **基座与异常体系**（`02-1`~`02-2`）：异常体系 `BizError` + 统一响应 `ApiResponse`；core 横切基座补齐（配置 / 安全基座）与阶段一已交付基座的登记
- **数据访问底座**（`02-3`）：异步引擎 / 会话工厂 / 四库方言 / 基类异步切换 / 读写分离占位
- **多租户数据拓扑**（`02-4`~`02-9`）：三库拓扑与建库、模型基类 `BaseModel` 与表规范、平台库基础表、租户解析中间件、引擎注册表与池管理、批量迁移与租户库初始化
- **模块注册表**（`02-10`~`02-12`）：`sys_module` 表与种子、注册唯一性校验、模块查询接口
- **CI 与阶段验收**（`02-13`~`02-15`）：三库集成测试与流水线收口、M1 验收门禁核对、测试报告与 README
- **跨阶段基座**（`02-16`）：缓存 Region 分域 / 数据范围注入 / 分片路由 / 事件发布消费 / 任务基座 / 审计捕获基座（登记 + 按阶段回补）

**依据**：《[总体项目规划](../../../规划/总体项目规划.md)》「工作分解结构（WBS）」节「里程碑」节（M1）、《[项目规划说明](../../../规划/项目规划说明.md)》「开发计划与验收标准」节、《[架构设计 · 后端基础类体系](../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[架构设计 · 数据架构](../../../设计/架构设计/05_架构设计_数据架构.md)》、《[架构设计 · 多租户路由](../../../设计/架构设计/08_架构设计_子系统_多租户路由.md)》、《[架构设计 · 数据访问与分片](../../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》、《[架构设计 · 模块注册](../../../设计/架构设计/07_架构设计_子系统_模块注册.md)》、《[后端开发规范](../../../规范/后端开发规范.md)》、《[数据库开发规范](../../../规范/数据库开发规范.md)》、《[API接口规范](../../../规范/API接口规范.md)》、《[测试规范](../../../规范/测试规范.md)》。

**目标**：`BizError` 与统一响应生效、`BaseModel` 落库（雪花 ID / 软删除 / 审计 / 乐观锁）、三库拓扑可路由（MySQL / PostgreSQL / 达梦 DM8）、租户隔离与批量迁移正确、模块注册校验生效（表前缀 / 错误码段 / 事件域冲突被拒）、基类异步切换完成；跨阶段基座登记齐备。

**边界说明**：

- 基座对**配置**只提供统一入口的方法与结构（占位实现，不真实读取），真实 `config.toml` 读取与启动校验由「[03 后端基础能力](03_需求_后端基础能力.md)」的配置管理落地——基座先于依赖它的能力。
- 认证与会话安全基座的**具体实现**归认证阶段；RBAC 数据范围**规则**归 RBAC 阶段；真实分片规则与缓存三防加固归分布式与监控阶段；事件总线与任务调度**业务实现**归系统集成与通用能力阶段。
- 前端组件库与业务模块（由产品仓库承载）不在本域范围。

## 2. 需求 02-1：异常体系与统一响应 <a id="r02-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：阶段一以 `NotFoundError` + 临时处理器过渡（body 结构与统一响应不一致）；若不在基座阶段统一，认证 / RBAC / 通用能力各模块将各自定义异常与错误响应，错误码口径必然发散。

**内容**（《后端开发规范》「异常与错误码」节、《API接口规范》）：

1. `app/core/exceptions.py`：统一异常基类 `BizError`（携带错误码与参数）+ 常用子类（参数异常 / 认证失效 / 权限不足 / 资源不存在 / 冲突等）；`NotFoundError` 过渡实现改为继承 `BizError`。
2. 全局异常处理器：`BizError` → 统一响应 `{code, message, data}`（HTTP 状态码与业务错误码分离）；未捕获异常 → 500 且不暴露堆栈（开发环境可含 trace_id）。
3. 统一响应模型 `ApiResponse`（Pydantic），成功 `code=0`；错误码平台段 `1xxxx`~`9xxxx` 登记于《架构设计 · 接口与集成》「错误码」节，本阶段建立骨架段位。
4. 业务异常在 services 层抛出、api 层不 catch；`main.py` 注销阶段一临时 404 处理器。
5. 测试：先登记 Kiwi 用例，再写自动化（异常分支 + 统一响应结构断言）；替换 demo 的过渡断言。

**完成标准**：`BizError` 及各子类可用；业务异常经全局处理器转统一响应结构；未捕获异常返回 500 且不泄露堆栈；错误码段位登记；阶段一临时处理器移除；`pytest`、`ruff`、`pyright` 全绿。

**参考文档**：《后端开发规范》「异常与错误码」节、《API接口规范》「统一响应与错误码」节、《架构设计 · 接口与集成》「错误码」节

## 3. 需求 02-2：core 基座补齐与登记 <a id="r02-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：工程骨架已交付 core 基座与三套基类，但**未在架构登记**（设计目录零提及），后续模块不知继承什么、公共能力加在哪；安全原语也缺统一落点，认证等阶段会各自实现。

**内容**（《架构设计 · 后端基础类体系》「基座分层」节「core 横切基座」节、《后端开发规范》「后端基座体系」节）：

1. 配置基座**结构与入口**：`app/core/config.py` 提供配置模型与读取接口的统一入口（分区模型、取值方法；本阶段为**占位实现**，返回默认值即可）；真实 `config.toml` 读取、环境分层覆盖与启动校验由「[03 后端基础能力](03_需求_后端基础能力.md)」需求 03-1 配置管理落地，落地后回填本基座登记。
2. 安全基座：`app/core/security.py`（密码哈希、令牌与会话安全原语），供认证与会话阶段复用。
3. 基座登记回写：将 `BaseObject` / `BaseCollection`（有序集合）/ `ConcurrentSorted*` / Redis 有序封装 / `BaseRepository` / `BaseService` / `BaseSchema` 的职责、继承关系与代码位置在《架构设计 · 后端基础类体系》与《后端开发规范》保持同源一致（架构节点已建，本需求负责代码侧对齐与差异补齐）。
4. 继承约定校验：新增 / 改造类必须继承对应基类，禁止重复定义公共字段 / 方法（CI lint 或评审条款）。

**完成标准**：配置基座结构（模型与读取接口）就位并可被上层引用（真实读取由 03-1 落地后回填登记）、安全基座就位并被后续阶段引用；《架构设计 · 后端基础类体系》基类清单与代码实现一致；继承约定纳入规范且可核对；`pytest`、`ruff`、`pyright` 全绿。

**参考文档**：《架构设计 · 后端基础类体系》「基座分层」节「core 横切基座」节、《后端开发规范》「后端基座体系」节、《命名规范》

## 4. 需求 02-3：SQLAlchemy 数据访问底座 <a id="r02-3"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：工程骨架的 `BaseRepository` / `BaseService` 为**同步内存基线**；数据库接入与异步化必须集中在基类一次完成，否则每个模块各自实现异步会话，事务边界与连接预算失控。达梦同步驱动（dmPython）与「全链路异步」的口径需先定案。

**内容**（《架构设计 · 数据访问与分片》、《后端开发规范》「SQL 与数据访问规范」节「异步与并发」节）：

1. 异步引擎工厂：按数据源创建 / 缓存 `AsyncEngine`（连接池参数、超时、`pool_pre_ping`）；多数据源经多 engine 管理。
2. AsyncSession 工厂：`async_sessionmaker`，请求级会话（依赖注入），事务边界显式（`with session.begin()`）；禁止异步会话跨请求共享。
3. 四库方言适配：MySQL（aiomysql）、PostgreSQL（psycopg 3）、达梦 DM8（dmPython，同步驱动经 `asyncio.to_thread` 封装例外口径）、SQLite（aiosqlite）；Alembic URL 经配置基座读取接口取值（真实读取随 03-1 配置管理落地）。
4. **基类异步切换**：`BaseRepository[T]` 数据库实现覆写原子方法为异步，`exists` / `count` 派生方法沿用；`BaseService[T]` 异步化；分页与软删除过滤等通用能力回填基类（只加基类，模块类不改）；同步内存基线保留为测试替身。
5. 读写分离占位：读写路由接口（按上下文标记选引擎），本阶段主从同源。
6. 测试：先登记 Kiwi 用例；单元用 SQLite，集成连三库（随 02-13）；`ruff`、`pyright` 全绿。

**完成标准**：异步引擎与会话工厂可用、事务边界正确；四库方言可切换（SQLite 单测 + 三库集成随 02-13）；基类异步切换完成且调用面一致；分页 / 软删除过滤在基类生效；读写分离占位可用。

**参考文档**：《架构设计 · 数据访问与分片》、《架构设计 · 后端基础类体系》「阶段落地（地基波 + 回补）」节、《后端开发规范》「异步与并发」节、《数据库开发规范》「迁移」节

## 5. 需求 02-4：三库拓扑与建库 <a id="r02-4"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：多租户隔离是本系统核心约束（一租户一库）；库模型 / 命名 / 字符集 / 跨库规则不定死，后续建库与迁移会各写各的；逻辑外键与禁 JOIN 是隔离底线。

**内容**（《架构设计 · 数据架构》「数据分布」节、《命名规范》「数据库命名」节）：

1. 三库模型与职责：平台库 `bms_platform`（租户注册、平台超管、平台统一菜单 / 权限码，本阶段仅 `sys_tenant` 与 `sys_module`）；租户库 `bms_tenant_{code}`（一租户一库，该租户全部业务数据，`code` 为租户编码全小写）；归档库 `bms_archive`（各租户归档数据统一收存，带 `tenant_id` 与原库表标识，只读，通用能力阶段起用——本阶段仅登记命名与连接配置占位，不建业务表）
2. 开发环境库模拟：本地开发 / 测试用**多个 SQLite 文件**模拟（`bms_platform.db`、`bms_tenant_demo.db`、`bms_archive.db`），一文件一库；环境库命名 `bms_dev` / `bms_test` / `bms_prod`（多环境实例名，与三库模型区分）
3. 建库标准：字符集 MySQL utf8mb4、PostgreSQL UTF8、达梦 UTF8；达梦注意 schema 前缀（开发实例 `bms_dev`，查询 / 迁移引用时统一小写标识符口径）；SQLite 开发库自动建表（`Base.metadata.create_all`，不依赖迁移脚本）
4. 跨库引用原则：一律逻辑外键（code），不建物理外键；跨库查询禁止 JOIN（服务层聚合或事件同步）

**完成标准**：三库在 SQLite 模拟下建库成功、互不串库；MySQL / PostgreSQL / 达梦三实例上 `bms_platform` 与示例 `bms_tenant_demo` 建库成功且字符集符合标准；跨库引用无物理外键。

**参考文档**：《架构设计 · 数据架构》「数据分布」节、《命名规范》「数据库命名」节、《数据库开发规范》「多租户与分片」节

## 6. 需求 02-5：模型基类与表规范 <a id="r02-5"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：全库表结构与字段行为（雪花 ID / 审计 / 软删除 / 乐观锁）在此一次定义；不先立，几十张表建完再补基类字段将全量返工，四库类型映射差异必须在骨架期实测。

**内容**（《架构设计 · 数据架构》「数据规范」节、《数据库开发规范》第 2/3 节）：

1. `app/models/base.py` 的 `BaseModel` 字段（每表必备，ORM 层定义一次）：
   - 主键 `id`：雪花 ID（yitter/IdGenerator，BIGINT 跨库类型），生成器封装于 `app/core/id.py`（`generate_id()`）
   - 审计：`created_at`（DATETIME/TIMESTAMP）、`created_by`、`updated_at`、`updated_by`——由 ORM 事件自动填充（insert/update 监听），业务代码禁止手动赋值
   - 软删除：`deleted_at`（DATETIME，NULL=未删）；乐观锁：`version`（INT，更新时比对，冲突返回明确错误码）
2. 四库类型映射表（基类字段跨方言实现，写入模型定义注释）：

   | 字段 | SQLite | MySQL | PostgreSQL | 达梦 DM8 |
   | --- | --- | --- | --- | --- |
   | id | INTEGER | BIGINT | BIGINT | BIGINT（自增列口径，雪花值写入） |
   | created_at 等 | DATETIME | DATETIME | TIMESTAMP | TIMESTAMP |
   | version | INTEGER | INT | INTEGER | INT |
   | 布尔（通用约定） | INTEGER 0/1 | TINYINT(1) | SMALLINT | SMALLINT（达梦无 BOOLEAN 时口径） |

   - 时间统一 UTC 存储（应用侧 UTC 写入），前端本地时区展示；金额 NUMERIC(20,4)、字符串 VARCHAR（长度显式）、禁用方言专用类型（JSON / ENUM / SERIAL）
3. 软删除机制：查询默认过滤 `deleted_at IS NULL`（repository 基类统一注入，禁止业务层手写过滤）；唯一约束统一建为 `(唯一字段, deleted_at)` 复合唯一索引——未删行 `deleted_at` 为 NULL，四库均允许多个 NULL 不冲突（**达梦按 Oracle 兼容口径，本阶段实测验证**）；删除时写入时间戳即释放唯一键、恢复即清 NULL；PostgreSQL 另加部分唯一索引优化（可选）
4. 索引规范：排序字段、外键（逻辑外键列）、数据权限过滤字段必须建索引；命名 `idx_字段` / `uq_字段`；每表索引不超过 5 个
5. 表级规范：表名单数 snake_case；表前缀平台域 `sys_`/`wf_`/`rpt_`/`ai_` 与业务模块 `{简称}_`（注册制）；每表与字段 COMMENT（中文）必填

**完成标准**：基于 `BaseModel` 的示例模型（`sys_tenant` 复用验证）在四库均能建表（SQLite 自动建表 + 三库迁移）；审计字段插入 / 更新自动填充实测通过；同表同值两行未删记录插入被 `(唯一字段, deleted_at)` 索引拒绝、软删除后再插入同值成功（达梦实测）；乐观锁版本冲突返回明确错误码。

**参考文档**：《架构设计 · 数据架构》「数据规范」节、《数据库开发规范》第 2/3/4 节、《命名规范》「数据库命名」节、《项目规划说明》第 6/11 节

## 7. 需求 02-6：平台库基础表 <a id="r02-6"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：`sys_tenant` 是租户解析与建库路由的依据、M1 门禁「三库拓扑可路由」的入口；demo 种子让后续所有链路可验证。

**内容**（《架构设计 · 数据架构》「平台库表」节、《架构设计 · 多租户路由》）：

1. `sys_tenant` 表（平台库，租户注册与路由依据），字段明细：

   | 字段 | 类型 | 约束 | 说明 |
   | --- | --- | --- | --- |
   | id | BIGINT | 主键（雪花 ID） | — |
   | code | VARCHAR(32) | uq（(code, deleted_at) 复合唯一） | 租户编码，全小写，建库后缀 `bms_tenant_{code}` |
   | name | VARCHAR(64) | — | 租户名称 |
   | domain | VARCHAR(128) | 可空 | 生产子域名（如 `demo.bms.example.com`），租户解析一级来源 |
   | db_key | VARCHAR(32) | 必填 | 指向配置的数据源配置键 |
   | status | SMALLINT | 默认 1 | 1 启用 / 0 停用 |
   | expire_at | DATETIME | 可空 | 过期时间（RBAC 阶段起用） |
   | created_at/created_by/updated_at/updated_by/deleted_at/version | 按基类 | — | 审计 / 软删除 / 乐观锁 |

   - 索引：`uq_code_deleted_at`（复合唯一）、`idx_domain`

## 8. 需求 02-7：租户解析中间件 <a id="r02-7"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：请求必须能确定「数据落哪个租户库」；不先做路由与隔离会串库——多租户产品不可交付，并发下 `TenantContext` 隔离是正确性底线。

1. 解析链（按优先级取第一个命中）：
   - 生产：子域名 `{tenant}.bms.example.com` → 查平台库 `sys_tenant.domain`（命中 Redis 短 TTL 缓存），解析出 tenant_code
   - 一人多租户切换：请求头 `X-Tenant-ID`（租户 code，切换后重发 token，认证阶段接入）

**完成标准**：`X-Tenant-ID: demo` 请求日志 tenant 字段为 `demo`，数据读写落在 `bms_tenant_demo` 库（SQLite 模拟实测）；未知租户 `X-Tenant-ID: ghost` 返回 404 + 80001；豁免路径（/docs、/healthz）不受租户校验影响；并发请求下 `TenantContext` 互不串扰（pytest 并发用例）。

## 9. 需求 02-8：引擎注册表与池管理 <a id="r02-8"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：租户库按需建连接，不管理池会造成连接耗尽拖垮数据库；多实例并发创建引擎需加锁防重；连接预算公式是容量安全线。

**内容**（《架构设计 · 多租户路由》「引擎注册表与生命周期」节、《架构设计 · 数据访问与分片》「多数据源管理」节）：

1. `EngineRegistry`（`app/db/registry.py`）：注册表 `{db_key → engine}`；**平台引擎常驻**（`bms_platform` 启动即建）；**租户引擎懒加载**（首次访问创建，连接参数来自配置的数据源声明）；`get_engine(db_key)` 同步接口（进程内锁保护创建段）
2. 闲置回收：LRU + 最后使用时间——超过闲置阈值（默认 30 分钟，可配）的租户引擎 `dispose()` 回收；停用租户强制回收；活跃租户引擎数上限（默认 32，可配）超出时按 LRU 淘汰
3. 连接预算：总连接 = worker 数 × (pool_size + max_overflow) ≤ 数据库 `max_connections` 的 70%（预留其他客户端）；参数在数据源声明中显式可配，启动校验预算不超限（超限启动告警日志）
4. 并发保护：引擎创建加锁（进程内锁 + Redis SETNX 分布式锁，防多实例同时为同一租户建引擎）；创建失败快速失败并记 ERROR 告警（监控阶段前以 warning 兜底）
5. 与数据访问底座衔接：`EngineRegistry` 管理需求 02-3 工厂产出的引擎（含达梦同步引擎）；`TenantContext` 持引擎引用而非全局查找

**完成标准**：demo 租户引擎首次请求才创建（懒加载实测：启动后仅平台引擎存在）；闲置阈值调短（如 5s）后租户引擎自动回收；活跃上限调小后超出按 LRU 淘汰；并发 20 请求仅创建 1 个租户引擎（加锁防重）；连接预算超限时启动输出告警日志。

**参考文档**：《架构设计 · 多租户路由》「引擎注册表与生命周期」节、《架构设计 · 数据访问与分片》「多数据源管理」节、《项目规划说明》「多数据源策略」节

## 11. 需求 02-10：sys_module 表与种子 <a id="r02-10"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：平台「注册制」的载体——表前缀 / 错误码段 / 事件域必须先登记才能分配；否则业务模块接入时标识符冲突（多产品扩展尤其突出）。

**内容**（《架构设计 · 模块注册》第 2/3 节、《项目规划说明》「模块注册要素」「模块前缀登记」「错误码段规则与注册」节）：

1. `sys_module` 表（平台库），字段明细：

   | 字段 | 类型 | 约束 | 说明 |
   | --- | --- | --- | --- |
   | id | BIGINT | 主键（雪花 ID） | — |
   | module_key | VARCHAR(32) | uq（(module_key, deleted_at) 复合唯一） | 模块简称，2-6 位全小写英文，与英文名一致（如 `purchase`） |
   | name | VARCHAR(64) | — | 模块中文名（如「采购管理」） |
   | table_prefix | VARCHAR(16) | uq（(table_prefix, deleted_at) 复合唯一） | 形如 `{简称}_`（如 `pur_`）；平台域为 `sys_`/`wf_`/`rpt_`/`ai_` |
   | errcode_segment | SMALLINT | uq（(errcode_segment, deleted_at) 复合唯一） | 两位段号，10 起（业务模块按注册段使用，示例 `10xxxx`）；平台域 0 占位（`1xxxx`~`9xxxx` 既有段） |
   | event_domain | VARCHAR(32) | uq（(event_domain, deleted_at) 复合唯一） | 事件域，小写，默认与 module_key 一致，多事件域模块预留扩展 |
   | status | SMALLINT | 默认 1 | 1 启用 / 0 规划中（未交付模块登记态，种子状态标记，非运行时开关） |
   | created_at/created_by/updated_at/updated_by/deleted_at/version | 按基类 | — | 审计 / 软删除 / 乐观锁 |

   - 多语言模块名附表 `sys_module_i18n`（module_id + locale 联合主键 + name），中文名存主表、英文名入附表（en-US）
2. 初始种子（Alembic 数据迁移或幂等种子脚本，随版本演进）：
   - 平台域固定 4 行：`sys`（系统，prefix `sys_`）、`wf`（工作流，`wf_`）、`rpt`（报表，`rpt_`）、`ai`（AI 域，`ai_`）
   - 业务模块**不预置**：由产品仓库交付时随平台扩展接入登记（前缀 / 错误码段 / 事件域写入 `sys_module`），本阶段只交付注册与冲突校验机制
3. 注册方式约束：运行时**无写接口**（不提供增删改）；新增模块 = Alembic 迁移 revision（建表 schema 迁移 + 注册种子数据迁移）原子落地，平台库单库执行一次；status 为种子状态标记，租户级模块开关另表 `sys_tenant_module`（RBAC 阶段）
4. 业务码口径：业务码与模块简称一致（`sys_business` 注册，RBAC 阶段）；错误码段与事件命名以 `sys_module` 登记值为权威

**完成标准**：与 `sys_tenant` 同库、同迁移流水线落表（三库迁移通过）；种子查询返回平台域 4 行（sys/wf/rpt/ai），prefix / 段号 / 事件域与平台注册规则一致；业务模块不预置（由产品仓库交付时登记）；`sys_module_i18n` 英文名可查；无任何写接口暴露。

**参考文档**：《架构设计 · 模块注册》第 2/3 节、《项目规划说明》「模块注册要素」至「错误码段规则与注册」节、《命名规范》「数据库命名」节

## 12. 需求 02-11：注册唯一性校验 <a id="r02-11"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

## 17. 需求 02-16：跨阶段基座登记与回补 <a id="r02-16"></a>

优先级：3（中）　|　状态：未开始　|　完成日期：—

**背景与动机**：缓存、数据范围、分片、事件、任务、审计六类能力都有「基座」成分（公共封装 + 模块只写差异），但它们依赖各自后端模块；若不在基座阶段把它们登记清楚，后续模块会各自实现缓存 key、数据范围注入、事件发布等，口径发散且重复。

**内容**（《架构设计 · 后端基础类体系》「阶段落地（地基波 + 回补）」节）：

1. **缓存 Region 分域基座**（回补通用能力阶段）：dogpile.cache Region 分域管理 + 全局版本号惰性比对；key 规范 `bms:{租户|global}:{域}:{业务键}`、全 key 带 TTL；三防（穿透空值 / 击穿互斥锁 / 雪崩随机偏移）在基座统一。
2. **数据范围注入基座**（回补 RBAC 阶段）：`BaseRepository` 的数据访问范围注入钩子（写读双向校验），规则由 RBAC 提供。
3. **分片路由基座**（回补分布式与监控阶段）：`ShardingRouter` 抽象（分片键 → 物理库 / 表解析），MVP 落地按月分表。
4. **事件发布 / 消费基座**（回补系统集成与消息阶段）：统一事件发布接口（RocketMQ 事务消息）与消费基类（分区有序消费），业务模块不直接调用通知 / 审计。
5. **Celery 任务基座**（回补通用能力阶段）：任务定义入库（`sys_task`）+ 自研 beat 调度基类 + 执行记录（`sys_task_log`）。
6. **ORM 审计捕获基座**（回补通用能力阶段）：ORM 事件自动捕获关键表字段级变更，审计事件走分区有序消费（哈希链）。
7. 登记要求：六类基座的职责、契约与回补阶段写入《架构设计 · 后端基础类体系》与阶段一计划表；对应阶段实施时在**该阶段计划**登记窗口（同一任务文档，不重复建任务）。

**完成标准**：六类跨阶段基座的职责与契约在架构节点登记；回补阶段与窗口写入阶段一计划表；对应阶段启动时按登记实施并回写状态；无遗漏、无重复实现。
