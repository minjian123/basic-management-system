## 2. 项目骨架目标与范围 <a id="goal"></a>

**M1 目标**（《总体项目规划》「里程碑」节 M1 行）：本地起服务、`/healthz`、`/readyz` 正常、CI 流水线激活通过。周期口径 3 周（兼职，T+0 = 2026-08-24；M1 基线 2026-09-28，累计 5 周）。

**范围内**（共 10 条需求，见第 3 节总清单）：

| 需求域 | 内容 |
| --- | --- |
| 一 工程骨架 | monorepo 根骨架、backend 工程初始化与分层目录、frontend/frontend-mobile 工程初始化、依赖锁定与 Python 3.14 兼容验证（**已完成**） |
| 二 后端基础能力 | 配置管理、日志体系、健康检查 |
| 三 CI 流水线 | CI 流水线激活（冒烟层 / 重验证层 / exists 守卫 / 覆盖率门禁 / CI 基础镜像） |

**范围外**：

- **已迁入阶段二 后端基座**：异常与错误码骨架（`BizError`/统一响应）、SQLAlchemy 数据访问底座与基类异步切换、多租户数据拓扑（三库拓扑/模型基类/平台库表/租户解析/引擎池/批量迁移）、模块注册表（sys_module）、三库集成测试与阶段验收（含 M2 门禁核对、测试报告）。
- 阶段四及以后交付物（认证与安全、RBAC 权限体系、通用能力等，见《总体项目规划》「工作分解结构（WBS）」节 WBS）
- 业务模块（采购 `pur_`、收付款 `pay_`、供应商 `sup_` 等）由产品仓库（biz）承载，交付时随平台扩展接入登记；阶段一不种子业务模块
- 前端页面与组件开发（阶段三 前端组件库及其后的前端全页面）；ElasticSearch 等阶段十六依赖（《开发部署规划》「开发服务器 mjbk 部署」节两节奏口径）
- 租户开通/停用/配额等租户管理业务功能（阶段五），阶段一仅交付工程骨架与基础能力

> 边界说明：`.gitlab-ci.yml` 流水线**框架**（六类 job）已于准备期 02-3/02-4 落地；阶段一代码落地后流水线随 job 的 exists 条件自动激活（03-1）。Python 3.14 与核心依赖/dmPython 兼容性已由 01-6 验证通过（保持 3.14）。

## 4. M1 验收门禁 <a id="accept"></a>

门禁定义（《总体项目规划》「里程碑」节 M1 行，收窄后）：**本地起服务、`/healthz` `/readyz` 正常、CI 流水线激活通过**。逐项核对：

| 验收点 | 核对方式 | 对应需求 | 结论 |
| --- | --- | --- | --- |
| 本地起服务 | backend `uv run uvicorn` 启动无报错、/docs 可访问；frontend/frontend-mobile `npm run dev` 可访问默认页 | 01-1 ~ 01-6、02-1 | 待阶段完成核对 |
| 健康检查正常 | /healthz 存活 200；/readyz 依赖（Redis）正常时 200、依赖停时 503；`database` 检查项随阶段二数据访问底座落地后启用 | 02-3 | 待阶段完成核对 |
| CI 流水线激活通过 | 含代码改动的 main 推送自动跑冒烟层且全绿（重验证层三库集成随阶段二 05-1） | 03-1 | 待阶段完成核对 |

**结论**：三库拓扑与模块注册校验已随「多租户数据拓扑 / 模块注册表」迁入阶段二，M2 门禁承接（见阶段二需求总览）；阶段一 10 条需求在本阶段内闭环，无跨阶段依赖（健康检查的 `database` 检查项除外，其随阶段二启用）。
