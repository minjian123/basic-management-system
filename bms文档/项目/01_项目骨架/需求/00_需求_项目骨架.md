## 1. 文档说明 <a id="purpose"></a>

本文档集是 BMS **阶段一（项目骨架（含后端基座））** 的需求基线：项目骨架要做什么、每条需求做什么、怎样算完成。按需求域拆分，与阶段一 WBS（父任务 01~04）逐条对应：

| 文档 | 内容 |
| --- | --- |
| 本文档 `00_需求_项目骨架` | 阶段一目标、范围、需求总清单、M1 验收门禁 |
| [01_需求_工程骨架](01_需求_工程骨架.md) | monorepo 三工程初始化与依赖兼容验证（6 条，**6/6 已完成**） |
| [02_需求_后端基座](02_需求_后端基座.md) | 后端基座（异常体系 / 数据访问底座 / 多租户数据拓扑 / 模块注册表 / CI 与阶段验收 / 跨阶段基座，16 条） |
| [03_需求_后端基础能力](03_需求_后端基础能力.md) | 配置管理 / 日志体系 / 健康检查（3 条） |
| [04_需求_CI流水线](04_需求_CI流水线.md) | CI 流水线激活（1 条，进行中） |

- **进度事实源**：需求/任务/计划三类文档为唯一事实源；本文档集的「状态 / 完成日期」随文档维护。
- **依据**：《[总体项目规划](../../../规划/总体项目规划.md)》「工作分解结构（WBS）」节（WBS 阶段一）、「里程碑」节（M1）、《[项目规划说明](../../../规划/项目规划说明.md)》「开发计划与验收标准」节（阶段一）、《[开发部署规划](../../../规划/开发部署规划.md)》「分阶段落地计划」节（CI 基础设施）、《[架构设计 · 后端基础类体系](../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[需求文档规范](../../../规范/需求文档规范.md)》。
- **范围调整（2026-09-12）**：后端基座**并入阶段一**——它是后端全部模块的前置地基（基座先立，认证 / RBAC / 通用能力等模块才有统一写法），须先于配置 / 日志 / 健康检查等上层能力落地；原独立「阶段二 后端基座」撤销，其 16 条需求（异常体系、数据访问底座、多租户数据拓扑、模块注册表、CI 与阶段验收、跨阶段基座）整体并入本阶段；后续阶段编号相应前移一位（原阶段三 前端组件库起顺延）。M1 门禁相应扩为「骨架三项 + 基座六项」。
- **基座与配置的边界**：基座只提供**统一入口的方法与结构**（占位实现，不真实读取配置），真实 `config.toml` 读取与启动校验由 [02_需求_后端基座](02_需求_后端基座.md) 之后的 [03 后端基础能力](03_需求_后端基础能力.md) 的配置管理落地并回填基座登记——保证基座先于依赖它的能力。
- **开发环境前置（工作区模型）**：开发机按工作区并置克隆 bms 与产品仓库（《开发部署规划》「仓库获取」节）；`AGENTS.md`、`.opencode` 与知识图谱位于工作区根，bms 仓库文档根为 `bms文档/`（见《平台可扩展性规划》「工作区模型与基座引用」节）。
- **已完成范围（2026-09-10）**：01 工程骨架域 6/6 完成，含后端 `BaseObject` 根基类、有序集合、并发集合、Redis 有序封装与 `BaseRepository` / `BaseService` / `BaseSchema` 三套基类（后端基座首批，详见《架构设计 · 后端基础类体系》）。

## 2. 项目骨架目标与范围 <a id="goal"></a>

**M1 目标**（《总体项目规划》「里程碑」节 M1 行）：本地起服务、`/healthz` `/readyz` 正常、CI 流水线激活通过（骨架三项），并达成后端基座六项——`BizError` 与统一响应生效、`BaseModel` 落库、三库拓扑可路由、租户隔离与批量迁移正确、模块注册校验生效、跨阶段基座登记齐备。周期口径：骨架 3 周 + 基座 4 周（兼职，串行）。

**范围内**（共 26 条需求，见第 3 节总清单）：

| 需求域 | 内容 |
| --- | --- |
| 一 工程骨架 | monorepo 根骨架、backend 工程初始化与分层目录、frontend/frontend-mobile 工程初始化、依赖锁定与 Python 3.14 兼容验证（**6/6 已完成**） |
| 二 后端基座 | 异常体系与统一响应、core 基座补齐与登记、SQLAlchemy 数据访问底座、三库拓扑与建库、模型基类与表规范、平台库基础表、租户解析中间件、引擎注册表与池管理、批量迁移与租户库初始化、`sys_module` 与注册校验、模块查询接口、三库集成与流水线收口、M1 门禁核对、测试报告与 README、跨阶段基座登记 |
| 三 后端基础能力 | 配置管理（真实读取 / 环境分层 / 启动校验）、日志体系、健康检查 |
| 四 CI 流水线 | CI 流水线激活（冒烟层 / 重验证层 / exists 守卫 / 覆盖率门禁 / CI 基础镜像） |

**范围外**：

- 认证与安全、RBAC 权限体系、通用能力等后续阶段交付物（见《总体项目规划》「工作分解结构（WBS）」节）。
- 业务模块（采购 `pur_`、收付款 `pay_`、供应商 `sup_` 等）由产品仓库承载，交付时随平台扩展接入登记；本阶段不种子业务模块。
- 前端页面与组件开发（前端组件库阶段及其后的前端全页面）；全文检索等后续阶段依赖。
- 租户开通 / 停用 / 配额等租户管理业务功能（RBAC 阶段），本阶段仅交付工程骨架、后端基座与基础能力。

> 边界说明：`.gitlab-ci.yml` 流水线**框架**（六类 job）已于准备期落地；阶段一代码落地后流水线随 job 的 exists 条件自动激活（04-1）。Python 3.14 与核心依赖 / `dmPython` 兼容性已由 01-6 验证通过（保持 3.14）。

## 4. M1 验收门禁 <a id="accept"></a>

门禁定义（《总体项目规划》「里程碑」节 M1 行，并入基座后扩展）：**骨架三项**——本地起服务、`/healthz` `/readyz` 正常、CI 流水线激活通过；**基座六项**——`BizError` 与统一响应生效、`BaseModel` 落库、三库拓扑可路由、租户隔离与批量迁移正确、模块注册校验生效、跨阶段基座登记齐备。逐项核对：

| 验收点 | 核对方式 | 对应需求 | 结论 |
| --- | --- | --- | --- |
| 本地起服务 | backend `uv run uvicorn` 启动无报错、/docs 可访问；frontend/frontend-mobile `npm run dev` 可访问默认页 | 01-1 ~ 01-6、03-1 | 待阶段完成核对 |
| 健康检查正常 | /healthz 存活 200；/readyz 依赖（Redis）正常时 200、依赖停时 503；`database` 检查项随数据访问底座（02-3）落地后启用 | 03-3 | 待阶段完成核对 |
| CI 流水线激活通过 | 含代码改动的 main 推送自动跑冒烟层且全绿；重验证层就绪项全绿（三库集成 job 随 02-13 激活） | 04-1 | 待阶段完成核对 |
| 异常体系生效 | `BizError` 抛错经全局处理器转统一响应 `{code, message, data}`；`NotFoundError` 过渡实现被替换 | 02-1 | 待阶段完成核对 |
| BaseModel 落库 | 雪花 ID / 软删除 / 审计字段 / 乐观锁 / 四库类型映射生效；三库迁移可执行 | 02-5 | 待阶段完成核对 |
| 三库拓扑可路由 | MySQL/PostgreSQL/达梦 DM8 驱动连通与迁移通过；租户请求路由到对应租户库 | 02-3、02-4、02-8、02-9 | 待阶段完成核对 |
| 租户隔离与批量迁移正确 | 跨租户访问被拒；租户库批量迁移演练通过 | 02-7、02-9 | 待阶段完成核对 |
| 模块注册校验生效 | 表前缀/错误码段/事件域冲突种子被启动与 CI 拒绝；GET /api/v1/modules 返回注册清单 | 02-10、02-11、02-12 | 待阶段完成核对 |
| 跨阶段基座登记齐备 | 缓存/数据范围/分片/事件/任务/审计基座的登记与回补窗口写入计划 | 02-16 | 待阶段完成核对 |

**结论**：阶段一 26 条需求在本阶段内闭环（跨阶段基座为登记 + 按对应阶段回补）；门禁核对与证据索引由需求 02-14 承载。
