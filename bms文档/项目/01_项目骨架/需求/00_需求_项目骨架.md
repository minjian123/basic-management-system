- **进度与验收**：需求文档只写「做什么与验收标准」；状态 / 完成日期 / 工时与验收门禁、证据归任务与计划文档。
- **依据**：《[总体项目规划](../../../规划/总体项目规划.md)》「工作分解结构（WBS）」节（WBS 阶段一）、「阶段内容与完成标准」节、《[总体项目规划](../../../规划/总体项目规划.md)》「阶段内容与完成标准」节、《[开发部署规划](../../../规划/开发部署规划.md)》「分阶段落地计划」节、《[架构设计 · 后端基础类体系](../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「基座分层」节「阶段交付与跨阶段基座契约」节、《[需求文档规范](../../../规范/需求文档规范.md)》。
- **范围调整（2026-09-12）**：后端基座**体系（骨架 + 接口占位）并入阶段一**并**按基座体系分层组织**（基座先立，认证 / RBAC / 通用能力等模块才有统一写法）；**阶段二 后端基座保留**，承载基座真实实现（数据访问底座 / Alembic 迁移与租户库初始化 / 多租户拓扑落库实测 / 模块注册与 `BaseModel` 落库 / 排序 DB 侧 / 三库真库与达梦实测）。本阶段基座只做「体系架构建成 + 接口占位」，机制类实现随后续回补。
- **基座与配置的边界**：基座对配置只提供**统一入口的方法与结构**（占位实现，不真实读取），真实 `config.toml` 读取与启动校验由 [03 后端基础能力](03_需求_后端基础能力.md) 的配置管理落地并回填基座登记。
- **「接口占位」口径**：机制类（数据访问 / 三库 / 租户 / 迁移 / 模块注册 / 三库集成）只落接口与抽象声明 + 占位实现（返回固定或批量数据），**不连真库、不跑迁移、不建表**，保证应用可启动、上层链路可先跑通。
- **开发环境前置（工作区模型）**：开发机按工作区并置克隆 bms 与产品仓库（《开发部署规划》「仓库获取」节）；`AGENTS.md`、`.opencode` 与知识图谱位于工作区根，bms 仓库文档根为 `bms文档/`。
- **首批交付范围**：01 工程骨架域的 monorepo 根骨架与三工程初始化、后端 `BaseObject` 根基类、有序集合、并发集合、Redis 有序封装与 `BaseRepository` / `BaseService` / `BaseSchema` 三套基类（后端基座首批，详见《架构设计 · 后端基础类体系》）。

## 2. 项目骨架目标与范围 <a id="goal"></a>

**阶段目标**（《总体项目规划》「阶段内容与完成标准」节）：**骨架三项**——本地起服务、`/healthz` `/readyz` 正常、CI 流水线激活通过；**基座体系**——基座分层与继承关系就位、`BizError` 与统一响应生效、与业务对接的最下层基类接口齐备（占位可跑、返回固定 / 批量数据）、配置 / 安全 / 日志基座结构就位、跨阶段基座登记齐备、补充扩展基座接口占位齐备。周期口径：骨架 3 周 + 基座体系（占位口径）约 3 周（兼职，串行）。

**范围内**（共 69 条需求，见第 3 节总清单）：

| 需求域 | 内容 |
| --- | --- |
| 一 工程骨架 | monorepo 根骨架、backend 工程初始化与分层目录、apps/desktop/frontend-mobile 工程初始化、依赖锁定与 Python 3.14 兼容验证 |
| 二 后端基座 | 根系 根基类与集合体系登记、模块基类（仓储 / 服务 / 请求响应 / 模型）、core 横切基座（异常落地 + 配置 / 安全 / 日志占位）、跨阶段基座登记、机制底座（数据访问 / 多租户拓扑 / 模块注册，接口占位）、前端组件支撑基座（验证码渠道 / 组织主数据 / 字典取数缓存 / 分片秒传 / 通知中心 / 列表查询偏好 / 检索查询 / AI 对话 / 用户偏好 / 租户自助 / 打印模板 / 图标与代码校验，接口占位） |
| 三 后端基础能力 | 配置管理（真实读取 / 环境分层 / 启动校验）、日志体系、健康检查 |
| 四 CI 与阶段验收 | CI 流水线激活、三库集成与流水线收口（占位）、M1 验收门禁核对、测试报告与 README |

**范围外**：

- 机制类**真实实现**（三库落库与拓扑、租户隔离实测、批量迁移、平台库表落库、模块注册落库、三库真库集成）——本阶段只做接口占位，随**阶段二 后端基座**填实现。
- 认证与安全、RBAC、通用能力等后续阶段交付物；前端页面与组件开发（前端组件库阶段及其后）；租户开通 / 停用 / 配额等租户管理业务功能（RBAC 阶段）。
- 业务模块（采购 `pur_`、收付款 `pay_`、供应商 `sup_` 等）由产品仓库承载，交付时随平台扩展接入登记。

> 边界说明：`.gitlab-ci.yml` 流水线**框架**（六类 job）已于准备期落地；阶段一代码落地后流水线随 job 的 exists 条件自动激活（04-1）。Python 3.14 与核心依赖 / `dmPython` 兼容性已由 01-6 验证通过（保持 3.14）。
