## 1. 域说明 <a id="intro"></a>

本域对应阶段一域「CI 流水线」（WBS 03，收窄后由原 05 域拆分而来——原 05 域的「三库集成测试 / M2 门禁核对 / 测试报告」已迁入**阶段二 后端基座** 域 05）。覆盖 `.gitlab-ci.yml` 分层流水线的激活与门禁：冒烟层、重验证层、exists 守卫、覆盖率门禁与 CI 基础镜像。

**依据**：《[总体项目规划](../../../规划/总体项目规划.md)》「监控与报告」节、《[开发部署规划](../../../规划/开发部署规划.md)》「开发工作流与 CI」「分阶段落地计划」节、《[测试规范](../../../规范/测试规范.md)》、《[架构设计 · 测试与质量](../../../设计/架构设计/29_架构设计_测试与质量.md)》。
**目标**：含代码改动的 main 推送自动跑冒烟层且全绿；重验证层就绪项全绿；覆盖率低于阈值即红。

## 2. 需求 03-1：CI 流水线激活 <a id="r03-1"></a>

优先级：2（高）　|　状态：进行中　|　完成日期：—

**背景与动机**：流水线框架已在准备期落地但空载；阶段一代码落地后必须以真实代码激活，门禁才有意义——否则覆盖率、构建、健康检查等无自动校验，后续阶段的「CI 通过」完成标准无据可依。

**内容**（《开发部署规划》「开发工作流与 CI」节、《测试规范》）：

1. 激活口径（单人开发期直推 main 不走 MR）：`.gitlab-ci.yml` 既有 job 以 exists 守卫——`backend/` 存在跑 Python 系、`frontend/` 存在跑前端系；纯业务文档推送免 CI，基座文档改动（`bms文档/规范`、`资料`、`资源`、`基座文档清单.md`）触发 `base-integrity`。
2. main 冒烟层（含代码改动直推自动执行）：gate-smoke + base-integrity（基座路径改动时）+ ruff check + pyright + pytest（SQLite）+ ESLint + Vitest + 双端构建；任一步失败 pipeline 红。
3. CI 基础镜像：`deploy/ci/Dockerfile.backend`（python3.14 + uv + 预建 backend venv）与 `deploy/ci/Dockerfile.frontend`（node22 + 双工程 node_modules 预装），按三份锁文件合并哈希写 label；`ci-base-build`（prepare 阶段）自动重建并经宿主 daemon 本流水线即用。
4. 重验证层（仅 main）：Playwright E2E、三库集成测试（随阶段二 05-1）、镜像构建推 Registry、Trivy 扫描（CVSS ≥ 9 阻断，外网不可达暂缓不阻塞）、swagger.json 契约快照、Allure 归档导入 Kiwi TCMS；重验证层 job 以激活开关守卫，逐项修复就绪后开启。
5. 覆盖率门禁：pytest-cov（核心 ≥ 80% / 整体 ≥ 70% 为后续阶段达标线，骨架期按 70% 起步）与前端 Vitest coverage 接入，低于阈值 pipeline 红。

**完成标准**：含代码改动的 main 推送自动跑冒烟层且全绿；重验证层就绪项全绿（Trivy 暂缓项按暂缓口径标注）；覆盖率报告产出且低于阈值时 pipeline 红；纯业务文档推送不触发 CI，基座文档改动触发 `base-integrity` 且通过。
