## 4. 需求 01-3：backend 分层目录与职责 <a id="r01-3"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-09-10

**背景与动机**：任务 03 已产生具体代码类，若不先定分层与公共基座，重复实现与逐类返工会随类数量放大——需要公共根基类集中字符串输出、序列化、相等语义等常用方法，做到「改一处、全局生效」；日常分析与排查中，`set` 无序且字符串哈希随机化（同一集合跨进程遍历顺序都不同）、`dict` 仅插入序，日志 / 存档 / 比对无法稳定分析，大数据量下尤为突出，需要有序集合基座；并发场景下集合读写的正确性与性能是系统关键点，而 Python 生态没有现成的「有序 + 并发安全」集合（`sortedcontainers` 明确非线程安全，同类 C 扩展库已停更十余年），进程内存又无法跨副本共享——因此还需要进程内并发集合（读写锁 / 单锁 / 分片锁 / 快照四策略）与 Redis 跨副本方案，并补齐读-改-写原子语义。以上基座一次定型，后续模块只扩展基类、不改业务类。

**内容**（《项目规划说明》「项目目录结构」节、《后端开发规范》「目录与分层职责」节「模块组织」节「后端基座体系」节）：

1. `backend/app/` 分层目录与首版文件（`__init__.py` 均带中文模块 docstring）：
   - `core/`：`config.py`（配置加载，02-1）、`security.py`（安全占位）、`exceptions.py`（异常体系，02-3）
   - `api/`：`deps.py`（公共依赖 `get_db` 等）、`router.py`（聚合注册）、`health.py`（健康检查，02-4）；模块目录 `api/{模块}/` 随模块按单数名词建
   - `models/`：`base.py`（BaseModel 基类，03-2）、模块文件 `{模块}.py`
   - `schemas/`：`common.py`（统一响应模型 ApiResponse/PageResponse，02-3）
   - `services/`：模块服务 `{模块}_service.py`（XxxService 类）
   - `repositories/`：模块仓库 `{模块}_repository.py`（XxxRepository 类，数据源路由，03 域）
   - `db/`：`engine.py`（引擎工厂）、`session.py`（会话工厂与 get_db，02-5）
   - `tasks/`（Celery 任务占位）、`ws/`（Socket.IO 占位）、`i18n/`（语言包占位）——目录与占位文件就位，实现随对应阶段
   - `alembic/`（03-6）、`tests/`（与 app 同构：tests/api/、tests/services/ 等）
2. 分层调用规则（在每层 `__init__.py` docstring 中写明）：
   - api 层只做参数校验与路由分发，依赖注入（`db: AsyncSession`、`redis: Redis`），**禁止直接操作模型、禁止写业务逻辑**
   - services 层承载业务逻辑与事务边界（`with session.begin()`），**禁止直接拼 SQL、禁止绕过 repositories**
   - repositories 层承载数据访问与数据源/分片路由，**禁止承载业务规则**
   - models/schemas 只放 ORM/Pydantic 模型，**禁止写业务逻辑**
3. 路由注册约定：模块内 `APIRouter(prefix="/{资源}", tags=["{模块}"])`，`app/api/router.py` 统一 include；模块四件套 models + schemas + services + repositories（+ api 路由）缺一不可
4. repositories / services / schemas 三套公共基类：BaseRepository（统一 CRUD 契约 + 内存基线通用实现，exists/count 派生方法）、BaseService（委派仓储 + 不存在语义）、BaseSchema（Pydantic 公共配置）；ORM BaseModel 仍归 03-2，本需求只留继承点
5. 继承约定落入《后端开发规范》（新建类必须继承对应基类，禁止绕过基类另起炉灶）；示例模块 demo 三件套改继承基类并回归
6. 并发集合与并发安全（嵌套子任务 01-3-2）：进程内并发有序集合（读写锁/单锁/分片锁/快照替换四种策略 + 原子复合方法 + 快照遍历）+ Redis 有序结构封装（ZSET/Hash/List 映射、Lua 原子复合操作、跨副本版本号一致性）；微基准与阶段压测验证
7. Redis 复合操作与并发语义（嵌套子任务 01-3-3）：`replace_if_equal` / `get_and_remove` 以 Lua 原子实现；`update_atomic` 以 WATCH+MULTI 乐观重试（默认上限 3 次，超限抛 `ConcurrentConflictError`）；`get_locked` 异步上下文 WATCH 提交（冲突上抛不重试）；真实 Redis integration 用例（标 `integration`）随 05-02 执行

**完成标准**：目录树与上述清单逐项一致；各层 `__init__.py` docstring 写明职责与禁止项；新建一个示例模块 `demo`（占位 CRUD 空壳）按四件套 + 路由注册走通，证明分层与注册机制可用；三套基类就位且 demo 三件套继承后测试全绿（覆盖率 100%）。

**参考文档**：《项目规划说明》「项目目录结构」节、《后端开发规范》「目录与分层职责」节「模块组织」节「后端基座体系」节、《命名规范》第 3/6 节

## 5. 需求 01-4：frontend 工程初始化 <a id="r01-4"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-09-10

**背景与动机**：管理端是业务主要入口，需先打通与后端的契约（代理 + `{code, message, data}` 解析 + OpenAPI 类型生成）并固化 TS / ESLint / Vitest 基线；否则每个页面各写一套请求与类型，契约变更时返工面不可控。

**内容**（《项目规划说明》「前端」「环境与配置」节、《前端开发规范》第 2/4/11 节）：

1. 技术基线：Vue 3 + Vite + **TypeScript**（strict 开启）；UI 库 Element Plus；SCSS 样式；npm 管理
2. `frontend/package.json` 依赖清单：`vue`、`vue-router@4`、`pinia`、`axios`、`element-plus`、`vue-i18n`、`socket.io-client`（预留）；devDependencies：`vite`、`typescript`、`vue-tsc`、`eslint` + `eslint-plugin-vue`、`prettier`、`vitest`、`@vue/test-utils`、`openapi-typescript`（契约生成）；`.nvmrc` 固定 `22`
3. `src/` 目录：`api/`（`http.ts` Axios 实例 + `types.ts` 生成类型占位 + `模块.ts` 接口定义）、`router/`（动态路由骨架 `routes.ts`，不硬编码业务路由表）、`stores/`（`useUserStore` 等占位）、`views/`（默认首页）、`layouts/`（基础布局壳）、`components/`、`i18n/`（`index.ts` + `zh-CN.ts`/`en-US.ts`）、`utils/`
4. 工程配置：`vite.config.ts`（`@` 别名、dev server 代理 `/api` → `http://localhost:8000`、`/docs` 不代理）；`.env.development`（`VITE_API_BASE=/api`）；ESLint + Prettier 配置（与规范一致，CI 强制）；TS 统一响应类型 `ApiResponse<T> = { code; message; data }`、`PageResponse<T>` 手写基类（openapi-typescript 生成类型随 05 域契约接入）
5. Axios 基线（`src/api/http.ts`）：请求拦截器预留 Bearer token 注入位（access token 仅存内存）、响应拦截器统一处理 `{code, message, data}`（code≠0 走统一错误提示）；401/会话失效处理留 TODO 占位（阶段四接入）
6. 前端基础类（嵌套子任务 01-4-1）：契约公共类型（`BaseEntity`——id 为 string、`BasePageQuery`）、`BaseApi`（模块 API 类基类）、`createCrudStore`（Pinia 通用 CRUD store）、`stableStringify`（稳定序列化）；双工程同款落地；《前端开发规范》增补继承约定；**ID 口径**：数据库 BIGINT 与 JOIN/索引不变，API 出参 `str(id)`、入参 `int(id)`，前端一律 string（雪花 ID 超 JS 安全整数，实测 number 丢精度）
7. 前端公共组合式与工具基座（嵌套子任务 01-4-2）：`useRequest`（异步状态 + 竞态保护）、`useListPage`（分页列表公共逻辑）、`validators`（常用校验与规则工厂）、`useTabs` 核心（Tab 单例 + `bms_open_tabs` 持久化 + 白名单，UI/路由随布局阶段）、`EntityStatus` 状态映射；`mountWithPlugins` 测试基座；双工程同款落地

**完成标准**：`npm ci` 通过；`npm run dev` 访问默认页（标题「BMS 基础管理系统」、显示 backend `/` 返回的 name/version，证明代理与响应解析链路通）；`npm run build`、`vue-tsc`、ESLint、`vitest run`（1 条冒烟用例）全通过；`.nvmrc` 生效（`node -v` ≥ 22）；前端基础类（01-4-1）双端落地且测试全绿，ID 字符串口径登记进 02-3/03-2。

**参考文档**：《项目规划说明》「前端」「环境与配置」节、《前端开发规范》第 2/4/11 节、《命名规范》「前端命名」节

## 7. 需求 01-6：依赖锁定与 Python 3.14 兼容验证 <a id="r01-6"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-09-10
