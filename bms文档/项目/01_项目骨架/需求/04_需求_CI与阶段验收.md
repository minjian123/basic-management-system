## 1. 域说明 <a id="intro"></a>

本域对应阶段一「CI 流水线激活与阶段验收」，覆盖四块：流水线激活（冒烟层 / 重验证层 / exists 守卫 / 覆盖率门禁 / CI 基础镜像）、三库集成与流水线收口（**接口占位**）、M1 验收门禁核对、阶段测试报告与 README。原「后端基座」域的三库集成 / 门禁核对 / 测试报告三条需求并入本域（后端基座并入阶段一后，验收口径统一为 M1）。

**依据**：《[总体项目规划](../../../规划/总体项目规划.md)》「里程碑」节（M1）、「监控与报告」节、《[开发部署规划](../../../规划/开发部署规划.md)》「开发工作流与 CI」节、《[测试规范](../../../规范/测试规范.md)》、《[架构设计 · 测试与质量](../../../设计/架构设计/32_架构设计_测试与质量.md)》「CI 流水线」节。

**目标**：含代码改动的 main 推送自动跑冒烟层且全绿；重验证层就绪项全绿；覆盖率低于阈值即红；M1 门禁（骨架三项 + 基座六项 + 验收留痕，共 10 个验收点）有可复现证据；阶段测试报告与 README 收口。

## 2. 需求 04-1：CI 流水线激活 <a id="r04-1"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-09-14

**背景与动机**：流水线框架已在准备期落地但空载；阶段一代码落地后必须以真实代码激活，门禁才有意义——否则覆盖率、构建、健康检查等无自动校验，后续阶段的「CI 通过」完成标准无据可依。

**内容**（《开发部署规划》「开发工作流与 CI」节、《测试规范》「覆盖率要求」节）：

1. 激活口径（单人开发期直推 main 不走 MR）：`.gitlab-ci.yml` 既有 job 以 exists 守卫——`backend/` 存在跑 Python 系、`frontend/` 与 `frontend-mobile/` 存在跑对应前端系；纯业务文档推送免 CI，基座文档改动（`bms文档/规范`、`资料`、`资源`、`基座文档清单.md`）触发 `base-integrity`
2. main 冒烟层：gate-smoke + base-integrity（基座路径改动时）+ ruff check + pyright 类型检查 + pytest（SQLite）+ ESLint + Vitest（frontend / frontend-mobile 双端）+ 双端构建 + 模块注册清单校验（`backend/ops/check_modules.py`）；任一步失败 pipeline 红
3. CI 基础镜像：`deploy/ci/Dockerfile.backend`（python3.14 + uv + 预建 backend venv）与 `deploy/ci/Dockerfile.frontend`（node22 + 双工程 node_modules 预装），按锁文件哈希写 label；`ci-base-build` 自动重建（push 失败按 best-effort 降级用单 runner 本机镜像，不阻塞冒烟层）
4. 重验证层（仅 main）：Playwright E2E、三库集成测试、镜像构建推 Registry、Trivy 扫描（**CRITICAL / HIGH 阻断**，外网不可达暂缓）、swagger.json 契约快照、Allure 归档导入 Kiwi TCMS、缺陷自动上报（任一自动化 job 失败即 `defect_capture.py` 产出 REPRO 包并建 / 复用 GitLab Issue）；以 `deploy/ci/verify-enabled` 激活开关守卫，逐项修复就绪后开启
5. 覆盖率门禁：pytest-cov（骨架期整体 ≥ 70%，核心模块 ≥ 80% 待模块路径确定后接入）与前端双端 Vitest coverage（整体 ≥ 70%、全量 `src/**` 采集）接入，低于阈值 pipeline 红

**完成标准**：含代码改动的 main 推送自动跑冒烟层且全绿（含 pyright 类型检查与模块注册清单校验）；重验证层就绪项全绿（Trivy 暂缓项按暂缓口径标注）；后端与前端覆盖率报告产出且低于阈值时 pipeline 红；纯业务文档推送不触发 CI（不建流水线），基座文档改动触发 `base-integrity` 且通过。

**参考文档**：《总体项目规划》「里程碑」节（M1）、「监控与报告」节、《开发部署规划》「开发工作流与 CI」节、《测试规范》「覆盖率要求」节

> 注：两条实现遗留——① Allure 结果当前仅归档 `allure-results` / `allure-report`，**导入 Kiwi TCMS 尚未接线**（Kiwi 结果导入口径待验证），随 04_01 实施；② CI 基础镜像 push 报 `blob unknown`，按 **best-effort** 处置（单 runner 本机镜像即可用，不阻塞冒烟层），恢复强制推送待 registry 排查。两条已在《项目骨架计划》「风险与对策」节登记。

## 3. 需求 04-2：三库集成与流水线收口（接口占位） <a id="r04-2"></a>

**内容**（《测试规范》「三库方言测试」节、《开发部署规划》「开发工作流与 CI」节）：

2. 拓扑路由用例骨架：租户库路由、跨租户隔离、批量迁移正确性的用例文件与断言位就位（对占位实现断言固定数据）
