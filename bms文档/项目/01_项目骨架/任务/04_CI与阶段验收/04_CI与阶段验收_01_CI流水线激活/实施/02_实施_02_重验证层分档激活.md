## 2. 实施概览 <a id="overview"></a>

```mermaid

    A[就绪评估<br/>四项前置与收益排序] --> B[开关分档<br/>verify/contract·defect·report·image·e2e·db]
```

结论：重验证层由「单开关全开/全关」改为**六档分档**；本轮开启 **P1**（`contract` 契约快照、`defect` 失败自动上报）与 **P2**（`report`：Allure 结果归档 + 结果导入 Kiwi）；`image`（P3）、`e2e` / `db`（P4）按前置登记待开。

## 3. 实施过程 <a id="process"></a>

1. **就绪评估**：逐项盘点四项前置（E2E / 三库真库 / 镜像 + Trivy / Allure→Kiwi），实测 `mjbk → ghcr.io` 可达（Trivy DB 可拉）、`backend/Dockerfile` 与 `apps/desktop/Dockerfile` 不存在（P3 前提）、`tests/e2e` 与 `--e2e-headless` 不存在（P4 前提）、`ops/test_db.py` 的 create/migrate/drop 与 `alembic/env.py` 在线分支仍为占位（P4 前提）；据此定 P1 → P2 → P3 → P4 顺序并写入计划 §3.1「重验证层激活路线」。
2. **开关分档**：`.gitlab-ci.yml` 中 12 处 `deploy/ci/verify-enabled` 全部改为**档位文件**——`e2e-playwright`→`verify/e2e`、`.integration-base`（三库）→`verify/db`、`backend-image` / `frontend-image` / `container-scanning`→`verify/image`、`swagger-snapshot`→`verify/contract`、`allure-report`→`verify/report`、`defect-capture`→`verify/defect`；文件头补分档语义与各档前置；镜像两个 job 原「仅 Dockerfile 守卫」改为档位守卫（避免空跑）。
3. **修复报告 job（三处实质错误）**：① 原脚本引用不存在的 `tests/unit` → 改为全量 `pytest -q --alluredir=allure-results`；② `allure-pytest` / `kiwitcms-pytest-plugin` 未在依赖 → `uv add --group dev`（allure-pytest 2.16.0、kiwitcms-pytest-plugin 15.4、tcms-api 15.0）；③ 原以为 `pip install allure-cli` 可生成 HTML 报告（Allure CLI 是 Java 工具，非 pip 包）→ 改为只归档 `allure-results/`，HTML 由需方按需生成。
4. **Kiwi 服务账号与凭据**：在容器内新建 CI 专用账号 `ci-runner`（随机口令，**只落 `deploy/.env` 与本机 `~/.tcms.conf`，不入库**）；项目 CI/CD 变量注册 `TCMS_API_URL`（内网 HTTP 入口）、`TCMS_USERNAME`、`TCMS_PASSWORD`（masked，经 GitLab API 创建）。
5. **内网 HTTP 入口**：Kiwi 容器仅映射 8443（HTTPS，自签名证书 SAN 为容器内主机名 → CI 用 IP 访问必然校验失败），且应用层 `SECURE_SSL_REDIRECT` **硬编码为真**（`tcms/settings/common.py`，不能用环境变量关闭）。故：`deploy/compose/kiwi.yml` 增加 `8061:8080` 映射并挂载 `deploy/compose/kiwi-nginx.conf`（基于镜像内 `/Kiwi/etc/nginx.conf`，仅把 8080 的 301 跳转改为**反代本机 8443 且跳过上游证书校验**）；Django 侧仍视为 https，不再跳转。同步文件到 mjbk 后用 **`docker compose --env-file /home/minjian/deploy/.env -f compose/kiwi.yml up -d`** 重建（见 [§4](#issues) 第 4 项）。
6. **导入链路验证**：`~/.tcms.conf` 指向 `http://<mjbk>:8061/xml-rpc/`，以 `TCMS_PRODUCT` / `TCMS_PRODUCT_VERSION` / `TCMS_BUILD` / `TCMS_PREFIX` 参数化——先以 `tests/api` 子集验证（`added: TP-2` / `TR-2`），再以**全量**验证：`417 passed / 7 skipped`（58.78s），结果成功写入平台。
7. **测试稳健性修正**：全量 + `--kiwicms` 首跑失败（`StopIteration`）——`tests/models/test_base_model.py` 的雪花 ID 用例直接 patch 了**全局 `time.time`**，插件 / IDE shim 等外部调用方读时钟即耗尽序列。改为 patch 为**隔离的假 time 模块**（`_fake_time_module`，序列用尽回落到末值），保留原时钟序列语义且不影响外部调用方。
8. **档位文件创建**：`deploy/ci/verify/contract`、`verify/defect`、`verify/report`（内容说明该档管控 job、前置与关档方式）。
9. **登记**：计划 §3.1 新增「重验证层激活路线（分档开关与顺序）」；测试报告 §1 / §2 / §4 / §5 同步（重验证层就绪度、遗留项 11 由「待接线」改「已接线」、下阶段建议指向计划 §3.1）；需求 04-1 追加「重验证层接线收口」注块。

| --- | --- | --- | --- |
| 1 | 单开关无法分批激活：若创建 `verify-enabled`，未就绪的 E2E / 三库会直接让流水线变红 | 12 处引用同一路径（全开 / 全关） | 改为六档文件 `deploy/ci/verify/*`，逐档开启；文件头注释与计划 §3.1 登记口径 |
| 2 | Kiwi 插件按环境变量配 url / 凭据无效（报 `Config file 'c:/tcms.conf' not found`） | tcms-api 走**文件配置**（`~/.tcms.conf`），插件 `TCMS()` 未读环境变量 | job 内以 `printf` 写 `~/.tcms.conf`（600），凭据仍来自 CI/CD 变量；`TCMS_PRODUCT` 等产品参数走 job `variables` |
| 3 | 8061 反代 uwsgi 仍 302（跳 `/init-db/` 或 HTTPS） | Kiwi 应用层 `SECURE_SSL_REDIRECT` 硬编码为真 | nginx 8080 改为反代**本机 8443（HTTPS）并 `proxy_ssl_verify off`**，Django 看到 https scheme，链路即通（`/xml-rpc/` 200 `application/xml`） |
| 4 | **重建容器后 Kiwi 落到未初始化态**（DB 环境变量为空，全部请求 302 到 `/init-db/`） | 在 `compose/` 目录直接 `docker compose -f kiwi.yml up -d` 时**未传 `--env-file`**（compose 目录下无 `.env`，变量插值为空） | 改用 `cd /home/minjian/deploy && docker compose --env-file /home/minjian/deploy/.env -f compose/kiwi.yml up -d`；已核验容器内 `KIWI_DB_*` 非空（该命令口径已记入本节与本文件） |

| 6 | 首次导入把自动用例建进了**策展产品**（34 条重复） | 插件按用例 summary（= pytest nodeid）匹配，与中文策展用例标题不一致即新建 | 清理后改口径：导入到**独立产品「BMS 自动化用例（CI）」**；策展库「BMS 基础管理系统」保持 69 条不变（清理与演练数据删除均已执行） |
| 7 | 新登记的策展用例编号为 **528**（非预期的 70） | Kiwi 的 `TestCase` 编号**跨产品全局自增**，自动用例已占用 70 ~ 527 | 归属已核验为策展产品「平台骨架」分类下（产品 1 用例 70 条 = 1 ~ 69 + 528）；编号跳号属平台机制，登记于本记录与 [§6](#deviations) |
| 8 | `attic`：allure job 的 `tests/unit` 路径、`pip install allure-cli`、镜像 job 的 Dockerfile 守卫 | 均为 04-01 阶段未激活时留下的口径 | 已随本轮一并修正（[§3](#process) 第 3 步） |

## 6. 偏差与遗留 <a id="deviations"></a>

- **口径变更（相对 04-01）**：重验证层开关由「单文件 + 全开」改为「六档分档」；镜像 job 由「Dockerfile 守卫」改为「档位守卫」；Allure job 由「解析 Allure 报告导入」改为「`kiwitcms-pytest-plugin` 执行期直写平台（`~/.tcms.conf` 配置）+ 结果归档」。均已在 `.gitlab-ci.yml` 注释、需求 04-1 注块与计划 §3.1 登记。
- **基础设施变更（mjbk，已入库声明）**：`deploy/compose/kiwi.yml` 增 `8061:8080` 映射并挂载 `deploy/compose/kiwi-nginx.conf`（8080 反代 8443 且跳过上游证书校验）；mjbk 上保留 `kiwi.yml.bak-20260915` 备份。**重建命令必须带 `--env-file`**（[§4](#issues) 第 4 项）。
- **凭据与账号**：Kiwi 服务账号 `ci-runner`（含随机口令）仅存 `deploy/.env`（gitignore）与本机 `~/.tcms.conf`；GitLab 项目 CI/CD 变量 `TCMS_API_URL` / `TCMS_USERNAME` / `TCMS_PASSWORD`（masked）。
- **编号口径变更**：Kiwi `TestCase` 编号跨产品全局自增——策展库后续新增用例编号会跳号（本轮为 **528**）；已在需求 04-1 注块与《测试规范》口径下按「编号以平台为准」执行，后续如需连续编号需另立产品级编号策略（已登记为观察项，不占排期）。
- **遗留（P3 / P4，计划 §3.1 已逐条登记）**：`image` 档待 `backend/Dockerfile` / `apps/desktop/Dockerfile`（Trivy 已确认可达 `ghcr.io`）；`e2e` 档待 `tests/e2e` 用例、`--e2e-headless` 选项、Playwright 依赖与浏览器、job 内服务编排；`db` 档待 `ops/test_db.py` 实现 + `alembic/env.py` 在线分支 + 方言用例命名 + masked 变量。
- **无新增产品缺陷**：本轮发现的问题均为 CI / 平台配置与测试稳健性问题，已当场修复并留痕（[§4](#issues)）。
