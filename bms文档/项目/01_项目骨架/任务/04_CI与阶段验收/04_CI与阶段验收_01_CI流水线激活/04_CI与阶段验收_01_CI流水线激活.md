## 2. 任务内容 <a id="content"></a>

1. main 冒烟层激活：gate-smoke + base-integrity（基座路径改动时）+ ruff check + **pyright 类型检查**（`backend-typecheck` job，已于 2026-09-14 补入）+ pytest（SQLite）+ ESLint + Vitest（apps/desktop / frontend-mobile 双端）+ 双端构建；各 job 以 exists 守卫随目录落地激活
2. **模块注册清单校验**：CI 接入 `backend/ops/check_modules.py`（模块注册项唯一性与格式校验），失败即 pipeline 红
3. **覆盖率门禁**：后端 pytest-cov 整体 ≥ 70%（核心模块 ≥ 80% 待模块路径确定后接入）；前端 Vitest coverage 双端接入（`test:cov`，全量 `src/**` 采集、阈值整体 ≥ 70%），低于阈值 pipeline 红
4. CI 基础镜像：`deploy/ci/build-base.sh` 按三份锁文件哈希 label 自动重建（`ci-backend:py314` / `ci-frontend:node22`）；push 失败按 best-effort 降级用单 runner 本机镜像，不阻塞冒烟层
5. 重验证层就绪项与开关：分档文件 `deploy/ci/verify/{contract,defect,report,image,e2e,db}` 守卫（本任务先以单开关 `verify-enabled` 设计，2026-09-15 改分档并开 P1 + P2，见[实施 02](实施/02_实施_02_重验证层分档激活.md)）；Playwright E2E、swagger.json 契约快照、缺陷自动上报（`scripts/tools/defect/defect_capture.py`）、Allure 归档接线（结果导入 Kiwi 口径先验证）；Trivy 扫描（CRITICAL / HIGH 阻断）与三库真库 job 按就绪度开启
6. 流水线口径收口：`.gitlab-ci.yml` 注释与需求 / 规范一致（需求编号、Trivy 严重度、开关守卫条件），纯业务文档推送免 CI 的行为经实测确认

## 3. 完成标准 <a id="accept"></a>

含代码改动的 main 推送自动跑冒烟层且全绿（含 pyright 类型检查与模块注册清单校验）；后端与前端覆盖率报告产出且低于阈值时 pipeline 红；重验证层就绪项全绿（Trivy 外网与三库真库未就绪项按开关守卫口径标注）；纯业务文档推送不建流水线、基座文档改动触发 `base-integrity` 且通过。
