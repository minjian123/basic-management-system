## 2. 任务内容 <a id="content"></a>

1. 激活口径（单人开发期直推 main 不走 MR）：`.gitlab-ci.yml` 既有 job 以 exists 守卫——backend/ 存在跑 Python 系、frontend/ 存在跑前端系；纯业务文档推送免 CI，基座文档改动（`bms文档/规范`、`资料`、`资源`、`基座文档清单.md`）触发 `base-integrity`
2. main 冒烟层（含代码改动直推自动执行）：gate-smoke + base-integrity（基座路径改动时）+ ruff check + pyright + pytest（SQLite）+ ESLint + Vitest + 双构建；任一步失败 pipeline 红
   - **基础层已修复并全绿（2026-09-10）**：backend-test 修正 `cd backend` 与 `--cov=app`；base-integrity 豁免本地凭据文档链接（全新克隆误报）；镜像 job 改为仅以 Dockerfile 守卫（exists 为「任一命中」语义）
   - **CI 基础镜像（2026-09-10 并入）**：`deploy/ci/Dockerfile.backend`（python3.14 + uv + 预建 backend venv）与 `deploy/ci/Dockerfile.frontend`（node22 + 双工程 node_modules 预装），按三份锁文件合并哈希写 label；`ci-base-build`（prepare 阶段）自动重建且经宿主 daemon 本流水线即用；backend/frontend 各 job 不再现场安装依赖
   - 遗留（2026-09-10）：基础镜像 push 到 GitLab Registry 时对已有层报 `blob unknown`（层 HEAD 存在、manifest PUT 校验失败，疑似 registry 元数据/跨仓库 blob 挂载问题）；当前 push 降级为 best-effort（单 runner 本机镜像即用），待排查后恢复强制推送
3. 重验证层（仅 main）：Playwright E2E（SQLite 起 backend + 前端产物）、三库集成（阶段二 05-1）、镜像构建推 Registry（bms-backend/bms-frontend）、Trivy 扫描（CVSS ≥ 9 阻断；外网不可达暂缓不阻塞）、swagger.json 契约快照、Allure 归档导入 Kiwi TCMS
   - **激活开关（2026-09-10 约定）**：重验证层 job（e2e / 三库集成 / Trivy / swagger / allure / defect-capture）暂以 `deploy/ci/verify-enabled` 存在为守卫（当前跳过）；本任务逐项修复就绪后创建该开关文件激活
   - 待修复项（2026-09-10 基线检查）：e2e 需 node/前端构建与 `tests/e2e` 用例；集成需 DB 变量与 `tests/integration` 数据库用例；镜像需 Dockerfile；swagger/allure 需依赖与产物路径核对；defect-capture 需 Variables 与脚本实测
4. 覆盖率门禁：pytest-cov 接入（核心 ≥ 80% / 整体 ≥ 70% 为后续阶段达标线；骨架期阈值按 70% 起步）；前端 Vitest coverage 同步接入（全量 `src/**` 采集，阈值随流水线门禁定案）
5. 与阶段二衔接：重验证层三库集成 job 随阶段二「数据访问底座 / 多租户数据拓扑」就绪后真实执行（阶段二 05-1 承接三库集成与收口），本任务只保证冒烟层与门禁框架可用

## 3. 完成标准 <a id="accept"></a>

含代码改动的 main 推送自动跑冒烟层且全绿；重验证层就绪项全绿（Trivy 暂缓项按暂缓口径标注）；覆盖率报告产出且低于阈值时 pipeline 红；纯业务文档推送不触发 CI，基座文档改动触发 `base-integrity` 且通过。
