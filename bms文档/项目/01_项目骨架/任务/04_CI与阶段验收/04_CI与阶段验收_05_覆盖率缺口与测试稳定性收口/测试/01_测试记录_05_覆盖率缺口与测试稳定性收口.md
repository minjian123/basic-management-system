## 5. 已知项 <a id="known"></a>

| # | 现象 | 判断 |
| --- | --- | --- |
| 1 | `-n auto`（本机 24 worker）下，平台 API 用例偶发 `20001/401`（不同用例随机命中：`test_menu_metadata` / `test_plugins` / `test_dict_api` 等），约每 2 次全量命中 1 次；改 `-n 8` 后连续全绿 | **存量偶发**，与本任务改动无因果证据：把平台 conftest 用 `git stash` 回退到改动前，同样 2/3 次命中 401（基线取证见实施记录 P9）。判定为高并行下的鉴权链路资源竞争，已登记遗留并**另立小任务**定位 |
| 2 | `engkit` 仓 `uv run pytest` 全部 PASSED 但进程退出码 1（`safe-delete` 环境钩子在解释器收尾报 EPERM） | 环境已知项；未触及的用例文件同样复现，非仓库缺陷 |
| 3 | `preflight --full` 的工程级 pytest 步骤与前端 `typecheck/build` 步骤被判失败，但日志显示用例 `[100%]` 通过、失败原因是 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`（pytest 临时目录 / `dist` 批量删除 >5000 文件被 IDE 钩子拦截） | 环境已知项（IDE `safe-delete` 钩子），非用例或代码缺陷；需在无该钩子的环境（CI / 服务器）跑 `preflight --full` 复核 |
| 4 | 外部进程在本会话期间向 `bms` 提交了 `108f2caaa fix(search): …`（HEAD 变更导致一次预检的 run_once 缓存失效、并影响该次 `scripts/tools` ruff 结论复现） | 记录在案；最终结论以当前 HEAD 复检为准（`ruff check ../scripts/tools` 已通过） |
