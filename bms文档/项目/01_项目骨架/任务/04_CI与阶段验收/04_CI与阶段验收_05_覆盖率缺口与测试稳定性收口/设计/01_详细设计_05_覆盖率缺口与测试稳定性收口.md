## 1. 目标与边界 <a id="scope"></a>

**目标**：把后端全量覆盖率从 **99.64%（缺 126 行 / 48 分支）** 收回到 **100%（行 + 分支）**，并消除「同一套用例换工作目录（仓库根 / 工程级 cwd）结果不一致」的测试稳定性问题，使覆盖率硬门禁恢复「不达标即红、无需人工判读」的效力。

**范围内**：

1. 逐缺口补用例：服务公共出口（8 个 `domains/*/public.py`）、迁移 / 启动建表 / 注册表模块（`db/migration.py`、`db/migration_guard.py`、`db/bootstrap.py`、`registry/products.py`）的离线分支与错误分支；
2. 边角属性 / 分支：`services/module_registry.py` 三张注入表的「同键异值即拒」、`datasource/registry.py`、`services/table_registry.py`、`tenant/provisioning.py`、`core/config.py`、`testing/fixtures.py`；
3. 死代码处置：`permission_meta.services.permission_meta._session`（零引用）删除；
4. 测试稳定性：工程级 cwd 依赖（`test_heavy_command_guard`、`test_products`）、并行共享态（`test_modules`）、选测契约失效断言（`test_other_formats`）；
5. 门禁口径回写：《测试规范》§6 增「本地全量口径与集成用例定位」。

**范围外**：

| 项 | 归口 / 理由 |
| --- | --- |
| `02_09` / `02_10` / `02_11` 的三库真库实测 | 随部署窗口执行，本任务不碰 |
| 重构与缺口无关的用例 | 只修 §4.4 列出的 6 处，不做「顺手清理」 |
| 前端（Vitest）覆盖率与用例 | 前端覆盖率已 100%，本次零改动 |
| 除 §4.2 之外的一切业务行为变更 | 唯一获批的业务改动是产品清单**相对路径基准**（决策 q2=B） |

### 2.3 集成跳过现状 <a id="integration"></a>

- 57 条跳过**全部是逐用例自判**（`pytest.skip(...)` + 环境变量守卫：`BMS_TEST_DB_URL` / `BMS_TEST_REDIS_URL` / `IDP_TEST_*` / `BMS_TEST_MINIO_*`），**没有全局 `pytest_collection_modifyitems` 钩子**；
- `pytest.mark.integration` 仅作标记，不参与跳过判定；
- 结论：集成跳过与覆盖率采集**互不影响**——跳过的用例不产生采集数据，缺口因此体现为「本地缺行」。

### 4.2 业务代码唯一改动：产品清单相对路径基准 <a id="d-manifest"></a>

**问题**：`load_product_manifests` 的 docstring 写「相对路径按当前工作目录解析」，而 `config.dev.toml` 的 `../../mdm/deploy/registry/mdm.json` 是按 **`backend/`** 写的（注释亦写「相对 backend/」），`ops.gateway_config.configured_manifests` 同样按 `root/backend` 解析——三处口径分裂，导致工程级 cwd 下清单落空。

**改法**（决策 q2=B）：

| 项 | 改法 |
| --- | --- |
| 解析基准 | `bms_core/registry/products.py` 增模块常量 `_MANIFEST_BASE = resolve_backend_root("alembic.ini", anchor=Path(__file__))`（复用 `bms_core.core.paths`，不引入 alembic 依赖） |
| 路径规整 | 新增私有 `_resolve_manifest_path(raw)`：绝对路径原样；相对路径 `_MANIFEST_BASE / path` |
| 调用点 | `load_product_manifests` 改用它（**函数签名与返回不变**） |

## 7. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 业务微改（清单基准）影响其它消费方 | `ops.gateway_config` 已按 `root/backend` 解析（一致）；`ops.seed_module` 从任意 cwd 变得更稳；绝对路径注入路径不变。全量用例 + 定向 ops 用例双向验证 |
| 替身用例「测了分派没测语义」 | 真实语义仍由集成用例承担（三库 / 达梦），替身只补「本地不可达分支」的接线断言；在设计表里逐条标注覆盖手段，避免被当作语义证据 |
| 临时 ini / 临时仓库树用例依赖 Alembic 内部行为 | 全部用 `tmp_path` + `monkeypatch` 常量（`BACKEND_ROOT` / `REPO_ROOT` / `VERSIONS_ROOT`），并显式清两张模块级缓存；断言只锁返回值与异常类型 |
| 平台 conftest 会话级夹具改变既有用例行为 | 夹具只固定「清单集合」与「注入表复位后重载」，不改变播种与接口语义；改动后跑平台工程级全量 + 仓库根全量两种 cwd 复核 |
| 覆盖率反复（新增用例自身引入新的未覆盖分支） | 验证阶段只看「全包 100%」单一结论，不做模块局部豁免 |
