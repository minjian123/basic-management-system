## 1. 范围与依据 <a id="scope"></a>

按 [详细设计 §2 决策记录](../设计/01_详细设计_01_单库测试基座与护栏.md#decision)（22 条）实施，本轮交付**基座与护栏**，不改造存量用例：

- 单库夹具（按逻辑数据源、全 worker 共用、文件锁选主、会话开始清库）；
- 命名空间助手（唯一编码 / 断言限定 / 查询过滤三合一）；
- 三条护栏（G1 自建库 / G2 裸 int ID / G3 清理他人数据）+ `own_db` 白名单 + `--list-own-db` 导出；
- 护栏判定实现落 engkit（跨仓单源），bms 只留薄包装与配置；
- 用例先登记：Kiwi **2399**（`test/scripts/kiwi/cases/2026-11-01_阶段一04-06-01_单库测试基座与护栏.json`）。

## 4. 存量误杀核对（一次性） <a id="audit"></a>

按决策 21 对全仓做一次性扫描（不固化为 CI 步骤）：

| 轮次 | 命中 | 构成 | 处置 |
| --- | --- | --- | --- |
| 首轮 | 1036 | G1 873 / G3 163 / G2 0 | 抽样发现 G3 大面积误判：`cache.delete(key)`、集合对象 `.delete()` 等非 SQL 调用被当成“清理他人数据” |
| 修正后 | 880 | G1 873 / G3 7 / G2 0 | G3 收紧为「模块从 `sqlalchemy` 导入 `delete` **且**为裸 `delete(...)` 调用」；`.delete()` 属性调用不再判 |

结论：

1. **G2（裸 int ID）存量 0 命中**——03_05 已把原生 SQL 的 ID 参数统一过 `sqlite_id()`，规则作为回退护栏保留。
2. **G1（自建库）873 命中**是 04-6-2 的主改造面，集中在 `libs/bms_core/tests/{alembic,ops,tenant/seed}`、`services/{platform,tenant}/tests`。
3. G3 剩余 7 处需逐条判“真违规 / 应为 `own_db`”，归 04-6-2 分类台账。

## 5. 问题与处置 <a id="issues"></a>

| # | 现象 | 原因 | 处置 |
| --- | --- | --- | --- |
| 1 | G3 首轮 163 命中，抽样多为误判 | 仅按调用名 `delete` 判定，未区分 SQLAlchemy 与普通对象方法 | 增加“模块导入 `sqlalchemy.delete`”前提 + 只认裸 `delete(...)`；`self_test` 补两条向量锁死该口径 |
| 2 | `ns` / `shared_*` 夹具在子工程 rootdir 下取不到 | `pytest` 的 rootdir 落在 `libs/bms_core/pyproject.toml` 时 `addopts` 不含启动插件 | 与既有口径一致：这类套件须显式 `-p bms_testing_plugin`（预检 / CI 已注入），不改实现 |
| 3 | `@contextmanager` + `Iterator[...]` 被 pyright 判 deprecated | 新版类型检查要求 `Generator[...]` | 改注解为 `Generator[None]` |
| 4 | 共享库清理漏删 `-wal` / `-shm` | 清理规则只按后缀 `.db` | 追加 `-wal` / `-shm` 与 `.init*` 判定 |
