## 2. 任务内容 <a id="content"></a>

1. **单库夹具（按逻辑数据源）**：`platform` / `tenant` 各一个 SQLite 文件，全 worker 共用；WAL + `busy_timeout` + 有限次重试；schema 一次建成（按已导入模型的 `Base.metadata` 并集 + 启动种子），会话内不再重建。
2. **库文件生命周期**：pytest 会话临时库落仓内 `.cache/test/`，会话开始删库重建、会话结束保留（供排查）；联调 / 部署用 test 环境库仍落 `database/bms/test`，两者按用途分工，互不覆盖。
3. **命名空间助手**：新增 `bms_core/testing/namespace.py`，三合一——唯一编码生成（含 worker 与序号，可反查归属）、`assert_scoped(...)` 断言限定、`scoped(select, ns)` 查询过滤。
4. **三条护栏**：禁止为图省事自建 SQLite 文件（白名单除外）、禁止原生 SQL 直绑 int ID、禁止清理非本用例数据；接入开发环增量步骤与推送预检。
5. **白名单**：`@pytest.mark.own_db("理由")` 必填理由；静态护栏识别 marker 放行并导出白名单清单，供审计与收口统计。
6. **pytest 配置**：临时目录基址与保留策略纳入 `pyproject.toml`（`basetemp` 沿用 `.cache/pytest`，库目录 `.cache/test`），不散落 `%TEMP%`。
7. **产品仓复用验证**：`mdm` 仓经 `bms_core.testing` 接入同一夹具与护栏（至少一个服务套件迁移通过），不复制第二套实现。
8. **文档回写**：《测试规范》「并行隔离」「测试数据」「测试产物落点」「测试公共基座」节与《AI开发规范》红线「配置唯一来源 / 临时产物落点」。

## 3. 完成标准 <a id="accept"></a>

单库夹具在 bms 与 mdm 两仓可用（同一实现、零复制）；**至少一个试点套件**已切到 `shared_platform_db_url` / `shared_tenant_db_url` 并在并行下稳定（其余套件仍走旧夹具、主分支保持绿）；三条护栏在开发环增量扫描生效（违规样例必红、合规样例不误杀、`own_db` 放行）；白名单可导出审计且每条带理由；全仓误杀核对结论落实施记录；`bms_core/testing/` 新增模块与 engkit 护栏模块覆盖率 100%（行 + 分支）；两份规范口径回写完成。
