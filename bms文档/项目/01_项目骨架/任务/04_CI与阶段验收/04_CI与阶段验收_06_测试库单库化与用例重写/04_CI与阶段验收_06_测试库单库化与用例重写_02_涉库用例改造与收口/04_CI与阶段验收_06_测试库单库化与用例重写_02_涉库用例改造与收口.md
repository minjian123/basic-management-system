## 2. 任务内容 <a id="content"></a>

1. **分类台账**：按需求 04-6「口径修订」的 A~E 判据，对后端 580 个测试文件逐文件定档（含 mdm 仓 36 个文件），台账落本任务 `实施/`，作为改造进度与验收取数依据。
2. **A 类（不动）**：纯逻辑 / 契约 / 路由 / 静态护栏 / 安全边界用例，仅核对确实不触库（约 3243 用例）。
3. **B 类（机械改造）**：涉库 CRUD / 查询用例——自建引擎与 `create_all` 换共享夹具，固定编码 / 哨兵换唯一命名空间，删除自建库文件与临时目录（约 850 用例）。
4. **C 类（语义重写）**：依赖“空库 / 精确总数 / 全表集合相等”的用例——重写 arrange 与 assert，改为“命名空间限定 + 相对增量断言”，业务场景与错误码断言一律保留（约 334 用例，实测 38 文件）。
5. **D 类（白名单收口）**：建库 / 迁移 / 多库拓扑 / 每租户派生库用例进 `@pytest.mark.own_db` 白名单，逐条补理由，并把白名单压到最小集合。
6. **E 类（删除）**：功能已不存在的用例删除；删前核对覆盖率，不得以删除制造新缺口。
7. **临时文件必要性审计**：逐类清点 `tmp_path` / 临时库 / 落盘夹具，保留导出 / 上传 / 迁移 / 发布编排等“被测功能本身要写文件”的部分，其余取消。
8. **mdm 仓同步**：36 文件 / 226 用例按同口径改造并回归（任务文档统一记在本任务，mdm 仓不另建任务）。
9. **收口验证**：全量用例全绿且并行稳定；临时文件数量与磁盘占用较改造前下降 90% 以上；覆盖率口径（100% 行 + 分支）恢复并达标；实施与测试记录留痕。

## 3. 完成标准 <a id="accept"></a>

全量测试只使用 `platform` / `tenant` 两个 SQLite 文件；无“每用例一套库”残留（护栏零豁免例外）；A~E 台账逐文件闭合，白名单每条带理由且可审计；mdm 仓用例同步达标；全量用例全绿、并行与串行结果一致；临时文件数量与磁盘占用下降 ≥ 90%；覆盖率 100%（行 + 分支）达标。
