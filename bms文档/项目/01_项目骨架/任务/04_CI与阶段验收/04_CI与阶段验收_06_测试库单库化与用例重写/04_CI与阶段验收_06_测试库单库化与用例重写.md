> **立项缘由**：`03_05` 实施时实测，一次部分全量就产生 381 个 SQLite 库 / 82MB；`-n auto` 在 10 个工程根默认启用后又按 worker 数放大，Windows 下旧会话清理失败导致跨会话累积到百万文件 / 20GB+。根因是测试体系假设“每用例一套干净库”，与生产“一套库 + 多用户并发 + 数据叠加”相反。按用户口径：**全局只允许一套 SQLite**，用例叠加，前序数据等同他人业务数据不得清理；只有单例调 bug 才允许临时独立库。

## 2. 任务内容 <a id="content"></a>

1. **单库**：整个测试会话一个 SQLite 文件（全 worker 共用），WAL + `busy_timeout` + 有限重试；库文件落仓内 `.cache/`，会话开始清空。
2. **叠加语义**：用例只增不改他人数据，按唯一命名空间（编码 / 前缀 / 业务键）创建并限定查询；禁止依赖空库、禁止清理非本用例数据。
3. **例外通道**：`BMS_TEST_ISOLATED_DB=1` 仅用于单例调试。
4. **临时文件必要性审计**：逐类判断 `tmp_path` / 临时库 / 落盘夹具是否必要，取消“为图省事建库 / 拷目录”的部分；必要项（导出 / 上传 / 迁移 / 发布编排）保留并收敛落点。
5. **用例重写**：涉库用例按新口径重写；纯逻辑 / 契约 / 路由 / 静态护栏 / 安全边界用例保留；功能已不存在的用例删除。
6. **门禁**：禁止自建 SQLite 文件、禁止原生 SQL 直绑 int ID（统一 `sqlite_id()`）、禁止清理非本用例数据；临时目录基址与保留策略纳入 pytest 配置。
7. **文档**：回写《测试规范》《AI开发规范》相关口径。

## 3. 完成标准 <a id="accept"></a>

全量测试只使用一套 SQLite 文件；用例可重复执行、可叠加（前序数据保留）；全量用例全绿且并行稳定；临时文件数量与磁盘占用较改造前下降 90% 以上；无“每用例一套库”残留；覆盖率口径（100% 行 + 分支）恢复并达标。
