## 3. 任务内容 <a id="content"></a>

1. **单库（按逻辑数据源）**：`platform` / `tenant` 各一个 SQLite 文件（全 worker 共用），WAL + `busy_timeout` + 有限重试；pytest 会话临时库落仓内 `.cache/test/`、会话开始删库重建；联调 / 部署用 test 环境库仍落 `database/bms/test`。
2. **叠加语义**：用例只增不改他人数据，按唯一命名空间（编码 / 前缀 / 业务键）创建并限定查询；禁止依赖空库、禁止清理非本用例数据；事务回滚仅撤销本用例自身写入（`DbTestCase` 保留为 opt-in）。
3. **例外通道**：`BMS_TEST_ISOLATED_DB=1` 仅用于单例调试；单文件 / 单用例调试默认与 CI 同口径（共享 `.cache/test/` 库）。
4. **临时文件必要性审计**：逐类判断 `tmp_path` / 临时库 / 落盘夹具是否必要，取消“为图省事建库 / 拷目录”的部分；必要项（导出 / 上传 / 迁移 / 发布编排）保留并收敛落点。
5. **用例改造（分层处置）**：A 类纯逻辑 / 契约 / 路由 / 静态护栏 / 安全边界不动；B 类涉库 CRUD 用例机械改造；C 类“依赖空库 / 精确总数”用例语义重写（改为命名空间限定 + 相对增量断言）；D 类“建库即被测”进白名单保留独立库；E 类功能已不存在的用例删除。判据与范围见需求 04-6「口径修订」。
6. **门禁**：禁止为图省事自建 SQLite 文件（白名单除外）、禁止原生 SQL 直绑 int ID（统一 `sqlite_id()`）、禁止清理非本用例数据；命名空间助手（唯一编码 / 断言限定 / 查询过滤）落 `bms_core/testing/` 单源；临时目录基址与保留策略纳入 pytest 配置。
7. **文档**：回写《测试规范》《AI开发规范》相关口径。

## 4. 完成标准 <a id="accept"></a>

全量测试只使用 2 个 SQLite 文件（`platform` / `tenant` 各一，会话内共享）；用例可重复执行、可叠加（前序数据保留）；全量用例全绿且并行稳定；临时文件数量与磁盘占用较改造前下降 90% 以上；无“每用例一套库”残留；A~E 五类处置完成且白名单可审计（含 mdm 仓 226 个用例）；覆盖率口径（100% 行 + 分支）恢复并达标。
