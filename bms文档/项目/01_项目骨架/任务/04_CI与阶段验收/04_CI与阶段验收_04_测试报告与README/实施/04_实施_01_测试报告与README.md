## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先登记**：经 mjbk 容器内 Django shell 登记本任务 1 条用例并取得编号 **69**（产品「BMS 基础管理系统」/ 分类「平台骨架」/ P2 / CONFIRMED / 标签「自动化」/ `is_automated=True`），题面含报告齐备、两脚本输出、复盘清单、门禁转达标与 54/54、README 一致五项断言。
2. **治理脚本一（度量采集）**：新增 `scripts/tools/governance/collect_metrics.py`——① 阶段工期偏差（基线取计划「里程碑对照」M1 日期、排期起点取「自 YYYY-MM-DD 起排」，偏差率＝偏差天数 / 排期窗口）；② 缺陷分布与收敛（GitLab API `state=all`，按 `defect-auto` 聚合，凭据取 `deploy/.env`、无凭据降级不报错）；③ 覆盖率（后端 `uv run pytest --cov=app --cov-branch --cov-fail-under=70` 取 `Total coverage` 精确值，前端读 `coverage-summary.json`，`--with-frontend` 可重跑）；④ 用例执行统计（pytest 摘要 + 双端 Vitest 摘要 + Playwright 未启用标注）。只读、默认不落中间产物（`--out` 可选）。
3. **治理脚本二（复盘清单）**：新增 `scripts/tools/governance/review_stage.py`——八项自动核对（三类文档一致 / 基座自检（subprocess 复用 `check-status.py`、`check-base.py`）/ 门禁表结论齐备 / 阶段残留为 0 / 遗留项登记 / 报告与 README 就位 / 记录齐备 / Kiwi 编号引用），逐项打印「通过 / 不通过 + 证据」，有不通过则退出码 1。
4. **工具链登记**：`scripts/README.md` 新增 `tools/governance/` 行（与 `base-check/`、`check-docs/` 同构口径）。
5. **数据采集**：`collect_metrics.py --with-frontend --out /tmp/bms_metrics.json` 产出——工期偏差 `-13 天（提前，92.9% 于 14 天窗口）`、缺陷 `总数 1 / 打开 0 / 已闭环 1（准备期 #1 自动缺陷）`、后端覆盖率 `99.75%（语句 3668 未覆盖 3、分支 392 未覆盖 7）`、前端双端 `100%`、用例 `后端 417 passed / 7 skipped；前端各 4 文件 / 18 用例`。
6. **报告初稿**：按设计 §4.1 写 `bms文档/项目/01_项目骨架/01_测试报告_项目骨架.md`（四章节 + 「5. 复盘与经验教训」+ 附录「数据采集命令与原始输出」）；§4 遗留项按计划 §3.1 逐条登记（52 条，权威表指向计划；后补登核心模块覆盖率 / 前端覆盖率扩面两项，现为 55 条）。
7. **交叉审核**：第二 AI 独立只读复核（见 [§4](#issues) 审核结论），异常项当场处置。
8. **README 同步（四份）**：根 README（项目状态改「阶段一已完成 54/54 + M1 门禁全部达标」、快速启动补本地门禁命令块、目录结构补 `governance`、文档导航补阶段一四件套与报告）；`backend/README.md`（简介与目录结构刷新：`ops/`、`health/`、六类跨阶段与补充扩展基座、`tests/` 结构；快速启动补门禁；导航补基类清单与阶段一）；`apps/desktop/README.md`、`frontend-mobile/README.md`（阶段一交付现状与 `test:cov`，导航补阶段一与报告）。
9. **收口回写**：《需求总览》§4 门禁第 10 行转**达标**、§4 结论改「10 项全部达标 + 54/54」、§5 域地图 04 域 4/0；需求 04-4 元信息行 + 实施结果注块；任务 04_04 与域总览（4/4、8h 全部交付）；计划（头计数 18/0、§1 排期对象与工时 129h/0h、§1 排期口径与达成日、§2 加 04_04 行、§3 剩余表清空保留表头、§4 甘特改阶段一交付区间、§5 留痕行转达标、里程碑对照改「2026-09-15 已达成」）；`文档首页` 5.5（04 域 4/4）与 5.6（报告已交付）。
