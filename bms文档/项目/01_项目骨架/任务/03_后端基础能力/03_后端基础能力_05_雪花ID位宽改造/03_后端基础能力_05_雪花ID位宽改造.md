> **立项缘由**：当前雪花 `41 + 10 + 12 = 63 位`，WorkerId 上限 1024。租户独立部署（架构 39 支持「一租户一业务域一服务一库」）与微服务扩容会乘数放大进程数，1024 / 4096 都可能在中期触顶；而主键位宽一旦有生产数据，再改就是「数据迁移 + 停机 + 双写兼容」量级。开发期无存量，按用户拍板一次到位，直接上宽 ID。

## 2. 任务内容 <a id="content"></a>

1. **位宽与位段**：`48 时间 + 40 机器 + 38 序列 = 126 位`（约 8925 年 / 约 1.1 万亿进程 / 约 2749 亿 ID/ms/进程）。
2. **存储类型**：`DECIMAL(38,0)`（达梦官方精度上限 38 位；2¹²⁶−1 落在 38 位十进制内）；SQLite 测试库用 TEXT 变体，避免 NUMERIC 转 REAL 丢精度；MySQL / PostgreSQL / 达梦统一 DECIMAL。
3. **统一类型**：新增 `SnowflakeId`（TypeDecorator）覆盖主键、逻辑外键、`tenant_id`、`created_by` / `updated_by`、`parent_id` 等全部雪花 ID 列；静态护栏禁止残留裸 `BigInteger` ID 列。
4. **生成器**：`bms_core/core/id.py` 位宽常量与时间/机器/序列位移同步；Python int 无上限，接口与日志按字符串处理。
5. **接口契约**：统一 `SnowflakeIdStr`（内部 int、JSON 输出 str）；前端 TS 类型同步 `number → string`，禁止 `Number()` / `parseInt()` 处理 ID。
6. **切换**：删库重建（开发期无存量）；dev / test / prod 停机切换，三环境统一；切换后旧 63 位 ID 不再生成。
7. **口径回写**：《数据库设计 · 总览》「主键」、数据规范、《命名规范》、《后端基类清单》雪花 ID 行、《架构设计 · 部署与运维》、数据库表文件的 `BIGINT` 描述。

## 3. 完成标准 <a id="accept"></a>

四库建表为 `DECIMAL(38,0)`（SQLite 为 TEXT 变体）且读写无精度丢失；同一进程 ID 单调递增且落在 126 位内；所有接口 ID 字符串输出、前端类型同步；全仓无裸 `BigInteger` 雪花 ID 列（静态护栏断言）；三环境停机切换完成；既有用例全绿、契约快照零漂移；新增 / 改动模块覆盖率达标（口径见《[AI开发规范](../../../../../规范/AI开发规范.md)「覆盖率要求」）。
