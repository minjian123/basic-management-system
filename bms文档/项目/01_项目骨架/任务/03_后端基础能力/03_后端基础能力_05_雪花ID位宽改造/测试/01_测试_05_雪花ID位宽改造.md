## 3. 覆盖范围与结果 <a id="cases"></a>

### 3.1 生成器（2393）

- 位段常量 48/40/38、`MAX_ID = 2^126-1`（38 位十进制）、`MAX_WORKER_ID = 2^40-1`；
- WorkerId 0 与上界合法、越界抛 `ValueError`；
- 同进程 500 个 ID 严格递增、机器段正确、总位宽不超 126；
- 序列回绕（压缩到 2 位）等待下一毫秒，不重复、不回退；
- 时钟回拨 ≤5ms 追平、超限抛 `RuntimeError`。

结果：**5 passed**。

### 3.2 存储类型（2394）

- 四方言 DDL：SQLite `TEXT`、MySQL / PostgreSQL / 达梦 `DECIMAL(38, 0)`，且无 `AUTO_INCREMENT` / `SERIAL`；
- 绑定：SQLite 38 位补零、其余方言整数；接受 `Decimal` / 数字字符串；NULL 原样；
- 非法值：负数、超上限、布尔、非整数 `Decimal`、浮点、未知类型均抛 `ValueError`；
- 读回：`int` / `Decimal` / 补零字符串统一转 int；
- SQLite 真库：`0` / `2^63+1` / `MAX_ID-1` / `MAX_ID` 往返不丢精度、定长 38、字典序 = 数值序、范围查询正确；
- ORM 往返：主键 / 逻辑外键 / `parent_id=0` 读回恒为 int。

结果：**15 passed**；`test_type_mapping` 四方言类型映射同步更新并通过。

### 3.3 契约字符串化（2395）

- JSON 输出：`id` / `tenant_id` / `created_by` 均为字符串（含 126 位上限值）；
- python dump：`id` 经全局兜底为字符串、`created_by` 保持 int（`when_used="json"` 口径）；
- 请求校验：接受十进制字符串（含补零）并转内部 int；
- JSON Schema：校验模式 integer、序列化模式 string；
- 真实端点：平台锁定 / 解锁返回 `locked_by` / `unlock_by` 为字符串。

结果：**4 passed** + 平台 / 服务定向断言通过。

### 3.4 静态护栏（2396）

- `engkit base snowflake-ids --self-test`：合规 / 非 ID 计数列 / 裸 BigInteger / schema 残留 / 白名单 5 个向量通过；
- 全仓扫描：922 个文件通过（白名单 7 条）；
- 前端扫描：`Number(xxxId)` / `parseInt(xxxId)` / `xxxId as number` 命中即失败；当前源码无命中。

结果：**自检 5/5、全仓通过、前端 2 passed**。

## 5. 未完成项与原因 <a id="gap"></a>

`libs/bms_core/tests` 全量在约 93% 处长时间无进展。定位为**测试体系自身的结构性问题**，不是本任务代码缺陷：

1. 每用例一套 SQLite（一次运行 381 个库 / 82MB，空库约 200KB）；
2. 原生 SQL 直绑 int（补零 TEXT 列查不到；>2^63 直接 `OverflowError`）；
3. ID 断言按数值比较（应断言字符串）；
4. 用例依赖“干净库”，与“单库 + 叠加”目标冲突。

2026-10-31 拍板：测试库全局一套 SQLite、用例叠加（前序数据等同其他用户业务数据，不得清理），**按新口径重写测试体系**，单独立项、排在 03_05 之后。本任务不再以全量绿作为收口前置。
