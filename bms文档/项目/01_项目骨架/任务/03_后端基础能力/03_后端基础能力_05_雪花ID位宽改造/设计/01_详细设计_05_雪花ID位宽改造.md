## 1. 设计目标与范围 <a id="goal"></a>

把全系统雪花 ID 从 `41 + 10 + 12 = 63 位` 一次改到 `48 + 40 + 38 = 126 位`，存储统一 `DECIMAL(38,0)`，接口统一字符串输出，并以机器护栏固化口径：

1. **位段与生成器**：`core/id.py` 常量、掩码、移位同步；WorkerId 上界 `2⁴⁰−1`。
2. **统一存储类型**：新增 `SnowflakeId`（TypeDecorator），四库落 `DECIMAL(38,0)`，SQLite 落零填充 `TEXT`。
3. **模型层全量替换**：94 个雪花 ID 列（主键 / 逻辑外键 / `tenant_id` / 审计人 / `parent_id`）改用该类型，禁止裸 `BigInteger` ID 列。
4. **接口字符串化**：`SnowflakeIdStr` 覆盖 107 个 ID 字段，响应 JSON 输出字符串。
5. **前端同步**：契约快照重导 → `api_types` 重新生成 → 手写代码排查 + 静态扫描用例。
6. **切换**：开发期无业务数据，dev / test / prod 三环境**停机删库重建**（2026-11-01 用户授权）。

**范围外**：WorkerId 的 Redis 动态注册（任务 `03_06`）；数据迁移脚本（无存量）；ID 以外的 `BigInteger` 计数 / 字节列；Excel 导入导出实现（阶段八 `04_01`，仅在本任务登记「大 ID 按字符串导出」的遗留约束）。

## 4. 位段与生成器 <a id="bits"></a>

### 4.1 位段布局

| 段 | 位数 | 取值 | 容量 |
| --- | --- | --- | --- |
| 时间戳 | 48 | `now_ms − epoch` | `2⁴⁸ ms ≈ 8925 年`（自 2020-09-13 起） |
| 机器 | 40 | WorkerId | `2⁴⁰ ≈ 1.1 万亿` 进程 |
| 序列 | 38 | 同毫秒自增 | `2³⁸ ≈ 2749 亿` ID/ms/进程 |

- `MAX_ID = (1 << 126) - 1 = 85070591730234615865843651857942052863`（38 位十进制，落在 `DECIMAL(38,0)` 内）。
- `_MAX_WORKER_ID = (1 << 40) - 1`；`_SEQ_MASK = (1 << 38) - 1`；`_WORKER_SHIFT = 38`；`_TIMESTAMP_SHIFT = 78`。

### 4.2 生成器不变量（保持语义不变）

1. 进程内线程安全（`threading.Lock`）；
2. 同毫秒序列用尽 → 自旋等下一毫秒再取；
3. 时钟回拨 ≤ 5ms → 用 `last_ts` 追平；> 5ms → `RuntimeError`；
4. 同一进程产出的 ID 严格单调递增；
5. 导出 `MAX_ID`、`MAX_WORKER_ID` 供类型层与测试共用（单一来源）。

### 4.3 配置上界

`AppSettings.worker_id` 改 `Field(default=0, ge=0, le=MAX_WORKER_ID)`；`config.toml` 注释、`backend/.env.example` 说明同步为「0 ~ 2⁴⁰−1」。

### 4.4 既有用例适配

| 用例 | 现状 | 调整 |
| --- | --- | --- |
| `test_default_worker_id_is_zero` | `(id >> 12) & 1023` | 改 `(id >> 38) & MAX_WORKER_ID` |
| `test_configure_and_invalid_worker` | 1023 合法 / 9999 越界 | 改 `MAX_WORKER_ID` 合法、`MAX_WORKER_ID + 1` 越界 |
| 序列耗尽用例（同毫秒 4097 个） | 12 位序列 4096 即耗尽 | 改为 monkeypatch 模块常量把序列压到 2 位验证回绕与等待，**不生成 2³⁸ 个 ID** |
| `test_fixtures_worker` | 派生范围 0~1023 | 派生值仍在 40 位内，断言不变（仅注释口径） |

## 5. 存储类型 `SnowflakeId` <a id="type"></a>

### 5.1 类型定义（`models/base.py`）

```python
SNOWFLAKE_DECIMAL_PRECISION = 38
SQLITE_PADDED_WIDTH = 38          # 2^126-1 的十进制位数
MAX_SNOWFLAKE_ID = (1 << 126) - 1  # 与 core/id.py 同源（core 导出，此处引用）

class SnowflakeId(TypeDecorator[int]):
    impl = DECIMAL(SNOWFLAKE_DECIMAL_PRECISION, 0)
    cache_ok = True

    def load_dialect_impl(self, dialect):
        # SQLite：TEXT 变体（NUMERIC 会把 >2^63 的整数转 REAL 丢精度）
        return dialect.type_descriptor(Text()) if dialect.name == "sqlite" else super().load_dialect_impl(dialect)

    def process_bind_param(self, value, dialect):
        number = _coerce_snowflake(value)          # int / Decimal / 数字字符串 → int，越界抛 ValueError
        return str(number).zfill(SQLITE_PADDED_WIDTH) if dialect.name == "sqlite" else number

    def process_result_value(self, value, dialect):
        return None if value is None else int(value)  # int / Decimal / str（含补零）统一回 int
```

- `_coerce_snowflake`：`None → None`；`bool` 拒收（防误传）；`0 ≤ value ≤ MAX_ID` 之外抛 `ValueError`（含负数与超 126 位）。
- 比较 / `ORDER BY`：TypeDecorator 的 `coerce_compared_value` 缺省返回 `self`（已核对 SQLAlchemy 实现），保证 WHERE / 范围 / 游标比较值也走同一绑定（SQLite 同样补零），不会出现「补零列 vs 未补零参数」的错比较。
- 读回不做上界校验（只 `int()`），避免历史 / 边界数据（如 `tenant_scope = 0`）读取失败。

### 5.2 四库映射（2026-11-01 离线编译实测）

| 方言 | DDL | 读回类型 | 状态 |
| --- | --- | --- | --- |
| MySQL 8.x | `DECIMAL(38, 0)` | `Decimal` → `int` | 实测（编译） |
| PostgreSQL | `DECIMAL(38, 0)` | `Decimal` → `int` | 实测（编译） |
| 达梦 DM8 | `DECIMAL(38, 0)` | `Decimal` / `int` → `int` | 编译实测；真库读写**待验**（随 test 环境切换复核） |
| SQLite（测试库） | `TEXT` | `str`（38 位补零）→ `int` | 实测（编译 + 单测） |

- 索引体积：MySQL `DECIMAL(38,0)` 约 17 字节 / 列，远小于 InnoDB 3072 字节索引上限；PG / 达梦无压力。
- **SQLite 补零约束**：直接写原生 SQL 比较 ID 列时，字面量必须是 38 位补零字符串；仓内 SQL 统一经 ORM / 类型层，新增原生 SQL 须在设计或注释中说明。ORM 侧 `ORDER BY id`、`id > :x`、`id IN (...)` 均正确。

### 5.3 存量语义兼容

| 值 | 处理 |
| --- | --- |
| `NULL` | 原样（可空列） |
| `0` | 合法（`tenant_scope` 全局哨兵、`GLOBAL_TENANT` 等）；补零为 38 个 `0` |
| `2⁶³ ~ MAX_ID` | 合法（本改造的目标区间） |
| 旧 63 位 ID | 数值上仍在范围内，切换后不再生成；删库重建后不存在 |

### 7.2 类型定义（`schemas/base.py`）

```python
SnowflakeIdStr = Annotated[int, PlainSerializer(str, return_type=str, when_used="json")]
```

- 校验：仍按 `int`（lax 模式接受数字字符串），请求体兼容前端传字符串 ID；
- 序列化：仅 JSON 模式转 `str`；`model_dump()`（python 模式）保持 int，内部链路零改动；
- 可空字段写 `SnowflakeIdStr | None`；
- `BaseSchema._serialize_ids` 与 `stringify_ids` 保留为兜底（`id` / `*_id`），与注解不冲突（值已是 str 时原样返回）；
- `created_by` / `updated_by` 由本轮注解首次实现字符串输出（现状为 int），属**有意的响应契约变更**。

## 9. 切换方案（三环境停机删库重建） <a id="switch"></a>

```mermaid
flowchart LR
    A[代码与文档合入] --> B[全量回归绿]
```

## 13. 风险与开放项 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| SQLite 补零与原生 SQL 混用导致错比较 | 设计约束 + 用例覆盖；审查新增原生 SQL |
| 达梦真库 `DECIMAL(38,0)` 读写差异 | test 环境切换时实测并回写方言文档（未实测前标「待验」） |
| 索引键体积与写入吞吐下降 10~30% | 接受（用户已确认加内存 / 换机器） |
| 切换期混跑撞号 | 停机窗口 + 停齐所有写进程；禁止滚动发布 |
| 契约基线变更被误判为回归 | 在实施记录登记「有意破坏性变更」并走 `baseline-update` |
| 前端遗漏大 ID 处理 | 契约类型 + 静态扫描用例 + 手写代码逐页核对 |
| Excel / CSV 导出科学计数法 | 登记为阶段八 `04_01` 约束：导出按字符串 |

**开放项**：无（三环境切换由本次执行；若 test / prod 环境不可达，转入实施记录并即时上报）。
