## 4. 实施要点 <a id="impl"></a>

1. **位段独立成模块**：`core/id_bits.py` 只放常量，避免 `core.id → core.factory → core.plugin → core.logging → core.config` 的循环导入；配置与模型类型从此处取上界。
2. **SQLite 补零**：`SnowflakeId` 在 SQLite 落 `TEXT`，绑定值统一 `zfill(38)`；字典序 = 数值序，`ORDER BY id` / 范围 / 游标语义与生产库一致。`coerce_compared_value` 缺省返回 `self`，比较值同样补零。
3. **`autoincrement=False`**：主键显式关闭自增，四库 DDL 不再出现 `AUTO_INCREMENT` / `SERIAL`。
4. **契约作用域**：`SnowflakeIdStr` 用 `when_used="json"`——`model_dump()` 保持 int，HTTP / JSON 输出 str；请求校验仍为 integer（兼容前端传数字或字符串）。
5. **契约基线**：重导快照后发现 `deploy/contracts` 相对 HEAD 已落后于 01_03 的作业内部端点（快照缺 `JobSubmitRequest` / `JobCancelRequest` 等），本次一并重导并更新基线；`created_by` / `updated_by` / `*_by` 由 integer → string 属**已批准的有意破坏性变更**。
6. **静态护栏**：判定逻辑落 engkit（遵循 13_06「判定逻辑在 engkit」），bms 侧只留薄包装；规则在 `engkit.toml [rules.snowflake_ids]`，白名单 7 条（`size` / `progress_*` / `limit_value` / `used_value`），语义 ID（`tenant_scope` / `rolled_back_from`）强制改造。
7. **原生 SQL 陷阱**：模型类型化后，测试里直插 ID 的 SQL 必须经 `sqlite_id()` 补零；超过 2^63 的 int 直接绑定 SQLite 会 `OverflowError`（即使列是 TEXT）。已在 `tests_support/tenant_sql.py`、租户 conftest 落地。
