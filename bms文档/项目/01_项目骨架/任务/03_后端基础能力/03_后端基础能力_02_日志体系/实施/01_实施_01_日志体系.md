## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先登记**：在 Kiwi TCMS 登记 03-2 用例一条并取得编号 **63**（产品「BMS 基础管理系统」/ 分类「平台骨架」/ 优先级 P2 / 状态 CONFIRMED / 标签「自动化」），覆盖渲染 / 上下文字段 / 脱敏 / 请求日志 / 慢请求 / 异常链路 / trace 关联。
2. **配置覆盖**：`config.dev.toml` / `config.test.toml` / `config.prod.toml` 补 `[log] slow_request_ms` = 500 / 1000 / 2000（落实「dev 严、prod 松」）。
3. **上下文**：`core/context.py` 新增 `current_request_id` / `current_client_ip` 与 setter / reset / getter（与 `current_trace_id` 同模式）。
4. **日志实现**：重写 `core/logging.py`——处理器链（上下文注入 → 级别 / logger / `ts` → 堆栈 → 脱敏）、`ProcessorFormatter`（dev console / test·prod JSON）、`_redact_sensitive`（键名黑名单含后缀 + 连接串密码正则、递归嵌套）、`StdoutLogger` 换芯 structlog、stdlib / uvicorn 统一渲染、`uvicorn.access` 关闭；`configure_logging` 幂等。
5. **中间件**：`api/middleware.py` 新增 `RequestLoggingMiddleware`（纯 ASGI：request_id / client_ip 上下文、访问日志单行分级、排除清单、异常时 status=500）；`TraceIdMiddleware` 回退顺序改为 `X-Trace-Id → request_id → 新生成`，两者均把 id 写入请求态（`scope["state"]`）供外层异常处理器取值。
6. **集成**：`main.py` 装配顺序 `TraceIdMiddleware` → `RequestLoggingMiddleware`（后者外层）；`api/errors.py` 未捕获异常走门面（堆栈 + 请求态上下文），`_request_id` 优先取请求态，`_respond` 回写 `X-Request-Id` 与 `X-Trace-Id`。
7. **测试**：新增 `tests/api/test_request_logging.py`；扩展 `tests/core/test_logging.py`（Kiwi 63 渲染 / 上下文 / 脱敏）与 `tests/api/test_middleware.py`（request_id 兜底）；`tests/conftest.py` 增请求上下文复位夹具。
8. **实测**：本地起服务（dev console / `BMS_ENV=test` JSON）验证——探针与 `/docs` 无访问行、业务路由单行日志、入站 `X-Trace-Id` 透传与回写、无入站头 `trace_id == request_id`、`ts` 含 `+08:00`、uvicorn.error 统一渲染且无 access 重复行。
9. **验证**：`uv run pytest --cov=app -q`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run pyright`、`python3 scripts/tools/base-check/check-base.py` 全绿（详见[测试记录](../测试/01_测试_01_日志体系.md)）。

## 4. 问题与处置 <a id="issues"></a>

| 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- |
| `TimeStamper(fmt="iso", utc=False)` 产出的 `ts` 无时区偏移（`2026-09-14T18:36:33.086559`） | structlog 该形态返回朴素本地时间，与《日志规范》示例（`+08:00`）不符 | 改用自定义 `_add_timestamp`（`datetime.now().astimezone().isoformat()`）；设计 §5.1 与 §14 #13 回写 |
| 访问日志取不到 `trace_id` | `TraceIdMiddleware` 在内层，其 `finally` 先于请求日志中间件复位上下文 | `_log_request` 从请求态 `scope["state"]["trace_id"]` 读取（不受上下文复位影响）；设计 §6.2 说明 |
| 未捕获异常的 500 响应缺 `X-Trace-Id` / `X-Request-Id` 关联 | `Exception` 处理器在 `ServerErrorMiddleware`（中间件外层）执行，响应不经中间件的 send 包装、上下文已复位 | 中间件把 id 写入请求态；`errors.py` 的 `_respond` 从请求态回写头部、异常日志从请求态取字段；设计 §8 回写 |
| httpx ASGITransport 在异常用例中默认重抛 | `ServerErrorMiddleware` 发送 500 后会重新抛出异常 | 用例改 `ASGITransport(app=app, raise_app_exceptions=False)`（测试手段） |
| pyright 严格模式：`Mapping` 收窄为 `Mapping[Unknown, Unknown]`、上下文元组元素类型不一致 | 动态值类型收窄限制 | `cast("Mapping[object, object]", value)` / `cast("list[object] | tuple[object, ...]", value)` 收窄；上下文元组标注 `tuple[tuple[str, object], ...]` |
| 慢请求 WARNING 难以稳定触发 | 真实耗时不可控 | 用例以 `slow_request_ms=0` 构造，稳定断言整行 WARNING |
| uvicorn 自带 handler 可能造成重复输出 | uvicorn 启动期配置独立 handler | 实测确认：`uvicorn.error` 经 root 统一渲染、`uvicorn.access` 关闭无重复；设计 §13 风险销项 |

## 6. 偏差与遗留 <a id="deviations"></a>

- **偏差（已回写设计）**：`ts` 时间戳由 `TimeStamper(utc=False)` 改为自定义 `_add_timestamp`（本地时区 ISO8601 含偏移，与《日志规范》示例一致）；设计 §5.1 / §14 #13 已同步。
- **实现细节（已落设计）**：请求态 `scope["state"]` 承载 `trace_id` / `request_id`（跨中间件复位供访问日志与全局异常处理器取值；`X-Trace-Id` 在 500 响应亦回写）；`uvicorn.access` 关闭（访问行由请求中间件统一输出）。
- **跨任务回写**：03-1 配置管理三环境覆盖补 `[log].slow_request_ms`（设计 §4.4 与实施记录已同步）；02-3-4 日志基座接入点遗留销项（实施记录补后续回写条）。
- **遗留归口**：
  - OpenTelemetry 链路上报与 `span_id` 关联 → 分布式与监控阶段（计划「后续阶段待办」表「链路追踪与 OpenTelemetry 接入」行）。
  - `tenant` / `user_id` / `user` 字段启用 → 租户解析 / 认证阶段（上下文变量与处理器已就绪，启用即生效）。
  - 请求 / 响应 body 日志的脱敏过滤器 → 按需后续接入（本任务不打印 body）。
