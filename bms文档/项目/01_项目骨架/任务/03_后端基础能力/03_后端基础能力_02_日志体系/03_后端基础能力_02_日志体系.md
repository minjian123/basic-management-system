## 2. 任务内容 <a id="content"></a>

1. structlog 输出，字段口径遵循《日志规范》「日志格式」节；渲染形态由 `[log] format` 单开关控制——`dev` 为 console 可读渲染，`test` / `prod` 强制单行 JSON；日志只写 stdout，不落文件
2. 上下文字段由中间件注入：`request_id`（兜底）、`trace_id`（入站读 `X-Trace-Id`、缺失生成 UUID4 并一律回写响应头）、`tenant`（租户解析接入后启用）、`user_id` / `user`（认证接入后启用）、`client_ip`、`duration_ms`；`trace_id` 取 02-3-11 交付的 `current_trace_id`
3. 脱敏：密码 / 令牌 / 凭据等敏感字段统一脱敏、禁写日志，清单口径见《日志规范》「脱敏要求」节
4. 请求日志中间件：记录方法 / 路径 / 状态码 / 耗时；探针（`/healthz`、`/readyz`）与文档路径（`/docs`、`/redoc`、`/openapi.json`）排除在请求日志之外，避免编排高频轮询刷爆日志
5. 慢请求分级：阈值走 `[log] slow_request_ms`（`dev` 严、`prod` 松），超阈值请求记 WARNING；依赖异常分级在事件总线落地前以 warning 兜底不告警
6. 落地后回填 02-12 日志基座结构占位的登记
7. **前置契约（已交付）**：配置读取取 [03_01 配置管理](../03_后端基础能力_01_配置管理/03_后端基础能力_01_配置管理.md)（2026-09-14 交付）的 `get_settings()`——`[log] level` / `format` / `slow_request_ms` 与生效环境（`app.env`）均为按 `BMS_ENV` 分层 + `BMS_` 覆盖后的生效值；本任务不另读 `config.toml`

## 3. 完成标准 <a id="accept"></a>

`test` / `prod` 下日志为单行 JSON 且含上下文字段（`dev` 为 console 渲染）；`X-Trace-Id: abc` 请求日志 `trace_id` 为 `abc` 且响应头回写同名值，缺失时生成 UUID4 并回写；密码 / token / 验证码 / 连接串密码等敏感字段全量日志无明文；请求日志中间件对业务路由生效，探针与 `/docs` 路径不产生 INFO 行；未捕获异常 ERROR 行堆栈单行、响应不回显堆栈；超 `[log] slow_request_ms` 的请求记 WARNING。单测覆盖上下文字段注入、脱敏与探针路径排除，覆盖率随全局门禁，用例同步 Kiwi。
