## 2. 任务内容 <a id="content"></a>

1. `backend/config.toml` 分区与关键键清单就位：`[app]`（name / env / debug）、`[server]`（host / port / workers）、`[log]`（level / format / slow_request_ms）、`[database]`（platform / tenants / archive，每库 url 不含密码、replicas 与连接池参数）、`[redis]`、`[minio]`（占位）、`[security]`（占位）、`[cors]`，逐项中文注释
2. 环境分层：`BMS_ENV` 指定 `dev` / `test` / `prod`（未设置时默认 `dev`，取非法值启动失败）
3. `BMS_` 前缀环境变量覆盖（12-factor）：嵌套键用双层下划线映射路径，如 `[database].platform.url` → `BMS_DATABASE__PLATFORM__URL`；部署时用环境变量覆盖敏感项，不落配置文件
4. `app/core/config.py` 以 pydantic-settings 建模、lifespan 内加载并校验：必填缺失、类型 / 取值非法、出现未知或拼错的分区 / 键一律启动即报错并指出键名
5. 新增 `backend/.env.example` 列出全部 `BMS_` 应用键与占位示例值（基础设施凭据仍只留 `deploy/.env`，两者不混）；密钥类配置不入库、不入镜像、不写日志
6. 落地后回填 02-10 配置基座结构占位的登记（真实读取入口就位）

## 3. 完成标准 <a id="accept"></a>

`BMS_ENV=dev|test|prod` 三套环境按分层覆盖正确加载（未设置时默认 `dev`）；`BMS_DATABASE__PLATFORM__URL` 注入后覆盖生效；缺必填键、类型 / 取值非法、`BMS_ENV` 取非法值、未知 / 拼错键四类情形均启动失败并指出键名；三环境差异处（日志级别、CORS）加载结果正确；密钥类配置不出现在 `config.toml`、`.env.example` 与日志中。单测覆盖加载 / 覆盖 / 校验失败路径，覆盖率随全局门禁，用例同步 Kiwi。
