## 2. 任务内容 <a id="content"></a>

1. 新增 `[database].sqlite_dir` 基址（env `BMS_DATABASE__SQLITE_DIR`，默认空）：相对 SQLite 连接串统一以其为基准解析，相对基址锚 `backend/` 工程根、非空自动建目录；非 SQLite 方言、绝对路径、内存库（`:memory:`）不介入。
2. 移除 `core/config.py` 中 `DatabaseTargetSettings` 的代码兜底默认 URL——平台 / 租户 / 归档三目标均必填，缺失即启动失败并指出键名（杜绝代码级硬编码）。
3. 本地库文件统一落点：把 `bms/backend` 下全部 `*.db`（含 `libs/`、`services/` 子目录）与两个 `.db-backup-*` 备份目录迁至工作区根 `database/bms`（备份目录保留原名）；`database/` 不入库。
4. 环境分层：`config.dev.toml` 订 `sqlite_dir = "../../database/bms"`、`config.test.toml` 订 `sqlite_dir = "../../database/bms/test"`，`config.toml` 基线 `[database].sqlite_dir = ""`；`.env.example` 列入该键。
5. ops 去硬编码：`check_tables` / `check_modules` 缺省读配置解析连接串（`--url` 保留为可选覆盖，新增 `--offline` 强制离线）；`seed_*` 等文档串示例改为配置口径（不出现写死库路径）。
6. 开发脚本 `本地全套.sh`：种子步骤走配置（去 `--url`）、`--reset-db` 指向统一库目录、解锁步骤经配置解析库路径。
7. CI 去硬编码：`backend-modules` job 设 `BMS_ENV=test`，去除写死连接串（`-x url` / `--url`），后端库相关步骤走 `config.test.toml`。
8. 规范固化：《AI开发规范》「红线与纪律」「数据库与表设计处理方式」「检查清单」写入「数据库连接配置以配置为唯一来源、禁止代码 / 脚本 / CI 写死；本地库文件统一放工作区根 `database/<仓库>/` 且不入库」。

## 3. 完成标准 <a id="accept"></a>

改 `[database].sqlite_dir` 一处即可切换库目录，且服务启动 / Alembic 迁移 / 种子 / 目录校验（`check_tables` / `check_modules`）全部跟随；全仓检索（排除测试与文档）无写死的 SQLite 连接串 / 库路径；`bms/backend` 下无 `*.db` 运行时库文件（统一落 `database/bms`）；`BMS_ENV=dev` 起服务于 `database/bms`、`BMS_ENV=test` 落 `database/bms/test`；CI 后端 job 无写死 URL 且通过；单测覆盖 `sqlite_dir` 解析（相对 / 绝对 / 非 SQLite / 内存 / 空基址）与三目标必填，用例同步 Kiwi（2244）。
