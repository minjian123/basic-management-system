## 4. 配置设计 <a id="config"></a>

### 4.1 `sqlite_dir` 语义 <a id="sqlite-dir"></a>

- 名称：`[database].sqlite_dir`；环境变量 `BMS_DATABASE__SQLITE_DIR`；类型 `str`，默认 `""`。
- 默认空：**不介入**，相对路径沿用「当前工作目录」语义（保持既有测试与 CI 兼容）。
- 非空：仅对**SQLite**方言、**相对文件路径**生效；相对基址**锚 `backend/` 工程根**（`_CONFIG_DIR`），避免随进程 CWD 漂移；首次解析自动 `mkdir(parents=True, exist_ok=True)`。
- 不介入：非 SQLite 方言、绝对路径、内存库（`:memory:`）、无文件名的 SQLite URL。

### 4.2 三环境取值 <a id="envs"></a>

| 环境 | `sqlite_dir` | 落地目录（相对 `backend/`） | 说明 |
| --- | --- | --- | --- |
| dev（缺省） | `../../database/bms` | 工作区根 `database/bms` | 本机裸跑全套库 |
| test（CI） | `../../database/bms/test` | 工作区根 `database/bms/test` | CI 后端 job / 集成测试库，与 dev 分离 |
| prod | 不设（走部署注入 MySQL） | — | 真库连接串经环境变量注入 |

- `config.toml` 基线设 `sqlite_dir = ""`；`config.dev.toml` / `config.test.toml` 覆盖为表内值。
- **切库即改一处**：换目录只改对应环境的 `sqlite_dir`（或经 `BMS_DATABASE__SQLITE_DIR` 注入），服务 / 迁移 / 种子 / 校验全部跟随。

## 5. 模型与解析实现 <a id="impl"></a>

### 5.1 基址解析函数 <a id="resolver"></a>

`core/config.py` 新增模块级函数（与 `DatabaseSettings.apply_sqlite_dir()` 配套）：

```python
_SQLITE_BACKEND = "sqlite"


def resolve_sqlite_dir(url: str, sqlite_dir: str) -> str:
    """按 `sqlite_dir` 基址归一 SQLite 相对文件路径（非 SQLite / 绝对 / 内存 / 空基址原样）。"""
    if not sqlite_dir:
        return url
    parsed = make_url(url)
    if parsed.get_backend_name() != _SQLITE_BACKEND:
        return url
    database = parsed.database
    if not database or database == ":memory:":
        return url
    path = Path(database)
    if path.is_absolute():
        return url
    base = Path(sqlite_dir)
    if not base.is_absolute():
        base = _CONFIG_DIR / base
    base = base.resolve()
    base.mkdir(parents=True, exist_ok=True)
    target = (base / path).resolve()
    return parsed.set(database=str(target)).render_as_string(hide_password=False)
```

### 5.2 模型改动 <a id="model"></a>

- `DatabaseSettings` 新增 `sqlite_dir: str = ""` 与：

```python
def apply_sqlite_dir(self, url: str) -> str:
    """按 `sqlite_dir` 基址归一相对 SQLite 路径（引擎 / 迁移解析连接串时统一调用）。"""
    return resolve_sqlite_dir(url, self.sqlite_dir)
```

- **移除代码兜底默认**：`tenants` / `archive` 由 `Field(default_factory=...)` 改为**必填**（`platform` 本就必填），三目标缺失即 `ValidationError` → `ConfigError`（键路径如 `database.tenants`）。

### 5.3 接入点 <a id="hook"></a>

- `EngineFactory._target_url`（平台 / 租户 / 归档、模板与回落 url 的**统一出口**）：各返回分支经 `self._settings.database.apply_sqlite_dir(...)` 归一。`resolved_url()`（含密码）与 `resolve_url()`（不含密码）均经此出口，自动覆盖。
- `db/migration.py::chain_url` 的**归档 / 租户回落**分支（不经 `EngineFactory`）：`return database.apply_sqlite_dir(database.archive.resolved_url())` / 同理 tenants；经库键（`db_key`）分支走 `EngineFactory.resolved_url`，已覆盖。

> 单一出口保证「一处配置、全链路跟随」，且避免同一 URL 被二次归一回。

### 6.3 开发脚本 <a id="script"></a>

