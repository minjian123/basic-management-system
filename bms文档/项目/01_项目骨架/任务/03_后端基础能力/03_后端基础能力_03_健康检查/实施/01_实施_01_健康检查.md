## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先登记**：经 mjbk 容器内 Django shell 登记 03-3 两条用例并取得编号 **64**（探针响应契约）/ **65**（聚合并发 / 超时与启动完成态）（产品「BMS 基础管理系统」/ 分类「平台骨架」/ P2 / CONFIRMED / 标签「自动化」）；平台既有用例 45 题面同步更新（契约字段更名与 `/readyz` 用例迁出）。
2. **配置**：`config.toml` 新增 `[health]`（`check_timeout_ms = 2000` / `total_timeout_ms = 5000`）；`.env.example` 补 `BMS_HEALTH__CHECK_TIMEOUT_MS` / `BMS_HEALTH__TOTAL_TIMEOUT_MS`；`core/config.py` 新增 `HealthSettings`（`ge=1`）并入 `Settings`。
3. **基座改造**：`health/base.py` 数据契约改响应形态（`HealthCheckResult{name, ok, error}` / `HealthCheckReport{ok, checks}`）；新增 `DEFAULT_CHECK_TIMEOUT_MS` / `DEFAULT_TOTAL_TIMEOUT_MS` 常量与注册表构造参数；`aggregate` 重写为 `asyncio.gather` 并发 + 单项 / 整体两级超时（`asyncio.timeout`，未完成项按 `TimeoutError` 兜底），异常兜底统一 `type(exc).__name__`，保持注册顺序与空集就绪语义。
4. **真实注册表**：新增 `health/registry.py` 的 `HealthCheckRegistry`（登记追加、`checks` 返回注册顺序元组，超时值构造注入）。
5. **检查项**：新增 `health/checks.py`——`RedisHealthCheck`（懒建 `redis.asyncio` 客户端 `PING`，实现 `BaseAsyncResource.aclose`）与 `DatabaseHealthCheck`（经 `EngineRegistry.get(PLATFORM_DB_KEY)` 取平台引擎执行 `SELECT 1`）；检查项不自行捕获异常（聚合统一兜底）。
6. **路由**：`api/health.py` 重写 `/readyz`——`startup_complete` 未完成 → 503 + 空 `checks`；否则聚合报告投影为 `{status, checks}`（动态键、`error` 仅异常类名），HTTP 200 / 503；`/healthz` 不变。
7. **装配**：`main.py` 改用 `HealthCheckRegistry`（注入 `[health]` 超时）并注册 `redis` → `database` 两项检查项；`RedisHealthCheck` 登记 `ResourceManager` 随生命周期释放；`app.state.startup_complete` 由 lifespan 维护（startup 校验通过置 True、shutdown 在资源释放前置 False）。
8. **测试**：重写 `tests/api/test_health.py`（Kiwi 2 / 64 / 65：就绪结构、失败不泄露、未注册省略、启动态、lifespan 后 200）；扩展 `tests/health/test_health_registry.py`（Kiwi 45 契约断言随改名更新 + Kiwi 65 并发 / 单项超时 / 整体超时）；新增 `tests/health/test_checks.py`（Kiwi 65：`from_url` 桩、内存 SQLite、失败类名）与 `tests/integration/test_health_integration.py`（`integration` 标记，真实 Redis 随 04_02）。
9. **实测与验证**：本地起服务三组——全好（200，`checks` 两项 `{ok:true,error:null}`）；Redis 指向不可达端口（503，`checks.redis.error=ConnectionError`，`/healthz` 保持 200）；平台库指向不可写路径（503，`checks.database.error=OperationalError`）；命令级验证见[测试记录](../测试/01_测试_01_健康检查.md)。

## 6. 偏差与遗留 <a id="deviations"></a>

- **设计偏差**：无。`aggregate` 整体超时捕获以 `contextlib.suppress(TimeoutError)` 实现（等价设计伪码 `try/except`），`redis-py` 部分未知类型配定向忽略；两处已在设计 §14 #15 登记。
- **拍板升级回写**：响应契约 `healthy/detail/items` → `ok/error/checks`（用户拍板「改基座契约」），02-39 契约与架构 / 基类清单登记同步更新；Kiwi 45 题面与断言同步维护。
- **跨任务回写**：03-1 配置管理设计键清单补 `[health]` 分区（对齐表第 16 条）；计划 §3.1「健康检查项真实实现」行销项（真实探针部分），剩余项改写为缓存 / 频率限流 / 告警联动。
- **遗留归口**：
  - `minio` 检查项 → 阶段八文件管理接入（注册即生效）。
  - 探针结果缓存 / 探测频率限流、失败告警联动 → 可观测性 / 运维阶段（计划 §3.1 已登记）。
  - 优雅停机完整链路（preStop / terminationGracePeriod）→ 部署与运维阶段（应用侧 shutdown 摘流已就位）。
  - 鉴权豁免与限流排除清单 → 认证（后续）/ 限流阶段按探针名单落地。
  - 三库（MySQL / PostgreSQL / 达梦）真实连通实测 → 落库阶段；健康检查集成用例随 04_02 重验证层启用。
- **结论**：本任务无设计偏差，遗留已全部登记去向，实施闭环完成。
