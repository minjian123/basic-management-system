> **立项缘由**：Redis 在架构层定位为「集群统一缓存源 / 共享基础设施」，已在会话 / 限流 / 分布式锁 / IdP 流程状态 / 验证码五域**缺省启用**，但十个能力域**各自建连**（无共享连接池）、不可用行为**五套口径并存**、架构要求的**短超时未落地**、开发与 CI 环境**没有 Redis** —— 结果是「每新增一处用到 Redis 的能力都要各自接线」，且故障语义不确定。按用户拍板，把 Redis 提升为**基础（必需）功能**并**提前统一使用**，一次到位。

## 2. 任务内容 <a id="content"></a>

1. **统一客户端能力域**：新增 `bms_core/redis/`（端口 `BaseRedisClient` + `redis` / `null` 实现 + **共享连接池** + 统一 key 前缀 / TTL / 超时）；十个能力域改为注入共享 client，**禁止各自 `from_url` 建连**。
2. **配置加厚**：`[redis]` 增 `db` / `pool_size` / `socket_timeout_ms`（缺省 500）/ `socket_connect_timeout_ms` / `health_check_interval_s` / `key_prefix` / `required`；三环境覆盖与 `backend/.env.example` 显式声明。
3. **不可用口径统一**：**必需功能 fail-closed**（会话 / 验证码 / 幂等 / 分布式锁 / IdP 状态：不可用即明确报错，新增错误码 `10012 REDIS_UNAVAILABLE` / 503）；**可降级两类**（`cache` / `dict` / `config` 命中失败直连库；`rate_limiter` 降级 `MemoryRateLimiter` 并补「降级中」指标与告警）。
4. **provider 默认翻转**：`[idempotency]` / `[consistency_barrier]` / `[cache]` / `[dict_cache_region]` / `[config_cache_region]` 缺省由 `null` / `memory` 改为 `redis`，dev 覆盖同口径。
5. **环境前置**：本地一键脚本自动拉起 Redis（不再默认指向远端开发机实例）；CI 增 Redis service 与 `BMS_TEST_REDIS_URL`，Redis 集成用例由 skip 转执行；单测提供 fakeredis 注入通道（保持 hermetic）。
6. **口径回写**：据实施结论回写《[后端开发规范](../../../../../规范/后端开发规范.md)》《[架构设计 · 后端基础类体系](../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》《[架构设计 · 性能与安全](../../../../../设计/架构设计/31_架构设计_性能与安全.md)》《[架构设计 · 服务间通信与分布式一致性](../../../../../设计/架构设计/37_架构设计_子系统_服务间通信与一致性.md)》《[后端基类清单](../../../../../后端基类清单.md)》与知识档案《Redis 技术介绍》《分布式事务》系列。

## 3. 完成标准 <a id="accept"></a>

全仓检索**无能力域自建 Redis 客户端**（`Redis.from_url` / `AsyncRedis.from_url` 仅出现在统一能力域）；十个能力域共用同一连接池且各项配置取自 `[redis]`；必需五域（会话 / 验证码 / 幂等 / 分布式锁 / IdP 状态）在 Redis 不可用时**明确报错（`10012` / 503）而非静默放行**，限流与缓存三域按 §8 口径定稿降级（限流补「降级中」指标与告警）；`[redis].socket_timeout_ms`（缺省 500）与 key 前缀 / TTL 口径生效；缺省配置下幂等 / 一致性屏障 / 缓存走真实 Redis；本地一键拉起含 Redis、CI 含 Redis service 且 Redis 集成用例执行通过；单测保持无外部依赖（fakeredis）；门禁（pytest / ruff / pyright / 契约与模块校验 / `preflight --fast`）全绿。
