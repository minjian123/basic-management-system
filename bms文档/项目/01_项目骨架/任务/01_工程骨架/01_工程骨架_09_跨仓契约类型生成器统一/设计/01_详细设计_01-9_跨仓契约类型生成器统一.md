| # | 决策 | 结论 |

## 3. 接口与配置 <a id="contract"></a>

### 3.1 实现导出

```js
export async function run({ packageDir, argv = process.argv.slice(2) }) // → 0 通过 / 1 失败 / 2 用法
```

- 薄壳：`await run({ packageDir })`（`packageDir` = 包目录，读 `<packageDir>/api-types.config.json`）；
- 直调：`node generate.mjs --config <path/to/api-types.config.json> [--check] [--files-from <文件|->]`。

### 3.2 配置字段

| 字段 | 说明 |
| --- | --- |
| `product` | 产品标识（仅日志 / 排障用） |
| `contractsDir` | 契约快照目录，**仓根相对**（如 `deploy/contracts`） |
| `outDir` / `indexFile` | 输出目录与汇总文件名，**包目录相对**（`src` / `index.ts`） |
| `header.title` | 首行标题模板，`{name}` 替换为契约名 |
| `header.generator` | 生成器路径文案（保持各仓现文案，产物零 diff） |
| `header.sourceNote` | 来源注记（`服务契约快照` / `产品契约快照`） |
| `header.regenerateCmd` | 重新生成命令文案 |
| `index.title` / `index.notes` / `index.exportTemplate` | 汇总文件头与导出模板（`{name}` 占位） |
| `inputs` | `--files-from` 增量判据前缀（缺省 `[contractsDir/, frontend/packages/api-types/]`） |

### 3.3 依赖解析

实现位于基座 `frontend/scripts/`，而 `openapi-typescript` 声明在各产品 api-types 包里 → 用 `createRequire(<packageDir>/package.json)` 解析并动态 `import`（兼容 CJS 桥接的 `{default:{default:fn}}` 形态）。

## 4. 生成与校验行为 <a id="behavior"></a>

| 场景 | 行为 |
| --- | --- |
| 生成 | 枚举 `contractsDir/*.json`（排序）→ 逐份生成 `<name>.ts` → 生成 `indexFile` |
| 增量 | 传 `--files-from` 且改动未命中 `inputs` 前缀 → 打印「跳过」并退 0 |
| 零漂移 | 缺失 → `缺少生成物：<outDir>/<name>`；差异 → `与契约快照漂移：… 第 N 行；期望 …，实际 …`；多余 → `多余生成物：…` |
| 成功文案 | `零漂移：N 份契约类型一致`（单契约且声明版本时追加 `（info.version=X）`） |
| 契约目录为空 | `未找到契约快照：<dir>`，退 1 |

## 5. 失败分支与边界 <a id="failures"></a>

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | 缺 `api-types.config.json` | 报错并退 1（薄壳漏配置） |
| 2 | `openapi-typescript` 未在调用方包内安装 | 解析失败即报错（不静默回退） |
| 3 | 新产品仓接入 | 只加配置 + 薄壳，不改实现 |
| 4 | 生成物形态 | 由各仓锁定的 `openapi-typescript` 版本决定，本任务不统一版本 |
