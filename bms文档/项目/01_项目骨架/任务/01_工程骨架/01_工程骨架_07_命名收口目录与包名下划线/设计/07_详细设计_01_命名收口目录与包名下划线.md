# 命名收口（目录 / 包名 / 工具脚本名下划线）详细设计

> 项目骨架 · 01 工程骨架 · 07 命名收口 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [07 命名收口](../01_工程骨架_07_命名收口目录与包名下划线.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：把《命名规范》已定的「标识符与文件名一律 snake_case」在**工程骨架登记面**上一次落实——目录名、包名、工具脚本文件名全部换下划线，并用机器护栏把这一口径钉住，避免「一套规范两种形态」。

**范围内**：

1. 10 个目录改名与 3 个包名改名；
2. 23 个 Python 工具脚本、5 个 shell 脚本文件名改名；
3. 全部引用同步（CI / engkit / tasks.json / 锁文件 / 构建配置 / README / 文档正文）；
4. 「登记目录与包名形态」护栏并入既有校验入口；
5. 《命名规范》补边界条目。

**范围外**（另行立项，本任务只登记去向）：

| 对象 | 数量 | 去向 |
| --- | --- | --- |
| 前端源文件 / 测试文件名（`module-api.ts`、`page-route.ts`、`*.spec.ts` 等） | 393 | 前端侧单独任务（涉及全量 import 与用例路径） |
| 前端路由 `path`、CSS 类、HTML 属性、图片名 | 数百 / 两万+ | **不改**：受 URL、CSS、浏览器语法与生态惯例约束，不属登记标识（规范边界条目固化） |
| ES 索引 / Milvus collection / MinIO bucket | 十余 | **不改**：上游产品命名要求小写连字符 |
| 文档文件名 | — | 已由《命名规范》「文档命名」节约束，存量合规 |

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 规范口径 | 《命名规范》「大小写风格」节：snake_case 用于 Python 标识符、文件、表 / 字段；「文档命名」节：文档文件名**不用连字符**（理由：连字符不能作标识符、`\w` 只认下划线） |
| 实际形态 | 工具目录 4 个、前端包 2 个、模块目录 1 个、组件目录 3 个仍为连字符；工具脚本 23 个 `.py` + 5 个 `.sh` 仍为连字符 |
| 引用锚点 | 上述路径被 `.gitlab-ci.yml`（job 脚本路径）、`engkit.toml`（预检步骤）、`.vscode/tasks.json`、`scripts/README.md`、各 README 与文档正文引用；包名被 `package.json` / `pnpm-lock.yaml` / import 说明符引用 |
| 约束 | 依赖外置：`node_modules` 是依赖仓的链接，目录改名后链接目标失配；`pnpm-lock.yaml` 必须由 `pnpm install` 重新生成（不得手改） |
| 护栏现状 | `check_base.py` 已断言目录清单一致性、清单 ↔ 代码零漂移，但**无标识形态断言** |

## 3. 设计 <a id="design"></a>

### 3.1 改名映射（唯一口径） <a id="map"></a>

**规则**：连字符 `-` → 下划线 `_`，其余字符（大小写、分词、语义）**一律不动**。

**目录（10）**：

| 现路径 | 改为 |
| --- | --- |
| `scripts/tools/base-check` | `scripts/tools/base_check` |
| `scripts/tools/check-docs` | `scripts/tools/check_docs` |
| `scripts/tools/reorder-design` | `scripts/tools/reorder_design` |
| `scripts/tools/reorder-stage` | `scripts/tools/reorder_stage` |
| `frontend/packages/api-types` | `frontend/packages/api_types` |
| `frontend/packages/ui-ep` | `frontend/packages/ui_ep` |
| `frontend/packages/ui-ep/src/components/form-design` | `…/components/form_design` |
| `frontend/packages/ui-ep/src/components/form-render` | `…/components/form_render` |
| `frontend/packages/ui-ep/src/components/import-export` | `…/components/import_export` |
| `frontend/modules/slot-sample` | `frontend/modules/slot_sample` |

**包名（5）**：`@bms/ui-ep` → `@bms/ui_ep`；`@bms/api-types` → `@bms/api_types`；`@bms/module-slot-sample` → `@bms/module_slot_sample`；`@bms/module-demo` → `@bms/module_demo`；`@bms/module-sample` → `@bms/module_sample`（后者两个为同名同规则顺带收口；规划中的 `@bms/ui-vant` → `@bms/ui_vant`）。

**工具脚本文件名（23 个 `.py` + 5 个 `.sh`）**：

| 目录（新） | 文件（连字符 → 下划线） |
| --- | --- |
| `scripts/tools/base_check/` | `check-backend-base.py`、`check-bare-collections.py`、`check-base.py`、`check-docs-scope.py`、`check-env-example.py`、`check-links.py`、`check-prototype-review.py`、`check-service-boundaries.py`、`check-system-fields.py` |
| `scripts/tools/check_docs/` | `check-status.py` |
| `scripts/tools/preflight/` | `check-ci-config.py`、`check-frontend-types.py`、`check-preflight.py`、`install-guard-hook.py`、`run-once.py`、`run-selected.py` |
| `scripts/tools/reorder_design/` | `fix-component-refs.py`、`migrate-component-structure.py`、`reorder-design.py` |
| `deploy/` + `scripts/tools/llamacpp/` | `ci/build-base.sh`、`setup/install-all.sh`、`postgres/init/01-keycloak.sh`、`install-systemd.sh`、`qwen-serve.sh` |

**不改**：中文名脚本（`安装-重启到Windows快捷方式.py` 等，连字符为中文标点用法而非词连接）、`bms文档/设计/原型设计/资源/vendor/` 下第三方 CSS。

### 3.2 引用同步（按类别的落点） <a id="refs"></a>

| 类别 | 文件 | 同步内容 |
| --- | --- | --- |
| CI | `.gitlab-ci.yml` | job 的 `script` / `exists` / `changes` 里的脚本与包路径 |
| 预检 | `engkit.toml` | 各步骤 `cmd` 里的脚本路径 |
| 编辑器任务 | `.vscode/tasks.json` | `command` / `args` 路径 |
| 前端工程 | 根与各包 `package.json`、`tsconfig*.json`、`vite.config.ts`、`vitest.config.ts`、`eslint.config.js` | 包名、workspace 依赖、路径别名、include/exclude |
| 锁文件 | `pnpm-lock.yaml` | **由 `pnpm install` 重新生成**（禁止手改） |
| 共享依赖 | `frontend/shared-dependencies.json` | 包名键 |
| 说明文档 | `README.md`、`scripts/README.md`、`frontend/README.md`、`backend/README.md`、`ops/README.md`、`bms文档/**` | 目录 / 包名 / 命令路径 |

**替换纪律**：按**完整路径前缀**匹配（如 `scripts/tools/base_check`、`@bms/ui_ep`、`components/form_design`），**不做裸子串替换**——避免误伤 `form-renderer`、`menu-form-*` 等无关字面。

### 3.3 执行顺序（防半改状态） <a id="order"></a>

```
1 git mv 目录（10）与文件名（28）      ← 先动结构，git 保留历史
2 文本引用替换（按前缀，排除产物目录）
3 pnpm install（重新生成锁文件）
4 前端全量用例 + 构建
5 后端 pytest + ruff + pyright
6 五项文档/基座校验（含新护栏）
7 命名规范与计划回写
```

**失败处置**：任一步失败即停在该步，不回退已改文件（整批改动在同一提交内，`git checkout .` 可整体回退）；`pnpm install` 失败优先查包名与 workspace glob 是否一致。

### 3.4 护栏设计（登记面形态断言） <a id="guard"></a>

**为什么只扫登记面**：全仓按字面扫连字符会命中 CSS 类、HTML 属性、URL、英文复合词（约 16 万处），既无法收敛也会让正常编码被误伤。护栏只判定**被系统登记 / 被工具按路径解析**的位置。

| # | 判定 | 位置 | 失败文案 |
| --- | --- | --- | --- |
| G1 | `scripts/tools/*` 下一级目录名为 `^[a-z][a-z0-9_]*$` | `check_base.py` | `[命名] 工具目录名含非法字符：<path>` |
| G2 | `scripts/tools/**` 下 `.py` / `.sh` 文件名主体为 `^[a-z0-9_]+$`（中文名跳过） | 同上 | `[命名] 工具脚本名含非法字符：<path>` |
| G3 | `frontend/packages/*` 与 `frontend/modules/*` 一级目录名同 G1 | 同上 | `[命名] 前端包目录名含非法字符：<path>` |
| G4 | 各 `package.json` 的 `name` 字段只含 `^[@a-z0-9/_-]+$` 且不含 `-`（scope 内段同样不含 `-`） | 同上 | `[命名] 包名含连字符：<name>（<path>）` |
| G5 | `alembic/versions/*` 一级目录名为业务域标识形态（`^[a-z][a-z0-9_]*$`） | 同上 | `[命名] 清单目录名非法：<path>` |

- **不扫**：前端源文件 / 测试文件名、路由 path、CSS、HTML、文档文件名与正文、第三方 vendor 资源。
- **零配置**：新增工具目录或包只需形态合规，不必改护栏；中文名脚本按「非 ASCII 主体」跳过（中文不是标识符字符，但属既有约定，改名成本高于收益，登记为规范例外）。
- 断言并入 `check_base.py`（既有入口），不新增脚本；`preflight --fast` 与 CI `base-integrity` 自动继承。

**失败分支**：

| 情形 | 处置 |
| --- | --- |
| 新增连字符目录 / 包名 | 断言失败，提示改为下划线形态 |
| 包名与目录名不一致 | 不断言（二者本就允许不同名，如 `@bms/core` ↔ `packages/core`），只断言各自形态 |
| 目录不存在 | 断言跳过（产品仓 / 精简检出），不报错 |

## 4. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 真实仓库形态断言 | G1~G5 全部通过（无连字符登记目录 / 包名） |
| 2 | 工具目录反例 | 临时目录内造 `tools/bad-name/` → G1 报错并指出路径 |
| 3 | 工具脚本反例 | 造 `tools/x/check-bad.py` → G2 报错 |
| 4 | 前端包反例 | 造 `packages/bad-name/package.json` → G3/G4 报错 |
| 5 | 清单目录反例 | 造 `versions/Bad-Name/` → G5 报错 |
| 6 | 中文名豁免 | 中文脚本名不报错（正例） |
| 7 | 引用完整性 | CI / `engkit.toml` / `.vscode/tasks.json` 中出现的脚本路径全部存在 |
| 8 | 前端可构建 | `pnpm install` + `ui_ep` / `api_types` / `slot_sample` 构建与全量用例通过 |
| 9 | 后端不回退 | `pytest` 全绿、`ruff` / `pyright` 无新增问题 |
| 10 | 文档不破链 | `check_links` / `check_docs_scope` / `check_base` / `check_status` / `preflight --fast` 全绿 |

**验收映射**：需求 01-7「完成标准」逐条对应用例 1（形态）、7（引用）、8~9（构建与用例）、10（校验）。
