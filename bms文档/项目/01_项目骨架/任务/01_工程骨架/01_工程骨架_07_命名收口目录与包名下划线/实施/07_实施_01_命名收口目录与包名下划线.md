## 2. 实施过程 <a id="process"></a>

### 2.1 设计核对与偏差处置 <a id="review"></a>

| # | 设计假定 | 实施事实 | 处置 |
| --- | --- | --- | --- |
| 1 | 目录/脚本改名不影响运行 | `run_once.py` / `run_selected.py` 是 engkit 的**薄包装**，转发子命令字面是 `run_once` / `run_selected`（下划线），而 engkit CLI 只认 `run-once` / `run-selected`——改名后按原字样转发即 `invalid choice` | 包装内转发名改为 CLI 正式名（`run-once` / `run-selected`）；文件名与转发名解耦，后续改名不影响 |
| 2 | 既有用例与新口径一致 | `test_parallel_guard.py` 断言包装内出现 `run_selected` 且按该名解析参数——该断言与 engkit CLI 实际选项不符（按现状应早已失败） | 断言改为 `run-selected`（与 CLI 一致），登记为顺带修复 |
| 3 | 前端包名只改 `ui-ep` / `api-types` / `module-slot-sample` | 同规则下 `@bms/module-demo` / `@bms/module-sample` 也带连字符（包名口径不分产品），`@bms/ui-vant` 为规划中的同形包名 | 一并收口为 `module_demo` / `module_sample` / `ui_vant`（目录 `modules/demo`、`modules/sample` 不动） |
| 4 | 模块目录改名 ⇒ 模块键改名 | `slot-sample` 同时是**运行时模块标识**（`manifest.name`、`remoteEntry` 路径、i18n pack key、区域项 key），受 `MODULE_NAME_PATTERN` 约束（当前只允许 kebab） | 目录与包名改下划线，**运行时标识暂留 `slot-sample`**（否则须改前端注册契约与全部用例）；登记为「登记型标识 sweep」遗留 |
| 5 | 后端 pytest 默认并行 | `backend/pyproject.toml` 的 `addopts` 只作用于以 `backend` 为 rootdir 的运行；跑子工程路径时 rootdir 落到 `libs/bms_core` / `services/*` 各自的 `pyproject.toml`（只有 `--import-mode=importlib`） | 11 个 `pyproject.toml` 统一追加 `-n auto`，实现「不加参数即并行」 |

### 2.2 改名执行（结构先动，保留历史） <a id="rename"></a>

- **目录（10）**：`git mv` 逐个改名（`scripts/tools/{base-check,check-docs,reorder-design,reorder-stage}`、`frontend/packages/{api-types,ui-ep}`、`ui_ep/src/components/{form-design,form-render,import-export}`、`frontend/modules/slot-sample`）。
- **脚本文件（28）**：23 个 `.py`（`base_check` 9 / `check_docs` 1 / `preflight` 6 / `bg` 4 / `reorder_design` 3）+ 5 个 `.sh`（`deploy/ci/build-base.sh`、`deploy/setup/install-all.sh`、`deploy/postgres/init/01-keycloak.sh`、`llamacpp/{install-systemd,qwen-serve}.sh`）。
- **包名（5）**：`@bms/ui_ep`、`@bms/api_types`、`@bms/module_slot_sample`、`@bms/module_demo`、`@bms/module_sample`（`package.json` 的 `name` + 全部 `workspace:*` 依赖 + import 说明符）。
- **中文名脚本**（`安装-重启到Windows快捷方式.py` 等）按设计豁免、不改名。

### 2.4 护栏（`check_base.py` 第 6 项） <a id="guard"></a>

| 判定 | 范围 | 失败文案 |
| --- | --- | --- |
| G1 工具目录名 | `scripts/tools/*` 一级目录 | `[命名] 工具目录名须为 snake_case：…` |
| G2 工具脚本名 | `scripts/tools/**` 的 `.py` / `.sh`（中文名跳过） | `[命名] 工具脚本名须为 snake_case：…` |
| G3 前端包目录名 | `frontend/{packages,modules}/*` 一级目录 | `[命名] 前端包目录名须为 snake_case：…` |
| G4 包名 | 上述目录的 `package.json` `name` 不含 `-` | `[命名] 包名须为 snake_case（不含连字符）：…` |
| G5 清单目录名 | `backend/alembic/versions/*` | `[命名] 清单目录名须为 snake_case：…` |

- 并入既有入口，不新增脚本；`preflight --fast` 与 CI `base-integrity` 自动继承。
- **不扫**：前端源文件 / 测试文件名、路由 path、CSS、HTML 属性、图片名、ES / Milvus / MinIO、文档文件名与正文、第三方 vendor。
- 自检：`--self-test` 新增 6 例（1 正例 + 4 反例 + 中文名豁免），与第 5 项合计 10 例。

### 2.5 后端测试默认并行（顺带收口） <a id="parallel"></a>

- 11 个 `pyproject.toml`（`backend` + `libs/bms_core` + 9 个 `services/*`）的 `addopts` 统一追加 `-n auto`；
- 效果：`uv run pytest libs/bms_core/tests` 从 **105s（串行）→ 23.5s（并行）**，用例数不变；前端 `pnpm -r test` 保持拓扑串行（按拍板：模块依赖基座包，顺序有意义）。
- **实测交叉点（24 核 Windows，spawn 开销显著）**：全量 2171 例 串行 105s / `-n auto` 23.5s / `-n 8` 29.2s；单目录 77 例 16.2s / 10.9s / 9.1s；**单文件 3 例 0.94s / 4.5s / 3.4s**——小集合并行反而慢，属 xdist 启动开销。故默认保留 `-n auto`（全量最优），单文件 / 单用例调试加 `-n 0` 走串行（已在 `addopts` 注释与本文登记）。
- **口径固化**：《测试规范》「执行侧配套口径」新增第 5 条「并行档位按执行规模选」（全量 / 预检 / 选测并行、单文件串行）；`.vscode/tasks.json` 增两条任务——「测试：后端当前文件（串行 · 秒级）」与「测试：后端全量（并行 · 缺省档）」，按场景选。
