## 2. 实施过程 <a id="process"></a>

### 2.1 设计核对与偏差处置 <a id="review"></a>

| # | 设计假定 | 实施事实 | 处置 |
| --- | --- | --- | --- |
| 1 | `i18n-name` / `i18n-text` 只作控件语义键 | 它们在 `FIELD_WIDGET_MAP` 中同时是**字段类型入参**（kebab 别名行），既是控件键也是类型键 | 一并删除 kebab 类型别名（只留 `i18n_name` / `i18n_text`），符合「一次改齐、不留双形态」 |
| 2 | 前端业务 / 动作 / 图标维护页「不新增本地正则」 | 三页已有本地格式校验（`^[a-z][a-z0-9-]*$`）与提示文案，不改会先于后端拒绝 snake 新值 | 同步改 `^[a-z][a-z0-9_]*$` 与提示为「小写字母 / 数字 / 下划线」；不新增额外规则 |
| 3 | 自建图标码文案统一为「图标键」 | 页面与注释混用「图标键 / 图标码」，与新口径（自建图标码、上游图标名例外）不一致 | 涉及 `sys_icon.code` 的提示 / 注释统一为「自建图标码」，`icon key` 前缀派生说明保留 |
| 4 | 存量测试数据可直接复用 | 平台测试用 kebab 业务 / 动作码（`biz-a` / `act-x` / `t-order` 等）作为编写夹具，新正则下被拒 | 夹具改 snake（`biz_a` / `act_x` / `t_order` 等）；属测试数据，不涉及生产数据迁移 |
| 5 | 护栏 self-test 4 例（1 正 + 3 反） | 实际拆为 5 例（1 正 + 4 反：后端控件键 / 前端控件键 / 业务动作码 pattern / 图标码正则），覆盖三类登记面更完整 | 按 5 例落地，`NAMING_CASES` 6 → 11 |
| 6 | 图标模型注释单行可容纳 | 新文案使 `code` 列 `mapped_column` 超过 120 列宽 | 按 ruff format 折行（无行为变更） |

## 4. 兼容与回滚 <a id="compat"></a>

- **控件语义键**：代码常量一次改齐，无 kebab 别名；表单布局只存字段类型键，控件键不落库，无数据迁移。
- **业务码 / 动作码**：只收紧校验，存量值本无连字符；不写迁移脚本。
- **自建图标码**：创建后不可改，收紧只影响新建；存量 kebab 码仍可读取，`custom:{code}` 解析不看形态。
- **回滚**：单批提交整体 revert；无库结构变更、无数据变更。
