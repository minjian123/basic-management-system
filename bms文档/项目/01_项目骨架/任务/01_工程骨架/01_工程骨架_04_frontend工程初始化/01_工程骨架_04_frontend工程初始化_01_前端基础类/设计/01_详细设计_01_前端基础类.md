## 1. 概述 <a id="overview"></a>

- **目标**：为 frontend / frontend-mobile 建立**前端基础类体系**，把契约公共字段、请求封装、CRUD store 模板与稳定序列化收敛到一处，与后端「基础类」对齐，避免模块类逐个改造。
- **范围**：双工程同款基线（契约类型 / BaseApi / createCrudStore / stableStringify）+ 《前端开发规范》继承约定 + 跨端 ID 口径登记；不含业务页面与具体模块 API/Store。
- **依据**：需求 [01-4](../../../../../需求/01_需求_工程骨架.md#r01-4) 第 6 条、《[前端开发规范](../../../../../../../规范/前端开发规范.md)》、《[命名规范](../../../../../../../规范/命名规范.md)》第 9 节、2026-09-10 ID 精度实测结论（JS number > 2^53 丢精度）。

## 2. 现状与差距 <a id="gap"></a>

| 现状（01-04/05 交付） | 差距 |
| --- | --- |
| `src/api/types.ts` 仅 `ApiResponse<T>` / `PageResponse<T>` | 缺公共实体/分页查询基类（字段口径不统一，各模块将各写一套） |
| `src/api/http.ts` 提供 `request<T>()` | 模块 API 无统一基类，路径拼接/方法封装将逐模块重复 |
| Pinia 仅 `useUserStore` 占位 | 列表/详情页 CRUD 逻辑（loading/列表/总数/增删改查）无模板，将逐模块重复 |
| 无稳定序列化工具 | 对拍/存档/日志输出键序随插入序，跨端比对不稳定 |
| ID 类型未定 | 雪花 BIGINT 超 JS 安全整数（实测 `...123` 解析为 `...000`），不定口径将出现查改删错行 |

## 4. 契约公共类型设计 <a id="types"></a>

```ts
/** 公共实体字段：id 用 string（雪花 BIGINT 超出 JS 安全整数，JSON 边界以字符串传输）。 */
export interface BaseEntity {
  id: string
  createdAt: string
  updatedAt: string
}

/** 分页查询参数基类（list 接口 query 统一继承）。 */
export interface BasePageQuery {
  page: number
  size: number
}
```

- **ID 口径（跨端约定）**：数据库 BIGINT 与 JOIN/索引**不变**（整型）；后端 API 出参 `str(id)`、入参 `int(id)`；前端一律拿 `string`，不做算术语义。该口径登记进 02-3（统一响应序列化）与 03-2（模型字段注记）。
- 时间统一字符串（UTC ISO 8601），展示层本地化；金额/精度字段沿用字符串或分单位整数（业务模块定）。

## 5. BaseApi 设计 <a id="base-api"></a>

```ts
export class BaseApi {
  constructor(private readonly basePath: string) {}

  protected get<T>(url = '', config?: AxiosRequestConfig): Promise<T> { ... }
  protected post<T>(url = '', data?: unknown, config?: AxiosRequestConfig): Promise<T> { ... }
  protected put<T>(url = '', data?: unknown, config?: AxiosRequestConfig): Promise<T> { ... }
  protected delete<T>(url = '', config?: AxiosRequestConfig): Promise<T> { ... }
}
```

- 各方法复用 `request<T>()`（统一响应解析、错误处理、token 位），仅负责 `basePath` 拼接与 HTTP 方法；模块 API 继承后暴露业务方法（如 `listDemos(query)`）。

## 6. createCrudStore 设计 <a id="base-store"></a>

Pinia 惯例是组合式函数而非类继承，故「BaseStore」以**工厂函数**实现，等价提供公共字段与方法：

| 成员 | 说明 |
| --- | --- |
| `list: Ref<Entity[]>` | 列表数据 |
| `total: Ref<number>` | 总数 |
| `loading: Ref<boolean>` | 加载态 |
| `fetchList(query)` | 拉列表（写入 list/total，维护 loading） |
| `fetchOne(id)` | 拉详情 |
| `create(data)` / `update(id, data)` | 增改（返回实体） |
| `remove(id)` | 删除并从本地列表移除、总数递减 |

- 入参 `CrudApi<Entity, Query>`：模块 API 实现 `list/get/create/update/remove` 五个方法即可接入（通常由 `BaseApi` 子类提供）。

## 7. stableStringify 设计 <a id="serialize"></a>

- 对象键递归排序；数组保序；
- `Set` → 元素归一后按稳定串排序；`Map` → 键转字符串、按键排序的对象；
- `Date` → ISO 字符串；`BigInt` → 字符串；`undefined` 按 JSON 语义（对象省略、数组置 null）；
- 用途：对拍、存档、日志字段输出稳定（对应后端「对外输出稳定序」约定）。

## 11. 边界与开放项 <a id="boundary"></a>

- 不含业务模块 API/Store 实现（后续模块按此基线派生）。
- `createCrudStore` 不含服务端排序/筛选参数拼装细节（由模块 Query 类型扩展）。
- 53-bit 雪花方案未采用（用户定案 A：BIGINT + 字符串传输，数据库/ JOIN 全程整型）。
- 前端覆盖率全量采集与阈值随 05-1 门禁任务。
