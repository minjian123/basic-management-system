## 1. 概述 <a id="overview"></a>

- **目标**：在 01-4-1（契约类型 / BaseApi / createCrudStore / stableStringify）之上，补齐前端**公共组合式与工具基座**：请求状态、分页列表逻辑、校验规则、Tab 管理、状态映射与测试入口，避免各页面重复实现。
- **范围**：双工程同款；`useTabs` 仅核心（增删激活 + 持久化 + 白名单），路由/UI 联动随布局阶段；权限/字典/表单框架等留对应阶段。
- **依据**：需求 [01-4](../../../../../需求/01_需求_工程骨架.md#r01-4) 第 7 条、《[前端开发规范](../../../../../../../规范/前端开发规范.md)》第 6/8/12 节。

## 2. 现状与差距 <a id="gap"></a>

| 现状 | 差距 |
| --- | --- |
| 页面各自 try/finally 管 loading，异步竞态无保护 | 需要 `useRequest` 统一状态与竞态处理 |
| 分页列表（page/size/query/list/total）无模板 | 需要 `useListPage` 收敛列表页公共逻辑（规范 §7.3 约定） |
| 表单校验将逐页各写（手机号/邮箱等） | 需要 `validators` 统一规则与框架无关的规则工厂 |
| 规范 §5/§7.1 已定 `useTabs` 契约（`bms_open_tabs`、白名单） | 尚无实现 |
| 状态（启用/停用）各页写魔法值与文案 | 需要 `EntityStatus` 常量与 i18n 映射 |
| 组件用例各自挂载插件 | 需要 `mountWithPlugins` 测试基座（规范 §11） |

## 4. useRequest 设计 <a id="use-request"></a>

```ts
export interface UseRequestOptions<T> {
  onSuccess?: (data: T) => void
  onError?: (error: unknown) => void
}

export function useRequest<T>(fetcher: () => Promise<T>, options: UseRequestOptions<T> = {}) {
  const data = ref<T | null>(null)
  const loading = ref(false)
  const error = ref<unknown>(null)
  let sequence = 0
  async function run(): Promise<T | null> { ... }
  return { data, loading, error, run }
}
```

- **竞态保护**：每次 `run` 递增序号，仅最新序号的响应写入状态（旧请求返回被丢弃）；
- 失败不清空既有 `data`，`error` 记录异常并触发 `onError`；`loading` 仅最新请求复位。

## 5. useListPage 设计 <a id="use-list-page"></a>

```ts
export function useListPage<Entity, Query extends BasePageQuery>(options: {
  api: { list(query: Query): Promise<PageResponse<Entity>> }
  defaultQuery: Query
}) { ... }
```

| 成员 | 说明 |
| --- | --- |
| `query` | 查询条件（初始 `defaultQuery` 深拷贝） |
| `list` / `total` | 由响应派生的 `computed` |
| `loading` / `error` | 来自 `useRequest` |
| `search()` | 回到第 1 页并请求 |
| `reset()` | 重置为 `defaultQuery` 并请求 |
| `changePage(page)` | 指定页请求 |
| `reload()` | 保持当前条件重新请求 |

## 6. validators 设计 <a id="validators"></a>

- predicates：`isPhone`（`1[3-9]` 段 11 位）、`isEmail`、`isIdCard`（18 位含校验位格式）、`isUrl`、`passwordStrength`（长度 + 字符类 → weak/medium/strong）；
- 规则工厂：`required(message)`、`pattern(regExp, message)` 返回结构 `{ required? / pattern?, message, trigger: 'blur' }`，Element Plus 与 Vant 规则均可直接使用（不引入任一 UI 框架类型，保持双端同款）。

## 7. useTabs 设计 <a id="use-tabs"></a>

```ts
export interface TabItem { path: string; title: string }

export function useTabs(options: { navigate?: (path: string) => void } = {}) {
  const tabs = ref<TabItem[]>([])
  const active = ref('')
  function openTab(path: string, title: string): void { ... }
  function closeTab(path: string): void { ... }
  function activate(path: string): void { ... }
  function restore(): void { ... }
  return { tabs, active, openTab, closeTab, activate, restore }
}
```

- **单例**：`tabs/active` 定义在模块作用域，多处调用共享同一状态（规范 §5）；
- **白名单**：`ALLOWED_PATHS` 过滤，未命中不建 Tab；
- **持久化**：`localStorage` 键 `bms_open_tabs`（规范 §7.1），增删激活时同步写入、`restore()` 恢复；
- **路由接入位**：`activate` 调 `options.navigate`（应用侧传 `router.push`），布局阶段接入 UI。

## 12. 边界与开放项 <a id="boundary"></a>

- `useTabs` 不含 UI（Tab 栏渲染）与路由守卫，随布局阶段接入（`navigate` 回调已留位）。
- `validators` 不含业务字段级规则（由模块扩展）。
- 权限指令 / 动态菜单（阶段四）、字典（字典管理接入）、上传下载（阶段六）、图表（报表阶段）不在本任务。
- 前端覆盖率门禁阈值随 05-1 定案。
