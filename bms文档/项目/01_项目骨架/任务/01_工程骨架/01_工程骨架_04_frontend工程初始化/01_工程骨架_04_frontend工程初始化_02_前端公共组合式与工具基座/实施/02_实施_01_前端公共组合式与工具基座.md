## 3. 实施过程 <a id="process"></a>

### 3.1 五类基座（`src/utils/`）

- `useRequest.ts`：`data/loading/error/run`；**竞态保护**——每次 `run` 递增序号，仅最新序号写入 data/error/loading，过期响应与过期失败均丢弃；可选 `onSuccess/onError`；
- `useListPage.ts`：基于 `useRequest` 的分页列表逻辑（`query/list/total/search/reset/changePage/reload`），`query` 由 `defaultQuery` 拷贝初始化，`list/total` 为响应派生 `computed`；
- `validators.ts`：`isPhone/isEmail/isIdCard/isUrl/passwordStrength` 与规则工厂 `required/pattern`，返回结构同时适配 Element Plus 与 Vant（不引入任一端 UI 类型，保持双端同款）；
- `useTabs.ts`：**模块级单例**（`tabs/active`），`openTab/closeTab/activate/restore`；白名单 `ALLOWED_PATHS` 过滤；`localStorage` 键 `bms_open_tabs` 持久化（增删激活即写、`restore` 容错解析）；`navigate` 回调留路由接入位（布局阶段传 `router.push`）；
- `status.ts`：`EntityStatus`（0 停用 / 1 启用）+ `entityStatusI18nKey`；i18n 两语言包补 `common.enabled/disabled`。

### 3.2 测试基座

- `tests/helpers/mount.ts`：`mountWithPlugins` 预挂 pinia / i18n，可经 `options.global` 覆盖（如 router）；`home.spec.ts` 改用之，统一组件测试入口。

### 3.3 双端落地与规范

- frontend 实现后同款复制 frontend-mobile（含 i18n 键与用例）；
- 《前端开发规范》同步：§7.3 增补「列表页优先用 `useListPage` / `useRequest` / `validators`」、§11 增补「组件测试统一用 `mountWithPlugins`」。

## 6. 偏差与遗留 <a id="deviations"></a>

- `useTabs` 不含 Tab 栏 UI 与路由守卫，随布局阶段接入（`navigate` 回调已留位）。
- `validators` 不含业务字段级规则（由模块按需扩展）。
- 权限指令 / 动态菜单（阶段四）、字典缓存（字典管理接入）、上传下载（阶段六）、图表（报表阶段）不在本任务。
- 前端覆盖率门禁阈值随 05-1 定案。
