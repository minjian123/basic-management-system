## 1. 概述 <a id="overview"></a>

- **目标**：落地工作流引擎适配契约与占位实现——`app/workflow/base.py` 的审批动作枚举 `WorkflowAction`（approve / reject / withdraw）、数据契约 `ProcessDefinition` / `ProcessInstance` / `WorkflowTask`、统一引擎契约 `BaseWorkflowEngine`（`deploy` / `start` / `complete_task`）、占位实现 `NullWorkflowEngine`（`deploy` 空操作、`start` / `complete_task` 固定返回占位实例；不连引擎）；常量 `WORKFLOW_STATUS` / `NULL_INSTANCE_ID` / `NULL_TASK_ID`；`app/api/deps.py` 提供者 `get_workflow_engine`；`app/main.py` 装配单例。
- **范围**：`app/workflow/`（新增）、`app/api/deps.py`（提供者导出）、`app/main.py`（装配）、单测；架构 04 §4 / §8、《后端基类清单》/《后端开发规范》/ 计划 / 需求 02-23 登记。
- **不含**（归后续阶段）：真实 SpiffWorkflow 适配（BPMN 2.0 解析、同步引擎线程池运行 `run_in_executor`）→ **工作流阶段**；流程定义与版本管理（`wf_process` + bpmn-js 前端建模 + `wf.process.deployed`）、流程实例与任务持久化（`wf_instance` / `wf_task` / `wf_record`，引擎本身不持久化）、节点推进与待办生成、会签 / 或签、驳回退回、待办 / 已办查询 → 同阶段；业务单据联动（`business_type` + `business_id`，产品仓库 biz 流程模板）→ 对应产品阶段；待办站内信与实时推送（`approval.todo`）→ 通知公告 / 实时推送阶段。
- **依据**：需求 [02-23](../../../../../需求/02_需求_后端基座.md#r02-23)、《[架构设计 · 工作流](../../../../../../../设计/架构设计/20_架构设计_子系统_工作流.md)》「流程定义与版本」「流程执行」「审批机制」节、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[命名规范](../../../../../../../规范/命名规范.md)》「后端命名」节。

## 4. 工作流引擎能力域（`app/workflow/base.py`） <a id="workflow"></a>

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `WORKFLOW_STATUS` | `tuple[str, ...]` 常量 | 实例状态：`("running", "completed", "rejected")`（占位期仅登记不校验） |
| `NULL_INSTANCE_ID` | `str` 常量 | 占位实例 id `"null-instance-id"` |
| `NULL_TASK_ID` | `str` 常量 | 占位任务 id `"null-task-id"` |
| `WorkflowAction` | `StrEnum` | 审批动作：`APPROVE = "approve"` / `REJECT = "reject"` / `WITHDRAW = "withdraw"` |
| `ProcessDefinition` | frozen dataclass（数据契约） | 流程定义：`definition_key: str` / `bpmn_xml: str` / `version: int = 1` |
| `ProcessInstance` | frozen dataclass（数据契约） | 流程实例：`process_id: str` / `definition_key: str = ""` / `business_type: str = ""` / `business_id: str = ""` / `current_node: str = ""` / `status: str = "running"` |
| `WorkflowTask` | frozen dataclass（数据契约） | 流程任务：`task_id: str` / `instance_id: str` / `node_id: str` / `assignee: str` / `status: str = "pending"` |
| `BaseWorkflowEngine(BaseCapability, ABC)` | 能力域契约中间层 | `key: str = "workflow_engine"` |
| `deploy(definition) -> None` | 抽象方法（async） | 部署流程定义（真实实现落 `wf_process` 并发布 `wf.process.deployed`） |
| `start(definition_key, *, business_type, business_id) -> ProcessInstance` | 抽象方法（async） | 启动流程实例（按最新版本） |
| `complete_task(task_id, *, action, variables=None) -> ProcessInstance` | 抽象方法（async） | 完成待办任务并推进（同意 / 驳回 / 撤回） |
| `NullWorkflowEngine(BaseWorkflowEngine, BaseNullObject)` | 占位实现 | `deploy` 空操作；`start` / `complete_task` 固定返回占位实例（**不连引擎**） |
| `get_workflow_engine(request) -> BaseWorkflowEngine` | 模块函数（提供者） | 取应用级单例（`request.app.state.workflow_engine`） |

**口径**：

| 情形 | 处置 |
| --- | --- |
| `deploy` 入参 | 以 `ProcessDefinition`（`definition_key` / `bpmn_xml` / `version`）传参；返回 `None` |
| `start` 入参 / 返回 | `start(definition_key, *, business_type, business_id) -> ProcessInstance`（业务绑定 `business_type` + `business_id`） |
| `complete_task` 入参 / 返回 | `complete_task(task_id, *, action: WorkflowAction, variables: Mapping[str, object] \| None = None) -> ProcessInstance` |
| 引擎运行 | SpiffWorkflow 同步引擎在异步栈中以线程池运行（`run_in_executor`）为**实现细节**，契约全异步、不暴露线程细节 |
| 引擎不持久化 | 流程 / 实例 / 任务 / 审批记录由 BMS 自建表维护（`wf_process` / `wf_instance` / `wf_task` / `wf_record`），归实现与上层 |
| 版本 | `start` 按**最新版本**启动；在途实例按原版本执行——由实现处理，契约不暴露版本参数（`start` 仅传 `definition_key`） |
| 会签 / 或签 | 归上层（待办生成与审批记录），本契约只做「完成任务 → 推进」原语 |
| 占位语义 | `deploy` 空操作；`start` 返回占位实例（`process_id=NULL_INSTANCE_ID`、回显 `definition_key` / `business_type` / `business_id`、`status="running"`）；`complete_task` 返回占位实例（`status="completed"`）；不连引擎 |
| 已注册协同 | 审批待办站内信 / 邮件取 02-4-4 `BaseNotifier`、待办实时提醒 `approval.todo` 取 02-4-5 `BaseRealtimePublisher`（任务文档已标注，本设计不重复） |

## 5. 应用装配与依赖注入 <a id="di"></a>

## 6. 继承与分层 <a id="base"></a>

- `BaseWorkflowEngine → BaseCapability → BaseObject`；`NullWorkflowEngine → BaseWorkflowEngine + BaseNullObject → BasePlaceholder → BaseObject`。
- `WorkflowAction` 为动作枚举（`StrEnum`，同 `NotifyChannel` / `CircuitState`）；`ProcessDefinition` / `ProcessInstance` / `WorkflowTask` 为能力域数据契约（frozen dataclass）。
- 与各能力域分工：本域管**流程推进原语**；站内信 / 邮件走 02-4-4、实时推送走 02-4-5、权限码走 02-3-9、幂等走 02-3-10。
