## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先行**：经容器内 Django shell 登记用例（平台既有编号至 962），取得 **963**；用例文件以 `@pytest.mark.kiwi_id(963)` 标注。
2. **缓存层**：
   - `app/cache/memory.py`：`MemoryCacheRegion`（进程内 LRU + TTL + 版本号 + `bump_version`；线程安全）。
   - `app/cache/redis.py`：`RedisCacheRegion`（redis-py 自写：同步契约方法 + 异步方法 `aget` / `aset` / `adelete` / `aincrease` / `asetnx` / `arelease_lock`；JSON 序列化、`ttl_with_jitter` 防雪崩、SETNX 防击穿、Lua 释放锁；连接 / 命令异常统一降级为未命中 / 空操作并记日志，不抛业务错）。
3. **字典域缓存**（`app/dict/cache.py`）：`MemoryDictCacheRegion`（L1 双分区 + 按租户版本 + 进程内锁）/ `RedisDictCacheRegion`（Redis 共享层 + 进程内 L1，命中回填）；`DictCacheRegion` **只增不改**新增异步缺省方法（`aget_type` / `aset_type` / `adrop_type` / `avalue_subset` / `aset_value_subset` / `aversion` / `aincrease_version` / `alock` / `arelease_lock`），`NullDictCacheRegion` 无需改动。
4. **模型与迁移**：`app/dict/models.py` 字典六表 + `app/listing/models.py` 查询方案表（字段 / 索引按《概要设计 · 字典管理》）；`alembic/env.py` 在线分支（异步引擎 + `run_sync`；URL 解析 `-x url=` > `BMS_MIGRATION_URL` > 配置）；首个迁移 `0001_dict_and_query_scheme`（七表 + 索引，四库兼容编写）。命令（SQLite 实测）：
   ```bash
   cd backend
   uv run alembic upgrade head          # 缺省租户库 bms_tenant_demo.db
   uv run python -m ops.seed_dict       # 幂等种子（首次 25 行 / 重复 0 行）
   ```
5. **真实取数与翻译**（`app/dict/sql.py`）：`SqlDictSource`（租户解析 → 引擎注册表 → 会话；版本三态 / 关键字 / 级联（空串 = 顶层）/ 按值子集 / 探针截断 + `has_more`·`total` / locale 经 `_i18n` 回退 / 停用不可见；缓存读写策略见第 4 节问题 3 / 4）；`SqlDictTranslator`（子集命中直出、缺失一次 `IN` 回填、未命中不占位）。
6. **高级查询与方案**：`app/dict/query.py`（`DictQueryService`：属性 schema 读取 / 条件引擎——字段与操作符白名单 + 参数绑定 + 方言 JSON 提取 / `target=items` 分页 / `target=business` 经注册表）；`app/dict/providers.py`（`BuiltinDictQueryProvider`：字典条目只读查询示例）；`app/query/local.py`（`LocalQueryProviderRegistry`）；`app/listing/store.py`（`SqlQuerySchemeStore`：三级默认解析 / owner 过滤 / 乐观锁转 409）。
7. **字段类型**（`app/fieldtype/local.py`）：`LocalFieldTypeRegistry` + `SimpleFieldType`（内建十类型，含 `dict` / `dict_multi`；`render_metadata` 输出 `widget` / `multiple` 与前端语义键对齐）。
8. **写路径**（`app/dict/service.py` + `app/api/dict.py`）：类型 / 条目 / 属性 CRUD（服务层唯一性校验 + 乐观锁；**先写库后删缓存 + `INCR` 版本**）；路由扩展 `query-providers` / `attrs` / `advanced-query` / 写接口；locale 经 `Accept-Language` 解析（端点内 `with` 作用域设置与复位 contextvar）。
9. **装配**：`app/core/assembly.py` 新增 9 个工厂（cache `memory` / `redis`、dict_cache_region `memory` / `redis`、dict_source / dict_translator / query_scheme_store `sql`、field_type_registry / query_provider_registry `local`）；`PLUGIN_WIRINGS` 中 `dict_cache_region` 前移至 `dict_source` / `dict_translator` 之前（取数 / 翻译工厂依赖已装配缓存）；`config.dev.toml` 切 dev 真实实现（memory 缓存，可切 redis）。
10. **用例**：`tests/dict/test_dict_real.py`（迁移 / 种子 / 取数 / 缓存 / 翻译 / 写路径 / 高级查询 / HTTP / 装配 / fakeredis）、`tests/listing/test_query_scheme_store.py`、`tests/fieldtype/test_local_registry.py`；既有 `tests/dict/test_dict.py`（占位契约）**未改动即通过**；三处既有断言随能力扩展同步（见第 4 节问题 6）。
11. **联调**：真实服务（uvicorn + dev 配置）验证 `GET /dicts/user_status`（含版本一致）/ `POST /dicts/batch` / 级联 `parent_id` / `attrs` / `query-providers` / `advanced-query` / `Accept-Language: en-US` / 写接口（新增类型 + 条目 → 版本递增 → 取数同步）；证据见第 5 节。
12. **登记回写**：《后端基类清单》（§2 / §9 / §10 + §9 开头段）、《后端开发规范》§3.1 补「字典取数与缓存必须走基座」、「架构设计 · 数据架构」缓存节口径回写（redis-py 自写）、02-13 相关文档口径回写（需求 02-13 / 任务 02_04 / 设计 04 / 03-5 设计）、需求 02-56 注块、任务与计划状态。
13. **数据库设计表文件补登（2026-09-21 收尾）**：按《数据库开发规范》「数据表设计文档组织」节，补 `sys_dict_type` / `sys_dict_item` / `sys_dict_type_i18n` / `sys_dict_item_i18n` / `sys_dict_attr` / `sys_dict_attr_i18n` / `sys_query_scheme` **七个表文件**（`bms文档/设计/数据库设计/数据表设计/`；字段 / 索引 / 迁移说明与 ORM 模型及首个迁移逐项一致；状态「待落库」）并在《数据库设计总览》「已设计数据表登记」登记——表结构唯一事实源就位（原收尾遗漏，用户确认后补齐）。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 插件注册表构建失败：`(cache, memory)` 等重名（实现类 / 工厂） | 零参实现类声明 `plugin_name` 被 `__init_subclass__` 自动收集，与显式工厂登记重名 | 对齐既有实现口径：**实现类不声明 `plugin_name`**（经工厂显式登记）；零参工厂亦不声明（避免自动收集）。回写详细设计 §18 |
| 2 | `dict_source` 工厂取不到缓存 | 装配按 `PLUGIN_WIRINGS` 顺序解析，缓存域排在取数 / 翻译之后 | `dict_cache_region` wiring 前移；工厂从 `app.state.dict_cache_region` 注入 |
| 3 | 带关键字（过滤）的取数命中了整类型缓存（返回未过滤结果） | 未获锁时「短暂等待后重读缓存」未区分是否带过滤；且互斥锁获取后未释放（内存实现 5s TTL 内后续请求走该分支） | `DictCacheRegion` 新增 `arelease_lock`（只增不改，内存 / Redis 实现覆写）；`by_type` 查库完成即释放锁；未获锁重读缓存仅限无过滤请求 |
| 4 | 探针请求（`limit=1`）返回全量（截断语义失效） | 带 `limit` 的请求命中了整类型缓存 | 读缓存条件加 `limit is None`；写缓存条件改为「无过滤 且（无 `limit` 或未截断）」——小字典探针（未截断）仍写缓存，大字典探针（截断）不写 |
| 5 | 全量测试时 HTTP 用例访问到旧库（`no such table`） | 插件工厂为**进程级登记实例**，首次装配时捕获 `app` 引用；多应用（测试）场景下后续应用复用旧工厂 | HTTP 用例改 `dependency_overrides` 绑定当前测试库的真实实现；新增「装配解析」用例只断言 provider 名与类型。**口径**：单应用生产无影响（既有装配机制），多应用场景由依赖覆盖隔离 |
| 6 | 既有用例断言随能力扩展失败 3 处 | 能力快照断言原为「仅 null 实现」 | `tests/crosscut/test_capability_cleanup.py`（cache 域含 memory / redis）、`tests/api/test_plugins.py`（cache 实现清单）、`tests/core/test_base_inheritance.py`（新类继承 `BaseObject` 已修）；均在用例内注明 02-4-27 扩展 |
| 7 | 新类被「必须继承基类」护栏拦截（`DictService` / `DictQueryService` / 种子数据类） | 新类未挂基类 | `DictService` / `DictQueryService` / `SeedItem` / `SeedAttr` / `SeedType` 继承 `BaseObject` |
| 8 | 依赖注入 `get_dict_service` 中 `EngineRegistry` 未导入 / `_LOGGER` 未定义 | 编辑遗漏 | 补 import 与模块级 logger；`ruff` / `pyright` 复核全绿 |

## 6. 偏差与遗留 <a id="deviations"></a>

- **设计偏差（已回写设计 §18）**：① 实现类与零参工厂不声明 `plugin_name`（经工厂显式登记，与既有实现口径一致）；② 缓存读写策略细化（带 `limit` 不读整类型缓存、未截断才写）；③ `DictCacheRegion` 增 `arelease_lock`（原设计只列 `alock`）。
- **示例提供者合并**：原设计列 `builtin`（items 条件引擎）与 `dict_items`（business 示例）两个提供者；实施合并为 `builtin` 一个（business 模式默认提供者，`target=items` 由 `DictQueryService` 直接承载），登记清单返回一条。
- **测试隔离口径**：插件工厂实例跨应用复用为既有装配机制；HTTP 用例经 `dependency_overrides` 绑定当前库（详见问题 5），生产单应用无影响。
- **遗留（归口）**：
  - 三库真库执行（MySQL / PostgreSQL / 达梦）与 `ops/test_db.py` 真实 `create/migrate/drop`、`alembic/env.py` 三库实测 → **阶段二 后端基座窗口**（需求 02-56 完成标准已登记）。
  - 真实 Redis 联调（开发服务器 Redis）：实现已就位（`RedisCacheRegion` / `RedisDictCacheRegion`，`config.dev.toml` 可切 `provider="redis"`），集成用例随 `BMS_TEST_REDIS_URL` → **阶段二窗口**（本任务以 fakeredis 覆盖语义）。
  - 字典管理页面 / 菜单、`dict:manage` / `dict:query-scheme` 权限码、操作日志与字段级审计、回收站、导入导出 → **阶段八 通用能力·字典模块**。
  - 表单元数据接口下发 `dictType` 与自建字段类型白名单（`EXT_FIELD_TYPES`）→ 表单定制窗口；前端消费方 `06_06`（联调已通）。
  - 缓存实现口径（redis-py 自写替代 dogpile.cache）已回写《数据架构》《后端开发规范》与 02-13 相关文档（需求 / 任务 / 设计）。
