## 1. 概述 <a id="overview"></a>

- **目标**：登记六类跨阶段基座（缓存 Region 分域 / 数据范围注入 / 分片路由 / 事件发布消费 / Celery 任务 / ORM 审计捕获）的职责、契约与回补阶段，并落地**本阶段可独立实现的接口与契约层骨架**；真实实现随对应阶段回补。
- **范围**：六个能力域包（`cache` / `scope` / `sharding` / `events` / `audit` / `tasks`）的契约基类与数据结构、`BaseRepository` 两个预留钩子（数据范围 / 分片路由）、`sys_task` / `sys_task_log` 模型骨架、架构与计划登记、单测。
- **不含**（归回补阶段）：dogpile Region 与全局版本号真实读写、RBAC 范围规则与读写过滤、按月分表物理路由、RocketMQ 事务消息与消费组、Celery 调度与执行记录写入、ORM 审计事件捕获与哈希链。
- **依据**：需求 [02-13](../../../../需求/02_需求_后端基座.md#r02-13)、《[架构设计 · 后端基础类体系](../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../../../规范/后端开发规范.md)》、《[命名规范](../../../../../../规范/命名规范.md)》。

## 4. 六类契约骨架设计 <a id="contracts"></a>

### 4.1 缓存 Region 分域基座（→ 阶段六 通用能力） <a id="cache"></a>

`app/cache/base.py`：

| 成员 | 说明 |
| --- | --- |
| `build_cache_key(*, tenant, domain, business_key) -> str` | key 规范 `bms:{租户\|global}:{域}:{业务键}`（无租户用 `global`） |
| `CacheRegion(BaseObject, ABC)` | Region 分域基座契约：`domain`（抽象属性）、`default_ttl`；抽象 `get` / `set` / `delete` / `get_global_version` |
| `CacheRegion.build_key(...)` / `is_stale(key, version)` | 派生：按域拼 key；全局版本号惰性比对（≠ 视为陈旧） |

- 全 key 带 TTL、三防（穿透 / 击穿 / 雪崩）在基座统一，回补阶段接 dogpile.cache Region。

### 4.2 数据范围注入基座（→ 阶段五 RBAC） <a id="scope"></a>

`app/scope/base.py`：`DataScope(BaseObject, ABC)`——`read_predicate()`（读过滤条件，规则由 RBAC 提供）、`allow_write(values)`（写校验，读写双向）；`NullDataScope`（占位：无过滤、恒允许）。

`BaseRepository` 新增钩子：

| 成员 | 说明 |
| --- | --- |
| `_data_scope: DataScope \| None` | 类属性默认 None（未注入） |
| `_apply_data_scope(scope)` | 注入数据范围（占位：仅挂载；读写过滤回补） |

### 4.3 分片路由基座（→ 阶段十一 分布式与监控） <a id="sharding"></a>

`app/sharding/base.py`：

| 成员 | 说明 |
| --- | --- |
| `ShardBinding(BaseObject)` | 分片解析结果：`db_key`（物理库）、`physical_table`（物理表） |
| `ShardingRouter(BaseObject, ABC)` | `resolve(logical_table, *, shard_key=None) -> ShardBinding` 抽象 |
| `NullShardingRouter` | 占位实现：不路由，返回 `default` + 逻辑表名（MVP 按月分表回补） |

`BaseRepository._resolve_shard` 接入：`_sharding_router`（类属性默认 None）为空返回逻辑表名，否则取 `resolve(...).physical_table`。

### 4.4 事件发布 / 消费基座（→ 阶段八 系统集成与消息） <a id="events"></a>

`app/events/base.py`：`EventEnvelope(BaseObject)`（`event_type` / `payload` / `trace_id`）；`EventPublisher(BaseObject, ABC)`（`publish` + `publish_transactional` 事务消息）；`EventConsumer(BaseObject, ABC)`（`subscribed_type` + `consume`，分区有序消费回补）。

### 4.5 Celery 任务基座（→ 阶段六 通用能力） <a id="tasks"></a>

- `app/tasks/base.py`：`BaseTask(BaseObject, ABC)`——`name`（抽象属性）、`queue`（默认 `default`）、`run(*args, **kwargs)`（抽象执行体）。
- `app/models/system.py`：`SysTask(BaseModel)`（`sys_task`：`name` 唯一、`handler`、`cron`、`enabled`）、`SysTaskLog(BaseModel)`（`sys_task_log`：`task_id`、`status`、`started_at` / `finished_at`、`result`）；表定义占位（不建表、不连库），调度入库与执行记录回补。

### 4.6 ORM 审计捕获基座（→ 阶段六 通用能力） <a id="audit"></a>

`app/audit/base.py`：`FieldChange(BaseObject)`（`field` / `old` / `new`）；`AuditCapturer(BaseObject, ABC)`——`is_audited(table)`（是否审计表）、`capture(*, table, model_id, changes, actor) -> EventEnvelope`（字段级变更 → 审计事件）；哈希链 / 分区有序消费回补。

## 5. 应用基类体系 <a id="base"></a>

- 契约基类统一 `Base*` 打头、继承 `BaseObject`（L0）；占位实现类非 `Base` 打头（`NullDataScope` / `NullShardingRouter`）。
- 继承链：`CacheRegion` / `DataScope` / `ShardingRouter` / `EventPublisher` / `EventConsumer` / `BaseTask` / `AuditCapturer → BaseObject`。

## 9. 边界与开放项 <a id="boundary"></a>

- 六类真实实现分别在阶段五 / 六 / 八 / 十一回补，实施时在对应阶段计划登记窗口（同一任务文档，不重复建任务）。
- `sys_task` / `sys_task_log` 表定义随回补落地（迁移、字段微调）；本阶段不建表、不连库。
- 缓存 key 前缀 `bms:` 与业务域简称遵循《命名规范》；分片键与物理表命名随回补固化。
