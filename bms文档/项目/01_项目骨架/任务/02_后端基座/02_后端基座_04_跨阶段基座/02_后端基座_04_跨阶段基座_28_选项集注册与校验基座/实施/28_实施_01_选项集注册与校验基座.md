## 2. 过程 <a id="process"></a>

1. **上下文**：按《AI开发规范》阅读顺序核对——需求 02-58、《组件设计 · 选项集字段》「候选来源：注册表选项集」节、《概要设计 · 表单定制》字段属性承载位、《概要设计 · 字典管理》业务规则、《命名规范》「通用原则」、《后端基类清单》§9、《后端基类实现契约》§6、《后端开发规范》§3.1、计划表与父任务清单。
2. **决策确认**：question 工具分四批共 15 项拍板（装配口径 / 缺省实现 / 冲突落点 / 产品覆盖判定 / `resolve` 语义 / `validate` 返回 / 引用校验 API / 内建清单 / 数据契约基型 / 版本口径 / Kiwi 条数 / 测试落点 / 投入与窗口 / 进度回写范围 / `config.toml` 分区）；另有 2 项实现细化（条目排序与冲突指纹、提供者 `namespace` / `name` / `version` / `info()`）记入设计 §15 第 16 / 17 行。
3. **设计回写（先行）**：原设计稿提供者「直取 `app.state`」改为**统一插件口径**（`Settings.option_set_registry` + `PluginWiring` + `register_plugin("option_set_registry","local",工厂)` + `resolve_plugin`）；补登记来源标记 `origin`、双向引用校验方法 + 同名模块薄封装、测试落点与 Kiwi 口径、进度回写范围，并补 §15 对齐记录。设计定稿已单独提交（`docs(02_28)`）。
4. **Kiwi 登记**：容器内 Django shell 查最新用例号（2335）后登记一条（**2336**，分类「平台骨架」、`P2`、`CONFIRMED`、标签「自动化」），覆盖范围写入用例文本。
5. **实施（基座）**：
   - `bms_core/optionset/__init__.py`：能力域包（docstring 口径）。
   - `bms_core/optionset/base.py`：常量 `OPTION_SET_KEY_SEPARATOR` / `OPTION_SET_KEY_PATTERN` / `PLATFORM_NAMESPACE` / 两来源标记；值对象 `OptionItem` / `OptionSetInfo`（frozen，集合字段 `ConcurrentStableFrozenList`）；`BaseOptionSet`（抽象 `key` / `describe` / `items` / `get` / `validate_value` + 具体 `namespace` / `name` / `version` / `info()`，`info()` 按 `sort` 升序后同 `value` 去重）；`BaseOptionSetRegistry`（覆写 `register`：标识校验、来源校验、单次声明归一与冲突、同标识合并 / 异义拒绝、产品覆盖基座拒绝；`origin_of` / `resolve` / `validate` / `check_references` / `unused_sets`）；`validate_option_set_key` 与两同名薄封装；提供者 `get_option_set_registry`。
   - `bms_core/optionset/null.py`：`NullOptionSetRegistry`（登记真实、`resolve` 恒定空集 `version=0`、`validate` 恒定通过）。
   - `bms_core/optionset/local.py`：`PLATFORM_OPTION_SETS`（本期空）+ `LocalOptionSetRegistry`（基座清单以 `platform`、注入项以 `product` 登记）。
   - `core/config.py`：`Settings` 增 `option_set_registry: PluginSelection`。
   - `core/assembly.py`：`_NULL_MODULES` 增 `bms_core.optionset.null`；`PLUGIN_WIRINGS` 增接线；`register_platform_plugins` 增 `local` 工厂登记；新增 `LocalOptionSetRegistryFactory`。
   - `api/deps.py`：导出 `get_option_set_registry`，docstring 补「选项集」。
6. **前置契约断言**：`services/platform/tests/crosscut/test_plugin_registration.py` 期望插件键补 `option_set_registry`。
7. **用例**：`libs/bms_core/tests/optionset/test_optionset.py`（12 条，`pytestmark = kiwi_id(2336)`）；覆盖契约继承 / 标识校验 / 数据契约缺省与 frozen / 合并 / 五类冲突 / 双向引用 / 解析与值域 / 占位语义 / 真实注册表 / 装载来源判定 / 依赖解析（含 `local` 插件键解析与探针路由）。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 设计稿提供者直取 `request.app.state.option_set_registry`，与现行能力域统一插件口径分叉 | 先回写设计 §6 / §8 / §15（统一 `resolve_plugin` + 配置分区 + 装配接线），再按新口径实施；`app.state` 仍由装配接线写入（供排障观察），提供者不再直取 |
| 2 | `BaseOptionSetRegistry` 无抽象方法 → 被插件注册表自动收集为 `(option_set_registry, null)`，与 `NullOptionSetRegistry` 撞名 | `_provider_key` 留 `@abstractmethod`（同 `BaseFieldTypeRegistry` 口径），由 `null` / `local` 各自声明；基座契约类回到抽象态、不再自动登记 |
| 3 | `LocalOptionSetRegistry` 声明 `plugin_name="local"` 后经继承自动登记，与显式 `register_plugin(..., "local", 工厂)` 撞名 | 移除类上 `plugin_name`（同 `LocalFieldTypeRegistry` 口径），实现名只由显式工厂登记提供 |
| 4 | `info()` 初版只排序未去重，同一 `value` 的重复声明在解析结果里出现两次 | 按《组件设计 · 选项集字段》「解析顺序」修正：`sort` 升序 → 同 `value` 去重保留首个 → 只读快照；补用例断言 |
| 5 | Kiwi 用例号需以平台自增主键为准 | 先查平台最新号（2335）再登记，取得 **2336** 并回填代码标注 |
