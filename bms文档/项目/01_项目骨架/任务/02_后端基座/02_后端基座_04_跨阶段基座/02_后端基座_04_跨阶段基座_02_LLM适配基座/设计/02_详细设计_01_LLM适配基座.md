## 1. 概述 <a id="overview"></a>

- **目标**：落地 LLM 适配能力域契约与占位实现——`app/llm/base.py` 的数据契约 `ChatMessage` / `ChatResult` / `EmbeddingResult` / `OcrResult`、统一 Provider 契约 `BaseLlmProvider`（`chat` / `embedding` / `ocr`）、占位实现 `NullLlmProvider`（固定返回、不调模型）；常量清单 `LLM_PROVIDER_TYPES` / `NULL_EMBEDDING_DIM` / `NULL_CHAT_REPLY` / `NULL_OCR_TEXT`；`app/api/deps.py` 提供者 `get_llm_provider`；`app/main.py` 装配单例。
- **范围**：`app/llm/`（新增）、`app/api/deps.py`（提供者导出）、`app/main.py`（装配）、单测；架构 04 §4 / §8、《后端基类清单》/《后端开发规范》/ 计划 / 需求 02-18 登记。
- **不含**（归后续阶段）：真实 Provider 实现（外部 API DeepSeek / Qwen、私有化端点 Ollama / vLLM、`sys_ai_provider` 端点与模型配置读取、API key Secret 管理、超时 / 重试 / 熔断）→ **AI 阶段（十七）**；AI 接口独立限流与预算控制 → 同阶段（复用 `BaseRateLimiter`）；RAG 管线（分段 / Milvus / 检索）、八项 AI 能力、交互审计 `ai_chat_log`、安全闸门（`ai.auto_execute` / `ai.auto_approve`）→ 同阶段；prompt 注入防护 → 同阶段。
- **依据**：需求 [02-18](../../../../../需求/02_需求_后端基座.md#r02-18)、《[架构设计 · AI 服务](../../../../../../../设计/架构设计/25_架构设计_子系统_AI服务.md)》「LLM 适配层」「八项能力」「交互审计」节、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[命名规范](../../../../../../../规范/命名规范.md)》「后端命名」节。

## 4. LLM 适配能力域（`app/llm/base.py`） <a id="llm"></a>

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER_TYPES` | `tuple[str, ...]` 常量 | Provider 类型清单：`("llm", "embedding", "ocr")`（对应 `sys_ai_provider.type`；占位期**仅登记不校验**） |
| `NULL_EMBEDDING_DIM` | `int` 常量 | 占位向量维度 `1024`（`NullLlmProvider.embedding` 生成零向量；真实维度随所选模型） |
| `NULL_CHAT_REPLY` | `str` 常量 | 占位对话回复 `"null-chat-reply"`（便于断言） |
| `NULL_OCR_TEXT` | `str` 常量 | 占位识别文本 `"null-ocr-text"`（便于断言） |
| `ChatMessage` | frozen dataclass（数据契约） | 对话消息：`content: str` / `role: str = "user"`（dataclass 字段序：必填在前） |
| `ChatResult` | frozen dataclass（数据契约） | 对话结果：`content: str` / `model: str \| None = None` / `provider_key: str \| None = None` |
| `EmbeddingResult` | frozen dataclass（数据契约） | 向量化结果：`vectors: tuple[tuple[float, ...], ...]` / `model: str \| None = None` / `provider_key: str \| None = None` |
| `OcrResult` | frozen dataclass（数据契约） | 识别结果：`text: str` / `model: str \| None = None` / `provider_key: str \| None = None` |
| `BaseLlmProvider(BaseCapability, ABC)` | 能力域契约中间层 | `key: str = "llm_provider"` |
| `chat(messages, *, provider_key=None, model=None) -> ChatResult` | 抽象方法（async） | 对话（真实实现调外部 / 私有化端点） |
| `embedding(texts, *, provider_key=None, model=None) -> EmbeddingResult` | 抽象方法（async） | 文本向量化（RAG 管线消费） |
| `ocr(image, *, provider_key=None, model=None) -> OcrResult` | 抽象方法（async） | 图片文字识别 |
| `NullLlmProvider(BaseLlmProvider, BaseNullObject)` | 占位实现 | `chat` 固定占位回复、`embedding` 固定维度零向量、`ocr` 固定占位文本（**不调模型**；`model` / `provider_key` 回显） |
| `get_llm_provider(request) -> BaseLlmProvider` | 模块函数（提供者） | 取应用级单例（`request.app.state.llm_provider`） |

**口径**：

| 情形 | 处置 |
| --- | --- |
| Provider 选择 | 三方法均带可选 `provider_key` / `model`；真实实现按 `sys_ai_provider`（`provider_key` 定位端点、`model` 覆盖默认）选择，占位**回显不校验** |
| `chat` 入参 | `messages: Sequence[ChatMessage]`（多轮对话；role 取 `user` / `assistant` / `system`） |
| `embedding` 返回 | `EmbeddingResult.vectors` 为 `tuple[tuple[float, ...], ...]`（每条文本一个向量，**frozen 契约用元组**保证不可变）；与 `texts` 等长 |
| `ocr` 入参 | `image: bytes`（扫描件 / 图片字节；真实实现本地 PaddleOCR 或多模态 API 可切换） |
| 结果携带 | 各结果回带 `model` / `provider_key`（便于审计与指标标签），占位回显入参 |
| 异步口径 | 三方法全异步（真实为载体网络 / 推理 IO） |
| 与限流 / 预算 | AI 接口独立限流与预算控制取 `BaseRateLimiter`（AI 阶段接入），本契约不实现 |
| 与审计 / 指标 | `ai_chat_log`（tokens / cost / model）与 `bms_ai_cost` 取数依赖本契约调用口径统一；落地归 AI 阶段 |
| 安全闸门 | 默认仅辅助、自动写 / 审批默认关闭、prompt 注入防护归 AI 阶段上层，本契约不实现 |

## 5. 应用装配与依赖注入 <a id="di"></a>

| 位置 | 变更 |
| --- | --- |
| `app/api/deps.py` | 导出 `get_llm_provider`（`app/llm/base.py`）；模块 docstring 补「LLM 适配」 |
| `app/main.py` `create_app()` | 装配 `app.state.llm_provider = NullLlmProvider()`（置于能力域基座装配段） |

提供者为普通同步函数（取 `app.state` 单例，无 IO）；本任务**不落路由**（AI 对话 / 向量化接口归 AI 阶段），故无路由与中间件改动。真实实现替换 `NullLlmProvider` 时调用面零改动。

## 6. 继承与分层 <a id="base"></a>

- `BaseLlmProvider → BaseCapability → BaseObject`；`NullLlmProvider → BaseLlmProvider + BaseNullObject → BasePlaceholder → BaseObject`。
- `ChatMessage` / `ChatResult` / `EmbeddingResult` / `OcrResult` 为能力域数据契约（frozen dataclass，同 `StoredObject` / `OAuthToken` / `SpanContext` 风格）。
- 与外部出站集成分工：出站集成为通用 HTTP / Webhook 通道；本域为 **AI Provider 专用契约**（chat / embedding / ocr 语义），不重复出站封装。

## 11. 边界与开放项 <a id="boundary"></a>

- **真实 Provider 实现**（外部 API DeepSeek / Qwen、私有化端点 Ollama / vLLM、`sys_ai_provider` 端点与模型配置、API key Secret 管理、超时 / 重试 / 熔断）→ AI 阶段（十七）；已登记计划「后续阶段待办」。
- **RAG 管线与八项 AI 能力**（分段 / embedding 事件驱动 / Milvus / OCR 衔接 / 语义检索 / NL2SQL 等）→ AI 阶段；embedding 经本契约 `embedding` 调用。
- **交互审计与安全闸门**（`ai_chat_log` 按月分片、prompt 注入防护、`ai.auto_execute` / `ai.auto_approve`）→ AI 阶段；模型 / 提供商标签取本契约结果字段。
- **AI 接口独立限流与预算控制** → AI 阶段；复用 `BaseRateLimiter`。
- **占位语义已知项**：占位回复 / 文本为常量串、向量为固定维度零向量（不反映真实语义）；真实判定随回补阶段生效——已知、可接受。
- **测试**：真实调用用例（外部 / 私有化端点连通、向量维度与语义、OCR 识别）随回补阶段补充。
