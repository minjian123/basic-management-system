## 1. 概述 <a id="overview"></a>

- **目标**：落地通知渠道能力域契约与占位实现——`app/notify/base.py` 的渠道枚举 `NotifyChannel`（站内信 / 邮件 / 短信）、数据契约 `NotificationMessage` / `SendResult`、统一发送契约 `BaseNotifier`（`send`）、占位实现 `NullNotifier`（固定返回成功、不真实发送）；常量 `NULL_MESSAGE_ID`；`app/api/deps.py` 提供者 `get_notifier`；`app/main.py` 装配单例。
- **范围**：`app/notify/`（新增）、`app/api/deps.py`（提供者导出）、`app/main.py`（装配）、单测；架构 04 §4 / §8、《后端基类清单》/《后端开发规范》/ 计划 / 需求 02-20 登记。
- **不含**（归后续阶段）：真实渠道实现（站内信落库 `sys_notification` + 实时推送、aiosmtplib 异步 SMTP + Jinja2 模板、阿里云 / 腾讯云短信）→ **通知公告阶段**；邮件 / 短信模板入库与在线编辑（`sys_mail_template` / `sys_sms_template` + i18n 附表）、发送记录（`sys_mail_log` / `sys_sms_log`）、渠道偏好过滤（`sys_user_preference` 开关与免打扰时段）、公告与已读回执（`sys_notice` / `sys_notice_read`）、短信渠道故障降级企业微信 / 钉钉 → 同阶段；通知生成的事件消费（通知组）→ 事件总线 / 通知公告阶段。
- **依据**：需求 [02-20](../../../../../需求/02_需求_后端基座.md#r02-20)、《[架构设计 · 通知公告](../../../../../../../设计/架构设计/22_架构设计_子系统_通知公告.md)》「站内信与待办通知」「邮件通知」「短信通知」节、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[命名规范](../../../../../../../规范/命名规范.md)》「后端命名」节。

## 4. 通知渠道能力域（`app/notify/base.py`） <a id="notify"></a>

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `NotifyChannel` | `StrEnum` | 渠道枚举：`INBOX = "inbox"`（站内信）/ `EMAIL = "email"`（邮件）/ `SMS = "sms"`（短信） |
| `NULL_MESSAGE_ID` | `str` 常量 | 占位消息 id `"null-message-id"`（`NullNotifier.send` 固定返回） |
| `NotificationMessage` | frozen dataclass（数据契约） | 通知消息：`channel: NotifyChannel` / `recipient: str` / `content: str` / `title: str = ""` / `biz_type: str \| None = None` / `biz_id: str \| None = None` |
| `SendResult` | frozen dataclass（数据契约） | 发送结果：`delivered: bool` / `message_id: str \| None = None` / `detail: str \| None = None` |
| `BaseNotifier(BaseCapability, ABC)` | 能力域契约中间层 | `key: str = "notifier"` |
| `send(message: NotificationMessage) -> SendResult` | 抽象方法（async） | 统一发送（按渠道分派；真实实现落站内信 / 发邮件 / 发短信） |
| `NullNotifier(BaseNotifier, BaseNullObject)` | 占位实现 | `send` 固定返回成功（`delivered=True`、`message_id=NULL_MESSAGE_ID`；**不真实发送**） |
| `get_notifier(request) -> BaseNotifier` | 模块函数（提供者） | 取应用级单例（`request.app.state.notifier`） |

**口径**：

| 情形 | 处置 |
| --- | --- |
| 渠道表示 | `NotifyChannel` 枚举（`inbox` / `email` / `sms`），与 `CircuitState` 等 `StrEnum` 风格一致 |
| `recipient` 语义 | 按渠道给定目标：站内信为用户 id、邮件为邮箱地址、短信为手机号 |
| `title` 语义 | 邮件主题 / 站内信标题；短信 / 无标题渠道可留空 |
| `biz_type` / `biz_id` | 业务关联（如 `approval` + 审批 id），供站内信跳转与去重；可选 |
| 传参形态 | 以 `NotificationMessage` 数据契约对象传参（便于扩展字段而不改方法签名） |
| 返回 | `SendResult`（`delivered` 是否发送成功、`message_id` 渠道回执 id、`detail` 失败说明） |
| 占位语义 | `NullNotifier.send` 固定返回成功（`delivered=True`、`message_id=NULL_MESSAGE_ID`），便于上层链路验证；不真实发送 |
| 渠道偏好过滤 | 发送前按用户偏好（`sys_user_preference`）与免打扰时段过滤渠道——归上层（通知公告阶段），本契约不实现 |
| 模板与 i18n | 邮件 / 短信模板落库与按收件人 locale 渲染归上层；本契约接收已渲染内容 |
| 异步口径 | `send` 异步（真实为载体网络 IO） |
| 降级 | 短信渠道故障降级企业微信 / 钉钉（架构 21）归上层 / 回补阶段，本契约不实现 |

## 6. 继承与分层 <a id="base"></a>

- `BaseNotifier → BaseCapability → BaseObject`；`NullNotifier → BaseNotifier + BaseNullObject → BasePlaceholder → BaseObject`。
- `NotifyChannel` 为渠道枚举（`StrEnum`，同 `CircuitState` / `FallbackAction`）；`NotificationMessage` / `SendResult` 为能力域数据契约（frozen dataclass）。
- 与实时推送 / 事件总成分工：本域管「通知发送」；站内信发送后触发实时推送（`notification.new`）为上层职责（通知公告阶段接线），实时推送基座归 02-4-5。

## 11. 边界与开放项 <a id="boundary"></a>

- **真实渠道实现**（站内信落库 `sys_notification` + 实时推送、aiosmtplib 异步 SMTP、阿里云 / 腾讯云短信）→ 通知公告阶段；已登记计划「后续阶段待办」。
- **模板与记录**（`sys_mail_template` / `sys_sms_template` + i18n 附表在线编辑、`sys_mail_log` / `sys_sms_log`）→ 通知公告阶段。
- **渠道偏好过滤与免打扰时段**（`sys_user_preference`）→ 通知公告阶段上层。
- **公告与已读回执**（`sys_notice` / `sys_notice_read`、过期自动下线）→ 通知公告阶段（含任务调度）。
- **通知生成事件消费**（业务事件 → 通知组 → 站内信）→ 事件总线 / 通知公告阶段。
- **短信渠道故障降级企业微信 / 钉钉** → 通知公告 / 运维阶段。
- **占位语义已知项**：占位 `send` 固定返回成功（不反映真实发送）；真实判定随回补阶段生效——已知、可接受。
- **测试**：真实发送用例（站内信落库、SMTP 发送、短信渠道）随回补阶段补充。
