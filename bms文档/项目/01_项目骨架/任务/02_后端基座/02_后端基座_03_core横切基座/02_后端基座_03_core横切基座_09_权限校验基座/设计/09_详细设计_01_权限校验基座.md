## 4. 契约核对（`app/permission/base.py`） <a id="contract"></a>

| 成员 | 形态 | 需求 02-24 对应条目 |
| --- | --- | --- |
| `BasePermissionChecker(BaseCapability, ABC)` | 能力域契约中间层，`key: str = "permission"` | 第 1 条「统一校验接口（能力域中间层）」 |
| `check(code) -> bool` | 抽象方法 | 第 1 条「`check` 签名」 |
| `require(code) -> None` | 具体方法，失败抛 `PermissionError`（30001 / 403） | 第 1 条「校验接口」（与依赖工厂配套） |
| `NullPermissionChecker(BasePermissionChecker, BaseNullObject)` | 占位实现，**恒定允许**（不读权限数据） | 第 2 条「占位实现 `NullPermissionChecker` 恒定允许」 |
| `get_permission_checker(request) -> BasePermissionChecker` | 依赖注入提供者（取 `app.state.permission_checker`） | 第 1 条「依赖注入可解析」 |
| `require_permission(code) -> Callable[..., None]` | FastAPI 依赖工厂（接口侧 `Depends(require_permission("业务:动作"))`） | 第 1 条「`require_permission` 依赖签名」 |

**与需求原文的口径差异说明**：需求第 1 条写作「`check` / `require_permission` 依赖签名」——本契约按该口径同时提供**依赖工厂** `require_permission`（对应需求原文）与**方法级** `require`（供基座内与非 FastAPI 场景调用，脱敏基座 `check_plain()` 即走此路径），二者共用 `check` 单一判定源，不引入第二套判定。

## 5. 继承与分层 <a id="base"></a>

- `BasePermissionChecker → BaseCapability → BaseObject`（能力域契约中间层口径，与 `BaseMasker` / `BaseDistributedLock` / `BaseCaptcha` / `BasePasswordPolicy` / `BaseFallbackPolicy` 同形）。
- `NullPermissionChecker → BasePermissionChecker + BaseNullObject → BasePlaceholder → BaseObject`（`placeholder` 标记 + `describe()` 统一描述）。
- 职责分工：`BasePermissionChecker` 管**权限码校验**（`业务:动作`，如 `data:plain`）；`DataScope`（`app/scope/base.py`）管**数据侧范围过滤**（行级读写条件）；二者互补，不互相替代。

## 7. 回补口径与消费方 <a id="deferred"></a>

| 回补 / 消费事项 | 阶段 | 说明 |
| --- | --- | --- |
| 真实 RBAC 判定（角色 → 权限码集合、多链并集去重） | 七 RBAC | 替换 `NullPermissionChecker`；权限码来源 `sys_business` / `sys_action`（平台库） |
| 主体链（用户 → 中间实体 → 角色，任意长度） | 七 RBAC | 通用绑定表 `sys_role_assign`（`subject_type` + `subject_id` + `role_id`）；新增实体类型仅扩展枚举 |
| 权限分层（菜单 → 表单 → 业务、按钮 → 动作、字段可见可编辑） | 七 RBAC | 菜单 / 表单 / 业务为**推导关系**（业务权限抽象解耦层不直接授予）；字段权限读时过滤 + 写时校验 |
| `data:plain` 与脱敏联动 | 七 RBAC | `BaseMasker.check_plain()` 单点调用本契约 `check("data:plain")`，调用方不传权限参数 |
| 接口侧逐接口接入 `require_permission("业务:动作")` | 各模块实现 / 认证 · RBAC 阶段 | 新增接口必须声明权限码（《API接口规范》§7.1、§7.2）；平台接口（`platform:manage`）已登记计划「后续阶段待办」 |
| `require_permission` 拒绝路径错误响应 | 认证 / RBAC 阶段 | `PermissionError` → 30001 / 403 已由全局处理器统一转响应（02-3-1 交付） |

## 11. 边界与开放项 <a id="boundary"></a>

- **真实 RBAC + 主体链 + 权限分层** → 七 RBAC 阶段；已登记计划「后续阶段待办」（`data:plain` 与权限分层两行）；实现期要点见需求 02-24 `> 注：` 块。
- **字段权限**（`visible` / `editable` 读时过滤与写时校验）→ 随《架构设计 · 权限计算引擎》「字段权限」节与 RBAC 阶段；与 `BaseSchema.masked_fields` 掩码是两条独立链路（掩码防泄露、字段权限防越权读取）。
- **OAuth2 scope 与权限码关系** → [02-3-13 开放接口 OAuth2 服务端与 scope 基座](../../02_后端基座_03_core横切基座_13_开放接口OAuth2服务端与scope基座/02_后端基座_03_core横切基座_13_开放接口OAuth2服务端与scope基座.md)：scope 为**授权面收敛**（第三方应用可访问范围），权限码为**主体权限判定**；开放接口侧口径在 02-3-13 落地时对齐（任务文档已标注协同契约）。
- **权限码命名与总表**：一律 `业务:动作`（《命名规范》「后端命名」节、《项目规划说明》「业务与动作清单（权限码总表）」），新增接口必须声明权限码；本基座不维护权限码清单。
- **缓存**：权限码集合的缓存与失效随 RBAC 阶段定稿（缓存三防属阶段八 通用能力）。
- **测试**：真实 RBAC 判定用例（角色并集、中间实体、权限分层推导、缓存失效）随回补阶段补充。
