## 2. 任务内容 <a id="content"></a>

1. 日志基座接入点声明：structlog 初始化入口（`app/core/logging.py` 或等价位置）与「日志只写 stdout、不落文件」约定；`request_id` / `trace_id` 贯穿约定（`X-Request-Id`）；渲染形态由配置 `[log] format` 控制（真实实现归需求 03-2 日志体系）
2. **中间层基类**：在详细设计中定义日志门面 / 结构化日志的中间层基类（纳入 `BaseObject` 体系），统一接入点、上下文与脱敏口径，避免模块各自 logger；具体形态随 03-2 日志体系细化
3. 登记：日志基座的职责与代码位置回写《架构设计 · 后端基础类体系》

## 3. 完成标准 <a id="accept"></a>

日志基座接入点声明就位、可被上层引用、依赖注入可解析、应用可启动不报错；`pytest`、`ruff`、`pyright` 全绿。**不实现日志细节**。
