## 4. 问题与处置 <a id="issues"></a>

| 问题 | 原因 | 处置与落点 |
| --- | --- | --- |
| 场景枚举断言变化 | `CAPTCHA_SCENES` 由三项扩为五项（本轮拍板） | 同步 `tests/captcha/test_captcha.py` 一处断言；历史用例语义与断言其余部分不动 |
| 两类验证码错误码分支在占位实现下不可达 | 占位三形态恒定通过（无状态、不真发） | 以**测试替身**（`verify_credential` 恒定 `False`）覆盖 `require_credential` 抛错路径；两个码位子类直接实例化断言码位 / HTTP 状态 |
| `check-backend-base.py` 清单对账 2 项失败 | 新增两数据契约直接继承 `BaseObject` 未登记 | 按预期在《后端基类清单》登记后通过（护栏生效，见[实施记录](../实施/14_实施_01_验证码渠道扩展基座.md)「问题与处置」） |
| `pyright` 报 `trace` 类型部分未知 | `default_factory` 未参数化 | 改 `default_factory=list[tuple[int, int, int]]`（仓库既有写法） |
