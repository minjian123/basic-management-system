## 1. 概述 <a id="overview"></a>

- **目标**：落地认证公共机制的两组契约与占位实现——`app/captcha/base.py` 的 `BaseCaptcha`（`generate` 返回挑战值对象 / `verify` 校验）+ `NullCaptcha`（恒定通过），`app/password/base.py` 的 `BasePasswordPolicy`（`validate` / `expired` / `reused`）+ `NullPasswordPolicy`（恒定允许）；验证码 key 统一拼接 `build_captcha_key`；两个依赖注入提供者与 `create_app` 装配。
- **范围**：`app/captcha/`、`app/password/`（新增）、`app/api/deps.py`（提供者导出）、`app/main.py`（装配）、单测。
- **不含**（归相邻任务 / 后续阶段）：真实 Pillow 出图与 Redis 存取（`bms:global:captcha:{uuid}`）、验证码失败计数与强制策略、密码复杂度 / 有效期 / 历史比对等真实规则 → **六 认证与安全**（需求 02-31 口径，同一任务文档不重复立项）；密码哈希原语 `PasswordHasher`（PBKDF2）→ 已交付的 `core/security.py`（随认证阶段填实现）；账号锁定（`sys_account_lock`，`fail_limit` / `inactive` / `manual`）与 180 天未登录扫描 → 认证阶段与任务调度；登录失败限流 → 02-3-10 限流幂等防重放中间层与认证阶段。
- **依据**：需求 [02-31](../../../../../需求/02_需求_后端基座.md#r02-31)、《[架构设计 · 子系统_认证与会话](../../../../../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》「密码与账号策略」节、《[架构设计 · 性能与安全](../../../../../../../设计/架构设计/31_架构设计_性能与安全.md)》「认证与存储安全」节、《[架构设计 · 数据架构](../../../../../../../设计/架构设计/07_架构设计_数据架构.md)》「key 空间规划」节、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节。

## 2. 现状与差距 <a id="gap"></a>

| 现状 | 差距 |
| --- | --- |
| 全库无 `BaseCaptcha` / `NullCaptcha` / `BasePasswordPolicy` / `NullPasswordPolicy`（检索零命中）；无 `app/captcha/`、`app/password/` 目录 | 登录图形验证码与密码策略无统一契约；若混入登录实现，策略调整会牵动登录逻辑 |
| `app/core/security.py` 只有**安全原语**（`BaseSecurity` + `PasswordHasher` / `TokenCodec` / `SessionSecurity`，占位抛错） | 原语是「工具」、认证机制是「策略与流程」，二者边界需明确（见第 6 节） |
| 验证码 key 与 TTL 已登记（架构 07「key 空间规划」节 `bms:global:captcha:{uuid}`；架构 13「密码与账号策略」节 TTL 5 分钟） | 无统一 key 拼接入口与 TTL / 场景常量 |
| 密码策略四项已定（复杂度 / 90 天有效期 / 近 5 次不可重复 / 180 天未登录锁定，sys_config 可配） | 无契约承载「校验 / 过期 / 重复」三个判定，无违规原因码口径 |
| `app/api/deps.py` 已汇总 `get_db` / `get_uow` / `get_tenant` / `get_masker` / `get_permission_checker` / `get_distributed_lock` | 两个新能力域无提供者，「依赖注入可解析」无落点 |

## 4. 验证码能力域设计（`app/captcha/base.py`） <a id="captcha"></a>

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `CAPTCHA_KEY_PREFIX` / `GLOBAL_CAPTCHA_SCOPE` | `str` 常量 | `"bms"` / `"global"`（验证码为全局 key，无租户维度，按架构 key 空间登记） |
| `CAPTCHA_TTL` | `int` 常量 | 验证码有效期 `300` 秒（5 分钟，架构 13「密码与账号策略」节） |
| `CAPTCHA_SCENES` | `tuple[str, ...]` 常量 | 场景取值：`("login", "reset_password", "bind")`；占位期仅登记、不校验 |
| `build_captcha_key(captcha_id) -> str` | 模块函数 | 统一拼 `bms:global:captcha:{uuid}` |
| `CaptchaChallenge` | `@dataclass(frozen=True)`，继承 `BaseObject` | 值对象：`captcha_id` / `image`（PNG 字节）/ `expires_in`（默认 `CAPTCHA_TTL`）/ `scene`（默认 `login`） |
| `BaseCaptcha(BaseCapability, ABC)` | 能力域契约中间层 | `key: str = "captcha"` |
| `generate(scene="login") -> CaptchaChallenge` | 抽象方法（async） | 生成验证码：真实实现 Pillow 出图 + 写 Redis（TTL `CAPTCHA_TTL`） |
| `verify(captcha_id, code) -> bool` | 抽象方法（async） | 校验验证码：真实实现校验后即删除（**单次有效**）、过期或不存在返回 `False` |
| `NullCaptcha(BaseCaptcha, BaseNullObject)` | 占位实现 | `generate` 恒定返回挑战（`image=b""`）、`verify` 恒定 `True`（**恒定通过**，不连 Redis） |
| `get_captcha(request) -> BaseCaptcha` | 模块函数（提供者） | 取应用级单例（`request.app.state.captcha`） |

**占位与口径**：

| 情形 | 处置 |
| --- | --- |
| `image` | 占位返回 `b""`（真实实现为 PNG 字节；Pillow 为同步阻塞库，回补时经线程池执行） |
| `captcha_id` | 占位用 `uuid4().hex`（形状与真实实现一致） |
| 单次有效 | 真实实现 `verify` 成功后删除 key；占位无状态、恒定通过 |
| 失败计数 / 连续失败 3 次强制 | 登录侧口径（架构 13），**不在基座内**；基座只提供校验能力 |
| `scene` | 取值见 `CAPTCHA_SCENES`；占位透传不校验 |

## 5. 密码策略能力域设计（`app/password/base.py`） <a id="password"></a>

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `PASSWORD_VIOLATIONS` | `tuple[str, ...]` 常量 | 违规原因码：`too_short` / `too_long` / `need_upper` / `need_lower` / `need_digit` / `need_symbol` / `username_included`；占位期仅登记，供上层映射提示文案（如 `error.password.{code}`） |
| `BasePasswordPolicy(BaseCapability, ABC)` | 能力域契约中间层 | `key: str = "password_policy"` |
| `validate(password, *, username=None) -> tuple[str, ...]` | 抽象方法（async） | 复杂度校验：返回违规原因码元组，**空元组＝通过**（不抛错，便于一次返回全部违规项） |
| `expired(pwd_changed_at, *, now=None) -> bool` | 抽象方法（async） | 是否超过有效期（真实实现按 sys_config 的 90 天、由 `pwd_changed_at` 驱动） |
| `reused(password, *, history) -> bool` | 抽象方法（async） | 是否命中历史密码（真实实现按近 5 次 `pwd_history` 比对；`history` 由调用方取，基座不查库） |
| `NullPasswordPolicy(BasePasswordPolicy, BaseNullObject)` | 占位实现 | `validate` 返回空元组、`expired` / `reused` 恒定 `False`（**恒定允许**） |
| `get_password_policy(request) -> BasePasswordPolicy` | 模块函数（提供者） | 取应用级单例（`request.app.state.password_policy`） |

**口径**：

| 情形 | 处置 |
| --- | --- |
| 返回形态 | 违规原因码元组（不抛异常）——调用方按文案映射提示，异常转译由接口层按需做（`ParamError` 10001） |
| `now` 参数 | 便于测试注入时间；`None` 时用当前时间 |
| `history` 参数 | 历史哈希 / 历史明文字符串序列由调用方提供（避免基座直连库），真实实现按 PBKDF2 校验比对 |
| 180 天未登录自动锁定 | 任务调度内置任务（架构 13），不在本基座 |
| 策略参数来源 | 真实实现从 sys_config 读取（复杂度规则 / 90 天 / 5 次），占位不读配置 |

## 6. 与既有安全原语的边界 <a id="boundary-security"></a>

| 维度 | `app/core/security.py`（安全原语，已交付占位） | `app/captcha/`、`app/password/`（认证公共机制，本任务） |
| --- | --- | --- |
| 内容 | `PasswordHasher`（PBKDF2 哈希 / 校验）、`TokenCodec`（双 token）、`SessionSecurity`（会话 id / 指纹 / 黑名单键） | 图形验证码（生成 / 校验）、密码策略（复杂度 / 有效期 / 历史重复） |
| 性质 | 无状态「工具」，纯计算或签名 | 「策略与流程」，涉及存储（Redis）、配置（sys_config）与时间语义 |
| 存储 | 不依赖存储 | 验证码依赖 Redis key `bms:global:captcha:{uuid}` |
| 回补阶段 | 六 认证与安全 | 六 认证与安全 |

## 8. 继承与分层 <a id="base"></a>

- `BaseCaptcha → BaseCapability → BaseObject`；`NullCaptcha → BaseCaptcha + BaseNullObject → BasePlaceholder → BaseObject`。
- `BasePasswordPolicy → BaseCapability → BaseObject`；`NullPasswordPolicy → BasePasswordPolicy + BaseNullObject → BasePlaceholder → BaseObject`。
- 与 `NullDataScope` / `NullMasker` / `NullDistributedLock` 同构；`CaptchaChallenge` 为能力域内值对象（同 `ScopeCondition` / `MaskRule` / `FieldChange` 风格）。

## 13. 边界与开放项 <a id="boundary"></a>

- **真实实现**（Pillow 出图经线程池、Redis 读写 `bms:global:captcha:{uuid}`、`verify` 单次失效、sys_config 策略规则、`pwd_history` 比对、90 天有效期）→ **六 认证与安全**；已登记计划「后续阶段待办」表。
- **验证码强制策略**：连续失败 3 次强制要求、失败计数窗口 → 登录侧（架构 13），消费方接入随认证阶段。
- **账号锁定**（`fail_limit` / `inactive` / `manual`）与 180 天未登录扫描 → 认证阶段与任务调度（架构 13、架构 16），不在本基座。
- **登录失败限流**：slowapi Redis 后端 → 02-3-10 限流幂等防重放中间层与认证阶段。
- **密码哈希**：`PasswordHasher`（PBKDF2）已在 `core/security.py` 占位，随认证阶段填实现；本基座只做策略判定，不重复哈希。
- **验证码图片传输**：接口层以 base64 / 二进制流返回由认证阶段定稿（本基座只返回字节）。
- **测试**：真实 Pillow / Redis 集成用例随六 认证与安全阶段补充。
