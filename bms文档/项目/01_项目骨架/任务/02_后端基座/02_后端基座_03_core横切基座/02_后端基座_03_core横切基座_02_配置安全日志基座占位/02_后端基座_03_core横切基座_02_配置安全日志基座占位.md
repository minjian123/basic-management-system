## 2. 任务内容 <a id="content"></a>

> **本阶段口径（接口占位）**：只落接口 / 抽象声明与占位实现（返回固定或批量数据，便于上层先跑通链路），不连真库、不跑迁移、不建表；下方为实现要点，随对应后续阶段填实现。
1. 配置基座沿用与登记：`app/core/config.py`（config.toml 分区 + `BMS_` 环境变量覆盖 + 启动校验）由**阶段一 02-1 配置管理交付**，本任务只做基座登记与统一入口确认，不重复实现。
2. 安全基座 `app/core/security.py`：密码哈希、令牌与会话安全原语收敛，供阶段四认证与会话复用（本任务只落基座接口与实现，不实现登录链路）。
3. 基座登记回写：`BaseObject` / `BaseCollection`（有序集合）/ `ConcurrentSorted*` / Redis 有序封装 / `BaseRepository` / `BaseService` / `BaseSchema` 的职责、继承关系与代码位置，与《[架构设计 · 后端基础类体系](../../../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》及《[后端开发规范](../../../../../../规范/后端开发规范.md)》保持同源；差异补齐（架构节点已建，本任务负责代码侧对齐）。
4. 继承约定校验：新增/改造类必须继承对应基类，禁止重复定义公共字段/方法（评审条款 + 代码注释标注）。

## 3. 完成标准 <a id="accept"></a>

接口 / 抽象声明就位、依赖注入可解析、应用可启动不报错、占位实现返回固定或批量数据可支撑上层链路；`pytest`、`ruff`、`pyright` 全绿。

> 实现期验收要点（随后续阶段）：配置基座沿用阶段一 02-1 交付件并完成登记、安全基座就位并被后续阶段引用；《架构设计 · 后端基础类体系》基类清单与代码实现一致；继承约定纳入规范且可核对；`uv run pytest` / `ruff check .` / `pyright` 全绿。
