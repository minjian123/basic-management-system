## 1. 概述 <a id="overview"></a>

- **目标**：落地 `BizError` 统一异常体系与全局异常处理器——业务异常携带错误码与 `http_status`，全局统一转 `ApiResponse` `{code, message, data}`；`NotFoundError` 由临时实现改为 `BizError` 子类；移除临时 404 处理器。
- **范围**：`app/core/exceptions.py`（`BizError` + 7 子类）、`app/schemas/common.py`（`ApiResponse`）、`app/api/errors.py`（处理器注册）、`main.py` / demo 接口接入、单测。
- **不含**（归相邻任务）：配置 / 安全 / 日志基座（[02-3-2 / 02-3-3 / 02-3-4](../../02_后端基座_03_core横切基座.md)）；各业务域具体错误码（认证 / RBAC 等后续阶段按段位登记）；认证与权限校验实现。
- **依据**：需求 [02-9](../../../../../需求/02_需求_后端基座.md#r02-9)、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「异常与错误码」节、《[API接口规范](../../../../../../../规范/API接口规范.md)》「统一响应」「错误码」节、《[架构设计 · 接口与集成](../../../../../../../设计/架构设计/09_架构设计_接口与集成.md)》「错误码分段」节。

## 2. 现状与差距 <a id="gap"></a>

| 现状 | 差距 |
| --- | --- |
| `app/core/exceptions.py` 仅 `NotFoundError`（占位 `Exception`）与 `ConcurrentConflictError` | 无 `BizError` 体系与错误码 |
| `main.py` 注册临时 `NotFoundError → 404 {"detail": ...}` | body 结构与统一响应不一致 |

| 无全局处理器（校验 / 未捕获） | 未捕获异常默认 500 可能泄露堆栈 |

## 4. BizError 与异常子类设计 <a id="errors"></a>

`app/core/exceptions.py`：`BizError` **继承 `BaseObject`**（纳入 L0 继承体系，获得统一序列化 / 字符串输出），同时是 `Exception`；错误码统一引用 `app/core/error_codes.py`。

```python
class BizError(BaseObject, Exception):
    """业务异常基类：携带业务错误码、HTTP 状态与数据。"""

    def __init__(self, code: int, message: str | None = None, *, http_status: int = 200, data: object | None = None) -> None: ...
    def __str__(self) -> str: ...  # 优先消息，缺省回落 i18n key
```

**错误码基座**（`app/core/error_codes.py`）：平台错误码与段位的**统一登记点**。

| 项 | 说明 |
| --- | --- |
| `ErrorCode`（IntEnum） | 平台码位：`INTERNAL` 10000、`PARAM` 10001、`NOT_FOUND` 10002、`CONFLICT` 10003、`CONCURRENT_CONFLICT` 10004、`AUTH` 20001、`PERMISSION` 30001 |
| `ErrorSegment`（IntEnum） | 段位：`GENERAL` 1 / `AUTH` 2 / `USER_ORG` 3 / `CONFIG` 4 / `FILE` 5 / `WORKFLOW` 6 / `NOTIFY_TASK` 7 / `OPEN_TENANT` 8 / `REPORT_AUDIT` 9 |
| 扩展 | 业务模块扩展段 `10xxxx` 起，模块各自定义错误码并引用注册段位，不得占用平台段 |

| 异常类 | 错误码（`ErrorCode`） | `http_status` | 说明 |
| --- | --- | --- | --- |
| `BizError` | 自定义 | 200（默认） | 业务异常基类（`BaseObject` + `Exception`） |
| `InternalError` | `INTERNAL` 10000 | 500 | 系统内部错误（未预期） |
| `ParamError` | `PARAM` 10001 | 200 | 参数 / 校验失败 |
| `NotFoundError` | `NOT_FOUND` 10002 | 404 | 资源不存在（由占位 `Exception` 改继承 `BizError`） |
| `ConflictError` | `CONFLICT` 10003 | 200 | 业务冲突（唯一键 / 状态） |
| `ConcurrentConflictError` | `CONCURRENT_CONFLICT` 10004 | 409 | 并发冲突（乐观锁 / 重试超限，`redis_collections` 复用） |
| `AuthError` | `AUTH` 20001 | 401 | 认证失效（认证阶段填充实现） |
| `PermissionError` | `PERMISSION` 30001 | 403 | 权限不足（RBAC 阶段填充实现） |

- `message` 可选：默认回落 i18n key `error.{code}`（文案由前端按码映射，后端不承担拼装）。
- `http_status` 承载传输层语义（404 / 401 / 403 / 409），其余业务失败统一 200（与《API接口规范》一致）。
- 继承链：`子类 → BizError → BaseObject`；错误码只改 `error_codes.py`（单点）。

## 5. 统一响应 ApiResponse 设计 <a id="response"></a>

`app/schemas/common.py`：

```python
class ApiResponse(BaseSchema):
    """统一响应体：{code, message, data}。"""

    code: int = 0
    message: str = "ok"
    data: Any = None

    @classmethod
    def ok(cls, data: Any = None) -> "ApiResponse": ...
```

- 继承 `BaseSchema`（Pydantic 公共配置 + 声明字段优先序列化）。
- 成功 `code=0`、`message="ok"`；分页 `data` 复用 02-2-3 的 `BasePageResponse` / `BaseCursorResponse`。
- 雪花 ID 在 JSON 中按字符串输出（`BaseSchema` 序列化口径 + 业务侧转换，见《数据库开发规范》「字段规范」节）。

## 6. 全局异常处理器设计 <a id="handlers"></a>

`app/api/errors.py`：`register_exception_handlers(app: FastAPI) -> None`（FastAPI 处理器属 api 层）。

| 处理器 | 行为 |
| --- | --- |
| `BizError` | `JSONResponse(status_code=exc.http_status, content=ApiResponse(code=exc.code, message=exc.message or f"error.{exc.code}", data=exc.data))` |
| `RequestValidationError` | 转 `ParamError`（10001）统一响应（`data` 含字段错误明细，开发期便于定位） |
| `Exception`（未捕获） | 500 + `InternalError`（10000）；**不暴露堆栈**；记录完整堆栈日志 |

- **trace_id**：读取请求头 `X-Request-Id`（缺失生成 UUID4），回写响应头；未捕获异常日志含 trace_id（真实链路追踪随 02-3-4 / 03-2）。
- `main.py` 调用 `register_exception_handlers(app)`，移除临时 `not_found_handler`；根路由与 `api/demo.py` 改用 `ApiResponse`。

## 7. 业务异常使用规则 <a id="usage"></a>

- 业务异常在 **services 层抛出**（`raise BizError(code=..., message=...)` 或子类），api 层不 `catch` 业务异常。
- 参数校验优先 Pydantic；自定义校验失败抛 `ParamError`（10001）。
- 仓储层不抛业务异常（不存在返回 `None`）；服务层将不存在转 `NotFoundError`。
- 不向外暴露堆栈与内部细节（生产）；异常日志记录完整堆栈。

## 11. 边界与开放项 <a id="boundary"></a>

- 各业务域具体错误码（2xxxx / 3xxxx / 4xxxx…）随对应模块登记；本任务只建骨架码位。
- `AuthError` / `PermissionError` 本阶段仅定义类与码位，认证 / RBAC 阶段填充实现。
- trace_id / 日志字段的真实链路追踪随 02-3-4 / 03-2 日志体系；`InternalError` 消息不暴露细节。
- `message` 默认回落 i18n key；前端按 `error.{code}` 映射文案。
