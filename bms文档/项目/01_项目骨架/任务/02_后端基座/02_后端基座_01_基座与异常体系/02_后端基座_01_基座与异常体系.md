## 3. 任务内容 <a id="content"></a>

1. 异常体系与统一响应契约：`BizError` 体系 → 全局异常处理器 → 统一响应 `{code, message, data}`（HTTP 状态码与业务错误码分离），错误码段位登记，替换阶段一临时 404 处理器
2. core 横切基座补齐与登记：安全基座落位；配置基座只提供统一入口的**方法与结构**（占位实现，不真实读取），真实 `config.toml` 读取与启动校验由 [03 后端基础能力](../../03_后端基础能力/03_后端基础能力.md) 的配置管理落地后回填登记；工程骨架已交付的 core 基座（`BaseObject` / 有序集合 / 并发集合 / Redis 封装）与三套基类（`BaseRepository` / `BaseService` / `BaseSchema`）在《[架构设计 · 后端基础类体系](../../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》与《[后端开发规范](../../../../../规范/后端开发规范.md)》回写登记
3. 继承约定收口：新增 / 改造类必须继承对应基类，禁止重复定义公共字段 / 方法（CI lint 或评审条款）

## 4. 完成标准 <a id="accept"></a>

`BizError` 及各子类可用、业务异常经全局处理器转统一响应、未捕获异常返回 500 且不泄露堆栈；阶段一临时处理器移除；core 基座清单与代码实现一致、配置基座结构就位、安全基座可被后续阶段引用；继承约定纳入规范且可核对；`pytest`、`ruff`、`pyright` 全绿（逐项验收见子任务清单）。
