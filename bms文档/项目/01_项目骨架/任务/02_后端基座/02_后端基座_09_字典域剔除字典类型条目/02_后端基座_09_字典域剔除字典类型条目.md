## 2. 任务内容 <a id="content"></a>

**口径来源（2026-10-11 用户拍板 + 逐项确认）**：**字典域＝原始需求**——字典字段、取数、缓存、翻译、数据权限左列、字典页；「**字典**」＝**基础数据 / 参考数据**（含主数据，但**不止主数据**：bms 的用户 / 角色 / 租户、biz 的仓库储位等也都是字典）。AI 自行编造的「**字典类型 / 字典条目 / 字典属性**」一套（实质是「选项类型 / 选项条目」）被借「字典」之名混入，**剔除之**；被剔处的取数改由**字典数据源登记 + 统一出口**承载。**不存在「拆除字典域」**（原立项作废）。

1. **删除（编造内容）**：「字典类型 / 字典条目 / 字典属性」——表 `sys_dict_type` / `sys_dict_item` / `sys_dict_attr` + 3 张 `_i18n` 附表；`bms_core/dict/` 的 `models` / `service`（维护写路径）/ `seed`（六表种子）/ `sql`（本地六表取数实现）；`ops/seed_dict.py` / `ops/backfill_dict_parent_id.py`；`platform/api/dict.py` 的**维护 / 属性**端点（`/types*`、`/items*`、`/attrs*`）；相关表文件与总览登记。
2. **保留（字典域本体，命名仍「字典」、路径仍 `/api/v1/dicts/*`）**：取数 / 翻译 / 缓存契约与实现（`dict/base|cache|null`）、**高级查询**（`/{dict_key}/attrs`、`/query-providers`、`/{dict_key}/advanced-query`）与查询方案（`sys_query_scheme`，含 `target=business` 列表筛选）、前端字典字段组件族、数据权限左列、字典页、字典需求（02-44 / 02-56）。
3. **新增（字典承载）**：**字典数据源登记**（统一注册表 + 构建期清单，各项目装载注入、运行期只读）+ **字典统一出口** + `GET /api/v1/dicts`（可用字典登记清单）；字典**取数 / 缓存 / 翻译 / 高级查询**改由登记出口供数（不再读本地字典表）。
4. **改指（不删）**：`dict/query`（高级查询执行）/ `dict/providers`（业务查询提供者）/ `dict/http`（跨服务读出口）改为**经登记出口取数**；登记项数据本体归各所有者域（平台实体表 / mdm / biz），消费方不直连权威库。
5. **命名（全仓收口）**：《命名规范》新增「**标识统一用 `key`、代码统一用 `code`**」；字典标识 `dict_type` / `dictType` → **`dict_key` / `dictKey`**（后端参数、`{dict_type}` 路径参、前端字段族、契约快照、`@bms/api-types` 全链改名）。
6. **数据权限**：`sys_data_scope` 归属由字典类型改按**字典标识**——`dict_type_id`（BIGINT）→ **`dict_key` VARCHAR(64)**（业务码字符串，如 `org_dept` / `sys_user` / `wms_bin`）；存量行迁移内清空、不回填；校验改由登记提供字段白名单与存在性。**查询方案**表 `sys_query_scheme.dict_type` 同步改 **`dict_key`**（2026-10-11 追加确认）。
7. **文档**：只改「字典类型 / 字典条目」相关内容；字典域文档（字典字段 / 字典页 / 概设 09 取数段 / 数据架构取数缓存段）**保留**；需求 02-44 / 02-56 能力保留、表述改述为「经字典数据源出口」。

> **补强移交**：原拟在本任务补「通用数据出口基类 + 可直用 / 可继承实现类」，**已并入任务 [02_10 统一数据源注册与通用数据接口](../02_后端基座_10_统一数据源注册与通用数据接口/02_后端基座_10_统一数据源注册与通用数据接口.md) 统一处理**（不再分两块）；mdm 需求域二 `02_01` 的前置＝`02_10`。

> 详细设计见 [09_详细设计_01_字典域剔除字典类型条目](设计/09_详细设计_01_字典域剔除字典类型条目.md)（含命名收口、迁移、登记 / 出口的字段与边界、测试映射）。
