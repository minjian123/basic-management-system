## 2. 任务内容 <a id="content"></a>

**口径来源**：《数据库开发规范》§3.1.2（表单系统字段 4 项）/ §3.1.3（字典系统字段 5 项）/ §3.1.4（对齐口径）——**表单标识一律 `form_key`**；`data_source_key` **不落实体表**（归数据源注册表，`form_key → data_source_key` 多对一解析，见 `02_10`）。

1. **表文件**：全仓数据表设计文件逐表补 `form_key` 系统字段——表单表按 §3.1.2（`form_key` + `code` / `bill_date` / `status`）；字典表按 §3.1.3（`form_key` + `code` / `name` / `status` / `parent_id`）。
2. **ORM 模型**：补 `form_key` 列（`VARCHAR(64)`、唯一 `(form_key, deleted_at)`、**保存后不变**）；字典表既有系统字段对齐。
3. **迁移**：各表加 `form_key` 列 + 复合唯一约束 `(form_key, deleted_at)`（软删除后释放唯一键）。
4. **规范对齐**：表文件 ↔ 模型 ↔ 迁移**零漂移**；§3.1.2 / §3.1.3 / §3.1.4 与实表一致；`data_source_key` **不进实体表**。
5. **跨仓协同**：产品仓（biz / mdm）表文件同步——各仓独立提交（另见产品仓任务）。

> 详细设计（逐表字段清单、迁移顺序、唯一约束与方言差异）随后续开发窗口另出——本任务**仅立项**。

> **协同补记（2026-10-22）**：产品侧 `form_key` 登记缺「应用装配注入入口」——本任务补全 `BaseServiceApplicationFactory.form_records()` 钩子 + 应用级清单视图（`app.state.form_registry`），`GET /api/v1/form-keys` 改读该视图；mdm 组织域 `01_02/_04`（`org_dept` / `org_post`）为该通道首个消费方。改动与验证见[实施记录 §8](实施/11_实施_01_系统字段form_key落表.md#form-hook)。
