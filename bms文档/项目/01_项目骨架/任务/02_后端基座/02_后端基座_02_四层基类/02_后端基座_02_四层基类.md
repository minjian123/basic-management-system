## 3. 任务内容 <a id="content"></a>

1. 四层基类落地：`BaseRepository[T]`（模板方法 `_build` / `_apply` + `exists` / `count` 派生）、`BaseService[T]`（委派仓储 + 不存在语义）、`BaseSchema`（Pydantic 公共配置）、`BaseModel`（雪花 ID / 软删除 / 审计字段 / 乐观锁 / 四库类型映射）——模块类只写差异部分
2. **承上启下的业务对接层占位**：与业务具体对接的最下层基类（数据访问引擎 / 会话 / 方言 / 读写路由、三库声明、平台库表、租户上下文与解析、引擎注册表、批量迁移与初始化入口、模块注册与查询）在本阶段**只落接口与抽象声明 + 占位实现**（返回固定 / 批量数据），不连真库、不跑迁移、不建表
3. 占位口径收口：占位实现须可被上层 dependency 正常解析、应用可启动；每个占位点标注「后续阶段填实现」的 TODO 与对应需求编号

## 4. 完成标准 <a id="accept"></a>

四层基类可继承且行为正确（数据库实现为占位、内存基线保留）；业务对接层接口 / 抽象声明齐备、依赖注入可解析、应用可启动不报错、占位返回固定 / 批量数据可支撑上层链路；`pytest`、`ruff`、`pyright` 全绿（逐项验收见子任务清单）。
