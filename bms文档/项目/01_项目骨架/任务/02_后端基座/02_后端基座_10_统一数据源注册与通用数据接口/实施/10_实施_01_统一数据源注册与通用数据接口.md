## 2. 实施过程 <a id="process"></a>

1. **泛化层新建** `bms_core/datasource/`：
   - `registry.py`：`DataSourceKind`（`dict` / `form`）/ `DataSourceOrigin` / `DataSourceStrategy` / `DataSourceStatus` / `DataSourceRecord` / `DATA_SOURCE_CATALOG`（**覆盖 bms 侧 12 张字典表 + `org_dept` / `org_post` 跨项目示例**）/ `merge_data_source_records` / `DataSourceRegistry`（含 `kind` 校验）。
   - `base.py`：通用条目 `DataSourceItem`（含 `extra` 动态列）+ 通用数据接口三层 `BaseGenericDataSource`（**框架对象**：抽象 `data_source` / 抽象 `load` / 缺省 `version`（0）/ 缺省 `batch`（逐键合并）/ `cache_domain`）← `BaseFormDataSource`（抽象 `form_key`）/ `BaseDictDataSource`（`DICT_FIELDS`）。
   - 原 `bms_core/dict/registry.py` **删除**（内容迁入并泛化）。
2. **字典层改指**：`dict/base.py`（`BaseDictSource → BaseDataSource`、`data_source_key`、`get_data_source`）、`dict/outlet.py`（提供者层迁出；`DataSourceOutlet` / `RoutedDataSource` / `EmptyDictDataSource` / `register_data_source` / `build_data_source_outlet`；**出口做 `DataSourceItem → DictItem` 映射**）、`dict/cache.py` / `http.py`（`HttpDataSource`）/ `null.py` / `providers.py` / `query.py`（字段与参数改名）。
3. **字典可直用 / 可继承实现类**：新增 `dict/table.py::DictTableDataSource`（+ `DictColumnMapping`）——读标准字典系统字段（启用 + 未软删、按 `sort` / `id` 排序、缺列回退），`mapping()` / `row_to_item()` 可继承覆写；mdm `02_01` 前置。
4. **`form_key → data_source_key` 回填**：`registry/forms.py` 的 `FORM_CATALOG` 逐条回填（默认 1:1 同名）+ `FormRegistry.validate()` 增「非空 + 格式」断言。
5. **列改名与迁移**：`sys_data_scope` / `sys_query_scheme` 的 ORM 列与唯一约束列改 `data_source_key`（`sys_data_scope` 约束更名 `uq_sys_data_scope_role_data_source_policy_deleted_at`）；新增 `platform:tenant/0016_data_source_key`（纯改名，`batch_alter_table` 四库兼容）。
6. **端点与清单**：新增 `api/data_source.py`（`GET /api/v1/data-sources`，可按 `kind` 过滤、非法类型 `ParamError`）；`api/dict.py` 移除 `GET /dicts` 清单端点；`api/router.py` 登记新路由。
7. **插件键与装配**：插件键 `dict_source → data_source`（`PluginWiring` / `register_plugin` / `settings.data_source` / `config.dev.toml [data_source]`）；`assembly.py` 工厂 `RoutedDataSourceFactory` / `HttpDataSourceFactory`；`api/deps.py get_data_source`；平台 `sources/dict_source.py::PlatformDictDataSource`（继承 `BaseDictDataSource`，本期仅 `role` 示例）。
8. **契约与前端类型**：`ops.contract_snapshot export` + `contract_gate baseline-update --service platform`；`pnpm run api_types:gen` 重生成 `@bms/api_types`（决策 6 调整，保 `preflight --fast` 契约零漂移）。
9. **基座校验扩展**：`scripts/tools/base_check/check_system_fields.py` 增 `diff_data_source_closure`（`form_key → data_source_key` 闭合）+ 自检反例（合计 8 例）。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | **提供者层与插件端口同键冲突**：`BaseGenericDataSource` 初始声明 `plugin_key = "data_source"`，与出口契约 `BaseDataSource` 同键 → `test_plugin_registration` 的「一端口一键 + null 实现须端口子类」断言失败 | 提供者层改为**框架对象**（`BaseFrameworkObject`），经出口的提供者注册表注入、**不占插件端口键**（新增决策 14，已回写设计 §5.2 / §12） |
| 2 | **`FormRegistry.validate()` 成员校验对注入记录误报**：产品侧注入的 `FormRecord` 其 `data_source_key` 不在 bms `DATA_SOURCE_CATALOG` 内 | 成员校验（闭合）改由 `check_system_fields.py` 对 bms 侧两张**构建期清单**断言；`FormRegistry.validate()` 只校验非空 + 格式（已回写设计 §7） |
| 3 | **SQLAlchemy 列真值判断**：`columns.get(x) or fallback` 抛 `Boolean value of this clause is not defined` | 改为显式 `is None` 判断（`dict/table.py`） |
| 4 | **迁移 batch 同批改名 + 约束导致约束丢失**：`alter_column` 与 `drop_constraint` / `create_unique_constraint` 同批执行，SQLite 重建表后唯一约束未落地（`test_alembic_drift` 报 `add_constraint`） | 拆为**独立 batch 上下文**（先改名、再改约束），与 `0015` 同法 |
| 5 | **`executemany` 键集不一致**：测试插入字典表行时部分行省略 `deleted_at`，SQLAlchemy 按首行键集编译 INSERT → 软删行未生效 | 用例内所有行显式给全键（`deleted_at: None`） |
| 6 | **`sources/dict_source.py` 模块导入被批量改名误伤**（`bms_platform.sources.data_source` 实际不存在） | 保留模块名 `sources/dict_source.py`，回退导入路径 |
| 7 | **前端 `api-types` 漂移致 `preflight --fast` 不绿** | 决策 6 调整：本任务一并重生成 `@bms/api_types`（已回写设计 §2 / §3 / §12） |
