## 2. 任务内容 <a id="content"></a>

**口径来源（2026-10-11 用户拍板）**：注册的对象本质是「**数据从哪来**」（一个数据源可被**多个界面 / 表单**复用），「字典」只是其中**一类**；表单是**界面**，其背后的数据也是数据源。故把「字典数据源登记」泛化为**统一数据源注册**（按类型区分），并将数据接口抽为**三层**。

1. **统一数据源注册**：登记**数据源**（`DataSourceRegistry`），记录 `data_source_key` / 名称 / **类型**（`dict` 字典 / `form` 表单，预留其它）/ 数据出口 / 字段白名单 / 级联 / 可用策略 / 状态；构建期清单 + 各项目装载注入、运行期只读；`GET /api/v1/data-sources` 下发清单。
2. **通用数据接口三层**：`BaseGenericDataSource`（**基础通用数据接口**，针对**所有表**：取数 / 版本比对 / 缓存 / 批量等通用部分）← `BaseFormDataSource`（**表单通用数据接口**：业务表单数据，**不含字典**）/ `BaseDictDataSource`（**字典通用数据接口**）；后两者继承基础、只声明各自差异。
3. **字典通用数据接口**：`BaseDictDataSource` + **可直用 / 可继承的实现类**（读标准字典系统字段 `code` / `name` / `parent_id` / `sort` / `status` 等），各项目直接使用或继承，避免各项目重复实现取数 / 缓存 / 翻译 / 版本比对——**原登记于 `02_09` 的补强，并入本任务统一处理（不再分两块）**，亦为 mdm 需求域二 `02_01` 的前置。
4. **命名重构（含 02_09 改名）**：`DictRegistry` → `DataSourceRegistry`、`dict_key` → **`data_source_key`**、`BaseDictSource` → `BaseDataSource`、`BaseDictDataProvider` → `BaseGenericDataSource` / `BaseDictDataSource`、`RoutedDictSource` → `RoutedDataSource`；`sys_data_scope` / `sys_query_scheme` 列同步 `data_source_key`；前端 `dictKey` → `dataSourceKey`。
5. **拆分**：表文件 / 模型 / 迁移的 `form_key` 落表归 [`02_11`](../02_后端基座_11_系统字段form_key落表/02_后端基座_11_系统字段form_key落表.md)；契约与 `@bms/api_types` 归 [`02_12`](../02_后端基座_12_数据源注册与通用接口契约/02_后端基座_12_数据源注册与通用接口契约.md)；前端通用页面路由归 [`02_13`](../02_后端基座_13_前端通用页面路由/02_后端基座_13_前端通用页面路由.md)。本任务聚焦**数据源注册 + 三层通用接口 + 命名重构**。
6. **跨仓协同**：产品仓（mdm / biz / cw）按本口径对齐其业务表单表（落 `form_key`）与数据源引用（`data_source_key`），各仓独立提交。

> **前置（已交付，2026-10-11）**：任务 [`02_11`](../02_后端基座_11_系统字段form_key落表/02_后端基座_11_系统字段form_key落表.md) 已交付 `form_key` 构建期清单（`bms_core/registry/forms.py`：`FormRecord` / `FORM_CATALOG` / `FormRegistry` / `merge_form_records`）与各字典表 `form_key` 列（多表联合判别列）。本任务把 `data_source_key`（暂空）**归并回填**进该清单，`form_key → data_source_key`（多对一）为任务 `02_13` 的解析依据。
