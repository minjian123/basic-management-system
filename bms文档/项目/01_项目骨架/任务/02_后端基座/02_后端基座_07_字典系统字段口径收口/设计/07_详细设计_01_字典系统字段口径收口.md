## 1. 目的与范围 <a id="purpose"></a>

把 `02-4-27` 落地的字典实现收口到《[数据库开发规范](../../../../../../规范/数据库开发规范.md)》「系统字段（基础 / 表单 / 字典统一口径）」节（2026-10-10 定案）的字典侧口径。

- **范围内**：`sys_dict_item.parent_id` 由「引用父条目 `value`（`VARCHAR(64)`）」改为「**上级字典 ID（`BIGINT`，自引用同表 `id`）**」及其全部连带面——模型 / 迁移 / 存量回填 / 取数与写入链路 / 契约 / 服务端接口 / 前端 / 种子 / 文档。
- **范围外（只评估登记，另立任务实施）**：`sys_dict_item.type_id` → `dict_type_id`（主表 ID 命名口径）、`sys_dict_type.type` → `code`、`sys_dict_item.label` → `name`。三者属规范同节收口项，但改名牵动接口路径（`/dicts/{type}`）、契约与大量引用，单独立项更稳。
- 规范同时明确：字典条目的**业务引用值**（`value`）属**业务字段**、不计入系统字段，本任务**不动** `value`（其非空约束维持现状）。

## 2. 口径与依据 <a id="basis"></a>

- 规范侧：上级字典 ID 与明细「上级明细 ID」同口径——`BIGINT`、自引用同表 `id`、顶层 `NULL`、建索引。
- 设计侧一致：**《概要设计 · 字典管理》「核心表」节已写「`parent_id` 逻辑引用条目自身 `id`」**，即**表文件与 ORM 模型是偏离方**；本任务向设计与规范收口，需求 02-44 注块的「引用父条目 `value`」随本任务回写。
- 现状（偏离项）：`bms_core/dict/models.py::SysDictItem.parent_id`、表 `sys_dict_item.parent_id`、迁移 `0001_dict_and_query_scheme`、`DictQuery.parent_id` / `DictItem.parent_id`、`platform/api/dict.py` Query 参数与出参、前端 `DictItem.parentId` 与树构建，均为「引值」形态。
- 兼容收益：改为自引用 `id` 后，条目改 `value` 不再影响层级关系（父关系与被引值解耦），且与菜单树（`sys_menu.parent_id`）、明细层级口径一致。

## 4. 契约变更 <a id="contract"></a>

| 契约 | 现状 | 目标 |
| --- | --- | --- |
| `DictItem` | `value` / `label` / `code` / `parent_id: str \| None` / `sort` / `status` / `color` | **新增 `id`**（雪花 ID，序列化为字符串）+ `parent_id: int \| None`（父条目 `id`，顶层 `None`） |
| `DictQuery` | `parent_id: str \| None`（`""` = 顶层） | `parent_id: int \| None`（**三态**：不传 = 不按父过滤；`0` = 顶层；`> 0` = 该父条目的子集） |
| 快照结构 | 键含 `parent_id`（字符串） | 键含 `id` 与 `parent_id`（整型）；**结构版本变更 → 缓存版本 bump** |
| 服务间线参 | `parent_id` 字符串（`""` = 顶层） | `parent_id` 整型；顶层传 `0` |

- `id` 必须进契约：前端与调用方需要「父条目的 `id`」才能做级联与树构建，而现契约只下发 `value` / `code`。
- 三态口径与 `sys_menu.parent_id`「0 为根」保持一致，避免「不传」与「顶层」在 `int | None` 下不可区分。

## 5. 数据模型与迁移 <a id="migration"></a>

**迁移顺序（关键）**：先数据、后改型——存量 `parent_id` 存的是父条目 `value`（非数字），直接改列型在 MySQL 会截断 / 报错，故：

1. **数据脚本**（`ops/backfill_dict_parent_id.py`）：按 `type_id` 分组读 `(value → id)` 映射，将各条目的 `parent_id`（父 `value`）改写为父 `id` 的**数字字符串**（列型仍为 `VARCHAR(64)`）；幂等（已是数字且能命中同类型条目 id 的跳过）；分批提交；统计「改写 / 跳过 / 悬空（父 `value` 无对应条目）」三类计数并输出（悬空值需人工确认后置 `NULL`）。
2. **迁移**：`parent_id` 由 `VARCHAR(64)` 改 `BIGINT`（`nullable=True`）——只改类型（《数据库开发规范》「迁移与建表口径」节），四库兼容写法（方言差异走 Alembic 方言参数，不写方言 SQL）。
3. **索引**：`idx_dict_item_parent_sort (type_id, parent_id, sort)` 保留（列型随列变更），公共软删除索引不变。
4. **校验**：改型后逐类型校验「非空 `parent_id` 均能命中同类型条目 `id`」，抽样核对省 / 市 / 区级联。

## 6. 取数链路 <a id="read-path"></a>

- `bms_core/dict/sql.py`：级联条件由「`parent_id == value` / `is_(None)`」改为三态——不传不过滤、`0` → `parent_id.is_(None)`、`> 0` → `parent_id == id`；`_build_conditions` 的「带过滤」判定（现 `parent_id is not None`）改用「是否显式传参」表达。
- 快照：`_snapshot_payload` 增 `id` 并写整型 `parent_id`；`_parse_snapshot` 增 `id` 解析，且对 `parent_id` 做**兼容解析**（数字字符串 → `int`；非数字丢弃为 `None`），以抗升级瞬间的旧快照。
- 缓存：迁移上线步骤含**字典缓存版本 bump**（全局版本键 `INCR`），使旧结构快照整体失效；内存 L1 随进程重启自然失效。

## 7. 写入链路与种子 <a id="write-path"></a>

- `bms_core/dict/service.py`：条目创建 / 更新载荷的 `parent_id` 改整型，并保留服务层校验（父条目须存在、同类型、非自身、层级不环）。
- `bms_core/dict/seed.py`：级联示例改为**两阶段**——先插全部条目，再以「父 `value` → 父 `id`」回填 `parent_id`（`SeedItem.parent_value` 字段保留语义、落库时转 id），保证幂等（重复执行不重复插入）。
- `bms_core/dict/http.py`：服务间取数线参 `parent_id` 改整型。

## 8. 服务端接口 <a id="api"></a>

`services/platform/src/bms_platform/api/dict.py`：

- `GET /api/v1/dicts/{type}` 的 `parent_id` Query 参数由 `str` 改 `int`（`ge=0`；`0` = 顶层），描述与错误码口径同步（非法值仍按参数非法拒绝）。
- 出参 `items` 增 `id`（字符串输出，雪花 ID 超 JS 安全整数）与整型 `parent_id`；`attr_json` 仍不进普通链路。
- 高级查询与批量接口不涉及 `parent_id`，仅随契约校验（响应模型）同步。

## 9. 前端同步 <a id="frontend"></a>

- `core/src/domain/dict.ts`：`DictItem` 增 `id`（字符串）；`parentId` 语义改「父条目 id」；`normalizeDictItem` 解析 `id` 与整型 `parent_id`；`toDictTreeNodes` 由 `item.parentId === node.value` 改为 **`item.parentId === node.id`**（孤儿提升顶层与深度上限不变）；参数构造 `buildDictTypeQuery` 顶层传 `'0'`。
- `dict-select.ts` / `dict-store.ts` / `dict-source.ts` / `ui-ep/useBaseDictSelect.ts`：`setParent(parentId)` 语义改为「父条目 id」（空串 → 顶层 `'0'`），其余加载 / 探测逻辑不变。
- `core/testing/dict.ts`：契约桩补 `id`，级联用例的 `parent_id` 改为父条目 `id`；`tests/domain-dict.spec.ts`、`tests/dict-select.spec.ts` 同步。

- **需求 02-44 注块**：`parent_id` 说明由「级联父值（引用父条目 `value`）」改为「上级条目 ID（自引用 `id`）」。
- **《概要设计 · 字典管理》**：§核心表已为 id 口径，仅需在实施记录中标注「表文件 / 模型已收口至此口径」，无需改文。
- **《组件设计 · 字典字段》**：级联过滤与接口节的 `parent_id` 参数语义、响应字段清单（增 `id`）同步。
- **待办（另立任务）**：`type_id` → `dict_type_id`、`sys_dict_type.type` → `code`、`sys_dict_item.label` → `name` 三项收口（规范 §3.1.4 已登记）。
- **上线步骤**：① 回填脚本 → ② 迁移改型 → ③ 缓存版本 bump → ④ 前端发布（契约与桩同步）。

## 13. 决策记录 <a id="decisions"></a>

1. **改自引用 `id`**（2026-10-10 用户拍板）：与《概要设计 · 字典管理》口径一致、避免条目改 `value` 破坏层级；代价＝列型变更 + 存量回填 + 契约 / 前端同步。
2. **迁移先数据后改型**：规避 `VARCHAR` → `BIGINT` 在 MySQL / PostgreSQL / 达梦下对非数字值的截断与报错风险；数据脚本与结构迁移分离（《数据库开发规范》「迁移与建表口径」节）。
3. **`id` 进契约**：前端做级联与树构建必须有父条目 `id`（现契约只下发 `value` / `code`）。
4. **三态线参口径**（不传 / `0` 顶层 / `> 0`）：与 `sys_menu.parent_id`「0 为根」一致，规避 `int | None` 下「不传」与「顶层」不可区分。
5. **缓存版本 bump**：快照结构变更，不作结构版本兼容会读到旧结构；同时保留解析侧兼容兜底。
6. **`value` 不动**：规范定其为业务字段；本任务不改变其非空约束与翻译链路。
