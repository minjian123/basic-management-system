## 2. 任务内容 <a id="content"></a>

按《[数据库开发规范](../../../../../规范/数据库开发规范.md)》「系统字段（基础 / 表单 / 字典统一口径）」节（2026-10-10 定案）收口字典侧系统字段口径：

1. **上级字典 ID 改自引用 `id`**：`sys_dict_item.parent_id` 由 `VARCHAR(64)`（引用父条目 `value`）改为 `BIGINT`（自引用同表 `id`）——列型变更 + 存量数据回填（同类型内 `value` → 对应条目 `id`，应用侧幂等脚本）。
2. **契约同步**：`DictItem` 增补条目 `id`（雪花 ID，序列化为字符串）且 `parent_id` 改整型；`DictQuery.parent_id` 改整型、**顶层口径由「空串」改 `0`**（三态：不传 = 不按父过滤）；快照序列化结构变更 → 字典缓存版本 bump。
3. **取数 / 写入链路**：`bms_core/dict/sql.py`（级联过滤、快照读写与反序列化）、`service.py`（写路径载荷）、`http.py`（服务间线参）、`platform/api/dict.py`（Query 参数与出参）。
4. **种子**：`bms_core/dict/seed.py` 级联示例（省 / 市 / 区）改为先插父条目、再以父 `id` 回填 `parent_id`。
5. **前端同步**：`core/src/domain/dict.ts`（`DictItem.id`、树构建由按 `value` 比对改按 `id` 比对）、`dict-select.ts` / `dict-store.ts` / `dict-source.ts` / `ui-ep/useBaseDictSelect.ts`（`setParent` 语义改「父 id」）、测试桩与用例；契约快照与 `@bms/api-types` 重生成。
6. **文档回写**：`sys_dict_item.md`（字段 / 索引 / 说明 + 变更记录）、《概要设计 · 字典管理》「核心表」节比对、《组件设计 · 字典字段》级联与接口节、需求 02-44 的 `parent_id` 注块（现为「引用父条目 `value`」）。
7. **其余收口项仅评估登记**（实施另立任务）：`sys_dict_item.type_id` → `dict_type_id`（主表 ID 命名口径）、`sys_dict_type.type` → `code`（代码列）、`sys_dict_item.label` → `name`（名称列）。

## 3. 完成标准 <a id="accept"></a>

口径与《数据库开发规范》「系统字段」节一致：`parent_id` 为 `BIGINT` 自引用 `id`，级联过滤与字典树构建按 `id` 生效；迁移与存量回填在 SQLite 实测通过、脚本按四库兼容写法（真库执行随部署窗口）；契约与 `@bms/api-types` 同步，前端字典字段与级联路径联调通过；`pytest` / `ruff` / `pyright` 全绿、覆盖率门禁达标；表文件、需求注块与组件设计回写齐备；实施 / 测试记录落盘。
