## 3. 实施过程 <a id="process"></a>

1. **契约先行**：`DictItem` 增 `id`（`BaseSchema` 会把 `id` / `*_id` 序列化为字符串，前端与 `api-types` 均按字符串消费），`parent_id` 由字符串改整型；`DictQuery` 三态口径与 `sys_menu.parent_id`「0 为根」保持一致。
2. **取数与快照**：级联条件由「引值等值 / `is_(None)`」改三态；快照写入 `id` 并对 `parent_id` 做兼容解析（抗升级瞬间的旧结构快照）；缓存版本 bump 仍走上线步骤（`DictCacheRegion` 全局版本键 `INCR`）。
3. **迁移与回填（先数据后改型）**：先以 `ops.backfill_dict_parent_id` 把父 `value` 改写为父 `id`（列型未变，安全），再由迁移只改列类型——规避 `VARCHAR` → `BIGINT` 在 MySQL / PostgreSQL / 达梦下对非数字值的截断与报错；数据与结构分离（《数据库开发规范》「迁移与建表口径」节）。
4. **前端同步**：树构建由「按 `value` 归并」改「按条目 `id` 归并」；`parentId` 语义改父 id，`''` 表示不级联（不传 `parent_id`），`'0'` 表示顶层——避免空串进入 Query（整型参数会 422）。
5. **契约产物**：`ops.contract_snapshot export` 重导出快照，`packages/api-types/scripts/generate.mjs` 重生成前端类型。
