## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：后端基座体系（地基波）——按《[架构设计 · 后端基础类体系](../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「基座分层」组织为四个子域：**01 根基类与集合体系**（L0 根基类 + 有序 / 进程内并发 / 跨副本 Redis 集合，工程骨架已交付，本域登记）、**02 四层基类**（`BaseRepository` / `BaseService` / `BaseSchema` / `BaseModel`，含与业务对接的最下层基类：数据访问 / 三库声明 / 平台库表 / 租户上下文 / 引擎注册 / 批量迁移入口 / 模块注册与查询）、**03 core 横切基座**（异常与错误码 / 配置 / 安全 / 日志）、**04 跨阶段基座**（缓存 Region / 数据范围注入 / 分片路由 / 事件 / 任务 / 审计捕获）。
- **定位**：后端**全部模块的前置地基**——基座体系先立，后续认证 / RBAC / 通用能力等模块才有统一写法；本域不在工程骨架期完成，后续模块就会各自定义异常、会话、路由与注册，口径必然发散。
- **本阶段口径**：**基座体系架构建成**——基类分层与继承关系就位、异常体系与统一响应落地；与业务对接的最下层基类（数据访问 / 三库 / 租户 / 迁移 / 注册）只落**接口占位**（返回固定或批量数据、不连真库、不跑迁移、不建表），实现随对应后续阶段填实现；配置 / 安全 / 日志基座为**结构占位**，真实读取由「03 后端基础能力」落地。
- **依据**：[需求 02-1 ~ 02-16](../../需求/02_需求_后端基座.md#r02-1)、《[架构设计 · 后端基础类体系](../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「基座分层」节「阶段落地（地基波 + 回补）」节、《[后端开发规范](../../../../规范/后端开发规范.md)》「后端基座体系」节、《[API接口规范](../../../../规范/API接口规范.md)》、《[数据库开发规范](../../../../规范/数据库开发规范.md)》。
- **边界**：配置真实读取归「03 后端基础能力」配置管理；机制类（数据访问 / 三库拓扑 / 租户路由 / 批量迁移 / 模块注册）真实实现随首个落库模块；认证 / RBAC 等能力的**具体实现**、真实分片规则、缓存三防加固归对应后续阶段；前端组件库与业务模块不在本域。

## 3. 工时与依赖 <a id="effort"></a>

- **工时合计**：34h（1 + 17 + 8 + 8；16 条需求、15 个嵌套子任务；机制类按**接口占位**口径重估，原实现口径 63h）。
- **关键依赖**：03 子域（异常与统一响应）为 02 子域前置（异常语义先行）；02 子域内部按「基类 → 业务对接占位」自下而上；04 子域依赖 01~03 子域（登记六类基座契约）；上游依赖工程骨架（backend 工程、分层目录、core 基座首批）。
- **下游**：后续认证 / RBAC / 通用能力 / 工作流等全部后端模块，以及产品仓库后端模块（按本域基类与基座写法接入）。
- **风险**：基座与机制实现分离——占位实现须「能跑不报错且有固定 / 批量数据」，否则上层链路无法先跑通（以占位契约用例护栏）；`BaseModel` 四库类型映射与实际落库差异（随后续阶段实测）；跨阶段基座易在后续模块各自实现（以登记与回补窗口约束）。
