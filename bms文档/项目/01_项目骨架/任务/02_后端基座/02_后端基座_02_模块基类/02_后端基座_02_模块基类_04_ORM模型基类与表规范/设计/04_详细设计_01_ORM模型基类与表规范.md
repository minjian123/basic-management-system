## 1. 概述 <a id="overview"></a>

- **目标**：落地 SQLAlchemy 2.0 声明式 `Base` 与 ORM 模型基类 `BaseModel`——每表必备字段（雪花 ID / 审计 / 软删除 / 乐观锁）一次定义，审计由 ORM 事件自动填充，乐观锁用 `version_id_col`；四库类型映射与表规范写入模型注释；`BaseModel` 为 L0，横切按插层扩展。
- **范围**：`app/models/base.py`（`Base` + `BaseModel`）、`app/core/id.py`（雪花生成器）、`app/core/context.py`（当前用户上下文占位）、模型级单测。
- **不含**（归相邻任务）：软删除查询过滤与分页回填（[02-5-1](../../../02_后端基座_05_机制底座/02_后端基座_05_机制底座_01_数据访问底座/02_后端基座_05_机制底座_01_数据访问底座.md)）；四库真库建表与 Alembic 迁移（后续落库阶段）；乐观锁冲突转 `BizError` 错误码（02-3-1 + 02-5-1）；多租户强制过滤 / 数据范围注入（跨阶段插层）。
- **依据**：需求 [02-8](../../../../../需求/02_需求_后端基座.md#r02-8)、《[架构设计 · 数据架构](../../../../../../../设计/架构设计/07_架构设计_数据架构.md)》「数据规范」节、《[数据库开发规范](../../../../../../../规范/数据库开发规范.md)》第 2/3/4 节、《[命名规范](../../../../../../../规范/命名规范.md)》「数据库命名」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节。
- **L0 触及说明**：`BaseModel` 需继承 `BaseObject`，而 SQLAlchemy `DeclarativeMeta` 与 `ABC` 元类冲突；本次将 `BaseObject` **去掉 `ABC`**（规范 §3.2 本就称「普通类」），`class BaseModel(Base, BaseObject)` + `__abstract__ = True` 可行（已实测）。回写 02-01 交付记录与架构33 §4。

## 4. BaseModel 设计 <a id="base"></a>

`app/models/base.py`：

```python
class Base(DeclarativeBase):
    """SQLAlchemy 2.0 声明式基类（元数据 / 注册表）。"""


class BaseModel(Base, BaseObject):
    """ORM 模型基类（L0）：每表必备字段与约定，模块模型继承之。"""

    __abstract__ = True
    __mapper_args__ = {"version_id_col": version}   # 乐观锁自动比对 / 自增
```

| 字段 | 类型（跨库） | 说明 |
| --- | --- | --- |
| `id` | `BigInteger`（四库 BIGINT） | 主键，雪花 ID（`default=generate_id`），**禁用数据库自增列** |
| `created_at` / `updated_at` | `DateTime`（UTC） | 插入 / 更新事件自动填充；UTC 存储 |
| `created_by` / `updated_by` | `BigInteger`（可空） | 由 `app/core/context.py` 当前用户上下文填充（占位 None） |
| `deleted_at` | `DateTime`（可空） | 软删除；NULL=未删；建索引参与查询 |
| `version` | `Integer`（非空，默认 1） | 乐观锁；`version_id_col` 自动 +1，并发覆盖抛 `StaleDataError`（后续转业务错误码） |

- **审计自动填充**（ORM 事件，`propagate=True` 覆盖全部子类，业务代码禁止手动赋值）：

```python
@event.listens_for(BaseModel, "before_insert", propagate=True)
def _fill_on_insert(mapper, connection, target): ...

@event.listens_for(BaseModel, "before_update", propagate=True)
def _fill_on_update(mapper, connection, target): ...
```

- **继承链**：`XxxModel → BaseModel → (Base, BaseObject)`；`BaseModel` 抽象（`__abstract__`），不建表。

## 5. 雪花 ID 生成器设计 <a id="id"></a>

`app/core/id.py`：自实现**标准雪花**（无外部依赖，支持分布式与高并发）。

| 项 | 设计 |
| --- | --- |
| 组成 | 时间戳（相对自定义 epoch，毫秒）+ WorkerId + 自增序列 |
| 位宽 | **41 + 10 + 12 = 63 位**（正数）：约 69 年、1024 个 Worker、单 Worker 4096 ID/ms（≈ 400 万/秒） |
| 序列输出 | ID 超过 JS 安全整数 → 接口按**字符串**输出（主键 / 外键；见《数据库开发规范》「字段规范」节与《API接口规范》「统一响应」节） |
| 时钟回拨 | 小幅回拨等待追平；超阈值抛 `RuntimeError`（不生成重复 ID） |
| 接口 | `generate_id() -> int`；`configure_id_generator(worker_id: int)`；WorkerId 由环境变量 `BMS_WORKER_ID` 或配置基座注入，占位默认 0 |
| 并发 | 进程内 `threading.Lock` 保护序列自增；同毫秒序列用尽等待下一毫秒 |

- **分布式 WorkerId**：由部署唯一分配（`BMS_WORKER_ID` / 配置注入，部署保证全局唯一）；**Redis 自动注册 WorkerId 作为后续回补**（容器化动态扩容场景）。
- 规划选型 `yitter/IdGenerator` 为多语言算法参考；本任务自实现标准雪花，避免 vendor 第三方源码与 PyPI 缺包问题（如需短 ID / 漂移，后续评估）。

## 6. 软删除与乐观锁设计 <a id="soft-delete"></a>

- **软删除**：字段 `deleted_at`（NULL=未删）；删除写时间戳、恢复清 NULL；**查询默认过滤由 02-5-1 在 repository 基类统一注入**（本任务只落字段与约定）。
- **复合唯一**：模块表唯一约束统一建为 `(唯一字段, deleted_at)`（四库均允许多个 NULL 不冲突），删除释放唯一键、恢复不冲突；由模块模型 `__table_args__` 声明（约定 + 单测示例）。
- **乐观锁**：`version` + `version_id_col` 自动比对与自增；并发覆盖抛 `StaleDataError`，后续由 service/repository 转明确业务错误码（02-3-1 已建错误码段位后）。

## 7. 四库类型映射与表规范 <a id="mapping"></a>

写入 `BaseModel` 定义注释（跨方言，禁用方言专用类型）：

| 字段 | SQLite | MySQL | PostgreSQL | 达梦 DM8 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | BIGINT | BIGINT | BIGINT |
| `*_at` | DATETIME | DATETIME | TIMESTAMP | TIMESTAMP |
| `version` | INTEGER | INT | INTEGER | INT |
| 布尔（通用约定） | INTEGER 0/1 | TINYINT(1) | SMALLINT | SMALLINT |

表级规范（写入模型注释与规范，代码评审约束）：

- 表名单数 snake_case；平台域前缀 `sys_`/`wf_`/`rpt_`/`ai_`，业务模块用注册前缀 `{简称}_`。
- 索引命名 `idx_字段` / `uq_字段`；排序 / 逻辑外键 / 数据权限过滤字段必须建索引；每表索引 ≤ 5。
- 每表与字段 COMMENT（中文）必填；时间 UTC、金额 `NUMERIC(20,4)`、字符串 VARCHAR（长度显式）。
- 逻辑外键（`目标表_id`），不建物理外键；跨库查询禁止 JOIN。

## 8. 分层与扩展 <a id="layers"></a>

`BaseModel` 为 **L0**（纯公共字段与约定），不堆叠横切；后续按「插中间层」新增：

| 扩展层（跨阶段回补） | 说明 |
| --- | --- |
| `BaseTenantModel` | 多租户强制过滤（RBAC / 多租户阶段） |
| `BaseScopedModel` | 数据范围注入（RBAC 阶段） |
| ORM 审计捕获 | 字段级变更捕获（通用能力阶段，02-13 登记） |

## 9. 继承与实现约定（登记） <a id="convention"></a>

- 业务模型 `XxxModel` **必须**继承 `BaseModel`，禁止重复声明公共字段（id / 审计 / 软删除 / 乐观锁）。
- 审计字段只由 ORM 事件填充，业务代码禁止手动赋值。
- 表名 / 索引 / COMMENT / 逻辑外键遵循《数据库开发规范》《命名规范》；软删除查询过滤由 repository 基类统一。
- 登记落点：《架构设计 · 后端基础类体系》§4（`BaseModel`、`BaseObject` 去 ABC）、§7 模块约定；《后端开发规范》§3.4。
