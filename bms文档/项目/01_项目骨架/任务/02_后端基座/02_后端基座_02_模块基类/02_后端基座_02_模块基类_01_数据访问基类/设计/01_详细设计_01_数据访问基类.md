## 1. 概述 <a id="overview"></a>

- **目标**：定型 `BaseRepository[T]` 的**统一 CRUD 契约**（同步内存基线 + `exists` / `count` 派生方法），预留**数据源绑定 / 分片路由**钩子，并新增**数据库实现骨架类** `BaseDbRepository[T]`（占位、不连库）；使后续模块仓储只写差异部分。
- **范围**：仅数据访问基类——契约定型、两个可覆写钩子、DB 骨架类、继承约定登记与单测。
- **不含**（归相邻任务）：异步切换、引擎 / 会话工厂、四库方言、读写分离真实路由（[02-5-1](../../../02_后端基座_05_机制底座/02_后端基座_05_机制底座_01_数据访问底座/02_后端基座_05_机制底座_01_数据访问底座.md)）；软删除过滤 / 分页回填（02-5-1）；分片路由真实实现（跨阶段回补，02-13 登记）；多租户数据源绑定 `EngineRegistry`（02-5-2）；`BaseService` / `BaseSchema` / `BaseModel`（[02-2-2](../../02_后端基座_02_模块基类_02_服务基类/02_后端基座_02_模块基类_02_服务基类.md) ~ 02-2-4）。
- **依据**：需求 [02-5](../../../../../需求/02_需求_后端基座.md#r02-5)、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「基类清单与继承链」节「各层基类与模块约定」节《[架构设计 · 数据访问与分片](../../../../../../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[命名规范](../../../../../../../规范/命名规范.md)》「后端命名」节、01-3-1《基础类详细设计》。

## 4. BaseRepository 契约与钩子设计 <a id="base"></a>

`app/repositories/base_repository.py`：`class BaseRepository[ModelT](BaseObject, ABC)`，模板方法 + 派生方法（现状定型，不改公共流程）。

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `_build(item_id, values) -> ModelT` | 抽象方法 | 内存基线：按字段值构造实体（子类实现） |
| `_apply(item, values) -> ModelT` | 抽象方法 | 内存基线：按字段值生成更新后实体（子类实现） |
| `list() -> list[ModelT]` | 通用方法 | 按 ID 升序返回全部 |
| `get(item_id) -> ModelT \| None` | 通用方法 | 不存在返回 None（仓储层不抛业务异常） |
| `create(**values) -> ModelT` | 通用方法 | 分配自增 ID 并存储 |
| `update(item_id, **values) -> ModelT \| None` | 通用方法 | 不存在返回 None |
| `delete(item_id) -> bool` | 通用方法 | 不存在返回 False |
| `exists(item_id) -> bool` | 派生方法 | `get(...) is not None`，子类免实现 |
| `count() -> int` | 派生方法 | 记录总数，子类免实现 |

**新增可覆写钩子**（只定义「绑定点」，不含真实路由；默认值即「单源同源、不路由」）：

| 钩子 | 签名 | 默认（占位） | 覆写方 |
| --- | --- | --- | --- |
| `_resolve_binding` | `(self, *, read_only: bool) -> str` | `"default"` | 02-5-1（引擎 / 读写分离按 `read_only` 选主从）、02-5-2（多租户 `EngineRegistry`） |
| `_resolve_shard` | `(self, logical_table: str) -> str` | 原逻辑表名 | 分片路由基座（跨阶段回补，02-13 登记） |

```python
def _resolve_binding(self, *, read_only: bool) -> str:
    """数据源绑定钩子（占位：单源同源）。返回 db_key。"""
    return "default"

def _resolve_shard(self, logical_table: str) -> str:
    """分片路由钩子（占位：不路由，返回原表名）。返回物理表名。"""
    return logical_table
```

- 钩子只描述「路由前需要什么」，具体引擎 / 会话由 02-5-1 在 `db/` 层实现并经依赖注入提供；基类不 import DB 驱动、不建连接。
- `read_only` 供读写分离使用；本阶段默认同源，两值均返回 `"default"`。

## 5. BaseDbRepository 数据库实现骨架设计 <a id="db"></a>

`app/repositories/base_db_repository.py`：`class BaseDbRepository[ModelT](BaseRepository[ModelT])`——**数据库实现骨架（占位，不连库）**，冻结 DB 侧继承点，真实实现归 02-5-1。

| 方法 | 骨架行为 |
| --- | --- |
| `_build` / `_apply` | 抛 `NotImplementedError`（数据库实现不经内存构造钩子） |
| `list` / `get` / `create` / `update` / `delete` | 抛 `NotImplementedError`（由 02-5-1 覆写为会话实现） |
| `count` | 抛 `NotImplementedError`（内存 `len(_items)` 对 DB 无效，需查询实现） |
| `exists` | **不覆写**：继承 `get(...) is not None` 派生链（真实实现只需实现 `get` / `count`） |

```python
class BaseDbRepository[ModelT](BaseRepository[ModelT]):
    """数据库实现骨架（占位，不连库）：02-5-1 接引擎 / 会话后覆写。"""

    def list(self) -> list[ModelT]:
        raise NotImplementedError("数据库实现由 02-5-1 数据访问底座接入")
```

- 统一占位文案：`"数据库实现由 02-5-1 数据访问底座接入"`。
- 类为**具体类**（非 ABC）便于测试断言「调用即抛错、且不发起连接」；本阶段无模块使用它（demo 走内存 `BaseRepository`）。
- `exists` 经派生链调用 `get`，同样表现为占位抛错，验证「派生方法沿用」语义。

## 6. 继承与实现约定（规范登记） <a id="convention"></a>

- 模块仓储**必须**继承 `BaseRepository[T]`（内存基线）或 `BaseDbRepository[T]`（数据库实现），只写差异：内存基线实现 `_build` / `_apply`；数据库实现覆写 `get` / `count` 等原子方法，`exists` 沿用。
- 登记落点：《架构设计 · 后端基础类体系》§4 基类清单加 `BaseDbRepository` 一行、§7 各层基类与模块约定补其口径；《后端开发规范》§3.4 模块基类补 `BaseDbRepository`。
- 命名合规：`Base` 前缀（《命名规范》「后端命名」节）。
