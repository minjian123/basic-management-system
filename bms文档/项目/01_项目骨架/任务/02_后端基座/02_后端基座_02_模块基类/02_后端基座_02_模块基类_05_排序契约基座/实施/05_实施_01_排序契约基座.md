## 3. 实施过程 <a id="process"></a>

1. **排序契约**（新增 `app/schemas/sorting.py`）：`SortDirection`（`asc` / `desc`）、`SortSpec`（`field` + `direction`，`parse` 解析 / `allowed` 白名单过滤）、`BaseSortQuery`（`order_by` 逗号分隔 + `order` 方向数组 + `specs(whitelist)`）；口径按设计——方向缺位 / 非法回退 `desc`、空白项与重复字段忽略、`whitelist=None` 仅限内部可信调用。
2. **分页契约**（`app/schemas/pagination.py`）：`BasePageQuery` / `BaseCursorQuery` 改继承 `BaseSortQuery`（单继承）；`BasePageResponse` / `BaseCursorResponse` 不动。
3. **仓储契约**（`app/repositories/base_repository.py`）：`list` 加 `sort` 关键字参数（抽象签名扩展）；新增类属性 `sortable_fields`（默认空白名单＝不开放排序）、`_resolve_sort(query)`（类属性为默认白名单，`specs(whitelist=...)` 可覆盖）、`_apply_sort[StatementT](statement, sort)` 钩子（占位原样返回）；`list_page` / `list_cursor` 改为 `self.list(sort=self._resolve_sort(query))` 后再切片。
4. **内存基线**（`app/repositories/base_memory_repository.py`）：新增模块级 `_sort_key`（空值分桶置尾、数值 / 字符串分桶、类型混合按字符串兜底）与 `_sort_items[ItemT]`（按规格逆序逐次稳定排序，保证主次键语义）；`list(*, sort=None)` 先作用域过滤 + ID 升序取数，再按规格排序，不传 `sort` 时行为与原先一致。
5. **DB 骨架**（`app/repositories/base_db_repository.py`）：`list(*, sort=None)` 签名对齐，实现仍统一抛 `NotImplementedError`（不连库）；`_apply_sort` 沿用契约占位。
6. **服务层**（`app/services/base_service.py`）：`list(*, sort=None)` 透传仓储；`DemoService` 未声明 `sortable_fields`，接口行为不变。
7. **测试**：新增 `tests/schemas/test_sorting.py`（Kiwi 29）；`tests/repositories/test_base_repository.py` 增补内存排序（单字段 / 多键 / 空值 / 类型混合）、白名单默认与覆盖、分页承载排序、DB 占位与 `_apply_sort` 用例（Kiwi 29）；适配 `tests/schemas/test_base_schema.py` 分页默认值断言（Kiwi 13）。
8. **登记**：《架构设计 · 后端基础类体系》§4 基类清单（新增排序契约基类、更新仓储与分页契约行、继承链补排序支线）与 §8 跨阶段基座表（新增排序契约行）；《后端开发规范》§3.1 增「排序」强制口径。
9. **验证**：`uv run pytest`、`uv run ruff check .`、`uv run pyright` 全绿，覆盖率快照（详见[测试记录](../测试/05_测试_01_排序契约基座.md)）。
