## 1. 概述 <a id="overview"></a>

- **目标**：定型 `BaseService[T]` 的**统一服务契约**——通用 CRUD 委派仓储、统一**不存在语义**（`NotFoundError`），并预留**事务边界钩子** `_transaction()`，使模块服务只写业务规则。
- **范围**：仅服务基类——契约定型、不存在语义、事务边界钩子、继承约定登记与单测。
- **不含**（归相邻任务）：异步切换与会话注入（[02-5-1](../../../02_后端基座_05_机制底座/02_后端基座_05_机制底座_01_数据访问底座/02_后端基座_05_机制底座_01_数据访问底座.md) 覆写 `_transaction`）；`BizError` 异常体系与错误码（[02-3-1](../../../02_后端基座_03_core横切基座/02_后端基座_03_core横切基座_01_异常体系与统一响应/02_后端基座_03_core横切基座_01_异常体系与统一响应.md)）；`BaseRepository` / `BaseDbRepository`（[02-2-1](../../02_后端基座_02_模块基类_01_数据访问基类/02_后端基座_02_模块基类_01_数据访问基类.md)）；`BaseSchema` / `BaseModel`（02-2-3 / 02-2-4）。
- **依据**：需求 [02-6](../../../../../需求/02_需求_后端基座.md#r02-6)、《[架构设计 · 后端基础类体系](../../../../../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「基类清单与继承链」节「各层基类与模块约定」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、《[架构设计 · 数据访问与分片](../../../../../../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》「事务边界规则」节、01-3-1《基础类详细设计》。

## 4. BaseService 契约与事务钩子设计 <a id="base"></a>

`app/services/base_service.py`：`class BaseService[ModelT] (BaseObject)`，包装仓储并统一不存在语义。

| 成员 | 形态 | 说明 |
| --- | --- | --- |
| `_repository: BaseRepository[ModelT]` | 字段（构造注入） | 仓储实例 |
| `_transaction() -> AbstractContextManager[None]` | **新增钩子** | 事务边界；占位返回 `contextlib.nullcontext()`（无事务） |
| `list()` / `count()` / `exists(id)` | 只读转发 | 直接委派仓储，不存在不抛 |
| `get(id) -> ModelT` | 读 | 不存在抛 `NotFoundError` |
| `create(**values) -> ModelT` | 写（包事务） | `with self._transaction():` 内委派仓储 |
| `update(id, **values) -> ModelT` | 写（包事务） | 不存在抛 `NotFoundError` |
| `delete(id) -> None` | 写（包事务） | 不存在抛 `NotFoundError` |

**事务边界钩子**（占位、不接会话）：

```python
from contextlib import AbstractContextManager, nullcontext

def _transaction(self) -> AbstractContextManager[None]:
    """事务边界钩子（占位：无事务）。02-5-1 覆写为会话事务。"""
    return nullcontext()
```

**写操作包裹**（读不包）：

```python
def create(self, **values: object) -> ModelT:
    with self._transaction():
        return self._repository.create(**values)

def update(self, item_id: int, **values: object) -> ModelT:
    with self._transaction():
        item = self._repository.update(item_id, **values)
        if item is None:
            raise NotFoundError(f"记录不存在：{item_id}")
        return item
```

- 占位 `nullcontext` 为**无副作用**：包与不包行为一致，保证阶段一同步内存基线不受影响。
- 02-5-1 覆写 `_transaction()` 为 `with session.begin()`（会话经依赖注入），写路径事务集中一处生效，模块服务不改（架构33 §8「实现口径切换」）。

## 5. 不存在语义设计 <a id="notfound"></a>

- `get` / `update` / `delete` 在记录缺失时统一抛 `NotFoundError`；`list` / `count` / `exists` 不抛（只读查询语义）。
- `NotFoundError` 本阶段**保持占位**（`app/core/exceptions.py`）；[02-3-1](../../../02_后端基座_03_core横切基座/02_后端基座_03_core横切基座_01_异常体系与统一响应/02_后端基座_03_core横切基座_01_异常体系与统一响应.md) 建立 `BizError` 体系时改为其子类并接入统一响应与错误码（基类不重复改，测试只断言异常类型）。
- 异常信息文案统一 `记录不存在：{id}`（占位，02-3-1 接入错误码后由处理器产出统一响应）。

## 6. 继承与实现约定（规范登记） <a id="convention"></a>

- 模块服务 `XxxService` **必须**继承 `BaseService[T]`，只写业务规则：不得拼 SQL、不得跨模块直连仓储；通用 CRUD 走基类。
- 事务边界由基类 `_transaction()` 钩子统一，模块服务不得自起事务（02-5-1 落地会话后由基类覆写）。
- 登记落点：《架构设计 · 后端基础类体系》§7 各层基类与模块约定补事务边界钩子口径；《后端开发规范》§3.4 服务基类条补「事务边界由基类钩子统一」。

## 10. 边界与开放项 <a id="boundary"></a>

- **同步口径**：本任务保持同步；异步切换与会话注入归 02-5-1（覆写 `_transaction`）。
- `NotFoundError` 占位保持；`BizError` 体系、错误码、统一响应归 02-3-1。
- 写后读主库（避免读到从库旧数据）由 02-5-1 读写分离实现（`_resolve_binding` + 会话）。
- 数据范围注入（写读双向校验）跨阶段回补（02-13 登记）。
