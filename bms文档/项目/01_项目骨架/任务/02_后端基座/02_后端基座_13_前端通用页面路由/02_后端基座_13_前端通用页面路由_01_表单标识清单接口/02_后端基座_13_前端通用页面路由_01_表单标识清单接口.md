## 2. 任务内容 <a id="content"></a>

**背景**：通用页面路由（父任务 `02_13`）需按 `form_key` 解析页面并经 `form_key → data_source_key` 取数；后端 `FormRegistry`（`bms_core/registry/forms.py`，`02_11`）已承载该映射，但**无下发端点**——`GET /api/v1/data-sources` 只含数据源记录（不含 `form_key`），`GET /api/v1/forms`（`menu.py`）是权限表单维护、字段不同。本子任务补一个**只读清单端点**供前端解析。

1. **新增端点**：`GET /api/v1/form-keys`（登录即可）——下发 `form_key` 构建期清单（`form_key` / 名称 / 类型 `kind` / 物理表 `table` / `data_source_key` / 状态），列表统一 `{items:[...]}` 包装；可按 `kind`（`dict` / `form`）过滤。
2. **契约模型**：新增 `FormKeyResponse` / `FormKeyListResponse`（`bms_core/schemas/form.py`，与 `DataSourceResponse` 同构）。
3. **装配**：读 `FormRegistry`（`merge_form_records()`：构建期清单，运行期只读），在 platform 服务新路由 `api/form_key.py` 登记并挂到 `/api/v1`。
4. **契约生成物**：契约快照（`deploy/contracts/platform.json`）+ 基线 + `@bms/api-types` 重生成，零漂移。

> **不做**：不落表、不做表单维护 / 增删改（维护端点为 `menu.py` 既有权限表单接口）；产品侧 `form_key` 注入随各自仓库任务。

## 3. 完成标准 <a id="accept"></a>

- □ `GET /api/v1/form-keys` 下发（登录即可、按 `kind` 过滤、非法 `kind` 报错 10001）
- □ 响应字段与 `FormRecord` 一一对应且具名类型化（`{items}` 包装）
- □ 契约快照 / 基线 / `@bms/api-types` 重生成零漂移
- □ 后端定向用例 + 契约护栏用例通过（Kiwi 先登记取号）
- □ 门禁全绿（check-links / check-docs-scope / check-base / check-backend-base / check-service-boundaries / check-system-fields / preflight --fast）
