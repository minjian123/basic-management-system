## 2. 过程 <a id="process"></a>

1. **决策确认**：按《AI开发规范》逐项确认（question 工具）——全链改名 / 核心新增能力基类 / 后端清单端点（`GET /api/v1/form-keys`，作嵌套子任务）/ 页面解析产物 / 原型不适用 / 联动深度 / Kiwi 先登记，共 10 项。
2. **详细设计**：落 [13 详细设计](../设计/13_详细设计_01_前端通用页面路由.md) + 子任务 [02-13-1 详细设计](../02_后端基座_13_前端通用页面路由_01_表单标识清单接口/设计/13_01_详细设计_01_表单标识清单接口.md)；定稿提交（`docs(02_13)`）。
3. **Kiwi 登记**：容器内 Django shell 登记两条用例（2291 / 2292），标注「自动化」。
4. **后端配套（02-13-1）**：`bms_core/schemas/form.py`（`FormKeyResponse` / `FormKeyListResponse`）+ `api/form_key.py`（`GET /api/v1/form-keys`）+ `api/router.py` 登记；契约快照 / 基线 / `@bms/api_types` 重生成（零漂移）。
5. **前端核心**：新增 `domain/page-route.ts`（清单归一 + 声明 + 解析纯函数）、`capabilities/page-route.ts`（`BasePageRoute`）；`manifest.ts` 登记 `page-route: ['placeholder-state']`；`index.ts` 具名导出。
6. **前端改名**：`dictKey → dataSourceKey` 全链（核心 domain / capabilities + `ui-ep` 组件与工具 + 宿主 + 测试），旧标识（`dictKey` / `dictKeys` / `dict_key` / `DictKeyMeta` / `selectedDictTypeId`）全仓归零（保留字典专用域名词）。
7. **宿主接线**：`api/registry.ts`（清单拉取）+ `router/page-route.ts`（声明 + 适配器 + 统一装载 / 卸载 + `resolvePageRoute`）；`router/index.ts` 平台表单页（`/sys/roles`、`/sys/users`）移出静态路由改由声明装载；`router/dynamic.ts` 占位路由改按**路径**判重；`main.ts` 会话就绪装载清单 + 装载表单页路由、登出卸载 + 重置；`api/permissionMeta.ts` 改指 `GET /data-sources`（读 `data.items`）。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 后端已有 `GET /api/v1/forms`（权限表单维护，`FormItem` 无 `form_key`）——端点命名冲突 | 新端点取 `GET /api/v1/form-keys`（区分「表单标识清单」与「权限表单维护」）；已回写详细设计决策 1 |
| 2 | `@bms/api_types` 已有 `data_source_key`，前端仍发 `dict_key` / 调 `GET /dicts`（**失配**） | 本任务全链改名 + 改指 `/data-sources`，恢复一致 |
| 3 | 平台表单页原为静态路由，菜单占位路由按**路由名**判重（表单页路由名 ≠ 路径）→ 同路径重复注册隐患 | `installMenuRoutes` 改按**路径**判重（`hasRoutePath`）；表单页路由先于菜单路由装载 |
| 4 | 页面 `formKey` 与后端 `FORM_CATALOG` 不一致（`role_form` / `sys/users` vs `role` / `user`） | 统一为清单值（`role` / `user`），列表偏好键随之 `list.role_form → list.role`（仅本地偏好，无迁移风险） |
| 5 | `apps/desktop` 无 `typecheck` 脚本 | 以 `vue-tsc -b`（build 的检查段）替代运行类型检查 |
