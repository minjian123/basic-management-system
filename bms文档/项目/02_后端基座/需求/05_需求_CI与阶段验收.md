## 2. 需求 05-1：三库集成测试与流水线收口 <a id="r05-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：开发与单测用 SQLite，生产支持 MySQL / PostgreSQL / 达梦 DM8，方言差异只有真库集成测试能暴露；三库集成 job 已于阶段一停用（激活开关守卫），本阶段底座就位后必须真实跑通。

**内容**（《测试规范》、《开发部署规划》「开发工作流与 CI」节）：

1. `bms_test` 前缀测试库流程：建库 → Alembic 迁移 → 集成用例 → 删库清理（job 内独立、互不污染）。
2. 拓扑路由用例：租户库路由、跨租户隔离、批量迁移正确性。
3. 重验证层三库集成 job 激活：创建 `deploy/ci/verify-enabled` 开关（阶段一约定），跑通后恢复守卫口径。
4. 达梦方言口径实测（软删除复合唯一索引、迁移脚本、schema 前缀），不通过按《项目规划说明》「数据库兼容」节口径调整并修订对应需求。

**完成标准**：MySQL/PostgreSQL/达梦 DM8 三库迁移与集成用例全绿；拓扑路由与租户隔离用例通过；重验证层集成 job 激活并稳定。

**参考文档**：《测试规范》「三库测试」节、《开发部署规划》「开发工作流与 CI」节、《数据库开发规范》

## 3. 需求 05-2：M2 验收门禁核对 <a id="r05-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：里程碑必须有可复现证据留痕（命令 / 日志 / 流水线链接），否则「后端基座可用」无法对外证明，也无法判断能否进入下一阶段（阶段三 前端组件库）。

**内容**：

1. 逐项核对 M2 六项门禁（异常体系 / BaseModel 落库 / 三库拓扑 / 租户隔离与批量迁移 / 模块注册校验 / 跨阶段基座登记），每项给出核对命令与证据索引。
2. 核对结论回写本阶段需求总览「M2 验收门禁」表（达标/不达标 + 证据索引）；16 条需求状态与完成日期同步更新。
3. 文档收口：M2 阶段需求/任务/计划文档全部更新为终态（已完成 + 完成日期 + 结论记录）。

**完成标准**：门禁表六项结论全部落文档且均有证据索引；16 条需求状态与完成日期回写完毕；M2 阶段文档全部终态收口；评审结论落档。

**参考文档**：《总体项目规划》「里程碑」节 M2 行、《项目管理规范》「状态与工时」节

## 4. 需求 05-3：测试报告与 README <a id="r05-3"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：阶段末需有测试汇总与现状一致的 README，作为进度与问题的正式沟通产物；报告数据由 CI 采集，减少人工统计成本。

**内容**：

1. 阶段末测试报告（`bms文档/项目/02_后端基座/测试报告_阶段二.md`，四章节固定）：用例执行统计（pytest/Vitest/Playwright 用例数与通过率，CI 数据脚本汇总 + AI 初稿 + 人工补充结论）；缺陷统计（本阶段 GitLab Issue 列表与状态，defect-auto 标注）；覆盖率（后端行/分支覆盖 vs 门禁阈值）；风险与遗留项（跨阶段基座回补窗口逐条登记）。
2. README 更新（根 + 三工程）：快速启动命令与现状一致；目录结构同步；文档导航补阶段二链接。
3. 报告初稿由脚本采集 + AI 汇总生成，第二 AI 交叉审核后提交给人处理异常项（见《项目规划说明》「治理机制的落地方式」节）。

**完成标准**：测试报告四章节齐备且数据来自 CI 采集；README 与现状一致；遗留项（跨阶段基座回补窗口）逐条登记。

**参考文档**：《测试规范》「测试报告」节、《项目规划说明》「项目度量与报告」节
