## 1. 域说明 <a id="intro"></a>

本域对应阶段二「跨阶段基座」（WBS 06），承载**依赖后端模块能力、须跨阶段回补**的基座能力：缓存 Region 分域基座、数据范围注入基座、分片路由基座、事件发布 / 消费基座、Celery 任务基座、ORM 审计捕获基座。本阶段完成**分层设计、接口契约与任务登记**，实现随对应阶段能力就绪后回补（任务树登记在阶段二目录、计划表标回补窗口）。

**依据**：《[架构设计 · 后端基础类体系](../../../设计/架构设计/33_架构设计_后端基础类体系.md)》「阶段落地（地基波 + 回补）」节、《[架构设计 · 数据架构](../../../设计/架构设计/05_架构设计_数据架构.md)》「缓存架构」节、《[架构设计 · 数据访问与分片](../../../设计/架构设计/09_架构设计_子系统_数据访问与分片.md)》、《[架构设计 · 事件总线](../../../设计/架构设计/12_架构设计_子系统_事件总线.md)》、《[架构设计 · 任务调度](../../../设计/架构设计/13_架构设计_子系统_任务调度.md)》、《[架构设计 · 审计哈希链](../../../设计/架构设计/15_架构设计_子系统_审计哈希链.md)》。
**目标**：六类跨阶段基座有明确分层与契约，登记为可回补的任务项，不遗漏。

## 2. 需求 06-1：跨阶段基座登记与回补 <a id="r06-1"></a>

优先级：3（中）　|　状态：未开始　|　完成日期：—

**背景与动机**：缓存、数据范围、分片、事件、任务、审计六类能力都有「基座」成分（公共封装 + 模块只写差异），但它们依赖各自后端模块；若不在基座阶段把它们登记清楚，后续模块会各自实现缓存 key、数据范围注入、事件发布等，口径发散且重复。

**内容**（《架构设计 · 后端基础类体系》「阶段落地（地基波 + 回补）」节）：

1. **缓存 Region 分域基座**（回补阶段六 通用能力）：dogpile.cache Region 分域管理 + 全局版本号惰性比对；key 规范 `bms:{租户|global}:{域}:{业务键}`、全 key 带 TTL；三防（穿透空值 / 击穿互斥锁 / 雪崩随机偏移）在基座统一。
2. **数据范围注入基座**（回补阶段五 RBAC）：`BaseRepository` 的数据访问范围注入钩子（写读双向校验），规则由 RBAC 提供。
3. **分片路由基座**（回补阶段十一 分布式与监控）：`ShardingRouter` 抽象（分片键 → 物理库/表解析），MVP 落地按月分表。
4. **事件发布 / 消费基座**（回补阶段八 系统集成与消息）：统一事件发布接口（RocketMQ 事务消息）与消费基类（分区有序消费），业务模块不直接调用通知/审计。
5. **Celery 任务基座**（回补阶段六 通用能力）：任务定义入库（sys_task）+ 自研 beat 调度基类 + 执行记录（sys_task_log）。
6. **ORM 审计捕获基座**（回补阶段六 通用能力）：ORM 事件自动捕获关键表字段级变更，审计事件走分区有序消费（哈希链）。
7. 登记要求：六类基座的职责、契约与回补阶段写入《架构设计 · 后端基础类体系》与阶段二计划表；对应阶段实施时在**该阶段计划**登记窗口（同一任务文档，不重复建任务）。

**完成标准**：六类跨阶段基座的职责与契约在架构节点登记；回补阶段与窗口写入阶段二计划表；对应阶段启动时按登记实施并回写状态；无遗漏、无重复实现。
