## 1. 域说明 <a id="intro"></a>

本域对应阶段三「基础组件类」（WBS 01，组件设计 02 基础组件类 L0-L4），是全组件库的根：所有基类收敛为一套分层体系，**公共字段/方法只在对应层基类维护，任何组件与模块不得重复实现**。分层权威定义见《[前端开发规范](../../../规范/前端开发规范.md)》「前端基础类体系」节，架构定位见《[架构设计 · 前端组件体系](../../../设计/架构设计/32_架构设计_前端组件体系.md)》，节点契约见《[组件设计 · 总览](../../../设计/组件设计/01_组件设计_总览.md)》02 类。

- **L0 总基类**：`BaseFrontend` / `useFrontendBase`——一切前端基类之根（通用字段、日志/错误上报/配置读取/i18n/生命周期钩子）。
- **L1b 最基础组件基类**：`BaseComponent` / `useComponentBase`——所有 UI 组件公共（attrs 透传与根元素约定、尺寸/密度/主题令牌、i18n 与命名空间、可访问性与 expose、loading/disabled/显隐）。
- **L2 七形态基类**：`BaseInteractive` / `BaseInputControl` / `BaseDisplayControl` / `BaseContainer` / `BaseFormContainer` / `BaseMedia` / `BaseLayout`。
- **L3 受控值与字段基类**：`BaseValue` → `BaseField`（组合 `BaseFieldShell` / `BaseFieldPerm`）。
- **L4 域基类**：`BaseInput`（输入域） / `DisplayBase`（展示域）。

**依据**：《项目规划说明》「前端页面清单与菜单机制」节、《前端开发规范》「前端基础类体系（L0-L4，强制）」节、《架构设计 · 前端组件体系》「基础类分层体系」节、《组件设计》02 基础组件类各节点。
**目标**：L0-L4 按层落地于 `frontend/src/components/base/<layer>/`，继承链与依赖方向符合规范；L1a 数据/契约基类复用阶段一成果不重复建设。

## 2. 需求 01-1：基类层 L0 / L1b / L2 七形态基类 <a id="r01-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：组件库承载上百个组件与海量字段，若每个组件各写一套透传/尺寸/主题/i18n/loading 逻辑，行为会发散、改一处要改上百处。必须先把「所有基类之根」与「所有 UI 组件公共能力」以及七种形态基类立起来，后续组件才有统一的继承起点。

**内容**（《前端开发规范》「前端基础类体系」节、《组件设计》02 类 L0/L1b/L2 节点）：

1. L0 `BaseFrontend` + `useFrontendBase`：通用字段（命名空间、版本/标识）与通用方法（日志、错误上报、配置/环境读取、i18n 取词、生命周期钩子）；不含 UI 或业务语义，L0 只放「所有基类共有」的横切能力。
2. L1b `BaseComponent` + `useComponentBase`：attrs 透传（`id`/`class`/`style`/`data-*`）与根元素约定、尺寸 `size`/密度 `density`/主题令牌消费、i18n 取词与样式命名空间/前缀、可访问性（aria）与 ref/expose、通用 `loading`/`disabled`/显隐。
3. L2 七形态基类：交互 `BaseInteractive`（可点击/loading/disabled/焦点语义）、输入 `BaseInputControl`（值绑定、前后缀插槽、清空、只读）、展示 `BaseDisplayControl`（密度/令牌/空值/省略）、容器 `BaseContainer`（插槽/折叠/分栏/区域）、表单容器 `BaseFormContainer`（表单/分区/校验汇总）、媒体 `BaseMedia`（图片/音视频/文件预览）、布局 `BaseLayout`（栅格/断点、间距/对齐令牌、布局根元素与透传、显隐）。
4. 代码落地：`src/components/base/` 下按层分子目录（`L0/`、`L1b/`、`L2/`）；Vue 3 无类多继承，统一以组合式函数 + 组件包装模拟继承；依赖方向只准上层依赖下层，L0 不得依赖任何上层。

**完成标准**：L0/L1b 与七形态基类均按层落地且可被具体组件继承；受控方向为单向（下层不反向依赖具体组件）；Vitest 覆盖基类契约关键项（透传、尺寸/密度令牌、loading/disabled、七形态各自的公共语义）；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《前端开发规范》「前端基础类体系（L0-L4，强制）」节、《组件设计》02 基础组件类 L0/L1b/L2 节点（含可交互原型）、《架构设计 · 前端组件体系》「基础类分层体系」节

## 3. 需求 01-2：受控值与域基类 L3 / L4 <a id="r01-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：字段控件是组件库用量最大的一类，值语义（受控 `modelValue`、三态、格式化调度、`change` 上报）、字段语义（字段上下文、字段权限、校验触发、`fieldKey`）与字段壳（label/必填/错误/栅格跨度/只读回显）若不在基类统一，字段将各写一套校验与权限判定，权限与校验会失控。

**内容**（《前端开发规范》「前端基础类体系」节、《组件设计》02 类 L3/L4 节点）：

1. L3 `BaseValue` + `useValueBase`：输入与展示共用的值语义——值归一、格式化调度、三态、`change` 上报。
2. L3 `BaseField` + `useFieldMeta`：字段上下文（字段壳）、字段权限、校验触发、`fieldKey`；**组合** `BaseFieldShell`（label/必填/帮助/错误/栅格跨度/只读回显）与 `BaseFieldPerm`（`visible`/`editable`/`required`/脱敏，`useFieldPerm` / `v-plain`）。
3. L4 `BaseInput`（输入域，原基础输入组件基类）：受控、三态、`disabled` 合并、校验触发、字段上下文，被基础控件类继承。
4. L4 `DisplayBase`（展示域）：值格式化、空值占位、密度，展示类与字段只读回显继承。
5. 字段控件统一继承链：`具体控件 → BaseInput(L4) → BaseField(L3) → BaseValue(L3) → BaseInputControl(L2) → BaseComponent(L1b) → BaseFrontend(L0)`；只读态不做两套组件，统一以 `disabled` 或纯文本回显。

**完成标准**：L3/L4 基类可被基础控件类与字段类继承；`v-plain`/`useFieldPerm` 的 `visible`/`editable`/`required`/脱敏契约可用；字段壳装配（label/必填/错误/栅格）生效；Vitest 覆盖受控值与字段权限契约；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《前端开发规范》「前端基础类体系（L0-L4，强制）」节、《组件设计》02 基础组件类 L3/L4 节点（含可交互原型）、《组件设计 · 总览》「通用设计约定」节
