## 1. 目标与边界 <a id="scope"></a>

**目标**：把「能力 → 域」（07B）与「域 → 部署单元与库」（`02_01`）接成一条解析链路，使消费方**只写能力名**即可拿到当前租户下可用的访问目标；并定义 `colocated` / `remote` / `local` 三种模式与失败语义（协议随租户上下文升版，见 §3.1）。

**范围内**：

1. 完整解析链路与返回结构；
2. `local` / `remote` 的判定条件（实例声明自身承载单元）；
3. 租户维度对解析的影响（拓扑按租户）与**分阶段落地口径**；
4. 失败语义（启动期 / 运行期）；
5. 与 07B 协议的兼容（消费方零改动）。

**范围外**：拓扑记录本身（`02_01`）、跨单元传输实现（进程内直调 / HTTP 复用既有调用链）、网关按租户路由（`04_03`）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 第一段 | 07B `02_02`：`resolve_capability(name)` → 能力记录（含 `domain` / `path` / `kind`）+ **过渡默认** `TopologyResolver`（域 = 同名服务键，`mode` 恒 `remote`） |
| 第二段 | `02_01`：`resolve(tenant_id, domain_key)` → `unit_key` + 库键；租户无记录回退默认拓扑 |
| 实例身份 | 当前服务实例**不声明自己承载哪些单元**；所有租户共用同一组实例（一租户一库） |
| 调用传输 | 只有 HTTP（`servicecall/http.py`），无进程内直调实现 |

## 3. 一个必须先讲清的矛盾 <a id="tension"></a>

「拓扑**按租户**配置」与「一组实例服务**所有租户**」不能同时成立到最后一步：

| 若… | 则… |
| --- | --- |
| 拓扑只作用于**库**（同一实例组，租户各自用不同库） | 单实例组可行，与现状一致；但租户 A 的采购无法跑在与租户 B 不同的进程里 |
| 拓扑作用于**服务地址**（按租户路由到不同实例组） | 需要“实例组按租户划分”+ 入口按租户路由；这是目标形态 |

**因此分两阶段落地**（同一套代码，靠实例配置区分）：

| 阶段 | 实例形态 | 拓扑作用范围 | `mode` 判定 |
| --- | --- | --- | --- |
| **A 单实例组**（当前） | 一组实例承载全部域 | 仅**库**（`unit_key` 决定库键） | 全部 `colocated`（同组、**非同一进程**），仍走既有 HTTP |
| **B 多实例组**（目标） | 每个租户（或租户群）一组实例，每组声明自身承载的单元集合 | **库 + 地址** | 与本实例**同进程** → `local`（进程内直调）；同承载集合但不同进程 → `colocated`；否则 `remote` |

**结论**：本任务先落地“解析链路 + 三段模式判定 + 失败语义”。阶段 A 恒为 `colocated`（仍走既有 HTTP，现网行为不变）；`local` 的**进程内直调**只在阶段 B 成立——这样“`local` = 同进程”的不变式不被提前破坏。

## 4. 设计 <a id="design"></a>

### 4.1 链路与返回 <a id="chain"></a>

**协议升版（v2）**：解析入口改为 `resolve(domain_key, tenant_id)`。`tenant_id` **必填**（后台任务显式传 `0` 表示平台级），不得缺省——因此 07B 侧“签名不变、消费方零改动”的说法相应修订为：**调用签名增加租户参数，语义不变**。

```
消费方: resolve_capability(name, tenant_id)
  → 第一段（07B）：能力记录 {domain, kind, path, branch_op, ...}
  → 第二段（02_01）：resolve(tenant_id, domain) → {unit_key, db_keys}
  → 组装 CapabilityTarget {mode, unit_key, service_key, base_url, db_keys}
  → 最终地址 = base_url + path（path 参数由消费方按业务填充）
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `mode` | 判定（§4.2） | `colocated` / `remote` / `local` |
| `unit_key` | 第二段 | 部署单元标识 |
| `service_key` | 第二段（单元 → 服务标识） | 阶段 A 等于单元对应的实例组标识；阶段 B 为具体实例组 |
| `base_url` | 由 `service_key` 按既有模板派生 | 阶段 A 与现状一致（`http://{service}:8000`） |
| `db_keys` | 第二段 | 平台库 / 租户库键（供需要直连库的调用方使用；一般不用） |

**兼容**：07B 的 `CapabilityEndpoint` 字段不变，仅 `target` 的取值从“过渡默认”变为“真实解析”；**消费方代码不改**。

### 4.2 `local` / `remote` 判定 <a id="mode"></a>

```
mode = local      若该单元与本实例同进程（阶段 B 才可能出现）
mode = colocated  若该单元 ∈ 本实例承载集合、但不同进程（阶段 A 恒此值）
mode = remote     其余（按单元地址跨组调用）
```

| 项 | 口径 |
| --- | --- |
| 实例声明 | 服务配置新增“本实例承载的单元集合”；**未声明时**取默认拓扑的单元集合（等价阶段 A 的“全承载”） |
| 集合非空 | 空集合视为配置错误 → **启动期拒启** |
| 阶段 A 行为 | 集合 = 默认拓扑全部单元 → 恒 `local`；消费方仍走既有 HTTP（到同组服务），行为不变 |
| 阶段 B 行为 | 集合为实例实际承载的域集合对应单元；跨单元 `remote` |

### 4.3 租户维度 <a id="tenant"></a>

| 项 | 口径 |
| --- | --- |
| 解析入参 | `tenant_id` 必须显式传入（不得默认 0）；缺失即报错（防止“以为按租户、实际用默认”） |
| 缓存 | 键 = (`tenant_id`, `topology_version`, `domain_key`)；跨租户不共享 |
| 后台任务 / 无租户上下文 | 允许传 `tenant_id = 0` 显式表示“平台级”，语义为默认拓扑；不得省略 |
| 跨租户批量场景 | 逐租户解析（不复用缓存结果），避免串租户 |

### 4.4 失败语义 <a id="failure"></a>

| 情形 | 时点 | 处置 |
| --- | --- | --- |
| 能力未登记（第一段缺失） | 取用时 | 抛错并定位能力名（07B 口径） |
| 默认拓扑缺该域 | 启动期 | **拒启**（配置缺失，非业务态） |
| 租户有自身拓扑、但不含该域 | 运行期 | **不回退默认**：按“该业务域未在当前租户启用”提示（租户记录完全覆盖默认） |
| 域在本租户 `disabled` | 运行期 | 返回“该业务域未在当前租户启用”（业务提示，非异常） |
| `unit_key` 无法派生服务地址（单元未登记入口） | 启动期 | **拒启**，列出单元 |
| `remote` 但远端不可达 | 运行期 | 沿用既有服务调用韧性（超时 / 重试 / 熔断）；写路径 fail-closed |

### 4.5 与网关的关系 <a id="gateway"></a>

南北向请求按租户路由到对应实例组属**入口职责**（`04_03`）；本任务只保证“给定租户与能力，能算出去处”。两者不重复实现路由逻辑。

## 5. 影响面 <a id="impact"></a>

| 类别 | 对象 | 变更 |
| --- | --- | --- |
| 修改 | 07B `TopologyResolver` 注册 | 过渡默认实现 → `02_01` 的真实解析 |
| 修改 | `CapabilityEndpoint.target` 组装 | 增加 `db_keys` 与真实 `unit_key` / `service_key` |
| 新增 | 服务配置项“本实例承载的单元集合” | 缺省取默认拓扑；空集合拒启 |
| 新增 | 单元 → 服务标识映射 | 由拓扑记录的单元派生（或登记表），启动期校验 |
| 不改 | 消费方代码（`03_01` 收编结果） | 接口形态不变 |
| 不改 | 传输实现（阶段 A） | 仍走既有 HTTP |

## 6. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 阶段 A：单实例组 | 全部解析为 `colocated`；地址与改造前一致 |
| 2 | 阶段 B：跨单元 | 非本实例单元解析为 `remote`，`service_key` 为对应实例组 |
| 3 | 实例未声明承载集合 | 取默认拓扑全部单元（不报错） |
| 4 | 承载集合为空 | 启动期拒启 |
| 5 | 未传 `tenant_id` | 立即报错（不默认 0） |
| 6 | `tenant_id = 0` 显式 | 按默认拓扑解析 |
| 7 | 租户拓扑缺域、默认有 | 不回退默认，返回“未启用该业务域”（不得串用默认拓扑） |
| 8 | 默认拓扑缺域 | 启动期拒启并列出域 |
| 9 | 域 `disabled` | 返回“未启用”提示，非异常 |
| 10 | 单元无入口映射 | 启动期拒启并列出单元 |
| 11 | `remote` 不可达 | 沿用既有韧性；写路径 fail-closed |
| 12 | 缓存键含版本 | 拓扑换版本后解析即为新结果 |
| 15 | 协议租户上下文 | 协议声明的 `tenant_id` 缺失即报错；显式传 `0` 表示平台级 |
| 13 | 跨租户不串 | 两个租户不同拓扑各自正确 |
| 14 | 消费方零改动回归 | 07B `02_02` 用例全绿 |

## 7. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| “按租户拓扑”被误解为当前就按租户分实例 | 设计明示两阶段；阶段 A 拓扑只作用于库，地址不变 |
| 解析入参 `tenant_id` 到处补，易漏 | 缺失即报错（不默认 0）；关键路径设显式断言 |
| 阶段 B 切换时地址突变 | 由 `service_key` 派生（阶段 A 已存在同名服务标识），切换即换映射，地址形态不变 |
| 单元 → 服务映射成为第二份事实源 | 映射由拓扑记录派生或登记表维护，启动期与拓扑校验一致 |
| 缓存跨租户串用 | 缓存键含 `tenant_id`，且用例覆盖 |

## 8. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 阶段 B 的“实例组”粒度（按租户 / 按租户群 / 按域） | 多实例部署需求出现时定 |
| 2 | `local` 的进程内传输实现（直调 vs 仍走本地 HTTP） | 阶段 B 初期可先用本地 HTTP，直调作为性能优化 |
| 3 | 承载单元集合是否支持热更新（不重启） | 部署形态稳定后评估 |
| 4 | 无租户上下文的后台任务如何取拓扑（默认拓扑是否足够） | 首个此类任务出现时定 |
