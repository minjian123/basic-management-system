## 1. 目标与边界 <a id="scope"></a>

**目标**：把「能力 → 业务域」（07B）与「业务域 → 部署单元与库」（`02_01`）接成一条解析链路，使消费方**只写能力名**即可拿到当前租户下实际可用的访问位置；并补上 `02_01` 留下的两个口子——**拓扑快照跨进程分发**与 **`local` / `colocated` / `remote` 判定**，同时让第二段解析出的地址真正进入调用链。

**范围内**：

1. 完整解析链路与返回结构（协议沿用 07B 签名，不升版）；
2. `local` / `colocated` / `remote` 的判定判据与「本实例承载单元集合」配置；
3. 拓扑快照跨进程分发（平台内部出口 + 各服务启动拉取）；
4. 第二段地址生效（`target.base_url` 进调用链）；
5. 失败语义（启动期 / 运行期 / 分发失败降级）；
6. 与 07B 协议的兼容（消费方零改动）。

**范围外**：拓扑记录本身与快照装载（`02_01`）、进程内直调传输实现（开放项 1）、网关按租户路由（`04_03`）、按拓扑生成部署编排（`04_01`）、拓扑迁移（`04_02`）、实例组粒度（阶段 B 多实例形态，开放项 2）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 第一段 | 07B `02_02`：`resolve_capability(name)` → 能力记录（含 `domain` / `path` / `kind`）→ 交给第二段解析 `domain` |
| 第二段 | `02_01`：`resolve_for(tenant_id, domain)` → `CapabilityTarget{unit_key, service_key, base_url, db_keys}`；`mode` **恒 `remote`** |
| 协议签名 | `TopologyResolver.resolve(domain)`（租户取 `current_tenant_id` 上下文，缺失按默认拓扑）；`02_01` 拍板「签名不变」，消费方零改动 |
| 快照归属 | 拓扑快照与解析器是 `bms_core/collaboration/topology.py` 的**进程级全局态**，只有 platform 进程装载；其它服务沿用 07B 过渡实现 `DomainLayoutTopologyResolver`（`unit_key` = 业务域、`mode` 恒 `remote`、`db_keys` 空） |
| 地址来源 | 消费方经 `build_capability_request` → `ServiceRequest{service: service_key}` → `build_service_url` 按 `http://{service}:8000` 拼；**`target.base_url` 未进调用链**（装饰字段） |
| 消费点 | 平台调产品能力（`mdm.org.*` / `mdm.role.*`）全部是**跨服务**调用；同服务内跨业务域协作经域 `public.py` 出口（`03_03`，D1 强制），不经能力寻址 |

## 3. 四项拍板（2026-10-29，决定实现形态） <a id="decisions"></a>

| # | 事项 | 结论 | 缘由 |
| --- | --- | --- | --- |
| 1 | 拓扑快照跨进程分发 | **平台内部出口 + 装配层统一拉取**：新增 `GET /api/v1/platform/internal/tenant-topologies`（服务身份可读全量快照）；基座在应用装配期拉取并登记快照与解析器，platform 进程跳过（本库即权威） | 与 07B 授权视图（`internal_capability_grants` + 启动拉取 + 降级标记）同构，不引入第二套机制、不跨库读表（表归属 `platform`，跨域读被 D1/D3 拦）；改动集中在基座一处，bms 九服务与 mdm 自动生效 |
| 2 | `local` / `colocated` 判定 | **按承载集合判三态**：该域负载服务 == 本服务 → `local`；否则该单元 ∈ 本实例声明集合（缺省 = 默认拓扑全部单元）→ `colocated`；否则 `remote` | 阶段 A（单实例组）得「自域 `local` + 他域 `colocated`」、不出现 `remote`，与真实部署形态一致；`local` 判据落在「承载服务」而非「单元」，因为单元可含多域、多域可跨服务 |
| 3 | `mode=local` 的调用路径 | **本轮不实现直调，只给语义**：`local` 表示「本进程承载、不该走网络」；今天不存在走能力寻址的本地消费点（同服务跨域走 `public.py`） | 直调传输（本地 ASGI / 进程内函数）依赖阶段 B 的实例组形态，提前做只有开销没有消费方；写明口径避免「标了 local 却走 HTTP」的隐式违约 |
| 4 | 第二段地址生效 | **`target.base_url` 覆盖**：`ServiceRequest` 增可选 `base_url`，`build_capability_request` 用解析结果填入；缺省仍按服务键模板 | 否则第二段算出的地址进不了调用链，拆分拓扑下取址不变，「两套拓扑取址不同」这条验收无从验证 |

## 4. 设计 <a id="design"></a>

### 4.1 解析链路与返回 <a id="chain"></a>

协议**不升版**：`TopologyResolver.resolve(domain)` 签名不变，租户取 `current_tenant_id`（缺失 / 非请求态按 `tenant_id = 0` 默认拓扑）；需要显式租户的场合（部署编排 / 运维 / 测试）用 `resolve_for(tenant_id, domain)`。`02_01` 已按此交付，本任务只补判定与地址，不改签名。

```
消费方: resolve_capability(name)                        # 07B 单点入口，签名不变
  → 第一段（07B）：能力记录 {domain, kind, path, branch_op, ...}
  → 第二段（02_01 + 本任务）：resolve_for(tenant_id, domain)
      → {unit_key, service_key, base_url, db_keys, mode}
  → 组装 CapabilityEndpoint（字段不变）
  → 调用地址 = target.base_url（缺省回落服务键模板）+ path
```

| 字段 | 来源 | 本任务变更 |
| --- | --- | --- |
| `mode` | 本任务判定（§4.2） | 由恒 `remote` → `local` / `colocated` / `remote` 三态 |
| `unit_key` | 第二段 | 不变 |
| `service_key` | 第二段（域 → 承载服务） | 不变（身份 / 限流 / 熔断依赖名仍按它） |
| `base_url` | 第二段（按 `unit_key` 与基址模板派生） | **进调用链**（§4.3） |
| `db_keys` | 第二段 | 不变：只含平台库键 `platform_{unit}`，租户库键由调用方按自身 `db_basis` 派生 |

**兼容**：`CapabilityEndpoint` / `CapabilityTarget` 字段集不变，`resolve_capability` 签名不变——消费方代码零改动（07B 用例原样回归）。

### 4.2 模式判定 <a id="mode"></a>

```
carrier = 该域的承载服务键（service_key_for_domain(domain)）
units   = 本实例承载单元集合（配置 topology.units；未配置 = 默认拓扑全部单元）

carrier == 本服务键            → local       # 同进程承载，不该走网络
unit_key ∈ units               → colocated   # 同一实例组内、不同进程
否则                            → remote      # 跨实例组，按单元地址调用
```

| 项 | 口径 |
| --- | --- |
| 本服务键 | `[app].service`（装配期已解析）；**为空**时不产生 `local`（无从判断同进程，保守退化为 `colocated` / `remote`） |
| 承载单元集合 | 新增 `[topology].units`（字符串数组）。**未配置（`None`）= 默认拓扑（`tenant_id=0`）快照的全部单元**；显式 `[]` = 本实例不承载任何单元 → 全 `remote` |
| 单元合法性 | 集合内每个单元必须出现在默认拓扑快照中；未登记单元属配置漂移 → **启动期拒启**并列出单元（与「单元无入口映射拒启」同口径） |
| 默认拓扑缺失 | 快照未装载时不做 `colocated` 判定（`units` 视为空），全部 `remote`——与 07B 过渡实现行为等价，不会误报同组 |
| 阶段 A 结果 | 单实例组：默认拓扑单元 = 各组域承载服务键，集合缺省为全单元 → 自域 `local`、他域 `colocated`，**不出现 `remote`** |
| 阶段 B 结果 | 每实例声明自身承载单元 → 跨组解析为 `remote`，`base_url` 随单元走 |

**为什么 `local` 判据落在承载服务而不是单元**：单元可由多域组成（`grp-purchase`），这些域的承载服务可能分属不同进程；「同进程」只能由「该域由本服务执行」判定，单元只决定「是否同组」。

### 4.3 地址生效 <a id="address"></a>

| 环节 | 变更 |
| --- | --- |
| `ServiceRequest` | 增可选 `base_url`（`str \| None`）：显式基址，缺省 `None` 表示按 `service` + 基址模板派生 |
| `validate_service_request` | 显式 `base_url` 须以 `http://` / `https://` 开头，否则 `ParamError`（10001，不发起调用） |
| `build_service_url` | 显式 `base_url` 优先（去掉尾部 `/`），否则沿用「已登记端点覆盖 → 模板派生」两段 |
| `build_capability_request` | 用 `endpoint.target.base_url` 填 `base_url` |

**等价性**：阶段 A 默认拓扑的单元 = 该域承载服务键，`base_url` 与按服务键派生**同值**——改造前后地址零变化（回归用例按字符串比对）。拆分拓扑下单元与承载服务分离，地址随单元走，两套夹具才能验出差异。

**不改的**：`service` 字段仍为承载服务键——出站服务 JWT 的 `sub`、限流维度、熔断依赖名（`service:<key>`）、服务目录校验都按它取，不因地址变化而变。

### 4.4 跨进程分发 <a id="distribute"></a>

```
platform 启动：自举默认拓扑 → 装载快照 → 登记解析器（02_01，已有）
其它进程启动：装配期拉取全量快照 → 逐租户登记 → 登记解析器（本任务）
```

**平台内部出口** `GET /api/v1/platform/internal/tenant-topologies`：

| 项 | 口径 |
| --- | --- |
| 鉴权 | 双模 `require_auth_or_service`：**服务身份可读全量**（拓扑是不含租户业务数据的全局配置，所有服务都需要它）；登录态需 `tenant-topology:query` |
| 响应 | `{default_version, snapshots: [{tenant_id, version, rows: [{domain_key, unit_key, status}]}]}` |
| 暴露面 | 只回解析必需四列；`note` / 审计 / 操作人等运营字段留在管理面（`/api/v1/tenant-topologies`） |
| 空快照 | 平台尚未自举时返回空 `snapshots`（调用方按「未装载」处理，不拒启） |

**基座引导** `bootstrap_remote_topologies(app)`（`bms_core/collaboration/bootstrap.py`，与 `bootstrap_remote_capability_grants` 同文件同风格）：

| 步 | 动作 | 失败 |
| --- | --- | --- |
| 1 开关 | `[topology].distribute = false` 时记 INFO 跳过（测试环境关） | — |
| 2 跳过平台 | 本服务键 == 平台服务键 → 直接返回（本库即权威，`02_01` 已在本进程装载） | — |
| 3 装配校验 | `app.state.service_client` 缺失 → `CatalogError` **拒启**（配置漂移，不给隐式降级） | 拒启 |
| 4 拉取 | 经内部出口取全量快照 | 不可达 → `WARNING` + `app.state.topology_degraded = True`，**保留过渡实现**、不拒启 |
| 5 装载 | 逐租户 `register_topology_snapshot` → `register_topology_resolver(TenantTopologyResolver())` | — |
| 6 校验 | `[topology].units` 内单元须在默认快照中出现 | 违反 → `CatalogError` **拒启** |
| 7 释放 | 登记 `TopologyResolverResource`（随应用关闭复位解析器与快照） | — |

**为什么降级而不拒启**（与 07B 授权视图同口径）：产品进程的管面与登录出口不依赖拓扑；平台重启窗口内把产品整体拖下水属过度耦合。「未装载」由 `app.state.topology_degraded` 与启动 `WARNING` 可观测，此时行为等同改造前（过渡实现，不会错址）。**但**装配缺失（无服务间客户端）属配置漂移，仍拒启。

**装配点**：`bms_core/application.py` 的 `service_lifespan`，紧随 `bootstrap_declarations(app)`（声明装载完成后才有域登记视图与承载服务映射），早于接库服务目录校验。

**刷新口径**：拓扑变更 = 一次发布动作 → 发布即重启进程 = 重新拉取，**不做运行期轮询**（与 07B「拓扑变更走发布」一致）；迁移期需要不中断刷新时随 `04_02` 评估（开放项 3）。

### 4.5 失败语义 <a id="failure"></a>

| 情形 | 时点 | 处置 |
| --- | --- | --- |
| 能力未登记 / 已禁用（第一段） | 取用时 | `ParamError`（10001），消息含能力名（07B 口径不变） |
| 拓扑未装载（`02_01` 未装配或分发降级） | 取用时 | `CatalogError`，`data.reason=not_loaded` |
| 该租户与默认拓扑都没有此域 | 运行期 | `CatalogError`，`not_registered`（不回退默认服务） |
| 域在本租户 `disabled` | 运行期 | `CatalogError`，`not_enabled`（业务态，非配置缺失） |
| `[topology].units` 含未登记单元 | 启动期 | `CatalogError` **拒启**，列出单元 |
| 分发拉取失败 | 启动期 | `WARNING` + `topology_degraded`，保留过渡实现 |
| 装配缺服务间客户端 | 启动期 | `CatalogError` **拒启** |
| `remote` 但远端不可达 | 运行期 | 沿用既有服务调用韧性（超时 / 重试 / 熔断）；写路径 fail-closed |
| 显式 `base_url` 非 http(s) | 取用时 | `ParamError`（10001），不发起调用 |

### 4.6 与网关、发布的关系 <a id="gateway"></a>

南北向请求按租户路由到对应实例组属**入口职责**（`04_03`）；按拓扑生成编排属**发布职责**（`04_01`）。本任务只保证「给定能力与当前租户，能算出单元、地址与模式」，不重复实现路由与编排。

- **Kiwi**：先登记取得编号再编码（编号回填本节与代码 `@pytest.mark.kiwi_id`）；
- **覆盖率**：行 + 分支 100%（口径见《AI开发规范》「覆盖率要求」节）。

## 7. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 装配层统一拉取放大影响面（所有服务启动多一次调用） | 开关 `[topology].distribute` 单测关闭；失败降级不拒启；只拉一次、无轮询 |
| 「标了 `local` 却走 HTTP」形成隐式违约 | `local` 只对本进程承载域成立，而该场景不产生寻址调用（同服务跨域走 `public.py`）；进程内直调登记开放项 1，实现前不引入消费方 |
| 承载集合配置与真实部署不一致 | 集合内单元须在默认拓扑登记（启动期拒启）；集合缺省取默认拓扑全单元，不配置即等价现状 |
| `base_url` 覆盖被滥用（消费方传任意地址） | 只能由 `build_capability_request` 从解析结果填入；`validate_service_request` 校验协议前缀；消费方自拼地址仍由 `04_01` 字面量护栏拦 |
| 内部出口成为第二份事实源 | 端点只读 `02_01` 的 `snapshot()`，不落库、不缓存第二份；写入口仍唯一（管理面 `PUT`） |
| 快照随租户规模增长 | 只下发「已配置自身拓扑的租户 + 默认拓扑」；容量上限沿用 `TOPOLOGY_SNAPSHOT_LIMIT` 淘汰 |
