## 1. 目标与边界 <a id="scope"></a>

**目标**：让「某租户的某业务域由哪个部署单元承载」成为**可登记的运营数据**，并提供运行期解析（域 → 部署单元与库），供能力寻址、部署编排与运维排查共用同一份事实。

**范围内**：

1. 拓扑记录的存储（`sys_tenant_topology`，表结构见数据库设计表文件）；
2. 写入与生效语义（整批替换、版本递增、审计、模板应用）；
3. 解析接口与缓存（按租户取当前版本、默认拓扑回退、失败语义）；
4. 校验（域已登记、单元命名、同域双映射、空单元、未知模板）；
5. 对外出口（能力寻址第二段、部署编排、运维查询）。

**范围外**：能力 → 域的第一段解析（07B `02_02`）、**拓扑快照向其它服务进程的分发与 `local` / `colocated` 判定**（本专项 `02_02`）、库与迁移改造（`03_02`）、拓扑变更的操作流程（`04_02`）。

**三处拍板（2026-10-29，影响实现形态）**：

| # | 事项 | 结论 | 缘由 |
| --- | --- | --- | --- |
| 1 | 租户如何进入解析 | 实现 `TopologyResolver` 时读 `current_tenant_id` 上下文变量，**协议签名不变**；另提供显式 `resolve_for(tenant_id, domain)` 供部署编排 / 运维 | 07B 已定「消费方代码零改动」；上下文缺失（非请求态）时按默认拓扑解析 |
| 2 | `CapabilityTarget.db_keys` 内容 | **只给平台库键** `platform_{unit}`；租户库键由调用方用**自身已持有的** `db_basis` 派生 `tenant_{unit}_{db_basis}` | 派生租户库名需 `db_basis`（`sys_tenant_database` 属 `tenant` 域），跨域读被 D1/D3 拦截；拓扑表加该列会成为第二份事实源 |
| 3 | 默认拓扑（`tenant_id=0`）由谁产生 | **启动钩子幂等自举**为「域 → 该域承载服务键」（与 07B 过渡实现行为等价、库名零变化），并配 `ops` 命令供 CI / 集成档显式执行 | 需求要求「拓扑缺失即拒启」，而库中原本没有这份数据；按 `single` 模板自举会把库名改成 `{prefix}_core`，与现状库冲突 |

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 拓扑记录 | **不存在**——「哪个租户跑在哪些单元与库上」只存在于部署配置与人的记忆里 |
| 库名派生 | 已参数化：`{prefix}_{service}` / `{prefix}_{service}_{db_basis}`，`prefix == service` 时去重（把 `service` 段换成 `unit` 即可复用） |
| 能力解析 | 07B `02_02` 定义了 `TopologyResolver` 协议与**过渡默认实现**（业务域 = 同名服务键），等待本任务提供真实实现 |
| 失败语义 | 07B 已定：第一段缺失即拒启；本任务需补第二段缺失的语义 |

## 3. 设计 <a id="design"></a>

### 3.1 表与记录 <a id="record"></a>

记录 = 一行「租户 × 业务域 → 部署单元」，表结构以《[sys_tenant_topology](../../../../../../设计/数据库设计/数据表设计/sys_tenant_topology.md)》为唯一事实源。关键列：`tenant_id`（`0` = 默认拓扑）/ `domain_key` / `unit_key` / `topology_version` / `status`。

**为什么不存库名**：库由部署单元派生（`{prefix}_{unit}` / `{prefix}_{unit}_{db_basis}`），存库名会让本表变成第二份事实源——改前缀或改派生规则时两处打架。

### 3.2 写入与生效 <a id="write"></a>

| 项 | 口径 |
| --- | --- |
| 写入单位 | **整批替换**：一次发布内，某租户的全部行在同一事务内写入，旧行软删除 |
| 版本 | 同一批次所有行写同一个 `topology_version`（旧版本 + 1），解析取**最大版本**的未删除行 |
| 生效 | 发布动作完成即生效；运行期解析读缓存，缓存键含版本号，故新版本自然可见（无需主动广播） |
| 模板 | 从参照模板（单体 / 分组 / 独立）展开为行集合，再整批写入；模板本身是平台常量，不落库 |
| 审计 | 整批替换记一条审计（租户、版本、域数、单元数、来源模板），单行变更不逐条记 |

**为什么整批替换而不是逐行改**：逐行改会产生“一半新一半旧”的中间态；整批 + 版本号保证解析永远看到完整拓扑。

### 3.3 解析 <a id="resolve"></a>

两个入口，语义一致、租户来源不同：

```python
resolve(domain) -> CapabilityTarget                     # 协议实现：租户取 current_tenant_id（缺失按默认拓扑）
resolve_for(tenant_id, domain) -> CapabilityTarget      # 显式租户（部署编排 / 运维 / 测试）
```

| 步骤 | 规则 |
| --- | --- |
| 1 定租户 | 协议入口取 `current_tenant_id`；为空（非请求态 / 启动期）按 `tenant_id = 0` 的默认拓扑 |
| 2 取版本 | 快照按 `(tenant_id, topology_version)` 组织；租户无快照则回退默认拓扑的快照（**整体覆盖，不逐域合并**） |
| 3 命中域 | 该版本行集合中找 `domain_key`；`status=disabled` 视为**该域在本租户未启用** |
| 4 派生目标 | `unit_key` 取自记录；`service_key` = 该域的承载服务键（`service_key_for_domain`）；`base_url` 由 `unit_key` 按服务间调用模板派生；`db_keys = [platform_{unit}]`；`mode` 恒 `remote`（`local` / `colocated` 判定归 `02_02`） |
| 5 失败 | 见下表，统一抛 `CatalogError`（`40003`），`data.reason` 区分三类，消费方异常处理零改动 |

| 失败情形 | `data.reason` | 消息要点 |
| --- | --- | --- |
| 解析器未装载快照（未走启动钩子 / 域布局未登记） | `not_loaded` | 提示检查启动装配与 `sys_tenant_topology` |
| 该租户与默认拓扑都没有此域 | `not_registered` | 含域名与租户，提示「拓扑未配置」 |
| 该域在本租户 `status=disabled` | `not_enabled` | 含域名与租户，属业务态（不是配置缺失） |

**为什么用进程内快照而不是逐次查库**：协议是同步签名，而库访问是异步；且拓扑只在发布时变化。故启动钩子装载快照（`(tenant_id) → (version, {domain: (unit, status)})`），写入后在同进程内替换该租户的键——`(tenant_id, version)` 为键使「新版本自然可见」无需失效广播，容量上限淘汰旧版本。

**与 07B 的接口**：实现 `TopologyResolver` 协议，启动期 `register_topology_resolver()` 替换其过渡默认实现；协议签名与返回（`CapabilityTarget`）不变，消费方代码零改动。

### 3.4 校验 <a id="validate"></a>

| # | 校验 | 处置（错误码） |
| --- | --- | --- |
| 1 | `domain_key` 在业务域登记中已存在（取 `domain_service_view()` 的键） | 拒绝整批写入，列出未登记域（`ParamError` 10001） |
| 2 | `unit_key` 命名合法：`^[a-z][a-z0-9-]{0,63}$` | 拒绝并指出单元（`ParamError` 10001） |
| 3 | 同一租户内同一域只出现一次 | 拒绝并指出重复域（`ConflictError` 10003；唯一键兜底） |
| 4 | 每个单元至少承载一个域（不产生空单元） | 拒绝并列出空单元（`ParamError` 10001） |
| 5 | 默认拓扑（`tenant_id=0`）必须覆盖**全部已登记业务域** | 拒绝并列出缺失域（`ParamError` 10001）——否则未配置租户会启动失败 |
| 6 | 模板名 ∈ `{single, grouped, isolated}` | 拒绝未知模板（`ParamError` 10001） |
| 7 | 版本递增（新版本 > 当前最大版本） | 拒绝回退（`ConflictError` 10003） |

校验 1 的取值面是**业务域登记视图**（`domain_service_view()`，由 `sys_domain` 与清单第九类派生），不是表归属登记——`file` / `search` / `report` 无自有表，按表归属取会漏。

### 3.5 参照模板 <a id="template"></a>

模板常量落 `bms_core/collaboration/topology_templates.py`（与 `TopologyResolver` 同目录：写入方、`02_02` 寻址、`04_02` 迁移三方共用，不绑 platform 服务）。

```python
expand_template(name, *, domains: Mapping[str, str]) -> ConcurrentStableList[TemplateRow]
```

| 模板 | 内容 | 用途 |
| --- | --- | --- |
| `single` | 全部已登记域 → `core` | 小微 / 试用 / 开发测试 |
| `grouped` | 平台域与 `org` → `core`；采购域（登记后）→ `biz-purchase`；仓储 + 销售域（登记后）→ `biz-ops` | 业务重心明显的租户 |
| `isolated` | 每域一个 `dom-*` 单元（`dom-` + 域标识，下划线换连字符） | 大型企业 / 强隔离 |

- **只展开已登记域**：`grouped` 的 `biz-*` 在其域登记前不出现（与 `01_02` §3.4「模板只引用已登记业务域」一致），故当前 `grouped` 与 `single` 展开结果相同；
- 模板是**展开用的常量**，展开后可人工调整再写入；模板变动不影响已落库的拓扑（已生效的拓扑是数据，不是引用）；
- **默认拓扑不使用模板**（见 §3.7）：模板表达目标形态，默认拓扑必须与现状承载一致。

### 3.6 对外出口 <a id="output"></a>

| 消费方 | 用途 | 形态 |
| --- | --- | --- |
| 能力寻址第二段（本专项 `02_02`） | 域 → 单元与库 | 进程内协议实现（§3.3） |
| 部署编排（`04_01` / `04_02`） | 按拓扑生成编排与迁移目标 | 只读导出端点 + `ops` 命令（按租户全量） |
| 运维排查 | 「这个租户的采购跑在哪」 | 管理面分页端点 |

**端点**（`/api/v1/tenant-topologies`，模块级 `require_auth`）：

| 方法 | 路径 | 权限码 | 语义 |
| --- | --- | --- | --- |
| GET | `""` | `tenant-topology:query` | 分页查询（可按 `tenant_id` / `domain_key` / `unit_key` 筛选） |
| GET | `/{tenant_id}` | `tenant-topology:query` | 某租户当前版本全量导出（部署编排输入） |
| PUT | `/{tenant_id}` | `tenant-topology:manage` | 整批写入（`rows` 或 `template` 二选一，整事务替换并留审计） |

- 新增端点须刷新公开契约快照与基线（`python -m ops.contract_snapshot export` + 基线同步），否则契约门禁会拦；
- **不下发到前端**：前端只关心业务域与命名空间，不需要知道单元。

### 3.7 启动装配与自举 <a id="bootstrap"></a>

启动钩子 `bootstrap_tenant_topologies(app)`（platform `startup_hooks`，晚于建表）：

| 步 | 动作 | 失败 |
| --- | --- | --- |
| 1 自举默认拓扑 | `tenant_id = 0` 无未删除行时，按「已登记域 → 该域承载服务键」生成版本 1 并整批写入 | 异常上抛，`CatalogError` 拒启 |
| 2 补齐默认拓扑 | 已有版本但缺某已登记域时（如产品新接入 `org`），按同一口径补行并写**下一版本**（幂等：无缺域不写） | 同上 |
| 3 校验覆盖 | 默认拓扑须覆盖全部已登记域（校验 5）；缺域即列名 | `ParamError` 拒启 |
| 4 装载与登记 | 读全部未删除行 → 建快照（默认 + 各租户）→ `register_topology_resolver(TenantTopologyResolver())` | `CatalogError` 拒启 |
| 5 释放登记 | 把「复位解析器与快照」登记进资源管理器，随应用关闭释放（进程级状态不在两次装配之间残留） | — |

**补齐的两个触发点**：① 启动钩子（步 2）；② **产品声明注册通道**（`PUT /api/v1/platform/internal/declarations` 落库并投影后调 `ensure_default()`）——注册可能带来新业务域，补齐后这些域的能力寻址才有拓扑，否则「默认拓扑覆盖全部已登记域」的不变式在运行期即被打破。

`ops` 入口：`python -m ops.tenant_topology bootstrap|export`（CI 集成档 / 部署前显式执行；与钩子共用同一服务实现，不写第二套逻辑）。

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 默认拓扑未覆盖全部域导致新租户启动失败 | 校验 #5 强制覆盖全部域；模板内置全量域 |
| 整批替换误删（事务内有异常） | 同一事务内软删除 + 插入，异常回滚；版本号递增后才可见 |
| 缓存与版本不同步 | 缓存键含版本号；不依赖主动失效 |
| 拓扑与部署实际不一致（记录说 A，实际跑在 B） | 记录是权威，部署编排按记录生成（`04_01`）；不一致由发布校验拦截 |
| 同一域历史行堆积 | 软删除行按租户整批替换产生，量级受“域数 × 变更次数”约束；必要时归档（当前不做） |
| 其它服务进程取不到本进程快照 | 本任务只保证 platform 进程内解析与只读导出端点；跨进程分发（快照下发 / 进程内直调）归 `02_02`，在此之前其它服务沿用 07B 过渡实现（行为不变，不会错址） |
