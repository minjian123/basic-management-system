### 2.2 三处拍板的落地点 <a id="decisions"></a>

| # | 结论 | 落地 |
| --- | --- | --- |
| 1 | 租户取 `current_tenant_id` 上下文，协议签名不变 | `TenantTopologyResolver.tenant_id()`（缺失 / 非法按默认拓扑）；另给显式 `resolve_for(tenant_id, domain)` |
| 2 | `db_keys` 只含平台库键 | `resolve_for` 返回 `[platform_{unit}]`；租户库键 `tenant_{unit}_{db_basis}` 由调用方派生（文档与 docstring 双处写明），未跨域读 `sys_tenant_database` |
| 3 | 默认拓扑自举为「域 → 承载服务键」 | `ensure_default()` 按 `domain_service_view()` 写入版本 1（单元 = 该域 `service_key`），库名与现状一致（`bms_platform` / `bms_mdm`） |

### 2.3 写入与生效 <a id="write"></a>

| 环节 | 实现 |
| --- | --- |
| 校验 | 域已登记（取 `domain_service_view()`，非表归属登记——`file` / `search` / `report` 无表会漏）/ 单元命名 `^[a-z][a-z0-9-]{0,63}$` / 同域唯一 / 非空 / 默认覆盖全部域 / 模板名 / 状态取值 |
| 版本 | 空则「当前 + 1」，显式给值须大于当前（回退即拒 `10003`） |
| 替换 | 单事务内软删该租户当前行 + 写新版本行 + `flush`；端点提交由 `uow.commit()` 负责 |
| 生效 | 写入后即时 `register_topology_snapshot()`（`(租户, 版本)` 键），解析立即返回新结果 |
| 审计 | 整批一条：`topology_version`（旧 → 新）+ `domains`（域数），`model_id` 取租户主键 |

### 2.4 与现有机制的一致性核对 <a id="consistency"></a>

| 核对项 | 事实 | 结论 |
| --- | --- | --- |
| 软删除过滤口径 | `BaseDbRepository._scope_where(include_soft_delete=True)` 才是「只看未删行」（`False` 为物理删除出口穿透） | 初版按字面传 `False` 导致替换后仍看到旧版本，已改正并补用例 |
| 域登记来源 | `domain_service_view()` 来自第九类 `[[domains]]` 与注册通道，含无表域 | 校验 1 与自举均用它，未用 `registered_domains()` |
| 默认拓扑与 07B 过渡实现等价 | 单元 = 承载服务键 ⇒ `build_platform_db_key(unit)` 得 `platform_{service}`，与改造前同值 | 库名 / 基址零变化，切换无感 |
| 无第二份事实源 | 拓扑表不存库名、不存 `db_basis`；模板是常量不落库 | 与架构 39 §4.1 三条不变式一致 |
| 边界纪律 | 新模型登记进 `platform_registry` 域路径；服务内四层均在 `domains/platform_registry/` | `check_service_boundaries` 通过（未归属 0 / 跨域 import 0 / 跨域表引用 0） |
