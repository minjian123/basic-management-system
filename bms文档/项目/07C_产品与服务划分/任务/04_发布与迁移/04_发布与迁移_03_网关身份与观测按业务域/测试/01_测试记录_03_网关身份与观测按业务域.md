## 2. 用例与结论 <a id="cases"></a>

设计 §5 的 14 条按落地形态逐条对照：

| # | 设计用例 | 落点 | 结论 |
| --- | --- | --- | --- |
| 1 | 单体拓扑生成路由（全部域指向同一单元） | `test_merged_unit_gets_single_upstream`（多域同单元只生成一条 upstream） | ✔ 单元内多域共用一个上游，不按域重复建 |
| 2 | 独立拓扑生成路由（各域各自单元，**路径与单体一致**） | `test_route_paths_stable_across_topologies`（两拓扑 `uris` / `id` 相同、`upstream_id` 不同） | ✔ 路径不变、上游随拓扑（前端口径无感） |
| 3 | 域 `disabled`：不生成该域路由 | `test_disabled_domain_generates_no_route`（路由为空、单元也不进上游段） | ✔ 不生成而非生成后拒绝 |
| 4 | 平台服务级路径不受拓扑影响 | `test_platform_service_routes_unaffected_by_topology`（路由 / 上游均不变） | ✔ 服务级面与产品域面解耦 |
| 5 | 令牌 `domains` 与实例承载域一致；未声明取默认拓扑 | `test_issue_declares_service_domains`（签发写 claim）、`test_verify_service_token_domains_claim`（校验回填）、`test_instance_domains_are_topology_intersect_units` / `test_instance_domains_empty_without_topology` | ✔ 声明＝默认拓扑启用域 ∩ 承载单元；未装载时为空集（不误判） |
| 6 | 入站：域不符 → 拒绝，错误含域 / 能力 / 消费方 | `test_domain_claim_mismatch_rejected`、`test_attribution_rejects_domain_mismatch` | ✔ 403，消息含三者；第一道拒绝后不再进第二道 |
| 7 | 入站：域符但无授权 → 拒绝（第二道拦截） | `test_service_without_grant_rejected`（既有用例，域声明补齐后仍拒） | ✔ 两道判定各自独立可验 |
| 8 | 出站 scope 仍为 `{domain}:read|write`，不新增形态 | `grant.py::granted_scopes`（既有用例 `test_capability_grant.py` 覆盖 `svc:{域}:{动作}`） | ✔ 未改 scope 形态（本任务只加域声明 claim） |
| 9 | 日志字段含 `domain_key` 与 `unit_key` | `test_access_log_carries_domain_and_unit` | ✔ 访问行带域（域段）与单元（`[app].unit`） |
| 10 | 指标标签可按域聚合；无域标注计入 `unknown` 并告警 | `test_metrics_carry_domain_and_unit_labels`、`test_unknown_domain_is_labelled_and_warned` | ✔ 标签 `domain` / `unit`；`unknown` 另发告警行且样本不丢 |
| 11 | 配置声明单元不存在 → 拒启 | `test_topology_mode.py::test_unknown_unit_rejected`（`02_02` 既有）+ `test_topology_units_declaration_accepted`（合法声明放行） | ✔ 未登记单元启动即拒（拓扑已装载时） |
| 12 | 配置同时声明单元与域集合 → 拒绝 | `test_topology_domains_declaration_rejected`（`ConfigError`，错误给出正确口径） | ✔ 声明即拒启（不静默择一） |
| 13 | 未启用域三层一致（不装配 / 不生成路由 / 调用被拒） | `test_disabled_domain_generates_no_route` + `test_domain_not_enabled_on_instance_rejected` + `test_attribution_rejects_domain_not_enabled_here` | **两层覆盖**：路由不生成、入站被拒；装配层未裁剪（设计 §9 开放项 6） |
| 14 | CI 生成物比对：拓扑变化时上游变化、路径不变 | `test_route_paths_stable_across_topologies` + `ops.gateway_config check`（零漂移） | ✔ 生成物比对进既有 CI 环节（`check`） |

**追加用例**（设计未列，按实现边界补）：

| 用例 | 断言 |
| --- | --- |
| `test_missing_topology_entry_rejected` / `test_empty_unit_rejected` | 域缺拓扑行 / 单元为空 → 生成前即拒（`CatalogError`，错误指明域与产品） |
| `test_product_path_overlapping_service_path_rejected` | 产品域路径与 `/api/{service}/v1` 重叠 → 拒（入口不产生歧义路由） |
| `test_route_targets_skip_blank_domain_rows` | 拓扑脏行（域为空）跳过，不产生目标也不报错 |
| `test_load_topology_from_db_maps_units_and_status` | 平台库默认拓扑行 → 域 / 单元 / 状态（停用域保留状态供生成时跳过） |
| `test_load_topology_ignores_tenant_domain_absent_from_default` | 租户有、默认没有的域不算偏离（不误报） |
| `test_registry_source_warns_on_tenant_deviation` | 其它租户域落点偏离默认 → 告警且不失败（边缘只用默认拓扑） |
| `test_registry_source_falls_back_when_topology_empty` | 平台默认拓扑为空 → 告警并退回域登记面（不错址、不误拒） |
| `test_load_reports_topology_read_failure` | 拓扑读面异常 → 退出码 1 并明示（不静默按默认拓扑生成） |
| `test_domain_claim_missing_rejected` | 旧版票据（无 `domains`）→ 403，提示升级签发侧 |
| `test_or_service_whitelist_skips_domain_gate` | 白名单内部服务 → 不经域判（内部调用不持域声明） |
| `test_null_capture_labels_domain_key` / `test_null_capture_unknown_table_falls_back` | 审计信封带 `domain_key`（表归属派生），未登记表回落 `unknown` |
| `test_domain_of_table_uses_table_ownership` | 表 → 域取归属登记（`sys_role` → `role`） |
| `test_module_exports_domain_claim_contract` | 域声明常量与令牌契约同源（单一来源） |
