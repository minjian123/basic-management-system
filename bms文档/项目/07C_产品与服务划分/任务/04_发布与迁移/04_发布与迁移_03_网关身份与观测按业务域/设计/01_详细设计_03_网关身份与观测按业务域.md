# 网关、身份与观测按业务域详细设计

> 产品与服务划分 · 04 发布与迁移 · 03 网关、身份与观测按业务域 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [03 网关、身份与观测按业务域](../04_发布与迁移_03_网关身份与观测按业务域.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：让**对外路径、调用身份、可观测性**三处都以**业务域**为稳定面——同一业务域在合并与拆分两种拓扑下对外路径不变、令牌可追溯、指标可按域归因；未启用的域不暴露。

**范围内**：

1. 外部路由生成规则的调整（域 → 单元 → 上游）；
2. 服务令牌的业务域声明与对账；
3. 日志 / 指标 / 审计按域标注；
4. 「本部署单元启用哪些域」的配置形态与运行期影响；
5. 拓扑切换下的路径一致性验证。

**范围外**：能力授权本身（07B `02_04`）、拓扑记录（`02_01`）、发布流程（`04_01`）、迁移操作（`04_02`）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 外部路径（产品） | 已按域：`productPrefix(product, domain)` = `/api/{product}/v1/{domain}` —— **这是现成的稳定面** |
| 外部路径（平台服务） | 按服务：`/api/{service}/v1/...`（`route_prefix` + `rewrite`） |
| 上游 | 由**服务键**决定（`upstream_node(service_key)`） |
| 令牌 | 服务令牌 `aud=service` + scope（如 `mdm:write`），无业务域维度 |
| 观测 | 日志 / 指标按服务与请求打标，无 `domain_key` |
| 配置 | 只有 `[app].service`（本实例服务标识），无「本单元承载哪些域」 |

**缺口一句话**：**路径已经按域了，路由与身份还没按域**——所以合并部署后，网关仍按服务拼上游，令牌也说不清“这个服务能碰哪些域”。

## 3. 设计 <a id="design"></a>

### 3.1 外部路由生成规则调整 <a id="route"></a>

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| 路由输入 | 服务清单 + 产品路由 | **产品路由 + 拓扑记录**（域 → 单元） |
| 外部路径 | `/api/{product}/v1/{domain}`（产品） / `/api/{service}/v1`（平台服务） | 产品路径**不变**；平台服务保留 `/api/{service}/v1`（服务级 API 不按域拆） |
| 上游 | `upstream_node(service_key)` | `upstream_node(unit_key)`——域所属单元 |
| 生成时机 | 服务清单变更时 | 拓扑变更（发布）或路由声明变更时 |

**规则**：

1. 一条外部路由 = 一个业务域的一段路径，上游指向该域**当前单元**；
2. 同一域在合并 / 拆分两种拓扑下，**外部路径完全相同**，只有上游变化——前端与调用方无感；
3. 平台服务保留服务级路径（`/api/{service}/v1`），因为它们是平台自身 API，不属产品能力面；与产品域路径**不重叠**；
4. 未启用（`disabled`）的域**不生成路由**（不是生成后拒绝）。

### 3.2 路径一致性验证 <a id="consistency"></a>

| 验证 | 方法 |
| --- | --- |
| 同域两种拓扑路径一致 | 夹具：同一份产品路由 + 两份拓扑（单体 / 独立），比对生成的路由路径集合 |
| 上游随拓扑变化 | 同上，比对 upstream 指向不同单元 |
| 未启用域无路由 | 构造 `disabled` 域，断言路由集合中不存在 |

该验证纳入 CI（生成物比对），避免“路径偷偷变了”。

### 3.3 令牌携带业务域 <a id="token"></a>

| 项 | 口径 |
| --- | --- |
| claim 新增 | `domains`：本服务实例**承载**的业务域列表（来自实例配置，非请求参数） |
| 派生来源 | 本单元所含域（`02_01`）∩ 平台启用的域清单；实例未声明时取默认拓扑 |
| 对账 | 入站：调用方 `domains` 必须包含被调能力所属域，且该「能力 × 消费方」有有效授权（`02_04`）；两者都满足才放行 |
| 出站 | scope 仍按 `{domain}:read|write` 派生（与 `02_04` 一致），不新增一套 scope |
| 失败 | 域声明缺失或与授权不符 → 拒绝并给明确错误（域 + 能力 + 消费方） |

**为什么不只靠 scope**：scope 是“能做什么动作”，`domains` 是“能碰哪些域”；合并部署后同一 scope 可能跨多个域，必须有域维度才能判断越界。

### 3.4 观测按业务域 <a id="observability"></a>

| 项 | 要求 |
| --- | --- |
| 日志 | 结构化字段增加 `domain_key` / `unit_key`（中间件统一注入，业务代码不重复打） |
| 指标 | `http_requests_total{route, domain, unit, status}`、`request_duration_seconds{domain}`；能力调用沿用 `capability_*`（`02_04`） |
| 审计 | 业务变更审计记录带 `domain_key`，便于按域检索“这个域的写操作都有哪些” |
| 面板 | 可按域下钻（服务 → 域 → 接口），归可观测性阶段实现 |

### 3.5 配置：本单元启用的域 <a id="config"></a>

| 项 | 口径 |
| --- | --- |
| 新增配置 | 实例声明承载的业务域集合（与 `02_02` 的「承载单元集合」同源：单元 → 域，由拓扑决定，配置只声明单元） |
| 冗余声明禁止 | 不同时声明“单元”和“域集合”——只声明单元，域由拓扑解析（避免两处不一致） |
| 校验 | 声明的单元必须在默认拓扑存在且非空；否则**拒启** |
| 未启用域 | 该单元不含的域：不装配其处理器、不生成路由、入站调用被拒（三层一致） |
| 凭据隔离 | 各业务域的配置与密钥**独立存放、不共享凭据**：合并部署只合并进程与库，不合并密钥作用域；配置按域分组加载，缺失即拒启 |

### 3.6 与相邻机制的接口 <a id="interface"></a>

| 机制 | 本任务关系 |
| --- | --- |
| `02_01` 拓扑记录 | 路由生成与域集合的唯一来源 |
| `02_02` 两段解析 | `local` / `remote` 判定依赖同一份“本实例承载集合” |
| `02_04` 能力授权 | 入站校验的第二道（授权）；`domains` 是第一道（域归属） |
| `04_01` 发布 | 拓扑变更后的路由重生成属于发布步骤之一 |
| 网关生成器（既有 `gateway_catalog`） | 改造输入与上游映射，不新建生成器 |

## 4. 影响面 <a id="impact"></a>

| 类别 | 对象 | 变更 |
| --- | --- | --- |
| 修改 | `bms_core/services/gateway_catalog.py` | 路由输入增拓扑；上游按单元；未启用域不生成 |
| 修改 | 网关配置生成物与校验脚本 | 生成规则与比对（`ops.gateway_config check`） |
| 修改 | 服务令牌签发（认证侧） | 增加 `domains` claim |
| 修改 | 入站校验中间件 | 域归属校验（第一道）+ 授权校验（第二道） |
| 修改 | 请求上下文 / 日志中间件 | 注入 `domain_key` / `unit_key` |
| 修改 | `config.toml` 与配置模型 | 新增“本实例承载单元”声明（替代直接声明域集合） |
| 不改 | 产品外部路径规则 | 已按域，保持 |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 单体拓扑生成路由 | 全部域路由指向同一单元 |
| 2 | 独立拓扑生成路由 | 各域路由指向各自单元；**路径与单体一致** |
| 3 | 域 `disabled` | 不生成该域路由 |
| 4 | 平台服务级路径 | 不受拓扑影响，仍为 `/api/{service}/v1` |
| 5 | 令牌 `domains` | 与实例承载域一致；未声明时取默认拓扑 |
| 6 | 入站：域不符 | 拒绝，错误含域 / 能力 / 消费方 |
| 7 | 入站：域符但无授权 | 拒绝（第二道拦截） |
| 8 | 出站 scope | 仍为 `{domain}:read|write`，不新增形态 |
| 9 | 日志字段 | 请求日志含 `domain_key` 与 `unit_key` |
| 10 | 指标标签 | 按域聚合可查；无域标注的请求计入 `unknown` 并告警 |
| 11 | 配置声明单元不存在 | 拒启 |
| 12 | 配置同时声明单元与域集合 | 拒绝（避免两处不一致） |
| 13 | 未启用域的三层一致 | 不装配 / 不生成路由 / 调用被拒 |
| 14 | CI 生成物比对 | 拓扑变化时上游变化、路径不变 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 路由生成依赖拓扑，拓扑错误会放大到入口 | 生成前校验拓扑完整（每域有单元、每单元非空）；生成物比对进 CI |
| `domains` 与 scope 两套判断口径 | 明确分工：`domains` 管域归属、scope 管动作；两者都由分配记录派生，不独立维护 |
| 日志重复打标 | 中间件统一注入，业务代码不再手写 |
| 未启用域“装配了但不暴露”造成误判 | 三层一致（装配 / 路由 / 校验）写进测试；任一不一致即失败 |
| 平台服务与产品域路径冲突 | 路径前缀规则固定（`/api/{service}/v1` 与 `/api/{product}/v1/{domain}`），生成时断言不重叠 |
