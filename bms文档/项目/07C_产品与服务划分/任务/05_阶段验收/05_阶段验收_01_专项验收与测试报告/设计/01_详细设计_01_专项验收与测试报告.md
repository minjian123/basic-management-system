## 1. 目标与边界 <a id="scope"></a>

**目标**：用可复现的证据给 07C 的 **7 行**门禁逐条结论（行数以计划 §5 为准），把「业务域稳定、部署单元可变——同一套业务域模型在合并与拆分两种拓扑下都能跑，且边界不因合并而消失」从声明变成机器可验的事实；并完成三类文档一致性与遗留归口。

**范围内**：

1. 门禁 7 行的证据形式与结论写法（含「限定达标」语义）；
2. 专项测试报告结构（七节 + 两附录）；
3. 三类文档一致性核对与收口断言用例；
4. 收口回写清单与遗留归口规则（含 `03_02` 遗留 3「表文件归属库行」的批改）。

**范围外**：任何功能实现（本任务只验证、批改字段级表述与收口）；平台巨型服务实际拆分（计划 §7 第 1 项，达阈值另立任务）；真库 / 真部署演练（计划 §7 第 5 项，部署窗口）。

## 2. 现状与先例 <a id="current"></a>

| 先例 | 可复用内容 |
| --- | --- |
| 07B `05_01` | 门禁逐行内联结论 + 证据索引的写法；报告七节 + 两附录；收口断言用例（`test_collab_closure.py`）；计划全量回写（头部计数、§2/§3、§5 结论、§7 台账） |
| 阶段七 `05_01` | `check_status` 与文档护栏把关；进度图改收口态以消除 S2 软提示 |

**07C 的差异**：① 门禁 **7 行**（少而宽，每行覆盖一个任务族）；② 证据以**两种拓扑下行为等价**为主线（合并 / 拆分夹具、默认拓扑零漂移、路径不随拓扑变）；③ 无界面交付（不设界面一致性节）；④ 收口附带一项**字段级文档批改**（`03_02` 遗留 3 归口本任务）。

## 3. 设计 <a id="design"></a>

### 3.1 门禁逐行证据形式 <a id="gate"></a>

每行统一四要素：**验证手段（命令）+ 通过标准 + 证据索引（用例 / 记录）+ 结论（达标 / 限定达标）**。

| # | 门禁行（计划 §5 原文缩略） | 验证手段 | 通过标准 | 证据索引 |
| --- | --- | --- | --- | --- |
| 1 | 业务域划分判据与目标业务域清单齐备 | `deploy/boundaries/domain_layout.json` 与 `platform.toml [[domains]]` 逐域对照 + 清单文档复核 | 判据四条 + 反例清单成文；清单覆盖平台 16 域 + 产品 `org`；每域给所有权 / 表前缀；清单被能力目录与表归属引用 | `01_01` / `01_02` 测试记录 |
| 2 | 租户拓扑可记录、可解析、可校验 | `pytest services/platform/tests/{api/test_tenant_topologies,api/test_internal_tenant_topologies,registry/test_tenant_topology_bootstrap}.py` | 按租户登记 + 变更留审计；同域双映射 / 未登记域 / 未登记单元均被拒 | 33 例（22 + 4 + 7） |
| 3 | 能力两段解析在两种拓扑下均正确 | `pytest tests/collaboration/test_topology_mode.py test_capability_resolution.py` | 合并与拆分夹具下同一能力取址一致；拓扑缺失启动拒启、运行期明确报错 | 22 例（10 + 12） |
| 4 | 合并部署下边界纪律仍成立 | `check_service_boundaries.py .` + `check_service_boundaries.py --self-test` | 跨域 import / 表引用 / 写 / 表声明均 0；域级基线 0 条；域公共出口只暴露 DTO（D6 违规 0、白名单逐条命中） | 护栏输出 + `03_01` / `03_04` 记录 |
| 5 | 两套拓扑迁移可复现且可回滚 | `pytest tests/ops/test_topology_migration.py test_migrate_topology.py` + `ops.migrate_topology` 五阶段流程 | 拆分端到端可复现（复制 / 四类对账 / 切换 / 清理）；P5 拓扑替换与清单写入同事务，校验不过整体回滚 | 39 例（14 + 25） |
| 6 | 对外路径与身份按业务域稳定 | `pytest tests/services/test_gateway_catalog.py tests/collaboration/test_domain_scope.py tests/api/test_require_capability.py` + `ops.gateway_config check` | 同域在合并 / 拆分下路径一致（仅上游变）；令牌声明业务域并与分配对账；指标按域可过滤；停用域不生成路由 | 60 例（36 + 12 + 12）+ 生成件零漂移 |
| 7 | 发布对账可给出结论 | `pytest services/platform/tests/release tests/ops/test_release_cli.py` | 输出逐域版本清单与契约兼容结论；不兼容拒绝且定位到域与能力；按清单（= 单元）批次回滚 | 27 例（24 + 3） |

**「限定达标」语义**：仅在证据受环境限制（真库 / 真部署需窗口）时使用，必须写「限定：{限制}（归口 §7 第 N 项）」；**不允许**用「限定」掩盖未实现。

**禁止**：只写「已达标」而无证据索引；证据指向不存在的用例或文件（由收口断言检出）；报告与计划各写一套结论。

### 3.2 专项测试报告结构 <a id="report"></a>

报告落 `bms文档/项目/07C_产品与服务划分/01_测试报告_产品与服务划分.md`，七节 + 两附录：

| 节 | 内容 |
| --- | --- |
| §1 结论 | 门禁 7 行总判定、专项价值断言达成与否、未达标项与归口 |
| §2 用例执行统计 | 各任务用例数、基座 / 身份 / 平台套件、护栏自测、定向选测与覆盖率门禁 |
| §3 缺陷统计 | 立项根因（无业务域层）、实施期发现与修复、收口轮发现与修复、环境类 |
| §4 覆盖率 | 变更模块定向覆盖率（行 + 分支 100%）+ 引用各任务快照的口径说明 |
| §5 门禁逐条核对 | 7 行表格（结论 + 证据索引，与计划 §5 同源） |
| §6 风险与遗留 | 遗留逐条归口，无「无归口」条目 |
| §7 复盘与经验教训 | 根因、机制收益、可复用经验（含本轮踩坑） |
| 附录 A | 复现命令清单（逐条命令 + 期望输出摘要） |
| 附录 B | 拓扑不变量对照（不变量 → 机器可验位置） |

**与计划 §5 的关系**：门禁结论**单一事实源在计划 §5**；报告 §5 同构引用、行数恒等。

### 3.4 收口断言用例 <a id="assert"></a>

新增 `backend/libs/bms_core/tests/crosscut/test_division_closure.py`（与 `test_collab_closure.py` / `test_m7_closure.py` 同族）：

| 断言 | 目的 |
| --- | --- |
| 计划 §5 门禁表恰 7 行，每行含「达标」且证据 > 60 字符 | 防漏行、防只写「待核对」 |
| 限定项恰 1 行且带「归口 §7 第 N 项」并指向存在条目 | 防「限定」滥用与归口悬空 |
| 计划头部计数 = 两张表行数、§3 无剩余行、工作量三项自洽 | 防收口只改表不改头部 |
| 报告七节 + 两附录齐备、§5 行数 = 7、声明同构引用计划 §5 | 防报告与门禁脱节 |
| 遗留台账每行「来源 + 归口」齐备、无「无归口」 | 防无主遗留 |
| 表文件「归属库」行统一写「归属部署单元」（全仓零「归属服务 \`」残留） | 防 `03_02` 遗留 3 回潮 |
| 任务文档 / 域总览不承载状态与完成日期 | 进度唯一落点在计划表 |

### 3.6 遗留归口规则 <a id="followup"></a>

| 规则 | 说明 |
| --- | --- |
| 每条必须有「来源 + 归口」 | 来源指向任务记录或本轮核对；归口指向具体任务 / 阶段 / 运维窗口 |
| 禁止「无归口」 | 断言用例检出即失败 |
| 环境类单列 | 真库、真部署、本机依赖未还原等标「环境类」，不计产品缺陷 |
| 已闭环标注保留 | 既有台账中已闭环项不删除，标「已交付」并注明落点（保留追溯链） |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 门禁结论「看起来达标」但证据不可复现 | 每行给命令 + 期望输出摘要；附录 A 列全部命令 |
| 计划与报告结论漂移 | 结论单一事实源在计划 §5，报告同构引用；断言用例校验行数一致 |
| 「限定」被滥用 | 限定必须指向 §7 条目且该条目有归口；断言用例校验格式与条数 |
| 字段级批改波及 56 份表文件 | 只替换「归属库」行的措辞（`归属服务` → `归属部署单元`），不动字段 / 索引 / 变更记录；批改后跑 `links` / `eol` / `check_base` |
| 进度图与已完成表冲突（S2 软提示） | 收口时进度图改「任务名 + done」形态，不再用计划编号作节点名 |
