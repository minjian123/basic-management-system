## 2. 实施过程 <a id="process"></a>

### 2.1 批 A：护栏与基线 <a id="batch-a-guard"></a>

| 步 | 内容 | 结果 |
| --- | --- | --- |
| 1 | engkit `service_boundaries.py` 增 D6 判定（`public_exports_of` / `load_public_exports` / `check_public_exports` / `finish_public_exports` / `public_export_kind_of` / `package_relative`） | 判定面 = `__all__` 声明 ∪ 顶层绑定；来源四类（模型 / 仓储 / `api/` / `services/`·`permission/`）即违规 |
| 2 | 配置字段 `public_export_baseline`（空串停用）与三个计数键 | 进 `[rules.service_boundaries]` 与 `counters`，越权改基线自动升全量 |
| 3 | 自检矩阵补正例 / 四型反例 / 声明与绑定不一致 / 白名单命中与陈旧 | `--self-test` 通过 |
| 4 | engkit 独立用例 `tests/test_base_boundaries_exports.py`（解析形状 / 结构非法 / 来源判定 / 端到端 / 早退容错 / 输出行） | 6 例通过，覆盖率 100% |
| 5 | bms 基线登记现状 | 首跑 **60 处**命中（`auth` 4 / `user` 10 / `role` 20 / `menu_form` 18 / `permission_meta` 8），逐条落白名单 |
| 6 | 修判据两处实现缺陷 | ① 目录判定误用仓根路径（`pkg/services/...` 自带 `services/` 段），改**包内相对路径**；② 共享库包只判模型（`bms_core.permission.field` 这类能力接口不算域内实现） |

### 2.2 批 A：`auth` 试点 <a id="batch-a-auth"></a>

| 项 | 实现 |
| --- | --- |
| DTO | 新增 `domains/auth/dto.py`，`IssuedSession` 从 `services/session_issuer.py` 迁入（仍 `@dataclass(frozen=True)`） |
| 端口 | 新增 `domains/auth/ports.py`：`SessionIssuerPort`（`issue(...) -> IssuedSession`）、`SessionCookiePolicy`（`apply_refresh` / `clear_refresh`） |
| 实现 | 新增 `domains/auth/services/cookie_policy.py`：cookie 读写逻辑唯一落点 + `HttpSessionCookiePolicy`；`api/cookies.py` 改薄转发（分层 `services` 不可 import `api`） |
| 装配 | 新增 `bms_identity/wiring.py`：再导出会话签发工厂 + `build_cookie_policy()`；身份联邦域改从装配面取 |
| 出口 | `public.py` 只留 `IssuedSession` / `SessionIssuerPort` / `SessionCookiePolicy` |
| 消费方 | `identity_federation/api/sso.py`（`build_cookie_policy().apply_refresh(...)`）、`services/sso.py`（类型改 `SessionIssuerPort`） |
| 基线 | 删 `auth` 4 条，护栏零命中 |

### 2.3 批 B：`role` 出口与消费点 <a id="batch-b"></a>

| 项 | 实现 |

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | D6 首版把仓根路径直接做目录匹配，`pkg/services/...` 里的 `services/` 段把**全部服务文件**判成「域内实现类」 | 判定改落在**包内相对路径**（`package_relative`），共享库包只判模型 |
| 2 | 批量文本替换把 `RoleReferencePort` 误伤成 `RoleSummaryerencePort`（`RoleRef` → `RoleSummary` 的子串替换） | 全量扫描还原；后续替换改为整词/结构匹配 |
| 3 | 删 `_dedupe` 时用「函数首行 → 下一个 class」切片，连带删掉了 `_user_payload` | 从 `git show` 取回原函数并恢复；切片改为按函数边界精确截取 |
| 4 | `HttpSessionCookiePolicy` / `bms_identity` 新增类未继承基类 | 基座断言（`test_all_app_classes_inherit_a_base`）拦截 → 策略类继承 `BaseFrameworkObject` |
| 5 | `IssuedSession` 迁移后值对象批次登记表仍指向旧路径 | `test_value_object_roots` 失败 → 登记表路径同步到 `domains/auth/dto.py` |
| 6 | `RoleRef` 与 `UserRoleBinding` 两种引用形状并存，`user` 侧还需要 `role_type` | 合并为 `RoleSummary`（含 `role_type` / `builtin`），删掉另两种 |
| 7 | 域内数据源直接 import `wiring`（域 → 装配 反向依赖） | 改成**注入工厂**：`PlatformDictDataSource(role_options=…)`、`PlatformPermissionDataSource(grants_factory=…)`；权限装配经 `app.state` 取工厂 |
| 8 | `role_resolvers` 返回 `tuple[...]` 触发裸集合护栏 | 改 `ConcurrentStableList[BaseRoleResolver]`（与基座 `PermissionSubjectService` 同口径），测试替身同步 |
| 9 | 现有用例大面积构造他域仓储（10+ 处） | 按「断言不变、构造随形态调整」改：构造经 `wiring` 工厂，替身方法名对齐 Port；`_apply_roles` 的三权前置断言移到 `role_assignment.py::set_user_roles` |
