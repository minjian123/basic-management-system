## 2. 实施过程 <a id="process"></a>

### 2.1 设计核对与冲突处置 <a id="review"></a>

动手前逐条核对「设计 → 代码现状」，发现两处结构性冲突，**停下经用户拍板后**按 §8 对齐记录执行：

| # | 冲突 | 现状事实 | 处置（用户拍板） |
| --- | --- | --- | --- |
| 1 | 设计 §3.1 规则 1「同一路径不得归属两个域」+ 规则 2「legacy 逐文件声明」假定「一文件一域」，但 platform 6 个域在**文件级切不开** | `bms_core/models/platform/{menu,system,user}.py` 各自声明 2~3 个域的表；`bms_platform/{api,services,repositories}/menu.py`、`services/role_grant.py`、`permission/*` 等跨域交叉 | 布局维持「一条目 = 一域 + 文件清单」，混域文件按**主域**登记，其对他域的声明 / 引用进基线（`kind` 分 `import` / `table_ref` / `table_declare`），只减不增 |
| 2 | 01_01 §5.3 定 `sys_account_lock` 划入 `auth` 域，但该表建在 **platform 库**（`owner=platform`，与 `sys_user` 同库），`auth` 承载服务是 identity | 双字段一致性判定下「域承载服务 ≠ 表归属服务」永远不一致；放宽则双字段校验失效 | **改归 `user` 域**（与 `sys_user` 同库同域），登录链路锁定写入经 user 域内部写通道（`api/internal_account_locks.py` 已是该形态）；已回写 01_01 §5.1 / §5.3 |

### 2.2 域布局声明（新增） <a id="layout"></a>

- 新增 `deploy/boundaries/domain_layout.json`：**16 个平台侧业务域**（`auth` / `identity_federation` / `user` / `role` / `permission_meta` / `menu_form` / `tenant` / `platform_config` / `platform_registry` / `task` / `notification` / `ai` / `txn` / `file` / `search` / `report`），共登记 **140 个域实现文件**；`shared_paths` 显式登记 **110 个域外文件**（装配 / 路由聚合 / 包入口 / 基座横切 / 基础设施 / demo）。
- 产品域 `org`（mdm 承载）**不在 bms 布局内**：其代码在 mdm 仓，布局随产品仓自建（设计开放项 4），避免出现指向未登记服务的空域条目。
- 域 ↔ 文件映射按实现语义逐文件判定（`api` / `services` / `repositories` / `schemas` / 模型目录），判定表由扫描脚本生成后人工复核，未归属文件数为 0。

### 2.3 域级断言接入护栏脚本 <a id="rules"></a>

`scripts/tools/base_check/check_service_boundaries.py` 在既有 10 项服务维断言之后追加：

| 断言 | 落地 |
| --- | --- |
| D1 跨域 import | 同服务内跨域 import 即失败（跨服务由规则 1 / 2 拦截，不重复计）；目标模块解析含 `from pkg import sub` 形态 |
| D2 跨域只经公共面 | 命中**目标域** `public_api` 出口放行；当前全部为空（分包前无出口） |
| D3 跨域表引用 | 原始 SQL / `ForeignKey` / 表名字符串 token 指向他域表即失败（读侧例外可按域登记） |
| D4 跨域写 | insert / update / delete / ddl 指向他域表即失败，**无例外** |
| D5 观测标注 | 越界文案带两侧 `domain_key`；运行期守卫日志与指标随带 `domain` / `owner_domain` 标签 |
| 域布局完整性 | 路径重复归属 / 与域外路径冲突 / 文件缺失 / glob 未命中 / `legacy` 域无路径 → 失败 |
| 域实现覆盖 | 声明了已登记表的文件未在布局登记 → `[域实现未登记]` 失败；未归属域文件数只作软指标 |
| 双字段一致 | `owner` == 域承载服务；基础设施表与 `demo`（不归域表）`domain` 恒空 |
| 基线只减不增 | 命中放行并计数；**条目不再命中即失败**（提示删除）；`--update-baseline` 人工重建 |

- 域级断言在**布局缺失或为空**时停用（产品仓 / 临时工程），服务维 1~10 照常，避免「无布局即全红」。
- 新增域级计数键 8 个（`cross_domain_import` / `cross_domain_table_reference` / `cross_domain_write` / `cross_domain_table_declare` / `domain_layout_violation` / `domain_ownership_violation` / `domain_baseline_total` / `domain_baseline_used`）与 2 个软指标（`domain_files_registered` / `domain_files_unregistered`）；`scripts/tools/governance/boundary_metrics.py` 同步纳入统计与输出。

### 2.8 域布局改由清单声明（2026-10-29 重开补正） <a id="domains-manifest"></a>

**背景**：07B `04_02` 两进程端到端实测——`mdm` 上报声明被平台拒（`40003`），8 条 `org` 域能力全部报「提供方业务域未登记（org）」。根因：域布局是各仓 `deploy/boundaries/domain_layout.json` **文件**，平台注册通道取不到产品仓的文件；§2.2 里「产品域随产品仓自建」的口径在**跨进程**场景下不成立（平台侧永远看不到）。

| # | 原口径 | 现口径 |
| --- | --- | --- |
| 1 | `domain_layout.json` 是**权威来源**，装载期读取 | 清单第九类 `[[domains]]` 是**唯一权威来源**；`domain_layout.json` 降为**本仓清单渲染的生成物**（`ops.check_modules --render-domain-layout` / `--check-domain-layout`），提交进 git、由漂移比对守护 |
| 2 | 产品域「随产品仓自建、不进 bms 布局」 | 产品域由**产品仓自己的清单**声明，经注册通道到达平台（`sys_domain` 表），平台不读任何产品仓文件 |
| 3 | 域 → 承载服务映射由布局文件派生 | 由 `domain_service_view()` 从**注册表快照**整表重建（`project_registry()` 的 `_project_domains()`） |
| 4 | 域级护栏读布局文件 | 护栏仍读本仓生成物（单仓 CI 场景）；**跨仓 / 运行期**以注册表为准 |

**域声明字段（全量复刻，不缺项）**：`domain_key` / `service_key` / `status` / `paths` / `public_api`（+ 可选 `name`）。渲染结果与迁移前文件**零差异**，证明声明完整覆盖原文件（16 域 / 127 条 `domain_shared_paths`）。

**为什么不是「一份信息存两处」**：产品各自自持声明，平台侧 `sys_domain` 是**注册表的落库投影**（由声明写入），不是第二份人工维护的来源。生成物同理——它是清单的确定性函数，漂移即报。

**连带影响**：§2.2 的「16 域 / 140 文件 / 110 域外文件」数值不变（生成物重新渲染后与迁移前逐字段一致）；`sys_domain` 作为第七张注册表登记进数据库设计总览与表文件。

### 2.4 表归属双字段（服务 + 域） <a id="owner"></a>

按数据库规范顺序实施：**表文件 → 模型 → 种子 → 对账**。

1. 表文件 `bms文档/设计/数据库设计/数据表设计/sys_table_ownership.md`：增「归属业务域」元信息行与 `domain` 字段行、变更记录 v2（2026-10-24）。
2. 模型 `bms_core/models/ownership.py::SysTableOwnership`：增 `domain` 列（`String(32)`，默认空串）。
3. 登记清单 `bms_core/services/table_registry.py`：`TableRecord` 增 `domain`（空串 = 不归域）、52 条记录逐条补域、`from_row` 读取、`_diff_ownership` 纳入 `domain`、`validate(domain_services=…)` 增域校验（不归域范围 / 标识形态 / 域已登记 / 承载服务一致）；新增 `table_domain` / `registered_domains` / `owned_tables_for_domain` 与 `NO_DOMAIN_TABLES`（`demo`）。
4. 种子 `ops/seed_tables.py` 与离线校验 `ops/check_tables.py`：写入 / 校验 `domain`；离线校验从 `deploy/boundaries/domain_layout.json` 取「域 → 承载服务」映射，镜像内无声明时降级为「只校验域标识形态」。
5. 表文件格式口径（设计 §3.3「本任务定格式」）回写《数据库开发规范》：`owner` / `domain` / `datasource` 三字段正交，表文件「归属业务域」须与 `domain` 一致。

### 2.5 运行期域维度判定 <a id="runtime"></a>

- `boundary/assess.py`：`assess_table` / `assess_statement` 增 `domain` 入参（非空即按**归属域**判定：同域放行、跨域拒绝、不归域与未登记表放行、只读例外按域匹配）；`OwnershipViolation` 增 `domain` / `owner_domain` 字段（服务维判定时为空串，保持既有调用面零改动）。
- `boundary/table.py`：守卫增 `domain` 入参；越界日志与指标随带 `domain` / `owner_domain`；`enforce` 阻断文案域维优先（`跨域库访问被拒：域 X 访问 T（归属域 Y）`）。
- `boundary/exceptions.py`：例外登记增可选 `domain` 字段（消费方按**服务或域**匹配）、`validate_exceptions` 增 `known_domains`。
- `boundary/domains.py`（新增）：`DomainEntry` / `DomainLayout` / `BaselineEntry` 契约与 `load_layout` / `load_baseline` / `dump_baseline`（结构非法抛 `ValueError`，语义问题返回值清单）。
- 运行期「当前域由部署单元决定」的装配点（守卫注入哪个域、库键单元段）**不在本任务**，归 `03_02` / `02_01` / `04_03`。
