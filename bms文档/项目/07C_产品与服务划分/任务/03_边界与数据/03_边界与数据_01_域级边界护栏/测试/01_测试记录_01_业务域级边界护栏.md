## 2. 用例与自动化落点 <a id="cases"></a>

平台一条用例覆盖设计 §5 的 14 项断言，自动化落点如下：

| 设计用例 | 断言 | 自动化落点 |
| --- | --- | --- |
| 1 / 2 | 布局覆盖完整 / 路径重复归属报错 | `tests/boundary/test_domain_boundary.py::test_layout_validate_detects_problems` / `test_resolve_files_reports_glob_miss_and_duplicate` |
| 3 / 5 | 跨域 import 拦截（基线外） | `test_domain_boundary.py::test_assess_table_by_domain`（判定）、`check-service-boundaries.py --self-test`「同服务内跨域 import 拦截」 |
| 4 | 跨域 import（legacy + 基线内）通过并计数 | `--self-test`「跨域 import 命中基线放行」；真实仓库 30 条基线全命中 |
| 6 | 经域内公共出口跨域放行（D2） | `--self-test`「域内公共 API 出口放行（D2）」 |
| 7 | 跨域表引用（SQL / FK / token）失败 | `--self-test`「跨域表引用拦截（D3）」；`test_assess_statement_by_domain` |
| 8 | 跨域写失败（D4，无例外） | `--self-test`「跨域写拦截（D4，无例外）」；`test_guard_domain_mode_blocks_cross_domain` |
| 9 | 表归属双字段不一致失败 | `--self-test`「表归属域与承载服务不一致拦截」；`test_registry_validates_domain_against_layout` / `test_registry_validates_domain_field` |
| 10 | 例外白名单带域 + 理由放行计数，无理由失败 | `test_exception_domain_field_and_matching` / `test_exception_load_with_domain_field`（理由必填由既有白名单 schema 断言） |
| 11 | 基线只减不增 | `--self-test`「陈旧基线条目拦截（只减不增）」 |
| 12 | 运行期跨域读表拒绝 | `test_guard_domain_mode_blocks_cross_domain`（`enforce` 阻断 + 文案）+ `test_assess_table_by_domain` |
| 13 | 既有服务维断言 1~10 回归 | `tests/crosscut/test_module_boundary.py`、`tests/boundary/test_boundary.py`、护栏自检原 21 例 |
| 14 | `--self-test` 覆盖正反例 | `check-service-boundaries.py --self-test`（原 21 例 + 新增 11 例） |

**合并部署反例**：域级断言按业务域判定，**同服务内不同域**（platform 的 `user` / `role` 等）在**同进程同库**下仍被拦截——自检样例即「同一服务两个域」，与合并部署形态同构。
