## 2. 用例与结果 <a id="cases"></a>

| 设计用例 | 断言 | 结果 |
| --- | --- | --- |
| 1 单域清单执行 | 清单名 / 分支标签 / 版本记录表名 / 目录；缺省清单 `platform_registry:tenant` | ✔ |
| 2 多域同库 | 同一库内 `alembic_version_user` 与 `alembic_version_role` 各读各值、互不覆盖 | ✔ |
| 3 重复执行 | 建表幂等：首跑新建、重跑「新建 0 / 已存在 N」 | ✔ |
| 4 单元含多域 | 单元清单按域名稳定排序、每清单只属一个域 | ✔ |
| 6 旧清单名 | `platform:tenant` 等旧形态被拒并提示改用域清单名 | ✔ |
| 9 库键单元段 | `[app].unit` 缺省回落 service；数据源键映射（平台 / 租户 / 归档） | ✔ |
| 10 跨单元访问 | 归属判定按单元（`resolve_db_key(unit=…)`，跨单元即拒） | ✔ |
| 11 归档库 | 单清单 `archive:archive`，表集为空、无基础设施表 | ✔ |
| 12 基础设施表 | 不进域清单；单元建表集含三表 | ✔ |
| 13 表归属越域 | 脚本建了域外表 → `ops.check_tables` 拦截（消息「不在该清单派生表集内」） | ✔ |
| 拓扑一致 | 合并单位表集 == 拆分各域表集并集；两库实际表名集合相等 | ✔ |
