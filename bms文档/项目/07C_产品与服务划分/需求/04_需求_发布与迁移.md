# 发布与迁移需求

> 07C 产品与服务划分 · 需求域 04：发布与迁移（2 条）

[文档首页](../../../文档首页.md) › [产品与服务划分总览](00_需求_产品与服务划分.md) › 发布与迁移

## 1. 域说明 <a id="intro"></a>

本域处理拓扑带来的两个运营问题：合并部署时怎么发版与对账、租户拓扑变更怎么迁。

- **依据**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「发布与版本」「拓扑迁移」节。

## 2. 需求 04-1：发布单元与版本对账 <a id="r04-1"></a>

优先级：2（高）

**背景与动机**：当前按服务发版；同一部署单元内合并多域后，会出现「三个域同时发布、契约版本互相不兼容」的情形——这在按服务发版时不会出现，因为各服务独立。

**内容**：

1. **发布单元 = 部署单元**：一次发布包含其内全部域的当次版本；域版本是部署单元版本的组成部分。
2. **契约版本对账**：合并部署前校验域间契约版本兼容（沿用协同节点的版本口径），不兼容即拒绝发布。
3. **产品版本解耦**：产品按自身节奏发版，只声明依赖的能力（域）与契约版本。
4. **回滚**：按部署单元整体回滚，避免同单元内版本错配。

**完成标准**：合并部署能给出域版本清单与契约兼容结论；不兼容时拒绝发布并定位到域与能力；回滚以部署单元为单位且有对应用例；产品版本与服务版本解耦的说明写入规划。

**参考文档**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「发布与版本」节、《[部署发布规范](../../../规范/部署发布规范.md)》

## 3. 需求 04-2：租户拓扑迁移 <a id="r04-2"></a>

优先级：2（高）

**背景与动机**：拓扑一旦可配，就一定会有「从单库单服务迁到分组」或「从分组迁回合并」的需求。这类动作涉及数据搬迁与流量切换，若无统一套路，每次都是高风险手工操作。

**内容**：

1. **先加后切**：新部署单元先上线并就绪，再切流量，最后下线旧单元。
2. **数据先行**：按域搬迁（表归属按域），搬迁期双写或停机窗口按租户等级选择。
3. **能力地址不变**：消费方按域寻址，拓扑切换对其透明；切换期允许短暂双活，但同一能力不得长期由两处提供。
4. **可回滚**：切换前保留旧单元与数据快照，回滚窗口内可整体退回。
5. **审计与告知**：变更留审计；涉及停机窗口须提前告知租户。

**完成标准**：从合并到拆分、从拆分到合并各有一条可复现的迁移步骤与回滚步骤；迁移期间能力取址不中断（夹具或演练验证）；迁移后数据完整性与表归属校验通过；变更留审计。
