## 1. 域说明 <a id="intro"></a>

本域把拓扑语义落成机制：租户拓扑的记录与解析、以及与跨产品协同能力寻址的对接（第二段解析）。

- **依据**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「部署拓扑」节；《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「消费方寻址与失败语义」节。

## 2. 需求 02-1：租户拓扑记录与运行时解析 <a id="r02-1"></a>

优先级：2（高）

**背景与动机**：拓扑按租户配置，但当前「哪个租户跑在哪些服务与库上」没有任何权威记录——部署编排靠人工理解配置文件，平台侧看不到全貌，也无法在运行期回答「某域此刻由哪个部署单元承载」。

**内容**：

1. **拓扑记录**：每租户一份「域 → 部署单元 → 库」映射，作为平台侧运营数据（可审计、可查全貌）。
2. **生效方式**：发布时生效（改拓扑 = 一次发布动作），不允许运行期随意漂移。
3. **解析入口**：提供运行期拓扑解析（给定域 → 当前租户的部署单元与库），供能力寻址、部署编排、运维排查共用。
4. **模板**：允许以模板预置常见组合（小 / 中 / 大 / 特定行业），单租户可在此基础上调整。
5. **校验**：拓扑引用的域与部署单元必须已登记；同一域在租户内只能映射到一个部署单元（禁止长期双活）。

**完成标准**：拓扑记录可登记、查询、变更（变更留审计）；运行期解析对「域 → 部署单元 → 库」给出唯一结果；引用未登记域 / 部署单元时拒绝；同域双映射被拒；模板可用且不改变语义。

**参考文档**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「部署拓扑」节

## 3. 需求 02-2：与能力寻址对接（两段解析） <a id="r02-2"></a>

优先级：2（高）

**背景与动机**：跨产品协同的能力目录原先只记录「能力 → 服务标识」，一旦同一域在不同租户由不同服务承载，服务标识就不再稳定。必须改为「能力 → 域」（稳定）与「域 → 部署单元」（可变）两段解析，否则拓扑一变就要改契约。

**内容**：

1. **第一段**：能力 → 域（能力绑域，稳定；见跨产品协同节点）。
2. **第二段**：域 → 部署单元与库（按当前租户拓扑解析）。
3. **寻址结果**：消费方拿到的是「当前租户下该能力的实际访问位置」，不感知服务标识。
4. **失败语义**：第一段缺失即拒启（沿用协同节点口径）；第二段缺失（拓扑未配置）在启动期拒启、运行期报明确错误，不得回落默认服务。

**完成标准**：消费方按两段解析取址，代码中无服务标识与路径字面量；同一能力在两种拓扑下均可正确取址（夹具验证：合并部署与拆分部署各一组）；拓扑缺失时启动拒启、运行期明确报错。
