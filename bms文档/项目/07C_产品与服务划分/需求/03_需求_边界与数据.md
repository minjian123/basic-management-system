# 边界与数据需求

> 07C 产品与服务划分 · 需求域 03：边界与数据（2 条）

## 1. 域说明 <a id="intro"></a>

本域保证「合并的是部署，不是边界」：域级边界护栏与按域的库与迁移口径。

- **依据**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」「数据与库」节。

## 2. 需求 03-1：域级边界护栏 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：现有边界护栏是按「服务进程」断言的：进程隔离时靠 import 边界与独立库，合并部署后这些约束全部失效——同一进程内任何域都能直接 import 他域实现、直接读写他域表。「最小形态」一旦上线，边界就名存实亡。

**内容**：

1. **依赖方向**：跨域访问只经能力契约；域间 import 由护栏静态断言拦截（不依赖进程隔离）。
2. **表归属**：每表唯一归属域；跨域读表按越界处理，由护栏与运行期检查双轨拦截。
3. **事务边界**：单域本地事务、跨域走强一致事务或事件；提供“同一部署单元内跨域写”的显式拒绝用例。
4. **观测标注**：指标、日志、审计按域标注，合并部署后仍可归因。

**完成标准**：护栏按域断言（不按进程）：跨域 import、跨域直接读表均被拦截且有反例用例；合并部署场景（域同进程同库）下反例仍被拦截；跨域写必须走契约或事件，有对应用例。

**参考文档**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」节

## 3. 需求 03-2：库与迁移按域聚合 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：库名与迁移链当前按服务组织；一旦域可拆可合，同一个库里的表集合会随拓扑变化，迁移链若仍按服务组织，拆分时会出现“链对不上、表缺一半”。

**内容**：

1. **库名派生**：库名由部署单元标识派生，不由域派生。
2. **表归属按域**：表前缀体现域；拓扑变更不改变表名。
3. **迁移链聚合**：迁移历史按部署单元聚合，保证任一拓扑下库结构 = 该部署单元所含域的表的并集。
4. **校验**：表归属登记 ↔ 模型 ↔ 迁移链三处一致，由既有校验脚本承接（不新增并行入口）。

**完成标准**：同一套域在「合并」与「拆分」两种拓扑下均可完成建表与迁移，结果一致；表名不随拓扑变化；迁移链聚合口径有文档与用例；三处一致性校验通过。
