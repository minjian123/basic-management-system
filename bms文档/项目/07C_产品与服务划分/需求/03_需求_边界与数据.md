# 边界与数据需求

> 07C 产品与服务划分 · 需求业务域 03：边界与数据（2 条）

[文档首页](../../../文档首页.md) › [产品与服务划分总览](00_需求_产品与服务划分.md) › 边界与数据

## 1. 业务域说明 <a id="intro"></a>

本业务域保证「合并的是部署，不是边界」：业务域级边界护栏与按业务域的库与迁移口径。

- **依据**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」「数据与库」节。

## 2. 需求 03-1：业务域级边界护栏 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：现有边界护栏是按「服务进程」断言的：进程隔离时靠 import 边界与独立库，合并部署后这些约束全部失效——同一进程内任何业务域都能直接 import 他业务域实现、直接读写他业务域表。「最小形态」一旦上线，边界就名存实亡。

**内容**：

1. **依赖方向**：跨业务域访问只经能力契约；业务域间 import 由护栏静态断言拦截（不依赖进程隔离）。
2. **表归属**：每表唯一归属业务域；跨业务域读表按越界处理，由护栏与运行期检查双轨拦截。
3. **事务边界**：单业务域本地事务、跨业务域走强一致事务或事件；提供“同一部署单元内跨业务域写”的显式拒绝用例。
4. **观测标注**：指标、日志、审计按业务域标注，合并部署后仍可归因。

**完成标准**：护栏按业务域断言（不按进程）：跨业务域 import、跨业务域直接读表均被拦截且有反例用例；合并部署场景（业务域同进程同库）下反例仍被拦截；跨业务域写必须走契约或事件，有对应用例。

**参考文档**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」节

## 3. 需求 03-2：库与迁移按业务域聚合 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：库名与迁移链当前按服务组织；一旦业务域可拆可合，同一个库里的表集合会随拓扑变化，迁移链若仍按服务组织，拆分时会出现“链对不上、表缺一半”。

**内容**：

1. **库名派生**：库名由部署单元标识派生，不由业务域派生。
2. **表归属按业务域**：表前缀体现业务域；拓扑变更不改变表名。
3. **迁移链按业务域**：每个业务域一条独立链（业务域内线性、业务域间独立），部署单元运行时执行所含业务域的各链；任一拓扑下库结构 = 所含业务域各链的并集，**拆 / 合不切迁移历史**。
4. **校验**：表归属登记 ↔ 模型 ↔ 迁移链三处一致，由既有校验脚本承接（不新增并行入口）。

**完成标准**：同一套业务域在「合并」与「拆分」两种拓扑下均可完成建表与迁移，结果一致；表名不随拓扑变化；迁移链按业务域的口径有文档与用例（含拆 / 合两种拓扑下链集一致）；三处一致性校验通过。
