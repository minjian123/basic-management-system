## 1. 业务域说明 <a id="intro"></a>

本业务域保证「合并的是部署，不是边界」：业务域级边界护栏与按业务域的库与迁移口径。

- **依据**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」「数据与库」节。

## 2. 需求 03-1：业务域级边界护栏 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：现有边界护栏是按「服务进程」断言的：进程隔离时靠 import 边界与独立库，合并部署后这些约束全部失效——同一进程内任何业务域都能直接 import 他业务域实现、直接读写他业务域表。「最小形态」一旦上线，边界就名存实亡。

**内容**：

1. **依赖方向**：跨业务域访问只经能力契约；业务域间 import 由护栏静态断言拦截（不依赖进程隔离）。
2. **表归属**：每表唯一归属业务域；跨业务域读表按越界处理，由护栏与运行期检查双轨拦截。
3. **事务边界**：单业务域本地事务、跨业务域走强一致事务或事件；提供“同一部署单元内跨业务域写”的显式拒绝用例。
4. **观测标注**：指标、日志、审计按业务域标注，合并部署后仍可归因。

**完成标准**：护栏按业务域断言（不按进程）：跨业务域 import、跨业务域直接读表均被拦截且有反例用例；合并部署场景（业务域同进程同库）下反例仍被拦截；跨业务域写必须走契约或事件，有对应用例。

**参考文档**：《[架构设计 · 产品与服务划分](../../../设计/架构设计/39_架构设计_子系统_产品与服务划分.md)》「边界纪律」节

## 3. 需求 03-2：库与迁移按业务域聚合 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：库名与表结构变更清单当前按服务组织；一旦业务域可拆可合，同一个库里的表集合会随拓扑变化，表结构变更清单若仍按服务组织，拆分时会出现“链对不上、表缺一半”。

**内容**：

1. **库名派生**：库名由部署单元标识派生，不由业务域派生。
2. **表归属按业务域**：表前缀体现业务域；拓扑变更不改变表名。
3. **表结构变更清单按业务域**：每个业务域一条独立清单（清单内线性、清单间独立、各自独立一张版本记录表），部署单元运行时执行所含业务域的各清单；任一拓扑下库结构 = 所含业务域各清单的并集，**拆 / 合不切迁移历史**。
4. **校验**：表归属登记 ↔ 模型 ↔ 表结构变更清单三处一致，由既有校验脚本承接（不新增并行入口）。

**完成标准**：同一套业务域在「合并」与「拆分」两种拓扑下均可完成建表与迁移，结果一致；表名不随拓扑变化；表结构变更清单按业务域的口径有文档与用例（含拆 / 合两种拓扑下清单集一致）；三处一致性校验通过。

## 4. 需求 03-3：域间出口 DTO 化 <a id="r03-3"></a>

优先级：2（高）

**背景与动机**：`03_03` 交付后「每业务域 1 个 `public.py`」让 D1 真正生效，但**出口导出的是实现**——ORM 模型、仓储、服务类。消费方拿到的是可变 ORM 对象：能直接改字段、按关系懒加载遍历、绕过域内校验规则。合并部署下这与「直接读写他业务域的表」等价，只是换了形式，边界在数据面仍形同虚设；同时出口形状与能力契约（`path` + 响应模型）是两套，跨域调用改一处漏一处。`02_02` 已交付进程内直调，跨域数据契约缺一个稳定落点，DTO 化正是这个落点。

**内容**：

1. **出口形态**：业务域 `public.py` 只暴露**基座不可变对象**（`BaseValueObject` 派生的 DTO）；不导出 ORM 模型、仓储、可变服务对象。
2. **契约对齐**：出口 DTO 字段与能力契约的响应模型一致；消费方按字段取值，不遍历模型关系、不依赖懒加载。
3. **装配约束**：跨域依赖只在装配面（`wiring.py`）注入；消费方只持 DTO 与领域服务接口，不持模型会话。
4. **机器护栏**：静态断言 `public.py` 不得导出 `MODEL_MODULES` 内的 ORM 类与仓储类（例外白名单 + 递减基线，条目只减不增）。
5. **渐进迁移**：按业务域逐个迁——先低消费试点域，再高消费域（组织 / 角色）；每步保持行为等价（回归用例零差异）。

**完成标准**：出口护栏可机器判定（红 / 绿用例齐备，基线条目只减不增）；试点域与一个高消费域的出口完成 DTO 化且消费方无 ORM 依赖（护栏零命中）；出口对象冻结不可变（改动即抛，用例断言）；出口 DTO 与能力契约响应字段一致（对账用例）；已迁 / 待迁清单登记，剩余域在计划偏差列跟踪。
