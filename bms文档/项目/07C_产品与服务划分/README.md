## 立项背景（2026-10-24） <a id="background"></a>

07B 解决了「业务域之间怎么连」，但「业务域怎么分、业务域怎么组合成部署单元与库」一直是混用状态：产品指独立仓库与发版单元，服务指部署单元，领域边界从未单独表达。结果是平台侧出现巨型服务（单服务容纳用户 / 角色 / 租户 / 菜单 / 权限元数据 / 参数 / 图标），产品侧出现单服务多业务域；而不同租户的业务重心差异（采购重 / 仓储重 / 销售重 / 全面重）无法用同一套拆分满足。

本专项以「**业务域稳定、部署单元可变**」为原则：同一套业务域模型，最小可单库单进程运行，极端可一租户一业务域一服务一库；拓扑按租户配置、平台记录、发布时生效。并明确「合并的是部署，不是边界」——业务域级边界护栏不依赖进程隔离。

## 边界 <a id="scope"></a>

- **范围内**：业务域划分判据与目标业务域清单、部署拓扑语义与租户拓扑机制、能力两段解析对接、业务域级边界护栏、库与迁移按业务域聚合、发布与版本对账、拓扑迁移、专项验收。
- **范围外**：能力契约与分配授权（归 07B / 架构 38）、服务调用机制与强一致事务（归架构 37）、部署编排实现细节（归架构 33 与详细设计）、产品业务功能本身。
