## 5. 复盘与经验教训 <a id="retro"></a>

| # | 经验 / 教训（已发生的事实） | 已固化的改进项 |
| --- | --- | --- |
| 1 | **机制就位不等于可用**：本阶段以「首个样例真跑通」为判定，`04_01` 用真实形态页面把「注册 → 独立构建 → 运行时加载 → 独立发布 / 回滚」整条链跑通，暴露菜单装配泛化、`element-plus` 分包、`#TYPE-001` 类型声明等一处登记不完就断链的集成缺口 | 样例先行 + 接入指南落知识档案《微前端》专题；模块契约 §7 接入检查项 |
| 2 | **隔离护栏要按模块泛化**：`guard:isolation` 首版对「全量模块」扫描，第二个模块接入即误报（流水线 #310 失败） | 修复为 `--module .` 只扫自身并纳入 `module-build`；护栏口径随模块数量泛化 |
| 3 | **共享面收窄是实测结论而非拍脑袋**：朴素共享 `element-plus` 把整库拉入首屏（660.7 KB），`eager:false` + `treeShaking runtime-infer` 启动仍异步拉取约 433 KB（指标失真） | 共享面锁定为**框架三件**（`vue` / `vue-router` / `pinia`）；`element-plus` 与基座包登记为**受控非共享项**（受控实测 + 机制判定），需求措辞同步回写 |
| 4 | **回滚要真跑一次**：02_02 / 03_02 / 04_01 真跑发布回滚演练（0.1.0 → 0.2.0 → 回滚 0.1.0），发现「回滚后源码 / 清单版本可不一致」的护栏提示 | 流程要点写入《部署发布规范》「模块发布与回滚」节（回滚后须同步处理源码版本） |
| 5 | **微前端两个反直觉行为踩过一次**：`app.use(router)` 即触发初始导航 → 路由安装须在模块装载之后（否则首屏直连模块路由落 404）；MF 插件在 Vitest 下自动空转 → 宿主用例须 `vi.mock('@module-federation/runtime')` | 已写入工程文档与门禁口述（本报告 §5 与《微前端》接入指南） |
| 6 | **覆盖率门禁口径不统一留下收口限定项**：模块工程只有 `typecheck` / `lint` / `test` + 产物断言，无覆盖率门槛 | 登记计划 §7 第 4 项（随《测试规范》前端门槛统一），并在门禁结论第 5 行以「（限定：…）」注明，不掩盖 |
