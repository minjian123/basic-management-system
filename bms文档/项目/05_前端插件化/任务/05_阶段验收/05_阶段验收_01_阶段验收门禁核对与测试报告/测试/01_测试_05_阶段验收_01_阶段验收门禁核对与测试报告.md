## 4. 问题与处置 <a id="issues"></a>

| 1 | 计划 §5 门禁表原为「达成路径」表述，无结论列，无法直接判读达标情况 | 用例编写 | 按决策项 3 内联结论与证据索引（`**达标（2026-09-24）**：…`）+ 新增里程碑对照表，表列结构不变 |

| 3 | 计划头部无「已完成 N 项，剩余 M 项」、工时行非校验形态 | 用例编写 | 规范化为标准形态（决策项 8）；`check-status` S1 的子校验自本任务起对阶段五生效 |
| 4 | 报告首跑前 `test_stage_report_archived_with_sections` 必红（报告未落盘） | 用例首跑 | 报告落盘后复跑通过；该断言对「报告归档」动作有效 |
| 5 | 阶段窗口 5 条 failed 流水线的归属需可复核 | 报告撰写 | 逐条经 GitLab API 取失败岗位与提交标题，按「窗口 + 状态分布 + 失败岗位」如实记录 |

## 5. 覆盖率 <a id="coverage"></a>

- 本任务**无生产代码改动**，只新增 1 个收口断言用例文件（`test_m5_closure.py`）；前端产物以「现场门禁重跑」口径记录，覆盖率快照如下：
  - 宿主（`frontend/apps/desktop`）：语句 **89.71%** / 分支 **76.39%** / 函数 **84.69%** / 行 **90.02%**（阈值 70%）；
  - 核心包（`packages/core` / `vue` / `ui-ep`）：不采覆盖率（包门禁为 typecheck + lint + test）；
  - 模块工程（`frontend/modules/*`）：**覆盖率门禁未启用**（计划 §7 第 4 项）；
  - 平台脚本：以 fixture + 临时工作区 / 端到端演练成对验证，不采覆盖率。
- 后端无本阶段代码改动，全量口径沿用[阶段二阶段测试报告](../../../../../02_后端基座与服务化地基/01_测试报告_后端基座与服务化地基.md)（1341 passed / 37 skipped、全量语句 95% / 分支 93%），本任务叠加 4 条收口断言用例后为 1345 passed / 37 skipped。

## 6. 偏差与遗留 <a id="deviations"></a>

- 同[实施记录 §6](../实施/01_实施_05_阶段验收_01_阶段验收门禁核对与测试报告.md#deviations)（设计偏差 1 处：`bms/README.md` 阶段五状态行同步；口径说明：后端重负载与生产部署形态不现场重跑；新增遗留 1 项：历史自动缺陷单）。
- 用例反向有效性：`test_gate_table_has_conclusions_and_evidence` 在门禁表仅有「达成路径」无结论、且需求总览仍挂表时**必然失败**；`test_plan_closure_state` 的「剩余 0 / 甘特里程碑 / 工时行可校验 / §7 台账存在」四项断言在收口前同样必红——断言对收口动作有效。
- 外部证据（流水线号、缺陷单状态）由 GitLab 承载，可经项目 2 的 API 复核（编号见[阶段测试报告 附录 A](../../../../01_测试报告_前端插件化.md#appendix)）。
