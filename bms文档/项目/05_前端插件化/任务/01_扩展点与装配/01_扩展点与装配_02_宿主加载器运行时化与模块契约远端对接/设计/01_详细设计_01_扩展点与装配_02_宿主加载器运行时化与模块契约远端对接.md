## 1. 设计目标与范围 <a id="goal"></a>

在阶段四「宿主薄壳与模块加载器接口」（[10_01](../../../../../04_前端组件库/任务/10_微前端骨架/10_微前端骨架_01_宿主外壳与模块加载器/10_微前端骨架_01_宿主外壳与模块加载器.md)）与本域 [01_01](../../01_扩展点与装配_01_扩展点注册表补齐与统一装配/01_扩展点与装配_01_扩展点注册表补齐与统一装配.md)（**两者前置契约均已交付**）之上：

1. **加载器运行时化**——宿主加载器由「本地定义表（静态 `import`）」升级为「按模块清单加载」：清单驱动 → 注入上下文 → 执行注册声明 → 挂载 → 卸载；**`ModuleLoader` 接口不变**（同接口换实现通路）；
2. **模块清单与版本字段**——清单（名称 / 入口 / 版本）外置为宿主 `modules.json`，启动期获取；缺字段 / 版本不匹配 / 加载失败**一律拒绝加载**并成文；
3. **注入上下文与只读约束**——宿主注入 router / Pinia / i18n / 用户 / 租户，注入前冻结为只读快照；`token` 不入上下文；模块上下文类型**收敛为单一契约**；
4. **注册声明校验与补齐**——八类声明通道补齐（新增字段渲染器声明通道），统一校验（唯一性 / 路径前缀 / 命名空间），注册与卸载清理成对；**渲染消费接线**（区域插槽渲染 / 令牌注入 `--bms-*` / 模块文案并入宿主 i18n）在本任务落地，挂载即生效、卸载即还原；
5. **演示验证**——演示模块彻底改由清单加载，验证「加载 → 注册 → 挂载 → 卸载」全链路（不进生产菜单）。

**不在本期**：Module Federation 接入与模块独立构建（`02_01`）、`shared` 依赖共享（`02_02`）、样式与运行时沙箱隔离（`03_01`）、清单唯一来源与发布 / 回滚治理（`03_02`）、按模块可观测（`03_03`）、样例模块的独立发布（`04_01`）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 模块清单契约与解析 <a id="manifest"></a>

清单为**发布产物**（宿主 `public/modules.json`，随部署替换，改清单不必重构建），落 `core/src/module/manifest.ts`（框架无关、核心可测）：

```ts
/** 模块清单项（宿主 `modules.json` 条目）。 */
export interface ModuleManifestEntry {
  /** 模块名（`MODULE_NAME_PATTERN`）。 */
  name: string
  /** 入口标识（本任务为模块源码标识，`02_01` 起为远端入口 URL）。 */
  entry: string
  /** 版本（与模块自报 `manifest.version` 严格相等）。 */
  version: string
}

/** 清单项被拒原因。 */
export interface ModuleManifestRejection {
  /** 模块名（缺名时为空串）。 */
  name: string
  /** 拒绝原因。 */
  reason: string
}

/** 解析模块清单（整份形态非法即抛错；单项非法逐项拒绝，不影响其余项）。 */
export function parseModuleManifest(raw: unknown): {
  entries: ModuleManifestEntry[]
  rejected: ModuleManifestRejection[]
}
```

| 校验 | 口径 | 处置 |
| --- | --- | --- |
| 整份形态 | 须为数组 | 非数组 / `null` → 抛 `BaseError(CAPABILITY_VIOLATION)`（宿主捕获为「空清单 + 错误状态」） |
| 单项字段 | `name` / `entry` / `version` **三字段齐全且非空**（`name` 另须合 `MODULE_NAME_PATTERN`） | 缺字段该项**拒绝加载**并记入 `rejected` |
| 单项重名 | 同一 `name` 出现多次（前项**校验通过**） | 保留先通过项，后续项拒绝（对齐注册表「同名拒重」语义）；前项自身被拒时不影响后续同名项 |

### 3.2 清单驱动加载器 <a id="loader"></a>

`ModuleLoader` 接口**不变**（仅 `load` 增可选 `context`，兼容既有实现）：

```ts
/** 模块加载器接口（阶段五远端加载按同一接口实现）。 */
export interface ModuleLoader {
  /** 按模块名加载（返回清单与注册声明，不挂载）。 */
  load(name: string, context?: ModuleHostContext): Promise<LoadedModule>
  mount(loaded: LoadedModule): void
  unmount(name: string): void
  isMounted(name: string): boolean
  mountedNames(): string[]
}
```

新增实现（`core/src/module/loader.ts`；`LocalModuleLoader` 保留——构建期合并形态与既有用例继续使用）：

```ts
/** 模块入口模块（默认导出模块定义）。 */
export interface ModuleEntryModule {
  /** 默认导出（`defineModule` 产物）。 */
  default?: unknown
}

/** 模块入口懒加载表（模块标识 → 入口加载器）。 */
export type ModuleEntryTable = Record<string, () => Promise<ModuleEntryModule>>

/** 清单驱动加载器（宿主运行期实现；入口经懒加载表解析）。 */
export class ManifestModuleLoader implements ModuleLoader {
  constructor(entries: readonly ModuleManifestEntry[], table: ModuleEntryTable)
}
```

`load(name, context)` 执行序与校验（任一校验不过即**拒绝加载**、抛错、不挂载）：

| 步 | 动作 | 失败处置 |
| --- | --- | --- |
| 1 | 查清单条目（按名） | 无 → `BaseError(PROVIDER_NOT_REGISTERED)` |
| 2 | 查入口懒加载表（按 `entry`） | 无 → `BaseError(PROVIDER_NOT_REGISTERED)`（入口未登记） |
| 3 | 动态 `import` 入口 | 异常 → 原样上抛（宿主记错误状态） |
| 4 | 取入口**默认导出**并校验为模块定义形状（`manifest` + `setup`） | 缺默认导出 / 形状非法 → `BaseError(CAPABILITY_VIOLATION)` |
| 5 | **清单 ↔ 模块自报一致性**：`manifest.name` 与清单 `name` 一致、`manifest.version` 与清单 `version` **严格相等** | 不一致 → `BaseError(CAPABILITY_VIOLATION)`（发布错位立即暴露） |
| 6 | 冻结上下文快照后调 `setup`：`Object.freeze({ ...context })` | `setup` 抛错 → 原样上抛（宿主记错误状态） |
| 7 | 返回 `LoadedModule`（`manifest` 以清单为准补 `entry`） | — |

- **挂载 / 卸载**语义沿用阶段四：`mount` 同名拒重（`REGISTRY_CONFLICT`）、`unmount` 幂等、`mountedNames()` 保挂载序。
- **不隐式回退**：加载器只认清单——清单缺失 / 入口缺失一律拒绝，不做「按约定猜路径」的兜底（对齐计划风险对策「加载器只认清单，不做隐式回退」）。

### 3.3 注入上下文与只读约束 <a id="context"></a>

| 项 | 口径 |
| --- | --- |
| 注入项 | `router` / `store`（Pinia）/ `i18n`（模块文案承载）/ `user` / `tenant`；**`token` 不入上下文**（不注入、模块不得读取与持久化） |
| 类型收敛 | 删除 `capabilities/module-context.ts` 内与 `module/types.ts` 同形的 `ModuleContext`；`BaseModuleContext` 直接消费 `ModuleHostContext`，`ModuleContextKey = keyof ModuleHostContext` |
| 只读实现 | 宿主与加载器在注入前 `Object.freeze({ ...context })` 冻结**快照**；实例本体（router / store）不冻结，其只读以契约成文 + 机器护栏（`token` 不入上下文、模块不写全局）保障 |
| 缺失项 | 以 `undefined` 呈现，模块自行降级（不假定存在）；`BaseModuleContext.inject()` 缺省空对象 → 空快照 |

### 3.4 注册声明补齐与校验 <a id="registration"></a>

`core/src/module/types.ts` 增字段渲染器声明（结构声明，不引入 provider 实例）：

```ts
/** 模块字段渲染器声明。 */
export interface ModuleFieldRendererDeclaration {
  /** 命名空间键（`<模块名>:<键>`）。 */
  key: string
  /** 渲染组件（组件对象或懒加载器）。 */
  component: unknown
  /** 字段类型（供 `resolveByType` 解析）。 */
  fieldType?: string
}
```

`ModuleRegistration` 增 `fieldRenderers?: ModuleFieldRendererDeclaration[]`；统一装配器 `buildPlan` / `registerEntry` / `releaseRegistrations` 增 `fieldRenderer` 分组（校验同其余命名空间域：键模式 + `<来源>:` 前缀；登记键 `fieldRenderer:<键>`）。至此**八类注册声明通道与八类注册表完全对齐**。

路由·菜单装配补图标：`RouteMenuProvider` 构造时从 `route.meta.icon` 取图标（缺省 `undefined`），供菜单派生直接消费，不再由宿主硬编码。

### 3.5 渲染消费接线 <a id="consume"></a>

三处「注册了但无消费」在本任务接线，**挂载即生效、卸载即还原**：

| 面 | 机制落点（core） | 装配落点（宿主） | 生效 / 还原 |
| --- | --- | --- | --- |
| 令牌注入 | `core/src/module/theme-tokens.ts`：`collectThemeTokens(registry, { mode? })` 汇聚已登记令牌、`applyThemeTokens(target, tokens)` 返回已写入令牌名、`releaseThemeTokens(target, names)` 逆序还原；`ThemeTokenTarget`（`setToken` / `removeToken`）由宿主注入——**核心不触 DOM** | `apps/desktop/src/module/themeTokens.ts`：以 `documentElement.style.setProperty / removeProperty` 实现 `ThemeTokenTarget` | 挂载写 `--bms-*`；卸载按名移除（回到宿主权威值） |
| 模块文案并入 | `core/src/module/i18n-packs.ts`：`ModuleMessageStore`（`merge(packs)` 返回并入键、`restore(keys)` 逆序还原且幂等、`translate(key, locale?)` 未命中返回 `undefined`、`messagesOf(locale)` / `locales()`；语言标识小写归一，缺省语言 `zh-cn`） | `apps/desktop/src/module/i18n.ts`：宿主单例 `moduleI18n`，经 `context.i18n` 注入模块 | 挂载并入；卸载还原（不跨来源合并、不替调用方兜底） |
| 区域插槽渲染 | — | `ui-ep` 组件「模块区域插槽」（见 3.8）+ 宿主布局插槽接线 | 组件按区域标识读注册表渲染；卸载后注册表清空 → 区域内容消失 |

- 宿主以**装配版本号**（`registriesRevision`，装配 / 释放后自增）通知视图重算，避免非响应式注册表实例造成视图不更新。
- 阶段定位：本任务只落**宿主级接线**（区域渲染、令牌注入、文案并入）；页面级消费与语言切换 UI 归全页面 / 国际化阶段，届时 `moduleI18n` 内部实现替换为 vue-i18n 适配（`mergeLocaleMessage` / `removeLocaleMessage`），**对外接口不变**。

### 3.6 宿主装配与启动时序 <a id="host"></a>

`apps/desktop/src/module/host.ts` 对外面（接口名保持与阶段四一致，仅实现通路替换）：

```ts
/** 清单装载与逐条挂载（启动期调用一次）。 */
export function installModules(context: ModuleHostContext): Promise<ModuleInstallSummary>

/** 加载并挂载模块（按模块名注册路由、扩展点与渲染消费接线）。 */
export function mountModule(name: string, context?: ModuleHostContext): Promise<LoadedModule>

/** 卸载模块（逆序：路由 → 文案 → 令牌 → 注册表 → 加载器；幂等）。 */
export function unmountModule(name: string): void

/** 平台自身注册（启动期；与模块注册共用同一通道）。 */
export function installPlatformRegistrations(): RegistrationKey[]

/** 菜单节点（**取自路由·菜单注册表快照**，保序）。 */
export function moduleMenuNodes(): MenuNode[]

/** 当前加载器（清单装载后可用）。 */
export function getModuleLoader(): ManifestModuleLoader | undefined

/** 装配版本号（装配 / 释放后自增，供视图重算）。 */
export const registriesRevision: Ref<number>

/** 清单装载结果汇总（成功项 / 失败项与原因）。 */
export interface ModuleInstallSummary {
  mounted: string[]
  failures: { name: string; version: string; reason: string }[]
}
```

`installModules` 时序：**获取清单 → 构造加载器 → 逐条挂载 → 归集失败**。

| 场景 | 处置 |
| --- | --- |
| 清单获取失败（网络 / 404 / JSON 非法 / 非数组） | **不阻塞启动**：记错误状态（带原因）、按**空清单**继续，平台页面照常渲染 |
| 单项缺字段 / 重名 | 该项不加载（解析期已拒），其余项照常 |
| 单项加载失败（入口缺失 / 版本不匹配 / 依赖模块失败 / `setup` 抛错） | `setModuleError`（带模块名与版本）→ 该项**不挂载**、菜单无该项，**回滚该项已产生的接线**，继续下一项 |
| 全部成功 | 应用挂载后首屏即可命中模块路由（延续「模块挂载先于 `app.mount`」口径） |

`main.ts` 时序：

```text
applyInitialTheme()  →  installMenuRoutes(占位菜单)  →  installPlatformRegistrations()
→  createApp / pinia / router  →  await installModules(context)  →  app.mount('#app')
```

```json

```

// apps/desktop/src/module/entries.ts —— 入口懒加载表（Vite 自动分包）

演示模块入口改为默认导出模块定义（`export default demoModule`），与负载器「取入口默认导出」口径一致。

### 3.7 菜单来源收敛 <a id="menu"></a>

- 菜单节点**只从路由·菜单注册表快照派生**（`path` / `title` / `icon` / 路由名），不再读加载结果；卸载后注册表清空 → 菜单自动消失，无两套来源不一致风险；
- 演示模块分组仍**仅开发态**出现（`import.meta.env.DEV`），不进入生产菜单。

### 3.8 新增组件「模块区域插槽」 <a id="component"></a>

| 项 | 内容 |
| --- | --- |
| 职责与边界 | 按**区域标识**把注册表中该区域的模块项渲染到宿主布局对应位置；**只读注册表**，不做区域兜底、不做排序裁定（按登记的 `order` 保序）；空区域渲染为空 |
| 语义与契约 | 输入：区域标识 + 注册表集合 + 装配版本号；输出：该区域全部注册项（保序），逐项以 `component` 渲染（组件对象直接用；懒加载器经异步组件包装）；未命中区域 → 空 |
| 继承链 | 按用途归**布局组件类**，主链**布局组件基类**（`BaseLayout`）+ **容器语义复用容器组件基类**（`BaseContainer`，内容承载与插槽）——与「主框架布局壳」同口径；ui-ep 侧经投影组合式 `useModuleArea`（承接既有布局与容器投影）挂链，组件不内联链上类 |
| 落点 | `ui-ep/src/components/layout/ModuleAreaOutlet.vue`、`ui-ep/src/composables/useModuleArea.ts`；组件设计节点 `组件设计/03_布局组件类/12_组件设计_模块区域插槽/`（含可交互原型），组件设计总览 §5 路线图登记 |
| 约束 | `<style>` 一律 `scoped`、样式只消费 `--bms-*` 令牌；不直用浏览器能力与第三方库（ui-ep 单一落点护栏）；文案键遵循《命名规范》 |
| 宿主接线 | `App.vue` 在 `MainLayout` 的 `header-right` 插槽内以 `area="layout.header"` 渲染该组件（演示模块的 `demo:hero` 据此可见） |

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 | 错误码 |
| --- | --- | --- |
| 清单整份形态非法（非数组 / 解析失败） | 宿主记错误状态 + 空清单继续（**不阻塞启动**） | `CAPABILITY_VIOLATION`（清单层） |
| 清单项缺 `name` / `entry` / `version` | 该项拒绝加载并记入 `rejected` | — |
| 清单项重名 | 保留首项，后续项拒绝 | — |
| 清单名为空 / 未登记 | 加载拒绝 | `PROVIDER_NOT_REGISTERED` |
| 入口标识不在懒加载表 | 加载拒绝（入口未登记） | `PROVIDER_NOT_REGISTERED` |
| 入口缺默认导出 / 非模块定义形状 | 加载拒绝 | `CAPABILITY_VIOLATION` |
| 清单版本与模块自报版本不一致 | 加载拒绝（发布错位） | `CAPABILITY_VIOLATION` |
| 入口动态 `import` 失败（网络 / 404 / 语法） | 加载拒绝 + 错误边界兜底（带模块名与版本） | 原始错误上抛 |
| `setup` 抛错 | 同上 | 原始错误上抛 |
| 同名模块重复挂载 | 拒重 | `REGISTRY_CONFLICT` |
| 卸载未挂载模块 | 幂等无副作用 | — |
| 模块注册键越权（无 `<模块名>:` 前缀）/ 键非法 | 装配拒绝，**零登记** | `CAPABILITY_VIOLATION` |
| 装配倒入途中同键冲突 | 回滚本次已登记项后抛错（无残留） | `REGISTRY_CONFLICT` |
| 挂载第 5 步（渲染消费接线）失败 | 回滚本次已产生的路由 / 注册项 / 令牌 / 文案，再上抛 | 原始错误上抛 |
| 区域未登记任何项 | 区域渲染为空（空插槽）——**不替调用方兜底** | — |
| 令牌 / 文案名在注册表中未命中 | 不写入 / 返回 `undefined`（文案未命中不返回键本身） | — |
| 卸载时令牌已被外部改动 | 按名 `removeProperty` 移除（回到宿主权威值，不恢复旧值） | — |

## 7. 边界与开放项 <a id="open"></a>

- **远端入口形态**：本任务 `entry` 语义为**模块源码标识**（懒加载表键），`02_01` 起同一字段承载远端入口 URL（Module Federation container），加载器实现替换、接口与清单结构不变；
- **清单治理**：清单唯一来源、版本发现、灰度 / 回滚归 `03_02`（本任务只做「获取 + 严格解析 + 拒绝口径」）；
- **`shared` 依赖共享**与模块独立构建归 `02_01` / `02_02`；
- **文案并入的最终消费**：宿主 i18n 尚未引入 vue-i18n（归国际化阶段）；本任务 `moduleI18n` 为轻量承载，后续以适配层替换内部实现；
- **令牌注入模式维度**：`mode` 仅作检索标注，本任务注入时按登记序合并（不区分模式），模式化切换随主题 / 品牌化阶段；
- **`LocalModuleLoader` 保留**：供构建期合并形态与既有用例使用，非运行期通路；其去留随 `02_01` 评估。
