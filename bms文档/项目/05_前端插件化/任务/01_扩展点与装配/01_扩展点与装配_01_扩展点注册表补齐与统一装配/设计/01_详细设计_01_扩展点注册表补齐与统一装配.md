## 1. 设计目标与范围 <a id="goal"></a>

在阶段四「统一注册表基座 + 五类注册表最小实现」（[10_02](../../../../../04_前端组件库/任务/10_微前端骨架/10_微前端骨架_02_模块契约与注册表基座/10_微前端骨架_02_模块契约与注册表基座.md)，**前置契约已交付**）之上：

1. **补齐八类扩展点注册表**——新增**页面区域**与**主题令牌**两类，与既有五类（路由·菜单 / 通用组件 / 字段渲染器 / 图标 / 工作台卡片）合为八类，一律基于统一注册表基座与注册项公共契约，不另起映射；
2. **统一装配**——平台自身注册与模块注册**走同一通道**：核心提供统一装配器（按来源打标、逐项倒入、登记键清单供卸载清理），宿主只做接线；装配时序为**平台自身注册（启动期）→ 模块注册（挂载期）**，同一入口同步执行；
3. **注册契约与校验**——同键唯一性拒重（基座支持严格 / 宽和两档，八类当前一律**严格**）、未命中返回空（不替各域裁决兜底）、遍历保序、只读快照；模块注册项额外做**命名空间校验**（防覆盖平台项）；
4. **「不注册不可用」护栏**——机器护栏断言「随包 / 随模块引入但未登记」的项不可解析，并配 fixture 拦截；
5. **契约文档化**——八类扩展点的注册声明字段、键命名与冲突处置成文，并被样例模块实际使用。

**不在本期**：宿主渲染消费接线（区域插槽渲染 / 主题令牌注入）——随 `01_02` 与全页面阶段接入；隔离增强、版本协商、清单治理、按模块观测（后续任务）。

### 1.1 现状与缺口 <a id="gap"></a>

```text
frontend/
├── packages/core/src/
│   ├── mechanisms/
│   │   ├── registry.ts                  # BaseProviderRegistry（唯一性拒重 / 保序 / 快照）   ← 本期加「严格·宽和」档
│   │   └── provider.ts                  # BaseProvider（注册项公共契约）                  ← 本期加 source 字段
│   ├── module/
│   │   └── types.ts                     # ModuleRegistration（routes/components/icons/cards）← 本期加 regions/themeTokens
│   └── registries/
│       ├── providers.ts                 # 5 注册项（路由·菜单 / 组件 / 字段渲染器 / 图标 / 卡片）← 本期 +2
│       ├── validate.ts                  # schemaError（组合校验文案）
│       ├── index.ts                     # 5 注册表 + createRegistries()                    ← 本期 +2 并入八类
│       └── assemble.ts                  # （本期新增）统一装配器
└── apps/desktop/src/module/
    ├── registries.ts                    # 注册表实例 + applyModuleRegistration（宿主私有）  ← 收敛
    └── host.ts                          # 模块挂载 / 卸载 + 注册倒入与清理                  ← 改走核心装配器
```

缺口：① 页面区域与主题令牌无注册表，模块无法按契约挂接；② 装配逻辑落宿主、平台自身注册无通道；③ 注册项无来源、冲突排查无法归因；④ 「不注册不可用」无机器护栏。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 八类扩展点与键规则 <a id="extension-points"></a>

| # | 扩展点 | 注册表 | 注册项 | 键规则 | 解析 |
| --- | --- | --- | --- | --- | --- |
| 1 | 路由·菜单 | `RouteMenuRegistry` | `RouteMenuProvider(key, path, title, icon?)` | 键 = 路由名；`path` 须以 `/` 开头 | `get(路由名)` |
| 2 | 页面区域 | `PageAreaRegistry` | `PageAreaProvider(key, area, component, order?)` | **命名空间键** `<来源>:<区域项>`；`area` 为**点分区域标识** | `get(key)`／`resolveByArea(area)` |
| 3 | 通用组件 | `ComponentRegistry` | `ComponentProvider(key, component)` | 命名空间键（kebab） | `get(key)` |
| 4 | 字段渲染器 | `FieldRendererRegistry` | `FieldRendererProvider(key, component, fieldType?)` | 命名空间键 | `get(key)`／`resolveByType(fieldType)` |
| 5 | 图标 | `IconRegistry` | `IconProvider(key, source, options?)` | icon key（`前缀:段`，段允许大小写 / 数字 / `._-`） | `get`／`resolve`／`byPrefix`／`search` |
| 6 | 工作台卡片 | `WorkbenchCardRegistry` | `WorkbenchCardProvider(key, component, title?)` | 命名空间键 | `get(key)` |
| 7 | 主题令牌 | `ThemeTokenRegistry` | `ThemeTokenProvider(key, tokens, mode?)` | **命名空间键** `<命名空间>:<主题标识>` | `get(key)`／`resolve(key)`／`byMode(mode)` |
| 8 | 通用提供者（能力域） | `CapabilityRegistry` 及能力域注册表 | 各域注册项（继承 `BaseProvider`） | 各域自定 | 各域自定 |

- **键模式**：命名空间键沿用 `REGISTRY_KEY_PATTERN = ^[a-z][a-z0-9-]*:[a-z][a-z0-9-]*$`（页面区域 / 主题令牌与既有四类同口径，不引入第二套键形态）。
- **页面区域标识**：`PAGE_AREA_ID_PATTERN = ^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*)+$`（点分，如 `layout.header`、`form.toolbar`）；**不设白名单**——未知区域解析为空列表（不替各域裁决兜底）。
- **主题令牌载荷**：`tokens: Record<string, string>`（`--bms-*` 变量名 → 值）+ 可选 `mode`（`light` / `dark` / 品牌标识等自由标注，仅作检索维度）。
- **来源类型**：`RegistrationSource` = `'platform'` 或模块名（`MODULE_NAME_PATTERN`）；注册项持 `source`，供排查与归因。

### 3.2 统一装配器 <a id="assembler"></a>

落点 `core/src/registries/assemble.ts`（框架无关、核心可测）：

```ts
/** 统一装配的注册声明（平台自身注册与模块注册同一形状）。 */
export type RegistryRegistration = ModuleRegistration

/** 装配结果：登记键清单（`<分组>:<键>`，供卸载清理）。 */
export type RegistrationKey = string

/** 统一装配（平台自身注册与模块注册共用）。 */
export function assembleRegistrations(
  registries: FrontendRegistries,
  source: RegistrationSource,
  registration: RegistryRegistration,
): RegistrationKey[]

/** 逆序释放已登记键（幂等）。 */
export function releaseRegistrations(registries: FrontendRegistries, keys: readonly RegistrationKey[]): void
```

装配规则：

| 分组 | 声明字段 | 校验 | 登记键格式 |
| --- | --- | --- | --- |
| `component` | `components?: Record<string, unknown>` | 键须为命名空间键；来源非 `platform` 时须以 `<来源>:` 开头 | `component:<键>` |
| `icon` | `icons?: Record<string, unknown>` | 同上（icon key 另经 `assertIconKey`） | `icon:<键>` |
| `card` | `cards?: readonly WorkbenchCardProvider[]` | 键须为命名空间键 + 前缀校验 | `card:<键>` |
| `region` | `regions?: readonly ModuleRegionDeclaration[]` | 键须为命名空间键 + 前缀校验；`area` 须为点分标识 | `region:<键>` |
| `themeToken` | `themeTokens?: readonly ModuleThemeTokenDeclaration[]` | 键须为命名空间键 + 前缀校验 | `themeToken:<键>` |
| `route` | `routes?: readonly ModuleRouteDeclaration[]` | 路径须以 `/` 开头；无 `meta.title` 不登记菜单项 | `route:<路由名>` |

- **平台自身注册**（`source === 'platform'`）：**不强制**前缀，键仍须为合法命名空间键（平台域作命名空间，如 `layout:header-actions`）；
- **模块注册**（`source === 模块名`）：**强制** `<模块名>:` 前缀，越权即抛 `BaseError(CAPABILITY_VIOLATION)`——这是「防覆盖平台项」的落点；
- **来源打标**：登记前统一写 `provider.source = source`；
- **时序**：平台自身注册在应用启动期执行、模块注册在模块挂载期执行，两者均走 `assembleRegistrations` 同一入口、同步执行；
- **卸载**：`releaseRegistrations` 按登记键**逆序**注销（后登记先注销）。

### 3.4 模块注册声明扩展 <a id="module"></a>

`core/src/module/types.ts`：`ModuleRegistration` 增两字段（结构声明，不引入 provider 实例，保持契约自包含）：

```ts
/** 模块页面区域声明。 */
export interface ModuleRegionDeclaration {
  /** 命名空间键（`<模块名>:<区域项>`）。 */
  key: string
  /** 区域标识（点分，如 `layout.header`）。 */
  area: string
  /** 挂接组件。 */
  component: unknown
  /** 同区域排序提示（缺省 0）。 */
  order?: number
}

/** 模块主题令牌声明。 */
export interface ModuleThemeTokenDeclaration {
  /** 命名空间键（`<模块名>:<主题标识>`）。 */
  key: string
  /** 令牌映射（`--bms-*` 变量 → 值）。 */
  tokens: Record<string, string>
  /** 模式标注（`light` / `dark` / 品牌标识等）。 */
  mode?: string
}
```

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 | 错误码 |
| --- | --- | --- |
| 同键重复注册（八类当前全严格） | 注册表拒重、不静默覆盖 | `REGISTRY_CONFLICT`（10003） |
| 键无命名空间 / 命名空间非法 | 抛错 | `CAPABILITY_VIOLATION`（10001） |
| 模块注册项键不以 `<模块名>:` 开头 | 抛错（防覆盖平台项） | `CAPABILITY_VIOLATION` |
| 页面区域标识格式非法（非点分 / 含非法字符） | 抛错 | `CAPABILITY_VIOLATION` |
| 路由路径不以 `/` 开头 | 抛错 | `CAPABILITY_VIOLATION` |
| 解析未登记键 | 返回 `undefined`（区域返回空数组）——**不替调用方兜底** | — |
| 模块路由名与宿主既有路由冲突 | 宿主跳过注册（不覆盖宿主路由） | — |
| 区域未登记任何项 | `resolveByArea` 返回空数组（空插槽，不渲染） | — |
| 宽和档同键（基座能力，本期未启用子类） | 告警保留首个，不抛错 | — |

## 7. 边界与开放项 <a id="open"></a>

- **宿主渲染消费**留 `01_02` 与全页面阶段（本期只保证注册表可用与装配通道打通）；
- **宽和档**为基座能力、本期八类未启用（架构「严格域抛错、一般域告警保留首个」的字面分档待各域消费方明确后再开）；
- 注册表按模块归因观测、清单对账扩展（`guard-base-registry` 对账面）随后续治理；
- 主题令牌与既有 `BaseTheme` / `tokens.scss` 的主题机制**尚未接线**，接线口径随宿主消费一并评估（避免二次分叉）。
