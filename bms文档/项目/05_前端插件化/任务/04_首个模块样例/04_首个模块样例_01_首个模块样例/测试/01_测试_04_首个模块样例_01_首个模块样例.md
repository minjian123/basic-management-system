## 3. 执行记录与结果 <a id="run"></a>

```bash
cd bms/frontend/packages/ui-ep && npx vue-tsc --noEmit -p tsconfig.json && npm run lint && npx vitest run

# 宿主（PC）
cd bms/frontend/apps/desktop && npx vue-tsc -b && npm run lint && npx vitest run && npm run build && npm run budget

cd bms/frontend/modules/sample && npm run lint && npm run typecheck && npm run test && npm run build && npm run budget && npm run guard:isolation

# 模块工程（demo 回归）
cd bms/frontend/modules/demo && npm run lint && npm run typecheck && npm run test && npm run guard:isolation

node frontend/scripts/check-shared-whitelist.mjs
node frontend/scripts/check-shared-deps.mjs

# 发布 / 回滚端到端（仓内真跑）

cd bms/frontend && node scripts/release-module.mjs publish --module sample

curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5002/sample/0.1.0/remoteEntry.js

# 文档与基座
cd bms && python3 scripts/tools/base-check/check-base.py
python3 scripts/tools/base-check/check-links.py
python3 scripts/tools/check-docs/check-status.py --stage 05_前端插件化 --strict
```

## 4. 覆盖率 <a id="coverage"></a>

- 模块 `frontend/modules/sample/`：新增源码（模块定义 / 上下文 / 数据服务 / 三个页面 / 四个组件 / 文案与组合式）由 `module-contract` + 模块专属用例覆盖；契约工厂断言「注入上下文 / 注册声明 / 共享依赖 / 样式约束」齐备，模块侧覆盖率随 `module-check` 的 `vitest run` 实测（新增模块 100% 门禁口径以契约用例与页面用例承载）。
- 核心 / 宿主 / ui-ep 既有覆盖率门禁不变（宿主 `test:cov` 阈值 70%）。

## 5. 偏差与遗留 <a id="deviations"></a>

- **偏差**：
  1. 列表页无操作列（平台页面约定），编辑 / 删除移至详情页、新建在列表工具栏（详见实施记录 §4 问题 4）；
  2. 第三方分包 `element-plus`（`output.codeSplitting.groups`）与非共享项体积阈值调整（546 → 660 KB）随实施回写（详见实施记录 §4 问题 1 / 2）；
  3. 模块构建 `#TYPE-001`（`02_02` 遗留）在 `04_01` 一并修复（入口引用 `env.d.ts` + `.vue` shim），demo / sample 重发归档（详见实施记录 §4 问题 8）；
  4. CI `module-build` 首推（流水线 #310）因逐模块 `guard:isolation` 全量扫描而失败（第二个模块暴露的集成缺口）；修复为 `--module .` 只扫自身，本地复现验证通过（详见实施记录 §4 问题 9）。
- **遗留**：
  1. **浏览器级手工验证**：动态路由 / 菜单联动 / 挂载卸载 / 兜底 / shared 单实例由宿主用例（替身远端解析器）与发布产物可达性覆盖；真机浏览器端到端（`serve-module-releases` + 宿主 `dev`）为人工步骤（命令见实施记录 §3 第 9 条），随阶段验收复跑；
  2. **真实接口 / 生产部署 / 字段渲染器·卡片消费 / 菜单权限过滤**：见实施记录 §6 遗留，归后续阶段。
