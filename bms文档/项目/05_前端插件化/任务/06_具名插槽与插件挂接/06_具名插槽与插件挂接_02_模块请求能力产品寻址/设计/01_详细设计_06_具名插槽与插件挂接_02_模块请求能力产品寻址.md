## 1. 设计目标与范围 <a id="goal"></a>

为「模块经宿主注入能力取数」补齐**产品面寻址**：产品服务对外只经产品命名空间 `/api/{产品键}/v1/{域}/...`（网关不为产品服务生成服务级路由），而寻址契约只组装平台服务前缀、模块又被禁止自拼前缀与自建 HTTP——产品前端模块（mdm 组织域页面与插件，mdm 需求 `01-4`）因此取不到数。本任务落地与平台服务寻址**同层并列**的产品寻址，使「模块不接触凭据、不感知寻址」的口径对产品服务同样成立。

1. **寻址契约**：新增产品键与域段的地址组装（单一来源），路径归一与错误口径与平台通道一致。
2. **模块请求能力**：新增产品域作用域 `api.product(产品键, 域)`（六法），语义与平台服务通道一致。
3. **护栏**：新增「自拼服务 / 产品前缀（R4）」判据（源码面 + 产物面）。
4. **文档回写**：模块契约 / 前端架构 / 前端基类清单 / 模块接入指南四处口径同步。
5. **范围外**：平台服务寻址（现行即产品清单外的 8 个平台服务）不变；网关产品路由与产品注册（**已由产品注册与服务接入机制交付**）不改；产品服务侧鉴权、数据范围与脱敏（服务侧强制，mdm 侧见需求 `01-3`）不改；模块契约版本升级（本任务为**向后兼容新增**）不做。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 寻址契约（`contracts/service-endpoint.ts`）

```ts
export const PRODUCT_KEYS = ['mdm'] as const            // 产品键登记点（与平台侧产品登记同源）
export type ProductKey = (typeof PRODUCT_KEYS)[number]
export function isProductKey(value: unknown): value is ProductKey
export function productDomain(domain: string): string        // 域段归一 + 格式校验（非法即抛）
export function productPrefix(product: ProductKey, domain: string): string   // /api/{产品键}/v1/{域}
export function productUrl(product: ProductKey, domain: string, path?: string): string
```

- **两类命名空间并列**：平台服务 `/api/{平台服务键}/v1{路径}`，产品服务 `/api/{产品键}/v1/{域}{路径}`；同文件、同层，**唯一组装入口**。
- **域段由产品自持**：基座**不维护**产品内部域清单（mdm 的 `org` / `sup` / `cus` / `mat` 由 mdm 自持），只做格式校验（`^[a-z][a-z0-9_-]*$`），避免双事实源。
- **未登记不静默放行**：未登记产品键 / 域段缺失或非法 / 未登记平台服务键，一律 `BaseError(CAPABILITY_VIOLATION)`（参数段位、零请求、不回落平台前缀）。
- **路径归一**：去首部斜杠、折叠重复斜杠；查询串与深层路径原样保留（与平台通道抽出同一函数，避免两处漂移）。

### 3.2 模块请求能力（`contracts/module-api.ts` + `capabilities/module-api.ts`）

```ts
export interface ModuleApiScope { get / post / put / patch / del / request }
export interface ModuleApi {
  /* 平台服务通道（不变） */ get / post / put / del / request
  product(product: ProductKey, domain: string): ModuleApiScope
}
```

- `product()` **同步返回作用域**并在调用时**立即校验**（未登记产品键 / 非法域段即抛，零请求）；作用域内的 `path` 相对产品域前缀。
- 作用域语义与平台通道一致：`request()` 执行经核心 `request()` → 宿主适配器；前缀组装与凭据注入、统一响应解包、401 静默刷新与重放全在宿主请求层。
- `patch` 为产品域便捷方法（平台通道未列，作用域内补齐，写方法自动幂等键）。

### 3.3 幂等键口径

`createIdempotencyKey(target: string, path: string)`（能力基类抽象方法 / **宿主实现点**）：`target` 为「平台服务键」或「产品键:域」，宿主口径 `<target>:<时间戳>:<随机>` 不变。查询 / 删除不生成；`request()` 逃生口按显式传入透传（与平台通道同口径）。

### 3.4 兼容与边界

| 项 | 口径 |
| --- | --- |
| 平台服务键清单 | **零变化**（8 个平台服务；`org` 归 mdm 后不回退） |
| 模块契约版本 | **不变**（新增方法属向后兼容新增；加载器 / 发布前强校验 / 清单护栏 / 回滚四处校验口径不动） |
| 模块可见面 | 仅新增 `product()` 与作用域类型；既有方法签名不变 |
| 产品键登记 | 新增产品接入时在 `PRODUCT_KEYS` 登记（与产品档案、网关产品路由同批），并写入接入指南 |
| 安全 | 前端只带登录态；产品服务侧的数据范围与脱敏由服务侧强制（mdm 侧见需求 `01-3`） |

## 4. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 未登记产品键 | `CAPABILITY_VIOLATION`（参数段位、零请求；不回落平台前缀） |
| 域段缺失 / 格式非法 | 同上 |
| 未登记平台服务键（既有） | 同上 |
| 请求适配器未注入 | `NOT_IMPLEMENTED`（占位零请求，既有口径） |
| 产品服务不存在 / 网关无路由 | 后端 404，经宿主请求层解包后模块收到统一错误（模块自行降级） |
| 模块自拼 `/api/...` 前缀 | 隔离护栏 R4 拦截（源码面 + 产物面） |
| 模块裸 `fetch` / `axios` / `XMLHttpRequest` | 隔离护栏 R3 拦截（既有） |
| 模块动态拼接前缀（非字面量） | **机器护栏不覆盖**：由契约评审 + 契约用例 + 模块契约测试兜底（见 §7 第 1 项） |

## 7. 边界与开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | **动态拼接前缀不被机器护栏覆盖**（判据只认 `/api/` 字面量与模板串） | 契约评审 + 模块契约测试；若需强约束，另立「模块访问面声明」需求（随模块契约版本升级承载） |
| 2 | 产品键**基座登记**（`PRODUCT_KEYS`）与平台侧产品档案 / 网关产品路由的**同源校验**尚无机器护栏 | 产品接入编排（R4.3 后续）或阶段五域 03 追加 |

## 8. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 产品寻址落点 | 与平台服务寻址**同层并列**（`contracts/service-endpoint.ts` 单一来源），不另起寻址模块 |
| 2 | 通道形态 | `ModuleApi` 增**产品域作用域**（`product(产品键, 域)`），非平铺方法，避免方法爆炸与签名歧义 |
| 3 | 产品键校验 | **登记式**（`PRODUCT_KEYS`，与服务键同口径：未登记不静默放行）；域段**由产品自持**，只做格式校验（避免双事实源） |
| 4 | 契约版本 | **不升** `MODULE_CONTRACT_VERSION`（向后兼容新增） |
| 5 | 幂等键抽象 | 能力基类 `createIdempotencyKey(target, path)`，`target` = 服务键 或 `产品键:域`（宿主实现点口径不变） |
| 6 | 护栏规则码 | 新增 **R4 自拼服务 / 产品前缀**（与 R3 自建 HTTP 并列，源码面 + 产物面同判据） |
| 7 | 需求归属 | 落**阶段五域 06**（该域已含「插件只经宿主注入 `api` 取数」与跨仓产品插件语境），机制基座引用阶段六 `06_02` |
