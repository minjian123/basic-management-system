## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段五需求域 06 的 3 条需求——[05-10 具名插槽基座功能与前后端配套插件（含样例）](../../需求/06_需求_具名插槽与插件挂接.md#r05-10)（2026-10-03 回补）、[05-11 具名插槽显式上下文注入通道](../../需求/06_需求_具名插槽与插件挂接.md#r05-11)（2026-10-06 补）与 [05-13 模块请求能力产品寻址](../../需求/06_需求_具名插槽与插件挂接.md#r05-13)（2026-10-08 补），3 个子任务（`06_01` / `06_02` / `06_03`）。
- **端范围**：**仅 PC**（`frontend/packages/*` + `frontend/apps/desktop` + 平台内样例模块/插件工程）；移动端 `ui-vant` 不在本次范围。
- **本域性质**：阶段五**回补域**——在已交付的「页面区域扩展点 + 区域插槽件 / `useModuleArea` 消费接线」之上，把插槽细化为**可运营的具名插槽机制**（命名约定 / 多插件 / 降级 / 前后端配套），并以**平台内样例插件**端到端验证；不改注册表基座与既有八类注册表。
- **服务 mdm 场景**：为 mdm 组织域「用户分配岗位」插件（挂 `sys.user.detail.tabs`、写 mdm 用户-岗位契约）提供平台侧挂接基座，使宿主页（用户管理）不硬编码依赖插件、插件缺失即降级隐藏。
- **公共前置**：`01_01`（八类扩展点注册表，含页面区域）、`01_02`（区域插槽件与消费接线 `useModuleArea`）；样例插件复用 `02_01`（模块工程脚手架）/ `03_02`（清单与发布治理）/ `03_03`（兜底与归因）。
- **依据**：《[架构设计 · 扩展点与插件化](../../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§8.2 / §9「具名插槽与前后端配套插件化」、《[架构设计 · 前端架构](../../../../设计/架构设计/08_架构设计_前端架构.md)》§9、《[架构设计 · 前端模块契约](../../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[前端基类清单](../../../../前端基类清单.md)》、《[前端开发规范](../../../../规范/前端开发规范.md)》「具名插槽与插件挂接」条。
- **执行序**：`06_01 具名插槽基座功能与前后端配套插件`（已交付）→ `06_02 模块请求能力产品寻址`（与 mdm 产品前端接入同批）→ `06_03 具名插槽显式上下文注入通道`（非路由承载宿主页的插件上下文，mdm 三插件全部可用的最后一环）——推进见[计划](../../计划/01_计划_前端插件化.md)。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：`06_01` 依赖 `01_01`（页面区域注册表）与 `01_02`（区域插槽件与消费接线）；样例插件复用 `02_01` / `03_02` / `03_03`（模块工程、清单发布、兜底归因）；`06_03` 依赖 `06_01`（插槽件与 `useModuleArea` 投影）；`06_02`（产品寻址）与 `06_03`（上下文通道）均服务 mdm 需求 `01-4` 的三个插件（前者＝产品模块取数通道，后者＝非路由承载宿主页的插件上下文）。
- **依赖与推进**：依赖关系与推进见[计划](../../计划/01_计划_前端插件化.md)。
- **风险**：具名插槽若另起注册映射会破坏统一拒重与对账（须一律基于页面区域注册表基座）；宿主页若直接依赖插件会破坏降级语义（护栏强制「宿主不直连插件」）；插件前后端配套约定若不先行成文，插件的注册声明字段与后端契约路径 / 权限码归属易各写一套；样例若绕过机制（直接挂宿主页）则失去验证意义。
