## 3. 实施过程 <a id="process"></a>

1. **先登记再编码**：写 Kiwi 用例输入 → 经 mjbk 容器 `register_cases.py` 登记 → 回读编号 **2260** → 代码与用例标注（`// kiwi_id: 2260`）。
2. **类型先行**：先在 core 落框架无关的 `ModuleSlotContext`（只读类型），再在 ui-ep 落 Vue 层通道实现。
3. **通道实现**：注入键 + 提供端（冻结浅拷贝，`Object.freeze({ ...context })`）+ 消费端（`useModuleSlotContext` / `useModuleSlotField`，未注入返回 `undefined`）。
4. **插槽件接线**：`ModuleAreaOutlet` 增 `context` prop 并 `provideModuleSlotContext(() => props.context)`——注入与 `inline` / `tabs` 形态无关；既有宿主页不声明 `context` 即不注入（行为零变化）。
5. **宿主页留槽**：`RoleAssignTab`（非路由承载的记录页签）声明 `sys.role.detail.assign` 并注入当前 `roleId`；同时接 `registries` / 装配版本 / 权限码，与用户详情页同一口径。
6. **用例与护栏**：ui-ep 覆盖通道四类行为；desktop 新增真挂载用例（探针插件项读出 `roleId`、插件缺失即隐藏、上下文随实体切换）；护栏补「新宿主页经插槽件留槽并注入上下文且不直连插件」。
7. **门禁复跑**：core / ui-ep / desktop / 模块工程用例、`tsc` / `vue-tsc` / ESLint、隔离扫描、预检全绿（见 §5）。

## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 处置 |
| --- | --- | --- |
| 1 | **组件继承链护栏拦截**：新增独立组合式 `composables/useModuleSlotContext.ts` 触发「每个组合式都以值引入核心基类或下层基类投影」 | 通道 API **并入 `useModuleArea.ts`**（插槽消费投影自身已挂基类投影），不新增基类、不改继承链（详见设计 §8 第 2 项）；类型仍在 core（框架无关） |
| 2 | `vue/require-default-prop`：新增可选 prop 缺缺省值告警（`--max-warnings 0` 下即失败） | `context: undefined` 入 `withDefaults` |
| 3 | 只读强度取舍：深冻结会破坏插件对嵌套数据的常规消费语义 | 采用**冻结浅拷贝**（顶层只读），并在设计与文档明示（§3.5 / §7） |
