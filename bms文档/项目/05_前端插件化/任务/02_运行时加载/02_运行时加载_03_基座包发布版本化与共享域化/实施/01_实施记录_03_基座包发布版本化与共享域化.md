## 1. 交付范围 <a id="scope"></a>

把 `@bms/core` / `@bms/ui-ep` 纳入 MF 共享域（宿主提供方 / 模块消费方），使依赖「模块级单例」的机制在真机形态下成立——首要验收＝阶段七 RBAC `02_02/_01` 的「插件取到宿主上下文 + 草稿随宿主保存」链路。

## 3. 关键口径与操作要点 <a id="decision"></a>

- **机制成立证据**：宿主产物出现 `_virtual_mf_…__loadShare___mf_0_bms_mf_1_core__loadShare__.js`（**provider 块**）；平台模块产物出现 `loadShare___mf_0_bms_mf_1_ui_mf_2_ep__loadShare__`（**消费共享域**）且不再含 `bms-module-area-outlet`（无本地副本）；`check-shared-deps` 判「依赖实例数 = 1（提供方份数：宿主 1 / 模块 0）」。
- **包版本变更后必须重装依赖**（pnpm 因 modules 目录状态不符自动 `install` 并在无 TTY 下中止）：`scripts/tools/deps/还原依赖.sh` → `CI=true pnpm install --config.confirmModulesPurge=false` → `外置依赖.sh`；此后 pnpm 命令一律带 `CI=true`。
- **构建被 `safe-delete` 拦（`dist/assets` 文件数超阈值）**：先手工 `rm -rf dist` 再构建。
- **G1 误报的处置（受控放行）**：唯一命中为 MF 运行时共享域解析的只读写法 `Object.prototype.hasOwnProperty.call(...)` ⇒ 判定为**误报**，护栏判据收窄为写入形态（不改「全局污染零容忍」口径，写入仍全部拦截，并补回归用例）。
