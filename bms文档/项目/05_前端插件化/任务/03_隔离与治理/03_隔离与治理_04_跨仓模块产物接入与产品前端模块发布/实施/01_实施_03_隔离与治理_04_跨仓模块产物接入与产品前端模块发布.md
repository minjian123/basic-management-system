## 3. 实施过程 <a id="process"></a>

1. **上下文与决策确认**：按《[AI开发规范](../../../../../../规范/AI开发规范.md)》读 bms 阶段五需求 / 任务 / 计划（域 03 与域 06）、`03_02` 详细设计与实施记录、前端发布脚本（`release-module.mjs` / `check-module-manifest.mjs` / `check-shared-deps.mjs` / `check-module-isolation.mjs` / `check-shared-whitelist.mjs`）、产品清单常量（`module_registry.py`）与 `sys_product` 表文件、《平台可扩展性规划》R4.3 条目。**待拍板事项逐项确认（question 工具，共 8 项）**：立项形态（域 03 追加子任务 + 需求顺延 `05-12`）、交付范围（机制最小集）、拉取形态（产物目录参数化）、前端包来源取值（产品前端工程标识）、回填时点（首次发布时回填、本任务回填已接入产品）、清单是否新增字段（不新增）、平台 CI 的跨仓覆盖边界（不伪装覆盖）、发布记录是否记路径（不记）。
2. **立项三处**：需求域 03 追加 `05-12`（并同步总览总清单 / 文档地图 / 范围说明 / 回补说明）；新建本任务文档并更新域总览子任务清单（3 → 4）与依赖；阶段五计划回写（头部统计、§1 计划说明与执行序、§3 与 §4 图表、§7 台账第 18 项）。
3. **Kiwi 先登记**：输入文件 `test/scripts/kiwi/cases/2026-10-08_阶段五03-04_跨仓模块产物接入与产品前端模块发布.json`，经 `register_cases.py`（走 Kiwi 容器 Django shell）回读编号 **2258**，回填输入文件 `case_id`。
4. **产物来源参数化**：`release-module.mjs` 增全局选项 `--module-dir <目录>`（相对路径按当前工作目录解析）；`checkReleaseGuards` 增入参 `moduleDir` 并返回实际目录与 `external` 标记；版本关 / sourcemap 关按该目录取数，归档源改为 `<moduleDir>/dist`，体积计量改为 `measureModuleDist(moduleDir)`；`publish` 打印实际产物目录（仅控制台）。
   - 命令：`node frontend/scripts/release-module.mjs publish --module <名> --module-dir <仓外目录> [...]`
5. **隔离与共享校验支持仓外工程**：`check-module-isolation.mjs` 新增 `scanExternalModuleSources(moduleDir)`（`src/` 缺失即无源码面，返回空）与 `scanModuleProductDir(moduleDir)`（缺产物即报错）；共享白名单护栏 `checkSharedWhitelist` 增 `moduleDirs` 选项（缺省遍历 `frontend/modules/*`，跨仓传该工程目录）；仓外分支的产物面扫描异常（缺 `budget.json` 等）归入违规清单，避免裸抛。
6. **清单护栏跨仓条目口径**：`check-module-manifest.mjs` 对无本地工程的**远端**条目按跨仓放行（只校清单契约与入口版本目录 + 留痕一致），`mode: local` 缺本地工程仍判失败；新增导出 `classifyManifestEntries(frontendDir)` 并在 CLI 输出「仓内 N 项 / 跨仓 M 项（跨仓条目：…——版本发现与产物校验在发布时执行）」。
7. **产物级共享断言泛化（可测化）**：`check-shared-deps.mjs` 由「宿主 × demo」二元对改为「宿主 × **每个在册仓内模块**」（`frontend/modules/*/dist`），失败信息带模块名；整段断言重构为导出纯函数 `checkSharedDeps({ frontendDir })`（返回 `{ problems, sharedNames, moduleNames }`）+ CLI 包装，并新增类型声明 `check-shared-deps.d.mts`；`FRONTEND_DIR` 推断补非 `file:` 协议回退（供 Vitest 载入）。
8. **前端包来源口径与回填**：`PRODUCT_CATALOG` 的 `mdm` 行回填 `frontend_package_source="mdm#frontend"`，清单说明改为「产品前端工程标识（`{仓库名}#{前端根}`），主机 / 凭据 / 访问地址由部署环境配置注入、不入库」；`sys_product.md` 字段说明与变更记录（v4）同步；后端用例（`test_module_registry` / 平台产品接口用例）同步断言；本地库 / 部署库需重跑 `ops.seed_module` 以对齐接库对账。
9. **发布留痕**：发布记录（`release-log.json`）新增 `source`（`local` / `external`，**不记路径**）；Markdown 摘要增「来源」列（历史记录缺字段按 `local` 显示）；`rollback` / `disable` / `enable` 流程与字段不变。
10. **文档回写**：知识档案《微前端 · 业务模块接入指南》补 §7.1「跨仓接入」（外部工程形态 / 校验与流程 / 凭据与拉取 / 留痕 / 平台 CI 边界 / 前端包来源 / 工程形态）；《概要设计 · 前端插件化》修正「只做构建期合并、不做运行时远程加载」等滞后表述（双轨登记 / 阶段边界 / 流程步骤 / 时序注记 / 页面清单 / 验收要点 / 边界共 6 处）；《架构设计 · 模块注册》接入判据④补交付事实；阶段二计划 §7 第 41 项②回写闭环。
11. **用例**：`apps/desktop/tests/module-release.spec.ts` 增「跨仓模块产物接入」与「共享依赖产物级断言：多模块遍历」两组（发布 / 归档 / 清单 / 留痕来源、失败矩阵六类、无源码面与带源码面隔离、共享关未登记依赖、清单护栏两形态分类、逐模块断言与产物缺失提示）。
12. **端到端演练**：以临时工作区（平台侧最小夹具：宿主清单 + 共享 / 契约声明；跨仓侧独立工程）真跑 `publish --module-dir` → 清单护栏 → 升级发布 → 回滚 → 停用 / 启用 → 状态 → 失败分支（目录不存在 / 缺 sourcemap），输出见 §5。
13. **门禁验证**：见 §5。

## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 原因 | 处置 | 落点 |
| --- | --- | --- | --- | --- |
| 1 | 用例运行前即报「Failed to parse source … invalid JS syntax」，指向脚本注释之后的代码行 | 块注释内写了 `frontend/modules/*/dist`——`*/` 提前闭合了注释块 | 注释内改写为 `frontend/modules/＜模块名＞/dist`（两处） | `check-shared-deps.mjs` |
| 2 | 用例导入共享断言脚本时抛「The URL must be of scheme file」 | 原实现 `fileURLToPath(new URL('..', import.meta.url))` 仅在 Node 直跑成立；Vitest 下 `import.meta.url` 非 `file:` 协议 | 改为同目录脚本一致的推断写法（`file:` 协议按脚本位置，否则按测试工程目录回退），并支持显式传参 | `check-shared-deps.mjs` |
| 3 | 仓外工程缺 `budget.json` 时以裸异常抛出（绕过违规清单） | 产物面扫描的 `collectProductTargets` 直接抛错 | 仓外分支以 try / catch 收编为违规项（提示不变、发布一致性不变） | `release-module.mjs` |
| 4 | 阶段五收口断言用例在阶段重开后失败（「剩余项应为 0」） | 断言写死收口终态 | 改为结构自洽（头部计数 = 两表行数、已完成 + 剩余 = 阶段合计），支持阶段重开追加任务（与阶段二同口径） | `test_m5_closure.py` |
| 5 | 全库链接校验报 14 处断链（阶段七 `02_06` 记录，与本任务无关的存量） | 设计 / 实施 / 测试子目录的相对链接少退一级 | 一并修正（独立提交），`check-links` 归零 | 阶段七 `02_06` 记录三份 |
| 6 | `ruff` E501（130 > 120 字符） | 模块清单说明里新增的长句 | 折行重排 | `module_registry.py` |
