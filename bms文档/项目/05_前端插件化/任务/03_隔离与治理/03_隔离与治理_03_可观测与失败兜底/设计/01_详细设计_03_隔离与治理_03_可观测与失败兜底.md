## 1. 设计目标与范围 <a id="goal"></a>

在 `02_01`（远端加载通路与失败处理口径：远端不可达 / 版本不一致 / 入口非模块定义一律拒绝加载、错误原样上抛 + 错误边界兜底）、`02_02`（模块产物**独立计量**与入口闭包 / 入口外块清单）、`03_01`（产物面「模块自有 JS 块」识别口径）、`03_02`（清单唯一来源 / 版本发现 / 发布回滚 / 契约版本）之上，补齐运行时模块的**可观测与失败兜底**闭环：

1. **加载失败兜底与超时**——模块加载超时（默认 10s，整个 `load()` 计时）与初始化异常统一呈现降级 UI（复用模块边界兜底件 + 错误页，带模块名与版本），**不白屏**；
2. **错误上报带模块名与版本**——复用总基类错误上报通道（`BaseObject.reportError` → 注入 sink），宿主装配期注入**模块感知** reporter，错误记录统一携带模块名 / 版本 / 阶段，可按模块聚合；
3. **按模块归因**——错误 / 性能 / 体积按模块归因：加载耗时拆 **resolve / setup / mount** 三段、首屏渲染耗时按模块采集；模块产物体积沿用独立计量并在**发布记录**留痕、汇总输出；
4. **Web Vitals 按模块**——核心 Web Vitals（LCP / CLS / INP）按**当前活动模块**归属采集，开发态观测面板按模块拆分查看；
5. **sourcemap 映射**——模块产物 sourcemap 随构建产出、随发布按版本归档，发布前强校验要求存在；映射口径成文，线上异常可定位到源码位置。

**不在本期**：生产 / mjbk 部署形态（map 与产物的制品库 / CDN 托管、部署侧清单）、按模块 SLO 与告警阈值、真实后端上报通道（本期为可替换插件 + 内存记录，通道接口就位）、sourcemap 上传与私有化（生产归部署阶段）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 遥测记录与观测钩子（核心，框架无关） <a id="telemetry"></a>

`core/src/module/telemetry.ts`（新增，非基类实现物；不触 DOM / 不依赖框架）：

```ts
/** 模块加载 / 渲染阶段。 */
export type ModuleTelemetryPhase = 'resolve' | 'setup' | 'mount' | 'render'

/** 加载 / 渲染耗时记录。 */
export interface ModuleLoadTimingRecord {
  kind: 'load'
  name: string
  version: string
  phase: ModuleTelemetryPhase
  durationMs: number
  ok: boolean
  at: string
}

/** 模块错误记录（携带模块名与版本；宿主渲染错误版本可空）。 */
export interface ModuleErrorRecord {
  kind: 'error'
  name: string
  version: string
  phase: string
  message: string
  at: string
}

/** Web Vitals 记录（非模块路由归属 `platform`，故 name/version 可空）。 */
export interface ModuleVitalRecord {
  kind: 'vital'
  name: string | null
  version: string | null
  metric: 'LCP' | 'CLS' | 'INP'
  value: number
  rating: string
  at: string
}

export type ModuleTelemetryRecord = ModuleLoadTimingRecord | ModuleErrorRecord | ModuleVitalRecord

/** 加载观测钩子（加载器注入；缺省不观测）。 */
export interface ModuleLoadObserver {
  onPhase(name: string, version: string, phase: 'resolve' | 'setup', durationMs: number, ok: boolean): void
}

/** 模块加载超时（整个 `load()` 计时；10s）。 */
export const MODULE_LOAD_TIMEOUT_MS = 10_000
```

### 3.2 加载器超时与阶段计时 <a id="loader"></a>

`ManifestModuleLoader` 改造（**接口兼容**，构造第三参可选）：

```ts
constructor(entries, resolveEntry, options?: { observer?: ModuleLoadObserver; timeoutMs?: number })
```

| 项 | 口径 |
| --- | --- |
| 计时范围 | 整个 `load()`（解析入口 → 形状 / 名称 / 版本 / 契约版本校验 → `setup` 返回注册声明），单次超时 |
| 阶段拆分 | `resolve`（入口解析 + 校验）、`setup`（模块 `setup` 调用）；两段分别调 `observer.onPhase`（不管成败都记，失败带 `ok=false`） |
| 超时处置 | 超时抛 `BaseError(CAPABILITY_VIOLATION, '模块加载超时（>{timeoutMs}ms）：<name>')`；原 Promise 后续结果 / 异常被吞（不产生未处理拒绝） |
| 挂载阶段 | `mount` 由宿主计时（`mountModule` 内装配接线耗时），不经加载器 |
| 超时配置 | 缺省 `MODULE_LOAD_TIMEOUT_MS`；`options.timeoutMs` 供测试注入（不写入清单 / 契约，避免契约面扩张） |

### 3.3 模块观测基类（能力域 + 插件两层） <a id="base"></a>

**能力域基类** `core/src/capabilities/module-telemetry.ts`：

```ts
/** 模块可观测能力域基类（固定第 2 层语义；承载遥测记录 / 聚合契约，框架无关）。 */
export abstract class BaseModuleTelemetry extends BaseCapability {
  readonly key = 'module-telemetry'
  /** 记一条遥测记录。 */
  abstract record(record: ModuleTelemetryRecord): void
  /** 只读快照（按模块聚合）。 */
  abstract snapshot(): ModuleTelemetrySnapshot
  /** 清空记录。 */
  abstract reset(): void
}

/** 具体遥测器（内存记录，环形上限；每条转发给解析到的上报实现）。 */
export class ModuleTelemetry extends BaseModuleTelemetry { ... }
```

```ts
/** 按模块聚合快照。 */
export interface ModuleTelemetrySnapshot {
  /** 模块名 → 版本 / 加载耗时（按阶段） / 错误 / Vitals。 */
  modules: Record<string, {
    version: string
    load: ModuleLoadTimingRecord[]
    errors: ModuleErrorRecord[]
    vitals: ModuleVitalRecord[]
  }>
  /** 非模块（平台页面 / 清单获取失败等）错误与 Vitals。 */
  platform: { errors: ModuleErrorRecord[]; vitals: ModuleVitalRecord[] }
}
```

**插件基类** `core/src/capabilities/module-reporter.ts`（与图表引擎 / 实时通道同构）：

```ts
/** 上报实现插件基类（可替换投递通道：缺省内存实现，后续换真实后端通道）。 */
export abstract class BaseModuleReporter extends BasePluggable {
  abstract report(record: ModuleTelemetryRecord): void
}
/** 缺省内存上报实现（保留投递副本，供面板与排障核对）。 */
export class InMemoryModuleReporter extends BaseModuleReporter { ... }
/** 上报实现注册项 / 注册表（同键拒重；未登记即空实现，不阻断观测）。 */
export class ModuleReporterProvider extends BaseProvider { key; build(): BaseModuleReporter }
export class ModuleReporterRegistry extends BaseProviderRegistry<ModuleReporterProvider> { ... }
```

| 项 | 口径 |
| --- | --- |
| 能力键登记 | `CAPABILITY_MANIFEST['module-telemetry'] = []`（能力依赖登记表） |
| 插件键 | `BaseModuleReporter.pluginKey = 'module-reporter'`；注册表 `pluginKey = 'module-reporter-registry'` |
| 解析未命中 | 上报实现未登记 → 不投递（内存记录仍在，面板可用），不阻断加载 / 渲染 |
| 依赖方向 | 仅上位（capabilities → mechanisms / module 类型）；核心仍零框架依赖（不引 `web-vitals` / DOM） |

> **契约版本不递增**：本次不改注入上下文 / 注册声明通道 / 清单字段语义 / 加载校验链；`MODULE_CONTRACT_VERSION` 保持 `1`，既有模块产物无需重发。

### 3.4 宿主错误上报与按模块归因 <a id="reporter"></a>

`apps/desktop/src/observability/`：

| 文件 | 职责 |
| --- | --- |
| `index.ts` | `installObservability()`：创建 `ModuleTelemetry` 单例 + 注册 `InMemoryModuleReporter`（缺省）→ `configureBase({ reporter })` 注入模块感知 sink → 安装 Web Vitals 采集；导出单例与查询接口 |
| `scope.ts` | 活动模块作用域：`setActiveModule(name, version)` / `clearActiveModule()` / `withModuleScope(name, version, fn)`（加载 / 挂载期间标注当前模块） |
| `reporter.ts` | `createModuleReporterSink(telemetry)`：把总基类 `reportError(error, meta)` 的调用**补模块名与版本**（取活动模块作用域；无则 `name='platform'`）后记入遥测；`reportModuleError(name, version, phase, error)` 供显式调用 |
| `webVitals.ts` | 经官方 `web-vitals`（`onLCP` / `onCLS` / `onINP`）采集；回调时按**当前活动模块**归属（无则 `platform`）；模块路由切换即刷新归属 |
| `timing.ts` | `markRender(routeName)`：模块路由视图挂载时记 `render` 耗时（导航开始 → 视图挂载） |

| 项 | 口径 |
| --- | --- |
| 通道复用（强制） | 统一走总基类 `configureBase({ reporter })` sink（**不得另起上报通路**）；模块感知 sink 只做「补模块名/版本 + 记遥测」，投递后端由 `ModuleReporterRegistry` 决定 |
| 加载 / 挂载错误 | 宿主 `installModules` / `mountModule` 捕获时 `reportModuleError(name, version, phase, error)`（phase：`resolve` / `setup` / `mount`） |
| 渲染错误 | `ModuleBoundary` 捕获 → 按当前路由解析所属模块 → `reportModuleError(name, version, 'render', error)` |
| 归属兜底 | 无活动模块（平台页面 / 清单获取失败）→ `name='platform'`、`version=''` |
| 聚合 | `ModuleTelemetry.snapshot()` 按模块名分组（加载耗时 / 错误 / Vitals），供面板与用例读取 |

### 3.5 失败兜底与单模块重试 <a id="retry"></a>

| 项 | 口径 |
| --- | --- |
| 降级 UI | 复用 `ModuleBoundary.vue` + `@bms/ui-ep` `ErrorPage`（500 + 重试）；文案带**模块名与版本**与原因（超时 / 远端不可达 / 契约版本不符 / 渲染异常） |
| 触发面 | ① 清单获取失败（空清单 + 错误状态，不阻塞启动；沿用 `01_02`）；② 单项加载（含超时）/ 挂载失败；③ 模块视图渲染异常 |
| 重试 | 错误页「重试」= **仅重挂该模块**（`unmountModule` → 清错误态 → `mountModule` 重载）；**不整页刷新**、不自动重试，避免重试风暴；路由停留在原地址即可重新命中 |
| 重试不可用 | 清单获取失败（无模块可重挂）→ 重试退回整页刷新（唯一例外，文案明示） |
| 状态 | 模块错误态记入遥测；重试成功后清除该模块错误态 |

### 3.6 加载 / 渲染耗时与体积归因 <a id="attribution"></a>

| 归因面 | 采集 | 可见 |
| --- | --- | --- |
| 加载耗时 | `resolve` / `setup`（加载器观测钩子）+ `mount`（宿主计时） | 面板按模块列出三段耗时；遥测快照 |
| 渲染耗时 | `render`：进入模块路由 → 模块视图挂载 | 面板按模块列出最近一次渲染耗时 |

| 项 | 口径 |
| --- | --- |
| 构建 | 模块远端构建开 `build.sourcemap: true`（**外部** `.map`，不内联源码）；产物含 `remoteEntry.js.map` 与异步块 `.map` |
| 归档 | 发布归档 `dist/` **全量**（含 `.map`）到 `releases/<模块名>/<版本>/`（版本不可变，map 随版本保留） |
| 发布强校验（第 4 关） | 发布前校验 `dist/remoteEntry.js.map` 存在（缺 map 拒绝发布，退出码 1、不写文件）；本地开发同口径 |
| 清单护栏 | 模块构建产物存在时断言 `dist/remoteEntry.js.map` 存在（CI `module-build` 覆盖） |
| 托管 | 本机发布存储（`serve-module-releases.mjs`）已托管 `.map`（MIME 已含）；生产由 nginx / CDN 托管版本目录（含 map），归部署阶段 |
| 映射口径 | 异常堆栈指向 `<origin>/<模块名>/<版本>/assets/<chunk>.js`，其 `sourceMappingURL` 指向同目录 `.map`；用 `source-map` 工具（或浏览器 DevTools）按版本目录解析即可定位源码。上报记录携带 `module` / `version`，据此取对应版本 map |
| 生产范围 | 本期只做本机形态；制品库 / 对象存储与私有化（map 不宜公开）归部署阶段，口径届时回写 |

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 |
| --- | --- |
| 模块加载超时（>10s） | 抛 `CAPABILITY_VIOLATION`（原因明示超时与模块名）→ 宿主记错误状态 + 遥测 + 降级 UI（重试可重挂） |
| 远端不可达 / 产物 404 / 语法错误 | 沿用 `02_01`：原样上抛 + 边界兜底 + 记错误状态；本轮补遥测与模块名/版本 |
| 模块契约版本 / 名称 / 版本不匹配 | 沿用加载器拒绝口径；本轮补遥测记录（phase `resolve`） |
| `setup` 抛错 | 加载拒绝；本轮补 phase `setup` 遥测；重试可重挂 |
| 模块视图渲染异常 | `ModuleBoundary` 捕获 → 按路由解析模块 → 记 `render` 错误 + 降级 UI + 单模块重试 |
| 渲染错误无法解析所属模块（平台页面） | 归 `platform`；不展示模块错误页（仅上报，平台错误由既有错误页处理） |
| 重试时清单获取本已失败（无模块可重挂） | 重试退回整页刷新（文案明示） |
| 重试时模块仍失败 | 保留错误态与遥测记录，等待下次重试；不自动重试 |
| 上报实现未登记 | 不投递（内存记录仍在）；不阻断加载 / 渲染 |
| `web-vitals` 指标在模块切换后回调 | 按**回调时刻**活动模块归属（简洁可解释）；不做跨模块拆分 |
| 浏览器不支持 PerformanceObserver / web-vitals | 采集静默降级（不采集 Vitals），加载 / 错误遥测不受影响 |
| 模块产物缺 sourcemap | 发布拒绝（第 4 关）；护栏在 CI 提示 |
| 已归档版本无 map（历史版本） | 不追改历史归档；重发用 `--force`（本地，记 `republish`）或升版本发布 |
| 生产 / mjbk 部署形态 | 不在本期（map 与产物托管、后端上报通道归部署 / 可观测阶段） |

## 7. 边界与开放项 <a id="open"></a>

- **真实后端上报通道**：本期为可替换插件 + 内存记录（`BaseModuleReporter` 就位），接入可观测子系统时注册真实 reporter（不改宿主调用面）；
- **生产部署形态**：map 与产物托管、制品库 / 对象存储、私有化映射（map 不公开）归部署阶段；
- **按模块 SLO 与告警阈值**：后补（需求域 03 已列为不做项）；
- **Vitals 归属精度**：按回调时刻活动模块归属，不做「指标跨模块切片」；后续如需更准可按路由分段；
- **超时配置**：本期为平台常量（`MODULE_LOAD_TIMEOUT_MS`）+ 测试注入，不开放为清单 / 模块可配（避免契约面扩张）；
- **`--force` 重发**：历史归档补 map 用本地重发（记 `republish`）或升版本；生产禁用（沿用 `03_02`）；
- **移动端宿主**：观测基类与遥测器在核心、可复用；面板为本期 PC 开发态，移动端后补；
- **`04_01` 接收项**：样例模块按本任务 sourcemap / 体积 / 上报口径接入示例。（**已闭环 2026-09-22**：sample 开外部 sourcemap、清单护栏体积汇总、发布记录体积字段均覆盖。）

## 8. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 加载超时时长 | **10s**（整个 `load()` 单次计时） |
| 2 | 超时计时口径 | 覆盖解析 + 校验 + `setup` 整体；不拆两段阈值 |
| 3 | 重试口径 | 手动重试、仅重挂该模块（不整页刷新、不自动重试）；清单获取失败例外退回整页刷新 |
| 4 | Web Vitals 采集 | 引入官方 `web-vitals`（宿主运行时依赖，落单一落点 `observability/webVitals.ts`） |
| 5 | 按模块可见形态 | 开发态模块观测面板页（dev-only 路由，不进生产） |
| 6 | 错误上报落点 | core 模块层加观测器（能力域 + 插件基类）+ 宿主 `configureBase` 注入模块感知 sink；模块生命周期错误必带模块名 / 版本 |
| 7 | 观测基类 | **能力域基类 `BaseModuleTelemetry`**（`module-telemetry`）+ **插件基类 `BaseModuleReporter`**（`module-reporter` + 注册表 / 注册项）两层都建 |
| 8 | 体积归因 | 发布记录增 `size` 字段 + 清单护栏按模块汇总输出（单一计量实现 `module-metrics.mjs`） |
| 9 | sourcemap | 模块构建开外部 sourcemap、发布归档含 map、发布前**第 4 关强校验**要求 map 存在 |
| 10 | CI | 扩展既有 job（不新增）：`module-build` 覆盖 sourcemap 与体积输出、`desktop-check` 覆盖观测用例 |
| 11 | Vitals 归属 | 按当前活动模块归属；非模块路由归 `platform` |
| 12 | 耗时采集 | 加载三段（resolve / setup / mount）+ 首屏渲染（render） |
| 13 | sourcemap 生产范围 | 本期只做本机形态；生产托管与私有化归部署阶段 |
| 14 | 契约版本 | 不递增（`MODULE_CONTRACT_VERSION` 保持 1；契约链未变，既有产物无需重发） |
| 15 | 遥测存储 | 内存环形记录 + 可替换上报实现；未登记上报实现即不投递（不阻断） |
| 16 | 超时配置面 | 平台常量 + 测试注入参数，不开放清单 / 模块配置 |
| 17 | 工时口径 | 本任务 12h（沿用计划；若有偏差按实施记录回写） |
| 18 | 排期窗口 | 03_03：2026-10-11；04_01：10-12 ~ 10-14 |
