## 1. 评估背景与范围 <a id="intro"></a>

需求 05-5 第 4 条要求就「是否需要 `Shadow DOM` / JS 沙箱」给出评估结论（含触发条件与代价），成文备查，**本期不引入**。本评估对象：运行时模块（`frontend/modules/*`）与宿主薄壳之间的样式与运行时隔离增强手段；评估依据为知识档案《[微前端 · 04 隔离与治理](../../../../../../资料/知识档案/微前端/04_微前端_隔离与治理.md)》§2 / §3 与《[微前端 · 03 技术方案对比](../../../../../../资料/知识档案/微前端/03_微前端_技术方案对比.md)》。

**当前隔离基线**（本任务已交付，见[详细设计](01_详细设计_03_隔离与治理_01_样式与运行时隔离.md) §3.1）：

| 面 | 已落地手段 |
| --- | --- |
| 样式 | SFC `<style scoped>` + 模块命名空间前缀约定 + 只消费 `--bms-*` 令牌 + 禁全局选择器 / 全局样式导入 |
| 全局 | 机器护栏拦截全局原型 / 全局事件 / 全局变量赋值 / 根节点直控（源码面 + 产物面双扫描，含 fixture） |
| 运行时 | 只经 `setup(context)` 只读快照消费宿主能力；禁自建宿主级实例；禁持久化 API |
| 共享依赖 | `shared` 单例 + 版本要求 + 双层实例数断言（`02_02`） |

## 2. 候选方案对比 <a id="compare"></a>

| 方案 | 原理 | 隔离强度 | 本项目代价与风险 |
| --- | --- | --- | --- |
| **Shadow DOM**（`strictStyleIsolation` / 类 Shadow DOM） | 模块包进 shadow root，样式与 DOM 封装 | 强（样式）/ 弱（JS） | **弹窗与下拉挂 `body` 会丢样式**（需 portal 适配）；可继承属性（字体、`--bms-*` 令牌）可穿透但需显式设计；部分 UI 库（Element Plus 弹层）不兼容；宿主与模块的主题 / 密度档位联动复杂化 |
| **Proxy 沙箱**（qiankun 默认） | 为模块创建 `fakeWindow`，拦截全局读写 | 中（JS） | 依赖 Proxy；隐式全局访问仍可能泄漏；与 Module Federation 运行时的全局（share scope）需协调；性能与调试成本 |
| **快照沙箱**（qiankun 降级） | 激活时快照 `window`、卸载回滚 | 中 | 仅支持单实例；切换有开销；与「模块常驻挂载」形态不匹配 |
| **`with` + 作用域隔离**（micro-app 等） | 包装执行作用域 | 弱 | 对动态代码与全局副作用防护有限 |
| **iframe 原生隔离**（wujie / 原生） | 模块 JS 在独立 iframe 上下文执行，DOM 代理到主文档 | 最强 | 通信与调试链路长；代理层复杂度高；与 MF 共享依赖、令牌注入、路由联动全部需重做 |
| **约定 + 机器护栏**（**当前方案**） | scoped / 令牌 / 禁止项约定，源码与产物双扫描 + fixture | 中（约定层） | 依赖护栏覆盖面与团队纪律；无法防「运行期动态注入」的极端情况 |

## 3. 评估结论 <a id="conclusion"></a>

**本期不引入 Shadow DOM / JS 沙箱**。理由：

1. 当前模块为**平台内 Vue 技术栈**（`frontend/modules/*` 独立工程但同框架、同基座包、共享框架三件），样式冲突面可由 `scoped` + 令牌 + 命名空间前缀收敛，全局污染面已由机器护栏（源码 + 产物）挡在提交前；
2. 引入沙箱的代价集中在**弹层挂载（`body`）与 UI 库兼容**、**令牌与主题穿透**、**MF 共享依赖与全局 share scope 协调**——为尚未出现的风险付出长期复杂度，不符合「最小闭环 + 逐步补齐」的阶段节奏；
3. 行业共识：微前端失败多因治理缺失而非框架选错；当前治理（隔离约定 + 护栏 + 依赖单例 + 清单治理）优先于沙箱。

## 4. 触发条件（任一命中即立项评估） <a id="trigger"></a>

| # | 触发条件 | 说明 |
| --- | --- | --- |
| 1 | **异构技术栈模块** | 出现非 Vue（或非本项目基座）模块，样式与运行时约定无法统一 |
| 2 | **不可信第三方代码** | 需嵌入外部 / 第三方提供的模块代码，安全域隔离成为需求 |
| 3 | **同页多模块强隔离** | 同一页面并行挂载多个模块，样式 / 全局冲突无法靠 scoped 与约定解决 |
| 4 | **第三方库全局冲突** | 依赖库全局变量 / 原型冲突无法靠升级、替换或隔离配置解决 |
| 5 | **合规要求** | 客户 / 等保 / 合同明确要求强隔离 |

## 5. 引入时的代价清单（预登记） <a id="cost"></a>

- 弹窗 / 下拉 / 提示等挂 `body` 的组件在 Shadow DOM 下丢样式，需 portal 适配或弹层代理；
- 令牌（`--bms-*`）与字体等可继承属性需显式穿透设计；深色 / 品牌化 / 密度档位联动需重测；
- UI 组件库（Element Plus）弹层与 Shadow DOM 兼容性需专项验证；
- JS 沙箱与 MF 运行时的全局（share scope / 预加载）需协调，双实例风险回潮；
- 调试链路变长（沙箱内错误栈 / sourcemap 映射），可观测口径需重做（与 `03_03` 口径联动）；
- 性能开销（代理层 / iframe）需按模块实测。
