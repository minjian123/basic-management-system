## 1. 域说明 <a id="intro"></a>

本域对应阶段五「阶段验收」：核对 M5 验收门禁（八类扩展点 / 运行时加载 / 依赖共享 / 隔离 / 清单与发布治理 / 可观测与兜底 / 首个模块样例）、产出阶段测试报告与证据索引，收口阶段状态。

**依据**：《总体项目规划》「阶段内容与完成标准」节（阶段五行）与「验收与收尾」节；《需求文档规范》《计划文档规范》《任务文档规范》《测试规范》《项目管理规范》。**目标**：M5 门禁逐条有结论与证据；阶段测试报告归档；三类文档（需求 / 任务 / 计划）状态一致。

## 2. 需求 05-9：阶段验收门禁核对与阶段测试报告 <a id="r05-9"></a>

优先级：2（高）

**背景与动机**：阶段五以「机制就位 + 首个样例真跑通」为完成判定，产物横跨宿主、核心包、模块工程、平台脚本与 CI 五处，须以门禁逐条核对并留证据，避免「做完了但不可证」；同时阶段五的收口动作（门禁结论、状态回写、遗留归口）此前未成文，须与阶段二 / 三 / 四同口径补齐，使 M5 的达成可复核、可追溯。

**内容**（《总体项目规划》「阶段内容与完成标准」节（阶段五行）、《测试规范》「测试报告」节）：

1. 门禁核对：逐条核对阶段五完成标准（八类扩展点注册表可用 / 宿主运行时加载模块 / `shared` 依赖单实例 / 模块不污染宿主 / 模块清单与发布治理可用 / 失败可兜底且可按模块归因 / 首个模块样例独立发布），逐项给出结论与证据索引。
2. 阶段测试报告：按《测试规范》产出阶段测试报告（用例执行统计 / 缺陷统计 / 覆盖率 / 风险与遗留项 / 复盘与经验教训 + 附录），归档到阶段目录。
3. 状态收口：需求 / 任务 / 计划三类文档状态一致；遗留项登记并归口。
4. 证据落点：门禁结论与证据索引落计划文档与测试报告（需求文档不承载门禁与进度）。

**完成标准**：M5 门禁逐条有结论与证据；阶段测试报告归档；三类文档状态一致；遗留项登记归口；校验通过。
