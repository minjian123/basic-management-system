## 1. 域说明 <a id="intro"></a>

本域把阶段四「注册表基座最小实现」补齐为**八类扩展点的完整注册能力**，并把宿主加载器从「本地演示模块」升级为「按模块清单加载」，是横向模块接入（`05-3`）的前置。

- **本域范围**：八类扩展点注册表（路由·菜单 / 页面区域 / 通用组件 / 字段渲染器 / 图标 / 工作台卡片 / 主题令牌）与统一装配；宿主加载器运行时化与模块契约远端对接。
- **不重复建设**：注册表**统一基于统一注册表基座与注册项公共契约**（阶段四已交付），本域只补齐缺失的扩展点域、统一装配与「不注册不可用」护栏。
- **依据**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9「扩展点 + 注册表」与「模块契约」、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.1 / §7.2、《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[前端基类清单](../../../前端基类清单.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 05-1：扩展点注册表补齐与统一装配（八类） <a id="r05-1"></a>

优先级：2（高）

**背景与动机**：阶段四只交付了五类注册表最小实现（路由·菜单 / 通用组件 / 字段渲染器 / 图标 / 工作台卡片），而架构要求「页面区域」「主题令牌」等同样以注册表挂接；若在本阶段不补齐，模块将无法按契约挂页面区域与主题，后续只能靠宿主硬编码或直接改主应用，运行时组合的意义被削弱。注册表若各自另起映射，也会重现「同键多实现无统一拒重」的老问题。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9「扩展点 + 注册表」）：

1. **八类扩展点注册表**：路由·菜单、页面区域、通用组件、字段渲染器、图标、工作台卡片、主题令牌各设注册表；**统一基于统一注册表基座与注册项公共契约**（不得另起映射登记实现），注册项继承注册项基类、注册表继承注册表基座。
2. **统一装配**：宿主提供统一的注册入口与装配时序（平台自身注册 + 模块注册共用同一通道），注册项携带来源（平台 / 模块名）供排查与归因。
3. **注册契约与校验**：同键唯一性拒重（严格域抛错、一般域告警保留首个）、未命中返回空（不替各域裁决兜底）、遍历保序、只读快照；模块注册项额外做**路径前缀与命名空间校验**（防越权覆盖平台项）。
4. **「不注册不可用」护栏落地**：未登记的扩展点不参与渲染与路由；机器护栏断言「随包/随模块引入但未登记」的项不可用。
5. **契约文档化**：以《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》为上位依据，列出八类扩展点的注册声明字段、键命名与冲突处置。

**完成标准**：
1. 八类注册表可用，注册 / 解析 / 拒重 / 未命中 / 保序 / 只读快照契约用例全绿（同一套断言覆盖各域）；
2. 平台自身与模块注册经同一通道，注册项来源可查；
3. 未登记项不生效，机器护栏含 fixture 拦截用例；
4. 注册声明字段与键命名成文并被样例模块实际使用；
5. `vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.1、《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[前端基类清单](../../../前端基类清单.md)》

## 3. 需求 05-2：宿主加载器运行时化与模块契约远端对接 <a id="r05-2"></a>

优先级：2（高）

**背景与动机**：阶段四的模块加载器以本地演示模块验证接口形态（静态 import / 本地产物），真实模块尚未经运行时加载；若加载器不先运行时化，`05-3` 的 Module Federation 接入与 `05-8` 的样例发布都无处落脚。同时模块契约（注入上下文 / 注册声明 / 样式约束）必须在远端形态下**同接口复用**，避免为远端另写一套契约。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9「模块契约」「运行时组合」）：

1. **加载器运行时化**：宿主加载器按**模块清单**（名称 / 入口 / 版本）加载模块 → 注入上下文 → 执行注册声明 → 挂载 → 卸载；加载器接口保持与阶段四一致（同接口接远端），仅替换实现通路。
2. **模块清单与加载器版本字段**：清单驱动加载（不硬编码模块地址）；清单加载失败 / 缺字段 / 版本不匹配时的处置口径（降级或拒绝加载）成文。
3. **注入上下文与只读约束**：宿主注入 router / Pinia / i18n / 当前用户与租户上下文；模块经模块上下文能力基类消费（只读约束），token 等敏感信息不落模块持久化。
4. **注册声明校验**：模块声明（路由 / 菜单 / 页面区域 / 组件 / 图标 / 卡片 / 主题）经统一校验（唯一性、路径前缀、命名空间），冲突处置成文；注册结果与卸载清理成对（无残留路由 / 菜单 / 注册项）。
5. **演示验证**：以本地或远端演示模块验证加载 → 注册 → 卸载全链路（不进入生产菜单）。

**完成标准**：
1. 宿主按模块清单加载模块，动态路由生效、菜单联动、挂载与卸载无残留；
2. 模块契约（注入上下文 / 注册声明 / 样式约束）在远端形态下同接口复用（不为远端另建契约）；
3. 清单缺字段 / 版本不匹配 / 加载失败各分支均有明确处置与用例；
4. `vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》、《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.2
