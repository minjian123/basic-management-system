## 1. 域说明 <a id="intro"></a>

本域管「模块接进来之后不出乱子」：样式与运行时不得污染宿主（`05-5`）、模块清单与发布要能独立发布与回滚（`05-6`）、加载失败要能兜底且问题可按模块归因（`05-7`）。三条共同构成运行时组合的最小治理闭环。

- **本域范围**：隔离约束与护栏、模块清单与发布 / 回滚治理、可观测与失败兜底。
- **不做（后补项）**：隔离增强（`Shadow DOM` / JS 沙箱）、灰度 / 蓝绿进阶策略、按模块 SLO 与告警阈值——按需评估后再立项。
- **依据**：架构 08 §9 治理表「样式与运行时隔离」「模块清单与发布治理」「可观测与失败兜底」、《[架构设计 · 部署与运维](../../../设计/架构设计/33_架构设计_部署与运维.md)》、《[前端审计规范](../../../规范/前端审计规范.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 05-5：样式与运行时隔离（Scoped / 令牌 / 全局污染约束） <a id="r05-5"></a>

优先级：2（高）

**背景与动机**：模块与宿主同处一个文档与运行时，一旦模块改写全局样式、全局原型或挂全局事件，问题会以「宿主页面偶发错乱」的形式出现且极难定位。隔离必须先以**约定 + 护栏**落地（不引入沙箱的复杂度），把违规挡在提交前。

**内容**（架构 08 §9 治理表「样式与运行时隔离」）：

1. **样式约定**：模块样式一律 `Scoped` 或加**模块命名空间前缀**；模块只消费平台设计令牌（不硬编码色值与尺寸）。
2. **全局污染约束**：模块不得改全局原型、不得挂全局事件、不得写全局样式（`*` / 根元素 / 第三方库全局变量覆盖）；平台侧对应的机器护栏覆盖模块目录。
3. **运行时约束**：模块不得直接操作宿主 store / router 实例（只经注入上下文与注册声明）；模块不私自持久化敏感上下文（token 等）。
4. **隔离增强评估**：就「是否需要 `Shadow DOM` / JS 沙箱」给出评估结论（含触发条件与代价），成文备查；本期不引入。
5. **契约文档化**：隔离约定并入模块契约（《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》），作为模块接入检查项。

**完成标准**：
1. 模块样式前缀与令牌消费约定成文，样例模块遵循；
2. 全局污染（全局原型 / 全局事件 / 全局样式 / 硬编码色值）由机器护栏拦截，含 fixture 拦截用例；
3. 模块经注入上下文访问宿主能力的口径成文并被样例模块使用；
4. 隔离增强评估结论成文（本期不引入，写明触发条件）。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9 治理表、《[前端开发规范](../../../规范/前端开发规范.md)》样式与令牌节、《[前端审计规范](../../../规范/前端审计规范.md)》单一落点与令牌维度、知识档案《[微前端 · 04 隔离与治理](../../../资料/知识档案/微前端/04_微前端_隔离与治理.md)》

## 3. 需求 05-6：模块清单与发布治理（版本发现 / 回滚 / 契约测试） <a id="r05-6"></a>

优先级：2（高）

**背景与动机**：模块能独立发布，就必须能独立回滚——否则一次模块发布事故会牵连整个前端。清单（名称 / 入口 / 版本）是唯一的发布与回滚控制面；同时模块与平台的契约（注入上下文 / 注册声明 / 共享依赖）需要有**契约测试**兜住，避免「模块改了宿主不知道」。

**内容**（架构 08 §9 治理表「模块清单与发布治理」）：

1. **模块清单**：清单字段（名称 / 入口 / 版本 / 可见性）与加载器版本字段口径统一（与 `05-2` / `05-3` 一致）；清单是模块加载与回滚的**唯一来源**。
2. **版本发现**：清单版本与模块产物版本一致性校验；发布时校验通过才可入清单。
3. **独立发布与回滚**：模块产物发布流程（构建 → 产物归档 → 清单更新）与**回滚**（清单版本回退到上一版本，模块产物保留）成文并可执行；灰度 / 蓝绿仅保留最小闭环（按清单指向切换），进阶策略后补。
4. **模块契约测试**：模块与平台的契约（注入上下文 / 注册声明 / 共享依赖 / 样式约束）纳入契约测试，**全部注册实现跑同一套断言**；契约变更走版本升级。
5. **发布留痕**：清单变更可追溯（谁、何时、哪个版本），与既有 CI / 发布记录口径一致。

**完成标准**：
1. 模块清单可用，字段与加载器口径一致；
2. 独立发布与**回滚**可执行并演练通过（清单版本回退生效）；
3. 模块契约测试覆盖全部注册实现（同一套断言），契约变更走版本升级；
4. 发布与回滚流程成文（含校验项与留痕要求）。

**参考文档**：架构 08 §9 治理表、《[架构设计 · 部署与运维](../../../设计/架构设计/33_架构设计_部署与运维.md)》发布与回滚节、《[架构设计 · 测试与质量](../../../设计/架构设计/32_架构设计_测试与质量.md)》契约测试节

## 4. 需求 05-7：可观测与失败兜底（超时 / 按模块归因 / sourcemap） <a id="r05-7"></a>

优先级：3（中）

**背景与动机**：运行时加载意味着**网络与远端产物成为新的失败面**（加载超时、产物 404、版本不匹配、初始化抛错）。若没有兜底与归因，“哪个模块、哪个版本出的问题”只能靠翻日志猜；同时模块性能若不可观测，后续无法定位首屏与交互退化来源。

**内容**（架构 08 §9 治理表「可观测与失败兜底」）：

1. **加载失败兜底与超时**：加载失败 / 超时 / 初始化异常时呈现降级 UI（复用模块边界兜底件与错误页），不白屏；超时时长与重试口径成文。
2. **错误上报带模块名与版本**：错误上报统一携带模块名与版本（复用总基类错误上报通道），便于按模块聚合。
3. **按模块归因**：错误 / 性能 / 体积按模块归因（模块产物体积单独计量；加载与渲染耗时按模块采集）。
4. **Web Vitals 按模块**：核心 Web Vitals 指标可按模块拆分查看。
5. **sourcemap 映射**：模块产物 sourcemap 归档与映射口径成文，上线异常可定位到源码位置。

**完成标准**：
1. 加载失败 / 超时 / 初始化异常均有降级呈现与用例（不白屏）；
2. 错误上报携带模块名与版本，可按模块聚合；
3. 模块体积与加载耗时按模块可见（含体积预算单独计量）；
4. sourcemap 归档与映射口径成文。
