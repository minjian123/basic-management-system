## 1. 域说明 <a id="intro"></a>

本域把横向模块接入从「接口预留」推进到「运行时真实加载」：宿主以 Module Federation 消费远端模块产物，模块独立构建、独立发布；同时以 `shared` 单例与版本偏斜检查保证框架级依赖不被重复打包（否则运行时会出现双实例、状态不通等难查问题）。

- **本域范围**：MF 接入与构建配置、模块独立构建产物与动态导入分包、`shared` 依赖单例与版本偏斜治理。
- **不做**：模块治理增强（依赖版本协商、灰度 / 蓝绿进阶、隔离增强、按模块 SLO）——随后续阶段或演进路线。
- **依据**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9「运行时组合（微前端，Module Federation）」与治理表「依赖共享与版本偏斜」、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.2、知识档案《[微前端](../../../资料/知识档案/微前端/01_微前端_总览.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 05-3：Module Federation 接入与模块独立构建 <a id="r05-3"></a>

优先级：2（高）

**背景与动机**：阶段四只交付了加载器接口与本地演示模块，模块产物仍需随平台一起构建；不接入 MF 就无法做到「模块独立构建与发布」，产品页面将被绑在平台发布节奏上。同时若不做动态导入分包，模块与重组件会挤进首屏，违背既有性能预算口径。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9）：

1. **Module Federation 接入**：宿主作为 host 消费远端模块（`remote` 声明与入口解析），模块作为 remote 暴露自身注册声明与页面；**模块产物独立构建**（模块有自己的构建命令与产物目录，不并入主应用产物）。
2. **模块清单与加载对接**：加载器按模块清单（名称 / 入口 / 版本）解析远端并加载；清单字段与加载器版本字段口径与 `05-2` 一致（不重复定义两套）。
3. **动态导入分包**：模块页面与重组件一律异步加载、独立分包，**不进首屏**；模块产物纳入体积预算计量口径。
4. **构建期合并保留为过渡 / 存量形态**：平台自身页面与未迁移模块仍随平台构建发布；两种形态共存期间由清单配置区分，不做一次性迁移。
5. **演示验证**：本地 / 内网提供演示 remote，宿主运行时加载并注册其路由（不进入生产菜单）。

**完成标准**：
1. 演示模块**独立构建**产出独立产物，宿主**运行时加载**成功（非构建期合并）；
2. 动态路由生效、模块挂载与卸载正常、卸载无残留；
3. 模块产物不进首屏，体积预算门禁通过（模块产物单独计量）；
4. MF 配置与模块清单字段成文，`05-2` 加载器同接口复用；
5. `vue-tsc`、ESLint、Vitest、构建与体积预算全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.2、《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》

## 3. 需求 05-4：依赖共享与版本偏斜治理 <a id="r05-4"></a>

优先级：3（中）

**背景与动机**：运行时组合下，若 Vue / 路由 / 状态 / 组件库等框架级依赖在宿主与模块中各打包一份，会出现**双实例**（响应式与状态不通、组件上下文丢失），且问题只在运行时以疑难杂症形式暴露。须在接入初期就把 `shared` 单例声明与版本偏斜检查固化，避免后续模块越多越难收拾。

**内容**（架构 08 §9 治理表「依赖共享与版本偏斜」）：

1. **`shared` 单例声明**：框架级依赖（框架本体 / 路由 / 状态 / UI 组件库 / 核心包）在宿主与模块构建配置中声明为 `shared` 且 `singleton`，并声明 `requiredVersion`。**实施口径（2026-09-21 实测修订）**：共享面落为**受控白名单**——框架三件（框架本体 / 路由 / 状态）入共享面；**UI 组件库与核心包经实测与机制判定后登记为受控非共享项**（UI 组件库共享会把整库拉入首屏，`eager:false` / `treeShaking runtime-infer` 实测启动期仍异步拉取约 433 KB 属指标失真；核心包为源码直出 + 别名消费，共享机制上无从生效），其共享前提与复评条件见任务 `02_02` 实施与测试记录。
2. **版本来源与偏斜检查**：共享依赖版本取自依赖清单（单一来源）；模块声明的版本与宿主不一致时按既定口径处置（告警 / 拒绝加载）并留痕。**实施口径**：单一来源为共享声明文件，版本不满足即**拒绝加载**并留痕（不留静默回退）；构建期与运行期双层断言依赖实例数为 1。
3. **构建期验证**：生产构建验证**无重复实例**（宿主 + 模块产物联合检查）。
4. **CI 断言**：以脚本 / 用例断言依赖实例数为 1（依赖实例数断言纳入门禁），失败即阻断。
5. **升级契约**：框架大版本升级视为**跨团队契约**（平台与模块协同升级），升级流程与兼容窗口成文。

**完成标准**：
1. 宿主与模块的共享依赖声明成文，`singleton` + `requiredVersion` 生效；
2. 生产构建无重复实例；CI 依赖实例数断言可执行且纳入门禁；
3. 版本不一致场景有明确处置与用例；
4. 升级契约（大版本协同升级流程）成文；
5. （实施口径补充）共享面为受控白名单，非共享项登记理由、版本要求与体积阈值并受护栏约束。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9 治理表、《[架构设计 · 测试与质量](../../../设计/架构设计/32_架构设计_测试与质量.md)》「依赖与构建」

## 4. 需求 05-14：基座包发布版本化与共享域化（补充 · 2026-10-09） <a id="r05-14"></a>

优先级：2（高）｜**补充需求**（2026-10-09 立项，承接 [05-4](#r05-4) 与本域既有开放项）

**背景与动机**：真机走查（阶段七 RBAC `02_02` 用户记录页「用户分配」三子页签）暴露：mdm 插件经 `sys.user.detail.tabs` **真挂接成功**，但插件侧 `useModuleSlotField('userId')` 与宿主注入的提交器通道取值**失败**（面板示「当前页面未提供实体标识」）。机制判定根因：`@bms/core` / `@bms/ui-ep` 为**源码直出 + 版本 `0.0.0`**、宿主以 `resolve.alias` 消费 ⇒ MF 探测不到模块请求、无 provider 块 ⇒ 两侧**各自打包**一份。凡依赖「**模块级单例**」的机制在真机形态下均失效——显式上下文注入（`MODULE_SLOT_CONTEXT_KEY` 为 Symbol，两份实例即不相等）、注册表、模块 `api` 注入、`moduleI18n`、主题令牌等；插件的「路由参数回退」通道对**页签式宿主页**（无 `:id` 路由）不适用。故把基座包纳入共享域，使单例机制跨模块边界成立（原登记为 `02_02` 与 `06_03` 的**开放项**）。

**内容**：

1. **基座包产物形态与版本**：`@bms/core` / `@bms/ui-ep` 由「源码直出 + `exports` 指 `src`」改为「**构建产物 + 语义版本**」（`version` 起于 `0.1.0`、`exports` 指 `dist` ESM + `types`）；宿主与模块均经**包解析**消费，运行期请求须可被 MF 探测（`resolve.alias` 仅保留必要的 TS 路径映射）。
2. **共享声明单一来源**：`frontend/shared-dependencies.json` 把两包自 `notShared` 迁入 `shared`（`singleton: true` + `requiredVersion` 语义范围）；`shared-deps.mjs` 支持从产物包 `package.json` 读版本。
3. **提供 / 消费两侧**：宿主为提供方、模块为消费方（`import: false`，**不打包本地回退副本**；版本不满足即**拒绝加载**并留痕——沿用「宁可失败不静默双实例」口径）。
4. **门禁与实测**：构建期产物断言（无副本 / 依赖实例数 = 1）与运行期共享域条目数断言**覆盖两包**；白名单护栏与模块隔离护栏口径同步；**首屏与产物体积实测**（复刻 `02_01` 实测方法，含 `eager` 取舍与结论登记），必要时设阈值。
5. **验收（真机）**：宿主 dev + 本机发布存储 + `mdm-org` 产物下，插件侧可取到 `userId` 与宿主提交器通道（「插件草稿随宿主保存」链路打通）；上下文 / 注册表 / `api` / `i18n` 四类单例机制各 1 例通过。

**完成标准**：

1. 两包有语义版本与构建产物，宿主与模块均经包解析消费（MF 可探测）；
2. 共享声明单一来源内两包为共享项，`singleton` + `requiredVersion` 生效；构建期与运行期实例数断言覆盖两包并纳入门禁；
3. 真机下插件侧取到宿主注入的上下文与提交器通道（RBAC `02_02/_01` 的宿主收草稿链路真机可达）；
4. 首屏与产物体积实测有结论（含 `eager` 取舍），白名单 / 隔离护栏无回归；
5. 文档回写：`02_02` / `06_03` 开放项注销、本域 §7 待办与共享面单一来源同步。

**范围外**：生产 / 部署形态（制品库 / CDN / 部署侧清单）与版本协商机制（本期仍为「单例 + 拒绝」）。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9 治理表；[05-3](#r05-3) / [05-4](#r05-4) / [05-11](06_需求_具名插槽与插件挂接.md#r05-11)；阶段七 [07-11](../../07_RBAC基础模块/需求/02_需求_用户与角色.md#r07-11)（真机发现来源）
