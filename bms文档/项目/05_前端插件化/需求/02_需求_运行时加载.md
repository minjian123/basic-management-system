## 1. 域说明 <a id="intro"></a>

本域把横向模块接入从「接口预留」推进到「运行时真实加载」：宿主以 Module Federation 消费远端模块产物，模块独立构建、独立发布；同时以 `shared` 单例与版本偏斜检查保证框架级依赖不被重复打包（否则运行时会出现双实例、状态不通等难查问题）。

- **本域范围**：MF 接入与构建配置、模块独立构建产物与动态导入分包、`shared` 依赖单例与版本偏斜治理。
- **不做**：模块治理增强（依赖版本协商、灰度 / 蓝绿进阶、隔离增强、按模块 SLO）——随后续阶段或演进路线。
- **依据**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9「运行时组合（微前端，Module Federation）」与治理表「依赖共享与版本偏斜」、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.2、知识档案《[微前端](../../../资料/知识档案/微前端/01_微前端_总览.md)》。
- **用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。

## 2. 需求 05-3：Module Federation 接入与模块独立构建 <a id="r05-3"></a>

优先级：2（高）

**背景与动机**：阶段四只交付了加载器接口与本地演示模块，模块产物仍需随平台一起构建；不接入 MF 就无法做到「模块独立构建与发布」，产品页面将被绑在平台发布节奏上。同时若不做动态导入分包，模块与重组件会挤进首屏，违背既有性能预算口径。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9）：

1. **Module Federation 接入**：宿主作为 host 消费远端模块（`remote` 声明与入口解析），模块作为 remote 暴露自身注册声明与页面；**模块产物独立构建**（模块有自己的构建命令与产物目录，不并入主应用产物）。
2. **模块清单与加载对接**：加载器按模块清单（名称 / 入口 / 版本）解析远端并加载；清单字段与加载器版本字段口径与 `05-2` 一致（不重复定义两套）。
3. **动态导入分包**：模块页面与重组件一律异步加载、独立分包，**不进首屏**；模块产物纳入体积预算计量口径。
4. **构建期合并保留为过渡 / 存量形态**：平台自身页面与未迁移模块仍随平台构建发布；两种形态共存期间由清单配置区分，不做一次性迁移。
5. **演示验证**：本地 / 内网提供演示 remote，宿主运行时加载并注册其路由（不进入生产菜单）。

**完成标准**：
1. 演示模块**独立构建**产出独立产物，宿主**运行时加载**成功（非构建期合并）；
2. 动态路由生效、模块挂载与卸载正常、卸载无残留；
3. 模块产物不进首屏，体积预算门禁通过（模块产物单独计量）；
4. MF 配置与模块清单字段成文，`05-2` 加载器同接口复用；
5. `vue-tsc`、ESLint、Vitest、构建与体积预算全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》§9、《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》§7.2、《[架构设计 · 前端模块契约](../../../设计/架构设计/35_架构设计_前端模块契约.md)》

## 3. 需求 05-4：依赖共享与版本偏斜治理 <a id="r05-4"></a>

优先级：3（中）

**背景与动机**：运行时组合下，若 Vue / 路由 / 状态 / 组件库等框架级依赖在宿主与模块中各打包一份，会出现**双实例**（响应式与状态不通、组件上下文丢失），且问题只在运行时以疑难杂症形式暴露。须在接入初期就把 `shared` 单例声明与版本偏斜检查固化，避免后续模块越多越难收拾。

**内容**（架构 08 §9 治理表「依赖共享与版本偏斜」）：

1. **`shared` 单例声明**：框架级依赖（框架本体 / 路由 / 状态 / UI 组件库 / 核心包）在宿主与模块构建配置中声明为 `shared` 且 `singleton`，并声明 `requiredVersion`。
2. **版本来源与偏斜检查**：共享依赖版本取自依赖清单（单一来源）；模块声明的版本与宿主不一致时按既定口径处置（告警 / 拒绝加载）并留痕。
3. **构建期验证**：生产构建验证**无重复实例**（宿主 + 模块产物联合检查）。
4. **CI 断言**：以脚本 / 用例断言依赖实例数为 1（依赖实例数断言纳入门禁），失败即阻断。
5. **升级契约**：框架大版本升级视为**跨团队契约**（平台与模块协同升级），升级流程与兼容窗口成文。

**完成标准**：
1. 宿主与模块的共享依赖声明成文，`singleton` + `requiredVersion` 生效；
2. 生产构建无重复实例；CI 依赖实例数断言可执行且纳入门禁；
3. 版本不一致场景有明确处置与用例；
4. 升级契约（大版本协同升级流程）成文。
