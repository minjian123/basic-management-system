## 1. 交付摘要 <a id="summary"></a>

| 项 | 内容 |
| --- | --- |
| 交付内容 | 内置判定由「角色码 ∈ 配置常量」**改按 `sys_role.role_type` 列**；`role.protected_codes` 常量与系统参数**退役**；角色码**放开可改**（含内置角色）；`role_type` 不可改；全局 `BaseSchema` 改**严格模式**（请求体未知字段即拒）；前端解除角色码只读并展示类型；原型与文档同步 |
| 迁移 | `platform:tenant/0009_role_type`（加列 + 按缺省清单回填 + 降级删列） |
| 契约 | platform 公开契约升版（`RoleUpdateRequest` 增 `code`、`RoleItem`/`RoleDetail` 增 `role_type`）；**全局**严格化使 8 份契约快照全部同步 |
| 用例编号 | Kiwi **2267**（先登记取号，再落用例） |
| 结果 | 后端全量 **2093 通过 / 51 跳过 / 0 失败**；前端基座四包 **944 例**、宿主 **292 例** 全通过；文档门禁与本地预检全绿 |

## 3. 关键处置与偏差 <a id="deviations"></a>

| # | 事项 | 处置 |
| --- | --- | --- |
| 1 | 「按码禁建内置角色」行为**取消** | 新口径下自建 `system_admin` 等码的角色类型为 `custom`、**允许创建**（内置保护只看类型）；既有断言与端点用例同步改造 |
| 2 | 全局严格化的**连锁面** | 8 份契约快照全部新增 `additionalProperties: false`；前端类型重生成后零漂移校验通过；后端全量回归未见其它「多传字段」调用（前一轮唯一的 1 例失败即角色域断言，已修） |
| 3 | 迁移链新头 → 写死链头的断言 | 同步 `test_alembic_chains.py`（1 处）与 `test_migration_ops.py`（3 处）的期望值 `0008_user_tables → 0009_role_type` |
| 4 | 回填口径的**边界** | 迁移仅按缺省清单回填；若某租户曾用系统参数覆盖 `role.protected_codes`（现役无覆盖），其覆盖值随参数退役失效——**部署迁移前**须按其覆盖清单补 `role_type`（本项入 §6 遗留） |
| 5 | 前端依赖环境被污染（非本次代码） | `bms/frontend/packages/*/node_modules` 被 **mdm 前端工作区安装**改写（`api-types` 的 `tsc` shim 指向 mdm store、路径错拼），致 `pnpm run check` 的 `api-types` 类型检查失败；按依赖维护口径「还原 → `pnpm install --frozen-lockfile`（必要时删根 `node_modules` 触发全量重链）→ 外置」修复后全量通过 |
| 6 | 全量回归参数副作用（已识别） | 用 `-p no:logging` 跑全量会使依赖 `caplog` 的既有用例报 `fixture 'caplog' not found`（ERROR，非失败）；**干净口径复跑为 2093 通过 / 0 失败 / 0 错误**，该参数不入回归口径 |
