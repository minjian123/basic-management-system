## 2. 任务内容 <a id="content"></a>

1. **内置判定脱钩**：`sys_role` 增 `role_type` 列（`custom` 缺省 / `system` / `security` / `audit`）；内置判定改按该列；`role.protected_codes` 常量与系统参数**删除**（迁移按缺省清单 `system_admin` / `security_admin` / `audit_admin` 回填存量行）；`role_type` **不可修改**。
2. **角色码放开可改**：`RoleUpdateRequest` 增 `code`；服务层按 `role.code_pattern` 校验格式、按 `(code, deleted_at)` 校验唯一（排除自身）；**任何角色（含内置）均可改**。
3. **全局契约严格**：`BaseSchema` 置 `extra="forbid"`——请求体未知字段即拒（消除「带 `code` 更新被静默忽略」一类问题）；契约快照与前端类型同步重生成。
4. **前端**：角色码输入解除只读（新增 / 编辑均可改）；列表列与表单**只读展示角色类型**（内置标记改按 `role_type` 判定）。
5. **一致性回写**：概要设计 06（「修改角色含 code」表述冲突）修正；数据表设计 `sys_role.md`（新列 + 变更记录）；《数据库设计总览》登记；可交互原型同步（`09_角色管理/02_角色列表页.html`、`03_角色表单页.html`）。
6. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

内置判定按 `role_type` 生效（创建校验、停用 / 删除保护、响应 `builtin` 标记）；角色码可改且格式 / 唯一校验生效（冲突拒绝、自身豁免）；`role_type` 无修改入口；请求体未知字段被拒（角色更新带 `code` 不再静默忽略）；前端展示与原型一致；后端全量与前端全量回归通过。
