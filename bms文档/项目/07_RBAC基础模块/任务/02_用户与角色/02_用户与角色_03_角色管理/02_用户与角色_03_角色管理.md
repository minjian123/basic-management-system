## 2. 任务内容 <a id="content"></a>

1. **角色 CRUD 后端**：`GET/POST /api/v1/roles`、`GET/PUT/DELETE /api/v1/roles/{id}`；`code/name/status`，`(code, deleted_at)` 复合唯一；内置角色（系统 / 安全 / 审计）不可删改归属；删除前校验主体绑定与授权引用。
2. **主体绑定**：`GET/POST /api/v1/roles/{id}/subjects`、`DELETE /api/v1/roles/{id}/subjects/{subject_type}/{subject_id}`；`sys_role_assign` 支持 user / post / dept，post / dept 的 `subject_id` 引用 mdm 组织主数据 id（跨库 code / id 逻辑引用）。
3. **菜单 / 表单 / 动作授权**：`GET/PUT /api/v1/roles/{id}/permissions`；`perm_type=menu/form/action`；菜单→表单→业务推导、动作默认无；批量授权**单事务全量覆盖提交**（先删后插）并支持 `Idempotency-Key`。
4. **字段权限**：`GET/PUT /api/v1/roles/{id}/fields`；`sys_role_field`（`visible/editable`），默认全部可见可编辑、授予后收窄。
5. **动作数据范围**：`GET/PUT /api/v1/roles/{id}/data-scopes`；`sys_data_scope`（动作 → 规则表达式）默认无；保存前沙箱解析校验、规则结果强制叠加租户过滤。
6. **版本失效与审计**：角色 / 授权 / 主体绑定 / 字段 / 数据范围变更统一触发权限版本 +1（一次递增）并清理相应用户缓存；授权接口高敏感，记录操作人、前后差异与 IP，变更落字段级审计；三权分立约束（`07-6`）。
7. **前端角色管理页**：角色列表、新建 / 编辑 / 删除、主体绑定、菜单 / 表单 / 动作授权树、字段权限矩阵、数据范围配置页签；经契约类型消费接口。
8. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

角色 CRUD 与引用校验正确、内置角色保护生效；主体绑定支持任意主体链（含 post / dept 引用 mdm id）；菜单→表单→业务推导正确、动作权限默认无；字段权限默认全开、收窄后读过滤 / 写拒绝生效；数据范围默认无、配置后读时过滤 / 写时校验双向生效且不跨租户；授权变更即时生效、批量授权幂等且单事务回滚；字段级审计可查；前端角色管理页功能齐备、`vue-tsc` / ESLint / Vitest 通过。
