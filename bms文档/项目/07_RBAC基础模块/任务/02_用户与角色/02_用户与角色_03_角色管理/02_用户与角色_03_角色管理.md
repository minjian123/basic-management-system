## 2. 任务内容 <a id="content"></a>

1. **角色 CRUD 后端**：`GET/POST /api/v1/roles`、`GET/PUT/DELETE /api/v1/roles/{id}`；`code/name/status`，`(code, deleted_at)` 复合唯一；内置角色（系统 / 安全 / 审计）不可删改归属；删除前校验角色分配与授权引用。
2. **角色分配**：`GET/POST /api/v1/roles/{id}/users`、`DELETE /api/v1/roles/{id}/users/{user_id}`（用户分配，维护 `sys_user_role`，与用户管理页「用户分配角色」同一张表）；岗位/部门分配数据与契约归 mdm 组织域（`org_role_post` / `org_role_dept`），经插件挂接，bms 不提供其写接口。
3. **菜单权限 / 表单权限授权**：`GET/PUT /api/v1/roles/{id}/permissions`；`perm_type=menu/action`（表单查看由菜单连带）；**菜单 ↔ 表单多对多**（关联表 `sys_menu_form`）、表单→业务推导；操作 / 字段权限默认无 / 全开、带**来源**（`source_menu_id`，本入口连带可改 / 非本入口来源只读）；「表单权限」页签列所有表单（含无入口表单）作补充授权；批量授权**单事务全量覆盖提交**（先删后插）并支持 `Idempotency-Key`。
4. **字段权限**：`GET/PUT /api/v1/roles/{id}/fields`；`sys_role_field`（`visible/editable`），默认全部可见可编辑、授予后收窄。
5. **数据权限**：`GET/PUT /api/v1/roles/{id}/data-permissions`；`sys_data_scope` 按**基础数据字典**结构化（数据选择 / 数据区域 / 数据匹配 / 扩展权限，**只选不编**）默认无；匹配值通配符受控校验、扩展权限参数存 JSON 交扩展自行解析；四类并集兜底、强制叠加租户过滤。
6. **版本失效与审计**：角色 / 授权 / 角色分配 / 字段 / 数据权限变更统一触发权限版本 +1（一次递增）并清理相应用户缓存；授权接口高敏感，记录操作人、前后差异与 IP，变更落字段级审计；三权分立约束（`07-6`）。
7. **前端角色管理页**：角色列表、新建 / 编辑 / 删除、角色分配、菜单权限（菜单入口的操作 / 字段）、表单权限（所有表单的操作 / 字段）、数据权限（基础数据字典 → 选择 / 区域 / 匹配 / 扩展）配置页签；经契约类型消费接口。
8. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

角色 CRUD 与引用校验正确、内置角色保护生效；角色分配（用户分配内建 + 岗位/部门分配经 mdm 插件）正确；权限分层正确（勾选菜单入口连带表单查看）、操作权限默认无、来源判定正确（本入口连带可改 / 非本入口来源只读）；字段权限默认全开、收窄后读过滤 / 写拒绝生效；数据权限只选不编、配置后读时过滤 / 写时校验双向生效且不跨租户；授权变更即时生效、批量授权幂等且单事务回滚；字段级审计可查；前端角色管理页功能齐备、`vue-tsc` / ESLint / Vitest 通过。
