## 2. 任务内容 <a id="content"></a>

1. **宿主提交注册通道**：角色记录页「角色分配」页签（`RoleAssignTab.vue`）在具名插槽上下文中注入**提交器注册**（约定键 `registerSubmitter`；插槽上下文仍为开放键值对象、浅冻结，**基座与机制不改**）；插件挂载时注册其提交函数、卸载时注销。
2. **保存编排**：角色记录页工具栏「保存」＝ ① **platform 本地事务**提交（角色本体 + 权限配置 + 用户分配，沿用既有覆盖提交与 `Idempotency-Key`）→ ② **mdm 两插件草稿提交**（`org_role_post` / `org_role_dept` 全量覆盖，携带同一业务幂等键）→ ③ 任一步失败：**按序反向补偿**（重试；超限落**死信**，处置＝**幂等重放**，**禁止手工改数据**）→ ④ 经**一致性屏障**（`BaseConsistencyBarrier`，超时 `10011` / 409 可重试）校验后返回；**「排除 2PC / XA」属默认路径口径**（非技术不可行）——本场景属「**部分完成业务上不可接受**」，**跨服务原子性已拍板改走强一致**（TM + 各服务 XA 分支，bms `05_07`）；**过渡期**仍按本条基线执行。
3. **脏数据与取消**：插件草稿计入角色记录页「脏数据」判定（保存拦截 / 离开确认沿用既有口径）；「取消」清空全部草稿（用户分配 + 两个插件）。
4. **降级与权限**：无 `org:update` 时插件子页签不渲染、其草稿不参与提交；插件未注册 / 不可达时按降级（子页签隐藏，保存仍提交 bms 部分，mdm 部分不参与、不阻塞）。
5. **列构成约束（宿主侧）**：宿主不提供插件列表的解绑入口（插件列表零操作列由 mdm 侧保证）；本任务不新增页面。
6. **一致性回写**：概要设计 06、组件设计 07《权限配置》、`01_01` 消费约定、原型 `09_角色管理/03_角色表单页.html`。
7. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

一次「保存」完成 platform 与 mdm 两侧提交（幂等键一致、失败可重试且**不静默放行半套状态**、反向补偿生效、屏障校验通过）；插件草稿计入脏数据判定并被「取消」清空；无 `org:update` 与插件缺失时降级正确、不阻塞 bms 部分；前端全量（基座 + 宿主）与后端受影响范围回归通过；原型与文档一致。
