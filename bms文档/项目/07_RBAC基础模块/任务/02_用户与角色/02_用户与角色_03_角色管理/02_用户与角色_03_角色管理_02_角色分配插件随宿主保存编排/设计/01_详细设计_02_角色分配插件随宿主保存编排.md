## 1. 设计目标与范围 <a id="goal"></a>

用户 2026-10-09 口径：组织域插件提交时机由「即时提交」改为**跟随宿主「保存」**，跨服务一致性由**宿主编排**。本子任务落**角色侧**编排（用户侧同口径切片归 `02_02` 嵌套子任务 `_01`；插件侧草稿改造归 mdm `01_02` 嵌套子任务 `_02`；**服务身份的写入通道**归 mdm `01_02` 嵌套子任务 `_03`）：

1. **宿主提交注册通道**：角色记录页「角色分配」页签经具名插槽上下文注入**提交器注册**（约定键 `registerSubmitter`；上下文为开放键值对象、浅冻结，**基座与机制不改**），插件挂载时注册提交函数、卸载时注销。
2. **后端编排端点**：角色记录页「保存」只发**一次**请求（全量载荷）；bms platform 先**本地事务**落「角色本体 + 权限配置 + 用户分配」，再以**服务身份**调 mdm 内部写端点落两插件分配；失败**快照回滚 + 重试**；写后**必经一致性屏障检查**。
3. **跨服务通道（mdm 侧）**：mdm 新增**内部写 / 基线读取 / 收敛版本**三类内部端点（`require_service("platform")` 白名单、不经网关、与只读出口双通道同构）——归 mdm `01_02` 嵌套子任务 `_03`。
4. **脏数据与取消**：插件草稿计入页面脏数据判定（保存拦截 / 离开确认沿用既有口径）；「取消」清空全部草稿（用户分配 + 两插件）。
5. **降级与权限**：无 `org:update` 时插件子页签不渲染、其草稿不参与提交；插件未注册 / 不可达时子页签隐藏，保存仍提交 bms 部分、mdm 部分不参与且不阻塞。

**不在本期**：不改具名插槽基座与区域项注册机制；不引 2PC / XA；不启用 Saga（判据不成立）；不做「跨服务自动重放队列」之外的人工干预后台（待人工项先落清单与日志）。

## 2. 口径与决策 <a id="decision"></a>

| # | 待定项 | 结论 |
| --- | --- | --- |
| 1 | 编排落点 | **后端编排**：角色页只发一次保存请求；bms platform 落本地事务后以服务身份调 mdm（同一幂等键）——补偿 / 幂等 / 屏障全在后端 |
| 2 | 补偿形态 | **快照回滚 + 重试**：保存前记两侧**基线快照**；任一步失败按序**反向写回**已成功的一侧（同源幂等键），重试超限落**待人工清单**并返回明确错误 |
| 3 | 屏障 | **本次接真实现**，且**每次跨服务写后必经检查**：通过即过；未通过**立即报错中断**（`10011` / 409 可重试），**后继功能一律依赖屏障结果决定是否执行**，不静默放行半套状态 |
| 4 | 跨服务写入通道 | mdm 新增**内部写端点**（`require_service("platform")` 白名单）；**不改**管理面鉴权（实测：管理面 `require_auth` 只认网关边缘身份 / 用户令牌 `aud=api`，服务 JWT 会被拒） |
| 5 | 幂等键 | **宿主编排生成同一业务幂等键**，作为 bms 编排请求与 mdm 内部写请求的共同 `Idempotency-Key`（重试同键，天然防重） |
| 6 | 屏障判据 | 采用 mdm 侧**租户级收敛版本**（`org:assign:applied:{tenant}`，写成功即推进）+ 内部只读查询；bms 编排侧**读后比对**「目标版本已达成」——**不做长等待**（立即判定，未达即报错） |
| 7 | 用例编号 | 后端 **2273**、前端 **2274**（平台自增为准，登记后回填） |

**派生口径**：

- **编排请求契约**：`PUT /api/v1/roles/{id}/grants-orchestrated`（**新增**，全量覆盖语义）——载荷＝既有授权载荷（菜单 / 表单 / 操作 / 字段 / 数据权限 + 用户分配）＋ 两个插件草稿（`post_ids` + `primary_post_id`、`dept_ids` + `primary_dept_id`）；响应返回两侧**生效结果**（便于前端刷新与脏数据基线更新）。
- **快照来源**：保存前经 mdm 内部**基线读取**端点取当前两分配集合 + 主要项；bms 侧基线取授权与用户分配的现值（读已有端点）。
- **失败分支**：① bms 本地事务失败 → 直接返回，未触 mdm（无补偿需要）；② mdm 写失败 → **按快照反向写回 bms 侧已成功部分**（同键补偿请求）→ 仍失败落待人工 + 返回 `10011`；③ 屏障不过 → 同上返回 `10011`（可重试），**不返回成功**。
- **降级**：mdm 不可达（`330101` 同族）→ 若插件草稿为空（用户未改插件）则**跳过 mdm 调用**、保存照常成功（bms 部分）；若草稿非空则整单失败并提示（不与本体形成半套状态）。
- **审计与日志**：编排每一步（bms 侧提交 / mdm 侧提交 / 补偿 / 屏障判定）写结构化日志并落审计占位；待人工项进统一清单（沿用审计阶段口径，先落日志与表登记）。

## 3. 编排协议与时序 <a id="protocol"></a>

```text
角色记录页「保存」
   └─(1) PUT /api/v1/roles/{id}/grants-orchestrated   [Idempotency-Key = K]
        bms platform：
          a. 读基线（授权 / 用户分配 + 经 mdm 内部读端点取两分配基线快照）
          b. 本地事务：角色本体 + 权限配置 + 用户分配（先删后插全量覆盖）
          c. 服务身份调 mdm：
             PUT /api/v1/org/internal/role-posts/{role_id}   (post_ids + primary_post_id, K)
             PUT /api/v1/org/internal/role-depts/{role_id}   (dept_ids + primary_dept_id, K)
          d. 屏障：GET /api/v1/org/internal/applied-version  → 比对目标版本
               达成 ⇒ 返回成功（含两侧生效结果）
               未达成 / mdm 失败 ⇒ 按 a 的快照反向补偿 b 侧 ⇒ 返回 10011（可重试）
```

| 方法 | 路径 | 归属 | 说明 |
| --- | --- | --- | --- |
| PUT | `/api/v1/roles/{id}/grants-orchestrated` | bms platform（新增） | 编排保存入口（全量载荷 + 幂等键） |
| PUT | `/api/v1/org/internal/role-posts/{role_id}` | mdm（新增，`_03`） | 角色-岗位全量覆盖 + 主要岗位 |
| PUT | `/api/v1/org/internal/role-depts/{role_id}` | mdm（新增，`_03`） | 角色-部门全量覆盖 + 主要部门 |
| GET | `/api/v1/org/internal/role-posts/{role_id}` / `.../role-depts/{role_id}` | mdm（新增，`_03`） | 基线读取（快照用） |
| GET | `/api/v1/org/internal/applied-version` | mdm（新增，`_03`） | 收敛版本查询（屏障判据） |

## 8. 风险与遗留 <a id="risk"></a>

| # | 风险 / 事项 | 处置 |
| --- | --- | --- |
| 1 | 补偿本身失败（两侧均不可达） | 落待人工清单 + 结构化日志 + 返回 `10011`；不返回成功、不静默放行 |
| 2 | 屏障「立即判定」在慢收敛下误报 | 收敛版本由 mdm 写成功时**同事务后**推进，正常路径即时可达；偶发未达按可重试错误处理；如需放宽可后续加**有界等待**（配置化，本期不做） |
| 3 | 编排端点载荷变大（含两插件草稿） | 全量覆盖语义下为 id 清单（小体量）；网关请求体上限足够（阶段二已改 32m） |
| 4 | 用户侧同口径编排（`02_02/_01`）复用本设计 | 抽取共享编排器（第 4 节 #2/#3），用户侧只换主体与插件集合 |
| 5 | 待人工清单无后台 | 先落日志与表登记，处置后台随审计 / 运维阶段；在计划 §7 台账登记 |
