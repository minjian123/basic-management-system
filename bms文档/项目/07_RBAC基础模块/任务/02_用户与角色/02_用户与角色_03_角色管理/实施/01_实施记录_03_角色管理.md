**结果小结**：角色域 5 表与 `sys_user` 同在 platform 服务租户库，**用户分配与最小用户查询同库完成**；角色 CRUD / 用户分配 / 菜单·表单·操作·字段·数据权限授权全量覆盖自平台侧闭环（授权目标经同服务平台库校验）；菜单 ↔ 表单改**多对多**（`sys_form` 去 `menu_id`、新增 `sys_menu_form`），platform 公开契约因破坏性变更升 **0.2.0**；前端交付通用「表单框架」机制（`FormFrame` + 页签 store）与角色管理页（列表 Tab + 记录 Tab + 权限配置容器 + 系统信息通用件）；定向用例与基座 / 文档门禁全绿。

## 3. 实施过程 <a id="process"></a>

1. **待决项确认（本轮 4 项）**：解绑后再分配语义（恢复原行）、最小用户查询端点落点（`api/users.py`）、`GET /forms` 的 `menu_id` 语义（保留参数改按关联过滤）、「系统信息」子页签实现方式（新增 ui-ep 通用件 `SysInfoPanel`）——逐项 question 确认后回显汇总表再执行。
2. **后端·用户分配**：新增 `services/platform/src/bms_platform/services/role_assign.py`（`RoleAssignService`）；`repositories/role.py` 增 `get_deleted_by_role_user` / `restore` / `soft_delete_by_role_user` / `list_filtered_by_role` / `count_filtered_by_role`（用户属性经同库子查询过滤）；`repositories/user.py` 增 `list_by_ids`。
3. **后端·最小用户查询**：`services/users.py` 增 `UserQueryService`（+`USER_STATUSES`）；新增 `api/users.py`（`/api/v1/users`，`user:query`，仅最小字段）。
4. **后端·角色 API**：新增 `schemas/role.py`（角色 / 分配 / 授权 / 字段 / 数据权限的请求与响应契约，含清单包装类型以支持幂等键结果复用）；新增 `api/role.py`（`/api/v1/roles` 及 `users` / `permissions` / `fields` / `data-permissions` 子资源；**双库依赖**：租户库 `get_uow` 写 + 平台库 `get_platform_uow` 只读元数据校验；`POST /roles/{id}/users` 与 `PUT /roles/{id}/permissions` 接 `Idempotency-Key`，范式同 `api/icon.py`）；`api/router.py` 登记两 router。
5. **后端·服务事务口径修复**：SQLAlchemy 2.0 下「先读后 `uow.begin()`」会抛 `InvalidRequestError`（会话已自动开启事务）——把 `RoleService.create_role/update_role/delete_role`、`RoleGrantService.replace_permissions/replace_fields/replace_data_scopes`、`RoleAssignService.assign_users/unassign_user` 的读 + 写统一收进 `async with self._uow.begin():`（口径同 `AccountLockService`）。
6. **后端·数据权限校验补强**：`_validate_data_scopes` 增加**字典类型存在性**校验（所有策略，不只 `match`），新增 `_dict_type_exists`。
7. **后端·`sys_data_scope.config` 列类型修正**：由裸 `JSON` 改 `StableJson`（写入前经 `normalize_collections` 规整集合类、读回递归转插入序集合类），与 `sys_dict_attr.operators/options` 同口径；`api/role.py` 的 `_data_scope_item` 随之简化。
8. **platform 返工（`sys_menu_form` 多对多）**：
   - 模型：`models/menu.py` 新增 `SysMenuForm`（`menu_id` / `form_id` + 复合唯一），`SysForm` 去 `menu_id` 与 `uq_sys_form_menu_id_deleted_at`；
   - 表归属：`TABLE_OWNERSHIP` 新增 `sys_menu_form`（`platform` / `PLATFORM`），`sys_form` 备注更新；
   - 迁移：新增 `platform/platform/0008_menu_form_multi.py`（建表 → 按 `sys_form.menu_id` 幂等搬迁（软删表单随其 `deleted_at` 一并落软删）→ `batch_alter_table` 删列与唯一约束；downgrade 加回可空列 + 按首个生效入口回填 + 删表，容器化说明见文件头）；
   - 仓储：`MenuFormRepository`（`list_all` / `list_by_menu` / `list_form_ids_by_menu` / `list_by_form` / `get_by_menu_form` / `delete_by_form` / `delete_by_menu`），`FormRepository` 去 `get_by_menu`；
   - 服务：`menu.py` 快照 `form_by_menu` → `forms_by_menu`（`SnapshotMenu.forms` 列表，新增模块级 `_snapshot_form`）、`list_forms(menu_id)` 改按关联过滤、`create_form` / `update_form` 改 `menu_ids`（全量替换关联）、`delete_form` 同步解除关联、`delete_menu` 改按关联判引用；`my_menu.py` 改多表单（任一表单业务码被授予即保留入口；`_to_form` 抽为方法）；
   - 契约：`schemas/menu.py`（`FormCreateRequest` / `FormUpdateRequest` 改 `menu_ids`，`FormItem.menu_id` → `menu_ids`，`MyMenuNode.form` → `forms`）；`api/menu.py`（`_service` 注入 `MenuFormRepository`，`_form_item(row, menu_ids)`）；
   - 种子：`ops/seed_menu.py`（表单按 `business_id` upsert + 经 `sys_menu_form` 关联入口；`role` 业务码文案改「角色管理」；建表清单含 `sys_menu_form`）。
9. **契约与类型**：`bms_platform/__init__.py` `CONTRACT_VERSION` `0.1.0` → **`0.2.0`**；`SERVICE_CATALOG` 的 `sys` 记录同步 `contract_version="0.2.0"`；`ops.contract_snapshot export` 重生成 9 份快照；`ops.contract_gate baseline-update --service platform` 更新基线；`pnpm --filter @bms/api-types gen` 重生成前端类型；宿主 `stores/menu.ts` 改多表单（`node.forms`，全部进表单索引，按路径取首个为主表单）。
10. **前端·ui-ep**：新增 `layout/FormFrame.vue`（列表 Tab 固定 / 记录 Tab 可关、脏标记、`beforeClose` 关闭拦截、`#list` / `#record` 插槽、`open` / `close` / `activate` 事件）与 `display/SysInfoPanel.vue`（系统信息通用件，字段：主键 / 版本 / 表单 / 创建人·时间 / 更新人·时间）；两件均经基类投影组合式（`useBaseLayout` / `useBaseDisplay`）挂继承链；`src/index.ts` 导出；护栏用例 `tests/form-frame.spec.ts` / `tests/sys-info-panel.spec.ts`；`layout-style.spec.ts` 冻结范围 18 → **19 件**。
11. **前端·宿主**：新增 `stores/tabs.ts`（页签管理：列表固定、记录增删、脏态、`close` 拦截 + `discard` 强关）、`api/role.ts`、`api/user.ts`（契约类型 + ID 字符串口径载荷）；新增 `views/system/RoleView.vue`（表单框架宿主：三段式列表、多选批量删除、双击开记录）、`views/system/RoleRecordTab.vue`（三子页签 + 工具栏单一保存 + 脏态上报）、`views/system/role/RolePermissionConfig.vue`（四页签容器，前三页签「待组件库 08_04 返工」空态）、`views/system/role/RoleAssignTab.vue`（用户分配：选择用户弹窗 + 已分配列表 + 挂起变更随宿主保存）；`router/index.ts` 静态注册 `/sys/roles`；`packages/core/src/domain/menu.ts` 的 `PLACEHOLDER_MENU` 作废 `/system/role` 占位；用例 `tests/{tabs-store,role-api,role-view}.spec.ts`。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 现象 | 处置 |
| --- | --- | --- | --- |
| 1 | **先读后 `uow.begin()` 抛错**（SQLAlchemy 2.0） | 服务方法内先查询再 `async with self._uow.begin()` → `InvalidRequestError: A transaction is already begun on this Session`（会话已自动开启事务） | 读 + 写统一收进同一 `begin()` 块（`RoleService` / `RoleGrantService` / `RoleAssignService` 共 8 处），与 `AccountLockService` 既有范式一致；已在 §6 登记为前序实现缺陷修复 |
| 2 | **`sys_data_scope.config` 落库报「非 JSON 序列化」** | 写入 `ConcurrentStableList[ConcurrentStableDict]` 时 `TypeError: Object of type ConcurrentStableDict is not JSON serializable` | 列类型改 `StableJson`（`process_bind_param` 经 `normalize_collections` 规整）；读回递归转插入序集合类 |
| 3 | **数据权限字典存在性校验缺位** | `select` / `region` 策略可用不存在的 `dict_type_id`（仅 `match` 经白名单触发校验） | `_validate_data_scopes` 增 `_dict_type_exists`（所有策略先校验字典类型存在） |
| 4 | **用例先读后写触发同一事务缺陷** | 服务级用例中「直接读断言 → 服务写方法」反复触发问题 1 | 用例侧约定：`helpers.commit()` 在每次服务调用前结束当前事务；期望异常分支后改用**标量 ID**（回滚会过期 ORM 属性，再取属性会触发懒加载 → `MissingGreenlet`） |
| 5 | **容器内应用未用临时租户库** | 端点用例里应用读到的仍是开发租户库（`database/bms/bms_tenant_demo.db`），出现跨次运行残留数据 | 端点用例改为**自建应用夹具**（`role_client`：`ApplicationFactory().create(None)` + lifespan + 依赖覆盖），确保租户库环境注入**早于**应用与引擎解析；并清理早期误写入开发库的角色行 |
| 6 | **布局族冻结范围与新增件冲突** | `layout-style.spec.ts` 断言 18 件齐备，新增 `FormFrame` 后失败 | 护栏更新为 19 件（同一护栏继续覆盖样式齐备与无硬编码色值）；登记为需求 07-9 冻结范围 + 02_03 新增件 |
| 7 | **EP `v-loading` 指令在测试/宿主未接线** | 项目内此前无 `v-loading` 用法，指令解析依赖未确认 | 改用语义等价的加载提示文本（表格数据驱动渲染），避免引入未验证的指令接线 |
