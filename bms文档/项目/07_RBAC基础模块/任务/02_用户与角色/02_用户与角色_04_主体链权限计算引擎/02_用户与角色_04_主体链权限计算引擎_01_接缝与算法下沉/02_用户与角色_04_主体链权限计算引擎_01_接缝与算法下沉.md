## 2. 任务内容 <a id="content"></a>

1. **新增元数据接缝**：在共享基座定义「权限元数据来源」契约（业务码 / 动作码 / 按钮与入口元数据取数），与既有角色解析器、字段权限 provider 接缝同构；各服务按自身装配注入实现。
2. **下沉计算主流程**：把权限聚合算法（角色集合 → 授权 → 码集 / 入口集）、快照计算、缓存读写从服务包迁入共享基座，只依赖既有与新增接缝，不碰任何 ORM、不 import 任何服务包。
3. **下沉四策略求值器**：数据范围四策略（`select` / `region` / `match` / `extension`）的求值逻辑迁入共享基座（纯算法，不碰 ORM）。
4. **插件化登记**：引擎以 `permission` 插件键登记实现，经 `[permission].provider` 切换；契约版本经插件机制校验主版本兼容。
5. **服务侧装配改造**：platform 注入「直查本库」实现，identity 注入「经契约取数」实现，使两服务 `require_permission` 真实生效（不再恒放行）。
6. **下沉边界守住**：角色 / 授权 / 元数据的仓储与模型留在服务侧，表归属登记与建表链不变；`owner` 语义按「表在哪里，归属就在哪里」不变。
7. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

判定与计算实现在共享基座，`bms_core` 不依赖任何服务包、不碰任何 ORM；元数据接缝定义并接入；platform 与 identity 两服务接入后 `require_permission` 真实生效（不再恒放行）；判定在进程内、单请求只取一次快照；`[permission].provider` 可切换且契约版本校验生效；表归属与建表链零变更；既有 platform 侧权限用例全绿、覆盖率达标、`preflight --fast` 全绿。
