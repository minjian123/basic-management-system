## 1. 背景与目标 <a id="goal"></a>

[`02_04` 主体链权限计算引擎](../../02_用户与角色_04_主体链权限计算引擎.md)（需求 07-4）已交付真实 RBAC 校验，但**实现落在 platform 服务包内**：`bms_platform.services.permission.PermissionService`（聚合 + 快照 + 缓存）、`bms_platform.permission.checker.RbacPermissionChecker`（判定）、`bms_platform.scope.rbac.RbacDataScope` 与 `bms_platform.scope.policies`（四策略）全部位于服务包，且直接 import `bms_core.models.platform.role` 与 `bms_platform.repositories.role`。

由此产生结构性缺陷：**其余服务无法复用真实权限校验**。共享基座 `bms_core.permission` 只有 `NullPermissionChecker`（`check` 恒 `True`），identity 等服务的 `require_permission` 实际恒放行（`api/session.py`、`api/clients.py`、`api/identity_providers.py`、`api/users.py` 共 5 个权限码）；而服务边界护栏（`check_service_boundaries.py` 规则 1/2）**禁止服务互相 import**，故无法经引用 platform 实现来补齐。

本任务把「**判定 + 计算**」下沉共享基座 `bms_core`：元数据接缝、计算主流程、四策略求值器、插件化登记与两服务装配改造；**数据访问（角色 / 授权 / 数据范围的仓储与模型）不下沉**，表归属与建表链零变更（《[后端开发规范](../../../../../../../规范/后端开发规范.md)》「模块边界与数据所有权」节的「代码下沉不改归属」口径）。

**目标**：

1. `bms_core` 内新增「权限元数据来源」与「权限数据来源」两个接缝，与既有角色解析器链 / 字段权限 provider / 校验链同构，各服务按自身装配注入实现。
2. 计算主流程（角色收敛 → 授权聚合 → 快照 → 缓存读写）与四策略求值器迁入 `bms_core`，**只依赖接缝**，不 import 任何服务包、不碰任何 ORM 模型。
3. 引擎以 `permission` 插件键登记 `rbac` 实现（基座内置登记），经 `[permission].provider` 切换，契约版本经插件机制校验主版本兼容。
4. platform 注入「直查本库」数据来源、identity 注入「经契约取数」数据来源，使两服务 `require_permission` **真实生效（不再恒放行）**。
5. 判定在进程内、单请求只取一次快照（沿用既有 `aprepare` 请求级预加载 + contextvar）。

**边界（不在本任务）**：

- **三层缓存与版本对齐**（基础数据 / 规则物化 / 用户快照三层进程内单份缓存、活动用户注销、容量护栏）归兄弟子任务 [`04-2`](../../02_用户与角色_04_主体链权限计算引擎_02_三层缓存与版本对齐/02_用户与角色_04_主体链权限计算引擎_02_三层缓存与版本对齐.md)。本任务**保持现有快照缓存与版本键不变**（决策 7）。
- **数据权限集合物化**（按规则共享、容量淘汰、大集合 SQL 形态、内存度量）归 [`04-3`](../../02_用户与角色_04_主体链权限计算引擎_03_数据权限集合物化/02_用户与角色_04_主体链权限计算引擎_03_数据权限集合物化.md)。
- **四策略口径修正**（与 `sys_data_scope` 表文件口径收口）归 [`04-4`](../../02_用户与角色_04_主体链权限计算引擎_04_四策略口径修正/02_用户与角色_04_主体链权限计算引擎_04_四策略口径修正.md)。本任务四策略求值器**逐行搬迁、行为零变化**（决策 8）。
- **前端**：无改动（权限概要仍经 `/api/v1/menus/my`，字段渲染归 `02_02`）。
- **数据库**：不新增表 / 列 / 索引 / 迁移；表归属登记（`TABLE_OWNERSHIP`）零变更。

## 4. 数据设计要点 <a id="data"></a>

不新增表。下沉后各接缝的数据形态如下（**均为基座中性结构，不含任何服务侧模型**）：

| 结构 | 字段 | 来源 |
| --- | --- | --- |
| `PermissionSubjectData` | `role_ids` / `role_types`（角色 id → `role_type`）/ `grants`（`perm_type` + `target_id`）/ `data_scope_rules`（`data_source_key` / `policy_type` / `config`） | 服务侧数据来源实现 |
| `PermissionMetadata` | `version` / `menu_forms`（菜单 id → 表单 id 列表）/ `permission_codes`（权限码 id → `业务码:动作码`） | 服务侧元数据来源实现 |
| `PermissionGrant` | `perm_type`（`menu` / `form` / `permission`）/ `target_id` | 授权行（`sys_role_permission`）映射 |
| `DataScopeRule` | `data_source_key` / `policy_type` / `config`（规则行列表） | 数据范围行（`sys_data_scope`）映射 |

**归属不变（强制）**：`sys_role` / `sys_user_role` / `sys_role_permission` / `sys_role_field` / `sys_data_scope` 仍建在 platform 服务租户库、`owner = platform`；`sys_menu` / `sys_form` / `sys_button` / `sys_permission` / `sys_field` 仍在 platform 平台库、`owner = platform`。`TABLE_OWNERSHIP` 与建表链**零改动**，`check_service_boundaries.py` 规则 5/6 不受影响。

**契约不变式**（对后代档位的承诺，沿用《[02_04 详细设计](../../设计/01_详细设计_04_主体链权限计算引擎.md#profile)》§11.2）：

1. 主流程五步不变：**角色收敛 → 聚合 → 快照 → 缓存 → 供数**；
2. 快照核心字段（`permission_codes` / `granted_menu_ids` / `granted_form_ids` / `data_scopes` / `field_perms` / `tier` / `profile`）语义**不变**，新增维度只进 `extensions`；
3. 校验入口签名 `BasePermissionChecker.check(code)` **不变**；扩展一律经 guard 链；
4. 数据范围策略经既有注册表（`bms_core.scope.policies`）扩展，核心不判策略类型；
5. 角色解析器链 / 字段权限 provider / 校验链 / 快照扩展位四个接缝**保持可替换**。

| 端点 | 方法 | 请求 | 响应 `data` | 说明 |
| --- | --- | --- | --- | --- |
| `/platform/internal/permissions/subject` | POST | `{"user_id": int}` | `role_ids` / `role_types` / `grants` / `data_scope_rules` | 按用户返回聚合所需**原始数据**（identity 侧本地跑同一引擎） |
| `/platform/internal/permissions/metadata` | GET | `?locale=` | `version` / `menu_forms` / `permission_codes` | 元数据批量取数（变更频率低） |

**白名单口径**：`subject` 与 `metadata` 只对 `identity` 开放（`platform` 自身直查本库，不经契约）；既有 `invalidate` 保持只对 `org` 开放。因同一 router 前缀承载两类白名单，按既有范式（`api/internal_users.py`）**拆两个 router**：`router`（`invalidate`，`require_service("org")`）与 `read_router`（`subject` / `metadata`，`require_service("identity")`）。

**失败语义**：非 2xx / `code != 0` / `data` 非对象 → 调用方（identity 数据来源）抛 `ServiceUnavailableError`（10007/503，fail-closed，**不降级为「无权限」或「全放行」**）。

### 5.3 校验器判定口径（下沉后不变）

| 项 | 口径 |
| --- | --- |
| 请求级预加载 | `aprepare(request)` 首次调用时按当前用户计算快照并写 `bms_core.permission.snapshot.current_permission_snapshot`；`request.state.permission_prepared` 标记保证**单请求只算一次** |
| 同步判定 | `check(code)`：无快照 → 拒（从严，提示依赖漏挂）；`snapshot.exempt` → 放行；码集不命中 → 拒；命中后经 guard 链（基础版空链） |
| 无用户上下文 | 服务身份 / 平台运营请求 → `tier = platform_admin` 快照（平台层豁免，边界由 `03_02` 机器护栏锁定） |
| 豁免 | `[permission].options.exempt_role_types`（缺省 `("system",)`）→ 命中即 `tier = system_admin` |
| 数据来源缺失 | `RbacPermissionCheckerFactory.create()` 时若无已登记数据来源 → **抛 `PluginError` 拒启**（决策 6） |

### 5.4 四策略求值器（下沉后不变）

`select` / `region` / `match` / `extension` 四求值器**逐行搬迁**自 `bms_platform/scope/policies.py`：非法 / 未注册规则一律退化为永假条件（`ScopeCondition("id", "in", [])`）并上报；`match` 通配符仅允许 `*` `?` 与中英文 / 数字 / 下划线；`region` 起 > 止即拒。**行为零变化**，与表文件口径的收口归 `04-4`。

### 5.5 服务装配口径

| 服务 | `prepare_settings` | 数据来源登记 | provider |
| --- | --- | --- | --- |
| platform | 未显式配置时置 `permission.provider = rbac` / `data_scope.provider = rbac` | `register_permission_data_source(PlatformPermissionDataSource(...))`（直查本库） | `rbac` |
| identity | 未显式配置时置 `permission.provider = rbac` | `register_permission_data_source(PlatformContractPermissionDataSource(service_client))`（经契约取数） | `rbac`（`data_scope` 保持 `null`：identity 无数据范围消费面） |
| 其余服务 | 不覆写 | 不登记 | `null`（占位，行为不变） |

**登记时点**：`prepare_settings`（早于 `register_platform_plugins` 与 `build_plugin_registry`）。数据来源注册表是**基座进程级模块级注册表**（与角色解析器链同构），`prepare_settings` 登记即可，无需等注册表冻结。

**幂等与隔离**：`register_permission_data_source` 同 key 覆盖；提供 `reset_permission_data_sources()` 供用例隔离（`bms_core.testing.fixtures.reset_plugin_registry` 不覆盖本注册表，测试侧显式复位）。

## 6. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 | 错误码 / 表现 |
| --- | --- | --- |
| `provider = rbac` 但服务未登记数据来源 | `RbacPermissionCheckerFactory.create()` 抛 `PluginError` | **启动即拒启**（明确提示需登记数据来源） |
| 数据来源取数失败（platform 查库异常） | 异常上抛，`aprepare` 失败 → 请求 500 / 业务错误码 | 不静默放行 |
| identity 调 platform 契约不可达 / 超时 / 非 2xx | `ServiceUnavailableError`（10007/503） | fail-closed，不降级为「无权限」也不放行 |
| identity 调 platform 契约返回 `code != 0` | `ServiceUnavailableError`（10007/503） | 同上 |
| 快照反序列化失败 | 视为未命中并重算（既有口径） | 请求仍正确 |
| 权限版本读失败（Redis 不可用） | 按 MISS 处理、直算不回写缓存（既有口径） | 请求仍正确，仅性能下降 |
| 元数据为空（无菜单 / 无权限码） | 码集为空、入口集为空 | 菜单 / 按钮不显示，接口拒（`30001`） |
| 授权行的 `target_id` 在元数据索引中缺失 | 该条不计入（与既有口径一致，未挂按钮的权限码不进索引） | 不越权 |
| 字段权限 provider 未登记（identity） | 字段全开（`field_perms` 为空） | identity 无字段消费面，不影响判定 |
| 四策略规则非法 / 未注册 | 退化为永假条件并上报（既有口径） | 该条不产生放行 |
| 无用户上下文（服务身份） | `tier = platform_admin` 快照 | 豁免（边界见 `03_02`） |
| 既有 platform 权限用例 | import 路径改为基座；断言口径不变 | 全绿 |

## 9. 决策确认 <a id="decide"></a>

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 元数据接缝形态 | **基座自定义中性元数据契约**（`PermissionMetadata`：菜单→表单、权限码 id→码、版本），不搬 platform 的 `SnapshotMenu` 系列；长期演进时元数据结构归基座 |
| 2 | 数据访问接缝 | **单一「权限数据来源」接缝批量取数**（`BasePermissionDataSource.load_subject` / `load_metadata`），一次取回角色集合 + 角色类型 + 授权行 + 数据范围规则；接缝数量最少、跨服务往返最少 |
| 3 | identity 取数粒度 | **取原始数据、在 identity 进程内跑同一引擎**——算法真正被多服务复用，判定完全在进程内，后续新增服务复用成本最低 |
| 4 | 下沉落点与文件划分 | `bms_core/permission/` 按职责分文件（`engine.py` 主流程、`sources.py` 接缝、`rbac.py` 校验器、`subject.py` 收敛服务）；四策略移入 `bms_core/scope/policies_rbac.py` |
| 5 | 插件登记与默认 provider | **基座内置登记 `rbac`**（不依赖任何服务包）+ 服务侧按需置默认（platform / identity 置 `rbac`，其余保持 `null`） |
| 6 | 未登记数据来源的处置 | **启动即拒启并明确报错**（与「未实现档位 fail-closed」同口径），不静默放行、不静默全拒 |
| 7 | 缓存边界 | **保持现有快照缓存与版本键不变**（`bms:{租户}:perm:{用户}:{版本}` + TTL）；三层进程内缓存与活动用户注销归 `04-2` |
| 8 | 四策略口径 | **只下沉、口径原样迁移**（行为零变化）；与表文件收口归 `04-4` |
| 9 | 配置项 | **复用既有选项，不新增**（`snapshot_ttl_seconds` / `exempt_role_types` / `require_org_roles`）；容量上限等由 `04-2` 统一加 |
| 10 | 本地验证范围 | **三套件全跑 + 变更模块覆盖率 100%**（共享底座变更退化全量） |
| 11 | Kiwi 用例粒度 | **一任务一条策展用例**（分类「平台骨架」、P2、`CONFIRMED`、标签「自动化」） |
| 12 | 契约与提交 | **重生成契约快照 + 前端类型**并保持零漂移；链内自动提交（详设 `docs` / 代码 `feat` / 记录 `docs` 分开），推送仍单独确认 |
