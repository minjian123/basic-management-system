## 2. 任务内容 <a id="content"></a>

1. **第一层·基础数据缓存**：角色 / 授权 / 数据范围 / 权限元数据在进程内**单份**缓存，按版本键失效（范式对齐既有菜单元数据缓存）。
2. **第二层·规则物化缓存**：数据范围规则求值结果（集合）在进程内**单份**缓存，按规则维度键控（与 04-3 共用物化载体）。
3. **第三层·用户快照缓存**：用户权限快照仅**活动用户**持有，按版本键失效。
4. **版本对齐机制**：三层均不落 Redis 共享（序列化与网络延迟不可接受）；一致性经**版本号**异步对齐——使用前查最新版本号，版本号可读内存 / Redis / 其他共享数据服务。
5. **活动用户追踪与注销**：记录用户最近活动时间；轮询任务注销超过 30 分钟不活动的用户快照；再次访问时即时重算并回填缓存。
6. **缓存容量护栏**：三层各自容量上限与淘汰策略，防内存膨胀；上限可配置、缺省保守。
7. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

三层缓存均按「进程内单份 + 版本号对齐」工作，不依赖 Redis 共享快照；版本变更后下一次使用即取到新版本（异步对齐、不要求跨副本同步时刻一致）；活动用户 30 分钟不活动后快照被注销、再次访问即时重算；三层容量上限生效且可配置；既有权限用例全绿、覆盖率达标、`preflight --fast` 全绿。
