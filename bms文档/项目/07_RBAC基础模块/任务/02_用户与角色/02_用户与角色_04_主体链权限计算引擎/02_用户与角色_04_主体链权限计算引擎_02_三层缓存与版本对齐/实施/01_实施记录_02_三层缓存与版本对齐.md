## 3. 实施过程与关键处置 <a id="process"></a>

### 3.1 三层缓存的载体落点（进程级单份，而非 app.state）

层2 由 `RbacDataScope.read_predicate()`（**同步**、无请求态）消费，若把缓存仓挂 `app.state`，同步消费方只能经全局访问器绕回。故按决策 1 落**模块级单份注册表**（与数据来源注册表、插件注册表同构）：

```text
_STORES: ConcurrentStableDict[str, PermissionCacheStore]  # 键 "default"
current_permission_cache_store()        # 惰性创建（缺省配置）
configure_permission_cache_store(options, snapshot_ttl=…)  # 装配期按配置重建
reset_permission_cache_store()          # 用例隔离
```

`ConcurrentStableDict` 的 `delete()` **键不存在即抛 `KeyError`**，复位与清理一律先判存在（首版直接 `delete` 导致全部用例 setup 阶段报错，已修）。

### 3.2 快照彻底移出共享缓存（Redis 只做版本号）

`PermissionEngine.snapshot_for` 改读缓存仓；`invalidate_permission_cache` 保留对旧键 `bms:{租户}:perm:{用户}:{版本-1}` 的**兼容删除**（升级前残留的 Redis 键），并在版本 +1 后清本进程条目。用例断言「共享缓存里不产生用户快照键」。

### 3.3 元数据与权限版本同源失效

`MenuService.invalidate` 追加权限版本 +1 与 `invalidate_metadata()`。此举修掉「元数据已新、快照仍旧」的错位（原先只能等快照 TTL）；一次建页含「建菜单 + 建表单」两次写，故平台用例按「版本至少 +1」断言，不锁死次数。

### 3.4 存量缺陷：真实规则行被静默丢弃（**执行期发现，用户确认后修正**）

`RbacDataScope._conditions` 原按 `isinstance(item, dict)` 过滤 `config` 行，而引擎产出的是 `ConcurrentStableDict`（`Mapping`，**不是** `dict` 子类；实测 `isinstance(...) == False`）——真实链路上的规则行被**静默丢弃**，`select` / `region` / `match` 都不产出条件，读过滤与写校验形同虚设；既有用例因测试侧用 `dict(...)` 构造而全部通过。

处置：改为 `_config_rows()` 按 `Sequence` / `Mapping` **协议**判定（与 `04-1` 实施记录 §3.4 同源处置），并补「真实行形态」回归用例 `test_mapping_rows_from_engine_produce_conditions`；四策略求值器零改动。已回写详细设计 §5.3 与决策 13。

### 3.5 闲置注销巡检的生命周期

`RbacPermissionChecker` 本就继承 `BasePluggable → BaseAsyncResource`，`assemble_plugins` 装配期调用 `setup()` 并登记 `ResourceManager`（关闭时逆序 `aclose`）——巡检任务经 `setup()` 起、`aclose()` 停，**不改装配入口**。单轮异常只记日志并继续（用例 `test_sweep_loop_survives_single_round_failure` 锁定）；阈值或周期非正即不启用。

### 3.6 裸集合护栏与基类继承护栏

首版缓存仓用内建 `dict` / `set` 注解，触发两条机器护栏：
`check_bare_collections.py`（集合声明须为插入序基座类）+ `test_base_inheritance.py`（自定义类须继承基类）。处置：内部账目改 `ConcurrentStableDict` / `ConcurrentStableSet`、`_Layer` 继承 `BaseFrameworkObject`、`int_option` 参数改收 `object` 并在内部按 `Mapping` 判定、`set_rule` 的值改收 `object` 并按 `len()` 计元素。两道护栏复跑全绿。

### 3.7 覆盖率分支收敛

首版多处「不可能分支」（索引与活动记录必然同步、写后必然登记账目）导致分支缺口，按「维护不变式、去掉不可达判定」收敛：`_drop_user` 直删索引、`clear_snapshots` 直删活动记录、层2 账目直取，仅保留「仅层1 用户无活动记录」这一真实分支。
