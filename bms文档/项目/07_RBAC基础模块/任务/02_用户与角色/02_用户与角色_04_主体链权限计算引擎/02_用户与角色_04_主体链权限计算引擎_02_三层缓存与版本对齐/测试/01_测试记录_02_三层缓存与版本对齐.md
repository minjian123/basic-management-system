## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 首版缓存仓用内建 `dict` / `set` 注解与无基类的 `_Layer`，触发 `check_bare_collections.py`（11 处）与 `test_base_inheritance.py`（1 处） | 改 `ConcurrentStable*`、`_Layer` 继承 `BaseFrameworkObject`、签名改收 `object` 并在内部按 `Mapping` 判定（见实施记录 §3.6） |
| 2 | 闲置注销用例首版误把 TTL 过期当成注销（默认 TTL 300s < 推进的 1799s） | 用例拉长 `snapshot_ttl`，只考察注销；并修正「命中即刷新活动时间」后的再闲置断言 |
| 3 | 平台用例断言权限版本「恰好 +1」不成立（一次建页含建菜单 + 建表单两次写） | 改为「至少 +1」，不锁死建页内部写次数 |
| 4 | `int_option(options: Mapping[...])` 与 `stats() -> dict` 等签名触发裸集合护栏 | 参数改收 `object`、返回改 `ConcurrentStableDict` |
| 5 | 首版多处「不可达分支」造成分支覆盖率缺口 | 按维护不变式收敛（实施记录 §3.7），保留唯一真实分支并补用例 |
| 6 | `preflight` 定向档 `-n auto` 下覆盖率数据合并出现随机缺口（同模块两次运行报不同分支） | 以串行采集为准复核（7 文件均 100%）；归口预检基础设施（实施记录 §6 第 5 项） |
| 7 | 平台单文件覆盖运行时曾出现 `test_form_keys_requires_auth`「插件注册表已构建」顺序敏感失败 | 单独复跑与三套件全量均通过；该失败由并行会话在改的注册表 `freeze` 与本文件无关，记录为观察项 |
