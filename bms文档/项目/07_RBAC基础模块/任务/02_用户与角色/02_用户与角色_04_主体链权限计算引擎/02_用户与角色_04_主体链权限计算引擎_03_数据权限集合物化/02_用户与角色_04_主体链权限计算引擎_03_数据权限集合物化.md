## 2. 任务内容 <a id="content"></a>

1. **集合物化载体**：规则求值产出集合（`ConcurrentStableSet`），在进程内物化持有；用户快照只持**规则引用**，不持集合内容。
2. **按规则共享**：同一规则被多个用户命中时共用同一份集合（不按用户复制），避免「用户数 × 集合大小」的内存放大。
3. **容量与淘汰**：集合物化层设容量上限与淘汰策略（按规则引用计数 / LRU），超限可降级为按需重算，不因物化而 OOM。
4. **大集合 SQL 形态**：读过滤不产出巨型 `IN (...)` 值列表——区域式 / 匹配式经 SQL 原生算子表达，扩展式与勾选式超出阈值时引导改用区域 / 匹配 / 扩展策略。
5. **内存度量**：物化层输出可观测指标（集合条数 / 总元素数 / 估算内存），供运维判断是否接近上限。
6. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注、实施记录与测试记录随任务留痕。

## 3. 完成标准 <a id="accept"></a>

集合按规则维度共享——N 个用户共用一条规则时集合只有一份（用例断言引用共享、内存不随用户数线性增长）；用户快照只持规则引用；容量上限与淘汰策略生效，超限不 OOM；大集合场景下 SQL 不出现巨型 `IN` 列表；物化层指标可查；覆盖率达标、`preflight --fast` 全绿。
