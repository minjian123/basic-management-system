## 2. 任务内容 <a id="content"></a>

1. **服务间只读出口**：platform 新增 `POST /api/v1/platform/internal/users/query`（`require_service`，**签发方服务白名单 = mdm 组织服务键 `org`**；东西向直连不经网关），供 **mdm 组织域只读出口**（组织数据源 `users` / 名称回显 `resolve_names(user)` / 按用户解析角色 `user-roles`）取用户明细——**mdm 不跨库读 `sys_user`**。
2. **契约字段**：`id` / `username` / `name` / `status` / `phone` / `email`；**不返回**口令哈希与锁定字段，亦**不含组织字段**（~~`dept_id`~~ **2026-10-09 修订**：随需求 `07-11` **移除**——用户-部门关系整体归 mdm，见嵌套子任务 `_01`）。
3. **入参**：`keyword`（账号 / 姓名，大小写不敏感）/ `status`（enabled / disabled）/ `ids`（**限定集合**，非空时在集合内筛选）/ `page` / `size`（基座页码分页口径）。
4. **敏感字段口径**：手机 / 邮箱**原样返回**（内部端点、服务间可达）；**脱敏由消费方（mdm 出口）按其 `masked_fields` 接入**，本端点不做掩码。
5. **契约与门禁**：公开契约快照重生成（**加性变更**，基线无需更新）；`require_service` 用例、筛选与分页用例、`ids` 限定集合用例。
6. **边界**：用户完整域 CRUD / 启停 / 删除 / 重置密码仍归 [02_01](../02_用户与角色_01_用户完整域后端/02_用户与角色_01_用户完整域后端.md)；数据范围 / 脱敏真实策略归消费方与后续阶段。

## 3. 完成标准 <a id="accept"></a>

内部只读出口可用且仅服务身份可入（白名单外一律拒）；关键字 / 状态 / `ids` 限定集合 + 分页筛选正确；契约字段与需求 07-2 口径一致；公开契约快照零漂移；`pytest` / `ruff` / `pyright` 与本地预检全绿。
