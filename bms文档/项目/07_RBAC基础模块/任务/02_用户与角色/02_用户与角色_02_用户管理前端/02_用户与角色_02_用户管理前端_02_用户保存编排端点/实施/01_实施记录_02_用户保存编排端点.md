## 3. 关键口径 <a id="decision"></a>

- **分支执行＝一次请求**：一个分支＝一条 XA 事务＝一条数据库连接，分支内全部写入必须一次请求完成；因此「一个请求」限制的是**分支**而非整个事务（请求总数＝`begin` + 各分支执行 + `commit`）。
- **同分支多 op**：岗位 + 部门合并为**同一分支的同一请求**（`ops` 列表，按序执行）；任一 `op` 未登记即**整体否决**、不触碰引擎。
- **调用方驱动**：TM 只做协议与协调、不承载业务语义 ⇒ platform 自身分支**进程内执行**（不另开 HTTP），组织域分支经参与端点执行，提交 / 回滚 / 核验由 TM 驱动。
- **提交后副作用**：停用账号的会话失效、角色分配变更的权限版本 +1 一律**放在提交之后**尽力而为（不卷入两阶段窗口）。
- **写入口径沿用**：内置管理员保护（30009）、停用账号不可分配（30045，判定以**本次请求生效后状态**为准）、乐观锁冲突（10003）。
- **`provider = null` 顺序提交**：platform 本地事务 → 组织域内部写通道 `/api/v1/org/internal/*`（服务身份 `platform` + `Idempotency-Key`），**不做反向补偿**（mdm 已判为废路径）。
