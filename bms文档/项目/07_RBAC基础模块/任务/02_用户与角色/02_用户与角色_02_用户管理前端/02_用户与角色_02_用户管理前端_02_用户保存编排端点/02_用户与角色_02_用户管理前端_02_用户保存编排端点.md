## 2. 任务内容 <a id="content"></a>

1. **编排端点**：platform 新增 `PUT /api/v1/users/{user_id}/assignments`——一次请求分段**全量覆盖**：`profile`（可空；昵称 / 邮箱 / 手机 / 状态 / 乐观锁版本）+ `role_ids` + `user_posts`（岗位集合与主要岗位）+ `user_depts`（部门集合与主要部门）；用户不存在（30002）、内置保护（30009）、停用账号不可分配（30045）、乐观锁冲突（10003）等错误码沿用既有语义。
2. **双路径一致性**：`[transaction_manager].provider = "xa"` 时走 **TM 全局事务**（调用方＝platform：自身分支进程内执行、mdm 分支经 `/api/v1/txn/branches` 驱动，全分支 `PREPARED` 后由 TM 提交）；`provider = null`（dev / test 的 SQLite）走**顺序提交**（platform 本地事务 → mdm 内部写通道），**不做反向补偿**（mdm 侧已确认过渡期基线与屏障判据属废路径）。
3. **权限与幂等**：权限码**分段校验**（`profile` 非空需 `user:update`；角色 / 岗位 / 部门段需 `user:assign_role`）；接受 `Idempotency-Key`（同一业务幂等键重复提交返回同结果）。
4. **响应回带**：返回用户详情与三段生效后集合（角色清单 / 岗位标识与主要项 / 部门标识与主要项），供宿主页保存后刷新。
5. **同批后端小改**：账号锁定记录契约 `LockItem` 增 `username` / `name`（与 `sys_user` 同库关联，非破坏性新增字段）；`ops/seed_menu.py` 移除 `/sys/users` 表单元数据中的 `dept_id`（`org-select`）字段挂接（对齐需求 `07-11`）。
6. **契约与类型**：公开契约快照、契约基线与前端 `@bms/api-types` 同批重生成（零漂移）。
7. **测试与登记**：先登记 Kiwi 用例再编码；双路径用例分层（XA 路径由 CI `2pc` 作业覆盖真库两阶段；`null` 路径跑顺序提交分支）。

## 3. 完成标准 <a id="accept"></a>

`PUT /api/v1/users/{user_id}/assignments` 可用：`provider=xa` 下用户基本信息、角色分配与 mdm 岗位 / 部门分配**同批原子生效**（任一步失败全不生效），`provider=null` 下顺序提交可用且失败明确报错；权限码分段校验与幂等键生效；响应回带生效后集合；`LockItem` 含 `username` / `name`；`/sys/users` 字段元数据不再含 `dept_id`；契约快照、契约基线与前端类型零漂移；定向用例与基座校验全绿。
