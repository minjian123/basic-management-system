# 01 详细设计 · 用户管理前端

> RBAC 基础模块 · 02 用户与角色 · 子任务 02（需求 07-2 · 关联 07-11）

[文档首页](../../../../../../文档首页.md) › [02 用户与角色](../../02_用户与角色.md) › [02 用户管理前端](../02_用户与角色_02_用户管理前端.md) › 详细设计

## 1. 背景与目标 <a id="goal"></a>

阶段七用户完整域后端（`02_01`）、菜单 / 表单元数据挂接（`03_01`）、主体链权限计算（`02_04`）与用户账号归口平台（`02_05`）均已交付，但**用户管理页与账号锁定页前端尚不存在**（当前仅有阶段五具名插槽样例宿主页 `SysUserDetailView.vue`）。本任务补齐两页，并落地需求 [07-2](../../../../需求/02_需求_用户与角色.md#r07-2) 的界面与边界修订：用户与账号锁定均按「列表 Tab + 记录 Tab」组织，列表**无操作列**、状态列**内联开关**、筛选仅「关键字 + 状态」，用户列表**不含部门 / 岗位 / 角色列**（不硬依赖 mdm 对象）。

两个嵌套子任务分担专门职责：`_01`（「用户分配」页签与插件子页签挂接）与 `_02`（跨服务保存的编排端点）。本详设覆盖**父任务自有部分**并登记与两个子任务的职责边界。

## 4. 页面设计 <a id="pages"></a>

### 4.1 用户管理页（列表 Tab） <a id="list"></a>

| 区域 | 内容 | 接口 |
| --- | --- | --- |
| 工具栏 | 新增 / 刷新 / 关闭 / 删除（批量，危险）/ 启用·停用（批量）/ 重置密码（限单行选中） | `POST /users`、`DELETE /users/{id}`、`PUT /users/{id}/status`、`PUT /users/{id}/password` |
| 筛选 | 关键字（对应 `kw`，搜索范围用户名 / 姓名 / 手机号 / 邮箱）+ 状态 | `GET /users?kw=&status=&page=&size=` |
| 表格 | 多选 · 用户名 · 姓名（内置标记）· 状态（**内联开关**）· 最近登录；**无操作列** | 同上 |
| 分页 | 缺省每页 20，保留筛选与分页 | 同上 |

交互口径：

- **双击行**开记录 Tab（不设新增 / 编辑抽屉）；「新增」开空白记录 Tab 并直接进入编辑态；
- **状态内联开关**：复用 `PUT /users/{id}/status`（不新增 toggle 接口）；**停用为危险操作**，切换前二次确认；成功即刷新，失败回滚显示并提示错误码文案（内置管理员 `30009`）；状态仅表示 `sys_user.status`，账号锁定态归账号锁定页；
- **删除**：批量、二次确认；内置管理员与自身受 `30009` 保护、存在角色分配引用时 `30011` 拒绝；
- **重置密码**：弹窗输入新密码 + 「强制下次登录改密」；成功后全部会话失效；
- **不渲染导入 / 导出**（归口见 §2）。

### 4.2 用户管理页（记录 Tab） <a id="record"></a>

| 页签 | 内容 |
| --- | --- |
| 详细信息 | 用户名（新增可填、创建后只读）/ 姓名 / 手机号（脱敏 + `data:plain` 明文）/ 邮箱 / 状态；`locale` / `timezone` 与组织字段**不在本模块** |
| 用户分配 | 三子页签（角色分配 / 岗位分配 / 部门分配）——**由 `_01` 交付**，本详设只登记挂接位 |
| 系统信息 | 系统字段（`SysInfoPanel`）+ **SSO 身份绑定**只读区块（`GET /users/{id}/identities`，权限码 `sso:bind`；无绑定显示空态） |

工具栏：查看态＝修改 / 删除 / 刷新 / 关闭；编辑态＝保存 / 取消 / 关闭；右侧显示「有未保存变更」或保护提示。

- **保存**：编辑态下按「基础资料 → 分配段」一次提交（分配段存在时走 [`_02`](../02_用户与角色_02_用户管理前端_02_用户保存编排端点/02_用户与角色_02_用户管理前端_02_用户保存编排端点.md) 的编排端点；仅改基础资料时走 `PUT /users/{id}`）；乐观锁冲突（`10003`）提示「记录已被修改，已重新加载最新数据」并刷新；
- **新增**：`POST /users`（带 `Idempotency-Key`）；后端随机生成初始密码时**一次性回显**提示管理员留存；成功后进入编辑态并刷新列表与页签标题；
- **脏数据拦截**：关闭 / 离开记录页签前确认（`_01` 的插件草稿一并计入脏态）；
- **停用 / 新增**：停用账号的分配子页签只读；新增态分配子页签不渲染（提示创建后可分配）——判定与呈现归 `_01`。

### 4.3 账号锁定页 <a id="locks"></a>

列表 Tab：

| 区域 | 内容 | 接口 |
| --- | --- | --- |
| 工具栏 | 手动锁定（primary）/ 解锁（批量，随选中态启用）/ 刷新 / 关闭 | `POST /account-locks`、`PUT /account-locks/{id}/unlock` |
| 筛选 | 关键字（用户名 / 姓名）· 锁定类型 · 解锁状态 | `GET /account-locks?...` |
| 表格 | 多选（**已解锁行不可选**）· 用户名 · 姓名 · 锁定类型（标签）· 锁定时间 · 自动解锁时间 · 解锁状态；**无操作列** | 同上 |
| 分页 | 缺省每页 20 | 同上 |

映射口径：`锁定类型` → `lock_type`（`fail_limit` / `inactive` / `manual`）；`解锁状态` → `active`（未解锁 = `true`、已解锁 = `false`）；关键字 → `kw`；用户名 / 姓名经 `LockItem.username` / `LockItem.name` 回显（后端同批新增字段）。

记录 Tab：

| 区块 | 内容 |
| --- | --- |
| 账号锁定信息 | 只读：用户名 / 姓名 / 锁定类型 / 锁定时间 / 自动解锁时间 / 锁定人 / 锁定原因 |
| 操作 | 解锁（独立动作，不走表单编辑态；确认后调 `PUT /account-locks/{id}/unlock`，记录 `unlock_by` / `unlock_at`） |
| 解锁记录 | 只读表格：锁定时间 / 锁定类型 / 解锁人 / 解锁时间 / 解锁方式 |

**不含「修改密码」**（重置密码入口收敛到用户记录页）。

## 5. 权限与字段控制 <a id="perm"></a>

- **按钮显隐**（动作码）：新增 `user:create`、删除 `user:delete`、启停 `user:update`、重置密码 `user:reset_pwd`、手动锁定 `user:lock`、解锁 `user:unlock`、分配 `user:assign_role`、SSO 绑定查看 `sso:bind`；**列表无操作列**（编辑在记录页工具栏）；
- **字段权限**：基础资料字段按 `sys_role_field` 收窄（不可见不渲染、不可编辑禁用）；响应侧由后端收窄为「不返回」；
- **脱敏**：手机号 / 邮箱按脱敏标记展示（`138****5678`），持 `data:plain` 权限码时展示明文；
- **前端只做显隐**，真正鉴权在后端（`require_permission`）。

## 6. 契约消费与请求层 <a id="api-consume"></a>

- 宿主页面统一经 `@/api/request` 的 `get/post/put/del(service, path)`（服务段 → 前缀由 `serviceUrl` 单一来源组装），**不手拼前缀、不自建 HTTP**；
- 类型全部取 `@bms/api-types` 的 `platform` / `identity` 命名空间（`platform.components['schemas']`），契约快照与类型由后端同批生成（含 `_02` 新增的编排端点与 `LockItem` 新字段）；
- 雪花主键传输按既有口径**字符串化**（见 `api/role.ts` 的 `SnowflakeId`）。
