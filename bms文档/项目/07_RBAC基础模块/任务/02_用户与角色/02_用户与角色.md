## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段七需求域 02 的 4 条需求——[07-2 用户完整域](../../需求/02_需求_用户与角色.md#r07-2)、[07-3 角色管理](../../需求/02_需求_用户与角色.md#r07-3)、[07-4 主体链权限计算引擎](../../需求/02_需求_用户与角色.md#r07-4)、[07-10 用户（账号）归口平台](../../需求/02_需求_用户与角色.md#r07-10)，6 个子任务（`02_01` ~ `02_06`）。
- **端范围**：PC（后端 platform / identity / org 服务 + 前端用户管理 / 账号锁定 / 角色管理页）。
- **本域性质**：阶段七主线域——在阶段六 `sys_user` 最小模型与认证链路上补齐用户完整域、角色授权与主体链权限计算，是全部业务接口权限校验的基座。
- **术语边界（2026-10-07 用户澄清）**：**组织域＝集团 / 公司 / 部门 / 岗位 / 人员**（归 mdm，bms 原 `org` 服务已于 2026-10-07 退役，bms 与业务产品经 mdm 组织契约消费）；**用户＝系统账号**属权限 / 身份体系（归 platform）。二者不得混用——`sys_user` 阶段六落 org 服务租户库仅为历史落地，随 `02_05` 归口 platform。
- **组织主数据依赖**：用户归属部门与角色分配的岗位/部门链引用 mdm 组织主数据（`org_dept` / `org_post`），岗位分配经 mdm「用户分配岗位」插件（挂 `sys.user.detail.tabs`，见 `01_01`）；角色分配的岗位/部门链归 mdm（`org_role_post` / `org_role_dept`），由「岗位分配 / 部门分配」插件挂角色表单具名插槽；mdm 组织域未就绪时相关子项**降级 / 占位**，不阻塞其余功能。
- **依据**：《[架构设计 · 权限计算引擎](../../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》、《[架构设计 · 认证与会话](../../../../设计/架构设计/14_架构设计_子系统_认证与会话.md)》、《[概要设计 · 用户管理](../../../../设计/概要设计/03_概要设计_用户管理.md)》《[概要设计 · 角色管理](../../../../设计/概要设计/06_概要设计_角色管理.md)》、mdm《概要设计 · 岗位管理》。
- **执行序**：`02_05 用户账号归口平台`（用户 / 角色 / 授权同库收敛，先行）→ `02_03 角色管理` → `02_06 平台用户只读出口内部契约`（**跨仓协同，随 mdm 阶段一 `01_03` 提前实施**，为 `02_01` 前置）→ `02_04 主体链权限计算引擎` → `02_01 用户完整域后端` → `02_02 用户管理前端`（具体依赖与推进见[计划](../../计划/01_计划_RBAC基础模块.md)）。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：阶段六 `sys_user` 最小模型、会话踢出通道与锁定记录读写；阶段五 `06_01` 具名插槽基座（`01_01` 登记）；菜单 / 业务 / 动作码与表单字段元数据（`03_01`，角色授予对象）。
- **依赖与推进**：`02_05` 为 `02_03` 剩余部分（用户分配 / 最小用户查询）与 `02_01` 用户完整域的前置——用户表落点先定，角色分配与用户查询才能同库完成；依赖关系与推进见[计划](../../计划/01_计划_RBAC基础模块.md)。
- **风险**：mdm 组织域尚未启动，岗位分配与岗位/部门角色分配链无法真实联调——须按降级 / 占位推进并登记外部依赖；已部署环境若迁移执行顺序颠倒（先删 org 表后搬数据）将丢数据，须固定「platform 建表 → 数据搬迁 → org 删表」顺序；identity 内部契约改指期间两端版本不一致会导致登录链路不可用，须随一次发布切换；权限缓存版本失效若与授权写入不在同一事务，易出现授权已改而权限未生效；字段权限读过滤若漏接序列化层，敏感字段会越权返回；数据范围规则若未强制叠加租户过滤，可能跨租户泄漏。
