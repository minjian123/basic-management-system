## 1. 设计目标与范围 <a id="goal"></a>

在 **platform 服务租户库**（`sys_user` / `sys_user_role` / `sys_account_lock` / 角色域 5 表**同库**）落地用户完整域：

1. **用户 CRUD**：列表（关键字 4 字段 + 状态）、详情、新建（初始密码可选 + 强制首登改密）、修改（昵称 / 邮箱 / 手机，乐观锁）、软删除（`deleted_at`，用户名可复用）；
2. **启用 / 停用**：独立端点 + **即时失效会话**；列表状态列内联开关复用该端点（不新增 toggle 接口）；
3. **重置密码**：PBKDF2 重哈希 + 复杂度 / 历史策略 + `pwd_changed_at` / `pwd_history` / `pwd_reset_required` + 失效全部会话；
4. **账号锁定治理**：锁定列表 / 详情 / 手动锁定 / 手动解锁（**已交付**，本任务只做串接与删除时的关闭，见 §5）；
5. **角色分配查看**（只读，维护归 `02_03`）与 **SSO 身份绑定查看**（**归 identity 服务既有端点**，本任务不重复实现）；
6. **契约与安全**：`user:*` 权限码、`3xxxx` 错误码、`sys.user.*` 事件发射、敏感字段日志脱敏、内置管理员与自身保护。

**不含（归口）**：组织 / 岗位 / 部门（mdm 插件，需求 [07-11](../../../../需求/02_需求_用户与角色.md#r07-11)）；`locale` / `timezone`（个人中心）；前端页面（[02_02](../../02_用户与角色_02_用户管理前端/02_用户与角色_02_用户管理前端.md)）；三权分立互斥校验（`03_02`，本任务仅登记码 `30010`）；真实字段级审计落库（审计阶段，本任务按 `AuditCapturer` 占位接入）；重置密码通知投递（通知渠道当前为占位，见 §8）。

**跨服务面（仅两处）**：

| 交互 | 方向 | 通道 |
| --- | --- | --- |
| 失效某用户全部会话 | platform → identity | **identity 新增内部端点**（本任务交付 identity 侧 1 模块 + 契约） |
| SSO 身份绑定查看 | 前端 → identity | identity **既有** `GET /api/v1/users/{user_id}/identities`（权限码 `sso:bind`），platform 不重复 |

### 3.1 端点清单 <a id="api-list"></a>

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/v1/users` | `user:create` | 新建用户（支持 `Idempotency-Key`；初始密码可选） |

### 3.2 请求契约 <a id="api-req"></a>

| Schema | 字段 | 必填 | 说明 |
| --- | --- | --- | --- |
| `UserAdminCreateRequest` | `username` | 是 | 登录账号（1~64，去空白；租户内唯一，含软删后复用） |
| | `name` | 是 | 昵称 / 显示名（1~128） |
| | `password` | 否 | 初始密码；**不传则后端随机生成**；传则校验复杂度策略（30005） |
| | `pwd_reset_required` | 否 | 是否强制首登改密，缺省 `true` |
| | `email` / `phone` | 否 | 联系方式（格式校验：邮箱正则 / 手机号 6~32 位数字与 `+ -` ） |
| | `status` | 否 | 初始状态，缺省 `enabled`（取值 `enabled` / `disabled`） |
| `UserUpdateRequest` | `name` / `email` / `phone` | 否 | `None` = 不改；空串 = 清空（邮箱 / 手机） |
| | `version` | 是 | 客户端版本（`ge=1`，乐观锁比对） |
| `UserStatusUpdateRequest` | `status` | 是 | `enabled` / `disabled`（其余值 10001） |
| `UserPasswordResetRequest` | `new_password` | 是 | 新密码（复杂度 30005 / 历史重复 30006） |
| | `force_change` | 否 | 是否强制首登改密，缺省 `true` |

### 3.3 响应契约 <a id="api-resp"></a>

| Schema | 字段 | 说明 |
| --- | --- | --- |
| `UserItem`（列表行，**扩展**） | `id` / `username` / `name` / `status` / `last_login_at` | 新增 `last_login_at`（原型「最近登录」列）；不含联系方式 |
| `UserDetail` | `id` / `username` / `name` / `status` / `email` / `phone` / `last_login_at` / `version` / `created_at` / `updated_at` | 编辑表单用；**声明 `masked_fields`（`phone` / `email`）**，无 `data:plain` 权限时按脱敏掩码返回 |
| `UserAdminCreateResult` | `user: UserDetail` / `initial_password: str \| None` | `initial_password` **仅本次返回**（后端生成时为明文；调用方指定时回 `None`） |
| `UserDeleteResult` | `deleted: bool` / `session_revoked: bool` | 会话撤销是否成功（见 §5 失败分支） |
| `UserStatusResult` | `user: UserDetail` / `session_revoked: bool` | 停用时 `session_revoked` 有效 |
| `UserPasswordResetResult` | `reset: bool` / `session_revoked: bool` | 不回显新密码 |
| `UserRoleItem` / `UserRoleList` | `items: list[UserRoleItem]` | `role_id` / `role_code` / `role_name` / `role_type` |

> 统一响应 `ApiResponse[T]`；主键经基座序列化**字符串化**（雪花精度）。

## 4. 实现要点与取数口径 <a id="impl"></a>

### 4.1 分层与依赖注入 <a id="impl-di"></a>

```text
api/users.py（参数校验 + 权限依赖 + 响应组装，禁业务逻辑）
└── services/users_admin.py（UserAdminService：事务边界 + 保护校验 + 事件发射）
    └── repositories/{user,role,account_lock}.py（同库，作用域过滤）
services/user_sessions.py（UserSessionClient：调 identity 内部端点）
```

依赖注入（均自 `bms_core/api/deps.py` 导出）：`get_uow` / `get_password_hasher` / `get_password_policy` / `get_idempotency_store` / `get_audit_capturer` / `get_outbox_store` / 服务间客户端。

### 4.2 写路径与事务 <a id="impl-tx"></a>

| 操作 | 事务与顺序 |
| --- | --- |
| 新建 | `async with uow.begin()`：幂等键前置去重 → 用户名唯一校验 → 密码哈希（策略校验）→ `create` → 发件箱 `sys.user.created` → 提交；**踢会话不适用** |
| 修改 | `begin()`：取行（不存在 30002）→ `version` 比对（不符 `ConcurrentConflictError` 10003）→ 改字段 → 发件箱 `sys.user.updated` → 提交（**不踢会话**：仅资料变更） |
| 启停 | `begin()`：取行 → 内置 / 自身保护（30009）→ 状态校验（10001）→ 写 `status` → 发件箱 `sys.user.updated` → 提交；**提交后**调 identity 撤销全部会话（reason `user_disabled`） |
| 删除 | `begin()`：取行 → 内置 / 自身保护（30009）→ **引用校验**：仍存在角色分配则拒（30011）→ `soft_delete` → 关闭该用户未解锁锁定记录（`unlock_at` / `unlock_mode=auto`）→ 发件箱 `sys.user.deleted` → 提交；**提交后**撤销全部会话（reason `user_deleted`） |
| 重置密码 | `begin()`：取行 → 复杂度（30005）与历史（30006）校验 → 重哈希 + 写 `pwd_changed_at` / `pwd_history`（追加，保留近 `password.history_count` 条）/ `pwd_reset_required` → 发件箱 `sys.user.password_reset` → 提交；**提交后**撤销全部会话（reason `password_reset`） |

**关键口径**：会话撤销是**跨服务调用、不可回滚**，故一律**放在事务提交之后**；失败不阻断主流程（见 §5），由 `session_revoked=false` 与 error 日志暴露。

### 4.3 关键字与筛选 <a id="impl-filter"></a>

`UserRepository._filter_conditions` 的 `keyword` 由「`username` / `name`」扩展为 **`username` / `name` / `email` / `phone` 四字段 OR LIKE**（大小写不敏感，`%` / `_` 按既有 `_like()` 语义），`status` 精确，`ids` 限定集合保持（`02_06` 内部出口复用同口径，**该扩展对其为加性**）。`count_filtered` 同口径，避免分页总数漂移。

### 4.4 密码与策略 <a id="impl-pwd"></a>

- 哈希：`BasePasswordHasher.hash/verify`（PBKDF2 自描述串）；无顶层 `hash_password` 函数。
- 策略：`BasePasswordPolicy.validate`（复杂度）/ `reused`（历史，`parse_password_history` 解析 `pwd_history` JSON 数组）/ `history_count`（近 N 次，缺省 5）。
- **参数键名以代码为准**（原概要写的 `pwd.*` 作废）：`password.min_length` / `password.max_length` / `password.require_upper|lower|digit|symbol` / `password.forbid_username` / `password.max_age_days`（90）/ `password.history_count`（5）/ `account.inactive_lock_days`（180）。
- `pwd_reset_required` 与 `pwd_changed_at` 的登录期语义（超期置真、改密清假）属 identity / `CredentialService`，本任务只负责**重置密码写入**。

### 4.5 保护规则 <a id="impl-guard"></a>

| 规则 | 判定 | 错误码 |
| --- | --- | --- |
| 内置管理员保护 | 目标用户持有任一 `role_type ∈ {system, security, audit}` 的角色（`sys_user_role` ⋈ `sys_role`，同库） | 30009（**停用 / 删除**均拒） |
| 不得操作自身 | `目标 user_id == 当前登录 user_id`（`current_user_id()`） | 30009（停用 / 删除） |
| 引用校验 | 删除前 `UserRoleRepository.count_by_user > 0` | 30011 |
| 状态取值 | `enabled` / `disabled` | 10001 |
| 乐观锁 | 入参 `version` ≠ 行 `version` | 10003（`ConcurrentConflictError`） |

> `30010`（三权分立互斥）本任务**只登记码**，真实校验归 `03_02`；`30004`（账号已停用）归认证域登录判定，本任务不抛。

### 4.6 事件 <a id="impl-event"></a>

- **载荷修订**：`sys.user.created` / `sys.user.updated` / `sys.user.deleted` 的载荷移除 `dept_id`（与需求 `07-11` 一致；当前无生产者，零成本）；`sys.user.password_reset` 载荷 `{user_id}` 不变。
- **发射**：四个事件在对应写路径的**同一事务**内经 `BaseOutboxStore.enqueue(EventEnvelope(...))` 落发件箱（范式同 `services/menu.py`）。
- 契约快照重导出：`uv run python -m ops.event_contracts export`（`deploy/events/contracts.json` 零漂移）。

### 4.7 identity 内部端点（会话撤销） <a id="impl-identity"></a>

| 项 | 口径 |
| --- | --- |
| 路径 | `POST /api/v1/identity/internal/sessions/revoke-user` |
| 鉴权 | `require_service("platform")`（服务间直连不经网关；租户取服务 JWT `tenant` claim） |
| 请求 | `RevokeUserSessionsRequest{user_id: int, reason: str}` |
| 响应 | `RevokeUserSessionsResult{revoked: int}`（撤销的在线会话数，0 表示本就无在线会话） |
| 实现 | `session_scope(...) → SessionService.revoke_user_sessions(user_id, tenant=<claim>, reason=reason)`（**复用阶段六既有方法**，不改其语义） |
| reason 取值 | `user_disabled` / `user_deleted` / `password_reset`（新增常量；`password_reset` 已在 session 域定义） |
| 契约 | identity 公开契约重导出 + 前端 `@bms/api-types` 重生成（**内部端点入契约但不在网关注册路由**，沿既有内部端点口径） |

### 4.8 种子与权限码 <a id="impl-seed"></a>

- `ops/seed_menu.py`：`ACTION_SEEDS` 补 `user:assign_role`；「用户管理」页按钮挂接补 `assign_role`（与既有 `user:*` 按钮同页）。

- 改动后需重跑 `seed_menu` + `seed_rbac`（本地：`bash bms/scripts/tools/dev/本地全套.sh seed`；已部署库为运维步骤，登记 §8）。

## 5. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 用户不存在（含已软删） | `UserNotFoundError` **30002**（404） |
| `username` 已被占用（未软删行） | `UsernameExistsError` **30003**（409） |
| 停用 / 删除内置管理员或自身 | `UserProtectedError` **30009**（403） |
| 删除时仍存在角色分配 | `UserReferencedError` **30011**（409，提示先解除角色分配） |
| `version` 不匹配 | `ConcurrentConflictError` 10003（409） |
| 状态 / 分页 / 密码格式非法 | `ParamError` 10001 |
| 密码不符复杂度 / 命中历史 | 30005 / 30006（400，附 `violations`） |
| 新建未传密码 | 后端随机生成（长度与字符集满足策略），响应 `initial_password` 一次性返回 |
| 幂等键重复 | 基座 `IdempotencyStore.begin` 判定非首次 → 返回**首次结果语义**（不重复建号）；Redis 未配置时降级为唯一约束兜底（30003） |
| **identity 不可达 / 撤销失败** | **不阻断主流程**（库内变更已提交）；响应 `session_revoked=false` + `logging.error(extra={user_id, reason})`；运维可见并按需重试（登记 §8） |
| 跨租户 | 仓储租户过滤强制叠加（不可绕过）；内部端点由服务 JWT `tenant` 解析租户库 |
| 并发同建同名账号 | 唯一约束兜底 → 30003 |

## 9. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 会话踢出通道 | **identity 新增内部端点** `POST /api/v1/identity/internal/sessions/revoke-user`（`require_service("platform")`），复用既有 `SessionService.revoke_user_sessions`；本任务含 identity 侧小改动与契约重导出 |
| 2 | SSO 绑定查看落点 | **复用 identity 既有端点**（`GET /api/v1/users/{id}/identities`），platform 不重复、不转发 |
| 3 | 绑定端点权限码 | **沿用 `sso:bind`**；概要 §2.1/§5.1 与前端入口显隐按此回写 |
| 4 | `sys.user.*` 事件 | **移除 `dept_id`** 并真正发射四个事件（事务内发件箱）+ 事件契约快照重导出 |
| 5 | 列表口径 | 关键字 OR LIKE 覆盖 `username/name/email/phone` + `status`；列表行**新增 `last_login_at`** |
| 6 | 新建初始密码 | `password` 可选；缺省**后端随机生成**并在响应**一次性回显**；`pwd_reset_required` 缺省真 |
| 7 | 删除语义 | 软删 + 关停未解锁锁定记录（`unlock_at` / `unlock_mode=auto`）+ 撤销会话 + 发 `sys.user.deleted` |
| 8 | 角色查看返回面 | `role_id` / `role_code` / `role_name` / `role_type`（同库 join，只读） |
| 9 | 幂等键 | 用基座 `IdempotencyStore`（`Idempotency-Key` 头）+ 唯一约束兜底 |
| 10 | 权限码与种子 | 补 `user:assign_role` 动作码与按钮挂接；内置系统管理员补 5 个 `user:*` 授权（防自锁） |
| 11 | 撤销会话调用时机（实现侧推导） | **事务提交之后**调用（跨服务不可回滚）；失败不阻断、以 `session_revoked` 暴露 |
| 12 | 删除前引用校验（依概要 §7 `30011`） | 存在角色分配即拒删，要求先解除分配 |
| 13 | 内置 / 自身保护（依概要 §7 `30009`） | 停用与删除均校验；判定按 `role_type ∈ {system, security, audit}` |
| 14 | 错误码占用（依实际占用重排） | 30002 用户不存在 / 30003 用户名已存在 / 30009 受保护 / 30011 引用禁删；30004、30010 只登记不抛 |
| 15 | 密码策略键名（实现侧纠正） | 以 `password.*` / `account.inactive_lock_days` 为准，概要 §6.3 回写 |
