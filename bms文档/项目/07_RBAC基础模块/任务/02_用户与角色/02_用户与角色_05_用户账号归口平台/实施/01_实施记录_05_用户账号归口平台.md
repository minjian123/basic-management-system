**结果小结**：`sys_user` / `sys_account_lock` 由 org 服务租户库迁 **platform 服务租户库**；用户（系统账号）/ 角色 / 授权终态同服务同库、**零跨服务引用**；identity 登录 / SSO / 找回密码链路经 platform 内部端点不变语义；账号锁定管理面路径改 `/api/v1/account-locks`；公开契约与前端类型一致；定向用例与基座门禁全绿。

## 3. 实施过程 <a id="process"></a>

1. **立项四步**：需求域 02 顺延新增 [07-10](../../../../需求/02_需求_用户与角色.md#r07-10) 并同步需求总览（计数 9 → 10、总清单 +1 行、域地图 3 → 4）；新建任务 `02_05`（目录 `02_用户与角色_05_用户账号归口平台/`）与父任务清单；计划表登记 `02_05` 行、计数与统计行、后续窗口顺延（`02_03` 状态改「部分完成」并登记已交付 / 剩余）、§7 台账第 16 项状态改「已立项」。
2. **详细设计**：落《01_详细设计_05_用户账号归口平台》，7 项决策逐项 question 确认（迁走范围 / 锁定端点路径 / identity 命名 / 搬迁脚本落点 / 契约版本 / 表集门禁口径 / 迁移顺序与基线），齐备交付物清单、接口与失败分支、迁移与回滚、测试设计与登记落点。
3. **数据库设计回写**：`sys_user` / `sys_account_lock` 表文件（归属库 / ORM 模型 / 状态 / 迁移 / 变更记录）、总览登记两行所属库、`07_数据库设计_角色管理.md` §3/§4 与变更记录、`sys_user_role` / `sys_user_extension` / `sys_user_identity` / `sys_session` / `sys_user_tenant` 的引用方向措辞（跨服务 → 同库 / org → platform）。
4. **表归属与迁移**：`TABLE_OWNERSHIP` 中两表归属 `org` → `platform`（`sys_user_role` 备注同步为同库）；新增 `platform/tenant/0008_user_tables.py`（建两表，down = `0007_role_tables`）与 `org/tenant/0006_drop_user_tables.py`（删两表、down 复原，down = `0005_sys_outbox`）。
5. **后端搬迁**：`git mv` 迁入 platform —— 模型（`models/user.py`：`SysUser` / `SysAccountLock` + 锁定常量）、仓储、服务（概要 / 重置目标 / 统一建号、凭据、锁定治理）、契约 schemas、端点（内部凭据 / 内部用户 / 内部账号锁定 / 锁定管理面）；org 侧删除对应文件、`MODEL_MODULES` 收敛为空元组、路由仅留组织主数据占位；端点前缀改 `/platform/internal/*`、`/account-locks`。
6. **identity 改指**：`services/org_client.py` → `services/platform_client.py`（`PlatformCredentialClient`，`PLATFORM_SERVICE = "platform"`，四组路径改指）；schema 类 `Org*` → `Platform*`；api / services 全部引用方与测试替身同步（`FakeSsoPlatformClient` / `FakeOidcPlatformClient` / `FakePlatformClient`）。
7. **运维脚本**：`ops/seed_user.py` 归属服务改 `platform`、模型导入改 `bms_platform.models.user`；新增 `ops/migrate_user_tables.py`（跨库幂等搬迁：按主键 upsert、`--code` / `--all-tenants` / `--dry-run` / `--url`+`--target-url` 单库演练、单租户失败不中断、达梦走同步驱动线程）；`ops/check_tables.py` 脚本表集断言改「净新建」口径（整链汇总 `(建表 ∪ 批量改表) − 删表 ⊆ 链表集`）。
8. **契约与类型**：`ops.contract_snapshot export` 重生成 9 份快照（org 移除用户 / 锁定端点、platform 新增、identity 仅描述文案变化）；`contract_gate baseline-update --service org` 与 `--service platform` 更新基线；`pnpm --filter @bms/api-types gen` 重生成前端类型。
9. **用例搬移与新增**：org 侧 `tests/{credentials,users,account_lock}` 迁 platform 并改导入与路径；identity 客户端用例改名 `test_platform_client.py`；基座断言同步（链头 / 表集 / 迁移 ops 版本）；`check_tables` 新增「先建后删相抵」用例；新增 `test_migrate_user_tables.py`（幂等 / 同步路径 / 单库演练 / 参数校验 / 失败汇总）。
10. **顺带修复（发现即改，见 §4）**：`bms_platform/services/role_grant.py` 三个授权条目 dataclass 补 `BaseValueObject` 基类；`libs/bms_core/tests/core/test_object_bases_roots.py` 的 org 硬编码路径改 platform。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 机械改名后 `ruff` 报 E501 与 import 重复（同一模块多行导入） | 路径 / 类名字符串替换后行宽与导入合并需人工收敛 | `uv run ruff format` + `ruff check --fix`；全量 `ruff check` 通过 |
| 2 | 导入 `bms_platform.models.account_lock` 失败（模块不存在） | 账号锁定模型与用户模型同文件 `models/user.py`（迁移时仅替换服务前缀） | 统一改为 `bms_platform.models.user`；受影响用例与端点全部修正 |
| 3 | `check-bare-collections` 抓 `_chain_script_errors` 签名的 `list[Path]` | 集合声明须落插入序集合类（护栏覆盖函数签名） | 签名与调用点改 `ConcurrentStableList[Path]` |
| 4 | `test_all_app_classes_inherit_a_base` 红：`role_grant.py` 三个条目「无基类」 | `02_03` 新增 `PermissionGrantEntry` / `FieldGrantEntry` / `DataScopeGrantEntry` 为 frozen dataclass 但未继承框架对象基类 | 补 `BaseValueObject`（值对象语义一致）；属 `02_03` 遗留缺陷，本任务顺带修复并登记 |
| 5 | `test_object_bases_roots.py` 红：找不到 `services/identity/.../org_client.py` 与 org 服务用户文件 | 用例内硬编码源文件路径 | 台账条目路径与类名改 `platform_client.py::PlatformCredentialClient`、`bms_platform/services/{account_lock,users}.py` |
| 6 | Kiwi 用例编号需先取得 | 规范要求「先登记再编码」 | 经容器内 Django shell 登记取得 **2247**，再回填用例标注 |
| 7 | `sys_account_lock.user_id` 表文件原写「跨服务只持值」 | 与 `sys_user` 同库（org 时期即同库），措辞笔误 | 改「同库」，并随归属迁移统一为 platform 服务租户库 |
| 8 | `ops/check_tables.py` 历史建表脚本在归属迁出后误报越界 | 原断言按**单脚本**判定，无法表达「同链先建后删相抵」 | 改**整链汇总净新建**口径；新增配对放行用例，原越界拦截用例保留 |

## 6. 偏差与遗留 <a id="deviations"></a>

| # | 事项 | 归口 / 去向 |
| --- | --- | --- |
| 1 | 三库（MySQL / PostgreSQL / 达梦）真库迁移演练与已部署库搬迁执行 | 随部署窗口；顺序固定「platform 建表 → `ops/migrate_user_tables` → org 删表」（本记录与迁移脚本头注释均写明） |
| 2 | `ops/init_tenant.py` / `provision_tenant.py` / `migrate_tenants.py` 核查结论 | **无需改动**（按「服务 × 数据源 × 租户」通用编排，链路集由归属登记派生）；结论入本记录，不再改动代码 |
| 3 | `sys_session.user_id` / `sys_user_identity.user_id` 仍为跨服务逻辑外键（identity → platform） | 设计边界（identity 只持值、不直连 platform 表）；如需收敛另行立项 |
| 4 | 已部署库 `sys_user_role` 存量行 `user_id` 的核对 | 本地开发库重建免此步；已部署环境随搬迁窗口核对（`user_id` 为雪花主键，搬迁按主键保序） |
| 5 | `ops/check_tables.py` 净新建口径属**有意放宽**（同链先建后删相抵） | 已加配对放行用例与原越界拦截用例；口径写入模块 docstring |
| 6 | 契约基线更新（org 移除端点属预期破坏性变更） | 已 `contract_gate baseline-update`（org + platform），随本次提交入库并在此登记理由 |
