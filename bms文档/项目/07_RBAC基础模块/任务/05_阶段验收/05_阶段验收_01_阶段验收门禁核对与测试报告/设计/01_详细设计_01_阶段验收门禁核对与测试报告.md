## 2. 门禁核对对象与判定口径 <a id="criteria"></a>

**核对对象**：计划 §5「M7 验收门禁」现有 **7 行**，与《[总体项目规划](../../../../../../规划/总体项目规划.md)》阶段七行 7 条完成标准逐条对位——**不新增、不合并、不删减**（决策项 7）：主体链任意长度权限计算正确 / 越权与跨租户访问被拒验证通过 / 数据范围读写检查生效 / 字段权限生效 / 配额超限拦截生效 / 三权互斥生效 / 租户模块开关生效。

**判定口径**：

- 结论只取 **「达标」**；「机制与产物已交付、真实业务链路或部署形态留后续阶段」的项仍记「达标」，其后以「（限定：… → 计划 §7 第 N 项）」注明归口与去向。
- 本次核对前**先修口径漂移**（§4）：凡证据链依赖 mdm 跨服务调用的门禁行（第 1 / 2 / 4 行），一律以**修复后**的代码与用例为准，不以修复前记录下结论。
- **不出现「未达标」**：若修复后仍有确凿不达标项，停下报用户确认，不自行按「达标」写下（《[AI开发规范](../../../../../../规范/AI开发规范.md)》「随时可停」）。
- 证据形态固定三类：**任务测试记录**（命令与原始输出）、**GitLab 流水线号**（项目 `bms/bms`）、**Kiwi TCMS 用例编号**；计数字面值只作**收口当日快照**。

## 4. 跨仓口径对齐（本次修复方案） <a id="align"></a>

**事实**：mdm 于 2026-10-23 完成服务标识归并（mdm 阶段一 `01_05`，Kiwi 2348）——服务键 `org` → `mdm`、内部路径 `/api/v1/mdm/*`、对外路由 `/api/mdm/v1/mdm/*`、分支 `op` 前缀 `mdm.*`、权限码 `mdm:*`、契约文件 `deploy/contracts/mdm.json`。bms 侧消费方仍按旧口径，真实部署下形成**断链**：

| 断点 | 现象 |
| --- | --- |
| 服务键 `org` 已不在服务目录 | 服务间调用在 `validate_service_request` 即抛 `ParamError`，不发起调用 |
| 岗位 / 部门链角色解析 | 异常被吞 → 降级空集（严格模式 `InternalError`）：「主体链权限计算」缺组织链 |
| 用户 / 角色分配跨服务写 | 内部写通道与 XA 分支 `op` 均不可达，分配不落 mdm 库 |
| 服务身份白名单 `require_service("org")` | mdm 以 `sub=mdm` 签票 → 取用户明细被拒（`330101` fail-closed） |
| 前端 `productPrefix('mdm','org')` | 网关只有 `/api/mdm/v1/mdm` 路由 → 组织数据源 404 |
