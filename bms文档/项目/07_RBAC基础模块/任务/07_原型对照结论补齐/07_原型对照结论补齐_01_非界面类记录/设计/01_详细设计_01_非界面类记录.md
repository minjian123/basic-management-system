## 1. 设计目标与范围 <a id="goal"></a>

为门禁命中的**纯逻辑类**历史测试记录补写「原型对照结论」节（内容为「不适用 + 理由」），使 `check_prototype_review.py --changed` 对该批零命中，从而解除「变更集含界面源码即阻断推送」的积压。

- **范围内**：门禁命中清单中判定为**无界面可见变更**的记录（2026-10-12 基线 **44 份**，见 §3）。
- **范围外**：界面类记录（归 `07_02` / `07_03`）；门禁脚本与 `preflight` 挂接（已生效，不改）；历史任务的实现代码（只补文档）。

## 2. 判定口径与依据 <a id="rule"></a>

**判定为「非界面类」的充要条件**（两条同时成立，依据 §4.9「纯逻辑改动可写不适用并给理由」）：

1. 该记录所属任务的**交付物不含可渲染界面**——任务目录内不引用 `frontend/**/src/{views,components,layouts}/**.vue`，且未登记页面 / 组件原型依据；
2. 该任务为后端基座 / 服务化地基 / CI 流水线 / 数据拓扑 / 治理 / 阶段验收报告等**非界面**性质。

**存疑处理**：任一条不成立或证据不足者，**不作非界面类处理**——移交 `07_02`（件族）或 `07_03`（页面）按更严一类执行；宁可多截图，不可漏对照。

## 4. 逐份核对与补写步骤 <a id="steps"></a>

```mermaid
flowchart LR
    A["重跑门禁取清单"] --> B["逐份核对任务交付物无界面变更"]
    B --> C["在该任务 测试/*.md 增「原型对照结论」节"]
    C --> D["节内写「不适用」+ 理由（≥10 字，无未完成词）"]
    D --> E["复跑门禁 + preflight 该项"]
```

1. **取清单**：`python3 scripts/tools/base_check/check_prototype_review.py . --changed`，替换 §3 表。
2. **逐份核对**：对每条记录核对第 2 节两条判据，登记「任务 / 记录 / 判定 / 依据」四列结论（可增补于本设计或任务测试记录）。
3. **补写节**：在**该历史任务自身**的 `测试/*.md` 内新增 `## 原型对照结论`（标题须含「原型」），内容示例：

   ```markdown
   ## 原型对照结论

   不适用：本任务为<后端基座 / CI 流水线 / 治理>类交付，未产生任何界面可见变更（无页面 / 组件新增或改动），故无原型对照对象。
   ```

4. **避免未完成词**：节内不得出现 `待补` / `待对照` / `待核` / `未核对` / `待定` / `TODO` / `待办`。
5. **只增不改**：不改历史记录既有结论语义；发现的实现偏离另立修复项并回写对应历史任务。

## 6. 边界与开放项 <a id="boundary"></a>

- **命中集合动态收敛**：门禁按 `origin/main...HEAD` 校验；一旦推送，`origin/main` 前移，已推送部分不再被校验——**以执行前脚本输出为准**。
- **理由文本质量**：门禁只校验「不适用 + ≥10 字」，但理由须**如实说明该任务为何无界面可见变更**；不得以模板套话批量填充（本设计给出示例，逐份按任务性质改写）。
- **归类复核**：分类脚本规则见《[需求 07-12](../../../../需求/07_需求_原型对照结论补齐.md#r07-12)》；`04_API网关与边缘_01_01 前端网关接入改造` 等含前端改动但无界面交付者归本批，**执行时须再核一次**。
