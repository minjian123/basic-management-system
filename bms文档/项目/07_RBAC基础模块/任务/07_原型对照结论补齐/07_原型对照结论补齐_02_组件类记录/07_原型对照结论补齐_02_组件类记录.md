## 2. 任务内容 <a id="content"></a>

1. **取值清单**：执行前重跑门禁取**组件类**待补记录清单（2026-10-12 初判 **10 份**：阶段四 `02_基础组件类` 7 份 / `03_布局组件类` 2 份 / `08_交互类_03_01` 1 份），并并入 `07_01` 移来的存疑记录。
2. **定位原型依据**：逐份定位对应的 `设计/组件设计/**/NN_原型设计_XXX.html`（件族任务原型依据落此处，共 123 份可选），在该记录内以**相对链接**引用（文件须存在）。
3. **件族截图**：以宿主开发态核对页或既有组件核对入口渲染件族，真机 / 无头截图；截图落 `测试/资源/<记录名>/`，**不引入新机制**（沿用既有核对页，必要时只加核对项，不改组件实现）。
4. **补写「原型对照结论」节**：在各历史任务自身的 `测试/*.md` 内新增该节，含①表头含「结论」的**对照表**（列建议 `# / 对照项 / 原型依据 / 实现实测 / 结论`，按件族粒度**逐件落行**）与②**至少一张存在的 `.png` 截图**引用；结论取「对齐 / 偏离（附处置归口）」；节内不含未完成词。
5. **去实现命名核对**：逐件核对可见文本无类名 / 函数名 / 能力键 / 路径 / 包名；发现即登记修复项（归口对应件族任务）。
6. **门禁复跑**：复跑 `check-prototype-review.py . --changed` 确认本批零命中；再跑 `check-preflight.py --fast`。
7. **落点**：逐份清单与对照结论落在本任务 `设计/01_详细设计_02_组件类记录.md`（执行期以脚本输出刷新）。

## 3. 完成标准 <a id="accept"></a>

判定为组件类的记录**全部**含「原型对照结论」节（逐件对照表 + 存在性 `.png` 截图 + 组件设计原型引用 + 去实现命名核对行），无未完成词；截图均为实际渲染结果；偏离项均已登记归口；复跑 `check-prototype-review.py . --changed` 对该批零命中；`check-preflight.py --fast` 该项通过；组件实现未被改动。
