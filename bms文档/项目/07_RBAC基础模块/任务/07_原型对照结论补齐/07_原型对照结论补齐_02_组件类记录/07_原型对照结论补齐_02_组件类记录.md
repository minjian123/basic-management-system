## 2. 任务内容 <a id="content"></a>

1. **取值清单**：执行前重跑门禁取**件族**待补记录清单（2026-10-12 初判 10 份：阶段四 `02_基础组件类` 7 份 / `03_布局组件类` 2 份 / `08_交互类_03_01` 1 份），并并入 `07_01` 移来的存疑记录；**执行期归类（2026-10-12 逐项确认）**：`02_基础组件类` 7 份交付物为**框架无关纯 TS 基类**（无渲染面）**改判非界面类**（按「不适用 + 理由」补节），故本任务按「件族逐件对照」执行的为 **4 份**（`03_布局组件类_01`、`03_布局组件类_02`、`08_交互类_03_01`、`07_01` 移入的 `01_扩展点与装配_02`）；两组清单见详细设计 §3.1 / §3.2。
2. **定位原型依据**：逐份定位对应的 `设计/组件设计/` 下件族自带原型 `NN_原型设计_XXX.html`（件族任务原型依据落此处，共 123 份可选），在该记录内以**相对链接**引用（文件须存在）。
3. **件族截图**：以宿主开发态核对页或宿主真机渲染件族，真机 / 无头截图；确无渲染入口的件族以组件设计原型页渲染作原型基准；截图落 `测试/资源/<记录名>/`（命名 `原型-*.png` / `实现-*.png`），**不引入新机制**（沿用既有核对页，必要时只加核对项，不改组件实现）。
4. **补写「原型对照结论」节**：在各历史任务自身的 `测试/*.md` 内新增该节，含①表头含「结论」的**对照表**（列建议 `# / 对照项 / 原型依据 / 实现实测 / 结论`，按件族粒度**逐件落行**）与②**至少一张存在的 `.png` 截图**引用；结论取「对齐 / 偏离（附处置归口）」；节内不含未完成词。
5. **核心基类族改判项**：`02_基础组件类` 7 份（框架无关纯 TS 基类，无渲染面）按「不适用 + 理由」补节，详见详细设计 §3.2。
6. **去实现命名核对**：逐件核对可见文本无类名 / 函数名 / 能力键 / 路径 / 包名；发现即登记修复项（归口对应件族任务）。
7. **门禁复跑**：复跑 `check-prototype-review.py . --changed` 确认本批零命中（并顺带修正 `07_01` 遗留的通配占位写法误报）；再跑 `check-preflight.py --fast`。
8. **落点**：逐份清单与对照结论落在本任务 `设计/01_详细设计_02_组件类记录.md`（执行期以脚本输出刷新）。

## 3. 完成标准 <a id="accept"></a>

判定为**件族（有渲染面）**的记录（4 份）**全部**含「原型对照结论」节（逐件对照表 + 存在性 `.png` 截图 + 组件设计原型引用 + 去实现命名核对行）；改判为非界面类的核心基类族（7 份）**全部**含「不适用 + 理由」节（理由 ≥ 10 字）；各节无未完成词；截图均为实际渲染结果；偏离项均已登记归口；复跑 `check-prototype-review.py . --changed` 对**本批零命中**（余 8 份页面类归 `07_03`）；`check-preflight.py --fast` 的「界面：check-prototype-review」项待 `07_03` 收口后转绿（本任务只保证本批零命中，不越权代做）；组件实现未被改动。
