## 2. 任务内容 <a id="content"></a>

1. **问题定位**：现有停用校验只覆盖 HTTP / RPC 入口（中间件 → 403 / `80002`）；消息消费、定时任务、事件消费等异步路径不经过 HTTP，停用租户仍可能产生副作用。
2. **基类能力**：在基类体系新增「租户可用性」基类（如 `BaseTenantGuard`），提供统一的同步 / 异步校验入口，复用现有 `RemoteTenantSource`（全局版本戳，停用即时生效），**不新建缓存**。
3. **三种使用形态**：HTTP 依赖（沿用中间件）、异步循环守卫（消费 / 任务每轮校验）、批处理前置检查（一批开始前校验一次）。
4. **产品扩展**：产品可继承基类并扩展自有实现（如消息平台在消费入口继承、补充命名空间校验）。
5. **分支语义**：未知租户、已停用、租户源不可达三种分支的错误码与降级口径明确，与 HTTP 入口一致。
6. **登记与验证**：基类登记到《后端基类治理台账》；提供继承示例与用例。

## 3. 完成标准 <a id="accept"></a>

- 基类可用于异步任务与消息消费入口，停用租户在这些路径被拦截。
- 校验复用基座租户源，不引入第二套缓存或状态判断。
- 产品继承示例可运行（以 msg 消费入口为例），且不修改基类代码。
- 三种分支的错误码与 HTTP 入口一致，不出现「HTTP 403、异步静默继续」。
- 基类已在治理台账登记，文档（基类实现契约第 4/6 节）同步。
