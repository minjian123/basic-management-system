## 2. 任务内容 <a id="content"></a>

1. **注销语义缺失**：当前只有「停用 / 启用」，没有「注销」；产品侧因此不敢做数据清理，长期占用磁盘且无法真正退租。
2. **注销流程定义**：停用 → 数据归档（可选）→ 产品侧清理 → 注册表标记 → 保留期后物理清理；每一步的状态与可回退边界明确。
3. **不可逆与确认**：注销与物理清理必须二次确认，并留审计；保留期内可恢复，保留期后不可逆。
4. **产品侧清理契约**：产品如何感知注销、清理什么、失败如何重试；与 04-04 的初始化契约对称。
5. **编码变更约束**：`code` 允许变更（库名冻结），但**产品侧内部键一律用 `tenant_id`**，禁止用 `code` 做目录名、缓存键、事件键；写入产品接入规范并在代码护栏中检查。
6. **事件补充**：如需要新增 `tenant.deleted` 契约，按事件契约流程登记版本与字段。

## 3. 完成标准 <a id="accept"></a>

- 注销流程有状态机与文档，明确每个状态的进入 / 退出条件与可回退性。
- 物理清理有保留期与二次确认，操作留审计。
- 产品侧清理契约有明确接口或事件约定，msg 有落地示例（停用保留、注销清理）。
- 编码变更约束写入产品接入规范，且能通过静态检查或评审清单发现违规用法。
- 新增事件（若有）已登记契约与版本。
