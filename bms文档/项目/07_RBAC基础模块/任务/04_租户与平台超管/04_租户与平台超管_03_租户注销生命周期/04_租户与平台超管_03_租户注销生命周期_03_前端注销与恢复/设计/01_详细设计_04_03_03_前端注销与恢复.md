## 3. 交互要点 <a id="key"></a>

| 位置 | 规则 |
| --- | --- |
| 动作可见性 | 注销：`status ∈ {active, suspended}`；恢复：`status = deleted` 且（`purge_at` 为空或未到）；其余隐藏 |
| 确认弹窗 | 手动输入租户编码（不做大小写宽松匹配），不匹配即禁用提交；原因选填（≤ 200 字） |
| 提示文案 | `82014` → 编码不匹配；`82003` → 当前状态不允许；`82015` → 已过保留期不可恢复（需运维介入） |
| 状态列 | 「已注销」标签；清理时点取 `purge_at` 展示为日期，为空展示「待归档」 |
| 保护动作 | 平台租户（`kind = platform`）不显示注销入口——列表接口按 `kind = business` 取数，平台租户不进列表；后端亦拒（`82003`） |
| 提示分码 | 后端按码给 4xx / 409，请求层须保留业务码（`82014` / `82003` / `82015`）才能分别给文案；无业务码时才回落缺省语 |

## 4. 施工顺序 <a id="steps"></a>

1. 可交互原型 → 评审 → 结论记录；
2. 类型生成（契约快照）；
3. 接口封装（`deleteTenant` / `restoreTenant`）；
4. 页面：动作列、确认弹窗、状态列、筛选；
5. 组件 / 页面用例；
6. 原型对照结论 + 实施 / 测试记录 → 计划回写。

## 5. 用例与验收 <a id="tests"></a>

| 组 | 覆盖 |
| --- | --- |
| 动作可见性 | 四种状态 × 平台 / 业务租户的动作组合；过期不可恢复时隐藏恢复 |
| 确认校验 | 未输入 / 输错禁用提交；输入正确才请求；原因超长被拦 |
| 错误提示 | `82014` / `82003` / `82015` 三条分别展示对应文案，不混用 |
| 展示 | 清理时点格式化；`purge_at` 为空展示「待归档」；筛选「已注销」可命中 |

- 原型对照结论按《原型审查规范》§4 记录，未通过不进阶段验收。

## 6. 前置与风险 <a id="risk"></a>

| # | 项 | 处置 |
| --- | --- | --- |
| 1 | 原型未定稿就写代码 | 阻塞施工步骤 2~5；原型先评审 |
| 4 | 列表项缺 `purge_at` 导致「清理时点」与恢复可见性无据 | 列表项补**只增可选**字段（响应契约不需版本抬升），快照与前端类型同批重导 |
| 5 | 4xx 业务码被折成 `10001`，三条拒绝提示不可分 | 请求层把「响应体带 `code`」作为通用上抛条件，401 原有刷新逻辑不变 |
| 2 | 手写响应类型漂移 | 一律由契约快照生成，改后端契约后重跑生成脚本 |
| 3 | 误把「注销」做成一次点击即生效 | 必须手动输入编码二次确认；后端也强校验，前端不作为唯一防线 |
