## 1. 本子任务范围 <a id="scope"></a>

父设计 §4.6（回填）与 §4.7（物理清理）的落地。**前置**：`-01` 已交付 `status = deleted`、`deletion_requested_at` / `purge_at` 两列与 `tenant.purged` 契约——本子任务不改表、不改事件契约，只消费它们。

- **不做**：注销 / 恢复端点（`-01`）；前端（`-03`）；归档执行器本体；备份校验（开放项，见父设计 §9.1 第 4 项）。
- **不新增表**：清理留痕复用作业执行记录 + 事件 + 审计日志三处。

## 3. 关键实现要点 <a id="key"></a>

0. **周期触发不是 `BaseTask`**：`BaseTask` 插件位自 01_02 起不再扩容，周期任务统一走「`sys_task` 内置任务 → 提交作业」。故 `tenant.purge.scan` 由内置任务 `purge_deleted_tenants` 每日提交，扫描与清理都在 tenant 服务作业里做（基座不跨库删库）。
1. **扫描与提交分离**：`tenant.purge.scan` 只做「回填 + 查到期 → 提交作业」，不内联删库；单租户一个作业，失败互不影响。
2. **作业步骤固定顺序**：取注册行 → 复核状态与到期 → 逐服务删库（单库失败不中断、记失败名）→ 全部成功才删对照行与注册行 → 同事务落事件 → 提交。
3. **幂等**：注册行不存在 → `skipped`（重复执行不重复发事件）；状态被恢复改回 `active` → `skipped`（防与恢复并发，`version` 乐观锁兜底重试）。
4. **失败不丢重试依据**：任一库删除失败即**不删注册行**，作业置失败并带失败服务清单；框架按策略重试，超限进死信 + 告警。
5. **回填**：`purge_at IS NULL` 的 `deleted` 租户，在归档 provider 非 `null` 时回填 `now + 保留期`（从当下起算，给足新保留期），审计留痕；仍为 `null` 则跳过等下一轮。
6. **删库语义**：走运维通道 `drop_database`（库不存在视为成功，本身幂等），不跨服务写业务表；平台库内的注册行删除只在本服务库。
7. **跨服务解析**：连接串解析必须 `allow_cross_service=True`（要删的是各服务租户库），否则归属校验直接 `DataOwnershipError`；该工厂只解析地址、不建业务引擎。
8. **作业落平台链**：`tenant_id = None`，`sys_job` 写本服务平台库——写进租户库会在删库时连带丢作业记录（重试依据与留痕同时失效）。
9. **提交幂等键**：`tenant.purge:{tenant_id}:{version}:{日期}`——同日重跑不重复提交，次日可再提交（死信后仍可收敛）。

## 4. 施工顺序 <a id="steps"></a>

1. 仓储 `purge_due` / `purge_pending` / `backfill_purge_at` / `purge_row` / `config_value`；
2. `tenant_purge.py` 编排（含失败清单与统计、`_resolve_drop` 跨服务解析）；
3. 两个作业处理器 + `job_handlers()` / `job_specs()`，与平台清单 `[[jobs]]` 对齐；
4. worker 入口 `bms_tenant/jobs.py` + compose `tenant-jobs`；
5. 内置任务 `purge_deleted_tenants`（每日提交 `tenant.purge.scan`）；
6. 审计与告警接线（`sys.operation.logged` 扩展位）；
7. 实施 / 测试记录 → 计划回写。

用例编号先到 Kiwi 登记再编码，覆盖父设计 §6 的 13~17：

| 14 | 未到期 / `purge_at` 空 | `skipped`、零副作用 |

- 删库用替身（mock）断言调用序列，不在单测里真删库；真删库由部署窗口验证（父设计 §9.1 第 4 项开放项一并核对备份）。

## 6. 前置与风险 <a id="risk"></a>

| # | 项 | 处置 |
| --- | --- | --- |
| 1 | 与恢复并发 | 作业步骤 2 复核 + `version` 乐观锁；恢复优先，作业 `skipped` |
| 2 | 单库失败导致「删了一半」 | 保留注册行、失败清单可重试；重跑幂等（库不存在视为成功） |
| 3 | 备份未校验即删库 | 开放项：作业只负责删；是否需要前置「最近备份时间」检查待评估，先在部署窗口确认 |
| 4 | 回填把所有 `purged` 都提前 | 回填只处理 `purge_at IS NULL`，且从当下起算保留期，不会缩短已有时点 |
| 5 | 跨服务删库被归属校验拒 | 连接串解析用 `allow_cross_service=True`（只解析地址），与开通编排同口径 |
| 6 | 作业记录写进租户库导致删库后丢记录 | 作业固定落平台链（`tenant_id=None`），`sys_job` 写本服务平台库 |
