## 1. 本子任务范围 <a id="scope"></a>

父设计 §4.6（回填）与 §4.7（物理清理）的落地。**前置**：`-01` 已交付 `status = deleted`、`deletion_requested_at` / `purge_at` 两列与 `tenant.purged` 契约——本子任务不改表、不改事件契约，只消费它们。

- **不做**：注销 / 恢复端点（`-01`）；前端（`-03`）；归档执行器本体；备份校验（开放项，见父设计 §9.1 第 4 项）。
- **不新增表**：清理留痕复用作业执行记录 + 事件 + 审计日志三处。

## 2. 落点清单 <a id="deliver"></a>

| 层 | 文件 | 动作 |
| --- | --- | --- |
| 仓储 | `services/tenant/src/bms_tenant/domains/tenant/repositories/tenant_registry.py` | `purge_due(now, limit)`、`purge_backfill(now, retention, limit)`、`purge_row(tenant_id)` |
| 编排 | `services/tenant/src/bms_tenant/domains/tenant/services/tenant_purge.py` | 新建：逐服务删库 + 删注册行 + 落 `tenant.purged` |
| 作业 | `services/tenant/src/bms_tenant/domains/tenant/jobs.py` | `TenantPurgeJob`（`job_type = "tenant.purge"`） |
| 任务 | `services/tenant/src/bms_tenant/tasks.py` | `TenantPurgeScanTask`（`tenant.purge.scan`，每日） |

## 3. 关键实现要点 <a id="key"></a>

1. **扫描与提交分离**：`tenant.purge.scan` 只做「查到期 → 提交作业」，不内联删库；单租户一个作业，失败互不影响。
2. **作业步骤固定顺序**：取注册行 → 复核状态与到期 → 逐服务删库（单库失败不中断、记失败名）→ 全部成功才删对照行与注册行 → 同事务落事件 → 提交。
3. **幂等**：注册行不存在 → `skipped`（重复执行不重复发事件）；状态被恢复改回 `active` → `skipped`（防与恢复并发，`version` 乐观锁兜底重试）。
4. **失败不丢重试依据**：任一库删除失败即**不删注册行**，作业置失败并带失败服务清单；框架按策略重试，超限进死信 + 告警。
5. **回填**：`purge_at IS NULL` 的 `deleted` 租户，在归档 provider 非 `null` 时回填 `now + 保留期`（从当下起算，给足新保留期），审计留痕；仍为 `null` 则跳过等下一轮。
6. **删库语义**：走运维通道 `drop_database`（库不存在视为成功，本身幂等），不跨服务写业务表；平台库内的注册行删除只在本服务库。

## 4. 施工顺序 <a id="steps"></a>

1. 仓储 `purge_due` / `purge_backfill` / `purge_row`；
2. `tenant_purge.py` 编排（含失败清单与统计）；
3. `TenantPurgeJob` 注册与作业参数校验；
4. `TenantPurgeScanTask` 每日调度（含批大小配置项）；
5. 审计与告警接线；
6. 实施 / 测试记录 → 计划回写。

## 5. 用例与验收 <a id="tests"></a>

用例编号先到 Kiwi 登记再编码，覆盖父设计 §6 的 13~17：

| # | 用例 | 断言要点 |
| --- | --- | --- |
| 13 | 到期清理 | 逐服务删库、注册行与对照行删除、`tenant.purged` 一次、统计正确 |
| 14 | 未到期 / `purge_at` 空 | `skipped`、零副作用 |
| 15 | 单库失败 | 注册行保留、失败清单准确、可重试收敛 |
| 16 | 幂等 | 二次执行 `skipped`、不重复发事件 |
| 17 | 与恢复并发 | 恢复后作业 `skipped`，租户仍 `active` |

- 覆盖率：变更模块行 + 分支 100%；时间注入固定 `now`，不用 `sleep`。
- 删库用替身（mock）断言调用序列，不在单测里真删库；真删库由部署窗口验证（父设计 §9.1 第 4 项开放项一并核对备份）。

## 6. 前置与风险 <a id="risk"></a>

| # | 项 | 处置 |
| --- | --- | --- |
| 1 | 与恢复并发 | 作业步骤 2 复核 + `version` 乐观锁；恢复优先，作业 `skipped` |
| 2 | 单库失败导致「删了一半」 | 保留注册行、失败清单可重试；重跑幂等（库不存在视为成功） |
| 3 | 备份未校验即删库 | 开放项：作业只负责删；是否需要前置「最近备份时间」检查待评估，先在部署窗口确认 |
| 4 | 回填把所有 `purged` 都提前 | 回填只处理 `purge_at IS NULL`，且从当下起算保留期，不会缩短已有时点 |
