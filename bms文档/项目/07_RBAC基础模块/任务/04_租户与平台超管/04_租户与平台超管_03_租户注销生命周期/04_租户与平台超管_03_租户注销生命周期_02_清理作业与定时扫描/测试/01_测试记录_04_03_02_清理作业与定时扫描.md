## 2. 用例与结果 <a id="cases"></a>

| Kiwi 用例 | 场景 | 断言要点 | 结果 |
| --- | --- | --- | --- |
| 13 | 到期清理 | 逐服务删库（platform / file 调用序列）、注册行与对照行删除、`tenant.purged` 一次且 `dropped_services=2`、审计一条（`action=tenant:purge`、`username=system`） | 通过 |
| 14 | 未到期 / `purge_at` 空 / 已恢复 / 停用 / 注册行缺失 | 五档一律 `skipped` 且原因准确（`not_due` / `purge_at_empty` / `status=active` / `status=suspended` / `missing`），零副作用、无事件 | 通过 |
| 15 | 单库失败 | 注册行与对照行保留、`failed_services=["file"]`、无事件；换健康执行器重试后收敛为 `purged` | 通过 |
| 16 | 幂等 | 二次执行 `skipped`（`missing`）、事件仍只有一条、删库只发生一轮 | 通过 |
| 17 | 与恢复并发 | 恢复后（`active`）作业 `skipped`，租户仍 `active`，无清理事件 | 通过 |
| 补充 | 回填（归档就绪） | `purge_at IS NULL` 行回填为 `now + 7` 天（参数 `tenant.deletion.retention_days=7`），本轮不进清理目标 | 通过 |
| 补充 | 回填（归档未就绪） | 不回填、`purge_at` 保持空 | 通过 |
| 补充 | 扫描目标筛选 | 只取已到期行，未到期与待回填不进入目标；目标带 `code` / `version` | 通过 |
| 补充 | 作业负载非法 | `tenant_id` 缺失 / 非数 → `failed` 且 `retryable=False`（数据问题，重跑无意义） | 通过 |
| 补充 | 作业成功 / 跳过 | 作业结果摘要带 `status` / `dropped_services` / `failed_services`；已删后重跑为 `skipped` 且仍记成功 | 通过 |
| 补充 | 作业失败 | 有库删失败 → `failed` + `retryable=True` + `failed_service_keys` | 通过 |
| 补充 | 扫描作业提交 | 到期 2 户提交 2 条 `tenant.purge`，`tenant_id=None`（平台链），幂等键为 `tenant.purge:{id}:{version}:{日期}`，进度 `(2, 2)` | 通过 |
| 补充 | 批大小回落 | 缺省 / 非整数 / 非正数回落 50，合法值照用 | 通过 |
| 补充 | 作业声明一致性 | `job_specs` 与登记清单的 service / domain / handler 三处不漂移 | 通过 |
| 补充 | worker 入口 | 声明齐备、`build_runner` / `build_worker` 可装配、`--once` 与中断分支返回 0 并释放资源、模块入口以 0 退出 | 通过 |
| 补充 | 保留期解析 | `None` / 非整数 / 0 / 负数回落 30，`"7"` 取 7；未装配配置时保留期取缺省、归档判未就绪 | 通过 |
| 补充 | 内置任务 | `purge_deleted_tenants` 向 tenant 提交 `tenant.purge.scan`，不带租户位，幂等键前缀 `tenant.purge.scan:platform:` | 通过 |

## 4. 未覆盖与说明 <a id="gaps"></a>

- **真删库**：单测全部用替身，实际 `drop_database` 的跨库 / 连接占用行为在部署窗口验证（设计 §6 第 3 项开放项：备份是否需前置校验一并核对）。
- **跨进程引擎回收**：作业进程删库时，其他 API 进程可能仍持有该租户库连接；停用 / 注销时的引擎回收已覆盖本进程，跨进程占用由部署侧确认（记录在案，不在本期代码内解）。
