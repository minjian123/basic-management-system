## 2. 任务内容 <a id="content"></a>

1. **到期扫描**：定时任务 `tenant.purge.scan`（`BaseTask`，每日）分批取 `status = deleted AND purge_at <= now`，逐租户提交清理作业；批大小可配，缺省 50。
2. **回填扫描**：同一轮扫 `status = deleted AND purge_at IS NULL`，归档能力就绪时回填 `purge_at = now + 保留期` 并留审计；未就绪则跳过等待。
3. **清理作业**：`TenantPurgeJob`（`job_type = "tenant.purge"`）按「服务目录已启用服务 × 租户」逐库 `drop_database`，删 `sys_tenant_database` 对照行与 `sys_tenant` 注册行，同事务落 `tenant.purged` 事件。
4. **失败与幂等**：单库失败不中断、不删注册行（保留重试依据），作业置失败并带失败服务清单交框架重试；注册行已不存在或状态已回 `active` 时 `skipped`，不重复发事件。
5. **观测**：清理结果落作业执行记录 + `tenant.purged` 事件 + 审计日志（`sys.operation.logged`，含 `tenant_id` / 删除统计 / 耗时），**不新增清理日志表**。

## 3. 完成标准 <a id="accept"></a>

- 到期租户被逐库清理，注册行与库名对照行一并删除，`tenant.purged` 只发一次且统计正确。
- 未到期 / `purge_at` 为空 / 已被恢复的租户一律 `skipped`，零副作用。
- 单库删除失败时注册行保留、失败服务清单准确、重试后能收敛；超限进死信并告警。
- 归档就绪后的回填能把「长期 `purge_at` 为空」的租户纳入倒计时，且给足新的保留期。
- 用例 13~17 全绿；变更模块行 + 分支覆盖率 100%；静态检查全绿。
