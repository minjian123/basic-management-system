## 3. 关键实现要点 <a id="key"></a>

1. **注销不软删**：`status = deleted` 但 `deleted_at` 保持 NULL，列表 / 详情 / 恢复全部沿用现有「过滤软删」查询，不新增第二套读取路径。
2. **编码与域名继续占用**：注销不清 `code` / `domain`、不改 `expire_at`；`code` / `domain` 唯一约束在保留期内仍生效，避免新旧租户同码导致产品侧按 code 派生的键串号；物理清理后自然释放。
3. **停用编排复用**：注销与停用共用「逐服务回收引擎 → `_revoke_sessions` → 租户源缓存失效」，抽成同一函数（当前实现在 `api/tenant_admin.py` 停用端点内）；回收 / 撤销失败只告警不回滚（与停用现状一致）。
4. **契约版本**：`_TENANT_EVENT_VERSION` 由 `2.1.0` 升 `2.2.0`（族共享），`tenant.deleted` 追加可选 `purge_at` / `reason`；`tenant.purged` 新登记 `1.0.0`。注册表描述由「产品按保留期归档或清理资源」改为「租户注销（产品停写、保留数据；清理授权见 `tenant.purged`）」。
5. **只读放行**：`readonly=True` 只跳过「停用 / 注销即拒」，不跳过租户解析与权限码判定；`TenantContext.status` 透出 `suspended` / `deleted` 供产品展示；命中记 `tenant_readonly_access` 日志。
6. **审计**：注销 / 恢复字段级审计（`status`、`deletion_requested_at`、`purge_at`），`reason` 进载荷、`confirm_code` 不落库。

## 4. 施工顺序 <a id="steps"></a>

1. 表文件两列 + 索引 + v9 → 总览登记；
2. ORM 模型与仓储方法；
3. 错误码与异常；
4. 事件契约（`2.2.0` / `purged` `1.0.0`）→ 快照重导出 → 兼容校验；
5. `sys_config` 默认项；
6. 守卫 `readonly` 参数与 `readonly_routes`（含 `tenant_readonly_access` 日志）；
6.1 生命周期端口加 `purged` 动作（`TENANT_LIFECYCLE_EVENT_TYPES` + `on_purged` 缺省 no-op）；
7. 服务层状态机（注销 / 恢复 / 保留期 / 归档判定）；
8. 接口层两个端点 + 停用编排抽公共函数；
9. 契约暴露（schemas）→ 前端类型快照重生成（`frontend/packages/api_types/scripts/generate.mjs`）；
10. 登记回写（概要 25、架构 09 / 12）→ 实施 / 测试记录。

## 5. 用例与验收 <a id="tests"></a>

用例编号先到 Kiwi 登记再编码，覆盖父设计 §6 的 1~12、18~23：

| 组 | 覆盖 |
| --- | --- |
| 注销 | 归档未就绪 / 就绪 / 失败三分支；确认码不匹配；平台租户；开通中；重复注销；不存在 |
| 恢复 | `purge_at` 空 / 未到 / 已过 / 非注销态 |
| 只读放行 | 命中白名单放行；未登记路径与写方法拒绝；配置为空全拒；放行不越权 |
| 契约 | 族版本 `2.2.0`、新增字段可选、`purged` `1.0.0`、快照零漂移、订阅主版本兼容 |
| 契约暴露 | `deleted` 可筛、两字段透出、空值序列化 |

- 覆盖率：变更模块行 + 分支 100%；时间相关用例注入固定 `now`，不靠 `sleep`。

## 6. 前置与风险 <a id="risk"></a>

| # | 项 | 处置 |
| --- | --- | --- |
| 1 | 归档执行器未就绪（计划 §7 第 32 项） | 不阻塞：注销时 `purge_at` 留空，由 `-02` 的回填扫描在归档就绪后补齐时点 |
| 2 | 契约族版本抬升影响面 | 四条租户事件同标 `2.2.0`；订阅方按主版本兼容，声明无需改；快照重导出后过零漂移 |
| 3 | 前端类型快照 | 改响应契约后必须重生成，否则 CI 类型门禁红 |
| 4 | 只读放行被误用为「绕过停用」 | 只允许 `GET` / `HEAD` + 路径前缀登记，缺省空即全拒；写方法与未登记路径维持拒绝 |
