## 3. 关键实现口径 <a id="impl"></a>

1. **契约定案落地**：`tenant.deleted` 留租户事件族、只增可选 `purge_at` / `reason`（族升 `2.2.0`）；`purged` 独立 `1.0.0`。`_TENANT_DELETED_PAYLOAD` 单独定义，避免 created / suspended / activated 平白获得无意义字段。
2. **注销不软删**：只置 `status = deleted` 并记 `deletion_requested_at` / `purge_at`，`deleted_at` 保持 NULL——保留期内数据与注册行都在，恢复只需清字段。
3. **归档未就绪即留空**：`settings.archive_policy.provider` 为空 / `null` 时不写 `purge_at`，由清理扫描回填；注销不被归档能力阻塞，也不会在未归档时销毁数据。
4. **保留期取值**：`sys_config` 键 `tenant.deletion.retention_days`（缺省 30，非法 / ≤0 回落并记 WARNING），改配置即时生效；参数默认项随平台种子下发。
5. **只读放行三条件**：`GET` / `HEAD` + `readonly_routes` 的「服务键:路径前缀」+ 状态 ∈ {suspended, deleted}；缺省空列表即全拒。**只在只读通道时**才向租户源 / 守卫实现传 `readonly` 关键字，既有自定义实现零影响。
6. **只读不放宽鉴权**：仍走权限码与租户上下文解析，只跳过「停用 / 注销即拒」一条；命中记 `tenant_readonly_access`（租户 / 状态 / 路径 / 方法），不写操作审计。
7. **`purged` 端口缺省告警**：`on_purged` 缺省 no-op 但记 WARNING——「注销成功但数据一直在」是静默失败的典型形态，必须能发现。
