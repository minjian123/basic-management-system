## 2. 任务内容 <a id="content"></a>

1. **表与模型**：`sys_tenant` 增 `deletion_requested_at` / `purge_at` 两列与 `idx_sys_tenant_purge_at` 索引（表文件 → ORM → 建表 → 总览登记），`status` 取值增 `deleted`。
2. **契约口径统一**：`tenant.deleted` 留在租户事件族，追加可选 `purge_at` / `reason`（族版本升 `2.2.0`）；`tenant.purged` 独立 `1.0.0`；注册表描述同步改写；契约快照重导出并过零漂移 + 兼容校验。
3. **状态机**：`active | suspended` →（确认码 + 原因）→ `deleted` →（保留期内恢复）→ `active`；注销**不软删**，`deleted_at` 保持 NULL 直到物理清理。
4. **两个端点**：`POST /tenants/{id}/delete`（`confirm_code` 必须等于租户编码、`reason` 可选）、`POST /tenants/{id}/restore`；错误码 `82014`（确认不匹配）/ `82015`（保留期冲突）；停用编排（引擎回收 + 会话撤销 + 缓存失效）抽成公共函数复用。
5. **保留期与归档判定**：`sys_config` 键 `tenant.deletion.retention_days`（缺省 30）；归档 provider 为 `null` 或归档失败时**不置 `purge_at`**，注销照常成功。
6. **只读放行口**（07 §7 第 58 项）：`[tenant_guard].readonly_routes` 白名单 + `require(readonly=True)`，缺省空即全拒；仅放行 `GET` / `HEAD` 且路径命中，写操作与未登记路径维持拒绝。
7. **登记回写**：概要 25（§2.1 / §2.2 / §2.3 / §4.1 / §5.1 / §5.3 / §7.1）、架构 09 事件清单、架构 12 §4、表文件与总览。

## 3. 完成标准 <a id="accept"></a>

- 注销 / 恢复按状态机执行，`provisioning` 与平台租户均被拒（`82003`），确认码不匹配不产生任何状态变更与事件（`82014`）。
- 注销后即时不可用（引擎回收 + 会话撤销 + 登录拦截），保留期内可恢复，过期恢复被拒（`82015`）。
- `tenant.deleted` 在租户事件族内标 `2.2.0` 且新增字段均为可选；`tenant.purged` 独立 `1.0.0`；快照零漂移、订阅主版本兼容。
- 归档未就绪时不置 `purge_at`，且不因此拒注销。
- 停用 / 注销租户的管理面只读请求按白名单放行，数据面与写操作仍拒；配置为空时一条不放行。
- 用例 1~12、18~23 全绿；变更模块行 + 分支覆盖率 100%；静态检查全绿。
