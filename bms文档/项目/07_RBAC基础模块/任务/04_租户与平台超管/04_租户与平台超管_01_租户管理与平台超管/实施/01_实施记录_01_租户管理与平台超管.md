## 3. 关键实现口径 <a id="impl"></a>

1. **平台超管模型**：不建 `sys_admin` 表；平台超管是「平台租户」内的 `sys_user`。`sys_tenant` 增 `kind`（`business` / `platform`），平台租户编码取 `[platform_tenant].code`（缺省 `platform`），首次启动幂等引导 + `ops.bootstrap_platform` CLI；业务租户列表 / 唯一启用兜底 / 租户切换均排除平台租户。
2. **平台内置角色**：`platform_admin`（`role_type=platform_admin`，经 `[permission.options] exempt_role_types` 全权限豁免）+ `platform_ops`（`custom`，只读运维）；初始超管绑定 `platform_admin`。
3. **开通**：同步全流程 + `Idempotency-Key`；先落 `provisioning` 注册行 → 建库 + `apply_chain_schema` 幂等建表 + 种子 → `active`；失败清理已建库并删除注册行，抛 `82006` 且告警。
4. **停用 / 启用**：停用置 `suspended`、发 `tenant.suspended`、回收引擎并调用 identity 内部端点按租户撤销全部会话（失败降级为告警，不阻断）；启用恢复并发 `tenant.activated`。
5. **模块门禁**：`require_permission` 在权限码校验后按「业务段 → 模块」判定，停用 / 未开通抛 `82008`；动态菜单按同一状态过滤，产品模块停用即隐藏对应菜单与表单；`module_key` 校验走 platform `/modules/snapshot`（未注册 / 未启用 `82007`）。
6. **配额**：`sys_tenant_quota` 三键（`user_count` / `storage_bytes` / `open_calls`），实时增量；已接「创建 / 删除用户」与「文件上传完成」两处，超限统一 `82005`；配额服务不可用按 fail-open 处理。
7. **自助改密**：`POST /auth/change-password` 校验旧口令 → platform 更新口令（策略 / 历史复用由 platform 判定）→ 失效其它会话；登录响应 `must_change_password` 时前端强制跳转 `/change-password`。
8. **引导与种子**：`ops/seed_platform.py` 幂等写平台 RBAC + 初始超管（随机口令一次性打印、首登强制改密）；`ops/seed_sso.py` 默认 IdP 播 `disabled` 占位；开通租户时按 `BUILTIN_ADMIN_ROLES` 写三类内置管理员、初始系统管理员与默认归档策略四键。
