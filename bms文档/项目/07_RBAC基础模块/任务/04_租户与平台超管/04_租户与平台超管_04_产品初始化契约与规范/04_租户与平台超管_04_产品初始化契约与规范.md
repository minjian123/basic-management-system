## 2. 任务内容 <a id="content"></a>

> **口径修订（2026-11-04 复核）**：本任务原拟「为非库类资源新建初始化标准位」，复核发现**机制已全部就绪**，不新建任何基座能力，只补**规范章节与落地示例**。

1. **缺口定位**：租户开通流程覆盖「服务 × 租户建库 + 迁移 + 种子」；非库形态的产品资源（msg 的命名空间与默认配额，未来的目录 / 索引等）没有统一的初始化约定。
2. **既有机制（直接引用，不重造）**：
   - `tenant.created` 事件契约 **v2.0.0** 已交付（`bms_core/events/platform_events.py`），与状态变更经 Outbox 同事务；
   - 产品事件消费组**声明归提供方**已交付（`event_consumer_records()`，架构 16 §5：基座不预置业务组、订阅声明进入契约覆盖校验）；
   - 部署期资源初始化已有**产品种子编排**（`[[seeds]]` + 平台统一编排 + XA 分支，产品可写平台库，mdm 已用）；
   - 产品接入规则已写「开通默认种子归基座、产品按同机制扩展」（《平台可扩展性规划》「开通所需的默认数据种子归基座」条）。
3. **规范内容（本任务唯一实质产出）**：非库类资源初始化的**二选一**约定与约束——
   - 路径 A：产品声明 `tenant.created` 消费组，在消费内幂等初始化（按 `tenant_id` 为自然键）；
   - 路径 B：懒初始化（首访创建），须写明幂等键、并发保护与可观测点；
   - 共同要求：失败**不阻塞租户开通**（开通成功与资源就绪解耦）、可重试（事件重试 / 死信可观测）、可观测（日志 + 指标）、可审计。
4. **文档落地**：写入产品接入规范对应章节（**引用**上述既有件，不复述机制细节）；msg（命名空间 + 默认配额）与 mdm（组织域默认数据）各给一条落地示例。
5. **边界**：只定规范与示例；不改基座代码、不改已有产品开通流程；存量产品按「存量豁免 + 新增遵守」处理。

## 3. 完成标准 <a id="accept"></a>

- 产品接入规范新增「非库类资源初始化」章节，明确二选一路径与幂等 / 失败 / 重试 / 观测 / 审计要求。
- 章节内**不重复定义**已有机制，逐条引用 `tenant.created` 事件契约、`event_consumer_records()` 消费组声明、`[[seeds]]` 种子编排与《平台可扩展性规划》既定条款。
- msg 与 mdm 各有一条示例，能对应到真实声明位置（msg `deploy/registry/msg.toml`、mdm 同）。
- 不改变现有建库类产品的开通流程（兼容已有实现），基座零代码改动。
