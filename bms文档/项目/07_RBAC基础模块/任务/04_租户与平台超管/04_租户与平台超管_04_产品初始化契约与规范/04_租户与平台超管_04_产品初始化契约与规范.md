## 2. 任务内容 <a id="content"></a>

1. **问题定位**：租户开通流程只覆盖「服务 × 租户建库 + 迁移 + 种子」；非库形态的产品资源（消息平台的命名空间与默认配额、未来的目录 / 索引等）没有统一初始化入口。
2. **两种形态分类**：建库类（mdm 等有租户库的产品，沿用现有流程）与非库类（无租户库、资源在平台库或文件系统），分别定义初始化方式。
3. **标准位定义**：为「非库类」提供明确落点——要么在 `tenant.created` 事件上提供产品初始化消费者的标准约定，要么明确「懒初始化」并规定其幂等与观测要求。
4. **规范内容**：初始化幂等、失败不阻塞租户开通、可重试、可观测（日志 / 指标）、可审计。
5. **文档落地**：写入产品接入规范（平台可扩展性规划 / 微服务演进规划相关章节），并在 msg 与 mdm 上各给一条落地示例。
6. **边界**：本任务只定契约与规范，不要求所有产品立即改造；已有产品按「存量豁免 + 新增遵守」处理。

## 3. 完成标准 <a id="accept"></a>

- 两种形态（建库类 / 非库类）的初始化方式有明确文档。
- 「非库类」有唯一推荐路径（事件消费或懒初始化），并写明幂等、失败处理、重试与观测要求。
- 产品接入规范新增对应章节，msg 与 mdm 各有一条落地示例。
- 不改变现有建库类产品的开通流程（兼容已有实现）。
