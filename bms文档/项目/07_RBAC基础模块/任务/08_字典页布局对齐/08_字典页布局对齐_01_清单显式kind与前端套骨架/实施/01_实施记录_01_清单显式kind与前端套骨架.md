## 2. 实施过程 <a id="process"></a>

### 2.1 后端 · 清单显式 `kind` 与派生字段 <a id="backend"></a>

1. `bms_core/registry/forms.py::FORM_CATALOG`（12 条）与 `bms_core/datasource/registry.py::DATA_SOURCE_CATALOG`（14 条）**逐条**补 `kind=FormKind.DICT.value` / `kind=DataSourceKind.DICT.value`；**取值保持既有不变**（本清单均为字典表），仅消除默认值兜底。两处清单改为「一键一行」写法并补清单文档串说明显式声明口径。
2. `bms_core/schemas/form.py::FormKeyResponse` 与 `.../schemas/datasource.py::DataSourceResponse` 各增 **Pydantic 计算字段** `is_dict`（`kind == <Kind>.DICT`）；端点签名与 `?kind` 过滤不变。
3. 计算字段**不入 `model_fields`**，故既有「响应字段集 = `model_fields`」断言改为「字段 ∪ 计算字段」（`_ITEM_FIELDS`）；并补「`is_dict` 与 `kind` 同源」与「`kind=form` → `is_dict=False`」断言（覆盖派生字段的假分支）。

### 2.2 基座校验脚本 <a id="check"></a>

`scripts/tools/base_check/check_system_fields.py` 新增：`parse_enum_values`（AST 解析 `StrEnum` 取值）、`resolve_kind_node`（解析 `kind` 取值节点：字符串字面量 / `<Enum>.<MEMBER>.value`）、`parse_kind_declarations`、纯函数 `diff_explicit_kind`；`check_form_catalog` 追加调用 `check_explicit_kind()`（两份清单各断言「`kind` 键存在」+「取值 ∈ 枚举」）；`--self-test` 增 4 例（正常 / 未显式声明 / 取值非法 / 取值无法解析），断言用例 8 → **12**。

### 2.3 前端 · `core` 判定与归一 <a id="core"></a>

1. `core/src/domain/page-route.ts`：新增常量 `DICT_KIND` 与**唯一判定** `isDictKind(kind)`；`DataSourceRecord` / `FormKeyRecord` 增 `isDict`，归一函数读 `isDict` / `is_dict`，**缺省回落 `isDictKind(kind)`**（兼容旧响应）。
2. `core/src/capabilities/page-route.ts`：`BasePageRoute` 增 `isDictPage(formKey)` / `isDictDataSource(dataSourceKey)`（清单未装载 / 未命中返回 `false`）。
3. `core/src/index.ts` 具名导出 `DICT_KIND` / `isDictKind`。

### 2.4 前端 · 系统信息件与骨架件 <a id="uiep"></a>

1. `ui_ep/src/components/display/SysInfoPanel.vue`：结构由 `el-descriptions` 改为 **`el-form` `label-position="top"` + 三列只读栅格**；固定 7 项 `ID` / `版本号` / `创建用户` / `创建时间` / `修改用户` / `修改时间` / `表单标识`；第 7 项为**禁用下拉框**（显示表单名、值为 `formKey`）；新增可选 prop `timezone`，创建 / 修改时间按该时区格式化为 `yyyy-MM-dd HH:mm`（无时区后缀），不可解析值或非法时区原样输出；`column` 保留为栅格列数（缺省 3）。
2. 新增 `ui_ep/src/components/layout/DictRecordLayout.vue`（布局族，经 `useBaseLayout` 投影）：工具栏插槽 + `el-tabs`（`detail` 详细信息为内置 `el-form` + 首行栅格 + `first-row` / `fields` 插槽；`extra-tabs` 业务 Tab 插在详细信息与系统信息之间；`sys` 系统信息内置 `SysInfoPanel`）；props `modelValue` / `info` / `disabled` / `timezone` / `detailLabel` / `sysLabel`，受控回写 `update:modelValue`。
3. `ui_ep/src/index.ts` 根出口导出 `DictRecordLayout`。
4. 布局族护栏 `ui_ep/tests/layout-style.spec.ts` 冻结范围 **19 → 20 件**（含新件）。

### 2.5 开发态核对页 <a id="devpage"></a>

新增 `apps/desktop/dict-record-check.html` + `src/dev/dictRecordCheck.ts` + `src/dev/DictRecordCheck.vue`（真实组装骨架件与系统信息件、本地样例不调后端、不进构建产物）；`.vscode/launch.json` 选页清单**两处同步**追加 `dict-record-check.html`（bms 仓 + 工作区根）。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | `FormKind.DICT.value` 是 `ast.Attribute` 而非 `ast.Constant`，既有 `parse_records` 会丢弃该关键字 ⇒ 直接复用会误判「未显式声明」 | 新增 `parse_enum_values` + `resolve_kind_node`：先解析枚举取值，再把 `<Enum>.<MEMBER>.value` 解析回取值；字符串字面量写法同样支持 |
| 2 | 计算字段不入 `model_fields`，既有「响应字段集 = `model_fields`」断言失败（4 例） | 两份接口用例引入 `_ITEM_FIELDS = model_fields ∪ model_computed_fields`，并补 `is_dict` 取值与 JSON Schema `type=boolean` 断言 |
| 3 | 新增布局件触发 `layout-style.spec.ts` 冻结范围断言失败 | 护栏更新为 **20 件**（含 `DictRecordLayout`），样式齐备与「无硬编码色值」断言不变 |
| 4 | `vue/require-default-prop` 要求可选 prop 有默认值，而 `timezone` 需「不传即回落内置件缺省」 | `withDefaults` 显式声明 `timezone: undefined`（不传即不覆盖内置件缺省） |
| 5 | 计划表插行误把 `07_03` 行尾并入同一行（`check_status` 报 H6） | 修正为独立两行；复跑 `--strict` 硬规则 0 不合规 |
