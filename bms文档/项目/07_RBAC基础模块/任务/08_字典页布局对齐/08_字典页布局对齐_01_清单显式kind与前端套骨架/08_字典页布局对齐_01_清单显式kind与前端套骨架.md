## 2. 任务内容 <a id="content"></a>

1. **后端清单显式声明 `kind`**：在 `bms/backend/libs/bms_core/src/bms_core/registry/forms.py` 的 `FORM_CATALOG` 与 `bms/backend/libs/bms_core/src/bms_core/datasource/registry.py` 的 `DATA_SOURCE_CATALOG` 中，**逐条显式写出 `kind`**（现全部依赖默认值 `dict`）——取值**保持既有不变**（平台内建项与 mdm 注入项确为字典表），仅消除「默认值兜底」的隐式口径。
2. **校验可断言**：基座校验脚本对两份清单断言 `kind` 已显式声明且取值合法（`dict` / `form`），使后续产品注入项漏写 `kind` 即被拦截。
3. **前端按 `kind` 判定与套骨架**：`form_key` / `data_source_key` 清单归一后提供「是否字典（`kind === 'dict'`）」的判定，字典记录页据此套用《[布局设计 · 字典页](../../../../../设计/布局设计/17_布局设计_字典页.html)》骨架（工具栏 + 信息栏「详细信息 / 系统信息」两 Tab + 详细信息首行三字段 `Code` / `Name` / `State`，三列等宽、顺序固定）；判定与套用只落一处，供后续新增字典记录页复用。
4. **通用系统信息件对齐 17 §2.5**：`frontend/packages/ui-ep/src/components/display/SysInfoPanel.vue` 改为 `el-form` `label-position="top"` + 三列只读栅格，固定 7 项（ID / 版本号 / 创建用户 / 创建时间 / 修改用户 / 修改时间 / `form_key`（字典对应的表单标识）），与表单页一致；时间按租户时区格式化、无时区后缀。
5. **文档回写（随本任务，不另立子任务）**：口径修正属设计先行项，随本任务一并落实——
   1. 《[布局设计 · 字典页](../../../../../设计/布局设计/17_布局设计_字典页.html)》：术语 `dict_key` → `data_source_key`；补「通用记录页骨架模板」适用范围（最少两 Tab + 详细信息首行三字段 + 系统信息区，其余业务 Tab 与字段不受限）与与《[布局设计 · 表单页](../../../../../设计/布局设计/08_布局设计_表单页.html)》的关系；系统信息第 7 项口径改为 `form_key`（字典对应的表单标识），与表单页一致。
   2. 《[概要设计 · 字典管理](../../../../../设计/概要设计/09_概要设计_字典管理.md)》§8.1：记录页布局引用与「所有字典记录共用一套记录页」表述对齐最终口径。
   3. 《[数据库开发规范](../../../../../规范/数据库开发规范.md)》§3.1.1：归属标识措辞更正为「字典页 = `form_key`（字典对应的表单标识）——经表单标识可解析出对应的数据源标识（字典标识 `data_source_key`）」。
6. **测试与登记**：先登记 Kiwi 用例再编码；用例编号标注与实施 / 测试记录留痕。

## 3. 完成标准 <a id="accept"></a>

两份构建期清单 `kind` 显式声明且校验脚本可断言（漏写即拒）；前端具备「按 `kind` 判定并套字典记录页骨架」的单一消费位；`SysInfoPanel` 的形态与 7 项口径符合《[布局设计 · 字典页](../../../../../设计/布局设计/17_布局设计_字典页.html)》§2.5；三份文档（17 / 概要 09 §8 /《数据库开发规范》§3.1.1）回写到位且口径相互一致；后端与前端定向用例通过、覆盖率达标、`check-preflight.py --fast` 全绿。
