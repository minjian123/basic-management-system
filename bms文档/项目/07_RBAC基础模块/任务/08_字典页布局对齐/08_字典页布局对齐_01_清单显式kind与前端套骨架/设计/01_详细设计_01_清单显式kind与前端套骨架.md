## 1. 设计目标与范围 <a id="goal"></a>

把「一个界面是不是字典页」的判定与「字典记录页骨架」的套用各自收敛到**唯一落点**：后端两份构建期清单逐条显式声明 `kind`、清单接口暴露派生字段 `is_dict`、基座校验脚本可断言；前端提供域层判定、能力层消费位与可复用骨架件，后续新增字典记录页零成本套用。

- **范围内**：`FORM_CATALOG` / `DATA_SOURCE_CATALOG` 显式 `kind`；`check_system_fields.py` 断言；清单接口派生字段 `is_dict`；`core` 域层判定与归一、`BasePageRoute` 消费位；`ui-ep` 的 `SysInfoPanel` 形态对齐与新增 `DictRecordLayout` 件；开发态核对页；三份文档回写（17 / 概要设计 09 §8.1 /《数据库开发规范》§3.1.1）。
- **范围外**：现有记录页（`RoleRecordTab` / `UserRecordTab`）的字段顺序与骨架改造归 [`08_02`](../../08_字典页布局对齐_02_现有记录页对齐/08_字典页布局对齐_02_现有记录页对齐.md)；字典条目运行时取数；`sys_account_lock` 等非字典记录页。

## 4. 接口与字段边界、失败分支 <a id="contract"></a>

### 4.1 后端清单显式 `kind` <a id="kind"></a>

- `FORM_CATALOG`（12 条）与 `DATA_SOURCE_CATALOG`（14 条，含 2 条 mdm 跨项目示例）**逐条**补 `kind=FormKind.DICT.value` / `kind=DataSourceKind.DICT.value`。
- **取值不变**：平台内建项与 mdm 注入项本就是字典表（表带 `name`，《[数据库开发规范](../../../../../../规范/数据库开发规范.md)》§3.1.3），本次只消除默认值兜底。
- 数据类 `FormRecord.kind` / `DataSourceRecord.kind` 的默认值**保留**（向后兼容：外部注入项未写仍可运行），显式约束由校验脚本承担。

### 4.2 清单接口派生字段 `is_dict` <a id="is-dict-api"></a>

- `FormKeyResponse` / `DataSourceResponse` 各增**派生字段** `is_dict: bool = kind == <Kind>.DICT`（Pydantic 计算字段，随 JSON 输出，不参与入参）。
- 端点（`GET /api/v1/form-keys`、`GET /api/v1/data-sources`）不变；`?kind` 过滤不变。
- 失败分支：无（派生字段无法非法）；既有断言「响应字段集 = `model_fields`」须改为「`model_fields` ∪ `model_computed_fields`」。
- 契约同步：`uv run python -m ops.contract_snapshot export` 重生成 `deploy/contracts/*.json`，再 `pnpm run api_types:gen` 同步 `@bms/api_types`。

### 4.3 门禁断言（`check_system_fields.py`） <a id="check"></a>

- 新增纯函数 `diff_explicit_kind(catalog_records, valid_kinds)`：逐条断言「`kind` 键**存在**（显式声明）」且「取值 ∈ 合法集合」。
- 复用既有 `parse_records`（AST 取常量关键字参数）：**键缺失 = 依赖默认值 ⇒ 报错**；两类清单各跑一次。
- 自检 `--self-test` 增反例：缺 `kind` / 取值非法。
- 失败分支：任一清单出现未显式声明或非法取值 → 打印问题清单并以退出码 1 结束（阻断推送）。

### 4.4 前端判定与归一（`core`） <a id="front"></a>

- 域层（`domain/page-route.ts`）：
  - `isDictKind(kind: string | undefined): boolean` —— **唯一判定**（`kind === 'dict'`）。
  - `FormKeyRecord` / `DataSourceRecord` 增 `isDict: boolean`；归一函数读 `isDict` / `is_dict`，**缺省回落 `isDictKind(kind)`**（向后兼容旧响应）。
- 能力层（`capabilities/page-route.ts`）：`BasePageRoute` 增 `isDictPage(formKey)`（经 `formKeys` 命中判定）与 `isDictDataSource(dataSourceKey)`；未装载清单时返回 `false`（占位零请求语义不变）。
- 失败分支：清单未装载 / 未命中 → `false`，不抛错。

### 4.5 `SysInfoPanel` 形态对齐 17 §2.5 <a id="sysinfo"></a>

- 结构改为 `el-form label-position="top"` + 三列只读栅格（`el-col :span="8"`）。
- 固定 7 项与顺序：`ID` / `版本号` / `创建用户` / `创建时间` / `修改用户` / `修改时间` / `表单标识`。
- 第 7 项：**禁用下拉框**，显示表单名（`formLabel`，缺省回落 `formKey`），值为 `formKey`。
- 时间：新增可选 prop `timezone`（缺省 `Asia/Shanghai`），`createdAt` / `updatedAt` **可解析为日期时按 `yyyy-MM-dd HH:mm` 输出、无时区后缀**；不可解析（含既有样例文本）原样输出。
- 保留既有 props：`info` / `title` / `column` / `placeholder`；`data-test` 命名沿用（`sys-info-<label>`）以免既有用例失效。
- 失败分支：字段缺失 → 占位符（沿用）。

### 4.6 `DictRecordLayout` 契约 <a id="layout"></a>

- **props**：`modelValue: string`（激活 Tab，受控，缺省 `detail`）、`info: SysInfoData`、`disabled?: boolean`（绑定详情区 `el-form`）、`timezone?: string`、`detailLabel?: string`（缺省「详细信息」）、`sysLabel?: string`（缺省「系统信息」）。
- **emits**：`update:modelValue: [value: string]`。
- **slots**：`toolbar`（工具栏区，位于信息栏之上）、`first-row`（详细信息首行三字段，页面填 3 个 `el-col :span="8"`）、`fields`（其余字段）、`extra-tabs`（业务 Tab，渲染在「详细信息」与「系统信息」之间，不受限）、`sys-extra`（系统信息侧扩展位，渲染在内置系统信息件之后；见 §9 对齐记录 2026-10-13 行）。
- **结构**：工具栏区 → `el-tabs`（「详细信息」= `el-form` + 首行栅格 + 其余字段；`extra-tabs`；「系统信息」= 内置 `SysInfoPanel`，`:info` / `:timezone`）。
- **基类挂链**：布局族，经 `useBaseLayout` 投影（满足组件继承护栏）。
- 失败分支：无（纯展示编排）。

### 4.7 开发态核对页 <a id="devpage"></a>

- 新增 `dict-record-check.html` + `src/dev/DictRecordCheck.vue` + `src/dev/dictRecordCheck.ts`：真实组装 `DictRecordLayout`（含首行三字段与业务 Tab 示例）+ 对齐后 `SysInfoPanel`，数据为本地样例、不调后端、不进构建产物。
- 两处 `.vscode/launch.json` 的选页清单同步追加（bms 仓与工作区根）。

## 8. 边界与开放项 <a id="boundary"></a>

- 骨架件只保证「最少两 Tab + 详细信息首行三字段栏位 + 系统信息区」；**业务 Tab 与其余字段不受限**，首行三列由 `first-row` 插槽承载（栏位给定，字段具体控件由页面决定）。
- 现有记录页迁移归 `08_02`，本任务不改页面行为。
- `kind` 默认值保留（兼容外部注入项）；「必须显式声明」的约束由 `bms` 侧清单 + 校验脚本承担。
- 未覆盖：其他工作区（如 cws）的 `bms` 克隆需 `git pull` 后同步；`mdm` 侧注入清单在本工作区不在扫描面内。
