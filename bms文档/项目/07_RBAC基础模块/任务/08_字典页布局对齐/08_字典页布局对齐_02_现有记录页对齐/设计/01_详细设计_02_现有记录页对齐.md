## 1. 设计目标与范围 <a id="goal"></a>

把现有两处字典记录页（角色 `RoleRecordTab` / 用户 `UserRecordTab`）从「各写一套页签与系统信息区」改为**统一消费 `08_01` 交付的骨架件** `DictRecordLayout`：首行三字段（`Code` / `Name` / `State`）三列等宽、顺序固定，其余字段一律排首行之后，信息栏固定含「详细信息」「系统信息」两侧，系统信息区由对齐后的通用件 `SysInfoPanel` 承载；业务 Tab（角色「权限配置」/ 用户「用户分配」）原样保留。为此给骨架件补一个**系统信息侧扩展位**（`sys-extra`），使「用户页 SSO 身份绑定只读区块」仍落在系统信息侧且不再由页面自建系统信息区。

- **范围内**：`ui-ep` 骨架件 `DictRecordLayout` 增 `sys-extra` 具名插槽；`RoleRecordTab` / `UserRecordTab` 改用骨架件并删除页内自建的页签与系统信息写法；两页既有用例调整与新断言；`08_01` 详细设计契约回写；计划进度回写。
- **范围外**：`08_01` 已交付的清单 `kind` / `is_dict` / 判定与消费位 / `SysInfoPanel` 形态（本次只回写其详设的插槽契约）；`SysUserDetailView`（具名插槽宿主页）、`AccountLockRecordTab`（`sys_account_lock` 非字典表）、字典条目明细区（登记项页职责）；两页业务逻辑（保存编排 / 草稿收集 / 权限码）一律不动。

## 4. 接口与字段边界、失败分支 <a id="contract"></a>

### 4.1 `DictRecordLayout` 契约扩展（`sys-extra`） <a id="sys-extra"></a>

- **唯一变更**：`slots` 增 `sys-extra`（可选），渲染位置＝「系统信息」页签内、内置 `SysInfoPanel` **之后**；页面不传时不渲染任何内容（不产生空容器）。
- **不变**：props（`modelValue` / `info` / `disabled` / `timezone` / `detailLabel` / `sysLabel`）、emits（`update:modelValue`）、既有插槽（`toolbar` / `first-row` / `fields` / `extra-tabs`）、组件落点与基类挂链（布局族，经 `useBaseLayout` 投影）。
- **失败分支**：无（纯展示编排）。

### 4.2 角色记录页（`RoleRecordTab`） <a id="role"></a>

- **骨架**：`<dict-record-layout v-model="section" :info="sysInfo" :disabled="!editing">`。
- **`section` 类型**：由 `'detail' | 'permission' | 'sys'` 收敛为 `string`（仅作受控页签键，无其它逻辑消费；与骨架件 `modelValue: string` 对齐，避免为窄化赋值引入运行时分支）。
- **`toolbar` 插槽**：原 `role-record__bar` 内全部控件（保存 / 撤销 / 编辑 / 关闭 / 载入中 / 脏标记 / 内置角色提示）原样投入，`data-test` 全部保留；页内删除 `__bar` 容器（间距由骨架件工具栏承担），保留 `__side` / `__dirty` / `__hint` 样式。
- **`first-row` 插槽**：三个 `el-col :span="8"`——`角色码`（`required`，`role-record-code`）/ `角色名`（`required`，`role-record-name`）/ `状态`（`el-select`，`role-record-status`，内置角色时 `:disabled="builtin"`）。
- **`fields` 插槽**：`角色类型` 只读输入（`role-record-type`）置于 `el-row :gutter="16"`；**一律排在首行之后**。
- **`extra-tabs` 插槽**：`<el-tab-pane label="权限配置" name="permission">` 包 `RolePermissionConfig`（`ref="permissionRef"`、 `role-id` 按 `new` / 详情主键、`@dirty` 原样）。
- **系统信息**：`SysInfoPanel` 由骨架件内置渲染；页内 `sysInfo` 语义不变（`id` 缺省 `'—'`、`formKey='role'`、`formLabel='角色管理'`、其余取详情字段），不再自行 `import SysInfoPanel`。
- **失败分支**：与现状一致（载入 / 保存 / 编排异常按 `Error` / 非 `Error` 分别提示），本次不改。

### 4.3 用户记录页（`UserRecordTab`） <a id="user"></a>

- **骨架**：`<dict-record-layout v-model="section" :info="sysInfo" :disabled="!editing">`；`section` 同 4.2 收敛为 `string`。
- **`toolbar` 插槽**：原 `user-record__bar` 内全部控件（保存 / 取消 / 修改 / 删除 / 刷新 / 关闭 / 载入中 / 脏标记）原样投入，`data-test` 全部保留。
- **`first-row` 插槽**：三个 `el-col :span="8"`——`用户名`（`:disabled="!isNew"`，`user-record-username`）/ `姓名`（`user-record-name`）/ `状态`（`el-select`，`user-record-status`，选项取 `USER_STATUS_OPTIONS`）。
- **`fields` 插槽**：`手机号`（`user-record-phone`）/ `邮箱`（`user-record-email`）/ 新增态 `首登改密`（`user-record-pwd-reset`），同排 `el-row`，一律排首行之后。
- **`extra-tabs` 插槽**：`<el-tab-pane label="用户分配" name="assign">` 包原内容（新增态空态提示 `user-assign-new-hint` / 停用只读提示 `user-assign-disabled-hint` / `ModuleAreaOutlet` 挂接位 `user-assign-slot`）。
- **`sys-extra` 插槽**：`SSO 身份绑定` 只读区块（区块标题 + 提示 + `el-table`，`data-test="user-record-identities"`）原样迁入；呈现位置在系统信息七项之后，仍在「系统信息」页签内（现状口径不变）。
- **系统信息**：`formKey='user'`、`formLabel` 由「用户表单」改为 **「用户管理」**。
- **失败分支**：与现状一致（详情 / 建号 / 删除异常提示、SSO 身份载入失败静默降级为空），本次不改。

### 4.4 页面未改动面（边界） <a id="unchanged"></a>

- 两页的保存编排、草稿收集（`registerSubmitter`）、脏态判定与上抛、权限码显隐、`defineExpose`（`save` / `isDirty`）与 props / emits 一律不变——本次**只换渲染骨架**。
- `RoleView` / `UserView`（表单框架宿主）与 `FormFrame` 不动；两页工具条的「单一保存」语义不变。
- 骨架件 `timezone` 不传（件内缺省 `Asia/Shanghai`）。

## 8. 边界与开放项 <a id="boundary"></a>

- 骨架件只保证「最少两 Tab + 首行三字段栏位 + 系统信息区 + 系统信息侧扩展位」；**业务 Tab 与其余字段不受限**（首行三列的控件形态仍由页面决定）。
- 两页为平台内建字典页，页面级不接 `isDictPage` 判定（决策 4）；后续新增**非**字典的宿主记录页需要回落形态时，另立任务设计，不在本次预留死分支。
- `SysInfoPanel` 的 `column` prop 与件内 `timezone` 缺省沿用 `08_01` 口径，本次不改。
- 未覆盖：其他工作区（如 cws）的 `bms` 克隆需 `git pull` 后同步；`mdm` 侧注入清单不在本工作区扫描面内。
