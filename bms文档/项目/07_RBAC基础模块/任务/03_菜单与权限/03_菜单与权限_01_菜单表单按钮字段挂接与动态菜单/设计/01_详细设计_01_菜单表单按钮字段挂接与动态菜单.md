## 1. 背景与目标 <a id="goal"></a>

权限分层（菜单 → 表单 → 业务、按钮 → 动作、字段可见可编辑）必须有**平台统一维护的元数据载体**；前端动态路由、侧边栏、按钮与字段显隐的**唯一依据**是动态菜单接口，不得硬编码路由或权限清单。缺少该能力，新增菜单 / 表单 / 按钮 / 字段都要改前端发版，角色授权也无从选择授权对象。

本任务把权限元数据（菜单 / 表单 / 按钮 / 字段 + 业务 / 动作码）落为平台库实体与挂接关系，并以 `GET /api/v1/menus/my` 下发菜单树与表单元数据，同时完成**前端消费**（按动态菜单注册路由 / 侧边栏、按钮按动作权限显隐、字段按字段权限显隐与只读）。

**边界（不在本任务，见「边界与开放项」节）**：

- 平台**菜单管理维护页 / 权限码管理维护页**（原型 `10_菜单管理` 四页）不在本任务，另立界面任务；本任务只交付后端元数据接口 + 前端**消费**。
- 平台 MVP 页面（用户管理 / 角色管理 / 账号锁定 / 租户管理）**页面本体**不在本任务；本任务只登记其菜单 → 表单 → 业务、按钮 → 动作链路与 i18n 文案（种子）。
- 字段权限**授予写接口** `PUT /api/v1/fields/permissions` 归 [`02_03` 角色管理](../../../02_用户与角色/02_用户与角色_03_角色管理/02_用户与角色_03_角色管理.md)；本任务只在动态菜单接口中**消费**字段权限标记。
- 真实权限计算（主体链收敛、版本失效）归 [`02_04`](../../../02_用户与角色/02_用户与角色_04_主体链权限计算引擎/02_用户与角色_04_主体链权限计算引擎.md)；本任务权限来源经 `BasePermissionChecker` 注入，占位实现为 `NullPermissionChecker`（恒允许）。

## 4. 数据设计要点 <a id="data"></a>

表结构以 **10 张表文件为唯一事实源**（本节只写跨表口径与形态，不复述字段清单）。

- **归属与链路**：六表统一归 `platform` 服务（`sys_` 前缀），随 `platform:platform` 链迁移落地（新迁移 `0007_menu_metadata`）；同步把 `TABLE_OWNERSHIP` 中 `sys_menu` / `sys_business` / `sys_action` 的 `owner` 由 `permission` 更正为 `platform`，六表 `status` 由 `planned` 转 `enabled`（转 enabled 后自动进链）。
- **公共约定**：全部继承 `BaseModel`（雪花 ID / 审计 / 软删除 / 乐观锁）；索引命名 `idx_*` / `uq_*`；逻辑外键不建物理外键；每表注释必填；每表索引 ≤ 5。
- **主表**：
  - `sys_business`：`code`（业务权限码，如 `user`）、`name`（默认文案）、`status`（`enabled` / `disabled`）；唯一 `(code, deleted_at)`。
  - `sys_action`：`code`（动作码，如 `create`）、`name`、`business_id`（逻辑外键 → `sys_business.id`）、`status`；唯一 `(business_id, code, deleted_at)`；索引 `business_id`。
  - `sys_menu`：`parent_id`（逻辑外键 → `sys_menu.id`，根为 `0`）、`name`、`path`（前端路由路径）、`component`（视图组件标识）、`icon`（完整 icon key）、`sort`、`hidden`（仅隐藏侧栏入口、权限仍生效）、`status`；唯一 `(path, deleted_at)`；索引 `parent_id`。
  - `sys_form`：`menu_id`（**1:1** 挂菜单）、`business_id`（**1:1** 挂业务）、`component`、`status`；唯一 `(menu_id, deleted_at)` 与 `(business_id, deleted_at)`。
  - `sys_button`：`form_id`、`action_id`（**1:1** 挂动作）、`name`、`type`（`toolbar` / `interface`）、`sort`、`status`；唯一 `(form_id, action_id, deleted_at)`；索引 `form_id` / `action_id`。
  - `sys_field`：`form_id`、`field_key`、`name`、`type`、`sort`、`status`；唯一 `(form_id, field_key, deleted_at)`；索引 `form_id`。
- **多语言附表**（照 `sys_module_i18n` 范式）：`sys_menu_i18n` / `sys_business_i18n` / `sys_action_i18n` / `sys_field_i18n`，列为 `{主表名}_id` + `locale` + `name`，唯一 `(主表 ID, locale, deleted_at)`；缺省**回退主表默认文案**。按钮名称**不建** i18n 附表（概要未列 `sys_button_i18n`）。
- **停用代替删除**：业务 / 动作码一经发布稳定，停用（`status=disabled`）代替删除；菜单 / 表单 / 按钮 / 字段同为软删除 + 状态双轨。

### 5.2 动态菜单接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/v1/menus/my` | 登录即可（`require_auth`） | 当前用户菜单树 + 表单元数据 + 权限码集合 |

**响应形态（单接口嵌套）**：

```text
MenuMyResponse
├── locale            # 解析后的语言（Accept-Language → SUPPORTED_LOCALES → DEFAULT_LOCALE）
├── version           # 元数据版本（缓存版本号，前端可据以判定变更）
├── permissions[]     # 当前用户权限码集合（业务码 + 动作码；供前端 v-perm / 字段显隐）
└── menus[]           # 过滤后的菜单树（保序；子节点嵌套）
    ├── id / parent_id / name(本地化) / path / component / icon / sort / hidden
    ├── children[]
    └── form           # 表单元数据（链路完整时非空）
        ├── id / menu_id / business_id / component
        ├── buttons[]  # id / action_id / action_code / name / type / sort / visible（按动作权限）
        └── fields[]   # id / field_key / name / type / sort / visible / editable（按字段权限）
```

**过滤规则**：

1. 菜单经其表单 → 业务的**业务码**校验（`checker.check(business.code)`）；**挂接链断裂**（菜单缺表单 / 表单缺业务）即不可见（对齐需求「缺失导致该链路不可见 / 不可用」）。
2. 表单下按钮按**动作权限码** `{business.code}:{action.code}` 标记 `visible`（不持有则不标记为可见，前端不渲染）。
3. 表单下字段按**字段权限**标记 `visible` / `editable`；占位阶段（`NullPermissionChecker`）按「默认全部可见可编辑」，真实授予集合随 `02_04`。
4. 菜单 `hidden` 仅隐藏侧边栏入口，**不**将其从响应中剔除（路由可直达）。

### 5.3 缓存设计 <a id="cache"></a>

- **缓存对象**：**未过滤**的菜单树 + 表单元数据（按 locale 维度），键 `bms:{tenant}:menu:{locale}:{version}`（经 `bms_core/cache/base.py::build_cache_key` 规范构造，域 `menu`、业务键 `{locale}:{version}`）。
- **版本号**：`bms:global:menu:version`（Redis 计数器）；元数据写操作**事务提交后** `+1`，旧版本键自然过期。
- **失效**：写操作提交后除 `+1` 外，另 `adelete` 当前请求 locale 的键，保证**即时生效**；TTL 兜底。
- **TTL**：取 `sys_config` 参数 `menu.tree_cache_ttl`（默认 `300` 秒，int 解析照 `password/default.py::_parse_int` 先例），随机偏移走 `RedisCacheRegion` 内置 `ttl_with_jitter`。
- **降级**：缓存读 / 写异常一律降级为「未命中 / 空操作」（`RedisCacheRegion` 已内置），由域层直连 DB 兜底；缓存 Region 取**应用级** `get_cache_region`（`CacheRegion` 契约），不新增插件键（见 §15-1）。
- **跨方言 / 跨实例**：键带租户位与全局版本号，多实例一致；无 Redis 时按未命中走 DB，功能不受影响。

### 5.4 事件发布 <a id="events"></a>

- 事件名 `sys.form.updated`（契约已预登记）；载荷 `{form_id, menu_id, business_id, changed_type}`，`form_id` / `changed_type` 必填、其余可选。
- `changed_type` 取值枚举：`menu` / `form` / `button` / `field`（表明变更对象类别；与契约 `fields` 声明一致，`form_id` 类变更填对应表单标识）。
- 发布落点：元数据写操作在**同一事务**内经 `SqlOutboxStore.enqueue(session, EventEnvelope(...))` 落 `sys_outbox`；**当前无消费者**（消费基座为占位，阶段十实现）→ 设计明确「只做发布侧、投递后无订阅方」，不阻塞、不重复建设。

## 6. 前端设计 <a id="frontend"></a>

### 6.1 数据接入（api + store）

- 新增 `api/menu.ts`：`fetchMyMenus()` → `MenuMyResponse`（类型取自 `@bms/api-types` 生成的 `platform` 命名空间）；经宿主请求层 `request.ts`（统一凭据 / 401 静默刷新 / 统一解包）。
- 新增 `stores/menu.ts`（pinia）：状态 `{ tree, formMeta, permissions, locale, version, loaded, error }`；动作 `load()` / `reload()` / `reset()`；装载成功时**回填权限码**（`utils/perm.ts::setPermissionCodes`）。
- `main.ts` 守卫 `ensureRoutes` 改为「`store.load()` → `ensureMenuRoutes(router, store.tree)`」；`App.vue` 侧栏 `useSideMenu` 的 `menu` 与 `canAccess` 改读 store（`canAccess` 走 `utils/perm.ts::canAccess`）。
- 会话联动：`session.$subscribe` 中令牌为 `null` → `store.reset()` + `uninstallMenuRoutesAll`；有令牌 → `store.load()` + `ensureMenuRoutes`。

### 6.2 降级口径

- **生产**：接口失败 → 菜单**置空** + 一次错误提示（不清会话、不阻断登录、不硬编码菜单）；`loaded=false` 时守卫按既有占位放行逻辑处理。
- **开发态（`import.meta.env.DEV`）**：失败回退 `PLACEHOLDER_MENU`，便于本地调页面。

### 6.3 按钮 / 字段权限消费

- **按钮**：复用既有 `v-perm` 指令（在 `main.ts` 全局注册），模板写 `v-perm="'user:create'"`；权限码集合来自 `stores/menu` 回填的 `utils/perm.ts`。
- **字段**：复用 `ui-ep` 的 `FormRenderer` / `FormRendererBody` 的 `permissions` prop（`Record<fieldKey, FieldPermission>`），由 `stores/menu` 的表单元数据按表单映射为 `FieldPermission`；核心 `resolveFieldRenderState` 承担显隐与只读。
- **验证载体**：新增**开发态核对页** `MenuCheck.vue`（照 `LayoutCheck.vue` 先例，不进构建产物），展示动态菜单树 + 按钮 v-perm 显隐 + `FormRenderer` 字段显隐/只读，作为《原型审查规范》实现侧对照载体。

### 6.4 菜单展开状态持久化

- 新增 `composables/useMenuExpanded.ts`：以 `localStorage` 键 `bms_menu_expanded` 存展开的菜单路径集合，接入 `SideMenu` / `MainLayout`（`uniqueOpened` 与 `default-openeds` 口径由宿主传入），刷新后恢复。
- **不做**（归标签 / 导航族后续任务，登记台账）：多标签栏「更多」溢出接线、标签拖拽排序、鼠标中键关闭。

## 13. 对齐记录 <a id="align"></a>

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 缓存 Region 取用（不新增插件键） | 复用**应用级** `CacheRegion`（`get_cache_region`）+ 规范键构造 `build_cache_key(domain="menu")`，键格式与概要一致；`CacheRegion` 补异步默认实现（`aget` / `aset` / `adelete` / `aincrease`）以兼容 memory / redis 两种 provider。理由：单任务不新增插件端口键（避免扩散 `_EXPECTED_PLUGIN_KEYS` 等核心断言），键与语义仍按概要。 |
| 2 | 概要错误码撞码 | 已报冲突并按「决策确认」第 9 项改用 `402xx`；概要 §7 与需求 07-5 item 6 回写。 |

| 4 | 业务 / 动作码写接口缺失 | 概要接口清单只列 `GET`（`business:query` / `action:query`）；本任务以种子落地全量码，维护写入归权限码管理页任务（见「边界与开放项」节）。 |
