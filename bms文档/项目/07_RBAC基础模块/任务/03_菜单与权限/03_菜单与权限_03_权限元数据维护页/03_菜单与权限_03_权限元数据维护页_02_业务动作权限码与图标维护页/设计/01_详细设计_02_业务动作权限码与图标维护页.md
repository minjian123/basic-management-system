## 1. 背景与目标 <a id="goal"></a>

三本权限字典（业务码 / 动作码 / 权限码）与租户自定义图标在 `03_01` 只交付了**只读清单接口**（`GET /businesses`、`/actions`、`/permissions`）与图标完整 CRUD 后端，前端无维护页。需求 `07-17` 要求把 `/sys/businesses`、`/sys/actions` 从占位页替换为真实页面，并新增 `/sys/permissions`、`/sys/icons`。

本任务同时补齐**后端写能力**：业务码 / 动作码 / 权限码的 POST / PUT / DELETE、权限码批量补生成、停用联动与引用保护；并登记两个新权限码与两个新错误码。

**边界（不在本任务）**：

- 菜单 / 表单维护页归[子任务 01](../03_菜单与权限_03_权限元数据维护页_01_菜单表单维护页/03_菜单与权限_03_权限元数据维护页_01_菜单表单维护页.md)。
- 平台 / 业务图标随代码发布、不落表；本页只维护**租户自定义图标**（`sys_icon`，`custom:` 前缀由后端派生）。
- 角色侧授权选择项来自本任务维护的数据，但授权关系写入归角色管理（`role:grant`）。

## 4. 数据设计要点 <a id="data"></a>

- **无表结构变更**：`sys_business` / `sys_action` / `sys_permission` / `sys_icon` 与各自 `_i18n` 已落表（`03_01` / 阶段六）。
- **唯一约束复用**：业务 / 动作 `(code, deleted_at)`；权限 `(business_id, action_id, deleted_at)`；图标 `(code, deleted_at)`。软删除组合下**同一组合可被重建**——创建前先探测软删除行，命中则 `restore` 并覆盖状态（避免逻辑重复行）。
- **权限码串**：`code = f"{business.code}:{action.code}"`，只读派生，不单独存列（响应时拼装）。
- **权限码名称**：`name = f"{business.name}·{action.name}"`（按当前 locale 取两张 `_i18n`，缺省回退主表默认文案）；不单独维护、不建 `sys_permission_i18n`。
- **种子**：
  - `MENU_SEEDS` 增 `/sys/permissions`（权限码管理，`el:key`，排序 7）、`/sys/icons`（自定义图标，`el:picture`，排序 8）；
  - `BUTTON_SEEDS` 增业务/动作/权限/图标的 create / update / delete，权限码增 `generate`（批量补生成，`toolbar`）；
  - `FIELD_SEEDS` 增各页列表字段（业务码 / 名称 / 状态；动作码 / 名称 / 状态；权限码 / 业务码 / 动作码 / 状态；图标预览 / 名称 / 分组 / 状态）；
  - `PERMISSION_SEEDS` 增 `("business","manage","管理","Manage")`、`("action","manage","管理","Manage")`。

## 5. 接口设计 <a id="api"></a>

统一响应 `{code, message, data}`；写接口支持 `Idempotency-Key`；权限码名称 / 串为派生只读字段。

### 5.1 业务码（`/api/v1/businesses`）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/businesses` | `business:query` | 清单（增 `permission_count`，`i18n` 已有） |
| POST | `/businesses` | `business:manage` | 新增：`{code, i18n, status}`；code 重复 `40209` |
| PUT | `/businesses/{id}` | `business:manage` | 更新：`{i18n, status}`；**code 不可改**（请求体不收 code） |
| DELETE | `/businesses/{id}` | `business:manage` | 删除：其下存在权限码（含停用）或有表单挂接 → `40206` |

**停用联动**：`PUT` 将 `status` 由 `enabled` 改为 `disabled` 时，校验其全部权限码是否被按钮 / 角色授权引用——任一被引用 → `40206`（整批拒绝）；否则同事务把该业务下**全部权限码置 `disabled`**。重新启用只恢复业务码本身，不自动恢复权限码。

### 5.2 动作码（`/api/v1/actions`）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/actions` | `action:query` | 清单 |
| POST | `/actions` | `action:manage` | 新增：`{code, i18n, status}`；重复 `40209` |
| PUT | `/actions/{id}` | `action:manage` | 更新：`{i18n, status}`；code 不可改；停用联动同业务码（作用于该动作下全部权限码） |
| DELETE | `/actions/{id}` | `action:manage` | 其下存在权限码 → `40206` |

### 5.3 权限码（`/api/v1/permissions`）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/permissions` | `permission:query` | 清单（`business_id` 可选过滤；增 `name`） |
| POST | `/permissions` | `permission:manage` | 手工新增组合：`{business_id, action_id, status}`；组合重复 `40210`；软删除行命中则恢复 |
| POST | `/permissions/generate` | `permission:manage` | 批量补生成缺失组合：`{business_ids?: [], action_ids?: [], include_disabled?: bool}`，默认启用业务 × 启用动作；返回 `{created, restored, skipped}` |
| PUT | `/permissions/{id}` | `permission:manage` | 仅允许改 `status`；**组合不可换绑**；停用时被按钮 / 角色授权引用 → `40206` |
| DELETE | `/permissions/{id}` | `permission:manage` | 被按钮 / 角色授权引用 → `40206` |

**引用定义**：按钮（`sys_button.permission_id`）、角色授权（`sys_role_permission.perm_type='permission' AND target_id=permission_id`）。

### 5.4 自定义图标（复用 `/api/v1/icons`）

已交付，本任务不改契约：GET 列表 / 详情、POST、PUT、DELETE（`icon:manage`）；前端只用现有字段（`code` / `name` / `i18n` / `category` / `tags` / `svg` / `status` / `reference_count`，以契约为准）。

### 5.5 失败分支汇总

| 码 | 场景 |
| --- | --- |
| `40201` | 业务码 / 动作码 / 权限码 / 图标不存在 |
| `40202` | 挂接链断裂（表单未挂业务等，前端保存前校验 + 后端兜底） |
| `40204` | 租户侧调用平台维护写接口（新增码生效后由 `require_permission` 拦截；种子授权仅系统管理员） |
| `40206` | 被引用：业务/动作下有权限码、权限码被按钮或角色授权引用、业务码被表单挂接 |
| `40208` | 多语言名称缺必填语言 |
| `40209` | 业务码 / 动作码 `code` 重复 |
| `40210` | 权限码组合重复（活动行已存在；软删除行走恢复） |

## 6. 前端设计 <a id="frontend"></a>

### 6.1 路由与菜单

- 静态路由：`/sys/businesses`（`SystemBusiness`）、`/sys/actions`（`SystemAction`）、`/sys/permissions`（`SystemPermission`）、`/sys/icons`（`SystemIcon`），`meta.title` 与菜单名一致。
- 菜单种子新增 `/sys/permissions`、`/sys/icons` 两条；`/sys/businesses`、`/sys/actions` 已存在，仅页面代码替换。
- 列表 / 记录均走 `FormFrame`（`stores/tabs`），列表 Tab 固定不可关、双击行或「新增」开记录 Tab。

### 6.2 页面骨架（四页同构）

| 页面 | 列表列 | 筛选 | 记录页签 |
| --- | --- | --- | --- |
| 业务码 | 业务码 / 名称 / 权限码数 / 状态 | 关键字 + 状态 | 详细信息（业务码只读、多语言名称、状态）/ 系统信息 |
| 动作码 | 动作码 / 名称 / 状态 | 关键字 + 状态 | 详细信息（动作码只读、多语言名称、状态）/ 系统信息 |
| 权限码 | 权限码 / 名称 / 业务码 / 动作码 / 状态 | 关键字 + 业务码 + 状态 | 详细信息（业务码 × 动作码只读派生、状态）/ 系统信息 |
| 图标 | 预览 / icon key（复制）/ 名称 / 分组 / 引用数 / 状态 | 关键字 + 分组 + 状态 | 详细信息（icon key 只读、多语言名称、分组、标签、SVG 上传预览、状态）/ 系统信息 |

- 新增态：业务 / 动作码 `code` 可填，保存后**只读**；权限码新增用业务码 / 动作码下拉（仅启用项）派生组合；图标新增时 `code` 可填（kebab-case 校验），后端派生 `custom:{code}`。
- 停用 / 启用、删除均走工具栏批量；删除二次确认并逐条汇总失败（`40206` 提示「先解除引用 / 停用」）。
- 权限码页工具栏额外「补生成缺失组合」→ `GenerateDialog`：范围（全部 / 指定业务 / 指定动作）+ 含停用项开关，提交后回显 `{created, restored, skipped}` 并刷新列表。
- 多语言名称统一用 `MultilingualNameField`；图标页 SVG 上传复用 `FileUploadField` / 现有上传件，限制类型 `image/svg+xml` 与大小上限，预览内联清洗后渲染。

### 6.3 状态与数据

- `api/business.ts` / `action.ts` / `permission.ts` / `icon.ts`：薄封装宿主 `request.ts`，类型取 `@bms/api-types` 的 `platform` 命名空间。
- 记录页 dirty：本体字段 + 名称多语言变化；关闭 / 切页签拦截。保存 = 一次 PUT / POST；新增保存成功后回填 ID 并切只读。
- 列表刷新：保存 / 删除后重拉当前页；业务码列表的「权限码数」由后端 `permission_count` 返回，不在前端聚合。

## 11. 边界与开放项 <a id="open"></a>

1. 业务 / 动作停用「连带停用权限码」为**单向**：重新启用不自动恢复权限码（避免误恢复），页面提示需逐条启用。
2. 权限码「补生成」默认只覆盖启用项；`include_disabled=true` 时也覆盖停用业务 / 动作（用于数据修复），结果计数区分 `created` / `restored` / `skipped`。
3. 图标页依赖现有 `/icons` 契约；若 `reference_count` 未在契约中，前端以列表返回为准并在对照表标注（实施时实测）。
4. 业务码 / 动作码删除为软删除；唯一约束按 `(code, deleted_at)`，重建同码时先探测软删除行并恢复。
5. 权限码组合只读 → 换组合需「删除 + 新建」；删除受引用保护，避免已授能力被静默改指。
