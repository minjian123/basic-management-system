## 1. 背景与目标 <a id="goal"></a>

合规要求管理员职责分离：**单一账号不得同时掌握系统配置、权限授予与审计查看**。租户侧据此设三类内置管理员角色——系统管理员（`role_type=system`）、安全管理员（`role_type=security`）、审计管理员（`role_type=audit`），三者权限互斥、同一用户不得兼任；`role` 业务（角色与授权本身）只归安全管理员，系统管理员与审计管理员不得越权授予。同时须明确**平台超管（`sys_admin`）的边界**：跨租户运营仅到租户级（开通 / 停用 / 域名 / 配额 / 模块开关），不进入租户业务数据、不经租户 RBAC 计算，平台级账号与租户侧账号隔离。

[`02_03` 角色管理](../../../02_用户与角色/02_用户与角色_03_角色管理/02_用户与角色_03_角色管理.md) 已交付内置角色保护（按 `sys_role.role_type` 判定，禁删 / 禁停用 / 禁改类型，错误码 `30043`）与错误码占位（`30048`），但**三权互斥的真实校验完全未实现**：三处 `sys_user_role` 写入口、角色授权写入入口均无任何互斥或归属校验。父任务风险条目明确指出——「三权分立若只在种子层预授、未在授权写入前置校验，仍可能被越权授予绕过」。本任务即补齐该前置校验，并把内置三类管理员与互斥预授清单固化为**单一来源**供 [`04_01` 租户管理与平台超管](../../../04_租户与平台超管/04_租户与平台超管_01_租户管理与平台超管/04_租户与平台超管_01_租户管理与平台超管.md) 开通种子引用。

**目标**：

1. 内置三类管理员角色与三权类型常量**单一来源**（`SEPARATION_ROLE_TYPES`），种子与校验共用。
2. **互斥校验前置生效**：三处 `sys_user_role` 写入口在事务内、写入之前校验「同一用户不得兼任两类内置管理员」，冲突拒绝 `30010`。
3. **`role` 业务归属强制**：`role:*` 权限码只允许授予 `role_type=security` 的角色（数据侧不变量，`30048`）；系统管理员 / 审计管理员调用角色域写端点即 `30048`（操作人侧护栏）。
4. **防自锁**：安全管理员不得修改自身所属角色的授权集合、不得通过授权使自身兼任互斥类型角色。
5. **平台超管边界可验证**：以机器护栏断言「平台层快照仅由无用户上下文的内部通道产生」「`sys_admin` 不在任何租户库表清单内」「平台库不含租户业务表」。
6. **审计留痕**：互斥拒绝 / 越权拒绝 / `role` 归属违规三类尝试经基座 `AuditCapturer` 产生审计事件（当前 `NullAuditCapturer` 不落库，用例以替身断言）。

**边界（不在本任务）**：

- **真实字段级审计落库**（`sys_data_audit_log` 表、哈希链）归审计合规模块（概要 28 / 数据库设计 29，尚未进入项目阶段）；本任务只接基座契约位 `AuditCapturer` 并在实施记录登记遗留。
- **租户开通种子编排**（开通流程批量写三类角色 + 初始系统管理员账号 + 首次登录强制改密）归 [`04_01`](../../../04_租户与平台超管/04_租户与平台超管_01_租户管理与平台超管/04_租户与平台超管_01_租户管理与平台超管.md)；本任务只定义口径与单一来源，不改开通流程、不建初始账号。
- **`sys_admin` 表与平台超管账号**（建表 / 首建 / 强制改密 / `tenant:manage`、`tenant:quota`）归 `04_01` 与 identity 服务；本任务只做边界断言。
- **组织主体链（`mdm` 组织角色）的三权互斥**不在本任务：`PermissionSubjectService` 的 `OrgRoleResolver` 结果不参与 `sys_user_role` 判定，互斥仅约束租户库直连角色分配。
- **前端**：本任务无前端改动；`30010` / `30048` 由统一错误提示呈现（既有件）。

## 4. 数据设计要点 <a id="data"></a>

不新增表。三权判定全部复用既有列，判定口径如下：

| 判定 | 载体 | 口径 |
| --- | --- | --- |
| 是否内置管理员 | `sys_role.role_type` | `role_type != 'custom'` 即内置（`02_03` 已定）；三权参与方仅 `system` / `security` / `audit` 三值 |
| 同一用户兼任几类 | `sys_user_role`（未软删）→ `sys_role.role_type` | 同一 `user_id` 的未软删角色中，`role_type ∈ SEPARATION_ROLE_TYPES` 的**去重值个数 > 1** 即兼任 |
| `role` 业务权限码 | 平台库 `sys_permission ⋈ sys_business(code='role')` | 权限码 id 集合；`sys_role_permission(perm_type='permission', target_id ∈ 该集合)` 即「`role` 业务授权」 |
| 角色归属合规 | `sys_role.role_type` | 存在 `role` 业务授权行的角色，`role_type` 必须为 `security` |
| 操作人所属角色 | `sys_user_role`（`user_id = current_user_id`）→ `sys_role.role_type` | 用于操作人侧护栏与防自锁 |

**常量单一来源**（`models/role.py`）：

```python
ROLE_TYPE_CUSTOM = "custom"
ROLE_TYPE_SYSTEM = "system"
ROLE_TYPE_SECURITY = "security"
ROLE_TYPE_AUDIT = "audit"
ROLE_TYPES = (ROLE_TYPE_CUSTOM, ROLE_TYPE_SYSTEM, ROLE_TYPE_SECURITY, ROLE_TYPE_AUDIT)

SEPARATION_ROLE_TYPES: tuple[str, ...] = (ROLE_TYPE_SYSTEM, ROLE_TYPE_SECURITY, ROLE_TYPE_AUDIT)
```

`ops/seed_rbac.py` 的三类角色 `plan` 与互斥预授清单改由该常量 + 角色码常量（`ROLE_SYSTEM_ADMIN` / `ROLE_SECURITY_ADMIN` / `ROLE_AUDIT_ADMIN`）驱动，`04_01` 开通种子直接引用同一来源，不再各自硬编码。

## 5. 接口设计 <a id="api"></a>

### 5.1 端点校验矩阵

不新增端点、不改请求 / 响应结构；仅在既有写端点插入校验。`_ROLE_DOMAIN_GUARD` = `Depends(_require_role_operator)`（操作人侧护栏，30048）。

| 端点 | 权限码（不变） | 操作人侧护栏 | 数据侧不变量 |
| --- | --- | --- | --- |
| `POST /roles` | `role:create` | ✔ | — |
| `PUT /roles/{role_id}` | `role:update` | ✔ | — |
| `DELETE /roles/{role_id}` | `role:delete` | ✔ | — |
| `POST /roles/{role_id}/users` | `role:grant` | ✔ | `30010` 兼任（增量：目标角色 ∪ 用户既有角色） |
| `DELETE /roles/{role_id}/users/{user_id}` | `role:grant` | ✔ | — |
| `PUT /roles/{role_id}/permissions` | `role:grant` | ✔ | `30048` `role` 归属 + 防自锁 |
| `PUT /roles/{role_id}/fields` | `role:grant` | ✔ | `30048` 防自锁 |
| `PUT /roles/{role_id}/data-permissions` | `role:grant` | ✔ | `30048` 防自锁 |
| `PUT /roles/{role_id}/assignments` | `role:grant`（+`role:update` 分段复校） | ✔ | `30010` 兼任（替换：该批用户） |
| `PUT /users/{user_id}/assignments`（`api/users.py`，用户域） | `user:assign_role` | —（非角色域端点） | `30010` 兼任（替换：该用户全量角色） |

依赖顺序：`require_auth`（模块级）→ 权限码依赖 → `_ROLE_DOMAIN_GUARD`。权限码先判（无权限者得 `PermissionError`），操作人护栏后判（系统管理员过权限码后在此被 `30048` 拦下）。

### 5.2 校验主体：`SeparationGuard`（`services/separation.py`）

```python
class RoleBusinessPermissions(BaseFrameworkObject):
    """`role` 业务的权限码集合（数据驱动，平台库）：`sys_business(code='role')` ⋈ `sys_permission`。"""

    def __init__(self, session: DbSession) -> None: ...
    async def permission_ids(self) -> ConcurrentStableSet[int]: ...


class SeparationGuard(BaseFrameworkObject):
    """三权分立校验（`03_02`）：互斥（30010）、`role` 归属与防自锁（30048）、操作人侧护栏（30048）。"""

    def __init__(
        self,
        *,
        roles: RoleRepository,
        user_roles: UserRoleRepository,
        business_permissions: RoleBusinessPermissions | None = None,
        audit: AuditCapturer | None = None,
    ) -> None: ...

    # 操作人侧护栏（30048）：系统 / 审计管理员不得进入角色域写端点
    async def ensure_role_domain_operator(self) -> None: ...

    # 分配路径（30010）：增量授予——目标角色 ∪ 用户既有角色 不得含两类内置管理员
    async def ensure_role_grant_exclusive(
        self, *, role: SysRole, user_ids: ConcurrentStableList[int]
    ) -> None: ...

    # 分配路径（30010）：替换授予——角色集合自身不得含两类内置管理员
    async def ensure_user_roles_exclusive(
        self, *, user_ids: ConcurrentStableList[int], roles: ConcurrentStableList[SysRole]
    ) -> None: ...

    # 角色 / 授权路径（30048）：`role` 业务只归 security；不得修改自身所属角色的授权集合
    async def ensure_grant_scope(
        self, *, role: SysRole, permission_ids: ConcurrentStableSet[int]
    ) -> None: ...

    # 字段 / 数据权限路径（30048）：不得修改自身所属角色的授权集合
    async def ensure_not_self_lock(self, *, role: SysRole) -> None: ...
```

判定细则：

1. **`ensure_role_domain_operator`**：`get_current_user_id()` 为 `None`（内部通道 / 平台层）→ 直接放行；否则取操作人未软删角色类型集合 `types`：`types ∩ {system, audit} ≠ ∅` 且 `security ∉ types` → `RoleSeparationConflictError("系统 / 审计管理员不得执行角色域写操作（三权分立）")`。`types` 含 `security`、或三类皆无（普通自定义角色）→ 放行（后者仍受权限码约束）。
2. **`ensure_role_grant_exclusive`**：`role.role_type ∉ SEPARATION_ROLE_TYPES` → 放行；否则逐个用户取既有角色类型（排除目标角色自身），若与 `role.role_type` 冲突（既有集合含其它 `SEPARATION_ROLE_TYPES` 值）→ `UserSeparationConflictError(f"用户已兼任内置管理员：{user_id}")`。
3. **`ensure_user_roles_exclusive`**：目标角色类型去重后 `∩ SEPARATION_ROLE_TYPES` 的个数 > 1 → `UserSeparationConflictError("同一用户不得兼任两类内置管理员（三权分立）")`。
4. **`ensure_grant_scope`**：① 若 `permission_ids ∩ role 业务权限码集合` 非空且 `role.role_type != security` → `RoleSeparationConflictError("`role` 业务仅限安全管理员角色持有（三权分立）")`；② 若操作人持有目标角色（`role.id ∈ 操作人角色`）且 `role.role_type ∈ SEPARATION_ROLE_TYPES` → `RoleSeparationConflictError("不得修改自身所属角色的授权集合（防自锁）")`。
5. **`ensure_not_self_lock`**：同 ② 的判定（字段 / 数据权限亦属授权集合）。

**前置性**：全部校验在写事务内、**写入语句之前**执行（`_require_role` 之后、`soft_delete_by_*` / `delete_by_role` / `create` 之前），拒绝时**不产生任何写入、不递增权限版本**。

### 5.3 错误码与拒绝语义

| 码 | 异常类 | HTTP | 场景 |
| --- | --- | --- | --- |
| `30010` | **新增** `UserSeparationConflictError(UserOrgError)` | 403 | 分配路径：同一用户将兼任两类内置管理员（三处 `sys_user_role` 写入口） |
| `30048` | 既有 `RoleSeparationConflictError(RoleError)` | 403 | 角色 / 授权路径：操作人侧越权、`role` 业务归属违规、防自锁 |

按路径分工的理由：`30010` 属用户域码段（`30009` 用户保护 / `30010` 用户三权冲突 / `30011` 用户被引用），语义主体是「用户」；`30048` 属角色域码段（`30041~30049`），语义主体是「角色 / 授权」。两者均已登记，本任务不新增码值。

### 5.4 缓存与版本

- 校验拒绝发生在写入前 → 权限版本键 `bms:{tenant_id}:permission:version` **不递增**（无 `_bump_version` 调用路径）。
- 校验放行后行为不变：一次成功写入一次版本 +1（既有实现）。
- 不新增缓存键、不改快照结构。

### 5.5 审计 <a id="audit"></a>

三类拒绝尝试在抛出异常**之前**经 `AuditCapturer.capture()` 产生事件（`FieldChange` 承载判定要素，`actor` 取 `current_user_id.get()`）：

| 尝试 | `table` | `model_id` | `changes` |
| --- | --- | --- | --- |
| 兼任互斥（30010） | `sys_user_role` | 用户 id | `FieldChange(field="role_type", old=既有类型, new=目标类型)` |
| 操作人侧越权（30048） | `sys_role` | `0`（未落库的操作） | `FieldChange(field="operator_role_types", old=操作人类型集合, new=目标操作)` |
| `role` 归属违规（30048） | `sys_role_permission` | 目标角色 id | `FieldChange(field="perm_type", old="", new="permission")` + `FieldChange(field="target_id", old="", new=违规权限码 id)` |
| 防自锁（30048） | `sys_role_permission` / `sys_role_field` | 目标角色 id | `FieldChange(field="role_id", old=操作人所属, new=目标角色)` |

当前 provider 为 `NullAuditCapturer`（不落库，返回 `EventEnvelope(event_type="audit.null")`）；用例以 `StubCapturer(AuditCapturer)` 断言调用次数与 `changes` 内容。真实 `sys_data_audit_log` 落库随审计合规模块回补，登记为遗留。

## 12. 决策确认 <a id="decide"></a>

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 校验实现形态 | 统一 `SeparationGuard`（新 `services/separation.py`，`BaseFrameworkObject`）；三处 `sys_user_role` 写入口在事务内、写入前统一调用；护栏可静态断言「写入口必调」 |
| 2 | 错误码分工 | 按路径分工：分配路径（写 `sys_user_role`、同一用户将兼任多个内置管理员）→ `30010`（新增 `UserSeparationConflictError`）；角色 / 授权配置路径（`role` 业务归属、防自锁、操作人越权）→ `30048`（既有 `RoleSeparationConflictError`） |
| 3 | `role` 业务归属强制 | 双层：① 数据侧不变量——`role:*` 权限码只允许授予 `role_type=security` 的角色，违反 `30048`；② 操作人侧护栏——请求主体持 system / audit 内置角色且不持 security 角色时，调用角色域写端点即 `30048` |
| 4 | `role` 业务识别 | 查平台库业务码：`sys_permission ⋈ sys_business` 取 `business.code == "role"` 的权限码集合（数据驱动，`RoleBusinessPermissions`） |
| 5 | 防自锁口径 | 自提权口径：安全管理员不得修改「自身所属角色」的授权集合；不得通过授权使自身兼任互斥类型角色；`role:*` 授权不得授予非 security 角色 |
| 6 | 平台超管边界验证 | 护栏断言现有边界：平台层快照仅由无用户上下文的内部通道产生、不经租户 RBAC 计算；`sys_admin` 不在任何租户库表清单内；平台库不含租户业务表。账号与开通流程留 `04_01` |
| 7 | 审计留痕 | 接基座契约位：互斥拒绝 / 越权拒绝 / `role` 归属违规三类尝试经 `AuditCapturer.capture()` 产生审计事件（当前 Null 实现不落库，用例可断言）；真实落库随审计合规模块，登记遗留 |
| 8 | 三权类型常量 | 模型层常量：`models/role.py` 增 `SEPARATION_ROLE_TYPES = (ROLE_TYPE_SYSTEM, ROLE_TYPE_SECURITY, ROLE_TYPE_AUDIT)`，种子与校验共用 |
| 9 | 测试夹具身份 | 新增 `grant_security_admin`，角色域用例改安全管理员身份；`permission_admin.py`（系统管理员）保留给菜单 / 用户扩展等非角色域用例 |
| 10 | 机器护栏落点 | 服务内 boundary 目录：`backend/services/platform/tests/boundary/test_separation_guard.py`（静态 AST 断言三处写入口均调 `SeparationGuard` 且调用在写入之前 + 行为断言内置角色保护与互斥前置） |
| 11 | `30010` 异常类 | 新增 `UserSeparationConflictError`（`30010`，HTTP 403），与 `RoleSeparationConflictError`（`30048`）并列 |
| 12 | 开通种子范围 | 定义口径并固化来源：三类内置角色与互斥预授清单固化为单一来源供 `04_01` 引用；不在本任务写开通流程与初始账号创建 |
