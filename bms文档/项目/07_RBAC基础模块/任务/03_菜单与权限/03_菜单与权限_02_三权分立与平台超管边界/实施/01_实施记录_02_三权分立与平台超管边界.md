## 2. 实施过程 <a id="process"></a>

### 2.1 基座异常与模型常量

- `libs/bms_core/src/bms_core/core/exceptions.py`：新增 `UserSeparationConflictError(UserOrgError)`（紧跟 `UserProtectedError`），码值 `ErrorCode.USER_SEPARATION_CONFLICT`（`30010`）、`http_status=403`，`data` 透传。码值早在 `error_codes.py` 登记，本任务只补异常类（此前只有 `RoleSeparationConflictError` / `30048` 有类）。
- `services/platform/src/bms_platform/models/role.py`：新增 `SEPARATION_ROLE_TYPES: tuple[str, ...] = (ROLE_TYPE_SYSTEM, ROLE_TYPE_SECURITY, ROLE_TYPE_AUDIT)`，docstring 声明为**三权类型单一来源**（互斥校验 / `role` 业务归属 / 种子预授清单 / 后续租户开通种子共用，禁止各自硬编码三值）。`ROLE_TYPES` 仍含 `custom`，四值口径不变。
- **不新增表 / 列 / 索引 / 迁移**：三权判定全部复用既有 `sys_role.role_type`、`sys_user_role`、`sys_role_permission`。

### 2.2 校验核心件 `services/separation.py`（新增，301 行）

```text
bms/backend/services/platform/src/bms_platform/services/
└── separation.py        # RoleBusinessPermissions + SeparationGuard（五个校验方法 + 审计拒绝辅助）
```

- `RoleBusinessPermissions(BaseFrameworkObject)`：`__init__(session: DbSession)` 构造 `BusinessRepository` / `PermissionRepository`；`async permission_ids() -> ConcurrentStableSet[int]` 遍历 `list_all()` 找 `code == "role"` 的业务行，再取其权限码 id 集合（**数据驱动**，不硬编码权限码串——`PermissionService._aggregate` 的码集来自按钮索引，未挂按钮的码不进快照，故不能用快照码集做归属判定）。
- `SeparationGuard(BaseFrameworkObject)`：`__init__(*, roles: RoleRepository, user_roles: UserRoleRepository, business_permissions: RoleBusinessPermissions | None = None, audit: AuditCapturer | None = None)`。`audit` / `business_permissions` 均可缺省（分支处理器与单元用例按需注入）。
- 五个公开校验方法（行号见 §4 覆盖明细）：

| 方法 | 码 | 判定 |
| --- | --- | --- |
| `ensure_role_domain_operator()` | `30048` | 操作人 `None`（内部通道 / 平台层）放行；`types ∩ {system, audit} ≠ ∅` 且 `security ∉ types` → 拒绝 |
| `ensure_role_grant_exclusive(*, role, user_ids)` | `30010` | 目标角色非三权类型放行；逐用户取既有三权类型（排除目标角色自身），`conflicting = others - {role.role_type}` 非空 → 拒绝 |
| `ensure_user_roles_exclusive(*, user_ids, roles)` | `30010` | 目标角色集合的三权类型去重后个数 > 1 → 拒绝 |
| `ensure_grant_scope(*, role, permission_ids)` | `30048` | `role` 业务归属（`permission_ids ∩ role 业务码` 非空且 `role_type != security` → 拒绝）+ 防自锁 |
| `ensure_not_self_lock(*, role)` | `30048` | 目标角色 ∈ 操作人所属角色 且 `role_type ∈ SEPARATION_ROLE_TYPES` → 拒绝 |

- 私有辅助：`_ensure_role_business_owner`、`_ensure_not_self_lock(role, table)`、`_role_types_of(user_id)`、`_separation_types_of(user_id, *, exclude_role_id)`、`_audit_reject(*, table, model_id, changes)`（`audit is None` 时静默返回，否则 `capture(..., actor=get_current_user_id())`）。
- 审计 `FieldChange` 承载判定要素（`sys_user_role` / 用户 id + `role_type`；`sys_role` / `0` + `operator_role_types`；`sys_role_permission` / 角色 id + `perm_type`、`target_id`），**在抛异常之前**产生，符合详细设计 §5.5。

| 文件 | 插入点 | 调用 |

### 2.4 授权入口与防自锁

- `services/role_grant.py`：`replace_permissions` 在 `_ensure_targets_exist` 之后、`delete_by_role` 之前调 `ensure_grant_scope(role=role, permission_ids=self._permission_targets(normalized))`；新增 `@staticmethod _permission_targets(entries)` 只取 `perm_type == PERM_TYPE_PERMISSION` 的 `target_id`（菜单 / 表单授权不参与 `role` 归属判定）。
- `replace_fields` / `replace_data_scopes` 各调 `ensure_not_self_lock(role=role)`（字段 / 数据权限同属授权集合）。
- `api/role.py::_grant_service` 注入含 `RoleBusinessPermissions(platform_uow.session)` 的 guard——`role` 业务码在**平台服务库**，与角色域租户库不同库，故必须用 `platform_uow` 会话。

### 2.5 操作人侧护栏（`api/role.py`，+131 / −19）

- 新增依赖别名 `ReadDbDep = Annotated[DbSession, Depends(get_read_db)]`、`AuditDep = Annotated[AuditCapturer, Depends(get_audit_capturer)]`。
- 新增 `async def _require_role_operator(db: ReadDbDep, audit: AuditDep) -> None` → `await _separation_guard(db, audit=audit).ensure_role_domain_operator()`，以 `_ROLE_DOMAIN_GUARD = Depends(_require_role_operator)` 挂到 **9 个角色域写端点**（`POST ""`、`PUT /{id}`、`DELETE /{id}`、`POST /{id}/users`、`DELETE /{id}/users/{user_id}`、`PUT /{id}/permissions`、`PUT /{id}/fields`、`PUT /{id}/data-permissions`、`PUT /{id}/assignments`），与既有权限码依赖并列（权限码先判、护栏后判）。
- 其中 5 个写端点签名补 `audit: AuditDep` 并透传给服务，使拒绝尝试可留痕。
- 用户域 `PUT /users/{user_id}/assignments` **不挂**该护栏（非角色域端点），其互斥由 `_apply_roles` 的 `30010` 负责。

### 2.6 种子单一来源（`ops/seed_rbac.py`，+42 / −4）

- 新增模块级 `BUILTIN_ADMIN_ROLES: tuple[tuple[str, str, str, tuple[str, ...]], ...]`——「三类内置管理员角色 + 授权清单」唯一来源（`04_01` 开通种子直接引用）；`seed_rbac()` 的 `plan` 改由它构造（原三条 `plan.add(...)` 删除），并导入 `SEPARATION_ROLE_TYPES` 做类型一致性约束。
- `SeedOutcome` 新增 `assign_conflicts: ConcurrentStableList[str]`（「因三权互斥被拒绝的绑定」）；`_ensure_assignment` 写 `sys_user_role` 前复用同一互斥语义：查目标角色 `role_type`，再查账号已持的 `SEPARATION_ROLE_TYPES` 类型，`any(held != target_type)` 即记 `assign_conflicts` 并跳过（**种子不绕过护栏**）。
- `main()` 输出新增一行「三权互斥、已拒绝绑定的账号」。
