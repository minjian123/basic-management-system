## 2. 任务内容 <a id="content"></a>

1. **消费约定登记**：登记阶段七侧消费口径——用户管理页（`07-2` 交付）以具名插槽 `sys.user.detail.tabs` 提供挂接位；mdm 组织域「用户分配岗位」插件按阶段五 `05-10` 约定注册区域项（插槽键 / 次序 / 权限码 `org:update` / 显示条件 / `tabs` 形态），写 mdm 用户-岗位契约（`/api/v1/org/user-posts`）。**另**：角色管理页（`07-3` 交付）「角色分配」页签以具名插槽（`sys.role.detail.assign`）提供挂接位，mdm「岗位分配 / 部门分配」插件注册区域项，写 mdm `org_role_post` / `org_role_dept`（依赖基座**显式上下文注入通道**，需求 `05-11`，见第 3 条）。
2. **降级口径**：插件未注册 / 未启用 / mdm 不可达 / 权限不满足时插槽项隐藏、宿主页其余正常（不报错、不阻塞）；阶段五 `05-10` 就绪前相关扩展位按降级处理，不阻塞用户完整域其余功能（转 `07-2` / `07-4`）。
3. **依赖与消费方标注**：沿用阶段五「宿主不直连插件」护栏；向 mdm 侧标注**前置契约已交付**（阶段五 `06_01`）；**角色分配页签的岗位/部门分配插件另依赖基座「显式上下文注入通道」（需求 `05-11`）**——**已就绪（2026-10-08，阶段五任务 `06_03` 交付：插槽件 `context` 只读注入 + 区域项 `useModuleSlotContext()` 消费，且角色分配页签 `RoleAssignTab` 已留槽并注入角色标识）**；跟踪 mdm 组织域（`org_dept` / `org_post` / `org_user_post` / `org_role_post` / `org_role_dept` 与用户-岗位、角色分配契约、组织只读出口）就绪情况，未就绪按降级推进。
4. **不重复实现**：具名插槽机制实现随阶段五 `05-10`，本任务只作阶段七侧消费与依赖登记，**不新建插槽基座、不改注册表基座**。

## 3. 完成标准 <a id="accept"></a>

用户管理页（`07-2` 交付后）按 `05-10` 约定提供 `sys.user.detail.tabs` 挂接位，mdm 插件经该槽挂接且缺失即隐藏、不报错；角色管理页「角色分配」页签（`07-3` 交付后）提供岗位/部门分配插件挂接位，插件缺失即隐藏（**上下文通道 `05-11` 已就绪**〔2026-10-08，阶段五 `06_03`〕，余依赖 mdm 组织域就绪）；消费约定、降级口径与依赖跟踪成文并有 mdm 侧消费方标注；阶段五 `05-10` 完成标准已全部达成（引用其验收证据）。

> **闭环完成（2026-10-09）**：闭环判据（mdm 插件经 `sys.user.detail.tabs` **真挂接** + **缺失即隐藏**）已真机验收通过——三子页签（角色分配 10 / 岗位分配 20 / 部门分配 30）同槽并列渲染、模块宿主未起时仅剩平台内建项且不报错、插件已取到宿主注入的上下文；证据与结论见[测试记录 §8](测试/01_测试记录_01_具名插槽挂接消费与依赖登记.md#closure)与[实施记录 §8](实施/01_实施记录_01_具名插槽挂接消费与依赖登记.md#closure)。余：插件**写链路**（草稿随宿主保存）归跨仓联调窗口（需 mdm 组织域服务，本机无 docker）。

> **前置登记段完成（2026-10-08）**：消费约定（两个消费位的槽 / 宿主 / 插件声明 / 写契约 / 权限码 / 上下文通道）、降级口径（7 类情形）与依赖 · 消费方标注已成文——[详细设计](设计/01_详细设计_01_具名插槽挂接消费与依赖登记.md)、[实施记录](实施/01_实施记录_01_具名插槽挂接消费与依赖登记.md)、[测试记录](测试/01_测试记录_01_具名插槽挂接消费与依赖登记.md)；计划表 `01_01` 记「**部分完成**」。**闭环**（mdm 插件经 `sys.user.detail.tabs` 真挂接 + 缺失即隐藏）随宿主正式页 `02_02` 交付后一并验收——mdm 组织域与其三插件、`05-11` 上下文通道均已就绪，闭环现仅待宿主正式页。

> **消费约定回写（2026-10-09，随 mdm `01_02/_02` 交付）**：① mdm 侧插件由**三个**增为**四个**——`sys.user.detail.tabs` 下为「用户分配岗位」（`order` 20）＋**新增「用户分配部门」**（`order` 30，键 `mdm-org:user-depts`）；`sys.role.detail.assign` 仍为岗位 / 部门两插件；② **上下文通道口径变更**：`sys.user.detail.tabs` 的作用实体标识由「路由参数（`/sys/users/:id`）」改为「**宿主经插槽上下文显式注入 `userId`**、路由参数**作兜底**」——因 `02_02` 用户记录页为**表单框架记录页签（非路由承载）**，无 `:id` 路由参数；宿主须在插槽上下文对象内提供 `userId`（`sys.role.detail.assign` 的 `roleId` 口径不变）；③ **宿主保存通道（新协作协议，需宿主侧成对接上）**：插件改动进**草稿**，宿主记录页签在插槽上下文中提供 `registerSubmitter`（**字段值即注册函数** `(entry) => void`，`entry = { submit, isDirty }`）⇒ 宿主工具栏「保存」统一提交、并以 `isDirty()` 做脏标记与离开拦截；宿主**未提供**该通道时插件自提交兜底（不回归）。宿主侧落地：`02_02` 用户记录页（及 `02_03/_02` 角色侧）；④ mdm 前置契约状态：`/api/v1/org/user-posts`、`/role-posts`、`/role-depts`、`/user-roles` 与**新增** `/api/v1/org/user-depts`、两条 `/…/primary` 置位端点**均已交付**（mdm `01_02/_02`，2026-10-09）。

> **完成口径（2026-10-04 拍板）**：本任务拆两段——**前置登记**（消费约定 / 降级口径 / 依赖标注与 mdm 侧消费方标注，可先行）＋**闭环**（mdm「用户分配岗位」插件经 `sys.user.detail.tabs` 真挂接且缺失即隐藏的验证）。闭环**外部依赖 mdm 组织域**（mdm 规划 §7「阶段三 主数据实现」，未启动实施；见[计划 §7 第 1 项](../../../计划/01_计划_RBAC基础模块.md#followup)），其宿主方为用户管理页 `02_02`；故本任务**不占阶段七「首个完成」位**，首个可完整交付的实现任务为 `03_01`。mdm 侧未就绪期间，用户管理页挂接位按降级（隐藏）推进。
