## 1. 域说明 <a id="intro"></a>

本域承载阶段七的**用户与角色**主线：在阶段六已交付的 `sys_user` 最小模型与认证链路上，补齐**用户完整域**（个人资料 / 头像 URL / 组织归属 / CRUD / 启停 / 删除 / 重置密码 / 主体角色绑定查看 / SSO 身份绑定查看 / 账号锁定与解锁），落地**角色管理**（角色定义、主体绑定、菜单/表单/动作/字段权限授予、动作数据范围配置）与**主体链权限计算引擎**（用户/岗位/部门任意主体链收敛、权限聚合、版本失效、两级校验、字段权限与数据范围）。

- **对应 WBS 域**：《总体项目规划》阶段七「用户/角色/主体链权限」；架构 15-权限计算引擎；概要 03-用户管理 / 06-角色管理。
- **组织主数据引用**：用户归属部门 `sys_user.dept_id` 为对 **mdm 组织主数据部门**（`org_dept`）的逻辑外键（字段保留在 bms）；用户-岗位关联随组织主数据迁 mdm（`org_user_post`，2026-10-03），岗位分配经 mdm「用户分配岗位」插件（挂用户管理页具名插槽 `sys.user.detail.tabs`，见 [07-1](01_需求_插件化挂接.md#r07-1)）读写；主体链 post/dept 主体 `subject_id` 引用 mdm 组织主数据 id，部门/岗位只读回显经组织主数据只读出口。
- **端范围**：PC（后端 org/identity 服务 + 前端用户管理 / 账号锁定 / 角色管理页）。
- **依据**：《[总体项目规划](../../../规划/总体项目规划.md)》（阶段七行、完成标准）、《[项目规划说明](../../../规划/项目规划说明.md)》（权限模型、业务与动作清单）、《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》、《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》《[概要设计 · 角色管理](../../../设计/概要设计/06_概要设计_角色管理.md)》、mdm《概要设计 · 岗位管理》「用户分配岗位插件」。

## 2. 需求 07-2：用户完整域 <a id="r07-2"></a>

优先级：2（高）

**背景与动机**：阶段六只落地了 `sys_user` 最小模型（账号状态 / 锁定 / 密码哈希等），仅供登录链路与 SSO JIT 建号使用，没有面向管理员的用户生命周期治理与自助资料；管理员无法建号、改资料、重置密码、分配组织归属，也无从查看账号锁定与 SSO 身份绑定。若不补齐，角色授权与主体链权限计算将缺少主体来源，用户无法被正常纳入 RBAC 体系。

**内容**（概要 03；《总体项目规划》阶段七行）：

1. **用户 CRUD**：列表 / 详情（筛选 `username/nickname/email/phone/status/dept_id/岗位`、分页）；新建（初始化密码 + 强制首登改密开关）；修改（昵称 / 邮箱 / 手机 / 部门 / `locale` / `timezone`）；软删除（`deleted_at`，`(username, deleted_at)` 复合唯一使删除即释放用户名）；启用 / 停用（停用即时失效会话）。
2. **密码重置**：PBKDF2 重哈希、写 `pwd_changed_at/pwd_history/pwd_reset_required`、失效该账号全部会话、可选通知。
3. **主体角色绑定查看**：查看该用户直接绑定的角色（`sys_role_assign`，绑定维护归角色管理侧，见 07-3）；**SSO 身份绑定查看**：只读展示 `sys_user_identity`（绑定管理归 sso 业务）。
4. **账号锁定治理**：锁定列表 / 详情、**手动锁定**（写 `sys_account_lock` `manual` 型，记录锁定人与原因）、**手动解锁**（记录 `unlock_at/unlock_by`）；与阶段六已交付的锁定读写口径衔接。
5. **组织归属**：部门引用 mdm 组织主数据（逻辑外键，经组织只读出口回显）；岗位分配经 mdm「用户分配岗位」插件（挂 07-1 具名插槽）写 mdm 用户-岗位契约，**插件未注册 / mdm 不可达时该 Tab 隐藏、页面其余正常**。
6. **前端页面**：用户管理页（列表筛选、新建 / 编辑 / 删除、启停内联切换、重置密码、主体绑定与身份绑定查看、岗位分配 Tab、导入入口）与账号锁定页（锁定列表、手动解锁、解锁记录）。
7. **契约与安全**：用户接口按公开契约快照与前端 `api-types` 生成，前端不硬编码；权限码 `user:query/create/update/delete/reset_pwd/lock/unlock/assign_role`；错误码段 3xxxx（30001~30011）；事件 `sys.user.created/updated/deleted/password_reset`；敏感字段（密码 / token）日志脱敏。
8. **安全约束**：不得停用 / 删除当前操作人自身；内置管理员不可停用删除；密码策略（复杂度 / 有效期 / 历史不可重复 / 长期未登录自动锁定）强制执行。

**完成标准**：用户 CRUD 全链路可用，软删除后用户名可复用；重置密码后强制改密生效且全部会话失效；停用 / 删除即时踢出；锁定列表 / 手动锁定 / 手动解锁可用、解锁留痕可查；部门经组织只读出口回显，岗位分配经 mdm 插件读写且缺失即隐藏、不报错；`user.*` 事件发布；密码策略（复杂度 / 有效期 / 近 5 次历史 / 未登录自动锁定）强制生效；`user.*` 契约与前端类型生成对齐。

**参考文档**：《[概要设计 · 用户管理](../../../设计/概要设计/03_概要设计_用户管理.md)》§2/§5/§6/§8；《[总体项目规划](../../../规划/总体项目规划.md)》阶段七行；《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§8；mdm《概要设计 · 岗位管理》§5.4；阶段七 [07-1 插件化挂接](01_需求_插件化挂接.md#r07-1)

## 3. 需求 07-3：角色管理 <a id="r07-3"></a>

优先级：2（高）

**背景与动机**：权限授予需要「角色」作为授权载体——菜单 / 表单 / 按钮 / 字段权限与动作数据范围都挂角色、再经主体绑定落到用户；阶段七前平台无角色定义与授予能力，无法把权限授予各类主体。角色管理是主体链授权与权限计算的授权数据来源。

**内容**（概要 06；架构 15 §2/§5/§6）：

1. **角色 CRUD**：`code/name/status`，`(code, deleted_at)` 复合唯一；内置角色（系统 / 安全 / 审计管理员）不可删改归属；删除前校验主体绑定与授权引用（防自锁）。
2. **主体绑定**：`sys_role_assign`（`subject_type` + `subject_id` + `role_id`）支持 user / post / dept 任意主体链，post / dept 的 `subject_id` 引用 mdm 组织主数据 id；新增实体仅扩枚举。
3. **菜单权限授予**：`sys_role_permission` `perm_type=menu`（**仅菜单入口**）；勾选菜单入口**连带授予其表单查看权限**（查看 = 表单权限）；业务权限按「表单→业务」对照关系推导，不直接授予业务码。
4. **表单操作权限授予**：`perm_type=action`（按钮级），**默认无任何按钮权限**，授予后显隐；带**来源标记**，本菜单入口连带生成的可改、非本入口来源只读。
5. **字段权限授予**：`sys_role_field`（`role_id+form_id+field_id` 的 `visible/editable`），默认全部可见可编辑，授予后收窄。
6. **动作数据范围配置**：`sys_data_scope`（动作 → 规则表达式：字段 + 运算符 + 预置变量），默认无数据权限；保存前沙箱解析校验，规则结果强制叠加租户过滤。
7. **变更即时生效**：角色 / 授权 / 主体绑定 / 字段权限 / 数据范围变更 → 权限版本 +1 并清理对应用户缓存；批量授权单事务全量覆盖提交（先删后插）。
8. **前端页面**：角色管理页（角色列表、新建 / 编辑 / 删除、主体绑定、菜单 / 表单 / 动作授权树、字段权限矩阵、数据范围配置页签）。
9. **契约与安全**：权限码 `role:query/create/update/delete/grant`；错误码段 3xxxx（30041~30049）；授权接口为高敏感操作，记录操作人、前后差异与 IP；角色 / 授权变更落字段级审计；三权分立约束见 [07-6](03_需求_菜单与权限.md#r07-6)。

**完成标准**：角色 CRUD 与引用校验正确，内置角色保护生效；主体绑定支持任意主体链；权限分层正确（勾选菜单入口连带表单查看，业务权限推导正确）；操作权限默认无、来源判定正确（本入口连带可改、非本入口来源只读），按钮显隐正确；字段权限默认全开、收窄后读过滤 / 写拒绝生效；数据范围默认无、配置后读时过滤 / 写时校验双向生效且不跨租户；授权变更即时生效（版本失效）；批量授权幂等且单事务回滚；角色 / 授权变更字段级审计可查。

**参考文档**：《[概要设计 · 角色管理](../../../设计/概要设计/06_概要设计_角色管理.md)》§2/§4/§5/§6/§8；《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§5/§6；需求 [07-6 三权分立](03_需求_菜单与权限.md#r07-6)

## 4. 需求 07-4：主体链权限计算引擎 <a id="r07-4"></a>

优先级：2（高）

**背景与动机**：阶段六认证链路已就绪但 token 不内嵌权限；登录后必须按主体链实时计算并缓存权限，作为菜单 / 按钮 / 字段显隐与后端接口强制校验的唯一依据。缺少该引擎，任何越权校验、数据范围与字段权限都无从落地，阶段七全部业务接口的权限校验也将失去基座。

**内容**（架构 15 §3/§4/§5/§6/§9；概要 06）：

1. **主体链收敛**：从用户出发沿 `sys_role_assign` 迭代收集「用户直接 + 岗位 + 部门」等全部绑定角色；链条任意长度，多链取并集去重，统一收敛为「用户 → 角色」。
2. **权限聚合**：角色集合 → `sys_role_permission` → 业务码集合 + 动作码集合；结果缓存 Redis（`bms:{tenant}:perm:{user_id}:{version}`）。
3. **版本失效**：角色 / 授权 / 主体绑定 / 岗位 / 部门变更 → 权限版本 +1 并清理相应用户缓存，保证变更即时生效。
4. **两级校验点**：业务级 `require_permission(业务码)`（依赖注入，路由注册时声明）与动作级 `require_permission("业务:动作")`；后端强制校验与前端显隐双重控制。
5. **字段权限**：读时序列化层过滤不可见字段（不返回不渲染），写时校验不可编辑字段（拒绝保存）；与数据脱敏（`data:plain`）互补。
6. **数据范围**：`sys_data_scope` 规则表达式解析为 SQL 条件注入 repository 查询（读时）、写入口校验（写时），双向检查；规则结果强制叠加租户过滤，任何规则不得跨租户。
7. **组织主数据只读出口联调**：用户 / 岗位 / 部门树作为主体链与数据范围的数据来源，统一经主数据查询出口（查询与批量回显分列、部门树一次性返回）；数据可见范围经数据范围注入过滤、敏感字段脱敏，**过滤与脱敏在实现侧强制接入、调用方不可绕过**；业务与前端只经该出口取数，不直连 mdm 组织表。前端组织选择字段族已交付（阶段四链路），本需求完成真实取数 / 数据范围 / 脱敏联调。
8. **权限概要装载**：登录后首次加载权限概要，供动态菜单与前端显隐使用。

**完成标准**：任意长度主体链权限计算正确、多链并集去重；越权与跨租户访问被拒验证通过；授权 / 岗位 / 部门变更经版本失效即时生效；字段权限读不返回、写拒绝生效；数据范围读写双向检查生效且强制租户过滤；组织主数据只读出口联通，过滤与脱敏不可绕过；登录后权限概要装载正确。
