## 1. 域说明 <a id="intro"></a>

本域收口《[原型审查规范](../../../规范/原型审查规范.md)》§4.9「实现 ↔ 原型 / 布局 核对（界面类交付验收）」的**机器门禁积压**：该门禁（`scripts/tools/base_check/check_prototype_review.py --changed`）在**变更集含界面源码**（`frontend/apps/desktop/src/{views,components,layouts}`、`frontend/packages/ui_ep/src`、任意 `*.vue`）时，要求 `origin/main...HEAD` 变更集内**全部测试记录**含「原型对照结论」节（原型依据引用 + 表头含「结论」的逐页表 + 至少一张**存在**的 `.png` 截图；纯逻辑改动可写「不适用」并给理由）。

- **本域范围**：为**历次未登记「原型对照结论」的测试记录**按 §4.9 补写该节——属**界面类**者以《[布局设计](../../../设计/布局设计/)》与**对应原型**（页面原型 `设计/原型设计/**.html` / 组件设计自带原型 `设计/组件设计/**/*.html`）为基准，真机 / 无头截图 + 识图逐页对照；属**纯逻辑**（后端 / CI / 治理 / 验收报告）者写「不适用」并给理由。
- **不重复建设**：原型资产（`设计/原型设计/` 页面原型、`设计/组件设计/` 组件原型共 123 份 `.html`）与《[布局设计](../../../设计/布局设计/)》均已交付；门禁脚本与 `preflight` / CI 挂接已生效；本域**只补记录侧的对照结论**，不改原型、不改实现（发现实现偏离原型的，另立修复项并回写对应任务）。
- **触发背景**：门禁按 `origin/main...HEAD` **变更集**校验。仓库长期未推送期间变更集持续累积，一旦新提交首次引入 `.vue` 改动（2026-10-12 覆盖率补齐轮修 `RoleRecordTab.vue`），门禁即转去校验变更集内**全部**历史测试记录——**2026-10-12 实测命中 58 份**（阶段一 10 / 阶段二 15 / 阶段四 12 / 阶段五 10 / 阶段六 11），全部缺该节。
- **已定口径（2026-10-12 拍板）**：
  1. **立项**：纳入**阶段七**、新增需求域 07「原型对照结论补齐」，**不改既有 11 条需求**；需求编号顺延为 `07-12` ~ `07-14`。
  2. **任务拆分**＝按**对照依据**分 3 个子任务（`07_01` 非界面类 / `07_02` 组件类 / `07_03` 页面类），与需求 `07-12` ~ `07-14` 一一对应。
  3. **非界面类口径**＝写「**不适用 + 理由**」（门禁显式允许，理由 ≥ 10 字），不造无效截图。
  4. **界面类深度**＝按 §4.9 **全量**：真机 / 无头截图 + 识图逐页对照，结论登记到**各历史任务自身的测试记录**（不新建平行记录）。
  5. **执行位置**＝插在 `05_01` 阶段验收**之前**（§4.9「未通过不得进入阶段验收」），`05_01` 顺延。
  6. **执行期清单以脚本输出为准**：命中集合随 `origin/main` 前移与变更集变化而**收敛**，实施前重跑 `check_prototype_review.py . --changed` 取最新清单。
- **依据**：《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 与 §6.2、《[文档生成规范](../../../规范/文档生成规范.md)》8.5「去实现命名」、《[测试规范](../../../规范/测试规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「覆盖率要求」节（机器门禁口径）。
- **用例口径**：本域**不产自动化单测**（对照结论为文档证据），故**不登记 Kiwi 用例**；门禁复跑命令即验收判据。

## 2. 需求 07-12：非界面类记录「原型对照结论」补齐 <a id="r07-12"></a>

优先级：2（高）

**背景与动机**：58 份命中记录中约四分之三属**纯逻辑**交付（后端基座、服务化地基、CI 流水线、数据拓扑、治理与阶段验收报告），其任务**没有界面可见变更**——但门禁只看「变更集是否含界面源码」，不区分单份记录的任务性质，故这些记录同样被要求含「原型对照结论」节。若不补齐，门禁恒红、**阻断推送**；若一律硬补逐页截图，则对无界面任务制造虚假对照，与 §4.9「不得以造假应付门禁」的精神相悖。门禁已显式给出「纯逻辑改动可写『不适用』并给理由」的口径，本需求即按该口径逐份登记。

**内容**（《[原型审查规范](../../../规范/原型审查规范.md)》§4.9「机器门禁（强制）」）：

1. **清单以脚本为准**：实施前重跑
   `python3 scripts/tools/base_check/check_prototype_review.py . --changed`
   取其命中清单，按本域 `07_01` 详细设计的判定规则**逐份归类**；初判非界面类 **44 份**（阶段一 10 / 阶段二 15 / 阶段四 1 / 阶段五 9 / 阶段六 9，2026-10-12 实测）。
2. **逐份核对**：对每份记录，核对其所属任务的**交付物**确无界面可见变更（检索该任务目录是否引用 `frontend/**/src/{views,components,layouts}/**.vue`、是否登记页面 / 组件原型依据），**逐份留痕该核对结论**，不得批量默认。
3. **补写节**：在各历史任务自身的 `测试/*.md` 内新增「原型对照结论」节，内容为「不适用」+ 理由（说明为何无界面可见变更，理由 ≥ 10 字），并**不含**未完成词（`待补` / `待对照` / `未核对` / `TODO` 等）。
4. **不改实现**：本需求只改文档；核对中发现实现侧偏离原型的，**登记为修复项并回写对应历史任务**，不在本需求内改代码。
5. **门禁复跑**：补写后复跑门禁与 `preflight`，确认不再命中。

**完成标准**：脚本命中清单中初判非界面类的记录**全部**含「原型对照结论」节，节内为「不适用 + 理由」且无未完成词；逐份核对结论可追溯；复跑 `check_prototype_review.py . --changed` 对这批记录零命中；`preflight` 该项通过。

**参考文档**：《[原型审查规范](../../../规范/原型审查规范.md)》§4.9、《[任务文档规范](../../../规范/任务文档规范.md)》「测试文档」节、《[文档生成规范](../../../规范/文档生成规范.md)》

## 3. 需求 07-13：组件类记录「原型对照结论」补齐 <a id="r07-13"></a>

优先级：2（高）

**背景与动机**：命中记录中属**前端组件库**（阶段四）的 12 份中，10 份交付的是 `ui-ep` **件族**（基础组件类 / 布局组件类 / 交互类面板与工具），其对照基准是《[组件设计](../../../设计/组件设计/)》**自带原型**（`设计/组件设计/**/*.html`，共 123 份）而非页面原型。§4.9 明确「件族任务用后者」，但既有记录既未引用该原型、也无逐页对照结论——需按「组件渲染截图 + 对照表」补齐。

**内容**（《[原型审查规范](../../../规范/原型审查规范.md)》§4.9、《[前端开发规范](../../../规范/前端开发规范.md)》）：

1. **清单以脚本为准**：同上重跑取清单；初判组件类 **10 份**（阶段四 `02_基础组件类` 7 份 / `03_布局组件类` 2 份 / `08_交互类_03_01` 1 份，2026-10-12 实测）。
2. **原型依据**：逐份定位对应的 `设计/组件设计/**/NN_原型设计_XXX.html`（件族任务的原型依据落此处），并在该记录内引用（相对链接，文件存在）。
3. **对照结论**：在对应历史任务的 `测试/*.md` 内新增「原型对照结论」节，含**表头含「结论」的对照表**（列建议 `# / 对照项 / 原型依据 / 实现实测 / 结论`）与**至少一张存在的截图**（落 `测试/资源/<记录名>/`）；对照项按件族粒度逐件落行，结论为「对齐 / 偏离（附处置归口）」。
4. **截图手段**：以宿主开发态核对页（`frontend/apps/desktop/*-check.html`）或既有组件核对入口渲染件族，真机 / 无头截图；**不引入新机制**。
5. **不改实现**：只补记录；发现组件偏离原型的，登记修复项并回写对应件族任务。

**完成标准**：初判组件类的记录全部含「原型对照结论」节（逐件对照表 + 存在性 `.png` 截图 + 组件设计原型引用），无未完成词；复跑门禁对该批零命中；`preflight` 该项通过。

**参考文档**：《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 与 §6.2、《[组件设计](../../../设计/组件设计/)》各件族原型、《[前端开发规范](../../../规范/前端开发规范.md)》

## 4. 需求 07-14：页面类记录「原型对照结论」补齐 <a id="r07-14"></a>

优先级：2（高）

**背景与动机**：命中记录中交付**可见页面 / 宿主外壳 / 模块样例**的 4 份（阶段四 `10_微前端骨架_01` 宿主外壳与模块加载器、阶段五 `04_首个模块样例_01`、阶段六 `05_登录前端_06` 登录页多租户选择、`01_认证与会话_07` 会话续期与登录入口可达性），其对照基准是《[布局设计](../../../设计/布局设计/)》与**页面原型**（`设计/原型设计/**.html`）。§4.9 要求**真机 / 无头截图 + 识图逐页比对**，是本次积压中要求最高、也最容易暴露真实实现缺陷的一批。

**内容**（《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 与 §5 步骤 7）：

1. **清单以脚本为准**：同上重跑取清单；初判页面类 **4 份**（2026-10-12 实测）。
2. **原型依据**：逐份定位对应页面原型（如 `设计/原型设计/03_通用骨架/02_登录页.html`、`设计/原型设计/06_首页工作台/` 等）与《[布局设计](../../../设计/布局设计/)》对应节，并在记录内引用（文件存在）。
3. **逐页对照**：在对应历史任务的 `测试/*.md` 内新增「原型对照结论」节，含表头含「结论」的**逐页**对照表（每个界面一行）与**至少一张存在的截图**（落 `测试/资源/<记录名>/`）；对照维度按 §4.9：逐页齐备 / 视觉完整无裸骨架 / 结构对齐布局设计 / 交互对齐原型 / **去实现命名**（可见文本不得出现类名 / 函数名 / 能力键 / 路径 / 包名）/ 主题与响应式 / 空态与加载与异常。
4. **识图比对**：真机 / 无头截图后按《原型审查规范》§6.2 以识图逐页比对；交互态页面（弹窗 / 详情）用静态检查确认结构。
5. **偏离处置**：发现实现偏离原型的，**登记修复项**（含归口任务）并回写对应历史任务；**未通过不得进入阶段验收**。
6. **承前**：本需求为 `05_01 阶段验收门禁核对与阶段测试报告` 的**前置**（执行位置在其前，见阶段计划）。

**完成标准**：初判页面类的记录全部含「原型对照结论」节（逐页对照表 + 存在性 `.png` 截图 + 页面原型引用 + 去实现命名核对行），无未完成词；识图比对完成且偏离项均已登记归口；复跑门禁对该批零命中；`preflight` 该项通过。

**参考文档**：《[原型审查规范](../../../规范/原型审查规范.md)》§4.9、§5、§6.2、《[布局设计](../../../设计/布局设计/)》对应节、《[原型设计](../../../设计/原型设计/)》对应模块、《[文档生成规范](../../../规范/文档生成规范.md)》8.5「去实现命名」
