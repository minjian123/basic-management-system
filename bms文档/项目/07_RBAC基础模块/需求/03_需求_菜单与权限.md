## 1. 域说明 <a id="intro"></a>

本域承载阶段七的**菜单与权限**主线：把权限元数据（菜单 / 表单 / 按钮 / 字段与业务 / 动作码）落为平台统一维护的实体与挂接关系，并以**动态菜单接口**下发菜单树与表单元数据，作为前端动态路由、侧边栏、按钮与字段显隐的唯一依据；同时落地**三权分立**（内置三类管理员互斥与平台超管边界），保证授权与运营的职责分离。

- **对应 WBS 域**：《总体项目规划》阶段七「菜单/表单/按钮/字段挂接、动态菜单接口、三权分立」；概要 07-菜单管理；架构 15-权限计算引擎 §2/§7/§8。
- **落点说明**：菜单 / 表单 / 按钮 / 字段与业务 / 动作码存**平台库**，平台超管统一维护，租户侧只读可分配不可增删；字段权限授予写入口在角色管理（`role:grant`），本域提供配置入口与元数据。
- **端范围**：PC（后端 meta 能力 + 前端动态路由 / 菜单 / 按钮 / 字段消费）。
- **依据**：《[概要设计 · 菜单管理](../../../设计/概要设计/07_概要设计_菜单管理.md)》、《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§7/§8、《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[概要设计 · 审计合规](../../../设计/概要设计/28_概要设计_审计合规.md)》（三权分立）。

## 2. 需求 07-5：菜单/表单/按钮/字段挂接与动态菜单接口 <a id="r07-5"></a>

优先级：2（高）

**背景与动机**：权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）必须有平台统一维护的元数据载体；前端动态路由、侧边栏、按钮与字段显隐的唯一依据是动态菜单接口，不得硬编码路由或权限清单。缺少该能力，新增菜单 / 表单 / 按钮 / 字段都要改前端发版，角色授权也无从选择授权对象。

**内容**（概要 07；架构 15 §2/§7）：

1. **菜单维护**：菜单树（`parent_id/name/path/component/icon/sort/hidden/status`），关联表单（多对多，经关联表 `sys_menu_form`——不同菜单入口可指向同一表单、表单可无入口）。
2. **表单维护**：表单实体（挂业务 `business_id`、`component`；菜单挂接经关联表），形成「表单→业务」链。
3. **按钮维护**：按钮实体（挂表单 `form_id`、挂权限码 `permission_id`、`type`（toolbar/interface）、`sort`），形成「按钮→动作」链，默认无任何按钮权限。
4. **字段维护**：字段实体（挂表单 `form_id`、`field_key/name/type/sort/status`），作为字段权限控制依据。
5. **业务 / 动作码管理**：`sys_business` / `sys_action` 平台统一维护，租户侧可见、可分配、不可增删；业务 / 动作码一经发布稳定，停用代替删除。
6. **挂接链完整性**：菜单 ↔ 表单**多对多**（关联表 `sys_menu_form`）、表单 1:1 挂业务、按钮 1:1 挂权限码、字段挂表单，任一缺失导致该链路不可见 / 不可用，角色授予时校验并提示（错误码 **40202**；菜单域错误码段位经 2026-10-04 确认由 `400xx` 修正为 `402xx`，详见概要《菜单管理》「错误码与异常处理」节）。
7. **多语言**：菜单 / 业务 / 动作 / 字段名称存各自 `_i18n` 附表，按当前 locale 关联，缺省回退主表默认文案。
8. **动态菜单接口**：`GET /menus/my` 按用户已授予的菜单 / 表单权限过滤菜单树并下发表单元数据（按钮按动作权限、字段按字段权限标记可见可编辑状态），登录即可访问；菜单树与表单元数据 Redis 短 TTL 缓存（含随机偏移、按 locale 维度），变更即时失效。
9. **前端消费**：按动态菜单注册路由与侧边栏（不硬编码路由表）、按钮按动作权限显隐、字段按字段权限显隐与只读；菜单 / 表单 / 字段 / 按钮变更发布 `sys.form.updated` 事件（AI 帮助更新触发）。
10. **平台 MVP 页面挂接齐备**：用户管理 / 角色管理 / 账号锁定 / 租户管理等平台页面菜单→表单→业务、按钮→动作链路齐全，配 i18n 文案。

**完成标准**：新增菜单 / 表单 / 按钮 / 字段后前端动态注册路由与侧边栏免发版生效、菜单名多语言显示正确（含缺省回退）；挂接链断裂在角色授予时被拦截并提示；动态菜单接口按权限过滤正确（未授予菜单不可见、未授予按钮不渲染、字段权限读时过滤 / 写时校验）；业务 / 动作码租户侧只读；`sys.form.updated` 事件与元数据缓存失效即时生效；平台 MVP 页面挂接完整。

**参考文档**：《[概要设计 · 菜单管理](../../../设计/概要设计/07_概要设计_菜单管理.md)》§2/§4/§5/§6/§8；《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§7；《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「动态菜单与权限显隐」节

## 3. 需求 07-6：三权分立（内置三类管理员互斥、平台超管边界） <a id="r07-6"></a>

优先级：2（高）

**背景与动机**：合规与安全要求管理员职责分离，防止单一账号集权越权（既管系统配置、又管权限授予、又管审计）；同时须明确平台超管与租户管理员的边界，避免平台运营账号进入租户业务数据。三权分立是阶段七完成标准的显式验收项，也是角色授予的安全护栏。

**内容**（架构 15 §8；概要 06 §2.2/§6.2；概要 25 §6.3）：

1. **租户侧三类内置管理员角色**：系统管理员（用户 / 岗位 / 部门等系统配置）、安全管理员（角色 / 业务 / 动作 / 数据范围 / 密码策略 / IdP 配置）、审计管理员（只读全部日志与审计数据），权限**互斥**。
2. **同一用户不得兼任**三类内置管理员；授予操作会造成职责互斥或兼任时拒绝（错误码 30010 / 30048）。
3. **内置角色保护**：系统 / 安全 / 审计管理员角色不可删除 / 停用 / 变更类型（判定按 `sys_role.role_type` 列，2026-10-08 改定）；`role` 业务仅安全管理员内置角色持有，系统管理员 / 审计管理员不可越权授予。
4. **防自锁**：安全管理员管理角色时不得授予 / 修改超出自身权限的授权，不得造成自身职责冲突。
5. **平台超管边界**：平台超管（`sys_admin`）跨租户运营仅到租户级（开通 / 停用 / 域名 / 配额 / 模块开关），**不进入租户业务数据**，不经租户 RBAC 计算。
6. **开通种子**：租户开通首建系统管理员账号（首次登录强制改密），由其创建另两类管理员；三类内置管理员角色互斥预授。
7. **护栏与审计**：互斥校验在授权写入前置执行；内置角色预授与越权尝试落字段级审计。

**完成标准**：三类内置管理员互斥校验生效、同一用户不得兼任；内置角色保护（禁删禁改归属）生效；`role` 业务仅安全管理员可授予、越权授予被拒；平台超管边界验证通过（不进入租户业务数据）；租户开通种子内置角色互斥预授、初始系统管理员账号创建正确；互斥与越权尝试留痕可查。

**参考文档**：《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§8；《[概要设计 · 角色管理](../../../设计/概要设计/06_概要设计_角色管理.md)》§2.2/§6.2；《[概要设计 · 租户管理](../../../设计/概要设计/25_概要设计_租户管理.md)》§6.3；《[概要设计 · 审计合规](../../../设计/概要设计/28_概要设计_审计合规.md)》；需求 [07-3 角色管理](02_需求_用户与角色.md#r07-3) / [07-7 租户管理](04_需求_租户与平台超管.md#r07-7)

> **实施交付注（2026-10-19，`03_02`，Kiwi 2314）**：三权分立已按本需求交付（任务 [`03_02`](../任务/03_菜单与权限/03_菜单与权限_02_三权分立与平台超管边界/03_菜单与权限_02_三权分立与平台超管边界.md)）——① **三类内置管理员互斥**：新增校验核心件 `SeparationGuard`（`services/separation.py`），三处 `sys_user_role` 写入口（角色分配 / 角色编排 / 用户编排）在**事务内、写入前**统一校验，同一用户将兼任两类内置管理员即拒 `30010`（新增异常类 `UserSeparationConflictError`），拒绝不产生写入且不递增权限版本；② **内置角色保护**：判定按 `sys_role.role_type`（`02_03` 交付），本任务补机器护栏断言（AST 断言 `create_role` / `update_role` 无 `role_type` 写入口）；③ **`role` 业务仅安全管理员**：数据侧不变量（`role` 业务权限码只允许授予 `role_type=security` 的角色，违反 `30048`）+ 操作人侧护栏（持 system / audit 且不持 security 者调角色域 9 个写端点即 `30048`，经 `_ROLE_DOMAIN_GUARD` 依赖）；④ **防自锁**：不得修改自身所属角色的授权集合（权限 / 字段 / 数据权限三条路径）；⑤ **平台超管边界**：护栏断言平台层快照仅由无用户上下文通道产生（`TIER_PLATFORM_ADMIN` 唯一产生点、不经租户 RBAC 计算）且 `sys_admin` 不在任何租户库表集内；⑥ **开通种子一致**：三类内置角色与授权清单固化为 `ops/seed_rbac.py::BUILTIN_ADMIN_ROLES` + `models/role.py::SEPARATION_ROLE_TYPES` 单一来源，种子绑定前复用互斥口径（冲突记 `assign_conflicts` 并跳过），编排归 [`04_01`](04_需求_租户与平台超管.md#r07-7)；⑦ **留痕**：互斥 / 越权 / 归属违规三类拒绝经 `AuditCapturer.capture()` 产生事件（当前 `NullAuditCapturer` 不落库，真实 `sys_data_audit_log` 落库归审计合规模块）。用例 Kiwi **2314**；定向覆盖率门禁 10 模块 100%（520 passed）。详见[实施记录](../任务/03_菜单与权限/03_菜单与权限_02_三权分立与平台超管边界/实施/01_实施记录_02_三权分立与平台超管边界.md)与[测试记录](../任务/03_菜单与权限/03_菜单与权限_02_三权分立与平台超管边界/测试/01_测试记录_02_三权分立与平台超管边界.md)。

## 4. 需求 07-17：权限元数据维护页（菜单 / 表单 / 按钮 / 字段 / 业务码 / 动作码 / 权限码 / 图标） <a id="r07-17"></a>

优先级：2（高）

**背景与动机**：需求 `07-5` 只交付后端元数据接口与前端**消费**（动态路由 / 侧边栏 / 按钮与字段显隐），平台侧**维护页面**一直未立项——种子数据里有 `/sys/menus`、`/sys/businesses`、`/sys/actions` 等菜单，前端却只能兜底到占位页（「页面建设中」），平台超管无法在界面上增改菜单、表单、按钮、字段与三本字典码，只能改 `seed_menu.py` 或直接调接口。`03_01` 交付时已把该缺口登记为遗留（计划表 `03_01` 行「归后续维护页任务」），但后续一直未补立任务；维护页缺失使「新增菜单 / 表单免发版生效」这一能力实际无法被业务方使用，也让「业务 / 动作 / 权限码平台统一维护」停留在口头口径。

**内容**（概要 07 §2 / §5 / §6 / §8；原型 `设计/原型设计/10_菜单管理/`）：

1. **菜单管理页**：列表 Tab 用树形表格承载菜单层级（列＝菜单名称 / 类型 / 路由路径 / 视图组件 / 排序 / 状态），**树拖拽调序**（回写 `parent_id` 与 `sort`）、批量停用 / 启用、删除（子节点、表单挂接与角色授权引用检查，命中拒绝 `40206`）；记录 Tab 三页签「详细信息 / 挂接配置 / 系统信息」，挂接配置含表单挂接（多对多）、按钮维护、字段维护（后两者页内内联明细，随宿主「保存」一次提交），**不提供字段权限入口**（字段权限统一在角色管理 `role:grant` 授予）。
2. **表单管理页**：独立列表页（含未挂接任何菜单入口的表单），列＝业务码 / 视图组件 / 关联菜单数 / 状态；记录页「详细信息（业务码、视图组件选择或手输、关联菜单多选、状态）/ 系统信息」；删除前检查按钮、字段、角色表单授权与字段权限引用。
3. **业务码 / 动作码管理页**：完整 CRUD（多语言名称）、停用 / 启用、有条件删除（无权限码、无表单 / 按钮引用，否则 `40206`）；停用业务码 / 动作码时其下权限码**连带停用**，其中任一被引用则整批拒绝（`40206`）。
4. **权限码管理页**：`业务码 × 动作码` 组合的查看与筛选、**手工新增组合**、**批量补生成缺失组合**、停用 / 启用、有条件删除；组合重复 `40210`。
5. **自定义图标管理页**：`sys_icon` 列表 Tab（图标预览 / icon key 复制 / 名称 / 分组 / 引用计数 / 状态）+ 记录 Tab（名称多语言、分组、标签、SVG 上传与预览、状态）；新增 / 编辑 / 启停 / 删除需 `icon:manage`，删除前置引用检查（`40206`）。**后端现状为占位实现（`NullIconRegistry`）**，本需求一并补齐真实落库 CRUD、SVG 类型 / 大小校验与基础拒绝（脚本 / 事件属性 / 外链），内容深度清洗仍归文件管理阶段。
6. **权限码与错误码**：新增 `business:manage`（业务码维护）、`action:manage`（动作码维护）两个权限码并授系统管理员；错误码段顺延 `40209`（业务码 / 动作码重复）、`40210`（权限码组合重复）。
7. **原型与文档**：新增「表单管理 / 表单记录页」原型两页，菜单维护页补树拖拽，菜单记录页去掉字段权限入口；回写概要 07「职责边界 / 删除与停用口径」、《架构设计 · 权限计算引擎》权限码清单与错误码登记。

**完成标准**：平台超管登录后 `/sys/menus`、`/sys/forms`、`/sys/businesses`、`/sys/actions`、`/sys/permissions`、`/sys/icons` 六个入口均渲染真实页面、无「页面建设中」占位；菜单拖拽排序持久化并在下次登录按新顺序下发；菜单 / 表单 / 按钮 / 字段 / 业务码 / 动作码 / 权限码 / 图标的增改与停用启用即时作用于动态菜单接口；停用与删除保护按上述口径生效（被引用一律 `40206`）；非平台超管侧三本字典只读（`40204`）；后端定向用例与前端用例全绿、变更源文件覆盖率 100%、`preflight` 全绿；原型对照结论登记到测试记录。
