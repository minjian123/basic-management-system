## 1. 域说明 <a id="intro"></a>

本域承载阶段七的**菜单与权限**主线：把权限元数据（菜单 / 表单 / 按钮 / 字段与业务 / 动作码）落为平台统一维护的实体与挂接关系，并以**动态菜单接口**下发菜单树与表单元数据，作为前端动态路由、侧边栏、按钮与字段显隐的唯一依据；同时落地**三权分立**（内置三类管理员互斥与平台超管边界），保证授权与运营的职责分离。

- **对应 WBS 域**：《总体项目规划》阶段七「菜单/表单/按钮/字段挂接、动态菜单接口、三权分立」；概要 07-菜单管理；架构 15-权限计算引擎 §2/§7/§8。
- **落点说明**：菜单 / 表单 / 按钮 / 字段与业务 / 动作码存**平台库**，平台超管统一维护，租户侧只读可分配不可增删；字段权限授予写入口在角色管理（`role:grant`），本域提供配置入口与元数据。
- **端范围**：PC（后端 meta 能力 + 前端动态路由 / 菜单 / 按钮 / 字段消费）。
- **依据**：《[概要设计 · 菜单管理](../../../设计/概要设计/07_概要设计_菜单管理.md)》、《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§7/§8、《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》、《[概要设计 · 审计合规](../../../设计/概要设计/28_概要设计_审计合规.md)》（三权分立）。

## 2. 需求 07-5：菜单/表单/按钮/字段挂接与动态菜单接口 <a id="r07-5"></a>

优先级：2（高）

**背景与动机**：权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）必须有平台统一维护的元数据载体；前端动态路由、侧边栏、按钮与字段显隐的唯一依据是动态菜单接口，不得硬编码路由或权限清单。缺少该能力，新增菜单 / 表单 / 按钮 / 字段都要改前端发版，角色授权也无从选择授权对象。

**内容**（概要 07；架构 15 §2/§7）：

1. **菜单维护**：菜单树（`parent_id/name/path/component/icon/sort/hidden/status`），1:1 挂接表单。
2. **表单维护**：表单实体（挂菜单 `menu_id`、挂业务 `business_id`、`component`），形成「菜单→表单→业务」链。
3. **按钮维护**：按钮实体（挂表单 `form_id`、挂动作 `action_id`、`type`（toolbar/interface）、`sort`），形成「按钮→动作」链，默认无任何按钮权限。
4. **字段维护**：字段实体（挂表单 `form_id`、`field_key/name/type/sort/status`），作为字段权限控制依据。
5. **业务 / 动作码管理**：`sys_business` / `sys_action` 平台统一维护，租户侧可见、可分配、不可增删；业务 / 动作码一经发布稳定，停用代替删除。
6. **挂接链完整性**：菜单 1:1 挂表单、表单 1:1 挂业务、按钮 1:1 挂动作、字段挂表单，任一缺失导致该链路不可见 / 不可用，角色授予时校验并提示（错误码 **40202**；菜单域错误码段位经 2026-10-04 确认由 `400xx` 修正为 `402xx`，详见概要《菜单管理》「错误码与异常处理」节）。
7. **多语言**：菜单 / 业务 / 动作 / 字段名称存各自 `_i18n` 附表，按当前 locale 关联，缺省回退主表默认文案。
8. **动态菜单接口**：`GET /menus/my` 按用户已授予的菜单 / 表单权限过滤菜单树并下发表单元数据（按钮按动作权限、字段按字段权限标记可见可编辑状态），登录即可访问；菜单树与表单元数据 Redis 短 TTL 缓存（含随机偏移、按 locale 维度），变更即时失效。
9. **前端消费**：按动态菜单注册路由与侧边栏（不硬编码路由表）、按钮按动作权限显隐、字段按字段权限显隐与只读；菜单 / 表单 / 字段 / 按钮变更发布 `sys.form.updated` 事件（AI 帮助更新触发）。
10. **平台 MVP 页面挂接齐备**：用户管理 / 角色管理 / 账号锁定 / 租户管理等平台页面菜单→表单→业务、按钮→动作链路齐全，配 i18n 文案。

**完成标准**：新增菜单 / 表单 / 按钮 / 字段后前端动态注册路由与侧边栏免发版生效、菜单名多语言显示正确（含缺省回退）；挂接链断裂在角色授予时被拦截并提示；动态菜单接口按权限过滤正确（未授予菜单不可见、未授予按钮不渲染、字段权限读时过滤 / 写时校验）；业务 / 动作码租户侧只读；`sys.form.updated` 事件与元数据缓存失效即时生效；平台 MVP 页面挂接完整。

**参考文档**：《[概要设计 · 菜单管理](../../../设计/概要设计/07_概要设计_菜单管理.md)》§2/§4/§5/§6/§8；《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》§2/§7；《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「动态菜单与权限显隐」节

## 3. 需求 07-6：三权分立（内置三类管理员互斥、平台超管边界） <a id="r07-6"></a>

优先级：2（高）

**背景与动机**：合规与安全要求管理员职责分离，防止单一账号集权越权（既管系统配置、又管权限授予、又管审计）；同时须明确平台超管与租户管理员的边界，避免平台运营账号进入租户业务数据。三权分立是阶段七完成标准的显式验收项，也是角色授予的安全护栏。

**内容**（架构 15 §8；概要 06 §2.2/§6.2；概要 25 §6.3）：

1. **租户侧三类内置管理员角色**：系统管理员（用户 / 岗位 / 部门等系统配置）、安全管理员（角色 / 业务 / 动作 / 数据范围 / 密码策略 / IdP 配置）、审计管理员（只读全部日志与审计数据），权限**互斥**。
2. **同一用户不得兼任**三类内置管理员；授予操作会造成职责互斥或兼任时拒绝（错误码 30010 / 30048）。
3. **内置角色保护**：系统 / 安全 / 审计管理员角色不可删除 / 停用 / 变更归属；`role` 业务仅安全管理员内置角色持有，系统管理员 / 审计管理员不可越权授予。
4. **防自锁**：安全管理员管理角色时不得授予 / 修改超出自身权限的授权，不得造成自身职责冲突。
5. **平台超管边界**：平台超管（`sys_admin`）跨租户运营仅到租户级（开通 / 停用 / 域名 / 配额 / 模块开关），**不进入租户业务数据**，不经租户 RBAC 计算。
6. **开通种子**：租户开通首建系统管理员账号（首次登录强制改密），由其创建另两类管理员；三类内置管理员角色互斥预授。
7. **护栏与审计**：互斥校验在授权写入前置执行；内置角色预授与越权尝试落字段级审计。

**完成标准**：三类内置管理员互斥校验生效、同一用户不得兼任；内置角色保护（禁删禁改归属）生效；`role` 业务仅安全管理员可授予、越权授予被拒；平台超管边界验证通过（不进入租户业务数据）；租户开通种子内置角色互斥预授、初始系统管理员账号创建正确；互斥与越权尝试留痕可查。
