## 1. 域说明 <a id="intro"></a>

本域把**字典（基础数据 / 参考数据）记录页**的骨架统一到《[布局设计 · 字典页](../../../设计/布局设计/17_布局设计_字典页.html)》，并补齐「一个界面是不是字典页」的判定口径，使后续新增基础数据页可直接套用同一骨架。

- **「字典」判定口径（2026-10-13 拍板）**：以《[数据库开发规范](../../../规范/数据库开发规范.md)》§3.1「系统字段（基础 / 表单 / 字典统一口径）」为准——**表单**额外系统字段为 `code` / `bill_date` / `status`，**字典**额外系统字段为 `code` / `name` / `status`（另有 `sort` / `parent_id`）；即**表带 `name` 者为字典表**。代码层落在构建期清单的 `kind`（`FormKind` / `DataSourceKind`，取值 `dict` / `form`，见 `bms/backend/libs/bms_core/src/bms_core/registry/forms.py` 与 `bms/backend/libs/bms_core/src/bms_core/datasource/registry.py`），前端经 `/form-keys`、`/data-sources` 归一为 `kind`。
- **17 的定位＝通用记录页骨架模板**：17 描述的不是某一个页面，而是**所有字典记录页共用的一套骨架**——工具栏 + 信息栏「详细信息 / 系统信息」两个子 Tab（**最少两 Tab**）+ 详细信息首行三字段 `Code` / `Name` / `State`（三列等宽、顺序固定）+「系统信息」区；**其余业务 Tab 与字段不受限**（可增）；登记项专属字段（来源 / 数据出口 / 字段白名单 / 级联 / 可用策略与明细区条目预览）仅数据源登记项页具备。
- **现状与缺口**：`kind` 虽已定义，但两份构建期清单**未显式声明 `kind`**（全部取默认 `dict`），前端也**无任何按 `kind` 套模板之处**；现有字典记录页（角色 / 用户）各自实现骨架，通用「系统信息」件（`ui-ep` 的 `SysInfoPanel`）形态与 17 不一致（`el-descriptions` 横排、第 3 项为「表单」而非第 7 项「`form_key`（字典对应的表单标识）」）。
- **对齐基准**：界面口径以《[布局设计 · 字典页](../../../设计/布局设计/17_布局设计_字典页.html)》为准（布局设计为界面权威）；对照基准沿用既有页面原型《[原型设计 · 用户管理](../../../设计/原型设计/08_用户管理/)》《[原型设计 · 角色管理](../../../设计/原型设计/09_角色管理/)》，**不新建原型**。
- **依据**：《[布局设计 · 字典页](../../../设计/布局设计/17_布局设计_字典页.html)》《[布局设计 · 表单页](../../../设计/布局设计/08_布局设计_表单页.html)》《[概要设计 · 字典管理](../../../设计/概要设计/09_概要设计_字典管理.md)》§8、《[数据库开发规范](../../../规范/数据库开发规范.md)》§3.1、《[原型审查规范](../../../规范/原型审查规范.md)》。

## 2. 需求 07-15：字典记录页骨架对齐 <a id="r07-15"></a>

优先级：2（高）｜**补充需求**（2026-10-13 立项）

**背景与动机**：字典（基础数据 / 参考数据，含角色 / 用户 / 租户 / 系统参数等）是平台内建的通用形态，其记录页在 17 里已定案为一套统一骨架（最少两 Tab + 首行三字段 + 系统信息区）；但实现侧各页各写一套、「系统信息」件形态与 17 不一致，且「一个界面是不是字典」在代码与前端都无可靠判定（清单未显式声明 `kind`、前端无处消费）——后续每新增一个基础数据页都要重复对齐一次。本需求把判定口径与骨架一次收敛，使「字典记录页」可复用、可按 `kind` 自动套用。

**内容**（《[布局设计 · 字典页](../../../设计/布局设计/17_布局设计_字典页.html)》《[数据库开发规范](../../../规范/数据库开发规范.md)》§3.1）：

1. **判定口径落地**：构建期清单（`FORM_CATALOG` / `DATA_SOURCE_CATALOG`）**逐条显式声明 `kind`**（不再依赖默认值，取值保持既有不变）；前端按 `kind` 判定并套用骨架模板。
2. **骨架对齐**：字典记录页统一为「工具栏 + 信息栏『详细信息 / 系统信息』两 Tab + 详细信息首行三字段 `Code` / `Name` / `State`（三列等宽、顺序固定）+『系统信息』区」；**其余业务 Tab 与字段不受限**；登记项专属字段仅登记项页具备。
3. **系统信息区**：按 17 §2.5 呈现（`el-form` `label-position="top"`、三列只读栅格、7 项，第 7 项为 `form_key`（字典对应的表单标识），与表单页一致；时间按租户时区格式化、无时区后缀）。
4. **现场对齐**：现有字典记录页（角色 `RoleRecordTab` / 用户 `UserRecordTab`）与通用系统信息件按上述口径对齐；非字典表记录页（如 `sys_account_lock` 的账号锁定记录页）**不在范围**。
5. **文档回写**：17（术语 `dict_key` → `data_source_key`、补适用范围与与表单页关系、§2.5 第 7 项口径）、《[概要设计 · 字典管理](../../../设计/概要设计/09_概要设计_字典管理.md)》§8、《[数据库开发规范](../../../规范/数据库开发规范.md)》§3.1.1（归属标识措辞更正）。
6. **测试与登记**：先登记 Kiwi 用例再编码；界面类另按《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 对照原型并登记「原型对照结论」（真机截图 + 逐页结论）。

**完成标准**：两份清单显式声明 `kind` 且校验脚本可断言；前端按 `kind` 套用骨架模板；现有字典记录页与系统信息件在骨架 / 系统信息区上与 17 一致（真机逐页对照，偏离项就地修复或登记归口）；三份文档回写到位且与实现口径一致；覆盖率达标、`check_preflight.py --fast` 全绿。
