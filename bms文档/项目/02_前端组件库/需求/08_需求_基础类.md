## 1. 域说明 <a id="intro"></a>

本域对应阶段二「基础类」（WBS 08，组件设计 09 基础类 01-03），是不带界面或横切的工具、指令与 store：请求封装 `http` / `request` / `useRequest` / `useListPage`、权限指令 `v-perm` / `hasPerm` / `canAccess`、格式化工具 `formatDateTime` / `formatAmount` / `validators` / `stableStringify`。

> 注：阶段一 `01-4-2 前端公共组合式与工具基座` 已交付 L1a 数据/契约基座（`BaseEntity`/`BasePageQuery`/`BaseApi`/`createCrudStore`/`stableStringify` 等），本域只补齐面向页面的**请求组合式、权限指令与格式化工具**，不重复建设已交付部分。

**依据**：《组件设计》09 基础类节点、《[API接口规范](../../../规范/API接口规范.md)》、《架构设计 · 前端组件体系》第 5/6 节、《[架构设计 · 接口与集成](../../../设计/架构设计/06_架构设计_接口与集成.md)》。
**目标**：页面可通过 `useRequest`/`useListPage` 统一取数、`v-perm` 统一按钮权限、格式化工具统一展示口径。

## 2. 需求 08-1：请求封装 / 权限指令 / 格式化工具 <a id="r08-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：页面取数、按钮权限与展示格式化是全站横切能力；若各页各写 axios 调用、权限判断与日期/金额格式化，会出现 401 处理不一致、权限显隐口径不一、金额/时间展示各异的问题。必须在组件库地基阶段统一。

**内容**（《组件设计》09 基础类 01-03、《API接口规范》、《架构设计 · 前端组件体系》「取数与缓存协作」节）：

1. 请求封装：`src/api/http.ts` Axios 实例（token 注入、401 静默刷新、统一响应 `{code, message, data}` 解析与错误提示）+ `useRequest`（loading/错误/重试/取消）+ `useListPage`（分页/筛选/排序/导出的列表页组合式）。
2. 权限指令：`v-perm="'业务:动作'"` / `hasPerm` / `canAccess`——按钮/动作权限渲染契约；字段权限不在本域（已迁至基础组件类 L3-04）。
3. 格式化工具：`formatDateTime`（用户时区）、`formatAmount`（金额/千分位）、`validators`（通用校验）、`stableStringify`（稳定序列化，供缓存 key / 条件去重）。
4. 与契约衔接：`ApiResponse<T>` / `PageResponse<T>` 类型与 openapi-typescript 生成的类型保持一致；错误码文案按 i18n key 映射（见《组件设计》09 类）。

**完成标准**：`useRequest`/`useListPage` 可用并被列表页复用；`v-perm` 与 `hasPerm` 显隐生效；格式化工具在时区/金额口径上与后端一致；Vitest 覆盖请求拦截与格式化分支；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《组件设计》09 基础类 01-03 节点（含可交互原型）、《API接口规范》、《架构设计 · 前端组件体系》第 5/6 节
