## 2. 需求 03-1：Kiwi TCMS 部署 <a id="r03-1"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-19

**背景与动机**：测试用例必须有唯一库（手工与自动化统一登记、用例 ID 与代码关联），否则用例散在文档 / 代码里无法统计与追溯；执行结果导入是测试报告的基础。

**内容**：

1. 部署 kiwitcms/kiwi 16.x，宿主机端口 8060，复用 bms-mysql（`deploy/compose/kiwi.yml`）
2. 定位：唯一测试用例库——手工与自动化用例统一在此登记（用例 ID 与代码关联），执行结果导入归档

**完成标准**：Kiwi TCMS Web 可访问（8060），用例登记与执行记录可用。

**参考文档**：《KiwiTCMS部署使用说明》、《测试规范》

## 3. 需求 03-4：平台分工 <a id="r03-4"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-21

**背景与动机**：缺陷与用例分属 GitLab Issue 与 Kiwi 两个平台，不明确分工会出现同一问题两处登记 / 互相找不到；口径固化后才可执行。

**内容**（《项目管理规范》）：

1. GitLab Issue：代码缺陷（P0–P3）与 MR 关联
2. Kiwi TCMS：测试用例登记与执行，平台上的缺陷链接指向 GitLab Issue

**完成标准**：分工口径已固化在《项目管理规范》，各入口按此执行，不混用。

**参考文档**：《项目管理规范》、《测试规范》

## 4. 需求 03-5：平台备份联动 <a id="r03-5"></a>

优先级：2（高）　|　状态：已完成　|　完成日期：2026-08-22T07:40:00Z

**背景与动机**：Kiwi 业务数据与附件若不在每日备份内，测试资产（用例 / 结果 / 附件）存在丢失风险；与 MySQL 备份 / 附件导出联动是最低成本保障。

**内容**（《开发部署规划》「备份与恢复」节）：

1. Kiwi TCMS 业务数据随 MySQL 每日 dump（复用 bms-mysql）
2. Kiwi uploads 附件卷随每日备份导出（backup_daily.sh 的 backup_kiwi_uploads 步骤）

**完成标准**：测试平台数据纳入每日备份，可按需恢复。

**参考文档**：《开发部署规划》「备份与恢复」节、《KiwiTCMS部署使用说明》
