## 2. 任务内容 <a id="content"></a>

把 01 / 02 的基座能力落到具体产品。共同口径：**继承项只引用架构节点、不复制基座能力；扩展项保留并写清边界**（架构 41 §6.2 第 3 条）。msg 本期改代码，mdm / biz 本期只对齐文档。

### 2.1 消息平台接入改造（需求 03-1，架构 41 §6.2 + msg 07 全文） <a id="w03-1"></a>

1. **重写 msg 05 需求**：只保留扩展项（重新编号 `05-1`、`05-2`…），继承项直接引用 bms 架构节点，不再重复定义租户解析、认证、RBAC、审计链。
2. **保留现有任务与记录**：原「租户用量板块与表单登记」任务、Kiwi 用例、实施记录保留并归入新的扩展项，不废弃、不重挂历史。
3. **三级映射**：msg `namespace` 对齐 `module_key`、`topic` 映射为 `resource_key`；命名空间校验迁到 02-1，主题归属校验作为产品规则（对照 msg 07 §2.2、§7）。
4. **四项扩展点一次改完**：作用域校验、错误码映射、配额只读回显、审计字段扩展；改造后跨租户、停用、未登记命名空间、错误码、配额回显、`log_id` 行为与改造前一致。
5. **数据面同源**：h2 帧入口复用基座同一解析函数，不得信任客户端自报头（msg 07 §4.1）。
6. **扩展项对账**：逐条核对 msg 的配额、topic ACL、审计留痕、生命周期四项是否都有「基座契约 + msg 任务」两段；缺任一段即视为未完成。

### 2.2 mdm 文档对齐（需求 03-2） <a id="w03-2"></a>

1. 盘点 mdm 现有租户与安全相关需求 / 设计，按架构 41 §3 三层模型识别继承项与扩展项。
2. 改写需求篇：继承项直接引用架构节点、删除对基座能力的重复定义；扩展项（主数据资源作用域、字段级权限、组织数据范围）保留并补边界说明。
3. 设计篇、任务篇按实际差异最小同步；本期不改 mdm 代码。
4. 基座能力缺失或不足的，回 bms 补（提需求或缺陷），不在 mdm 仓复制实现。

### 2.3 biz 文档对齐（需求 03-3） <a id="w03-3"></a>

1. 盘点 biz 现有租户与安全相关需求 / 设计，识别继承项与扩展项。
2. 改写需求篇：继承项直接引用架构节点；扩展项（业务资源作用域、业务权限码、业务数据范围）保留并补边界说明。
3. 设计篇、任务篇按实际差异最小同步；本期不改 biz 代码。
4. 基座能力缺失或不足的，回 bms 补，不在 biz 仓复制实现。
