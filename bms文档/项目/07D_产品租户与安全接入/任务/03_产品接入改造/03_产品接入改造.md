## 2. 任务内容 <a id="content"></a>

把 01 / 02 的三级作用域与标准扩展点落到具体产品：msg 做需求重写与四项扩展点代码改造，mdm / biz 本期只对齐现有需求篇。三者的共同口径是——**继承项只引用架构节点、不复制基座能力；扩展项保留并写清边界**。

| 工作项 | 对应需求 | 交付重心 |
| --- | --- | --- |
| 03-1 消息平台接入改造 | [03-1](../../需求/03_需求_产品接入改造.md#r03-1) | msg 05 重写、四项扩展点接入、扩展项对账、行为回归 |
| 03-2 mdm 文档对齐 | [03-2](../../需求/03_需求_产品接入改造.md#r03-2) | 继承 / 扩展两分类改写、边界说明 |
| 03-3 biz 文档对齐 | [03-3](../../需求/03_需求_产品接入改造.md#r03-3) | 继承 / 扩展两分类改写、边界说明 |

### 2.1 消息平台接入改造（03-1） <a id="w03-1"></a>

1. **重写 msg 05 需求**：只保留扩展项（重新编号 `05-1`、`05-2`…），继承项直接引用 bms 架构节点、不另立清单；不再重复定义租户解析、认证、RBAC、审计链等基座能力。
2. **保留现有任务**：原「租户用量板块与表单登记」任务、Kiwi 用例与实施记录保留，归入新的扩展项；不废弃、不重挂历史。
3. **映射**：消息平台 `namespace` 映射为 `module_key`、`topic` 映射为 `resource_key`；命名空间校验迁到 02-1，主题归属校验作为产品规则。
4. **四项扩展点一次改完**：作用域校验、错误码映射、配额只读回显、审计字段扩展；改造后跨租户、停用、未登记命名空间、错误码、配额回显、`log_id` 行为与改造前一致。
5. **同步文档**：msg 设计 07、任务 05、规划 01、需求总览 00 的定位与引用同步更新；msg 仓与 bms 仓的跨仓依赖与声明登记保持一致。
6. **扩展项对账**：逐条核对 msg `05-1`（配额，接 02-3）、`04-4`（topic ACL，接 02-5）、`04-5`（审计留痕，接 02-4）、`04-6`（生命周期，接 01-4，开通初始化已由 msg `05-1` 第 7 条承接）是否都有「基座契约 + msg 任务」两段；缺任一段即视为未完成，不得只改文档不落任务。

**交付物**：msg 05 重写稿、五项接入说明（作用域校验 / 错误码映射 / 配额回显 / 审计字段 / ACL 约束）、扩展项对账表（基座契约 ↔ msg 任务）、行为回归基线。
**边界**：不改产品业务功能；不把产品实现回写 bms。

### 2.2 mdm 文档对齐（03-2） <a id="w03-2"></a>

1. 盘点 mdm 现有租户与安全相关需求 / 设计，识别继承项与扩展项。
2. 改写需求篇：继承项直接引用架构节点、删除对基座能力的重复定义；扩展项（主数据资源作用域、字段级权限、组织数据范围等）保留并补边界说明。
3. 设计篇、任务篇按实际差异最小同步；本期不改 mdm 代码。
4. 基座能力缺失或不足的，回 bms 补（提需求或缺陷），不在 mdm 仓复制实现。

**交付物**：mdm 需求篇「继承项 / 扩展项」改写稿、扩展项边界说明、设计 / 任务最小同步清单。
**边界**：本期不改代码；不扩产品业务范围；不改与租户安全无关的章节。

### 2.3 biz 文档对齐（03-3） <a id="w03-3"></a>

1. 盘点 biz 现有租户与安全相关需求 / 设计，识别继承项与扩展项。
2. 改写需求篇：继承项直接引用架构节点、删除对基座能力的重复定义；扩展项（业务资源作用域、业务权限码、业务数据范围等）保留并补边界说明。
3. 设计篇、任务篇按实际差异最小同步；本期不改 biz 代码。
4. 基座能力缺失或不足的，回 bms 补（提需求或缺陷），不在 biz 仓复制实现。

**交付物**：biz 需求篇「继承项 / 扩展项」改写稿、扩展项边界说明、设计 / 任务最小同步清单。
**边界**：本期不改代码；不扩产品业务范围；不改与租户安全无关的业务域章节。
