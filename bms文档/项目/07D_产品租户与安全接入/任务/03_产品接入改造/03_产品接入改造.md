## 2. 任务内容 <a id="content"></a>

把 01 / 02 的基座能力落到消息平台。共同口径：**继承项只引用架构节点、不复制基座能力；扩展项保留并写清边界**（架构 41「继承清单与产品接入流程」节）。msg 本期改代码；mdm / biz 两仓本期零改动（原 03-2 / 03-3 已摘除，两仓无「租户与安全」需求篇，专项不生造需求）。

### 2.1 消息平台接入改造（需求 03-1，架构 41「继承清单与产品接入流程」+ msg 07 全文） <a id="w03-1"></a>

1. **复核 msg 05 需求**：05 已重写为「继承基座 + 扩展项 `05-1` ~ `05-7`」，只保留扩展项、重新编号，继承项直接引用 bms 架构节点；本任务只做引用可达性复核与改造结论增量修订，不重做、不重挂历史。
2. **保留现有任务与记录**：原「租户用量板块与表单登记」任务、Kiwi 用例、实施记录保留并归入新的扩展项 `05-7`，不废弃、不重挂历史。
3. **三级映射**：msg `namespace` 对齐 `module_key`、`topic` 映射为 `resource_key`；命名空间校验迁到 02-1 的 `scope_rule` 规则链，主题归属校验作为产品规则（对照 msg 07「租户标识与三级命名空间」「授权」节）。
4. **四项扩展点一次改完**：作用域校验、错误码映射、配额只读回显、审计字段扩展；改造后跨租户、停用、未登记命名空间、错误码、配额回显、`log_id` 行为与改造前一致（强审计写入失败属已确认的新增行为，单列基线）。
5. **数据面同源**：h2 帧入口复用基座同一解析函数，不得信任客户端自报头；管理面 / 数据面 / 异步三路径同结论（msg 07「租户解析与状态校验」节）。
6. **扩展项对账**：逐条核对 msg 的配额、topic ACL、审计留痕、生命周期四项是否都有「基座契约 + msg 任务」两段；缺任一段即视为未完成。对账表以本任务[详细设计](设计/01_详细设计_03_产品接入改造.md)为唯一事实源，msg 任务 05 文档引用。
7. **文档同步**：msg 设计 07、任务 05、规划 01、需求总览 00 的定位与引用同步更新；msg 仓与 bms 仓的跨仓依赖与声明登记保持一致（以需求 03-1 为准）。
