### 3.2 关键实现口径

| 项 | 实现 |
| --- | --- |
| 解析顺序 | 租户（`BaseTenantGuard.require`）→ 模块形态 + 登记态 → 类型形态 + 前缀归属 + 注册与有效态 → 资源取值 + 归属 |
| 模块判定 | 只判 `sys_module.status`（`service_catalog_view()`，进程内），租户模块开关不进本链 |
| 类型已停用 | 与未注册同码（82011），内部日志分 `scope_resource_type_inactive` / `scope_resource_type_unknown` 两个事件 |
| 跨模块越权 | 类型标识前缀 ≠ `module_key` 即 82011（`scope_resource_type_cross_module` 事件） |
| 跨租户 | `owner_tenant_id` 传入且 ≠ 当前租户即 82012（`scope_resource_cross_tenant` 事件）；不传表示由产品授权模型保证 |
| 三路径 | `require` / `per_round` / `batch` 全部委托 `resolve`；数据面帧入口由 `03` 任务按同一入口接入 |
| 管理面 | `require_scope(module_key, resource_type, resource_from="path|query", owner=...)`；不自动读请求体（会消费请求流） |
| 失败语义 | 租户 80001 / 80002 / 10007 原样冒泡；模块与资源用 82009 ~ 82012 |

### 4.2 关键实现口径

| 项 | 实现 |
| --- | --- |
| 上下文变量 | `core/context.py::current_scope`，与租户 / 用户 / 链路上下文同处；`ResolvedScope` 只在 `TYPE_CHECKING` 下引入，避免 `resolver → tenant.guard → context` 的循环 |

| 管理面注入 | `require_scope` 依赖解析成功后 `set_scope_context`；随请求 task 结束销毁，不显式复位 |
| 异步注入 | `per_round` 每轮写入（覆盖上一轮）；`batch` 进入写入、`finally` 复位 |
| 数据面注入 | `frame()`（`@asynccontextmanager`）进入写入、`finally` 复位；`require` 保持纯判定，避免帧间残留上一帧作用域 |
| 扩展位 | `Mapping[str, object]`，`__post_init__` 冻结为 `MappingProxyType`；`compare=False` 不参与相等与哈希；`with_extensions()` 返回新实例 |
| 文案 | `82011` 对「未注册」与「已停用」同句同码，`82009` 同覆盖「未登记」与「已退役」；不泄露存在性 |
| 审计字段 | 载荷 `module_key` / `resource_key` 只在有上下文时写入；与既有 `module`（权限码业务段）语义分开，不互相赋值 |

| --- | --- |
| 事件名 | 沿用 `tenant.created` / `tenant.suspended` / `tenant.activated`，新增 `tenant.deleted`；需求字面 disabled / enabled 映射到 suspended / activated，不另立同义事件 |

| 保留期 | `on_deleted` 内按 `ScopeResourceTypeRecord.retention_days` / `removal_policy` 处置；审计记录不随资源删除 |
| 空实现 | 四动作 no-op 且每次记 `tenant_resource_action_skipped` WARNING（漏配可发现）；账本进程内 |
