## 2. 任务内容 <a id="content"></a>

1. 固定解析顺序：`tenant_id` → `module_key` → `resource_key`；来源与优先级由基座统一。
2. 管理面复用中间件注入的租户上下文；数据面在帧入口复用同一解析函数；异步路径在每轮 / 每批入口调用同一守卫。
3. 固定校验顺序：租户可用性 → `module_key` 已登记启用 → `resource_key` 已注册且归属正确 → 产品自定义规则。
4. 定义失败语义：租户不存在 / 停用、`module_key` 未登记 / 未启用、`resource_key` 未注册 / 越界分别拒绝；租户源不可达 fail-closed（503）；不泄露存在性。
5. 禁止产品自建解析、信任客户端自报头、自建状态缓存；补三条路径一致性测试与越权测试。
6. **交付物**：三入口共用的解析函数说明、固定校验顺序、失败语义表（含租户源不可达 503 与不泄露存在性）、三路径一致性与越权测试清单；边界——不改基座中间件既有的租户解析顺序，不在帧入口另写第二套解析。

## 3. 完成标准 <a id="accept"></a>

同一请求在管理面、数据面、异步路径解析出同一组三级标识；跨租户、跨 `module_key`、未注册 `resource_key` 被拒；停用即时生效；租户源不可达 503；代码中无第二套解析实现。
