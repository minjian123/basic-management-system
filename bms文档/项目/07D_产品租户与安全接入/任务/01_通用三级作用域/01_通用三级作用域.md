## 2. 任务内容 <a id="content"></a>

架构 41 §4 已定「资源归属用 `tenant_id / module_key / resource_key` 三级表达」，但基座只有租户身份与模块登记：`module_key` 不是作用域层级、`resource_key` 没有模型、三条入口各写各的解析。本任务把这套语义落成**基座唯一实现**，四段按需求条目串行推进——先有模型与注册，才有解析，再有上下文与错误码，最后才是生命周期清理。

### 2.1 三级作用域模型与注册（需求 01-1，架构 41 §4.1 / §4.2-3） <a id="w01-1"></a>

1. 三级值对象：`tenant_id`（雪花内部身份、不可变）、`module_key`（复用模块注册键）、`resource_key`（受已登记类型约束）。
2. 作用域类型注册记录：产品、模块键、类型标识 `{module_key}.{kind}`、命名规则、状态、声明版本、保留期与处置策略；声明态与运营态分列，运营期停用不被声明重放冲掉。
3. 注册校验（fail-closed）：模块键必须已登记且启用、类型标识全局唯一、命名规则可编译；未登记即拒，不做「先跑起来再补登记」。
4. 装载通道与产品自持声明同源（新增一类声明），不建第二套注册表；装载后生成进程内只读视图供解析复用。
5. 与业务域、部署单元的关系用示例固化：`module_key` 不等于业务域，`resource_key` 归属 `module_key` 而非部署单元，拓扑变化不改三级标识。

### 2.2 作用域解析与校验（需求 01-2，架构 41 §4.2-2/4/7、§5.1） <a id="w01-2"></a>

1. 解析顺序固定 `tenant_id` → `module_key` → `resource_key`，来源与优先级由基座统一，产品不得在入口自行拼装。
2. 三处入口复用同一实现：管理面取中间件注入的租户上下文；数据面在帧入口调用同一函数；异步路径在每轮 / 每批入口调用同一守卫。
3. 校验顺序固定：租户可用性 → 模块已登记启用 → 资源已注册且归属正确 → 产品自定义规则；前三步基座统一，产品只追加最后一步。
4. 失败语义：租户两类沿用既有码、模块与资源四类新增码；租户源不可达按 fail-closed 返回 503；对外不泄露存在性。
5. 禁止清单：产品自建解析、信任客户端自报头、自建状态缓存、数据面用连接建立时的租户覆盖后续请求。

### 2.3 作用域上下文与错误码（需求 01-3，架构 41 §5.1、§7.1） <a id="w01-3"></a>

1. 不可变作用域上下文：三级标识 + 产品自定义扩展；生命周期为请求级或批次级，禁止全局单例持有。
2. 三处注入：HTTP 依赖、数据面帧上下文、异步守卫返回值；业务模块只经上下文取作用域。
3. 六类错误码逐条定义并登记，产品码落在服务行登记段内，文案键交 i18n；管理面与数据面同码。
4. 审计上下文注入：作用域字段进入审计条目，涉及具体记录的操作可带记录级定位字段（接任务 02）。

### 2.4 租户生命周期与产品资源清理（需求 01-4，架构 12 生命周期节、41 §4.3） <a id="w01-4"></a>

1. 分工固化：基座拥有租户生命周期，产品只消费 `tenant.*` 事件，不自建状态表 / 状态机、不轮询基座租户表。
2. 事件契约：`created` / `disabled` / `enabled` / `deleted`，携带 `tenant_id`、`module_key`、前后状态与版本戳；至少一次投递，幂等键为「租户 + 事件类型 + 版本戳」。
3. 状态动作矩阵：懒初始化（失败不阻塞开通）、停用拒绝收发、恢复受理、删除按登记的保留期归档或物理删除并断开连接；每个动作幂等可重入。
4. 失败与死信：清理失败不反向阻塞基座已提交的删除事务；失败进重试，耗尽进死信，必须有日志与指标与可运维处置入口。
5. 保留期联动：资源类型登记带保留期（§2.1），删除后保留期内只读、到期物理删除；审计记录不随资源删除。

## 4. 完成标准 <a id="accept"></a>

| 需求 | 完成标准 |
| --- | --- |
| 01-1 | 三级模型有唯一权威定义；类型可登记 / 查询 / 停用；未登记或未启用的模块键被拒；类型冲突被拒；与架构 41 §4 一致 |
| 01-2 | 同一请求在管理面、数据面、异步路径解析出同一组三级标识；跨租户、跨模块键、未注册资源被拒；停用即时生效；租户源不可达 503；代码中无第二套解析 |
| 01-3 | 三类入口都可取到不可变上下文；六类错误码逐条有定义并登记；管理面与数据面同码；审计条目带作用域字段；无业务层自行拼装响应 |
| 01-4 | 四类生命周期事件可被产品消费且逐条可验证；重复投递无重复副作用；停用与恢复即时生效；删除后按保留期归档 / 清理且可核对；失败可重试、可观测、有死信出口；产品仓无自建租户状态表与轮询实现 |

## 6. 依赖与风险 <a id="dep"></a>

- **关键依赖**：模块注册（11）提供模块键权威登记；多租户路由（12）提供租户身份、解析链与生命周期；事件总线（16）提供生命周期事件通道；审计哈希链（19）提供审计写入。
- **风险与对策**：

| 风险 | 对策 |
| --- | --- |
| `module_key` 与业务域、部署单元混用 | 架构 41 §4.3 已区分；本任务 §2.1-5 用示例固化 |
| 数据面与异步路径各写一套解析 | 三路径复用同一函数 / 守卫，用例断言同结论 |
| 资源类型注册粒度过细，产品接入成本高 | 按「资源类型」登记，不按单个资源实例登记 |
| 注册期强校验导致产品无法先跑起来 | 明确「注册在先」是红线（架构 41 §8 红线七），不为过渡期开口子 |
