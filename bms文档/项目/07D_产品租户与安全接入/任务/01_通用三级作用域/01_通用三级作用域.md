## 2. 任务内容 <a id="content"></a>

本任务是 07D 的核心新增能力：把 `module_key` 提升为作用域第二级，补齐 `resource_key` 的注册、解析、校验、上下文与错误码，并在租户生命周期事件下收口产品资源清理。四项工作项串行——先有模型与注册，才有解析，再有上下文与错误码，最后才是生命周期清理。

| 工作项 | 对应需求 | 交付重心 |
| --- | --- | --- |
| 01-1 作用域模型与注册 | [01-1](../../需求/01_需求_通用三级作用域.md#r01-1) | 三级值对象、类型注册记录、注册校验、装载通道 |
| 01-2 作用域解析与校验 | [01-2](../../需求/01_需求_通用三级作用域.md#r01-2) | 解析与校验顺序、三路径同口径、失败语义 |
| 01-3 作用域上下文与错误码 | [01-3](../../需求/01_需求_通用三级作用域.md#r01-3) | 不可变上下文、六类错误码、审计注入 |
| 01-4 租户生命周期与产品资源清理 | [01-4](../../需求/01_需求_通用三级作用域.md#r01-4) | 事件契约、状态动作矩阵、失败与死信 |

### 2.1 作用域模型与注册（01-1） <a id="w01-1"></a>

1. 定义三级作用域值对象：`tenant_id`（雪花内部身份、不可变）、`module_key`（复用模块注册键、须已登记且启用）、`resource_key`（在已登记的类型约束下标识具体资源）。
2. 设计作用域类型注册记录：产品、`module_key`、类型标识 `{module_key}.{kind}`、命名规则（正则 + 最大长度）、状态（启用 / 停用）、声明版本、保留期与处置策略；声明态与运营态分列，运营期停用不被声明重放冲掉；登记与停用均留审计。
3. 设计注册校验：`module_key` 必须已登记且启用；类型标识产品内唯一、全局不冲突；命名规则可编译；未登记即拒绝（fail-closed），不做「先跑起来再补登记」；装载期失败用注册错误拒绝，不占业务错误码段。
4. 装载通道与模块注册、产品自持声明同源（声明新增一类），不新增第二套注册表；装载后生成进程内只读视图，供解析与校验复用。
5. 固化关系语义：`module_key` 是模块注册键、不等于业务域；`resource_key` 归属 `module_key`、不归属部署单元；拓扑变化不改变三级标识（关系写成示例，不建清单）。
6. 提供作用域类型的登记（声明装载）、查询（快照段）、停用（运营面接口）能力；停用即时反映到只读视图并留审计。

**交付物**：三级作用域值对象与类型记录定义、类型注册记录结构与状态迁移、注册校验规则与拒绝口径、与模块注册 / 产品自持声明共用装载通道的说明、快照段与停用接口。
**边界**：不新增第二套注册表；不定义产品业务资源语义（主题 / 存储桶 / 组织树的含义归产品文档）；不在注册记录里承载进度。

### 2.2 作用域解析与校验（01-2） <a id="w01-2"></a>

1. 固定解析顺序：`tenant_id` → `module_key` → `resource_key`；来源与优先级由基座统一，产品不得在入口自行拼装。
2. 三处入口复用同一实现：管理面取中间件注入的租户上下文；数据面在帧入口调用同一解析函数；异步路径在每轮 / 每批入口调用同一守卫；不写第二套解析。
3. 固定校验顺序：租户可用性 → `module_key` 已登记启用 → `resource_key` 已注册且归属正确 → 产品自定义规则；前三步由基座统一，产品只追加最后一步。
4. 定义失败语义：租户不存在 / 已停用、`module_key` 未登记 / 未启用、`resource_key` 未注册 / 越界分别拒绝并映射到已登记错误码；租户源不可达按 fail-closed 返回 503；对外不泄露存在性。
5. 禁止清单：产品自建解析、信任客户端自报头、自建状态缓存覆盖基座判定、数据面用连接建立时的租户覆盖后续请求；配套三路径一致性用例与越权用例。

**交付物**：三入口共用解析函数说明、固定校验顺序、失败语义表（含 503 与不泄露存在性）、三路径一致性与越权用例清单。
**边界**：不改基座中间件既有的租户解析顺序；不在帧入口另写第二套解析。

### 2.3 作用域上下文与错误码（01-3） <a id="w01-3"></a>

1. 定义不可变作用域上下文：`tenant_id`、`module_key`、`resource_key` 与产品自定义扩展；生命周期为请求级或批次级，禁止全局单例持有。
2. 上下文注入三处：HTTP 依赖、数据面帧上下文、异步守卫返回值；业务模块只经上下文取作用域，不再自行解析。
3. 定义六类错误码：租户不存在、租户停用、`module_key` 未登记、`module_key` 未启用、`resource_key` 未注册、`resource_key` 越界；产品码落在服务行登记段内，文案键交 i18n 管理。
4. 管理面与数据面同码；错误渲染经 02-2 的统一单点，业务层不拼装 HTTP 响应。
5. 审计上下文注入：作用域字段进入审计条目；涉及具体记录的操作可带记录级定位字段（接 02-4）。

**交付物**：不可变上下文定义、三处注入点说明、六类错误码与登记位置、审计上下文字段清单。
**边界**：不在业务层新增响应拼装；不让上下文生命周期越过请求 / 批次边界。

### 2.4 租户生命周期与产品资源清理（01-4） <a id="w01-4"></a>

1. **分工固化**：基座拥有租户生命周期，产品只消费 `tenant.*` 事件；产品不得自建租户状态表 / 状态机，不得轮询基座租户表反推状态。
2. **事件契约**：至少四类事件（`tenant.created` / `disabled` / `enabled` / `deleted`），字段含 `tenant_id`、`module_key`、变更前后状态、版本戳；投递为至少一次，幂等键为 `tenant_id` + 事件类型 + 版本戳；归档事件按需另立，不与删除混用。
3. **状态动作矩阵**：`created` 懒初始化（失败不阻塞开通）、`disabled` 拒绝收发（复用基座版本戳）、`enabled` 恢复受理、`deleted` 按登记的保留期归档或物理删除并断开连接、清理延迟区；每个动作标注幂等与可重入要求。
4. **失败与死信**：清理失败不反向阻塞基座已提交的删除事务；失败进事件重试，耗尽后进死信，必须有日志与指标，并给出可运维处置入口，禁止静默丢弃。
5. **保留期联动**：资源类型登记必须带保留期（01-1）；删除后保留期内只读，到期物理删除；审计记录不随资源删除（接 02-4）。
6. **反例清单**（进评审项与 04-1 规则输入）：自建 `tenant_status` 表、在删除事件里回调基座改状态、把清理做成一次性脚本、清理失败让租户删除长期挂起。

**交付物**：事件消费契约说明、状态动作矩阵、失败与死信处置口径、反例清单——并入 02 任务的产品接入说明，不另立第二份。
**边界**：不让产品反向写基座租户状态；不以清理失败为由阻塞基座删除。

## 3. 完成标准 <a id="accept"></a>

| 工作项 | 完成标准 |
| --- | --- |
| 01-1 | 三级模型有唯一权威定义；作用域类型可登记 / 查询 / 停用；未登记或未启用的 `module_key` 被拒；类型冲突被拒；与架构 41 §4 一致 |
| 01-2 | 同一请求在管理面、数据面、异步路径解析出同一组三级标识；跨租户、跨 `module_key`、未注册 `resource_key` 被拒；停用即时生效；租户源不可达 503；代码中无第二套解析实现 |
| 01-3 | 三类入口都可取到不可变上下文；六类错误码逐条有定义并登记；管理面与数据面同码；审计条目带作用域字段；无业务层自行拼装响应 |
| 01-4 | 四类生命周期事件可被产品消费且逐条可验证；重复投递无重复副作用（幂等键可断言）；停用拒绝与恢复受理即时生效；删除后资源按保留期归档 / 清理且可核对；清理失败可重试、可观测、有死信出口；产品仓库无自建租户状态表与轮询实现 |

## 5. 依赖与风险 <a id="dep"></a>

- **关键依赖**：模块注册（11）提供 `module_key` 权威登记；多租户路由（12）提供租户身份与解析链、生命周期；数据访问与分片（13）提供数据面入口；事件总线（16）提供生命周期事件通道。
- **风险与对策**：

| 风险 | 对策 |
| --- | --- |
| 把 `module_key` 与业务域、部署单元混用 | 以架构 41 §4.3 区分三者，并在 01-1 正文用示例固化 |
| 数据面与异步路径各写一套解析 | 三条路径复用同一函数 / 守卫，用例断言同结论 |
| `resource_key` 注册粒度过细，产品接入成本过高 | 按「资源类型」登记，不按单个资源实例登记 |
