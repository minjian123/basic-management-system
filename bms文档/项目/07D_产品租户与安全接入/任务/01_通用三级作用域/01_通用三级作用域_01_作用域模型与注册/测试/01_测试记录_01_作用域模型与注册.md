### 验收标准对照 <a id="accept"></a>

| 完成标准（需求 01-1） | 证据 |
| --- | --- |
| 三级模型有唯一权威定义 | `ResourceScopeKey` + `ScopeResourceTypeRecord` 为唯一落点；值对象用例 3 例 |
| 作用域类型可登记 / 查询 / 停用 | 登记：清单解析 + 落库用例；查询：`GET /api/v1/scope-resource-types` + `?with=resource_types`；停用：`PATCH` + 幂等 + 审计 |
| 未登记或未启用的 `module_key` 被拒 | `_check_resource_types`（离线）/ `validate_scope_resource_types`（注册期）用例各一组 |
| 类型冲突被拒 | 跨产品撞键、同清单重复两分支 |
| 与架构 41 §4 一致 | 类型标识 `{module_key}.{kind}`、`module_key` 复用模块注册、`resource_key` 由产品声明登记；§4.3 关系写成示例表（设计 §3.8） |

## 4. 问题与偏差 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 首次 `--with resource_types` 未请求时 `CatalogSnapshotResponse` 新增字段导致既有 `test_modules_snapshot` 断言失败 | 属预期契约变更：期望集补 `resource_types`、`snapshot_version` 由 `"2"` 改 `"3"`，并补「未请求即空数组」断言 |
| 2 | `test_owned_tables_and_chain_derivation` 期望集缺新表 | 补 `sys_scope_resource_type`（表归属是单一来源，属预期变更） |
| 3 | 覆盖缺口先后出现两处：`_has_nested_unbounded` 的不可达分支、`resource_kind` 单段回落 | 删除不可达分支并改写为无分支 `any(...)`；补「可选 / 有界 / 无界」三形态与单段标识容错用例 |
| 4 | 运营面响应初版带 `id` / `disabled_at` / `disabled_by` 而记录值对象无这些字段 | 收敛响应字段（实施记录 §5-3），停用人与时间统一查审计链 |
| 5 | 用例内注册落库后未提交，运营期写路径先回滚空事务导致「未登记」误报 | 用例侧落库后显式 `commit`（模拟注册通道独立事务），与生产路径一致 |
| 6 | 模块级覆盖率未在本轮判定 | 归推送环（本任务只提交不推送）；已在实施记录 §5-8 登记 |
