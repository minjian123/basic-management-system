## 2. 任务内容 <a id="content"></a>

把产品接入时最常见的四类差异收敛为基座契约：产品只实现语义，基座负责顺序、入口与统一渲染。资源级 ACL 不收敛为基座引擎，只定义接入约束与上收条件。接入次序固定为「作用域校验 → 错误码映射 → 配额回显 → 审计字段」。

| 工作项 | 对应需求 | 交付重心 |
| --- | --- | --- |
| 02-1 作用域校验扩展点 | [02-1](../../需求/02_需求_标准扩展点.md#r02-1) | 契约（输入 / 输出 / 异常）、装配与解析、三路径复用 |
| 02-2 错误码映射扩展点 | [02-2](../../需求/02_需求_标准扩展点.md#r02-2) | 映射声明、撞码检测、统一渲染单点 |
| 02-3 配额只读回显扩展点 | [02-3](../../需求/02_需求_标准扩展点.md#r02-3) | 投影契约、只读不双写、三态区分 |
| 02-4 审计字段扩展点 | [02-4](../../需求/02_需求_标准扩展点.md#r02-4) | 标准 + 扩展字段、留痕类别、记录级定位 |
| 02-5 资源级 ACL 接入约束 | [02-5](../../需求/02_需求_标准扩展点.md#r02-5) | 判定顺序、边界、单点与上收条件 |

### 2.1 作用域校验扩展点（02-1） <a id="w02-1"></a>

1. 定义扩展点契约：输入为作用域上下文 + 产品自定义参数，输出为通过或拒绝（产品错误码）。
2. 基座负责租户可用性、`module_key` 登记校验、`resource_key` 注册校验三步；产品只注册资源级归属判定，不得调整顺序、不得跳过前三步。
3. 扩展点经统一装配机制注册与解析；必需扩展点未注册即拒启，可选扩展点按产品声明跳过（不得做成隐式必需）。
4. 数据面、异步消费、定时任务、批处理复用同一扩展点；扩展点异常按 fail-closed 处理。
5. 消息平台的命名空间校验迁移到该扩展点，主题归属校验作为产品规则；迁移后行为与改造前一致。

**交付物**：契约（输入 / 输出 / 异常）、装配与解析规则、三路径复用说明、msg 命名空间校验迁移对照表。
**边界**：不承载产品业务规则；不新增第二套装配机制。

### 2.2 错误码映射扩展点（02-2） <a id="w02-2"></a>

1. 定义映射扩展点：产品声明「基座码 → 产品码」映射与文案键，映射只在统一错误渲染单点生效。
2. 产品码段在服务行登记；码级定义随产品自持声明装载；平台负责唯一性、撞码检测与契约反向对账。
3. 管理面与数据面同码；映射只做语义改写——不改 HTTP 状态语义、不吞错、不把系统性失败改写成业务成功或参数错误。
4. 禁止业务层自行拼装 HTTP 响应、绕过统一渲染、使用未登记码段或未登记文案键。
5. 消息平台现有映射迁移到该扩展点；其他产品按需接入，未接入时沿用基座默认渲染。

**交付物**：映射声明格式、装载与撞码检测规则、统一渲染单点说明、msg 迁移对照表。
**边界**：不改 HTTP 状态语义、不吞错、不允许业务层自拼响应。

### 2.3 配额只读回显扩展点（02-3） <a id="w02-3"></a>

1. 定义产品配额投影契约：维度、限额、用量、单位、周期、软硬限、更新时间、来源；字段语义统一，产品按契约返回。
2. 产品自维护配额值与执行点，值是单一事实源；平台只读装载——不写平台通用配额表、不做双写、不代替产品执行配额。
3. 产品登记数据源与取数端点；平台负责权限、脱敏与读取审计；缺省值、不可用、超限三态可区分。
4. 支持一个产品多个维度、多个 `module_key`；投影可按租户 / `module_key` / 资源维度聚合。
5. 消息平台现有用量端点与表单登记按契约改造，保持「产品自维护 + 平台只读」口径不变。

**交付物**：投影契约（字段与语义）、只读装载与权限 / 脱敏 / 读取审计口径、三态区分、msg 用量端点改造对照表。
**边界**：不写平台通用配额表、不双写、不代替产品执行配额。

### 2.4 审计字段扩展点（02-4） <a id="w02-4"></a>

1. 定义审计标准字段 + 扩展字段契约：作用域字段、资源标识、记录级定位、产品自定义字段。
2. 产品声明必须留痕的操作类别；普通读写不逐条留痕，只做指标统计；记录级定位字段只出现在涉及具体记录的操作上。
3. 扩展字段只补充语义，不改变哈希链构造、归档与校验口径；产品不得自建审计表、不得绕过基座审计写入、不得删除审计记录。
4. 审计写入失败按操作类别处置：需强审计的操作失败即失败；其余记录指标与告警，不静默丢弃。
5. 消息平台重放 / 删消息 / 位点重置 / 延迟转投异常处置等操作按契约带 `log_id`，可从审计条目一次定位到记录。

**交付物**：标准字段 + 扩展字段契约、留痕类别与判定、记录级定位字段规范、失败处置口径、msg 操作类别对照表。
**边界**：不改哈希链构造与归档口径、不自建审计表、不逐条留痕普通读写。

### 2.5 资源级 ACL 接入约束（02-5） <a id="w02-5"></a>

1. **定位**：资源级 ACL 是产品特有扩展，不是第五类标准扩展点；基座只给约束、判定顺序与上收条件，不实现通用 ACL 引擎。
2. **判定顺序**：固定为「基座 RBAC（功能级）→ 产品资源级 ACL → 作用域归属（`tenant_id` / `module_key`）」，任一步拒绝即终止；ACL 不得前置——前置会泄露资源存在性。
3. **边界**：ACL 只在同一 `module_key` 内生效；跨租户、跨 `module_key` 一律拒绝且不因 ACL 放行；资源级授权不得扩大租户或模块边界。
4. **产品义务**：ACL 存储自持、不写平台表；变更留痕接 02-4；管理面、数据面、异步路径同口径校验；重放 / 删除 / 位点重置等记录级操作必须有资源级校验。
5. **单点与上收**：ACL 判定收敛为单点接口（可替换），为「第二个产品提出同类需求时上收为基座通用授权能力」预留过渡；上收条件见《[平台可扩展性规划](../../../../规划/平台可扩展性规划.md)》「边界争议的处置」节。
6. **反例清单**（三处历史易漏点，各给可验证的拒绝用例形态）：跨租户订阅、管理接口只校验登录、重放任意主题。

**交付物**：ACL 接入约束清单、判定顺序与反例清单、上收条件说明——并入 04 任务的护栏规则输入，不新建通用授权模块。
**边界**：不实现通用 ACL 引擎；不在产品仓复制权限码体系。

## 3. 完成标准 <a id="accept"></a>

| 工作项 | 完成标准 |
| --- | --- |
| 02-1 | 扩展点可注册、可解析、可配置；校验顺序不可绕过；三条路径同结论；未注册必需扩展点时拒启；msg 迁移后跨租户 / 停用 / 未登记命名空间行为不变 |
| 02-2 | 映射可声明、可装载、可校验；撞码或未登记码段被拒；管理面与数据面同码；msg 迁移后行为不变；无业务层自行拼装响应 |
| 02-3 | 投影字段完整且语义统一；平台只读可见且与产品侧一致；无双写；超限 / 不可用可区分；msg 改造后可用 |
| 02-4 | 扩展字段可写入、可查询；审计链完整、归档口径不变；普通读写不产生洪泛；msg 记录级定位可用；审计失败处置有明确口径 |
| 02-5 | 判定顺序唯一且有测试证明 ACL 无法绕过 RBAC 或作用域归属；跨租户 / 跨 `module_key` 有拒绝用例；管理面与数据面同口径；ACL 变更可在基座审计链查到；判定收敛为单点接口且具备上收替换条件；三处反例各有可执行用例；产品仓无自建 RBAC 引擎与复制权限码 |

## 5. 依赖与风险 <a id="dep"></a>

- **关键依赖**：[01 通用三级作用域](../01_通用三级作用域/01_通用三级作用域.md)提供上下文与错误码；扩展点与插件化（10）提供装配与解析；接口与集成（09）提供统一渲染；审计哈希链（19）提供审计写入；跨产品协同（38）提供码段登记。
- **风险与对策**：

| 风险 | 对策 |
| --- | --- |
| 扩展点契约过宽，变成第二套框架 | 只定义契约与顺序、不承载业务；扩展边界以架构 41 §3 判定 |
| 产品在扩展点之外复制基座机制 | 反例进 04-1 护栏规则输入；评审按禁止清单核对 |
| 四类扩展点接入顺序混乱 | 固定「作用域校验 → 错误码映射 → 配额回显 → 审计字段」次序 |
