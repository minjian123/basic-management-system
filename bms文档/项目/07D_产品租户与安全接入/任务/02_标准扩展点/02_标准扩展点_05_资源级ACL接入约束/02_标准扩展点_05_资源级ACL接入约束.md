## 2. 任务内容 <a id="content"></a>

1. **定位写清**：资源级 ACL 是产品特有扩展，不是第五类标准扩展点；基座只给约束、判定顺序与上收条件，不实现通用 ACL 引擎。
2. **判定顺序**：固定为「基座 RBAC（功能级）→ 产品资源级 ACL → 作用域归属（`tenant_id` / `module_key`）」；任一步拒绝即终止；明确 ACL 不得前置，并给出「前置会泄露资源存在性」的反例。
3. **边界**：ACL 只在同一 `module_key` 内生效；跨租户、跨 `module_key` 一律拒绝且不因 ACL 放行；资源级授权不得扩大租户或模块边界。
4. **产品义务**：ACL 存储自持、不写平台表；变更留痕接 02-4；管理面、数据面、异步路径同口径校验；重放 / 删除 / 位点重置等记录级操作必须有资源级校验。
5. **单点与上收**：ACL 判定收敛为单点接口（可替换），为「第二个产品提出同类需求时上收为基座通用授权能力」预留过渡；上收条件引用《平台可扩展性规划》「边界争议的处置」。
6. **反例清单**（三处历史易漏点必须覆盖）：跨租户订阅、管理接口只校验登录、重放任意主题；每条给出可验证的拒绝用例形态。
7. **交付物**：ACL 接入约束清单、判定顺序与反例清单、上收条件说明；并入 03-1 护栏规则输入，不新建通用授权模块。

## 3. 完成标准 <a id="accept"></a>

- 判定顺序唯一，且有测试证明 ACL 无法绕过 RBAC 或作用域归属；
- 跨租户、跨 `module_key` 访问有拒绝用例；
- 管理面与数据面同口径（含「只校验登录」反例）；
- ACL 变更可在基座审计链查到（接 02-4）；
- ACL 判定收敛为单点接口，具备上收替换条件；
- 三处历史易漏点各有可执行的反例用例；
- 产品仓库无自建 RBAC 引擎、无复制权限码体系。
