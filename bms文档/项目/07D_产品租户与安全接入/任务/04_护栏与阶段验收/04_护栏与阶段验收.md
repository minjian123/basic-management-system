## 2. 任务内容 <a id="content"></a>

> **前置契约（已交付）**：01 通用三级作用域、02 四类标准扩展点与资源级 ACL 接入约束、03 msg 四项扩展点迁移（`scope_rule` / `maps_from` / `kind=quota` / `record_ref`）均已交付；03 的 `03-2` / `03-3` 已摘除，专项需求 12 条。本任务按 12 条逐条核对；mdm / biz 两仓本期零改动，护栏仍按「产品仓库不出现继承层实现」判定。

护栏本期只设计规则、不实现；阶段验收按架构 41 §7.2 的八条判据收口。两者输入同源：01 / 02 的反例清单——护栏把反例变成可判定规则，验收把反例变成可核对证据。

### 2.1 护栏规则设计（需求 04-1，架构 41 §3、§8） <a id="w04-1"></a>

1. 规则分三类：**继承层复制**（租户解析 / 令牌 / 权限引擎 / 审计链 / 自建租户状态机）、**扩展点外复制**（含资源级 ACL 绕过基座 RBAC 与作用域归属）、**字面量硬编码**（平台表名 / 服务标识 / 权限码 / 路径）。
2. 判定方式：依赖检查、路径与符号检查、字面量检查；优先复用 engkit 既有护栏机制，不新增第二套。
3. 误报处理：白名单、注释标记、评审确认三种；白名单须有期限与责任人，不得长期豁免。
4. 规则分级：阻断级（继承层复制、扩展点外复制）与告警级（字面量硬编码）；本期只设计，实现另立任务。
5. 接入点：明确与 engkit 的规则配置方式、CI 触发时机与新增仓库的接入步骤。
6. 规则输入须覆盖具象反例：自建租户状态表、删除事件回调基座改状态、ACL 前置、管理接口只校验登录、重放任意主题——不得只写通用三类而漏掉这些。

### 2.2 阶段验收（需求 04-2，架构 41 §7.2） <a id="w04-2"></a>

1. 按八条判据逐条验收：同一性、越权拒绝、停用即时、未登记拒绝、审计可追溯、配额可核对、错误码一致、无复制实现。
2. 12 条需求逐条核对完成情况，每条给出结论（达标 / 限定达标 / 不达标）与证据索引。
3. 证据包括需求、设计、任务、实施 / 测试记录、基座与产品回归结果；证据不足的条目不得判达标。
4. 未达标项写明归口（后续任务、其他专项或明确不采纳），不得静默带入下一阶段。
5. 输出专项测试报告：验收点、核对方式、结论、证据、未达标项与归口。
