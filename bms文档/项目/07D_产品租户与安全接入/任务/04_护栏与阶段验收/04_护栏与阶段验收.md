## 2. 任务内容 <a id="content"></a>

护栏本期只设计规则、不实现；阶段验收按架构 41 §7.2 的八条判据收口。两者的输入都来自 01-4 与 02-5 的反例清单——护栏把反例变成可判定规则，验收把反例变成可核对证据。

| 工作项 | 对应需求 | 交付重心 |

| 04-2 阶段验收 | [04-2](../../需求/04_需求_护栏与阶段验收.md#r04-2) | 八条判据、14 条需求核对、专项测试报告 |

### 2.1 护栏规则设计（04-1） <a id="w04-1"></a>

1. 规则分三类：**继承层复制**（租户解析 / 令牌 / 权限引擎 / 审计链 / 自建租户状态机）、**扩展点外复制**（含产品资源级 ACL 绕过基座 RBAC 与作用域归属）、**字面量硬编码**（平台表名 / 服务标识 / 权限码 / 路径）。
2. 每类给出判定方式：依赖检查、路径 / 符号检查、字面量检查；优先复用 engkit 既有护栏机制，不新增第二套。
3. 误报处理给三种方式：白名单、注释标记、评审确认；白名单须有期限与责任人，不得长期豁免。
4. 规则分级：阻断级（继承层复制、扩展点外复制）与告警级（字面量硬编码）；本期只设计，实现另立任务。
5. 明确与 engkit 的接入点、规则配置方式与 CI 触发时机，输出规则清单与实现建议。
6. 规则输入须覆盖 01-4 与 02-5 的具象反例（自建租户状态表、删除事件回调基座、ACL 前置、只校验登录、重放任意主题），不得只写通用三类而漏掉这些具象反例。

**交付物**：三类规则清单（含具象反例）、判定方式、误报处理流程、engkit 接入点与 CI 触发时机。
**边界**：本期只设计不实现；不新增第二套护栏机制；不长期豁免白名单。

### 2.2 阶段验收（04-2） <a id="w04-2"></a>

1. 按[架构 41 §7.2](../../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#accept-criteria) 的八条判据逐条验收：同一性、越权拒绝、停用即时、未登记拒绝、审计可追溯、配额可核对、错误码一致、无复制实现。
2. 14 条需求逐条核对完成情况，每条给出结论（达标 / 限定达标 / 不达标）与证据索引。
3. 证据包括需求、设计、任务、实施 / 测试记录、基座与产品回归结果；证据不足的条目不得判达标。
4. 未达标项写明归口（后续任务、其他专项或明确不采纳），不得静默带入下一阶段。
5. 输出专项测试报告：验收点、核对方式、结论、证据、未达标项与归口。

**交付物**：专项测试报告（八条判据 × 结论 × 证据索引、14 条需求核对表、未达标项归口）。
**边界**：不提前判达标；不以文档对齐代替行为验证；不静默带入下一阶段。

## 5. 依赖与风险 <a id="dep"></a>

- **关键依赖**：01~03 全部工作项交付（规则与验收的对象）；engkit 既有护栏机制（判定落地通道）；测试规范与项目管理规范（验收口径）。
