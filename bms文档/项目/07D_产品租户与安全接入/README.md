## 立项背景 <a id="background"></a>

消息平台的多租户与安全需求曾按「本域定义一套租户边界与安全防线」组织，但实际实现已经复用基座解析链、租户源、可用性守卫、服务身份、RBAC 与审计链——文档口径与代码事实不一致，评审时容易被读成「产品要自建一套」。同类风险在其他产品同样存在：产品为了「自主可控」复制一份租户解析或权限判定，短期能跑，长期会在基座停用、权限变更、审计归档时出现不可见的断链。

基座能力以架构节点为唯一权威：租户、认证、权限、审计、通用配额、模块注册、能力契约、安全防护都已按节点交付，产品直接按其契约接入，**不设继承清单、不维护接入基线**；能力缺失或接口不足的，回 bms 补，不在产品仓复制实现。

本专项只补三处缺口：

1. **通用三级作用域**：`tenant_id / module_key / resource_key` 的模型、注册、解析、校验，以及租户生命周期事件下的产品资源清理；
2. **四类标准扩展点**：作用域校验、错误码映射、配额只读回显、审计字段扩展；外加产品资源级 ACL 的接入约束；
3. **产品接入改造与护栏**：msg 先行，按四类标准扩展点接入并同步文档定位；护栏规则先设计。

## 边界 <a id="scope"></a>

- **范围内**：通用三级作用域（含租户生命周期资源清理）、四类标准扩展点与资源级 ACL 接入约束、msg 的接入改造与文档定位同步、禁止层护栏规则设计、专项验收。
- **范围外**：基座已有能力的重新实现（租户解析、认证、RBAC、审计链、通用配额等归各自架构节点）；产品业务功能；资源级 ACL 的通用化（当前归产品，本专项只定义接入约束与上收条件）；配额统一执行（当前只做只读回显）；护栏的代码实现（本专项只设计规则）；继承清单 / 接入基线类文档的维护。
- **与 07B 的分工**：07B 管「能力目录、分配与授权」；本专项管「产品接入时的租户、身份、作用域、审计口径」。
- **与 07C 的分工**：07C 管「业务域、部署单元与租户拓扑」；本专项的 `module_key` 是模块注册键，不替代业务域，`resource_key` 不归属部署单元。
