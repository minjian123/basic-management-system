## 立项背景 <a id="background"></a>

消息平台的多租户与安全需求曾按「本域定义一套租户边界与安全防线」组织，但实际实现已经复用基座解析链、租户源、可用性守卫、服务身份、RBAC 与审计链——文档口径与代码事实不一致，评审时容易被读成「产品要自建一套」。同类风险在其他产品同样存在：产品为了「自主可控」复制一份租户解析或权限判定，短期能跑，长期会在基座停用、权限变更、审计归档时出现不可见的断链。

已有的基座能力并不缺：租户解析、状态校验、生命周期、服务身份、RBAC、审计链、通用配额、模块注册、能力契约都已交付（盘点见[需求总览](需求/00_需求_产品租户与安全接入.md#inventory)）。真正缺的是一层**产品接入语义**——哪些必须继承、哪些允许扩展、哪些禁止复制，以及产品特有资源如何嵌进统一的作用域与扩展点。

本专项不重复建设基座已有能力，只补四类缺口：

1. **继承清单与接入基线**：把已交付能力盘清楚，形成所有产品可引用的基线；
2. **通用三级作用域**：`tenant_id / module_key / resource_key` 的模型、注册、解析与校验；
3. **四类标准扩展点**：作用域校验、错误码映射、配额只读回显、审计字段扩展；
4. **产品接入改造与护栏**：msg 先行，mdm / biz 现有文档对齐；护栏规则先设计。

## 边界 <a id="scope"></a>

- **范围内**：能力盘点与接入基线、通用三级作用域、四类标准扩展点、msg / mdm / biz 的接入改造与现有文档对齐、禁止层护栏规则设计、专项验收。
- **范围外**：基座已有能力的重新实现（租户解析、认证、RBAC、审计链、通用配额等归各自架构节点）；产品业务功能；资源级 ACL 的通用化（当前归产品）；配额统一执行（当前只做只读回显）；护栏的代码实现（本专项只设计规则）。
- **与 07B 的分工**：07B 管「能力目录、分配与授权」；本专项管「产品接入时的租户、身份、作用域、审计口径」。
- **与 07C 的分工**：07C 管「业务域、部署单元与租户拓扑」；本专项的 `module_key` 是模块注册键，不替代业务域，`resource_key` 不归属部署单元。
