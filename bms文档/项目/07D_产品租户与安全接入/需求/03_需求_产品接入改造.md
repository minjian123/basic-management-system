## 1. 域说明 <a id="intro"></a>

本域把 01~02 域定义的三级作用域与标准扩展点落到具体产品：消息平台先行（文档重写 + 四项扩展点代码改造），mdm / biz 本期只对齐现有文档（设计、任务按需最小同步）。本域不重复建设基座能力，也不改产品业务功能。

覆盖范围：msg 接入改造、mdm / biz 文档对齐。依据见《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 6.2、7 节。

## 2. 需求 03-1：消息平台接入改造 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：消息平台的 05 需求把多租户与安全写成「本域定义一套」，但代码已经复用基座解析链、租户源、可用性守卫、服务身份、RBAC 与审计链；文档与代码事实不一致。同时，02 域的四类扩展点需要在 msg 上先落地验证。

**内容**（[架构 41 §6.2 / §7](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#inherit-flow)）：

1. **重写 msg 05**：只保留扩展项（重新编号 `05-1`、`05-2`…），继承项直接引用 bms 架构节点（不另立清单）；不再重复定义租户解析、认证、RBAC、审计链等基座能力。
2. **保留现有任务**：原「05-1 租户用量板块与表单登记」任务、Kiwi 用例与实施记录保留，归入新的扩展项；不废弃、不重挂历史。
3. **映射**：消息平台的 `namespace` 映射为 `module_key`，`topic` 映射为 `resource_key`；命名空间校验迁移到 02-1，主题归属校验作为产品规则。
4. **四项扩展点一次改完**：作用域校验（02-1）、错误码映射（02-2）、配额只读回显（02-3）、审计字段扩展（02-4）；改造后跨租户、停用、未登记命名空间、错误码、配额回显、`log_id` 行为与改造前一致。
5. **同步文档**：msg 设计 07、任务 05、规划 01、需求总览 00 的定位与引用同步更新；msg 仓与 bms 仓的跨仓依赖与声明登记保持一致。
6. **msg 05 扩展项与 07D 需求的对应关系**（本条是分工，不是新增功能）：`05-3 配额` → 07D `02-3` 出投影契约，msg 侧任务实现配额自维护与执行点；`05-4 topic ACL` → 07D `02-5` 出接入约束，msg 侧任务实现 ACL 存储与判定；`05-5 审计留痕` → 07D `02-4` 出扩展字段契约，msg 侧任务声明留痕类别与 `log_id` 定位；`05-6 租户生命周期` → 07D `01-4` 出事件与清理分工，msg 侧任务实现资源清理（「开通初始化」已由 msg `05-1` 第 7 条承接）。四条扩展项一律「基座出契约、产品出任务」，不得把产品实现回写到 bms。

**完成标准**：msg 05 只写扩展项，继承项直接引用架构节点且可达；原 05-1 任务与记录保留并归入扩展项；四项扩展点全部接入；跨租户 / 停用 / 未登记 / 错误码 / 配额 / 审计行为回归通过；msg 设计与任务文档口径一致。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 6.2、7 节；消息平台需求 05、设计 07、任务 05；[需求 02-1](02_需求_标准扩展点.md#r02-1) ~ [02-4](02_需求_标准扩展点.md#r02-4)。

## 3. 需求 03-2：mdm 文档对齐 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：mdm 是主数据产品，已有租户与安全接入，但需求篇没有按「继承项 / 扩展项」组织，读者无法判断哪些能力来自基座、哪些是 mdm 特有。需要按架构 41 的能力边界对齐，避免后续维护时再分叉。

**内容**（[架构 41 §6.2](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#inherit-flow)）：

1. 盘点 mdm 现有租户与安全相关需求 / 设计，识别继承项与扩展项；继承项直接引用架构节点，扩展项保留并写明「为什么只能由主数据产品实现」。
2. 改写 mdm 需求篇：删除对基座能力的重复定义；扩展项（如主数据资源作用域、字段级权限、组织数据范围等）保留并补边界。
3. 设计篇、任务篇按实际差异最小同步；本期不改 mdm 代码。
4. 验收：mdm 需求篇无基座能力重复定义；扩展项边界清晰；引用架构节点可达。
5. 基座能力缺失或不足的，回 bms 补（提需求或缺陷），不在 mdm 仓复制实现。

**完成标准**：mdm 需求篇按继承 / 扩展两类改写完成；继承项引用可达；扩展项有边界说明；设计 / 任务按需同步；无代码改动。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「接入流程（语义级）」节；mdm 产品文档。

## 4. 需求 03-3：biz 文档对齐 <a id="r03-3"></a>

优先级：2（高）

**背景与动机**：biz 企业运营管理产品有采购、收付款、销售、仓储等业务域，租户与安全需求分散在各业务域文档中；不按架构 41 的能力边界对齐，容易出现「业务域各自定义租户边界」的重复建设。

**内容**（[架构 41 §6.2](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#inherit-flow)）：

1. 盘点 biz 现有租户与安全相关需求 / 设计，识别继承项与扩展项；继承项直接引用架构节点，扩展项保留并写明业务域边界。
2. 改写 biz 需求篇：删除对基座能力的重复定义；扩展项（如业务资源作用域、业务权限码、业务数据范围等）保留并补边界。
3. 设计篇、任务篇按实际差异最小同步；本期不改 biz 代码。
4. 验收：biz 需求篇无基座能力重复定义；扩展项边界清晰；引用架构节点可达。
5. 基座能力缺失或不足的，回 bms 补（提需求或缺陷），不在 biz 仓复制实现。

**完成标准**：biz 需求篇按继承 / 扩展两类改写完成；继承项引用可达；扩展项有边界说明；设计 / 任务按需同步；无代码改动。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「接入流程（语义级）」节；biz 产品文档。
