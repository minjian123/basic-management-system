## 1. 域说明 <a id="intro"></a>

本域把 01~02 域定义的三级作用域与标准扩展点落到具体产品：消息平台先行（05 需求复核 + 四项扩展点代码改造 + msg 文档定位同步）。本域不重复建设基座能力，也不改产品业务功能。

覆盖范围：msg 接入改造。依据见《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「继承清单与产品接入流程」「失败语义与验收判据」节。

> 原 `03-2 mdm 文档对齐`、`03-3 biz 文档对齐` 已按用户拍板摘除：两仓没有「租户与安全」需求篇与产品扩展项，不为不存在的需求改写文档；两仓本期零改动，遗留去向见[计划](../计划/01_计划_产品租户与安全接入.md)「后续阶段待办」节。

## 2. 需求 03-1：消息平台接入改造 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：消息平台的 05 需求把多租户与安全写成「本域定义一套」，但代码已经复用基座解析链、租户源、可用性守卫、服务身份、RBAC 与审计链；文档与代码事实不一致。同时，02 域的四类扩展点需要在 msg 上先落地验证。现 05 需求已按「继承基座 + 扩展项」重写，本需求聚焦把 msg 的产品先行实现迁回基座契约。

**内容**（[架构 41「继承清单与产品接入流程」「失败语义与验收判据」](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)）：

1. **复核 msg 05**：05 需求已重写为「继承基座 + 扩展项 `05-1` ~ `05-7`」，原「05-1 租户用量板块与表单登记」任务、Kiwi 用例与实施记录保留并归入扩展项 `05-7`；本需求只做引用可达性复核与按改造结论的增量修订，不重做、不改编号、不重挂历史。
2. **映射**：消息平台的 `namespace` 映射为 `module_key`，`topic` 映射为 `resource_key`；命名空间校验迁移到 02-1 的 `scope_rule` 规则链，主题归属校验作为产品规则。
3. **四项扩展点一次改完**：作用域校验（02-1）、错误码映射（02-2）、配额只读回显（02-3）、审计字段扩展（02-4）；改造后跨租户、停用、未登记命名空间、错误码、配额回显、`log_id` 行为与改造前一致（强审计一条除外，见完成标准）。
4. **数据面同源**：h2 帧入口复用基座同一解析函数，不得信任客户端自报头；管理面 / 数据面 / 异步三路径得出同一结论。
5. **同步文档**：msg 设计 07、任务 05、规划 01、需求总览 00 的定位与引用同步更新；msg 仓与 bms 仓的跨仓依赖与声明登记保持一致。
6. **msg 05 扩展项与 07D 需求的对应关系**（本条是分工，不是新增功能）：`05-3 配额` → 07D `02-3` 出投影契约，msg 侧任务实现配额自维护与执行点；`05-4 topic ACL` → 07D `02-5` 出接入约束，msg 侧任务实现 ACL 存储与判定；`05-5 审计留痕` → 07D `02-4` 出扩展字段契约，msg 侧任务声明留痕类别与 `log_id` 定位；`05-6 租户生命周期` → 07D `01-4` 出事件与清理分工，msg 侧任务实现资源清理（「开通初始化」已由 msg `05-1` 第 7 条承接）。四条扩展项一律「基座出契约、产品出任务」，不得把产品实现回写到 bms。
7. **扩展项对账**：逐条核对配额、topic ACL、审计留痕、生命周期四项是否都有「基座契约 + msg 任务」两段；对账表以任务 03 详细设计为唯一事实源，msg 任务 05 文档引用。

**完成标准**：msg 05 只写扩展项，继承项直接引用架构节点且可达；原 05-1 任务与记录保留并归入扩展项；四项扩展点全部接入；跨租户 / 停用 / 未登记 / 错误码 / 配额 / 审计行为回归通过（记录级操作的强审计写入失败由「只告警」变为「业务失败」，属已确认的新增行为，单列基线）；msg 设计与任务文档口径一致。
