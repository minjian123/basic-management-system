## 1. 域说明 <a id="intro"></a>

本域把产品接入时最常见的四类差异收敛为标准扩展点：作用域校验、错误码映射、配额只读回显、审计字段扩展。四类扩展点由基座定义契约、顺序与统一入口，产品只实现语义；不在四类中的需求，先按架构 41 §3 判定是继承、扩展还是新能力，不直接在产品侧开新口子。

覆盖范围：四类扩展点的契约边界、接入方式、失败语义与验收判据。依据见《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「标准扩展点」节。

## 2. 需求 03-1：作用域校验扩展点 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：消息平台当前用租户守卫的扩展钩子做 `module_key` 校验，`scope` 是自由字符串，基座不解释；其他产品接入时没有统一挂载点，容易各自在入口写校验。需要把「作用域校验」收敛为基座契约，产品只注册资源级规则。

**内容**（[架构 41 §5.1](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#ext-scope)）：

1. 基座定义作用域校验扩展点契约：产品注册「资源级归属判定」，基座负责租户可用性、`module_key` 登记校验、`resource_key` 注册校验三步。
2. 扩展点输入为作用域上下文 + 产品自定义参数，输出为通过或拒绝（产品错误码）；产品不得调整校验顺序、不得跳过前三步。
3. 扩展点注册与解析走统一装配机制；必需扩展点未注册即拒启，可选扩展点未注册时按产品声明跳过。
4. 数据面、异步消费、定时任务、批处理复用同一扩展点，不另写一套；异常按 fail-closed 处理。
5. 消息平台的命名空间校验迁移到该扩展点，主题归属校验作为产品规则；迁移后行为与改造前一致。

**完成标准**：扩展点可注册、可解析、可配置；校验顺序不可绕过；三条路径同结论；未注册必需扩展点时拒启；msg 迁移后跨租户 / 停用 / 未登记命名空间行为不变。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「作用域校验」节；《[架构设计 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》；《[架构设计 · 多租户路由](../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》「租户解析链」节。

## 3. 需求 03-2：错误码映射扩展点 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：消息平台已有「基座码 → 产品码」的改写实现，但它是单产品特例；其他产品接入时仍可能各自在业务层拼 HTTP 响应，导致管理面与数据面不同码。需要把错误码映射收敛为所有产品可用的契约。

**内容**（[架构 41 §5.2](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#ext-error)）：

1. 基座定义错误码映射扩展点：产品声明「基座码 → 产品码」映射与文案键；映射只在统一错误渲染单点生效。
2. 产品码段在服务行登记；码级定义随产品自持声明装载；平台负责唯一性、撞码检测与契约反向对账。
3. 管理面与数据面同码；映射只做语义改写，不改 HTTP 状态语义、不吞错、不把系统性失败改写成业务成功或参数错误。
4. 禁止业务层自行拼装 HTTP 响应、绕过统一渲染、使用未登记码段或未登记文案键。
5. 消息平台现有映射迁移到该扩展点；其他产品按需接入，未接入时沿用基座默认渲染。

**完成标准**：映射可声明、可装载、可校验；撞码或未登记码段被拒；管理面与数据面同码；msg 迁移后行为不变；无业务层自行拼装响应的实现。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「错误码映射」节；《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》错误码节；《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「协同契约要素（类别与归属）」节。

## 4. 需求 03-3：配额只读回显扩展点 <a id="r03-3"></a>

优先级：2（高）

**背景与动机**：产品自有配额（消息平台的主题数、消息存储、吞吐、连接数）由产品自维护，平台只读展示；现有 `[[data_sources]]` 只解决「能读」，缺统一的投影 schema，导致各产品返回结构不一致、权限与审计口径不统一。需要把「配额只读回显」收敛为契约。

**内容**（[架构 41 §5.3](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#ext-quota)）：

1. 定义产品配额投影契约：维度、限额、用量、单位、周期、软硬限、更新时间、来源；字段语义统一，产品按契约返回。
2. 产品自维护配额值与执行点，值是单一事实源；平台只读装载，不写平台通用配额表，不做双写，不代替产品执行配额。
3. 产品登记数据源与取数端点；平台负责权限、脱敏与读取审计；缺省值、不可用状态、超限状态要可区分。
4. 支持一个产品多个维度、多个 `module_key`；投影可按租户 / `module_key` / 资源维度聚合。
5. 消息平台现有用量端点与表单登记按契约改造，保持「产品自维护 + 平台只读」口径不变。

**完成标准**：投影字段完整且语义统一；平台只读可见且与产品侧一致；无双写；超限 / 不可用状态可区分；msg 改造后可用。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「配额只读回显」节；《[架构设计 · 多租户路由](../../../设计/架构设计/12_架构设计_子系统_多租户路由.md)》「配额管理」节；《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「协同契约要素（类别与归属）」节；消息平台需求 05-3 的「产品自维护 + 基座只读回显」拍板口径。

## 5. 需求 03-4：审计字段扩展点 <a id="r03-4"></a>

优先级：2（高）

**背景与动机**：消息平台的重放、删消息、位点重置等操作需要带记录级定位字段（如 `log_id`），当前靠产品自行拼装审计事件；其他产品接入时也会遇到「标准字段不够、扩展字段无契约」的问题。需要把审计字段扩展收敛为基座契约，同时保持哈希链与归档口径不变。

**内容**（[架构 41 §5.4](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md#ext-audit)）：

1. 基座审计事件在标准字段之外提供扩展字段契约：作用域字段（`tenant_id` / `module_key` / `resource_key`）、资源标识、记录级定位、产品自定义字段。
2. 产品声明必须留痕的操作类别；普通读写不逐条留痕，只做指标统计；记录级定位字段只出现在涉及具体记录的操作上，避免审计洪泛。
3. 扩展字段只补充语义，不改变哈希链构造、归档与校验口径；产品不得自建审计表、不得绕过基座审计写入、不得删除审计记录。
4. 审计写入失败的处置按操作类别与合规要求区分：需强审计的操作失败即失败；其余记录指标与告警，不静默丢弃。
5. 消息平台重放 / 删消息 / 位点重置 / 延迟转投异常处置等操作按契约带 `log_id`，可从审计条目一次定位到记录。

**完成标准**：扩展字段可写入、可查询；审计链完整、归档口径不变；普通读写不产生洪泛；msg 记录级定位可用；审计失败处置有明确口径。

**参考文档**：《[架构设计 · 产品租户与安全接入](../../../设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「审计字段扩展」节；《[架构设计 · 审计哈希链](../../../设计/架构设计/19_架构设计_子系统_审计哈希链.md)》；消息平台需求 05-6 的「记录级定位」口径。
