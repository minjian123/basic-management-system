## 2. 任务内容 <a id="content"></a>

### 2.1 触发 <a id="trigger"></a>

13_10 T7 全量取证（CI #1784）暴露既有存量红 157 条，按域归口为独立批次；identity 认证域占比最大，登记于[计划表 §7 后续阶段待办 #54](../../../计划/01_计划_后端基座与服务化地基.md#followup)。

业主 2026-11-26 拍板：这是**缺陷修复**，不是新需求——一个任务装下整个 identity 域，不再拆子任务，也不新增需求编号。

### 2.2 实测基线（2026-11-26，HEAD = `1f7e8ae4e`） <a id="baseline"></a>

CI #1784 的清单已明显过时（该轮之后 13_10 修了 12 类引入项），按子目录在共享库上串行复跑：

| 子目录 | CI #1784 | HEAD 实测（未治理） | 主要现象 |
| --- | --- | --- | --- |
| `oidc/` | 36 | **13 failed / 38 passed**（全在 `test_clients.py`） | 403（`open:manage`） |
| `idp/` | 10 | **12 failed / 2 passed**（单文件跑）；整目录跑 41 passed | 403（`idp:manage`）+ 顺序耦合 |
| `sso/` | 12 | **17 failed / 25 passed** | 403（`sso:bind`） |
| `auth/` | 49 | **4 failed / 15 passed**（`test_login.py`） | 失败计数 / 验证码前提 |
| `internal/` | 3 | 待实测 | 待定 |
| `oidc/test_authorize.py` + `test_token.py` | 18 | **23 passed**（已随 13_10 修复消解） | — |

> 「整目录跑反而绿、单文件跑红」说明存在跨用例状态耦合（同一进程内的授权 / 缓存 / 顺序前提），正是本批要消除的对象，不能以「整目录绿」交差。

### 2.3 根因 <a id="rootcause"></a>

| 族 | 根因 | 涉及 |
| --- | --- | --- |
| F1 权限拒绝（403） | identity 的豁免权限替身打在**模块级装配期**（替换 `build_identity_source`），而全系统装配改为**会话级一次**后，app 不再由本目录 conftest 装配；注册表持有的是装配时的函数对象，用例期替换已读不到 → 五个权限码（`session:query` / `session:kick` / `open:manage` / `idp:manage` / `sso:bind`）走真实 RBAC，测试主体无任何授权 | oidc / idp / sso 的主体部分 |
| F2 计数与验证码前提 | 登录失败计数、验证码强制等状态按主体 / 全局累积，跨用例互相影响 | `auth/test_login.py` |
| F3 顺序耦合 | 同一进程内授权、权限快照缓存、IdP 配置等状态跨用例存活，单文件与整目录结论不一致 | `idp/test_manage.py`、`sso/` |
| F4 自建应用壳缺 state | 用例自带 `ApplicationFactory().create(None)` 未补 `engine_registry` / `role_resolvers_factory` 等装配期状态 | 待逐条确认（identity 侧目前仅 `identity_app_factory` 定义，无使用点） |

### 2.4 目标与边界 <a id="scope"></a>

**目标**：identity 认证域在共享库上**单文件 / 窄目录实跑全绿**，且不引入新红。

**范围**：

1. `backend/services/identity/tests/**` 的用例与夹具；
2. `backend/tests_support/**` 的共用授权准备入口（若现有 `permission_admin.setup_min_tenant` 已够用，则只补夹具接线，不新造第二套）；
3. 计划表 #55 的前置处置：并行档位单源（见 §2.5 T0）。

**不在范围**：platform / tenant / file / bms_core 的存量红（按域另立批次）；产品能力新增。

**不动清单**：覆盖率门限 100%、`-n` 强制并行、0.1 秒忙等、零复制库、预算数值（300 / 420 / 600）、既有规范条文；**不得用独占库 / 内存库换绿**（13_10 已定口径）。

### 2.6 已确认结论 <a id="decided"></a>

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 任务粒度 | 缺陷修复，**一个任务**装下 identity 全域，不拆子任务、不新增需求（业主 2026-11-26） |

## 3. 完成标准 <a id="accept"></a>

- `oidc/` / `idp/` / `sso/` / `auth/` / `internal/` 五个子目录在同一份共享库上**单目录实跑全绿**（不靠整目录互相掩盖、不靠独占库换绿）。
- **不引入新红**：本任务触及范围之外的文件失败数不增加；失败集合与改动前对照为准。
- 共用授权准备是**单一入口**：identity 各子目录不再各写一套豁免 / 授权替身；已失效的模块期补丁删除。
- 基座护栏基线**只减不增**：`check_test_premises.py` 的 P1 / P5 项数不增加，`engkit base bare-collections` 通过。
- 变更模块覆盖率 100%（若触及 `src`）；仅改测试 / 夹具时以预检判定为准。
- 计划表 #54 状态与 #55 处置回写完成；测试记录含逐子目录实测数与失败归因。
