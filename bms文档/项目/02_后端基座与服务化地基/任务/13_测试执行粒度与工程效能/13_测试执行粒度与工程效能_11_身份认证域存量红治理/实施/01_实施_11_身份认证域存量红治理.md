### 2.2 T1 真实授权准备 <a id="auth"></a>

**根因**：identity 的豁免权限替身有两条旧路径——函数级 `monkeypatch.setattr(bms_identity.permission, "build_identity_source", ...)` 与模块级 `_patched_exempt_source()`。二者都只改**模块属性**，而权限数据来源在**装配期**已按函数对象登记进进程级注册表；且模块级补丁的执行时机晚于会话级全系统装配。补丁完全失效，五个权限码走真实 RBAC，测试主体在租户库无任何角色 → 403。

**改法**：identity conftest 增一条会话级 autouse 夹具，直接复用 platform 侧既有入口：

```text
_authorized_subject(shared_tenant_db_url)
  └─ tests_support.permission_admin.setup_min_tenant(url)
       └─ _grant_once：按（连接串 + 主体 + 角色码）每进程一次，幂等
```

同时删除已失效且会误导后来者的旧件：`_exempt_permission_source`、`_ExemptPermissionSource`、`_build_exempt_source`、`_patched_exempt_source`、`identity_module_env`（改造后已无使用点）、`identity_app_factory` / `_new_app` / `_SeedTenantSource`（identity 侧无使用点，装配后也不需要自带 app）。

### 2.3 T1 附 装配态每例还原（本次新增的共用夹具） <a id="restore"></a>

清 403 后暴露第二族问题：**跨用例状态污染**，表现为单文件绿、整目录红。

| 实证 | 现象 | 状态源 |
| --- | --- | --- |
| `sso/test_authorize.py` → `sso/test_bind.py` | bind 两条 403 | `test_authorize.py` 直接写 `app.dependency_overrides[...]`，用例结束不卸载 |
| `sso/test_callback.py` → 后继全部回调用例 | 期望 400/200/503，实际全 302 | `test_callback_redirect_responses` 就地改 `app.state.settings.sso.success_redirect` / `failure_redirect` |

**改法**：新增 `backend/tests_support/app_state.py`，提供两个还原上下文与一个统一入口：

- `restore_dependency_overrides(app)`：进入前快照 `app.dependency_overrides`，退出还原；
- `restore_settings(settings)`：按 `Settings` 顶层各段做深拷贝快照，退出按字段写回（保持对象身份，装配期持有同一对象的组件不受影响）；
- `restore_assembled_app(app)`：两者合一，服务 conftest 只挂一条 autouse 夹具。

identity conftest 的 `_restore_app_overrides` 即调用统一入口，各子目录不再各写清理。

### 2.4 顺手修 #50：权限数据来源工厂按应用固化 <a id="fix50"></a>

首轮 CI（#1785）失败 84 处同源：identity 请求走到 platform 的取数实现，`build_platform_source` 读 `request.app.state.role_resolvers_factory` 抛 `AttributeError` → 500 / 403。本地用「platform 自建壳 + identity 会话」同进程复现（7 红），回退对照证明与本任务测试改动无因果——即计划表 #50「权限数据来源注册表最后登记者生效」。

**改法**（核心 2 处 + 护栏 2 条）：

| 落点 | 改动 |
| --- | --- |
| `bms_core/application.py` | 应用创建完成时（`prepare_settings` 刚登记完本服务工厂）把当时生效的工厂钉到 `app.state.permission_data_source_factory` |
| `bms_core/permission/rbac.py` | `_resolve_source` 优先取 `request.app.state.permission_data_source_factory`，未固化时回落进程级注册表（旧行为） |
| `tests/permission/test_sources.py` | 新增「应用级工厂优先于注册表」用例；请求构造改为替身对象（避开 P5 对 `app.state` 赋值写的拦截） |
| `tests/testing/test_session_assembly.py` | 新增「identity 与 platform 各钉各的工厂」装配护栏 |

验证：混合复现组合 7 红 → **20 passed**；`test_sources.py` 17 passed；`test_session_assembly.py` 7 passed；前提护栏基线 205 → **204 条**（`test_sources` 的 P5 计数清零）。提交 `c9f8454be`（预检 17 项全过，73.3s）。
