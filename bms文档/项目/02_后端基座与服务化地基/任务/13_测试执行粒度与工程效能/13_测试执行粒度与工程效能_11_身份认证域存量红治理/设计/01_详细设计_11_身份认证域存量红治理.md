## 1. 设计目标 <a id="goal"></a>

把 identity 认证域在共享库上的存量红清到 0，且治法可复用、不产生新的同类问题。三条硬要求：

1. **单一入口**：授权准备只在 `tests_support` 一处实现，identity 各子目录只接线、不复制；
2. **与真实运行形态一致**：走真实 RBAC 与真实数据，不用「替换权限来源 / 改 app 状态」绕开；
3. **可复现**：本地预检与 CI 同并行档位（计划表 #55），同一批用例两侧结论一致。

## 2. 现状与根因 <a id="rootcause"></a>

### 2.1 装配形态变了，夹具没跟上 <a id="assembly-gap"></a>

13_10 把「逐用例 / 逐文件装配」改为「会话级一次全系统装配」：

- 装配发生在第一个用例之前，`identity` 的 app 来自 `assembled_system.app("identity")`；
- 权限检查器与数据来源工厂在**装配期**登记进进程级注册表（`bms_core/permission/sources.py` 的 `_FACTORIES`），注册表持有的是**函数对象**；
- identity conftest 仍保留两条旧手法：函数级 `monkeypatch.setattr(identity_permission, "build_identity_source", ...)`，以及模块级 `_patched_exempt_source()`。

两者都只改**模块属性**，改不到注册表里已登记的函数对象；且模块级补丁的执行时机晚于会话级装配。结果是豁免完全失效，五个权限码走真实 RBAC，测试主体（`1001`）在租户库里没有任何角色 → 403。

### 2.2 为什么「整目录跑反而绿」 <a id="order-coupling"></a>

`idp/test_manage.py` 单文件跑 12 failed，整目录跑 41 passed。同一份代码、同一份库，差异只能来自**进程内跨用例状态**：

- 权限快照缓存（`configure_permission_cache_store`，TTL 300s）按（租户, 主体）缓存；
- 前序用例可能触发过不同分支，让后续请求命中不同的数据来源实现（注册表「最后登记者生效」，见计划表 #50）；
- IdP 配置、会话状态在共享库上叠加。

这类「靠别人先跑一遍」的绿是假绿，本设计不接受；判据必须是**单目录从零跑也绿**。

### 2.3 其余两族 <a id="other-families"></a>

| 族 | 现象 | 方向 |
| --- | --- | --- |
| 计数 / 验证码前提 | `auth/test_login.py` 4 条：连续失败强制验证码、失败不计入、记住我分支、无客户端 IP 跳过限流 | 计数状态按主体命名空间隔离；断言只认本次写入 |
| 自建应用壳缺 state | `ApplicationFactory().create(None)` 后直接打受保护路由，缺 `engine_registry` / `role_resolvers_factory` | 能改用装配实例的改用；确需自带 app 的补最小状态（见 §3.3） |

## 3. 治法 <a id="approach"></a>

### 3.1 T0 并行档位单源（计划表 #55） <a id="jobs"></a>

**问题**：本地预检缺省 `-n auto`（本机 22 worker），CI 固定 `-j 6`；同一批用例在两种并发下结论可能不同（13_08 §2.25 已实证串并行不一致）。

**设计**：

1. engkit `PytestConfig` 增字段 `jobs: str = "auto"`，并提供「配置值 → 预检缺省档位」的唯一读取点；
2. `bms/engkit.toml` 的 `[pytest]` 增 `jobs = "6"`；
3. `.gitlab-ci.yml` 去掉硬编码 `--jobs 6`，改由同一份配置提供；同时修正「本地预检同档一致」的过时注释（此前并不一致）。

**为什么单源**：两处各写一个数字，改一处忘一处就再次漂移；配置是仓级事实，本地与 CI 读同一处才能保证「本地过 = CI 同档过」。

**回退判据**：若 6 档下定向档逼近 600s 上限，先缩批次 / 缩小选测面，**不改预算数值**；若确认档位与耗时不可兼得，回到业主拍板，不自行调数。

### 3.2 T1 共用授权准备 <a id="auth-fixture"></a>

**设计**：identity conftest 增一条会话级 autouse 夹具，在装配前把测试主体置为内置系统管理员：

```text
_authorized_subject(shared_tenant_db_url)
  └─ tests_support.permission_admin.setup_min_tenant(shared_tenant_db_url)
       └─ _grant_once：按（连接串 + 主体 + 角色码）每进程一次，幂等
```

要点：

1. **为什么是内置管理员**：本套件绝大多数用例测的是 SSO / 会话 / IdP 的业务语义，不是授权链路；`role_type=system` 命中校验器豁免层级，等价于 13_10 §15.2 在 platform 侧已经落地的口径。
2. **为什么在会话级**：授权行落共享租户库，写入一次对全部用例可见；函数级每例授权会在并行下反复抢租户写门（`_grant_once` 的进程内缓存也会失效，因为每例都换 URL 变量）。
3. **为什么删旧补丁**：模块期替换已失效，留着会误导后来者以为「这里还有豁免」；`tests/permission/` 目录不依赖豁免效果（只测数据来源的字段映射，不断言主体缺权）。
4. **影响面**：授权是全局的（租户库共享），platform 侧的 `setup_min_tenant` 早已如此；identity 加入不会引入新的全局状态种类。断言「主体无任何角色」的用例一律改用库内恒无授权数据的主键（13_10 §15.5 已立此口径）。

### 3.3 T1 附：最小应用壳补全 <a id="shell"></a>

只对**必须自带 app** 的用例（破坏性全局操作、装配失败分支）提供，不推广：

- 在 `tests_support` 增一个「最小应用壳补全」助手：按需补 `engine_registry`（指向共享库）、`role_resolvers_factory`（真实解析器）、`session_factory`；
- 补全后仍须进 `own_db` / `destroy` 白名单并写明理由；
- 能改用 `assembled_system.app(...)` 的一律改用，不保留双份装配路径。

identity 侧目前 `identity_app_factory` 只有定义、无使用点，若清红中确认无需求，直接删除该夹具，避免留第二个装配入口。

### 3.4 T2~T5 分域清红 <a id="batches"></a>

按「先收口 403 族，再处理状态族」的顺序，每个子目录单独验证：

| 批 | 范围 | 判据 |
| --- | --- | --- |
| B1 | `oidc/`（`test_clients.py` 13 条） | 单目录 51 passed |
| B2 | `idp/`（`test_manage.py` 12 条 + 顺序耦合） | 单文件 14 passed、单目录 41 passed + 1 skipped |
| B3 | `sso/`（17 条） | 单目录全绿 |
| B4 | `auth/` + `internal/`（4 + 3 条） | 单目录全绿 |

**每批的固定动作**：

1. 先按根因归类（403 / 计数前提 / 顺序耦合 / 缺 state），同类一次改完；
2. 改完先跑**单文件**，再跑**单目录**；两者都要绿，避免互相掩盖；
3. 不引入独占库；需要唯一性就按命名空间派生（`ns.code(...)`）；
4. 断言只认本次写入，不写「全表条数」「全局清单全等」。

### 3.5 产品缺陷的处置 <a id="product-bug"></a>

业主已批「允许顺手修」，但按规范仍需：

- 在设计文档登记该缺陷（现象 / 根因 / 影响面），不默默改；
- 若改后端响应契约，必须重导 `deploy/contracts/*.json` 与前端类型；
- 补对应用例并保证变更模块覆盖率 100%；
- 与测试改动同批提交（`feat`），记录写进实施记录。

## 4. 验收映射 <a id="accept-map"></a>

| 完成标准 | 验证方式 |
| --- | --- |
| 五个子目录单目录全绿 | 逐目录 `pytest <dir> -q -n 0`（串行）＋ `-n 6`（同档复核） |
| 不引入新红 | 改动前后失败集合对照；触及范围外的目录抽样复跑 |
| 单一授权入口 | 代码检索：identity 各目录无第二份豁免 / 授权替身；`_patched_exempt_source` 删除 |
| 护栏基线只减不增 | `check_test_premises.py`（P1 / P5 计数）、`engkit base bare-collections` |
| 覆盖率 | 预检 / CI 判定（仅改测试时以预检为准） |
| #55 落地 | engkit 自测 + `engkit.toml` 生效值 + CI 片段无硬编码 |

## 5. 风险与回退 <a id="risk"></a>

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 全局授权改变其它域结论 | platform / tenant 中「主体缺权」断言失效 | 与 13_10 §15.5 同口径：缺权断言改用恒无授权的主键；本任务结束时抽样复跑相关文件 |
| 权限快照缓存跨用例残留 | 改完仍偶发 403 / 200 | 需要时在夹具内复位快照仓（`reset_permission_state`），不作为默认动作 |
| 单文件绿、整目录红（或反之） | 假绿 | 两级判据都跑；发现顺序耦合先定位状态源，不加锁、不排序兜底 |
| 6 档耗时上升 | 定向档逼近 600s | 缩批次 / 缩选测面；不改预算数值 |
| 顺手修产品缺陷扩大范围 | 提交面变大 | 单条登记、单条验证；确需大改则拆出另立任务 |

## 6. 边界与开放项 <a id="open"></a>

- identity 之外的存量红（platform / tenant / file / bms_core）不在本设计范围；
- 计划表 #50（权限数据来源注册表「最后登记者生效」）是本次顺序耦合的上游成因之一，本任务只保证 identity 用例不依赖该行为，不改注册表语义；
- `tests/permission/` 的真实权限链路覆盖是否足够，待清红后复核，不在本次扩写。
