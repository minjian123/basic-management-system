## 2. 实施过程 <a id="process"></a>

### 2.1 基座模块（11 个文件）

```text
bms_core/testing/
├── __init__.py      # 公共出口
├── assertions.py    # assert_error / assert_no_error（异常-响应-JSON 三形态）
├── logs.py          # log_events / assert_logged（structlog JSON + caplog）
├── output.py        # stdout_text / stderr_text / assert_output / CliResult / run_cli / assert_exit
├── transaction.py   # rollback_session（外层事务 + savepoint + 补丁会话工厂）
├── fixtures.py      # bms_isolate_settings / platform_db / reset_request_context / reset_plugin_registry / clear_tenant_cache / has_fixture
├── base.py          # BaseTestCase（方法别名 + 模板方法钩子）
├── db.py            # DbTestCase（db_session 回滚夹具）
├── api.py           # ApiTestCase（client）
├── service.py       # ServiceTestCase（service_app，按子类 app_factory）
└── plugin.py        # `-p bms_core.testing.plugin` 入口（显式导入夹具）
```

### 2.2 conftest 收编

| 套件 | 处置 |
| --- | --- |
| `libs/bms_core/tests` | 5 个公共夹具收编，仅留 `platform_db_url`（依赖 `ops.seed_tenant`）与令牌 / fakeredis 追加 |
| `services/platform` | 留 `platform_db_url`（额外 `seed_modules`）/ `fake_tenant_source` / `service_app` / `client` |
| `services/identity` | 留 `platform_db_url` / `_SeedTenantSource` / `service_app` / `client`；IDP 状态存储关闭在追加段 |
| `services/{ai,file,notification,report,search}` | 五个同构文件统一精简为「公共夹具 + 服务专属接线」 |
| `services/tenant` | 收编；保留 `platform_db_url`（含 `_align_tenant_ids`）/ `fake_tenant_source` / `service_app` / `client` |
| `services/txn` | 收编；只依赖 `bms_isolate_settings` 并追加「就绪探针回落」（无平台库夹具，`platform_db` 自动跳过） |

各收编套件新增一个 3 行包装启用公共 autouse 夹具：

```python
@pytest.fixture(autouse=True)
def _plugin_fixtures(platform_db: None, reset_request_context: None, reset_plugin_registry: None) -> None: ...
```

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | `pytest_plugins` 在「`-p` 加载的插件模块」中**不再被处理**（该机制只对 conftest 生效） | `plugin.py` 显式导入夹具对象到本模块命名空间；各 conftest 再显式导入并列入 `__all__`（否则 ruff 以「未使用」删除，pytest 就找不到夹具） |
| 2 | 公共隔离夹具与各 conftest 同名 `isolate_settings` 冲突（后者需覆盖前者） | 公共夹具命名为 **`bms_isolate_settings`**（`@pytest.fixture(name=...)`），各 conftest 的 `isolate_settings` 显式依赖它 |
| 3 | 插件内 autouse 夹具与 conftest 的 autouse 顺序不确定（跨目录时令牌密钥被清空 → 验签 20001） | 插件夹具**全部非 autouse**，由各 conftest 的 `_plugin_fixtures` 包装显式依赖，顺序确定（公共隔离 → 服务追加 → 平台库） |
| 4 | SQLite（aiosqlite legacy 隔离）延迟到首条 DML 才真正 BEGIN，会话 savepoint 成为最外层事务并被 `commit` 提交（回滚失效） | `rollback_session` 对 SQLite 显式 `exec_driver_sql("BEGIN")`；抽出 `needs_explicit_begin()` 供非 SQLite 分支测试 |
| 5 | `platform_db` 用 `request.fixturenames` 判断 `platform_db_url` 是否存在——该属性只含**已解析**夹具（依赖链），不含 conftest 里「可用但未请求」的夹具 ⇒ 判定恒为假，`platform_db` 从不注入库 URL（表现为 tenant 的 switch 用例 401 / config 默认值断言失败） | 改 `resolve_fixture`（`request.getfixturevalue` + 捕获 `FixtureLookupError`，缺失返回 `None`）；抽 `apply_platform_db` 便于单测两分支。修复后 10 个 conftest **全部收编**、各套件全绿 |
| 6 | 基类继承护栏要求 `bms_core/src` 下所有类继承业务基类 | 测试基建类（`BaseTestCase` / 内部替身）不属业务继承链：`test_base_inheritance.py` 对 `bms_core/testing/` 目录豁免并注释依据 |
| 7 | 裸集合护栏拦截 `list[str]` / `dict[...]` 注解 | 基座与用例统一改用 `ConcurrentStableList` / `ConcurrentStableSet`；映射入参用 `Iterable[tuple[...]]` |
| 8 | pyright：动态导入模块作类型注解、夹具函数「未被存取」、`asynccontextmanager` 返回注解弃用 | 度量辅助按 `Any`；`_plugin_fixtures` 加 `# pyright: ignore[reportUnusedFunction]`；`AsyncIterator` → `AsyncGenerator` |
