## 2. 任务内容 <a id="content"></a>

1. **形态**：pytest 插件（夹具 / hook / marker）+ **可无限派生的测试基类**（先定三层：`BaseTestCase` → `DbTestCase` / `ApiTestCase` / `ServiceTestCase` → 具体测试类）；资源走 fixture，基类只做方法别名与扩展点；支持「测试类扩展新方法后由同类测试继承」。
2. **统一事务**：回滚夹具（外层事务 + savepoint），夹具内 patch `session_scope` / `unit_of_work` 使被测代码复用同一外层事务；用例结束整体回滚，不落盘、无跨用例污染。
3. **统一报错**：`assert_error(target, code=…, status=…)` 自动识别异常实例 / 响应对象 / JSON dict，统一覆盖 `pytest.raises` 与错误码断言两类高频写法。
4. **统一日志**：`log_events(capsys)` 解析 structlog JSON 行 + `assert_logged(event=…, level=…, **字段)`，替代各文件手写解析器。
5. **统一输出**：`stdout_text` / `stderr_text` / `assert_output(contains=…)` 统一 capsys；`run_cli(*args)` 跑 ops / scripts 入口并断言退出码与输出。
6. **夹具收编**：10 个 `conftest.py` 的重复夹具（`isolate_settings` / `platform_db_url` / `platform_db` / `reset_request_context` / `fake_tenant_source` / `service_app` / `client` / `clear_tenant_cache`）收编到插件，**保持同名同语义**，存量用例零改动。
7. **落点与门禁**：公共基座落 `backend/libs/bms_core/src/bms_core/testing/`（基座包内，产品仓可直接复用），纳入基座覆盖率门禁（`bms_core.testing` 行 + 分支 100%）。

## 3. 完成标准 <a id="accept"></a>

10 个 conftest 的重复夹具收敛到单一来源且存量用例零改动通过；新增用例可用统一事务（结束自动回滚、不落盘）与统一断言 / 日志 / 输出 helper；`bms_core.testing` 覆盖率行 + 分支 100%；有对应用例（Kiwi 登记）与规范登记（《测试规范》补「测试公共基座」节）。
