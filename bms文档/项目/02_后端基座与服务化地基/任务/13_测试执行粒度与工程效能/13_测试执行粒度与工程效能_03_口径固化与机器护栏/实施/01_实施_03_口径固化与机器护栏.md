### 3.5 《测试规范》§2.1 补节

在 §2.1 原 4 条原则之后追加六个子节（原 4 条不动）：

| 子节 | 内容要点 |
| --- | --- |
| 2.1.1 推导依据 | 单一共享实现 + 三类依据（目录同构 / 导入关系 / 工作区依赖反向闭包）+ 按目录自动发现不维护白名单 |
| 2.1.2 双重收敛与差集 | 两重缺一不可的理由 + 四类差集处理表（含「测试文件自身变更必选」） |
| 2.1.3 退化条件与显式输出 | 四类触发表（全局 / 基础模块 / 无引用者 / 基准不可解析）+ 显式打印要求 + 假绿风险说明 |
| 2.1.4 覆盖率扩圈 | 四步机制 + 门禁目标恒为最初变更模块 + 门禁口径不打折（引用《AI开发规范》） |

| 2.1.6 执行侧配套 | 并行可配与稳定性、自测按需、重复面划界、覆盖率采集前置（含漏计原理） |

写法按决策 2 执行：**不写脚本文件名、不写阈值数值**（避免改名 / 调参即漂移），落点指向工程说明。`13_02` 遗留第 5 项（并行 / 自测 / 重复面 / 采集前置条款）随 2.1.6 闭环。

### 3.6 CI 流水线锁修复（`.gitlab-ci.yml`）

根因与设计见详设 §9。实现要点：

| 改动 | 说明 |
| --- | --- |
| `owner_finished()`（两处） | 解析 owner 为「项目路径#流水线号」；仅本项目查 GitLab API；终态返回 0、进行中 1、不可判定 2 |
| acquire 主判据 | 终态 ⇒ **立即接管**并打印「auto_cancel 泄漏锁」；进行中 ⇒ 等待；不可判定 ⇒ 年龄兜底 |
| acquire 兜底 | `at` 年龄 ≥ stale 仍接管（跨项目 / API 不可用时行为与修订前一致） |
| release 增强 | 锁不属于本流水线但 owner 已终态 ⇒ 顺带清理并打印原因 |
| 注释校正 | 删除「持有者每条作业启动刷新 `at`」（实现中并不存在），改为准确描述两级判定 |
| 工具约束 | `docker:27-cli` 无 `curl` / `python3`（实测），用 BusyBox `wget --header` + `sed` 解析；token 不开 `set -x`、不入日志 |
