## 2. 任务内容 <a id="content"></a>

### 2.1 触发与实测 <a id="trigger"></a>

2026-11-23 推送收尾时，`libs/bms_core/tests/ops/test_seed_menu.py` 的一条用例在定向档第 2 批必红：
`_seed_menu_in_session` 断言「主表默认文案 ≡ 附表默认语言」，而共享平台库里存在他人写入的
`sys_action#manage`（主表 `管理`、附表 `管理（含查询与维护）`）。把它改成独占库能让这条用例变绿，
但这正是本条需求的触发点——**用独占库把「库里有别人数据」这一真实条件排除掉，测出来的仍不是真实行为**。

业主口径（2026-11-23）：实际运行时不可能出现「让你独占测试」的情况，所以独占库这个前提假设同样是错的。

同类实证（本轮与 13_09 实测，均指向同一类前提）：

| 现象 | 用例假设的前提 | 真实运行条件 |
| --- | --- | --- |
| 种子派生一致性用例必红 | 库里只有本次装载写的数据 | 库长期累积、他人写入 |
| `/api/v1/plugins` 精确清单多出 `stub` | 进程内注册表只装产品实现 | 同 worker 收集了测试替身 |
| 「无授权即拒」偶发返回 200 | 库里没给该服务授过能力 | 并行 worker 会真实授予 |
| 版本号写死 `== 1`、产品首页前 20 条、帮助导航前 50 条 | 库处于初始态 | 版本累计、条目累积 |
| 10 个文件共用 `platform-global-state` 文件锁 | 整段全局状态必须独占 | 真实系统里没有这种独占窗口 |
| 每次用例重走完整启动（插件注册表构建 / 声明校验 / 拓扑分发 / 事件消费者装载） | 进程是冷的、每次从零启动 | 进程长驻，启动只发生一次 |

### 2.2 目标与边界 <a id="scope"></a>

**目标**：让用例的断言前提与真实运行形态一致——库非空、有他人数据、全部后端服务同时运行、用例并发执行。三条可验收的要求：

1. **不假设干净库**：断言只针对**本次写入的数据**（唯一命名空间 + 显式构造前置），不断言库的全局收尾状态（`total == 0`、列表全等、条数写死）；需要「初始状态」的地方，由用例自己写入所需前置，而不是依赖库为空。
2. **运行形态只有共享库一种**：用例必须能在共享库上成立；**临时库、内存库、每用例新建库、独占库一律不允许**。2026-11-25 收紧：开发、生产、测试中都不存在「分给某个用例一个库」的形态，凡使用平台共享库与租户共享库之外的库即为错误。迁移脚本、建库建表、库名与连接串派生改为**纯逻辑断言**（断言生成的 SQL / 目标清单 / 派生结果），真实执行由初始化阶段承担一次；唯一例外是真外部服务联调（连部署环境的真实服务，不建库、缺配即跳过）。独占库不能作为让用例变绿的手段——**在共享库上跑不通，说明用例写错了，改用例**。
3. **全系统装配一次**：一轮测试固定「初始化 → 装配 → 并发跑用例」三阶段，顺序不可颠倒；装配阶段把**本仓全部后端服务**一次装配完毕，用例只作为用户并发访问已装配系统；不得按用例 / 文件 / 单个服务各自装配；随之删除 `platform-global-state` 文件锁。

**范围外**：压测与高并发场景不在本任务范围。本任务的「并发」只指并行执行用例，不承担吞吐、延迟、资源竞争验证。

**不动清单（沿用 13_08 / 13_09 已拍板口径）**：

1. 0.1 秒忙等、一份库零复制、覆盖率门限 100%、`-n auto` 并行档；
2. `[preflight.budget]` 数值与 `PUSH_MAX_TOTAL_SECONDS = 600` 硬上限；
3. 《测试规范》《AI开发规范》与 engkit 文档的既有条文不删改，本任务只做落地与必要的口径回写。

**推进方式**：先立检测（禁止新增），再按域清存量；每域改造后以「该域在共享库上全量单轮通过」判定，不用独占库换绿（2026-11-24 起不再以连跑两轮判定，理由见 §3 完成标准）。

### 2.4 已确认结论 <a id="decided"></a>

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 独占库能否作为解法 | **不能**：实际运行不存在独占窗口，前提假设本身错误（业主 2026-11-23） |
| 2 | 治理范围 | 所有「假设干净库」的情况，含全部独占库 |
| 3 | 与需求 13-8 第 4 条的关系 | 承接并落地——该条已写明「禁止依赖空库」，缺的是执行与检测 |
| 4 | 与 13_09 的先后 | 13_09 先收口推送（已完成），本任务独立推进，不回改 13_09 的验收结论 |
| 5 | 已提交的独占库改造 | `test_seed_menu` 的独占库改法按本任务口径属待整改项，改造时一并回退为「只断言本次写入的行」 |
| 6 | 运行形态 | **只有共享库一种**：运行时不存在「给你独占」的情形。用例在共享库上跑不通即为用例写错，需改用例，不得改执行形态绕开（业主 2026-11-23） |
| 7 | 装配范围 | **全部后端服务一次装配**，不是只装被测服务；权限来源、缓存、限流、内部契约本身就是跨服务检测目标，预设单服务环境是错的（业主 2026-11-24） |
| 8 | 压测 | **不在本任务范围**；本任务的「并发」只指并行执行用例，不承担吞吐 / 延迟 / 资源竞争验证（业主 2026-11-24） |
| 9 | 临时独立库 | **即使是临时的也不允许**（业主 2026-11-24）；**2026-11-25 再收紧：任一形态的独占库、内存库、临时库全部不允许**——迁移与库名派生改纯逻辑断言，真实执行由初始化阶段承担；仅真外部服务联调保留（连部署环境真实服务，不建库） |
| 10 | 表单设计结构变更 | 开发阶段可改数据结构；**测试与生产一律生成迁移脚本、在初始化阶段执行**，生产运行期不改表结构。测试必须走与生产相同的初始化路径，不得在用例里另走「直接执行 DDL」的捷径。**生成与执行拆开**：生成段产出脚本内容（纯逻辑，测试断言其内容），执行段只负责应用；执行由初始化阶段真实跑一次（业主 2026-11-24） |
| 11 | 用例改造边界 | 不重写用例、不逐文件迁移、不做「最小应用 + 替身」的分层重构；改的是初始化阶段、装配阶段与夹具（业主 2026-11-24） |
| 12 | T7 全量判据 | 由「全量失败 0」修订为「全量单轮取证完成 + **本轮引入的失败为 0**」；既有存量按域登记独立批次，不并入本任务（业主 2026-11-26；依据见测试记录 §6） |

## 3. 完成标准 <a id="accept"></a>

- 一轮严格按「初始化 → 装配 → 并发跑用例」执行：装配在第一个用例之前完成，一轮只装配一次、不随用例数增长；用例只作为用户访问已装配系统，不得再创建 / 替换 / 修改 app。
- 全量在**同一份共享库上单轮取证完成**：失败 / 通过数如实记录（2026-11-26 实取 157 failed / 5223 passed / 72 skipped、`database is locked` = 0；此前 `backend-test` 长期被跳过 / 超时 / 日志截断，未产出过完整清单）。不靠「再跑一轮」发现问题——用例必须在共享库上单轮成立（业主 2026-11-24 取消连跑两轮的门禁）。
- **本轮引入的失败为 0**：本轮引入项逐条修复并单文件复验；既有存量按域登记为独立批次（identity 认证域 / 平台自建壳 / 租户自愈 / 种子口径），不并入本任务验收（2026-11-26 业主拍板，判据由「失败 0」修订为本条，理由：T7 是「本轮改造是否达标」的验收，不是全量存量治理；与本节「存量清理由独立批次推进」一致）。
- 空库前提断言**新增 0**：静态护栏 P1 的存量（已登记在 `deploy/boundaries/test_premises_baseline.json`，现存 21 条 / 36 项）**只减不增**，判据是 `engkit base test-premises` 通过；存量清理由独立批次推进，不并入本任务验收（业主 2026-11-26）。
- `own_db`、`isolated_*`、`:memory:`、`tmp_path` 建库**全部清零**；唯一保留真外部服务联调用例（连部署环境的真实服务，不建库、缺配即跳过）。其余用例全部在共享库上跑通，迁移与库名派生以纯逻辑断言覆盖。
- 初始化阶段执行迁移脚本；运行期不再有任何 `ALTER TABLE` / 开运行期 DDL，表单设计类结构变更全部走「生成迁移脚本 → 初始化阶段执行」。
- 补列脚本生成段与执行段分离；生成段有断言脚本内容的用例，执行段由初始化阶段真实跑一次；测试与生产走同一条初始化路径。
- `platform-global-state` 文件锁从使用面清零。
- 静态护栏能拦住新增的空库前提断言、无理由独占库与「改 app 状态」，且有正反自测用例。
- 覆盖率门禁仍 100%，选中文件数与改造前一致（无漏测）。
