## 2. 任务内容 <a id="content"></a>

1. **ruff 配置基线单一来源**：在 engkit 仓根 `toolchain/` 目录放一份 `ruff-base.toml`（行宽 / 规则集 / 忽略项 / 目标版本口径），各仓 `pyproject.toml` 的 `[tool.ruff]` 段改用 `extend` 指向该基线，各仓只保留本仓专属项（`known-first-party` / `include` 等）。
2. **工具版本随 engkit 下发**：engkit 的 `pyproject.toml` 增可选依赖组（`devtools`），固定 `ruff` 与 `pyright` 版本；bms 与 mdm 改为 `engkit[devtools]` 的 git 源依赖，升级只改 engkit 的 rev 一处，各仓版本自动收敛。
3. **bms 取得 engkit 的方式切换**：bms 由「平级克隆 + 路径探测」改为 git 源依赖安装（与 mdm 同构），`ENGKIT_HOME` 路径探测保留为兜底；预检包装入口不变。
4. **CI 克隆步收口**：bms `.gitlab-ci.yml` 抽公共片段统一提供 engkit 克隆（基线文件外置后，ruff / pyright job 也必须有克隆），`backend-lint` / `tooling-lint` / `backend-typecheck` / `base-integrity` / `backend-test` 与前端选测片段统一引用。
5. **缺克隆即失败**：基线文件缺失时 ruff 直接报错退出（不静默回落），提示信息指向克隆指引；本地与 CI 同口径。
6. **前端工具链不在本次范围**：engkit 是 Python 包，前端（pnpm / eslint / vitest）的配置基线需另发 JS 共享包，属独立事项，本次只登记为开放项。

## 3. 完成标准 <a id="accept"></a>

`engkit/toolchain/ruff-base.toml` 成为 ruff 规则的唯一来源，bms / mdm / engkit 三仓 `[tool.ruff]` 段不再出现重复的规则集与行宽声明（只留 `extend` 与本仓专属项）；三仓 `ruff` 与 `pyright` 版本一致且由 engkit 的可选依赖组锁定；bms 与 mdm 的 `uv run ruff check` / `ruff format --check` / `pyright` 行为不回退（升级前后诊断结果一致，实测 bms 1364 个文件、mdm 108 个文件全部通过）；bms CI 相关 job 均有 engkit 克隆且命令原文不变；删掉 engkit 克隆后 ruff 明确失败并给出指引（有用例或实跑证据）；engkit 侧 `pytest` + `ruff` + `pyright` + 覆盖率门禁全绿。
