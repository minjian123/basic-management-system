## 2. 任务内容 <a id="content"></a>

1. **规则与判定分离**：把 8 个基座校验器（`check-base` / `check-backend-base` / `check-service-boundaries` / `check-bare-collections` / `check-system-fields` / `check-prototype-review` / `check-env-example` / `boundary_metrics`，含 `check-status`）的**规则数据**（标识符段 / 表前缀 / 业务码与错误码段 / 模块与边界清单 / 系统字段清单 / 原型目录 / 环境模板键位 / 集合形态白名单）抽到各仓 `engkit.toml` 的 `[rules.*]` 段，判定逻辑留在实现侧。
2. **迁入 engkit**：校验器以子命令或预检步骤两种形态提供，与 `[[preflight.steps]]` 的声明式口径一致；**包内不得出现任何仓名 / 目录 / 包名字面**（沿用 `test_guards.py` 的机器断言）。
3. **bms 侧零回退**：原脚本改薄包装，入口名 / 参数 / 输出 / 退出码与 CI 命令全部不变；预检步骤清单仍由 `engkit.toml` 声明（不在包内硬编码）。
4. **各仓规则对齐**：mdm 等产品仓登记本仓规则段并实跑通过；未登记项按「缺配置即报错」处理，不靠缺省值掩盖；biz / cw 随各自窗口按接入说明执行。
5. **存量缺口闭环**：`check-base` → 护栏用例映射的存量缺口（`13_05` 边界与开放项第 2 条）一并补齐，映射表覆盖目录内全部脚本。

## 3. 完成标准 <a id="accept"></a>

8 个校验器可在 engkit 内以配置驱动运行且包内无仓名字面（机器断言）；bms 侧既有入口与 CI 命令行为零回退；mdm 至少接入与自身相关的校验并实跑通过；规则数据全部落各仓配置、脚本内不再出现仓专属字面；`check-base` 映射缺口补齐且映射表覆盖目录内全部脚本；engkit 侧 `pytest` + `ruff` + `pyright` + 覆盖率门禁全绿。
