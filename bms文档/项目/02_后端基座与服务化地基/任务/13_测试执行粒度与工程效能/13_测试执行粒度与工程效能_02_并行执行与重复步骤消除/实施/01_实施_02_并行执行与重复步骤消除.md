## 2. 实施过程 <a id="process"></a>

### 2.1 并行档位（`scripts/tools/preflight/parallel_jobs.py`，新增）

`--jobs auto|N|off` → `-n auto` / `-n N` / 空；预检与执行器共用，非法值抛 `ValueError`（消息给合法取值）。
`check-preflight.py` 解析一次后：定向档透传给 `run-selected.py --jobs`；`--full` 档的聚合全量与 10 个工程级范围
两条 pytest 调用各自追加；日志打印 `[preflight] 并行 -n auto` / `串行（--jobs off）`。

### 2.2 worker 级 SQLite 库隔离（`bms_core/testing`）

| 文件 | 改动 |
| --- | --- |
| `fixtures.py` | 新增 `configure_sqlite_basetemp()` / `worker_sqlite_dir()`；`isolate_settings` 在清 `BMS_` 后按 worker 注入 `BMS_DATABASE__SQLITE_DIR=<basetemp>/sqlite-<worker>`（串行不注入） |
| `plugin.py` | `pytest_configure` 注入 basetemp，并**重载 `fixtures`**（并行下模块顶层行落入覆盖率统计） |
| `tests/core/test_config.py` | 2 处 `sqlite_dir` 默认值断言先 `delenv("BMS_DATABASE__SQLITE_DIR")`（语义仍是配置默认值） |

根因与验证：未隔离时全量并行 67 failed（identity 为主）；按文件分发仍有 35 failed；identity 绑单 worker 全绿但
单服务串行 82s。隔离后全量并行 **0 failed**（详见 §2.5 实测）。

### 2.3 自测按需（`check-preflight.py`）

- `_SelfTest(label, script, deps)` + `_SELF_TESTS`（7 项）；`_self_test_selected()` 按「脚本自身或依赖前缀」判定；
- `_run_self_tests(force_all=fast or full)`：缺省按需、`--fast` / `--full` 全跑、变更不可判定（`_git_changes` 两条 git 命令均失败）时全跑；
- 跳过逐条打印：`跳过（变更未触及 <脚本> 及其依赖）`；
- 原散落在 `main` 的 7 段自测调用合并为一处（本体检查顺序不变）。

### 2.4 CI 重复面（`.gitlab-ci.yml` + `backend-service.yml`）

| 改动 | 说明 |
| --- | --- |
| `test_selection.py` | 新增 `changed_services()` 与 `--format changed-services`（只认 `backend/services/<服务>/**` 直接变更，不做闭包） |
| `backend-service.yml` 的 `service-test` | 清理测试库之前判定：有直接变更 ⇒ 照常；无（仅 `uv.lock` / `Dockerfile` / `libs` 等共享底座）⇒ 打印原因并 `exit 0`，`build` / `release` 照常；基准不可解析或判定失败 ⇒ 保守执行 |
| `.gitlab-ci.yml` 的 `backend-test` | `run-selected.py` 追加 `--jobs auto`；rules 与归档不变 |

### 2.5 预算标定与覆盖率排除

| 项 | 改动 |
| --- | --- |
| 定向档预算 | 120s / 180s → **300s / 420s** |
| 全量档预算 | 600s / 1200s → **900s / 1800s** |
| 预算断言 | `test_preflight_scoping_guard.py`（Kiwi 2311）同步新值，并加「`--jobs auto` 不是仓库根」断言 |
| 覆盖率目标排除 | `run-selected.py` 的 `_COVERAGE_EXCLUDED_MODULES = ("bms_core.testing.plugin",)`，命中即从 `--cov` 目标中剔除并打印原因（决策 14） |

### 2.6 覆盖率采集前置（决策 15，替代决策 14 的排除）

| 文件 | 改动 |
| --- | --- |
| `backend/bms_testing_plugin.py`（新增） | addopts 的 `-p` 入口：模块顶层**只依赖标准库与 coverage**，按 `BMS_COVERAGE_DATA` / `BMS_COVERAGE_SOURCE` 启动采集，再在 `pytest_configure` 注册 `bms_core.testing.plugin`；`pytest_sessionfinish` + `atexit` 双保险落盘（后缀用 `os.getpid()`） |
| `backend/pyproject.toml` | `addopts` 由 `-p bms_core.testing.plugin` 改为 `-p bms_testing_plugin` |
| `scripts/tools/preflight/coverage_gate.py`（新增） | 合并 `<data-file>.*` → 导出 JSON → 按模块判定「缺行 0 + 缺分支 0」；输出 `[coverage] files=… missing_lines=… partial_branches=… percent=…` |
| `run-selected.py` | 每轮：清理旧数据 → pytest（env 注入采集）→ gate 判定 → 扩圈；删除 `--cov` 拼接与插件入口排除 |
| `check-preflight.py` | `--full`：env 注入采集 → 聚合全量（并行）→ gate 判定（10 包全部文件） |
| `backend-service.yml` | `service-test`：env 采集 + `coverage_gate.py --module bms_$SERVICE`；`coverage:` 正则改 `[coverage].*percent=` |
| `.gitlab-ci.yml` | `backend-test` 的 `coverage:` 正则同步改为 `[coverage].*percent=` |
| `bms_core/testing/plugin.py` | 移除 configure 期的 `fixtures` 重载（采集前置后不再需要） |
| `platform/tests/permission/test_field_permission.py` | 补「未登记字段权限工厂 ⇒ 返回 None」分支用例（全量复验时唯一缺口） |

**效果**：`bms_core.testing.fixtures` 与 `bms_core.testing.plugin` 均 100%（排除逻辑删除）；全仓 10 包
**628 文件 / 0 缺行 / 0 缺分支 / 100%**（含并行 `-n auto`，25 份 worker 数据全部合并）。

## 4. 验证与结论 <a id="verify"></a>

### 4.1 静态与基座门禁

| 命令 | 结论 |
| --- | --- |
| `uv run ruff check .`（改动文件范围） | 通过 |
| `uv run ruff format --check`（改动文件范围） | 通过（24 文件） |
| `uv run pyright`（后端全量） | **0 errors** |
| `python scripts/tools/preflight/check-preflight.py --self-test` | 12 项全通过 |
| `python scripts/tools/preflight/check-preflight.py --fast` | 全绿（40.8s；自测全跑 7 项） |
| `python scripts/tools/preflight/check-preflight.py`（定向档） | **全绿（100.5s）**：退化全量 + 并行 402 文件 + `[coverage] files=2 missing_lines=0 partial_branches=0` |
| `python scripts/tools/preflight/check-preflight.py --full`（采集前置后） | **全绿（194.8s）**：`[coverage] files=628 missing_lines=0 partial_branches=0 percent=100.00`；10 个工程级范围与全部门禁通过；预算 900/1800 未触发 |

### 4.2 并行与串行一致性（后端全量）

| 模式 | 结果 | 耗时 |
| --- | --- | --- |
| 串行 | 2960 passed / 57 skipped | 289.04s |
| `-n auto` 第 1 轮 | 2960 passed / 57 skipped | 48.55s |
| `-n auto` 第 2 轮 | 2960 passed / 57 skipped | 48.64s |
| `-n auto` 第 3 轮 | 2960 passed / 57 skipped | 48.49s |
| `-n auto`（采集前置 + 补 2 条用例后） | 2962 passed / 57 skipped | 49.40s |

加速比 **≈5.9x**；各轮结果与串行完全一致（含用例数 / 跳过数）。

### 4.3 定向档对比

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| 单次定向档（含 402 文件退化全量） | 单步 120s 触发、总体 156.6s 中止 | **100.5s 全绿**（并行测试段约 50s，含采集合并） |
| 自测步 | 7 项全跑 | 2 项跳过（未触及纯标准库脚本）、5 项执行（依赖基座） |
| `--fast` | 35.8s | 40.8s（自测仍全跑，日志增档位行） |

### 4.4 覆盖率（采集前置后）

| 项 | 结果 |
| --- | --- |
| `bms_core.testing.fixtures` | 行 + 分支 **100%**（不再需要重载） |
| `bms_core.testing.plugin` | 行 **100%**（排除逻辑已删除，决策 14 撤销） |
| 全仓 10 包 `--full`（并行 `-n auto`） | **`files=628 missing_lines=0 partial_branches=0 percent=100.00`** |
| 全仓 10 包对照（`coverage run -m pytest` 串行） | 29249 行 / 0 缺失 / 5056 分支 / 0 未覆盖 = 100%（定位采集缺口时的证据） |
| 定向档门禁（改动模块范围） | `files=2 missing_lines=0 partial_branches=0 percent=100.00` |

### 4.5 结论

- 并行在 worker 级库隔离后与串行结果一致（三轮复核），全量耗时降到约 1/6；
- 自测按需、重复面判定、预算标定均按设计生效且都有显式输出；
- 全仓覆盖率由 93.36% 修复至 **100%**（行 + 分支，并行并集），修复手段为「采集前置」而非补 2261 行用例；
- `--full` 由「聚合全量失败」转为 **全绿（194.8s）**。
