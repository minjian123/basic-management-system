## 1. 域说明 <a id="intro"></a>

本域对应阶段二「测试执行粒度与工程效能」：把《[测试规范](../../../../规范/测试规范.md)》§2.1 第 2 条「按变更范围只跑受影响的部分」从**服务级**下沉到**模块级 / 包级**，并补齐并行执行，消除「为跑一个点而跑全量」的重复消耗。依据《测试规范》§2.1（被测物与执行范围，强制）与 §5（执行方式），实测底稿见《[测试执行粒度与影响分析评估](../../../../资料/知识档案/工程化与质量/测试执行粒度与影响分析评估.md)》；对应需求域十三（13-1 ~ 13-7）。

**问题实测**：改 `backend/libs/bms_core/` 任一文件 → 整个 `libs/bms_core/tests`（227 文件 / 1476 用例 / 63.4s）；改 `backend/services/platform/` 任一文件 → 整个 `services/platform/tests`（85 文件 / 607 用例 / 170.8s）；同一批 2327 用例串行 282.7s，`-n 4` 仅 73.4s（3.85x，且 `pytest-xdist` 已在依赖内却未使用）。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：`13_01` 是 `13_02` / `13_03` 的前置（选测器是并行档与护栏的作用对象）；`13_03` 收口规范与护栏，须在 `13_01` / `13_02` 落地后执行；`13_05`（跨仓工具包）以 `13_01` / `13_02` / `13_03` 的现有实现为**迁移对象**，须在其后执行（`13_04` 可选复用）；`13_07`（工具链基线与版本统一）以 `13_05` 建成的 engkit 仓与接入机制为前提。
- **约束**：覆盖率门禁口径**不降级**（行 + 分支 100%），细粒度选测须以「覆盖率扩圈」机制保证不漏测；预检与 CI 必须共用同一份推导实现，禁止两侧各自维护规则；`13_05` 迁入后该「单一来源」扩展到**跨仓**——包内不得硬编码任何仓名 / 目录，各仓只放配置，禁止再出现第二套推导或护栏实现；`13_07` 把该原则延伸到**工具链配置与版本**，各仓不得再复制 ruff 规则段或各自声明 ruff / pyright 版本。
- **风险**：选测漏测风险（跨目录隐式引用、动态导入、字符串化导入）以 AST 图 + 扩圈循环 + 退化路径兜底；并行档的用例稳定性（数据隔离、共享夹具、SQLite 文件库冲突）须专项验证；`13_05` 属**跨仓基础件**改动（bms / mdm / biz / cw 均消费），迁移期须保证 bms 既有入口与 CI 命令**行为零回退**，并逐个仓库验证接入；`13_07` 使 engkit 克隆成为**所有 lint / typecheck 的前置依赖**，本地与 CI 缺克隆即失败（按「必选仓」口径处理，不做仓内副本兜底）。
