## 2. 任务内容 <a id="content"></a>

1. 建表路径切换：启动期按「服务 × 数据源」表集**幂等自动建表**并放开到 SQLite / MySQL / PostgreSQL / 达梦（方言无关），同时新建 **ops 显式建表入口**（运维 / CI / 首次接入），两处共用同一表集派生点。
2. 迁移脚本清空：删除 `backend/alembic/versions/**` 全部历史迁移脚本与只服务于它们的测试；**迁移机制保留**（分链注册、配置段、版本目录、方言补丁、库级编排），将来需 schema 演进时按新基线重建脚本。
3. 编排改「建表先行」：数据引导（bootstrap）与一键部署（`release.py deploy`）的迁移步骤改建表步骤；三库集成流程（`ops.test_db` 与 CI 集成 job）由「建库 → 迁移」改「建库 → 建表」（命令名保留、语义内改）。
4. 前置数据步骤机制退役：`PREREQUISITE_STEPS` 登记与批量迁移的提示行随脚本一并删除（无脚本即无前置步骤）。
5. 测试与覆盖率：删除「迁移专属」用例、把「仅以迁移当建表夹具」的用例改建表夹具、保留机制用例；机制代码（链注册 / 建表 / 库级编排）的 100% 覆盖率由**临时链脚本自检**承接（不依赖仓库内脚本）。
6. 口径与文档回写：规范 / 架构节点 / 数据库设计 / 部署说明 / 后端 README 与 `alembic/README.md` 同步「脚本清空、建表走启动期 + ops、开发库删库重建」；移除「旧口径存量数据」排障条目。
7. 现场全量重建：开发服务器 drop 全部 `bms_*` 业务库 → 建库 → 建表 → 种子 → 全服务部署与健康门禁（缺陷 #103 的处置口径随本任务改写）。

## 3. 完成标准 <a id="accept"></a>

启动期自动建表对四库方言生效且幂等（重复启动不改动既有对象）；ops 建表入口可单独调用并对缺库 / 缺表幂等补齐；`alembic/versions` 无脚本而分链机制组件（链注册 / 配置段 / 库级编排）仍可用；三库集成门禁由建表路径跑通；开发库删库重建后各服务 `healthy`、`/readyz` 200、门禁通过；`pytest` / `ruff` / `pyright` 与覆盖率门禁（行 + 分支 100%）与完整预检全绿。
