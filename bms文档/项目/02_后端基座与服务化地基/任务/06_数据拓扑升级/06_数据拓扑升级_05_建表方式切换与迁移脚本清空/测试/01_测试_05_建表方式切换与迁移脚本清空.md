## 5. 现场与 CI 回归结论 <a id="pending"></a>

- **现场全量重建与回归（已完成，2026-10-18）**：20 个 `bms_*` 业务库 `mysqldump` 留痕 → drop（保留基础设施库）→ `bootstrap`（账号授权 → 建库 → **建表** → 种子）+ 手工补齐 `seed_module` / `seed_tables` / `seed_tenant` → `deploy --all --tag a8b5dc73`。结果：**27 个 `bms_*` 库 / 130 张表**（`bms_platform_demo` 13、`bms_platform_acme` 13）/ `sys_tenant` 2 行；**9 服务全部 `healthy` + `/readyz` 200（catalog ok）+ 网关可达**，台账 9 服务 `current.tag=a8b5dc73`；`admin@demo` 登录 200、用户态读目录清单/快照 200、无凭证/伪造令牌 401。
- **CI 侧实证（已完成）**：流水线 **#991** 先因 `core-check` 前端用例超时（flaky，本地复跑 14 passed）失败 → **重跑 core-check 通过** → 父流水线继续、**9 个服务子流水线全部 success**（镜像构建 / 推送 `a8b5dc73`）；`backend-modules` 建表路径与集成流程改动随子流水线一并验证。
- **三库真库建表（MySQL / PostgreSQL / 达梦）**：经 CI 三库集成 job 按需触发（`ops/test_db` 的 `migrate` 段现为建表语义）；**达梦真库建表未实测**（开放项，结论回写《方言特性》达梦文档）。
- **现场暴露的两处旧口径残留**：`ops.seed_dict` 残留（已在 `release.py` 删除）与部署租户集合不一致（已对齐 `demo,acme`），处置见实施记录 §4 问题 #9 / #10。
- **缺陷 #103**：按「删库重建」新口径重记并已**关闭**（关闭评论含 dump / drop / 重建 / 门禁 / 登录全链证据）。
