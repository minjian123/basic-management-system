## 3. 演练记录 <a id="drill"></a>

### 3.1 SQLite 多服务多库全量演练（已执行）

前置：备份既有开发库（`bms_*.db` → `/tmp/bms_devdb_backup`，41 个文件）后按分链重建。

```bash
cd backend
uv run python -m ops.provision_tenant --code demo --code acme --migrate   # 建库 + 开通即迁移
uv run python -m ops.seed_tables                                          # 归属登记种子
uv run python -m ops.check_tables --url sqlite+aiosqlite:///./bms_platform.db
uv run python -m ops.check_budget --service platform
```

| 观测项 | 结果 |
| --- | --- |
| 编排目标 | 共 **27** 个目标（平台服务库 9、服务租户库 18）；归档库 1（`--target all` 时的独立目标） |
| 首跑 | 成功 **6**、跳过 **21**、失败 **0**（成功 = `platform:platform` 1 + `platform:tenant` 2 + `tenant:platform` 1 + `tenant:tenant` 2） |
| 重复执行（幂等） | 成功 **0**、跳过 **27**、失败 **0** |
| 无脚本链 | 其余 7 个服务（identity / org / file / notification / search / ai / report）的两条链均输出「无脚本（跳过）」 |
| 迁移后版本 | `bms_platform.db` = `0005_sys_table_ownership`（7 表）；`bms_platform_{demo,acme}.db` = `0003_sys_outbox_event_version`（11 表）；`bms_tenant.db` = `0003_sys_outbox_event_version`（5 表）；`bms_tenant_{demo,acme}.db` = `0002_sys_outbox_event_version`（4 表）；其余服务库 0 表 |
| 归属登记 | 种子新增 39 行 / 更新 0；接库对账通过（清单 39 项 + 模型表对账 + 脚本表集 + 接库） |
| 连接预算 | 按服务 × 库类别逐行输出，均在预算内（`max_connections = 0` = 不校验） |

结论：分链形态、表集派生、批量编排、开通即迁移、幂等与无脚本跳过、归属登记种子 / 对账、库数量统计与按服务预算核对**端到端可用**；开发库与真库表集口径一致（无脚本链两边都跳过）。

### 3.2 三库真库演练（已执行，2026-09-23，主机 192.168.0.107）

流程按 `ops/test_db.py` 固定四步：**建库 → 分链迁移 → 集成用例 → 删库清理**（每方言平台 / 租户两对象）。

```bash
cd backend && set -a && . ../deploy/.env && set +a
export BMS_TEST_DB_URL=<该方言平台对象>  BMS_TEST_TENANT_DB_URL=<该方言租户对象>
uv run python -m ops.test_db create  --engine <方言> --execute
uv run python -m ops.test_db migrate --engine <方言> --execute
uv run python -m ops.seed_tables  --url "$BMS_TEST_DB_URL" [--schema <达梦模式>]
uv run python -m ops.check_tables --url "$BMS_TEST_DB_URL" [--schema <达梦模式>]
uv run pytest libs/bms_core/tests/integration -k <方言>
uv run python -m ops.test_db drop --engine <方言> --execute
```

| 方言 | 对象（字符集 / 隔离单位） | 建库 | 分链迁移（平台 / 租户） | 归属登记种子 + 接库对账 | 集成用例 | 清理 |
| --- | --- | --- | --- | --- | --- | --- |
| MySQL 8.4 | `bms_test_mysql` / `bms_test_mysql_t1`（`utf8mb4` 库级） | 新建 | `0005_sys_table_ownership` / `0003_sys_outbox_event_version` | 39 行新增、重跑 0/0（幂等）；对账通过 | 9 passed | 已删 |
| PostgreSQL 16 | `bms_test_pg` / `bms_test_pg_t1`（库级） | 新建 | `0005_sys_table_ownership` / `0003_sys_outbox_event_version` | 39 行新增、对账通过 | 9 passed | 已删 |
| 达梦 DM8 | `BMS_TEST_DM` / `BMS_TEST_DM_T1`（**模式**级） | 新建 | `0005_sys_table_ownership` / `0003_sys_outbox_event_version` | 39 行新增、对账通过 | 13 passed | 已删 |

**演练发现并当场修复的问题**（真库实测，SQLite 无法暴露）：

1. **集成用例未随分链更新**（MySQL / PG 首跑 2 例红）：`resolve_chain("platform")` 在分链后已非法 → `test_three_db_integration.py` 改按 `platform:platform` / `platform:tenant` 取链；`test_tenant_isolation` 的平台侧表改为 `sys_module`（`sys_tenant` 已随分链归 `tenant` 服务的平台库）。修复前 CI `verify/db` 档三者会同红。
2. **达梦不支持 `ALTER COLUMN ... DROP NOT NULL`**：`platform:platform/0002` 的 `alter_column(errcode_segment, nullable=True)` 在 DM8 报 `-2007 语法分析出错`（冗余改写——`errcode_segment` 可空已在链首 `0001` 直接建为可空，模型口径一致）。处置：链首直接建为可空 + 移除 0002 的冗余 `alter_column`（升级 / 回退两侧），保留 `sys_tenant.db_key` 的 `batch_alter_table`（其可空变更对已在库真实有效，四库兼容）；同时修正因移除该改写而暴露的链内列可空口径漂移（`test_alembic_drift`）。
3. **`ops/seed_tables.py` / `ops/check_tables.py` 缺同步方言路径**：按 `--url` 直连时对达梦用异步驱动报 `requires an async driver`。处置：新增同步分支（`db/sync.is_sync_only_url` + `db/migration.apply_session_schema` + `AUTOCOMMIT` 连接），两者补 `--schema` 参数（达梦模式）。
4. **达梦测试模式残留旧链对象**：`BMS_TEST_DM` 模式内已有分链前的 `ALEMBIC_VERSION`（无对应表）→ Alembic `CREATE TABLE alembic_version` 报 `-2124 对象已存在`。处置：按「库重建口径」`drop` → `create` → `migrate` 后通过（REPORT 中已登记该口径）。
5. **达梦凭据口径**：`DM8_TEST_PASSWORD` 与实例实际 SYSDBA 密码不符（报 `-2501`），改用 `DM8_SYSDBA_PASSWORD`；`test_db.py` 的达梦路径本就以 SYSDBA 连接、无独立测试账号（与文档一致），故仅属**演练凭据取用**问题，未改代码，登记为 CI 变量口径提示。

结论：分链形态在 **MySQL / PostgreSQL / 达梦** 三库真库均「建库 → 迁移 → 种子 + 对账 → 集成用例 → 清理」闭环通过；达梦模式级隔离、大小写折叠与 `NUMBER(1)` 布尔承载等差异均由集成用例覆盖（13 例）。
