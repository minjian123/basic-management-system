## 2. 任务内容 <a id="content"></a>

1. **表归属产品注入与合并视图**：`TABLE_OWNERSHIP` 由「平台侧常量」升为「注册表 + 产品注入合并」——新增注册 / 合并入口（平台侧登记行与产品自报注入行按「同 `table_name` 同值去重、异值即拒」处理）；`chain_tables` / `chain_metadata` / 开发库自动建表 / 归属校验一律取合并视图；产品侧经应用装配钩子与 ops / alembic 入口在装载时注册本产品表记录。
2. **服务包模型名前缀参数化**：链的服务模型包名前缀由配置 `[app].package_prefix` 派生（平台默认 `bms`，产品配自有前缀）；「服务已启用但服务包缺失」快速失败（免静默空清单导致迁移与自动建表不建表）。
3. **产品业务码 / 动作码种子**：产品管理面权限码按产品域登记（业务码 + 域级 / 专属动作码），经平台种子写入 `sys_business` / `sys_action`。
4. **规范与清单回写**：《[数据库开发规范](../../../../../规范/数据库开发规范.md)》「表与字段口径」、《[数据库设计 · 数据规范](../../../../../设计/数据库设计/02_数据库设计_数据规范.md)》「公共字段」、《[后端开发规范](../../../../../规范/后端开发规范.md)》「模型模块按服务声明」与《[后端基类清单](../../../../../后端基类清单.md)》「表归属登记 / 服务应用装配基座」同步回写。

## 3. 完成标准 <a id="accept"></a>

产品可自持登记表归属并进链（迁移与开发库自动建表生效）；产品服务模型按配置前缀解析、服务包缺失即快速失败；产品业务码 / 动作码种子可用；规范与清单回写完成；`pytest` / `ruff` / `pyright` / 本地预检全绿。
