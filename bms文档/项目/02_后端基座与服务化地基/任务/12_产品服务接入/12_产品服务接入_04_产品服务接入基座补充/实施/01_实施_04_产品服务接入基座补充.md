## 3. 实施过程 <a id="process"></a>

1. **上下文与决策**：按《AI开发规范》读 bms《后端开发规范》《数据库开发规范》《数据库设计 · 数据规范》《后端基类清单》《架构设计 · 模块注册》与 12_01 / 12_02 / 12_03 详设与实施记录，并核对基座现状（`services/table_registry.py` / `application.py` / `db/migration.py` / `core/config.py` / `ops/check_tables.py` / `ops/seed_tables.py` / `ops/seed_menu.py`、`boundary/directory.py`）。
   - **待拍板事项逐项确认**（question 工具，共 16 项）：表归属落点（基座新增注入通道）、服务包模型解析（配置驱动包名前缀）、关联表主键（规范向实现收口为雪花 `id`）、审计接入（接基座 `AuditCapturer` 占位）、事件契约时点（随 mdm `01-2` 登记）、权限码与种子（新增 `org` 业务码 + 5 动作码）、契约基线（随 mdm `01-3`）、横切能力范围、覆盖率口径、bms 侧登记方案（新增需求 12-4 + 任务 12_04）与台账回写。
2. **登记**：需求域十二顺延新增需求 12-4（需求总览同步：总清单 + 域文档地图 + 合计）；新建子任务 `12_04`（父任务 `12_产品服务接入` 子任务清单同步）；阶段二计划两表与统计行回写（父任务重开为部分完成）。
3. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_阶段二12-04_产品服务接入基座补充.json`（经 `register_cases.py` 走 Kiwi 容器 Django shell），平台回读编号 **2254**；用例代码以 `@pytest.mark.kiwi_id(2254)` 标注。
4. **表归属注入通道**（`bms_core/services/table_registry.py`）：新增 `merge_table_records()`（同 `table_name` 同值去重、异值即拒）、`register_table_records()`（装载期登记、同值重复无操作）、`injected_table_records()` / `reset_table_records()`（读取与测试隔离）、`table_ownership_view()`（合并视图）；`table_owner` / `table_record` / `owned_tables_for` / `infrastructure_tables` / `chain_tables` / `table_names` / `registered_services` 与 `TableOwnershipRegistry` 缺省清单一律改读合并视图。


**关键机制实测**（可复现）：

- 注入 2 条产品表记录后 `table_ownership_view()` 条目数 = 平台清单 + 2，`chain_tables("org", "tenant")` 含注入表 + 基础设施三表，`table_owner("org_dept") == "org"`；`reset_table_records()` 后回到平台清单。
- 同 `table_name` **同值**注入 → 去重（条目数不变）且 `TableOwnershipRegistry().validate() == []`；**异值**注入 → 报「表名重复登记」（fail-closed）。
- 装配钩子：不覆写 `table_records()` 的工厂视图严格等于 `TABLE_OWNERSHIP`；覆写并注入后视图含注入表且注入表进链。
- 包名前缀：默认 `bms` → `service_package("platform") == "bms_platform"`；配 `mdm` → `service_package("org") == "mdm_org"`；包缺失时严格入口抛 `ConfigError`（含 `bms_zzz_ghost.models` 与 `package_prefix` 提示）。
- 种子：`BUSINESS_SEEDS` 含 `org`、`ACTION_SEEDS` 含 `org` 五码，且业务码 / 「业务码 + 动作码」幂等键均唯一。
