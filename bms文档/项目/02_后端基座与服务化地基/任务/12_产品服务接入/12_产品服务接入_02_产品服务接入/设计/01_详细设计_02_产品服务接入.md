## 1. 设计目标与范围 <a id="goal"></a>

承接需求 12-2：落**产品服务接入机制与接入骨架**——平台侧提供服务目录与契约 / 版本登记、认证（OIDC）、开放接口（`/api/open`）、事件接入、网关路由与独立库对接，并给出接入验收判据。**真实产品（mdm）联调随产品接入推进**（本期为「机制 + 骨架」）。

本期范围（七项）：

1. **服务目录与契约 / 版本登记**：产品服务经 `SERVICE_CATALOG` 登记（服务标识 / 注册要素 / 契约版本），**产品公开契约由产品侧自持**（产品仓库生成 OpenAPI 快照 + 基线并自跑 oasdiff 门禁）；bms 侧只做「产品自报契约版本 ↔ 平台登记值」**主版本兼容校验**（复用既有口径，见 §3）。
2. **认证接入**：产品服务经平台 OIDC 校验（用户 JWT `aud=api` / 服务 JWT `aud=service`，平台 JWKS）；服务间经服务身份（`require_service`）。**不新增认证代码**（复用既有基座，见 §8）。
3. **开放接口**：`sys_client` 注册要素（client 凭据 / scope / IP 白名单 / 调用日志）；本期落**开放接口 scope 登记与校验**（`sys_client` 注册 / 更新时校验 scope 属登记集合），真实 `/api/open` 令牌签发与运行期 scope 校验归阶段十（见 §6）。
4. **事件接入**：产品注册事件域（`SERVICE_CATALOG.event_domain`，随产品接入补登），经平台事件总线发布 / 订阅；本期落**产品事件契约登记扩展点**与快照 CLI 注入（见 §7）。
5. **网关路由**：产品服务经平台网关以**产品命名空间**暴露——新增「域段 → 服务」显式映射登记，网关按产品聚合生成产品级路由 `/api/{product_key}/v1/{domain}/...`；平台服务仍 `/api/{service_key}/v1/...`（见 §5）；每服务独立库（× 每租户）口径不变。
6. **接入骨架**：`sys_client` 注册要素 / 最小 scope 集合 / 必供项（健康检查 / 审计 / 事件订阅）/ 平台版本兼容承诺清单 + **接入验收五项判据**（复用既有门禁，见 §9）。
7. **12_01 遗留归口**：产品档案 HTTP 只读出口——`GET /api/v1/products`（清单分页 + 状态筛选）与 `GET /api/v1/products/{product_key}`（明细）（见 §4）。

**不在本期**：真实产品（mdm）完整联调（随产品接入，跨仓）；`/api/open` 真实令牌签发 / 撤销 / 调用审计（归阶段十开放接口管理）；前端多包合并（R4.3）；共享基座产品服务装配（归 12_03）；`mdm` 各域模块行与产品级路由映射的登记（先注册后建表，随产品接入补登，见 §12）。

## 4. 产品档案只读出口（12_01 遗留） <a id="products-api"></a>

### 4.1 路由与字段

- **路由模块**：`bms_platform/api/products.py`，`BaseRouter(key="products", prefix="/products", tags=["product"], dependencies=[Depends(require_auth)])`；登记进 `bms_platform/api/router.py`。
- **清单**：`GET /api/v1/products`——参数 `page` / `size` / `order_by` / `order`（`page_query` 依赖工厂）+ `status` 筛选；响应 `ApiResponse.ok(BasePageResponse[ProductResponse])`，`data = {list, total, page, size}`。
- **明细**：`GET /api/v1/products/{product_key}`——按 `product_key` 精确匹配（软删行视为未登记）；未登记抛 `NotFoundError`（10002 / 404 + 统一响应体）。
- **响应契约**：`ProductResponse`（`bms_core/schemas/product.py`，对称既有 `bms_core/schemas/module.py`）字段集固定 4 项——`product_key` / `name` / `frontend_package_source` / `status`；**不含密钥 / 敏感项**，字段集以护栏用例严格断言（不多不少）。
- **鉴权**：路由级 `require_auth` 登录态占位（真实权限码随 RBAC 阶段回补，调用面零改动）。
- **数据源**：平台库 `sys_product`，经 `get_platform_read_db`（强制平台库 + 只读；请求带租户上下文时仍读平台库）。
- **排序白名单**：`sys_product` 除主键外无单列索引（`product_key` 为复合唯一），故 `sortable_fields = {"id"}`；白名单外排序请求项忽略、回落 `id` 升序。

### 4.2 仓储扩展

`ProductRepository`（`bms_platform/repositories/product_repository.py`）增 `page_products(query, *, status=None) -> (records, total)`（筛选 + 排序白名单 + 当前页 + 筛选后总数，筛选条件与 `list_products` 收敛同源，防口径漂移）；既有 `list_products` / `get_by_key` 保持（种子校验与既有用例消费）。只读边界不变（无写方法、无会话写调用）。

### 4.3 边界与失败分支

| 场景 | 处置 |
| --- | --- |
| 未播种空库 | 清单 `list=[]` / `total=0`；明细 404（视为未登记），不报错 |
| 未登记 `product_key` | `NotFoundError`（10002 / 404 + 统一响应体） |
| 软删登记行 | 清单不可见、明细视为未登记（仓储软删过滤口径） |
| `page` 超上限 / `size` 越界 / 非整数 | `BasePageQuery` 校验失败 → 参数错误（10001） |
| 路径对清单发 POST / PUT / DELETE | 405（无写路由） |
| 平台库不可读 | 全局处理器转 `DatabaseUnavailableError`（10006 / 503）或 500（与 `modules` 同口径） |

## 5. 产品级路由与命名空间 <a id="gateway"></a>

### 5.1 映射登记与校验

产品对外命名空间为**产品级**（`/api/mdm/v1/org/users` 形态），与平台服务的服务级命名空间（`/api/{service_key}/v1/...`）**不混**。域段经**显式映射登记**与上游服务解耦：

```text
bms_core/services/module_registry.py
├── PLATFORM_MODULES / SERVICE_CATALOG / PRODUCT_CATALOG     # 既有，不改
├── ProductRouteRecord(product_key, domain, service_key, description)   # 新：产品级路由记录
├── PRODUCT_ROUTES: tuple[ProductRouteRecord, ...] = ()               # 新：产品级路由映射登记（本期空清单）
└── validate_product_routes(routes, modules, products)                # 新：离线 / 接库共用的映射校验
```

`ProductRouteRecord` 字段：

| 字段 | 说明 |
| --- | --- |
| `product_key` | 归属产品标识（须在 `PRODUCT_CATALOG` 登记） |
| `domain` | 外部域段（产品命名空间首段，如 `org`；全局唯一，小写标识符） |
| `service_key` | 上游服务标识（须在 `SERVICE_CATALOG` 登记为**产品分组**行，且其 `product_key` 与本行一致） |
| `description` | 说明（中文） |

校验规则（`validate_product_routes`，离线与接库共用同一实现）：

1. `domain` 标识符格式合法、**全局唯一**；`service_key` **全局唯一**（一个服务只挂一个域段）；
2. `product_key` 须在 `PRODUCT_CATALOG` 登记（产品先注册后接入）；
3. `service_key` 须在 `SERVICE_CATALOG` 登记、`service_group = product`，且该行 `product_key` **与本记录一致**（**防映射与服务目录漂移的关键断言**）；
4. 目标服务行 `status = disabled` 即拒（`planned` 允许——「先注册后建表」，网关不生成路由；模块级注销态在 `sys_module` 取值中尚未建模，见 §13.2 对齐记录 10）。

校验入口：随 `ModuleRegistry.validate()` 一并执行——**离线**对 `SERVICE_CATALOG` / `PRODUCT_CATALOG` 清单、**接库**对库中 `sys_module` / `sys_product` 未软删行（`validate_catalog` 同路径），启动校验与 CI `ops.check_modules` 自动覆盖；冲突即退出码 1。

### 5.2 网关生成

`gateway_catalog.py` 增产品级路由生成（`render_product_routes()`）：对每条 `PRODUCT_ROUTES` 记录，**仅当目标服务登记行 `status = enabled`** 时生成路由——

| 项 | 取值 |
| --- | --- |
| 路由 id | `route-{product_key}-{domain}` |
| `uris` | `/api/{product_key}/v1/{domain}`、`/api/{product_key}/v1/{domain}/*` |
| `upstream_id` | 该记录的 `service_key`（上游由既有 `render_upstreams()` 按启用服务生成） |
| `proxy-rewrite.regex_uri` | `^/api/{product_key}/v1(.*)$` → `/api/v1$1`（外部产品前缀剥离为服务内统一前缀；域段保留） |
| 插件 | 与平台服务路由同口径（`forward-auth` + `limit-count` + `prometheus` + 灰度 / 路由钩子按 `service_key` 合并） |

`render_apisix_config()` 的 `routes` 段 = 平台服务路由 + 认证敏感路由 + **产品级路由**。产品路由与平台路由的插件口径一致，故认证与限流复用，无需新增插件。

### 5.3 边界与失败分支

| 场景 | 处置 |
| --- | --- |
| `PRODUCT_ROUTES` 为空清单（本期） | 网关生成件与现状完全一致 → 零漂移校验通过（无生成件变更） |
| 映射指向未登记 / 非产品分组服务 | `validate_product_routes` 检出，启动 / CI 拒绝 |
| 映射 `product_key` 与目标服务行不一致 | 同上（防漂移断言） |
| 域段重复 / 服务重复 | 同上 |
| 目标服务尚未启用（`planned`） | 校验放行，网关**不生成**路由（服务不可达不暴露） |
| 目标服务 `disabled` | 校验拒绝（模块级注销态在 `sys_module` 取值中尚未建模，归后续） |

## 6. 开放接口 scope 登记 <a id="scopes"></a>

`bms_core/oauth/scopes.py`（与既有 `oauth` 能力域同域，语义内聚）：

```text
bms_core/oauth/scopes.py
├── SCOPE_READ / SCOPE_WRITE / SCOPE_SEPARATOR      # 动作段与分隔符常量
├── OpenScope(scope, description, write)            # 单条 scope 登记记录
├── PLATFORM_OPEN_SCOPES                            # 平台开放接口基础 scope（open:read / open:write，write=True 需显式授予）
├── OIDC_SCOPES                                     # OIDC 标准 scope（openid / profile / email，复用 oidc_provider 常量）
├── product_scopes(product_key)                     # 产品域 scope（{product_key}:read / :write）
├── OPEN_SCOPES                                     # 登记集合视图（平台基础 + OIDC + 各已登记产品域）
├── known_scopes(products=None)                     # 登记 scope 集合（校验基准）
└── validate_scopes(scopes, products=None)          # 未登记 scope 明细（空列表＝通过）
```

- **最小 scope 集合**：平台基础（`open:read` / `open:write`，写接口需显式授予）+ OIDC 标准（`openid` / `profile` / `email`，授权码客户端必备）+ 各已登记产品域（`{product_key}:read` / `{product_key}:write`，随 `PRODUCT_CATALOG` 自动派生，无需另行登记）。
- **接线**：`bms_identity/services/clients.py::_validate` 在既有字段校验后调用 `validate_scopes(allowed_scopes)`，未登记 scope 抛 `ClientInvalidError`（80112 / 400）并带明细；创建与（后续）更新路径共用同一校验。
- **不在本期**：`/api/open` 令牌签发与运行期 scope 判定（`BaseOAuthServer` / `BaseScopeChecker` 真实实现）、调用日志 `sys_open_log`、按 client 限流与防重放均归阶段十。

## 7. 事件接入 <a id="events"></a>

`bms_core/events/product_events.py` ：

```text
bms_core/events/product_events.py
├── PRODUCT_EVENT_CONTRACTS: tuple[EventContract, ...] = ()          # 产品事件契约（bms 侧本期为空）
├── PRODUCT_EVENT_SUBSCRIPTIONS: tuple[EventSubscription, ...] = ()  # 产品订阅声明（本期为空）
└── register_product_event_contracts(contracts=..., *, subscriptions=..., registry=None)   # 登记入口（幂等）
```

- **登记入口**：产品服务装配 / 快照时把本产品事件契约与订阅登记进目标注册表（缺省进程级默认注册表）；同值重复登记无操作（既有注册表语义）。
- **快照 CLI 注入**：`ops/event_contracts.py` 增可选参数 `--product-contracts <模块路径>`（`export` / `check` 共用，缺省不加载）——导入该产品侧声明模块并调用其 `register_product_event_contracts(registry)`，把产品契约并入注册表参与校验、兼容比对与快照渲染；导入失败 / 模块缺声明函数即报错退出码 1（fail-closed，不静默降级）。
- **事件域**：产品事件域由 `SERVICE_CATALOG.event_domain` 提供（`known_event_domains()`），随产品模块行接入补登；未登记事件域即校验拒绝（既有口径）。
- **零漂移**：本期产品契约为空清单、CLI 参数缺省不加载 ⇒ `deploy/events/contracts.json` 与现状一致（零漂移）。

## 8. 认证接入（复用口径） <a id="auth"></a>

产品服务与平台服务的入站认证**同构、零新增代码**：

| 面 | 复用资产 | 口径 |
| --- | --- | --- |
| 用户请求 | 网关 `forward-auth` 转调 `/api/v1/auth/introspect` → 注入身份头 + 换发短时服务 JWT | 产品服务经网关注入身份；不自行校验用户票据（除非直连） |
| 用户 JWT 直连 | `UnifiedTokenVerifier.verify(token, audience="api")` | 校验签名 / `exp` / `iss` / `aud`（本地用户令牌 JWKS） |
| 服务间入站 | `require_service(*allowed_services)` | 取 `Authorization: Bearer` 按 `aud=service` 全校验，并限定签发方服务标识白名单 |
| 服务间出站 | `service_client`（剥离 `Authorization` + 附服务 JWT） | 出站只走公开契约 |

护栏用例：以产品服务身份（服务 JWT，`service=<产品服务标识>`）断言 `require_service` 白名单「命中放行 / 非白名单拒绝 / 缺凭证拒绝」，证明产品服务可直接复用该依赖。

## 9. 接入骨架（必供项与验收判据） <a id="skeleton"></a>

| 项 | 内容 |
| --- | --- |
| `sys_client` 注册要素 | client 标识 / 凭据、最小 scope 集合（⊆ `OPEN_SCOPES` 登记集合）、IP 白名单（第三方 / 外部系统经 `/api/open`） |
| 必供项 | 健康检查（`/healthz` / `/readyz`）、审计接入、事件订阅声明 |
| 版本兼容承诺 | 平台能力接口与注册要素按契约管理；破坏性变更提前公告 + 过渡期（见《平台可扩展性规划》5.5） |
| **接入验收（五项）** | ① 注册唯一性（前缀 / 错误码段 / 事件域）② 契约测试通过 ③ 权限与审计复用 ④ 前端模块可加载（R4.3 / 前端阶段）⑤ 数据隔离（租户 / 数据范围） |

**判据落点（本任务交付，不新增脚本——复用既有门禁）**：

| 验收点 | 判据与门禁 |
| --- | --- |
| ① 注册唯一性 | `ModuleRegistry.validate()` / `ProductRegistry.validate()` 离线 + `ops.check_modules --url` 接库双向对账（含产品路由映射校验） |
| ② 契约测试通过 | 产品侧自持（产品仓库 OpenAPI 快照 + oasdiff 门禁）；bms 侧 `check_service_declarations` 校验「自报 ↔ 登记」主版本兼容 |
| ③ 权限与审计复用 | 复用平台 `require_permission` / `AuditCapturer` / 审计链基座（产品服务不另起） |
| ④ 前端模块可加载 | 归 R4.3 前端多包合并 / 产品前端接入（本期登记占位，不验收） |
| ⑤ 数据隔离 | 每服务独立库 × 每租户（既有库键 / 路由 / 边界硬校验）；`check-service-boundaries.py` 边界校验 |
