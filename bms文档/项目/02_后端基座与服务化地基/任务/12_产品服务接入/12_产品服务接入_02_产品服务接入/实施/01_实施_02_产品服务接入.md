## 3. 实施过程 <a id="process"></a>

1. **上下文与决策（第 1~2 步）**：按《AI开发规范》读本地资源 → 规划 → 规范 → 设计 → 项目 → 需求 → 任务 → 计划，并核 12_01 实交口径（`PRODUCT_CATALOG` / `ModuleRegistry(products=…)` / `validate_products` / `SysProduct` / `ProductRepository` / 平台链 head `0009_sys_product` / 种子 19 行，**均一致**）。**15 项待拍板事项**分四组用 question 逐项确认（落地范围 / 产品命名空间 / 登记通道 / 跨仓契约 / scope 落点 / 事件注入 / 认证复用 / 路由映射 / 产品档案出口 / 映射表落点 / 事件形态 / scope 落点 / mdm 登记 / 验收判据 / Kiwi 条数）。
2. **详设回写（设计为准）**：把 15 项结论与落点修正回写详设（§1~§13 + 决策记录），补「§13.2 对齐记录」8 条；随后提交 `docs(12_02)`。
3. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_阶段二12-02_产品服务接入.json`（经 `register_cases.py` 走容器 Django shell），平台回读编号 **2250**；用例代码以 `@pytest.mark.kiwi_id(2250)` 标注。
4. **产品档案只读出口**：`bms_core/schemas/product.py` 新增 `ProductResponse`（4 字段）；`ProductRepository` 增 `page_products`（与 `list_products` 同源筛选、排序白名单仅 `id`）；新增 `bms_platform/api/products.py`（清单分页 + 明细 + `require_auth` 占位 + `get_platform_read_db`）并登记进 `api/router.py`。
5. **产品级路由映射**：`module_registry.py` 增 `ProductRouteRecord` / `PRODUCT_ROUTES`（本期空清单）/ `validate_product_routes()`；`ModuleRegistry` 构造增 `routes` 入参并把映射校验并入 `validate()`（离线对清单、接库对库中行，`ops/check_modules.py` 零改动）。
6. **网关产品命名空间**：`gateway_catalog.py` 增 `product_route_prefix()` / `product_gateway_routes()` / `render_product_routes()`，并入 `render_apisix_config()` 路由段；仅目标服务已启用时生成（映射为空清单 → 生成件零漂移）。
7. **开放接口 scope 登记**：新增 `bms_core/oauth/scopes.py`（`OpenScope` / `PLATFORM_OPEN_SCOPES` / `OIDC_SCOPES` / `OPEN_SCOPES` / `product_scopes()` / `known_scopes()` / `validate_scopes()`）；`bms_identity/services/clients.py::_validate` 接线（未登记 scope → `ClientInvalidError` 80112）。
8. **事件接入扩展点**：新增 `bms_core/events/product_events.py`（`register_product_event_contracts()`，bms 侧空清单）；`ops/event_contracts.py` 增 `load_product_contracts()` 与 `--product-contracts <模块路径>`（`export` / `check` 共用；缺声明 / 不可导入即 fail-closed）。
9. **认证接入（复用）**：零新增认证代码；补「产品服务身份入站校验」护栏用例（`require_service` 白名单命中 / 非白名单 / 缺凭证）。
10. **用例与连带产物**：新增 / 扩展 9 个用例文件；重生成 `deploy/contracts/platform.json` 与前端 `@bms/api-types`（`src/platform.ts`）。
11. **验证**：定向用例 454 项、共享基座全量 1232 项、平台 414 项 + identity 289 项全绿；`ruff` / `pyright` 零问题；五项零漂移校验（契约 / 事件 / 网关 / api-types / 服务目录）与基座、文档、状态校验全部通过。

## 7. 偏差与遗留 <a id="deviations"></a>

- **实施偏差（已回写详设 §13.2 对齐记录 9~12）**：① 校验入口由 `ops/check_modules.py` 显式接线改为「随 `ModuleRegistry.validate()` 一并执行」；② 映射校验只拒 `disabled`（模块级注销态在 `sys_module` 取值中尚未建模）；③ 公开契约变更连带重生成 `deploy/contracts/platform.json` 与前端 `@bms/api-types`（契约基线不随本次更新）；④ Kiwi 编号回填 2250。
- **遗留（归口）**：① 产品档案 HTTP 只读出口已交付（12_01 遗留 **闭环**）；② `frontend_package_source` 取值 → **R4.3 前端多包合并**；③ `mdm` 各域模块行与产品级路由映射登记 → **mdm 产品接入**（先注册后建表；`PRODUCT_ROUTES` 本期为空清单）；④ 真实 `/api/open` 令牌签发 / 撤销 / 调用日志 / 按 client 限流 → **阶段十开放接口管理**；⑤ `org` 标识待 bms `org` 服务退役（11_01）后释放给 mdm；⑥ 模块级注销态建模 → 后续数据库治理。
- **开放项**：产品事件契约的实际登记随产品接入（本期只落扩展点与 CLI 注入）。
