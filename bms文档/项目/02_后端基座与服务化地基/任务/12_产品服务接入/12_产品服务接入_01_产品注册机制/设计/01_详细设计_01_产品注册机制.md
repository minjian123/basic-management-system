## 1. 设计目标与范围 <a id="goal"></a>

承接需求 12-1：把平台服务目录从「平台独占」扩展为**支持产品级注册**——新增轻量**产品档案表 `sys_product`**（产品级属性只存一处），`sys_module.product_key` 逻辑引用它；产品注册要素（表前缀 / 业务码 / 错误码段 / 事件域）沿用 `sys_module` 单一登记与唯一性校验。

1. **产品档案**：`sys_product`（`product_key` / `name` / `frontend_package_source` / `status`）；本期登记 `biz`（`enabled`）/ `cw`（`enabled`）+ `mdm`（`planned`，先注册后建表的预登记）。
2. **模块-产品关联**：`sys_module.product_key` 逻辑引用 `sys_product.product_key`（不开物理外键）。
3. **唯一性校验**：产品标识与各注册要素全局唯一（启动 / CI 校验冲突即拒）。
4. **先注册后建表**：产品先登记注册要素，再建表 / 建代码；产品可先于其模块登记，**不要求产品必有模块**。
5. **清单来源**：产品**本地登记**自身服务清单，接入时经**注册通道写入** bms 服务目录。

**不在本期**：产品服务接入机制（归 12_02）；共享基座装配（归 12_03）；产品档案 HTTP 只读出口（归 12_02）。

## 3. 数据模型 <a id="data"></a>

| 表 | 表文件 | 关系 |
| --- | --- | --- |
| `sys_product` | [sys_product.md](../../../../../../设计/数据库设计/数据表设计/sys_product.md) | 产品档案；`product_key` 唯一 |
| `sys_module` | [sys_module.md](../../../../../../设计/数据库设计/数据表设计/sys_module.md) | 服务 / 模块登记；`product_key` 逻辑引用 `sys_product.product_key` |

- **单一登记表不变**：模块 / 服务级要素（表前缀 / 错误码段 / 事件域 / 契约版本）仍只在 `sys_module`；本任务**只加一张产品档案表**，不动 `sys_module` 结构（其 `product_key` 列已存在）。
- **产品级属性下沉**：前端包来源、产品状态等产品级属性只存 `sys_product`，模块行**不重复**。
- **下线语义**：产品下线 `sys_product.status = retired`（保留登记）；模块注销沿用 `sys_module.status`（见架构 11「模块契约与产品下线」节）。
- **模型落点在服务侧**：`sys_product` 归 `platform` 服务、库类别 `platform`（链 `platform:platform`），模型随 `SysModule` 落 `bms_platform/models/catalog.py`（06_02「模型归服务」口径）。

## 4. 注册与校验机制 <a id="registry"></a>

| 项 | 口径 |
| --- | --- |
| 产品档案来源 | **平台库种子**（随平台链迁移 + `seed_module` 幂等 upsert，`PRODUCT_CATALOG` 单一来源） |
| 启动（离线） | `ModuleRegistry.validate()` 增**产品归属校验**：`service_group = product` 的模块其 `product_key` 须在 `PRODUCT_CATALOG` 登记，否则拒启；平台启动经 `validate_catalog` 对**库中行**执行同一校验（**不改 `validate_catalog` 签名**，12_03 注入不受影响） |
| CI（接库） | `ops.check_modules --url`：`sys_module` 双向对账 + **`sys_product` 清单 ↔ 库双向对账**（`validate_products()`），冲突 / 漂移即退出码 1 |
| 产品标识唯一 | `PRODUCT_CATALOG.product_key` 唯一校验；`sys_product` DB 复合唯一 `(product_key, deleted_at)` |
| 产品档案一致性 | 模块 `product_key` 须有对应产品登记；**产品可先于模块登记**（先注册后建表），不要求产品必有模块 |
| 注册要素唯一 | 沿用 `ModuleRegistry._validate_duplicates`（`table_prefix` / `event_domain` / `errcode_segment` / `service_key` 全局唯一） |
| 只读边界 | 运行时无增删改（只读查询）；升级走版本化迁移 + 种子 |

## 5. 产品服务清单来源与登记 <a id="source"></a>

| 阶段 | 做法 |
| --- | --- |
| 产品侧（本地） | 产品仓库维护自身服务清单（与 `bms_core` 同口径的注册要素），本地自校验（见 mdm `01_01` 设计） |
| 接入时 | 经平台**注册通道**（R4.2 提供）把产品服务清单**写入 bms `sys_module`**；平台启动 / CI 对账「平台 + 产品」清单 |
| 冲突处置 | 产品注册要素与平台 / 其他产品冲突即拒（启动失败 / CI 不通过） |
| 错误码段 | 产品按注册段使用（附加段自 10xxxx 起顺延），注册即定、不回收改派 |
| 产品级属性 | `sys_product`：`name` / `frontend_package_source` / `status`；**前端包来源本期留空**，随 R4.3 前端多包合并定稿后回填 |

## 6. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 模块产品归属缺产品档案 | 离线校验拒绝（`product_key` 未在 `PRODUCT_CATALOG` 登记） |
| 模块 `product_key` 与库中 `sys_product` 漂移 | CI 接库对账检出、退出码 1（启动期以离线清单为准） |
| 产品标识 / 注册要素冲突 | 启动失败 / CI 不通过 |
| 空目录（未播种） | 仅告警放行（沿用既有口径） |
| 库不可读 / `sys_module` 表缺失 | 启动失败（沿用既有口径） |
| 产品下线 | `status = retired` 保留登记；不物理删除、不回收段位 |
