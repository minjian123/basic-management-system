## 3. 实施过程 <a id="process"></a>

1. **上下文与决策（第 1~2 步）**：按《AI开发规范》读本地资源 → 规划 → 规范 → 设计 → 项目 → 需求 → 任务 → 计划 → 详细设计；并核对该任务相关现状（`module_registry.py`、`ops/seed_module.py`、`ops/check_modules.py`、启动接库校验、表归属登记、平台链迁移与用例）。**7 项待拍板事项**用 question 逐项确认：模型落点 / 产品清单落点 / 清单内容与来源字段 / 校验与对账口径 / 只读出口 / 断链修复范围 / 设计节点补齐。
2. **详设回写（设计为准）**：实施前把 6 项偏差与口径变更回写详设（§1~§12）：ORM 落点改 `bms_platform/models/catalog.py`、产品清单含 `mdm` 预登记、校验改「离线 + CI 接库对账」且不改 `validate_catalog` 签名、本期不加 HTTP 只读接口、补齐设计节点 03、一并修断链，并补「§12 对齐记录」6 条。
3. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_阶段二12-01_产品注册机制.json`（经 `register_cases.py` 走容器 Django shell），平台回读编号 **2249**；随后在用例代码内以 `@pytest.mark.kiwi_id(2249)` 标注。
4. **表结构与登记**：`sys_product.md` 状态改「已落库」+ 变更记录 v2 / v3（`status` 取值补 `planned`）+ ORM 与迁移落点修正；《数据库设计 · 总览》登记状态同步；新建节点 [`03_数据库设计_模块注册.md`](../../../../../../设计/数据库设计/03_数据库设计_模块注册.md)（消除总览悬空引用）；`TABLE_OWNERSHIP` 增 `sys_product`（`platform` / 平台服务库 / enabled）。
5. **模型与迁移**：`bms_platform/models/catalog.py` 增 `SysProduct`（`product_key` / `name` / `frontend_package_source` / `status`，唯一 `(product_key, deleted_at)`，公共软删除索引）；新增平台链迁移 `0009_sys_product`（`down_revision=0008_menu_form_multi`，只建表 + 建索引，四库通用）。
6. **产品清单与校验**：`bms_core/services/module_registry.py` 增 `ProductStatus` / `ProductRecord` / `PRODUCT_CATALOG`（`biz` / `cw` / `mdm`）/ `product_keys()` / `ProductRegistry`（`list_products` + `validate`）/ `validate_products`（清单 ↔ 库双向对账）；`ModuleRegistry` 构造增 `products` 参数（默认为 `PRODUCT_CATALOG`），`_validate_record` 增**产品归属**校验（产品分组模块 `product_key` 须已登记），`validate_catalog` 签名不变。
7. **只读仓储**：新增 `bms_platform/repositories/product_repository.py::ProductRepository`（`list_products` 按状态 / `get_by_key` 单条；无写方法、无会话写调用）。
8. **种子与 CI 脚本**：`ops/seed_module.py` 扩为「服务目录 + 产品档案」同脚本幂等 upsert（返回合计新增 / 更新行数，`--dry-run` 分别列出两类种子）；`ops/check_modules.py` 离线增 `ProductRegistry().validate()`、接库增 `sys_product` 读库对账（含空表 / 表缺失判失败）。
9. **用例与适配**：新增产品清单 / 校验 / 归属 / 对账 / 模型落库用例（`libs/bms_core/tests/services/test_module_registry.py`）、种子与接库对账用例（`tests/ops/test_module_ops.py`、`tests/ops/test_check_modules.py`）、只读仓储用例（`services/platform/tests/repositories/test_product_repository.py`）；适配链头与表集断言（`test_alembic_chains.py`、`test_migration_ops.py`、`test_table_registry.py`）。
10. **验证与实测**：`ruff` / `pyright` / `check-bare-collections` / `check-base` / `check-docs-scope` / `check-backend-base` / `check-links` / `check_tables` / 契约与网关零漂移全绿；临时平台库执行 `0009` 迁移 + 种子 + 接库对账实测（新增 19 行 → 重复 0 / 0 → 校验通过）。
11. **文档顺带修正**：`alembic/README.md` 平台两条链的派生表集摘要按归属登记校正（`org:tenant` 行随 11_01 回写）；`sys_module.md` 的 ORM / 迁移路径滞后描述修正；域十一 / 十二详设与 `sys_product.md` 相对链接层级修正（`check-links` 断链 19 → 0）。

## 7. 偏差与遗留 <a id="deviations"></a>

- **实施偏差（已回写详设 §12 对齐记录）**：① ORM 落点 `bms_core/models/platform.py` → `bms_platform/models/catalog.py`；② 校验口径由「`validate_catalog` 覆盖产品维度」调整为「离线 `validate()` 产品归属 + CI 接库 `validate_products` 对账」，`validate_catalog` 签名不变；③ 产品清单含 `mdm`（`planned` 预登记）；④ 产品档案 HTTP 只读出口本期不做；⑤ 补齐数据库设计节点 03；⑥ 一并修复 19 处断链与两处文档滞后描述。
- **遗留（归口）**：产品档案 HTTP 只读出口（`GET /api/v1/products`）→ **12_02**；`frontend_package_source` 取值 → **R4.3 前端多包合并**；`mdm` 各域模块行补登 `SERVICE_CATALOG` → **mdm 产品接入**；`alembic/README.md` 的 `org:tenant` 行 → **11_01 组织服务退役**。
- **开放项**：产品档案多语言附表（`sys_product_i18n`）按需再补（详设 §9 第 2 项）。
