# 01 详细设计 · 共享基座产品服务装配支持

> 后端基座与服务化地基 · 12_产品服务接入 · 子任务 03（需求 12-3）· 详细设计

[文档首页](../../../../../../文档首页.md) › [12 产品服务接入](../../12_产品服务接入.md) › 详细设计　|　[← 任务](../12_产品服务接入_03_共享基座产品服务装配支持.md)

## 1. 设计目标与范围 <a id="goal"></a>

承接需求 12-3：让共享基座库 `bms_core` 支持**产品服务装配**——产品服务（跨仓库、独立部署）可经 `BaseServiceApplicationFactory` 装配并启动，不因平台专属服务集产生隐式依赖；平台 8 服务装配行为不变。

1. **服务目录参数化**：`SERVICE_CATALOG` 支持**注入产品服务记录**（产品侧提供本产品服务清单，与平台清单合并校验），或等价扩展点。
2. **服务身份参数化**：应用工厂支持产品服务身份（`service_name` / `service_title` / 契约版本 / 产品维度），不硬编码平台服务集。
3. **依赖可分离**：产品服务经共享基座装配时不因平台专属服务集产生隐式依赖；跨仓库依赖（git 源）可用。
4. **向后兼容**：平台 8 服务装配行为不变。

**不在本期**：产品注册表（归 12_01）；产品服务接入机制（归 12_02）。

## 3. 装配机制设计 <a id="mechanism"></a>

| 面 | 现状 | 目标 |
| --- | --- | --- |
| 服务清单 | `SERVICE_CATALOG` 为平台服务固定元组（单一来源） | 支持**追加产品服务记录**（产品侧清单）形成「平台 + 产品」视图；平台默认视图不变 |
| 目录校验 | `ModuleRegistry.validate()` / `validate_catalog()` 面向平台清单 | 支持对账**合并清单**；产品服务启动时校验自身登记（产品行），平台服务启动校验不变 |
| 应用装配 | `BaseServiceApplicationFactory` 已参数化服务身份（`service_name` / 标题 / 版本 / 契约版本） | 确保装配链路不强引用平台专属服务集；产品服务经同一基座装配 |
| 插件装配 | 各服务经共享基座逐进程装配，注册表限本进程 | 产品服务同样逐进程装配，不因跨仓库改变机制 |
| 依赖方向 | 共享库不依赖任何服务 | 保持；产品服务只依赖 `bms-core` 与自身 |

- **扩展点形态（二选一，实施时定）**：① `ModuleRegistry(catalog=…)` 追加记录（已有构造入参，补合并语义）；② 新增 `product_catalog` 配置 / 入口（产品侧提供清单，平台合并校验）。择优取**显式注入**，不引入隐式全局状态。
- **契约版本兼容**：产品服务自报契约版本与（平台登记 / 产品登记）主版本兼容校验，口径沿用既有 `_check_running_service`。

## 4. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 产品服务记录与平台冲突 | 合并校验拒绝（唯一性冲突即启动失败） |
| 产品清单缺失 / 非法 | 启动校验失败并给出明细 |
| 平台服务（8）装配 | 行为不变；默认 `SERVICE_CATALOG` 视图不变 |
| 产品服务隐式引用平台专属服务 | 边界校验拦截（沿用 `check-service-boundaries.py` 口径） |
| 跨仓库依赖不可用 | 构建失败（git 源不可达），不静默降级 |
