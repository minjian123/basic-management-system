## 2. 任务内容 <a id="content"></a>

1. **运行镜像机器可读声明**：`ops` 全部 31 个脚本声明 `RUN_IMAGE`（`platform` / `tenant` / `txn` / `ci` / `*`）并在 docstring 写明依据；**跨包脚本未声明或声明值非法即失败**。当前登记的跨包脚本——`bootstrap_platform`（tenant 镜像）、`check_modules` / `check_plugins`（CI / 开发机全量工作区）、`txn_recovery`（txn 镜像 / 运维机）；其余只依赖基座的脚本声明 `*`。
2. **导入闭包断言**：扩展 `scripts/tools/base-check/check-service-boundaries.py`（或新增同源护栏脚本），断言「脚本声明镜像所含包 ⊇ 脚本**传递导入闭包**（含 `ops` 内部互导）所需服务包」（镜像包 = `bms_core` + 本服务 + `ops`；`*` 只覆盖 `bms_core` + `ops`）；镜像包集合常量须与 `backend/Dockerfile` 的 COPY 面一致；新增两条反向断言——「`services/*/src` 非 platform 服务不得导入 `bms_platform`」「`services/*/src` 不得导入 `ops`」，**硬断言、不设例外**。
3. **镜像启动自检**：`deploy/ci/templates/backend-service.yml` 的 `service-build` 在 `docker build` 后增加容器内 `import bms_<service>.main` 自检（构建期暴露缺模块），失败输出须直接打印**缺失模块名**便于定位；`Dockerfile` 说明同步。
4. **冒烟门禁说明**：《[部署发布规范](../../../../../规范/部署发布规范.md)》补小节——`contract-smoke` 失败语义与镜像边界的关系，明确「冒烟失败先看容器启动诊断」并区分两类根因。
5. **部署侧口径清理**：`scripts/tools/deploy/release.py` 中「种子按服务包挑镜像」的注释与分支改为读取脚本的运行镜像声明（标准库 `ast` 静态读取，`*` 回落 platform），不留解释性注释；顺带统一全部 `ops` 调用点。
6. **护栏自测**：护栏具备 `--self-test`，并用本次缺陷做回归样本（在修复前版本上失败、修复后通过）。

## 3. 完成标准 <a id="accept"></a>

每个 `ops` 脚本都有 `RUN_IMAGE` 声明且断言通过（跨包脚本未声明即失败）；`services/*/src` 导入 `ops` 归零、非 platform 服务导入 `bms_platform` 归零并有硬断言；`service-build` 导入自检生效（故意缺包时构建失败并打印缺失模块名）；规范补入对应小节；`--self-test` 通过且能复现本次缺陷（含**间接跨包**形态）；预检 `--fast` 与 CI `base-integrity` 纳入该护栏。
