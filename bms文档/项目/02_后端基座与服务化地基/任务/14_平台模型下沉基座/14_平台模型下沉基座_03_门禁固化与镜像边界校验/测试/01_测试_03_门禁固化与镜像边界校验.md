## 3. 缺陷回归样本（本次缺陷复现） <a id="regression"></a>

在临时仓库构造本次缺陷的**间接链形态**，验证护栏在修复前语义下会失败、当前实现能拦住：

```text
backend/ops/tenant_provisioning.py   RUN_IMAGE = "tenant"  →  from ops.seed_platform import ...
backend/ops/seed_platform.py         RUN_IMAGE = "*"       →  from bms_platform.models import menu
backend/services/tenant/src/.../main.py → from ops.tenant_provisioning import ...
```

护栏输出（实测）：

```text
[导入闭包越界] ops.seed_platform 声明 RUN_IMAGE = '*'（仅含 bms_core + ops），但闭包需要服务包 ['bms_platform']
[导入闭包越界] ops.tenant_provisioning 声明 RUN_IMAGE = 'tenant'（含 ['bms_core', 'bms_tenant', 'ops']），但闭包需要 ['bms_platform']
[运行期依赖运维通道] backend/services/tenant/src/bms_tenant/main.py:1 import ops.tenant_provisioning
```

结论：**只看直接导入会漏判**（`tenant_provisioning` 自身只导入 `ops`），传递闭包口径才拦得住——与流水线 1188 的根因形态一致。

## 7. 结论 <a id="conclusion"></a>

设计所列验收项均有对应用例或命令证据：①31 个 `ops` 脚本运行镜像声明完整合法；②护栏三项新规则生效，本次缺陷的**间接跨包形态**与运行期反向依赖均被拦截；③镜像包集合与 Dockerfile 一致性可断言；④`service-build` 构建期导入自检缺模块直出模块名；⑤`release.py` 按声明选镜像、部署命令零改动；⑥《部署发布规范》已补冒烟诊断小节；⑦`--self-test` 27 样例通过且含本次缺陷回归样本。偏差与遗留见[实施记录 §7](../实施/01_实施_03_门禁固化与镜像边界校验.md#deviation)。
