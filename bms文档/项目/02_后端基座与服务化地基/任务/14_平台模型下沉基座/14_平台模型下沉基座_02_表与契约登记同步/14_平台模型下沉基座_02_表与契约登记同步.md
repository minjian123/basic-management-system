## 2. 任务内容 <a id="content"></a>

1. **表登记同步**：核对已搬 38 张表的表文件「归属服务 / 模块」字段，模型归属标为基座共享；`TABLE_OWNERSHIP`（`bms_core/services/table_registry.py`）的 `owner` 与 `datasource` **保持不变**（链归属由其派生，改动会让表跑到别的链）；同步《数据库设计总览》「已设计数据表登记」状态（两处一致）。
2. **自动建表发现口径**：核对 `bms_core/db/migration.py`（`COMMON_MODEL_MODULES` / `service_model_modules()` / `chain_metadata`）、`bms_core/db/bootstrap.py::ensure_service_schema`、`ops/init_schema.py`、`alembic/env.py` 的模型包发现逻辑，确认基座三个新子包被纳入扫描且 `chain_metadata` 交集非空。
3. **契约与快照**：`ops.contract_snapshot check`、`ops.event_contracts check`、`ops.check_contracts`、`ops.check_tables` 零漂移；必要时按规范重新导出归档。
4. **迁移链核对**：启动期自动建表、`ops.init_schema --dry-run` 与（按需）Alembic 建表链路均能建出 38 张表；`planned` 表（`sys_task` / `sys_task_log` / `sys_user_preference` / `demo`）仍不进链。

## 3. 完成标准 <a id="accept"></a>

四项 check 全部通过且零漂移；启动期建表与 `ops.init_schema` 建出 38 张表（`planned` 表不计入）且无「模型存在但未登记 / 已登记但无模型」的差额；表文件、总览登记、目录一致性校验通过；`TABLE_OWNERSHIP` 与迁移前后逐条一致（仅模型文件位置变化）。
