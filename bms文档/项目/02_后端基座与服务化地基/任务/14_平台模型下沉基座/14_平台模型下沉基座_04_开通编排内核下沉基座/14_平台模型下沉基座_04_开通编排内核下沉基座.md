## 2. 任务内容 <a id="content"></a>

1. **内核下沉**：`ops/tenant_provisioning.py` → `backend/libs/bms_core/src/bms_core/tenant/provisioning.py`；公开接口（`ProvisionOutcome` / `provision_infrastructure` / `enabled_tenant_services`）与签名不变，行为不变（建库 → 逐链幂等建表 → 批量种子 → 失败逆序清理）；落点归**租户能力域**（不放 `db/`：`db` 域只放数据库机制，种子含平台内置数据）。
2. **种子下沉**：`ops/seed_platform.py` / `seed_rbac.py` / `seed_sso.py` / `seed_user.py` → `bms_core/tenant/seed/{platform,rbac,sso,user}.py`；种子数据（内置管理员角色与互斥预授、菜单 / 权限码 / 表单、初始系统管理员、默认 IdP 占位、系统参数）内容不变。
3. **调用方切换**：`services/tenant/src/bms_tenant/services/platform_tenant.py:23`、`services/provisioning.py:25`、`api/tenant_admin.py:459` 改基座路径；`bms_tenant` 运行期对 `ops` 的导入归零。
4. **CLI 薄壳**：`ops/` 保留同名入口（`python -m ops.seed_platform` / `ops.seed_rbac` / `ops.seed_sso` / `ops.seed_user` / `ops.tenant_provisioning`），只做参数解析与基座调用，命令 / 参数 / 退出码不变；`scripts/tools/deploy/release.py` 零改动。
5. **依赖方向**：`bms_core/tenant/` 只依赖 `bms_core`；禁止 `bms_core` 反向导入 `ops` 或任何服务包（动态导入仅限模型包发现的既有机制）。
6. **口径回写**：《[平台可扩展性规划](../../../../../规划/平台可扩展性规划.md)》三层模型节补边界（基座可承载「开通所需的默认数据种子」，不得承载业务运营逻辑）；《[后端开发规范](../../../../../规范/后端开发规范.md)》分层依赖节补对应一句。

## 3. 完成标准 <a id="accept"></a>

`python -c "import bms_tenant.main"` 在仅含 `bms_core` + `bms_tenant` + `ops` 的环境下通过；`services/*/src` 对 `ops` 的导入归零；四个 `ops` 种子脚本为薄壳（仅参数解析 + 基座调用）；`python -m ops.<script>` 与部署脚本行为不回退（初始化结果逐项一致）；`bms_core/tenant/` 无 `ops` / 服务包导入；规划与规范已回写；相关测试迁移到 `libs/bms_core/tests` 且全绿。
