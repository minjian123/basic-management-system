## 2. 任务内容 <a id="content"></a>

1. **既有类型缺口修正**：`backend/ops/` 12 个文件共 **33 处** `pyright` 严格模式错误全部修正（不留基线豁免）：
   - `tuple` 赋给 `ConcurrentStableList`（`init_schema` / `migrate_tenants` / `seed_menu` / `test_db`）→ 按集合类构造；
   - `sqlalchemy Table.create` 类型未知（`seed_tenant` / `seed_oidc_client`）→ 显式 `cast`；
   - 动态 `getattr` 取值导致类型丢失（`check_contracts` / `contract_snapshot`）→ 显式类型收窄；
   - 参数类型不匹配（`check_budget` / `contract_gate` / `gateway_config` / `provision_tenant`）→ 按签名修正。
2. **门禁接线**：`backend/pyproject.toml` 的 `[tool.pyright] include` 增加 `ops`（与 `libs` / `services` 同 strict 口径），现有 `backend-typecheck` CI job 与本地预检「后端静态」自动覆盖，**不新增 job**。
3. **行为零回退**：`ops` 各 CLI 的 `--dry-run` / 正常路径 / 退出码不变（既有 `libs/bms_core/tests/ops/` 用例回归）。
4. **范围外**：`scripts/tools/` **不纳入**（开发辅助工具链，不属后端开发内容；且其 2536 处错误会形成「工具检查自己」的口径混乱，见需求 14-5 范围界定）。

## 3. 完成标准 <a id="accept"></a>

`uv run pyright`（`include` 含 `ops`）**0 error**；`backend/ops` 全目录 strict 零错且无 `# pyright: ignore` 滥用（确需忽略处逐条注明理由）；既有 `ops` 用例全通过（CLI 行为零回退）；CI `backend-typecheck` 与本地预检「后端静态」覆盖 `ops`；预检缺省定向档全绿。
