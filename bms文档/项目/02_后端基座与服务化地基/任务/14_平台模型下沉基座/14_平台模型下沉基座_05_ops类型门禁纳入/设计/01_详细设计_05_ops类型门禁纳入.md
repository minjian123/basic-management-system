## 1. 目标与边界 <a id="scope"></a>

**目标**：把 `backend/ops/`（运维通道：建库 / 建表 / 种子 / 校验 / 迁移等一次性命令）纳入 `pyright` 严格类型门禁——该目录与后端代码同仓同审、是部署与运维的实际入口，却长期在 `include` 之外，33 处严格模式错误中既有会掩盖真实缺陷的类型谎报，也有类型丢失。

**范围内**：

1. **33 处既有错误全部修正**（12 个文件，不留基线豁免）。
2. **`include` 扩至 `ops`**（与 `libs` / `services` 同 `strict`），复用现有 CI job 与本地预检。
3. **行为零回退**（`ops` 各 CLI 的 `--dry-run` / 正常路径 / 退出码不变）。

**范围外（明确不做，理由见 §8）**：

- **`scripts/tools/` 不纳入**：开发辅助工具链（本地全套 / 镜像拉取 / 备份 / 依赖维护 / 设计重排 / WinRM / WOL 等），不属后端开发内容；实测 2536 处 / 55 文件，纳入会形成「工具检查自己」的口径混乱。工具脚本静态检查维持 `ruff`（CI `tooling-lint` 已覆盖）。
- 不新增 CI job、不改预检脚本（`include` 扩容即自动生效）。
- 不改 `ops` 脚本的业务行为与 CLI 契约。

## 4. 设计 <a id="design"></a>

### 4.1 配置改动 <a id="config"></a>

```toml
[tool.pyright]
typeCheckingMode = "strict"
pythonVersion = "3.14"
include = ["libs", "services", "ops"]   # 新增 ops（14_05）
ignore = ["alembic"]
```

- **`extraPaths` 无需改**：`ops` 直接位于 `backend/` 下（与 `pyright` 执行目录同级），本就可解析；
- **`ignore` 不加 `ops`**：`ops` 须与 `libs` / `services` 同口径受检；
- **不新增 job**：`backend-typecheck`（`cd backend && uv run pyright`）与本地预检「后端静态：pyright」自动覆盖。

### 4.2 逐类修正细则 <a id="fixes"></a>

**① `tuple` → 集合类**（与「集合声明一律落插入序集合类」口径一致）：

```python
# 修正前
return MigrationSummary(succeeded=tuple(succeeded), skipped=tuple(skipped), failed=tuple(failed))
# 修正后（succeeded / skipped / failed 本就是 ConcurrentStableList）
return MigrationSummary(succeeded=succeeded, skipped=skipped, failed=failed)
```

**② `Table.create` 显式 cast**：

```python
await connection.run_sync(cast("Table", SysTenant.__table__).create, checkfirst=True)
```

**③ 动态 `getattr` 类型收窄**：把「取属性 + 判 callable + 调用」改为**先收窄类型再调用**：

```python
items = getattr(openapi, "items", None)
if callable(items):
    for key, value in cast("Callable[[], ItemsView[str, Any]]", items)():
        contract.set(str(key), value)
```

**④ 参数类型按签名修正**：`check_budget` / `contract_gate` 传集合类而非 `tuple` / `list`；`gateway_config` 的空值分支先行（`None` 早退或给缺省串）；`provision_tenant` / `seed_menu` 显式注解返回值。

### 4.3 门禁覆盖验证 <a id="coverage-check"></a>

新增用例 `test_ops_type_gate.py`：

1. 读 `backend/pyproject.toml`，断言 `[tool.pyright].include` **含 `ops`**（防回退）；
2. 跑 `pyright ops`（子进程），断言 **0 error**；
3. 断言 `backend/ops/**` 无未注明的 `# pyright: ignore`（有则须带理由文本）。

**为什么用「跑 pyright」而非只断言配置**：配置正确但代码有错时门禁仍红——用例须同时覆盖「已接线」与「当前零错」两个事实。

### 4.4 行为零回退 <a id="no-regression"></a>

`ops` 改动仅限类型标注与构造方式，**不改逻辑**。回归范围：

- `libs/bms_core/tests/ops/`（含 `test_release_image_selection` / `test_service_build_selfcheck` 等 14_03 新增）；
- `libs/bms_core/tests/tenant/`（14_04 下沉的种子 / 编排用例，与 `ops` 薄壳同源）。

## 6. 兼容与回滚 <a id="rollback"></a>

- **兼容**：`ops` 行为与 CLI 契约零变化（只改类型标注 / 构造方式）；CI 不新增 job、耗时增量可忽略（`pyright` 全仓本就运行）；
- **回滚**：`git revert` 本任务提交即可（配置与类型标注回退，无运行时影响）；
- **风险**：① 类型修正误改语义 → 以既有 `ops` 用例 + CLI 行为用例兜底；② `include` 扩容后暴露新错误（如后续新增脚本）→ 正是门禁目的，属预期。
