## 2. 任务内容 <a id="content"></a>

1. **整包搬迁**（模型定义 / 表名 / 表前缀 / 字段 / 约束 / 模块级常量**零改动**，只改导入路径）：
   - `services/platform/src/bms_platform/models/{menu,role,user,catalog,system,demo}.py` → `backend/libs/bms_core/src/bms_core/models/platform/`（6 文件 / 29 表）；
   - `services/identity/src/bms_identity/models/{client,identity_provider,session,user_identity}.py` → `bms_core/models/identity/`（4 文件 / 4 表）；
   - `services/tenant/src/bms_tenant/models/{tenant,tenant_database,tenant_module,tenant_quota,user_tenant}.py` → `bms_core/models/tenant/`（5 文件 / 5 表）。
   - 口径：按「服务 `models` 包零服务内依赖即整包归基座」一次搬完，不做逐文件挑拣（避免长期「一半在基座、一半在服务」）。
2. **引用同步（不留转发层）**：全仓 **131 处**引用（`bms_platform.models` 80 / `bms_identity.models` 29 / `bms_tenant.models` 22，含服务内 src、`tests_support`、各服务测试）一次性改到基座新路径；三个原 `models` 包**不保留 re-export 转发模块**（转发层会掩盖「不得导入服务包」的违例）。
3. **两处登记同步**（漏改即故障）：源服务 `models/__init__.py` 的 `MODEL_MODULES` 删除已搬模块（漏删 → 同名表双注册 `Table already defined`）；`bms_core/db/migration.py` 的 `COMMON_MODEL_MODULES` 加入 15 个新模块路径（漏加 → `chain_metadata` 取不到模型、建表静默 0 表）。
4. **`ops` 模型层收口**：`seed_platform` / `seed_rbac` / `seed_menu` / `seed_user` / `seed_module` / `seed_sso` / `seed_oidc_client` / `seed_tenant` / `migrate_tenants` 的模型导入改基座路径（`migrate_tenants` / `seed_tenant` 的惰性导入保留惰性）；`check_plugins` 对 `bms_platform.main` 的依赖保留并按 `14_03` 登记运行镜像例外。
5. **依赖声明**：`bms_core/pyproject.toml` 补齐模型所需依赖；各服务 `pyproject.toml` **不新增**服务间源码依赖；`uv.lock` 零漂移。

## 3. 完成标准 <a id="accept"></a>

三个服务的 `models` 包在服务侧不再含已搬模块（`__init__.py` 仅剩 `MODEL_MODULES` 与说明）；全仓 `from bms_platform.models.*` / `from bms_identity.models.*` / `from bms_tenant.models.*` **0 处**（无转发层残留）；`ops` 模型层跨包导入归零；`COMMON_MODEL_MODULES` 与 `models/{platform,identity,tenant}/` 一致；`uv sync --frozen` 通过；`libs/bms_core` 与服务侧相关测试全绿；覆盖率统计分母随模型归属迁移后仍为行 + 分支 100%；tenant 服务导入链零 `ModuleNotFoundError`（与 `14_04` 联合验证）。
