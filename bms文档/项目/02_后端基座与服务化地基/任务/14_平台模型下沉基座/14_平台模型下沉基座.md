## 1. 域说明 <a id="intro"></a>

本域对应阶段二「平台模型下沉基座」：把**跨服务共用**的 ORM 模型从 `bms_platform.models` / `bms_identity.models` / `bms_tenant.models` **整包**下沉到基座 `bms_core.models.{platform,identity,tenant}`，并把被 tenant 服务运行期依赖的**租户开通编排内核**（`ops.tenant_provisioning` + 四个种子模块）下沉到 `bms_core.tenant`，消除「服务镜像内的代码依赖其他服务源码 / 运维包」的隐式耦合。

**问题来源**：流水线 1188 `contract-smoke-tenant` 失败——tenant 镜像启动即 `ModuleNotFoundError: No module named 'bms_platform'`，导入链为 `bms_tenant/main.py:11 → services/platform_tenant.py:23 → ops/tenant_provisioning.py:37-40 → ops/seed_platform.py:30 → bms_platform.models`；**同一链路还需 `bms_identity.models`**（`ops/seed_sso.py:34-35`），故只下沉菜单 / 角色 / 用户三个模型修不掉。

**范围**：`platform.models`（6 文件 / 29 表）、`identity.models`（4 文件 / 4 表）、`tenant.models`（5 文件 / 5 表）共 17 文件 / 38 表整包下沉（三个包实测零服务内交叉依赖）；开通编排内核 + 四种子下沉；`ops` 跨包脚本按运行镜像显式登记并纳入门禁。**不含** `txn.models.ledger`（TM 私有账本，按运行镜像声明处理）与基座阶段三 / 四能力域占位目录。依据《[平台可扩展性规划](../../../../规划/平台可扩展性规划.md)》三层模型与《[后端开发规范](../../../../规范/后端开发规范.md)》分层依赖口径；对应需求 14-1 ~ 14-4。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：`14_01` 是本域前置——`14_02`（表登记与发现口径）、`14_03`（导入闭包断言）、`14_04`（内核下沉后只依赖 `bms_core`）均以其迁包结果为前提；`14_02` 与 `14_04` 可并行，`14_03` 收口在两者之后（断言对象是最终导入闭包）。
- **约束**：模型定义、表名、表前缀与字段**不得改动**（只改导入路径）；`TABLE_OWNERSHIP` 的 `owner` 与 `datasource` **不得改动**（链归属由其派生）；`COMMON_MODEL_MODULES` 与源服务 `MODEL_MODULES` 两处登记须同步（漏删双注册报 `Table already defined`，漏加静默 0 表）；不留 re-export 转发层；`ops` 命令入口与部署脚本行为零回退。
- **风险**：迁包引发**双注册 / 漏建表**（靠 14-02 建表核对兜底）；契约快照与事件契约漂移（靠快照 check 兜底）；17 个模型文件迁入 `bms_core` 后**覆盖率统计分母归属变化**，须确认各工程覆盖率仍为行 + 分支 100%；`ops` 运行镜像声明不实（靠护栏 `--self-test` 用本次缺陷做回归）；基座承载「开通用默认种子」与「基座不自营业务」的口径冲突（随 14_04 回写规划与规范定界）。
