## 1. 域说明 <a id="intro"></a>

本域对应 WBS 阶段二「后端基座与服务化地基」的服务边界治理：把跨服务共用的菜单 / 角色 / 用户 ORM 模型从平台服务下沉到共享基座，使服务镜像不再因共享表模型而依赖其他服务源码。

**覆盖范围**：模型迁包（`bms_platform.models` → `bms_core.models`）、全仓 58 文件 / 80 处引用同步、`ops` 导入闭包收口、表登记与契约快照 / 迁移链同步、导入边界护栏与镜像启动自检。

**依据**：需求域十四《[平台模型下沉基座](../../需求/14_需求_平台模型下沉基座.md)》；《[平台可扩展性规划](../../../../规划/平台可扩展性规划.md)》第 3 节三层分层模型。

**触发事实**：流水线 1188 `contract-smoke-tenant` 失败，tenant 镜像启动报 `ModuleNotFoundError: No module named 'bms_platform'`，导入链经 `ops.tenant_provisioning → ops.seed_platform → bms_platform.models` 跨入平台服务源码。

## 3. 依赖与风险 <a id="dep"></a>

**关键依赖**：

- 需求 14-1 / 14-2 / 14-3 与子任务 01 / 02 / 03 一一对应，**02 依赖 01**（先迁包再同步登记），**03 依赖 01**（护栏以迁包后的边界为断言对象）。
- 依赖阶段二已交付的契约门禁与表登记机制（任务域 03、09）。
- 依赖 `ops.init_schema` 与 Alembic 自动建表的模型包发现逻辑。

**风险**：

- **迁移面广**：58 文件 / 80 处引用，遗漏一处即运行时 `ImportError`；以「转发模块过渡 + 全量回归」双保险。
- **建表发现漏表**：迁包后若自动建表仍按平台包发现，三张表将不被创建；需在 02 显式核对并加断言。
- **契约快照漂移**：ORM 包路径变化可能影响 OpenAPI schema 生成顺序，需重新导出并人工确认差异仅为路径。
- **覆盖率硬门禁**：模型迁包会改变覆盖率统计的分母归属，需确认迁移后各工程覆盖率仍为 100%。
