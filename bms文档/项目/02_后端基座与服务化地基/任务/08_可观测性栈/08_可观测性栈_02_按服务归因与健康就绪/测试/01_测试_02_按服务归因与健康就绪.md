## 3. 真实冒烟（mjbk） <a id="smoke"></a>

一键拉起：`docker compose -p compose -f compose/bms.yml --env-file .env up -d`；platform（8000）与 identity（8001，`BMS_SERVICE_CLIENT__PROVIDER=http` + `base_url_template=http://localhost:8000`）宿主直跑（`BMS_LOG__FORMAT=json`，日志落 `~/deploy/observability/logs/`）。

| 场景 | 命令 / 操作 | 实测结果 |
| --- | --- | --- |
| 组件就位 | `docker ps` | alertmanager / blackbox-exporter / pushgateway Up（连同既有六组件） |
| Alertmanager 配置校验 | `amtool check-config` | SUCCESS（1 抑制规则 / 2 receivers，no-op 形态合法） |
| 规则加载 | `GET /api/v1/rules` | bms-probes / bms-dependencies / bms-http-slo / bms-outbox |
| 告警目标 | `GET /api/v1/alertmanagers` | active `http://alertmanager:9093/api/v2/alerts` |
| 探针 | `query=probe_success` | healthz=1 / readyz=1 |
| 服务指标抓取 | `query=up{job="bms-services"}` | 1 |
| 依赖指标持续刷新 | `query=bms_dependency_up` | redis / database / catalog 均 1（blackbox 周期调 `/readyz`） |
| 目录降级指标 | `query=bms_catalog_degraded` | platform = 0 |
| 跨服务 Trace | Tempo `/api/v2/traces/b65e538a…` | 同一 trace：`identity`（GET 客户端 span）+ `platform`（`GET /api/v1/modules/snapshot` 服务端 span + `connect` / `SELECT` DB span） |
| 告警真实触发 | 停 platform → 150s | Prometheus `BmsServiceMetricsDown` + `BmsProbeFailing`×2 firing；Alertmanager 3 条 active |
| 告警恢复 | 重启 platform → 95s | `probe_success=1`；Alertmanager active=0 |
| 阶段度量通道 | 样例推送 → Prometheus | 推送 `http=200`；`bms_release_total`（success=3 / failure=1）与 `bms_contract_breaking_total=0` 可查 |
| Grafana | 容器挂载 + 日志 | 三张面板在（总览 / SLO 与告警 / 阶段度量）；`finished to provision dashboards` |
| 清理 | 进程 / 样例 | 服务进程 0；Pushgateway 组数 0（卷重建）；可观测栈容器保留 |
