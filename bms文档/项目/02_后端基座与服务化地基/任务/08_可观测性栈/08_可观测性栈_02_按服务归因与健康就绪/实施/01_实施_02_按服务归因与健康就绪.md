## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记**：登记一条策展用例（平台骨架 / P2 / CONFIRMED / 自动化）并回读编号 **2183**（输入 `test/scripts/kiwi/cases/2026-09-24_阶段二08-02_按服务归因与健康就绪.json`）；先登记后编码。
2. **应用侧指标扩展**：`metrics/base.py` 的 `METRIC_NAMES` 增 `bms_catalog_degraded` 与阶段度量名（`bms_release_total` / `bms_contract_breaking_total`，注释注明由 CI 推送）；`metrics/prometheus.py` 的 `METRIC_DOCS` 增对应 HELP 并修正越界指标文案；`health/checks.py` 增 `CATALOG_CHECK_KEY` 常量（`CatalogHealthCheck.key` 复用）；`api/health.py` 的 `/readyz` 聚合后按 `catalog` 检查项刷新 `bms_catalog_degraded`（失败 1 / 成功 0，与 `bms_dependency_up` 同点、写入失败静默）。
3. **SLO 告警规则**：`deploy/observability/rules/bms-slo.yml`——四组八条基座规则（`BmsServiceMetricsDown` / `BmsProbeFailing` / `BmsDependencyNotReady` / `BmsCatalogDegraded` / `BmsHighErrorRate` 0.1% / `BmsCriticalErrorRate` 5% / `BmsSlowRequestsP99` 0.8s / `BmsOutboxBacklog` 100），分级与 `for` 按设计；业务链路 SLO（登录 / 审批 / Socket.IO / 备份）注释留位登记。
4. **Alertmanager 与渲染通道**：`deploy/observability/alertmanager.yml.tmpl`（路由 / 分级 / 抑制 / receiver 骨架，占位符三块）+ `scripts/tools/observability/render_alertmanager.py`（读 `.env` → 渲染 `rendered/alertmanager.yml`；邮件 / webhook 条件分支、缺参跳过提示、幂等、`--check`）；`deploy/.gitignore` 忽略产物；`deploy/observability/rendered/.gitkeep` 保留目录；`.env.example` 增告警 / 探针 / 阶段度量变量段。
5. **探针观测**：`deploy/observability/blackbox.yml`（`http_2xx` 仅 200 成功）+ `prometheus.yml` 增 `bms-probe` job（`/probe`、`module=http_2xx`、relabel 生成 `instance` / `probe` 标签、指向 `blackbox-exporter:9115`）。
6. **编排与 Prometheus 接线**：`compose/observability.yml` 增 alertmanager（9093，挂渲染产物 + 命名卷）/ blackbox-exporter（9115，`extra_hosts` 探测宿主）/ pushgateway（宿主 9092 → 容器 9091，命名卷）；`prometheus.yml` 增 `rule_files` / `alerting`（`alertmanager:9093`）/ `pushgateway`（`honor_labels`）/ `alertmanager` 抓取与规则目录挂载。
7. **Grafana**：新增 `bms-slo.json`（告警状态 / 错误率 / P99 / 依赖 / 探针 / catalog 降级 / 发件箱 / 告警明细）与 `bms-stage-metrics.json`（发布成功率 / 发布次数 / 契约破坏数 / 运行期越界数 / 口径说明）；`bms-overview.json` 增 `service` / `version` 变量并按服务过滤（目录 provisioning 自动加载，无需改 loader）。
8. **用例编码**：`tests/tracing/test_cross_service_trace.py`（真实 uvicorn + httpx 网络，断言 traceparent 贯通 / 同 trace / 父链 / 上下文一致）；`tests/health/test_catalog_check.py` 增 `/readyz` 指标断言（1 / 0）；`tests/ops/test_observability_config.py` 增规则 / 组件 / 抓取 / 探针 / 面板 / 变量断言并更新组件清单断言；`tests/ops/test_render_alertmanager.py`（条件分支 / 缺参跳过 / 幂等 / `--check`）；`tests/metrics/test_metrics.py` 清单断言适配。
9. **门禁**：全量 `pytest`（1295 passed / 37 skipped）/ `ruff check` / `ruff format --check` / `pyright`（0 error）/ 基座与边界校验 / `check-status` / `check-preflight --fast` 全绿。
10. **mjbk 真实冒烟**：拉取三组件镜像（`拉取镜像.sh`，并登记镜像清单）→ 同步 `deploy/` 与 `backend/`（`~/bms-smoke/backend`，服务器 `uv sync --all-packages`）→ 本地渲染 Alertmanager 配置（no-op）随 `deploy/` 同步 → 一键 `up -d` → 逐项验证（组件 / 规则 / 探针 / 依赖指标 / 跨服务 trace / 告警真实触发与恢复 / 阶段度量样例 / 面板）→ 清理（服务进程、Pushgateway 样例、日志留痕）。
11. **登记回写**：部署发布规范 / 可观测性栈部署使用说明 / 开发部署规划 / 后端开发规范 / 后端基类清单 / 计划 / 父任务 / 任务 / scripts README / 镜像清单（见 §6）。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| httpx 埋点不覆盖 ASGI 传输（关键） | 跨服务用例首版用 `httpx.ASGITransport` 断言 CLIENT span，实际 exporter 只有 FastAPI 的 SERVER / 内部 span——查 instrumentor 源码确认补丁目标是 `AsyncHTTPTransport.handle_async_request`（真实网络层），ASGI 传输不被埋点 | 用例改为**真实 uvicorn（后台线程）+ 真实 httpx 网络请求**，断言 CLIENT / SERVER 双 span、同 trace、父链与上下文一致（0.3s，稳定） |
| Alertmanager 空 receiver 合法性 | 无凭据时 receiver 仅声明名称（no-op），不确定配置校验是否允许 | mjbk 实测 `amtool check-config` **SUCCESS**（空 receiver 合法）；模板保留 no-op 形态，部署说明写明「无凭据仅 UI 可见」 |
| Pushgateway 推送 400 | `odd number of components`（路径 `/metrics/job/bms-ci/platform` 被解析为额外 label）；修正后 `unexpected end of input stream`（数据末尾缺换行） | 推送路径改 `/metrics/job/bms-ci`；数据以 `printf` 保证末尾换行（命令模板入部署说明） |
| Pushgateway 样例清理 404 | `DELETE /api/v1/metrics/job/...` 与 `/api/v1/admin/wipe` 均 404——admin API 默认关闭（未启 `--web.enable-admin-api`） | 不为清理放宽安全默认；改**停容器 → 删数据卷 → 重建**（`compose_pushgateway-data`）清空样例（组数 0 实测） |
| `pkill -f` 误杀 SSH 会话 | 远端清理命令字符串含 `bms_platform`，`pkill -f` 匹配到 sshd 的子 shell 导致会话中断、后续命令未执行 | 改按 PID 精确清理（`ps -ef \| awk '/[b]ms_(identity\|platform)/ {print $2}'` 再 `kill`；`[b]` 技巧避免匹配命令自身） |
| Grafana 管理凭据缺失 | 服务器 `deploy/.env` 无 `GRAFANA_ADMIN_*`（默认口令亦不匹配旧数据卷），API 认证失败 | 面板验证改经容器挂载与 provisioning 日志（三张面板文件在、`finished to provision dashboards`），不触碰凭据 |
| 越界指标标签与设计初稿不符 | 设计 §4.6 写 `service` / `table` / `action` / `verdict`，实际为 `service` / `prefix` / `owner` / `operation`（05_02 实现） | 回写设计（§4.6 表 + 决策记录第 17 项）；`METRIC_DOCS` 文案同步修正为「按服务 / 表前缀 / 归属 / 操作」 |
| 阶段度量面板标签口径 | `bms_outbox_backlog` 实际仅 `service` 标签（无库键标签） | 面板 `legendFormat` 改为 `{{service}}`（设计文档口径以实现为准） |
