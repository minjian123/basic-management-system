## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记（先登记后编码）**：登记输入 `test/scripts/kiwi/cases/2026-09-23_阶段二03-03_服务目录只读接口.json`，平台回读编号 **2164**（导出落 `test/scripts/kiwi/exports/2026-09-23_阶段二03-03_登记回读.json`）。
2. **平台库只读会话依赖**：`db/session.py` 的 `_open_session` / `_resolve_engine` 增 `db_key` 参数（None 保持按请求租户上下文解析，既有行为不变）；新增 `get_platform_read_db`（`PLATFORM_DB_KEY` + `read_only=True`，无副本回落主库、按方言分流）；`api/deps.py` 导出并补重导出用例。
3. **依赖工厂校验口径修复**（实施中发现并追加确认）：`api/base.py` 新增私有 `_build_query`——`page_query` / `sort_query` / `cursor_query` 内构造契约的 `ValidationError` 统一转 `ParamError`（10001），明细剔除 `ctx`（`value_error` 的 ctx 含不可序列化的异常对象，具体约束信息已在 `msg`）。
4. **只读仓储扩展**：`module_repository.py` 收敛 `_catalog_conditions`（`list_catalog` / `page_catalog` 同源），新增 `page_catalog`（排序 + `LIMIT/OFFSET` + 同条件 `COUNT`）与 `get_by_service_key`；声明 `sortable_fields = frozenset({"id"})`（基座要求可排序字段须有索引，`sys_module` 仅复合唯一约束）。
5. **只读路由重写**：`bms_platform/api/modules.py` 清单改读库（`page_query` + `status` / `group` + `BasePageResponse[ModuleResponse]`）；新增明细路由（`service_key` 优先、未命中回退 `module_key`、未登记 `NotFoundError`）；路由挂 `require_auth` 登录态占位；删除内存清单依赖与 `ModuleRegistry` 注入。
6. **测试库播种**：`services/platform/tests/conftest.py` 会话级平台库增 `seed_modules`（16 行服务目录），启动接库校验走非空对账路径；libs conftest 不动（保持空库路径覆盖）。
7. **用例与门禁**：`test_modules.py` 重写（分页 / 筛选 / 排序 / 明细 / 404 / 字段护栏 / 空库，Kiwi 28 / 2163 / 2164）；`test_router_base.py` 增依赖工厂口径用例；`test_engine_routing.py` 增平台库读会话用例；`test_module_repository.py` 增分页 / 按服务键用例并扩展只读护栏；全量门禁与 preflight 全绿。
8. **开发库实测**：`ops.seed_module` 幂等（新增 0 / 更新 0）；接口实测——清单 16 行分页结构、`group=foundation` 筛选、末页 `size=5`、`id` 降序、非法排序忽略、`page=101` → 200 + 10001、明细 `platform` / `pur`（回退）/ `ghost`（404 + 10002）、POST 405。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| 排序请求整体被忽略 | `page_catalog` 传 `order_by=module_key` 不生效（仍 `id` 序） | 基座排序白名单为类属性 `sortable_fields`（默认空）；按「可排序字段须有索引」口径声明 `{"id"}`（`sys_module` 仅复合唯一约束、无单列索引），其余排序项按白名单忽略回落 `id` 升序；详细设计 §4.2 补排序白名单口径 |
| 依赖工厂契约校验漏 500 | `page=101` 经 `page_query` 内 `BasePageQuery` 限深校验抛裸 `ValidationError` → 500 + 10000（`size=201` 走 FastAPI 参数校验则正常 10001） | 追加确认后修复：`_build_query` 统一转 `ParamError`（10001），三个依赖工厂共用；登记《后端基类清单》接口层基座行 |
| `ParamError(data=exc.errors())` 序列化失败 | 修复后 `page=101` 转 `ParamError` 但统一响应序列化报 `PydanticSerializationError`（`ctx.error` 为 `ValueError` 对象） | `exc.errors(include_context=False)` 取明细（`msg` 已含具体约束信息） |
| Ruff RUF022（`__all__` 未排序） | `api/deps.py` 的 `get_platform_read_db` 插入位置不合字母序 | 调整至 `get_permission_checker` 之后、`get_preference_store` 之前 |

## 6. 偏差与遗留 <a id="deviations"></a>

- **破坏性变更登记**：清单响应由数组改为分页对象（`{list, total, page, size}`）——消费方为零（前端与各服务均无调用，已检索确认），随本任务一次落地；OpenAPI 契约快照将随下次导出体现（归 09_需求契约门禁）。
- **范围追加**：依赖工厂校验口径修复（`page_query` / `sort_query` / `cursor_query` → 10001）为实施中发现、经用户追加确认的基座修复，已登记《后端基类清单》接口层基座行。
- **口径细化**：排序白名单当前仅 `id`（`sys_module` 无单列索引）；如需按 `module_key` 等排序，先加单列索引再扩白名单（归后续按需）。
- **归口（详见详细设计 §8）**：真实登录态与平台管理权限码 → 认证 / RBAC 阶段；i18n 名称 → 国际化阶段；oasdiff 契约快照门禁 → 09_需求；平台库只读副本真实化与达梦真库实测（CI `integration-dm8` 临时关闭）→ 后续。
