## 2. 实施概览 <a id="overview"></a>

```mermaid
flowchart LR
    A["Kiwi 用例登记（2163）"] --> B["core/version.py + CatalogError 40003"]
    B --> C["module_registry 接库校验内核"]
    C --> D["9 服务自报 CONTRACT_VERSION + ServiceIdentity"]
    D --> E["application 启动接线与顺序调整"]
    E --> F["ops/check_modules 双模式 + CI job 四步"]
```

结果小结：启动由「仅内存清单校验」升级为「离线清单 + 接库目录」双层校验（空目录告警放行、冲突经 `CatalogError` 拒启并释放已装配资源）；服务包自报契约版本经 `ServiceIdentity` 带入，启动比「自报 vs 登记」、CI 比「服务包 vs 清单」主版本；`ops/check_modules.py` 扩为离线 / 接库双模式，CI 冒烟 job 增「迁移 → 种子 → 接库校验」；只读边界由仓储 / 路由 / 启动快照三条护栏固化。全量 `pytest` / `ruff` / `pyright` / 基座校验 / preflight 全绿。

## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记（先登记后编码）**：登记输入 `test/scripts/kiwi/cases/2026-09-23_阶段二03-02_启动与CI唯一性校验.json`，平台回读编号 **2163**（导出落 `test/scripts/kiwi/exports/2026-09-23_阶段二03-02_登记回读.json`）。
2. **共享校验内核**：新增 `core/version.py`（`CONTRACT_VERSION_RE` / `contract_major`），`core/plugin.py` 删私有 `_CONTRACT_VERSION_RE` / `_contract_major` 改引共享实现（错误消息不变）；`ErrorCode.CATALOG = 40003` + `CatalogError(ConfigError)`（启动期致命）；`module_registry.py` 删本地 `_SEMVER_RE` 改用共享正则，新增 `ModuleRecord.from_row`、`validate_catalog`（库内查重 / 双向对账 / 运行服务契约主版本）与 `_diff_catalog` / `_check_running_service` / `_contract_compatible`。
3. **服务自报契约版本**：9 个服务包 `__init__.py` 新增 `CONTRACT_VERSION = "0.1.0"`；`ServiceIdentity` 增 `contract_version`、`attach_service` 增入参、`BaseServiceApplicationFactory.contract_version`；9 个 `main.py` 工厂显式从包常量声明。
4. **启动接线**：`service_lifespan` 顺序调整为「离线清单校验 → 开发库自动建表 → 接库服务目录校验 → 插件装配 → 就绪」；`_validate_service_catalog` 经 `session_scope` + `ModuleRepository.list_catalog` 读主库（只读语义、不提交），空目录 `warning("service_catalog_empty")` 放行、冲突 `critical("service_catalog_invalid")` + `CatalogError` 拒启、库不可读提示先执行迁移；启动失败路径补 `resources.aclose()`（释放引擎连接池，避免失败残留）。
5. **CI 离线校验**：`ops/check_modules.py` 双模式——默认离线（清单 + 服务包声明 AST 静态比对，服务工程 ↔ 清单双向），`--url` 接库（只读读库、空库判失败、库不可读给可读错误）；`.gitlab-ci.yml` `backend-modules` 冒烟 job 增「SQLite 临时库 `bms_ci_catalog.db` → Alembic 平台链迁移 → 种子 → 接库校验」。
6. **只读护栏**：仓储只读（AST 扫描自有方法无写动词、无 `self._session` 写调用）、服务目录路由仅 GET（以 OpenAPI 契约为准）、启动校验前后 `sys_module` 行快照一致。
7. **用例与门禁**：新增 `tests/core/test_version.py`、`tests/core/test_service_catalog_startup.py`，扩展 `test_module_registry.py` / `test_module_repository.py` / `test_check_modules.py` / 平台 `test_modules.py`（均标注 Kiwi 2163）；全量门禁与 preflight 全绿。
8. **开发库实测**：离线校验通过；CI 临时库实测「迁移 head 0002 → 种子 16 行 → 接库对账」通过；开发平台库接库对账通过；platform / identity 服务 lifespan 启动通过（身份 `0.1.0` / 契约 `0.1.0`）。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| 既有启动冲突用例断言失效 | 原断言 `RuntimeError` / 「模块注册校验失败」，现统一为 `CatalogError`（40003）/「服务目录校验失败」 | 按设计语义升级适配平台用例（异常类型与消息）；游离内建异常改统一异常基类 |
| Ruff B009（`getattr` 常量属性） | `ModuleRecord.from_row` 15 处 `getattr(row, "常量")` 被 B009 命中 | 改经 `cast("Any", row)` 后属性访问，保留字段级 `cast` 文档语义 |
| Pyright 报 `contextmanager` 弃用 | 测试日志捕获助手返回 `Iterator` 命中 typeshed 弃用重载 | 返回类型改 `Generator`；ORM 表 `create` 按既有口径 `cast("Table", …)` |
| 启动失败路径引擎残留 | 接库校验失败用例出现 aiosqlite 线程关闭期日志错误（引擎连接池未释放） | lifespan 启动段包 `try/except`，失败先 `resources.aclose()` 再抛（成功路径仍走原 `finally`） |
| 路由只读护栏取不到路径 | FastAPI 新版把 `include_router` 包为 `_IncludedRouter`，`app.routes` 不再展平业务路径 | 护栏改以 `app.openapi()["paths"]`（契约面）判定「`/api/v1/modules` 仅 get」 |
| 入口守卫用例 RuntimeWarning | `runpy.run_module` 报「found in sys.modules」（测试模块已导入同模块） | 用例显式 `pytest.warns(RuntimeWarning, match="found in sys.modules")` 断言该已知告警 |

## 6. 偏差与遗留 <a id="deviations"></a>

- **CI job 定义改动不在同一条流水线自验**：`backend-modules` 的迁移 / 种子 / 接库三步在下次命中 `backend/**` 路径的流水线生效（纯 CI 配置改动只跑 gate-smoke / base-integrity）；本次已在本地按同序完整实测（见 §5），配置改动风险低、可回退。
- **覆盖率说明**：`application.py` 未覆盖行为既有连接预算告警两行（无测试触发预算超限），非本次新增逻辑；本次新增模块与改动逻辑覆盖率 100%。
- **归口（详见详细设计 §8）**：只读 HTTP 接口 → 03_03；契约快照门禁与 `service_version` 回写 → 09_需求；跨服务数据所有权与每服务独立库 → 05_02 / 06_需求；真实库（MySQL / PostgreSQL / 达梦）迁移后查重未接入冒烟层（当前 SQLite 临时库；达梦接库路径未单独实测，随达梦环境修复）。
