## 4. 参考文档 <a id="ref"></a>

- 《架构设计 · API 网关与边缘》「安全边界」节

> **前置契约（已交付 · 07_01，2026-09-23）**：自托管 OIDC IdP（Keycloak）与后端 OIDC 客户端 / JWKS 验签已就位——IdP issuer 形如 `http://<idp-host>:8090/realms/bms`，JWKS `<issuer>/protocol/openid-connect/certs`；`bms_core/idp/jwks.py` 提供 JWKS 缓存与 JWT 验签助手（仅 RS256/ES256、校验 `exp`/`iss`/`aud`），`OidcIdentityProvider.verify_token` 为后端侧统一票据校验入口。**本任务接线点**：网关 `openid-connect` 插件按 issuer / JWKS 校验用户 JWT（APISIX 侧自带 JWKS 缓存），`exp`/`iss`/`aud` 口径与后端 `verify_token` 保持一致；后端服务间服务 JWT 校验可复用 `idp/jwks.py` 助手，校验通过后经 `ROUTE_HEADERS_SET` 注入可信身份并按 `[edge].provider` 替换边缘信任实现。

> **前置契约（已交付）**：04_02（2026-09-23）已交付边缘身份头契约与请求净化机制——身份头常量单一来源 `bms_core/edge/headers.py`（`X-User-Id` / `X-Tenant-Id` / `X-User-Scopes` / `X-Service-Identity` / 网关标记 `X-Gateway-Identity`）、后端边缘信任能力域 `bms_core/edge/`（`BaseEdgeTrust` 契约 + `get_edge_trust` 提供者 + 授权下沉依赖 `require_edge_identity` + `EdgeGuardMiddleware` 剥头 / 信任注入 / 旁路拒绝）、网关声明式净化（`global_rules::edge-sanitize` 剥除客户端伪造身份头 + 路由级 `proxy-rewrite.headers.set` 置网关标记）、路由级身份注入钩子 `ROUTE_HEADERS_SET`（`bms_core/services/gateway_catalog.py`，默认空）。**本任务接线点**：接入真实用户 JWT（`openid-connect` / JWKS）与服务 JWT 校验后，经 `ROUTE_HEADERS_SET` 按服务填充身份头（如 `{"X-User-Id": "$jwt_claim_sub", "X-Tenant-Id": "$jwt_claim_tenant", ...}`）；以真实服务 JWT 校验实现替换 `[edge].provider`（`marker` → 真实实现），`require_auth` 由占位切到真实用户体系；`X-Service-Identity` 服务身份注入与旁路防护真实化。身份头契约与剥除 / 标记配置结构不变。

> **前置契约（已交付 · 04_03，2026-09-23）**：边缘限流已按真实客户端 IP 落地（`limit-count` + 共享 Redis，见 04_03）。**本任务限流维度扩展钩子**：`bms_core/services/gateway_catalog.py::rate_limit_plugin` 的 `key` 参数为唯一接线点——注入身份头后改 `key_type=var_combination`、`key="$remote_addr $http_x_tenant_id $http_x_user_id"` 即扩为用户 / 租户维度；客户端（client_id）维度随开放接口阶段。生成结构不变。
