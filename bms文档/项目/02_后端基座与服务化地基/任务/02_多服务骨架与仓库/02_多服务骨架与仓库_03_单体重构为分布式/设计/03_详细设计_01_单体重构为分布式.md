## 1. 概述 <a id="overview"></a>

- **目标**：把 `bms_platform` 单服务承载的全部业务模块按限界上下文拆入新增服务工程（用 `scripts/new_service.py` 同构生成），把每服务都需要的应用装配逻辑沉淀为 `bms_core` 的**共享服务应用基座**，并按服务边界迁移路由、骨架表模型与测试；补齐「禁跨服务 import / 禁跨库访问」的边界硬校验接线。完成后「一服务一工程、服务内五层、服务只依赖共享库与自身、既有接口契约与业务语义不变」可执行验证。
- **依据**：《微服务演进规划》「目标架构与服务清单」「与现状差异及迁移」节；《架构设计 · 总体架构》「分层视图」「进程模型」「工程结构（Monorepo）」节；《后端开发规范》「目录与分层职责」「依赖方向」「后端基座体系」节；需求 [02-3](../../../../需求/02_需求_多服务骨架与仓库.md#r02-3)。
- **范围（本任务）**：
  1. **共享服务应用基座**：把 `bms_platform.main` 的通用装配（服务身份 / 中间件 / 异常处理 / 状态与前缀工厂 / 引擎注册表 / 租户源 / 插件装配 / lifespan）抽为 `bms_core` 的 `application.py`（包根组合根：装配必然触达 `api` / `services`，置包根以满足 `core → api/services` 反向依赖约束）（`service_lifespan` + `BaseServiceApplicationFactory`），各服务只声明身份与业务路由。
  2. **服务拆分**：保留 `services/platform`（平台地基 / 配置服务），新增 8 个服务工程 `identity` / `tenant` / `org` / `file` / `notification` / `search` / `ai` / `report`，各含独立 `pyproject.toml`（依赖 `bms-core`）、`src/bms_<名>/`（入口 + 五层 + 路由聚合）、`tests/`。
  3. **路由迁移**：现有 16 个路由按服务归属迁移；跨路由复用的辅助函数（`current_code_of`）沉淀进 `bms_core`。
  4. **骨架表模型归属**：`ai_chat_log` → `ai`；`sys_notification` → `notification`；`sys_task` / `sys_task_log` / `sys_user_preference` / `sys_icon` / `sys_icon_i18n` 随 `platform`；`sys_tenant` / `sys_module` 暂留 `bms_core`。
  5. **测试随边界走**：`services/platform/tests` 的 68 个测试文件按域归属整目录迁移（路由 / 能力域随服务、无路由的共享能力域随实现入 `bms_core/tests`），各服务独立 `conftest.py`。
  6. **边界硬校验**：`check-service-boundaries.py` 四规则接入 CI `base-integrity`（此前未接），新增**第 5 规则（表 / 表前缀跨服务唯一）**与自检样例。
  7. **工程适配**：根 `pyproject.toml`（isort 第一方 / pyright extraPaths / pytest testpaths）、`.gitlab-ci.yml`（`--cov` 覆盖各服务）、`deploy/ci/Dockerfile.backend`（成员 pyproject）、`scripts/new_service.py`（改用共享基座）、`backend/README.md`。
- **不含（明确归口，见第 8 节）**：能力域**实现**不迁出 `bms_core`（本任务只迁路由 / 装配 / 测试）；服务目录与注册要素登记（`sys_module` 服务维度 / 契约版本 / 种子）归 03_01；每服务独立配置与迁移链归 06_需求；运行时跨库检测 / 读侧出口 / 越界度量归 05_02；父-子流水线与按服务构建发布归 09_需求；无现有代码的目标服务（任务调度 / 工作流 / 表单定制 / 公告 / 导入导出 / 开放接口 / 归档 / 备份 / 回收站 / 首页工作台 / 权限 / 审计 / 会话等）不预建骨架。

## 2. 现状与差距 <a id="gap"></a>

| 关注点 | 现状（02_02 交付后） | 差距（本任务目标） |

## 4. 领域设计 <a id="design"></a>

### 4.1 服务清单与路由 / 能力域 / 测试归属 <a id="services"></a>

服务命名沿用 `bms_<英文短名>`（与 `bms_core` / `bms_platform` 同构）；目录名与服务短名一致。归属映射如下（“能力域测试”指 `services/platform/tests/<域>/` 整目录迁移落点）：

| 服务（目录 / 包） | 服务名 / 标题 | 承载路由 | 迁入的能力域测试 | 迁入的骨架表模型 |
| --- | --- | --- | --- | --- |
| `platform` / `bms_platform` | `platform` / `BMS 基础管理系统`（保留） | `modules` `plugins` `demo` `dict` `icon` `preference` `query_scheme` `codecheck` | dict / icon / preference / listing / codecheck + api / models / schemas / services / repositories / core / crosscut / integration / contracts / health | `sys_task` `sys_task_log` `sys_user_preference` `sys_icon` `sys_icon_i18n` |
| `identity` / `bms_identity` | `identity` / `BMS 认证与身份服务` | `captcha` | captcha / idp / oauth / password | — |
| `tenant` / `bms_tenant` | `tenant` / `BMS 租户与配置服务` | `tenant` | tenant | — |
| `org` / `bms_org` | `org` / `BMS 组织主数据服务` | `org` | org | — |
| `file` / `bms_file` | `file` / `BMS 文件服务` | `file` | storage | — |
| `notification` / `bms_notification` | `notification` / `BMS 通知服务` | `notification` | notification / notify / ws | `sys_notification` |
| `search` / `bms_search` | `search` / `BMS 检索服务` | `search` | search / globalsearch | — |
| `ai` / `bms_ai` | `ai` / `BMS AI 服务` | `chat` | chat / llm | `ai_chat_log` |
| `report` / `bms_report` | `report` / `BMS 报表打印服务` | `print` | print | — |
| `bms_core`（共享库，非服务） | — | — | archive / audit / circuit / dashboard / fallback / fieldtype / i18n / idempotency / lock / metrics / outbound / query / ratelimit / replay / tracing / transfer / workflow | `sys_tenant` `sys_module`（暂留） |

- **能力域实现不迁**：`bms_core/<能力域>`（含 `dict` / `storage` / `cache` 真实实现与各 null 实现）全部保留在共享库；服务经依赖注入（`bms_core.api.deps`）与插件注册表消费，行为不变。
- **平台地基路由留 `platform`**：服务目录（`modules`）、插件清单（`plugins`）、字典 / 图标 / 偏好 / 查询方案 / 代码校验同属平台配置能力，随 `platform`；认证（`captcha`）与租户（`tenant`）虽为地基服务，按其限界上下文独立成服务。
- **`globalsearch` 随 `search`**：检索查询能力域（多域聚合 / 审计检索 / 文件内容检索）与其路由 `/api/v1/search` 同服务；`bms_core.search`（全文索引写入契约）无路由，其测试随共享能力域（`search/` 整目录随 `search` 服务，见映射——本表按「有路由能力域随服务」口径归属）。

> 说明：`bms_core.search`（`BaseSearchIndex`）与 `globalsearch`（查询聚合）紧邻，二者测试同迁 `search` 服务，避免检索域测试分散。

### 4.2 共享服务应用基座 <a id="app-base"></a>

新增 `bms_core/application.py`，把 `bms_platform.main` 现有通用装配原样上提（行为不变）：

```text
bms_core/application.py
├── service_lifespan(app)                 # 共享 lifespan：启动校验 → 插件装配 → 开发库自动建表 → 就绪标记；
│                                         #   关闭：取消就绪 → ResourceManager 逆序释放（02_02 语义不变）
└── BaseServiceApplicationFactory(BaseApplicationFactory)   # 服务应用工厂基座
    ├── service_name / service_title / version             # 服务身份（子类声明）
    ├── service_routers() -> Sequence[APIRouter]           # 子类覆写：业务路由（探针由基座统一挂载）
    ├── prepare_settings(settings) -> None                 # 钩子：创建前调整配置（脚手架置空健康 provider）
    ├── configure_service(app, settings) -> None           # 钩子：服务专属 state（platform 注入 demo_service）
    └── create(options) -> FastAPI                         # 通用装配编排（原 bms_platform.main.create 逐项等价）
```

- **通用装配编排（与现状逐一对应）**：`get_settings` → `prepare_settings` → `configure_logging` → `FastAPI(title/service_title, version)` → `attach_service`（02_02）→ 中间件（只读 / 请求日志 / 链路 / 租户）→ 异常处理器 → `app.state`（resources / module_registry / settings / startup_complete）→ `register_platform_plugins` → `build_plugin_registry` → 工厂登记与解析（engine / session / id）→ `EngineRegistry` / `PrimaryHealth` / `TenantSource` → 资源登记 → `configure_service` → 根路由（`{name, version}`）→ 挂载共享探针路由 + `service_routers()`。
- **探针统一**：`/healthz` `/readyz` 由基座统一挂载 `bms_core.api.health.router`，各服务无需自建（平台服务与脚手架同受益）。
- **不改行为**：路由前缀与响应体、中间件顺序、插件装配语义、探针口径、迁移链路与表集、四库方言行为均不变（由既有测试迁移后全绿证明）。
- **落地**：`bms_platform/main.py` 改为 `class ApplicationFactory(BaseServiceApplicationFactory)` 声明身份 + `service_routers()` + `configure_service()`（demo 注入），删除本地 lifespan 与装配；各新服务 `main.py` 同构。

### 4.3 服务工程骨架与同构接入 <a id="skeleton"></a>

每个服务工程（`services/<名>/`）由 `scripts/new_service.py` 生成后填入迁移件，结构与 `platform` 同构：

```text
services/<名>/
├── pyproject.toml                 # 包 bms-<名>，依赖 bms-core；[tool.uv.sources] bms-core = { workspace = true }
├── src/bms_<名>/
│   ├── __init__.py                # __version__ + SERVICE_NAME + SERVICE_TITLE
│   ├── main.py                    # ApplicationFactory（共享基座 + 身份 + service_routers）
│   ├── asgi.py / __main__.py      # uvicorn 入口 / python -m bms_<名>
│   ├── api/{__init__,router}.py   # 路由聚合（业务路由经 register_router / build_api_router 挂 /api/v1）
│   ├── api/<路由>.py              # 迁入的业务路由（只做参数校验与路由分发）
│   ├── services/ repositories/    # 五层（按需；本任务多为占位 docstring）
│   ├── models/                    # 骨架表模型（仅 notification / ai 有）
│   └── schemas/                   # 请求响应契约（按需）
└── tests/                         # conftest.py（client）+ 迁入的域测试
```

- **测试夹具**：各服务 `tests/conftest.py` 沿用 `platform` 现有夹具（`isolate_settings` / `platform_db` / `reset_request_context` / `client`），`client` 改由本服务 `ApplicationFactory` 构造应用。
- **无状态服务**（identity / tenant / org / search / report 等暂无新表）五层目录保留占位 docstring，符合脚手架约定。

### 4.4 路由迁移与共享助手沉淀 <a id="route-move"></a>

- **路由迁移为文件搬迁**：`bms_platform/api/<路由>.py` → `bms_<服务>/api/<路由>.py`；路由内容（前缀 / tags / 依赖 / 响应）不变，仅调整 import 头。
- **共享助手沉淀**：`bms_platform/api/tenant.py` 的 `current_code_of(tenant)` 被 `icon` / `codecheck` / `print` 复用，迁为 `bms_core/api/deps.py` 的 `current_code_of`；迁移后的 `icon` / `codecheck` / `print` / `tenant` 路由统一从 `bms_core.api.deps` 导入（消除跨路由 / 跨服务引用）。
- **路由聚合**：各服务 `api/router.py` 仅登记本服务业务路由（经新增的 `mount_service_routers` 以**服务级登记表**挂 `/api/v1`，避免多服务同进程经全局登记表串扰）；`bms_platform/api/router.py` 去掉 `health_router`（基座统一挂载）并收敛为平台路由。
- **不改契约**：`/api/v1/...` 前缀、请求 / 响应体、错误码、鉴权占位语义全部保持（现有路由测试迁移后断言不变）。

### 4.5 骨架表模型归属 <a id="models"></a>

| 模型 | 现位置 | 迁移后 | 依据 |
| --- | --- | --- | --- |
| `AiChatLog`（`ai_chat_log`） | `bms_platform/models/ai.py` | `bms_ai/models/ai.py` | AI 域数据所有权 |
| `SysNotification`（`sys_notification`） | `bms_platform/models/system.py` | `bms_notification/models/notification.py` | 通知域数据所有权 |
| `SysTask` / `SysTaskLog` / `SysUserPreference` / `SysIcon` / `SysIconI18n` | `bms_platform/models/system.py` | 留 `bms_platform/models/system.py` | 无对应服务（任务调度 / 通用能力阶段），随 `platform` |
| `SysTenant` / `SysModule` / `SysModuleI18n` | `bms_core/models/platform.py` | 留 `bms_core/models/platform.py` | 平台基础模型，所有权随服务边界定案（02_01 开放项） |

- 迁移后各服务间**无模型互引**（护栏保证）；表结构 / 迁移链表集不变（骨架表本就不在任何迁移链表集，见 02_01 §4.8）。

### 4.6 测试组织与迁移 <a id="tests"></a>

- **归属口径**：测试随其验证对象的服务边界走——**打某服务业务路由 / 装配某服务应用**的测试随该服务；**只验证共享能力域契约与实现**（不依赖具体服务路由）的测试随 `bms_core`。
- **基座侧测试应用夹具**：`libs/bms_core/tests/conftest.py` 新增一个最小测试服务工厂（`BaseServiceApplicationFactory` 子类，无业务路由）与 `app_factory` / `client` 夹具，供迁入的共享能力域测试构造应用与探针（原 `bms_platform.main.ApplicationFactory` + `lifespan` 的等价替换：`app = app_factory().create(None)`、`async with app.router.lifespan_context(app)`）。
- **平台测试支撑保留**：`tests/contracts/`（插件契约套件与支撑 `support.py`）、`tests/crosscut/`、`tests/api/` 留 `platform`；迁入 `file` 的 `storage` 测试所需的 `build_snapshot` 支撑改由本地小工具替代（不经跨包导入）。
- **迁移清单**（整目录 `git mv`，随后改写 import 与夹具用法）：
  - `platform`：`api/`（main / health / modules / plugins / demo / errors / router_base / request_logging）、`dict/`、`icon/`、`preference/`、`listing/`、`codecheck/`、`models/`、`schemas/`、`services/`、`repositories/`、`core/`、`crosscut/`、`contracts/`、`integration/`、`health/`。

- **根 pytest 汇总**：`testpaths` 覆盖 `libs/bms_core/tests` + `services/*/tests`，一条命令跑全量；覆盖率按包名汇总。
- **Kiwi 断言不重编号**：既有用例号随测试文件迁移保留（`kiwi_id` 标注不变）。

### 4.7 边界硬校验接线 <a id="guard"></a>

`scripts/tools/base-check/check-service-boundaries.py`：

| # | 规则 | 口径 | 变更 |
| --- | --- | --- | --- |
| 1 | 共享库不得依赖服务 | `libs/*` 不 import `services/*` 包 | 已有 |
| 2 | 服务不得互相依赖 | 任一服务不 import 另一服务包 | 已有 |

## 5. 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| 服务 import 另一服务内部实现 | 护栏规则 2 / 4 失败，CI 拦截 |
| `bms_core` import 服务 | 护栏规则 1 失败，CI 拦截 |
| 服务内反向依赖（如 models→api） | 护栏规则 3 失败，CI 拦截 |
| 两服务声明同名表 / 同表前缀（非 `sys_`） | 护栏规则 5 失败，CI 拦截 |
| 路由迁移后 import 断链 | 全量 pytest 收集即暴露（ImportError）；逐服务补正 |
| 共享能力域测试迁入 `bms_core` 后无应用可建 | 基座 `conftest` 提供测试应用工厂与夹具；迁入测试改用夹具 |
| platform 去 `health_router` 后平台探针缺失 | 探针由基座统一挂载，`test_health` 迁移后仍断言 200 / 503 |
| `current_code_of` 迁移后旧引用未改 | 全量 pytest + pyright 暴露；改从 `bms_core.api.deps` 导入 |
| 新增服务未装入工作区 venv | `uv sync` 装配 `services/*` 成员；Dockerfile / job 补成员 pyproject |
| 迁移改正了业务语义 | 以「路由前缀 / 响应体 / 错误码 / 中间件顺序 / 探针口径 / 迁移链表集不变」守恒，由既有测试迁移后全绿证明 |
| 每服务端口冲突（本地并行） | 本任务不落每服务配置；本地并行经 `BMS_SERVER__PORT` 覆盖，正式每服务配置归 06_需求 |

## 8. 边界与开放项 <a id="boundary"></a>

- **归 03_01**：服务目录登记（`sys_module` 服务维度 / 契约版本 / 注册要素取值与种子）；`sys_` 前缀在服务间的归属拆分。

- **不改**：路由前缀与业务响应体、中间件顺序、插件装配语义、探针口径、迁移链路与表集、四库方言行为、既有 Kiwi 用例号。
