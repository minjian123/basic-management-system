## 2. 任务内容 <a id="content"></a>

1. **启动器替换**：`bms_core/core/run.py` 由 uvicorn 换 **hypercorn**——`build_server` 按 `[server]` 的 host / port 构造 hypercorn 配置，`run_service` 以 hypercorn 的 asyncio 服务入口启动；保留单进程口径（一服务一容器）、`log_config=None` / 关闭 access log、structlog 统一渲染。
2. **信号先摘流**：SIGTERM / SIGINT 到达时先调用注入的 `ServiceRuntime.start_drain()`（`/readyz` 随即 503），再触发 hypercorn 停止接新连接 → 等待在途 → lifespan shutdown → 释放资源；二次信号强制退出；`start_drain` 幂等。hypercorn 无 uvicorn `handle_exit` 等价钩子，需在启动器内接管信号并以 `shutdown_trigger` 驱动，行为与原 `ServiceServer` 对齐。
3. **依赖落点**：`hypercorn` 写进 `bms_core` 依赖，所有服务与产品经 bms-core 传递获得；bms 9 个服务 `pyproject` 移除 `uvicorn[standard]`；`uv.lock` 更新；不保留 uvicorn 运行时开关，回滚靠镜像。
4. **TLS 配置**：`[server]` 增可选 `certfile` / `keyfile`（二者同时给或同时空，否则启动即校验失败）；配置齐全时启用 TLS 并由 ALPN 协商 h2；未配置时仍提供 **h2c prior knowledge**；不支持 `Upgrade: h2c`（文档写明，RFC 允许）。
5. **协议与兼容**：HTTP/1.1 行为不变；WebSocket 走 HTTP/1.1；健康探针 `/healthz` / `/readyz` 与依赖就绪聚合口径不变；不改业务端点、鉴权、租户与审计。
6. **全产品回归**：bms 9 个服务 + mdm 在役服务——启动、`/healthz` `/readyz`、HTTP/1.1 请求、h2c 握手、SIGTERM 优雅停机、滚动重启。
7. **文档与脚本同步**：`backend/README.md`（技术栈、启动命令、版本表）、`scripts/tools/governance/review_stage.py`（README 期望串）、`规划/开发部署规划.md` 与 `规划/项目规划说明.md`（uvicorn 命令 / 技术栈摘要）、《[后端基类清单](../../../../../后端基类清单.md)》（`core/run.py` 描述）、必要时《[后端开发规范](../../../../../规范/后端开发规范.md)》。
8. **测试**：改造 `libs/bms_core/tests/core/test_run.py`（配置构造 / 信号先摘流 / 二次信号）；新增 TLS 配置校验用例；新增 h2c 握手与 HTTP/1.1 回归冒烟；mdm 启动与探针冒烟。
9. **边界**：不做 msg 帧协议（msg 03 域）、不做网关 h2c 上游配置（部署任务）、不做多 worker（沿用一服务一容器横向扩容）、不做 HTTP/3（hypercorn 能力保留但本期不验）。

## 3. 完成标准 <a id="accept"></a>

- `bms_core` 依赖包含 hypercorn，9 个服务与 mdm 无直接 uvicorn 依赖；锁文件一致。
- `[server]` 的 TLS 字段「同给 / 同空」校验生效；TLS + ALPN 与 h2c prior knowledge 均可握手。
- SIGTERM 到达先摘流（`/readyz` 503）再排空在途；二次信号强制退出；`start_drain` 幂等。
- bms 9 服务 + mdm 启动、探针、HTTP/1.1 请求、h2c 握手、滚动重启全部通过。
- README / 治理脚本 / 规划 / 基类清单同步，`review_stage` 与文档三项校验通过。
- 变更模块行 + 分支覆盖率 100%，`pytest` / `ruff` / `pyright` 全绿。
