## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记（先登记后编码）**：登记 1 条策展用例，平台回读编号 **2419**；覆盖启动器配置映射、信号先摘流与二次强退、TLS 字段校验、h2c / TLS 真网络握手、全产品冒烟。
2. **依赖切换**：`bms_core/pyproject.toml` 增 `hypercorn>=0.18,<0.19`；bms 9 个服务与 mdm `services/org` 删除 `uvicorn[standard]`；`uv lock` / `uv sync --frozen` 后 hypercorn 0.18.0 与 `h2` / `hpack` / `hyperframe` / `priority` / `wsproto` 就位，uvicorn / uvloop / httptools / watchfiles / websockets 退出依赖树。
3. **配置字段**：`core/config.py` 的 `ServerSettings` 增 `certfile` / `keyfile`（默认空，`model_validator` 校验同给或同空）与 `graceful_timeout_seconds`（默认 30，`ge=1, le=600`）；`config.toml` / `.env.example` 补注释与键位。
4. **启动器重写**：`core/run.py` 删除 `ServiceServer` / `build_server`，改为
   - `build_config`：bind、`workers=1`、关闭 access / error 日志、`graceful_timeout`、TLS 路径存在性校验；
   - `serve_service`：安装 `SIGTERM` / `SIGINT` / `SIGBREAK`（Windows 回退 `signal.signal`），第一次信号先 `start_drain()` 再置 `shutdown_trigger`，第二次信号记日志后 `os._exit(1)`，`finally` 恢复原处理器；
   - `run_service`：取配置 → 初始化日志 → 构造应用 → 取 `ServiceRuntime` → `asyncio.run(serve_service(...))`。
5. **日志口径**：hypercorn 自带 access / error 日志关闭；`core/logging.py` 的处理器清理补 `hypercorn` / `hypercorn.error`，并关闭 `hypercorn.access`，structlog 继续统一渲染。
6. **既有用例迁移**：`test_cross_service_trace.py` 由后台线程起 uvicorn 改为起 hypercorn（`shutdown_trigger` + 端口就绪轮询）；`test_run.py` 重写并补 TLS 半配置、事件循环优先、`signal.signal` 回退、处理器恢复失败分支；`test_config.py` 补 TLS 配对与超时边界；新增 `test_http2_runtime.py`（HTTP/1.1、h2c、TLS ALPN）。
7. **脚手架与文档同步**：`scripts/new_service.py` 模板不再生成 uvicorn 依赖、命令改 hypercorn；9 服务 `asgi.py` 与平台 `main.py` docstring 同步；`backend/README.md`、`config.toml`、`.env.example`、`review_stage.py` 期望串、`规划/开发部署规划.md`、`规划/项目规划说明.md`、`后端基类清单.md`、`设计/基类体系/后端基类实现契约.md`、架构设计（总体架构 / 性能与安全 / 决策与风险）与《英文简称规范》同步。
8. **冒烟**：以临时端口逐个启动 bms 9 服务与 mdm，验证 `/healthz`、`/readyz`、HTTP/1.1、h2c 与 SIGBREAK 优雅退出；mdm 单机冒烟以测试环境开关（`registry.register_on_startup=false` / `topology.distribute=false`）跳过跨进程登记，并注入临时服务令牌密钥。
9. **门禁**：单文件 `ruff check` / `ruff format --check`、`uv run pyright`、定向 `pytest` 全绿；`core/run.py` 模块级覆盖率 **100%**。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| hypercorn 类型与 starlette 不同源 | `pyright` 严格模式报 `serve` 部分未知与 `FastAPI` 不能赋给 `Framework` | 上游类型未对齐，运行时无影响；按仓库既有口径加两处细粒度 `# pyright: ignore[...]` 并注明原因，不改调用 |
| 信号钩子差异 | hypercorn 无 uvicorn `handle_exit` 等价钩子 | 传入 `shutdown_trigger` 时 hypercorn 不注册信号，由 `serve_service` 自建控制器：第一次摘流 + 置事件，第二次强退 |
| 明文 h2c 协商失败 | 仅 `http2=True` 时客户端仍走 HTTP/1.1 | `httpx.AsyncClient(http2=True, http1=False)` 才发 HTTP/2 preface（已写入用例与协议说明） |
| 既有链路用例依赖 uvicorn | `test_cross_service_trace.py` 直接 `import uvicorn`，依赖移除后失败 | 改为后台线程起 hypercorn，端口就绪轮询替代 `server.started`，停机用 `threading.Event` 驱动 |
| 冒烟子进程日志阻塞 | 以 PIPE 收集 DEBUG 日志时管道写满，服务启动阻塞、连接超时 | 冒烟脚本改日志落 `tmp/` 文件，启动与探针恢复正常 |
| mdm 单机启动依赖平台 | 启动期上报声明 / 拉拓扑失败即拒启 | 冒烟显式关闭 `registry.register_on_startup` 与 `topology.distribute`（测试环境开关），并注入临时服务令牌密钥；跨进程上报由部署环境覆盖 |
| 脚手架仍生成 uvicorn | 新服务会继续引入旧服务器 | `new_service.py` 模板移除 uvicorn 依赖并改命令，避免新服务与基座分叉 |

## 7. 偏差与遗留 <a id="deviations"></a>

- **偏差（已闭环）**：① `core/run.py` 公开 API 按拍板改名 `build_config` / `serve_service` / `run_service`，删除 `ServiceServer` / `build_server`；② 优雅停机超时从 hypercorn 默认 3s 改为 `[server].graceful_timeout_seconds`（默认 30）；③ 既有跨服务链路用例改用 hypercorn（依赖移除的必然结果）；④ `core/logging.py` 追加清理 hypercorn 日志器，属接口替换的连带改动。
- **遗留（归口）**：① HTTP/1.1 无 httptools，吞吐可能低于原 uvicorn，由 msg 03-1 基准评估，不达标再另议 uvloop / granian；② 证书热轮换不做，重启生效（部署任务）；③ `workers > 1` 在 hypercorn `serve` 下无效，维持一服务一容器横向扩容；④ 响应头 `server: hypercorn-*` 是否隐藏另议（安全扫描口径）；⑤ mdm 跨进程声明上报 / 拓扑分发未在单机冒烟覆盖，由部署环境回归。
