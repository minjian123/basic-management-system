## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记（先登记后编码）**：登记 1 条策展用例覆盖全部断言面，平台回读编号 **1205**；登记输入 `scripts/kiwi/cases/2026-09-22_阶段二02-02_服务运行与健康检查.json`（实施中补充脚手架 null 就绪说明并同步平台正文）。
2. **服务运行时基座**：新增 `libs/bms_core/src/bms_core/core/service.py`——`ServiceIdentity`（名称 / 版本 / 中文名）+ `ServiceRuntime`（登记身份、`draining` 标记、`start_drain()` 幂等摘流）+ `attach_service`（解析身份：包声明默认 + `[app].service` 覆盖、配置为空回写解析结果；绑定日志上下文；落 `app.state.service_runtime` / `service_identity` / `draining`）+ `bind_service_identity`（structlog 全局上下文绑定 `service` / `service_version`）。
3. **配置驱动启动入口**：新增 `core/run.py`——`ServiceServer(uvicorn.Server)` 覆写 `handle_exit`（先 `start_drain` 再 `super().handle_exit`）、`build_server`（按 `[server]` host / port 构造 uvicorn 配置，日志走 structlog）、`run_service`（取配置 → 初始化日志 → 构造应用 → 取运行时作停机回调 → 启动）。
4. **配置与日志**：`core/config.py` 的 `AppSettings.service` 默认由 `"platform"` 改为 `""`（`config.toml` 移除硬编码、`.env.example` 注明为可选覆盖）；`core/logging.py` 处理器链首部加 `structlog.contextvars.merge_contextvars`，使身份字段对业务日志与 uvicorn / stdlib 日志一并生效。
5. **探针**：`api/health.py` 两探针追加服务身份 `service` / `version`（无身份不附加）；`/readyz` 在 `draining` 或启动未完成时返回 503 空 checks（不执行依赖探测）。
6. **平台服务接入**：`bms_platform/__init__.py` 新增 `SERVICE_NAME` / `SERVICE_TITLE`；`main.py` 经 `attach_service` 接入运行时（title / 根路由取身份常量）；新增 `__main__.py`（`python -m bms_platform`）。
7. **脚手架升级**：`scripts/new_service.py` 模板——`__init__` 加身份声明、`main.py` 经 `attach_service` 接入且就绪回退 null 注册表（最小服务无依赖检查）、新增 `__main__.py`、冒烟用例覆盖 `/healthz` `/readyz`。
8. **用例**：新增 `test_service_runtime.py`（身份解析 / 配置覆盖 / 日志绑定与处理器链 / drain 幂等）、`test_run.py`（启动配置 / `handle_exit` 顺序 / `run_service` 主流程）、`test_service_lifecycle.py`（平台身份 / 摘流 503 / lifespan 释放）；更新 `test_health.py`（探针身份 + 无身份回退 + 503 分支）、`test_new_service.py`（`__main__` + 探针）、`test_config.py` / `test_tenant_routing.py`（服务标识默认口径）。
9. **门禁与冒烟**：全量 `pytest` / `ruff` / `pyright` / 基座校验 / 边界护栏 / 状态校验全绿；真实进程 `python -m bms_platform` 启动，`/healthz` 与 `/readyz` 探针带身份，SIGTERM 触发 `service_shutdown_started` 后再优雅收尾。
10. **登记回写与记录**：见 §6 与测试记录。

关键命令：

```bash
cd backend
uv run pytest -q --cov=bms_core --cov=bms_platform --cov-branch
uv run ruff check . && uv run ruff format --check . && uv run pyright
BMS_SERVER__PORT=8123 uv run python -m bms_platform    # 启动冒烟（Ctrl+C / SIGTERM 触发优雅停机）

python3 scripts/tools/base-check/check-service-boundaries.py --self-test
python3 scripts/tools/base-check/check-base.py && python3 scripts/tools/base-check/check-links.py

```

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| 运行时未落 `app.state` | 生命周期用例取 `app.state.service_runtime` 报 `KeyError` / `AttributeError` | `ServiceRuntime.__init__` 落 `app.state.service_runtime = self`（由 `attach_service` 统一构造） |
| 服务标识默认置空引发既有断言语义变化 | `test_tenant_url_template_resolution` 期望 `bms_platform_acme.db`，实际 `bms__acme.db` | 该用例直接构造 `EngineFactory`（无启动回写）——用例显式设置 `settings.app.service = "platform"` 表示「启动期回写后的值」；`test_config` 默认断言由 `"platform"` 改为 `""` |
| 新基座类未登记 | `check-backend-base` 报 `ServiceIdentity` / `ServiceRuntime` 未在《后端基类清单》登记 | 在《后端基类清单》§7 core 横切基座补「服务运行时基座」行 |
| 新增模块覆盖率未达 100% | `core/run.py` 的 `run_service`、`api/health.py` 无身份分支未覆盖 | 补 `run_service` 主流程用例（替身服务器）与 `/healthz` 无身份回退用例；`service.py` / `run.py` / `health.py` 覆盖率均 100% |
| 生成件 `/readyz` 500 | 最小脚手架未接入插件注册表，`health_check_registry` 解析 `local` 失败 | 脚手架模板显式回退 null 注册表（空检查项、恒定通过）并注明「接入依赖后切换实现」；生成件开箱 `/healthz` `/readyz` 200 |
| 脚手架模板 `{}` 触发 `str.format` | 生成件冒烟用例含 `{}` 导致 `generate` 抛 `IndexError` | 模板内 `{}` 转义为 `{{}}` |

## 7. 偏差与遗留 <a id="deviations"></a>

- **偏差（已闭环）**：① 探针响应由设计初稿「保持现状」按用户拍板改为「追加 `service` / `version`」，已同步架构节点、既有用例与 README；② 脚手架就绪回退 null 注册表（原设计未细化），已回写详细设计 §4.7 并同步 Kiwi 用例正文。
- **遗留（归口）**：① `minio` 检查项接入 `/readyz` → **文件管理阶段**（架构定案）；② 每服务独立配置（`config.<service>.toml`）与迁移链 → **06_需求**；③ 按服务归因的 OTel 指标 / 链路资源标签（`service.name` / `service.version`）→ **08_02**；④ 多 worker / 多副本停机编排 → 编排（入口单进程）；⑤ `bms_platform/__main__.py` 覆盖率 0%（进程入口，与 `asgi.py` 同口径，由真实启动冒烟覆盖）；⑥ 脚手架生成服务的依赖检查随服务接入依赖后按配置切换实现并登记检查项。
