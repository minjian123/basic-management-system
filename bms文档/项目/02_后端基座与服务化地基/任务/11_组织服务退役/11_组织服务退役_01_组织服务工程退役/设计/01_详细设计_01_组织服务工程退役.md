# 01 详细设计 · 组织服务工程退役与登记清理

## 1. 设计目标与范围 <a id="goal"></a>

承接需求 11-1：**一步到位退役 bms `org` 服务**——删除服务工程，清理服务目录 / 网关 / 契约快照 / api-types / 迁移链 / 部署脚本 / CI 与校验脚本中的 org 登记；组织主数据职责归 mdm。

1. **工程删除**：`backend/services/org/` 整目录。
2. **登记清理**：`SERVICE_CATALOG` org 条目、网关 upstream/route、契约快照与 baseline、api-types、`Dockerfile` COPY、`ops/dev_run.py`、相关测试与校验脚本引用。
3. **迁移链与库**：删除 `alembic/versions/org/` 与 `org:platform`；清理已存在的 `bms_org_{code}` 租户库。
4. **服务规模**：平台服务由 **9 → 8** 个平台服务工程。

**执行顺序（跨任务，强制）**：本任务须在 **11_02 前段（前端 / 调用方切 mdm 出口）完成后**执行，再进入 **11_02 后段（`bms_core/org` 契约与装配移除）**——即「先切出口、后删服务、再移除基座契约」。

**不在本期**：`bms_core/org` 契约与装配移除、前端 adapter 切换（归 11_02）；门禁回归与阶段收口（归 11_03）。

## 3. 去实现点位与处理 <a id="points"></a>

| 点位 | 现状 | 处理 |
| --- | --- | --- |
| `services/org` | 组织主数据占位路由（`/org/users` 等，走 `bms_core/org` 契约 Null 实现） | 整目录删除 |
| `SERVICE_CATALOG`（module_registry） | 含 `org`（表前缀 `org_`、事件域 `org`、`CAPABILITY` 组、`build_batch=2`） | 移除该 `ModuleRecord`；启动 / CI 唯一性校验对 8 服务通过 |
| 网关 `apisix.yaml` | `upstream: org`（`org:8000`）+ `route-org`（`/api/org/v1`） | 移除该 upstream 与路由 |
| 契约快照 | `deploy/contracts/org.json` + `baseline/org.json` | 删除；`ops/contract_snapshot` / `contract_gate` 覆盖 8 服务 |
| api-types | 含 org 契约类型 | `scripts/generate.mjs` 重新生成 8 份 |
| 表归属登记 | `org` 无专属表（`sys_user` / `sys_account_lock` 已迁 platform；`sys_outbox` 等为每服务自有基建） | 无需转表；`sys_outbox` / `sys_event_*` 随 org 服务移除（每服务自有，不涉他服务） |
| alembic `org:tenant` | 0001~0006（`sys_user` → 迁出 → `drop_user_tables`，仅剩 outbox 基建） | 整链删除；`org:platform` 一并删除 |
| `dev_run.py` | org loopback `127.0.0.3`、`KNOWN_SERVICES` 含 org | 移除 |
| `Dockerfile` / `Dockerfile.backend` | `COPY services/org/pyproject.toml` | 移除该行 |
| 测试 / 校验脚本 | 多处以 org 为样例（边界 / 租户路由 / 库键 / 提权搬迁脚本） | 逐处清理或改用现存服务（保持断言有效） |

## 4. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 服务目录移除后启动校验 | 对账 8 服务通过；如报「运行服务登记行多余 org」须清理运行库登记行 |
| 契约快照残留 org | `contract_snapshot check` 报漂移 → 重新生成（8 服务）后零漂移 |
| api-types 与契约不一致 | 前端类型零漂移门禁失败 → 重新生成 |
| 迁移链删除后真库残留 | `bms_org_{code}` 库由运维清理（DROP）；旧链记录清理（不参与新迁移） |
| 网关残留 org 路由 | 网关配置校验（`gateway_config check`）失败 → 移除后通过 |
| 前端仍调用 bms org 出口 | 由 11_02 前段先行切换（本任务前置条件），避免空窗 |

## 6. 实施要点 <a id="impl"></a>

- **顺序内嵌**：确认 11_02 前段（前端 adapter 切 mdm 出口）已完成后开动；本任务完成后再做 11_02 后段（`bms_core/org` 移除）。
- **重生成**：契约快照、baseline、api-types 以工具重新生成（非手改），保证与实现一致。
- **不动既有语义**：平台其余 8 服务不受影响；共享基座 `bms_core` 除 `SERVICE_CATALOG` 外本任务不提前改动（`bms_core/org` 移除归 11_02）。

## 9. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 退役方式 | **一步到位**：删除服务工程 + 一次性全清登记项 |
| 2 | 服务规模 | 平台服务 **9 → 8** |
