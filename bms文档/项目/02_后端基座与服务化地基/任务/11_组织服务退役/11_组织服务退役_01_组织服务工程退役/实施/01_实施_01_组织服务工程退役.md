## 2. 实施过程与落地 <a id="process"></a>

按「基座能力 → 工程退役 → 登记置位 → 生成件重生成 → 前端与脚本同步 → 文档台账」六段推进：

| # | 段 | 落地内容 |
| --- | --- | --- |
| 1 | 基座能力（三项） | ① **库名前缀参数化**：`core/config.py` 增 `[database].name_prefix`（默认 `bms`）、`db/keys.py` 增 `DEFAULT_DATABASE_NAME_PREFIX` / `archive_database_name()` 且 `platform_database_name` / `tenant_database_name` / `database_name` 接受 `prefix`，`db/engine.py` 与 `ops/provision_tenant.py` 接线，`backend/config.toml` 增配置项；② **产品服务合并**：`module_registry.py` 增 `merge_service_records()`（同 `module_key` 同值去重、异值即拒），`application.py::create()` 改经其合并平台清单与注入记录；③ **网关服务级路由分组**：`gateway_catalog.py` 增 `platform_route_services()`（enabled + 非产品分组），`render_routes()` 改取其集，`render_upstreams()` 仍取全量启用服务 |
| 2 | 工程退役 | 删除 `backend/services/org/`、`backend/alembic/versions/org/`、`ops/migrate_user_tables.py` 与其测试；`pyproject.toml` 去 `bms_org` / `services/org` 成员与 testpaths；`Dockerfile` / `deploy/ci/Dockerfile.backend` 去 org COPY；`.gitlab-ci.yml` 去 `trigger-org` / `contract-smoke-org` 与 `--cov=bms_org`；`deploy/compose/services.yml`、`deploy/observability/prometheus.yml` 去 org 服务与抓取目标；`backend/uv.lock` 重解析（移除 `bms-org`） |
| 3 | 登记置位 | `SERVICE_CATALOG` 的 `org` 行**易主**（`product` / `product_key=mdm` / `errcode_segment="33"` / `build_batch=3` / 名称改「mdm 组织主数据服务」，四要素不变）；`PRODUCT_ROUTES` 增 `mdm/org → org`；`PRODUCT_CATALOG` 的 `mdm` 升 `enabled`；`enabled_service_keys()` / `enabled_service_records()` 排除产品分组（平台服务视图 8 项） |
| 4 | 生成件重生成 | `ops.gateway_config render`（移 `route-org`、增 `route-mdm-org`、保留 upstream `org`）；删除 `deploy/contracts/org.json` 与 `baseline/org.json`；重生成前端 api-types（8 份，删 `org.ts` 与 index 导出） |
| 5 | 前端与脚本同步 | `@bms/core` `SERVICE_KEYS` 9 → 8（含用例）；桌面端 `orgSourceOptions()` 改指 mdm 产品命名空间 `/api/mdm/v1/org`；`scripts/tools/dev/本地全套.sh` 与 `backend/ops/dev_run.py` 联调集去 org（`tenant / platform / identity`）并修正 unlock 读 platform 租户库；`scripts/tools/deploy/release.py` SERVICES 去 org；`scripts/tools/{base-check/check-service-boundaries,preflight/check-preflight}.py` 去 org 样例与覆盖率参数；`backend/alembic/README.md` 回写 org 链退役 |
| 6 | 文档台账 | 需求 11（次序修订 + 11-1 内容与完成标准 + 11-2 兼容期）、阶段二计划两表与统计行、架构 04 / 11、《后端开发规范》、《后端基类清单》、本任务实施与测试记录；12_02 / 12_03 / 06_01 详设对齐记录 |

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 平台侧登记行与产品侧自报注入记录并存会因 `module_key` 重复被唯一性校验拒启 | 采 **R 架构**：基座合并改「同值去重、异值即拒」（新增 `merge_service_records()`），两侧同值不冲突；异值仍 fail-closed |
| 2 | 产品行 `enabled` 后 `render_routes()` 会额外生成服务级路由 `/api/org/v1`，与「产品只经产品命名空间」冲突 | 服务级路由改只取非产品分组；`render_upstreams()` 保持全量（产品级路由的 `upstream_id` 需要 upstream） |
| 3 | `enabled_service_keys()` / `enabled_service_records()` 原含产品行，导致契约快照 / 表归属 / 发布编排 / compose / prometheus 去扫 `bms_org`（`ModuleNotFoundError`） | 两处一并排除产品分组（平台服务视图），产品服务的契约与工程由产品侧自持 |
| 4 | 前端 `ServiceKey` 去掉 `org` 后，`sourceEndpoint('org')` 触发类型错误（与「出口切换留 11_02」冲突） | 该函数改为**不经 `ServiceKey`** 的产品命名空间字面量常量 `/api/mdm/v1/org` 并注明待 mdm 出口就绪；真实契约与类型随 mdm 需求 01-3 |
| 5 | `ops/migrate_user_tables.py`（用户 / 账号锁定两表 org → platform 的一次性搬迁脚本）源库随本任务退役 | 经拍板**整体退役**（脚本 + 测试删除）；需求 11-1 第 6 条由「清理引用」改为「脚本退役」 |
| 6 | 库名前缀硬编码 `bms_`，产品库名无法体现产品标识 | 采 `[database].name_prefix` 单一来源参数化（默认 `bms` 行为不变，mdm 配 `mdm`）；调用面实测仅 `db/engine.py` 与 `ops/provision_tenant.py` 两处 |
