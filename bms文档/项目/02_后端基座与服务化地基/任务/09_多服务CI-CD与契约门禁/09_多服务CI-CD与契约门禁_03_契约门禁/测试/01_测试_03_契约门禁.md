## 3. 真机冒烟（mjbk） <a id="smoke"></a>

| 验证项 | 操作 | 实测结果 |
| --- | --- | --- |
| 工具镜像 | `docker pull tufin/oasdiff:v1.32.1` / `schemathesis/schemathesis:4.28.0` | 拉取成功（登记《镜像清单》） |
| oasdiff 兼容比对 | 基线 ↔ 当前 platform 契约（`breaking --fail-on ERR --format json`） | `[]`，exit 0 |
| oasdiff 破坏拦截 | 人为删除 `GET /api/v1/modules/snapshot` 后比对 | 输出 `api-path-removed-without-deprecation`（`level:3`、`path` 与 `operationId` 齐全），exit 1 |
| oasdiff 调用方式（首推流水线发现 + 修复复验） | `docker run -v <job 路径>` 实测挂空 → oasdiff 返回码 102；改 `docker create + docker cp + docker start -a` | 兼容 exit 0、破坏 exit 1（`start -a` 回传退出码）；`diff` 执行器桩用例覆盖 create/cp/start/rm 序列 |
| Schemathesis 调用方式（首推流水线发现 + 修复复验） | `--network container:$HOSTNAME` 报 `No such container`、`-v` 挂 schema 宿主不可见；改「已构建镜像起命名容器 + `--network container:<服务容器>` + schema 经 `docker cp` 进 `/tmp`」 | 通过（可固定重现）；`docker_schemathesis` 桩用例覆盖 create/cp/start/rm 与容器网络 |
| Schemathesis 命令口径 | 容器 `run --help` 实测 | `--max-examples` / `--checks` / `--include-method` / `--suppress-health-check` / `--exclude-path` 有效；无 `--method`（改 `--include-method`） |
| Schemathesis 打真实服务（重设计后） | 用已构建镜像 `docker run -d -e BMS_ENV=dev` 起容器 + Schemathesis `--network container:<服务容器>` 打（按服务、仅变更服务；固定 tag） | 通过，exit 0（可固定重现） |

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 发现阶段 | 处置 |
| --- | --- | --- | --- |
| 1 | Schemathesis 无 `--method` | mjbk `--help` | 改 `--include-method`（见实施记录 §4） |
| 2 | 健康检查误报 | 冒烟命令设计 | 增 `--suppress-health-check all` |
| 3 | oasdiff `level` 数值 | mjbk 破坏拦截实测 | `count_breaking` 兼容数值 `3` |
| 4 | `--include-method HEAD` 无匹配告警 | mjbk Schemathesis | 无害警告（exit 0），保留只读语义，登记说明 |
| 5 | 工具容器与被测服务跨网络 | 设计 / mjbk | 改「已构建镜像起命名服务容器 + Schemathesis `--network container:<服务容器>`」（见实施记录 §4 第 10、12 项） |
| 6 | 首推流水线 `contract-gate` 全服务 oasdiff 返回码 102 | 真实流水线（`docker run -v` 挂 job 路径至宿主空目录） | 改 `docker create + cp + start -a`（见实施记录 §4 第 9 项）；补充 `diff` 执行器桩用例 |
| 7 | 首推流水线 `contract-smoke` 全服务失败 | 真实流水线（`--network container:$HOSTNAME` 报 `No such container`；`-v` 挂 schema 宿主不可见） | 改 `docker create + docker cp`（schema 进 `/tmp`）；被测量改为已构建镜像容器（见实施记录 §4 第 10、12 项） |
| 8 | `contract-smoke` 机制通后仍全服务失败 | 真实流水线（dev 环境探针 `/readyz` 503 + platform `outbox/dead-letters` 500） | 排除基础设施端点 `/healthz` `/readyz` `/metrics`；非阻断（`allow_failure`）；dev 5xx 归口（见实施记录 §4 第 11 项）；**2026-09-24 由任务 06_04 修复根因并转阻断** |
| 9 | 冒烟口径重设计（用户拍板） | 用户要求「用打好容器、只跑变更服务、可固定重现」 | 弃源码直跑；改已构建镜像起容器 + 按服务仅变更服务运行 + `--max-examples 1`（见实施记录 §4 第 12 项） |
