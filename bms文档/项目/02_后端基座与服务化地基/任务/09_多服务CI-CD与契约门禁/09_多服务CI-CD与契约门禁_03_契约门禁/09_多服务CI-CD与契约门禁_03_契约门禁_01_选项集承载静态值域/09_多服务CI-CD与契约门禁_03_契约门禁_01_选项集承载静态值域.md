## 2. 任务内容 <a id="content"></a>

1. 值域声明下沉到 `deploy/registry/<仓>.toml` 的 `[[option_sets]]`（`key` / `name` / `contract_name` / `extensible` / `items`），随产品清单装载进选项集注册表；代码不保留第二份值清单
2. 先落首批三条：`bms.tenant.status`（**闭集**）、`bms.tenant.module_status` 与 `bms.datasource.kind`（**可增长**）
3. 响应模型改以 `str` + `optionSetKey` 标记值域来源，撤掉 Python 枚举 / `Literal` 作为值来源；导出公开契约时按 `extensible` 派生 `enum` / `x-extensible-enum` 命名组件
4. 前端类型生成器把 `x-extensible-enum` 回填为 `enum`（已知取值仍为闭合联合）；前端改为消费选项集快照，删除状态文案硬编码
5. 新增只读快照接口 `GET /api/v1/option-sets?keys=…`（登录即可；数据权限后续挂同一入口）
6. 判据与操作口径沉淀进《后端开发规范》「静态值域与选项集」节、《后端基类实现契约》选项集条；Kiwi 用例先登记后编码

## 3. 完成标准 <a id="accept"></a>

三条选项集在运行时 OpenAPI、`deploy/contracts` 快照与基线中按可增长性分别呈现 `enum`（闭集）与 `x-extensible-enum`（可增长）；可增长集合新增值不再改契约基线，闭集加值触发门禁；前端类型零漂移且状态 / 类型文案随配置更新，未知状态显式标注而非默认成「启用」；快照接口鉴权生效、未登记标识 404；相关后端与前端用例、静态检查全绿。
