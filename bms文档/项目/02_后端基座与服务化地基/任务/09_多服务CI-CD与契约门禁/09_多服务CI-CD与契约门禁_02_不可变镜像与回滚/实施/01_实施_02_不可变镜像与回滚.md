## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记**：登记一条策展用例（平台骨架 / P2 / CONFIRMED / 自动化）并回读编号 **2185**（输入 `test/scripts/kiwi/cases/2026-09-24_阶段二09-02_不可变镜像与回滚.json`，结果 `exports/…_登记结果.json`）；先登记后编码。
2. **服务容器编排**：`deploy/compose/services.yml`——9 个已启用服务（服务名取 `service_key`、容器 `bms-{service}`），镜像 `${REGISTRY_IMAGE_PREFIX}/bms-{service}:${BMS_TAG_<SERVICE>:?}`（标签必填、无 latest 兜底），仅 `expose 8000`（不映射宿主端口）、`depends_on: [redis, mysql]`、健康检查沿用镜像、边界白名单挂载 `/opt/deploy/boundaries`；环境变量含 MySQL 每服务库 URL 模板、Redis / OTLP Compose DNS、`service_client` http；纳入 `bms.yml` include。
3. **镜像迁移能力**：`backend/Dockerfile` 追加 `COPY alembic ./alembic` + `COPY ops ./ops`；`.dockerignore` 不排除二者；运行镜像兼作一次性迁移容器。
4. **发布 CLI**：`scripts/tools/deploy/release.py`（纯标准库）——`bootstrap`（账号授权 + 建库 + 分链迁移 + 种子）/ `deploy`（迁移先行 → 起容器 → 门禁 → 台账，失败自动回滚）/ `rollback`（上一版本 / `--to`）/ `status` / `prune`（Registry API 清理 SHA 标签）/ `health-gate`；版本台账 `deploy/releases/`（gitignore）；compose 标签经 `_fill_service_tags` 与子进程环境注入。
5. **采集口径切换**：`deploy/observability/prometheus.yml` 的 `bms-services` / `bms-probe` 目标切 `{service_key}:8000`（9 服务逐项）。
6. **CI 改造**：`.gitlab-ci.yml` workflow 与 9 个 trigger job 增 tag `v*` 规则；子模板 `service-build` / `service-release` 支持 tag 流水线，release 扫描通过后 `docker tag/push` 语义化标签 + 产出 `release-manifest.json` artifact；`deploy/ci/verify/image` 说明更新。
7. **护栏与预检**：`tests/ops/test_deploy_config.py`（编排 / 标签 / 抓取 / 网络 / 迁移能力 / 聚合）+ `tests/ops/test_release_cli.py`（台账 / 回滚目标 / 清理 / 清单）+ `test_ci_pipeline.py` 增 tag / semver / 清单断言（Kiwi 2185）；`check-preflight.py` 解析 `deploy/compose/*.yml` 并断言 CLI 就位。
8. **门禁**：全量 `pytest`（1313 passed / 37 skipped）+ `ruff check` / `ruff format --check` / `pyright`（0 error）+ 基座 / 边界 / 状态 / 契约校验 + `check-preflight`（非 fast）全绿。
9. **mjbk 真机冒烟**：同步 `deploy/` + `scripts/tools/deploy/` + `backend/`（含迁移能力）→ 本地构建 9 服务镜像（`smoke0924`）→ `bootstrap`（账号授权 / 建库 / 分链迁移 / 种子）→ `deploy --all`（9 服务门禁全通过）→ 一键回滚（`smoke0924b` → `smoke0924`）→ 自动回滚演练（故障镜像门禁失败自动回滚）→ `up{job="bms-services"}` 9/9、`probe_success` 18/18 = 1。详见[测试记录](../测试/01_测试_02_不可变镜像与回滚.md)。
10. **登记回写与记录**：规范 / 规划 / 部署说明 / README / 计划 / 任务；实施与测试记录；代码与文档分开提交。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 现象 | 处置 |
| --- | --- | --- | --- |
| 1 | 发布 CLI 在部署机语法错误 | mjbk `python3` 3.12 报 `except urllib.error.URLError, OSError` SyntaxError（PEP 758 允许无括号多异常为 Python 3.14 特性，ruff `target-version=py314` 自动去括号） | 拆为 `except urllib.error.HTTPError` + `except OSError`（`URLError` 是其子类）；CLI 须兼容部署机 py3.12 |
| 2 | 单一服务镜像运行迁移工具强依赖 `bms_tenant` | `ops.migrate_tenants` / `provision_tenant` / `seed_tenant` 模块级 `from bms_tenant.models.tenant import SysTenant`；platform 镜像无 `bms_tenant` → `ModuleNotFoundError` | 改为**惰性导入**（仅读 `--all-tenants` 注册库 / 归属服务运行时）；`seed_tenant` 增模块级 `__getattr__` 兼容外部 `from ops.seed_tenant import SysTenant`（测试）；`seed_module` 复用 `resolve_url` 不再连带导入 |
| 3 | `compose run` 额外环境变量未进容器 | `seed_dict` 的 `BMS_MIGRATION_URL` 落回 SQLite 兜底，报 `no such table: sys_dict_type` | `_compose_run` 的 `extra_env` 改经 `-e KEY=VAL` **注入容器**（compose 仅自动传入服务 `environment` 声明的变量） |
| 4 | 编排需全部 `BMS_TAG_<服务>` 方可插值 | 单服务操作报 `required variable … is missing` | `_fill_service_tags` 按「已有 > 台账当前 > `BMS_IMAGE_TAG`」补齐全部服务标签 |
| 5 | `seed_dict` 逐服务循环失败 | 非 platform 服务租户库无字典表（字典表归属 platform） | bootstrap 仅对 platform 租户库种子字典 |
| 6 | 网关路由 502（nginx） | APISIX 直连 9080 正常（401），经 nginx 8088 返 502 | `bms-gateway-nginx` 启动时缓存 `apisix` 解析地址、APISIX 其后重建换 IP → `docker restart bms-gateway-nginx` 即解；登记《服务编排与发布部署使用说明》排障 |
| 7 | 抓取目标改后不生效 | prometheus 仍抓 `host.docker.internal` | 单文件 bind mount 换 inode 不生效：`up -d --force-recreate prometheus blackbox-exporter` 重挂载；`SIGHUP` 无效 |
| 8 | 自动回滚演练首用镜像缺迁移能力 | 故障镜像无 `ops` 模块，迁移步即失败（未进门禁，无自动回滚） | 以「基于服务镜像、仅覆盖 CMD 退出」的故障镜像重演：迁移通过 → 容器不 healthy → 门禁失败自动回滚上一版本通过 |
| 9 | 开发库测试文件被改动 | 跑全量测试触碰 tracked 的 `*.db` | `git checkout` 还原，不夹带无关改动 |
