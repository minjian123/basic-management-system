## 1. 概述 <a id="overview"></a>

- **目标**：在 04_01（网关接入 + 服务发现按名寻址）与 04_02（边缘认证与请求净化）之上，交付**边缘限流（共享 Redis 多副本一致计数，登录限流优先）**、**服务发现「无硬编码 IP」可回归护栏**、**边缘观测出口（指标 / 访问日志）**与**灰度路由预留**，规则全部声明式入 Git、随流水线零漂移校验、运行时热加载。
- **依据**：《[架构设计 · API 网关与边缘](../../../../../../设计/架构设计/36_架构设计_子系统_API网关与边缘.md)》「边缘功能」「部署形态与演进」节；《[架构设计 · 部署与运维](../../../../../../设计/架构设计/33_架构设计_部署与运维.md)》「集群设计要点」「故障应对」节；《[架构设计 · 可观测性](../../../../../../设计/架构设计/27_架构设计_子系统_可观测性.md)》「指标采集」节；《[架构设计 · 性能与安全](../../../../../../设计/架构设计/31_架构设计_性能与安全.md)》「限流与降级」节；《[部署发布规范](../../../../../../规范/部署发布规范.md)》「API 网关配置与热加载」节；需求 [04-3](../../../../需求/04_需求_API网关与边缘.md#r04-3)；前置任务 [04_01 详细设计](../../04_API网关与边缘_01_网关接入与声明式配置/设计/01_详细设计_01_网关接入与声明式配置.md) / [04_02 详细设计](../../04_API网关与边缘_02_边缘认证与请求净化/设计/01_详细设计_02_边缘认证与请求净化.md)。
- **范围（本任务）**：
  1. **边缘限流**：生成器为每条服务路由注入 `limit-count`（`policy: redis` 共享计数），默认按**真实客户端 IP**（`remote_addr`）计数、档位 `300 次 / 60s`；Redis 故障 `allow_degradation: true` 放行（可用性优先）；用户 / 租户 / client 维度留 `var_combination` 钩子随 07_03 身份注入扩展。
  2. **登录限流优先**：新增**独立登录路由** `route-identity-auth-login`（精确匹配认证敏感路径，显式 `priority` 高于身份服务路由），挂更严档位 `10 次 / 60s`。
  3. **真实客户端 IP**：`global_rules` 增 `real-ip`（`source: http_x_real_ip`，基于 nginx 已设头），使经 nginx 入口的限流按真实客户端 IP 计数。
  4. **服务发现护栏**：生成器增「上游节点必须为服务名、不得为 IP 字面量」校验；CLI `check` 纳为断言——把「禁硬编码 IP」变成可回归门禁（服务发现寻址本身 04_01 已按 Compose DNS 落地）。
  5. **边缘观测出口**：`config.yaml` 启 `prometheus`（`export_addr 0.0.0.0:9091`）+ 访问日志（`nginx_config.http`，输出 stdout）；生成器给路由挂 `prometheus: {}`；`gateway.yml` 暴露指标端口。真实抓取 / 展示 / 告警归 08 可观测性栈。
  6. **灰度预留**：生成器预留 `traffic-split` 灰度钩子（`GRAY_TRAFFIC`，默认空）+ 单元用例演示按权重灰度，规则声明式入 Git、默认不改变流量。
  7. **配置与凭据外部化**：限流 Redis 连接经 `${{GATEWAY_REDIS_*:=默认}}` 环境变量替换（默认 Compose DNS `redis:6379`），密码经 `.env` 注入、不入库。
- **不含（明确归口，见第 8 节）**：后端接口级 slowapi 真实 Redis 后端（归性能与安全阶段）；真实可观测栈接入 / 抓取 / 展示（08_需求）；网关认证插件启用与用户 / 租户维度限流接线（07_需求）；每服务独立端口（06_需求）。

## 4. 领域设计 <a id="design"></a>

### 4.1 边缘限流（limit-count + 共享 Redis） <a id="ratelimit"></a>

**规则单一来源**：生成器 `bms_core/services/gateway_catalog.py` 内置声明式规则表（决策 #1），随服务目录生成、零漂移校验。

```text
gateway_catalog.py（限流相关）
├── DEFAULT_RATE_LIMIT_COUNT = 300 / DEFAULT_RATE_LIMIT_WINDOW = 60   # 通用档
├── LOGIN_RATE_LIMIT_COUNT = 10   / LOGIN_RATE_LIMIT_WINDOW = 60      # 登录档（更严）
├── RATE_LIMIT_REJECTED_CODE = 429
├── RATE_LIMIT_KEY = "remote_addr"                                    # 默认维度：真实客户端 IP
├── GATEWAY_REDIS_HOST / PORT / DATABASE / PASSWORD                   # 环境变量名常量
├── env_var(name, default) -> "${{name:=default}}"                    # 环境变量替换发出
├── rate_limit_plugin(count, window, key=RATE_LIMIT_KEY) -> dict      # limit-count 配置
└── render_routes() 内对每条服务路由注入 limit-count
```

`limit-count` 配置（`rate_limit_plugin` 产物，真机实测点见 §4.4）：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `count` / `time_window` | `300` / `60`（登录 `10` / `60`） | 档位集中常量，便于统一调档 |
| `key_type` / `key` | `var` / `remote_addr` | 默认维度 IP；用户 / 租户 / client 随 07_03 改 `var_combination` |
| `policy` | `redis` | **共享计数**，多副本 APISIX 一致 |
| `redis_host` | `${{GATEWAY_REDIS_HOST:=redis}}` | Compose DNS 服务名，**禁硬编码 IP** |
| `redis_port` / `redis_database` | `${{GATEWAY_REDIS_PORT:=6379}}` / `${{GATEWAY_REDIS_DATABASE:=0}}` | 环境变量替换（APISIX 按字段类型还原为整数） |
| `redis_password` | `${{GATEWAY_REDIS_PASSWORD:=}}` | 凭据经 `.env` 注入；缺省空串——APISIX 源码 `conf.redis_password ~= ''` 时不发 AUTH，dev 无鉴权 Redis 可用 |
| `rejected_code` | `429` | 与《API接口规范》「HTTP 状态码表示传输层语义（429 限流）」一致 |
| `show_limit_quota_header` | `true` | 响应携带 `X-RateLimit-*`，便于观测与用例断言 |
| `allow_degradation` | `true` | Redis 故障**放行**、不阻断业务（可用性优先，与《部署与运维》降级矩阵一致），由告警兜底 |

- **多副本一致**：所有 APISIX 实例共用同一 Redis（Compose DNS `redis`），计数落 Redis，跨实例配额一致；本任务以 mjbk 双实例共享 Redis 冒烟实证（§6）。
- **维度扩展钩子**：`rate_limit_plugin` 的 `key` 参数为唯一接线点；07_03 网关认证注入 `X-User-Id` / `X-Tenant-Id` 后，将 `key_type` 改 `var_combination`、`key` 改 `$remote_addr $http_x_tenant_id $http_x_user_id` 即接入用户 / 租户维度，生成结构不变。

### 4.2 登录限流优先（独立路由） <a id="login"></a>

- **认证敏感路径**：`LOGIN_PATHS = ("/api/identity/v1/auth/login", "/api/identity/v1/auth/refresh")`（外部形态；身份服务内部 `/api/v1/auth/...`，与《接口与集成》「动作类动词短语（/auth/login）」一致）。
- **独立路由** `route-identity-auth-login`：

  | 字段 | 值 |
  | --- | --- |
  | `id` | `route-identity-auth-login` |
  | `uris` | `LOGIN_PATHS`（精确路径） |
  | `priority` | `10`（高于服务路由默认 0，保证精确路由优先命中） |
  | `upstream_id` | `identity`（与身份服务同上游） |
  | `plugins` | `proxy-rewrite`（前缀重写 `/api/identity/v1(.*) → /api/v1$1` + 置网关标记）、`limit-count`（**登录档** 10/60）、`prometheus: {}` |

- **生成条件**：仅当服务目录中 `identity` 服务**启用**时生成（`gateway_services()` 判定），避免对未启用服务产生悬空上游。
- **匹配顺序**：APISIX 路由按 `priority` 优先、同优先级按路径精度；显式 `priority: 10` 确保登录请求命中更严的独立路由，其余身份路径仍走通用路由。**真机实测确认**（§6 冒烟第 3 项）。

### 4.3 真实客户端 IP（real-ip） <a id="realip"></a>

- 经 nginx 入口（8088）时，APISIX 观测到的 `remote_addr` 是 nginx 容器 IP；按 IP 限流会退化为全站同一计数。故 `global_rules` 新增 `edge-real-ip`：

  ```yaml
  global_rules:
    - id: edge-real-ip
      plugins:
        real-ip:
          source: http_x_real_ip
          trusted_addresses:
            - '${{GATEWAY_TRUSTED_CIDR:=172.16.0.0/12}}'
  ```

- `source: http_x_real_ip` 取 nginx 覆写的 `X-Real-IP`（nginx 侧 `proxy_set_header X-Real-IP $remote_addr`，客户端伪造会被 nginx 覆盖）。
- `trusted_addresses` 限定可信代理网段（默认 Docker 私网 `172.16.0.0/12`，可经 `GATEWAY_TRUSTED_CIDR` 覆盖），减少直连 9080 伪造 `X-Real-IP` 的绕过面；**开放项**：生产应关闭 9080 直连暴露并收紧网段（见 §8）。
- real-ip 在 rewrite 阶段执行、早于 limit-count（access 阶段），限流按还原后的真实 IP 计数。

### 4.4 边缘观测出口 <a id="observe"></a>

本任务交付**出口**，真实采集 / 展示 / 告警归 08 可观测性栈（决策 #8）。

- **指标**：`config.yaml` 增

  ```yaml
  plugin_attr:
    prometheus:
      export_addr:
        ip: 0.0.0.0
        port: 9091
  ```

  生成器给每条路由（含登录路由）挂 `prometheus: {}`（prometheus 插件默认在启用列表，但**按路由指标需路由显式挂载**）；指标端点 `:9091/apisix/prometheus/metrics`；`gateway.yml` 暴露 `${GATEWAY_METRICS_PORT:-9091}` 供 08 的 Prometheus 抓取。
- **访问日志**：`config.yaml` 的 `nginx_config.http` 配访问日志（`enable_access_log: true`、`access_log_format_escape: json`、输出 `/dev/stdout`），随 `docker logs` 可见、供 08 的 Loki / 日志栈采集。
- **K8s 平移**：`plugin_attr.prometheus` → ServiceMonitor / PodMonitor；访问日志 → 采集 sidecar / DaemonSet（§4.6）。

### 4.5 灰度预留（traffic-split） <a id="gray"></a>

- 生成器预留 `GRAY_TRAFFIC: dict[str, dict[str, object]] = {}`（按 `service_key` 合并到路由 `plugins` 的 `traffic-split` 配置），默认空、不改变流量。
- 按版本 / 权重灰度示例（文档与用例演示，**不写入生成件**）：

  ```yaml
  plugins:
    traffic-split:
      rules:
        - weighted_upstreams:
            - upstream_id: tenant-v2      # 新版本
              weight: 1
            - upstream_id: tenant         # 旧版本
              weight: 9                   # 约 10% 走新版本
  ```

- 上游多版本以**独立 upstream 段**承载（生成器预留 `GRAY_UPSTREAMS` 或后续按需扩展 `render_upstreams`）；规则声明式入 Git、K8s 阶段平移为 HTTPRoute `backendRefs` 权重。

### 4.6 K8s 平移口径 <a id="k8s"></a>

| 单机（本任务） | K8s 阶段 | 说明 |
| --- | --- | --- |
| `limit-count`（`policy: redis`） | APISIX Ingress 插件 / Redis 共享计数 | 限流语义不变 |
| 登录独立路由 + `priority` | HTTPRoute `matches`（精确路径）+ 规则优先级 | 精确匹配语义一致 |
| `real-ip` | Ingress Controller `X-Forwarded-*` / 网关真实 IP 处理 | 客户端真实 IP 语义一致 |
| `prometheus` + `export_addr` | ServiceMonitor / PodMonitor | 指标抓取不变 |
| `nginx_config.http.access_log` | 采集 sidecar / DaemonSet | 日志出口不变 |
| `traffic-split` 权重 | HTTPRoute `backendRefs[].weight` | 灰度语义一致 |
| 上游 `{service_key}:8000`（Compose DNS） | `Service` 名（CoreDNS） | 按名寻址不变 |

## 5. 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| Redis 不可用 / 连接失败 | `allow_degradation: true`：跳过限流、请求放行（可用性优先），由 08 告警兜底 |
| Redis 无鉴权（dev） | `redis_password` 空串，APISIX 不发 AUTH（源码 `~= ''` 判定），正常计数 |
| Redis 有鉴权（prod） | `.env` 注入 `GATEWAY_REDIS_PASSWORD`，compose 传入容器环境，APISIX 启动时解析 |
| 直连 9080 伪造 `X-Real-IP` | `trusted_addresses` 限定可信网段；生产关闭 9080 直连暴露（§8 开放项） |
| 登录路由与通用路由匹配冲突 | 登录路由显式 `priority: 10`（高于默认 0），精确路径优先命中；mjbk 实测确认 |
| `identity` 服务未启用 | 不生成登录路由（避免悬空上游），仅生成启用服务的通用路由 |
| 上游节点写成 IP（人为改动 / 回归） | `render` 生成件为服务名；`check` 的 `validate_service_discovery` 拦截并退出码 1 |
| 环境变量未设置 | `${{VAR:=默认}}` 回退默认（host=redis / port=6379 / database=0 / password 空），生成件可独立跑通 |
| 环境变量在容器初始化后新增 | APISIX 文档告警：需重建 / 重启容器（`gateway.yml` 以 `environment` 声明，随 `up -d` 生效） |
| 指标端点不可达 | prometheus `export_addr.ip: 0.0.0.0` + compose 端口映射；08 抓取归后续 |
| 灰度钩子为空 | 默认不注入 `traffic-split`，流量不变 |
| 达梦 / 三库方言 | 不涉及（网关不直连数据库） |

## 8. 边界与开放项 <a id="boundary"></a>

- **归 07_03**：网关认证注入 `X-User-Id` / `X-Tenant-Id` 后，将默认 IP 维度扩为用户 / 租户维度（`var_combination`）；`ROUTE_PLUGINS` 认证插件启用。
- **归 08_需求**：Prometheus 抓取 APISIX 指标端点、Grafana 展示、Loki 采集访问日志、告警阈值。
- **归性能与安全阶段**：后端接口级 slowapi 真实 Redis 后端（`bms_core/ratelimit`，见其 docstring）与登录失败锁定（5 次锁 15 分钟）。
- **归 06_需求**：每服务独立端口（`SERVICE_PORT` 由常量改为按服务端口来源）。
- **归 09_需求**：服务容器化后上游可达；按服务发布。
- **开放项（安全）**：`real-ip` 的 `trusted_addresses` 默认 Docker 私网段，直连 9080 仍可伪造 `X-Real-IP`；生产应关闭 9080 直连暴露并收紧网段（随部署加固）。
- **开放项（限流维度）**：当前仅 IP 维度（用户 / 租户头未注入）；客户端（client_id）维度随开放接口阶段。
- **开放项（灰度）**：加权上游需第二版本实例，本任务只交付钩子与结构，真实灰度随版本发布流程。
- **不改**：服务内 `/api/v1` 前缀与响应体、网关外部路径约定、探针口径、既有服务目录生成规则、既有 Kiwi 用例号、`require_auth` 占位语义。
