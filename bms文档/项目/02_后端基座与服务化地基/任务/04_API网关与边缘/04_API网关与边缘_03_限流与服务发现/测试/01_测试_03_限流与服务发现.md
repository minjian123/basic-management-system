## 2. 测试范围 <a id="scope"></a>

本任务为**边缘限流 / 服务发现护栏 / 观测出口 / 灰度预留**，测试面分三层：

1. **生成器单元**（`bms_core/services/gateway_catalog.py`）：限流规则（共享 Redis / IP 维度 / 档位 / 降级）、登录独立路由、real-ip 全局规则、prometheus 挂载、灰度钩子、`plugin_metadata`、无硬编码 IP 护栏。
2. **CLI 单元**（`backend/ops/gateway_config.py`）：`render` / `check` 零漂移 + 无 IP 护栏拦截。
3. **真实冒烟**（mjbk Docker）：两实例共享 Redis 的跨实例配额一致、登录更严、real-ip 还原、指标端点、伪造身份头剥除不回归。

## 5. 真实冒烟（mjbk） <a id="smoke"></a>

编排：`bms-apisix`（compose 项目 `compose`，:9080 / 指标 :9091）与临时 `bms-apisix-2`（:9081 / 指标 :9092）同挂 `~/deploy/gateway`、同连 `compose_default` 网络与 `bms-redis`；上游 `traefik/whoami`（别名 `platform` / `identity`，端口 8000）。

| # | 场景 | 请求 | 预期 | 实测 |
| --- | --- | --- | --- | --- |
| 1 | 配置加载 | 两实例启动日志 | 无限流 schema 错误 | 均 0 条 `failed to check` |
| 2 | 共享限流（登录） | 实例 A 连打登录路由 10 次 | 200 且 remaining 递减 | A #1~#10 **200**（remaining 9→0） |
| 3 | 登录限流优先 | A 第 11 次 | 429 | **429** |
| 4 | 多副本一致 | 实例 B 第 1 次（同 IP） | 429（共享配额） | **429** |
| 5 | 通用档与响应头 | `GET /api/platform/v1/ping` | 200 + `X-RateLimit-*` | 200；Limit 300 / Remaining 299 / Reset 60 |
| 6 | 计数落 Redis | `redis-cli --scan --pattern '*limit*'` | 共享键存在 | `plugin-limit-count:v1:/routes/route-identity-auth-login:…:172.18.0.1` |
| 7 | real-ip 还原 | `GET /api/platform/v1/ping` + `X-Real-IP: 203.0.113.9` | 限流按真实 IP 计数 | platform key 末尾 `203.0.113.9` |
| 8 | 指标端点 | `GET :9091` / `:9092` `/apisix/prometheus/metrics` | 含 `apisix_*` 指标 | 75 / 106 条 |
| 9 | 剥头不回归 | `GET /api/platform/v1/ping` + 伪造身份头 + 自定义头 | 伪造头被剥、标记注入、自定义头透传 | 含 `X-Gateway-Identity: bms-edge` / `X-Custom-Probe`；不含伪造身份头 |
| 10 | 清理 | `docker rm -f bms-upstream-smoke bms-apisix-2` + 清限流 key | 无残留 | 无残留容器 / 0 限流 key |

结论：**共享限流计数多副本一致、登录限流优先生效、服务按名寻址无硬编码 IP、指标端点与访问日志出口就位、灰度结构预留**，完成标准达成。

## 6. 问题与偏差 <a id="issues"></a>

- 首轮部署 `limit-count` 的 `redis_port` / `redis_database` 用环境变量替换致 schema 校验失败（配置整份未加载）→ 改整数字面量；实施记录 §4 与设计 §4.1 已回写（含实测结论）。
- 冒烟首轮上游缺 `identity` 别名致登录路由 503（限流计数仍正常）→ 重建上游补别名后复测 200×10 / 429 通过。
- `limit-count` Redis 配置无法经 `plugin_metadata` 共享（官方 metadata_schema 仅响应头名）→ 生成器逐路由统一注入。
- 未发现缺陷；无关遗留（达梦 / `init_tenant` 等）见阶段计划「后续阶段待办」。
