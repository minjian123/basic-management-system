## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记**：登记一条策展用例（平台骨架 / P2 / CONFIRMED / 自动化）并回读编号 **2191**（输入 `test/scripts/kiwi/cases/2026-09-26_阶段二04-1-1_前端网关接入改造.json`；先登记后编码）。
2. **核心单一来源**：新增 `packages/core/src/contracts/service-endpoint.ts`（`ServiceKey` / `SERVICE_KEYS` 9 个 / `servicePrefix` / `serviceUrl` / `isServiceKey`）与 `packages/core/src/domain/route-guard.ts`（`resolveAuthRedirect` / 公开白名单）；`index.ts` 追加导出。
3. **宿主请求层**：`api/request.ts` 去单前缀 `API_PREFIX`，改 `apiUrl(service, path)` + `get/post/put/del(service, path)`；`api/http.ts` baseURL 取 `VITE_API_BASE ?? '/'`；`main.ts` 装配 `installHttpAdapter`（401 → 清会话 + 跳登录）。
4. **能力源端点**：新增 `api/endpoints.ts`（`authHeaders` / `sourceEndpoint` / `dict·org·captcha·upload·search` 选项 / `aiStreamEndpoint`）；接线 dev 页 `DictCheck.vue`（platform）、`CaptchaCheck.vue`（identity）。
5. **守卫骨架**：`router/guard.ts`（`VITE_AUTH_GUARD=on` 启用，缺省关闭）+ `router/index.ts` 注册 `/login` 与接线；新增 `views/LoginView.vue` 占位（仅消费 `--bms-*` 令牌，无硬编码色值）。
6. **dev 代理与环境**：`vite.config.ts` 改函数式配置，`/api` 代理目标取 `VITE_API_PROXY`（缺省 `http://localhost:8088` 网关 nginx）；`env.d.ts` 声明 `VITE_API_BASE` / `VITE_API_PROXY` / `VITE_AUTH_GUARD`。
7. **契约类型生成**：新增 workspace 包 `frontend/packages/api-types`（`package.json` / `tsconfig` / `vitest.config` / `eslint.config` / `scripts/generate.mjs` / `tests/exports.spec.ts`）；`openapi-typescript@^7.13.0` 生成 9 服务 `src/<service>.ts` + `src/index.ts`（按服务命名空间导出）。
8. **依赖与锁文件**：`还原依赖.sh` → `pnpm install`（新增 `openapi-typescript` 及传递依赖、链接 `@bms/api-types`）→ 更新根 `package.json` 脚本与 `lint` / `check` 链（api-types 纳入）。
9. **CI 与预检**：`.gitlab-ci.yml` 新增 `api-types-check` job（`deploy/contracts/**` + `frontend/packages/api-types/**` + 锁文件变更单独拉起，`pnpm run api-types:gen:check`）；`check-preflight.py` 增前端契约类型零漂移步骤（node 直跑生成器 `--check`，不经 pnpm 避免依赖重装）。
10. **门禁与回写**：跑通前端各包 lint / typecheck / test、宿主构建与体积预算、模块工程门禁；回写前端基类清单 §9、计划 §3 / 甘特、任务与父任务状态；实施 / 测试记录；代码与文档分开提交。

## 7. 偏差与遗留 <a id="deviations"></a>

- **偏差（已回写设计）**：守卫落点 `api/guard.ts` → `router/guard.ts`；`vite.config.ts` 改为函数式配置以读取 `VITE_API_PROXY`。
- **遗留（归口见详细设计 §8）**：真实登录链路（`/auth/login` / `/auth/refresh`、用户 claims、`X-User-Id`）与守卫默认开启归**阶段六**；RBAC 权限码接线归**阶段七**；运行时模块请求能力 `api` 注入 `ModuleHostContext` 归**插件化后续**；移动端宿主装配归**移动端阶段**；`VITE_API_PROXY` 缺省端口随部署域名 / TLS 复核。
- 涉及契约的消费方（阶段六认证前端接入）已在本记录与详细设计登记接口与端点口径。
