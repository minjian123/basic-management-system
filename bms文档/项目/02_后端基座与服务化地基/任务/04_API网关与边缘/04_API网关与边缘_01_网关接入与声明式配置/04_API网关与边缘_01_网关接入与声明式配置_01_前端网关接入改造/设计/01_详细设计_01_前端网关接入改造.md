## 1. 概述 <a id="overview"></a>

- **目标**：网关外部路径已由 `/api/v1` 变更为 `/api/{service_key}/v1/...`（04_01 交付）；前端请求原按单一 `/api/v1` 组装的方式失效。本任务把前端接入改造为**按服务段寻址**——「域 → 服务前缀」映射在前端框架无关核心建立**单一来源**；宿主请求层与能力源（字典 / 组织 / 验证码 / 文件 / 检索 / AI）经该来源按服务分流；9 份服务契约以 `deploy/contracts/` 快照为唯一事实源生成前端类型到 `@bms/api-types`（禁止手写漂移）；登录页 / 路由守卫 / 401 刷新按服务段寻址的骨架就位（真实登录链路联调归阶段六）。
- **依据**：《[架构设计 · 前端架构](../../../../../../../设计/架构设计/08_架构设计_前端架构.md)》「多服务寻址」节（第 1 / 2 / 3 节与「与其他节点的协调」）；《[架构设计 · API 网关与边缘](../../../../../../../设计/架构设计/36_架构设计_子系统_API网关与边缘.md)》「边缘功能」「与内部服务的关系」节；《[前端开发规范](../../../../../../../规范/前端开发规范.md)》§4 TypeScript、§11 请求封装（多服务寻址强制口径）；《[总体项目规划](../../../../../../../规划/总体项目规划.md)》阶段六「前端接入」口径；需求 [04-4](../../../../../需求/04_需求_API网关与边缘.md#r04-4)。
- **范围（本任务）**：
  1. **「域 → 服务前缀」单一来源**：核心包新增框架无关的服务键与服务前缀映射及 URL 组装函数（`servicePrefix` / `serviceUrl`），落 `contracts/`。
  2. **宿主请求层改造与 baseURL 收敛**：宿主请求入口改为服务段组装（`apiUrl(service, path)` + `get/post/put/del(service, path)`），去单前缀 `API_PREFIX`；Axios `baseURL` 收敛为可配（`VITE_API_BASE`，缺省同源 `/`）。
  3. **能力源按服务注入 `endpoint`**：宿主提供能力源端点选项解析（按服务前缀 + 令牌请求头），接线到现有 dev 检查页（`DictCheck` / `CaptchaCheck`）与后续页面统一消费。
  4. **9 份契约前端类型生成**：新增 workspace 包 `frontend/packages/api-types`（`openapi-typescript` 从 `deploy/contracts/<service>.json` 生成 `src/<service>.ts` + `index.ts`），附生成脚本与零漂移校验。
  5. **登录 / 守卫 / 401 按服务段就位（骨架）**：401 处理钩子按服务段收敛；路由守卫逻辑落核心可测、默认关闭强制跳转（阶段六登录就绪后开启）；登录占位页。
  6. **CI 与本地门禁**：新增 `api-types-check` CI job（重新生成比对零漂移）；`@bms/api-types` 纳入根 `lint` / `check` 链；本地预检接入。
- **不含（明确归口，见第 8 节）**：真实登录链路（`/auth/login` / `/auth/refresh`、用户 claims、`X-User-Id` 填充）归**阶段六**；RBAC 权限码归阶段七；运行时模块请求能力 `api` 注入上下文（模块契约扩展）与产品模块实际请求归**插件化后续**；移动端宿主装配归移动端阶段（本任务核心映射已跨端可复用）。

## 4. 领域设计 <a id="design"></a>

### 4.1 外部寻址口径与「域 → 服务前缀」单一来源 <a id="mapping"></a>

- **外部路径**：`/api/{service_key}/v1/{资源...}`；与网关 04_01 生成的路由 `uris`（`/api/{service_key}/v1`、`/api/{service_key}/v1/*`）严格一致。服务内仍为 `/api/v1/{资源...}`（前端不感知重写）。
- **单一来源落点**：核心包 `packages/core/src/contracts/service-endpoint.ts`（框架无关；宿主请求层、ui-ep 能力源、移动端宿主、运行时模块共用）。**全前端只此一份**服务前缀映射，禁止各模块 / 页面自拼。
- **服务键**（与后端服务目录 `service_key` 同源，9 个启用服务，保持目录顺序）：

| 服务键 | 名称 | 外部前缀 |
| --- | --- | --- |
| `platform` | 平台地基与配置服务 | `/api/platform/v1` |
| `identity` | 认证与身份服务 | `/api/identity/v1` |
| `tenant` | 租户与配置服务 | `/api/tenant/v1` |
| `org` | 组织主数据服务 | `/api/org/v1` |
| `file` | 文件服务 | `/api/file/v1` |
| `notification` | 通知服务 | `/api/notification/v1` |
| `search` | 全文检索服务 | `/api/search/v1` |
| `ai` | AI 服务 | `/api/ai/v1` |
| `report` | 报表打印服务 | `/api/report/v1` |

- **API 形态**（核心导出）：

```text
service-endpoint.ts
├── type ServiceKey = 'platform' | 'identity' | … | 'report'
├── const SERVICE_KEYS: readonly ServiceKey[]        # 9 个，顺序固定（与目录一致）
├── const API_VERSION_SEGMENT = 'v1'                 # 外部版本段
├── isServiceKey(value): value is ServiceKey         # 判定（未知服务不静默放行）
├── servicePrefix(service): string                   # `/api/{service}/v1`
└── serviceUrl(service, path?): string               # `/api/{service}/v1{path}`（path 归一并去重斜杠）
```

- **路径归一**：`serviceUrl(service, '')` → 前缀；`serviceUrl(service, '/users')` 与 `serviceUrl(service, 'users')` 均得 `/api/{service}/v1/users`；反斜杠不做转换（URL 用正斜杠）。

### 4.2 宿主请求层改造与 baseURL 收敛 <a id="request"></a>

- **请求入口**（`apps/desktop/src/api/request.ts`）：
  - 移除 `API_PREFIX` 与单前缀 `get/post/put/del(url)`；改为 `apiUrl(service, path)` 与 `get/post/put/del(service, path, …)`，URL 一律经核心 `serviceUrl` 组装；写方法仍自动带幂等键；`newKey` 保留。
  - 兼容说明：现有调用方仅测试与 dev 占位（无生产页面），改造无生产破坏面。
- **baseURL 收敛**（`apps/desktop/src/api/http.ts`）：Axios `baseURL` 取 `import.meta.env.VITE_API_BASE ?? '/'`（同源部署：静态由 nginx 托管、`/api` 反代网关；跨源联调时可经 env 指向网关）。请求 URL 为服务段绝对路径（`/api/...`），与 baseURL 拼接后不变。
- **401 口径**：沿用 `HttpHooks.onUnauthorized`（宿主入口注入清会话 + 跳登录），后端登录就绪后由阶段六注入刷新处理器；未注入时按会话失效占位（清会话 + 跳登录、不发请求）——与《前端开发规范》§11「实现口径」一致。本任务只把钩子装配按服务段收敛，不引入真实刷新。

### 4.3 能力源按服务注入 endpoint <a id="sources"></a>

- **资源段 → 服务映射**（依据后端各服务路由 prefix；前端单一来源消费）：

| 能力源 | 资源段 | 服务 |
| --- | --- | --- |
| 字典数据源（含高级查询 / 查询方案） | `/dicts/*`、`/query-schemes` | `platform` |
| 组织主数据源 | `/org/*` | `org` |
| 验证码数据源 | `/captcha/*` | `identity` |
| 文件上传传输 / 预签名 URL | `/files/*` | `file` |
| 全文检索引擎 | `/search/*` | `search` |
| AI 流式 / 助手 | `/chat/*` | `ai` |
| 通知 | `/notifications/*` | `notification` |
| 租户 | `/tenants/*`、`/tenant-registry` | `tenant` |
| 报表打印 | `/prints/*` | `report` |

- **宿主端点选项解析**（`apps/desktop/src/api/endpoints.ts`，仅组装纯对象，无 UI / 路由依赖）：

```text
SourceEndpointOptions = { endpoint: string; headers: () => Record<string, string> }
├── authHeaders()                 # 有令牌时 `{ Authorization: 'Bearer <token>' }`，否则 `{}`
├── sourceEndpoint(service)       # { endpoint: servicePrefix(service), headers: authHeaders }
├── dictSourceOptions()           # sourceEndpoint('platform')
├── orgSourceOptions()            # sourceEndpoint('org')
├── captchaSourceOptions()        # sourceEndpoint('identity')
├── uploadTransportOptions()      # sourceEndpoint('file')
├── searchEngineOptions()         # sourceEndpoint('search')
└── aiStreamEndpoint(path?)       # serviceUrl('ai', path ?? '/chat/stream')
```

- **消费接线**：`DictCheck.vue` → `createHttpDictSource(dictSourceOptions())`；`CaptchaCheck.vue` → `createHttpCaptchaSource(captchaSourceOptions())`；其余能力源（org / file / search / ai）当前 dev 页用桩，宿主提供同名选项函数供后续页面按同口径消费（结构类型可直接传入各 `createHttp*` 选项）。
- 能力源内部仍走 `globalThis.fetch` + 注入 `headers`（既有设计），不新增第二套请求客户端。

### 4.4 路由守卫与登录占位（默认关闭） <a id="guard"></a>

- **守卫逻辑落核心**（`packages/core/src/domain/route-guard.ts`，纯函数、可测）：`resolveAuthRedirect({ hasToken, path, publicPaths? })` 判定；命中规则：无令牌且路径不在公开白名单（`/login`、错误页 `/403` `/404` `/500`）→ 返回登录路径，否则 `null`。
- **宿主接线**（`apps/desktop/src/router/guard.ts` + `router/index.ts`）：注册 `router.beforeEach`，**默认关闭强制跳转**——仅当 `import.meta.env.VITE_AUTH_GUARD === 'on'` 时启用（阶段六登录就绪后改为默认开启）。开关关闭时守卫直接放行，不破坏现有 dev / 演示可用性。
- **登录占位页**（`views/LoginView.vue`）：提示「登录链路随阶段六接入」，路由 `/login` 始终注册（供守卫开启时跳转）。
- **公开白名单**：`/login` 与错误页；其余路径受守卫管辖（开启时）。

### 4.5 9 份契约前端类型生成（`@bms/api-types`） <a id="types"></a>

- **包形态**：新增 workspace 包 `frontend/packages/api-types`（`pnpm-workspace.yaml` 已含 `frontend/packages/*`，自动纳入）。`exports["."] = ./src/index.ts`（源码直出，与 `@bms/core` 同款）。
- **唯一事实源**：`deploy/contracts/<service>.json`（9 份公开契约快照；`deploy/contracts/baseline/` 为门禁基线，**不作为生成来源**）。
- **生成器**（`scripts/generate.mjs`）：枚举 `deploy/contracts/*.json`（排除 `baseline/`），逐个经 `openapi-typescript` 转 AST → `astToString` 写 `src/<service>.ts`；生成 `src/index.ts`（`export type * as <service> from './<service>'`，命名空间与服务键一致）。产物带「勿手改 + 重生成命令」头注释；输出稳定、可比对（无时间戳）。
- **零漂移校验**（`gen:check`）：重新生成到临时目录并与仓库产物逐字节比对，不一致退出码 1（CI / 预检用）。
- **消费范围（本任务）**：交付生成包与生成 / 校验链路；当前组件能力源以 `unknown` 透传、无手写 API 类型可迁移，业务侧逐步消费（不强改现有组件）。
- **纳入门禁**：`@bms/api-types` 纳入根 `lint` / `check` 链（lint + typecheck + 导出面用例）。

### 4.6 dev 代理与联调口径 <a id="proxy"></a>

- `vite.config.ts` 的 `server.proxy`：`/api` 代理目标取 `VITE_API_PROXY`（缺省 `http://localhost:8088`，即网关 nginx 入口），按服务段原样透传（不经前端重写），dev 与生产同形；未起网关时可改指单服务 `http://localhost:8000` 过渡。
- `/healthz` 保留代理（默认同目标）；`/info` 保留指向后端（连通验证）。
- `env.d.ts` 声明 `VITE_API_BASE` / `VITE_API_PROXY` / `VITE_AUTH_GUARD`。

### 4.7 CI 零漂移门禁与预检 <a id="ci"></a>

- **新增 job `api-types-check`**（`test` 阶段，镜像 `ci-frontend:node22`）：`pnpm install --frozen-lockfile` → `pnpm run api-types:gen:check`；`rules:changes` 命中 `deploy/contracts/**/*`、`frontend/packages/api-types/**/*`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`（契约变更单独拉起前端类型校验，不受 `core-check` 路径限制）。MR 事件同样放行。
- **根链纳入**：`frontend/package.json` 增 `api-types:typecheck / lint / test / gen / gen:check` 脚本，`lint` / `check` 链插入 `api-types:*`；`core-check` job 经 `pnpm run check` 自动覆盖。
- **本地预检**：`check-preflight.py` 在「基座与边界」步骤后增前端类型零漂移步骤（`pnpm` 不可用时跳过并提示），保证推送前本地可验。

## 5. 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| 未知服务键调用 `servicePrefix` / `serviceUrl` | `isServiceKey` 判定；未知键按类型层约束（调用方传 `ServiceKey`），运行期传入非法值经归一兜底（不静默拼出错误前缀）——由用例锁定 |
| `serviceUrl` path 为 `''` / `/` / 多斜杠 | 归一为单斜杠拼接，不产生 `//` |
| 未注入请求适配器 | 核心 `request()` 抛 `BaseError(NOT_IMPLEMENTED)`（既有行为，不变） |
| 401 | 宿主钩子 `onUnauthorized`（清会话 + 跳登录）；未注入刷新处理器时按会话失效占位；不重复发请求 |
| 能力源未注入 `endpoint` | 各 `createHttp*` 保持既有缺省 `/api/v1`（占位 / 兼容），**但宿主一律显式注入服务段 endpoint**；未注入时按占位不请求（既有降级语义） |
| 契约快照缺某服务文件 | 生成器报错退出非 0（不产出半份类型）；`gen:check` 失败 |
| 契约变更未重生成类型 | `api-types-check` job 与本地预检零漂移失败（阻断） |
| 登录链路未就绪、守卫开启 | 无令牌 → 跳 `/login` 占位页；默认关闭时放行（不破坏现状） |
| dev 未起网关 | `/api` 代理 502；改 `VITE_API_PROXY` 指向单服务或先起网关（文档化） |
| 移动端 / 模块消费 | 核心映射跨端可用；宿主装配与模块 `api` 注入归后续（见第 8 节） |

## 8. 边界与开放项 <a id="boundary"></a>

- **归阶段六**：完整登录链路（`/auth/login` / `/auth/refresh`、授权码回调 / state / nonce / PKCE、用户 claims 与 `X-User-Id`）、401 刷新处理器真实注入、守卫默认开启与登录页真实表单。
- **归阶段七**：RBAC 权限码与路由 `meta.perm` 判定接线（守卫的模式位预留）。
- **归插件化后续**：运行时模块请求能力 `api` 注入 `ModuleHostContext` 与模块侧消费（本任务核心映射已跨端可复用，模块经宿主注入消费）。
- **归移动端阶段**：移动端宿主按同口径消费端点选项与守卫。
- **开放项**：`VITE_API_PROXY` 缺省网关端口（8088）与部署端口口径一致，随部署阶段域名 / TLS 复核；模块契约版本若因 `api` 注入扩展而递增，随该任务处理。
- **不改**：后端服务内 `/api/v1` 契约与响应体、网关声明式路由、既有 Kiwi 用例号、组件能力源既有缺省（`/api/v1`）兼容语义。
