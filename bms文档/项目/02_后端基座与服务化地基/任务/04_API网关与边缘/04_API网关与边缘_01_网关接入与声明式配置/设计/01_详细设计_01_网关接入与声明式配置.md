## 1. 概述 <a id="overview"></a>

- **目标**：以 Apache APISIX **standalone（文件驱动）** 模式建立边缘统一入口，随 `deploy` 编排一体、本地一键拉起；路由 / 上游由**服务目录**（`SERVICE_CATALOG`）生成、声明式入 Git，改动经流水线校验与热加载；前端静态资源由 nginx 托管、与 API 流量分流；配置模型保持可平移 K8s Ingress / Gateway API。
- **依据**：《[架构设计 · API 网关与边缘](../../../../../../设计/架构设计/36_架构设计_子系统_API网关与边缘.md)》「部署形态与演进」「边缘功能」节；《[微服务演进规划](../../../../../../规划/微服务演进规划.md)》「技术选型」「服务化地基要求与门禁（S4）」节；《[架构设计 · 部署与运维](../../../../../../设计/架构设计/33_架构设计_部署与运维.md)》「基础设施编排」节；《[部署发布规范](../../../../../../规范/部署发布规范.md)》；需求 [04-1](../../../../需求/04_需求_API网关与边缘.md#r04-1)。
- **范围（本任务）**：
  1. **容器化接入**：新增 `deploy/compose/gateway.yml`（APISIX standalone 容器 + nginx 静态分流容器），与 `deploy/compose/base.yml` 组合随一键拉起就位。
  2. **声明式配置入 Git**：`deploy/gateway/config.yaml`（APISIX 启动配置：standalone `data_plane` + yaml provider）与 `deploy/gateway/apisix.yaml`（路由 / 上游，**由服务目录生成**）。
  3. **路由以服务目录为依据**：生成脚本读 `SERVICE_CATALOG`，为每个**启用**服务产出上游与路由；外部路径 `/api/{service_key}/v1/...` 经 `proxy-rewrite` 还原为服务内 `/api/v1/...`。
  4. **静态资源分流**：`deploy/gateway/nginx.conf` 托管静态目录并把 `/api/` 反代至网关（骨架，前端产物接入归部署阶段）。
  5. **零漂移校验接入 CI**：`backend/ops/gateway_config.py check` 断言「服务目录 → apisix.yaml」零差异，接入 `base-integrity` job 与本地预检。
  6. **演进预留**：认证 / 限流插件挂点在生成器中预留（`ROUTE_PLUGINS` 钩子、`consumers` / `plugin_metadata` 结构可扩展），**默认不启用**——真正开启归 04_02 / 04_03。
- **不含（明确归口，见第 8 节）**：边缘认证与请求净化（04_02）；限流与服务发现共享计数（04_03）；OIDC IdP 与双类 JWT（07_需求）；边缘观测出口（RocketMQ / ES，08_需求）；前端静态产物构建与接入（部署阶段 13）；每服务独立配置与端口（06_需求）。

## 4. 领域设计 <a id="design"></a>

### 4.1 部署形态与编排 <a id="deploy"></a>

- **模式**：APISIX **standalone 文件驱动**（`deployment.role: data_plane` + `role_data_plane.config_provider: yaml`，镜像经 `APISIX_STAND_ALONE=true` 跳过 etcd 初始化）——**不引入 etcd / Admin API / Dashboard**；路由规则落 `apisix.yaml`，APISIX 每 1 秒轮询文件变化并**热更新内存**（不重启进程）。
- **编排**：`deploy/compose/gateway.yml` 定义两个服务，与 `base.yml` 组合使用（共享默认网络，服务名即 DNS 名）：

| 服务 | 镜像 | 容器 | 端口 | 挂载 |
| --- | --- | --- | --- | --- |
| `apisix` | `apache/apisix:3.18.0-debian` | `bms-apisix` | `${GATEWAY_APISIX_PORT:-9080}:9080` | `../gateway` → `/etc/bms-gateway`（ro，目录挂载） |
| `gateway-nginx` | `nginx:1.27` | `bms-gateway-nginx` | `${GATEWAY_HTTP_PORT:-8088}:80` | `../gateway/nginx.conf`（ro）、`../gateway/static`（ro） |

- **热加载挂载口径（关键）**：**不用单文件 bind mount**——宿主文件被替换（git 检出 / 重建）后单文件 bind 仍指向旧 inode，APISIX 的 1s 文件轮询读不到新内容、无法热加载。改为**目录挂载 + 启动时软链**：`entrypoint` 覆写为「`ln -sfn /etc/bms-gateway/{config,apisix}.yaml` 进 `conf/` 后 `exec /docker-entrypoint.sh docker-start`」，宿主替换即时经软链可见（mjbk 实测原地写入与整文件替换均触发 `apisix.yaml reloaded`）。
- **一键拉起**（在 `deploy/` 目录，`.env` 提供变量）：

```bash
docker compose -f compose/base.yml -f compose/gateway.yml --env-file .env up -d
```

- **无状态与可平移**：APISIX 只读挂载声明式配置，无本地状态；迁 K8s 时同 `apisix.yaml` 换由 Ingress Controller / Gateway API CRD 承载（见 4.6）。
- **端口口径**：网关容器内监听 `9080`（HTTP）；暴露端口与 nginx 入口端口均可用环境变量覆盖，避免与宿主端口冲突。

### 4.2 APISIX 启动配置 <a id="boot"></a>

`deploy/gateway/config.yaml`（启动配置，手写、不含密钥；`#END` 仅 `apisix.yaml` 需要）：

```yaml
apisix:
  node_listen: 9080
deployment:
  role: data_plane
  role_data_plane:
    config_provider: yaml
nginx_config:
  error_log_level: warn
```

- `node_listen`：网关 HTTP 监听端口（容器内 9080）。
- `role: data_plane` + `config_provider: yaml`：文件驱动 standalone，Admin API 不启用。
- 其余键（TLS / 插件默认集等）沿用镜像默认；需要调整时在此文件显式声明。

### 4.3 声明式路由与上游（服务目录生成） <a id="config"></a>

**单一来源**：`bms_core/services/module_registry.py::SERVICE_CATALOG`。生成规则：

| 项 | 规则 |
| --- | --- |
| 参与生成 | `service_key` 非空 **且** `status == enabled` 的服务行（当前 9 个：`platform` / `identity` / `tenant` / `org` / `file` / `notification` / `search` / `ai` / `report`） |
| 排除 | 纯模块行（`service_key` 为空，如 biz 产品模块）、`planned` 服务（如 `wf` 尚未实现）、`disabled` 服务 |
| 上游 `id` | 服务标识 `service_key` |
| 上游节点 | `{service_key}:{port}`（Compose DNS 名 + 服务端口；端口常量默认 `8000`，每服务端口归 06_需求） |
| 上游类型 | `roundrobin` |
| 路由 `id` | `route-{service_key}` |
| 路由 `uris` | 精确 `/api/{service_key}/v1` 与前缀 `/api/{service_key}/v1/*` |
| 上游绑定 | `upstream_id: {service_key}` |
| 路径重写 | `proxy-rewrite.regex_uri = ['^/api/{service_key}/v1(.*)$', '/api/v1$1']` |

- **顺序**：按服务目录（`SERVICE_CATALOG`）原始顺序输出，保证确定性。
- **生成件**（`deploy/gateway/apisix.yaml` 形态，节选）：

```yaml
# 本文件由 backend/ops/gateway_config.py render 生成，请勿手工修改；来源：服务目录 SERVICE_CATALOG。
upstreams:
  - id: platform
    type: roundrobin
    nodes:
      'platform:8000': 1
  - id: identity
    type: roundrobin
    nodes:
      'identity:8000': 1
routes:
  - id: route-platform
    uris:
      - '/api/platform/v1'
      - '/api/platform/v1/*'
    upstream_id: platform
    plugins:
      proxy-rewrite:
        regex_uri:
          - '^/api/platform/v1(.*)$'
          - '/api/v1$1'
  - id: route-identity
    uris:
      - '/api/identity/v1'
      - '/api/identity/v1/*'
    upstream_id: identity
    plugins:
      proxy-rewrite:
        regex_uri:
          - '^/api/identity/v1(.*)$'
          - '/api/v1$1'
#END
```

- `#END` 为 APISIX 文件驱动模式的**必需结束标记**，缺少则不加载。
- 生成字符串一律**单引号包裹**（正则含 `^ $ ( ) *` 等 YAML 特殊字符）；键 / 结构固定，输出稳定可比对。

### 4.4 外部路径约定与重写 <a id="path"></a>

- **外部**：`/api/{service_key}/v1/{资源...}`；**内部**：各服务统一 `/api/v1/{资源...}`（`bms_core/api/base.py::API_PREFIX` 不变）。
- **重写**：`^/api/{service_key}/v1(.*)$ → /api/v1$1`。示例：

| 外部请求 | 命中路由 | 上游 | 到服务内路径 |
| --- | --- | --- | --- |
| `GET /api/identity/v1/captcha/challenges` | `route-identity` | `identity:8000` | `GET /api/v1/captcha/challenges` |
| `GET /api/org/v1/org/users` | `route-org` | `org:8000` | `GET /api/v1/org/users` |
| `GET /api/platform/v1/modules` | `route-platform` | `platform:8000` | `GET /api/v1/modules` |

- **消费方影响（契约变更，需标注）**：前端经网关接入的后端基址由 `/api/v1` 变为 `/api/{service_key}/v1`（组件 `endpoint` 已可配置，按服务切换）；本任务**只登记该对接事项**，前端实际改造与 baseURL 收敛归前端接入环节（08 / 09_需求）。现有服务端契约（`/api/v1/...`）不变。

### 4.5 nginx 静态资源分流 <a id="nginx"></a>

`deploy/gateway/nginx.conf`（`/etc/nginx/conf.d/default.conf`，http 上下文内）：

| 位置 | 行为 |
| --- | --- |
| `location /api/` | `proxy_pass http://apisix:9080`，透传 `Host` / `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto`；`Upgrade` / `Connection` 透传（WebSocket 放行，如 `/socket.io`） |
| `location /` | `try_files $uri $uri/ /index.html`（前端静态托管；SPA 回退） |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy`（CSP / HSTS 留占位，dev 关闭，生产随 TLS 启用） |

- **分流口径**：静态资源由 nginx 直接托管、API 流量统一经 `/api/` 反代网关（「网关只处理 API」）。
- **静态目录**：`deploy/gateway/static/`（本任务含占位 `index.html`）；前端构建产物接入归部署阶段 13。

### 4.6 K8s 平移口径 <a id="k8s"></a>

| 单机（本任务） | K8s 阶段 | 说明 |
| --- | --- | --- |
| APISIX `route.uris` + `upstream_id` | Ingress `path` + `backend.service` / Gateway API `HTTPRoute.matches` + `backendRefs` | 路径与方法匹配语义一致 |
| `proxy-rewrite.regex_uri` | Ingress `rewrite-target` annotation / HTTPRoute `URLRewrite` filter | 前缀重写语义一致 |
| 上游节点 `{service_key}:8000`（Compose DNS） | `Service` 名（CoreDNS） | 「按名寻址」心智平移，不换选型 |
| `config.yaml` / `apisix.yaml` 入 Git | Ingress Controller CRD / Helm values 入 Git | 声明式 + GitOps 不变 |

- 域名与 TLS 由边缘统一管理（K8s 阶段接入证书），本任务不落 TLS。

### 4.7 生成与校验脚本 <a id="script"></a>

**核心生成器** `bms_core/services/gateway_catalog.py`（纯逻辑，可单测）：

```text
gateway_catalog.py
├── SERVICE_PORT = 8000                       # 上游默认端口（每服务端口归 06_需求）
├── ROUTE_PLUGINS: Mapping[str, Mapping[str, object]] = {}   # 路由插件钩子（04_02 认证 / 04_03 限流填充）
├── gateway_services() -> tuple[ModuleRecord, ...]   # 目录过滤：service_key 非空且 enabled
├── route_prefix(service_key) -> str          # /api/{service_key}/v1
├── render_upstreams() -> list[dict]          # 上游段
├── render_routes() -> list[dict]             # 路由段（含重写与插件钩子合并）
├── render_apisix_config() -> dict            # {upstreams, routes}（可扩展 consumers / plugin_metadata）
└── render_apisix_yaml() -> str               # 确定性 YAML 文本（单引号包裹，末尾 #END）
```

**命令入口** `backend/ops/gateway_config.py`（薄 CLI，stdlib + `bms_core`；自动把 `libs/bms_core/src` 加入 `sys.path`）：

| 命令 | 行为 |
| --- | --- |
| `render` | 生成 `deploy/gateway/apisix.yaml`（覆盖写入） |
| `check` | 与仓库内 `apisix.yaml` 逐字节比对；不一致打印差异提示并退出码 1（CI / 预检用） |
| `--print` | 打印生成内容到 stdout（调试用） |

- **CI 接入**：`.gitlab-ci.yml` 的 `base-integrity` job 增跑 `python backend/ops/gateway_config.py check`（无 Docker、秒级；脚本仅依赖标准库 + `bms_core` 的 stdlib 导入链）。
- **本地接入**：`scripts/tools/preflight/check-preflight.py` 的基座与边界步骤纳入同一命令。
- **热加载**：更新 `apisix.yaml` 后无需重启容器——APISIX 1 秒内轮询到文件变化并热更新；流水线部署时替换挂载文件即可。

### 4.8 认证与限流预留（不启用） <a id="reserve"></a>

- 生成器输出结构天然支持 APISIX `consumers` / `plugin_metadata` / `global_rules` 段与路由级 `plugins`；本任务只输出 `upstreams` / `routes`，路由插件仅 `proxy-rewrite`。
- `ROUTE_PLUGINS` 钩子按 `service_key` 合并附加插件：04_02 填 `openid-connect`（认证）、04_03 填 `limit-count`（限流），无需改生成结构。
- **不启用**原因：IdP（Keycloak，07_01）与共享 Redis 限流尚未就绪，启用会导致冒烟链路被未就绪依赖阻断；本任务保持「可独立跑通」。

## 5. 失败分支与边界 <a id="failures"></a>

| 场景 | 处理 |
| --- | --- |
| 服务目录某启用服务无对应容器 | 网关按其上游名路由，DNS 解析失败 / 连接拒绝 → 502（预期；服务容器化归 09/06） |
| 未登记服务的路径（如 `/api/foo/v1/...`） | 无匹配路由 → APISIX 404 |
| 路由 `uris` 仅匹配 `/api/{service_key}/v1` 与 `/v1/*` | 其它形态（缺 `v1`、多段错位）不匹配，返回 404，避免误路由 |
| `apisix.yaml` 缺 `#END` | APISIX 不加载规则（空配置）→ 全 404；由生成器保证末尾标记 + `check` 兜底 |
| 生成件与目录漂移（手工改了 yaml / 目录变更未重生成） | `gateway_config.py check` 退出码 1，CI `base-integrity` 拦截 |
| `SERVICE_CATALOG` 出现重复 `service_key` | 生成器去重校验失败（不应发生；目录校验 03_02 已拦） |
| 上游端口与 06_需求 每服务端口不一致 | 本任务端口常量 8000（统一默认）；06_需求落地后回改 `SERVICE_PORT` 来源并重生成 |
| nginx 未启动 / 静态目录为空 | `/api/` 反代不可达报 502；`/` 占位页可访问（前端产物接入归 13） |
| 宿主端口冲突（8088 / 9080 被占） | 经 `GATEWAY_HTTP_PORT` / `GATEWAY_APISIX_PORT` 覆盖 |
| 达梦 / 三库方言 | 不涉及（网关不直连数据库） |

## 6. 测试设计与验收映射 <a id="tests"></a>

用例先登记 Kiwi TCMS（本任务登记 **1 条策展用例**，多条断言共用同一 `kiwi_id`，编号以平台回读为准，见第 9 节）。

## 8. 边界与开放项 <a id="boundary"></a>

- **归 04_02**：边缘认证（`openid-connect`）与请求净化（剥头 / 注入身份）——在 `ROUTE_PLUGINS` 与 `global_rules` 上扩展。
- **归 04_03**：限流（`limit-count` + 共享 Redis）与服务发现（DNS 寻址用例、无硬编码 IP）——上游寻址本任务已定 `{service_key}:{port}`。
- **归 06_需求**：每服务独立配置与端口；`SERVICE_PORT` 由常量改为按服务端口来源。
- **归 07_需求**：OIDC IdP 与双类 JWT；网关认证接线（07_03）。
- **归 08_需求 / 部署阶段 13**：边缘观测出口（RocketMQ / ES）；前端静态产物构建与接入、域名与 TLS。
- **归 09_需求**：每服务镜像构建发布（服务容器化后上游名可用）；父-子流水线。
- **开放项**：外部路径前缀 `/api/{service_key}/v1` 属**契约变更**，前端 baseURL 收敛归前端接入环节；服务目录未登记 URL 前缀字段（前缀由约定推导，未落库）。
- **不改**：服务内 `/api/v1` 前缀与响应体、探针口径、既有服务目录生成规则、既有 Kiwi 用例号。
