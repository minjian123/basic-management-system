## 2. 测试范围 <a id="scope"></a>

本任务为**边缘网关接入与声明式配置**，测试面分三层：

1. **生成器单元**（`bms_core/services/gateway_catalog.py`）：服务目录过滤、上游 / 路由结构、外部前缀重写、确定性、插件钩子、YAML 发出器分支。
2. **CLI 单元**（`backend/ops/gateway_config.py`）：`render` / `check` / `--print` 与零漂移拦截、`__main__` 入口。
3. **真实冒烟**（mjbk Docker）：容器随编排拉起、按服务路由 + 路径重写、nginx 分流、未登记服务 404、配置热加载（原地写入 / 整文件替换）。

## 5. 真实冒烟（mjbk） <a id="smoke"></a>

编排：`docker compose -p bmsgwsmoke -f compose/gateway.yml up -d`（APISIX 3.18.0-debian + nginx），最小上游 `traefik/whoami`（容器名 / DNS `platform`，端口 8000）。

| # | 场景 | 请求 | 预期 | 实测 |
| --- | --- | --- | --- | --- |
| 1 | 网关容器随编排拉起 | `docker ps` | `bms-apisix` / `bms-gateway-nginx` Up | 通过（`Server: APISIX/3.18.0`） |
| 2 | 按服务路由 + 前缀重写 | `GET :9080/api/platform/v1/ping` | 命中 `platform` 且上游见 `/api/v1/ping` | 200；`GET /api/v1/ping` |
| 3 | 经 nginx 入口分流 | `GET :8088/api/platform/v1/ping` | 200 且重写一致 | `GET /api/v1/ping` |
| 4 | 静态资源托管 | `GET :8088/` | 200 | 200（占位首页） |
| 5 | 精确前缀路径 | `GET :9080/api/platform/v1` | 200 且上游见 `/api/v1` | `GET /api/v1` |
| 6 | 未登记服务 | `GET :9080/api/nope/v1/x` | 404 | 404 |
| 7 | 热加载（原地写入） | 追加 `route-hotreload` → `GET /api/hotreload/v1/ping` | 1s 内生效 | 200；日志 `apisix.yaml reloaded` |
| 8 | 热加载（整文件替换） | 移除 `route-hotreload` → 访问 | 新路由撤销、原路由不受影响 | 404 / 原路由 200 |

结论：**路由以服务目录为依据、经网关按服务路由到目标服务、路径重写正确、声明式配置改动经文件轮询热加载生效**，完成标准达成。

## 6. 问题与偏差 <a id="issues"></a>

- 单文件 bind mount 无法热加载 → 改「目录挂载 + 软链进 `conf/`」（实施记录 §4；设计 §4.1 已回写）；真实冒烟第 7/8 项为该修正的验证。
- 外部路径前缀 `/api/{service_key}/v1` 属契约变更，消费方 04_02 / 04_03 / 前端接入已登记（消费方现网为零）。
- 未发现缺陷；`init_tenant` / 达梦等无关遗留见阶段计划「后续阶段待办」。
