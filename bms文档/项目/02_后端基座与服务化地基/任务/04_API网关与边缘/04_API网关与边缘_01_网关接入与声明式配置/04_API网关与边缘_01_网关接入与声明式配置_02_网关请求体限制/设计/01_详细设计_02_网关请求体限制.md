## 1. 概述 <a id="overview"></a>

明确**网关请求体上限**的取值与落点，并使其与**文件上传口径**一致：≤20MB（`file.upload.max_size`）整包直传、>20MB 走分片；超限在边缘层先拒（413），APISIX 侧同值作纵深防御。配置**声明式入 Git**（模板 / 编排 / 启动配置），并以**机器校验**保证三方一致。

## 2. 现状与差距 <a id="gap"></a>

| 面 | 现状 | 差距 |
| --- | --- | --- |
| 边缘 nginx（`deploy/gateway/nginx.conf.template`） | 未配置 `client_max_body_size` → **默认 1m** | 20MB 整包直传被 413 先拒（与文件策略冲突） |
| APISIX（`deploy/gateway/config.yaml`） | 无请求体限制 | 直连 APISIX（绕过边缘）时无上限 |
| 编排 / 环境变量 | 无该项键位 | 上限无法按环境调整、无口径校验 |

## 3. 交付物清单 <a id="deliver"></a>

| # | 交付物 | 落点 |

## 4. 领域设计 <a id="design"></a>

### 4.1 取值口径（与文件上传对齐） <a id="value"></a>

| 项 | 值 | 依据 |
| --- | --- | --- |
| 整包上传上限 | **20MB**（`20971520` 字节） | 《概要设计 · 系统参数》`file.upload.max_size`；超限走分片 |
| 单文件上限 | 2GB（`file.upload.max_file_size`） | 同上（超限拒绝，与网关无关） |
| 网关请求体上限 | **32m**（缺省，经 `GATEWAY_MAX_BODY_SIZE` 可调） | 20MB 整包 + multipart 表单开销 + 一片余量；**下界约束：≥ 20MB** |

**入方向（边缘 nginx 414/413）**：请求体 > 上限 → nginx 先拒（**413**）；APISIX 侧同值（直连时同样受限）。
**分片不受影响**：分片单片大小由文件管理阶段初始化接口下发，**单片 ≤ 整包上限（20MB）** 时天然低于网关上限；若将来单片值上调超过上限，须同步上调网关值（登记为开放项，见 §7）。

### 4.2 落点与声明式 <a id="landing"></a>

- **边缘（确定生效）**：模板 `location /api/` 内 `client_max_body_size ${GATEWAY_MAX_BODY_SIZE};`——经 nginx 官方镜像入口脚本按 `NGINX_ENVSUBST_FILTER=^GATEWAY_` 渲染；**不硬编码**（按环境可调，生产可下调）。
- **APISIX（纵深防御）**：`config.yaml` 的 `nginx_config` 节内配置同值；键名沿用该文件既有 `http` 节（与访问日志配置同节、与 apisix `3.18.0-debian` 既有可用配置一致）；APISIX 3.9+ 该节更名为 `http_config`，**若目标镜像启动校验拒绝 `http` 键名则改 `http_config`**（实测口径，见 §7）。
- **编排与键位**：`compose/gateway.yml` 提供缺省值（无缺省会导致渲染出空值、nginx 启动失败）；`.env.example` 登记键位（`check-env-example` 覆盖）。

### 4.3 机器校验（三方一致 + 口径对齐） <a id="guard"></a>

`ops.gateway_config check` 在既有「生成件零漂移 + 服务发现无硬编码 IP」之外新增断言（`validate_body_size`）：

| # | 断言 | 失败即退出码 1 |
| --- | --- | --- |
| 1 | 边缘模板**含变量化声明**（`client_max_body_size ${GATEWAY_MAX_BODY_SIZE};`） | 硬编码 / 缺失 |
| 2 | 编排给出**缺省值**且可解析（`k` / `m` / `g` / 纯字节） | 无缺省 / 不可解析 |
| 3 | APISIX 配置值与**编排缺省值一致** | 缺项 / 不一致 |
| 4 | `.env.example` 键位值与编排缺省值一致 | 缺项 / 不一致 |
| 5 | 上限 **≥ 文件上传整包上限**（20MB） | 小于整包上限 |

### 4.4 失败分支与边界 <a id="edge"></a>

| 场景 | 行为 |
| --- | --- |
| 请求体超上限 | 边缘 nginx 返回 **413**（不落 500/502）；前端应在提交前按文件上限预校验，服务端 413 作兜底 |
| 分片上传（单片 ≤ 20MB） | 不受影响（每片独立请求，均低于上限） |
| 生产下调上限 | 允许（经环境变量），但不得低于「整包上限 + multipart 开销」——由 §4.3 第 5 项兜底（下界 = 20MB） |
| APISIX 键名不被镜像接受 | 改 `http_config`（实测口径，登记 §7） |

### 4.5 测试设计 <a id="test"></a>

| 验收点（需求 04-5） | 校验 |
| --- | --- |
| 配置就位且与文件策略一致 | §4.3 五项断言（仓库内 + 负例） |
| 超限拒绝口径一致 | 边缘先拒（413）；APISIX 同值（真机实测随部署，见 §7） |
| 分片上传实测通过 | 真机实测随部署（单片 ≤ 20MB 时天然满足） |
| 校验通过 | `preflight --fast` 含 `gateway_config check`；`pytest` / `ruff` / `pyright` |

## 5. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 取值口径 | **32m**（20MB 整包 + multipart 开销 + 一片余量），经 `GATEWAY_MAX_BODY_SIZE` 可调（生产可下调） |
| 2 | 落点 | **双保险**：边缘 nginx（先拒）+ APISIX 全局同值（纵深防御） |
| 3 | 实测方式 | **配置断言 + 随部署实测**（本机无容器运行时；真机 413 与分片实测登记为部署联调随行） |
| 4 | 校验形态 | 纯函数 `validate_body_size(root)` 可单测；接入 `check`（纳入预检与 CI） |
