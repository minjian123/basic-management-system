## 3. 实施过程 <a id="process"></a>

1. **Kiwi 用例登记（先登记后编码）**：登记 1 条策展用例覆盖全部断言面，平台回读编号 **2165**；登记输入 `test/scripts/kiwi/cases/2026-09-23_阶段二04-01_网关接入与声明式配置.json`。
2. **生成器（单一来源）**：新增 `bms_core/services/gateway_catalog.py`——读 `SERVICE_CATALOG`，仅 `service_key` 非空且 `status=enabled` 的服务参与（9 个）；输出 `upstreams`（id=service_key、节点 `{service_key}:8000`、roundrobin）与 `routes`（外部 `/api/{service_key}/v1` 精确 + 前缀，`proxy-rewrite.regex_uri` 还原 `/api/v1$1`）；手写最小 YAML 发出器（单引号按需包裹、`#END` 结尾）；`ROUTE_PLUGINS` 钩子供 04_02 / 04_03 合并插件。
3. **命令行入口**：新增 `backend/ops/gateway_config.py`（`render` / `check` / `--print`），自行把共享库源码根加入 `sys.path`，仅依赖标准库 + `bms_core` 的 stdlib 导入链，可在 CI 精简镜像（python:3.14-slim）下运行。
4. **编排与配置**：新增 `deploy/gateway/config.yaml`（standalone `data_plane` + yaml provider）、`deploy/gateway/apisix.yaml`（生成件）、`deploy/gateway/nginx.conf`（静态托管 + `/api` 反代 + 安全响应头 + WebSocket 放行）、`deploy/gateway/static/index.html`（占位）与 `deploy/compose/gateway.yml`（APISIX + nginx，`APISIX_STAND_ALONE=true`），并与 `base.yml` 组合拉起。
5. **热加载口径修正（关键）**：真实冒烟前实测发现**单文件 bind mount** 在宿主文件被替换（git 检出 / 重建）后，容器内仍指向旧 inode，APISIX 的 1s 文件轮询读不到新内容；**改为挂载配置目录 + 启动时软链进 `conf/`**（`entrypoint` 覆写），使宿主替换即时可见——mjbk 实测「原地写入」与「整文件替换」均触发 `apisix.yaml reloaded`。
6. **依赖与锁定**：`pyproject.toml` dev 依赖补 `pyyaml>=6.0`（生成件 YAML 结构校验用）并 `uv lock`（`uv.lock` +1 行）。
7. **CI 与预检**：`.gitlab-ci.yml` `base-integrity` 增跑 `python backend/ops/gateway_config.py check`；`scripts/tools/preflight/check-preflight.py` 基座与边界步骤纳入同命令（docstring 同步）。
8. **用例与门禁**：新增 `test_gateway_catalog.py` / `test_gateway_config.py`（各断言面 + 私有分支全覆盖）；全量 `pytest` / `ruff` / `pyright` / 基座校验 / 预检全绿。
9. **mjbk 真实冒烟**：配置送 mjbk 临时目录 → `docker compose -p bmsgwsmoke -f compose/gateway.yml up -d` 拉起 APISIX + nginx → 同网络起最小上游 `traefik/whoami`（命名 `platform`，端口 8000）→ 逐项验证（见 §5）→ 清理无残留。
10. **登记回写与记录**：见 §6 与测试记录。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| 单文件 bind mount 无法热加载 | 宿主替换 `apisix.yaml`（新 inode）后容器内读到的仍是旧内容，APISIX 文件轮询不触发 | 改挂载配置目录 `../gateway:/etc/bms-gateway:ro`，`entrypoint` 覆写为「软链 `config.yaml` / `apisix.yaml` 进 `conf/` 后 exec 官方 `docker-start`」；实测原地写入与整文件替换均热加载 |
| 镜像标签 | 问题确认口径为 `apache/apisix:3.18.0`，但官方 Docker 实际标签为 `apache/apisix:3.18.0-debian` | compose 采用 `3.18.0-debian`（仍锁定版本）；设计 §4.1 与决策记录已按实际标签登记 |
| CLI 在精简镜像可运行 | CI `base-integrity` 用 python:3.14-slim，无后端依赖 | `ops/gateway_config.py` 自行插入 `libs/bms_core/src`；已验证 stdlib 导入链（`module_registry` → `core.base` → `core.serialization` / `core.version`）纯标准库 |
| runpy 入口用例告警 | `runpy.run_module` 报「found in sys.modules」`RuntimeWarning` | 用例先 `monkeypatch.delitem(sys.modules, "ops.gateway_config")` 再执行 `__main__` 守卫 |
| 生成件 YAML 需可解析验证 | 手写发出器需保证语法合法 | dev 依赖补 `pyyaml`，用例 `yaml.safe_load` 生成件并断言结构 |
| 设计文档相对链接层级 | 需求 / 计划链接少一级导致 4 处断链 | 按同级任务口径修正为 `../../../../需求|计划/…`；`check-links` 全库 0 断链 |

## 7. 偏差与遗留 <a id="deviations"></a>

- **偏差（已登记）**：① 单文件 bind mount 无法热加载 → 改目录挂载 + 软链（设计 §4.1 已补）；② APISIX 实际镜像标签为 `3.18.0-debian`（设计 §4.1 / 决策记录按实际登记）；③ dev 依赖新增 `pyyaml` 并 `uv lock`（ci-backend 基础镜像按锁哈希自动重建）。
- **契约变更（消费方已标注）**：外部路径前缀 `/api/{service_key}/v1/...`（原前端默认 `/api/v1`）——消费方为 04_02 / 04_03 / 07_03（网关认证接线）与前端接入环节（08 / 09_需求）；服务内 `/api/v1` 契约不变，现网消费方为零。
- **遗留（归口）**：① 每服务上游端口现为常量 8000 → **06_需求**（每服务独立配置与端口）；② 各服务容器化前，网关对未部署服务的路由返回 502（预期）→ **09_需求**（按服务镜像构建发布）；③ 边缘认证 / 限流插件钩子默认空 → **04_02 / 04_03**；④ 前端静态产物接入与 TLS / 域名 → **部署阶段 13**。
