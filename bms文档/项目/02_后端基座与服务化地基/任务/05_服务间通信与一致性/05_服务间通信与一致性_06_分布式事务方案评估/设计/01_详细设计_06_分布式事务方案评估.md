## 1. 设计目标与范围 <a id="goal"></a>

承接需求 05-5：在 05_05 交付达梦 XA 方言、2026-10-06 三库 XA 实测的基础上，**回答「要不要引入应用级分布式事务（2PC / 跨服务 TM）」并给出可落地的替代方案**。本设计结论为：

1. **单库原子**：把要求「要么全成功要么全失败」的那部分数据（如结构化权限的「角色 + 用户分配 + 权限项」）**收敛到单一服务库**，用**本地事务**保证原子——不需要任何分布式事务。
2. **跨服务最终一致**：跨服务部分继续走既有「本地事务 + 事务性 Outbox + 幂等消费（+ 判据内 Saga 补偿）」基线，保证最终一致。
3. **新增一致性屏障**：补上基线缺的**「等待收敛」**一环——执行前校验「目标变更是否已应用」，未应用则有界等待、超时报错。这是本任务的**主交付代码**。
4. **2PC / 跨服务 TM 作技术储备**：不引入为主路径，但把「三库 2PC 可行性 + 自研跨服务 TM 可行方案」沉淀为知识档案，作为**将来对强一致要求严格的客户时经插件化替换**的后备方案。

**不在本期**：自研跨服务 TM 的运行时实现（协调服务 / 全局事务账本 / 服务侧 XA 参与端点，见知识档案《分布式事务 · 跨服务 TM 方案》）；悬挂分支自动回收器（本期仅取证与人工口径）。

### 1.1 现状与缺口 <a id="gap"></a>

- **已有（可直接复用）**：本地事务（`UnitOfWork`）、事务性 Outbox（`outbox/`）、幂等消费（`ProcessedEventStore`）、Saga 三态执行器（`saga/`）、权限版本失效机制（架构 15 §3，Redis 版本号 + 缓存键带版本）。
- **缺口**：① 跨服务变更后，**执行方无法确认变更是否已生效**，只能假定已生效或静默读旧值；② `bms_core` 无「一致性屏障」类能力域；③ 三库 2PC / 跨服务 TM 的完整可行性与代价未成文。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 一致性屏障契约 <a id="barrier"></a>

```python
class BaseConsistencyBarrier(BasePluggable, ABC):
    key: str = "consistency_barrier"
    plugin_key: str = "consistency_barrier"

    async def await_applied(
        self, *, scope: str, target_version: int, tenant: str | None = None,
        timeout_ms: int | None = None, poll_ms: int | None = None,
    ) -> None:
        """阻塞至「已应用版本 ≥ target_version」；超时抛 ConsistencyBarrierTimeout(10011)。"""

    async def applied_version(self, *, scope: str, tenant: str | None = None) -> int:
        """读取当前已应用版本（无记录返回 0）。"""

    async def mark_applied(self, *, scope: str, version: int, tenant: str | None = None) -> None:
        """推进已应用版本（消费方在副作用落库后调用；单调不回退）。"""
```

- **语义**：「版本」由**写方**在提交后产生（如权限版本号 +1），由**消费方 / 收敛点**在副作用落库后 `mark_applied` 推进；**执行方**在执行受保护操作前 `await_applied` 校验。
- **`scope`**：收敛域的键（如 `perm` 表权限、`org` 表组织）；与租户拼接为存储键 `bms:{tenant|global}:consistency:{scope}`。
- **默认值**：`timeout_ms` / `poll_ms` 缺省取配置分区（缺省 3000 / 100）。
- **单调性**：`mark_applied` 只前推不回退（`max(旧值, 新值)`），防乱序消费回退。
- **无状态依赖**：`null` 实现为即返回的 no-op（缺省），屏障按需开启、不默认拦业务。

### 3.2 三库单进程 2PC（技术储备，不接调用面） <a id="2pc"></a>

| 项 | 口径 |
| --- | --- |
| 适用范围 | **同一进程**同时连多个库、且需跨库原子（迁移 / 共址运维 / 将来的 TM 参与者），**不是**跨独立服务的默认能力 |
| 引擎 | **仅同步引擎**（SQLAlchemy 异步 API 不暴露 `begin_twophase`） |
| PostgreSQL 前置 | `max_prepared_transactions > 0`（实测 100）并重启 |
| 达梦前置 | `XA_COMPATIBLE_MODE ≠ 2`；连接串方言 `dmxa`（05_05 已交付，自动归一） |
| MySQL | InnoDB XA，`pymysql` 同步引擎直接可用 |
| 悬挂分支 | 三库均可见（MySQL `XA RECOVER` / PG `pg_prepared_xacts` / 达梦 `TABLE(DBMS_XA.XA_RECOVER())`）；**回收策略仅人工口径**，自动回收器另立 |
| 调用面 | **不对外暴露 2PC API**；确需时按场景另行立项（与「跨服务一致性只走 Outbox/Saga」基线不冲突） |

### 3.3 跨服务 TM（技术储备，不落地） <a id="tm"></a>

自研协调者形态、协调算法、全局事务账本、服务侧参与协议、崩溃恢复与悬挂对账的**可行方案**见知识档案《分布式事务 · 跨服务 TM 方案》。本期**不实现**；将来引入时按「能力基类 + 插件注册表 + 配置选择 + 提供者」替换（替换点见该档案 §插件化替换）。

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 | 表现 |
| --- | --- | --- |
| 屏障未开启（provider 空 → null） | 即返回，不拦业务 | 无影响（缺省口径） |
| 等待超时（变更未收敛） | 抛 `ConsistencyBarrierTimeout`（10011 / 409） | 明确可重试错误，不静默放行旧值 |
| Redis 不可用（read/write 异常） | 记 warning；`await_applied` 放行（degrade-open）、`mark_applied` 忽略 | **不阻断主路径**（与幂等域同口径：存储故障不升级为业务故障） |
| 版本乱序（旧标记晚到） | `mark_applied` 只前推 | 版本单调，不影响收敛判定 |
| `target_version` 已达成 | 立即返回 | 零等待 |
| 同一 scope 并发等待 | 各自轮询 | 无共享锁，无阻塞扩散 |

> **放行口径说明**：屏障是**增强**而非强约束——存储不可用时选择放行（而非拒绝），避免「屏障自身成为单点」。真正要求强一致的核心链路，应在**业务侧**同时保留版本校验兜底（如权限读时校验版本）。

## 6. 实施要点 <a id="impl"></a>

- **能力域落点**：`bms_core/consistency/`（`base.py` / `null.py` / `redis.py`），严格走「端口 → 提供者 → 插件注册表 → 配置选择」范式（与 `idempotency/` 同构）。
- **Redis 键**：`bms:{tenant|global}:consistency:{scope}`，复用 `[redis].url`、`redis.asyncio` 惰性建连。
- **配置唯一来源**：超时 / 轮询间隔经 `Settings`（`[consistency_barrier]`）读取，不硬编码。
- **不动既有语义**：`null` 为缺省，不改变任何现有行为；屏障按需在受保护调用前显式使用。

## 9. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 是否引入应用级跨服务 2PC | **不引入**；单库原子（本地事务）+ 跨服务最终一致为基线 |
| 2 | 强一致（2PC / XA / TM）定位 | **技术储备**；沉淀为知识档案，将来经插件化替换落地 |
| 3 | 跨服务「等待收敛」 | 新增**一致性屏障**能力域（`consistency_barrier`，缺省 null、可切 Redis） |
| 4 | 屏障失败口径 | 未收敛超时报 `10011 / 409`（可重试）；存储不可用放行（degrade-open） |
| 5 | 权限保存原子性 | 权限主数据收敛权限服务单库，本地事务；跨服务部分走事件最终一致 |
| 6 | 2PC 调用面 | 不对外暴露；达梦 `dmxa` 方言保留（05_05 已交付），三库 2PC 仅取证 |
