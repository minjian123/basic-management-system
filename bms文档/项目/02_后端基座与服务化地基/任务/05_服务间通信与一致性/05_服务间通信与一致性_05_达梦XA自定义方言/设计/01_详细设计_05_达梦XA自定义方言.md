## 1. 设计目标与范围 <a id="goal"></a>

为达梦 DM8 补齐**两阶段事务（XA）**驱动能力：达梦服务器已支持 XA（`DBMS_XA` 包，见《数据库设计 · 方言特性》达梦「事务与连接」2026-10-06 实测），但 `dmSQLAlchemy` 同步方言未接 `DBMS_XA`、`dmPython` DBAPI 未暴露 TPC，致 SQLAlchemy `begin_twophase()` 抛 `NotImplementedError`。本设计以**纯 Python 自定义方言**（继承 `dmSQLAlchemy` 同步方言，把 `do_*_twophase` 接到 `DBMS_XA`）补齐，**不改编译驱动**；并**将全部达梦连接统一切到新方言 `dmxa`**。

1. **方言实现**：`DMXADialect`（继承 `dmSQLAlchemy.dmpython.DMDialect_dmPython`），实现 `do_begin / do_prepare / do_commit / do_rollback / do_recover_twophase`，底层经 `DBMS_XA`（`XA_START / XA_END / XA_PREPARE / XA_COMMIT / XA_ROLLBACK / XA_RECOVER`）。
2. **方言注册**：经 SQLAlchemy 方言注册表登记为 `dmxa`（`dmxa+dmPython`）；`bms_core` 导入即生效（进程级）。
3. **接入**：达梦连接串方言切为 `dmxa`（配置唯一来源）；引擎工厂把 `dmxa` 纳入**同步方言**（达梦走同步门面 `SyncSession`）；迁移 / `ops` 复用同一工厂。
4. **不改常规语义**：非 2PC 的 CRUD 与既有 `dm` 路径行为一致（方言仅多两阶段方法）。

**不在本期**：跨服务协调器（TM）与三库统一 2PC 方案（归 `05_06`）；MySQL / PostgreSQL 的 2PC 接入（框架用例覆盖，正式接入随 `05_06`）。

### 1.1 现状与缺口 <a id="gap"></a>

```text

├── engine.py        # EngineFactory：create（异步）/ create_sync（同步，达梦走此）；SYNC_ONLY_DIALECTS 判定
```

缺口：① 无两阶段方言（`begin_twophase` 报错）；② 达梦方言名 `dm` 直连 `dmSQLAlchemy`，无从插入 XA 能力；③ 无 2PC 用例与护栏。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 方言契约 <a id="dialect"></a>

```python
class DMXADialect(DMDialect_dmPython):
    name = "dmxa"
    driver = "dmPython"
    supports_statement_cache = True

    # xid（SQLAlchemy 传入的字符串/对象）→ DBMS_XA_XID 的 gtrid（64 位整数，稳定派生）
    @staticmethod
    def _gtrid(xid) -> int: ...
    def _exec(self, connection, xid, stmt: str) -> None: ...  # 执行 PL/SQL 块并校验返回码

    def do_begin_twophase(self, connection, xid) -> None: ...       # XA_START(x, TMNOFLAGS)
    def do_prepare_twophase(self, connection, xid) -> None: ...      # XA_END(x, TMSUCCESS) → XA_PREPARE(x)
    def do_commit_twophase(self, connection, xid, *, is_prepared=True, recover=False) -> None: ...  # （必要时先 prepare）→ XA_COMMIT(x, FALSE)
    def do_rollback_twophase(self, connection, xid, *, is_prepared=True, recover=False) -> None: ...  # （未 prepare 先 XA_END）→ XA_ROLLBACK(x)
    def do_recover_twophase(self, connection) -> list: ...            # XA_RECOVER（本期返回空；悬挂清理归 05_06）
```

- **xid → XID**：`digest = blake2b(str(xid).encode(), digest_size=16)` → `gtrid = digest[:8].hex()`、`bqual = digest[8:].hex()`；`DBMS_XA_XID(1, HEXTORAW(gtrid), HEXTORAW(bqual))`——**用 `RAW` 形态**承载标识（达梦 `DBMS_XA_XID(<INTEGER>)` 为 **32 位**，大值报「数据溢出」，见 §8 决策 4）。
- **返回码**：`XA_*` 函数返回 `0`（`XA_OK`）为成功，非 0 抛 `RAISE_APPLICATION_ERROR` 携返回码（如 `XAER_*`）。
- **常量**：`TMNOFLAGS=0`、`TMSUCCESS=0x04000000`。

### 3.2 注册与接入 <a id="register"></a>

- `bms_core.db.dialects` 导入时 `registry.register("dmxa", ...)` 与 `registry.register("dmxa.dmPython", ...)`（`dmxa+dmPython://` 按 `dmxa.dmPython` 解析）。
- **连接串方言切名**：达梦 URL 由 `dm+dmPython://` 改为 **`dmxa+dmPython://`**（配置唯一来源：`config.toml` / `config.{env}.toml` / 部署环境变量）；入口对旧 `dm` 方言**兼容归一**到 `dmxa`（避免存量配置即挂）。
- **同步方言集**：`SYNC_ONLY_DIALECTS` 增 `dmxa`（达梦无异步驱动，运行期走同步门面 `SyncSession`；`EngineFactory.create` 对 `dmxa` 抛 `ConfigError`、`create_sync` 可用）。
- 迁移（Alembic）与 `ops` 经同一工厂取引擎 → 同步切到 `dmxa`。

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 | 表现 |
| --- | --- | --- |
| `DBMS_XA` 未创建 | 同上（对象不存在） | 明确错误 + 文档提示创建 |
| 未 `XA_START` 即 `XA_END/PREPARE` | 达梦返回 `XAER_PROTO` | 非 0 → 抛错 |
| `prepare` 后会话断（悬挂分支） | 经 `XA_RECOVER` 可见、`XA_COMMIT/XA_ROLLBACK` 清理 | 清理策略归 `05_06` |
| 异步路径误用 | `EngineFactory.create` 对 `dmxa` 抛 `ConfigError`（走同步门面） | 明确错误 |
| 非 2PC 常规 CRUD | 行为与 `dm` 方言一致（仅多两阶段方法） | 无回归（护栏用例） |
