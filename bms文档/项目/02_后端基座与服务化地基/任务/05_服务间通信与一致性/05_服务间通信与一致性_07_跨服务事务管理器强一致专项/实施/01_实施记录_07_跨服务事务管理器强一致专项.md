## 3. 交付物与实施要点 <a id="deliver"></a>

### 3.1 数据库设计（先表文件后代码） <a id="deliver-db"></a>

```text
bms文档/设计/数据库设计/数据表设计/
├── txn_global.md            # 新建（全局事务主记录）
├── txn_global_branch.md     # 新建（参与方分支；db_key 为不透明库键）
└── txn_global_recovery.md   # 新建（恢复 / 对账台账；处置只驱动协议）
```

- 三表 `datasource = PLATFORM`，落 **`bms_txn`（平台侧独立基础设施库）**；`txn` 服务**只建 `txn:platform` 一条迁移链**（**不建 tenant 链、不为每租户建账本库**）。
- **彻底去租户**：账本**不含租户列、不分库不分区**，删除原「一次全局事务只允许同一租户」限制；分支以 `service` + **不透明 `db_key`** 标识（详设 §4 / §8 第 7 项）。
- 三表已在《[数据库设计 · 总览](../../../../../../设计/数据库设计/01_数据库设计_总览.md)》「已设计数据表登记」登记（状态 `待落库`，与表文件一致）。

### 3.2 基座能力域：`bms_core/transaction/` <a id="deliver-core"></a>

## 4. 问题与处置 <a id="issue"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 原 `do_recover_twophase` 恒空，且 `_xid_raw` 以 `blake2b` **不可逆派生** ⇒ 恢复器即使列举出 `(gtrid, bqual)` 也**驱动不了** `commit` / `rollback`（二次哈希对不上） | 引入**可回放载体** `DMXARecoveredXid` 并在 `_xid_raw` 中识别（详设 §8 第 5 项两要点之一）；用例覆盖「列举 → 驱动」闭环 |
| 2 | 详设 §4 原写「落 `txn` 服务租户库 + 账本按 `tenant` 分区 + 不跨租户」 | 经用户纠正「TM 是分布式事务基础设施、跨的是数据库、与租户/业务无关」⇒ 改为**平台侧独立基础设施库 `bms_txn` + 彻底去租户**（表文件与详设 §4 同步；详设 §13 对齐记录 1 留痕） |
| 3 | 新增能力域须三件套自声明（`key == plugin_key` / `plugin_name = NULL_PLUGIN_NAME` / `contract_version` 一致）且缺省实现须继承 `BaseNullObject` | 端口与缺省实现按既有口径书写；`_EXPECTED_PLUGIN_KEYS` 同步补键；平台插件登记用例通过 |
| 4 | 新增测试替身签名使用裸 `list[...]` | 触发裸集合护栏（`check-bare-collections`）⇒ 改 `ConcurrentStableList[...]`；属性显式标注类型以消 `Never` 推断 |
| 5 | **决定点后分支驱动失败仍落终态**（真库端到端用例暴露）：原 `_drive` 不论分支是否全确认都 `_decide(committed)` ⇒ 失败分支**永不被恢复器重驱动**（终态不在扫描面内），违反「决定点后所有分支最终必须 commit」不变量 | 改「**未全确认即不落终态**」：任一分支驱动失败保持 `committing` / `rolling_back`，由恢复器下轮重驱动；用例 `test_drive_failure_keeps_non_terminal_and_recovery_resumes` 覆盖（§8.3） |
| 6 | **分支 `prepare` 后连接释放把已 PREPARE 分支回滚掉**（真库实测 MySQL / PostgreSQL）：`Connection.detach()` **不清** `_transaction`，随后 `close()` 经方言 `do_rollback_twophase` 回滚分支 ⇒ `XA_RECOVER` 随即为空、**业务写入永不落地**（原注释误以为 `detach()` 已摘净事务） | 改为**先关底层 DBAPI 连接**（`connection.connection.dbapi_connection.close()`）再让 SQLAlchemy 收尾；双库实测「列举 → 驱动提交 → 业务行可见」闭环；达梦同口径复测通过（§8.3） |
| 7 | **执行器未提交会话级 SAVEPOINT ⇒ 分支空**（真库实测达梦）：savepoint 模式下 `SyncSession.close()` **静默回滚**处理器未提交的写入（分支 PREPARE 成功但业务表无行） | 执行器在 `prepare` 前统一 `flush + commit` 会话级 SAVEPOINT（处理器自提交部分不重复写）；用例 `test_participant_commits_session_before_prepare` 覆盖（§8.3） |
| 8 | **悬挂列举项表示因方言而异**（MySQL 为 bytes / PostgreSQL 为 `gid` 字符串 / 达梦为可回放载体）⇒ 原字符串比较使 MySQL 分支被判 `active`（TM 误回滚）；**未 `PREPARED` 分支的回滚**原会因 `XAER_NOTA` 判失败、使事务滞留 `rolling_back` | 核验改**方言感知比较**（达梦走方言匹配器、bytes 按字节比、其余按文本比）；回滚改**幂等**（未 PREPARED / 已回收即直接成功，详设 §3.1 口径） |

- **清理语义（详设 §3.5）**：`txn_global` 终态（`committed` / `rolled_back` / 启发式三态）且 `updated_at` 超期 ⇒ 就地物理删除，**连同该事务全部 `txn_global_branch`**；`txn_global_recovery` 按 `detected_at` 超期就地物理删除；**非终态（在途）一律不清理**。
