## 3. 交付物与实施要点 <a id="deliver"></a>

### 3.1 数据库设计（先表文件后代码） <a id="deliver-db"></a>

```text
bms文档/设计/数据库设计/数据表设计/
├── global_txn.md            # 新建（全局事务主记录）
├── global_txn_branch.md     # 新建（参与方分支；db_key 为不透明库键）
└── global_txn_recovery.md   # 新建（恢复 / 对账台账；处置只驱动协议）
```

- 三表 `datasource = PLATFORM`，落 **`bms_txn`（平台侧独立基础设施库）**；`txn` 服务**只建 `txn:platform` 一条迁移链**（**不建 tenant 链、不为每租户建账本库**）。
- **彻底去租户**：账本**不含租户列、不分库不分区**，删除原「一次全局事务只允许同一租户」限制；分支以 `service` + **不透明 `db_key`** 标识（详设 §4 / §8 第 7 项）。
- 三表已在《[数据库设计 · 总览](../../../../../../设计/数据库设计/01_数据库设计_总览.md)》「已设计数据表登记」登记（状态 `待落库`，与表文件一致）。

### 3.2 基座能力域：`bms_core/transaction/` <a id="deliver-core"></a>

| 落点 | 内容 |
| --- | --- |
| `transaction/base.py` | 状态词表（`TXN_*` / `BRANCH_*` 与终态集合）；值对象 `BranchSpec` / `BranchRef` / `GlobalTransaction`（`is_terminal`）；端口 `BaseTransactionManager`（`begin` / `commit` / `rollback` / `status` + `enabled`）与 `BaseTransactionParticipant`（`execute_branch` / `commit_branch` / `rollback_branch` / `branch_state` / `recover_branches`）；分支业务处理器注册表 `BranchHandlerRegistry`（**统一注册通道**：`op` → 本服务已有服务层方法，重复登记即拒）；依赖提供者 `get_transaction_manager` / `get_transaction_participant` |
| `transaction/null.py` | 缺省实现：`NullTransactionManager`（`enabled=False` ⇒ 调用方回退既有基线路径）与 `NullTransactionParticipant`（协议动作抛 `TransactionUnavailableError` `10013` / 503，**明确拒绝、不静默降级**；悬挂列举恒空） |
| `core/error_codes.py` | 新增 `TRANSACTION_UNAVAILABLE = 10013`（不复用 `10011` 一致性屏障 / `10012` Redis） |
| `core/exceptions.py` | 新增 `TransactionUnavailableError`（`10013` / 503） |
| `core/config.py` | 新增 `TransactionManagerSettings`（`[transaction_manager]`：`branch_timeout_seconds` / `prepare_timeout_seconds` / `deadline_seconds` / `recovery_interval_seconds` / `leader_lock_ttl_seconds` / `leader_lock_key`；缺省 `provider` 空 ⇒ 不启用） |
| `core/assembly.py` | `_NULL_MODULES` 增 `bms_core.transaction.null`；`PLUGIN_WIRINGS` 增两条（`transaction_manager` / `transaction_participant`，**共用 `transaction_manager` 分区**） |
| `api/deps.py` | 复用既有依赖通道（提供者按需在消费方取用） |

### 3.3 达梦悬挂分支回收（详设 §8 第 5 项两要点） <a id="deliver-dm"></a>

| 落点 | 内容 |
| --- | --- |

## 4. 问题与处置 <a id="issue"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 原 `do_recover_twophase` 恒空，且 `_xid_raw` 以 `blake2b` **不可逆派生** ⇒ 恢复器即使列举出 `(gtrid, bqual)` 也**驱动不了** `commit` / `rollback`（二次哈希对不上） | 引入**可回放载体** `DMXARecoveredXid` 并在 `_xid_raw` 中识别（详设 §8 第 5 项两要点之一）；用例覆盖「列举 → 驱动」闭环 |
| 2 | 详设 §4 原写「落 `txn` 服务租户库 + 账本按 `tenant` 分区 + 不跨租户」 | 经用户纠正「TM 是分布式事务基础设施、跨的是数据库、与租户/业务无关」⇒ 改为**平台侧独立基础设施库 `bms_txn` + 彻底去租户**（表文件与详设 §4 同步；详设 §13 对齐记录 1 留痕） |
| 3 | 新增能力域须三件套自声明（`key == plugin_key` / `plugin_name = NULL_PLUGIN_NAME` / `contract_version` 一致）且缺省实现须继承 `BaseNullObject` | 端口与缺省实现按既有口径书写；`_EXPECTED_PLUGIN_KEYS` 同步补键；平台插件登记用例通过 |
| 4 | 新增测试替身签名使用裸 `list[...]` | 触发裸集合护栏（`check-bare-collections`）⇒ 改 `ConcurrentStableList[...]`；属性显式标注类型以消 `Never` 推断 |
