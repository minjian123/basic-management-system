## 1. 域说明 <a id="intro"></a>

本域对应阶段二「多服务 CI-CD 与契约门禁」：把 CI/CD 升级为**父-子流水线**（按服务构建与独立发布）、不可变镜像 + 一键回滚 + 健康门禁、契约门禁（oasdiff 破坏性变更拦截 + Schemathesis 冒烟）。

**依据**：《微服务演进规划》「服务化地基要求与门禁」（S7）；《架构设计 · 测试与质量》「CI 流水线」节；《架构设计 · 部署与运维》「版本与发布管理」节；知识档案《[微服务 · 12 选型对比（BMS）](../../../资料/知识档案/微服务/12_微服务_选型对比.md)》。**目标**：服务可独立构建与发布；发布可回滚；契约变更受门禁保护。

## 2. 需求 09-1：父-子流水线 <a id="r09-1"></a>

优先级：2（高）

**背景与动机**：monorepo 多服务若单流水线全量构建会慢且噪音大；需按变更路径调度、按服务构建与独立发布。

**内容**（《架构设计 · 测试与质量》「CI 流水线」节）：

1. 父流水线：按变更路径（`rules:changes`）判断受影响服务，`trigger` 拉起对应服务子流水线；新分支 / 无 diff 基准时用合并请求流水线 + `compare_to` 兜底。
2. 子流水线：只构建 / 测试 / 发布该服务；镜像与版本按服务独立。
3. 公共模板：构建模板经 include / CI Components 抽取，跨项目 include 固定完整 SHA。
4. 并发保护：`resource_group` 防同服务并发发布打架。

**完成标准**：改动某服务仅触发其子流水线；服务可独立构建与发布；公共模板复用且无重复 YAML；校验通过。

**参考文档**：《架构设计 · 测试与质量》「CI 流水线」节；《部署发布规范》

## 3. 需求 09-2：不可变镜像 + 一键回滚 + 健康门禁 <a id="r09-2"></a>

优先级：2（高）

**背景与动机**：多服务发布需可追踪、可回滚、可摘流；可变标签与手工发布无法保证一致性。

**内容**（《架构设计 · 部署与运维》「版本与发布管理」节）：

1. 不可变镜像：镜像按 `commit short SHA` / 语义化版本打标签，禁止以 `latest` 作生产引用；镜像按版本留存 Registry。
2. 一键回滚：回滚即切换上一版本 tag；迁移向前修复优先（仅兼容性迁移允许 downgrade）。
3. 健康门禁：发布后经 `/readyz` 与冒烟回归判定，失败触发回滚预案。
4. 发布留痕：发布检查单关键项由 CI 采集输出（与部署与运维节点衔接）。

**完成标准**：镜像标签不可变可追溯；回滚可一键完成；健康门禁生效（就绪失败阻断）；发布留痕可查；校验通过。

**参考文档**：《架构设计 · 部署与运维》「版本与发布管理」节；《部署发布规范》「发布与回滚」节

## 4. 需求 09-3：契约门禁 <a id="r09-3"></a>

优先级：2（高）

**背景与动机**：服务独立发布下，破坏性契约变更会静默打断消费方；须以工具把契约兼容变成 CI 门禁。

**内容**（《架构设计 · 测试与质量》「测试金字塔」「CI 流水线」节）：

1. 契约快照：每服务导出 OpenAPI 契约快照并维护**独立基线**（入仓库或随发布留存）。
2. 破坏性变更门禁：oasdiff `breaking` 比对基线与当前，破坏性变更即失败并输出变更清单；「只加不删」。
3. 接口正确性冒烟：Schemathesis 基于 OpenAPI 生成用例打真实服务（零 Broker）。
4. 门禁位置：挂 MR / main 流水线；基线更新须走评审合入（不得自动覆盖）。

**完成标准**：破坏性契约变更被 CI 拦截并给出清单；Schemathesis 冒烟可运行；基线更新受评审约束；校验通过。

**参考文档**：《架构设计 · 测试与质量》「CI 流水线」节；《架构设计 · 接口与集成》「服务间通信与契约」节
