## 1. 域说明 <a id="intro"></a>

本域对应阶段二「组织服务退役」：**组织主数据（部门 / 岗位 / 用户-岗位）统一归 mdm 产品**，bms 侧原 `org` 服务（`backend/services/org`）退役——其现存职责仅为组织主数据占位路由（`/org/users` `/org/posts` `/org/dept-tree` `/org/resolve-names`），与 mdm 组织域重复。退役**一步到位**：删除服务工程，清理服务目录 / 网关 / 契约快照 / 前端 api-types / 迁移链 / 部署脚本 / CI 与校验脚本中的 org 登记；组织只读出口（组织数据源 / 名称回显）两契约自 `bms_core/org` 迁 **mdm 组织域**实现，bms 前端组织选择字段切 mdm 出口。

**依据**：mdm《mdm 主数据管理规划》（`mdm/mdm文档/规划/mdm主数据管理规划.md`）「组织服务归位」「标识符登记」节、mdm《知识档案 · 主数据管理 · 项目评估与选型》（`mdm/mdm文档/资料/知识档案/主数据管理/14_主数据管理_项目评估与选型.md`）「组织服务（bms org 服务）归位」节；《[架构设计 · 总体架构](../../../设计/架构设计/03_架构设计_总体架构.md)》「进程模型」节；《[微服务演进规划](../../../规划/微服务演进规划.md)》「目标架构与服务清单」节；《[后端开发规范](../../../规范/后端开发规范.md)》「目录与分层职责」「组织主数据」节；《[需求文档规范](../../../规范/需求文档规范.md)》。

**依赖与顺序**：**mdm 先实现、bms 后退役**——bms 退役任务 11_01 / 11_02 依赖 mdm 组织主数据只读出口就绪（见 mdm 需求 `01-3`）。

## 2. 需求 11-1：组织服务工程退役与登记清理 <a id="r11-1"></a>

优先级：2（高）

**背景与动机**：bms `org` 服务在用户 / 账号、角色两批迁出后仅剩组织主数据占位路由，与 mdm 组织域重复；保留会形成「两处组织主数据源」、服务清单多一个空壳服务，且网关 / 契约 / CI / 迁移链各留一份耦合。

**内容**（mdm《mdm 主数据管理规划》「组织服务归位」节、《架构设计 · 总体架构》「进程模型」节）：

1. 删除服务工程 `backend/services/org/`（源码 / 测试 / `pyproject.toml`）。
2. 服务目录：移除 `bms_core/services/module_registry.py` 的 `SERVICE_CATALOG` 中 `org` 条目；平台服务清单由 9 → **8 个平台服务工程**。
3. 网关与部署：移除 `deploy/gateway/apisix.yaml` 的 upstream `org` 与 `route-org` 路由；移除 `Dockerfile` / `deploy/ci/Dockerfile.backend` 的 `COPY services/org/pyproject.toml`；移除 `ops/dev_run.py` 的 org loopback 别名与 `KNOWN_SERVICES` 中的 org。
4. 契约与类型：移除契约快照 `deploy/contracts/org.json` 与 `deploy/contracts/baseline/org.json`；移除前端 api-types 中 org 契约类型。
5. 迁移链与表归属：移除 `alembic/versions/org/`（`org:tenant` 0001~0006，剩余每服务自有基建表 `sys_outbox` / `sys_event_*`）与 `org:platform`；`table_registry` 无 org 专属表需转（`sys_user` / `sys_account_lock` 已迁 platform）。
6. 校验与测试：清理 `scripts/tools/base-check/check-service-boundaries.py`、`scripts/tools/preflight/check-preflight.py`、`bms_core` 测试（`test_tenant_routing` / `test_keys` / `test_boundary_metrics` / `test_migrate_user_tables` / `test_provision_tenant`）与 `ops/migrate_user_tables.py` 中对 org 服务 / `bms_org` 的引用。

**完成标准**：`services/org/` 工程、`SERVICE_CATALOG` org 条目、网关 / 契约快照 / api-types / Dockerfile / `dev_run` / `alembic` org 链与相关测试引用全部移除；启动与 CI 服务目录唯一性校验通过（8 服务）；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[架构设计 · 总体架构](../../../设计/架构设计/03_架构设计_总体架构.md)》「进程模型」节；《[后端开发规范](../../../规范/后端开发规范.md)》「目录与分层职责」节；mdm《mdm 主数据管理规划》「组织服务归位」节

## 3. 需求 11-2：组织只读出口契约迁出与前端切换 <a id="r11-2"></a>

优先级：2（高）

**背景与动机**：组织只读出口契约（组织数据源 / 名称回显）现位于 `bms_core/org`（含 `NullOrg*` 兜底），随组织主数据迁 mdm 应一并迁 **mdm 组织域**；bms 前端组织选择字段经 HTTP 出口 `/api/org/v1` 消费，退役后须切 mdm 出口。

**内容**（《架构设计 · 权限计算引擎》「组织主数据读出口」节、《后端开发规范》「组织主数据」节）：

1. 契约迁出：`bms_core/org/`（`base.py` / `null.py` 及数据契约 `OrgUser` / `OrgPost` / `OrgDept` / `OrgNameRef` 与常量）迁 mdm 组织域，由 mdm 提供真实实现（mdm 需求 `01-3`）。
2. 基座清理：移除 `bms_core/core/assembly.py` 的 `org_data_source` / `org_name_resolver` 装配与 `bms_core.org.null` 模块登记；移除 `bms_core/api/deps.py` 对应导出（`get_org_data_source` / `get_org_name_resolver`）。
3. 前端切换：前端组织选择字段族（`OrgSelectField` / `PostSelectField` / `DeptTreeSelectField` / `OrgCompositePicker`）与 `OrgCheck` 出口地址切 mdm 组织域公开契约；`OrgSourceAdapter` http 默认实现指向 mdm 出口（查询与批量回显分列、部门树一次性返回）。
4. 兼容期：mdm 出口就绪前不得删除 bms 出口（依赖 mdm 需求 `01-3` 交付）。

**完成标准**：`bms_core/org` 契约与装配 / 导出移除；前端组织选择字段经 mdm 出口取数联通；无残留 org 出口引用；`pytest` / `ruff` / `pyright` 与前端检查全绿。

**参考文档**：《[架构设计 · 权限计算引擎](../../../设计/架构设计/15_架构设计_子系统_权限计算引擎.md)》「组织主数据读出口」节；《[前端基类清单](../../../前端基类清单.md)》「组织选择字段」；mdm《概要设计 · 部门管理》《概要设计 · 岗位管理》

## 4. 需求 11-3：门禁回归与阶段收口 <a id="r11-3"></a>

优先级：3（中）

**背景与动机**：退役是一次跨服务目录 / 网关 / 契约 / 迁移链 / 前端的联合变更，落地后须以门禁与文档回写确认「零漂移 + 口径一致」，避免残留旧服务的当前状态表述。

**内容**：

1. 门禁回归：服务目录 / 网关配置 / 契约快照 / api-types 零漂移；`check-preflight --fast` 全绿；契约冒烟与事件契约校验通过。
2. 文档回写：核对并补齐架构设计 03 / 04 / 09 / 15 / 33、后端开发规范、后端基类清单、数据库设计总览与相关表文件、阶段二计划与需求总览（2026-10-07 已部分回写）口径一致。
3. 阶段结论：阶段二计划回写状态与完成日期（进度以计划表为唯一落点，嵌套子任务并入父任务行）；必要时更新阶段测试报告与阶段验收结论（阶段门禁结论不变）。

**完成标准**：全部门禁零漂移且预检全绿；文档与实现口径一致（无「org 服务」当前状态残留）；阶段二计划两表回写完成。
