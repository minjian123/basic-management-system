## 1. 域说明 <a id="intro"></a>

本域对应阶段二「后端基座真实实现」：把阶段一交付的**接口占位**填为真实实现——数据访问底座（引擎 / 会话 / 四库方言 / 读写分离 / 连接池）、多租户数据拓扑、`BaseRepository` 异步化与 DB 实现、`BaseModel` 落库、Alembic 在线迁移与排序契约 DB 侧、三库真库集成与达梦方言实测。

**依据**：《总体项目规划》「阶段内容与完成标准」节（阶段二行）；《架构设计 · 后端基础类体系》「阶段交付与跨阶段基座契约」节；《架构设计 · 数据访问与分片》《架构设计 · 多租户路由》《架构设计 · 数据架构》；《后端基类清单》「跨阶段基座」节；《后端开发规范》「后端基座体系（强制）」节。**目标**：三库拓扑可路由（MySQL / PostgreSQL / 达梦 DM8）、租户隔离与批量迁移正确、模块注册接库校验生效、`BaseModel` 落库与排序 DB 侧生效、基类异步切换完成、三库真库集成与达梦方言实测通过。

## 2. 需求 01-1：数据访问底座落库 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：阶段一数据访问底座仅接口占位（不连真库、不跑迁移），无法支撑任何真实 CRUD；`DbUnitOfWork` 事务、多异步 bind、读写分离路由、连接池均为占位，业务模块无法按统一口径落库。

**内容**（《架构设计 · 数据访问与分片》「多数据源管理」「读写分离」「事务边界规则」节）：

1. 引擎与会话工厂真实实现：多异步 bind（SQLAlchemy 2.0 多引擎）、`AsyncSession` 工厂按请求上下文读写标记选引擎；引擎 / 会话生命周期管理到位。
2. 四库方言与驱动：MySQL（aiomysql）、PostgreSQL（psycopg 3）、达梦 DM8（dmPython）、SQLite（aiosqlite，开发/测试）可连通；ORM 层禁用方言特有功能（JSON 等用跨方言通用类型，分页统一 limit/offset）。
3. 读写分离：写与事务强制走主库；写后同一会话内读主库；主库故障只读模式降级（从库响应查询、写接口明确报错）。
4. 事务边界：`DbUnitOfWork` 上下文管理器（services 层显式事务），大事务拆小、短事务；异步会话禁止跨请求共享。
5. 连接池：pool_size / max_overflow 可按服务与 worker 配置；超时与失败快速失败并告警。

**完成标准**：四库（含开发 SQLite）可连通且引擎按请求上下文正确选主从；`DbUnitOfWork` 事务提交 / 回滚用例通过；读写分离路由用例通过；连接池参数生效；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 数据访问与分片》「多数据源管理」「读写分离」「事务边界规则」节；《后端基类清单》「数据访问与多租户基座」节

## 3. 需求 01-2：多租户数据拓扑落库与实测 <a id="r01-2"></a>

优先级：2（高）

**背景与动机**：多租户是平台既定形态，但阶段一只落接口占位（拓扑声明未接库、未实测）。租户解析、引擎注册表 LRU 与连接预算、租户隔离是全部业务的前置底座。

**内容**（《架构设计 · 多租户路由》「租户解析链」「引擎注册表与生命周期」「隔离边界」节）：

1. 租户解析全局中间件：按 子域名 / `X-Tenant-ID` / token `tenant_id` 三级解析链构造租户上下文；豁免路径配置；禁止全局单例持有租户引擎。
2. 平台库表落库：`sys_tenant`（租户注册、db_key）与平台侧表建库落库。
3. 引擎注册表：平台服务库引擎常驻、租户库引擎懒加载；LRU + 闲置回收、停用租户强制回收；活跃引擎数上限。
4. 连接预算：按活跃租户数规划，避免全量租户连接常驻（与需求 01-1 连接池衔接）。
5. 租户隔离实测：跨租户访问拒绝用例通过；查询强制 tenant 过滤（repository 统一注入）。

**完成标准**：三级解析链用例通过（含豁免路径）；引擎懒加载与 LRU 回收用例通过；跨租户访问拒绝用例通过；连接预算参数生效；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 多租户路由》「租户解析链」「引擎注册表与生命周期」「隔离边界」节

## 4. 需求 01-3：BaseRepository 异步化与 DB 实现 + BaseModel 落库 <a id="r01-3"></a>

优先级：2（高）

**背景与动机**：`BaseRepository` / `BaseModel` 阶段一为占位；业务仓储与模型无法真实落库（雪花 ID、软删除、审计字段、乐观锁、四库类型映射缺一不可）。

**内容**（《架构设计 · 后端基础类体系》「各层基类与模块约定」「阶段交付与跨阶段基座契约」节）：

1. `BaseRepository` 异步化：由占位切为异步 DB 实现（async session），CRUD / 分页 / 存在性检查等基座方法落库。
2. `BaseModel` 落库：雪花 ID（yitter/IdGenerator，时钟回拨处理）、软删除（`deleted_at`）、审计字段（created_at/created_by/updated_at/updated_by，ORM 事件自动填充）、乐观锁（version）真实生效。
3. 四库类型映射：跨方言通用类型映射（含达梦）；软删除复合唯一索引（`(唯一字段, deleted_at)`）四库口径验证；布尔 / 多值字段存储口径与规范一致。
4. 模块注册表落库：`sys_module` 表与平台域种子落库（与需求 03 服务目录衔接）。

**完成标准**：`BaseRepository` 异步 CRUD 与分页用例通过；`BaseModel` 雪花 ID / 软删除 / 审计 / 乐观锁用例通过；四库类型映射与复合唯一索引验证通过；`sys_module` 落库且种子正确；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 后端基础类体系》「各层基类与模块约定」节；《后端基类清单》「模块基类」「ORM 模型基类」节；《架构设计 · 数据架构》「数据规范」节

## 5. 需求 01-4：Alembic 在线迁移与租户库初始化 + 排序契约 DB 侧 <a id="r01-4"></a>

优先级：2（高）

**背景与动机**：阶段一 `alembic/env.py` 在线分支为 `NotImplementedError`、`versions/` 为空；迁移与租户库初始化未真实执行。排序契约 DB 侧（ORDER BY 白名单拼接、四库 NULLS、分页限深）亦为占位。

**内容**（《架构设计 · 数据架构》「迁移策略」节、《架构设计 · 数据访问与分片》「查询规范」节）：

1. `alembic/env.py` 在线分支实现：连接地址来自配置，按数据源分别维护迁移脚本；MySQL / PostgreSQL / 达梦 DM8 三套方言迁移。
2. `ops` 批量迁移：`create` / `migrate` / `drop` 真实实现，遍历租户库**幂等**执行；新租户开通自动执行（与需求 06-1 衔接）。
3. SQLite 开发库自动建表（不依赖迁移脚本）。
4. 排序契约 DB 侧：`_apply_sort` 白名单拼接与防注入、四库 NULLS 口径对齐、排序字段索引配合、分页限深（100 页）与游标键。
5. 迁移演练：三库按方言执行建库 → 迁移 → 校验 → 清理。

**完成标准**：Alembic 三库在线迁移执行通过；`ops` 批量迁移幂等（重复执行结果一致）；排序 DB 侧用例通过（白名单 / NULLS / 限深）；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 数据架构》「迁移策略」节；《架构设计 · 数据访问与分片》「查询规范」节；《部署发布规范》「发布流程」节

## 6. 需求 01-5：三库真库集成与达梦方言实测 + CI 三库 job <a id="r01-5"></a>

优先级：2（高）

**背景与动机**：三库兼容是平台承诺（信创含达梦），但阶段一无真库集成与方言实测；CI 三库 job（`verify/db` 档）未激活。达梦方言差异（复合唯一 NULL 语义、迁移 DDL、schema 前缀与大小写、类型映射）需实测确认。

**内容**（《架构设计 · 测试与质量》「测试金字塔」节、《部署发布规范》）：

1. 真库集成用例：连接 MySQL / PostgreSQL / 达梦 DM8 常驻库，覆盖多数据源、读写分离路由、真实分片规则、迁移与租户隔离。
2. 达梦方言实测：软删除复合唯一索引 NULL 语义、迁移 DDL、schema 前缀与大小写、类型映射逐项验证并记录结论。
3. CI 三库 job：`verify/db` 档激活（建 `bms_test` 前缀独立测试库 → 迁移 → 测试 → 清理）；按方言命名或加方言标记，保证 `pytest -k "$DB_DIALECT"` 有匹配用例。
4. 敏感变量配齐：三库测试密码等凭据走 CI 变量（不落库不入库）。

**完成标准**：三库真库集成用例全绿；达梦方言实测结论登记（差异与处置）；CI `verify/db` 档可运行且通过；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 测试与质量》「测试金字塔」「CI 流水线」节；《架构设计 · 数据架构》「迁移策略」节
