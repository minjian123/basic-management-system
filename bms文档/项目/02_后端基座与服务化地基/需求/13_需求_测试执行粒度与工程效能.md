## 1. 域说明 <a id="intro"></a>

本域对应阶段二「测试执行粒度与工程效能」：把《[测试规范](../../../规范/测试规范.md)》§2.1 第 2 条「按变更范围只跑受影响的部分」从**服务级**下沉到**模块级 / 包级**，并补齐并行执行，消除「为跑一个点而跑全量」的重复消耗。

**依据**：《[测试规范](../../../规范/测试规范.md)》§2.1「被测物与执行范围」（强制）、§5「用例管理」执行方式条；《[AI开发规范](../../../规范/AI开发规范.md)》「覆盖率要求」节；实测底稿见《[测试执行粒度与影响分析评估](../../../资料/知识档案/工程化与质量/测试执行粒度与影响分析评估.md)》。

**目标**：同一份变更在预检与 CI 两侧只执行一次受影响范围；覆盖率门禁口径不降级；本地预检定向档在常见变更下由分钟级降到十秒级。

**背景**：服务级已按变更路径拆分（域九 09_01 父-子流水线），但库级 / 包级仍为工程级——`backend/libs/**` 任一文件改动即跑全部 10 个 `testpaths`，前端任一文件改动即跑四个包全量。叠加覆盖率 100% 硬门禁后，表现为「为跑一个点必须跑全量」。

## 2. 需求 13-1：变更影响分析与细粒度选测 <a id="r13-1"></a>

优先级：2（高）

**背景与动机**：预检与 CI 的范围推导只到工程级（`backend/libs/bms_core/**` → 整个 `libs/bms_core/tests`；`backend/services/<服务>/**` → 整个 `services/<服务>/tests`），而实际目录同构性良好（`bms_core` 源码 66 域 / 测试 53 目录、49 个同名可一对一映射）。映射信息已具备，未被使用，导致大量与变更无关的用例被重复执行。

**内容**（《测试规范》§2.1 第 2 条）：

1. **选测器作为单一来源**：新增共享的「变更 → 受影响测试」推导模块，预检与 CI 共用同一份实现，禁止两侧各自维护推导规则（避免口径分叉）。
2. **双重收敛**：先按**目录同构**取候选（源目录 ↔ 测试目录），再用 **AST 导入图**收敛到真实引用者（含跨目录引用与反向依赖闭包）；实测全图构建 0.36s，可常驻并缓存。
3. **基础模块识别**：反向依赖闭包超过阈值的模块（实测 471 个源模块中 49 个，占 10%）识别为「基础模块」，命中时直接退化为工程级全量并**显式打印原因**，不做无谓的假精细。
4. **覆盖率扩圈**：选测后读覆盖率报告，若变更模块未达 100%，把「未覆盖行」反查所属模块并并入选测集重跑，收敛通常 1~2 轮；不收敛则退化全量并显式说明。**门禁口径不降级**。
5. **前端同构**：按变更包推导受影响包（`pnpm --filter`），替代「任一个前端文件改动即四包全量」。

**完成标准**：同一变更在预检与 CI 两侧推导结果一致；常见变更（非基础模块）测试量显著低于工程全量且无漏测；覆盖率门禁仍为行 + 分支 100%；退化路径有显式输出与用例覆盖；推导器有自测用例。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》§2.1；《[测试执行粒度与影响分析评估](../../../资料/知识档案/工程化与质量/测试执行粒度与影响分析评估.md)》§3 / §4

## 3. 需求 13-2：并行执行与重复步骤消除 <a id="r13-2"></a>

优先级：2（高）

**背景与动机**：`pytest-xdist` 已在 `backend/pyproject.toml` 声明但预检与 CI 均未使用；实测同一批 2327 个用例串行 282.7s、`-n 4` 为 73.4s（3.85x）。同时预检 30 个步骤里有 19 个是 `--self-test`（护栏自检，与变更无关），11 个是全库扫描，构成与变更无关的固定开销。

**内容**：

1. **并行执行**：定向档与全量档均启用 `-n auto`（可配、可关）；须验证用例在并行下的稳定性（数据隔离、共享夹具、SQLite 文件库冲突）。
2. **自测步骤按需**：`--self-test` 仅在变更触及对应脚本（或其依赖）时执行，`--fast` 与 `--full` 档保留全跑口径。
3. **重复面清理**：`backend-test`（全量）与 `service-test`（服务级）在 `backend/libs/**` 变更时同时拉起的重复面，按「共享底座变更按其影响的集合放行」重新划界。
4. **预算护栏对齐**：预检单步 / 总体耗时上限随实测重新标定（现行上限低于真实耗时会导致必然超时中止）。

**完成标准**：并行档下全部用例通过且结果与串行一致；预检定向档在常见变更下显著缩短；`--fast` / `--full` 档口径不变；预算护栏不再因真实耗时被触发。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》§5「执行方式」；《[测试执行粒度与影响分析评估](../../../资料/知识档案/工程化与质量/测试执行粒度与影响分析评估.md)》§2.2 / §2.3

## 4. 需求 13-3：口径固化与机器护栏 <a id="r13-3"></a>

优先级：3（中）

**背景与动机**：范围推导规则目前只存在于脚本代码里，没有规范表述、没有护栏用例；一旦有人为省事把推导改回工程级，或新增工程未纳入映射，问题会静默复发。

**内容**：

1. **规范补节**：《测试规范》§2.1 增补「变更影响分析」执行细则（推导依据、退化条件、扩圈机制、两侧一致性要求）。
2. **护栏用例**：断言预检与 CI 使用同一份推导实现；断言新增工程 / 新目录未纳入映射时失败；断言退化路径有显式输出；断言覆盖率扩圈循环不会静默放弃。
3. **登记与留痕**：选测结果（选中测试文件数 / 全量数 / 是否退化 / 扩圈轮次）在预检输出中可见，便于复盘与度量。

**完成标准**：规范有对应条款；护栏用例覆盖「同一来源」「新增工程必登记」「退化显式」「扩圈不静默」四项；预检输出含选测度量。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》§2.1 / §5；《[文档生成规范](../../../规范/文档生成规范.md)》

## 5. 需求 13-4：测试公共基座（统一事务 / 日志 / 输出 / 报错）（补充需求，2026-10-19） <a id="r13-4"></a>

优先级：2（高）

**背景与动机**：后端测试的公共能力**没有单一来源**——同一段夹具在 10 个 `conftest.py` 里各写一份（`isolate_settings` 10、`platform_db_url` + `platform_db` 9、`reset_request_context` 8、`service_app` + `client` 8、`clear_tenant_cache` 8），事务边界存在三种并存写法（`session_scope` ≈37 处、夹具手工 `commit()` ≈109 处、autouse 清表 41 个文件），错误断言 ≥700 处 `pytest.raises` 与 260 处 `resp.json()["code"]` 无统一 helper，日志断言靠各文件手写 `_records()` 解析 structlog JSON，输出捕获 173 处 capsys 各写各的。结果是：改一处口径要改十个文件、用例之间靠落盘 SQLite + 手工清表隐式隔离、**排查问题时断点无处可落**（每个测试类都要单独改）。产品仓（mdm / biz）接入时还会再复制一套。

**内容**：

1. **形态**：pytest 插件（夹具 / hook / marker）+ **可无限派生的测试基类**（先定三层：`BaseTestCase` → `DbTestCase` / `ApiTestCase` / `ServiceTestCase` → 具体测试类）；公共能力走 fixture，基类只做方法与扩展点（不持有连接 / 会话），并支持「测试类扩展新方法后由同类测试继承」。
2. **统一事务**：新增回滚夹具（外层事务 + savepoint），并在夹具内 patch `session_scope` / `unit_of_work` 工厂使被测代码复用同一外层事务；用例结束整体回滚，不落盘、无跨用例污染。存量按触及文件渐进切换。
3. **统一报错**：`assert_error(target, code=…, status=…)` 自动识别异常实例 / 响应对象 / JSON dict，统一覆盖 `pytest.raises` 与错误码断言两种高频写法。
4. **统一日志**：`log_events(capsys)` 解析 structlog JSON 行 + `assert_logged(event=…, level=…, **字段)`；不再每文件手写解析器。
5. **统一输出**：`stdout_text` / `stderr_text` / `assert_output(contains=…)` 统一 capsys；`run_cli(*args)` 跑 ops / scripts 入口并断言退出码与输出。
6. **夹具收编**：10 个 `conftest.py` 的重复夹具收编到插件（**保持同名同语义**，存量用例不改），各 conftest 只留服务专属覆盖。
7. **落点与门禁**：公共基座落 `backend/libs/bms_core/src/bms_core/testing/`（基座包内，产品仓可直接复用），**纳入基座覆盖率门禁**（基座自身 100%）。

**完成标准**：10 个 conftest 的重复夹具收敛到单一来源且存量用例零改动通过；新增用例可用统一事务（结束自动回滚、不落盘）与统一断言 / 日志 / 输出 helper；基座 `bms_core.testing` 行 + 分支覆盖率 100%；有对应用例与规范登记（《测试规范》补「测试公共基座」节）。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》§3 / §5 / §6；《[后端开发规范](../../../规范/后端开发规范.md)》「架构铁律」（继承链口径）

## 6. 需求 13-5：跨仓工程化工具包（`engkit`）（补充需求，2026-10-22） <a id="r13-5"></a>

优先级：2（高）

**背景与动机**：护栏与开发脚本目前**只在 bms 仓内、且写死 bms 目录结构**——文档链接/锚点校验（`check-links.py`）只 walk `bms文档/`、文档口径护栏（`check-docs-scope.py`）只扫 `bms文档/`、预检与重命令包装（`check-preflight.py` / `run-once.py`）的工程清单与路径全部按 bms 布局硬编码，Kiwi 用例登记则两仓都只有文档模板、没有脚本。后果在 mdm 仓已实测：**跑一次定向验证需手敲四条命令**（`ruff` / `format` / `pyright` / `pytest --cov`），文档链接只能临时写脚本核对，文档口径（进度类字段只允许落阶段计划）无人守、存量文档长期漂移。若各仓各自复制一份，护栏会变成多份实现、口径必然分叉——与「选测器单一来源」的既有决策相悖。故抽为**独立仓库与可安装包**，各仓以 git 源依赖引用同一份实现；后续新建仓库（域十四之外仍会继续增加）零复制接入。

**内容**（《[AI开发规范](../../../规范/AI开发规范.md)》「重命令不重跑」与「文档要求」节、《[测试规范](../../../规范/测试规范.md)》§2.1 / §5、《[计划文档规范](../../../规范/计划文档规范.md)》「排期唯一落点与边界」节 <!-- docs-scope:allow:引用规范节名 -->）：

1. **仓库与包形态**：新仓 `engkit`（文档根 `engkit文档/`），Python 包 `engkit` + 统一命令入口 `engkit <子命令>`；各仓以 **git 源依赖锁 rev** 引用（口径与 `bms-core` 同构：`{ git = "…/engkit.git", rev = "<SHA>" }`），**不建私有 PyPI**。
2. **仓结构探测配置化（强制）**：文档根、源码根、工程清单、选测映射表等一律从**各仓根的一份配置**读取（如 `engkit.toml`）；包内代码**不得出现任何仓名或目录硬编码**（含 `bms文档` / `backend` / `bms_core` 等字面），新仓接入只加配置、不改代码。
3. **四类能力迁入**：① 文档**链接与锚点**校验（`engkit links`）；② 文档**口径护栏**（`engkit docs-scope`：进度类字段只允许出现在阶段计划文档）；③ **预检与重命令包装**（`engkit preflight` / `engkit run-once`：定向档、选测、预算护栏、未包装拦截、缓存回放）；④ **Kiwi TCMS 用例登记**（`engkit kiwi`：批量登记与回读，凭据从各仓 `deploy/.env` 或环境变量取，不硬编码、不入库）。
4. **单一来源约束**：`13-1` 的选测器与 `13-2` 的并行 / 自测按需映射**随本次迁入 `engkit`**；bms 侧只保留**薄包装入口**（命令名与行为不变），**不得出现第二套推导或护栏实现**；`13-3` 的四项护栏断言继续锁「同一来源」，作用对象改为 `engkit` 内的实现。
5. **各仓接入**：bms 侧原有入口（`check-preflight.py` / `run-once.py` / `check-links.py` / `check-docs-scope.py` / CI job 命令）改为调用 `engkit` 且**行为不回退**；mdm 侧接入并把链接校验、文档口径、预检纳入本地与 CI；biz / cw 随各自窗口接入（本次只出接入说明）。
6. **存量整改**：mdm 全仓需求 / 任务 / 记录文档的进度类字段清理（唯一落点改为阶段计划表）；bms 侧不得因迁移放宽既有口径。
7. **工作区模型同步**：`engkit` 仓接入工作区（`AGENTS.md` 仓库清单与引用写法、`搭建工作区` 脚本、`.gitignore` / `.ignore` 与忽略模板、IDE 工作区文件）随建仓一并回写；`engkit` 仓自身文档根为 `engkit文档/`。

**完成标准**：`engkit` 可按 rev 安装，`engkit links` / `docs-scope` / `preflight` / `run-once` / `kiwi` 均可用，且包内无仓名 / 目录硬编码（机器断言）；bms 侧同名入口与 CI 命令行为不回退（`--fast` / 定向档、缓存命中与 `--force`、四个 `preset` 全覆盖）；mdm 接入后链接 0 断链、口径 0 违规、一条命令跑出定向用例与覆盖率门禁；`13-1` 选测器与 `13-3` 护栏在迁移后全绿且**全仓只有一份实现**（护栏断言）；工作区模型文档与搭建脚本已含 `engkit`；Kiwi 登记凭据仅存 `deploy/.env` / 环境变量。

**参考文档**：《[AI开发规范](../../../规范/AI开发规范.md)》「重命令不重跑」/「文档要求」节；《[测试规范](../../../规范/测试规范.md)》§2.1「被测物与执行范围」、§5「用例管理」；《[计划文档规范](../../../规范/计划文档规范.md)》「排期唯一落点与边界」节（`docs-scope:allow` 引用规范节名）；《[KiwiTCMS部署使用说明](../../../资料/开发服务器/linux/KiwiTCMS部署使用说明.md)》「用例约定」/「用例登记（脚本化批量）」节；[13_01 详细设计](../任务/13_测试执行粒度与工程效能/13_测试执行粒度与工程效能_01_变更影响分析与细粒度选测/设计/01_详细设计_01_变更影响分析与细粒度选测.md)

## 7. 需求 13-6：基座校验器迁入与各仓规则对齐（补充需求，2026-10-23） <a id="r13-6"></a>

优先级：2（高）

**背景与动机**：13-5 把四类能力（链接与锚点 / 文档口径 / 预检与重命令包装 / Kiwi 用例登记）与选测器迁入跨仓工程化工具包，但**基座校验器仍只在 bms 仓内、规则写死 bms 结构**——业务码段、错误码段、表前缀、模块边界、系统字段、原型对照、环境模板键位这些校验的**规则数据**散落在各脚本源码里，产品仓（mdm / biz / cw）无法复用同一套基座口径。结果是「平台基座有护栏、产品仓靠人眼」：产品仓新增表 / 新增服务 / 新增原型时，同类口径无人守。各仓若各自复制一份校验器，护栏又多出 N 份实现，与 13-5 定下的「单一来源」相悖。

**内容**（《[AI开发规范](../../../规范/AI开发规范.md)》「可追溯」与「文档要求」节、《[数据库开发规范](../../../规范/数据库开发规范.md)》「与数据库设计的关联与事实源」节）：

1. **规则配置化**：8 个校验器（`check-base` / `check-backend-base` / `check-service-boundaries` / `check-bare-collections` / `check-system-fields` / `check-prototype-review` / `check-env-example` / `boundary_metrics`，含 `check-status`）的**判定逻辑与规则数据分离**——判定留实现、规则落各仓 `engkit.toml`（`[rules.*]` 段），包内**不得出现任何仓名 / 目录 / 包名字面**（机器断言）。
2. **迁入 engkit**：以子命令或预检步骤两种形态提供（与 `preflight` 的 `[[preflight.steps]]` 声明式口径一致），各仓按需启用；bms 侧原脚本改**薄包装**，入口名 / 参数 / 退出码 / CI 命令全部不变（行为零回退）。
3. **各仓规则对齐**：mdm / biz / cw 各自登记本仓的标识符段、表前缀、模块清单、原型目录与模板键位；未登记项按「缺配置即报错」处理，不靠缺省值掩盖。
4. **存量缺口闭环**：`check-base` → 护栏用例映射的存量缺口（13-5 边界与开放项第 2 条）随本次一并补齐，映射表覆盖目录内全部脚本。
5. **门禁不变**：engkit 侧 `pytest` + `ruff` + `pyright` + 覆盖率门禁（口径见《[AI开发规范](../../../规范/AI开发规范.md)》「覆盖率要求」节）保持；预检步骤与预算护栏口径不回退。

**完成标准**：8 个校验器可在 engkit 内以配置驱动运行，包内无仓名字面（机器断言）；bms 侧既有入口与 CI 命令行为零回退（参数 / 输出 / 退出码不变）；mdm 至少接入其中与自身相关的校验并实跑通过；规则数据全部落各仓配置，脚本内不再出现仓专属字面；`check-base` 映射缺口补齐且映射表覆盖目录内全部脚本。
