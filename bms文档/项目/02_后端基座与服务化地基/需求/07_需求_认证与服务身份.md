## 2. 需求 07-1：OIDC IdP 接入 <a id="r07-1"></a>

优先级：2（高）

**背景与动机**：微服务与网关认证需要统一身份源；已有 SSO（OIDC 客户端 / BMS 兼作 IdP）规划，但服务化需自托管 IdP 作为统一签发 / 校验基点。

**内容**（《架构设计 · 认证与会话》「SSO 集成」节、《微服务演进规划》「技术选型」节）：

1. IdP 部署：自托管 OIDC IdP（Keycloak）随 `deploy` 编排一体，本地一键拉起。
2. 集成方式：BMS 作为 OIDC 客户端接入；票据校验经 JWKS；与既有 SSO（OIDC / CAS / 企业微信 / 钉钉）框架衔接。
3. 用户体系对接：外部身份映射（idp_key + external_id）与 JIT 建号口径沿用既有设计；完整登录链路随阶段六。
4. 只作身份源：IdP 不承载业务逻辑；密钥 / 客户端凭据走环境变量 / Secret。

**完成标准**：IdP 随编排就位并可完成 OIDC 客户端接入（JWKS 校验通过）；客户端凭据不落库不入镜像；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 认证与会话》「SSO 集成」节；《架构设计 · 接口与集成》「对外 API」节

## 3. 需求 07-2：双类 JWT <a id="r07-2"></a>

优先级：2（高）

**背景与动机**：服务间调用需独立身份，若与用户 token 混用会导致「用户 token 直调内部服务」的安全漏洞；必须区分两类令牌。

**内容**（《架构设计 · 认证与会话》「服务身份与服务间认证」节）：

1. 用户 JWT：`aud=api`，承载用户与租户上下文（access / refresh 口径归阶段六）。
2. 服务 JWT：`aud=service`，短时 + scope + 服务标识，用于服务间调用。
3. 签名与校验：RS256 / ES256，公钥经 JWKS 分发；必须校验 `exp` / `iss` / **`aud`**。
4. 隔离：内部服务 JWT 与用户 JWT 必须 `aud` 区分；外部 access token 不透传内部。

**完成标准**：双类 JWT 可签发与校验；`aud` 区分生效（用户 token 调内部服务被拒）；密钥轮换可并行验证；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 认证与会话》「服务身份与服务间认证」节；《架构设计 · 性能与安全》「服务间安全」节

## 4. 需求 07-3：网关认证接线与服务身份校验 <a id="r07-3"></a>

优先级：2（高）

**背景与动机**：认证须在边缘统一完成并向下游传递可信身份；服务间流量须校验服务身份，防网关旁路。

**内容**（《架构设计 · API 网关与边缘》「边缘功能」「安全边界」节）：

1. 网关认证接线：网关校验用户 JWT（含 `aud`），注入验证过的身份头透传后端；后端不重复认证。
2. 服务身份校验：服务间调用校验服务 JWT；内部服务只接受带服务身份的流量。
3. 请求净化：剥离客户端伪造身份头（与 [04_需求_API网关与边缘](04_需求_API网关与边缘.md) 衔接）。
4. 演进预留：K8s 阶段引入 Linkerd 自动 mTLS 补传输层身份（不在本阶段）。

**完成标准**：网关认证后请求携带可信身份、后端仅做授权；服务间调用经服务身份校验；网关旁路（伪造身份）被拒；用例覆盖；校验通过。

**参考文档**：《架构设计 · API 网关与边缘》「安全边界」节；《架构设计 · 认证与会话》「服务身份与服务间认证」节
