## 1. 域说明 <a id="intro"></a>

本域对应阶段二「服务目录与契约登记」：把阶段一交付的业务模块注册表（`sys_module`）**升格为服务目录与契约登记**——登记服务清单与注册要素（表前缀 / 业务码 / 错误码段 / 事件域 / 契约版本），服务启动与 CI 校验唯一，并提供只读服务目录接口；服务按「平台地基 → 边缘独立 → 核心主数据 → 产品服务」分组与批次登记，**具体各服务的注册要素取值留实施时的登记清单**（本基线只定机制与分组）。

**依据**：《微服务演进规划》「目标架构与服务清单」节；《架构设计 · 模块注册》「服务目录与契约登记」节；《架构设计 · 服务间通信与分布式一致性》「服务边界与契约」节；《项目规划说明》「平台扩展接入流程」「错误码段规则与注册」节。**目标**：服务清单与注册要素可登记、可校验（冲突即拒）、可只读查询；契约版本可追踪。

## 2. 需求 03-1：服务目录与注册要素登记 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：微服务形态下「模块」即「服务」，需要统一的服务目录回答「系统里有哪些服务、各自注册要素是什么、当前版本与契约版本是什么」；阶段一 `sys_module` 只登记业务模块，未覆盖平台服务与契约版本。

**内容**（《架构设计 · 模块注册》「服务目录与契约登记」节）：

1. `sys_module` 升格：在既有注册表上扩展服务维度与契约版本字段，服务与模块同源登记（模块即服务）。
2. 注册要素：表前缀 / 业务码 / 错误码段 / 事件域，条目定义与唯一性规则沿用既有口径；**具体取值按服务分组与批次在实施登记清单中确定**。
3. 契约版本：登记每服务公开契约（OpenAPI）版本与服务版本，供契约兼容门禁依据。
4. 归属与分组：登记服务归属（平台地基 / 平台能力 / 产品服务）与建设批次，对齐《微服务演进规划》「目标架构与服务清单」节。
5. 种子登记：服务以平台种子数据方式注册（Alembic 数据迁移或种子脚本），随版本发布。

**完成标准**：服务目录表结构就位（含服务维度与契约版本）；服务清单与注册要素可按分组登记并落库；平台域与业务域种子齐备；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 模块注册》「服务目录与契约登记」节；《微服务演进规划》「目标架构与服务清单」节；《项目规划说明》「错误码段规则与注册」节

## 3. 需求 03-2：启动与 CI 唯一性校验 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：注册要素冲突（表前缀 / 错误码段 / 事件域 / 服务标识重名）必须在启动与 CI 阶段被拒绝，否则会在运行期引发难以定位的冲突；阶段一已有离线校验，需扩展到服务维度与契约版本。

**内容**（《架构设计 · 模块注册》「注册时机与唯一性校验」节）：

1. 启动校验：应用启动读取服务目录，校验服务标识 / 表前缀 / 错误码段 / 事件域唯一且格式正确（冲突即启动失败并给出冲突项）。
2. CI 校验：流水线对种子与迁移脚本执行同规则校验（测试库迁移后查重），冲突不允许合并。
3. 契约版本校验：契约版本不符（主版本不兼容）在启动 / CI 阶段被拒并告警。
4. 只读边界：服务目录运行时不提供增删改接口，新增服务走开发期种子。

**完成标准**：重名 / 格式错误 / 契约版本不符启动被拒（退出码非 0、错误可读）；CI 离线校验可拦截非法登记并随冒烟层执行；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 模块注册》「注册时机与唯一性校验」节；《测试规范》「流水线分层与自动触发」节

## 4. 需求 03-3：服务目录只读接口 <a id="r03-3"></a>

优先级：3（中）

**背景与动机**：运维与平台管理需要只读入口核对「系统当前有哪些服务、各自注册要素与契约版本」，且不得暴露密钥；阶段一插件清单接口只覆盖能力 provider，未覆盖服务目录。

**内容**（《架构设计 · 模块注册》「运行时只读边界」节、《架构设计 · 接口与集成》）：

1. `GET /api/v1/modules`（沿用既有口径）返回服务清单：服务标识 / 名称 / 归属 / 分组 / 表前缀 / 错误码段 / 事件域 / 契约版本 / 状态。
2. `GET /api/v1/modules/{service_key}`：单服务明细。
3. 只读接口，不提供注册 / 启停 / 切换操作；返回不含任何密钥 / 敏感 options。
4. 未登记服务返回 404（统一错误码口径）；鉴权按平台管理口径随认证 / RBAC 阶段接入。

**完成标准**：只读接口可查且字段与架构一致；不含密钥 / 敏感项；未登记服务 404 与统一响应体一致；自动化用例覆盖；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 模块注册》「运行时只读边界」节；《架构设计 · 接口与集成》「API 设计规范」节
