## 1. 域说明 <a id="intro"></a>

本域对应阶段二「多服务骨架与仓库」：在 `bms` monorepo 内建立**多服务工程**（一服务一工程 + 共享基座库），把阶段一~五已交付的单体分层代码按服务边界重组，并提供服务运行与健康检查、本地一键拉起。

**依据**：《微服务演进规划》「目标架构与服务清单」「阶段与排期影响」节；《架构设计 · 总体架构》「分层视图」「进程模型」「工程结构（Monorepo）」节；《架构设计 · 基础类体系》；《后端开发规范》「目录约定」节。**目标**：多服务工程可本地一键拉起；服务分层与依赖方向清晰；现有产出保留并重构为分布式。

## 2. 需求 02-1：monorepo 多服务工程与共享基座库 <a id="r02-1"></a>

优先级：2（高）

**背景与动机**：单体分层工程无法承载「一服务一容器一库、独立发布」；需在同一仓库内划分多个服务工程并抽出共享基座库，避免各服务重复实现基座。

**内容**（《架构设计 · 总体架构》「工程结构（Monorepo）」节）：

1. 多服务工程结构：每个服务独立工程目录，按 api / services / repositories / models / schemas 分层；服务可独立构建。
2. 共享基座库：core 横切基座与模块基类抽为共享库，各服务复用；服务化语义基座（服务契约 / 服务间调用 / Outbox）承载于此（见 [05_需求_服务间通信与一致性](05_需求_服务间通信与一致性.md)）。
3. 依赖方向与边界：服务内分层依赖单向；服务之间只经公开契约或事件；禁止跨服务 import 内部实现。
4. 工程登记：服务目录结构、文件清单与命名以《[后端基类清单](../../../后端基类清单.md)》与《[后端开发规范](../../../规范/后端开发规范.md)》为准。

**完成标准**：多服务工程可分别构建；共享基座库被各服务复用且无重复实现；服务内分层依赖单向、无循环；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 总体架构》「工程结构（Monorepo）」节；《后端开发规范》「目录约定」节；《后端基类清单》

## 3. 需求 02-2：服务运行与健康检查 <a id="r02-2"></a>

优先级：2（高）

**背景与动机**：每服务需独立可运行、可探活，才能被网关路由与编排；阶段一仅有单体 `/healthz` `/readyz`，无按服务的运行与配置加载口径。

**内容**（《架构设计 · 可观测性》「健康检查与优雅停机」节、《架构设计 · 部署与运维》）：

1. 每服务独立启动：配置按环境分层加载（`config.toml` + 环境变量）、日志结构化、服务名与版本标识。
2. 健康探针：每服务 `/healthz`（存活）与 `/readyz`（依赖就绪），响应口径与豁免规则与既有基座一致；`minio` 等检查项按依赖接入。
3. 优雅停机：SIGTERM 后停止接收新请求、等待在途完成、`/readyz` 置 503 摘流。
4. 本地一键拉起：一条命令拉起全部服务与依赖（见 [04_需求_API网关与边缘](04_需求_API网关与边缘.md) 网关与 `deploy` 编排）。

**完成标准**：每服务可独立启动并暴露探针；就绪探针聚合依赖且失败返回 503；优雅停机用例通过；本地一键拉起全部服务（多容器）成功；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 可观测性》「健康检查与优雅停机」节；《架构设计 · 部署与运维》「基础设施编排」节

## 4. 需求 02-3：现有单体重构为分布式 <a id="r02-3"></a>

优先级：2（高）

**背景与动机**：已决定「保留阶段一~五产出、重构为分布式，不推倒重来」；需把单体代码按服务边界迁移到多服务工程，避免重复开发与产出作废。

**内容**（《微服务演进规划》「与现状差异及迁移」节）：

1. 产出保留：阶段一~五已交付的分层、基类体系、`sys_module` 注册、事件总线、前端模块化保留。
2. 按服务边界重组：现有代码按服务划分迁入对应工程；共享部分沉淀进基座库。
3. 边界硬校验接线：禁止跨服务 import 内部实现、禁止跨服务库访问（与 [05_需求_服务间通信与一致性](05_需求_服务间通信与一致性.md) 衔接）。
4. 迁移不改业务语义：重构不改变既有接口契约与业务行为。

**完成标准**：单体代码按服务边界完成迁移且无重复实现；既有测试全绿；边界硬校验可拦截越界；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《微服务演进规划》「与现状差异及迁移」节；《架构设计 · 总体架构》「工程结构（Monorepo）」节
