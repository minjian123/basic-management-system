## 1. 域说明 <a id="intro"></a>

本域对应阶段二「产品服务接入」：把平台从**独占服务目录**扩展为**支持产品服务注册与接入**——产品（mdm / biz / cw 等）以**独立服务**形态部署（每服务独立库），经统一认证（OIDC）+ 开放接口（`/api/open`）+ 事件与平台集成；共享基座库支持**产品服务装配**。对应《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》落地路线图 **R4.1 / R4.2** 与 5.3 扩展点第 1 / 4 项。

**依据**：《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「代码复用能力边界」「落地路线图」R4.1 / R4.2 节；《[微服务演进规划](../../../规划/微服务演进规划.md)》「目标架构与服务清单」「服务化地基要求与门禁」（S1~S7）节；《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》「独立接入边界」「服务目录与契约登记」节；《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》「独立服务接入骨架」节；《[项目规划说明](../../../规划/项目规划说明.md)》「平台扩展接入流程」节。

**解锁对象**：本域解除 **mdm 产品实施**的阻塞——mdm 需求 `01-1`（产品工程骨架与平台接入）依赖本域交付。

**范围外**：R4.3 前端多包合并（归前端阶段 / 产品前端接入）、R4.4 契约与兼容机制（随首个产品接入前落地）。

## 2. 需求 12-1：产品注册机制（R4.1） <a id="r12-1"></a>

优先级：2（高）

**背景与动机**：平台服务目录（`sys_module`）现仅登记平台自身服务；产品服务无法登记注册要素（表前缀 / 错误码段 / 事件域 / 前端包来源），产品接入无「先注册后建表」的入口。

**内容**（《平台可扩展性规划》R4.1 节、5.3 第 1 项）：

1. **产品级注册**：`sys_module` 扩展或新增产品级注册表，支持**产品 / 产品服务**登记注册要素（服务 / 模块标识、表前缀、业务码、错误码段、事件域、前端包来源）。
2. **唯一性校验**：产品注册要素与平台、其他产品**全局唯一**（启动与 CI 校验冲突即拒）。
3. **错误码段扩展**：产品按注册段使用（既有附加段自 10xxxx 起顺延）。
4. **注册先行**：产品**先注册后建表**——注册要素即得权限码、事件域与错误码段。

**完成标准**：产品可登记注册要素并经启动 / CI 唯一性校验；冲突被拒；登记可读、可对账。

**参考文档**：《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「代码复用能力边界」「落地路线图」节；《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》「服务目录与契约登记」节；《[命名规范](../../../规范/命名规范.md)》

## 3. 需求 12-2：产品服务接入（R4.2） <a id="r12-2"></a>

优先级：2（高）

**背景与动机**：产品服务要实现「独立部署、经认证 / 开放接口 / 事件与平台互通」，须平台侧提供服务目录与契约 / 版本登记、网关路由、认证与开放接口 / 事件接入的对接机制。

**内容**（《平台可扩展性规划》R4.2 节、5.7 节；《架构设计 · 接口与集成》「独立服务接入骨架」节）：

1. **服务目录与契约 / 版本登记**：产品服务经平台服务目录登记（服务标识 / 契约版本），公开契约纳入契约快照与门禁。
2. **认证接入**：产品服务经平台 OIDC（用户 JWT `aud=api` / 服务 JWT `aud=service`，平台 JWKS）校验；服务间经服务身份。
3. **开放接口**：产品对外/对外系统的数据交互经平台 `/api/open`（OAuth2 Client Credentials）+ `sys_client` 注册要素（最小 scope 集合）。
4. **事件接入**：产品注册事件域，经平台事件总线发布 / 订阅（事件契约登记与校验）。
5. **网关路由**：产品服务经平台网关暴露（**产品命名空间**，如 `/api/mdm/v1/...`），独立库（每服务独立库 × 每租户）。
6. **接入骨架**：`sys_client` 注册要素 / 最小 scope 集合 / 必供项（健康检查 / 审计 / 事件订阅）与平台版本兼容承诺清单。

**完成标准**：产品服务可独立发布，并经认证 / 开放接口 / 事件与平台互通（含接入验收：注册唯一性、契约测试、权限与审计复用、数据隔离）。

**参考文档**：《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「独立服务形态口径」节；《[微服务演进规划](../../../规划/微服务演进规划.md)》「服务化地基要求与门禁」节；《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》

## 4. 需求 12-3：共享基座产品服务装配支持 <a id="r12-3"></a>

优先级：2（高）

**背景与动机**：共享基座库 `bms_core` 的应用装配（`BaseServiceApplicationFactory`）与 `SERVICE_CATALOG` 现面向平台服务；产品服务（跨仓库、独立部署）无法经共享基座装配，mdm 等产品实施被阻。

**内容**（《[后端开发规范](../../../规范/后端开发规范.md)》「服务应用装配必须走共享基座」条）：

1. **服务目录参数化**：`SERVICE_CATALOG` 支持**注入产品服务记录**（产品侧提供本产品服务清单，与平台清单合并校验），或等价扩展点。
2. **服务身份参数化**：应用工厂支持**产品服务身份**（`service_name` / `service_title` / 契约版本 / 产品维度），不硬编码平台服务集。
3. **依赖可分离**：产品服务经共享基座装配时，不因平台专属服务集产生隐式依赖；跨仓库依赖（git 源）可用。
4. **向后兼容**：平台 8 服务装配行为不变（登记与校验口径一致）。

**完成标准**：产品服务可经共享基座 `BaseServiceApplicationFactory` 装配并启动（探针可用）；平台服务行为不变；服务目录注入与唯一性校验生效；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[后端开发规范](../../../规范/后端开发规范.md)》「目录与分层职责」「服务应用装配」节；《[后端基类清单](../../../后端基类清单.md)》；mdm《01_01 产品工程骨架与平台接入详细设计》（`mdm/mdm文档/项目/01_mdm 产品奠基/任务/…`）

## 5. 需求 12-4：产品服务接入基座补充（表归属注入 + 服务包模型前缀 + 产品种子） <a id="r12-4"></a>

优先级：2（高）

**背景与动机**：mdm 承接组织主数据（mdm 需求 `01-2`）落表时暴露三处基座缺口——① **表归属登记** `TABLE_OWNERSHIP` 为平台侧代码常量，产品表无法自持登记，产品迁移链与开发库自动建表取不到表；② **服务包模型解析**按 `bms_{service}.models` 硬编码取模型清单，产品服务包名（`mdm_{service}`）取不到模型；③ 产品管理面权限码（业务码 / 动作码）缺产品侧登记通道，产品接入后无法按码授权。三者均属「基座 / 公共封装 / 扩展点」性质，会被后续每个产品复用（mdm 后续域、biz、cw），故按《[AI开发规范](../../../规范/AI开发规范.md)》§3.1 补充立项。

**内容**（《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「代码复用能力边界」节；《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》「独立接入边界」节）：

1. **表归属产品注入与合并视图**（镜像服务目录 R 架构）：`TABLE_OWNERSHIP` 由「平台侧常量」升为「**注册表 + 产品注入合并**」——新增注册 / 合并入口，平台侧登记行与产品自报注入行按「**同 `table_name` 同值去重、异值即拒**」处理；`chain_tables` / `chain_metadata` / 开发库自动建表 / 归属校验**一律取合并视图**。产品侧经**应用装配钩子**与 **ops / alembic 入口**在装载时注册本产品表记录。
2. **服务包模型名前缀参数化**：链的服务模型包名前缀由配置 `[app].package_prefix` 派生（平台默认 `bms`，产品配自有前缀）；「服务已启用但服务包缺失」**快速失败**（免静默空清单导致迁移与自动建表不建表）。
3. **产品业务码 / 动作码种子**：产品管理面权限码按产品域登记（业务码 + 域级 / 专属动作码），经平台种子写入 `sys_business` / `sys_action`。
4. **规范与清单回写**：《[数据库开发规范](../../../规范/数据库开发规范.md)》「表与字段口径」、《[数据库设计 · 数据规范](../../../设计/数据库设计/02_数据库设计_数据规范.md)》「公共字段」、《[后端开发规范](../../../规范/后端开发规范.md)》「模型模块按服务声明」与《[后端基类清单](../../../后端基类清单.md)》「表归属登记 / 服务应用装配基座」同步回写。

**完成标准**：产品可自持登记表归属并进链（迁移与开发库自动建表生效）；产品服务模型按配置前缀解析、服务包缺失即快速失败；产品业务码 / 动作码种子可用；规范与清单回写完成；`pytest` / `ruff` / `pyright` / 本地预检全绿。

**参考文档**：《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「代码复用能力边界」节；《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》「独立接入边界」节；《[数据库开发规范](../../../规范/数据库开发规范.md)》「迁移与建表口径」节；mdm《01_02 组织主数据域实现详细设计》（`mdm/mdm文档/项目/01_mdm 产品奠基/任务/…`）
