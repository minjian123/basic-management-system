## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | `services/report/tests` 无 `serial_db_write` 夹具（工程根 conftest 在子工程 rootdir 时不参与），共享租户库写入用例直接报 fixture 缺失 | 在 `services/report/tests/conftest.py` 补同名薄壳（复用具名锁 `shared-db-write`，与 platform / file 服务一致，不复制逻辑） |
| 2 | 覆盖防护初版对「有 key 被更晚作业引用」的作业仍写 `expired_at`，与设计 D3「跳过且不标记」不符（用例 `test_cleanup_skips_key_referenced_by_newer_job` 抓到） | 改为「本作业存在被引用 key 时整体不标记」，`skipped` 按被引用 key 数计 |
| 3 | 直接跑 `pyright` 报 78 个 unknown（`Import "sqlalchemy" could not be resolved`） | 该项目 pyright 无 `venvPath` 配置，须显式 `--pythonpath .venv/Scripts/python.exe`；补该参数后仅剩 3 处 `dict` 取值 unknown，加 `cast` 后清零 |
| 4 | 复核 `export_limits.py` 时把 PEP 758 无括号 `except` 误判为语法错误（用 PATH 上的 3.13 解释器验证） | 实为 py314 合法语法；已撤销误改，并把「验证只用仓内 venv」写入工作区 `AGENTS.md` |

## 6. 偏差与遗留 <a id="deviation"></a>

| # | 项 | 说明与归口 |
| --- | --- | --- |
| 1 | 同步打印产物无回收路径 | `POST /prints/exports` 与同步批量不写作业记录，本次不覆盖（详设 §10-1）；产物 key 按「模板 + 单据」去重，堆积上界 = 单据数 × 模板数。如需覆盖，走「产物登记表」或存储契约加 `list`，另立任务 |
| 2 | 被跳过的作业长期留在扫描面 | 覆盖防护跳过时不写 `expired_at`，每轮重扫（作业量小可接受）；收敛需产物索引或对象 mtime（详设 §10-2） |
| 3 | 历史孤儿 | 04_02 之前产生的打印产物无记录可依，本次不处理 |
| 4 | 两条内置任务需存量租户回填 | 新增 `sys_task` 两行由租户开通种子写入，存量租户执行 `python -m ops.seed_platform` 回填（部署动作，非代码遗留） |
