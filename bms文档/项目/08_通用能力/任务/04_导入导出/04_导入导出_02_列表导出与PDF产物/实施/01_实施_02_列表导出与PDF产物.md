## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 导出端点报 `10001 query.deps Field required` | 端点模块用了 `from __future__ import annotations`，注解变字符串；`Annotated[_ExportDeps, Depends(deps_of)]` 里的 `deps_of` 是闭包内局部函数，解析时不在全局命名空间 | 移除该模块的 future 导入（与 `api/imports.py` 一致）；类型问题改在别的层解决 |
| 2 | 超阈值导出报 `A transaction is already begun on this Session` | 阈值判定先 `count` 读库（隐式事务已开），随后 `uow.begin()` 再开事务冲突 | 提交作业前先结束只读事务（`in_transaction()` 为真则 `rollback()`），再 `async with uow.begin()` |
| 3 | 导出清理作业导致 pytest 卡死（xdist worker 被判 node down） | 清理按 `finished_at` 查询，标记 `expired_at` 后同一行仍会被扫到 → 死循环 | 改为按 offset 分批推进 + 跳过已标记行；同时把「读批」与「标记」拆成两个事务，避免事务后读 ORM 属性 |
| 4 | 合并打印产物覆盖逐份产物 | merged 以批内首键命名（`A.pdf`），与 separate 的 `A.pdf` 同键 | merged 改为 `{首键}-merged`（既保留单据来源又不覆盖） |
| 5 | 参数非法（`ids` / `paper`）返回 HTTP 200 | 项目错误响应的 HTTP 状态取**错误码表声明**（`10001` 声明为 200），不取异常自带状态 | 测试按项目口径断言 `code`；仅 `504xx`（400/404/409）按声明断言 HTTP |
| 6 | 平台服务启动报「路由重复登记：import_export」 | 导出路由 `BaseRouter.key` 与导入路由同名 | 导出路由 key 改 `import_export_exports` |
| 7 | 导出用例单跑通过、整批失败 | 共享租户库跨文件累积数据（用户数超 50 触发 PDF 异步分支、首行不再是本用例数据） | 断言改为与列表接口 `total` / 首行对照，或显式 `ids` 限定单行 |
| 8 | 批量打印作业读不到 `keys`（列表为空） | 作业负载里是 `ConcurrentStableList`（非 `list` 子类），`isinstance(raw, list \| tuple)` 判假 | 统一改为 `Iterable` 判定（排除 str / bytes / dict） |
| 9 | 分块导出断言「拼接等于再次生成」偶发失败 | xlsx 元数据含生成时间，两次生成字节不保证一致 | 改为解析拼接结果断言表头与行数 |

## 7. 偏差与遗留 <a id="deviations"></a>

1. **实际投入高于计划列**：新增 PDF 渲染引擎接入、报告服务 worker 与 compose 容器、清理作业与两套测试使实际投入明显增加；阶段计划表按原列位归档，阶段合计不变。
2. **前端未做**：导出按钮 / 对话框 / 列偏好归阶段十五；本段接口可直调验收。
3. **站内信未做**：超阈值导出完成只到作业终态 + 状态端点取址，通知归 07_01（需求注块已登记）。
4. **审计未落库**：只到 `AuditCapturer.capture` 边界 + 明文 `warning` 日志；落库与链校验归 06_01 / 06_02。
5. **单据打印产物未清理**：`print.artifact.cleanup` 不在本段；platform 导出产物已由 `platform.export.cleanup` 覆盖。
6. **取数性能**：导出用 offset 分批（`fetch_batch_size` 默认 500），超大表末页会扫描较多行；真库瓶颈出现后评估 keyset 游标。
7. **时区**：导出时间按 UTC 格式化；用户时区偏好（05_02）落地后只改 `format_export_time` 一处。
8. **模板变量清单为空**：内置模板不声明变量，渲染按实际字段；模板定义与渲染定义归 10_01。
