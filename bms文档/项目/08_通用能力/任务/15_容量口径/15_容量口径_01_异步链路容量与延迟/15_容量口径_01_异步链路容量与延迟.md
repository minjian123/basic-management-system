## 2. 任务内容 <a id="content"></a>

1. **主链路不被阻塞**：写接口的响应不等待异步副作用（操作日志 / 通知）落库。压测固定同一写接口、固定工作负载，在三种配置下各跑一轮——「副作用全关」「仅操作日志」「全开（含字段级审计）」——**全开相对全关的 P99 差异 ≤ 5%**；字段级审计的同事务捕获成本单列说明（06_02 定的是同事务强一致，属设计明确的例外，不混入异步副作用口径）。
2. **审计链消费延迟**：同租户事件从投递到落入审计表 **P95 ≤ 5 秒**。当前 01_01 的 msg 消费组运行时尚未落地（`[event_consumer].provider` 唯一实现为 `null`），本任务按「指标 + 告警 + 可复现写入侧基准」交付，端到端实测口径与差距在报告中单列，真实链路复测归口 01_01 补口任务（详见详细设计 §12）。
3. **写入吞吐基线**：固定数据集**单租户 5 万条**、固定**并发 32**，单租户日志写入 **≥ 500 条/秒**；给出实测吞吐与 P50 / P95 / P99 写入时延。
4. **分片表提前量与跨月**：下月审计分片表在**当月 25 日前**创建；以注入时钟模拟跨月，验证**跨月 0 失败**（新月首条写入直接成功、链头衔接正确），并给出「次月就绪」信号与告警判定。
5. **积压与死信**：Outbox 待投递条数超阈值（**默认 1 万 / 租户**，按库键出明细）告警；死信进库后 **24 小时内**未处置告警。两类告警均须给出**可触发的验证方式**（规则单测 + 指标发射用例），指标在 `/metrics` 与监控面板可查。
6. **压测方法与环境**：固定数据集 + 固定并发 + 四类指标采集（主链路 P99 / 审计链消费 P95 / 单租户写入吞吐 / 分片与 Outbox 积压）；报告写明环境规格（机器、库、缓存、是否真 broker），做不到的项目标「限定达标」并写清差距与归口，**不得编造实测值**。

## 3. 完成标准 <a id="accept"></a>

- 压测报告给出上述四项实测值与目标逐项对比（达标 / 未达标 + 原因 + 归口），并写明环境规格与固定口径（数据集规模、并发、配置差异）；
- 主链路 P99 差异实测 ≤ 5%（未达标须给出归因与改进归口）；
- 跨月切换实测 0 失败（注入时钟模拟）；次月分片在当月 25 日前就绪的判定信号与告警可验证；
- Outbox 积压阈值告警与审计链断裂 / 延迟告警均可触发（规则单测真跑表达式 + 指标发射用例），指标在 `/metrics` 端点与容量面板可查到；
- 新增指标全部落基座指标体系（`BaseMetrics` / `METRIC_NAMES` / `METRIC_DOCS`），**不在模块内自研平行指标**；新增 / 变更模块行 + 分支覆盖率 100%；
- Kiwi 用例先登记后编码，编号回读核对一致。
