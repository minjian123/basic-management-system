## 2. 过程 <a id="process"></a>

### 2.1 批 1：配置与常量收敛

- `[dict]` 新增 7 个参数（`type_ttl_seconds` / `empty_ttl_seconds` / `lock_ttl_seconds` / `lock_wait_seconds` / `l1_max_items` / `probe_limit` / `invalidate_on_write`），配套 `DictSettings`。
- 字段名取 `dict_options` + `validation_alias="dict"`：直接叫 `dict` 会遮蔽 `BaseSettings.dict()`（实测 pydantic 告警），且 `Settings` 为 `extra="forbid"`——配置节与字段必须同批落地，否则启动即失败。
- 基线 `config.toml` 补 `[data_source]`（routed）/ `[dict_translator]`（routed）/ `[dict_cache_region]`（memory）：**修掉 test / prod 落 null 实现（字典恒空）** 的现状；`config.dev.toml` / `config.prod.toml` 覆盖为 `redis`，`config.test.toml` 压短 TTL。
- 新增 `datasource/keys.py::DataSourceKey`（12 个平台 key 的 StrEnum）+ `platform_data_source_keys()`；`DATA_SOURCE_CATALOG` 与 `FORM_CATALOG` 的 `data_source_key` 全部改用枚举值（24 处字面量收敛）。
- `DictCacheRegion.lock_cache_key()` + `adrop_id_subset()`；Redis 缓存域互斥锁键由 `lock:bms:...` 改为 `bms:{tenant}:dict:lock:{locale}:{type}`（命名规范口径）。

### 2.2 批 2：出口与表源

- `DictOptions`（值对象，`[dict]` 的唯一运行期形态，`from_settings()` 构造）；`RoutedDataSource` 注入 options。
- 出口四处改造：空结果走 `empty_ttl_seconds`、带过滤条件不缓存、互斥锁 TTL / 等待可配、`batch` 尊重入参 `locale`（缺省值视为未指定，沿用 `Accept-Language`）。
- 翻译复用缓存：先读 `aid_subset` → 只对缺失 id 回源 → 回填（原实现每次全量 `load`）。
- 提供者异常边界：`_load_rows()` 只包 `provider.load`，异常记 `warning` 并返回空结果、**不写缓存**。
- `DictTableDataSource` 扩展：`db_scope`（platform / tenant）+ `DictI18nSpec`（i18n 附表 LEFT JOIN + `COALESCE` 回退）+ `sort` 列可缺省（按 `id` 排序）。
- 新增 `DictInvalidator`（DEL 各语言类型键 + id 子集键 → `INCR` 版本键；失败只告警）+ `get_dict_invalidator` 依赖。

### 2.3 批 3：平台规格与失效接入

- 新增 `dict_specs.py`：12 个 key 一行规格（库域 / 表 / 列映射 / i18n / 排序 / `mode`），平台库 5 + 租户库 7；`role` 保留 `mode=port` 走 `RoleReferencePort`，其余 `mode=table` 走表源。
- `PlatformDictDataSource` 改为按规格分派（表源实例按 key 缓存），**新增字典不再改本文件**。
- 角色域三个写端点（`POST /roles`、`PUT /roles/{id}`、`DELETE /roles/{id}`）在服务层提交后调 `invalidate(("role",))`——顺序为「先提交、后失效」。

### 2.4 批 4：启动校验与护栏

- `application.service_lifespan` 前置 `_validate_data_sources()`：清单自校验（复用 `DataSourceRegistry.validate()`）+ 覆盖校验（仅 `provider=routed` **且本进程已登记提供者**时，避免非平台服务启动即失败）。
- `ops/check_tables.py` 的 `check_offline` 追加数据源登记校验（运维 / CI 离线复跑同一规则）。
- 护栏用例两份：基座 `tests/datasource/test_registry_guard.py`（枚举 ↔ 清单、无 `sys_dict*` 表、声明表外无 `data_source_key` 字面量）、服务侧 `tests/dict/test_dict_registry_guard.py`（规格 ↔ 清单 ↔ 模型列 ↔ 库域 ↔ i18n 关联列）。
