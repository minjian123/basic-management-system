## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 编解码往返失败：解码报「消息体不是 JSON 对象：str」 | `ConcurrentStableDict` **不是 dict 子类**（是 `Mapping`），`json.dumps(..., default=str)` 把它整体转成字符串 | `encode_event` 改用 `json.dumps(dict(body), ...)`；测试锁住往返保真 |
| 2 | 护栏「集合声明」多轮拦截（list / dict / Sequence / tuple / Mapping） | `check_bare_collections` 要求集合声明命中 `ConcurrentStable*` 白名单 | 端口入参、局部集合、返回值、测试夹具全部改并发集合（含 `main(argv)` 与 `asyncio.Queue` 容器） |
| 3 | 发件箱用例全量报 `TypeError: non-default argument follows default argument` | `OutboxRecord.trace_id` 被插在无默认值的 `status` 之前 | 移到默认值区（`error_msg` 之后）；`to_envelope` 关键字传参不受顺序影响 |
| 4 | 消费用例「订阅不支持该契约版本：1.0.0」→ 与预期（重试成功）不符 | `encode_event` 用 `DEFAULT_EVENT_VERSION` 补版本，而 `sys.user.created` 契约已升 `2.0.0` | 改为按登记契约补版本（`resolve_event_version`，与发件箱 `enqueue` 同源）；消费端保留版本兼容校验 |
| 5 | 消费用例单独跑通过、全量跑失败 | 用例依赖「进程内已注册平台事件契约」（同目录其它用例先注册），存在顺序依赖 | 补 autouse 夹具 `register_platform_event_contracts()`，与真实启动路径同源 |
| 6 | 设计假设「整批统一 ack」与 SDK 实际不符 | 官方 `SimpleConsumer.ack(message)` 是**单条**确认；`receive` 是**长轮询** | 实现按真实 API 逐条 ack；长轮询下无需额外 sleep；同步 SDK 调用统一 `asyncio.to_thread` |
| 7 | `event_consumer` 域同时出现处理器与组两个 null 实现 | 处理器轨与组端口共用插件域会重名 | 处理器轨独立为 `event_handler`（不参与装配），组端口独占 `event_consumer`；装配测试与插件契约用例同步 |
| 8 | 迁移脚本口径与表文件不一致 | 表文件记「平台链 `0003` / 租户链 `0002`」，但脚本已随 06_05 清空（结构以模型为事实源） | 设计开放项 1 按实际口径改写：改模型 + 表文件即可，不新造迁移脚本 |

## 7. 偏差与遗留 <a id="deviations"></a>

1. **未接真 broker 验证**：本机未起 broker，完成标准里的「投递器中断恢复补投、同租户链序、死信告警」只在替身用例层面验证；真 broker 端到端待 broker 就绪后按设计 §4.10 步骤执行（需先补 `base.yml` 的 8081 映射）。
2. **业务消费组不在本段**：审计链组 / 日志组 / 通知组 / Webhook 组随 06_01 / 06_02 / 07_01 在自己服务的 `event_consumer_records()` 声明；本段交付机制与运行时。
3. **Outbox 多实例投递**：`claim_pending` 无行锁，多实例并发会重复投递（消费端幂等收敛）。单实例部署无影响，开放项保留。
4. **Kiwi 用例编号**：本段新增用例未登记 Kiwi 编号，测试记录标「待登记」，不编造。
5. **覆盖率门禁**：开发环不采集覆盖率；推送前按推送环跑覆盖率门禁（新增模块目标 100% 行 + 分支）。
