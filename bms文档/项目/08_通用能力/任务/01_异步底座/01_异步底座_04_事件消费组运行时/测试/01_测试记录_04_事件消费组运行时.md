## 4. 真栈验收 <a id="e2e"></a>

环境：开发服务器 Compose（msg 0712 + platform 97b4cafa + tenant 97b4cafa + event-worker 97b4cafa + MySQL / Redis）；库结构重建与产品登记恢复过程见[实施记录](../实施/01_实施记录_04_事件消费组运行时.md#process-e2e)。

| 验收项 | 判据 | 结果 |
| --- | --- | --- |
| 主题供给 | 每启用租户每个契约主题存在、审计三主题 4 分区 | **通过**：3 租户 × 22 主题 = 66，`wf` 未启用跳过 3；msg 库 `msg_topic` 共 67 行（含 1 行历史），分区 1~4 |
| 消费组加入 | 每（租户 × 审计主题）一条消费单元，拿到分区 | **通过**：9 个单元 `event_consumer_unit_started`，`partitions=[0, 1, 2, 3]` |
| 两进程分区不重叠 | 同组第二成员分到互补分区、`join_failed` 为 0 | **通过**：第二进程分到 `[0, 1]`，`join_failed` 0 条 |
| 发布 → 消费 → 审计分片落库 | 三类审计事件落对应月分片、链校验通过 | **阻塞**：`POST /api/v1/msg/publish` 恒 500（msg `record.py` 记录头 msgpack 打包 `topic_id` 溢出 uint64），消息写不进 broker |
| 消费端到端 P95 | 按日志类型给出 P50 / P95 / P99 | **阻塞**（同上）；不补造数字，复跑口径见 15_01 报告 §9.5 |

结论：01_04 的运行时、主题供给与消费组加入在真栈成立；端到端与 P95 被 msg 0712 编码缺陷阻断，未闭环。

## 6. 观察项 <a id="observe"></a>

1. **真 msg 集成用例在本机恒跳过**：本机无 Docker、无 msg 实例，3 条集成用例按设计自动跳过；真实链路只在开发服务器真栈验证，不在本机伪造。
2. **`pyright` 必须指定解释器**：以文件参数直接运行时若不传 `--pythonpath .venv/Scripts/python.exe`，会把第三方依赖全部报成未解析（实测 587 条假错误），不能据此判断代码质量。
3. **消费时长直方图只测处理器**：`bms_event_consume_duration_seconds` 从进入处理器到返回，不含退避等待与传输时间；端到端时延以 15_01 的 lag 口径为准。
4. **真栈供给以库核对替代 CLI 自校验**：msg 的主题列表接口 500（`MissingGreenlet`），`ops.event_topics --check` 取不到已存在主题，本次改用 `msg.msg_topic` 直接核对行数与分区，缺陷登记遗留。
5. **真栈阻塞点属 msg 侧**：发布恒 500（记录头 msgpack 打包雪花 id 溢出）在 bms 侧无可绕开手段；01_04 记为「代码交付完成、真栈端到端待 msg 修复复跑」，不把未取得的分位写成结论。
