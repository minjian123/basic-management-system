## 3. 实施过程 <a id="process"></a>

### 3.1 契约与配置（批次 1） <a id="process-contract"></a>

- **租户清单只读契约**：租户服务新增 `GET /api/v1/tenant-registry/active`，只返回启用且未软删的租户，按主键升序、不分页，响应字段 `code` / `name` / `tenant_id` / `db_basis` / `status`；仓储侧复用既有 `active_rows`。契约快照 `deploy/contracts/tenant.json` 与前端类型 `frontend/packages/api_types/src/tenant.ts` 同步重导。
- **租户目录端口**：`db/tenant.py` 增加 `TenantDirectory` 协议（`active_tenants()`）；`db/tenant_remote.py` 的 `RemoteTenantSource` 结构化实现该协议，按 `[tenant].resolve_cache_ttl` 缓存，失败上抛由运行时保留旧集合。
- **运行参数**：`EventConsumerSettings` 补 `long_poll_ms`（缺省 20000）与 `tenant_refresh_seconds`（缺省 60）；`visibility_timeout_seconds` 保留但注明对 msg 不生效。
- **发布器修正**：`MsgEventPublisher` 的命名空间缺省取事件类型首段（事件域），`[event].options.namespace` 仅作显式覆盖；缺省租户取 `[platform_tenant].code`，无租户事件不再被判 `350012`；`ops/outbox.py` 同源修正。

### 3.2 运行时（批次 2） <a id="process-runtime"></a>

`MsgEventConsumerGroup`（`bms_core/events/msg_consumer.py`）实现端口 `BaseEventConsumerGroup`，关键语义：

- **装载与订阅**：`load()` 按 bms 组合并声明，组名补 `group_prefix`，按组建立处理器表与「主题 → 命名空间」表；同一主题派生出不同事件域即抛 `EventConsumeError`（实现缺陷，fail-closed）。`subscriptions()` 由真实声明派生，供契约覆盖校验与启动日志使用。
- **租户覆盖**：平台租户固定并入；业务租户经 `TenantDirectory.active_tenants()` 动态枚举，`_tenant_loop()` 按 `tenant_refresh_seconds` 刷新；新增租户建立全部单元，停用租户停单元并 `close()`；清单不可用时保留旧集合（首轮退化为平台租户），只告警不中断消费。
- **消费单元**：最小单位为「租户 × 组 × 主题」，每单元一个 `MsgConsumer` + 一个拉取协程；`join()` 失败（主题不存在 / 租户未开通 / 网络抖动）只告警并关闭该消费者，下一轮刷新重试；分配为空时不拉取，按 `poll_interval` 等待心跳更新分配；`paused` 视作背压退避。
- **跨主题串行**：每个 bms 组一个 `KeyedLaneExecutor`，该组所有主题、所有租户共用；`ordered=True` 的组道数固定 1。分区键顺序为 `aggregate_key → tenant_id → event_id`，审计三类事件（`tenant:{id}`）因此落在同一道，跨主题串行追加。
- **幂等**：`seen()` → `handler.consume()` → `remember()` 整体在串行道内；命中 L1 计 `skipped` 并 `ack`；Redis 不可用降级放行，L2 唯一约束兜底。
- **重试与死信**：处理器失败按 `retry_backoff_seconds × 2^(n-1)` 退避，最多 `max_retries` 次，成功计 `retried`；耗尽写 `sys_event_dead_letter`（`source=consumer`、`consumer=组名`、`retry_count`）后 `ack`；毒消息（解码失败 / 无处理器 / 主版本不支持）不重试直接死信；死信落库失败**不 ack**，并尝试 `nack`（`processing_failed` / `schema_invalid`）兜底，仍失败留给可见性超时重投。
- **停机**：`stop()` 先停租户刷新与新单元创建，再逐单元取消拉取协程、`close()`（`leave` + 关传输），最后关闭执行器；`aclose()` 幂等。
- **指标**：`bms_event_consume_total{group,result}`、`bms_event_dead_letter_total{consumer}`、`bms_event_consume_duration_seconds{group,result}` 三处发射点；`METRIC_NAMES` / `METRIC_DOCS` 同步。

### 3.3 装配与运维入口（批次 3） <a id="process-wiring"></a>

- `core/assembly.py` 登记 `event_consumer` 的 `msg` 工厂，注入 `EngineRegistry` / `SessionFactory` / `BaseMetrics` / `TenantDirectory`；`setup()` 仅在 `enabled` 且 `host == "in_service"` 时启动，`worker` 宿主只装载；`aclose()` 随资源管理器逆序回收。
- `ops/event_consumer.py` 与进程内宿主共用 `build_msg_event_consumer_group(...)`，不再维护第二套装配；CLI 支持 `--groups`（打印组 / 主题 / 租户）、`--once`（单轮拉取消费）、`--worker`（独立宿主）。
- `deploy/compose/services.yml` 新增 `event-worker`（复用 `bms-platform` 镜像、`expose: []`、独立 `BMS_APP__WORKER_ID=106`、`BMS_EVENT_CONSUMER__HOST=worker`）；platform 服务改为 `host=worker`，通知服务保持 `in_service`。
- 三环境：`config.dev.toml` 打开 `[event].provider=msg` / `[event_consumer].provider=msg`、`enabled=true`；`config.prod.toml` 写全套参数但 `enabled=false`；`config.test.toml` 两个 provider 为空，单测不连 msg。

### 3.4 主题供给（批次 4） <a id="process-topics"></a>

`ops/event_topics.py`（新增）：装载平台内置与产品注入的事件契约 → 按 `namespace = event_type.split(".")[0]`、`topic = topic_for(event_type)` 去重派生 → 经 `/tenant-registry/active` 取租户 → 逐租户逐主题 `POST /api/v1/msg/admin/topics`（`350008` 视为已存在）→ 审计三主题目标 4 分区、其余 1 分区，已有且不足时扩分区（只增不减）→ 命名空间未启用（`350010`）跳过并 warn。`--check` 只读校验存在性与同组各主题分区数一致性，缺口退出码 1。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 根因 | 处置 |
| --- | --- | --- |
| 真 broker 集成用例 3 条跳过 | 本机无真实 msg 实例（`[service_client].instances.msg` 未配置） | 设计即允许自动跳过；真栈验收在开发服务器补齐 |
