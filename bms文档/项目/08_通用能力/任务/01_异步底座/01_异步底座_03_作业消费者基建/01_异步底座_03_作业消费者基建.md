## 2. 任务内容 <a id="content"></a>

1. **作业模型与基础设施表**：`sys_job`（基础设施表，每服务每链一份）承载作业标识（雪花 ID，字符串输出） / 类型 / 提供方 / 租户 / 提交人 / 负载 / 结果 / 优先级 / 进度 / 尝试次数 / 状态 / 租约 / 时间戳；状态机 `queued` / `running` / `succeeded` / `failed` / `canceled` / `dead`；部署保证 `worker_id` 全局唯一。
2. **提交与幂等**：事务性提交（同业务事务落库）、提交即持久、幂等键同键返回既有作业；提交失败不得留下半条作业。
3. **统一执行引擎**：任务调度保留 `sys_task` 定义与 cron 调度，到期生产作业；`sys_task_log` 保留为任务历史并由作业终态回写；任务 worker 与 Redis 任务队列退役，既有任务 API 查询口径不变。
4. **消费者与租约**：每服务独立 worker；数据库条件更新抢占 + 租约续租；全局并发 + 单租户并发上限 + 租户内优先级；协作式取消（批次边界）、优雅停机、租约过期回收。
5. **重试与死信**：可重试失败指数退避回队，达到上限或不可重试转 `dead`；死信可查、可人工重试并留痕。
6. **作业类型注册**：产品自持清单新增 `jobs` 记录类（作业类型 / 提供方 / 执行者 / 超时 / 重试 / 并发 / 负载版本 / 状态）；平台装载为只读作业类型视图，代码侧 handler 注册与声明对账，不一致按装载失败语义处置。
7. **监控、事件与管理面**：作业生命周期事件 + 平台投影 `sys_job_monitor`；`sys.job.completed` 契约登记；平台提供作业类型目录与统一监控查询（读投影），取消 / 重试转发到作业所在服务；权限码 `job:query` / `job:manage`。
8. **迁移与保留期**：03_01 孤儿清理迁为文件服务 `file.cleanup_orphans` 作业，旧触发型路径移除；txn 恢复轮询、outbox 投递器与事件消费组保持原样；作业记录保留 30 天，内置清理作业按保留期删除。
9. **统一基类与产品扩展**：作业模型 / 负载 / 结果 / 处理器 / 消费者 / 仓储 / 注册表等公共语义在共享基座维护；产品默认继承 `BaseJobHandler`，只实现 handler、负载与作业类型声明；确有必要可继承更深的消费者 / worker 基类，但须保持统一状态机、租约、进度与事件契约，偏差自担且不影响其他产品；不得另起炉灶自研平行队列 / 消费者 / 租约 / 重试 / 监控，不得绕过基类写作业表；第三方组合轨经统一注册通道接入并过同一契约测试。

## 3. 完成标准 <a id="accept"></a>

作业提交后进程重启 / Redis 不可用仍能继续执行；作业标识全系统唯一（部署 `worker_id` 全局唯一）；多 worker 并发下同一作业只执行一次，租约过期可回收；进度、尝试次数、错误摘要可查；重试退避与死信生效且死信可人工重试；取消在批次边界生效并落终态；任务到期生成作业且 `sys_task_log` 历史仍可查、既有任务 API 行为不变；03_01 孤儿清理经作业执行且旧触发路径零残留；`jobs` 声明装载、代码侧 handler 对账与不一致拒绝生效，平台可查作业类型目录；生命周期事件与平台投影可查，`sys.job.completed` 契约登记；管理面权限与转发取消 / 重试生效；产品侧继承 `BaseJobHandler` 并声明即可接入，未自研队列 / 租约 / 重试；真 Redis 多 worker 竞争、租约回收与重试用例通过；覆盖率达标（口径见《[AI开发规范](../../../../../规范/AI开发规范.md)「覆盖率要求」）。
