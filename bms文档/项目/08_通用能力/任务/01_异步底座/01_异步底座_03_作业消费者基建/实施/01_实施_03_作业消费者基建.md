## 2. 关键实现 <a id="key"></a>

- **状态机**：`queued → running → succeeded / failed / canceled / dead`；终态不可回退，重试只发生在 `running → queued`；`failed` 是业务终态，`dead` 是重试耗尽 / 系统异常。
- **提交即持久**：`JobRunner.submit` 在调用方事务写 `sys_job` 与 `sys.job.submitted`；幂等键先查 + 唯一约束兜底（冲突由调用方独立事务回读）。
- **抢占**：`claim_job` 条件 UPDATE（`status='queued' AND next_run_at<=now`）+ `rowcount=1`；不依赖 `SKIP LOCKED`，四方言同口径。
- **执行**：`JobExecutor` 统一上下文 / 进度节流 / 心跳续租 / 超时 / 终态；worker 与 `run_inline` 共用；`transactional_writes` 区分「自开事务」与「调用方事务」。
- **公平**：全局并发 + 单租户并发 + 类型并发三重信号量；`priority` 只在同租户内排序。
- **取消 / 重试**：队列中直接取消；运行中置 `cancel_requested` 由 handler 批次边界协作；死信 / 失败可人工重试（重置 `attempts` 回队）。
- **保留期**：`cleanup_finished_jobs` 按 30 天硬删终态作业与行级错误；运行中 / 待执行不删。
- **任务迁移**：beat 只在同一租户库事务内写 `sys_task_log(running)` 并提交作业；`TaskJobHandler` 按白名单解析执行体，终态回写任务日志并发 `sys.task.completed`。
- **文件迁移**：handler 复用 file 域 `FileService.cleanup_orphans`（对象存储 / 分片上传插件按需装配），进度为「回收数 / 扫描数」；旧触发型路径零残留。
- **平台管理面**：读平台投影 `sys_job_monitor`；取消 / 重试按 `service_key` 转发内部契约；目录读 `sys_job_type`（启动自举写入，`content_hash` 未变不写、退役不删行）。
