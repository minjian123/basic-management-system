## 2. 关键实现说明 <a id="impl"></a>

### 2.1 上传契约 <a id="upload"></a>

- 秒传：`POST /files/dedup`，体 `{name, size, sha256, mime?}`；未命中 `data=null`。
- 分片：`POST /files/multipart`（体 `{name, size, sha256, mime?}`，对象键由后端按主键派生，不再由前端生成）、`PUT /files/multipart/{id}/parts/{no}`（头 `X-Part-Sha256`）、`GET /files/multipart/{id}`（读 `uploaded`）、`POST .../complete`、`DELETE ...`。
- 哈希：引擎按任务只算一次，保留 `{sha256, partHashes}`；**分片模式必然计算**（后端初始化与每片校验都要求摘要），秒传关闭且整包上传时不请求哈希。
- 批量回显：后端 `ids` 去重保序、上限 200；非法形态统一 `10001`。

### 2.2 字典版本联动 <a id="dict"></a>

`revalidateType` 复用 `_loadOne`（带当前版本），同类型在途去重；版本一致后端回 `items=null` 时保留现有条目，失败保留旧候选并回错误态。字段在 `focus` 与下拉展开时触发，同字段 3 秒节流（两个事件共用同一时间戳，避免双请求）。

### 2.3 通知与审计 <a id="notice-audit"></a>

- 通知请求类型映射：`todo → approval`、`system → system`、`notice → alert`；响应侧经 `normalizeNotificationType` 归一（`approval → todo`、其余 → `notice`）。
- 顶栏在宿主能力未装配时降级为未就绪（不发请求），保证组件可独立挂载 / 单测。
- 审计：后端每行一个字段变更；`useAuditDiff` 按 `event_id` 分组为记录行，选中时**复用组内行**映射字段差异（不额外请求，规避“按事件过滤”端点缺失）；链校验结果与断裂月份透出。

## 3. 偏差与遗留 <a id="deviation"></a>

| # | 项 | 处置 |
| --- | --- | --- |
| 1 | 详设写「审计选中调详情端点」 | 后端详情只按审计主键返回单字段行、无按 `event_id` 过滤；改为组内行直接映射，**零额外请求**（页面边界注明） |
| 2 | 通知请求侧 `notice → alert` | 后端类型为 `system/approval/alert/import`，前端 `notice` 档无同名类型；按通知类取 `alert`，`import` 归入 `notice` 展示（筛选时可能漏 `import`，登记遗留） |
| 3 | 审计列表 `total` 按字段行计 | 页面注明；按事件计总数需后端新增分组端点（新契约） |
| 4 | 真实 mdm / 短信渠道 | 部署窗口联调；本任务以契约桩验收 |
| 5 | 通知 Socket.IO | 阶段十；本轮轮询占位校准未读数 |
| 6 | 产品页面接入 | 阶段十五；本任务只交付组件与宿主默认源 |
