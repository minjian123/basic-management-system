## 2. 实施过程

1. **先定口径并确认**：落库位置（平台库集中）/ 事件通道 / 捕获范围 / 动作来源 / 脱敏 / 登录捕获 / 分片建表 / 域与种子 / 链校验 / 归档边界，逐项 question 确认后开工。
2. **基座先行**：真实链 → 事件构造 → 发射器 → 中间件 → 配置与错误码，再接服务侧消费与查询。
3. **分片与链**：运行期 `ensure_shard`（Core 建表 + 台账）+ 启动预热 + 预创建任务；写路径「同月优先、其次更早月」取链尾。
4. **登录捕获**：在 API 层包裹登录调用，按异常类型映射 `fail_reason`；成功另记一条，`last_login_at` 仍归 platform。
5. **查询与校验**：时间范围缺省 / 上限、前后各扩一月路由分片、雪花 ID 反解月份查详情；校验器按租户跨月衔接并在指定月份校验时预加载更早链尾。
6. **契约与种子**：事件契约 / OpenAPI 快照重生成；`log` 域、表归属、审计管理员授权与菜单种子同步。

## 4. 问题与处置

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| `[audit]` 段与既有字段级审计能力选择冲突 | 配置段名已占用（`AuditCapturer`） | 新段改名 `[audit_log]`，字段 `AuditLogSettings`；设计同步回写 |
| 事件契约校验报「字段名占用信封保留键」 | 载荷误放 `occurred_at` / `trace_id`（信封已有） | 载荷移除二者，消费侧取 `EventEnvelope.occurred_at` |
| 插件注册表「`hash_chain:sha256` 重名」 | 零参类导入时自动登记 + 显式 `register_plugin` 重复 | 只保留自动登记；由平台 `domains/log/jobs.py` 导入并作为 provider 缺省回落名，不牵动基座 `assembly.py` |
| 台账唯一约束未生效 | `(log_type, shard_month, deleted_at)` 中 `NULL` 互不相等 | 改为 `(log_type, shard_month)`（台账行不软删），表文件同步 |
| 异步会话建表回调参数是 `Session` 而非 `Connection` | `AsyncSession.run_sync` 传入同步 `Session` | 回调内 `sync_session.connection()` 再 `create_all`；达梦同步门面走 `raw.get_bind()` |
| 登录详情按雪花 ID 定位分片失败 | 测试注入时钟月份与 ID 时间戳月份不一致 | 详情用例改用与 ID 同月的记录；生产按真实写入时钟，二者一致 |
| 定向选择首轮 5 项失败 | 域布局数量 / 异常构造表 / 基类继承 / 事件契约条数 / 导出用例偶发 | 前四项随本任务补登记与基类继承；导出用例单跑与复跑均通过（共享库并行偶发，非本改动引入） |
