结果小结：

- 关键表经 ORM 变更即自动落 `sys_data_audit_log_{yyyyMM}`，**一行一字段**、带 `domain_key`，敏感列落 `***`；
- 审计事件与业务**同事务**入发件箱（业务回滚则审计不留、提交则必达），经 `audit-chain` 有序组逐条成链；
- 新增三条 `/api/v1/audit/*` 端点（`log:query` 查询、`log:manage` 链校验），篡改可精确定位到月 / 序号 / 记录；
- 三权分立的拒绝尝试从空实现改为真实落库，并新增「审计管理员授权只读」不变量（越界 `30048`）。

## 4. 问题与处置 <a id="issues"></a>

| 问题 / 现象 | 原因 | 处置 |
| --- | --- | --- |
| 计划里「审计域复用 log 域仓储 / 校验器」不可行 | engkit 域边界门禁 D2 只允许跨域指向 `public`，D6 禁止 `public` 导出仓储 / `services` 实现 | 与用户确认后改为链内核上移基座，两域共用同一实现；`log` 域留再导出薄壳（设计 §11 已回写） |
| `sys_tenant_quota` 进基座白名单被「跨服务库访问」拦下 | 基座不得引用他人服务库表名 | 从基座常量移除，改由 tenant 服务装载期 `register_audited_tables()` 注册 |
| 硬删除（`session.delete`）不产生审计 | `before_flush` 时 `state.deleted` 仍为 False，删除态须由会话三态判定 | 改为按 `session.new` / `session.deleted` 身份集合判定，并补用例 |
| ORM 实例不可哈希（`set(session.new)` 报 unhashable） | `BaseModel` 带 `__eq__` 未定义 `__hash__` | 改用 `id(obj)` 身份集合 |
| 事件 topic 原设计写 `bms-sys-data-changed` | topic 按「域 + 对象」两段派生 | 修正为 `bms-sys-data`（设计 §5 / §13 已回写） |
| 覆盖率门禁先报 21 行未覆盖 | 新模块用例尚未补齐（删除分支 / 截断 / 失败分档 / 同步门面 / 空月份分页 / 事件构造） | 逐条补用例，最终 34 文件行 + 分支 100% |
| 提交钩子报「只能全仓判定的步骤」拒绝提交 | 前端 typecheck / vitest 步骤无文件级判据 | 按规范手动跑同一门禁（`--allow-full-steps`，36 项全绿）后 `--no-verify` 提交，推送环复判 |
| SQLite 内存库线程校验失败 | `SyncSession` / aiosqlite 跨线程使用连接 | 用例引擎加 `check_same_thread=False` |
| `ruff` / `pyright` 首轮 8 处报错 | 未使用导入、私有函数被测试引用、集合声明未用基座集合类 | 逐条修正（引用锚点常量、公开 `parse_months`、返回 `ConcurrentStableList`） |
