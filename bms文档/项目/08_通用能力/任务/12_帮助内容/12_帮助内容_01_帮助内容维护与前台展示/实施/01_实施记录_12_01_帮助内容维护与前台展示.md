## 2. 实施概览 <a id="overview"></a>

```mermaid
flowchart LR
    A[反馈表与表归属] --> B[错误码 / 配置 / 语言助手]
    B --> C[目标校验抽取]
    C --> D[维护仓储与服务]
    D --> E[读者 / 统计 / 包管理]
    E --> F[路由与装配]
    F --> G[内容缓存与种子]
    G --> H[契约 / 前端类型 / 测试]
    H --> I[文档回写]
```

- 新建 `sys_help_feedback` 模型与表文件，表归属由 `planned` 转 `enabled`；
- `help` 域新增维护 / 读者 / 统计 / 包管理四组服务、六个契约文件、四个路由；
- 内容缓存落在 `DatabaseHelpContentResolver`（只缓存命中结果），写路径经租户内容版本键即时失效；
- 新增三分类 + 三篇双语基础文章种子与 `help:package` 权限码；
- 契约快照与前端类型重生成；错误码 40014~40023 与中英文案补齐。

## 3. 实施过程 <a id="process"></a>

1. **数据库设计**：新建 `sys_help_feedback` 表文件，更新《数据库设计 · 帮助中心》「表清单」/「关键设计要点」/「与相邻模块的边界」节与总览登记；`TABLE_OWNERSHIP` 转 `enabled`。
2. **基座**：`HelpPackageSettings`（`[help_package].root`）；错误码 40014~40023、`HelpContentError` 子段基与 10 个异常；`error_seed` 中英文案。
3. **语言助手**：`repositories/help_locale.py` 增启用语言清单；`repositories/help_anchor.py` 增「锚点 → 类型」映射。
4. **目标校验**：新增 `domains/help/targets.py`，`package_spec.py` 改为复用，装载器与维护面共用同一映射。
5. **维护面**：`repositories/maintenance.py`（分类 / 文章 / 反馈 / 统计 / 包列表）+ `services/maintenance.py`（校验 / 状态机 / 事件 / 缓存失效）+ `schemas/*` + `api/manage.py`。
6. **读者面**：`services/reader.py`（分类树 / 列表 / 详情 / 阅读计数去重 / 反馈）+ `schemas/reader.py` / `feedback.py` + `api/reader.py`。
7. **统计与包管理**：`services/statistics.py`、`services/package_admin.py`（受限目录 + 08_03 计划器）+ 对应 schema / 路由。
8. **装配**：`wiring.py` 四个构造器、`api/deps.py`、`api/router.py` 挂载三个路由。
9. **内容缓存**：`bms_core/help/cache.py`（版本键 / 缓存键 / 编解码 / 降级）；`DatabaseHelpContentResolver` 命中缓存、未命中不缓存；维护 / 包写路径递增版本。
10. **种子**：`tenant/seed/help.py` + `ops/seed_help.py` + `[[seeds]] seed-help` + `SEED_OPS` / 分支处理器；`help:package` 权限种子。
11. **契约与类型**：`ops.contract_snapshot export`；`pnpm api_types:gen`。
12. **测试**：先登记 Kiwi 2529，再写基座 / 维护 / 读者 / 反馈统计 / 包管理 / 缓存 / 种子 / 目标校验用例。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 内容缓存最初放在 `menu_form` 解析服务，08_02 的桩解析用例连续改桩数据会被缓存挡住 | 缓存下沉到 `DatabaseHelpContentResolver`（真实内容实现侧），桩实现不参与缓存；只缓存**命中**结果，未命中不缓存（避免运维直写 / 种子写入后仍读到「暂无帮助」） |
| 2 | 共享库语言清单被其他用例改写，文章多语言用例偶发 40022 | 用例内固定 `load_help_default_locale` / `load_help_locales`（与真实实现同签名），避免跨用例状态耦合 |
| 3 | 文章编辑时默认语言行已被 `existing` 占位，新标题 / 正文不生效 | `_resolve_texts` 增 `replace_default`：编辑显式传标题 / 正文时覆盖默认语言行；传 `i18n` 时以 `i18n` 为准，缺默认语言才用请求体补齐 |
| 4 | 计数 `UPDATE` 触发 ORM 会话同步，响应把增量算了两次 | 计数更新加 `synchronize_session=False`，响应按「读到的旧值 + 增量」计算 |
| 5 | 种子用例在内存库触发字段级审计，缺 `sys_outbox` 表 | 种子用例 autouse 关闭 `audit_capture.enabled`；跨用例污染用 SQL `update` 代替 ORM 行更新 |
| 6 | 用例创建的全局锚点文章 / 平台动作码锚点污染共享库，08_02 的「未命中」与锚点计数断言失败 | 相关用例在 `finally` 内软删文章、硬删自造动作码；全局目标文章一律在用例结束清理 |
| 7 | 提交环选测不采集服务侧覆盖率（无同名测试，按既有口径「交推送环」） | 本地用 `bms_testing_plugin` + `BMS_COVERAGE_DATA=.cache/coverage/.coverage` 窄目录采集，再用 `coverage_report.py --module` 查缺口；新模块 19 个全部 100% |
| 8 | `pyright` 报测试里访问私有 `_should_count_view` / `_summary_of` | 前者改公开 `should_count_view`（语义上本就是可复用判定），后者改公开 `summary_of` |
| 9 | 防御性分支（分类树成环、`_node_of` 找不到刚写入的分类）无法构造 | 按规范加带理由的 `# pragma: no cover - ...`；其余分支全部补真实用例 |
| 10 | 改既有测试基线：权限码 126 → 127、动作码 32 → 33、种子 op 10 → 11 | 属本任务新增权限 / 动作 / 种子，基线同步并在注释写明来源 |
| 11 | 提交前完整预检仍报 2 项存量红灯 | `@bms/core` 类型检查失败（10_02 `form-query.spec.ts` 的 `sort`，本任务未触及 core）；`11_01` 测试记录缺「原型对照结论」（早前未推送提交遗留）。均属范围外，未改动；本任务改动集无界面源码 |
