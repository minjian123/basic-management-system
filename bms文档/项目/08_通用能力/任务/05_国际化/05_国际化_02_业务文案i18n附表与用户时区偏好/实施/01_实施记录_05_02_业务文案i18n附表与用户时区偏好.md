## 2. 实施过程

1. **基座助手**：先把 `load_i18n` 从「单语言精确匹配」改为「语言优先级序 + 大小写不敏感」，再补多文案列与连带清理；投影函数一律用「取列直赋值」而非 `if 值存在`，避免不可达分支拉低覆盖率。
2. **默认语言上下文**：`BaseLocaleRegistry.default_locale()` 在同步路径不能取 Request，改由 `locale_scope` 写 contextvar，`i18n_text.request_locale` / `derive_default_name` 读它；`request_locale` 去掉常量白名单（清单解析已在 `locale_scope` 完成）。
3. **存量接线**：菜单 / 字段 / 业务码 / 动作码仓储的 `list_i18n` 统一传 `locales=[请求语言, 默认语言]`；字典表源改双左连 + `coalesce` 三级。
4. **连带清理**：7 个删除路径在事务内「先附表、后主表」；`sys_module` 无删除入口故不涉及（设计已回写）。
5. **偏好端点**：schema（部分更新语义）→ service（归一 / 校验 / 生效值派生 / 单次 UPDATE）→ api（`/profile/preferences`，登录即可）；不在事务外读 ORM 属性（提交后即过期）。
6. **台账与护栏**：先落 `attachments.py`，再写脚本断言「模型 ↔ 台账 ↔ 文档」三方一致，随后补文档台账（脚本首跑即抓到 `sys_icon_i18n` / `sys_notice_i18n` 两处文档缺行）。
7. **覆盖率补齐**：按门禁口径采集（`BMS_COVERAGE_DATA` 绝对路径 + 项目插件）后查缺口，按缺口补用例并消除不可达分支，最终 100%。

## 4. 问题与处置

**问题 1：新端点 404（服务层测试怎么跑都失败）。**
根因是 **pytest rootdir**：在 `backend/` 下跑 `services/platform/tests/**` 时，`ApplicationFactory` 取到的是基座通用应用（只有 health / metrics 5 条路由），业务路由未挂载。处置：平台服务测试一律 `cd backend/services/platform` 再跑；该口径写进测试记录。

**问题 2：pydantic 不认 `ConcurrentStableDict` 配置字段。**
直接写 `Annotated[ConcurrentStableDict[str, str], CONTRACT_STABLE_DICT]` 报 `PydanticSchemaGenerationError`——`CONTRACT_STABLE_DICT` 是 default_factory 工厂，不是契约元数据。处置：改用 `Annotated[..., CONTRACT_COLLECTION]`（与既有 `allow_origins` 等同口径），实测可解析 TOML 子表。

**问题 3：`ParamError` 的 HTTP 状态是 200 而非 400。**
既有约定是「业务错误统一 HTTP 200 + body `code`」；我按 400 写断言导致用例失败。处置：断言改为 `status_code == 200` + `code == 10001`，设计文档同步回写。

**问题 4：`request_locale` 去掉常量白名单后，既有用例失败。**
`test_request_locale_falls_back_when_unsupported` 断言「不在 `SUPPORTED_LOCALES` 时回退默认语言」；运行期扩语言后该白名单会误判新语言。处置：语义改为「未设置 → 回退默认语言；已设置 → 原样采用（清单解析在 `locale_scope`）」，用例同步更新并注明 05_02 口径。

**问题 5：`sys_icon_i18n` / `sys_notice_i18n` 台账文档缺行。**
护栏首跑即发现（文档只提了 9 张表）。处置：在《30 国际化管理》补「i18n 附表登记」节，11 行全覆盖。

**问题 6：覆盖率报缺口集中在「投影函数」。**
`if 值 is not None`、`if bucket:` 这类防御分支在同构数据下不可达（助手只返回非空桶）。处置：改为「按槽位收集 + 直赋值」，消除不可达分支；另补「空白值跳过 / 多主表多列」用例覆盖剩余分支。

**问题 7：偏好用例偶发 44010。**
xdist 并发下语言清单缓存可能留陈旧快照。处置：fixture 内主动 `PUT /i18n/cache/invalidate` 再进用例（与 05_01 用例同口径），并串行持 `i18n-locale-message` 文件锁。
