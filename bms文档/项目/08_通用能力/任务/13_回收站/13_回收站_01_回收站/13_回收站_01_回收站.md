## 2. 任务内容 <a id="content"></a>

1. 按模块 / 表查看 `deleted_at` 非空数据（业务码 `recycle`）：首批纳管 12 张业务实体表（用户、角色、自定义图标、帮助分类 / 文章 / 反馈 / 包、工作台卡片 / 模板、表单布局 / 字段属性 / 自建字段），6 张多语言 / 锚点类子表随主表级联、不单独列出；模块接口给各表删除条数，列表单表分页 + 关键字 + 删除时间范围 + 详情展示列快照。
2. 恢复（清空 `deleted_at`）：单条恢复 + `Idempotency-Key`；唯一键冲突按 `(唯一字段, deleted_at)` 语义预检并返回冲突字段（95002），数据库约束兜底；主表恢复同事务级联恢复子表行；动作落操作日志与字段级审计（白名单表经 ORM 自动捕获，其余表显式留痕 `deleted_at`）。
3. 超期物理清理（01_02 定时任务，与归档清理衔接）：`[recycle]` 配保留期 / 批次 / 单轮上限；`purge_soft_deleted` 提交 `platform.recycle.purge` 作业，逐表分批物理删除超期软删数据；新增 `sys_recycle_log` 清理批次表，逐表记录条数 / 状态 / 耗时 / 保留期，可按表与状态查询。
4. 通用引擎与扩展：查询 / 恢复 / 清理逻辑落共享基座 `bms_core.recycle`，平台服务只做 HTTP 面与作业；其他服务 / 产品表后续复用同一引擎自挂路由，平台不跨库直写。
5. 配套：`[recycle]` 运行参数、错误码 95001~95004 与中英文案、回收站菜单 + 查询 / 恢复按钮种子、契约快照与前端类型重生成、数据库设计 33 节点与 `sys_recycle_log` 表文件。

## 3. 完成标准 <a id="accept"></a>

- 软删除数据可按模块 / 表查看：模块计数、单表分页、关键字与删除时间筛选、详情展示列均可用；子表不单独出现在列表。
- 恢复后数据回到业务列表；同名 / 同码等唯一冲突被拒并返回冲突字段（95002），不产生半套恢复；主表恢复时登记的子表行同事务恢复。
- 恢复动作可在操作日志与字段级审计中查到时序；非白名单表也有 `deleted_at` 留痕。
- 超过保留期的软删除数据被定时任务物理删除，逐表清理批次记录可查（条数 / 状态 / 耗时 / 保留期），失败可按作业重试且不重复删除。
- `(唯一字段, deleted_at)` 复合唯一索引口径不变，恢复冲突判定不按方言分叉。
- 新增 / 改动模块覆盖率 100%（行 + 分支）；契约快照与前端类型零漂移；菜单 / 按钮种子幂等可查。
