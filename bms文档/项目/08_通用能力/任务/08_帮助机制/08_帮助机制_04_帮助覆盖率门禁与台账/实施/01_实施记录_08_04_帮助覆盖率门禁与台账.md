## 3. 实施过程 <a id="process"></a>

1. **口径落地**：按拍板结果把「有权限码的动作」落为按钮（`sys_button` 1:1 权限码），「有权限码的菜单」落为「启用 + 有组件 + 挂表单 + 业务有权限码」的功能菜单；表单 / 字段 / 动作码兜底只作参考列。
2. **快照**：`load_help_coverage_snapshot` 一次读取启用且未软删的元数据，按权限码拼出按钮动作、按 `sys_menu_form` 拼出菜单业务码与按钮菜单路径；锚点复用 `list_help_anchors`。
3. **分组**：`sys_module` 的 `business_code → (product_key, module_key)` 优先；未登记时产品段取 `platform`、模块名取业务码（`platform/user`、`platform/role`…），避免平台动作全挤进「未登记」桶。
4. **确定性**：所有列表固定排序（动作先于菜单 → 产品 → 模块 → 键），JSON `sort_keys` + `indent=2`，浮点 `round(…, 4)`，`as_of` 显式入参；同一快照两次输出已实测逐字节一致。
5. **豁免**：文件式限期豁免（`kind` / `key` / `owner` / `reason` / `expires_at` / 可选 `product_key`），非法文件整次拒收；生效 / 过期 / 陈旧三类判定，过期计缺口、陈旧只告警。
6. **对账**：`covered + orphan = list_help_anchors` 的菜单 / 按钮锚点数，重复锚点置 `consistent=false`；强档下不一致与豁免后缺口同样阻断。
7. **命令行**：默认告警（退出 0），`--strict` 或 `BMS_HELP_COVERAGE_STRICT=1` 才在缺口 / 对账不一致时退出 1；参数、库、豁免 / 基线文件错误退出 2。
8. **接口**：`menu_form` 域复用基座引擎；产品 / 模块过滤影响摘要、分组与明细，`kind` 只过滤明细；`include_reference=false` 时参考统计置零。
9. **CI**：新增 `help-coverage` 作业，以临时 SQLite 跑 `seed_module --write` + `seed_menu` 后出 markdown 台账；缺口不阻断，强档留给 16_01 / 发布窗口。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 平台业务码不在 `sys_module`，严格按登记表分组会把平台侧全部动作挤进一个桶 | 与用户确认后改为「登记表优先、未登记以业务码兼作模块名（产品段 `platform`）」；平台台账按 `platform/user`、`platform/role`… 分组 |
| 2 | 同一权限码会出现在多个菜单的按钮上（`log:query`、`archive:query` 等） | 动作单元以按钮主键为准、`key` 仍为 `业务码:动作码`（按钮 1:1 权限码，同表单唯一），`menu_paths` 列出全部承载菜单，缺口可定位到页面 |
| 3 | 菜单可挂多个表单，业务归属不唯一 | 取业务码字典序最小者归组并标 `multi_business=true`，同一菜单只计一次，结果确定 |
| 4 | 端点在 `menu_form` 还是 `help` 域 | 菜单 / 按钮表归 `menu_form`，接口落该域避免跨域读表；引擎在基座供命令行与接口共用 |
| 5 | 接口权限码只有 `help:query` | 按概要 17 §5 补 `help:manage`（同时供 12_01 内容维护使用），种子幂等播种 |
| 6 | 豁免路径部署可变 | 新增 `[help_coverage].exemption_paths`；缺省文件不存在视为空，命令行显式路径缺失即报错 |
| 7 | 提交环前端类型 / 用例只能全仓判定，钩子无法透传 `--allow-full-steps` | 按任务约定先手工跑完整预检（35 项全通过），提交时用 `git commit --no-verify`（推送环仍会完整复判） |
| 8 | 既有 `core/config.py`、`seed/menu.py` 体量大，模块级 100% 不在提交环采集范围 | 提交环已判改动行；新引擎 / 快照 / 命令行模块本地实测 100%（行 + 分支），平台域与既有大模块的模块级 100% 交推送环 |
