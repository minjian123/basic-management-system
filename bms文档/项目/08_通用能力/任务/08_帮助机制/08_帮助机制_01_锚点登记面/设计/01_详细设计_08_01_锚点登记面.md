## 1. 概述 <a id="overview"></a>

- **目标**：把 `help_key` 变成菜单元数据上的**正式、可装载、可校验、可追溯**字段，为 08_02 的五级解析与 08_04 的覆盖率台账提供唯一事实源。
  1. **五表加列**：`sys_menu` / `sys_form` / `sys_field` / `sys_action` 各增 `help_key`（可空），并按本次拍板**额外给 `sys_button` 加列**——动作级真实锚点落在「表单 × 权限码」的按钮行，`sys_action` 只承载全局动词兜底。
  2. **格式与唯一**：五段冒号式 `{product}:{module}:{form}:{field}:{action}`，按节点类型限定非空段位置；跨五表全局唯一；空值一律 `NULL`，空串归一为 `NULL`。
  3. **写入口**：五类元数据的创建/更新请求可选带 `help_key`，服务层统一校验、同事务落库；接口不新增端点、不新增权限码。
  4. **装载面**：以现有种子声明为装载入口（平台 `seed_menu` + 产品 `[[seeds]]`），提供批量声明与 upsert 助手：全量校验 → 按自然键定位 → 仅差异更新；不存在「声明即清空」语义。
  5. **下发**：维护清单（菜单树 / 表单 / 按钮 / 字段 / 动作码）返回 `help_key`；动态菜单 `my_menus` 与五级解析归 08_02，本任务不下发。
  6. **审计**：仅 `help_key` 实际变化时显式留痕（`AuditCapturer.capture` → 暂存 → 审计中间件落 `sys_data_audit_log`）；四表不整表纳入 ORM 捕获白名单。
  7. **不参与鉴权**：权限计算链路不读该字段，以回归用例证明鉴权结果与改造前一致。
- **依据**：需求 [10-1](../../../../需求/10_需求_锚点登记面.md#r10-1)；《[架构设计 · 帮助中心](../../../../../../设计/架构设计/28_架构设计_子系统_帮助中心.md)》§3.4 / §4.2、《[概要设计 · 帮助中心](../../../../../../设计/概要设计/17_概要设计_帮助中心.md)》§2.1 / §4 / §7、《[帮助包规范](../../../../../../规范/帮助包规范.md)》§5 / §6、《[数据库开发规范](../../../../../../规范/数据库开发规范.md)》§2 / §3 / §5。
- **范围（本任务）**：
  - `bms_core`：`help_key` 格式与形状校验（新 `bms_core/help/anchors.py`）、跨表唯一性读助手（新 `bms_core/repositories/help_anchor.py`）、种子声明 upsert 助手（新 `bms_core/tenant/seed/help_anchor.py`）、五表模型加列、错误码 `40211` 与中英文案。
  - `platform` 服务：`menu_form` 域的菜单 / 表单 / 按钮 / 字段请求与响应、服务写路径校验与审计；`permission_meta` 域的动作码请求与响应、服务写路径校验与审计；`wiring.py` 注入审计捕获器。
  - 数据设计：五张表文件加字段与变更记录；契约快照与前端类型重建。
  - 规范回写：《帮助包规范》§5 / §6 示例与锚点引用规则统一到本任务定稿格式；《概要设计 · 菜单管理》§7 补 `40211`。
- **不含（归口见 §9）**：五级解析链 / 未命中降级 / 按钮显隐 / `GET /api/v1/help/context`（08_02）；产品帮助包装载（08_03）；覆盖率台账与 CI 门禁（08_04）；前端锚点编辑框与帮助按钮（阶段十五 09_01）；数据库方言特性实测（无可空列以外的方言差异）；装载期（无请求上下文）的字段级审计落库。

| --- | --- | --- | --- |
| 1 | 动作级锚点落点 | 四表 + `sys_button.help_key`；`sys_action.help_key` 作全局动词兜底 | 帮助包规范的动作锚点示例是 `user:create`（权限码）；按钮 1:1 权限码，「有权限码的动作 = 按钮」，解析链与覆盖率口径自洽 |
| 2 | 字符串格式 | 五段冒号式 `{product}:{module}:{form}:{field}:{action}`，本级段非空、右侧留空但保留分隔符 | 按需求原文；节点类型可由段位置直接判定，解析不需要额外类型字段 |
| 3 | 产品段 | 平台 `platform`、产品各自 `product_key`；装载校验声明方一致 | 与 `deploy/registry/<仓>.toml` 的 `product_key`、权限码产品维度同口径 |
| 4 | 唯一性 | 跨五表全局唯一；代码 + 装载校验；不加 DB 唯一约束 | 保证一篇帮助的锚点只解析到一条元数据；规避达梦「复合唯一中 NULL 视为相等」 |
| 5 | 空值 | `NULL` = 未登记；空串 / 纯空白归一 `NULL`；装载声明未写 = 不修改 | 与需求「老数据 NULL」一致，保留「不写 ≠ 清空」的区分 |

## 5. 领域设计 <a id="design"></a>

### 5.1 `help_key` 格式与语义 <a id="format"></a>

**段式**（固定 5 段、4 个冒号分隔）：

```text
{product}:{module}:{form}:{field}:{action}
```

- **字符集**：每个非空段限 `[a-z][a-z0-9_]*`（小写字母开头，仅小写字母 / 数字 / 下划线），单段 ≤64 字符；整串 ≤255 字符（与列宽一致）。
- **空段**：允许空（保留分隔符）；空串或纯空白整串归一为 `NULL`（不落 `''`）。
- **首段产品**：平台 `platform`，产品取 `sys_product` / 清单 `product_key`（`biz` / `mdm` / `cw`）；装载声明时校验首段等于声明方 `product_key`，接口写入只做字符集校验（平台管理员可维护各产品元数据）。
- **节点类型由非空段位置判定**（`HelpAnchorKind`）：

| 节点 | 表 | 非空段位置 | 形态示例 | 说明 |
| --- | --- | --- | --- | --- |
| 菜单（模块级） | `sys_menu` | 1、2 | `platform:platform:::` | 菜单是模块入口，承载模块级锚点 |
| 表单 | `sys_form` | 1、2、3 | `platform:platform:user::` | 表单级帮助 |
| 字段 | `sys_field` | 1、2、3、4 | `platform:platform:user:username:` | 字段级帮助（解析链最高优先级） |
| 按钮（动作级） | `sys_button` | 1、2、3、5 | `platform:platform:user::create` | 按钮 1:1 权限码，动作级真实锚点 |
| 动作码（全局动词兜底） | `sys_action` | 1、5（首段须 `platform`） | `platform::::create` | 全库通用「新建」帮助；被按钮级覆盖时按解析链优先按钮 |

> 说明：动作段的业务语义是「按钮所属表单 + 权限码动作」；`sys_action` 只有全局一条，故不携带模块 / 表单段。

**唯一性**：同一 `help_key` 在五表之间**全局唯一**（含软删除行不参与判定，删除后释放）。判定分两处：

1. **写接口**：保存前查五表（排除自身行）；
2. **装载声明**：批量内查重 + 查库；跨批期间的并发写入由写接口的唯一性校验兜底（装载与人工编辑并发属运维窗口，冲突即报错，不静默覆盖）。

> 不加数据库唯一约束：五表分别建 `(help_key, deleted_at)` 唯一键会因**达梦把复合唯一中的 NULL 视同相等**而让多条未登记行互撞（既有已知差异），故唯一性由代码与装载校验承担；08_04 台账复用同一读助手。

**空值**：`NULL` = 未登记，合法且不报错；未登记不影响菜单与表单渲染；存量数据一律保持 `NULL`，不回填。

### 5.2 数据模型 <a id="tables"></a>

字段唯一事实源为表文件，本设计不复制完整字段清单：

- [sys_menu](../../../../../../设计/数据库设计/数据表设计/sys_menu.md)
- [sys_form](../../../../../../设计/数据库设计/数据表设计/sys_form.md)
- [sys_field](../../../../../../设计/数据库设计/数据表设计/sys_field.md)
- [sys_button](../../../../../../设计/数据库设计/数据表设计/sys_button.md)
- [sys_action](../../../../../../设计/数据库设计/数据表设计/sys_action.md)

五表统一追加：

| 字段 | 类型 | 可空 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `help_key` | VARCHAR(255) | 是 | 无默认；`NULL` = 未登记 | 帮助锚点（段式标识；格式与唯一性由应用校验，见 §5.1） |

落地顺序（强制）：表文件（含变更记录）→ ORM 模型 → 启动期幂等建表 / `ops.init_schema` → 回写表文件状态。可空列在 SQLite / MySQL / PostgreSQL / 达梦无方言差异，开发 / 测试库删库重建，不涉及 ALTER，不新增方言特性条目。

### 5.3 校验与错误码 <a id="validate"></a>

**校验入口唯一**：`bms_core/help/anchors.py::validate_help_key`，写接口与装载助手共用；不在 API / 仓储各写一份。

```text
输入 raw + kind + declaring_product?
→ normalize（trim；空 → None）
→ 段数必须 5
→ 各非空段字符集 / 单段长度
→ 整串长度 ≤255
→ 按 kind 校验非空段位置（§5.1 表）
→ declaring_product 非空时校验首段 == 声明方（或声明方为 platform 时首段 platform）
→ 返回归一值（str | None）
```

失败抛 `MenuHelpKeyInvalidError`（新错误码 `40211`，HTTP 400），消息带具体违规段与原因；一批声明收集全部违规后一次报出。

| 错误码 | 名称 | HTTP | 场景 |
| --- | --- | --- | --- |
| 40211 | `MENU_HELP_KEY_INVALID` | 400 | `help_key` 段数 / 字符集 / 长度 / 非空段位置 / 产品段不符；跨表重复；装载声明的目标元数据不存在 |

### 5.4 写入口与下发 <a id="write"></a>

**请求**（均 `help_key: str | None = None`，`max_length=255`；语义为「整体替换」，`null` 表示清空）：

| 契约 | 变更 |
| --- | --- |
| `MenuCreateRequest` / `MenuUpdateRequest` | 加可选 `help_key` |
| `FormCreateRequest` / `FormUpdateRequest` | 加可选 `help_key` |
| `ButtonCreateRequest` / `ButtonUpdateRequest` | 加可选 `help_key` |
| `FieldCreateRequest` / `FieldUpdateRequest` | 加可选 `help_key` |
| `ActionCreateRequest` / `ActionUpdateRequest` | 加可选 `help_key` |

**响应**（维护清单；新增字段可空、向后兼容）：

| 契约 | 变更 |
| --- | --- |
| `MenuItem` / `FormItem` / `ButtonItem` / `FieldItem` / `ActionItem` | 加 `help_key: str | None` |

**服务写路径**（五类一致）：

```text
normalize + validate（kind 对应）
→ 若非 None：查五表唯一（排除自身）→ 冲突抛 40211
→ 仓储 create/update 写入 help_key
→ 若为更新且 old != new：audit.capture(table, id, [FieldChange("help_key", old, new)])（失败只告警）
→ 既有缓存失效 / 事件发布逻辑不变
```

**不新增端点、不新增权限码**：菜单 / 表单 / 按钮 / 字段沿用 `menu:create` / `menu:update`，动作码沿用 `action:manage`。

**不下发**：`my_menus`（动态菜单）与 `GET /api/v1/help/context` 不在本任务改；前端类型重建只为保持契约一致。

### 5.5 装载面（种子声明 + upsert） <a id="load"></a>

**声明载体**：`bms_core/tenant/seed/help_anchor.py`

- `HelpAnchorDeclaration`（不可变值对象）：`kind` / `help_key` / 自然键字段 / `declaring_product`。
  - 菜单：`menu_path`
  - 表单：`business_code`
  - 字段：`business_code` + `field_key`
  - 按钮：`business_code` + `action_code`（即权限码右半）
  - 动作码：`action_code`
- `apply_help_anchor_declarations(session, declarations) -> HelpAnchorApplyResult`：

```text
1. 逐条 normalize + validate（kind 形状 + declaring_product 首段）；收集全部违规
2. 批内 help_key 重复 → 违规
3. 按自然键定位目标行（未软删）；缺失 → 违规
4. 违规非空 → 抛 MenuHelpKeyInvalidError（列全部）；一条不写
5. 逐条：目标为 NULL 或与声明不同 → 写 help_key；相同 → 跳过
6. 返回（created, updated, unchanged）计数
```

**平台种子接入**：`seed/menu.py` 增可选声明表（缺省空）：

```python
MENU_HELP_KEYS: ConcurrentStableDict[str, str]        # 菜单 path → help_key
FORM_HELP_KEYS: ConcurrentStableDict[str, str]        # 业务码 → help_key
FIELD_HELP_KEYS: ConcurrentStableDict[tuple[str, str], str]  # (业务码, field_key) → help_key
BUTTON_HELP_KEYS: ConcurrentStableDict[tuple[str, str], str] # (业务码, action_code) → help_key
ACTION_HELP_KEYS: ConcurrentStableDict[str, str]      # 动作码 → help_key
```

种子写入完成后，把非空声明转成 `HelpAnchorDeclaration` 并调用 upsert；**声明缺省 = 不修改**，不提供「清空」。产品仓在自己的 `[[seeds]]` 入口里调用同一助手（声明方 `product_key` 取自本产品清单），不在产品侧另写一套。

**装载期审计**：种子进程无请求上下文，暂存事件不会被中间件排空，故装载期变更**不落字段级审计**，只记 WARN 日志并在实施记录登记；人工经接口变更仍正常留痕（见 §5.6）。

### 5.6 审计留痕 <a id="audit"></a>

- 触发条件：**更新路径**上 `help_key` 旧值 ≠ 新值（含设置为 `NULL`）；创建路径不单独留痕（属元数据创建，由操作日志覆盖「谁建了这行」）。
- 方式：服务层调注入的 `AuditCapturer.capture(table=..., model_id=..., changes=[FieldChange(field="help_key", old=..., new=...)], actor=...)`；`DbAuditCapturer` 转 `sys.data.changed` 事件投入请求级暂存，由审计中间件收尾入 `sys_outbox` → `audit-chain` → `sys_data_audit_log_{yyyyMM}`。
- 失败分档：留痕失败只记 WARN `help_key_audit_capture_failed`，**不反噬业务写**（与 i18n 多语言维护同口径）。
- 脱敏：`help_key` 是元数据标识，非敏感数据，按通用脱敏口径原样入账（不命中敏感名单）。
- 四表 / 五表**不加入** `AUDITED_TABLES`：避免租户开通种子为每行每列产生审计洪水；ORM 捕获白名单保持 06_02 现状。

### 5.7 鉴权边界 <a id="auth"></a>

- 权限计算引擎（主体链 / 角色授权 / 字段权限 / 动态菜单过滤）**不读** `help_key`；本任务只在元数据模型与维护接口追加字段。
- 回归方式：既有 `permission` / `my_menu` 用例全跑；新增一例「同一租户在给菜单 / 表单 / 字段 / 按钮设置 `help_key` 前后，`GET /api/v1/menus/my` 的 `permissions` 与 `visible` / `editable` 完全一致」。

## 6. 接口契约变化 <a id="api"></a>

路径不变，仅请求 / 响应字段变化；错误码 `40211`。示例：

```json
// PUT /api/v1/menus/{id} 请求（节选）
{
  "parent_id": "0",
  "path": "/sys/users",
  "i18n": {"zh-CN": "用户管理"},
  "help_key": "platform:platform:::"
}

// GET /api/v1/menus 响应（节选）
{
  "code": 0,
  "data": {
    "items": [
      {
        "id": "123",
        "path": "/sys/users",
        "help_key": "platform:platform:::"
      }
    ]
  }
}
```

格式违规返回：

```json
{"code": 40211, "message": "help_key 格式非法：段数须为 5", "data": null}
```

## 7. 失败分支与边界 <a id="failures"></a>

| 场景 | 处置 | 结果 |
| --- | --- | --- |
| 请求未带 `help_key` | 视为清空（整体替换语义） | 更新后为 `NULL` |
| 请求传空串 / 纯空白 | 归一为 `NULL` | 落库 `NULL` |
| 段数不足 / 多段 | `40211`，消息指明段数 | 不写库 |
| 非空段含大写 / 空格 / 点 / 连字符 | `40211`，消息指明段与字符集 | 不写库 |
| 单段 >64 或整串 >255 | `40211` | 不写库 |
| 非空段位置与节点类型不符 | `40211`（如菜单声明成字段形状） | 不写库 |
| 装载声明首段与声明方产品不符 | `40211`，列全部冲突项 | 整批不写 |
| 与其它表 / 同行已有值重复 | `40211`，消息带冲突表与记录 | 不写库 |
| 装载声明目标元数据不存在 | `40211`，列全部缺失目标 | 整批不写 |
| 批内同一 `help_key` 重复声明 | `40211`，列重复键 | 整批不写 |
| 装载声明与库中值相同 | 跳过（unchanged） | 不写库 |
| 装载声明未写 `help_key` | 不修改库值 | 保持原值 |
| 审计捕获失败 | WARN 日志，业务照常提交 | 业务成功、缺审计（可观测） |
| 老数据 `help_key=NULL` | 合法，不报错、不渲染影响 | 菜单 / 表单正常展示 |
| 权限计算链路 | 不读该字段 | 鉴权结果与改造前一致 |
