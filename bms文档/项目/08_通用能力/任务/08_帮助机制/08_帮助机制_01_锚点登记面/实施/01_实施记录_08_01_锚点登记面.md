## 2. 实施内容 <a id="content"></a>

### 2.1 数据库与模型

- 五张元数据表加 `help_key`（`VARCHAR(255)` 可空、无默认、存量保持 `NULL`）：`sys_menu` / `sys_form` / `sys_field` / `sys_action` / `sys_button`。
- 先改表文件（含变更记录 v4 ~ v6）→ 再改 ORM 模型（`bms_core/models/platform/{menu_form,permission_meta}.py`）→ 启动期幂等建表；未走迁移脚本（历史脚本已清空，开发 / 测试库删库重建）。
- 未加数据库唯一约束：达梦把复合唯一中的 `NULL` 视同相等，多行未登记会互撞；唯一性由应用层保证。

### 2.2 基座

- 新 `bms_core/help/anchors.py`：五段冒号式格式、按节点类型的非空段形状、字符集（`[a-z][a-z0-9_]*`）、单段 / 整串长度、空串归一 `NULL`、装载声明产品段校验；`__init__.py` 统一出口。
- 新 `bms_core/repositories/help_anchor.py`：跨五表唯一性探测（可排除自身）与全量锚点列示（供 08_04 复用）。
- 新 `bms_core/tenant/seed/help_anchor.py`：`HelpAnchorDeclaration` / `HelpAnchorApplyResult` + 批量校验（格式 / 形状 / 产品段 / 批内重复 / 目标存在 / 跨表唯一）+ 仅差异 upsert（整批原子：任一违规零写入）。
- 错误码 `40211 MENU_HELP_KEY_INVALID`（HTTP 400）+ `MenuHelpKeyInvalidError` + 中英文案。

### 2.3 platform 服务

- `menu_form` 域：菜单 / 表单 / 按钮 / 字段的创建、更新请求带可选 `help_key`；维护清单响应返回该字段；写路径统一「归一 + 格式 / 形状校验 + 跨表唯一 + 落库 + 差异留痕」。
- `permission_meta` 域：动作码创建 / 更新同上（全局动词兜底形态 `platform::::{action}`）。
- 审计：仅 `help_key` 实际变化时调 `AuditCapturer.capture`（暂存 → 审计中间件落 `sys_data_audit_log`）；失败只记 WARN，不反噬业务写；四表不加入 ORM 整表捕获白名单。
- 缓存 / 事件 / 权限链路未改；`my_menus` 不下发 `help_key`（归 08_02）。
- `wiring.py` 注入审计捕获器；`get_audit_capturer` 依赖在两域 API 使用。

### 2.4 种子装载

- `bms_core/tenant/seed/menu.py` 增五张可选声明表（`MENU_HELP_KEYS` / `FORM_HELP_KEYS` / `FIELD_HELP_KEYS` / `BUTTON_HELP_KEYS` / `ACTION_HELP_KEYS`，缺省空，不改变现有播种结果）与 `_apply_help_keys`；种子写入收尾统一 upsert。
- 产品仓在自己的 `[[seeds]]` 入口调用同一 `apply_help_anchor_declarations`，不在产品侧另写一套。

### 2.5 契约与前端类型

- 重建 `deploy/contracts/platform.json` 与 `frontend/packages/api_types/src/platform.ts`；`ops.contract_snapshot check` 零漂移、`pnpm api_types:gen:check` 零漂移。

### 2.6 文档回写

- 五张表文件（字段 + 变更记录）、《概要设计 · 菜单管理》§7（`40211`）、《架构设计 · 帮助中心》§3.4（锚点形状与按钮级落点）、《帮助包规范》§5 / §6（示例与引用规则统一）。
