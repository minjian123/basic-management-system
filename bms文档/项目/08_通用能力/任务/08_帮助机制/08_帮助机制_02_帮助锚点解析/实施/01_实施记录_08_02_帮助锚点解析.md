## 2. 实施内容 <a id="content"></a>

### 2.1 基座：内容侧端口与五级链

- 新 `bms_core/help/content.py`：`HelpLevel`（field / action / form / module / global）、`HelpAnchorCandidate`、`HelpArticle` / `HelpArticleSummary` / `HelpCategory`、`HelpContentQuery` / `HelpContentResult`（`matched` 只看文章）、`BaseHelpContentResolver` 端口与依赖注入提供者 `get_help_content_resolver`。
- 新 `bms_core/help/null.py`：`NullHelpContentResolver`（恒定未命中、不查库、无副作用）。
- 新 `bms_core/help/context.py`：`HelpContextInput`（入参归一）、`build_help_candidates`（五级顺序、去重、末项全局）、`resolve_help_context`（把有序候选交给内容侧）。
- 新 `bms_core/help/index.py`：锚点索引值对象（菜单 / 表单 / 字段 / 按钮 / 动作码）、缓存键 `bms:global:help:anchors:{version}`、编码 / 解码与缓存装载（脏载荷返回 `None` 并按未命中重建）。
- `bms_core/repositories/help_anchor.py`：新增 `load_help_anchor_index`（只取启用且未软删行，按业务码 / 字段键 / 权限码动作归集；存量非法菜单锚点跳过并告警）。
- `bms_core/core/config.py` 加 `help_content` 能力域配置；`core/assembly.py` 登记缺省实现模块与装配接线；`backend/config.toml` 加 `[help_content]` 段（provider 缺省空 = 空实现）。

### 2.2 platform 服务：解析接口与动态菜单下发

- `menu_form` 域新增 `schemas/help.py`（`HelpContextResponse` 及文章 / 分类摘要）、`services/help_context.py`（索引缓存 → 候选链 → 内容侧 → 响应映射）、`api/help.py`（`GET /api/v1/help/context`，仅 `require_auth`）。
- `services/metadata_cache.py` 抽出 `menu_cache_ttl`（菜单快照与锚点索引共用 `menu.tree_cache_ttl`）；`api/menu.py` 的 `_tree_ttl` 改为委托，行为不变。
- `my_menus` 四级下发：快照（菜单 / 表单 / 按钮 / 字段）与 `MyMenu*` 契约各加可空 `help_key`；快照字段带缺省 `None`，兼容升级前的旧缓存载荷。
- `wiring.py` 加 `build_help_context_service`；`api/router.py` 挂载 `/help` 路由。

### 2.3 契约与前端类型

- 重建 `deploy/contracts/platform.json` 与 `frontend/packages/api_types/src/platform.ts`；`ops.contract_snapshot check` 与 `pnpm api_types:gen:check` 均零漂移。

### 2.4 文档回写

- 《架构设计 · 帮助中心》§4.2 命中判据与内容侧边界（语义层）；《概要设计 · 帮助中心》§5 解析接口说明；《帮助包规范》§6 补 `global` 说明、§10 最小示例改五段式锚点；《后端基类清单》登记 `help_content` 能力域。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 文章 / 分类表尚未建（归 08_03 / 12_01），本任务无法直接查库返回文章 | 开工前确认：新增 `help_content` 能力域端口 + 空实现；真实内容随 12_01 接入，解析链与接口不改 |
| 2 | `sys_form` 无 `form_key` 列；`sys_business.form_key` 是「多表联合判别列」而非表单键 | 按 08_01 锚点示例与种子声明口径，表单自然键取**业务码** `sys_business.code` |
| 3 | 动作入参可能是动作码（`create`）或完整权限码（`user:create`） | 两种都收：带前缀时按前缀定位按钮；前缀与 `form_key` 不一致则不产生按钮候选，仍落动作码兜底 |
| 4 | 模块级无自然键列 | 按菜单锚点第 2 段匹配 `module_key`；多产品同名段由可选 `product_key` 消歧（缺省平台优先） |
| 5 | 缓存载荷手写逐字段校验：根节点重复校验一处不可达，另一处分支在改动行门禁上漏计 | 改由内部契约模型（`BaseSchema`）承载结构校验：脏缓存 / 旧结构统一返回 `None` 并重建，消除不可达分支 |
| 6 | 08_01 用例断言「`my_menus` 不含 `help_key`」 | 本任务起动态菜单下发该字段，删除该负向断言（覆盖改由 `test_my_menus_delivers_help_keys` 承担）；权限 / 可见性断言不变 |
| 7 | 首轮改动行门禁报 `help_anchor.py` 权限失联分支未执行 | 用例补「权限码挂失联业务码 / 动作码」两条直插行，覆盖 `continue` 分支 |
| 8 | 测试编码用 `ns.code()` 生成含连字符的业务码，与锚点段字符集冲突 | 用例统一改为 `{ns.prefix}_{后缀}`（08_01 同口径）；同时在用例里核对按钮锚点五段形状（第 4 段留空） |
