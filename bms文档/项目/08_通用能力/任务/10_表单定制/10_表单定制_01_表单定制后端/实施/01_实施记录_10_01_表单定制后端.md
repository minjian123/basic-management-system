## 2. 关键实现说明 <a id="impl"></a>

### 2.1 三级解析与权限优先 <a id="resolve"></a>

- **层级命中**：`role` → `tenant` → `platform` → 空回退；角色层按 `role_type` 内置优先级（`platform_admin > system > security > audit > custom`）+ `role_id` 升序取首个**非空**布局（空配置不锁死链路）。
- **字段属性同层同源**：选了哪层布局就用哪层属性（`sys_form_field_attr` 与 `sys_form_layout` 共用 `(form_code, scope, role_id)`）。
- **权限优先**：`visible=false` 字段从字段清单与**全部布局引用**（分区 / 分组 / 查询区 / 明细列 / 字典高级查询）一并剔除；`editable=false` 保留并标 `permissions`，服务端跳过其必填校验。

### 2.2 动态 DDL <a id="ddl"></a>

- **不进建表链**：`ext_*` 物理列由运行期 DDL 执行器加列；元数据在 `sys_field_ext`（`pending` / `active` / `failed`）。
- **参数化编译**：`AddColumn(table, Column(name, type_obj, comment=...)).compile(dialect)`，全程不拼字符串；达梦 `VARCHAR2(n CHAR)` 等方言差异由 SQLAlchemy 承担。
- **标识符白名单**：`field_key` / `column_name` / `table_name` 三重正则 + 保留字拒收，非法形态在**登记阶段**抛 `10001`。
- **单租户串行**：`build_lock_key(tenant, "form-ddl:{table}")`，TTL 30s / 等待 5s；取不到锁 `10004`（可重试）。
- **停用不删列 / 重建复用列**：`status=disabled` 不生成 `DROP COLUMN`；同名 `column_name` 的停用字段可恢复复用。

### 2.3 动态校验 <a id="validate"></a>

- 能力域 `BaseFormValidator`（基座）+ `LocalFormValidator`（真实实现，服务侧）+ `NullFormValidator`（占位恒通过）。
- 规则：`type` → `required` → `length` / `range` / `pattern` / `options`；失败项 `{field_key, rule}`，文案由前端按 `rule` 取词。
- **无配置即放行**：该表单无任何布局与属性时直接通过（既有接口行为不变）。

### 2.4 导入模板联动 <a id="import"></a>

- `BaseImportDefinition` 新增异步钩子 `columns_for(session)`，默认返回静态 `columns`（既有定义零改动）。
- 编排三处（内联 / 异步作业 / 模板下载）统一改调钩子；`users` 定义覆写为按 `user` 表单布局派生。
- 派生规则：布局字段序在前 → 自建 `active` 字段按布局位置插入 → 布局未引用的基线列保序追加（不丢列）。
