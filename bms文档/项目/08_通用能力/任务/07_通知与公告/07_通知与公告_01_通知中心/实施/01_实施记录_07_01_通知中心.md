## 3. 关键实现说明 <a id="impl"></a>

### 3.1 事件生成 <a id="event"></a>

- 新增 `notification.requested` 平台事件契约（`1.0.0`）：`user_id` / `title` / `type` 必填，`content` / `biz_type` / `biz_id` / `email` / `phone` 可选。
- `bms_core/notification/request.py` 提供 `NotificationRequest`、`build_requested_envelope`、`enqueue_notification_request`；生产方与业务写同事务入发件箱。
- 通知组 `notification-inbox` 订阅该事件，解析租户 → 读偏好 → 落库 → 发布 `notification.sent` → 推送。

### 3.2 通知中心读面 <a id="center"></a>

- `DatabaseNotificationCenter`（插件名 `db`）零参构造、懒建引擎注册表；每次调用按当前租户上下文开会话，写操作自开事务。
- 仓储查询强制 `user_id = 当前用户`；列表支持 `keyword`（标题）/ `type` / `is_read` / 分页，默认 `created_at DESC, id DESC`。
- 详情查看即已读；不存在 `70101`、他人 `70102`；删除他人 `70106`；批量已读空 / 超 500 → `70103`；跨用户 id 批量已读静默忽略。
- 未读数直接 COUNT，不加缓存。

### 3.3 渠道偏好与免打扰 <a id="preference"></a>

- `SqlPreferenceStore`（`preference` 插件 `sql`）：当前用户 get / set / reset；键前缀白名单 `ui` / `list` / `notify` / `dashboard` / `wizard`；单键 64KB、单用户 200 键；`notify.channels` / `notify.dnd` 结构校验。
- 平台内部端点 `POST /api/v1/platform/internal/preferences/resolve`（`require_service("notification")`）按用户返回偏好值 + 时区。
- `notification_preference` 能力域：`null` 全渠道开启；`http` 经 service_client 读取，失败回落默认。
- 免打扰按用户时区判定，跨午夜支持；命中只跳过实时推送，站内信仍落库。

### 3.4 导出完成通知 <a id="export"></a>

- `ExportExecuteJob` 成功后读取 `payload.actor`（提交人）与 `sys_user.locale`，按中 / 英文案构造 `NotificationRequest`，`type=import`、`biz_type=export`、`biz_id=作业主键`。
- 通知入队失败只告警，不改变导出成功结果。
- 无提交人（`actor` 为空）不发。
