## 1. 业务域说明 <a id="intro"></a>

本域只定**异步链路的量化口径**：审计与日志是「分区有序 + 按月分表」，如果主链路被副作用拖住、分片表没提前创建、积压没有阈值，功能齐全也会在第一次高峰崩掉。这一条不新增功能，只给数字与验证方法。

- **依据**：平台《架构设计 · 事件总线》§4「生产一致性」、§6「幂等与重试」；《架构设计 · 任务调度》§5「内置任务清单」；《架构设计 · 审计哈希链》。
- **前置**：需求 `03-1`（事件总线）、`03-2`（任务调度）、`05-1` / `05-2`（日志与审计）。

## 2. 需求 11-1：异步链路容量与延迟口径 <a id="r11-1"></a>

优先级：3（中）

**背景与动机**：审计、操作日志、登录日志全部改成异步落库之后，「快了多少」「会不会积压」「跨月会不会写失败」都没有口径，验收只能靠感觉。等出问题再回头量，代价远高于现在写下四个数字。

**内容**：

1. **主链路不被阻塞**：写接口的响应不等待异步副作用（审计 / 日志 / 通知）落库；有 / 无副作用两条路径的 P99 延迟差异不超过 **5%**。
2. **审计链消费延迟**：同租户内事件从投递到落入审计表，**P95 ≤ 5 秒**（分区键 = 租户，保证链序）。
3. **写入吞吐基线**：单租户日志写入不低于 **500 条/秒**（基准数据集可调，压测按此口径出数）。
4. **分片表提前量**：下月分片表在**当月 25 日前**创建（跨月 0 失败），由 `03-2` 的内置任务执行。
5. **积压与死信**：Outbox 待投递条数超阈值（默认 1 万 / 租户）告警；死信进库后 **24 小时内**必须有人处理，超时再告警。
6. **压测方法**：固定数据集（单租户 N 万条）+ 固定并发 + 采集四类指标；报告给出实测值与环境（库 / 机器规格），不只给结论。

**完成标准**：压测报告给出上述四项实测值并与目标对比（达标 / 未达标 + 原因）；主链路延迟差异实测 ≤5%；跨月切换实测 0 失败（模拟跨月）；积压阈值告警可触发；死信超时告警可触发；所有指标可在监控面板上查到（不只存在于报告里）。

**参考文档**：平台《架构设计 · 事件总线》§4 / §6；《架构设计 · 任务调度》§5；《[测试规范](../../../规范/测试规范.md)》「性能测试」节。
