## 1. 域说明 <a id="intro"></a>

本业务域是**非功能口径**：把「异步链路不能拖慢主链路」与「审计链能扛住写入、消费不积压、分片提前就绪」落成可采集、可告警、可复现的指标与压测方法，而不是一句「性能要好」。

- **依据**：《[架构设计 · 事件总线](../../../设计/架构设计/16_架构设计_子系统_事件总线.md)》§4 / §5 / §6；《[架构设计 · 任务调度](../../../设计/架构设计/17_架构设计_子系统_任务调度.md)》§5；《[架构设计 · 审计哈希链](../../../设计/架构设计/19_架构设计_子系统_审计哈希链.md)》§3~§5；《[架构设计 · 可观测性](../../../设计/架构设计/27_架构设计_子系统_可观测性.md)》「指标采集」；《[部署发布规范](../../../规范/部署发布规范.md)》§11「告警」。
- **前置**：异步底座（01_01 / 01_02 / 01_03）、日志与审计（06_01 / 06_02）、归档（14_01）。
- **不含**：前端容量页面、生产环境容量规划与扩容采购、具体优化实现（链尾缓存 / 批量追加等另立任务）。

## 2. 需求 11-1：异步链路容量与延迟口径 <a id="r11-1"></a>

优先级：3（中）

**背景与动机**：审计、日志、通知等副作用已改走事件与异步作业，但「响应到底有没有变慢」「审计链消费会不会积压」「写入能不能扛住」「分片表会不会跨月才建」此前都没有数字。没有可采集指标与可复现压测，容量问题只能在生产暴露；没有明确阈值，告警也无法判断「正常抖动」与「真故障」。本需求把四类口径固定下来，作为阶段验收与后续扩容决策的依据。

**内容**（《[架构设计 · 事件总线](../../../设计/架构设计/16_架构设计_子系统_事件总线.md)》§4~§6、《[架构设计 · 可观测性](../../../设计/架构设计/27_架构设计_子系统_可观测性.md)》「指标采集」、《[部署发布规范](../../../规范/部署发布规范.md)》§11）：

1. **指标与告警**：按基座指标体系登记并真实发射——审计链写入计数 / 消费时延、链完整度 / 断裂、次月分片就绪、发件箱积压（带库键）、死信待处置数与最老时长；告警规则至少覆盖 Outbox 积压 1 万/租户、审计链消费 P95 超 5 秒、链断裂、次月分片 25 日后未就绪、死信 24 小时未处置；规则须有可执行的规则单测。
2. **主链路口径（不阻塞主链路）**：同一端点、同一请求体、同一并发与请求数，只切审计开关三档（全关 / 仅操作日志 / 全开）；判据 `P99(全开) / P99(全关) - 1 ≤ 5%`。操作日志在响应体发送后发射，客户端时延天然不含该段；字段级审计同事务成本单列，不计入「异步副作用」结论。
3. **审计链消费口径**：事件 `occurred_at` → 审计分片落库完成的端到端 P95 ≤ 5 秒。无 broker / 无消费组时只能测「消费侧处理段」，须在报告中明确标注限定，不得把处理段当端到端结论。
4. **单租户写入吞吐**：审计链单租户稳态写入 ≥ 500 条/秒；官方口径恒为**一条一事务**，批量提交只用于区分「链计算成本」与「每事务 fsync 成本」，不作为达标值。
5. **分片提前量与跨月**：次月分片须在当月 25 日前就绪；时钟推进到次月 1 日后三类日志写入成功，次月首条 `prev_hash` 衔接上月同租户末条，链校验通过、0 失败。
6. **压测方法可复现**：固定数据集（单租户 5 万条审计事件）与固定并发（32）；报告须写明机器 / 系统 / 库 / 缓存 / 是否真 broker、固定口径、四项指标总表、主链路与写入段明细、分片与跨月结果、告警验证证据、限定达标项与差距归口、命令级复跑步骤。
7. **差距有归口**：未达标或限定达标的项必须写明环境限制、影响面与后续动作（生产库复测 / 独立任务 / 部署窗口），不得只写结论不写去向。

**完成标准**：指标可在 `/metrics` 文本中看到真实样本；告警规则在 `promtool` 下触发 / 不触发两组序列均通过；容量面板可加载；5 万条写入基准与主链路三档 A/B 出数并形成报告；跨月与提前量用例通过；四项指标逐项给出「达标 / 限定达标 / 未达标」与差距归口；报告含命令级复跑步骤，可按步骤重现；新增与改动模块覆盖率达标（口径见《[AI开发规范](../../../规范/AI开发规范.md)#coverage》「覆盖率要求」节）。
