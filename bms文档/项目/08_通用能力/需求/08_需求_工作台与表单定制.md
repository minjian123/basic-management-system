## 1. 业务域说明 <a id="intro"></a>

本业务域是**平台可配置性的后端支撑**：工作台决定每个用户登录后看到什么（三级模板 + 个人布局），表单定制决定每张业务表单长什么样（布局 / 字段属性 / 租户自建字段）。两者都把「配置」当数据存，把「解析」放在读取时做。组件回补（`08-3`）是它们的前端消费面。

- **依据**：《[概要设计 · 首页工作台](../../../设计/概要设计/35_概要设计_首页工作台.md)》《[概要设计 · 表单定制](../../../设计/概要设计/36_概要设计_表单定制.md)》《[架构设计 · 首页工作台](../../../设计/架构设计/29_架构设计_子系统_首页工作台.md)》《[架构设计 · 表单定制](../../../设计/架构设计/30_架构设计_子系统_表单定制.md)》。
- **前置**：阶段四组件库（06 字段类 / 07 展示类）、阶段七 RBAC（角色 / 菜单 / 字段权限）、需求 `01-1`（字典选项集来源）。

## 2. 需求 08-1：首页工作台后端 <a id="r08-1"></a>

优先级：2（高）

**背景与动机**：不同角色的首页诉求不同（财务看报表、审批人看待办、运维看告警），若首页写死，每加一个角色就要改前端。工作台必须支持「平台默认 → 角色模板 → 个人布局」三级回退，且卡片可注册、可停用。

**内容**（《概要设计 · 首页工作台》§2.1 / §2.2）：

1. **渲染与聚合**：按 个人 → 角色 → 平台 三级回退解析布局，聚合卡片数据（待办 / 已办、通知、公告、快捷入口、统计、图表）；空布局回退字段默认栅格。
2. **个人布局定制**：卡片显隐、排序、网格拖拽布局、卡片尺寸；自建图表卡片（选数据集 + 图表类型）；保存为个人布局（落用户偏好）。
3. **卡片注册**：内置卡（`builtin`）由平台种子登记，租户侧**只能停用、不能增删改定义**；租户自建数据卡单独登记。
4. **模板维护**：平台默认模板（`scope=platform`，唯一，作为全部用户初始布局来源）、角色模板（`scope=role`，按角色绑定，覆盖平台默认；角色无模板时回退平台默认），权限码 `dashboard:manage`。
5. **一键重置**：个人布局清空后回到「角色模板 → 平台默认」链路。
6. **待办角标**：顶栏 / 侧边栏待办数与通知未读数角标，经 Socket.IO 实时刷新（数据来自工作流与通知中心既有能力，不重复计算）。

**完成标准**：新用户首次登录得到平台默认模板布局；绑定角色模板后该角色用户看到角色布局；个人改动只影响本人且重置后回到角色 / 平台模板；停用某卡片后所有用户布局中该卡消失且不报错；自建图表卡片保存后刷新仍存在；待办角标随事件实时变化（无需刷新）；租户无法修改内置卡定义（越权被拒）。

**参考文档**：《概要设计 · 首页工作台》§2「功能分解与业务流程」、§5「接口设计」；《架构设计 · 首页工作台》「三级模板与解析」节。

## 3. 需求 08-2：表单定制后端 <a id="r08-2"></a>

优先级：1（紧急）

**背景与动机**：同一个业务表单，不同租户要不同字段（行业差异），同一租户不同角色要不同必填项（岗位差异）。若表单写死在前端，每处差异都要改代码；若允许租户随便加列，又会带来 DDL 注入与跨库类型不一致的风险。

**内容**（《概要设计 · 表单定制》§2.1 / §2.2）：

1. **布局定制**：分区 / 分组、列数（1/2/3）、跨列、字段顺序、标签宽度；查询表单区与明细区列配置；字典高级查询方案联动。
2. **三级布局解析**：角色视图 → 租户覆盖 → 平台默认 → 空布局回退字段 `sort` 默认栅格；与字段权限叠加时**权限优先**（无可见权限的字段即使布局里有也不下发）。
3. **字段属性调整**：必填 / 默认值 / 提示 / 校验规则（长度 / 范围 / 正则）、组件类型切换、选项集来源（只引用注册表选项集，不允许自由文本）。
4. **租户自建字段**：新建自定义字段（文本 / 长文本 / 数字 / 日期 / 字典单选多选 / 开关 / 文件）→ **动态 DDL 建物理列**（`ext_` 前缀）；类型走**白名单 + 跨四库类型映射**，DDL 生成**不走字符串拼接**。
5. **服务端动态校验**：新增 / 编辑接口按当前生效布局配置动态校验必填 / 长度 / 范围 / 正则 / 选项集；**展示类属性改配置即生效，不改数据**。
6. **导入导出联动**：导入模板列按布局配置生成（平台字段 + 已生效自建字段），校验规则与表单一致。
7. **安全**：字段标识与 DDL 标识符白名单校验，注入尝试在登记阶段即拒。

**完成标准**：同一表单在两种角色视图下下发不同布局（字段顺序 / 必填不同）；无字段权限的字段不出现在下发结果中；新增自建字段后物理列被创建且四库类型映射一致；服务端校验按当前布局生效（改了必填后接口立刻要求）；展示类属性变更不需要改数据；非法字段标识 / 类型在登记时被拒（注入用例覆盖）；导入模板列与布局一致。

**参考文档**：《概要设计 · 表单定制》§2「功能分解与业务流程」、§4「数据模型与表设计」、§6「权限与配置」；《[架构设计 · 数据架构](../../../设计/架构设计/07_架构设计_数据架构.md)》「跨四库类型映射」节。

## 4. 需求 08-3：字段类与展示类组件回补 <a id="r08-3"></a>

优先级：3（中）

**背景与动机**：阶段四组件库交付时，字典字段、组织选择、文件上传、通知、文件预览、审计差异这些组件缺少后端能力支撑，只能先做占位版。阶段八能力就绪后，这些组件必须从占位版补齐为可用版，否则前端页面仍无法落地。

**内容**（《[架构设计 · 前端组件体系](../../../设计/架构设计/05_架构设计_前端组件体系.md)》；阶段四 06 字段类 / 07 展示类设计）：

1. **06 字段类**：字典字段（`data_source_key` 取数 + 高级查询 + 缓存版本联动）、组织选择（mdm 组织域接口）、文件上传（分片 + 断点续传 + 进度）、验证码字段。
2. **07 展示类**：通知与公告展示、文件预览（图片 / PDF / 音视频，预签名失效重取与降级下载）、审计差异展示（旧值 / 新值对比）。
3. **口径**：组件只消费平台能力出口，不自建数据通道；占位版的能力缺口逐项在组件设计里销账。
4. **验收**：组件用例覆盖真实后端契约（mock 走契约 DTO，不用临时字段）。

**完成标准**：字典字段能按 `data_source_key` 取数并响应缓存版本变化；文件上传支持分片与断点续传且进度准确；文件预览在预签名失效时自动重取、失败降级为下载；审计差异组件能渲染旧值 / 新值；原先标记为占位的能力缺口在组件设计里全部销账。

**参考文档**：《架构设计 · 前端组件体系》；阶段四《[组件设计 · 字典字段](../../../设计/组件设计/)》《[组件设计 · 文件预览](../../../设计/组件设计/)》。
