## 1. 业务域说明 <a id="intro"></a>

本业务域是**异步能力的底座**：事件总线负责「写后副作用」（审计落库、通知、Webhook、索引同步），任务调度负责「定时与手动触发的批处理」，异步作业中心负责「一次性异步执行」（导入 / 导出 / 归档 / 备份等，含进度、重试、取消与死信）。三者职责不同、通道不同——事件走 RocketMQ，任务定义与到期走数据库调度，作业执行走数据库租约；**不共用一套驱动语义**。

- **依据**：《[架构设计 · 事件总线](../../../设计/架构设计/16_架构设计_子系统_事件总线.md)》《[架构设计 · 任务调度](../../../设计/架构设计/17_架构设计_子系统_任务调度.md)》《[架构设计 · 异步作业中心](../../../设计/架构设计/40_架构设计_子系统_异步作业中心.md)》《[概要设计 · 任务调度](../../../设计/概要设计/23_概要设计_任务调度.md)》。
- **前置**：阶段二事件契约（`EventEnvelope` 占位）、RocketMQ 与 Redis 部署（阶段八起）。

## 2. 需求 03-1：事件总线（RocketMQ） <a id="r03-1"></a>

优先级：1（紧急）

**背景与动机**：当前事件域只有接口占位与默认实现，异步清单里的协作（审计落库、通知、Webhook）仍靠同步直写，主链路被副作用拖慢；没有发件箱与投递器，「写库成功但事件丢了」无法保证。阶段八要把总线做成可用设施，而不是框架里的一个空壳。

**内容**（《架构设计 · 事件总线》§2 / §3 / §4 / §5 / §6）：

1. **事件信封**：`EventEnvelope` = `event_id`（幂等键）+ `type`（`{域}.{对象}.{动作}`）+ `tenant_id`（租户主键十进制字符串）+ `occurred_at` + `payload`；topic 命名 `bms.{事件域}.{事件}`。
2. **同步 / 异步判定落地**：跨模块协作默认同步；仅「写后副作用」走事件（审计落库、操作 / 登录日志、通知、Webhook、索引同步）；**读与强一致写禁止异步化**。
3. **生产一致性**：事务性发件箱——业务事务内同库同事务写 `sys_outbox`，投递器轮询投递（后续可切 CDC），业务代码不直接操作 MQ 客户端。
4. **消费组**：审计链组（分区有序，分区键 = 租户）、日志落库组、Webhook 推送组、通知组并行；ES / embedding 组留待后续阶段。
5. **幂等与重试**：`event_id` 去重（Redis SETNX 短窗口 + 业务唯一约束兜底）；失败指数退避有限次 → 死信 topic 落库标记并告警；Outbox 保留期内可按类型 / 区间重放（消费端幂等，重放安全）。
6. **契约**：主版本内字段只增不删、新增可选；破坏性变更升主版本。
7. **过渡**：总线未就绪时的同步直写实现保留为降级路径，但发布点必须预留，不得把同步直写当终态。

**完成标准**：业务事务提交后事件必达（人为制造投递器中断，恢复后事件补投且不重复生效）；同一 `event_id` 重复投递只产生一次副作用；消费失败进入死信并有告警记录；审计链组在并发写入下账本顺序与租户内顺序一致；事件类型与 topic 命名符合登记规范（CI 可校验）。

**参考文档**：《架构设计 · 事件总线》§2「事件模型」、§4「生产一致性」、§5「消费组架构」、§6「幂等与重试」；《[架构设计 · 接口与集成](../../../设计/架构设计/09_架构设计_接口与集成.md)》事件清单。

## 3. 需求 03-2：任务调度 <a id="r03-2"></a>

优先级：1（紧急）

**背景与动机**：归档、清理、备份、分片表预创建这些批处理目前没有统一入口——要么散在部署脚本里（改了要重启），要么人工执行（忘了就出事故）。定时任务必须入库、可页面管理、有执行记录，才能被运维真正用起来。

**内容**（《概要设计 · 任务调度》§2.1 / §2.2、《架构设计 · 任务调度》§2–§5）：

1. **任务定义**：`sys_task`（`name` / `handler` / `cron` / `args` / `status` / `last_run_at` / `remark`）增删改查，权限码 `task:manage`。
2. **调度器**：celery-beat 单副本 + 自研数据库调度器周期扫描到期任务投递；Redis 分布式锁 `bms:global:lock:beat` 防双调度；任务 CRUD / 启停经 Redis pub/sub 热加载，无需重启。
3. **启停与手动触发**：停用任务不再被投递但保留定义与历史；手动触发不受周期限制（`task:trigger`），立即投递一次。
4. **执行与重试**：worker 多副本执行，失败有限次重试 + ack 防丢；执行记录落 `sys_task_log`（状态 / 耗时 / 错误 / 起止时间）；执行完成落 `sys.task.completed` 事件。
5. **内置任务**：孤儿分片清理、日志归档、分片表预创建、每日全量备份、未登录账号锁定扫描、软删除残留物理清理（后续再加帮助文章质量评估）。
6. **执行约束**：worker 为同步进程，任务内执行异步业务须 `asyncio.run` 或独立引擎，禁止跨事件循环复用连接 / 会话。

**完成标准**：新任务入库后不重启即生效；双 beat 实例下同一任务不重复执行（锁生效）；停用任务不再产生执行记录；手动触发即时产生一条执行记录；失败任务按配置重试并在记录中体现重试与最终状态；内置任务清单可查且各自有执行记录；任务内异步代码不因事件循环复用报错。

**参考文档**：《概要设计 · 任务调度》§2「功能分解与业务流程」、§5「接口设计」；《架构设计 · 任务调度》§3「调度器设计」、§4「执行与重试」、§5「内置任务清单」。

## 4. 需求 03-3：异步作业中心 <a id="r03-3"></a>

优先级：1（紧急）

**背景与动机**：孤儿分片清理（03_01）以「内置任务 → 服务内部端点」的触发型补丁实现，这是同类异步执行的第二次；导入异步、导出异步、归档、备份等场景还会继续出现。每新增一个长任务就重复实现一遍轮询、进度、重试与失败处理，且平台既不知道各服务有哪些作业执行者，也看不到执行情况。需要一个统一的作业消费者基建：提交即持久、执行可恢复、进度可查、失败可重试、终态可通知、执行者可发现。

**内容**（《[架构设计 · 异步作业中心](../../../设计/架构设计/40_架构设计_子系统_异步作业中心.md)》§3~§9、《[架构设计 · 任务调度](../../../设计/架构设计/17_架构设计_子系统_任务调度.md)》§3~§4、《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》§4.2）：

1. **作业模型与状态机**：作业记录含作业标识（雪花 ID，接口按字符串输出；部署保证 `worker_id` 全局唯一）、类型、提供方、租户、提交人、负载 / 结果（版本化）、优先级、进度、尝试次数、状态、租约与时间戳；状态为 `queued` / `running` / `succeeded` / `failed` / `canceled` / `dead`，支持重试回队与死信终态。
2. **事务性提交与幂等**：需要与业务写入同生共死的作业在同一事务内落库；提交成功即持久，不依赖进程内队列；提交方携带幂等键时同键返回既有作业，不重复执行。
3. **统一执行引擎**：任务调度保留 `sys_task` 定义与 cron 调度，到期**生产作业**；执行统一走 `sys_job`，`sys_task_log` 保留为任务执行历史并由作业终态回写；任务 worker 与 Redis 任务队列退役；任务 API 的既有查询口径不变。
4. **消费者与租约**：每服务独立 worker，只加载本服务 handler；数据库条件更新抢占 + 租约续租，多副本只一个执行；租约到期回收；全局并发 + 单租户并发上限 + 租户内优先级；协作式取消（批次边界检查）；优雅停机；至少一次语义。
5. **重试、退避与死信**：可重试失败按指数退避回队，达到上限或不可重试错误转 `dead` 并保留错误摘要；死信可查询、可人工重试，重试动作留痕。
6. **作业类型注册与可发现**：产品自持清单新增 `jobs` 记录类，声明作业类型、提供方、执行者、超时 / 重试 / 并发默认值、负载版本与状态；平台装载为只读作业类型视图，并与代码侧 handler 注册对账；不一致按装载失败语义处置，不静默降级。
7. **监控、审计与通知**：作业生命周期事件（提交 / 开始 / 进度 / 终态）经事件总线发布，平台消费并投影为统一监控视图；作业记录仍在各服务本地库；登记 `sys.job.completed` 事件供通知中心后续消费；提交 / 取消 / 重试 / 终态写结构化日志，业务数据变更按各域审计口径。
8. **管理面**：平台提供作业类型目录与统一监控查询（读投影）；取消 / 重试按作业所在服务转发到其 `/jobs` 管理端点；权限码 `job:query` / `job:manage`。
9. **迁移与保留期**：03_01 孤儿清理迁为文件服务的 `file.cleanup_orphans` 作业，旧「内置任务 → 内部端点」路径移除；txn 恢复轮询、outbox 投递器与事件消费组保持原样；作业记录保留 30 天，由内置清理作业按保留期删除。
10. **统一基类与产品扩展**：作业模型 / 负载 / 结果 / 处理器 / 消费者 / 仓储 / 注册表等公共语义在共享基座维护；产品默认继承 `BaseJobHandler`，只实现本产品的 handler、负载与作业类型声明；确有必要可继承更深的消费者 / worker 基类，但必须保持统一状态机、租约、进度与事件契约，偏差由该产品自担且不得影响其他产品；**不得另起炉灶自研平行队列 / 消费者 / 租约 / 重试 / 监控，也不得绕过基类写作业表**；不继承基类的第三方实现经统一注册通道接入，仍须通过同一套契约测试。

**完成标准**：作业提交后进程重启 / Redis 不可用仍能继续执行；作业标识全系统唯一（部署 `worker_id` 全局唯一）；多 worker 并发下同一作业只执行一次，租约过期可回收；进度、尝试次数、错误摘要可查；重试退避与死信生效且死信可人工重试；取消在批次边界生效并落终态；任务到期生成作业且 `sys_task_log` 历史仍可查、既有任务 API 行为不变；03_01 孤儿清理经作业执行且旧触发路径零残留；`jobs` 声明装载、代码侧 handler 对账与不一致拒绝生效，平台可查作业类型目录；生命周期事件与平台投影可查，`sys.job.completed` 契约登记；管理面权限与转发取消 / 重试生效；产品侧继承 `BaseJobHandler` 并声明即可接入，未自研队列 / 租约 / 重试；真 Redis 多 worker 竞争、租约回收与重试用例通过；新增 / 改动模块覆盖率达标（口径见《[AI开发规范](../../../规范/AI开发规范.md)「覆盖率要求」）。

> **交付注块（2026-11-01 立项）**：本需求为 04_01 导入异步的前置；04_01 不再自建 `sys_transfer_job` 与轮询任务，统一使用 `sys_job`。详细设计、实施与测试记录落任务 [01_03 作业消费者基建](../任务/01_异步底座/01_异步底座_03_作业消费者基建/01_异步底座_03_作业消费者基建.md) 目录。
