## 1. 业务域说明 <a id="intro"></a>

本域只做一件事：把 `help_key` 变成**元数据上的正式字段**。它是帮助机制的声明面，但改动落在阶段七的四张元数据表与产品清单格式上——跨阶段，所以单独立域、单独验收，不藏在帮助中心里。

- **依据**：平台《架构设计 · 帮助中心》§3.4「锚点声明与覆盖率门禁」、§8「与其他子系统的协调」；《[概要设计 · 帮助中心](../../../设计/概要设计/17_概要设计_帮助中心.md)》§4。
- **前置**：阶段七（`sys_menu` / `sys_form` / `sys_field` / `sys_action` 与权限码清单）、07B 产品清单装载、07C 域归属。

## 2. 需求 10-1：锚点登记面扩展 <a id="r10-1"></a>

优先级：2（高）

**背景与动机**：帮助要像权限一样「功能自己声明」，声明就必须有位置。现在元数据表没有 `help_key` 字段，帮助只能靠人工给文章填 `target`——新功能上线没人知道要补，覆盖率也无从计算。这个字段不在帮助中心自己的表里，而在阶段七的元数据上，所以必须显式立项、单独验收，否则容易被当成"顺手加个字段"漏掉。

**内容**（架构 28 §3.4）：

1. **四表增字段**：`sys_menu` / `sys_form` / `sys_field` / `sys_action` 各增 `help_key`（可空，`VARCHAR`）；可空是刻意的——未登记不报错，缺口由覆盖率台账暴露。
2. **格式与唯一性**：`help_key` 形如 `{product}:{module}:{form}:{field}:{action}` 的段式标识（缺省段留空但分隔符保留），格式校验在装载时执行，违规拒收并报错。
3. **清单声明**：产品清单（07B / 07C 装载面）支持在菜单 / 表单 / 字段 / 动作声明项里带 `help_key`；装载时 upsert 到元数据，已存在则更新。
4. **不参与鉴权**：`help_key` 只用于帮助解析与覆盖率对账，**不得影响权限计算**（鉴权链路不读该字段）。
5. **变更留痕**：`help_key` 变更落字段级审计（谁在什么时候把锚点从 A 改成 B）。
6. **兼容**：既有数据 `help_key` 为 `NULL`，不改变任何既有接口返回结构（仅在元数据接口中新增字段，向后兼容）。

**完成标准**：四张表均有 `help_key` 且可空；清单声明后装载可查（元数据接口返回该字段）；格式违规在装载时被拒并给出错误码；权限计算回归用例全部通过（鉴权结果与改造前一致）；锚点变更可在字段级审计中查到；老数据（`NULL`）不影响菜单与表单的正常渲染。

**参考文档**：平台《架构设计 · 帮助中心》§3.4；《概要设计 · 帮助中心》§4「数据模型与表设计」；《[数据库开发规范](../../../规范/数据库开发规范.md)》。
