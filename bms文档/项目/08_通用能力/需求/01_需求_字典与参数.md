## 1. 业务域说明 <a id="intro"></a>

本业务域提供**运行期可维护的基础数据**：字典（值域）与系统参数（配置）。两者的共同约束是「平台只做出口，数据由所有者域承载」——字典不再有平台侧字典表与写路径，参数则是「平台默认 + 租户覆盖」两层。

- **依据**：《[概要设计 · 字典管理](../../../设计/概要设计/09_概要设计_字典管理.md)》《[概要设计 · 系统参数](../../../设计/概要设计/10_概要设计_系统参数.md)》。
- **前置**：阶段二缓存与数据访问基座、阶段七 RBAC（`config:manage` 等权限码）、07C 域归属（数据所有者域）。

## 2. 需求 01-1：字典统一数据源与运行时查询 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：早期字典是「平台建六张表 + 平台库种子 + 租户库覆盖」，结果是同一份值域有两处写路径、字典数据与业务实体脱节（字典条目改了、引用它的业务表还是旧值），且新增一种值域就要改平台表结构。2026-10-11 已拆除字典六表（`sys_dict_type` / `sys_dict_item` / `sys_dict_attr` + 3 张 `_i18n`），需要把「统一出口 + 所有者域承载」补齐。

**内容**（《概要设计 · 字典管理》§2.1 / §2.2）：

1. **统一数据源登记**：登记项含 `data_source_key`（全局唯一，格式 `^[a-z][a-z0-9_]*$`，启动期 / CI 校验）、名称、类型 `kind`（`dict` / `form`，预留其它）、来源、数据出口、字段白名单、级联、可用策略、状态；登记来源为**构建期清单**（平台内建 + 各项目装载注入），运行期只读。
2. **运行时查询**：按 `data_source_key` + `locale` 经统一出口路由到所有者域取启用条目；查询未登记的字典返回空结果（不报错）。
3. **版本化缓存失效**：数据变更后由所有者域删除 Redis key 并 `INCR bms:{tenant}:dict:version`，前后端进程内缓存按版本比对自动重载；缓存未命中走互斥锁回源重建（三防）。
4. **条目标识口径**：条目 `id`（雪花）是内部关联唯一键，业务表与字典字段一律存 `id`（`BIGINT`，多值存 JSON 数组）；`value` 仅用于展示与导出。
5. **高级查询与查询方案**：按可查字段（固定字段 + 登记项字段白名单）或注册的查询提供者构造组合条件取项；查询方案统一落 `sys_query_scheme`（`target=items` 供字典取项 / 筛选，`target=business` 供列表页），不再为字典单开一套。
6. **与选项集分工**：运行期可维护的值域走字典；运行期不可变（随发版）的枚举走选项集。
7. **状态与多语言**：登记项与数据源均可启停，停用即时从运行时结果消失（已引用旧值的业务数据不受影响）；label 按当前 locale 由所有者域随出口下发，缺省回退默认文案。

**完成标准**：字典六表在四类库（平台 / 租户 / 归档）中均不存在；运行时按 key 取数成功且未登记 key 返回空；改数据源后下一次请求即读到新值（版本号变更生效，不需重启）；同一 key 在两种 locale 下返回对应 label 且缺省回退正确；业务表字典字段落 `id` 而非 `value`；`data_source_key` 格式违规在启动期或 CI 被拒。

**参考文档**：《概要设计 · 字典管理》§2「功能分解与业务流程」、§5「接口设计」、§6「权限与配置」。

## 3. 需求 01-2：系统参数（平台默认 + 租户覆盖） <a id="r01-2"></a>

优先级：2（高）

**背景与动机**：安全参数（密码策略、会话上限）、业务开关这类配置没地方放时，只能硬编码或散落在各服务配置文件中，改一次要发版；而多租户下「平台定默认、租户按需覆盖」是刚需，缺了就会退化成每租户一套部署配置。

**内容**（《概要设计 · 系统参数》§2.1 / §2.2）：

1. **参数维护**：分页查询（按 `config_key` 筛选、分组浏览）、新增、修改、重置 / 删除（软删除，进回收站可恢复）；权限码 `config:manage`；字段为 `config_key`（MySQL 保留字规避）、`value`、`remark`。
2. **两层取值**：平台库存默认参数（租户开通种子自动下发），租户库可写覆盖值；读取时先取租户覆盖、缺省回退平台默认。
3. **运行时读取**：各模块经参数服务 + Redis 缓存读取（短 TTL），**不开放外部接口**（系统内部能力）；缓存策略为先写库后删缓存。
4. **并发与生效**：更新走乐观锁 `version` 比对，冲突返回并发冲突错误并提示刷新；安全敏感参数（密码策略、会话上限）修改后缓存删除即生效，且落操作日志与字段级审计。
5. **命名**：`config_key` 点分小写（如 `password.max_age_days`），清单随详细设计确定。

**完成标准**：平台默认值在租户未覆盖时生效；租户覆盖后仅本租户读到覆盖值，其它租户不受影响；重置后回落到平台默认；并发修改同一条参数时后写者收到版本冲突而非静默覆盖；删除后参数进回收站且可恢复；参数读取命中缓存（同 key 连续读取不重复回源）。

**参考文档**：《概要设计 · 系统参数》§2「功能分解与业务流程」、§6「权限与配置」；《[数据库设计 · 数据规范](../../../设计/数据库设计/02_数据库设计_数据规范.md)》。
