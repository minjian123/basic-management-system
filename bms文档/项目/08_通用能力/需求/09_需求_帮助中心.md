## 1. 业务域说明 <a id="intro"></a>

帮助中心是**与权限同级的横切机制**（2026-10-31 口径，见[架构 28](../../../设计/架构设计/28_架构设计_子系统_帮助中心.md)）：功能声明自己要哪篇帮助（锚点），运行时按上下文解析展示；内容既可后台维护，也随产品包装载。三层各自可验收——**声明面**（锚点，登记口径见 `10-1`）、**装载面**（产品帮助包）、**内容面**（分类 / 文章 / 反馈）。包格式与装载规则见《[帮助包规范](../../../规范/帮助包规范.md)》。

- **依据**：《[架构设计 · 帮助中心](../../../设计/架构设计/28_架构设计_子系统_帮助中心.md)》§1 / §3.3 / §3.4 / §4.2 / §7、《[概要设计 · 帮助中心](../../../设计/概要设计/17_概要设计_帮助中心.md)》。
- **前置**：需求 `10-1`（锚点登记面）、阶段七菜单 / 表单 / 字段 / 动作元数据、07B 产品清单装载。

## 2. 需求 09-1：帮助锚点声明与上下文解析 <a id="r09-1"></a>

优先级：2（高）

**背景与动机**：现在页面内帮助靠文章手填 `target`（只有 module / form 两档），新功能上线没人知道要补帮助，按钮也常不显示；用户点了没反应，比没有按钮更糟。帮助要像权限一样「功能自己声明」，运行时按最贴近的上下文命中。

**内容**（架构 28 §4.2、概要 17 §2.1 / §5）：

1. **五级解析链**：字段（`field_key`）→ 动作（`action_code`）→ 表单（`form_key`）→ 模块（`module_key`）→ 全局，逐级降级，命中即返回文章与锚点定位。
2. **未命中降级**：全不命中时返回空 + 该功能所属分类列表，前端提示「暂无帮助」，不出现空白弹窗。
3. **按钮显隐**：解析链上任一级命中才显示帮助按钮；无锚点不显示（避免「点了没反应」）。
4. **锚点下发**：`help_key` 随菜单接口与表单元数据接口下发，前端不硬编码模块名。
5. **多篇命中**：同一锚点多篇时按来源优先级 `builtin > product > tenant` 取一篇，其余列「相关内容」。
6. **接口**：`GET /api/v1/help/context`（入参 field / action / form / module），登录即可调用。

**完成标准**：五级各自命中与逐级降级均正确（构造五种数据验证）；全不命中返回空且前端可打开分类列表；无锚点时按钮不显示；同锚点多篇按优先级取用且其余可见；解析结果有缓存（连续请求不重复回源）；关闭某级锚点后自动降级到下一级。

**参考文档**：《架构设计 · 帮助中心》§4.2「页面内帮助按钮」；《概要设计 · 帮助中心》§5「接口设计」。

## 3. 需求 09-2：产品帮助包装载注册 <a id="r09-2"></a>

优先级：2（高）

**背景与动机**：biz / mdm / cw 各自有大量帮助文档，现在只能由人在后台逐篇录入——版本、升级、卸载全靠自觉，产品升级后帮助要么过期要么丢失。帮助必须能**随产品包发布并装载**。

**内容**（《[帮助包规范](../../../规范/帮助包规范.md)》；架构 28 §3.3）：

1. **包格式**：`help/package.yaml`（`schema_version` / `product_key` / `package_version` / `checksum` / `includes`）+ 一篇一文件的 `articles/*.yaml`。
2. **装载器**：`ops.help_package`，幂等键 `(product_key, source_key, package_version)`；装载前默认要求 `--dry-run`（输出新增 / 更新 / 下线 / 跳过条数）。
3. **升级同步**：同 `source_key` 更新内容，**`local_override` 的租户编辑跳过**；包内移除项标 `offline`（不物理删）；再次出现恢复 `published`。
4. **卸载**：按 `product_key` 下线该包全部来源文章，租户自建（`source=manual`）不受影响。
5. **冲突与校验**：`checksum` 不符拒收整包；锚点不可解析报 `40008`；产品包不得覆盖平台内建同 target 文章（跳过并告警）。
6. **权限与留痕**：装载 / 卸载需 `help:package`；动作落操作日志，内容变更落字段级审计；`sys_help_package` 登记版本与条数。

**完成标准**：同版本重复装载零变更；升级时新增 / 更新 / 下线计数与 `dry-run` 预测一致；`local_override` 文章不被覆盖；卸载后该包来源文章全部 `offline` 且租户自建保留；`checksum` 不符与锚点不可解析均被拒并给出错误码；装载后 `sys_help_package` 记录版本与条数。

**参考文档**：《帮助包规范》§7「装载、升级与卸载语义」、§8「校验与门禁」；《架构设计 · 帮助中心》§3.3。

## 4. 需求 09-3：帮助覆盖率门禁与台账 <a id="r09-3"></a>

优先级：3（中）

**背景与动机**：没有覆盖率，就永远不知道「哪些功能没有帮助」——只能等用户投诉。覆盖率必须像边界护栏那样**能报数字、能落到具体动作码**，否则「补帮助」永远是口头任务。

**内容**（架构 28 §3.4）：

1. **对账口径**：以权限码清单为基准，「有权限码的动作 / 菜单」减去「已声明 `help_key` 的动作 / 菜单」，差集为缺口。
2. **台账输出**：按产品与模块分组的可计数清单，逐条含动作码 / 菜单码与所属模块；可导出为文档表格与报告数据。
3. **门禁行为**：CI 脚本默认**不阻断**构建、结果进阶段报告；强档可配置为阻断（发布前必须清零或登记豁免）。
4. **一致性**：覆盖率数字与元数据实时一致（同一输入重复生成结果相同）。

**完成标准**：同一输入两次生成的台账完全一致；缺口精确到动作码（可据此建任务）；阻断开关切换行为正确（开则失败、关则告警）；覆盖率数字与 `10-1` 登记的锚点数量对得上；台账出现在阶段测试报告中。

**参考文档**：《架构设计 · 帮助中心》§3.4「锚点声明与覆盖率门禁」；《[测试规范](../../../规范/测试规范.md)》。

## 5. 需求 09-4：帮助内容维护与前台展示 <a id="r09-4"></a>

优先级：3（中）

**背景与动机**：机制解决「找得到」，内容解决「看得懂」。文章要能在后台维护（草稿 / 发布 / 下架 / 置顶）、多语言、可被反馈驱动优化；同时为阶段十九的 AI 生成留好草稿位（本阶段不实现生成）。

**内容**（概要 17 §2.1 / §2.2 / §4）：

1. **分类与文章**：分类树（`parent_id` / 排序 / 状态，删除前须处理子文章）；文章在线编辑入库，正文统一 HTML（轻 Markdown 保存时转 HTML），前后端双向 XSS 白名单清洗。
2. **状态机**：草稿 → 发布 → 下架 → 重新发布；置顶；软删除（可回收站恢复），变更落字段级审计。
3. **多语言**：标题与内容存 `sys_help_article_i18n`（`article_id + locale`），按当前 locale 展示、缺省回退。
4. **前台展示**：分类树 + 列表 + 详情（PC + 移动端），工作台卡片与个人中心双入口；仅已发布可见。
5. **反馈与统计**：有帮助 / 无帮助 + 评论（`(article_id, user_id)` 联合主键防重复、可改投）、阅读计数、后台统计视图。
6. **AI 草稿位**：文章带 `generated_by / ai_model / reviewed_by` 字段，草稿态与审核留痕可用；生成能力本身阶段十九实现，**生产默认关闭**（架构 28 §7.6）。

**完成标准**：草稿不可见 / 发布可见 / 下架隐藏 / 置顶排序正确；两种 locale 展示正确且缺省回退；重复反馈不产生多条但可改投；阅读计数递增可查；统计视图的帮助率与反馈明细一致；`generated_by=ai` 的文章未填 `reviewed_by` 时不允许发布。

**参考文档**：《概要设计 · 帮助中心》§2「功能分解与业务流程」、§4「数据模型与表设计」；《架构设计 · 帮助中心》§7「AI 智能维护」。
