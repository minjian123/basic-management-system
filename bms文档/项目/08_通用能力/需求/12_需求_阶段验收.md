## 1. 业务域说明 <a id="intro"></a>

本域只承载阶段八收口的**结论与证据**：26 条需求逐条给出「达标 / 限定达标 / 未达标」，门禁逐行有结论，遗留逐条有归口。结论单一事实源是阶段计划的门禁表，本域只定义「要产出什么」。

- **依据**：《[测试规范](../../../规范/测试规范.md)》《[计划文档规范](../../../规范/计划文档规范.md)》「门禁」节；阶段七《测试报告》、07C《专项测试报告》为先例。

## 2. 需求 12-1：阶段验收与测试报告 <a id="r12-1"></a>

优先级：2（高）

**背景与动机**：通用能力横跨十余个模块，最容易出现「每个模块都说做完了，合起来没人验证过」。阶段末必须一次性对照：能力是否齐、贯穿口径是否守住（写路径唯一 / 软删除 / 审计先过链再归档 / 多语言附表 / 异步只在副作用）、帮助机制三层是否都能验收——否则缺口会以「小问题」漏进下一阶段。

**内容**：

1. **逐条结论**：26 条需求按完成标准给出结论，无「待定」；限定达标须写明限定范围与归口。
2. **门禁表**：能力齐备 / 写路径唯一 / 异步与任务底座可用 / 审计链可校验 / 多语言可运行期扩展 / 数据生命周期可执行 / 帮助机制三层可用 / 可配置性后端可用 / 遗留有归口。
3. **测试报告**：用例执行统计（单元 / 接口 / 集成分层）、缺陷统计与处置、覆盖率（改动模块行 + 分支）、门禁逐条核对表、风险与遗留、复盘。
4. **遗留台账**：每条写明来源与归口，不允许「无归口」条目；跨阶段待办上升为计划「后续阶段待办」。
5. **收口断言**：机器可校验的用例盯住「结论写了、证据指得着、行数对得上」，防文档漂移。
6. **口径如实**：未验证项（真库 / 真部署 / 压测环境受限）标「限定达标」并写明限定，不以「达标」掩盖。

**完成标准**：26 条逐条有结论且证据可解析（用例文件或命令输出）；门禁表行数与报告门禁节行数一致；遗留台账每行有归口；报告七节 + 附录取证齐备；收口断言用例通过。

**参考文档**：《[测试规范](../../../规范/测试规范.md)》「测试报告」节；《[计划文档规范](../../../规范/计划文档规范.md)》「门禁」节。
