## 1. 业务域说明 <a id="intro"></a>

本业务域解决「加一门语言不发版」：界面文案走 `sys_i18n_message` 语言包，业务数据的多语言走 `{主表}_i18n` 附表，语言清单可运行期扩展（含 RTL 标记），用户时区偏好决定时间展示。

- **依据**：《[概要设计 · 国际化管理](../../../设计/概要设计/29_概要设计_国际化管理.md)》《[架构设计 · 国际化](../../../设计/架构设计/24_架构设计_子系统_国际化.md)》。
- **前置**：阶段二缓存、阶段七用户偏好（`sys_user_preference`）。

## 2. 需求 06-1：语言清单与语言包 <a id="r06-1"></a>

优先级：2（高）

**背景与动机**：文案写死在代码里时，新增一门语言意味着全量发版 + 翻译文件与代码强耦合；阿拉伯语这类 RTL 语言还需要布局方向切换。语言清单与语言包必须都能在运行期维护。

**内容**（《概要设计 · 国际化管理》§2.1 / §2.2）：

1. **语言清单维护**：语言增改 / 启停（`code` / `name` / `rtl` / `status`），支持运行期动态扩展；清单含**默认语言标记**（唯一），`rtl` 驱动前端布局方向切换。
2. **启用语言清单下发**：登录即可获取启用语言清单（`code` / `name` / 默认标记 / `rtl`），供各模块多语言文案字段渲染。
3. **语言包维护**：`sys_i18n_message` 页面在线维护（`msg_key` 增删、各语言 `value` 编辑），**新增语言免发版**。
4. **运行时下发**：`GET /api/v1/i18n/messages` 返回当前语言包，Redis 缓存 + 前端 `localStorage` 二次缓存；语言包变更后缓存失效。
5. **Babel 提取**：开发期用 gettext 提取消息 key 入库（`Accept-Language` 驱动），避免手工维护 key 清单。
6. **缺省回退**：某 key 在某语言下缺失时回退默认语言文案，不出现空白或 key 原文。

**完成标准**：新增一门语言（含 RTL）后前端无需发版即可切换且布局方向正确；语言包编辑后下一次请求即生效；删除某语言的某个 key 后回退默认语言文案而非显示 key；默认语言唯一且不可停用；语言包接口有缓存（重复请求不重复回源）。

**参考文档**：《概要设计 · 国际化管理》§2「功能分解与业务流程」、§5「接口设计」；《架构设计 · 国际化》「语言包与回退」节。

## 3. 需求 06-2：业务文案 i18n 附表与用户时区偏好 <a id="r06-2"></a>

优先级：3（中）

**背景与动机**：语言包只覆盖界面文案，业务数据本身（字典 label、公告标题、帮助文章、邮件主题）也要多语言；另外跨时区用户看到的「昨天 23:00」必须是自己的本地时间，否则日志与单据时间无法对齐。

**内容**（《概要设计 · 国际化管理》§2.1 / §2.2）：

1. **业务文案附表**：`{主表}_i18n` 按 locale 存翻译（与主表同域、同生命周期），查询关联当前 locale、缺省回退主表默认文案。
2. **覆盖范围**：字典 label、公告、帮助文章、邮件模板、菜单 / 表单名称等「面向用户的文本列」，逐项在设计里登记，不做全表无差别附挂。
3. **写入口径**：文案变更与主表变更同一事务，附表不单独提供写接口（随主表编辑）。
4. **用户时区偏好**：个人中心维护 `sys_user.timezone`，时间按偏好时区展示，数字 / 日期用 `Intl` 本地化；存储统一 UTC。
5. **缺省行为**：用户未设置时区时取默认语言时区；时区非法值在保存时拒绝。

**完成标准**：业务文案在两种 locale 下返回对应语言且缺省回退正确；主表删除时附表同步清理（无孤儿行）；用户切换时区后列表与详情时间展示随之变化，存储值不变；非法时区保存被拒。

**参考文档**：《概要设计 · 国际化管理》§2「功能分解与业务流程」、§4「数据模型与表设计」；《[数据库设计 · 数据规范](../../../设计/数据库设计/02_数据库设计_数据规范.md)》「多语言附表」节。
