## 1. 业务域说明 <a id="intro"></a>

本业务域分出三类触达：**通知中心**（个人站内信，可按偏好过滤渠道）、**公告**（面向全员，带已读回执）、**邮件与短信**（外发渠道，模板化）。三者的共同约束是「模板与文案可维护、发送有记录、失败可查」。

- **依据**：《[概要设计 · 通知中心](../../../设计/概要设计/16_概要设计_通知中心.md)》《[概要设计 · 公告管理](../../../设计/概要设计/18_概要设计_公告管理.md)》《[概要设计 · 邮件通知](../../../设计/概要设计/24_概要设计_邮件通知.md)》《[架构设计 · 通知公告](../../../设计/架构设计/22_架构设计_子系统_通知公告.md)》。
- **前置**：阶段二实时推送契约（Socket.IO）、阶段七用户与角色、需求 `03-1`（事件驱动落信）。

## 2. 需求 04-1：通知中心 <a id="r04-1"></a>

优先级：2（高）

**背景与动机**：审批待办、系统告警、导入完成这类消息目前只能靠用户主动刷新页面发现；没有站内信落库与角标，工作流上线后会立刻出现「待办没人处理」。

**内容**（《概要设计 · 通知中心》§2.1 / §2.2）：

1. **通知列表与详情**：分页 + 类型 / 已读状态筛选（PC + 移动端），权限码 `notification:query`；详情自动标记已读，`biz_type` / `biz_id` 支持跳转业务单据。
2. **待办角标**：未读 / 待办计数，经 Socket.IO 实时推送增量更新（登录态内建，不设权限码）。
3. **已读管理**：单条已读、批量已读、全部已读（`notification:update`）。
4. **删除**：单条软删除，仅本人数据；已删除通知不再进入列表与未读数（`notification:delete`）。
5. **渠道过滤**：按用户通知偏好（站内信 / 邮件 / 短信开关、免打扰时段）过滤，被过滤渠道不发送；偏好数据取用户喜好域。
6. **生成路径**：由业务事件触发（工作流待办、导入完成、告警），经通知组消费落库并推送——不由业务代码直接写通知表。

**完成标准**：事件触发后目标用户收到站内信且角标实时变化（无需刷新）；详情打开即已读，未读数同步下降；批量 / 全部已读生效且幂等；删除后列表与未读数都不再包含该条；关闭站内信渠道后不再产生通知记录（该渠道被过滤）；通知只能看到本人数据（跨用户不可见）。

**参考文档**：《概要设计 · 通知中心》§2「功能分解与业务流程」、§5「接口设计」；《架构设计 · 通知公告》「通知」节。

## 3. 需求 04-2：公告管理 <a id="r04-2"></a>

优先级：3（中）

**背景与动机**：全员通知（停机维护、制度变更）与个人站内信是两件事：公告要面向全员可见、可置顶、到期自动下线，还要能统计「谁没看」。混在通知里做，既发不全也统计不出。

**内容**（《概要设计 · 公告管理》§2.1 / §2.2）：

1. **发布与编辑**：标题 / 内容 / 类型 / 优先级 / 发布时间 / 过期时间；已发布公告修改后重新发布并推送更新事件（`notice:create` / `notice:update`）。
2. **删除**：软删除（`deleted_at`），动作落操作日志（`notice:delete`）。
3. **置顶**：`is_top` 置顶在列表前排，多公告置顶按更新时间排序（`notice:update`）。
4. **过期自动下线**：到达 `expire_at` 后不再对全员展示，读取校验 + 定时扫描兜底双保险。
5. **已读回执**：阅读后落 `(notice_id, user_id)` 联合主键回执（防重复），统计已读 / 未读人数。
6. **查看**：全员在 PC 与移动端查看已发布列表与详情（含置顶标识、已读状态），`notice:query`。

**完成标准**：发布的公告全员可见且置顶排序正确；到期后不再展示（即使缓存未失效，读取校验也拦得住）；重复阅读不产生重复回执；已读 / 未读人数之和等于应读人数；软删除后列表与详情均不可见且操作日志可查。

**参考文档**：《概要设计 · 公告管理》§2「功能分解与业务流程」、§5「接口设计」。

## 4. 需求 04-3：邮件与短信通知 <a id="r04-3"></a>

优先级：2（高）

**背景与动机**：验证码、告警、审批提醒要走出站内信，就必须有外发通道；模板硬编码在代码里意味着改一句文案要发版，且中英混排时无法按 locale 取文案。短信渠道还涉及多云（阿里云 / 腾讯云）切换。

**内容**（《概要设计 · 邮件通知》§2.1 / §2.2）：

1. **邮件模板**：`code` / `name` / `subject` / `content`（Jinja2）/ `status` / `remark` 增删改查；保存时做**语法校验 + 沙箱渲染测试**，权限码 `mail:send`。
2. **模板多语言**：主题与内容按 locale 存 `sys_mail_template_i18n`，查询按当前 locale 关联，缺省回退主表默认文案。
3. **邮件发送**：按模板 `code` + 参数渲染并**异步** SMTP 发送，记录 `sys_mail_log`（成功 / 失败 / 错误信息）。
4. **短信**：模板（`code` / `name` / `content` / `channel`：aliyun / tencent / `status`）增删改查；验证码 / 告警 / 通知三类场景发送，记录 `sys_sms_log`。
5. **发送记录**：邮件与短信记录均可按状态 / 时间查询，失败原因可见。

**完成标准**：模板语法错误在保存时被拒（不进库）；同一模板在两种 locale 下渲染出对应文案且缺省回退正确；发送失败落记录且错误信息可定位（SMTP 拒绝 / 渠道返回码）；切换短信渠道后新发送走新渠道且记录标注渠道；发送动作不阻塞主请求（异步）。

**参考文档**：《概要设计 · 邮件通知》§2「功能分解与业务流程」、§5「接口设计」；《概要设计 · 国际化管理》§2.1「业务文案 i18n 附表」。
