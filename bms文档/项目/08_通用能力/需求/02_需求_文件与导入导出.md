## 1. 业务域说明 <a id="intro"></a>

本业务域提供**文件进出的三条通道**：文件本体（上传 / 下载 / 预览）、批量导入（Excel → 业务表）、导出（列表 → Excel / PDF）。三条通道共用同一套约束：类型白名单、租户隔离、权限码、审计衔接。

- **依据**：《[概要设计 · 文件管理](../../../设计/概要设计/13_概要设计_文件管理.md)》《[概要设计 · 导入导出](../../../设计/概要设计/19_概要设计_导入导出.md)》。
- **前置**：阶段二存储契约（MinIO / S3）、阶段七 RBAC 权限码、07C 域归属与配额。

## 2. 需求 02-1：文件上传与下载 <a id="r02-1"></a>

优先级：1（紧急）

**背景与动机**：附件、头像、导入源文件、导出产物都需要「一次做好、各模块复用」的存储通道。若每个业务域自己接对象存储，类型校验、租户隔离、配额与孤儿清理会各写一遍，且必然漏掉其中几项。

**内容**（《概要设计 · 文件管理》§2.1 / §2.2）：

1. **整包上传**：≤20MB 一次性上传，上传前校验 MIME 类型白名单与大小；权限码 `file:upload`。
2. **分片上传**：超限文件走「初始化 → 逐片上传（SHA256 校验）→ 合并」，单文件上限可配（默认 2GB）。
3. **断点续传**：按 `part_no` 状态列表只重传缺失分片；分片临时对象 key 带 `.part` 标识，合并后清理。
4. **下载与预览**：后端不代理文件流，一律发**预签名 URL 限时下载**；图片 / PDF 直开预览（PC + 移动端）；下载前复核类型与大小。
5. **状态机**：`uploading` → `completed`（全片校验通过合并，落 `file.uploaded` 事件）/ `failed`（清理临时对象，可重新初始化）/ `orphan`（超时，Celery 回收）。
6. **隔离与配额**：私有桶按租户前缀隔离，查询强制租户过滤；上传前校验租户存储配额 `storage_bytes`，超限拦截并告警。
7. **对象与元数据**：`sys_file` 记录每片状态、整文件 `sha256`、大小、类型；列表查询与删除（含对象清理）按 `file:manage` / `file:delete`。
8. **孤儿回收**：Celery 定时扫描超时 `.part` 与超期 `uploading` 记录，物理清理。

**完成标准**：≤20MB 文件整包上传成功、>20MB 自动走分片并在断网重传后仍能合并；类型白名单外的文件被拒（含改扩展名绕过）；预签名 URL 过期后不可下载；跨租户不可见他人文件；配额用尽时上传被拦截且有告警；超时上传在定时任务后被清理且记录状态为 `orphan`。

> **交付注块（2026-10-31，任务 03_01）**：已交付并推送同批。两表落库（`sys_file` 元数据 + 上传会话、`sys_file_part` 分片权威，分片行只硬删）；`multipart_upload` 真实实现（共享基座 + `local` 流式拼接 / `minio` 组合对象双 provider，与 `[storage].provider` 配对校验）；12 端点（整包 / 初始化 / 分片 / 断点状态 / 合并 / 取消 / 秒传 / 列表 / 下载取址 / 预览取址 / 软删 / 内部孤儿清理）；类型白名单（`file.upload.whitelist`，扩展名 + 嗅探双校验）与大小上限（`file.upload.max_size` / `max_file_size`）经 `BaseConfigSource` 真实消费；配额后置占用（超限删对象 + `82005` + 告警，秒传不重复占用）；孤儿回收由内置任务触发型驱动；事件 `file.uploaded` / `file.deleted` / `file.upload.abandoned` 经发件箱与状态同事务写出。设计与偏差见[详细设计](../任务/03_文件管理/03_文件管理_01_文件管理/设计/01_详细设计_01_文件管理.md)。

> **交接（归 13_01 回收站）**：秒传使多条 `sys_file` 共享同一 `object_key`，**物理清理对象前须确认「同 `sha256` + `size` 无其他活行」**（仓储方法 `FileRepository.count_live_by_content` 已提供）；删除当下只软删元数据、对象保留、配额不释放。

> **已知限制**：分片路径无字节可嗅探，仅按扩展名 + 声明 MIME 相容校验（OOXML 只判 ZIP 容器，不做容器内目录复核）；预签名过期由对象存储侧返回 403 表达（本地实现的 `file://` 无过期语义，仅开发用）。

**参考文档**：《概要设计 · 文件管理》§2「功能分解与业务流程」、§5「接口设计」；《[架构设计 · 子系统 · 文件](../../../设计/架构设计/)》。

## 3. 需求 02-2：Excel 批量导入 <a id="r02-2"></a>

优先级：2（高）

**背景与动机**：建租户、初始化用户、批量改数据都靠人工逐条录入，几十条就要半天且容易错行；直接写导入脚本又绕开校验与审计，出错无法回溯。

**内容**（《概要设计 · 导入导出》§2.1 / §2.2）：

1. **模板下载**：按业务表字段生成 Excel 模板（openpyxl），含列头与填写说明；列集支持按表单定制布局生成（见 `08-2`）。
2. **批量导入**：上传文件 → 解析校验（类型 / 必填 / 长度 / 唯一性 / 外键存在性）→ 逐行落库 → 返回错误行报告（行号 + 原值 + 原因）。
3. **幂等拦截**：请求携带 `Idempotency-Key`，Redis `SETNX` 前置拦截 + 唯一约束兜底，重复提交不产生重复数据。
4. **审计衔接**：导入动作落操作日志（模块 / 动作 / 结果摘要）；导入产生的数据变更按各业务表既有审计口径落字段级审计。
5. **部分成功语义**：校验阶段全量预检，非法行不落库；落库阶段按行事务，失败行回滚并计入错误报告。

**完成标准**：模板可下载且列头与字段一致；含非法行时返回逐行错误（行号、原值、原因）且非法行未落库；同一 `Idempotency-Key` 重复提交只生效一次；导入后操作日志可查到本次导入摘要，数据变更可在字段级审计中追溯；万行级导入不超时（异步任务 + 进度可查）。

**参考文档**：《概要设计 · 导入导出》§2「功能分解与业务流程」、§5「接口设计」；《概要设计 · 表单定制》§2.1「导入导出联动」。

## 4. 需求 02-3：列表导出与 PDF 产物 <a id="r02-3"></a>

优先级：2（高）

**背景与动机**：导出最容易出两类事故——导出结果与页面筛选不一致（用户对不上数）、敏感字段明文外泄（手机号 / 身份证）。另外单据打印与列表导出 PDF 的产物需要可分享、可限期清理，不能落本地磁盘。

**内容**（《概要设计 · 导入导出》§2.1 / §2.2、《概要设计 · 文件管理》§2.1）：

1. **同口径导出**：按当前筛选条件导出列表为 Excel，导出与查询共用同一查询构造（不允许另写一套 SQL）。
2. **脱敏**：敏感字段（手机号 / 邮箱 / 身份证等）默认脱敏；持 `data:plain` 权限码方可导出明文，且该动作落审计。
3. **PDF 产物**：单据打印与列表导出 PDF 按模板渲染，支持单据 / 列表两种类型、逐份 / 合并；产物落对象存储，返回限时取址（可分享），文件名 / 保留期 / 清理随单据策略。
4. **大数据量**：超阈值异步导出（`sys_task` 执行），完成后进通知中心，产物同样落对象存储。
5. **权限**：`export:download` 控制导出入口，`data:plain` 单独控制明文。

**完成标准**：同一筛选条件下导出条数与列表总数一致；无 `data:plain` 时导出文件敏感列脱敏，有该权限时明文且审计可查；PDF 产物可通过限时链接下载，链接过期失效；超阈值导出转异步且完成有通知；导出文件不出现在本地磁盘路径。

**参考文档**：《概要设计 · 导入导出》§2「功能分解与业务流程」、§6「权限与配置」；《概要设计 · 文件管理》§2.1「打印 / 导出 PDF 产物」。
