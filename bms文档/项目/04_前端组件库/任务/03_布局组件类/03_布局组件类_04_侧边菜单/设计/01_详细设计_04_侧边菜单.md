## 1. 概述 <a id="overview"></a>

- **目标**：落地 PC 管理端侧边菜单（仅 `frontend/`）——`SideMenu`（动态菜单树渲染 / 折叠 / 搜索 / 高亮 / 徽标可选 / 外链）与递归项 `MenuNode`；菜单数据层 `stores/menu.ts`（占位 loader 可注入）；占位菜单树 `config/placeholder-menu.ts`；**路由守卫** `router/guard.ts` 接入。
- **范围**：任务 [03-4](../03_布局组件类_04_侧边菜单.md)（需求 [03-4](../../../../需求/03_需求_布局组件类.md#r03-4)）；主框架侧栏组成部分，宿主编排（`AppLayout` + 菜单 → 路由注册 `buildRoutes` + `addRoute`）归 `03_05`。
- **依据**：《组件设计》[13_组件设计_侧边菜单](../../../../../../设计/组件设计/08_交互类/13_组件设计_侧边菜单/13_组件设计_侧边菜单.md)（契约基准，含可交互原型）、《布局设计》[04_主框架](../../../../../../设计/布局设计/04_布局设计_主框架.html) / [05_导航](../../../../../../设计/布局设计/05_布局设计_导航.html)、《[前端开发规范](../../../../../../规范/前端开发规范.md)》§3 / §7 / §8。
- **前置契约（已交付）**：`useAccess`（权限上下文，占位空集）/ `useDynamicRoutes`（动态路由构建，占位菜单源）/ `v-perm` / `hasPerm` / `canAccess`（`02_06`）、`usePersistedState`、`useConfirm`（`03_01`）、基础令牌（`03_06`）、`tokenManager`（`02_06_01`）。
- **边界**：不含真实菜单接口（`GET /menus/my`，随阶段七 ~ 八回补）；不含顶栏元素（语言 / 通知 / 用户，回补波）；不含移动端（抽屉 / TabBar 另算）；菜单 → 路由的 `addRoute` 接线归 `03_05`。

## 4. 契约设计 <a id="contract"></a>

### 4.1 `MenuItem`（菜单数据契约） <a id="item"></a>

```ts
export interface MenuItem {
  /** 菜单名（i18n 文案由后端按 locale 下发；缺省直接展示） */
  name: string
  /** 路由 path（叶子菜单必填；与路由 name/path 对应） */
  path?: string
  /** 图标 key（`IconDisplay` 回补前占位降级） */
  icon?: string
  /** 排序（升序） */
  sort?: number
  /** 不上菜单但可用于路由 */
  hidden?: boolean
  /** 徽标（可选；缺省不配——角标统一放顶栏口径） */
  badge?: string | number
  /** 外链（新开窗口） */
  external?: boolean
  children?: MenuItem[]
}
```

### 4.2 `SideMenu`（节点 §3 / §4） <a id="side-menu"></a>

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `menus` | `MenuItem[] \| null` | null | 菜单树；**传 null 即消费 store**（`stores/menu.ts`），传数组即受控 |
| `collapsed` | boolean | false | 折叠态（仅图标 + hover 弹出子菜单，EP `el-menu` 能力） |
| `activePath` | string | '' | 当前路由 path（高亮与父级自动展开） |
| `searchable` | boolean | true | 是否显示菜单搜索（布局设计：> 30 项时提供） |
| `uniqueOpen` | boolean | false | 同级只展开一个子菜单（手风琴） |
| `theme` | 'light' \| 'dark' | 'light' | 菜单主题（暗色随品牌化任务启用） |

- 事件：`navigate: [menu: MenuItem]`（点击叶子；有 router 时默认 `push(path)`）。**实现调整**：原设计 `collapse-change` 移除（折叠由宿主持久化与控制，组件无产生方）。
- 暴露（`defineExpose`）：`setActive(path)` / `expandByPath(path)` / `filter(keyword)` / `openKeys`。
- 行为（节点 §4）：
  - 渲染：递归 `MenuNode`（`el-menu` + `el-sub-menu` / `el-menu-item`）；`hidden` 过滤；`sort` 升序；
  - 图标：一级菜单图标（回补前占位降级）；折叠态仅图标；
  - 高亮：`el-menu` `default-active = activePath`，匹配叶子并**自动展开父级**（`expandByPath`）；
  - 子菜单：点击展开 / 收起；`uniqueOpen` 映射 `unique-opened`；
  - 搜索：本地过滤（名称匹配）——保留命中路径的父链；命中后自动展开；无命中显示空态（`feedback` 文案 `tree.searchPlaceholder` 复用 + 空态提示）；
  - 徽标：`badge` 显示于节点右侧（可选）；
  - 外链：`external` → `window.open(path)`（不参与路由 push）；
  - 折叠持久化：`collapsed` 由宿主（`03_05`）持久化（本任务透传 prop，不改写）。
- 数据源：`menus` 未传时从 store 读（`store.visibleMenus`：过滤 `hidden` + 排序）；`configureMenuLoader` 注入后由宿主调用 `store.load()`。

### 4.3 `MenuNode`（递归项） <a id="menu-node"></a>

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `node` | MenuItem | 菜单项 |
| `depth` | number | 层级（深度建议 ≤ 3，超深不阻断） |
| `collapsed` | boolean | 折叠态（仅一级展示图标） |
| `activePath` | string | 高亮匹配 |
| `keyword` | string | 搜索关键词（命中高亮） |

- 有 `children`（过滤 `hidden` 后非空）→ `el-sub-menu` 递归；否则 `el-menu-item`。**实现调整**：叶子点击统一经 `el-menu` 的 `select` 事件在 `SideMenu` 处理（`MenuNode` 不含点击逻辑，纯渲染 + 递归）。递归组件通过 `defineOptions({ name: 'MenuNode' })` 自引用。

### 4.4 菜单 store（`src/stores/menu.ts`） <a id="store"></a>

```ts
export interface MenuLoader {
  load: () => Promise<MenuItem[]>
}

export const useMenuStore = defineStore('menu', () => {
  const menus = ref<MenuItem[]>([])
  const loaded = ref(false)
  const loading = ref(false)
  const expandedKeys = ref<string[]>(readLocal(EXPANDED_KEY))   // bms_menu_expanded
  const keyword = ref('')

  return { ... }

```

- 持久化：展开集 `bms_menu_expanded`（规范 §8.1 localStorage 前缀口径；远端偏好随用户喜好任务）。

### 4.5 路由守卫（`router/guard.ts`） <a id="guard"></a>

```ts
export function setupRouterGuard(router: Router): void {
  router.beforeEach((to) => {
    if (to.meta.public === true) return true
    if (!tokenManager.hasToken()) {
      return { path: '/login', query: { redirect: to.fullPath } }   // 登录页占位（页面任务补）
    }
    if (to.meta.perm !== undefined && !canAccess(to.meta.perm as string | string[])) {
      return { path: '/403' }
    }
    return true
  })
}
```

- `meta` 约定：`public`（公开路由）/ `perm`（权限码，string | string[]）；静态壳路由（`/`、错误页）标记 `public: true`（错误页已含 `/403` `/404` `/500`；Home 是否公开？——Home 是登录后主页面：**不标记 public**（未登录跳登录）；测试与占位阶段无 token → 跳 /login（登录页占位 404）——为保证开发可用性：给 `/` 加 `public: true`？与「未登录跳登录」冲突。
  决定：**不公开**（`/` 需登录）；开发阶段 token 由未来发展登录页注入；测试用 `tokenManager.setAccessToken('test')` 注入模拟。占位菜单演示（无 token 时 /login 404）登记为已知（登录页任务修复）。
  嗯，这会让 dev 环境下打开首页直接 404（跳 /login 不存在→ catch-all → /404）。可接受？「登录页 / 403 页（路由与页面）→ 页面任务」——期间 dev 体验差。**折中**：守卫在 `/login` 路由不存在时不跳转（检查 `router.hasRoute('login')` 或 path 存在）——`router.resolve('/login').matched.length === 0` → 跳过登录跳转（保持现状）。这很实用！守卫实现：
  ```ts
  if (!tokenManager.hasToken()) {
    const hasLogin = router.resolve('/login').matched.length > 0
    if (hasLogin) return { path: '/login', query: { redirect: to.fullPath } }
    return true   // 登录页未就绪（页面任务前）：放行（由请求层 401 占位兜底）
  }
  ```
  这个「登录页未就绪放行」的占位语义合理（对齐占位模式）✓ 设计写明。
- 注册：`routes.ts` 在 `createRouter` 后 `setupRouterGuard(router)`。
