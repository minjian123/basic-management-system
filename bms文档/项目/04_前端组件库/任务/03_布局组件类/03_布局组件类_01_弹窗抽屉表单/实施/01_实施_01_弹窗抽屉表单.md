## 3. 实施过程 <a id="process"></a>

1. **上下文**：按《AI开发规范》§2 顺序读规范（前端开发规范 §3 组件根与片段 / §5 SFC / §8 FormFrame / §9 样式令牌）→ 设计（[弹窗节点](../../../../../../设计/组件设计/04_容器组件类/01_组件设计_弹窗抽屉表单/01_组件设计_弹窗抽屉表单.md)、[布局设计 · 弹窗](../../../../../../设计/布局设计/10_布局设计_弹窗.html)、[表单页](../../../../../../设计/布局设计/08_布局设计_表单页.html)）→ 项目（任务 03-1、计划、需求 03-1）→ 现状（`useRequest` / `stableStringify` / `hasPerm` / `useContainer` 契约、`main.ts`、vite 按需导入配置、测试基座）。
2. **决策确认**（question 逐项 + 汇总回显）：① 片段组合 = 组件根 `useComponentBase` + 容器片段 `useContainer`（不组合 `useFormContainer`，字段元数据未就绪避免空转）；② 用例拆分 2 条；③ 回写范围 = 惯例 + 弹窗 html 关闭 / 拦截口径；④ 仅 apps/desktop（需求范围外不含移动端）。
3. **i18n**：`common` 补 `save` / `cancel` / `close` / `delete` / `edit` / `confirm` / `reset`；新增 `modal` 节（`titleCreate` / `titleEdit` / `titleView` 带 `{name}` 插值 + 未保存拦截 / 确认 / 删除 / 详情失败文案），zh-CN / en-US 双补。
4. **组合式**：
   - `useConfirm.ts`：封装 `ElMessageBox.confirm`（warning + `el-button--danger` + 禁遮罩 / Esc；`beforeClose` 中 `onConfirm` 异步 loading 后 `done`；返回 `true` / `false` 不抛异常）。
   - `useFormModal.ts`：三态打开（`openCreate` 默认值 + 基线 / `openEdit` / `openView` 详情回填与 `version`）；`dirty` 由 `stableStringify` 基线比对；提交经 `useRequest`（`pendingSubmit` 读取动态 create / update 分支，`edit` 携带 `version`）；成功关闭 + `onSuccess`；409（`httpStatus === 409` 或 `CONFLICT_CODE`）重载详情覆盖；详情失败禁止提交；`close()` 复位在途提交。
5. **容器**（`src/components/modal/`）：内部共享壳 `useModalShell.ts`（宽度阶梯映射 / 拦截链 / 页脚可见性 / 标题文案）+ 三容器 SFC：
   - `FormDrawer` / `FormDialog`：共用 Props / 事件 / 插槽契约；`useComponentBase` 根属性（`data-size` / `data-test` 等）与外部 attrs 合并后透传 EP 容器；`useContainer` 组合；页脚（左 `footer-extra`、右 取消 / 删除 / 保存，视图态「编辑」入口按 `submitPerm`）；关闭经 EP `before-close` / `handleClose` 走统一拦截链。
   - `ConfirmDialog`：强制禁遮罩 / Esc、danger 确定按钮、`confirm` / `cancel` 事件、`loading` 态。
   - 域出口 `index.ts`（三件 + 类型）。
6. **Kiwi 登记（先登记后编码）**：按《KiwiTCMS部署使用说明》与 test 仓 `register_cases.py`（本批走正式脚本流程）登记 → 回读 **724 / 725**（分类「平台骨架」、P2、CONFIRMED、标签「自动化」）。
7. **用例**：`tests/modal-containers.spec.ts`（Kiwi 724，7 条）与 `tests/modal-composables.spec.ts`（Kiwi 725，6 条）——共新增 13 条。
8. **验证**：见[测试记录](../测试/01_测试_01_弹窗抽屉表单.md) §3（含 EP 组件的 jsdom 适配说明）。
9. **回写**：《布局设计 · 弹窗》补「关闭规则与未保存拦截」节（登记项①）、需求 03-1 注块（实现期要点 + 用例编号 + 遗留去向）、任务 03-1 与域总览、计划（§1 工时 / §2 已完成 / §3 剩余 / §3.1 第 39 行新增 / §4 甘特注释）、阶段 README、文档首页 §5.11 / §5.12；test 仓台账（§2 第 24 行 / §3 最新批次 / §4 对账）。
10. **提交**：代码（`feat(前端)`）与文档（`docs(项目)`）分笔提交；test 仓（cases / 台账）独立提交。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 容器 `SharedModalProps` 漏 4 个 EP 直传 props（`closeOnClickModal` / `closeOnPressEscape` / `destroyOnClose` / `lockScroll`），`vue-tsc` 报模板属性不存在 | 设计 props 表有、类型接口漏登 | 补 `SharedModalProps` 与两容器 `withDefaults` 默认值（设计 §4.1 表已含，无需回写） |
| 2 | `mode` 未给默认值 → `TITLE_KEYS[undefined]` → `t(undefined)` 抛「Invalid arguments」 | `withDefaults` 未覆盖 `mode` | 两容器补 `mode: 'create'` 默认；`useModalShell` 标题键加兜底（双保险） |
| 3 | 视图态「编辑」入口在 `submitPerm=null` 时误显示 | `editVisible` 用 `permitOk`（空码放行）与设计「由 `submitPerm` 存在与否决定」不符 | 改为 `!!props.submitPerm && permitOk(...)`（设计无需回写，口径原本如此——实现纠偏） |
| 4 | Vitest 加载 EP 按需样式的 `theme-chalk/base.css` 报 `Unknown file extension ".css"` | 依赖外部化后 Node 直载 CSS | `vitest.config.ts` 增 `server.deps.inline: ['element-plus']`（测试基建，实施记录说明） |
| 5 | EP Dialog 在 jsdom 下初始 `modelValue=true` 不渲染（overlay `display:none`、无按钮） | VTU + jsdom 环境行为（真实浏览器 `onMounted` 正常） | 测试统一「初始 `false` → `setProps({ modelValue: true })`」打开（容器组件行为不改） |
| 6 | 关闭后 `update:modelValue` 不触发（EP 在 `afterLeave` 才 emit） | VTU 默认 stub `transition`，过渡钩子不执行 | 测试 `stubs: { transition: false }` + `vi.waitFor` 轮询（测试记录说明） |
| 7 | `ConfirmDialog` 的 `loading` 态下点击确定无 `confirm` 事件 | EP 按钮 loading 即禁点（预期行为） | 测试先断言 loading，再 `setProps({ loading: false })` 后点击 |
| 8 | `eslint` 报 `_code` / `_options` 未使用（mock 实参） | 项目 lint 规则未忽略 `_` 前缀参数 | mock 改用 `vi.fn<签名>(() => 值)` 无实参写法 |
