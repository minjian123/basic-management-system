结果小结：`LoadingContainer`（四态互斥 `loading（延迟后）> error > empty > content`；`delay` 防闪烁；内置轻量 `mask` / `skeleton` / `spin`（与 04_02 骨架同视觉）；`#loading` / `#empty` / `#error` 插槽优先（frontend 可传域 03 件获完整视觉）；缺省 i18n 文案 + 重试按钮（点击自锁、`loading` 复位）；`--bms-loading-min-height` 覆盖点）与 `SectionContainer`（轻量分区：标题 / 描述 / `extra` / `footer`；复用 `useContainer` 折叠状态机（非受控 / 受控 + `collapse-change`）；`v-if` 按需渲染；档位内边距消费 `--bms-space-*`、分隔线消费 `--bms-color-border`；区域属性透传）落地。

## 3. 实施过程 <a id="process"></a>

1. 上下文：读两节点 §3 / §4 / §6 / §8；核对 `useContainer` 片段 API 与域 03 反馈件依赖面。
2. 决策确认（用户 4 项）+ **方案澄清**：原选「移植反馈件到 mobile」经澄清不可行于同款口径（EP 专有 `el-button` / svg 资源 / `api/error` 依赖链）→ 改「内置轻量四态 + 插槽」（同 04_02 先例；域 04 保持 25h）。
3. 实现：i18n 三键（双端）；`LoadingContainer.vue`（延迟状态机 / 四态 / 内置三形态 / 重试自锁 / `state` 暴露）；`SectionContainer.vue`（片段复用 / 档位映射 / 折叠开关 CSS 三角）；`index.ts` 扩展。
4. 双端同步：`frontend-mobile/` 同款复制（`diff -r` 无差异）+ i18n 双端。
5. Kiwi 登记（`register_cases.py`）：**749**（加载遮罩）/ **750**（分区）；双端用例两件（各 9 条）；双端全量门禁通过。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 「移植反馈件到 mobile」不可行 | 域 03 反馈件含 EP 专有依赖（`el-button`）、svg 资源与 `@/api/error` + `useRequest` 链路；移植后两端必然不同款 | 改「内置轻量四态 + 插槽」（frontend 传件获完整视觉）；设计 §1-2 与对齐记录 5 记录澄清经过 |
| 2 | 片段档位命名与节点不一致（片段 `compact / loose` ↔ 节点 `small / large`） | 片段（域 02）与节点（域 04）命名口径差异 | `fragmentPadding` 映射仅用于 `data-padding` 区域属性；视觉内边距按 `--bms-space-*` 独立映射；设计对齐记录 7 |
| 3 | 状态类与形态类命名冲突风险（均用 `--` 后缀） | 命名空间 | 状态类 `is-loading` / `is-error` / …；形态类 `loading-container-status--<mode>`；设计对齐记录 6 |
| 4 | `collapsed` 受控判定的传参坑（传 `computed` 包 undefined 会被判受控） | 片段以 `options.collapsed !== undefined` 判定 | 受控时才展开传参（`...(controlled ? { collapsed: … } : {})`）；受控判定挂载时静态；设计 §9-4 |
