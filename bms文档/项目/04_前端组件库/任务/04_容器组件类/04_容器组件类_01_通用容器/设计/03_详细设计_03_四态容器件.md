## 1. 设计目标与范围 <a id="goal"></a>

四态容器（加载遮罩容器）：`loading → ready / empty / error` 四态承载内容；状态受控（宿主常接 `useFeedback`）；`empty` / `error` 插槽可传 `03_02` 的 `EmptyState` / `ErrorPage`；延迟显示防闪烁。

与 `03_02` 的边界：`LoadingMask` / `SkeletonBlock` 为**轻量态件**；本件为**容器级四态**（承载内容 + 状态切换 + 插槽组合 + 重试）。

不在本期：骨架屏形态细化（`03_02`）；全局加载条（随宿主）。

## 3. 接口 / 契约与边界 <a id="contract"></a>

### 3.1 `StatusContainer` <a id="status-container"></a>

- **Props**：`status: 'loading' | 'ready' | 'empty' | 'error'`、`delay?`（延迟显示缺省 200ms）、`text?`（加载文案）、`emptyText?` / `errorText?`（内置轻量形态文案）、`retryable?`（错误态是否显示重试）、`keepContent?`（非 `ready` 态是否保留内容挂载，缺省 false）。
- **Events**：`retry` / `status-change`。
- **Slots**：默认（`ready` 内容）/ `loading`（覆盖加载态，缺省内置轻量骨架 / 遮罩）/ `empty`（可传 `EmptyState`）/ `error`（可传 `ErrorPage`）/ `actions`。
- 状态经反馈组件基类 `BaseFeedback`（投影 `useFeedback`）；`status` 受控，变化时同步投影状态并发 `status-change`。
- 延迟防闪：仅 `loading` 受延迟约束（`delay` 内转 `ready` 则不显示加载态）。

## 4. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 |
| --- | --- |
| `delay` 内状态转 `ready` | 不显示加载态（防闪烁） |
| `empty` / `error` 插槽缺失 | 渲染内置轻量形态（图标 + 文案） |
| 错误态未开启 `retryable` | 不渲染重试按钮 |
| `keepContent` 为真 | 非 `ready` 态内容隐藏但保留挂载（保状态） |
| 未知 `status` 值 | 回退 `ready`，开发态告警 |
| 重试点击 | 发 `retry`，状态仍由宿主受控 |
