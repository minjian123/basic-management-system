## 1. 概述 <a id="overview"></a>

- **目标**：落地**片段机制**（`BaseCapability` + `useCapabilityBase`）与**注册表基座**（`BaseRegistry` + `BaseRegistryItem` + `useRegistryBase`），并交付**预置 31 个能力片段**（双端 `frontend/` + `frontend-mobile/` 同款）：
  - 形态 7 / 值·字段链 4 / 选项源 1 / 复用类 19；
  - 片段落点 `src/components/base/<能力域>/useXxx.ts`（一域一目录）+ 各域 `index.ts` 汇总导出，域汇总再经 `src/components/base/index.ts` 统一出口；
  - 片段以 `useCapabilityBase({ key, depends })` 声明标识与依赖，开发态校验（依赖已登记 / 无循环）。
- **范围**：需求 [02-3](../../../../需求/02_需求_基础组件类.md#r02-3)、任务 [02-3](../02_基础组件类_03_片段机制与预置片段.md)。
- **依据**：《组件设计》[03 片段机制](../../../../../../设计/组件设计/02_基础组件类/01_机制基类/03_组件设计_片段机制/03_组件设计_片段机制.md)、[06 注册表基类](../../../../../../设计/组件设计/02_基础组件类/01_机制基类/06_组件设计_注册表基类/06_组件设计_注册表基类.md) 与 `02_能力片段/` 31 个节点（含可交互原型）；《[前端开发规范](../../../../../../规范/前端开发规范.md)》§3.1 / §3.2；《[前端基类清单](../../../../../../前端基类清单.md)》§5「能力片段」与 §7「目录与依赖」；《[架构设计 · 前端架构](../../../../../../设计/架构设计/08_架构设计_前端架构.md)》。
- **边界**：不含 `BaseXxx.vue` 片段包装（按需随具体组件任务交付，本次拍板）；不含请求组合式（`useRequest` / `useListPage`，归 `02_06`）；不含静态护栏（继承 / 依赖方向 / 清单对账，归 `02_05`）；不含真实后端能力（占位降级先行）。

## 4. 契约设计 <a id="contract"></a>

### 4.1 片段机制（`src/base/capability.ts`） <a id="capability"></a>

```ts
export interface CapabilityOptions {
  key: string                    // 片段标识（全局唯一，kebab-case；如 value / field / option-source）
  depends?: string[]             // 依赖片段标识（只准依赖同层已登记片段，单向）
  enabled?: boolean              // false 时跳过校验与登记（预览 / 测试）
  strict?: boolean               // true 时违规抛 BaseError（默认开发态告警不阻断）
  onWarn?: (message: string) => void
  owner?: BaseComponent          // 传入即构造时挂接组件根 mechanisms
}

export interface CapabilityDescriptor {
  readonly key: string
  readonly depends: readonly string[]
  describe(): string             // `key(depends: a,b)`
}

export class BaseCapability extends BaseComponent implements MechanismLike { /** 同上语义（类轨） */ }
export function useCapabilityBase(options: CapabilityOptions): UseCapabilityBaseReturn

/** 已知片段 key 登记（由片段层 `src/components/base/index.ts` 调用，避免机制层反向依赖片段层） */
export function registerKnownFragments(map: Record<string, readonly string[]>): void
export function knownFragments(): Readonly<Record<string, readonly string[]>>
export function resetKnownFragments(): void               // 测试用
```

| 行为 | 口径 |
| --- | --- |
| 声明 | 片段以 `useCapabilityBase({ key, depends })` 声明；`key` 取 kebab-case，与《前端基类清单》『能力片段』节 一致 |
| 校验时机 | **仅开发态**（`enabled !== false` 且 `isDev`）执行；生产态零开销（直接返回描述符） |
| 校验规则 | ① `depends` 每项必须**已登记**（`registerKnownFragments` 的 key 集内），未登记告警（严格模式抛错）；② **不得形成循环**（以已知依赖表做 DFS，命中回边即告警 / 抛错）；③ 自身 `key` 必须非空且 kebab-case |
| 不实现项 | 「不得依赖上层（反向）」由 `02_05` 的 import 方向护栏静态扫描（片段层无法在运行期判定上层归属）——登记为遗留 |
| 告警 | 默认经根系 `log('warn')` 输出（含片段、依赖与原因），`onWarn` 可覆盖；**不阻断渲染**（除非 `strict`，抛 `BaseError` 码 `10003`，段位待对齐） |
| 装配 | 与其它机制一致：`mechanisms.attach()` 挂接、组件根释放联动；未挂接时开发态一次告警（复用 02_02 口径） |
| 依赖方向 | `capability.ts` 只依赖组件根（机制层不引用片段层） |

### 4.2 注册表基座（`src/base/provider.ts`） <a id="registry"></a>

```ts
export interface RegistryItemLike {
  readonly key: string
  describe(): string
}

export abstract class BaseRegistryItem implements RegistryItemLike {
  abstract readonly key: string
  abstract describe(): string
}

export interface RegistryOptions { strict?: boolean; owner?: BaseComponent }

export class BaseRegistry<T extends RegistryItemLike = RegistryItemLike>
  extends BaseComponent implements MechanismLike {
  register(item: T): void           // 同 key：strict 抛 BaseError（码 10002 占位，待 02_05 对齐），否则告警并保留首个
  unregister(key: string): boolean
  get(key: string): T | undefined   // 未命中返回 undefined（不抛错）
  has(key: string): boolean
  keys(): string[]                  // 保序（登记顺序）
  values(): T[]
  list(): readonly T[]
  snapshot(): readonly T[]          // 冻结副本
  get count(): number               // 已登记数量（`size` 已被组件根尺寸档位占用）
}

export function useRegistryBase<T extends RegistryItemLike = RegistryItemLike>(
  options?: RegistryOptions,
): UseRegistryBaseReturn<T>
```

| 行为 | 口径 |
| --- | --- |
| 唯一性 | 同 `key` 拒重：`strict` 抛 `BaseError`（`code = 10002`，**段位待 `02_05` 与后端清单对齐**）；非严格告警并保留**首个**（对齐后端「唯一性拒重」）；数量取 `count`（`size` 已被组件根尺寸档位占用） |
| 未命中 | `get` 返回 `undefined`，各域自行兜底（基座不替各域裁决） |
| 保序 | Map 维护，`keys` / `values` / `list` 按登记顺序（稳定渲染与测试） |
| 快照 | `snapshot()` 返回 `Object.freeze([...items])`，防调用方改写 |
| 生命周期 | 声明式（模块初始化）与运行时（插件 / 片段）双入口；`useRegistryBase` 作用域内登记的项在作用域释放时自动注销 |
| 注册项契约 | `BaseRegistryItem`（抽象 `key` + `describe()`）+ 域扩展字段（组件 / 函数 / 配置对象由各域补充） |
| 复用方 | 域 10 微前端骨架的片段注册表、字段渲染器注册表、图标 / 工作台卡片注册表（后续任务继承本基座补充聚合） |
| 依赖方向 | 只依赖组件根 |

**共同口径**（31 片段一致）：

1. **公开面**：`useXxx(options)` 返回对象（getter 保持响应）+ 必要方法；类型全部导出，禁止 `any`。
2. **依赖横切能力**：一律经根系（`log` / `reportError` / `getConfig` / `t`）与组件根（令牌属性、`mechanisms`）取得，不重复实现；需要后端能力的片段走**占位降级**（不请求 / 空结果 / 降级 / 禁用态）。
3. **声明与登记**：每片段以 `useCapabilityBase({ key, depends })` 声明；`src/components/base/fragments.ts` 维护 31 项 key / depends 权威表并登记到机制（`registerKnownFragments`）。
4. **作用域**：使用异步资源 / 订阅的片段（上传、异步任务、媒体、树、水印、表单元数据等）经 `useAsyncResourceBase` 登记句柄，组件卸载自动释放。
5. **无 UI 语义**：片段不含具体视觉与业务语义；展示由组件与设计令牌决定。

## 10. 边界与开放项 <a id="boundary"></a>

- **不含** `BaseXxx.vue` 片段包装（约 20 余个）——按需随具体组件任务交付（决策 6）。
- **不含**请求组合式（`useRequest` / `useListPage` / `useFormModal`）——归 `02_06`；`form-page` / `column-config` / `query-scheme` 与它们的协作在任务 `02_06` 内接。
- **不含**静态护栏（import 方向 / 继承 / 清单对账）——归 `02_05`；片段机制只做运行期声明与开发态校验。
- **占位降级范围**：选项源（后端字典 / 组织）、上传引擎（对象存储）、异步任务（任务调度）、预签名、用户展示、表单元数据、权限码（`useAccess` 初始化空集 + 版本号）、偏好远端同步、动态路由（菜单树来源）——真实能力随对应阶段回补。
- **注册表错误码**：`10002`（注册表唯一性冲突）为前端内建，**待与《后端基类清单》段位对齐**（归 `02_05`）。
- **依赖表口径**：`depends` 仅登记**片段→片段**单向依赖；「协作 / 消费」关系（节点正文的「与 X 协作」）不入表，避免伪依赖。
- **`fragments.ts` 与清单一致性**：以《前端基类清单》『能力片段』节 为权威，代码内常量与清单逐项对齐（对账脚本归 `02_05`）。
