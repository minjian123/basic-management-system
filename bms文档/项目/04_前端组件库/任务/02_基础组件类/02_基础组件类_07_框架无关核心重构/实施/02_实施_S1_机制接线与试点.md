## 2. 交付物 <a id="deliverables"></a>

| 块 | 内容 |
| --- | --- |
| CI（S0 遗留） | `.gitlab-ci.yml`：触发面加 `packages/**`、`apps/**`、根 `package.json` / `package-lock.json` / `tsconfig.base.json` / `.npmrc`；新增 `core-check` job（`ci-frontend:node22` 镜像；复用镜像预置依赖 `cp -a /opt/ci/frontend/node_modules .` + `@bms/*` symlink 装配 + `npm run check`） |
| 核心响应式基元 | `packages/core/src/base/observable.ts`：`observable()` / `Observable` / `MutableObservable`（读 / 写 / 订阅；帧同值不触发）——**纯 TS，无 Vue**，供任意渲染引擎桥接 |
| 能力注册与提供者 | `packages/core/src/capabilities/registry.ts`：`CapabilityRegistry`（登记 `key` / `depends` / `create` 工厂）+ `createCapability()`（**不注册不可用**：未注册抛 `BaseError(10002)`；冲突默认告警保留首个 / `strict` 抛 `10003`） |
| 能力试点（字段链） | `capabilities/value.ts`（`BaseValue`：受控读写 / 三态 / 统一写入门禁 / `onChange`）、`field-shell.ts`（`BaseFieldShell`）、`field-perm.ts`（`BaseFieldPerm`：三态 + 脱敏）、`field.ts`（`BaseField`：**组合** value + shell + perm，门禁合并 `effectiveDisabled`、必填校验） |
| 能力清单 | `capabilities/manifest.ts`（核心侧权威表：value / field-shell / field-perm / field；导入即登记）+ `capabilities/index.ts`（导入即注册；出口） |
| Vue 绑定插件 | `packages/vue`：`useValue` / `useField`（**组合式只存在于插件层**：实例化核心能力 + `shallowRef` 投影 + scope 停止时取消订阅并 `dispose()`） |
| 根脚本 | `core:check` / `vue:check` / `check`（串联） |

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | CI 无 `npm ci`（镜像预置依赖模式） | `core-check` 以 `cp -a` 复用镜像依赖 + **symlink 装配 `@bms/*`**（等价 npm workspaces 链接）；`npm run check` 不触发安装 |
| 2 | TS：能力类欲用 `disabled` getter 与组件根通用属性冲突（TS2611） | **能力不抢占组件根通用名**：`BaseFieldPerm.permDisabled` / `BaseField.effectiveDisabled`（域语义命名 + 唯一裁决点）——审计「冲突治理」口径的落地示例 |
| 3 | TS：`createCapability(key, options)` 的 options 为各能力自有形状 | 注册表作动态装配点：`options: object`（宽松）+ 内部形状断言；各能力 Options 的 `key` 改可选（`createXxx` / 注册表自动注入） |
| 4 | 能力释放状态不可观测 | `BaseCapability` 增 `isDisposed` + `dispose()` 置位（可断言、契约价值） |
| 5 | `vitest` peer `vite`（S0 已记） | 根 devDeps 显式 `vite@^8.2.2` |
