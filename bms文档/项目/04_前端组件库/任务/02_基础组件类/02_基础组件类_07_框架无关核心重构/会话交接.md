### 4.2 建议设计要点（启动前需 question 逐项确认） <a id="design"></a>

1. **`packages/ui-vant` 形态**：同接口组件实现（Vant 组件映射，如 `van-popup` / `van-nav-bar` /
   `van-pull-refresh` 等）；哪些件先做（建议容器件 8 件起步——与 desktop 容器域同构，契约最清晰）。
2. **注入点归属**：`ui-ep` 的各 `configureXxx` 注入点是「插件各自提供」还是「下沉到 `@bms/core`
   统一注册」？——长期倾向前者 + core 契约测试统一断言（待设计确认）。
3. **契约测试**：「同一套断言」的组织形式（core 契约用例参数化跑多实现，或两端各自 spec 同源模板）。
4. **结构迁移节奏**：`frontend-mobile/` → `apps/mobile/` 是否随 S4 同步（同 S5b 口径：git mv + 全链
   引用 + 镜像路径 `/opt/ci/frontend-mobile` 保持）。
5. **CI**：`core-check` 扩展（加 `ui-vant` 测试）；`frontend-mobile-check` 路径与依赖桥（`/opt/ci/frontend` 预置）。

### 4.3 关键约束与惯例（勿忘） <a id="rules"></a>

- **执行纪律**：待拍板事项一律 question 逐项确认（推荐项在前）；提交分笔（代码 / 文档）；
  **推送需用户明确指令**；全程中文；动手前先读《AI开发规范》与相关设计。
- **架构口径**：「同接口多实现 + 契约测试同一套断言」（废止「双端同款 diff」）；能力避让组件根
  通用名（`busy` / `inactive` / `pending` / `metaVersion` / `permVisible` 等）；「不注册不可用」
  （`BaseError 10002`）；`packages/core` 禁依赖 Vue / UI 库 / 插件 / 宿主（护栏）。
- **镜像与 CI**：镜像内路径 `/opt/ci/frontend`、`/opt/ci/frontend-mobile` 保持；job 名
  `frontend-check` / `frontend-mobile-check` / `core-check` 保持；依赖桥模式见 `.gitlab-ci.yml`。
- **服务器**：睡眠时先 `python3 scripts/tools/wol/wake_mjbk.py` 唤醒（凭据在 `deploy/.env`）。
- **提交前全套**：`apps/desktop`（lint / test / build / budget）+ bms 根 `npm run check` +
  `check-links.py` + `check-base.py`；CI 推送后 `gl_watch_pipeline` 跟盯。
