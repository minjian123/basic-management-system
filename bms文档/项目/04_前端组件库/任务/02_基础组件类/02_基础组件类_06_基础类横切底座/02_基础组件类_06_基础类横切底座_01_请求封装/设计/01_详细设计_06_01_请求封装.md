## 1. 概述 <a id="overview"></a>

- **目标**：把阶段一 Axios 基线补全为**完整请求底座**（双端同款）——`http` 实例与拦截器（token 注入 / 统一响应 / 统一错误提示 / 401 静默刷新）、`request<T>()` 泛型解包、`ApiError` 与错误码映射、`tokenManager`（内存 + 并发刷新收敛）、`BaseApi`（自动幂等键）、`useRequest` / `useListPage` 组合式；提示与跳转经**注入式适配**解耦（PC=Element Plus + 路由，移动端后续注入 Vant）。
- **范围**：需求 [02-6](../../../../../需求/02_需求_基础组件类.md#r02-6)、任务 [02-6-1](../../02_基础组件类_06_基础类横切底座_01_请求封装/02_基础组件类_06_基础类横切底座_01_请求封装.md)；**不含**权限指令（02-6-2）与格式化工具（02-6-3）。
- **依据**：《组件设计》[01_请求封装](../../../../../../../设计/组件设计/09_基础类/01_组件设计_请求封装/01_组件设计_请求封装.md)（含可交互原型）、《[前端开发规范](../../../../../../../规范/前端开发规范.md)》§11 / §12、《[API接口规范](../../../../../../../规范/API接口规范.md)》、《[架构设计 · 前端组件体系](../../../../../../../设计/架构设计/05_架构设计_前端组件体系.md)》「取数与缓存协作」节。
- **边界**：后端 `/auth/*` 未就绪——401 刷新按**占位降级**（未注入 `refreshHandler` 时不发请求，直接按会话失效处理）；登录页 / 403 页尚未建立——跳转目标留占位路由约定；移动端本轮只同款核心（提示 / 跳转注入随后续移动端任务接入）；i18n 语言包只补**错误码最小集**（完整错误码总表随后端接入）。

## 4. 契约设计 <a id="contract"></a>

### 4.1 适配注入（`api/adapter.ts`） <a id="adapter"></a>

```ts
export interface HttpAdapter {
  /** 统一错误提示（缺省仅根系日志，不弹 UI） */
  notify?: (message: string, level?: 'error' | 'warning') => void
  /** 会话失效跳登录（redirect 为当前路径） */
  redirectToLogin?: (redirect?: string) => void
  /** 403 跳无权限页 */
  redirectToForbidden?: () => void
  /** 刷新处理器（返回新 access token；`null` 表示失败 / 未接入 → 占位降级） */
  refreshHandler?: (refreshTokenHint?: string) => Promise<string | null>
}
export function configureHttpAdapter(adapter: HttpAdapter): void
export function getHttpAdapter(): HttpAdapter
export function resetHttpAdapter(): void   // 测试用
```

- **框架无关**：核心不 import `element-plus` / `vant` / `vue-router`；各端入口注入（PC：`ElMessage` + `router.push`；移动端：Vant 轻提示，随后续任务）。
- 未注入 `notify` 时错误只走根系 `reportError` + 日志（不抛 UI 依赖错误）。

### 4.2 `http` 实例与拦截器（`api/http.ts`） <a id="http"></a>

| 项 | 口径 |
| --- | --- |
| 实例 | 单一实例：`baseURL = import.meta.env.VITE_API_BASE ?? '/api'`、`timeout = 15000`；`appInfoClient`（`/info` 探针）保留 |
| 请求拦截器 | ① `tokenManager.getAccessToken()` → `Authorization: Bearer`；② `Accept-Language` 取当前 locale（`i18n.global.locale`）；③ `X-Request-Id`（UUID）；④ 写方法缺 `Idempotency-Key` 时由 `BaseApi` 生成（拦截器兜底生成）；⑤ `config.metadata.startedAt` 记录耗时 |
| 成功分支 | HTTP 2xx 一律放行（含业务码非 0）——**业务码判定在 `request.ts`**（解包点单一、便于 `raw` 读取完整响应）；业务错误构造 `ApiError(code, message, details)`，`silent` 跳过提示，`notify` 提示 `errorMessage(code, message)` |
| HTTP 400 / 422 | 归一为平台 `10001`（PARAM；响应体带业务码时优先取业务码），提示后端 message |
| HTTP 401 | 非白名单且未重放（`config.__authRetried`）→ `tokenManager.refresh()`；成功 → 更新 header 重放一次；失败 / 未接入 → 清会话 + `redirectToLogin(currentPath)` + 抛 `ApiError(20001 会话失效)`；白名单：`/auth/login`、`/auth/refresh`、`/info` 或 `config.metadata.skipAuthRefresh === true` |
| HTTP 403 / 404 / 409 / 5xx | 403 → `redirectToForbidden?.()`（未注入则提示「无权限」）；404 → 「资源不存在」；409 → 「记录已被修改」（乐观锁）；5xx → 「服务异常（traceId: …）」并记录 traceId；全部抛 `ApiError(httpStatus → code 映射：403→30001、404→10002、409→10003、5xx→10000`） |
| 结构异常 | 非 `{code,message,data}`（如反代 HTML）→ `ApiError(-1)` 归一 + 提示 |
| 网络错误 | 无响应（`!error.response`）→ `ApiError(-1, errorMessage('network'))` + 提示 |

### 4.3 `request<T>()`（`api/request.ts`） <a id="request"></a>

```ts
export interface RequestOptions {
  silent?: boolean          // 不自动提示（调用方处理，如表单校验回显 / 登录失败）
  raw?: boolean             // true 返回完整 ApiResponse（需读 message / code）
  timeout?: number          // 覆盖默认超时
  idempotencyKey?: string   // 显式幂等键
  signal?: AbortSignal      // 取消
}
export function request<T>(config: AxiosRequestConfig, options?: RequestOptions & { raw?: false }): Promise<T>
export function request<T>(config: AxiosRequestConfig, options: RequestOptions & { raw: true }): Promise<ApiResponse<T>>
```

- 选项并入 `config.metadata`（`silent` / `raw`）与 `config`（`timeout` / `signal` / 幂等键 header）；成功返回 `data`（或完整响应）；失败原样抛 `ApiError`（拦截器已提示）。
- 业务错误与 401 分支经根系 `reportError` 上报（保留阶段一行为）。

### 4.4 `ApiError` 与 `errorMessage`（`api/error.ts`） <a id="error"></a>

```ts
export class ApiError extends BaseError {
  readonly httpStatus: number
  readonly details?: unknown
  readonly traceId?: string
}
export function errorMessage(code: number, fallback?: string): string
```

- `ApiError extends BaseError`（继承 `code` / `userMessage` / 上报与 `isAuth()` 等能力；`userMessage` 缺省取 `errorMessage(code, fallback)`），附加 `httpStatus` / `details` / `traceId`。
- `errorMessage`：i18n `error.{code}` 优先 → 后端 `fallback`（message）→ `error.default`（通用「操作失败，请稍后重试」）。
- 会话失效码 `AUTH_SESSION_CODE = 20001`（镜像平台 AUTH 段；后端接口接入后可读响应码覆盖）。

### 4.5 `tokenManager`（`api/token.ts`） <a id="token"></a>

```ts
export const tokenManager = {
  getAccessToken: (): string | null
  setAccessToken: (token: string | null): void
  hasToken: (): boolean
  /** 单飞刷新：并发 401 只触发一次；未注入 refreshHandler → 返回 null（占位降级） */
  refresh: (): Promise<string | null>
  /** 清会话（登出 / 刷新失败） */
  clear: (): void
}
```

- **并发收敛**：`refresh()` 共享同一在途 Promise（`refreshing`）；成功写回 token；失败 / 未接入清 token 并返回 `null`。
- `useUserStore` 的 `setToken` / `clear` 同步调用 `tokenManager`（store 作为展示态，token 唯一内存源在 `tokenManager`）。
- refresh token 走 HttpOnly Cookie（前端不可读）——本轮仅留 `refreshHandler` 注入位（占位）。

### 4.6 `BaseApi`（`api/base.ts`） <a id="baseapi"></a>

- 方法签名：`get/delete(url, params?, options?)`、`post/put(url, data?, options?)`（`options: RequestOptions`）；内部统一走 `request<T>`。
- **幂等键**：`post/put/delete` 未显式给 `idempotencyKey` 时**显式生成** UUID v4（`createRequestId()`，`crypto.randomUUID` 兜底）；`get` 不生成；拦截器对写方法兜底生成（双保险）。
- 保留 `extends BaseFrontend`（根系上报出口）。

### 4.7 `useRequest`（`utils/useRequest.ts`，兼容扩展） <a id="userequest"></a>

```ts
export interface UseRequestOptions<T> {
  immediate?: boolean                       // 挂载即发起（缺省 false，保持阶段一行为）
  onSuccess?: (data: T) => void
  onError?: (error: unknown) => void
}
export interface UseRequestResult<T> {
  data: Ref<T | null>
  loading: Ref<boolean>
  error: Ref<unknown>
  run: () => Promise<T | null>              // 既有签名保留；内部透传 AbortSignal 给 fetcher
  refresh: () => Promise<T | null>          // 用上次参数重发
  cancel: () => void                        // 取消在途（AbortController）
}
export function useRequest<T>(fetcher: (signal: AbortSignal) => Promise<T>, options?: UseRequestOptions<T>): UseRequestResult<T>
```

- 竞态：seq 序号 + `AbortController`；**仅最新请求写回状态**；过期请求失败不写 `error`（保留阶段一用例行为）；`cancel()` 中止在途并复位 `loading`。
- `fetcher` 形参新增 `signal`（既有零参 `() => Promise<T>` 兼容）。

### 4.8 `useListPage`（`utils/useListPage.ts`，`query` 改 reactive） <a id="uselistpage"></a>

```ts
export interface UseListPageOptions<Entity, Query extends BasePageQuery> {
  api: {
    list(query: Query, options?: { signal?: AbortSignal }): Promise<PageResponse<Entity>>
    remove?: (id: string) => Promise<void>          // 可选：删除能力（无则不提供 remove）
  }
  defaultQuery: Query
  immediate?: boolean                                // 缺省 false
}
export interface UseListPageResult<Entity, Query extends BasePageQuery> {
  query: Query                                       // reactive（决策 8）
  list: ComputedRef<Entity[]>
  total: ComputedRef<number>
  data: Ref<PageResponse<Entity> | null>
  loading: Ref<boolean>
  error: Ref<unknown>
  selection: Ref<Entity[]>
  search(): Promise<PageResponse<Entity> | null>     // 回第 1 页
  reset(): Promise<PageResponse<Entity> | null>      // 清空后恢复 defaultQuery（保留 reactive 身份）
  reload(): Promise<PageResponse<Entity> | null>
  onPageChange(page: number): Promise<PageResponse<Entity> | null>   // 保留筛选
  onSortChange(sort: { prop?: string; order?: 'ascending' | 'descending' | null }): Promise<PageResponse<Entity> | null>  // 约定写 `sort` / `order`
  remove(id: string): Promise<boolean>               // 二次确认由调用方完成；删除后 reload
  clearSelection(): void
}
```

- `reset` 实现：逐键删除 + `Object.assign(query, defaults)`（保持 reactive 对象身份，避免整体替换失效）。
- 排序字段约定 `query.sort` / `query.order`（泛型未声明时内部按 `Record<string, unknown>` 写入并文档化）。

### 4.9 i18n 最小集与入口接线 <a id="i18n"></a>

## 5. 双端同款 <a id="dup"></a>

- 两工程各一份**同内容**实现（`api/adapter.ts`、`error.ts`、`request.ts`、`token.ts`、`http.ts`、`base.ts` + `utils/useRequest.ts`、`useListPage.ts` + i18n 两文件）；`diff -r` 为空；双端门禁全跑。
- 移动端入口本轮不改（`configureHttpAdapter` 未注入时核心按无 UI 依赖运行）；移动端提示注入随后续移动端任务（登记遗留）。
