## 3. 实施过程 <a id="process"></a>

1. **上下文**：按《AI开发规范》§2 顺序读本地资源 → 规划 → 规范（前端开发规范 §3、日志规范、命名规范）→ 设计（组件设计根系节点 + 原型、架构 05/08）→ 项目（阶段四 README / 需求 02 / 任务 02_01 / 计划）→ 详细设计；并按 §6 定向检索「根系 / 前端基类」（命中《前端基类清单》《架构 08》《组件设计·根系基类》）。
2. **决策确认**（question 逐项）：① 代码落点 → 按组件设计节点拆两文件；② 配置来源 → 构建期 `import.meta.env` + 运行期可注入；③ 日志/上报 → 统一出口 + 最小实现；④ 双端同款 → 双端同步落地；⑤ 组件包装 → 本任务一并交付 `BaseFrontend.vue`；⑥ 契约/数据根 → 本任务接上根系。
3. **实现**（`frontend/src/base/`）：
   - `BaseFrontend.ts`：`BaseFrontend` 抽象类 + `resolveBuildConfig` / `configureFrontendBase` / `resetFrontendBaseConfig` / `getFrontendRuntimeConfig` / `setFrontendSinks`；`log` / `reportError`（分级 + 指纹去重限流 + sink 注入）/ `getConfig` / `t` / 生命周期钩子 / 幂等 `dispose`。
   - `useFrontendBase.ts`：作用域子类承载等价能力，`getCurrentScope()` 非空时经 `onScopeDispose` 自动释放，方法以箭头函数绑定支持解构。
   - `BaseFrontend.vue`：可选组件包装（props `ns` / `identifier`，默认插槽作用域参数 `{ base }`，事件 `created` / `disposed`）。
4. **Kiwi 登记（先登记后编码）**：按《KiwiTCMS部署使用说明》「用例约定」「用例登记（脚本化批量）」节，用 Django shell 批量脚本经 ssh 管道登记，回读得 **case id 698（frontend）/ 699（frontend-mobile）**。
5. **用例**：`frontend/tests/base-frontend.spec.ts`（Kiwi 698，12 条）覆盖字段 / 配置解析 / 分级与限流 / 错误归一化 / sink 异常兜底 / i18n / 钩子幂等 / 组合式作用域释放 / 组件包装；双端复制后仅 Kiwi 号不同（699）。
6. **契约/数据根接根系**：`api/base.ts` 改 `BaseApi extends BaseFrontend`（`ns = api`、`identifier = basePath`）；`stores/base.ts` 在工厂内组合根系并在 `fetchList` 失败时上报后原样抛出；`api/http.ts` 模块级根系实例 + `request()` 业务错误与 401 分支上报（拒绝值与拒绝对象身份不变）；对应断言并入既有用例 Kiwi 21 / 25（移动端 22 / 26）。
7. **双端同款**：`diff -r frontend/src/base frontend-mobile/src/base` 无差异；`api/`、`stores/`、用例文件仅 Kiwi 编号不同。
8. **验证**：见[测试记录](../测试/01_测试_01_根系基类.md) §3。
9. **回写**：《前端基类清单》§2/§4/§7、《架构设计 · 前端架构》§8、《组件设计》根系节点 §2、需求 02-1 与总览/域地图、任务 02_01 与域总览、计划（两表 + 甘特 + 头部计数工时）、阶段 README。
