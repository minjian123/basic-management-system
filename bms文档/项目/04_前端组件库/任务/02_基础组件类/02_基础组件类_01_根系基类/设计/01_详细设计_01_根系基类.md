## 1. 概述 <a id="overview"></a>

- **目标**：落地前端**根系基类**——抽象类 `BaseFrontend` 与等价组合式 `useFrontendBase`，为一切前端基类（契约/数据根 `BaseApi`/`createCrudStore`、组件根 `BaseComponent`、机制基类、域基类）提供**通用字段与通用方法**（命名空间、实例标识、运行环境、只读配置视图、日志、错误上报、配置读取、i18n 取词、生命周期钩子），双端（`frontend/` + `frontend-mobile/`）同款。
- **范围**：需求 [02-1](../../../需求/02_需求_基础组件类.md#r02-1)；`frontend/` 与 `frontend-mobile/` 各一套根系实现与用例；同步《前端基类清单》《架构设计 · 前端架构》的落点与状态登记。
- **依据**：《组件设计》[01_组件设计_根系基类](../../../../../../设计/组件设计/02_基础组件类/01_机制基类/01_组件设计_根系基类/01_组件设计_根系基类.md)（契约与原型）、《[前端开发规范](../../../../../../规范/前端开发规范.md)》「前端基类体系（开放式，强制）」节（§3.1 强制用法 / §3.4 继承与组合分工）、《[前端基类清单](../../../../../../前端基类清单.md)》「根系与组件根」「目录与依赖」节、《[架构设计 · 前端架构](../../../../../../设计/架构设计/08_架构设计_前端架构.md)》「组件体系（基类体系与目录登记）」节、《[日志规范](../../../../../../规范/日志规范.md)》、《[命名规范](../../../../../../规范/命名规范.md)》「前端命名」节。
- **边界**：不含契约/数据根（阶段一已交付，本任务**只接根系、不改其代码**）；不含组件根与机制基类（子任务 02、03）、域基类（子任务 04）、扩展登记机制（子任务 05）、请求封装/权限指令/格式化工具（子任务 06）。

## 4. 契约设计 <a id="contract"></a>

### 4.1 通用字段 <a id="fields"></a>

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| `ns` | `string` | 命名空间（日志前缀 / 样式前缀 / 埋点域）；默认 `bms`，空白串回落默认 |
| `identifier` | `string` | 实例标识（日志与错误上报定位）；默认取 `ns` |
| `env` | `'dev' \| 'test' \| 'prod'` | 运行环境，**实时读**运行期配置（构造后 `configureFrontendBase` 生效） |
| `config` | `Readonly<Record<string, unknown>>` | **按命名空间解析后**的只读配置视图（`${ns}.${key}` 覆盖同名全局键），每次访问取快照 |

### 4.2 通用方法 <a id="methods"></a>

| 方法 | 签名 | 口径 |
| --- | --- | --- |
| `log` | `(level: LogLevel, message: string, meta?: Record<string, unknown>) => void` | 分级过滤（低于 `logLevel` 丢弃）→ 指纹去重限流 → sink（默认 console 分级输出） |
| `reportError` | `(error: unknown, meta?) => void` | 归一化为 `{ name, message, stack }` → 指纹去重限流 → sink（默认 console.error）；**任何输入都不抛错、不阻断业务** |
| `getConfig` | `<T = unknown>(key: string, fallback?: T) => T` | 从解析后视图取值；缺失返回 `fallback`（不抛错） |
| `t` | `(key: string, params?: Record<string, unknown>) => string` | 委托 vue-i18n 全局实例；未就绪 / 缺词回退 `key` 原文 |
| `onBaseCreated` / `onBaseDisposed` | `protected` 钩子 | 构造时触发 `onBaseCreated`；`dispose()` 触发 `onBaseDisposed`（供子类扩展，不改根系行为） |
| `dispose` | `() => void` | **幂等**释放入口（钩子触发者）；重复调用无副作用 |

> `dispose()` 属**新增**（设计节点只列钩子未列触发者），按《前端开发规范》§3.2「新增为兼容变更」处理，见 §12 对齐记录。

### 4.3 运行期配置与构建期解析 <a id="config"></a>

```ts
export interface FrontendRuntimeConfig {
  env: 'dev' | 'test' | 'prod'
  logLevel: 'debug' | 'info' | 'warn' | 'error'
  values: Record<string, unknown>   // 配置键值（扁平键）
  windowMs: number                  // 去重限流窗口，默认 5000
}
export interface FrontendConfigPatch extends Partial<FrontendRuntimeConfig> {}

export function resolveBuildConfig(): FrontendRuntimeConfig   // 构建期解析：VITE_APP_ENV + VITE_* → 默认值
export function configureFrontendBase(patch: FrontendConfigPatch): void  // 运行期覆盖（浅合并，幂等）
export function resetFrontendBaseConfig(): void               // 复位为构建期默认（测试 / 热重载）
export function getFrontendRuntimeConfig(): Readonly<FrontendRuntimeConfig>
export function setFrontendSinks(sinks: { log?: LogSink; error?: ErrorSink }): void
```

- **env 解析**：`VITE_APP_ENV` ∈ {`dev`,`test`,`prod`} 为准；缺失 / 非法 → `import.meta.env.PROD ? 'prod' : 'dev'`。
- **values 解析**：取所有 `VITE_` 前缀键（**排除** `VITE_APP_ENV`），键名去前缀 → 小写 → `_` 转 `-`（`VITE_API_BASE` → `api-base`）；构建期值参与运行期合并。
- **logLevel 默认**：`env === 'prod'` 时 `warn`，否则 `debug`（可被 patch 覆盖）。
- **运行期接入**：`configureFrontendBase({ values })` 为唯一入口，后端「系统参数」就绪后由应用启动流程调用（阶段六/八回补），**根系不改**。

### 4.4 日志与错误上报（最小实现） <a id="log"></a>

```ts
export interface LogRecord { level; ns; identifier; message; meta?; repeat: number; timestamp: string }
export interface ErrorRecord { ns; identifier; name; message; stack?; meta?; repeat: number; timestamp: string }
export type LogSink = (record: LogRecord) => void
export type ErrorSink = (record: ErrorRecord) => void
```

- **指纹**：日志 `level|ns|message`；错误 `name|message|stack`。
- **去重限流**：同指纹在 `windowMs` 内只**输出一次**（首条 `repeat = 1`），窗口内后续同指纹被折叠并计数；窗口过期后再次出现时以累计 `repeat` 输出一条汇总（对齐组件设计 §8「日志风暴 / 错误上报重复」边界）。
- **生产分级**：由 `logLevel` 控制；默认 sink 映射 `console.debug/info/warn/error`，前缀 `[ns]`；`timestamp` 为 ISO 字符串。
- **不阻断**：sink 抛错被吞并降级为 `console` 输出；`reportError` 对 `string` / 任意对象 / `undefined` 均可归一化。
- **后端上报**：本任务只留 `setFrontendSinks` 注入点（阶段八/十三接入），**不发任何网络请求**。

### 4.5 组合式等价（`useFrontendBase`） <a id="composable"></a>

```ts
export function useFrontendBase(options?: FrontendBaseOptions): UseFrontendBaseReturn
// UseFrontendBaseReturn = { ns, identifier, env, config, log, reportError, getConfig, t, dispose }
```

- 内部以「作用域子类」实例承载同一套能力（**等价口径**），`env` / `config` 以 getter 暴露（实时读，不引入响应式——根系无响应式）；
- 处于组件 / 副作用作用域内（`getCurrentScope()` 非空）时经 `onScopeDispose` 自动 `dispose()`；作用域外调用不报错（可手动 `dispose`）；
- 方法以箭头函数绑定，支持解构使用（不丢 `this`）。

### 4.6 失败分支与边界 <a id="edge"></a>

| 场景 | 行为 |
| --- | --- |
| 配置缺失 / 未注入 | `getConfig` 返回 `fallback`；`env` 回构建期推断 |
| 非法 `VITE_APP_ENV` | 回退 `PROD ? 'prod' : 'dev'` |
| 命名空间空白 | 回落 `bms` |
| i18n 未就绪 / 缺词 | `t()` 返回 `key` 原文 |
| 日志风暴 / 错误重复上报 | 指纹去重 + 窗口限流 + `repeat` 计数 |
| sink 抛错 | 吞掉并降级输出，不影响调用方 |
| `reportError` 传入非 Error | 归一化为 `{ name: 'Error', message: String(error) }` |
| `dispose()` 重复调用 | 幂等（钩子只触发一次） |
