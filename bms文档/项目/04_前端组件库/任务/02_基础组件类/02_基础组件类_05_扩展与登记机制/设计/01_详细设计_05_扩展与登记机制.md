## 4. 契约设计 <a id="contract"></a>

### 4.1 继承护栏（AST，`tests/guard-inheritance.spec.ts`） <a id="inheritance"></a>

扫描范围与规则（正样例即当前仓库，全部通过；违规样例见 §4.4）：

| # | 规则 | 检查方式 |
| --- | --- | --- |
| R1 | `src/base/*.ts`：`BaseFrontend` 无父类；`BaseComponent` → `BaseFrontend`；`BaseCapability` / `BasePlaceholder` / `BaseAsyncResource` / `BaseRegistry` / `BaseSubscription` → `BaseComponent`；`BaseError` → 标准 `Error` | TS AST：类声明 `extends` 标识符比对期望父类表 |
| R2 | `src/components/base/**/use*.ts`：预置片段实现必须调用 `declareFragment('<key>')`（key 属 `fragments.ts` 表） | AST：函数体 `CallExpression` 名称 + 首参字面量 |
| R3 | 域基类组合式（`useXxxBase.ts`）：不声明片段 key，但必须组合至少一个片段（调用 `use<Fragment>`）或字段上下文机制 | AST：调用表达式集合比对 |
| R4 | 域基类包装（`BaseXxx.vue`）：`script` 中必须调用 `useComponentBase`（组件根）与同域 `useXxxBase` | SFC 解析 script/scriptSetup → TS AST |

- **实现**：`@vue/compiler-sfc` 的 `parse()` 取 SFC 脚本（`script` / `scriptSetup`）→ `typescript.createSourceFile` → 遍历 `ClassDeclaration` / `CallExpression`；纯函数 `scanInheritance(files: { path, source }[]): Problem[]`（违规样例可直接注入）。
- **产出**：`expect(scanInheritance(repoFiles)).toEqual([])`；违规含文件与原因，`Problem = { file: string; rule: string; message: string }`。

### 4.2 依赖边界（`tests/guard-dependency.spec.ts`） <a id="dependency"></a>

| # | 规则 | 说明 |
| --- | --- | --- |
| R1 | `src/base/**` 不得 import `@/components/**`（含相对路径 `../components/**`） | 机制层不反向依赖片段层 / 具体组件 |
| R2 | `src/components/base/**` 不得 import 具体组件与 UI 库：`@/views/**`、`@/layouts/**`、`element-plus`、`@element-plus/**`、`vant` | 基类不依赖具体组件；域基类框架无关（双端同款基线） |
| R3 | 片段→片段依赖单向且登记：以 `fragments.ts` 的 `depends` 为权威，扫描片段实现（`useXxx.ts`，非 `useXxxBase`）间 import，断言「被依赖片段 ∈ depends」且**无环**（DFS） | 片段依赖须单向并登记；反向依赖 / 循环静态拦截 |
| R4 | `src/components/base/**` 不得 import `axios` / `pinia` / `vue-router` / `vue-i18n` | 横切能力经根系出口 / 能力片段取得，不得重复实现（仅允许 `vue` 与同层片段 / 机制层） |

- **实现**：TS AST 提取 import 说明符（含 `import type`）；纯函数 `scanDependency(files, fragments): Problem[]`。
- **说明**：R3 的 import→片段映射按目录名（`./<dir>` / `../<dir>/…`）归一；域基类组合式（`useXxxBase`）不被解析为片段（不参与片段图）。

### 4.3 清单对账（`tests/guard-manifest.spec.ts`） <a id="manifest"></a>

- **输入**：`../bms文档/前端基类清单.md`（monorepo 相对路径）+ 代码侧文件集与 `fragments.ts`。
- **解析**：
  - §2 角色总览表：形如 `| 角色 | ... | BaseXxx ... | ... 状态 |`——抽取机制基类行与域基类行；
  - §5 能力片段表：`| `useXxx` | `key` | depends | 职责 |`——抽取 `${'`key`'}` 与 depends 列；
  - §6 域基类节：4 件实现落点（`BaseChart` 规则行不要求文件）。
- **双向断言**：
  1. 清单『能力片段』节 ≡ 代码 `FRAGMENTS`（key / depends 逐项相等；条数一致）；
  2. 每个片段实现文件存在（`src/components/base/<域>/useXxx.ts`，域目录按 §7 口径解析；片段实现 ↔ 清单双向）；
  3. 清单『角色总览』节 机制基类 ↔ `src/base/` 文件存在（`BaseXxx` 导出）；
  4. 清单 §6 域基类 4 件 ↔ 目录 + `BaseXxx.vue` + `useXxxBase.ts` 存在；`BaseChart` 允许只有规则行。
- **实现**：Markdown 表格区间解析（正则 + 节标题定位）；纯函数 `reconcileManifest(manifestText, codeIndex): Problem[]`（漏登记 / 僵尸条目双向）。

### 4.4 新增流程成文与演练（`tests/guard-evolution.spec.ts`） <a id="evolution"></a>

- **成文**：《前端基类清单》『扩展与演进』节补**新增演练步骤（可执行）**：① 候选（满足复用 + 接口可定）→ ② 设计节点（契约 + 原型）→ ③ 评审确认（question 逐项）→ ④ 清单登记（§5 / §6 + `fragments.ts`）→ ⑤ 护栏通过（四类用例全绿）→ ⑥ 消费方回引。`02_04` 域基类（4 件 + 1 规则）按此链路交付，作为真实案例引用。
- **fixture 演练**（护栏自身可失败验证）：
  1. 违规继承样例（`class Demo extends Object` / 片段未 `declareFragment`）→ `scanInheritance` 报错；
  2. 反向依赖样例（`src/base/x.ts` import `@/components/base`）→ `scanDependency` 报错；
  3. 对账差异样例（片段代码有、清单无；清单有、代码无）→ `reconcileManifest` 报错；
  4. 正样例（当前仓库扫描结果）→ 无报错。
- **目录约定**：新增护栏用例一律落 `tests/guard-*.spec.ts`，扫描核心放 `tests/helpers/guard/`（纯函数、可注入 fixture）。

### 4.6 机制未挂接升级评估结论 <a id="unattached"></a>

- **结论：保持开发态告警**（`warnUnattachedMechanism`），不升级构建期硬失败。
- **理由**：片段 / 域基类组合式允许脱离组件根独立使用（工具函数、独立测试、非组件场景），硬失败将阻断合法用法；现行为已保证「同一机制同进程一次告警、生产态零输出」。
- **再评估触发条件**：出现生产事故源于机制未挂接，或「不注册不可用」（`10_02`）落地后语义变化时再评估。
- **留痕**：结论写《前端基类清单》『扩展与演进』节 / 《前端开发规范》§3.5 注记；计划 §3.1 第 12 行划销。

## 5. 双端同款 <a id="dup"></a>
