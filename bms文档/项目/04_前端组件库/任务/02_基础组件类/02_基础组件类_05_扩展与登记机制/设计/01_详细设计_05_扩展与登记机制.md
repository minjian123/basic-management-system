## 4. 契约设计 <a id="contract"></a>

### 4.1 继承护栏（旧护栏，随旧层删除，历史经 git 追溯） <a id="inheritance"></a>

扫描范围与规则（旧护栏；现行护栏为 `frontend/packages/core/tests/guard-core-framework-agnostic.spec.ts` + `frontend/packages/core/tests/contracts/*.spec.ts`）：

| # | 规则 | 检查方式 |
| --- | --- | --- |
| R1 | `frontend/packages/core/src/{base,mechanisms}/*.ts`：`BaseFrontend` 无父类；`BaseComponent` → `BaseFrontend`；`BaseCapability` / `BasePlaceholder` / `BaseAsyncResource` / `BaseRegistry` / `BaseSubscription` → `BaseComponent`；`BaseError` → 标准 `Error` | TS AST：类声明 `extends` 标识符比对期望父类表 |
| R2 | `frontend/packages/core/src/capabilities/*.ts`：预置能力实现必须经 `manifest.ts` 登记（`registerKnownCapabilities`；key 属 `capabilityManifest` 表） | 模块加载即登记 + `knownCapabilitiesView` 比对 |
| R3 | 域能力类（`frontend/packages/core/src/capabilities/<域>.ts`）：组合面齐备（`BaseCapability` 子类 + `manifest.ts` 登记） | AST：调用表达式集合比对 |
| R4 | 域包装（按需形态，历史未落码）：`script` 中调用 `useComponentBase`（组件根） | SFC 解析 script/scriptSetup → TS AST |

- **实现**：旧护栏（随旧层删除，历史经 git 追溯）；现行护栏扫描核心为 `frontend/packages/core/tests/guard-core-framework-agnostic.spec.ts`。
- **产出**：`expect(...).toEqual([])`；违规含文件与原因（文件 / 规则 / 说明）。

### 4.2 依赖边界（`frontend/packages/core/tests/guard-core-framework-agnostic.spec.ts`） <a id="dependency"></a>

| # | 规则 | 说明 |
| --- | --- | --- |
| R1 | `frontend/packages/core/src/**` 不得 import `@/components/**`（含相对路径 `../components/**`） | 机制层不反向依赖能力层 / 具体组件 |
| R2 | `frontend/packages/core/src/capabilities/**` 不得 import 具体组件与 UI 库：`@/views/**`、`@/layouts/**`、`element-plus`、`@element-plus/**`、`vant` | 基类不依赖具体组件；域基类框架无关（同接口多实现基线） |
| R3 | 能力→能力依赖单向且登记：以 `manifest.ts` 的 `depends` 为权威，扫描能力实现（`*.ts`）间 import，断言「被依赖能力 ∈ depends」且**无环**（DFS） | 能力依赖须单向并登记；反向依赖 / 循环静态拦截 |
| R4 | `frontend/packages/core/src/capabilities/**` 不得 import `axios` / `pinia` / `vue-router` / `vue-i18n` | 横切能力经根系出口 / 能力类取得，不得重复实现（仅允许 `vue` 与同层能力 / 机制层） |

- **实现**：现行护栏 `frontend/packages/core/tests/guard-core-framework-agnostic.spec.ts`（核心零框架依赖 + 包依赖面为空）。
- **说明**：R3 的 import→能力映射按目录名归一；域能力类（`frontend/packages/core/src/capabilities/<域>.ts`）不参与旧护栏能力依赖图。

### 4.3 清单对账（`frontend/packages/core/tests/contracts/s2-capability-matrix.spec.ts`） <a id="manifest"></a>

- **输入**：`../bms文档/前端基类清单.md`（monorepo 相对路径）+ 代码侧文件集与 `manifest.ts`。
- **解析**：
  - §2 角色总览表：形如 `| 角色 | ... | BaseXxx ... | ... 状态 |`——抽取机制基类行与域基类行；
  - 『能力』节：`| `BaseXxx` | `key` | depends | 投影（@bms/vue） | 职责 |`——抽取 `${'`key`'}` 与 depends 列；
  - 『域基类』节：4 件实现落点（`BaseChart` 规则行不要求文件）。
- **双向断言**：
  1. 清单『能力』节 ≡ 代码 `capabilityManifest`（key / depends 逐项相等；条数一致）；
  2. 每个能力实现文件存在（`frontend/packages/core/src/capabilities/<域>.ts`，能力落点按『目录与依赖』节 口径解析；能力实现 ↔ 清单双向）；
  3. 清单『角色总览』节 机制基类 ↔ `frontend/packages/core/src/{base,mechanisms}/` 文件存在（`BaseXxx` 导出）；
  4. 清单『域基类』节 4 件 ↔ `frontend/packages/core/src/capabilities/{input-control,display-control,tree-data,editor-kernel}.ts` 存在；`BaseChart` 允许只有规则行。
- **实现**：`frontend/packages/core/tests/contracts/s2-capability-matrix.spec.ts`（能力矩阵：`manifest.ts` ↔ 机制登记 ↔ 注册表 → 可创建）；清单 ↔ 代码对账护栏（新体系版）待按新体系重建。

### 4.4 新增流程成文与演练（`frontend/packages/core/tests/contracts/s2-behaviors.spec.ts`） <a id="evolution"></a>

- **成文**：《前端基类清单》『扩展与演进』节补**新增演练步骤（可执行）**：① 候选（满足复用 + 接口可定）→ ② 设计节点（契约 + 原型）→ ③ 评审确认（question 逐项）→ ④ 清单登记（『能力』/『域基类』节 + `manifest.ts`）→ ⑤ 护栏通过（四类用例全绿）→ ⑥ 消费方回引。`02_04` 域基类（4 件 + 1 规则）按此链路交付，作为真实案例引用。
- **fixture 演练**（护栏自身可失败验证）：
  1. 违规继承样例（`class Demo extends Object` / 能力未经 `manifest.ts` 登记）→ 契约断言拦截；
  2. 反向依赖样例（`frontend/packages/core/src/mechanisms/x.ts` import `@bms/vue`）→ 核心护栏拦截；
  3. 对账差异样例（能力代码有、清单无；清单有、代码无）→ 契约断言拦截；
  4. 正样例（当前仓库扫描结果）→ 无报错。
- **目录约定**：新增护栏用例一律落 `frontend/packages/core/tests/`（`guard-core-framework-agnostic.spec.ts` + `contracts/*.spec.ts`）。

### 4.6 机制未挂接升级评估结论 <a id="unattached"></a>

- **结论：保持开发态告警**（`warnUnattachedMechanism`），不升级构建期硬失败。
- **理由**：能力 / 域能力类允许脱离组件根独立使用（工具函数、独立测试、非组件场景），硬失败将阻断合法用法；现行为已保证「同一机制同进程一次告警、生产态零输出」。
- **再评估触发条件**：出现生产事故源于机制未挂接，或「不注册不可用」（`10_02`）落地后语义变化时再评估。
- **留痕**：结论写《前端基类清单》『扩展与演进』节 / 《前端开发规范》§3.5 注记；计划 §3.1 第 12 行划销。

## 5. 同接口多实现 <a id="dup"></a>

- 两工程各一份**同内容**实现（3 处常量修改 + `tests/helpers/guard/` + 5 份用例）；护栏扫描各自仓库 `src/`，清单对账读同一份 `../bms文档/前端基类清单.md`。
- 校验：`diff -r`（源码与用例逐字一致）；双端门禁（prettier / eslint / `vue-tsc` / Vitest + 覆盖率 / build + budget）。
- **CI**：护栏随 `npm run test:cov` 在 `desktop-check` / 移动端宿主（`frontend/apps/mobile`）检查 job 自动执行，无需改 `.gitlab-ci.yml`。
