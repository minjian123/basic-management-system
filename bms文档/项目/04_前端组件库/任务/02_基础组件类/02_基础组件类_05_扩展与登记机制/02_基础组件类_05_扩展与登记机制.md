## 2. 任务内容 <a id="content"></a>

1. 扩展流程落地：候选 → 设计节点（《组件设计》，契约与原型）→ 评审确认 →《[前端基类清单](../../../../../前端基类清单.md)》登记 → 同步《[架构设计 · 前端组件体系](../../../../../设计/架构设计/05_架构设计_前端组件体系.md)》与《[前端开发规范](../../../../../规范/前端开发规范.md)》。
2. 组合轨默认口径：组件以组合片段为主，派生域基类仅作语义归类（可选）；机制变更（根系 / 组件根 / 片段机制）须评估全链影响。
3. 兼容性口径：新增片段 / 基类为兼容变更；调整既有片段契约（行为 / 参数 / 事件）须评估使用方并升主版本标注。
4. 双端同款基线：`frontend/` 与 `frontend-mobile/` 同步扩展，不得只在单端加基类能力。
5. 目录与命名校验：机制层 `src/base/`、能力域 `src/components/base/<能力域>/index.ts`；基类 `BaseXxx`、片段 `useXxx`、机制层组合式 `useXxxBase` 符合《[命名规范](../../../../../规范/命名规范.md)》。
6. 护栏落地（本任务侧）：继承护栏、依赖边界测试、清单对账脚本；「不注册不可用」随微前端骨架任务（`10_02`）落地。
7. 演练一次新增（文档级 + 单测目录约定），验证流程可行。

## 3. 完成标准 <a id="accept"></a>

扩展流程与兼容口径成文并被至少一次新增演练验证；继承 / 依赖方向 / 清单对账三类护栏用例可查（注入违规可失败）；《前端基类清单》《前端开发规范》《架构设计 · 前端组件体系》三者口径一致；Vitest 与静态护栏全通过。
