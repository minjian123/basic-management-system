## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 清单 §2 对账误报后端对照名（`BaseNullObject` / `BaseProviderRegistry` / `BaseEventWorker` 等） | 解析取了整行文本，命中「职责」列里的后端对照说明 | 解析限定「基类 / 能力」列（第 3 列）取 `BaseXxx`；`manifest.ts` 修正 |
| 2 | 字段壳能力（字段上下文语义）被旧护栏当作能力误报 | 它是字段壳能力、非 31 预置能力 | 旧护栏（随旧层删除，历史经 git 追溯）按白名单处理，与清单『能力』节 注记口径一致 |
| 3 | 错误码改常量后既有用例是否受影响 | 既有用例均以常量（`NOT_IMPLEMENTED_CODE` 等）断言 | 无需改断言；仅注册表契约用例标题码值同步（`10002` → `10003`）；历史记录保留旧值作当日留痕 |
| 4 | AST 依赖导入方式（`typescript` 为 CJS）与 SFC 多脚本块 | `import ts from 'typescript'` 在 bundler 解析下不稳；SFC 需合并 `script` + `scriptSetup` | 用 `import * as ts`；`scriptOf` 拼接两个脚本块后统一解析 |
| 5 | 清单对账在独立克隆（无 `bms文档/`）时失败 | 清单是 monorepo 内路径 | `readManifest()` 缺省返回 `undefined` + `describe.skipIf`（CI 在 monorepo 内始终执行）；设计 §10 已注明 |
| 6 | 旧护栏能力依赖图对域能力类（`frontend/packages/core/src/capabilities/<域>.ts`）误建边 | 域能力类不参与旧护栏 `depends` 图 | 旧护栏（随旧层删除，历史经 git 追溯）排除域能力类文件 |
| 7 | 护栏自身不可失败则无意义 | 需证明「违规可拦截」 | 旧护栏（随旧层删除，历史经 git 追溯）内置三类违规 fixture（错误父类 / 反向依赖 / 对账差异）+ 正样例断言 |
