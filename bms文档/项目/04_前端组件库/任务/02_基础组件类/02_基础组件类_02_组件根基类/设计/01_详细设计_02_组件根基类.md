## 4. 契约设计 <a id="contract"></a>

### 4.1 组件根通用 props 与状态属性协议 <a id="props"></a>

| prop | 类型 | 默认 | 口径 |
| --- | --- | --- | --- |
| `size` | `'small' \| 'default' \| 'large'` | `'default'` | 写根元素属性 `data-size`，映射令牌 `--bms-size-*` |
| `density` | `'compact' \| 'default' \| 'loose'` | 未设（继承） | 未设**不写** `data-density`（由上层容器 / 用户偏好决定）；设置时写属性并映射 `--bms-density-*` |
| `ns` | `string` | `'bms'` | 命名空间：class 前缀（`${ns}-`）、日志前缀、埋点域；空白串回落 `bms` |
| `loading` | `boolean` | `false` | 写 `aria-busy`，并加状态类 `is-loading` |
| `disabled` | `boolean` | `false` | 写 `aria-disabled`，并加状态类 `is-disabled` |
| `visible` | `boolean` | `true` | `false` ⇒ **不渲染**（与 `v-show` 区别：不是隐藏而是不产出 DOM） |
| `dataTest` | `string` | `''` | 非空时写根元素属性 `data-test` |

- **属性协议**：组件根只写**属性**（`data-size` / `data-density` / `data-test`）与**状态类**（`is-loading` / `is-disabled`），不产出具体视觉；视觉由令牌文件的选择器 `[data-size='small']` / `[data-density='compact']` 提供（§4.5）。
- **命名空间 helper**：`nsClass(name?)` → `bms-<name>`（缺省只返回 `bms-` 前缀），供具体组件拼接自身 class。

### 4.2 组件根能力（类 `BaseComponent`） <a id="base-component"></a>

```ts
export type ComponentSize = 'small' | 'default' | 'large'
export type ComponentDensity = 'compact' | 'default' | 'loose'

export interface ComponentBaseOptions {
  ns?: string
  identifier?: string
  size?: ComponentSize
  density?: ComponentDensity
  loading?: boolean
  disabled?: boolean
  visible?: boolean
}

export abstract class BaseComponent extends BaseFrontend {
  constructor(options?: ComponentBaseOptions)
  get size(): ComponentSize
  get density(): ComponentDensity | undefined
  get loading(): boolean
  get disabled(): boolean
  get visible(): boolean
  setProps(patch: Partial<ComponentBaseOptions>): void        // 运行期更新（组合式/包装同步用）
  nsClass(name?: string): string
  rootAttrs(extra?: Record<string, unknown>): Record<string, unknown>   // data-* / aria-* / 状态类合并
  passthroughAttrs(attrs: Record<string, unknown>): Record<string, unknown>  // 过滤内部键后的透传面
  readonly mechanisms: MechanismRegistry                      // 机制基类装配点
  protected onComponentMounted(): void
  protected onComponentUnmounted(): void
}
```

| 能力 | 口径 |
| --- | --- |
| attrs 透传 | **单根元素**约定；未声明属性 / 事件透传根元素；`class` / `style` 与内部值**合并**（内部类在前）；内部保留键不出现在透传面（`data-size` / `data-density` / `aria-disabled` / `aria-busy` / `data-test` 由 `rootAttrs` 统一产出，避免重复） |
| 令牌消费 | 不硬编码色值与尺寸；只写属性，视觉由令牌选择器提供（具体组件同样只消费令牌） |
| i18n | 经根系 `t`，组件不硬编码文案 |
| 生命周期埋点 | `base-mounted` / `base-unmounted`（包装组件事件）+ 可选 `trackEvent(name, meta?)`（经根系 `log('debug')`，生产静默由 `logLevel` 控制） |
| 可访问性基础 | `rootAttrs` 产出 `aria-disabled`（`disabled` 时）/ `aria-busy`（`loading` 时）；`role` / `tabindex` 由具体组件或交互片段细化 |
| `expose` 规范 | 包装组件 `defineExpose({ base, mechanisms, setProps })`；具体组件按需追加（`focus` / `blur` / `validate`），命名不加前缀 |
| `mechanisms` | 见 §4.4 |

### 4.3 组合式与组件包装 <a id="composable"></a>

```ts
export function useComponentBase(
  props?: Partial<ComponentBaseOptions> & Record<string, unknown>,
): UseComponentBaseReturn
// UseComponentBaseReturn = {
//   ns, identifier, size, density, loading, disabled, visible,
//   nsClass, rootAttrs, passthroughAttrs, mechanisms, setProps, dispose,
// }
```

- 传入**响应式 props 对象**时可保持响应（getter 实时读 `props.x`）；传入普通对象等价于一次性配置；不传则用默认值。取值优先级：**props 提供的键 > `setProps` 运行期更新 > 构造默认值**（props 是声明来源时以 props 为准）。
- 与类版**能力等价**（同一套 `ComponentBaseOptions` 语义），实现复用 `BaseComponent` 的静态工具函数，避免两套口径。
- 组合式处于组件 / 副作用作用域内时经 `onScopeDispose` 自动 `dispose()`（与根系一致）。

**`BaseComponent.vue`（组件包装）**：

| 项 | 设计 |
| --- | --- |
| props | `ns` / `identifier` / `size` / `density` / `loading` / `disabled` / `visible` / `dataTest`（同 §4.1，均带默认值） |
| 根元素 | 单根 `<div>`（`inheritAttrs: false`，`v-bind="mergedAttrs"`），不引入额外布局样式 |
| attrs 合并 | 外部 `$attrs`（含 `class` / `style`）与 `rootAttrs()` 合并：内部状态类在前、外部 class 保留、`style` 合并 |
| `visible=false` | **不渲染**根元素（`v-if`），插槽不执行 |
| 插槽 | 默认插槽，作用域参数 `{ base }`（`UseComponentBaseReturn`） |
| 事件 | `base-mounted`（挂载后）/ `base-unmounted`（卸载后，先释放再发事件） |
| expose | `{ base, mechanisms, setProps }` |
| 使用口径 | 需要统一组件根行为的组件包一层即可；逻辑优先直接 `useComponentBase()` |

### 4.4 机制基类装配点（`mechanisms`） <a id="mechanisms"></a>

```ts
export interface MechanismLike {
  readonly mechanismKey: string                   // 'placeholder' | 'resource' | 'subscription'
  attachToComponent(owner: BaseComponent): void   // 由装配点调用（挂接标记）
  detachFromComponent(): void                     // 脱离挂接（显式 detach，不释放资源）
  releaseFromComponent?(): void                   // 释放联动（组件根 dispose 时调用；未实现则回落 detach）
}
export interface MechanismRegistry {
  attach(mech: MechanismLike): () => void     // 返回 detach
  detach(mech: MechanismLike): void
  get<T extends MechanismLike>(key: string): T | undefined
  list(): readonly MechanismLike[]
  readonly size: number
}
```

- **挂接口径**：机制基类实例经 `base.mechanisms.attach(mech)`（组合式经 `base.mechanisms`）挂接；组件根在 `dispose()` 时**逆序释放全部**已挂机制（调 `releaseFromComponent()`，未实现则回落 `detachFromComponent()`）——即组件根释放会**联动取消订阅 / 释放资源**，再释放自身。
- **开发态校验**：机制基类构造时若未处于任何组件根装配上下文（无 `attachToComponent` 调用），开发态经根系 `log('warn', …)` 输出一次告警（生产静默）；实现用模块内「当前装配上下文」栈，由 `attach` / `detach` 维护，**不引入全局单例状态**（栈为空即视为未挂接）。
- **不阻断**：未挂接只告警，机制仍可独立使用（保证片段 / 兼容库场景可用）。

### 4.6 占位基类（`placeholder.ts`） <a id="placeholder"></a>

```ts
export type PlaceholderReason = 'pending' | 'null' | 'stub'
export type PlaceholderDegrade = 'empty' | 'disabled' | 'hidden'

export interface PlaceholderOptions { reason?; label?; degrade?; silentInProd?; owner? }   // owner 传入即构造时挂接
export class BasePlaceholder extends BaseComponent {
  get reason(): PlaceholderReason
  get label(): string
  get degrade(): PlaceholderDegrade
  get silentInProd(): boolean
  describe(): string
  mark(el?: Element | null): void                  // 加 data-placeholder=<reason>（开发态徽标）
  placeholderAttrs(): Record<string, unknown>      // data-placeholder / data-placeholder-label（供 rootAttrs 合并）
  assertImplemented(scope: string): void           // reason === 'stub' 时抛 BaseError（未实现）
  get interactive(): boolean                       // degrade === 'disabled' 时 false
  get allowRequest(): false                        // 占位态不发起请求（恒 false，供调用方守卫）
  setDegrade(degrade: PlaceholderDegrade): void
}
export function usePlaceholderBase(options?: PlaceholderOptions): UsePlaceholderBaseReturn
```

| 行为 | 口径 |
| --- | --- |
| 开发态标记 | 构造时输出一次 `describe()`（`reason` + `label`）；`mark(el)` 给根元素加 `data-placeholder`；`silentInProd=true` 时生产态不输出、不加标记 |
| 三类原因 | `pending`（依赖后端能力未就绪）/ `null`（恒空、恒成功）/ `stub`（调用即抛错）——对齐后端 `BasePlaceholder` / `BaseNullObject` / `BaseStub` |
| 三类降级 | `empty`（空态占位）/ `disabled`（保留结构、整体禁用、不请求）/ `hidden`（整块不渲染） |
| 不请求 | `allowRequest` 恒 `false`、`interactive` 在 `disabled` 下 `false`；调用方以此守卫，**不写缓存、无副作用** |
| `stub` 抛错 | `assertImplemented(scope)` 抛 `BaseError`（`code = 10001` 未实现段，登记为待对齐项，见 §10） |
| 契约测试 | 占位与真实实现跑同一套片段契约（片段任务内联，本任务只交付基类与自身用例） |

### 4.7 异步资源基类（`resource.ts`） <a id="resource"></a>

```ts
export type ResourceKind = 'timer' | 'subscription' | 'request' | 'instance'
export type ResourceHandle = (() => void) | AbortController | { dispose(): void } | { destroy(): void } | number

export interface AsyncResourceOptions { kind?; autoRelease?; onError?; owner? }   // owner 传入即构造时挂接
export class BaseAsyncResource extends BaseComponent {
  track(handle: ResourceHandle, kind?: ResourceKind): () => void   // 返回幂等释放函数
  addTimer(cb: () => void, ms: number, opts?: { repeat?: boolean }): () => void
  addAbort(): AbortController
  addDisposer(fn: () => void): () => void
  onRelease(cb: () => void): void          // 释放钩子（保存草稿 / 断开连接等）
  releaseAll(): void                       // 逆序释放（后登记先释放）
  get count(): number                      // 已登记资源数（`size` 已被组件根的尺寸档位占用）
  get released(): boolean                  // 是否已释放（组合式同样暴露）
  dispose(): void                          // 幂等；释放后拒绝新登记
}
export function useAsyncResourceBase(options?: AsyncResourceOptions): UseAsyncResourceBaseReturn
```

| 行为 | 口径 |
| --- | --- |
| 句柄归一化 | 函数 → 直接调用；`AbortController` → `abort()`；`{dispose}` / `{destroy}` → 调用之；`number` → 定时器 id（浏览器；`clearTimeout` + `clearInterval` 双清）；含 `ref` / `unref` 的对象（Node `Timeout`）→ 同样按定时器清；其余类型 → 开发态告警并忽略 |
| 自动释放 | 组合式绑定组件作用域（`onScopeDispose` → `releaseAll()`）；`autoRelease=false` 供长生命周期宿主显式管理 |
| 释放顺序 | **逆序**（对齐后端 `ResourceManager`）；先释放已登记资源、再执行释放钩子（同逆序）；单个失败经 `onError` + 根系告警上报，**不阻断**其余 |
| 幂等 | 释放函数、`releaseAll()`、`dispose()` 均幂等；`dispose()` 后 `track()` 拒绝登记并开发态告警 |
| 与订阅协作 | 订阅取消函数经 `track()` 登记（`kind='subscription'`），卸载自动取消 |
| 与请求协作 | `addAbort()` 返回的 `AbortController` 用于竞态取消（搜索联想 / 快速切 Tab），卸载自动 `abort` |

> 「四态（加载 / 成功 / 失败 / 空）与重试」按决策 9 归 `useAsyncTask` 片段（子任务 03）与请求层（子任务 06）；本基类只做资源登记与释放。

### 4.8 错误基类（`error.ts`） <a id="error"></a>

```ts
export const NOT_IMPLEMENTED_CODE = 10001   // 未实现（占位 stub）——段位待与后端清单对齐
export const RATE_LIMIT_CODE = 10005        // 限流（组件设计错误节点 §4）
export const PERMISSION_CODE = 30001        // 权限不足（组件设计错误节点 §4）

export interface BaseErrorInit { code: number; message?: string; userMessage?: string; data?: unknown; cause?: unknown }
export class BaseError extends Error {
  readonly code: number
  readonly userMessage: string
  readonly data?: unknown
  readonly cause?: unknown
  constructor(init: BaseErrorInit)
  static fromResponse(response: unknown, fallbackCode?: number): BaseError | null   // {code,message,data}；code === 0 或非响应结构返回 null
  toUserMessage(base?: Pick<BaseFrontend, 't'> | null): string                     // i18n error.{code} → 静态映射 → 通用回退
  report(base: Pick<BaseFrontend, 'reportError'>, meta?: Record<string, unknown>): void
  isAuth(): boolean          // 20000 ~ 29999
  isPermission(): boolean    // === PERMISSION_CODE
  isRateLimit(): boolean     // === RATE_LIMIT_CODE
}

export const ERROR_MESSAGES: Readonly<Record<number, string>>   // 内置最小映射（未映射时由调用方 i18n 兜底）
export function registerErrorMessages(map: Record<number, string>): void
export function messageForCode(code: number): string | undefined
```

| 行为 | 口径 |
| --- | --- |
| 继承 | `extends Error`（保留 `instanceof Error` / `message` / `stack`；`this.name = 'BaseError'`），经 `mechanisms` 语义**挂接在组件根机制层**（决策 6） |
| 响应解析 | `fromResponse` 仅接受 `{ code, message?, data? }` 且 `code !== 0`；`code === 0` 或结构不符返回 `null`（调用方不改既有成功路径） |
| 提示映射 | `toUserMessage()`：根系 `t('error.' + code)` 命中优先 → `ERROR_MESSAGES[code]` → 通用回退「操作失败，请稍后重试」；**禁止组件内硬编码错误文案** |
| 上报 | `report(base, meta)` 委托根系 `reportError`（附 `code` / `name` / `page` / `component` 元信息）；**不另建通道**，去重限流由根系负责 |
| 段位判定 | `isAuth`（2xxxx）/ `isPermission`（30001）/ `isRateLimit`（10005）供请求层与订阅基类分流；其余段位不做判定 |
| 用户取消 | 主动取消（`AbortController`）**不构造** `BaseError`、不提示、不上报（由调用方判断） |

### 4.9 订阅基类（`subscription.ts`） <a id="subscription"></a>

```ts
export type SubscriptionSource = 'realtime' | 'local' | 'placeholder'
export type SubscriptionHandler = (payload: unknown) => void

export interface SubscriptionOptions { source?; topicPattern?; onError?; owner? }   // owner 传入即构造时挂接
export class BaseSubscription extends BaseComponent {
  get source(): SubscriptionSource
  setSource(source: SubscriptionSource): void      // 'realtime' 未接入 → 告警并回落 'placeholder'
  subscribe(topic: string, handler: SubscriptionHandler): () => void   // 返回幂等取消函数，登记异步资源
  once(topic: string, handler: SubscriptionHandler): () => void
  unsubscribe(topic?: string): void
  publish(topic: string, payload?: unknown): void  // 本地发布（占位 / 本地组件通信）
  has(topic: string): boolean
  get topics(): readonly string[]
}
export function useSubscriptionBase(options?: SubscriptionOptions): UseSubscriptionBaseReturn
```

| 行为 | 口径 |
| --- | --- |
| 来源解耦 | 调用方只认 `topic` + `handler`；`source` 由基类按接入阶段选择：`placeholder`（默认，占位总线）/ `local`（显式本地）；`realtime` 在阶段五接入前**告警并回落** `placeholder` |
| 占位实现 | 不连 socket、不报错；`subscribe` 正常注册，`publish` 仅本地生效；真实推送接入后 `setSource('realtime')` 切换，**调用方不改** |
| 事件名 | `topic` 点分小写（`领域.动作`，与后端事件表同源）；开发态校验格式（`^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*)+$`），不符告警但**不阻断**；禁止自创驼峰事件名 |
| 卸载取消 | `subscribe` 返回的取消函数登记到异步资源基类（`kind='subscription'`），组件卸载自动取消、幂等；重复取消无副作用 |
| 迟到事件 | 取消后仍可能收到已入队回调（迟到事件），由业务侧幂等处理；基类不做隐式节流（去抖 / 批量归业务侧） |
| 本地发布 | `publish(topic, payload)` 仅在本地总线分发（同步回调）；不代替后端事件，不用于跨页面持久通信 |

## 10. 边界与开放项 <a id="boundary"></a>

- **不含**片段机制（`BaseCapability`）、注册表基类（`BaseProviderRegistry` / `BaseProvider`）——子任务 03；域基类——子任务 04；继承 / 依赖 / 清单对账护栏用例——子任务 05。
- **不含**真实实时推送连接（Socket.IO 接入、断线重连）——占位总线先行，真实接入随阶段五；本任务只保证「切换来源不改调用方」。
- **不含**请求四态与重试语义（归 `useAsyncTask` 片段与请求层）、不含统一错误提示 Toast 与 token 注入（子任务 06）。
- **令牌范围**：本次只落 size / density 与属性协议；`--color-*` / `--font-*` / `--space-*` / `--radius-*` 基础令牌随布局域任务落地，届时改为引用（登记为遗留归 `02_05`）。
- **错误码**：`10001`（未实现）为前端内建、**待与《后端基类清单》错误码段位对齐**；`10005` 限流与 `30001` 权限来自组件设计错误节点 §4，其余段位判定（3xxxx 细分等）不实现（挂接上游登记，归 `02_05`）。
- **未挂接告警**：机制基类脱离组件根使用时只**开发态告警**、不阻断（兼容片段独立使用场景）；是否升级为构建期硬失败待 `02_05` 护栏评估。
- **`density` 继承**：未设 `density` 时不写属性，视觉继承上层容器 / 用户偏好；上下文提供者（组件根之上的密度提供）留给布局域。
- **`mark()` 依赖 DOM**：类侧 `mark()` 接受元素参数（由包装或组件传入）；类侧不主动查找 DOM（无渲染依赖）。
