## 3. 实施过程 <a id="process"></a>

1. **上下文**：按《AI开发规范》§2 顺序读规范（前端开发规范 §3、命名规范）→ 设计（组件设计五节点 + 可交互原型、架构 05）→ 项目（需求 02-2、任务 02_02、计划、域总览）→ 现状（`src/base/` 三件、`main.ts`、tsconfig、vitest 配置、测试基座）。
2. **决策确认**（question 逐项，共十项）：① 组件根按节点落两文件并回写清单；② 交付 `BaseComponent.vue`；③ **顺带建最小令牌文件**（双端 + `main.ts` 导入）并回写《设计令牌》节点；④ 机制基类挂接 = 组件根 `mechanisms` 装配点 + 开发态校验；⑤ 组合式统一 `useXxxBase`；⑥ `BaseError extends Error` + 上报委托根系；⑦ Kiwi 按机制基类拆 5 条（双端共用）；⑧ 上游回写限清单 + 规范 §3（其余归 `02_05`）；⑨ 异步资源按节点实现（「四态与重试」归 `02_03` / `02_06`）；⑩ 双端同款。
3. **实现**（双端 `src/base/`，7 件）：
   - `BaseComponent.ts`：通用 props（`size` / `density` / `ns` / `loading` / `disabled` / `visible` / `dataTest`）、`rootAttrs`（`data-size` / `data-density` / `data-test` / `aria-disabled` / `aria-busy` + 状态类）、`passthroughAttrs`（过滤保留键）、`nsClass`、`trackEvent`、生命周期钩子、幂等 `dispose`（先逆序释放机制）；`MechanismRegistry` 装配点（`attach` / `detach` / `get` / `list` / `size` / `releaseAll`）+ `warnUnattachedMechanism`（开发态一次告警、生产静默、不阻断）。
   - `useComponentBase.ts`：组合轨等价能力；**读前同步 props**（props 提供的键 > `setProps` > 构造默认值），保证 `size` 与 `rootAttrs()` 同源；作用域内自动 `dispose`。
   - `BaseComponent.vue`：单根包装（`inheritAttrs: false` + 自定义合并：内部状态类在前、外部 `class` / `style` 保留）、`visible=false` 不渲染、插槽下发 `{ base }`、事件 `base-mounted` / `base-unmounted`（先释放再发）、`defineExpose({ base, mechanisms, setProps })`。
   - `placeholder.ts`：`BasePlaceholder` + `usePlaceholderBase`；三类原因（`pending` / `null` / `stub`）、三类降级（`empty` / `disabled` / `hidden`）、`describe` / `mark` / `placeholderAttrs` / `assertImplemented`（stub 抛 `BaseError`，码 `10001`）、`allowRequest` 恒 `false`、生产静默（`silentInProd`）。
   - `resource.ts`：`BaseAsyncResource` + `useAsyncResourceBase`；`track` 句柄归一化（函数 / `AbortController` / `{dispose}` / `{destroy}` / 定时器 id / Node `Timeout`）、逆序 `releaseAll`、释放钩子、幂等 `dispose`、释放后拒绝登记、单资源失败不阻断（`onError` + 上报）；`addTimer` / `addAbort` / `addDisposer` 便捷入口。
   - `error.ts`：`BaseError extends Error`（保留 `name` / `stack` / `cause`）+ `fromResponse` / `toUserMessage`（i18n `error.{code}` → 静态映射 → 通用回退）/ `report`（委托根系 `reportError`）/ 段位判定（`isAuth` / `isPermission` / `isRateLimit`）+ `ERROR_MESSAGES` / `registerErrorMessages`。
   - `subscription.ts`：`BaseSubscription` + `useSubscriptionBase`；`subscribe` / `once` / `unsubscribe` / `publish` / `has` / `topics`；来源解耦（`placeholder` 占位总线默认，`local` 显式；`realtime` 未接入时告警并回落）；取消函数登记内部异步资源（卸载自动取消、幂等）；事件名点分小写开发态校验（不阻断）。
4. **最小设计令牌**：`src/styles/tokens.scss`（双端同款，`main.ts` 导入）——size（small / default / large）与 density（compact / default / loose）档位变量 + 五个语义变量 + `[data-size]` / `[data-density]` 属性选择器；基础令牌（color / font / space / radius）留待布局域。
5. **Kiwi 登记（先登记后编码）**：按《KiwiTCMS部署使用说明》「用例约定 / 用例登记（脚本化批量）」节，用测试资产仓 `scripts/kiwi/register_cases.py` 批量登记（输入落 `scripts/kiwi/cases/2026-09-16_阶段四02-02_组件根基类.json`），回读得 **case id 700 ~ 704**（组件根 / 占位 / 异步资源 / 错误 / 订阅）。
6. **用例**（双端同款，5 份）：`base-component.spec.ts`（Kiwi 700，9 条）、`base-placeholder.spec.ts`（701，7 条）、`base-resource.spec.ts`（702，6 条）、`base-error.spec.ts`（703，6 条）、`base-subscription.spec.ts`（704，6 条）——本任务新增 34 条，双端合计 67 条全绿。
7. **双端同款**：`diff -r frontend/src/base frontend-mobile/src/base` 无差异；`src/styles/tokens.scss` 与五份用例逐字一致（同一 Kiwi 编号，双端共用）。
8. **验证**：见[测试记录](../测试/01_测试_02_组件根基类.md) §3。
9. **回写**：《前端基类清单》§2/§7、《前端开发规范》§3.1 / §3.2、《组件设计》组件根节点 §2/§3 与占位 / 异步资源 / 订阅节点 §2/§3（组合式更名）、错误节点 §1（继承口径）、《布局设计 · 设计令牌》（size / density 映射）、需求 02-2 与总览 / 域地图、任务 02_02 与域总览、计划（两表 + 甘特 + 头部计数工时）、阶段 README。
10. **提交**：代码（`feat(前端)`）与文档（`docs(项目)` 等）分笔提交；消费方任务 `02_03` ~ `02_06` 的「前置契约（已交付）」在同批文档提交内补。

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | `BaseAsyncResource.size` 与组件根 `size`（尺寸档位）冲突（`vue-tsc` TS2416） | 子类 getter 覆盖父类同名 getter 且类型不同 | 资源计数改名 `count`（`released` 保留）；详细设计 §4.7 同步，用例与组合式返回值一并更新 |
| 2 | 组合式 `setProps` 生效但 `rootAttrs()` 仍用实例旧值（getter 与 `rootAttrs` 不同源） | props 优先只在 getter 上实现 | 组合式改为**读前同步 props** 到实例（`sync()`），所有读路径同源；详细设计 §4.3 补优先级口径 |
| 3 | Node 运行时 `setTimeout` 返回 `Timeout` 对象，`number` 分支不匹配 → 登记被忽略并发告警 | 句柄归一化只覆盖浏览器定时器 id | `toReleaser` 增「含 `ref` / `unref` 的对象按定时器清理」分支；详细设计 §4.7 句柄表同步 |
| 4 | 组件根 `dispose()` 后订阅仍能收到 `publish`（释放未联动取消） | 装配点只调 `detachFromComponent`（脱离 ≠ 释放） | `MechanismLike` 增 `releaseFromComponent()`（默认回落 `detach`），装配点 `releaseAll` 走释放联动；三个机制基类实现之；详细设计 §4.4 同步 |
| 5 | `releaseAll()` 后再调资源释放函数会二次执行释放动作 | 释放幂等标记在返回的函数闭包里，`releaseAll` 绕过了它 | 幂等标记移到 `ResourceEntry.done`，`releaseEntry` 统一判定；用例 ⑮ 逆序期望按真实语义修正 |
| 6 | `vue/require-default-prop` 对包装组件的可选 props 报错（`eslint --max-warnings 0`） | `withDefaults` 只给了部分默认值 | 全量补默认（`ns: 'bms'` / `identifier: ''` / `density: undefined` 等） |
| 7 | 订阅基类 `owner` 参数未生效（装配点查不到） | 构造器漏掉 `options.owner.mechanisms.attach(this)` | 补齐；用例 ㉛ 覆盖 owner 装配与组件根释放联动 |
| 8 | `placeholder.ts` 函数覆盖率 68.75%（低于新增文件 70% 口径） | 组合式返回的 getter / 方法未被断言 | 扩「组合式等价」断言（全量 getter 与 `mark` / `setDegrade` / `assertImplemented` / `detach` 路径），覆盖率升至 96.87% |
