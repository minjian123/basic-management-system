## 1. 设计目标与范围 <a id="goal"></a>

落地「纯 TS 框架无关核心 + 可替换渲染插件」的**工程骨架与机器护栏**，为后续基类实现（`02_01` ~ `02_06`）提供可跑的家与门禁：

- 复用根目录既有 workspace 配置（`package.json` / `pnpm-lock.yaml` / `tsconfig.base.json` / `.npmrc`，均未随前端清空删除）；
- 本期**只建 `frontend/packages/core` 最小可跑骨架**；`vue` / `ui-ep` / `ui-vant` 与宿主随后续需求域补；
- 本期交付：核心框架无关护栏、错误码段位常量、契约用例工厂最小骨架；契约套件与清单对账护栏随 `02_03` / `02_04` / `02_05` 收口。

不在本期：基类实现（`02_01` ~ `02_06`）、渲染插件 / 宿主骨架、Module Federation 与微前端（域 10）、契约套件全量断言。

## 3. 工程结构与配置 <a id="structure"></a>

```text
frontend/packages/core/
├── package.json          # @bms/core（private；无 dependencies / peerDependencies；exports . 与 ./testing）
├── tsconfig.json         # 继承 ../../../tsconfig.base.json，types: ["node"]
├── eslint.config.js      # flat config（typescript-eslint + skip-formatting）
├── vitest.config.ts      # environment: node，include tests/**/*.spec.ts
├── src/
│   ├── index.ts          # 运行时入口（导出 ErrorCodes / ErrorCode）
│   └── mechanisms/
│       └── error-codes.ts # 前端内建错误码段位常量
├── testing/
│   └── index.ts          # 契约用例工厂骨架（describeContract）
└── tests/
    ├── guard-core-framework-agnostic.spec.ts
    └── error-codes.spec.ts
```

- **源码直出**：`exports` 指 `./src/index.ts` 与 `./testing/index.ts`，消费方（插件 / 宿主）由其构建器编译；核心不做独立构建步骤（与既往口径一致）。
- **无运行时依赖（强制）**：`dependencies` / `peerDependencies` 均为空，护栏校验；`vue` / `element-plus` / `vant` / 其它 `@bms/*` 仅可出现在插件包。
- **工具链**：复用根 `devDependencies`（`typescript ~6.0.2` / `vitest ^5` / `eslint ^10` / `typescript-eslint ^8`），核心包不新增依赖、**不改 `pnpm-lock.yaml`**。

## 4. 接口 / 契约与边界 <a id="contract"></a>

### 4.1 错误码段位 <a id="error-codes"></a>

`src/mechanisms/error-codes.ts`：

```ts
export const ErrorCodes = {
  CAPABILITY_VIOLATION: 10001,   // 能力声明 / 依赖校验违规（PARAM）
  PROVIDER_NOT_REGISTERED: 10002, // 未注册不可用
  REGISTRY_CONFLICT: 10003,      // 注册表唯一性冲突（CONFLICT）
  RATE_LIMITED: 10005,           // 限流
  PERMISSION_DENIED: 30001,      // 权限
  NOT_IMPLEMENTED: 19001,        // 未实现（前端保留子段 19xxx）
} as const

export type ErrorCode = (typeof ErrorCodes)[keyof typeof ErrorCodes]
```

- 段位对齐平台（参数 / 未登记 / 冲突 / 限流 / 权限）；`19xxx` 为前端保留子段（《命名规范》「前端命名」节）；**不自造段位、不复用平台已发布码**。
- `BaseError`（`mechanisms/error.ts`）本体归 `02_05`，直接引用本常量。

### 4.2 契约用例工厂 <a id="testing"></a>

`testing/index.ts`（仅测试消费，`@bms/core/testing`；运行时入口不含）：

```ts
export function describeContract(name: string, define: () => void): void
```

- 作为「同一契约、多实现」断言套件的统一登记入口；各渲染插件在自己的 spec 中调用并传入本实现，跑同一套断言。
- 本期只交付入口与最小用例；具体契约套件（值 / 字段 / 输入 / 确认 / 权限 / 容器件 / 反馈件等）随 `02_03` / `02_04` / `02_05` 就位补齐（契约用例工厂在此文件追加导出）。

### 4.3 核心框架无关护栏 <a id="guard"></a>

`tests/guard-core-framework-agnostic.spec.ts`（随 `pnpm run core:check` 执行）：

- ① 扫描 `src/**/*.ts` 的 `import` / `export ... from` 来源，命中禁止项（`vue` / `@vue/*` / `element-plus` / `vant` / `@bms/{vue,ui-ep,ui-vant}` / `apps/`）即失败；
- ② 校验 `package.json` 的 `dependencies` 与 `peerDependencies` 为空；
- ③ fixture 护栏自检（构造违规样本必须被拦截）。

### 4.4 根门禁收敛 <a id="root-check"></a>

根 `package.json` 的 `lint` / `check` 本期改为只调用 core（`core:lint` / `core:check`）；四包脚本（`vue:*` / `ui-ep:*` / `ui-vant:*`）保留，随各包落地后挂回。理由：CI `core-check` 以 `frontend/packages/core/package.json` 存在为守卫执行根 `pnpm run check`，缺包时四包串联会直接失败。

## 5. 失败分支与边界 <a id="edge"></a>

| 边界 / 失败场景 | 处置 |
| --- | --- |
| 核心源码出现框架 import | 护栏 ① 失败，阻断 `core:check` |
| 核心包声明运行时依赖 | 护栏 ② 失败 |
| 根 `check` 仍枚举缺包 | 本期收敛为 core（第 4.4 节）；缺包报错即回归 |
| 子任务 01 ~ 06 追加源码 | 在 `src/index.ts` 追加导出；护栏自动覆盖新源码 |
| 契约套件未就绪 | 本期只留入口；`02_03` / `02_04` / `02_05` 追加，不阻塞本任务 |
| 本地 `node_modules` 缺工具链 | 已在役（tsc / eslint / vitest 可执行）；不新增依赖、不改锁文件 |

## 8. 边界与开放项 <a id="open"></a>

- **渲染插件 / 宿主骨架**（`vue` / `ui-ep` / `ui-vant` / `apps`）随后续需求域补；届时根四包脚本挂回。
- **契约套件全量断言**与**清单对账护栏**随 `02_03` / `02_04` 收口（本任务不交付具体断言）。
- **CI 基础镜像**：`deploy/ci/build-base.sh` / `Dockerfile.frontend` 仍引用已清空的 `frontend/apps/{desktop,mobile}/pnpm-lock.yaml`；`ci-base-build` 在其触发路径变更时会失败。该问题属阶段级（前端整体重建中），登记为遗留，随宿主包重建闭环；本任务不改 CI 脚本、不改 `pnpm-lock.yaml`（避免触发 `ci-base-build`）。
- **Node 版本**：CI 镜像 `node22`；本地 Node 24 可跑。核心包不声明 `engines`（避免与镜像口径冲突，随宿主包统一）。

## 9. 对齐记录 <a id="align"></a>

对齐后端已验证的基类体系做法（只引文档，不引代码）：

- **工程与护栏分层**：对齐后端「CI 静态护栏（继承 / 层依赖 / 错误码段位）」与「逐基类 + contracts + crosscut」测试分层——本任务落核心框架无关护栏，契约套件（`tests/contracts` 类比）与 crosscut（组合轨边界）随基类域补。
