## 4. 联调（后端 `02_28`） <a id="integration"></a>

- **接口结论**：选项集**不设 HTTP 接口**（装载期注册、运行期只读），前端消费点只有「元数据下发的已解析快照」；本任务按**注入式占位**交付——未下发 `optionSets` 时件层空态降级、**零请求**，未伪造任何快照数据。
- **契约一致性**：`OptionItem` 字段（`value` / `label` / `label_key` ↔ `labelKey` / `color` / `disabled` / `sort`）与 `OptionSetInfo`（`optionSetKey` / `items`）逐项对齐；解析顺序「`sort` 升序 → 同 `value` 去重保留首个」前后端同口径（前端 `resolveOptionSetItems` 与后端 `BaseOptionSet.info()` 行为一致，各有用例锁定）。
- **职责边界**：注册冲突判定（同 value 异义 / 同 label 异值 / 同标识异义 / 产品覆盖基座）只在后端，前端**不重复实现**；前端仅做展示期归一（i18n 回退、颜色 / 禁用透传）。
- **待接通**：`layout-effective` 的 `optionSets` 实际下发随表单定制阶段；届时只需后端按上表结构下发，前端零改造（`createOptionSetResolver` 直接消费）。

## 5. 原型对照 <a id="prototype"></a>

**原型依据**：《[14_原型设计_选项集字段](../../../../../../设计/组件设计/06_字段类/14_组件设计_选项集字段/14_原型设计_选项集字段.html)》「① 枚举形态（widget 决定）」与「③ 只读回显与导入导出」页；实现载体为开发态核对页 `frontend/apps/desktop/field-check.html`（③ 选项集区，六形态真实组装）。

**逐页对照**（截图：`tmp/06-10-prototype-enum.png` 原型 / `tmp/06-10-field-check-section3.png` 实现）：

| 项 | 原型 | 实现 | 结论 |
| --- | --- | --- | --- |
| 单选 radio（默认） | `el-radio-group`，2-5 项全展示 | 同控件、高 / 中 / 低全展示 | 一致 |
| 单选 button | `el-radio-button`，强调操作感 | 同控件、选中态语义色一致 | 一致 |
| 单选 segmented | `el-segmented` 分段控件（原型按时间粒度，实现按优先级） | 同控件、单段选中 | 一致（形态一致，演示值集不同） |
| 单选 dropdown | `el-select` 可搜索 / 可清空 / 占位「请选择」 | 同控件（`searchable` / `clearable`），选项 3 演示 > 8 建议位 | 一致 |
| 多选 checkbox | `el-checkbox-group`，≤ 8 项 | 同控件、按选项集顺序回显 | 一致 |
| 多选 tag | 标签点选（`el-check-tag` 语义） | `CheckboxInput` tag 形态，选中态一致 | 一致 |
| 多选 dropdown-multi | `el-select multiple` + 折叠标签 | 同控件，折叠为「选项 1 × + 1」 | 一致 |
| 只读回显 | 原型「只读态」开关切换纯文本 | 独立只读件：单选 label / 多选顿号 | 一致 |
| 缺项回退（补充口径） | 原型未单列 | 缺项回显原值 + `data-missing`，只读不报错 | 一致（按设计 §3.6 补充） |

**结论**：六种形态的控件本体、选中态、只读回显与原型一致；差异仅在演示数据（选项值与数量），无形态 / 布局偏差。

**截图与控制台**：`tmp/06-10-field-check.png`（整页）、`tmp/06-10-field-check-section3.png`（选项集区）、`tmp/06-10-prototype-enum.png`（原型 ① 页）。控制台仅 favicon 404 与一次 Vite 依赖重优化 504（HMR 期，刷新后恢复），**无组件运行期报错**。
