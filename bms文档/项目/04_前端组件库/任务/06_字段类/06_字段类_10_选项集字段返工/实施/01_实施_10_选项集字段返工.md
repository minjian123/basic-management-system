## 2. 实施过程 <a id="process"></a>

```mermaid
flowchart LR
    A["决策确认（15 项）"] --> B["详细设计（定稿提交）"]
    B --> C["core 选项集领域与契约套件"]
    C --> D["core 元数据口径与计划结构"]
    D --> E["ui-ep 注入式解析工具"]
    E --> F["ui-ep 两件六形态"]
    F --> G["渲染协同与件名统一"]
    G --> H["测试拆分与用例迁移"]
    H --> I["Kiwi 登记与验证 / 原型对照"]
    I --> J["文档回写与提交"]
```

1. **决策确认（15 项）**：注入方式 / 元数据形状 / 装配落点 / 形态取值 / > 8 建议 / i18n / 缺项告警 / 空态降级 / 代码落点 / 旧 `options` / 用例编号 / 覆盖率 / 原型对照 / 渲染器文档 / 定制件范围，逐项经用户拍板（见设计 §1.1）。
2. **core 选项集领域**：新增 `domain/option-set.ts`——`OptionSetItem` / `OptionSetSnapshot` 类型，`resolveOptionSetItems`（sort 升序 → 同值去重保留首个 → 空值剔除 → labelKey 翻译三级回退 → 颜色 / 禁用归一）、`optionLabelOf` / `optionLabelsOf` / `missingOptionValues` / `buildOptionSetIndex` / `suggestOptionWidget`；新增契约套件 `testing/option-set.ts`（`describeOptionSetResolverContract`）并由 `core/tests/option-set.spec.ts` 自验。
3. **core 元数据口径**：`FieldRenderAttrs` 增 `optionSetKey`、`LayoutEffective` 增 `optionSets`；`normalizeField` 保留 `optionSetKey`，`option` / `option_multi` 的内联 `options` **归一丢弃**（开发态告警一条）；`normalizeRenderMetadata` 归一快照集；`buildRenderPlan` 把快照解析结果写入 `plan.options` 并带 `optionSetKey`；`validateFieldValue` / `validateFormData` 的值域校验改按计划内选项集。
4. **ui-ep 注入式解析**：新增 `utils/optionSet.ts`——`OPTION_SET_RESOLVER` 令牌、`createOptionSetResolver(sets)`（按需取值）、`provideOptionSetResolver`、`useOptionSet({ optionSetKey, translate })` 投影、开发态标记 `isOptionSetDevMode` / `setOptionSetDevMode`。**定位为工具层**（非基类投影），避免与组合式挂链护栏冲突。
5. **ui-ep 两件**：`EnumField.vue` / `EnumMultiField.vue` 改名为 `OptionSetField.vue` / `OptionSetMultiField.vue` 并按新契约重写——只收 `optionSetKey`（**删除 `options` prop**）、单选四形态（`radio` / `button` / `segmented` / `dropdown`）、多选三形态（`checkbox` / `tag` / `dropdown-multi`）；只读回显（单选 label、多选顿号、缺项回退原值）、缺项 `data-missing` 与开发态告警、空态禁用与占位、数量上下限 `exceed`、受控值去重保序。
6. **渲染协同与件名统一**：`FormRendererBody` 装配 `provideOptionSetResolver(createOptionSetResolver(() => plan.optionSets))`；枚举字段只下发 `optionSetKey` 与 `form`（**不下发 `options`**）；`formWidgets` / `index.ts` 导出与类型改名（`OptionSetFieldForm` / `OptionSetFieldValue` / `OptionSetMultiForm` / `OptionSetMultiValue`）；核对页 `FieldCheck.vue` 与宿主守卫断言同步。
7. **测试拆分**：`field-switch-enum.spec.ts` 拆为 `field-switch.spec.ts`（开关三件，Kiwi 969，逐条迁移）与 `field-option-set.spec.ts`（选项集，Kiwi 2337）；核心新增 `option-set.spec.ts`、渲染用例扩选项集协同；样式护栏与替代件说明改名。
8. **验证与对照**：三包 lint / typecheck / test 全绿；变更源文件覆盖率 100%；按原型六形态截图对照（见测试记录 §5）。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 选项集后端**无 HTTP 接口**，前端无法取数 | 元数据下发 `optionSets` 快照 + 注入式解析器消费；未下发即空态降级，**不伪造快照、零请求** |
| 2 | 删除逐字段 `options` 后，core 值域校验失去来源 | 校验改读计划内由快照解析的 `options`（`resolveOptionSetItems` 同一套解析），渲染与校验单源 |
| 3 | `OptionSetMultiField` 用 `computed` 产出 `selected` 新数组，下游控件回写触发**渲染递归**（`Maximum recursive updates exceeded`） | 改为 `ref` + 值比较（内容相同不换引用），打破回写循环 |
| 4 | 解析注入放在 `composables/` 触发「组合式须挂基类投影」护栏 | 按职责下沉到 `utils/optionSet.ts`（工具层，不冒充基类投影），护栏保持绿 |
| 5 | `import.meta.env.DEV` 在构建期被静态内联，测试无法覆盖「生产静默」分支 | 抽出 `isOptionSetDevMode()` / `setOptionSetDevMode()` 模块标记（构建期取值、测试可覆盖），两分支均有用例 |
| 6 | 只读态仍展示「选项不在选项集中」红字（存量脏值） | 只读态**不校验**：回退原值展示 + `data-missing` + 开发态告警；编辑态才要求重选（设计 §3.6） |
| 7 | `formWidgets.resolveFieldComponentByType` 此前零用例（覆盖率 93.33%） | 补「按字段类型直接解析」用例，该文件达 100% |
| 8 | 前台启动 dev server 被长驻命令阻断 / `--port` 未透传（pnpm 传参吞掉） | 改为后台 `Start-Process` 启动，使用 Vite 默认 5173 完成截图对照 |
| 9 | 原型为本地 HTML，Playwright 禁止 `file:` 协议 | 以 `python -m http.server` 临时静态服务打开原型页截图（完成后关停，临时文件不入库） |
