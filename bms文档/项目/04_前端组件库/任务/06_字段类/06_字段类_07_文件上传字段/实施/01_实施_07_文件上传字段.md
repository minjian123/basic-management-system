## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先行**：经容器内 Django shell 登记用例（平台既有编号至 964），取得 **965**；核心与插件用例文件首行标注 `// kiwi_id: 965`。
2. **依赖安装**：`pnpm --filter @bms/ui-ep add cropperjs@^2.2.0`（npmmirror），更新 `frontend/packages/ui-ep/package.json` 与根 `pnpm-lock.yaml`（CI 基础镜像随锁文件变更由 `ci-base-build` 自动重建）。
3. **核心领域 `domain/file.ts`**：常量（整包阈值 20MB / 缺省分片 5MB / 单文件 2GB / 分片与多文件并发 3 / 重试 3 次指数退避 / 压缩与裁剪缺省 / 错误码 50101~50105 文案 / 本地占位前缀）、类型（`FileMeta` / `FileRef` / `UploadPartPlan` / `UploadSessionInfo` / `UploadTaskSnapshot` / 校验与决策类型）与纯函数（归一（兼容 snake_case、失效与本地占位标记）、校验（空文件 / 类型扩展名 + MIME 双重 / 大小 / 图片尺寸与比例）、选择与上限、排序与合并、模式决策与分片计划、进度聚合与缺失分片、线参数构造、会话与分片结果归一、压缩决策、退避与错误码、**增量 SHA-256**（FIPS 180-4 纯 TS，非破坏性摘要））。
4. **插件轨 `capabilities/upload-transport.ts`**：`BaseUploadTransport`（十方法：`hash` / `check` / `uploadWhole` / `initiate` / `uploadPart` / `complete` / `abort` / `listParts` / `resolveFiles` / `presign`；未覆写返回 `undefined` 即不请求）+ `UploadTransportProvider` + `UploadTransportRegistry`；注入面 `UploadTransportAdapter`。
5. **上传引擎扩展（重挂占位语义）**：`BaseUploadEngine` 父基类 `BaseComponent` → `BasePlaceholderState`（依赖登记 `['placeholder-state', 'presigned-url']`）；新增任务队列（多文件并发）、秒传（哈希 + 判定，命中零上传）、整包 / 分片决策与分片调度（并发 + 指数退避重试 + 进度聚合）、断点续传（`listParts` 覆写仅补缺失 / 未覆写全量重传）、取消（信号 + 通路 `abort` + 进度复位、不视为失败）、错误码与释放；既有 `uploader` / `upload` / `progress` / `cancel` / `abort` / `chunkSize` / `maxSize` 逐字兼容（`08_05` 导入流保持）。
6. **预签名扩展 `capabilities/presigned-url.ts`**：按文件标识 keyed 缓存、用途（`get` / `put`）、提前刷新阈值、失效重取一次、同键并发合并、降级策略声明；无 key 调用保持既有单 URL 语义（`07_03` 文件预览 / `08_08` 审批图 / `BaseFileDownload` 行为不变）。
7. **组件基类 `capabilities/file-upload.ts`**（父 `BaseInput`）：文件列表（受控值为标识，在途上传以本地占位引用展示、完成替换为服务端标识）、校验与上限、图片配置（压缩 / 裁剪 / 尺寸比例）、批量回显（`resolveFiles` 一次批量、未命中失效、已解析不重复）、预览（预签名取址）与下载（下载触发）、任务并入与 `mergeRefs` / `taskOfFile` 件层支撑。
8. **登记与导出**：`manifest`（`upload-engine` 依赖改 `placeholder-state`，新增 `file-upload`）；`form-render`（`FormWidget` 增 `file-upload` / `image-upload`，旧键保留，`FIELD_WIDGET_MAP` 重挂）；`form-layout`（`FieldRenderAttrs` 增 `uploadAccept` / `uploadMaxSize` / `uploadLimit` / `uploadMultiple`）；`core/src/index.ts` 与 `core/testing/index.ts` 导出。
9. **契约套件（`@bms/core/testing/file-upload.ts`）**：`describeUploadEngineContract` / `describeFileUploadContract` + 上传通路桩（调用轨迹 / 秒传可控 / 失败一次 / 慢分片 / 已传分片）；核心与 `ui-ep` 各传适配器跑同一套断言（同契约多实现）；`06_01` 冻结的 `describePlaceholderFieldContract` 由真实实现继续复用。
10. **投影与工具**：`useBaseFileUpload`（内建引擎 + 预签名取址器 + 响应式面 + `onScopeDispose` 释放）、`useBaseUploadEngine` 扩展（通路 / 任务 / 配置面，既有面保持）；`utils/uploadTransport.ts`（HTTP 内建十方法 + 统一解包 + 默认键 `http` + 中断信号桥接）、`utils/fileHash.ts` + `fileHash.worker.ts`（整文件与每片哈希，Worker 优先、降级主线程）、`utils/imageProcess.ts` + `imageProcess.worker.ts`（尺寸探测（超时降级）/ 压缩（Worker 优先、原格式输出）/ 对象 URL）、`utils/imageCrop.ts`（cropperjs v2 JS API 装配 + 输出 PNG）。
11. **件族四件**：
    - `FileUploadField`（真实实现，保留 `06_01` 冻结契约）：拖拽 / 点击选择、文件列表（名称 / 大小 / 进度 / 重试 / 取消 / 移除 / 预览 / 下载）、只读回显与失效占位；项内**首个按钮为移除**（兼容冻结用例）；
    - `ImageUploadField`（缩略图网格 / 添加卡 / 多图拖拽排序 / 尺寸与比例校验 / 压缩 / 裁剪入口 / 头像圆形形态 / 只读回显）；
    - `FileListField`（只读列表：名称 / 大小 / 缩略图 / 下载 / 预览 / 失效置灰，复用 `07_03` `FilePreview`）；
    - `ImageCropDialog`（cropperjs v2 装配、复位 / 缩放 / 确认 / 取消、装配失败降级提示；经 `useBaseInput` 挂链）。
12. **表单渲染协同**：`formWidgets`（`file-upload` / `image-upload` 映射 + `MULTIPLE_WIDGETS` 纳入）；`FormRendererBody.extraProps`（上传属性透传）。
13. **令牌与核对页**：`tokens.scss` 新增 `--bms-file-*`（亮 / 暗两套）；`vite.config.ts` 增 `vendor-cropperjs` 独立分包；`file-check.html` + `src/dev/{fileCheck.ts,FileCheck.vue}`（12 项自检 + 桩通路 + 裁剪弹窗真实装配）。
14. **登记回写**：《前端基类清单》（§2.1 新增 `BaseFileUpload` + 引擎父基类 / 职责回写 + 预签名职责 + §2.2 / §4 / §5.2 / §5.3 / §8 / §9）、《组件设计 · 文件上传字段》落地口径注块、《架构设计 · 前端组件体系》「取数与缓存协作」节、《布局设计 · 设计令牌》2.6 文件上传令牌、任务 / 父任务 / 计划与状态、协同契约（`06_01` / `08_05` / `07_03` / `08_06` / `07_05` / `02-4-18`）。

## 6. 偏差与遗留 <a id="deviations"></a>

- **设计偏差（已回写设计 §10）**：① 件族未提供 `engine` prop（引擎由投影内建，件经 `transport` / `presigned` / `download` 注入）；② 族基类与投影补 `taskOfFile` / `taskIdOfFile` / `mergeRefs`（件层进度与回显名需要）；③ `readImageDimension` 增超时降级、`createObjectUrl` 增异常降级（无能力环境不挂起）；④ 核对页自检等待口径改「轮询空闲」（引擎 `start` 为调度语义）。
- **对外契约扩展（向后兼容）**：`FileUploadField` 新增可选 Props（`placeholder` / `multiple` / `transport` / `presigned` / `download` / `partSize` / `wholeMaxSize` / `concurrency` / `autoDedup` / `draggable` / `readonly` / `required` / `errorMessage` / `emptyText` / `showProgress` / `downloadable` / `previewable`）、事件（`retry` / `cancel` / `fail` / `limit-exceed` / `invalid` / `progress` / `done`）与插槽（`empty` / `item` / `tip` / `actions`）；既有 Props / 事件 / 插槽 / `data-test` 不变。
- **核心面新增（只增不改）**：`domain/file.ts`、`capabilities/upload-transport`、`capabilities/file-upload`、契约套件两套；`BaseUploadEngine` 重挂父基类（依赖登记变更）与任务编排扩展；`BasePresignedUrl` keyed 扩展；`FormWidget` 增 `file-upload` / `image-upload`（旧键保留）、`FieldRenderAttrs` 增 `upload*`（前端先冻结，后端表单元数据下发归表单定制窗口）。
- **依赖新增**：`cropperjs@2.2.0`（npmmirror；独立异步块 `vendor-cropperjs`，不进首屏）。
- **遗留（归口）**：
  - 真实文件存储与联调（整包 `POST /files`、分片真实托管、秒传判定落地、`sys_file` 落库、下载 / 预览预签名、白名单与配额、分片状态机与孤儿回收）→ **阶段八「通用能力 · 文件存储」窗口**（后端 `02-4-18` 已交付分片占位契约，契约缺口已登记）。
  - 权限码（`file:upload` / `file:download` / `file:manage`）→ RBAC 阶段。
  - 表单元数据接口下发 `uploadAccept` / `uploadMaxSize` / `uploadLimit` / `uploadMultiple` → 表单定制窗口。
  - 上传直传（预签名 `PUT`）模式为通路扩展位（覆写 `uploadPart` 即可接入），本期实现走服务端中转。
  - 移动端实现（契约套件与投影就位供同契约多实现）。
  - 压缩 / 裁剪的工作线程与主线程双路径已就位；超大图压缩跳过阈值与输出格式口径可经 Props 覆盖（后续如接入对象存储直传再评估 WebP 输出）。
