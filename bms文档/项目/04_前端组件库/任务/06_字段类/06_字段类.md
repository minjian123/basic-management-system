## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：阶段四需求域 06 的 8 条需求——[06-1 占位版交付](../../需求/06_需求_字段类.md#r06-1)、[06-2 基础与数据源字段](../../需求/06_需求_字段类.md#r06-2)、[06-3 富文本与高级交互字段](../../需求/06_需求_字段类.md#r06-3)、[06-4 验证码字段](../../需求/06_需求_字段类.md#r06-4)、[06-5 组织选择字段](../../需求/06_需求_字段类.md#r06-5)、[06-6 字典字段](../../需求/06_需求_字段类.md#r06-6)、[06-7 文件上传字段](../../需求/06_需求_字段类.md#r06-7)、[06-8 多语言文案字段](../../需求/06_需求_字段类.md#r06-8)，按「1 需求 = 1 子任务」拆 8 个子任务（`06_02` / `06_03` 含嵌套子任务）。
- **端范围**：**仅 PC**（`frontend/packages/ui-ep`，Element Plus）；移动端 `ui-vant` 本阶段范围外。
- **占位口径**：依赖后端的字段（字典 / 组织 / 文件 / 验证码）由 `06_01` 先交付**占位版**（骨架 + 空态 / 禁用态 / 降级语义 + 占位契约测试），**契约先行冻结**；`06_04` ~ `06_07` 真实实现**只换数据通路、不改对外契约**（变更走版本升级）。
- **依赖关系**：`06_02` / `06_03` 无后端强依赖；`06_04` ← 认证与安全能力、`06_05` ← RBAC 能力、`06_06` / `06_07` ← 通用能力。
- **依据**：《组件设计》字段类各节点、《[前端开发规范](../../../../规范/前端开发规范.md)》「前端基类体系（强制）」节、《[前端基类清单](../../../../前端基类清单.md)》、《[架构设计 · 前端组件体系](../../../../设计/架构设计/05_架构设计_前端组件体系.md)》「取数与缓存协作」节。
- **执行序**：`06_01 占位版交付` → `06_02 基础与数据源字段` → `06_03 富文本与高级交互字段` → `06_05 组织选择字段` / `06_04 验证码字段` / `06_06 字典字段` / `06_07 文件上传字段`（依赖就绪后推进，见[计划](../../计划/01_计划_前端组件库.md)）；**追加任务** `06_08 多语言文案字段`（2026-10-10 追加，见下条进展）在其后推进。
- **进展（2026-09-21）**：`06_05` 已完成（前端先行 + 通路注入式；五件 + 组件基类 `BaseOrgSelect` + 注入式组织数据源插件轨 + 契约套件 + 表单渲染 `dept` → `org-select` 协同；真实 RBAC 联调归阶段七）。`06_06` 字典字段**范围扩为前后端全链路**（用户拍板）：后端「字典真实取数与缓存」提前落地并登记于后端基座（`02-4-27` / [需求 02-56](../../../01_项目骨架/需求/02_需求_后端基座.md#r02-56)），本任务交付前端件族（四件 + 条件组构建件）并与后端真实接口端到端打通。`06_07` 文件上传字段已完成（2026-09-21，Kiwi 965；前端先行 + 通路注入式：组件基类 `BaseFileUpload` + 上传引擎扩展（分片 / 秒传 / 断点续传 / 并发重试 / 取消）与预签名扩展 + 上传通路插件轨与 HTTP 内建实现 + 四件（`FileUploadField` 真实实现 + `ImageUploadField` / `FileListField` / `ImageCropDialog`）+ 表单渲染协同；真实文件存储联调归阶段八窗口）。`06_04` 验证码字段已完成（2026-09-21，Kiwi 966；前端先行 + 数据源注入式：交付件族（`CaptchaField` 真实实现 + `ImageCaptcha` / `SliderCaptcha` / `SmsCaptcha`）、组件基类 `BaseCaptcha`、验证码数据源插件轨与 HTTP 内建实现、领域纯函数与契约套件、表单渲染协同与 13 项核对页；真实出题 / 短信下发 / 限流联调归阶段六认证窗口）。**本域 7 个子任务全部完成**。

## 3. 依赖与风险 <a id="dep"></a>

- **追加任务（2026-10-10）**：新增需求 `06-8` 与子任务 `06_08 多语言文案字段`——既有各实体维护表单把多语言名称写死为「中文名称 + 英文名称」两栏（每加一种语言要加一栏、逐语言铺开撑高表单且与同排字段对不齐），故把「语言维度」收敛为一个通用字段件：语言项由**启用语言清单**动态生成、装配为「语言下拉 + 单输入框」、**必填语言＝当前登录用户语言**（未启用则回退系统默认语言）、其余语言缺省回退并提示缺失。组件设计节点为字段类 13，**先于其消费方（菜单 / 业务码 / 动作码 / 图标 / 字段维护表单）落地**。
- **关键依赖**：`06_01` 依赖 `02_04`（输入组件基类）、`03_02`（空态）；`06_02` 依赖 `02_04` / `02_06` / `05_01`；`06_03` 依赖 `02_04` / `02_06` / `05_01` / `06_01`（富文本图片上传占位）；`06_04` 依赖认证与安全；`06_06` 依赖 `02-4-27`（字典真实取数与缓存，后端提前落地）与 `06_01` / `02_03`；`06_07` 依赖通用能力（文件存储）。
- **风险**：占位契约若在真实实现时被改会连带页面与字段壳（须契约先行冻结）；富文本 XSS 双向清洗与编辑器内核分包；上传分片 / 秒传 / 断点续传与后端契约强耦合；树 / 级联懒加载与回显口径；同屏重复请求（字典 / 组织缓存）。
