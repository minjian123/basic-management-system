## 3. 核对页与自检设计 <a id="design"></a>

### 3.1 页面结构 <a id="page"></a>

| 区 | 内容 |
| --- | --- |
| 头部 | 核对页标题 + 环境信息（内核名 / 视口宽度 / stage 参数） |
| 自检区（上屏） | `inputsCheck.ts` 的执行结果逐条渲染：`[✅/❌] 项名 — 期望 / 实测`；供截图直接作为证据 |
| 八件展示区 | 八件各一块：可交互实例（受控 ref）+ 关键状态切换（`readonly` / `disabled` / `readonlyMode` / 空值 / 已填） |
| 遗留项区 | `05_01` ~ `05_03` 遗留项对应场景（清空按钮 / 下拉弹层 / 步进 / 分段 / 三态清空 / tag 关闭 / 危险确认） |
| 触发参数 | `?stage=1`（默认，静态首屏）/ `?stage=2`（自动交互：设值 + 失焦 + 点击，用于「交互后」截图） |

### 3.2 跨件一致性自检项（八类，双端同一套） <a id="checks"></a>

| # | 项 | 断言方式（DOM 层） |
| --- | --- | --- |
| 1 | 受控写入 | 对每件执行程序化写值 → 断言值 ref 更新且 `update:modelValue` 计数递增（八件逐件） |
| 2 | 三态 | 空值时只读文本为 `—`（`input.emptyText`）；`NumberInput` 的 `0` 与 `SwitchInput` 的 `false` 视为已填（不显示占位） |
| 3 | `disabled` 写门禁 | `disabled` 实例写值 → 值不变（八件逐件） |
| 4 | `change` 上报 | 失焦（或选择类确认）后 `change` 计数递增 |
| 5 | 校验触发 | `required` + 空 + 失焦 → `validate(false)`；填值 + 失焦 → `validate(true)` |
| 6 | 字段壳装配 | 每件根含 `.bms-input` + `.bms-input-label`（传 `label`）+ `.bms-input-required`（`required`）+ `.bms-input-error`（传 `error`）+ `.bms-input-help`（传 `help`） |
| 7 | 只读两种呈现 | 默认（`readonlyMode='text'`）不渲染输入元素且显示文本；`readonlyMode='disabled'` 渲染禁用控件 |
| 8 | 栅格 | `span=12` → 根含 `is-inline` 且 `style` 含 `--bms-input-span:12`（或 12 值） |

判定口径：全部项通过 → 自检区显示「全部通过（N/N）」；任一失败 → 该条标 ❌ 并上屏期望 / 实测，核对结论记为不通过并登记偏差。

## 4. 行为、边界与失败分支 <a id="behavior"></a>

| 项 | 设计 |
| --- | --- |
| 核对页不产生产物 | `inputs-check.html` 与 `src/dev/**` 不进 `vite build`（与 `containers-check.html` 同口径），故不影响体积预算与覆盖率；`prettier` / `lint` 仍需通过（属源码） |
| 双端同接口多实现 | 两个 `InputsCheck.vue` 结构一致，仅组件来源（`@bms/ui-ep` vs `@bms/ui-vant`）与必要选择器差异；`inputsCheck.ts` 的断言以「类名钩子 + 壳类名」为准（跨端稳定面），内核差异（`.el-input` / `.van-field`）只用于「是否渲染输入元素」判定 |
| 交互真实性 | 浏览器层用真实点击 / 输入 / 失焦（非 jsdom 模拟），覆盖 `05_01` ~ `05_03` 中「jsdom 不稳定」而留作浏览器层核对的项（清除图标、下拉弹层、惰性确认弹窗） |
| 危险确认核对 | `SwitchInput` 的 `dangerConfirm` 触发 `ElMessageBox` / `showConfirmDialog`；截图前需 `?stage=2` 自动取消（避免遮挡）；结论以「弹窗出现且取消后值不变」为准 |
| 失败分支 | 任一件渲染异常 / 自检项失败 → 核对记录结论记「不通过（N 项）」，逐项登记偏差并回写对应子任务实施记录与设计 §8；不掩盖 |
| 真机不可及项 | 软键盘类型（`inputmode` 实际弹出）、惯性滚动、iOS 全屏限制 → 记录「环境不可及」并归口页面 / 移动端任务 |

## 8. 对齐记录 <a id="alignment"></a>

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | 核对口径沿用域 04 | 采用「dev 核对页 + 自检上屏 + 截图」的同一套口径，保证阶段内两域收口证据形态一致 |
| 2 | 自检断言走跨端稳定面 | 只断言类名钩子与壳装配（`bms-*` / `bms-input*`），不依赖 EP / Vant 内核类名（内核类名仅用于「是否渲染输入元素」判定），双端同一套断言 |
| 3 | 遗留项在浏览器层关闭 | `05_01` ~ `05_03` 中「jsdom 不稳定 / 需真实交互」的遗留项（清除图标、下拉弹层、危险确认弹窗）在核对页真实交互下关闭或明确归口 |
| 4 | 收口阶段不改实现 | 本任务原则上只核对；若发现缺陷，缺陷修复计入本任务并同步偏差与对应子任务记录（避免「核对即改测」） |
