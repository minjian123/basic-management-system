## 3. 接口设计 <a id="api"></a>

### 3.1 core：`domain/boolean.ts` <a id="api-boolean"></a>

```ts
/**
 * 布尔值归一（后端 `SMALLINT` 1/0 与字符串 / 布尔字面量统一入口）。
 *
 * - `true` / `1` / `'1'` / `'true'` / `'TRUE'`（含首尾空格）→ `true`；
 * - `false` / `0` / `'0'` / `'false'` → `false`；
 * - `null` / `undefined` / `''` → `null`（未设置）；
 * - 其余无法识别的值 → `null`。
 */
export function normalizeBooleanValue(value: unknown): boolean | null
```

判定口径：数字仅认 `1` / `0`（其余数字 → `null`）；字符串先 `trim` 再 `toLowerCase()` 后比对 `'1'` / `'0'` / `'true'` / `'false'`；`0` 与 `false` **不得被空值判定吞掉**（`null` 与 `false` 严格区分，与 `05_02` 的 `null` / `0` 口径一致）。

### 3.2 组件契约 <a id="api-components"></a>

**`RadioField`（双端同 props / emits）**：

| props | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `modelValue` | `OptionValue \| null` | `null` | 受控值（单选值 / `null`） |
| `options` | `readonly OptionItem[]` | `[]` | **静态**选项（字典 / 枚举来源归字段类，经 `option-source` 接入） |
| `widget` | `'radio' \| 'button' \| 'segmented'` | `'radio'` | 形态 |
| `optionType` | `'default' \| 'success' \| 'warning' \| 'danger'` | `'default'` | `button` 形态语义色 |
| `inline` | `boolean` | `false` | `radio` 形态横向排列（默认纵向） |
| 其余 | — | — | 壳 props（`label` / `required` / `help` / `error` / `disabled` / `readonly` / `readonlyMode` / `size` / `density` / `span` / `fieldKey`） |

| emits | 说明 |
| --- | --- |
| `update:modelValue` | 归一后的 `OptionValue \| null`（空 / 无效值 → `null`） |
| `change` | 失焦 / 点选后的值 |
| `validate` | 必填结果 |

暴露：`selectOption(value)`（点选单入口，契约与端内共用；禁用项、无效值拒绝）。

**`CheckboxField`（双端同 props / emits）**：

| props | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `modelValue` | `OptionValue[]` | `[]` | 受控值（多值数组） |
| `options` | `readonly OptionItem[]` | `[]` | 静态选项 |
| `widget` | `'checkbox' \| 'tag'` | `'checkbox'` | 形态 |
| `min` / `max` | `number` | — | 数量上下限（`max` ≤ 0 视为不限制，同 `reachMaxCount` 口径） |
| `selectAll` | `boolean` | `false` | 显示全选行（忽略禁用项） |
| `inline` | `boolean` | `false` | `checkbox` 形态横向排列 |
| 其余 | — | — | 壳 props（同 `RadioField`） |

| emits | 说明 |
| --- | --- |
| `update:modelValue` | 归一后的 `OptionValue[]`（无效值已剔除、去重并按**选项顺序**保序；空 → `[]`） |
| `change` | 失焦 / 点选后的值 |
| `validate` | 必填 + 数量下限（不足 `min` 时 `false`） |

暴露：`selectOption(value)`（点选单入口，达 `max` 拒绝）、`toggleSelectAll()`（全选 / 反选，忽略禁用项）。

**`SwitchInput`（双端同 props / emits）**：

| props | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `modelValue` | `boolean \| null` | `null` | 受控值（支持三态；对外只发 `boolean \| null`） |
| `activeText` / `inactiveText` | `string` | `''` | 开关文案（空则用 i18n `input.switchOn` / `input.switchOff`） |
| `loading` | `boolean` | `false` | 加载态（切换中，禁止重复点击） |
| `dangerConfirm` | `string` | `''` | 危险切换确认文案（非空时二次确认） |
| `threeState` | `boolean` | `false` | 区分未设置（`null`）与关（`false`） |
| `allowClear` | `boolean` | `false` | 三态下提供清空入口（回 `null`） |
| 其余 | — | — | 壳 props（同 `RadioField`） |

| emits | 说明 |
| --- | --- |
| `update:modelValue` | `boolean \| null`（后端 1/0 已归一；清空 → `null`） |
| `change` | 切换 / 清空后的值 |
| `validate` | 必填结果 |

暴露：`toggle()`（切换单入口，契约与端内共用；`loading` / 只读 / 确认取消时不写值）、`clear()`（回 `null`）。

## 4. 行为、边界与失败分支 <a id="behavior"></a>

| 项 | 设计 |
| --- | --- |
| 单选：归一 | 空 / 无效值 → `null`（`normalizeOptionValue(value, options, false)`）；`0` / `false` 等假值选项按值相等判定（不被空值吞掉） |
| 单选：只读 | 只读态以 `displayText = labelOfOption(...)` 回显选中项文本（`readonlyMode='disabled'` 时渲染禁用控件并保留选中高亮）；只读 / 禁用时点选被域拒绝 |
| 单选：形态差异 | `radio`：`el-radio-group`（`inline` 控制横纵）；`button`：`el-radio-button`（`optionType` 映射语义色）；`segmented`：`el-segmented`（选项多时横向滚动，`overflow` 由内核处理） |
| 单选：移动端 | `radio` 用 `van-radio-group` + `van-radio`（触控尺寸）；`button` / `segmented` 共用 `van-button-group` + `van-button`，选中项加 `bms-radio-field--option-active` 类 |
| 复选：归一 | 无效值剔除 + 去重 + 按选项顺序保序（`normalizeOptionValue(value, options, true)`）；空 → `[]` |
| 复选：全选 | `selectAll` 行：全部可选（非禁用）项已选 → 选中；部分选中 → 半选（`indeterminate`）；点击 → 全选（**忽略禁用项**）/ 反选（清空可选中的已选项，保留禁用项若已选） |
| 复选：数量上限 | 达 `max` → 未选项不可选（`isOptionSelectable`，PC 置 disabled / 移动端灰显不可点）+ 帮助文案 `input.maxCount`；超出值不写入域 |
| 复选：数量下限 | 失焦时 `value.length < min` → `validate(false)` + 帮助文案 `input.minCount`（件规则在壳必填结果之后合并上报） |
| 复选：tag 形态 | PC `el-check-tag`（`checked` + 点击切换）；移动端 `van-tag` + 点击切换（选中 / 未选中两态样式） |
| 开关：值域归一 | 受控值经 `normalizeBooleanValue` 归一后进入域；对外只发 `boolean \| null`（后端 `SMALLINT` 1/0 由边界收敛，不在组件内暴露数字） |
| 开关：三态 | `threeState=true` 时 `null` 渲染为「未设置」（灰色中性态 + 文案 `input.notSet`，与 `false` 的关闭态视觉区分）；点击 `null` → `true`，随后 `true ↔ false`；`allowClear` 打开时提供清空入口回 `null`；`threeState=false` 时 `null` 按 `false` 呈现（点击 → `true`） |
| 开关：加载态 | `loading=true` → 渲染 loading + 根类 `is-loading`，`toggle()` / 点击不写值（防重复提交） |
| 开关：危险确认 | `dangerConfirm !== ''` 且本次切换为「由开转关」（或首次由 `null` → `false`）→ 先 `confirm({ message: dangerConfirm, danger: true })`；确认 `true` 才写值，取消 / 失败保持原值（不 emit `update:modelValue`） |
| 开关：文案 | `activeText` / `inactiveText` 非空优先；为空时取 i18n `input.switchOn` / `input.switchOff`；三态未设置取 `input.notSet` |
| 只读：三件 | 默认壳文本态（`displayText` 由件层传入：单选 `labelOfOption`、复选 `labelOfOption`（数组 → 选项顺序「、」拼接）、开关是 / 否 / 未设置）；空值统一走 `input.emptyText`（`—`） |
| 失败分支 | `options` 为空 → 单选 / 复选渲染空容器（不报错）；`modelValue` 类型不符（单选传数组 → 取首个可识别值；复选传单值 → 视作单元素数组，同 `normalizeOptionValue` 既有口径）；`min > max` → `max` 优先（达上限禁选，下限校验不再报错）；`confirm` 实现抛错 → 视为取消（保持原值）；`loading` 期间清空入口同样禁用 |

## 7. 边界与开放项 <a id="open"></a>

- **不含**：字典 / 远程选项来源（归 `06_6`，经 `option-source` 接入）；枚举单选 / 多选字段与列表内联开关（归 `06_8`）；穿梭框 / 标签区（归其余域）。
- **性能**：静态选项渲染建议 ≤ 7（单选）/ ≤ 12（复选），超出建议改用下拉框（设计节点 §8 已提示）；`groupOptions` 未使用（本三件按设计节点不含分组，分组下拉在 `05_02`）。
- **开放项**：① 移动端 `segmented` 用 `van-button-group` 模拟的观感与原型差异，随 `05_04` 真机核对评估；② 开关三态在移动端是否需要显式「未设置」清空按钮（当前 `allowClear` 打开时渲染）；③ 复选 `tag` 形态在移动端的关闭交互是否需要独立关闭图标（当前整标签点击切换）——均留 `05_04` 收口。

## 8. 对齐记录 <a id="alignment"></a>

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | 三形态与两形态内核 | 确认「PC 与移动端均用各自 UI 内核（EP / Vant）」：单选三形态与复选两形态都吃内核内置件，双端 DOM 不同但契约断言同一套 |
| 2 | 全选忽略禁用项 | 设计节点原文「全选/反选（忽略禁用项）」落地为：全选只写非禁用项；反选清空可选项（已选禁用项保留，避免值与界面不一致） |
| 3 | 数量界限方向 | 与 `05_02` 一致取「值永远合法」：`max` 达上限即禁选（不产生越界值），`min` 只在失焦时校验（输入过程中不打断） |
| 4 | 三态语义 | 采用「`null` 是初始态、`false` 是明确关闭」，故点按顺序为 `null → true ↔ false`，回 `null` 走显式 `allowClear`；不复刻三态循环（避免误点） |
| 5 | 危险确认复用既有注入点 | 不新增能力与依赖：直接用插件既有 `confirm()`（`ui-ep/src/confirm.ts` / `ui-vant/src/confirm.ts`，已接 `core` `createConfirmService`），宿主可 `configureConfirm` 覆盖 |
| 6 | 布尔归一独立成域文件 | 归一层面在 core（`domain/boolean.ts`）而非件内，字段类与列表内联开关共用；组件只做「调用 + 只发布尔」 |
| 7 | 契约断言取舍 | 弹层 / 内核交互（EP / Vant 差异大）不进契约：契约聚焦「根类名 + 壳 + 归一 + 只读文本 + 上限拒绝 + 三态归一 + 加载/确认不外发」跨端稳定面；点选与弹层行为由各端 spec 覆盖 |
| 8 | `OptionItem` 与选项域复用 | 本任务不新增契约与选项域文件：`OptionItem`（`05_02` 落 `contracts/option.ts`）与 `normalizeOptionValue` / `labelOfOption` / `isOptionSelectable` / `reachMaxCount` 直接复用，避免双份归一 |
| 9 | 实施细化：移动端按钮 / 分段形态自绘容器 | Vant 4 未提供 `ButtonGroup` 按需入口（`vant/es` 下无 `button-group`）→ 移动端 `button` / `segmented` 改自绘容器（`.bms-radio-field-options--{button,segmented}`）+ `van-button` 并排，选中项 `type="primary"` + `bms-radio-field--option-active` |
| 10 | 实施细化：件层 `innerValue` 适配内核空值 | EP `el-radio-group` / `el-segmented` 的 `model-value` 类型不接受 `null` → 件层加 `innerValue()`（空值 → `undefined`），模板三处统一使用 |
| 11 | 实施细化：复选壳值传受控 prop | 壳的 `model-value` 若传件层 computed（归一函数每次返回新数组）会触发「壳 watch → 写域 → computed 重算」递归更新 → 壳值改传受控 prop，`modelValue` 类型放宽为 `OptionValue[]`（与壳 prop 兼容） |
| 12 | 实施细化：写值断言需等待一次渲染 | `selectOption` / `toggleSelectAll` 为同步方法，域写入后 Vue 的 pre-flush watcher 尚未执行 → 契约补 `await view.flushRender()`、端内补 `await nextTick()`；EP 侧 `label` 点击在 jsdom 不激活 `input`，端内改用 `input[type="radio"\|"checkbox"].setValue()`，禁选断言改走 exposed `selectOption` |
| 13 | 实施细化：`validated` 控制下限提示时机 | 数量下限提示若只看当前值会与「尚未填写」混淆 → 仅失焦 / 主动 `validate()` 之后才出现 `input.minCount` 提示 |
