## 1. 域说明 <a id="intro"></a>

本域对应[《组件设计》](../../../设计/组件设计/01_组件设计_总览.md)「布局组件类」（`03_布局组件类/`，11 节点），沉淀页面 / 区域布局与结构，均组合布局片段 `useLayout`；页面形态以《[布局设计](../../../设计/布局设计/01_布局设计_总览.html)》为准。

本域另含三件按执行顺序前移的需求（契约与原型归属不变，仅需求条目归本域）：

| 需求 | 契约节点归属 | 前移原因 |
| --- | --- | --- |
| `03-1` 弹窗抽屉表单 | 《组件设计》容器组件类「01 弹窗抽屉表单」 | 结构布局的页签 / 菜单关闭要复用其确认能力，须先于 `03-3` |
| `03-2` 异常与空状态 | 《组件设计》展示类「05 异常与空状态」 | 结构布局（空态 / 骨架屏）与通用容器（四态）的共同前置，须先于 `03-3` 与 `04-1` |
| `03-4` 侧边菜单 | 《组件设计》交互类「13 侧边菜单」 | 主框架布局壳的侧栏组成部分，与 `03-5` 同批 |

- **框架与容器**：主框架布局壳 `AppLayout`、表单框架壳 `FormFrame`、页面容器 `PageContainer`。
- **结构布局**：多标签导航 `TabsNav` / `FormFrameTabs`、树形主从布局 `MasterDetail` / `MasterTree`、栅格 `Grid`、间距 / 分割线 `Space` / `Divider`、分栏 `Split`、内容页签 `Tabs`、卡片 `Card`、折叠面板 `Collapse`。
- **弹窗与反馈**：弹窗抽屉表单 `FormDialog` / `FormDrawer` / `ConfirmDialog` / `useFormModal` / `useConfirm`；异常与空状态 `ErrorPage` / `EmptyState` / `SkeletonBlock` / `LoadingMask` / `useFeedback`。

**依据**：《[项目规划说明](../../../规划/项目规划说明.md)》「前端页面清单与菜单机制」节、《[布局设计](../../../设计/布局设计/01_布局设计_总览.html)》各节点、《组件设计》布局组件类各节点、《[架构设计 · 前端组件体系](../../../设计/架构设计/05_架构设计_前端组件体系.md)》「八类组件与边界」节。
**用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。
**目标**：页面可由「主框架布局壳 + 页面容器 + 通用组件」直接组装，结构一致、可复用；弹窗表单与空状态反馈口径统一。

## 2. 需求 03-1：弹窗抽屉表单 <a id="r03-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：新增 / 编辑 / 详情普遍以弹窗或抽屉承载，若每页各写弹窗表单，尺寸阶梯、三态（新增 / 编辑 / 详情）、生命周期、脏数据拦截与二次确认会各不相同，交互一致性无从保证；而页签关闭、菜单切换等场景又需要通用确认能力，故本项须先于结构布局交付。

**内容**（《布局设计》弹窗节点、《组件设计》容器组件类「弹窗抽屉表单」）：

1. `FormDialog` / `FormDrawer`：三态契约（新增 / 编辑 / 详情）、尺寸阶梯、生命周期、脏数据拦截与提交前确认；提交复用 `02-6` 的 `useRequest`。
2. `ConfirmDialog` / `useConfirm`：通用二次确认对话框，供页签关闭、删除确认等场景复用。
3. `useFormModal`：弹窗表单的组合式封装（打开 / 关闭 / 提交 / 重置 / loading）。
4. 语义色、间距、遮罩行为对齐 Element Plus 与《布局设计》弹窗节点；字段插槽先以占位内容验证（真实字段随字段类需求接入）。

**完成标准**：三态弹窗表单可用、脏数据拦截生效、尺寸阶梯与《布局设计》一致；`useFormModal` 与 `useConfirm` 可被页面与其他组件直接调用；Vitest 覆盖三态与拦截行为；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《布局设计》[10_布局设计_弹窗](../../../设计/布局设计/10_布局设计_弹窗.html)、《组件设计》[01_组件设计_弹窗抽屉表单](../../../设计/组件设计/04_容器组件类/01_组件设计_弹窗抽屉表单/01_组件设计_弹窗抽屉表单.md)（含可交互原型）

> 注：实现期要点——落点 `src/components/modal/`（`FormDrawer` / `FormDialog` / `ConfirmDialog` + 内部共享壳 `useModalShell.ts`）与 `src/utils/{useFormModal,useConfirm}.ts`；三态（动作词 + 对象名标题）/ 尺寸阶梯（抽屉 400 / 480 / 640 / 720，对话框 420 / 480 / 520、`xl` 落 `lg`）/ 脏数据拦截链（提交中忽略 → 放弃确认 → `beforeClose` 串联）/ 视图态编辑入口（`submitPerm` 判显隐）；提交经 `useRequest`（页面注入 api，`edit` 带 `version`、409 重载）、脏数据基线 `stableStringify`、权限 `hasPerm`、错误文案 `error.{code}`；字段插槽占位（真实字段随字段类任务）。用例：Kiwi **724**（容器）/ **725**（组合式）。遗留去向：《概要设计 · 表单定制》弹窗承载与字段子集、《菜单管理》页脚权限口径 → 上游待补（计划 §3.1）；移动端 `van-popup` → 移动端任务；真机视觉核对 → `03_05` 组装复核。

## 3. 需求 03-2：异常与空状态 <a id="r03-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：错误页、空数据、加载骨架与内容遮罩是跨页面高频反馈元素，也是结构布局空态、通用容器四态、宿主外壳加载失败兜底的共同依赖；不统一会出现「每页一个空态风格」与加载闪烁，因此随地基波先行。

**内容**（《布局设计》异常与空状态节点、《组件设计》展示类「异常与空状态」）：

1. `ErrorPage`：403 / 404 / 500 错误页（含返回与重试入口）。
2. `EmptyState`：空状态矩阵（无数据 / 无结果 / 无权限 / 未选择），支持自定义插画与操作区。
3. `SkeletonBlock`：骨架屏（列表 / 卡片 / 详情形态）。
4. `LoadingMask`：内容区遮罩 loading（延迟显示防闪烁）。
5. `useFeedback`：反馈组合式（loading / 空 / 错误状态机与重试），供容器与页面统一调用。

**完成标准**：五项就位且被结构布局（`03-3`）、通用容器（`04-1`）实际引用；空状态矩阵与《布局设计》一致；Vitest 覆盖状态机与关键渲染分支；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《布局设计》[12_布局设计_异常与空状态](../../../设计/布局设计/12_布局设计_异常与空状态.html)、《组件设计》[05_组件设计_异常与空状态](../../../设计/组件设计/07_展示类/05_组件设计_异常与空状态/05_组件设计_异常与空状态.md)（含可交互原型）

> 注：实现期要点——落点 `src/components/feedback/`（`ErrorPage` / `EmptyState` / `SkeletonBlock` / `LoadingMask` + `types.ts` + 域出口）与 `src/utils/useFeedback.ts`（内部复用 `useRequest`，不重复实现竞态 / 取消）；插画自绘 `src/assets/images/empty-*.svg`（7 个，线性 `currentColor`）；错误页独立路由 `/403` `/404` `/500` + 未知路径兜底 `/404`（修复 `redirectToForbidden` 落点），缺省动作直跳 + emit（`home` / `retry` / `contact`）；空态场景矩阵与 `actionPerm` 权限按钮；`LoadingMask` 以 `delay` 防闪。构建体积预算放宽 100 / 75 → **130 / 90 KB**（规范 §14 调整记录）。用例：Kiwi **726**（错误页）/ **727**（空状态）/ **728**（骨架）/ **729**（遮罩）/ **730**（组合式）。遗留去向：全局运行时错误处理器 → 阶段十二；通用表格 / 图表卡内态 → 回补波；移动端骨架 / 触底 / 下拉刷新 → 移动端任务；真机视觉核对 → `03_05` 组装复核。

## 4. 需求 03-3：结构布局 <a id="r03-3"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：页面内部结构（多标签、左树右表、栅格分栏、间距分割、页签、卡片、折叠）是高频重复元素，需要统一的结构组件以避免每页各写布局；其中树形主从与多标签导航承载较复杂交互（选中过滤、可调分割、窄屏抽屉、页签关闭与脏数据确认），统一实现可显著降低页面开发成本。

**内容**（《布局设计》各形态节点、《组件设计》布局组件类「多标签导航 / 树形主从布局 / 栅格 / 间距与分割线 / 分栏 / 内容页签 / 卡片 / 折叠面板」）：

1. 多标签导航 `TabsNav`：页面级多标签（打开 / 关闭 / 右键菜单 / 固定）与表单框架双层 Tab（`FormFrameTabs`，供 `03-5` 表单框架壳使用）；页签状态统一经页签状态片段 `useTabs`（打开 / 关闭 / 固定 / 缓存键 / keep-alive 清单，与内容页签共用）；关闭确认复用 `03-1` 的 `useConfirm`。
2. 树形主从布局 `MasterDetail` / `MasterTree`：左树右表 / 右详情、选中过滤、可调分割、折叠、窄屏抽屉与空态（空态复用 `03-2`）。
3. 栅格 `Grid`：24 栅格 + 响应式断点。
4. 间距 / 分割线 `Space` / `Divider`。
5. 分栏 `Split`：可拖拽左右 / 上下分栏。
6. 内容页签 `Tabs`（区别页面级多标签）、卡片 `Card`、折叠面板 `Collapse`（手风琴 / 多开）。
7. 八件均组合布局片段 `useLayout`，视觉与交互对齐 Element Plus 与《布局设计》。

**完成标准**：八项结构组件可用且可组合（如「卡片 + 折叠 + 栅格 + 分栏」搭出详情页分区）；树形主从的选中过滤与可调分割生效；页签状态与 keep-alive 清单正确；Vitest 覆盖关键交互；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《布局设计》[05_布局设计_导航](../../../设计/布局设计/05_布局设计_导航.html)、[07_布局设计_列表页](../../../设计/布局设计/07_布局设计_列表页.html)、[10_布局设计_弹窗](../../../设计/布局设计/10_布局设计_弹窗.html)、《组件设计》[04_组件设计_多标签导航](../../../设计/组件设计/03_布局组件类/04_组件设计_多标签导航/04_组件设计_多标签导航.md)、[05_组件设计_树形主从布局](../../../设计/组件设计/03_布局组件类/05_组件设计_树形主从布局/05_组件设计_树形主从布局.md)、[06_组件设计_栅格](../../../设计/组件设计/03_布局组件类/06_组件设计_栅格/06_组件设计_栅格.md)、[07_组件设计_间距与分割线](../../../设计/组件设计/03_布局组件类/07_组件设计_间距与分割线/07_组件设计_间距与分割线.md)、[08_组件设计_分栏](../../../设计/组件设计/03_布局组件类/08_组件设计_分栏/08_组件设计_分栏.md)、[09_组件设计_内容页签](../../../设计/组件设计/03_布局组件类/09_组件设计_内容页签/09_组件设计_内容页签.md)、[10_组件设计_卡片](../../../设计/组件设计/03_布局组件类/10_组件设计_卡片/10_组件设计_卡片.md)、[11_组件设计_折叠面板](../../../设计/组件设计/03_布局组件类/11_组件设计_折叠面板/11_组件设计_折叠面板.md)（均含可交互原型）

## 5. 需求 03-4：侧边菜单 <a id="r03-4"></a>

**内容**（《布局设计》主框架 / 导航节点、《组件设计》交互类「侧边菜单」）：

1. `SideMenu` / `MenuNode`：动态菜单树渲染、折叠 / 展开、搜索过滤、图标与徽标、多级展开互斥；菜单树由后端按权限下发（前端不硬编码路由表）。
2. 菜单到路由的注册 / 卸载统一经动态路由片段 `useDynamicRoutes`；权限过滤经权限上下文片段 `useAccess`（`02-3`），权限指令复用 `02-6`。

4. 样式与交互对齐 Element Plus 菜单与《布局设计》导航节点。

**完成标准**：侧边菜单可用（折叠 / 搜索 / 徽标 / 多级）、与路由联动正确；占位菜单树可驱动完整交互；Vitest 覆盖菜单树渲染与权限过滤分支；`vue-tsc`、ESLint、Vitest 全通过。

## 6. 需求 03-5：框架与容器 <a id="r03-5"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：主框架与表单框架是全站页面的外壳，列表 / 详情的四段式（工具栏 + 筛选 + 表格 + 分页）与表单页形态若不在壳组件统一，页面各写一套布局，交互与间距会发散，且动态菜单、标签页 keep-alive、页签状态无处承载。

**内容**（《布局设计》主框架 / 表单框架 / 列表页 / 表单页 / 响应式适配节点、《组件设计》布局组件类「主框架布局壳 / 表单框架壳 / 页面容器」）：

1. `AppLayout` 主框架布局壳：侧栏（`03-4` 侧边菜单）+ 顶栏 + 内容区 + 标签页，配合动态菜单渲染与路由 keep-alive；标签栏本体由 `03-3` 的 `TabsNav` / `FormFrameTabs` 提供，顶栏元素（语言切换、待办与通知角标、用户信息）以插槽占位，真实元素随展示类与交互类需求接入。
2. `FormFrame` 表单框架壳：列表固定 + 详情多开双层 Tab（`FormFrameTabs`），承载列表页与表单页的页签状态。
3. `PageContainer` 页面容器：标题 / 描述 / 面包屑 / 工具栏 / 内容 / 底部插槽。
4. 三件均组合布局片段，消费设计令牌（间距 / 断点 / 主题）；响应式按《布局设计》响应式适配节点处理（侧栏折叠 / 抽屉化）。

**完成标准**：以三件套可搭出列表页与表单页骨架；标签页切换与 keep-alive 生效；响应式断点行为与《布局设计》一致；Vitest 覆盖壳组件关键行为；`vue-tsc`、ESLint、Vitest 全通过。
