## 1. 域说明 <a id="intro"></a>

本域对应阶段四「微前端骨架起步」：微前端已定案引入（Module Federation，阶段四搭骨架、阶段五完成运行时加载），本域只交付**宿主外壳（薄壳）与片段契约**，使后续业务页面可按「片段」形态开发。

- **本域范围**：宿主外壳与片段加载器接口、片段契约（注入上下文 / 注册声明）与注册表基座最小实现。
- **随阶段五及后续落地**：运行时加载（Module Federation 接入）、片段清单与版本字段、`shared` 依赖 singleton 基础配置，以及隔离增强 / 版本协商 / 灰度回滚 / 按片段观测等治理项（清单见[阶段五需求提出清单](../../05_前端插件化/README.md)）。
- **本域无《组件设计》对应类别**：需求域编号在八个组件类别（02 ~ 09）之后顺延为 10。

**依据**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「前端插件化与运行时组合（微前端）」节与「片段治理要求」表、《[架构设计 · 子系统 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》「前端插件化」节、《[总体项目规划](../../../规划/总体项目规划.md)》「阶段内容与完成标准」节（阶段四）、《[项目规划说明](../../../规划/项目规划说明.md)》「演进路线」节。
**用例口径**：本域用例入 Kiwi TCMS，自动化用例标注用例编号（随任务实施登记）。
**目标**：宿主薄壳与片段契约就位，可加载本地演示片段并注册路由；设计令牌与组件契约保持可被片段复用的形态。

## 2. 需求 10-1：宿主外壳与片段加载器 <a id="r10-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：微前端已定案引入；若没有宿主薄壳与加载器接口，后续页面只能继续构建期合并形态，阶段五切换运行时加载将被动作重构。须先把「壳」搭好——布局 / 路由 / 片段加载器保持极薄，业务知识不进宿主。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「前端插件化与运行时组合（微前端）」节，阶段四范围）：

1. 宿主外壳：布局壳（复用 `03-5` 主框架布局壳）与顶层路由接入；宿主保持薄壳（不含业务页面逻辑），提供片段挂载点与加载失败兜底位（错误边界占位，复用 `03-2` 错误页）。
2. 片段加载器：定义加载器接口（按片段名加载远端模块 → 挂载 → 卸载），阶段四以本地演示片段（静态 import / 本地产物）验证接口；接口形态按阶段五 Module Federation 远端模块预留。
3. 路由与菜单衔接：片段注册的路由并入平台动态路由，侧边栏（`03-4`）与页签（`03-3`）正常联动；菜单树到路由的注册 / 卸载统一经动态路由片段 `useDynamicRoutes`（前端不硬编码路由表）。
4. 演示验证：提供一个本地演示片段，宿主可加载并注册其路由（不进入生产菜单）。

**完成标准**：宿主薄壳与片段加载器接口就位；本地演示片段可被加载、路由注册与卸载正常；`vue-tsc`、ESLint、Vitest（加载器与路由注册用例）全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「前端插件化与运行时组合（微前端）」节、《[架构设计 · 子系统 · 扩展点与插件化](../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》「前端插件化」节

> 注：远端加载（Module Federation）、片段清单与版本字段随阶段五落地（见[阶段五需求提出清单](../../05_前端插件化/README.md)）。

## 3. 需求 10-2：片段契约与注册表基座 <a id="r10-2"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：片段与宿主之间必须依赖显式契约（注入什么、注册什么、约束什么），否则全局状态耦合、依赖重复、体验漂移等问题会在阶段五集中爆发；契约与一致性基础（设计令牌、组件契约）须在阶段四先行确定。

**内容**（《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「片段治理要求」表，阶段四先行项）：

1. 宿主注入上下文契约：`router` / Pinia / i18n / 当前用户与租户上下文（token 不落片段持久化）——注入清单与只读约束成文。
2. 片段侧上下文消费统一经片段上下文片段 `useFragmentContext`（宿主注入 router / pinia / i18n / 用户 / 租户，只读约束）。
3. 片段注册声明契约：片段对外提供的路由 / 菜单 / 页面区域 / 组件等注册声明的字段与校验规则（唯一性、路径前缀）。
4. 一致性基础：设计令牌（经设计令牌片段 `useDesignToken`）与组件契约保持可被片段复用的形态；片段样式作用域约束（Scoped + 前缀，禁止全局污染：不改全局原型、不挂全局事件与全局样式）。
5. 注册表基座最小实现：路由 / 菜单、通用组件、字段渲染器、图标、工作台卡片注册表的最小实现与注册契约（注册项唯一性 / 路径前缀校验），复用片段机制中的注册表基类 `BaseRegistry` / `BaseRegistryItem`（`02-3`），供片段注册与平台自身注册共用；「不注册不可用」护栏在本需求落地。
6. 契约文档化：以《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「片段治理要求」表为上位依据，输出片段契约说明。

**完成标准**：宿主注入上下文、片段注册声明与注册表基座（路由·菜单、组件、字段渲染器、图标、工作台卡片）契约成文并被演示片段实际使用；设计令牌与组件契约可被演示片段复用；样式作用域约束生效（演示片段不污染宿主）；未注册项不生效；Vitest 覆盖注册声明校验分支；`vue-tsc`、ESLint、Vitest 全通过。

**参考文档**：《[架构设计 · 前端架构](../../../设计/架构设计/08_架构设计_前端架构.md)》「前端插件化与运行时组合（微前端）」节与「片段治理要求」表、《[架构设计 · 前端组件体系](../../../设计/架构设计/05_架构设计_前端组件体系.md)》「渲染器与扩展点注册机制」节、知识档案《[微前端 · 04 隔离与治理](../../../资料/知识档案/微前端/04_微前端_隔离与治理.md)》

> 注：隔离增强（Shadow DOM / 沙箱）、依赖版本协商、片段清单 / 灰度 / 回滚、按片段观测等治理后补项随阶段五与后续阶段落地（见[阶段五需求提出清单](../../05_前端插件化/README.md)）。
