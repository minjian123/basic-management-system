## 1. 域说明 <a id="intro"></a>

本域承载 `ui-ep` 组件库的**件族样式补齐**：阶段四交付的组件只落了结构与交互逻辑，大量件**没有样式实现**（无 `<style scoped>` 块，模板以裸原生元素承载），宿主页面呈现为**裸骨架**；本域按《组件设计》各节点自带的**可交互原型**为验收基准，逐件补齐样式并做原型对照。

- **本域性质**：**组件库补样式域**，与阶段七「06 布局样式」域（`07-9`，布局族 18 件）同性质——后者只覆盖 `layout/` 一族，本域覆盖其余各族的同类缺口。
- **跨域归属**：样式缺口分布在 `ui-ep` 的**七个组件族**（基础控件类 / 容器组件类 / 字段类 / 展示类 / 交互类 / 布局组件类的异常与空状态 / 表单设计器与渲染器等专题族），非单一需求域问题，故按**跨域需求**在总览下顺延新增域编号 `11`，不并入既有域文档。
- **发现经过**：2026-10-13 用户反馈角色管理页「权限配置」区样式缺失；排查确认权限配置族九件**全部无样式**且模板为裸原生元素（`<input>` / `<button>` / `<select>`），与原型（`el-tabs` + `el-tree` + `el-table`）差距显著；进一步全库盘点发现同类缺口共 **76 件**。
- **全库盘点实测（立项时点，2026-10-13）**（`frontend/packages/ui_ep/src/components/`）：

| 类别 | 件数 | 判据 | 处置 |
| --- | --- | --- | --- |
| 真裸骨架 · 纯自绘 | 54 | 模板全为自绘 DOM（`div` / `span` / `button` / `input` 等），无任何 Element Plus 件，无样式块 | 按原型改用组件库件重构模板 + 补样式 |
| 真裸骨架 · 混合 | 12 | 自绘外壳 + 内部使用 Element Plus 件，外壳无样式 | 同上 |
| EP 薄包装 | 10 | 根元素即 Element Plus 件（`el-input` / `el-select` / `el-dialog` 等），无自绘 DOM，靠组件库全局样式已正常呈现 | **不补样式**，入护栏豁免清单（显式列名 + 理由） |

> **当前时点口径补注（2026-10-14，`11_03` 实施期复测）**：上表为**立项时点**口径；`11_01` 已补交互类 17 件、`11_02` 已补容器与展示反馈 18 件、`11_03` 已补字段与基础控件 17 件（另新增时间 / 百分比 / 枚举多选 / 三态开关 4 件），当前**无样式件为 24 件**（真裸骨架 14 件 + EP 薄包装 10 件），**剩余真裸骨架 14 件全部归 `11_04` 专题件族**。

> **本域交付完成补注（2026-10-14，`11_04` 交付）**：`11_04` 已补专题件族 14 件（导入导出 5 / 表单设计器 4 / 表单渲染器 2 / 图表卡 1 / i18n 1 / 报表设计器 1），**全库真裸骨架件归零**、件族样式护栏**转绿**；本域 4 个批次**全部交付**，「件族样式护栏落地后门禁持续红、全库补齐前不推送」的过渡口径随之**闭环**。EP 薄包装 10 件仍按豁免清单不补样式（靠组件库全局样式已正常）。

- **共性成因**：阶段四各域任务按「结构与交互逻辑先行」交付，**样式项未进入任务交付物清单、详细设计与验收标准**，测试记录亦无「视觉完整」对照维度；阶段七布局族同类缺口暴露后新增的《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 三向对齐与界面类准出项，尚未回溯覆盖组件库其余各族。
- **依据**：《[组件设计](../../../设计/组件设计/01_组件设计_总览.md)》各族节点自带可交互原型（原型即验收基准）、《[前端开发规范](../../../规范/前端开发规范.md)》「样式规范」节（样式作用域 / 令牌消费 / 组件库件复用）、《[原型审查规范](../../../规范/原型审查规范.md)》§4.9（实现 ↔ 原型 / 布局核对）、《[布局设计 · 设计令牌](../../../设计/布局设计/02_布局设计_设计令牌.html)》。

## 2. 需求 11-1：组件库件族样式补齐 <a id="r11-1"></a>

优先级：2（高）

**背景与动机**：`ui-ep` 是全部宿主页面与运行时模块的渲染基座，件族样式缺失会让**每一个消费该件的页面**都呈现裸骨架——已实证的是角色管理页「权限配置」区（九件全无样式，与原型差距显著），其余各族在对应页面被消费时同样会暴露。这类缺口属**基座级缺陷**，不是单页问题：不补齐则界面类验收无据、观感交付无从谈起，且每新增一个消费页面都要重复暴露一次。集中补齐并加机器护栏，可一次性消解存量并防复发。

**内容**（《组件设计》各族节点自带原型、《[前端开发规范](../../../规范/前端开发规范.md)》「样式规范」节、《[原型审查规范](../../../规范/原型审查规范.md)》§4.9）：

1. **全库盘点与分类**：对 `frontend/packages/ui_ep/src/components/` 全部件逐一实测 `<style scoped>` 与模板构成，区分「真裸骨架」（需补齐）与「EP 薄包装」（靠组件库全局样式已正常，入豁免清单）；盘点结论（件数、分类、逐件清单）登记于任务详细设计与测试记录。
2. **按族分批补齐**：按组件族分批交付，每批独立完成「详细设计 → 实施 → 测试 → 原型对照」；**首批为交互类 17 件**（权限配置族九件 + 图标选择器族两件 + 代码表达式编辑器族六件），覆盖本次暴露的角色管理页权限配置区；其余各族（基础控件类 / 容器组件类 / 字段类 / 展示类 / 异常与空状态 / 导入导出 / 表单设计器与渲染器 / 国际化文案编辑器 / 报表设计器 / 图表卡）随后续批次补齐，批次划分与顺序登记于任务详细设计与计划表。
3. **样式口径（强制）**：
   - 模板**按原型改用组件库件承载**（Element Plus 基础件 + `@bms/ui_ep` 既有件）——业务侧不得以裸原生交互元素自绘（《[前端开发规范](../../../规范/前端开发规范.md)》「组件库件复用」）；库内实现以 Element Plus 为底座。
   - 样式一律落件 `<style scoped>`；类名 kebab-case（BEM 简化）并带件名前缀。
   - **令牌消费（强制）**：只消费 `--bms-*` 令牌，**不得硬编码色值**（色值不设豁免）；尺寸沿用《[前端开发规范](../../../规范/前端开发规范.md)》尺寸硬编码白名单。
   - 令牌不足时按「**新增令牌先登记后使用**」补语义令牌（如权限配置的「未挂接」标记底、「来源只读」标记底），登记落点为宿主令牌文件与《[布局设计 · 设计令牌](../../../设计/布局设计/02_布局设计_设计令牌.html)》。
   - 暗色主题经令牌自动可读，不为单件写死颜色分支。
4. **既有对外契约保持**：补齐只改模板结构与样式，**不改各组件的 Props / 事件 / 插槽 / 暴露方法对外形状**；既有 `data-test` 钩子保留或按新结构等价迁移，用例断言同步更新。
5. **机器护栏**：新增件族样式护栏用例（与 `layout-style.spec.ts` 同口径），**硬断言全库真裸骨架件**「含非空 `<style scoped>` 且无硬编码色值」；EP 薄包装以**显式豁免清单**列名并附理由。护栏落地后门禁持续红，直至全库真裸骨架件补齐。
6. **原型对照**：逐批以对应《组件设计》节点的可交互原型为基准，用开发态核对页做**无头真机截图**，逐项对照（结构 / 样式 / 交互 / 去实现命名 / 主题与响应式），对照结论登记测试记录（《[原型审查规范](../../../规范/原型审查规范.md)》§4.9 八项）。

**完成标准**：全库真裸骨架件（盘点清单所列）逐件补齐样式且模板经组件库件承载；EP 薄包装豁免清单显式登记且附理由；件族样式护栏用例就位（硬断言 + 豁免清单），`ui-ep` 用例、宿主 `vue-tsc` / ESLint / Vitest 全通过；各批以对应组件设计原型完成真机截图逐项对照并在测试记录登记「原型对照结论」；新增 / 变更模块覆盖率达标、`check_preflight.py` 全绿；相关文档（任务详细设计、实施与测试记录、计划表、必要处《组件设计》节点）回写到位。
