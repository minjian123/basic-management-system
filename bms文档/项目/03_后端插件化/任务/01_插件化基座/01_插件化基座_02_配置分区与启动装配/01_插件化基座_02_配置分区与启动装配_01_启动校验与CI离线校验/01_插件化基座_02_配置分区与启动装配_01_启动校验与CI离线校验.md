## 2. 任务内容 <a id="content"></a>

1. 启动校验：provider 存在性 / 契约版本 / 依赖可用性校验；失败以统一错误类型拒启（退出码非 0、错误信息可读，不静默回退 `null`）
2. 依赖隔离：未选中实现不被导入（不为其背依赖）；实现依赖缺失 / 服务不可达按校验口径拒启
3. CI 离线校验：与 `backend/ops/check_modules.py` 同构，新增 `backend/ops/check_plugins.py`——运行现有注册表校验各能力 provider 引用合法性 / 重名 / 契约版本，接入 CI 冒烟层
4. 用例：非法 provider / 重名 / 契约版本不符三类拦截（启动与 CI 两口径）；未选中实现未被导入的依赖隔离断言

## 3. 完成标准 <a id="accept"></a>

非法 provider / 重名 / 契约版本不符启动被拒（退出码非 0、错误信息可读）；CI 离线校验能拦截非法配置且随冒烟层执行；未选中实现不被导入（依赖隔离可证）；`pytest` / `ruff` / `pyright` 全绿。
