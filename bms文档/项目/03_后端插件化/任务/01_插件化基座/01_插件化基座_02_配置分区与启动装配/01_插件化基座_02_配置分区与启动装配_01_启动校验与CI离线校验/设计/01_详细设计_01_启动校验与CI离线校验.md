## 1. 概述 <a id="overview"></a>

- **目标**：落实「非法 provider / 重名 / 契约版本不符启动被拒」「未选中实现不被导入（依赖隔离）」「CI 离线校验随冒烟层执行」三件事。
- **范围**：`backend/ops/check_plugins.py`（新增）、`.gitlab-ci.yml`（新增 `backend-plugins` job）、`tests/crosscut/test_plugin_validation.py`（Kiwi 534）。
- **不含**：装配主体（清单 / 解析 / `setup` / 日志）归父任务 [02 配置分区与启动装配](../../01_插件化基座_02_配置分区与启动装配.md)；真实实现的依赖探活（MinIO 连通等）随 04-1 / 对应阶段。
- **依据**：[需求 01-2](../../../../../需求/01_需求_插件化基座.md#r01-2)、《架构设计 · 扩展点与插件化》「配置驱动装配」「阶段三交付与验收（M3 口径）」节、《[测试规范](../../../../../../../规范/测试规范.md)》「流水线分层与自动触发」节、《[02 配置分区与启动装配详细设计](../../设计/01_详细设计_01_配置分区与启动装配.md)》。

## 4. 校验口径 <a id="rules"></a>

| 口径 | 规则 | 落点 |
| --- | --- | --- |
| provider 存在性 | 配置 provider（空 → `null`）在快照中存在；未注册 → `PluginError`（消息含键与已注册实现） | 装配 `resolve`（父任务）；CI 离线预检 |
| 重名 / 版本格式 | `(plugin_key, plugin_name)` 重名、`X.Y.Z` 格式非法 → 构建期 `PluginError`（明细聚合） | `build_plugin_registry()`（已有） |
| 契约版本兼容 | 装配按端口 `contract_version` 主版本比对实现实例（工厂实现读实例属性）；不匹配告警 + `PluginError` | 装配 `resolve(expected_version=…)`（已有） |
| 依赖可用性（启动期） | 工厂调用（含实现模块导入）/ `setup()` 抛错 → 装配包装为 `PluginError`（含键、provider、原因）+ CRITICAL 日志 → 拒启（非零退出） | 父任务装配路径 |
| 依赖隔离 | 未选中 provider 的工厂不被调用（延迟导入 → 未选中实现模块不进 `sys.modules`） | 装配按选中 provider 单路解析；用例证明 |
| CI 离线校验 | `ops/check_plugins.py`：`load_settings()` → `register_platform_plugins` → `build_plugin_registry()` → 逐清单项校验 provider 引用存在性与版本格式；打印明细，退出码 0 / 1 | 新增脚本 + 冒烟层 job |

## 5. CI 接入 <a id="ci"></a>

`.gitlab-ci.yml` 新增 job（与 `backend-modules` 同构、并行，stage `lint`）：

```yaml
backend-plugins:
  stage: lint
  image: $REGISTRY_IMAGE_PREFIX/ci-backend:py314
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
      exists: [backend/pyproject.toml]
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
      exists: [backend/pyproject.toml]
  script:
    - cd backend && uv run python -m ops.check_plugins
```

- 离线（不连真库 / 服务），失败即退出 1；触发路径沿用 `backend/**/*`（job 自动生效）。

## 6. 测试设计（Kiwi 先行） <a id="tests"></a>

用例先登记 Kiwi（本任务登记 **Kiwi 534**，平台自增顺延）；新增 `tests/crosscut/test_plugin_validation.py`：

| Kiwi | 用例 | 断言要点 |
| --- | --- | --- |
| 534 | 非法 provider 拒启 | lifespan 抛出 `PluginError`（含键与 provider），`app.state` 未装配完成 |
| 534 | 契约版本不符拒启 | 测试工厂返回 `contract_version = "2.0.0"` 实例 → 装配 `PluginError` + 告警 |
| 534 | 依赖不可用拒启 | `setup()` 抛错 → 包装 `PluginError` + CRITICAL；工厂导入失败 → 包装 `PluginError` |
| 534 | 依赖隔离 | 注册 `used` / `unused` 两 provider（工厂内导入 `tmp_path` 探针模块）：选中 `used` 后仅 `used` 探针进 `sys.modules` |
| 534 | CI 脚本（子进程） | `python -m ops.check_plugins`：默认可行退出 0；`BMS_STORAGE__PROVIDER=ghost` 退出 1 且输出明细（子进程保证注册表与配置全新） |

- 覆盖率：装配 / 校验相关新增代码 100%；既有用例全量回归。

## 7. 实施步骤 <a id="steps"></a>

1. 父任务装配完成后，`ops/check_plugins.py` 落 CI 校验入口（复用 Settings / 清单 / 注册表）。
2. `.gitlab-ci.yml` 增加 `backend-plugins` job。
3. Kiwi 534 登记 → 新增启动 / 隔离 / CI 用例。
4. 验证：`pytest` / `ruff` / `pyright` 全绿；手动跑 `python -m ops.check_plugins` 与非法配置失败路径。
5. 回写：任务 / 需求 / 计划状态（与父任务一并闭环）；实施 / 测试记录。

## 8. 验收映射 <a id="accept-map"></a>

| 完成标准 | 验证方式 |
| --- | --- |
| 非法 provider / 重名 / 契约版本不符启动被拒（退出码非 0、错误可读） | 拒启用例（lifespan 抛出 + 消息断言） |
| CI 离线校验能拦截非法配置且随冒烟层执行 | 子进程脚本用例（合法 0 / 非法 1）+ job 定义核对 |
| 未选中实现不被导入（依赖隔离可证） | sys.modules 探针用例 |
| `pytest` / `ruff` / `pyright` 全绿 | 验证命令输出 |

## 9. 边界与开放项 <a id="boundary"></a>

- 真实实现的服务可达性探活（MinIO / SMTP 等）属实现自身 `setup()` 职责与对应阶段实测；本任务只保证「失败即拒启」路径。
- CI job 的凭证 / 变量无需新增（纯离线校验）。
