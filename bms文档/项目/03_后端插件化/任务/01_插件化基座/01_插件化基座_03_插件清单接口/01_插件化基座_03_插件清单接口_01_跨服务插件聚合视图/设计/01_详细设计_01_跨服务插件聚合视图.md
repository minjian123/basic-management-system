## 1. 概述 <a id="overview"></a>

- **目标**：为平台超管提供**跨服务插件聚合视图**（需求 01-4）**接口占位**——在 `platform` 服务落地 `GET /api/v1/plugins/aggregate`，冻结跨服务聚合的响应契约，并以护栏用例锁定固定返回；**不发起真实跨服务调用**。
- **范围**：`libs/bms_core/src/bms_core/schemas/plugin.py`（新增聚合响应模型）、`services/platform/src/bms_platform/api/plugins.py`（新增 `/aggregate` 占位路由）、`services/platform/tests/api/test_plugins.py`（新增护栏用例）、`deploy/contracts/platform.json`（公开契约快照重导出）。
- **不含**（归触发时）：真实经 `service_client` 调用各服务 `GET /api/v1/plugins` 取数、并发与降级、`platform:manage` 鉴权（随认证 / RBAC 阶段）。
- **性质**：需求 01-4 为**触发式**——触发条件未满足前只做接口占位、不实现真实取数（《架构设计 · 扩展点与插件化》「服务化下的插件边界」节）。触发条件：多服务出现按服务差异化的插件配置，或运营需要统一查看面。
- **依据**：[需求 01-4](../../../../../需求/01_需求_插件化基座.md#r01-4)、《[01 详细设计 · 插件清单接口](../../设计/01_详细设计_01_插件清单接口.md)》、《[架构设计 · 扩展点与插件化](../../../../../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》「服务化下的插件边界」节、《[架构设计 · 接口与集成](../../../../../../../设计/架构设计/09_架构设计_接口与集成.md)》「服务间通信与契约」节、《[后端开发规范](../../../../../../../规范/后端开发规范.md)》（API 接口规范）。

## 4. 接口契约 <a id="api"></a>

### 4.1 端点与占位口径（本次） <a id="placeholder"></a>

`GET /api/v1/plugins/aggregate`（统一 `ApiResponse`，只读）：

- **占位返回固定值**：`{"placeholder": true, "services": []}`——不读注册表、不读 `options`、**不发起任何服务调用**。
- **鉴权**：沿用既有 plugins 路由口径**暂不鉴权**（与 `GET /api/v1/plugins` 一致）；`platform:manage` 随认证 / RBAC 阶段接入。
- **只读**：仅 `GET`；写方法 → `405 Method Not Allowed`。
- **路由顺序**：`/aggregate` 须注册在 `/{plugin_key}` **之前**，避免被明细动态路由吞掉（`"aggregate"` 不会命中任何已登记能力，静态路由优先命中）。

### 4.2 响应结构（冻结） <a id="shape"></a>

按**服务嵌套**汇总，字段与既有 `PluginGroupResponse` 一致；触发时 `services` 由空数组填充为各启用服务条目，`placeholder` 置为 `false`（**契约只加不删，非破坏性**）。

占位响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "placeholder": true,
    "services": []
  }
}
```

触发时的服务条目形状（本任务冻结、由 `PluginAggregateServiceResponse` 约束）：

```json
{
  "service_key": "identity",
  "service_title": "认证与身份服务",
  "status": "ok",
  "groups": [
    {
      "plugin_key": "cache",
      "provider": "redis",
      "implementations": [
        {"plugin_name": "memory", "contract_version": "0.1.0", "status": "registered"},
        {"plugin_name": "redis", "contract_version": "0.1.0", "status": "active"}
      ]
    }
  ]
}
```

| 字段 | 口径 |
| --- | --- |
| `placeholder` | 占位期恒 `true`；触发时真实实现置 `false` |
| `services[].service_key` | 服务目录标识（`SERVICE_CATALOG` 启用服务） |
| `services[].service_title` | 服务显示名（服务目录登记） |
| `services[].status` | 取数结果：`ok`（可调用）/ `unreachable`（调用失败，条目保留、组为空，不使整请求失败） |
| `services[].groups[]` | 该服务 `GET /api/v1/plugins` 的返回（`plugin_key` / `provider` / `implementations[]`，复用 `PluginGroupResponse`） |
| 密钥 | 全程不含 `options`（沿用清单口径，只出 provider 名与实现元信息） |

### 4.3 触发时实现口径（预留，不在本次范围） <a id="trigger"></a>

1. 读**本服务（platform）服务目录**取启用服务清单，排除自身或按需纳入。
2. 各服务经 `get_service_client()`（`BaseServiceClient`）调用 `GET /api/v1/plugins`，用 `ServiceRequest` 显式策略（超时 / 重试）；目标须在服务目录登记启用（基座 `validate_service_request` 前置校验）。
3. 单服务失败 → 该条目 `status="unreachable"`、`groups=[]`，其余正常返回（聚合不因单点失败而整体 5xx）。
4. 鉴权接入 `platform:manage`（随认证 / RBAC 阶段）。
5. 公开契约快照与 oasdiff 门禁沿用，无破坏性变更。

## 5. 实现要点 <a id="impl"></a>

- **响应模型**：落 `bms_core/schemas/plugin.py`（`BaseSchema` 体系，与既有插件契约同源）：
  - `PluginAggregateServiceResponse`：`service_key` / `service_title` / `status: Literal["ok","unreachable"]` / `groups: list[PluginGroupResponse]`。
  - `PluginAggregateResponse`：`placeholder: bool` / `services: list[PluginAggregateServiceResponse]`。
- **路由**：`api/plugins.py` 在 `@router.get("/{plugin_key}")` **之前**新增 `@router.get("/aggregate")`，恒定返回 `ApiResponse.ok(PluginAggregateResponse(placeholder=True, services=[]))`；不注入 `service_client`（占位不发调用），触发时再接入。
- **契约快照**：`uv run python -m ops.contract_snapshot export` 重导出 `deploy/contracts/platform.json`；新增端点属「只加不删」兼容变更，**baseline 不更新**（口径见《[契约门禁与契约测试使用说明](../../../../../../../资料/开发服务器/linux/契约门禁与契约测试使用说明.md)》「契约基线与目录」节）。

## 9. 边界与开放项 <a id="boundary"></a>

- **触发条件**（未满足前维持占位，不实现）：多服务出现按服务差异化的插件配置，或运营需要统一查看面。
- 真实取数、单服务降级、并发与缓存、`platform:manage` 鉴权、`by-capability` 轴（若要「同一能力一处核对」的矩阵视图）均归触发时；如触发时新增查询参数或独立端点，按契约「只加不删」演进。
- baseline 不更新（新增端点属兼容变更）；`platform.json` 快照随本次提交刷新。
