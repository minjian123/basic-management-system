## 2. 任务内容 <a id="content"></a>

1. `GET /api/v1/plugins`：按能力分组返回各 `plugin_key` 的注册实现与当前 provider（`plugin_key` / `plugin_name` / `contract_version` / 当前 provider / 状态）
2. `GET /api/v1/plugins/{plugin_key}`：单能力明细（注册实现列表 + 当前选中 + 版本）
3. 只读接口，不提供启停 / 切换操作；返回不含 `options` 密钥
4. 未登记能力返回 404（统一错误码口径）；鉴权按 `platform:manage` 口径随认证 / RBAC 阶段接入（当前暂不鉴权，与既有平台接口一致）
5. 路由与响应模型落地（`app/api/plugins.py` + 聚合路由）；自动化用例覆盖（随测试阶段入 Kiwi）

## 3. 完成标准 <a id="accept"></a>

双接口可查且字段与架构一致；不含任何密钥 / 敏感 `options`；未登记能力 404 与统一响应体一致；`pytest` / `ruff` / `pyright` 全绿。
