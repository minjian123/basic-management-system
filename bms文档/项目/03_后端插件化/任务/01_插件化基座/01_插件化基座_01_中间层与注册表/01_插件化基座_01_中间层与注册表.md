## 2. 任务内容 <a id="content"></a>

1. `app/core/plugin.py` 落地 `BasePluggable(BaseCapability)`：字段 `plugin_key` / `plugin_name` / `contract_version`；生命周期 `setup()` / `aclose()`（默认空实现，`aclose` 经 `ResourceManager` 统一回收）；`describe()` 元信息（供插件清单与排障）
2. 插件注册表：进程内两级映射 `plugin_key → {plugin_name → 实现}`，启动期构建、运行期只读；提供登记与快照查询入口（供解析 / 清单接口消费）
3. 双轨登记：`__init_subclass__` 自动登记仅对可实例化子类（无未实现抽象方法）生效，抽象端口 / 中间层不登记；显式 `register_plugin(plugin_key, plugin_name, impl)` 面向组合路径（虚拟子类 / `Protocol` 结构化）；两轨汇入同一注册表
4. 唯一性：`(plugin_key, plugin_name)` 冲突即拒（不静默覆盖）
5. 缺省实现：`NullXxx` 自动登记为 `plugin_name = "null"`
6. 单测：双轨登记 / 重名拒 / 抽象端口与中间层不误登记 / `Null` 登记；注册表语义纳入契约测试基座（与 03-1 口径一致）

## 3. 完成标准 <a id="accept"></a>

`BasePluggable` 字段 / 生命周期 / `describe` 齐备；继承自动登记（仅可实例化子类）与显式注册双轨均可用且汇入同一注册表；`(plugin_key, plugin_name)` 重名注册即拒、`NullXxx` 登记为 `null`；`pytest` / `ruff` / `pyright` 全绿。
