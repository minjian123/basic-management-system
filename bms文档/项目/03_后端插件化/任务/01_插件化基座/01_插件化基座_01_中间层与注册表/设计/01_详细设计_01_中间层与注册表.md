## 1. 概述 <a id="overview"></a>

- **目标**：落地「实现可替换」中间层机制——`BasePluggable`（插件键 / 实现名 / 契约版本 / 生命周期 / `describe`）与 `PluginRegistry`（进程内两级映射、双轨登记、唯一性拒重、只读快照），机制唯一落点 `app/core/plugin.py`。
- **范围**：`app/core/plugin.py`（新增）、`app/core/exceptions.py` 与 `app/core/error_codes.py`（新增 `PluginError` / `40002`）、单测。
- **不含**（归后续任务）：`resolve_plugin` 解析与实例缓存、契约版本主版本兼容判定（02 任务）；配置分区与启动装配、`setup()` 调用（03 任务）；启动 / CI 离线校验与依赖隔离（04 任务）；插件清单接口（05 任务）；40 个能力域基类改继承与 `null.py` 迁移（域二）。
- **依据**：[需求 01-1](../../../../需求/01_需求_插件化基座.md#r01-1)、《[架构设计 · 扩展点与插件化](../../../../../../设计/架构设计/10_架构设计_子系统_扩展点与插件化.md)》（「基类承载与双轨」「注册表与三阶段发现」节）、《[架构设计 · 后端基础类体系](../../../../../../设计/架构设计/04_架构设计_后端基础类体系.md)》（「基类候选」节）、《[后端基类清单](../../../../../../后端基类清单.md)》、《[后端开发规范](../../../../../../规范/后端开发规范.md)》（「后端基座体系（强制）」节）。

## 4. BasePluggable 契约 <a id="pluggable"></a>

`app/core/plugin.py`：`BasePluggable(BaseCapability, BaseAsyncResource)`（叠继承决策见第 7 节）。

| 成员 | 类型 / 默认 | 语义与边界 |
| --- | --- | --- |
| `plugin_key` | `str`，默认 `""` | 能力域键；未显式声明时回退 `key`（登记键 = `plugin_key or key`）；02-1 起各能力域基类显式声明（与 `key` 一致） |
| `plugin_name` | `str`，默认 `""` | 实现名（平台内建实现显式声明，如 `local` / `minio`）；`BaseNullObject` 子类未声明时登记为 `null`；其余无名非 `Null` 可实例化子类**不登记** |
| `contract_version` | `str`，默认 `0.1.0` | 契约版本；构建期校验 `X.Y.Z` 格式（`DEFAULT_CONTRACT_VERSION`）；主版本兼容判定归 02 任务 |
| `setup()` | `async def -> None`，默认空实现 | 生命周期钩子；装配侧（03 任务）随应用 lifespan 调用 |
| `aclose()` | `async def -> None`，默认空实现 | 释放钩子（幂等）；经 `ResourceManager` 逆序统一回收 |
| `describe()` | `-> str` | `f"{plugin_key or key}:{plugin_name 或 null}@{contract_version}"`；实例为 `BasePlaceholder` 子类时追加「（占位实现，待回补真实实现）」 |
| `__init_subclass__` | 类创建钩子 | 把子类收集进默认注册表候选；**不做**抽象判定与校验（统一在构建期，错误可聚合） |

```python
class BasePluggable(BaseCapability, BaseAsyncResource):
    """插件化中间层：登记进插件注册表，按配置解析（resolve_plugin）。"""

    plugin_key: str = ""
    plugin_name: str = ""
    contract_version: str = DEFAULT_CONTRACT_VERSION

    def __init_subclass__(cls, **kwargs: Any) -> None:
        super().__init_subclass__(**kwargs)
        _DEFAULT_REGISTRY.collect(cls)

    async def setup(self) -> None:
        """生命周期钩子（默认空实现）。"""

    async def aclose(self) -> None:
        """释放钩子（默认空实现，幂等）。"""

    def describe(self) -> str:
        """插件元信息（插件标识 + 占位后缀）。"""
```

- 抽象性判定时机：Python 3.14 的 `inspect.isabstract` 已支持在 `__init_subclass__` 内判定（实测），但本设计仍统一在**构建期**判定与校验——错误聚合、启动期一次性拒启、与 04 任务 CI 离线校验同口径；类定义不产生副作用。
- `describe()` 组合语义解决 MRO 遮蔽：`NullXxx(BaseXxx, BaseNullObject)` 中 `BasePluggable` 先于 `BasePlaceholder`，既有 20+ 处「占位实现」断言不破。

## 5. 登记规则与注册表 <a id="registry"></a>

### 5.1 构建期登记规则（两轨合并）

| # | 规则 | 处理 |
| --- | --- | --- |
| 1 | 抽象剔除：`inspect.isabstract(cls)` | 跳过（抽象端口 / 中间层本身不登记） |
| 2 | 登记键：`plugin_key or key` | 为空 → 错误明细 |
| 3 | 登记名：`plugin_name`；未声明且 `BaseNullObject` 子类 → `null` | 其余为空 → **不登记**（实工具类，如 `HealthCheckRegistry`） |
| 4 | 契约版本格式：`^\d+\.\d+\.\d+$` | 非法 → 错误明细 |
| 5 | 唯一性：`(plugin_key, plugin_name)` 冲突 | 错误明细（含双方实现类名，不静默覆盖） |
| 6 | 显式登记项：`plugin_key` / `plugin_name` 非空；`impl` 为可调用（类须非抽象，或零参工厂） | 违反 → 错误明细 |

- 全部检查完成后一次性抛 `PluginError`（消息含全部明细），满足「重名注册启动期即拒」。
- 注册项类型：`PluginImpl = type[BasePluggable] | Callable[[], object]`——实现类（继承轨自动登记同款）或零参工厂；组合路径（虚拟子类 / `Protocol` 结构化）与延迟导入（工厂内 `import`，03 / 04 任务）均经工厂承载。

### 5.2 PluginRegistry 与入口

| 成员 | 说明 |
| --- | --- |
| `PluginRegistry(BaseObject)` | 注册表类：独立实例可测试；持有候选、显式登记项与冻结快照 |
| `collect(impl_cls)` | 自动轨收集（`__init_subclass__` 调用，导入期）；构建后再收集不更新已冻结快照（重复 `build()` 才重算） |
| `register(plugin_key, plugin_name, impl)` | 显式轨登记；**构建后拒**（`PluginError`，运行期只读） |
| `build()` | 合并两轨 → 执行 5.1 校验 → 冻结快照（幂等；返回快照） |
| `snapshot()` | 只读快照 `Mapping[str, Mapping[str, PluginImpl]]`（`MappingProxyType` 两级包装，写入抛 `TypeError`）；未构建则先构建；按 `plugin_key`、`plugin_name` 排序稳定输出 |

模块级入口（默认实例 `_DEFAULT_REGISTRY = PluginRegistry()`）：

| 入口 | 说明 |
| --- | --- |
| `register_plugin(plugin_key, plugin_name, impl)` | 组合路径登记薄封装（`__init_subclass__` 的自动轨亦汇入默认实例） |
| `build_plugin_registry()` | 启动装配入口（03 任务接入 lifespan） |
| `plugin_registry_snapshot()` | 快照查询入口（02 任务解析、05 任务清单、03-1 契约套件消费） |

## 6. 错误与失败分支 <a id="errors"></a>

- `PluginError(ConfigError)`：落 `app/core/exceptions.py`；错误码 `ErrorCode.PLUGIN = 40002`（`error_codes.py`，4xxxx 系统配置段、启动期致命；实施后回写《架构设计 · 接口与集成》错误码表）。
- 失败分支：键为空 / 版本格式非法 / `(键, 名)` 冲突 / 显式项键名或 `impl` 非法 → 构建期 `PluginError`（明细聚合）；构建后 `register` → `PluginError`。
- 与需求口径对应：「非法 provider / 重名 / 契约版本不符启动被拒」中，本任务负责**重名**与**版本格式**；provider 存在性与版本兼容由 02 ~ 04 任务接续。

## 7. 生命周期与资源回收 <a id="lifecycle"></a>

- 叠继承决策：`BasePluggable(BaseCapability, BaseAsyncResource)`——`aclose()` 满足异步资源抽象（默认空实现），`ResourceManager` 无需改动，装配侧可直接 `resources.register(instance)`、应用关闭逆序释放。
- 继承链登记：`BasePluggable → BaseCapability → BaseAsyncResource → BaseObject`（相对架构原图多 `BaseAsyncResource` 旁支；实施后回写架构 04 / 基类清单）。
- MRO 实测（实施后由护栏用例固化）：`NullObjectStorage → BaseObjectStorage → BasePluggable → BaseCapability → BaseAsyncResource → BaseNullObject → BasePlaceholder → BaseObject`。
- 02-1 改继承约定：域基类 `class BaseXxx(BasePluggable, ABC)`、`Null` 类 `class NullXxx(BaseXxx, BaseNullObject)` 形状不变。
