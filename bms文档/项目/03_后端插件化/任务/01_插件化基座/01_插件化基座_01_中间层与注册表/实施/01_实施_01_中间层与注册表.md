## 3. 实施过程 <a id="process"></a>

1. **错误码与异常**：`app/core/error_codes.py` 加 `PLUGIN = 40002`；`app/core/exceptions.py` 加 `PluginError(ConfigError)`（4xxxx 段位、启动期致命）。
2. **BasePluggable**：`app/core/plugin.py` 落 `BasePluggable(BaseCapability, BaseAsyncResource)`——`plugin_key`（未声明回退 `key`）/ `plugin_name`（Null 未声明取 `null`、显式优先）/ `contract_version`（默认 `0.1.0`）；`setup()` / `aclose()` 默认空实现；`describe()` 插件标识 + 占位后缀；`__init_subclass__` 仅收集候选（抽象判定与校验统一在构建期）。
3. **PluginRegistry**：`collect` / `register` / `build` / `snapshot`；构建期合并双轨并聚合校验（抽象剔除、无名非 Null 跳过、契约版本 `X.Y.Z` 格式、`(plugin_key, plugin_name)` 重名即拒、显式项键名与 impl 校验）；快照为两级 `MappingProxyType`（只读、稳定排序）；构建后 `register` 拒绝（运行期只读）。
4. **入口函数**：进程级默认实例 + `register_plugin` / `build_plugin_registry` / `plugin_registry_snapshot` 薄封装（装配接线归 02 任务）。
5. **测试**：Kiwi 先登记（**529**；68/69 已被既有策展用例占用，按平台自增顺延），后写 `backend/tests/core/test_plugin.py`（14 条用例、`@pytest.mark.kiwi_id(529)`）。
6. **验证**：命令与结果见[测试记录](../测试/01_测试_01_中间层与注册表.md)；`app/core/plugin.py` 覆盖率 100%。
7. **文档重构（口径修正）**：需求 01-1 / 01-2 由两个平级任务共担与状态核对硬规则（任务已完成 ⇒ 需求已完成）冲突，经确认将「解析器与契约版本」「启动校验与 CI 离线校验」降为嵌套子任务（01-1-1 / 01-2-1），顶级任务与需求 1:1；任务域、计划、首页与 README 同步。

## 4. 问题与处置 <a id="issues"></a>

| 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- |
| Kiwi 设计预分配 68，平台 68/69 已被既有策展用例占用 | 策展库用例号连续登记，新用例以平台自增主键为准 | 顺延登记 **529**；设计对齐记录 / 测试记录同步（编号对齐纪律） |
| 细拆后需求 01-1 / 01-2 由两个平级任务共担，与「任务已完成 ⇒ 需求已完成」硬规则冲突 | 前序任务完成时需求尚未闭环（后置任务未完成） | 经确认**嵌套重构**：解析器与契约版本 → 01-1-1、启动校验与 CI 离线校验 → 01-2-1；顶级任务与需求 1:1，嵌套并入父任务统计 |
| `__init_subclass__` 收集期无法直接使用 `__abstractmethods__`（ABC 机制时序） | `ABCMeta` 在 `type.__new__` 之后才写入抽象集合 | 抽象判定统一在构建期（`inspect.isabstract`，Python 3.14 实测收集期亦可判定）；构建期判定便于错误聚合与启动一次性拒启（设计第 4 节已述） |
| 测试类会经 `__init_subclass__` 汇入进程级默认注册表 | 自动登记为进程级行为 | 用例以 `monkeypatch` 替换默认实例隔离（夹具 `registry`）；冲突 / 非法类不污染真实默认注册表 |
