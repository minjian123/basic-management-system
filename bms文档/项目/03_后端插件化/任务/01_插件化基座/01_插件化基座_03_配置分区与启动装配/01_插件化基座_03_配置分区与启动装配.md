## 2. 任务内容 <a id="content"></a>

1. `config.toml` 各能力分区按需补 `provider` / `options` 字段（仅被替换域添加）；`app/core/config.py` 建模支持（未知键 / 取值非法启动即报错，延续 [《后端基础能力需求》03-1（配置管理）](../../../../01_项目骨架/需求/03_需求_后端基础能力.md#r03-1) 口径）；密钥类只走 Secret / 环境变量，不入配置文件
2. 启动装配（`app/main.py` lifespan）：读取各能力 provider → 实例化并缓存 → 调 `setup()`；装配结果落 `app.state`，替代现有直连 `NullXxx()` 的装配段
3. 延迟导入：注册表登记实现类（或工厂），实例化时才导入具体实现模块——未选中实现不进启动路径
4. `aclose()` 经 `ResourceManager` 逆序统一回收
5. 启动日志：打印各能力当前 provider（不含 `options` 密钥），供排障核对
6. 单测：切换 provider 后装配结果随实现生效（消费方代码零改动）/ 未配置能力维持 `null` / 启动日志不含密钥

## 3. 完成标准 <a id="accept"></a>

切换某能力 provider 后装配随实现生效且消费方代码零改动；未配置能力维持解析到 `null`；启动日志可核对各能力 provider 且不含密钥；延迟导入生效（未选中实现不进启动路径）；`pytest` / `ruff` / `pyright` 全绿。
