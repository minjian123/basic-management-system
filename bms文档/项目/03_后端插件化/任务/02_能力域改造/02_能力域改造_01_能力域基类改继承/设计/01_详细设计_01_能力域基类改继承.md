# 能力域基类改继承详细设计

> 后端插件化 · 02 能力域改造 · 01 能力域基类改继承 · 详细设计

[文档首页](../../../../../../文档首页.md) › [01 能力域基类改继承](../02_能力域改造_01_能力域基类改继承.md) › 01 详细设计　|　[← 父任务](../02_能力域改造_01_能力域基类改继承.md)

## 1. 概述 <a id="overview"></a>

- **目标**：40 个能力域基类（直接 `BaseCapability` 子类）由 `BaseCapability` 换挂 `BasePluggable`（业务方法签名不变），并显式声明 `plugin_key` / `plugin_name` / `contract_version`；`BaseEventWorker` 迁至 `app/events/base.py` 解开循环导入；登记名规则调整为「自身声明优先」以消除端口声明的继承误登记。
- **范围**：约 35 个能力域源文件（含 `app/core/capability.py`、`app/events/base.py`）、`app/core/plugin.py`（登记规则）、新增注册语义用例。
- **不含**（归后续任务）：提供者 `get_xxx` 改经 `resolve_plugin`（02-2）；`null.py` 拆分迁移（02-3）；配置分区与启动装配（域一 01_02）；注册表构建接线（域一 01_02 在 lifespan 调 `build_plugin_registry()`）。
- **依据**：[需求 02-1](../../../../需求/02_需求_能力域改造.md#r02-1)、《架构设计 · 扩展点与插件化》「基类承载与双轨」节、《架构设计 · 后端基础类体系》「基类候选」节、《[后端基类清单](../../../../../../后端基类清单.md)》「能力域基类清单」节、《[后端开发规范](../../../../../../规范/后端开发规范.md)》「后端基座体系（强制）」节、[《01 详细设计 · 中间层与注册表》](../../../01_插件化基座/01_插件化基座_01_中间层与注册表/设计/01_详细设计_01_中间层与注册表.md)（机制契约）。

## 2. 现状与差距 <a id="gap"></a>

| 现状 | 差距 |
| --- | --- |
| 实测 40 个直接 `BaseCapability` 子类（含 `BaseEventWorker`，不含中间层 `BasePluggable` 本身），当前全部继承 `BaseCapability, ABC` | 未挂 `BasePluggable`、无 `plugin_key` / `plugin_name` / `contract_version`，实现类不触发自动登记 |
| `BaseEventWorker` 位于 `core/capability.py`，而 `core/plugin.py` 依赖 `capability.py` | 直接换挂会循环导入（plugin → capability → plugin） |
| 登记名规则按「继承到的 `plugin_name`」判定 | 端口声明 `plugin_name = "null"` 后，具体非 Null 子类（如 `HealthCheckRegistry`）会继承 `"null"` 误登记 |

## 5. 登记名规则调整 <a id="rule"></a>

`core/plugin.py` `_registration_name` 由「继承值判定」改为「**自身声明优先**」：

| 判定顺序 | 规则 | 示例 |
| --- | --- | --- |
| 1 | 类自身（`cls.__dict__`）声明且非空 `plugin_name` | `MinioStorage.plugin_name = "minio"` → `minio` |
| 2 | 自身未声明且 `BaseNullObject` 子类 | `NullObjectStorage` → `null` |
| 3 | 其余（含仅继承到端口声明的具体子类） | `HealthCheckRegistry`（继承 `BaseHealthCheckRegistry.plugin_name = "null"`）→ 不登记 |

- 语义：端口的 `plugin_name = "null"` 是「缺省实现名」的契约文档值，只对 Null 规则生效，不被具体子类继承。
- 影响面：01-1 / 01-1-1 既有用例在新规则下语义不变（显式实现的 `plugin_name` 均为自身声明；Null 走规则；无名不登记）；新增用例覆盖「继承申明不生效」。

## 6. `BaseEventWorker` 迁移 <a id="event-worker"></a>

- 落点 `app/events/base.py`：`class BaseEventWorker(BasePluggable)` + 三属性 + 抽象 `event_type`；`EventPublisher` / `EventConsumer` 继承关系不变。
- `core/capability.py` 删除该类并同步模块说明；`tests/core/test_capability.py` 改为从 `app.events.base` 导入。
- 依赖方向：`events/base.py → plugin.py → capability.py`（单向，无循环）。
- 登记回写：基类清单与架构 04 的 `BaseEventWorker` 代码位置（`core/capability.py` → `app/events/base.py`）。
