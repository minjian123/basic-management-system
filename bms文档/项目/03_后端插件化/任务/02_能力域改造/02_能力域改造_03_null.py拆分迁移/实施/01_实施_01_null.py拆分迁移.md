## 3. 实施过程 <a id="process"></a>

1. **类块迁移（codemod phase1）**：AST 按目标 `null.py` 分组抽取 38 个类块；生成导入（按原模块命名空间解析：契约 / 常量 / 三方导入）与 `__all__`；原文件删类块、`__all__` 移除、模块说明中迁移类条目清理。
2. **导入改写（phase2）**：遍历 `app` / `tests`，拆分含被迁类的 `ImportFrom` 并改写为 `from app.<domain>.null import …`；同模块多来源合并为一组导入。
3. **多源同目标修复**：`outbound`（http + webhook）、`transfer`（exporter + importer）两处目标文件被后写覆盖——修复 codemod 按目标分组生成，恢复两个源文件（`git checkout`）后定向重做。
4. **私有辅助随迁**：`_null_transaction`（db）与 `_EmptyExporterStream`（transfer）为缺省实现的内部工具，随类迁入对应 `null.py`（消除私有跨界引用与未用告警）。
5. **清理与验证**：`ruff check --fix` + `ruff format`；`Kiwi 532` 平台先登记，后写 `tests/crosscut/test_null_migration.py`（落点护栏 / 可导入 / 旧路径不可用 / 登记语义不变）。
6. **回写**：架构 10「结构迁移」注记、基类清单「代码位置」列（33 域补 `null.py`）。

关键命令：

uv run python -m ops.check_modules

## 4. 问题与处置 <a id="issues"></a>

| 问题 / 现象 | 原因 | 处置与落点 |
| --- | --- | --- |
| `app.outbound.null` / `app.transfer.null` 缺类（ImportError） | codemod 按「原模块」逐一写目标文件，多源同目标后写覆盖 | 修复为**按目标分组**生成；`git checkout` 恢复源文件后定向重做（其余目标不受影响） |
| `_null_transaction` / `_EmptyExporterStream` 私有跨界引用（pyright 报错） | 缺省实现的内部工具留在原文件 | 随实现迁入 `db/null.py` / `transfer/null.py`；原文件清理未用定义 |

| 测试 `tests/storage/test_storage.py` 等断言继承 `BaseCapability` | 02-1 后能力域基类经 `BasePluggable` 间接继承 | 断言仍成立（`BasePluggable → BaseCapability`），无需改动 |
