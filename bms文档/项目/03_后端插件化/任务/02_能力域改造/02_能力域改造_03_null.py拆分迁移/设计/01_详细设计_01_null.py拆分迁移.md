## 1. 概述 <a id="overview"></a>

- **目标**：38 个 `NullXxx`（缺省实现）自各域 `base.py` 等文件迁至同域 `null.py`，原文件只保留端口契约 / 数据契约 / 常量；导入路径全量调整、不留转发导出；目录结构对齐「`base.py`（契约）/ `null.py`（缺省实现）/ `<impl>.py`（平台内建实现）」。
- **范围**：38 个类、33 个目标 `null.py`（新增）、原文件（`base.py` 等 36 个）删除类块与导出、`app` / `tests` 导入改写、护栏用例。
- **不含**（归后续任务）：平台内建实现落点 `<domain>/<impl>.py`（随域四 04-1）；`app/plugins/` 集中区不启用；配置分区与启动装配（域一 01_02）。
- **依据**：[需求 02-3](../../../../需求/02_需求_能力域改造.md#r02-3)、《架构设计 · 扩展点与插件化》「代码结构（目标）」节（「结构迁移」注记）、《[后端基类清单](../../../../../../后端基类清单.md)》、《[后端开发规范](../../../../../../规范/后端开发规范.md)》、[《02-1 详细设计》](../../02_能力域改造_01_能力域基类改继承/设计/01_详细设计_01_能力域基类改继承.md)。

## 5. 结构与导出口径 <a id="structure"></a>

- 原文件（`base.py` 等）只保留端口契约 / 数据契约 / 常量；类块移除、`__all__` 同步移除、模块说明中提及迁移类的条目清理。
- `null.py`：模块说明（「<域> 缺省实现（Null Object）」）+ 必要导入 + 迁移类原样 + `__all__`（排序）。
- **不留转发导出**：旧路径（如 `app.storage.base.NullObjectStorage`）不可用；`from app.<domain>.null import NullXxx` 为唯一路径。
- 类实现与语义不变（`BaseNullObject` 子类、`placeholder` 标记、`describe` 占位后缀、插件登记 `null` 不变）。

## 6. 导入路径全量改写 <a id="imports"></a>

- 覆盖 `app` / `tests`（`ops` 无引用）：对每个「从旧模块导入被迁类」的 `ImportFrom` 语句拆分/改写为 `from app.<domain>.null import …`；原语句若剩余其它名称则保留（仅移除被迁名），为空则删除语句。
- 同域内其它模块（如 `app/health/registry.py` 引用 `NullHealthCheckRegistry`、`app/api/deps.py` 等）同样按此改写。
- 实施后以 `ruff check --fix` 清理导入顺序与未用导入，`pyright` / 全量 `pytest` 把关。
