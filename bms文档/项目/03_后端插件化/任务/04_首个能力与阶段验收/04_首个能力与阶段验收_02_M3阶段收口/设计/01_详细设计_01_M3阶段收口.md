## 4. 设计 <a id="design"></a>

### 4.1 门禁核对口径（8 项）

- **证据三件套**：命令输出（本地同口径）/ 流水线号（GitLab bms/bms）/ Kiwi 用例编号；缺一不算达标。
- **结论口径**：`达标`（证据齐备可复核）/ `不达标`（转缺陷或后续任务，门禁保持未达标并在风险登记）。
- 逐项复核方式：门禁表既有「核对方式」列 + 本阶段任务记录索引（链接到任务文档与记录）。

### 4.2 里程碑与状态收口

| 对象 | 动作 |
| --- | --- |
| 门禁表 | 8 项结论 + 证据索引；「阶段验收留痕」由本报告 + 收口记录承担 |
| 计划 §5 | 逐项结论同步；§4 甘特加 M3 里程碑节点；头部「已完成 11/11」 |
| 需求总览 | 11 条需求状态全 `已完成`；进度注「阶段三 M3 达成」 |
| 阶段 README | 标注 M3 达成（日期 + 关键 Kiwi 编号） |
| 任务 / 需求域文档 | 04_02 / 04-2-1 状态与日期；04 域文档子任务清单 |

### 4.3 偏差回写与遗留处理

- 核对中发现的实施与设计偏差：回写对应设计（架构 10 / 基类清单 / 各任务设计）——本阶段各任务已在收口时逐项回写，本任务只做**复核**与遗漏兜底。
- 遗留项去向：既有 §3.1 台账（第 1 ~ 5 项闭环；第 6 ~ 8 项随阶段八 / 认证 / RBAC 等对应阶段；第 8 项已随流水线 #194 闭环）——本任务复核台账无遗漏。
