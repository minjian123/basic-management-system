## 1. 概述 <a id="overview"></a>

- **目标**：归档阶段测试报告（落点 `bms文档/项目/03_后端插件化/01_测试报告_后端插件化.md`；结构与阶段一报告同构），并完成三类文档状态收口与三项自检留痕。
- **范围**：报告撰写（执行统计 / 缺陷与遗留 / 覆盖率 / 风险与对策 / 复盘与经验教训 / 附录）+ 状态收口复核。
- **不含**：代码与用例改动；门禁结论（归父任务 04-2）。
- **依据**：[需求 04-2](../../../../../需求/04_需求_首个能力与阶段验收.md#r04-2)、《测试规范》「测试报告」与「用例管理」节、[阶段一测试报告先例](../../../../../../01_项目骨架/01_测试报告_项目骨架.md)。

## 2. 报告结构（与阶段一同构） <a id="structure"></a>

| 节 | 内容 | 数据来源 |
| --- | --- | --- |
| 测试信息 | 阶段 / 范围 / 环境 / Kiwi 用例范围（529 ~ 66x） | 任务记录汇总 |
| 1 用例执行统计 | 全量 `pytest`（passed / skipped）、契约套件与关键域用例、按域 Kiwi 编号清单 | `uv run pytest -q`、各任务测试记录 |
| 2 缺陷统计 | 本阶段缺陷（自动捕获 + 人工）：数量 / 级别 / 状态 / 去向 | GitLab Issue（`defect-auto` 标签） |
| 3 覆盖率 | TOTAL 与关键模块（插件机制 / 注册表 / 装配 / provider / 存储） | `pytest --cov` term-missing |
| 4 风险与遗留项 | 遗留台账（阶段八真实连通、认证 / RBAC、第三方插件演进等）+ 风险回顾（计划 §6） | 计划 §3.1 / §6 |
| 5 复盘与经验教训 | 过程问题与改进项（设计预判 / 测试先行 / 文档链接易错点等） | 各任务实施记录 §4 |
| 附录 A | 数据采集命令与原始输出（含流水线号） | 收口当日命令留档 |

## 3. 数据采集口径 <a id="collect"></a>

```bash
uv run pytest --cov=app --cov-branch --cov-report=term-missing -q   # 执行与覆盖率
uv run ruff check . && uv run ruff format --check . && uv run pyright
uv run python -m ops.check_plugins
python3 scripts/tools/check-docs/check-status.py --stage 03_后端插件化
python3 scripts/tools/base-check/check-base.py
python3 scripts/tools/base-check/check-links.py
```

- 流水线号：以阶段末推送后实际流水线为准（写入附录；如失败则记风险并保持门禁未达标）。
- Kiwi 用例编号：按域汇总（01 域 529 ~ 534、565 / 566；02 域 531 / 532 / 565；03 域 567 / 568 / 651 / 652 / 655；04 域 661 / 662 / 66x）。

| Kiwi | 用例 | 执行方式 | 断言要点 |
| --- | --- | --- | --- |
| 待登记 | `test_stage_report_archive` | 文档核对（报告存在 + 关键节齐备 + 链接可解析 + 数据可复核） | 报告六节 + 附录齐备；引用链接无断链；执行数据与命令输出一致 |

## 6. 实施步骤 <a id="steps"></a>

1. 采集数据（命令 + 流水线）→ 撰写报告。
2. 状态收口复核 → 三项自检 → 报告附录填实际输出。
3. 实施 / 测试记录；父任务门禁回写联动。

## 7. 验收映射 <a id="accept-map"></a>

| 完成标准 | 验证方式 |
| --- | --- |
| 报告归档且结构齐备 | 文档 diff + 核对清单 |
| 数据可复核 | 附录命令与实测输出一致 |
| 状态一致 + 自检通过 | 三项自检输出 |

## 8. 边界与开放项 <a id="boundary"></a>

- 报告数据为收口当日快照；后续阶段引用以本报告为准（不改历史数据）。
- 缺陷统计以 GitLab 实际 Issue 为准；本阶段无新增自动缺陷时记「0」。
