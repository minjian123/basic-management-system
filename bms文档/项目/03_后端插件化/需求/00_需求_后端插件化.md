## 2. 阶段三目标与范围 <a id="goal"></a>

**M3 目标**（《总体项目规划》「里程碑」节 M3 行）：**`BasePluggable` 与插件注册表可用；配置切换 provider 生效且业务代码零改动；非法 provider / 重名 / 契约版本不符启动被拒；继承与组合双轨注册可用；契约测试覆盖全部注册实现**。周期口径 2 周（兼职）。

**范围内**（共 11 条需求，见第 3 节总清单）：

| 需求域 | 内容 |
| --- | --- |
| 一 插件化基座 | 插件化中间层 `BasePluggable` 与插件注册表（`core/plugin.py`）、配置驱动装配与启动 / CI 校验、插件清单接口 |
| 二 能力域改造 | 40 个能力域基类改继承 `BasePluggable`、35 个提供者改经 `resolve_plugin`、代码结构对齐（`null.py` 拆分迁移） |
| 三 契约与收敛提取 | 契约测试基座（统一契约套件）、`BaseProvider` 与 `BaseProviderRegistry` 提取 |
| 四 首个能力与阶段验收 | 对象存储（local + MinIO）接入验证、M3 门禁核对与阶段测试报告 |

**范围外**：

- 运行时热插拔（实例级 holder 原子替换、启停 / 灰度 / 回滚）与第三方 entry points 自动发现——三阶段演进的后两阶段，按需再评估（见《架构设计 · 扩展点与插件化》成熟度表）。
- P2 暂缓项：配置源中间层（触发：远端配置 / Secret 多源）、日志落点中间层（触发：阶段十三多落点日志采集）。
- 对象存储之外的各能力真实实现——随对应阶段（通知随通知公告阶段、LLM 随 AI 阶段、检索随全文检索阶段等）。
