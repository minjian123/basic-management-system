## 2. 需求 03-1：契约测试基座 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：阶段验收门禁明确「**契约测试覆盖全部注册实现**」。现状各域测试各写各的（字段类型注册表、查询提供者注册表、仪表盘卡片注册表、健康检查注册表四套独立用例），插件化后实现可替换——**每个实现都必须满足同一套语义**（唯一性、未命中、Null 无副作用等），逐个手写必漏。

**内容**（《架构设计 · 扩展点与插件化》「阶段三交付与验收（M3 口径）」节交付物 #7）：

1. 统一契约套件（pytest）：以参数化 fixture 遍历**注册表全部注册实现**，统一校验——注册唯一性（重名拒）/ 未命中语义（抛错或空响应按域约定）/ `Null` 无副作用 / 聚合模板（聚合型能力的合并语义）/ 生命周期（`setup` 幂等、`aclose` 可重入）。
2. **自动纳入**：新增实现仅需登记注册表即被套件遍历（防漏测）；用例与被测域解耦（不改套件加实现）。
3. 覆盖注册表与当前全部注册实现（含 `Null` 缺省实现）；对象存储双实现（04-1）纳入。
4. 执行口径：入常规 `pytest` 链路（本地 / CI 冒烟与全量分层一致）；用例入 Kiwi（若已部署）。

**完成标准**：契约套件可运行并遍历全部已注册实现；新增实现自动纳入（以对象存储双实现验证）；`Null` 实现纳入；全量 `pytest` / `ruff` / `pyright` 全绿；作为 M3「契约测试全覆盖」证据入阶段测试报告（04-2）。

**参考文档**：《架构设计 · 扩展点与插件化》「阶段三交付与验收（M3 口径）」节；《测试规范》「自动化测试分层」节；《后端开发规范》测试要求

## 3. 需求 03-2：BaseProvider 提取 <a id="r03-2"></a>

优先级：3（中）

**背景与动机**：4 类插件型「提供者」（字段类型 `BaseFieldType`、查询提供者 `BaseQueryProvider`、仪表盘卡片提供者 `BaseDashboardCardProvider`、健康检查 `BaseHealthCheck`）目前各自继承 `BaseCapability` 并要求 `key`，形似而神散；阶段一基座盘点登记为 P1 候选（缩一个公共契约）。

**内容**（《架构设计 · 后端基础类体系》「基类候选」节）：

1. 提取 `BaseProvider(BaseCapability)`：统一「注册项」公共契约（抽象 `key` + 元信息），4 类提供者改继承。
2. 与 `BasePluggable` 边界保持清晰：提供者走**组合轨**（`register_plugin` 显式登记，进入能力域插件命名空间），不因本提取混入继承自动登记。
3. 登记回写：架构 04、基类清单。

**完成标准**：4 类提供者统一继承 `BaseProvider`；既有注册表与契约套件（03-1）不破、全量测试通过；文档登记同步。

**参考文档**：《架构设计 · 后端基础类体系》「基类候选」节；《后端基类清单》候选表；《架构设计 · 扩展点与插件化》「基类承载与双轨」节（组合轨）

## 4. 需求 03-3：BaseProviderRegistry 提取 <a id="r03-3"></a>

优先级：3（中）

**背景与动机**：4 个域注册表（字段类型 / 查询提供者 / 仪表盘卡片 / 健康检查）与 `Null` 注册表各自实现「注册（唯一性拒重）+ 获取（未命中语义）+ keys」，语义同构、代码重复；阶段一基座盘点登记为 P1 候选（提取公共实现，聚合模板保留各域）。

**内容**（《架构设计 · 后端基础类体系》「基类候选」节）：

1. 提取 `BaseProviderRegistry[K, V]`：公共 `register`（唯一性拒重）/ `get`（未命中统一语义）/ `keys`；4 个域注册表与 `Null` 注册表改继承，行为不变。
2. 聚合模板（如健康检查聚合、卡片聚合）**保留在各域**（共性收敛、特性留域）。
3. 与插件注册表语义对齐：唯一性 / 未命中语义一致（插件注册表为两级结构，不合并实现）——契约套件可复用同一断言口径。
4. 登记回写：架构 04、基类清单。

**完成标准**：4 个域注册表收敛且行为不变（既有用例全绿）；插件注册表语义口径对齐；全量 `pytest` / `ruff` / `pyright` 通过；文档登记同步。
