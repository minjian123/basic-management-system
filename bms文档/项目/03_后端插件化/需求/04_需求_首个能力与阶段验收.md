## 2. 需求 04-1：首个纵向能力接入验证（对象存储 local + MinIO） <a id="r04-1"></a>

优先级：2（高）　|　状态：未开始　|　完成日期：—

**背景与动机**：插件化机制（域一）与改造面（域二）是否真的「可替换」，必须用一个**真实能力**端到端验证：对象存储被文档管理 / 附件 / 导入导出等多处消费，且「本地文件系统 ↔ MinIO ↔ 未来云端对象存储」是可预见的替换场景（《平台可扩展性规划》「开源与商业组件可替换」原则的典型样本）；选它做首个接入样本，兼顾验证代表性（有真实消费方）与依赖可控（`local` 零依赖即可跑通切换验证）。

**内容**（《架构设计 · 扩展点与插件化》「阶段三交付与验收（M3 口径）」节交付物 #8）：

1. 对象存储能力落两个**平台内建实现**：
   - `local`：本地文件系统实现（零依赖，本机临时目录可读写，缺省可用）；
   - `minio`：MinIO 客户端实现（延迟导入、端点 / 凭据走配置与 Secret，密钥不落日志 / 不进清单）。
2. 配置切换：`config.toml` `[storage] provider = local | minio`，切换后消费方（`get_storage` 调用方）**零改动**。
3. 依赖隔离验证：`provider = local` 时 MinIO 客户端不被导入；`provider = minio` 且依赖缺失 / 服务不可达时按启动校验口径拒启（错误信息可读）。
4. 两实现纳入契约测试（03-1）与插件清单（01-3）；MinIO 真实连通的端到端实测随阶段八（文件管理），本阶段以「配置 + 单元 / 契约测试」验证切换正确性，不依赖 MinIO 服务常驻。

**完成标准**：`local` / `minio` 双实现就位且落点 `<domain>/<impl>.py`；`local` 真实读写通过、`minio` 延迟导入与密钥分离可证；切换 provider 消费方零改动；双实现纳入契约套件与插件清单；全量 `pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《架构设计 · 扩展点与插件化》「阶段三交付与验收（M3 口径）」节；《平台可扩展性规划》「开源与商业组件可替换」节；《后端基类清单》`BaseStorage` 行；《架构设计 · 数据与存储》对象存储口径
