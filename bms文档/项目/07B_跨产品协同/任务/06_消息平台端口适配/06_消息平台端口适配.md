## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：`bms_core` 既有 `servicecall` / `events` / `circuit` / `idempotency` 能力域与 `PluginSelection` 配置模型；msg 04-1 ~ 04-4 已交付的协议库（frame / client / retry / circuit / 五类错误分类）；两仓契约快照与护栏。
- **风险**：① 只搬 `client/` 不搬帧编解码与协议异常，反向引用只是被藏起来、环未真断；② `errors.py` / `config.py` 整体上移会把 25 个产品业务异常与数据面常量带进基座，违反「产品标识不入基座」；③ 改名不彻底使基座残留 `msg` 字面量，与已收口的零命中硬门禁冲突；④ 两仓版本错配导致帧格式或错误码漂移；⑤ 切换 / 回滚窗口的在途请求与未确认事件处置不当产生重复副作用。
- **对策**：详细设计逐文件列「上移 / 切割 / 留仓」清单并给逐项判据；常量改通用语义名、帧字节与码值不动；契约快照字段值改从基座常量读取，加版本门禁；回滚三态写明 drain、配置版本戳与 outbox 重投，演练步骤进测试设计。
