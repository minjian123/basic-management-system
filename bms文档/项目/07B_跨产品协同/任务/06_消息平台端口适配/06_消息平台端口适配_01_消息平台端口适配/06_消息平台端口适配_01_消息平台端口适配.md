## 2. 任务内容 <a id="content"></a>

1. **前置步骤 · 协议链上移**（另立实施子任务，代码归后续会话）：在 `bms_core` 新增能力域 `msgclient/`，按[详细设计 §3.2](设计/01_详细设计_01_消息平台端口适配.md#uplift) 的 A / B / C 三类清单搬迁——A 类整体上移（客户端、帧编解码与 payload、`deadline` / `naming`、两个值对象、RPC 常量段），B 类切一刀（两个枚举、协议异常基类、三个协议异常上移；25 个业务异常与 `MsgErrorMapper` 留 msg），C 类明确留 msg 仓（服务端装配态 / `api` / `broker` / `schemas` / 数据面常量）。
2. **命名与登记**：帧字节、码值与契约形状不变，产品字面量改通用语义名；`msgclient` 能力域登记进《[后端基类清单](../../../../../后端基类清单.md)》§9 与《[跨产品协同登记清单](../../../../../跨产品协同登记清单.md)》§2；msg 仓作为首个接入产品在声明里给具体值。
3. **msg 仓改造**：删除 `bms_msg/client/` 与帧协议本地副本，服务端与用例统一 `from bms_core.msgclient import …`；`protocol/contract.py` / `rpc/contract.py` 改为读取基座常量后重导 `deploy/contracts/msg.json`，快照仍由 msg 仓导出。测试替身、既有设计文档引用口径同步更新。
4. **适配层实现**：在 `bms_core` 内新增 `BaseServiceClient` / `EventPublisher` 的 msg 版实现，接入既有 `resolve_plugin`；`call(ServiceRequest)` → `/rpc/{service}/{method}`、`publish(event)` → `/msg/publish`，`ServiceCallPolicy` 的韧性字段映射到 04-4 的 `RetryPolicy` / 熔断 / 幂等键，不重复实现。
5. **配置切换**：`[service_client].provider` / `[event].provider` 取 `msg` 即整进程切换，取原值即回滚；缺实现时拒启并给出明确错，不静默降级；业务代码零改动。
6. **错误与上下文**：按 04-4 的 `category` / `retryable` / `code` 映射 bms 异常，保留原始码与 `retryable`；`trace_id` / `tenant_id` / 服务 JWT 透传，沿用既有租户解析链。
7. **回滚演练与两仓联调**：按[详细设计 §3.8](设计/01_详细设计_01_消息平台端口适配.md#rollback) 演练在途请求 / 未确认事件 / 双写窗口三态；跨仓共享 fixture（请求 / 响应 / 错误 / timeout / cancel / 幂等键）跑契约测试；替换一个真实 `HttpServiceClient` 调用并验证切回后行为恢复。
8. **边界**：不改 bms 端口契约；不做产品业务迁移（8B_08）、事务消息（8B_04）、outbox relay 替换、多实例选主（04-6 / 8B_05）；不在 bms 仓内重写帧客户端；不新增第二套插件装配路径。

## 3. 完成标准 <a id="accept"></a>

- `bms_core` 代码零 `bms_msg` 引用；bms 单仓 CI 不 clone msg 即可通过；msg 仓无客户端本地副本，协议实现唯一。
- 所有继承 `bms-core` 的产品仓可直接 `from bms_core.msgclient import …` 调用，无需额外部署或跨仓装配。
- 业务代码不改即可在 `msg` 与原实现之间切换；切回原实现后行为恢复；缺实现拒启。
- 错误码 / 超时 / trace / 租户映射正确，原始码与 `retryable` 不丢；回滚三态演练有结论。
- 一个真实 `HttpServiceClient` 调用被 RPC 替换、事件发布链路可切换（8B_03 退出条件）。
- 两仓变更模块行 + 分支覆盖率 100%；ruff / format / pyright、契约快照、文档三项校验全绿；Kiwi 用例在编码前回读最大号 +1 登记并回读核对。
