# engkit 产品字面量规则详细设计

> 跨产品协同 · 04 护栏与 CI · 01 engkit 产品字面量规则 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [01 engkit 产品字面量规则](../04_护栏与CI_01_engkit产品字面量规则.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：在 engkit 中新增一条**通用**护栏规则——「平台类仓的禁入面不得出现产品标识」，判定面、标识清单与允许位置**全部由各仓配置声明**（engkit 包内零仓名、零产品名），从机制上阻止“改一处、漏五处”的复发。

**范围内**：

1. 规则模块与 CLI 子命令（`product-literals`）；
2. 配置字段（扫描面、禁入面、允许面、标识清单、基线、豁免标记）；
3. 匹配规则（词边界与组合形态，避免误伤）；
4. 基线递减与“收编完成后转硬门禁”的切换路径；
5. 自测与包内元校验；接入预检与 CI。

**范围外**：bms 侧的具体收编（`03_01` / `03_02` / `03_03`）、CI 作业编排本身（`04_02`）、文档类护栏（已有 `docs-scope`）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| engkit 结构 | `src/engkit/*.py` 模块级规则（`docs_scope.py` / `docs_links.py` / `coverage.py` / `guard.py` / `preflight.py` 等），CLI 在 `cli.py` 注册子命令 |
| 规则风格 | **规则通用、白名单由各仓 `engkit.toml` 声明**（如 `[docs.scope]` 的 `whitelist_dirs` / `whitelist_files`），规则代码不出现仓名 |
| 自测 | 规则模块提供 `--self-test`（内置正反夹具，`preflight` 会调用其中若干项） |
| 豁免标记 | 文档类规则支持行内标记（如 `docs-scope:allow:<理由>`） |
| 缺口 | **无产品标识护栏**——本次跨仓漂移（`org` → `mdm`）无任何机器拦截，靠人工发现 |

## 3. 设计 <a id="design"></a>

### 3.1 规则定位 <a id="position"></a>

| 项 | 口径 |
| --- | --- |
| 通用性 | 规则本体只认「配置给的标识清单」与「配置给的路径面」，不内置任何仓名 / 产品名 / 目录名 |
| 插件形态 | 独立模块 `product_literals.py` + CLI 子命令 `product-literals`，与 `docs-scope` 平级 |
| 适用仓 | 任何“平台类”仓（声明 `[product_literals]` 即启用）；产品仓可声明**反向**用法（禁入面为自己的下游标识），但本任务只服务平台仓 |

### 3.2 配置字段 <a id="config"></a>

```toml
[product_literals]
enabled = true
# 禁入面：平台源码、平台种子、前端常量（相对仓根）
deny_globs = [
  "backend/libs/**/*.py",
  "backend/services/**/*.py",
  "backend/ops/**/*.py",
  "frontend/packages/**/*.ts",
  "frontend/apps/**/*.ts",
  "frontend/apps/**/*.vue",
]
# 允许面：测试夹具、产品自持声明、文档与登记清单
allow_globs = [
  "**/tests/**",
  "deploy/registry/**",
  "bms文档/**",
]
# 标识清单（各仓自declared；不写进规则代码）
literals = ["mdm", "biz", "cw"]
# 组合形态（与该标识紧邻的下划线 / 点分片段，如表前缀、事件域、业务码）
combine_suffixes = ["_", ".", ":", "-"]
# 存量基线（收编期为递减清单；空 = 硬门禁）
baseline = "scripts/tools/base_check/product-literals-baseline.txt"
# 行内豁免标记前缀（必须带非空理由）
exempt_marker = "product-literal:allow:"
```

| 字段 | 必填 | 语义 |
| --- | --- | --- |
| `enabled` | 是 | 关闭时子命令直接返回 0（保留给产品仓） |
| `deny_globs` | 是 | 禁入面；命中即违规 |
| `allow_globs` | 否 | 允许面；优先于禁入面判定 |
| `literals` | 是 | 需拦截的标识清单 |
| `combine_suffixes` | 否 | 判定“组合形态”是否仍算违规（缺省 `["_", ".", ":", "-"]`，即 `mdm_` / `mdm.x` / `mdm:x` 都算） |
| `baseline` | 否 | 存量基线文件；为空表示零容忍 |
| `exempt_marker` | 否 | 行内豁免标记前缀；理由为空视为无效豁免 |

### 3.3 匹配规则 <a id="match"></a>

| 形态 | 判定 | 例 |
| --- | --- | --- |
| 裸标识（词边界） | 违规 | `service = "mdm"` |
| 组合形态（标识 + 后缀） | 违规 | `mdm_dept`（表前缀）、`mdm.org.*`（事件域 / 能力名）、`mdm:query`（权限码） |
| 出现在字符串 / 注释 / 标识符中 | **一律判定**（注释里的旧口径同样会误导线上的后来者） | `# 组织关系归 mdm` |
| 允许面命中 | 不判定 | `tests/**`、`deploy/registry/**`、文档 |
| 行内豁免 | 不判定，但**理由必须非空**；空理由按违规报 | `... # product-literal:allow:兼容历史事务分支` |

**为什么组合形态也算违规**：本次漂移正是“服务键变了、表前缀 / 事件域 / 权限码跟着变”，只拦裸标识会漏掉 `mdm_`、`mdm.`、`mdm:` 三种最常见的引用形态。

**为什么允许面含文档**：登记清单与架构节点**必须**写产品名（否则无法表达），护栏只约束代码与种子。

### 3.4 基线递减与门禁切换 <a id="baseline"></a>

| 阶段 | 行为 |
| --- | --- |
| 收编期 | 存量违规写入基线文件（每条记「相对路径 + 行指纹」）；运行只报**新增**违规，退出码按新增计 |
| 收编完成 | 基线清空（删除文件内容），规则转为硬门禁：任一命中即失败 |
| 基线维护 | `--update-baseline` 仅用于“确认存量”的受控动作，需人工执行并审阅差异；CI 一律**不允许**自动更新 |

### 3.5 输出与退出码 <a id="output"></a>

**输出**：逐条 `相对路径:行号  命中片段  → 建议`，建议文案固定为「改为按能力名 / 服务目录取用，或登记到产品自持声明」。

**汇总**：`检查 N 个文件，命中 M 处（新增 X / 基线 Y / 豁免 Z）`。

| 退出码 | 含义 |
| --- | --- |
| 0 | 无新增违规（含全部命中基线或豁免） |
| 1 | 存在新增违规 |
| 2 | 配置错误（缺 `literals`、`baseline` 不可读、glob 非法） |

### 3.6 自测与包内元校验 <a id="selftest"></a>

| 项 | 要求 |
| --- | --- |
| `--self-test` | 内置夹具覆盖：裸标识命中、组合形态命中、允许面不命中、豁免（含空理由判违规）、基线抑制、退出码 |
| 包内元校验 | 自测中断言「engkit 源码自身不含配置里的标识清单」——防止规则把产品名写进包 |
| 与 `preflight` 集成 | `preflight --fast` 增加一步（秒级），CI 的基座完整性作业同步加入 |

### 3.7 与既有规则的边界 <a id="boundary"></a>

| 已有规则 | 分工 |
| --- | --- |
| `check_service_boundaries`（bms 自研） | 断言服务包之间的 import 与目录边界；本规则断言**标识字面量** |
| `docs-scope` | 文档进度字段落点；本规则不碰文档 |
| `check_backend_base` / `check_bare_collections` | 继承链与集合声明；与本规则无交集 |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 裸标识命中 | 报违规、退出码 1、含行号与建议 |
| 2 | 组合形态（`_` / `.` / `:` / `-`） | 四种均命中 |
| 3 | 允许面 | `tests/**` / `deploy/registry/**` / 文档不报 |
| 4 | 行内豁免（有理由） | 不报，计入豁免计数 |
| 5 | 行内豁免（空理由） | 按违规报 |
| 6 | 基线抑制 | 基线内命中不报，退出码 0 |
| 7 | 新增违规（不在基线） | 报并退出码 1 |
| 8 | `--update-baseline` | 生成/更新基线；CI 场景禁用的断言（命令存在性检查） |
| 9 | 配置错误（缺 `literals`） | 退出码 2，信息可读 |
| 10 | 关闭开关 | 直接返回 0 |
| 11 | 自测 | `--self-test` 全通过 |
| 12 | 包内元校验 | engkit 源码不含配置中的标识清单 |
| 13 | 误伤检查 | 与 `mdm` 无关的英文词（如 `mdma`）不命中（词边界正确） |
| 14 | 性能 | 仓内全量扫描在预检秒级档内完成 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 误伤（表前缀、事件域合法使用场景） | 组合形态**故意**计入违规（这些正是要迁移的引用）；确需保留时用带理由的豁免，评审关注豁免增长 |
| 豁免滥用导致规则失效 | 理由必填 + 统计豁免数量 + 评审；基线只减不增（新增即失败） |
| 标识清单遗漏（新产品未加入） | 产品接入流程（《项目规划说明》接入步骤）增加“登记到 `literals`”；清单与产品目录对账写入 `04_02` |
| 规则分散在多仓难以升级 | 规则在 engkit 单一实现，各仓只声明配置 |
| 与产品仓冲突（产品仓内出现自己名字是正常的） | 规则只对声明了禁入面的仓生效；产品仓不声明或声明为空 |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 是否按“标识 → 建议动作”给出更细的整改提示（如“改为 `resolve_capability('mdm.org.user-roles')`”） | 规则稳定后评估；当前给统一建议文案 |
| 2 | 是否扩展到“平台源码不得出现产品表前缀”的独立规则 | 当前已由组合形态覆盖，出现误判再拆分 |
| 3 | 产品仓是否启用“反向护栏”（不得直连其他产品） | 产品间直连真实出现时评估 |
| 4 | 基线文件的存储位置与审阅方式 | 与仓库既有基线文件口径统一 |
