## 2. 决策确认 <a id="decisions"></a>

实施前逐项确认 **9 项**（结论已回写设计 §8 决策记录）：

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 校验对象 | **双层**：L1 跨仓文件校验（契约定位 / 版本 / 种子入口 / 错误码段位）+ L2 临时库注册（跨产品一致性 + 注册表↔声明对账） |
| 2 | `product_manifests` | **本轮退役**；清单模式取源改「本仓自动发现 + `--manifest` 参数」 |
| 3 | 服务行格式前置校验 | **随本轮做**，复用离线校验同一套规则（抽 `validate_module_record()`） |
| 4 | CI 作业形态 | **独立 job**（stage lint，并行），一次性硬门禁；仅 `CROSS_REPO_ALLOW_MISSING=1` 显式跳过 |
| 5 | 本地等价入口 | **扩 `ops.check_modules`** + 预检加一步（不新增薄包装脚本） |
| 6 | 工作量 | **需重估**（计划表内原值不含 §3.4 口径修正与两项前置校验）；数值在计划表 |
| 7 | mdm `87b7c94` | 单独推送（`7da985f..87b7c94`），与本任务解耦 |
| 8 | 实测 11 项存量差异 | **修口径**（A 收窄平台载荷 / B 基准改声明集 / C 常量未声明产品降为警示） |
| 9 | `[seeds.tables]` 表名存在性 | **随本轮做，只校平台自身**；产品种子保留告警 |

## 3. 实施落点 <a id="changes"></a>

### 3.1 校验与入口（`backend/ops/check_modules.py`）

| # | 内容 |
| --- | --- |
| 1 | **跨仓档** `--cross-repo`（+ `--product-root` / `--manifest` / `--ephemeral` / `--keep-tmp` / `--allow-missing`）：L1 一次装载（本仓 + 产品仓清单）→ `inspect_product_manifests`；L2 建一次性 SQLite（`apply_unit_schema`，26 表）→ 平台自注册 → 各产品按 `product_key` 升序注册 → `check_catalog_db` + `check_registry_db` 双向对账 → 临时目录清理（`--keep-tmp` 保留） |
| 2 | **取源改**：`manifest_paths()` = 本仓 `local_manifest_paths()` + `--manifest`（去重保序）；`check_manifests()` 由「读配置键」改为「本仓自动发现」——修掉平台 `platform.toml` 四段校验长期**空跑**的缺陷 |
| 3 | **平台载荷收窄**：`platform_payload()` 只并 `product_key` 为空的平台自身服务行（抽 `_with_platform_services()`，与 `declaration_bootstrap` 同口径） |
| 4 | **接库基准改声明集**：`check_catalog_db(url, payloads, warnings)`——平台自身行以常量为基准双向对账（`validate_catalog(..., products=常量, routes=空)`，路由属声明方所有不重复判）；产品档案以**声明**为基准；常量有声明无的产品（计划产品）只警示 |
| 5 | **对账逐方**：`check_registry_db(url, payloads, warnings)` 对每个声明方跑 `diff_platform_declarations`，差异带声明方前缀 |
| 6 | **产品仓根三形态**：仓根 / `deploy/registry` 目录 / **克隆容器目录**（CI 的 `../product` 逐个子目录展开） |
| 7 | **平台声明缺失守卫**：接库 / 一次性库 / 跨仓三档在「无平台声明」时直接判错（不静默放行） |
| 8 | async 化：接库校验拆 `_check_catalog_db` / `_check_registry_db`（注册表档在事件循环内），保留同步壳给 CLI |

## 4. 与设计的偏差（实施期修正，已回写设计） <a id="deviations"></a>

| # | 设计原写 | 实施 | 原因 |
| --- | --- | --- | --- |
| 1 | 种子表名校验「调用点：L1 的 `inspect_product_manifests`」 | 落在 **`ops.check_modules.check_manifests`**（L1 ops 层）+ 注册期 `validate_declarations` | 放 `inspect_product_manifests` 会让产品进程为一条平台专属校验额外拉模型元数据 |
| 2 | 表集来源「`Base.metadata`（惰性导入）」 | 改 **`unit_metadata(unit, datasource)`**（按种子 `db_key` 解析） | 实测：`Base.metadata` 在未导入模型模块时为空集 → 合法表名（如 `sys_tenant`）被全判缺失；且 `sys_tenant` 属 `tenant` 单元，只按平台单元取值也会漏 |
| 3 | `PRODUCT_REPOS` 缺省 `mdm` | **无缺省**，未配置即 job 失败 | 需求 04-2「仓库地址不写死在仓库文件」；且仓库名属产品标识，不应出现在平台仓 |
| 4 | `--cross-repo` 未写与 `--url` 冲突 | 互斥（退出码 2） | 跨仓档固定一次性临时库，避免误连部署库 |
| 5 | 未提 `validate_catalog` 需扩参数 | 增 `products` / `routes` 可选基准 | 平台行对账需排除「产品级路由映射」校验（路由属声明方，`diff_platform_declarations` 已逐方比对） |
| 6 | 未提「平台声明缺失守卫」 | 三档均加 | `payloads_of` 在平台清单缺失时返回空集，会让对账静默变空跑 |
| 7 | 未提 `--product-root` 支持「克隆容器目录」 | 支持（逐子目录展开） | CI 传的是 `../product`（装各仓的容器），不是单个仓根 |
