# CI 跨仓契约校验详细设计

> 跨产品协同 · 04 护栏与 CI · 02 CI 跨仓契约校验 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [02 CI 跨仓契约校验](../04_护栏与CI_02_CI跨仓契约校验.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：让平台仓 CI 能拿到**产品仓的自持声明**，执行与本地同源的装载校验与契约定位校验；取不到即失败（不静默跳过），使「能力声明 ↔ 对端契约」的漂移在合并前暴露。

**范围内**：

1. 校验内容（装载 + 能力/错误码段 + 契约定位 + 产品键对账）；
2. 校验脚本的参数形态（CI 与本地等价）；
3. CI 作业、变量、失败语义与跳过开关；
4. 缓存与开销控制。

**范围外**：装载与校验的实现（`02_01` / `02_05`）、字面量护栏（`04_01`）、产品仓自身的 CI（各产品仓自持）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| CI 结构 | `.gitlab-ci.yml` 分 `prepare / lint / test / trigger / build / verify`；`base-integrity` 作业（stage: lint）串行执行十余个护栏脚本 |
| 跨仓能力 | **已有先例**：`base-integrity` 通过 `ENGKIT_REPO_URL`（缺省拼 `CI_JOB_TOKEN` + `CI_SERVER_HOST`）克隆 engkit 并 checkout 固定 SHA |
| 产品仓清单 | 仅本地工作区通过 `config.dev.toml` 指向 `../../mdm/deploy/registry/*.json`；**CI 中拿不到**，故 `check_modules` 的能力段/契约定位校验在 CI 上等于没跑 |
| 后果 | 产品改名、路径变更、契约与声明不一致，CI 全绿而部署即断（本次 `org` → `mdm` 即如此） |

## 3. 设计 <a id="design"></a>

### 3.1 校验内容 <a id="checks"></a>

在 CI 中对**每个已声明产品仓**执行（复用 `02_01` / `02_05` 的同一套校验函数，不另写一套）：

| # | 校验 | 失败即红 |
| --- | --- | --- |
| 1 | 清单可解析（toml 合法、必填字段齐备、归属一致） | 是 |
| 2 | 能力记录完整（`kind` 与要素匹配、名称唯一） | 是 |
| 3 | 能力访问面在对端契约可定位（`paths` 归一化匹配） | 是 |
| 4 | 契约版本主版本一致（能力 / 错误码 vs 服务行） | 是 |
| 5 | 错误码段位与唯一性（含与平台码不撞） | 是 |
| 6 | 契约反向：契约声明的错误码已登记 | 是（未声明 `x-error-codes` 的端点只统计） |
| 7 | 产品键与平台产品档案一致（`sys_product` 视角） | 是 |
| 8 | 种子声明格式（模块路径与入口名形态） | 是（**不校验可调用性**——CI 不装产品依赖，可调用性由产品仓自测） |

### 3.2 脚本与参数（CI 与本地等价） <a id="script"></a>

新增薄包装脚本 `scripts/tools/base-check/check-product-catalog.py`，两种取源方式：

| 参数 | 语义 |
| --- | --- |
| `--local <path>` | 使用工作区内已克隆的产品仓（本地预检默认走这条） |
| `--repo-url <url> --rev <ref>` | 浅克隆到临时目录后校验（CI 走这条） |
| `--strict`（缺省开） | 取不到清单即失败 |
| `--allow-missing` | 显式跳过并输出警示（仅用于紧急放行，需在 CI 变量中显式开启） |

**输出**：逐产品一行结论；失败时定位到「能力名 / 错误码 / 契约路径」。

### 3.3 CI 作业与变量 <a id="job"></a>

新增独立作业（stage: lint，与 `base-integrity` 并行）：

```yaml
cross-repo-check:
  stage: lint
  image: $REGISTRY_IMAGE_PREFIX/ci-backend:py314
  variables:
    GIT_STRATEGY: fetch
  script:
    - python scripts/tools/base-check/check-product-catalog.py \
        --repo-url "${PRODUCT_REGISTRY_BASE_URL:-${CI_SERVER_PROTOCOL}://gitlab-ci-token:${CI_JOB_TOKEN}@${CI_SERVER_HOST}/bms}/mdm.git" \
        --rev "${PRODUCT_REGISTRY_REV:-main}"
```

| 变量 | 缺省 | 说明 |
| --- | --- | --- |
| `PRODUCT_REGISTRY_BASE_URL` | 由 `CI_SERVER_*` 与 `CI_JOB_TOKEN` 拼出 | 产品仓基址（多仓时按仓名拼） |
| `PRODUCT_REGISTRY_REV` | `main` | 产品仓分支 / 标签（**固定到稳定分支**，不跟随临时分支） |
| `PRODUCT_REGISTRY_ALLOW_MISSING` | 未设置 | 置 `1` 时以 `--allow-missing` 运行并输出警示（仅紧急场景） |

**为什么独立作业而非塞进 `base-integrity`**：失败原因不同（网络 / 外部仓状态 vs 本仓静态问题），独立作业便于定位、重试与单独放行；并行执行不延长流水线总时长。

**多产品接入**：`PRODUCT_REGISTRY_REPOS`（逗号分隔仓名）驱动循环；未声明时只校验 `mdm`（当前唯一产品仓）。

### 3.4 失败语义 <a id="failure"></a>

| 情形 | 行为 |
| --- | --- |
| 克隆失败（网络 / 权限 / 仓不存在） | **作业失败**，输出明确原因；`ALLOW_MISSING=1` 时跳过并警示 |
| 清单缺失或不可解析 | 作业失败，输出路径与解析错误 |
| 任一校验不通过 | 作业失败，定位到能力名 / 错误码 / 契约路径 |
| 契约文件缺失 | 失败（与 `02_01` 一致）；显式 `--skip-contract` 才可跳过并警示 |

**禁止**：默认“拉不到就跳过”。这正是 `02_01` 里“CI 单仓拿不到清单”问题的根源。

### 3.5 缓存与开销 <a id="cost"></a>

| 手段 | 说明 |
| --- | --- |
| 浅克隆 | `--depth 1`，只取所需分支的 HEAD |
| 缓存目录 | GitLab `cache` 缓存产品仓临时目录，命中时 `git fetch` 增量 |
| 校验范围 | 只读清单与契约文件，不构建产品仓、不装其依赖 |
| 失败快照 | 失败时保留临时目录路径于日志，便于复现（不归档产物） |

### 3.6 与相邻任务的分工 <a id="boundary"></a>

| 任务 | 分工 |
| --- | --- |
| `02_01` / `02_05` | 提供**校验函数**（本任务只做“取源 + 调用 + 作业编排”） |
| `04_01` | 断言平台源码无产品字面量；本任务断言“声明与契约一致”——两条互补，都属 lint 阶段 |
| 本地预检 | 提供 `--local` 等价步骤，推送前可自查（`preflight --fast` 增加一步，工作区无产品仓时自动降级为“跳过并提示”，不阻断本地开发） |

## 4. 影响面 <a id="impact"></a>

| 类别 | 对象 | 变更 |
| --- | --- | --- |
| 新增 | `scripts/tools/base-check/check-product-catalog.py` | 薄包装（取源 + 调用校验） |
| 新增 | `.gitlab-ci.yml`：`cross-repo-check` 作业 | stage: lint，与基座完整性并行 |
| 修改 | `engkit.toml` 或预检脚本 | 本地预检增加一步（无产品仓时提示跳过，不阻断） |
| 修改 | CI 变量文档（部署发布规范 / 运行手册） | 新增三个变量与跳过开关的适用场景 |
| 不改 | `02_01` / `02_05` 的校验实现 | 本任务只调用 |
| 不改 | 产品仓 CI | 各产品仓自持（其清单校验在其仓内） |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | `--local` 指向合法产品仓 | 全部校验通过，退出码 0 |
| 2 | `--repo-url` 浅克隆成功 | 同上（CI 主路径） |
| 3 | 克隆失败（错误地址） | 退出码非零，原因明确 |
| 4 | 克隆失败 + `--allow-missing` | 退出码 0 + 警示输出 |
| 5 | 清单缺能力段 | 失败并指出缺失 |
| 6 | 能力访问面不在契约 | 失败并定位能力名与路径 |
| 7 | 契约版本主版本不一致 | 失败并给两侧版本 |
| 8 | 错误码段位越界 | 失败并给码与段 |
| 9 | 契约反向（契约列了未登记码） | 失败并给出未登记码 |
| 10 | 产品键与平台档案不一致 | 失败 |
| 11 | 契约文件缺失 | 失败；`--skip-contract` 时跳过并警示 |
| 12 | 本地预检（工作区无产品仓） | 提示跳过，不阻断（退出码 0） |
| 13 | 多仓循环 | 两仓均校验，任一失败即整体失败 |
| 14 | 缓存命中 | 第二次运行不重复全量克隆 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 平台流水线依赖产品仓可达性 | 固定稳定分支 + 浅克隆 + 缓存；失败原因明确；`ALLOW_MISSING` 仅人工显式开启并留痕 |
| 产品仓分支变动导致平台 CI 随机失败 | 固定 `PRODUCT_REGISTRY_REV` 到稳定分支；产品侧改动走其自身流水线 |
| `CI_JOB_TOKEN` 跨项目权限不足 | 需在产品仓授予平台项目 job token 读权限（运维配置，写入运行手册） |
| 校验函数与本地不一致 | 同一函数、同一脚本，仅取源方式不同 |
| 本地开发被打扰 | 本地预检在无产品仓时跳过并提示，不阻断 |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 是否在 MR 中自动评论“能力/契约变更摘要” | 流水线稳定后评估 |
| 2 | 产品仓侧是否也跑“对平台契约的定位校验”（双向） | 产品仓接入时评估 |
| 3 | 多产品仓时的并行拉取 | 仓数量增长后评估 |
| 4 | `ALLOW_MISSING` 的审批要求（是否必须 MR 说明理由） | 与《Git 协作规范》一并定 |
