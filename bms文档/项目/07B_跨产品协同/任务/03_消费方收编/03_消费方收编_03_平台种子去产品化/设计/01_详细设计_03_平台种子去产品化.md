## 1. 目标与边界 <a id="scope"></a>

**目标**：平台种子只播平台自身数据——移除其中的产品业务码与产品权限码，改由产品种子声明、`02_03` 的编排入口统一执行；同时把种子统计探针从**平台侧硬编码**改为**按种子声明派生**，使「平台源码不出现产品标识」在种子面同样成立。已部署库的存量数据不受影响（不删、不重建）。

**范围内**：

1. 平台种子中产品条目的移除（业务码、权限码）与相关口径注释的归一；
2. **全局动作码（动词）的归属与校验边界**（产品不得自造动词）；
3. 产品种子承担的内容与写入语义（**前置已交付**，本任务只做对账与回归）；
4. **种子统计探针改声明驱动**：删除平台侧 `mdm-admin-codes` 硬编码，值列按表结构自动派生；
5. 已部署库的补种顺序与存量处置；
6. 回归断言（动作码字典不减少、权限码总数对账、探针逐项统计）、护栏基线递减与运维口径同步。

**范围外**：种子编排机制本体（`02_03` 已交付，本任务只调整探针登记入口与时序）、清单字段定义（`02_01`）、mdm 菜单 / 表单种子（平台菜单不含产品菜单）、产品仓其它收编点（`03_01` / `03_02` 已交付）、`biz` / `cw` 接入登记（随其产品仓）。

## 3. 设计 <a id="design"></a>

### 3.1 移除范围 <a id="remove"></a>

| 位置 | 移除内容 |
| --- | --- |
| `BUSINESS_SEEDS` | 产品业务码条目（`mdm` 及其名称） |
| `PERMISSION_SEEDS` | 产品权限码 4 条（`mdm:query` / `create` / `update` / `delete`） |
| 模块 docstring / `PERMISSION_SEEDS` docstring | 以产品为例的口径说明改为「随产品接入登记，由产品种子声明、平台调度」的通用表述（不再出现具体产品标识） |

**不移除**：平台自身业务码与权限码、菜单 / 按钮 / 字段种子、`sys_action` 全域动词字典来源（见 §3.2）。

### 3.2 动作码（全局动词）的归属 <a id="action"></a>

动作码是**全局唯一的动词维度**（`query` / `create` / `update` / `delete` / `approve`…），不属于任何单一产品。归属与边界：

| 项 | 口径 |
| --- | --- |
| 维护方 | **平台统一维护**（`ACTION_SEEDS` 仍由平台权限码派生，产品不参与派生） |
| 产品权限码 | 只能使用**已登记的动词**；产品种子里出现未登记动词 → **报错**（mdm 种子已实现该校验，`ParamError`） |
| 新动词需求 | 产品需新增动词时，先向平台登记（随平台发版进入 `ACTION_SEEDS`），再在产品权限码中使用 |
| 回归要求 | 移除产品权限码后，**动作码字典不得减少**——实测 `query` / `create` / `update` / `delete` 仍被平台业务码使用（断言：字典集合与改造前相等，31 个动词不变） |

**为什么动词必须集中**：权限码是「业务码 × 动作码」的组合，动作码一旦分散定义，同一语义会出现 `delete` / `remove` / `del` 三种写法，菜单与权限配置无法统一渲染。

### 3.3 产品种子承担的内容（前置已交付，对账口径） <a id="product"></a>

产品种子入口（`02_03` 契约：`module` + `entry`，`async def entry(session, args) -> None`）负责：

| 内容 | 本任务对账结论 |
| --- | --- |
| 业务码 | **已交付**：`mdm` + 中文名，按 `code` 判存 |
| 权限码 | **已交付**：`mdm:query` / `create` / `update` / `delete`，按 `(business_id, action_id)` 判存；动作码须为已登记动词 |
| 期望行 | **已交付**：`expected_rows()` 覆盖业务码一条（动作码由平台先行播种，只读不写，故不列入） |

**写入语义**：按自然键幂等 upsert；已存在且异值 → 计入 `conflicts` 并报告（不覆盖，与 `02_03` 一致）。

**本任务不改产品仓种子实现**，只在回归中验证「平台种子 + 产品种子」两段执行后业务码与 4 条权限码齐备。

### 3.4 种子统计探针改声明驱动 <a id="probe"></a>

#### 3.4.1 数据契约 <a id="probe-contract"></a>

`[seeds.tables]` 语义按 `SeedRecord.tables` 的既有契约执行——**真实表名 → 自然键**（多列用逗号分隔）：

| 项 | 口径 |
| --- | --- |
| 键 | 真实表名（如 `sys_business`），须与 ORM 表名一致 |
| 值 | 自然键列（如 `code` / `business_id,action_id`） |
| 值列 | **不声明**，由探针按表结构自动派生：排除主键列、自然键列与系统列（`tenant_id` / `created_at` / `updated_at` / `deleted_at`） |
| 未声明 `tables` 的种子 | 不登记探针；报告按「无统计口径」出 `note`，`created` / `updated` / `skipped` 为 0（不阻断） |
| 表名不存在 | 该表跳过并在报告 `warnings` 记一条（不阻断；避免声明笔误把整批种子拦下） |

**为什么值列自动派生**：值列属表结构事实，写进声明会随表结构变更而过期；自然键才是种子的稳定契约。自动派生保证「同一表结构下判定口径唯一」，且新增列自动参与对比（种子只在插入时写值，跳过行不会误判为「更新」）。

#### 3.4.2 注册入口与时序 <a id="probe-register"></a>

| 项 | 处置 |
| --- | --- |
| 入口 | `register_seed_probes(participant, records)`：按**本次编排实际装载的种子记录**构造探针（不再读静态表） |
| 时机 | 由 `SeedOrchestrationService.orchestrate()` 在 `_load_records()` **之后**调用——消除「登记时产品种子尚不可见」的时序隐患 |
| 平台侧薄入口 | `register_seed_stats(participant, records)` 继续作为平台服务的暴露入口，转调基座实现（与既有分工一致） |
| 静态表 | 删除 `_PROBE_TABLES` 与 `_TableSpec.value_columns` 的手工维护职责（保留派生逻辑） |

### 3.5 已部署库的补种与顺序 <a id="existing"></a>

| 场景 | 处置 |
| --- | --- |
| 存量库（已有产品业务码与权限码） | 平台种子不再写它们，但**不删除**；数据保持可用（清理会破坏既有授权，见 §8） |
| 新装库 | 执行编排入口（平台种子 + 产品种子），产品数据由产品种子写入 |
| 执行顺序 | **平台种子先、产品种子后**（编排器按登记顺序与 `after` 保证）；顺序反了也能收敛（双方均幂等），但平台侧不保证产品权限码存在 |
| 双写窗口（当前状态） | 平台种子与产品种子写同一批行、值相同；移除平台侧后**只产品侧写**，冲突预检口径不变（异值即报错） |
| 漏跑产品种子 | 表现为「产品权限码缺失 → 产品管理面全拒」，由编排报告逐项可见（不再靠人工发现） |
| 冲突 | 存量值与产品种子期望值不一致（如名称被改过）→ 报告冲突，人工处置 |

### 3.6 回归断言 <a id="regression"></a>

| 断言 | 目的 |
| --- | --- |
| 动作码字典集合与改造前一致（31 个动词） | 移除产品权限码不得导致动词消失 |
| 平台权限码数量 = 改造前 110 − 4，业务码 = 44 − 1 | 证明只移除了产品条目，未误删平台条目 |
| 产品种子执行后，产品业务码与权限码齐备 | 证明去产品化未造成功能缺失 |
| 平台种子执行后，库中不含新增的产品条目 | 证明越界已消除 |
| 探针按声明登记（10 项）且逐项 `created` / `skipped` 可读 | 证明探针改声明驱动未削弱逐项报告 |
| 未声明 `tables` 的种子不登记探针且报告有 `note` | 防止静默失效 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 移除后未跑产品种子 → 产品管理面全拒 | 编排入口统一执行 + 报告逐项可见；运维文档明确「平台 + 产品」两段 |
| 动作码被误删（若某动词仅产品使用） | 回归断言「字典集合不变」；出现仅产品使用的动词时，该动词须先由平台登记 |
| 存量库数据与产品种子不一致 | 冲突报告 + 人工处置，不自动覆盖 |
| 平台种子与产品种子都写同一业务码 | 唯一键冲突被幂等 / 冲突逻辑捕获；命名约定上避免重叠（产品业务码 = 产品键） |
| 值列自动派生引入误判 | 排除主键 / 自然键 / 系统列；种子只在插入时写值，「跳过」行不会产生差异；差异判定仍按「自然键命中 + 值变化」 |
| 声明表名笔误导致统计静默失效 | 未知表名记 `warnings` 且不阻断；§8 开放项登记「装载期表名存在性校验」 |
