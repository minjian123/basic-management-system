# 平台种子去产品化详细设计

> 跨产品协同 · 03 消费方收编 · 03 平台种子去产品化 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [03 平台种子去产品化](../03_消费方收编_03_平台种子去产品化.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：平台种子只播平台自身数据——移除其中的产品业务码与产品权限码，改由产品种子声明、`02_03` 的编排入口统一执行；已部署库的存量数据不受影响（不删、不重建）。

**范围内**：

1. 平台种子中产品条目的移除（业务码、权限码）；
2. **全局动作码（动词）的归属与校验边界**（产品不得自造动词）；
3. 产品种子承担的内容与写入语义（幂等 upsert）；
4. 已部署库的补种顺序与存量处置；
5. 回归断言（动作码字典不减少、权限码总数对账）。

**范围外**：种子编排机制（`02_03`）、清单中的种子声明字段（`02_01`）、菜单与表单种子（平台菜单不含产品菜单，产品菜单由产品前端模块注册）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 业务码种子 | `BUSINESS_SEEDS` 内直接列产品业务码（`mdm`“组织主数据（mdm 产品）”） |
| 权限码种子 | `PERMISSION_SEEDS` 内直接列产品权限码 4 条：`mdm:query` / `mdm:create` / `mdm:update` / `mdm:delete` |
| 动作码字典 | `ACTION_SEEDS` 由 `PERMISSION_SEEDS` **去重派生**（全局动词：`query` / `create` / `update` / `delete` 等） |
| 写入语义 | `seed_menu(url) -> (created, skipped, updated)`，逐条 `_exists` 判断后插入（幂等，但不覆盖异值） |
| 越界事实 | 平台种子代写产品业务码与权限码：新增产品或调整产品权限码都要改平台代码 |

## 3. 设计 <a id="design"></a>

### 3.1 移除范围 <a id="remove"></a>

| 位置 | 移除内容 |
| --- | --- |
| `BUSINESS_SEEDS` | 产品业务码条目（`mdm` 及其名称） |
| `PERMISSION_SEEDS` | 产品权限码 4 条（`mdm:query` / `create` / `update` / `delete`） |

**不移除**：平台自身业务码与权限码、菜单 / 按钮 / 字段种子、`sys_action` 全域动词字典来源（见 §3.2）。

### 3.2 动作码（全局动词）的归属 <a id="action"></a>

动作码是**全局唯一的动词维度**（`query` / `create` / `update` / `delete` / `approve`…），不属于任何单一产品。归属与边界：

| 项 | 口径 |
| --- | --- |
| 维护方 | **平台统一维护**（`ACTION_SEEDS` 仍由平台权限码派生，产品不参与派生） |
| 产品权限码 | 只能使用**已登记的动词**；产品种子里出现未登记动词 → **报错**（不允许产品自造动词，否则动词维度会碎片化） |
| 新动词需求 | 产品需新增动词时，先向平台登记（随平台发版进入 `ACTION_SEEDS`），再在产品权限码中使用 |
| 回归要求 | 移除产品权限码后，**动作码字典不得减少**——`query` / `create` / `update` / `delete` 仍被大量平台业务码使用（断言：字典集合与改造前相等） |

**为什么动词必须集中**：权限码是「业务码 × 动作码」的组合，动作码一旦分散定义，同一语义会出现 `delete` / `remove` / `del` 三种写法，菜单与权限配置无法统一渲染。

### 3.3 产品种子承担的内容 <a id="product"></a>

产品种子入口（`02_03` 契约：`module` + `entry`，`async def seed_xxx(ctx) -> SeedResult`）负责：

| 内容 | 说明 |
| --- | --- |
| 业务码 | 本产品业务码（如 `mdm`），含中英文名称 |
| 权限码 | 本产品管理面权限码（如 `mdm:query` / `create` / `update` / `delete`），动作码须为已登记动词 |
| 默认授权数据 | 如需要（与 `02_04` 的默认消费方一致，不在此重复登记） |

**写入语义**：按自然键（业务码 `code`、权限码 `(business, action)`）幂等 upsert；已存在且异值 → 计入 `conflicts` 并报告（不覆盖，与 `02_03` 一致）。

**校验**：权限码的动词不在 `sys_action` 中 → 报错并列出该动词，提示“需先在平台登记动词”。

### 3.4 已部署库的补种与顺序 <a id="existing"></a>

| 场景 | 处置 |
| --- | --- |
| 存量库（已有产品业务码与权限码） | 平台种子不再写它们，但**不删除**；数据保持可用 |
| 新装库 | 执行编排入口（平台种子 + 产品种子），产品数据由产品种子写入 |
| 执行顺序 | **平台种子先、产品种子后**（编排器按登记顺序保证）；顺序反了也能收敛（双方均幂等），但平台侧不保证产品权限码存在 |
| 漏跑产品种子 | 表现为“产品权限码缺失 → 产品管理面全拒”，由编排报告逐项可见（不再靠人工发现） |
| 冲突 | 存量值与产品种子期望值不一致（如名称被改过）→ 报告冲突，人工处置 |

### 3.5 回归断言 <a id="regression"></a>

| 断言 | 目的 |
| --- | --- |
| 动作码字典集合与改造前一致 | 移除产品权限码不得导致动词消失 |
| 平台权限码数量 = 改造前数量 − 4 | 证明只移除了产品条目，未误删平台条目 |
| 产品种子执行后，产品业务码与权限码齐备 | 证明去产品化未造成功能缺失 |
| 平台种子执行后，库中不含新增的产品条目 | 证明越界已消除 |

## 4. 影响面 <a id="impact"></a>

| 类别 | 对象 | 变更 |
| --- | --- | --- |
| 修改 | `ops/seed_menu.py` | 移除产品业务码与权限码条目；更新模块文档字符串中的口径说明 |
| 修改 | mdm 产品种子入口（随 `02_03` 契约） | 新增/对齐：写业务码 + 4 条权限码 |
| 修改 | `tests/ops/test_seed_menu.py` | 原断言含 `mdm` 条目，改为「平台种子不含产品条目」+「动作码字典不变」 |
| 修改 | 部署文档与补种说明 | 补种改为「平台种子 + 产品种子」，并注明存量库不删数据 |
| 不改 | `ACTION_SEEDS` 派生逻辑 | 仍由平台权限码派生 |
| 不改 | 菜单 / 按钮 / 字段种子 | 平台菜单不含产品菜单 |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 平台种子执行 | 库中无产品业务码与产品权限码新增 |
| 2 | 动作码字典 | 集合与改造前一致（`query` / `create` / `update` / `delete` 均在） |
| 3 | 平台权限码数量 | 恰为改造前 − 4 |
| 4 | 产品种子执行 | 产品业务码与 4 条权限码写入成功，名称正确 |
| 5 | 产品种子重复执行 | 幂等（`created=0`），无重复行 |
| 6 | 产品种子使用未登记动词 | 报错并列出动词 |
| 7 | 存量库补种 | 已有产品数据保持；平台种子不删除、不覆盖 |
| 8 | 冲突（既有名称被改） | 报告冲突，不覆盖 |
| 9 | 顺序反转（先产品后平台） | 最终状态一致（幂等收敛） |
| 10 | 编排报告 | 逐项可见产品种子状态；漏跑可被发现 |
| 11 | 既有平台权限码回归 | 平台管理面权限判定不受影响 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 移除后未跑产品种子 → 产品管理面全拒 | 编排入口统一执行 + 报告逐项可见；部署文档明确“平台 + 产品”两段 |
| 动作码被误删（若某动词仅产品使用） | 回归断言“字典集合不变”；出现仅产品使用的动词时，该动词须先由平台登记 |
| 存量库数据与产品种子不一致 | 冲突报告 + 人工处置，不自动覆盖 |
| 平台种子与产品种子都写同一业务码 | 唯一键冲突被幂等/冲突逻辑捕获；命名约定上避免重叠（产品业务码 = 产品键） |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 产品业务码是否允许与产品键不同名 | 当前约定同名；若出现多产品共用一个业务码的诉求再评估 |
| 2 | 存量库中“平台代写的产品权限码”是否清理 | 不清理（清理会破坏既有授权），仅停止代写 |
| 3 | 动词表是否开放给产品自助登记 | 暂不开放（集中维护是动词一致性的前提） |
