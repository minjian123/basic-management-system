# 前端目录消费详细设计

> 跨产品协同 · 03 消费方收编 · 02 前端目录消费 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [02 前端目录消费](../03_消费方收编_02_前端目录消费.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：前端的「产品键」与「产品命名空间」不再写死，改为消费平台目录快照（`GET /api/v1/modules/snapshot?with=collaborations`），使**新增产品零前端改动**；目录不可用时显式降级并提示，不静默拼错地址。

**范围内**：

1. 目录快照的前端消费（加载时机、缓存、失败语义）；
2. `PRODUCT_KEYS` 常量与 `isProductKey` 的运行时化；
3. 组织数据源默认端点的解析改造（`orgSourceEndpoint`）；
4. 页面端点常量（`ORG_PRODUCT_ENDPOINT`）的移除；
5. 降级形态与“新增产品零改动”夹具验证。

**范围外**：目录快照的后端实现（`02_02`）、授权与白名单（`02_04`）、组织选择组件本身的交互（组件设计节点）。

## 2. 现状 <a id="current"></a>

| # | 落点 | 现有写法 |
| --- | --- | --- |
| 1 | `packages/core/src/contracts/service-endpoint.ts` | `PRODUCT_KEYS = ['mdm'] as const`；`ProductKey` 为字面量联合类型；`isProductKey()` 查静态数组；`productPrefix(product, domain)` 先做静态校验再拼 `/api/{product}/v1/{domain}` |
| 2 | `packages/ui_ep/src/utils/orgSource.ts` | `orgSourceEndpoint()` 返回 `productPrefix('mdm', 'mdm')`（即 `/api/mdm/v1/mdm`） |
| 3 | `packages/core/src/capabilities/org-source.ts` | 选项 `endpoint?` 可覆盖默认端点（**天然注入点**，改造可复用） |
| 4 | `apps/desktop/src/api/endpoints.ts` | `ORG_PRODUCT_ENDPOINT = '/api/mdm/v1/mdm'` 常量直接传给组织数据源 |

**问题**：产品标识同时以「类型」「常量数组」「字面量字符串」三种形态存在于前端；产品改名或新增时必漏改（阶段七收口时组织选择与回显即因命名空间过期不可用）。

## 3. 设计 <a id="design"></a>

### 3.1 目录快照消费 <a id="catalog"></a>

| 项 | 口径 |
| --- | --- |
| 数据源 | `GET /api/v1/modules/snapshot?with=collaborations`，返回 `{ modules, products, collaborations }`（`02_02` 定义） |
| 加载时机 | 应用引导阶段（登录后、首屏路由进入前）调用一次；`ensureProductCatalog()` 幂等（并发调用共享同一 Promise） |
| 缓存 | 进程内缓存（页面刷新重取）；不落 localStorage（避免陈旧授权/目录） |
| 失败语义 | 首次失败**重试一次**；仍失败 → 置 `unavailable` 状态，依赖产品目录的能力进入降级（§3.5），并输出 `console.warn` 与上报 |
| 结构校验 | 缺失 `products` 或 `collaborations` 字段视为响应不合规 → 按失败处置（不静默用空数组） |

**数据模型（前端）**：

| 字段 | 用途 |
| --- | --- |
| `products[].product_key` | 产品键集合（替代 `PRODUCT_KEYS`） |
| `collaborations[].name` | 能力名（用于取址，如 `mdm.org.dept-data`） |
| `collaborations[].domain` | 业务域 |
| `collaborations[].frontend_prefix` | 命名空间域段（缺省时回退同域产品路由段） |
| `collaborations[].path` | 该能力在服务内的访问面（前端按外部命名空间等价组装，不直接使用内部路径） |

### 3.2 产品键与域段的运行时化 <a id="keys"></a>

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| `PRODUCT_KEYS` | `['mdm'] as const` | 删除常量；改为 `productKeys()`（读目录缓存，返回 `readonly string[]`） |
| `ProductKey` | 字面量联合类型 | `type ProductKey = string`（**类型放宽，校验移至运行时**） |
| `isProductKey()` | 查静态数组 | 查 `productKeys()`；目录未加载时返回 `false` |
| `productPrefix(product, domain)` | 静态校验后拼串 | 组装规则不变（`/api/{product}/v1/{domain}`），校验改为运行时（未登记即抛 `CAPABILITY_VIOLATION`） |

**为什么接受类型放宽**：产品键本身是运行期登记数据，编译期无法穷举。补偿手段：① 运行时校验保留（非法键仍抛错，不静默拼串）；② 提供 `assertProductKey()` 供关键路径断言；③ 夹具用例覆盖“新增产品无需改代码”。

### 3.3 组织数据源端点解析 <a id="org-endpoint"></a>

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| 默认端点 | `productPrefix('mdm', 'mdm')` | `resolveOrgSourceEndpoint()`：按能力 `mdm.org.dept-data` 的 `product_key` + `frontend_prefix` 组装 |
| 返回值 | `string` | `string \| null`（目录不可用或能力未登记时返回 `null`） |
| 注入点 | 选项 `endpoint?` 覆盖 | **保留**：显式 `endpoint` 优先（宿主与测试仍可固定地址） |
| 失败 | 拼出地址后 404 | 返回 `null` → 消费方进入降级（不发起请求） |

**兼容**：仍导出 `orgSourceEndpoint()` 作为**同步只读**入口（读缓存，未加载返回 `null`），调用方需先 `await ensureProductCatalog()`；测试可在不加载目录时显式传 `endpoint`，避免测试依赖网络。

### 3.4 页面端点常量移除 <a id="endpoints"></a>

`apps/desktop/src/api/endpoints.ts` 删除 `ORG_PRODUCT_ENDPOINT`，组织数据源选项改为：

```
endpoint: resolveOrgSourceEndpoint() ?? undefined   // undefined 时由组件走降级
```

同时清理该文件里指向具体产品命名空间的注释，改为指向能力名。

### 3.5 降级形态 <a id="degrade"></a>

| 情形 | 表现 |
| --- | --- |
| 目录不可用（加载失败） | 依赖产品目录的能力（组织选择 / 回显）**禁用**并在界面给出明确提示（“组织数据暂不可用，请稍后重试”），提供“重试”动作重新加载目录 |
| 能力未登记（清单缺失） | 同“不可用”，提示文案区分（“未接入组织主数据”） |
| 能力已登记但请求失败 | 组件原有错误提示（不新增静默降级） |

**禁止**：拼一个默认地址继续请求（会把“未接入”伪装成“404”）；用空数组冒充“无组织数据”。

### 3.6 零改动验证夹具 <a id="fixture"></a>

构造一份含**虚构产品**（如 `demo`）的快照响应，断言：

1. `productKeys()` 含 `demo`；
2. 以该产品的一项能力取址，组装出 `/api/demo/v1/{prefix}`；
3. 全程**未修改任何前端代码**（夹具只改快照数据）。

该用例是“新增产品零前端改动”这一门禁行的直接证据。

## 4. 影响面 <a id="impact"></a>

| 类别 | 对象 | 变更 |
| --- | --- | --- |
| 新增 | `packages/core/src/catalog/product-catalog.ts` | 快照加载、缓存、失败态、`productKeys()` / `resolveCapability()` |
| 修改 | `packages/core/src/contracts/service-endpoint.ts` | 删 `PRODUCT_KEYS` 常量；类型放宽；校验运行时化 |
| 修改 | `packages/ui_ep/src/utils/orgSource.ts` | `orgSourceEndpoint()` 改为读目录（返回 `string \| null`） |
| 修改 | `apps/desktop/src/api/endpoints.ts` | 删除常量，改用解析函数 |
| 修改 | 应用引导 | 登录后 `await ensureProductCatalog()` |
| 修改 | 既有测试 | 引用 `PRODUCT_KEYS` 常量的断言改为夹具驱动（`module-release.spec.ts` / `module-api.spec.ts` / `service-endpoint.spec.ts` 等） |
| 不改 | `productPrefix` 的组装规则、服务键（`SERVICE_KEYS`）体系 | 平台服务键仍为编译期常量（不在本次范围） |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 快照加载成功 | `productKeys()` 与快照一致；能力可取址 |
| 2 | 快照加载失败（首次） | 重试一次；仍失败则进入 `unavailable` |
| 3 | 并发加载 | 只发一次请求（共享 Promise） |
| 4 | 响应结构不合规（缺字段） | 按失败处置，不静默用空数组 |
| 5 | `productPrefix` 非法产品键 | 抛 `CAPABILITY_VIOLATION`（不拼串） |
| 6 | `productPrefix` 非法域段 | 同上 |
| 7 | 组织端点解析（正常） | 返回 `/api/{product}/v1/{prefix}`，与能力声明一致 |
| 8 | 组织端点解析（目录不可用） | 返回 `null`；组件禁用并提示 |
| 9 | 显式 `endpoint` 覆盖 | 优先使用显式值（测试与宿主场景） |
| 10 | 零改动夹具（虚构产品） | 不改代码即可取址（门禁证据） |
| 11 | 既有断言改造 | 原引用 `PRODUCT_KEYS` 的用例改夹具后全绿 |
| 12 | 类型检查 | 受影响包 `typecheck` 通过（类型放宽不引发逃逸错误） |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 类型放宽后“产品键拼错”不再在编译期暴露 | 运行时校验保留 + `assertProductKey()` + 夹具用例；评审关注新增的裸字符串拼接 |
| 引导阶段多一次请求 | 单次请求、幂等缓存；失败不阻塞首屏（仅相关能力降级） |
| 测试依赖目录加载 | 测试显式传 `endpoint` 或注入快照夹具，不依赖真实网络 |
| 与后端快照契约漂移 | 快照结构由 `02_02` 定，前端做**结构校验**，缺字段即失败 |
| 旧缓存导致的权限陈旧 | 不落持久化缓存，刷新即取最新 |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 平台服务键（`SERVICE_KEYS`）是否同样运行时化 | 当前为编译期常量且与后端服务目录同源，暂不改；服务数量增长后评估 |
| 2 | 目录快照按消费方裁剪（前端只看得到自己可用的能力） | `02_04` 分配落地后评估 |
| 3 | 目录变更的前端热更新（无需刷新） | 出现“新增产品要求不重启前端”诉求时评估 |
| 4 | 多语言提示文案的 key 化 | 随国际化接入统一处理 |
