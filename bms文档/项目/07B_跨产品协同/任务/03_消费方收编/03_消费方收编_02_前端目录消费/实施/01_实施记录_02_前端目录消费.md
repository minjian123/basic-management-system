## 2. 实施概览 <a id="overview"></a>

```mermaid
flowchart LR
    A["环境准备<br/>前端依赖重装 / 纠错链"] --> B["后端契约补充<br/>kind 字段 + snapshot_version 2"]
    B --> C["契约与生成类型<br/>contract_snapshot / api_types"]
    C --> D["core 端口层<br/>catalog/lookup + target + 寻址运行时化"]
    D --> E["ui_ep 组织源<br/>目录取址 + 降级文案"]
    E --> F["宿主适配<br/>api/catalog + guard 钩子 + 令牌复位"]
    F --> G["注释归一与基线递减<br/>149 → 95（消耗 54）"]
    G --> H["门禁与记录<br/>前端三包 + 后端全量 + 预检"]
```

结果小结：前端产品键 / 服务键全部改为运行期取自目录快照，组织数据源端点按「业务域 + 能力种类」推导；目录四类不可用均显式降级；后端能力段补 `kind` 并把带参快照版本升到 `2`；前端产品字面量基线由 **149 条降至 95 条**（本任务消耗 **54 条**，前端清零）。

## 3. 实施过程 <a id="process"></a>

### 3.1 环境准备 <a id="p1"></a>

| 动作 | 结果 |
| --- | --- |
| `python scripts/tools/deps/重装依赖.py --frontend-only` | 前端依赖装好（pnpm install --frozen-lockfile） |
| 发现 `packages/ui_ep/node_modules/*` 指向 **mdm 工作区 store**（element-plus 2.14.7），与桌面端（2.14.6）形成双实例，desktop 用例 50 例因 Element Plus provide/inject 失败 | 清理 `node_modules` 后重装，统一到本仓 store（desktop 全绿） |
| `pnpm run api_types:gen` | 首次因外置链接失效报 `openapi-typescript` 找不到；`还原依赖` 后生成成功（`platform.ts` +135 行） |
| 收尾 | `外置依赖 --frontend-only` 恢复外置态（`node_modules` 为 junction） |

### 3.2 后端契约补充 <a id="p2"></a>

| 落点 | 变更 |
| --- | --- |
| `bms_core/schemas/module.py` | `CollaborationSnapshotItem` 增 `kind: str`（`read` / `dataset` / `txn-branch`） |
| `platform_registry/api/modules.py` | 能力段下发 `kind`；`CATALOG_SNAPSHOT_VERSION` `"1"` → `"2"`；端点响应注解补两分支联合（数组形态 / 带参对象形态） |
| `deploy/contracts/platform.json` 与 `baseline/platform.json` | `ops.contract_snapshot export` 重生成；`ops.contract_gate baseline-update --service platform`（响应补类型属评审放行，基线同步） |
| `frontend/packages/api_types/src/platform.ts` | 由新契约重生成（含 `CatalogSnapshotResponse` / 产品段 / 能力段） |
| 用例 | `test_modules_snapshot.py` 断言 `kind` 与 `snapshot_version == "2"` |

> 契约导出在 Windows 下写出 CRLF，按仓库行尾口径用 `engkit eol --fix` 纠正为 LF。

### 3.3 core 端口层与寻址运行时化 <a id="p3"></a>

| 落点 | 变更 |
| --- | --- |
| `catalog/lookup.ts`（新增） | 目录端口：四态、产品 / 服务 / 能力投影、`productKeys()` / `derivedServiceKeys()`、`resolveCapabilityTarget(domain, kind)`（唯一目标，否则 `capability-missing` / `ambiguous`） |
| `catalog/target.ts`（新增） | 取址出口：组装 `/api/{产品键}/v1/{域段}`（复用寻址契约单一拼装来源） |
| `contracts/service-endpoint.ts` | 删 `PRODUCT_KEYS`；`ProductKey` / `ServiceKey` 放宽为 `string`；标识形态 `IDENTIFIER_PATTERN`；未加载按形态放行、加载后按目录判定；`SERVICE_KEYS` 保留为编译期基线与对账基准 |
| `index.ts` | 导出目录端口与取址；停止导出 `PRODUCT_KEYS` |

### 3.4 ui_ep 组织源与降级文案 <a id="p4"></a>

| 落点 | 变更 |
| --- | --- |
| `utils/orgSource.ts` | `orgSourceEndpoint()` 改为按 `ORG_SOURCE_DOMAIN('org')` + `ORG_SOURCE_CAPABILITY_KIND('dataset')` 从目录推导，返回 `string \| null`；`null` 时**不发请求**并只告警一次；查询参数抽 `appendOrgSearchParams()`（空值过滤可测）；降级文案三档常量 |
| `index.ts` | 导出新常量与 `appendOrgSearchParams` |

### 3.5 宿主适配与引导 <a id="p5"></a>

| 落点 | 变更 |
| --- | --- |
| `api/catalog.ts`（新增） | 请求 `?with=modules,products,collaborations`；**生成类型**结构校验；四类不可用；**仅请求失败重试一次**；并发共享 Promise；映射进 core 端口；复位递增代次（在途结果丢弃） |
| `api/endpoints.ts` | 删 `ORG_PRODUCT_ENDPOINT`；`orgSourceOptions()` 端点取目录解析结果（不可用则不给端点）；`SourceEndpointOptions.endpoint` 改可选 |
| `router/guard.ts` | `AuthGuardDeps` 新增可选 `ensureCatalog`，会话就绪后、动态路由前调用；抛错不阻断并记 `catalog-failed`；守卫关闭时也触发一次 |
| `main.ts` | 注入 `ensureCatalog`；令牌变化分支先 `resetProductCatalog()` |
| `dev/OrgCheck.vue` | 自检第 13 项改为「虚构产品目录推导 + 复位后降级」 |

## 4. 问题与处置 <a id="issues"></a>

| # | 问题 | 原因 | 处置 |
| --- | --- | --- | --- |
| 1 | desktop 50 例 `Element Plus ElTabPane` 注入失败 | 依赖还原后 `ui_ep` 依赖链指向 mdm 工作区 store（element-plus 2.14.7），与桌面端 2.14.6 双实例 | 清理 `node_modules` 重装，统一 store；结论记入本记录 |
| 2 | 端点响应在公开契约里是**无类型** `ApiResponse`，无法生成前端类型 | 端点原注解为 `ApiResponse` | 注解改两分支联合；按评审放行口径 `baseline-update --service platform`（设计 §3.5 / §9 已回写） |
| 3 | core 零依赖、未依赖 `@bms/api_types` | 基座包不依赖服务契约生成物 | 改为**端口落 core、适配落宿主**（设计 §3.2 / §3.5 / §9-13） |
| 4 | `check_bare_collections` 拦截响应注解里的 `list[...]` | 裸集合护栏要求 `ConcurrentStable*`，但 Pydantic 不支持该泛型作响应注解 | 保留 `list`（OpenAPI 数组形态必需），按规则加行内豁免标记并在设计说明 |
| 5 | `test_m7_closure::test_mdm_alignment_lockdown` 断言旧硬编码 | 该断言锁定阶段七的 mdm 直写口径，已被本任务取代 | 改为锁定新口径（不得回退 `PRODUCT_KEYS` / 产品命名空间常量） |
| 6 | `domain/org.ts` 存量覆盖缺口（96.8%）会拖红「变更文件 100%」 | 该文件历史缺口与本次无关 | 降级文案常量改落 `ui_ep/utils/orgSource.ts`（该文件 100%），设计同步回写 |
| 7 | 产品字面量规则扫到 `frontend/modules/*/node_modules` | 依赖外置后链接被顺扫 | `exclude_globs` 增 `**/node_modules/**` |
| 8 | 契约导出文件为 CRLF | Windows 下文本写出 | `engkit eol --fix` 纠正为 LF |
