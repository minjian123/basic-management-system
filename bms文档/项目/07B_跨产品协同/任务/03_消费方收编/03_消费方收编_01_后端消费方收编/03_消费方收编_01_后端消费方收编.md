## 2. 任务内容 <a id="content"></a>

1. **权限解析器**：只读出口的服务标识与路径改按能力名取用。
2. **用户保存编排**：内部写通道路径、分支动作名、分支参与者标识改按能力名取用；强一致路径沿用既有事务口径（TM + XA 与顺序提交两条路径）。
3. **角色保存编排**：同构改造（角色-岗位 / 角色-部门）。
4. **平台内部端点白名单**：三处入站白名单（用户只读出口 / 权限失效 / 系统参数内部读）由能力声明的消费方登记推导，不再逐个写服务标识。
5. **基座「恒开通模块」清单**：产品模块的「恒开通」属性随模块登记声明，基座常量不写产品标识。
6. **行为等价**：权限计算结果、分配写入结果与拒绝语义与收编前一致。

## 3. 完成标准 <a id="accept"></a>

上述落点不再出现产品标识与对端路径字面量（护栏通过）；既有后端用例全绿；新增「改声明中的路径 / 动作名 → 消费方行为随之变化」用例；写路径失败为 fail-closed；定向覆盖率达标（行 + 分支）。
