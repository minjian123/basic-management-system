# 产品错误码自持与装载详细设计

> 跨产品协同 · 02 协同基座 · 05 产品错误码自持与装载 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [05 产品错误码自持与装载](../02_协同基座_05_产品错误码自持与装载.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：把错误码从「段自持、码只在产品代码里」改为「段与码同一份自持声明」，平台装载后与自身错误码合并成单一 `码 → 定义` 视图，用于统一渲染、撞码与越段检测、契约反向对账与手册导出。

**范围内**：

1. 错误码段（第七类记录）的字段与清单结构；
2. 记录模型、合并视图（平台枚举 + 产品声明）与冲突拒绝；
3. 三类校验：段位归属、全局唯一、契约反向；
4. 渲染路径改造（最小侵入：异常未显式给状态与文案时由视图补全）；
5. 手册导出与登记清单回写。

**范围外**：产品侧异常类改造（各产品自行把声明与异常对齐，属 `03_01` 类收编工作）、文案翻译本体（产品语言包）、平台 `ErrorCode` 枚举迁移（拍板：不迁）。

## 2. 现状 <a id="current"></a>

| 项 | 现状事实 |
| --- | --- |
| 段位 | 服务行 `errcode_segment` 已自持（平台各服务 `01` ~ `04`、产品 `mdm` = `33`），`ModuleRegistry.validate()` 已校验段位格式与**段唯一** |
| 具体码 | 平台在 `bms_core/core/error_codes.py` 的 `ErrorCode` 枚举（5 位，万位为段）；产品在各自仓代码（mdm 形如 `330051`，6 位 = 2 位段 + 4 位序号） |
| 渲染 | 异常对象 `BaseError(code, message, http_status)` 自带状态与文案；`api/errors.py::register_exception_handlers` 直接输出——平台**不查表**，因此对产品码无认知 |
| 校验 | 无「码不得落平台区」的机器校验；无跨产品撞码检测；无契约与码定义的双向对账 |
| 边界 | 规范已写「业务模块扩展段由产品仓库各自定义，不得占用平台段」——**文档有约束、机器无校验** |

## 3. 目标设计 <a id="design"></a>

### 3.1 清单段与字段 <a id="format"></a>

```toml
[[errcodes]]
code = 330051
domain = "org"
http_status = 404
message_key = "mdm.error.dept_not_found"
severity = "warning"
description = "部门不存在"
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `code` | 是 | 整数；产品码为 6 位（前两位 = 本产品声明段）；平台码为 5 位（1~9 万位） |
| `domain` | 是 | 归属业务域（须在业务域清单登记） |
| `http_status` | 是 | 传输层状态（404 / 401 / 403 / 409 / 500 等）；业务失败统一 200 的既有口径不变 |
| `message_key` | 是 | 文案键（产品语言包内解析） |
| `severity` | 是 | `info` / `warning` / `error`；用于日志级别与告警分级 |
| `description` | 是 | 默认中文描述（文案缺失时兜底，同时供手册导出） |
| `status` | 否 | `enabled` / `disabled`，缺省 `enabled` |

**约束**：`code` 不允许重复声明（含同一清单内）；`message_key` 命名遵循 `<product>.error.<snake_case>`。

### 3.2 记录模型与合并视图 <a id="view"></a>

**记录**：`ErrorCodeRecord`（`@dataclass(frozen=True)`，继承既有登记记录契约），唯一键 `code`。

**注册与视图**（与能力 / 种子同族）：

| 函数 | 语义 |
| --- | --- |
| `register_error_code_records(records)` | 装载产品错误码；同 `code` 同值合并、异值即拒（`CatalogError`） |
| `error_code_view()` | **合并视图**：平台 `ErrorCode` 枚举在前 + 已装载产品码在后，返回 `code → ErrorCodeRecord` |
| `reset_error_code_records()` | 测试隔离用 |

**平台码适配**：平台枚举无 `message_key` 与 `severity`，视图转换时取 `enum.name` 生成稳定 key（如 `platform.error.param`），`severity` 统一 `error`、`http_status` 取枚举对应异常类的既有值（以异常类为唯一事实源，不重复声明）。

**视图不变式**：`code` 全局唯一；任一 `code` 在视图中**有且仅有一条**定义；视图构建后只读。

### 3.3 三类校验 <a id="validate"></a>

| # | 校验 | 判定 | 失败处置 |
| --- | --- | --- | --- |
| 1 | 段位归属 | `str(code)` 前两位 == 本清单 `services[].errcode_segment`；且码长与该段位形态一致（产品 6 位） | `CatalogError`，信息含 `code` 与段 |
| 2 | 平台码区禁入 | 码落在平台区（5 位且首位 1~9）即为越界；产品不得声明 5 位码 | 同上 |
| 3 | 全局唯一 | 与平台 `ErrorCode` 值不撞；跨产品清单同 `code` 不同值即拒 | 同上 |
| 4 | 契约反向 | 契约中以 `x-error-codes` 扩展（数组）声明该端点可能返回的码：① 契约列出的码必须已登记；② 已登记且 `status=enabled` 的码若在某端点契约中列出，须与登记的定义一致（`http_status` 相同） | 装载 / 校验期报错；契约未声明扩展的端点计入「未声明错误码的端点」报告（**软提示**，不阻断） |
| 5 | 文案键格式 | `message_key` 满足 `<product>.error.<snake>` | 报错 |

**契约缺扩展的处置**：现阶段多数端点未声明 `x-error-codes`，因此第 4 条分两档——**已声明即强校验**（码必须登记、定义须一致），**未声明只统计**。待各产品补齐扩展后转为全量强校验（登记于开放项）。

### 3.4 统一渲染路径 <a id="render"></a>

**最小侵入改造**（不推翻既有 `BaseError(code, message, http_status)` 结构）：

| 环节 | 改造 |
| --- | --- |
| 异常构造 | 若异常未显式传 `http_status` / `message`，从 `error_code_view()` 取定义补全（显式传值优先，保持既有代码零改动） |
| 全局处理器 | 输出响应前查视图：命中且请求带语言偏好 → 用 `message_key` 解析文案；缺失文案 → 回退 `description` 并记 `WARNING`（`code` / `message_key` / `locale`） |
| 未登记码 | 运行期兜底为 `10000` + `500`，并记 `ERROR`（属防御路径；产品码在装载期已被校验，正常不出现） |
| 观测 | 指标 `error_code_unresolved_total{code}`（文案缺失）、`error_code_unknown_total{code}`（未登记码） |

**为什么不在异常里直接查表**：异常构造点在业务深处，查表会引入视图依赖与启动顺序问题；把补全放在处理器（单点）更安全，且天然覆盖所有抛出点。

### 3.5 手册导出 <a id="export"></a>

`ops.export_errcodes --format md|json`：按 `error_code_view()` 输出错误码表（`code` / 段 / 业务域 / `http_status` / `message_key` / `severity` / `description` / 提供方）。

**校验**：导出结果与视图逐项一致（用例断言）；导出文件不落库、不参与运行时。

### 3.6 与能力 `codes` 的边界 <a id="boundary"></a>

| 概念 | 含义 | 段 / 命名空间 |
| --- | --- | --- |
| 能力 `kind = "codes"` 的 `permission_codes` | **业务码 / 权限码**（如 `mdm:query`） | 权限体系，与错误码无关 |
| 错误码（本任务） | **失败语义**（如 `330051`） | 错误码段（服务行 `errcode_segment`） |

两者不共用段、不共用命名空间，也不互相引用；能力声明里的 `permission_codes` 不得填入错误码（装载期可加白名单格式校验兜底）。

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 合法错误码装载 | 视图含该码，字段与声明一致 |
| 2 | 段位不符（码前两位 ≠ 声明段） | 报错，信息含码与段 |
| 3 | 平台码区越界（产品声明 5 位码） | 报错 |
| 4 | 跨产品撞码（同码异义） | 报错，信息含两侧提供方 |
| 5 | 与平台 `ErrorCode` 撞码 | 报错 |
| 6 | 合并视图完整性 | 平台码 + 产品码齐备；每码仅一条；平台码 `message_key` 由枚举名生成 |
| 7 | 异常未给状态与文案 | 由视图补全，响应状态与文案键符合声明 |
| 8 | 异常显式给值 | 以显式值为准（既有行为不变） |
| 9 | 文案缺失回退 | 回退 `description` 并产出 `WARNING` + `error_code_unresolved_total` +1 |
| 10 | 未登记码运行期兜底 | 返回 `10000` + 500 并产出 `ERROR` + `error_code_unknown_total` +1 |
| 11 | 契约反向：契约列了未登记的码 | 报错 |
| 12 | 契约反向：未声明 `x-error-codes` 的端点 | 计入报告，不阻断（软提示） |
| 13 | 手册导出 | 与视图逐项一致（`md` 与 `json` 两种格式） |
| 14 | 能力 `permission_codes` 误填错误码 | 格式校验拦截 |
| 15 | 既有平台错误码行为回归 | 全部平台异常的状态与文案与改造前一致 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 产品码与代码实际抛出不一致（声明了但没用、用了但没声明） | 契约反向校验 + 手册导出对照；后续可加「代码中出现的码必须已登记」护栏（见开放项） |
| 文案键大面积缺失导致回退 | 回退有日志与指标，长期高位视为文案欠账；不做静默兜底 |
| 视图与 `ErrorCode` 枚举双源 | 枚举是平台码唯一事实源，视图只是适配展示；不反向写回枚举 |
| 契约 `x-error-codes` 覆盖不全 | 分两档校验（已声明强校验、未声明统计），避免一上线就全红 |
| 产品码段调整 | 段随服务行登记，调整即触发码段位校验失败，属预期（段一经发布稳定不变） |
