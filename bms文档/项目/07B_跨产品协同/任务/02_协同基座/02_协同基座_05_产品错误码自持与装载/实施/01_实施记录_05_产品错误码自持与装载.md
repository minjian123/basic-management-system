## 2. 决策确认 <a id="decisions"></a>

实施前分五批共 **23 项**逐项确认（结论已回写设计 §8 对齐记录），要点：

| 组 | 事项（结论） |
| --- | --- |
| 落点与跨仓范围 | 记录 / 视图并入 `services/module_registry.py`；校验并入 `inspect_product_manifests()`；导出新增 `ops/export_errcodes.py`；mdm 三件同批（清单段 + 自身装载 + 对账用例） |
| 渲染与文案 | 未登记码保留异常自值 + 观测（不兜底 10000/500）；文案分档（真实 translator 才解析）；`message_key` 产品语义键 / 平台 `error.{code}`；公共渲染单点 |
| 校验口径 | 契约反向两档；`x-error-codes` 为整数数组；`domain` 只做形态校验；同码同值合并放行 |
| 字段与观测 | 注入 `product_key` / `segment`；`severity` 不驱动日志；两条 `bms_` 指标；mdm 对账用例 |
| 收尾 | 平台码形态只在用例断言；导出 `export` / `check` 双命令；视图不下发快照；Kiwi 编号归 `05_01` |

补充三项（实施期发现、先问后做）：平台码 `http_status` 用显式映射表（只列非 200）+ 用例对齐；有 `errcodes` 缺 `errcode_segment` 即拒启；`status = disabled` 仍参与渲染、导出标注「码位保留不复用」。
