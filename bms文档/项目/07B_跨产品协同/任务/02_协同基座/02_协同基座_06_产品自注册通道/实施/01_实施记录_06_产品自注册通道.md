## 2. 决策确认 <a id="decisions"></a>

实施前分四批共 **15 项**逐项确认（结论已回写设计 §3 ~ §9 与《跨产品协同登记清单》），要点：

| 组 | 事项（结论） |
| --- | --- |
| 表结构 | 一类一表新建 6 张（`sys_product_route` / `sys_data_source` / `sys_collaboration` / `sys_collaboration_usage` / `sys_seed` / `sys_errcode`），与 `sys_module` / `sys_product` 同风格 |
| 注册协议 | 单次全量上报（`PUT /api/v1/platform/internal/declarations`，携清单文本）；服务端按「本产品维度整体对账」：新增插入、未声明置退役、其余比对 |
| 声明演进 | 覆盖 + 留痕（同键同值不写、内容变化更新并记结构化日志）；跨产品撞键才拒 |
| 写入口 | 注册取代种子写库（`sys_module` / `sys_product` 由注册写入）；平台自身也走注册（读本仓 `platform.toml` + `SERVICE_CATALOG`） |
| 落库范围 | 八类全落（产品档案 / 服务行 / 产品路由 / 数据源 / 能力 / 种子 / 错误码 / 使用声明）；清单降为**注册输入** |
| 作用域 | 对账按**声明方**作用域：共享表里别的产品的行不退役、不覆盖；平台行（`product_key` 为空）归 `platform` |
| 视图投影 | 落库后按**注册表快照整体重建**进程内视图（先复位再登记），声明演进与退役如实反映；常量承载的行（`PRODUCT_CATALOG` / `SERVICE_CATALOG`）不重复登记 |
| 启动语义 | 平台：启动钩子注册自身声明（失败拒启，库不可用降级放行）；产品：启动上报 → 拉全量快照 → 投影；**无清单即告警跳过**（脚手架空服务不被拒启） |
| 开关 | `[registry].register_on_startup`（生产 true；`config.test.toml` 置 false，用例显式调端点） |

## 4. 实施期修正（用例暴露的真实缺陷） <a id="fixes"></a>

| # | 缺陷 | 影响 | 修正 |
| --- | --- | --- | --- |
| 1 | `load_snapshot()` 未填 `owners` | 声明方作用域失效：退役判定、跨产品撞键、owner 查询全部静默不生效 | 补 `owners` 与 `_owner_of_row()`（共享表 `product_key` 为空归 `platform`） |
| 2 | 退役写库后回读崩（`CollaborationStatus("retired")` 非法） | 任何退役都会让后续读取失败的连锁故障 | `_status_of()`：命中枚举走枚举、否则原样保留 |
| 3 | 平台自注册把 `SERVICE_CATALOG` 的产品模块行一起声明 | 与产品注册跨产品撞键，平台起不来 | 只并入 `product_key` 为空的平台自身服务行 |
| 4 | 库内 JSON 字段损坏时静默返回空集合 | 视图与库不一致却无人知晓；且触发「吞异常」护栏 | 改为抛 `CatalogError`（违例即暴露） |
| 5 | 常量承载的行（产品档案 / 服务行 / 平台种子）被投影重复登记 | 目录视图出现重复项（产品列表 `total` 翻倍） | 投影排除常量行 |
| 6 | 无清单服务（脚手架空服务）被拒启 | 新建服务无法启动 | 区分「没声明」（告警跳过）与「声明坏了」（拒启） |
| 7 | `release.py cmd_seed` 把 `_compose_run` 的返回值（`None`）当退出码用（收尾批代码审查发现，非本任务引入） | 种子编排的冲突（1）/ 执行失败（2）/ 前置错误（3）**全部被吞**：恒打印「编排未通过」而实际退出码为 0，部署流水线据此误判成功 | `_compose_run` 改为返回容器退出码（抽出 `_compose_proc`，新增 `raise_on_error` 关闭「非零即抛」），`cmd_seed` 以 `raise_on_error=False` 取真实业务码并原样透出；用例 `test_cmd_seed_propagates_business_exit_code` 守住 |
