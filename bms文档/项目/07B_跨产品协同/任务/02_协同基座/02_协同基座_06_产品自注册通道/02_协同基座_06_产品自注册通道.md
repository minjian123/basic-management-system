## 2. 任务内容 <a id="content"></a>

1. **注册上报**：产品服务启动时把自身四类声明（服务行 / 产品档案 / 能力 / 消费方使用声明）上报平台；平台幂等合并落库（同键同值幂等、异值拒收并回报差异）。
2. **落库与恢复**：能力声明与使用声明落 `sys_collaboration`（一表两类，键与来源分列）；服务行 / 产品档案沿用既有 `sys_module` / `sys_product` 并按其口径扩展；平台重启自库恢复权威视图，不再读清单文件。
3. **权威视图出口**：新增服务身份专用出口下发**完整**能力视图（含访问面路径、分支标识与动作名、访问面类别、承载服务键）；浏览器侧目录出口保持不含内部路径。
4. **消费方取数改源**：`resolve_capability` 取数来源改为平台权威视图（平台进程本库直读、产品进程启动期拉取）——`03_01` 的收编据此一次到位。
5. **口径重写**：`ops.check_modules`、网关配置生成、服务目录出口、装载校验一律改对注册表 / 权威视图校验；产品清单降为**注册输入**。
6. **断链即拒启**：注册校验不过、拉取失败一律拒启，错误信息可定位到能力名 / 声明方。

## 3. 完成标准 <a id="accept"></a>

平台在零产品清单文件的情况下得到完整登记视图且重启后仍成立；产品服务只上报自身声明、不再装载别家清单；改声明即改注册表、消费方取址与入站判定随之变化（有用例）；重复注册幂等、异值拒收并报差异；拉取失败拒启；`ops.check_modules` 与网关配置改对注册表校验后全绿；四类声明的库表与视图一一对应（无第二套手写源）。
