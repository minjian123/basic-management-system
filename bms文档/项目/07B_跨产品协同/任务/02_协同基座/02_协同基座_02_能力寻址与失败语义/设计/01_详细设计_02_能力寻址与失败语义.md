# 能力寻址与失败语义详细设计

> 跨产品协同 · 02 协同基座 · 02 能力寻址与失败语义 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [02 能力寻址与失败语义](../02_协同基座_02_能力寻址与失败语义.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：消费方以**能力名**取用访问面，取代现有五类字面量（服务键、路径、分支动作名、白名单服务标识、前端命名空间）；把失败语义收敛为三档并逐能力可声明；扩展既有目录快照下发能力与产品键，使服务启动对账与前端取址共用同一份。

**范围内**：

1. 能力视图的查询接口与返回模型（缺失即抛，不返回空）；
2. **两段解析的第一段**（能力 → 业务域）与第二段的**接口占位**（业务域 → 部署单元，实现归 07C `02_02`）；
3. 三档失败语义的判定点、降级声明模型与可观测要求；
4. 既有 `/api/v1/modules/snapshot` 的能力段扩展（向后兼容）；
5. 消费方改造的统一入口（各消费方改法归 `03_01` / `03_02`）。

**范围外**：能力分配记录与白名单派生（`02_04`）、种子调度（`02_03`）、进程内直调传输的实现（07C `02_02`）、各消费方的具体收编（`03_01` / `03_02`）。

## 2. 现状 <a id="current"></a>

| 现状 | 事实 |
| --- | --- |
| 消费方字面量 | 五类落点各自持有对端服务键、路径、分支动作名、白名单标识、产品命名空间（清单见《[跨产品协同登记清单](../../../../../../跨产品协同登记清单.md)》§7） |
| 服务间调用 | `servicecall` 仅有 `http` 与 `null` 两种实现；`build_service_url` 按 `http://{service}:8000` 拼装——**只能按服务名寻址**，无“业务域 → 部署单元”概念 |
| 目录快照 | `GET /api/v1/modules/snapshot` 查 `sys_module` 返回 `ModuleResponse` **数组**；能力记录**不落库**（来自产品清单装载的内存视图），因此现有快照天然查不到能力 |
| 降级 | 读取侧异常一律降级为空集（如组织角色链），无声明、无指标——断链不可见（本次问题即由此掩盖） |

## 3. 目标设计 <a id="design"></a>

### 3.1 能力视图查询 <a id="resolve"></a>

**入口**（单点，消费方不得自拼）：

```python
def resolve_capability(name: str) -> CapabilityEndpoint: ...
```

**返回模型 `CapabilityEndpoint`**：

| 字段 | 说明 |
| --- | --- |
| `name` | 能力名（回显，便于日志与错误定位） |
| `domain` | 提供方业务域 |
| `kind` | `read` / `write` / `txn-branch` / `dataset` / `codes` |
| `path` | 访问面路径（可含 `{param}` 模板） |
| `branch_op` | `txn-branch` 时的分支动作名 |
| `data_source_key` | `dataset` 时的数据源键 |
| `permission_codes` | `codes` 时的业务码 / 权限码集合 |
| `frontend_prefix` | 前端命名空间前缀（缺省取同业务域的路由段） |
| `contract_version` | 契约版本 |
| `target` | **第二段解析结果**（见 §3.2）：`CapabilityTarget(mode="remote"/"local", service_key, base_url)` |

**语义**：

- 能力未声明 → **抛 `ParamError`（10001）**，消息含能力名与「请检查清单与装载」提示；**不得返回 `None` 或空对象**；
- 返回值为冻结对象，消费方只读；
- `codes` 类能力无 `path`，`resolve_capability` 返回的 `path` 为 `None`，消费方不得据此发起调用。

### 3.2 两段解析 <a id="two-stage"></a>

| 段 | 输入 → 输出 | 归属 |
| --- | --- | --- |
| 第一段 | 能力名 → 能力记录（含提供方**业务域**） | 本任务（读 `collaboration_catalog_view()`） |
| 第二段 | 业务域 → **部署单元与库** | 接口在本任务定义，实现归 07C `02_02` |

**接口占位**：定义 `TopologyResolver` 协议（`resolve(domain: str) -> CapabilityTarget`）；**默认实现**为「业务域 → 同名服务键，`mode="remote"`，基址取现有模板」——与现状行为等价，保证 07C 未落地前系统可运行。

**不变式**：`target.mode == "local"` 时消费方必须走进程内直调（传输实现归 07C）；本任务的默认实现恒为 `remote`，不引入行为变化。

**失败语义**：第二段解析不到（07C 拓扑未配置）→ **装载期拒启**；运行期已启动的实例不因拓扑变更而失效（拓扑变更走发布）。

### 3.3 三档失败语义 <a id="failure"></a>

| 档 | 时点 | 判定点 | 行为 |
| --- | --- | --- | --- |
| 一 | 装载 / 启动 | `02_01` 的六类校验 + 消费方**使用登记**校验（声明的能力必须存在） | **拒绝启动**（`CatalogError`），信息定位能力名 |
| 二 | 运行期写 / 强一致路径 | 消费方调用点（`kind in {write, txn-branch}` 或其业务语义为写） | **fail-closed**：整体失败、报明确错误码，**不得捕获后静默跳过**；写链不得出现“写一半”（沿用既有 TM + XA / 顺序提交口径） |
| 三 | 运行期读 / 弱一致路径 | 消费方**显式声明**了降级的能力 | **有界降级**：按声明返回空集或旧副本，**必须**输出结构化日志 + 指标；未声明降级的能力失败即上抛 |

**禁止**：全局缺省降级；以 `try/except: pass` 或 `or []` 形式吞掉失败（护栏见 §5 用例 9）。

### 3.4 降级声明模型 <a id="degrade"></a>

降级是**消费方策略**（提供方无权替消费者决定能否接受空集），故声明落在消费方侧：

```python
CAPABILITY_USAGES = (
    CapabilityUsage(name="mdm.org.user-roles", degrade="empty", reason="组织角色链缺失时按无岗位角色处理"),
)

@dataclass(frozen=True)
class CapabilityUsage:
    name: str
    degrade: str = "none"   # none | empty | stale
    reason: str = ""        # 声明降级时必须给出理由（非空）
```

**校验**：

- 声明了 `degrade != "none"` 但 `reason` 为空 → 装载期报错（不允许无理由降级）；
- 声明了未登记的能力 → 装载期报错（能力名拼错即暴露，不留到运行期）；
- 声明了 `stale` 但无本地投影来源 → 装载期报错（无法兑现的承诺）。

**可观测**：

| 项 | 要求 |
| --- | --- |
| 日志 | `WARNING` 结构化字段：`capability` / `consumer` / `degrade_mode` / `reason` / `target_service` / `error_code` |
| 指标 | `capability_degrade_total{capability, consumer, mode}`；`capability_resolve_error_total{capability, consumer}` |
| 审计 | 不写审计链（读侧降级属运行态，非业务变更） |

### 3.5 目录快照扩展 <a id="snapshot"></a>

**同一端点**（`GET /api/v1/modules/snapshot`），按查询参数分支，**缺省保持原契约**：

| 请求 | 响应 `data` |
| --- | --- |
| 无参数（现状） | `ModuleResponse` **数组**（不变） |
| `?with=collaborations` | `{ "modules": [...], "products": [...], "collaborations": [...] }` |

**各段来源**：

| 段 | 来源 | 说明 |
| --- | --- | --- |
| `modules` | 既有 DB 查询（`sys_module`） | 不变 |
| `products` | `product_catalog_view()` | 前端产品键来源 |
| `collaborations` | `collaboration_catalog_view()` | 只下发 `status=enabled` 且 `kind != "codes"` 的项；字段含 `name / domain / kind / path / frontend_prefix / contract_version`（**不含** `default_consumers` 等授权信息） |

**要点**：

- 能力来自运行时视图而非 DB（不落库），因此该分支**必须**在装载完成后才有效；未装载时返回空数组并给 `warning` 字段；
- 授权信息（分配记录）不下发到该快照，避免越权可见（分配相关出口归 `02_04`）；
- 前端取址：`/api/{product_key}/v1/{frontend_prefix}` 由快照数据组装，前端不再持有常量（`03_02` 消费）。

### 3.6 消费方改造统一入口 <a id="consumer"></a>

三类消费点统一改为：

| 消费点 | 改造后 |
| --- | --- |
| 权限解析器（读出口） | `endpoint = resolve_capability("mdm.org.user-roles")`；用 `endpoint.target.base_url + endpoint.path`；失败按 `CapabilityUsage` 声明处置 |
| 用户 / 角色保存编排（写 + 事务分支） | `resolve_capability("mdm.org.user-*.assign")` 取 `path` 与 `branch_op`；写路径 fail-closed |
| 平台内部端点白名单 | 由 `02_04` 的分配记录派生（本任务只提供能力视图，不改白名单来源） |

| 类别 | 对象 | 变更 |

| 新增 | `bms_core/capability/`（`endpoint.py` / `usage.py` / `topology.py`） | 能力寻址模型、降级声明、拓扑协议与默认实现 |

| 不改 | 既有 `/snapshot` 无参调用方（各服务启动对账、既有前端） | 契约不变 |
| 不改 | 网关路由生成 | 不涉 |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 能力存在 → 取用 | 返回字段与清单一致；`target.mode == "remote"` 且基址按模板 |
| 2 | 能力不存在 → 取用 | 抛 `ParamError`（10001），消息含能力名；不返回 `None` |
| 3 | `codes` 类能力取用 | `path is None`；消费方若使用 `path` 发起调用应被类型/断言拦住 |
| 4 | 默认拓扑实现 | 业务域 → 同名服务键，行为与改造前一致（等价性用例） |
| 5 | 第二段解析失败（模拟拓扑缺失） | 启动期拒启，消息含业务域名 |
| 6 | 写路径 fail-closed（提供方不可达） | 整体失败、无可观测的半写；错误码明确 |
| 7 | 读路径声明 `empty` 且提供方不可达 | 返回空集 + 产出一条 `WARNING` 日志 + `capability_degrade_total` 计数 +1 |
| 8 | 未声明降级的读路径失败 | 失败上抛（不被吞） |
| 9 | 吞异常反例（`except: pass` / `or []`） | 护栏用例断言消费方代码不含无声明降级写法（AST 或代码检索） |
| 10 | 降级声明无理由 | 装载期报错 |
| 11 | 声明了未登记能力 | 装载期报错 |
| 12 | `stale` 声明但无投影来源 | 装载期报错 |
| 13 | 快照无参 | 返回数组（与改造前逐字段一致） |
| 14 | 快照 `?with=collaborations` | 返回三段；`collaborations` 不含 `default_consumers`；`codes` 类不下发 |
| 15 | 未装载时请求带参快照 | `collaborations` 为空数组且有 `warning` 字段 |
| 16 | 既有启动接库对账回归 | 各服务对账结果不变 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 快照响应形态分支导致消费方混用 | 缺省行为严格不变；带参形态在响应中加 `snapshot_version` 字段便于识别 |
| 降级声明被滥用（到处声明 `empty`） | 必须给 `reason` + 评审检查；指标按能力统计，长期高位降级视为契约问题而非正常态 |
| 第二段默认实现“同名服务键”固化 | 明确为过渡实现；07C `02_02` 落地时替换，不改消费方代码 |
| 能力视图与 DB `sys_module` 双源 | 能力不落库，快照中两段来源不同但职责不同（模块=注册要素，能力=协同契约），不构成双事实源 |
| 消费方仍在别处自拼路径 | 由 `03_01` / `03_02` 收编 + 04_01 字面量护栏兜底 |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 能力取用错误是否单列错误码（当前复用 10001） | 出现需区分「能力缺失」与「参数非法」的运维诉求时再拆码 |
| 2 | 快照是否按消费方裁剪（不同消费方看到不同能力集） | `02_04` 分配落地后评估；当前全量下发且不含授权信息 |
