## 2. 决策确认 <a id="decisions"></a>

实施前分四批 + 补充一批共 **19 项**逐项确认（结论已回写设计 §8 对齐记录）：

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 新包落点 | `bms_core/collaboration/`（设计与 `core/capability.py` 撞名，改术语） |
| 2 | 第二段默认映射 | 按域布局派生「业务域 → 承载服务键」，未登记域装载期拒启 |
| 3 | 解析签名 | 单参 `resolve_capability(name)`；租户维度留 07C 升版 |
| 4 | 降级声明通道 | `ApplicationFactory.capability_usages()` 覆写钩子（同 `service_records()` 模式） |
| 5 | 降级执行 | 基座统一 helper（解析 + 降级 + 日志 + 指标）+ 无声明降级护栏 |

| 8 | 能力段下发过滤 | `enabled` + `deprecated` 下发、`disabled` 与 `codes` 不下发 |
| 9 | 快照响应形状 | `{modules, products, collaborations, snapshot_version, warnings[]}` |

| 15 | 使用登记校验触发点 | `service_lifespan` 新增独立步骤（装配期，失败拒启） |

| 17 | `status=disabled` 取用 | 抛 `ParamError` 并注明状态（与快照不下发同口径） |

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 设计写默认实现「业务域 → **同名**服务键」，真实数据不成立（mdm：`domain=org` / `service_key=mdm`，同名拼出 `http://org:8000`） | 改按域布局 `service_key` 派生（决策 2），并补装载期「域缺承载服务即拒」校验；回写设计 §3.2 / §8-2 |
| 2 | 设计写新增 `bms_core/capability/`，与既有 `core/capability.py`（`BaseCapability`）撞名 | 改 `bms_core/collaboration/`（决策 1），回写设计 §4 / §8-1 |
| 3 | 指标名设计无前缀，与全仓 `bms_` 约定冲突 | 加前缀并登记 `METRIC_NAMES`（决策 6） |
| 4 | 设计 §3.5 内部矛盾（「只下发 `enabled`」vs「`deprecated` 保留下发」） | 统一为 `enabled` + `deprecated` 下发、`disabled` / `codes` 不下发（决策 8） |
| 5 | 未装载告警字段设计为单数 `warning` | 改 `warnings` 数组 + `snapshot_version`（决策 9） |
| 6 | 设计写改 `servicecall/base.py` 构造 `ServiceRequest`，但默认拓扑实现要引用其基址模板 → 会成导入环 | 落 `collaboration/request.py`，保持 `collaboration → servicecall` 单向依赖（决策 13） |
| 7 | 缺省快照分支返回 `ConcurrentStableList` → 响应序列化失败（`Unable to serialize unknown type`） | 缺省分支返回纯数组（`modules.to_list()`），逐字段与原契约一致；带参形态走 `CatalogSnapshotResponse` |
| 8 | `product_catalog_view()` 恒非空（平台 `PRODUCT_CATALOG` 常量），「产品目录为空」警示为死分支 | 删除该死分支，覆盖率门禁无缺行 |
| 9 | `register_domain_services(Mapping[...])` / `build_capability_request(Mapping[...])` 被裸集合护栏判新增违规 | 入参改基座不可变集合 `ConcurrentStableFrozenDict`（与 `ServiceRequest` 字段同口径） |
| 10 | `DomainLayoutTopologyResolver` 无基类，被「所有类须继承基类」护栏判违规 | 继承体系根 `BaseFrameworkObject` |
| 11 | 新增可选查询参数导致公开契约与前端类型漂移 | 重生成 `deploy/contracts/platform.json` 与 `api_types/src/platform.ts`（加法变更，422 与既有带参端点同口径） |
| 12 | 手工 `--cov` 运行在 `backend/.coverage` 留下产物，被判工作区卫生违规 | 删除该文件；覆盖率采集统一走 `.cache/coverage/`（预检内） |
| 13 | 记录文档相对链接层级少一层（`../../../../../` 应为 6 级），`engkit links` 报 14 处断链——本任务两处 + `02_01` 两处同源 | 四份记录统一改为 `../../../../../../`；断链 0 处（同一缺陷族顺手修正，`02_01` 侧同步换行修正不改内容） |
