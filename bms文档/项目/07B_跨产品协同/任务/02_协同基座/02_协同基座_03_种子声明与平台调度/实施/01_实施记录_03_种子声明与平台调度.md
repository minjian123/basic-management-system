## 2. 决策确认 <a id="decisions"></a>

实施前分五批共 **15 项**逐项确认（结论已回写设计 §8 对齐记录），要点：

| 组 | 事项（结论） |
| --- | --- |
| 机制统一 | 用户否决草案「两套机制、两个事务」，改为**一套装载 + 一个 XA 全局事务**；平台种子外置 `deploy/registry/platform.toml`，与产品同构 |
| 编排形态 | 每种子一分支、**严格串行**（前一分支 prepared 才开下一分支）；冲突**事务前统一预检**；`--only` 不补依赖；`--require` 人工强制前置 |
| 执行落点 | 编排在 **platform 服务进程内**（XA 分支需引擎注册表 + 分支处理器 + 参与方）；CLI 只做触发与报告渲染；部署顺序「起服务 → 跑种子 → 开流量」 |
| 契约与报告 | 沿用分支处理器范式 `async def entry(session, args) -> None`；统计由**编排器统一采集**（种子不报数）；失败时全部标「已回滚」+ 突出根因 |
| 收尾 | 参数错误退出码 64；`dry-run` 只预检不执行；不建种子执行记录表（开放项） |

补充三项（实施期发现、先问后做）：

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 跨库种子（`seed-platform` / `seed-rbac` 各写两库） | 各拆成「角色」「授权」两个种子，`after` 串联；一分支一库 |
| 2 | 种子实现在 `ops/` 导致服务运行期依赖运维通道（边界检查 5 处违规） | **种子实现下沉 `bms_core/tenant/seed/`**（1551 行），`ops/` 改薄壳转发 |
| 3 | 种子依赖表结构就绪，编排原缺此阶段 | 编排加**结构前置阶段**（`ensure_structure` → 幂等建表），失败即中止；并补**迁移清单注册校验**（`validate_series_registry`） |
