# 种子声明与平台调度详细设计

> 跨产品协同 · 02 协同基座 · 03 种子声明与平台调度 · 详细设计（开发核心文档）

[文档首页](../../../../../../文档首页.md) › [03 种子声明与平台调度](../02_协同基座_03_种子声明与平台调度.md) › 设计

## 1. 目标与边界 <a id="scope"></a>

**目标**：把「产品默认数据」从平台种子里挪出去——产品在自持声明中提供种子入口，平台用**唯一编排入口**按依赖顺序执行，统一幂等、冲突报告与失败隔离；平台种子只播平台自身数据。

**范围内**：

1. 种子分类（平台自身种子 / 产品声明种子）与平台自身种子登记表；
2. 产品种子入口契约（签名、上下文、返回结果）；
3. 编排：依赖排序、循环依赖拒绝、逐项执行与报告、退出码；
4. 幂等、冲突、失败隔离与事务边界；
5. 与既有 10 个 `seed_*` 命令的关系与迁移口径。

**范围外**：具体种子内容（各产品自行维护）、平台种子去产品化的清单改动（`03_03`）、能力与错误码记录（`02_01` / `02_05`）。

## 2. 现状 <a id="current"></a>

| 项 | 事实 |
| --- | --- |
| 入口 | 10 个独立 CLI：`seed_platform`（平台租户 RBAC）、`seed_module`、`seed_menu`、`seed_rbac`、`seed_tables`、`seed_tenant`、`seed_user`、`seed_config`、`seed_sso`、`seed_oidc_client` |
| 实现位置 | `ops/seed_platform.py` 已是薄壳，实现在 `bms_core/tenant/seed/platform.py`；其余脚本各自带 `main(argv)` 与 `async def seed_*(url)` |
| 编排 | **无统一编排**——部署时按文档手工逐个执行，漏跑靠人工发现（曾出现“模块目录未播种导致整批拒启”） |
| 幂等 | 各脚本内部自实现（按自然键 upsert），口径不完全一致 |
| 冲突 | 有的报错、有的覆盖，未统一 |
| 产品数据 | 平台 `seed_menu` 直接写产品业务码与权限码（越界，`03_03` 移除） |

## 3. 目标设计 <a id="design"></a>

### 3.1 种子分类 <a id="kinds"></a>

| 类别 | 来源 | 示例 |
| --- | --- | --- |
| **平台自身种子** | 平台内部登记表（随代码，不落清单） | 平台租户与 RBAC、模块目录、菜单与权限元数据、表归属、配置项、SSO / OIDC 客户端 |
| **产品声明种子** | 产品自持清单 `[[seeds]]`（`02_01` 定义） | mdm 的管理面业务码与权限码 |

**边界**：平台自身种子只播平台数据；产品数据一律由产品入口提供，平台不代写（`03_03` 收口）。

### 3.2 平台自身种子登记表 <a id="registry"></a>

内部常量（随代码，不落清单、不入库），一项一条：

| 字段 | 说明 |
| --- | --- |
| `name` | 种子名（全局唯一，与产品种子共用一个命名空间） |
| `entry` | 可调用对象（模块内函数引用，非字符串） |
| `after` | 依赖的其他种子名（可空） |
| `description` | 用途说明 |

**为什么平台侧用可调用引用而不是模块路径**：平台种子与代码同仓同版本，引用即可；产品种子跨仓，只能声明**模块路径 + 入口名**（`02_01` 已定义），装载期校验可解析。

### 3.3 产品种子入口契约 <a id="contract"></a>

产品在清单声明 `module` + `entry`；平台按点分路径导入并以统一上下文调用：

```python
async def seed_admin_codes(ctx: SeedContext) -> SeedResult: ...
```

| 类型 | 内容 |
| --- | --- |
| `SeedContext` | `db_url`（目标库）/ `dry_run`（试运行）/ `logger` / `tenant_codes`（需按租户铺种时）/ `params`（清单或命令行透传的键值） |
| `SeedResult` | `created` / `updated` / `skipped` / `conflicts`（列表，含键与差异）/ `messages`（列表） |

**校验**：入口不存在 / 不可调用 / 返回类型不符 → 装载期或执行期报错（缺失即拒启，与 `02_01` 的种子校验同一口径）；`dry_run` 下不得产生写操作（由上下文约束，种子实现负责遵守）。

### 3.4 编排与依赖 <a id="orchestrate"></a>

1. **汇总**：平台自身种子 + 已装载产品种子，按 `name` 去重（重名即拒，不静默取一）。
2. **排序**：按 `after` 拓扑排序；**出现循环依赖即拒**（报出环上的种子名）。
3. **筛选**：`--only NAME`（可多次）与 `--skip NAME`（可多次）支持运维按需执行；`--only` 时其依赖**不自动补跑**（显式优于隐式），但输出提示缺失依赖。
4. **执行**：逐项调用，逐项收集 `SeedResult`；单次运行的依赖顺序固定，便于复现。

### 3.5 执行语义 <a id="semantics"></a>

| 语义 | 口径 |
| --- | --- |
| **幂等** | 每种子按自然键 upsert：重复执行结果一致（`created=0` / `updated` 或 `skipped` 计数），不产生重复行 |
| **冲突** | 目标行已存在且**异值**：不覆盖，计入 `conflicts` 并在报告中给出「键 + 现有值 + 期望值」；整体退出码非零 |
| **失败隔离** | 单种子抛错 → 记 `failed` 并继续后续（缺省）；`--fail-fast` 时立即终止。已成功种子的数据不回滚（各种子独立事务） |
| **事务边界** | **每种子一个事务**；不跨种子合并事务（避免长事务与回滚放大）。产品内多种子顺序执行、各自事务 |
| **试运行** | `--dry-run` 全链路不写库，输出“将创建 / 将更新 / 将冲突”预演结果 |
| **可重入** | 同一命令可任意重复执行；升级场景即“再跑一次” |

### 3.6 逐项报告与退出码 <a id="report"></a>

**输出**（表格，逐种子一行）：`name` / `source`（platform / product） / `status`（ok / skipped / conflicts / failed） / `created` / `updated` / `skipped` / `conflicts` / `note`。

**汇总行**：各类计数与冲突明细数。

**退出码**：

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功（含 skipped） |
| 1 | 存在冲突（数据未按期望写入，需人工处置） |
| 2 | 存在失败（异常） |
| 3 | 编排前置错误（重名 / 循环依赖 / 入口不可解析） |

### 3.7 与既有 10 个命令的关系 <a id="legacy"></a>

| 命令 | 处置 |
| --- | --- |
| `seed_platform` | **升级为唯一编排入口**（保留 `--assign-user` 等既有参数，内部把原 RBAC 播种登记为平台自身种子之一） |
| `seed_module` / `seed_menu` / `seed_rbac` / `seed_tables` / `seed_tenant` / `seed_user` / `seed_config` / `seed_sso` / `seed_oidc_client` | 实现保留为平台自身种子的入口；CLI **保留但标注“内部单步”**，文档与部署脚本统一改用编排入口 |

**兼容**：既有部署脚本若仍调用单步命令，行为不变（不破坏），但文档明确“新部署只用编排入口”，避免长期两套调用方式。

### 3.8 部署场景 <a id="scenario"></a>

| 场景 | 做法 |
| --- | --- |
| 空库首次 | 执行编排入口一次（平台自身种子 + 已装载产品种子） |
| 版本升级 | 再执行一次（幂等；新增种子自动纳入） |
| 新产品接入 | 装载其清单后执行一次；只跑产品种子可 `--only <name>` |
| 已部署库补种 | 同上；冲突项按报告人工处置（不自动覆盖） |

## 5. 测试设计 <a id="test"></a>

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 空库首次执行 | 平台自身种子与产品种子全部执行，退出码 0，报告逐项 |
| 2 | 重复执行（幂等） | `created=0`，无重复行，退出码 0 |
| 3 | 冲突（异值） | 不覆盖、报告含键与两侧值、退出码 1 |
| 4 | 单种子异常 | 其余种子继续，退出码 2，报告标 `failed` |
| 5 | `--fail-fast` | 首个失败即终止，后续未执行 |
| 6 | `--dry-run` | 无任何写操作，输出预演结果 |
| 7 | 循环依赖 | 编排前置报错，退出码 3，报出环上种子名 |
| 8 | 重名（平台种子与产品种子同名） | 拒绝，退出码 3 |
| 9 | 产品入口不可解析 | 拒绝，定位 `module:entry` |
| 10 | 产品入口返回类型不符 | 拒绝并定位种子名 |
| 11 | 依赖排序 | 执行顺序满足 `after`；无依赖时按登记顺序稳定 |
| 12 | `--only` / `--skip` | 只执行指定项；缺依赖时输出提示 |
| 13 | 事务边界 | 后段种子失败不影响前段已提交数据 |
| 14 | 单步命令兼容 | 直接调用 `seed_menu` 等单步命令行为不变 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 产品种子体积大 / 耗时长 | 逐种子独立事务 + 逐项报告；必要时产品侧分批（种子内部实现） |
| 冲突大量出现导致“每次都要人工处置” | 冲突语义固定为“异值不覆盖”，从根上要求产品种子与库中既有数据同源；反复冲突视为声明与实现不一致，需修种子而非放宽 |
| 单步命令与编排入口并存造成两套口径 | 文档与部署脚本统一用编排入口；单步命令标注“内部单步”，不对外推荐 |
| 平台自身种子登记表与清单重名 | 编排阶段统一去重并拒绝重名（不静默择一） |
| 种子依赖形成环 | 拓扑排序检测并拒绝，报出环 |

## 7. 开放项 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 是否需要“种子执行记录表”（记录上次执行版本，实现增量） | 出现种子数量与数据量显著增长时评估；当前靠幂等重跑 |
| 2 | 单步命令何时彻底下线 | 所有部署脚本切换完成后评估 |
| 3 | 产品种子是否需要按租户铺种（`tenant_codes` 语义） | 首个按租户铺种的产品需求出现时定 |
| 4 | 冲突是否支持 `--force` 覆盖 | 暂不提供（覆盖会掩盖声明与实现不一致） |
