## 2. 任务内容 <a id="content"></a>

1. **种子入口声明**：产品在自持清单声明种子入口（模块路径 + 入口 + 依赖顺序），平台装载时校验可解析（不可解析即拒启）。
2. **统一调度**：并入**既有平台种子编排入口**（`seed_platform`）——**平台自身种子与产品种子走同一套装载注册机制**（均为 `deploy/registry/*.toml` 自持声明），由平台统一编排，在**一个 XA 全局事务**内按依赖顺序**串行**执行、统一提交或**整体回滚**；统一幂等（重复执行结果一致）、冲突（事务前统一预检，已存在异值即报错并输出差异，不覆盖）。
3. **逐项结果**：每次执行输出逐项结果（跳过 / 新建 / 冲突 / 失败原因），供运维与验收核对。
4. **平台种子去产品化**：与 `03_03` 配合——本节只提供调度能力与用例，实际移除产品条目由 `03_03` 完成。

## 3. 完成标准 <a id="accept"></a>

种子入口不可解析时拒启；调度按依赖顺序**串行**执行且重复执行幂等；构造冲突时非零退出并输出差异；**任一产品种子失败即整体回滚、无脏数据**（统一事务下「失败隔离」升级为「整体回滚」，比原口径更强）；逐项结果可核对；用例覆盖上述正反路径，含「中间态不可见」与「失败后零写入」两条强断言。

## 6. 设计要点（2026-10-27 拍板） <a id="keypoints"></a>

**核心口径**：一套装载注册机制 + 一个 XA 全局事务。

| # | 要点 | 说明 |
| --- | --- | --- |
| 1 | **声明统一** | 平台种子外置为 `bms/deploy/registry/platform.toml`，与产品 `<产品>/deploy/registry/*.toml` 完全同构 |
| 2 | **装载统一** | 同一解析器、同一 `SeedRecord`、同一 `SEED_CATALOG` 合并视图；不建第二套登记表 |
| 3 | **编排统一** | 冲突预检 → 拓扑排序 → 派生分支 → 一个 XA 全局事务；无第二个播种入口 |
| 4 | **执行统一** | 每种子一分支（`service` + `db_key` 声明），**严格串行**：前一分支 prepared 才开下一分支 |
| 5 | **失败即整体回滚** | 任一分支失败 → 全部回滚，零脏数据；报告全部标「已回滚」+ 突出根因 |
| 6 | **中间态不可见** | 分支 prepare 后锁持有到 commit，其他事务读不到未提交数据 |
| 7 | **入口契约** | 沿用分支处理器范式 `async def seed_x(session, args) -> None`，不新增第二套范式 |
| 8 | **统计口径** | 编排器统一采集（执行前后对比），种子不报数 |
| 9 | **部署顺序** | 起服务 → 跑种子 → 开流量（XA 参与方须在线） |

> **与草案的差异**：草案原为「平台种子代码常量 + 产品种子清单、两处各自执行、失败隔离」——该方案被否决（两套机制、中间态可见、无法整体回滚）。差异逐条见详细设计 §8 对齐记录。

> 交付物：种子调度实现、逐项报告输出、详细设计、实施与测试记录
