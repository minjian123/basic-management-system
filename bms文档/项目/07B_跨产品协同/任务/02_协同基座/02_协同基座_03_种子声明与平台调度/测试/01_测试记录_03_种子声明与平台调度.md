## 3. 核心用例（13~17）落地方式 <a id="cases"></a>

这五条是「统一机制」的**核心验收点**，也是与草案「失败隔离」口径差异的证明（详设 §8 #3 / #7）。
**SQLite 不支持两阶段**（`begin_twophase` 抛 `NotImplementedError`，已实测），故按三层方案落地：

| 层 | 用例 | 断言 |
| --- | --- | --- |
| **① 编排层替身** | 13 串行时序 | 前一分支 `prepared` 才开下一分支；执行序即计划序；失败即停止后续分支；`commit` 只在全部分支 prepared 后发生 |
| | 14 全部成功 | 各分支 prepared → 统一 `commit`；报告逐项 `ok`；统计随报告下发 |
| | 15 失败整体回滚 | 某分支 rejected → 立即 `rollback` 全部；报告全标「已回滚」+ 突出失败根因；异常路径同样回滚并进报告 |
| **② 真实 SQLite 可见性** | 16 无脏数据 | 事务内写入 → 回滚 → 另一连接查询为空 |
| | 17 中间态不可见 | 未提交写入对另一连接不可见；提交后可见（对照组） |
| **③ 真库 XA（按环境变量跳过）** | 17 真库补充 | `BMS_TEST_MYSQL_URL` / `BMS_TEST_PG_URL` / `BMS_TEST_DM_URL` 已配置时验证两阶段可用；未配置即 skip |
