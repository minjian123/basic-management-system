## 3. 设计用例（待落地） <a id="cases"></a>

详细设计 §5 列出 29 条用例，**本任务实施阶段未落地**，另开新会话处理。要点：

| 组 | 用例 | 关键断言 |
| --- | --- | --- |
| 装载（1~3） | 平台声明装载 / 合并视图 / 自动发现 | 9 条记录、平台在前、同类型 |
| 预检（4~10） | 重名 / 数据异值 / 环 / 前缀 / 入口 / 依赖 / `db_key` | 各自退出码 3 或 1 |
| 排序与派生（11~12） | 拓扑序 / 分支派生 | `after` 满足、`branch_id` ≤ 16 |
| **执行（13~17）** | **串行时序 / 全部成功 / 失败回滚 / 无脏数据 / 中间态不可见** | **本任务核心验收点** |
| 幂等与筛选（18~22） | 重复执行 / dry-run / only / skip / require / 参数错误 | `created=0`、退出码 64 |
| 报告（23~24） | 逐项统计 / `--json` | 与目标表实际变化一致 |
| mdm（25~26） | 真实播种 / 冲突 | 业务码 + 4 权限码、预检拦截 |
| 兼容（27） | 单步命令 | `ops.seed_menu` 行为不变 |
| 跨服务（28~29） | 远程分支 / 超时 | `prepared` 参与全局提交、超时回滚 |

> **优先补 13~17**（串行时序 / 整体回滚 / 无脏数据 / 中间态不可见）——这四条是本任务「统一机制」的核心保证，也是与草案「失败隔离」口径差异的证明。
