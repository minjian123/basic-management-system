## 2. 决策确认 <a id="decisions"></a>

实施前分四批共 **16 项**逐项确认（结论已回写设计 §8 对齐记录）：

| # | 事项 | 结论 |
| --- | --- | --- |
| 1 | 授权数据跨进程可见性 | 平台内部出口 + 基座拉取缓存（`register_capability_grant_source` / `ensure_grant_view`） |
| 2 | 声明默认值同步时机 | 平台服务 `startup_hooks()` 落库；差异计算为 `bms_core` 纯函数 |
| 3 | 入站校验挂载形态 | 显式 `require_capability("<能力名>")`，不做 path 反查 |
| 4 | 是否接线三处 platform 端点 | 不接（能力未声明，归 `03_01` 一次性切换） |
| 5 | 出站 scope 命名 | `svc:{业务域}:{read\|write}`（与开放接口 scope 分区） |
| 6 | scope 派生落点 | `build_capability_request()` 缺省自动填 `policy.scopes` |
| 7 | 拒绝错误码 | `PermissionError`（30001 / 403） |
| 8 | 管理面权限码 | 新增业务码 `capability-grant` + `query` / `manage`，补 `ops.seed_menu` |
| 9 | 授权视图出口 | `/api/v1/platform/internal/capability-grants`（`provider` / `consumer` 二选一 + 域 / 自身校验） |
| 10 | 缓存刷新 | 启动必拉 + TTL 60s 惰性重拉 + 授予 / 撤销主动清快照 |
| 11 | 声明回归语义 | `source=declared` 且因声明移除 disabled 的记录，声明回归即恢复 |
| 12 | 快照按消费方裁剪（`02_02` 开放项 2） | **不裁剪**，维持现状（该项闭环） |
| 13 | 审计留痕 | 走 `AuditCapturer.capture()` 占位契约，真实落库归 29-审计合规 |
| 14 | 指标口径 | `call_total{capability,consumer,result}` / `denied_total` / `grant_active` 三个 |
| 15 | Kiwi 编号 | 归 `05_01` 统一登记 |
| 16 | 撤销接口 | `DELETE /api/v1/capability-grants/{grant_id}` 软撤销 |

另有 7 条**文档冲突/偏差**按架构铁律先行处置（详见设计 §8 第 17~19 行与各节修订注）：

## 5. 问题与处置 <a id="issues"></a>

| # | 现象 | 原因 | 处置与落点 |
| --- | --- | --- | --- |
| 1 | 授予 / 声明同步抛「A transaction is already begun on this Session」 | 服务内先做了只读查询（分页 / 现状 / gauge 统计），会话上已 autobegin 事务，再 `begin()` 冲突 | 新增 `_write_scope()`：写事务前先 `rollback()` 清空遗留只读事务（无挂起写入，安全幂等），三处写路径统一经它 |
| 2 | `invalidate_capability_grants(provider=...)` 抛 `KeyError` | 快照键不存在时直接 `delete` | 改为存在才删（未加载即无需失效） |
| 3 | 健康检查 / 插件用例在「未建表」环境启动失败 | 启动钩子对库不可读一律拒启 | 按「表归属接库校验」同口径：`SQLAlchemyError` → 降级放行 + `WARNING` + `app.state.grant_sync_degraded`；声明不一致 / 出口不可达仍拒启 |
| 4 | `test_base_inheritance` 报 `CapabilityGrantService` 无基类 | 服务类未继承体系基类 | 改继承 `BaseFrameworkObject`（与既有服务类一致） |
| 5 | 契约快照重新导出后其他服务文件被标记改动 | 导出工具按当前运行期重写全部快照（换行 / 键序差异） | 仅保留 `platform.json` 实质变更，其余还原；`contract_snapshot check` 通过 |
| 6 | `check_bare_collections` 报两例同构 `tuple` 入参 | 测试辅助函数签名用了 `tuple[str, ...]` | 改 `ConcurrentStableFrozenList[str] | None` |
| 7 | **（2026-10-29 复核修正）** 基座常量 `GRANT_VIEW_PATH` 写 `/api/v1/internal/capability-grants`，真实路由是 `/api/v1/platform/internal/capability-grants` | 平台内部面命名带 `/{服务}/internal/...` 段，常量漏了 `platform` 段；旧用例又各自复制了一份同样的字面量，测试跟着常量一起错，没人发现 | 常量对齐真实路由；`test_capability_grant_bootstrap.py` 改为导入基座常量（不再有第二份字面量）；平台侧新增「常量 == 真实路由 + 出现在 OpenAPI 路径表」防漂断言（Kiwi **2368**，覆盖授权视图与拓扑快照两个出口）。影响：修正前产品进程远端拉授权视图必然 404 → 长期「降级 + 首访 fail-closed」 |
