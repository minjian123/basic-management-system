## 2. 任务内容 <a id="content"></a>

1. **默认分配声明**：产品自持清单声明「默认允许谁消费本能力」；装载时校验声明中的消费方已登记。
2. **分配记录落地**：平台装载后落分配记录（运营期数据），支持在平台侧调整与撤销，变更留审计。
3. **派生**：入站校验（谁能调我）＝本能力有效分配；出站授权（我能调谁）＝消费方维度有效分配，落实为服务令牌 scope；监控维度＝「调用方 × 能力」。
4. **合法性判定**：有有效分配即合法（直连或经平台中转均可）；无分配时运行期拒绝并报明确错误，装载期无法解析的分配拒启。
5. **默认策略**：产品间默认经平台中转，直连须先有分配记录（策略判定不写在调用方）。
6. **审计与指标**：分配 / 调整 / 撤销进审计链；调用侧按「调用方 × 能力」打点（调用量 / 失败率 / 越权尝试）。

## 3. 完成标准 <a id="accept"></a>

分配记录可由产品声明装载落库，并可在平台侧调整 / 撤销（变更进审计链）；入站白名单与出站 scope 均由分配记录派生，代码中无调用方字面量；无分配时运行期拒绝并报明确错误、装载期解析失败即拒启；指标按「调用方 × 能力」打点且有断言；默认策略（中转优先、直连需分配）有对应用例；定向覆盖率达标（行 + 分支）。
