## 1. 目标与边界 <a id="scope"></a>

**目标**：用可复现的证据给 07B 的 9 行门禁逐条结论，把“产品变更不再触发平台侧改动、断链在启动期暴露”从口号变成机器可验的事实；并完成三类文档一致性与遗留归口。

**范围内**：

1. 门禁 9 行的证据形式与结论写法（含“限定”语义）；
2. 专项测试报告结构（七节 + 附录）；
3. 三类文档一致性核对与收口断言用例；
4. 收口回写清单与遗留归口规则。

**范围外**：任何功能实现（本任务只验证与收口）；阶段七（`07_RBAC基础模块`）的验收（已收口）；07C 的验收（另行）。

## 2. 现状与先例 <a id="current"></a>

| 先例 | 可复用内容 |
| --- | --- |
| 阶段七 `05_01` | 门禁逐行内联结论 + 证据索引的写法；报告六节 + 界面一致性节 + 附录；`check-status` 与收口断言用例把关；计划全量回写（头部计数、§2/§3、§5 结论与对照、§7 台账） |

**07B 的差异**：本专项**不产出界面**（无界面一致性节），但多两类证据——「跨仓一致性」与「护栏生效」；门禁 9 行（比阶段七的 7 行多两行：与既有机制统一、错误码可对账）。

## 3. 设计 <a id="design"></a>

### 3.1 门禁逐行证据形式 <a id="gate"></a>

每行统一四要素：**验证手段（命令）+ 通过标准 + 证据索引（用例 / 报告节）+ 结论（达标 / 限定达标）**。

| # | 门禁行 | 验证手段 | 通过标准 | 证据索引 |
| --- | --- | --- | --- | --- |
| 1 | 零产品字面量 | `check-product-literals`（含 `--self-test`） | 全仓零命中、基线清空、豁免均带理由 | 用例（护栏自测）+ 报告 §5 |
| 2 | 声明缺失/不符即拒启 | `check_modules` 六类反例 + 装载用例 | 六类反例均拒启且定位到能力名 | 用例清单 + 报告 §5 |
| 3 | 写 fail-closed、读降级仅限声明 | 定向用例（写路径 / 读路径 / 未声明降级 / 吞异常反例） | 写失败无半写；降级仅限声明且有日志与指标；未声明即上抛 | 用例 + 报告 §5 |
| 4 | 种子统一调度 | 编排用例（幂等 / 冲突 / 失败隔离 / 顺序反转） | 四种场景均符合 `02_03` 口径 | 用例 + 报告 §5 |
| 5 | 前端新增产品零改动 | 夹具用例（虚构产品） | 不改代码即可取址 | 用例 + 报告 §5 |
| 6 | 与既有注册机制统一 | 代码检索 + 登记清单 §8 对照 | 无第二套注册表 / 目录出口 / 播种入口 / 校验入口 | 检索结论 + 清单 §8 |
| 7 | 分配：有则合法、无则越界 | 入站 / 出站 / 过期 / 直连越界用例 | 无授权拒绝且定位能力名；撤销有界生效 | 用例 + 报告 §5 |
| 8 | 错误码可渲染可对账 | 渲染用例（补全 / 回退 / 未知码）+ 契约反向用例 | 三类反例被拒；文案缺失回退并告警；手册导出与视图一致 | 用例 + 报告 §5 |
| 9 | CI 能取产品仓清单并校验 | CI 作业实跑（或本地等价 `--repo-url`） | 作业绿；构造不一致即红并定位能力名 | 流水线链接 + 报告 §5 |

**“限定达标”语义**：仅在证据受环境限制（如真库联调需部署窗口）时使用，必须写「限定：{限制}（归口 §7 第 N 项）」；**不允许**用“限定”掩盖未实现。

**禁止**：结论只写“已完成/已达标”而无证据索引；证据指向不存在的用例或文件（由收口断言检出）。

### 3.2 专项测试报告结构 <a id="report"></a>

报告落 `bms文档/项目/07B_跨产品协同/01_测试报告_跨产品协同.md`，七节 + 两附录：

| 节 | 内容 |
| --- | --- |
| §1 结论 | 门禁 9 行总判定、专项目标达成与否、未达标项与归口 |
| §2 用例执行统计 | 后端定向 / 前端包 / engkit 自测 / 护栏自测的用例数与通过率 |
| §3 缺陷统计 | 本专项发现与修复的缺陷（含跨仓漂移的收编追溯）、外部缺陷单归口 |
| §4 覆盖率 | 变更文件定向覆盖率（行 + 分支 100%）+ 引用既有快照的口径差异说明 |
| §5 门禁逐条核对 | 9 行表格（结论 + 证据索引，与计划 §5 同源） |
| §6 风险与遗留 | 遗留逐条归口，无“无归口”条目 |
| §7 复盘与经验教训 | 根因（架构缺能力层）、机制收益、可复用经验 |
| 附录 A | 复现命令清单（逐条命令 + 期望输出摘要） |
| 附录 B | 收编对照表（11 处硬编码 → 目标形态 → 证据） |

**与计划 §5 的关系**：门禁结论**单一事实源在计划 §5**；报告 §5 与之同构引用，不各写一套结论。

### 3.3 三类文档一致性 <a id="consistency"></a>

| 手段 | 覆盖 |
| --- | --- |
| `check-status --stage 07B_跨产品协同` | 需求编号集合、任务状态与日期口径、任务 ↔ 域总览 ↔ 计划一致、计划两表互斥、投入与编号挂接 |
| 收口断言用例（新增） | 门禁表行数与结论字样、报告七节齐备、登记清单无“待收编”残留、文档无未归口遗留 |
| `check-links` / `check-base` / `check-docs-scope` | 链接与锚点、基座完整性、进度字段落点 |

### 3.4 收口断言用例 <a id="assert"></a>

新增 `backend/libs/bms_core/tests/crosscut/test_collab_closure.py`（与 `test_m6_closure.py` / `test_m7_closure.py` 同族）：

| 断言 | 目的 |
| --- | --- |
| 计划 §5 门禁表恰 9 行，每行含「达标」或「限定」 | 防漏行、防只写“待核对” |
| 计划头部计数与两表一致、§3 无剩余行 | 防收口只改表不改头部 |
| 报告七节齐备（§1 ~ §7）且 §5 行数 = 9 | 防报告与门禁脱节 |
| 登记清单 §2 状态无「设计已定（待收编）」 | 防“文档说已收编、代码没改” |
| 登记清单 §7 收编映射 11 行均有目标形态 | 防收编遗漏 |
| 架构 38 节点与规划节互链可解析 | 防语义层与实现层断链 |

### 3.5 收口回写清单 <a id="writeback"></a>

| 对象 | 回写内容 |
| --- | --- |
| 专项计划 | 头部计数（12 项全完成）、§2 追加 `05_01` 行、§3 清空、§5 九行结论、§7 台账结论与说明 |
| 登记清单 | §2 状态全部改「已收编」；§7 映射表补“证据”列 |
| 专项 README | 报告链接、任务与需求状态索引 |
| 文档首页 / 仓根 README | 报告与专项索引同步 |
| 遗留台账 | 逐条给归口；`ALLOW_MISSING` 等运维开关的适用场景入 §7 |

**不回写**：架构节点与规划（不写实现状态）；《总体项目规划》（专项不占阶段编号，达成状态只在专项计划与报告体现）。

### 3.6 遗留归口规则 <a id="followup"></a>

| 规则 | 说明 |
| --- | --- |
| 每条必须有「来源 + 归口」 | 来源指向任务记录或本轮核对；归口指向具体任务 / 阶段 / 运维窗口 |
| 禁止“无归口” | 断言用例检出即失败 |
| 环境类单列 | Windows 护栏误判、CI 网络等标“环境类”，不计入产品缺陷 |
| 设计口径类单列 | 明确“已定、无需回改”的条目单列，避免被反复重开 |

## 6. 风险与边界 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 门禁结论“看起来达标”但证据不可复现 | 每行必须给命令 + 期望输出摘要；附录 A 列全部命令 |
| 计划与报告结论漂移 | 结论单一事实源在计划 §5，报告同构引用；断言用例校验行数一致 |
| “限定”被滥用 | 限定必须指向 §7 条目且该条目有归口；断言用例校验格式 |
| 收编状态回写与代码实际不符 | 断言登记清单状态；代码侧以护栏（零字面量）为事实依据 |
| 覆盖率数字口径混乱 | §4 明确“变更文件定向 100% + 既有快照引用”，并标注口径差异 |
