## 1. 业务域说明 <a id="intro"></a>

本业务域承载「先把语义补齐」这一步：架构设计此前只有「产品如何接入平台」（架构 10 / 11、规划 5.2 ~ 5.7），没有「产品之间/平台与产品之间如何协同」，导致消费方只能各自写死对端标识与访问面。本业务域补架构节点、规划节、接入流程步骤与实现侧登记清单，为后续机制与收编提供依据。

- **依据**：《[平台可扩展性规划](../../../规划/平台可扩展性规划.md)》「产品间协同与能力契约」节、《[文档生成规范](../../../规范/文档生成规范.md)》「架构节点的语义与实现分层」节「架构节点的语义与实现分层」。
- **性质**：纯文档交付（无代码），是本专项后续全部工作的前置。

## 2. 需求 01-1：跨产品协同架构节点与能力登记 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：阶段七收口时，产品服务标识归并（`org` → `mdm`）导致平台侧五类消费点静默断链，读取侧因降级路径存在而「少一半也不报错」。复盘确认根因在架构层——跨产品协作只有「服务级登记」，没有「能力级契约」，消费方除写死对端别无他法，于是每次产品演进都要全仓搜改。若不先补语义，后续机制与收编没有判定依据，同类问题必然复发。

**内容**（架构 38 节点；规划 5.8 节；《项目规划说明》「平台扩展接入流程」）：

1. **架构节点**：新建《架构设计 · 跨产品协同》，写清三类协同方向（平台内建→产品、产品→平台、产品↔产品）、能力目录语义（能力名唯一 / 提供方唯一 / 消费方登记 / 产品自持声明 + 平台装载校验）、协同契约要素类别与归属、契约版本与兼容、消费方寻址与三档失败语义、依赖方向与五条红线、与相邻节点分工、演进与开放项。
2. **规划节**：《平台可扩展性规划》「产品间协同与能力契约」节（新增）（只写方向与边界，细节引架构节点），并把「协同能力登记」写入《项目规划说明》的接入流程步骤。
3. **登记清单**：新建《跨产品协同登记清单》，登记现有 11 项跨产品能力（能力名 ↔ 提供方 ↔ 消费方 ↔ 访问面类别 ↔ 业务语义要素 ↔ 前端面 ↔ 版本 ↔ 状态）、消费方登记、产品间直连登记（当前为空）、产品自持声明要素类别、种子登记与「现状 → 目标」收编映射。
4. **导航同步**：架构总览节点地图收录新节点、相邻节点（37）前后导航补齐、阶段 README 与仓根 README 增专项索引。

**完成标准**：四份文档落地且互相引用可跳转；架构节点只写语义（无实现侧命名、代码落点、配置项与代码片段、脚本命令、字段级结构，符合《文档生成规范》「架构节点的语义与实现分层」节）；登记清单覆盖 11 项能力且每项有提供方与消费方；规划节与接入流程步骤可追溯到架构节点；文档校验（链接自洽 / 基座完整性 / docs-scope）全通过。
