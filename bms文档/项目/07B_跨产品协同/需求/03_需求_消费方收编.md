# 消费方收编需求

> 07B 跨产品协同 · 需求业务域 03：后端、前端与平台种子的收编（3 条）

[文档首页](../../../文档首页.md) › [跨产品协同总览](00_需求_跨产品协同.md) › 消费方收编　|　[← 协同基座](02_需求_协同基座.md)　[→ 护栏与 CI](04_需求_护栏与CI.md)

## 1. 业务域说明 <a id="intro"></a>

本业务域把阶段七收口时盘出的 11 处硬编码逐处收编到能力寻址上，使「产品改名 / 改路径 / 换标识」不再触发平台侧代码改动。收编须行为等价：既有权限、分配、种子与前端取数结果不变。

- **依据**：架构 38 节点 §3 ~ §8；《跨产品协同登记清单》§7「收编映射」。
- **性质**：既有代码改造（后端 / 前端 / 运维脚本），无新增业务功能。

## 2. 需求 03-1：后端消费方收编 <a id="r03-1"></a>

优先级：2（高）

**背景与动机**：后端的跨产品协作面共五类落点（权限解析器的服务键与只读出口路径、用户保存编排的内部写通道与分支动作名、角色保存编排的同构两组、平台内部端点白名单三处、平台种子中的产品权限码），全部持有对端字面量；产品标识归并时同时断链，且降级掩盖了故障。

**内容**：

1. **权限解析器**：改为按能力名取只读出口的访问面（服务标识与路径均来自能力视图）。
2. **用户保存编排 / 角色保存编排**：内部写通道路径、分支动作名、分支参与者标识均按能力名取；强一致路径沿用既有事务口径。
3. **平台内部端点白名单**：调用方白名单由**能力分配记录**派生，不再逐处硬编码服务标识。
4. **行为等价**：权限计算结果、分配写入结果、白名单拒绝语义均与收编前一致。

**完成标准**：上述落点不再出现产品标识与对端路径字面量（护栏通过）；既有后端用例全绿；新增「改能力声明中的路径 / 动作名 → 消费方行为随之变化」的用例；定向覆盖率达标（行 + 分支）。

**参考文档**：《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》§3、§7、§8；《[跨产品协同登记清单](../../../跨产品协同登记清单.md)》§2、§7

## 3. 需求 03-2：前端目录消费 <a id="r03-2"></a>

优先级：2（高）

**背景与动机**：前端把产品键与产品命名空间写成常量（产品键清单、组织数据源默认端点、产品寻址工具、页面端点常量），产品标识变更时前端必然漏改——阶段七收口时组织选择与回显即因命名空间过期而不可用。

**内容**：

1. **产品键来源**：前端产品键取自平台目录快照（运行期），不再维护手写常量清单。
2. **命名空间取址**：组织数据源等产品端点按能力的前端面取址，由寻址契约统一组装。
3. **失败语义**：目录快照不可用时给出明确降级（禁用相关产品能力并提示），不得静默拼出错误地址。
4. **零改动验证**：以测试夹具模拟「新增一个产品」时前端无需改代码即可取址。

**完成标准**：前端源码不再出现产品标识与产品命名空间字面量（护栏通过）；产品键与端点均由目录快照驱动；快照不可用时有明确降级与提示；新增产品夹具用例通过；受影响包的类型检查与用例全绿。

**参考文档**：《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》§7、§8；《[架构设计 · 模块注册](../../../设计/架构设计/11_架构设计_子系统_模块注册.md)》

## 4. 需求 03-3：平台种子去产品化 <a id="r03-3"></a>

优先级：2（高）

**背景与动机**：平台种子清单里直接写着产品业务码与四个权限码，新增产品或调整产品权限码都要改平台代码，与「产品自持、平台不写产品」的口径相抵。

**内容**：

1. 平台种子移除产品业务码与产品权限码条目。
2. 产品权限码改由产品种子声明、平台统一调度（机制见需求 `02-3`）。
3. 已部署库的补种口径随之更新：平台种子 + 各产品种子按声明执行。

**完成标准**：平台种子清单无产品标识（护栏通过）；执行「平台种子 + 产品种子」后产品权限码正确入库；重复执行幂等；平台侧既有种子用例全绿。

**参考文档**：《[架构设计 · 跨产品协同](../../../设计/架构设计/38_架构设计_子系统_跨产品协同.md)》§5、§8；需求 [`02-3`](02_需求_协同基座.md#r02-3)
