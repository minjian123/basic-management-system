## 1. 域说明 <a id="intro"></a>

本域承载专项收口：按专项完成标准逐条核对门禁、归档阶段测试报告、做需求 / 任务 / 计划三类文档一致性核对，并把遗留项登记归口。

- **依据**：《[测试规范](../../../规范/测试规范.md)》「测试报告」节、《[计划文档规范](../../../规范/计划文档规范.md)》、《[AI开发规范](../../../规范/AI开发规范.md)》「覆盖率要求」节。
- **性质**：验证与文档收口（无独立功能代码）。

## 2. 需求 05-1：专项验收与测试报告 <a id="r05-1"></a>

优先级：2（高）

**背景与动机**：本专项的全部价值在于「产品变更不再触发平台侧改动、断链在启动期暴露」。这两点若只在实现时口头声称，无法证明；必须有机器可验的门禁与可追溯证据，否则收编完一段时间后又会退回「哪里报错改哪里」。

**内容**：

1. **门禁逐条核对**：平台源码 / 平台种子 / 前端常量零产品字面量；能力声明缺失或与契约不符时拒绝启动；写路径 fail-closed、读路径降级仅限显式声明；产品种子由平台统一调度且幂等、冲突报错；前端在产品新增时零改动；CI 能取产品仓清单并校验。
2. **阶段测试报告归档**：用例执行、缺陷、覆盖率、风险与遗留、复盘与经验教训。
3. **三类文档一致性**：需求 ↔ 任务 ↔ 计划编号与挂接一致、进度只在计划表；跑一致性核对脚本与预检。
4. **收口回写**：按结论回写计划、登记清单状态（「设计已定（待收编）」→「已收编」）、索引；遗留项逐条归口。

**完成标准**：门禁逐条有结论与证据索引、无未达标项（限定项注明归口）；阶段测试报告归档且结构齐备；需求 / 任务 / 计划一致、编号无缺失、一致性核对无硬规则不合规；遗留项全部登记归口，无「无归口」条目。
