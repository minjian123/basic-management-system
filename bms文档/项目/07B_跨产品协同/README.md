## 立项背景（2026-10-24） <a id="background"></a>

阶段七收口核对发现：mdm 完成服务标识归并（`org` → `mdm`）后，bms 侧五类消费点（权限解析器的服务键与出口路径、用户 / 角色保存编排的内部写通道与分支动作名、平台内部端点白名单、平台权限码种子、前端产品键与命名空间）**全部静默断链**——读取侧因降级路径存在，运行期表现为「能力少一半」而不报错。

根因不是实现疏漏：**架构设计缺少「跨产品协同」这一层**——现有 10 / 11 / 36 / 37 节点只覆盖「产品如何接入平台」与「服务如何通信」，没有「能力级契约」；消费方除写死对端标识与访问面外别无他法，于是「遇一个改一个」。

本专项补这一层：新建架构节点 38 与《跨产品协同登记清单》，以「产品自持声明 + 平台装载校验 + 消费方按能力名寻址」收编既有 11 处硬编码，并以机器护栏防止复发。

## 边界 <a id="scope"></a>

- **范围内**：协同架构语义、能力目录与登记、产品自持声明格式与装载校验、能力寻址与失败语义、产品种子声明与平台调度、后端与前端消费方收编、字面量护栏与 CI 校验、专项验收。
- **范围外**：服务间调用机制与强一致事务（归架构 37）、注册要素与模块登记明细（归架构 11）、网关路由与命名空间拼装（归架构 36）、前端模块产物加载（归架构 35）；不改动产品的业务功能本身。
