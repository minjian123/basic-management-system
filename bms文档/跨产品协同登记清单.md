# 跨产品协同登记清单

> 跨产品能力的**实现侧权威登记**：能力名 ↔ 提供方 ↔ 消费方 ↔ 访问面 ↔ 版本 ↔ 状态

## 1. 定位与分工 <a id="position"></a>

- **语义**（能力是什么、谁声明、成败语义、红线）见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》，本清单**不重复**。
- **本清单登记**：有哪些跨产品能力、由谁提供、谁在消费、访问面与业务语义要素落在哪、契约版本、收编状态。
- **不在本清单**：后端基类 / 继承链 / 代码落点 → 《[后端基类清单](后端基类清单.md)》；前端链层 / 能力 / 落点 → 《[前端基类清单](前端基类清单.md)》；具体实现做法与字段级结构 → 任务详细设计。
- **单一权威**：能力的**声明源在产品仓**（产品自持声明）；本清单是平台侧**登记视图**，用于跨仓对账与收编跟踪，不代替产品声明。

## 4. 能力分配登记 <a id="assignment"></a>

分配是平台对「能力 × 消费方」的授权记录，粒度能力级；**有有效分配即合法（直连或经平台中转均可），无分配即越界**（口径见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「能力分配与授权」节）。

**两层**：产品自持声明写「默认允许谁消费」，平台装载后落分配记录（运营期数据，可调整 / 撤销并留审计）。

| 能力 | 默认消费方（产品声明） | 直连许可 | 状态 |
| --- | --- | --- | --- |
| `mdm.org.user-roles` | platform | 不需要（平台内建 → 产品，属单向协作） | 设计已定（待收编） |
| `mdm.org.user-*` / `mdm.org.role-*.assign` | platform | 不需要（同上） | 设计已定（待收编） |
| `mdm.org.dept-data` / `mdm.org.post-data` | platform、desktop | 不需要（前端经网关，不属产品间直连） | 设计已定（待收编） |
| `platform.user.query` / `platform.permission.invalidate` / `platform.config.snapshot` | mdm（`config.snapshot` 另含 identity） | 不需要（产品 → 平台，属既有白名单口径） | 设计已定（待收编） |

> 当前**无**产品间直连分配。后续出现产品间调用时，须在此登记默认消费方与直连许可，并由平台落为分配记录；未登记即按越界拦截。分配调整 / 撤销的审计与监控维度口径见架构节点。

## 5. 产品自持声明要素（登记项类别） <a id="manifest"></a>

提供方在产品自持声明中按能力登记以下类别的要素（**字段名与文件结构归详细设计**，本节只列类别与必填性）：

| 要素类别 | 必填 | 说明 |
| --- | --- | --- |
| 能力名 | 是 | 全局唯一、语义化、与提供方实现标识解耦 |
| 访问面类别 | 是 | 契约读出口 / 内部写通道 / 事务参与分支 / 参考数据出口 / 业务语义要素集合 |
| 访问面位置 | 是 | 须能在对端公开契约中被定位（装载期校验） |
| 业务语义要素 | 按需 | 业务码 / 权限码 / 分支动作名 / 数据源标识 |
| 前端命名空间 | 按需 | 供前端按能力取址；domain 段由提供方自持 |
| 种子入口 | 按需 | 该能力实施所需默认数据种子的声明（平台统一调度执行） |
| 错误码（产品级，非按能力） | 按需 | 段位随服务行登记；码级要素为 `code` / `http_status` / `message_key` / `severity` / `description`，与能力不共用命名空间 |
| 契约版本 | 是 | 随提供方服务契约版本 |

## 6. 种子登记 <a id="seeds"></a>

| 提供方 | 种子 | 内容 | 执行方 | 状态 |
| --- | --- | --- | --- | --- |
| mdm | 管理面权限码种子 | 业务码 `mdm` + `mdm:query` / `create` / `update` / `delete`（部门移动复用 `update`） | platform 种子调度（按声明入口调用） | 设计已定（待收编） |

| # | 现状落点 | 现写法 | 目标 |

| 5 | 基座「租户恒开通模块」清单 | 模块标识字面量 | 由模块登记 + 「恒开通」属性声明（不写产品标识） |
| 6 | 平台权限码 / 菜单种子 | 产品业务码与权限码字面量 | 由产品种子声明、平台调度播种 |

| 9 | 前端产品寻址工具 | 产品键与domain 段字面量 | 同上 |
| 10 | 前端页面端点常量 | 产品命名空间字面量 | 同上 |
| 11 | 部署配置中的产品声明路径 | 指向具体产品仓 | 保持为部署配置（可接受），但改为「声明目录」而非单产品文件 |

## 8. 登记项 ↔ 既有机制对应 <a id="mapping-registry"></a>

协同层只增加「记录种类」，不增加「机制种类」（口径见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「与既有注册机制的统一口径」节）。对应关系：

| 登记形态 | 载体 | 视图 / 出口 | 校验 | 本专项 |
| --- | --- | --- | --- | --- |
| 产品档案 | 产品自持清单 `products` 段 | `product_catalog_view()`（平台 + 已装载产品合并） | `ops.check_modules` | 不变 |
| 服务行 | 清单 `services` 段；代码级 `service_records()` 自报 | `service_catalog_view()`；`/api/v1/modules/snapshot` | `ops.check_modules` | 不变 |
| 产品路由 | 清单 `product_routes` 段 | 网关生成物 + 目录快照 | `ops.gateway_config check` | 不变 |
| 数据源 | 清单 `data_sources` 段 | 数据源视图 | `ops.check_modules` + 契约校验 | 不变 |
| **能力（本专项新增，第五类）** | 清单 `collaboration` 段 | **与四类同一合并视图族**；**扩既有 `/api/v1/modules/snapshot`（不新开端点）** | **并入 `ops.check_modules`** | 新增 |
| 表归属 / 表单标识 | 代码级 `table_records()` / `form_records()` | 应用级视图 | `check_backend_base` / `ops.check_forms` | 不变 |
| 种子 | 清单种子段 + 既有 `seed_*` 种子族 | — | 执行结果逐项输出 | **并入 `seed_platform` 统一编排** |
| **租户拓扑（业务域 → 部署单元与库）** | 平台库表（运营期数据，发布时生效） | 拓扑解析视图（供能力寻址第二段） | 并入 `ops.check_modules` | 07C 专项 |
| **产品错误码（第七类记录）** | 产品清单 `errcodes` 段 | 与平台 `ErrorCode` 合并的 `码 → 定义` 视图（供渲染 / 手册导出） | 并入 `ops.check_modules` + 契约反向对账 | 新增 |
| **能力分配（授权记录）** | 产品清单默认消费方声明 → 平台库表落地（运营期可调整 / 撤销） | 分配视图（按消费方裁剪下发） | 并入 `ops.check_modules`；变更进审计链 | 新增 |

**通道分工判据**：需被**其他进程**消费（能力、注册要素）→ 文件级（部署期装载、跨进程可读）；仅进程内自报身份（表归属、表单标识）→ 代码级。能力声明**恒走文件级**，消费方不得依赖提供方实现。

## 9. 维护规则 <a id="maintain"></a>

- 新增能力：提供方在自持声明中登记 → 平台装载校验通过 → 在本清单 §2 增行并在 §3 登记消费方 → 消费方改为按能力名取用。
- 能力改名 / 下线：按《架构设计 · 跨产品协同》「契约版本与兼容」节走弃用期，本清单同步标注「弃用（替代能力）」，过渡期结束后移除。
- 禁入项：本清单不得出现具体产品的表结构、字段级定义与代码片段；那些归详细设计与数据库设计。
- 机器护栏：平台源码 / 平台种子中的产品标识由 engkit 通用规则拦截；本清单与产品声明的对账由预检步骤校验。
