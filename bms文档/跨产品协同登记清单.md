## 1. 定位与分工 <a id="position"></a>

- **语义**（能力是什么、谁声明、成败语义、红线）见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》，本清单**不重复**。
- **本清单登记**：有哪些跨产品能力、由谁提供、谁在消费、访问面与业务语义要素落在哪、契约版本、收编状态。
- **不在本清单**：后端基类 / 继承链 / 代码落点 → 《[后端基类清单](后端基类清单.md)》；前端链层 / 能力 / 落点 → 《[前端基类清单](前端基类清单.md)》；具体实现做法与字段级结构 → 任务详细设计。
- **单一权威**：能力的**声明源在产品仓**（产品自持声明）；本清单是平台侧**登记视图**，用于跨仓对账与收编跟踪，不代替产品声明。

## 4. 能力分配登记 <a id="assignment"></a>

分配是平台对「能力 × 消费方」的授权记录，粒度能力级；**有有效分配即合法（直连或经平台中转均可），无分配即越界**（口径见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「能力分配与授权」节）。

**两层**：产品自持声明写「默认允许谁消费」，平台装载后落分配记录（运营期数据，可调整 / 撤销并留审计）。

| 能力 | 默认消费方（产品声明） | 状态 |
| --- | --- | --- |
| `mdm.org.user-roles` | platform | 已装载落库（`source=declared`，随启动钩子同步；`02_04`） |
| `mdm.org.user-*` / `mdm.org.role-*.assign` | platform | 同上 |
| `mdm.org.dept-data` / `mdm.org.post-data` | platform（前端可见性由能力快照下发决定，前端不参与分配） | 同上 |
| `platform.user.query` / `platform.permission.invalidate` / `platform.config.snapshot` | mdm（`config.snapshot` 另含 identity） | 设计已定（随 `03_01` 声明） |

> 当前**无**产品间直连分配。后续出现产品间调用时，须在此登记默认消费方，并由平台落为分配记录；未登记即按越界拦截（**不设独立于分配的「直连许可」维度**——有分配则直连与中转都合法）。分配调整 / 撤销的审计与监控维度口径见架构节点。

## 5. 产品自持声明要素（登记项类别） <a id="manifest"></a>

提供方在产品自持声明中按能力登记以下类别的要素（**字段名与文件结构归详细设计**，本节只列类别与必填性）：

**清单结构（2026-10-26 落地）**：产品自持声明为 **toml 单文件六段**——`products` / `services` / `product_routes` / `data_sources` / `collaborations`（能力，第五类）/ `seeds`（种子，第六类）；字段级定义见[《02_01 详细设计》](项目/07B_跨产品协同/任务/02_协同基座/02_协同基座_01_声明toml化与装载校验/设计/01_详细设计_02_声明toml化与装载校验.md) §3.1。装载期六类校验（能力重名 / 提供方业务域 / 归属一致 / 访问面契约定位 / 契约版本兼容 / 种子入口可解析）并入既有 `ops.check_modules`，任一不满足即拒启；mdm 已按此切换（`deploy/registry/mdm.toml`）。

| 要素类别 | 必填 | 说明 |
| --- | --- | --- |
| 能力名 | 是 | 全局唯一、语义化、与提供方实现标识解耦 |
| 访问面类别 | 是 | 契约读出口 / 内部写通道 / 事务参与分支 / 参考数据出口 / 业务语义要素集合 |
| 访问面位置 | 是 | 须能在对端公开契约中被定位（装载期校验） |
| 业务语义要素 | 按需 | 业务码 / 权限码 / 分支动作名 / 数据源标识 |
| 前端命名空间 | 按需 | 供前端按能力取址；domain 段由提供方自持 |
| 种子入口 | 按需 | 该能力实施所需默认数据种子的声明（平台统一调度执行） |
| 错误码（产品级，非按能力） | 按需 | 段位随服务行登记；码级要素为 `code` / `http_status` / `message_key` / `severity` / `description`，与能力不共用命名空间 |
| 契约版本 | 是 | 随提供方服务契约版本 |

## 6. 种子登记 <a id="seeds"></a>

## 8. 登记项 ↔ 既有机制对应 <a id="mapping-registry"></a>

协同层只增加「记录种类」，不增加「机制种类」（口径见《[架构设计 · 跨产品协同](设计/架构设计/38_架构设计_子系统_跨产品协同.md)》「与既有注册机制的统一口径」节）。对应关系：

| 登记形态 | 载体 | 视图 / 出口 | 校验 | 本专项 |
| --- | --- | --- | --- | --- |
| 产品档案 | 产品自持清单 `products` 段 | `product_catalog_view()`（平台 + 已装载产品合并） | `ops.check_modules` | 不变 |
| 服务行 | 清单 `services` 段；代码级 `service_records()` 自报 | `service_catalog_view()`；`/api/v1/modules/snapshot` | `ops.check_modules` | 不变 |
| 产品路由 | 清单 `product_routes` 段 | 网关生成物 + 目录快照 | `ops.gateway_config check` | 不变 |
| 数据源 | 清单 `data_sources` 段 | 数据源视图 | `ops.check_modules` + 契约校验 | 不变 |
| **能力（本专项新增，第五类）** | 清单 `collaborations` 段 | **与四类同一合并视图族**；取用单点入口 `resolve_capability()`；**扩既有 `/api/v1/modules/snapshot`（不新开端点）** | **并入 `ops.check_modules`** + 装载期消费方声明校验 | **已落地**：记录 / 视图 / 六类校验（`02_01`）；取用入口 / 三档失败语义 / 快照 `?with=` 带参段（`02_02`） |
| 表归属 / 表单标识 | 代码级 `table_records()` / `form_records()` | 应用级视图 | `check_backend_base` / `ops.check_forms` | 不变 |
| 种子 | **平台 `deploy/registry/platform.toml` + 产品 `deploy/registry/*.toml`（同一形态）** | `seed_catalog_view()`（平台 + 产品合并视图） | `ops.check_modules`（新字段 / 前缀 / 重名 / `after` / `db_key`）+ 事务前冲突预检 | **声明与入口校验已落地（`02_01`）；统一装载与 XA 编排归 `02_03`** |
| **租户拓扑（业务域 → 部署单元与库）** | 平台库表（运营期数据，发布时生效） | 拓扑解析视图（供能力寻址第二段） | 并入 `ops.check_modules` | **第二段协议与过渡实现已落地（`02_02`）**：业务域 → 承载服务键由域布局派生、未登记即拒启；真实租户拓扑归 07C 专项 |
| **产品错误码（第七类记录）** | 产品清单 `errcodes` 段 | 与平台 `ErrorCode` 合并的 `码 → 定义` 视图（供渲染 / 手册导出） | 并入 `ops.check_modules` + 契约反向对账 | **已落地（`02_05`）**：记录 / 视图 / 三类校验 + 统一渲染单点 + `ops.export_errcodes` 手册导出；mdm 已声明 25 条，端点补 `x-error-codes` 与全量强校验归 `04_02` |
| **能力分配（授权记录）** | 产品清单 `collaborations[].default_consumers` → 平台库表 `sys_capability_grant`（运营期可调整 / 撤销） | 授权视图：出站 scope 派生 `svc:{业务域}:{read\|write}`、入站 `require_capability()`、内部出口 `/api/v1/platform/internal/capability-grants` | 装载期消费方声明校验（`02_01`）+ 入库前同判据校验；状态变更经 `AuditCapturer.capture`（占位，真实落库归 29-审计合规） | **已落地（`02_04`）**：表 / 模型 / 派生 / 管理面三端点 / 启动钩子同步；端点接线与字面量清理归 `03_01` |

**通道分工判据**：需被**其他进程**消费（能力、注册要素）→ 文件级（部署期装载、跨进程可读）；仅进程内自报身份（表归属、表单标识）→ 代码级。能力声明**恒走文件级**，消费方不得依赖提供方实现。

## 9. 维护规则 <a id="maintain"></a>

- 新增能力：提供方在自持声明中登记 → 平台装载校验通过 → 在本清单 §2 增行并在 §3 登记消费方 → 消费方改为按能力名取用。
- 能力改名 / 下线：按《架构设计 · 跨产品协同》「契约版本与兼容」节走弃用期，本清单同步标注「弃用（替代能力）」，过渡期结束后移除。
- 禁入项：本清单不得出现具体产品的表结构、字段级定义与代码片段；那些归详细设计与数据库设计。
- 机器护栏：平台源码 / 平台种子中的产品标识由 engkit 通用规则拦截；本清单与产品声明的对账由预检步骤校验。
