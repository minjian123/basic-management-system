# 后端审计规范

> 后端合规审计：基座继承链 · 横切件 · 模块边界 · 契约 · 清单对账 · 错误码与事件名 · 流程与报告

## 1. 目的与适用范围 <a id="purpose"></a>

规范**后端**（`backend/`，FastAPI）的**合规审计**：以「机器护栏 + 脚本盘点 + 人工判定」对已交付的后端代码与后端文档做结构性核验，并按「修复 → 回写 → 护栏沉淀 → 复跑」闭环。流程与报告口径与《[前端审计规范](前端审计规范.md)》**同一套**（审计 ≠ 测试：测试查「行为正确」见《[测试规范](测试规范.md)》）。

审计细则**引用式**：《[后端开发规范](后端开发规范.md)》§2（目录与分层职责）/ §3（后端基座体系）与《[后端基类清单](../后端基类清单.md)》为唯一口径来源（含护栏、用例与落点登记），本规范不重复定义、不列具体实现物明细；检查维度见 §5 与附录。

## 2. 审计类型 <a id="types"></a>

| 类型 | 内容 | 主要依据 |
| --- | --- | --- |
| **合规审计**（默认） | 基座继承链（根系 根基类 / 集合体系 / 模块基类 / core 横切）、横切件挂接、模块边界与依赖方向、契约套件、清单对账、命名与错误码段位、事件名与主题 | 《[后端开发规范](后端开发规范.md)》§2 / §3、《[后端基类清单](../后端基类清单.md)》、《[命名规范](命名规范.md)》、《[API接口规范](API接口规范.md)》 |
| 安全审计（后端侧） | 敏感操作审计日志留痕、密钥与配置、权限判定链、依赖漏洞 | 《[安全开发规范](安全开发规范.md)》 |
| 性能审计 | 数据库索引与查询、缓存策略、N+1 与分页、任务与定时 | 《[数据库开发规范](数据库开发规范.md)》、平台《架构设计》性能节 |
| 文档审计（后端） | 后端任务目录 / 命名 / 链接自洽 / 基座文档清单一致 | 《[文档生成规范](文档生成规范.md)》、《[命名规范](命名规范.md)》 |

> 一次审计可覆盖多类型；默认指合规审计。

## 3. 触发时机 <a id="trigger"></a>

1. **阶段收口前（默认）**：阶段内后端交付（基座 / 插件 / 业务模块等）收口时执行一次后端合规审计，结论作为收口门禁项之一（与测试报告并列）；
2. **按需**：用户 / 评审要求时；重大重构、分层调整、批量模块交付后；
3. **例外**：纯文档改动或单点修复可不触发（在阶段收口时合并执行）。

## 4. 审计流程 <a id="flow"></a>

```mermaid
flowchart LR
    A["触发（§3）"] --> B["范围界定（对象清单 + 排除项）"]
    B --> C["方法：护栏复跑 + 脚本盘点 + 人工判定"]
    C --> D["问题分级（§7）"]
    D --> E["修复（偏差回写设计后改）"]
    E --> F["回写（设计 / 实施 / 规范 / 计划）"]
    F --> G["护栏沉淀（§8：机器护栏或白名单）"]
    G --> H["复跑（后端测试门禁 + 脚本复核零违规）"]
    H --> I["报告（§6）+ 索引登记"]
```

- **范围界定**：列明审计对象清单与**排除项**（如迁移脚本 / 本地开发工具不适用模块基类强制），排除必须写明理由；
- **方法三件套**：① 护栏复跑（横切件、契约与基类用例，落点见《[后端基类清单](../后端基类清单.md)》）；② 脚本盘点（全量文件级检查，结论可复算）；③ 人工判定（语义项逐处记录依据）；
- **治理协作**：审计结论与度量随治理脚本采集（口径与落点见《[项目管理规范](项目管理规范.md)》），阶段复盘引用；
- **修复原则**：违规必修；修改前**回写设计/规范**（偏差回写口径同《[AI开发规范](AI开发规范.md)》）。

## 6. 报告规范 <a id="report"></a>

| 项 | 约定 |
| --- | --- |
| 落点 | 阶段级审计报告放 `项目/<阶段>/审计/`；**审计资产台账与跨阶段审计文档一律放 `bms文档/审计/`**（后端见《[后端资产清单](../审计/02_审计_后端资产清单.md)》） |
| 命名 | `<NN>_审计_<主题>.md`（`NN` 两位序号） |
| 结构 | ① 审计信息（日期 / 人 / 触发 / 范围与排除 / 依据 / 方法 / 结论）；② 结果逐项（B1 ~ B10 × 审计点 × 结果）；③ 违规与修复（位置 / 修复 / 回写）；④ 分级处置；⑤ 护栏补强；⑥ 复跑证据（后端门禁命令与结果）；⑦ 遗留与去向 |
| 索引 | 报告在所属阶段 README「文档索引」登记一行；阶段收口回写时引用结论 |
| 入库 | 报告与证据随仓库提交；本地覆盖率产物（`.coverage` / `coverage/`）不入库（口径见《[项目管理规范](项目管理规范.md)》阶段复盘节） |

## 7. 问题分级与处理 <a id="grade"></a>

| 分级 | 判定 | 处理 |
| --- | --- | --- |
| **违规** | 违反《[后端开发规范](后端开发规范.md)》**强制口径**（绕过基类、越层依赖、错误码自造段位、敏感操作无审计日志等） | **必修**（回写设计后修复 + 护栏拦截同类） |
| **偏离** | 与参考口径 / 设计节点不一致但非强制 | 评估修复或**登记去向**（设计对齐记录 + 计划 §3.1） |
| **机会项** | 优化空间（索引 / 缓存 / 查询合并等） | 登记计划 §3.1（明确归口与时点） |
| **白名单** | 结构性常量豁免（协议常量 / 方言分支写法 / 迁移脚本本地方言等） | 写入本规范或《[后端开发规范](后端开发规范.md)》豁免节；首次审计时定义 |

## 8. 护栏沉淀（强制） <a id="guard"></a>

- 审计修复的**每一类违规**必须沉淀为机器护栏（新用例或扩大既有扫描面），随 CI 后端测试 job 执行；
- 护栏需配 **fixture 拦截用例**（构造违规样例断言被拦），与正向用例成对；
- 暂无法机器化的检查项（如事件名语义）在报告中标注「人工项」，下次审计复跑时复核；
- 护栏与白名单口径变更须同步《[后端开发规范](后端开发规范.md)》与历次审计报告（报告只增不改）。
