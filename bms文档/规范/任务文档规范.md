# 任务文档规范

> 任务文档格式契约 · 任务内容与需求关联（进度归计划表）

[文档首页](../文档首页.md) › 规范 › 任务文档规范　|　[同级：需求文档规范 →](需求文档规范.md)　[计划文档规范 →](计划文档规范.md)　|　[关联：项目管理规范 →](项目管理规范.md)

## 1. 目的与适用范围 <a id="purpose"></a>

本规范定义**任务文档**（父任务/域总览 + 子任务文档 + 任务附属文档：任务级设计、测试记录、实施记录）的固定格式，是项目任务的**统一契约**：文档即任务登记载体，承载「做什么 / 完成标准 / 需求关联」；**进度（工时 / 状态 / 完成日期 / 排期）不落任务文档，唯一落点为阶段计划文档**（《[计划文档规范](计划文档规范.md)》「排期唯一落点与边界」节）。

- 适用于 `bms文档/项目/{阶段}/任务/` 下全部任务文档（阶段0 准备期、阶段一 项目骨架已按本规范编写）。
- 本规范只约束**文档怎么写**；管理口径（主题命名、描述三段式、父任务、负责人、进度口径）以《[项目管理规范](项目管理规范.md)》为准，两者配套。
- **强制契约**：任务文档必须符合本规范规定格式；字段缺失、行格式不符即为不合格文档，需修正后方可进入阶段验收。
- 与《[文档生成规范](文档生成规范.md)》、《[需求文档规范](需求文档规范.md)》同时适用。

## 2. 文件组织 <a id="files"></a>

一个阶段的任务文档按「**需求域文件夹 → 任务 → 子任务…**」组织，**任务目录可递归嵌套**（与需求域一一对应，层级不限）：

```text
任务/
├── {NN}_{域名}/                            # 需求域文件夹（与需求域一一对应，按需求对照分类）
│   ├── {NN}_{域名}.md                      # 父任务/域总览：父任务信息 + 子任务清单
│   │   └── 例：01_环境与工具链/01_环境与工具链.md
│   ├── {NN}_{域名}_{序号}_{任务名}/         # 子任务目录（一级任务）：一条任务一目录
│   │   ├── {NN}_{域名}_{序号}_{任务名}.md   # 子任务文档（与目录同名）
│   │   │   └── 例：01_环境与工具链/01_环境与工具链_05_备份体系/01_环境与工具链_05_备份体系.md
│   │   ├── 设计/                           # 任务级详细设计（可选，可多份）
│   │   │   └── 例：05_详细设计_01_备份体系.md  # {本层级序号}_详细设计_{设计序号}_{任务名}
│   │   ├── 测试/                           # 任务测试记录（可选，可多份）
│   │   │   └── 例：05_测试_01_备份体系.md      # {本层级序号}_测试_{测试序号}_{任务名}
│   │   ├── 实施/                           # 任务实施记录（任务完成后生成）
│   │   │   └── 例：05_实施_01_备份体系.md      # {本层级序号}_实施_{实施序号}_{任务名}
│   │   └── {父目录名}_{序号}_{子任务名}/    # 嵌套子任务（可再嵌套，依次后缀）
│   │       ├── {同目录名}.md                # 嵌套任务文档（与目录同名）
│   │       ├── 设计/ 测试/ 实施/            # 与上级同构，按需创建
│   │       └── …                           # 更深层级同理
└── {NN}_{域名}/                            # 下一个需求域（同构）
```

- 域编号两位（`01`/`02`/`03`…），与需求编号前缀、WBS 域对应；**需求域文件夹 `{NN}_{域名}/` 与其下域总览 `{NN}_{域名}.md` 同名**，域总览与全部子任务目录一律收拢在域文件夹内，按需求域对照分类。
- 子任务目录名与其内子任务文档同名（含**序号**与**任务名**）；域号已由前缀 `{NN}_{域名}` 承载，序号不重复域号。
- **嵌套子任务**：目录名/文档名 = 父级目录名（或父任务文档名）后缀 `_{序号}_{子任务名}`；序号在**本层级内**从 `01` 起且唯一；层级不限、依次后缀，每级结构相同（均可含 `设计/ 测试/ 实施/` 与更深子任务）。
- 设计/测试/实施文档名中的**序号**为该任务内同类型文档的顺序号，从 `01` 起（与任务序号区分，如任务 02 的首份设计为 `02_详细设计_01_{任务名}.md`）；嵌套任务文档不重复上级前缀，序号取**本任务在其父级下的序号**（如 01-3-1 的设计为 `01_详细设计_01_基础类.md`，位于其任务目录内）。
- 父任务（域总览）映射 WBS 父级（域级任务），收拢于域文件夹 `{NN}_{域名}/`；子任务目录映射 WBS 子任务；嵌套子任务映射 WBS 更深拆解。
- `设计/`、`测试/`、`实施/` 为任务附属目录，仅在对应产物存在时创建，不建空目录。

## 3. 父任务/域总览文档格式 <a id="parent"></a>

父任务文档固定章节：

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 域说明 | `## 1. 域说明` | `intro` | 对应 WBS 域、覆盖范围、依据 |
| 子任务清单 | `## 2. 子任务清单` | `list` | 本域全部子任务汇总表（下表） |
| 依赖与风险 | `## 3. 依赖与风险` | `dep` | 关键依赖与风险（不含工时 / 排期） |

**子任务清单表**列固定为（顺序不可变）：

```markdown
| 编号 | 任务 | 任务文件 |
| --- | --- | --- |
| 01 | mjbk Ubuntu 基础 | 01_环境与工具链_01_mjbk_Ubuntu基础/01_环境与工具链_01_mjbk_Ubuntu基础.md |
| 05 | 备份体系 | 01_环境与工具链_05_备份体系/01_环境与工具链_05_备份体系.md |
```

- **编号**：`{序号两位}`（域内唯一），与需求编号的序号、文件名序号一致；主键为「域号 + 序号」。
- **任务**：任务名，与子任务文档标题一致。
- **任务文件**：相对链接，指向子任务文档。
- **进度不在此表**：工时 / 状态 / 完成日期只在阶段计划表维护（见第 7 节），本表不设这些列。

**嵌套任务的子任务清单**：任务下含嵌套子任务时，其任务文档在「任务信息」表后增加 `## 2. 子任务清单 <a id="list"></a>` 章节（表列与上表相同，编号/文件引用相对本任务），其后章节顺延。如此任务可随时附加子任务，不依赖既有序号连续性。

## 4. 子任务文档格式（核心结构单元） <a id="task"></a>

### 4.1 任务信息表 <a id="meta"></a>

子任务文档以「任务信息」表承载全部可解析字段，表结构固定：

```markdown
# 01-5 备份体系

## 1. 任务信息 <a id="meta"></a>

| 项 | 值 |
| --- | --- |
| 编号 | 01-5 |
| 父任务 | 01_环境与工具链.md |
| 对应需求 | 01-5 |
| 依赖 | 01-1（机械盘）、01-3（三库）、02-1（GitLab） |
| 负责人 | minjian |
```

**字段契约**：

| 项（固定） | 值格式 | 说明 |
| --- | --- | --- |
| 编号 | `{序号两位}`（域内唯一）；嵌套任务链式 `{域}-{父序号}-{本序号}`（如 `01-3-1`） | 任务主键，与文件名、清单表一致；跨域引用写 `{域号}_{序号}` |
| 父任务 | `[父任务名](父任务文件)` | 映射 WBS 父级；子任务必填 |
| 对应需求 | `[需求编号](需求文件#r{编号})` | 关联需求，用于互链 |
| 依赖 | `{序号}（{说明}）、…`（域内）；跨域 `{域号}_{序号}` | 前置任务编号（人读；排期与依赖以计划表为准） |
| 负责人 | `{账号}` | 当前一律 `minjian` |

> 本表**不承载进度**：工时 / 状态 / 完成日期只在阶段计划表维护（见第 7 节），任务正文其它位置同样不作进度记录。

### 4.2 任务正文 <a id="content"></a>

「任务信息」表之后固定三节，对应描述三段式（《项目管理规范》「描述三段式模板」节）：

| 章节 | 标题（固定） | 锚点 | 说明 |
| --- | --- | --- | --- |
| 任务内容 | `## 2. 任务内容` | `content` | 「内容」段（编号清单） |
| 完成标准 | `## 3. 完成标准` | `accept` | 「完成标准」段 |
| 参考文档 | `## 4. 参考文档` | `ref` | 「参考文档」段 |

```markdown
## 2. 任务内容 <a id="content"></a>

1. 三库：cron 每日 02:00 dump 至备份目录（按库分子目录），保留 7 天
2. GitLab：容器内 `gitlab-backup` 每日执行，落备份目录

## 3. 完成标准 <a id="accept"></a>

各备份文件按期生成；至少完成一次从备份恢复的验证。

## 4. 参考文档 <a id="ref"></a>

- 《开发部署规划》「备份与恢复」节
```

### 4.3 章节顺序 <a id="order"></a>

子任务文档元素顺序固定：`# 标题 → ## 1. 任务信息（表）→ ## 2. 任务内容 → ## 3. 完成标准 → ## 4. 参考文档`；含嵌套子任务时，在「任务信息」后插入 `## 2. 子任务清单`，其后章节顺延（任务内容 3 / 完成标准 4 / 参考文档 5）。

## 5. 实施文档（任务执行记录） <a id="impl"></a>

子任务完成后，在任务目录 `实施/` 下生成实施记录（命名 `{任务序号}_实施_{实施序号}_{任务名}.md`，实施序号从 `01` 起），记录**实际实施过程**：做了什么、怎么做的、遇到什么问题、如何处置、验证结果与偏差遗留。实施文档是任务执行的事实留痕，供复盘与后续任务复用。

**固定章节**（顺序不可变）：

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 实施信息 | `## 1. 实施信息` | `meta` | 固定字段表（见下） |
| 实施概览 | `## 2. 实施概览` | `overview` | 步骤总览（逻辑关系可用 mermaid）+ 结果小结 |
| 实施过程 | `## 3. 实施过程` | `process` | 按步骤记动作、关键命令与结果 |
| 问题与处置 | `## 4. 问题与处置` | `issues` | 问题/现象、原因、处置与落点 |
| 验证结果 | `## 5. 验证结果` | `verify` | 对照完成标准的验证方法与实测结果 |
| 偏差与遗留 | `## 6. 偏差与遗留` | `deviations` | 与设计的偏差、未决项与后续动作 |

**实施信息表**字段固定（缺省 `—`）：任务 / 对应需求 / 详细设计 / 实施日期 / 实施人 / 实施环境 / 提交 / 结论。

口径：

- 只记**事实**：命令、版本、路径、结果按实际记录（涉及工具/版本先核实），禁止编造。
- 实施过程含关键命令与输出摘要，保证可复现；失败与返工同样记录。
- 不写修订记录（《文档生成规范》「修订记录约定」节），修订由 git 承载；本机私有信息（账号、内网地址等）不入库。

## 6. 测试文档（任务测试记录） <a id="test"></a>

任务完成自动化/冒烟测试（或专项测试）后，在任务目录 `测试/` 下生成测试记录（命名 `{任务序号}_测试_{测试序号}_{任务名}.md`，测试序号从 `01` 起），记录**测试范围、用例与执行结果、问题与覆盖率**。与《[测试规范](测试规范.md)》配套：用例先登记 Kiwi TCMS、后写自动化代码；测试记录只做任务级留痕，不替代 Kiwi 用例库与阶段测试报告。

**固定章节**（顺序不可变）：

| 章节 | 标题（固定） | 锚点 | 内容 |
| --- | --- | --- | --- |
| 测试信息 | `## 1. 测试信息` | `meta` | 固定字段表（见下） |
| 测试范围与用例 | `## 2. 测试范围与用例` | `scope` | 本任务测试范围、用例清单（Kiwi ID / 类型 / 自动化文件） |
| 执行记录与结果 | `## 3. 执行记录与结果` | `run` | 命令与输出摘要、接口/手工验证、结果汇总 |
| 问题与处置 | `## 4. 问题与处置` | `issues` | 测试过程问题、原因、处置与落点 |
| 覆盖率 | `## 5. 覆盖率` | `coverage` | 覆盖率快照与门禁口径 |
| 偏差与遗留 | `## 6. 偏差与遗留` | `deviations` | 未覆盖项、后续任务接收项 |

**测试信息表**字段固定（缺省 `—`）：任务 / 对应需求 / 详细设计 / 实施记录 / 测试日期 / 测试人 / 测试环境 / Kiwi 用例 / 结论。

口径：

- 用例**先登记 Kiwi TCMS 再写代码**（《测试规范》§5），自动化用例以 `kiwi_id` 标注关联；测试记录中的用例清单须含 Kiwi 编号。
- 执行结果记实（命令、输出摘要、端点状态码等），失败与返工同样记录；覆盖率只作任务内快照，门禁阈值以《测试规范》§6 与流水线为准。
- 不写修订记录（《文档生成规范》「修订记录约定」节）；本机私有信息（账号、内网地址等）不入库。

## 7. 进度口径 <a id="status"></a>

任务文档**不承载进度**：不设工时、状态、完成日期与排期字段，也不承载验收结论与证据。

- **进度唯一落点**：阶段计划文档（已完成任务表 / 剩余任务排期表）；状态取值与工时、完成日期、排期窗口口径见《[计划文档规范](计划文档规范.md)》与《[项目管理规范](项目管理规范.md)》「进度口径」节。
- **依赖与风险**：任务文档可在「依赖与风险」节写关键依赖与风险（语义描述），排期事实以计划表为准。
- 任务确需标注「搁置」等处置时，在「任务内容」或 `> 注` 中说明，**不引入进度字段**。

## 8. 检查清单 <a id="checklist"></a>

- □ 需求域文件夹 `{NN}_{域名}/` 与其下域总览 `{NN}_{域名}.md`、子任务 `{NN}_{域名}_{序号}_{任务名}.md` 命名一致，任务全部收拢于对应域文件夹
- □ 子任务清单表三列表头与顺序正确，编号唯一且与文件名一致
- □ 子任务「任务信息」表五项齐全（编号/父任务/对应需求/依赖/负责人）
- □ 任务内容/完成标准/参考文档三节齐备，对应描述三段式
- □ 任务文档无工时 / 状态 / 完成日期 / 排期字段（进度见阶段计划表）
- □ 有自动化/冒烟测试的任务在 `测试/` 下生成测试记录，第 6 节固定章节齐备、用例含 Kiwi 编号
- □ 任务完成后在 `实施/` 下生成实施记录，第 5 节固定章节齐备
- □ 嵌套子任务按「父名_序号_子任务名」递归命名，序号本层级唯一；含嵌套子任务的任务文档有「子任务清单」节（进度并入其父任务行，见阶段计划表）
