# 帮助包规范

> 产品帮助包（`help/*.yaml`）的格式、装载与版本约定

[文档首页](../文档首页.md) › 规范 › 帮助包规范　|　[同级：文档生成规范 →](文档生成规范.md)　[架构节点：28-帮助中心 →](../设计/架构设计/28_架构设计_子系统_帮助中心.md)

## 1. 目的与适用范围 <a id="purpose"></a>

统一「产品如何随包提供帮助内容」的格式与装载语义，使帮助中心从「后台逐篇人工录入」变成**可装载、可升级、可卸载、可对账**的机制面。适用于平台内建帮助与全部产品仓（biz / mdm / cw 等）；与《[文档生成规范](文档生成规范.md)》《[命名规范](命名规范.md)》《[国际化规范](国际化规范.md)》配套使用。

- 上游语义：架构 28 §3.3（帮助包与装载注册）、§3.4（锚点声明与覆盖率门禁）。
- 本规范只管**包的形状与装载规则**；帮助内容的写作口径（语气、结构、截图约定）另见产品侧写作指引，不在本规范。

## 2. 文件组织 <a id="files"></a>

```text
{产品仓}/
└── help/
    ├── package.yaml              # 包清单（唯一入口；装载器只认这个文件名）
    ├── categories.yaml           # 分类树（可选；也可内联在 package.yaml）
    ├── articles/                 # 文章正文（一篇一文件，便于评审与 diff）
    │   ├── user-create.yaml
    │   ├── role-assign.yaml
    │   └── …
    └── assets/                   # 截图等静态资源（可选，随包上传对象存储）
```

- 装载器**只读 `help/package.yaml`**，其余文件由包清单的 `includes` 引用，避免目录扫描带来的不确定性。
- 文件名用 kebab-case（《[命名规范](命名规范.md)》）；一篇一文件，便于代码评审时看清单篇改动。

## 3. 包清单 <a id="manifest"></a>

```yaml
schema_version: 1                 # 包格式版本；不兼容变更才升
product_key: bms                  # 与 sys_module 的产品键一致（bms / biz / mdm / cw）
package_version: 1.4.0            # 语义化版本；升级比对与幂等键的组成部分
generated_at: 2026-10-31T09:00:00Z
checksum: sha256:9f2c…            # 装载器校验用（覆盖 package.yaml + includes 全文）
includes:
  categories: categories.yaml
  articles:
    - articles/user-create.yaml
    - articles/role-assign.yaml
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 包格式版本，当前 `1`；装载器拒收不认识的版本 |
| `product_key` | 是 | 产品键，决定卸载粒度（按产品清理）与冲突优先级 |
| `package_version` | 是 | 语义化版本；同版本重复装载为幂等空操作 |
| `checksum` | 是 | `sha256:` 前缀；与实际内容不符即拒收（防止半成品包被装载） |
| `includes` | 是 | 显式列出被引用文件；装载器不扫描目录 |

## 4. 分类定义 <a id="categories"></a>

```yaml
categories:
  - path: 快速上手
    sort: 10
  - path: 快速上手/首次登录
    sort: 11
```

- `path` 用 `/` 分隔，**父级必须先出现**；装载器按路径逐级 upsert，不依赖数据库 ID（跨环境可移植）。
- `sort` 十进制整数，同级内排序；缺省按出现顺序。
- 分类已存在时只更新 `sort`，**不改其下已有文章**（分类是弱归属）。

## 5. 文章定义 <a id="articles"></a>

```yaml
source_key: bms.user.create          # 包内稳定键（升级比对主键），一经发布不得修改
title: 新建用户
category_path: 系统管理/用户与角色
status: published                    # draft / published / offline
is_top: false
targets:                             # 锚点（可多个）；解析优先级见架构 28 §4.2
  - type: module
    key: platform.user
  - type: form
    key: sys_user
  - type: action
    key: user:create
locales:
  zh-CN:
    title: 新建用户
    content: |
      <h2>适用场景</h2><p>…</p>
  en-US:
    title: Create user
    content: |
      <h2>When to use</h2><p>…</p>
provenance:                          # 内容来源留痕（人工 / AI 生成）
  author: manual                     # manual / ai
  model: ""                          # ai 生成时必填（如 claude-sonnet-4.5）
  reviewed_by: ""                    # ai 生成时必须有人工审核人
```

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `source_key` | 是 | 格式 `{product_key}.{模块}.{对象}.{动作}`，小写点分；**发布后不可改**（改键等于删旧增新） |
| `category_path` | 是 | 必须能在 `categories` 或既有分类中解析 |
| `status` | 是 | 包内只允许 `published` / `offline`；`draft` 不作为包内容发布（草稿属本地编辑） |
| `targets[]` | 是（至少 1） | `type` ∈ `global` / `module` / `form` / `field` / `action`；`key` 必须是已登记的锚点（见 §6） |
| `locales{}` | 是 | 至少含默认语言；`content` 为 HTML（富文本白名单见《[安全开发规范](安全开发规范.md)》），Markdown 在生成阶段转 HTML |
| `provenance` | 是 | `author=ai` 时 `model` 与 `reviewed_by` 必填，缺一即拒收 |

## 6. 锚点引用规则 <a id="anchors"></a>

- 锚点是**元数据上的声明**（`sys_menu` / `sys_form` / `sys_field` / `sys_action` 的 `help_key`），包只**引用**，不创建。
- `targets[].key` 必须能被装载器解析到具体元数据记录；解析不到 → 该篇拒收并报 `40008`（锚点不可解析），整包按 `--strict` 决定拒绝或跳过。
- 覆盖率对账：CI 用「有权限码的动作 / 菜单」减「已声明 `help_key` 的动作 / 菜单」得差集台账，按产品与模块分组输出（见架构 28 §3.4）。

## 7. 装载、升级与卸载语义 <a id="lifecycle"></a>

| 动作 | 语义 |
| --- | --- |
| 首次装载 | 按 `source_key` 新增；登记 `sys_help_package`（product_key / version / checksum / 条数） |
| 升级（同 `source_key`） | 更新内容；**`local_override=true` 的文章跳过**（租户编辑优先）；`package_version` 更新 |
| 包内移除 | 该 `source_key` 标 `offline`，**不物理删**（可恢复、留审计）；再次出现则恢复 `published` |
| 卸载 | 按 `product_key` 把该包全部来源文章标 `offline`；租户自建（`source=manual`）不受影响 |
| 幂等 | 幂等键 `(product_key, source_key, package_version)`；同版本重复装载不产生任何变更 |
| 冲突 | 同一锚点命中多篇时按来源优先级 `builtin > product > tenant`；产品包不得覆盖平台内建同 target 文章（跳过并告警） |

- 装载前必须 `--dry-run`（平台侧默认要求）：输出将新增 / 更新 / 下线 / 跳过（`local_override`）的条数，确认后再落库。
- 装载与卸载需 `help:package` 权限；动作落操作日志，内容变更落字段级审计。

## 8. 校验与门禁 <a id="check"></a>

| 层级 | 校验 | 失败处理 |
| --- | --- | --- |
| 包结构 | `schema_version` / 必填字段 / `includes` 文件存在 | 拒收整包 |
| 完整性 | `checksum` 与实际内容一致 | 拒收整包 |
| 内容 | HTML 白名单清洗、正文非空、`locales` 含默认语言 | 该篇拒收 |
| 锚点 | `targets[].key` 可解析（见 §6） | `40008`，按 `--strict` 拒整包或跳过该篇 |
| 覆盖率 | 「有权限码但无 `help_key`」的动作 / 菜单 | 输出台账，默认不阻断、强档阻断 |

- 产品仓 CI 至少跑「包结构 + 完整性 + 内容」三层；平台在装载时再跑「锚点 + 覆盖率」，两道都过才算可用。

## 9. 只读边界（重要） <a id="readonly"></a>

帮助包**只影响帮助内容**，不得携带任何改变系统行为的东西：

1. 不得声明或修改功能、权限、菜单、表单、字典、参数、路由——这些归各自的清单与装载通道。
2. 不得包含可执行代码、模板表达式、脚本片段；正文只允许静态 HTML + 受控图片资源。
3. 不得通过 `targets` 反向影响元数据（引用不存在的锚点只会被拒收，不会自动创建）。
4. AI 生成内容一律 `provenance.author=ai` + 人工审核人；未审核的 AI 内容不得进包（见架构 28 §7）。

## 10. 最小示例 <a id="example"></a>

```yaml
# help/package.yaml
schema_version: 1
product_key: bms
package_version: 0.1.0
checksum: sha256:0000…（按实际内容计算）
includes:
  categories: categories.yaml
  articles: [articles/user-create.yaml]
```

```yaml
# help/articles/user-create.yaml
source_key: bms.user.create
title: 新建用户
category_path: 系统管理/用户与角色
status: published
targets:
  - type: form
    key: sys_user
  - type: action
    key: user:create
locales:
  zh-CN:
    title: 新建用户
    content: "<h2>适用场景</h2><p>为新员工开通账号时使用。</p>"
provenance:
  author: manual
```

## 11. 检查清单 <a id="checklist"></a>

- [ ] `help/package.yaml` 的 `schema_version` / `product_key` / `package_version` / `checksum` / `includes` 齐备
- [ ] 每篇 `source_key` 唯一、格式合规、**未修改过已发布的键**
- [ ] `category_path` 均可解析，父级先出现
- [ ] 每篇至少一个 `targets`，且 `key` 均能在元数据中解析
- [ ] 每个 `locales` 至少含默认语言，正文为清洗后的 HTML
- [ ] `provenance` 齐备；`author=ai` 的有 `model` 与 `reviewed_by`
- [ ] 装载前已跑 `--dry-run` 并核对新增 / 更新 / 下线 / 跳过条数
- [ ] 覆盖率台账已生成，缺失项登记到对应产品的待补清单
