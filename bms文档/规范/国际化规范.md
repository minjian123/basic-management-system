# 国际化规范

> i18n 键管理 · 语言包 · 文案约定

## 1. 目的与适用范围 <a id="purpose"></a>

规范本项目前后端的国际化（i18n）组织方式：key 命名、语言包管理、文案约定与多语言数据。
与平台《概要设计 29 国际化管理》设计配套；
命名约定见《[命名规范](命名规范.md)》「国际化命名」节。

## 2. i18n key 约定 <a id="key"></a>

- key 用点分命名：`模块.页面.字段`，如 `user.form.username`、`common.confirm`、`wf.task.title`。
- 顶层按域：`common`、`user`、`dept`、`wf`、`open`、`error`、`login` 等；与模块目录对应。
- 全小写 + 点分，禁止混合大小写与中文 key；key 语义化（`form.username` 而非 `f1`）。
- 新增文案必须同时补中英文两个语言包，CI 检查 key 对齐（缺失即失败）。

## 3. 前端语言包 <a id="frontend"></a>

- 语言包按语言代码分文件组织（默认语言简体中文、第二语言英文，语言代码取标准 locale 取值）；文件落点见《[前端基类清单](../前端基类清单.md)》。
- 组件内文案一律 `t('key')`（vue-i18n），禁止硬编码中文/英文。
- 页面级 key 与路由/页面名对应（`user.form.*`）；跨页通用文案放 `common.*`。
- 动态文案用插值（`确认删除「{name}」？`），不用字符串拼接，保证语序正确。
- 复数/占位符：英文复数用 ICU（`{count} items` 由库处理），中文按需。

## 4. 后端文案 <a id="backend"></a>

- 后端按 gettext 约定的语言目录组织翻译文件（目录名用语言代码）；msgid 用英文原文，msgstr 本地化。
- 业务提示（`message`）与校验错误输出本地化文案；接口层按请求语言（Accept-Language / 租户配置）选择。
- 邮件模板、通知消息（审批提醒、告警）中英文双版本（见平台《项目规划说明》初始化数据）。
- 服务端异常错误信息对用户隐藏内部细节，仅提示通用文案（《[安全开发规范](安全开发规范.md)》「注入与输入校验」节）。

## 5. 错误码文案 <a id="error"></a>

- 错误码（`20001` 等）与文案分离：后端返回 `code`，前端按 `error.20001` 映射文案（《[API接口规范](API接口规范.md)》「错误码」节）。
- 文案 key 与错误码一一对应：`error.20001: 用户名或密码错误` / `Invalid username or password`。
- 新增错误码同时补 `error.*` 中英文 key。

## 6. 数据与字典国际化 <a id="data"></a>

- 字典/菜单/表单标签等多语言数据入库（语言清单与文案两类表，表结构见数据库设计；租户级可覆盖，见平台《概要设计 29 国际化管理》）。
- 字典值（状态、类型）显示文案走字典 + i18n，不硬编码在前端。
- **语言维度不写死在界面**：业务文案（菜单 / 业务码 / 动作码 / 字段 / 字典 / 邮件模板 / 工作台卡片 / 自建字段等）统一用**多语言文案字段**维护（平台《组件设计 · 多语言文案字段》）——表单里只占**一行**：文本框就地编辑必填语言文案 + 一个**图标按钮**（悬停提示，标题不标注「多语言」字样）；弹框内明细行由**启用语言清单**（平台《概要设计 29 国际化管理》）动态生成，支持筛选并标出系统默认语言与必填语言——新增一种语言只需在语言清单启用，界面与接口契约都不用改；**禁止**写成固定的「中文名称 / 英文名称」等按语言命名的栏目与字段，也禁止逐语言铺开占满表单。
- **必填语言＝当前登录用户语言**（该语言未启用或为空时回退**系统默认语言**）：在字段外壳就近编辑、在弹框内置顶并标「必填」，为空即阻断；服务端按**请求语言**强制校验（产品模块 / 开放接口 / 导入共用同一道门）；其余语言可缺省。
- **多语言明细弹框为可复用件**：所有多语言场景共用同一弹框（明细表行内编辑 + 语言关键字 / 仅看缺失 / 仅看已填筛选 + 系统默认语言与必填语言标记）；弹框内为草稿，「确定」回写字段、「取消」丢弃，**落库一律随宿主工具栏「保存」**统一提交，不在弹框内直接提交。
- **附表承载全部语言**：`{主表}_i18n` 附表存该实体的全部语言（含默认语言）；主表默认文案列是服务端按**优先级兜底**（系统默认语言 → 必填语言 → 首个有值语言）派生的快照（供列表零关联展示），不由界面单独提交，避免同一文案两处编辑而漂移。
- **系统默认语言由语言清单的默认标记确定**（全清单唯一、不可停用），不写死为某个语言标识；它只承担「派生默认文案」与「缺省回退目标」，**不承担必填语义**；某语言缺省时按**系统默认语言文案回退**（不合成值、不阻塞渲染）。
- 初始化数据种子：菜单/表单/字段/字典/帮助/邮件模板含中英文附表（平台《项目规划说明》「初始化数据」）。

## 7. 文案与格式约定 <a id="format"></a>

- 占位符统一 `{var}`；日期时间用 Intl/ICU 格式化（`2026-08-11 09:30` / `Aug 11, 2026`），不硬编码格式串。
- 数字/金额按 locale 格式化（千分位、小数点）；货币符号随语言。
- 中文文案用全角标点；中英混排规范（数字与英文两侧留空格）。
- 英文文案首字母大写规则遵循句子式（sentence case）。

## 8. 检查清单 <a id="checklist"></a>

- □ 无硬编码文案（前后端），全部走 i18n
- □ key 命名 `模块.页面.字段`，中英文语言包同步
- □ 错误码文案映射 `error.xxxxx` 完整
- □ 字典/菜单等多语言数据在语言表有种子
- □ 业务文案多语言字段由语言清单驱动（字段一行 + 可复用明细弹框，无写死语言栏、不逐语言铺开）、弹框确定回写而落库随宿主保存、必填语言（＝当前登录用户语言）必填、缺省回退默认文案；主表默认文案为优先级兜底派生的快照
- □ 动态文案用插值，日期数字按 locale 格式化
