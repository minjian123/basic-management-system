## 1. 概述 <a id="overview"></a>

本文档定义本项目后端（backend，FastAPI）的开发规范：基座体系、分层职责、编码与命名、异常与错误码、接口开发、SQL 与数据访问、异步并发、事件任务、测试写法与提交规范。
依据《项目规划说明》《架构设计》《命名规范》《文档生成规范》展开，与《前端开发规范》配套。**后端基座体系与平台《架构设计 · 后端基础类体系》同源**——架构节点定分层语义与收口原则，本规范定强制用法口径，基类清单、契约与代码位置由《[后端基类清单](../后端基类清单.md)》提供；与之对称的前端口径见《[前端开发规范](前端开发规范.md)》「前端基类体系」节。

## 架构铁律（强制 · 先读） <a id="iron-rules"></a>

> **主体开发（平台内建主线）用继承保统一，项目二次开发 / 定制用组合保灵活**——两轨不互斥，汇入同一登记与契约体系。本条即 §3.1「插件化（能力可替换）」条的**前置口径**；前端同构口径见《[前端开发规范](前端开发规范.md)》「架构铁律」节，AI 侧见《[AI开发规范](AI开发规范.md)》。

1. **主体内建必须继承**：平台自有实现一律沿继承链派生（根系 根基类 → 各层模块基类 → 能力基类 → 插件中间层），**能力即继承链上的层**；公共字段 / 方法只在链上对应层维护；业务代码只依赖能力基类与提供者，不得绕过链层另起炉灶，**不得在链外自由挂接能力**。
2. **二次开发 / 定制用组合**：不继承平台基类，经显式注册 / 虚拟子类 / 结构化契约登记接入，**不回改平台基类**。
3. **两轨汇入同一体系**：同一张插件注册表（「能力键 + 实现名」唯一）+ 同一套契约测试（契约版本校验），**均须过契约测试**；实现名与能力键视为契约，变更走破坏性变更流程。
4. **依赖方向**：只准上层依赖下层，禁止反向依赖；能力之间的依赖须在登记显式声明。
5. **返工教训（2026-09-17，第二次返工 · 推翻重来级）**：前端曾把该口径写成「组合轨默认、能力不在继承链上、域基类只是可选语义归类」，导致能力平铺、无层次、无统一管理、散落系统各处 → **处置不是修补，而是推翻重来**（能力入继承链；设计口径与双端已交付件全部重做）。**后端新增实现 / 设计 / 文档前同样必须核本铁律；与铁律冲突的旧口径以铁律为准、先报冲突并回写，不允许出现第三次返工。**

## 2. 目录与分层职责 <a id="structure"></a>

```text
backend/                         # 工作区根（uv workspace：libs/* 共享库 + services/* 服务）
├── pyproject.toml               # 工作区配置（成员 + dev 依赖 + ruff / pyright / pytest）
├── libs/
│   └── bms_core/                # 共享基座库（各服务复用，独立构建）
│       ├── pyproject.toml
│       ├── src/bms_core/
│       │   ├── application.py   # 服务应用装配基座（service_lifespan + BaseServiceApplicationFactory；包根组合根）
│       │   ├── core/            # 配置、安全、异常与基座（根系 / 集合 / 横切）
│       │   ├── api/             # 接口层基座（路由基类 / 异常处理 / 中间件 / 探针 / 依赖注入）
│       │   ├── db/              # 数据访问底座（引擎 / 会话 / 读写分离 / 租户路由）
│       │   ├── repositories/    # 数据访问基类与公共实现（多数据源 / 分片路由）
│       │   ├── services/        # 服务基类与模块注册
│       │   ├── schemas/         # 请求 / 响应基类与公共契约（分页 / 游标 / 过滤 / 排序）
│       │   ├── models/          # ORM 基类与平台基础模型
│       │   └── <能力域>/        # 横切能力域（缓存 / 锁 / 检索 / LLM …）
│       └── tests/
├── services/                    # 每服务独立工程（一服务一容器一库、独立构建）；2026-09-22 02_03 拆分为 9 服务
│   ├── platform/       # 平台地基 / 配置服务（服务目录 / 插件 / 字典 / 图标 / 偏好 / 查询方案 / 代码校验）
│   ├── identity/       # 认证与身份服务（验证码；SSO / 会话 / 服务身份随认证阶段）
│   ├── tenant/         # 租户与配置服务
│   ├── org/            # 组织主数据服务
│   ├── file/           # 文件服务
│   ├── notification/   # 通知服务
│   ├── search/         # 检索服务
│   ├── ai/             # AI 服务
│   ├── report/         # 报表打印服务
│   └── <服务名>/                # 各服务同构骨架（用 `scripts/new_service.py` 生成）
│       ├── pyproject.toml
│       ├── src/bms_<服务名>/
│       │   ├── main.py asgi.py  # 服务入口与应用工厂（只声明身份 / 路由，通用装配由基座承载）
│       │   ├── api/             # 路由层（按模块），依赖注入；只做参数校验与路由分发
│       │   ├── services/        # 业务逻辑与事务边界
│       │   ├── repositories/    # 数据访问，多数据源 / 分片路由

```

- **依赖方向（强制）**：服务只依赖共享基座库 `bms_core` 与自身包；**共享库不得依赖任何服务**；**服务之间不得互相 import**（只经公开契约或事件）；服务内 `api → services → repositories → models / schemas` 单向，`models / schemas` 不得反向。由 `scripts/tools/base-check/check-service-boundaries.py`（CI base-integrity）与套内 `test_module_boundary` 护栏断言。
- **新增服务**：用 `backend/scripts/new_service.py <服务名>` 生成同构骨架，不在链外自建工程结构。

> 目录与文件的**具体登记**（各层子目录、基座落点、当前实现位置）见《[后端基类清单](../后端基类清单.md)》「继承链与代码位置」节与任务详细设计；本节只给骨架与分层职责。

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| api | 参数校验、路由分发、依赖注入（权限校验依赖等） | 禁止直接操作模型 / 写业务逻辑 |
| services | 业务逻辑、事务边界、事件发布 | 禁止直接拼 SQL / 绕过数据访问层 |
| repositories | 数据访问、数据源与分片路由、数据范围过滤 | 禁止承载业务规则 |
| models / schemas | ORM 模型 / 请求响应模型 | 禁止在 models 写业务逻辑 |

- **基座与继承约定（强制）**：公共字段/方法只在所属基类维护，模块类只写差异部分，不得重复实现、不得绕过基类另起炉灶；完整分层（根系 根基类 + 集合体系 + 模块基类 + core 横切 + 中间层 + 跨阶段基座）、各层职责、继承链与扩展规则见第 3 节，清单与落点见《[后端基类清单](../后端基类清单.md)》

## 3. 后端基座体系（强制） <a id="base-class"></a>

> 合规审计（基座继承链 / 横切件 / 模块边界 / 契约 / 清单对账 / 错误码段位）按《[后端审计规范](后端审计规范.md)》执行：检查维度（B1 ~ B10）与现有资产见其 §5 与附录，首次审计校准。

后端所有**基类**收敛为一套分层体系，**公共字段/方法只在对应层基类维护，任何模块不得重复实现**；调整某一层基类即全链生效（适配上百模块与海量接口场景）。**基类清单**（分层、职责、代码位置、继承链、状态）与**各能力域细则**（必须走哪个基类、契约与禁止事项）由《[后端基类清单](../后端基类清单.md)》提供（「中间层基类 / core 横切基座 / 跨阶段基座」节）；本规范只定**强制性规则口径**，体系机制与收口原则见平台《架构设计 · 后端基础类体系》，详细契约见对应详细设计。**架构节点只写架构语义**（分层、边界、机制、收口原则与阶段波次）；实现细节以《后端基类清单》（实现侧单一权威）与详细设计为准，本规范只定全局强制口径、不承载技术细节（见《[文档生成规范](文档生成规范.md)》「架构节点的语义与实现分层」节）。

### 3.1 强制用法 <a id="base-class-usage"></a>

- **必须继承（强制）**：后端**所有自定义类都必须继承项目基类**，不得以 Python 内建 `object` 为唯一基类——普通类 / 值对象 / 数据契约从根系派生，模块类经各层基类落地（仓储 / 服务 / 请求响应 / ORM 模型 / 集合 / 能力域契约 / 占位实现 / 异步资源各有对应基类）；CI 静态护栏校验（见 3.5）。
- **异常类必须继承异常基类（强制）**：一切自定义异常继承统一异常基类，并按错误码段位归入段位基（通用 / 认证 / 用户与组织 / 系统配置 / 文件 / 开放·租户·SSO；新增段位先加段位基）；禁止直接继承内建异常、禁止模块内游离异常。
- **能力实现必须走基座（强制）**：平台能力（脱敏 / 权限 / 锁 / 验证码 / 密码策略 / 降级熔断 / 限流幂等防重放 / 指标链路 / 健康检查 / 开放接口 / 对象存储 / LLM / 全文检索 / 通知 / 实时推送 / 出站集成 / 工作流 / 身份源 / 会话 / 查询 / 导入导出 / 哈希链 / 归档 / 字段类型 / 国际化 / 工作台卡片等）一律走「能力基类（端口）+ 插件注册表 + 配置选择 + 提供者」——业务代码只依赖能力基类与提供者，**禁止直连具体实现**（不直接依赖对象存储 / 厂商 SDK / 模型等），禁止各模块自研平行实现（限流计数、幂等 / 限流键、签名、掩码、降级分支等）；换实现只改配置文件的实现名与选项。各能力域「必须走哪个基类、关键契约与禁止事项」见《[后端基类清单](../后端基类清单.md)》「中间层基类 / core 横切基座 / 跨阶段基座」节。
- **服务应用装配必须走共享基座（强制）**：各服务应用一律经 `bms_core.application.BaseServiceApplicationFactory` 构造（`service_lifespan` + 通用装配编排：身份 / 中间件 / 异常处理 / 引擎与租户源 / 插件装配 / 探针），服务只声明身份（`service_name` / `service_title` / `version`）、业务路由（`service_routers()`）与可选钩子（`prepare_settings()` / `configure_service()`）；**禁止各服务自建 lifespan / 中间件链 / 探针挂载 / 引擎与租户源装配**。业务路由经 `mount_service_routers` 以**服务级登记表**挂 `/api/v1`（避免多服务同进程登记串扰）；探针由基座统一挂载。
- **接口路由必须走路由基座（强制）**：模块（能力域）路由一律继承统一路由基类（统一前缀 / 标签 / 默认错误响应 / 元信息），经登记表登记并由统一挂载入口挂到统一 API 前缀；**禁止裸建路由、手工拼前缀、各自拼装分页 / 排序参数**（统一经分页 / 排序 / 游标依赖工厂）；统一响应与异常沿用统一响应模型 + 全局处理器，探针路由豁免统一前缀与统一响应；真实登录态与权限校验随认证 / RBAC 阶段。细则见《[后端基类清单](../后端基类清单.md)》「接口层基座」节。
- **用户偏好必须走偏好基座（强制）**：用户偏好（列表个性化 / 列配置 / 通知偏好 / 工作台布局 / 向导开关）**一律经统一偏好基座读写**，键遵循统一分段格式（域 + 键）、单键上限由基座统一约束；**禁止各模块自建偏好存储 / 各自定义键格式**；占位实现固定回退默认值。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **列表查询与偏好必须走基座（强制）**：列表筛选 / 分页 / 排序参数一律走列表查询基座契约（序列化口径按《[API接口规范](API接口规范.md)》），**禁止各接口自定筛选格式**；列表个性化经列表偏好契约、按统一列表偏好键经偏好基座读写；查询方案一律经查询方案基座（个人 > 租户 > 平台三级优先级），**禁止各模块自建方案存储**。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **通知中心读接口必须走基座（强制）**：站内信 / 待办通知的列表 / 详情（查看即已读）/ 未读计数 / 已读（批量 / 全部）/ 删除**一律经通知中心基座**，**禁止各模块自建通知存储**；**未读数以服务端为唯一口径**（已读接口返回操作后的未读总数，前端据此校准角标；推送与已读的并发由实现侧按用户加锁裁决）；列表筛选 / 分页复用列表查询基座契约，通知新事件的负载字段见平台《架构设计 · 实时推送》「事件路由」节。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **AI 对话必须走基座（强制）**：AI 流式对话 / 中断、会话（列表 / 详情 / 消息 / 删除）与自动执行确认 / 撤销**一律经对话基座三契约**（流式对话 / 会话存储 / 动作闸门），**禁止各模块自建流式通道或会话存储**；流式契约只描述**事件语义**（增量片段 / 结束 / 错误 / 审计标识）、不绑定传输实现，会话以对话审计数据为**派生视图、不另建独立会话事实源**；自动执行与自动审批开关**默认关闭**、各自独立、审批依赖执行开启，执行前**强制二次确认**、缺少确认一律拒绝、撤销落审计。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **检索查询必须走基座（强制）**：全局搜索 / 审计日志检索 / 文件内容检索**一律经检索基座三契约**（全局搜索 / 审计检索 / 文件内容检索），**禁止各模块自建多域聚合与降级提示**；可检索域按**权限并集**、租户隔离与动作级数据范围在**检索侧强制**（调用方不可绕过）、结果只返业务标识与高亮（详情回查库）、高亮按白名单清洗；引擎不可用时返回**降级标记与替代入口**，前端提示不阻塞页面。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **组织主数据必须走基座（强制）**：用户 / 岗位 / 部门树查询（关键字 / 部门与含子级 / 状态筛选、分页）与按标识批量回显**一律经组织主数据基座两契约**（组织数据源 / 名称回显），**禁止各模块直连组织表或自建组织读出口**；租户隔离、动作级数据范围与敏感字段脱敏由**实现侧强制接入**（调用方不可绕过）；部门树一次性返回、**不分页**，已删除 / 停用对象以存在性 / 状态标记回显、不抛错。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **字典取数与缓存必须走基座（强制）**：字典取数（按类型 / 批量 / 关键字 / 级联父值 / 按值子集 / 探针）、后端翻译与缓存（类型 key / 全局版本键）**一律经字典基座三契约**（取数 / 翻译 / 缓存域），**禁止各模块直连字典表、自建字典缓存或平行翻译实现**；普通运行时链路**不返回扩展属性**（`attr_json` 仅高级查询接口按命中子集返回）；版本比对**只作优化、不作正确性兜底**（缓存不可用降级直连库并返回全量）；缓存实现经缓存 Region 基座（`memory` / `redis` 两实现，**禁止模块内自建 Redis 客户端与 key 规范**）。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **字典取数与翻译必须走基座（强制）**：字典普通取数（按类型 / 批量合并 / 级联父值 / 按值子集 / 版本比对）与后端翻译（导出 / 通知 / 报表 / 审批 / 明细行批量）**一律经字典能力域三契约**（取数 / 翻译 / 缓存域），**禁止各模块直连字典表、自建字典缓存或平行翻译实现**；进程内 L1 经 `02-13` 缓存 Region 承载、key 规范 `bms:{tenant}:dict:{locale}:{type}` 与版本键 `bms:{tenant}:dict:version`（版本比对只作优化、不作正确性兜底），普通运行时链路**不返回扩展属性 `attr_json`**（归字典高级查询）；扩展属性条件查询经查询提供者基座、查询方案经查询方案基座，不属本域。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **文件分片上传与秒传必须走基座（强制）**：文件分片上传与秒传判定（初始化会话 / 分片 / 合并 / 取消 / 秒传命中查询）**一律经对象存储扩展基座出口**，**禁止各模块自接分片 SDK、自建秒传判定或平行分片通道**；分片状态机（状态流转 / 断点续传分片状态）、孤儿分片回收、类型与大小校验、租户配额联动归上层文件管理模块；上传会话幂等经幂等基座承载，重传与重复初始化不得产生重复对象。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **验证码必须走基座（强制）**：图形 / 滑块 / 短信三类验证码的**出题与一次性校验**一律经验证码能力域出口，三类**共用同一挑战编号空间**，**禁止各模块自研出题、自建滑块轨迹判定、直连短信厂商 SDK 或平行实现验证码存取**；场景与策略（是否强制 / 连续失败阈值 / 有效期 / 重发冷却）一律经基座策略入口读取，**禁止登录侧自读配置拼默认值**；短信目标一律**脱敏后回显**、下发经通知渠道出口、限次与防滥用经限流基座；失败计数与「连续失败 N 次强制」、渠道不可用降级归上层认证流程；只有「不匹配 / 不存在或过期 / 发送过于频繁」三类失败才走专用错误码，接口层按需以强制校验入口（抛错）或判定入口（布尔）消费。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **租户自助必须走基座（强制）**：用户自助视角的「我加入的租户 / 切换租户 / 品牌信息」**一律经统一租户自助基座读写**，**禁止各模块自建租户列表、切换与品牌读取**；当前租户的权威来源仍是租户解析链（本基座不参与解析、不读请求上下文，当前租户由调用方传入），切换以「生效方式 + 是否需重发令牌 + 令牌」表达语义、令牌签发归认证阶段，**解析链命中优先级不变**；品牌信息**登录前可用**（登录页需要），未配置项回退平台默认；数据源键一律由租户编码派生、业务与前端不得自拼。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **打印模板与 PDF 导出必须走基座（强制）**：单据打印 / 列表导出 PDF / 批量打印（逐份 / 合并）**一律经统一打印导出出口**，模板定义来源（模板键 / 名称 / 单据类型 / 变量清单）**一律经模板来源出口**，**禁止各模块自接 PDF 引擎、自建模板来源或平行导出通道**；模板来源只出模板元数据、**不承载渲染定义**，导出侧只按模板键 + 单据数据产出、不反向读取渲染定义；产物经对象存储出口落库并以**限时取址**下发（后端不代理文件流、不暴露存储路径），**产物对象 key 一律由基座统一助手派生、业务与前端不得自拼**；批量超阈值转后台任务（任务标识 + 完成后限时下载）归任务调度口径；打印 / 导出动作与产物关联留痕归审计。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **自定义图标与代码校验必须走基座（强制）**：租户自定义图标的清单查询与增删改**一律经统一图标注册表出口**（图标键为唯一业务标识；前端 icon key **由基座统一派生**，业务与前端不得自拼前缀），**禁止各模块自建图标清单或平行维护自定义图标**；平台官方与业务自绘图标随代码发布、不经该出口落库。SQL 只读试算与表达式校验**一律经统一校验出口**（诊断级别 / 类别 / 部位、试算字段清单与预览行、耗时与截断标记统一表达），**禁止各模块直连数据源执行用户 SQL、自建校验实现或平行诊断结构**；**校验不通过以结果契约返回、不作为异常**（只有执行侧故障由实现侧抛错）；只读试算只允许只读语句、走只读从库，超时与限流经基座承载；cron 合法性校验不属该出口（归任务调度口径）。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **边缘信任与请求净化必须走基座（强制）**：边缘身份头契约（网关注入 / 后端信任）与可信身份判定**一律经边缘信任能力域**（`BaseEdgeTrust` 契约 + `get_edge_trust` 提供者 + `EdgeGuardMiddleware` + `require_edge_identity` 依赖），**禁止各模块自行解析身份头、自行判定网关来源或平行实现请求净化**；身份头常量（剥除清单 / 网关标记 / 用户主体）取能力域**单一来源**（`edge/headers.py`，网关生成器与后端同源复用）；信任模式（`[edge].require_gateway_identity`）下客户端伪造身份头一律剥除、租户身份只采信网关注入值，后端只做授权（`require_edge_identity`）不重复认证；真实用户 JWT / 服务 JWT 校验替换只改 `[edge].provider`，调用面零改动。**内部服务入站必须校验服务身份（强制）**：`[edge].provider` 默认真实实现 `ServiceJwtEdgeTrust`（入站服务 JWT 本地 JWKS 验签、`aud=service`），**禁以北南向标记头（`X-Gateway-Identity`）作为唯一信任依据**（标记非密钥、可伪造）；网关经 `forward-auth` 转认证服务按 `aud=api` 校验用户 JWT 后换发**短时网关服务 JWT**附给上游（外部 access token 不透传），后端只信有效服务 JWT。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **认证与身份源接入必须走基座（强制）**：外部 IdP 客户端接入（OIDC 等）与票据校验（JWKS）**一律经身份源能力域**（`BaseIdentityProvider` 契约 + `get_identity_provider` 提供者 + 真实 `OidcIdentityProvider` + `verify_token`），**禁止各模块直连外部 IdP 端点、自行验签 JWT 或平行实现 OIDC 流程**；票据验签只接受非对称算法白名单（`RS256` / `ES256`）、必须校验 `exp` / `iss` / `aud`；客户端凭据（client secret）**一律经环境变量 / Secret 注入**，不写入配置文件、不入镜像；外部身份以 `idp_key`（来源） + `subject`（外部标识）唯一定位，JIT 建号归认证上层、身份源基座不产生建号副作用。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **服务间身份与服务 JWT 必须走基座（强制）**：双类 JWT 的**签发与校验一律经开放接口能力域**（`BaseServiceTokenIssuer` / `issue` + `jwks` 与 `BaseTokenVerifier` / `verify`），**禁止各模块自签 JWT、自行验签或平行实现 audience 分流**；用户 JWT（`aud=api`）由外部 IdP（Keycloak）签发、后端只校验，服务 JWT（`aud=service`）由 BMS 自签（短时 + scope + 服务标识），**受众按「期望输入」分流**（`service` → 本地 JWKS、`api` → IdP JWKS），`exp` / `iss` / `aud` 全校验、仅接受 `RS256` / `ES256`；**自签私钥只经环境变量 / Secret 注入**（公钥经 `/.well-known/jwks.json` 分发、多密钥 `kid` 并行轮换）；服务间出站**剥离入站 `Authorization`**、按开关改附自签服务 JWT（**外部 access token 不透传内部**）。细则见《[后端基类清单](../后端基类清单.md)》「跨阶段基座」节。
- **禁止**：模块类重复定义基类已提供的公共字段/方法；绕过服务类直连数据访问层；直接继承第三方校验 / 序列化基类；另起炉灶新建平行的 CRUD / 序列化 / 并发 / 异常 / 日志实现。
- **集合与排序**：有序集合对外输出稳定序、禁止裸无序集合；多线程共享走并发集合（锁策略显式传入）；跨副本走跨副本封装（外部存储为事实源），禁止进程内集合跨副本共享；锁内禁止 IO 与外部回调。列表排序一律走排序契约——请求侧统一排序参数、仓储以可排序字段白名单声明（白名单外忽略），禁止排序字段直接拼接用户输入。
- **中间层**：占位实现继承占位基类（统一未实现抛错），能力域契约继承能力基类，异步资源继承异步资源基类（统一释放协议）。
- **插件化（能力可替换）**：平台内建实现继承能力基类（并可演进为继承插件中间层），经注册表登记且「能力键 + 实现名」唯一；第三方 / 项目二次开发实现可不继承基类，经显式注册 / 虚拟子类 / 结构化契约登记（继承 / 组合双轨，均须过契约测试）；实现名与能力键视为契约，变更走破坏性变更流程。
- **依赖方向**：只准上层依赖下层，**禁止反向依赖**（core 不得依赖接口层 / 服务层 / 业务模块；数据访问层不得依赖服务层）；跨模块协作走服务层。
- **模块独立性（数据所有权）**：模块只拥有自己的数据，跨模块协作经服务层接口或事件；边界声明（表前缀 / 业务码 / 错误码段 / 事件域）随模块注册并受 CI 校验。写侧硬禁、读侧出口、归属与例外登记见第 3.2 节。
- **命名**：基类、集合、模块类命名统一遵循《[命名规范](命名规范.md)》「后端命名」节；清单与落点见《[后端基类清单](../后端基类清单.md)》。
- **多重继承克制**：仅请求响应基类与接口路由基类因须混合第三方框架基类（数据校验 / 路由框架）而使用多重继承；其余横切能力以基类方法或组合实现。
- **基座未就位，后端模块不得开工**：跨阶段回补项须在对应阶段登记为**前置**，模块不得自行实现临时版本（否则 CRUD、序列化、并发保护、异常语义会在每个模块重复实现、口径发散）。

### 3.2 模块边界与数据所有权 <a id="base-class-boundary"></a>

> 本节是**微服务形态下的服务边界纪律**（服务化地基收口后口径）：模块即服务，主要收益是服务可独立部署、独立演进与数据所有权清晰。服务拆分已定案（目标架构与演进路线见平台《微服务演进规划》），**不保留单体运行形态**；后续服务按服务目录登记与建设批次推进。下文写侧硬禁 / 读侧出口 / 归属唯一即服务间边界，服务间调用基座与数据所有权硬校验见本节后续条款。

| 面 | 规则 | 允许 | 禁止 |
| --- | --- | --- | --- |
| 写侧（硬禁） | 模块只写自己表前缀的表，事务边界不跨模块 | 本模块表；跨模块写经对方服务层接口 | 跨模块直写他模块的表、共享 ORM 关系与物理外键、跨模块 JOIN 后写、一个事务写多个模块的数据 |
| 读侧（两条合法出口） | 读他模块数据只能经出口 | ① 服务层接口 + DTO（少量、强一致、同步）；② 只读投影（只读视图 / 数据查询提供者 / 事件投影表，用于列表聚合、报表、检索） | 业务代码直接跨模块 JOIN、直接依赖他模块 ORM 模型 |
| 归属 | 每张表有且只有一个归属模块，随模块注册登记表前缀 | 平台域共享表（用户 / 部门 / 字典等）归属平台对应模块，其余模块按只读出口消费 | 无归属的「公共表」（无人负责，是新的耦合源头） |

- **给读侧留出口的原因**：报表 / 工作台 / 检索天然需要跨模块聚合，一律禁 JOIN 只会让规则被绕过；出口须在设计侧登记（出口名 / 消费方 / 数据范围），且**只读出口不得用于写**。
- **跨模块副作用走事件**：状态变更需通知他模块时发布事件（事件域随模块注册），不直接调用对方仓储或服务。
- **服务间调用必须走基座（强制）**：服务间**同步**调用一律经服务间调用基座（`BaseServiceClient` + `get_service_client`），**禁止**各服务自研 HTTP 客户端 / 自拼目标地址 / 绕过公开契约；调用只走**公开契约路径**（`/api/v1`）且目标服务须在服务目录登记启用（越界抛参数错误），韧性（显式超时 / 重试 / 熔断 / 限流）由基座统一承载、不重复实现；面向**外部系统**的出站调用走 `outbound/http`，两者语义不同、不得混用。**跨服务读**只经两条合法出口——契约 DTO（`ServiceDto` + 同步调用）或本地只读投影（数据查询提供者 `BaseQueryProvider`），**禁止**直接依赖他服务 ORM 模型 / 跨库 JOIN。
- **数据所有权边界硬校验与例外登记（强制）**：数据所有权由**机器护栏**执行、不靠自觉——构建期 `scripts/tools/base-check/check-service-boundaries.py`（规则 5/6）按**平台层表的表级唯一归属**硬校验「跨服务表声明 / 引用」（原始 SQL / `ForeignKey` 目标 / 已知表名字符串），越界即 CI 失败（`sys_` 前缀**不再整体放行**，未登记表名即拒）；**确需跨服务直读**须在 `deploy/boundaries/data_ownership_exceptions.json` 登记（出口 / 消费方 / 理由 / 替代方案评估 / 失效条件，`access` 只允许 `read`——**写侧硬禁无例外**），未登记一律视为违规；**运行期**经数据所有权边界守卫（`BaseDataOwnershipGuard`，插件键 `data_ownership_guard`）在 SQL 执行前按**表级归属**检测跨服务访问（`[data_ownership].mode` = `warn` 记录计数 / `enforce` 阻断），越界数经 `boundary_metrics.py` 纳入阶段度量（S7）。
- **库级归属校验（强制）**：除表级守卫外，**取数据源引擎入口**（引擎工厂与引擎注册表）同样校验库键归属——全限定键（`platform_{service}` / `tenant_{service}_{code}`）的服务段非当前服务即拒（**数据所有权 10008**）；**跨服务建库 / 迁移**仅经运维通道显式豁免（`allow_cross_service`，限 `ops` 脚本与命令行显式库键），运行期业务代码不得使用。库键与库名一律经基座单一来源派生（禁自拼库键 / 库名）。
- **模型模块按服务声明与迁移链派生（强制）**：服务包在 `bms_{service}/models/__init__.py` 声明本服务模型模块清单（`MODEL_MODULES`；无模型声明空元组，服务包不存在则视为无模型）；迁移与运维期由基座**按链的服务动态导入**（`bms_core/db/migration.py`——共享基座库**不静态依赖任何服务包**，依赖方向不变），链表集由表归属登记派生（`status = enabled` 表 ∩ 已有模型）：新增表须**先登记归属**（表级唯一、库类别明确），再补模型与迁移脚本，禁止把自家表挂到他人服务的链上；`planned`（未定稿 / 未落库）表不进链。
- **事件契约与 Outbox（已交付）**：事件契约版本与事务性发件箱已随服务化地基（阶段二）交付，强制用法见第 10 节；「跨模块调用全事件化」仍为演进方向，随事件总线阶段深化。
- **例外登记**：确需跨模块直读（性能、历史数据、第三方视图）时，在模块设计文档登记「出口名 / 消费方 / 理由 / 替代方案评估」，经评审加入白名单并写清失效条件；无登记的跨模块访问一律视为违规。
- **执行护栏**：边界由机器校验，不靠自觉——服务边界、分层依赖方向与表级归属由 `scripts/tools/base-check/check-service-boundaries.py` 在 CI 执行（规则与例外登记见上条「数据所有权边界硬校验与例外登记」）。落点与运行方式见第 3.5 节。

### 3.3 扩展规则 <a id="base-class-extend"></a>

- **加类型**：出现新的类类型（新集合形态、新数据源形态、新契约形态）→ 新增对应基类；**加扩展**：出现新的横切能力（多租户强制过滤、限流、灰度路由、审计捕获等）→ 新增一层基类。
- 公共逻辑只在所属层基类维护，模块类只负责自身差异；修改公共行为改基类即可全链生效。
- **新增/调整基类须同步**：《[后端基类清单](../后端基类清单.md)》+ 平台《架构设计 · 后端基础类体系》登记 + 对应阶段任务基座登记 + 相关详细设计。
- **新能力替换**：某能力需「实现可替换」时，先定能力基类（端口）+ 默认实现，再按插件化机制接入（插件中间层 / 注册表 / 配置选择）；插件中间层为跨阶段回补项，未交付前不得自行实现临时替换框架（同下条「基座未就位不得开工」）。机制语义见平台《架构设计 · 扩展点与插件化》。
- **基座未就位，后端模块不得开工**：否则 CRUD、序列化、并发保护、异常语义会在每个模块重复实现、口径发散；跨阶段回补项须在对应阶段登记为**前置**，模块不得自行实现临时版本。

### 3.4 分层演进原则 <a id="base-class-evolve"></a>

- 遇到职责冲突或共享范围扩大就**插入中间层**承前启后（可插入多层），每层只解决一类横切职责；**加层优先于在既有层堆逻辑**，禁止把多类横切职责塞进同一层。
- 演进示例（集合逐层加层、基类统一切异步、横切抽中间层）见《[后端基类清单](../后端基类清单.md)》「扩展与演进」节。

### 3.5 执行护栏（指引） <a id="base-class-guard"></a>

本节强制口径由**机器护栏**执行（不依赖自觉）：继承扫描（扫描业务代码中无基类 / 仅继承内建类型或内建异常等禁止基类的类，命中即失败）、分层依赖硬校验（各层 import 方向断言）、模块越界扫描（批 1：跨模块依赖与分层方向；批 2：ORM 关系与表前缀，白名单例外见第 3.2 节）、契约测试套件（注册表 + 全部注册实现跑同一套用例）、插件启动校验（实现存在性 / 「能力键 + 实现名」唯一 / 契约版本 / 依赖可用性，失败即拒启）、清单对账（《[后端基类清单](../后端基类清单.md)》↔ 代码双向校验）。护栏明细、脚本落点与运行方式随平台《架构设计 · 后端基础类体系》与平台《架构设计 · 测试与质量》登记、《项目管理规范》与《部署发布规范》执行，本规范不重复展开。

## 4. Python 编码规范 <a id="python"></a>

- 命名：snake_case（函数/变量）、PascalCase（类）、UPPER_SNAKE（常量）、私有成员单下划线前缀；模块名名词；详见《命名规范》
- 全部公开函数与成员必须有类型注解（类型检查严格模式，CI 强制）
- lint/format：ruff（CI 强制）；禁止未使用导入、避免 except 裸异常
- 请求/响应模型与 ORM 解耦（Pydantic v2）；响应模型显式声明，禁止直接返回 ORM 对象
- 依赖注入：参数名小写，会话与缓存客户端经依赖注入获取；禁止在函数内手动创建全局引擎 / 会话

### 4.1 注释规范 <a id="python-comment"></a>

**注释是交付物的一部分**：代码注释、接口文档、数据库注释同源维护；注释一律使用中文（代码标识符用英文，见《命名规范》）。

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 模块 docstring | 文件顶部，说明模块职责与主要对外对象；每个模块文件必写 | `"""用户模块：模型、服务与仓库的聚合定义。"""` |
| 函数/方法 docstring | Google 风格：功能一句话 + Args + Returns + Raises；公开 API（服务层 / 数据访问层 / 任务）必须写，私有方法复杂逻辑必写 | `"""创建用户。\n\nArgs:\n    req: 用户创建请求。\n\nReturns:\n    新建用户 ID。\n\nRaises:\n    BizError: 用户名已存在（30001）。\n"""` |
| 接口（路由）docstring | summary（一句话）+ description（用途、关键参数、权限码、业务约束）——**自动进入 OpenAPI 契约快照并随契约导出给外部系统与前端类型生成**，必须完整书写 | `"""创建用户。\n\n需要 user:create 权限；支持幂等键；用户名全局唯一。\n"""` |
| 模型字段 | ORM 模型字段写 comment（中文），成为数据库表注释 | `Column(String(64), comment="用户登录名")` |
| 行注释 | 解释"为什么"（why），不解释"是什么"（what）；复杂逻辑（算法、状态机、跨系统交互、并发控制）必须注释 | `# 先删缓存再返回，避免并发下读到旧值` |
| 标记 | TODO（待办）/ FIXME（已知缺陷）/ HACK（临时方案）统一前缀，带简述 | `# TODO: 接入配额校验后移除临时限制` |

- **类型注解优先**：类型注解能表达的语义（参数类型、返回值、Optional）不重复写注释
- **禁止**：逐行废话注释（"此处加 1"）、注释掉的代码（一律删除，需要时从 git 找回）、与代码不同步的过期注释
- 枚举/常量：定义处注释业务含义；配置项逐项注释说明
- docstring 与代码变更同步更新；改逻辑必查影响注释

## 5. 模块组织 <a id="module"></a>

- 按模块分组：路由、模型、请求响应、服务、数据访问各按模块成文件；模块目录用单数名词
- 路由注册：模块路由继承统一路由基类并登记默认路由表，经统一挂载入口挂到统一 API 前缀（禁止手工挂载 / 手工拼前缀）
- 权限码声明：路由以依赖声明权限码，与菜单 / 按钮挂接一致
- 新增模块四件套：模型 + 请求响应 + 服务 + 数据访问（+ 路由），缺一不可
- **基座与继承约定（强制）**：模块类**必须**继承对应基类（仓储 / 服务 / 请求响应 / ORM 模型各继承对应层基类），公共方法经根系落点；模块类只写差异部分，**禁止**重复定义基类已提供的公共字段/方法，禁止绕过基类另起炉灶（新公共能力加到基类，改一处全局生效）。各层职责、继承链与扩展规则见第 3 节「后端基座体系」，清单与代码位置见《[后端基类清单](../后端基类清单.md)》

## 6. 异常与错误码 <a id="error"></a>

### 6.1 统一响应 <a id="error-response"></a>

- 统一响应 `{code, message, data}`；code=0 成功，非 0 为业务错误码；HTTP 状态码与业务错误码分离
- 分页响应 `{list, total, page, size}`；大数据量用游标分页 `{cursor, limit}`
- 文案由前端按错误码 i18n 映射（`error.{code}`），后端不承担文案拼装

### 6.2 错误码分段 <a id="error-code"></a>

平台段 1xxxx~9xxxx 分段表（一经发布稳定不变、按段内序号递增、禁止复用已发布码）见平台《架构设计 · 接口与集成》与《API接口规范》错误码节；产品业务扩展段（10xxxx 起）分配见《项目规划说明》"平台扩展接入流程"节。

### 6.3 异常使用规则 <a id="error-usage"></a>

- 统一自定义异常基类，携带错误码与参数；全局异常处理器统一转换为 `{code, message, data}`
- 异常类必须继承统一异常基类及对应段位基（见第 3.1 节「异常类必须继承异常基类」）；禁止以 Python 内建异常作为自定义异常的基类，禁止就地定义游离于异常体系之外的异常类
- 业务异常在服务层抛出，api 层不 catch 业务异常
- 参数校验：模型校验优先；自定义校验失败抛统一参数异常（1xxxx 段）
- 不向外暴露堆栈与内部细节（生产环境）；异常日志记录完整堆栈（含链路 ID）

## 7. 接口开发规范 <a id="api"></a>

### 7.1 RESTful 与路径 <a id="api-rest"></a>

- 前缀 `/api/v1`；资源复数名词，子资源嵌套
- 动词交给 HTTP 方法：GET 查、POST 建、PUT 全量改、PATCH 部分改、DELETE 删；动作类用动词短语（如登录、重置密码）
- 分页参数 `page`（从 1 起）/ `size`；筛选查询参数；排序 `order_by`（白名单字段）
- 响应字段命名与数据库字段映射（下划线 ↔ 小驼峰）由 OpenAPI 契约同步工具生成，禁止手写漂移
- ID 口径：雪花主键 / 外键出参转字符串、入参转整数；数据库大整数与 JOIN 不变（见《API接口规范》「统一响应」节）

### 7.2 鉴权与权限 <a id="api-auth"></a>

- 除登录 / 刷新 / 健康检查外一律 Bearer 访问令牌；依赖注入获取当前用户与租户上下文
- 权限两级校验：业务级（表单入口 / 表访问）+ 动作级权限码校验；新增接口必须声明权限码
- 数据范围：读操作在数据访问层注入数据范围条件；写操作保存前校验（双向）
- 字段权限：读时过滤（序列化层按可见性）、写时校验（保存前按可编辑性拒绝）
- 租户隔离：查询强制租户过滤；禁止跨租户访问（逻辑外键引用）

### 7.3 幂等键 <a id="api-idem"></a>

- 审批提交、Excel 导入等写接口支持幂等键（请求头 `Idempotency-Key`）
- 实现：前置去重拦截（重复键直接返回首次结果）+ 幂等键字段唯一约束兜底
- 幂等键空间按「租户 + 接口 + 键」组织并带 TTL（键结构统一经基座拼接）

## 8. SQL 与数据访问规范 <a id="data"></a>

- 禁止 `SELECT *`；批量写入用批量接口；禁止循环内逐条写
- 事务：服务层显式声明边界；事务尽量短；禁止跨请求共享会话
- 读写分离：读走副本、写与事务强制主库；请求级只读标记由框架中间件按方法设置、路由可显式覆盖；写路径经工作单元绑定主库会话（写后同会话内读主库）；只读数据集 / 报表等强制从库；主库故障只读降级（写返回明确错误、读走副本）；主从选择一律由数据访问基座承载，业务代码不得自行选引擎
- 多租户路由与隔离：请求租户由全局租户中间件按解析链（子域名 → `X-Tenant-ID` → 令牌租户位）确定，豁免路径与无来源回落策略按租户配置执行；请求级会话按租户数据源键选引擎（无租户上下文回落平台库），租户库连接串与库键一律由数据访问基座解析，**业务代码不得自选租户库、自拼数据源键或持有租户引擎**；模型含 `tenant_id` 列时经仓储基座强制注入租户条件（物理库隔离为第一层、条件过滤为第二层兜底）；租户注册记录取数经统一租户源（缓存失效随租户管理写路径）
- N+1 走查：循环查询用预加载；新增列表接口须自查 N+1
- 索引：排序字段、外键、数据权限过滤字段必须建索引（统一前缀命名）；唯一约束用唯一索引
- 软删除：业务数据用删除时间字段；查询默认过滤已删除；唯一约束用「唯一字段 + 删除时间」复合唯一索引
- 审计字段：创建 / 更新人与时间由 ORM 事件自动填充，禁止手动赋值
- 乐观锁：版本字段更新时比对；冲突返回明确错误码
- 仓储写入：模块仓储一律继承数据库实现基类并经请求级会话构造注入；写入字段经基类白名单（`id` / 审计字段 / 版本 / 软删时间不可写），租户维度模型写入自动注入 / 校验租户并禁止改租户；软删除与物理删除一律走基类出口（`delete` / `soft_delete` / `hard_delete`，硬删穿透软删过滤），禁止模块内自行拼写删除与作用域过滤 SQL
- 会话入口：模块取会话一律经请求依赖或统一会话入口（`session_scope`），禁止模块内自建 `async_sessionmaker`；仓储只 `flush` 不提交，事务边界统一经工作单元
- 分片表：按月分片表经分片路由解析，查询必须带分片键条件；逻辑表名不带后缀
- 排序：排序字段须经白名单校验并解析为模型列（禁止拼接用户原始输入）；**四库 NULL 位次统一为「NULL 恒排末位」**（跨方言用 `列 IS NULL` 排序键表达，禁写 `NULLS FIRST/LAST` —— MySQL 语法不支持），排序键以主键兜底保证稳定序；模块声明可排序白名单（`sortable_fields`）时须保证字段有索引或为主键（护栏工具 `assert_sortable_fields_indexed`）
- 分页：页码分页**限深**（`page ≤ [pagination].max_page`，默认 100；超限按参数非法 10001），大数据量列表用 **keyset 游标分页**（排序键 + 主键元组比较、`LIMIT` 无 `OFFSET`；游标为不透明令牌，与当前排序规格不一致即拒绝）
- 结构变更与建表：结构变更一律走 Alembic 迁移（按数据源分链，命令 `alembic -n alembic:<链名> upgrade head`）；模块取会话 / 建表口径见下；SQLite 开发库由启动期自动建表覆盖（按迁移链表集，`[database].auto_create`，仅 SQLite 生效）；建库 / 删库一律经基座能力（`ops/db_admin.py`）与批量迁移 / 新租户初始化脚本（`ops/migrate_tenants.py` / `ops/init_tenant.py`），业务代码不得自建库表
- 跨方言：禁用方言特有功能（类型用跨方言通用类型、分页统一 limit/offset）
- 连接池：池参数按库默认 + 按服务（`[app].service`）覆盖；worker 数 × (`pool_size` + `max_overflow`) 须在该库 `max_connections` 的 70% 内（启动期告警）；建连超时与池等待快速失败
- 数据范围规则：规则表达式解析为查询条件（见权限设计文档）

## 9. 异步与并发 <a id="async"></a>

- 全链路异步：Web 框架 + 异步 ORM + 异步缓存客户端；禁止在请求路径用同步数据库驱动
- 异步会话禁止跨请求共享；大事务拆小
- 异步任务 worker 为同步进程：任务内异步业务须独立事件循环或独立引擎，禁止跨事件循环复用连接 / 会话
- **同步方言门面（强制）**：目标库为**仅同步驱动方言**（达梦）时，会话一律经统一会话入口（`session_scope` / 请求级依赖）**按方言分流**到同步门面（`SyncSession` + `asyncio.to_thread`）；业务代码**不得**自行判断方言或另起同步连接——分流点只有会话入口一处，注册表负责同步引擎取用（`get_sync` / `is_sync_only`）。会话公共契约为 `DbSession`（异步会话或同步门面），**新增会话方法须同步维护契约与两处实现**（登记见《后端基类清单》）
- 分布式锁：带过期时间防死锁；幂等 / 调度防重 / 引擎创建防重等场景使用（实现走分布式锁基座，见《后端基类清单》）
- 并发集合：进程内多线程共享用并发集合（锁策略按读写比选择）；跨副本共享用跨副本封装 + 版本号惰性比对；锁内禁止 IO 与外部回调，原子更新的计算函数必须纯计算（语义见《并发集合与并发安全详细设计》）
- **骨架期过渡口径**：早期交付的集合基座为同步实现；数据访问与服务基类已统一切换异步（调用面改动集中一次，模块类不改）。达梦同步驱动例外口径按数据访问与分片节点与本节执行

## 10. 事件与任务规范 <a id="event"></a>

- 事件发布：统一事件发布组件（事件信封携带事件 ID / 类型 / 版本 / 租户 / 发生时间 / 载荷）；业务代码不直接操作消息队列客户端
- 事件命名：`{已登记事件域}.{对象}.{动作}` 点分小写，**首段必须是服务目录 `sys_module.event_domain` 已登记的事件域**（如 `sys.user.created`、`wf.task.completed`；见《[命名规范](命名规范.md)》「基础设施命名」节）；新事件**先登记事件契约再发布**
- **事件契约（强制）**：事件是长期契约——**字段只增不删、新增必须可选、破坏性变更升主版本**（删除字段 / 改类型 / 改必填性 / 新增必填 / 弃用回退均属破坏性）；事件类型不物理删除，退休置 `deprecated` 保留登记；契约经统一注册表登记（`bms_core/events/contracts.py`），平台默认清单在 `bms_core/events/platform_events.py`，快照入仓 `deploy/events/contracts.json`（`ops/event_contracts.py` 导出 / 零漂移 + 兼容校验）；消费者以订阅声明支持主版本集合（`EventSubscription`），**升主版本前须覆盖全部订阅**；签发按 `[event].contract_mode` 校验（`off` / `warn` / `enforce`，缺省 `enforce`，未登记拒发 `10010`）；事件版本经 `EventEnvelope.event_version` 承载并由发件箱持久化保真
- 生产一致性（强制）：关键事件一律经**事务性发件箱**写入——业务事务内同时写业务数据与 `sys_outbox`（同库同事务，经 `BaseOutboxStore.enqueue`），投递器（`BaseOutboxDispatcher`）轮询转发并标记；**业务代码不直连消息队列客户端**（发布经事件发布端口，MQ 实现可替换）
- 消费者：必须幂等（事件 ID 去重）——经 `ProcessedEventStore.mark(*, consumer, event_id)` 与业务副作用**同一本地事务**登记，命中 `(consumer, event_id)` 唯一键即跳过；失败指数退避重试，最终转死信（`sys_event_dead_letter` 看板人工处置）
- **Saga / 补偿（强制）**：仅在判据成立时使用——**跨 ≥2 服务且部分完成业务上不可接受**（资金 / 权益可能重复消耗、长流程含人工审批）才用 Saga / 补偿，能用「本地事务 + 事件 + 幂等」就不用；短流程用**协同式**（各服务订事件、各自补偿），步进与补偿一律经 Saga 执行器（`BaseSagaExecutor`，TCC 三态：预占 `try` / 确认 `confirm` / 取消 `cancel`）；**补偿动作必须幂等**（执行器经 `ProcessedEventStore` 承载「同一触发事件只执行一次」，动作自身仍须业务幂等）；步骤动作、幂等登记与发件箱事件**同一本地事务**；同 Saga 事件 `aggregate_key = saga_id` 保序；编排式运行时（Temporal）按判据再引入、不在本阶段
- **强一致场景口径（强制）**：
  - **审计哈希链**：链按 `(service, tenant)` 分条（`build_chain_key`）、服务内本地强一致；业务变更 + 链追加 + 发件箱**同库同事务**；跨服务由审计服务幂等消费汇总、**只校验不重算**；**一条链不得拆到多服务维护**
  - **财务 / 收付款**：收敛到**单一账务服务**（库内 ACID）；幂等键 + 分录唯一约束；跨服务用「预占-确认-取消」；显式状态机 + 乐观锁；对账兜底
  - **审批状态机**：单服务内显式状态 + 合法迁移 + 本地事务 + 发件箱；跨服务长流程交编排式运行时（按判据再引入）
  - 软删除复合唯一属单库问题，不涉分布式事务（口径见平台《架构设计 · 数据架构》）
  - **排除 2PC / XA**（Python 无事务管理器、dmPython 无 XA）；**禁止跨库两阶段提交**，跨服务一致性只走「本地事务 + 事件 + 幂等（+ 按判据的 Saga 补偿）」
- 异步任务：任务定义入库、对应处理函数命名 snake_case 动词短语；任务内避免长事务
- 审计类事件：分区键取租户（保证链序）；审计日志异步写入不阻塞主流程

## 11. 测试写法 <a id="test"></a>

- 目录：测试按测试对象分层（接口 / 核心 / 数据访问 / 服务 / 请求响应 / 集成）；测试数据与独立种子按需建立，不与初始化数据混用
- 命名：`test_模块.py`；类 `TestXxx`；函数 `test_行为_期望`（如 `test_create_user_returns_201`）
- 技术：pytest + httpx（免启服务器直连应用）；测试库用轻量文件库（多库文件模拟平台 / 租户 / 归档库）
- 依赖替换：缓存 / 消息队列用测试替身或本地模拟；外部 API 用响应桩
- 覆盖要求：新增接口必须带接口测试（成功 + 失败分支 + 权限拒绝 + 越权）；关键写操作补字段级审计断言
- 集成测试：以集成标记标注，需真实外部服务（三库 / 缓存，连接经环境变量注入），未配置环境时自动跳过；三库方言迁移、读写分离、分片路由、哈希链校验由 main 重验证层执行
- 安全用例：越权 / 注入 / XSS / 上传绕过 / 限流爆破 / 脱敏泄露纳入安全专项用例集

## 12. 日志与可观测性 <a id="log"></a>

- 结构化 JSON 日志；携带请求 ID（中间件注入）；链路 ID 关联调用链
- **服务标识按服务归因（强制）**：每服务经统一服务运行时基座启动（读环境分层的 `[server]` 配置），日志携带 `service` / `service_version`（进程级注入，业务代码零改动）；服务名取服务包声明、可由 `[app].service` 覆盖；探针 `/healthz` `/readyz` 响应携带服务身份
- **指标一律走能力域基座（强制）**：数值采集一律经 `BaseMetrics`（`counter` / `gauge` / `histogram`）与提供者 `get_metrics`，禁止各模块自研平行指标；真实实现为 `PrometheusMetrics`（默认启用），提供者统一注入 `service` 标签按服务归因；指标名取 `METRIC_NAMES` 候选清单（`bms_` 前缀）、标签基数由调用方保证有界（HTTP `route` 用路由模板而非原始 path，`version` 不进标签）；每服务暴露 `/metrics` 采集端点（免鉴权 / 免租户 / 免访问日志，仅内网可达），由 Prometheus 抓取。**服务目录快照降级**（`catalog` 非必需健康项失败、不摘流）经 `/readyz` 聚合记录 `bms_catalog_degraded`（1 降级 / 0 可达）供告警联动，模块不得另造降级指标；**阶段度量**（发布成功率 / 契约破坏数）由 CI 推送 Pushgateway，不占用应用侧调用面。
- **链路一律走能力域基座且 OTel 为事实源（强制）**：调用链一律经 `BaseTracer`（`span` 异步上下文）与提供者 `get_tracer`；真实实现为 `OtelTracer`（默认启用），经 otel-collector 上报 Tempo；**日志 / 中间件的 `trace_id` 一律经 `resolve_trace_id` 取 OTel 当前 span**（保证日志与 Trace 一致），禁止各模块自行生成链路 ID；跨服务经 W3C `traceparent` 传播（httpx 自动埋点）
- **停机摘流先于排空（强制）**：收到 SIGTERM / SIGINT 即置停机摘流（`/readyz` 立即 503 停止路由新流量），再停止接收新连接、等待在途请求完成与资源释放；停机摘流经统一运行时基座（`draining` 标记）承载，模块不得自行拦截信号或另造停机逻辑
- 敏感字段（密码、令牌、密钥）脱敏后记录，不落原始值
- 关键操作（登录 / 踢出 / 删除 / 审批 / 权限变更）必须落操作日志（记动作权限码）
- 依赖调用（数据库 / 缓存 / 对象存储）异常记 error 级并告警；慢查询走慢查询日志
