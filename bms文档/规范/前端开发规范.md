## 1. 概述 <a id="overview"></a>

本文档定义本项目前端（`frontend/packages/*` 基座包；`frontend/apps/desktop` PC 管理端与 `frontend/apps/mobile` 移动端按同约定执行）的开发规范：
目录约定、TypeScript、Vue 组件、状态管理、权限、布局框架组件、样式、国际化、请求封装、
测试与提交规范。依据《项目规划说明》《架构设计》《命名规范》《文档生成规范》及
《主框架布局设计》《表单框架布局设计》《移动端布局设计》展开，与《后端开发规范》配套。

## 架构铁律（强制 · 先读） <a id="iron-rules"></a>

> **主体开发（平台内建主线）用继承保统一，项目二次开发 / 定制用组合保灵活**——两轨不互斥，汇入同一登记与契约测试体系。本条为 **§3「前端基类体系」的前置口径**，细则见 §3.4「继承与组合双轨」；AI 侧同步见《[AI开发规范](AI开发规范.md)》「架构铁律」节与工作区约定。

1. **主体内建必须继承**：平台自有实现一律沿继承链派生（根系 → 组件根 → 机制基类 → 能力层 → 域基类 → 具体组件 / 件），**能力即继承链上的层**；公共字段与方法只在链上对应层维护；不得绕过链层另起炉灶，**不得在链外自由挂接能力**。
2. **二次开发 / 定制用组合**：不继承平台基类，经统一注册通道登记接入，不回改平台基类。
3. **两轨汇入同一体系**：同一登记清单 + 同一套契约测试（契约用例工厂对全部实现跑同一套断言），**均须过契约测试**。
4. **依赖方向**：只准上层依赖下层，禁止反向依赖；层 / 能力之间的依赖须在登记表显式声明，禁止隐式自由挂接。
5. **返工教训（2026-09-17，第二次返工 · 推翻重来级）**：本规范原 §3.4 写作「组合轨默认、能力不在继承链上、域基类只是可选语义归类」，导致能力平铺、无层次、无统一管理、散落系统各处被各自创建使用 → **处置不是修补，而是推翻重来**（能力入继承链；设计口径与双端已交付件全部重做）。**动手前必须核本铁律；与铁律冲突的旧口径以铁律为准、先报冲突并回写，不允许出现第三次返工。**

## 2. 目录约定 <a id="structure"></a>

```text
frontend/apps/desktop/
├── src/
│   ├── api/        # 请求封装与接口定义
│   ├── router/     # 动态路由生成（不硬编码路由表）
│   ├── stores/     # 状态管理
│   ├── views/      # 页面（按模块分目录）
│   ├── layouts/    # 主布局（侧边栏 + Tab 栏 + 内容区）
│   ├── components/ # 通用组件（PascalCase 单数名词）
│   ├── i18n/       # 中英文文案
│   ├── styles/     # 全局样式与令牌（含移动端安全区）
│   └── utils/      # 通用工具与组合式函数
├── tests/          # 集中测试（与 src 分离）
├── .npmrc          # npm 源
├── package.json
├── package-lock.json # 依赖锁定（必须提交）
└── .nvmrc
```

> 目录与文件的**具体登记**（各包目录树、关键文件落点）见《[前端基类清单](../前端基类清单.md)》「目录与依赖」节；本节只给骨架与命名约定。

- 双工程独立：`frontend/apps/desktop` 与 `frontend/apps/mobile` 各自依赖清单 / 锁定与 lint / 格式化 / TS 配置，互不共享；npm 管理；**前端单仓多包 workspace**（基座包见 §3）
- **包级门禁**：各包 lint（零告警）与类型检查、测试统一汇入根命令与 CI（命令与配置见工程说明，不在此列明细）
- npm 源与锁定：`.npmrc` 配镜像源；`package-lock.json` 必须提交；`legacy-peer-deps` 仅在上游 peer 声明滞后时临时启用并在文件内注明
- **基础类与继承约定（强制）**：公共字段/方法只在基础类维护，模块不得重复实现；体系角色（根系 / 组件根 / 机制基类 / 能力 / 域基类）与扩展约定见第 3 节
- 路由 path kebab-case（`/user-management`）；路由 name PascalCase 与页面组件对应
- 图片等资源 kebab-case（如 `logo-bms.png`）

## 3. 前端基类体系（开放式，强制） <a id="base-class"></a>

与后端《[后端开发规范](后端开发规范.md)》「后端基座体系（强制）」节对齐：前端基类按**角色 + 开放扩展**组织（根系 / 组件根 / 机制基类 / 能力 / 域基类），**公共字段/方法只在对应基类或能力维护，任何组件与模块不得重复实现**；新增能力 = 新增**核心能力类 + 登记 + 按需投影**，不改根、不设层数/数量上限。**基类清单**（角色、职责、代码位置、依赖、状态）由《[前端基类清单](../前端基类清单.md)》提供，本规范只定强制用法口径；组件契约见组件设计 00 类节点，体系机制见平台《架构设计 · 前端组件体系》。**架构节点只写架构语义**（分层、边界、机制、约束与阶段落点）；实现细节以《前端基类清单》（实现侧单一权威）与详细设计为准，本规范只定全局强制口径、不承载技术细节（见《[文档生成规范](文档生成规范.md)》「架构节点的语义与实现分层」节）。

**分层（强制）**：前端基类体系 = **纯 TS/JS 框架无关核心** + 可替换渲染插件。单仓多包 workspace：

| 层 | 职责 | 约束 |
| --- | --- | --- |
| 核心 | 根系 / 机制基类 / 能力类 / 领域逻辑 / 契约（框架无关） | **不得依赖任何渲染框架 / UI 库 / 插件 / 宿主**（由核心护栏校验）；能力类必须继承机制基类并登记 |
| 渲染绑定（投影） | 核心实例 ↔ 框架响应式的薄适配、指令、令牌样式 | 依赖核心，不依赖 UI 库与宿主；投影只做适配，不含判定逻辑 |
| 渲染实现插件 | PC 与移动端各一套 UI 实现 | 依赖核心 + 绑定；插件之间不互相依赖 |
| 宿主装配 | 路由 / 菜单运行时 / 页面 / 注入接线 | 依赖插件与核心；宿主不含基座实现 |

**依赖方向（强制）**：宿主 → 插件 → 核心；**「同接口多实现 + 契约测试同一套断言」**——同一契约由各渲染插件实现，契约用例工厂对全部实现跑同一套断言（不得只在单端新增导致契约漂移）。

### 3.1 强制用法 <a id="base-class-usage"></a>

- **必须从根派生（强制）**：一切基类从根系派生（契约 / 数据根、组件根、机制基类、能力层、域基类同）；UI 组件必须挂到组件根或域基类的组件包装上；任何层不得绕过链层另起炉灶（命名规则见《[命名规范](命名规范.md)》「前端命名」节）。
- **必须经能力取得横切行为（强制）**：正交横切行为必须经链上能力层取得（核心能力类化 + 登记 + 按需投影），禁止在组件内自实现（同后端「禁止绕过服务基类直连数据访问层」）。
- **继承与组合双轨（强制）**：**主体内建（平台主线）一律走继承轨**——能力即继承链上的层、统一受控；**项目二次开发 / 定制走组合轨**——不继承平台基类、经注册通道接入、不回改平台基类；两轨汇入同一登记与契约测试体系，详见 3.4 节。
- **禁止**：组件/模块重复实现基类或能力已提供的公共字段/方法；绕过基类体系另起炉灶；基类依赖具体组件；能力反向依赖上层；未登记能力存在。
- **依赖方向**：只准上层依赖下层（具体组件 → 域基类/能力 → 组件根 → 根系）；机制基类供链上各层复用、由组件根统一挂接（装配与释放联动：取消订阅 / 释放资源），不直接面向具体组件；层次由依赖关系决定，**不设层数上限**；能力之间依赖须单向并登记。
- **组件根契约（强制）**：UI 组件经组件根取得通用属性与**令牌属性协议**——档位只写根元素属性、状态只加状态类、可访问性基础属性由组件根统一产出；组件只消费令牌语义变量，**不得硬编码色值与尺寸**；未声明属性经单根元素透传（内部保留键不回传）。通用属性清单见《[前端基类清单](../前端基类清单.md)》。
- **尺寸硬编码白名单（豁免项）**：以下结构常量允许直接书写：① 1px 描边 / 分隔线；② 媒体查询断点；③ 树形 / 层级递归缩进；④ JS 运行时计算的内联值（弹出层坐标等）；⑤ 组件内置图形与骨架 / 加载形态尺寸（令牌化随品牌化任务统一评估）。**色值不设豁免**（一律消费令牌，护栏拦截硬编码色值）。
- **命名（强制）**：核心类（根系 / 组件根 / 机制基类 / 能力类 / 域基类）一律 `Base` 打头；注册项类型与能力键、组合式投影命名按其命名规则执行——统一遵循《[命名规范](命名规范.md)》「前端命名」节，清单与落点见《[前端基类清单](../前端基类清单.md)》。
- **同一契约多实现（强制）**：PC 与移动端是**同一契约的两个实现**，不要求字节级同款；一致性由契约用例工厂（同一套断言）与核心共享逻辑（单实现）共同保证。新增基础能力时：**先落核心与绑定（框架无关）**，再按需在各渲染插件提供实现与契约用例。

### 3.2 扩展规则 <a id="base-class-extend"></a>

- **新增能力 → 新增核心能力类**（纯 TS，正交可组合，形态等预置项只是首批、非封闭枚举）；**机制横切归机制基类**（占位 / 异步资源 / 订阅 / 注册表 / 错误等体系公共机制）；**新增域语义 → 新增域基类**（核心能力 + 投影 + 插件包装）——两者均不改动根系 / 组件根。契约要点见对应组件设计节点与《[前端基类清单](../前端基类清单.md)》，本规范只给强制原则：
  - **机制基类**：占位按原因与降级形态分类，**占位态不发起请求、不写缓存、无副作用**，未实现调用统一抛错；异步资源登记后**逆序释放**、幂等、释放后拒绝登记、单资源失败不阻断；错误携带错误码与用户提示并统一响应解析 + 提示映射（回退 i18n），上报委托根系；订阅主题与后端事件同源、来源解耦、取消函数登记为异步资源（卸载自动取消）。
  - **能力机制（强制）**：能力类继承能力基类并在**能力登记表**登记依赖（**只登记能力 → 能力的单向依赖**；「协作 / 消费」关系不入表）；开发态校验「依赖已登记 / 无循环 / 键名合法」，违规默认告警；「不得依赖上层」由核心护栏（import 方向扫描）把关。
  - **注册表（强制）**：同键**唯一性拒重**（严格域抛错、一般域告警保留首个）、未命中**不替各域裁决兜底**、遍历保序、只读快照；注册项须带键与自描述；各域注册表基于统一基座扩展，**不得另起映射登记实现**。
  - **错误码段位（强制）**：前端内建码对齐平台段位（参数 / 未登记 / 冲突 / 限流 / 权限），前端保留自有子段；不得自造段位或复用平台已发布码。段位数值见《API接口规范》错误码节与《前端基类清单》。
  - **代码分层（强制）**：能力类落**核心包**（框架无关）、领域共享逻辑落核心领域层、契约类型落核心契约层；组合式投影落**绑定包**；具体组件落各**渲染插件**的域目录——落点与当前清单见《[前端基类清单](../前端基类清单.md)》。能力**不含 UI 视觉与业务语义**；旧基座层已废弃，新代码一律走现行分层（历史经 git 追溯）。
- **新增即登记**：候选 → 设计节点（组件设计）→ 评审确认 →《[前端基类清单](../前端基类清单.md)》登记 → 同步《架构设计 · 前端组件体系》；未登记的能力不得散落在具体组件内重复实现。
- 公共逻辑只在所属能力 / 基类维护，具体组件只负责自身特性；修改公共行为改能力 / 基类即可全链生效。
- **兼容性**：新增能力 / 基类为兼容变更；调整既有能力契约（行为 / 参数 / 事件）须评估使用方并升**主版本**标注（组件设计节点与清单同步）。

### 3.3 演进原则 <a id="base-class-evolve"></a>

- 遇职责冲突优先**新增能力**或**插入中间机制**承前启后，每能力只解决一类横切职责；禁止把多类横切职责塞进同一能力，禁止为容纳新类型而扩充封闭枚举。
- 演进示例（形态与域职责冲突 → 拆分能力消解、集合逐层加层等）见《[前端基类清单](../前端基类清单.md)》「扩展与演进」节。

### 3.4 继承与组合双轨（强制） <a id="base-class-composition"></a>

口径与后端《[后端开发规范](后端开发规范.md)》「后端基座体系」节**同构**：**主体开发（平台内建主线）用继承保统一，项目二次开发 / 定制用组合保灵活**；两轨不互斥，汇入同一登记与契约测试体系。

> **返工教训（2026-09-17，第二次返工 · 推翻重来级）**：本节原写作「组合轨默认、能力不在继承链上、域基类只是可选语义归类」，直接导致能力平铺、无层次、无统一管理、散落系统各处被各自创建使用。**处置不是修补，而是推翻重来**——能力入继承链，设计口径与双端已交付件全部重做。**任何实现 / 设计 / 文档动手前先核本节；口径冲突以本节为准、先报冲突并回写冲突文档，不得沿旧口径继续实施——不允许出现第三次返工。**

**继承轨（主体内建，强制）**：

```mermaid
flowchart TD
    ROOT["根系（框架无关核心）"] --> COMP["组件根（核心）"]
    COMP --> MECH["机制基类（占位 / 异步资源 / 订阅 / 注册表 / 错误）"]
    COMP --> CAP["能力层（核心，一类一层）"]
    CAP --> DOM["域基类（输入 / 展示 / 树 / 图表 / 编辑器 / 字段 …）"]
    DOM --> C["具体组件 / 件（各渲染插件）"]
    CAP --> PROJ["投影（绑定包）"]
    PROJ --> C
```

- **主体内建一律沿此继承链派生**（根系 → 组件根 → 机制基类 → 能力层 → 域基类 → 具体组件 / 件）：**能力即继承链上的层**，层间依赖方向由继承关系确定，**不允许链外自由挂接能力、不允许绕过链层另起炉灶**；
- 公共字段 / 方法只在链上对应层维护，改一层即全链生效；机制基类（体系公共机制，不是某个组件的能力）供链上各层复用，不直接面向具体组件；
- 投影是继承轨在渲染框架侧的**薄适配**（核心可订阅状态 → 框架响应式，不含判定逻辑），只存在于绑定包；换渲染框架即换一份适配 + 渲染插件，链本身不动。

**组合轨（二次开发 / 定制，非主体）**：

- 项目二次开发、租户定制、第三方实现**不继承平台基类**，经统一注册通道登记接入（登记 + 契约测试），**不回改平台基类**；
- 组合轨实现与继承轨**汇入同一登记与同一套契约测试**；
- 判定一句话：**平台内建 = 继承轨；平台之外 = 组合轨**；同一能力可同时存在内建实现与定制实现，替换实现不改使用方。

**分工判定（新层 / 新能力落点）**：

| 新层 / 新能力形态 | 落点（语义） |
| --- | --- |
| 多个组件可自由选配的横切能力（形态 / 值 / 权限 / 数据源 / 上传…） | 新增**能力层**（核心能力类 + 登记；投影按需） |
| 同类组件的家族身份与统一契约（输入域 / 展示域 / 树域 / 图表域 / 字段域…） | 新增**域基类**（继承链上的一层：核心实现 + 投影 + 插件包装） |
| 体系级公共机制（能力声明 / 占位 / 资源释放 / 注册表 / 错误 / 订阅…） | 新增**机制基类**（核心机制层） |
| 所有基类共有的横切（日志 / 配置 / 生命周期…） | 上提**根系**；所有 UI 组件共有 → 上提**组件根** |
| 视觉 / 交互实现（同契约多端） | 各**渲染插件** + 契约用例 |
| 平台之外的定制 / 二次开发实现 | **组合轨**：注册通道登记接入，不继承平台基类、不回改平台基类 |

### 3.5 执行护栏（指引） <a id="base-class-guard"></a>

本节强制口径由**机器护栏**执行（不依赖自觉），护栏项与落点见《[前端基类清单](../前端基类清单.md)》与工程说明：

- **核心框架无关护栏**：核心源码零渲染框架 / UI 库 / 插件 / 宿主依赖 + 包依赖面为空；
- **契约测试套件**：核心契约（确认 / 权限 / 容器件 / 权限按钮 / 反馈件 / 输入控件等）由各插件跑**同一套断言**——「同接口多实现」的机器保障；
- **能力登记校验**：能力登记表 + 开发态依赖校验（违规告警）；
- **清单对账护栏（新体系版）待重建**（能力登记表 ↔《前端基类清单》↔ 插件导出 ↔ 组件清单双向校验），列入后续工程化待办；旧双端护栏随旧层删除，历史经 git 追溯。

以上护栏汇入 CI 与双端测试门禁执行。**机制未挂接**保持开发态告警（不升级构建期硬失败；再评估触发条件随新护栏批次）。

> 合规审计（基类链 / 能力声明 / 组件根 / 令牌 / 依赖方向 / 双端契约一致性）按《[前端审计规范](前端审计规范.md)》执行：检查维度与现有资产见其附录。

## 4. TypeScript 规范 <a id="ts"></a>

- 变量/函数 camelCase；常量 UPPER_SNAKE；类型/接口 PascalCase；禁止 any（除适配层显式注释）
- 接口类型由后端 OpenAPI 自动生成（保持前后端契约一致）；手写类型不得与生成类型冲突
- 统一响应类型：`{ code, message, data }`；分页响应 `{ list, total, page, size }`
- 严格模式开启（strict）；ESLint + Prettier 强制（CI）

### 4.1 注释规范 <a id="ts-comment"></a>

**注释是交付物的一部分**：组件文档、接口类型注释与后端契约同源；注释一律使用中文（标识符用英文，见《命名规范》）。

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 组件文件头注释 | JSDoc：组件职责、主要 props/emit、使用场景；每个页面/通用组件必写 | `/**\n * 用户列表页：列表查询 + 双击行打开详情。\n * 与 UserForm 经 FormFrame 约定事件交互。\n */` |
| 函数 JSDoc | @param / @returns；复杂逻辑（状态机、缓存、权限计算）必写说明 | `/** 打开详情 Tab，已打开则激活。 @param item 列表行数据 */` |
| 类型/接口注释 | 字段注释含义，枚举值逐一说明；接口字段与后端字段映射说明（如 deptId ↔ dept_id） | `/** 数据范围规则：字段+运算符+预置变量 */\ntype ScopeRule = {...}` |
| 生成类型注释链路 | 后端接口 docstring → OpenAPI description → 生成的 TS 类型自带注释；引用生成类型不重复注释，注释不全的字段在业务侧补注 | — |
| 行注释 | 解释"为什么"（why）；复杂表达式、权限指令、边界处理必写 | `// 关闭激活 Tab 后激活左侧相邻，与 VS Code 一致` |
| 模板注释 | `<!-- 说明 -->` 仅在结构不直观处（嵌套插槽、条件块）使用，避免泛滥 | `<!-- 编辑态才显示保存按钮 -->` |
| 标记 | TODO（待办）/ FIXME（已知缺陷）统一前缀，带简述 | `// TODO: 接入游标分页后移除 limit/offset` |

- **类型优先**：TS 类型能表达的语义不重复写注释；禁止为变量名可读的代码加注释
- **禁止**：逐行废话注释、注释掉的代码（一律删除，需要时从 git 找回）、与代码不同步的过期注释
- 组件 props 定义处逐项注释（编辑器悬停提示即组件文档）；emit 事件说明触发时机
- 注释随代码变更同步更新；组件职责变化必须同步文件头注释

## 5. Vue 组件规范 <a id="component"></a>

### 5.1 SFC 结构 <a id="component-sfc"></a>

- 组合式 API（`<script setup lang="ts">`）；组件名 PascalCase 单数名词；文件名与组件名一致
- 需要被 keep-alive 缓存的组件显式声明 name
- SFC 顺序：template → script → style（scoped）；样式类名 kebab-case（BEM 简化）
- 逻辑提取：组件内逻辑超过约 200 行拆组合式函数（同级组合式或工具目录）

### 5.2 props / emit 约定 <a id="component-props"></a>

- props 用 withDefaults + 类型定义；事件名 kebab-case（如 `open-detail` / `title-change`）；emit 显式声明
- 列表页与表单页通过框架组件约定事件交互（见第 8 节），禁止跨组件直接访问内部状态
- 表单页 expose 脏数据状态供框架组件拦截确认

## 6. 状态管理（Pinia） <a id="store"></a>

- store 命名 `use + 模块 + Store`；按模块拆分，禁止单一巨型 store
- 服务端数据不重复存 store（列表/详情数据由页面组件管理，store 只存会话、权限、配置等全局态）
- 页签状态为模块级组合式（非 store）：唯一来源为核心页签能力 + 绑定包投影，宿主经装配适配桥接路由联动 / 缓存键 / 本地持久化（键统一 `bms_` 前缀）

## 7. 动态菜单与权限 <a id="perm"></a>

- 菜单树由后端按权限动态下发（含 locale 翻译），前端动态注册路由与生成侧边栏，禁止硬编码路由表
- 按钮显隐：权限指令（默认无按钮权限，支持任一满足 / 全部满足 / 取反）；字段权限按表单元数据可见 / 可编辑状态渲染
- 路由守卫：校验登录态与权限码，无权限跳 403 页（或首页）；地址栏直达无权限路由同样拦截
- 权限码变更（角色/授权）后刷新权限缓存（后端版本号机制），前端重新拉取菜单
- **实现口径（强制）**：权限码集合与判定**唯一来源为核心权限能力**（绑定包提供投影）；应用态 store 只做集合 / 菜单 / 版本 / 加载编排，不得另建判定；无权限移除 DOM、权限恢复回插；脚本场景经宿主权限工具 → 插件注入点（宿主装配注入）；路由守卫注册与 403 页随后续任务。落点见《[前端基类清单](../前端基类清单.md)》。

## 8. 布局与框架组件约定 <a id="layout"></a>

### 8.1 Tab 与路由 <a id="layout-tabs"></a>

- 顶层 Tab 由页签能力管理：激活 Tab 同步路由 push；前进/后退驱动激活；直接访问先建后激活（详见《主框架布局设计》）
- Tab 标题取菜单名（locale 翻译）/路由 meta 标题，不直接用路由 name；按白名单过滤可建 Tab 的路径
- 本地持久化键统一 `bms_` 前缀

### 8.2 FormFrame / FormDetailPanel <a id="layout-frame"></a>

- 实体页面路由组件统一用表单框架组件（路由 props 注入标题 / 列表组件 / 详情组件）
- 视图名 → 组件映射经插件注入点解析（宿主装配接入路由视图工具；未注册回退占位视图并开发态告警，防菜单配置错误白屏）
- 表单页复用明细面板组件（只读/编辑分态、信息栏、主表+明细）；简单表单可自行实现
- 表单内 Tab 为页面内部状态（框架组件内维护），不参与顶层页签与持久化

### 8.3 列表页 / 表单页约定 <a id="layout-list-form"></a>

- 职责分离：列表页与表单页独立组件文件，仅通过约定事件交互（打开详情 / 已保存 / 已删除 / 标题变更 / 拉取列表 / 脏数据）
- 列表页公共逻辑（分页/查询/刷新）与异步状态、竞态处理优先复用通用组合式与规则工厂（落点见《前端基类清单》）
- 列表页无操作列，双击行打开详情（移动端点击进入）；分页 `page` / `size` + 筛选参数
- 保存：整体提交主表+明细（单事务）；携带 version 乐观锁；保存后刷新列表
- 脏数据保护：切换/关闭 Tab 前确认（详情见《表单框架布局设计》）

## 9. 样式规范 <a id="style"></a>

- SCSS + UI 库主题变量定制；避免引入重型 CSS 方案
- 设计令牌：唯一来源为宿主令牌文件（落点见《[前端基类清单](../前端基类清单.md)》）——基础令牌分组（颜色 / 字体 / 间距 / 圆角 / 阴影）+ 尺寸与密度档位；间距用数字步进；组件只消费令牌语义变量，**不得硬编码色值与尺寸**；UI 库主题变量由令牌映射（色阶运行时派生）；**新增令牌先登记后使用**
- 深色/浅色主题：CSS 变量驱动切换，主题偏好持久化 + 本地临时态
- 类名 kebab-case（BEM 简化）；组件内样式 scoped；全局样式仅放全局变量/混入
- 空态与加载分级：空状态优先**文案引导**（空态组件按场景矩阵；插画统一按插件资产约定，kebab-case，不内联大段 SVG）；首屏用骨架屏、局部刷新用内容遮罩（防闪）、按钮提交用按钮内 loading；错误页**不展示技术堆栈**，独立路由 403 / 500 与未知路径兜底 404
- 移动端：postcss px→vw 视口适配（设计稿 375、保留 1px，兼容问题可切 rem）+ 安全区变量
- **浏览器能力降级**：基线为现代浏览器；关键能力缺失一律提供降级态——全屏 API 不可用 / 被拒 → 固定铺满降级；`aspect-ratio` 不支持 → padding-top 技巧；尺寸 / 交叉观察器缺失 → 尺寸回调 / 直接渲染降级

## 10. 国际化 <a id="i18n"></a>

- 文案不硬编码：vue-i18n 语言包运行时从后端拉取（服务端缓存 + 本地二次缓存）
- i18n key 点分：`模块.页面.字段`；错误码按 `error.{code}` 映射
- RTL 布局按语言的 RTL 标记切换；时间/数字按用户时区与 Intl 本地化
- **实现口径（强制）**：格式化一律走 `Intl`、按用户时区 / locale、空值与非法值占位（默认基准经宿主注入）；校验规则工厂空值跳过、必填独立；格式化器注册表随展示域回补波按新体系重建。落点见《[前端基类清单](../前端基类清单.md)》。

## 11. 请求封装 <a id="http"></a>

- 统一实例：请求拦截器注入访问令牌（仅存内存）；响应拦截器统一处理 `{code, message, data}`
- 请求统一经封装入口解开统一响应结构；模块 API 继承请求基类，禁止绕过基类裸用请求库
- 401 静默刷新（刷新令牌轮换）；刷新失败跳登录；会话失效强制登出
- 统一错误提示；业务错误码映射 i18n 文案
- 写接口带幂等键；列表接口统一分页参数
- **实现口径（强制）**：请求层两宿主同契约（核心不依赖 UI 库与路由）；提示 / 登录与 403 跳转 / 刷新处理器经各端入口注入；**未注入刷新处理器时 401 按会话失效占位**（清会话 + 跳登录、不发请求）；业务错误码在请求层判定并抛业务错误（继承核心错误基类），文案走 i18n；请求基类继承核心根系，写方法自动生成幂等键。落点见《[前端基类清单](../前端基类清单.md)》。

## 12. 测试 <a id="test"></a>

- 单元/组件测试统一放 `tests/`（与 src 分离），文件 `模块.spec.ts`；覆盖核心组件与组合式函数
- 组件测试统一用测试基座（预挂状态管理 / 国际化，可选路由）
- E2E：功能描述命名；覆盖登录、RBAC 权限（按钮显隐与字段权限）、核心 CRUD 主流程
- E2E 环境：CI 服务容器起后端与前端产物
- 组件测试断言：渲染、事件、权限指令行为

## 14. 构建体积预算 <a id="budget"></a>

- **门禁**：双端构建后统计产物 gzip 体积，与工程阈值配置比较，超限阻断（阈值与脚本见工程说明）；已挂 CI 构建 job
- **阈值口径**：取「当前基线 + 20%」；因需求增长需放宽时，在同一提交中调整阈值配置并说明原因（评审可见）；**历次调整记录随提交与测试记录留痕**（不在本规范维护）
- **定位**：防「悄悄变大」的早期预警，不替代性能优化（缓存、懒加载、拆包按《项目规划说明》性能设计执行）
