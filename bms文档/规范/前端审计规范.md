# 前端审计规范

> 前端合规审计：基类体系 · 组件根 · 能力 · 令牌 · 清单对账 · 契约一致性 · 流程与报告

## 1. 目的与适用范围 <a id="purpose"></a>

规范**前端**（基座包与宿主工程）的**合规审计**：以「机器护栏 + 脚本盘点 + 人工判定」对已交付的前端代码与前端文档做结构性核验，并按「修复 → 回写 → 护栏沉淀 → 复跑」闭环。**审计 ≠ 测试**：测试查「行为正确」（《[测试规范](测试规范.md)》），前端审计查「结构是否按《[前端开发规范](前端开发规范.md)》」；后端对称口径见《[后端审计规范](后端审计规范.md)》。

审计细则**引用式**：《[前端开发规范](前端开发规范.md)》§3（强制用法 / 扩展规则 / 执行护栏）与《[前端基类清单](../前端基类清单.md)》为唯一口径来源（含护栏与落点登记），本规范不重复定义、不列具体实现物明细。

## 2. 审计类型 <a id="types"></a>

| 类型 | 内容 | 主要依据 |
| --- | --- | --- |
| **合规审计**（默认） | 基类体系（继承链 / 能力声明与登记 / 组件根）、命名（类 / 投影 / 能力键 / 文件）、令牌消费、注释齐备、清单对账、依赖方向、契约一致性（同接口多实现） | 《[前端开发规范](前端开发规范.md)》§3 / §4.1 / §9、《[前端基类清单](../前端基类清单.md)》、《[命名规范](命名规范.md)》 |
| 安全审计（前端侧） | 密钥不入前端包、敏感信息展示脱敏、请求层 401 / 403 口径 | 《[安全开发规范](安全开发规范.md)》 |
| 性能审计 | 构建体积门禁、分包与懒加载、长列表与渲染路径 | 《[前端开发规范](前端开发规范.md)》构建体积预算节 |
| 文档审计（前端） | 前端任务目录 / 命名 / 链接自洽 / 公开文档红线 | 《[文档生成规范](文档生成规范.md)》、《[命名规范](命名规范.md)》 |

> 一次审计可覆盖多类型；默认指合规审计。

## 3. 触发时机 <a id="trigger"></a>

1. **阶段收口前（默认）**：阶段内前端交付（组件域 / 页面任务等）收口时执行一次前端合规审计，结论作为收口门禁项之一（与测试报告并列）；
2. **按需**：用户 / 评审要求时；重大重构、架构调整、批量组件交付后；
3. **例外**：纯文档改动或单点修复可不触发（在阶段收口时合并执行）。

## 4. 审计流程 <a id="flow"></a>

```mermaid
flowchart LR
    A["触发（§3）"] --> B["范围界定（对象清单 + 排除项）"]
    B --> C["方法：护栏复跑 + 脚本盘点 + 人工判定"]
    C --> D["问题分级（§7）"]
    D --> E["修复（偏差回写设计后改）"]
    E --> F["回写（设计 / 实施 / 规范 / 计划）"]
    F --> G["护栏沉淀（§8：机器护栏或白名单）"]
    G --> H["复跑（全量验证 + 脚本复核零违规）"]
    H --> I["报告（§6）+ 索引登记"]
```

- **范围界定**：列明审计对象清单与**排除项**（如应用装配层不适用组件根强制、开发专用资产不纳入产物口径），排除必须写明理由；
- **方法三件套**：① 护栏复跑（核心护栏、契约套件与各插件用例，落点见《[前端基类清单](../前端基类清单.md)》）；② 脚本盘点（全量文件级检查，结论可复算）；③ 人工判定（脚本无法判定的语义项，逐处记录依据）；
- **修复原则**：违规必修；修改前**回写设计/规范**（偏差回写口径同《[AI开发规范](AI开发规范.md)》）；修改契约须**双端（多实现）同步**并跑契约套件（若适用）。

## 5. 检查项框架（引用式） <a id="checklist"></a>

检查项**不在本规范写死**，按「维度 + 引用来源 + 执行方式」组织；各端检查明细见附录与本项目历次审计报告：

| 维度 | 引用来源 | 执行方式 |
| --- | --- | --- |
| 继承链（总基类 → 组件根 → 插件基类 → 能力域基类 → 具体组件 / 件；每条链长短不一） | 《前端基类清单》（唯一权威）+ 开发规范 §3 | 护栏 + 人工 |
| 能力声明与登记（能力类继承、依赖登记、键名规范） | 同上 | 护栏（核心）+ 人工 |
| 组件根调用（UI 组件必须挂组件根取得通用属性与令牌协议） | 开发规范 | 组件契约套件 + 人工 |
| 令牌消费（禁硬编码色值；尺寸白名单） | 设计令牌文档 + 开发规范 | 脚本盘点 + 人工 |
| 清单对账（基类清单 ↔ 能力登记 ↔ 插件导出双向） | 前端基类清单 | **护栏待重建**（候选） |
| 依赖方向（宿主 → 插件 → 核心；核心零框架依赖；能力不反向 / 不循环） | 开发规范 | 核心护栏 + 人工 |
| 命名（核心类 / 投影 / 能力键 / 文件 / 标识符） | 《[命名规范](命名规范.md)》 | 脚本 + 人工 |
| 注释齐备（模块头职责 / 导出与模块内定义 JSDoc / 类与接口成员 JSDoc / 复杂逻辑行注释） | 《[前端开发规范](前端开发规范.md)》§4.1 | 核心护栏（注释齐备用例）+ 脚本盘点 + 人工 |
| 契约一致性（同一契约多实现跑同一套断言） | 产品口径（同接口多实现） | 契约套件 |
| 文档（目录 / 链接 / 清单 / 公开红线） | 《[文档生成规范](文档生成规范.md)》 | 脚本（基座校验 / 链接校验） |

## 6. 报告规范 <a id="report"></a>

| 项 | 约定 |
| --- | --- |
| 落点 | 阶段级审计报告放 `项目/<阶段>/审计/`；**审计资产台账与跨阶段审计文档一律放 `bms文档/审计/`**（前端见《[前端资产清单](../审计/01_审计_前端资产清单.md)》） |
| 命名 | `<NN>_审计_<主题>.md`（`NN` 两位序号） |
| 结构 | ① 审计信息（日期 / 人 / 触发 / 范围与排除 / 依据 / 方法 / 结论）；② 结果逐类（对象 × 审计点 × 结果）；③ 违规与修复（位置 / 修复 / 回写）；④ 分级处置（违规 / 白名单 / 机会项）；⑤ 护栏补强；⑥ 复跑证据；⑦ 遗留与去向 |
| 索引 | 报告在所属阶段 README「文档索引」登记一行；阶段收口回写时引用结论 |
| 入库 | 报告与证据（截图等）随仓库提交（二进制证据放报告同级「资源」目录） |

> 报告中的**对象与执行明细**（具体目录、文件、护栏名）属实现侧事实，随报告留痕；规范侧只给维度与引用来源。

## 7. 问题分级与处理 <a id="grade"></a>

| 分级 | 判定 | 处理 |
| --- | --- | --- |
| **违规** | 违反开发规范**强制口径**（如未挂组件根、硬编码色值、未登记能力） | **必修**（回写设计后修复 + 护栏 / 契约套件拦截同类） |
| **偏离** | 与参考口径 / 设计节点不一致但非强制（如档位命名差异、视觉常量） | 评估修复或**登记去向**（设计对齐记录 + 计划 §3.1） |
| **机会项** | 优化空间（动画 / 性能 / 精细度） | 登记计划 §3.1（明确归口与时点） |
| **白名单** | 结构性常量豁免（1px 描边 / 断点 / 递归缩进 / 运行时内联值等） | 写入《[前端开发规范](前端开发规范.md)》§3.1 尺寸硬编码白名单，色值不设豁免 |

## 8. 护栏沉淀（强制） <a id="guard"></a>

- 审计修复的**每一类违规**必须沉淀为机器护栏（新规则或扩大既有护栏扫描面）：核心护栏、契约用例与插件用例的落点见《[前端基类清单](../前端基类清单.md)》，随 CI 与双端测试门禁执行；
- 护栏规则需配 **fixture 拦截用例**（构造违规样例断言被拦），与正向「全绿」用例成对；
- 暂无法机器化的检查项（如语义判定）在报告中标注「人工项」，并在下次审计复跑时复核；
- 护栏与白名单的口径变更须同步宿主规范与历次审计报告（报告只增不改，变更以新报告 / 规范修订记录）。
