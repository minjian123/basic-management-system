## 1. 目的与适用范围 <a id="principles-purpose"></a>

规范本项目数据库的**强制口径**与**数据库设计文档体系**，保证 MySQL 8 / PostgreSQL 16 / 达梦 DM8 三库方言兼容（CI 三库测试要求）。命名约定见《[命名规范](命名规范.md)》「数据库命名」节，本文档在其基础上约束写法。

- 本规范只写**强制口径与文档体系规则**；**字段级设计与方言差异细节不在此重复**——其唯一事实源见第 2 节，本规范逐节给出指向。
- 冲突时以本规范（强制口径）为准，并按第 2 节「变更传导」回写对应事实源文档。

**变更传导（强制）**：

1. 表结构变更：**先改表文件**（追加「变更记录」）→ 改 ORM 模型 → 生成 Alembic 迁移（第 5 节）→ 回写总览登记状态与表文件状态。
2. 通用约定变更：先改《数据规范》→ 再改受影响表文件与模型 → 再改迁移。
3. 方言差异变更：先改对应方言特性文档（标注「实测」或「待验」）→ 再改引用方；**未实测结论不得写入表文件或规范**。
4. 三处一致性（表文件 ↔ 总览登记 ↔ 目录）由 `scripts/tools/base-check/check-base.py` 断言；迁移与模型零漂移见第 5 节。

## 3. 表与字段口径 <a id="principles-table"></a>

- 表前缀：平台域固定 `sys_`（系统 / 权限）、`wf_`（工作流）、`rpt_`（报表）、`ai_`（AI 域）；产品业务表用各模块独立前缀（注册制：先登记于平台模块登记表再建表，唯一性由启动与 CI 校验，登记表见平台《项目规划说明》「平台扩展接入流程」节；产品示例：biz `pur_`/`pay_`/`sup_`/`sale_`/`wh_`、cw `cw_`）；表名单数 snake_case。
- 主键统一 `id`（雪花 ID，应用侧生成，**禁用数据库自增列**）；关联表联合主键、不设 `id`。
- **公共字段**统一由 ORM 模型基类提供（`id` / 审计四字段 / `deleted_at` / `version`），关联表是否带审计与软删除按表文件声明；字段级约定（类型、可空、默认、填充时机）见《数据规范》「公共字段」节。
- **类型口径**：设计侧只写三库通用类型（`BIGINT` / `VARCHAR(n)` / `DATETIME` / `TEXT` / `BOOLEAN` / `DECIMAL(20,4)` / `JSON`）与逻辑类型，**禁止方言专用类型**；各库实际落点见《数据规范》「类型映射与字段约定」节与对应方言特性文档。
- 金额用 `DECIMAL(20,4)`，**禁止 FLOAT / DOUBLE**；状态、类型配字典管理（不写死魔法值）；字符串长度显式声明；大字段（BLOB/TEXT/JSON）独立成表或明确评估。
- 表与字段必须带 COMMENT（中文）。
- 时间统一 UTC 存储、命名 `xxx_at`；禁止以数据库端时间函数（`NOW()` / `SYSDATE` 等）作为业务语义来源。
- 多语言文案不入主表：由 `{主表}_i18n` 附表承载（结构与唯一约束见《数据规范》「多语言与 i18n 附表」节）。
- API 序列化：主键 / 外键以**字符串**输出（雪花 ID 超 JS 安全整数，见《[API接口规范](API接口规范.md)》「统一响应」节），入参字符串转 `int`；数据库与索引保持 BIGINT。

## 4. 索引口径 <a id="principles-index"></a>

- 命名：普通索引 `idx_字段`（多列 `idx_a_b`）、唯一索引 `uq_字段`；**索引名须含表名**（`idx_{表}_{列}`）——PostgreSQL / 达梦下索引名在库 / 模式内唯一，短名跨表冲突；ORM `index=True` 由元数据命名约定生成该形态。
- 建索引的列：**排序字段**（进排序白名单的字段必须建索引，由后端「排序字段索引配合」断言工具校验）、逻辑外键列、数据权限与租户过滤列、软删除参与条件时的 `deleted_at`。
- 唯一约束统一 `(唯一字段, deleted_at)` 复合唯一（软删除后释放唯一键）；**禁止冗余索引**；每表索引 ≤ 5 个（联调阶段从严）。**达梦下该口径不成立**（已实测：达梦视复合唯一中的 NULL 相等，未删行不能共存）——差异与兜底归口见《数据库设计 · 方言特性》达梦文档（`bms文档/设计/数据库设计/方言特性/03_DM8.md`）与对应任务记录；定案前**不得按方言在应用层各写一套**。
- **无物理外键**：逻辑外键写 `目标表.字段` 并注明是否同库。
- 公共软删除索引与各库索引能力差异（部分索引 / 前缀长度 / 改名语法等）见《数据规范》「索引与唯一约束」节与对应方言特性文档。

## 5. 迁移与建表口径 <a id="principles-migration"></a>

- 所有结构变更走 Alembic 迁移脚本，**禁止手工 DDL**（开发库可临时，但必须随后补迁移）；迁移文件命名按迁移工具自动生成的「修订号 + 描述」形态，提交信息 `feat(db): ...`。
- **按数据源分链维护**：迁移脚本按平台库 / 租户库 / 归档库分目录存放（`alembic/versions/<链名>/`），链内编号独立（从 `0001` 起）、链首声明 `branch_labels=("<链名>",)`，并在 `alembic.ini` 登记配置段 `[alembic:<链名>]`；命令 `alembic -n alembic:<链名> upgrade head`（缺省 `[alembic]` 段 = 租户链）。
- **一套方言无关脚本在三库执行**：脚本内不写方言 SQL；达梦注意 schema 前缀（库级隔离用模式，命令加 `-x schema=<模式名>`，迁移前切换会话当前模式）——方言执行差异见《方言特性》各库文档。
- **零漂移**：迁移脚本须与 ORM 模型元数据一致（逐链 autogenerate 比对断言，防列 / 索引 / 唯一约束漂移）。
- **建库 / 删库 / 批量迁移**：库级建删经基座能力（`ops/db_admin.py`：MySQL / PostgreSQL 建删库、SQLite 建删文件、达梦建删模式，幂等且不擅动既有对象）；批量迁移 `ops/migrate_tenants.py`（平台 + 各租户 + 归档，失败不中断 + 汇总）；新租户初始化 `ops/init_tenant.py`（建库 → 迁移 → 幂等种子）；迁移执行一律经基座入口（`alembic_config` / `head_revision` / `upgrade_chain`），运维脚本不得各自拼装 Alembic 配置。
- **三库测试库流程（CI 与本地同一路径）**：`ops/test_db.py` 为测试对象唯一事实源（每方言**平台 + 租户两对象**：库 / 达梦模式；库名须与 CI 变量逐字一致）——`create --execute` 幂等建库 / 建模式 + 建测试账号与最小授权（MySQL 库级 `bms_test%` 的 `ALL`、PostgreSQL 角色 `CREATEDB`、达梦以 `SYSDBA` 承载），**PostgreSQL 由管理员建库后须转属主**（15+ `public` 模式默认不授予非属主 `CREATE`）；`migrate --execute` 按对象分链（平台对象 `platform` 链、租户对象 `tenant` 链）；`drop --execute` 幂等清理（失败路径先导现场再清理）；未配置连接串即失败（不静默跳过）。达梦建删模式用「去模式段」连接串 + 显式模式名，迁移加 `-x schema=<模式名>`。
- SQLite 开发库由启动期自动建表（按迁移链表集、不依赖迁移脚本）；真库一律走迁移。
- **新建表前置**：先在《数据库设计总览》登记（表文件创建 + 「已设计数据表登记」登记）再生成迁移，未登记视为未定稿（第 9.1 节）。
- CI 三库测试流程：job 内建测试前缀库 → 迁移 → 集成测试 → 删库（复用常驻三库，见平台《开发部署规划》「常驻数据库」节）。
- 数据变更（种子、修复数据）单独脚本，与结构迁移分离，可重复执行（幂等）。

## 6. SQL 口径（三库兼容） <a id="principles-sql"></a>

- SQL 一律参数化（ORM 传参），**禁止字符串拼接**（防注入，见《[安全开发规范](安全开发规范.md)》）；ORM 为主（SQLAlchemy），原生 SQL 仅限复杂统计且必须三库测试。
- 分页统一 `LIMIT/OFFSET` 语法（三库均支持），参数 `page/size`；**禁止 MySQL 方言 `LIMIT a, b`**；页码限深（默认 100 页、可配置），超限按参数非法拒绝；大数据量列表用 keyset 游标分页兜底。
- **排序**：字段须经排序白名单校验且已建索引（第 4 节）；四库 NULL 位次统一为「**NULL 恒排末位**」（以 `IS NULL` 排序键实现，**禁止写 `NULLS FIRST/LAST`**——MySQL 不支持该语法）；以主键兜底保证稳定序。
- 避免方言函数：`GROUP_CONCAT` / `STRING_AGG`（字符串聚合）、`DATE_FORMAT` / `to_char`（日期格式化）等各库形态不一；时间由参数化传入；字符串拼接（`CONCAT` / `||`）须评估各库差异。
- 标识符统一小写（达梦默认大写存储，引用时注意）；布尔 / 空值用 `= 0/1` 或显式 `IS NULL`，**禁止方言布尔字面量**。
- 禁止 `SELECT *`；批量写入用 bulk 且分批提交（第 8 节）。
- 各库具体差异（含未实测项）见《方言特性》对应库文档。

## 7. 多租户与分片口径 <a id="principles-tenant"></a>

- 库拓扑：平台库 + 租户库（库名按租户编码派生）+ 归档库（只读），开发环境单库（库命名见《[命名规范](命名规范.md)》「数据库命名」节）；表归属与迁移链见《数据规范》「库划分与迁移归属」节。
- 租户隔离优先库级（一租户一库）；同库场景所有表必须含 `tenant_id` 且查询强制过滤。
- 分片键：语义名 `tenant` / `date`；分片表预创建由定时任务维护；查询强制带分片键条件（缺分片键拒绝执行或告警）。
- 跨库查询禁止 JOIN，改服务层聚合或事件同步（机制见《架构设计 · 数据访问与分片》「分片路由」节；分片与归档的字段级约定见《数据规范》「分片与归档」节）。

## 8. 性能口径 <a id="principles-perf"></a>

- 新增 / 修改查询需 EXPLAIN 确认走索引；禁止全表扫描的列表查询。
- 列表查询禁止 N+1（ORM 关系预加载 selectin / joinedload）。
- 批量写（导入、归档）分批提交（每批 ≤ 500 行），禁止单事务超大集合。
- 慢查询（> 1s）登记并优化；三库均开启慢查询日志（开发环境已配置）。

## 9. 数据库设计文档体系 <a id="docs"></a>

数据库设计采用「总纲 + 节点文件 + 表文件 + 方言特性文件」结构，事实源与变更传导见第 2 节。

### 9.1 数据表文件组织 <a id="docs-table-org"></a>

为防止表结构在设计文档中分散维护、相互冲突，数据表设计统一集中、单点维护：

- **集中存放**：全部数据表设计放在 `bms文档/设计/数据库设计/数据表设计/`，**一张表一个文件**，文件名为 `{表名}.md`（如 `sys_tenant.md`）；禁止在架构、概要、需求、任务等文档内散落字段清单。
- **表文件结构**：归属库与模块 → 上游依据 → 字段表（字段 / 类型 / 可空 / 约束 / 说明）→ 索引与约束 → 分片 / 归档 / 迁移说明；公共字段（雪花 ID / 审计 / 软删除 / 乐观锁）随 ORM 模型基类 约定列出。
- **统一引用**：其他文档需要表结构时，一律用相对链接指向对应表文件（首次提及给可点击链接），**不复制字段清单**；表结构只在表文件单点维护。
- **登记**：表文件创建后须在《数据库设计总览》（`bms文档/设计/数据库设计/01_数据库设计_总览.md`）「已设计数据表登记」节登记（表名 → 文件链接 → 所属库 / 模块 → 状态），**表文件状态与登记状态保持一致**；未登记视为未定稿；一致性由基座校验脚本断言（第 2 节）。
- **变更传导**：表结构变更先改表文件（并追加「变更记录」），再改引用方与 Alembic 迁移（见第 5 节），保证「表文件为唯一事实源」。

### 9.2 数据表文件规范 <a id="docs-table-spec"></a>

数据表文档（`数据表设计/{表名}.md`）描述**一张表**的字段级结构，是全库表结构的唯一事实源。格式遵循《文档生成规范》，组织与登记遵循第 9.1 节。

#### 9.2.1 结构与必备章节 <a id="docs-table-spec-structure"></a>

固定五节，顺序固定、锚点固定；按需可增补可选章节：

| # | 章节               | 锚点        | 内容                                                  |
| - | ------------------ | ----------- | ----------------------------------------------------- |
| 1 | 归属与依据         | `meta`    | 归属库 / 模块 / 上游依据 / ORM 模型 / 状态 / 相关节点 |
| 2 | 字段               | `fields`  | 字段表（含ORM 模型基类 公共字段）                    |
| 3 | 索引与约束         | `index`   | 索引 / 约束表与逻辑外键说明（**只列业务索引**，公共软删除索引见《数据规范》） |
| 4 | 分片 / 归档 / 迁移 | `storage` | 分片键、归档策略、迁移归属                            |
| 5 | 变更记录           | `revlog`  | 每次结构变更的日期 / 版本 / 变更 / 作者               |

- 可选扩展章节：ER 关系（`relations`）、示例数据（`samples`）等，置于固定五节之后。
- 标题：1 级标题固定「`{表名}`（{中文名}）」；正文首部带面包屑（文档首页 › 数据库设计总览 › 已设计数据表登记 › 表名）。

#### 9.2.2 归属与依据 <a id="docs-table-spec-meta"></a>

- 元信息表固定字段：归属库、覆盖模块、上游依据、ORM 模型、状态、相关节点。
- **状态四值**（与《数据库设计总览》「已设计数据表登记」一致，禁止自造取值）：
  - `已设计`：字段级结构已定稿，尚未排入迁移；
  - `待落库`：已排入迁移、待执行建表；
  - `已落库`：迁移已执行、表已存在；
  - `已废弃`：停止使用（保留历史与原因说明）。
- 上游依据须写章节名（可追溯至规划 / 架构 / 需求），首次提及其它文档给可点击链接。

#### 9.2.3 字段 <a id="docs-table-spec-fields"></a>

- 字段表五列固定：**字段 / 类型 / 可空 / 约束或默认 / 说明**。
- 继承 ORM 模型基类 的公共字段（`id` / 审计 / 软删除 / `version`）**逐行列出**，并在说明列标注「审计」「软删除」「乐观锁」等；语义不重复展开（统一见《数据规范》「公共字段」节）。
- 类型用三库通用类型（大写，如 `BIGINT` / `VARCHAR(64)` / `DATETIME` / `TEXT` / `BOOLEAN` / `DECIMAL(20,4)`），禁用方言专用类型。
- 字段顺序：`id` → 业务字段 → 公共字段；金额用 `DECIMAL/NUMERIC`，状态 / 类型配字典。

#### 9.2.4 索引与约束 <a id="docs-table-spec-index"></a>

- 表列：**名称 / 类型（主键 / 唯一 / 普通）/ 列 / 说明**；命名遵循第 4 节（`idx_字段` / `uq_字段`，含表名）。
- **只列业务索引**：公共软删除索引 `idx_{表}_deleted_at` 由元数据命名约定生成，统一见《数据规范》「索引与唯一约束」节，表文件不重复列出。
- 无物理外键；逻辑外键须注明指向（`目标表.字段`）与是否同库。

#### 9.2.5 分片 / 归档 / 迁移 <a id="docs-table-spec-storage"></a>

逐项写明：分片（是否按月分片、分片键与物理表名规则）、归档（是否归档、依据的归档策略）、迁移（随平台库 / 租户库 / 归档库 Alembic 链、真实迁移归属节点；骨架表注明「本阶段仅结构声明，不建表」）。

#### 9.2.6 变更记录 <a id="docs-table-spec-revlog"></a>

- 表列：**日期 / 版本 / 变更 / 作者**；新建表首行登记。
- 表结构每次变更追加一行，与 Alembic 迁移一一对应；禁止只改字段表不留记录。

### 9.3 数据库设计节点与方言特性文档规范 <a id="docs-node-spec"></a>

**节点文件**（`设计/数据库设计/`）：

| 项 | 约定 |
| --- | --- |
| 总览 | `01_数据库设计_总览.md`（体系定位 / 设计依据 / 数据分布 / 通用规范 / 表清单总表 / 文档结构 / 登记与一致性核对） |
| 数据规范 | `02_数据库设计_数据规范.md`（字段级通用约定唯一事实源；公共字段 / 类型映射 / 时间 / 多语言 / 索引约束 / 分片归档 / 库划分与迁移） |
| 模块节点 | `{编号}_数据库设计_{模块名}.md`，与《概要设计》模块**一一对应**，编号顺延、不与既有编号冲突；以「模块有哪些表」为索引，字段级结构仍以表文件为准 |

**方言特性文档**（`设计/数据库设计/方言特性/`）：

| 项 | 约定 |
| --- | --- |
| 组织 | **一库一文件**：`{序号}_{库名}.md`（如 `01_MySQL.md` / `02_PostgreSQL.md` / `03_DM8.md`）；新增目标库顺延编号，并在总览「方言特性登记」登记 |
| 固定章节 | 归属与依据（`meta`）→ 类型映射（`type`）→ DDL 与对象差异（`ddl`）→ 空值与排序（`null`）→ 标识符与模式（`identifier`）→ 索引与约束（`index`）→ 事务与连接（`tx`）→ 实测记录（`measured`）；顺序与锚点固定 |
| 结论标注 | 每条结论标注「**实测**」（已真库验证，注明日期与证据）或「**待验**」（实施前须实测并回写）；**未实测结论不得写入表文件或本规范** |
| 记录口径 | 实测记录节按「日期 / 项 / 结论 / 证据」登记；迁移、建删库、类型映射等结论与详细设计 / 实施记录一致 |

## 10. 检查清单 <a id="principles-checklist"></a>

- □ 表前缀 / 字段命名符合《命名规范》，含审计字段与 COMMENT；表结构已在《数据库设计总览》登记（表文件状态与登记状态一致）
- □ 字段类型三库通用，无方言专用类型；各库落点已核对对应方言特性文档
- □ 索引命名合规（含表名）、只列业务索引、数量与冗余合规
- □ 结构变更已生成 Alembic 迁移（分链）并在三库通过，且与模型元数据零漂移
- □ 公共字段 / 多语言附表 / 分片与归档约定符合《数据规范》（未在表文件重复展开）
- □ SQL 参数化、方言兼容、分页与排序口径统一（白名单 + NULL 末位 + 限深）
- □ 租户隔离与分片键处理正确，无跨库 JOIN
- □ 列表查询无 N+1，EXPLAIN 走索引
- □ 涉及方言差异的结论均标「实测」或「待验」，且已回写对应方言特性文档
