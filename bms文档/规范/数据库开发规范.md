## 1. 目的与适用范围 <a id="purpose"></a>

规范本项目数据库的表设计、索引、迁移与 SQL 编写，保证 MySQL 8 / PostgreSQL 16 / 达梦 DM8 三库
方言兼容（CI 三库测试要求）。命名约定见《[命名规范](命名规范.md)》「数据库命名」节，本文档在其基础上
约束结构与写法。

## 2. 表结构设计 <a id="design"></a>

- 表前缀：平台域固定 `sys_`（系统/权限）、`wf_`（工作流）、`rpt_`（报表）、`ai_`（AI 域）；产品业务表用各模块独立前缀（注册制：先登记于平台模块登记表再建表，唯一性由启动与 CI 校验，登记表见平台《项目规划说明》「平台扩展接入流程」节；产品示例：biz `pur_`/`pay_`/`sup_`/`sale_`/`wh_`（采购/收付款/供应商/销售/仓储）、cw `cw_`）；表名单数 snake_case。
- 主键统一 `id`；关联表联合主键、不设 id。
- 每表必备审计字段：`created_at`、`created_by`、`updated_at`、`updated_by`；软删除表加 `deleted_at`、并发控制加 `version`。
- 金额用 DECIMAL/NUMERIC，禁止 FLOAT/DOUBLE；状态、类型用 `status`、`type` 短整型或枚举，配合字典管理（不写死魔法值）。
- 大字段（BLOB/TEXT/JSON）独立成表或明确评估：主表行宽保持可控，避免索引失效。
- 表与字段必须带 COMMENT（中文），与平台《项目规划说明》「数据规范」一致。

## 3. 字段规范 <a id="field"></a>

| 类别      | 约定                                                                          | 示例                         |
| --------- | ----------------------------------------------------------------------------- | ---------------------------- |
| 主键      | `id`（BIGINT，应用侧按雪花算法生成；跨库统一，禁用数据库自增列） | `id`                       |
| 外键      | `目标表名_id`；逻辑外键为主（避免物理外键拖累性能），必要时加索引           | `dept_id`、`role_id`     |
| 布尔      | `is_` 前缀（tinyint/smallint/BOOLEAN）                                      | `is_enabled`               |
| 时间      | `xxx_at`（DATETIME/TIMESTAMP，统一存储时区时间）                            | `expired_at`               |
| 枚举/状态 | 字典表管理，字段存 code 字符串或短整型                                        | `status`、`subject_type` |
| 通用      | `sort`、`remark`、`version`                                             | —                           |

> 字段类型尽量三库通用：字符串 VARCHAR、整数 BIGINT/INT、金额 NUMERIC(20,4)；避免 MySQL 专用 `ENUM`/`JSON`、PG 专用 `SERIAL` 等方言类型。
>
> API 序列化：主键/外键以**字符串**输出（雪花 ID 超 JS 安全整数；见《[API接口规范](API接口规范.md)》「统一响应」节），入参字符串转 `int`；数据库与索引保持 BIGINT。

## 4. 索引规范 <a id="index"></a>

- 普通索引 `idx_字段`（多列 `idx_a_b`）、唯一索引 `uq_字段`。
- 外键列、高频查询过滤列、排序列（`sort`、`created_at`）建索引；复合索引遵循最左前缀。
- 禁止冗余索引（已有 `idx_a_b` 不再建 `idx_a`）；索引数量每表不超过 5 个（联调阶段从严）。
- 软删除查询注意 `deleted_at` 参与条件；大表按分片键设计索引（见第 7 节）。

## 5. 迁移规范（Alembic） <a id="migrate"></a>

- 所有结构变更走 Alembic 迁移脚本，禁止手工 DDL（开发库可临时，但必须随后补迁移）。
- 迁移文件命名按迁移工具自动生成的「修订号 + 描述」形态，提交信息 `feat(db): ...`。
- **按数据源分链维护**：迁移脚本按平台库 / 租户库 / 归档库分目录存放（`alembic/versions/<链名>/`），链内编号独立（从 `0001` 起）、链首声明 `branch_labels=("<链名>",)`，并在 `alembic.ini` 登记配置段 `[alembic:<链名>]`；命令 `alembic -n alembic:<链名> upgrade head`（缺省 `[alembic]` 段 = 租户链）。
- 迁移脚本必须三库可执行：不写方言 SQL；达梦注意 schema 前缀（库级隔离用模式，命令加 `-x schema=<模式名>`，迁移前切换会话当前模式）。
- **零漂移**：迁移脚本须与 ORM 模型元数据一致（逐链 autogenerate 比对断言，防列 / 索引 / 唯一约束漂移）。
- **建库 / 删库 / 批量迁移**：库级建删经基座能力（`ops/db_admin.py`：MySQL / PostgreSQL 建删库、SQLite 建删文件、达梦建删模式，幂等且不擅动既有对象）；批量迁移 `ops/migrate_tenants.py`（平台 + 各租户 + 归档，失败不中断 + 汇总）；新租户初始化 `ops/init_tenant.py`（建库 → 迁移 → 幂等种子）。
- SQLite 开发库由启动期自动建表（按迁移链表集、不依赖迁移脚本）；真库一律走迁移。
- CI 三库测试流程：job 内建测试前缀库 → 迁移 → 集成测试 → 删库（复用常驻三库，见平台《开发部署规划》「常驻数据库」节）。
- 数据变更（种子、修复数据）单独脚本，与结构迁移分离，可重复执行（幂等）。

## 6. SQL 编写（三库兼容） <a id="sql"></a>

| 事项       | 要求                                                        | 反例                                        |
| ---------- | ----------------------------------------------------------- | ------------------------------------------- |
| 分页       | 统一 LIMIT/OFFSET 语法（三库均支持）；分页参数`page/size` | MySQL 方言`LIMIT a, b`                    |
| 字符串拼接 | 避免方言函数（CONCAT 三库支持）；达梦用`\|\|` 需评估        | `GROUP_CONCAT`/`STRING_AGG`（各库不同） |
| 日期       | 参数化传入时间戳/ISO 字符串，避免`NOW()` 差异             | `DATE_FORMAT`/`to_char` 混用            |
| 大小写     | 标识符统一小写；达梦默认大写存储，查询时注意引用            | 混合大小写列名                              |
| 布尔/空值  | 用`= 0/1` 或显式 `IS NULL`，不用方言布尔字面量          | MySQL`TRUE` 与 PG `TRUE` 语义           |

- SQL 一律参数化（ORM 传参），禁止字符串拼接（防注入，见《[安全开发规范](安全开发规范.md)》）。
- ORM 为主（SQLAlchemy），原生 SQL 仅限复杂统计且必须写方言兼容版本并在三库测试。

## 7. 多租户与分片 <a id="tenant"></a>

- 库拓扑：平台库 + 租户库（库名按租户编码派生）+ 归档库，开发环境单库（库命名见《[命名规范](命名规范.md)》「数据库命名」节）。
- 租户隔离优先库级（一租户一库）；同库场景所有表必须含 `tenant_id` 且查询强制过滤。
- 分片键：语义名 `tenant` / `date`；分片表预创建由定时任务维护（孤儿分片清理见规划）。
- 跨库查询禁止 JOIN，改服务层聚合或事件同步（见平台《架构设计 · 多租户路由》）。

## 8. 性能要求 <a id="perf"></a>

- 新增/修改查询需 EXPLAIN 确认走索引；禁止全表扫描的列表查询。
- 列表查询禁止 N+1（ORM 关系预加载 selectin/joinedload）。
- 批量写（导入、归档）分批提交（每批 ≤ 500 行），禁止单事务超大集合。
- 慢查询（> 1s）登记并优化；三库均开启慢查询日志（开发环境已配置）。

## 9. 检查清单 <a id="checklist"></a>

- □ 表前缀/字段命名符合《命名规范》，含审计字段与 COMMENT
- □ 字段类型三库通用，无方言专用类型
- □ 索引命名与数量合规，无冗余索引
- □ 结构变更已生成 Alembic 迁移并在三库通过
- □ 表结构已在《数据库设计总览》「已设计数据表登记」登记，字段以对应表文件为唯一事实源
- □ SQL 参数化、方言兼容、分页统一
- □ 租户隔离与分片键处理正确，无跨库 JOIN
- □ 列表查询无 N+1，EXPLAIN 走索引

> 依《文档生成规范》编写 · 与《命名规范》《安全开发规范》配套

## 10. 数据表文档组织<a id="table-docs"></a>

为防止表结构在设计文档中分散维护、相互冲突，数据表设计统一集中、单点维护：

- **集中存放**：全部数据表设计放在 `bms文档/设计/数据库设计/数据表设计/`，**一张表一个文件**，文件名为 `{表名}.md`（如 `sys_tenant.md`）；禁止在架构、概要、需求、任务等文档内散落字段清单。
- **表文件结构**：归属库与模块 → 上游依据 → 字段表（字段 / 类型 / 可空 / 约束 / 说明）→ 索引与约束 → 分片 / 归档 / 迁移说明；公共字段（雪花 ID / 审计 / 软删除 / 乐观锁）随 ORM 模型基类 约定列出。
- **统一引用**：其他文档需要表结构时，一律用相对链接指向对应表文件（首次提及给可点击链接），**不复制字段清单**；表结构只在表文件单点维护。
- **登记**：表文件创建后须在《数据库设计总览》（`bms文档/设计/数据库设计/01_数据库设计_总览.md`）「已设计数据表登记」节登记（表名 → 文件链接 → 所属库 / 模块 → 状态）；未登记视为未定稿。
- **变更传导**：表结构变更先改表文件，再改引用方与 Alembic 迁移（见第 5 节），保证「表文件为唯一事实源」。

## 11. 数据表文档规范 <a id="table-doc-spec"></a>

数据表文档（`数据表设计/{表名}.md`）描述**一张表**的字段级结构，是全库表结构的唯一事实源。格式遵循《文档生成规范》，组织与登记遵循第 10 节。

### 11.1 结构与必备章节 <a id="table-doc-structure"></a>

固定五节，顺序固定、锚点固定；按需可增补可选章节：

| # | 章节               | 锚点        | 内容                                                  |
| - | ------------------ | ----------- | ----------------------------------------------------- |
| 1 | 归属与依据         | `meta`    | 归属库 / 模块 / 上游依据 / ORM 模型 / 状态 / 相关节点 |
| 2 | 字段               | `fields`  | 字段表（含ORM 模型基类 公共字段）                    |
| 3 | 索引与约束         | `index`   | 索引 / 约束表与逻辑外键说明                           |
| 4 | 分片 / 归档 / 迁移 | `storage` | 分片键、归档策略、迁移归属                            |
| 5 | 变更记录           | `revlog`  | 每次结构变更的日期 / 版本 / 变更 / 作者               |

- 可选扩展章节：ER 关系（`relations`）、示例数据（`samples`）等，置于固定五节之后。
- 标题：1 级标题固定「`{表名}`（{中文名}）」；正文首部带面包屑（文档首页 › 数据库设计总览 › 已设计数据表登记 › 表名）。

### 11.2 归属与依据 <a id="table-doc-meta"></a>

- 元信息表固定字段：归属库、覆盖模块、上游依据、ORM 模型、状态、相关节点。
- **状态四值**（与《数据库设计总览》「已设计数据表登记」一致，禁止自造取值）：
  - `已设计`：字段级结构已定稿，尚未排入迁移；
  - `待落库`：已排入迁移、待执行建表；
  - `已落库`：迁移已执行、表已存在；
  - `已废弃`：停止使用（保留历史与原因说明）。
- 上游依据须写章节名（可追溯至规划 / 架构 / 需求），首次提及其它文档给可点击链接。

### 11.3 字段 <a id="table-doc-fields"></a>

- 字段表五列固定：**字段 / 类型 / 可空 / 约束或默认 / 说明**。
- 继承 ORM 模型基类 的公共字段（`id` / 审计 / 软删除 / `version`）**逐行列出**，并在说明列标注「审计」「软删除」「乐观锁」等；语义不重复展开。
- 类型用三库通用类型（大写，如 `BIGINT` / `VARCHAR(64)` / `DATETIME` / `TEXT` / `BOOLEAN` / `DECIMAL(20,4)`），禁用方言专用类型。
- 字段顺序：`id` → 业务字段 → 公共字段；金额用 `DECIMAL/NUMERIC`，状态 / 类型配字典。

### 11.4 索引与约束 <a id="table-doc-index"></a>

- 表列：**名称 / 类型（主键 / 唯一 / 普通）/ 列 / 说明**；命名遵循第 4 节（`idx_字段` / `uq_字段`）。
- 无物理外键；逻辑外键须注明指向（`目标表.字段`）与是否同库。

### 11.5 分片 / 归档 / 迁移 <a id="table-doc-storage"></a>

逐项写明：分片（是否按月分片、分片键与物理表名规则）、归档（是否归档、依据的归档策略）、迁移（随平台库 / 租户库 Alembic、真实迁移归属节点）。

### 11.6 变更记录 <a id="table-doc-revlog"></a>

- 表列：**日期 / 版本 / 变更 / 作者**；新建表首行登记。
- 表结构每次变更追加一行，与 Alembic 迁移一一对应；禁止只改字段表不留记录。

### 11.8 检查清单 <a id="table-doc-checklist"></a>

- □ 文件名 `{表名}.md`，位于 `数据表设计/`，并已在《数据库设计总览》「已设计数据表登记」登记

- □ 变更记录与迁移脚本对应
