## 1. 目的与适用范围 <a id="purpose"></a>

定义 BMS 前端 `frontend/`（`frontend-mobile/` 同款）**总基类**的组件设计：抽象类 `BaseFrontend` 与组合式 `useFrontendBase`，为**一切前端基类**（数据/契约基类 `BaseApi`/`createCrudStore` 与 UI 组件基类 `BaseComponent` 等）提供**通用字段与通用方法**。它是组件设计体系 **L0 层**，与后端「基础类」体系对齐，分层权威见[《前端开发规范》](../../../../../规范/前端开发规范.md)第 3 节「前端基础类体系（L0-L4）」。

| 职责 | 归属 |

| 数据/契约基类（响应类型、请求、CRUD store、稳定序列化） | [《前端开发规范》](../../../../../规范/前端开发规范.md) L1a + 项目骨架《前端基础类》 |
| UI 组件公共能力（透传、尺寸/密度/主题、i18n、可访问性、loading/disabled…） | [L1b 最基础组件基类](../../L1b_最基础组件基类/01_组件设计_最基础组件基类/01_组件设计_最基础组件基类.md) |
| 形态/受控值/字段/域基类 | L2 形态基类、L3 受控值与字段基类、L4 域基类（各节点详见总览路线图） |

上游依据：[《前端开发规范》](../../../../../规范/前端开发规范.md)（§3 分层权威、依赖方向与扩展规则）、[《架构设计 · 前端架构》](../../../../架构设计/28_架构设计_前端架构.md)（组件分层与目录）。

> 本篇为 **00 基础组件类 · L0 层**。**范围边界**：L0 只放"所有基类共有"的横切能力；数据/UI 特有逻辑不得上提 L0；具体能力见各上层节点。

## 2. 组件清单与职责 <a id="components"></a>

| 组件 / 工具 | 位置 | 职责 |
| --- | --- | --- |
| `BaseFrontend` | `src/base/l0/BaseFrontend.ts` | 抽象类：通用字段（命名空间 `ns`、实例标识）与通用方法（日志、错误上报、配置/环境读取、i18n、生命周期钩子） |
| `useFrontendBase.ts` | `src/base/l0/useFrontendBase.ts` | 组合式：为组合式基类提供与 `BaseFrontend` 等价的通用能力（Vue 以组合式模拟继承） |

- 命名遵循[《命名规范》](../../../../../规范/命名规范.md)；目录遵循[《前端开发规范》](../../../../../规范/前端开发规范.md)（L0 归 `src/base/l0/`）。

## 3. 契约（Props 与能力） <a id="contract"></a>

| 通用字段 | 类型 | 说明 |
| --- | --- | --- |
| `ns` | string | 命名空间（用于日志前缀、样式前缀、埋点域） |
| `identifier` | string | 实例/组件标识（用于日志与错误上报定位） |
| `env` | 'dev' \| 'test' \| 'prod' | 运行环境（由配置读取） |
| `config` | Readonly\<Record\<string, any\>\> | 只读配置视图（按命名空间隔离） |

| 通用方法 | 签名 | 说明 |
| --- | --- | --- |
| `log` | (level, message, meta?) => void | 统一日志（级别、命名空间、时间戳；生产分级） |
| `reportError` | (error, meta?) => void | 统一错误上报（去重、限流；不阻断业务） |
| `getConfig` | (key, fallback?) => any | 配置/环境读取（含默认值） |
| `t` | (key, params?) => string | i18n 取词（委托 vue-i18n） |
| `onBaseCreated` / `onBaseDisposed` | hook | 生命周期钩子（供子类扩展） |

- 事件/钩子：子类通过覆写钩子接入，不直接改 L0 行为；组合式通过返回值接入。

## 4. 继承与实现约定 <a id="inherit"></a>

| 项 | 设计 |
| --- | --- |
| 派生关系 | `BaseApi`/`createCrudStore`（L1a）与 `BaseComponent`（L1b）均继承/组合 `BaseFrontend`/`useFrontendBase` |
| 模拟继承 | Vue 3 无类多继承：组合式组件用 `useFrontendBase()`，非组件类可 `extends BaseFrontend`；二者能力等价 |
| 依赖方向 | L0 只被上层依赖，**不得依赖任何上层**；不得引用 UI、store、业务 |
| 横切边界 | 只有"所有基类共有"的能力才进 L0；单侧（数据或 UI）特有逻辑不得上提 |
| 扩展 | 出现新的"所有基类共有"能力时增补 L0；出现"某一侧共有"能力时增补对应 L1 基类 |
| 双端同款 | frontend 与 frontend-mobile 同步实现 |

## 5. 场景集成 <a id="scenes"></a>

| 场景 | 说明 |
| --- | --- |
| 数据/契约基类 | `BaseApi` 等在构造时接入 `useFrontendBase` 的日志/错误上报/配置 |
| UI 组件基类 | `BaseComponent` 继承 L0，再向 L2_形态基类/L3_受控值与字段基类/L4 传递通用能力 |
| 具体组件 | 通过继承链获得日志/配置/i18n，不各自实现 |

## 7. 权限 / i18n / 移动端 <a id="cooperate"></a>

- **权限**：L0 不含权限判定（字段权限见 [L3-04 字段权限基类](../../L3_受控值与字段基类/04_组件设计_字段权限基类/04_组件设计_字段权限基类.md)，动作权限见 [04 基础类 02 权限指令](../../../04_基础类/02_组件设计_权限指令/02_组件设计_权限指令.md)）。
- **i18n**：`t` 委托 vue-i18n，不硬编码文案。
- **移动端**：独立工程，L0 能力同款实现。

## 8. 性能与边界 <a id="performance"></a>

| 场景 | 设计 |
| --- | --- |
| 开销 | L0 无 DOM、无响应式，纯能力集合；`log`/`reportError` 生产分级与限流 |
| 边界 | 配置缺失（回退默认）、环境判断错误、日志风暴、错误上报重复、i18n 未就绪、命名空间冲突 |
| 不支持 | 数据/契约基类（L1a）、UI 能力（L1b）、形态/值/字段/域基类（L2-L4）、权限判定 |

## 9. 检查清单 <a id="checklist"></a>

- □ 通用字段：`ns`/`identifier`/`env`/`config`；通用方法：`log`/`reportError`/`getConfig`/`t`/生命周期钩子
- □ 派生：L1a 与 L1b 均继承；依赖方向单向（L0 不依赖上层）
- □ 只放共有能力，不掺 UI/业务/权限
- □ 模拟继承（组合式 + 类）能力等价；双端同款
- □ 权限/i18n/移动端符合第 7 节；性能边界符合第 8 节
- □ 三项上游登记已确认：前端基础类分层、组件分层与目录、前端配置与环境
