## 1. 目的与适用范围 <a id="purpose"></a>

定义 BMS 前端 `apps/desktop/`（`frontend-mobile/` 同款）**片段机制**的组件设计：抽象类 `BaseCapability` 与组合式 `useCapabilityBase`，为**全部能力片段**提供公共机制——片段标识、依赖声明、单向依赖校验、开发态告警。它是组件设计体系 **机制基类「片段机制」**，对齐后端 `BaseCapability`（能力域标识 `key`）的机制口径，继承 [组件根基类](../../01_机制基类/02_组件设计_组件根基类/02_组件设计_组件根基类.md)。

### 1.1 定位与分层 <a id="positioning"></a>

```mermaid

    COMP["组件根 BaseComponent"] --> CAP["片段机制 BaseCapability / useCapabilityBase"]
    CAP --> CAPS["能力片段（预置 31，开放集合）"]
    CAPS --> DOM["域基类（按需）"]
```

| 职责 | 归属 |

| 片段标识、依赖声明、单向依赖校验、开发态告警、登记入口 | **本节点（片段机制）** |
| UI 通用能力（透传、尺寸/密度、可访问性、loading/disabled） | [组件根基类](../../01_机制基类/02_组件设计_组件根基类/02_组件设计_组件根基类.md) |
| 每片段的具体横切能力 | [能力片段](../../02_能力片段/01_组件设计_交互片段/01_组件设计_交互片段.md) 各节点 |
| 域语义归类 | [域基类](../../03_域基类/01_组件设计_输入域基类/01_组件设计_输入域基类.md) 各节点 |

上游依据：[《前端开发规范》](../../../../../规范/前端开发规范.md)（§3.1 依赖方向、§3.2 扩展规则）、[《架构设计 · 前端组件体系》](../../../../架构设计/05_架构设计_前端组件体系.md)（组合轨默认与开放扩展）、[《架构设计 · 前端架构》](../../../../架构设计/08_架构设计_前端架构.md)（`src/base` 目录）。

> 本篇为 **基础组件类 · 机制基类「片段机制」**。**范围边界**：具体能力归各片段；域细化归域基类；本机制只做「片段如何声明、如何依赖、如何被校验与登记」，不做任何 UI 或业务语义。

## 2. 组件清单与职责 <a id="components"></a>

| 组件 / 工具 | 位置 | 职责 |
| --- | --- | --- |
| `BaseCapability` | `src/base/capability.ts` | 抽象类：片段标识 `key`、元信息 `describe()`、依赖声明 `depends` |
| `useCapabilityBase.ts` | `src/base/capability.ts` | 组合式：片段声明、依赖登记、单向校验与开发态告警，供全部能力片段复用 |

- 命名遵循[《命名规范》](../../../../../规范/命名规范.md)：机制层基类 `BaseXxx`、机制层组合式 `useXxxBase`；目录遵循[《前端开发规范》](../../../../../规范/前端开发规范.md)（机制层归 `src/base/`）。
- **实现口径（2026-09-16 交付）**：已知片段 `key` 与依赖表由**片段层**注入（`src/components/base/fragments.ts` 调 `registerKnownFragments`，与《前端基类清单》『能力片段』节 逐项对齐），机制层不反向依赖片段层；开发态校验「依赖已登记 / 无循环 / `key` kebab-case」，违规默认经根系告警（`strict` 抛 `BaseError` 码 `10001`，对齐平台 PARAM 段位；2026-09-16 由 `10003` 对齐），生产态零开销；「不得依赖上层（反向）」由 `02_05` 的 import 方向静态护栏把关（`tests/guard-dependency.spec.ts`，运行期无法判定上层归属）。

## 3. 契约（Props 与方法） <a id="contract"></a>

| 属性 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `key` | string | 必填 | 片段标识（全局唯一，登记与依赖引用用；如 `value` / `field` / `option-source`） |
| `depends` | string[] | `[]` | 依赖片段标识（只准依赖下层或同层已登记片段，单方向） |
| `enabled` | boolean | true | 是否启用（false 时跳过校验与登记，供预览/测试） |
| `onWarn` | (message) => void | 开发态告警 | 开发态告警回调（生产不执行） |

| 方法 / 事件 | 说明 |
| --- | --- |
| `describe()` | 片段元信息（标识、职责、依赖），登记与调试用 |
| `assertDeps()` | 单向依赖校验：反向依赖（依赖上层）或依赖未登记片段时告警/抛错（开发态） |
| `register()` | 片段登记入口（与「注册表基类」对接，供 09 类注册表复用） |
| `fragment:mounted` / `fragment:warn` | 可选事件：片段挂载与告警（调试面板/埋点） |

## 4. 行为与实现约定 <a id="behavior"></a>

| 项 | 设计 |
| --- | --- |
| 声明 | 片段以 `useCapabilityBase({ key, depends })` 声明；组件组合片段不改片段内部实现 |
| 依赖方向 | 只准上层依赖下层（组件 → 域基类/片段 → 组件根 → 根系）；片段之间依赖须**单向并登记** |
| 校验时机 | 开发态在片段挂载时校验；生产态跳过（零开销） |
| 校验规则 | ① 依赖必须是已登记片段；② 不得形成循环依赖；③ 不得依赖上层（反向） |
| 告警 | 违规用 `onWarn` 输出（含片段、依赖、原因）；校验失败不阻断渲染，仅告警（可配置严格模式抛错） |
| 登记 | 片段新增走「候选 → 设计节点 → 评审确认 →《前端基类清单》登记」，`key` 与清单一致 |
| 组合 | 片段正交可组合；同一组件可声明多个片段，机制只保证依赖合法 |
| 依赖方向 | 本机制只依赖 组件根；不得依赖任何片段或具体组件 |

## 5. 场景集成 <a id="scenes"></a>

| 场景 | 说明 |
| --- | --- |
| 全部能力片段 | 各片段经 `useCapabilityBase` 声明标识与依赖（如 `value` → 无依赖、`field` → `value`+`field-shell`+`field-perm`） |
| 组件组合 | 组件按需组合片段，片段依赖由机制统一校验 |
| 注册表对接 | `register()` 与 [注册表基类](../06_组件设计_注册表基类/06_组件设计_注册表基类.md) 衔接，供扩展点登记 |
| 调试 | `describe()` 汇总片段依赖关系，供调试面板与文档生成 |

## 7. 权限 / i18n / 移动端 <a id="cooperate"></a>

- **权限**：不做权限判定（字段权限见[字段权限片段](../../02_能力片段/11_组件设计_字段权限片段/11_组件设计_字段权限片段.md)，动作权限见[基础类「权限指令」](../../../09_基础类/02_组件设计_权限指令/02_组件设计_权限指令.md)）。
- **i18n**：告警与元信息为开发态文案，不进语言包。
- **移动端**：机制同款实现（片段声明与校验不依赖 PC 组件库）。

## 8. 性能与边界 <a id="performance"></a>

| 场景 | 设计 |
| --- | --- |
| 开销 | 校验仅开发态执行；生产为静态声明，无运行时开销 |
| 边界 | `key` 重复、`depends` 未登记、循环依赖、反向依赖、严格模式误开、生产态误依赖告警 |
| 不支持 | UI 能力（组件根）、片段具体能力（各片段）、域语义（域基类）、权限判定 |

## 9. 检查清单 <a id="checklist"></a>

- □ 契约：`key` / `depends` / `enabled` / `onWarn` + `describe` / `assertDeps` / `register`
- □ 校验：无循环、不依赖上层、依赖已登记；生产态零开销；告警含片段与原因
- □ 片段 `key` 与《前端基类清单》一致；新增片段走候选→评审→登记
- □ 权限/i18n/移动端符合第 7 节；性能边界符合第 8 节
- □ 三项上游登记已确认
