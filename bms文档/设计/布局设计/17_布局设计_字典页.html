1. 目的与适用范围

规范 BMS 管理端字典页的统一布局：字典数据（sys_dict_type 字典类型与 sys_dict_item 字典条目） 的查看与编辑界面共用同一套布局模板——参考《布局设计-表单页》的 表单页（FormDetailPanel）形态：工具栏 + 信息栏（详细信息 / 系统信息两个 Tab）+ 字段区（详细信息内可含明细区）。

「所有字典数据」的界面同一模板：无论编辑哪一个字典类型、哪一条字典条目，界面都由 「详细信息 + 系统信息」两个 Tab 组成；详细信息的第一行固定为三个字典系统字段，标识为 Code / Name / State（与数据库列一一对齐），三列等宽、顺序固定， 其后才排该记录类型的其余字段。列标题（界面上显示的字段名）不写死——按具体需求显示（如「编码 / 名称 / 状态」「类型编码 / 显示名称 / 启用状态」等）， 但标识与顺序不变。 字典域模型与页面清单见《概要设计 · 字典管理》§4 / §8， 字段语义与多语言（类型 name / 条目 label 走 _i18n 附表）见同文档 §2.2 / §4.1。

职责划分：列表侧（字典类型列表 + 条目列表、筛选与批量操作）按《布局设计-列表页》； 记录侧（单条字典类型 / 条目的查看与编辑）按本布局；表格明细（类型下挂条目）按《布局设计-表格明细》； 弹窗形态（字典项快速编辑）按《布局设计-弹窗》。

2. 页面结构

字典页结构（FormDetailPanel · 字典数据记录）
工具栏：修改 / 删除 / 刷新 / 关闭（只读态）· 保存（编辑态）· 启用停用（按需求）
信息栏：详细信息 │ 系统信息
详细信息（首行三字段 + 其余字段 + 明细区）
首行（三列，顺序固定）：界面上显示列标题（示例「编码」│「名称」│「状态」，按需求显示）
其余字段（三列栅格，按记录种类）：类型 = 排序等；条目 = 值 / 语义色 / 上级 / 排序 / 扩展属性
明细区：类型记录下挂「条目」明细 Tab（行内编辑，仅编辑态可用）；条目记录无明细
系统信息：label 上方三列只读栅格（ID / 版本号 / 创建用户 / 创建时间 / 修改用户 / 修改时间 / 字典类型，只读）

2.1 信息栏（详细信息/系统信息）

  • 信息栏分两个子 Tab：「详细信息」与「系统信息」，与表单页同口径（同位置、同交互、同视觉）。
  • 详细信息 = 首行三个字典系统字段 + 其余字段（按记录种类） + 明细区（仅字典类型记录有下挂条目）。
  • 系统信息为系统审计字段区，字段形态与业务字段一致（disabled 输入框），仅只读不可编辑，各模块统一，见 2.5。
  • Tab 切换不切换记录、不重取数；两 Tab 共用同一份记录数据与同一套字段权限判定。

2.2 详细信息：首行三个字典系统字段

详细信息 · 第一行（el-form label-position="top" · 三列栅格，顺序固定）
编码
名称
状态

图上显示的是列标题（此处「编码 / 名称 / 状态」为示例，实际按需求显示）· 三列字段标识固定 Code → Name → State（与数据库列一一对齐，不出现在界面上）· 三列等宽（el-col :span="8"）· 与同排字段同高对齐（多语言文案字段恒占一行，不逐语言铺开）
  • 标识与顺序固定：三列的字段标识恒为 Code / Name / State，顺序与列宽固定，任何字典记录页都不得调换、改名或省略；三字段是字典数据的系统字段（区别于各记录类型的其余业务字段）。界面上显示的是列标题（见下条），标识只用于接口字段与数据库列对齐，不直接出现在界面上。
  • 标识与数据库列一一对齐：字典类型记录 → Code = sys_dict_type.type、Name = sys_dict_type.name（sys_dict_type_i18n.label）、State = sys_dict_type.status；字典条目记录 → Code = sys_dict_item.code、Name = sys_dict_item.label（sys_dict_item_i18n.label）、State = sys_dict_item.status。两级记录列名不同，但标识与显示口径一致（同一模板）。
  • 列标题按需求显示：界面上显示的字段名不写死为「代码 / 名称 / 状态」——按具体需求取用（如类型侧「类型编码 / 类型名称 / 状态」、条目侧「条目编码 / 条目名称 / 状态」，或统一「编码 / 名称 / 状态」）；标题文案由字段元数据下发（见 §5），前端不硬编码，且改标题不改标识（接口字段、提交载荷与数据库列一律以标识 / 列名为准）。
  • 控件形态按需求：三字段的控件形态可按模块需求选取，取值见 §3 表（如 Code 只读文本 / 新建时可填；Name 统一用多语言文案字段；State 用状态开关或下拉）。

2.3 详细信息：其余字段

记录种类其余字段（首行之后，三列栅格）说明
字典类型（sys_dict_type） 排序（sort） 数字输入（整数，升序）；> 8 字段时用分区标题（el-divider / SectionContainer）分组
字典条目（sys_dict_item） 值（value）、语义色（color）、上级条目（parent_id）、排序（sort）、扩展属性（attr_json） 语义色为下拉（成功 / 警告 / 危险 / 信息 / 主色，可空）；上级条目为同类型条目选择（级联联动）；扩展属性按 sys_dict_attr schema 渲染（属性未启用或该类型无属性时不显示该分区）
  • 其余字段一律排在首行三字段之后，按「三列栅格」顺排；长文本 / JSON / 备注类字段跨整行（:span="24"）。
  • 字段增删由模块需求决定，但首行三字段的顺序与列宽不变；新增字段只能追加在首行之后。

2.4 明细区（类型下挂条目）

  • 字典类型记录：详细信息下部为「条目」明细 Tab（表格明细，口径见《布局设计-表格明细》）——列含 编码 / 名称 / 值 / 语义色 / 上级 / 排序 / 状态（标题按需求显示）；行内编辑，新增行 / 删除行仅编辑态可用；随主表整体提交（单事务）。
  • 明细行内编辑时，条目字段的显示口径与条目记录页首行一致（三字段同语义、同顺序，标题同样按需求显示）。
  • 字典条目记录：无明细区；如需查看同类型其它条目，经工具栏「关闭」回到列表侧（或由列表侧切换记录）。
  • 扩展属性分区（条目侧）不进入明细表格，仅在条目记录页展示，避免明细行过宽。

字段顺序固定 · label 上方 · 三列只读栅格（disabled 输入框，仅不可编辑；字典类型为禁用下拉框）· 时间按租户时区格式化（无时区后缀）· 无编辑态
  • 与表单页唯一差异：第 7 项由「表单标识」换为「字典类型」——记录当前记录所属的字典类型（用禁用下拉框展示：显示类型名，值为 type 编码，如 sys_status）；字典类型记录本身该项显示「—」或类型自身标识。
  • 其余六项（ID / 版本号 / 创建用户 / 创建时间 / 修改用户 / 修改时间）与表单页完全一致，实现复用《原型-公共组件/04-系统信息组件》。
  • 系统信息无编辑态、不参与校验与提交；保存冲突（409）时提示「记录已被修改」并重载最新数据（见 §6）。

3. 首行三字段显示口径

三字段为字典数据系统字段：标识固定（Code / Name / State，与数据库列一一对齐）、列标题与控件形态按需求；按下表选取，同一模块内保持一致。

字段标识（固定）数据库列（一一对齐）语义标题（按需求显示）可选显示口径（按需求）约束
Code 类型 sys_dict_type.type / 条目 sys_dict_item.code 稳定标识：类型编码 / 条目编码 「编码」「代码」「类型编码」「条目编码」等（按需求） ① 只读文本（默认，一经发布稳定不变）；
② 新建态可填 + 编辑态只读（推荐：新建时可填、保存后锁定）；
③ 可编辑输入框（仅内部临时字典，且须提示影响面） 		唯一（类型 type 全局唯一；条目 code 同类型内唯一）；字母数字与下划线；保存后不随显示形态变化
Name 类型 sys_dict_type.name / 条目 sys_dict_item.label（均带 _i18n 附表） 展示名称：类型名 / 条目名 「名称」「显示名称」「翻译名」「类型名称」「条目名称」等（按需求） ① 多语言文案字段（默认，推荐）——表单里恒占一行：文本框就地编辑必填语言（＝当前登录用户语言）文案 + 图标按钮开多语言明细弹框；
② 单语言输入框（仅无需多语言的内部字典） 		启用语言中的必填语言必填；其余语言可缺省并按默认文案回退；禁止写死「中文名称 / 英文名称」或用逐语言铺开占满表单（见 §5）
State 类型 / 条目 status 启用 / 停用 「状态」「启用状态」「启用 / 停用」等（按需求） ① 状态开关（el-switch，默认，编辑态可用、只读态以状态标签回显）；
② 状态下拉（启用 / 停用，需与其它字段同栅格对齐时）；
③ 只读状态标签（仅查看态） 		启用 / 停用两值；停用即时从运行时查询结果消失（缓存失效即时生效，见 §6）；停用的条目在明细与列表中以状态标签区分
  • 三字段为首行整体：即使某模块只关心其中一项，也不得拆散顺序或把其余字段插到首行内。
  • 只读态回显口径：Code 直出编码文本；Name 按当前界面语言回显、无值沿回退链（当前语言 → 系统默认语言 → 派生默认文案）；State 以状态标签（启用 / 停用）回显，语义色按字典条目 color 或内置语义映射解析。

4. 只读/编辑分态

状态进入方式行为
只读（默认）双击列表行打开 / 保存后停留字段禁用，仅查看；点工具栏「修改」进入编辑态
编辑点「修改」 / 工具栏「新增」打开新 Tab字段可编辑（Code 按所选口径），工具栏「修改」切换为「保存」
  • 新增 Tab 打开即编辑态（无需先点「修改」），保存后回填 id 与版本号。
  • 修改未保存时切换 / 关闭 Tab → 弹确认框（脏数据保护，dirty 检测）。
  • 明细区（类型下挂条目）仅编辑态可用；只读态以表格只读呈现。

5. 字段权限与多语言文案

  • 字段权限联动：字段按表单元数据接口下发的字段权限渲染——visible=false 不渲染，editable=false 编辑态亦保持禁用（写时校验由后端兜底）；首行三字段同样受字段权限约束（如 Code 常配为不可编辑）。
  • 敏感字段脱敏：字典数据一般无敏感字段；若扩展属性含敏感值，按脱敏规则掩码，持 data:plain 权限码方可查看明文。
  • 多语言文案字段：Name（类型名 / 条目名）一律用多语言文案字段——表单里只占一行（文本框就地编辑必填语言文案 + 图标按钮，悬停提示完整度或缺失语言，字段标签不标注「多语言」）；弹框内为明细表（语言 / 文案两列行内编辑），语言行由启用语言清单动态生成（加语言不改界面与提交契约），标出系统默认语言与必填语言，支持语言关键字与「仅看缺失 / 仅看已填」筛选；弹框内为草稿，「确定」回写、「取消」丢弃，最终随工具栏「保存」统一提交；必填语言为空即阻断并定位，其余语言可缺省并按默认文案回退。契约依据见组件设计 · 多语言文案字段。
  • 语言行为动态：启用语言清单变化时，Name 的多语言明细行随之增减，字典页布局与提交载荷不变。

6. 校验与提交

  • 唯一性：类型 type 全局唯一；同类型下条目 code 唯一（软删除后释放唯一键）；冲突返回业务错误码（字典域 401xx 段，见《概要设计 · 字典管理》§7）并在对应字段定位提示。
  • 必填与格式：Code / Name / State 必填（Code 与 Name 非空、长度上限；State 二值）；错误信息走 i18n。
  • 整体保存：字典类型记录一次性提交主表 + 明细（条目）+ 各自 _i18n 附表，单事务。
  • 乐观锁冲突：保存请求携带 version，冲突（409）提示「记录已被修改」并重载最新数据。
  • 引用校验：删除被业务引用的条目 / 非空类型时拒绝删除并提示（先解除引用）。
  • 缓存即时生效：保存成功后（先写库后删缓存 + 版本号递增）提示「字典已更新，各处字典下拉即时生效」；停用条目即时从运行时结果消失。
  • 保存成功后刷新列表侧（列表数据与表单一致）。

7. 与 FormFrame / 列表页的协作

交互方向约定
记录标识FormFrame → 字典页prop main-id（Number，null 表示新增）+ 记录种类（类型 / 条目）
保存/删除/标题字典页 → FormFrameemit("saved", id) / emit("deleted") / emit("title-change", 名称)
脏数据状态FormFrame ← 字典页字典页 expose dirty（切换 / 关闭 Tab 时拦截确认）
  • 列表侧（类型列表 + 条目列表、筛选、批量启用停用）按《布局设计-列表页》；菜单「字典管理」的菜单 → 表单 → 业务挂接与权限码见《概要设计 · 字典管理》§6.2。
  • 字典页作为 FormFrame 的「表单 Tab」内容，按《布局设计-表单框架》经路由 props 注入 title / listComponent / detailComponent；被 keep-alive 缓存，切换顶层 Tab 不丢数据。
  • 快速新建（条目 ≤ 6 字段）可直接用弹窗形态（《布局设计-弹窗》），保存后回到字典页刷新。

8. 检查清单

  • □ 信息栏（详细信息 / 系统信息）结构正确，与表单页同位置同交互
  • □ 详细信息第一行为三个字典系统字段，顺序与列宽固定、无字段插队；界面显示的是列标题，其字段标识固定为 Code / Name / State（与数据库列一一对齐，不出现在界面上）
  • □ 三字段列标题按需求显示（不写死「代码 / 名称 / 状态」，由字段元数据下发；改标题不改标识，接口与提交载荷以标识为准）
  • □ 三字段显示口径按模块需求选定且同模块内一致（Code 只读或新建可填；Name 用多语言文案字段；State 开关 / 下拉 / 状态标签）
  • □ 其余字段（类型：排序；条目：值 / 语义色 / 上级 / 排序 / 扩展属性）一律排在首行之后，三列栅格、长字段跨整行
  • □ 类型记录的条目明细区按表格明细口径（行内编辑、随主表整体提交）
  • □ 系统信息 label 上方三列只读栅格统一（第 7 项为禁用下拉的「字典类型」；时间无时区后缀）
  • □ 只读 / 编辑分态切换正确，新增 Tab 直接可编辑，脏数据拦截生效
  • □ 唯一性（type / 同类型 code）、引用校验、乐观锁冲突提示、缓存即时生效提示齐备
  • □ 字段权限（visible / editable）与脱敏（如扩展属性含敏感值）生效
  • □ Name 多语言：字段恒占一行（文本框 + 图标按钮，无写死语言栏、不逐语言铺开），弹框定稿回写而落库随宿主保存，必填语言缺失阻断并定位
