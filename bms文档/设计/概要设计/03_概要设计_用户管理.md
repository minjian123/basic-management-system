## 1. 模块概述与职责 <a id="overview"></a>

> **服务化归口（2026-09-22）**：本项目以微服务为目标架构（平台模块与产品全服务化，见《[微服务演进规划](../../规划/微服务演进规划.md)》）；本节点在服务化形态下对应**一个服务或服务内能力单元**——拥有独立库（每服务每租户一库）、独立部署与发布，与其他服务经**公开契约或事件**协同（服务边界与一致性见[架构设计 37](../架构设计/37_架构设计_子系统_服务间通信与一致性.md)）。

本节对应[《项目规划说明》](../../规划/项目规划说明.md)「功能模块」之**用户管理**模块，与「核心数据表清单」「认证与安全」「权限模型」「事件总线事件模型」章节。架构设计依据[《架构设计》](../架构设计/01_架构设计_总览.md)14-认证与会话、15-权限计算引擎节点。

用户管理负责用户生命周期的全量治理：账号的增删改查、启用/停用、密码重置、岗位分配、角色分配、SSO 身份绑定查看，以及账号锁定/解锁（锁定列表、手动解锁、解锁记录审计）。模块承载 `sys_user` 密码策略字段（`pwd_reset_required / pwd_changed_at / pwd_history / last_login_at`）与个人化字段（`locale / timezone`），并衔接 Excel 批量导入（`import:execute`）。

> **组织与岗位关系引用（2026-10-03；2026-10-09 修订）**：**用户-岗位 / 用户-部门关系整体归 mdm 组织域**（`org_user_post`；用户-部门 `org_user_dept` 随需求 [07-11](../../项目/07_RBAC基础模块/需求/02_需求_用户与角色.md#r07-11) 落），每条关系带**至多一个「主要」标记**（主要岗位 / 主要部门，用户所属岗位与部门以主要项为准）；`sys_user` **不落组织字段**——原「`dept_id` 逻辑外键保留在 bms」的写法**取消**（cws 无 mdm 时该字段恒空且无对象可指）。分配均经 mdm 插件（「岗位分配」/「部门分配」，挂用户记录页「用户分配」页签的具名插槽 `sys.user.detail.tabs`）读写 mdm 契约。部门 / 岗位主数据由 mdm 产品仓库统一维护，bms 不持有副本、不直连 mdm 组织表。

> **角色分配归口（2026-10-06）**：本模块「角色分配」（用户视角）与[角色管理](06_概要设计_角色管理.md)「角色分配—用户分配」（角色视角）**共用同一张 `sys_user_role`**（仅用户维度）；岗位 / 部门主体链归 mdm 组织域（角色-岗位 `org_role_post`、角色-部门 `org_role_dept`）。

职责边界：密码的哈希与校验（PBKDF2）、登录防爆破、双 token 签发、会话生命周期属于《认证与会话》子系统；本模块只负责账号数据治理与密码重置动作，不触碰会话实现细节。角色授予本体在[角色管理](06_概要设计_角色管理.md)（`role:grant`），本模块提供「角色分配」的功能入口并按 `user` 业务收敛权限码。

> **界面与边界修订（2026-10-09）**：① 用户与账号锁定均按[《布局设计 · 表单框架》](../布局设计/06_布局设计_表单框架.html)组织为「**列表 Tab + 记录 Tab**」——列表**无操作列**、双击行开记录 Tab、状态列**内联开关**；② 用户记录 Tab 信息栏＝**详细信息 / 用户分配 / 系统信息**，「用户分配」内含角色分配（bms 内建）+ 岗位分配 / 部门分配（mdm 插件子页签，含「主要」标记，见 [07-11](../../项目/07_RBAC基础模块/需求/02_需求_用户与角色.md#r07-11)）；③ 用户**列表与筛选不含部门 / 岗位**（不硬依赖 mdm 对象，cws 无 mdm 时用户即纯账号）；④ `sys_user` **不落组织字段**（原 `dept_id` 设计取消）；⑤ `locale` / `timezone` 维护入口归**个人中心**；⑥ 账号锁定端点路径随 02_05 归口 platform 改为 `/api/v1/account-locks`（原 `/api/v1/org/locks`）。原型见[《原型设计 · 08 用户管理》](../原型设计/08_用户管理/01_设计说明.html)。

## 2. 功能分解与业务流程 <a id="func"></a>

### 2.1 功能点分解 <a id="func-list"></a>

| 功能点 | 说明 | 权限码 |
| --- | --- | --- |
| 用户列表/详情 | 关键字（用户名/昵称/手机/邮箱）+ 状态筛选、分页查询；列表**无操作列**、双击行打开用户记录 Tab；**不含部门 / 岗位 / 角色列与筛选**（不硬依赖 mdm 对象） | user:query |
| 新建用户 | 创建账号并初始化密码（哈希存储）；强制首登改密开关；部门 / 岗位在记录 Tab 的「用户分配」页签经 mdm 插件另行操作 | user:create |

| 重置密码 | 管理员重置：PBKDF2 重新哈希、强制首登改密、失效全部会话、可发通知 | user:reset_pwd |
| 分配岗位（插件） | 经 mdm **「岗位分配」插件**（mdm 组织域提供，挂用户记录页「用户分配」页签内的具名插槽 `sys.user.detail.tabs`）：读 / 写经 mdm **用户-岗位契约**（表落 mdm `org_user_post`，含**主要岗位**至多一个）；插件未注册时该子页签隐藏 | user:assign_role |
| 分配部门（插件） | 经 mdm **「用户分配部门」插件**（同一插槽）：读 / 写经 mdm **用户-部门契约**（表落 mdm `org_user_dept`，含**主要部门**至多一个）；插件未注册时该子页签隐藏（需求 07-11） | user:assign_role |
| 角色分配 | 查看/维护该用户直接绑定的角色（与角色管理页「角色分配—用户分配」**同一张表** `sys_user_role`；岗位 / 部门主体链归 mdm） | user:assign_role |
| SSO 身份绑定查看 | 查看 sys_user_identity 全局身份映射（IdP、外部账号）；绑定管理在 sso 业务 | user:query |
| 锁定列表/手动解锁 | 查询 sys_account_lock 锁定记录，手动解锁（记录解锁人与时间） | user:unlock |
| 手动锁定账号 | 手动锁定账号（写 sys_account_lock `manual` 型并置账号锁定状态，记录锁定人与原因） | user:lock |
| Excel 批量导入 | 衔接导入导出模块（`import:execute`），模板校验后批量建号 | import:execute |

### 2.2 业务规则 <a id="func-rules"></a>

- 唯一性：`username` 唯一，采用 `(username, deleted_at)` 复合唯一索引——删除即释放用户名，三库均允许多个 NULL 不冲突
- **组织与岗位关系归 mdm**：用户-岗位 / 用户-部门多对多与「主要项」标记（至多一个主要岗位 / 主要部门）均归 mdm 组织域；`sys_user` 不落组织字段
- **不硬依赖 mdm 对象**：bms 单独运行 / cw 工作区（无 mdm）时用户即**纯账号**（无部门、无岗位）——用户页不呈现相关列 / 筛选 / 页签，插件缺失即隐藏，不报错、不阻塞
- **界面形态（表单框架）**：用户与账号锁定均按「列表 Tab + 记录 Tab」组织；列表**无操作列**（双击行开记录 Tab），状态列以内联开关切换
- 密码策略（sys_config 可配）：复杂度校验（长度/字符组合）、90 天有效期强制改密（`pwd_changed_at` 驱动）、近 5 次历史密码不可重复（`pwd_history`）、180 天未登录自动锁定（定时任务扫描 `last_login_at`）
- 账号锁定类型：`fail_limit`（登录失败触发，认证子系统写入；`expire_at` = 锁定时间 + 限流窗口，到期自动解锁）/ `inactive`（长期未登录，任务写入；无期限，须手动解锁）/ `manual`（管理员手动锁定；无期限，须手动解锁）；本模块负责查看、手动锁定与手动解锁
- 停用/锁定/删除的用户：登录即被拒绝；停用与删除时注销该用户全部在线会话（删 Redis 会话标记 + 吊销 refresh）
- 安全约束：不得停用/删除当前操作人自身；内置管理员（系统/安全/审计）不得被停用删除，且同一用户不得兼任两类管理员（三权分立）
- 重置密码后强制失效该账号全部会话；被重置用户 `pwd_reset_required=true`，下次登录必须改密
- 批量导入：同模板字段校验（用户名唯一、格式校验），逐行失败可跳过并输出失败明细，整体提交用幂等键防重

### 2.3 流程步骤 <a id="func-flow"></a>

1. **新建用户**：填表单（含初始密码/强制改密标志）→ 校验用户名唯一与密码复杂度 → PBKDF2 哈希入库 → 发布 `sys.user.created` → 落操作日志与字段级审计（岗位分配在用户管理页经 mdm 插件另行操作）
2. **重置密码**：校验操作人权限（user:reset_pwd）→ 新密码策略校验 → 更新 `password_hash / pwd_changed_at / pwd_history / pwd_reset_required` → 作废全部会话 → 发布 `sys.user.password_reset`（Webhook 可订阅）
3. **解锁**：查看锁定列表（含锁定类型/时间/原因）→ 手动解锁 → 写 `sys_account_lock.unlock_at / unlock_by` → 落操作日志（解锁动作审计）
4. **异常分支**：用户名冲突（30002）→ 提示修改；账号已锁定/已停用仍可维护资料但不可登录；删除失败（存在未解除的引用或内置管理员）→ 明确错误码返回，不做部分提交

## 3. 关键时序与协作 <a id="sequence"></a>

```mermaid
sequenceDiagram
    autonumber
    participant 管理员
    participant 用户服务
    participant DB
    participant 认证会话 as 认证/会话
    participant 事件总线

    管理员->>用户服务: POST /users
    用户服务->>DB: PBKDF2+校验 → insert sys_user
    DB-->>用户服务: 返回
    用户服务->>事件总线: 发布 sys.user.created
    Note over 用户服务: 岗位分配经 mdm 插件（写 org_user_post）
    用户服务->>认证会话: 失效全部会话 → 广播 session.revoked
    管理员->>用户服务: PUT 密码重置 → 更新密码字段
    用户服务->>事件总线: 发布 sys.user.password_reset（Webhook 可订阅）
    Note over 用户服务: 更新 password_hash / pwd_history
```

协作要点：重置密码/停用/删除的会话失效复用《认证与会话》的踢出通道（Redis 会话标记删除 + refresh 吊销 + Socket.IO 广播），本模块仅发起动作；用户变更影响权限计算时，权限引擎按 `sys_user_role` 角色分配变化触发权限版本 +1，保证权限变更即时生效。

## 4. 数据模型与表设计 <a id="data"></a>

### 4.1 核心表 <a id="data-tables"></a>

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| sys_user | username、password_hash、name（昵称）、email、phone、status、pwd_reset_required、pwd_changed_at、pwd_history、last_login_at、locale、timezone | 用户主表（platform 服务租户库）；密码策略字段与语言 / 时区偏好（`locale/timezone` 维护入口归个人中心）；**不含组织字段**（部门 / 岗位关系归 mdm）；软删除 + 审计字段 + version 乐观锁 |
| org_user_post / org_user_dept（mdm） | — | **2026-10-03 起归 mdm 组织域**：用户-岗位（`org_user_post`）与用户-部门（`org_user_dept`，随需求 [07-11](../../项目/07_RBAC基础模块/需求/02_需求_用户与角色.md#r07-11) 落）多对多关联，各含**至多一个「主要」标记**；bms 不持有这两张表 |
| sys_user_role | role_id、user_id | 角色 × 用户分配（与角色管理页「角色分配—用户分配」**同一张表**）；本模块按用户展示/维护其直接角色；权限计算收敛为用户→角色；岗位/部门主体链归 mdm（`org_role_post` / `org_role_dept`） |
| sys_account_lock | user_id、lock_type（fail_limit/inactive/manual）、reason、locked_at、locked_by、expire_at、unlock_at、unlock_by、unlock_mode | 账号锁定/解锁记录（解锁操作审计依据） |
| sys_user_identity | idp_key、external_id、tenant_id、user_id | 【平台库】SSO 全局身份映射，本模块只读展示（sso:bind 管理） |

### 4.2 索引与唯一约束 <a id="data-index"></a>

- `sys_user`：复合唯一索引 `(username, deleted_at)`；索引 `status`、`last_login_at`（未登录扫描任务用）
- 用户-岗位 / 用户-部门已归 mdm（`org_user_post` / `org_user_dept`）：雪花 `id` 主键 + 业务列复合唯一（`(user_id, x_id, deleted_at)`，2026-10-07 关联表主键口径修订），索引与约束在 mdm 组织库维护
- `sys_user_role`：索引 (role_id) 与 (user_id)，支撑角色反查与用户直接角色收敛
- `sys_account_lock`：索引 (user_id, locked_at) 与 (unlock_by)；解锁记录保留 90 天后随审计归档

### 4.3 数据流转 <a id="data-flow"></a>

- 创建/更新/删除经 ORM 事件自动落审计字段与字段级变更审计（sys_data_audit_log，按月分表）
- 用户变更经 RocketMQ 事件驱动：操作日志异步落库、Webhook 推送、全文检索主数据索引同步（后续）
- 删除为软删除：数据进回收站（recycle 业务查看/恢复）；过期残留由 Celery 定时物理清理
- 解锁记录与字段级审计同属审计域：90 天热表后按归档策略冷化，哈希链随归档导出

### 5.2 分页/幂等/限流 <a id="api-rule"></a>

- 分页统一 `page`（从 1 起）/ `size`，响应 `{list, total, page, size}`；常规列表 limit/offset（限深 100 页）
- 幂等：新建用户、批量导入等写接口支持请求头 `Idempotency-Key`——Redis SETNX 前置拦截 + 幂等键字段唯一约束兜底
- 限流：用户列表按用户维度限流（slowapi，Redis 后端）；重置密码、导入接口叠加更严限流防滥用
- 统一响应 `{code, message, data}`；登录/刷新外的全部接口 Bearer access token + `require_permission` 两级校验

### 5.3 事件发布 <a id="api-events"></a>

| 事件 | 触发时机 | 主要载荷 | Webhook 订阅 |
| --- | --- | --- | --- |
| sys.user.created / sys.user.updated / sys.user.deleted | 用户创建/修改/删除后 | 用户 ID、username、dept_id、status | 是 |
| sys.user.password_reset | 管理员重置密码或自助找回后 | 用户 ID | 是 |
| identity.user.jit_created | SSO 首登自动建号 | user_id、idp_key | 是 |

## 6. 权限与配置 <a id="perm"></a>

### 6.1 权限码 <a id="perm-codes"></a>

本模块对应 `user` 业务（sys_business 平台库维护，默认归属系统管理员），动作按 sys_action 分配：

| 权限码 | 动作 | 说明 |
| --- | --- | --- |
| user:query | query | 列表/详情/锁定列表/SSO 绑定查看 |
| user:create / user:update / user:delete | create / update / delete | 账号增删改与启停 |
| user:reset_pwd | reset_pwd | 重置密码 |
| user:unlock | unlock | 手动解锁 |
| user:lock | lock | 手动锁定账号 |
| user:assign_role | grant | 分配岗位/角色分配 |
| import:execute | execute | Excel 批量导入（import 业务） |

### 6.2 菜单挂接 <a id="perm-menu"></a>

- 菜单「用户管理」（form=user_form，挂 user 业务）与「账号锁定」（form=lock_form）
- 按钮挂接：新增 / 删除（create / delete）、重置密码（reset_pwd）、启用·停用（update）、角色分配（grant）、手动锁定 / 解锁（lock / unlock）、导入（import:execute）——默认无按钮权限，按角色授予后显隐；**列表无操作列**（编辑在记录 Tab 工具栏）
- 字段权限：手机号/邮箱等敏感字段注册脱敏标记（data:plain 查看明文）；字段可见可编辑由 sys_role_field 按角色收窄
- 列表内联切换：用户列表「状态」列以开关**内联切换**（列表页无操作列），复用 `PUT /users/{id}/status`，**不新增 toggle 接口**；需记录级可编辑（`sys_role_field.editable`）与 `user:update` 动作权限；**停用为危险开关**，切换前二次确认，失败回滚原值并提示错误码文案（契约见[《组件设计 · 开关与枚举字段》](../组件设计/06_字段类/08_组件设计_开关与枚举字段/08_组件设计_开关与枚举字段.md)）；状态**仅表示启用 / 停用**，账号锁定态归「账号锁定」页
- 插件页签权限：岗位 / 部门分配的操作按钮与取数由 mdm 插件自带（区域项 `perm` 与 mdm 端点权限码同源），宿主不二次兜底；插件缺失时子页签整体不渲染

| 参数 | 默认 | 说明 |

| pwd.min_length / pwd.complexity | 8 / 字母+数字 | 密码复杂度 |
| pwd.expire_days | 90 | 密码有效期，pwd_changed_at 驱动强制改密 |

### 6.4 种子数据 <a id="perm-seed"></a>

- 平台库种子：user 业务码与动作码（create/update/delete/query/reset_pwd/unlock/lock/grant）、用户管理/账号锁定菜单表单按钮字段挂接与 i18n 文案
- 租户开通种子：初始系统管理员账号（租户开通首建，由其创建安全/审计管理员）、内置三类管理员角色互斥预授

## 7. 错误码与异常处理 <a id="error"></a>

本模块错误码段 3xxxx（用户与组织）。非 0 即业务错误，文案由前端按 i18n 映射，后端不承担文案拼装。

| 错误码 | 说明 |
| --- | --- |
| 30001 | 用户不存在 |
| 30002 | 用户名已存在 |
| 30003 | 账号已锁定 |
| 30004 | 账号已停用 |
| 30005 | 密码不符合复杂度策略 |
| 30006 | 新密码与近 5 次历史密码重复 |
| 30007 | 锁定记录不存在或已解锁 |
| 30008 | 用户已删除（软删除） |
| 30009 | 内置管理员不可停用/删除，或操作人不得操作自身 |
| 30010 | 三权分立约束：同一用户不得兼任两类管理员 |
| 30011 | 用户仍被角色/流程引用，禁止删除 |

异常处理要求：多步骤写操作（建号+分配岗位）显式事务边界，任一步失败整体回滚；并发冲突用 version 乐观锁返回 30001 上下文错误；敏感字段（密码、token）日志脱敏，不落原始值；导入文件逐行失败收集明细，不中断整体。

## 8. 页面清单与验收要点 <a id="page"></a>

### 8.1 页面清单 <a id="page-list"></a>

| 页面 | 端 | 说明 |
| --- | --- | --- |
| 用户管理 | PC | 列表（关键字 + 状态筛选、状态内联开关、无操作列、双击行开记录 Tab）；记录 Tab 三个子页签：详细信息（用户名/昵称/手机/邮箱/状态）· 用户分配（角色分配；岗位 / 部门分配由 mdm 插件插入，含主要岗位 / 主要部门标记）· 系统信息；工具栏 新增 / 刷新 / 关闭 / 删除 / 启用·停用 / 重置密码 / 导入 / 导出 |
| 账号锁定 | PC | 列表（关键字 + 锁定类型 + 解锁状态筛选、无操作列、双击行开记录 Tab）；手动锁定；手动解锁；解锁记录（记录 Tab 内可查） |

### 8.2 验收标准 <a id="page-accept"></a>

- 用户 CRUD 全链路可用，软删除后回收站可见、username 可复用（复合唯一索引生效）
- 重置密码后强制改密生效、全部会话失效；停用/删除即时踢出（Redis 标记 + Socket.IO）
- 锁定列表 / 手动锁定 / 手动解锁可用、解锁记录（unlock_by/unlock_at）可查，锁定与解锁动作落操作日志
- 角色分配变更权限计算即时生效（权限版本 +1）；岗位 / 部门分配经 mdm 插件（含「主要」标记）即时提交生效；三权分立互斥校验通过
- **无 mdm 场景（bms 单独运行 / cw 工作区）**：用户页无部门 / 岗位列与筛选，岗位 / 部门分配子页签隐藏——页面其余功能正常、不报错
- `locale` / `timezone` 不在本模块维护（归个人中心），用户页与契约均不含该维护入口
- 批量导入成功/失败明细可查，幂等键防重提交验证通过；user.* 事件 Webhook 推送成功
- 密码策略（复杂度/90 天/近 5 次历史/180 天未登录锁定）强制执行；字段级审计与哈希链校验通过
