## 1. 模块概述与归属 <a id="overview"></a>

登录日志记录**登录成功 / 失败**（登录名、来源、结果、失败原因），与操作日志同属审计域：异步写入、按月分片、哈希链防篡改、90 天热表归档。失败信息为账号锁定判定提供事实依据，但**锁定动作本身仍由认证域执行**（`sys_account_lock`）。字段唯一事实源为表文件，本节点不复制字段清单。

| 项 | 值 |
| --- | --- |
| 对应概要 | [《概要设计 · 登录日志》](../概要设计/12_概要设计_登录日志.md) |
| 对应架构 | [《架构设计 · 审计哈希链》](../架构设计/19_架构设计_子系统_审计哈希链.md) §3 / §4 / §5 / §6 |
| 归属部署单元 / 库 | `platform` 服务 · **平台服务库** `bms_platform`（审计属平台治理数据，集中存放；带 `tenant_id`） |
| 迁移 | 逻辑表不进迁移链（`planned`）；物理分片由运行期 `ensure_shard` 幂等建表 |

| 表 | 用途 | 表文件 |

## 3. 关键设计要点 <a id="key"></a>

- **捕获归认证域**：identity 登录端点统一捕获成功 / 失败，失败原因映射 `rate_limited` / `captcha_invalid` / `account_locked` / `account_disabled` / `bad_credentials` / `backend_unavailable` / `internal_error`；密码本身不落日志。
- **只记事实、不做判定**：失败计数与 `fail_limit` 锁定仍由 identity 限流基座 + platform `apply_login_state` 判定；本表只提供可查证据。
- **链与分片**：与操作日志同一实现（`Sha256HashChain` + 运行期分片 + `sys_audit_shard` 台账），链按 `(login, tenant_id)` 分条。
- **成功登录联动**：`last_login_at` 仍由 platform 写回；登录日志另存一条 `success` 记录供审计。
- **不建物理外键**：`tenant_id` / `user_id` 为逻辑外键。
