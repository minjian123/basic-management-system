## 1. 模块概述与归属 <a id="overview"></a>

## 3. 关键设计要点 <a id="key"></a>

- **库归属与引用关系**：5 表全部落 **platform 服务租户库**（`bms_platform_{code}`，与字典 / 系统参数 / 用户扩展同库）——授权引用的**平台元数据**（`sys_menu` / `sys_form` / `sys_action`）在 platform 服务平台库（同服务、不同库，校验经平台侧完成，不必跨服务）；`sys_user_role.user_id` 指向 **org 服务租户库**的 `sys_user`（跨服务，只存 ID）。一律**逻辑外键**（不 join、不建物理外键）；字典类型（`sys_dict_type`）为同库引用。
- **唯一约束含 `deleted_at`**：5 表唯一键均以 `(业务列…, deleted_at)` 复合，软删除后可复用；**「无来源」以 `0` 表达而非 NULL**，规避唯一约束在 NULL 上的跨库语义差异（MySQL / PostgreSQL / 达梦一致）。
- **授权来源判定**：`sys_role_permission` / `sys_role_field` 的 `source_menu_id` 区分「本菜单入口连带」（可改）与「非本入口来源」（只读）；取消菜单勾选**仅撤销本入口来源**的连带行。
- **数据权限只选不编**：`sys_data_scope.config` 按 `policy_type` 分结构（选择 / 区域 / 匹配 / 扩展），四类并集兜底、默认无、读写双向校验、强制叠加租户过滤（过滤与校验实施归 `02_04` 权限计算引擎）。
- **变更即时生效**：本域写入（角色 / 授权 / 分配 / 字段 / 数据权限）触发**权限版本 +1**（键按租户 `bms:{tenant}:permission:version`，见《后端基类清单》与详细设计 §5.4），供权限计算引擎判定缓存失效。
- **内置角色保护**：内置角色（`system_admin` / `security_admin` / `audit_admin`）由**配置常量**判定，不设库列；禁删、禁停用、禁改归属。

## 4. 与相邻模块的边界 <a id="boundary"></a>

| 相邻 | 归属 | 说明 |
| --- | --- | --- |
| 菜单 / 表单 / 按钮 / 字段元数据 | platform 服务平台库 | 授权只引用其 ID；菜单 ↔ 表单多对多关联表 `sys_menu_form` 归 platform |
| 用户账号 | org 服务租户库（`sys_user`） | 本域只存 `user_id` 逻辑引用；用户完整域 CRUD 归用户管理任务 |
| 岗位 / 部门与角色-岗位 / 角色-部门 | mdm 组织域（产品仓库） | bms 不落表，经具名插槽插件呈现、经只读契约汇聚 |
| 字典类型 / 扩展属性 | platform 服务租户库 | 数据权限按字典配置；匹配字段白名单经字典属性 schema 读出口取 |
