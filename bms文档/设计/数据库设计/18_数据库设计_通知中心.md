# 数据库设计 · 通知中心

> BMS · 数据库设计 · 模块节点 18（通知中心）

## 1. 模块概述与归属 <a id="overview"></a>

通知中心承载**个人维度**的站内信 / 待办提醒：业务方发布 `notification.requested`，通知组消费落库并发布 `notification.sent`、触发实时推送；读面提供列表 / 详情（查看即已读）/ 未读数 / 已读 / 软删除。与公告（全员广播、`sys_notice`）在受众、触发方式与数据表上严格分离。

| 项 | 值 |
| --- | --- |
| 对应概要 | [《概要设计 · 通知中心》](../概要设计/16_概要设计_通知中心.md) |
| 对应架构 | [《架构设计 · 子系统 · 通知公告》](../架构设计/22_架构设计_子系统_通知公告.md) §2 / §6 |
| 归属部署单元 / 库 | notification 服务租户库 `bms_notification_{code}`（域 `notification`，`datasource=tenant`） |
| 迁移 | 历史脚本已清空；结构以模型为唯一事实源，随 `notification:tenant` 链幂等建表 |

## 2. 表清单 <a id="tables"></a>

| 表 | 库 / 链 | 用途 | 表文件 |
| --- | --- | --- | --- |
| `sys_notification` | notification 服务租户库 | 个人站内信 / 待办：收件人、标题、正文、类型、业务标识、已读标记 | [sys_notification.md](数据表设计/sys_notification.md) |

- 用户通知偏好（`sys_user_preference`）归 05-用户喜好 / platform 服务，不在本节点；通知组经 `notification_preference` 能力域跨服务读取。
- 公告（`sys_notice` / `sys_notice_read` / `sys_notice_i18n`）归 19-公告管理，不在本节点。

## 3. 关键设计要点 <a id="key"></a>

- **个人维度**：一行一个收件人；所有查询强制 `user_id = 当前用户`，跨用户详情 / 删除显式拒绝（70102 / 70106）。
- **查看即已读**：详情默认 `mark_read=true`；批量 / 全部已读幂等；未读数以服务端 COUNT 为唯一口径。
- **软删除**：用户删除写 `deleted_at`，列表 / 未读 / 详情 / 删除全部过滤；数据保留至归档。
- **内容语言**：正文由生产方按收件人 locale 渲染后写入，不走 i18n 附表（运行时内容，非可维护文案）。
- **幂等**：消费幂等由 `sys_event_consumed` 负责；`biz_type` / `biz_id` 只做跳转与业务识别，不建唯一约束。
- **索引**：`(user_id, created_at)` 列表倒序、`(user_id, is_read)` 未读与筛选、`(user_id, type)` 类型筛选；业务 3 个 + 公共 `deleted_at` = 4 个（≤5）。

## 4. 与相邻模块的边界 <a id="boundary"></a>

| 相邻 | 归属 | 说明 |
| --- | --- | --- |
| [公告管理](19_数据库设计_公告管理.md) | `sys_notice*` | 公告面向全员，不产生个人站内信；两套事件（`sys.notice.published` / `notification.*`）互不混用 |
| 用户喜好（05） | `sys_user_preference`（platform 服务） | 通知渠道开关与免打扰由通知组读取，不在本节点建表 |
| 事件总线 | `notification.requested` / `notification.sent` | 站内信生成与发送事件；消费幂等归事件账本 |
| 实时推送 | `notification.new` / `approval.todo` | 本节点只存事实，推送通道归实时推送阶段 |
