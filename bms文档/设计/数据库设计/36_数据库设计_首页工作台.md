## 2. 库划分与表定位 <a id="layout"></a>

- **三表全部租户库**：卡片注册表与模板都是**租户级配置**（不同租户可停用不同卡片、维护不同默认布局），与平台库的权限元数据分离。
- **内置卡随租户开通复制**：平台内置卡（`card_type=builtin`）与平台默认模板由租户库种子写入（`bms_core.tenant.seed.dashboard`，幂等且**只增不改**——租户停用后重跑种子不会重新启用）；平台升级新增内置卡时对存量租户重跑同一幂等种子即可补齐。
- **个人布局不落本节点**：个人布局存 `sys_user_preference`（`pref_key = dashboard.layout`），归属用户喜好节点，本节点不新建存储。
- **模板唯一性以 `role_id = 0` 占位**：`(scope, role_id, deleted_at)` 复合唯一在 `NULL` 上不生效（四库同语义），平台层级用 `0` 占位，保证「平台仅一份、一角色至多一份」成立（与 `sys_form_layout` 同范式）。
- **定位键 `code`**：布局与模板只引用卡片 `code`（业务键），不存雪花 ID——卡片删除重建不影响既有模板。

## 4. 表间关系 <a id="relation"></a>

```mermaid
erDiagram
    SYS_DASHBOARD_CARD ||--o{ SYS_DASHBOARD_CARD_I18N : "card_id"
    SYS_DASHBOARD_CARD ||--o{ SYS_DASHBOARD_TEMPLATE : "code（layout_config 内引用）"
    SYS_DASHBOARD_TEMPLATE }o--o| SYS_ROLE : "role_id（scope=role）"
    SYS_USER_PREFERENCE }o--|| SYS_DASHBOARD_TEMPLATE : "个人布局覆盖模板（pref_key=dashboard.layout）"
    RPT_DATASET_PLATFORM["rpt_dataset（报表中心）"] ||--o{ SYS_DASHBOARD_CARD : "dataset_id（scope=dataset）"
```

- 全部为**逻辑外键**，不建物理外键：`card_id` 同库；`role_id` 同库（`sys_role.id`）；`dataset_id` 跨服务（报表中心数据集）。
- 模板对卡片的引用存在 `layout_config` JSON 内（`cards[].code`），不是表间外键关系——解析期按 `code` 匹配卡片注册表并过滤失效项。

## 5. 字段级约定 <a id="fields"></a>

公共字段（`id` / 审计四字段 / `deleted_at` / `version`）语义见《[数据规范](02_数据库设计_数据规范.md)》§2，本节点与表文件不重复展开；类型映射见同文档 §3，多语言附表约定见 §5。

## 6. 分片 / 归档 / 建表 <a id="storage"></a>

- **分片**：均不分片（租户库配置表，体量极小）。
- **归档**：不归档（配置元数据；定义变更留痕走字段级审计）。
- **建表**：三表随 **`platform:tenant` 链**幂等建表落地（表集经表归属登记派生）；启动期 `ensure_service_schema` 自动建表、运维 / CI 经 `ops.init_schema`。
