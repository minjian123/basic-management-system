## 1. 模块概述与归属 <a id="overview"></a>

文件管理承载**文件元数据与上传会话状态**：内容一律存对象存储（MinIO 私有桶 `bms-files`，按租户前缀隔离），**库内只存 key、校验值与状态**，因此本模块的数据设计重点是「元数据的生命周期」而不是「文件内容」。本节点对应 **file 服务租户库** `bms_file_{code}` 的两张表（字段唯一事实源为各表文件，本节点不复制字段清单）。

| 项 | 值 |
| --- | --- |
| 对应概要 | [《概要设计 · 文件管理》](../概要设计/13_概要设计_文件管理.md) |
| 对应架构 | [《架构设计 · 文件管理》](../架构设计/20_架构设计_子系统_文件管理.md) §2 分片状态机、§3 安全控制 |
| 归属部署单元 / 库 | `file` 服务 · 租户库 `bms_file_{code}`（链 `file:tenant`） |
| 迁移 | 历史脚本已清空；结构以模型为唯一事实源，随链幂等建表（删库重建口径） |

## 3. 关键设计要点 <a id="key"></a>

- **元数据与内容分离**：`object_key` 是唯一的内容指针，格式 `{tenant_code}/files/{yyyy}/{mm}/{file_id}`；库内不存内容，也不存可访问 URL（预签名 URL 每次现取，不落库——落库即等于把限时凭证写进历史）。
- **四态状态机**：`uploading` → `completed` / `failed` / `orphan`；`completed` 不回退，`failed` 只能重新初始化（新行）。`completed` 才允许下载与预览。
- **孤儿判据是 `expires_at`**，不看 `created_at` 推算：会话有效期（`[file].session_ttl_seconds`）与 Redis 会话快照 TTL 绑成同一个值，避免「库说没过期、会话已没」的两套真值。
- **分片表只硬删**：分片是临时期数据，`complete` / `abort` / 孤儿回收即物理删；唯一约束因此可写 `(file_id, part_no)` 而不带 `deleted_at`，避开「NULL 互不相等使唯一约束失效」的共性问题（与 `sys_config` 同源）。
- **秒传共享对象**：命中同 `sha256` + `size` 的既有文件时，新行**复制** `object_key`，不重复写对象、不重复占用存储配额；因此 `object_key` **非唯一**，共享引用计数走 `idx_sys_file_sha256_size`（同校验值 + 同大小即同一对象）。物理删对象前必须确认无其他活行引用（清理归 13_01 回收站）。
- **删除语义**：软删（`deleted_at`）只改元数据，**不删对象、不释放配额**——恢复即真恢复；空间释放随 13_01 的物理清理。
- **租户隔离**：表在租户库内，隔离由库边界保证；`object_key` 前缀再叠一层租户编码，防止桶内串目录。
- **不建物理外键**：`file_id` 为逻辑外键。

## 4. 与相邻模块的边界 <a id="boundary"></a>

| 相邻 | 归属 | 说明 |
| --- | --- | --- |
| 对象存储（MinIO） | 部署与运维 | 桶与生命周期策略不在库内；库只记 `bucket` / `object_key` |
| 租户配额 | [26-租户管理](26_数据库设计_租户管理.md) | `storage_bytes` 占用与释放由 tenant 服务记账；本模块只在完成时发起占用 |
| 回收站 | [33-回收站](01_数据库设计_总览.md#structure-modules) | 物理清理与配额释放归 13_01；清理前按「同 `sha256` + `size` 是否仍有活行」判定对象可删 |
| 导入导出 / 打印 | 导入导出节点（概要 19） | 产物复用本模块表（`source=export` / `print`），不另建表 |
| 全文检索 | 全文检索节点（概要 33） | 经 `file.uploaded` 事件驱动，索引不在库内 |
