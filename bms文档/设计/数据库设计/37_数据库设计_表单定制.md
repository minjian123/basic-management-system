## 2. 库划分与表定位 <a id="layout"></a>

- **四表全部租户库**：布局与自建字段都是**租户级配置**（不同租户不同表单形态），与平台库的 `sys_form` / `sys_field` 分离。
- **`scope = platform` 的平台默认布局存在租户库**：随租户开通种子复制（《概要设计 · 表单定制》§4 / §6 口径），读路径零跨库。已开通租户改平台默认不自动回填，属已知口径。
- **定位列统一 `form_code`**（业务码字符串，逻辑引用平台库 `sys_business.code`）：不存雪花 `form_id`，避免渲染热路径跨库与删库重建后 ID 漂移。
- **`role_id = 0`** 表示非角色层级（与 `sys_role_permission.source_menu_id = 0` 同范式，规避唯一约束在 `NULL` 上的跨库语义差异）。
- **`ext_*` 物理列**：运行时在业务表上 `ALTER TABLE ADD COLUMN` 生成，**不在任何迁移 / 建表链**；列类型按 `bms_core/fieldtype/mapping.py` 四库映射，由 SQLAlchemy 按方言编译（不拼字符串）。

## 4. 表间关系 <a id="relation"></a>

```mermaid
erDiagram
    SYS_BUSINESS_PLATFORM["sys_business（平台库）"] ||--o{ SYS_FORM_LAYOUT : "code = form_code"
    SYS_BUSINESS_PLATFORM ||--o{ SYS_FORM_FIELD_ATTR : "code = form_code"
    SYS_BUSINESS_PLATFORM ||--o{ SYS_FIELD_EXT : "code = form_code"
    SYS_FIELD_EXT ||--o{ SYS_FIELD_EXT_I18N : "field_id"
    SYS_FORM_LAYOUT ||--o{ SYS_FORM_FIELD_ATTR : "同 form_code + 同 scope 层级共用"
    SYS_FIELD_EXT }o--|| BUSINESS_TABLE["业务表 ext_* 物理列"] : "column_name"
```

- 全部为**逻辑外键**，不建物理外键；`form_code` 跨库（平台库 → 租户库），`field_id` 同库。
- `sys_form_layout` 与 `sys_form_field_attr` **同层同源**：同一 `(form_code, scope, role_id)` 的布局与属性在解析时取同一层级。

## 5. 字段级约定 <a id="fields"></a>

公共字段（`id` / 审计四字段 / `deleted_at` / `version`）语义见《[数据规范](02_数据库设计_数据规范.md)》§2，本节点与表文件不重复展开；类型映射见同文档 §3。

## 6. 分片 / 归档 / 建表 <a id="storage"></a>

- **分片**：均不分片（租户库配置表）。
- **归档**：不归档（配置元数据；定义变更留痕走字段级审计）。
- **建表**：四表随 **`platform:tenant` 链**幂等建表落地（表集经表归属登记派生）；启动期 `ensure_service_schema` 自动建表、运维 / CI 经 `ops.init_schema`。
- **`ext_*` 物理列不在建表链**：由表单定制域的 DDL 执行器在运行期加列，元数据在 `sys_field_ext`。
