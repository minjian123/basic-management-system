## 1. 目的与适用范围 <a id="purpose"></a>

- 本文承载**全部表的字段级通用约定**：公共字段、类型映射、时间、多语言附表、索引与唯一约束、分片与归档、库划分与迁移归属；**各表文件（`数据表设计/{表名}.md`）只写本表差异**，通用部分不再逐表重复。
- 事实源分工（强制）：
  - **字段级事实源**＝本文（通用约定）+ 各表文件（单表差异）；
  - **方言差异事实源**＝[方言特性](方言特性/01_MySQL.md) 各库文档（MySQL / PostgreSQL / 达梦）；
  - **强制口径**（禁用方言类型、禁方言 SQL、迁移分链、参数化等）见《[数据库开发规范](../../规范/数据库开发规范.md)》「表与字段口径」至「性能口径」各节；本文不重复规范口径。
- 变更传导：本文约定变更 → 先改本文 → 再改受影响表文件与 ORM 模型 → 再改迁移脚本（见《[数据库开发规范](../../规范/数据库开发规范.md)》「迁移与建表口径」节）。

## 2. 公共字段 <a id="common"></a>

全部业务表继承 ORM 模型基类（`app/models/base.py::BaseModel`），公共字段**逐表逐行列出**（表文件「字段」节），语义只在本文说明一次：

| 字段 | 类型 | 可空 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 否 | 主键，雪花 ID（应用侧生成） | 主键；禁用数据库自增列 |
| `created_at` | DATETIME | 否 | 审计（插入自动填充） | 创建时间（UTC） |
| `created_by` | BIGINT | 是 | 审计（插入自动填充） | 创建人（无上下文时为 NULL） |
| `updated_at` | DATETIME | 否 | 审计（插入与更新自动填充） | 更新时间（UTC） |
| `updated_by` | BIGINT | 是 | 审计（插入与更新自动填充） | 更新人 |
| `deleted_at` | DATETIME | 是 | 软删除（NULL = 未删）；**建索引** | 软删除时间 |
| `version` | INT | 否 | 默认 1；`version_id_col` 自动比对与自增 | 乐观锁版本 |

- 审计字段由 ORM 事件自动填充，**业务代码禁止手工赋值**；软删除经 `soft_delete()` / `restore()` 出入，唯一约束统一按 `(唯一字段, deleted_at)` 复合唯一（软删除后释放唯一键）。
- 关联表（两表名单词连接，如 `sys_user_post`）：**联合主键、不设 `id`**；是否带审计与软删除按表文件声明（无 `version` 的表须在表文件「字段」节显式标注）。
- 并发冲突（`version` 不匹配）在服务层转译为统一错误（乐观锁冲突），落点见《[后端基类清单](../../后端基类清单.md)》。

## 3. 类型映射与字段约定 <a id="types"></a>

设计侧一律写**三库通用类型**（表文件「字段」节：`BIGINT` / `VARCHAR(n)` / `DATETIME` / `TEXT` / `BOOLEAN` / `DECIMAL(20,4)`）；ORM 用跨方言逻辑类型，**禁止方言专用类型**（MySQL `ENUM` / PG `SERIAL` / 达梦 `VARCHAR2` 直写等）。实测落点（编译四方言 DDL 与真库验证，2026-09-22）：

| 逻辑类型（设计侧写法） | SQLite | MySQL 8 | PostgreSQL 16 | 达梦 DM8 |
| --- | --- | --- | --- | --- |
| `BIGINT`（主键 / 外键） | BIGINT | BIGINT | BIGINT | BIGINT |
| `DATETIME`（各 `*_at`） | DATETIME | DATETIME | TIMESTAMP WITHOUT TIME ZONE | DATETIME |
| `INT` / `SMALLINT` | INTEGER / SMALLINT | INTEGER / SMALLINT | INTEGER / SMALLINT | INTEGER / SMALLINT |
| `VARCHAR(n)` | VARCHAR(n) | VARCHAR(n) | VARCHAR(n) | VARCHAR2(n CHAR) |
| `TEXT` | TEXT | TEXT | TEXT | TEXT |
| `BOOLEAN` | BOOLEAN | BOOL（TINYINT(1)） | BOOLEAN | SMALLINT |
| `JSON`（多值字段） | JSON | JSON | JSON | JSON |
| `DECIMAL(20,4)`（金额） | NUMERIC(20,4) | DECIMAL(20,4) | NUMERIC(20,4) | DECIMAL(20,4) |

- 布尔：统一 `BOOLEAN`（各库落为布尔 / 小整数等价形式），**不手写方言布尔字面量**；前端真 / 假 / 未设置三态归一口径见《[架构设计 · 数据架构](../架构设计/07_架构设计_数据架构.md)》「数据规范」节。
- 多值字段：统一 `JSON` 存数组（标签类简单集合可逗号分隔字符串），接口仍按数组传输；**例外**——仅在应用侧读写、无需库内 JSON 检索的场景可用 `TEXT` 存 JSON 字符串（如 `sys_user_preference.pref_value`，取最大跨方言安全），须在表文件「字段」节注明理由。
- 字符串**长度显式声明**；超长文本用 `TEXT` 且按需独立成表（避免主表行宽与索引失效）。
- 金额一律 `DECIMAL(20,4)`，禁止 FLOAT / DOUBLE。
- 状态 / 类型字段用短整型或 code 字符串，取值由字典表管理（不写死魔法值）。
- 每表与字段 COMMENT **必填**（中文），与各库注释落点差异见对应方言特性文档。

## 4. 时间与时区 <a id="time"></a>

- 全部时间字段存 **UTC**（naive，不带时区），ORM 侧统一 `datetime.now(UTC).replace(tzinfo=None)` 写入；展示层按本地时区换算（前端职责）。
- 字段命名 `xxx_at`；禁止数据库端默认值 / 方言时间函数（`NOW()` / `SYSDATE` / `datetime('now')`）作为业务语义来源。
- 分区 / 分片键取时间的表（见第 7 节），分片值由应用侧按 UTC 计算后传入。

## 5. 多语言与 i18n 附表 <a id="i18n"></a>

需要多语言的主表，**文案独立成附表**（不在主表加多语言列）：

| 项 | 约定 |
| --- | --- |
| 命名 | `{主表}_i18n`（如 `sys_module_i18n`、`sys_dict_type_i18n`） |
| 归属 | 与主表**同库同链**（随主表迁移） |
| 关键列 | `{主表名}_id`（逻辑外键 → 主表 `id`）、`locale`（`VARCHAR(16)`，小写归一，如 `zh-cn`）、文案列（`name` / `label` / `remark` 等，按表文件声明） |
| 唯一约束 | `({主表名}_id, locale, deleted_at)` 复合唯一（软删除后可复用） |
| 索引 | 主表外键列 `idx_...`（命名见第 6 节）；locale 不单独建索引（复合唯一已覆盖） |
| 语言清单 | 语言清单与固定文案语言包落 `sys_i18n_locale` / `sys_i18n_message`（见总览「核心表清单总表 · 租户库」） |

- 平台默认文案落**平台库**对应附表，租户覆盖文案落**租户库**同名附表；查询按 locale 关联，缺省语言回退规则见《[国际化规范](../../规范/国际化规范.md)》。

## 6. 索引与唯一约束 <a id="index"></a>

- 命名：普通索引 `idx_字段`（多列 `idx_a_b`；ORM `index=True` 由命名约定生成 `idx_{表}_{列}`）、唯一 `uq_字段`（唯一索引名含表名，避免 PostgreSQL / 达梦下索引名库内重名）。
- 建索引的列：**排序字段**（进排序白名单的字段必须建索引，由后端「排序字段索引配合」断言工具校验）、逻辑外键列、数据权限与租户过滤列、软删除参与条件时 `deleted_at`。
- 唯一约束统一 `(唯一字段, deleted_at)` 复合唯一；**不用物理外键**（逻辑外键写 `目标表.字段` 并注明是否同库）。
- 禁止冗余索引（有 `idx_a_b` 不再建 `idx_a`）；每表索引 ≤ 5 个。
- **公共软删除索引**：继承 ORM 模型基类的表均由元数据命名约定生成 `idx_{表}_deleted_at`（`deleted_at` 恒建索引），**表文件「索引与约束」节只列业务索引**，不重复列该公共索引（与「公共字段语义只在本文说明一次」同口径）。
- 分片表与归档表的索引在「物理分片表」上建（见第 7 节）；各库索引能力差异（部分索引、索引名前缀长度等）见对应方言特性文档。

## 7. 分片与归档 <a id="sharding"></a>

- **分片键**：语义名 `tenant`（一租户一库时由库级隔离承担）或 `date`（时间分片）；分片规则在 repository 层声明（分片注册表：逻辑表 → 分片键 + 物理表名模板），不做透明代理。
- **MVP 时间分片表**：`sys_operation_log` / `sys_open_log` / `sys_data_audit_log` / `ai_chat_log` 按月分片，物理表名带 `yyyyMM` 后缀（逻辑表名不带后缀）；新月份分片表由 Celery 定时任务提前创建，过期分片归档后物理清理。
- **查询约束**：跨库禁止 JOIN（服务层聚合或事件同步）；分片表查询**强制带分片键条件**，缺分片键的查询拒绝执行或告警。
- **归档**：归档库 `bms_archive` **只读**，承载可归档历史数据；归档策略、留存期与清理顺序见《[架构设计 · 数据架构](../架构设计/07_架构设计_数据架构.md)》「回收站机制」节与《[架构设计 · 数据访问与分片](../架构设计/13_架构设计_子系统_数据访问与分片.md)》「分片路由」节；归档流转与任务调度衔接（先归档再物理清理）。
- 单表「是否分片 / 是否归档」在**表文件「分片 / 归档 / 迁移」节**逐表声明，本节点不列举。

## 8. 库划分与迁移归属 <a id="migration"></a>

| 归属库 | 命名 | 迁移链 | 承载 |
| --- | --- | --- | --- |
| 平台库 | `bms_platform` | `platform` | 平台级配置与注册（租户、模块、平台超管、全局字典默认等） |
| 租户库 | `bms_tenant_{code}` | `tenant` | 租户业务数据（一租户一库） |
| 归档库 | `bms_archive` | `archive` | 归档历史数据（只读） |

- 表归属与状态在《[数据库设计总览](01_数据库设计_总览.md)》「已设计数据表登记」登记（表文件为字段唯一事实源，未登记视为未定稿）；迁移链组织、编号、命令与建删库口径见《[数据库开发规范](../../规范/数据库开发规范.md)》「迁移与建表口径」节。
- 表结构每次变更：**先改表文件（追加变更记录）→ 改 ORM 模型 → 生成迁移脚本 → 回写状态**；SQLite 开发库由启动期自动建表（按链表集），真库一律走迁移。
- 骨架表（仅结构声明、本阶段不建表）在表文件「分片 / 归档 / 迁移」节标注「本阶段仅结构声明，不建表」，由其所属阶段自带迁移。

## 9. 检查清单 <a id="checklist"></a>

- □ 公共字段齐全（`id` / 审计 / 软删除 / `version`），语义未在表文件重复展开
- □ 类型为三库通用类型与逻辑类型，无方言专用类型；字符串长度显式
- □ 时间字段 UTC、命名 `xxx_at`，无数据库端时间函数语义
- □ 多语言文案走 `{主表}_i18n` 附表，复合唯一为 `({主表名}_id, locale, deleted_at)`
- □ 索引命名 `idx_` / `uq_`、排序与外键列已建索引、无冗余索引、每表 ≤ 5 个
- □ 分片 / 归档 / 迁移（含是否建表）已在表文件逐表声明；表文件已在总览登记
- □ 方言差异已核对对应方言特性文档（类型映射 / DDL / NULL 语义 / 标识符 / 事务）
