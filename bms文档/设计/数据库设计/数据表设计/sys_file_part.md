## 2. 字段 <a id="fields"></a>

公共字段继承 `BaseModel`（雪花 ID / 审计 / 软删除 / 乐观锁），下表不再重复说明其语义。
本表是**断点续传的分片状态权威**：某文件已收哪些片、每片校验值，均以本表为准。

| 字段 | 类型 | 可空 | 约束 / 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 否 | 主键，雪花 ID | 主键 |
| `file_id` | BIGINT | 否 | 与 `part_no` 复合唯一 | 所属文件（逻辑指向 `sys_file.id`，无物理外键） |
| `part_no` | INT | 否 | 与 `file_id` 复合唯一 | 分片序号（从 1 起） |
| `size` | INT | 否 | > 0 | 分片字节数（末片可小于分片大小） |
| `sha256` | CHAR(64) | 否 | — | 分片 SHA256（服务端复算值与客户端声明比对通过后落库） |
| `etag` | VARCHAR(128) | 是 | — | 存储侧分片 etag（留痕；MinIO 组合按对象名，不依赖此值） |
| `created_at` | DATETIME | 否 | 审计 | 创建时间（UTC） |
| `created_by` | BIGINT | 是 | 审计 | 创建人 |
| `updated_at` | DATETIME | 否 | 审计 | 更新时间（UTC） |
| `updated_by` | BIGINT | 是 | 审计 | 更新人 |
| `deleted_at` | DATETIME | 是 | 软删除（NULL=未删） | **本表不使用软删**（见 §4），列随基类保留 |
| `version` | INT | 否 | 默认 1 | 乐观锁版本 |

## 3. 索引与约束 <a id="index"></a>

| 名称 | 类型 | 列 | 说明 |
| --- | --- | --- | --- |
| `uq_sys_file_part_file_id_part_no` | 唯一 | `(file_id, part_no)` | 同文件同片唯一（重传为覆盖写，不是新增行） |
| `idx_sys_file_part_file_id` | 普通 | `(file_id)` | 按文件取全部片（断点状态列表 / 合并前齐全校验） |

- 无物理外键。
- 业务索引 2 个（公共 `idx_sys_file_part_deleted_at` 由基类元数据约定生成，不在此重复列）。

## 4. 分片 / 归档 / 建表 <a id="storage"></a>

- **只做硬删，不做软删**：分片是上传过程中的临时期数据，`complete` 成功、`abort` / 失败、孤儿回收时**物理删除**；因此唯一约束写 `(file_id, part_no)` 而**不带 `deleted_at`**，规避「`deleted_at IS NULL` 时 NULL 互不相等导致唯一约束失效」的全平台共性问题（同问题登记见 `sys_config` 表文件 §3）。
- **不分片、不归档**（行随上传会话生命周期存在，最长 = 会话过期时长）。
- **建表**：已定稿并进入 file 服务的**租户链**，由启动期建表引导 / `ops.init_schema` 幂等建表落地（`sys_table_ownership.status = enabled`）。
