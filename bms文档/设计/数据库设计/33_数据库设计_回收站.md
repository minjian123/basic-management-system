## 1. 模块概述与归属 <a id="overview"></a>

回收站承载软删除数据的查看、恢复与超期物理清理。**软删除数据不另建表**：复用各业务表的 `deleted_at` 字段（NULL = 未删），回收站只读 / 只改该字段；超期清理的逐表批次留痕新建 `sys_recycle_log`（platform 服务租户库）。字段唯一事实源为表文件，本节点不复制字段清单。

| 项 | 值 |
| --- | --- |
| 对应概要 | [《概要设计 · 回收站》](../概要设计/32_概要设计_回收站.md) |
| 对应架构 | [《架构设计 · 数据架构》](../架构设计/07_架构设计_数据架构.md)「回收站机制」、[《架构设计 · 扩展点与插件化》](../架构设计/10_架构设计_子系统_扩展点与插件化.md)「回收站」 |
| 归属部署单元 / 库 | `platform` 服务租户库 `bms_platform_{code}`（清理批次表与平台自有业务表同库） |
| 迁移 | `sys_recycle_log` 为 `status = enabled`，进 platform 服务租户链；软删除数据表沿用各自既有归属 |

> **新表例外**：《概要设计 · 回收站》§4 原文写「本模块无独立新表」。软删除数据仍无独立表；新增的 `sys_recycle_log` 只承载**清理批次留痕**（不是回收站数据表），与归档执行记录同构，差异已回写概要设计节点。

## 2. 表清单 <a id="tables"></a>

| 表 | 用途 | 表文件 |
| --- | --- | --- |
| `sys_recycle_log` | 超期软删除数据物理清理的逐表批次记录（条数 / 状态 / 耗时 / 保留期） | [sys_recycle_log.md](数据表设计/sys_recycle_log.md) |
| 各业务表 | 软删除数据本体（`deleted_at` 非空即进入回收站），无独立回收站表 | 见各模块节点与表文件 |

## 3. 关键设计要点 <a id="key"></a>

- **复用软删除**：回收站不复制数据、不做「删除快照表」；列表 / 详情直接查原表的 `deleted_at` 非空行，恢复即清空该列。
- **唯一约束口径不变**：业务唯一约束统一 `(唯一字段, deleted_at)`；恢复前按业务键预检冲突，数据库约束兜底。含 `form_key` 的复合唯一不作为恢复冲突依据（页面标识，不是行唯一键）。
- **纳管表规格**：首批 12 张可见业务表 + 6 张级联子表，登记在 `bms_core/recycle/registry.py`；子表不单独出列表，随主表级联恢复，但同样参与超期清理。
- **清理批次逐表一行**：同一次作业共享 `batch_key`，按 `table_name` 区分；`status` 三态（`running` / `success` / `failed`），`running` 超时回收为 `failed`。
- **同库同事务**：清理批次表与被清理数据同在 platform 租户库，避免「数据删了、记录没写」的跨库窗口。
- **服务边界**：平台回收站只触达 platform 自有租户表；文件服务 `sys_file` 与其他服务 / 产品表由各自服务复用基座引擎接入，平台不跨库。
