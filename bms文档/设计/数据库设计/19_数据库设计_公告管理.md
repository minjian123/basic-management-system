## 1. 模块概述与归属 <a id="overview"></a>

公告管理承载**租户全员**公告：发布 / 编辑 / 软删除、置顶、过期自动下线、已读回执与已读 / 未读统计。公告与个人站内信（`sys_notification`）在受众、触发方式与数据表上严格分离；发布 / 更新 / 过期下线经 `sys.notice.published` 出站供 Webhook 订阅。

## 3. 关键设计要点 <a id="key"></a>

- **主键与软删除**：三表均继承 `BaseModel`（雪花 ID 主键 + `deleted_at` 软删除 + 审计 + 乐观锁）；回执 / 附表唯一约束统一带 `deleted_at`（阶段八贯穿口径），**不使用联合主键**。
- **状态机**：`draft` 草稿 → `published` 发布中 → `offline` 已下线；`offline → published`、`published → draft`、`draft → offline` 拒绝（70204）。
- **可见性**：`status=published AND publish_at <= now AND (expire_at IS NULL OR now < expire_at)`；读取侧实时校验，过期扫描只做状态收敛与下线事件，不承担展示兜底。
- **置顶排序**：`is_top DESC, CASE WHEN is_top THEN updated_at ELSE publish_at END DESC, id DESC`；置顶组内按更新时间（概要口径），非置顶组按发布时间。
- **多语言**：标题 / 正文逐语言存 `sys_notice_i18n`；主表两列是系统默认语言派生快照，调用方只提交 locale 映射；读取三级回退（显式 locale → `Accept-Language` → 默认常量 → 主表列）。
- **回执幂等**：`(notice_id, user_id)` 先查后插 + 唯一约束兜底；重复阅读保留首次 `read_at`。
- **统计口径**：已读 = 回执去重用户数；应读 = 平台当前启用用户数（实时读取）；未读 = `max(应读 - 已读, 0)`；已停用用户存量回执仍计入已读，读 > 应读时未读记 0。
- **审计**：`sys_notice` 属关键表，字段级变更经 ORM 事件记录（由 notification 服务装载期注册白名单）；回执与 i18n 附表不单独审计。
- **索引**：`sys_notice` 业务 3 个（`(status,is_top,publish_at)` / `(status,expire_at)` / `(type)`）+ 公共 `deleted_at` = 4；`sys_notice_read` 唯一 + `(user_id)` + 公共 = 3；`sys_notice_i18n` 唯一 + 公共 = 2。

## 4. 与相邻模块的边界 <a id="boundary"></a>

| 相邻 | 归属 | 说明 |
| --- | --- | --- |
| [通知中心](18_数据库设计_通知中心.md) | `sys_notification` | 个人站内信；公告不产生个人站内信，两套表与事件互不混用 |
| 国际化管理（30） | `sys_i18n_locale` / `sys_i18n_message`（platform 服务） | 公告多语言只走本节点 `sys_notice_i18n`；默认语言标记暂由基座常量兜底 |
| 用户管理（04） | `sys_user`（platform 服务） | 应读人数经平台用户只读出口实时取启用用户数，不跨库读 `sys_user` |
| 任务调度（24） | `sys_task` / `sys_task_log` | 过期下线为内置任务 `expire_notices`（每小时），执行体调通知服务内部端点 |
| 归档（31） | 归档策略机制 | 两表可纳入 14_01 归档策略；本节点不建策略 |
| 事件总线 | `sys.notice.published` | 发布 / 更新 / 过期下线出站；载荷含可选 `action` 与类型 / 优先级 / 时间 |
