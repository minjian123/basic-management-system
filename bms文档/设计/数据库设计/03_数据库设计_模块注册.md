## 1. 模块概述与归属 <a id="overview"></a>

模块注册承载平台的**服务目录与契约登记**：以 `sys_module` 为**单一登记表**登记服务 / 模块的注册要素（表前缀 / 业务码 / 错误码段 / 事件域 / 契约版本），并以轻量**产品档案表 `sys_product`** 承载**产品级注册**（产品标识 / 名称 / 前端包来源 / 状态），`sys_module.product_key` 逻辑引用之。本节点对应 **platform 服务平台库** `bms_platform` 的三张表（字段唯一事实源为各表文件，本节点不复制字段清单）。

| 项 | 值 |
| --- | --- |
| 对应概要 | [《概要设计 · 模块注册》](../概要设计/02_概要设计_模块注册.md) |
| 对应架构 | [《架构设计 · 模块注册》](../架构设计/11_架构设计_子系统_模块注册.md) |

## 3. 关键设计要点 <a id="key"></a>

- **单一登记表**：模块 / 服务级注册要素（`table_prefix` / `business_code` / `errcode_segment` / `event_domain` / `service_version` / `contract_version`）只在 `sys_module`；**产品级属性只存 `sys_product`**（`name` / `frontend_package_source` / `status`），模块行不重复。
- **先注册后建表**：产品先登记注册要素再建表 / 建代码；**产品可先于其模块登记**，不要求产品必有模块（`mdm` 随产品接入补登记各域）。
- **唯一性两段承担**：非空列（`module_key` / `table_prefix` / `event_domain`）建 DB 复合唯一（含 `deleted_at`，软删后可复用）；可空列（`service_key` / `errcode_segment`）与产品 / 模块归属一致性由**启动（离线校验）+ CI（接库对账）**承担（规避达梦多 NULL 差异）。
- **一律逻辑外键**：`sys_module.product_key` 逻辑引用 `sys_product.product_key`，`sys_module_i18n.module_id` 逻辑引用 `sys_module.id`；不建物理外键。
- **只读运行时**：运行时不提供增删改（只读查询）；新增模块 = 一个 revision（建表 + 种子）原子落地，种子走 `ops/seed_module.py` 幂等 upsert（`SERVICE_CATALOG` / `PRODUCT_CATALOG` 单一来源）。
- **下线保留登记**：产品下线 `sys_product.status = retired`、模块注销 `sys_module.status`，不物理删除、不回收错误码段位（架构 11「模块契约与产品下线」节）。

## 4. 与相邻模块的边界 <a id="boundary"></a>

| 相邻 | 归属 | 说明 |
| --- | --- | --- |
| 菜单 / 表单 / 按钮 / 字段 / 动作元数据 | platform 服务平台库 | 业务码（`sys_business` / `sys_action`）与 `business_code` 对应关系归菜单管理节点 |
| 表归属登记 `sys_table_ownership` | platform 服务平台库 | 表 → 「归属服务 + 库类别」单一来源（候选 06_03）；本节点只登记模块与产品注册要素 |
| 租户 / 用户 / 角色 | platform 服务（平台库 / 租户库） | 各归其节点；本节点不做跨服务引用 |
