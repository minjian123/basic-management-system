## 1. 概述 <a id="overview"></a>

任务调度子系统为**自研双角色**（beat 调度器 + Redis 队列执行器，01_02 落定，原 Celery 方案作废）：任务定义入库（sys_task）、
页面动态增删改与启停、手动触发、执行历史。对应[《项目规划说明》](../../规划/项目规划说明.md)的「定时任务」章节，覆盖任务调度模块。

## 2. 任务模型 <a id="model"></a>

- `sys_task`：code / name、handler（`module:attr` 执行体路径）、cron、args、status、next_run_at、last_run_at、remark
- `sys_task_log`：task_id、run_id、trigger_source、status（running/success/failed/**skipped**）、retry_count、cost_time、error_msg、started_at、finished_at
- 权限码：查询 task:query、维护与启停 task:manage、手动触发 task:trigger

## 3. 调度器设计 <a id="scheduler"></a>

- beat 单副本长驻：逐租户扫描到期任务，按 cron 计算 next_run，**条件 UPDATE 抢占**（`WHERE next_run_at <= now`，`rowcount = 1` 才算抢到）后落 `running` 记录、再 `LPUSH` 进队列
- 单副本保障 = **数据库 CAS 抢占 + Redis 锁双保险**：锁（`bms:global:lock:beat`）只省扫描，正确性由 CAS 保证——锁在 TTL 边界 / 网络分区失效时第二个 beat 的 UPDATE 因 `rowcount = 0` 自动让行
- 变更热加载：任务 CRUD/启停 → Redis pub/sub **只做唤醒**（不持久、断线即丢），正确性由 `poll_interval` 周期轮询兜底，最多晚一个周期生效
- 任务队列与事件总线解耦（Redis 管任务，RocketMQ 管事件）；执行器不依赖 Celery（无 kombu / 无 broker 语义映射）

## 4. 执行与重试 <a id="execution"></a>

- 执行器多副本横向扩展：多协程 `BRPOP` 抢消息（一消息只被一个副本拿到）；失败**应用内**退避重试（`backoff × 2^(n-1)`，只对异常重试），不把失败消息丢回队列放大重试次数
- 执行器为 asyncio 进程：执行体统一 `async`，租户库会话经 `TaskContext.session()` 注入；**禁止任务内自行 asyncio.run 或另建事件循环**（跨循环复用连接会引发运行时错误）
- 终止态（success / failed / **skipped**）与执行记录**同事务**写 `sys_outbox`，发 `sys.task.completed`（Webhook 默认不可订阅）；重试中间态不发事件
- worker 失联兜底：`running` 超过 `run_timeout_seconds` 由 beat 回收为 `failed`（失败可查）
