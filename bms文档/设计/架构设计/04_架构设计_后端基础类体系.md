> BMS · 基座分层、基类清单与贯穿全阶段的实施约束

## 1. 概述 <a id="overview"></a>

后端基础类体系定义 backend（FastAPI）的**基座分层、各层基类清单与继承关系、扩展规则与阶段落地**，是《[后端开发规范](../../规范/后端开发规范.md)》「后端基座体系（强制）」节与「模块组织」「异步与并发」节在架构层的落地依据（本节点定分层、清单与**强制用法细则**，规范定强制性规则口径，二者同源）。对应[《总体项目规划》](../../规划/总体项目规划.md)的「阶段内容与完成标准」节阶段一（基座体系骨架与接口占位）与阶段二（真实实现）；工程结构与分层职责见[03-总体架构](03_架构设计_总体架构.md)、数据访问机制见[13-数据访问与分片](13_架构设计_子系统_数据访问与分片.md)。

**为什么单列节点**：后端基座是**影响全局、贯穿全程**的地基——core 基座（根基类、有序集合、并发集合、Redis 封装、异常、配置、安全）与模块基类（repository / service / schema / model）决定所有模块的写法，任一基类能力调整即全链生效；基座不完成，认证 / RBAC / 通用能力等全部后端模块无法按统一口径实现（CRUD、序列化、并发保护、异常语义在每个模块重复实现，口径必然发散）。因此后端基座与前端组件库（[05-前端组件体系](05_架构设计_前端组件体系.md)）并列：基座体系（骨架 + 接口占位）随阶段一交付，真实实现（机制落库与三库实测）随**阶段二 后端基座**。

## 2. 体系定位与范围 <a id="position"></a>

## 3. 基座分层 <a id="layers"></a>

后端基座以 **根系 根基类**为根，向上分出三条支线：**集合体系**（有序 / 并发 / 跨副本）、**模块基类**（数据访问到模型）、**core 横切基座**（配置 / 异常 / 安全 / 日志）。公共字段与方法只在所属基类维护，模块类只写差异部分。

```mermaid
flowchart TD
    根系["根系 根基类 BaseObject<br/>to_dict / to_json / __str__ / __repr__ / __eq__ / __hash__"]
    COL["集合体系<br/>BaseSorted → SortedList / SortedDict / SortedSet"]
    CONC["进程内并发集合<br/>BaseConcurrentSorted → ConcurrentSorted*"]
    REDIS["跨副本有序封装<br/>redis_collections（ZSET / Hash / List + Lua 复合操作）"]
    REPO["BaseRepository[T]<br/>通用 CRUD + 派生方法 + 数据源/分片路由"]
    SVC["BaseService[T]<br/>通用 CRUD 委派 + 不存在语义"]
    BTS["BaseTransactionalService[T]<br/>事务边界（UnitOfWork）"]
    UOW["UnitOfWork<br/>事务公共方法 begin/commit/rollback"]
    SCH["BaseSchema<br/>Pydantic 公共配置"]
    ORM["BaseModel<br/>雪花 ID / 软删除 / 审计字段 / 乐观锁"]
    CORE["core 横切<br/>配置 / 异常与错误码 / 安全 / 日志"]
    MOD["模块类<br/>XxxRepository / XxxService / XxxSchema / XxxModel"]
    根系 --> COL
    COL --> CONC
    CONC --> REDIS
    根系 --> REPO
    根系 --> SVC
    根系 --> SCH
    根系 --> ORM
    根系 --> CORE
    REPO --> MOD
    SVC --> BTS
    BTS --> MOD
    BTS --> UOW
    SCH --> MOD
    ORM --> MOD
```

> 各层基类一览（层 / 基类 / 形态 / 父层 / 代码位置 / 职责 / 状态）以《[后端基类清单](../../后端基类清单.md)》「分层总览」为准，本节点只给分层视角。

约定：只准上层依赖下层；基类一律 `Base` 打头，非 `Base` 打头为继承基类的具体实现类（命名自由）；模块类必须继承对应基类，**禁止重复定义基类已提供的公共字段/方法**；新增公共能力只加到基类或新增基类层（`BaseObject` 是公共方法唯一落点）。

## 4. 基类清单与继承链 <a id="classes"></a>

模块基类是**平行的兄弟基类**（各自继承根系 `BaseObject`，互不继承）；模块类分别继承对应基类。它们之间是**调用链**（服务调用仓储、仓储操作模型），不是继承层级。

**基类清单与继承链以《[后端基类清单](../../后端基类清单.md)》为准**——「分层总览」表、「根系 / 集合体系 / 模块基类 / 中间层基类 / core 横切 / 数据访问与多租户 / 跨阶段基座」各节、「继承链与代码位置」节与「基类候选」节；本节点不复制清单（状态随清单回写）。

## 5. 有序与并发集合 <a id="collections"></a>

集合体系（有序 / 进程内并发 / 跨副本三类形态、锁原语与复合操作语义）见《[后端基类清单](../../后端基类清单.md)》「集合体系」节；**强制用法**（对外稳定序、并发集合原子复合方法与快照遍历、跨副本禁进程内共享、锁内禁 IO 与外部回调）以《[后端开发规范](../../规范/后端开发规范.md)》「后端基座体系（强制）」节为准。

## 6. core 横切基座 <a id="core"></a>

core 横切基座（配置 / 异常与错误码 / 安全 / 日志 / 稳定序列化 / 并发锁原语 / 雪花 ID / 请求上下文）见《[后端基类清单](../../后端基类清单.md)》「core 横切基座」节；链路 / 健康检查 / 开放接口鉴权等横切契约见清单「跨阶段基座」节与 [27-可观测性](27_架构设计_子系统_可观测性.md)、[09-接口与集成](09_架构设计_接口与集成.md)、[14-认证与会话](14_架构设计_子系统_认证与会话.md) 等对应子系统节点。

## 7. 各层基类与模块约定 <a id="convention"></a>

| 模块类 | 必须继承 | 只写什么 |
| --- | --- | --- |
| `XxxRepository` | `BaseMemoryRepository[T]`（内存基线）/ `BaseDbRepository[T]`（数据库实现） | 均继承契约 `BaseRepository[T]`；内存基线只实现 `_build` / `_apply`，数据库实现覆写 CRUD，`exists` 沿用 |
| `XxxService` | `BaseService[T]`（通用）/ `BaseTransactionalService[T]`（需事务） | 通用 CRUD 走基类；业务规则以覆写 / 新增方法实现；事务由 `BaseTransactionalService` 经 `UnitOfWork` 统一 |
| `XxxCreateRequest` / `XxxResponse` | `BaseSchema` | 字段与约束 |
| 分页请求 / 响应 | `BasePageQuery` / `BasePageResponse[T]` 或 `BaseCursorQuery` / `BaseCursorResponse[T]` | 列表接口统一分页契约 |
| 接口响应 | `ApiResponse` | 统一响应 `{code, message, data}`；列表分页 `data` 用分页响应契约 |
| `XxxModel` | `BaseModel` | 表名、字段、关系；公共字段（雪花 ID / 审计 / 软删除 / 乐观锁）不得重复声明 |

禁止：在模块类重复定义基类已提供的公共字段 / 方法；绕过基类另起炉灶（新增公共能力加到基类，改一处全局生效）。

## 8. 强制用法（细则） <a id="usage"></a>

> 本节为《[后端开发规范](../../规范/后端开发规范.md)》（「后端基座体系（强制）」节的强制性规则口径）在架构侧的**能力域细则**展开——各能力域「必须走哪个基类、关键契约与禁止事项」随基类与能力域变化在设计侧维护（规范不再逐条复制）；基类是否存在、在哪层、代码位置与状态以《[后端基类清单](../../后端基类清单.md)》为准。

- **必须继承（覆盖一切自定义类，强制）**：后端**所有自定义类都必须继承项目基类**，不得以 Python 内建 `object` 为唯一基类——普通类以 根系 根基类 `BaseObject` 为根、经各层基类落地：`XxxRepository → BaseRepository[T]`、`XxxService → BaseService[T]` / `BaseTransactionalService[T]`、请求/响应模型 → `BaseSchema`、ORM 模型 → `BaseModel`、普通类 / 值对象 → `BaseObject`、集合 → `BaseSorted` / `BaseConcurrentSorted`、能力域契约 → `BaseCapability` / `BaseEventWorker`、占位 → `BaseNullObject` / `BaseStub`、异步资源 → `BaseAsyncResource`；**数据契约（dataclass 值对象）也必须继承 `BaseObject`**（统一 `to_dict` / `to_json` / 字符串输出），公共方法只在基类维护。CI 静态护栏 `tests/core/test_base_inheritance.py` 校验本约定：扫描 `app/` 下无基类、仅继承 `object` / 内建异常等禁止基类的类，命中即失败。
- **异常类必须继承异常基类（强制）**：一切自定义异常继承 `BizError`，并按错误码段位归入段位基（`GeneralError` 1xxxx 通用 / `AuthError` 2xxxx 认证 / `UserOrgError` 3xxxx 用户与组织 / `ConfigError` 4xxxx 系统配置 / `OpenTenantError` 8xxxx 开放·租户·SSO；新增段位先加段位基）；异常类统一落 `app/core/exceptions.py`、错误码落 `app/core/error_codes.py`。**禁止**自定义异常直接继承 Python 内建 `Exception` / `RuntimeError` / `ValueError` 等，禁止在模块内就地定义游离于异常体系之外的异常类。
- **禁止**：模块类重复定义基类已提供的公共字段/方法；绕过 `BaseService` 直连 `BaseRepository`；直接继承 `pydantic.BaseModel`；另起炉灶新建平行的 CRUD / 序列化 / 并发 / 异常 / 日志实现。
- **集合**：有序集合对外输出稳定序、禁止裸 `set`；多线程共享走并发集合（`ConcurrentSorted*`，锁策略显式传入）；跨副本走跨副本封装（`RedisSortedSet` / `RedisSortedDict` / `RedisSnapshot`，Redis 为事实源），禁止进程内集合跨副本共享；锁内不得做 IO 与外部回调。
- **排序**：列表接口排序一律走排序契约——请求继承 `BaseSortQuery`（`order_by` 逗号分隔 + `order` 方向数组，缺省 `desc`，口径见《[API接口规范](../../规范/API接口规范.md)》「参数与分页」节），仓储以类属性 `sortable_fields` 声明可排序字段白名单，**白名单外字段忽略**；排序字段禁止直接拼接用户输入（DB 侧在 `_apply_sort` 钩子内落地）。
- **中间层**：占位实现继承 `BaseNullObject` / `BaseStub`（统一 `_not_implemented` 抛错），能力域契约继承 `BaseCapability` / `BaseEventWorker`，异步资源继承 `BaseAsyncResource`（统一 `aclose`）。
- **插件化（能力可替换）**：平台能力的实现可替换一律走「能力基类 + 插件注册表」——平台内建实现继承能力基类（推荐演进为继承中间层 `BasePluggable`，见平台《架构设计 · 扩展点与插件化》（10 号节点）），实现经注册表登记且 `(plugin_key, plugin_name)` 唯一；业务代码只依赖能力基类与提供者 `get_xxx`，**禁止直连具体实现**（不直接 `import` MinIO / 模型 / 厂商 SDK 等），换实现只改 `config.toml` 的 `provider` + `options`（阶段一重启生效）。第三方 / 项目二次开发实现可不继承基类，经显式 `register_plugin(...)` 或 `BaseXxx.register(...)` 虚拟子类 / `Protocol` 结构化登记（继承 / 组合双轨，两条路径汇入同一注册表，均须过契约测试）；`provider` 名与实现名视为契约，变更走破坏性变更流程。
- **脱敏与权限**：敏感字段掩码一律走 `BaseMasker`（`masking/base.py`：字段注册 + `mask` / `reveal`，持 `data:plain` 的判定在基座内，调用方不传权限参数）；请求 / 响应模型以类属性 `masked_fields` 声明敏感字段，序列化自动掩码（未注入掩码器时直通）；权限码校验一律走 `BasePermissionChecker`（`permission/base.py`，接口侧用 `require_permission` 依赖工厂）。禁止各模块自行掩码或另起权限校验。
- **分布式锁**：跨实例（多副本）互斥一律走 `BaseDistributedLock`（`lock/base.py`：异步 `acquire` 带 TTL 返回锁令牌 / `release` 按令牌释放 / `extend` 续租 / `hold` 异步上下文，未取到锁抛 `ConcurrentConflictError`）；锁 key 经 `build_lock_key` 统一拼接，禁止自研 SETNX 或自拼 key；锁内禁止长 IO 与外部回调。同实例并发仍走 `core/locking.py` 原语（`LockStrategy` / `ReadWriteLock` / `LockGuard`），两类锁可叠加。
- **验证码与密码策略**：图形验证码与密码策略一律走能力域基座——验证码用 `BaseCaptcha`（`captcha/base.py`：异步 `generate(scene)` / `verify(captcha_id, code)`，key 经 `build_captcha_key`、TTL 取 `CAPTCHA_TTL`），密码复杂度 / 有效期 / 历史重复用 `BasePasswordPolicy`（`password/base.py`：异步 `validate` / `expired` / `reused`，违规原因码取 `PASSWORD_VIOLATIONS`）；密码**哈希**仍走 `core/security.py` 的 `PasswordHasher`。禁止在登录实现内自研验证码或密码策略。
- **降级与熔断**：依赖故障应对一律走能力域基座——降级动作用 `BaseFallbackPolicy`（`fallback/base.py`：异步 `resolve(dependency, *, exc)` 返回 `FallbackAction`），熔断放行与记录用 `BaseCircuitBreaker`（`circuit/base.py`：异步 `allow` / `record_success` / `record_failure` / `state`）；依赖标识取 `DEPENDENCIES`（单一落点）。禁止调用点各自 `try/except` 硬编码降级分支或自研熔断计数。
- **限流 / 幂等 / 防重放**：写接口防护一律走能力域基座——限流用 `BaseRateLimiter`（`ratelimit/base.py`：异步 `check(key, rule)` 返回 `RateLimitDecision`，接口层一行接入用 `require`，超配额抛 `RateLimitError` 10005 / 429），key 经 `build_rate_limit_key`（维度取 `RATE_LIMIT_DIMENSIONS`）；幂等用 `IdempotencyStore`（`idempotency/base.py`：`begin` 前置去重 → `load` 取首次结果直接回响应 → `save` 写首次结果），key 经 `build_idempotency_key`、请求头取 `IDEMPOTENCY_HEADER`；开放接口防重放用 `BaseReplayGuard`（`replay/base.py`：`verify` / `require`，时间窗 `X-Timestamp` + 签名 `X-Signature` + `X-Nonce` 由基座统一编排，签名计算取 `core/security.py` 的 `SignatureCodec`）。禁止各模块自研限流计数、自拼幂等 / 限流 key 或自实现 HMAC 签名。
- **指标与链路（可观测性）**：指标一律走 `BaseMetrics`（`metrics/base.py`：异步 `counter` / `gauge` / `histogram`，指标名取 `METRIC_NAMES`（`bms_` 前缀）、依赖状态类标签 `dependency` 取 `DEPENDENCIES`），链路一律走 `BaseTracer`（`tracing/base.py`：`async with tracer.span(name)` 异步上下文，异常路径自动结束与复位）；链路 id 一律读 `core/context.py` 的 `current_trace_id` / `current_span_id`（入站 `X-Trace-Id` 由 `api/middleware.py` 的 `TraceIdMiddleware` 生成 / 透传，中间件为纯 ASGI 实现）。禁止各模块自埋指标、自生成链路 id 或自写 trace 中间件。
- **健康检查（就绪探针）**：依赖就绪检查项一律实现 `BaseHealthCheck`（`health/base.py`：`name` + 异步 `check() -> HealthCheckResult`）并注册到 `BaseHealthCheckRegistry`（`key = "health_check_registry"`；`aggregate` 聚合模板收敛异常兜底与空集语义），`/readyz` 一律经注册表聚合（全部就绪 200、否则 503）；依赖类检查项 `name` 取 `DEPENDENCIES`（与降级 / 熔断 / 指标同源）。禁止在探针路由内硬编码依赖检查或另起聚合。
- **开放接口鉴权**：开放接口服务端签发 / 撤销一律走 `BaseOAuthServer`（`oauth/base.py`：异步 `issue_token(ClientCredentials)` 返回 `OAuthToken`、`revoke(token)`），授权面 scope 校验一律走 `BaseScopeChecker.check(granted, required)`（同步纯比对）；开放接口**先 scope 后权限码**（权限码仍走 `BasePermissionChecker`），三层收口——scope（授权面）→ 权限码（功能面）→ 数据范围（行级）；防重放 / 限流 / 签名复用 `BaseReplayGuard` / `BaseRateLimiter` / `SignatureCodec`。禁止自研令牌签发 / 撤销或另立 scope 判定。
- **对象存储**：文件 / 对象存取一律走 `BaseObjectStorage`（`storage/base.py`：异步 `put` / `get` / `delete` / `exists` / `presign`；桶取 `STORAGE_BUCKET`、预签名 TTL 取 `DEFAULT_PRESIGN_TTL`）；`get` 未命中抛 `NotFoundError`、`delete` 幂等；下载 / 预览走预签名 URL（后端不代理文件流）。禁止各模块自接 MinIO / 自搭文件系统或另起存储路径口径。
- **LLM 适配**：AI 能力一律走 `BaseLlmProvider`（`llm/base.py`：异步 `chat` / `embedding` / `ocr`，`provider_key` / `model` 可选，按 `sys_ai_provider` 选择端点与模型）；返回 `ChatResult` / `EmbeddingResult` / `OcrResult`。禁止各功能直连模型 API、另写 Provider 适配或自拼端点 / 密钥。
- **全文检索**：全文检索一律走 `BaseSearchIndex`（`search/base.py`：异步 `index(SearchDocument)` / `delete(index, doc_id)` / `search(SearchQuery)`，契约对象传参；索引名以 `SEARCH_INDEX_PREFIX` 开头、默认条数 `DEFAULT_SEARCH_SIZE`）；索引均含 `tenant_id`、查询强制租户隔离并叠加数据权限过滤（由实现从上下文注入，调用方不可绕过）；检索只返回 id + 分数 + 高亮，详情回查数据库。禁止各模块自连 ES、自拼索引名或绕过租户 / 权限过滤。
- **通知发送**：站内信 / 邮件 / 短信发送一律走 `BaseNotifier`（`notify/base.py`：异步 `send(NotificationMessage)`，渠道取 `NotifyChannel` 枚举）；模板渲染、渠道偏好过滤与发送记录归上层。禁止各模块自接 SMTP / 短信 SDK 或另写发送入口。
- **实时推送**：向客户端实时推送一律走 `BaseRealtimePublisher`（`ws/base.py`：异步 `emit(RealtimeEvent)` / `join(session_id, room)` / `leave(session_id, room)`，事件名取 `REALTIME_EVENTS`）；目标（用户 / 会话 / 房间）随事件指定。禁止各模块直接操作 Socket.IO、自拼房间名或绕过基座推送。
- **出站集成**：外部 HTTP 调用一律走 `BaseHttpClient`（`outbound/http.py`：异步 `request`；超时 / 重试 / 熔断由实现内部处理），Webhook 投递一律走 `BaseWebhookSender`（`outbound/webhook.py`：异步 `send`；签名经 `core/security.py` 的 `SignatureCodec`，出站口径 `sha256(secret, body)`）。禁止各模块自建 httpx 调用或自写 HMAC 签名。
- **工作流引擎**：流程定义 / 实例 / 任务一律走 `BaseWorkflowEngine`（`workflow/base.py`：异步 `deploy(ProcessDefinition)` / `start(definition_key, *, business_type, business_id)` / `complete_task(task_id, *, action, variables)`，动作取 `WorkflowAction`）。禁止业务模块直连 SpiffWorkflow 或自建流程实例状态。
- **身份源与会话存储**：外部身份源接入一律走 `BaseIdentityProvider`（`idp/base.py`：异步 `authorize` / `exchange_token` / `userinfo`，协议取 `IDP_PROTOCOLS`），会话存取一律走 `BaseSessionStore`（`session/base.py`：异步 `save` / `load` / `delete`，TTL 取 `DEFAULT_SESSION_TTL`）；对接外部 IdP 的 HTTP 调用取 `BaseHttpClient`。禁止各模块直连外部 IdP 或自建会话存储。
- **数据查询提供者**：即席数据集 / 字典高级查询一律实现 `BaseQueryProvider`（`query/base.py`：抽象 `key` + 异步 `query`）并注册到 `BaseQueryProviderRegistry`（`query` 聚合模板，未命中抛 `NotFoundError`）；只读数据源约束（数据集白名单 / 只读从库 / 租户隔离）由实现保证，禁止经此写库。禁止各模块自建查询扩展点。
- **导入导出**：Excel 导入一律走 `BaseImporter`（`transfer/importer.py`：异步 `parse` / `validate`，列定义取 `ColumnSpec`），导出一律走 `BaseExporter`（`transfer/exporter.py`：`export` 流式返回字节流）；模板 / 结果文件存取取 `BaseObjectStorage`、导出脱敏取 `BaseMasker`。禁止各模块自写 openpyxl 读写或另起错误回执口径。
- **审计哈希链**：审计记录哈希计算一律走 `BaseHashChain.compute`（`audit/hashchain.py`：`SHA256(prev_hash + 规范化记录)`，链头取 `GENESIS_HASH`、算法取 `HASH_ALGORITHM`），链校验一律走 `BaseHashChain.verify`。禁止各审计域自算哈希或另起校验口径。
- **归档策略**：归档条件判定一律走 `BaseArchivePolicy.matches`、归档搬迁一律走 `BaseArchivePolicy.archive`（`archive/base.py`），归档数据查询位置路由一律走 `BaseArchiveQueryRouter.resolve`（位置取 `ARCHIVE_LOCATIONS`）；归档前链校验取 `BaseHashChain`、冷化 / 归档文件取 `BaseObjectStorage`。禁止各模块自定义归档条件或另起查询路由。
- **表单字段类型**：自建字段类型一律实现 `BaseFieldType`（`fieldtype/base.py`：抽象 `key` + 同步 `validate` / `render_metadata` / `column_type`）并注册到 `BaseFieldTypeRegistry`（`validate` / `column_type` 聚合模板，未命中抛 `NotFoundError`）；方言取 `COLUMN_TYPE_DIALECTS`。禁止各模块自写字段校验或自拼列类型。
- **国际化翻译**：后端取词一律走 `BaseTranslator`（`i18n/base.py`：异步 `translate` / `load_messages` + 同步 `resolve_locale`，key 命名 `模块.页面.字段`，locale 取 `SUPPORTED_LOCALES` / 回退 `DEFAULT_LOCALE`）；错误码文案按 `error.{code}` 映射。禁止各模块自读语言包或硬编码文案。
- **工作台卡片**：工作台卡片一律实现 `BaseDashboardCardProvider`（`dashboard/base.py`：抽象 `key` + 同步 `metadata` / 异步 `fetch`）并注册到 `BaseDashboardCardRegistry`（`metadata` / `fetch` 聚合模板，未命中抛 `NotFoundError`）；卡片类型取 `CARD_TYPES`；卡片数据接口一律转发来源模块接口、不绕行其权限校验。禁止各模块自建卡片清单。
- **依赖方向**：只准上层依赖下层，**禁止反向依赖**（`core/` 不得依赖 `api/` / `services/` / 业务模块；`repositories/` 不得依赖 `services/`）；跨模块协作走 services。
- **模块独立性（数据所有权，为可拆分性保留）**：模块只拥有自己的数据——写侧禁止跨模块直写他模块的表、共享 ORM 关系或跨模块 JOIN；读侧经服务层接口或**只读投影**（只读视图 / 数据查询提供者 / 事件投影）；边界声明（表前缀 / 业务码 / 错误码段 / 事件域）随模块注册并受 CI 校验。写侧硬禁、读侧出口、归属与例外登记以《[后端开发规范](../../规范/后端开发规范.md)》「模块边界与数据所有权」节为准；事件契约版本与 Outbox 不随本节落地，作为《[架构设计 · 事件总线](16_架构设计_子系统_事件总线.md)》阶段的设计输入。单体形态下保留未来拆分为独立服务的选项（是否拆分见知识档案《[微服务项目评估（BMS）](../../资料/知识档案/微服务/10_微服务_项目评估.md)》「重评触发条件」节）。
- **命名**：基类 `BaseXxx`、集合 `Sorted*` / `ConcurrentSorted*`、模块类 `XxxRepository` 等统一遵循《[命名规范](../../规范/命名规范.md)》「后端命名」节。
- **多重继承克制**：仅 `BaseSchema` 因混合 Pydantic 使用多重继承；其余横切能力以基类方法或组合实现。

## 9. 阶段落地（地基波 + 回补） <a id="phases"></a>

后端基座分两波：**骨架 + 接口占位**随阶段一交付；**地基波（真实实现）**在**阶段二 后端基座**交付；**跨阶段基座**（依赖后端模块能力）阶段一已落契约骨架与登记，随对应阶段回补（回补窗口见《项目骨架计划》§3.1）。

| 波次 | 覆盖 | 阶段 |
| --- | --- | --- |
| 骨架 + 接口占位（已交付） | `BaseObject`、有序集合、进程内并发集合、Redis 有序封装与复合操作、`BaseRepository` / `BaseService` / `BaseSchema`（同步基线）、`BaseModel` 基类、异常体系 `BizError` + 统一响应、配置 / 安全 / 日志结构、机制底座接口占位（数据访问 / 多租户拓扑 / 模块注册） | 一 项目骨架 |
| 地基波（真实实现） | 数据访问底座（引擎 / 会话 / 四库方言 / 读写分离 / `DbUnitOfWork` / `BaseRepository` 异步与 DB 实现）、Alembic 迁移与租户库初始化、多租户拓扑落库实测、模块注册与 `BaseModel` 落库、排序 DB 侧、三库真库实测与阶段验收 | 二 后端基座 |
| 跨阶段回补 | 缓存 Region 分域基座（→ 阶段八 通用能力）、数据范围注入基座（→ 阶段七 RBAC）、分片路由基座（→ 阶段十三 分布式与监控）、事件发布 / 消费基座（→ 阶段十 系统集成与消息）、Celery 任务基座（→ 阶段八）、ORM 审计捕获基座（→ 阶段八） | 各对应阶段 |

**跨阶段基座契约**（缓存 Region / 数据范围 / 分片路由 / 事件 / 任务 / 审计捕获，以及横切扩展的脱敏 / 权限校验 / 分布式锁 / 验证码 / 密码策略 / 降级 / 熔断 / 限流 / 幂等 / 防重放 / 指标 / 链路 / 健康检查 / 开放接口 / 对象存储 / LLM / 全文检索 / 通知 / 实时推送 / 出站集成 / 工作流 / IdP 与会话 / 查询 / 导入导出 / 哈希链 / 归档 / 字段类型 / 国际化 / 工作台卡片）见《[后端基类清单](../../后端基类清单.md)》「跨阶段基座」节（含契约与状态；骨架阶段一已交付，真实实现随对应阶段回补）。

> **数据访问底座已在阶段一 02-5-1 落地**：`EngineFactory`（`db/engine.py`）/ `get_db`（`db/session.py`）/ 异步 `UnitOfWork` + `DbUnitOfWork` / `db/routing.py`；`BaseRepository` / `BaseService` 及派生类 CRUD 统一切异步，分页（`list_page` / `list_cursor` / `page` / `cursor_page`）、只读上下文标记、`StaleDataError → ConcurrentConflictError` 转译就位（架构 §4 登记）。真实四库连通、软删除 SQL、读写分离真实路由与达梦同步驱动封装随落库阶段回补，见[13-数据访问与分片](13_架构设计_子系统_数据访问与分片.md)。
