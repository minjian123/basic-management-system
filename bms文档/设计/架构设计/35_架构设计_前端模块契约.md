## 1. 目的与适用范围 <a id="purpose"></a>

定义**产品前端模块**与**宿主薄壳**之间的契约边界：宿主注入什么、模块声明什么、双方各自不得做什么。阶段四交付薄壳与契约（本地演示模块验证），阶段五接入 Module Federation 运行时加载——**契约不因加载形态改变**。

范围：模块上下文注入、注册声明字段与校验、注册表基座与解析规则、样式与运行时约束。不在范围：隔离增强（Shadow DOM / JS 沙箱）、依赖版本协商、模块清单 / 灰度 / 回滚、按模块观测（见「模块治理要求」表，随后续阶段落地）。

## 2. 角色与边界 <a id="roles"></a>

| 角色 | 职责 | 不得 |
| --- | --- | --- |
| 宿主薄壳 | 布局壳与顶层路由、模块加载与挂载 / 卸载、上下文注入、注册表实例与解析、加载失败兜底 | 含业务页面逻辑；替模块裁决业务兜底 |
| 产品模块 | 声明路由 / 组件 / 字段渲染器 / 图标 / 工作台卡片；在 `setup` 内使用注入上下文 | 直接写注册表；持有 / 持久化凭据；改全局原型 / 全局事件 / 全局样式 |

## 3. 宿主注入上下文 <a id="context"></a>

| 注入项 | 类型 | 说明 |
| --- | --- | --- |
| `router` | 路由实例 | 模块只读使用；不得替换或改写宿主路由表 |
| `store` | Pinia 实例 | 模块不得注册与宿主冲突的全局 store |
| `i18n` | 国际化实例 | 文案键遵循《命名规范》 |
| `user` | 当前用户 | **只读** |
| `tenant` | 当前租户 | **只读** |
| ~~`token`~~ | — | **不注入**；模块不得读取 / 持久化凭据 |

- 契约类型：`ModuleHostContext`（`@bms/core`）；模块侧经模块上下文能力基类 `BaseModuleContext` 消费（冻结为只读快照）。
- 上下文缺失项以 `undefined` 呈现，模块须自行降级，不得假定存在。

## 4. 模块声明与注册 <a id="registration"></a>

```ts
defineModule({
  manifest: { name, version, entry? },
  setup: (context) => ({ routes?, components?, icons?, cards? }),
})
```

| 注册项 | 键规则 | 校验 |
| --- | --- | --- |
| `routes` | 键 = 路由名（缺省路径） | `path` 须以 `/` 开头；与既有路由名冲突则**跳过**（不覆盖宿主路由） |
| `components` | `<模块名>:<键>`（kebab） | 命名空间前缀校验 + 同键唯一性拒重 |
| `icons` | `<模块名>:<键>` | 同上 |
| `cards` | `<模块名>:<键>` | 同上 |

- **注册执行方**：模块只声明；宿主装配时逐项倒入注册表（`RouteMenuRegistry` / `ComponentRegistry` / `FieldRendererRegistry` / `IconRegistry` / `WorkbenchCardRegistry`），均基于统一提供者注册表基座 `BaseProviderRegistry`（同键拒重、保序、只读快照）。
- **不注册不可用**：解析 `registries.*.get(key)` 未命中返回 `undefined`，由使用方降级；宿主不替调用方兜底。
- 卸载：宿主按登记键逆序注销（`unregister`），模块级路由按路由名移除。

## 5. 一致性基础 <a id="consistency"></a>

- **组件契约复用**：模块可直接消费 `@bms/ui-ep` 组件与 `@bms/core` 契约类型。
- **设计令牌复用**：模块样式只使用 `--bms-*` 令牌变量，不写死色值 / 间距（令牌由宿主注入，随主题 / 租户品牌化统一变化）。
- **样式作用域（强制）**：模块与组件 `<style>` 一律 `scoped`；禁 `:global`、禁全局样式导入；禁改全局原型（`Object.prototype` 等）、禁挂全局事件与全局样式；机器护栏拦截。
- **失败兜底**：模块加载 / 渲染失败由宿主模块边界渲染错误页（带模块名与版本），支持重试。

## 6. 与阶段五的衔接 <a id="stage5"></a>

| 项 | 阶段四（本节点） | 阶段五 |
| --- | --- | --- |
| 加载形态 | 本地模块（静态 `import`） | Module Federation 远端模块（`entry`） |
| 接口 | `ModuleLoader`（`load` / `mount` / `unmount`） | 同接口换实现 |
| 清单治理 | `name` / `version` / `entry` 字段预留 | 模块清单、版本发现、灰度 / 回滚 |
| 共享依赖 | 不引入 MF 依赖 | `shared` singleton 与版本偏斜检查 |

## 7. 检查清单 <a id="checklist"></a>

- □ 注入清单与只读约束（`token` 不注入）
- □ 注册键命名空间与路由路径校验
- □ 五个注册表基于统一基座，解析未命中返回 `undefined`
- □ 样式 scoped / 无 `:global` / 不改全局原型（护栏通过）
- □ 加载失败兜底与错误带模块名 / 版本
- □ 契约不依赖加载形态（阶段五同接口）
