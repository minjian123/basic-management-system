## 3. 进程模型 <a id="process"></a>

微服务形态：**一服务一容器一库**，各服务独立构建、独立发布；逻辑多服务 + 物理单机多容器（Docker Compose），按可平滑迁多机 / k3s 设计。

| 进程 / 服务 | 职责 | 部署形态 |
| --- | --- | --- |
| API 网关（APISIX） | 边缘统一入口：TLS 终止、认证校验、路由、限流、灰度、边缘观测；隐藏内部拓扑 | 1+ 容器（standalone → K8s Ingress/Gateway API） |
| 平台地基服务（认证身份 / 租户配置 / 权限 / 服务目录 / 审计） | 全局横切能力：OIDC 与双类 JWT、租户开通与路由、RBAC、服务清单与契约登记、审计哈希链 | 每服务独立容器 + 独立库（× 每租户） |
| 平台能力服务（组织主数据 / 工作流 / 表单 / 报表 / 文件 / 通知 / 检索 / AI 等） | 平台业务能力，按限界上下文切分 | 每服务独立容器 + 独立库（× 每租户） |
| 产品服务（biz / cw） | 产品业务域，独立仓库、独立发布；经认证 + 开放接口 + 事件与平台集成 | 每服务独立容器 + 独立库（× 每租户） |
| 各服务 worker（Celery） | 该服务的异步 / 定时任务（如孤儿分片清理、日志归档、备份），broker 用 Redis；beat 单副本 + Redis 分布式锁防重复调度 | 随所属服务 |
| frontend/apps/desktop / frontend/apps/mobile | 构建产物由 nginx 托管（PC + 移动端静态资源） | 静态资源 |

## 4. 组件视图与协作 <a id="components"></a>

```mermaid
flowchart TD
    GW["API 网关<br/>认证 / 路由 / 限流"] --> AUTH["认证身份服务"]
    GW --> PERM["权限服务"]
    GW --> BIZ["能力服务 / 产品服务"]
    AUTH --> CAT["服务目录与契约登记"]
    PERM --> CAT
    BIZ --> CAT
    BIZ -->|"同步 REST（契约）"| AUTH
    BIZ -->|"异步事件"| MQ["RocketMQ 事件总线"]
    BIZ -->|"事务性 Outbox"| MQ
    AUTH --> INF["共享基础设施<br/>独立库 · Redis · MinIO · ES"]
    BIZ --> INF
    AUTH --> OBS["OpenTelemetry<br/>Trace / Metrics / Log"]
    BIZ --> OBS
```

**协作规则**：

- **服务分层职责（服务内）**：api 层只做参数校验与路由分发；services 承载业务逻辑与事务边界；repositories 承载数据访问与数据源/分片路由，禁止在 api 层直接操作模型
- **服务边界（服务化地基 S1 / S2）**：每服务只拥有自己的库，写侧禁止跨服务直写、共享 ORM 关系与跨库 JOIN，读侧经契约 / 事件或只读投影；服务注册要素（表前缀 / 业务码 / 错误码段 / 事件域 / 契约版本）由服务目录与 CI 校验，详见《[微服务演进规划](../../规划/微服务演进规划.md)》「服务化地基要求与门禁」节
- **同步通信**：服务间同步走 REST（OpenAPI 契约），每个下游调用设显式超时 / 重试 / 熔断降级；契约「只加不删」、破坏性变更升版本（见 [09-接口与集成](09_架构设计_接口与集成.md)、[37-服务间通信与分布式一致性](37_架构设计_子系统_服务间通信与一致性.md)）
- **异步与一致性**：跨服务副作用优先走事件；「业务写 + 事件发布」以事务性 Outbox 保证原子，消费端幂等去重；跨服务事务用 Saga / 补偿（见 [16-事件总线](16_架构设计_子系统_事件总线.md)、[37](37_架构设计_子系统_服务间通信与一致性.md)）
- 认证由网关统一，身份与权限下沉到地基服务；关键写操作经 ORM 事件自动触发审计捕获，审计事件经事件总线分区有序消费（见审计哈希链子系统）
- 业务服务不直接调用通知/审计：通过事件总线发布事件，由对应消费方落库/推送（服务解耦）

## 5. 工程结构（Monorepo） <a id="structure"></a>

仓库为**单体多工程（monorepo）**：多个后端服务工程、双端前端、部署编排、开发期工具链、产品运维脚本与文档体系各成目录；服务共享基座库与工具链，CI 按服务粒度构建。

```mermaid
flowchart TD
    ROOT["bms（monorepo）"] --> BE["backend/<br/>多服务工程（地基 / 能力 / 网关配置）+ 共享基座库 + 迁移 + 测试"]
    ROOT --> FE["frontend/apps<br/>PC 管理端 · 移动端 H5（各自独立工程）"]
    ROOT --> DEP["deploy<br/>多服务编排与网关（含研发基础设施编排）"]
    ROOT --> TOOL["scripts · ops<br/>开发期工具链 · 产品运维脚本"]
    ROOT --> DOC["bms文档<br/>规划 / 规范 / 设计 / 资料"]
    ROOT --> CI["CI 流水线定义（自托管 GitLab）"]
```

- **后端多服务**：每个服务按 api / services / repositories / models / schemas 分层；同步走 REST、异步走事件；共享基座库承载 core 横切与模块基类；服务边界与注册要素见服务目录。分层职责与依赖方向见[04-后端基础类体系](04_架构设计_后端基础类体系.md)。
- **后端工作区**：`backend/` 为 uv 工作区——`libs/bms_core/`（共享基座库）+ `services/<服务>/`（各服务独立工程、独立构建）；服务只依赖共享库与自身，**共享库不依赖服务、服务之间不得互相 import**；具体落点与目录见《[后端开发规范](../../规范/后端开发规范.md)》「目录与分层职责」节。2026-09-22（02_03 单体重构）后现有单服务按限界上下文拆为 9 个服务工程：**platform**（平台地基 / 配置）、**identity**（认证与身份）、**tenant**（租户与配置）、**org**（组织主数据）、**file**（文件）、**notification**（通知）、**search**（检索）、**ai**（AI）、**report**（报表打印）；能力域实现仍由共享基座库承载，各服务按需装配。
- **前端双工程**：PC 管理端与移动端 H5 各自独立（依赖清单、构建与配置互不共享），工程内按 接口封装 / 路由（动态生成）/ 状态 / 页面（按模块）/ 布局 / 通用组件 / 国际化 / 工具 分层；详见[08-前端架构](08_架构设计_前端架构.md)。
- **目录与文件登记**：具体路径、目录树与文件清单以《[后端基类清单](../../后端基类清单.md)》（后端基座落点）、《[前端基类清单](../../前端基类清单.md)》（前端分层落点）与《[后端开发规范](../../规范/后端开发规范.md)》《[前端开发规范](../../规范/前端开发规范.md)》「目录约定」为准——本节点只给工程骨架，不复制登记表。
