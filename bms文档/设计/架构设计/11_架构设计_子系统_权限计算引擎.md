# 架构设计 · 子系统 · 权限计算引擎

> BMS · RBAC 主体链、权限分层与数据范围

[架构设计](01_架构设计_总览.md) › 11-权限计算引擎　|　[← 10-认证与会话](10_架构设计_子系统_认证与会话.md) · [12-事件总线 →](12_架构设计_子系统_事件总线.md)

## 1. 概述 <a id="overview"></a>

权限计算引擎实现 RBAC + 主体链 + 权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）
+ 动作级数据权限。对应[《项目规划说明》](../../规划/项目规划说明.md)的「权限模型」「业务与动作清单（权限码总表）」章节，
是全部业务模块的权限基座。

## 2. 权限模型 <a id="model"></a>

- **主体链**：用户与角色间可插入任意中间实体（岗位、部门等），链条任意长度（用户→岗位→角色、用户→部门→角色、用户→岗位→部门→角色…）；权限计算统一收敛为 用户 → 角色；多链取并集合并去重；通用绑定表 sys_role_assign（subject_type + subject_id + role_id），新增实体类型仅扩展枚举
- **权限分层**：菜单权限（入口，用户视角只接触菜单与表单，授予即隐含对应表单）→ 表单权限（1:1 挂菜单，授予即隐含对应业务）→ 业务权限（1:1 挂表单，抽象解耦层：界面不可见、不直接授予，由已授予的菜单/表单权限按"表单→业务"对照关系推导）；按钮权限（挂表单，1:1 挂动作，默认全无）→ 动作权限；字段权限（挂表单）
- **权限码**：命名 `业务:动作`（如 user:create）；业务存 sys_business、动作存 sys_action（均平台库，租户可见可分配不可增删）
- **双重控制**：前端按权限码控制菜单/按钮/字段显隐，后端接口 require_permission 强制校验

## 3. 权限计算与缓存 <a id="compute"></a>

- 主体链收敛：从用户出发沿 sys_role_assign 迭代收集全部绑定角色（用户直接 + 岗位 + 部门 + 多链），取并集去重
- 权限聚合：角色集合 → sys_role_permission → 业务码集合 + 动作码集合；结果缓存 Redis（`bms:{tenant}:perm:{user_id}:{version}`）
- 版本失效：角色/授权/主体绑定变更 → 权限版本号 +1（Redis 计数器），缓存读取时校验版本；同时清理对应用户缓存——保证变更即时生效

## 4. 两级校验点 <a id="check"></a>

| 级别 | 校验内容 | 实现 |
| --- | --- | --- |
| 业务级 | 表单入口、数据表访问（业务权限经已授予的菜单/表单权限按对照关系推导） | 依赖注入 require_permission(业务码)，路由注册时声明 |
| 动作级 | 按钮对应接口（create/update/delete/approve 等） | 依赖注入 require_permission("业务:动作") |

## 5. 字段权限 <a id="field"></a>

- 字段实体 sys_field 挂表单（form_id + field_key）；授予存 sys_role_field（role_id + form_id + field_id + visible + editable），默认全部可见可编辑，授予后收窄
- 读时过滤：不可见字段序列化层过滤（不返回不渲染）；写时校验：不可编辑字段保存时拒绝
- 与数据脱敏（data:plain）互补：脱敏是掩码展示，字段权限是可见性控制

## 6. 数据范围 <a id="scope"></a>

- 默认无任何数据权限；权限管理人员在动作上配置（sys_data_scope：action_id → config 规则表达式）
- 匹配规则为可配置规则表达式（字段 + 运算符 + 预置变量），解析为 SQL 条件注入查询（读时），写入保存时校验（写时），双向检查；规则形态见权限设计文档
- 租户边界：规则解析结果强制叠加租户过滤，任何规则不得跨租户

## 8. 三权分立 <a id="sep"></a>

- 平台超管（sys_admin）：跨租户运营（租户开通/停用/域名/配额），不进入租户业务数据
- 租户侧三类内置角色权限互斥、同一用户不得兼任：系统管理员（用户/岗位/部门等系统配置）、安全管理员（角色/业务/动作/数据范围/密码策略/IdP 配置）、审计管理员（只读全部日志与审计数据）
- 租户开通首建系统管理员账号，由其创建另两类管理员
