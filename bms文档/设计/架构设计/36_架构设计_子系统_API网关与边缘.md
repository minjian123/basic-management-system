## 1. 概述 <a id="overview"></a>

API 网关与边缘子系统承载微服务形态下的**边缘统一入口**：外部流量经网关进入，网关负责路由、认证校验、
限流、灰度与边缘观测，隐藏内部服务拓扑。对应《[微服务演进规划](../../规划/微服务演进规划.md)》「服务化地基要求与门禁」S4 与
「技术选型」；选型见知识档案《[微服务 · 12 选型对比（BMS）](../../资料/知识档案/微服务/12_微服务_选型对比.md)》。

## 2. 定位与职责 <a id="position"></a>

| 项 | 说明 |
| --- | --- |
| 定位 | 平台级基础能力（**机制**，非用户可见业务模块）；系统唯一外部入口 |
| 职责 | 边缘路由、认证校验、限流、灰度与版本路由、请求净化、边缘观测、静态资源托管分流 |
| 边界 | 只管**进程外边缘**：不承载业务逻辑、不直连数据库、不做服务间调用代理（东西向由内部服务经契约直连） |
| 技术选型 | Apache APISIX（Apache-2.0，OIDC/JWT、Redis 分布式限流、RocketMQ/ES 日志出口一次给全；standalone → K8s 同配置模型） |

## 3. 边缘功能 <a id="functions"></a>

| 功能 | 语义 |
| --- | --- |
| 路由 | 按路径 / 主机将外部请求路由到目标服务；路由依据服务目录（见 [11-模块注册](11_架构设计_子系统_模块注册.md)） |
| 认证 | 校验用户 JWT（BMS 自签，经认证服务 JWKS 校验签名 / 过期 / issuer / **audience**），拒绝未认证请求；认证细节归 [14-认证与会话](14_架构设计_子系统_认证与会话.md) |
| 请求净化 | **剥掉**客户端伪造的身份头（X-User-Id / X-Service-Identity 等），注入网关验证过的身份信息后透传给后端 |
| 限流 | 按用户 / 客户端 / 租户 / IP 限流（令牌桶），基于共享 Redis 实现多副本一致计数 |
| 灰度与版本 | 按版本 / 权重做金丝雀与灰度路由（路由规则声明式、入 Git） |
| 边缘观测 | 访问日志与指标（经现有 RocketMQ / ES / 可观测栈出口），见 [27-可观测性](27_架构设计_子系统_可观测性.md) |
| 静态资源 | 前端静态资源由 nginx 托管，与 API 流量分流（网关只处理 API） |

## 4. 部署形态与演进 <a id="deploy"></a>

- **单机阶段**：以 standalone 声明式模式运行（配置入 Git），无需独立配置中心组件；路由 / 认证 / 限流规则随流水线热加载
- **迁 K8s 阶段**：切 Ingress Controller / Gateway API，**配置语义基本平移**（不换选型）；域名与 TLS 由边缘统一管理
- **演进触发**：单机多容器资源触顶或编排复杂度上升时随平台整体迁 k3s（见《[微服务演进规划](../../规划/微服务演进规划.md)》演进路线 E1 / E2）

## 5. 与内部服务的关系 <a id="internal"></a>

- 网关按**服务目录**路由：服务注册要素与服务清单是路由的权威依据（见 [11-模块注册](11_架构设计_子系统_模块注册.md)）
- 服务间**东西向**调用不经网关，直接经契约互调（见 [37-服务间通信与分布式一致性](37_架构设计_子系统_服务间通信与一致性.md)）；网关只承接**南北向**外部流量
- 前端按**服务段寻址**经网关接入：外部路径 `/api/{service_key}/v1/...`（网关重写为服务内 `/api/v1`），前端请求层集中维护「域 → 服务前缀」映射；**BFF 不引入**（见 [08-前端架构](08_架构设计_前端架构.md)、[09-接口与集成](09_架构设计_接口与集成.md)）

## 6. 安全边界 <a id="security"></a>

- **网关旁路风险**：内部服务若直接可达，攻击者可绕过网关；对策是内部服务只接受带服务身份的流量（服务 JWT，K8s 阶段加 mTLS），非同网段裸暴露
- 网关认证后，后端只做授权（scope / 权限码），不重复认证；外部 access token 不透传给内部服务
- 身份头由网关注入、后端只信任来自网关或带服务身份的请求（零信任，见 [31-性能与安全](31_架构设计_性能与安全.md)）
