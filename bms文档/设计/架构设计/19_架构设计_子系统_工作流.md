## 1. 概述 <a id="overview"></a>

工作流子系统基于 SpiffWorkflow（Python 生态最成熟 BPMN 2.0 引擎）+ bpmn-js（前端拖拽建模）：
流程定义与版本管理、流程实例执行、待办/已办、审批记录、会签/或签、条件分支可视化。
对应[《项目规划说明》](../../规划/项目规划说明.md)的「工作流引擎」「工作流管理」章节；业务单据流程（采购/收付款审批）由产品仓库（biz）设计接入。

## 2. 流程定义与版本 <a id="define"></a>

- wf_process：definition_key、name、bpmn_xml、version、status；definition_key 标识同一流程，definition_key+version 唯一，支持版本管理
- 管理端 bpmn-js 拖拽建模（用户任务、网关、结束事件、条件分支可视化），保存 BPMN XML；发布新版本落 wf.process.deployed 事件
- 权限码 wf:define（流程定义与版本管理）、wf:approve（审批）、wf:query（查询）
- 业务流程模板种子由产品仓库提供并登记（biz：采购申请三级审批、付款申请审批等流程模板），平台引擎本身不预置业务流程

## 3. 流程执行 <a id="execute"></a>

- SpiffWorkflow 同步引擎：在 FastAPI 异步栈中以线程池运行（run_in_executor），避免阻塞事件循环
- 引擎本身不持久化：流程实例（wf_instance：process_id、business_type、business_id、current_node、status）、任务（wf_task）、审批记录（wf_record）由 BMS 自建表维护
- 执行模型：节点推进 → 生成待办（wf_task）→ 审批动作驱动继续推进；驳回退回指定节点
- Python 3.14 兼容风险：引擎未适配则整体回退 3.13（已定口径）

## 4. 审批机制 <a id="approve"></a>

- 待办：wf_task（instance_id、node_id、assignee、status、deadline）；会签（多人审批）/ 或签（任一通过）
- 审批动作：同意/驳回/撤回，落 wf_record（action、comment）；写接口幂等键防重复提交
- 我的待办/已办查询（PC + 移动端）；待办角标经实时推送子系统
- 流程版本：新单走最新版本；在途实例继续按原版本执行

## 5. 与业务单据的联动 <a id="business"></a>

- 业务绑定：wf_instance.business_type + business_id 关联业务单据（具体单据由产品仓库定义，如 biz 的 pur_purchase_apply、pay_payment）
- 业务链路样例（biz）：申请提交 → 流程启动 → 审批全部通过 → 生成下游单据（如采购订单 pur_purchase_order）→ 落产品事件（pur.order.created）
- 收付款链路样例（biz）：付款申请提交 → 审批全部通过 → 落 pay.approved 事件 → 执行付款并落收付款流水（pay_payment_flow，pay.executed）；收款/退款审批链路同源复用
- 驳回：业务单据状态回退，申请人可修改后重新提交（重新触发流程）

## 6. 与其他子系统的协调 <a id="coordination"></a>

- **[事件总线](14_架构设计_子系统_事件总线.md)**：wf.process.deployed / wf.instance.started / wf.task.completed / wf.instance.rejected / wf.instance.finished（Webhook 可订阅）
- **[通知公告](20_架构设计_子系统_通知公告.md)与[实时推送](16_架构设计_子系统_实时推送.md)**：待办生成 → 站内信 + Socket.IO（approval.todo）
- **[权限计算引擎](13_架构设计_子系统_权限计算引擎.md)**：审批人由流程定义 + 主体链解析（部门经理 = 部门负责人角色等）
