## 1. 概述 <a id="overview"></a>

认证与会话子系统负责身份认证、会话生命周期与账号治理：双 token（access + refresh）、
SSO（OIDC/CAS/企业微信/钉钉）、图形验证码、密码策略、账号锁定、数据脱敏与开放接口鉴权。
对应[《项目规划说明》](../../规划/项目规划说明.md)的「认证与安全」「身份认证（SSO）」章节，覆盖认证、会话管理、SSO、个人中心模块。

> **微服务形态（2026-09-22）**：认证由**网关统一**校验（见 [36-API 网关与边缘](36_架构设计_子系统_API网关与边缘.md)），本子系统作为**地基认证服务**提供用户认证与令牌；另新增**服务间身份**（双类 JWT），见第 7 节。

## 2. 双 token 模型 <a id="token"></a>

| 项 | 设计 |
| --- | --- |
| access token | 30 分钟；载荷 sub、tenant_id、jti（会话 id）、type=access；仅存前端内存（刷新页面后静默续期） |
| refresh token | 14 天滚动轮换；httpOnly + Secure + SameSite cookie（防 XSS 窃取）；CSRF 双重提交校验（SameSite=Lax + 自定义请求头校验） |
| 签发 | BMS 自签（identity 服务持签名私钥签发用户 access / refresh，公钥经 `/.well-known/jwks.json` 分发）；密钥轮换新旧并行验证期 |
| 刷新轮换 | refresh 使用一次即轮换（**会话 id 稳定**）：签发新 access + refresh、更新 `sys_session.refresh_token_hash`，旧 refresh 因哈希不符在下次使用被拒（转轮换代次见登出 / 强踢） |
| 登出 / 强踢 | refresh `jti` 入黑名单（`bms:global:token:blacklist:{jti}`，短 TTL）即时失效；会话记录置 revoked、删 Redis 会话标记 |

## 3. 会话管理 <a id="session"></a>

- 持久层 sys_session（refresh_token_hash、设备、IP、login_at、expires_at、revoked_at）+ 运行时 Redis 标记 `bms:{tenant}:sess:{session_id}`（TTL 与 refresh 有效期对齐）
- 每请求校验链：验签（access）→ 类型校验 → Redis 会话标记存在性（不存在=已踢出/登出）→ 设备/IP 一致性（可选强度）；每请求一次 Redis 读（毫秒级）。**01_05 落地**：`require_auth` 恒定强制登录态——网关路径消费可信边缘身份（`X-User-Subject` / `X-Tenant-Id` / `X-Session-Id`），本地路径本地校验 `aud=api` 用户令牌（取 access `jti`）；标记不存在 → `20012` / 401（踢出即时生效）；`[session].device_check` 默认关
- 强制踢出：删 Redis 会话标记 + 吊销 refresh + revoked_at 落库 + Socket.IO 广播 session.revoked 关闭该会话全部实时连接；HTTP 侧下一请求即拦截（即时生效）
- 多端会话：允许并发登录，活跃会话数上限（默认 5，配置可配；租户 `sys_config` 覆盖归后续），超限自动作废最旧会话
- 会话管理接口：`GET /api/v1/sessions`（在线列表）/ `GET /api/v1/sessions/{session_id}`（详情）/ `POST /api/v1/sessions/{session_id}/kick`（强制踢出）；鉴权 `require_auth` + 权限码 `session:query` / `session:kick`（RBAC 就绪前平台超管口径）
- 撤销一致性：登出 / 踢出 / 超限作废共用**统一撤销原语**（吊销 refresh 黑名单 + `revoked_at` 落库 + 删 Redis 标记 + 广播占位），三路径清理口径一致（01_04 落地）
- 会话管理页面：在线会话查看（session:kick 踢出）

## 4. SSO 集成 <a id="sso"></a>

- authlib：OIDC 为主 + CAS 兼容——作为客户端接入各租户外部 IdP（Keycloak/AD/Authing 等）；同时提供 OIDC Provider 能力（BMS 兼作 IdP，其他系统以 BMS 用户体系为统一认证源）
- 企业微信/钉钉免登复用同一外部身份框架；移动端内嵌 H5 走各自 OAuth 免登
- SSO 首次登录 JIT 自动建号（sys_user_identity 全局映射定位租户与用户；唯一约束防并发重复建号）；本地账号密码登录并存（超管应急通道，防 IdP 故障锁死）
- 登录页展示租户配置的 IdP 入口（sys_identity_provider）
- **SSO 登录链路落地口径（02_01）**：入口清单 / 授权跳转 / 回调三端点（路由参数为 IdP 标识 `idp_key`）；流程状态（state / nonce / PKCE `code_verifier`）经 `idp_state_store` 能力域短 TTL 一次性消费，回调租户以 state 记录为权威；回调成功 `302 {success_redirect}?tenant=…` + refresh cookie，失败可配 `302` 跳登录页（未配置回退 JSON）；错误码 `20051`~`20056`（404 / 400 / 503 / 403 / 409 / 429）；外部 IdP 故障不阻断本地登录（并存口径）
- **JIT 建号口径（02_02）**：JIT 开关按 IdP 行 `config.jit_enabled` 优先、缺配回落全局 `[sso].jit_enabled`（皆缺省关闭，需显式开启）；首登映射未命中经 **org 内部接口**建 `sys_user` 最小模型（口令哈希为**不可登录占位**，「是否 SSO 账号」以 `sys_user_identity` 绑定为事实源）；并发防护以**分布式锁能力域**按映射键串行化 + `sys_user_identity` 唯一约束兜底（冲突回读复用，不产生重复用户）；建号受**域名白名单**（行 `config.allowed_email_domains`）与**租户白名单**（`[sso].jit_allowed_tenants`）双层校验，空 = 不限制；用户名 `preferred_username → email 本地部分 → sub` 派生清洗、撞名加后缀 `_2.._5`；首登建号在平台库与映射写**同事务**落 `identity.user.jit_created`（Outbox，仅首登发）；`sso:bind` 绑定关系可查（只读端点，RBAC 前超管口径）
- **CAS 适配口径（02_03）**：CAS 无令牌交换——授权后 IdP 以服务票据 `ticket` 回跳，客户端凭票据调 `serviceValidate`（默认 CAS 3.0 `p3/serviceValidate`，含属性）一次取回主体与属性；身份仍经 `BaseIdentityProvider` 契约承载（`IdentityToken.identity` 直接回填），复用**同一 SSO 链路与 JIT / 映射**，不为 CAS 另建链路；登录跳转与校验使用**同一 `service`**（由链路按回调地址 + `state` 统一生成，防票据挪用于其他服务）；属性映射账号 / 姓名 / 邮箱（内置默认 + 行配置覆盖）；失败语义复用认证错误码段（票据无效 / 服务未注册 → 回调校验失败、IdP 不可达 / 响应非法 → IdP 不可用、未匹配 → 身份未匹配），企微 / 钉钉沿用同一契约扩展
- **企业微信 / 钉钉免登口径（02_04）**：企业微信（新版扫码登录 `wwlogin/sso/login`，`mode=oauth` 兼容内嵌 H5 网页授权）与钉钉（新版 OAuth2 `login.dingtalk.com/oauth2/auth`）各按 `BaseIdentityProvider` 契约适配，复用**同一 SSO 链路与 JIT / 映射**，不为两平台另建链路；扫码登录的二维码渲染 / 轮询由前端（域五）消费——后端经授权 URL 端点（返回授权 URL / `state` / 有效期）提供二维码内容，用户确认后回跳**同一 `callback`** 完成会话签发；身份主键企业微信取 `userid`（非成员回落 `openid`）、钉钉取 `unionId`（回落 `openId`）；凭据缺失 / 非法时入口不可用（配置类错误），授权失败与接口不可达各有专用错误码（`20057`~`20062`）；移动端内嵌 H5 免登与真实企业凭据联调归阶段十七

## 5. 密码与账号策略 <a id="password"></a>

- PBKDF2 哈希（标准库，不引入额外密码库）；登录失败限流（slowapi，Redis 后端，如 5 次锁 15 分钟）
- 图形验证码：Pillow 生成，Redis 存储（bms:global:captcha:{uuid}，TTL 5 分钟），连续失败 3 次后强制要求
- **验证码渠道（2026-09-20 登记，前端组件库 06_04；同日随需求 02-42 接口占位落地）**：图形码之外支持**滑块挑战**与**短信验证码**，三类共用同一挑战编号空间与「场景（登录 / 找回密码 / 绑定手机 / 解绑手机 / 注册）→ 是否强制、连续失败阈值、有效期、重发冷却」的策略口径，策略**由配置按租户下发**、缺省回落平台默认；验证码基座只负责**出题**与**一次性凭证校验**（图形 / 短信用校验码、滑块校验轨迹凭证），短信目标一律**脱敏后回显**、下发经通知渠道、限次与防滥用经限流基座——三者职责边界不重叠；失败计数与「连续失败 N 次强制」、渠道不可用降级归认证流程（契约边界与命名见《[后端基类清单](../../后端基类清单.md)》「跨阶段基座」节）
- 密码策略（sys_config 可配）：复杂度校验、90 天有效期强制改密（pwd_changed_at 驱动）、近 5 次历史密码不可重复（pwd_history）、180 天未登录自动锁定（定时任务扫描 last_login_at）
- 找回密码：邮箱与企业微信/钉钉双通道；token 存 Redis（TTL 15 分钟、单次有效）；叠加限流防滥用（每账号 1 次/5 分钟、每 IP 5 次/小时）；重置成功后强制失效该账号全部会话
- 账号锁定/解锁：sys_account_lock（lock_type: fail_limit/inactive/manual），锁定列表/手动解锁/解锁记录审计（user:unlock）
- 数据脱敏：敏感字段注册标记，序列化层默认掩码（138****5678）与导出脱敏；持 data:plain 权限码方可查看明文

## 6. 开放接口鉴权 <a id="open-auth"></a>

- OAuth2 Client Credentials：client_id/secret 换取 access token（自签 JWT 短 TTL），支持 scope（接口权限范围）、独立撤销
- 按 client 维度独立限流（slowapi）；IP 白名单（sys_client.ip_whitelist）
- 调用审计：sys_open_log 按月分片 + 哈希链（open:call 权限码）

## 7. 服务身份与服务间认证（微服务） <a id="service-identity"></a>

微服务形态下认证分两层：用户认证（网关 + 本子系统）与服务间认证。

| 层 | 机制 |
| --- | --- |
| 用户认证 | 用户经网关认证；access / refresh 双 token 校验由本子系统（地基认证服务）提供 |
| 服务间身份 | **双类 JWT**：用户 JWT（`aud=api`，BMS 认证服务自签）与服务 JWT（`aud=service`，短时 + scope + 服务标识，自签）；网关校验用户 JWT 并换发网关服务 JWT，下游只信任网关或校验内部 JWT |
| 服务身份演进 | K8s 阶段引入 Linkerd 自动 mTLS 提供传输层身份（与应用层 JWT 互补） |

- **关键约束**：内部服务 JWT 与用户 JWT 必须 `aud` 区分，防用户 token 直调内部服务；签名用 RS256/ES256、必须校验 exp/iss/aud；不要把外部 access token 透传给内部服务
- 服务间认证约定见 [37-服务间通信与分布式一致性](37_架构设计_子系统_服务间通信与一致性.md)，网关认证见 [36-API 网关与边缘](36_架构设计_子系统_API网关与边缘.md)
