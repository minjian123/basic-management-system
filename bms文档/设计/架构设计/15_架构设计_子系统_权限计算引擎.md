## 1. 概述 <a id="overview"></a>

权限计算引擎实现 RBAC + 主体链 + 权限分层（菜单→表单→业务、按钮→动作、字段可见可编辑）
+ 动作级数据权限。对应[《项目规划说明》](../../规划/项目规划说明.md)的「权限模型」「业务与动作清单（权限码总表）」章节，
是全部业务模块的权限基座。

## 2. 权限模型 <a id="model"></a>

- **主体链**：用户与角色间可插入任意中间实体（岗位、部门等），链条任意长度（用户→岗位→角色、用户→部门→角色）；权限计算统一收敛为 用户 → 角色；多链取并集合并去重。**角色分配拆分归属（2026-10-06）**：用户直接分配留 bms（`sys_user_role`，联合主键 `role_id` + `user_id`，与用户管理页「用户分配角色」同一张表）；岗位/部门分配数据与契约归 **mdm 组织域**（用户-岗位 `org_user_post`、角色-岗位 `org_role_post`、角色-部门 `org_role_dept`），权限引擎经 mdm「按用户解析角色」**只读契约跨服务汇总**。
- **双轨权限（2026-10-10 拍板）**：**界面维度**与**安全维度**正交——**入口可见性**由菜单 / 表单授权独立判定（勾选菜单**连带授予其表单查看权限**；**菜单 ↔ 表单多对多**，关联表 `sys_menu_form`），**接口 / 数据访问**一律走**权限码**。二者互不推导，故后续精细化 / 结构化升级只动安全维度，界面维度原样兼容。
- **三词分治（2026-10-10 拍板）**：**业务码**（`sys_business`，纯资源维度）· **动作码**（`sys_action`，全局动词维度）· **权限码**（`sys_permission`，`业务码 × 动作码` 组合，**唯一强制校验单位**）。业务码与动作码为独立字典（平台库，租户可见可分配不可增删），权限码为受控可授项（只能选已存在的组合）。
- **权限分层**：菜单权限（入口）→ 表单权限（「查看」= 表单权限，进入/列表可见）→ 权限码（`业务:动作`，挂表单的按钮、默认全无，带**来源标记**：本菜单入口连带生成的可改、非本入口来源只读）；字段权限（挂表单）
- **双重控制**：前端按权限码与入口授权控制菜单/按钮/字段显隐，后端接口 require_permission 强制校验

- **组织主数据读出口（2026-09-20 登记并交付，前端组件库 06_05；2026-10-03 随组织主数据迁 mdm，读出口由 mdm 组织域实现，2026-10-07 bms org 服务退役）**：用户 / 岗位 / 部门树作为主体链与数据范围的**数据来源**，统一经主数据查询出口提供（关键字 / 部门与包含子级 / 状态筛选、按标识批量回显、部门树一次性返回）；**查询与批量回显分列两个出口**，数据可见范围经数据范围注入过滤、敏感字段经脱敏，**过滤与脱敏在实现侧强制接入、调用方不可绕过**；业务与前端只经该出口取数，不直连组织模块的表；**前端落地（2026-09-21，任务 06_05）**：组织选择字段族经注入式 `OrgSourceAdapter`（内建实现 `BaseOrgSource` 经 `OrgSourceRegistry` 登记，默认键 `http`）消费上述出口（查询与批量回显分列，批量回显避免 N+1、部门树一次性返回），未注入即占位零请求；落点见《[前端基类清单](../../前端基类清单.md)》与[06_05 详细设计](../../项目/04_前端组件库/任务/06_字段类/06_字段类_05_组织选择字段/设计/01_详细设计_05_组织选择字段.md)，真实取数 / 数据范围 / 脱敏联调随 RBAC 阶段；**2026-10-08（11_02）**：基座侧两契约与空实现**已移除**（`bms_core/org` 零残留），前端 HTTP 内建数据源默认端点经**寻址契约**组装为 **mdm 产品命名空间**（`productPrefix('mdm','org')` = `/api/mdm/v1/org`，路径 `/data-source/{users,posts,dept-tree}` 与 `/resolve-names`）

## 3. 权限计算与缓存 <a id="compute"></a>

- 主体链收敛：**用户直接角色**读 bms `sys_user_role`；**岗位/部门角色**经 mdm「按用户解析角色」只读契约跨服务取回（mdm 依 `org_user_post` 与 `org_role_post` / `org_role_dept` 解析）；两路取并集去重，统一收敛为「用户 → 角色」。mdm 不可达时按降级处置（仅用户直接角色生效并上报）
- 权限聚合：角色集合 → sys_role_permission → **权限码集合** + **入口授权集合**（菜单 / 表单）
- **三层进程内缓存（2026-10-20，子任务 `04-2`）**：判定是每个接口的必经路径，故计算产物**全部在进程内单份**、不落 Redis 共享（序列化与网络延迟不可接受）——① **基础数据**（用户聚合输入 / 元数据索引）、② **规则物化结果**（数据范围规则求值条件，按规则内容指纹键控、跨用户共享）、③ **用户快照**（仅活动用户持有）；各层条目上限 + TTL + 规则层元素总量预算，活动时间由巡检任务按 30 分钟闲置注销。落点 `bms_core/permission/cache.py`
- 版本失效：角色/授权/角色分配（用户）变更 → 权限版本号 +1（Redis 计数器，唯一跨副本共享项）；**mdm 侧岗位/部门分配变更经事件通知 → 同样触发版本 +1**；**元数据（菜单 / 表单 / 按钮 / 字段 / 权限码）变更一并递增权限版本**（元数据是快照的解析输入，否则码集 / 入口集滞后）；各副本读取前查最新版本号换键，异步对齐 + 本进程条目清理——保证变更即时生效
- **执行前收敛（一致性屏障）**：需要「执行前已应用最新权限」的调用，经**一致性屏障**等待「已应用版本 ≥ 目标版本」——未收敛有界等待、超时报错（`10011` / 409），不静默读旧权限；跨服务收敛点落副作用后推进已应用版本（见《[服务间通信与分布式一致性](37_架构设计_子系统_服务间通信与一致性.md)》「跨服务一致性（强一致事务）」节与知识档案《分布式事务 · 一致性屏障》）

## 4. 入口级 / 权限码级校验点 <a id="check"></a>

| 级别 | 校验内容 | 实现 |
| --- | --- | --- |
| 入口级（界面维度） | 菜单 / 表单入口可见性：菜单授权命中，或其所关联表单的表单授权命中 | 入口授权集合（`granted_menu_ids` / `granted_form_ids`）判定，非权限码 |
| 权限码级（安全维度） | 接口 / 数据表访问与按钮对应操作 | 依赖注入 require_permission("业务:动作")，路由注册时声明 |

> **双轨说明**：受保护接口一律挂**权限码**（如 `user:create`、`role:grant`），不存在「裸业务码」接口；入口可见性由入口授权独立判定，与权限码互不推导。

## 5. 字段权限 <a id="field"></a>

- 字段实体 sys_field 挂表单（form_id + field_key）；授予存 sys_role_field（role_id + form_id + field_id + visible + editable），默认全部可见可编辑，授予后收窄
- 读时过滤：不可见字段序列化层过滤（不返回不渲染）；写时校验：不可编辑字段保存时拒绝
- 与数据脱敏（data:plain）互补：脱敏是掩码展示，字段权限是可见性控制

## 6. 数据权限 <a id="scope"></a>

- 默认无任何数据权限；权限管理人员**按基础数据字典**结构化配置（`sys_data_scope`：role_id × data_source_key × policy_type → config），**只选不编**——四类策略：**数据选择**（勾选字典数据）、**数据区域**（开始值 / 结束值）、**数据匹配**（字段 + 通配符值，默认代码字段；仅允许 `*` `?` 与中英文 / 数字 / 下划线，越界拒绝）、**扩展权限**（预设 / 二次开发注册的后端筛选器，每行一条 + 参数 JSON，由扩展功能自行解析）
- 四类结果**并集兜底**，用于读时过滤（数据访问层）与写时校验（写入口），双向检查
- 移除了自由规则表达式（原动作级 `action_id → config`），杜绝写出预设范围外的越权规则；扩展场景由扩展权限承担
- 租户边界：过滤结果强制叠加租户过滤，任何策略不得跨租户
- **集合物化与大集合 SQL 形态（2026-10-20，子任务 `04-3`）**：规则求值的 `in` 值去重物化为集合，**按规则维度共享一份**（层2 键不含用户，快照只持规则引用）；物化层按「规则引用计数 + 值元素总数 + 估算字节」治理——超条目上限或元素预算时**先淘汰零引用规则**，全部被引用才退化为 LRU（后续命中重算）。读过滤**不产出巨型 `IN` 值列表**：并集合并后任一 `in` 条件元素数超阈（缺省 1000，可配）即整体退化为永假并上报引导（改用区域 / 匹配 / 扩展策略）；区域 / 匹配本身以 `between` / `like` 原生算子表达、不枚举值。写校验与读共用同一批条件，任一条件永假即拒绝写入。实现落点 `bms_core/permission/cache.py`、`bms_core/scope/rbac.py`
- **四策略求值口径与条件形态（2026-10-20，子任务 `04-4`）**：`config` 按《数据库设计 · sys_data_scope》收口——`select`（`item_code`，取值语义为字典项 `value`，读入兼容前端历史 `itemCode`）→ 值集合 `in`、`region`（`start` / `end`）→ 区间 `between`，二者**不含字段名**、改产「**数据源维度条件**」（`ScopeCondition.data_source_key`）；`match` → `like`（保留白名单字段并附数据源标识）；`extension` → 按扩展键聚合一次调用、**直接返回条件集合**。消费方（仓储 / 写入口）声明「数据源 → 实体列」映射（`BaseScopedRepository.scope_columns`）后翻译落地，未声明即该条不产生放行；集合值按目标列类型归一（转换失败即永假）。非法 / 未注册规则退化为永假并记 `stats().invalid_rule_rejections`；`select` 勾选数超 `[data_scope].options.max_in_values` 配置期即拒（`30047`，引导改用区域 / 匹配 / 扩展）。实现落点 `bms_core/scope/{base,limits,policies,policies_rbac,rbac}.py`、`bms_core/repositories/*`、platform `services/role_grant.py`

## 8. 三权分立 <a id="sep"></a>

- 平台超管（**平台租户内的 `platform_admin`**，2026-10-20 `04_01` 拍板不建 `sys_admin` 独立账号表）：跨租户运营（租户开通 / 停用 / 域名 / 配额 / 模块开关），不进入租户业务数据，不经租户 RBAC 计算
- 租户侧三类内置角色权限互斥、同一用户不得兼任：系统管理员（用户/岗位/部门等系统配置）、安全管理员（角色/业务/动作/数据范围/密码策略/IdP 配置）、审计管理员（只读全部日志与审计数据）
- 租户开通首建系统管理员账号，由其创建另两类管理员

## 10. 引擎档位与演进 <a id="profile"></a>

> 2026-10-08 拍板：权限计算引擎按**档位（`profile`）**分三代演进，供不同规模组织选用；三者为**同一引擎的递增装配形态**，不是三套实现。

| 档位 | 受众 | 定位 | 状态 |
| --- | --- | --- | --- |
| `smb` | 中小企业 | **基础版权限引擎**：主体链 → 权限码集 + 入口授权 + 数据范围（四策略）+ 字段权限 + 入口 / 权限码双轨校验 + 概要装载（即本章 §2 ~ §9 口径） | 2026-10-08 交付（任务 `02_04`） |
| `enterprise` | 大型企业 | **精细化权限管理引擎**：在 `smb` 之上扩展更细的授权与生效规则 | 方向已定，接缝已备 |
| `enterprise_hr` | 大型企业（人事） | **结构化权限管理引擎**：在 `enterprise` 之上扩展面向人事（组织结构 / 岗位层级 / 汇报关系）的权限管理 | 方向已定，接缝已备 |

- **配置**：`[permission].profile`（缺省 `smb`）；未实现的档位**启动即 fail-closed**（不静默降级为 `smb`）；
- **与三权分立的关系**：§8 的租户侧三类管理员互斥、平台超管边界**与档位无关**，各档位一律适用；
- **扩展接缝（显式框架化，基础版已定义协议与骨架）**：① 角色解析器链（`BaseRoleResolver`，基础版注册「直接角色」「mdm 组织链」两个解析器）；② 字段权限 provider（`BaseFieldPermissionProvider`，基础版为静态收窄）；③ 校验链 guard（`BasePermissionGuard`，基础版空链）；④ 数据范围策略经既有注册表扩展；⑤ 权限快照扩展位（`profile` + `extensions`）。
- **主流程不变式**：新维度一律经接缝注入、新增数据只进快照 `extensions`，**不改主流程与快照核心字段**；校验入口签名不变。

## 11. 下沉共享基座 <a id="sink"></a>

> 2026-10-19 拍板（需求 07-16）：**判定与计算下沉共享基座**，数据访问留服务侧。起因是 `02_04` 的实现落在 platform 服务包内，其余服务无法复用真实校验（基座只有占位实现，`require_permission` 恒放行），而服务边界护栏禁止服务互相 import。

- **下沉边界**：只下沉「判定 + 计算」——判定契约、快照结构、校验链、版本键、角色解析器与字段权限 provider 接缝、计算主流程（角色收敛 → 聚合 → 快照 → 缓存）、四策略求值器；**数据访问不下沉**（角色 / 授权 / 数据范围的仓储与模型留服务侧），表归属与建表链零变更（「代码下沉不改归属」）。
- **数据访问经两个接缝**（显式框架化，与既有接缝同构）：
  - **权限元数据来源**：菜单 → 表单、权限码 id → 权限码的索引，供授权行的两段解析；
  - **权限数据来源**：按用户一次取回角色集合 / 角色类型 / 授权行 / 数据范围规则 / 字段收窄。
  两者都返回基座中性结构，服务侧只负责「取数 + 映射」——platform 直查本库、其余服务经内部只读契约取原始数据。
- **一致性口径**：各服务在**本进程内**用同一引擎计算快照，不逐请求远程取判定结果；跨服务只发生在取数环节，且失败即 fail-closed（不降级为「无权限」也不放行）。
- **插件化与 fail-closed**：引擎以 `permission` 插件键登记，经 `[permission].provider` 切换（`null` 占位 / `rbac` 本仓实现 / 将来第三方）；**配了真实实现却未注入数据来源即启动拒启**，不静默放行也不静默全拒。
- **主流程不变式（对后代的承诺不变）**：五步主流程、快照核心字段语义、校验入口签名一律不变；新增维度仍只经接缝注入、进快照 `extensions`。
