## 1. 概述 <a id="overview"></a>

通知公告子系统承载站内信/待办提醒、全员公告与已读回执、邮件与短信通知。
对应[《项目规划说明》](../../规划/项目规划说明.md)的「通知中心」「公告管理」「邮件通知」章节。待办提醒与通知中心
（个人维度）区别于公告（面向全员）。

## 2. 站内信与待办通知 <a id="notification"></a>

- sys_notification：user_id、title、content、type、biz_type、biz_id、is_read（个人维度）
- 生成路径：业务方发布 `notification.requested`（已渲染正文 + 收件人）→ 通知组 `notification-inbox` 消费 → 站内信落库 + 发布 `notification.sent` + 触发实时推送（`notification.new` / 审批类 `approval.todo`）
- 渠道偏好过滤：发送前按用户通知偏好（`sys_user_preference`）过滤渠道（站内信 / 邮件 / 短信开关）与免打扰时段，被过滤渠道不发送；通知服务经 `notification_preference` 能力域（`http` → platform 内部端点）按收件人读取，读不到回落全渠道开启
- 免打扰语义（2026-11-16 登记）：命中时段时站内信仍落库，仅跳过实时推送；邮件 / 短信的延迟补发归 07_03
- 待办提醒：审批待办生成 → 站内信 + Socket.IO（approval.todo）+ 待办角标
- 批量已读/全部已读（PC + 移动端）
- **通知中心读口径（2026-09-20 登记，前端组件库 07_04）**：列表 / 详情（查看即已读）/ 未读计数 / 已读（单条 / 批量 / 全部）/ 删除按用户维度提供；**未读数以服务端为唯一口径**，实时推送与已读并发由服务端裁决、前端以返回值校准角标；推送事件负载含标题 / 类型 / 业务类型与业务标识，供前端跳转与插入；通知内容按收件人语言运行时渲染，前端只展示
- **通知中心契约基座（2026-09-20 登记，补充三 02-46）**：读接口统一经 `BaseNotificationCenter`（`app/notification/`，`list` / `detail` / `unread_count` / `mark_read` / `mark_all_read` / `delete`），**禁止各模块自建通知存储**；通用接口 `/api/v1/notifications`（登录即可）；已读接口返回操作后的未读总数（服务端唯一口径），推送与已读的并发由实现侧按用户加锁裁决；`notification.new` 负载字段见[实时推送](18_架构设计_子系统_实时推送.md)「事件路由」节

## 3. 公告与已读回执 <a id="notice"></a>

- sys_notice：title、content、type、priority、is_top、publish_at、expire_at、status（draft / published / offline）——发布 / 编辑 / 置顶 / 过期自动下线（读取校验 + 内置任务 `expire_notices` 每小时扫描）
- sys_notice_read（雪花 ID 主键 + `(notice_id + user_id + deleted_at)` 复合唯一）：已读回执统计（全员维度）；重复阅读幂等
- sys_notice_i18n（`(notice_id + locale + deleted_at)` 复合唯一）：标题 / 正文多语言附表；主表两列为默认语言派生快照，读取三级回退
- 列表排序：置顶组按更新时间倒序、非置顶组按发布时间倒序；应读人数实时取平台启用用户数（经用户只读出口）
- 发布 / 更新 / 过期下线落 `sys.notice.published` 事件（可选 action / type / priority / publish_at / expire_at；Webhook 可订阅）；删除不发事件

## 4. 邮件通知 <a id="mail"></a>

- sys_mail_template（code、name、subject、content、status）：Jinja2 模板入库、页面在线编辑、保存前语法校验与沙箱渲染测试；多语言主题/内容存 sys_mail_template_i18n
- 平台默认模板在代码内置、租户库可覆盖；租户停用视为显式停用，删除覆盖行后回落默认
- 发送：发送请求写 `sys_mail_log`（pending）+ 提交作业，worker 用 aiosmtplib（异步 SMTP）+ Jinja2 渲染结果发送；按收件人 locale 渲染内容
- 场景：审批提醒、告警通知、找回密码重置链接（短时效 token）
- 权限码 mail:send / mail:query；外发经外发调度器统一过滤渠道与免打扰

## 5. 短信通知 <a id="sms"></a>

- sys_sms_template（code、name、content、channel: aliyun/tencent、scene: code/alert/notify、provider_template_id、provider_param_keys、status）：页面在线编辑
- 渠道：阿里云 / 腾讯云二选一（`[sms].channel`）；云短信只能发送厂商已审核模板，模板按 `(code, channel)` 唯一
- 发送：外发调度器写 `sys_sms_log`（pending，正文脱敏）+ 提交作业，worker 按厂商模板调用并回写状态
- 场景：验证码、告警通知；渠道故障落 failed 并告警（企业微信 / 钉钉降级归 08_02）
- 验证码 / 找回密码经 `BaseNotifier` 的 `http` 实现调通知服务内部发送端点（能力 `notification.send`）

## 6. 与其他子系统的协调 <a id="coordination"></a>

- **[事件总线](16_架构设计_子系统_事件总线.md)**：通知请求 `notification.requested` 经通知组消费（模块解耦）；落库后发布 `notification.sent`
- **[实时推送](18_架构设计_子系统_实时推送.md)**：站内信/待办推送触发；批量已读同步角标状态
- **[工作流](21_架构设计_子系统_工作流.md)**：审批待办生成 → 站内信；审批提醒邮件（Jinja2 模板 + i18n）
- **[认证与会话](14_架构设计_子系统_认证与会话.md)**：找回密码邮件/短信通道（Redis token 单次有效）
- **[任务调度](17_架构设计_子系统_任务调度.md)**：公告过期自动下线为内置任务 `expire_notices`（每小时），执行体经通知服务内部端点完成扫描 / 状态收敛 / `offline` 事件
- **[国际化](24_架构设计_子系统_国际化.md)**：邮件模板多语言内容走 i18n 附表；运行时通知按收件人 locale 渲染
