# 基座文档清单

> 通用基座权威清单：bms 仓库为权威源维护，产品仓库以工作区符号链接引用（见《平台可扩展性规划》4.3）

[文档首页](文档首页.md) › 基座文档清单　|　[配套：平台可扩展性规划 →](规划/平台可扩展性规划.md)

## 1. 基座定义 <a id="def"></a>

三层分层（见《[平台可扩展性规划](规划/平台可扩展性规划.md)》第 3 节）：**通用基座** / **平台专属** / **产品专属**。
- **通用基座**：跨项目共享的规范与基础设施，判据——内容对任意基于平台的产品都适用（规范方法论、共享基础设施、平台通用能力）。
- 平台专属（规划/项目/设计/平台部署记录）与产品专属内容**不登记**本清单。

基座内容按归属分三类，避免「登记了却不知归属」的歧义：

| 类别 | 范围 | 引用/维护方式 |
| --- | --- | --- |
| **① 基座文件** | 第 2 节清单主体（规范 20 篇、共享基础设施资料、公共资源） | 权威源唯一，产品仓库不复制，以工作区符号链接引用（见《平台可扩展性规划》4.3） |
| **② 各仓库自带副本** | `用户文档/本地资源.md`（各仓库文档根下；本地资源凭据，内容各仓库不同） | 登记为基座模板，但**不参与校验**（已 gitignore，各仓库自建） |
| **③ 清单本体** | 本文件《基座文档清单》 | 只在权威源 bms 维护，产品仓库**不复制**；产品按需查阅 bms 仓库

## 3. 平台默认标识说明 <a id="platform-prefix"></a>

基座文档中 `bms`、`bms_`、`BMS_`、`bms:` 等为**本平台默认标识**（仓库名、库名、环境变量前缀、镜像名、Redis key 前缀等，定义见《[命名规范](规范/命名规范.md)》第 3 节与《[英文简称规范](规范/英文简称规范.md)》）。
- 复用本平台的产品：沿用默认标识（作为平台扩展运行时即平台标识）；
- 独立部署的产品：可整体替换为自身标识。

**共享基础设施**：开发服务器（mjbk）、Windows 服务器（mjw）、开发机（mjpc）及其服务属通用基座（见第 2 节 `bms文档/资料/开发服务器`、`bms文档/资料/开发机`），基座规范中出现的具体主机名、端口、库名视为**平台示例取值**，产品按自身环境替换即可，环境分层与隔离要求不变。

**文档根命名约定**：文档根目录按项目命名——平台仓库为 `bms文档/`，产品仓库为 `<产品>文档/`（如 `biz文档/`、`cw文档/`）；产品侧基座子目录经符号链接映射到自身文档根下。

**跨层引用口径**：基座文档只引用基座内的相对路径（含各仓库文档根下的 `文档首页.md`、`用户文档/本地资源.md`）；指向平台专属文档（`规划`、`项目`、`设计`）时一律写「平台《文档名》」形式的**文档名引用**，不写相对路径——平台专属文档不随工作区进入产品仓库，写相对路径在产品侧必然断链。

## 4. 变更与工作区同步 <a id="sync"></a>

- 权威源：通用基座只在 bms 仓库演进，产品以工作区符号链接引用，不复制、不 fork 二次维护。
- 同步靠 git：改动任一处 bms 克隆 → 提交推送 → 其他工作区的 `bms/` 克隆 `git pull` 更新；产品文档中的基座相对路径引用在软链下即时生效。原 base-sync 脚本机制已退役，**不引入 git submodule、不保留文件同步脚本**。
- 产品专属资料（如 cw 的 `bms文档/资料/创作/`）：保存在产品仓库实目录中，**不写入基座子目录**（软链下写入会改到 bms 仓库）。
- 一致性自检（CI job `base-integrity` 与本地）：`python3 scripts/tools/base-check/check-base.py` 校验基座链接自洽、无跨层引用、无措辞残留、清单与磁盘一致；任一项不通过退出码 1。
- 首次切换：cw 早期规范为人工改编版（BMS→CW 前缀替换），已按权威源切回中性权威版（软链引用）；cw 特有增补迁到产品专属文档。

## 5. 维护约定 <a id="maintain"></a>

- 新增/删除基座目录或文件：同步更新第 2 节清单；新增基座子目录（如 `bms文档/资料/新域/`）时，各产品仓库需补对应符号链接（`资料/新域 -> ../../../bms/bms文档/资料/新域`）。
- 平台专属（`bms文档/规划`、`bms文档/项目`、`bms文档/设计`）与产品专属内容：不登记本清单。
- 基座文档中性化口径：项目称谓用「本项目/本平台」（标识符 `bms`/`BMS_`/`bms_`/`bms:` 按第 3 节保留），跨层引用按第 3 节「跨层引用口径」写文档名引用。
- 基座文档链接须自洽：bms 仓库内 `bms文档/` 的相对链接零断链（含锚点），由 CI 的「基座完整性」校验把关。
