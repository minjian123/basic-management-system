## 1. 用途与维护 <a id="purpose"></a>

- **定位**：后端基类**权威登记表**——回答「有哪些基类、在哪一层、父层是谁、代码在哪、是否已交付」。强制用法见《[后端开发规范](规范/后端开发规范.md)》「后端基座体系（强制）」节；体系口径见《[后端基类体系说明](设计/基类体系/后端基类体系说明.md)》。
- **口径**：所有可继承的后端类收敛为一套分层体系（根系 根基类 + 集合体系 / 模块基类 / core 横切 / 跨阶段基座 + 中间层基类）；**公共字段 / 方法只在对应层基类维护，任何模块不得重复实现**；调整某一层基类即全链生效。
- **状态取值**：`已交付` / `占位`（接口或结构就位、真实实现待回补）/ `待交付`（已设计未落地）；与平台架构节点登记一致。
- **维护**：新增 / 调整基类须同步本清单 + 平台《架构设计 · 后端基础类体系》登记 + 对应阶段任务基座登记 + 相关详细设计；状态列随实施回写。
- **代码路径口径**：本清单「代码位置」为**包根相对路径**——共享基座库路径根为 `backend/libs/bms_core/src/`（`bms_core/...`），各服务路径根为 `backend/services/<服务>/src/`（平台服务包 `bms_<服务>/...`，产品服务包 `{包前缀}_{服务}/...`——包前缀经 `[app].package_prefix` 配置）；共 8 个**平台**服务：platform / identity / tenant / file / notification / search / ai / report（`org` 已退役，组织主数据归 mdm 产品服务）；工程结构与依赖方向见《[后端开发规范](规范/后端开发规范.md)》「目录与分层职责」节。

## 3. 根系 根基类 <a id="l0"></a>

- **根基类 `BaseObject`**（`bms_core/core/base.py`）：非 ABC 普通类，一切可继承后端类之根——公共方法唯一落点（序列化、稳定序序列化、统一字符串输出、主键相等与哈希）；体系根清单与承接见《[后端基类实现契约](设计/基类体系/后端基类实现契约.md)》§7。
- **值容器 `ValueHolder`**（`bms_core/core/base.py`）：`get_locked` 上下文内可替换值容器。

## 4. 集合体系（非并发有序 / 基础并发 / 跨副本 / 通用缓存） <a id="collections"></a>

| 形态 | 基类 / 封装 | 代码位置 | 职责 |
| --- | --- | --- | --- |
| 基础集合基类（**集合体系唯根**） | `BaseCollection` | `core/collections.py` | 集合通用**语义约定**：有序语义 + 对外输出稳定序（禁止裸无序集合）+ `collection_kind` 标记；**所有集合类一律继承本根、无任何例外** |
| 非并发有序（无锁高效） | `BaseSorted` → `SortedList` / `SortedDict` / `SortedSet` | `core/collections.py`（`BaseSorted`）+ `core/sorted_collections.py`（`Sorted*`） | 进程内**无锁**有序：稳定序列化 / 排序视图 / 分批 / 集合运算（同步读）；`Sorted*` 为无锁高效形态，也是并发形态的数据底座——**业务与契约不得直接声明 / 继承**（业务排序走排序契约） |
| 基础并发 | `BaseConcurrent` | `core/concurrent.py` | 锁策略守卫 + 原子复合操作 + 快照遍历模板（`BaseSorted` 之**并发子层**，承载 `LockStrategy` 显式传入与 SNAPSHOT 写时复制） |
| 进程内并发（插入序，**业务与契约唯一落点**） | `BaseConcurrent` → `ConcurrentStable*` | `core/concurrent.py` | **插入序稳定输出、不比较元素**（`collection_kind="stable"`）；**分段写 + 插入序号归并**（`SHARDED`，写并发 ≈ 段数；序号分配用独立轻量锁，读按整数序号归并还原插入序）；只读面补齐为 `Sequence` / `Mapping` / `Set`；**通用功能面补齐**为内置容器日常写法（写糖 / 通用方法 / 输出可读性，见下「通用功能面」小节）；承载 Pydantic 模型 / `dict` / ORM 模型等不可比较元素与须保序的清单（08_02 / 08-4）；**不可哈希**（`__hash__ = None`，与内置 `list` / `dict` / `set` 一致——可变对象做内容哈希会在内容变化后破坏容器桶定位） |
| **不可变层（值对象集合字段唯一落点）** | `BaseConcurrent` → `BaseImmutable` → `ConcurrentStableFrozen*` | `core/collections.py`（`BaseImmutable`）+ `core/concurrent.py`（三形态） | **构造期写、构造后恒冻结**（`collection_kind="stable_frozen"`）：构造期走分段写路径（`__init__` 末行 `self.update(items)`，需分段写锁与全局序号锁——故承 `BaseConcurrent` 而非 `BaseSorted`），构造完成即置 `_frozen`，此后一切写操作抛 `TypeError`；**不复用 `freeze()`**（其实质是 `_freeze_clone` 完整重构造，会付两遍写路径成本）；**内容哈希**（与 `__eq__` 语义对齐：列表按序、集合与映射用 `frozenset`，哈希值缓存）；派生运算（`\|` / `union` / `difference` / `symmetric_difference`）走「先算可变临时实例、最后一次冻结」；**`BaseValueObject`（frozen dataclass）的集合字段一律落本层**（其生成 `__hash__` 依赖字段可哈希）（08-5） |
| 进程内并发（升序，**体系内部**） | `BaseConcurrent` → `ConcurrentSorted*` | `core/sorted_collections.py` | 多线程共享：原子复合方法 + 快照遍历；**只读面补齐为 `Sequence` / `Mapping` / `Set`**（索引 / 切片 / `keys` / `items` / `values` / 集合运算 / 与内置容器内容相等）；**通用功能面与插入序形态同一套写法**（两形态 API 不分叉，08-4）；锁策略 `LockStrategy` 显式传入（`RW` 默认 / `RLCK` / `SHARDED` / `SNAPSHOT`）；**业务与契约不得直接声明 / 继承**（升序需比较 + 维护有序结构，写并发天生受限；业务排序走排序契约）（只读 API 与内部化口径随 08_02） |
| 跨副本异步有序 | `BaseAsyncSorted` → `RedisSortedSet` / `RedisSortedDict` | `core/redis_collections.py` | 跨副本 / 多 worker：外部存储为事实源 + 版本号（`{key}:version` 惰性比对）；**并发由 Lua 原子脚本 + `WATCH` / `MULTI` 乐观重试承载，无同步锁层**；公共段＝`async size()` / `async version()` / `version_key()`，读写方法留各自类，**无同步读入口、禁 sync 到 async 桥接** |

### 4.1 通用功能面（写糖 / 通用方法 / 输出可读性） <a id="general-surface"></a>

**口径（08-4）**：**写糖一律等价于对应原子方法、不新增写路径**——`append` ≡ `add`、`extend` ≡ `update`、`d[k] = v` ≡ `set`、`del d[k]` ≡ `delete`；不额外加锁、不额外快照拷贝。

| 类 | 通用方法面 |
| --- | --- |
| `ConcurrentStableList` / `ConcurrentSortedList` | `append` / `extend` / `+=` / `+`（返回同类新实例）/ `pop(i)` / `l[i] = v` / `del l[i]` / `sorted(key=, reverse=)` / `merge`（顺序拼接）/ `copy` |
| `ConcurrentStableSet` / `ConcurrentSortedSet` | `remove(x)`（缺失抛 `KeyError`）/ `pop()` / `copy` / `union` / `intersection` / `difference` / `symmetric_difference` 及四个 `*_update` / `update` |
| `ConcurrentStableDict` / `ConcurrentSortedDict` | `d[k] = v` / `del d[k]` / `clear` / `pop(k[, default])` / `popitem` / `setdefault` / `fromkeys` / `update(映射 \| 键值对 \| kwargs)` / `\|` / `\|=` / `sorted_items` / `sorted_keys` / `copy` |

**输出可读性**：`__str__` / `__repr__` 统一为「类名 + 内置字面量」（序列 `[..]`、集合 `[..]`、字典 `{..}`），超 `REPR_ITEM_LIMIT`（10）项截断并提示「共 N 项」；**跨副本形态（`RedisSortedSet` / `RedisSortedDict`）为描述式**（`类名(key='…')`，不读远端），**任何形态打印均不抛错**。

**冻结只读快照**：`freeze()` 返回**冻结副本**（内容独立），此后**一切写操作抛 `TypeError`**；`PluginRegistry.snapshot()` 等「只读快照」场景以它落成**真实机制**（不再依赖「碰巧没有 `__setitem__`」）。跨副本形态与缓存快照不支持 `freeze`（无同步读入口）。

**禁用方法（不提供）**：`insert` / 原地 `sort` / 原地 `reverse`——须**全表重编号**并持**全局写锁**，会阻塞所有写；替代写法为重建集合（`ConcurrentStableList(新顺序)`）。切片赋值与切片删除同理不支持（切片**读取**仍返回同类快照）。

### 4.2 不可变形态与哈希分工 <a id="immutable"></a>

| 项 | 口径 |
| --- | --- |
| 三形态 | `ConcurrentStableFrozenList` / `ConcurrentStableFrozenSet` / `ConcurrentStableFrozenDict`（承 `BaseImmutable`，`collection_kind = "stable_frozen"`） |
| 构造 | **构造期写、构造后冻结**：`super().__init__(items)` 走分段写路径，返回后置 `_frozen = True`；**不调用 `freeze()`**（其本质是完整重构造） |
| 写入 | 构造后一切写操作抛 `TypeError`（`_ensure_mutable` 守卫） |
| 内容哈希 | 与 `__eq__` 语义对齐——**列表按序**（`("seq", tuple(...))`）、**集合与映射无序**（`frozenset`）；递归规范化以支持嵌套；**哈希值缓存**（首次 O(n)、后续 O(1)） |
| 派生运算 | `\|` / `union` / `intersection` / `difference` / `symmetric_difference` 走「先算可变临时实例、最后一次冻结」（原 `copy()` 后 `update()` 会撞冻结） |
| 哈希分工 | **可变形态不可哈希**（`__hash__ = None`，与内置 `list` / `dict` / `set` 一致）；**内容哈希只给不可变形态**。frozen dataclass 值对象（`BaseValueObject`）字段一律落不可变形态 |
| 不适用 | 跨副本形态（`RedisSortedSet` / `RedisSortedDict` 无同步读入口，无法计算内容哈希）与 `BaseCacheSnapshot` |

> **为什么不挂 `BaseSorted`**：不可变只保证「构造完成后不再变」，构造期即写路径（实测 `__init__` 末行 `self.update(items)` 持分段写锁 + 全局序号锁），且构造完成前若被共享仍需锁保护；`BaseSorted` 无锁设施。

### 4.3 复杂度与「禁用 / 慎用场景」表 <a id="complexity"></a>

| 方法 | 复杂度 | 使用建议 |
| --- | --- | --- |
| `append` / `extend` / `+=` / `d[k] = v` / `del d[k]` / `pop(k)` / `setdefault` / `add` / `discard` / `add_if_absent` / `put_if_absent` / `update_atomic` / `get_and_remove` | O(1)（`extend` 为 O(k)） | 随便用 |
| `__contains__` / `get` / `len` | O(1)（`len` 为 O(段数)，`SHARDED` 下 16） | 随便用 |
| `pop(index)` / `l[i] = v` / `del l[i]` | **O(n)**（先取快照定位序号） | 循环里按索引改列表 → 改「先 `to_list()` 在快照上改，再重建集合」 |
| `popitem()` | **O(n)**（取快照定位末条序号） | 仅用于低频收尾；批量消费用 `to_list()` + `clear()` |
| `sorted` / `sorted_items` / `sorted_keys` / `sorted_by` | O(n log n) | 结果只要一次就用内置 `sorted(...)`；列表排序优先走**排序契约**（仓储层） |
| `__add__` / `union` / `intersection` / `difference` / `symmetric_difference` / `copy` / `merge` | O(n + k) | 返回新实例；高频拼接改用原地 `extend` / `update` |
| `repr` / `str` | O(n)（一次快照） | **禁止**在大集合热路径日志里直接打 `repr`；用 `len()` + 摘要 |
| 不可变形态内容哈希 | 首次 O(n)（递归规范化 + `frozenset`），后续 O(1)（缓存） | 高频新建 + 高频哈希场景慎用；同内容实例只需算一次 |
